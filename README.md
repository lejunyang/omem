# omem

个人记忆与助理：把文档、代码、聊天、笔记放进同一个知识库，带依据地回答问题，记住约定并在被纠正时更新，持续跟进事项，还能把编码任务交给其他 Agent 并保留检查与评审结果。

**文档站**：<https://lejunyang.github.io/omem/>（功能介绍、安装和使用，源码在 [site/](site/)）

## 主要特色

**接收外部事件。** 外部系统可以把事件直接推到插件的回调。回调可先落库再应答，由插件按发送方协议返回受理结果；同一标识、同一正文不重复处理，正文不同则报冲突。支持普通 webhook 和 Chat Completions 回执。回调地址和密钥在 设置 → 插件 里配置。[怎么接入](site/features/plugins.md#接收外部事件)

**工作线：本月在推进。** 从已经关联事项的会话里追问，助手会看到这条线的现状和待定变化，新建的相关待办也会归到线上。 这几周在推进的一件事建成一条工作线，需求、缺陷、评审挂在它下面。打开 omem 先看到的“工作”页，每条线一张卡：一句“截至今天”的现状，最近几条关键变化排成一条点线（改期、决定、风险、结果，各带来源），末尾是虚线的下一步，下面是各工作项走到哪。等你处理的问题、流程关卡、没定的变化合在右栏。点开一条线，看最近几周各忙了什么、下一步（点“就这么做”助手就去做）、时间线、相关的人和群，还能在旁边直接问这条线。每晚整理近况时，助手会提议该建哪几条线。线不用你自己关：上线了先观察两周，群里和指标没有新问题就自己结束，写一段收尾小结；以前的线在工作页下面的“已结束”里按月翻、能搜。见 [工作线](site/features/work-lines.md)。

![工作页：两条线的现状、关键变化和下一步](site/public/screens/work-overview.png)

**事项按流程推进。** 在事项上开始一份流程，按前提走过澄清、方案、编码和推送；阶段条显示进度和用时，需要你确认或动手时直接给出操作卡片。推送那一段可以设成“改动推到远端就算做完”：你推送以后，后面的阶段自己开始，也可以手动点做完。点阶段能看承担者、方案、交办和原件依据。在“流程 → 流程定义”讲讲做法，让助手起草，确认后启用。[怎么用流程](site/features/items.md)。

阶段卡在网页和飞书用同一套内容和动作。平台暂时不可用时，助手可以等一段时间再重试；能自己补的文档、字段或证据交回原助手，不请你代做。确实要你处理时，卡片写清卡点和依据，也可以直接写一句指示让助手接着做。

你自己做的普通阶段只在事项进展里提醒一声，不用回来点“做完了”。助手根据你说的话、关联群的消息和挂在事项上的对象核实，查实就带依据推进；有计划时间时，到点也会核对。网页仍可手动完成或跳过。跳过一段不会让下游越过它尚未完成的上游。

对账查到流程目标已达成或不再成立，助手会带依据收口，不再请你到网页停止。要同事补材料时，在卡片上可以直接把草稿发到机器人所在的关联群。

启用 GitHub 插件并连接账号后，把合并请求链接发给助手，就能挂到事项上跟进状态，流程也能等它合并或关闭后接着走。事项页的合并请求卡上可以直接点“合并”；助手也能合并，默认每次先问你。状态一变还能触发规则（比如“合并请求没合就被关掉时告诉我”）；状态没变但有新提交、新评论时算“有更新”，流程可以等它、规则也能选它，插件带回调的，平台一通知 omem 就去读，不用等定时检查。omem 自己的事（运行结束、评审结束、事项和流程阶段变化……）也能当规则的触发。插件停用后保留最后状态并停止跟进。仓库里的 `examples/plugins/ghdelivery` 是一个现成的场景包：GitHub 需求交付的流程、建合并请求 / 等检查 / 合并三个技能和一条规则。

流程进行中，关联的群、会话和文档有了新内容，助手会攒一批看看这件事变了什么。新要求影响已经在做或做完的部分时，先问你要并进、另开还是不用管，不替你答应；你自己拍板或直接让助手去改的，直接并进。这些变化列在事项页上，等你定的排在最上面，可以逐条处理；文档更新只看新增或改过的行。

你直接在仓库里提交的代码，助手也会帮你核对属于哪件事，在卡片上由你选择挂到已有事项、新建一件事或不用管。确认挂上以后，还没开始的编码阶段可一并补记完成；首次接入不会翻以前的提交。

流程也支持把已经做过的阶段补记完成、对验证结果逐条签字；同一开始关卡连着直接同意后，会先问你是否以后直接开始，重开或暂停时改回每次问。新内容每天默认最多看 12 批，多的留到明天；事项页的阶段上有“这一段已经做过了”，验证结果每条可以点“看过，对”或“不对”；工作页的“按阶段”把在走流程的事项按阶段分列（侧栏不再单列“流程”，流程定义从“按阶段”右上角进），工作页右栏列出流程里等你的；这几个数和开关在 设置 → 推进工作 里。每件走流程的事项在工作页下有自己的页面（事项列表、看板、工作页和飞书进度卡都直接打开它），头部是阶段条和等你的那一段，“流程”标签按文章的写法排：背景、每一段做了什么（截图插在对应的文字后面）、接下来要做的和这件事的来源；等你的卡片下可以写一句话（开始时照这句做、做完了不满意就按这句重做、卡住了就按这句重开），也可以点“在对话里讨论”把这一段带进对话。

事项跟进会从已采集的群聊和私聊里找正在谈这件事的会话，挂上时把依据记在时间线。助手随手挂的会话连续五批没有变化和相关线索就会放下，材料仍可查。预筛跳过的批次不占额度，距阶段计划或事项截止不到 48 小时时，当天的额度放宽一倍。

轮到你做的一段，只收到一张“轮到你了”的卡片，写着要做的事，做完点“做完了”，不再先问“开始吗”。定义里的开始关卡和需要你判断的条件仍会询问。交办完成卡上已有“确认并推送”时，到卡上点一次，推送成功后流程会核对并完成该段。卡片上可直接打开改动、所属事项或流程依据。

重开上游会收回下游还挂着的开始确认；等推送信号的阶段不问开始，远端已有这次交付就直接完成。返工已经交给正在编码的一轮就跟着它，不用再起一轮。有新交付时，助手会核对久等的阶段，能根据记录确认已做完的就补记并收回旧卡；当天你已经在这件事上有动作，停留提醒顺延。

配置了决策模型时，流程等确认、等你做或卡住后，有新材料、交付、事项变化或你的关联会话发言，就会合批复核。摘要显示某个卡点可能有变化才启动对账，判断与结果留在事项时间线。门槛可在 设置 → AI → 决策 调整。

流程结束时（走完、你停下或事项关闭），事项页上多一块“这一次走得怎样”：各段用了多久、其中等你多久、卡在哪、返工几次、哪些关卡你每次都直接同意。同一份流程又结束满三件，助手会对照这几份回顾看定义要不要改，有站得住的修改就起草一份新定义等你点“启用”，不会直接改。重开前面的阶段时，后面正在做的阶段不会被悄悄停掉，会问你要停下还是继续做。

流程还可按需一轮一轮转：默认等你说“再来一轮”，也可设完成后、每天或每周几开始。运行阶段可指定 AI 档位、允许开始的时间段、分钟预算和有限的升档次数；`agents.tiers` 在配置中把 `strong / standard / cheap` 各映射到 `{ profile, model?, effort? }`，默认不配。事项页上能看到现在第几轮、点“再来一轮”、改这一轮的预算；在 设置 → 后端与模型 → 默认 AI 与档位 配置模型档位。[字段与接口](docs/v2/studies.md#第一期的实现)。

持续探索项目可用内置“研究”流程：先写功能清单，再提方向交给你选，按预算逐个试验，最后把有复现依据的问题归并成发现。没有值得做的方向、没有新发现都可以照实结束；默认由你开始下一轮。事项页的“研究记录”里看发现、每个试验的结果、各个方向和各功能试过几次；选方向、判定一条发现算不算，也在那里。发现按条件、现象、为什么是问题、建议分节写，可以带试验的截图；每条可以“就这条问”或“看不懂，重写”带进对话，助手能替你改写、改状态，改好的标“已改好”排到最后。定方向时能看到以前各轮的方向和发现标题，避开做过的；“再来一轮”时可以写这一轮看什么。[研究的用法与边界](docs/v2/studies.md#第二期的实现)，[发现的写法与避开做过的方向](docs/v2/studies.md#发现的写法改好与避开做过的方向)。

研究可限定能碰哪些仓库、选用登记的执行环境；试验在自己的副本里跑，同一方向固定在确认时的版本，不改你的检出目录。你允许改代码后，可以挑几条发现一起“交给改”（不限轮次和类型，也可以在对话里让助手交），omem 按顺序一次交办一条，用研究范围里指定的 AI 改代码和评审；评审通过的自动标为已改好，没过的留给你看，改动都留在各自的交办分支上等你确认。范围在事项页“研究记录”顶上改，发现上有“去改”，执行环境在 设置 → 推进工作 → 研究的试验在哪跑 登记。[范围与执行环境](docs/v2/studies.md#第三期的第一步)。

新交办的研究发现默认由你选的评审 AI 做编码前检查、专项评审和主审。续轮评审仍按最初的复现步骤验收，不把本轮的修改项当成新需求。

含“改”阶段的研究流程可在你允许的方向上逐条改缺陷，经评审后重跑失败试验，留在交办分支上等你应用；没改成的留给你看。你通过范围接口登记远端和分支前缀后，试验与改后重跑可在这个范围内推送，每次有记录；已有流程需自行补上“改”阶段。[自动改与推送](docs/v2/studies.md#第三期的第二步)。

登记执行环境时可以选“派给设备”：这个环境的试验交给你配对过的另一台设备，它按远端地址找到自己的那份仓库，在自己的工作区里切到方向确认时的提交，用自己的模型跑完，把结果和证据文件送回这里的记录。只对你自己的设备开放；那台离线或出错时再派一次，之后记“跑不了”。[派给另一台设备](docs/v2/studies.md#第四期把试验派给另一台设备)。

**做了什么，有数可查。** “数据”页分两栏：“工作数据”是你工作上的指标，按工作线分组，连着数据源目录、观测计划和助手写的报表；每个指标写着它回答什么问题、从哪份计划来，助手在后台提的放在最上面一张“等你确认”的清单里，一行一个，可以一个个、一组或全部保留或不要；“omem 自己”先是几个关键的数和一排节导航，再按时间段列出 omem 做了多少件事、用在哪、替你挡了多少找你的消息、别人直接问机器人多少次、做得怎么样、编码交付、知识用上了没有、花了多少时间和长期走势。点任何一个数，右侧抽屉里是它按天的记录、按场景 / 空间 / 模型 / 谁触发等拆开的样子和记录本身，也能导出给周报用。系统自己的整理另外算；没有基线就不推算省了多少时间。[怎么读这一页](site/features/insights.md)。

**交办编码，多维度评审。** 编码 Agent 把需求拆成修改项，一项一组提交；评审负责人按改动决定这次让功能、业务、架构、历史、规范、精简哪几个评审项看、各看什么；评审问题变成修改项自动改，由提出它的评审项验证，改坏了自动回退重做；和需求、实际用法无关的边界问题记成“以后再做”，不让交办在细枝末节里打转。只有业务和功能上的取舍才问你，问的时候别的项照做。需求做完就可以先推送验证，推送后接着改，下次在同一分支交办时接上没做完的项。每一项都能单独看改动、单独回退。 仓库还能从反复采纳的评审问题里学到约定：同类问题在两次交办出现后默认启用，能写成模式的由宿主检查新增行，其余交给编码和评审遵守；你在空间设置里维护。

![交办概览：五个评审项的结论、所用模型和待处理问题](site/public/screens/review-overview.png)

评审概览上的“分享结论”生成一个只读链接，发给写分支的同事或别的评审人：里面是结论、每个问题（级别、文件和行、说明、建议）和你定的改 / 暂不改 / 不改，左边有问题目录，正文里引用的代码行、原件和记忆一并复制，点开在右边看；不含评审过程，不用登录就能打开，可在 设置 → 分享 里撤销；也可以让助手发（`share_review`）。交办或评审归在某个事项上、事项的流程有一段在等你时，运行页概览顶部显示这一段的卡片，和流程页上的一样，定完问题直接在这里点“做完了”。

**从需求走到代码。** 每次评审都把需求拆成变更点，标出已实现、部分实现、没实现和对应的代码行；需求大时按页面或模块分组，像文件夹一样展开。点变更点，代码高亮并滚到它的标记；拆得不顺手，可以让助手按你的要求重新整理。差异可以上下或左右对比，左侧是可折叠的文件树。

![变更：点变更点 C3，对应的代码行高亮](site/public/screens/review-change.png)

**Wiki 的每个论断都贴着出处。** 一页 Wiki 同时引用需求文档、技术方案、讨论群和代码，点任意一个引用，右侧打开原件并高亮被引用的那几行。问答也一样：回答里的引用指向聊天里那一句、需求里那一行。工作文件和确认表里的代码锚点也引用库内代码原件，先核对版本和行号，不根据 Git 地址猜网页链接。

![Wiki：一页同时引用四份材料，点开代码引用](site/public/screens/wiki-citations.png)

**每晚抽检助手自己写的页面。** 每晚 05:10 从整理材料、修正页面等运行写的 Wiki 里抽几页，核对角色对照原件和代码检查，有事实问题的交回修改；按运行类型统计，低于门槛的一类加严。运行旁的“抽检”可看问题与修改进展，设置 → 自检与复盘 → 每晚抽检 可改开关、页数、门槛和交回方式。设计见 [docs/v2/quality.md](docs/v2/quality.md)。

每晚也会抽查 Agent 给原件和目录定的关注程度，优先看“忽略”“仅检索”和大目录；不对的在“原件 → 待复核”给出建议，由你采纳或保持。

**还有：**

- **选中就能引用**：在差异、评审或打开的原件里选中几段，编号后一起提问，或攒成下一轮的修改点；提问抽屉可以缩小成可拖动的图标。
- **Git 同步交给它**：交办时先拉取、合并或变基，冲突先交给编码 Agent，拿不准的问你；中断的合并、变基、拣选提交或撤销在原现场继续，完成后再同步和编码；应用时快进到目标分支，推送到你选的分支。
- **不用每次重装依赖**：仓库可以把几个装好依赖的工作区借给交办轮流用，准备命令只在锁文件变了时才跑。
- **在自己电脑上看交办的页面**：交办视图点“预览”，omem 在那次交办的工作区里起服务，认出它开的端口，按同样的端口号转到你的电脑上；主子应用、写死 localhost 端口的项目也不用另配。
- **截图、录屏和测试报告留在交办上**：编码 Agent 和检查命令把它们放进 `$OMEM_ARTIFACTS`（或用工具交），omem 收下、按修改项挂好，交办视图“产物”里直接看图、拖视频、打开报告；评审和逐项验证也拿得到。
- **方案与变更说明**（`docs/v2/coding-plan.md`）：值得的交办在编码前先写方案——几个决定，分新增 / 修改 / 删除 / 重构，各写要点：行为对照表、对外的约定、删什么、不选什么——你在卡片或方案页上通过、提意见或换个思路，通过后照它编码，每个修改项挂到决定上，偏差和“有没有更简单的做法”写回决定；不走方案的交办结束时交一份变更说明。别人的技术方案也能交给助理跟进：提取作者的决定、回到代码核对，写出问题、风险、改进和要问作者的，文档更新后重新评估；别人的分支出来后对照同一份方案评审，改动归到决定上，逐个决定看做了没有、偏差在哪。
- **编码前先查影响面**：新交办开始编码前，另一个 Agent 查改动会碰到什么、这些文件以前出过什么问题（需求点、交办、评审问题、提交）、改完要回归什么；编码 Agent 拆修改项时照着补，评审拿它核对。
- **记忆有版本，事项会收尾**：约定被纠正时旧版本保留并指向新版本；事项有时间线和期限，没进展自己过期，有新消息再打开。
- **改了以后怎么做，你看得到**：助手改技能、规则或关注，通知里会列改动前后，可以撤回。规则页和周报能看到哪些规则经常安静结束；确认问题未恢复、又没有后续安排时，会提醒你。
- **有期限的事会主动找上门**：在规则页启用“清点指派给我的事”，主助手在工作日早上按内置技能 `assigned-sweep` 和你提供的查询技能找有时限的外部指派。新发现且三天内到期的合成一条通知，其余在早上的“今天”里看。事项不到 48 小时截止、一天没进展且没在走流程时，巡检会先做只读预查；点“按这个开始”才在事项会话继续。[事项用法](site/features/items.md#指派清点与临期预查)。
- **插件做强交互的事**：一个插件打包 Agent 档案、技能、工具、数据和独立页面。内置的“英语练习”按场景出一组题（中英互选、填空、听写、翻译），一次提交，宿主判客观题、陪练评翻译并点评；陪练在后台补题库，“下一组”按你的水平和薄弱点当场挑出来；也可以和语音模型按场景说英语，陪练评价口语，记进同一份学习画像。自己的插件放数据目录，只写清单和档案就能用表单、图表和默认页面；带代码和常驻服务的（比如实时看机器状态）要你在设置 → 插件里确认后才运行，页面能经 omem 和服务保持 WebSocket 连接，声明了语音的页面能和语音模型对话（麦克风在 omem 的页面里，插件只拿到文字）。不带代码的插件叫“场景包”：可把空间结构、已有档案、完整技能、停用规则和不含密钥值的 MCP 定义一起打包，交给别人安装；命令 MCP 仍须先确认信任。插件可以按成员投递通知、接收表单回答；通知出口默认关闭。插件也能接入自己的聊天渠道，身份、会话、回复和通知由宿主管理。
- **飞书里用**：机器人回答带进度卡片和思考过程，规则一句话写成“遇到什么就做什么”，提问和评审结果都是带按钮的卡片。成员需要用自己的 AI 账号时，可在飞书授权后继续原运行。
- **给 Agent 接 MCP 服务**：Agent 页 → MCP 服务 配置命令或网址，再到档案或内置角色里勾选；环境变量和请求头的值按密钥保存，保存后只显示是否已设置。可检测连接并查看工具，删除前列出使用它的档案和角色。仅你自己的运行带这些服务，其他成员、访客和评审不带；夜间复盘只用标为只读的服务。
- **按网络条件使用后端**：给后端设 TUN 网卡或代理和出口要求（地区 / IP）；用之前查一次出口，一小时内有效，网卡断了或出口不对时停下，按兜底顺序换后端。也可以查 IPv6 出口和 DNS 设置。设置 → 后端与模型 → 通用，点开后端 → 网络条件。[使用方法](site/features/agents.md#限定后端的网络环境)。
- **向量和重排可走云端**：不装本地模型也能用向量检索和重排，在 设置 → 检索与记忆 的两张卡里选来源、先“试一下”再保存；密钥复用 AI 服务商的密钥库，或从环境变量读取。原件分块、记忆和查询会发给选中的提供者。更换向量模型、维度或服务地址要先确认清空与重算数量。插件也能算向量。[配置与检测接口](docs/v2/architecture.md#向量和重排用云端接口)。
- **不自带模型**：理解和写作交给你已安装的 Agent（Codex、Claude Code、Gemini CLI 等），omem 管存储、索引、调度和权限。

> v2 是一次精简重写（2026-10）。v1 的代码与文档在 Git 历史和 `docs/archive/v1/` 中；设计取舍见 [docs/v2/architecture.md](docs/v2/architecture.md)，评测见 [evaluation.md](docs/v2/evaluation.md)，验收步骤见 [acceptance.md](docs/v2/acceptance.md)。

## 它怎么工作

```mermaid
flowchart LR
  subgraph 输入
    A[文件 / 目录 / 代码仓库] --> S
    B[网页 / 飞书文档] --> S
    C[聊天：飞书机器人、个人会话] --> S
    D[对话中说的话] --> S
  end
  S[(原件 + 索引<br/>SQLite FTS / 向量)] --> T{{omem 工具<br/>MCP}}
  M[(记忆<br/>带有效期与版本链)] --> T
  I[(事项<br/>带时间线)] --> T
  W[(Wiki<br/>Markdown + Git)] --> T
  T <--> AG[Agent<br/>Codex / Claude Code / …]
  AG --> O[回答 · 页面 · 记忆 · 事项 · 代码改动]
```

- **空间**把领域分开，类型有个人、项目、代码仓库、学习、通用。代码仓库挂在它所属的业务空间下（业务空间设置里的“仓库”），在业务空间里检索、交办、评审都包括它。检索默认在当前空间和它的**相关空间**，主助手可显式检索所有可访问空间；代码仓库默认按基线分支的提交建索引、每小时拉取更新，分支和交办的代码作为叠加索引按需查、用完自动清理（`docs/v2/code-index.md`）；Wiki 用 `[[space:slug]]` 跨空间关联。互相调用的仓库、同一项目的几个空间可以关联（设置 → 空间，或对助理说“A 调用 B 的接口”）：整理、复核这类只管一个空间的任务也会读相关空间（只读，写入仍在自己的空间），写记忆时会提示相关空间里已有的相近记忆；定期整理会从互相引用、页面互链、依赖声明和共用标签里发现可能相关的空间，确认后关联，你移除的不会再被加回。一个空间可同时放项目文档、讨论和代码，但只关联一个仓库；多个仓库分别建空间。本人可在主助手对话中创建空间、关联本地仓库或接入 Git 链接。
- **原件**是依据，只保留最新版；聊天按追加保存。**Wiki、记忆、事项**是派生知识，都引用原件。
- **空间归属与归档**：问答、原件（含文档）、需求树、运行列表跟随所选空间；需求切换时先显示新标题和加载骨架，编码列表批量读取状态摘要；切换空间退出旧详情（“编码”里打开的需求和交办也退回列表）。规则分为“任务规则”和“归档规则”。自动采集优先使用手动归属和来源绑定，再按创建顺序匹配条件，未命中的批量交给归档角色判断：宿主附上旁证（知识库位置、同目录文档的去向、引用它的业务页面和事项、贴过它的群），几条指向同一业务空间就移过去，确实个人或判断不了的留在个人空间；之后出现新旁证、空间或归档规则变了，每晚再判断一批。为业务事项写的工作文件放进那个业务空间。“从个人空间归位”列出自动移走的（可移回）、等你定的和读者打不开的页面引用。归档规则可让 AI 编写草稿，核对后保存启用；历史材料先预览再应用，迁移保留 ID、引用和行号。
- **原件页**：普通空间按目录树展示，一层一层展开：飞书知识库按知识库和节点层级（文档本身也是节点，下面还能有子页面），知识库外的云文档按“由哪篇文档链接进来”或“直接导入”，聊天按群聊 / 话题群 / 单聊 / 机器人、再按会话和月份（会话里的图片收在“图片”下），网页按站点，会议和日程按年月，笔记和工作文件按月。每个目录带份数和关注程度色点，筛选（关键词、类型、关注程度）同时作用于计数。在任一目录上设关注程度，整个子树连同以后进来的都按这一档。知识库里看到过、但还没采集的节点显示为灰色，点“采集”读进来。业务空间名下的仓库也是树里的目录，展开是仓库的路径树。代码仓库空间在文件较多时按路径目录展示，网址和会话标识保留为独立原件。
- **主动读飞书知识库**：omem 每周列出你在飞书里能看到的知识库，由 kb-scout 角色按你写的方向提议每个知识库放进哪个空间（已有的或新建的）、先读哪些、读进来按什么关注程度；默认归入已有空间和“不读”的建议直接生效，新建空间仍等你确认；也可选择全部等确认或全部直接生效。每次通知列出已处理和待确认的数量，生效后可改回。每晚按优先级读一些，目录级的关注程度让整个知识库的页面都按这一档。只读飞书，不改知识库。
- 理解和写作由你已安装的 **Agent** 完成（通过 ACP 或命令行），它们用 omem 的工具（MCP，或 shell 里的 `omem tool`）检索、阅读、写入，同时保有自己的文件与搜索能力。omem 负责存储、索引、调度和权限，不自带模型。
- **Wiki** 是 Markdown 文件，整个知识库目录是一个 Git 仓库，每次修改都有历史和差异。页面按路径分目录（`a/b/c` 是目录 `a/b` 里的页面 `c`），网页里是可折叠的目录树；页面移动后旧路径仍能打开。
- **记忆**被更正时不覆盖：旧版本标记为“已被更正”并链接到新版本，所以“之前怎么约定的”和“现在是什么”都能回答。
- **记忆按目录分层**：每条记忆在空间里有一个目录（如 `工作/项目A/发布`，最多三层），记忆页左侧是目录树。助理写记忆时按目录说明选目录，没有合适的才新建并写一句说明；拿不准的先放“未归档”，每两小时由整理目录的运行归档，每周再看一遍结构（拆太满的、并太小的、补说明）。标签只用来串起跨目录的东西（同一个人、同一个季度）。
- **记忆质量不靠人工逐条看**：写入前有规则检查（免责式、超长、转述原件、事件复述、无来源、重复的会被退回并告诉模型怎么改），之后每小时由复核模型盲评保留、改写或撤回；可以再挂几个模型做对比运行，在“记忆 → 质量”里按模型比较。
- **相关记忆自动带上**：开了向量检索后，对话新消息或回答、办事的任务开始前，和它足够相近的各类记忆（含偏好、经验，最多 5 条）会自动带上，提示里已有的不重复，助理不用先想起来去查；不够相近就什么都不加（门槛在设置 → 检索与记忆，校准数据见 docs/v2/evaluation.md）。
- **偏好与经验按用途带上**：对话常驻最多 60 条偏好；档案自己的经验不超过 12 条时全带，更多时带最新 6 条和目录提示。任务带自己的偏好（最多 16 条）、最多 12 条自身经验和最接近任务的 8 条共享偏好与经验；有向量时按相关性挑选，其余可按目录查询。“记忆 → 召回”分自动带上、任务挑选、主动查询统计带上和引用次数，整理时查看单列，不计入；从未召回不含偏好。
- **重排（可选）**：检索先按全文和向量取候选，再由本地的 bge-reranker-v2-m3 把问题和前 20 条逐条对读、重新排序；开着时对话前带上的记忆也由它判断相关不相关。公开中文检索集上排序指标 nDCG@10 从 86.6 提到 91.6，代价是每次检索多几秒 CPU，超时就保持原来的顺序。`omem setup rerank` 经 osdk 下载模型，设置 → 检索与记忆 里开关和调参数。
- **问你和给你选项**：Agent 遇到非你决定不可的事用卡片问你：选项都短时排成按钮，按手机宽度均匀分行；有一个长选项时，所有选项按编号逐行显示完整文字，旁边点“选择”；输入框后有“用文字回答”，问题里列了几条要逐条答时输入框可以写多行。卡片发在群里时开头 @ 要回答的人。你答完它在同一轮继续；原来那轮已结束也会接着回答并发回原会话。编码的技术返工先交给助手调查，已有授权能在后台接着执行，完整技术记录在卡片里默认折叠；回答以建议结尾时附上下一步按钮。要问好几件事时，它给你一张表一次问完（单选多选、日期、开关、几个方案卡片挑一个、一批条目逐条通过或不通过），网页上直接填，飞书里点链接去填，也可以直接回一句话；数据和对比放在回答下面：先是一句结论（图标标出达成、需要关注还是故障），再是带涨跌箭头和走势的指标、柱状 / 横向条形 / 折线 / 面积 / 饼图、可排序的表格、方案对比；飞书里用卡片自己的组件画成同样的版式。设计方案、界面改动这类要你试过才好判断的，它写一个可以点的小页面（在沙箱里运行，不能联网），你在页面里试完选一个，选择直接交回给它。设置 → 安全 → 工具审批可逐个选“每次问我 / 做完告诉我 / 不用问”。连续批准默认 10 次后会问一次要不要改成做完告知，只有你同意才改；拒绝理由会回给 Agent，机器点击、输入类插件工具始终要批准。

## 快速开始

需要 Node.js 22.18+（推荐 24），以及至少一个已登录的 Agent。任何支持 [Agent Client Protocol](https://agentclientprotocol.com) 的 Agent 都能用，装在 PATH 里就会被自动识别：

| Agent | 安装 | 配置 id |
| --- | --- | --- |
| Codex | `npm i -g @agentclientprotocol/codex-acp` | `codex` |
| Claude Code | `npm i -g @agentclientprotocol/claude-agent-acp` | `claude` |
| Gemini CLI | `npm i -g @google/gemini-cli` | `gemini` |
| Antigravity CLI | 按[官方说明](https://antigravity.google/docs/getting-started?tab=cli)安装 `agy`，再 `agy acp --login` | `antigravity` |
| GitHub Copilot CLI | `npm i -g @github/copilot` | `copilot` |
| Qwen Code | `npm i -g @qwen-code/qwen-code` | `qwen` |
| Cursor Agent | `curl https://cursor.com/install -fsS \| bash` | `cursor` |
| OpenCode | `npm i -g opencode-ai` | `opencode` |
| CodeBuddy Code / Qoder / iFlow | `npm i -g @tencent-ai/codebuddy-code` / `@qoder-ai/qodercli` / `@iflow-ai/iflow-cli` | `codebuddy` / `qoder` / `iflow` |
| Kimi CLI / Mistral Vibe | `uv tool install kimi-cli` / `mistral-vibe` | `kimi` / `vibe` |
| goose、Kilo、Auggie、Cline、Factory Droid、Grok、MiniMax、Amp、Junie、Devin、pi、DeepAgents、TraeX | 见 `omem agents --all` | 同名 |
| Claude / Codex / TraeX 命令行（非 ACP 兜底） | `claude`、`codex` 或 `traex` 在 PATH 中 | `claude-cli` / `codex-cli` / `traex-cli` |
| 豆包 CLI（本机运行；2.38 起经 ACP 用 MCP 工具，更早的版本经 `omem tool`） | `npm i -g @bytedance/doubao-cli`，再 `doubao login` | `doubao-cli` |
| 豆包 OpenAPI（云端 Managed Agent，无需本地程序） | 飞书应用开了豆包用户权限并授权：`omem doubao status` / `omem doubao login` | `doubao` |

豆包 CLI 按 PATH 中的 `doubao` 命令识别；已有其他发行包提供同名命令时可以直接用，无需重装。omem 按 `doubao --help` 判断版本能做什么：有 `doubao acp serve` 的走 ACP（omem 工具经 MCP、过程逐步显示、模型按名字选），有 `doubao delete` 的单次任务会话用它删除（成员自己的账号也能删），旧版仍用 `-p` 和 OpenAPI 清理。

Antigravity CLI 按 PATH 中的 `agy` 识别，以 `agy acp` 启动并复用 CLI 登录。额度通过 CLI 自己的 `/usage` 读取，不消耗模型额度；后端页显示各模型组的已用比例和重置时间，快用完时按模型组避让。ACP 注册表下载的 `antigravity-acp` 是另一份独立运行包，认证配置与 CLI 分开；已经装好并登录 `agy` 时直接选 `antigravity`；原先手动添加、同样以 `agy acp` 启动的后端会顶替它，保留原名和设置并共用额度。成员可以在“我的 AI 账号”里用网页登录自己的 agy；本人可以在后端卡片上“再加一个账号”，同一个后端登录多个号，各有登录目录和额度（Codex、Claude Code、TraeX、Copilot 也可以）。

自动选型的对话每轮开始前也看已缓存的额度；原后端接近上限且有可用替代时，在原对话换后端接着答。手动指定的后端不因额度接近上限而换。

云端会话可以按运行授权检索、读原文，研究的阶段也能交给云端后端跑并用工具交结果。默认关闭。本人探测并确认后端后，可指定它能使用的工具；云端和这台机器在同一个内网时，可以允许用内网的 http 地址。每次调用沿用成员和运行的空间权限。[配置云端工具](docs/v2/external-access.md#云端后端调工具)。

`omem agents` 列出已识别的 Agent；`omem agents registry` 列出官方 ACP 注册表里的全部 Agent，`omem agents add <id> [--via npx|uvx|binary]` 一步加入（npm 包可以 npx 运行不安装，独立程序会下载并校验到数据目录）。`omem setup` 和网页“设置 → 后端与模型 → 添加 Agent”做同样的事；内置目录里有 npm 包的，在“其他支持的 Agent”里点“安装”就在后台装好（有 osdk 和 Node 时用 osdk 装）。每个 Agent 第一次用前在终端直接运行一次完成登录；模型和推理强度在“检测模型”里选。也可以不登录、改用 API key：设置 → 后端与模型 → API key 添加 OpenAI、Anthropic、火山方舟或其他第三方（OpenAI 兼容）的 key，勾选要生成的后端，就多出 `codex@<编号>`、`claude@<编号>`、`opencode@<编号>` 这样按 API 计费的后端，和本机登录的那个并存，额度分开算；第三方的 key 生成的后端用这个 key 列出的模型（也可以只挑几个，第一个是默认），Claude Code 要的 Anthropic 格式地址检查时自动找；这些后端经 omem 转发，限流、每日用量、额度用完和欠费按提供方的错误码认出来，限流换后端，额度类暂停这个 key 并通知你；key 存在数据目录的 `secrets/ai-keys.json`，网页只显示后 4 位。同一页的 OpenAI key 也给语音、决策、图片三类模型用（设置 → 后端与模型 的对应子页，设计见 [docs/v2/ai-models.md](docs/v2/ai-models.md)）。

设置 → 后端与模型 → 决策 可配置多个模型，按顺序或每次随机先问一个；不可用、拒答或出错会换下一个，刚出错的 5 分钟内排到最后，判断记录显示由谁回答及换用情况。 巡检、盯群、有人找你和直接答复分别设最低把握，按后续结果记录漏看、多看；同页可看报告，也可用命令离线比较其他决策模型。

```bash
# 源码运行（osdk 管理 Node/pnpm 与模型）
osdk install && osdk deps --frozen
osdk run dev          # API :4317 + 网页 :5173，数据在 ./.omem

# 或直接用 npm/pnpm（pnpm workspace：应用、插件 SDK、VS Code 插件、Chrome 扩展、文档站共用一份锁文件）
pnpm install                      # 只要应用：pnpm install --filter @omem-ai/app
pnpm run build && pnpm start      # http://127.0.0.1:4317，数据在 ~/.omem
npm install -g .                  # 可选：把命令行 omem 链接到这个仓库

# 或从 npm 装发布版（包名 @omem-ai/app，命令是 omem）
npm install -g @omem-ai/app

# 只用别人（或常驻服务器）的 omem：轻量命令行，单文件、无依赖，命令也是 omem
npm install -g @omem-ai/cli
```

`@omem-ai/cli`（`packages/cli`）只有连远程 omem 的命令：`omem login`、`omem tool`、`omem mcp`、`omem open`、`omem remote`，不含服务端、本机的库和 `--peer`。两个包装一个就行，完整版也有这些命令。

向量模型可选：使用云端接口或插件提供者时不用下载本地向量模型，重排也可以独立走云端。密钥和外发内容的设置见 [检索配置](docs/v2/architecture.md#向量和重排用云端接口)。

第一次使用先运行 `omem setup`（或 `osdk run cli -- setup`）：交互式选择 Agent 后端与模型、向量模型与重排模型（经 osdk 下载并锁定）、PDF/DOCX 解析（Docling 及其模型）、飞书 / Telegram / QQ·微信渠道、注入标记、桌面与浏览器控制（可选）、会话与并发、定时任务。每一项都会先显示本机已安装什么、各选项的代价；缺的 uv、llama.cpp 和模型经 osdk 装好（不用把 osdk 的 shims 加进 PATH）。最后可以直接启动后台服务。

**后台服务**：`omem service start | stop | restart | status | logs`。用 omem 自带的 PM2 常驻运行（PM2 数据放在 `~/.omem/service/pm2`，不碰你自己的 PM2），崩溃自动重启，日志在 `~/.omem/service/logs` 按天和大小轮换。`omem service enable` 设置开机自启（macOS 用 LaunchAgent，Linux 用 systemd 用户服务并开启 linger、没有 systemd 时用 crontab `@reboot`，Windows 在“启动”文件夹放一个隐藏窗口的启动脚本，都不需要管理员权限），`omem service disable` 取消；`omem setup` 结束时也会问。自启用的是设置时终端里的 PATH，之后装了新 Agent 或换了 Node 版本再 `enable` 一次。前台调试用 `omem serve`。

**更新**：在源码仓库里 `osdk run upgrade`（或 `node scripts/upgrade.ts`）：拉最新代码、装依赖、构建、`npm install -g .` 链接全局命令；加 `--restart` 顺便重启后台服务，`--no-global` 跳过全局安装。装了 osdk 时依赖由 osdk 安装，npm 包从 `osdk.toml` 里 `[registries.npm]` 指定的公开源下载，不管这台机器的 `.npmrc` 指向哪个镜像（公司镜像缺版本或缺发布时间时 pnpm 会装不上）；要换源改那一项。

**传输压缩**：Web 服务为支持 gzip 的客户端压缩网页静态资源和超过 1 KB 的 JSON 等文本响应；实时事件保持流式发送。

**监听地址**：默认监听所有网卡（`0.0.0.0`），方便其他设备配对和打开网页；本机的请求不需要令牌，其他机器的请求必须带令牌（配对码或 `omem link` 给的）。“本机”只认用 `localhost` / `127.0.0.1` 访问、且不是别的网站发来的请求（检查 `Host` 和 `Origin`），所以浏览器里打开的其他网页借不到这份信任。只想本机访问，配置里写 `"host": "localhost"`。Windows 第一次启动时防火墙可能会询问是否允许 Node 访问网络。

打开网页后：

1. **设置 → 后端与模型**：确认至少一个后端显示“已安装”。在 **Agent → 档案** 中为内置角色和自定义档案设置默认后端、模型与思考强度；可用后端排在前面，模型和强度自动检测，检测不到时可手填。默认配置里 Codex 使用 `gpt-6.1-sol`、低 effort。
2. 在主助手对话中说“创建一个项目空间”或“关联这个本地仓库 / Git 链接”，也可在 **设置 → 空间** 新建。网页选择“代码仓库”后，同一输入框自动识别目录和 HTTP(S)/SSH Git 地址；本地目录填运行 omem 的机器上的绝对路径，Git 地址会尝试克隆到 omem 数据目录下的 `repos/`。主助手接入已有路径时复用空间，关联后导入文件（遵守 `.gitignore`）。私有仓库使用服务器已有 Git/SSH 读取权限，链接不含密码或令牌。
3. **Wiki → 规划并生成 Wiki**，或直接对助手说“生成 Wiki”：共用先规划、再逐页写作的流程，用户要求传到每一页。可结合多个空间的代码和文档，页面写入指定空间；当前实现以代码为准，过时文档会注明。
4. **工作 / 问答**：直接提问或交代事情——“记住：周四下午三点和小王同步项目A”“不对，预算改成 120 了”“下周一提醒我交报销单”“帮我盯着项目A的需求变化”。
5. 按 <kbd>Ctrl K</kbd> 搜索或提问，<kbd>Ctrl J</kbd> 保存材料（文本、网址、飞书文档、拖入文件）。

文档解析支持 PDF、DOCX、XLSX、PPTX、CSV 和 HTML；Docling 在源码和安装后的构建中使用同一份解析脚本。结构化 Office / CSV 无需 PDF 模型，旧版 DOC / XLS / PPT 需额外安装 LibreOffice。飞书文档附件先保存原文件，再单独解析；解析失败在“运行 → 解析附件”中重试，不阻塞消息回溯。视频封面可选，正文中的图片副本外链保留为引用，不计入原附件缺失。

**不急的进展一起发。** 后台做完、查清的结论等不需要你现在处理的通知，先出现在网页，到 09:30、13:30、18:30（按设置的时区）一起推送；超过两条合成一份清单。你离开飞书会议或会议结束时，攒着的通知立即放出，不占下个时点。设置 → 通知与打扰 → 通知时间 可以增删时点，清空后新通知照常立即发。数据页“omem 自己”一栏的“提醒”一节按运行类型和会话列出近 30 天处理、先已知道、只看、没看与反感的数量；至少 8 条、一次也没处理的会话可确认后设为免提醒，点名或限时的事除外。你对普通通知回负面表情，助手会学出限定场景的忽略规则，稍后告诉你；通知页能删规则，设置 → 通知与打扰 能关闭学习，紧急提醒不受影响。对工具“做完告诉我”的汇报回负面表情，工具立即改回每次先问你，连续批准次数重新计算。

后台主动汇报的结果，如果决策模型根据你近期发出的相关消息确认你已经知道、也没有新事需要你处理，飞书会略过推送，网页仍保留通知。规则或关注排查出仍在影响人的问题，只有从触发到复查都没人收到消息、也没人接着办时，才会补一条提醒。

内置技能包括 `wiki-writing`、`lark-messaging`、`desktop-control`、`meeting-assist`（旁听会议时按会议性质主动查），以及 `research`（先查库、再查外部并交叉核对，给出有依据的结论）和 `improve-loop`（按可检查的目标逐轮改进，保留有效改动，停滞时换方向或交回）。启动时补进技能库，已有内容不覆盖。 编码改进目标由宿主固定度量命令、测基线，逐轮检查并决定留下或新增提交回退；达到目标、预算用完、连续四轮无效或到点就停止并发报告。运行页能看前后数字和每轮结果，循环不合并或推送分支。

成员还可以使用“网页只读观察者”预设，在获准空间查看工作线、事项、运行和评审。成员打开“工作”看到他能读的线（线下有他读不到的事项时不给整条线的现状）和他自己的线，右栏是等他处理的；他的线每天整理只用他自己登录的 AI 账号，默认不开。助手可以替你问成员某条线的进展（“去问小林退款接口到哪了”），回答记成那条线的一条变化，见[成员的工作页](site/features/work-lines.md#成员的工作页)。每个人能做什么在 设置 → 成员 → 能做什么 里按项给或不给，可以只在某个空间另设；网页只显示他能用的入口和按钮，见[成员能力](docs/v2/multi-user.md#成员能力)。

## 日常用途

**跟一类反复发生的事**：告诉助手“每次演练开始前先查这次的范围，异常就私下告诉我”，再说怎么认出开始。它记成一条持续跟进的规则，每次演练单独开一次跟进；别的运行也能看到这一次并把发现记回对应事项。也可以直接说这次开始了。网页上它和别的规则一起在规则页：可以新建，用一句话生成条件或直接设条件，在“各次”里看、手动开始或结束一次；工作页右栏列着正在跟进的。见 [持续跟进的规则](docs/v2/situations.md)。

每次有不同的协作群时，在规则设置的「这一次的群里」选「先给我看」或「直接发」，再在说明里写清怎么认出群、哪些进展发过去。默认不发群消息。

任务板的每块任务也可指定已配对设备：默认借那台的后端在本机只读调查；需要那台的仓库或登录时，选择在对方运行。对方默认不接活，可在那台的 设置 → 设备 →“接别的设备派来的活”改成只接只读或也接要写的，并按配对来源单独设定（`node.acceptWork`、`node.acceptWorkFrom`）。进度里写着每块在哪台、借后端还是在对方跑；远端结果、限量证据和用量回到任务板，超时或失败可以只重派这一块。

## 会话

巡检、材料整理、每日整理、简报、群筛选、学习出卡和 Wiki 写作/检查会复用各自的后台 ACP 会话。角色说明只在新会话发送；角色、空间、权限、工作目录、模型或说明变化时另开。按后端 `usage_update` 的真实上下文占用计算，超过 60% 就释放，下次任务新开；后端不报告本轮用量时不复用。后台池默认空闲 60 分钟释放、最多保留 3 个进程，与聊天会话独立，可在 `config.json` 的 `sessions.background` 设置 `enabled`、`liveMinutes`、`maxLive`、`maxContextRatio`（默认 `0.6`）和 `maxContextTokens`（默认 `120000`：上下文超过这么多 token 也换新会话，窗口很大的模型不会每次带着几十万 token 跑；`0` 只看比例）。

角色说明（共同约定、角色、环境、偏好与经验、技能目录）每个 Agent 会话只发一次：后端在 ACP 里声明支持系统提示（codex-acp 2.5、claude-agent-acp 0.99 以上）时作为系统提示，否则放在新会话的第一条消息；接上的会话（编码续轮、多 Agent 话题续轮、对话）只发这一轮的内容，当前时间写在每轮开头。编码交办的下一轮默认接着上一轮的编码会话，但上一轮结束时会话已超过 `sessions.codeResumeMaxTokens`（默认 100000）token 上下文时换新会话：任务里带上原始任务、工作分支上已有的提交和上一轮的说明，改动从分支读，不再每次调用都带着前几轮的全部历史。

一次性 Codex CLI / TraeX CLI 任务使用 `--ephemeral`，Claude CLI 使用 `--no-session-persistence`。TraeX 的该参数适用于 `exec`，不适用于 `acp serve`；选 `traex-cli` 使用原生临时模式。ACP 没有通用的不落盘开关：后端声明支持 `session/delete` 时，omem 在临时会话释放时请求移出后端列表；当前 Codex ACP 实际执行归档，磁盘上仍可能保留历史。TraeX ACP 未声明 `session/delete`，释放时改用目录中声明的 `traex archive <会话 ID>`。其他后端可在后端配置中声明 `archiveArgs`，通过同一个可执行程序归档；既无协议清理也无归档命令时，会在运行中提示历史可能仍保留，不能保证所有 ACP 都能归档。会话闲置、超过占用阈值、取消或正常停服时都清理，原来的 Agent 进程已经退出或连接已断时另起一个进程清理；omem 自身被强杀或清理失败时仍可能留下记录。普通聊天和需要续轮的编码/交办会话保留恢复能力；聊天换成新的 Agent 会话时清理旧的。既有历史不批量处理。豆包 CLI 和 OpenAPI 的单次运行结束或失败后，会通过这台机器上的 OpenAPI 授权（`omem doubao login`）删除这次建的会话；授权过期且无法刷新时需要重新登录。每次任务在 omem 内仍有独立运行记录和工具调用归属。

后端会话清理连续失败 12 次后停止自动重试，并在本机保留失败时间和原因。本人可用 `GET /api/agents/session-cleanup/failures` 查看记录。恢复后端配置或授权后，向 `POST /api/agents/session-cleanup/retry` 提交该条记录的 `backendKey` 和 `sessionId`，宿主从下一次清理扫描起重新尝试。

每个网页对话、飞书私聊、群、群里的话题（Telegram 论坛话题同理）各是一个会话，接着上下文继续聊：

- **连续**：回复后 Agent 进程保留一段时间（默认 20 分钟），下一条消息直接进同一个 Agent 会话；释放或重启后用 Agent 自己的会话恢复（Claude Code、Codex 都支持）；都不行时，新会话会拿到本会话的滚动摘要和最近消息，需要细节时自己读原话。
- **独立**：每个会话一次只处理一轮，不同会话并行；对话和后台任务用不同的并发槽，生成 Wiki 不会拖慢回复；存量整理另有一个自己的槽、一次一批，新材料的整理和巡检不用等它。`omem diag` 会报工具调用耗时的 p90，超过 30 秒提醒（多半是在排队）。几秒内连发的消息合并成一轮；一轮还在进行时再发的消息，会在它下一次调用工具时交给它（不打断、不另开一轮），没赶上就照常排成下一轮。服务重启时正在跑的后台运行会重新排队，在原来的 Agent 会话里接着做（12 小时内开始的），并被告知重启前已经做过哪些写入，不会重发消息。失败或停下的运行点“重试”时，编码交办接着原来的工作区和编码会话做（已写完代码的只重跑检查和评审），Agent 运行会被告知上次已经做过哪些写入（发过的消息不再发）；先发分享的群、合并转发、图片或文件再补一句说明时，会多等十几秒（`sessions.contentWaitMs`），和后面的说明一起处理。代码仓库的 Git 子模块会递归检出并索引（omem 自己克隆的仓库；单个子模块无权限会报原因）。交办编码评审不通过时自动在同一会话续轮，复用原来的工作区和编码 Agent 会话；飞书里会单独开一张“编码交办”卡片持续更新进度和各轮独立评审摘要。自动最多推进 3 轮，到上限后持久记录等待本人处理；本人明确继续时，`continue_code_run` 可安排第 4 轮及以后，仍复用最初工作区和编码会话。卡片创建、更新失败会保存脱敏错误并有限重试，重启后恢复；收尾记账失败不改变运行结果，也不阻断其他任务的进度恢复；`read_run` 可看 `codeProgress`，`retry_code_progress` 可单独恢复原卡片投递。复杂的多 Agent 长任务会单独开工作会话（飞书话题）：话题里只有一张原地更新的进度卡（第几轮、谁在做什么、最近一步、运行记录链接）；每轮报告交回后主助手接手，能推进的自己续轮或换 Agent（你上次说话后最多连续 6 次），这些中间回复只留在工作会话和运行页里，做完、要你决定或卡住时才发消息，回复下面折叠完整报告（设置 → 通知与打扰 → 过程消息可改成每轮都发）；Agent 之间可以互相请教（`ask_agent`）。交办时助手先看对方档案有没有要用的工具，没有的自己做那一步，或在这一轮临时借给它（只能借助手自己能用的，以你的身份写飞书、在群里发消息、再交办的工具借不出去）。编码交办停下时，发起的助理也会主动说结果和下一步。
- **过期**：私聊或整群会话空闲超过 12 小时（`/idle` 可改），下一条消息开始新会话并带上上一段的摘要；`/resume` 回到旧会话。
- **跨会话**：问“上次在 xx 群里怎么说的”时，助理会查找并阅读其他会话；`/link <id>` 把另一个会话的摘要固定为本会话背景。
- **互相知道**：宿主记下每个运行在办什么（哪个群和话题、哪条消息、哪件事项），新开始的运行会看到同时在办同一件事的其他运行和它们的结论，以及这件事项在别的会话里说到哪；后台运行发出通知、消息或回答之前，你在它范围里说过话（同一个群或话题、回复了触发它的消息、在别的会话里谈了同一件事项），先把你的话交回给它再看一遍；它还在跑时你说的话会在它下一次调用工具时送到。设计见 docs/v2/awareness.md。
- **主动开新任务**：`/new 任务描述` 归档当前会话，立即把后面的完整内容作为新会话首条任务；不带任务只开空白会话。`/topic 任务描述` 在飞书群聊和机器人私聊的主界面都可发起：以你发指令的这条消息作为话题根消息，机器人先开话题，再启动任务；已在话题中则直接拒绝，不重置上下文。进度、答案和后续追问都在该话题中，即使群设置为 `/mode chat` 也保持独立。两种指令都不自动带入旧会话或群里的历史，显式引用的消息仍作为材料。群里需真正 @ 机器人；私聊机器人时不需要 @。指令与任务之间用空格或换行分隔。
- **群聊**：被 @ 时，助理能看到群里（或话题里）前面的发言；`/mode topic` 让每个话题独立，`/mode chat` 让整个群共用一个会话。
- **飞书思考与 @**：过程显示在原生思考气泡；投递失败时尝试撤回异常气泡，任务继续，兜底卡片只显示状态和最终答案。超时不再让后续对话停用气泡；权限拒绝只暂停当前群的气泡。@ 人可用姓名或邮箱，姓名无法唯一匹配时核对目标群的完整成员列表；已知机器人使用本应用收到的 @ 消息里的名字或 open_id，不能用 app_id。群里有人 @ 机器人问事，回答开头 @ 提问的人（访客也一样，私聊不 @）；要某人回答或批准的卡片（提问、审批、规则确认、编码交办的决定，Agent 限定了处理人的卡片）发在群里时开头 @ 那个人。思考气泡跟着这一轮回复的那条消息：消息在话题里，或后来被编码进度卡片开成了话题，气泡就发在话题里，和回答在一处。设置 → 通知与打扰 → 过程消息里的“思考气泡”有三档：只在回答你自己消息的那一轮显示（默认）、全部（交办的 Agent、主助手看报告、唤醒、规则触发的运行也显示）、关；过程在网页的运行页都看得到。

命令由宿主直接解析；带任务的 `/new`、`/topic` 和 `/as` 会继续启动 AI，整理摘要也会调用模型。除标明飞书专用的命令外，各渠道通用：

```bash
omem space sync omem --exclude docs/archive # 同步仓库空间并排除路径
omem space relate shop-web shop-api -n "调用订单接口"  # 关联两个空间（--remove 取消）
omem wiki export omem .repo-review/wiki     # 把 Wiki 导出成仓库里可读的 Markdown
omem hook claude|codex                      # 记录编码 Agent 会话（配在钩子里）
omem peer invite|add|list|call / omem diag   # 多台设备：配对、诊断、远程检查，见“多台设备”
omem peer share <名字> --space 空间:query|sync[:内容]   # 给别人的 omem 服务开放几个空间（它用自己的服务账号）
omem peer subscribe <设备> <空间> [--sync] / omem peer subscriptions / omem peer sync   # 关注别的服务共享过来的空间：检索得到，--sync 定时同步到本机只读空间
omem lark docs-refresh [--space <id>]        # 重新读已保存的飞书文档（补下载图片、画板，导入链接的文档）
omem lark docs-dedupe [--space <id>] [--apply]  # 合并同一篇飞书文档的 /docx/ 与 /wiki/ 两份原件，默认只列出
omem lark docs-missing [--retry|--ignore all] # 链接里读不到的飞书文档（多半没权限）：立即重试或不再重试
omem lark docs-check [--force]               # 检查飞书文档有没有更新（默认只查到期的）
omem lark backfill [会话…|--name 群名片段|--kind group|--all] [--days 0]  # 回溯这些会话的历史消息（服务采集时逐页推进）
omem lark fill-files [会话…|--name …|--all]  # 补拉已保存消息里缺的图片和附件
omem lark wiki-crawl [<知识库页面链接> --depth 3 --max 500 --batch 100 | --continue <id> | --stop <id>]  # 按目录树读飞书知识库，不带参数看进度
omem lark kb list [--status proposed|mapped|…]  # 能看到的飞书知识库：状态、建议的空间和理由、每晚读的进度
omem lark kb discover                        # 立即发现知识库，新出现的浅读一层目录，排队交给 kb-scout 提建议
omem lark kb read [--limit 30] [--kb <id>]    # 立即从已归入空间的知识库读一批
omem lark kb map <id> accept|map|create|ignore|later|reset|pause|resume|update [--space …|--new-id … --name … --description …] [--priority high] [--level reference] [--share 5]  # 处理一个知识库
omem lark user-permissions [--grant]         # lark-cli 本人登录缺哪些权限（读知识库、写文档），--grant 发起授权
omem lark bot-permissions [--scan]           # 机器人缺哪些权限（@ 人要 user_id、邮箱），给申请链接或扫码补齐
omem link                                   # 从其他设备打开网页的链接（带令牌）
```

数据目录默认 `~/.omem`（`--home` 或 `OMEM_HOME` 可改）：`config.json` 配置，`omem.db` 索引与记录，`library/` 是 Wiki 的 Git 仓库，`files/` 存原始文件，`runs/` 存交办编码的工作区（每个仓库一个 worktree）和补丁，`workspaces/` 是仓库设置了复用工作区时 omem 自建的那几个。各部分占了多少在设置 → 占用里看。

## 给其他 Agent 用

在 Claude Code、Codex 等里把 omem 配成 MCP 服务（`omem mcp`，只读用 `--read-only`），它们就能检索你的知识库、读原文、记记忆和事项。`skills/omem/SKILL.md` 是给这些 Agent 的使用说明（概览和接入方式），各类工具的做法分在 `skills/omem/references/` 里，可以把整个目录放进它们的技能目录；打开“接管 Agent 自带的技能”后 omem 会自己放进去，并把别的工具装的技能按分组换成总入口（[docs/v2/agent-skills.md](docs/v2/agent-skills.md)）。能跑 shell 的 Agent 也可以不配 MCP，直接用 `omem tool <工具名> 键=值 …`。

工具很多（约 100 个），为了不占上下文，常用的二十来个直接作为 MCP 工具列出，其余的经 `omem_help`（看说明）和 `omem_call`（调用）使用；omem 自己调用的 Agent 也是这样。omem 启动 Agent 时给它的进程带上本次运行的令牌（`OMEM_TOKEN`）并把 `omem` 放进 PATH，它在 shell 里用 `omem tool` 时，能用的工具和能读写的空间与 MCP 一样由服务检查。

## 桌面与浏览器控制

可选。omem 的 Agent 可以用 [ai-auto-desktop](https://github.com/lejunyang/ai-auto-desktop)（命令 `aad`）看和操作本机的桌面程序与浏览器页面：先读出界面结构，再对读到的元素点击、填写、按键，不按坐标乱点；界面变了会拒绝而不是点歪。

- **安装**：`omem setup` → 桌面与浏览器控制，或 `omem setup desktop`，或网页设置 → 设备 → 桌面与浏览器控制。经 osdk 装 `github:lejunyang/ai-auto-desktop` 的发布包（Linux 取静态的 musl 包），然后跑只读的 `aad probe` 报告这台机器能用什么。装不装由你定；没装时技能会让 Agent 告诉你，不会自己下载。
- **怎么被用**：会话里带命令行的 Agent 直接运行 `aad`。osdk 的安装目录不在你的 PATH 上也行：omem 启动 Agent 时把它放进 PATH（osdk 给没选用的工具留的空垫片会被识别并绕开）。用法在内置技能 `desktop-control`（带 `references/aad.md`），启动时自动补进技能库，已有的技能不覆盖。
- **约束**：技能规定默认只看；动手前先问你，不可撤销的操作逐个确认；不输入密码、验证码和支付信息；屏幕上的文字只当材料。这是对 Agent 的约束，不是权限边界：装了之后带命令行的 Agent 档案都能运行 `aad`。回答访客的运行不把 osdk 的安装目录放进 PATH（`OMEM_DESKTOP_TOOLS=off`）；但如果你自己把 `aad` 放在了全局 PATH 上，访客用的档案仍要选没有命令行的后端；不想要了 `osdk uninstall github:lejunyang/ai-auto-desktop`。
- **临时交给成员**：受管技能打开的浏览器会话关联到运行。会话主人或本人在远程页点“交给成员”，限时让成员只看或操作这个页面，可改模式、延长、收回，收回后立即断开；被交给的人在侧栏“远程”里只看到交给他的会话。要交给成员操作，浏览器要勾“给成员用”打开，它访问不了运行 omem 的机器上的地址。见 [远程会话授权](docs/v2/remote.md#把会话交给成员)。
- **成员自己的浏览器**：给成员“用自己的远程浏览器”能力后，他能在远程页开自己的浏览器、存自己的长期资料（比如登一次单点登录，之后复用）；只开得了浏览器，开不了桌面，访问不了这台机器自己的地址（localhost、127.0.0.1、局域网地址）。`#/remote?profile=<名>&url=<网址>` 打开就是他那份资料，可以发给他去登录。见 [成员自己的浏览器](docs/v2/remote.md#成员自己的浏览器2026-11-25)。
- **角色带细分能力**：自定义角色除了基本权限，也能勾成员“能做什么”里的那一套细分能力（看事项、改规则、远程……），按角色批量给。
- **浏览器长期资料**：技能带的 `scripts/browser.mjs` 按名字开 Chrome，资料放在数据目录 `remote/profiles/<名>`（和“远程”页同一处），登录状态和缓存都留着，同一份资料开着时直接复用、开新标签页；默认无界面、按 1440×900 开窗口；`shot <资料名> --out 文件` 截页面现在的可见区域（弹窗和本人看到的一样，`--full` 截整页）；`--header 域名=请求头:值` 给指定域名的请求加头（如测试环境的泳道头）；页面想打开本机别的程序（`xxx://` 链接，Chrome 会弹“要打开 xdg-open 吗”）一律拦下。技能要求 Agent 一个测试账号用一份资料，做通的网页操作（登录、填某张表）存成技能和脚本，下次先跑脚本。
- **查看**：`omem diag` 的 `tools.aad` 和 `omem setup` 开头一行显示是否装好、版本；网页设置 → 设备 → 桌面与浏览器控制 里有安装 / 更新按钮。
- **远程操作与录制技能**（导航“远程”，装了 `aad` 才出现）：在网页上打开 omem 所在机器的一个浏览器页面（默认无窗口，可选长期资料保留登录，或复制本机 Chrome、Edge 某份资料的登录；资料被占用时可先关闭占用它的浏览器）或桌面（整个、某块显示器或某个窗口），画面经 omem 转发，鼠标键盘、输入法、滚动都送过去。要教助手一件事时先说要做什么，点“开始录制”做一遍：浏览器录下每个动作、页面变化、请求（cookie 和令牌替换成占位）和截图，桌面按共享的窗口（共享整个屏幕时按所选程序）录元素和动作。也可以不开远程会话，用 Chrome 扩展在自己的浏览器里录（侧栏「录制」，上传到 `POST /api/remote/recordings/import`，格式和远程页的浏览器录制相同，多了本人加的标记）。停止后录制交给右边的助手，它读步骤和请求（工具 `read_recording`），按内置技能 `skill-from-recording` 和你确认会变的值、成功的标志，再保存成技能，技能只带上完成这件事用到的接口（埋点、静态资源、预检、轮询先略去）。要教的是“遇到这种情况怎么判断、怎么回”时用**演示**：一次演示是一个对话，开始后扩展的录制和拾取、结束时收进的你在飞书里发的消息和远程页的录制按时间记在里面（不起一轮），结束时按内置技能 `skill-from-demo` 整理成技能，或写成关注的经验（`关注/<名>/演示/<目标>.md`，处理这个关注的助手和经验一起读）、事项的工作文件；在扩展侧栏、关注页和事项页、`/演示` 和 `/演示结束` 命令里开始和结束。画面断开时自动重新连接，也可以手动刷新。“画面设置”调格式（自动、只传变化、视频、整张图片）、画质、帧率、最大宽度、鼠标指针和剪贴板，可以直接应用到开着的会话。设计见 [docs/v2/remote.md](docs/v2/remote.md)。

## 飞书

**机器人**（指挥助理、代你回复）：运行 `omem setup` → 渠道 → 飞书机器人。它会先读本机 lark-cli 的应用和登录状态、omem 已保存的应用，然后让你选：

- **继续用 / 绑定已有应用**：已保存凭据的直接校验；没有凭据的扫码授权，omem 拿到凭据并补齐所需权限。
- **创建新机器人**：扫码后在飞书里一步建好应用，开启机器人能力、长连接事件（`im.message.receive_v1` 等）和卡片回调 `card.action.trigger`，并授予消息、卡片、文档、日历、任务等权限（不含群管理和权限修改）。

扫码走官方 SDK 的应用注册流程，事件走 SDK 长连接，不需要公网地址；扫码人的 open_id 自动设为本人，只有你（和 `omem user add` 登记的人）能指挥它。App Secret 存在 `~/.omem/secrets/lark.json`（仅本人可读），配置文件只记 App ID；环境变量 `OMEM_LARK_APP_SECRET` 仍可覆盖。企业租户里新权限可能要管理员审批后才生效。

- 回答时先在你的消息上加“处理中”表情，再发一张进度卡片，实时显示 Agent 的步骤、思考片段和正在写的答案，完成后原地变成答案。
- 飞书里 @ 不能和文件放在同一条消息里：@ 机器人时一起贴的图片、视频随这一轮交给助理；@ 完紧接着单独发的图片和文件（两分钟内，同一个人、同一个群或话题）也并进这一轮。私聊里发的图片和文件同样进对话，没写要做什么时等十几秒再开始，后面的话会并进来。
- 给机器人的回答加个表情就是反馈：👍、鼓掌算好，👎、捂脸算不好，OK、DONE、+1 只算“收到”（映射在 `feedback.emoji` 里可改）。Agent 页按档案和模型统计（默认只看你的，其他人和访客分开），夜里复盘和整理记忆会先看收到负面表情的回答。设置 → 渠道 → 飞书机器人 里的“机器人权限与事件” 能检查应用缺哪些权限和事件订阅，扫码补齐。
- Agent 可以用机器人回复或开话题回复、@人（按名字或邮箱，机器人用通讯录的 user_id 去 @）、加表情、发 Markdown、图片和文件、带按钮/下拉/输入框/表单的卡片（表单每题一行粗体问题、几题自动编号，按钮按手机宽度分行），并限定只有某些人能操作（发在群里时卡片开头 @ 他们）；别人点了按钮或提交了表单，会作为新消息回到原来的会话继续处理。还可以对指定的人加急（应用内加急，`urgent`），或在群里发只给某几个人看的卡片（`only_to`，其他人看不到）：默认都不能用，只有你在对话里明确要求、或规则勾了“允许加急 / 允许只给部分人看”时工具才放行，什么情况用、对谁用照你的原话。用法见内置技能 `lark-messaging`。

@ 群里的其他机器人可按名字从近期历史提及中核实身份，不必在同一条消息里同时 @ 两个机器人。普通 @ 会按目标群核对姓名。确认不在群内的人自动跳过，其他人的提醒与正文照常发送；不会把全局同名联系人记录误报成群内重名。

**回答里的引用**：飞书打不开 omem 自己的引用，发出去前逐条换掉（回答、规则开话题回复、主动发送、更新卡片都一样）。属于句子的引用（“按[《差旅报销制度》]第 3 条”）保留文字、链到原处；跟在句末的换成 (1) (2) 这样的编号链接（编号多了大小也一致），段落不再以一串标题结尾。飞书文档和网页链到原文；聊天里的那句话和来自飞书的消息直接打开飞书会话并定位到那条消息（新采集的消息记下了位置，旧消息发送前用 lark-cli 补读一次，读不到时只打开会话）。代码、工作文件、记忆、Wiki 页面或小节这类 omem 自己的东西，发送时复制成一个**只读分享**：链接放在“网页地址”上，带一个随机令牌，打开不用登录，只能看到这条消息引用的那几处（原件的被引行和前后几行、记忆、页面），里面再提到的东西不能点开；默认不过期（设置 → 分享 改有效期），在那里也能看到每个分享来自哪次运行、哪个群、被打开过几次，随时撤销。只复制这次运行能读的空间（访客回答只复制群所在的空间）；没填网页地址时不生成分享，这类引用直接省略，不再显示成文字。

![只读分享：一条飞书回答引用的排查记录和代码](site/public/screens/share-link.png)

**同事和别的机器人 @ 它**（设置 → 代你回复 → 访客提问，默认关）：没有登记的同事在群里 @ 机器人时，先由“访客提问把关”判断该回答、拒绝还是不理——要它执行命令或脚本、读本机文件、打听私人信息（别人的私聊、个人记忆、你的日程和设定）、问无关或敏感的事，直接回一句拒绝；能回答的由“回答访客”只读这个群所在的空间（个人空间不开放）和你另外开放的空间，不带你的偏好和技能。别的机器人 @ 它时先交给规则，没有规则接手再让把关判断它说的事要不要处理。每人每小时有次数上限；私聊机器人的陌生人可另外打开。你自己也在的群可以放宽（“你也在群里时”）：照常受限回答；把关后交给助理本身回答（像你自己问的一样，能用全部资料和工具，助理知道提问的是同事）；或者不把关直接由助理回答。群里被拒绝的请求，你会收到一张只有你能看见的卡片（你在群里就在群里出现，不在就发到私聊），写着谁、要做什么、为什么被拦；点“同意这次”就交给助理本身按你的身份处理、结果回在群里，“不同意”就不理。两个角色的后端和模型在“Agent”页设：把关用快的小模型，回答访客最好用不能在本机执行命令的后端。

**再加几个机器人，各管一摊**：`omem setup` → 渠道 → 飞书 → 添加机器人（扫码），给每个机器人选一个 Agent 档案当回答者（也可以是主助手角色，但会话独立）；设置 → 渠道 → 其他机器人里改回答者、填你在那个应用里的 open_id、启停。你在群里 @ 它或私聊它时由它回答，同一个群里可以同时 @ 几个。每个机器人都知道群里还有哪些 omem 机器人、各自做什么；回复里 @ 另一个，omem 就把这条回复转给它接着做，它的回复再 @ 回来也一样，连续转交有上限（默认 4 次），有人发话后重新计数。每个机器人能做的事和主机器人一样：进度卡片和思考气泡、卡片按钮、@ 人、加急和只给部分人看、访客提问（访客、私聊指令等设置对所有机器人生效），会话里的后续结果、提问卡片和编码进度也从同一个机器人发。群消息的采集和规则只做一次：主机器人在群里就由它做，不在才由那个机器人做；不属于某个会话的通知（简报、事项提醒）仍从主机器人发给你。

有人 @ 机器人就是在直接找它：这条消息不再交给规则（等待、静默排查、跳过这些只管没人找它的消息），由机器人直接回答。

**私聊指令**（设置 → 代你回复 → 私聊指令，默认关）：在你和别人的私聊里发 `/ai`（可在后面写要求，如 `/ai 帮我回他部署的问题`），omem 一分钟内读到，助理读最近的私聊把事情处理掉，以你的身份在那个私聊里回复，结尾带“（此消息由 AI 代发）”；只想给自己看的（如“/ai 总结一下”），结果发给你，不发给对方。私聊里发不了思考气泡和卡片，只发最后的结论。`/ai拉群 [群名]` 建一个你、对方和机器人的群，机器人读之前的私聊，在新群里接着处理，之后在群里 @ 它继续。这是 omem 仅有的以你身份发消息的地方，只在你亲手发指令时发生。企业不让 lark-cli 以你的身份发私聊时，把“代回怎么发”改成“经豆包发送”：每次建一个新的豆包会话，只交给它定稿的回复和对方是谁，让它原样发出、用完删除，再读私聊核对，没核对上会告诉你。

任务规则的 Agent 动作可单独勾选“隐藏思考气泡”，并选择失败时“通知本人”或“发到群聊”，与成功结果的回复方式分开。失败由工具按所选位置报告，运行失败也会通知；不会再把同一份失败报告自动发回群里。

**以你的身份写飞书文档**：你让助理把东西整理成文档时，它用 lark-cli 以你的身份新建（`lark_doc_create`）、编辑（`lark_doc_update`：先用 `lark_doc_fetch` 读出要改的那一节或那张表和 block id，再按块替换、插入、删除、调整顺序或替换一段文字，只在你要求整篇重写时覆盖；做法在内置技能 `lark-docs`）。表格、多维表格、幻灯片、云空间 Markdown 文件、任务和评论也能让它读和改（`lark_read` / `lark_write`：跑 lark-cli 的命令，只放行它标为只读或写入的那些，删除清空之类的高风险操作不做；你自己的文件直接改，别人的文件和任务先发给你批准，按文件复用），日历、邮件、聊天记录、妙记只读；做法在内置技能 `lark-suite`，它先读 lark-cli 自带的官方说明和移动（`lark_doc_move`）飞书文档，文档归你。默认放在你的个人文档库；在个人文档库或你自己的云空间文件夹、文档里直接做，放进别人也在用的知识库、别人的文件夹或文档时，先把具体位置和改动摘要发给你批准；首次列出所有待改文档，批准后这些文档的追加、局部替换和失败重试不再逐次问，换轮或换会话也沿用，并兼容此前已批准的文档。完整复制知识库文档用 `lark_doc_copy`，保留表格、图片和排版。也可让助理用 `lark_doc_authorize` 给你指定的知识库节点及其全部子页面一次申请新建、复制、局部编辑和范围内移动的批准，后续新页面、会话和定时规则沿用；执行时核对飞书当前层级。文档审批卡发到你的机器人私聊。范围外操作和整篇覆盖仍需批准。lark-cli 的登录缺权限时，omem 发起只要那一项的授权，把链接发到你的飞书私聊，你确认后自动完成登录；`omem lark user-permissions` 或设置 → 采集 → 飞书文档里可以先检查一遍。外部 Agent 经 `omem mcp` 用不了这几个工具。

**读取你自己的飞书**（lark-cli 个人登录；以你的身份发消息只限上面的私聊指令，写文档见上一段）：在 setup 的同一部分选择读取方式；lark-cli 未登录或登录过期时会直接发起扫码登录（lark-cli 还没有应用时可以用机器人应用），并可顺手开启每 10 分钟的采集。

- 消息：可选“所有有新消息的会话”或“只读订阅的会话 + @我”。每个群或私聊存成一份聊天原件，第一次往前读 72 小时，之后每次只拉上次之后的新消息，包括话题里的回复；回复别人的消息会带上被引用的那句；图片、文件会下载保存；飞书文档链接会读成原件。
- @我消息直接写入对应群原件，联系人学习照常执行；旧的 `lark:mentions` 聚合原件保留，不再追加。
- 同一篇飞书文档只存一份：在知识库里的文档按 /wiki/ 链接保存，先用 /docx/ 链接导入、后来又从知识库读到（或反过来）时都落到同一份原件。以前留下的两份用 `omem lark docs-dedupe --apply`（远程 `sources-merge-duplicates`）合并：标注、关注程度和引用移到知识库那份，旧 id 保留为别名，记忆、页面、聊天和分享里的旧引用照常能打开。内容完全相同的不同文档不合并，检索时只显示一份，注明“另有 N 份相同内容”。
- 群里别人发的文件（CSV、表格、图片）助理可以直接读：已经存成原件的给原件，没下载过的先下载进这个群的空间（`lark_message_file`）。视频和音频只保存文件，不转写、不抽帧。
- 飞书文档：里面的图片、画板（缩略图）、视频和附件（默认 100 MB 以内，`lark.capture.docMediaMaxMB`）都下载到本地，原件页不用登录飞书就能看；内嵌的电子表格读成表格，同步块读出原文，分栏、高亮块、按钮、勾选框和子页面列表照常显示，多维表格保留链接。文档里链接的其他飞书文档一并读进同一空间（默认往下两层，`docLinkDepth`，层数从最先给的那篇算起；每篇最多 30 篇，`docMaxLinked`），链接换成本地原件；知识库页面在知识库里的子页面也算它的链接（每页最多 50 个，`docWikiChildren`，正文没链接到的列在末尾“知识库子页面”），一次导入最多读 100 篇（`docMaxPerImport`）。更大的知识库用知识库爬取（`lark_wiki_crawl` 工具或 `omem lark wiki-crawl`）：从一个页面按目录树逐层往下读，可设层数、总量（默认 2000 篇，`wikiCrawlMaxDocs`）和每批篇数，进度存在库里，读完一批暂停等下次继续（定时规则或助理的唤醒），重启后接着读；设置 → 采集 → 飞书文档里看进度、继续或停止。读不到的（多半是没有权限）汇总发一条通知，之后每 6 小时重试、最多 3 次（`docRetryHours`、`docRetryMax`），用完就不再提（已删除的、不是文档的链接如表格和多维表格不重试也不提醒）；不需要的用 `omem lark docs-missing --ignore` 放弃。读到后只整理新读到的那篇，原文里只改那条链接。以前存的文档用 `omem lark docs-refresh` 重新读一遍补上图片；重新读取中途重启服务会接着读。
- 文档更新：每天检查一次到期的文档，在文档上次修改后 7 天、1 个月、3 个月、半年、一年各查一次（`docRecheckDays`），先问飞书最后修改时间，改过的才重新读并整理；超过一年没改的不再查。
- 更早的历史：新会话里按“保存并整理”处理的（单聊、订阅的群）默认再往前补 30 天；任何会话都可以在原件页点“回溯历史”、用 `omem lark backfill --name 报警 --days 0` 一次安排一批，或对助理说“把名字带‘报警’的群全部历史读进来，图片附件也补上”。回溯时图片和附件随消息下载；以前存下却缺图片或附件的消息（采集时没下载、早期只记了 key）用 `omem lark fill-files` 补拉（远程：`peer call <机器> lark-fill-files`）。机器人在群里实时写下的消息，本人采集再读到时不会重复写。历史在单独的后台循环里按设定速度读（默认每分钟 20 页、同时 2 个会话，被限流时自动放慢；会话多时对助理说“回溯快一点”，它会调高速度），按月存成“群名（2026-09 历史）”原件，只保存可检索，不触发整理（除非要求）。
- 原件页把聊天显示成聊天：发送人、时间、被引用的消息、话题、换行和 Markdown、图片、文件、卡片；被 @ 的人后面附上邮箱，方便认出是谁；长聊天只渲染屏幕附近的部分。消息里的 open_id 只存在消息记录里，不出现在聊天原文和检索里。
- 你最近打开过的飞书文档（文档、旧版文档、知识库页，默认 7 天内，`lark.capture.recentDocs` / `recentDocsDays`）每次采集先读：没在聊天里出现过的文档也能进来。每篇只读一次（每次最多 10 篇，其余下次），之后由每天的文档更新检查跟进。
- 日程（前一天到未来一周）和妙记（总结、待办、逐字稿）也会读进来。
- 会话分成单聊（人）、机器人单聊、普通群、话题群，加上免打扰状态。每类可以设成“保存并整理”“与我有关时整理”（你发言、被 @ 或参与的话题有新消息时才整理）“只保存”“不读取”，默认分别是：单聊整理、机器人单聊只保存、群和话题群与我有关时整理、免打扰不读。设置 → 采集 → 消息采集列出所有采集过的会话（加上订阅了还没读到的），每行可以开关订阅、改采集到的空间、单独改处理方式；订阅的会话一定读取，按“保存并整理”。omem 机器人自己的私聊和它在群里发的消息不会被采集。
- 要整理的新内容交给助理，整理成记忆和事项。同空间、同整理要求的材料等待 30 秒合并，排队期间持续去重，每批最多 40 份，同空间串行执行；聊天保留最早待整理行号。空间的“新材料保存后让助理整理”开关只控制后续入队，不会主动回溯或补整理旧材料；显式要求“回溯并整理”时，补拉的历史聊天也会作为新入库材料进入整理队列。

**规则**：助理替你保存的规则默认停用，回答后点确认卡片里的“启用规则”立即生效，网页同步更新；也能在规则页启用。侧栏“规则”里用一句话说“遇到什么情况就做什么”，例如“报警群里小王发报警卡片时，在卡片下开话题交给 alert-analyst 分析，需要关注就 @ 值班人”“值班群里我被 @ 就把机器人拉进去并优先采集”。模型把原话写成条件（群名、发送人、邮箱、关键词、@ 本人、卡片……）和动作（交给 Agent、开话题、拉机器人进群、转发到别的群或某人、优先采集、持续监听、通知），能写成条件的由 omem 直接判断，写不成的请模型按原话判断；保存前可以“用最近的消息试一试”。“转发到”把触发的消息转到你选的群或某人：比如通知机器人私聊你的提醒转到值班群；群里没有机器人时先用你的身份拉进去，目标是某人时第一次用你的身份建一个你、对方和机器人的群。还能先“等某个会话的新消息”再转：比如有人私聊或 @ 你要验证码，等验证码机器人发来新的那条，再“回到触发的会话”发给他；勾上“快速检查”后每分钟搜一次，不用等平常的采集。说“P0 报警加急值班的小王”“超时的工单只发给提单人看”，交给 Agent 的动作会勾上“允许加急”或“允许只给部分人看”，什么情况、对谁写在任务里。值班这类场景可以让规则“等 10 分钟没人回应再处理”“我已在讨论里 / 已有人回复就跳过”，Agent 用“静默排查”：群里看不到过程，它读完讨论自己决定要不要发、要不要追问缺的信息，有结论才在话题里回复，之后跟进那个话题，你一插话就停。也可以直接对助理说，它建的规则默认不启用，等你核对。会议也能写成规则：“我加入标题带‘评审’的会议时，问我要不要把机器人拉进去，记录会议，有人问到我时提醒我”——你入会时（用你的 lark-cli 登录接收入会事件）按会议标题、人数、参会人判断，先发卡片问你，点了再让选中的机器人入会；也能在同一条规则里设置“30 人及以上先问，否则直接拉”，人数未知时先问，试运行会显示入会方式；会上的转写、会中聊天、谁进谁出和共享的文档记成一份会议原件，会后补进妙记；选了旁听的 Agent 每几分钟看一次新内容，有人点你的名、要你表态或有和你有关的决定时提醒你，会后给你一份简短纪要；会上有人叫机器人（会中聊天写到它的名字或你设的叫法，也可以是说话时叫它），先由决策模型判断是不是在问它，再由主助手按你的权限查代码、文档和数据，用两三句话回答；还可以打开“会上主动查”，按会议性质（排查问题、需求评审）去查会上提到的点。答案默认先发给你看，你点了才发到会里，可设谁问才答和每场上限，会中发 `/ai 停` 就停。保存会议规则后页面上直接检查 lark-cli 和各机器人的飞书权限，缺的给出申请链接。一阵报警连着来时，交给 Agent 的规则默认“处理中再次触发时并入同一会话”：同一个群里复用 Agent 会话，可选“合并回复”一起下结论，或“每次触发分别回复”，依次完成每条的任务并各自答复。关闭后各自开会话并行处理。要用每个人自己的账号做的事（比如查每个人本周的合并请求写周报），在“交给 Agent”里选“以谁的身份运行”：机器人先问每个人同不同意（规则是在群里设的就在群里问，不然私聊），运行时助手依次换成同意了的人，插件登记过的命令行用他的登录跑，成员在自己的账号页可以随时撤回。设计见 [docs/v2/rules.md](docs/v2/rules.md)。 实时事件的 `bot` 与消息读取接口的 `app` 都识别为机器人，卡片按原消息核实发送者名称后再匹配规则；名称查询暂时失败会在下条消息重试，不把错误名称长期缓存。

**关注**（盯群）：在群里 @ 机器人说“帮我盯一下这个群，有人问接口进度就帮我回”，或把群分享给助理（机器人不在群里时它用你的身份把机器人拉进去，和拉人进群是同一个工具 `lark_invite`）。之后群里的消息攒成一批（默认 10 分钟，@ 你或机器人的 30 秒内）交给助理，整个群一个上下文；它只在能回答、值得排查或你需要知道时动手，独立的话题可以交给别的 Agent 单独做，节奏它自己调，到期（默认 3 天）自动停。也可以在规则页新建关注。要它在群里回复时，它先拟一份“要处理哪些、不处理哪些、什么结论值得发”给你确认（只有你看得到的卡片）；回复先是只有你看得到的草稿，可以改了再发、选不发的原因，连续照发几条后才问你要不要直接发，你对自动回复点了不满意的表情就改回草稿；问你的、要你拍板的只私下告诉你。一个关注可以有几个群，一个群也可以在几个关注里；看哪些消息、攒多久再看、要不要去查、问你的要不要替你答、开会时要不要进会都是每个关注自己的设置，在关注页的“设置”里改，每项下面写着它实际做什么，也可以直接跟助手说“把退款值班的关注改成只看 @ 我的”。工作线的关注读哪些群在线页面的“人和群”里加或拿掉；线进了观察期，它的关注只管报错、用户反馈和数据异常。群里有人求助的事按问题跟：处理完记下这件事在等谁、怎样算完，之后的消息先对照它判断有没有新信息，有才接着查（“有人找你”回复对方之后也这样接着跟）；规则交给关注时可以把触发的群一起收进来（一单一群的值班群），问题都结了、安静几天后放回。每次处理都记成案例（包括你自己在群里的回复），处理新消息时参考最相近的案例，攒够了后台按场景整理成经验（包括回完要不要跟、跟到哪算完）；在工作页打开对应工作线，可以在“关注设置”里看设置、经验和案例，也可以点“在关注页打开”。已启用的独立群关注，在规则页的“关注”列表点名称打开。关注页分“在聊什么 / 经验和案例 / 记忆 / 处理记录 / 设置”几个标签看，案例可以标“该回 / 不该回 / 回得不对”。“有人找你”也按同样的案例和经验来。长期分工（报警群、oncall 群…）先建一个处理它的 Agent 档案，再在群里发 `/watch 档案名 [all|mention|keyword:正则] [none|draft|auto]`，或对助理说“报警群的 P0/P1 告警交给 alert-handler，回复前先给我看”。

- `none` 只处理不回复；`draft` 回复先变成草稿卡片发给你，你点“发送”才发出；`auto` 直接用机器人回复（机器人需在群里）。
- 每个群（或话题）是处理 Agent 的一个连续会话，每条消息只处理一次；机器人在群里时实时处理，不在时随采集处理。

读飞书文档评论和读正文是两项权限。助手需要时会单独请你确认只读评论权限，不要求云空间读写；如果已经授权却仍被飞书拒绝，请检查你在那篇文档上的权限。

## Telegram、QQ / 微信与插件渠道

`omem setup` 的渠道部分开启。Telegram 的机器人 token 放在环境变量 `OMEM_TELEGRAM_TOKEN`，再填你的 chat id，私聊、群、论坛话题与飞书一样各是一个会话；QQ / 微信经 OneBot v11 兼容桥（NapCat、LLOneBot 等）接入，没有话题，每个私聊或群一个会话。命令与飞书相同。插件还能通过 `api.channel` 接入其他聊天平台：信任并启用后在 设置 → 渠道 显示，绑定身份才回答，群里只答明确发给它的消息；停用后回复和通知入口一起注销。插件渠道需要选择“在 omem 里运行”，不支持隔离模式。

## 多人使用

omem 默认只服务你自己。要给同事用，在设置 → 成员里打开“多人登录”：

- 从别的机器打开网页会看到登录页，用飞书登录（用的是 omem 自己的机器人应用，先在飞书开发者后台的“重定向 URL”里加上设置页给出的回调地址）。运行 omem 的这台机器、你配对过的设备仍然算作你本人，不用登录。
- 第一次登录的人先进“等待批准”，你在成员页批准，或 `omem user approve <id>`。用邀请链接（成员页生成，或 `omem user invite --space team`）登录的人直接建好账号并加入选的空间。
- 可以设一个主要登录方（比如飞书）：之后只能用它登录，其他方式只在账号页绑定；以前用别的方式建的账号，下次登录要先绑定它。企业外的人用不了飞书登录，可以在他的账号上允许其他登录方式，或者给他令牌。
- 私聊机器人发 `/login`，会收到一个 5 分钟内有效、只能用一次的网页登录链接。
- 可以按邮箱先建好账号（成员页“按邮箱添加成员”，或 `omem user add 小周 --email zhou@example.com --space team`），分好空间：之后谁用这个邮箱来——本企业的飞书账号登录（登录时读飞书的企业邮箱和邮箱，企业邮箱优先），或从命令行带着鉴权插件认得的凭据——就直接对应到这个账号，不用再批准。邮箱对应到多个账号时不自动对应，通知你处理。不用等他登录：他第一次在飞书上找机器人时，机器人用自己的通讯录权限认出他（通讯录邮箱，或账号邮箱在飞书上的 user_id；没写邮箱的账号按名字，只有一个同名账号时才对应），对应到这个账号，之后按他的空间权限回答、不再当访客，并通知你。
- 同事在自己的电脑上用 Claude Code、Codex 等时，运行 `omem login <网页地址>`，在浏览器里登录并确认，再 `omem mcp --url <网页地址>`（他们只需 `npm i -g @omem-ai/cli`，不用装完整的 omem）：工具列表按他的有效能力裁剪，调用以他的身份在获准的空间里执行，每个会话在运行页记成他的一条运行。也可以不走浏览器，给 `OMEM_AUTH_CMD` 一条输出凭据（比如组织内部登录体系的 JWT）的命令，由数据目录里的鉴权插件（`api.authenticator`）验证并认人；内部系统怎么验证写在插件里，不进仓库。账号页“命令行与 MCP”能看到和撤销这些令牌；没有 `tools.external` 权限的角色用不了（内置的管理员、成员、访客都有）。设计见 [docs/v2/remote-clients.md](docs/v2/remote-clients.md)。
- 每个人在“账号”页看自己的登录方式和登录过的设备，可以让某台设备退出；你在成员页能停用账号、让他所有设备退出、调整他能读写的空间。

也可以在命令行登记：

```bash
omem user add 小王 --id wang --lark ou_xxx --space team   # 建用户、绑定飞书身份、可读 team 空间（--edit 可写）
omem user add 小周 --email zhou@example.com --space team   # 按邮箱预建：之后用这个邮箱来的人对应到这个账号（--login-any 允许不用飞书登录网页）
omem user token wang                                # 给他发一个 API 令牌（只显示一次）
omem space share project-a wang [--edit]           # 再开放一个空间
```

成员私聊机器人时，会话进他自己的个人空间，只能检索自己和被共享的空间；`/whoami` 显示他能访问什么。事项和偏好各归各的。每个人有一个全局角色（管理员、成员、访客，或你建的角色），在加入的每个空间里有一个空间角色（只读、贡献者、编辑、管理，或自定义的）：能不能写记忆、写 Wiki、看别人的运行、管空间成员都按角色来；管理员能管理规则，也能改已有 Agent 档案的用途和状态。管理员打开内置角色时可查看用途和默认 AI。系统设置、设备、交办编码只给你。角色之外，成员页每人一个“能做什么”：二十多项能力（看工作线、改事项、看规则、操作运行……）各自跟预设、允许或不给，按空间的能力能逐个空间另设。自己建的空间自己管理，在账号页加人。成员的 Agent 运行只拿到他能用的工具。

成员的 AI 运行沿用你的任务选型。允许借用的后端在你的额度充足时优先用你的登录。额度紧张或已用完时使用成员自己的账号。还没登录时，飞书机器人会发官方授权链接或扫码卡片，完成后继续原运行。群话题里提示等待，授权卡片在同一群里仅发起人可见。额度未知时按逐后端的账号规则处理。

成员可在飞书会话发 `/agent 后端id` 或 `/model 模型名`。加 `save` 保存为个人默认，也可在 **账号 → 个人 AI 设置** 里设默认后端与模型，写一段按任务选 AI 的偏好。偏好会和你的总体偏好、候选适用说明一起交给决策模型。

Linux 上装了 bubblewrap（用系统的包管理器装 `bubblewrap`，或 `osdk pkg apply`；系统要允许非特权用户命名空间）以后，成员可以在账号页“我的 AI 账号”里登录 Codex、TraeX、豆包命令行（设备码或二维码），Claude Code 也能直接登录（在授权页拿到授权码贴回页面），或粘贴在自己电脑上用 `claude setup-token` 生成的令牌；使用成员自己的登录时，额度和使用记录算在他名下：他的套餐额度在他的沙箱里读，显示在他的页面上，选后端时按他自己的额度避让；可选的模型也按他的账号检测。点“登录”后，链接和验证码同时由机器人发到他的飞书私聊。插件可以给某个后端加登录方式（比如用公司的统一身份登录，`api.agentLogin`，见 [docs/v2/plugins.md](docs/v2/plugins.md)），成员在页面上选用哪种，插件登录到期前自动续签，续不了时提醒他重新登录。所有人的 Agent 都以同一个系统用户运行，靠沙箱把各人的账号目录隔开：使用自己登录的成员在沙箱里运行，HOME 是他自己的账号目录，看不到你的登录、omem 的数据目录和别人的账号目录。你开着“接管 Agent 自带的技能”时，omem 的说明和技能分组入口也会写进他的账号目录。你在设置 → 成员 → 成员的 AI 账号 里按后端设允许借用、换别的后端或只用自己的登录，也能看到谁用什么方式登了哪些后端、让他退出；停用一个成员时，他的登录和账号目录一并删除。你在配置里自己加的后端也可以写 `account` 一段，让成员按人登录。macOS、Windows 和没有 bubblewrap 的 Linux 上没有这一项。默认模式下按配置沿用本机环境，运行记录写明未隔离的原因；配置 `agents.accountIsolation` 为 `require` 后，成员只使用能隔离的后端，没有可用后端时会提示原因。`omem diag` 的 `agentAccounts` 显示这台机器能不能用。设计见 [docs/v2/agent-accounts.md](docs/v2/agent-accounts.md)。

成员在编码沙箱里可以直接提交。交办没有指定分支名时，主编码可以给临时分支命名。完成修改项时，宿主校验提交并快进工作分支。每个仓库的原始 Git 公共目录保持只读。

本机使用本人登录的 Agent 也可启用 Linux 只读沙箱，并在隔离成功后统一关闭后端自己的审批。两个开关默认沿用原行为，在设置 → 安全 →“运行的沙箱”“完全访问”里改：沙箱能读你的主目录，只能写列出来的地方，可写和要藏起来的目录在那里增删。见[本人的运行进沙箱](docs/v2/agent-accounts.md#本人的运行进沙箱)。

Linux 严格成员沙箱通过本机代理出网。本人可按主机审批、拒绝或查看运行连接汇总，也可为指定域名开启路径检查。配置见[出网代理](docs/v2/command-gate.md#出网代理)。

除了飞书，内置的“连接平台”插件还能接 Notion、GitHub、Google、Slack、Jira、钉钉、微信等约 500 个平台：你在设置 → 采集 → 其他平台里搜到平台，按提示在平台开发者后台建应用、填回 Client ID 和 Secret（用 key 连接的平台不用这步），再开放给成员；能确认身份的平台（GitHub、Google、钉钉、微信……）还能用来登录和绑定账号，其余只用来读取。成员连接后，直接让助手以他的身份读这些平台（连了平台才有这些工具），把需要的内容存成原件（只读，不会改平台上的东西）。Figma、Notion、GitHub、Google 云盘 / Gmail / 日历、Slack、Jira、Confluence、Linear 有平台包：设计稿、页面、issue、频道消息直接整理成 Markdown，让助手“盯着”某个项目、仓库或频道后，改动会定时同步进来，账号页能看到和停掉。说明见 [docs/v2/connectors.md](docs/v2/connectors.md)。

成员可以在账号页“已连接的应用”里连接自己的飞书，按功能一项项授权（群聊消息、单聊消息、文档与知识库、表格、日程、妙记、让助手写文档；每打开一项跳一次飞书授权页，只要那一项的权限），也可以在登录页先勾好，登录时一起授权。飞书的授权只增不减，账号页每项功能有“omem 是否使用”的开关：关掉的不采集、对应的工具不用，飞书那边的授权要在飞书里撤销。连接以后，他的 Agent 运行以他自己的身份读写飞书（`lark_read`、`lark_write`、文档工具），没连接就用不了，不会借用你的登录；他的助手要用而还没授权时，会把一个预先勾好所缺功能的授权链接发给他，他在飞书里确认后，刚才那个会话自动接着做。消息授权以后默认不采集，只在他让助手看时读；在账号页打开“采集到 omem”的群聊或单聊后，后台采集他最近活跃的这类聊天，存进他的个人空间；打开了日程、妙记、文档的，他的日程、妙记和最近打开的文档也一样。已经在他能读的共享空间里的群、文档、妙记和日程不会再存一份，只记下他也能看到；正文里嵌着表格的文档按各人看到的分开存。同一个聊天或文档在几个空间各有一份时，检索只显示一条，注明另有几处；内容相同的切块只算一次向量。用到的权限要先在机器人应用的开发者后台开通：设置 → 渠道 → 飞书机器人 里的机器人检查会列出成员连接还缺哪些用户身份的权限，“扫码更新”一并申请。令牌加密存在本机 `secrets/vault.db`，不随快照和多台设备同步。空间管理者可以把某份原件设为“受限”（只有记下的人和管理者能看，比如放进项目空间的一段单聊），也可以让空间里的飞书文档按各人的飞书权限显示（成员连接飞书后，飞书说他能看的才显示全文）；这两类原件都不会分享出去，也不会发给别的服务。设计与分期见 [docs/v2/multi-user.md](docs/v2/multi-user.md)。同一台机器、同一个数据目录，不做多租户隔离。

助手读取表格或多维表格时遇到该功能的权限缺口，授权链接会预勾「表格与多维表格」，可一次补齐这组读取权限。文档、消息、日程和妙记也按对应的功能补授权。

登录或连接飞书时勾选「文档与知识库」，会一起申请读取正文、搜索文档、浏览目录和下载文档素材的权限。旧连接缺文档搜索权限时，可在账号页重新打开这一项，供后台找出最近打开的文档。

「让助手写文档」包含新建、编辑、复制、移动文档，以及读取目标正文和定位知识库所需的权限。只勾这一项时，后台不会搜索最近打开的文档。

哪些文档存进 omem 由各人自己定：成员在账号页“采集到 omem”里开关“读过的文档”，下面可以打开“不读我的个人文档库”（成员默认打开），再贴链接排除单篇文档、知识库页面（连同子页面）、整个知识库或云空间文件夹；你自己的在 设置 → 采集 → 飞书文档 的“你最近打开的文档”里设。排除的文档不再被最近打开的采集、它们链过去的文档和（你的）聊天里的链接自动读进来，已经存进来的不删，让助手读的照常读。登录页勾了群聊消息、单聊消息或文档时，下面会多出“存进 omem”的勾选，授权回来时一并生效（文档默认勾上，聊天默认不勾）。

## 多台设备

**和别人的 omem 共享**：设置 → 设备 → 和别人的 omem 共享，选几个空间、每个空间“只检索”或“可同步”、开放哪些内容（Wiki、记忆、文档、聊天……），生成配对码给对方。对方的服务用它自己的服务账号连进来，只能看到这些；你随时可以停止。对方在“关注别人共享的空间”里选你的空间：检索和助手就能查到（助手要引用时先把原件取到它那边一个只读空间，引用按它本机的 id），选“同步”的每半小时把原件、页面和记忆同步过去，引用自动换成它本机的副本；同步过去的内容不会被再整理一遍。令牌只在各自那台，传过去的只有内容。

常见用法是一台机器常驻运行（采集、定时任务），其他机器拉它的数据、看它的状态、让它执行检查。机器之间不必能直接访问：可以经中间那台转发。

```bash
# 常驻那台（默认就监听所有网卡；不是本机的请求没有令牌一律拒绝）
omem peer invite --label laptop           # 打印一行配对码（omem1.…），含本机所有网卡地址；服务不必正在运行

# 另一台
omem peer add <配对码>                    # 直接能访问到
omem peer add <配对码> --via <中间那台>     # 只能经中间那台访问（中间那台先和它配对）
omem peer back <设备> on                  # 反向连接：本机一直连着它，它连不到本机时也能调用本机、借本机的 Agent（off 关掉并撤销令牌）
omem peer list
omem peer name laptop                     # 改本机在设备中的名字（默认主机名，存为配置 node.id）
omem peer url <设备> http://<新地址>:4317   # 对方换了地址、码里的地址都连不上时（不用重新配对）
omem diag <设备>                          # 版本、数量、最近失败、飞书采集状态、Agent
omem peer commands <设备>                 # 可远程执行的命令
omem peer call <设备> logs '{"stream":"out","lines":5000}'  # 气泡请求与成功记录
omem peer call <设备> logs '{"stream":"err","lines":5000}'  # 气泡失败与超时记录
omem peer call <设备> lark-raw '{"command":"+chat-messages-list","chat_id":"oc_…"}'
omem peer call <设备> sql '{"query":"select count(*) from lark_messages"}'   # 只读
omem peer call <设备> update               # git pull --ff-only、安装依赖、构建、重启服务
omem peer call <设备> agents '{}'           # 只读：它上面的 AI 后端、ACP 适配器的已装版本、模型和探测结果
omem peer call <设备> search '{"query":"退款规则","limit":5}'   # 只读：Agent 的 search 工具同一套检索，看真实数据上的命中
omem peer call <设备> prompt '{"space":"personal","role":"coder","task":"…"}'   # 只读：预览一次运行收到的常驻说明（不含令牌）
omem peer call <设备> ide '{}'              # 只读：网页版 VS Code 的服务端版本、扩展与语言包（界面按键翻译了多少）、omem 插件、可复用的设置与扩展、语言和终端设置、日志、进程
omem peer call <设备> replays '{}'          # 只读：夜间复盘的状态（定时、replay-judge 的模型、上次结果或没跑的原因）和最近的结论
omem peer call <设备> quality '{}'          # 只读：每晚抽检统计、加严名单、待检页数和最近 20 条摘要（不含问题正文）
omem peer call <设备> replay-run '{"run_id":"r…","axis":"M1"}'   # 立即复盘一题（不带参数按选题规则挑）
omem peer call <设备> agent-upgrade '{"id":"codex"}'   # 把已装的 ACP 适配器（如 codex-acp）升到 npm 最新版（osdk 管着的用 osdk，其余从 osdk.toml 的公开源用 npm 装），等装完返回前后版本；加 "version":"2.7.0" 装指定版本，这一次不受那台机器 npm 的发布时长下限限制
omem peer call <设备> lark-docs-refresh '{}'  # 让它在后台重新读飞书文档，完成后发通知；进度看 lark-docs-status
omem peer call <设备> lark-docs-refresh '{"metadataOnly":true,"unchecked":true}'  # 只补读从没读过知识库位置的文档的目录（不重读正文），补全原件页的知识库目录树
omem peer call <设备> sources-merge-duplicates '{}'  # 列出同一篇飞书文档的 /docx/ 与 /wiki/ 两份原件；'{"dryRun":false}' 合并（旧 id 保留为别名）
omem peer call <设备> wiki-restore-aliases '{"space":"<空间>"}'  # 列出被重写后丢了旧路径的 Wiki 页面（从知识库 Git 历史找回）；加 "dryRun":false 补回
omem peer call <设备> schedule-set '{"id":"dream","enabled":true}'  # 打开或关闭一个定时任务（只改开关；schedule-run 立即跑一次）
omem peer call <设备> lark-doc-import '{"url":"https://…/docx/…"}'  # 立即读一篇，返回素材下载情况和没处理掉的标签
omem peer call <设备> lark-kb-list '{"status":"proposed"}'  # 能看到的飞书知识库、建议和每晚读的进度；lark-kb-discover 立即发现，lark-kb-read 立即读一批
omem peer call <设备> lark-kb-map '{"kb":"<知识库 id>","action":"accept"}'  # 采纳建议；map / create / ignore / later / reset / pause / resume / update（只改 omem 自己的库）
omem tool --peer <设备> search query=退款     # 用本机的 Agent 整理它的库：工具在它上面执行，每次调用记成它的一条运行；见 skills/omem/SKILL.md“在另一台设备上用这个库”
omem peer pull <设备>                     # 经 HTTP 合并：数据库总会拉，在终端里逐项选知识库、附件、仓库、编码工作区和拉进哪个目录
omem peer pull <设备> --only library,files --to ~/omem-copy -y  # 不询问：只拉这几项，合并进另一个数据目录
omem peer pull <设备> --dry-run           # 预览数据库合并，不改本机数据或仓库
omem peer pull <设备> --prefer-remote     # 知识库页面两边都改过时用对方的版本（本机的存为 .local.md）；自动备份就是这样拉的
omem peer pull <设备> --overwrite         # 停掉本机服务后替换；旧数据库、文件和仓库留备份
omem peer open <设备>                     # 在本机浏览器打开它的网页，经中间机器的也行，不用令牌；交办的预览按原端口号转到本机
omem peer remove <设备>                   # 移除；先请对方撤销给本机的令牌，本机用它的 Agent 一并删除
omem peer acp <设备> <Agent>              # 用它的 ACP Agent（stdio 上说 ACP）；一般不手动运行，由设置 → 设备里打开的 Agent 配置调用
```

网页的 **设置 → 设备** 做同样的事：生成配对码、粘贴配对码添加（可选经哪台转发）、检查在线和版本、改地址、移除；列出拿着本机令牌的设备（最近使用时间），可逐个撤销。

**反向连接**：本机能连到对方、对方连不到本机时（本机在 NAT 后面，或对方只能经别的设备转发到），在 设置 → 设备 里给那台打开“让它反过来连本机”（或 `omem peer back <设备> on`）。本机一直连着它，它要调用本机时经这条连接请本机再连进来一条，在上面走普通的 HTTP：对方的设备列表里会出现本机，`peer call`、请教、借本机的 Agent（下一段）都能用。本机给它签一个本人权限的令牌，关掉时撤销；这样进来的请求一律按令牌认人，不算本机的请求。经中间设备转发的也行，中间那台和对方都要更新到支持的版本。

**用设备的 Agent**：在设备下面打开它的某个 ACP Agent，本机多一个 Agent 配置（`agents.profiles` 里带 `peer: {id, agent}`）。运行时本机启动 `omem peer acp`，经 `/api/peer/acp`（经中间设备的也行）连到对方，对方在自己的数据目录 `peer-acp/<本机名>` 里启动那个 Agent；会话要的 MCP 服务只把名字发过去，对方给 Agent 一个只在这条连接上有效的替身，工具调用回到本机执行。所以 Agent 用的是对方的登录和额度，读写的是本机的库，但看不到本机的文件，编码交办不要选它。对方和中间设备都要更新到支持的版本。

`pull` 单向拉取，不会把本机修改传回去；未配对的主机走 SSH。业务数据包括原件（含代码和工作区索引）、记忆与质量记录、事项和提醒时间、材料关联、会话、运行与事件、代码评审及问题、原件标注和归档信息、学习卡片、规则与定时任务；Wiki、Agent 档案和技能随 `library/` 合并。附件复制整个 `files/`，编码补丁随运行复制。两端都升级后才能传仓库和完整文件目录；拉旧版本的设备时会提示，并补拉能识别的附件。

同一文档按更新时间取较新版本；聊天把远端缺少的消息行追加到本机，保留本机行号，并换算远端记忆、标注、聊天消息和 Wiki 的引用。记忆、事项等按记录 ID 合并，辅助表用跨设备标识区分本地自增编号。没有更新时间的已有设置优先留本机。Wiki、档案和技能走 Git 合并，冲突保留本地，远端另存 `.remote.md`（非 Markdown 文件追加 `.remote`）。合并不传播物理删除；原件墓碑和记忆撤回状态随记录更新。

仓库带 Git 历史、分支、标签、已暂存和未暂存改动，以及未被 `.gitignore` 排除的未跟踪文件；已检出的子模块与交办 worktree 一起保存。不传仓库 hooks、凭据配置或忽略的未跟踪文件。新仓库放在数据目录的 `repos/pulled/` 并关联空间；已有仓库仅在两边工作区干净、同分支且能快进时更新，本地改动和分叉会保留，远端分支放在 `refs/remotes/omem-pull/<空间>/…`，完整远端工作区另留副本。运行中的工作区路径会换成本机副本。

配置、密钥、API 令牌、采集游标、模型和服务日志留在本机；合并时重建检索索引，不复制另一台的向量。新拉来的任务规则、定时任务和存量整理任务先停用或暂停，排队与运行中的远端任务取消，原 Agent 进程会话不恢复，避免两台重复执行。覆盖也会停用任务规则和定时任务；本机服务启动后按需要启用。

设备的名字是对方配置里的 `node.id`（`omem peer name` 查看或设置），没配就是它的主机名；最好在配对之前起好名字，之后改名的话对方那边仍记着旧名字。配对码里是对方的所有可能地址和一个为本人生成的 API 令牌（标签 `peer:<名字>`）；`add` 留下能连上的地址，之后正在用的地址连不上时会自动换码里的其他地址，所以断线、重启、换网后不用重新配对。`omem user revoke owner peer:<名字>` 撤销令牌即解除配对；配对信息存在 `secrets/peers.json`，令牌用 `omem user tokens` 查看。远程命令是固定的一组（诊断、日志、配置、飞书只读查询、手动采集与回溯、记忆统计、运行记录、只读 SQL、AI 后端 / 检索 / 说明 / 网页版 VS Code 的只读查看、git 与更新、重启），没有任意 shell。本机打开网页不需要令牌；要看已配对的设备的网页，最省事的是 `omem peer open <设备>`：本机起一个只给本机用的转发地址，经 `--via` 的设备也能打开（经中间机器时上传文件不可用）。从别的机器直接打开时运行 `omem link`，它打印带新令牌的链接（每个网卡地址一个），打开一次后令牌存在那个浏览器里；也可以在页面提示时粘贴 `omem user token owner` 生成的令牌。

`scripts/relay.mjs` 是一个临时的白名单转发：在只能 ssh 到其他机器的那台上运行（不配置时只有本机目标 `local`，经已配对的设备执行 `omem peer call` / `omem diag`），往 `.remote/relay/inbox/` 放请求文件，它经 ssh 执行允许的命令（omem 子命令、git/pnpm 的检查与更新、lark-cli 只读查询、本机 API 的 GET、几个系统信息命令）并把结果写到 `outbox/`。目标机器在 `.remote/relay/config.json` 里配置，详见脚本开头的说明。

交办时可以先做 Git 同步：拉取目标分支在 origin 上的新提交，再合并或变基到另一个分支（如 main），也可以只同步不编码。冲突先交给编码 Agent 解决，业务上拿不准的它会问你，解决不了的停下来发卡片给你（在工作区里解决后点“继续”，或放弃这次同步）。同步的提交在应用时快进到目标分支；目标分支在交办后又有了新提交、应用不上时，点“移到目标分支最新提交”同步一次，默认合并（merge），也可选择变基（rebase）；目标已经包含在工作区中时直接跳过。已应用的编码改动可在运行详情填写提交信息，选择“提交”或“提交并推送”；也可让主助手通过 `code_git_status` / `code_git_action` 操作。只提交暂存区，未暂存修改保留；默认推送到原分支的 `origin`，也可以推到别的分支，变基过的分支可强制推送（带 lease，远端有别人的新提交时不会覆盖）；失败保留本地提交并可仅重试推送。提交与推送目前走网页或工具，未新增 CLI 子命令。

宿主对同一份材料有几道可以独立回答的判断题时，可用 `decideMany` 合并请求；需要逐题套门槛、留记录时用 `decideSceneMany`。见[决策模型](docs/v2/ai-models.md#决策)。

## 当前限制

- 多人：能登录、批准、邀请，按角色和空间角色管权限，成员能连接自己的飞书，能和别人的 omem 服务共享空间；成员用自己的 AI 账号只在装了 bubblewrap 的 Linux 上有，还没在真机上跑过；成员的后台采集只有聊天，检索结果还不按同一个平台对象合并显示（docs/v2/multi-user.md 的分期），不做多租户隔离。
- 默认监听所有网卡，其他机器必须带令牌（配对或 `omem link`）或登录；在同一台机器上用反向代理对外暴露时，打开多人登录后带 `X-Forwarded-For` 的请求不算本机（代理要传这个头或 `Host`），没打开时经代理来的请求看起来来自本机，要配置 `token`。多台设备是“一台常驻写入、其他来看”，还没有双向持续同步。
- 除 Claude Code、OpenCode 外，其他 ACP Agent 只验证过连接握手；各家登录和模型名以实际“检测模型”结果为准。
- 代码解析：TS/JS/JSX/TSX/Vue 用 TypeScript AST；Python 用导入与缩进分析；Go、Rust、Java、Kotlin、Swift、C、C++、Objective-C、C#、PHP、Ruby、Scala、Dart、Lua、Zig、Elixir、OCaml、ReScript、Solidity、Bash、Emacs Lisp 用 tree-sitter（WebAssembly，无需编译，按需加载语法）；其他语言（Haskell、Erlang、Clojure、Elm…）只做通用声明识别。
- 跨文件调用解析到具体定义：TS/JS/Python 按导入；Go 按包（同目录与导入路径）；Rust 按 `use` 路径、`mod` 和工作区 crate；Java/Kotlin 按包、导入和静态导入（两者互通）；Swift 按整个模块；其余 tree-sitter 语言先看本类型、本文件和导入的文件（`#include`、`require`、`import … as`、`open`），再在同一语言里找唯一的同名定义，有多个同名就不连。对变量调用方法（`db.open()`）需要类型推断，和动态派发、第三方包一样只有名称级候选。
- 扫描版 PDF 需要 OCR，当前只解析文字 PDF / DOCX（Docling、pdftotext 或 pandoc 任一可用即可）。
- 微信只能通过 OneBot 兼容桥接入，没有话题概念，每个私聊或群是一个会话。

## 事项来源与历史关联修复

通知保留本次事件的来源快照，飞书在正文和来源区之间按原件最终 URL 去重。通知附带 HTTP(S) 外链时，飞书卡片显示“打开链接”按钮（事项正文或来源已有同一链接时不重复）；站内路由只在网页使用。事项继续累积有效来源和事件历史；显式 `replace/remove` 可纠正来源，空数组不会意外清空。后台整理可只读发现本人可访问空间中的已有事项，跨空间进展先提交提案，由有权限的主助手复核后应用。

修复历史错关联通过 omem MCP 的 `repair_item_association` 预览和应用，审计用 `read_item_repair`；需要同步原飞书卡片时再调用 `refresh_item_notification`。这些是 MCP 工具，不新增远程任意 SQL 或 shell 命令。部署与数据修复步骤见 [事项维护](docs/v2/item-maintenance.md)。

编码交办的轮次与等待状态在 `src/agents/code-chain.ts`；按修改项推进的交办（修改项、检查点、预算、回退）在 `src/agents/code-tasks.ts`，每轮编码之后的验证、阶段评审和下一步在 `src/agents/code-loop.ts`；飞书进度投递、失败重试与恢复在 `src/channels/lark-code-progress.ts`，投递记录保存在发起 ask 运行的 `output.codeProgress`。恢复步骤见 `docs/v2/acceptance.md` 的“编码进度故障恢复”。
