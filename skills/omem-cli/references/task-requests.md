# 交办与更新事项

先确认 `omem status --json` 中服务可用，再用 `omem agent settings --json` 核对主助手配置。Agent CLI 在服务机器须已安装、登录；沿用已配置模型与 CLI/ACP，不要求本地 Decision 权重。

普通 `omem ask "能帮我建个买牛奶的待办吗？" --json` 可以交办。后续更新沿用返回的 conversation.id，例如 `omem ask "能把刚才那条标为完成吗？" --conversation CONVERSATION_ID --json`。也可明确写出事项名称；同名事项给出项目与内容区别。纯查询用 `--research`，它不会应用事项操作。

主助手先读取现有事项并提出候选。独立会话再核对完整本人原话及实际对象，判断执行、拒绝或含糊；疑问语气不直接否定交办，否定须按其作用范围处理。指代可以依赖近期本人原话或实际操作回执，候选列表中只有一个事项并不能填补对象缺口。截止时间与提醒时间分别核对，模型不能从项目截止日期补出新提醒的截止。

只有持久回执可证明已创建或已更新，模型回答和候选不能证明成功。用 `omem tasks list --json` 核对事项及版本；变更沿用同一事项，不重新创建。主助手没有提出候选时不会额外调用判定模型，普通查询和已完成请求重放也不再次判断。

模型不可用、对象未确定或请求取消时不应用，不回退动词词表。没有收到成功回执时先查看返回的拒绝原因，补充具体事项或核对 Agent 连接后再尝试；版本已变化则重新读取现状。自然语言识别仍可能出错，有限合成样本通过不代表总体准确率，独立调用会增加等待。

当前这条语义判断已覆盖普通待办创建及完成、重新打开、改期、等待、暂缓提醒和取消的候选。开发交办和其他工作操作仍有旧规则，不能据此认为全部操作已经迁移。它不绕过本人身份、可见范围或 MemoryService 写入规则，也不直接发送外部消息。
