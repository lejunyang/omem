# Agent、技能与运行（agents）

## 档案与交办

- `list_agents`：本人建好的 Agent 档案，同时列出可以教的内置角色。
- `run_agent(name, task, own_topic?)`：交给专门的 Agent。多步或长任务用 `own_topic=true`：工作在独立会话（飞书话题）里进行；每轮 Agent 交回报告后，omem 的主助手在工作会话里接手，决定继续交办、汇报或请本人决定（本人上次说话后最多自动推进若干次，可在设置里调），回复和折叠的完整报告只在话题里发一次。
- 已经在这个话题里时再调用 `run_agent(own_topic=true)` 会续在同一项工作上（不传 `name` 沿用上一轮的 Agent，传 `work_id` 指定哪一项），同一个 Agent 接着它上一轮的会话。
- 没有专门档案的一次性任务可 `run_agent(name="assistant", …)`，继承调用者的工具、空间和发送范围，不能再交办；不用为临时换模型新建或修改档案。
- `ask_agent(name, question)`：向另一个档案请教并同步拿到回答（被请教的不能再请教或交办）。别的 omem 的 Agent 写 `name: "<档案>@<节点>"`（常驻说明里“网络里的其他 omem”列出了有谁、各自做什么）：它在对方那台上用对方的 AI 和对方共享出来的资料回答，只读；回答里的引用在这台订阅了对应空间时会落成本机的原件，否则会说明打不开。问题属于对方领域时用它，只是查对方共享的资料用 `peer_search`。
- `save_agent`：建或改档案，只在本人要求时做；档案正文只写稳定的职责和原则。`tools` 写工具名，或 `group:<分组 id>` 给一整类（这个分组以后加的工具自动带上），`-<工具名>` 从中排除一个，如 `[group:read, group:wiki, -write_page]`；只要少数几个就直接列名字，不存在的分组会被拒绝。档案 frontmatter 的 `traits: [research]` 表示它是研究档案（查本库之外的材料），夜间复盘的 R3 轴会交给它；`mcpServers: [docs-search]` 引用本人在 Agent 页配置的 MCP 服务，只给本人运行使用；夜间复盘只放行标为只读的服务。旧内联 `mcp` 仍支持，其中标 `readOnly: true` 的服务器才会在复盘时放行。
- 交办前看 `list_agents` 里对方档案的工具：做完这件事要用、它又没有的，那一步自己先做，或 `run_agent` 带 `extra_tools: [工具名]` 借给它这一轮（只在这一轮有效，下一轮要用再借）。只能借你这次自己能用的工具；以本人身份写飞书（`lark_write`、`lark_doc_*` 的写入、`lark_invite`）、在群里发消息（`lark_send` 等）、再交办（`run_agent`、`delegate_code` 等）和角色专用的交结果工具借不出去，这类步骤让对方把内容交回给你来做。借出的工具照样按本人的权限和这一轮的空间范围检查。
- 过程消息（设置 → 通知与打扰 → 过程消息，默认“只在完成和卡住时发”）：协调这一轮调用了 `run_agent` 排出下一轮、没有 `ask_user`、也不是在回答本人在话题里说的话时，这一轮的回复只留在工作会话里，飞书话题里只有一张原地更新的进度卡；做完、要本人决定或卡住、交办失败时的回复照常发出。所以接着交办的那一轮写一两句记录即可，要本人看的写在停下来的那一轮。

## 并行任务板

几块调查可以同时开始，而且每块都能写清交什么材料算完成时，用 `dispatch_work` 一次派出 2～6 块。一两步就能做完的直接做。后一块依赖前一块结论的，留到前一块交付后再派。

- 给每块写 `title`、`goal` 和 `accept`。例如核对两份清单时，分别说明清单的日期、去重口径和差异行出处。可选 `agent` 指定档案，`execution` 指定后端或已配置的 strong、standard、cheap 档。补充材料可设 `required: false`。默认每板同时执行 3 块，截止时间从派出算起，默认 30 分钟。
- 每块可带 `device`（已配对的设备 id）和 `mode`。默认 `borrow`：只借对方 ACP 后端，在本机读库；要对方目录或登录时用 `remote`，在对方起运行。`space` 指定同名空间，默认当前空间；空间对不上或配对权限不足会拒绝。`remote` 默认 `access: "read"`，`write` 只开放记忆、页面和事项写入，须两边都有空间写权限且对方允许接写任务。对方按自己的档案名找，找不到用主助手；后端由对方选，模型和强度只是偏好。
- `list_ai_backends` 和派发返回的 `devices` 列出在线设备的名字、后端空位与仓库空间名称和数量，不含库里的内容。只需要空位选 borrow，需要环境选 remote。对方 `node.acceptWork` 默认 off，可设 read 或 write；`node.acceptWorkFrom` 按配对令牌标识覆盖。
- 工具返回 `work_id` 和各块 id。告诉本人已经分头在做，结束本轮。本人问进展时，用 `work_status(work_id)` 看各次尝试的模型、排队和执行用时。
- 问整件工作时，传 `work_status(item_id)`；从某次运行追问，传 `work_status(run_id)`。两者返回分块的文字进度、等待原因和输入输出 token。每次只传一种标识。合计含重做和子运行，共用运行只计一次；有缺报时只报已记录的数。
- 必选块交齐后，按各自的 `accept` 查报告。长报告按续页提示调用 `read_run(run_id, offset)`，直到读到所需依据。抽查原件行号和数据口径，对便宜模型给出的数字重算一遍。对协调消息标出的本轮验收 ID 用 `work_review(work_id, decisions)` 接受、退回或标阻塞。可选块仍在执行时，可以先汇总必选结果。退回写明缺的证据，可以换模型、设备或模式；不填沿用上次设备，`device: "local"` 回本机。每块最多重做两次，沿用原 id。对板上的块重试或换模型也走这次验收，原运行链接仍可查。重做后结束本轮，下一轮再验收。
- 本人撤销时用 `work_cancel(work_id)`，指定 `task` 只取消一块。汇总时逐条标明依据来自哪一块，阻塞的写明缺什么材料。每次远端尝试带期限和幂等键，本机约每 10 秒查状态；失联超过一小时或到期记失败，可按原块重派。重派和取消之后的旧结果只记迟到。取消会通知对方，离线时继续收尾。结果中的对方原件引用标明在哪台查看；小产物带回，超限产物给出对方运行页。任务板工具不能通过 `extra_tools` 借出。

## 选 AI

- `list_ai_backends()` 返回可用后端、默认模型、缓存的模型 / 强度、各模型现在的占用与上限（`limit` 为 0 是本人不想自动用的，不要选）、近 7 天的完成和失败，以及本人的任务选型偏好；同一账号的命令行后端不单独列出；传 `profile` 可检测该后端，`refresh: true` 强制刷新。模型上的 `replay28d` 是夜间复盘近 28 天的单变量对比（同一题只换模型重答后盲评）：`type` 题型、`vs` 对照的模型、`w/t/l` 胜平负（从这个模型看）、`tokens` 上下文峰值之比，少于 3 次的不列；样本小，只作参考，不要因此改档案的默认模型。后端上的 `quota` 是本机登录账号的套餐额度：`windows` 每项 `used` 已用百分比、`resetsIn` 多久后重置、`perDayLeft` 一周这类窗口剩下的平均到距重置的每一天（%/天）；有 `avoid` 的账号快用完了（本人在设置里定的阈值），同样合适时选别的，本人偏好里写了额度条件的按这些数字对照。准备临时换 AI 时先核对，未知选项不要猜；同样合适时选空闲的。豆包（`tools: false`）用不了 omem 工具，交给它时把材料原文写进任务。
- `run_agent`、`ask_agent` 可传 `execution: {profile, model?, effort?, source: "user" | "auto", reason}`；`profile` 是后端 id，`name` / `agent` 仍是档案名。本人明确指定填 `user`，助手根据任务选择填 `auto`；关闭自主选型时后者被拒绝。普通 Agent 工作的后续轮次需继续显式传入本人的指定。选择只作用于任务并留运行记录；更换后端或模型时使用新会话并携带工作经过。
- `switch_run_ai(run_id, execution, with_children?)`：给已经安排的运行换 AI（后端一直排队或失败、本人要求中途换模型）。排队中的直接改，进行中的停下后重新排队，失败的用新 AI 重试，默认连同子运行（如 Wiki 各页写作）；编码交办改用 `continue_code_run` 的 `execution`。 运行是对话轮次（ask）时，换的是它所在会话的后端、模型和强度（等同 `/agent`、`/model`），这一轮重新排队后和之后的轮次都用新的 AI、开新会话。

## 技能与改进

- `list_skills` / `read_skill`：本人沉淀的做法。`read_skill(name, file="references/checks.md")` 可读技能内的多层附属文本文件；返回的文件列表使用相对路径。不接受越界或符号链接，文本限 2 MB。
- 技能分组：从 Agent 自带目录接管来的技能（以及本人分过组的）按组给出，技能目录里每组一行。`read_skill(name="<组名>")` 返回这一组按用途列出的技能，大组的各用途说明在 `file="purposes/NN.md"`；`list_skills(group="<组名>")` 列出组里全部技能、用途和是否停用。
- `organize_skills`：改技能的分组（`group`，null 移出）、组内用途（`purpose`，几个字）和开关（`enabled`），改组的标题、说明（`description`：做哪类事时该读这一组，Agent 平时只看得到这一句）和整组开关；一次可改多项。本人说“把某组按用途整理一下”时，先 `list_skills(group=…)` 看全组，按用途归成几类（每类几个到几十个），写好组说明后一次提交。你按本人的话改的分组和用途记为本人定过，后台的技能整理角色（新技能进来、说明变了时自动跑）不会再改它们。
- `save_skill`：把可复用做法存成技能；`agent="档案名"` 保存后直接挂到该档案或内置角色（主助手教档案时用；内置角色会先复制成本人的自定义版本），档案内运行不填默认挂当前档案，`attach: false` 只建技能不挂；名字不存在会报错。
- 做梦提炼某个档案或角色的经验目录时，用 `save_skill(agent="名字", draft=true)` 挂到原归属；正文保留 `mem:` 出处。草稿交给夜间复盘 K1 试用，达到启用门槛后才生效，原经验保留。
- `propose_profile_change(target, kind, title, reason, …)`：给档案或内置角色提改进建议（`prompt` 新正文、`skill` 新技能全文、`settings` 加减工具和技能），本人在 Agent 页采纳后才生效；偏好和经验直接 `remember(agent=…)`。

## 运行记录

- `revise_reply_outcome(run_id, label, why)`：`read_run` 里有“按后续消息标的结果”时（回答发出几小时后，按之后大家说的话由决策模型标的：解决了、被追问、被纠正、别人接手了、看不出），你读了那几句话确定它标错了才用；`label` 写英文的那个词（resolved / followup / corrected / taken_over / unrelated），`why` 写哪句话说明了什么。原标注保留，之后以你的为准。本人在运行页改过的不能再改。
- `review_reply_outcomes(verdicts)`：只给夜里复查回复结果的 outcome-reviewer 交结论。任务里每条回答给一个 `{run_id, label, why}`，`label` 多一个 `silent`（发出后一整天里没人就这件事说过话）；和第一遍一样记为同意，不一样就改判，第一遍的标注留着。不在这次任务里的、本人标的、按表情记的、已经被改判或复查过的会跳过。
- `list_runs` / `read_run`：查运行的状态、输入输出和子运行。`read_run` 单列思考气泡的 `thinkingDelivery` 错误，它是投递状态，任务成败看运行 status。
- 任务后面的“同时在办的相关工作”列出和这次同一个会话、同一条消息或同一件事项的其他运行（进行中或 30 分钟内结束）：先 `read_run` 看它做到哪，不重复做。
- `take_over_run(run_id)`：本人在问的事正由后台运行（巡检、有人找你的处理、盯群、唤醒、规则的 Agent）在办，由你来答更合适时，停下它并拿到它最后写的文字、工作文件、碰过的事项和已经发出的消息，接着做；已结束的也能取结果。只能接手同一个人的后台运行，编码交办和评审用 `stop_code_run`。
