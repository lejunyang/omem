# 流程：一件事的阶段和关卡

流程是一份阶段清单，挂在事项上。每段由运行、编码交办、方案或本人承担，也可以只等。前提都已完成或跳过才开始；条件拿不准、关卡要求本人确认或连续自动开始达到上限时，宿主问本人。确认只认事项本人的回答，等待多久都不会自动通过。

| 工具 | 参数与用法 |
| --- | --- |
| `list_flows` | 不填列定义（id、名称、说明、阶段名）；填 `item` 返回这个事项适用的流程 id。 |
| `save_flow` | `yaml` 是整份 YAML。先给本人看阶段、承担者、关卡与完成要求；本人选“启用”才保存。只用于主人的共享定义。 |
| `flow_start` | `item`、`flow`；一个事项同时只能有一个进行中的流程。开始时复制定义，之后改模板不影响它。 |
| `stage_report` | `item`、`stage`、`state: done / blocked / skip`、`note`；可带 `evidence`、`waiting_on`。做完须有依据，卡住写等谁或等什么，跳过写理由。 |
| `stage_reopen` | `item`、`stage`、`reason`，可带 `refs`。该段重新开始，下游已完成的变成待复核，已跳过的保持跳过。 |

`read_item(item_id)` 的 `flow` 返回流程摘要、阶段状态、进入时间、承担者、等待对象、依据和最近 50 条日志。工具只能修改本次运行可写空间里、属于调用者的事项。

依据可以是 `src:<原件id>#L起-L止`、运行 id（也接受 `run:<id>`）、`code-work:<交办首轮id>` 或 `design:<方案id>`。必须是调用者可读的材料。`done: confirm` 时交结果会另问本人，不能代答。本人说还不行会把理由交给同一承担者重做，第三次仍未通过就卡住；运行结束却没交结果也会卡住，不自动重试。

定义格式见 `docs/v2/flows.md`。第一期支持 `by: {run: {agent?, skill?}}`、`by: {object: code-work / design}`、`by: owner`、`by: wait`；`needs` 只指向更早的阶段，不填等上一个、`[]` 无前提。`when` 与文字完成要求最多 300 字，`note` 最多 1000 字。`done` 可用 `confirm`、一句话或已有对象状态。person、signal、插件对象留待后续阶段。定义在 `library/_flows/<id>.yaml`，内置模板只补缺。

阶段运行复用事项材料和会话摘要，使用 `note` 说明这段做什么；`agent` 可以是内置角色或 Agent 档案，不填用主助手，`skill` 只给这一轮。流程监听已有对象和运行事件，更新同一张进度通知；流程走完不关闭事项。网页流程条和飞书进度卡的专门版式尚未实现。
