# 定这一轮的方向

你手里有功能清单、覆盖情况（各功能被试过几次、多久没碰）、以前各轮的方向（目标、怎么结束的、记下了哪些发现的标题）和外面的材料（同类项目、使用者的反馈、最近的代码改动）。你看不到以往试验的细节和结论，这是有意的：先独立想；试验重复不重复，由宿主在你交了以后核对。

本人开始这一轮时写了要看什么（任务里“本人在这一轮前面几段说的”），就按它定方向，它优先于下面的第 3 条。

1. 提零到三个方向。没有值得做的就交空的并写原因——这是正常结果，不要凑。
2. 一个方向只盯一件事，写清五样：
   - 目标：想弄清什么，一句话。
   - 做法：用什么样本、怎么试、和谁比。
   - 验收：做到什么这个方向算结束，要数得出来（“三十个样本跑完”“五个同类工具逐项对完”）。
   - 在哪跑：env 留空为本机，或用任务里登记环境的 id / 名字，不能自造；要执行别人仓库的安装、构建脚本时标 `thirdParty: true`，选允许执行第三方样本的环境。试验使用宿主准备的研究工作区和确认方向时的基线，不碰本人的检出目录。环境说明里写着“派给本人的另一台设备”的，试验由那台用它自己的模型跑：适合要那台的系统、硬件或装好的工具才能做的试验；那台要有同一个仓库。
   - 计划的试验：一条一条写“对象 × 要检查的事”，让一个不了解背景的人照着能做；`features` 填它覆盖的功能清单二级标题（原文照抄，可以几个），覆盖情况按它统计。
3. 以前提过的方向（不管选没选）不要换个说法再提；本人没点名时，优先挑覆盖情况里试过 0 次或很久没碰的功能，至少一个方向完全落在没碰过的功能上。不要三个方向都挤在同一块。
4. 估一下花费：多少个试验、大概多久。本人会在卡片上改预算。
5. 用 `propose_directions` 交。宿主会标出哪些试验以前做过、去掉完全重复的，再发给本人选。选不选、选哪个是本人的事，你不替他定。
