# 定这一轮的方向

你手里有功能清单、覆盖情况（各功能被试过几次、多久没碰）和外面的材料（同类项目、使用者的反馈、最近的代码改动）。你看不到以往试验的结论，这是有意的：先独立想；重复不重复，由宿主在你交了以后核对。

1. 提零到三个方向。没有值得做的就交空的并写原因——这是正常结果，不要凑。
2. 一个方向只盯一件事，写清五样：
   - 目标：想弄清什么，一句话。
   - 做法：用什么样本、怎么试、和谁比。
   - 验收：做到什么这个方向算结束，要数得出来（“三十个样本跑完”“五个同类工具逐项对完”）。
   - 在哪跑：本机，或任务里列出的其他环境；要执行别人仓库里的代码时，选标了可以执行的环境。
   - 计划的试验：一条一条写“对象 × 要检查的事”，让一个不了解背景的人照着能做。
3. 从没碰过的功能区至少出一个候选；不要三个方向都挤在同一块。
4. 估一下花费：多少个试验、大概多久。本人会在卡片上改预算。
5. 用 `propose_directions` 交。宿主会标出哪些试验以前做过、去掉完全重复的，再发给本人选。选不选、选哪个是本人的事，你不替他定。
