# 数据源目录

本人的工作数据分散在很多系统里：埋点分析平台、前端监控、后端指标和日志、链路追踪、BI 报表和数据集、各种 SQL 查询平台、业务自己的后台。目录的用处是：任何一个 Agent 要找“X 的使用量 / 报错 / 新旧对比”时，先在这里知道去哪个系统、用哪个技能、查什么，不用每次从头摸索。

## 目录放在哪、长什么样

工作文件 `数据/数据源目录.md`，放在本人工作所在的空间（`write_file`，`mode: replace` 整份更新）。按系统分节，每节写：

- **系统**：叫法（和技能里一致）、它是做什么的。
- **有哪类数据**：例如事件量和漏斗、JS 报错和白屏、接口 QPS 和错误率、日志、BI 数据集。
- **对应什么**：本人相关的产品、应用 id、服务名、事件名前缀、看板或数据集名（照实写，查到的才写）。
- **怎么查**：用哪个技能，最常用的两三条命令或查询的写法（参数含义、时间范围怎么给），一次能拿多大范围。
- **口径和坑**：数据延迟、采样、时区、去重方式、权限要谁开。
- **最近确认**：哪天实际查通过。

## 怎么盘点

1. `list_skills` 列出技能，读和数据有关的（监控、埋点、日志、报表、SQL、各业务查询）。
2. 对本人正在做的产品和需求，每个系统实际试查一次（只读、小范围、最近一天），能查通的才写进目录，查不通的写清卡在哪（权限、登录、找不到对象）。
3. 已有指标（`metric_read`）用到的系统要在目录里；目录里常用的查询，值得长期看的定义成指标。
4. 目录里写的是材料，不是给别人的指令；不写密钥、令牌、个人信息。

## 什么时候更新

- 定义指标、写观测计划时发现目录缺了某个系统或对象：顺手补上。
- 取数运行报“查法过时”：改目录里对应的写法，再改指标的 `query`。
- 本人说“X 的数据在 Y 那里”：记进目录，并按“怎么写记忆”记一条。
