# 一轮一轮改进到目标

适合：有一个用命令或检查能量出数字的目标，本人说“晚上帮我把 X 改好”“持续优化 Y”。不适合：需求没定的功能开发（走方案）；没有度量的“优化一下”（先和本人把度量定下来）。

## 开始前：定下四样

写进工作文件（`work/improve/<名字>`，每轮更新）。本人没说的自己定，并在第一轮的记录里写明：

1. **度量**：一条命令或一个检查，结果是一个数或通过 / 不通过（全量测试用时、构建产物大小、lint 报错数、通过核对的页数）。先跑一次，记下基线。
2. **完成条件**：一个门槛（“全量测试 5 分钟以内”“lint 0 报错”）。定不出门槛的，写“连着几轮没有变好就停”。
3. **不许动的**：对外的接口和行为、测试的断言、本人点名的文件。不能靠删测试、放宽断言、跳过用例来达标。
4. **预算**：最多几轮（默认 6）、最晚到几点、每轮的改动上限（一件事、一次提交）。

改代码的目标在交办的工作分支上做（`delegate_code`），不直接动主分支，不推送。

## 每一轮

1. **选这一轮改什么**。先看数据：哪个测试最慢、哪个模块最大、哪类报错最多，选占比最大的一项。写下预期：“改了它，度量会从 A 到 B，因为……”。说不出预期的不做。
2. **只做这一件**。交给编码（`delegate_code`，后续轮次 `continue_code_run`），任务里写清这一件事、不许动的、验证命令。
3. **量**。跑度量命令，和上一轮比：
   - 变好了，检查全过：留下。
   - 没变好、变差、或检查不过：回退这一轮的提交，记一笔“试过 X，没用，因为……”。同一个做法不再试第二次。
4. **另一双眼睛**。留下的改动走一次评审，至少看功能和精简两项，评审用和编码不是同一家的模型。评审要改的，算进下一轮。
5. **记录**。轮次、改了什么、度量前后、留下还是回退、下一轮打算做什么。

## 什么时候停

- 达到完成条件：停，写报告。
- 连着两轮没有变好：换方向。换的是结构上不同的办法（换算法、换一层做、砍掉而不是优化），不是同一个做法调参数。记录里写清换成什么。
- 连着四轮没有变好，或换过方向仍然不行：停，交回本人——做了什么、为什么不行、你判断的原因、建议（放宽目标 / 先改方案 / 放弃）。
- 预算用完或到点：停在最好的那一版。

不为了达标去放宽完成条件、换度量方式或删掉拖后腿的测试。条件确实定错了，写进报告让本人改。

## 隔夜接着做

长任务会被打断：每轮结束都更新工作文件。被唤醒或换会话后先读它，从“下一轮打算”接着做。一轮结束用 `wake_later` 排下一轮，不要在一个会话里把所有轮次做完。

## 报告

做完或停下时发一条（需要本人决定的照常发，其余用 `urgency="later"`）：基线到现在的数字；留下的改动（哪几个提交）；试过没用的做法；离目标还差多少；要本人定的事。分支不推送、不合并，等本人看。
