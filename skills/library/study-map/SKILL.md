# 梳理功能清单

目标是一张别人照着能把这个项目“用一遍”的清单，不是代码结构的复述。

1. 从使用者的入口读起：README、命令行的子命令和参数、配置项、对外的接口、界面的页面。每个入口是一条功能。
2. 每条写四样：是什么（一句话）；怎么触发（命令、配置、调用，能照着做）；现在有哪些测试盖着它（文件和用例名，没有就写没有）；依赖什么环境（系统、网络、账号）。带代码引用。
3. 按使用场景分组，二级标题是功能名——之后统计“哪些功能试过”就按这些标题对。一个功能一个标题，不要把十个子命令塞进一条。
4. 读不懂的、文档和代码对不上的，单独列在最后一节“没弄清的”，不要猜。
5. 写成一份工作文件（路径在任务里），结束时 `stage_report` 的 `evidence` 填它，`note` 写共多少条、没弄清的有几处。

不评价项目好不好，不提改进建议：那是后面每一轮的事。
