# 插件

有些事不适合一问一答：出一组题、你一次提交、看完结果再出下一组；或者一块每秒刷新的机器状态屏。机器人只适合一条一条地说，这类强交互放在插件的页面里做。

一个插件把一类事需要的东西打成一个包：

- **Agent 档案**：理解和出主意的那个“人”，和其他档案一样出现在 Agent 页，能换模型、挂技能、有专属记忆、被每晚复盘；
- **技能**：这类事的做法，首次启动补进技能库；
- **工具**：插件自己注册的工具（判分、查数据、调服务），加上清单里列出的 omem 工具；
- **数据**：插件自己的存储，按用户隔开；
- **页面**：出现在侧栏，有自己的设置。

内置插件有两个：[英语练习](./english)，以及“连接平台”（见下文）。

## 页面里怎么交互

Agent 不靠输出一段 JSON 和页面打交道，而是调工具交出一个**内容块**：一组题、一张表单、一张图。参数由插件声明的格式校验，不合格的直接退回给 Agent 改。你在页面上做完点“提交”，插件能确定的当场判分（答案只在服务端，提交后才给页面看），结果整理成一条消息回到同一个会话，Agent 接着点评、出下一组。

每个插件都能用的通用块：

| | |
| --- | --- |
| 表单 | 文字、多行、数字、单选、多选、1–5 打分，可标必填 |
| 图表 | 柱状图或折线图，深浅色各一套配色，悬停看数值，能展开成表格 |

所以一个没写一行代码的插件，也能让 Agent 发表单给你填、画图给你看。

## 自己做一个

在数据目录（默认 `~/.omem`）建 `plugins/<id>/`，写一份清单和一个档案就够了：

```yaml
# ~/.omem/plugins/journal/plugin.yaml
id: journal
name: 每日复盘
agents: [coach]          # 档案在 agents/coach.md，对外名字是 journal-coach
tools: [recall, remember]
page: { title: 每日复盘 }
settings:
  - { key: tone, label: 语气, type: select, options: [温和, 直接], default: 温和 }
```

重启后侧栏出现“每日复盘”。没有自己的页面时，omem 给它一个默认页：和它的 Agent 对话，Agent 用表单和图表和你交互。设置项在页面右上角的“设置”里改。

侧栏图标由插件自己定（`icon`），不喜欢就在 设置 → 插件 里点图标换一个。插件的档案在 Agent 页改过之后存一份你的版本，删掉就回到插件自带的。

## 带代码的插件

- **`server.ts`**：注册自己的工具和内容块（含判分）。会在机器上动手的工具（点击、输入）可以标成每次都要你批准。
- **`services`**：声明一个常驻进程（每秒采一次机器状态、截屏、连设备），只在本机监听，第一次用到时启动，闲着自动停。
- **流**：页面通过 omem 和服务保持 WebSocket 连接，二进制帧直接转发，截屏这类每秒几帧的数据也能实时显示。
- **自己的页面**：任何前端写法都行，用插件 SDK（npm 上的 `@omem-ai/plugin-sdk`）和 omem 通信，拿到 omem 的样式和主题。
- **语音**：清单写 `voice: true`，页面就能用 `omem.voice()` 和语音模型（设置 → AI → 语音）对话，说明由插件给。麦克风和连接在 omem 自己的页面里，插件页面只拿到两边说的文字；只在你点了按钮之后开始，进行中顶上一直显示“正在使用麦克风”和“结束”。英语练习的[口语对话](./english#口语对话)就是这样做的。不需要写代码。
- **连接器**：插件可以带一个让人连接的平台（授权方式、令牌交换、“我是谁”、功能和权限）。每个人在账号页连接自己的账号，插件的工具以用的那个人的身份调这个平台；令牌由 omem 保管，只发往插件声明的接口地址。

例子：一个四个文件的“看机器状态”插件。服务每秒推 CPU 和内存，页面画两条进度条实时更新；问它的档案“机器现在负载怎么样”，档案调插件的工具读当前值回答。

### 信任

数据目录里的插件带代码时，代码以你的身份运行，所以**你确认之前一行都不运行**：清单、档案、技能和页面照常可用，工具和服务不启动。在 设置 → 插件 点“信任并运行”，立即加载；代码一改就要重新确认。那里也能看服务在不在跑、最近输出了什么，随时撤销信任。

## 安全边界

- 插件页面在隔离的框架里运行，拿不到你的登录令牌和 Cookie，只能读写这个插件自己的数据、和它自己的 Agent 对话；用语音时也拿不到麦克风和录音，只拿到转写的文字。
- 服务拿不到 omem 的令牌和密钥类环境变量，只认带自己令牌的请求。
- 公司内部系统可以做成插件放在你的数据目录里，不进 omem 的仓库。

## 在飞书里

在飞书里让插件的 Agent 干活（比如 `/as english-tutor 来一组面试的题`），它把内容放进插件页面的一个新会话，回一个链接给你。设置 → 设备 填了“网页地址”时，这个链接在飞书里能直接打开。

设计细节见仓库里的 `docs/v2/plugins.md`。

## 连接其他平台

内置的“连接平台”插件把 Notion、GitHub、Google（云盘、邮件、日历）、Slack、Jira、Confluence、Linear、钉钉、微信、Gitee、语雀等约 500 个平台接进来，平台列表取自 Nango 的开源目录，国内平台另外补充。

- **能确认身份的平台**（GitHub、Google、微软、钉钉、微信、QQ……）：可以用来登录 omem、绑定账号，也能读取。
- **其余平台**：只用来读取。连接后只保存令牌，不当作身份。

接入步骤：

1. 你在 **设置 → 连接 → 其他平台** 里搜到平台，按提示在它的开发者后台建一个应用，把给出的回调地址填进去，再把 Client ID 和 Secret 填回来。用 API Key 连接的平台不用建应用。
2. 把平台开放给成员。
3. 每个人在 **账号** 页连接自己的账号（或者填自己的 key）。

连了平台以后，直接告诉助手要哪个平台的哪些内容，它以你的身份读，再存成原件，之后可以检索、引用，也可以整理进 Wiki。它只能读，不会改动平台上的内容；同一项内容再采一次是更新，不会重复。

Figma、Notion、GitHub、Google 云盘 / Gmail / 日历、Slack、Jira、Confluence、Linear 各有一个平台包，读出来的是整理好的正文：Figma 文件按页面和画框列出文字和评论，Notion 页面保留标题、列表和表格，Slack 一天的消息带着线程。让它“盯着”某个 Figma 项目、GitHub 仓库或 Slack 频道，之后的改动会定时同步成原件，账号页能看到同步情况，随时停掉。
