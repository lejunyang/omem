# 插件与场景包

有些场景装不进普通的“一问一答”聊天框里：比如一次出一组英语练习题、你做完统一交卷判分再练口语；或者需要把公司内部的工单、发布、鉴权系统接进 omem 的工作流。

**插件（Plugins）把处理一类事所需的所有组件打包在一起**——小到**不写一行代码**就能拥有带表单和图表的专属页面、一键导出分享给同事的**场景包**，大到接入 **500+ 外部平台连接器**、嵌入事项流程关卡或提供统一身份凭据。

## 1. 不写一行代码：做一个自己的插件，或导出“场景包”

### ① 零代码插件：一份清单 + 一个档案 = 专属交互页面

在数据目录（默认 `~/.omem`）下新建 `plugins/<id>/plugin.yaml` 和一个 Agent 档案 `agents/coach.md`：

```yaml
# ~/.omem/plugins/journal/plugin.yaml
id: journal
name: 每日复盘
agents: [coach]          # 档案在 agents/coach.md，对外名字是 journal-coach
tools: [recall, remember]
page: { title: 每日复盘 }
settings:
  - { key: tone, label: 语气, type: select, options: [温和, 直接], default: 温和 }
```

重启后，左侧导航就会出现**“每日复盘”**。你不需要写任何前端页面代码，omem 会自动为它提供一个默认页：它的 Agent 直接调用通用内容块给你**发表单**（单选/多选/文本/数字/1–5 打分）、**画图表**（柱状/条形/折线/面积/饼图）和**展示带涨跌走势的指标卡**；它的档案也会出现在 Agent 页，照常拥有专属记忆并接受每晚复盘。

<Shot src="plugin-default" caption="零代码“每日复盘”插件：仅靠一份 YAML 清单和一个档案，即可在默认页里由 Agent 发表单、画图表交互" />

### ② 打成“场景包”（把整套工作配置一键分享给别人）

不带代码的插件叫做**场景包**。当你调好了一套空间目录、Agent 档案、技能、规则、事项流程和 MCP 服务定义，想发给团队同事直接用时：
- 在 **设置 → 插件 → 打成场景包** 勾选要打包的项（或运行 `omem plugin pack --id projecta --name "项目 A" --agents helper --skills project-guide`）。
- **自动防泄密检查**：打包绝对不会导出 MCP 密钥值；若文本里不小心包含了已存密钥或你本机的用户目录绝对路径，打包会直接拦截并精确报告到文件与行号。
- **对方一行命令安装**：同事拿到目录后运行 `omem plugin install ./projecta-pack`，空间结构、档案、技能和流程就会自动补齐（同名已有配置绝不覆盖，导入的规则默认停用等对方核对，无代码无命令的场景包无需额外信任审批）。仓库里的 `examples/plugins/ghdelivery` 就是一个完整的 GitHub 需求交付场景包示例。

## 2. 内置“连接平台”插件：接入 500+ 外部平台与定时同步

除了内置的[英语练习](./english)插件，omem 还内置了**“连接平台（`connect`）”**插件，基于 Nango 开源目录并补充国内平台，支持接入 **GitHub、Notion、Figma、Google（云盘 / Gmail / 日历）、Slack、Jira、Confluence、Linear、钉钉、微信、语雀、Gitee 等约 500 个平台**：

1. **三步接入**：你在 **设置 → 采集 → 其他平台** 搜到目标平台，按提示填入开发者后台的 Client ID / Secret（用 API Key 的平台免此步）并开放给成员；每个人在自己的**账号 → 已连接的应用**里绑定个人账号，令牌由 omem 加密保管，只发往该平台声明的官方接口地址。
2. **只读采集为原件 & 8 大平台包定时同步**：
   - 连接后，直接让助手以你的身份读取平台内容并存为本地原件（全程只读，不改外部平台数据；支持确认身份的平台如 GitHub、Google、钉钉、微信还可直接用来登录 omem）。
   - **Figma、Notion、GitHub、Google、Slack、Jira、Confluence、Linear** 拥有深度平台包：设计稿画框与评论、Notion 表格、Issue、频道消息直接转为结构化 Markdown；对助手说**“盯着某个 Figma 项目 / GitHub 仓库 / Slack 频道”**，后续改动会自动定时同步入库。

## 3. 带代码的插件：深度扩展 omem 的每个角落

开发者可以用 `@omem-ai/plugin-sdk` 编写带 `server.ts`、常驻服务（`services`）和自定义前端页面的插件（公司内部系统的对接逻辑全部做成私有插件放在数据目录里，不污染公开仓库）。带代码的插件可以深度接入 omem 的以下九个扩展点：

### ① 嵌入事项流程、工作页侧栏与 AI 后端

<Shot src="flow-plugin-checks" caption="插件参与流程定义：在流程阶段开启插件的“完成前检查”，指定针对哪一阶段生效及出错时是否暂停等待" />

<Shot src="flow-stage-blocked" caption="事项流程中的插件拦截：当某阶段被插件检查拦下时，直接展示原因与证据，供你修复后重检或单次放行" />

- **流程完成信号、确定性运行器与完成前检查**：插件可以向[事项流程](./items#2-事项按流程推进flows)提供完成信号（如等外部发布单完成）、承担某个阶段的确定性自动化执行，或在阶段完成前做合规检查。
- **界面插槽（`api.slot`）**：无需打开插件自己的页面，插件可通过 `api.slot("item.panel", …)` 把展示块（如 GitHub PR 的 CI 检查摘要）直接嵌进**事项详情侧栏、流程阶段下方或工作页右栏**，按当前查看者的空间权限动态取数。
- **自定义 AI 后端**：插件可在清单中声明新的 ACP 后端，信任后直接出现在 **设置 → 后端与模型** 列表中。

### ② 统一凭据管理与出借（一次登录，供给多个命令行与 AI 后端）

声明了 `permissions.credential: true` 的进程内插件可以统一管理内部系统的登录凭据（见示例 `examples/plugins/acmeauth`）：

<Shot src="account-credentials" caption="账号 → 凭据：清晰展示各统一凭据的有效期、出借范围，以及下方由该凭据自动供给的 AI 后端与命令行" />

- **自动续签与会话无感恢复**：成员在 **账号 → 凭据** 登录一次，即可同时供给多个 AI 后端和受保护的命令行工具；短效令牌在后台自动提前续签，真需重新授权时机器人私聊发官方授权链接，授权完原对话自动接着跑。
- **可控的凭据出借与实时权限核验**：在 **设置 → 安全 → 凭据的出借** 中，可设为“直接借 / 先问持有人 / 不借”。开启直接借后，当某位成员未登录时，插件会**实时向资源服务核实该成员本人是否对该资源拥有读取权（`who_can`）**——确认有权才借用开放的凭据执行只读命令；无权则拒绝并直接附上权限申请链接。

### ③ 接入检索召回、重排与自定义向量计算

<Shot src="search-providers" caption="设置 → 检索与记忆 → 插件参与召回：按空间开启外部搜索服务召回，实时记录每次耗时与异常" />

- 在 **设置 → 检索与记忆** 中，插件可以作为额外的**检索召回源**（按空间开启，返回库内 ID 由宿主校验阅读权限）、替换**重排模型（Reranker）**，或者通过 `api.embedder` 提供自定义的**向量计算服务**。

### ④ 解析新文件格式（表格按行引用）与自定义 Wiki 页面类型

<Shot src="source-table" caption="插件解析的结构化表格原件：点击任意一行即可复制该行的精确行号引用，从引用点开时自动滚动高亮该行" />

- **自定义原件解析器（`api.sourceParser`）**：支持解析专有格式文件或特定内部网址；若解析为表格或条目，原件页直接渲染为交互表格，**每一行都能单独复制成 `src:<id>#L行号` 引用并在侧栏高亮定位**。
- **自定义 Wiki 类型（`api.wikiPageKind`）**：为 Wiki 提供专用的写作模板、确定性检查项与定期核对周期。

### ⑤ 接收外部 Webhook、自定义通知出口与聊天渠道

<Shot src="settings-outlets" caption="设置 → 通知与打扰 → 通知出口：管理内置与插件新增的通知出口，按紧急程度分流并支持交互回答回传" />

- **接收外部 Webhook 事件**：插件声明回调后，在 **设置 → 插件** 一键生成密钥与回调地址。支持“先落库再按发送方协议返回固定应答”、按投递 ID 自动幂等去重（同一 ID 正文不同报 `409` 冲突）以及失败有限重试。
- **自定义通知出口与聊天渠道**：插件可注册新的**通知出口**（按紧急程度投递提问、提醒或审批，并将用户的点选带回原会话）和新的**聊天渠道**（如 Matrix，走 omem 统一收件箱与身份绑定）。
- **外部事项、评审同步与语音流**：通过 `api.subscribe` / `api.itemProvider` / `api.reviewProvider` / `api.metricProvider` 双向同步外部 Issue、把代码评审问题发为 PR 行内评论、定时推送业务指标；声明 `voice: true` 或 `streams` 即可在页面内调用全双工语音模型或通过 WebSocket 实时推流。

## 4. 开发调试与安全隔离边界

- **本地热重载开发（`omem plugin link`）**：开发插件时运行 `omem plugin link ~/code/my-plugin`，omem 直接读取原目录不复制，修改代码后自动热重载，目录级信任一次后无需每次重审。
- **安装与严格的信任边界**：
  - 支持从本地目录、`npm:包名@版本` 或 `github:owner/repo#tag` 安装（源码包会先列出安装与构建命令全文，经你确认后才在无密钥临时目录中构建）。
  - **未点“信任并运行”前，一行代码都不执行**（仅加载静态清单、档案与页面）；数据目录内插件的代码一旦被修改，必须重新确认信任。
  - **沙箱化前端与无密钥服务**：插件前端页面运行在隔离框架中，拿不到你的 Cookie、登录令牌和原始麦克风音频（语音模式只拿转写文字）；插件后台服务拿不到 omem 的密钥环境变量，会在机器上执行点击/输入的工具强制标记 `approval: true` 每次请你批准。
