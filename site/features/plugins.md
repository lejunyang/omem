# 插件

有些事不适合一问一答：出一组题、你一次提交、看完结果再出下一组；或者一块每秒刷新的机器状态屏。机器人只适合一条一条地说，这类强交互放在插件的页面里做。

一个插件把一类事需要的东西打成一个包：

- **Agent 档案**：理解和出主意的那个“人”，和其他档案一样出现在 Agent 页，能换模型、挂技能、有专属记忆、被每晚复盘；
- **技能**：这类事的做法，首次启动补进技能库；
- **工具**：插件自己注册的工具（判分、查数据、调服务），加上清单里列出的 omem 工具；
- **规则和 MCP**：规则首次导入停用，等你看过再启用；MCP 只带变量和请求头的名字，值在 Agent 页填，命令要先确认信任；删掉插件也保留这些配置；
- **聊天渠道**：插件实现平台收发，omem 管身份、会话、回复和通知；
- **数据**：插件自己的存储，按用户隔开；
- **页面**：出现在侧栏，有自己的设置。

成员可以通过凭据插件授权一次，供给多个命令行和 AI 后端。插件声明 `permissions.credential: true`，经本人信任后在 omem 进程里运行。成员通过 `/api/credentials` 设置谁能借用自己的登录。登录快到期时，提醒发给持有人。

服务端插件可以订阅获准空间里的事项和评审变化，把外部项目的条目同步成事项，也可以定时为指标提供数据。外部条目默认先成为候选，回写状态时由你确认。

通知也可以送到插件。在 设置 → 通知与打扰 →“通知出口”里，一行一个出口：内置的网页和飞书只写能不能送达；插件加的出口可以打开、选最低紧急程度（不急的也发 / 一般及以上 / 只发紧急的）、发一条测试，最近一次出错写在名字下面。能回答问题的出口点开后勾“哪些问题发到这里”：提问和下一步建议随便勾，审批要确认一次（在那个渠道上点一下就能批准命令或工具）；成员在自己的账号页设置，审批要你先为那个出口打开（在 设置 → 成员 → 他那一行的“通知出口”里勾上）。可交互出口能将选项或表单回答带回原提问。

![设置里的通知出口](/screens/settings-outlets.png)

检索也可以接插件。在 设置 → 检索与记忆 →“插件参与召回”里逐个打开插件的召回，可以只对某几个空间生效；搜索会从插件的索引召回库内资料，沿用原有阅读权限。每一路写着上一次用了多久，出错时写出原因。没有插件提供召回时这张卡不出现。插件的重排在“重排”卡里选（来源选“插件”，先“试一下”再保存），主检索和对话前带上的记忆都会用它；换了以后在“对话前带上相关记忆”卡里按插件的分数重新定重排门槛（允许负数、零或大于 1）；空着按余弦门槛筛选，再按插件分数排序，插件出错或超时时退回本地模型。配置项是 `search.retrievers`、`rerank.provider` 和 `rerank.pluginPassiveThreshold`。

插件也能自己算向量：声明 `permissions.embedder: true` 并通过 `api.embedder` 注册模型、维度和编码方法。确认权限时会说明正文可能被插件发到外部服务；新增权限要重新确认。本人在“向量检索”卡里把来源选成“插件”并选中它（配置项 `embeddings.provider: "plugin:<插件>:<id>"`）后才启用，宿主负责分批、校验和落库，只交授权空间的资料。模型或维度升级时先暂停并通知，确认重建后再计算。[云端配置](./sources.md#向量和重排用云端接口)。

## 插件参与流程和 AI 后端

插件可以判断阶段完成，或承担一个确定动作并交回结果与证据。运行器由本人确认流程，结果检查按流程启用，拦下时给出原因，本人可以对这一次仍然通过。清单还可声明 ACP 后端，信任后进入目录；改启动声明重新确认。

在流程定义页打开一份流程，每一段下面点“改谁来做、怎么算完”：“做到什么算完”里按来源分组列出内置的和各插件的信号，“谁来做”里有“插件执行”。选了插件的信号或运行器，下面写着它的用途和参数（简单的参数是表单，复杂的写 JSON）。带插件执行的新版本保存后先变成确认卡，你点“启用”才生效。同一页下面的“完成前的检查”逐条打开插件的检查，挑它看哪些阶段，以及检查出错或超时时要不要停下等你。插件停用了，定义里用到它的地方照样显示，标明停用，等它信号的阶段可以你自己点完成。

<Shot src="flow-plugin-checks" caption="流程定义：完成前的检查，只看“写检查文件”这一段，出错时停下等你" />

事项的流程里，在等插件信号的阶段写着在等谁、多久后再问；插件问不到时写“问不到”和下次再问的时间。插件执行的阶段写着由谁执行，可以点进那次运行。被检查拦下的阶段列出原因和插件交的证据，你可以这一次仍然通过，或等处理好以后重新检查。

<Shot src="flow-stage-blocked" caption="事项的流程：写检查文件被检查拦下，等你决定" />

插件声明的 AI 后端在 设置 → 后端与模型 和 Agent 档案的后端下拉里标着“来自插件 ××”；插件停用后，已经选了它的地方仍显示它，标不可用和原因，并给去插件页的链接。插件页在信任之前就列出它的后端和启动命令。[写法与文件示例](https://github.com/lejunyang/omem/blob/main/docs/v2/plugins.md#流程的完成信号)。

## 页面里怎么交互

Agent 不靠输出一段 JSON 和页面打交道，而是调工具交出一个**内容块**：一组题、一张表单、一张图。参数由插件声明的格式校验，不合格的直接退回给 Agent 改。你在页面上做完点“提交”，插件能确定的当场判分（答案只在服务端，提交后才给页面看），结果整理成一条消息回到同一个会话，Agent 接着点评、出下一组。

每个插件都能用的通用块：

| | |
| --- | --- |
| 表单 | 文字、多行、数字、单选、多选、1–5 打分，可标必填 |
| 图表 | 柱状、横向条形、折线、面积、饼图，和 omem 自己的页面同一种画法（梯级柱、刻度行、逐点折线、发丝线面积、刻度表盘），深浅色各一套配色，第一次看到时画一遍，悬停看这一处所有的值，能展开成表格 |
| 指标与结论 | 带涨跌和走势的指标卡；图标标出语气的结论块 |

所以一个没写一行代码的插件，也能让 Agent 发表单给你填、画图给你看。

## 自己做一个

在数据目录（默认 `~/.omem`）建 `plugins/<id>/`，写一份清单和一个档案就够了：

```yaml
# ~/.omem/plugins/journal/plugin.yaml
id: journal
name: 每日复盘
agents: [coach]          # 档案在 agents/coach.md，对外名字是 journal-coach
tools: [recall, remember]
page: { title: 每日复盘 }
settings:
  - { key: tone, label: 语气, type: select, options: [温和, 直接], default: 温和 }
```

重启后侧栏出现“每日复盘”。没有自己的页面时，omem 给它一个默认页：和它的 Agent 对话，Agent 用表单和图表和你交互。设置项在页面右上角的“设置”里改。

侧栏图标由插件自己定（`icon`），不喜欢就在 设置 → 插件 里点图标换一个。插件的档案在 Agent 页改过之后存一份你的版本，删掉就回到插件自带的。

## 打成场景包

不带代码的插件叫**场景包**。设置 → 插件 → 打成场景包，勾选已有 Agent 档案、技能、规则、流程和 MCP 服务，填 id、名字和说明。完成后显示服务器上写到的目录和未打包的依赖提醒。

包里的流程装上时补进对方的流程清单：对方已有同 id 的不覆盖，删掉的不再加回来；用到别的插件的对象类型（比如 GitHub 的合并请求）时，要等那个插件启用后才加上，插件详情里写着原因。仓库里的 `examples/plugins/ghdelivery` 是一个完整的例子：GitHub 需求交付的流程（澄清 → 编码 → 建合并请求 → 等检查 → 合并）、三个技能和一条“合并请求被关掉时通知我”的规则。

还可以勾选空间，或在 CLI 重复传 `--space <id>`，带走名称、类型、说明和技能挂载，不带原件、页面、记忆、成员、仓库路径或会话信息；个人和代码仓库空间不能打包。安装启用时按清单顺序创建空间，已有同 id 空间完整保留，插件详情列出“已创建”或“已有同名空间，没有改动”，停用和卸载都保留空间。规则和空间一起打包，所属空间与 Agent 动作的空间会保留，导入后仍停用；遗漏的空间和挂载技能会提示补选。

```bash
omem plugin pack --id projecta --name "项目 A" --agents helper --skills project-guide --mcp web-search
omem plugin install ./projecta-pack
```

默认输出到 `<数据目录>/plugins-out/<id>/`，CLI 可用 `--out ./projecta-pack` 改目录，也可用 `--rules <规则id>` 选规则、`--flows <流程id>` 选流程。安装本地目录时完整复制，不建立链接。没有代码也没有命令 MCP 的场景包不需要信任。

技能会带上完整资源目录；规则导入后显示来源，默认停用，删掉后不再自动创建；MCP 服务用插件前缀避免撞名，已有同名项不会被覆盖，插件卡片提示还要填哪些密钥。删除插件会保留本人已有的规则和 MCP。

打包始终不导出 MCP 密钥值；其他文本含已存密钥或用户目录绝对路径时先拒绝，按文件和行报告，整个包不写入。清理后重试；用户目录路径可以在 CLI 用可重复的 `--allow <包内相对文件>` 放行，已存密钥不能放行。规则里你在这台机器上选的东西不随包走：带脚本或转发的规则不打包，完全访问、发到的会话、指定的 AI 和未打包的空间去掉，装上后在规则页重新选。不能写入仓库或正在使用的 `plugins/`，也不覆盖已有目录。

## 带代码的插件

- **`server.ts`**：注册自己的工具和内容块（含判分）。会在机器上动手的工具（点击、输入）可以标成每次都要你批准。
- **`services`**：声明一个常驻进程（每秒采一次机器状态、截屏、连设备），只在本机监听，第一次用到时启动，闲着自动停。
- **流**：页面通过 omem 和服务保持 WebSocket 连接，二进制帧直接转发，截屏这类每秒几帧的数据也能实时显示。
- **自己的页面**：任何前端写法都行，用插件 SDK（npm 上的 `@omem-ai/plugin-sdk`）和 omem 通信，拿到 omem 的样式和主题。
- **语音**：清单写 `voice: true`，页面就能用 `omem.voice()` 和语音模型（设置 → 后端与模型 → 语音）对话，说明由插件给。麦克风和连接在 omem 自己的页面里，插件页面只拿到两边说的文字；只在你点了按钮之后开始，进行中顶上一直显示“正在使用麦克风”和“结束”。英语练习的[口语对话](./english#口语对话)就是这样做的。不需要写代码。
- **连接器**：插件可以带一个让人连接的平台（授权方式、令牌交换、“我是谁”、功能和权限）。每个人在账号页连接自己的账号，插件的工具以用的那个人的身份调这个平台；令牌由 omem 保管，只发往插件声明的接口地址。
- **AI 账号的登录方式**：[成员用自己的 AI 账号](./devices#成员用自己的-ai-账号)时，插件可以给某个后端提供登录方式（`api.agentLogin`，比如用公司的统一身份登录）。成员在“我的 AI 账号”里选它，插件引导授权、把凭据写进他的账号目录；omem 负责显示链接和验证码（网页上和飞书私聊里）、按人保存插件要的一份秘密、到期前续签、退出时调插件清理。清单要声明 `permissions.agentLogin`，只在你信任并选“在 omem 里运行”时生效。写法见 [docs/v2/plugins.md](https://github.com/lejunyang/omem/blob/main/docs/v2/plugins.md)。

例子：一个四个文件的“看机器状态”插件。服务每秒推 CPU 和内存，页面画两条进度条实时更新；问它的档案“机器现在负载怎么样”，档案调插件的工具读当前值回答。

### 信任

数据目录里的插件带代码时，代码以你的身份运行，所以**你确认之前一行都不运行**：清单、档案、技能和页面照常可用，工具和服务不启动。在 设置 → 插件 点“信任并运行”，立即加载；代码一改就要重新确认。那里也能看服务在不在跑、最近输出了什么，随时撤销信任。

### 放到 omem 自己的页面上

插件的展示块可以放进 omem 的页面，不用打开插件页：事项页侧栏（外部状态下面）、流程里某个阶段的说明下面、工作页右栏。比如合并请求的检查结果显示在挂着这个合并请求的事项旁边：

```ts
api.slot("item.panel", { block: "ci_summary", when: { object: "pull-request" } });
```

块按看页面的人、在事项所在的空间里取数，你看不到的事项也看不到它的块。可以只在挂着某种对象、某个阶段、某个流程或某个空间的事项上显示。一个块读不到或画错，只在那一块里写原因，页面其他部分照常。插件停用或撤销信任，块就消失。

### 边写边试：plugin link

```bash
omem plugin link ~/code/my-plugin
```

omem 直接读这个目录，不复制。改了文件，运行中的 omem 自动重新加载；带代码的插件在 设置 → 插件 里信任一次，信任记的是这个目录，之后改代码不用再确认。设置页给它标“开发中”。链接只在这台设备上，不随设备同步，拉取别的设备的数据也不会去掉它。不用了 `omem plugin unlink <id>`，目录里的文件不动。

### 从源码安装

装的包是源码（有 `build` 脚本、构建产物还没有）时，omem 先列出要运行的命令：装依赖（不运行依赖的安装脚本）和 `npm run build`，以及这些脚本的原文。你在终端或设置页的弹窗里确认后，才在解开的临时目录里运行，不带 omem 的密钥，最多十分钟，输出记在数据目录的 `logs/plugin-builds/` 下。构建完照常等你信任。

## 安全边界

- 插件页面在隔离的框架里运行，拿不到你的登录令牌和 Cookie，只能读写这个插件自己的数据、和它自己的 Agent 对话；用语音时也拿不到麦克风和录音，只拿到转写的文字。
- 服务拿不到 omem 的令牌和密钥类环境变量，只认带自己令牌的请求。
- 公司内部系统可以做成插件放在你的数据目录里，不进 omem 的仓库。

## 在飞书里

在飞书里让插件的 Agent 干活（比如 `/as english-tutor 来一组面试的题`），它把内容放进插件页面的一个新会话，回一个链接给你。设置 → 设备 填了“网页地址”时，这个链接在飞书里能直接打开。

设计细节见仓库里的 `docs/v2/plugins.md`。

## 连接其他平台

内置的“连接平台”插件把 Notion、GitHub、Google（云盘、邮件、日历）、Slack、Jira、Confluence、Linear、钉钉、微信、Gitee、语雀等约 500 个平台接进来，平台列表取自 Nango 的开源目录，国内平台另外补充。

- **能确认身份的平台**（GitHub、Google、微软、钉钉、微信、QQ……）：可以用来登录 omem、绑定账号，也能读取。
- **其余平台**：只用来读取。连接后只保存令牌，不当作身份。

接入步骤：

1. 你在 **设置 → 采集 → 其他平台** 里搜到平台，按提示在它的开发者后台建一个应用，把给出的回调地址填进去，再把 Client ID 和 Secret 填回来。用 API Key 连接的平台不用建应用。
2. 把平台开放给成员。
3. 每个人在 **账号** 页连接自己的账号（或者填自己的 key）。

连了平台以后，直接告诉助手要哪个平台的哪些内容，它以你的身份读，再存成原件，之后可以检索、引用，也可以整理进 Wiki。它只能读，不会改动平台上的内容；同一项内容再采一次是更新，不会重复。

Figma、Notion、GitHub、Google 云盘 / Gmail / 日历、Slack、Jira、Confluence、Linear 各有一个平台包，读出来的是整理好的正文：Figma 文件按页面和画框列出文字和评论，Notion 页面保留标题、列表和表格，Slack 一天的消息带着线程。让它“盯着”某个 Figma 项目、GitHub 仓库或 Slack 频道，之后的改动会定时同步成原件，账号页能看到同步情况，随时停掉。


GitHub 合并请求挂到事项后，相关评审结束时可以在确认卡里选择要发布的行内评论。作者的回复会回到评审运行。复审判为已修后，本人可以确认结束讨论。

## 插件带来的聊天渠道

插件可以接 Matrix 等平台，和飞书、Telegram 一样走 omem 的收件箱。安装后在 设置 → 插件 选择“在 omem 里运行…”、确认信任并启用，在插件设置填本人在该平台的 id；渠道状态和最近发送错误在 设置 → 渠道，那里可以直接跳回插件设置。

只有绑定身份的人能得到回答；未绑定时，私聊会提示如何设置本人 id。群里只有明确发给机器人的消息才处理。后续会话回复仍回原会话，通知发到本人或成员的私聊。停用或撤销信任会注销回复和通知入口。

渠道和连接器、内容块一样，只能在 omem 进程里运行，隔离模式不可用。写插件的 API 和限制见仓库 `docs/v2/plugins.md` 的“渠道”。

## 原件格式和 Wiki 类型

插件可以读取一种新文件或网址，把解析结果保存成可按行引用的正文。多个插件能读同一格式时，在配置的 `documents.parserOrder` 里按顺序填写解析器全名。要接管内置格式，也在这里明确指定。设置 → 采集 → 其他平台 的“能读的格式（插件）”列出现在有哪些解析器、各认哪些扩展名和地址、最近一次读失败的原因。

插件把原件读成表格或一条条记录时，原件页默认按表格或条目显示，可以切回原文；原件信息里写着由哪个解析器读的（插件停用后写“读它的插件停用了”）。点表格的一行或“选中这一条”，地址里记下这一行在正文里的行号，可以复制成引用或跳到原文的这几行；从引用点过来时，对应的行会标出来并滚到眼前。

插件还可以提供 Wiki 页面类型（写作模板、检查项和定期核对的间隔）。页面头部写着它的类型；编辑页面和“写一页新文章”时可以选类型，每种类型带一句什么时候用。停用插件后，已保存的原件和页面仍可阅读，页面照原样显示类型名。
