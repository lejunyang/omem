# 工作线：本月在推进

**工作线是你这几周正在推进的一件大事（例如“示例商城 · 退款改造”）。** 围绕这件事的需求、缺陷、技术方案、编码交办、合并请求、关注群和观测指标全部挂在它下面（支持“工作线 → 需求 → 缺陷”最多三层）。打开 omem 网页，第一眼看到的就是**“工作”页**——不用在几十个群和单据里来回翻，一屏看清每条线截至今天的现状、关键变化和下一步。

## 1. 工作页：一屏看清所有在推进的事

工作页顶部提供三种视角切换，右侧固定为**“需要你处理”**行动栏：

| 视角 / 区域 | 看什么、怎么用 |
| --- | --- |
| **按工作线**（默认） | 每条进行中的工作线一张大卡片：<br/>• **一句“截至今天”的现状**与截止时间<br/>• **关键变化点线**：最近 6 条关键变化按时间从左到右排列，用颜色区分性质（风险/改期偏暖色，决定/范围是蓝色，结果/风险解除是绿色），点任意节点可在右侧展开原因、风险与原文出处；**末尾的虚线点是建议的下一步**<br/>• **下属工作项进度**：列出挂在线下的事项，走流程的带迷你阶段条，正等你处理的标黄 |
| **按时间** | 把所有工作线的变化按天排成时间流，可按变化种类（决定 / 风险 / 范围 / 时间 / 结果 / 阶段）和来源（群聊 / 流程 / 指标 / 会议 / 你定的）筛选，右侧配每日柱状图点击过滤 |
| **按阶段** | 流程看板视图：把所有正在走流程的事项按当前所处阶段分列展示；右上角可直接进入“流程定义” |
| **右栏：需要你处理** | 把全系统等你的事收在一处：**待答提问与工具审批、流程里轮到你或卡住的阶段、影响已做工作的范围变化、AI 提议的新事项、飞书待发草稿**，点击任意一条直接在侧栏回答或拍板；下方附带值班群“在跟的问题”计数与快捷提问框 |

## 2. 一条工作线的详情页与“需求到交付”四栏链路

点击任意工作线或工作项，就进入它的专属页面：不仅有阶段条、**最近四周各忙了什么**、建议的**下一步**（每条带“就这么做 / 不用”按钮），还在右侧自带**“问这条线”**专属对话框（可直接问“现在卡在哪？”“按这条线写一份周报”，在已关联该事项的飞书会话里追问也会自动带上整条线的现状与待定变化）。

<Shot src="work-line" caption="一条工作线的页面：阶段进度、最近四周进展、可一键执行的下一步，右侧直接针对这条线提问" />

### 需求到交付：四栏看清上下游全链路

当工作项下挂了需求点、研究发现、技术方案或编码交办时，页面会展开**“需求到交付”**四栏视图。鼠标悬停（或 Tab 聚焦）在任意一条上，**和它关联的上下游条目会立刻高亮，其余变淡**，点击即可跳进对应详情页：

<Shot src="item-chain" caption="需求到交付：鼠标指着一个需求点，和它关联的技术方案决定与编码交办立刻联动高亮" />

1. **需求**：拆解出的需求点、最近一次代码评审确认的实现状态（已实现 / 部分实现 / 未实现）及测试通过数。
2. **发现**：自动化“研究”试验跑出的复现问题、你的判定结论以及发起修复后的重跑结果。
3. **方案**：技术方案中的各个架构决定，自动连向它所落地的需求点。
4. **交付**：编码交办、分支评审进度、测试结果，以及所挂载的 GitHub 合并请求在远端平台上的实时状态。

下方紧接着**“在做的”**面板，把当前正在跑的流程阶段、多 Agent 任务板、编码交办和评审并排列出，等你的或卡住的醒目高亮。

<Shot src="work-progress" caption="在做的：流程停在推送阶段等你确认，旁边并列展示同一件事的交办与评审进度" />

## 3. 早上一张“今天”卡片：一次勾完所有待办与提议

你不需要每天被十几张零散的通知卡片打断。每天早上（默认 `09:30`，可在 **设置 → 通知与打扰 → 早上一张“今天”** 调整），omem 会把所有需要你过目的事合成一张**“今天”**卡片发到飞书私聊（同时出现在工作页右栏顶部）：

<Shot src="today-card" caption="早上一张“今天”：汇总今日简报、各条工作线的新下一步、夜间提议的新线/候选事项/指标与自动收尾清点，一次勾选提交" />

卡片按模块分段展示（没有内容的段落自动隐藏），你可以逐项勾选后**一次提交**：
1. **今日简报**：今天最要紧的两三件事，以及助手提前替你备好的材料链接（如查好的会上数字、预审完的文档问题）。
2. **等你处理**：最紧急的待答提问、流程卡点与审批摘要。
3. **各条工作线的现状与下一步**：每条线一句“截至今天”，对新提议的下一步直接选**“就这么做”**（助手立即在后台启动一轮去读材料、跑测试、看指标或起草询问）或**“不用”**（记下偏好，下次不再提同类建议）。
4. **夜里整理出的提议与清点**：提议新建的工作线（建 / 不用 / 并进已有线）、AI 发现的候选事项（留下 / 不要）、自动收尾或明天到期的事项（恢复 / 保留）、复盘提出的技能/提示词改进建议、AI 提议的新观测指标。

## 4. 全自动生命周期：怎么来、怎么记变化、怎么观察收尾

### 工作线从哪来？

- **每晚自动提议**：每晚整理工作近况时，助手根据你近期活跃的群、文档和代码，自动把新事项归入已有工作线；发现你正在推进一件新的大事时，会在第二天早上的“今天”卡片里问你“要建成工作线吗”。
- **随时手动新建**：在工作页右上角点 **＋ 工作线**，填名字和一句目标即可。

### 关键变化台账：多路看到也只记一次

一条工作线的群聊和文档会被采集整理、规则、有人找你、群关注、定时巡检等多路同时看到。omem 通过底层的**幂等变化台账（`item_changes`）**保证井井有条：
- **绝不重复记账**：同一条群消息或同一处改动被多路看到时只生成一条时间线记录，后续各路发现的细节作为“补充”合入原条（悬停可看谁先记的、谁补了什么、哪一路因为已有处理者而主动让开）。
- **原定范围内反馈直接并进，扩大范围先问你**：群里出现的常规验收反馈和明确改期会直接并入流程并更新截止时间；但凡涉及**扩大需求范围、推翻既有决定或需要你选做法**的变化，都会先列在工作线顶部等你拍板（并进 / 另开新项 / 不用管），绝不擅自替你答应。

### 上线后自动进“观察期”，稳定两周自动收尾

工作线不需要你专门记得去点“关闭”，它有完整的**进行中 → 观察中 → 已结束**三段生命周期：

<Shot src="work-ended" caption="工作页底部：上线后的工作线自动移入“观察中”小卡片；观察期满无异常自动归入“已结束”并附上收尾小结，按月可查可搜" />

1. **自动进入“观察中”（默认 14 天）**：当工作线的流程走完、下属事项全部办结，或助手从群里/发布系统读到“已全量 / 上线完成”时，自动转入观察期。观察期内，群关注只盯**线上报错、用户反馈和数据异常**，忽略普通闲聊。
2. **观察期满无异常，自动结束并写小结**：若观察期满且没有未结事项、没有越界指标、近三天群里也无新报障，工作线自动结束——同时停止关注与指标采集，由助手写一段**收尾小结**（做成了什么、关键决定、上线后指标表现、遗留项）置顶保存，并供周五自动写进周报；第二天早上的“今天”卡片里会告知你（点“恢复”可随时重开）。若期满时群里还在讨论或指标仍在波动，则静默延长观察一周；只有长期僵持拿不准时才会发卡问你一次。

## 补充说明：团队成员的工作页与跨人催进展

- **给同事开放只读观察或协作**：在 **设置 → 成员 → 能做什么** 中将同事设为“网页只读观察者”（或授予“看工作线”）并共享项目空间后，同事打开“工作”页就能看到该空间内的工作线现状、阶段与变化（若线下某件子事项在他无权读取的空间，该子事项与整条线汇总现状会自动隐藏，只提示“有一部分你看不到”）。有编辑权限的成员还能创建属于他自己的工作线（使用他自己登录的 AI 账号每日整理）。
- **让助手替你去问成员进展**：当某条线卡在同事手上时，直接对助手说“去问小林退款接口联调到哪了”。助手会发卡片到小林的飞书私聊（或他的工作页右栏），小林回答后，原话自动作为一条带“成员回答”出处的**关键变化**记回这条工作线的时间线上。
