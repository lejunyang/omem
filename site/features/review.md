# 交办与评审

在问答里说“在 shop 仓库实现……”“前端和订单服务一起改……”，或在运行页点“交办”，或 `omem delegate`。

## 流程

1. 每个涉及的仓库各开一个**独立 Git worktree**，你的工作目录不受影响；改过的文件在应用前就能检索。
2. **编码 Agent** 在这些 worktree 里一起实现，跑项目的检查命令。
3. 按改动大小和位置选**评审档位**（默认轻 / 标准 / 完整），每档挑做哪些评审项、最多几轮。
4. 各**评审项独立审查**：功能、业务、架构、历史、规范，以及你挂上去的专项评审（比如只看鉴权的安全评审）。
5. **评审负责人**合并重复的问题、决定哪些要改，写修改单；下一轮编码续在同一个工作区和编码会话里，只复审受影响的评审项。
6. 改不动、僵持或需要换方案时停下来，在飞书或运行页问你。评审结束发一张带摘要和按钮的卡片。

## 概览

<Shot src="review-overview" caption="概览：结论、各评审项的结果和所用模型、待处理问题" />

“待处理”列出要改的、暂不改的和还没定的问题；评审负责人驳回、合并的和没人要求改的提示收在“全部”里。每个问题可以选“改 / 暂不改 / 不改”（不改要写一句业务理由，会记到事项上，之后的评审不再提）；开始修改时没选“改”的就记成暂不改，之后各轮的“待处理”里还看得到（标着第几轮），随时可以改主意。展开一个问题，先是问题和依据，再是建议；建议不对或说得不清楚时点“改建议”直接改写，下一轮只按你写的改（原建议还能展开看），不用再引用一遍加补充。同一个分支请两个模型各评了一次时，在其中一份的概览里勾“一起看同一分支的其他评审”，两份的问题放在一起挑，一次修改改完。下面写补充要求（需求变化、评审没发现的问题），切到别的标签再回来也还在；需要时选之后各轮的评审档位（可以比之前轻）、要不要再拆需求、每轮换不换模型、功能评审用哪个 AI，点“开始修改”。档位设置里打开“多轮时换模型复审”后，第 2 轮起各评审项轮换用列表里的模型，同一轮各项也错开，多看几种意见。和对助手说“改 #4 #7，后面评审从简”是一回事。

交办还在编码时，运行页上方的“补充给编码 Agent”可以直接把新要求交给它：它下一次调用 omem 工具时收到，最晚在这一轮检查之前，不用等这一轮结束；已经写完代码在评审中的，随下一轮交给它。同一处能改之后各轮的评审。“停止”停下这一轮，不再自动续轮，工作区保留。

## 变更

<Shot src="review-change" caption="变更：评审时把需求拆成变更点，点一条高亮对应代码，涉及几处时逐处跳转" />

每次评审都会和各评审项同时把需求拆成变更点，每条写需求怎么说（带原文引用）、代码怎么做、状态（已实现 / 部分实现 / 没实现 / 需求外）和实现位置。点变更点，代码高亮并把它的第一处标记滚到屏幕上部；一个变更点涉及几处（几个文件）时，下面列出各处位置（`文件:行`），点哪处跳哪处，代码上方的“上一处 / 下一处”（键盘 `n` / `N`）按顺序走一遍，左侧切到“文件”时它涉及的文件带同色圆点；点行号旁的标记看讲解、就地提问。升级前的评审可以点“拆分需求”补一次。

需求涉及几个页面或模块时，变更点按页面或模块分组成树（最多 4 层），像文件夹一样折叠展开；点一组，组下全部变更点的代码一起高亮，“上一处 / 下一处”走遍它们。分得不顺手，点“重新整理”写一句要求（如“按前端页面分组”“C3 拆细一点”），或在问答、飞书里跟助手说，它带着原来的变更点只重做拆分，没提到的保持原样，不重跑评审。

## 活动

<Shot src="review-activity" caption="活动：编码 Agent、各评审项、需求拆分、评审负责人各一节，展开看自己的工具步骤和文字" />

评审页每个评审项旁有“看过程”，跳到活动里对应的一节。

活动上方的“上下文”按编码 Agent 和各评审项列出：omem 的说明怎么发的（作为系统提示 / 放在第一条消息 / 接上会话没再发）、多少字、由哪几部分组成，模型调用了几次，上下文从多少涨到多少，累计读入多少 token。额度用得快时先看这里。

<Shot src="run-context" caption="上下文：各 Agent 的说明组成、调用次数和上下文用量" />

说明每个 Agent 会话只发一次；编码 Agent 只拿到和编码有关的共同约定，偏好与经验只带它自己的和与任务最接近的几条。下一轮编码默认接着上一轮的会话，上一轮的会话已经很长（默认超过 100K token）时换新会话，从工作分支读已有的改动。按评审修改时只复审提出这些问题的评审项，每隔一轮全部重审。

## 评审已有分支

“帮我评审 shop-api 的 feature/refund”，运行页“交办 → 评审分支”，或 `omem review-branch <空间> <分支>`。分支检出到独立工作区，只看它从基线分叉以来的改动，只出意见不改代码。要按意见修改，在概览里选好要改的问题点“开始修改”，会基于这个分支交办。

## 设置

**Agent → 评审**：档位按改动行数、文件数、路径等条件，或一句话说明（交给 AI 判断）来选择；每档设评审项、最多几轮、是否由评审负责人协调、是否先给你看计划。“加专项评审”把一个 Agent 档案挂成评审项。交办时说“用完整评审”直接指定档位。
