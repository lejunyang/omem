# 交办与评审

当你发起一次编码交办（或让助手评审一个已有分支 `omem review-branch`），打开它的详情页，你会看到五个核心标签页：**概览、需求点 / 变更（或方案）、评审、活动、分支**。这一页详细说明六个评审角色是怎么配合的，以及你怎么在网页上看改动、挑问题、发 GitHub PR 评论和查 Token 消耗。

## 1. 六维独立评审与异构模型交叉把关

编码 Agent 写完代码并跑过宿主执行的仓库检查命令（宿主会把检查跑在哪个 commit、退出码和完整输出直接交给评审，评审角色负责核对测试是否真实覆盖了改动、有没有跳过用例或吞掉报错，不再各自浪费时间重跑整套测试）后，按改动规模进入**轻 / 标准 / 完整**评审档位：

| 评审维度 | 专门审查什么 |
| --- | --- |
| **功能评审（`reviewer`）** | 需求点是否完整实现、边界条件与错误处理是否严密、测试是否真正覆盖了改动 |
| **精简评审（`review-simplify`）** | **在功能不变的前提下，哪些代码能删、能合并、能改用编码前检查找出的已有实现**（改满 40 行源码必出场，防止 AI 堆砌冗余胶水代码） |
| **业务评审（`review-business`）** | 对照空间内的产品文档、历史群聊约定与业务术语，检查是否违背既有业务口径或破坏上下游流程 |
| **架构评审（`review-arch`）** | 模块职责边界、接口契约、数据流向与跨仓库调用是否合理（第 3 次修补同一位置时优先提供结构级重构方案） |
| **历史评审（`review-history`）** | 对照这些文件以往的提交历史、过去踩过的坑和历史评审记录，防止把以前修好的 Bug 又改回来 |
| **规范评审（`review-style`）** | 只查项目写明的硬性约定（如 `AGENTS.md` 与仓库学到的约定），以及真正会误导人的命名、注释和类型 |
| **自定义专项评审** | 你可以在 **Agent → 评审** 里点“加专项评审”，把任何自定义档案（如“安全与鉴权评审”）挂进评审流水线 |

### 默认尽量换“别家模型”交叉审

自己审自己写的很容易漏看。在 **Agent → 评审 → 换模型复审** 中：
- **异构模型优先**：当某个评审项的默认模型与本次写代码的编码 Agent 属于同一模型家族（例如都是 Claude 或都是 GPT）时，系统会**自动从候选池里挑第一个可用的别家模型**来审；实在没有别家可用时才沿用，并在摘要里明确标出“同一家模型（不算独立评审）”。
- **多轮轮换与黑名单排除**：开启“多轮时换模型复审”后，从第 2 轮起各评审项会自动轮换使用候选列表里的不同模型；如果某个模型近期表现不好，在“编码评审排除的模型”里填一行名称片段（如 `opus`）即可一键在全评审链路中跳过它。

## 2. 概览页：定下改哪些、一键同步到 GitHub PR

<Shot src="review-overview" caption="概览页：结论、各评审项结论与所用模型、待处理问题清单（可直接选改 / 暂不改 / 不改，或改写修改建议）" />

在“概览”页，所有评审问题按**“现在的实现 / 源实现（迁移时）/ 触发条件 / 问题说明 / 修改建议”**结构化列出，正文里的代码与原件引用点开即看：
- **看不懂就让助手重写，不满意建议就直接改**：觉得某条问题描述太绕，点**“看不懂，重新描述”**，助手会结合代码用直白的话重写；觉得评审给的改法不对，点**“改建议”**直接改成你的做法，下一轮编码 Agent 严格只按你改后的建议执行。
- **三档决定（改 / 暂不改 / 不改）**：对每个问题选“改”“暂不改”（留到以后轮次仍可见）或“不改”（写一句业务理由记入事项，后续轮次不再重提）。如果你请两个不同模型对同一分支各评了一次，勾选**“一起看同一分支的其他评审”**即可把两份问题合在一处挑选，一次修改全部改完。

### 把评审问题作为行内评论发到 GitHub 合并请求（PR）

如果这件事项上挂了 GitHub 合并请求（且启用了内置 GitHub 插件）：

<Shot src="review-sync" caption="同步到合并请求：显示已发布条数、作者回复数与待重定位数，支持确认后批量发布行内评论或一键 Resolve 已修讨论" />

- **逐条勾选发布行内评论**：点**“发布 N 条…”**，在弹出的确认卡上逐条核对（必须由你本人点确认，助手绝不擅自往同事 PR 上刷评论），确认后直接作为 GitHub PR 对应代码行的 Inline Comment 发出。
- **自动读回作者回复与一键 Resolve**：平台上作者回复了评论，omem 会自动读回并直接显示在该问题下方；同事改完代码后点**“复审”**，评审项会把上次的问题逐条判为**已修 / 仍在 / 不再适用**，确认已修的问题可点**“结束已修的 N 条…”**在 GitHub 上批量 Resolve 讨论线程。

## 3. 变更页：从需求变更点一键高亮跳转到代码行

看几千行代码 diff 最怕迷失在文件堆里，不知道哪段代码对应哪条需求。omem 在每次评审时，会自动把需求拆解为结构化的**变更点（Change Points）**：

<Shot src="review-change" caption="变更页：左侧把需求拆成变更点树（标出已实现 / 部分实现 / 没实现），点击变更点 C3，右侧代码立刻高亮并滚动到对应实现行" />

<Shot src="review-split-diff" caption="代码差异视图：支持一键切换上下统一对比或左右并排（Split）对比，左侧可切为折叠文件树" />

- **按页面或模块折叠成树**：每条变更点写明**需求原话（带文档引用）、代码实际怎么做的、实现状态（已实现 / 部分实现 / 没实现 / 需求外）**。大需求自动按模块或页面分成最多 4 层的折叠树；觉得拆分角度不顺手，点**“重新整理”**写一句“按前端页面分组”或“把 C3 拆细一点”，助手只重做拆分，不重跑评审。
- **点击变更点，代码同步高亮跳转**：点击任意变更点（或整组），右侧代码视图立刻高亮所有关联代码段并滚到第一处；涉及多个文件时，按上方“上一处 / 下一处”（或快捷键 <kbd>n</kbd> / <kbd>N</kbd>）即可按顺序走遍所有改动点，点击行号旁的标记还能看讲解或就地提问。

## 4. 评审与活动页：全过程透明，Token 账单一目了然

- **评审页（按轮次与逐项验证查看）**：展开最新一轮每个评审项的完整审查报告与全部原始问题（已转为修改项的问题带有 `T` 编号链接）；正在进行中的阶段评审会实时标出哪几项已交、哪几项还在看，下方单列编码过程中边写边验的**“修改项验证”**记录。

<Shot src="review-checks" caption="评审页：查看每个评审角色的完整结论与它报出的全部问题明细" />

<Shot src="code-work-stage-review" caption="进行中的阶段评审：两项已交结论、三项正在审查，下方列出编码期间的修改项即时验证记录" />

- **活动页（分段折叠过程 + 上下文 Token 账单）**：
  - 将每一轮清晰切分为**编码 → 宿主检查 → 阶段评审**几段，正在跑的那一段默认展开，已跑完的收成一行摘要（写明耗时、做了哪几个修改项、检查是否通过）；点开任意角色小节可查看完整的工具调用步骤与思考文字。
  - 顶部的**“上下文”**面板详细列出编码 Agent 和每个评审项：**系统提示词是怎么发的、占了多少字、由哪几块组成、调用了几次模型、上下文从多少涨到多少、累计读入多少 Token**——发现某个账号额度掉得快时，打开这里一眼就能看清花在了哪一处。（当编码会话上下文超过 `100K` tokens 时，下一轮会自动换新会话并从 Git 分支读取已有改动，避免每轮背着十几万历史 Token 空耗额度）。

<Shot src="review-activity" caption="活动页：一轮按编码、宿主检查、阶段评审分段，展开每个评审角色可看其每一步工具调用" />

<Shot src="code-work-round" caption="活动折叠视图：已完成的编码和宿主检查收成一行摘要，当前正在进行的阶段评审自动展开" />

<Shot src="run-context" caption="上下文与 Token 账单：每个角色的提示词结构、模型调用次数与上下文增长曲线清清楚楚" />

- **看提示词原文**：“上下文”里每个角色那一行有“看提示词”，打开后是这一轮实际发给它的全部内容，分成“说明”（共同约定、角色说明、环境、偏好与经验、技能目录）和“这一条消息”（任务、自动带上的相关记忆）两块。
  - **分节看占用**：每一节标着字数和占比条，先看哪一节占得多，再点开读原文；想知道某条经验或某个技能有没有被带上，在“在提示词里找”里搜。
  - **接上原会话的轮次**：这一轮没有再发说明时，页面会写明，并给出当时一个新会话会收到的说明作参考。
  - **保留多久**：原文存在本机数据目录，最近 14 天用过的才留着（天数和开关在 **设置 → 检索与记忆 → 每次运行带上的经验和技能** 里），只有本人和这次运行为之工作的成员能看。普通的运行页（**运行** → 某次运行 → 上下文）同样有这个入口。

<Shot src="run-prompt" caption="看提示词：说明和消息按小节列出字数，点开任一节读原文" />
