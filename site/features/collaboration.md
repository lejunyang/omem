# 多 Agent 协作与会话

一件事交给助理后，往往不是一轮问答就能结束的：它可能需要先派调查员查资料、再让编码 Agent 改代码、请独立评审把关，或者等半小时后再看 CI 结果。**这一页介绍多个 Agent 怎么接力把长任务做完、后台几路任务同时跑时怎么避免互相撞车，以及你在中途怎么随时插话指挥。**

## 1. 长任务独立话题：多 Agent 接力，主助手统筹

面对需要多个角色配合的复杂任务，主助手会单开一个**工作会话**（在飞书里对应一个独立话题）：

1. **派活与原地更新进度卡**：主助手把当前阶段交给专职 Agent（调查、写文档、编码等），话题里只维护一张**原地刷新的进度卡片**（显示当前第几轮、谁在做、最近一步工具操作、运行记录链接）。
2. **主助手自动接力（不刷屏）**：专职 Agent 一轮做完后把报告交回主助手。主助手检查结果——能继续往下推进的，它自己直接续一轮或换下一个 Agent 接手（你上次说话后默认最多连续推进 6 次）；**中间这些交接过程只更新进度卡，不在飞书里发消息吵你**。只有全部做完、需要你拍板或卡住时，才发正式回复（下方折叠完整报告）。
3. **交办时自动临时借工具（`extra_tools`）**：主助手派活前会检查对方档案的工具清单。如果完成这步需要读某张表而对方没有该工具，主助手要么自己先查好，要么**仅在这一轮把该只读工具临时借给对方**，省去来回转交（以你身份写飞书、在群里发消息或再次交办的高权限工具绝不外借）。
4. **Agent 之间互相请教（`ask_agent`）**：一个 Agent 做到一半需要其他领域的专长时，可以直接调用 `ask_agent` 请教另一个档案（甚至跨设备请教配对机器上的 `档案@节点`）；对方用自己的工具、技能和专属记忆查清后，把答案回传给提问的这一轮。

## 2. 中途随时插话、消息自动合并与重启不断连

你不需要傻等 Agent 跑完一整轮才能说话，也不用担心后台整理材料会卡住你的聊天：

| 机制 | 实际体验 |
| --- | --- |
| **运行中实时插话（Steer）** | 一轮还在跑的时候你再发一条补充（如“只看 9 月以后的”或交办页“补充给编码 Agent”），**Agent 在当前这一轮就能立刻收到**（Codex 直接注入当前轮，其他后端在下一次调工具时收到），不打断、不重开一轮 |
| **连发与传文件自动合并** | 几秒内连发的多条短消息自动合并成一轮；先发分享群聊、合并转发、图片或文件再补说明时，会自动多等十几秒合在一起处理 |
| **对话与后台并发槽隔离** | 每个会话内部串行、不同会话之间并行；**日常对话、后台巡检/Wiki、存量批量整理各自使用独立的并发槽**，后台生成几十页 Wiki 也不会拖慢你聊天的响应速度 |
| **服务重启不打断正在跑的一轮（`restartHold`）** | 当 omem 服务升级或重启时，正在执行编码、评审、流程阶段或课题试验的那一轮 Agent 会在独立小进程（`agent-host`）中继续跑；重启后的 omem 自动把它接回来等它做完（默认最多等 5 分钟），不重发提示、不丢进度 |
| **失败重试不重复发消息** | 失败或被中断的后台运行点“重试”时，会在原 Agent 会话和工作区上继续，并明确被告知中断前已经完成过哪些写入，**已经发出去过的飞书消息绝不会再发第二遍** |

## 3. 多路运行互相感知（Awareness）：不各答一遍、你插手就让开

在 omem 里，后台常常有好几路机制同时看着你的工作：定时巡检、“有人找你”分诊、群「关注」、临时唤醒、规则触发的 Agent。为了防止它们各自为政，宿主维护了统一的**运行态势感知**：

- **开工前先看谁在办**：任何一路运行启动时，都会自动看到 **30 分钟内正在处理同一个会话、同一条消息或同一件事项的其他运行及其结论**，先看别人做到哪了再动手，绝不针对同一条群消息各答一遍。
- **你亲自插手了，后台在发出前自动复核或撤回**：后台运行（如巡检、盯群、有人找你）在准备发出通知或群回复的最后一刻，如果检测到**你刚刚在它的范围里说过话**（在同一个群/话题发了言、回复了触发消息，或在别的会话里谈了同一件事项），宿主会**先把你的原话交回给该运行再看一遍**——它会根据你的话改写结论，或者直接静默收起不再发送。
- **跨会话串联与主动接手**：一件事项在哪几个群和对话里谈过，都记在事项页的“在这些会话里进行”里，你在任何一处追问，助理都知道别处聊到了哪；如果你在对话里直接问助理一件后台正在查的事，主助手可以直接**接手**后台那一路已查到的成果接着答，无需重头再查。

## 4. 临时唤醒与定时巡检预筛

- **一句话设临时唤醒（Wakes）**：对助理说“半小时后看看 CI 结果”或“小王发了发布单就检查回滚方案”。助理会设一个**定时**或**等特定消息**的唤醒（可在 **规则 → 临时唤醒** 查看或取消），到点在原会话接着做，没有新变化就保持安静不打扰你。
- **定时巡检（Heartbeat）智能预筛**：巡检默认每 15 分钟看一次关注对象与临期事项。开启**预筛**（默认开）后，每次先由便宜的决策模型花一秒钟判断新采集的材料与你关注的事项有没有关系——无关就直接跳过不起大模型（跳过的材料每 12 小时兜底补看一次），大幅节省后台 Token 消耗。
- **后台会话池智能复用**：巡检、材料整理、Wiki 写作等后台运行会自动复用各自的 ACP 进程池，只有当真实上下文占用超过 **60%**（或超过 `120,000` tokens）时才自动释放并开启新会话，既享受到 Prompt 缓存的高速，又不会让上下文无限膨胀。
