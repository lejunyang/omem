# 群里的协作

## 有人找你

别的群里有人 @ 你，或同事私聊你，过几分钟你还没处理时（已读、回了表情、在那里回复了，哪几样算处理过可以在设置里分别勾选），omem 分三步处理，越往后越费，前一步说值得才做下一步：

1. **先免费地筛**：规则先于它——有规则在这条消息上触发过（不论是交给 Agent 还是只通知你、转发），或正等着处理它，就交给规则，这里不管；规则还在判断时先等一等。你已经看过、回过、回了表情，或者在盯这个群，也到此为止。同一个话题里连着的几条一起看；同一个人在同一话题里接着说，并进已有的处理。
2. **一次很小的判断（分诊）**：用决策模型看这条消息和前后的聊天、发消息的人、可能相关的在办事项和资料、本人写的分诊说明，判断是不用管、简短提醒你，还是值得先查，并选交给主助手还是哪个 Agent 档案。没有决策模型时按设置用通用模型判断，或者直接简短提醒。
3. **按需处理**：值得查的，交给主助手（或选中的档案）以你的身份读上下文、查事项、记忆和 Wiki，事情属于已有事项的记到时间线上，再提醒你：标题是一句话结论（“小王问退款口径：按未发货行算，可以直接回”），正文是对方要什么、查到的情况、建议的下一步或可以照着回的话、原消息链接。你回复这条提醒，就接着和它聊这件事。

查不出来、出错或超时（默认 10 分钟），照常发一条简短提醒：谁、在哪、说了什么。同一条消息几个运行都看到了，也只提醒一次。每次分诊和处理都在运行页里，能看到分诊的判断和依据。

**回复对方**（默认关）：群里和私聊各三档——不回，只提醒你；草稿，提醒旁边多一张卡片，你可以改了再点发送；自动，分诊也认为不用你拍板时直接回，回了什么写在提醒里。群里由机器人在对方那条消息的话题里回（机器人不在群里时用你的身份把它拉进来）；私聊可以选拉一个你、对方和机器人的群（只建一次），或以你的身份回、末尾带署名。每次回复都记进审计。

**经豆包发送**：有的企业不让 lark-cli 以你的身份发私聊，“以你的身份回”就发不出去。这时把“以你的身份”改成“经豆包发送”（要先 `omem doubao login` 授权豆包）：每条回复建一个新的豆包会话，只交给它定稿的回复和对方是谁（姓名、邮箱、id），让它原样发到和对方的私聊，用完就删掉会话；发完 omem 用 lark-cli 读那个私聊核对。核对上才算回复成功；豆包说发了但私聊读不了，提醒里写“未核对”；没发出或内容对不上，单独提醒你，附上原因和要发的全文，这次不会再自动发第二遍。草稿档点了发送后，卡片先变成“正在经豆包发送”，结果另发提醒。设置页能看到豆包现在能不能用（没授权、缺权限会写原因），有个“给自己发一条测试私聊”按钮（命令行是 `omem doubao send-test`），部署后先试一次。

在 设置 → 渠道 → 有人找你 里开关（默认开）、决定私聊算不算、等几分钟、写分诊说明、没有决策模型时怎么办、每天最多分诊和处理几次（超过只发简短提醒）、回复方式。分诊的判断标准是内置角色“有人找你·分诊”（mention-triage），在 Agent 页可以改。它排在所有规则之后：规则页列表最后一条“没有规则处理的、找你的消息 → 有人找你”就是它，显示开关和今天用了几次，点进去到设置里这一节。要对某类群另作处理（比如值班群直接交给某个档案），写一条规则，这里自动让开。这套流程不限于飞书，现在只接了飞书；回复对方的方式按渠道分别设。

## 盯群

临时有事时，在群里 @ 机器人说“帮我盯一下这个群，有人问接口进度就帮我回”，或把群分享给助理（机器人不在群里时，它用你的身份把机器人拉进去）。

- 群里的消息攒成一批交给助理（默认 10 分钟；@ 你或机器人的 30 秒内），整个群在一个上下文里看。
- 多数消息不管，能回答、值得排查或你需要知道时才动手；独立的话题可以交给别的 Agent 单独做。
- 节奏它自己调，到期（默认 3 天）自动停。规则页“正在盯的群”里能看到和取消。

## 长期分工的群

报警群、值班群这类长期要有人看的，先建一个处理它的 [Agent 档案](./agents)，再在群里发：

```text
/watch alert-handler mention draft
```

或者对助理说“报警群的 P0/P1 告警交给 alert-handler，回复前先给我看”。范围可以是全部消息、@ 时、或匹配某个关键词；回复方式三选一：

- `none`：只处理不回复；
- `draft`：回复先变成草稿卡片发给你，你点“发送”才发出；
- `auto`：直接用机器人回复（机器人需在群里）。

每个群（或话题）是处理 Agent 的一个连续会话，每条消息只处理一次。更细的条件（等 10 分钟没人回应再处理、已经有人回复就跳过、静默排查）用 [规则](./rules) 写。

## 几个机器人，各管一摊

`omem setup` → 渠道 → 飞书 → 添加机器人（扫码），给每个机器人选一个 Agent 档案当回答者。

- 你在群里 @ 它或私聊它时由它回答，同一个群里可以同时 @ 几个。
- 每个机器人都知道群里还有哪些 omem 机器人、各自做什么。回复里 @ 另一个，omem 就把这条回复转给它接着做；连续转交有上限（默认 4 次），有人发话后重新计数。
- 每个机器人能做的事和主机器人一样：思考气泡、卡片、@ 人、访客提问。
- 群消息的采集和规则只做一次，不会因为群里有几个机器人而重复。

## 同事 @ 机器人：访客提问

默认关，在 设置 → 渠道 → 访客提问 打开。

1. 没登记的同事在群里 @ 机器人时，先由内置角色 `gatekeeper` 判断该回答、拒绝还是不理：要它执行命令、读本机文件、打听私人信息（别人的私聊、你的记忆和日程）、问无关或敏感的事，直接回一句拒绝。
2. 能回答的由 `guest` 角色回答：只读这个群所在的空间和你另外开放的空间，不读你的个人空间，不带你的偏好和技能，也不能写记忆或发别的消息。
3. 群里被拒绝的请求，你会收到一张只有你能看见的卡片：谁、要做什么、为什么被拦。点“同意这次”就交给助理按你的身份处理，结果回在群里。

每人每小时有次数上限。你自己也在的群可以放宽：把关后交给主助手回答，或不把关直接交给主助手。两个角色的模型在 Agent 页设：把关用快的小模型，回答访客最好用不能在本机执行命令的后端。

“回答访客时完全访问”默认关：打开后回答访客的运行（`guest` 角色，以及你也在群里时由主助手回答访客的那一轮）命令不进后端的沙箱、不经审批。访客的话可能让它在这台机器上执行命令，只在回答访客的后端本来就不能执行本机命令、或你信任群里的人时打开。你自己的主助手打开了完全访问，回答访客的那一轮也不跟着打开。

在“开放给访客的空间”下拉框里按名称多选空间，再点一次可取消；选择对所有访客生效。另行开启“也回答未登记的人与机器人的私聊”后，私聊只读这些空间，未选择时没有知识库资料可查。群聊还可读群所属的非个人空间。

## 私聊指令

默认关，在 设置 → 渠道 → 私聊指令 打开。

- 在你和别人的私聊里发 `/ai`（可以在后面写要求，比如 `/ai 帮我回他部署的问题`），一分钟内助理读最近的私聊把事情处理掉，以你的身份在那个私聊里回复，结尾带“（此消息由 AI 代发）”。只想给自己看的（“/ai 总结一下”），结果发给你，不发给对方。
- `/ai拉群 [群名]` 建一个你、对方和机器人的群，机器人读之前的私聊，在新群里接着处理。

这是 omem 仅有的以你身份发消息的地方，只在你亲手发指令时发生。lark-cli 发不了私聊时，“代回怎么发”可以选“经豆包发送”，做法和上面“有人找你”的一样。
