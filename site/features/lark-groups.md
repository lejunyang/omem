# 群里的协作

在几十个飞书群里同时办公，最花精力的不是写代码，而是“别人找你问进度、盯重点项目群的动静、反复回答同类问题”。omem 为群聊协作提供了五套机制：**有人找你自动分诊协查、按问题盯群（关注）、同类型事件持续跟进、多机器人分工转交，以及同事访客提问把关。**

## 1. 有人找你：先分诊、查清背景，再带草稿提醒你

当别的群里有人 `@` 你，或同事私聊你，而你过几分钟还没看、没回时（可在 **设置 → 代你回复 → 有人找你** 设定等多久），omem 按“漏斗式”三步处理，既省额度又不漏事：

1. **第一步：免费过滤**：如果你已经已读、回过话或贴了表情，或者这条消息已经被某条[规则](./rules)或群「关注」接手处理了，直接跳过。同一话题里连续几条消息自动合并。
2. **第二步：小模型快速分诊（`mention-triage`）**：由便宜的决策模型结合前后聊天、对方身份、相关事项和你写的分诊说明，判断是**不用管**、**简短提醒你**，还是**值得先去查资料**。
3. **第三步：按需深查并拟好回复草稿**：值得查的交给主助手（或指定档案）查清事项、文档和代码，把进展记入关联事项时间线，再发一张提醒卡片给你——**标题是一句话结论**（如“小王问退款口径：按未发货行算，可直接回”），**正文附带查到的依据和拟好的回复草稿**。

### 提速与代回选项

- **90 秒快速通道（“先帮你回复”）**：开启后，在第 3 步深查前先让快模型在 90 秒内看一眼分诊材料；答得上来就立刻把结论和回复草稿发给你，答不上来再转交主助手深查。
- **怎么回复对方（不回 / 草稿 / 自动）**：
  - **草稿档**（推荐）：拟好的回复附在提醒卡下方，你点“发送”（或改两句再发）才发出；点“不发”时可选原因（不用回 / 太啰嗦 / 没有结论 / 我自己回）。
  - **自动档**：分诊确认无需你拍板的事直接替你回（群里由机器人在话题里回；私聊可拉一个你、对方和机器人的三人小群，或以你身份带署名回）。**草稿连续照发满 10 次会询问是否升为自动；自动回复若被你点个负面表情，立刻退回草稿档。**
- **越用越像你的口吻**：omem 会记下每次草稿的去向以及你后来自己在群里回的原话；下次同一个人或同类问题再来，分诊和拟稿都会参考你以往真实的回复长短与口径。

## 2. 关注（盯群）：按问题跟到底，而不是按消息刷屏

临时要盯一个或几个项目群时，在群里 `@` 机器人说“帮我盯一下这个群，有人问接口进度就帮我回”，或者把群分享给助理（也可以在 [工作线](./work-lines) 的“人和群”里把相关协作群挂上去）。这就建立了一个**关注**。

### 它和普通关键词机器人有什么不同？

- **多群合一，共享上下文**：一个需求的研发群、测试群、值班群可以放进同一个关注里，同一件事跨群讨论也能连起来。
- **攒批预筛，绝不刷屏**：普通消息默认攒 10 分钟看一批（`@` 你或机器人的 30 秒内即看），先由决策模型筛掉无关闲聊；讨论热烈时自动缩短间隔。
- **按“问题”跟到收尾**：群里有人报障或求助，助理处理后会记下**“这件事在等谁、怎样算完”**。之后群里的新消息先对照该状态判断——只有等的人回了、补了截图/ID 或出现新卡点才继续查；群友发“收到”“谢谢”不会触发它重复查一遍。
- **主动推进只读步骤**：在工作线的关注里，测试同学说“可以验收了”，助手会自动在后台核对部署与测试记录，把结果和依据写回工作线时间线；需要改外部系统或发消息时，才生成执行卡等你点“执行”。
- **积累案例与经验**：每次处理（包括你自己在群里的回复，以及你对草稿标的“该回 / 不该回 / 回得不对”）都会存为案例，后台定期按场景提炼成这个关注的专属经验文档。

### 每个关注可调的设置

你可以直接在关注页的“设置”标签里改，也可以直接对助手说“把退款值班的关注改成只看 @ 我的”：

| 设置项 | 可选档位（粗体为默认） | 核心作用 |
| --- | --- | --- |
| **在群里回复** | 不回，只看 / **先给我看** / 直接回 | “先给我看”会先把草稿发成仅你可见的卡片，点发送才发出 |
| **看哪些消息** | 只看 @ 我或机器人的 / **挑和说明有关的** / 每批都看 | 配合决策模型预筛与把握门槛（0.5–0.95），过滤无关批次 |
| **攒多久再看 / 每日上限** | 不等 / 5 分钟 / **10 分钟** …（每天默认 **20 批**） | `@` 你或机器人的消息 30 秒内响应且不受每日批次上限限制 |
| **要不要去查** | 能直接答的才答 / **值得查的就去查** | 调用技能、日志、代码和知识库核实后再给结论 |
| **问我、要我拍板的** | **只私下告诉我** / 拟一条给我看 / 可以替我答 | 排期、承诺、对外口径等默认绝不在群里替你表态 |
| **群里有人开会时** | 不管 / **问我要不要进会** / 直接进会旁听 | 带着该关注的说明和经验进会旁听，会后小结写回该关注 |
| **主动推进（工作线）** | 不主动 / **每天提几条下一步** / 只读的事先做 | 每天梳理现状与下一步放进早上的“今天”卡片 |

> **长期固定分工的群（`/watch`）**：对于常年运作的报警群、oncall 群，可以先建一个专门的 [Agent 档案](./agents)，再在群里发 `/watch alert-handler mention draft`（范围可选 `all | mention | keyword:正则`，回复可选 `none | draft | auto`）。

## 3. 持续跟进的规则：同一类事，每次发生单独开一轮

有些事不是盯某一个固定的群，而是**“同一类周期性或突发事件，每次发生都要先查一遍、再跟到结束”**（例如“每次项目 A 演练开始，先核对范围，出异常私下告诉我”）。

在 [规则](./rules) 页新建时选择**“持续跟进”**：
- **共用说明与经验，每次独立建项**：写明什么时候算开始、发生时关心什么。每次命中触发条件，omem 就单独开一次跟进（独立的事项与会话），你在别的会话里补充的情况也会自动汇入这一次。
- **首条预查 + 跨群同步**：开启“帮你回复”后，每次新开时先跑只读预查脚本并发出第一条结论，随后带着结果持续跟进；在规则的“这一次的群里”选“先给我看”或“直接发”，还能让它自动认出当次演练的协作群并把后续进展发过去。

## 4. 多个机器人各管一摊，还能互相 `@` 转交

你可以在 `omem setup`（或 **设置 → 渠道 → 飞书**）里扫码添加几个不同的飞书机器人，也可以让团队成员在 **账号 → 我的助手** 里一键创建属于他自己的机器人：

- **各自绑定专职档案**：比如一个叫“主助手”，一个叫“报警分析”，一个叫“代码评审”。
- **群内互相 `@` 接力**：每个机器人都知道群里还有哪些 omem 机器人、各自负责什么。你在群里可以同时 `@` 几个；一个机器人在回复里 `@` 另一个机器人时，omem 会自动把这条回复转交给对方接着处理（连续自动转交上限默认 4 次，有人发言后重置）。群消息采集和规则触发只执行一次，不会因为群里有多个机器人而重复。

## 5. 同事 `@` 机器人：访客提问与安全把关

在 **设置 → 代你回复 → 访客提问** 开启后（默认关闭），未登记为 omem 成员的群友也能在群里 `@` 机器人问项目上的事，同时严格保护你的私人数据：

1. **第一道门：访客把关（`gatekeeper`）**：用快模型先审一遍——凡是要求执行本机命令或脚本、读取本机文件、打听私人信息（别人的私聊、你的个人记忆和日程）或无关敏感话题，直接礼貌回绝。
2. **第二道门：受限回答（`guest`）**：通过把关的问题，由 `guest` 角色**只读该群所属的非个人空间**以及你在下拉框里明确“开放给访客的空间”，不带你的个人偏好、不挂载写工具。
3. **被拒请求可一键放行**：被把关拦下的群友请求，会发一张**仅你可见**的卡片给你；如果你觉得这个问题可以答，点**“同意这次”**就会转交主助手按你的权限查清并回复在群里（你自己也在的群，还可设置为把关后直接交主助手回答）。

## 补充说明：私聊 `/ai` 指令与经豆包代发

- **私聊 `/ai` 指令**（在 **设置 → 代你回复 → 私聊指令** 开启，默认关）：在你和别人的飞书私聊里，亲手发出 `/ai 帮我回他部署的问题`，助理会在一分钟内读最近私聊、查清资料，并以你的身份发出结尾带 `（此消息由 AI 代发）` 的回复；若只发 `/ai 总结一下`，结论只私聊发给你自己；发 `/ai拉群 [群名]` 则自动建一个你、对方和机器人的三人小群接着处理。
- **企业限制发私聊时经豆包代发**：如果公司飞书租户禁止 `lark-cli` 以个人身份发私聊消息，可在“有人找你”或“私聊指令”里将发送方式改为**“经豆包发送”**（需先运行 `omem doubao login` 授权，并用 `omem doubao send-test` 试发验证）。每次代发会新建一个独立的豆包 OpenAPI 云端会话，只传入定稿正文与收件人，发完立即销毁会话并用 `lark-cli` 只读核对私聊记录，核对无误才算发送成功。
