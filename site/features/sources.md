# 原件与空间

<Shot src="sources-catalog" caption="原件：按目录树展示，知识库、云文档、聊天、网页和会议各有自己的层级；目录上可以设关注程度" />

## 原件

原件是一切回答的依据：文档、聊天、代码文件、网页、笔记、日程和妙记。

- **保存方式**：<kbd>Ctrl J</kbd> 保存材料（文本、网址、飞书文档、拖入文件），`omem add`，或者渠道自动采集。
- **文档解析**：PDF、DOCX、XLSX、PPTX、CSV、HTML；Docling 可选，旧版 Office 需要 LibreOffice。
- **代码**：按符号切分，有调用图——原件页点函数名可以看谁调用它、它调用了谁。
- **聊天**：显示成聊天，有发送人、时间、引用的消息、话题、图片和文件；长聊天只渲染屏幕附近的部分。
- **版本**：只保留最新版；聊天按追加保存；删除留墓碑，引用它的地方会提示已移除。
- **重复**：同一篇飞书文档只存一份（知识库里的按 /wiki/ 链接）。以前留下的 docx / wiki 两份用 `omem lark docs-dedupe --apply` 合并，旧的引用照常能打开。内容完全相同的不同文档检索时只显示一份，注明“另有 N 份相同内容”，可以展开。

## 目录

原件页按目录树一层一层展开，每个目录带份数和关注程度色点：

- **飞书知识库**：知识库 → 各级节点 → 文档（文档下面还能有子页面）。看到过但没采集的节点是灰色的，点“采集”读进来。
- **知识库外的飞书云文档**：按“由哪篇文档链接进来”分组，单独给的在“直接导入”。
- **聊天**：群聊 / 话题群 / 单聊 / 机器人 → 会话 → 月份；会话里的图片收在“图片”下。
- **网页**按站点，**会议和日程**按年月，**笔记和工作文件**按月；代码仓库按路径。
- **业务空间的仓库**：挂在业务空间下的仓库是树里的目录（代码图标和份数），展开就是这个仓库的路径树；仓库多时收在一个“仓库”目录里，默认折叠。仓库那一行的菜单里能看到它的本地路径，“单独打开”切到仓库空间（同步目录在那里）。

列表上方两行筛选：第一行是关键词和类型，第二行是关注程度（选项里带各档份数），右边的“待复核”打开要你确认的 Agent 判断，再点“回到目录”回来。筛选同时作用于计数。

## 关注程度

可以在目录树的任一目录上设关注程度：整个子树连同以后进来的都按这一档（本人给单份定过的档不变）。每份原件也可以单独选“重点关注 / 一般 / 仅检索 / 忽略”，过时或关键的段落可以加标注（写清以哪份为准）。重点的排在检索前面，仅检索的排后面，忽略的不再出现；命中过时段落时带着标注。也可以直接说“这个知识库都是历史资料”“值班群的要重点看”，助理会定级、加标注或存成规则。

标注按它盖住的那部分生效：一大段里只有一行有误，不会把整段压下去。测试数据、粘贴的日志可以标成“不检索”。文档改版后，标注会跟着被标的那段移动；那段被删掉时标注显示“原文已改动”，不再影响排序。

<Shot src="sources-review" caption="待复核：Agent 写的标注和目录定级，按影响面排序，逐条确认或否定" />

Agent 写的标注先按一半强度生效。原件页的“待复核”按影响面（影响过多少次检索结果、目录下有多少份）列出 Agent 的标注和目录定级，逐条确认或否定：确认的“有误”和“不检索”段落不再被检索到；否定的不再起作用，Agent 也不会再加同一条。经常被回答和 Wiki 引用的原件排序稍微靠前（最多 ×1.1）。

## 搜索

<Shot src="search-hits" caption="Ctrl K 的搜索结果：标题在前，所在位置和链接在后，摘录是匹配处周围的文字，查询词高亮" />

<kbd>Ctrl K</kbd> 同时搜原件、Wiki 页面、记忆和代码符号。每条结果先写标题（文档标题，不是链接），接着是类型、所属空间和位置（飞书文档的知识库路径、小节标题、Wiki 页面所在目录），链接放在次要位置；下面是匹配处周围的摘录，已经去掉 Markdown 和 HTML 表格的标记，查询词高亮。长文档里的匹配靠后时，摘录也落在匹配处。

## 空间

空间把领域分开：个人、项目、代码仓库、学习、通用。

- 检索默认在当前空间和它的**相关空间**里，主助手可以显式查所有你能访问的空间。
- 互相调用的仓库、同一项目的几个空间可以关联（设置 → 空间，或对助理说“A 调用 B 的接口”）；整理时会发现可能相关的空间，确认后关联。
- 代码仓库挂在它所属的业务空间下：业务空间的设置里“仓库”一栏，填本地路径或 Git 链接“添加”，或把已有的仓库“归到这里”（设置页会提示哪些仓库可能属于这里：你关联过的、交办记在这里的、事项挂着的）。之后在业务空间里检索、交办、评审都包括这些仓库，交办记在业务空间；左上角选业务空间就是整个业务，也能只选其中一个仓库。仓库自己的检查命令、目录等在它的“设置”里。不属于任何业务的仓库单独列出。
- 一个空间可以同时放项目文档、讨论和代码，但只关联一个仓库；几个仓库就各自挂在业务空间下。

在 **设置 → 空间** 新建“代码仓库”时，一个输入框自动识别目录和 HTTP(S)/SSH Git 地址。目录填运行 omem 的机器上已有的绝对路径；Git 地址自动克隆到数据目录的 `repos/`，再导入文件（遵守 `.gitignore`）。私有仓库使用服务器已有 Git/SSH 读取权限，链接里不含密码或令牌。克隆期间显示等待状态，失败后可修改表单重试，不创建空空间。

## 代码索引：基线与分支

代码仓库的索引可以有两种来源，在仓库“设置”的 **代码索引** 里选：

- **按基线分支**：从远端默认分支（或你填的分支、标签、提交）的提交里读文件，不管仓库目录里检出了哪个分支、有没有没提交的改动。新接入、有 origin 的仓库默认是这种。
- **按目录现状**：读目录里现在的样子（以前的做法，已接入的仓库保持不变，点一下即可切换）。目录停在功能分支上时，那个分支的代码就是索引里的代码。

切换和更新都不改原件 id，Wiki 和记忆里的代码引用照常能打开。

- **定期更新**：每小时拉取一次远端（只 fetch，不动目录和本地分支），一个仓库的几个子目录空间只拉一次；基线有新提交才重读改过的文件，没有变化时只问一次远端、不拉取。拉取失败（没权限、网络）会写在仓库设置里，业务空间的仓库列表也会标出“上次同步出错”。“立即同步”马上拉取一次。
- **跟的分支**：正在做的功能分支、预发分支加进“跟的分支”，和基线一起刷新；问到时直接可查。
- **助手默认只查基线**：不说分支时只查基线；说了分支（或这次运行就是那次交办、那条分支的评审）才连同分支的改动一起查。结果和读到的代码都写着“代码来自”哪个分支、哪次提交，回答里也会说明依据。
- **临时索引自动清理**：查过的分支、评审过的提交、交办改过的文件都是临时索引：交办确认或丢弃后马上删，评审某个提交建的 3 天没用就删，其他分支 14 天没用就删。
- **推送后马上同步**：代码平台能发 webhook 的，点“变更通知令牌…”生成令牌（只能触发拉取，不能读任何内容），推送时调用 `POST /api/code-index/notify`，内容写 `{"repo": "<仓库地址>", "branch": "<分支>"}` 或 `{"space": "<空间 id>"}`。各家平台的推送格式怎么转成这个调用，写成数据目录里的技能或规则。

## 归档规则

“规则 → 归档规则”按标题、正文、网址或路径、采集渠道、知识库目录设条件，把同类材料自动放进对应空间；写不成条件的交给 AI 判断。历史材料先预览再应用，迁移保留 id、引用和行号。

## 整理一大批材料

原件页“整理”：先“分级”过一遍，再“精读整理”成主题页、案例页、标注和记忆。后台一批一批地做，可以几批同时跑在不同模型上，`omem digest` 看进度。

引用落在表格、列表或代码块内部时，抽屉保留完整结构并高亮整个块。切到原文行号可以核对精确引用行。
