# 原件与空间

**omem 不把文档、聊天和代码拆成三个互不相通的系统，而是把它们统一存为“原件（Sources）”，并用“空间（Spaces）”隔离不同的项目与领域。** 所有的 Wiki、记忆、事项和回答都必须引用原件的具体行号。

## 1. 原件：一切知识的事实依据

无论是通过 <kbd>Ctrl J</kbd> 手动粘贴/拖入、`omem add` 命令行导入，还是由飞书/连接器自动采集，所有材料进入 omem 后都是原件：

| 原件类型 | 切分与展现方式 | 版本与去重机制 |
| --- | --- | --- |
| **文档与网页**（Markdown / PDF / DOCX / XLSX / PPTX / CSV / HTML） | 按章节标题切分；插件解析的表格或记录原件可直接按表格行浏览并逐行引用 | 按路径或 URL **只保留最新版**；同一篇飞书文档从 `/docx/` 与 `/wiki/` 进入自动归一；内容完全相同的不同文档检索时合并展示并注明“另有 N 份相同内容” |
| **代码文件**（支持 25+ 语言 AST / Tree-sitter） | 按函数、类等**代码符号**切分，自动构建跨文件**调用图**（在原件页点函数名即可看谁调用它、它调用了谁） | 默认按远端**基线分支**的提交建立索引，不受本地目录检出状态干扰；功能分支与交办工作区按需建立临时叠加索引 |
| **聊天与会议**（群聊、话题、私聊、会议转写） | 按会话时间窗口切分；原件页还原真实聊天视图（发送人、时间、引用回复、图片与附件），超长聊天虚拟滚动 | 按**追加（Append-only）**保存；删除原件时保留墓碑记录，已引用它的页面会明确提示原件已移除 |

## 2. 空间与跨空间关联

空间用来把不同领域的资料隔开，分为五种类型：**个人、项目、代码仓库、学习、通用**。

- **业务空间挂载多个代码仓库**：一个项目往往包含前端、后端等多个仓库。你可以在业务空间的 **设置 → 仓库** 里添加本地路径或 Git 链接（自动识别并克隆到 `repos/`），或把已有仓库归入该业务空间。此后在该业务空间里**检索、交办编码、评审**都会自动覆盖旗下所有仓库；原件目录树里也会直接把旗下仓库作为目录展开。
- **相关空间联动检索**：互相调用的仓库、同一项目的几个空间可以建立关联（在 **设置 → 空间** 添加，或对助手说“A 调用 B 的接口”；定期整理也会根据互链和依赖自动提议关联）。**检索时默认同时查当前空间及其相关空间**；整理、复核等单空间后台任务也会对相关空间只读，避免重复造记忆。

## 3. 关注程度与段落标注：让重要、新鲜的资料排在前面

资料库大了以后，历史过期文档和噪音群聊会干扰检索。omem 用**四档关注程度**和**行级段落标注**来控制检索权重：

| 关注程度 | 检索与整理行为 | 怎么设置 |
| --- | --- | --- |
| **重点关注** | 检索权重提升（`×1.6`），后台整理与 Wiki 补写优先读取 | 可在单份原件上选，也可在**目录树任意节点**上设（整个子树及未来新进该目录的材料全部继承）；或直接对助手说“值班群要重点看” |
| **一般**（默认） | 正常参与检索与新材料整理 | 默认档位 |
| **仅检索** | 检索权重降低（`×0.55`），**不触发后台自动整理** | 适合历史归档知识库（对助手说“这个知识库都是历史资料”） |
| **忽略** | **不进检索结果、不整理**（仅通过精确 ID 仍可读取） | 适合废弃材料或无关群聊 |

### 段落级标注与双模型复核

如果一篇文档只有其中一段过时了，不需要整篇忽略——可以在具体行上加**标注**（**已过时 / 有误 / 关键 / 备注 / 不检索**，并写明“以哪份新文档为准”）：
- **精准作用于重叠行**：标注只降低或提升它所覆盖那几行的检索权重；命中过时段落时，检索结果会同时附上标注说明和指向的新原文。文档改版后，标注会通过文本锚点自动跟随段落移动；若原段落被彻底删改，标注自动失效并列入待复核。
- **先半效、再盲评、每晚抽检**：Agent 自动打上的标注先按 `50%` 强度生效；每小时由独立的 `note-reviewer` 模型对照原文复核（保留的升为 `80%` 强度，撤回的失效，拿不准的放进 **原件 → 待复核** 交由你确认）；只有你本人确认的“有误 / 不检索”才会彻底从检索结果中隐藏。此外，每晚还会自动抽检 Agent 对目录和原件的定级。

## 4. 搜索原理：全文 + 向量 + 代码符号 + 重排

按 <kbd>Ctrl K</kbd> 可同时搜索原件、Wiki 页面、记忆和代码符号。搜索结果先写文档标题、所属空间与目录路径，下方展示去除杂乱标记后的纯文本高亮摘录；引用落在表格或代码块内时，抽屉会保留完整排版并高亮对应行。

<Shot src="search-hits" caption="Ctrl K 搜索结果：标题与知识库路径清晰前置，匹配处周围正文高亮展示" />

<Shot src="citations-table" caption="表格与代码块引用：从第 7 项开始引用时，右侧抽屉仍保留完整表格结构并高亮目标行" />

底层检索走同一条流水线，融合三路召回：
1. **SQLite FTS5 全文检索**：内置中文双字分词与代码驼峰/下划线标识符拆分（如 `upsertSource` 自动拆为 `upsert source`）。
2. **向量语义检索（可选）**：支持本机 `bge-small-zh / bge-base-zh / bge-m3`（内存 `int8` 量化矩阵，17 万片段仅占约 0.4 GB 内存），或走云端 API / 插件向量接口。
3. **代码符号精确匹配**：直接定位函数、类与变量定义。
4. **交叉编码器重排（Rerank，可选）**：经 RRF 融合取出前 20 条候选后，可开启本地 `bge-reranker-v2-m3`（或云端/插件重排接口）将问题与候选全文逐条对读打分，在公开中文检索集（T2Retrieval）上将 `nDCG@10` 从 **86.6 提升至 91.6**；开启后，对话前自动带上的相关记忆也会由重排模型把关相关性。

## 补充说明与进阶配置

### 代码索引：基线分支与分支叠加

在代码仓库空间的 **设置 → 代码索引** 中：
- **按基线分支索引（默认）**：直接从 Git 远端默认分支（或指定分支/标签）的提交对象里读取文件，每小时自动 `fetch` 增量更新；**无论你在本地工作目录里检出了什么分支、有没有未提交的脏改动，都不会带偏知识库索引**。还支持配置 webhook（`POST /api/code-index/notify`）实现代码推送后立刻同步。
- **按分支检索（叠加索引）**：把正在开发的功能分支加进“跟的分支”，或在提问/命令里指定分支（`omem search --space shop-api --branch feature/refund`），omem 只为该分支改动和删除的文件建立轻量叠加索引，用完到期自动清理。回答时始终注明代码来自哪个分支、哪次提交。

### 自动归档与“从个人空间归位”

- **归档规则**：在 **规则 → 归档规则** 中，可按标题、正文、网址/路径、采集渠道、飞书知识库目录设条件（或用一句话让 AI 起草规则），把新采集的材料自动分流到对应项目空间；历史材料支持先预览再批量迁移（保留原件 ID 与所有行号引用）。
- **从个人空间自动归位**：未命中规则的材料先落入个人空间。每晚归档角色会结合**旁证**（所在飞书知识库、同目录文档去了哪个空间、哪些业务页面或事项引用了它、在哪个群被贴过）重新判断，多条线索指向同一业务空间时自动移过去（为业务事项写的工作文件直接随事项归位）。你可以在 **规则 → 归档规则 → 从个人空间归位** 查看自动移走的记录（可一键移回并锁定）、批量处理 AI 拿不准的材料，或排查哪些业务页面引用了协作者无权打开的个人空间原件。

### 向量与重排使用云端接口 & 批量整理存量材料

<Shot src="settings-search-providers" caption="设置 → 检索与记忆：向量与重排均可独立选择本机模型、云端 API 或插件，保存前先点“试一下”验证" />

- **免装本地模型走云端 API**：在 **设置 → 检索与记忆** 的“向量检索”和“重排”卡片中，可将来源设为**“云端接口”**（复用 **设置 → AI** 中保存的服务商密钥或环境变量）或**“插件”**。修改后可先点**“试一下”**（仅发送固定测试短句，不外发库内资料）检验连通性与维度；更换向量模型或维度时，系统会先弹窗列出需清空和重算的条数，经你确认后才重建。
- **批量整理存量旧材料**：导入一大批历史群聊或旧文档后，可在原件页点**“整理”**（或运行 `omem digest <空间> --mode triage|digest`），先批量“分级”，再多模型并行“精读整理”成主题 Wiki 页、排查案例页、段落标注和记忆。
