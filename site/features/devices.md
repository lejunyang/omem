# 多台设备与多人协作

omem 既可以作为你个人的**多设备分布式知识网络**（一台服务器 24 小时常驻采集，你的笔记本和台式机随时连上去看、拉取完整备份、互相借用 AI 算力与派活），也可以在开启**“多人登录”**后作为**整个小团队的共享助理**（按空间与二十多项细粒度能力管控权限，成员在 Linux 沙箱里使用各自的飞书连接与各自的 AI 账号，互不串号）。

---

## 第一部分：你自己的多台设备（Peer 组网与算力共享）

最典型的个人架构是：**一台机器常驻运行**（服务器、Mac mini 或家里的台式机，负责 24 小时采集飞书、跑定时任务和编码交办），**你随身带的笔记本与之配对**。两台机器甚至不需要能直接互通——支持经中间节点（`--via`）转发，或开启**反向连接（`peer back`）**穿透 NAT。

### 1. 五种跨设备协同方式

| 你想做什么 | 怎么操作 | 核心优势 |
| --- | --- | --- |
| **1. 在笔记本浏览器里看常驻机器（含预览端口转发）** | `omem peer open <常驻设备>`（或用 `omem link` 打印带令牌的链接） | 在本机起一个免令牌安全转发地址；**点开交办的网页预览时，自动在你笔记本监听相同端口号并转发 HTTP 与热更新 WebSocket** |
| **2. 借用另一台设备的 AI 后端与额度** | 在 **设置 → 设备** 展开对方设备，勾选它上面的某个 ACP Agent（如对方登录了 Claude Code 或有空闲额度） | 该 Agent 直接出现在你本机的 Agent 列表里；**模型在对方机器上跑（用对方的登录和额度），但调的工具和读写的知识库全都在你本机** |
| **3. 让两台 omem 的 Agent 互相请教（Mesh）** | 配对设备每 10 分钟自动交换一次“节点名片”；提问涉及对方领域时，助手自动调用 `ask_agent("档案@节点")`（也可直接说“问问某台的某个 Agent”） | 在对方机器上只读调查并用对方的 AI 作答，回答里引用的原件自动取回本机，点开就能看原文 |
| **4. 用本机大模型整理常驻机器的库、审它的分支或改它的代码** | `omem tool --peer <设备> …` 或 `omem mcp --peer <设备>` | 本机无需跑 omem 服务，直接用本机的 Claude Code / Codex 读写整理服务器上的知识库，或接手服务器上的 `review_branch`（分支评审）和 `delegate_code`（编码交办），不花服务器模型额度 |
| **5. 把调查任务块或“研究”试验派给另一台设备跑** | 任务板 `dispatch_work` 指定 `device`（`borrow` 借算力 / `remote` 在对方环境跑）；或将研究流程的执行环境设为“派给设备” | 适合需要另一台机器特定操作系统、编译环境或已登录平台的场景，结果、截图证据与 Token 用量自动传回发起端 |

### 2. 三行命令完成配对、反向连接与自动全量备份

```bash
# 1. 在常驻机器上生成一行配对码（含本机所有网卡地址与专属令牌）
omem peer invite --label server

# 2. 在你的笔记本上添加配对（若需中间机器转发则加 --via <中间设备>）
omem peer add <配对码>
omem peer back server on                    # 可选：开启反向连接，让连不到你笔记本的服务器也能反过来借你笔记本的 Agent

# 3. 开启自动全量备份（每 20 分钟检查一次，连得上就增量拉取数据库、Wiki、附件和代码仓库到本地目录）
omem peer backup server --to ~/omem-backup --at 00:00
```

- **离线随时查看备份**：白天笔记本带出门断网没关系，晚上连上同一网络后会自动补齐备份；传到一半断了会从断点接着传，连续 3 次没拉下来会发一条通知。想单独查看这份备份数据时，运行 `omem --home ~/omem-backup serve --no-background --port 4400` 即可只读浏览，不会误触发定时任务或重复发通知。
- **跨服务共享指定空间（和朋友或别的团队的 omem 互联）**：在 **设置 → 设备 → 和别人的 omem 共享** 中，可挑选几个空间设为“只检索”或“可同步”，生成受限配对码发给对方；对方订阅并勾选“同步到本机”后，每半小时自动同步成只读镜像（**一个空间只有一个主节点**：在镜像端让助手记的记忆或改的 Wiki 会自动发往主节点落库再同步回来，两台机器绝不产生分叉版本；想彻底留在本地的空间可勾选“仅本机”）。

## 第二部分：团队多人协作（权限矩阵、各自飞书与沙箱 AI 账号）

omem 默认只服务你本人。当你想把这台 omem 开放给项目组的同事一起用时，进入 **设置 → 成员** 开启**“多人登录”**。

### 1. 怎么让同事进来、怎么精细控制“每个人能做什么”

- **免审批预建或扫码即登**：
  - 你可以直接在飞书里 `@` 助手说**“把 @小王 @小李 加成用户，项目 A 可写”**，或在成员页**按企业邮箱预建账号**并分好空间——同事第一次在飞书上找机器人、或用飞书扫码登录网页时，系统自动按通讯录邮箱认出他并赋予对应空间权限，无需二次批准（也可生成一次性邀请链接 `omem user invite --space team`）。
  - 同事如果只想在自己电脑的 Claude Code / Codex 里查团队知识库，只需装轻量包 `npm i -g @omem-ai/cli`，运行 `omem login <网页地址>` 确认后，再用 `omem mcp --url <网页地址>` 即可按他自己的空间权限调用只读与整理工具。
- **全局角色 + 空间角色 + 20 多项细粒度能力表**：
  - 每位成员拥有一个**全局预设角色**（访客 / 成员 / **网页只读观察者** / 管理员）和在各空间内的**空间角色**（只读 / 贡献者 / 编辑 / 管理）。
  - 点开成员行的**“能做什么”**，右侧会展开包含“工作与事项、资料与知识、规则与流程、运行与编码、对话与通知、成员管理、设置（分 7 个区域各自独立控制查看与修改权）”的 **20 多项能力矩阵**——每一项都支持单独设为**跟预设 / 允许 / 不给**，还能点“按空间”针对单个空间特殊授权！网页界面会根据每个人的实际能力自动裁剪，没权限的导航菜单、设置卡片和操作按钮直接隐藏或置为只读。

### 2. 成员连接自己的飞书，看受限原件

- **按功能逐项授权自己的飞书**：每位成员可在 **账号 → 已连接的应用** 里连接他自己的飞书（按群聊、单聊、文档与知识库、表格、日程、妙记、写文档逐项勾选开关）。连接后，**他的 Agent 运行和属于他的助手完全以他自己的飞书身份读写文档与表格，绝不借用你本人的飞书登录**；他在账号页开启“采集到 omem”后，他的群聊、日程和最近打开的文档也会自动采集进他自己的个人空间（可设置默认排除个人文档库或指定链接，已在共享空间里的文档自动去重不存两份）。
- **原件级权限保护**：空间管理员可以把某份敏感原件（如放进项目空间的一段单聊）设为**“受限”**（仅点名的人和管理员可见），或者开启**“按各人的飞书权限显示文档”**（成员连接飞书后，实时向飞书核实他有权阅读才展示全文，且这两类原件绝不会生成外部只读分享链接）。

### 3. Linux 沙箱隔离：让同事用他自己的 AI 账号与额度

如果不希望同事的提问和日常整理消耗你本人的 Claude / Codex 套餐额度，在装有 `bubblewrap` 的 Linux 服务器上（运行 `apt install bubblewrap` 或 `osdk pkg apply`），每位成员都可以登录并隔离使用他自己的 AI 账号：

- **网页或飞书私聊一键扫码/贴码登录**：成员在 **账号 → 我的 AI 账号** 里点登录（Codex、TraeX、豆包显示设备码/二维码并同步发到他飞书私聊；Claude Code 粘贴授权码或 `setup-token`；企业统一身份可通过 `api.agentLogin` 插件接入）。
- **操作系统级账号目录隔离（`bubblewrap`）**：虽然所有运行属于同一个 Linux 系统用户，但当成员使用自己的 AI 登录时，宿主会将其 Agent 放入独立的 `bubblewrap` 沙箱中运行——**沙箱内的 `HOME` 是该成员专属的独立目录，完全看不到你本人的 AI 登录、omem 主数据目录和其他同事的账号目录**；他的套餐额度在他的沙箱里独立读取、独立避让，用完了只影响他自己。
- **灵活的借用与强制隔离策略**：你在 **设置 → 成员 → 成员的 AI 账号** 中，可按每个后端设置未登录成员是**“借用本人的”**（你额度充足时先借用，你额度快用完时自动切回成员自己的登录）、**“换别的后端”**还是**“只能用自己的”**；把全局 `agents.accountIsolation` 设为 `require` 后，任何无法实现沙箱隔离的后端都会对成员直接禁用。
