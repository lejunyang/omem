# 多台设备与多人

## 互相知道、互相请教

配对的 omem 每十分钟交换一次名片：那里有哪些助手（是谁的、做什么）、哪些 Agent 可以请教、共享了哪些空间。你的助手的说明里会多一段“网络里的其他 omem”，问题属于对方的领域时它用 `ask_agent` 去问，对象写「档案@节点」；你也可以直接说“问问 某台 的 某个 Agent”。被问的 Agent 在对方那台上运行、用对方的 AI，只读对方共享出来的空间，回答里的引用会取回你这台，点开就是原文。

你自己的几台设备之间什么都能看到、都能问。别人的服务默认只知道你共享了哪些空间：要让它请教你的 Agent，在 设置 → 设备 里它的共享下面选“可以请教的 Agent”，可以限每天几次；“让对方看到这台上有哪些助手”是另一个开关。别人的服务问你的助理时，它只读共享的空间，不带你的偏好和记忆。

名片列表在 设置 → 设备 最上面的“网络里的 omem”。设计和后续（借对方的 AI、按空间定主从的同步）见仓库的 docs/v2/mesh.md。

## 多台设备

常见用法是一台机器常驻运行（采集、定时任务），其他机器拉它的数据、看它的状态、让它执行检查。机器之间不必能直接访问，可以经中间那台转发。

```bash
# 常驻那台
omem peer invite --label laptop       # 打印一行配对码，含本机所有网卡地址

# 另一台
omem peer add <配对码>                # 直接能访问到
omem peer add <配对码> --via <中间那台> # 只能经中间那台访问
omem diag <设备>                      # 版本、数量、最近失败、采集状态、Agent
omem peer commands <设备>             # 可远程执行的命令
omem peer call <设备> update          # 拉代码、装依赖、构建、重启
omem peer pull <设备>                 # 拉一份快照合并进本机（逐项选拉哪些、拉进哪个目录）
omem peer open <设备>                 # 在本机浏览器打开它的网页
omem tool --peer <设备> search query=退款  # 用本机的 Agent 整理它的库（见下）
```

`peer pull` 的数据库（原件、记忆、事项、会话、运行记录……）总会拉；另外四项可选：知识库（Wiki、Agent 档案、技能）、附件与图片、代码仓库、编码工作区与运行产物。在终端里运行时逐项勾选，并问拉进哪个数据目录（默认当前的，`--to` 指定别的，不存在会新建）；脚本里用 `--only library,files`（给空字符串只拉数据库）和 `-y`。合并是增量的：已有的记录按时间取新，附件只传本机没有的，搜索索引不传、在本机按拉来的原件重建；数据库和仓库每次仍是整份传。对方版本较旧时会发来全部内容，本机只合并选中的部分。

网页里 **设置 → 设备** 能做同样的事：生成配对码、粘贴添加、检查在线、改地址、移除，并列出拿着本机令牌的设备，可以逐个撤销。设备之间是 HTTP 直连，令牌有本人的全部权限，只在自己的局域网或 VPN 里配对。

`diag` 的 `eventLoop` 一节说明主线程有没有被卡住：事件循环延迟（p50 / p99 / 最大）、最近几次超过 500 ms 的卡顿（卡了多久、当时在做的同步步骤，如某条 SQL、某个 git 命令，以及刚开始的请求或工具）和最慢的同步步骤。卡顿同时记一行日志 `[omem] 事件循环卡了 … ms：…`，用 `omem peer call <设备> logs '{"stream":"err"}'` 能看到。

远程命令是固定的一组（诊断、日志、配置、只读查询、手动采集与回溯、运行记录、只读 SQL、查看 AI 后端 / 检索 / 运行说明 / 网页版 VS Code、git 与更新、重启），没有任意 shell。配对码里的令牌可以随时撤销。

### 用本机的模型整理它的库

常驻服务器上的知识库想让本机的 Claude Code、Codex 来整理（用本机的模型，而不是服务器自己的），不用登录服务器，直接把工具指到设备上：

```bash
omem tool --peer <设备>                          # 列出能用的工具
omem tool --peer <设备> search query=退款 space=project-a
omem tool --peer <设备> --session 整理项目A remember '{"kind":"fact","content":"…"}'
omem mcp --peer <设备>                           # 或配成 MCP 服务给 Agent 用
```

工具和 `omem mcp` 是同一套，但去掉了会对外发消息或动手的：飞书发送、通知、交办编码、让对方机器的 Agent 或模型干活、唤醒，以及改档案、技能和规则。读取、检索、记忆、Wiki 页面、原件关注度与标注、事项这些整理类的读写都可以。每次调用都记在对方的一条“设备的外部 Agent”运行里（一个会话一条，`--session` 区分），运行页能看到做了什么，写入的记忆来源档案是 `peer:<本机名>`。本机不用开 omem 服务；经中间机器连接时，中间机器不用更新。`--space` 选默认空间，`--spaces a,b` 限定可读写的空间，`--read-only` 只读。

也可以让本机的 Agent 评审它上面的分支：`review_branch` 经 `--peer` 调用时，那台机器只负责检出分支、取改动、建索引，评审项留给本机的 Agent。它用 `review_task` 取材料，逐项 `submit_review` 提交，交齐后那台机器汇总结论、通知你，评审页上每项显示 `peer:<本机名>` 和模型。整个过程不用那台机器的模型。

写代码也一样：`delegate_code` 经 `--peer` 调用时，那台机器只建工作分支、工作区和依赖，代码由本机的 Agent 用 `code_workspace` 在那个工作区里读写、运行你在仓库设置里允许的命令（检查、准备、“设备的外部 Agent 可以运行的命令”）、提交。写完 `finish`，那台机器运行检查、生成 diff，再交给本机 Agent 或那台机器的评审；最后由你在网页上应用。

反过来，需要那台机器自己的 Agent 去做的事（用它的模型、它那里的技能，比如在那台上操作浏览器），本机的 Agent 可以用 `run_agent` 交过去：立即返回一个运行 id，用 `read_run` 看结果。

### 借用设备的 Agent

本机没装某个 Agent，或者额度用完了，可以用另一台设备上的：在 **设置 → 设备** 里那台设备下面打开它的 Agent，它就出现在本机的 Agent 列表里，可以分给角色、档案和规则。Agent 在那台机器上运行，用它的登录和额度；检索、记忆和页面读写的始终是本机的库，本机的工具令牌不会发过去。它看不到本机的文件，所以适合问答、调查和写作，不要用来交办编码。两台机器（以及中间转发的那台）都要更新到支持这个功能的版本。

## 和别人的 omem 共享

设置 → 设备 → 和别人的 omem 共享：选几个空间，每个“只检索”或“可同步”，开放哪些内容（Wiki、记忆、文档……），生成配对码给对方。对方用自己的服务账号连进来，只能看到这些，你随时可以停止。对方关注你的空间后，检索和助手都查得到；“同步”的空间每半小时同步到对方一个只读空间，引用换成对方本机的副本，不会被再整理一遍。

```bash
omem peer share 项目A服务器 --space handbook:sync:wiki,memory,doc   # 你这边
omem peer add <配对码> && omem peer subscribe <你的设备名> handbook --sync   # 对方那边
```

## 多人

omem 默认只服务你自己。要给同事用，在 设置 → 成员 打开“多人登录”：

- 从别的机器打开网页会看到登录页，用飞书登录（omem 自己的机器人应用；先把设置页给出的回调地址加进开发者后台的“重定向 URL”）。运行 omem 的那台机器和你配对的设备仍然算你本人，不用登录。
- 第一次登录的人先等你批准；用邀请链接登录的人直接建好账号并加入选好的空间。
- 可以设主要登录方（如飞书）：之后只能用它登录，其他方式只在账号页绑定。
- 私聊机器人发 `/login`，收到 5 分钟内有效、只能用一次的登录链接。
- 可以按邮箱先建好账号、分好空间（成员页“按邮箱添加成员”）：之后谁用这个邮箱来——本企业的飞书账号登录，或从命令行带着鉴权插件认得的凭据——就直接对应到这个账号。
- 同事在自己的电脑上用 Claude Code、Codex：装轻量命令行 `npm i -g @omem-ai/cli`（不含服务端），`omem login <网页地址>` 在浏览器里确认后，`omem mcp --url <网页地址>` 以他的身份、在他能看的空间里用工具（不对外发消息、不交办编码）。也可以用 `OMEM_AUTH_CMD` 给一条输出组织登录凭据（如 JWT）的命令，由数据目录里的鉴权插件验证。令牌在账号页“命令行与 MCP”里撤销。
- 每个人的“账号”页列出登录方式和登录过的设备；你在成员页批准、停用、让某人所有设备退出、调整他的空间。

也可以在命令行登记：

```bash
omem user add 小王 --id wang --lark ou_xxx --space team   # 建用户、绑定飞书身份、可读 team 空间
omem user add 小周 --email zhou@example.com --space team  # 按邮箱预建账号
omem user token wang                                      # 发一个 API 令牌
omem space share project-a wang [--edit]                  # 再开放一个空间
omem user approve <id>                                    # 批准登录建好的账号
omem user invite --space team [--edit project-a]          # 邀请链接（只能用一次）
```

他私聊机器人时，会话进他自己的个人空间，只能检索自己和被共享的空间；事项和偏好各归各的。每个人有一个全局角色（管理员、成员、访客或自定义），在每个空间里有一个空间角色（只读、贡献者、编辑、管理或自定义），在 设置 → 成员 里改；管理员能改 Agent 和规则，系统设置、设备、交办编码只给你。自己建的空间自己管理，在账号页加人。

成员在账号页“已连接的应用”里连接自己的飞书，按功能一项项授权，也可以在登录页先勾好一起授权。飞书的授权只增不减，账号页每项功能有开关，关掉的 omem 就不用。连接后他的 Agent 以他自己的身份读写飞书，打开“我的消息”后后台采集他最近活跃的聊天到他的个人空间，打开日程、妙记、文档的还有他的日程、妙记和最近打开的文档；已经在共享空间里的群、文档和妙记不再存一份。同一个聊天在几个空间各有一份时，检索只显示一条，注明另有几处。用到的权限先在机器人应用的开发者后台开通，设置 → 渠道 的机器人检查会列出还缺哪些。没连接的成员用不了以个人身份读写飞书的工具，不会借用你的登录。

空间管理者可以把单份原件设为“受限”（只有记下的人和管理者能看），也可以在空间设置里让飞书文档按各人的飞书权限显示：成员连接飞书后，飞书说他能看的才显示全文，结果记一天。这两类原件不会进分享链接，也不会发给别的服务；共享空间的 Wiki 不能引用受限原件。同一台机器、同一个数据目录，不做多租户隔离。
