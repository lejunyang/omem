# 多台设备与多人

## 互相知道、互相请教

配对的 omem 每十分钟交换一次名片：那里有哪些助手（是谁的、做什么）、哪些 Agent 可以请教、共享了哪些空间。你的助手的说明里会多一段“网络里的其他 omem”，问题属于对方的领域时它用 `ask_agent` 去问，对象写「档案@节点」；你也可以直接说“问问 某台 的 某个 Agent”。被问的 Agent 在对方那台上运行、用对方的 AI，只读对方共享出来的空间，回答里的引用会取回你这台，点开就是原文。

你自己的几台设备之间什么都能看到、都能问。别人的服务默认只知道你共享了哪些空间：要让它请教你的 Agent，在 设置 → 设备 里它的共享下面选“可以请教的 Agent”，可以限每天几次；“让对方看到这台上有哪些助手”是另一个开关。别人的服务问你的助理时，它只读共享的空间，不带你的偏好和记忆。

## 借对方的 AI

自己的额度不够时，可以把另一台 omem 的 AI 当成本机的一个后端：模型在对方那台上跑，工具和资料都在你这台，所以查的还是你自己的空间。你自己的设备之间本来就可以这样用（设置 → 设备 里勾选那台的 Agent）。别人的服务要先由对方在给你的共享下面选“可以借用的 AI”并定每天几次；之后你这边同样在设备的 Agent 列表里勾选，再到 设置 → 后端与模型 → 排队与兜底 里决定它排在换后端顺序的哪一位。

借来的 AI 会看到经过它的提示和工具调用内容。不想让某个空间的内容出这台机器，在空间设置里勾“仅本机”：这个空间不能共享，在它里面的运行也不会用别人借出的 AI。

## 把课题的试验交给另一台跑

课题的执行环境可以选“派给设备”（设置 → 推进工作 → 课题的试验在哪跑）。选了这个环境的试验交给你自己的另一台设备：它按仓库的远端地址找到自己的那份仓库，在自己的工作区里切到方向确认时的提交，用自己的模型和技能跑完，把结果和证据文件送回发起的这台。只接受你自己设备派来的试验，别人的服务派不了；那台只做“跑这一个试验”，不接别的命令。用法见 [事项与流程](./items.md) 里的课题。

## 接任务板派来的活

已配对的设备可以派来一块任务。默认 `borrow` 只借本机后端，资料与工具留在发起设备；`remote` 在本机用自己的目录、库和登录。remote 默认拒绝，在 设置 → 设备 →“接别的设备派来的活”里选三档之一：不接；只接只读（对方的任务在这台用这台的资料和登录做调查，不改任何东西）；也接要写的（还能写任务所在空间的记忆、Wiki 页和事项，不改代码、不发消息）。同一张卡下面列出持有本机配对令牌的设备，每台可以单独设成不接、只读、可写，或跟随上面的档位；改上面的档位不会动单独设过的。配置项是 `node.acceptWork` 和 `node.acceptWorkFrom`。当前只接受配对映射为本人的设备，不采信任务里自报的身份。

<Shot src="settings-devices-work" caption="这台只接只读的活，lab-mac 单独设成不接" />

发起的一方在运行页和工作页的进度里看得到每块任务在哪跑：本机的不写，借了别的设备后端的写“借 ×× 的后端”，在对方跑的写“在 ×× 跑”；展开历次尝试能看到期限和对方运行页的链接（能直连时；任务板的时间轴里还写只读或可写），过了期限才回来的结果标“过了期限才回来，没采用”。

接活设备上的飞书读取跟随任务空间。把文档或群记录迁出该空间后，后续派来的任务就读不到它。整群历史分属不同空间时，可以指定任务空间内已归档的消息 ID。

收到的任务出现在本机运行页，标题注明来自哪台。对方通过轮询收结果、证据和用量。单个文件最多 2 MB、合计 8 MB；大文本带回开头，其他大文件留在本机并给出运行地址。对方原件引用注明在哪台查看。到期或取消后收尾，重发同一次尝试不会另开运行。

接活三档和按来源覆盖的网页控件尚未接入，现可通过配置设置。经中间节点或反向连接看远端运行时，使用 `omem peer open <设备>` 打开对方网页。

## 自动备份

想在自己的电脑上留一份常驻那台的完整数据：

```bash
omem peer backup <设备> --to <目录>
```

想固定在每天某个时间拉，加 `--at 00:00`（到点连不上，之后连上了再补）；`--every <小时>` 是按间隔。

之后本机的 omem 服务每 20 分钟看一眼：到期了（默认每 12 小时一次，或过了 `--at` 的时间而当天还没成功）、那台设备连得上（直连或经另一台设备转发），就把它的数据库、知识库、附件和代码仓库拉进这个目录并合并；连不上就下次再看，所以白天断开、晚上回到能连上的网络后会自己补上。三天没成功会提醒一次。状态用 `omem peer backup` 或 设置 → 设备 → 自动备份 看。

备份目录是一份普通的数据目录，可以单独打开来看，不启动定时任务和采集：

```bash
omem --home <目录> serve --no-background --port 4400
```

自动备份需要本机的 omem 服务在运行（`omem service start`，开机自启用 `omem service enable`）。第一次拉取是完整的；之后每次只带上次成功以后变过的原件和运行事件，检索索引和向量不传、在本机重建。只想在本机日常使用对方的某个空间，用下面的“关注并同步”。

## 一个空间只有一个主

在自己的另一台设备上关注并同步了一个空间（设置 → 设备 → 关注别人共享的空间，勾“同步到本机”），这台上就有它的一个只读镜像，离线也能查。在镜像里让助手记一条记忆、存一篇笔记或改一页 Wiki 时，这次写入不落在这台，而是写到主那台上，再同步回来——两台不会各有一个版本。主那台连不上时，写入先放进发件箱，下次同步时自动补发；主不接受的（比如没通过检查）会告诉你原因，不会反复重试。发件箱在 设置 → 设备 里。

名片列表在 设置 → 设备 最上面的“网络里的 omem”。设计和还没做的部分（事项的同步、换主、采集的接管）见仓库的 docs/v2/mesh.md。

## 多台设备

常见用法是一台机器常驻运行（采集、定时任务），其他机器拉它的数据、看它的状态、让它执行检查。机器之间不必能直接访问，可以经中间那台转发。

```bash
# 常驻那台
omem peer invite --label laptop       # 打印一行配对码，含本机所有网卡地址

# 另一台
omem peer add <配对码>                # 直接能访问到
omem peer add <配对码> --via <中间那台> # 只能经中间那台访问
omem peer back <设备> on              # 反向连接：它连不到本机时，本机一直连着它，它也能调用本机
omem diag <设备>                      # 版本、数量、最近失败、采集状态、Agent
omem peer commands <设备>             # 可远程执行的命令
omem peer call <设备> update          # 拉代码、装依赖、构建、重启
omem peer pull <设备>                 # 拉一份快照合并进本机（逐项选拉哪些、拉进哪个目录）
omem peer open <设备>                 # 在本机浏览器打开它的网页
omem tool --peer <设备> search query=退款  # 用本机的 Agent 整理它的库（见下）
```

`peer pull` 的数据库（原件、记忆、事项、会话、运行记录……）总会拉；另外四项可选：知识库（Wiki、Agent 档案、技能）、附件与图片、代码仓库、编码工作区与运行产物。在终端里运行时逐项勾选，并问拉进哪个数据目录（默认当前的，`--to` 指定别的，不存在会新建）；脚本里用 `--only library,files`（给空字符串只拉数据库）和 `-y`。合并是增量的：已有的记录按时间取新，附件只传本机没有的，搜索索引不传、在本机按拉来的原件重建；数据库和仓库每次仍是整份传。对方版本较旧时会发来全部内容，本机只合并选中的部分。

网页里 **设置 → 设备** 能做同样的事：生成配对码、粘贴添加、检查在线、改地址、移除，并列出拿着本机令牌的设备，可以逐个撤销。设备之间是 HTTP 直连，令牌有本人的全部权限，只在自己的局域网或 VPN 里配对。

`diag` 的 `eventLoop` 一节说明主线程有没有被卡住：事件循环延迟（p50 / p99 / 最大）、最近几次超过 500 ms 的卡顿（卡了多久、当时在做的同步步骤，如某条 SQL、某个 git 命令，以及刚开始的请求或工具）和最慢的同步步骤。卡顿同时记一行日志 `[omem] 事件循环卡了 … ms：…`，用 `omem peer call <设备> logs '{"stream":"err"}'` 能看到。

远程命令是固定的一组（诊断、日志、配置、只读查询、手动采集与回溯、运行记录、只读 SQL、查看 AI 后端 / 检索 / 运行说明 / 网页版 VS Code、git 与更新、重启），没有任意 shell。配对码里的令牌可以随时撤销。

### 用本机的模型整理它的库

常驻服务器上的知识库想让本机的 Claude Code、Codex 来整理（用本机的模型，而不是服务器自己的），不用登录服务器，直接把工具指到设备上：

```bash
omem tool --peer <设备>                          # 列出能用的工具
omem tool --peer <设备> search query=退款 space=project-a
omem tool --peer <设备> --session 整理项目A remember '{"kind":"fact","content":"…"}'
omem mcp --peer <设备>                           # 或配成 MCP 服务给 Agent 用
```

工具和 `omem mcp` 是同一套，但去掉了会对外发消息或动手的：飞书发送、通知、交办编码、让对方机器的 Agent 或模型干活、唤醒，以及改档案、技能和规则。读取、检索、记忆、Wiki 页面、原件关注度与标注、事项这些整理类的读写都可以。每次调用都记在对方的一条“设备的外部 Agent”运行里（一个会话一条，`--session` 区分），运行页能看到做了什么，写入的记忆来源档案是 `peer:<本机名>`。本机不用开 omem 服务；经中间机器连接时，中间机器不用更新。`--space` 选默认空间，`--spaces a,b` 限定可读写的空间，`--read-only` 只读。

也可以让本机的 Agent 评审它上面的分支：`review_branch` 经 `--peer` 调用时，那台机器只负责检出分支、取改动、建索引，评审项留给本机的 Agent。它用 `review_task` 取材料，逐项 `submit_review` 提交，交齐后那台机器汇总结论、通知你，评审页上每项显示 `peer:<本机名>` 和模型。整个过程不用那台机器的模型。

写代码也一样：`delegate_code` 经 `--peer` 调用时，那台机器只建工作分支、工作区和依赖，代码由本机的 Agent 用 `code_workspace` 在那个工作区里读写、运行你在仓库设置里允许的命令（检查、准备、“设备的外部 Agent 可以运行的命令”）、提交。写完 `finish`，那台机器运行检查、生成 diff，再交给本机 Agent 或那台机器的评审；最后由你在网页上应用。

反过来，需要那台机器自己的 Agent 去做的事（用它的模型、它那里的技能，比如在那台上操作浏览器），本机的 Agent 可以用 `run_agent` 交过去：立即返回一个运行 id，用 `read_run` 看结果。

### 反向连接：连不到本机的设备也能用本机

配对是单向的：本机能连到常驻那台，常驻那台却常常连不到本机（本机在家里或公司的 NAT 后面，或那台只能经别的设备转发到）。这时在 **设置 → 设备** 里给那台打开“让它反过来连本机”，或运行 `omem peer back <设备> on`。本机会一直连着它，断了自动重连；它要调用本机时，经这条连接请本机再连进来一条。

打开后，那台的设备列表里会出现本机：可以对本机 `peer call`、请教本机的 Agent，也可以借本机的 Agent 用本机的登录和额度（见下一节，在那台的设备页里打开）。本机给它一个本人权限的令牌，关掉时撤销，它那边的记录也跟着去掉。经这条连接进来的请求一律按令牌认人，不会被当成本机的请求。

### 借用设备的 Agent

本机没装某个 Agent，或者额度用完了，可以用另一台设备上的：在 **设置 → 设备** 里那台设备下面打开它的 Agent，它就出现在本机的 Agent 列表里，可以分给角色、档案和规则。Agent 在那台机器上运行，用它的登录和额度；检索、记忆和页面读写的始终是本机的库，本机的工具令牌不会发过去。它看不到本机的文件，所以适合问答、调查和写作，不要用来交办编码。两台机器（以及中间转发的那台）都要更新到支持这个功能的版本。

## 和别人的 omem 共享

设置 → 设备 → 和别人的 omem 共享：选几个空间，每个“只检索”或“可同步”，开放哪些内容（Wiki、记忆、文档……），生成配对码给对方。对方用自己的服务账号连进来，只能看到这些，你随时可以停止。对方关注你的空间后，检索和助手都查得到；“同步”的空间每半小时同步到对方一个只读空间，引用换成对方本机的副本，不会被再整理一遍。

```bash
omem peer share 项目A服务器 --space handbook:sync:wiki,memory,doc   # 你这边
omem peer add <配对码> && omem peer subscribe <你的设备名> handbook --sync   # 对方那边
```

## 多人

omem 默认只服务你自己。要给同事用，在 设置 → 成员 打开“多人登录”：

- 从别的机器打开网页会看到登录页，用飞书登录（omem 自己的机器人应用；先把设置页给出的回调地址加进开发者后台的“重定向 URL”）。运行 omem 的那台机器和你配对的设备仍然算你本人，不用登录。
- 第一次登录的人先等你批准；用邀请链接登录的人直接建好账号并加入选好的空间。
- 可以设主要登录方（如飞书）：之后只能用它登录，其他方式只在账号页绑定。
- 私聊机器人发 `/login`，收到 5 分钟内有效、只能用一次的登录链接。
- 可以按邮箱先建好账号、分好空间（成员页“按邮箱添加成员”）：之后谁用这个邮箱来——本企业的飞书账号登录，或从命令行带着鉴权插件认得的凭据——就直接对应到这个账号。他第一次在飞书上找机器人时也会认出他、对应到这个账号，不用等他登录。
- 同事在自己的电脑上用 Claude Code、Codex：装轻量命令行 `npm i -g @omem-ai/cli`（不含服务端），`omem login <网页地址>` 在浏览器里确认后，`omem mcp --url <网页地址>` 以他的身份、在他能看的空间里用工具（不对外发消息、不交办编码）。也可以用 `OMEM_AUTH_CMD` 给一条输出组织登录凭据（如 JWT）的命令，由数据目录里的鉴权插件验证。令牌在账号页“命令行与 MCP”里撤销。
- 每个人的“账号”页列出登录方式和登录过的设备；你在成员页批准、停用、让某人所有设备退出、调整他的空间。

也可以在命令行登记：

```bash
omem user add 小王 --id wang --lark ou_xxx --space team   # 建用户、绑定飞书身份、可读 team 空间
omem user add 小周 --email zhou@example.com --space team  # 按邮箱预建账号
omem user token wang                                      # 发一个 API 令牌
omem space share project-a wang [--edit]                  # 再开放一个空间
omem user approve <id>                                    # 批准登录建好的账号
omem user invite --space team [--edit project-a]          # 邀请链接（只能用一次）
```

他私聊机器人时，会话进他自己的个人空间，只能检索自己和被共享的空间；事项和偏好各归各的。每个人有一个全局角色（管理员、成员、访客或自定义），在每个空间里有一个空间角色（只读、贡献者、编辑、管理或自定义），在 设置 → 成员 里改；管理员能改 Agent 和规则，系统设置、设备、交办编码只给你。自己建的空间自己管理，在账号页加人。

### 每个人能做什么

成员那一行点“能做什么”，右边打开他的能力表：顶上是预设（访客、成员、网页只读观察者、管理员……，就是全局角色），下面按“工作与事项、资料与知识、规则与流程、运行与编码、对话与通知、成员管理”列出二十多项能力，每项写着他现在有没有、从哪来（预设带的、空间角色带的、单独给的、单独不给）。每项可以选“跟预设 / 允许 / 不给”；按空间的能力点“按空间”展开他能读的空间，逐个空间另设，有另设的在那一行标出几个空间。改完点底部“保存”，按钮旁写着这次改了什么；不给优先于允许。成员行上写着他的预设和“另设 N 项”，不打开也知道这人不是纯预设。

命令行和 MCP 使用成员自己的凭据，工具列表随有效能力和空间范围裁剪。

### 给成员看或改一部分设置

设置分知识、助手、AI、渠道与协作、成员、安全和系统七个区域，能力表的“设置”一组里每个区域有“查看”和“修改”两项。给了以后他的侧栏出现设置的齿轮，设置页只列他能看的分类；能看不能改的卡片照样显示，标题旁写“只读”，控件点不动。代你回复、凭据、命令和出网这类只有你能改的项，对他始终只读，写着“只有××能改”。他保存了不该改的项时，页面写明是哪一项、为什么没保存，不会改一半。后端与模型、渠道、采集、设备、插件这几类还要旧的“管理设置”权限才出现。

![小林只能看和改助手区域：代你回复里只有本人能改的那几项是只读的](/screens/settings-member.png)

成员详情里还有一行“例行整理”：替他打开或关上每晚整理他自己的线，旁边写现在能不能跑（没登录自己的 AI 账号、这台机器不能把他的运行隔开时写原因）。打开后用的是他自己的 AI 账号。

再下面一行“通知出口”，点开就是他账号页上的那张出口清单：内置的网页和飞书能不能送到他，插件加的出口开没开、最低紧急程度、哪些问题发过去。你和能管成员的人可以替他打开或关上出口、改紧急程度；审批类的提问只有你能为他打开，你在这里勾上“审批”就是为那个出口给了他授权，他自己的账号页上这一项随之能勾。成员页、设置页里写“只有××能改”的地方用的是你的名字（没有名字时写“主人”）。

“网页只读观察者”能看你的工作线、事项、原件、规则、运行、编码、评审和指标，能提问，不能改任何东西。网页按各人的能力只显示能用的入口：观察者的侧栏有工作、事项、原件、规则、运行这些，没有 Agent、抽检、学习；他的工作页只有你的工作线和已结束的线，没有等你处理的、提问框和新建；规则页是只读清单；打开事项和运行看不到改动的按钮。直接打开没有权限的页面会回到问答。

### 成员的工作页

有“看工作线”的成员打开“工作”，看到的是你放在他能读的空间里的工作线（现状、阶段、下一步、人和变化，和你看到的一样），加上他自己的线。一条线下面有他读不到的事项时，那件事不出现、不计数，整条线的现状也不给他，只写“这条线有一部分你看不到”。能改事项的成员可以把自己的事项建成线；你的线对他只读。右栏是他自己的“需要你处理”，顶上能展开他的“今天”。他的线默认不每天整理，要他在账号页打开并登录自己的 AI 账号，用的是他的账号。你也可以让助手“去问小林……到哪了”，他的回答会记成那条线的一条变化。见 [工作线](./work-lines#成员的工作页)。

成员在账号页“已连接的应用”里连接自己的飞书，按功能一项项授权，也可以在登录页先勾好一起授权。飞书的授权只增不减，账号页每项功能有开关，关掉的 omem 就不用。连接后他的 Agent 以他自己的身份读写飞书；还没授权的功能被用到时，助手把预先勾好的授权链接发给他，授权后那个会话自动接着做。群聊和单聊消息授权后默认不采集，只在他让助手看时读；在账号页“采集到 omem”里打开群聊或单聊后，后台采集他最近活跃的这类聊天到他的个人空间，打开日程、妙记、文档的还有他的日程、妙记和最近打开的文档；已经在共享空间里的群、文档和妙记不再存一份。同一个聊天在几个空间各有一份时，检索只显示一条，注明另有几处。用到的权限先在机器人应用的开发者后台开通，设置 → 渠道 → 飞书机器人 里的机器人检查会列出还缺哪些。没连接的成员用不了以个人身份读写飞书的工具，不会借用你的登录。

登录或连接飞书时勾选「文档与知识库」，会一起申请读取正文、搜索文档、浏览目录和下载文档素材的权限。旧连接缺文档搜索权限时，可在账号页重新打开这一项，供后台找出最近打开的文档。

「让助手写文档」包含新建、编辑、复制、移动文档，以及读取目标正文和定位知识库所需的权限。只勾这一项时，后台不会搜索最近打开的文档。

哪些文档存进 omem 由各人自己定：成员在账号页“采集到 omem”里开关“读过的文档”，下面可以打开“不读我的个人文档库”（成员默认打开），再贴链接排除单篇文档、知识库页面（连同子页面）、整个知识库或云空间文件夹；你自己的在 设置 → 采集 → 飞书文档 的“你最近打开的文档”里设。排除的文档不再被最近打开的采集、它们链过去的文档和（你的）聊天里的链接自动读进来，已经存进来的不删，让助手读的照常读。登录页勾了群聊消息、单聊消息或文档时，下面会多出“存进 omem”的勾选，授权回来时一并生效（文档默认勾上，聊天默认不勾）。

### 成员用自己的 AI 账号

成员的 Agent 运行默认借用你在这台机器上登录的 Codex、Claude Code 这些后端。Linux 上装了 bubblewrap 以后，成员可以用自己的账号：

- 安装：用系统的包管理器装 `bubblewrap`（`apt install bubblewrap` / `dnf install bubblewrap`），或在 omem 的目录里运行 `osdk pkg apply`（要 sudo；omem 升级时不会自动装）。系统要允许非特权用户命名空间。装好后重启 omem，`omem diag` 里的 `agentAccounts` 显示能不能用。macOS、Windows 和没有 bubblewrap 的 Linux 上没有本机账号沙箱。
- 成员在账号页“我的 AI 账号”里登录：Codex、TraeX 是设备码（页面上给出链接和验证码，机器人也会发到他的飞书私聊，写明是 omem 为他发起的登录），豆包命令行是二维码链接，Claude Code 点“登录”后在授权页最后拿到一段授权码，贴回页面即可（也可以粘贴他在自己电脑上用 `claude setup-token` 生成的令牌，只存在本机的密钥库里）。之后他发起的运行用他自己的账号，额度和使用记录算在他名下。
- 成员可以在编码沙箱里直接提交。每个仓库有本轮私有的 Git 目录；完成修改项时，宿主把提交快进接到分配的工作分支。宿主分支已被别人推进时，会保留双方提交并提示基点已变化。
- 他的套餐额度在他的沙箱里读，显示在他的页面上（可以点“重新读取”）；选后端时按他自己的额度避让，他的账号用完了只影响他自己的运行。可选的模型也按他的账号检测，`/model` 和助手列出的是他能用的。
- 公司要求用统一身份登录某个后端时，可以装一个提供登录方式的插件（`api.agentLogin`，见[插件](./plugins.md)）：成员在这个后端的下拉里选它登录，到期前自动续签，续不了时提醒他重新登录。
- 一次授权要同时供给几个后端和命令行时，用凭据插件（`api.credential`）：成员在账号页“凭据”里登录、选谁能借，它供给的后端在“我的 AI 账号”里标着来源，见[插件](./plugins.md)。
- 所有人的 Agent 都以运行 omem 的同一个系统用户运行，靠沙箱把各人的账号目录隔开：成员用自己的登录时在沙箱里运行，HOME 是他自己的账号目录，看不到你的登录、omem 的数据目录和别人的账号目录；omem 的工具照常能用，权限仍按他本人算。你开着“接管 Agent 自带的技能”时，omem 的说明和技能分组入口也写进他的账号目录。
- 你在 设置 → 成员 → 成员的 AI 账号 里按后端选：没登录的成员“借用本人的”（默认）、“换别的后端”（按这次运行的兜底顺序换一个他登录过、或允许借用的后端），或者“只能用自己的”（他的运行失败，提示去登录）。这里也能看到谁用什么方式登了哪些后端，让某人退出。停用一个成员时，他的登录、令牌和账号目录一并删除，并记进审计。
- 你在配置里自己加的后端（`agents.profiles`）也可以写 `account` 一段（和内置后端同样的字段），保存时会检查：`{home}` 只能写在 `env` 的值里，`env` 不能指向账号目录以外的绝对路径。

成员交办省略分支名时，主编码可以在本轮为临时分支命名。工作区和宿主分支会一起改名，已提交的改动保留原提交号。

设置 → 成员 → 成员的 AI 账号 最上面写着这台机器能不能把成员的运行和你的分开（不能时写原因），以及哪些后端上分不开（云端的、设备代跑的、用共享密钥的）。需要所有成员运行都隔离时，把下面“成员的运行不能隔离时”选成“不运行”（配置项 `agents.accountIsolation` 为 `require`）。借用本人的登录、云端服务和设备代跑都会被跳过；如果配置的后端都无法隔离，运行会停止并说明原因。默认值 `prefer` 沿用原来的账号选择，未隔离的原因记在运行详情里。本人自己的运行照常。

空间管理者可以把单份原件设为“受限”（只有记下的人和管理者能看），也可以在空间设置里让飞书文档按各人的飞书权限显示：成员连接飞书后，飞书说他能看的才显示全文，结果记一天。这两类原件不会进分享链接，也不会发给别的服务；共享空间的 Wiki 不能引用受限原件。同一台机器、同一个数据目录，不做多租户隔离。
