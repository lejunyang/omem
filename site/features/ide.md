# VS Code

交办的代码可以用你习惯的编辑器看：本机的 VS Code（或 Insiders、Cursor），经 Remote-SSH 连到常驻机器，或者直接在浏览器里开那台机器上的网页版 VS Code。评审问题、提问和修改点都能在编辑器里处理。

## 打开交办的工作区

编码运行的页头有“在 VS Code 中打开”：工作区还在时打开工作区，工作区归还了就打开检出这条分支的目录。

网页在 omem 所在的机器上时直接打开本地目录。从别的电脑看（局域网链接、`omem peer open`）时用 Remote-SSH：第一次点会让你填这台机器在你电脑上的 SSH 主机名（`~/.ssh/config` 里的 Host），记在你的浏览器里。旁边的齿轮可以换成 VS Code Insiders 或 Cursor。

齿轮里还能选“网页版 VS Code”：在新标签页里打开 omem 所在机器上的工作区，不用本地装 VS Code，也不用配 SSH。它用的是这台机器上官方的 `code serve-web`：所有项目共用服务端，已有完整版本就直接进入，新版本在后台下载、下次启动时换上；首次没有缓存时由 omem 下载，等待页显示下载进度（已下载多少、速度、大约还要多久），准备好后自动进入，失败时可以重新下载。由 omem 代理和鉴权，只对你开放；它带终端，等于这台机器的命令行。经 `omem peer open` 打开的网页也能用，包括经中间机器才能访问的设备。选它时齿轮里会显示用的是那台机器上哪个 VS Code 命令行；找不到就在那里填路径。

浏览器是中文时，界面用那台机器上装的中文语言包翻译；语言包比 VS Code 旧时，新加的几处显示英文，菜单不会错位。omem 自己的 VS Code 插件已经装在里面，直接连着这台 omem，不用设置。打开交办的工作区时直接按已信任打开，不会每次都问“是否信任此文件夹”；别的文件夹照常进受限模式（`ide.web.trustCodeFolders: false` 可关掉）。网页版第一次启动时，会拿那台机器上 Remote-SSH（或桌面 VS Code）的设置当初始值；那边装过的扩展默认不复制，设置 `ide.web.reuseExtensions: true` 后会把适合这台机器和这一版的各复制一份。快捷键、主题这些存在浏览器里，要和桌面一样，在网页版里登录账号打开“设置同步”。

## 预览：看改出来的页面

前端改动要看页面效果时，不用等推送，也不用登上那台机器起服务。在设置 → 空间 → 编辑仓库里填“预览命令”，一行一条“名字: 命令”，就是平时在仓库里起服务的命令，端口不用填：

```text
主站: pnpm --dir apps/main dev & pnpm --dir apps/sub dev & wait
H5: pnpm --dir wap/h5 dev
```

交办视图点“预览”，选一条启动。工作区还没装依赖（比如交办应用后单独建的目录）时，先运行仓库的准备命令，装好后自动接着启动。omem 在这次交办的工作区里运行预览命令，显示最近的输出；它和它启动的进程开始监听端口后，列出这些端口，能返回网页的标“网页”，点 `localhost:<端口>` 打开。

端口号和在那台机器上一样：网页和 omem 在同一台机器时直接打开；在别的电脑上用 `omem peer open <设备>` 打开 omem，它会在你电脑上的同样端口号上监听并转过去，HTTP 和热更新的 WebSocket 都按原样转。所以主应用加载子应用、资源地址写死 `localhost:3000` 这类多应用项目，也不用为预览另配什么。直接从别的电脑打开那台的网页时没法转发，页面会提示改用 `omem peer open`。

同一个仓库同时只开一个预览（项目的端口是固定的），开新的会先停掉旧的；端口上 30 分钟没有连接就停（`preview.idleMinutes`），交办的工作区收回、应用或丢弃后也停。和网页版 VS Code 一样只对你开放。

## 插件：在代码里处理评审

仓库的 `vscode/` 里有插件（`pnpm run package` 打出 .vsix 安装）。打开交办的工作区后：

- 评审问题挂在对应代码行上，线程标题上点“改 / 暂不改 / 不改”，“不改”写一句理由；侧栏“修改单”列出全部问题。
- 选中代码按 `Ctrl+Alt+A`（或右键“问 omem”），在这段代码上开一个线程：输入后点“提问”，回答写回线程；点“记为修改点”留给下一轮。
- “修改单”的“开始修改”把标了“改”的问题和修改点一起交给编码 Agent，状态栏显示轮次，点开看过程。
- 侧栏“交办”的 ＋ 选仓库后在临时文档里写任务，右键“引用到交办任务”可以把选中代码带进去，点文档顶部的“提交交办”。
- 按修改项推进的交办多一个“修改项”视图：等你决定的问题、每一项和它的验证意见、检查点。点一项用 VS Code 的多文件对比看它自己的改动，检查点可以看这一步或和现在比，标题栏“我上次看过之后的改动”和“和分支比较…”（整条分支和上线分支比，右边是工作区里的文件，能直接问 omem、记修改点）；看过的改动还按目录列在“改动的文件”视图里，文件多时从这里一个个点开看；右键回答、重做、不做、回退、回到某个检查点，标题栏加修改项、暂停 / 继续。工作区在另一台机器上也能看对比。
- 任何交办都能看改动：“修改单”标题栏的“看全部改动”列出从交办开始到工作区现在的全部改动，没提交的也算；“和分支比较…”看整条分支和上线分支的差别。让另一台设备的 Agent 编码、它还没交结果时，也是从这里看它已经改了什么。
- 交办有方案时多一个“方案”视图：每个决定一行，写着落在它下面的文件和增删行、有没有偏差、还有几条意见没解决。点一个决定只看它自己的改动，展开后点文件只看这个文件；没挂在任何决定上的改动列在“方案之外的改动”。确认方案和回答问题仍在网页上做。

点状态栏左下的 omem（或命令“omem：连接 omem…”）选 omem 在哪里：这台机器上（含 Remote-SSH 连到的那台，一般什么都不用填）、另一台机器（粘贴 `omem link` 的链接或 `omem peer invite` 的配对码，或填地址和令牌）、本机 `omem peer add` 配好的设备（从列表里选，本机 omem 服务不用开）。连别的机器时，要从评审跳到代码还得填那台机器的 SSH 主机名。
