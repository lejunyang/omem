# VS Code 与实时预览

交办的代码跑在常驻机器上，但你随时可以用最顺手的方式看代码、改代码、试页面：**既可以用本机桌面 VS Code（或 Cursor、Insiders）经 Remote-SSH 打开，也可以免装任何软件直接在浏览器里打开内置的网页版 VS Code；想看前端改动效果时，点一下“预览”就能把远端端口按原端口号转到你自己的电脑上。**

## 1. 三种方式一键打开交办工作区

在任何编码交办页面顶部，点**“在 VS Code 中打开”**（及旁边的齿轮按钮）：

| 打开方式 | 适合什么场景 | 开箱即用的便利设计 |
| --- | --- | --- |
| **1. 网页版 VS Code**（齿轮里选择，最省事） | 电脑上没装 VS Code、没配 SSH，或临时用别的机器看代码 | • **浏览器新标签页即开**：基于官方 `code serve-web`，由 omem 统一代理鉴权（仅对你本人开放，带完整服务器终端），支持内网 HTTP IP 直连与 `omem peer open` 中继访问<br/>• **免配置、免点信任**：**内置已自动装好并连上当前服务的 omem VS Code 插件**；自动复用机器上桌面/Remote-SSH 的设置与中文语言包，交办目录默认按“已信任”直接打开 |
| **2. 本机桌面编辑器** | omem 就跑在你当前这台电脑上 | 直接调起本机的 VS Code（齿轮里可切换为 **VS Code Insiders** 或 **Cursor**）打开该交办的 worktree 目录 |
| **3. Remote-SSH 远程打开** | omem 跑在常驻服务器上，你在自己的笔记本上用桌面编辑器 | 首次点击填入服务器在你 `~/.ssh/config` 里的 SSH 主机名（保存在浏览器本地），此后一键通过 Remote-SSH 打开远端工作区 |

## 2. omem VS Code 插件：在代码行上直接处理评审与修改项

无论你用网页版还是桌面版（桌面版可在仓库 `vscode/` 下打包 `.vsix` 安装，支持自动连接本机、远程链接或已配对的 `peer` 设备），打开交办工作区后，**评审意见和修改项都直接挂在代码里**：

- **代码行内直接批复评审问题**：所有评审问题作为评论线程（Comment Thread）直接挂在对应的代码行上。看完上下文，直接在线程标题上点**“改 / 暂不改 / 不改”**（选“不改”填一句理由），左侧“修改单”面板实时同步。
- **选中代码就地提问或记修改点（<kbd>Ctrl+Alt+A</kbd>）**：在编辑器里划选一段代码按 <kbd>Ctrl+Alt+A</kbd>（或右键“问 omem”），即可在这段代码上开一个对话线程提问，或点**“记为修改点”**攒到下一轮；全部看完后，在侧栏点**“开始修改”**一键把选定的评审问题和修改点交给编码 Agent 续跑下一轮。
- **按“修改项”或按“技术方案决定”隔离看 Diff**：
  - **修改项视图**：列出待你决定的问题、每个修改项（`T1`、`T2`…）的验证结论和检查点。**点任意一项，直接用 VS Code 原生多文件对比只看这一项改了什么**；也可一键查看“我上次看过之后的增量改动”或“整条分支与上线分支对比”（哪怕另一台设备上的 Agent 还在写代码没交结果，也能实时看它已经改了什么），并支持右键单步重做、回退或恢复到某个检查点。
  - **方案视图**：有技术方案的交办会多出一个“方案”面板，按方案里的每个“决定”分组——**点一个决定，只看落在它下面的文件改动与偏差**，未归入任何决定的文件单列在“方案之外的改动”里。
- **从编辑器直接发起新交办**：在侧栏“交办”点 `＋`，在弹出的临时 Markdown 文档里写任务（可右键把当前选中的代码段直接引用进去），点顶部“提交交办”即可开跑。

## 3. 一键预览：看交办改出来的页面，原端口号自动转发到本机

前端或全栈交办改完页面后，不用等代码合并推送，也不用自己登到服务器上敲命令起服务：

1. **在仓库空间填好预览命令**：在 **设置 → 空间 → 编辑仓库** 的“预览命令”里填平时启动开发服务的命令（一行一条 `名字: 命令`，无需填端口号）：
   ```text
   主站: pnpm --dir apps/main dev & pnpm --dir apps/sub dev & wait
   H5: pnpm --dir wap/h5 dev
   ```
2. **在交办页点“预览”一键启动**：omem 会在这次交办的工作区里先确保依赖就绪，然后启动该命令并实时显示控制台输出，**自动识别出它和子进程监听的所有端口**，能返回网页的直接标出 `localhost:<端口>` 链接。
3. **跨机器原端口号透明转发（解决写死 `localhost` 的痛点）**：
   - 如果你在自己的笔记本上通过 `omem peer open <常驻设备>` 查看常驻机器上的 omem，点击预览时，**`omem peer open` 会在你笔记本本地自动监听一模一样的端口号，并把 HTTP 请求和 Vite/Webpack 热更新（HMR）的 WebSocket 原样转发过去**。
   - 这意味着哪怕你的项目是微前端主应用加载子应用、或者在开发配置里写死了 `http://localhost:3000` 跨域白名单，在你的笔记本浏览器里点开 `localhost:3000` 就能完美预览，无需改一行配置！（端口连续 30 分钟无连接或工作区归还后自动停止服务）。
