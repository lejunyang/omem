# 问答：带依据的回答

在飞书里直接问机器人，或者在网页的**“工作”页右栏**、**“问答”页**及全局快捷键 <kbd>Ctrl K</kbd> 里提问和交代事情。**omem 的回答有两个硬标准：每一句事实结论都必须贴着原文行号出处；文字说不清的时候，直接给你画图表、发表单或生成可点击的沙箱交互页。**

<Shot src="ask-citations" caption="带依据的回答：引用紧贴在论断旁边，点击直接在右侧抽屉打开原件并高亮对应行" />

## 1. 为什么它的回答敢直接拿去用？

- **文档、群聊、代码同库交叉印证**：问“退款金额现在怎么算？”，助理在同一次检索里同时查出最初需求文档里的规则、群里后来改口的讨论和代码分支里的真实实现，把三处出处一并引上，并明确告诉你哪份文档已经过时。
- **引用贴着论断，支持逐层下钻**：点击回答里的引用标签，右侧抽屉立刻打开原件并高亮那几行原话；如果回答引用了一页 Wiki 或一条记忆，在抽屉里还能继续点开那页 Wiki 背后引用的代码行和群聊记录。
- **相关记忆自动挂载**：开启向量检索（及重排）后，每次收到新消息，和当前问题高度相关的记忆、偏好与经验（最多 5 条）会自动附入上下文，不用等助理先想起来去搜；曾经被纠正过的约定，连同版本演变链一起呈现。
- **拦截“正确的废话”**：如果 Agent 生成的回复只有“收到，我看看”“可能是……建议进一步确认”而没有任何实质结论或具体缺失项，宿主在发出前会**自动拦下并退回给 Agent 重写一次**，确保发到你面前的是有依据的结论。
- **回答时顺手记事项与记忆**：你在对话里随口说的计划、承诺、在等谁回复，不用专门加一句“记住”，助理回答完会顺手记成记忆或事项，并在那一轮底部清晰列出本次新建或更新了哪些条目，点开即可查看或撤回。

## 2. 不止于文字：表单、图表与可点击的交互小页面

当一问一答的纯文字效率太低时，助理会直接调用结构化组件与你交互（网页与飞书卡片同步支持）：

### 一张表单一次问完（不再来回追问五六轮）

需要你一次拍板好几件事时，助理直接在回复下方附上一张组合表单：支持**单选/多选、文本框、数字、1–5 打分、日期选择、开关、并排方案卡片挑一个、一批条目逐条“通过/不通过”加备注、拖拽排先后**。提交后数据直接回到同一轮会话接着执行；不想填表也可以直接回一句话。

<Shot src="ask-form" caption="内嵌表单：上线方案在并排卡片里挑，日期用日历选，退款规则逐条通过或驳回" />

### 把查到的数据直接画成图

涉及数据趋势、新旧对比或进度汇总时，回复下方直接渲染**一句话结论块（带达成/关注/故障图标）、带涨跌箭头与小走势的指标卡、梯级柱状图/条形图/折线图/面积图/刻度表盘，以及可按列排序的表格**。所有数字均来自库内真实记录或查询工具，悬停可看明细，点“看数据”可展开为表格（飞书里自动渲染为原生图表卡片）。

<Shot src="ask-view" caption="数据可视化回答：过去两周退款指标、每日趋势图与两种上线方式的对比表" />

### 可点击的沙箱交互页（先试过再做决定）

遇到界面改版、交互状态切换或几种设计方案难以靠文字想象时，助理会写一个**可点击的迷你网页**直接嵌在问题里：几种方案并排切换、开关可拨、状态可试。你在页面里试完直接点“选 A”或“选 B”，选择立刻交回给 Agent；每次修改保留历史版本可回翻对比（页面在无网隔离沙箱中运行，读不到你的登录态与私有数据）。

<Shot src="ask-page" caption="可点击的交互页：在沙箱页面里切换退款进度页的不同状态看效果，直接点选方案 A 或 B" />

## 3. 多模态输入、语音对话与跨人询问

- **粘贴或拖入截图与文件**：在网页输入框直接粘贴截图或拖入文件，上方会出现缩略图，正文中生成 `[图片1]`、`[文件1]` 引用标记（点击缩略图可在光标处再次插入引用）；Agent 直接读取原图与文件进行分析。
- **语音输入与实时全双工语音对话**：在 **设置 → 后端与模型 → 语音** 配好语音模型后，输入框旁会出现两个按钮：
  - **麦克风**：说完自动转成文字填入输入框，可修改后再发。
  - **波形按钮（实时语音对话）**：像打电话一样和助理实时语音交流，助理可以边聊边只读查询你的原件、记忆、事项和 Wiki，并口头报出所依据的文档名，对话结束后完整记录自动保存。
- **替你去问同事**：对助理说“去问一下小李周四能不能参加评审”，助理会把问题单独发给小李（飞书私聊卡片或站内通知，注明是你的助手在问），小李点选或回复后，结果自动带回你的会话。

## 4. 跟进长任务（`/跟进`）与回答效果回扫

### 跟进一件长任务

大型编码交办（默认拆出 ≥6 个修改项或预计 ≥3 轮）、持续探索的“研究”流程以及多 Agent 协作任务，会自动开启**长任务跟进**；你也可以对任何复杂目标发送命令手动开启：

```text
/跟进 把项目 A 的迁移验证做完，发布前问我
/跟进 codex astra xhigh 把迁移验证做完
```

开启后，系统在独立工作话题中生成一份**任务书**（包含原始目标、完成条件、范围边界、必须问你的事，你可随时直接编辑修改），由指定的监督 AI（`longTasks.supervisor` 或 `/强` 组）持续协调各轮推进：

| 想做的操作 | 在工作话题内发送 |
| --- | --- |
| 查看当前状态、剩余预算与近期进展 | `/跟进` |
| 暂停或继续自动推进 | `/跟进 暂停` 或 `/跟进 继续` |
| 增加运行时间预算 | `/跟进 加 3 小时` |
| 更换负责跟进的 AI 模型 | `/跟进 换 claude opus high` |
| 退出跟进（保留已有成果，回到普通对话） | `/跟进 结束`（或在原会话说“不用跟进”） |

- **方案要你确认**：交办写好的方案，跟进不能替你确认。等着的方案会列在进度卡的“等你确认的方案”里。
- **研究里补的试验**：跟进为研究补跑的试验也记进研究记录，由小结归并成发现，不用你去重开小结。

### 自动追踪每次回答到底有没有帮上忙

你不需要每次都点表情反馈，omem 默认在后台评估每次回答的真实效果：
1. **几小时后初判**：小模型根据同一会话或群里大家随后的发言，先标一个临时状态。
2. **满一天后深度回扫（`outcome-reviewer`）**：通读整段后续对话，按目标把问答拆成一件件事，判定每次回答是**解决了、接着往下推进、需要补充（写明缺什么）、被纠正，还是被别人接手了**，并自动归类工作场景。
3. **有据可查**：在运行页的“回复发出后”可查看判定依据（判错了可手动改），在 [数据 → omem 自己](./insights) 中按回扫结果统计真实解决率。

## 补充说明：常用斜杠命令与 ID 精准定位

- **高频斜杠命令**：`/new [任务]`（开新会话）、`/topic [AI] <任务>`（飞书开独立话题）、`/as <档案> <任务>`（交给专门 Agent）、`/codex astra xhigh` 或 `/强`（切换本会话或当轮 AI，加 `save` 保存默认）、`/review`（复习 FSRS 记忆卡）、`/help all`（查看完整命令清单）。
- **复制 ID 秒开记录**：在全局搜索 <kbd>Ctrl K</kbd> 或运行页搜索框里，直接粘贴任何运行 ID（`r…`，兼容飞书回答底部的整行文字）、原件 ID（`src:…`）、记忆 ID（`mem:…`）或事项 ID，都会**第一优先级置顶显示精确命中**，随后再流式追加正文匹配的搜索结果。
