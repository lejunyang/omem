# 机器人与卡片

在飞书里私聊机器人，或在群里 @ 它，就是在和 omem 的主助手说话。网页上能做的事，大多在这里也能做。

## 回答的过程看得见

- 收到消息先在上面加一个“处理中”表情。
- 思考和步骤显示在飞书原生的思考气泡里；不能用气泡的地方发一张进度卡片，实时显示步骤和正在写的答案，完成后原地变成答案。气泡和回答在一处：你在话题里回复，气泡就在话题里；后台接着做的一轮（比如编码交办结束后助理看结果）回复的那条消息已经被进度卡片开成话题时，气泡也发进那个话题。
- 多 Agent 的长任务开一个话题，每个 Agent 的过程按顺序出现在话题里（见 [多 Agent 协作](./collaboration)）。
- 一件事后来自己发出的消息（唤醒复查的结果、交办结束的汇报、多 Agent 的协调回复）跟着这件事走：在哪个话题发起就回到哪个话题；你换个地方接着聊它——在别的话题或私聊里回复它的消息，或让助理在那里继续、调整它的运行——之后的消息就发到新地方。在私聊或群里直接发时，只引用这件事自己的上一条消息，没有就不引用，不会引用不相干的消息。原来的话题被删或机器人被移出群时，改发到你的私聊，开头写明是哪件事的后续。
- 回答底部显示 `id r… · codex · gpt-6.1-sol · low`，对应这次运行记录中的后端、模型和思考强度；未指定模型或强度时显示“默认模型”或“默认强度”。复制整行到网页的 <kbd>Ctrl K</kbd> 直接打开那次运行的完整记录。

## 卡片

需要你看一眼、选一下的东西都做成卡片，点按钮就是回答，结果回到原来的会话继续处理：

| 卡片 | 什么时候出现 |
| --- | --- |
| 提问 | 助理遇到非你决定不可的事（比如两种方案选哪个、这次要不要推送）。选项都短时排成按钮，按手机宽度均匀分行；有一个长选项时，所有选项按编号逐行显示完整文字，旁边点“选择”。输入框后点“用文字回答”，问题里列了几条要逐条答时输入框可以写多行；也可以直接在对话里回一句、回个编号；它在**同一轮**接着做，不用等它结束再重说一遍。要问好几项时卡片里就是一张表单（输入框、下拉、日期、勾选），漏填必填项会提示、卡片不关；排序、按列填表这类卡片填不了的，给“打开填写”链接。没答的问题在网页“今天”页的“等你回答”里 |
| 数据和图表 | 助理把表格、图表放在回答下面时，回复之后跟一张卡片：表格可以翻页，图表是飞书自己的图表，带“在网页上查看” |
| 交互页 | 助理写了可以点的页面让你选时，卡片里是问题和“打开交互页”按钮 |
| 替别人问 | 别人的助理替 ta 问你时，卡片发在你和机器人的私聊里，写明是谁的助手在问，回答交给 ta |
| 下一步 | 回答以建议结尾时附上几个按钮，点一下就等于你说了那句话 |
| 草稿确认 | 盯群设成草稿模式时，要发到群里的回复先变成给你的卡片，点“发送”才发出 |
| 文档编辑审批 | 修改共享文档前，列出本次要编辑的文档和简短改动摘要；一次批准后，这些文档的分段写入和失败重试不再逐次问，换轮或换会话也沿用已批准的编辑范围。换文档、整篇覆盖或移动位置时再批准 |
| 编码交办 | 一次交办一张，持续更新进度和每轮评审摘要；评审计划和“默认要改的问题”是表格，评审结束带着按钮决定改哪些 |
| 事项清点 | 每天一张，列出自动收尾的和明天过期的事项，要留下的点“保留”或“恢复” |
| 入会确认 | 会议规则命中时问你要不要把机器人拉进会 |
| 访客把关 | 配了决策模型（设置 → AI → 决策）时，先由它判断回答 / 拒绝 / 不理，快且便宜；没配或关掉时由“访客提问把关”角色判断 |
| 访客请求 | 同事的请求被把关拦下时，给你一张只有你能看见的卡片，点“同意这次”交给助理处理 |
| 模型配置 | 发 `/model` 弹出，换这个会话用的模型和思考强度 |

<Shot src="ask-question" caption="网页上的同一个提问：选一个按钮，或写一句自己的回答（飞书里是一张带同样按钮的卡片）" />

要某个人回答或批准的卡片发在群里时，开头 @ 那个人；在你和机器人的私聊里不 @。

**在飞书侧边栏里打开**：设置 → 渠道 打开“飞书网页应用”，页面会写出要在飞书开发者后台填的东西：给机器人的应用加“网页应用”能力，桌面端和移动端主页填 `<网页地址>/lark/`，H5 可信域名加上网页地址的域名，然后发版。之后卡片上的“打开填写”“打开交互页”“在网页上查看”在飞书桌面端的侧边栏打开（手机上全屏），直接用你的飞书身份登录，不用再输入什么。手机和电脑都要能访问这个网页地址。

Agent 自己也能发卡片：按钮、下拉、输入框、表单（每题一行粗体问题，几题自动编号），并限定只有某些人能操作，发在群里时开头 @ 这些人；别人点了按钮或提交了表单，作为新消息回到原来的会话。

## 在群里说话

- 回复或开话题回复、@ 人（按姓名或邮箱，重名时核对群成员）、加表情、发 Markdown、图片和文件。
- **@ 其他机器人**：助理可按名字从群的近期历史提及中核实身份，不用每次在同一条消息里同时 @ 它们。发送身份与个人采集身份分开，避免拿错 open_id。
- **加急**（应用内加急）和**只给部分人看**的卡片默认都不能用：只有你在对话里明确要求，或规则勾了“允许加急 / 允许只给部分人看”时才放行，对谁用、什么情况用照你的原话。
- 有人直接 @ 机器人，就是在找它：这条消息不再交给规则，由机器人直接回答，回答开头 @ 提问的人（同事按访客模式回答时也一样；你在私聊里问不 @）。

这些用法写在内置技能 `lark-messaging` 里，Agent 发消息前会读它。

## 表情就是反馈

给机器人的回答加个表情：👍、鼓掌算好，👎、捂脸算不好，OK、DONE、+1 只算“收到”（映射在 `feedback.emoji` 里可改）。Agent 页按档案和模型统计（默认只看你的，同事和访客分开）；每晚复盘和记忆整理会先看收到负面表情的回答。见 [学习与进步](./learning)。

## 回答里的引用

飞书打不开 omem 自己的引用，发出去前逐条换掉：

- 属于句子的引用（“按《差旅报销制度》第 3 条”）保留文字、链到原处；跟在句末的换成 (1) (2) 这样的编号链接（数字多了也一样大），段落不再以一串标题结尾。
- 飞书文档和网页链到原文；群聊里的那句话直接打开飞书会话并定位到那条消息。
- 代码、工作文件、记忆、Wiki 页面这类 omem 自己的东西，发送时复制成一个**只读分享**：打开不用登录，只能看到这条消息引用的那几处，里面再提到的东西点不开。

<Shot src="share-link" caption="只读分享：一条回答引用的排查记录和代码，被引的行标出来" />

分享链接放在“网页地址”（设置 → 设备）上，没填就不生成，这类引用直接省略。默认长期有效；设置 → 分享 改新分享的有效期，看每个分享来自哪次运行、被打开几次，随时撤销。只复制这次运行能读的空间：访客回答不会带出你的个人空间。

## 常用命令

斜杠命令不经过模型，直接执行：

- `/new 任务` 开新会话，`/topic 任务` 在飞书里开话题
- `/as 档案 任务` 交给某个 Agent 档案
- `/model [模型] [effort=…]` 本会话临时换模型或思考强度
- `/watch 档案 …` 让一个档案长期处理这个群（见 [群里的协作](./lark-groups)）
- `/help` 看全部

## 免打扰

免打扰时段的普通通知早上补发；你已经在飞书里读过、回过表情的通知不再推。

点击确认卡片或建议后，助手会继续处理并把回答发回原会话。即使提问那轮已经结束，也能在飞书收到后续回答。编码需要决定的卡片先显示问题，技术记录默认折叠。
