# 数据：omem 做了什么，有数可查

左侧导航的“数据”分两栏，两类数不混在一起：

- **工作数据**（默认）：你工作上的数，见下面的“工作上的指标”。
- **omem 自己**：omem 和机器人给你、给别人做过的事，以及每天存下的用量曲线。

下面先说“omem 自己”。默认看最近 30 天，可以选 7 天、90 天或最多 180 天的自定义日期，再按空间、触发人、场景、Agent 档案、模型、机器人和触发会话筛选。日期按设置中的时区；链接保留筛选，结果缓存约三分钟。

“做得怎么样”里的“回复发出后的结果”不靠表情：它按回答之后大家说的话统计解决了、接着往下（在结果上提了下一步）、要补充（原来要的没答全）、被纠正、别人接手了各多少，“回复有用的占比”把解决了和接着往下都算作有用。第一遍是小模型在回答发出几小时后标的，只是临时结论；发出满一天后还有一次回扫：outcome-reviewer 读那个会话的整段对话，把回答分成一件件事（一个人为一个目标连着问的几轮），重新判每次回答，记下缺的是什么、这件事属于哪类工作、查过哪些数。表里的数都按回扫后的结果算，“回扫同意第一遍的占比”告诉你第一遍有多可信。任务类型一开始是空的，回扫遇到没有合适类型的事就自己建一个，可以分两级（比如问题排查下面的报警排查）。你自己标的、按表情记的不改，你改过的谁都不再改。“谁触发的”筛选和拆分显示飞书上的姓名，同一个模型的不同写法算一个。

编码交付后是“流程”：每份流程定义一张按阶段的表，写这段时间里各段平均每件在做、等你、卡住多少小时，你要求返工几次；上面是走完的、中途停下的事项数和等你的时间合计。按人、模型等运行条件筛选时不统计流程。

再往后是“研究”：期间有已交结果的试验时，显示按研究的四种试验结果、新发现及本人的判定、其中有改动的和改后重跑通过或仍然失败的、结束方向和按模型的试验运行次数，数字可回到运行或事项，导出也包含。发现多少不代表做得好坏，不做排名或发现率；按模型等运行条件筛选时，省略不能归属的发现和方向。

时间段、和上一段比、筛选、导出在两栏切换的同一行右侧。下面先是四个最关键的数（做了多少件、成功率、用过的人、提醒或替你答了），再是一排可以粘在顶部的节：用量、提醒、回答、编码与流程、知识、运行时长、长期走势，点一个跳过去。每节里依次是：用了多少、用在哪、替你挡了多少、给别人带来什么、做得怎么样、编码交付、流程（有走流程的事项时）、研究（期间有试验时）、知识用上了没有、花了多少时间。每一块默认只放最要紧的一两张图、排行的前八行和几个数，其余点“展开这一节”；口径收在“怎么数的”里。每天任务按场景叠加，每周人数分本人、成员、访客与机器人。后台整理是系统维护知识的工作，定时巡检里没有新动静、安静结束的那些也算在这里；它们默认单列，不计入使用和成本合计；可以打开“包含后台整理”。成功率始终排除整理，只算已完成或失败的运行。

点任何一个数或一根条，右侧打开这个数的抽屉：大数字和上一段比变了多少，每天有几条记录，再按场景、Agent、空间、模型、谁触发、在哪个会话、结果拆开（只有一组的不拆）；点拆分里的一行就只看这一组，标成小胶囊，点胶囊去掉。最下面是记录清单，可搜索，每条写时间、谁触发、用了多久、结果，点标题回到运行或对应列表。链接带着这个数和抽屉里的筛选，可以直接发给别人；Esc 关闭，焦点回到点开它的那个数。不会显示访客的提问和答案正文。主人能看全部；成员只看自己触发或拥有、且有权阅读的运行。不会给人排效率名次。

## 工作上的指标

除了 omem 自己做了什么，助手也替你看工作上的数据：需求的埋点事件量、上线后的报错和使用量、迁移时新旧平台的对比。

- 每个指标写清它回答你的什么问题（“部分发货改造上线后，退款接口有没有更容易出错”）、在哪个系统、怎么查（读系统靠你数据目录里的技能），可以挂到事项或关注上，设成按小时、每天或每周自动取；变化超过门槛时告诉你，并写进事项时间线和关注的会话。
- 需求事项可以有一份观测计划（内置技能 `observation-plan`）：先写下你对这件事真会问的几个问题，再定上线前要埋的点、上线后看哪些报错和使用指标、改版或迁移的新旧对比和护栏指标；计划里的指标定义到事项上，每个都指回计划里的那一节。
- 助手可以盘点一份数据源目录（内置技能 `data-sources`）：哪个系统有哪类数据、对应哪些产品和服务、怎么查。
- omem 自己的用量也每天存一份（运行、时长、各 AI、回答被判成什么和谁判的、案例、新会话），原始记录过期以后历史还在；在“omem 自己”一栏的“长期走势”里看。一个用量一格（分好几类的数写合计），点开是每天的合计和按类型、结果、经由等各拆一张。

### 指标从哪来，由你定

你在对话里亲口让助手加的指标直接生效。助手在后台定的（写观测计划、看一条线的时候）只是**提议**：它们都在“工作数据”最上面的“等你确认”清单里，按工作线分组，一行一个指标：名字、从哪个系统取、多久取一次、它想回答什么问题、已经取到的最新值，行尾“保留 / 不要”。组名旁边可以“这一组都保留 / 都不要”，清单顶上有“全部保留”。定完的从清单里消失，留下的出现在下面。提议照样按时取数，等你决定时已经有真实的数；但它变化再大也不通知你、不写进时间线。

点一个提议的名字，在这一行下面展开它的图和定义，右上三个按钮：

- **保留**：从此按门槛告诉你变化。
- **改**：改名字、单位、它回答的问题、取数频率、门槛、哪个方向是好的、怎么画；提议可以“保存并保留”，也可以只保存先不定。
- **不要**：不再取数，也不在这里显示。可以写一句为什么（一组一起不要时也可以写一句，不写也行），助手以后提指标前会读到你最近留下了哪些、不要了哪些和理由，同一个指标不会再提。

升级到这一版时，以前助手定义的工作指标都没有经过你确认，所以都先变成提议；omem 自己的用量不受影响。

### 一个指标怎么画

点一个数，详情就在这一排下面展开，再点一次或按 Esc 收起，数字不会重新跳一遍。图怎么画由指标自己的“画法”决定，助手定义时给，你在“改”里也能换：

- 走势线、面积（看量）、每天一根柱、叠加的柱（看几类的合计）；
- 几组并排：分维度记的数（新 / 旧平台、PC / 手机）各画一条线，卡片上的大数是其中一组，其余写在下面；可以另画一张占比（“新的占比”）；
- 最近一次的构成：画成表盘；
- 只列数、只看最新的数：不画图。

只有一两天的数时不画几乎空白的线，直接写“只有 1 天的数：11-19 新 1,284 单 / 旧 2,906 单”；还没取过的写清楚从哪个系统、多久取一次、第一次大概什么时候。图在左边，右边依次是为什么看、说明、从哪来、怎么查（长的先收起）、基线和门槛、多久取一次、挂在哪件事上、来自哪份观测计划（点开是计划里那一段）、是谁定的；分维度记的指标，下面按每个维度各拆一张（30 天合计，比例取平均）。分了好几类的计数，格子上和图上都是合计。

### 报表：好几张图一起看

要一起看好几张图的分析（新旧对比、构成、排行、表格），助手写成报表：工作文件放在 `数据/报表/` 下，结论在前，每个结论旁边放图和取数口径。“工作数据”右上角那一行小字里点“报表”，抽屉里列出报表，点一份就在抽屉里直接画出来；挂在工作线上的报表也会出现在那条线的“数据”一栏。别的工作文件里带图表块的，也算报表列在这里。

<Shot src="insights-report" caption="报表：助手写在 数据/报表/ 下的工作文件，里面的构成和排行在页面上直接画出来" />

“工作数据”一栏把所有工作指标放在一页：上面是等你确认的提议，下面是在看的指标，按挂的工作线分节（挂在需求或缺陷上的算到它所在的线，节名点开是那条线）。一个指标一格，格子一样大：名字、最新值、和基线比的变化或“每天 · 上次 11/20”、一条小走势，越过门槛的会标出来；还没取到的写“还没取到 · 下次 02:50”。点开后的图可以切 7、30 或 90 天。数据源目录、观测计划、采集记录和报表在页头右侧一行小字里，点开是抽屉里的清单。工作线页的“数据”一栏是同一块板，只放这条线和下面各项的指标和报表。

## 数字该怎么读

- **有人找你**数的是处理批次，一批可能包含几条消息。预筛、合并和直接提醒有旁支；漏斗没有把它们强行算成同一条路径。通知的处理、已知、已读、未读、反感来自已记录的结果，尚未标注的另列。
- **回答用时**是机器人运行创建至完成，包含排队；没有实际送达时刻。旁边的本人基线来自找你的消息及你自行回复的记录。双方各至少 10 个有效样本才画对比条；这是两类样本，不能直接推出省了多少时间。
- **质量**只报收到的反馈、草稿去向、评审裁决、抽检和复盘结果。没有反馈不等于满意；没有核完的抽检不计准确率。
- **交付**按交办首轮发起日期分组，显示这一批交办目前的通过、应用、丢弃与轮数。流程阶段的停留、等待、返工指标会随流程功能补入。
- **知识**中页面阅读是全部阅读，记录不能区分回答和整理；仓库约定命中是累计值。按人员等运行维度筛选时不显示这些无法归属的数据。记忆召回则能区分回答和整理，“引用率”只表示召回记录被标为引用，不是检索评测得分。
- **成本**只报后端、模型、场景的次数与运行时长，没有完整账单就不推算金额。旧运行缺失身份或模型时单列，不猜测。

“和上一段比较”使用紧邻的同天数期间，有两段记录的指标才显示前值。页面总量、累计命中等没有历史快照的数字不做比较。Markdown、CSV 导出保留指标、图表数据、口径和明细链接，便于写周报。

“估算”默认留空。你可以自己填“每次已代答按多少分钟算”，页面才按已代答样本数换算，并标明假设。这个假设只存在当前浏览器，不上传服务器，不会变成实测的节省用时。
