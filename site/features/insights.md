# 数据：工作指标与 omem 运行统计

左侧导航的**“数据”**页把两类数字清晰分开，互不混杂：
1. **工作数据**（默认）：你业务工作上的观测指标（如埋点事件量、上线后的报错率、新旧平台流量对比）与多图表分析报表。
2. **omem 自己**：omem 和各个机器人替你做了多少件事、挡了多少消息、回答真正解决了多少问题、编码与流程耗时以及 Token 用量走势。

---

## 第一部分：工作数据（业务观测指标与报表）

上线一个新需求或推进一条[工作线](./work-lines)时，你不需要每天手动去各个后台拉图表。只要对助手说一句**“给这个需求写个观测计划”**或**“帮我盯着新平台的流量占比”**，助手就会调用你数据目录里的查询技能定时取数，在越过门槛时主动提醒你并记入工作线时间线。

<Shot src="insights-work" caption="工作数据：顶部是 AI 提议、等你确认的指标清单；下方按工作线分节展示指标卡片，点击任意卡片就地展开趋势图、取数口径与关联的观测计划" />

### 1. 观测计划与“等你确认”的指标提议

- **从观测计划自动生成指标**：使用内置技能 `observation-plan`，助手会先列出这项业务你真正关心的几个问题，再定义上线前埋点、上线后报错与使用量、迁移期新旧对比及护栏指标（还可配合 `data-sources` 技能盘点团队的数据源目录）。
- **亲口要的直接生效，后台提的先当“提议”**：
  - 你在对话里亲口让加的指标直接生效。
  - 助手在写观测计划或巡检工作线时自己提的指标，统一放进页面顶部的**“等你确认”**清单里（后台照常定时取数，让你决定时能看到真实数字，但未确认前绝不发告警通知、不写时间线）。
  - 你可以逐条或整组点**“保留”**、**“改”**（修改名称、单位、取数频率、告警门槛和画图方式）或**“不要”**（可写一句不要的理由，助手以后提指标前会先读你的取舍记录，不再提同类冗余指标）。

### 2. 自动选最合适的画法，多图合成报表

- **按数据形态自动画图**：点击任意指标格子，下方就地展开详情——支持**趋势折线、面积图、每日柱状图、堆叠柱状图、多维度并排对比（如新/旧平台各画一条线外加一张“新平台占比”图）、构成表盘**；若只有 1–2 天的数据则直接列出具体数字，不画空洞的折线。右侧清晰写明“为什么看这个指标、从哪个系统怎么查、基线与告警门槛、来自哪份观测计划”。
- **多图分析报表（`数据/报表/`）**：需要把几张图放在一起做综合分析（如新旧转化漏斗、错误类型排行与明细表）时，助手会写成 `数据/报表/` 下的工作文件，结论前置，点击右上角**“报表”**（或对应工作线的“数据”标签）即可直接在抽屉里渲染出完整图表。

## 第二部分：omem 自己（系统运行、回答质量与交付统计）

切换到**“omem 自己”**一栏，可以按最近 7 天、30 天、90 天或自定义时间段（支持与上一周期环比，以及按空间、触发人、场景、Agent 档案、模型、机器人筛选），查看 omem 的真实工作账单，并支持一键导出为 Markdown 或 CSV 供你写周报。

### 1. 七个维度看清助手到底帮了多少忙

页面顶部有吸顶导航，点击任意一个数字或条形图，右侧抽屉立刻展示**按天走势、多维度拆分胶囊（场景 / Agent / 空间 / 模型 / 触发人 / 会话 / 结果）以及每一条可点击溯源的运行记录**：

| 统计分节 | 核心回答什么问题 |
| --- | --- |
| **1. 用量与去向** | 这段时间共执行了多少次有效任务、分布在哪些项目空间和场景、每周有多少人（本人 / 团队成员 / 访客）在使用（系统后台自维护的例行整理默认单列，不掺入业务使用量） |
| **2. 提醒与挡消息** | “有人找你”和群关注替你预筛掉了多少无关消息、分诊协查了多少次；**近 30 天发给你的提醒里，哪些你真处理了、哪些你早就知道了、哪些从来没点开过**（满 8 条从未处理的会话可在此一键设为免提醒） |
| **3. 回答质量（回扫）** | 不靠人工点表情，按 `outcome-reviewer` 满一天后回扫整段对话的真实结果，统计每次回答是**解决了、接着往下推进、需补充、被纠正还是别人接手了**，并给出“回复有用占比”与“回扫同意初判占比” |
| **4. 编码、流程与研究** | • **编码交付**：各批次交办的评审通过率、应用推送数、丢弃数与平均修改轮次<br/>• **流程耗时**：每份流程定义在各阶段平均“在做 / 等你 / 卡住”多少小时、返工几次<br/>• **研究试验**：各探索方向的试验结果分布、新发现与你的认可数、交给改代码后的重跑通过数 |
| **5. 知识有没有用上** | Wiki 页面被阅读的次数、记忆在回答和办事中被被动带上或主动检索的次数与实际引用率、代码仓库“学到的约定”命中次数 |
| **6. 运行时长与成本** | 各 AI 后端、模型与场景的调用次数、排队与执行时长及对比本人自行回复的基线耗时 |
| **7. 长期走势** | 每天自动归档一份轻量统计快照，即使很久以前的原始运行日志清理了，长期的每日用量、各模型表现与回答解决率曲线依然完整保留 |

### 2. 客观克制的统计口径（绝不虚报“省了多少时间”）

omem 的数据页坚持**只报有据可查的事实，不替你编造漂亮数字**：
- **不给团队成员排效率名次**：主人可看全局，成员只看自己触发或有权阅读的记录；系统绝不生成人员效率排行榜。
- **不猜账单金额、不虚报节省时间**：没有完整上游计费单就不瞎估金额；页面底部的“节省时间估算”**默认留空**——只有当你自己在浏览器里填入“每次代答按多少分钟折算”的假设时，页面才会按实测代答样本数帮你算一个参考值，并明确标出你的假设（该假设仅存在你本地浏览器中）。
