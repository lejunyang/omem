# 工作分支、同步与推送

**omem 的每一次编码交办都在自己管理的独立工作区和独立 Git 分支上进行，绝不会弄乱你平时正在开发的本地仓库目录。** 同时，它帮你省掉了“每次新建工作区都要重新 `pnpm install` 装几分钟依赖”和“手动解合并冲突”的麻烦。

## 1. 工作区池与工作分支：免重装依赖、多需求并行

### 自动复用的工作区池（不用每次重装 `node_modules`）

你不需要做任何配置，omem 会在数据目录的 `workspaces/<空间>/` 下按需维护一个**工作区池**（每个仓库最多 4 个 Git worktree）：
- **依赖一直留着，锁文件没变就秒开**：一次交办结束归还工作区时，omem 只清理改动过和新增的源文件，像 `node_modules` 这类被 `.gitignore` 忽略的依赖目录会原样保留。下次新交办借用这个工作区时，宿主自动检测锁文件（`pnpm-lock.yaml` / `yarn.lock` / `package-lock.json` / `bun.lockb`）——**只要锁文件跟上次成功时一样，直接跳过安装命令，秒级开始写代码**。
- **多个需求同时改也不打架**：你可以对同一个仓库同时发起两三个不同需求的交办，每个交办各占一个工作区、各走一条独立分支；编码 Agent 知道同一仓库下还有哪些并行的未确认交办，需要借用另一条分支的改动时可以直接 `cherry-pick`。

### 工作分支的完整生命周期

| 阶段 | 具体怎么运作 |
| --- | --- |
| **1. 切出分支** | 未指定分支时，默认从仓库当前提交切出临时分支 `omem/<运行id>`，编码 Agent 写完第一项后自动按功能改名为规范的分支名；若指定了已有分支（`from_branch`），则直接在该分支最新提交上继续 |
| **2. 按修改项分步提交** | 编码 Agent 每完成一个修改项（`T1`、`T2`…）就单独提交一次，遵守仓库 Commit 规范；一轮结束时若还有检查脚本改出的未提交文件，宿主自动兜底提交，确保每轮历史清晰可回退 |
| **3. 同步到你自己的目录验证（可选）** | 如果你想在自己平时开发的仓库目录里跑服务试一下，在交办页“工作分支”里点**“在仓库目录检出”**——你的目录会切到这条工作分支，此后每轮产生的新提交都会**自动快进（fast-forward）同步过去**；你自己在那个目录里顺手提交的改动，下一轮也会自动合并进交办工作区 |
| **4. 一键确认并推送** | 评审通过后只需点**“确认并推送”**（可勾选“先压缩成一个提交”）：直接推到 `origin` 的同名分支并设好上游，同时自动归还工作区。一次交办跨多个仓库时，可以只勾选其中几个仓库推送；若远端有别人新推的提交会自动拦截提示，只有在你明确勾选“覆盖远端”时才会执行带安全保护的 `--force-with-lease` |

## 2. 编码前先同步分支，冲突先由 AI 按意图解决

<Shot src="delegate-sync" caption="编码前同步：交办时可选择先拉取远端新提交、再合并或变基到 main 等目标分支，也可设为“只同步不编码”专门让 AI 解冲突" />

无论是在新建交办时、还是在编码中途（直接对助手说“先把 `main` 合进这次交办，冲突你先解决”），你都可以让宿主执行 **Git 同步**：
- **三种同步动作**：拉取当前分支在 `origin` 上的新提交（快进、合并或变基）；再合并（`merge`）或变基（`rebase`）到另一个基准分支（如 `main`）；或者勾选**“只同步，不再编码”**，专门把一次棘手的分支合并交给 Agent 处理。
- **冲突三级处理机制**：
  1. **编码 Agent 先按业务意图合代码**：合并或变基停在冲突文件上时，宿主先把冲突交给编码 Agent——它通读两边的改动上下文按意图合并，遇到业务上拿不准的取舍直接发卡片问你。
  2. **真解不开时保留现场等你处理**：只有当 Agent 实在无法安全解开冲突时，运行才会暂停并给你发卡片（列出冲突文件与工作区路径）。你在工作区里解决并 `git add` 后点**“已解决，继续”**（或点“放弃这次同步”一键回到同步前状态）。
  3. **未完结 Git 现场跨轮续接 & 评审复核**：即使遇到跨多提交的 `cherry-pick`、`rebase` 或 `revert` 中途停下，下一轮也会在原冲突索引现场继续完成剩余提交；**所有由 AI 解决过的冲突都会在运行说明里详细列出“每个文件相对同步前改了什么”，交给评审角色专门核查**，防止合丢代码。

## 补充说明：切换本地仓库目录与清理工作区

- **换用你自己装好依赖的仓库目录**：如果某个空间最初是让 omem 自动克隆到 `repos/` 下的，而你本机另一处已经有一份相同 `git remote` 的克隆目录，只需在 **设置 → 空间 → 编辑仓库** 里点**“换目录”**（或直接把本地路径发给助手），即可无缝切换过去。
- **一句话清理搁置的工作区**：直接对助手说**“把没确认的交办清理一下”**，助手会列出所有搁置交办的仓库、分支和改动文件数（含遗留工作区），你勾选同意后即批量丢弃并清理未推送的临时分支。事项关闭时，挂在它下面的交办所占用的工作区也会自动归还。
