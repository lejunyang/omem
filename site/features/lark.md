# 飞书

omem 和飞书是两种身份的连接：

- **机器人**（飞书应用，租户身份）：回答你、在群里说话、发卡片、加表情、入会。只有你（和 `omem user add` 登记的人）能指挥它；同事 @ 它时走单独的访客模式。
- **你本人**（lark-cli 登录）：读你能看到的消息、文档、知识库、日程和妙记，默认只读。以你的身份写的只有几处，都要你亲手发起（见下）。

两者配合起来，飞书就是 omem 的主要入口：材料自己进来，问题在飞书里问，结果和需要你决定的事以卡片回到飞书。

## 能做什么

| | |
| --- | --- |
| [机器人与卡片](./lark-bot) | 进度卡片和思考气泡、提问卡片、下一步按钮、草稿确认、表情反馈；@ 人、加急、只给部分人看；回答里的引用变成能点的链接和只读分享 |
| [消息、文档与知识库](./lark-capture) | 群聊和私聊按类型决定存不存、整不整理；文档连图片、表格、附件一起存；知识库按目录爬，或让它按你写的方向自己发现该读什么 |
| [会议](./lark-meetings) | 你入会时问要不要把机器人带进去；记录转写、会中聊天和共享文档；有人点你的名时提醒你，会后给纪要 |
| [群里的协作](./lark-groups) | 盯群、长期分工的群、几个机器人各管一摊并互相转交、同事 @ 机器人时先把关、私聊里 `/ai` 让助理代回 |

规则（“值班群里我被 @ 就把机器人拉进去”“我加入评审会时问我要不要带机器人”）是飞书场景最常用的入口，见 [规则](./rules)。

## 接入

`omem setup` → 渠道：

1. **飞书机器人**：绑定已有应用，或扫码一步建好应用（机器人能力、长连接事件、卡片回调和所需权限）。事件走官方 SDK 的长连接，不需要公网地址。扫码人自动设为本人。
2. **读取你的飞书**：用 lark-cli 登录你自己。未登录或过期时直接发起扫码登录，可以顺手打开每 10 分钟一次的采集。

之后在 **设置 → 渠道 → 机器人权限与事件** 检查应用缺的权限和事件订阅，一键申请或扫码补齐（改了事件订阅要在开发者后台发布新版本）。企业租户里新权限可能要管理员审批。

## 以你的身份写，只有这几处

- **飞书文档**：你让助理“整理成一篇飞书文档”时，它以你的身份新建、追加、改写或移动文档，默认放在你的个人文档库；放进别人也在用的知识库或文件夹时，每次都先把具体位置发给你批准。
- **把 omem 的机器人拉进群**：规则里配置的“拉机器人进群”，或你在自己的消息里让助理盯一个它不在的群。
- **私聊指令**：你在和别人的私聊里亲手发 `/ai` 或 `/ai拉群`（默认关，见 [群里的协作](./lark-groups#私聊指令)）。

Agent 自己的工具不能以你的身份发消息。别人写的内容（群聊、文档、网页）对 Agent 来说是材料，不是指令。

## 在飞书里打开 omem

设置 → 渠道 → **网页地址** 填一个飞书里能打开的地址（局域网、VPN 或你自己的域名）。填了之后，通知卡片的“打开链接”、回答里 omem 自己的引用、插件给的练习链接都能在飞书里直接点开。

## Telegram 与 QQ / 微信

`omem setup` 的渠道部分开启。Telegram 的私聊、群、论坛话题各是一个会话；QQ / 微信经 OneBot v11 兼容桥（NapCat、LLOneBot 等）接入。命令与飞书相同，飞书专有的卡片、采集和会议功能不在这两个渠道里。
