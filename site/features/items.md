# 事项

<Shot src="items" caption="事项：待办、等待回复和持续关注，详情里有材料、相关依据和时间线" />

事项是要跟进的事：待办、提醒、待决定、等待回复和持续关注。这几周在推进的一件大事可以建成 [工作线](./work-lines)，需求、缺陷、评审挂在它下面，打开 omem 的“工作”页看各条线的现状、关键变化和下一步。它和记忆的区别是会结束：做完、过期，或者被新消息重新打开。

你直接在仓库里提交代码后，助手会核对它属于哪件事，在卡片上请你选择挂到已有事项、新建或不用管。确认挂到已有事项时，还没开始的编码阶段会补记完成；第一次接入不翻以前的提交。

把 GitHub 合并请求链接发给助手，就能挂到事项上跟进；流程可以等它合并或关闭后继续。需要启用对应插件并连接账号。事项页的“外部状态”里也能直接贴链接挂上，那里显示它现在的状态和几个要紧的字段。

卡片上还有插件给的按钮，比如合并请求开着时的“合并”：点了先确认一次，然后用你在平台上的身份去做，做完马上再读一次状态，流程和规则跟着走；平台拒绝（检查没过、缺评审）时原因写在卡片下面。助手也能做同样的事，默认每次先问你，在 设置 → 安全 → 工具审批 里可以改成“做完告诉我”或“不用问”。每次执行都记在审计里。

打开一件事项，材料上方会提示适用的流程，点“开始”先看各段做什么，再确认；没有适用建议时，点“用流程推进…”从全部定义中选。阶段条显示每段的进度、用时和尝试次数，点一段能看承担者、方案或交办、原件依据和最近进展；助手在这一段交过的截图（比如复现缺陷时的画面）也列在下面，飞书里报“做完了 / 卡住了”的进度卡会带上最近几张截图；卡片先加粗写哪一段怎么了，再是这一段的结论（长的折起来），最后是整条流程各段的状态和接下来要做的、等你的话你能做什么，按钮直接打开流程页。流程页里每段的截图是一排缩略图，点开在当前页预览，左右切换；同一张图交了两次只显示一张，这一段重做过时之前几次的截图收在折叠里。验证这类阶段交给助手做时，它按需求点逐条去试，每条的结果、做了什么、截图和录屏都列在这一段下面的“逐条的结果”里，你照着看完再确认；你给的测试账号它可以自己在测试环境登录，账号不够时会来问你。需要你确认、轮到你做或卡住时，条下直接显示操作卡片；跳过、重开或手动完成要写明原因。经过可以展开查看，流程走完后仍由你决定是否关闭事项。

流程定义在侧栏“流程 → 流程定义”。新建时讲讲这类事你平时怎么做（从哪开始、分几步、每步谁来做、哪里要你拍板、做到什么算完），点“交给助理起草”，助理在对话里问清拿不准的地方，起草好发给你；等你确认的草稿也列在左边，点“启用”才生效。打开一份先看“它会怎么走”的清单（逐段写明谁来做、怎么开始、做到什么算完、要等谁）；想改就写一句交给助理，它起草新版本给你确认。定义原文（YAML）收在“查看定义”里，熟悉格式的也可以直接改，读得通才可保存；每一段的“谁来做”和“做到什么算完”也可以直接选，装了插件时还能选插件的信号、交给插件执行，并在“完成前的检查”里打开插件的检查（见 [插件参与流程](./plugins#插件参与流程和-ai-后端)）。没有人参与时连着自己开始几段后先问你、停在等你的阶段过几天提醒一次，在 设置 → 推进工作 → 自动推进 里改。修改定义不影响已经开始的事项。

流程进行中，关联的群、会话和文档有了新内容，助手会攒一批看看这件事变了什么。新要求影响已经在做或做完的部分时，先问你要并进、另开还是不用管，不替你答应；你自己在群里拍板、或直接让助手去改的，不再问，直接并进。事项页把等你定的变化放在流程条下面，写明影响哪几段、并进来会重开哪一段；下面是全部变化的记录和正在跟的群、文档。文档更新时只看新增或改过的行。

流程卡住或有了新材料时，助手会核对群消息和平台上的真实进展。看到了复测通过之类的依据，会补在原确认卡上，你不用再去查一遍；还是你来点确认。卡住先查能自己查的，最后需要你登录或找人补资料，工作页“需要你处理”里会有一步动作或现成草稿。

重开上游会收回下游还没过的开始确认；如果你已经推送了当前交付，等推送的一段可以直接完成。不用为返工另起一轮，只要正在编码的这一轮已接手本次修改。新交付也会触发对久等阶段的核对：产出确实已经在别处做完的，助手会补记并撤回旧卡，要你拍板的事不代答。当天你已经在这件事上有动作，停留提醒顺延。

没有模板也能让助理接着做：直接交代这件多步工作，助理为这件事项起一次性清单并告诉你各步。只读或本地可回退的阶段可以直接开始；写外部系统、部署、对外发消息前仍先确认。走完以后，可以把清单存成模板，不用从头写。

<Shot src="item-flow" caption="事项流程：评审通过，轮到你推送" />

已经做过的阶段可以补记完成，验证结果可以逐条签字；同一开始关卡连着直接同意后，会先问你是否以后直接开始，重开或暂停时改回每次问。新内容每天默认最多看 12 批，多的留到明天；事项页的阶段上有“这一段已经做过了”，验证结果每条可以点“看过，对”或“不对”；工作页的“按阶段”把在走流程的事项按阶段分列（侧栏不再单列“流程”，流程定义从“按阶段”右上角进），工作页右栏列出流程里等你的；这几个数和开关在 设置 → 推进工作 里。每件走流程的事项在 [工作线](./work-lines) 下有自己的页面（事项列表、看板、工作页和飞书进度卡都直接打开它），头部是阶段条和等你的那一段，“流程”标签按文章的写法排：背景、每一段做了什么（截图插在对应的文字后面）、接下来要做的和这件事的来源；等你的卡片下可以写一句话（开始时照这句做、做完了不满意就按这句重做、卡住了就按这句重开），也可以点“在对话里讨论”把这一段带进对话。

流程结束时（走完、你停下或事项关闭），事项页上多一块“这一次走得怎样”：各段用了多久、其中等你多久、卡在哪、返工几次、哪些关卡你每次都直接同意。同一份流程又结束满三件，助手会对照这几份回顾看定义要不要改，有站得住的修改就起草一份新定义等你点“启用”，不会直接改。重开前面的阶段时，后面正在做的阶段不会被悄悄停掉，会问你要停下还是继续做。

持续探索一个项目可用内置“研究”流程：梳理功能清单 → 提方向由你选 → 按预算逐个试验 → 小结归并发现。功能清单存事项空间的工作文件；提方向时看得到以前各轮的方向和记下的发现标题（看不到试验细节和结论），提交后宿主再去掉完全重复的试验；点“再来一轮”时可以写这一轮想看什么、别碰什么。预算用满后剩下的留到下一轮，默认由你说何时继续；没有方向、没有新发现都是正常结果。事项页的“研究记录”分四块：发现（没判定的在前，可以认可、不算、以后再说或标为已改好；正文按条件 / 现象 / 为什么是问题 / 建议分节，可带截图；“就这条问”“看不懂，重写”把这一条带进对话，助手可以改写或改状态，第一次的原文留着）、试验（没做好的在前，展开看摘要和依据）、方向（等你选时在这里选，在做的可以结束并写结论）、覆盖（各功能试过几次、哪些没碰过）。完整字段见仓库的 `docs/v2/studies.md`“第二期的实现”。

研究可限定仓库、选择登记的执行环境，试验在自己的副本里按确认时的版本运行，不改你的检出目录。允许改代码后，可以挑几条发现一起“交给改”（不限轮次和类型；也可以在对话里让助手交），omem 按顺序一次交办一条，用范围里选的“改代码用的 AI”和“评审改动用的 AI”；评审通过的自动标为已改好，没过的留给你看，改动留在各自的交办分支上等你确认。范围在事项页“研究记录”顶上改，发现上有“去改”，执行环境在 设置 → 推进工作 → 研究的试验在哪跑 登记。

执行环境可以选“派给设备”：试验交给你配对过的另一台设备跑（比如要那台的系统或装好的工具）。那台按仓库的远端地址找到自己的那份仓库，缺方向确认时的提交就自己取一次，在它自己的工作区里跑，用它自己的模型和技能；本人在那台的检出目录不动。结果和证据文件送回这里的记录，试验上写着在哪台跑的、那边的运行是哪一条；单个证据文件超过 2 MB 的文本只带回开头。那台没有这个仓库时试验记“跑不了”；离线或出错时过 10 分钟再派一次，还不行记“跑不了”。停止流程、重开或预算用完时会请那台停下。只对你自己的设备开放，别人的服务不能接。

含“改”阶段的流程可按你允许的方向逐条改缺陷，评审通过后重跑失败试验，改动留在交办分支上等你应用；没改成的留给你看。通过范围接口登记远端和分支前缀后，试验与改后重跑可在授权范围内推送，每次有记录；已有流程需自行补上“改”阶段。

由你来做或只等进展的阶段可以写 `done: { signal: git.pushed }` 或 `done: { signal: git.merged }`。关联交办的改动应用到仓库后，所有仓库的提交都已在远端（合并信号则在目标分支的远端）时，这一段会自己完成，后面的阶段接着走；你也可以照旧手动点做完。内置需求交付模板的推送段已采用推送信号；已有模板只在你修改后生效，进行中的事项保留启动时的副本。

流程定义也支持重复轮次：`repeat: { from: plan, every: manual }` 从指定阶段起重做，默认等你说“再来一轮”；也可写 `done`、`day` 或 `[tue, fri]`。上一轮没做完不开新的，连续自动开始到上限先问你。

流程有待答提问、等你确认或卡住时，新情况会攒三分钟再交给决策模型。判断可能影响卡点时，助手先核对相关卡点和依据。事项时间线可以看到判断和对账结果。设置 → AI → 决策 可调“流程卡点复核”门槛。

轮到你做的阶段只发一张“轮到你了”的卡片（写着要做的事，做完点“做完了”），不再先问“开始吗”，即使连续自动开始到了上限。流程明写的开始关卡和待你判断的条件照常询问。有交办完成卡时，在那张卡上点“确认并推送”即可，推送成功后流程会核对并完成对应阶段。阶段卡和对账卡的正文可以点开事项，阶段卡也会附上相关的承担运行和交办。

对账发现目标已经达到或不再成立，会带依据直接收口，不开下一轮。需要同事配合时，只要机器人在事项关联群，卡片就能直接发草稿；不用另外打开群复制。返工不算开始新的一段：已确认过或做完过的助手阶段直接重做（流程明写需要确认的除外）。上游重开后，助手会停下还在用旧结果的下游工作，等上游重新做完再继续；你的阶段只标待复核。“停下 / 继续做”只适用于以前发出的卡片。

运行阶段可用 `ai: strong / standard / cheap`，在配置的 `agents.tiers` 把档位映射为 `{ profile, model?, effort? }`；未配置沿用默认 AI，额度用完等恢复。`at: "10:00"` 与 `window: "23:00-05:00"` 按配置时区限制开始；普通运行用满分钟预算会停止并等你，trials 阶段的 `budget: { minutes: 240, trials: 8 }` 用满任一上限则完成本轮阶段、保留剩余队列。写了 `ai` 的运行或 trials 阶段可加 `escalate: { to: strong, max: 2 }`，交不出结果或拿不准时带反馈换档重做，trials 每个试验最多升档一次。事项页上能看到现在第几轮、点“再来一轮”、改这一轮的预算。

同一次推送修好的几件事项，回归验证可以一起做：给这一段写 `together: push`，几件走到这一段时合用一个运行（先等一分钟让同批的到齐），环境和账号只准备一次，结果仍按事项分开交，各自的流程页只显示自己的用例和截图。

## 不用专门去记

- 对话里说“周五前把方案发给小王”“等财务回复报销口径”，助理回答时顺手记成事项，并在回答末尾列出。
- 群聊和文档整理时，和你有关的承诺、请求、待决定的事会被提出来。
- 也可以在“事项”页右上角“新建事项”写一句话，交给助理理解时间和对象。

你没开口、助手自己从材料里看出来的事（整理群聊、巡检、简报、有人找你、规则），要先说清你为什么会要它：你自己说过的话、你让它盯着的「关注」，或你近况里正在推进的哪条线。说不清的不建；拿不准的先放进“可能要跟的”：不提醒、不进四栏，每天早上的“今天”和事项页顶上逐件给你点“留下”或“不要”，三天不答就放下。你每次留下或不要都会记下来，助手下次建事项前会先看你以前怎么选的。判断用的门槛在 设置 → 后端与模型 → 决策 的“自动建事项”。

## 指派清点与临期预查

在规则页启用“清点指派给我的事”（默认关闭）。工作日 09:00，主助手用内置技能 `assigned-sweep` 清点还没结束、指派给你而且有时限的外部对象。把要查的平台和查询技能写进工作近况的“本人补充”；没技能或没权限时，运行里会写清楚，不猜查法。重复看到同一对象只更新原事项；新发现且三天内到期的合成一条通知，其余在早上的“今天”和事项页看。

如果一件事不到 48 小时截止、一天没有进展，也没在走流程，巡检会先只读核对材料和原链接，把现状、查到的依据、下一步和需要你先定的事放到“需要你处理”。有定时提醒的，结论并到原提醒，不再多发一张。点“按这个开始”才在事项会话接着做；点“先不用”不会开始。一个截止只预查一次，改到更晚后符合条件才再查。

预查建议的是同一件多步工作时，点“按这个开始”后，助手会在事项会话里开一份一次性阶段清单，不用你逐步交代。涉及外部操作的阶段照常等你确认。

## 从别的平台同步

<Shot src="item-sync" caption="设置 → 推进工作 → 事项同步：订阅一个项目，新条目先当候选还是直接建、这边改了状态要不要写回" />

issue、需求、缺陷这类在别的平台上的条目，可以同步成事项：那边的标题和状态变了，这边跟着变。能读哪些平台由启用的插件提供（内置的 GitHub 插件能读一个仓库的 issue），用的是你在账号页连接的那个账号。

在 设置 → 推进工作 → 事项同步 点“订阅”，选平台、填要读的项目、选放进哪个空间。每个订阅有两项可调：

- **新条目**：先当候选（出现在事项页“可能要跟的”里，你说要才算数），或读到就直接建成事项。
- **这边改了状态**：先问你要不要把那边也改掉，或下次同步时直接写回。只读的平台没有这一项。

订阅可以暂停，也可以点“现在读一次”。同一个条目只归第一次读到它的空间；这个卡片在有插件提供平台之后才出现。

<Shot src="item-external" caption="从平台来的事项：它在那边叫什么、现在什么状态；这边关掉以后先问要不要写回" />

从平台来的事项，详情里多一块“来自……”：条目的编号和标题（点开是那边的页面）、它在那边的状态、负责人和上次读的时间。你在这边把它关掉或重新打开，这一块会问“把那边也改成……吗”，点“写回”或“只改这边”；同一个问题也在工作页“需要你处理”里。那边在你改之后又变了，就不写回，留给你看。

## 跟到收尾

- **时间线**：每次变化（改期、完成、新消息）都记一条，带来源。通知只带这次变化的来源，错的来源可以撤回并留历史。
- **期限**：待办 14 天、待决定和关注 7 天、等待回复 14 天没有新进展就自动“过期”（不算完成，有新进展会重新打开）。期限在 设置 → 推进工作 → 事项自动收尾 里改。工作线（以及走过流程、挂着别的事项、开着关注的事项）不按期限过期，而是先观察、再自己结束，见 [工作线](./work-lines)。
- **自己判断办没办**：你在来源群里回过话、回了表情的，由助理判断是否已经办了并关掉；回 DONE 表情直接关。
- **每日清点**：自动收尾的（包括观察期满自己结束的工作线）和明天过期的，要留下的选“保留”或“恢复”；助手自己建、等你定的候选也在这里。开着早上一张“今天”（默认开，见 [工作线](./work-lines#早上一张-今天)）时，它是那张卡片里的一段；关掉后每天 9:30 单独发一张清点卡片。
- **唤醒**：说“半小时后看看 CI 结果”“小王发了发布单就检查回滚方案”，它设一个定时或等消息的唤醒，到时候在原会话里接着做，没变化不打扰你。

## 拿不准先问你

<Shot src="ask-question" caption="拿不准的取舍先问你：选一个，或写一句自己的回答" />

做事项的过程中遇到非你决定不可的事，助理发一张卡片问你：选一个按钮，或在对话里回一句。你答完它在同一轮接着做。还没答的问题都在工作页右栏的“需要你处理”里。

设置 → 安全 → 工具审批 可以逐个选“每次问我 / 做完告诉我 / 不用问”。默认连续批准 10 次会问一次要不要改成“直接做，做完告诉我”，你同意才改；次数可调，0 不提议。做完告知会放进不急的通知里。随时能改回每次问，机器点击、输入类插件工具始终要批准；拒绝理由会回给 Agent。

## 大事项

- **材料**：大型需求可以建一个事项，把文档、群聊、代码分支、要对照的仓库挂上去；之后的交办和评审会读这些材料，结果也挂回事项。
- **工作文件**：要做好几天的事（逐个回溯一批群、清点一批文档），助理把当前成果写成工作文件挂在事项上：做了哪些、得到什么、下一步。下次接着做先读它。
- **周报**：建一条定时规则（工作日 18:00）让某个 Agent 往 `weekly/<周>` 工作文件里追加当天进展，周五整理成稿。
- **在这些会话里进行**：助理在哪个会话或群里记了、更新了这件事，事项就和那里关联上；详情里列出这些会话（最近活动和最后一句话）和正在为它跑的运行。在任一会话里再谈这件事，助理都知道别处说到哪了（见 [多 Agent 协作与会话](./collaboration)）。

## 需求点与测试点

一个需求要开发、评审好几轮时，把它拆成需求点放进业务空间的“需求”树：系统 → 模块 → 页面 → 功能，功能下面挂测试点。在事项的材料里点“拆需求点”，AI 读需求文档和讨论拆好，你在左侧“编码”的“需求”标签里确认或修改。

- 切换需求点时先显示新标题和加载骨架，返回后再显示详情；编码列表只读状态摘要，交办轮次多也不用搬回完整补丁。
- 切换空间后显示该空间的需求树，并退出原来的需求详情和编码与评审；打开跨空间的需求链接时，会切到它所属的空间。
- 交办这个事项时，编码 Agent 按需求点开发；评审逐个核对，需求树上每个点显示最近一次评审的结果（已实现、部分实现、没实现）。
- 为这个事项做的交办和分支评审列在需求点下的“编码”里，和“交办”标签的写法一样：在等谁、进度、分支；点开转到“交办”标签里的这次交办，定要改的问题、回答等你决定的项、确认并推送。树上等你处理的节点标“等你 N”。交办的“需求点”标签里点一个需求点，就只看它这一轮的变更点和代码。
- 编码 Agent 跑完测试后把每个用例的结果交上来，写明它对应哪个测试点；需求树上标“测试通过 / 测试失败 N”，点开测试点能看到每个测试最近一次的结果、失败原因和截图、录屏，更早的结果折叠起来。同一个测试只留最近 3 次结果的截图和录屏，不会越积越多。
- 每个仓库的测试怎么跑、用例里怎么写测试点 id，写成技能挂在这个仓库的空间上（设置 → 空间 → 这个空间的技能）：技能放在 omem 的数据目录，不用放进代码仓库，只有这个仓库的编码和评审会用到。
- 改需求分两种：写错了选“更正”；规则变了选“业务变更”，写清原因和依据，以后翻时间线能看到当时为什么改。
- 需求跨业务时，在两边的需求点之间加“关联”，不复制。
- 需求点能被搜索到，测试点不进搜索。
- 拆需求的角色可以在 Agent 页改：改说明、换模型、挂技能（比如在团队的测试平台上同步生成用例）。
