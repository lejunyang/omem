# 事项

<Shot src="items" caption="事项：待办、等待回复和持续关注，详情里有材料、相关依据和时间线" />

事项是要跟进的事：待办、提醒、待决定、等待回复和持续关注。它和记忆的区别是会结束：做完、过期，或者被新消息重新打开。

## 不用专门去记

- 对话里说“周五前把方案发给小王”“等财务回复报销口径”，助理回答时顺手记成事项，并在回答末尾列出。
- 群聊和文档整理时，和你有关的承诺、请求、待决定的事会被提出来。
- 也可以在“事项”页右上角“新建事项”写一句话，交给助理理解时间和对象。

## 跟到收尾

- **时间线**：每次变化（改期、完成、新消息）都记一条，带来源。通知只带这次变化的来源，错的来源可以撤回并留历史。
- **期限**：待办 14 天、待决定和关注 7 天、等待回复 14 天没有新进展就自动“过期”（不算完成，有新进展会重新打开）。期限在 设置 → 定时任务 里改。
- **自己判断办没办**：你在来源群里回过话、回了表情的，由助理判断是否已经办了并关掉；回 DONE 表情直接关。
- **每日清点**：每天一张卡片，列出自动收尾的和明天过期的，要留下的点“保留”或“恢复”。
- **唤醒**：说“半小时后看看 CI 结果”“小王发了发布单就检查回滚方案”，它设一个定时或等消息的唤醒，到时候在原会话里接着做，没变化不打扰你。

## 拿不准先问你

做事项的过程中遇到非你决定不可的事，助理发一张卡片问你：选一个按钮，或在对话里回一句。你答完它在同一轮接着做。还没答的问题都在“今天”页的“等你回答”里。

想让某些操作必须先经你批准，在配置里列出工具名（`approvals.tools`，默认不开）；拒绝时写的理由会回给 Agent。

## 大事项

- **材料**：大型需求可以建一个事项，把文档、群聊、代码分支、要对照的仓库挂上去；之后的交办和评审会读这些材料，结果也挂回事项。
- **工作文件**：要做好几天的事（逐个回溯一批群、清点一批文档），助理把当前成果写成工作文件挂在事项上：做了哪些、得到什么、下一步。下次接着做先读它。
- **周报**：建一条定时规则（工作日 18:00）让某个 Agent 往 `weekly/<周>` 工作文件里追加当天进展，周五整理成稿。
