# Agent 与技能

**omem 不自带大模型，也不把几十条死板的 prompt 规则硬编码在宿主里。** 理解、调查、写代码和审代码全部交给你已安装的 Agent（Codex、Claude Code、Gemini CLI、Antigravity、Copilot、Qwen、Cursor、豆包等 25+ 种支持 ACP 或 CLI 的工具）；omem 给它们提供近 **50 个专职内置角色**、一套按需展开的 **MCP 工具与技能库**，以及完整的**智能选型、额度避让、网络出口绑定、操作审批与 Linux 文件/出网沙箱**。

<Shot src="agents" caption="Agent 页：近 50 个内置角色与自定义档案，每个可独立配置后端、模型、思考强度、工具分组与技能" />

## 1. 近 50 个内置角色与自定义档案：各司其职

在 omem 里，不是让同一个笼统的“AI 助手”包揽所有活，而是每类任务都由专门的角色负责：

| Agent 页上的分组 | 内置角色 |
| --- | --- |
| **对话与代答** | 主助手（`assistant`）、访客把关（`gatekeeper`）、回答访客（`guest`）、90 秒快速通道（`first-look`）、有人找你分诊（`mention-triage`）、会话滚动摘要（`summarizer`） |
| **事项与流程** | 定时巡检（`heartbeat`）、每日简报与周报（`brief`）、事项收尾（`item-keeper`）、事项跟进（`item-follow`）、流程对账（`flow-reconcile`）、提交认领（`commit-claim`）、工作近况与人物卡（`work-state`）、长任务跟进（`supervisor`） |
| **编码与评审** | 需求拆解（`req-splitter`）、编码前检查（`business-analyst`）、写方案（`designer`）、编码（`coder`）、功能评审（`reviewer`）、评审负责人（`review-lead`）、业务评审（`review-business`）、架构评审（`review-arch`）、历史评审（`review-history`）、精简评审（`review-simplify`）、规范评审（`review-style`） |
| **采集与归档** | 材料整理（`ingest`）、空间归档（`archivist`）、归档规则起草（`archive-rule-writer`）、原件定级（`triager`）、关注群筛选（`curator`）、飞书知识库侦察（`kb-scout`）、标注复核（`note-reviewer`） |
| **Wiki** | 目录规划（`wiki-planner`）、页面撰写（`wiki-writer`）、发布前与每晚核对（`wiki-checker`）、原件变更巡检（`wiki-linter`）、目录归整（`wiki-organizer`）、精读整理（`distiller`）、卡片出题（`tutor`） |
| **记忆与技能** | 夜间做梦（`dreamer`）、记忆盲评复核（`memory-reviewer`）、记忆目录整理（`memory-organizer`）、技能分组整理（`skill-organizer`） |
| **复盘与改进** | 档案复盘（`coach`）、盯群经验提炼（`listen-coach`）、夜间回放盲评（`replay-judge`）、回复效果回扫（`outcome-reviewer`）、AI 规则起草（`ai-policy-writer`） |

### 档案多了怎么找：分组和搜索

Agent 页左边的列表按分组折叠，顶上有一个搜索框：

- **内置角色按用途分成上表的七组**：默认收起，每组标着个数，点开才列出角色；右边打开哪个角色，它所在的组自动展开。
- **你自己的档案自己分组**：在档案表单的“分组”里写几个字（如“值班”“写作”），已有的分组可以直接点选；没写分组的排在最前面，插件带来又没分过组的归在“来自插件”。分组只影响这一页怎么排，Agent 自己看不到。也可以对助手说“把 oncall-helper 放进值班组”。
- **搜索**：在“Agent 档案”标签下按名字、用途和分组名同时筛档案和内置角色；在“技能”标签下按名字、说明、用途和分组名筛，结果跨分组列成一张表，每条写着它在哪个分组、哪个用途下。

### 每个角色都能自由定制，且不怕升级冲突

在网页 **Agent** 页点开任意内置角色，或者点 **＋ 新建** 创建你自己的专职档案（如“报警值班分析”，在聊天里用 `/as 档案名 任务` 调用）：
- **按能力配模型**：分诊、把关用便宜的快模型；写 Wiki、写代码、做架构评审用强模型和高思考强度（`effort`）。
- **按分组勾选工具与外部 MCP**：在“omem 工具”里按分组勾选（如 `group:read` 整组勾选、再单独取消 `-write_page`），也可挂载你在 **Agent → MCP 服务** 里配置好的外部 MCP 服务（密钥独立加密保存，支持一键检测连通性）。**你对内置角色增减的工具、技能和 MCP 单独记录，不复制角色正文，omem 升级后角色说明自动同步新版。**
- **改写角色说明并支持三方合并**：想改内置角色的提示词时，点自定义会复制一份到数据目录；日后 omem 升级了源码版说明，可用 `omem roles merge <角色名>` 将你的修改与新版三方合并（冲突交由 AI 辅助解决）。

## 2. 怎么选 AI：AI 组、一句话定规则、额度避让与故障切换

当你同时装了 Codex、Claude Code、Gemini、Antigravity、豆包，又配了几个 API Key 时，omem 帮你把所有算力统筹起来：

<Shot src="settings-ai-rules" caption="设置 → 后端与模型 → 规则：按任务类别设定可用 AI 组、禁用模型族，也可用上方一句话自然语言修改" />

1. **AI 组（`strong / standard / cheap` 与自定义组）**：在 **设置 → 后端与模型 → 规则 → AI 组** 中，把多个“后端 · 模型 · 思考强度”按优先级排成一组（支持设定仅在如 `20:00-09:00` 夜间时段生效）。组名本身就是聊天斜杠命令——发 `/写作` 或 `/强` 立刻切换到该组当前第一个可用的 AI。
2. **按任务类别定规则（支持“用一句话改”）**：系统将所有运行分为 9 大类（日常整理、巡检与分诊、对话、写作、编码、评审、调查与交办、流程与研究、长任务跟进）。你可以为每类指定可用组和禁用项，或者直接在顶部输入框写一句**“日常整理别用 Gemini 和 Claude Code”**——系统会自动起草规则并列出近 7 天受影响的运行次数，你点确认即生效。
3. **运行前 1 秒自动选型**：开启“运行前自动选”后，未指定 AI 的任务在启动前由决策模型结合**任务内容、你的总体选型偏好（任务选型）、候选说明与各账号剩余额度**，在 1–2 秒内排好最合适的 AI 优先级顺序。
4. **多账号额度实时监控与自动避让**：
   - **同一后端可登多个账号**：Codex、Claude Code、TraeX、Copilot、Antigravity 支持在网页上直接点**“再加一个账号”**，生成独立的 `antigravity#2` 等后端，各自拥有独立的登录目录与额度。
   - **自动避开快用完的账号**：omem 每隔几分钟不耗额度地读取本机 Codex、Claude Code、Antigravity 账号的 5 小时窗口与周额度（API Key 后端则支持设置每分钟 RPM / TPM 限额自动排队，以及按模型设定每日次数上限）。任一窗口用到 **90% 以上**（或周剩余日均额度低于阈值）时，该账号自动排到队尾，后台任务优先用其他账号；遇到后端崩溃、断流或限流时，**当前运行自动无缝切换到下一个候选后端接着做**（并告知新后端此前已完成的写入，绝不重复发消息）。

## 3. 并行任务板：让主助手分头核对多份材料

当你让主助手同时核查几块独立材料（例如“分别核对这三份清单的数量和出处”），主助手会分头派出多个子运行并行调查，并在运行页和工作项页展示实时**任务板**：

<Shot src="run-board" caption="运行页任务板：横向时间轴展示各并行分块的执行人、所用模型、排队与执行时长及验收状态" />

<Shot src="progress-board" caption="分头在做的：汇总任务板、编码交办与评审进度，需你确认的用暖色标出，重做过的记录历次耗时" />

- **自动逐块验收与换模型重做**：必选分块交回报告后，主助手会逐块核验依据；发现有缺口或疑点的分块，会自动换另一个模型补查（最多重做两次），全部收齐后再给你一份带各块出处的汇总结论。
- **跨设备派活（`borrow` / `remote`）**：任务板的每个分块还可以指定派给你已配对的另一台设备——既可以只借对方的 AI 后端算力来查本机的库（`borrow`），也可以在对方开启接活授权（`node.acceptWork`）后直接去查对方机器上的仓库和资料（`remote`）。

## 4. 技能（Skills）与接管外部几百个杂乱技能

**技能**（`library/_skills/<名>/SKILL.md`）是沉淀下来的标准操作手册，挂载到档案上供 Agent 按需调阅：
- **开箱即用的内置技能**：包括 `lark-messaging`（飞书卡片与消息规范）、`lark-docs` / `lark-suite`（飞书文档与套件操作）、`wiki-writing`（读者优先的 Wiki 写法）、`research`（先查内库再查外网并交叉核对，严禁外发内部名称与代码）、`improve-loop`（固定度量命令测基线，逐轮尝试改动，无提升自动回退，达标或连续四轮停滞后输出报告）、`desktop-control`（用 `aad` 操作桌面与浏览器）。
- **技能草稿由夜间复盘自动试用转正**：你或“做梦”提炼出的技能草稿，会由夜间回放盲评（`K1`）在真实历史问题上试用，累计两胜且胜多于负即自动启用（见 [学习与进步](./learning)）。
- **一键接管 Agent 自带的几百个技能（`omem skills take-over --on`）**：很多外部工具会往 `~/.claude/skills`、`~/.agents/skills` 里塞进几百个技能，导致提示词被截断、模型根本看不过来。开启**“Agent 自带的技能 → 接管”**后：
  1. omem 将这些技能收进统一技能库（保留原件备份可随时一键撤销），按名称前缀和用途自动归成**“分组 → 用途 → 技能”**三层目录树。
  2. 原 Agent 的技能目录里**只保留 omem 说明和每组一个一句话总入口**——Agent 平时只看几十个字的总入口，需要时才按图索骥读取具体技能全文，上下文瞬间清爽。
- **技能说明按相关度自动带上**：配了向量模型后，每次运行的说明里技能只列名字（分组只列组名），和这条消息或这次任务相近的技能（最多 4 个）才把说明附在消息后面；无关的消息一个说明都不带，同一个会话里给过的不重复。
  - **没有向量模型时**：照旧给整份目录，主助手每个技能一行说明。
  - **想看实际带了什么**：在运行页“上下文 → 看提示词”里，“可用技能”一节是常驻的名字，“可能用得上的技能”是这一条自动带上的。
  - **觉得带少了或带多了**：在 **设置 → 检索与记忆 → 每次运行带上的经验和技能** 里调技能的相似度门槛和每次最多带几个，也可以整个关掉，回到每次给整份目录。

## 5. 安全防线：操作规则、网络条件与 Linux 沙箱

当 Agent 拥有命令行、文件读写和浏览器操作能力时，omem 提供三层硬隔离来守住安全底线：

### ① 操作规则（Command & HTTP Gate）：写操作与敏感接口必审

在 **设置 → 安全 → 操作规则** 中，可以按生效顺序配置匹配规则（不仅拦截 Agent 直接敲的命令，连它写的 Shell / Python / Node 脚本里调的子命令以及 `aad` 浏览器发出的 HTTP 请求都能拦住）：

<Shot src="security-rules" caption="操作规则：按命令、文件、omem 工具或 HTTP 接口设定放行、拒绝或需指定人批准，下方可一键启用插件规则包" />

- **四类匹配对象**：**命令**（程序名、子命令如 `mr create`、参数正则）、**文件**（读写删改路径正则）、**omem 工具**（工具名与参数字段正则）、**HTTP 请求**（域名、方法、路径与请求体，支持从浏览器录制记录里直接提取生成规则）。
- **审批流转**：命中的操作可设为放行、拒绝、只记录或**要批准**（发飞书卡片给本人或指定审批人，可选“只这一次 / 本次运行同类放行 / 永久放行”）。所有拦截、批准及以你身份发出的消息全部记录在底部的**审计记录**中。

<Shot src="security-audit" caption="安全审计记录：按时间完整记录所有规则拦截、人工批准、代发消息与成员权限变动，点击可查原始内容" />

### ② 限定后端的网络出口条件（TUN / 代理 / 出口地区校验）

如果某个国外模型后端必须走特定 TUN 网卡或代理、且要求出口 IP 必须在指定地区：在 **设置 → 后端与模型 → 通用** 点开该后端配置**“网络条件”**：

<Shot src="ai-network-conditions" caption="后端网络条件：绑定 TUN 网卡或代理，调用前自动核验 IPv4/IPv6 出口地区与 DNS 设置" />

- 调用前自动请求目标站点的 Trace 接口核验 IPv4 与 IPv6 出口地区/IP（结果缓存 1 小时），运行期间每 2 秒监测网卡与代理端口状态；一旦 TUN 断开或出口不符，**立即停下并按兜底顺序切换到其他可用后端**，绝不裸连泄漏请求。

### ③ 本机 Linux 文件沙箱与出网代理（`bubblewrap`）

在装有 `bubblewrap` 的 Linux 服务器上，不仅团队成员的运行可以隔离在各自的账号目录里，你本人的运行也可以在 **设置 → 安全 → 运行的沙箱** 中开启文件系统与出网隔离：

<Shot src="settings-sandbox" caption="运行的沙箱：基于 bubblewrap 自动遮蔽浏览器资料、SSH/云工具凭据与系统套接字，普通写入落入写时复制层" />

<Shot src="settings-egress" caption="沙箱出网代理：统一管控沙箱内命令行工具的网络连接，查看每次运行连接的主机明细与被拒请求" />

- **敏感凭据自动隐身**：沙箱默认遮蔽 Chrome/Edge 等浏览器资料、`~/.ssh`、云厂商凭据与宿主套接字；受保护的命令（如 `lark-cli`、`gh`、私有 `npm`）通过宿主侧独立执行器按审批调用，Agent 进程本身摸不到原始密钥文件。开启“进了沙箱的运行全部开启完全访问”后，Agent 在沙箱内无需每条命令弹框确认，既流畅又安全。
- **主目录写时复制**：沙箱里写进主目录的东西（工具缓存、配置、下载的文件）落在每人自己的一层，下一轮还在，真实主目录不变。卡片上的“主目录的改动”列出每层多大，点“清空”后下一轮从真实主目录重新开始。
- **自己登记要登录的命令**：凭据插件没有声明的命令行工具，可以在“你登记的命令”里填命令名、登录目录和登录变量名。之后新起的运行里，这些登录目录被遮住，调用经执行器用你的登录跑。这一项要以本人身份登录网页才能改，在服务器本机直接打开的页面不行。
- **出网代理与云端后端只读工具**：开启 **出网代理** 后，沙箱内所有外发请求均经过本机代理，可按域名与路径执行 HTTP 操作规则审计（规则可限定请求来自哪里：Agent 直接发的、执行器里的命令、浏览器里的，例如只拦 Agent 直连内网接口、命令行工具照常用）；而在 **设置 → 安全 → 云端后端调工具** 中，还可为豆包 OpenAPI 等纯云端后端授予限时（默认 15 分钟、最多 32 次调用）、仅限当轮空间权限的只读回调凭证，让云端模型也能安全核对本机库内原文。

<Shot src="settings-cloud-tools" caption="云端后端调只读工具：经双向连通性探测与本人确认后，为云端会话签发当轮即废的限时只读凭证" />
