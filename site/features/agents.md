# Agent 与技能

omem 不自带模型。理解、调查和写作交给你已经装好的 Agent（Codex、Claude Code、Gemini CLI、Copilot CLI、Qwen Code、Cursor Agent……，任何支持 ACP 的都行），omem 给它们一组工具（检索、读原件、写记忆和事项、发飞书消息……）和一份角色说明。所有写入都经过工具，按空间和角色限定权限，记在运行里。

## 用 API key 运行

不想在这台机器上登录 Codex 或 Claude Code，或者想让一部分任务按 API 计费：设置 → AI → API key 添加 OpenAI 或 Anthropic 的 key，勾选要生成的后端（Codex / Claude Code 的 ACP 和命令行版本）。生成的后端叫 `codex@<编号>`、`claude@<编号>`，在 Agent 页和任务选型里和其他后端一样选；它们的额度、并发和“额度用完”跟本机登录的那个分开算。

key 存在数据目录的 `secrets/ai-keys.json`，不写进配置文件，网页上只显示后 4 位；“检查”按钮发一个不花钱的请求确认 key 能用。删掉提供方时 key 和生成的后端一起删掉。

设置 → AI 另有语音、决策、图片生成三个子页，选好提供方和模型后才启用对应的功能。

## 豆包后端

本机豆包 CLI 用 `doubao-cli` 后端，omem 工具经终端里的 `omem tool` 调用；OpenAPI 用 `doubao` 后端，在云端回答，不能调用本机工具。CLI 按 `doubao` 命令识别，同名命令由哪个发行包安装不影响接入。

豆包的会话保存在账号里。先用 `omem doubao login` 授权 OpenAPI，omem 就能在 CLI 或 OpenAPI 的单次任务结束、失败后删除这次建的会话；聊天会话保留供追问，换成新会话后清理旧的。没有授权或清理失败时，运行里会提示。授权过期且无法刷新时需要重新登录，既有历史不会批量删除。

## 内置角色

omem 自己的每类工作都由一个专门的角色来做，大约三十个：

| 做什么 | 角色 |
| --- | --- |
| 和你对话、交办、协调 | 主助手 |
| 编码与评审 | 编码、功能评审、业务评审、架构评审、历史评审、规范评审、评审负责人 |
| 整理材料 | 材料整理、精读整理、原件定级、归档、归档规则编写、筛选值得关注的群、知识库侦察（`kb-scout`） |
| Wiki | 规划、写作、目录整理、检查 |
| 记忆与事项 | 记忆复核、记忆目录整理、事项维护、做梦、简报、巡检 |
| 复盘与进步 | 档案复盘（`coach`）、夜间复盘评判（`replay-judge`） |
| 飞书访客 | 访客把关（`gatekeeper`）、回答访客（`guest`） |
| 学习 | 英语陪练、口语评价（`speaking-coach`） |

每个角色在 Agent 页都能：

- **换模型**：选后端、模型和思考强度。把关这类用快的小模型，写作和评审用强的。
- **改说明**：复制一份到你的数据目录（`library/_roles`）再改。omem 更新后，角色说明有变化时可以恢复源码版，或三方合并，冲突交给 AI 处理（`omem roles`）。
- **挂技能、加专属记忆**：评审这类内置角色也一样。挂上或去掉技能（以及增减工具）不会复制角色说明，只单独记一份“在哪个版本上加了什么”，omem 更新后角色照常用新说明，不用你合并。

## 自建档案

**档案**（`library/_agents/*.md`）是一个专门的处理者：做什么、用哪些技能和工具、默认后端和模型。

- 说“建一个负责报警分析的 Agent”，或在 Agent 页点 + 新建，按表单填。
- `/as 档案 任务` 把一件事交给它；规则、盯群、插件、多机器人都能指定档案。
- 纠正它的话记成它的专属记忆，每晚复盘提出改进建议（见 [学习与进步](./learning)）。
- 专门跑命令行排查的档案可以打开“完全访问”：命令不进后端的沙箱、不经审批（Codex、Claude 支持，表单下方写明当前后端支不支持）。只有你能在 Agent 页打开，档案被助手改时保持不变。

## 技能

**技能**是沉淀下来的做法（`library/_skills/<名>/SKILL.md`，可以带 `references/`），挂到档案上，Agent 需要时去读。

- 说“把这个做法记成技能”，或在 Agent 页的技能区写。
- **内置技能**随 omem 一起来，启动时补进技能库，已有的不覆盖：
  - `lark-messaging`：在飞书里怎么 @ 人、发卡片、加急、只给部分人看；
  - `wiki-writing`：页面和案例页怎么写给人读（开头给答案、样本进表格、不写调查过程），写 Wiki 的角色都挂着它；
  - `desktop-control`：用 ai-auto-desktop 看和操作本机的桌面程序与浏览器（先 `omem setup desktop`；默认只看，动手前先问你，不输入密码）。
- 公司内部系统（工单、报警、发布平台）的用法也写成技能，放在你自己的数据目录里，不进 omem 的代码。

## 选哪个 AI

- 档案和角色里的 AI 是默认值。
- “这次用某个后端、模型和强度做……”只影响这次交办。
- **任务选型**（设置 → AI）：写一段总体偏好和各候选组合适合做什么，主助手每次交办时对照着挑；可以关掉。
- **并行**（设置 → AI）：后台任务总数、每个模型的上限；某个模型满了就换到配置过的其他模型，都满了排队。
- 本机没装某个 Agent 或额度用完，可以借另一台设备上的（见 [多台设备](./devices#借用设备的-agent)）。
