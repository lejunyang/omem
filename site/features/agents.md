# Agent 与技能

omem 不自带模型。理解、调查和写作交给你已经装好的 Agent（Codex、Claude Code、Gemini CLI、Copilot CLI、Qwen Code、Cursor Agent……，任何支持 ACP 的都行），omem 给它们一组工具（检索、读原件、写记忆和事项、发飞书消息……）和一份角色说明。所有写入都经过工具，按空间和角色限定权限，记在运行里。

## 用 API key 运行

不想在这台机器上登录 Codex 或 Claude Code，或者想让一部分任务按 API 计费：设置 → AI → API key 添加 OpenAI 或 Anthropic 的 key，勾选要生成的后端（Codex / Claude Code 的 ACP 和命令行版本）。生成的后端叫 `codex@<编号>`、`claude@<编号>`，在 Agent 页和任务选型里和其他后端一样选；它们的额度、并发和“额度用完”跟本机登录的那个分开算。

key 存在数据目录的 `secrets/ai-keys.json`，不写进配置文件，网页上只显示后 4 位；“检查”按钮发一个不花钱的请求确认 key 能用。删掉提供方时 key 和生成的后端一起删掉。

设置 → AI 另有语音、决策、图片生成三个子页，选好提供方和模型后才启用对应的功能。决策模型可以用 OpenAI、Jev（TypeSafe 或 OpenRouter）、Cloudflare 的 Clef（填 API token 和账号 ID；`clef-flash` 便宜，`clef` 更准，`clef-omni` 还能看图、听音频、看视频），或本机的 StartLux。

## 豆包后端

本机豆包 CLI 用 `doubao-cli` 后端，omem 工具经终端里的 `omem tool` 调用；OpenAPI 用 `doubao` 后端，在云端回答，不能调用本机工具。CLI 按 `doubao` 命令识别，同名命令由哪个发行包安装不影响接入。

豆包的会话保存在账号里。先用 `omem doubao login` 授权 OpenAPI，omem 就能在 CLI 或 OpenAPI 的单次任务结束、失败后删除这次建的会话；聊天会话保留供追问，换成新会话后清理旧的。没有授权或清理失败时，运行里会提示。授权过期且无法刷新时需要重新登录，既有历史不会批量删除。

## 内置角色

omem 自己的每类工作都由一个专门的角色来做，大约三十个：

| 做什么 | 角色 |
| --- | --- |
| 和你对话、交办、协调 | 主助手 |
| 编码与评审 | 编码、功能评审、业务评审、架构评审、历史评审、规范评审、评审负责人 |
| 整理材料 | 材料整理、精读整理、原件定级、归档、归档规则编写、筛选值得关注的群、知识库侦察（`kb-scout`） |
| Wiki | 规划、写作、目录整理、检查 |
| 记忆与事项 | 记忆复核、记忆目录整理、事项维护、做梦、简报、巡检 |
| 复盘与进步 | 档案复盘（`coach`）、夜间复盘评判（`replay-judge`） |
| 飞书访客 | 访客把关（`gatekeeper`）、回答访客（`guest`） |
| 学习 | 英语陪练、口语评价（`speaking-coach`） |

每个角色在 Agent 页都能：

- **换模型**：选后端、模型和思考强度。把关这类用快的小模型，写作和评审用强的。
- **改说明**：复制一份到你的数据目录（`library/_roles`）再改。omem 更新后，角色说明有变化时可以恢复源码版，或三方合并，冲突交给 AI 处理（`omem roles`）。
- **挂技能、加专属记忆**：评审这类内置角色也一样。挂上或去掉技能（以及增减工具）不会复制角色说明，只单独记一份“在哪个版本上加了什么”，omem 更新后角色照常用新说明，不用你合并。
- **完全访问**：命令不进后端的沙箱、不经审批，比如让和你对话的主助手跑要联网的命令行时不用一条条等审批。只对你自己的运行生效（你的对话、后台任务）；别的用户、访客不受影响，规则里的运行看规则上的开关，访客另在 设置 → 渠道 → 访客提问 里设。

## 自建档案

**档案**（`library/_agents/*.md`）是一个专门的处理者：做什么、用哪些技能和工具、默认后端和模型。

- 说“建一个负责报警分析的 Agent”，或在 Agent 页点 + 新建，按表单填。
- `/as 档案 任务` 把一件事交给它；规则、盯群、插件、多机器人都能指定档案。
- 纠正它的话记成它的专属记忆，每晚复盘提出改进建议（见 [学习与进步](./learning)）。
- 专门跑命令行排查的档案可以打开“完全访问”：命令不进后端的沙箱、不经审批（Codex、Claude、TraeX 支持，表单下方写明当前后端支不支持）。只有你能在 Agent 页打开，档案被助手改时保持不变。

## 命令规则

有些命令会改敏感数据，你想让 Agent 执行之前先问一声，而且不只是它直接敲的命令，它写的脚本（Shell、Python、Node）里调用的也算。在 **设置 → 安全 → 命令规则** 里写：

- **命令名**和**参数模式**（正则，留空表示任何参数），如 `acmectl` + `^(deploy|delete)\b`；
- **动作**：需要审批、一律拒绝，或放行（在更宽的规则前开口子）。从上到下匹配，第一条命中的生效；
- **审批人**：你自己、某个 omem 用户、某个飞书用户，或由运行从你给的名单里提名；
- 命令等审批多久（默认 90 秒）、批准的有效期、批准一次是只放行一次还是有效期内都放行，以及给审批人看的说明。

Agent 执行受保护的命令时，审批人收到一张飞书卡片（完整命令、目录、哪次运行发起的、Agent 写的原因），网页首页“等你回答”里也能批。等待期内批准，命令接着执行；没等到，命令以退出码 126 返回，批准后 omem 唤醒那次运行，让它原样重跑。每次放行、审批、拒绝都记在运行记录和审计日志里。

它管的是经 PATH 查找的调用：用绝对路径调用、Agent 自己改 PATH、直接调命令背后的接口都拦不住，Windows 上不经 shell 的 `.exe` 调用也拦不住。它防误操作和“默认路径”，不是对付有意绕过的 Agent；真正要保护的凭据不要放在 Agent 能读到的地方。设计和边界见仓库里的 `docs/v2/command-gate.md`。

## 技能

**技能**是沉淀下来的做法（`library/_skills/<名>/SKILL.md`，可以带 `references/`），挂到档案上，Agent 需要时去读。

- 说“把这个做法记成技能”，或在 Agent 页的技能区写。
- **内置技能**随 omem 一起来，启动时补进技能库，已有的不覆盖：
  - `lark-messaging`：在飞书里怎么 @ 人、发卡片、加急、只给部分人看；
  - `wiki-writing`：页面和案例页怎么写给人读（开头给答案、样本进表格、不写调查过程），写 Wiki 的角色都挂着它；
  - `desktop-control`：用 ai-auto-desktop 看和操作本机的桌面程序与浏览器（先 `omem setup desktop`；默认只看，动手前先问你，不输入密码）。
- 公司内部系统（工单、报警、发布平台）的用法也写成技能，放在你自己的数据目录里，不进 omem 的代码。

## 选哪个 AI

- 档案和角色里的 AI 是默认值。
- “这次用某个后端、模型和强度做……”只影响这次交办。
- **任务选型**（设置 → AI）：写一段总体偏好和各候选组合适合做什么，主助手每次交办时对照着挑；可以关掉。
- **运行前自动选**（同一处）：没指定 AI 的运行在开始前从候选里挑一个。和助手的对话（新开会话时选，会话延续期间不换）、规则交给的 Agent、交办和后台任务分别设“不选 / 有决策模型时选 / 总是选”；配了决策模型时一两秒选完，“总是选”在没有决策模型时让通用模型挑。快用完、刚出过故障、到了每天上限的候选不拿出来选。规则里指定的 AI、对话里 /model 选的不会被换。每次运行的详情里都有一行“自动选 AI：……”或“没有自动选 AI：……”，写着选了谁、谁选的、理由，或者为什么没选（关着、没有候选、没有决策模型、点名了 AI）。
- **出故障换后端**：后端崩溃、断开、长时间没反应，或者上游模型的回复中途断掉（“stream disconnected”“empty stream”“RST_STREAM”这类）时，这次运行或对话换到下一个后端接着做，它会知道上一个已经发过、写过什么。崩溃的后端 15 分钟内排到最后；同一个模型 15 分钟内上游出错两次、或在服务端排队超过上限，这个模型 15 分钟内排到最后。
- **点名的 AI 不可用时**（设置 → AI → 任务选型）：规则指定、交办时选的、你指定的 AI 先用、只用它；它排队超时、限流、额度用完或出故障时，默认换到兜底和候选接着做，运行里写“原指定的 AI（…）……，改用 …”；也可以设成“不换，直接失败”。
- **并行**（设置 → AI）：后台任务总数、每个模型的上限；某个模型满了就换到配置过的其他模型，都满了排队。有的后端按模型限每天的次数、又不告诉还剩多少：给这个模型填“每天最多”，omem 按自己记的当天（你的时区）在它上面开始的运行数算，到了就不再自动选它，直到第二天。后端报“今日额度用完”这类错误时，只避开这一个模型到第二天。
- **账号额度**（同一处）：本机登录的 Codex、Claude Code 账号还剩多少套餐额度（5 小时、每周、按模型），几分钟读一次，不耗额度。快用完的账号排到最后，后台任务先用别的，助手交办时也看得到：阈值有两个，“任一窗口用到多少 % 以上”（默认 90）和“周额度剩余 ÷ 距重置天数 低于每天多少 %”（默认不看）。你发起的对话不受影响。
- 本机没装某个 Agent 或额度用完，可以借另一台设备上的（见 [多台设备](./devices#借用设备的-agent)）。
