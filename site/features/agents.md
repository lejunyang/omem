# Agent 与技能

omem 不自带模型。理解、调查和写作交给你已经装好的 Agent（Codex、Claude Code、Gemini CLI、Copilot CLI、Qwen Code、Cursor Agent……，任何支持 ACP 的都行），omem 给它们一组工具（检索、读原件、写记忆和事项、发飞书消息……）和一份角色说明。所有写入都经过工具，按空间和角色限定权限，记在运行里。

## 用 API key 运行

不想在这台机器上登录 Codex 或 Claude Code，或者想让一部分任务按 API 计费：设置 → 后端与模型 → API key 添加 OpenAI 或 Anthropic 的 key，勾选要生成的后端（Codex / Claude Code 的 ACP 和命令行版本）。生成的后端叫 `codex@<编号>`、`claude@<编号>`，在 Agent 页和任务选型里和其他后端一样选；它们的额度、并发和“额度用完”跟本机登录的那个分开算。

key 存在数据目录的 `secrets/ai-keys.json`，不写进配置文件，网页上只显示后 4 位；“检查”按钮发一个不花钱的请求确认 key 能用。删掉提供方时 key 和生成的后端一起删掉。

设置 → 后端与模型 另有语音、决策、图片生成三个子页，选好提供方和模型后才启用对应的功能。决策模型可以用 OpenAI、Jev（TypeSafe 或 OpenRouter）、Cloudflare 的 Clef（填 API token 和账号 ID；`clef-flash` 便宜，`clef` 更准，`clef-omni` 还能看图、听音频、看视频），或本机的 StartLux。

决策可以配置多个模型，用上移、下移调整顺序，选择“按顺序”或“每次随机选一个”。不可用、拒答或出错自动换下一个，刚调用出错的 5 分钟内排到最后；每项显示状态，判断记录写实际回答的模型和换用情况。

巡检、盯群、有人找你和直接答复分别有最低把握：不够确定就多看一眼、提醒你或先等你拍板，设置 → 后端与模型 → 决策可以修改四项门槛。下面的报告按后续结果统计漏看、多看，并给出只读建议；盯群和直接答复目前只记录，暂不标注结果。想比较其他模型，可以用 `omem decision replay --scene triage --model <提供方ID>:<模型>` 重答保存的材料，不会改写记录或设置。

决策模型也用于[巡检预筛](./collaboration#事件自动触发)：新材料和关注、等待中的事项无关时，不启动助手；跳过的材料定期完整补看。在 设置 → 定时任务 点开“巡检”那一行可改开关和补看间隔。

## 限定后端的网络环境

设置 → 后端与模型 → 通用，点开一个后端，在“网络条件”里添加。设了以后，这个后端只在出口符合要求时用；同一个账号的 ACP 和命令行默认一起勾上，走同一个网络的几个后端也可以共用一条。没设的后端什么网络下都用。

- **用 TUN**：“怎么连出去”选跟随系统路由，“看哪块网卡”选 TUN 的网卡：网卡消失或关闭（Linux 看 IFF_UP）时立刻停下。
- **用代理**：填 HTTP / HTTPS 代理地址。出口检测走这个代理，后端通过 `HTTP_PROXY` / `HTTPS_PROXY` 用它；代理连不上时不会改成直连。
- **出口要求**：填检测地址，选 Cloudflare Trace（读 `ip` / `loc`）或 JSON（自己指定字段）。检测地址用模型接口那个站点的，比如 Claude 用 `https://claude.ai/cdn-cgi/trace`，查到的就是模型请求的出口。地区和 IP 可以只填一项，都填时两项都要满足。

什么时候查：用这个后端之前查一次出口，结果默认一小时内有效，过期后等下次要用再查，空闲时不查。有运行在用时每两秒看一次网卡和代理端口：网卡没了、地址变了（不指定网卡时只看实体网卡的 IPv4，容器、虚拟机网卡和轮换的 IPv6 临时地址不算）、代理端口拒绝连接，立刻停下；端口没响应、检测地址没回应要连着两次才停。

出口不对时默认停下正在跑的，按兜底顺序换别的后端，也可以改成“正在跑的继续，新的不用它”。都换不了时运行失败并写明原因，已经做的保留。网络恢复后连续两次查到出口正常才恢复。改条件（包括改名）只会重新查，不打断正在跑的。模型检测、额度读取和借给别的设备的 ACP 同样受它管；别的设备上的后端在那台设备上设。

**也查 IPv6 出口**：检测地址的域名有 IPv6 地址时，从每个地址（最多四个）各查一次出口，地区或 IP 不对同样停下。这台机器没有 IPv6 出口、或域名没有 IPv6 地址时只看 IPv4，状态里写一句。系统 DNS 查不到 IPv6 地址时依次问 Google、Cloudflare 的 DoH（走代理时经代理问），高级里可以换掉或清空；本地域名不会发给它们。结果按 TTL 缓存，限流时按 `Retry-After` 退避。

**检查 DNS 设置**：列出系统用的 DNS 服务器（Linux 用 `resolvectl`，macOS 用 `scutil`，Windows 用 PowerShell），填了预期列表时指出列表外的；填了 Mihomo 的生成配置时检查内置 DNS、TCP / UDP 53 接管和 strict-route。有问题列在状态里，不拦运行。

这些检查用 Node 自带的 HTTP(S)、TLS 和 DNS 做，Windows 上不用装 curl 或 dig。配置在 `agents.networkPolicies`。

<Shot src="ai-network-conditions" caption="点开后端：默认模型、适合做什么、网络条件和用量" />

TUN 里换节点不一定改变网卡，最晚到出口结果过期才发现出口变了。要在 TUN 断掉的那一刻就不让请求直连出去，得在代理或系统防火墙里限制出站。

## 豆包后端

本机豆包 CLI 用 `doubao-cli` 后端，omem 工具经终端里的 `omem tool` 调用；OpenAPI 用 `doubao` 后端，在云端回答，不能调用本机工具。CLI 按 `doubao` 命令识别，同名命令由哪个发行包安装不影响接入。

豆包的会话保存在账号里。先用 `omem doubao login` 授权 OpenAPI，omem 就能在 CLI 或 OpenAPI 的单次任务结束、失败后删除这次建的会话；聊天会话保留供追问，换成新会话后清理旧的。没有授权或清理失败时，运行里会提示。授权过期且无法刷新时需要重新登录，既有历史不会批量删除。

后端会话清理连续失败 12 次后停止自动重试，并在本机保留失败时间和原因。本人可用 `GET /api/agents/session-cleanup/failures` 查看记录。恢复后端配置或授权后，向 `POST /api/agents/session-cleanup/retry` 提交该条记录的 `backendKey` 和 `sessionId`，宿主从下一次清理扫描起重新尝试。

## 内置角色

omem 自己的每类工作都由一个专门的角色来做，大约三十个。每个角色的页面上可以选默认 AI、MCP 服务和 **omem 工具**：点“按分组选择”，勾分组名是整组、展开后逐个勾，整组里取消一个就是排除它。你的加减单独记着，角色正文继续跟着 omem 更新；角色交结果用的工具去不掉，回答访客的两个角色只用自带的只读工具。

| 做什么 | 角色 |
| --- | --- |
| 和你对话、交办、协调 | 主助手 |
| 编码与评审 | 编码、功能评审、业务评审、架构评审、历史评审、规范评审、评审负责人 |
| 整理材料 | 材料整理、精读整理、原件定级、归档、归档规则编写、筛选值得关注的群、知识库侦察（`kb-scout`） |
| Wiki | 规划、写作、目录整理、检查 |
| 记忆与事项 | 记忆复核、记忆目录整理、事项维护、做梦、简报、巡检 |
| 复盘与进步 | 档案复盘（`coach`）、夜间复盘评判（`replay-judge`） |
| 飞书访客 | 访客把关（`gatekeeper`）、回答访客（`guest`） |
| 学习 | 英语陪练（插件 `english-tutor`，也评价口语对话） |

每个角色在 Agent 页都能：

- **换模型**：选后端、模型和思考强度。把关这类用快的小模型，写作和评审用强的。
- **改说明**：复制一份到你的数据目录（`library/_roles`）再改。omem 更新后，角色说明有变化时可以恢复源码版，或三方合并，冲突交给 AI 处理（`omem roles`）。
- **挂技能、加专属记忆**：评审这类内置角色也一样。挂上或去掉技能（以及增减工具）不会复制角色说明，只单独记一份“在哪个版本上加了什么”，omem 更新后角色照常用新说明，不用你合并。
- **完全访问**：命令不进后端的沙箱、不经审批，比如让和你对话的主助手跑要联网的命令行时不用一条条等审批。只对你自己的运行生效（你的对话、后台任务）；别的用户、访客不受影响，规则里的运行看规则上的开关，访客另在 设置 → 代你回复 → 访客提问 里设。

## 自建档案

**档案**（`library/_agents/*.md`）是一个专门的处理者：做什么、用哪些技能和工具、默认后端和模型。

- 说“建一个负责报警分析的 Agent”，或在 Agent 页点 + 新建，按表单填。
- 工具按分组选：整组（这个分组以后加的工具自动带上）、整组里排除某个、或只勾几个；面板底下显示的 `group:read`、`-write_page` 就是档案文件里的写法。不选时用默认的只读工具。
- `/as 档案 任务` 把一件事交给它；规则、盯群、插件、多机器人都能指定档案。
- 纠正它的话记成它的专属记忆，每晚复盘提出改进建议（见 [学习与进步](./learning)）。
- 专门跑命令行排查的档案可以打开“完全访问”：命令不进后端的沙箱、不经审批（Codex、Claude、TraeX 支持，表单下方写明当前后端支不支持）。只有你能在 Agent 页打开，档案被助手改时保持不变。

## 同时核对几份材料

可以让主助手同时核对几份独立材料。例如让它分别核查两张清单的数量和来源，要求各自给出原件与行号。主助手分头派出后会先告诉你工作已经开始。必选报告收齐后，它逐块验收，有疑点的块可以换模型补查，最多重做两次。最后的汇总会说明每个结论来自哪一块。中途可以问进度，也可以让助手取消其中一块或整组。

## MCP 服务

在 Agent 页切到 **MCP 服务**，点“添加”：填名称，选择命令（参数一行一个）或网址，写一句说明。命令需要的环境变量、网址需要的请求头按“名称 + 值”添加；值单独存为密钥，保存后只显示“已设置”，点“改”才能重新填。勾“只读”表示只查不写，夜间复盘只会用标为只读的服务。

点“检测”连接服务并列出工具名和说明；失败显示原因，最多等 20 秒。列表显示哪些档案和内置角色还在用它，删除前会再次列出；删除后这些档案和角色不再获得这个服务。

配置一次后，在档案表单或内置角色卡片的 **MCP 服务** 中勾选。档案文件用 `mcpServers: [docs-search]` 保存名称；旧文件里的内联 `mcp:` 继续保留，表单只显示其名称和“写在档案文件里”。内置角色的选择单独保存，不必自定义角色正文。

只有你自己的运行带这些服务，访客、其他成员的运行和评审不带；回答访客和访客把关角色不能挂载。密钥的值不会返回网页。

## 操作规则

有些操作会改敏感数据，你想让 Agent 做之前先问一声，而且不只是它直接敲的命令，它写的脚本（Shell、Python、Node）里调用的也算。在 **设置 → 安全 → 操作规则** 里一行一条，从上到下第一条命中的生效，都没命中就放行：

![操作规则：按生效顺序一行一条，点开是编辑；下面是规则包](/screens/security-rules.png)

- **匹配什么**（四种）：**命令**（可执行文件名，可加子命令如 `mr create`、按位置的参数正则、整串参数的正则）；**文件**（读 / 写 / 删 / 改名和路径正则，Agent 自己来请求许可时生效）；**工具**（omem 工具名和参数里某个字段的正则）；**HTTP**（主机、方法、路径和请求体字段）。HTTP 规则在 Agent 用 aad 操作的浏览器里生效：页面的请求发出前先问，拒绝的不发，要批准的等你在卡片上点了、Agent 重做那一步才发出去（要带请求闸门的 aad 版本）。不经这个浏览器发出的请求——命令行里的 curl、别的程序——这类规则管不到。
- **怎么处理**：放行（在更宽的规则前开口子）、拒绝、要批准、只记录。要批准时选**谁来批**（你自己、某个 omem 用户、某个飞书用户，或由运行从你给的名单里提名）和**等多久**（默认 90 秒）。
- **对谁生效**：成员、角色或档案、空间、后端，都不选就是所有人。
- 每行有开关和上移 / 下移；改完点底部的“保存”，整份一起存。存不进去的（比如正则写错了）原因写在那一行下面。

Agent 执行受保护的命令时，审批人收到一张飞书卡片（目标摘要、目录、哪次运行发起的、Agent 写的原因），网页首页“等你回答”里也能批。卡片上可选只这一次、这次运行里的同类操作、以后按这条规则放行；交给其他人审批时，对方只能批准一次。等待期内批准，命令接着执行；没等到，命令以退出码 126 返回，批准后 omem 唤醒那次运行，让它原样重跑。每次放行、审批、拒绝都记在运行记录和审计日志里。

**规则包**：插件或技能可以带一组现成的规则（比如某个命令行工具的写操作清单），列在操作规则下面。启用时选好范围，包里的规则才加进上面的清单（带包名的小标签，匹配内容只读，范围和开关可以改）；包更新了会列出新增、去掉和改了的规则，你点“换成新版”才换；停用后这些规则从清单里去掉。

它管的是经 PATH 查找的调用：用绝对路径调用、Agent 自己改 PATH、直接调命令背后的接口都拦不住，Windows 上不经 shell 的 `.exe` 调用也拦不住。它防误操作和“默认路径”，不是对付有意绕过的 Agent；真正要保护的凭据不要放在 Agent 能读到的地方。设计和边界见仓库里的 `docs/v2/command-gate.md`。

**记录**：同一页最下面的“记录”把这些事按时间列出来，最新的在前：规则拦下、问过或放行了什么命令、文件和工具，是哪条规则、谁批准的；以你的身份发出了什么（代你回复、拉人进群、会议里的回答）；成员、登录、分享和连接的变动。可以只看其中一类，点一行看当时记下的原样内容和那次运行。能管成员的人也看得到这张卡，原样内容只有你自己能看。

### 本机登录的文件系统隔离

Linux 上，本人可从 `GET /api/security/sandbox` 查看 bubblewrap 是否可用、默认可写目录和各后端要更新的状态目录。同一地址的 PUT 保存设置。网页入口待接入。以下设置会隐藏 SSH 目录。

```json
{"mode":"prefer","writable":[],"hidden":["~/.ssh"],"fullAccess":"sandboxed"}
```

`prefer` 能隔离就用，不能用时运行会说明原因。`require` 要求每次本地启动都能隔离。`off` 是默认值。本人 HOME 默认可读，额外保密的目录写入 `hidden`。需要项目外的写权限时，把已有目录加进 `writable`。评审的原工作区只读，本轮快照可以跑测试。

`sandboxed` 只在进入本人沙箱后统一启用后端完全访问，包含只读角色和访客。成员借本机登录仍按角色选模式。`per-role` 沿用原来的单项开关。`all` 为本人的可写角色统一启用完全访问，保存时另传 `confirmAll: true`。此时未隔离的运行也能写宿主文件。

### 成员沙箱的出网权限

Linux 成员运行开启严格隔离后，命令行工具通过本机代理访问网络。本人用 `GET /api/security/egress` 查看支持情况和最近运行访问的主机，用同一地址的 PUT 保存配置。默认只管严格运行，`all-sandboxed` 扩展到所有成员沙箱，`off` 关闭。设备代跑不经过这台机器。

普通 HTTPS 只能看到主机。默认放行未命中规则的公共主机，回环和内网需要明确的规则。要审批未知主机，把 `default` 设为 `approve`。有路径规则又看不到路径时，`tunnelWhenUnsure` 决定放行并记录、审批或拒绝。

只有列进 `inspect` 的域名才解密。沙箱信任本机生成的专用根证书，代理能看到这些请求的明文，钉证书的客户端会连接失败。请只列需要按路径控制的域名。

## 技能

**技能**是沉淀下来的做法（`library/_skills/<名>/SKILL.md`，可以带 `references/`），挂到档案上，Agent 需要时去读。

- 说“把这个做法记成技能”，或在 Agent 页的技能区写。
- **内置技能**随 omem 一起来，启动时补进技能库；你没改过的会跟着 omem 更新成新版，改过的不覆盖：
  - `lark-messaging`：在飞书里怎么 @ 人、发卡片、加急、只给部分人看；
  - `wiki-writing`：页面和案例页怎么写给人读（开头给答案、样本进表格、不写调查过程），写 Wiki 的角色都挂着它；
  - `research`：先查库、再查外部并核对来源，报告开头给结论；
  - `improve-loop`：按度量逐轮改进目标，留下有效的改动，停滞时换方向或交回；
  - `desktop-control`：用 ai-auto-desktop 看和操作本机的桌面程序与浏览器（先 `omem setup desktop`；默认只看，动手前先问你，不输入密码）。浏览器用长期保留的资料（一个账号一份，登录过就不用再登），做通的网页操作会存成技能和脚本，下次直接跑。
- 公司内部系统（工单、报警、发布平台）的用法也写成技能，放在你自己的数据目录里，不进 omem 的代码。

### 调研一个问题

给一个 Agent 档案加 `traits: [research]`，保留读工具（如 `search`、`scan`、`read_source`、`read_page`、`recall`），挂载 `research` 技能，再从 Agent 页选择一个或多个 MCP 服务；网页搜索服务标为“只读”，夜间复盘 R3 才能使用。`traits` 可以在档案原文的 frontmatter 里填写。技能不授予工具，档案要有相应的工具和服务。

它先拆出要查清的小问题，库里先查，再用档案的 MCP 搜索外部材料；另一模型的云端调研报告也只算一个来源，出处照样核对。事实交叉核对后，报告开头给结论和建议，缺证据的列明缺什么。

内部名字、未公开数字和代码不得放进外部查询；查外面时改用通用说法。内部搜索平台或另一模型云端调研的具体接法写成技能，放在自己的数据目录 `library/_skills/`，挂到档案上，不进公开仓库。

### 晚上逐轮改进一个指标

挂 `improve-loop` 技能，给出可度量的目标（例如构建产物大小或测试用时）。先定完成条件、不许动的范围和预算，跑一次基线；每轮只做一个有依据的改动，没有变好就回退，留下的走评审。连续两轮没有变好换方向，四轮停滞交回本人，预算用完停在最好的一版。工作文件记下每轮结果，唤醒后接着做；报告给基线到现在的数字、保留和回退的改动、还差什么。

### 技能草稿由复盘试用

启用夜间复盘并给 `replay-judge` 选模型后，K1 会为最近的问题挑匹配的技能草稿或待处理技能提案，只给变体追加正文。默认累计两胜且胜多于负后启用，发一条稍后合并投递的通知；两负无胜的提案被拒绝，草稿仍保留。Agent 页显示“复盘 N 胜 M 负”和“复盘后自动启用”，可在技能里删除，或从档案卸下挂载。设置 → 自检与复盘 → 夜间复盘可调整门槛，设为 0 只试用。有胜场但尚未达门槛的提案不按年龄过期；已有选轴计划不迁移，可恢复默认或加入 K1。

不想要某个技能，在技能页点“停用”：它变回草稿，不再出现在任何 Agent 的技能里，复盘也不会再试用、再启用它；点“启用”恢复。

### 接管 Agent 自带的技能

有的命令行工具会往 Claude Code、Codex、TraeX 的技能目录（`~/.claude/skills`、`~/.agents/skills`、`~/.trae/skills`）里一次装进几百个技能。这样每个 Agent 都带着全部技能的说明，命令行会把说明截短，模型也就分不清该读哪个。

在 Agent 页 → 技能，不选中任何技能时右边有“Agent 自带的技能”。可以先点“看看会收哪些”预览，再打开接管，命令行是 `omem skills take-over --on`：

- 这些技能会移进 omem 的技能库，原件留一份备份，“撤销最近一次”能把它们放回原处。
- 技能按名称前缀归组，凑不成组的放进 `other`。各 Agent 的技能目录里只剩 omem 的使用说明和每组一个**总入口**：Agent 平时只看到“这一组是做什么的”这一句，用到时先读总入口，再按用途找到具体技能、读它的全文。
- 工具升级时又装回来的技能，每 10 分钟收一次。新版本会替换旧版本，分组、用途和开关保持不变。

左侧技能列表最上面是“技能分组”，按 分组 → 用途 → 技能 三层展开，没分组的技能列在下面。点一个分组，右边按用途分节列出它的技能：可以改这一组的说明（Agent 靠这句话判断什么时候该读它）、单个停用或整组停用，每个技能的“移动”可以换分组或用途。从分组点进一个技能后，顶上的分组名可以回到原处，浏览器的后退也行。

**自动整理**（面板上的“自动整理分组”，默认打开）：新收进来的技能、上游更新后说明变了的技能，以及你自己的技能里没分组的攒到 8 个以上时，等几分钟没有新变化，就交给后台的技能整理角色。它会对照现有分组和用途把这些技能放好，必要时新建分组、补写说明，做完发一条通知，写明移动了哪些。你手动移动过的技能、改过的分组说明，它不会再动。分组页的“让助手整理”会让它重新看一遍整组。omem 自己的运行同样按组给出这些技能，停用的不会出现。

## 选哪个 AI

- 档案和角色里的 AI 是默认值。
- “这次用某个后端、模型和强度做……”只影响这次交办。
- **任务选型**（设置 → 后端与模型 → 任务选型）：写一段总体偏好；每个后端点开后写它适合做什么，还可以给其中几个模型各写一句（不再按强度分），写了的就是候选。主助手每次交办时对照着挑；可以关掉。
- **运行前自动选**（同一处）：没指定 AI 的运行在开始前从候选里挑一个。和助手的对话（新开会话时选，会话延续期间不换）、规则交给的 Agent、交办和后台任务分别设“不选 / 有决策模型时选 / 总是选”；配了决策模型时一两秒选完，“总是选”在没有决策模型时让通用模型挑。快用完、刚出过故障、到了每天上限的候选不拿出来选。规则里指定的 AI、对话里 /model 选的不会被换。每次运行的详情里都有一行“自动选 AI：……”或“没有自动选 AI：……”，写着选了谁、谁选的、理由，或者为什么没选（关着、没有候选、没有决策模型、点名了 AI）。
- **出故障换后端**：后端崩溃、断开、长时间没反应，或者上游模型的回复中途断掉（“stream disconnected”“empty stream”“RST_STREAM”这类）时，这次运行或对话换到下一个后端接着做，它会知道上一个已经发过、写过什么。崩溃的后端 15 分钟内排到最后；同一个模型 15 分钟内上游出错两次、或在服务端排队超过上限，这个模型 15 分钟内排到最后。
- **换谁、按什么顺序**：额度快用完时排到后面、出故障后接手、点名的 AI 用不了时回退，都参考任务选型里的总体偏好和候选说明。运行前选 AI 时，决策模型不只选一个，而是把所有选项排好先后，这次运行要换就按这个顺序；没经过选择的运行在第一次要换时问一次决策模型，同类运行十分钟内沿用这个顺序，不会每次出错都再问。没有决策模型时按 设置 → 后端与模型 → 排队与兜底 中的顺序。运行里换后端的那一行写着顺序来自哪里（决策模型按选型说明，或设置里的静态顺序）。
- **点名的 AI 不可用时**（设置 → 后端与模型 → 任务选型）：规则指定、交办时选的、你指定的 AI 先用、只用它；它排队超时、限流、额度用完或出故障时，默认换到兜底和候选接着做，运行里写“原指定的 AI（…）……，改用 …”；也可以设成“不换，直接失败”。
- **并行**（设置 → 后端与模型 → 并行）：后台任务总数、对话总数、每个模型默认的上限；点开某个后端，在“用量”里设整个账号和单个模型的上限，不想自动用的设 0。某个模型满了就换到配置过的其他模型，都满了排队。有的后端按模型限每天的次数、又不告诉还剩多少：给这个模型填“每天最多”，omem 按自己记的当天（你的时区）在它上面开始的运行数算，到了就不再自动选它，直到第二天。后端报“今日额度用完”这类错误时，只避开这一个模型到第二天。
- **账号额度**（点开后端看“用量”）：本机登录的 Codex、Claude Code 账号还剩多少套餐额度（5 小时、每周、按模型），几分钟读一次，不耗额度。快用完的账号排到最后，后台任务先用别的，助手交办时也看得到：阈值有两个，“任一窗口用到多少 % 以上”（默认 90）和“周额度剩余 ÷ 距重置天数 低于每天多少 %”（默认不看），默认值在 并行 里设，单个账号可以另设。你发起的对话不受影响。
- 本机没装某个 Agent 或额度用完，可以借另一台设备上的（见 [多台设备](./devices#借用设备的-agent)）。
