# 记忆与事项

## 记忆

<Shot src="memory" caption="记忆按目录分层，每条带类型、复核状态和来源" />

记忆是事实、约定、决定、人物、偏好和经验，每条都引用原件。

- **版本链**：被更正时不覆盖，旧版本标记为“已被更正”并链接到新版本。“之前怎么约定的”和“现在是什么”都能回答。
- **目录**：每条记忆在空间里有一个目录（最多三层）。助理按目录说明选目录，拿不准的先放“未归档”，之后由整理目录的运行归档，每周再看一遍结构。
- **质量**：写入前有确定性检查（免责式、超长、转述原件、无来源、重复的会被退回，并告诉模型怎么改），之后由复核模型盲评保留、改写或撤回。“记忆 → 质量”按模型比较。
- **不足**：“记忆 → 不足”列出回答没找到、被你纠正、失败的运行、被撤回的记忆，每晚整理时逐条看能不能补。
- **档案专属记忆**：纠正某个 Agent 时（“以后评审先看错误处理”），记成它的专属记忆。

## 事项

<Shot src="items" caption="事项：待办、等待回复和持续关注，详情里有材料、相关依据和时间线" />

事项是待办、提醒、等待回复和持续关注的事。

- **时间线**：每次变化（改期、完成、新消息）都记一条，带来源；通知只带这次变化的来源，错的来源可以撤回并留历史。
- **期限与自动收尾**：待办 14 天、待决定和关注 7 天、等待回复 14 天没有新进展就自动“过期”（不算完成，有新进展会重新打开）。你在来源群里回过话、回了表情的，由助理判断是否已经办了。
- **每日清点**：一张卡片列出自动收尾的和明天过期的，要留下的点“保留”或“恢复”。
- **材料**：大型需求可以建一个事项，把文档、群聊、代码分支、要对照的仓库挂上去；之后的交办和评审会读这些材料，结果也挂回事项。
- **工作文件**：要做好几天的事，助理把当前成果写成工作文件挂在事项上，下次接着做先读它。
