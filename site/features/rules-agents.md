# 规则与 Agent 档案

## 规则

<Shot src="rules" caption="规则：一句话写成条件和动作，能判断的由 omem 直接判断" />

在侧栏“规则”里用一句话说“遇到什么情况就做什么”：

- “报警群里小王发报警卡片时，在卡片下开话题交给 alert-analyst 分析，需要关注就 @ 值班人”
- “值班群里我被 @ 就把机器人拉进去，并优先采集这个群”
- “工作日 18:00 把今天的进展追加到本周周报”

模型把原话写成**条件**（群名、发送人、邮箱、关键词、@ 本人、卡片……）和**动作**（交给 Agent、开话题、拉机器人进群、优先采集、持续监听、通知）。能写成条件的由 omem 直接判断，写不成的请模型按原话判断；保存前可以“用最近的消息试一试”。

值班这类场景可以“等 10 分钟没人回应再处理”“我已在讨论里 / 已有人回复就跳过”，Agent 用“静默排查”：群里看不到过程，有结论才在话题里回复。助理建的规则默认不启用，等你核对。

“交给 Agent”可以打开“指定 AI”，给这条规则选后端、模型和思考强度；不指定就用档案自己的设置。设置里的任务选型只在助手交办时用，规则和定时任务不经过它，所以想让某条规则用某个模型，就在这里指定（写在任务说明里不会生效）。

### 会议规则

触发选“我加入会议时”，例如“我加入标题带‘评审’、三人以上的会议时，问我要不要把机器人拉进去，记录会议，有人问到我时提醒我”：

- 你入会时（用你的 lark-cli 登录发现你入会；没订阅入会事件也行，每分钟查一次）按会议标题、人数、参会人判断。人数有两种：在会人数（入会那一刻在会里的人，不算机器人）和会邀人数（日程邀请了多少人，邀请的群按成员算，入会时就是准的；临时会议没有日程，是未知）。先给你发一张卡片，点“拉进去”才让选中的机器人入会（所有参会人都能看到它）。不拉机器人也可以只以你的身份记录。
- 入会确认可选“始终询问 / 直接加入 / 满足条件时询问”。例如“当我入会时，30 人及以上先发卡片问我，否则直接拉机器人”，一句话生成一条规则；也可以手动填写确认条件。人数未知时先问你，之后人数变化不重新切换方式。“用最近的会议试一试”会显示哪些会议先问、哪些直接加入，不执行动作。
- 也可以不靠规则：在会议里把 omem 的机器人邀请进来（机器人的应用要订阅“机器人被邀请入会”事件）。你邀请的直接入会，同事邀请的先发卡片问你。
- 会上的转写、会中聊天、谁进谁出、共享的文档记成一份会议原件，会后补进妙记，再整理进记忆和事项。
- 选了旁听的 Agent 每几分钟看一次新内容：有人点你的名、要你表态，或出现和你有关的决定、待办、风险时提醒你；会后给你一份简短纪要。也可以让它在会中聊天里回答点名机器人的问题。你离会时机器人一起离开。
- 保存后规则页直接检查飞书权限：lark-cli 的应用和登录、每个机器人的应用缺什么，给出申请或授权链接。会议本身要打开 AI 纪要和“允许智能体加入”。机器人拿到的是文字事件，不能在会上说话。

## 盯群

临时有事时，在群里 @ 机器人说“帮我盯一下这个群，有人问接口进度就帮我回”，或把群分享给助理（机器人不在群里时，它用你的身份把机器人拉进去）。之后群里的消息攒成一批交给助理（默认 10 分钟，@ 你或机器人的 30 秒内），整个群在一个上下文里看：多数消息不管，能回答、值得排查或你需要知道时才动手，独立的话题可以交给别的 Agent 单独做。节奏它自己调，到期（默认 3 天）自动停，规则页“正在盯的群”里能看到和取消。

## Agent 档案与技能

<Shot src="agents" caption="Agent：内置角色和自定义档案，每个选后端、模型和思考强度" />

- **档案**是一个专门的处理者：做什么、用哪些技能和工具、默认后端和模型。说“建一个负责代码评审的 Agent”，或在“Agent”页新建；`/as 名称 任务` 交给它。
- **内置角色**（编码、各评审项、整理、Wiki 写作……）也能自定义，omem 更新后可以合并或恢复源码版本（`omem roles`）。
- **技能**是沉淀下来的做法（`library/_skills/<名>/SKILL.md`），可以挂到档案上。说“把这个做法记成技能”。
- **内置技能**：随 omem 一起来的（`lark-messaging`、`desktop-control`、`wiki-writing`……），启动时补进技能库，已有的不覆盖。`wiki-writing` 规定页面和案例页怎么写给人读：开头给答案，样本进表格，不写调查过程，写 Wiki 的角色都挂着它，想改写法直接在技能页改。`desktop-control` 教 Agent 用 ai-auto-desktop 看和操作本机的桌面程序与浏览器：先 `omem setup desktop` 装好；默认只看，动手前先问你，不输入密码。
- **复盘**：每晚复盘有纠正、失败或收到表情的档案，提示词和技能的改动提成建议，等你采纳；建议 14 天没处理会过期，过期前两天提醒一次。Agent 页首屏按档案和模型统计飞书里收到的表情。
- **多 Agent 协作**：长任务用独立会话（飞书话题），每轮交回报告后由主助手接手，决定继续、汇报或请你决定；Agent 之间可以互相请教。

## 夜间复盘

换一条信息路径把旧问题再答一次，看清记忆、原件级别、Wiki 和模型到底帮没帮上忙。

- **先选评判**：在 Agent 页打开内置角色 `replay-judge`，选一个模型（最好和主助手不同家）。没选之前夜间复盘不运行，设置页和 Agent 页都会提示。
- **打开**：设置 → Agent → 夜间复盘，打开每天 4:30 的定时，设每晚几题（默认 1 题，没有 token 上限）。题型、每种信号先试哪个轴、模型阶梯都能在这里改。
- **怎么做**：挑最近被你纠正、说没找到、加了表情或正常完成的问题，回到提问的时候（那时的记忆、聊天和原件，之后才有的看不到）重答两次：一次设置不变，一次只改一处——深检索、加空间、交给研究档案（档案里写 `traits: [research]`）、只看重点原件或连忽略的一起看、去掉记忆、不看页面、模型降或升一档。两份回答先过引用检查（引用了提问之后的东西就作废），再由 `replay-judge` 两种顺序各评一次，一致才算胜负。
- **结论用在哪**：误导的记忆送回复核，帮上忙的记一次；误导的页面排一次检查；把原件降为“仅检索”、改回“一般关注”、建事项导入缺的材料这类建议，在早上 9:30 的事项清点卡片（“昨晚复盘”一节）或 Agent 页采纳 / 忽略。模型对比只作为 `list_ai_backends` 里的 `replay28d` 参考，不会自动换模型。
- **手动**：`omem replay run --run <运行id> [--axis M1]` 复盘某一次回答，`omem replay` 看结论。

## AI 的选择

档案里的 AI 是默认值。“这次用某个后端、模型和强度做……”只影响这次交办；设置 → Agent → 并行里设各模型的并发上限，某个满了就换到配置过的其他模型。
