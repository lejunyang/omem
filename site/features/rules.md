# 规则

<Shot src="rules" caption="规则：一句话写成条件和动作，能判断的由 omem 直接判断" />

规则是“遇到什么就做什么”。在侧栏“规则”里用一句话说：

- “报警群里小王发报警卡片时，在卡片下开话题交给 alert-analyst 分析，需要关注就 @ 值班人”
- “值班群里我被 @ 就把机器人拉进去，并优先采集这个群”
- “工作日 18:00 把今天的进展追加到本周周报”
- “我加入标题带‘评审’的会议时，问我要不要把机器人拉进去”

## 一句话变成条件和动作

模型把原话写成：

- **触发**：新消息、被 @、入群、卡片、我加入会议、定时巡检。
- **条件**：群名、成员、发送人、邮箱、关键词、@ 本人、卡片……写不成条件的部分交给 AI 按原话判断；AI 判断的规则跑一阵后可以“固化”成确定性条件。
- **动作**：交给某个 Agent、开话题、拉机器人进群、转发到别的群或某人、优先采集、持续监听、通知或 @ 值班人。

能写成条件的由 omem 直接判断，不花模型。要模型判断的部分，可以选“决策模型优先”（默认：设置 → 后端与模型 → 决策 配了决策模型时用它，快、便宜，只给是 / 否）或“通用模型”（读完规则和讨论再判断，会写理由）。保存前可以“用最近的消息试一试”，看哪些会命中。助理替你建的规则默认不启用；回答之后出现确认卡片，核对后点“启用规则”立即生效，网页状态同步更新。规则改过后需要核对新内容，旧卡片不能直接启用。也可以在规则页启用。

## 核对规则有没有动静

每条规则下方写近 7 天和 30 天触发多少次、安静结束多少次。发过消息或通知你的不算安静。周报把触发够多、却大多安静的规则列出来，附最近两次安静的理由，不会替你改规则。复查确认问题没恢复，又没有安排后续时，助手会给你一条遵守免打扰的普通提醒。

助手替你改规则、技能、关注或档案时，打开“通知”可看改动前后、保留或撤回。同一份设置在汇总前连续改动时合在一条；你后来自己改过的内容不会被旧对照覆盖。

## 所属空间

每条规则有一个所属空间，或者是“全局”。列表里每条规则下面写着它属于哪里；在编辑页“所属空间”里随时可以改。所属空间决定规则看哪里：消息规则只看这个空间的会话，文档变化只看这个空间的文档，对象状态变化只看这个空间的事项，会议记录放进这个空间；交给 Agent 时，它默认在这个空间里查资料。全局规则不限空间，所以在每个空间的规则列表里都会出现，不是重复。

## 别人在处理时不插手

值班这类场景：

- **等一等**：“等 10 分钟没人回应再处理”。
- **跳过**：“我已在讨论里 / 已有人回复就跳过”。
- **静默排查**：Agent 在后台读完讨论，自己决定要不要发、要不要追问缺的信息，有结论才在话题里回复，之后跟进那个话题；你一插话它就停。
- 有人直接 @ 机器人时规则让开，由机器人直接回答。
- **处理中再次触发时并入同一会话**（默认勾上）：同一条规则在同一个群里复用 Agent 会话。可选“合并回复”（默认），把后续触发交给当前一轮一起下结论；或“每次触发分别回复”，按顺序逐条完成任务、分别答复，前面的调查可以复用。关掉则各自使用独立会话，可以并行。

## 加急与只给部分人看

说“P0 报警加急值班的小王”“超时的工单只发给提单人看”，交给 Agent 的动作会勾上“允许加急”或“允许只给部分人看”，什么情况、对谁写在任务里。不勾的规则，Agent 用不了这两种发法。

## 指定 AI

“交给 Agent”可以打开“指定 AI”，给这条规则选后端、模型和思考强度；不指定就用档案自己的设置，并按 设置 → 后端与模型 → 任务选型 的“运行前自动选”：配了决策模型时（默认）它在开始前从候选里挑一个更合适的，选不出就用档案的；后端额度用完、出故障时换兜底接着做。想让某条规则一直用某个模型就在这里指定，指定的不会被别的选择换掉；只有它排队超时、限流、额度用完或出故障时，按 设置 → 后端与模型 → 任务选型 的“点名的 AI 不可用时”换兜底（默认换，运行里写明原指定的是谁、为什么换），也可以设成不换。

## 转发到

“新消息”规则可以把触发的消息转发到别的群，或转给某个人：在“转发到”里选目标（列的是采集过的群和私聊），可加一句附言。来源可以是群，也可以是私聊，包括机器人私聊你的消息，比如某个通知机器人发给你的提醒，条件写“会话类型是私聊、发送人包含它的名字”。

- 目标是群：机器人发过去，带上来源、发送人和时间；群里还没有 omem 的机器人时，先用你的身份把它拉进去。
- 目标是某人的私聊：机器人不能在私聊里发言，第一次转发时用你的身份建一个你、对方和机器人的群，之后都发到这个群。

### 等一条消息再转：比如有人要验证码

“等某个会话的新消息”让规则先等，等到了再接着做：触发后每 10 秒读一次你选的会话（比如验证码机器人私聊你的那个），最多等你设的分钟数，只认触发之后、符合“包含的词”或正则的第一条；没等到就通知你，或者什么都不做。后面接“转发到 · 回到触发的会话”，就把等到的这条发回给提问的人：群里回复在那条消息下，私聊就用你的身份建一个你、对方和机器人的群发进去。

比如：新消息、勾“快速检查”，条件写“（私聊，或群里 @ 了我）且正文包含 验证码，且发送人是人”，动作“等「验证码机器人」的新消息，5 分钟，包含 验证码”，再“转发到 · 回到触发的会话”。最好再按发送人或群名限定范围，不然谁问都会拿到验证码。

平常的采集要隔一阵（常驻服务器上是 10 分钟）才读到私聊和没有机器人的群。规则勾上“快速检查（每分钟）”后，omem 每分钟用你的身份搜一次群里 @ 你和私聊里的新消息，搜的词就是条件里“正文包含”的词，所以要请求最多晚 1 分钟被看到。

转发目标由你指定：在规则页选，或在对话里直接说，比如在值班群里对助手说“以后虚拟号通知私聊我的消息都转到这个群”。只有在回答你自己消息的那一轮，助手才能新加或改转发目标；唤醒、别人的消息或它自己整理规则时改不了。

## 完全访问

报警、值班这类要跑联网命令行的规则，可以在“交给 Agent”里打开“完全访问：命令不进沙箱、不经审批”。默认关着：Codex 在只读沙箱里联网的命令要一条条审批，审批偶尔会卡几分钟，规则就会报失败。打开后，Codex 用 `agent-full-access`，Claude 用 `bypassPermissions`，TraeX 用 `bypass_permissions`，命令行兜底后端加对应参数；没有这类模式的后端照旧，运行里会写明。运行页“使用 AI”那行带“完全访问”。交给别的 Agent 时也照此运行。

omem 每次调用工具仍检查空间和权限，命令垫片仍执行操作规则。启用本人的 Linux 沙箱以后，命令能写哪些目录由 omem 的挂载决定。默认的 `per-role` 使用规则原有开关；统一开关的用法见[本机登录的文件系统隔离](./agents#本机登录的文件系统隔离)。只有你能在规则页打开完全访问。

## 以成员的身份运行

有些事要用每个人自己的账号做，比如每周五查每个人在研发平台上的合并请求写周报。“交给 Agent”里选“以谁的身份运行”，挑几位成员。保存后机器人会问每个人同不同意：规则是在群里设的就在那个群里 @ 他问，不然私聊问；没有 omem 账号、不能用助手或没关联飞书的人直接标“用不了”并写原因。

运行时还是一次运行，助手依次换成每个同意了的人：插件登记过的命令行（比如研发平台的）用他的登录、在他的账号环境里跑，飞书个人工具用他的连接读写。他自己的文件可直接写，其他文件和任务由机器人私聊请他批准。写入会记在运行和审计里，群消息仍由机器人发。缺少飞书登录时 omem 提醒成员授权，本次跳过。每个人的状态（已同意、等他同意、没同意、撤回了）写在规则页，可以“再问一次”。成员在自己的“账号”页能看到哪些规则用他的身份，随时撤回。

## 会议规则

触发选“会议”：你入会时，或 omem 的机器人所在的群里有人发起会议时（你不在会上也算）；按会议标题、人数、参会人、在哪个群判断，先问你要不要拉机器人入会，记录会议、旁听提醒、会后纪要。详见 [会议](./lark-meetings)。

## 文档变化

触发选“文档变化”，贴上要盯的飞书文档、电子表格、多维表格或知识库页面的链接（一行一个）。有人编辑、改了多维表格的记录或字段、在评论里 @ 了机器人时触发；连续的编辑合成一次。条件可以按修改人、改了什么、@ 了谁（包括你和机器人）、文档标题和所在的知识库目录写。

电子表格按行比：订阅时先存一份各工作表的内容（每行写成“列名：值”），之后每次有人改，就和上一份比对，每个新增或改动的行单独触发一次，条件里能用工作表名、行号、新增还是改动；只改了格式、没有哪一行变了时不触发。同样内容的行只触发一次。表头改了的工作表重新存一份，这次不触发。很大的表只比对前 2000 行。多维表格同样按记录逐条触发，字段写成字段名和可读的值。

条件“是本人改的 · 不是”可以把你自己的改动排除掉。交给 Agent 时可以选“发到”某个群（和定时规则一样）：Agent 能在那个群里直接回复，也能先在群的聊天记录里找到对应的那条消息，回复在它下面并 @ 表格的修改人。Agent 用 `lark_write` 回写这张表引起的改动，不会再次触发同一条规则。

在群里对助手说“这个群……”建规则时，条件里的“这个群”就是说话的那个群，结果也默认发回这个群。

飞书只把编辑和表格变化发给文档的管理者：保存后规则页检查一遍，订阅不了的改为按“订阅不了时每隔多久查一次”（默认 30 分钟）用你的登录查更新，改过就读出改了什么再触发；要即时，在文档右上角“…”→“添加文档应用”把 omem 的机器人加进来。文档被重新读后照常交给整理，只想读到最新内容的，把这篇设为“仅检索”。omem 每天也会为已经采集的飞书文档订阅一批，订阅上的改了就重新读，不用等定时检查。

## 对象状态变化

事项上挂的合并请求这类平台对象（由启用的插件提供）变了状态时触发。触发选“对象状态变化”，在“哪种对象”里选类型，在“变成”里勾关心的状态（不勾是任何状态），比如“合并请求 → 已关闭”：没合并就被关掉时通知你。第一次挂上时读到的状态不算变化；只看你能读的空间里的事项，选了所属空间就只看这个空间的。条件可以按对象标题、原来的状态、关联事项写；动作和文档变化一样，可以交给 Agent、通知你、延时、AI 判断或执行脚本。

状态没变、对象却有了新东西（合并请求推了新提交、有人回了评论）叫“有更新”：在“哪些变化”里勾“有更新（状态没变）”，比如让助手在别人的合并请求有新提交时复审一遍。插件带回调的，在 设置 → 插件 的插件卡上“生成地址”，把地址填进平台的 webhook，平台一有变化 omem 就去读，不用等定时检查。

## omem 里发生的事

omem 自己的事也能触发规则：运行结束或失败、评审结束、交办应用或丢弃、提问被回答或失效、事项新建或改了状态、流程阶段变了、插件发了信号。触发选“omem 里发生的事”，勾关心的几种，条件里可以按运行类型、档案、新状态、事项、流程和阶段细分，比如“评审结束、结论要改时告诉我”。动作和文档变化一样。这种规则起的运行结束时不会再叫醒这种规则，同一件事在同一个状态上十分钟内只算一次。

## 延时、AI 判断和脚本

“做什么”里还有三种：

- **延时**：后面的动作过一阵再做，例如“半小时后提醒我看看”。
- **模型判断**：写一个问题（“这次改动涉及上线时间吗？”），AI 看事件和前面的结果回答是或否，否就不做后面的。
- **执行脚本**：在运行 omem 的这台机器上执行你写的 Node、Python 或 Bash 脚本，触发的事件以 JSON 交给它（环境变量 `OMEM_EVENT` 和标准输入）。默认执行前机器人私聊你一张卡片，写着规则、事件和脚本，点“执行”才执行；也可以交给指定的人批准，或让 AI 从事件里找出审批人（比如改文档的人）。只有你本人能保存带脚本的规则，脚本拿不到 omem 的密钥。

## 预查和先看一眼

群里报的问题很多跑一两条固定的查询、看一眼就能答，不用每次都让 Agent 从头查。

- **预查**：你存好的只读脚本（Node、Python 或 Bash），可以写一个正则，消息匹配才跑，正则取到的值（比如 UID）交给脚本。只有你能存、改、删；助手发现同一类消息每次都先跑同样几条查询时，会把代码发给你，问要不要存成预查，你点“保存”才存。规则里可以单独放一个“预查”动作，它的输出和“执行脚本”的输出会交给后面的动作（交给 Agent 的任务、模型判断、通知和转发的正文）。
- **先看一眼**：交给 Agent 的动作打开“先看一眼”、选几个预查后，触发时先跑预查，再由一个快模型（便宜、低思考强度）在 90 秒内看消息和预查结果：答得了就直接答，要你定就只告诉你，答不了才交给原来的 Agent 深查，深查的任务里带着预查输出和快模型的结论。
- **第一条发到哪**：群里、私聊你、或群里只有你看得到的卡片（默认私聊，设置里可改，每条规则也能单独选）。只有规则的回复方式是“直接回复”时才真的发在群里，否则改成只有你看得到的卡片，卡片上点“发给大家”才以机器人身份发出去；要深查时第一条写着还在查什么，点“不用查了”就停下深查，深查的结论发到同一个地方。

关注也有同样的三项，打开后不用等攒批的时间，一来消息先看一眼。详见 [docs/v2/first-look.md](https://github.com/lejunyang/omem/blob/main/docs/v2/first-look.md)。

## 归档规则

“规则 → 归档规则”是另一类：按标题、正文、网址或路径、采集渠道、知识库目录设条件，把同类材料自动放进对应空间。见 [原件与空间](./sources#归档规则)。
