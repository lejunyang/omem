# omem 是什么

**omem 是一个跑在你自己机器上的个人与团队助理。** 它深度接入飞书，把日常散落在各处的**聊天消息、云文档、会议妙记和代码仓库**收进同一个本地知识库：带着原文行号回答问题、记住约定并在被纠正时保留演变历史、围绕工作线持续跟进事项；派给它的任务由多个专职 Agent 接力完成，编码交办则有六个维度的独立评审把关。

它**不自带也不绑定大模型**——理解、调查和写作交给你已经安装的 Agent（Claude Code、Codex、Gemini CLI、豆包、Cursor 等 25+ 种），omem 负责存储、索引、调度、安全沙箱和权限边界。

## 它和别的工具哪里不一样

市面上不缺“本地知识库（RAG）”“聊天机器人”或“AI 编程助手”，但它们各自只解决半截问题。omem 的设计从一开始就针对真实工作里的断层：

| 常见痛点 | 普通工具的做法 | omem 的做法 |
| --- | --- | --- |
| **材料散在各处** | 文档放知识库、代码在 IDE、讨论留聊天群，互不相通 | **统一原件体系**：飞书聊天、文档、会议、网页和 Git 代码都在同一个库里，一次提问同时对齐三处材料，指出哪份文档已过时 |
| **AI 回答不敢信** | 给一段综合摘要，或者只附上整篇文档的标题链接 | **行级精确溯源**：每句结论、每条记忆、每页 Wiki 都链到原文具体行号（`src:<id>#L起-L止`），点开直接在侧栏高亮原话或代码行 |
| **知识越存越乱、越存越旧** | 记忆被新说法直接覆盖；生成的文档没人维护很快就废了 | **版本链 + 自动化质检**：记忆被纠正时保留旧版并指向新版（过去和现在都能答）；Wiki 写完先由核对角色逐条查验，原件变了自动巡检改写 |
| **机器人只会一问一答** | 你问一句它答一句，说完就忘，不会主动跟进后续 | **工作线与流程推进**：随口说的事自动记成事项，挂进工作线；群里有新进展或你推了代码，助手核实依据后自动推进流程阶段，观察期满自动收尾 |
| **AI 写代码没人把关** | 在你电脑上改一堆文件，需要你全程盯着看 diff | **常驻机器交办 + 六维评审**：在独立 Git worktree 里按修改项（T1、T2…）开发，功能、业务、架构、历史、规范、精简六个角色换不同模型交叉审，谁提的问题谁验收 |
| **换个工具就要重配一套** | 绑定单一模型厂商，或者在宿主里写死冗长的提示词 | **轻量宿主 + 开放 Agent**：宿主只管数据、索引、调度和权限；30+ 内置角色用短 Markdown 定义，可按任务自动选型、管额度、跨设备借用算力 |

## 核心设计：四层结构

理解 omem 只需要记住四个词：**空间、原件、派生知识、Agent**。

```text
文件 / 代码仓库 / 网页 / 飞书文档 / 群聊与私聊 / 会议妙记
                      │  保存、只读采集
                      ▼
  ┌──────────────────────────────────────────────────────┐
  │ 空间（Space）：按项目、代码仓库、个人、学习隔离领域      │
  │  ├─ 原件（Source）：只读事实依据（全文 FTS + 向量 + 符号）│
  │  ├─ Wiki（Git）：按读者问题组织的 Markdown 页面          │
  │  ├─ 记忆（Memory）：带有效期、版本链与目录树的事实/经验   │
  │  └─ 事项（Item）：工作线、待办、等待、关注（带变化台账）   │
  └───────────────────────────┬──────────────────────────┘
                        omem 工具（MCP / CLI）
                              │  按用户、空间与角色校验权限
                              ▼
         Agent：Codex / Claude Code / Gemini CLI / 豆包 …
                              │
         回答 · Wiki 页面 · 记忆 · 事项推进 · 代码改动与评审
```

1. **原件（Sources）是唯一的事实依据**：一份文档、一个群的聊天记录、一个代码文件、一场会议。文档和代码只保留最新版，聊天按追加保存，删除留墓碑。所有外部输入都只当作材料，不当作指令。
2. **空间（Spaces）隔离领域**：个人、项目、代码仓库、学习各自建空间。代码仓库可以挂在所属的业务空间下，互相调用的仓库或同项目的空间关联起来后，检索和交办会自动覆盖相关空间。
3. **派生知识全部指回原件**：
   - **Wiki**：存在 Git 仓库里的 Markdown 页面，按用户会问的问题组织，每次修改都有提交历史和差异。
   - **记忆**：提炼出的事实、约定、决定、人物、偏好和经验，按三层目录归档，更正时保留版本链。
   - **事项与工作线**：要跟进到收尾的事，所有渠道看到的变化通过幂等台账记在时间线上。
4. **Agent 负责理解与写作，omem 负责工具与边界**：omem 通过 ACP（Agent Client Protocol）或命令行启动你装好的 Agent，按角色注入 MCP 工具。模型没有直接写数据库的权限，每次写入都经过工具层校验空间与身份，并完整记录在运行（Run）里。
