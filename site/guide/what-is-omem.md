# omem 是什么

omem 是一个跑在你自己机器上的个人知识库和助理。它把文档、代码、聊天、笔记放进同一个库，用你已经安装的 Agent（Codex、Claude Code、Gemini CLI 等）来理解和写作，自己负责存储、索引、调度和权限。

## 几个基本概念

**原件**是依据：一份文档、一个群的聊天、一个代码文件、一个网页。原件只保留最新版，聊天按追加保存，删除留墓碑。

**空间**把领域分开：个人、项目、代码仓库、学习、通用。检索默认在当前空间和它的相关空间里，互相调用的仓库、同一项目的几个空间可以关联起来。

**派生知识**都引用原件：

- **Wiki** 是 Markdown 页面，整个知识库是一个 Git 仓库，每次修改都有历史；
- **记忆**是事实、约定、决定、人物和偏好，被更正时保留版本链；
- **事项**是待办、等待回复和持续关注的事，有时间线和期限。

**Agent** 做理解和写作。omem 通过 ACP（Agent Client Protocol）或命令行调用它们，给它们一组 MCP 工具（检索、读原件、写记忆和事项……），所有写入都经过工具，按空间和角色限定权限，记录在运行里。

```text
文件 / 代码仓库 / 网页 / 飞书文档 / 聊天
            │  保存、采集
            ▼
   原件 + 索引（全文 / 向量）      记忆      事项      Wiki（Git）
            └──────────────┬──────────────────────────────┘
                     omem 工具（MCP）
                           │
           Agent：Codex / Claude Code / Gemini CLI …
                           │
          回答 · 页面 · 记忆 · 事项 · 代码改动（都引用原件）
```

## 适合做什么

| 想做的事 | 怎么做 |
| --- | --- |
| 之后问“之前怎么约定的 / 有什么变化 / 依据在哪” | 保存材料，助理整理成记忆和事项，问答里引用到原文行 |
| 读懂一个陌生项目 | 建代码仓库空间，生成 Wiki，或直接问 |
| 平时说的计划、承诺、在等谁回复 | 不用说“记住”，助理回答时顺手记下，在回答末尾列出 |
| 交办编码、看差异和评审 | “在 xx 仓库实现……”，运行页分概览、变更、评审、活动 |
| 评审同事的需求分支 | “帮我评审 shop-api 的 feature/refund” |
| 合并 main、变基、解决冲突、推送 | 交办时选同步方式，冲突先交给编码 Agent |
| 遇到某类消息就做某事 | 规则：一句话说“遇到什么就做什么” |
| 一台机器常驻，别的电脑查看 | 配对后诊断、拉数据、远程检查 |
