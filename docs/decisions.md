# 最后集中确认的事项

当前方案已基于下列默认值完整设计，没有因这些问题暂停文档与原型。你的答案主要影响部署、首批连接器和自动化边界，随后可以按答案调整方案再进入实现。

| 待确认 | 当前建议/默认 | 会影响什么 |
| --- | --- | --- |
| 首批主要服务谁：你个人，还是已经有多人/多 Agent 共用？ | 个人起步，数据结构保留团队/租户 | 登录、权限细粒度、部署复杂度；不需要首版就做完整组织平台 |
| 运行位置与模型：长期服务器/本机？可用哪些 LLM、embedding、reranker？ | 可控 Linux 服务器；模型走可替换接口，支持自托管；不默认把资料发到外部服务 | 资源、吞吐、费用、响应时间；已有资源会大幅影响选型 |
| 首批真实材料和 Agent 接入优先级？ | 飞书文档/Wiki + Git/Markdown + Trae/Codex 等任务轨迹；先选一个宿主跑闭环 | 最先做的 2–3 个 connector、任务验证样本 |
| 自治边界是否接受：普通有证据变更自动应用，扩大范围/批量硬删/全局行为规则才集中问？ | 接受该模式；待判断超时不当同意 | policy 默认值、通知频率、可执行 Skill 发布边界 |
| 可接受的运行预算和通知节奏？ | P0 测资源与 token 后定日预算；普通变化合并摘要，重要冲突单独提示 | 引擎数量、是否本地模型、主动抓取频率、自动学习规模 |

具体可以一次性回答：“个人/团队；部署位置；可用模型；前三个来源/宿主；自治边界和预算”。若你更关心某个业务场景，例如研发全生命周期、个人工作助理或客服经验，首批数据集和原型示例也应换成那个场景。

## 已作出的设计决定，不再逐项询问

- 在 omem 新建，不改旧 agent-knowledge、不搬历史权威标记。
- 证据版本与引用 ID 由 omem 统一管理，框架是能力适配器。
- 引用无限逐层展开，按需取一跳，循环可回跳；旧引用不漂移。
- 保留固定原件和完整历史，普通自动变更可用新的修订恢复。
- 热度/有用性与证据可信度分开，模型生成不自证。
- 主推 WeKnora 文档引擎与 Hindsight 学习引擎 PoC，保留轻量组件替代路线。
- 本次只交付 docs 和离线交互原型；真实后端、旧库迁移、外部发布另属实施阶段。
