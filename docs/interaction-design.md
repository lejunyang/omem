# 交互设计：围绕证据阅读，而不是围绕管理配置

版本 v0.1 · 2026-09-26。直接打开 [交互原型](prototype/index.html)。原型参考用户 HTML 的黑白灰、三栏阅读和层叠引用语言，重做产品信息架构；没有复用其中未经验证的公司政策或外部研究数字。

## 1. 视觉和信息层级

主界面保留暗色顶栏、浅灰目录、接近纸张的阅读区、白色 AI 侧栏。衬线标题建立文档阅读感；正文和导航用清晰的无衬线字体。重点由文字层级、边线和引用样式表达，不用彩色仪表盘争抢注意力。

| Token | 值/原则 |
| --- | --- |
| 主文字 / 次文字 | `#202020` / `#606060` |
| 纸面 / 面板 / 分隔线 | `#fafafa` / `#ffffff` / `#e6e6e6` |
| 主动作 | `#242424` 背景、白字 |
| 引用 | 浅灰底、深字、细下划线、上标；hover 加深 |
| 标题字体 | Noto Serif CJK SC / Songti / SimSun / Georgia 回退 |
| 正文字体 | Noto Sans CJK SC / PingFang / Microsoft YaHei / system-ui |
| 阅读字号 | 原型可调 14–20px；正式版主正文建议 16px，辅助元信息不承载关键结论 |
| 圆角 | 普通控件 4–7px，证据弹窗 12px |
| 动效 | 仅状态和层级切换的短过渡，尊重 reduced-motion |

普通用户看到材料名称、版本、出处和适用范围；不需要知道“这条结果来自哪个向量库”。引擎和路由只在能力/诊断页面展示。学习进展用具体事件表达，例如“从复盘补充了一条验证步骤”，不以大量未经解释的增长指标代替质量。

## 2. 页面结构

| 页面 | 用户主要任务 | 主内容 | 原型实现 |
| --- | --- | --- | --- |
| 知识阅读 | 找到并读懂一条知识 | 目录、文章、引用、AI | 3 篇文章可切换；引用/圈选/追问 |
| 经验与方法 | 理解 Agent 学到了什么 | 经历→验证→方法；适用条件；待判断项 | 可点开证据；可保持范围/建议补证 |
| 材料来源 | 了解知识从何处来及是否新鲜 | 来源状态、采集范围、同步时间 | 模拟同步状态变化；版本入口 |
| 变更与学习 | 查看为何修改、必要时恢复 | 事件流、before/after、证据、恢复 | 可展开差异；恢复追加记录；localStorage |
| 能力与连接 | 开启所需能力 | 引擎状态、外部 Agent 接入 | 演示引擎启停；明确未接服务 |
| 搜索 | 定位知识/片段/经历 | 混合类型结果、无答案建议 | 本地标题/文本检索、无结果状态 |

正式版可再增加工作区设置、通知中心、诊断控制台；先保证阅读主链不被后台配置打断。

## 3. 引用交互是整个系统的核心

### 默认呈现

引用贴着它支持或指向的句子显示，不只放在文章尾部。角标在当前文章内编号；固定引用 ID 和版本在协议里，不展示难读的 UUID。段落下方可显示“已支持”“存在分歧”“依据待更新”；不要一律盖“可信”章。

点击引用打开居中弹窗，背景文章保持原滚动位置。头部展示证据路径、当前层号、材料标题、原文版本与时间；正文优先显示被引用的句子及必要上下文；底部有返回、复制片段链接、就这段追问。

### 层级与返回

弹窗引用打开下一层；同一个 dialog 容器仅切换当前材料，避免无限创建 DOM 和焦点陷阱。上一层用露出标题条表示，路径面包屑保留全部访问历史；每一层保留滚动位置、当前 tab 和追问草稿。返回时恢复这些状态，关闭全部后焦点回到起始引用。

深路径面包屑可横向浏览；正式版在小屏或超过 8 层时加“查看完整路径”的列表，列表按需渲染。原型用可滚动完整面包屑验证 100 层，不将 100 层设为产品上限。

“无限分层”的边界：没有固定业务层数限制；当前材料没有引用就显示末端；路径遇到环就提示已访问层并可跳回；重复 ID 不继续压栈。服务端每次只返回一跳，权限和预算对每次读取独立生效。

### 四个证据视图

- **引用片段**：突出被引用的原文；清楚标识明确引用、提炼、支持、历史等关系。
- **上下文**：展开原段落/页面附近内容，防止断章取义；大文档按块分页。
- **谁引用了它**：反向引用列表，显示直接引用者；点入仍可继续导航，遇环提示。
- **版本**：固定历史版和现行版差异，明确“打开新版本”动作；绝不悄悄用新正文替换旧引用。

## 4. 追问保持原来的阅读位置

正文右侧问答适合文章问题；弹窗里的“就这段追问”在当前弹窗内展开局部问答，整个路径不关闭。选中原文出现轻量“追问选中内容”；按钮可以在 dialog 的顶层正常点击。键盘/触屏无法方便圈选时，底部就这段追问始终可用。

每个追问显示固定的材料和选区。默认范围为本段+直接依据，可选择当前路径或授权知识库；切换范围不改变焦点原文。长链路径只是导航历史，不自动无限扩充模型输入。

问答内容分流式正文、待核对引用、已解析引用、证据不足说明。回答里的引用可以继续打开；再返回，原问答历史仍在。每个节点的局部会话隔离，防止看 A 时把 B 的草稿和回答误当 A 的依据。

“沉淀为候选”创建带原始 evidence refs 的候选，后台按普通风险策略自动验证并决定是否应用；生成回答不直接变为独立证据。原型会模拟候选记录，明确未执行真实模型验证。

## 5. 自动变更和例外

首屏不是一排待审批卡。Agent 完成常规更新后进入变更流，用户能看到触发原因、被改内容、受影响引用和操作主体。变更流默认按 ChangeSet 聚合，不为每个底层片段创建一条噪声通知。

恢复先显示具体 before/after 与影响范围，再执行为新修订；如果后续有人编辑过，则需要重新合并，不提供无条件回退。已物理删除/已外发动作不显示可以完全恢复的承诺。

例外队列按需出现：冲突的两份证据、超范围的泛化建议、批量/不可逆动作。每条都给出 Agent 已尝试的补证、可选动作和当前保持的状态。用户可以暂缓，不因超时自动同意。

通知频率建议：常规整理只写事件，重要源变化合并通知，待判断形成摘要。正式默认频率由用户确认；原型没有发送任何外部通知。

## 6. 边界状态与无障碍

| 场景 | 界面回应 | 不能做什么 |
| --- | --- | --- |
| 材料首次导入中 | 原件可读，显示正在解析/整理及阶段 | 用空白页掩盖已保存数据 |
| 原文暂无权限 | 根据存在性权限显示通用不可用或申请访问 | 泄露标题、片段或关联计数 |
| 已删除 | tombstone 与允许展示的删除时间 | 以缓存还原被删除内容 |
| 上游暂不可用 | 有权限快照+上次同步时间，重试入口 | 声称快照是最新版本 |
| 原文更新 | 旧引用固定，显式提示新版本 | 自动跳转导致历史答案无法核对 |
| 锚点/OCR 不可靠 | 显示无法精确定位，可查看原件 | 高亮近似文本并标作精确证据 |
| 搜索无结果 | 说明范围、给关键词或补证建议 | 伪造一条看似可信的答案 |
| 模型失败/取消 | 保留问题与选区，停止生成，可重试 | 把半成品回答记为成功知识 |
| 引擎停用 | 保持原件和引用可读，显示能力降级 | 删除权威数据或清空阅读内容 |

键盘 Tab 保留在活动 dialog；Esc 返回一层；关闭全部回到起始元素；所有引用可聚焦。状态含文本，不能只靠颜色。生产目标 WCAG 2.2 AA；原型验证了 native dialog 和主要键盘路径，但尚未做完整读屏、对比度自动审计。移动端引用全屏，右侧问答改抽屉/内嵌区域，点击区域正式版按 ≥44px 验收。

## 7. 推荐体验顺序

1. 打开首页，点击“回滚方案、负责人和验证结果必须到位”。
2. 沿“操作手册→发布复盘→验证轨迹→代码→测试→健康指标→原始记录”查看 8 层。
3. 在任一层点击“就这段追问”，发一个问题，再点击回答中的引用。
4. 回到复盘，点击“复盘关联发布规范”，观察循环处理。
5. 打开 r6 引用，切到版本页，对比现行 r7。
6. 在左侧“体验引用边界”测试 100 层、无权限、删除、定位失效。
7. 打开“变更与学习”，查看差异并恢复，刷新后验证演示历史仍保留。

这条体验路径同时是 P1 前端验收脚本；原型的浏览器自动检查覆盖主要动作，结果见 [验证说明](validation.md)。
