# omem 要做成什么，现在做到哪里

omem 是一个先记得住、再帮你办事的个人助手。文档、代码、聊天、图片都进入同一份材料库。代码多一层 AST 帮助定位函数和依赖；Code Wiki、回答和学习卡都是从材料生成的内容，不各自建一份事实库。

可以用四个日常场景理解它：

| 你做什么 | 助手应该做什么 | 本轮进展 |
| --- | --- | --- |
| 问“这个函数为什么这样写？” | 找到代码、相关设计说明、决定和测试，给出能逐层打开的引用 | 保留统一引用链；检索已融合原文、记忆和 Wiki，补齐跨段引用；精确跨文件调用仍未实现 |
| 中文问一份英文资料 | 换同义词或英文搜索，再回到原文作答 | 已真实验证：中文问熔断阈值，找到英文原文中的 7 次和 41 秒 |
| 说“10 月 2 日上午 9 点提醒我复习英语”，随后改期、说完成 | 记录明确时间，改同一个事项，完成后不再提醒 | 创建→改期→完成已真实验证；当前为站内一次性提醒，重复安排和外部到期发送未接通 |
| 某篇说明从“重试 3 次”改成“5 次” | 停用旧结论，重新分析新材料，独立复核后更新原记忆，保留旧历史 | 已用真实 GPT-5.6-sol 验证同 ID 从 3 次更新为 5 次；旧原文保留，不能只排队就算完成 |

材料之间可以互相引用，阅读时可以一直往下看。检索和模型每次处理多少内容另设预算；不能为了控制模型开销限制你打开引用的层数。

接下来仍有三块实质工作：

- **更强召回**：当前是 FTS5/BM25、中文短词、记忆/Wiki 路由和一次模型补搜；还没有 embedding 与语义重排。沿用已有调研中的可替换检索提供方，不迁移原件和事实存储。
- **更主动跟进**：当前有来源变更触发的重核验和到期站内提醒；等待别人回复、临近截止追踪、周期治理和外部提醒仍要逐项接入。
- **英语学习**：学习材料沿用 Capture，卡片引用固定原文；卡片内容与复习进度分开。调度复用已调研的 FSRS，导出采用稳定 omem ID 的 Anki 文本格式。卡片、评分和复习页面目前尚未实现，也不会拿普通待办冒充间隔重复。

下面是此前的详细调研档案，基线为 `94aafe9`。它解释为什么选这些机制；实际能力以 [当前实施进度](../implementation/status.md) 和代码为准。
