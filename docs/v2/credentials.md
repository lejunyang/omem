# 凭据：每人一次授权、出借、缺权限时找谁

状态：第一期已实现（2026-11-22）。成员通过 HTTP 管理凭据和出借范围。后台负责供给、续签、提醒和 AI 后端选择。第二期已接入命令结果识别、权限记录、预检和查询。缺少本地登录时，支持实时授权核验的插件可在出借人环境里执行只读命令。分期见文末，做到哪一步记在 `docs/v2/status.md`。相关：[成员的 AI 账号](agent-accounts.md)（每人一个账号目录、沙箱、插件登录方式）、[操作规则与命令垫片](command-gate.md)、[多人](multi-user.md)。

## 要解决的事

omem 给一个团队用以后，Agent 跑的命令行工具（公司内部的命令行、代码托管、数据库查询……）需要“是谁在调用”：

- 成员发起的运行应该用成员自己的身份。插件可以在他的账号目录里为多个后端和命令行准备同一份授权。
- 一个人往往要登好几样东西。很多环境里它们认同一个根凭据，应该授权一次就都能用，过期了有人提醒。
- 发起人没有权限的资源，团队里可能有人有。现在只会让本人去申请。

## 概念

**凭据种类**：由插件登记（`api.credential`），说明怎么登录、怎么续签、怎么检查、供给哪些 AI 后端和命令行、怎么认出命令失败的原因。宿主不认识任何具体的系统，只按声明办事。

**持有**：某个人对某种凭据的一份登录。成员的放在他的账号目录里（`accounts/<用户>/home`，见成员的 AI 账号）；本人的就是本机已有的登录，不复制。状态：没登录 / 有效 / 快到期 / 过期 / 登录中。

**出借设置**（每份持有一个，持有人自己定）：只给自己用 / 给指定的成员 / 给所有成员。成员默认只给自己；本人的默认给所有成员。

**出借方式**（管理员定，`credentials.lending`）：

| 值 | 含义 |
| --- | --- |
| `auto`（默认） | 按各人的出借设置直接借，不再问 |
| `confirm` | 不直接借：每次要用别人的凭据时，先问持有人，他同意才用（见“确认”）；出借设置在这一档表示“可以来问我”的范围 |
| `off` | 不借也不问，只用自己的；没有就提示登录或申请权限 |

**成员的 AI 后端用谁的登录**（管理员定，已有的 `agents.accounts`，补一个全局默认 `agents.accountsDefault`）：可以借（按上面的出借）/ 必须自己登录 / 自己没登录就换一个他登录过的后端。

## 插件登记一种凭据

```ts
api.credential({
  id: "corp",                       // 全名 <插件>:corp
  name: "公司账号",
  describe: "一次授权，供给 acme 命令行和 ×× 后端",
  required: true,                   // 接入清单里标成必做
  login(ctx, show): Promise<{ user: string; expiresAt?: number }>,   // show({ url, code? })：给这个人看的授权链接
  refresh?(ctx): Promise<{ expiresAt?: number } | null>,              // null：续不了，要重新登录
  check?(ctx): Promise<{ state: "ok" | "expired" | "missing"; user?: string; expiresAt?: number }>,  // 只读
  logout?(ctx): Promise<void>,
  provide?(ctx): Promise<void>,     // 登录和每次续签后调用：把凭据写到这个人账号目录里各工具认的位置
  provides: {
    backends: ["somebackend"],      // 这些 AI 后端的登录由它负责（等价于现在的 agentLogin）
    commands: [{
      name: "acme",                 // 可执行文件名
      install: ["~/.local/share/acme"],        // 只读挂进成员沙箱的安装目录
      state: [".local/share/acme/data"],       // 它要写的状态目录（相对 HOME）
      readOnly: [{ subcommand: ["db", "query"] }, { subcommand: ["log", "search"] }],   // 算只读的调用，匹配写法同操作规则的命令匹配
      resource: [{ match: { subcommand: ["db", "query"] }, key: "db:{option.instance}" }], // 这次调用碰的是哪个资源
      outcomes: {                   // 失败时怎么认原因；按顺序匹配，都不中算普通失败
        unauthenticated: [{ json: "$.code", equals: "AUTH_REQUIRED" }],
        expired: [{ json: "$.details.status", equals: "refresh_failed" }],
        denied: [{ json: "$.status_code", equals: 403 }],
        applyUrl: "$.details.apply_urls[0]",
      },
    }],
  },
  precheck?(ctx, req: { resource: string; user: string; command?: { name: string; args: readonly string[] } }): Promise<{ allowed: boolean | null; verifiedRead?: true; missing?: string; applyUrl?: string }>,
});
```

- `ctx` 同插件登录方式的上下文：`userId`、`home`、展开后的 `env`、按人保存的 `secret`、`signal`。回调在 omem 进程里执行，只读写这个人的账号目录和 `secret`。
- 清单声明 `permissions.credential: true`，本人信任插件并选“在 omem 里运行”才生效。声明里的 `install`、`state`、匹配规则都进信任指纹。
- 已有的 `api.agentLogin` 继续可用；新的插件用 `api.credential`，一种凭据供给多个对象。
- 宿主按 `expiresAt` 在到期前续签（沿用现有的十分钟提前量），续签后调 `provide`；每天对每份持有调一次 `check`。

## 运行时用谁的

发起人 R 的运行要用凭据 K：

1. R 自己的持有有效：用它。
2. 否则找出借给 R 的持有人（本人排最前，其余按最近一次成功使用排）：`auto` 档直接借，`confirm` 档先问。
3. 第一期选择失败时提示登录；策略为 `own-or-other` 时尝试符合条件的后端。后续按需登录的设计为：`agents.accounts` 是“必须自己登录”或没人可借时，给 R 发授权链接（见“什么时候登录”），这次运行等十分钟。

每次借用在运行事件里写一行（借了谁的哪种凭据、为什么），并写 `audit_events`。

**AI 后端的借用**沿用现有做法：整轮运行在出借人的登录下启动（本人的是本机登录，成员的是他的账号目录），所以它只在 `auto` 档、并且出借人把这份持有开放给了 R 时才发生；`confirm` 档不借 AI 后端。

**逐命令借用**在运行令牌标明发起人和命令所在账号相同时生效。R 有有效持有时仍用自己的登录。命令在 R 的账号下返回 `denied`，垫片保留退出码、stdout、stderr，并显示可用的申请链接。三十天内已知 R 无权的资源也走本地。

R 缺少有效持有时，宿主先按运行身份检查操作规则，再匹配可信插件声明的 `readOnly` 和具体资源。仅在 `auto` 档选择把该凭据开放给 R 的有效持有人。已知有该资源权限的人优先，其次是本人，再按最近成功使用排序，跳过已知无权的人。每条调用最多尝试两位出借人。`confirm` 档提示需要持有人确认，`off` 档照常在本地执行。

每次代跑前，宿主用候选人的登录调用预检。插件收到的 `req.user` 来自发起人的运行令牌，`req.command` 是命令名和完整 argv。插件须将该用户映射到资源服务认识的身份，按命令实际语义核对访问的确切资源、操作和返回数据范围，再向资源服务实时确认该用户的读取权。只有同时返回 `allowed: true` 和 `verifiedRead: true` 才会执行。遇到额外选项、多个资源、不可确定的服务端身份或行级可见范围时，插件应省略回执。仅用于查询的插件继续只返回 `allowed`。离线示例插件保留这种方式。

宿主在新建的空目录里，以原 argv 启动命令，标准输入关闭。成员使用账号沙箱，只挂回该命令声明的登录状态目录，按运行的出网规则连接。本人使用本机登录，启用本人沙箱后须在沙箱内运行。要求严格成员隔离或所有成员沙箱隔离出网时，跳过本机登录。运行完成后删除临时目录，垫片直接转交退出码和两个输出流，每个流保留末尾 20,000 字节。预检和命令分别写运行事件和审计；命令结果记在实际执行人的权限记录中。

## 权限记录（第二期）

表 `credential_access`：凭据种类、资源、用户、有 / 没有、什么时候得知、从哪次运行或哪次预检得知。来源是命令的结果（成功记“有”，`denied` 记“没有”）和插件的 `precheck`。记录三十天后算过期，过期的当“不知道”。

- 工具 `who_can(resource)`（只读，`read` 组）：返回已知有权限的成员、最近一次得知的时间、申请链接。助手在动手之前可以先查，回答里可以说“这个库小王能查”。
- 查询支持可选的完整 `kind`。成员只能查自己和向自己开放该种凭据的人，本人能看全部。申请链接取可见范围内最近三十天的拒绝结果。
- 没有可见记录时，按出借设置选最多五位有效持有人，两路并发预检，每次最多二十秒。插件收到的 `req.user` 是被查的人。查询身份优先用发起人自己的有效持有，缺少时仅在 auto 档借用已开放的凭据，本人优先。每次调用把查询身份、被查人、种类和资源写入审计及关联运行事件。超时或返回 `allowed: null` 时保持未知。
- 不用记忆存这些：它们要按人按资源查、会过期、要被宿主拿来做判断，模型不能改写。

## 确认（第三期）

`confirm` 档下要用别人的凭据，或者 `auto` 档下出借人没有开放给 R 但权限记录显示他有权限时，宿主向持有人发一张确认卡：谁、为哪件事、要跑哪条只读命令（原样列出）、碰哪个资源。选项：这一次可以 / 这次任务里都可以（到这轮运行结束）/ 不行。同意后命令在持有人的环境里跑，结果交回 R 的运行；不同意或十分钟没答，R 的运行得到“持有人没同意”，并附申请链接。

卡片发到哪：

1. 请求来自群聊：在**那个群里**发，只有持有人看得见（渠道支持“仅某人可见”的卡片时）。持有人不在群里就先拉进来：先用机器人拉；机器人拉不了、并且本人打开了 `credentials.confirm.inviteAsOwner` 时，用本人的身份拉。拉不进来，或渠道不支持仅某人可见，退到机器人私聊。
2. 请求来自和机器人的私聊或网页：机器人私聊持有人。
3. 两处都同时进持有人在 omem 里“等我的”清单；任一处答了，另一处的卡作废。

以本人身份拉人进群是一条新的以本人身份写飞书的路径：只在这一个场景、目标只限持有人和触发的那个群、每次写 `audit_events` 并在本人的通知里说明；开关默认关。实现时把它加进 AGENTS.md “以本人身份写飞书”的清单。

## 什么时候登录、失效了怎么办

- **用到时**：R 的运行要用 K 而没人可借，机器人把授权链接私聊给 R（群里只说“已私聊你”），运行等十分钟。
- **第一次进来**：成员第一次登录网页或第一次 @ 机器人之后，给一张接入清单：`required` 的凭据标必做，其余可选；每项写清覆盖哪些工具。网页的账号页列出同样的清单，可以登录、重新授权、退出、改出借设置。
- **失效**：续签失败、每天的 `check` 发现过期或三天内到期、运行中命令以 `unauthenticated` / `expired` 失败，都把这份持有标成过期并通知持有人（走成员的通知出口；私聊不到的，在他下次 @ 机器人时先提醒）。这次在本地运行的命令保留原结果。下次调用时按缺少有效持有的条件重新判定。

## 第一期开通的存储与执行

首发迁移一次建立三张表和续签、每日检查、出借排序的索引。凭据声明放在本机 `credential_kinds`，每人每种持有是 `credential_holds` 的唯一键，接入通知标记在 `credential_onboarding`。这三表不随快照同步；秘密仍在密钥库里，回调异常只显示操作失败，不将插件错误原文写入接口或日志。本人持有从只读检查取得，不假设已登录；没有 `check` 的跳过。

成员的 `check` 报告 `missing` 后，对外显示未登录，停止自用、出借和续签。已供给的文件仍归这份凭据管理，旧后端退出接口仍返回 409。在正常的登录周期内，检查再次读到有效登录可以恢复已供给的后端。

整份退出时，宿主删除这份凭据的密钥，按持有记录清理命令和后端的状态目录，保留其他登录共用的路径。只改过出借设置的成员尚未占用任何路径。插件已停用或撤销信任时，两种凭据 DELETE 接口照常清理本地状态，不调用插件的 `logout`。清理完成后保留检查时间；后续检查不再把这些文件算作该凭据供给，单后端退出也不再因它返回 409。

成员登录和续签时，宿主在调用插件前把后端 ID、命令名以及校验过的相对路径并入持有。路径来自命令的 `state` 和后端的 `account.owns`。插件改供其他后端后，原后端的检查与退出仍认这份归属。新后端在登录或续签成功供给后才可自用、出借。续签换目录时保留两次的路径，完整退出时再次校验。这样即使插件自带后端已卸载，仍可删除独占文件、保留其他持有的共用目录。持有的 `provision` 记录历次供给可能写过的范围，`supplied_backends` 记录最近一次成功供给的后端。

同一份持有的登录、续签、检查、退出串行。登录等链接 60 秒、总计 11 分钟；续签检查 2 分钟、退出 20 秒，超时取消后晚到结果不写状态或秘密。状态目录相对 HOME，安装与本人可写目录均经现有沙箱路径校验。声明中不存在的安装目录跳过并在状态列出。

## 第二期已接入的命令结果

运行令牌绑定的发起人和命令所在账号相同时，凭据命令可向本机宿主上报。成功退出且命中资源声明时记“有”。失败输出先按一个 JSON 对象读取，包含日志时逐行取最后一个能解析的对象，再按插件的 outcomes 声明顺序读取 JSON 字段。`denied` 记“没有”，返回可用的申请链接；`unauthenticated` 或 `expired` 将对应持有标成过期，并按第一期的通知设置每天提醒一次。普通失败保留调用方看到的原始结果。

## 接口和设置

- `GET /api/credentials`（自己的持有和清单）、`POST /api/credentials/:kind/login`、`DELETE /api/credentials/:kind`、`PUT /api/credentials/:kind/sharing`；本人另有 `GET /api/credentials/all`（每个成员登了什么、出借给谁，不含凭据）和 `DELETE /api/credentials/:user/:kind`（替成员退出）。
- `:kind` 是完整的 `<插件>:<凭据 id>`。登录返回 `{url, code?}` 或 `{done: true}`，之后从自己的清单读取当前状态。出借设置的请求体为 `{"scope":"self"}`、`{"scope":"all"}` 或 `{"scope":"members","members":["member-a"]}`。成员只能操作自己的凭据。
- 对凭据供给的后端，成员调用 `DELETE /api/me/agent-accounts/:backend` 或本人调用 `DELETE /api/agent-accounts/:user/:backend` 会收到 HTTP 409。响应为 `{error: string}`，逐份列出凭据名称、完整 kind、覆盖的后端和命令，以及当前调用者可用的凭据 DELETE 路径。持有、供给文件、出借和续签保留。调用对应的凭据 DELETE 才会退出整份授权。
- 设置：`credentials.lending`、`credentials.confirm.inviteAsOwner`、`agents.accountsDefault`，都只有本人能改，归“安全”区域。
- 成员沙箱里只读挂载声明过的 `install`；本人沙箱的默认可写清单加上声明过的 `state`。
