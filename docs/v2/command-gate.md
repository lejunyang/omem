# 操作规则与审批

本人通过 `GET /api/security/operation-rules` 读取规则，用 `PUT` 提交完整的 `{ "rules": [...] }`。数组中的顺序就是优先级。第一条已启用、范围和目标都匹配的规则生效。读取结果的 `enforcedBy` 列出执行点，空数组表示目前只有匹配器。

例如，下面的规则把项目 A 中创建合并请求的操作交给本人审批。查看合并请求仍走原来的执行流程。

```json
{
  "id": "acme-mr-create",
  "revision": 1,
  "enabled": true,
  "title": "在项目 A 创建合并请求",
  "scope": { "spaces": ["project-a"] },
  "match": { "kind": "command", "executable": "acme", "subcommand": ["mr", "create"] },
  "action": "approve",
  "approval": { "approver": "owner", "waitSeconds": 90, "expiresSeconds": 86400 }
}
```

## 如何匹配

- `scope` 可以限定成员 ID、角色或档案、空间 ID、后端 ID（`members / roles / spaces / backends`）。同一维度的多个值满足一个即可，指定的各维度都要满足。省略范围时对所有运行生效。
- 命令按可执行文件名匹配，Windows 忽略大小写。`subcommand` 匹配从头开始的位置词，跳过以短横线开头的参数。分开传入的选项值也占位置词。要精确指定参数，使用 `argv: [{ "index": 2, "regex": "^write$" }]`，下标从零开始，包含选项在内。`argsRegex` 匹配原始参数按空格连接后的字符串。
- HTTP 可指定方法列表、主机、URL 规范化后的路径正则和请求体字段。`*.example.com` 匹配子域名；路径不含查询串。文件按操作和路径正则匹配。工具按服务、工具名和参数字段匹配；omem 自己的服务名可以省略。
- JSON 字段从 `$` 开始，支持 `$.item.name` 和 `$.items[0].state`。同一规则中的多个参数条件要同时满足。正则最长 2000 字符，保存时检查语法。单次匹配输入超过 8192 字符或正则执行超时，执行点收到拒绝决定。
- 保存修改后宿主更新规则版本。审批绑定服务器返回的版本。旧 `security.commandRules` 加载时按原顺序迁移，下一次保存配置写入 `security.operationRules`。设置 → 安全 → 操作规则直接读写 `/api/security/operation-rules`（整份保存，四种匹配、范围、开关和顺序都在这一页；规则包的规则只改范围和开关），下面的“规则包”一张卡走 `rule-packs` 接口。旧接口 `GET/PUT /api/security/command-rules` 仍可编辑旧格式能表达的命令规则，保存时保留其他规则和范围；网页只从它取审批人的选项和平台。

## 执行点

| 执行点 | 能看到的字段 | 命中后的行为和边界 |
| --- | --- | --- |
| PATH 命令垫片（含 Windows、macOS） | 文件名、完整 argv、调用进程的 cwd。运行令牌提供身份和上下文 | 拒绝、等待批准、记录或执行。经 PATH 查找的脚本子进程也经过垫片。绝对路径、被替换的 PATH、直接调用底层库和 Windows 直接启动真实 exe 的进程在覆盖范围之外 |
| Linux 本人及成员沙箱 | 宿主从运行令牌确定账号、工作区和权限，再核对命令名、argv、cwd | 已知入口挂上只读垫片。需要登录的命令在独立执行器中运行。自行安装的软件仍只能使用 Agent 沙箱可见的文件和网络权限 |
| ACP 权限回调 | 适配器上报的结构化命令、参数或文件操作与路径，以及当前会话上下文 | 拒绝和审批规则介入回调；审批超时按拒绝处理。仅有标题或缺少可匹配字段时沿用适配器的 kind 和运行写权限判断。后端没有发起权限请求的操作不会经过这里 |
| omem 工具 | omem 服务名、实际调用的工具名、工具参数、运行上下文 | deny 拒绝，approve 进入工具审批，allow 略过按工具名配置的每次询问，log 记录并继续原流程。工具可见性、成员权限和工具自身的授权条件仍生效 |
| 浏览器请求（`browser`） | 方法、完整 URL、文本或 JSON 的请求体（最多 64KB）、发出请求的页面。运行令牌提供身份和上下文 | aad 驱动的浏览器会话在请求发出前问 `/api/operation-gate/http`：拒绝或等批准时请求不发出，放行才继续。要带请求闸门的 aad 版本；不经这个浏览器发出的请求（命令行里的 curl、别的程序、已建立的 WebSocket 里的消息）管不到，见下面“网页请求” |

经 PATH 执行受保护命令时，ACP 回调把一次批准留给当前轮次的命令垫片。垫片核对规则版本、身份、参数和目录后核销。轮次结束时，未用的交接失效。

Agent 启动时，宿主为启用的 command 规则和已启用、受信任的凭据插件声明的命令生成垫片。失去信任或停用插件后，下次生成会移除只由它声明的垫片。从无垫片变为有垫片时，已有进程需要重启才会拿到新的 PATH。

有运行令牌时，垫片先问 `POST /api/command-gate`。受规则保护的调用连不上宿主时以 126 退出。凭据命令在离线时按本地的命令及参数规则判断，没有匹配规则就照常执行。离线时无法核对的规则范围按受保护处理。

新版垫片在执行前询问时带 `credentialExecution: true`。发起人缺少有效登录、命令匹配只读和具体资源、出借设置允许自动借用时，宿主用插件实时核验发起人的资源权限。确认后命令在出借人的环境中执行，响应的 `execution` 带退出码和分别以 base64 编码的 stdout、stderr。垫片按原字节输出。宿主通过 HTTP 102 告知新版垫片已接手，再延长等待时间以容纳预检和命令执行。连接宿主仍沿用原超时。旧版垫片继续执行本地命令。预检契约和隔离范围见[凭据设计](credentials.md#运行时用谁的)。

放行后，在发起人自己账号中运行的凭据命令会实时输出 stdout 和 stderr。退出后垫片用运行令牌调用 `POST /api/credentials/outcome`，成功只报退出码和调用参数，失败附最近 20,000 个字符。宿主按声明顺序识别 JSON 中的失败原因，保留原命令的退出码，拒绝时给出申请链接。结果上报失败时，调用方仍收到本地结果。

设备代跑（peer ACP）启动后端时，把执行设备的命令垫片放在 PATH 首位。垫片向执行设备的 omem 请求决定，由该设备按本机规则审批和记录审计。自有设备之间传递发起运行的成员 ID；旧版发起设备没有提供成员时，按配对身份处理。借用他人借出的后端时，执行设备按借用凭据对应的成员匹配规则。MCP 工具仍回到发起设备执行。设备上的后端使用当地服务账号，跨设备运行没有成员账号沙箱。

## 执行器

本人设置的额外可写目录也属于执行器的工作区，沿用本轮最终挂载权限。命令可在其中切换工作目录或用参数引用仓库。后端状态和隐藏目录继续隔离。

Linux 本机沙箱的垫片把完整 argv 和 cwd 发给原来的命令闸门。放行后宿主签发一次性执行许可，只对当前运行令牌有效。垫片通过 `POST /api/command-gate/stream/:permit` 发送 stdin；响应分别传输 stdout、stderr 和退出码。连接断开、令牌撤销或执行超时会终止子进程。执行器需要支持 `--bind-fd`、`--ro-bind-fd` 的 bubblewrap。

- 插件只要声明命令即可进入闸门。规则决定放行、审批、拒绝或记录。没有命中规则时放行并审计。执行器从宿主安装中定位程序，只挂回该声明的状态目录、本轮工作区和程序运行所需的文件。使用非标准登录路径的插件应在 `state` 声明相对 HOME 的路径。借用别人的登录继续按原有只读预检处理。
- `git push/fetch/pull/clone/ls-remote`、`git remote update` 和 `git submodule update --remote` 经执行器使用当前身份的远端登录。`git status`、列出或增删 remote、未带 `--remote` 的子模块更新默认留在 Agent 沙箱；本地操作命中 Git 规则时仍询问闸门。私有仓库的地址与本地路径由 Git 解析，因此公开仓库的 clone 也走执行器。
- 飞书 `lark-cli` 在同身份执行器里运行 omem 随包安装的 CLI，可读取和续签该账号的 `.lark-cli`、`.local/share/lark-cli`。Agent 默认看不到其中的凭据。插件可以登记与后端 `account.owns` 重合的命令状态目录。沙箱中的命令执行器按命令声明取用状态。
- 本地 ACP 后端与它自行执行的工具共享挂载视图。本人或成员启动沙箱时，若后端状态与插件命令的登录路径相同或互为父子，宿主在启动进程前报告重合的路径。本人选「能用就用」也会收到该错误。可改用其他后端，或让插件分别供给权限独立的凭据并分开存放。同一令牌存成两份仍具有相同权限。
- SSH/SCP/SFTP、GitHub/GitLab CLI、AWS/Azure/Google Cloud CLI、kubectl 和 Docker CLI 的标准文件登录也按命令挂回执行器。额外路径、企业认证助手和自定义登录方式需要声明对应状态和安装目录。
- 标准命令可取得各自的登录变量，例如 `gh` 的 `GH_TOKEN` 和 npm、pnpm 的 `NPM_TOKEN`、`NODE_AUTH_TOKEN`。凭据插件可用 `commands[].loginEnv` 声明沙箱已过滤的命令登录变量名，例如 `ACME_TOKEN`。执行器仅为命中该声明的调用恢复变量。本人使用 Agent 后端档案的值，缺省时取宿主环境；成员只取本轮成员账号配置。
- 审计的 `command.execute` 带命令、完整 argv、cwd 和运行编号。审批指纹绑定 argv 和 cwd。执行器按允许清单构造环境，保留 HOME、语言与宿主选定的 PATH，Git 可使用对应的认证套接字。Agent 传入的解释器启动参数、动态库路径和配置路径不会带入。
- PATH 上发现的同名文件和符号链接目标会盖上垫片。可识别的 npm 包入口和 Python 模块入口也会覆盖。清空环境后，垫片因缺少运行令牌退出。复制或另外安装的程序仍在 Agent 的挂载和出网范围内。命令名规则本身无法撤销工作区已有的写权限，也无法约束一个匿名服务接受的请求。
- 闸门审计凭据命令的启动。CLI 可以解释参数、项目配置和扩展，也可以使用其原有网络权限。在同一执行器进程及其子进程内部，不会对每次文件读取、插件调用或 HTTP 请求另行审批。命令行子进程需要额外的网络约束时，使用出网代理。
- 用户的 `~/.npmrc` 默认在 Agent 内提供只读快照。保留源、作用域、代理和 CA 设置，移除令牌、用户名密码、客户端证书和密钥设置，代理 URL 中的登录信息也会去掉。成员档案和运行环境提供的 npm 等命令登录变量同样会过滤。只读配置不需要认证的安装可在 Agent 内完成。私有源需要认证时，将 npm 或 pnpm 配成受保护命令，执行器只读挂回本身份的完整用户配置，或由本人安装。授权安装也会授权它按项目配置运行生命周期脚本。`~/.pypirc` 继续隐藏。

- 普通 Agent 在 HOME 安装工具、修改配置和填充缓存时，改动只进入本身份的写时复制层。执行器从真实安装目录解析程序，使用独立的挂载计划。
- 每次受保护调用新起一个沙箱。支持二进制管道，没有 TTY。交互式登录应通过已有的登录流程完成。启动时读取当前凭据路径和安装清单；新增登录位置或安装工具后应重新开始运行。没有工具令牌的模型调用遇到受保护入口会直接拒绝。

## 网页请求

本人可以在远程页或 Chrome 扩展录一次手动操作，然后说“刚才取消订单的接口要审批”。助手读 `read_recording part=requests`，按请求编号用 `propose_operation_rule` 起草。比如 `POST shop.example.test/api/v1/orders/8812/cancel` 会保留主机、方法和版本号，路径变成 `^/api/v1/orders/[^/]+/cancel$`。可用请求体字段进一步限定。同一段录制里，所选请求必须命中，GET、HEAD 和噪声请求都要避开。直接指定接口时，卡片注明未经录制核对。

卡片给本人看所选步骤、匹配范围和命中次数。默认要运行发起人（`caller`）批准。点“启用”后，新规则排在覆盖该主机和接口的宽泛放行规则前，其余规则保留原有顺序。没有这样的放行规则就追加到末尾。录制来源随设置接口返回在 `recording: { id, requestId, step }`，其中未关联步骤时 `step` 为 null。本人可在设置 → 安全 → 操作规则删除。

草稿不限正文时，旧放行规则即使限定了正文字段，也排在覆盖该接口的新规则后。两条规则都限定正文时，启用会用录制中命中草稿的每个请求核对当前放行规则。比如取消请求同时满足旧规则的 `state=open` 和草稿的 `intent=cancel`，启用后它就要审批。直接指定接口时没有正文样本，卡片会说明覆盖该接口的放行规则也排在新规则后。

HTTP 规则的执行点在 Agent 用 aad 操作的浏览器里（`src/agents/http-gate.ts`）。两个接口，都只接受本机回环地址上带运行令牌的请求（和命令垫片同一种调用方），aad 从环境里的 `OMEM_URL` / `OMEM_TOKEN` 找到它：

- `GET /api/operation-gate/http` 返回要问哪些请求：`{ revision, watch: [{ host, methods }] }`。只列对这个调用方生效、动作不是放行的 HTTP 规则（放行规则只是在更宽的规则前开口子，把请求带到这里的是那条更宽的规则）；`host` 是主机名或 `*.` 开头的后缀，`methods` 为空表示任何方法。浏览器按它收窄拦截范围，`watch` 为空就不用拦；`revision` 变了说明要重新取。
- `POST /api/operation-gate/http`，正文 `{ method, url, body?, contentType?, page?: { url, title }, session? }`，回答 `{ decision: "allow" }`、`{ decision: "deny", message }` 或 `{ decision: "pending", message, askId }`。判定和命令走同一个 `gateOperation`：按顺序找第一条命中的规则，要批准的发审批卡片并挂住请求到规则的等待时间（默认 90 秒），到时没人答就回 `pending`，这次不发；批准以后同样的请求再来一次直接放行，一次批准用一次。

请求体只有是 JSON 时才参与 `body.jsonPath` 的匹配，表单和二进制不匹配任何请求体条件。卡片、通知和审计里一个请求写成“方法 主机 路径”，不带查询串和请求体；批准绑定的是方法、主机、路径和规则里指定的那个请求体字段，换一个路径要重新批准。

边界：这道闸只管经 aad 开的浏览器发出的请求。会话没有带着运行令牌的调用方驱动过就不拦；aad 问不到 omem（服务没起、令牌失效、超时）时，在范围里的请求不发。沙箱内的命令行请求由出网代理处理。

## 出网代理

本人用 GET 查看 `/api/security/egress`，用 PUT 提交整份配置，例如：

```json
{"mode":"strict-only","default":"approve","tunnelWhenUnsure":"deny","inspect":[],"waitSeconds":90}
```

| 模式 | 新启动的本机运行 |
| --- | --- |
| `strict-only`（默认） | 严格成员沙箱（`agents.accountIsolation = "require"`）启用出网隔离。创建网络命名空间失败就拒绝启动。 |
| `all-sandboxed` | 本人和成员的本机文件沙箱均启用代理。本人沙箱无法隔离出网时拒绝启动。成员沙箱沿用原有回退策略。非严格运行在不支持的机器上记录原因，沿用原网络。 |
| `off` | 沿用原网络。 |

bubblewrap 创建独立网络命名空间，仅挂载系统运行库、程序、账号和指定工作目录。分配工作目录时应避开能代为联网的宿主 Unix 套接字。回环中继连到宿主为本次运行创建的 Unix 套接字。程序通过大小写代理变量访问 HTTP 和 HTTPS。代理解析目标域名并固定连接地址。沙箱内直接发送 TCP、UDP 和 DNS 包都无法出网。非 Linux、设备代跑以及沙箱外忽略代理变量的程序不受这个执行点控制。运行结束或工具令牌撤销时，入口和已有连接一并关闭。

`default` 默认放行。后端目录声明的公共模型服务和配置的 base URL 自动放行。配置了 HTTP(S) 上游代理时，由宿主在判定后代连。npm、PyPI 和 Git 源走普通规则。宿主地址、回环、内网和链路本地需要显式放行或批准。工具回调校验端口、路径和运行令牌。

普通 HTTPS 隧道只能按 CONNECT 目的地主机判定。遇到方法、路径或正文条件时，`tunnelWhenUnsure` 默认放行并记录，也可以改为 `approve` 或 `deny`。审批默认最多等 90 秒（可设 1 至 300 秒），超时或拒绝回 403。同一目标指纹的并发请求合问一次。每个入口最多 64 个连接、16 个不同的待批目标及 256 个主机记录。

`inspect` 默认空。加入精确域名或 `*.example.org` 后，代理为名单内 CONNECT 建立两段 TLS，并按明文 HTTP 规则检查每个请求。需要 openssl，根私钥位于数据目录的 `secrets/egress-ca`。只有公有证书包进入沙箱。宿主信任库沿用原配置，代理校验上游证书。钉证书的客户端会报证书不匹配，忽略沙箱信任包的客户端会报未知 CA。试点支持 HTTP/1.1。对有正文字段条件的主机，压缩或超过 1 MiB 的正文会被拒绝。审批卡片只展示规则指定的正文字段。请求和响应正文不写入流量日志。

GET 返回配置、`support`、`rootGenerated`、`inspectionAvailable`、代跑说明、最近运行的 `runs`、`denied` 和 `pending`。主机行含次数、字节合计、拒绝数与后端标记。运行历史保存汇总，命中记录进操作审计。HTTP 规则的 `enforcedBy` 同时列出 `browser` 与 `egress`。

## 授权范围

- **只这一次**。批准绑定成员、命中的规则及版本和目标指纹。命令指纹包含可执行文件、完整 argv 和 cwd。多个等待者竞争同一授权时仅放行一次。原调用已超时，宿主会唤醒原发起者，重试仍需满足相同条件。
- **这次运行里的同类操作**。本人可让同一成员在同一个运行内继续执行命中同一条规则的操作。运行结束、授权过期或规则版本变化后重新审批。
- **以后按这条规则放行**。本人确认后把整条规则改为 allow，作用范围包括该规则所列的全部成员和目标。其他审批人只能批一次。旧规则配置的 window 仍支持由本人按原审批方式在有效期内重试同一目标。

命令规则可指定本人、登记的成员或飞书联系人，也可用 run 从预设名单中接受运行提名。等待时间默认 90 秒，卡片和授权的默认有效期各为一天。操作与审批结果写入 audit_events，按成员、运行和规则版本核对。命令卡片显示目标摘要和参数哈希。

## 规则包

插件或技能可在目录中提供 `operation-rules.yaml`。本人通过 `GET /api/security/rule-packs` 查看来源、包名、版本、规则数和启用状态。启用时调用 `POST /api/security/rule-packs/:id/enable` 指定范围，安装的规则带有包名、版本及包内规则 ID。发现新版本时先查看差异，再确认替换。停用通过 `POST /api/security/rule-packs/:id/disable`。安装插件或技能本身不会授予放行权限。
