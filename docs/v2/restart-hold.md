# 重启不打断正在跑的一轮

本人一天要往常驻服务器上部署好几次（`omem peer call <设备> update`：拉代码、构建、重启服务），而那台机器上几乎一直有交办、评审、跟进、课题试验在跑。以前重启会把正在进行的一轮切断：重启后运行回到队列，在同一个 Agent 会话里接着做（`markRestarted` / `takeRestart`），但模型正在想的、正在调的工具、并行的几个评审检查都丢了要重做，恢复会话失败时整轮从头来。部署也常要等一个没人在跑的空档，这个空档很少有。

现在一轮 Agent 的进程可以活过 omem 的重启：重启前的 omem 把它交出去，重启后的 omem 接回来，这一轮接着跑完，不重发提示，结果照常交给运行。实现在 `src/agents/agent-host.ts`（宿主进程）、`src/agents/hosted.ts`（omem 这边：启动、登记、接回、清理）、`src/agents/host-frames.ts`（两边之间的帧），接进 `src/agents/acp.ts` 的 `openAcpOnce`、`spawn.ts` 的 `launch`。

## 怎么做的

每一轮运行里的 ACP Agent 不再是 omem 的直接子进程，而是放在一个很小的“Agent 宿主”进程下面。宿主由 omem 起，但起完马上脱离（先起一个启动器，启动器再以独立会话起宿主后退出），不是 omem 进程树里的一员：PM2 重启 omem 时按进程树停进程，停不到它。宿主拿着 Agent 的 stdin、stdout、stderr，在数据目录的 `agent-hosts/` 下开一个本机套接字（Linux / macOS 是 Unix 套接字，Windows 是命名管道），omem 经这个套接字和 Agent 说 ACP，用起来和自己的子进程一样（`HostedChild`）。连接要带宿主启动时给的密钥。

宿主只懂一点 JSON-RPC：哪个请求是正在进行的这一轮（`session/prompt`）、Agent 发来的哪些请求还没人回答（比如问权限）。其余原样转发。

### omem 停下时

- 正常停止（`omem service restart`、部署后的重启）：`serve` 的退出流程先告诉每个宿主“我要走了”（`detachHostsForShutdown`），再给正在回答的工具调用最多 5 秒做完（`drainToolCalls`），然后退出。崩溃时没有这一步，宿主看到连接断了，同样处理。
- 宿主没有了 omem：Agent 照常跑；它这一轮说的话（`session/update`）宿主都记着；它问 omem 的事（权限）先压着，等下一个 omem 来回答；这一轮的最后结果也先存着。
- 宿主等一段时间（设置 `agents.restartHold.minutes`，默认 5 分钟）。到时没有 omem 回来，就取消这一轮、停掉 Agent、退出，这次运行回到以前的重启做法（同一会话里接着做，告诉它是重启打断的）。
- 宿主连着 omem 时 omem 主动停它（这一轮结束、取消、看门狗超时），宿主停掉 Agent 后退出；omem 断开时宿主上没有进行中的一轮（还在建会话，或这一轮已经交回），也直接停掉退出。

### omem 回来时

- 启动时照旧把被打断的运行放回队列。运行的处理函数重新执行，走到要开 ACP 会话的地方，先查有没有宿主替它留着这一轮：同一次运行、同一个角色或检查（`hostSlot`：检查名、档案名或角色名）、同一个 AI、同一个工作目录（`claimHost`）。有就接回，不起新进程、不开新会话。
- 接回时宿主把这一轮里 Agent 说过的话交给新的 omem：重启前已经交给旧 omem 的那部分只用来拼出完整的回复，不再重复记成运行事件；之后的照常记下。然后 omem 发 `_omem/await_turn`，宿主把压着的权限请求、接回之后 Agent 新说的话交过去，这一轮做完时把原来那个 `session/prompt` 的结果作为它的回答。这一轮在 omem 不在时已经做完的，直接拿到结果。
- 同一个角色或检查有对不上的宿主（换了 AI、换了目录，或一个槽有两个）就停掉：重跑的那一轮自己做这件事，不让两个 Agent 同时改同一个工作区。
- 和以前的重启做法一样，“接回”的是这次运行里这个角色或检查重启后的第一轮。编码交办重启后的第一轮本来就是“接着做被打断的这一轮”，接回的正是那一轮。

### 这一轮里的工具调用

- Agent 拿到的 omem 地址（HTTP MCP 的地址、stdio 桥和 `omem tool` 用的 `OMEM_URL`）都换成宿主自己开的本机 HTTP 代理（宿主转发 `session/new` 时改写，起 Agent 时改环境变量），代理再转给 omem。omem 不在（或正在接回）时，调用在代理里等；接回之后放行，连接被拒（omem 还没起完）就过半秒再试。到时没有 omem 回来，等着的调用返回 503。
- omem 已经收到、做到一半时被重启切断的调用不重发（可能已经写了），照常失败，Agent 自己看着办。重启前那 5 秒就是为了让这种调用尽量做完。
- Agent 启动时拿的工具令牌只在旧 omem 的内存里。接回时宿主把它交给新的 omem，新 omem 核对它的哈希（登记里记着）后，让它代表这一轮重新准备的令牌（`aliasToolToken`）：同样的工具、空间和运行，一起撤销。命令拦截的垫片用的也是这个令牌和地址，同样经代理。
- 在 omem 自己的沙箱里跑的，Agent 的 `/tmp` 是启动时建的那个目录；接回时执行器替它跑受保护命令也改用这个目录（`private_tmp`），重跑时新建的那个删掉。

### 登记

表 `agent_hosts` 记这台机器上的宿主：运行、槽、AI、目录、会话、Agent 的能力和名字、宿主和 Agent 的 pid、套接字、密钥、令牌哈希、`owner`（现在和它说话的是哪个 omem）。只是本机的进程状态，不同步到别的设备。宿主持有的后端会话在会话清理的账上记成宿主的 pid，宿主活着时不会被当成没人用的会话删掉。启动时和之后每分钟清一遍（`sweepAgentHosts`）：宿主已经没了的删记录；运行已经结束的，经套接字让宿主停掉；运行还在队列里或正在跑的，等它来接。停宿主只经套接字发停止，不按 pid 杀进程（pid 可能已经给了别的进程）。

## 哪些一轮会这样跑

- 第一期是运行里经 `runRole` 跑的 ACP 一轮：交办编码、评审和它的检查、跟进、课题试验、流程阶段、规则交给 Agent 的任务等。设置 `agents.restartHold.enabled`（默认开）关掉后都回到原来的直接启动。
- 对话会话（私聊、群、话题里的 `sessions.ts`）和后台复用的会话（`background-sessions.ts`）这期不变：它们的 Agent 进程跨好几轮常驻，交接要处理的是“两轮之间的空闲会话”而不是“进行中的一轮”，规则不同；而且对话被打断后由渠道恢复重发回复（`recoverReply`），影响比交办小。之后要做时，宿主的做法可以直接用，要补的是会话层的接回。
- 不走宿主的：走 omem API key 中转的后端（中转的令牌和模型请求都在 omem 进程里，omem 一停模型就断）、要出网隔离的运行（出网代理在 omem 进程里）、云端后端经 HTTP 调工具的一轮（它的凭据在 omem 进程里）、探测。它们照旧，重启后按以前的做法接着做。

## 限制

- Agent 自己对工具调用有超时：Codex 调 MCP 工具默认 60 秒，Node 的 fetch（stdio 桥）等响应头 5 分钟。omem 重启加上接回超过这个时间，那一次工具调用在 Agent 那边就算失败了，和以前一样由模型自己决定重试。重启越快越好：构建在重启之前做完，接回发生在运行重新开始的那一刻。
- 机器重启、`systemctl` 重启整个服务单元，会连宿主一起停掉；这时回到以前的做法。
- 每一轮多一个 Node 进程（宿主，几十 MB 内存），起一轮多一两百毫秒。
- Linux 上 bubblewrap 沙箱、固定挂载的描述符、npm 源配置的管道经启动器和宿主原样传给 Agent（同样的描述符号），这部分只在 Linux 上有，开发机（Windows）跑不到，要在常驻服务器上验。

## 测试

`test/agent-host.test.ts` 用两个 App 实例开同一个数据目录，代表重启前后的两个 omem（第一个交出宿主、停掉 HTTP 服务、忘掉工具令牌），用 `test/fake-acp-agent.ts` 的 `FAKE_MODE=gap`（说一段、等一个文件、再调 omem 的搜索、可以先问一次权限）和 `FAKE_MODE=thread`（`FAKE_DELAY` 拖长一轮）：

- 第一个 omem 开始的一轮在第二个 omem 下做完：同一个 Agent 进程，只收到过一次提示；omem 不在时发出的搜索在接回后成功，地址是宿主的代理；回复里有重启前说的话，那部分不再重复上报。
- omem 不在时 Agent 问的权限，交给第二个 omem 回答。
- omem 不在时这一轮已经做完，第二个 omem 接回时直接拿到结果。
- 到时没有 omem 回来：宿主和 Agent 都退出，第二个 omem 按以前的做法在同一会话里接着做（提示里有“omem 重启打断了这次任务”）。
- omem 不在时运行结束了：清理时停掉宿主。
- 没有重启的一轮照常跑完，宿主随之退出。

`OMEM_TEST_HOSTED=1` 让测试里所有一轮都经宿主跑（`test/helpers.ts` 默认关），可以用它把会话、卡住、换后端、权限、会话清理、跟进这些测试经宿主再跑一遍。
