# 情境：关注一类会反复发生的事

地方型关注看一个地方，事项型关注跟一件事。情境看一类事，例如项目 A 的例行演练：每次有各自的对象、时间窗口和事项，各次共用本人写的说明和积累的经验。说明写发生时在意什么、什么时候需要本人知道，不写成固定步骤。查某个平台的方法放在处理者的技能里。

## 情境与开始信号

情境是 `listen_contexts.kind = situation` 的一条记录，包含所属用户、名字、说明 `note`、开始信号 `recognize`、处理者 `spec`、空间和关注设置。没有固定群，也没有模板自己的处理会话。保存时复用规则编译器生成触发条件，可用新消息、文档变化、对象状态变化／更新或 omem 内部事件，以及规则已有的三种判断方式。宿主固定动作 `context`，不采纳模型生成的动作。生成规则使用 `origin: {kind:"situation", contextId, name}`，随模板启停、改名和删除；规则 API 只读它。规则不占用这条消息的答复权。

## 一回的生命周期

- 命中信号时，没有未到期的一回就新开；否则决策模型在进行中的各回、新的一回、不相关之间选择，不设决策模型时并到最近一回。模型报错时不猜归属。本人也可从对话或 HTTP 明确开一回。
- 一回在 `situation_instances` 里，关联带原事件引用的事项和独立 `listen` 会话。同一回串行，不同回可并行。首轮带说明、经验、最近小结与本次信号；先查清这一次的范围，再按情况使用已有 `wake` 排窗口内的复查。异常需要本人知道时用 `notify` 私下说，不回原群。
- 新信号、外来事项进展和相关的本人发言把窗口推到至少从现在起 4 小时；处理者可更新现状、显式延长或交小结结束。复查本身不会自动延长。窗口到了只排一次收尾；没交结果或超时，宿主按最后的现状结束。结束同步收尾事项，保留会话和实例记录。会话原件与经验文件索引留在本人的个人空间，不写进共享空间。暂停只阻止新信号或手工新开，已经开始的回合继续收尾；删除立即结束进行中的各回。

### 开始时先看一眼

打开“先看一眼”后，每回首个信号先跑所选预查，再用[快速通道](first-look.md)看一眼。快模型读情境说明、怎么认出来、触发事件和预查输出；结果与投递去处随首个信号交给处理者。答完、要本人定、超时或出错都照常开始跟进。每天按这个关注的 `perDay` 限制先看次数，超额只跳过快速通道；并入已有一回的后续信号只跑所选预查，不再先看。群消息可按设置发回触发处（直接发仍须授权）或发独享卡，其他信号和手工开一回只私聊本人。后续异常由处理者私下告知，不接着在群里回复。

## 别的运行怎么知道

1. 同一用户的其他对话轮次和后台运行会看到至多三条“正在进行的情境”。范围可能相符时，先读事项，确认后记录发现；不要把正在进行误当作已经有人处理。
2. 事项事件和变化写入共用台账；外来变更批量送回实例会话，附作者或来源及运行 id。同一会话的运行自己写的不回流。
3. 宿主从已有会话和飞书采集读本人的话，逐条判断是否与这一回有关，送达时合为一批，按消息 id 去重；没有可用决策模型只送事项已关联的会话和群里的话。不会因一句话启动另一回。这条路径不代替飞书采集，机器人看不到的群仍要等个人采集读到。

## 怎么教

- 本人给说明：主助手用 `save_situation`。本人明确交代建或改的直接保存；主助手自己提出的新情境先停用，回复后展示启用确认；提议修改已有情境时，确认前保留原版。改说明要列出前后文字。
- 做一遍：本人结束非情境事项后，宿主查关联会话和有事项依据的运行，至多取最近 12 次有助手结果且去掉合并重复的本人轮次。至少三轮才安排事项收尾判断；Agent 确认确实是逐步指挥且可复用才提议，不从普通问答提炼。提议进入“需要你处理”和“今天”：可以（保存并启用）、改一改（打开编辑表单）、不用（写入取舍记录，不再提同类）。
- 每回收尾：有小结的实例作为经验案例。跟其他关注一样，累计达到门槛后由 listen-coach 整理，不回写本人的说明。

## 默认值

| 项 | 值 |
| --- | --- |
| 没有新活动的窗口 | 4 小时 |
| 最多同时进行 / 每天新开（每个情境，按设置时区） | 3 回 / 12 回 |
| 手动延长 | 从当前时间算，最多 24 小时，不缩短已有窗口 |
| 收尾 | 1 轮，排队与执行共给 2 分钟；否则用最后现状 |
| 送达扫描 | 常驻进程每 15 秒；每回每批最多 30 条本人发言、30 条事项反馈 |
| 提示和案例 | 其他运行最多 3 回；实例带最近 5 个小结；5 个新案例后可排经验整理 |

## HTTP 接口

以下接口只给系统本人，使用既有认证；`id` 是路径参数。未填的修改字段保持原值。空间不传时新情境用 `personal`。`kind` 创建后不变。

| 方法与路径 | 参数 | 返回 |
| --- | --- | --- |
| `GET /api/listen?kind=situation` | `kind` 可选，省略含其他关注 | 关注视图数组；情境含 `kind`, `id`, `userId`, `name`, `note`, `recognize`, `spec`, `spaceId`, `knobs`, `status`, `expiresAt`, `ruleId` 等 |
| `GET /api/listen/:id` | 情境 id | 原有关注详情外壳，`context` 为同一视图；经验在 `playbook`，各回从实例列表读 |
| `POST /api/listen` | `{kind:"situation", name, note, recognize, spec?, spaceId?, knobs?, status?, expiresAt?}`，不用 `chats` | 新情境视图；默认 `active` |
| `PUT /api/listen/:id` | `{name?, note?, recognize?, spec?, spaceId?, knobs?, status?, expiresAt?}`；`status` 取 `active` 或 `paused` | 修改后的情境视图 |
| `DELETE /api/listen/:id` | 情境 id | `{ok:true}` |
| `POST /api/listen/:id/start` | `{about}`（1–2000 字） | `{instance, runId}`，`runId` 是进入会话的轮次，没排到返回 `null` |
| `GET /api/situation-instances` | `contextId?`、`status?`（`active` 或 `ended`）、`limit?`（1–100，默认 50） | 实例数组，进行中在前，各组内按开始时间倒序 |
| `GET /api/situation-instances/:id` | 实例 id | `{instance, item, events}`；事项不存在时 `item:null` |
| `POST /api/situation-instances/:id/end` | `{summary?}`（最长 3000 字，不传用最后的现状） | 结束后的实例；重复结束不改小结 |

实例对象含 `id, contextId, userId, itemId, conversationId, spaceId, title, status, startedAt, windowUntil, current, summary, endedAt, closingRun, closingDeadline`。时间是 ISO 字符串，尚未有的小结和结束信息为 `null`。无权限 `403`，查不到 `404`，停用或并发改动 `409`，规则编译失败 `422`，超过实例上限 `429`。名称、说明、怎么认出来上限分别为 80、2000、1000 字。生成规则可从 `GET /api/rules` 读到，写入和删除走情境接口。

## 没做的

增量拉取只合并已结束的实例，不从另一设备接续在办的窗口。

这一片不改界面，不给成员建情境，不提供任意群代发或接具体平台；拒绝过的类别按规范化名字拦截；有决策模型时还与最近 30 条拒绝过的类别做一次语义对照。没设决策模型时靠收尾 Agent 参考拒绝记录，不保证换名也能拦住。没有决策模型时不会把实例范围外的话猜成相关。
