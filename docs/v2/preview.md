# 交办工作区的预览

交办在 omem 所在机器（常驻服务器）的工作区里写代码，本人想看页面效果时，要么等推送后在别处起服务，要么登上那台机器。预览让本人在交办视图里点一下，就在那次交办的工作区里起服务，在自己电脑的浏览器里打开。实现在 `src/agents/previews.ts`（起停、认端口）、`src/core/listening.ts`（进程树与端口）、`src/server/preview-http.ts`（接口与隧道）、`src/core/preview-forward.ts`（本机转发），页面是 `web/src/components/WorkPreview.vue`。

## 用法

1. 仓库空间的设置里填“预览命令”，一行一条 `名字: 命令`，只有一条时可以不写名字。命令在工作区目录里运行（Linux / macOS 用 `sh -c`，Windows 用 `cmd /c`），和平时在仓库里起服务的命令一样，比如：

   ```text
   主站: pnpm --dir apps/main dev & pnpm --dir apps/sub dev & wait
   H5: pnpm --dir wap/h5 dev
   ```

   要一次起几个应用，命令里用 `&` 连起来、最后加 `wait`（否则前台那个先退出时预览就算结束），或者在仓库里写一个脚本（同事也能用）。环境变量直接写在命令前面（`NODE_ENV=development …`）。预览命令不继承 omem 后台服务的 `NODE_ENV=production`（`omem service` 用 PM2 运行时设的），否则开发服务器会按生产模式构建；需要时命令自己设。Windows 上命令由 `cmd` 运行，后台起多个用 `start /b`。
2. 交办视图顶部点“预览”，选仓库和命令。工作区没装过依赖（比如交办应用后单独建的目录）或锁文件变了时，先运行仓库的准备命令，规则和编码前一样（`setupCommandFor` / `setupKey`，装好记下，下次不再装），页面显示“准备依赖”。然后 omem 在这次交办的工作区里运行预览命令，显示最近的输出；这条命令和它启动的进程开始监听端口后，列出端口，能返回网页的标“网页”。
3. 点端口打开。地址是 `http://localhost:<端口>/`，端口号和在那台机器上一样。

## 为什么按原端口号转发

多应用的前端项目常把本机地址写死在开发配置里：资源地址 `http://localhost:3000/`、子应用入口 `http://127.0.0.1:3001`、热更新固定连某个端口。预览如果挂在 omem 地址下的某个路径或另一个域名，这些都会失效，只能逐个应用改写，项目越多配置越多。按原端口号转发时，浏览器看到的就是 `localhost:<端口>`，和本地跑一样，omem 不需要知道有几个应用、谁是主应用。

## 三种看法

| 浏览器在哪 | 怎么看 |
| --- | --- |
| 和 omem 同一台机器 | 端口本来就在本机，直接打开 |
| 别的电脑，用 `omem peer open <设备>` 打开 omem | 本机这个进程在同样的端口号上监听（127.0.0.1，能监听时也监听 ::1），每个连接经设备隧道原样转到那台机器的端口；HTTP、WebSocket（热更新）都按字节转，不改请求。一端结束时另一端先把已收到的数据写完再结束（`peer-tunnel.ts` 的 `splice`），开发服务器的代理回完响应就关连接（`Connection: close`）时，慢链路上的大文件也不会被截断 |
| 别的电脑，直接打开那台的网页 | 看不了：浏览器所在的电脑上没有能监听端口的东西。页面提示改用 `omem peer open` |

隧道：本机进程对每个浏览器连接发一个 `GET /api/previews/<id>/tcp?port=<端口>`（`Upgrade: omem-tcp`），经 `--via` 的中间设备照样转发（中间设备对本人的升级请求不看路径原样转发，由最后那台自己鉴权，所以中间设备不用为预览更新到新版；以前它只转发 `peer-tunnel.ts` 里 `tunneled` 列出的路径），到预览所在的机器后接到那个端口，回 101 后两边对接。本机端口被占用（比如自己也在跑同一个服务）时，那个端口标“本机已被占用”，别的端口照常。

## 管理

- 端口由 omem 自己认：每隔几秒查预览命令的进程和它的子进程在监听哪些 TCP 端口（Linux 读 `/proc`，macOS 用 `lsof`，Windows 用 `netstat` 和进程列表），不用配置。只转发这些端口，不是那台机器上的任意端口。
- 同一个仓库同时只有一个预览：项目的端口是写死的，两个工作区抢不了同一个端口。开新的会先停掉旧的。
- 没人在看就停：预览的端口上没有连接（浏览器标签关了、热更新的 WebSocket 断了）超过 `preview.idleMinutes`（默认 30）分钟，停掉。
- 交办的工作区被收回、交办应用或丢弃后，预览跟着停。
- omem 重启时，上次留下的预览进程按记录（kv `previews`）停掉。
- 只对本人开放，和网页版 VS Code 一样：预览命令是本人写的，起的服务能看到工作区里的代码。
- 输出里出现文件监听到上限的报错（`EMFILE` 加 `watch`：inotify 实例数；`ENOSPC`：监听数）时，页面在状态下面说明原因（`previewHint`）。Linux 上同一用户的 inotify 实例常见上限是 128，桌面程序、编辑器都占，开发服务器各占一个；满了就是这台机器的设置要调，不是项目的错。

## 接口

- `GET /api/runs/:id/previews`：这次交办能预览的工作区（仓库、路径、分支、预览命令）和正在运行的预览；`local` 表示浏览器和 omem 在同一台机器。
- `POST /api/previews`（`{ run, space, name? }`）开始；`GET /api/previews/:id` 状态、端口和最近输出；`DELETE /api/previews/:id` 停止；`GET /api/previews` 全部。
- 升级请求 `/api/previews/:id/tcp?port=`：隧道，只接受本人令牌（或没设令牌时本机的请求）。
- `omem peer open` 的本机进程另外处理 `/api/local/forwards`（列出、`POST { preview, ports }` 打开、`DELETE /api/local/forwards/:preview` 关闭），不转发给设备；omem 自己的服务对这个地址回 `{ forwarder: false }`。

## 不做的

- 手机上看：手机上没有 omem，没法按原端口号监听。以后可以加一个单端口的转发，只适合资源都用相对路径的项目。
- 接真实后端：要公司域名和登录态，交给项目自己的 Mock 或代理配置。
- 同一仓库的几个交办同时预览：端口是项目写死的。以后在 Linux 上可以给每个工作区一个独立的网络命名空间。
- Agent 用预览截图：Agent 在那台机器上直接访问 `localhost` 就行，不需要转发；截图交给运行的做法另外设计。
