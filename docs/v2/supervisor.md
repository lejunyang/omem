# 长任务的跟进：让一个强模型把一件事盯到底

2026-11-27 已接入对话命令和主助手工具。两种入口都会开工作话题。本人确认任务书后，助手协调编码交办和工作 Agent，通过飞书进度卡汇报。省略 AI 时先取“长任务跟进用的 AI”（`longTasks.supervisor`），未设置时取强模型档位。指定的 AI 不可用时排队等候。

宿主会提示重复尝试、回退、连续修复、路径越界、超时和目标缺失。相邻补丁还原检测和重纠偏复核留作后续。研究接入、接管已有交办和网页列在第 12 节第三期。实际用法见 [对话里的跟进命令](../../site/features/ask.md#跟进一件长任务)。

下面是整体设计。AI 组和规则见 [ai-policy.md](ai-policy.md)，相关机制见 [coding-loop.md](coding-loop.md)（交办、修改项、谁叫醒谁）、[studies.md](studies.md)（研究）、[flows.md](flows.md)。

## 1. 引入长任务跟进前，助手能把一件事跟到哪一步

能做到的：

- 助手交办编码后，交办停下（完成、轮数用完、不收敛、失败）或有“等助手处理”的修改项时，宿主在汇报的会话里排一轮，助手会被叫醒（`wakeAssistantForCodeResult`、`wakeAssistantForTasks`）。
- `run_agent` 开的多 Agent 工作，每个 Agent 一轮结束会排一轮协调（`onWorkRunSettled`）。

做不到的：

1. **叫醒的不一定是强模型。** 那一轮用这个会话当时的 AI；会话开新 Agent 会话时选型可能换成便宜的。只有本人在会话里 `/model` 定过才稳定。
2. **它不会自己续。** 交办停下后的那一轮禁用编码工具（`CODE_HANDOFF_DENY`，为了不绕过自动推进的轮数），助手只能汇报、等本人说“继续”；多 Agent 协调本人不说话时最多 6 轮（`autoAdvance.turns`）。
3. **只在停下时叫醒。** 一轮编码跑一两个小时，中间反复改、回退、钻进很边缘的问题，没人看，等停下时时间已经花掉了。
4. **没有任务书。** 每次叫醒看的是会话摘要和这一轮的结果，原始目标被一轮轮的细节冲淡，助手容易顺着最近的问题走。
5. **问题直接到本人。** 编码里“等你决定”的项、研究确认方向的关卡、试验要不要升档，都直接发卡片；助手没有先挡一道。
6. **进度是散的。** 交办卡片、研究记录、运行页各有一块，没有一处写“这件事做到哪了、还剩什么、下一步”。

以前这些靠在外面开一个会话专门跟进：它派活、盯着运行事件、读改动、发话纠偏、回答问题、决定推进。下面把这件事做进 omem。

## 2. 概念

- **长任务**：一件有明确目标、要跑很久的事（一次改造、一个研究、一次排查、一次迁移）。它是一个持续关注类的事项（事项页、工作页能看到）加上：一个工作话题、一份任务书、负责跟进的 AI 和跟进笔记。新表 `long_tasks`。
- **跟进**：助手使用指定的 AI（例如 codex · gpt-6.2-astra · xhigh），用新角色 `supervisor`。它不写代码、不跑试验：派活、看结果、纠偏、回答下面的问题、向本人汇报。
- **干活的**：交办的编码负责人和编码助手、评审、研究的试验、调查用的 Agent 档案。用各自的 AI，或助手指定的（过 AI 规则）。

## 3. 任务书

开始时助手按本人的话起草，本人确认一次（卡片上可以直接改）。之后每次唤醒助手跟进，任务书全文放在最前面。

| 项 | 内容 | 谁能改 |
| --- | --- | --- |
| 目标 | 本人的原话，逐字保留；助手可以在下面写自己的理解 | 本人 |
| 怎么算完成 | 可以检查的几条 | 本人；助手可提 |
| 不做的 | 明确不在范围里的 | 本人；助手可提 |
| 范围 | 涉及的仓库、目录、环境 | 本人；助手可提 |
| 约束 | 不推送 main、不改某目录、不动线上配置…… | 本人 |
| 预算 | 截止时间或总时长、编码总轮数、助手每天被叫醒的上限 | 本人 |
| 必须问本人的 | 默认：推送或合并到主分支、发布、改目标或碰到“不做的”、超预算、不可逆的操作（删数据、改别人的东西）、产品和业务取舍 | 本人 |
| 本人补充 | 本人之后在话题里说的话，逐条原文、带时间，只追加 | 宿主自动记 |

“助手可提”的改动走一张确认卡，本人点了才生效。

## 4. 什么时候唤醒助手跟进

只靠事件，同一件长任务同时只有一轮跟进在跑，5 分钟内的事件合成一轮。

| 事件 | 来自 | 说明 |
| --- | --- | --- |
| 本人在话题里说话 | 话题 | 最优先，不等合批；话进“本人补充” |
| 交办停下，或有“等助手处理”的项 | `code-chain` / `code-tasks` | 交办属于某个长任务时，唤醒任务指定的 AI 跟进；可以使用编码工具，轮数看长任务的预算 |
| 一项做完、被回退、第三次尝试 | 修改项状态变化 | 合批 |
| 干活的提问 | `ask_user`、`report_task(owner)`、评审负责人的 escalate | 先到助手（第 6 节） |
| 研究的阶段做完、方向待确认、试验拿不准要升档 | 流程 / 研究 | 流程关卡加 `confirm: supervisor` |
| `run_agent` 的一轮结束 | `onWorkRunSettled` | 工作属于长任务时，协调由助手做，不受 `autoAdvance.turns` 限制，受长任务预算限制 |
| 宿主发现的跑偏信号 | 第 5 节 | 立即 |
| 定时看一眼 | 宿主 | 有活在跑、且 40 分钟没有别的叫醒时；宿主先看这段时间有没有新提交、新修改项状态、新运行事件，没有就不叫醒 |

## 5. 防跑偏

### 5.1 宿主算的信号（确定的，不靠模型）

- 同一项尝试 3 次以上、被回退、修了又修超过两层（已有，`MAX_ATTEMPTS`、`MAX_FOLLOW_DEPTH`）。
- 改回去：相邻两个检查点之间，同一个文件的同一段改了又改回原样。
- 出范围：改到任务书“范围”以外的路径。
- 拖太久：一项花的时间超过同一交办里其他项中位数的 3 倍，或超过助手给它定的时限。
- 不收敛、只剩打磨（已有）。
- 来源不明：属于长任务的修改项要带 `goal`（对应任务书的哪一条，助手派活时写）；评审提出、对不上任何目标的新项标“来源不明”。

信号出现时立即唤醒助手跟进，信号原文写在那一轮的最前面。

### 5.2 助手每轮交的报告

助手每轮最后调用 `supervise_report`（跟进角色专用的交结果工具，进 `ROLE_TOOLS`）：

```yaml
status: on-track | drifting | stuck | needs-owner | done
goalCheck:             # 现在在做的各对应哪条目标；哪些是边缘的、给了多少时限
decisions:             # 这一轮自己定的，每条一句理由
  - { what: 跳过 T7（旧浏览器兼容）, why: 任务书“不做的”第 2 条 }
actions:               # 做了的纠偏：给编码负责人发话、跳过 / 以后再做某项、回退到检查点、暂停、换干活的 AI、加轮次
progress: { done: [...], doing: [...], next: [...] }
askOwner:              # 只放必须问本人的；每条带选项和助手自己的倾向
```

宿主把它变成进度卡（第 7 节），把 `decisions` 和 `actions` 记进跟进笔记。

### 5.3 助手自己也会跑偏

- **方向从任务书来，不从长会话来。** 助手的 Agent 会话每到一个阶段、或上下文超过 `sessions.background.maxContextTokens`，就换新会话；新会话读任务书和跟进笔记（宿主维护：计划、每轮的决定和理由、放下的事和原因、本人推翻过的决定）。
- **发话要有依据。** 助手给干活的发的话（`message_code_run`、`settle_code_task` 等）要带 `basis`：任务书的哪一条、本人补充的哪一句，或哪次运行、哪条测试输出。没有依据的方向性改动（改目标、碰“不做的”）宿主拒绝，提示它问本人。
- **重的纠偏先复核。** 回退到检查点、跳过对应某条目标的项、换掉干活的方案这几类，先让另一家的模型（`families.ts`）对着任务书和证据看一次，两边一致才执行；不一致的连同两边理由交给本人。可以在任务书里关掉。
- **决定都给本人看得见。** 每条自己定的事都出现在进度汇报里，本人说“这个别跳过”就进“本人补充”，下一轮照办。

## 6. 问题怎么分

- 干活的提问、要人定的修改项，属于长任务时由负责跟进的 AI 先处理（沿用“等助手处理”）。
- 在任务书授权内的，助手自己答：技术取舍、范围内的细节、重试、跳过边缘项、换干活的 AI、给交办加轮次（在总预算内）。答案记在那一项上，干活的照做。
- 在“必须问本人的”清单里、或助手拿不准而且挡着进度的，才问本人。同一轮的合成一张卡，每条写清问题、选项、助手的倾向和理由。默认本人不回就一直等；任务书里可以设“N 小时不回按助手的倾向”。
- 不挡进度的拿不准，不发卡片：写进进度汇报的“想听听你的意见”，继续做别的。

## 7. 进度

- **话题里一张进度卡**，助手每轮更新：目标、完成度、在做、下一步、最近的决定、风险、花了多少（助手和干活的用量、预算用了多少）。
- **完成度**由宿主算：修改项 14 / 20、轮数 5 / 12、时长 3.5 / 8 小时、研究的试验 6 / 8；助手可以补一句说明，不让模型自己报百分比。
- **推给本人**（私聊提醒）：开任务时选，默认“里程碑 + 要你定 + 纠偏 + 每 3 小时一条摘要”。免打扰时段只攒着，到点一条。
- **工作页、事项页**：长任务的时间线，每轮一条，点开看依据（运行、提交、修改项）。

## 8. 本人中途调整

- 在话题里直接说：进“本人补充”，马上唤醒助手跟进，这一轮先处理本人的话。
- 进度卡的按钮：暂停、继续、加预算、结束、换跟进的 AI。
- 在别的会话里说“那件事改成……”：助手用 `message_supervisor` 转到该任务的工作话题。

## 9. 怎么开始

- 命令：`/跟进 [AI] 任务`，例如 `/跟进 codex astra xhigh 把退款回调改成异步，做完前不推送`。AI 的写法同 `/<后端>` 命令（[ai-policy.md](ai-policy.md) 第 5 节）；不写就用“长任务跟进用的 AI”，未配置时取强模型档位；也可以 `/跟进 强 …`。它开一个话题，助手起草任务书发确认卡。
- 说话：“用 astra xhigh 盯着把这件事做完”，助手调 `start_long_task`（带 AI），效果同上。
- 已有的研究：研究页“交给助手跟进”；研究流程里确认方向、升档的关卡改成先过助手。
- 已有的交办：交办卡片上“交给助手跟进”，或 `/跟进 接管`（在交办的话题里），把这次交办挂到一个新长任务下。
- 在长任务的话题里：`/跟进` 看状态，`/跟进 暂停 | 继续 | 结束 | 加 3 小时 | 换 claude opus high`。

## 10. 预算、费用和可用性

- 跟进的 AI 贵，所以只按事件叫醒、合批、定时前先看有没有新事实；每天叫醒有上限（默认 40 次，任务书里改）；用量写在进度卡上。
- 属于长任务的交办，自动推进的轮数从长任务的预算里扣，助手可以自己续，不用本人说“继续”；单个交办仍受 `codeRoundsMax` 约束，到了就由助手决定开新交办还是停。
- 跟进的 AI 按 `strict` 处理：暂时用不了时等待同一个 AI，超过 `queueTimeoutMinutes` 就停止本轮，在话题中告诉本人。

## 11. 和现有部分的关系

| 现有 | 怎么用 |
| --- | --- |
| 多 Agent 工作（`agent-work.ts`）的工作话题和进度卡 | 长任务的话题和卡片沿用它 |
| 交办的唤醒（`wakeAssistantForTasks`、`wakeAssistantForCodeResult`） | 交办挂在长任务下时，改为唤醒助手跟进；`CODE_HANDOFF_DENY` 对跟进轮次不适用 |
| “等助手处理”的修改项、`settle_code_task` | 由负责跟进的 AI 处理 |
| 流程关卡、研究的轮次和升档 | 关卡加 `confirm: supervisor` |
| 唤醒（`wakes.ts`） | 定时看一眼用它；长任务自己的唤醒不占 `MAX_PENDING` |
| 事项 | 长任务挂一个持续关注类事项，时间线写每轮汇报 |

新增：`long_tasks` 表（加进 `pull-data.ts`）、`supervisor` 角色（`roles/supervisor.md`，加进 `roleNames`）、工具 `start_long_task` / `message_supervisor` / `long_task_status`（新分组 `supervise`，写进 `skills/omem/references/` 和 `SKILL.md` 的分组表）和交结果的 `supervise_report`、跑偏信号的计算（`src/agents/drift.ts`）、`/跟进` 命令。

## 12. 分期

1. 长任务和任务书、`supervisor` 角色、交办和 `run_agent` 的事件改为唤醒助手跟进、`supervise_report`、进度卡和推送、问题先到助手、`/跟进` 和 `start_long_task`。
2. 跑偏信号（改回去、出范围、拖太久、来源不明）、跟进会话按阶段换新、发话要有依据、重的纠偏先复核。
3. 研究接入（关卡 `confirm: supervisor`、研究页“交给助手跟进”）、接管已有交办、网页（工作页的长任务时间线、设置里的“长任务跟进用的 AI”）。
