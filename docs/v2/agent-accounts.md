## 插件凭据供给账号（2026-11-22）

`api.credential` 可在一次成员授权后供给多个后端。持有和到期状态放在本机的 `credential_holds`，秘密仍走密钥库。登录和续签后先完成 `provide`，然后后端才算已登录；旧的 `api.agentLogin` 契约不变。成员账号目录预建插件声明的状态目录，安装目录只读挂载；本人沙箱的默认可写清单列出这些状态目录。本人只用本机已有登录，仅调用只读 `check`。

成员自己的登录优先。允许借用时，先选开放给发起人的本人凭据，再按最近成功使用时间选其他成员。借用成员时，HOME 只挂入所选后端和凭据的状态。`account.dirs` 中其余目录在借用沙箱内以 0700 创建，供每轮写临时文件、建套接字。会话重建时重新校验出借，仅实际成功的持有更新最近使用时间。借用写运行事件和审计，`confirm` 和 `off` 均不借 AI 登录。全局策略取 `agents.accountsDefault`，逐后端的 `agents.accounts` 优先。默认 `owner` 和 `auto` 配合使用时，未登记插件凭据的后端沿用本机登录。

旧版曾把对供给文件的检查记成独立原生登录。升级后，同一成员同一后端既有这种缓存又有凭据持有记录的，以持有的有效期为准。密钥库里单独保存的后端令牌仍可使用。两种来源重叠时，仅靠文件登录的独立原生账号可以重新登录。

续签和每日检查经索引每批最多 32 份。续签失败、检查发现过期或三天内到期时，走持有人的通知出口；同一状态一天最多提醒一次。插件停用或撤销信任后不再执行回调。

## 本人的运行进沙箱

本人可为使用本机登录的 Agent 选择 Linux bubblewrap 文件系统隔离。自己的运行、访客和借用本人账号的同事都适用。成员用自己账号时继续用独立 HOME。云端和借别的设备执行的后端不进这台机器的沙箱。本人沙箱保留原来的网络连接方式，本机服务仍按各自的鉴权策略接收请求。`security.egress` 仍只控制成员账号。

`agents.ownSandbox.mode` 默认是 `off`。`prefer` 会先检查本机的 bubblewrap 和用户命名空间，不能用时在运行开头写原因并沿用原来的运行方式。`require` 会拒绝这次本地启动。探测成功后，实际挂载失败也会报错，避免把本应受隔离的完全访问运行直接放到宿主上。

**文件和环境**

- 宿主系统和本人 HOME 默认只读。后端仍能读取登录信息、SSH 配置和其他个人文件。需要保密的目录加进 `hidden`，沙箱内看到的是空目录。
- omem 数据目录整体隐藏。宿主只挂回当轮所需的目录。omem 程序、Node、命令垫片、命令闸门和技能只读。工作区按角色挂载，可写角色能修改工作树。评审只能读原工作树，可以在自己这一轮的快照里运行测试。
- 本轮产物写入 `OMEM_ARTIFACTS`（提供时）。本轮的临时工作目录是 `OMEM_RUN_DIR`，对应 `runs/<id>/scratch`。其他宿主记录留在遮蔽层下。每个进程有私有 `/tmp`，关闭后随命名空间释放。聊天可以恢复后端保存的会话，每轮重新起隔离进程。
- 后端状态路径由目录条目声明。Codex 使用 `CODEX_HOME`，默认 `~/.codex`。TraeX 使用 `TRAE_HOME`，默认 `~/.trae`。Claude 使用 `CLAUDE_CONFIG_DIR`，默认 `~/.claude`，另挂已有的 `~/.claude.json`。已有会话目录、技能写入路径和声明的登录状态按档案展开。未声明的额外路径由本人加进 `writable`。
- 默认可写缓存为 `~/.cache`（工具和构建缓存）、`~/.npm`（npm 下载及 npx 安装）、`~/.local/share/pnpm/store`（pnpm 内容存储）。状态目录和额外可写目录在不同运行间共用。
- 环境保留 HOME、后端登录和 API 凭据、SSH、代理、语言等宿主变量。`TMPDIR` 指向私有 `/tmp`。清除宿主继承的 `OMEM_*`、飞书应用密钥（含 `LARKSUITE_CLI_APP_SECRET`）、配置指定的 Telegram 和 OneBot 令牌，以及启用远程向量接口时指定的密钥变量。若一个变量同时供 omem 服务和后端使用，按服务密钥清除。运行只带本轮的 omem 工具地址和令牌，以及已分配的目录、命令闸门和桌面开关。

**完全访问**

表中每格先写未进本人沙箱的情况，再写已进的情况。“原”沿用规则、档案、内置角色或访客开关。“全”请求后端关闭它自己的沙箱和审批。后端没有相应模式时，ACP 在运行里说明并选择原角色模式。

| 运行 | `per-role`（默认） | `sandboxed` | `all` | omem 的写权限 |
| --- | --- | --- | --- | --- |
| 本人可写角色 | 原 / 原 | 原 / 全 | 全 / 全 | 原可写范围 |
| 本人只读角色、评审 | 原 / 原 | 原 / 全 | 原 / 原 | 沙箱里原工作区只读，ACP 拒绝编辑、删除和移动 |
| 访客，含交给主助手回答 | 原 / 原 | 原 / 全 | 原 / 原 | 同上，工具按访客运行原有范围 |
| 同事借本人登录 | 原 / 原 | 原 / 原 | 原 / 原 | 仍依原角色和成员授权 |
| 成员独立账号 | 原 | 原 | 原 | 沿用成员账号沙箱及原权限 |

omem 工具授权、`denyTools` 和操作规则仍生效。命中拒绝规则的命令经 PATH 上的垫片返回 126。未隔离时，原有单项完全访问设置保持原义。全局档位自动打开后端完全访问时，原开关没有新增“强制关闭”一档。

**本人设置接口**

`GET /api/security/sandbox` 返回本机支持情况及原因（`support`）、两个开关、已保存的额外目录、示例运行的默认清单（`defaults`）以及各本地档案的状态路径（`backends`）。列表里的示例工作区、产物路径随实际运行替换。网页在 设置 → 安全 的“运行的沙箱”和“完全访问”两张卡：路径按 `home` 写成 `~/…`，“按角色”下面按 `fullAccessGrants` 列出单独开着完全访问的内置角色、档案和规则，各链到对应页面。本人可用同一地址的 PUT 完整保存设置。以下配置允许已有的构建缓存目录写入，并隐藏 SSH 目录。

```json
{"mode":"prefer","writable":["~/build-cache"],"hidden":["~/.ssh"],"fullAccess":"sandboxed"}
```

额外目录各限 32 项，每项最多 1024 字符。可写目录须事先建好。保存时展开 `~/`、解析符号链接、合并重复路径。拒绝根目录、HOME 和数据目录本身或它们的祖先、宿主 `/tmp`、`/proc`、`/sys`、`/dev` 树。额外可写列表也拒绝数据目录的子路径和 `/usr`、`/etc`、`/var`、`/run` 等系统目录本身。受保护的只读工作区优先于与它重叠的可写目录。

选 `all` 每次保存都要另带 `"confirmAll":true`。未进沙箱且使用完全访问的运行不受后端的文件系统和审批限制。接口返回这条提示，并把成功的设置修改写入 `audit_events`。

## 要解决的事

omem 支持多人登录以后，同事在 omem 里提问、交办，背后跑的 Agent（Codex、Claude Code、TraeX、豆包命令行……）用的还是本人的登录。结果是：

- 额度、费用和服务端的使用记录全算在本人头上；
- 有的命令行登录后能读写这个人在平台上的东西（代码托管、文档、内部服务），用本人的账号等于把本人的权限借给了别人；
- 公司环境里，很多内部服务只认“是谁在调用”，必须用调用者自己的身份。

目标：每个成员在 omem 里登录一次各个后端，之后他发起的运行就用他自己的账号；没登录的按本人设的规则处理（借用本人的，或者拒绝并提示去登录）。

## 先看各家命令行怎么放登录态

主流命令行都把登录态放在 HOME 下的一个目录里，并且大多认一个环境变量来换这个目录。没有一家提供“同一个进程里切账号”。下表在一台 Linux 上用空目录实测过（2026-11-20：两个空账号目录同时启动，用文件跟踪看各自打开了哪些路径；都还没有用真实账号登录）。

| 后端 | 每个账号要分开的 | 无界面登录 | 实测结果 |
| --- | --- | --- | --- |
| Codex | `CODEX_HOME`、`HOME` | `codex login --device-auth`（设备码） | 空目录下 `login status` 为未登录 |
| Claude Code | `CLAUDE_CONFIG_DIR`、`HOME` | `claude setup-token` 打印长期令牌，之后可用 `CLAUDE_CODE_OAUTH_TOKEN` 直接注入 | Linux 上凭据文件和配置都落在 `CLAUDE_CONFIG_DIR`（macOS 在钥匙串，不随目录变） |
| TraeX | `TRAE_HOME`（也认 `TRAECLI_HOME`）、`HOME`、私有的 `XDG_RUNTIME_DIR` 和 `TMPDIR`（0700） | `traex login --sso-device`（设备码） | 两个空账号同时完成 ACP 初始化，各自只查自己的登录文件；技能从 `$TRAE_HOME/skills` 读；目录不能是符号链接 |
| 豆包命令行 | `HOME`、`XDG_DATA_HOME`，**还要私有的 `/tmp` 和 PID 视图** | 二维码 | 只分开目录时，两份进程用了同一个 `/tmp` 下的服务 socket，后启动的连进了前一个账号的服务；用 bubblewrap 各给一个 `/tmp` 和 PID 命名空间后才各连各的。程序可以直接从本机安装的绝对路径启动，不用每人复制一份 |

所以 omem 能用同一个办法处理所有后端：**每个用户一个账号目录（当作他的 HOME），在沙箱里启动 Agent，把对应变量指向它**。差异写进 Agent 目录（`src/agents/catalog.ts`），运行时不按 Agent 名特判。豆包这一行也说明只换目录变量不够，沙箱（私有 `/tmp`、PID 视图）是必需的，不是加固项。

## 设计

### 1. 账号目录

- 位置：数据目录下 `accounts/<用户 id>/home/`，权限 0700，不允许符号链接。它是这个人在沙箱里的整个 HOME，各后端的目录（`.codex`、`.trae`、`.local/share/doubao_cli`……）都在里面，所以不靠各家的目录变量也能分开；`account.env` 只用来补那些不从 HOME 推目录的后端。本人不用这一层，照旧用本机已有的登录。
- 目录里放什么由后端决定，omem 不读不写里面的凭据，只负责建目录、设变量、删除。
- 删除用户、用户退出某个后端时删掉对应目录（先让后端自己 logout，失败也删）。

### 2. Agent 目录里的新字段 `account`

```ts
account?: {
  /** 启动时设的环境变量，{home} 是这个用户的账号目录（沙箱里的 HOME） */
  env: Record<string, string>;            // 例：{ CODEX_HOME: "{home}/.codex" }
  /** 要预先建好的子目录（0700），比如 socket 目录 */
  dirs?: string[];                        // 例：[".run"]，配合 env 里的 XDG_RUNTIME_DIR: "{home}/.run"
  /** 沙箱里要只读挂进来的本机安装（程序从本机的绝对路径启动，不每人复制） */
  mounts?: string[];                      // 例：豆包命令行的 app/current
  /** 无界面登录：命令、从输出里认出链接和验证码的正则、超时 */
  login?: { args: string[]; url: string; code?: string; timeoutMs?: number };
  /** 查登录状态：退出码 0 算已登录，输出里认出账号名的正则 */
  status?: { args: string[]; user?: string };
  logout?: { args: string[] };
  /** 能直接用令牌登录时：令牌放进哪个变量（存在 omem 的密钥库里，按用户） */
  tokenEnv?: string;                      // 例：CLAUDE_CODE_OAUTH_TOKEN
}
```

只有带 `account` 的后端才能按人分账号。用户手动加的后端（配置里的 profiles）也可以写这一段。

### 3. 运行时怎么选账号

主编码、解冲突、编码助手、方案、编码前检查、需求拆分、评审项、评审负责人和复看都使用交办发起人的 omem 身份。角色指定的模型和档案继续生效。工具令牌、可读空间和后端账号按成员选择。任务板、`run_agent` 与 `ask_agent` 的子运行继承发起人的身份；本机流程阶段和课题试验使用事项所属成员。历史子记录缺少成员字段时，从关联的交办或父运行取回。

`agents.accountIsolation` 与按后端配置的 `agents.accounts` 分开设置。本人自己的运行沿用本机登录。

| 场景 | 默认 `prefer` | `require` |
| --- | --- | --- |
| 本机支持 bubblewrap，成员已登录所选后端 | 使用成员的 HOME 和登录态 | 同左 |
| 后端支持分账号，成员还没登录 | 按后端的 `owner`、`own`、`own-or-other` 分别借用本人、提示登录、尝试备用 | 从配置的备用后端中找可隔离的一个，找不到就报原因 |
| 自定义本机进程后端，无 `account`、无共享密钥 | 沿用服务环境 | 使用成员 HOME 启动，后端须能在该环境中工作 |
| 云端、设备代跑、共享密钥档案，或本机沙箱探测失败 | 沿用原来的后端，在运行事件中记录未隔离的原因 | 跳过这些后端，找不到可隔离的后端时停止 |

`omem diag` 的 `agentAccounts` 和 `GET /api/agent-accounts`、`GET /api/me/agent-accounts` 返回的 `isolation` 提供同一组字段。`mode` 是配置策略，`ok` 和 `reason` 描述本机沙箱探测结果。`profiles[]` 按档案给出 `id`、`execution`（`local`、`peer` 或 `cloud`）、`supported` 和原因。实际运行是否借用了登录，看该运行的状态事件。

访客（不是 omem 用户的人）不受影响：访客模式照旧用本人设的后端，它本来就只读。

### 4. 跟着账号走的东西

这些现在按“后端”区分，要改成按“后端 + 账号”区分：

- 后台会话池（`background-sessions.ts` 的 key）、会话续用（resume）：不同账号的会话不能互相复用。
- 额度（`quota.ts`）：每个账号单独读、单独记，选型时按发起人的额度避让。
- 会话记录目录（`sessionHistory.root` / `env`）、技能目录（`skills.read` / `write` 里的 `${CODEX_HOME:-~/.codex}` 这类）：按账号目录展开。omem 写进技能目录的说明（`agent-skills.ts`）在建账号目录时同步一份。
- 模型探测缓存：同一后端不同账号可用的模型可能不同（套餐不同），按账号缓存。

### 5. 登录界面

设置里加“我的 AI 账号”（每个人都能看到自己的）：

- 列出带 `account` 的后端，每个显示 已登录（账号名）/ 没登录 / 登录过期，以及本人对这个后端的规则（借用 / 必须自己的）。
- “登录”：宿主在这个人的账号目录里起 `login` 命令，从输出里认出链接和验证码显示在页面上（也可以发到他的飞书私聊），等命令结束后跑 `status` 确认。命令超时或失败就清掉进程，目录留着可以重试。
- 令牌型：粘贴令牌，存进 omem 的密钥库（`secrets/vault.db`，按用户），不进账号目录、不进配置文件。
- “退出”：跑 `logout` 后删目录。
- 本人在 设置 → 成员 → 成员的 AI 账号 能看到每个成员登了哪些后端（不显示令牌），能替他退出。

### 6. 插件提供登录方式

有的后端在公司环境里不走它自己的登录，而是用公司统一身份换来的凭据。插件可以给某个后端注册一个登录方式：

```ts
type AgentLoginContext = {
  userId: string;
  /** 这个人的账号目录（沙箱里的 HOME） */
  home: string;
  /** Agent 目录里 account.env 展开后的变量（例：TRAE_HOME=<home>/.trae）：凭据写到它们指的位置 */
  env: Record<string, string>;
  /** 宿主替插件按人保存的一份秘密（存在 secrets/vault.db，不进账号目录），比如刷新令牌 */
  secret: { get(): Promise<string | null>; set(value: string | null): Promise<void> };
  signal: AbortSignal;
};

api.agentLogin({
  backend: "traex",
  id: "company",                 // 同一个后端可以有几种登录方式，插件内唯一
  label: "用公司账号登录",
  // 引导这个用户授权（设备码或网页 OAuth），拿到凭据后写进 env 指的位置
  login(ctx: AgentLoginContext & { show(link: { url: string; code?: string }): void }): Promise<{ user: string; expiresAt?: number }>;
  // 可选：续签。宿主在 expiresAt 前（提前 10 分钟，最短 1 分钟一次）调用，也可以由“检查”手动触发；
  // 返回新的 expiresAt；返回 null 表示续不了，要这个人重新登录
  refresh?(ctx: AgentLoginContext): Promise<{ expiresAt?: number } | null>;
  // 可选：退出时清理（撤销令牌等）；宿主之后照常删目录
  logout?(ctx: AgentLoginContext): Promise<void>;
});
```

宿主只负责调用（在 omem 进程里，不进沙箱：插件只写文件）、把链接和设备码显示给这个人（网页上，以及用机器人发到他的飞书私聊，写明是 omem 为谁、为哪个后端发起的）、超时取消（11 分钟）、按 `expiresAt` 安排续签；凭据怎么换、写成什么格式由插件决定。续签失败或返回 null 时状态改成“登录过期”并通知这个人。插件要在清单里声明 `permissions.agentLogin: [<后端>]`，本人信任插件、并选“在 omem 里运行”时才生效。“我的 AI 账号”里，一个后端同时列出它自己的登录方式和插件提供的登录方式。数据目录里的公司插件就用这个让同事用公司账号登录 TraeX。

### 6.5 别人怎么做的

开源项目里，按人分账号大致有三种做法：

| 做法 | 例子 | 优点 | 缺口 |
| --- | --- | --- | --- |
| 只换各家的目录变量 | 各种多账号切换工具：每个账号一个目录，启动时设 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` | 简单，不要权限 | Agent 执行的子进程（git、gh、shell）仍用原来的 HOME，能读到本人的配置和令牌；macOS 上 Claude Code 的凭据在钥匙串里，不随目录变 |
| 每人一个系统用户 | Clay：给每个成员建 Linux 账号，用 `setfacl` 管文件权限，Agent 进程用他的 uid / gid 启动 | 由内核保证互相读不到 | 要 root 或 sudo 建用户、切用户 |
| 每人一个容器或沙箱 | agent-fleet：每人一个容器（没有 Docker 时用 bubblewrap），家目录持久，各自 `/login` | 隔离完整，HOME 本身就是他的 | 要准备镜像或沙箱里的程序，后端自带的沙箱要能嵌套 |

可以借用的组件：Anthropic 开源的 sandbox-runtime（`srt`），Linux 上用 bubblewrap，macOS 上用 sandbox-exec，同时管文件和网络，能包住任意进程。

所以只换目录变量不够：Agent 跑的命令会继承真正的 HOME。omem 第一期就把**整个 HOME 换成这个人的账号目录**，并在 Linux 上用 bubblewrap 启动（不需要 root）：只读挂系统和程序，可写挂他的 HOME 和这次运行的工作目录，别人的账号目录和 omem 数据目录不挂进去。

### 6.6 支持哪些系统

- 第一期只支持 Linux，并且要求装了 bubblewrap、允许非特权用户命名空间（启动时检查一次）。
- 不满足条件的机器（macOS、Windows、没有 bubblewrap 的 Linux）不提供多账号：账号页不显示“我的 AI 账号”，设置 → 成员 不显示“成员的 AI 账号”，默认模式记录原因后沿用本机后端，严格模式停止成员运行。
- macOS 以后再看：钥匙串、豆包命令行的数据目录（`~/Library/Application Support`）、sandbox-exec 都要单独验证。
- Windows 以后再看，候选做法（都还没试）：
  - **每人一个本地 Windows 账号**，用那个账号的身份启动 Agent（CreateProcessWithLogon 一类）：文件隔离由系统权限保证，相当于 Linux 上每人一个系统用户。sandbox-runtime 在 Windows 上就是这样做的（还是 alpha）。要管理员建账号，并保存每个账号的登录凭据。优先试这个。
  - **AppContainer**：系统自带的轻量沙箱（浏览器渲染进程用的那种），进程只能访问显式授权的文件、注册表和网络。授权靠给目录加 ACL，Agent 要用的程序、Node、git 都要逐个放行，适配量大。
  - **受限令牌 + ACL**：能限制 Agent 执行的命令往哪里写，但不按人分开，只能作为补充。
  - **Windows Sandbox / Hyper-V 容器**：本质是虚拟机，要专业版或企业版，启动慢，不考虑。
  - 另外要实测各后端在 Windows 上把登录态放在哪（`%USERPROFILE%`、`%APPDATA%`，或凭据管理器）。

### 7. 隔离的边界（重要）

同一台机器、同一个系统用户跑所有人的 Agent 时，账号目录只能防止“串号”（A 的运行用了 B 的账号），**防不了一个能执行命令的 Agent 去读另一个人的账号目录**：它们的文件属于同一个系统用户。

bubblewrap 隐藏宿主 HOME、数据目录和临时目录，再按运行的计划挂回需要的目录。普通运行的 cwd、成员 HOME 和产物目录可写。编码交办由宿主指定各仓库的工作树。沙箱可写挂载实际的工作树目录，在本轮私有目录里还原多仓链接。编码前检查沿用相同的多仓入口，只读挂载分配的工作树。Git 公共目录按原仓库定位，只读挂载。每轮主编码及每个助手按仓库分配私有 Git 元数据。成员可以直接 `git add` 和 `git commit`。主编码用 `name_work_branch` 命名自动分配的临时分支，宿主同步改名并更新接收登记。工作树里的 `.git` 在沙箱内指向私有目录，宿主仍看到原来的工作树。

`finish_task` 接收成员分支上从预期基点开始的提交，保留原提交号。主编码和助手即使已经提交过，留下的文件改动也会在成员最新提交之上补交，提交信息标明当前修改项。接收使用独立的导出环境，禁用钩子；进入宿主对象库前由 Git 校验对象。宿主只推进登记的工作分支或助手工作树的游离 HEAD。分支或基点已变时，接收报错，成员提交保留在本轮私有目录。

助手某个仓库交付失败时，主轮仍拣入各仓已经接收的提交。宿主在只读沙箱里分别读取当前 HEAD 和登记分支自上次接收以来的提交，按提交号去重，用提交标签识别受影响的修改项。任一引用或文件状态读失败时，已读到的标签继续参与结算，归属标记为待核对。未完整合入的修改项回到待做，失败原因记在任务时间线上，助手工作树和私有提交保留。

同步分支或拣选助手提交遇到文本冲突时，Agent 编辑冲突文件。宿主检查原先有标记的文件，按路径暂存清除了标记的文件，再检查剩余冲突。

宿主在工作区准备依赖，直接运行项目的安装命令。仓库检查和度量也由宿主执行，走仓库命令垫片。两种操作均在启动前写审计和运行事件，带发起成员、根交办、当前轮次和仓库。助手工作树触发安装时，审计也关联到助手运行，运行事件记在该助手名下。

设备代跑的 ACP 后端在执行节点启动。命令垫片使用执行节点的闸门、规则和审计，按发起成员匹配范围。成员账号目录尚未跨设备挂载，因此要求隔离的成员运行会跳过设备代跑。另一个独立入口“派课题试验到设备”只接受本人的试验。

以后如果有 root，可以换成每人一个系统用户（Clay 的做法），隔离由内核保证，也不再需要嵌套沙箱。

### 7.5 沙箱里的命令规则（以后）

[命令规则](command-gate.md)现在靠在 PATH 最前面放同名包装来拦，它自己写明了拦不住的几种：用绝对路径调用真正的命令、Agent 改 PATH 或改写拦截目录、直接调命令背后的接口。沙箱能把前两种堵上，第三种也能大幅收窄：

- **真正的命令不进沙箱**：受保护的命令在沙箱里只挂成包装（`--ro-bind <包装> <真实路径>`，绝对路径调用也落到包装上），真正的程序和它的配置、令牌（多半在本人的 HOME 下）都不挂进去。
- **批准后由宿主执行**：包装问 omem，放行时由宿主在沙箱外运行真正的命令，把标准输入输出和退出码转回来；工作目录在沙箱内外是同一个路径，所以命令看到的文件一样。这就是 command-gate.md 末尾说的“凭据代理”：令牌只在宿主那边，Agent 拿不到。
- **拦截目录和规则只读**：沙箱里看不到数据目录，包装文件是只读挂载，Agent 改不了。
- **还拦不住的**：Agent 自己带的代码直接调这些服务的接口。命令的令牌不在沙箱里，它多半没有凭据可用；严格成员运行已接入[出网代理](command-gate.md#出网代理)，由本机代理按目标主机或指定域名的路径再判定。
- 成员的运行由宿主代执行时用的是本人的凭据，所以成员触发的受保护命令一律要审批，审批卡片上写明“以本人身份执行”。
- 本人自己的运行现在不进沙箱（要用本人的登录和本机的一切）。可以加一个开关，让本人的运行也在沙箱里启动：挂本人的 HOME，只把受保护命令的程序和配置目录挡掉。

前提是第一期的沙箱启动已经稳定；只在支持沙箱的系统上生效，其他系统照旧用 PATH 包装。

### 8. 不做的

- 不在宿主里替后端换凭据、刷新令牌：凭据由后端自己（或插件）管。
- 不把本人的登录复制给成员：刷新令牌可能是轮换的，副本一刷新本人的登录就可能失效。
- 不按用户限额：额度由各平台按账号算，omem 只显示。

## 分期

1. Agent 目录的 `account` 字段（TraeX、豆包命令行、Codex、Claude Code），账号目录（整个 HOME）的建立和删除，bubblewrap 启动和启动前的系统检查，`prepareRun` 按发起人选账号，设置 `agents.accounts`。后台会话池、续用、额度、探测缓存按账号区分。
2. “我的 AI 账号”页面：设备码 / 二维码登录、令牌粘贴、状态、退出；本人的总览。系统不支持时整页不出现。
3. 插件的 `api.agentLogin`（公司插件用它做 TraeX 的公司账号登录）。

## 要先验证的

- 每个后端在独立账号目录里能完成一次完整的 ACP 往返（初始化、建会话、一轮对话）。
- 同一后端两个账号目录同时运行互不干扰；同一个账号在两个目录里同时运行会怎样（有的后端限制单个共享服务）。
- 设备码登录的输出格式（链接和验证码能不能稳定地用正则认出来）。
- 沙箱里没有系统钥匙串（keyring）时，各后端的登录态能不能落在文件里、跨进程保留。有的命令行在没有钥匙串的环境里只把令牌放在内存里，换个进程就要重登。

### 本人沙箱的状态字段

`GET /api/security/sandbox`（仅本人）增加 `home`：规范化后的当前主目录，客户端可据此将子路径写作 `~/…`。`fullAccessGrants: { roles, profiles, rules }` 分别列出单独打开完全访问的内置角色、档案和规则，每项 `{ id, name }`；规则按已保存的授权列出，停用规则仍保留设置。全局 fullAccess 档位仍单独返回，不扩展成员权限。规则清单通过 rules_full_access 部分索引读取，迁移只在数组末尾追加。

### 档案与技能列表的操作权限

`GET /api/agents` 与 `GET /api/skills` 按 agents.view 授予查看；每项新增 `canEdit`、`canDelete`，按当前调用人的档案管理权限计算。插件自带且未在本地覆盖的档案 canDelete 为 false；可改成自己的副本。没有 agents.manage 的成员调用删除档案或技能接口仍返回 403。成员档案列表只返回名称、说明、状态及 AI 选择，不带工作路径、工具授权或私有正文。

### 豆包 CLI 的工作目录能力

本机 CLI 启动前只用 `--help` 探测目录参数，优先识别声明的 `-C`，也支持 `--cwd` / `--directory` / `--workdir` / `--working-directory`；目录参数放在 `--resume`、`-p` 之前。帮助未声明时直接使用进程 cwd。探测按实际二进制、文件时间与大小、启动参数和账号目录缓存，不按版本号选择。帮助只读，无需登录，不发起会话。

进度接口 `/api/runs/:id/progress`、`/api/items/:id/progress` 的任务 attempts 增加 `access?: "read" | "write"`，保留任务板每次尝试的访问档位；普通本地运行没有显式设备档位时省略。

### 检索设置的只读后端列表

有 settings.knowledge.view 的成员读取 `GET /api/settings?section=knowledge` 时也得到 agents 后端摘要与 unavailableBackends。摘要只包含 id、name、installed、transport、model、effort、pluginBackend、canProbe 和裁剪后的 probe（at、models、efforts、effortsByModel），成员 canProbe 为 false；不含命令、参数、环境变量、工作路径或密钥。列表的模型缓存以一次 kv 主键查询批量读取，优先使用当前成员自己的缓存，再用宿主缓存。

`POST /api/agents/:id/probe` 对有知识或 AI 查看权的成员只读缓存，返回 `{ agent, models, efforts, at?, effortsByModel?, cached: true, readOnly: true }`；没有缓存时返回空模型和强度数组，不启动后端。refresh=true、实际探测和修改设置仍仅本人。网页应据 canProbe 隐藏“重新检测”，直接使用列表中的缓存。
