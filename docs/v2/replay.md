# 夜间复盘：换一条信息路径再答一次

一次回答好不好，主要取决于信息怎么进来：查了哪些说法、看了哪些空间、带了哪些记忆和页面。只换模型重答，赢了也说不清是模型更好还是它碰巧多查了一次。夜间复盘每次只改一个变量，大多数变量是信息路径，模型只是其中一个轴；结果按“题型 × 变体”累计，再用到记忆复核、原件级别、Wiki 和任务选型上。

代码在 `src/agents/replay.ts`（选题、两臂、检查、评判、改动）和 `src/agents/replay-view.ts`（回到当时）。

## 一 一次复盘的流程

原题 → 回到当时（as-of t）→ 两臂：**基线重跑**（档案和设置不变）+ **变体**（只改一个轴）→ 确定性检查 → 盲评 → 归因 → 改动。

- **回到当时**：t 是提问的时间（问答取本人那条消息的时间，档案运行取运行创建时间）。
  - 记忆按 supersede 链取 t 时有效的版本：t 之后写的不出现，t 之后才被更正或撤回的按当时的样子出现（撤回原因不给）。本人纠正后补记的记忆会泄题，所以必须这样。
  - 原件：t 之后才收进来的不存在；聊天和对话原件逐行截到 t 之前（行上有飞书消息 id 或 omem 消息 id 时按精确时间，否则按行首的分钟，同一分钟算之后）；文档和页面只有最新版，t 之后改过的标“可能泄题”。
  - 事项：t 之后建的不出现，进展只给 t 之前的。
  - 会话只给提问前最近 8 轮；任务开头的“现在”写 t。
  - 不给 `read_run`、`list_runs`、`read_conversation`（能直接读到原运行和本人的纠正）。
- **为什么重跑基线**：原答案是在旧库上做的，直接拿来比，会把“库变了”算成“变体赢了”。

## 二 变体轴

| 轴 | 变体 | 实现 | 回答什么问题 |
| --- | --- | --- | --- |
| 检索 | R1 深检索：先列三种说法、`scan` 穷举再答 | 任务里加一段说明 | 没找到是因为查得浅吗 |
| | R2 加相关和可访问的空间 | 运行不限空间，任务说明用 `space='*'` | 答案在别的空间吗 |
| | R3 研究档案 | frontmatter `traits` 含 `research` 的档案（宿主不认名字）；它的外部 MCP 只放行标了 `readOnly: true` 的 | 本库缺材料吗 |
| 原件级别 | S1 只看重点 + 仅检索；S2 连忽略的一起看 | 运行级参数 `sourceLevels`，检索、扫描、读原件按它过滤 | 级别定得对吗 |
| 记忆 | M1 去掉原运行碰过的记忆；M2 全去；M3 去掉存量整理写的经验 | 运行级参数 `memoryFilter`，作用于提示里的偏好与经验、被动召回、`recall`、`search`、`scan`、`read_source(mem:)` | 记忆帮了忙还是误导了 |
| Wiki | W1 不给页面；W2 先读页面 | W1 去掉页面工具、检索不出页面；W2 任务说明 | 页面有用吗，过时了吗 |
| 模型 | A1 降一档；A2 升一档 | `replay.models` 列出的阶梯（便宜到强）；没列时在同一模型上降或升一档思考强度 | 这类题用哪个模型 |
| 技能 | K1 加挂一个候选技能 | 未实现 | 这套做法值不值得固化 |

M1 的“碰过”：原运行 `memory_recalls` 里的记忆（`recall` 和被动召回给过的）、工具事件里 `read_source(mem:…)` 读过的、回答里 `mem:` 引用的，加上基线这一臂提示里带的偏好与经验。M2 每周最多两次。

## 三 怎么选题、选轴

候选是最近 `replay.days` 天（默认 3）本人的问答（`ask`）和档案运行（`agent`）；唤醒、协调轮次、请教、被监听群的批量消息、规则的静默排查不选。每条候选取最强的一个信号：

| 信号 | 怎么判断 | 默认的轴（按顺序取第一个适用、这题没试过的） |
| --- | --- | --- |
| 负面表情 | `feedback` 里这次运行的负面表情 | M1 → S1 → W1 → A2 |
| 本人纠正 | 回答后 6 小时内本人在同一会话的下一句以“不对、错了……”开头 | M1 → S1 → W1 → A2 |
| 回答说没找到 | 回答开头符合“没找到”的说法 | S2 → R2 → R1 → R3 → A2 |
| 超时失败 | 失败原因是无活动、没有开始回答等；工具报错是 bug，不复盘 | A1 |
| 正面表情 | 每晚最多一题，作对照，量评判的误报率 | 随机一个适用的轴 |
| 慢 | 用时高于同类运行近 14 天的 p75（至少 8 次） | A1 → M3 |
| 正常完成 | 以上都不是 | A1 |

信号到轴的表在 `replay.plan`，设置页可以改。轴是否适用由宿主判断，不调模型：

- 预检：用问题在全部级别、所有可访问空间里检索（按 t 过滤），看命中落在哪。只在被忽略的原件里有 → S2；只在别的空间有 → R2；本空间有 → R1；哪都没有 → R3（没有研究档案就跳过）。
- M1 要有碰过的记忆；S1 要原运行引用过一般或忽略级别的原件；W1 要原运行读过页面；W2 要预检命中页面而原运行没读；A1 / A2 要阶梯上有下一档。
- 一题只跑一个变体；同一题同一轴不重跑。

每晚题数 `replay.max`（默认 1）由本人设，按信号强弱排序；两题以上时，如果当晚没有 A1，留一题给降级测试（它对选型帮助最大，也不需要失败信号）。

## 四 隔离、检查、评判

- **隔离**：每臂是一次普通运行，开新会话。工具只给只读的（`list_spaces`、`search`、`scan`、`read_source`、`source_outline`、`list_sources`、`find_symbol`、`list_pages`、`read_page`、`recall`、`list_items`、`list_skills`、`read_skill`）；写入仍按影子运行处理（`shadow_writes`），飞书、通知、唤醒、交办、问本人都没有。后端用只读模式，工作目录是临时目录。两臂共用一份检索缓存：同一个（工具，参数，t）只算一次（按最宽的条件算），各臂在缓存的结果上按自己的视图过滤。
- **时间**：不设 token 上限。每臂照常受后端的空闲超时限制，另外最长 30 分钟。存量整理（digest / triage）在跑或排队时顺延 20 分钟，最多 6 次。
- **确定性检查**先过：`src:` / `mem:` 能解析；行号在范围内；引用的记忆、原件、消息不晚于 t（晚于 t 算泄题，这题作废）；说“没找到”而另一臂引用的那一行确实存在，说没找到的一臂不过。没过检查的一臂直接判负，不送评判；两臂都没过记持平。
- **评判**：内置角色 `replay-judge`，不给工具，一次调用。宿主把问题、提问前的会话、两臂答案、各自引用解析出来的原文片段、本人事后的反应（纠正的话、表情）交给它。两种顺序各评一次，结论一致才算胜负，否则记持平；顺便从 `replay.taskTypes` 里给题目标一个题型。
- **评判用哪个模型由本人选**：在 Agent 页给 `replay-judge` 设默认 AI。没选之前夜间复盘不运行，记下原因，设置页和 Agent 页提示“先给 replay-judge 选模型”。评判和主助手是同一家的模型时只提示（同一家的模型偏爱同类写法），不拦。

## 五 结果改什么

| 结论 | 改动 | 方式 |
| --- | --- | --- |
| M1 胜（去掉记忆后答对了） | Agent 写的那几条清空 `reviewed_at`、重新排进复核，`review_note` 写“复盘 rp_x：去掉后答对”；supersede 还是撤回由 memory-reviewer 决定。本人写的只提示 | 自动 |
| 基线胜 M1 | 这几条记一次“帮上忙”；复核时能看到，做梦合并重复时保留帮过忙的 | 自动 |
| M3 胜 | 近 28 天两次以上时写进做梦的任务：存量整理写的经验噪声大，优先归并 | 提示 |
| S1 胜 | 基线引用、变体没引用的一般 / 忽略级别原件：建议降为“仅检索” | 卡片按钮 |
| S2 胜 | 答案在被忽略的原件里：建议改回“一般关注”（由整理规则定级的会注明） | 卡片按钮 |
| R2 胜 | 列为空间关联候选，交给做梦第 7 步 | 自动 |
| R1 胜 | 记下；coach 复盘该档案时读到，同题型反复胜才提提示词建议 | 本人确认 |
| R3 胜 | 本库缺材料：建议建事项“导入材料” | 卡片按钮 |
| W1 胜 | 基线读过的页面排一次页面检查（不管引用的原件变没变） | 自动 |
| A 轴 | 计入选型证据（见六） | — |

每条改动记进 `replay_effects`；需要本人决定的，9:30 的事项清点卡片和 Agent 页都有“采纳 / 忽略”。

## 六 怎么帮以后选模型

- 按（模型，题型，对照的模型）汇总近 28 天模型轴的胜 / 平 / 负和上下文峰值之比。只统计单变量对比，所以“A1 持平”可以直接读成“便宜一档也够用”。
- `list_ai_backends` 给每个模型附 `replay28d: [{type, vs, w, t, l, tokens}]`，少于 3 次的不出；任务选型说明里有一句“replay28d 是夜间复盘的单变量对比，样本小，只作参考”。宿主不据此自动换模型。
- 每晚一题时，模型轴一个月二三十次，分到六个题型每类只有几次，只能看出明显的差距。

## 七 早上的卡片

9:30 的事项清点卡片加一节“昨晚复盘”：每题一行（问题摘要 · 改了什么 · 结论 · 一句原因），已经自动处理的数一下，下面列出需要本人点的建议，每条有“采纳 / 忽略”按钮。全是持平时只写一行“N 题都持平”；当晚没有复盘就没有这一节，只有复盘时也会发卡片。表情里 OK、DONE、+1 这类只表示收到，不算好坏。公开评测不在夜里跑。

## 八 表、任务、角色、设置

- 运行类型：`replay`（每题一个，父运行，同一 lane 一题一题跑）、`replay-arm`（两臂）、`replay-judge`（评判，两种顺序各一个）。
- 表：`replays(id, task_run_id, signal, task_type, axis, variant, as_of, base_run_id, baseline_run_id, arm_run_id, touched, checks, verdict, judge, cost, status, at, finished_at)`；`replay_effects(id, replay_id, target_kind, target_id, effect, note, status, at, resolved_at)`。两张表随 `omem peer pull` 同步。
- 配置 `replay`：`max`（每晚题数）、`days`（选题范围）、`taskTypes`、`plan`（信号到轴）、`models`（A 轴阶梯）。设置 → Agent → 夜间复盘。
- 定时任务 `replay` 4:30（在 profile-review 4:10 之后），默认关；开关就是设置页那个开关。
- 手动：`omem replay run [--run <运行id>] [--axis <轴>]`、`omem replay list`、`POST /api/replays/run`、`GET /api/replays`、同伴命令 `replay-run`、`replays`（只读），`omem diag` 带复盘状态。
- runRole 新参数 `replay: { view, tools }`，`view` 含 `asOf`、`sourceLevels`、`memoryFilter`、`noPages`、`cache`。档案 frontmatter 加 `traits`；MCP 条目加 `readOnly`。
- 角色：`replay-judge`（新增）；coach、dreamer 的说明各加一段“读复盘证据”。

## 九 还没做

- K 轴（加挂一个候选技能）。
- coach 按近 28 天的汇总证据（某题型某变体 n≥8，降级时胜 + 平 ≥75%、升级时胜 ≥60%）提 `routing.candidates` 的设置建议。
- 胜出的题收进私有回归集。
- 第一周要量的指标：两种顺序的一致率（目标 ≥80%，状态里有“评判一致”的计数）、对照题上变体被判胜出的比例（误报率，目标 ≤20%）、泄题作废数（目标 0）、每题用时和上下文峰值、基线重跑和原答案的差异（噪声）。达标后再把每晚题数往上调。
