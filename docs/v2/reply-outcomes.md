# 回复发出后有没有用

状态：已实现（2026-11-15）；夜里复查 2026-11-20。飞书真机、真实的决策模型和复查用的真实模型还没有验证。下一步（按件判、细分“被追问”、任务类型、提问人和模型的维度、查数记录）的设计在 [回扫](reply-sweep.md)。

## 为什么要有

以前判断一条回复有没有用，靠三样：别人点的表情、本人在同一个会话里的下一句话是不是像纠正（按固定说法匹配）、运行失败或超时。表情很少有人点；固定说法漏掉委婉的纠正；助手在群里回答别人（同事 @ 它、访客提问、规则触发的回答）的那部分，只有表情这一个信号，等于没有人评。

回复之后大家说的话本来就在库里：会话里的下一条消息、群里的后续消息。这里把它们读成这条回复的结果。

## 怎么判

1. **登记**。回答别人的运行（问答、访客提问、私聊指令、交给 Agent 的、规则触发的回答）每发出一条回复，登记一次：会话里的助手消息（`threads.ts` 的 `addMessage`）和机器人在飞书里发的回答（`lark-feedback.ts` 的 `recordLarkSent`）。一次运行发了几条，以最后一条的时间为准。巡检、简报、协调轮次、唤醒发的消息不算回答，不登记。
2. **等**。默认等 6 小时（`replies.outcome.afterHours`），让后续的话有时间出现。
3. **取后续**。两处：同一个会话里之后的用户消息（最多 8 条）；同一个飞书群里之后的消息（只取人说的文字，机器人和系统消息不算）。群里优先取回复它的、和它在同一个话题里的；没有这样的，只取回复后两小时内的，再晚的多半在说别的事。同一条消息两处都有时只算一次。最多 12 条。
4. **标**。
   - 一句后续都没有：直接记“没人接话”，不问模型。只有表情：正面记“解决了”，负面记“被纠正”。
   - 有后续：把“问的是什么、助手答了什么、之后大家说了什么”交给决策模型，五选一：

     | 标注 | 含义 |
     | --- | --- |
     | 解决了 | 提问的人接受了：道谢、确认解决、照着做了，或在回答的基础上继续往下推进 |
     | 被追问 | 就同一件事追问、要求补充或又问了一遍，回答还不够 |
     | 被纠正 | 有人指出回答不对、不全、答非所问，或让它重查 |
     | 别人接手了 | 本人或别人自己把问题答了、处理了，没有用上这条回答 |
     | 看不出 | 后面的话和这条回答无关 |

   - 决策模型给自己选的那一项的概率低于门槛（`replies.outcome.threshold`，默认 0.6）时，按“看不出”算，原来选的是哪一项照样留着。
   - 没有配决策模型，或它一直答不上：每小时再试，一周后记“没判”。

标注在巡检的每个节拍里顺带做，一次最多 12 条，不占巡检的时间（不等它跑完）。

第一次启用时，把最近一周已经发出的回答补登记一次（按各自最后一条消息的时间），这样不用等一周才有数；更早的不补。

## 标错了怎么办

决策模型是小模型，会错。第一遍的标注留着不动，之后重看这次运行的人可以改判，以改判为准：

| 谁 | 怎么改 |
| --- | --- |
| 夜里复查 | 见下一节：每晚挑一批，同意的记同意，不同意的改判 |
| 夜间复盘的评判 | 评判材料里带着这条标注和它依据的那几句话。两种顺序的评判都认为该标成另一个，宿主就改判 |
| coach | `read_run` 里能看到标注和依据；复盘一个档案时发现标错了，用 `revise_reply_outcome` 改，并写一句依据 |
| 本人 | 运行页的“回复发出后”一栏，点另一个结果就改，可以写一句依据 |

本人改过的（运行页改判）是事实，之后复查、复盘评判和 coach 都不再改它（`reviseReply` 对别人返回 409，复盘评判跳过）。

被改判的次数会数出来（“用在哪”一节）：改得多，说明决策模型在这件事上不可靠，该换一个或调门槛。

## 夜里复查

第一遍只看发出后几个小时、最多十来句，而且大多没人再看：常驻服务器上约七成是把握不够的猜测。每晚（定时任务 `outcome-review`，05:20，默认开）再读一遍（`src/agents/outcome-review.ts`）：

1. **挑哪些**。一到三天前发出的回答（`replies.outcome.review.days`，默认 3；至少满一天，后面一整天的话都在），只挑第一遍是决策模型标的；本人标的、本人改判过的、按表情记的、已经被谁改判或复查过的都不挑。宿主记的“没人接话”只在后来有动静时才挑。按这个顺序：
   - 后来的动静和标注对不上（几条查询就能算出来）：提问的人一天内又问了差不多的话（同一个人、问题的字对重合四成以上）；提问的不是本人、本人之后在那里自己答了（回复它或同一话题，或两小时内，或「有人找你」的案例里本人自己回了）；有人点了负面表情；有人说“不对”“错了”这类话。比如标着“解决了”，提问的人第二天又问了一遍。信号越多越靠前；
   - 第一遍的把握低于门槛（按看不出算的那些），把握越低越靠前；
   - 第一遍标的是“看不出”；
   - 再从有把握的里随机抽 `sample` 条（默认 5），用来看第一遍平常准不准，不因为当晚名额有空就多抽。
   每晚最多 `max` 条（默认 30），每 `batch` 条（默认 10）一个运行；还有没跑完的复查时当晚不再排。
2. **谁来读**。内置角色 `outcome-reviewer`（在 Agent 页给它选一个比决策模型强的模型），只读工具 `read_run`、`read_conversation`、`read_source`、`search`，交结果用 `review_reply_outcomes`（只给它用）。每条回答的材料：问的、答的、第一遍标了什么和看到了哪几句、发出后一整天里那个会话或群里的消息（回复它、同一话题、两小时内，以及提问的人和本人之后说的，最多 40 条）、表情、本人之后的动作、同一个群里相近的案例、这个群以往回答的结果。角色说明写明：没人说话不是信号，本人的话和表情是事实，宿主算出的信号只是线索。
3. **怎么记**。每条交一个结果和一句依据，结果在第一遍的五种之外多一个“没人接话”（一整天里没人就这件事说过话）。和第一遍一样记为同意（`checked = 'confirmed'`），这时把握低的第一遍标注就按它本来的选择算，不再按看不出算；不一样就是改判（写进 `revised_*`，`revised_by` 是“夜里复查（模型）”，`checked = 'revised'`）。第一遍的标注都留着。

复查同意的比例就是第一遍可信多少。因为先挑的是可疑的，整体的同意比例会低于第一遍的实际准确率；随机抽的那部分单算，更接近第一遍平常的准确率。

## 用在哪

- **数据页**“做得怎么样”：一张小表“回复发出后的结果”，按回答的是谁分行（对话里的回答、别人问机器人的、规则触发的回答、交给 Agent 的），列是五种结果；“回复有用的占比”= 解决了 ÷（解决了 + 被追问 + 被纠正 + 别人接手了），没人接话和看不出的不算；“被复盘改判的”单列一个数。这些都按改判后的结果算，复查同意的按第一遍的选择算。有复查过的回答时，再加三个数：“夜里复查过的”、“复查同意第一遍的占比”和“随机抽查里同意第一遍的占比”。每个数都能点开看是哪些运行。
- **每天的用量**：指标 `omem.reply_outcomes` 按改判后的结果分，维度有谁判的（本人 / 表情 / 宿主 / 模型）、有没有改判过、复查同意还是改判（`review`）。复查在发出一到三天后，所以每天记新的一天时，前四天的这个指标会删掉重算。
- **运行页**：“回复发出后”一栏写结果、谁标的、把握多少、依据的那几句话；复查同意时多一行“夜里复查（模型）同意：依据”。
- **夜间复盘挑题**：标成“被纠正”的回答按“本人纠正”同等对待，优先重答。
- **整理消息的运行**：群聊原件后面多一行“助手在这个会话里以往的回答：N 条里，解决了几条、被追问几条……”，和“本人对以往提醒的反应”并列。全是看不出的时候不写这一行。
- **读运行的 Agent**：`read_run` 的结果里带着它。

## 数据

`reply_outcomes`，一次运行一行：发出时间、渠道、会话或群、第一遍的标注（`label` / `confidence` / `by` / `evidence`）、改判（`revised_label` / `revised_by` / `revised_why`）、夜里复查（`checked` 同意或改判、`checked_label` / `checked_by` / `checked_why`、为什么挑它 `checked_pick`、`checked_at`）、该判的时间（`due_at`）。随运行一起拉取到别的设备。

设置在 设置 → 代你回复 → 回复发出后看有没有用：开关、等几小时、每晚复查的开关和每晚最多几条（`replies.outcome.review` 里还有 `batch`、`sample`、`days`）。关掉以后不再登记，已经标的留着。

## 没做的

- 只读文字：后续消息里的图片、文件、卡片操作不算。
- 以本人身份发出的回复（“有人找你”的自动回复）不在这里：它有自己的记录（草稿照发、改了再发、不发）。
- 夜里复查只用假的复查运行测过（`test/outcome-review.test.ts`），没用真实模型跑过；同意比例多少、改判站不站得住，要看过几晚的结果再说。
- 复查只看那个会话或群；本人在别的会话里问助手同一件事、事项上的变化不算进“本人之后的动作”，复查的角色要自己用 `search` 找。
