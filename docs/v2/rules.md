# 规则：什么情况下自动叫哪个 Agent 做什么

本人用一句话描述“遇到什么情况就做什么”，omem 在消息到来、发现新群或定时巡检时判断是否满足，满足就执行动作（交给某个 Agent、开话题处理、拉机器人进群、优先采集、通知本人）。判断先用确定的条件（便宜、可预期），条件写不出来的部分交给模型判断；模型可以把一句话规则“固化”成条件，本人看得懂、改得动。

## 例子

| 本人的话 | 触发 | 条件 | 动作 |
| --- | --- | --- | --- |
| 群名包含“答疑”或群里有“问答机器人”时，把助手拉进群，等用户提问后交给 support-agent 尝试解决 | 新消息（每个群只触发一次） | 群名包含“答疑” 或 群里的机器人包含“问答机器人” | 拉机器人进群；持续监听：@ 机器人的消息交给 support-agent，回复先给本人看 |
| 报警群里，A 或 B 发报警卡片时，在卡片下开话题让 alert-analyst 分析，需要关注就 @ 值班人 | 新消息 | 群名包含“报警” 且 发送人是 A、B 之一 且 消息是卡片 | 交给 alert-analyst：从这条消息开话题，可以直接回复（结论和 @ 值班人写在话题里） |
| 值班群里我被 @，立刻把机器人拉进群，并优先采集 | 新消息（每个群只触发一次） | 群名包含“值班” 且 @ 了本人 | 拉机器人进群；优先采集这个群 |
| 有人在任何群里提到“合同到期” | 新消息 | 消息包含“合同到期” | 通知本人 |
| 每天早上看一眼发布群，有没有失败的发布 | 定时（cron） | （无，交给模型） | 交给 release-checker，结论通知本人 |

## 模型

一条规则（表 `rules`）：

- `description`：本人的原话，规则的依据。条件和动作都可以重新从它生成。
- `trigger`：`message`（新消息，含卡片）、`chat-new`（第一次看到的群）、`schedule`（cron）。`once: "event" | "chat"`：每条消息都可能触发，或每个群只触发一次（拉机器人、开始监听这类）。
- `conditions`：确定的条件（JSON，见下），可以为空。
- `judge`：`code`（只看条件）、`ai`（只交给模型）、`code+ai`（条件先筛，命中的再请模型确认）。条件为空时只能是 `ai`。
- `actions`：按顺序执行。
- `enabled`：助理替本人建的规则默认不启用，本人在规则页启用。

### 条件

```json
{ "all": [
  { "field": "chat.name", "op": "contains", "value": "报警" },
  { "any": [ { "field": "sender.name", "op": "in", "value": ["小王", "小李"] }, { "field": "sender.email", "op": "endsWith", "value": "@example.com" } ] },
  { "field": "message.type", "op": "equals", "value": "interactive" }
] }
```

字段：`chat.id`、`chat.name`、`chat.kind`（group / p2p）、`chat.bots`（群里的机器人名字，第一次用到时用本人的 lark-cli 读成员，缓存一天）、`chat.hasOwnBot`（群里有没有 omem 自己的机器人，按 `lark.appId` 比对成员的应用 id，不看名字；机器人收到的消息直接算有；读不到成员时视为未知，is true / is false 都不成立）、`sender.name`、`sender.email`、`sender.kind`（owner / user / bot）、`message.text`、`message.type`（text / post / interactive（卡片）/ image / file…）、`message.mentionsOwner`、`message.mentionsBot`、`message.inTopic`、`message.cardTitle`。运算：`equals`、`contains`、`startsWith`、`endsWith`、`matches`（正则）、`in`（列表）、`is`（布尔）。组合：`all`、`any`、`not`。

“固化成代码”就是这份 JSON：宿主直接求值，不执行模型写的程序。模型从规则原话生成条件，本人在页面上看到的是一句句“群名包含 报警”，可以直接改；生成后先在最近的消息上试一遍，看命中了哪些。

### 判断

1. 触发类型和范围不对的直接跳过。
2. `code`：条件求值。`ai`：把规则原话和这条事件（群、发送人、消息正文的前一千字）交给一次模型调用（无工具），回答是否满足和一句理由。`code+ai`：条件先筛，命中的再问模型。
3. 只交给模型的消息规则，每条规则每小时最多问 60 次，超出的跳过并记录；这类规则建议先固化出群名之类的条件缩小范围。
4. 每条事件对每条规则只处理一次（机器人实时事件和本人采集都会看到同一条消息，按规则 + 消息 id 去重；`once: chat` 按规则 + 群去重）。

### 动作

- `agent`：交给某个 Agent 档案。`ownTopic` 从触发消息开一个话题在里面处理（机器人要在群里）。`reply`：`none`（只把结论发给本人）、`draft`（它要在群里说的话先变成给本人的确认卡片）、`auto`（可以直接在这个群 / 话题里回复和 @ 人）。它只能往这个群发，不能发到别处。
- `watch`：开始监听这个群，后续消息交给某个 Agent（同 `/watch`：全部 / @ / 关键词，回复方式同上）。
- `invite-bot`：以本人身份把 omem 自己的机器人加进这个群（lark-cli `im chat.members create`，只加 omem 的 app_id，不发消息、不加别的成员）。这是本人身份唯一的写操作，只在本人配置的规则里发生。
- `capture`：把这个群设为“与本人有关”并立刻采集一次（之后按 ingest 策略整理）。
- `notify`：通知本人（可标紧急），正文带规则名、事件摘要和理由。

每次触发记一条 `rule_firings`：事件、判断方式和理由、各动作结果（运行 id、错误）。规则页显示最近的触发和每条规则的命中次数。

## 界面

侧栏“规则”：左边规则列表（启用开关、命中次数、最近触发），右边编辑：

- 规则原话（必填）。
- 触发：新消息 / 新群 / 定时（cron）；每条消息触发或每个群一次。
- 判断：条件（一句句可读的条件，可增删改）+ “让 AI 从原话生成条件”；判断方式。
- 动作：按顺序的卡片，选 Agent、开话题、回复方式等。
- “用最近的消息试一试”：拿最近采集的消息（可选某个群）按当前条件求值，列出会命中的消息和理由（只交给模型的规则抽样试）。
- 触发记录。

助理也能建规则：本人在聊天里说“以后值班群里我被 @ 就把机器人拉进去”，助理用 `save_rule` 写原话、生成条件和动作，规则默认不启用，回复里给出规则页链接让本人确认后启用；本人明确说“现在就启用”时可以直接启用。

## 实现

`src/rules/`：`types.ts`（结构与校验）、`conditions.ts`（求值与中文描述）、`store.ts`（表与去重）、`engine.ts`（事件分发、判断、试运行）、`actions.ts`、`compile.ts`（模型生成条件、模型判断）。事件来源：`lark-bot.ts`（机器人所在群的实时消息）、`lark-personal.ts`（本人采集的所有会话，含第一次读到的群）、定时任务 `rule:<id>`。
