# 编码前检查：影响面、以前的问题和回归清单

状态：2026-11-07 实现。落实 [review.md](review.md) 5.2 设计过、一直没做的“业务简报”（`business-analyst`），并把历史评审（`review-history`）要查的一部分提前到编码之前。

## 1. 为什么

交办过去的顺序是：拆修改项 → 编码 → 逐项验证 → 阶段评审。会被波及的现有功能、以前在这里踩过的坑，要到阶段评审才有人看（历史评审），发现了只能返工；编码 Agent 拆修改项时只看任务本身。

影响分析不交给编码 Agent 顺带做：它的会话每轮接着用，上下文本来就大。另开一个只读的短运行先查完，交给编码 Agent 的只有一两千字。

## 2. 什么时候做

新交办的第一轮，工作区和依赖准备好以后、编码 Agent 开始之前，做一次。以后各轮不再做，换新会话的轮次把结果连同原始任务一起给新会话。

不做的情况：设置里关掉（设置 → Agent → 自动推进 → 编码前检查，`agents.autoAdvance.preCheck`，默认开）；助手交办时 `delegate_code` 传 `pre_check: false`（改文案、样式这类一眼看得清影响的小改动）；只做 Git 同步的、分支评审、外部 Agent 编码的交办；重试第一轮时沿用上一次的结果。

查不完（20 分钟上限）、出错或没交结果，在活动里写一句，直接开始编码，不挡交办。

## 3. 查什么

内置角色 `business-analyst`（Agent 页叫“编码前检查”，可改说明、选模型）在交办的工作区里只读地查，用 `submit_brief` 交一份结构化结果，存在交办第一轮的运行上（`output.preCheck`）：

| 部分 | 内容 |
| --- | --- |
| 概要 | 一段话：改哪里、会碰到什么、风险在哪 |
| 预计改动的位置 | 文件和一句说明 |
| 要顾及的 | 会被波及的现有功能、调用方、共用的接口和类型、同一组件或接口的其他页面、同一业务流程的其他环节、关联的需求点；写位置和需求点 |
| 以前出过的问题 | 这些地方以前的问题、修过的坑，必须带依据（`mem:`、`src:`、`run:`、提交号） |
| 回归清单 | 改完要回归的：有现成自动化测试的标“自动”并写命令或用例，没有的标“人工”写步骤；关联的测试点写需求点 id |
| 没查清的 | 需要本人或助手确认的 |

改动小、影响清楚的，几行就够；角色说明要求不凑数。

## 4. 宿主给的线索：code_history

“这个文件以前为哪些需求、哪些交办改过，出过什么事”由宿主查一次，编码前检查和历史评审都用：`code_history`（`space` 写仓库或业务空间，`paths` 一次最多 20 个），每个文件列出

- 对上的需求点和最近的状态（评审拆分记下的位置，`req_status.locations`）；
- 改过它的交办：修改项预计改的文件、评审问题所在的文件、需求点位置，归到交办，写标题、日期、确认或丢弃；
- 在它上面提过的评审问题：级别、标题、评审项、日期、结果（已修复、驳回、以后再做……）；
- 仓库里最近的提交（`git log --follow`）。

只列调用者能读的空间里的运行和问题。工具在“代码仓库与 Git”分组，评审项也可用。

## 5. 结果给谁

- **编码 Agent**：任务末尾多一节“编码前的检查”，要求拆修改项时把要顾及的写进完成标准（需要单独改的另列一项）、别再犯以前的问题、回归清单里有自动化测试的在对应的项做完后跑；认为不成立的在说明里写理由，不必照做。
- **阶段评审**：每个评审项和评审负责人的材料里都有这一节。历史评审先核对“以前出过的问题”有没有避开，不再从头找，接着只看实际改动超出它的部分；评审负责人看回归清单和要顾及的点，碰到了却没人验证、没人看过的，按问题处理。
- **本人**：交办视图“概览”里一张“编码前的检查”卡片，写概要和各部分的条数，展开看全部。

## 6. 和设计过的“业务简报”的差别

review.md 5.2 设想的业务简报写成工作文件 `item/<id>/brief`、带编号变更点，`brief: wait` 时先请本人确认。这次没有做确认这一步，也不出变更点（变更点仍由阶段评审时的需求拆分给出）：交办不该在编码前停下来等人。结果挂在交办上，而不是事项上，不属于事项的交办也有。

## 7. 没做的

- 编码后按实际 diff 再查一次影响面：现在由评审负责人对照回归清单和实际改动判断。
- 回归清单里的自动化测试由宿主自动跑：现在由编码 Agent 跑，宿主的检查命令照旧跑。
- 需求点状态按修改项更新、测试点回写（coding-work.md 第 3 阶段）。
