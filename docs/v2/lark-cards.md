# 飞书卡片与图表的版式

状态：2026-11-14 实现。展示组件（`show`、`ask_user` 的 `view`）在飞书卡片和网页上的画法；组件块本身见 [interactive-ui.md](interactive-ui.md) 第 2.1 节。

## 1. 做法

Agent 不写卡片 JSON。它交出组件块，只做几个判断：这条结论是什么性质（达成、需要关注、故障），哪个指标越少越好，数据适合哪种图。版式、颜色、间距由宿主决定：

- 飞书：`src/channels/lark-ui.ts` 把组件块画成卡片 2.0 的元素。
- 网页、插件页：`packages/plugin-sdk/blocks.ts` 画成 HTML 和 SVG。
- 其他渠道：`viewText` 的文字版加网页链接。

这样同一份内容在几处长得一致，改一处版式不用改角色说明，模型写错字段时宿主的校验能直接告诉它。让模型直接写卡片 JSON 的做法（按主题挑色板、生成后用预览工具截图检查）每张卡都要模型重新排一遍版，也只能在飞书里看。

## 2. 组件怎么画

| 组件 | 飞书卡片 | 网页 |
|---|---|---|
| `callout` | `interactive_container`：一律 `grey-50` 底、8px 圆角，标题行带飞书图标库的图标（`info_filled`、`succeed_filled`、`warning_filled`、`error_filled`），只有图标按语气着色 | 浅灰底，只有左侧的小图标按语气着色 |
| `metric` | 每项一列（`column_set` 里等宽的 `column`，`grey-50` 底），两项一行或三项一行，四项排成两行两列；标签灰色小字，数值按长度用 `heading-1` 到 `heading-3`，变化带箭头，好坏分别是绿和红，看不出好坏时灰色 | 带细边框的指标卡，按个数排成整齐的几行（4 个以内一行，5–6 个每行三个，7–8 个每行四个，窄时每行两个）；变化只给文字着色；`spark` 画成第一个系列色的小折线 |
| `chart` | `chart`（VChart）：系列颜色固定为下面的 8 个；柱子最宽 24px、数据端 4px 圆角；折线 2px 平滑；面积图淡色填充；`hbar` 是 `direction: horizontal`；`goal` 是一条 `markLine`；数据点 12 个以内在柱顶或点上标数值；饼图把占比写进名字（`chart_spec` 只能是纯 JSON，不能写格式化函数） | SVG：整数刻度，一个轴只用一种写法（全是 5,000 或全是 0.5万）；悬停时竖线对准横坐标，提示框列出这一处所有系列；柱状悬停整格高亮；横向条形按给的顺序从上往下；饼图画成圆环，中间是合计；方向键逐个看；下面能展开“看数据” |
| `table` | `table`：灰底加粗的表头，数字列右对齐、千分位、小数位按数据；超过 4 列冻结首列 | 可按列排序的表格 |
| `compare` | 每个方案一列（`grey-50` 底），优点前面绿色“＋”，代价前面红色“－” | 方案卡片 |
| `heading`、`timeline`、`markdown` | Markdown | 同 |

只有第一个 `callout` 是需要关注或故障时卡片头才是橙色、红色，其余是灰色；`config.summary.content`（消息列表里那一行）是标题加第一个结论或第一个指标。

## 3. 颜色

- omem 的界面是素的，版式也按这个来：底色只用一种浅灰（`grey-50`），不给每块配不同的底色；颜色只标在数值、状态和图标上，并且总有箭头、图标或文字说同一件事，不只靠颜色。卡片里的颜色只用飞书的颜色枚举，深色模式由飞书自己换。
- 图表系列色是一套 8 个颜色，按固定顺序分配（靛蓝、青、珊瑚红、琥珀、紫、翠绿、橙、天蓝），网页和飞书用同一套；2026-11-14 从六套候选里由本人选定。深色模式是同样色相、按深色面板调过亮度的一套，同一个系列换主题不换色相。两套在 omem 的浅色和深色面板上都过了色觉区分（相邻两色在色弱模拟下的差异 ΔE 至少 8.9）、正常视力区分和对比度检查，前三个两两之间也分得开（圆环图三块时两两相邻）；浅色下青、珊瑚红、琥珀、橙、天蓝对白底不到 3:1，所以图上有数值标签、悬停提示和数据表格。顺序本身是区分的手段：紫和天蓝放在一起时色弱读者分不开，所以隔开排。只靠 `color_theme` 换不了单系列图表的颜色，所以 `chart_spec.color` 是显式写的。
- 没有用 `config.style.color` 自定义颜色：自定义色要自己配浅色、深色两套，现在的枚举够用。

## 4. 卡片能力的边界

按飞书卡片 2.0 的文档核对过，写组件时要守住的：

- `table` 只能放在 body 最外层。分栏、交互容器、表单、折叠面板里放表格会被拒；这些位置要表格时写 Markdown 表格。
- 分栏的 `column` 能设 `background_style`（飞书 7.9 起），但没有圆角；要圆角的块用 `interactive_container`，不能点的写 `behaviors: []`。
- `markdown` 元素可以带 `icon`（图标库的 `standard_icon`），不用先上传图片；要用自己的图片做图标，得先上传拿到 `img_key`，这里没有做。
- 卡片大小有上限（约 30 KB），所以表格、图表每张卡各最多 5 个，多的写成文字。
- 卡片被飞书拒收时，`deliverViews` 改发文字版和网页链接，不会什么都不发。
