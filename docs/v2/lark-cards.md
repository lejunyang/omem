# 飞书卡片与图表的版式

状态：2026-11-14 实现。展示组件（`show`、`ask_user` 的 `view`）在飞书卡片和网页上的画法；组件块本身见 [interactive-ui.md](interactive-ui.md) 第 2.1 节。

## 1. 做法

阶段确认、阶段阻塞和对账下一步不是通用“需要你回答”。`StageCard` 和网页用同一份标题、事项入口、结构化小节和动作，飞书按原提问的按钮索引和文字提交，把回答交回同一个处理函数。长卡折起“依据”，保留完整的决定问题；配置外部网页地址后，事项流程和“在对话里讨论”可直接打开。纯进展与停留提醒仍是通知。

普通本人阶段轮到时不新建飞书提问，只在同一事项的进展通知里说明要做什么。网页阶段卡仍有输入框和“我做完了／跳过这一段”，旧飞书卡保留原答复入口。对账过了计划时间且没法确认时，最多只在进展里问一句，不发“做完点做完了”的卡片。

Agent 不写卡片 JSON。它交出组件块，只做几个判断：这条结论是什么性质（达成、需要关注、故障），哪个指标越少越好，数据适合哪种图。版式、颜色、间距由宿主决定：

- 飞书：`src/channels/lark-ui.ts` 把组件块画成卡片 2.0 的元素。
- 网页、插件页：`packages/plugin-sdk/blocks.ts` 画成 HTML 和 SVG。
- 其他渠道：`viewText` 的文字版加网页链接。

这样同一份内容在几处长得一致，改一处版式不用改角色说明，模型写错字段时宿主的校验能直接告诉它。让模型直接写卡片 JSON 的做法（按主题挑色板、生成后用预览工具截图检查）每张卡都要模型重新排一遍版，也只能在飞书里看。

## 2. 组件怎么画

| 组件 | 飞书卡片 | 网页 |
|---|---|---|
| `callout` | `interactive_container`：一律 `grey-50` 底、8px 圆角，标题行带飞书图标库的图标（`info_filled`、`succeed_filled`、`warning_filled`、`error_filled`），只有图标按语气着色 | 浅灰底，只有左侧的小图标按语气着色 |
| `metric` | 每项一列（`column_set` 里等宽的 `column`，`grey-50` 底），两项一行或三项一行，四项排成两行两列；标签灰色小字，数值按长度用 `heading-1` 到 `heading-3`，变化带箭头，好坏分别是绿和红，看不出好坏时灰色 | 带细边框的指标卡，按个数排成整齐的几行（4 个以内一行，5–6 个每行三个，7–8 个每行四个，窄时每行两个）；变化只给文字着色；`spark` 画成第一个系列色的小折线 |
| `chart` | `chart`（VChart）：系列颜色固定为下面的 8 个；柱子最宽 24px、数据端 4px 圆角；折线 2px 平滑；面积图淡色填充；`hbar` 是 `direction: horizontal`；`goal` 是一条 `markLine`；数据点 12 个以内在柱顶或点上标数值；饼图把占比写进名字（`chart_spec` 只能是纯 JSON，不能写格式化函数） | SVG：整数刻度，一个轴只用一种写法（全是 5,000 或全是 0.5万）；悬停时竖线对准横坐标，提示框列出这一处所有系列；柱状悬停整格高亮；横向条形按给的顺序从上往下；饼图画成圆环，中间是合计；方向键逐个看；下面能展开“看数据” |
| `table` | `table`：灰底加粗的表头，数字列右对齐、千分位、小数位按数据；超过 4 列冻结首列 | 可按列排序的表格 |
| `compare` | 每个方案一列（`grey-50` 底），优点前面绿色“＋”，代价前面红色“－” | 方案卡片 |
| `heading`、`timeline`、`markdown` | Markdown | 同 |
| `list` | 每条一个 Markdown：`<text_tag>` 彩色标签在前，标题加粗（有链接时是链接），下一行灰字；条目都没有说明时合成一个 Markdown | 细线隔开的条目，标签用 `.badge` 的语气色，有链接的标题后面带 ↗ |
| `fields` | `column_set`（`bisect`，`grey-50` 底），每对一列：灰色名字、加粗的值 | 浅灰底的一块，四对以内一行排完，窄屏两列 |
| `fold` | `collapsible_panel`，默认收起 | `details`，带细边框 |
| `image` | `img`：发卡片前宿主下载图片（不取本机和链路本地地址，限 10 MB、`image/*`）再上传拿 `img_key`；失败时是一个链接 | `img`，最高 480px |

只有第一个 `callout` 是需要关注或故障时卡片头才是橙色、红色，其余是常规的不着色卡片头（2026-11-28 前是灰色：飞书规范里灰色表示失效，看起来像过期的卡）；`config.summary.content`（消息列表里那一行）是标题加第一个结论或第一个指标。

### 宿主自己的卡片

流程阶段卡（卡住了、到你了、等你确认开始 / 做完）、方案确认这类宿主发起的确认，和组件块用同一套画法：提问带 `ui.head`（标题、所属事项或交办、状态标签）、`ui.body`（代替问题正文显示的一两句）、`ui.view`（组件块）、`ui.links`（要打开的页面）。问题正文 `question` 仍是完整的文字版，给 Agent、通知和没有卡片的渠道。阶段卡在读出时按存下的 `StageCard` 排（`src/flows/stage-card.ts` 的 `stageCardUi`）：阶段名做标题，事项做副标题，状态做标签；要本人定的那一节是 `callout`，长的“依据”收进 `fold`；事项流程页和“在对话里讨论”是一行链接。方案确认把决定列成 `list`，决定的类型做标签。回答以后卡片保留标题，标签换成结果（已回答、已批准、已拒绝、已失效），原来的内容收进“当时的内容”。

卡片头：有状态标签时卡片头不着色（`template: default`），颜色只在标签上。飞书的消息卡片设计规范要求单聊尽量用常规标题、不要张张高亮，omem 的卡片大多发在私聊。要打开的页面是一行小字链接，放在回答的按钮前面，不和回答用的按钮混在一起。网页上同一张卡（`AskCard.vue`）：标题、语气色的标签、灰色副标题，卡片左边线跟着标签的语气。

## 3. 颜色

- omem 的界面是素的，版式也按这个来：底色只用一种浅灰（`grey-50`），不给每块配不同的底色；颜色只标在数值、状态和图标上，并且总有箭头、图标或文字说同一件事，不只靠颜色。卡片里的颜色只用飞书的颜色枚举，深色模式由飞书自己换。
- 图表系列色是一套 8 个颜色，按固定顺序分配（靛蓝、青、珊瑚红、琥珀、紫、翠绿、橙、天蓝），网页和飞书用同一套；2026-11-14 从六套候选里由本人选定。深色模式是同样色相、按深色面板调过亮度的一套，同一个系列换主题不换色相。两套在 omem 的浅色和深色面板上都过了色觉区分（相邻两色在色弱模拟下的差异 ΔE 至少 8.9）、正常视力区分和对比度检查，前三个两两之间也分得开（圆环图三块时两两相邻）；浅色下青、珊瑚红、琥珀、橙、天蓝对白底不到 3:1，所以图上有数值标签、悬停提示和数据表格。顺序本身是区分的手段：紫和天蓝放在一起时色弱读者分不开，所以隔开排。只靠 `color_theme` 换不了单系列图表的颜色，所以 `chart_spec.color` 是显式写的。
- 没有用 `config.style.color` 自定义颜色：自定义色要自己配浅色、深色两套，现在的枚举够用。

## 4. 卡片能力的边界

按飞书卡片 2.0 的文档核对过，写组件时要守住的：

- `table` 只能放在 body 最外层。分栏、交互容器、表单、折叠面板里放表格会被拒；这些位置要表格时写 Markdown 表格（JSON 2.0 才画成表格：每页 5 行带翻页，一个 Markdown 元素最多 4 个表格，不能设列宽）。2026-11-28 在卡片搭建工具的手机视图里看过：Markdown 表格每列约 125px，四列的表格在手机上只露出前两列多一点，其余横着滑，所以 fold 里的明细宜一项一行写或只留两三列（`skills/omem/references/owner.md` 的 `fold`）。
- 分栏的 `column` 能设 `background_style`（飞书 7.9 起），但没有圆角；要圆角的块用 `interactive_container`，不能点的写 `behaviors: []`。
- `markdown` 元素可以带 `icon`（图标库的 `standard_icon`），不用先上传图片；要用自己的图片做图标，得先上传拿到 `img_key`，这里没有做。
- 卡片大小有上限（约 30 KB），所以表格、图表每张卡各最多 5 个，多的写成文字。
- 卡片被飞书拒收时，`deliverViews` 改发文字版和网页链接，不会什么都不发。

## 5. 怎么看卡片画出来的样子

飞书没有离线渲染卡片 JSON 的接口或组件（2026-11-27 调研）。能用的：

- **`node scripts/card-preview.ts [目录]`**（不用登录）：用真实的卡片代码在临时数据目录里生成样例卡片（阶段卡、回答后的阶段卡、方案确认、批准、提问、展示块、表单），用开发依赖 open-feishu-card（照网页版飞书的渲染规则写的第三方渲染器，MIT）按电脑 520px 和手机 340px 宽度画出来截图；`--json=文件` 画任意一张卡，`--site` 重画文档站的 `lark-card-*` 截图。和卡片搭建工具对照过：卡片头的状态标签、浅灰底的结论块、Markdown 里的彩色标签、按钮、折叠面板都一致；Markdown 元素上的图标不画，分栏的 `grey-50` 底色不画，下拉框画成空框，图片只有占位。画之前按客户端的样子改两处：Markdown 里的 HTML 实体（`cardText` 把 `:` 写成 `&#58;`）先解码；Markdown 表格（这个渲染器画成原样的竖线文字）换成每列 125px、每页 5 行的表格组件，手机宽度下和客户端一样要横着滑。另一个开源渲染器 feishu-card-renderer（React）不画卡片头的标签、容器底色和图标，没有用。

- **卡片搭建工具**（open.larkoffice.com/cardkit，要登录）：编辑器“导入卡片”收 `{"name": …, "dsl": <卡片 JSON 2.0>, "variables": []}` 格式的 `.card` / `.json` 文件，导入进当前卡片后画布按飞书客户端的样子画出来，能切桌面和手机。直接导入裸的卡片 JSON 会变成一张空的旧版卡片。搭建工具没有折叠面板组件，导入时 `collapsible_panel` 会被丢掉，折叠面板要在客户端里看。
- **建卡片实体接口**（`POST /open-apis/cardkit/v1/cards`，`type: card_json`）只校验 JSON，不发消息、不出图。
- 发到只有自己的私聊里看，最接近真实客户端。
