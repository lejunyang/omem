# 有人找你：预筛、分诊、处理、回复

代码：`src/channels/lark-mentions.ts`（预筛、调度、兜底）、`src/channels/mention-triage.ts`（分诊的材料和判断）、`src/channels/mention-reply.ts`（回复对方）、`roles/mention-triage.md`（分诊标准）。设置：`lark.mentions`（设置 → 渠道 → 有人找你）。

## 目标

别的群里有人 @ 本人，或同事私聊本人，本人一时没看。提醒不该只是“某某 @ 了你”：要说清是什么事、现在什么状态、怎么回，能推进的先推进。同时这类消息很多，大多不值得调一个带工具的 Agent，所以按成本分三段，前一段说值得才进下一段。

## 流程

```
采集（lark-cli 轮询 / @我 搜索 / 机器人实时）
  └─ queueMention：有人 @ 本人或私聊本人、不是机器人、不是本人、6 小时内；每条只记一次
       └─ mention 运行（每个会话话题一个，等 delayMinutes）
            1. 预筛（不调模型）
               本人已读 / 回表情 / 已回复 → 结束
               盯群在管、规则的 Agent 在管 → 结束
               同一批行的整理（ingest）还没做完 → 一分钟后再看（最多 8 次）
               同一人同一话题 30 分钟内已有处理 → 并进那次处理（还没开始的追加消息；已开始或已做完的接着它的会话），不再分诊
               今天的分诊次数用完 → 简短提醒
            2. 分诊（mention-triage，一次小判断）→ 记进运行事件和 output.triage
               ignore → 结束；notify → 简短提醒（带“对方要什么”）；handle ↓
            3. 处理（agent 运行，主助手或分诊选的档案，本人身份）
               今天的处理次数用完 → 简短提醒
               读上下文、查事项/记忆/Wiki、更新事项 → 最后的回答作为提醒（或 stay_quiet）
               失败、超过 timeoutMinutes、没写结论 → 简短提醒
            4. 回复对方（可选）：reply_to_asker → off / 草稿卡片 / 自动发
```

## 分诊：给决策模型什么

决策模型只回答选择题（几个选项各自的概率），不写理由，所以材料要小而够用，问题要短。宿主一次性准备这些（`triageMaterial`，有上限，见 `LIMITS`）：

| 材料 | 内容 | 为什么 |
| --- | --- | --- |
| 会话 | 群名或“和某人的私聊”、是否话题、所在空间和相关空间 | 群的性质决定很多事（值班群、需求群、闲聊群） |
| 发送人 | 名字；近 30 天发过几条、和本人有没有私聊、找过本人几次 | 常联系的人、反复找的人更可能要本人处理 |
| 找本人的消息 | 每条最多 800 字，带被引用的那条 | 判断的主体 |
| 前后的聊天 | 同话题（或同会话）前 15 条、后 5 条，共不超过 3000 字，标出本人和机器人 | 看是不是已经有人答了、在回应什么 |
| 消息里的链接 | 已收进来的原件标题（不读正文），没收进来的只列链接 | 知道是哪份文档就够判断，不必读 |
| 可能相关的在办事项 | 本人打开的事项里，来源是这个会话的，和与消息共享词最多的，前 5 条，标题加一行 | 属于已有事项的，值得接着推进 |
| 相关的记忆和页面 | 对消息文本检索一次，记忆和 Wiki 各取标题加一行，共 6 条 | 以前处理过、有现成结论的，值得查 |
| 可以交给 | 主助手和每个可用的 Agent 档案，一句说明 | 选处理者 |
| 本人的分诊说明 | 设置里的自由文本 | 本人的偏好优先 |
| 本人说过不用提醒的 | `notify-lessons` 学到的规则 | 本人明说过的不再打扰 |
| 现在 | 本人时区的时间、星期 | 半夜和工作日不同 |

宿主只做数据准备：一次检索、几条 SQL，不替模型做多轮检索，也不写规则清单式的提示词。

问题（`roles/mention-triage.md`，本人可在 Agent 页改）：三个选项和各自的判断标准，一段话。决策模型最多问三次，都是一次往返：

1. 动作：`ignore` / `notify` / `handle`（拿不准选 handle）。
2. 只在 handle 且有 Agent 档案时：交给谁（选项是“可以交给”里的每一项）。
3. 只在 handle 且这类会话的回复是“自动”时：查清后能不能不经本人拍板就答复。

没有决策模型时（`noDecision`）：`general` 用通用模型（助手的后端，一次不带工具的调用，同一段标准加 JSON 输出格式，多给出“对方要什么”和紧急程度）；`notify` 一律简短提醒；`handle` 一律交给主助手。决策模型出错时，`ai.decision.fallback = general` 且 `noDecision = general` 改用通用模型，否则按 `noDecision`（`general` 时按简短提醒）。

分诊结果记进运行事件（`status` 事件带 `triage`）和运行的 `output.triage`、`output.material`：运行页能看到判断、概率和它看到的材料，本人可以据此调分诊说明或角色。

## 处理

交给主助手（或分诊选的档案），`kind = agent`，带 `input.mention`：

- 以本人身份，空间不限于一个（`assistantScope.spaces = null`，按 `accessibleSpaces`），因为这类排查常跨业务空间。
- 不交办编码、不建规则和盯群、不交给别的 Agent、不以本人身份写飞书（`MENTION_DENY`）；不能用 `lark_send` 发消息（`lark.chats = []`）。
- 任务材料：分诊的结论和分诊时找到的上下文（标题加一行，要用就读原文），要求读全上下文、查清能查的、更新事项、写提醒。
- 它最后写的文字就是提醒：第一行作标题，其余作正文，引用这次的消息（`notify`，按已读、夜间、重复提醒的规则推送）。它也可以自己 `notify`（比如带事项按钮），宿主就不再发；`stay_quiet` 不提醒。
- 归属（`agents/home.ts`）：处理运行的会话设为本人和机器人的私聊；提醒卡片在 `lark_sent` 里记着这个运行，本人引用回复它，这件事就跟着到那里接着聊。回复了对方以后，归属移到回复所在的群或话题。
- 超时 `timeoutMinutes`（默认 10 分钟）。运行出错、超时、没写结论，都发简短提醒；手动取消或服务重启不发（重启后运行会再跑）。

## 回复对方

`lark.mentions.reply`：`group`、`p2p` 各三档，默认 `off`。

- `off`：建议的回复写在给本人的提醒里。
- `draft`：处理运行用 `reply_to_asker(text)` 拟回复，变成给本人的卡片（可编辑的输入框、“发送”、“不发”）；本人点发送才发，算本人亲自发起。
- `auto`：本人在设置里给的持续授权。只有分诊也认为“查清后不用本人拍板”时才是自动，否则这次按草稿。

发到哪里（都是已有的通道）：

- 群：机器人不在群里时用本人身份把 omem 的机器人拉进来（`targetChat` / `inviteOwnBot`），机器人在对方那条消息的话题里回复并 @ 对方。
- 私聊，`p2pVia = group`：建本人、对方和机器人的群（和规则“转发到私聊”同一个函数，同一个人只建一次），机器人在群里回复。
- 私聊，`p2pVia = signed`：以本人身份在那个私聊里发一条，末尾带 `/ai` 的署名。

每次回复写 `audit_events`（`lark.mention-reply`，记操作者 agent/owner、方式、消息 id、内容），提醒里写清回了什么。一次处理只回一次。飞书没有给机器人或本人的已发消息提供可靠的撤回接口，这里没有撤回入口：要撤回本人在飞书里自己撤。

## 省资源

- 预筛不调模型：已读、已回复、有规则或盯群在管的消息不花一分钱。`delayMinutes` 给本人先看的时间。
- 合并：同一话题连着的几条一次分诊；同一人同一话题 30 分钟内接着说，并进已有的处理，不再分诊。
- 分诊用决策模型，最多三次选择题；材料有字数上限。
- 只有 `handle` 才起带工具的运行；每天的分诊和处理次数有上限（`perDay`，默认 80 / 20），超过只发简短提醒。
- 处理有时限，超时就停，发简短提醒。

## 和规则的关系

规则先于它：消息命中了交给 Agent 的规则（`rule_firings` 里有这条消息或这个会话的触发），或这个群在盯，这里让开，不分诊。它是“没有规则管的、找本人的消息”的默认处理。

没有做成一条内置规则：规则引擎处理的是“满足条件就执行一串动作”，而这里要按分诊结果分叉（三种动作、选处理者、每天上限、合并到已有处理、失败兜底），塞进规则会让规则的结构为这一种情形变复杂；所以保留独立模块，复用规则那边的函数：拉机器人进群和建三人群（`rules/forward.ts targetChat`）、看群里有没有机器人（`chatBots`）、主助手的权限范围写法（`assistantScope`）、决策模型和通用模型的选择方式（`core/decision.ts`、`agents/oneshot.ts`）。本人要对某类群另作处理（比如值班群直接交给某个档案并回群），仍然写规则，这里自动让开。
