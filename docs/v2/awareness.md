# 会话与运行的感知

omem 里每个会话（飞书群、群里的话题、私聊、网页对话）是一条串行的线，不同会话并行；另外还有很多后台运行：定时巡检、“有人找你”的处理、盯群的一批消息、唤醒、规则触发的 Agent、多 Agent 工作的各轮。它们原来互相不知道对方，也不知道本人在它们工作期间说了什么。真实使用里看到三类问题：

1. 同一个群里两路同时处理同一件事，各回一遍。
2. 助手在后台查一件事，中途本人自己介入、补充了内容，后台那一轮照旧发出过时的结论或无用的提醒。
3. 一件事在几个群、几个会话里同时进行，每个会话只按眼前的上下文回答。

这一套由宿主做：宿主从已经记录的东西（运行的输入、调用的工具、采集的飞书消息、会话消息、事项）得出每个运行在办什么、本人说过什么，告诉运行；判断怎么做仍交给 Agent。宿主不替模型决定“是不是同一件事”，只给事实和候选。

## 1. 运行的范围键

表 `run_scope(run_id, kind, key, topic, via, at)`，`src/agents/run-scope.ts`。运行开始时（`runs.ts` 的 `kick` 认领之后）由 `recordRunStart` 从输入得出，运行中由事项工具补上；不靠模型自报。

| kind | key | 从哪来 |
| --- | --- | --- |
| `conversation` | 会话 id | 对话轮次的 `conversationId`、交办回报的 `threadId`（“有人找你”的处理例外：它的 `conversationId` 是本人和机器人的私聊，只是提醒发去的地方，不算范围） |
| `chat` | 飞书 `oc_…`，`topic` 是话题 id（整个群为空） | 飞书会话的 `external_id`；“有人找你”的群和话题；规则的 `silent`、`replyAt`、`lark.chats`（不超过 3 个时）；整理新材料的群聊原件 |
| `message` | 飞书消息 id | “有人找你”的消息、规则的触发消息、对话轮次所答消息的 `externalId` |
| `item` | 事项 id | 输入里的 `itemId`；运行中调用 `read_item`、`upsert_item`、`settle_items`、`propose_item_update`、带 `entity_id` 的 `notify`（`via = tool`） |

两个运行的键有交集：kind 和 key 相同，`chat` 的话题在两边都有时还要相同（很多采集的行没有话题标记，一边没有就算同一个群）。

## 2. 同时在办的相关工作

`relatedNote`：和这个运行范围有交集、正在进行或 30 分钟内结束（`RECENT_MINUTES`）的其他运行，每个一行：运行 id、谁（档案、角色或运行类型）、在哪个会话、进行中还是几点结束、标题、交集是什么，下一行是结论一句（`stay_quiet` 的原因、回答的第一行或摘要）。不列：同一条线（lane）里会话自己之前的轮次（会话记录里已经有）、这个运行自己起的子运行、别人的运行、记账类运行（会话摘要、唤醒本身、记忆复核、复盘等）。最多 6 条，没有就不出现这一段。

放在任务后面：`runner.ts` 的 `runRole`（包括后台会话池的任务）和 `sessions.ts` 的 `threadTurn`（会话轮次的新消息部分）都接 `awareness.ts` 的 `awarenessNote`。评审检查、复看、复盘和对比运行不加。`roles/_common.md` 的“同时在办的工作”说怎么用：先 `read_run` / `read_conversation` 看对方做到哪，对方已经在答的不再答一遍，结论不一致时说明哪边更新。

## 3. 发出前复核

后台运行指没人等它回答的运行，判断沿用 `quiet.ts` 的 `mayStayQuiet`，限于对话轮次、Agent 运行、巡检、整理新材料、简报和事项收尾（`awareness.ts` 的 `BACKGROUND_KINDS`）：唤醒、盯群的一批、规则的 Agent、“有人找你”的处理、交办交回的修改项、巡检。本人直接提问的对话轮次、访客、私聊指令、外部 Agent 不在内；编码、评审、Wiki 和记忆整理不发消息给本人，也不在内。会议里机器人的实时发言（`meeting_send`）不拦，拦下会让回答迟到。

### 本人在范围内说的话（`ownerMoves`）

从运行排队（`created_at`）之后算，去掉已经交给它看过的（`output.awareness.seen`）：

- 范围里的飞书群（和话题）里本人发的消息（`lark_messages.sender_kind = 'owner'`）；
- 本人回复了触发它的消息（`parent_id` 是范围里的消息 id），不论在哪个话题；
- 范围里的会话里本人的话（`messages` 里本人的 user 消息，不含群里别人的发言、访客、唤醒说明、斜杠命令、Agent 报告，也不含这个运行自己答的和被并进来的）；
- 运行碰过的事项关联的其他会话和群里本人的话（第 4 节）。

不算：触发它的消息本身、这个运行自己发的（`lark_sent`，以及以本人身份回复对方的那条）。

### 什么时候拦、拦几次

- 工具：后台运行调用 `notify`、`lark_send`、`lark_card`、`lark_send_file`、`reply_to_asker` 时（`tools.ts` 的 `runTool`，`preSendCheck`）。有上面的话，或者 `notify` 引用的消息本人已经看过，这次调用不执行，结果里写出本人说的话，请它对照：还要说就改写后再发，本人已经处理了就 `stay_quiet`。
- 最终回答：宿主在运行结束后替它发的回答（唤醒、盯群一批的回答，规则 Agent 的回答，“有人找你”的提醒）。`jobs.ts` 的 `ask` 处理和 `runAgentTask` 在发出前调用 `recheckAnswer`：有上面的话就再过一轮（会话轮次接着会话，Agent 运行先试着接上会话，接不上带上任务原文和草稿开新会话），它的新回答代替草稿，`stay_quiet` 就不发。静默规则和会议运行只通过工具发言，只在工具上拦。
- 每次运行最多复核一次（`output.awareness.recheckedAt`），之后照它的决定发出。复核那一轮出错，按原来的回答发出。

### 和通知闸门合成一套

原来的通知闸门（`notify-gate.ts` 的 `ownerAlreadyHandled`：触发消息已读、本人回了表情、本人之后在同群同话题回复过）只在推送时静默丢掉通知，运行自己不知道。现在同样的判断先在运行里用：`notify` 的引用、“有人找你”的消息已经被本人看过，算作复核的理由，交回给运行决定。推送时（`lark-bot.ts`）对已经复核过的运行发的通知不再拦一次；没经过复核的通知（宿主自己发的简短提醒、到点的提醒）和夜里攒到早上才发的照旧检查。

## 4. 运行中送达

后台运行还在跑时，本人在它范围里说了话：它下一次调用任何 omem 工具，工具结果末尾附“本人刚说了”（`ownerNews`，接在 `tools.ts` 的 `steering` 后面），每条只附一次（记进 `seen`，之后的复核也不再算它）。不依赖后端支持中途插话。本人自己的对话轮次不走这条：同一会话里的新消息已经由 `steer.ts` 交给正在进行的那一轮。

## 5. 一件事跨会话

`src/items/places.ts`。

- **关联就是事项材料**：omem 会话是 `conversation` 材料，没有会话的飞书群是群聊原件的 `source` 材料。事项页、评审和交办读材料时都看得到，`materials_remove` 取消。
- **自动关联**：运行用 `upsert_item` 写了事项，宿主把事项关联到这个运行范围里的会话和群（`linkRunPlaces`；群有 omem 会话的用会话，否则用群聊原件），工具结果里写一句关联到了哪里。只读事项不关联。
- **显式关联**：`upsert_item` 的 `materials_add`（kind=conversation 或 source）、`materials_remove`。工具说明写明了这是“这件事在哪里进行”。
- **这件事还在这些会话里进行**：运行所在的会话或群关联了打开的事项（最多 3 件），任务后面列出这些事项在别处的会话和群，每处一行：名字、id、最近活动时间、会话摘要的前两行或最后一句话。
- **候选**：运行所在的会话或群还没有关联打开的事项时（只对对话轮次和 Agent 运行），按引用了这个群的消息、同一个链接或单号、提到同一个人、共同的词（同“有人找你”分诊的打分）、时间相近打分，最多列 3 件和理由，由 Agent 读过后决定是否关联。宿主不自动关联候选。
- **全貌**：`read_item` 多返回 `places`（各会话和群的摘要）和 `runs`（碰过这件事、或在它的会话和群里正在进行的运行），连同原有的时间线、材料和工作文件。只给事项的主人：别人的 `read_item` 照旧被拒，`GET /api/items/:id` 对别人返回空的 `places` 和 `runs`。
- **事项页**：详情面板“在这些会话里进行”（`web/src/components/ItemPlaces.vue`），在材料上面。

## 6. 接手不作废

本人在对话里问起后台正在办的同一件事时，这一轮从第 2 节看到后台那一轮。`take_over_run(run_id)`（分组 `delegate`）停下那一轮，返回它最后写的文字、写过的工作文件、碰过的事项、已经发出的消息，接着做而不用重查；已经结束的也可以用来取结果。只能接手同一个人的后台运行；编码交办和评审用 `stop_code_run`；回答别人消息的运行不能接手。

## 默认值

| 项 | 值 | 位置 |
| --- | --- | --- |
| 相关运行“刚结束”的时间窗 | 30 分钟 | `run-scope.ts` 的 `RECENT_MINUTES` |
| 相关运行最多列几个 | 6 | `relatedRuns` |
| 本人的话从何时算起 | 运行排队时间（`created_at`） | `ownerMoves` |
| 每次运行复核几次 | 1 | `output.awareness.recheckedAt` |
| 关联事项最多列几件、每件几处 | 3 件、5 处 | `itemPlacesNote` |
| 候选事项门槛、最多几件 | 6 分、3 件 | `placeCandidates` |

## 没做的

- 范围键不含 Agent 自己在消息里提到的群和人；`lark_send` 发到的群也不补进范围。
- 运行中送达和复核只对后台运行；本人自己的对话轮次在别的会话里说的话不送进来（同一会话的由 `steer.ts` 处理）。
- 候选只按字面打分，不用向量；人名只认会话里的发言人名字。
- 复核的最终回答在“有人找你”之外不检查已读（只有本人说过话才复核）。
- 多 Agent 工作的协调轮次（`coordinate`）和交办交回的结果（`handoff`，修改项和方案除外）不复核：它们本来就是写给本人的汇报。
- 跨设备（`--peer`）的外部 Agent 不记范围。
