# 每晚抽检

助手整理材料、修正页面时也会直接写 Wiki。每晚 05:10，`quality-audit` 从这些已发布的页面里抽几页，交给 `wiki-checker` 对照原件和代码核对。报告在网页“运行”旁的“抽检”，地址 `#/quality`；也可以点“现在抽检”。

## 抽哪些页面

夜间抽检之外，本人在 Wiki 页面点“这页有错”或在对话中指出错误，会记成 `page_corrections`：先改原页，再排查同空间同类运行近 90 天写的页面和最多 20 个搜索命中，同目录优先、默认最多 15 页（`wiki.corrections.sweep`，0 关闭）。`wiki-sweep` 调用同一个 `checkPublished`，有同类问题的经与夜间抽检共用的 `sendPagesBack` 交回写作与核对，等实际发布且核对通过后才计入已改；检查了页面才发一条 `later` 汇总。本空间最近 20 条指正也会带给以后的草稿核对和抽检，详见 [Wiki 指正与同类排查](wiki-verify.md#_7-本人指正与同类排查-11-15)。

`page_writes` 记录每次写入的身份和运行。候选是最近 3 天内、最新版由 Agent 写入、这一版尚未抽检的页面；排除已经在发布前核对的 `wiki-write`、抽检运行自身、目录页、日志页及 worktree 空间。本人写的最新版和从其他设备镜像来的写入不作为候选。没有运行记录的 Agent 写入归为 `external`。

先看同一次运行写的其他页面：其中有页面在近 7 天抽出事实问题的优先，其次是本人在近 7 天改过同次运行另一页的。然后看近 14 天被回答或办事的运行通过 `read_page` 读过的页面，读取多的在前；余下随机抽。后台维护角色的读取不计入 `page_reads`。

普通抽样每晚最多 8 页、每类运行最多 3 页；同次运行出问题或被本人纠正的优先页可以突破每类上限，但仍占普通抽样总数。加严的运行类型另用每晚共 12 页的额度，并非每类各 12 页。

## 怎么判，怎么改

核对角色读已发布正文、引用的原件行和可读的相关空间资料，用 `submit_page_check` 提交原句、问题、依据及修改建议。引用、代码、否定结论、冲突（`cite`、`code`、`negative`、`conflict`）属于事实问题；其余属于写法问题。

| 结论 | 含义 |
| --- | --- |
| 没问题（ok） | 核完，未发现问题 |
| 只有写法问题（style） | 有表达等问题，没有事实问题 |
| 有事实问题（wrong） | 至少一条事实问题 |
| 没核完（unchecked） | 核对失败或没有提交结论；不算通过。同一版本下一晚再抽一次，两次都没核完就不再抽 |

默认把有事实问题的页面连同核对意见交回 `generateWiki({ pages, focus })`，按空间排 `wiki-write`，经过正常的写作、核对、发布流程。设置可改为不交回，或写法问题也交回。抽检记录保留页面版本时间、写作者运行及 AI、核对 AI、抽到原因、问题清单、抽检运行和修改运行。

每次抽检发一条链接到 `#/quality` 的通知。有事实问题或加严状态变化时正常通知，其余只在网页显示（silent）。核对未完成的版本也记一次抽检，不自动重试这一版。

## 数字与加严

页面按写作者的运行类型统计近 14 天的抽检、没问题、写法问题、事实问题和没核完的页数。“没有事实问题的比例”是 `(ok + style) / (ok + style + wrong)`；没核完不进分母，也不用于触发加严。

一类运行至少有 6 页核完，比例低于 80% 就加入加严名单：候选范围内它写的页面每页都看，仍受每晚加严总额度限制。比例回到门槛且样本数足够时恢复普通抽样。当前窗口样本不足时保留已有加严状态。

## 原件与目录定级抽检

同一个 `quality-audit` 运行还会逐项调用 `wiki-checker`，每晚最多抽 `quality.audit.levels` 条 Agent 定级，默认 6 条，0 关闭这一项。候选包括单篇原件的自主定级和待复核中的目录、知识库、会话等节点定级；本人和规则设置的级别不抽。先目录后单篇；各自先看“忽略”和“仅检索”，目录按所含原件数从多到少，其后按定级时间从新到旧。

单篇定级保存 `attention_at`、理由和设置它的运行；目录沿用 `source_node_levels.updated_at`、`reason`、`run_id`。旧单篇没有时间的决策也可抽一次。目录候选只有 active 的 Agent 定级，按空间共用现有内存目录 `catalog`（与待复核相同），每个空间在这次选样中只取一次目录，用 `sourcesUnder` 和 `nodePath` 得到原件数与路径；不持久化目录，也不在采集、更新时维护审计专用的目录数据。目录排好序后，单篇候选通过 `sources_agent_attention` 部分索引做集合 SQL 查询，只返回剩余额度内的决策，不载入正文。选中后单篇只取前 4000 字、标题和位置；目录从本次保存的原件 ID 列表中等距取最多 15 个 ID，一次按 ID 查询标题，不扫描整个目录做窗口排序。

核对回答“这个级别对不对：对 / 不对（应该是哪一级，为什么）/ 看不出来”，用审计步骤专用的 `submit_level_check` 提交。对只记记录；不对也不自动改变级别，原件 → 待复核显示建议级别和理由，本人点“采纳”改为建议，点“保持”保留原级别，两者都成为本人的决定并移出队列。建议只匹配当时的决策；级别后来改变或本人接管后，旧建议失效。

记录沿用 `quality_audits`，`category=level`，`target` 为 `level-source:<id>` 或 `level-node:<key>`；`pipeline` 仍是设置它的运行类型，不明则 `level`。每个决策只抽一次，“看不出来”也记录为 `unchecked`，不重复抽、不进准确率分母。报告增加“定级：抽了 N 个，M 个不对（见原件 → 待复核）”。质量页在相同统计窗口中单列“定级”：抽检数、判错数及 `ok / (ok + wrong)`。定级不参与页面的运行类型统计和自动加严。

## 默认值与设置

设置 → AI → 通用 → 每晚抽检，可开关抽检、修改三个页数上限、百分比门槛和交回方式；设置 → 定时任务可改运行时间。Agent 页给 `wiki-checker` 选核对模型，最好与写作模型不同。

| `quality.audit` 字段 | 默认值 | 含义 |
| --- | --- | --- |
| enabled | true | 启用排队 |
| max | 8 | 普通抽样每晚总额 |
| perPipeline | 3 | 普通抽样每类上限，优先页除外 |
| strictMax | 12 | 加严抽样每晚总额 |
| levels | 6 | 每晚定级抽样总额，0 关闭 |
| lookbackDays | 3 | 候选写入窗口（天） |
| days | 14 | 统计窗口（天） |
| minSamples | 6 | 更新加严状态所需核完页数 |
| threshold | 0.8 | 没有事实问题的比例门槛 |
| fix | wrong | off 不交回；wrong 事实问题交回；all 写法问题也交回 |

候选窗口、统计窗口和最少样本数可通过配置或设置 API 修改。`GET /api/quality` 和 `POST /api/quality/audit` 只给本人；后者在关闭、没有候选、已有抽检排队或运行时不新建运行。远程命令 `omem peer call <设备> quality '{}'` 只读统计、加严名单、等待页数和最近 20 条摘要，不传问题正文。

## 尚未覆盖

页面和 Agent 定级已纳入抽检。记忆、原件标注有各自的复核。核对者可能与写作者使用同一模型，网页会标“和写的是同一个模型”。核对角色本身还没有用已知错误题集检验，因此这些数字表示核对角色的判断，不是已经测定的真实准确率，也不能直接比较不同运行类型的能力。
