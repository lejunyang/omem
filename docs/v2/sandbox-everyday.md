# 日常都在沙箱里跑

目标：本人和成员在这台机器上的本机运行默认都进沙箱，进了沙箱以后能做的事和不进时一样。沙箱不再靠“HOME 只读、少写几处”来约束 Agent，它的作用只有一个：让审批规则绕不过去。要批准的高危操作（某个命令行工具的写子命令、浏览器里对某些站点的写请求）只能经闸门做成，别的照常。

这一页接着 [command-gate.md](command-gate.md)（规则、执行点、执行器、出网代理）和 [next.md](next.md) 第四节的分期表，是第七期。

## 改造前的限制

一台常驻机器上 14 天、约八万七千次带命令正文的工具调用（类别可重叠）：

| 现象 | 占比 | 改造前的行为 |
| --- | ---: | --- |
| 用到要登录的命令行工具 | 19% | 已声明的（凭据插件、内置的飞书 CLI、git 远端、gh、ssh 等）经执行器照常用；没声明的读不到被藏起来的登录 |
| 引用 `/tmp` 下的文件 | 7.9% | 每轮一个私有 `/tmp`：同一轮里写的还在，上一轮写的看不到。对话的下一轮、编码的下一轮都算新的一轮 |
| 读工作区外的 omem 数据 | 4.6% | 整个数据目录看不到：别的仓库和工作区、产物、原件、别的运行目录都读不了（其中多数是本该能读的东西，少数是数据库和密钥） |
| 桌面和浏览器 | 1.9% | X11 套接字和浏览器资料目录看不到，桌面控制做不了 |
| 全局安装、写 HOME 下的配置 | 0.02% | HOME 只读，失败 |
| 起常驻进程（预览、开发服务器） | 0.01% | 运行结束时进程跟着结束 |

另有几处小问题：`~/.gitconfig` 被当作登录藏起来，沙箱里提交没有作者；有的插件把整个 `~/.npm` 声明成登录状态，npm 缓存跟着被藏；有的后端要写的目录（例如 `~/.config/<后端>`）没在后端目录里声明，只读。

这些都不是要拦的东西。要拦的是另一类：带着本人或成员的登录去改远端。

## 原则

- **写照常写，写进沙箱自己的那份。** HOME 用写时复制：沙箱里看到的是真实 HOME，写下的东西落在这个身份自己的一层里，下一轮还在；真实 HOME 不变。宿主、执行器和本人自己的终端会执行的文件（shell 启动文件、PATH 上的目录、命令行工具的安装目录、Python 的 site 目录、git 钩子、corepack 和其他缓存）因此不会被沙箱里的进程改掉。这比列一张“哪些文件不能写”的清单可靠：清单永远列不全。
- **权力留在外面。** 登录文件和令牌、桌面和浏览器、omem 的数据库和密钥不进 Agent 的沙箱。要用它们只能经执行器（受保护的命令）或 omem 工具，规则在那里判定。
- **闸门三处叠加。** 命令规则在执行器前判定（命令名、子命令、参数）；浏览器请求规则在 aad 驱动的浏览器里判定（方法、URL、正文字段）；出网规则在代理里判定，兜住“读到某个令牌后自己发请求”这条路。

## 做法

### 1. HOME 写时复制

已实现。每个身份单独保存版本。数据目录在 HOME 外时，层存在数据目录的 `sandbox-home/`。数据目录在 HOME 内时，用 `/var/tmp` 下服务账号独占的目录，按数据目录和身份分开。沙箱在真实 HOME 的路径上挂载 overlay。登录文件、凭据插件的状态目录和本人加的隐藏目录照旧盖在上面，看不到。

- 照旧真写的只有：后端自己的状态目录（登录续签要写回去）、本人在 `agents.ownSandbox.writable` 里加的目录、本轮的工作区和产物目录。缓存（`~/.cache`、`~/.npm`、pnpm 的仓库）可以读取已有内容，新下载或替换的内容只写进身份层。
- 每个运行以启动时的版本为下层，使用独立的上层和工作目录。进程退出时，宿主在身份锁下发布新版本。并发修改的不同文件都保留，同一路径随后结束的修改生效，同时记录并发合并。删除标记和不透明目录随版本保存。
- `GET /api/security/sandbox` 的 `overlay` 给出本机能力和回退原因，`layers` 给出身份及已保存版本的磁盘字节数。本人可通过 `DELETE /api/security/sandbox/layers/:identity` 清空。清空前开始的运行不会把旧改动写回来。
- 宿主使用系统 Python 3 管理版本。出网隔离时，HOME 的下层再经过 FUSE，只提供目录、文件和链接，滤掉宿主进程的套接字。机器不支持所需的挂载时退回只读挂载，状态接口和运行开头的说明写明原因。
- 成员用自己的 AI 账号时 HOME 本来就是他自己的目录，不变。

### 2. 跨轮的 `/tmp`

`/tmp` 按“这件事”保留：对话按会话，编码交办按交办，流程按事项，其他按运行。放在 `<数据目录>/sandbox/tmp/<键>/`，最后一次用后若干天清掉，有总量上限。执行器仍用自己的临时目录。X11 套接字不放进来（桌面走第 7 条）。

### 3. omem 数据的只读视图

已实现。系统 Python 的 `fuse` 模块按访问路径提供只读文件系统；无法启动时保留数据目录遮罩，并记录原因。仓库和工作树只列 Git 跟踪文件，读取当前工作副本。隐藏文件、常见密钥名和特殊设备不进入资料视图。

- 本人：仓库和工作区（`repos/`、`workspaces/`）、产物、原件文件、技能和档案（`library/`）、别的运行中的补丁、工作树和评审快照。运行上下文、环境和 scratch 留在宿主。产物须已登记；收件目录只为本轮挂回。
- 成员按可访问空间查知识库和托管仓库。产物还检查所属运行，原件只采用宿主保存的来源关系；需要另外核实文档权限的仍经 omem 工具读取。
- 谁都不挂：数据库、`config.json`、`secrets/`、服务自己的目录、远程设备和托管浏览器的资料、备份。读这些经 omem 工具，工具按身份和空间判定。

### 4. 登录配置的只读快照

`~/.gitconfig`（和 `~/.config/git/config`）像 `~/.npmrc` 一样给一份过滤后的只读副本：作者、别名、核心设置留着，凭据助手、`http.*.extraHeader`、带口令的 `url.*.insteadOf`、指向被藏路径的 `include` 去掉。push、fetch 照旧经执行器用完整配置。

### 5. 没声明的登录工具

本人可以在设置里把一个命令登记成“要登录的命令”（命令名、它的登录目录、登录变量），效果和插件声明一样：沙箱里藏起它的登录，调用经执行器。用不着为一个工具写插件。

### 6. 后端都能在沙箱里起来

后端目录里的每个本机后端都要声明它运行时要写的目录。机器上装了的后端都要在新的挂载计划里真起一次会话来确认。

### 7. 桌面和浏览器经执行器

沙箱里调桌面控制（`aad`）时，命令在执行器里跑：它能看到桌面（显示服务的套接字和授权文件）和 omem 托管的浏览器资料，看不到本人自己的浏览器资料。aad 的请求闸门照旧用这次运行的令牌问 omem，浏览器里的写请求按 HTTP 规则判定。aad 有常驻的后台进程时，它跑在执行器那一侧，不随某一次调用结束。

### 8. 出网：分清是谁发的

本人沙箱可以接上出网代理（`security.egress.mode = all-sandboxed`）。HTTP 规则要能分清两种请求：Agent 在沙箱里直接发的，和执行器里受保护的命令发的。后者已经过了命令规则，不该再被“Agent 直接发的”那类规则拦，git 走 SSH 远端也要能用。这样可以写一条“Agent 直接对内网接口主机发请求要审批”的兜底规则，而命令行工具经执行器照常工作。

后端进程自己的流量（和模型服务通信）在后端目录声明的主机上自动放行。后端自己的登录令牌仍在沙箱里可读（后端要用它）；同一个令牌还能调别的接口时，只能靠这条出网规则兜住。

### 9. 常驻进程

已核对。本人可在交办页面选择仓库已配置的预览命令，由宿主启动和管理。预览接口只对本人开放。Agent 工具清单里没有启动宿主预览的入口。

### 10. 打开范围

已按原时间窗复核。读取数据库或隐藏的登录文件、写其他工作区、读取其他运行未登记的产物，仍会遇到权限限制。命令中出现受限路径也可能只是检查文件是否存在。变量拼出的路径、已回收的工作树和后来才登记的产物，无法只凭历史命令判定当时的结果。

逐步放开时保留已有的 `agents.ownSandbox.includeKinds`。常用后端能建立会话、临时文件能跨轮复用、登录命令和桌面操作都经过执行器后，建议将 `includeKinds` 和 `excludeKinds` 都设为 `[]`。受限路径分布在多种运行中，按类型豁免会让同类运行一起失去隔离。

## 规则由本人定

宿主给的是执行点和两种通用的办法，要拦什么由本人和插件定：

- **命令行工具里的写操作：插件判定。** 有的命令行工具有“直接调某个接口”的子命令，写不写要看调的是哪个接口，一条按参数写死的规则表达不了。声明命令的插件可以给命令带一个判定函数：宿主把这次调用的参数交给它，它回答放行、要批准、拒绝或没意见，并给出卡片上的一句话和批准绑定的对象（例如某个接口名）。插件自己的设置里放它的判定依据，例如写接口的动词清单、白名单和黑名单。本人在设置里写的规则先判，插件的判定在后；判定出错按“要批准”处理。
- **审批人可以是调用者。** 规则和插件判定都可以把审批人设成 `caller`：这次运行替谁做事，就由谁批准。本人自己的运行由本人批，成员发起的由那位成员批。
- **浏览器里的写请求：从录制里挑。** 本人在远程页（或自己 Chrome 里的扩展）录一段手动操作，在对话里告诉 Agent 某一步调的接口要审批。Agent 用 `read_recording part=requests` 找到那一步的请求编号，交给 `propose_operation_rule`。卡片展示泛化后的路径、审批人和整段录制的核对结果。本人点“启用”后，规则排在同主机更宽的放行规则前。
- **兜底**：对内网接口主机，Agent 直接发的请求设成审批或拒绝。

内网命令行工具的登录、命令声明、写操作的判定和相关技能都由同一个私有插件提供，不进仓库，宿主里不出现这些工具的名字。

## 边界

- 写时复制以后，Agent 在 HOME 里装的全局工具、改的配置只在沙箱里有效。要改真实 HOME，把那个目录加进 `writable`，或由本人自己改。
- 后端令牌和别的接口共用时，只有第 8 条兜底；要彻底分开，得让后端用只能访问模型服务的凭据。
- 只在 Linux。Windows 和 macOS 仍只有 PATH 垫片。
