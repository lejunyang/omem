# 飞书消息：选择会话、保留材料，再决定要不要跟进

个人登录采集和机器人通知是两条通道。官方 `lark-cli` 用你的身份读取消息；已有机器人绑定负责把需要关注的变化和同步故障通知给你。采集器没有发送、回复、删除或标记已读的接口。机器人不需要加入被采集的每一个群。

## 现在怎样使用

在 `osdk run dev` 的「飞书消息」页点击「读取最近活跃会话」，发现最多 300 个会话，默认排除免打扰。发现不会自动订阅。选择「订阅」的群或单聊持久保存；「仅提及时」不定时拉普通消息；「排除」连提及也跳过。首次回溯默认 24 小时，同步默认每 5 分钟一次，均可在页面调整。最后勾选「开启定时采集」并保存。

**新库默认暂停。** 实际采集设置保存在个人数据库，开发服务和后台服务使用同一数据目录时共享设置。切换服务前先停止旧进程，不同时运行两个采集实例。

每页最多 50 条，分页游标、时间窗、订阅和待处理工作写入数据库；处理完一页再推进位置，重启可接着处理。页面可暂停、立即同步、查看原消息、实际理解结果和关联项目、打开原件，以及重试失败的资源读取。会话选择和采集设置放在折叠区；默认先看消息及其需要跟进的内容。发现结果只提供选会话的候选，不承诺这 300 个会话覆盖全部关注对象。

## 消息理解和纠正

消息旁显示的是实际流程：原文已保存 → 正在理解/独立复查 → 已更新记忆或事项，或者需要补充、理解失败、已阅读但没有新增记忆。依据是后台 job、proposal 与应用回执；分类分数不充当理解结果。保存的约定、事实和个人待办用可读文字展示，已被更新的旧结论折叠为历史。项目关联显示正式项目名称；需求仅选入材料和已经引用这条消息分开标记。

点击「纠正理解」可以说明提议尚未决定、负责人不对等情况。默认只针对本条；明确选择同会话后续消息时，才作为后续偏好使用。本人原话保存为新的固定材料，重新调查原消息及相关需求；旧结论在处理完成前保留。有效纠正变化会使正在处理的旧输入失效，不直接改记忆、授予编码权限或发飞书消息。撤销后退出新的调查输入，历史原文和旧引用仍保留。理解失败时「重新理解」只使用本地已保存材料；资源失败则继续用「重新读取与判断」。

日常助理的项目跟进按最近变化、待确认与阻塞、等待回复和个人待办组织。可以直接调整关注点和反馈，打开行动来源及完整需求。个人待办仍来自既有应用与行动关联流程，不把别人的承诺直接变成我的任务。

## 免打扰和提及

普通群同步前重新读取群设置，免打扰期间跳过普通消息，也不在解除免打扰后补拉整个静默时段。另一个提及通道用官方搜索的 `at_chatter_ids` 查询当前用户：官方语义包含 @我 和 @所有人，可以覆盖没有普通订阅的免打扰群。关闭「同时检查所有群里的 @我 / @所有人」即可收窄到普通订阅。

`is_muted` 和 `is_mute_at_all` 是两个设置：仅免打扰仍保留提及；明确屏蔽 @所有人则忽略此类广播，直接 @我 仍保留。当前授权可见范围和搜索服务返回范围仍由飞书决定。

真实只读实验已得到 18 条提及搜索结果；这组结果没有可单独确认的 @所有人样本，因此 **@所有人的官方查询语义和程序分流已经接入，真实命中仍未验收**。上一轮抽查的 9 条未读消息重读后仍是未读；本轮采集只调用读取接口。这些观察不等于我们控制飞书客户端的未读实现。

## 不只处理文字

| 输入 | 当前处理 | 还没有完成 |
| --- | --- | --- |
| 文字、富文本、卡片 | 保存 CLI 展开的正文、原始消息、作者、时间和固定版本；话题回复作为独立消息保存 | 普通会话上下文目前只取已入库的前 8 条；不是无限回溯 |
| 飞书文档链接 | 用现有官方 CLI 导入器保存独立文档版本，并把导入结果提供给本条材料处理 | 不自动递归抓取无限层引用；画板、嵌套资源仍受现有导入器能力限制 |
| 图片 | 保存原件；PNG/JPEG/WebP 小于 5 MB 时作为图像输入交给支持视觉的 ACP 角色 | 文本决策模型不会读像素，不把下载成功说成图片已理解 |
| PDF / DOCX | 下载后复用 Docling，保存附件原件、解析正文与结构 | OCR、复杂布局仍有限；消息下载与标准 CLI 的 PDF/DOCX 导入均限制为 20 MB；超限需缩小或拆分文件 |
| 小型文本附件 | TXT/Markdown/CSV/JSON/log 作为文字输入 | 大文件需要单独导入 |
| 视频、音频和其他附件 | 保留可下载原件，提示仍需理解 | 没有自动转写或视频分析 |

资源权限失败、尚未读取、话题回复未拉全，都显示在消息旁，不把缺背景消息自动应用为记忆。原始消息仍保留；「重新读取与判断」会重试资源处理。CLI 对话题的自动展开有数量限制，目前没有额外的话题分页补全。轮询保留一分钟重叠，能去重并发现这个窗口里的变化，尚不能完整检测很久以前的编辑或撤回。

## 决策模型究竟决定什么

复用 StartLux 2B/4B 共用服务，`decisions.mode=auto` 根据机器内存余量与负载选择一份常驻模型；不运行时下载模型。查看[准备方法和实测](fast-decisions.md)。

每条消息结合本人身份、已保存的前文、当前事项和已读取资源，判断七个维度：安排与跟进、学习、业务知识、代码、关注原因、缺失背景、可疑指令。关注原因区分行动请求、等待的进展、变化、信息、噪声和不确定。被 @ 不直接等于被交办，其他人的承诺不直接变成我的待办。

高分噪声且无资源的消息暂不交给大模型整理，但原件保留；可疑指令单独留待检查。其他完整材料交给现有 Agent 调查、提取和独立复核，最后仍由 MemoryService 应用。低分或决策服务不可用也可以走 Agent；模型标签没有事实写入权。配置中必须开启已有 learning 后台并提供可用 ACP profile，排队不代表已经生成记忆。

本轮用真实私密消息中的文字、富文本、卡片各一条试跑 2B，暖机两条分别约 2.65 秒、1.56 秒，首条含加载约 26.60 秒。关注原因分数只有 0.155–0.264，不能称为分类准确；界面提示需要 Agent 补查。模型还曾在附件未读时选“上下文充分”，宿主按资源状态保留缺口，禁止据此假定已经读全。此次没有运行这三条私密消息的完整 Sol 记忆应用；工程检查与排队成功不能替代内容验收。

## 通知与服务状态

复用已有 `owner_notification` 绑定、通知队列与飞书投递 worker，不另建发送通道。一个会话连续同步失败只首次提醒，恢复后再提醒；已应用的记忆与事项继续走原有通知路径。未绑定时站内保留变化，不向被采集群发消息。已有机器人发送流程由用户确认已验证，本轮未再次向飞书发送测试通知。

后台管理使用项目锁定的 PM2，操作见[运行说明](operations.md)。`osdk run service:status` 同时检查进程、API、采集是否开启、订阅数量和异常数量；非正常状态返回非零退出码。服务自己完全退出时无法给自己发送故障消息：PM2 会尝试重启，持续失败需要外部监控状态命令。电脑休眠时任务不运行，重启电脑后的系统启动项尚未安装。

## 修改入口

- `integrations/lark-personal/client.ts`：只有只读方法的官方 CLI 适配；查询、提及、偏好和资源下载。
- `materials.ts`：多模态资源进入共同 Capture → Source / Revision。
- `policy.ts`：多维判断问题；`service.ts`：订阅、分页、重试、分类和现有学习流程的连接。
- `integrations/lark/owner-notice.ts`：复用原有通知投递，消息采集不直接发送。
- `messages/understanding.ts`：投影实际后台理解、应用结果和需求关联；`messages/feedback.ts`：本人纠正的固定原件、作用范围、重试与撤销。
- `PersonalLark.vue`：会话选择、资源与实际理解结果；`AssistantWorkPanel.vue` / `FollowupFeedback.vue`：项目状态与直接纠正入口；`scripts/service.ts`：后台进程与健康状态。

后续继续评估跨消息上下文、外部回复是否满足已保存的等待条件，以及资源缺口的补读；当前状态可见与纠正入口不代表完整自动跟进已经可靠。

## 查看隔离演示

开发者可用 `osdk run demo:followup` 在一个 gitignored 目录生成可查看的数据：合成群聊、需求文档与小仓库，真实 Traex ACP / gpt-5.6-sol 负责调查、写作、独立复核、记忆理解和编码。这个命令不调用飞书，也没有外部通知绑定；需要已登录的 Traex。已存在的演示库不会重复生成。

```bash
osdk run demo:followup
OMEM_REPO_ROOT="" OMEM_DATA_DIR="$PWD/.repo-review/runtime/followup-demo/data" OMEM_CONFIG="$PWD/.repo-review/runtime/followup-demo/config.json" osdk run dev
```

按服务打印的地址打开日常助理和飞书消息。空 `OMEM_REPO_ROOT` 让这一演示只显示自己的合成材料；日常开发仍使用原来的个人库。演示库包含固定原文、真实模型输出和编码副本，查看结束后再清理，不能在服务仍运行时删除。真实业务项目的正确性仍需要另行验收。
