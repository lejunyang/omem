# 当前实现、不足与解法

实现说明更新于 2026-10-04。本文描述已接通的能力；[整体复审](review.md) 进一步核对了实际发布文章、失效机制与外部检索结果。六篇指南均待更新、逐文件说明仍占主要目录、调查读取与章节依据未分开，是下一步优先改变的结构问题。早先“全局搜索还是 LIKE”“角色完全不能补读”的结论属于旧基线，不能当今天状态。

## 先区分质量的四个问题

事实是否成立、读者是否理解、问题是否得到完整回答、内容是否帮助行动，是四种不同质量。引用位置与 schema 检查只覆盖其中很小一部分。独立 verifier 对事实支持性有帮助，但同一模型分开会话仍可能有共同盲点；它不能代替实际读者。

此前的偏差是把证据保存和局部检查当主要交付，逐次修复用户反馈，却没有围绕“第一次认识系统、带问题找回信息、利用经验行动”形成统一流程。正确的修正是改变调查与讲解方法，而不是再加一句通俗提示或更多边界测试。

## 材料接入与清洗

`store.ts` 保存 Capture、Source、Revision、Fragment。相同输入可去重，内容变化保留旧版。文本、链接、图片和来源元数据进入共同体系。仓库适配器过滤二进制、依赖和生成文件等，原文基本按原样保存。

保存仍以保真为主，旧 Fragment 的空行切分没有被当作阅读目录。`retrieval/units.ts` 另建 Markdown 章节、完整函数和会话的检索投影，结构背景已进入全文与中文向量；引导句与紧随的列表、表格或代码尽量一起返回。长单位仍需要向量窗口，窗口不改变原件或阅读结构。

新增材料用途整理：原生 Agent 阅读后，为固定版本保存主要用途、状态、主题、适用对象、明确的有效期和带原文行的概念别称。读者可在原文旁查看、修正；人工修正优先，新原件版本不继承旧分类。当前明确触发，尚未自动处理每份新输入，也不能把一个主要用途用于准确描述混合文档的每一段。

解法：原件不可变，另建解析与检索投影。Markdown 使用 marked 保留标题、列表、围栏和表格；代码保留符号与所在模块；会话保留参与者、回复链及事件背景。复杂 PDF/DOCX 用 Docling 适配，不让通用 Capture 接管外部解析器的数据库或 UI。图像可进入视觉分析，但当前没有通用 OCR/布局定位和视觉索引闭环。

## 检索与 RAG

主要入口现在使用 `UnifiedRetrieval`：ICU 中文分词、SQLite FTS5 BM25、osdk 锁定的 BGE-small-zh-v1.5、CPU ONNX 和 SQLite 向量比较。全文/语义候选融合一次，过滤弱向量尾部，再合并重复、限制同来源摘录。讲解正文、原件、记忆和事项使用共同的 `RetrievalHit`；知识命中直接返回讲解及其固定引用，不只返回原始片段。旧 Keyword/Semantic 模块保留兼容，不代表今天主入口仍按旧方式多次融合。

此前噪声的成因包括两字泛词、标题扩散、整份 artifact JSON 命中、知识全章引用扩散和多次融合。现在主要只搜索读者正文，按命中段落回溯引用，并保留结构背景；这些修复没有让相关性问题消失：

1. 提到同一主题不等于能回答问题，词法覆盖仍可能命中复述问题的调研。
2. 明确符号已独立召回，调用方也有名称级候选；这改善定位入口，但未解决长机制问题所需的完整功能链和接收者类型。
3. 计划与实现混杂。正式材料用途开始参与排序，但未分类来源和同页混合用途仍可能误导。
4. 中文 cross-encoder 已可选接入，真实对照同时出现收益与退步，未默认启用；去重和重排均不等于回答完整性保障。

`assistant/runtime.ts` 已通过原生 ACP 调查器反复搜索、补读、查记忆、固定历史与代码导航，再提交答案候选。材料/知识工具共享检索，可按正式用途和明确有效期筛选；这仍不是完整时态推理、跨文件功能链或可靠的无答案判定。长期会话有历史和用户纠正，不是持续维护的项目理解。

正式材料说明和段落概念已经接入：用途/时间在候选截断前过滤，默认降低计划、调研、示例和过时状态的排序偏好；概念仅进入其原文范围，供 BM25 与中文向量共同使用。偏好是产品策略，不能冒充事实判断。现在的重点是拆开候选召回、回答上下文和界面去重，检查这些规则是否丢掉必要材料；本轮外部词法对照未显示稳定优于简单基线。见 [材料用途与概念入口](material-understanding.md) 和 [外部评测](external-evaluation.md)。

## 代码理解

`code/parse.ts` 使用 TypeScript 单文件语法树与 Vue SFC 脚本，不是完整 Program/TypeChecker。相对 import 能定位；calls 仍有单文件名称级 candidate；跨 revision 身份续接有限。显式设计/测试关联来自 associations.json，结构候选不是已确认业务关系。

AST 回答“定义在哪里、有哪些结构”，业务意义需要调查调用者、类型、配置、测试、设计记录及输入输出。一条真实功能链通常跨页面、请求入口、保存、任务、模型和展示。不能按文件各写几百字，再期待目录汇总自动解释因果。

调查现在可使用原生 Read/Grep/Glob 与 MCP 符号、原文、讲解和历史工具；固定原件也导出为临时文件。Agent 可以围绕案例补读完整实现与背景，AST 是导航辅助。代码概念说明同样能按具体行进入检索；它仍是模型理解，不是完整业务调用图。是否真正解释了因果，要抽读文章和任务结果，不能由工具调用次数判断。

## Wiki 与 harness

材料说明兼容路径与按读者目的的 `writePage` 并存。读者路径从页面目的、案例、问题和阅读后行动出发，由原生 Agent 自主调查写作，再由独立角色重新补查。发布前仍有有限的修订尝试；调查的模型/工具循环交给 CLI harness，没有宿主输入输出 token 限制或固定三轮研究限制。

知识研究与材料用途角色使用原生 skill、只读 MCP 和固定材料目录。研究、写作和独立复核有各自目的与输出；最终通过 `submit_result` 提交 schema 校验的候选。一次 ACP prompt 内可以有多次模型和工具交互，不能用请求数推断推理轮数。当前没有文件系统层面的完整隔离，原生 CLI 仍可能读取祖先指令；只读权限不等于只能看到导出材料。

中间说明、工具状态、最终候选已经分开，普通助手页面能显示调查进度、取消及继续追问。完整 trace 用于诊断，不直接进入文章。schema、引用检查、独立补查共同减少事实错误；文章是否短、易懂、有案例和操作入口仍需人读。真实回答已有过长、重复说明的问题，不能因复核通过就称内容质量解决。

Traex 已实际用于 ACP。Codex/Claude 有 CLI 输出适配与示例 profile，但当前助手只接受 ACP；Claude CLI 参数关闭工具。角色 profile_ref 和 native skill 路径还带 traex 偏好，多提供方对等接入未完成，不宣称均已实测。

## 长期记忆与主动事项

claim 表达事实与归属/有效期；episode 记录触发、行动与结果；procedure 记录步骤、前提和反例；task 用于交办和跟进。抽取 → 独立复核 → MemoryService 应用有实际链路，来源更新能重核验并保存历史。模型没有直接事实写入权限。

这些记录还没有稳定形成“这个项目现在是什么情况、这个人有什么背景、我过去哪些做法有效”的综合理解。事件时间不等于捕获时间；有效期字段不等于完整时态检索。每个配置文件自动抽取也会制造低价值条目和任务负担。

应按价值和目的选择记忆，再形成经历、当前事实/偏好/经验、持续维护的人物/项目/主题理解，最后用于行动。比较 Hindsight 的整合与 mental models、Graphiti 的时间关系，先做原件适配与同题对照，能减少自研就使用组件。任务已有等待、改期、完成和站内提醒；自动监听回复、周期回顾、英语卡片仍待实现。

## 人如何认识陌生系统

以一个实际场景建立问题，再跟完输入到结果的旅程，途中认识最少术语，随后看整体地图、关键机制和取舍，最后尝试修改或排障。初学者不是先背 Source/Revision/Fragment；先看到“同一规则变了，为什么旧回答还能打开旧原文”，再认识来源和版本。

教程、概念解释、操作指南、机制、决策和参考各有目的。入门主线不讨论 200 层 URL、JSON 修复、测试计数。原文章中出现“此前引用已被新范围替代”等编辑过程属于质量失败，即使每句话有出处也不能发布为系统解释。

验收用真实问题和读者操作：是否能解释主流程、找到必要背景、定位修改入口。给齐材料仍答不好属于生成失败；给齐能答好而检索后答不好属于召回或上下文失败。先做可读页面和任务，不先追求全库覆盖率。
