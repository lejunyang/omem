# 可编辑的知识目录草案

知识库里的多篇文章应有一条可理解的阅读路线。目录草案先记录你要了解的主题，以及每页准备回答什么问题；你可以调整后再确认写作。保存草案不会改动正式目录，也不会自动生成正文。

例如，新同事拿到需求文档和一个陌生代码仓库，想知道如何修改某项功能。按文件列出材料通常无法回答这个问题。可以先规划“用一次操作认识功能”，再解释其中的概念，接着讲主流程，最后给出修改入口。这里的标题只是例子，实际目录由读者目标和材料决定；读者也可能只需要一页排障指南。

## 从网页开始

进入知识库，打开“规划知识目录”，新建目录草案。

1. 选择已保存的文档、代码或会话材料，也可以选择正式项目或主题。项目范围包含后来加入的材料；另选的来源作为明确的背景保留。服务不会因为你规划目录就抓取新的外部仓库或飞书文档。
2. 填写目录名称、整体阅读目标和读者。可以写“第一次接触这个系统，想知道一次请求怎样运行，以及修改权限判断应从哪里入手”。分类路径用 `/` 分隔知识层级，留空时由页面分别设置。
3. 选择“让 AI 建议目录”，或者手动添加页面。AI 会搜索并补读所选范围，查看已有讲解后给出目录理由和背景缺口；这一步只生成页面计划。
4. 检查每页标题及用途，补充场景和要回答的问题。可以调整阅读顺序、修改分类路径，增删每页材料，合并重复页面。已有文章可以加入草案作为更新目标，继续使用同一篇文章的身份。
5. 保存草案。确认路线和范围后，选择“确认目录并开始写作”。各页进入自主调查、撰写和独立补查，完成发表后才能阅读新正文。

尚未配置 Agent 时，可以保存并手动编辑草案，目标和选材尚未填写完整也能先保存。发起目录调查或确认写作前，需要补齐整体目标和读者，并选入至少一份已有材料；选择项目或主题时，该范围也需要已有材料。AI 拟目录和确认后的正文整理需要在“能力与连接”配置已登录的 Agent、模型及相应思考强度。发现模型选项不代表已经拥有实际调用权限。

合并页面会合并草案里的问题和材料，保留选定的目标页面。它不会删除已有文章；从草案移除页面也只取消本次计划。关闭时有未保存修改，应先保存再继续，否则刷新页面可能丢失本地修改。已保存草案位于当前个人库，可以换窗口继续查看。

## 草案、页面计划和正文各保存什么

| 对象 | 保存内容 | 什么时候改变正式知识 |
| --- | --- | --- |
| 目录草案 | 整体目标、读者、所选范围，有顺序的页面建议，以及调查理由和缺口 | 编辑和 AI 提议都不改变正式页面计划 |
| 页面计划 | 每页用途、问题、分类与范围，正式页面身份和顺序 | 确认整个草案时保存，并安排写作 |
| 正文版本 | 章节、固定引用，生成与独立复核记录 | 写作和复核完成后发表 |
| 原始材料 | 来源及历次内容版本 | 沿原有 Capture → Source / Revision 流程保存 |

草案里的 `materialKeys` 指已保存来源的当前材料，不能将它当作某次原件的固定版本。`contextIds` 指正式项目或主题的成员范围。Agent 开始目录调查时才固定本次快照；确认后，各文章在自己的调查开始时读取当前范围并固定快照。草案调查后原件有变化，正文会基于写作时的材料重新调查。

每页材料必须属于整个草案的所选范围。某一页需要别的背景时，先把来源或项目加入整个草案，再分配到该页。`entryPaths` 只是范围内的调查入口，不能借它扩大读取权限。

确认后，正式目录的标题、分类与顺序可以先采用已保存计划。旧正文继续可读，页面会提示目标已调整或内容待更新；新计划不会改写旧正文，也不会改变旧引用指向的版本。复用同一文章可保持阅读链接，新增文章的正式 key 则由宿主分配。

## 进度和失败怎么处理

| 草案状态 | 意义 | 下一步 |
| --- | --- | --- |
| `editing` | 人工草案已保存 | 继续编辑，或请求 AI 建议 |
| `planning` | 目录调查已排队或正在执行 | 等待查看，或选择“停止调查并编辑草案”；还没有开始正文写作 |
| `ready` | AI 建议已保存 | 检查页面和范围，修改后再确认 |
| `failed` | 目录调查没有完成 | 看错误，已有页面建议仍保留，可以修改或重试 |
| `applied` | 正式计划已保存，写作已排队 | 检查每页 `pageStatuses`；排队不等于发表 |

页面写作失败或取消后，草案已确认这一事实保持不变。在草案的每页进度中选择“重试整理”，或通过知识库该页的重新整理入口重试，旧文和固定历史继续保留。已有文章正在写作时，确认包含它的新草案会提示等待；本轮不在运行中覆盖它的目标。

想保留现有路线再让 AI 重新建议，可以先“另存为新草案”，后续修改只影响副本。调查过程中选择“停止调查并编辑草案”，会保存当前计划并取消旧调查，之后可以手动调整或重新调查。停止调查不会删除已经保存的页面建议。

更新草案需要当前 `version`。其他窗口或 Agent 已更新它时，服务拒绝旧版本覆盖；重新载入现状，比较后合并修改。AI 完成调查也会产生新版本，因此不能拿发起调查时的 version 直接确认结果。已确认草案不能继续编辑；网页可用“复制并调整目录”建立新草案并复用正式文章，也可以调整正式文章的材料与目标。

删除草案只删除这份计划。已排队的目录调查会取消；已确认草案对应的正式文章及写作任务不因删除草案而撤销。正文任务的取消或重试仍使用现有任务管理入口。

## 让外部 Agent 代办

已有 CLI 能力的 Agent 读取随包 [omem-cli 技能](../../skills/omem-cli/SKILL.md)和[目录草案指引](../../skills/omem-cli/references/knowledge-outlines.md)，可以替你查询材料、拟定计划并修改草案。先用 `knowledge list` / `contexts list` 获取真实 key 和 ID，再用 `knowledge outline create/propose/show/save`，最后按你的明确确认 apply。

当前主助手的自然语言 `work_action` 还没有注册目录草案操作，不能把“机器人能够管理定时任务”推断成它已经能规划目录。外部 Agent 通过 CLI 操作和网页编辑是本轮入口。调用者应报告具体状态和错误，不要求用户自己串联命令，也不替用户假定已确认目录。

## 现有代码如何接起来

`packages/contracts/src/knowledge-outline.ts` 定义草案、页面建议与返回状态。草案页面保存临时 `id`；只有确认时才生成正式文章 key，或沿用明确选择的 `existingKey`。

`apps/server/src/knowledge/outlines.ts` 将草案写入同一个个人库的 `knowledge_outline_drafts` 表。`knowledge:outline` 使用现有持久任务队列；版本和 job 身份核对后才接收模型建议。人工保存会取消旧调查请求，迟到结果不能覆盖新编辑；模型失败时保留之前的页面。

`knowledge-outliner` 角色通过现有 native research 工作区调查。所选快照提供原件读取，以及 MCP 检索和代码导航；已有文章帮助理解，不能充当新的独立原始事实。结果通过合同提交为候选草案，模型没有应用权限。

`apps/server/src/knowledge/api.ts` 提供 `/api/knowledge/outlines` 的创建与查询，草案更新，以及 propose/apply/delete 操作。确认前先检查所有页面的范围和已有文章状态，再用同一事务保存每个 `WikiPageBrief` 并调用 `KnowledgePageService.refresh`。它复用 `KnowledgePageWorker` 和 `KnowledgePipeline`，不再增加一套正文生成器。

`apps/web/src/knowledge/KnowledgeOutline.vue` 承载选材和目标、页面编辑与进度展示；`outline-editing.ts` 处理顺序、路径与合并。正式知识阅读仍使用现有 `KnowledgeHome` 和引用下钻组件。目录按照持久计划的分类和顺序展示，原正文及固定历史独立保留。

## 当前限制

- 草案最多 32 页。它处理明确选材后的阅读组织，全库自动分类和去重治理仍未完成。
- 复用已有文章要求它具有普通正式页面计划；需求跟进页使用自己的工作流，不能在目录草案中覆盖。同一已有文章在一个草案里只能出现一次。
- 确认时所有页面都安排写作，尚未提供只应用导航并逐页选择写作的选项。模型重拟建议会替换草案页面，应先核对修改再使用。
- 合并和移除只作用于草案，尚未实现已发表文章的自动退役或历史迁移。
- 目录建议和独立复核不能证明文章已经易懂。仍需检查案例是否帮助理解，页面能否回答问题，以及是否提供实际修改入口。本轮结果以[进度页](progress.md)为准。
