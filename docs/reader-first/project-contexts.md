# 让后来的记录进入同一篇项目说明

一篇活动说明已经整理好，后来又收到场地变更。仅仅把新消息保存进知识库，不等于它已经属于这场活动。现在可以明确建立项目或主题，把文档、代码、聊天和图片放到同一个材料范围，让文章持续跟踪这个范围。

## 怎么使用

1. 在“输入材料”里选择项目或主题，没有时可以就地新建。名称描述对象，范围说明写清哪些事情属于它；保存材料时归属一起保存。已有材料在原文的“所属项目与主题”里调整。
2. 整理文章时，选择“持续跟踪项目或主题”。现有材料会出现在选材列表，仍可以另外选择背景材料。这里选择的是材料范围；文章分类和正文引用各自保留用途。
3. 文章生成后，开启“随所选材料自动更新”。属于该项目的新材料、已有材料换版或材料移出，会触发同一篇文章的调查、更新和独立复核。关闭自动更新时仍可手动重新整理。

例如“阅读小组”已有活动时间和费用约定，后来把“场地改为东侧阅读室、小周负责签到”的消息存入同一项目，文章会纳入新安排。同名但没有加入项目的另一场活动不会进入材料范围。模型仍需分清时间、负责人角色和哪些旧约定被替换；范围正确不能代替理解正确。

项目选入的材料随整个范围加入，不能在这篇文章里单独取消其中一项。若归属错误，去原文调整；若文章只讨论其中一部分，取消跟踪整个项目，改为明确选材。一个材料可以属于多个项目或主题。原件换版保留归属，移出不会删除原文或旧文章引用。

## 已实现到哪一层

`MaterialContexts` 保存项目/主题以及到稳定 source 身份的关联，当前仍是 personal 单用户范围。归属是明确的用户输入，与材料正文分开；不会把文件路径、会话 ID 或相似标题当项目。输入接口在保存原件的同一事务中写归属，无效项目不会留下半份捕获。

文章计划保存 `contextIds` 与额外 `materialKeys`，每次调查按当时归属解析材料集合。跟踪动态范围的发布资产另存这次实际选择的材料键；明确选材的计划已经保存这些键，开放调查也不为每篇文章重复存一份整库目录。调查记录与引用仍按固定版本保存。范围在生成途中变化时，旧结果不会覆盖新范围；自动维护下一轮处理最新集合，失败期间旧文继续可读。文章维护复用现有持久队列和研究、写作、复核角色，没有新增一套生成管线。

修改入口：`contexts/repository.ts` 和 `store.ts` 管保存，`knowledge/repository.ts` 解析范围与发布检查，`page-worker.ts` 观察新增/移出，`pipeline.ts` 与 `maintenance.ts` 提供当前材料及变化，网页的 `ContextPicker`、`SourceContexts`、`ArticleComposer` 提供入口。

## 围绕项目提问

个人助手的原生调查现在可以查看已保存的项目名称、范围说明和成员，再按项目查原件、已有解释、记忆或代码。例如两个项目都叫“新版发布”，范围分别是 Web 和移动端，用户问 Web 验收安排时，助手可以先辨认项目，再读取其中没有重复项目名的“负责人改为许宁”消息。归属提供查找范围；哪条消息替代旧约定，仍需读正文判断。

`list_material_groups` 返回本次可读的项目与主题，`groups.json` 提供相同目录。`list_materials`、`search_materials`、`search_contexts`、`search_knowledge`、`search_memories` 和 `code_navigation` 接受其中的 `groupIds`。多个项目取并集；同时指定材料键时取交集。项目及成员随原件一起封存，调查中途修改归属不会悄悄改变该次结果。

目录仅列出本次获准原件涉及的项目，数量不是整个个人库的总数；没有出现在目录里不等于不存在。群聊调查暂不提供个人项目名称和范围说明。网页普通搜索尚未提供项目过滤。

### 会话如何记住正在谈的项目

个人会话保存 `project_id`。Agent 根据当前问题、已澄清的会话和实际材料，从正式项目中提交 `project_selection`；歧义没有解决时保持空值，切换项目时换成新 ID，无关问题或跨项目比较时清空。选定对象与成功回答一起保存，失败/取消不改变它，重启后仍能继续。材料主题可用于搜索，但不冒充事项的项目身份。

后续初始召回在排名截断前按该项目的来源成员筛选，上轮引用也按此范围重选。它只是读材料的起点，不是权限：Agent 的原生工具仍能查询其他已授权材料，发现问题换了对象时可以重新调查。尚未辨认项目的首轮仍搜索整个可见库；本轮切换对象后的深查由 Agent 发起，没有额外增加一轮固定路由模型。

新事项把本轮项目写入 `tasks.project_id` 和事项历史，当前交办原文也加入该项目。已有事项改期、完成或延后保留事项原项目，相关指令按事项归属保存，不随当前聊天主题迁移。事项列表传给 Agent 时包含项目身份，MemoryService 仍负责授权、版本和应用回执。没有给群聊开放个人目录，也不将项目选择当作事实写入权限。

修改入口：`assistant/runtime.ts` 管初始选材、结果应用与事项归属，`assistant/research.ts` 校验可选择项目，`acp-model.ts` 提供讨论对象和工具上下文；`conversation/router.ts` 保存跨轮身份，`storage/repository.ts` 保存事项及版本的项目。普通事实抽取的项目 scope 仍未接上，不等于已经有持续项目综合记忆。

**还没有实现从内容自动判断归属。** 不同项目的相似消息、转述和模糊代词，需要后续结合现有材料调查再建立关系。这次也没有把该关系直接接到记忆写入的 `project_trusted`、全库搜索的项目过滤或外部会话自动归属。MemoryService 的事实/事项权限不变，不能把文章自动维护称为完整项目助理。

## 验证

工程检查覆盖实际 HTTP 捕获与归属修改、换版保留归属、无效项目不保存原件、重启后新材料进入文章、同名未关联材料排除、移出后重新整理和旧版本回读。界面经真实 API 20 项与实际 dev 12 项检查，并抽看桌面、768px、390px 截图。

项目调查的 MCP 检查覆盖同名项目按范围分别检索、同一材料多组归属、调查期间修改归属后快照保持原范围，以及群聊不暴露个人项目目录。

2026-10-05 的真实 Sol 三轮对话约 139/49/33 秒：含糊询问时列出 Web、移动端和未归属的同名记录，澄清 Web 后正确使用更新的负责人、沿用的截止时间和“不改交互则无需功能重验”的条件；追问“找她确认”创建了一条联系正确负责人的事项。目录工具实际被使用，但这份小库首轮就召回了四条短原件，后两轮主要读取会话和初始上下文，没有实证大库中按 `groupIds` 搜索的收益。

检查实际内容和持久状态发现两个问题：首稿擅自默认用户通常问 Web，由独立复核纠正；提醒时刻虽正确，却存进了完成期限，后续通知会称为到期。这次旧结果仍保留为失败依据。随后补“先辨认对象再答”的调查顺序和新建提醒字段说明，区分完成期限与检查时刻，并让回执如实展示字段含义。

修正后同样三轮真实重放约 62/57/36 秒：先明确询问移动端还是 Web，没有默认某个项目或启动独立复核；明确 Web 后通过指定其两份材料的分问题检索核对负责人、截止和例外，回答不再追加素材审核问题。追问保存一条“找许宁确认 Web 端验收结果”，`dueAt=null`、`next_check_at=2026-10-07T07:00:00Z`。调用真实站内调度入口时，提前不提醒、到点生成一条“事项待跟进”、重复检查不重发，没有虚构完成期限。此处推进的是隔离库的检查时钟，没有等待真实日期或发送外部通知。

上述结果来自四条短合成原件，第一轮已能全部召回；只证明对象澄清、变化条件和提醒语义这条流程，不代表大库检索收益或稳定时延。该次实现还没有事项项目身份，不能继承为本轮贯通后的真实验收。材料时刻的时区解释仍用了会话默认值。报告与 trace 在 `runtime/research/project-scope-flow/report.json` 和 `project-scope-replay/report.json`，完成后均释放临时数据库，没有写入个人库；后续实验覆盖更新专项简报，不继续积累副本。

本轮持久项目身份的工程检查已覆盖重启、关闭聊天历史输入后仍按项目召回、新事项与交办原文归属、切换聊天项目后修改旧事项，以及无关事项不继承项目。真实 Sol 重放另行核对，不能把协议测试当作模型会正确辨认对象。

实际 Traex ACP / gpt-5.6-sol 已完成三步：按项目首次生成活动说明约 151 秒；停机后原件换版、重启自动维护约 120 秒，把费用 80 元改为 120 元、截止 18:00 改为 20:00；另存一条属于项目的聊天约 171 秒后，文章改为东侧阅读室、小周负责签到，保留小林组织、活动时间、费用包含材料费但不含交通费、报名截止等条件。另一场同名但未关联的 999 元活动未进入调查范围，旧文与固定引用仍可读。最后正文是一节两段，没有额外未知问题；首次稿曾把“含材料费”收窄成“只含材料费”，后两稿没有这个额外限制，说明仍需检查措辞。结果覆盖同一个 `page-maintenance.json`，实验数据库已释放。这是一组明确归属的合成活动记录，不代表模糊归属、复杂项目或时间推理已经解决。
