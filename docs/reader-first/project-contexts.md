# 让后来的记录进入同一篇项目说明

一篇活动说明已经整理好，后来又收到场地变更。仅仅把新消息保存进知识库，不等于它已经属于这场活动。现在可以明确建立项目或主题，把文档、代码、聊天和图片放到同一个材料范围，让文章持续跟踪这个范围。

## 怎么使用

1. 在“输入材料”里选择项目或主题，没有时可以就地新建。名称描述对象，范围说明写清哪些事情属于它；保存材料时归属一起保存。没有指定时，启用后台原生 ACP 处理后，会先调查已有项目和相关原文。已有材料在原文的“所属项目与主题”里查看判断原因或调整。
2. 整理文章时，选择“持续跟踪项目或主题”。现有材料会出现在选材列表，仍可以另外选择背景材料。这里选择的是材料范围；文章分类和正文引用各自保留用途。
3. 文章生成后，开启“随所选材料自动更新”。属于该项目的新材料、已有材料换版或材料移出，会触发同一篇文章的调查、更新和独立复核。关闭自动更新时仍可手动重新整理。

例如“阅读小组”已有活动时间和费用约定，后来把“场地改为东侧阅读室、小周负责签到”的消息存入同一项目，文章会纳入新安排。同名但没有加入项目的另一场活动不会进入材料范围。模型仍需分清时间、负责人角色和哪些旧约定被替换；范围正确不能代替理解正确。

项目选入的材料随整个范围加入，不能在这篇文章里单独取消其中一项。若归属错误，去原文调整；若文章只讨论其中一部分，取消跟踪整个项目，改为明确选材。一个材料可以属于多个项目或主题。原件换版保留归属，移出不会删除原文或旧文章引用。

## 已实现到哪一层

`MaterialContexts` 保存项目/主题以及到稳定 source 身份的关联，当前仍是 personal 单用户范围。归属与材料正文分开，记录手动选择或模型调查的来源；不会把文件路径、会话 ID 或相似标题直接当项目。输入接口在保存原件的同一事务中写手动归属，无效项目不会留下半份捕获。

文章计划保存 `contextIds` 与额外 `materialKeys`，每次调查按当时归属解析材料集合。跟踪动态范围的发布资产另存这次实际选择的材料键；明确选材的计划已经保存这些键，开放调查也不为每篇文章重复存一份整库目录。调查记录与引用仍按固定版本保存。范围在生成途中变化时，旧结果不会覆盖新范围；自动维护下一轮处理最新集合，失败期间旧文继续可读。文章维护复用现有持久队列和研究、写作、复核角色，没有新增一套生成管线。

修改入口：`contexts/repository.ts` 和 `store.ts` 管保存，`knowledge/repository.ts` 解析范围与发布检查，`page-worker.ts` 观察新增/移出，`pipeline.ts` 与 `maintenance.ts` 提供当前材料及变化，网页的 `ContextPicker`、`SourceContexts`、`ArticleComposer` 提供入口。

## 围绕项目提问

个人助手的原生调查现在可以查看已保存的项目名称、范围说明和成员，再按项目查原件、已有解释、记忆或代码。例如两个项目都叫“新版发布”，范围分别是 Web 和移动端，用户问 Web 验收安排时，助手可以先辨认项目，再读取其中没有重复项目名的“负责人改为许宁”消息。归属提供查找范围；哪条消息替代旧约定，仍需读正文判断。

`list_material_groups` 返回本次可读的项目与主题，`groups.json` 提供相同目录。`list_materials`、`search_materials`、`search_contexts`、`search_knowledge`、`search_memories` 和 `code_navigation` 接受其中的 `groupIds`。多个项目取并集；同时指定材料键时取交集。项目及成员随原件一起封存，调查中途修改归属不会悄悄改变该次结果。

目录仅列出本次获准原件涉及的项目，数量不是整个个人库的总数；没有出现在目录里不等于不存在。群聊调查暂不提供个人项目名称和范围说明。网页普通搜索尚未提供项目过滤。

### 会话如何记住正在谈的项目

个人会话保存 `project_id`。Agent 根据当前问题、已澄清的会话和实际材料，从正式项目中提交 `project_selection`；歧义没有解决时保持空值，切换项目时换成新 ID，无关问题或跨项目比较时清空。选定对象与成功回答一起保存，失败/取消不改变它，重启后仍能继续。材料主题可用于搜索，但不冒充事项的项目身份。

后续初始召回在排名截断前按该项目的来源成员筛选，上轮引用也按此范围重选。它只是读材料的起点，不是权限：Agent 的原生工具仍能查询其他已授权材料，发现问题换了对象时可以重新调查。尚未辨认项目的首轮仍搜索整个可见库；本轮切换对象后的深查由 Agent 发起，没有额外增加一轮固定路由模型。

新事项把本轮项目写入 `tasks.project_id` 和事项历史，当前交办原文也加入该项目。已有事项改期、完成或延后保留事项原项目，相关指令按事项归属保存，不随当前聊天主题迁移。事项列表传给 Agent 时包含项目身份，MemoryService 仍负责授权、版本和应用回执。没有给群聊开放个人目录，也不将项目选择当作事实写入权限。

修改入口：`assistant/runtime.ts` 管初始选材、结果应用与事项归属，`assistant/research.ts` 校验可选择项目，`acp-model.ts` 提供讨论对象和工具上下文；`conversation/router.ts` 保存跨轮身份，`storage/repository.ts` 保存事项及版本的项目。

### 新消息怎样更新项目记忆

后台记忆整理现在也读取正式归属。输入来源共同属于唯一项目时，提供该项目及受其约束的旧记忆；没有或有多个项目时保持未知，不拿会话 ID 或标题代替。ACP 的抽取和独立复核均接入已有原生调查工作区：可以搜索项目原件、现有记忆、文章与代码，补读前后记录。初始提示只给输入入口，完整原件与图片由工具读取，没有额外输入输出 token 配额。非 ACP 仍使用所给材料的有界处理方式。

例如另存“负责人改为小王，截止和素材规则不变”，无需为了更新记忆而改写旧文件。调查者先找到原来的项目记忆和原件，用同一记忆 ID 提议修订，并保留未变化条件。独立复核另查旧原文与新消息，区分明确修订、未解决矛盾和关系不清。MemoryService 不再把所有跨来源更新一律当冲突；同范围、正确版本且复核确认的明确修订可按普通变化应用和通知。真实矛盾或缺背景仍保留待判断。旧原件、旧记忆版本和固定依据继续保留。

实现复用 `learning/pipeline.ts`、`knowledge/agent-research.ts` 和 `memory/service.ts`。`read_fragments` 返回精确片段引用、原文与说话者信息，`read_memory` 返回可用于更新的版本；衍生正文只提供理解背景。归属在调查途中或抽取与复核之间变化时，旧结果不应用。

### 事实与个人待办

事实和个人待办分开：材料说某人负责工作、某天截止，保存的是可查询和修订的项目事实；只有用户自己的承诺或明确要求跟进，才提议个人待办。用户转述他人的任务不会把负责人变成用户。抽取阶段若把他人的姓名填成待办所有者，提交工具会返回修正说明，让 Agent 改为有依据的事实；不能直接替换成用户 ID 来通过检查。独立复核也检查类型和行动意图，不只检查引用中有没有人名和日期。

未指定归属时的调查流程已接入后台抽取之前，真实 Sol 已完成下述同名项目与人工补充流程。外部自动采集的范围和回复监听仍是独立集成；本功能不自动订阅群聊，也不创建新的项目。

### 未指定归属的材料怎样处理

仅在后台学习开启、使用原生 ACP、已有项目/主题且材料没有手动归属时调查。Agent 读取完整新材料、项目说明和相关旧原件，给出明确匹配、需要补充或不属于已有项目的判断。明确匹配由另一个独立会话补查，两者同意同一组归属后才保存；随后复用原有事实抽取、独立复核和 MemoryService 应用。项目材料范围变化会被已有文章维护队列发现，不再另建一套 Wiki 管线。

“接上次 Web 发布约定，负责人改为小王”可以通过旧记录定位；只说“负责人改了”，且多个项目都可能符合，就显示候选项目和要补充的具体问题，原文仍可读，不先写成无范围事实。原文的“所属项目与主题”展示判断原因。用户选择后会重新排队整理；手动选择优先，包括明确不选任何项目，后续换版也不会自动覆盖。

人工纠正使原来的项目范围不再成立时，依赖该来源的旧范围记忆保留历史并停止作为当前事实使用，后台按新范围重新提炼；不会静默搬动已有记忆或个人事项。文章仍按自己的范围和自动维护设置更新。若调查期间原文换版或用户调整归属，旧判断不应用。没有合适项目时保留材料并继续普通整理，不因缺少分类而丢掉有用内容；一份材料明确涉及多个项目时可以多选，但当前事实抽取只对唯一共同项目建立单一项目范围。

归属提案、独立判断和实际模型 trace 随处理任务分阶段保存；事实结果仍有单独产物。SQLite 第 24 版迁移保留既有 role_outputs，增加阶段身份，避免调查、复核和抽取互相覆盖。关键入口：`LearningPipeline.resolveContexts`、`MaterialContexts.saveResolution`、`Store.setSourceContexts` 与 `SourceContexts.vue`。此处记录的是实现机制，不能代替真实同名项目和模糊消息的效果验证。

### 有疑问不等于整条事实不可保存

“截止时间明确，但未说明具体完成口径”仍可以保存截止约定；“不知道是哪一个项目的截止时间”则会改变事实的适用范围。独立复核现在逐项判断候选疑问是否影响拟保存的主体、范围、时间、条件或行动授权，并说明原因。MemoryService 仅在正文有依据、疑问明确不影响这条候选、没有必要背景缺口且其他应用条件满足时保存。未复核的疑问仍保留待补充；原始备注与复核解释都保存，不删除疑问来制造通过。

必要背景缺口会从独立复核传到写入层；复核自己发现的实质疑问也会阻止自动应用，即使抽取者没填疑问。这个判断不能替代原件校验、个人任务授权、明确修订关系或影响范围检查。实现入口仍是共享 assessment 合同、`learning/pipeline.ts` 和 `memory/service.ts`。

### 记忆里的三种时间

消息何时出现、事情何时到期、某个状态何时有效，是三种不同的信息。“周五交稿”中的周五写入截止事实正文；周五过去后，这条约定仍可查询，不能由此推断已经交稿或负责人不再负责。“小周只在周一到周五临时负责签到，此后结束”则明确给出了职责的有效范围。

抽取字段 `valid_from` / `valid_to` 只表示所述状态开始或停止成立的时间。没有说开始时间的“当前负责人是小周”，起点留空，不用消息保存时间补齐；明确说“现在改为小王并生效”，可以用可信消息时刻表示变更生效。相对日期仍要结合原消息的时间与时区解释。

这些含义同时写入共享字段说明、抽取指令与独立复核要求。复核分别检查正文和有效期：正文支持截止日期，不代表也支持把这个日期填成事实失效时间。宿主没有按关键词猜日期，也没有自动清空历史记忆的有效期；以前误填的记录仍需按原件重新核对。
