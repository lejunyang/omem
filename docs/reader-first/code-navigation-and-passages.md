# 找调用方，以及让重排读到真正相关的代码

这次先解决上轮对照中两个可以明确定位的问题：问“谁调用这个方法”却先给定义；候选已经找到长方法，重排却只看到了开头。它们分别发生在查找意图和模型输入阶段，换一个更大的重排器不能代替这两项修正。

## 从问题到原文，实际怎样走

普通“这个方法如何工作”仍走全文、中文向量、符号入口的联合搜索，保留解释性文章。明确找定义或调用方则走导航入口：

| 查找 | 请求示例 | 返回什么 |
| --- | --- | --- |
| 看定义 | `search_materials({query: "reserveParcel", codeIntent: "definition"})` | AST 标出的同名定义及其固定原文范围 |
| 看调用位置 | `search_materials({query: "reserveParcel", codeIntent: "callers"})` | 原件 AST 中调用该名称的最小包围代码单位，带调用行号与候选标记 |
| 理解处理流程 | `search_materials({query: "reserveParcel 如何处理预约失败？", purpose: "implementation"})` | 实现和解释共同参与排序，之后按需补读被调用方法、配置和背景 |

网页搜索“谁调用 reserveParcel”“哪些地方调用 reserveParcel”也能进入调用方导航。这里只识别明确措辞，不假装实现完整的自然语言意图理解；Agent 和 HTTP 可以直接传 `codeIntent`，无需迎合这些措辞。HTTP 参数在 `/api/search`，研究工具在 `search_materials`。其他表达可用代码导航或原生 Grep 补查。

调用方导航先在符合范围的代码单位中找名称，再复用 `code/parse.ts` 对**完整的已捕获文件版本**做 AST 解析。注释、字符串和 import 中出现名字不会因此变成调用。相互重叠的外层/内层函数只保留覆盖调用位置的较小单位；结果按文件交错排列，先展示不同调用入口，再展示同一文件的其他位置；多个调用位置不会被默认“每文件两个结果”截掉。仍受请求总条数限制，不表示返回了所有调用。

每条结果保持原有 Source/Revision/行范围，另附 `codeMatches` 中的调用行号。缓存仅以不可变 revision 为键；不读取当前工作区来解释旧快照。可见范围仍在生成结果之前检查。

**这是按名称得到的调用候选。**当前解析器支持 TS/JS/Vue，记录调用末级名称，没有跨文件类型解析。`ParcelService.reserveParcel` 查调用方时可能包含其他接收者的同名方法；别名导入、动态调用等也可能漏掉。Agent 必须继续读所在函数与 import，不能把结果写成完整、已确认的调用图。无匹配时返回空结果，表示本次范围与解析能力内没找到，不能据此断言系统从不调用它。

## 重排为什么曾读不到方法尾部

旧流程有两处损失：向量检索已经找到了相关窗口，但融合到符号路线时窗口被覆盖；随后将整段的前 1,200 字符交给模型，方法后半段的写入与分支可能完全没出现。

现在融合保留已找到的向量窗口。`rerank-passages.ts` 对长单位最多选两段：向量命中附近的连续上下文，以及查询词集中出现的局部文本；显式方法名不参与后一项的词覆盖，避免只因签名出现名字就总选开头。与问题概念相关、且原文行范围重叠的正式别称也参与窗口选择，把中文问题接到英文调用名；不会把整份文档的所有别称塞给每个方法。高度重叠的窗口只保留其中一段评分。短单位保留全文。

各段分别与问题交给同一个 cross-encoder，单位取最高段落分数，再进入原有融合与用途/状态排序。最终摘录展示得分最高的原文，固定引用仍能打开整个原件单位。这里没有改 embedding 的预处理或投影身份，不需要因窗口选择变化重建全部向量。

这借鉴了长文档检索的 passage 评分思路，而不是声称完整复现某篇论文。参考 [BERT passage reranking](https://arxiv.org/abs/1901.04085)、[长文档重排研究](https://arxiv.org/abs/2205.04275)；定义导航与全文查找分开也可对照 [Zoekt 符号查询](https://github.com/sourcegraph/zoekt/blob/main/doc/query_syntax.md)。本项目使用现有 TypeScript AST 和 SQLite，没有额外安装搜索服务。

仍有明确限制：最多两段不是全文理解；800 字符正文与 160 字符背景仍会受模型 512 token 配对上限截断；最高分聚合可能偏爱长文中一个局部相关段落，不能保证整篇能回答问题。短解释中的否定、旧方案状态和模型之后的宿主排序仍需单独检查。Agent 阅读原件不受这些重排摘录长度限制。

## 改造位置与采用条件

- `retrieval/port.ts`：可选 `codeIntent` 与候选调用位置。用途、导航目标、原件定位各自独立。
- `retrieval/code-navigation.ts`：复用原件 AST，缓存固定版本的调用线索。
- `retrieval/unified.ts`：导航分路、范围检查、窗口保留、局部评分聚合和结果映射。
- `retrieval/rerank-passages.ts`：查询相关的局部文本选择，保持正文原字节连续。
- `app.ts`、`knowledge/agent-research.ts`：网页 HTTP 与 Agent 共享同一能力。

默认仍只启用中文 embedding，BGE 重排为可选。使用同一冻结材料库比较改造前后，区分模型分数和最终排序；保留上轮 16 个问题，再增加调用、明确定义和缺失名称场景。旧题已在材料里出现，不当成未知评测。实际收益、退步与本轮检查见[对照报告](../../.repo-review/knowledge/verification/navigation-passages.md)。

下一步应优先解决结果能否回答，而不是仅增加导航类型：同名调用需要接收者和 import 背景；查机制需要完整流程；无答案需要明确缺口。重排器只有在同库实测带来稳定收益后才值得默认开启。
