# 个人库、缓存与冷存储

安装版默认 `~/.omem`，可用 `--data-dir` 或 `OMEM_DATA_DIR` 指定。源码开发默认仓库 `.omem`。CLI 和 Web 连接同一服务；`data` 子命令直接管理本机目录，不通过 HTTP，不能使用 `--url` 操作远程库。

## 实际存了什么

| 数据 | 热存储 | 本轮冷存储与保留策略 |
| --- | --- | --- |
| 来源与原件 | `omem.sqlite`；附件在 `assets/<sha256>` | 代码、本地文件和飞书文档只保留最新原件；聊天与人工更正按事件保留；旧原件只留标识、摘要和移除原因 |
| 文章、记忆、事项与项目归属 | `omem.sqlite` | 普通刷新等待新结果发布；显式删除或替换会清除选定旧成果正文，留下少量删除审计 |
| 消息同步游标、分页位置、消息 ID、去重摘要、处理状态 | 同一 SQLite | 始终保留，归档不导致重新全量拉取 |
| 消息原始 JSON、决策详情、资源清单 | SQLite | 可按更新时间归档为校验过的 gzip 文件；最近 200 条、采集失败和 pending 消息保留热载荷；ready/review 可归档，不代表后续 Agent 整理已完成 |
| 图片、附件和下载原件 | `assets/<sha256>` | 可按文件时间迁到另一目录/磁盘；ID 不变，读取自动回到冷存储 |
| 全文与向量检索数据 | SQLite | 目前仍在主库，不宣称完成索引分库 |
| 模型运行输出和任务审计 | SQLite；另有 Agent 工作目录 | 清除成果时旧输出和嵌入草稿一并移除；任务身份、来源定位、digest 和执行状态保留；临时工作目录另行清理 |
| PM2、配置、加密凭据、模型环境 | 独立文件目录 | 不混入知识；备份含配置和 `secrets`，排除可重装模型、PM2 状态与临时工作区 |

目前大多数结构化状态仍在一个 SQLite 中。附件和重复消息载荷可以冷归档；可重建索引仍在主库，运行审计尚未分库。可变材料的历史原文已改为自动清除，聊天事件仍会积累，长期容量还需要按实际占用治理。

## 原件保留与重新处理

`source_retention` 正式保存每个来源的 `latest` 或 `event` 策略。代码、本地文件和飞书文档默认 `latest`；聊天消息及人工反馈默认 `event`。服务打开已有库时会按这些类型补齐策略，并压缩可变材料已有的历史，保留当前 head。修改代码或文档后的捕获也会执行同一策略。

移除旧原件后，旧 Revision 和 Fragment 的身份仍在，正文、代码快照里的重复全文和旧检索内容被清除。引用仍指向原来的身份，并说明“此可变材料只保留最新原件，引用所指的旧原件已移除”。不会用当前代码或当前文档的文字填进旧链接；依赖旧原件的文章可能需要重新核对。

聊天事件里的附件和当时分享的文档 JSON 属于那个事件的原件。文档自身更新后，只展示它的最新原件；消息资源清单仍可保留当时分享的 JSON，以便重放这条消息时读取当时内容。这份事件记录不会作为文档的新版本，更新该事件的资源清单后，失去引用的旧字节才可回收。

原件中的附件 ID 建立轻量引用索引。清除旧原件后只检查附件候选，保留正在解析或解析失败的 `document_imports` 原文件、消息资源清单里的下载文件，以及未结束任务的输入。没有这些引用的候选会从热存储和已配置的冷存储移除。首次历史压缩只在批量处理完成后统一回收；普通文字或代码捕获不扫描整库附件。

“删除旧成果再重新处理”会按所选用途清除材料说明、文章或学习结果。删除文章会移除该文章各版正文及旧问题入口，保留页面目标，供下一次调查和写作使用；已有人工创建的事项继续保留。普通刷新保留旧正文到新结果发布，显式替换则先删除旧成果。清除记录阻止启动时的静态资产导入和较早模型任务恢复旧正文；新生成的成果可以正常发布。

从材料学习出的记忆与未被修改的模型事项可以直接清除。人工维护过、已完成或已有其他来源支持的内容保留实际状态，并解除此次材料的派生关联。执行回执和外部行动的审计保留；清除本地成果不会撤回已发生的外部行动。旧学习任务会取消，来源有效期计数增加，迟到的输出不能再次应用。

这些操作不会自动整理 SQLite 空闲页，也不清理 Agent 工作目录和仓库里用于验收的静态资产；它们由后面的数据维护命令及 `review:prune` 管理。

## 命令与恢复

```bash
omem data info
omem service stop
omem data backup /Volumes/Backup/omem-2026-10-06
omem data restore /Volumes/Backup/omem-2026-10-06 --to /Volumes/Data/omem-restored
omem --data-dir /Volumes/Data/omem-restored service start

# 迁移保留原目录；确认新库正常后再自行处置旧库
omem data migrate --to /Volumes/Data/omem

# 默认只列出候选；--apply 才迁出，--compact 再收缩主库文件
omem data archive --before 2026-09-01 --to /Volumes/Archive/omem
omem data archive --before 2026-09-01 --to /Volumes/Archive/omem --apply --compact
omem data prune --before 2026-09-01
```

数据维护要求停止这个个人库的后台服务及所有前台开发进程。新版 Store 持有进程租约，维护命令检测到活跃实例会拒绝执行；升级前已运行的旧服务没有这个租约，也必须先停止。日期用于挑选冷归档候选，不自动判定知识失效。可变材料旧原件的移除由上述保留策略执行。归档目录写入 `cold-store.json`；当前只支持一个文件系统冷存储根，不直接支持 S3。目录不可用时不能完整读取旧资源，应挂载磁盘，不重新下载冒充旧版本。

备份使用 SQLite 的 [`VACUUM INTO`](https://sqlite.org/backup.html)，再复制附件、冷存储、配置和加密凭据，记录各文件 SHA-256。恢复先校验，目标必须为新目录。含冷存储的备份可独立恢复，不依赖原挂载路径。机器人本机生成的 `secrets/master.key` 随备份保存；备份含个人材料和解密密钥，必须私密保管。显式环境变量密钥、第三方 CLI 登录不在备份中，应另行保管。跨机器恢复后要检查配置内模型路径、捕获目录和第三方登录。

## 消息缓存不是只缓存最后一页

每个订阅独立保存 watermark、固定查询窗口和 page_token；分页未完只继续该窗口，完成后保留一分钟重叠，补捉窗口交界。消息按 ID 与摘要去重，同一消息不重复产生模型任务。冷归档保留 ID、摘要和处理状态。

群内文档链接成功读取后，十分钟内复用固定修订；同一图片/附件按账号、资源类型和 key 复用已保存字节，缓存有效期 30 天，缓存过期只允许重新读取；原件是否保留按来源策略和事件资源引用判断。失败不缓存为成功，显式重试绕过缓存。十分钟缓存意味着可变文档可能短暂不是最新内容；消息正文没变时不会为了链接轮询远端文档，独立文档持续同步尚需后续接入。

`messages status --json` 显示每条流最近一页的时间窗口、拉取数、复用数、处理数及后续分页。这里的 fetched 是顶层消息数，cached/processed 还包括返回的线程回复；并非模型准确率或完成事项数。所有读取继续保留用户未读状态。

实现入口：`storage/retention.ts` 管原件策略、旧成果清除和附件回收，`storage/library.ts` 管维护，`storage/cold.ts` 管固定 ID 读取，`storage/library-lock.ts` 管维护互斥；个人消息 `service.ts` 管游标/去重，`materials.ts` 与 `cache.ts` 管资源缓存。不引入另一套消息数据库或文件名驱动的业务分类。

## 编码工作区

新增 `development/projects` 保存目标仓库与命令配置，`development/runs` 保存独立代码副本、检查与评审结果。`data info` 单独统计这一部分；当前备份/迁移只覆盖个人事实库、资源与个人配置，不复制这些编码副本。未应用的实现需保留原个人目录或单独保存 run 目录与补丁，不能把它当可随意删除的临时缓存。`data prune` 不清理开发任务。

开发结果简报进入同一 SQLite 的 Source/Revision，`development_results` 只保存运行到当前来源版本及学习任务的索引，`knowledge_page_inputs` 保存与需求页的明确关联。每个运行复用同一个 Source；恢复和应用追加 Revision，固定旧引用不变。日志和补丁只捕获有限摘录，全文留在上述私人运行目录。这部分材料历史仍需保留，并没有随本轮回流实现自动冷归档。
