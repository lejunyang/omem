## 当前结论

[整体复审](review.md)的三条主线仍未全部完成。文章已经能围绕阅读目标生成，并随明确选材或项目材料范围持续维护；助手已经能自主搜索、补读和独立复核。**基础检索的有效性、答案取舍与耗时，以及自动识别新增记录归属、连接项目记忆和行动，仍是主要缺口。** 默认 Traex ACP / gpt-5.6-sol，不再把小模型筛选或少量融合权重当主线。

## 已经可以使用

### 整理和维护一篇文章

- 正式文章、参考资料和内部笔记分别保存。旧逐文件说明与批次专题退出默认阅读和知识召回，506 份旧发布资产已移除；原件与固定引用所需历史保留。
- 在知识库选材料、说明读者和目标，Agent 在固定快照中自主调查、写作并由独立会话补查。保存单位、检索单位和讲解章节分开。
- 已有文章可以“调整材料与目标”或“补充背景”，保持同一文章身份。用户计划跨重启、资产导入保留；新结果失败或生成中计划变化，不覆盖旧正文。
- 维护时提供旧解释、目标变化、原文差异和受影响章节；保留未受影响的内容，重新核对当前引用。正文引用、必要背景前提和调查轨迹分开，偶然读过的材料换版不让整页失效。
- 章节按引用所在的原文结构判断是否需要核对，无关导读或行号移动不自动使整页退出检索。旧文章、引用和问题入口仍能回读，缺失来源明确提示。
- “随所选材料自动更新”接入持久队列：连续变化合并，重启恢复，失败保留旧文，不无限重试同一失败输入；手动整理也走同一队列。

写作取消固定篇幅和章节配额。一个短活动场景已从五节、977 字缩为一节、357 字并保留必要事实；复杂机制页仍有不必要的边界说明，不能以短文改善代表整库达标。详见[发布与维护](publication-lifecycle.md)、[写作与阅读](writing.md)。

本轮在现有调查阶段增加组织决策：判断旧稿适合局部维护，还是应按读者目标重新组织。后者不再强制沿旧稿修补，仍保留文章身份、历史和独立复核。真实 Sol 对检索页选择重组，对记忆和生成页选择维护；检索页去掉实验数字和大部分参数列表，案例主线更集中。另两页仍有偏多的术语和边界说明，不能说整库阅读质量已经达标。

### 让后来的项目记录进入文章

- 在“输入材料”选择或新建项目/主题；原文的“所属项目与主题”可以调整归属。关系绑定稳定来源，换版保留；移出不删除原文。
- 文章可以跟踪整个项目/主题，也可另外选择背景材料。新成员、成员移出和原件换版触发同一维护流程；同名但没有归入范围的材料不会混入。
- 项目材料范围、文章分类和正文引用是不同关系。生成时封存实际选材，途中范围变化不发布旧结果。只有动态范围保存额外选材快照，不为每篇指南复制整库目录。

明确归属后的自动维护已有真实 Sol 验证。本轮未指定归属时的调查、独立补查与人工纠正已提交（`9b9eae5`、`ffecd42`、`dc928cb`、`db4cf49`）。真实 Sol 从省略项目名的规则续接定位 Web，约 208 秒更新同一负责人记忆，保留截止和规则；另一条模糊消息约 54 秒后提出具体问题，未改动事实。人工选择移动端后约 154 秒更新其原负责人记忆，最后约 43 秒正确比较两端安排。锁定依赖、445 项测试、类型与构建通过；实际 dev 的归属说明、人工纠正、待补充入口和 1440/768/390px 布局已检查。这是四条短合成消息的流程验证，不能代表大库归属可靠或已有提速收益。详见[项目与主题材料](project-contexts.md)。

个人助手调查已接项目目录和按归属搜索，成员关系随调查快照封存。本轮继续保存跨轮讨论项目：后续初始召回按已归属来源筛选，Agent 可切换或清空对象；新事项与其版本保存项目，旧事项修改保留原归属。实现已提交为 `ba7b526`。真实 Sol 六轮完成对象澄清、Web 问答、重启后创建提醒、切换移动端、无关事项清空项目，以及完成原 Web 事项；实际初始召回和事项历史符合所选范围。这是四条合成原件的小库验证，不能代表大库搜索收益或普遍可靠的项目理解。

后台抽取和独立复核现复用同一原生调查工具，能读取完整原件、项目旧记忆及其依据。新消息可提议更新同一条记忆，独立复核明确判断它是修订还是冲突；取消“不同来源必定待确认”的旧限制，保留真实矛盾和范围变动的处理。首轮真实 Sol 发现负责人和截止时间被误提议为他人的待办，写入层拦下后没有形成事实记忆；任务成功和复核通过未发现这种遗漏。`8a76f2c` 修正事实/待办区分和提交纠错反馈后，真实重放已保存两项目七条事实，Web 负责人更新同一 ID 到第 2 版，其余六条不变，最终问答正确。事实有效期仍有下述问题。

时间字段现明确区分消息时刻、事件期限和状态有效期，抽取与独立复核都逐项检查有效期依据；没有新增关键词日期猜测，也不自动改写旧记忆。`98dd4b0` 同模型四条消息重放已完成：普通截止没有填成失效时间，明确任期正确保留，约 138 秒回答“过了截止不能证明完成”和“临时职责已结束”。改动前 `4f74258` 同题也答对，约 65 秒；这不能证明质量提升或提速。

重放暴露了新的断点：首次截止事实已有原文和独立复核支持，却因抽取者备注“未说明具体完成口径”被写入层搁置，直到后来消息重新提议才保存。现在独立复核明确判断疑问是否影响整条候选，写入层可接受已经解释清楚的旁支疑问，同时保留必要背景、主体、时间、授权等限制。原始疑问与复核解释均保存。`393d8bc` 真实重放完成：四步约 121/147/154/115 秒，首次保存四条事实，最终八条，Web 负责人修改同一 ID，期限和规则保留；约 110 秒问答正确区分截止已过、完成未知与任期结束。本次抽取者没有再提出那条旁支疑问，所以验证了首次完整保存，不能单独证明新增判断带来语义收益。

### 搜索、问答与跟进

- 原文、已有解释、记忆和事项共享召回基础。词法使用 ICU/FTS5，可选中文 BGE；融合改为标准 RRF，移除最低词面门槛、原始分数调制和错误触发的调用者过滤。
- 候选召回、回答上下文和阅读分组分开。同一文件的多项必要事实不再受首屏去重上限限制；命中后恢复固定版本的完整章节/函数、上级引言和相关原件。
- 材料用途增加按来源开启的持续整理：换版后重新读原文、定位概念，持久排队、重启恢复，当前人工修正优先；导入说明不自动触发整库分析。真实 Sol 同一短材料从提案换成现行说明，约 56/36 秒完成，默认与用途筛选的实际 HTTP 查询反映新版，旧说明保留。首轮把运行说明误归为实现，明确用途与状态的区别后重放纠正；这不是大库排序收益。
- 多部分问题可通过 `search_contexts` 分别检索，保留各部分对应的完整语境，不重新压成一个全局排名。Sol 根据缺口选择补读；工具本身不判断“已经回答”。
- 复杂答案可在独立 Sol 会话中补查关键前提。追问引用恢复上轮完整原文范围，避免退回首片段而丢失条件；通过校验并保存的最终结果可以及时收束 ACP 会话。
- 日常助理已有持久会话、记忆换版、事项交办、等待、改期、延后、完成、取消和站内提醒。来源约定从 80 改为 120 后更新同一记忆、重启提醒及完成的真实流程已验证。

当前仍会出现计划或题集排在有效解释前面，以及模型读到了却回答过长、追加未问内容。完整跨轮对象和时间理解仍不可靠。参见[检索改造](retrieval-redesign.md)、[按问题调查](answer-investigation.md)、[个人记忆与跟进](assistant-memory-flow.md)。
