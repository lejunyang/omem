# 当前实施进度

更新：2026-10-04。本页记录当前交付与缺口；逐次测试和提交细节留在 Git 与专项简报。模型复核、程序检查和读者验收不是同一件事。

## 现在做到哪里

主线仍是[整体复审](review.md)确定的三步：可持续阅读的知识库、有效的检索与回答、持续项目理解。发布与维护的核心实现已完成；检索完成候选与上下文分离，但排序和答案要点选择未解决；持续记忆处于隔离试验。默认使用 Traex ACP / gpt-5.6-sol，不再把小模型筛选当主线。

### 知识发布与维护

已经完成：

- 正式文章、参考资料、内部笔记分别持久化；旧的逐文件说明和批次合成退出默认阅读与知识召回。506 份旧发布资产已移除，个人库与固定原文历史保留。
- 页面计划独立保存，按读者问题选材、调查、写作、独立补查；失败保留计划和有效旧文。材料分类与文章主题都是正式数据，不靠文件路径或引用关系猜目录。
- 调查中读过的材料、正文引用、未直接引用但影响结论的背景前提分开记录。原文变化按相关章节或函数判断影响，未受影响解释与固定引用继续保留。
- 已有文章可以“调整材料与目标”，保持文章身份重新整理；用户补充背景会进入下次选材，计划在重启及资产导入后保留。生成途中改变计划，旧结果不会覆盖新选材。
- 历史文章恢复为当前展示版本时，也恢复其问题入口；重复导入保留已经回答或转为事项的状态。仅导入历史、没有替换当前文章时，不改当前问题。

真实流程已跑通：两份明确标注的合成材料，经实际 HTTP 操作和 Traex/Sol，完成“首次写作发现负责人缺失 → 补充米拉负责 → 调整目标并重写同一文章”。新版引用补充原文、保留预算与活动顺序，旧版仍可回读；重开数据库后用户计划未被默认导入覆盖。首次约 190 秒，补充后约 293 秒。它证明这条维护流程接通，不代表所有文章质量已验收。

当前仍有阅读问题：旧策略默认要求完整页面写 5～8 节、1200～2500 字，简单任务容易被扩写成限制说明。新策略移除篇幅配额，合并重复提示，按读者目标决定案例、图表和未知问题；返修先处理具体问题，保留未受影响解释。在同一材料与目标上，真实 Sol 产物由五节、977 个正文字符变为一节、357 个字符，保留三处可回读引用；独立复核通过，人工抽读也能直接找到准备、集合、交接顺序。新策略已应用到正式 writer/refresher/verifier 角色。这只是一个短场景；复杂机制页还要检查因果、案例和修改入口，不能把短当质量。

四篇受影响指南已完成实际刷新并提交：检索、生成机制、维护操作、开发参考。生成后同步最新源码，八篇发布文章均有部分章节需要核对；本轮 205 处固定引用仍可回读。维护操作页能沿具体活动解释选材和更新，机制与参考页仍有术语和限制说明偏密的问题，将用新策略继续检查。后台任务使用固定材料；后续实现变化可能让部分章节再次待核对，不把“发布成功”写成“全部 current”。界面通知已收束为简短提示，完整变化留在通知中心。

详见[发布与维护](publication-lifecycle.md)、[写作与阅读](writing.md)。

### 检索与回答

已经完成：

- 共享原文、知识、记忆和事项召回基础；全文使用 ICU/FTS5，开发环境中文 BGE 已就绪。曾出现的模型加载失败不再永久缓存，源码变化后使用新 API 进程加载模型。
- 助手和调查工具保留回答候选，阅读列表再做去重；同一来源中的必要事实不因每页展示上限提前丢弃。
- 章节/函数父子关系独立持久化。命中后恢复同一固定版本的完整结构与上级引言；Agent 可以沿目录补读，历史版本仍读取自己的原文。
- 去掉词法最低匹配数门槛，修复普通代码报错叙述误触发调用者导航导致空结果的问题；读取优化不改变该轮候选排名。

效果仍有限：

| 已完成对照 | 观察与适用范围 |
| --- | --- |
| T2Retrieval：118,605 份材料、22,812 题 | BM25 Recall@20 54.2599%，当前词法阅读结果 54.2596%，没有证明优于基线。旧实现完整对照仍在运行 |

这些对照都不能代表向量、重排、Agent 和最终回答的整体质量。实际 HTTP 搜索仍可见计划或提示词排在有效解释之前。标准融合、跨轮对象解析和回答要点覆盖选择尚未完成。下一步先简化候选融合，再判断当前问题还缺什么材料；不继续围绕少量仓库路径题调权重。详见[外部评测](external-evaluation.md)与[检索改造](retrieval-redesign.md)。

### 持续记忆

现有系统已用真实 Traex 验证：约定从 80 改为 120 后更新同一记忆，创建跟进、重启后提醒、延后及完成；这不等于持续项目理解已经解决。

Hindsight 0.10.2 在隔离环境中通过实际 Traex/Sol 与现有中文 BGE 运行。四条合成项目材料的保存、查询和综合视图刷新已接通：能更新上线日期、预算和付款时间；但一次观察合并混淆了补充事实的记录日期，工具适配也曾出错。保存与刷新成本明显，尚未接入生产或双写个人库。

公开 LongMemEval 七类预选 oracle 案例已完成直接 Sol 与 Hindsight 对照，后者的 12 次整理累计约 38 分钟，回答中位约 125 秒，直接阅读约 12 秒；没有证明净收益。能合并金额、找回名称和比较先后，但有冗长、额外细化年份及含糊更新的分歧。这不是完整长历史召回成绩，也没有官方总分；生产未接入，实验数据库与专用服务均已停止。详见[外部评测](external-evaluation.md#longmemeval给足相关会话后的七类诊断)和[组件接入](component-integration.md)。
