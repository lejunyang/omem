## 最近完成与正在验收

原件与重新处理切片已完成实现检查。PDF/DOCX 上传后即建立持久导入记录，解析失败仍可下载原件；后台任务可跨重启继续。机器人保留事件 JSON 和资源，复用个人消息的资源处理，停用连接后也能离线重做理解；离线重放不会再次执行旧委托或回复。只有明确选择读取新版才访问来源，未下载成功的附件仍是缺口。独立文档只留最新原件，聊天当时分享的文档响应归属事件原件。

`omem reprocess` 区分解析、理解、用途说明、远端刷新和文章写作，`--replace` 真正删除对应旧成果及正文历史，再生成新结果；也可只删除成果。原件、人工修改的记忆和事项、已执行外部动作保留。旧任务和启动恢复不能把删除前的正文重新发布；持久处理记录跟踪后续学习和独立复核，派发成功不会提前显示完成。完整步骤见[重新处理](../../skills/omem-cli/references/reprocessing.md)。

运行日志统一为 Pino JSON，默认 info，可通过配置或 `OMEM_LOG_LEVEL` 选择等级。任务、来源和消息标识串联失败，debug 记录逐条检索决策；正文、提示词和工具输出不进入诊断日志，凭据脱敏。`service logs` 提供有界筛选查询，PM2 隔离加载随包轮换模块，默认 10 MiB、7 份压缩归档。实际压缩/保留检查发现上游 3.0.0 布尔配置问题，锁定兼容的 2.7.0 后通过。配置与限制见[日志](logging.md)。

## 接下来交付什么

2026-10-05 用户要求停止围绕小题集与同几篇指南反复优化。已知检索缺陷继续保留，但不再要求先修到“完整闭环”才能推进其他能力。单轮实验没有明显收益就保留基线，不反复改同一题；.repo-review 是验证输入，不能成为产品工作的主要负担。

需求跟进与主动实现的首个可用 CLI 切片已交付。主助手已接自然语言跟进、关注与反馈、后台编码和进度结果。**通用外部能力目录已接通**：登记已有 skill/MCP/CLI、检查可用状态、按项目装配；真实业务项目由用户稍后提供。恢复同一编码任务、显式应用评审补丁、需求行动关联待办现已接回主助手；Codex 实际编码和评审已通过，外部资料选择保存与找回、远端 Git 准备已接通；项目检查配置已接入，未应用任务的变更计划与续做已接，下一步接真实 Figma/公司 Git 验收和已应用后的迭代；Claude 仍缺认证。具体文件和验收见[主助手方案](assistant-orchestration.md)。存储按实际占用优先分离可重建索引与治理旧向量；自动冷归档调度、远程对象存储和完整历史分库尚未实现。

1. **完善真实文件导入。** PDF/DOCX 的持久导入、失败原件保存和重新处理已交付，接下来补 OCR 和原页定位；飞书继续补画板、引用文档和附件的完整读取，不新增另一套抓取器。
2. **继续验证主题知识组织。** 可编辑目录草案已接通网页与 CLI，下一步让主助手能查询和修改同一草案，并用真实多材料项目检查是否遗漏概念、案例和修改入口。已发表文章合并与退役尚未实现；不以目录生成成功替代阅读验收。
3. **继续扩展日常跟进。** 消息实际理解、项目/需求关联、纠正和可调整的跟进已接到界面，机器人首次配置和可恢复配对已补齐。下一步在用户选定的真实需求群验收私聊交办、群里本人确认、同一事项更新与必要通知，再扩多项目指代和今日跟进，随后接学习卡片。外部回复已能续接同一待办；这些能力共用个人库。

上述能力共用逐段、多维决策层：优先接检索材料的阅读排序、明确无关项省略和入库多标签建议，再扩展目录归属、父章节选择与更新候选。复杂记忆写入仍经现有应用流程，不能因此让可撤销的辅助分类一直停在实验里。具体代码改造见[组件接入](component-integration.md)和[快速决策](fast-decisions.md)。

## 数据与运行边界

专项简报覆盖更新，自动报告按有界策略轮换，不累加验收正文或复制库。本轮临时页面验收库已停机并释放，原有用户演示库保留。个人库、正式运行库与模型权重保留；可变材料旧原件按保留策略回收，文章历史在显式替换或删除前保留。运行中的任务和用途不明目录不清理。

当前仍是 SQLite/shared-token 单用户实现，不宣称团队隔离。原生 CLI 可在快照中自主读材料，但尚无完整文件系统隔离。外部通知、采集范围与 OS 服务分别显式集成。
