# 当前实施进度

更新：2026-10-05。这里记录当前能做什么、主要缺口和下一步；实验方法与逐题结果留在专项报告，旧状态可查 Git。总体判断仍是：**主流程可用，检索有效性、文章可读性和持续项目理解尚未完成。**

## 已经可以使用

| 用户流程 | 当前行为 | 仍需注意 |
| --- | --- | --- |
| 保存材料 | 文档、代码、聊天与图片共享来源和固定版本；同来源类型、稳定标识可以追加修订；代码有 AST 定位 | PDF/Office/OCR 成熟解析尚未接通；代码的跨文件关系仍有限 |
| 整理文章 | 在知识库选择材料、填写读者与目标；Sol 在快照中自主搜索、补读、写作，再由独立会话补查 | 模型复核不等于读者验收；部分复杂指南仍有过多术语和边界说明 |
| 维护文章 | 保持同一文章身份，调整目标、补背景或跟踪项目；材料换版与成员增减进入持久队列，重启继续，失败保留旧文 | 大型函数/组件的复查范围仍可能过宽；旧文章中待核对的直接解释可能退出检索 |
| 维护材料说明 | 原文页可让 AI 分析用途、状态、概念别称并人工修正；按来源开启换版后的持续整理 | 未开启的来源不会自动分析；整份文档的用途无法区分内部的步骤、实验和旧计划 |
| 查找与问答 | 原文、文章、记忆和事项共享全文、中文向量与符号召回；命中后恢复固定章节/函数及父级背景；Agent 按问题补查 | 前排仍会出现主题相关但不回答问题的内容；答案取舍和耗时未达标 |
| 持续记忆与事项 | 新记录可以调查项目归属、修订同一记忆；会话保存讨论对象；支持交办、等待、改期、延后、完成、取消和站内提醒 | 小规模真实流程已验证，复杂多项目、人物和时间理解仍不可靠；外部回复需用户主动告知 |

具体实现与使用入口见[文章维护](publication-lifecycle.md)、[项目与主题](project-contexts.md)、[材料说明](material-understanding.md)、[按问题调查](answer-investigation.md)和[个人记忆与跟进](assistant-memory-flow.md)。

正式文章、参考资料和内部笔记已经分开。旧逐文件说明与批次专题退出默认目录和知识召回，506 份旧发布资产已移除；原件和固定引用所需历史保留。文章的目录、项目范围、正文引用和调查轨迹是不同关系。无关章节变化或仅行号移动不应让整篇解释消失；必要背景改变仍需要复查。

## 接下来交付什么

2026-10-05 用户要求停止围绕小题集与同几篇指南反复优化。已知检索缺陷继续保留，但不再要求先修到“完整闭环”才能推进其他能力。单轮实验没有明显收益就保留基线，不反复改同一题；.repo-review 是验证输入，不能成为产品工作的主要负担。

1. **真实文件导入与结构阅读。** 接 Docling 处理 PDF/DOCX，保留原件、标题层级、表格、图片和页码定位，提供输入、解析状态、预览与失败重试。聊天与代码分别保留会话关系和 AST 定位。
2. **可编辑的主题知识组织。** 多份材料先形成有页面目的的目录草案，可合并、移动和修改，再由 Agent 调查写作；已有文章优先维护。入口、概念、案例和机制按页面用途组织，不再逐文件成文。
3. **日常消息的可见处理。** 展示提取的约定、变化、所属项目和事项，提供修正入口；继续扩展待回复、今日跟进与学习卡片，不把每一类都当独立知识产品。

上述能力共用逐段、多维决策层：优先接检索材料的阅读排序、明确无关项省略和入库多标签建议，再扩展目录归属、父章节选择与更新候选。复杂记忆写入仍经现有应用流程，不能因此让可撤销的辅助分类一直停在实验里。具体代码改造见[组件接入](component-integration.md)和[快速决策](fast-decisions.md)。

## 数据与运行边界

专项简报覆盖更新，自动报告按有界策略轮换。已结束实验的数据库副本按用途与进程核对后释放；本轮候选实验直接固定只读事务，没有再复制整库。个人库、正式运行库、固定原件/文章历史和模型权重保留，运行中的任务不清理。

当前仍是 SQLite/shared-token 单用户实现，不宣称团队隔离。原生 CLI 可在快照中自主读材料，但尚无完整文件系统隔离。外部通知、采集范围与 OS 服务分别显式集成。
