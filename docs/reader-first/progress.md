## 已有能力与实际边界

| 环节 | 已有交付 | 仍不够的地方 |
| --- | --- | --- |
| 捕获与原件 | 文档、代码、聊天、图片共享固定来源和版本；Markdown、TS/Vue 有结构定位 | PDF/Office/OCR 未接完整成熟解析流程；多段用途仍较粗 |
| 材料理解 | 固定版本用途、状态、适用对象、时间和局部概念，可由模型整理、人工修正 | 需要明确触发；分类不证明内容正确，也未普遍自动化 |
| 检索 | 共享原文、知识、记忆入口；ICU/FTS5、中文 BGE、符号和调用候选；可选重排 | 主题相近却答非所问、上下文丢失和多事实覆盖仍明显；不是完整调用图 |
| 知识生成 | 页面 brief、自主调查、原生文件和 MCP、写作、独立补查；真实 Traex/Sol 已运行 | 发布用途与目录未彻底重构；读取依赖太宽；页面整体过期影响已有理解 |
| 问答 | 持久会话、自主搜索补读、独立答案复核、取消/重试、固定引用 | 复杂题常耗时较长，复核也可能错误；Agent 补查成功不代表首轮搜索已好用 |
| 记忆与行动 | 原件换版重核验记忆；交办、等待、改期、延后、完成、取消和站内提醒 | 缺少持续人物/项目理解、完整时间推理、外部回复监听、周期回顾和英语卡片 |

SQLite/shared-token 仍是单用户；不宣称团队隔离。原生 CLI 的祖先指令读取也未实现完整文件系统隔离。

## 模型与已经测过的范围

默认助手保持 Sol。Luna 未显示明显收益，停止反复比较。GLiClass multilingual mini、Qwen3.5-4B 和 Plumb-4B 的本机筛选已完成：部分阅读顺序有收益，但材料充分性、选项顺序和记忆决策不稳定，未接管生产路由或事实写入。9B+ 本机排除，明确仅英语的候选低优先级。

可选 `assistant.readingProfileId` 先读材料作答，需要时独立复核或把同一快照交给主 Agent。三份明确标注的合成生活材料上，四题常规耗时约 41/41/41/58 秒，先读约 29/31/34/53 秒；复杂仓库三题仍约 153～233 秒。只能说明该短场景收益，不能说全局提速。实测、资源口径和失败见[快速决策简报](../../.repo-review/knowledge/verification/fast-decisions.md)。

上一完整个人流程用真实 Traex 验证了约定从 80 改为 120 元后更新同一记忆、跟进不重复、重启提醒、延后和完成。它证明那条流程接通，不代表长期项目理解已经解决。参见[个人流程](assistant-memory-flow.md)。

## 下一步的三个完整切片

1. **发布与维护知识。** 内部笔记、参考和读者页成为正式用途；页面地图独立保存。把调查轨迹、复查依赖和章节依据分开；原文变动定位影响，保留仍有用的解释和固定历史。用真实 Sol 更新一个完整主题，检查读懂、定位、操作和持续更新。
2. **简化检索和上下文。** 原始来源统一保存，但符号定位、机制解释、跨轮追问和历史查询分策略。透明候选基线、父章节补读、回答材料选择与界面去重分开。中文用 T2Retrieval，代码/文档用 FreshStack，避免继续把本仓库路径题当主要指标。
3. **持续项目理解。** 比较 Hindsight 的综合视图与现有记忆；明确原文、事件时间和变化，用 LongMemEval 检查更新、跨会话、时间和缺失信息。保留 MemoryService 的应用职责。先证明能持续理解，再考虑小模型节省成本。

不把完整调用图、全库覆盖、所有公开榜单或额外决策模型做成前置门。每片完成相关检查即单独提交；涉及知识能力的实现后，按真实 Traex/Sol 更新受影响资产并单独提交。
