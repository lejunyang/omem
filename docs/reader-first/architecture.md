# 目标流程与实施边界

这是重构目标，交付状态见 progress.md。

## 一个来源体系，多种用途

原始材料进入 Capture，保留 Source 与 Revision。文本、图片、链接和上下文一起保存；代码是同一材料体系的专用解析，不建立独立知识库。

保存单位、检索单位、讲解单位分开：原件保留历史；结构块按标题/列表/表格/函数/对话组织；页面围绕一个读者问题跨材料解释。派生内容能够引导检索和提供理解背景，但不成为第二份独立事实。

## 问题驱动的知识生成

选择材料与阅读目的 → 可编辑目录草案 → 确认页面计划 → 按问题检索、读取与补充上下文 → 写解释 → 检查事实和页面目的 → 发布 → 按依赖增量更新。仓库只是输入之一；单篇文章仍可直接建立页面计划。

目录草案独立保存，包含整体目标、材料范围和有顺序的页面建议。AI 可以在固定快照中搜索、补读并提议目录，读者也可以手动编辑；提议不自动应用。确认才将每页转换为现有 `WikiPageBrief`，写入正式页面计划并安排调查与写作。已有文章沿用原身份和历史，草案版本与正式正文版本分开。详细流程及代码改造见[知识目录草案](knowledge-outlines.md)。

页面计划包含读者、页面类型、要回答的问题、阅读后能做什么、场景和调查入口。入口是调查线索，不是固定文件清单；模型可以继续搜索、阅读调用者、类型、测试与设计文档。ACP 知识任务已经使用原生文件读取/搜索和 MCP 在已捕获快照中调查，独立复核也能补查；没有宿主 token 预算或研究轮数限制。当前 Traex 使用只读配置；不由模型直接写入事实或外部发送消息。保留运行记录，引用与识别到的实际读取进入依赖。

分析记录可以内部复用；不要求先把所有文件写成文章，才能写一篇跨文件机制解释。缺背景先调查，无法确认再明确说明。设计动机区分有记录的决策与基于代码的推断。

## 统一检索与回答

所有用户搜索入口复用同一 RetrievalPort。全文、符号、记忆、知识、可选中文向量合并候选，按问题补上下文。查名字重精确；问机制补功能链；问原因补设计背景；问历史区分业务时间和捕获时间。当前时间过滤能力不能冒充历史 as-of 推理。

每个结果保留固定来源，同时可以携带父章节、代码定义、相邻解释和派生文章。不要只把命中的几百字符当作完整回答材料。重排器与新 embedding 在真实问题上对照后再接入，模型身份变化重建向量。

## 记忆与主动事项

原始记录 → 经历 → 当前事实/偏好/经验 → 人物、项目、主题综合理解 → 行动。维护变化与来源，避免每轮问答从孤立事实重新拼凑。来源更新已有重核验可复用；周期整合、事件时间检索、自动回复跟进和学习卡另列后续阶段，不写成已实现。

## 第一阶段

以 omem 本仓库做五篇页面：认识系统、材料旅程、检索问答、原文与记忆更新、修改完整功能链。直接用真实 traex ACP / gpt-5.6-sol 生成与独立复核。这五篇是实验输入配置，不是产品固定目录或默认首页。

## 分类、范围与引用（2026-10-02 修正）

文章的 `topicPath` 保存从宽到窄的人读分类，如“语言学习 / 英语 / 听说”。草案中的分类和页面顺序在确认后进入正式计划，目录可以按已保存计划显示调整；已发表正文及其固定历史保持原版本，等待重新整理。没有分类的旧文章按未分类处理，不按 key、文件夹、生成批次或新旧版本猜分组。`category` 允许不同领域自己的类型名称。分类只负责组织，不改变来源权威性；引用依赖只负责关联与更新，不自动成为目录父子关系。

页面计划的 `materialKeys` 是明确的调查范围，`entryPaths` 只是范围内的入口线索。网页选择固定材料版本后，将选择转换为同一来源体系中的材料 key，研究、写作、复核、发布都复用通用流程。不存在“仓库才可以生成指南”的分支。知识搜索可显式限定分类，并按文章返回最相关章节，避免长文章重复占据结果。

通用代码不根据 `docs/archive`、项目名、文件名前缀或问句中的“历史”等词决定可见性或加减分。本仓库的导入、旧 key 兼容和本地 Markdown 链接留在输入适配层；旧 key 的来源别名持久保存，通用解析器只查询数据，不识别 `omem:`。排序效果不足继续作为缺口，不能用对题集的路径特判遮盖。

目录草案处理明确选材后的阅读组织，已有文章可被选为更新目标。自动全库分类治理仍未完成；材料范围需要明确选择，大库候选检索与跨主题冲突仍需继续完善。

本轮补充第六篇生成过程指南：沿一篇跨设计与代码的文章，解释自主调查、作者补读、独立复核与发布。它也是普通页面计划数据，不能成为通用生成器的特殊分支。
