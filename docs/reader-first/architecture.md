# 目标流程与实施边界

这是重构目标，交付状态见 progress.md。

## 一个来源体系，多种用途

原始材料进入 Capture，保留 Source 与 Revision。文本、图片、链接和上下文一起保存；代码是同一材料体系的专用解析，不建立独立知识库。

保存单位、检索单位、讲解单位分开：原件保留历史；结构块按标题/列表/表格/函数/对话组织；页面围绕一个读者问题跨材料解释。派生内容能够引导检索和提供理解背景，但不成为第二份独立事实。

## 问题驱动的知识生成

仓库侦察 → 读者任务与页面计划 → 按问题检索、读取与补充上下文 → 写解释 → 检查事实和页面目的 → 发布 → 按依赖增量更新。

页面计划包含读者、页面类型、要回答的问题、阅读后能做什么、场景和调查入口。入口是调查线索，不是固定文件清单；模型可以继续搜索、阅读调用者、类型、测试与设计文档。研究发生在已捕获快照内，不赋予任意 shell 或外部写权限。保留实际读取范围和运行记录。

分析记录可以内部复用；不要求先把所有文件写成文章，才能写一篇跨文件机制解释。缺背景先调查，无法确认再明确说明。设计动机区分有记录的决策与基于代码的推断。

## 统一检索与回答

所有用户搜索入口复用同一 RetrievalPort。全文、符号、记忆、知识、可选中文向量合并候选，按问题补上下文。查名字重精确；问机制补功能链；问原因补设计背景；问历史区分业务时间和捕获时间。当前时间过滤能力不能冒充历史 as-of 推理。

每个结果保留固定来源，同时可以携带父章节、代码定义、相邻解释和派生文章。不要只把命中的几百字符当作完整回答材料。重排器与新 embedding 在真实问题上对照后再接入，模型身份变化重建向量。

## 记忆与主动事项

原始记录 → 经历 → 当前事实/偏好/经验 → 人物、项目、主题综合理解 → 行动。维护变化与来源，避免每轮问答从孤立事实重新拼凑。来源更新已有重核验可复用；周期整合、事件时间检索、自动回复跟进和学习卡另列后续阶段，不写成已实现。
