# 通用知识流程修正

日期：2026-10-02。此页跟进本轮实现与验证。

## 为什么要改

第一轮把本仓库当样板时，通用调查器混入了目录排除、历史关键词门控；排序器接入路径权重，页面按 key 前缀摆放五篇指南与旧综述。即使本仓库的几道问题改善，也不能证明多领域知识库有效。这些规则撤销，不换成另一套隐蔽的问句特判。

## 本轮交付

- 调查搜索对明确范围内的材料一视同仁；代码 AST 定位仍保留。来源移除与固定旧版本是生命周期事实，与内容“历史价值”分开。
- 正式文章合同保存人读的 `topicPath`，分类可有多层，领域名称不设软件工程白名单。API、SQLite 保存、恢复、搜索、目录使用同一数据。
- 引用不作为父子目录；没有分类的文章就是未分类，不安排专门的旧版区域。
- 页面可选材料、填写阅读目标，通过 `/api/knowledge/pages` 调查、写作、独立复核和发布；同一路径接受文档、代码、学习笔记等。范围选择保存在文章 reading 数据中。
- 分类内查找先限定文章和相关材料；一个文章只占一个结果，附最佳命中章节。顶部搜索区分等待、成功、空结果与失败，快速换词或离开页面不会被旧请求回写。
- 仓库导入器移到 review 适配层；已有 `omem:` 材料 key 作为持久别名保留，通用代码不再解析特定项目名前缀。没有重写旧正文冒充重新复核。

## 验证与剩余工作

程序检查覆盖独立领域的分类持久化、重启恢复、分类检索、调查选材范围，以及引用与目录解耦。真实生成与浏览器结果将在执行后补记；未执行前不作为通过结论。

后续仍需来源集合和分类编辑、自动分类治理、大库检索性能与通用相关性优化。当前分类是文章级组织，尚不是完整的材料集合权限或项目隔离；不把选材范围当安全边界，也不声称已解决自然语言排序。旧适配器中的人工关联和代码图历史兼容仍保留，不参与知识目录或路径加权。
