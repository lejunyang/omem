# 让文章在材料变化后仍然可用

本轮实现从一个阅读问题开始：用户整理了一篇活动说明，其中预算和集合地点来自同一份原文。只修改原文的导读，不应让两节解释同时消失；预算变化时，应标出费用部分需要核对，集合说明仍可查阅。引用始终指向写作时的身份。聊天或更正事件保留原件；代码和可变文档只留最新原件，移除的旧引用会说明原因，不自动换成新文字。

## 保存什么，向读者展示什么

`knowledge_pages` 独立保存页面目标、发布用途和生成状态。生成失败保留计划；普通重新整理保留原来的正文，直到新结果经过独立复核并发布。选择删除旧成果后重新处理时，先清除旧正文及其各版成果，只保留计划与删除审计。知识库可以开始计划中的页面、重试失败的页面，以及重新整理已有文章。

| 用途 | 产生方式 | 阅读与召回 |
| --- | --- | --- |
| 正式文章 | 带入门、解释或操作目标的 `writePage` | 主题文章目录、搜索和助手背景 |
| 参考资料 | 带 reference 目标的 `writePage` | 独立参考目录，也可搜索和提供背景 |
| 内部笔记 | 对明确选中材料进行 `analyze` | 留作内部分析，不发布到目录、知识召回或通知 |

旧资产按保存的 `reading` 目标迁移用途，没有目标的旧逐文件说明归为内部笔记，不根据项目名、文件路径或 key 前缀推断。`review:generate <路径>` 只生成内部笔记；旧的模块归组、每十二份子材料拼专题和整库逐文件合成已移除。正式页面使用 `review:guides` 或网页的“整理文章”。

目录不是依赖图。页面可以跨任意来源引用，分类来自保存的主题路径；没有生成成功的页面也可以保留阅读目标。

## 三种来源关系

1. **正文引用**：解释某句话或段落的来源，可以打开固定章节或代码范围。
2. **章节背景前提 `reviewSources`**：某个未写进正文的配置、约定或调用条件发生变化，也需要重新核对该节。作者选择原文范围并说明原因，独立复核检查关键前提。不能把所有阅读记录都放进去。
3. **调查轨迹 `investigation`**：研究者、作者和复核者实际读取过的材料，以及运行 trace。保留范围和审计信息，偶然读到的材料换版不直接判正文失效。

检索和调查快照仍尊重整个生成背景的可见范围；把阅读记录与更新依据分开，不代表可以跨越原材料的访问范围。

## 怎样判断变化影响

`knowledge/lifecycle.ts` 是发布、API 和检索共用的判断入口。原件仍保留时，它比较固定原文与当前原文：引用所在完整 Markdown 章节或代码符号未变时，允许其行号移动，继续使用原来的解释；引用所在上下文或明确背景前提变化时，标出需要核对的章节。来源丢失或按最新原件策略移除后，说明无法读取原来的依据；旧链接不会改指当前正文。整体页面留在目录，当前搜索只使用仍可用的章节。

当引用跨过 Markdown 的导读和几个章节，最小共同标题常常是整篇文章。现在把这种文档根范围分成导读与直接子章节，只比较引用实际涉及的完整部分；子章节内部的条件和下级标题一起保留，不能只比较字面引用句。所选范围之外的筹备记录变化不会让前面的安排说明过期；范围内新增、重排章节，所引章节改动或身份定位不唯一，仍需要复查。单个小节内部其他句子的变化依然可能影响含义，不自动判断为无关。

一次真实维护暴露了这一区别：记忆指南用项目说明的 3–19 行作为文章更新的背景，远处新增验证结果也让它失效；这是把根标题等同于整篇依赖造成的过宽判断。另一处引用与“正在验证”状态写在同一小节，修改状态也牵连引用。前者由通用结构比较修正；后者把实验状态移到独立验证章节、把事实/待办说明独立分节，并让模型按新结构重新核对，不能为本仓库特判某些句子无关。

代码的阅读范围包含 AST 识别的附属 JSDoc，包括箭头函数声明上的说明。实际文章常把说明和实现一起引用；只从函数声明行开始比较，会把这种引用误当成没有结构的全文引用，导致无关函数增删也触发复核。声明本身的代码导航行号不变；附属说明发生变化同样需要核对，不能只比较函数体。

这只是定位复查范围，**不是 AST 证明代码语义不变**。未列入依据的跨文件配置、调用方和运行环境仍可能影响解释；作者和复核者需要把这类重要前提记录下来。无法确定结构的普通文本仍按整份原文变化处理。当前也没有完整调用图或自动语义影响分析。

已有用户纠正会让相应文章等待重新整理；引用其他文章时仍沿固定版本核对原件，新的解释可能触发上层核对。一次复核成功不能代替读者验收。

原生知识调查不再预先排除整篇待更新的已发布文章。例如预算变化、集合地点未变时，后续路线指南仍可以搜索已有的集合说明，或阅读旧文了解背景。知识目录提供固定修订、整体状态和章节标题；共享检索投影只返回仍适用的章节，直接读取旧文章则明确标为 `needs-review`。所有调查、写作、独立复核阶段使用同一批获准文章，超出本次选材范围的背景仍不进入。新增文章引用旧知识后，依赖仍固定到该版并按所引章节传播更新状态；它不是绕过原件检查的捷径。这个改动允许复用已有解释，并不保证模型一定选择或正确理解这些背景。

## 更新、删除与历史

`writePage` 保存计划，调查、写作和独立复核后发布。失败保留有效旧文和计划；在页面点击“重新整理这篇”会使用当前材料重新运行，不新建一篇同名文章。

现在可以在文章上开启“随所选材料自动更新”。必须先明确选择材料或项目/主题范围，默认关闭；原件保存新版本后，后台将这篇文章加入持久队列。只跟踪这篇文章的选材，不按项目名、路径或相似词猜测其他来源。选择整个项目或主题时，后来明确归入该范围的新材料会自动成为选材；只选择固定材料时，新增材料仍从“调整材料与目标”加入。开启后，补充背景加入计划也会触发维护。范围的使用与边界见[项目与主题材料](project-contexts.md)。

`knowledge/page-worker.ts` 把自动更新设置与正文、阅读目标分开保存到 `knowledge_page_maintenance`，网页手动整理也改为同一个持久队列。它复用 `DurableJobWorker`，仅处理 `knowledge:maintain-page`；实际研究、写作和独立复核仍由 `KnowledgePipeline` 的角色任务负责。后台定时检查已选原件，不在 GET 请求中调用模型。排队期间的连续变化合并，执行时读取最新选材；执行中再次变化则下一轮处理。服务重启后保留设置与待办任务，关闭自动维护会取消尚未完成的自动任务，不取消明确手动发起的整理。

失败保留旧文章并显示重试入口，不反复对同一份失败输入调用模型。新材料版本、范围成员变化或手动重试可以再次执行。界面显示排队、调查写作、完成或失败，旧引用按来源保留策略读取或说明不可用原因；一次后台维护不会把知识文章变成独立事实，也不会直接修改个人记忆或事项。当前支持明确材料与项目/主题成员，尚未从内容自动判断新材料归属，也未实现周期回顾。

维护已有文章时，调查者现在会收到旧正文、旧阅读目标、本次目标变化、受影响章节、新增选材和已读原件的版本变化。原文变化范围复用界面的 jsdiff；它提供新旧行范围作为补读入口，不声称已经理解语义，也不自动迁移引用。没有保存过完整旧目录的开放选材计划，不会把所有未读文件都误报为新增材料。

调查者先检查旧稿是否仍有清楚的阅读路线，再用 `composition` 选择维护或重组。局部事实更新使用 `knowledge-refresher`，保留有效场景与解释；旧结构妨碍理解时使用 `knowledge-writer`，依据调查结论和当前原件重新组织，不把旧稿作为逐段补丁交给它。之后的复核返修仍使用新草稿。独立复核既检查新事实，也检查必要前提；重组时不要求恢复无关旧章节。历史正文与页面身份不变，引用重新核对当前原文。若旧文超出本次材料范围，本来就不会提供旧稿。运行记录保留前一版本、变化概要与组织决策，不复制整篇旧正文；失败草稿只有在阅读目标、输入版本及组织决策相符时才复用。

完整独立复核完成后，若页面已经能完成读者目的，其余事实和关键前提均通过，所有阻塞问题仅是已有材料引用的行范围，复核者可通过 `rangeRepair` 给出准确修订。例如正文正确解释了两条分支，而引用只截取其中一条，复核者补读后可以直接指出需要覆盖的起止行。宿主只替换这些行号并重新提取原文 `quote`，保留正文与结构，跳过一次作者返修。下一轮启动新的独立会话，仅提供受影响章节及前次复核记录，补查新范围是否支持相关论断；全部获准原件仍可搜索和读取，不限于短引文。

这条路径只处理已有材料引用的准确行范围。正确范围未知，或需要改正文、增删引用、调整引用关系或章节背景前提时，继续普通返修与全文复核。局部补查发现新的事实错误、决定性前提遗漏或页面目的未完成，也会撤销局部资格，返回写作和全文复核。运行 trace 分别记录全文检查与范围补查，并关联前次复核任务；最终范围补查不冒充重新做过全文检查。

每次模型阶段与发布前检查本次原件的 revision 身份。即使正文相同，只要已换版或移除，也停止沿用旧输入，显示 `KNOWLEDGE_INPUT_CHANGED` 和“原件已变化或移除，请按最新材料重新整理”。阅读目标或本人补充变化同样要求重新调查。普通整理保留旧文章；显式选择删除替换时，旧成果已清除，失败后只能从保留的原件再次生成。

重启不会把局部检查的章节摘录当成完整旧稿。输入仍匹配时，从持久父复核链恢复完整草稿与已应用的范围修订，供普通返修继续使用；不继承前次接受结论，新一轮仍需全文复核。父记录缺失或原件已变化时不复用该草稿，按最新材料重新调查。这些是当前执行规则；协议与工程检查不能证明真实 Traex 已走过该局部路径，也不能证明内容已经适合目标读者，实际验收见 [progress.md](progress.md)。

真实 Traex / Sol 已完成一次同页维护：复用此前实际模型生成的装备检查指南，只把集合时间从 18:00 改为 18:30，并在原文前插入标题使行号变化。研究、改写、独立复核三阶段完成，保留同一章节、米拉负责人、80 元预算及先检查后开场的顺序；例子同步改为 18:30，引用从旧第 2 行重定位到当前第 4 行，旧文章仍可读取。约 311 秒，实验数据库结束后释放。这证明简单变化接通，不是自动语义影响分析或稳定提速的证明。新稿还增加了不必要的报销说明，复杂页面的保留与删减质量仍需改善。

统一 Agent 启动配置后，同一旧文章与同一材料变化重跑约 244 秒完成；三个角色没有再尝试读取无关的仓库 README/进度文档，时间、负责人、预算、顺序和固定引用仍正确，旧文保留，实验数据库已释放。此次正文没有新增报销说明，但仍重复了旧时间和未知清单。单次运行不能把约 67 秒差异全部归因于配置，也不能据此声称内容质量稳定改善。两个结果保留在同一 ignored `runtime/experiments/knowledge-maintenance`，不进入个人知识库。

“补充背景”会把回答保存成原始材料，同时加入这篇文章的选材计划。下一次重新整理时，研究者、作者和独立复核者都能读取它。保存补充本身不等于正文已经更新；开启持续维护后由后台排队，否则需要手动重新整理。两种方式都应检查新结果。

导入的历史文章成为当前展示版本时，同步恢复正文中的问题入口，即使其引用原文已经变化也可以继续补充背景。重复导入保留已回答、已转事项的状态；仅作为历史保存的另一版本不改当前问题。问题是否仍待回答，与文章是否需要重新整理是两件事。

已有文章可点击“调整材料与目标”，在同一个两步弹窗里增删材料、修改主题、阅读目标与读者，再保存并重新整理。文章身份和旧版引用保留；用户修改的计划独立标记，启动时导入仓库默认计划或文章不能覆盖它。若模型执行中又加入补充，较早任务发布前会发现计划变化，保留旧文与新计划并提示重新整理。

资产导入按目录记录所管理的文章版本，只有新资产真正成为当前正文后才推进这条记录。校验失败、等待依赖或因个人修改而仅保存为历史，都保留上次实际导入的版本；否则下次会把旧正文误认成个人改写，阻止正常更新。文件从该目录移除后，只退出该导入拥有的发布版本；用户后来改写的版本、个人材料和仍供固定引用读取的历史不被删除。目录重新加入相同资产可以恢复发布。可变原件的旧全文按来源策略自动移除。显式删除文章会清除各版正文、失效旧任务，并记录删除的 revision；同一旧静态资产再次导入也不会复活，只有清除后生成的新成果可以恢复。文章的目录下架仍是单独操作。

## 修改入口与验收

- 合同与模型：`packages/contracts/src/knowledge.ts`、writer/refresher/verifier 的角色合同和指令。
- 发布与更新：`knowledge/pipeline.ts`、`citation-repair.ts`、`maintenance.ts`、`page-worker.ts`、`repository.ts`、`lifecycle.ts`、`artifacts.ts`。
- 搜索与调查：`retrieval/units.ts`、`knowledge/research-snapshot.ts`、`assistant/research.ts`。
- 阅读与操作：`KnowledgeHome.vue`、`KnowledgeDocument.vue`、`knowledge/api.ts`。

验收分别检查：计划在失败后可恢复；无关章节变化不让整页失效；重要前提变化能提示对应章节；引用仍指向旧版；删除导入资产后不恢复无用目录且保留个人内容；真实 Traex/Sol 写出的一个完整主题能让新人理解、使用和修改。工程检查与模型、浏览器结果记录在 [progress.md](progress.md)，不沿用上一轮通过率。
