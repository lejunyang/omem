# 飞书与文档导入：保留原件，按结构阅读

更新：2026-10-07。输入页已有「PDF / Word」入口，支持文字 PDF 和 DOCX。上传先保存原文件，再由持久任务解析；解析失败或服务重启后可继续处理。个人飞书链接通过项目依赖中的官方 `@larksuite/cli@1.0.97` 获取正文，机器人使用接收应用自己的权限；Docling 负责文件解析。

## 怎样使用

安装版先按[依赖与模型](../../skills/omem-cli/references/dependencies.md)准备 osdk，再在服务机器运行 `omem setup`，选择 documents，并在子选项中选择是否一起准备 PDF 模型；直接选择 document-models 也会补上解析环境。无需手动串联两条命令。Docling 环境在个人库 optional/，权重由 osdk 管理；运行不隐式下载。Windows Python 路径已适配，但尚未实际验收 Windows/Linux 全新安装；OCR 仍关闭。

源码开发使用以下任务。

```bash
# 可选文件解析能力，首次显式准备
osdk run documents:prepare
# PDF 额外需要布局和表格模型；由 osdk 下载、锁定和校验
osdk run documents:models
osdk run dev
```

在「输入材料」选择 PDF / Word、选取文件、保存。文件最大 20 MB、200 页，解析文字最多 20 万字符。原文件立即保存到个人库，导入记录显示等待、正在解析或失败原因；成功后才创建可阅读的正文，启用材料理解时再排队学习。完成后在「原始材料」阅读标题、段落、表格和原位置插图。导入记录可以下载保存的原件，解析失败时也能下载。

例如，上传「活动约定.docx」后发现解析环境尚未准备，导入记录会显示失败，原文件仍在。准备环境后选择「重新处理 → 重新解析保存的原文件」即可重试，不必重新上传。服务重启会继续已排队的任务；已失败的任务需要显式重试。启用材料理解后，重新解析也会安排新的理解任务，不能因为同一正文以前已处理成功就跳过；停用理解时只等待解析完成。

命令行可查看导入记录，再用保存的原文件重新解析。以下 ID 来自 `imports list`，不是文件路径。

```bash
omem imports list
omem imports show <导入ID>
omem reprocess run document <导入ID> --action parse --wait
omem reprocess run source <来源ID> --action understand --replace --wait
```

`parse` 重新提取文件正文、表格与图片；`understand` 使用已有正文重新整理记忆和事项，需要先启用材料理解并配置 Agent。`--replace` 会清除对应旧成果后再处理，失败后需用原件重试；不指定则保留有效旧成果。`--wait` 等待实际解析和已安排的后续理解任务，失败退出 1，Ctrl+C 只停止等待。重新处理记录可查看各阶段状态；排队成功不代表文章或记忆已更新。

飞书继续使用「飞书链接」。安装项目依赖后已包含官方 CLI，无需借用全局安装；它使用本机用户登录和文档权限。服务端与 CLI 命令入口都走同一个连接器。完整官方响应保存为附件，正文单独进入阅读和检索，块 ID、媒体和引用元数据不会作为一大段 JSON 混进正文。

机器人收到消息后先保存事件 JSON，并安排持久收件任务。图片和附件下载到个人库后才解析；文档链接用官方 SDK 读取并保留完整响应 JSON。私聊和群消息复用个人采集的资源适配，机器人身份无权读取的文档会留下失败原因，不借用个人 CLI 登录。资源失败后任务重试或重启恢复会优先使用已保存的字节。

机器人「重新理解」只读已保存的事件、资源字节和文档响应，连接停用后仍可离线处理。它会安排新的学习任务，不重新执行旧委托，也不再发送当时的回复。未下载成功的资源不能从消息 JSON 中恢复；这时记录会明确失败，需恢复备份或选择「从来源读取最新版」。后者会重新访问飞书，获取的是远端当前内容，不能视作当时的旧原件。

当前机器的官方 CLI 登录读取已经恢复，真实私密文档与消息的只读实验结果保存在仓库外。此前的钥匙串阻塞不再是当前结论，没有降级为明文凭据。基础正文可读不等于内嵌画板、表格和引用文档都已自动展开；这些能力仍需在导入器中补齐。个人消息里的资源处理见[飞书消息](personal-messages.md)。

## 保存了什么，代码在哪里

| 层         | 当前实现                                                                                                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 原件       | `imports/documents.ts` 将原字节按 SHA256 保存为附件；`imports/service.ts` 在解析前建立持久导入记录。同一导入身份保留最新原件，运行中的任务固定使用其输入字节；不再无限保留每次上传的完整文件 |
| 任务       | `document_imports` 记录原件、解析任务与失败原因；`document_parse` 完成后才发布 Capture，并把新理解任务关联到解析任务。被新上传替代的旧任务不能覆盖当前正文                                   |
| 解析       | `scripts/document-parser/convert.py` 使用锁定的 Docling 2.133.0；保存完整 DoclingDocument、顺序块、标题层级、表格、图片，以及 PDF 页码和坐标                                                 |
| 阅读       | `DocumentReading.vue` 按原顺序渲染；图片请求受具体 revision 的附件清单约束，下载原件带用户会话认证                                                                                           |
| 检索与写作 | Docling 导出的 Markdown 进入现有 Capture、结构切分和 RetrievalPort，与其他材料共享处理链。Agent 可继续读固定正文；结构附件中的插图目前供页面阅读，尚未映射到 Agent 的视觉材料列表            |
| 飞书       | `connectors.ts` 解析项目内官方 CLI 的固定包路径，执行 `docs +fetch`，保留 URL、文档身份、修订和原始响应                                                                                      |
| 机器人     | `integrations/lark/realtime.ts` 将事件和资源清单持久保存，`lark_inbound` worker 负责收件和重放；`resources.ts` 以接收应用身份读取图片、附件和 docx/wiki 正文                                 |
| 环境       | Python / uv 由 osdk 管理；包版本由独立 `uv.lock` 固定；布局和表格权重由 `osdk.toml` / `osdk.lock` 管理。正常导入不下载依赖或权重                                                             |

原件、结构附件与阅读文字用途不同。当前检索引用仍指派生文字的固定章节/行；页面坐标已保存，但尚未提供「点击引用直接框选 PDF 原页」的交互。解析失败不会创建空正文；失败导入保留原件和任务错误。代码与文档按最新版原件策略管理，已回收的旧原件不可下载；历史引用的可用性由保留策略明确说明，不能悄悄展示新版本。

## 本轮实际验证与限制

- 此前本机真实转换了中文 DOCX 和文字 PDF。DOCX 的标题与表格保留；PDF 保留页码/区域，样本中无边框表格被识别成文字，不能声称所有表格都正确。
- 此前实际 `dev` 页面上传了明确标注为验收用途的 DOCX，原始材料页显示正文、表格和插图；本轮新增导入与重新处理界面仍需实际页面验收。
- 2026-10-07 使用合成上传字节与图片验证原件先保存、解析失败后保留、两次重启后继续、机器人停用后的离线重放，以及缺原件不访问远端且不排队学习。文件解析器与资源端口在这组检查中注入；固定飞书响应不会被更新后的缓存正文替换。相关新检查与既有机器人恢复检查共 24 项通过。此轮未访问私人飞书或调用外部模型，不能据此声称真实应用资源权限已验收。
- 机器人 docx/wiki 当前读取纯文本；内嵌表格、画板和文档图片尚未展开。PDF/DOCX 附件复用 Docling；其他暂不支持理解的附件仍保留字节，并明确资源缺口。
- OCR 当前关闭，图内文字不会自动识别，解析没有正文时会报错；图片占主导的扫描件、复杂版式和跨页表格没有完成验收。
- 原文阅读保留结构不等于生成了易懂的 Wiki。后续知识组织仍应先明确页面问题，再由 Agent 选材、补背景和写作。

后续补 OCR，并把页码/区域接到引用阅读。布局识别继续使用 Docling。上游的数据结构见 [DoclingDocument](https://docling-project.github.io/docling/concepts/docling_document/)，官方飞书工具见 [larksuite/cli](https://github.com/larksuite/cli)。
