# 围绕问题调查，再检查答案是否有用

2026-10-03。后续问答与验收统一使用 Traex ACP / GPT-5.6-sol，停止 Luna 对照。保留可配置 profile，不做快慢模型路由。本文说明本轮实现，实际效果另写验证报告。

## 问题与目标

“关键前提遗漏”可能发生在没有找到必要条件、命中后没读上下文、读到后没写进结论三个环节。“资料相关却答非所问”则常发生在把术语介绍、问题清单或计划当成已经回答问题。schema 和引用正确都不能发现这些语义缺口。

目标是让用户得到可用判断。例如询问服务是否自动运行，需要解释触发点、启用条件和用户要做什么；询问普通约定，则需要保留会改变结果的适用对象、时间和例外。

## 当前实际流程

助手沿用原生 Traex 工具循环。复杂问题用 `investigation_notes` 保存简短事实笔记：用户需要的结果、材料已回答的问题、具体未解缺口。笔记写在本次临时工作区，不是个人记忆，也不是内部思考过程。简单查询可以直接读原文回答。

调查使用原有搜索、完整章节、历史、记忆、图片和代码导航。每次补查围绕一个缺口，使用材料里发现的术语和定位。初始命中仍只是线索；相关性分数不等于能够回答。`code_navigation` 增加导入别名、调用表达式、接收者、构造调用、外围条件及完整方法的定位，便于继续核对真实入口。它仍是候选导航，不解析完整接收者类型、变量传播或跨文件调用图；提前返回及其他上下文仍须读完整方法。按导入别名寻找调用目前用于此调查工具，不等于所有 HTTP 搜索都已支持别名解析。

作者对复杂机制、冲突、当前行为的关键前提选择 `review_answer`。新 Sol 会话读取原问题、候选答案和相同固定材料快照，可自主补查；不接收作者调查笔记，不提供递归复核工具。原文、历史、记忆、文章和材料说明来自作者的封存数据库，新产生的实时变化不混入同一道问题。原生 CLI 仍不具备完整文件系统隔离。

独立读者集中返回会改变结论或行动的错误、遗漏和偏题问题，包含影响、原文位置及简短建议。作者补读后修改答案；无新增实质疑问时不再例行复核。普通短查询不强制增加模型调用。角色会话沿用可配置 ACP profile，当前使用 Sol，没有新增宿主 token 或工具次数上限。

## 宿主究竟检查什么

`assistant/answer-review.ts` 提供笔记和复核工具，`assistant/acp-model.ts` 接入独立 ACP 会话，`assistant/research.ts` 仍校验来源与事项候选。作者标记需要复核后，未完成复核不能提交；有重要意见的原样草稿也不能直接提交。修订稿由作者负责吸收反馈，宿主不能用“字符串变了”证明语义已经改好。是否需要复核仍由模型判断，可能漏判；复核者也可能遗漏。

复核失败返回实际错误，不伪装成功。候选与意见在各自工作区保存；复核无个人事实或事项写入权限。最终行动仍由原有 MemoryService/事项应用流程处理。

## 检索用途的调整

原先对整篇计划、调研、示例统一降权会误伤有效材料。现在只在明确 `purpose=implementation` 且未指定材料用途时保留当前实现偏好；综合、概念、背景及明确用途查询不受这个全局惩罚。用途仍来自版本化正式标注，不按目录或题目猜测。尚未实现段落级混合用途，也未证明此调整提高所有查询的首屏排名。

## 验收方法

真实 Sol 验收看最终回答是否保留必要条件、直接回应问题、给出需要的操作入口；普通文档与代码都要读实际正文。结合初始命中、MCP/原生读取记录、笔记、草稿、复核意见和最终回答，定位是没找到、没有补读还是最后遗漏。工具记录只能证明读取请求发生，不能证明模型已经理解。

问题文件放在未采集的 runtime，区分已有回归问题和新问题。不按某道题的路径调排序；不以工具次数、引用数或复核通过作为阅读质量分数。实现检查通过后更新受影响指南，实际成功、失败、耗时及未验证项记在本轮报告。
