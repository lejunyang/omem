# 自主调查这轮做到了什么，还缺什么

2026-10-02。此页记录实际结果；整体方案见 current-system.md、component-integration.md 与 agent-research.md。模型生成的文章仍需真实读者使用，独立复核不代表用户验收。

## 已落地的流程

知识生成现在使用 Traex 自带的 Agent 循环。研究者在固定原件中搜索、读完整文件和章节，作者收到研究结论后可以继续查，独立复核者在新会话重新调查草稿中的关键因果。初始输入主要是阅读目标、目录和工具方法；没有宿主输入/输出 token 预算，也没有固定三轮调查门槛。模型自己的窗口和上下文压缩、运行超时与取消仍存在。

原始代码、文档和图片导出到独占工作区，内部知识和记忆通过 MCP 读取。工具覆盖材料发现、全文与语义搜索、章节与行段、已有解释、记忆、符号和候选调用、关联、历史、图片和最终候选提交。只读调查不需要每次让用户确认；发布仍由宿主完成。普通助手问答与记忆抽取没有因这次改造自动换成该流程。

已经用真实 traex / gpt-5.6-sol 跑通一个小型工单样例，并用同一正式流程更新本仓库受影响的源码解释与读者指南。研究、作者、审阅者都有实际工具调用。小型样例包含输入输出、流程图、概念区别和修改入口，不是协议 fixture。图像和历史工具、长时间全库调查尚未逐项完成真实模型验收。

## 检索改善与没有解决的部分

已修复中文切词、候选概念覆盖、局部段落评分、标题扩散、重复融合、向量弱尾部、同源重复摘录及知识引用扩散。知识文章只把实际命中的段落、列表项或表格行所引用的原文带入候选，不再因为命中一章而推高该章所有代码。不存在的精确标识符返回空。

中文 BGE embedding 保留为默认；中文/英文 BGE cross-encoder 用 osdk 下载、校验和锁定，并接为可选配置。六个新问法的实际库对照没有证明开启它后总体更好，故未默认开启。索引建立、同义词样例通过、公开回归题命中，都不能解释成复杂问题已经检索好用。

另外做了已有讲解段落的语义检索原型：使用同一 BGE，对文章标题、节标题和解释正文生成 1,018 个窗口，保留回原件的引用，不写入正式片段向量。这对“谁应用记忆”“重复导入”“引用哪些代码行”等问题提供了更有用的解释；“等待跟进”和“Agent 自主调查”仍有明显误召回。它是实验，没有接入默认检索，也不是一套已标注的通过率评测。

下一片应优先改检索表示和问题用途，而不是继续调分数：

1. 在 `knowledge/retrieval.ts` 和检索适配层为讲解段落建立单独投影，结果带文章、章节、引用与原件；既能找解释，也能继续查代码。
2. 在 `knowledge/structure.ts` 与 `retrieval/semantic.ts` 给原件检索单位补章节、函数职责与来源背景。对照 Contextual Retrieval；派生背景不改原文，换预处理就换向量身份。
3. 在统一检索请求中表达找定义、问机制、查变化、跟进事项等用途，使用正式范围和当前/历史适用状态；不按仓库名、路径或验收题特殊排序。
4. 用未放进材料库的真实问题分别判断能否找到必要背景、首屏是否无关、给足材料后能否回答，再决定是否默认启用重排。

## 真实运行暴露的问题

整库角色工作区曾长期保留数据库和原件副本，积累到磁盘不足，造成真实任务失败。现在成功、失败、取消和准备异常后释放大副本，保留目录、结果与调查 audit；正式原件、旧文章和历史保留。原库完整性检查为 ok。不能把 gitignore 当临时资源管理。

`agents.ts` 的首轮逐文件说明在多轮事实复核后仍失败，旧有效历史保留。改用明确的读者问题“同一次请求如何经过 ACP 或 CLI 返回”重新调查与写作，随后独立补查通过；原失败没有从报告中抹掉。这说明读者目标会影响调查和讲解，不能只把每个文件丢给同一摘要模板。

检索指南的一次独立复核超时；重试使用相同模型和工具，把允许运行时间从八分钟延长到十分钟，没有增加 token 预算。独立审阅也确实发现了草稿错误，例如把研究者的读取误写为自动过期依赖；实际只记录正文引用以及作者、复核者的读取，研究 trace 单独保留。

## 阅读与报告怎么判断

实际隔离的 `osdk run dev` 页面检查了菜单、引用行段、上下展开、逐层滚动返回、原始 Markdown、变更差异、自动能力读取和 1440/768/390px 阅读。浏览器回归 17 组通过。现有 viewport 脚本最后只接受段末引用的定位，在新版行内引用上失败；临时检查改用真实引用链接定位后，10 组检查通过且没有页面异常。原脚本的兼容问题仍保留，不把这次适配说成已经修好了脚本。

`.repo-review/knowledge/verification.json` 是最近一次当前报告；其 history 是旧报告追溯，不累加成今天的通过率。`material-refresh.json` 记录选定源码的生成与失败；`retrieval-experiments.json` 保存实际库重排对照及最终 HTTP 结果；`knowledge-paragraph-experiment.json` 保存解释段落原型。coverage 描述 current/stale/pending 和本次生成失败，不能把未选中的旧库缺口当成本轮已经补齐。

源码实现与模型派生资产分别本地提交，没有推送。启动 dev 恢复已发布知识，更新后需要重启才能看到新文章，不自动调用模型生成整库，也不清空个人库。
