# Review 启动模式修复（2026-10-01）

现象：`dev:review` 的 Vite 先监听，API 仍在恢复仓库材料。此时打开页面，第一次 `/api/review/health` 失败，旧入口直接退回个人工作区，之后持续请求 review 不提供的 `/api/tasks`、`/api/jobs` 等接口；API 就绪后也不会重新识别模式。

修复：入口在确认运行模式前显示连接状态；只有 review health 明确返回 404，且个人 health 成功，才启动个人页面和业务轮询。网络失败、超时、代理 5xx、鉴权失败均保持连接状态并重试，提供令牌输入和手动重连。review 探测携带现有会话令牌。

验证：在用户的 65091/65092 实例上暂停 API 30 秒，重新打开页面显示等待，API 恢复后自动进入仓库视图。现有 Code Wiki 浏览器脚本增加 503→恢复回归，断言等待期间及恢复后没有个人业务 API 请求；沿用三个视口、递归引用与深链检查。全项目检查通过（351 项测试、类型检查和构建）。

另一个独立环境问题：用户服务使用 Desktop/osdk-home，原中文模型位于默认 osdk 目录。已在用户服务的 OSDK_DATA_DIR 下用 `osdk model sync memory-zh` 恢复锁定快照并校验，重启后 health 为 ready。应用仍不隐式下载模型；没有修改用户 osdk 路径或锁文件。
