# 一、决策摘要

**建议继续当前 TypeScript/Fastify/SQLite/Vue + ACP 路线，下一阶段从“有材料、有角色、有页面”推进到两个可持续闭环：任何回答可追溯，现行知识会随来源更新，历史回答保留原版本并标明是否过期；任何交办事项都能从理解一直跟到提醒与完成。** Code Wiki、记忆、事项和学习属于同一证据系统上的不同视图与操作，不新建一个代码知识孤岛，也不把它们硬塞成同一种对象。

优先顺序：

1. 修正已出现的引用→原片段映射、AST调用归属、时间/版本与真实接线断点，建立冻结评测和本轮可复现基线
2. 在既有 RetrievalPort 上接混合召回、权限与时间过滤、重排及可解释查询计划；同时打通日常交办→时间解析→持久提醒→完成/取消闭环
3. 补齐 memory refresh_dependents，并将知识正文、长期记忆、事项和学习卡的更新依赖统一纳入可审计治理
4. 提升 AST 语义和增量 Code Wiki：先 TS/Vue，按真实需求再扩语言；保持文件/符号/文档互引及原始证据统一
5. 加入英语学习与间隔重复插件；Anki/SRS

不要先做的事情：不因旧设计提到 Python/React/PostgreSQL 就重写；不先堆 GraphRAG、向量库、图数据库和多Agent框架；不批量把每句话都变正式记忆；不让用户重新承担逐句质量标注；不把阅读弹窗的递归深度和检索/模型运算预算混为一谈。

“超强记忆”应以真实行为定义：同义与跨语言问法能找回，跨文档与代码能补齐必要证据，知道谁在什么时候说了什么，知道后来的更改取代什么，不把自己的总结当新证据，找不到时清楚说明缺什么。
