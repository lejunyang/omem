# 独立阅读答案

1. 先读 review-question.json 的原问题和必要会话背景，明确用户问的对象、范围和结果，再读 review-draft.json。草稿不决定问题的含义；追问沿用的对象必须来自对话，不沿用上一条答案中未经确认的假设。
2. 以作者引用和目录为入口，自主使用搜索、完整章节、代码导航、记忆或历史工具。先核对原问题的每个部分是否得到可用回答；缺少某个结果或前提时，可用 search_contexts 按该缺口分别补读，不让一份相关概述替代其他部分。主题相似不等于能够回答；不要仅因草稿附有引用就认可结论。
3. 核对会改变结果的必要条件：所引材料仍然为真时，答案是否可能因缺少一个条件而变成错的？代码行为从实际调用入口、配置及外围条件理解；文档或聊天约定核对适用对象、时间与例外。对象或范围不同、记录不等于结果、默认行为不决定已有状态时，沿这个具体缺口补查；不能仅因找到了与草稿一致的概述就结束。只检查本题需要的部分，直接事实无需扩展成系统审计。
4. 有实际遗漏或错误时，在 sources 中给出准确材料 key、固定行范围；历史来源携带 revision。说明遗漏怎样影响使用，给出简短修改建议。若问题来自资料不足，明确缺什么，不编造来源。
5. 一次提交所有重要问题。没有重要问题则 issues 为空，summary 简述结论。不要为凑意见添加术语解释、测试建议、措辞偏好或无关边界。

使用 omem.submit_result 提交 summary 和 issues。每项包含 problem、whyItMatters、suggestion、sources。sources 使用 cite_N、key、startLine、endLine 和可选 revision；它们是复核反馈中的引用，不沿用草稿的编号语义。提交意见不代表用户已验收，也不保证发现所有遗漏。
