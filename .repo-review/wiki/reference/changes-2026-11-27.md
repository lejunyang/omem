## 长任务的任务书、跟进报告和查询接口（2026-11-27）

从 `src/agents/supervisor.ts` 看一轮跟进怎样收到任务书、本人补充和跑偏信号。`src/agents/supervisor-report.ts` 把报告记入时间线并更新原进度卡。编码和工作 Agent 按同一预算派活和续轮，工作者待答的问题会保留到助手处理。

长任务在所在空间创建一条关注事项和一个工作会话。`src/agents/long-tasks.ts` 保留目标原文、确认后的任务书和带时间的本人补充。报告和进度文字写入本轮运行，决定、理由和下一步追加到跟进笔记，每轮在事项时间线上留一条记录。跨设备拉取保留这些记录，进行中的长任务在新设备上暂停。

`src/server/long-tasks-http.ts` 提供四个接口。列表和详情沿用事项阅读权限，修改要求调用者是发起人且仍有空间写权。

| 请求 | 输入与结果 |
| --- | --- |
| `GET /api/long-tasks` | 可传 `space`、`limit`、`offset`，返回 `tasks` 摘要列表。 |
| `GET /api/long-tasks/:id` | 返回任务书、原话补充、预算、笔记、事项时间线，以及最近报告和宿主统计的进度、用量。 |
| `POST /api/long-tasks` | `goal` 必填，可传 `space`、发起会话 `threadId`、`ai`、`budget`、`notifications`，返回新建的草案。 |
| `PATCH /api/long-tasks/:id` | `action` 取 `pause`、`resume`、`end`、`budget`、`ai` 或 `supplement`。后三项分别传 `budget`、`ai` 或 `text`。预算字段按新总额更新，可只给一项。 |

## 对话里开长任务、给助手补充要求（2026-11-27）

用 `/跟进 [AI] 任务` 或请主助手开工作话题，确认任务书后按进度跟进。在话题里查看状态、加时、换 AI、暂停、继续或结束，也可以请助手从另一会话按编号转达原话。见 [对话用法](../../../site/features/ask.md#跟进一件长任务)。

## 用后端别名或设备名换 AI（2026-11-27）

从 `src/agents/ai-spec.ts` 读起。命令与规则共用程序识别；后端配置的 `aliases` 可增加中文命令，保存组和后端设置时检查重名。同程序的本机登录优先，可按提示指定 key 或设备。

## 自定义后端按实际程序匹配规则（2026-11-27）

`src/agents/backend-names.ts` 统一识别本地、密钥和远端后端的程序。后端换了编号仍受同一条规则约束；没有给出型号时，只对 Codex、Claude、Gemini 和 Antigravity 采用已知的默认模型族。

## 运行入口按允许的组选择和接手（2026-11-27）

从 `src/agents/choose-ai.ts` 的 `chooseAI` 读起。新会话和后台运行先检查类别规则与成员账号，再把前三个可用组交给决策模型。组内按时段和可用情况选择后端。首选失败后沿用同一次判断的顺序，后续组保留设置中的先后。概率门槛和最小领先差距分别由 `ai.decision.thresholds.route` 和 `ai.decision.routeMinGap` 控制，默认 0.55 和 0.15。

## 一句话改 AI 规则（2026-11-27）

设置接口或对话将原话交给强组，宿主根据结构化草稿生成预览卡。列出的影响次数来自近七天的选型记录。只有本人点确认才更新配置；修改原话会重新起草，过期的预览需重新生成。实现见 `src/agents/ai-policy-proposal.ts`。

## 允许的组之间选 AI（2026-11-27）

`routeGroups` 接收规则筛过的组。首选概率达标且比第二名高至少 0.15 时采用模型顺序，对话最多等 8 秒，后台最多等 20 秒。每次判断在 `decisions` 保留运行编号、概率、门槛和实际顺序。决策报告接口和 `omem decision report` 按任务类别比较两种顺序的完成率。

## 在对话里指定一轮或整个话题的 AI（2026-11-27）

`src/agents/ai-spec.ts` 解析后端、组、模型和强度，`ai-command.ts` 按发令人的身份应用选择。带任务的命令独立排队。飞书话题可以在首条命令指定 AI，后续消息沿用。

## 按任务类别限定 AI 与接手范围（2026-11-27）

从 `src/agents/run-classes.ts` 看运行归类，从 `src/agents/ai-policy.ts` 看组的先后、可用时段、排除规则和严格等待。会话和后台运行沿用同一个范围。旧的三个档位与候选说明在加载配置时带入各组。设置接口按类别返回最近七天的选择次数。

## 卡片聚合复杂内容：清单、成对的值、收起的细节、图片；确认卡片带状态标签（2026-11-27）

- 组件块加 `list`（一条一行，标题前彩色短标签，可带链接和一行说明）、`fields`（成对的名字和值）、`fold`（收起的细节）、`image`（http(s) 图片；飞书里发卡片前宿主下载再上传，不取本机和链路本地地址，失败时是链接）。飞书用卡片自己的元素画（Markdown 里的 `<text_tag>`、`grey-50` 底的分栏、折叠面板），网页由 `packages/plugin-sdk/blocks.ts` 画，展示块里的 Markdown 改用卡片字号，块间距统一为 12px。
- 提问可带 `ui.head`（标题、副标题、状态标签）、`ui.body`（代替问题正文显示）、`ui.links`（要打开的页面）。流程阶段卡读出时由 `stageCardUi` 排：阶段名做标题、事项做副标题、状态做标签，要本人定的一节是 `callout`，长依据收起，流程页和讨论是一行链接（不再是和回答混在一起的按钮）。方案确认卡把决定列成带类型标签的清单。回答后保留标题，标签换成结果，原内容收进“当时的内容”。
- 有状态标签的飞书卡片头不着色（飞书设计规范：单聊用常规标题），颜色只在标签上；网页 `AskCard` 同样的头部，左边线跟着标签的语气。角色说明和 `owner` 说明页写了何时用这些块。
- 卡片的样子可以在飞书卡片搭建工具里看：导入 `{"name", "dsl", "variables"}` 格式的文件；搭建工具不显示折叠面板（docs/v2/lark-cards.md 第 5 节）。

## 交办调查的报告交回主助手；“先看一眼”卡片只发回复（2026-11-27）

- 主助手不开话题的 `run_agent`：子 Agent 的报告不再以“X 完成了……”原样发到会话（群里会看到整份调查过程），改为交回主助手。交办那一轮还在进行时等它结束；结束后在原会话给主助手一轮，按报告写回复，没有新东西就 `stay_quiet`。那一轮已经用 `read_run` 读过完成的报告时跳过。本人 `/as` 交办、Agent 互相唤醒的仍直接回会话。工具说明提示：这一轮就要结果用 `ask_agent`，不要 `run_agent` 后轮询。
- “先看一眼”卡片：“背景和依据”折叠在触发的消息下面，分隔线下是回复；整段的依据按句拆成一行一条。“发给大家”和直接发到群里的只有回复本身，依据只留在本人的卡片和运行里；角色说明要求 `text` 不写判断过程、`evidence` 分条。

## 流程卡片好读一些（2026-11-27）

- 开始关卡的卡片不再写“要你定的事：轮到这一段了，开始吗？”（标题已经是“等你确认开始”）；只有因连续自动推进到上限或要重做才停下时，多一段“为什么问你”。
- “现在”改成“前面”：每个上一段一行“名称（已完成）：第一句”，取它说明的第一段（`engine.ts` 的 `leadSentence`），不再按 120 字截断，也不再把它自己的“现在”“依据”小标题带进来。要本人确认做完的卡片，助手交的说明放在“结果”下。
- “建议的做法”在开始和本人阶段的卡片上改成“这一段做什么”：先一句谁来做，再写做法，最后一行“怎样算做完”（默认的“交了结果就算做完”不写），不再把谁做、怎样算完放进括号；“确认后接着”单独一段“接下来”。卡住的卡片仍叫“建议的做法”。
- 流程进展卡的“流程”从“A ✓ → **B 等你开始**”改成编号列表，每段写明状态（`store.ts` 的 `STATE_WORDS`）。

## API key 的后端经 omem 转发，按提供方错误码处理（2026-11-27）

- 第三方 key 生成的后端用 key 的模型：API key 页的“后端可用的模型”可添加多个（第一个是默认），不添加就用模型列表里适合这个后端的全部模型；通用页“检测模型”直接返回它们，默认模型不再是 OpenAI 的；每个模型的思考强度取自模型列表（方舟的 `effort.supported_levels`）。“检查”用一个模型名试调，被拒（方舟 `ModelIDAccessDisabled`）就把 key 记为只能用接入点，页面改为手填 `ep-…`，接入点调通后按回答里的模型名对到列表，取它的强度和格式。Codex 启动时带上列表里的上下文长度；Agent 附带请求点名它那家的模型（Codex 起标题用 `gpt-5.6-luna`）时，转发改成后端的默认模型；方舟默认地址不再被当成官方地址。运行时的模型在启动时给出（`config.ts` 的 `keyModelsFor`、`keyedModelEnv`），在通用页改默认模型只保存模型和强度，其余配置跟着 key。API key 页的“生成的后端”单独一块、一行一个，“看 N 个模型”改为“查看”。

- 设置 → 后端与模型 → API key 新增“火山方舟”一类（`ark`），和“OpenAI 兼容”分开：默认地址、Anthropic 格式地址按方舟的规则，认得方舟的错误码；以前按兼容接口加的方舟 key 那一行可点“改成火山方舟”。
- API key 生成的后端在服务运行时都经 omem 转发（`src/core/ai-relay.ts`，`/api/ai/relay/…`）：后端拿 omem 发的令牌，omem 换上 key 原样转发，回答以流的方式原样传回。错误按提供方码表分类（`src/core/ai-errors.ts`：方舟、OpenAI、Anthropic、Cloudflare，其他按状态码和字眼）：限流在转发处等几秒重试，仍限流就交还 429 并让这个 key 退后 1 分钟；每日用量、额度、欠费改成 400 交还，让 Agent 立刻停下，key 暂停到午夜或检查通过，额度和 key 被拒通知本人一次。运行失败时按转发看到的错误改写为 `rate-limit` / `quota`（`relayFailure`）。
- Codex 把提供方报错当回复交回（“exceeded retry limit, last status: 429”等）的回合现在算失败（`acp.ts` 的 `codexErrorReply`）；第三方的 Claude Code 只重试 3 次（`CLAUDE_CODE_MAX_RETRIES`）。
- 决策模型出错用同一套分类决定排到后面多久（以前一律 5 分钟），错误也记在 API key 页那一行。
