## 研究小结能读到方向编号（2026-11-27）

`read_ledger` 增加“方向”一节，默认列当轮和仍在做的方向，支持按方向 id 或轮次查询。每个方向附目标、验收、试验结果及未完成的计数，已结束的附结论首行。试验行带所属方向 id。小结传错 id 时，`close_direction` 在有权限的本研究内提示可结束的方向。两轮回归见 `test/studies.test.ts`。

## 研究的托管克隆跟随代码索引基线（2026-11-27）

托管克隆的方向基线和定方向材料的最近 20 条提交都按代码索引的基线引用读取。引用不可用时取本地 HEAD，在方向确认记录和缺方向基线的交办里写明。本人自己的检出取 HEAD。已有方向仍用确认时记下的提交。回归见 `test/study-workspace.test.ts`。

## 第三方 key 的模型显示名、多模态和完全接管（2026-11-27）

- 接入点 ID 只用来调用：API key 页、通用页模型下拉、运行记录和选型说明都显示它背后的模型名（`ai-keys.ts` 的 `modelDisplayName`，运行的 `ai.modelName`）。
- 模型列表的输入类型存为 `inputs`，页面标“能看图片、视频”或“只读文字”；只读文字的模型跑时环境说明让 Agent 遇到图片直接说看不了。
- 第三方 key 的 Codex 用数据目录 `agents/keyed/<后端>` 作 CODEX_HOME，关掉插件市场同步（github.com）、远程模型目录、统计和更新检查（chatgpt.com），出网白名单不再放 OpenAI 的地址；实测三种访问模式下只连 omem 转发。
- 第三方 key 的 Claude Code 也用自己的配置目录，WebFetch 不再先问 api.anthropic.com；落到 auto 模式时改用 default（auto 的检查在 Anthropic 服务器上，连不上会拒绝所有动作）。实测方舟上 Codex 的 web_search、Claude Code 的 WebSearch 和 WebFetch 都能用。
- API key 页每个 key 的说明从一行圆点连接改成“key / 地址 / 可用于 / 模型列表”的标签和值，长地址在自己的格子里换行。

## 流程卡片好读一些（2026-11-27）

- 开始关卡的卡片不再写“要你定的事：轮到这一段了，开始吗？”（标题已经是“等你确认开始”）；只有因连续自动推进到上限或要重做才停下时，多一段“为什么问你”。
- “现在”改成“前面”：每个上一段一行“名称（已完成）：第一句”，取它说明的第一段（`engine.ts` 的 `leadSentence`），不再按 120 字截断，也不再把它自己的“现在”“依据”小标题带进来。要本人确认做完的卡片，助手交的说明放在“结果”下。
- “建议的做法”在开始和本人阶段的卡片上改成“这一段做什么”：先一句谁来做，再写做法，最后一行“怎样算做完”（默认的“交了结果就算做完”不写），不再把谁做、怎样算完放进括号；“确认后接着”单独一段“接下来”。卡住的卡片仍叫“建议的做法”。
- 流程进展卡的“流程”从“A ✓ → **B 等你开始**”改成编号列表，每段写明状态（`store.ts` 的 `STATE_WORDS`）。

## API key 的后端经 omem 转发，按提供方错误码处理（2026-11-27）

- 第三方 key 生成的后端用 key 的模型：API key 页的“后端可用的模型”可添加多个（第一个是默认），不添加就用模型列表里适合这个后端的全部模型；通用页“检测模型”直接返回它们，默认模型不再是 OpenAI 的；每个模型的思考强度取自模型列表（方舟的 `effort.supported_levels`）。“检查”用一个模型名试调，被拒（方舟 `ModelIDAccessDisabled`）就把 key 记为只能用接入点，页面改为手填 `ep-…`，接入点调通后按回答里的模型名对到列表，取它的强度和格式。Codex 启动时带上列表里的上下文长度；Agent 附带请求点名它那家的模型（Codex 起标题用 `gpt-5.6-luna`）时，转发改成后端的默认模型；方舟默认地址不再被当成官方地址。运行时的模型在启动时给出（`config.ts` 的 `keyModelsFor`、`keyedModelEnv`），在通用页改默认模型只保存模型和强度，其余配置跟着 key。API key 页的“生成的后端”单独一块、一行一个，“看 N 个模型”改为“查看”。

- 设置 → 后端与模型 → API key 新增“火山方舟”一类（`ark`），和“OpenAI 兼容”分开：默认地址、Anthropic 格式地址按方舟的规则，认得方舟的错误码；以前按兼容接口加的方舟 key 那一行可点“改成火山方舟”。
- API key 生成的后端在服务运行时都经 omem 转发（`src/core/ai-relay.ts`，`/api/ai/relay/…`）：后端拿 omem 发的令牌，omem 换上 key 原样转发，回答以流的方式原样传回。错误按提供方码表分类（`src/core/ai-errors.ts`：方舟、OpenAI、Anthropic、Cloudflare，其他按状态码和字眼）：限流在转发处等几秒重试，仍限流就交还 429 并让这个 key 退后 1 分钟；每日用量、额度、欠费改成 400 交还，让 Agent 立刻停下，key 暂停到午夜或检查通过，额度和 key 被拒通知本人一次。运行失败时按转发看到的错误改写为 `rate-limit` / `quota`（`relayFailure`）。
- Codex 把提供方报错当回复交回（“exceeded retry limit, last status: 429”等）的回合现在算失败（`acp.ts` 的 `codexErrorReply`）；第三方的 Claude Code 只重试 3 次（`CLAUDE_CODE_MAX_RETRIES`）。
- 决策模型出错用同一套分类决定排到后面多久（以前一律 5 分钟），错误也记在 API key 页那一行。

## 第三方 API key 也能生成后端（2026-11-26）

- 设置 → 后端与模型 → API key：第三方（OpenAI 兼容，例如火山方舟）的 key 以前只能给语音、图片用，现在和 OpenAI / Anthropic 的 key 一样生成后端：Codex（ACP / 命令行）、OpenCode 走 OpenAI 格式，Claude Code 走 Anthropic 格式地址（检查时自动找，方舟是 `…/api/compatible`）。这一行多了“后端用的模型”（从账号列出的模型里选或手填接入点 ID）；检查时用它发一次 1 个 token 的请求，把服务的报错写出来。OpenAI 和 Anthropic 的 key 也能生成 OpenCode。
- Codex 0.169 已经不读 `OPENAI_BASE_URL`，改了地址的 OpenAI key 生成的 Codex 其实一直连官方地址；现在非官方地址都配成 Codex 自己的模型提供方（`config.ts` 的 `keyedProfiles`，key 放进 `keyVars` 列出的变量）。
- 模型列表存下每个模型支持的接口和用途（`ai-keys.ts` 的 `listModelEntries`），“看 N 个模型”可展开筛选。OpenAI 决策只列 `gpt-6-luna`（Decisions API 只接受它）；决策页去掉了各家接口的说明。
- 界面：key 显示成“key 尾号 xxxx”；页首说明（`HelpText lead`）和其他说明一样只占一行，其余放进 (i)；添加表单的两列不再挤在一起；设置等页面切换时滚动条位置一直留着（`.main` 的 `scrollbar-gutter: stable`），短页面和加载中不再左右跳。

## 长标题看得到全文（2026-11-26）

- 运行和对话的标题由消息开头生成，以前分别只留 60 字和 40 字、列表里再单行省略，看不到说的是什么。现在运行标题留 200 字、对话标题留 120 字（`src/core/util.ts` 的 `RUN_TITLE_MAX` / `CONVERSATION_TITLE_MAX`）；运行列表和对话列表最多两行，悬停看全；问答运行的详情页把这一轮的提问原文完整列出（接口 `context.question`，超长时折叠，可展开）。

## 运行记下用的是谁的 AI 账号（2026-11-26）

- 运行的 AI 记录（`runs.ai`）多了 `account`：谁的账号、登录名、是不是借的、为什么选它（`src/agents/run-account.ts`）。以前只有后端、模型和强度，成员借本人登录还是用自己的、本人用的是哪个账号，只能翻活动记录里的一行状态。运行页头部、列表悬停和交办页头部显示。本机登录的账号名取设置页最近一次“检查”的结果，存进 kv 后重启不丢。

## 续聊也避让额度快用完的后端（2026-11-26）

- 没指定 AI 的对话每轮开始前看缓存；有可用替代时才避让，不重跑任务选型，不影响手动指定。Antigravity 把额度用完当回复文字返回时，宿主识别告警，按倒计时记下恢复时间，并换兜底后端处理这一轮。

## 流程收口通知是进展卡，依据能点开（2026-11-26）

- 对账收口（“已收口：…”）的通知原来没标成流程视图，替换流程进展卡后变成了事项待办卡：带“已处理 / 忽略”，而且通知不带 `sourceRefs`，依据里的 `src:` 引用被换成纯文字“看原文”。现在按流程进展卡发（`view: "flow"`，绿色）。
- 通知卡片解析引用时带上发通知的运行：没有外部地址的原文（工作文件、运行记录）按那次运行读过的部分做只读分享链接，不再只剩标签（`src/channels/item-notification.ts`）。

## 规则和关注改动的通知按设置项写（2026-11-26）

- 助手改规则或关注后的通知按设置项写：规则的动作按步拆开（“第 1 步的任务”），短的值写前后值，长文字只写哪一项删加改写了几段；以前把整串 `actions` 的 JSON 和长说明各截前 50 字，前后两半开头一样、看不出改了什么。完整对照页同样按步列出。

## 先看一眼没事就不出声（2026-11-26）

- `first_look_outcome` 多一种结果 `quiet`：进退群、例行提醒、别人已经答了的确认这类不用回、本人也不用知道的，宿主不发卡片、不起深查，处理记录记 `ignored`，关注里这几条从这一批拿走并在会话里留一句。以前“不用回”只能当 `answered` 交，结论写着“无需回复”的卡片照样发给本人。
- 群里只有本人看得到的卡片点了按钮后换上的新卡片（以及慢回调后补发的更新）保留顶部的 @，以前只有第一次发出时有。

## 编码轮重跑保留未提交改动（2026-11-26）

- 同一轮中断后重跑，未提交的改动原样留给编码 Agent，不再记为用户的修改。上一轮正常结束后，新一轮首次编码前仍按原规则记录；分支上的已有提交照常识别。

## 事项跟进自动找会话（2026-11-26）

- 组批前从本人可读的近三天飞书聊天找候选。标题、材料标识、重合参与者用于排序，决策模型确认后挂上。入列依据记在时间线，只有判定为新变化的历史行交给下一批；原线索没变时，未通过或出错的候选七天内不重复判断。
- 助手挂的聊天连续五批没有变化和线索就放下，保留材料，同步关注群列表。新线索能触发重新判断；主动移除记住取舍。无关批次不占日额度，临近阶段计划或事项截止时当天额度放宽一倍。自动验收见 `test/item-follow-places.test.ts`。
- 判断候选会话时给决策模型看“为什么是候选”和这个会话近七天最后几条消息（含机器人的卡片：经机器人协作的群内容大多是卡片），不只是命中线索的那几行；问法改成“是不是在谈这件事的会话（为它建的群，或最近在讨论它）”。按旧问法判过不相关的会话重判一次（`clues.v`）。

## 已连接飞书的成员按功能补授权（2026-11-26）

- `lark_read` 读电子表格或多维表格缺少该功能的 scope 时，授权卡预勾「表格与多维表格」。点开可一次申请七项读取权限。文档与知识库、消息、日程、妙记与会议同样用账号页已有的功能。若飞书同时报出旧权限和功能内的细分权限，选用细分权限。
- 授权回来后，原会话拿到实际缺的 scope 就能继续。该项权限已授予而飞书仍拒绝时，提示核对资源访问权限。功能表未覆盖的权限仍按原名申请。假飞书与 CLI 的回归覆盖授权链接、OAuth 请求、会话续跑和重复通知，见 `test/connections.test.ts`。

## 本人自己推了分支，编码一段不再等“评审通过”（2026-11-26）

- 跟着编码交办的阶段重开后，交办被本人推送或应用而结束（`ended`，含在 omem 外推送）就算这一段做完：不再因为最后一轮没有“评审通过”的结论一直卡住（按轮数预算暂停的一轮本来就没有结论）。本人要求过、没人做也没说明不做的修改项仍然拦着（`src/flows/code-rework.ts`、`objects.ts`）。
- 工作线页的“更新”先重查这条线上各流程跟着的对象和信号（`advanceFlowNow`，不用模型），再排整理现状的运行；以前只整理现状，阶段状态不会动。
- 事项的关注页“处理记录”列出这件事（含下面各项）的事项跟进和接手运行，各写记了几条变化、并进流程几条、做了什么；“在聊什么”没有总结时显示工作线的现状。以前只列关注自己会话里的批次，有流程的事项由事项跟进在读，页面一直是空的（`src/channels/listen-http.ts` 的 `handlingOf`）。
- 改名前开始的持续跟进，后续运行沿用了旧的发起人名字，运行页还在显示和按它筛选：一次性把这些运行和会话消息上的名字改成“持续跟进”（`SITUATION_SPEAKER_MIGRATION`）。
- “推送”一段的信号检查认得在 omem 外推送而结束的交办：没有 `appliedTo` 时按结束时记下的远端提交（`pushed`）核对，不再报“还没应用到仓库”（`src/flows/signals.ts`）。

## 插件页只摆要本人决定的事（2026-11-26）

- 设置 → 插件的卡片正面只留图标、名字、一句说明、来源小标签（内置 / 开发中 / npm · 版本）、启用开关和一行计数（“页面 · 2 个档案 · 9 个工具 · 1 个回调”）。等信任、代码改过、回调还没有密钥、最近一次投递失败、MCP 还要填值放在一块暖色提示里，带按钮。
- 工具只在“详情”里列一次并标出会写入的；它的 Agent 还能用的宿主工具、权限、档案、技能、规则、流程、目录（链接的插件以前在标题行和正文各显示一次）和运行方式也在详情里。
- 回调是详情里的一小块：名字、地址和复制、密钥状态、生成或重新生成（先确认旧密钥失效）、最近投递（结果和失败原因，可刷新），技术参数收进“接入说明”。地址以前用页面自己的 `location.origin` 拼，经别的设备转发打开时会拼出回环地址；现在 `GET /api/plugins` 的 `hooks[].url` 和生成密钥的应答按 `webUrl` 给出，没配置时才用页面地址，是回环地址时提示外部访问不到。`hooks[].lastDelivery` 给卡片判断最近一次投递是否失败（`src/plugins/hooks.ts`，`src/core/util.ts` 的 `webBase`）。
- 回调没收下的请求（密钥不对、太频繁、不符合约定）留最近一次的时间、状态码和次数（内存里，`noteHookRefused`，`GET /api/plugins/:id/hooks/:name/refused`），回调块在投递列表下显示，分得清“没发到”和“到了被拒”。

## 评审只报用户走得到的问题（2026-11-26）

- 一次按修改项推进的交办里，业务、架构、历史评审项接连提出“页面内切换账号后旧请求覆盖新账号”“权限查询偶发失败要加重试入口”“白名单外的用户用不了某个子功能”，评审负责人都接受了。这三条的前提用户都走不到：换账号要回列表页重新进入，失败后用户会刷新，白名单外的用户根本没有可选的数据。依据是代码注释和一条被泛化的旧记忆。
- “只报实际用法会发生的问题”原来只写在 `roles/reviewer.md` 里，别的评审项拿不到。现在挪到 `roles/_common.md` 的“什么算评审问题”，按 `submit_review` 发给每个评审项：触发前提要写清用户怎么走到，只凭监听、注释或参数不算；刷新就能恢复的偶发失败不报；记忆和以前的评审结论只是线索，场景不同不照搬。`reviewer.md` 里重复的那句删掉。
- `roles/review-lead.md`：`accept` 前先核对触发前提用户走得到；要求补恢复手段的问题（重试入口、失败和无权限分开、页面里换上下文后丢弃旧请求的结果）默认 `defer`，除非需求要求或不补会丢内容、写错数据。

## 本人的阶段不用回来点完成（2026-11-26）

- 普通本人阶段只进入合并的事项进展通知，网页保留完成、跳过和说明。旧卡和显式确认仍能答，信号或对象继续走原有核对。
- 关联群、对象和本人的新话可能触发定向复核。有计划时间到点也查，沿用退避和每日上限；凭可复核依据直接完成，确实查不到且明显超期才在进展问一次。
- `needs` 对 `skipped` 递归检查前提；旧规则提前打开且没人动过的阶段收回、撤卡并指出还缺哪个上游。

## 流程卡住时先让助手处理（2026-11-25）

- 阶段关卡、阻塞和对账下一步用同一份卡片数据，网页和飞书都显示现状、卡点、做法和依据；按钮与文字走同一答复路径。旧卡仍能按原按钮回答。
- 对账区分等外部恢复、原助手能做和只有本人能做。外部等待复用巡检，以至少 15、30、60 分钟退避，三次失败才问；原助手能做的带指示重开，进展通知写清安排。只有本人能做时说明为什么。
- 网页上没有待答卡片的卡住阶段（助手承担的）多一个“让助手接着做”：带着卡片上建议的做法和本人写的话重做这一段（`FlowWaiting.vue`）。

## 插件可以自定事件受理应答（2026-11-26）

- 异步回调先落库，可由同步 `accept` 返回状态码、头和正文。首次投递只有 2xx 才排队；插件拒绝、抛错或超时均不排队。暂时写不了库回 503。
