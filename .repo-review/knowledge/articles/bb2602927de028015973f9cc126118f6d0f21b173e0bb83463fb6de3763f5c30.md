# docs-validation.md · 模块理解

该文档保存首轮设计与离线原型的验证边界，记录执行流程、浏览器覆盖及未验证事项。阅读时应结合当前实施状态：早期“真实模型与服务端尚未部署”已被替代，但外部集成、兼容性、长期性能等仍需逐项确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-background"></a>
## 职责与历史背景

`docs/validation.md` 的职责是记录 2026-09-26 对架构材料与离线交互原型的首轮验证，而非当前 Vue、API、SQLite 产品的完整验收报告；原文也明确要求以实施状态记录当前能力。[首轮验证范围声明 ↗](../../../docs/validation.md#L1 "支持该文档属于第一轮架构与原型验证、不能代表当前运行代码的历史定位。") 当时的流程包括读取需求材料、核验上游仓库、构建自包含 React 原型，以及执行 Chromium 多视口测试、人工视觉检查和静态一致性检查。[首轮执行流程 ↗](../../../docs/validation.md#L7 "支持材料核验、原型构建、浏览器测试、人工视觉检查和静态一致性检查的流程概括。") 因此，它主要提供早期设计与交互方案的可追溯验证基线。

<a id="coverage-and-boundary"></a>
## 验证流程与证据边界

浏览器覆盖集中于阅读交互，包括 8 层与 100 层引用链、循环跳回、历史版本不重定向、弹窗追问、滚动与焦点恢复、权限异常、搜索、模拟同步及手机布局。[离线原型浏览器覆盖 ↗](../../../docs/validation.md#L16 "支持多层引用、循环、追问、焦点恢复、异常状态、搜索和多视口等具体覆盖范围。") 文档同时排除了真实引用准确率、中文召回、幻觉率、真实连接器、团队 ACL、灾备、完整无障碍审计、Safari/Firefox 兼容和长期路径性能等事项，并强调“字段存在”或原型“可点击”不能证明生产能力。[首轮明确未验证范围 ↗](../../../docs/validation.md#L45 "支持真实质量、外部集成、团队能力、兼容性和长期性能等结论不可由原型外推。")

<a id="relations-and-current-status"></a>
## 与当前实现的关系、进展和限制

早期“真实模型与服务端尚未部署”的结论已经被后续进展替代：当前记录显示完整检查、真实 Vue/API/SQLite 浏览器流程、隔离数据库重建及六份真实模型模块说明均已完成。[后续复审验证进展 ↗](../../../docs/implementation/status.md#L7 "支持完整检查、真实浏览器流程、隔离数据库重建和限定范围真实模型生成已经完成，替代早期未部署结论。") 但这里的限制应精确理解为：这六份模型说明本身尚不等于独立语义核验，且 Code Wiki 的跨文件调用、embedding 和下游重核验仍未交付；不能据此推断整个系统没有独立复核。[模型说明与代码知识边界 ↗](../../../docs/implementation/status.md#L12 "限定未核验的是六份真实模型结果，并列出跨文件调用、embedding、统一代码角色 worker 和下游重核验的具体缺口。") 通用 `KnowledgePipeline` 已使用独立会话复核正文，未通过内容不会发布。[通用知识分析与独立复核 ↗](../../../docs/implementation/knowledge-pipeline.md#L23 "证明通用 KnowledgePipeline 已使用独立会话复核，避免把局部模型说明未核验误写为整个系统没有独立复核。")

个人知识与仓库知识还共用证据阅读组件，并已通过真实浏览器验证多层引用、深链、焦点恢复及多视口行为。[共用证据阅读验收 ↗](../../../docs/implementation/knowledge-pipeline.md#L45 "支持个人知识与仓库知识共用阅读组件，以及多层引用、深链、焦点和多视口已由真实浏览器流程验证。") 仍有原文明确支持的缺口包括 `refresh_dependents` 尚未执行完整 extractor/verifier 重跑、G20 仅以同库新 runtime 模拟而未做真实进程 kill/restart，以及 Code Wiki 无 embedding、跨文件 calls 和跨 revision 身份续接。[当前仍有依据的实现缺口 ↗](../../../docs/implementation/status.md#L90 "支持自动重核验、真实进程重启、跨文件调用、跨版本身份续接和语义检索仍存在明确限制，同时避开已过时的无 traecli 前提。") 至于真实 ACP 主助手和飞书 WebSocket 的当前 live 状态，材料内部同时存在“旧环境记录已过时”和较早未验证结论，不能据此确定现状。[当前环境声明与旧记录冲突 ↗](../../../docs/implementation/status.md#L3 "材料明确说明较早的无 traecli和无模型 live记录已经过时，因此真实 ACP 主助手及飞书链路现状不能继续仅据旧前提断言。")
