# 飞书应用注册与能力核验

封装飞书应用设备注册并维持同一设备码下的有限网络重试；通过 OpenAPI 核对权限、回调和机器人身份，同时把事件订阅留给运行时投递验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="registration"></a>
## 设备注册与有限重试

注册适配器把内部创建模式、既有应用 ID、预设及附加能力映射给飞书 SDK，并将二维码和轮询状态转换为稳定回调。为避免一次临时网络故障终止设备码流程，它只拦截注册路径上的 5xx 与指定传输错误，沿用原请求和同一 device code 做指数退避；取消信号、非目标接口、非瞬时错误或超过次数的请求会直接拒绝。[注册轮询重试与 SDK 映射 ↗](../../../apps/server/src/integrations/lark/registration.ts#L29 "支持注册参数转换、二维码和状态回调，以及仅对目标注册请求的瞬时失败进行有限重试。")

<a id="capability"></a>
## 能力探测与封闭失败

能力探测先从固定的 `open.feishu.cn` 获取 tenant access token，再并行查询机器人和应用信息，整理实际 scopes、callbacks 与 bot open ID，并与请求配置比较。公共应用接口不暴露事件订阅列表，因此 events 保持为空，事件能力必须由配对期间真实收到的 WebSocket 投递补证。[OpenAPI 能力探测 ↗](../../../apps/server/src/integrations/lark/registration.ts#L135 "支持 token 获取、应用与机器人信息查询、缺失权限比较，以及事件订阅只能由运行时投递验证的边界。")

若调用方没有配置真实探针，拒绝型实现返回明确缺失项，不会把请求中的 addons 当成已生效能力。[未配置探针时拒绝激活 ↗](../../../apps/server/src/integrations/lark/registration.ts#L225 "支持缺少真实能力探针时返回封闭失败结果，而非信任请求配置。") 实时消息处理确实会从当前连接版本的 capability profile 读取 botOpenId 以过滤机器人自发消息，但所给材料没有展示探测结果写入该字段的持久化链路；因此不再断言二者已经确定接通。[实时路由读取机器人身份 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L503 "说明实时消息处理会读取 capability profile 中的 botOpenId，但该片段本身不能证明探测结果如何写入该字段。")
