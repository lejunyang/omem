# Lark 应用注册与能力核验适配

该模块封装飞书/Lark 官方应用注册 SDK，为设备码轮询补充瞬时故障重试，并通过真实 OpenAPI 查询应用权限、回调和机器人身份。公开接口无法确认事件订阅，因此事件仍需在配对期间通过 WebSocket 投递核验；未配置真实探针时，拒绝型实现会返回用于失败关闭的缺项结果，但是否阻止激活取决于上层调用方。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-contracts"></a>
## 职责与输入合同

模块把上层配置合同转换为官方注册 SDK 所需的请求：输入包含创建模式、可选应用标识、配置、取消信号，以及二维码和状态回调；输出统一为客户端凭据与可选用户信息。配置类型直接从共享合同的 Zod schema 推导，因此此处复用公共输入模型，而未另建配置定义。[注册请求与共享配置类型 ↗](../../../apps/server/src/integrations/lark/registration.ts#L3 "支持注册适配器的输入、回调和返回合同，并说明配置类型由共享合同 schema 推导。")

这一适配边界使调用方不必直接处理 SDK 的字段命名和回调形状，同时保留 `AbortSignal`，以便外部取消可能持续轮询的注册过程。

<a id="registration-flow"></a>
## 注册流程与故障恢复

正式适配器调用官方 `registerApp`，逐项传递 source、preset、addons 与取消信号；二维码回调把 SDK 的 `expireIn` 映射为内部的 `expiresInSeconds`，代码本身没有执行单位换算。注册结果中的客户端凭据和用户信息也会转换为内部命名。[官方注册 SDK 字段映射 ↗](../../../apps/server/src/integrations/lark/registration.ts#L73 "支持注册参数和回调的转发、二维码有效期字段映射，以及凭据字段向内部命名的转换。")

构造适配器时会全局安装一次响应拦截器。它只重试注册路径上的 HTTP 5xx 或列明的网络错误，并复用原请求以维持同一个设备码；退避从 500 毫秒指数增长，最高 4 秒。请求已取消、达到重试上限、路径不匹配或错误不可重试时，原错误继续向上抛出。[注册轮询重试拦截器 ↗](../../../apps/server/src/integrations/lark/registration.ts#L29 "支持重试适用路径、可重试错误、终止条件、退避上限、原请求复用和全局单次安装等边界。") 模块级安装标志意味着多个适配器实例共享这套重试策略。

<a id="capability-probe"></a>
## 真实能力探针流程

能力探针先用应用凭据换取 tenant access token；HTTP 状态、业务码或令牌任一不符合预期，都会抛出带阶段标识的错误。取得令牌后，探针并行查询机器人信息与应用详情，任一查询失败都不会返回部分成功结果。[令牌获取与并行能力查询 ↗](../../../apps/server/src/integrations/lark/registration.ts#L141 "说明探针先鉴权，再并行获取机器人和应用信息，并在各阶段失败时抛出明确错误。")

应用响应中的权限和回调可能采用多种字段形状，探针会抽取字符串、去重并排序，再合并租户与用户所需权限，与实际权限及回调逐项比较，生成稳定排序的 `missing`；结果还包含机器人 open ID 和修复提示。[权限、回调与缺项计算 ↗](../../../apps/server/src/integrations/lark/registration.ts#L187 "支持响应字段抽取、去重排序、必需权限合并、缺项比较、机器人身份和修复提示的生成。") 响应体采用宽松类型读取，可兼容部分字段差异，但字段漂移主要通过运行时错误或缺项暴露，未见独立的结构化响应校验。

<a id="limits-relations"></a>
## 验证边界与安全降级

公开应用接口不能列出事件订阅，因此 OpenAPI 探针把 `actual.events` 留空，并以 `eventVerification: "runtime"` 标记事件需要在运行时核验；注释说明，配对所需事件应由首次匹配的 WebSocket 投递确认。[事件订阅的运行时核验边界 ↗](../../../apps/server/src/integrations/lark/registration.ts#L135 "说明公开应用接口不暴露事件列表，运行时标记表示事件仍需通过配对期间首次匹配的 WebSocket 投递核验，而非核验已经完成。") 这不表示核验已经完成：即使权限和回调没有缺项，也不能据此证明事件订阅已经验证成功；本文件同样没有记录匹配投递、验证状态保存、超时或失败处理。

`LarkCapabilityProbe` 是上层装配能力检查的接口。没有真实探针时，拒绝型实现返回空的实际能力、`live_capability_probe_not_configured` 缺项及配置提示，为上层采取失败关闭策略提供明确信号，并表达拒绝直接信任请求中 addons 的设计意图。[未配置真实探针时的缺项结果 ↗](../../../apps/server/src/integrations/lark/registration.ts#L225 "支持拒绝型探针返回明确缺项和修复提示，并表达不直接信任请求能力的失败关闭意图；实际激活门禁仍取决于未提供的上层调用方。") 但材料没有展示激活调用方，无法确认该缺项是否必然中止激活或阻止状态变更。
