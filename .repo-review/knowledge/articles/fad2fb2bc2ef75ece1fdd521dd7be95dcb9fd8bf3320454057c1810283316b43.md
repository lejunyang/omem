# 研究背景与技术选型

研究以固定版本证据、本地隐私和可替换检索为边界，对代码知识组件及外部记忆工具进行可追溯选型；当前成果限于环境与源码核验、许可证消歧、方案取舍和 PoC 设计，不代表已经完成集成或形成生产能力。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="research-basis"></a>
## 研究边界与核验方法

代码知识研究受现有实现约束：材料按不可变 revision 切片并以固定 fragment 锚定引用，检索仍是 SQLite 关键词方案，跨 revision 身份续接和语义检索尚未实现；代码与文档关系只有人工登记后才能成为 confirmed。[代码知识处理的当前约束 ↗](../../../docs/research/code-wiki-landscape.md#L5 "支持固定版本与片段引用、关键词检索现状、跨版本身份缺口及人工关系治理边界。") 上游调查采用固定提交下的 README、许可证和部分接口源码，且明确没有运行 benchmark。[上游源码核验方法 ↗](../../../docs/research/sources.json#L1 "支持调查使用提交元数据、不可变 README 与许可证及部分接口源码，并明确未执行运行时 benchmark。") 具体仓库条目另存检查文件的 SHA-256 与固定 URL，从而支持输入复核和内容漂移检查。[固定源码文件与内容摘要记录 ↗](../../../docs/research/sources.json#L49 "以 WeKnora 条目证明具体检查文件绑定固定提交 URL 和 SHA-256，并包含处理器、路由及类型源码。") 对平台标为 `NOASSERTION` 的项目另读许可证正文完成消歧，不能据此断言项目闭源。[许可证消歧原则 ↗](../../../docs/research/source-index.md#L25 "支持对 NOASSERTION 项目补读许可证正文，以及不依据 star 数或供应商 benchmark 选型。")

<a id="selection-and-shape"></a>
## 组件取舍与检索投影

代码知识方向倾向借鉴 SCIP 快照模型、Tree-sitter 结构解析、repo-map 图排序及本地 embedding，而不整体引入自带数据库、UI 和模型编排的平台。[代码知识组件与平台取舍 ↗](../../../docs/research/code-wiki-landscape.md#L13 "支持借鉴 SCIP、Tree-sitter、repo-map 和本地 embedding，同时避免整体引入完整平台的研究结论。") 外部工具边界也不同：MemPalace 的检索路径不要求生成式 LLM，Hindsight 的事实提取需要 LLM 端点，WeKnora 则是部署较重的完整平台。[三类外部工具的能力边界 ↗](../../../docs/research/integration-readiness.md#L18 "支持 WeKnora、Hindsight 与 MemPalace 在模型需求、固定片段适配和部署形态上的差异。") MemPalace 高层接口缺少任意外部身份字段，同文不同源可能误合并；建议用 sidecar 保存可重建投影，搜索后仍由 omem 回查固定原件、有效性与范围。[MemPalace 固定证据身份障碍 ↗](../../../docs/research/mempalace/README.md#L67 "解释高层接口缺少外部身份字段、正文去重可能误合并不同来源，以及需要专门身份验收的原因。")[薄适配器投影与原件回查 ↗](../../../docs/research/mempalace/README.md#L77 "支持将 MemPalace 作为可重建 sidecar、返回候选后由 omem 回查原件，并保留关键词降级与 generation 回退。")

<a id="verified-progress"></a>
## 现有成果与被替代结论

目前完成的是只读环境核验、固定源码快照、许可证消歧和上游已保存指标的重新聚合。环境核验确认 Docker 是“未安装”，替代旧报告的“permission-denied”结论；同时未安装软件、未下载权重或修改项目配置。[只读环境核验与 Docker 更正 ↗](../../../docs/research/integration-readiness.md#L1 "支持只读核验范围、未发生安装或配置变更，并以“未安装”替代旧的 Docker permission-denied 结论。") 指标审计只复算既有 metrics，不会重跑检索或验证金标准。[指标重聚合的可信边界 ↗](../../../docs/research/mempalace/audit_artifacts.py#L1 "说明脚本只重新聚合上游保存指标，不重跑检索或验证金标准。") 其哈希不符会显式失败，但划分、重复问题 ID 和 held-out 集合一致性依赖 Python `assert`，关闭断言后不能视为稳定保证。[审计约束与失败机制 ↗](../../../docs/research/mempalace/audit_artifacts.py#L40 "支持哈希采用显式异常，而划分、重复 ID 和 held-out 一致性依赖 assert 的限制。")

<a id="poc-gates"></a>
## 后续验证门与未实现项

代码索引仍须依次验证 TS/Vue 符号抽取、SCIP 风格双向回链、跨版本续接、本地 embedding 和 PageRank 上下文；其中 P1–P3 不依赖 embedding，可独立推进。[代码索引分阶段验证门 ↗](../../../docs/research/code-wiki-landscape.md#L281 "支持五项 PoC 的执行顺序、验收要求以及 P1–P3 不依赖 embedding 的关系。") MemPalace PoC 则须保证候选可回查固定片段、同文不同源不误合并、预热后离线无外部请求、索引可重建，并在冻结中文语料上与关键词基线同口径比较。[本地检索 PoC 的采用条件 ↗](../../../docs/research/mempalace/README.md#L92 "支持证据回查、更新过滤、离线运行、可重建运维及同口径基线比较等采用门。") 启动该 PoC 还需用户授权修改项目配置、安装 Python 依赖和下载权重，并决定 embedding 取向。[MemPalace PoC 授权与模型决策 ↗](../../../docs/research/integration-readiness.md#L111 "直接支持启动 PoC 前需要授权修改配置、安装依赖、下载权重，并选择 embedding 方向。") 在这些验证门通过前，上游指标不能写成 omem 服务指标，研究建议也不能表述为已实现能力。
