# 实时语义检索冒烟验证脚本

该脚本在临时 SQLite 数据库中写入四类中文材料，显式完成语义索引，再以自然语言问题验证融合检索的首位命中、语义路由和可见性过滤，最后输出可留档的运行报告并清理资源。它属于真实模型与存储链路的集成冒烟检查，但不覆盖后台自动追索引、异常降级、并发和长文本分窗等行为。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-setup"></a>
## 验证目标与隔离环境

脚本解决的是“中文 embedding、持久化捕获与语义检索能否真实串通”的验证问题，而非用固定向量替身证明接口可调用。它创建临时目录和 `Store`，把数据库交给 `SemanticRetrieval`，模型则通过 `loadChineseEmbedding` 延迟加载；这些依赖关系均由脚本的直接导入和实例化体现。[冒烟脚本的依赖与初始化 ↗](../../../scripts/live-retrieval-smoke.ts#L1 "支持脚本直接创建临时 Store、语义检索器并加载中文 embedding 的论断。") `Store` 构造时会建立 SQLite 文件、执行迁移并初始化仓储组件，因此每次运行都有隔离且结构完整的数据环境。[Store 的 SQLite 初始化 ↗](../../../apps/server/src/store.ts#L38 "说明临时 Store 会创建数据库、迁移结构并初始化相关仓储组件。")

<a id="capture-index-search"></a>
## 捕获、建索引与检索断言

四个用例覆盖就医、故障处理、语言学习和报销等中文语义差异。脚本先用捕获合同校验手工文本输入，保存每条首个 fragment 的固定 ID，再循环调用 `indexBatch`，直到没有待处理项。[中文语义检索测试用例与捕获 ↗](../../../scripts/live-retrieval-smoke.ts#L11 "支持四类中文材料经 captureSchema 校验后写入并循环完成索引的流程。") 语义索引实现按当前 head 查找缺少指定模型向量的 fragment，并将标题与文本窗口批量送入 passage embedding；因此这里验证的是实际数据库追索引链路。[语义索引批次实现 ↗](../../../apps/server/src/retrieval/semantic.ts#L45 "解释 indexBatch 如何选择未索引的当前 fragment、分窗并生成 passage 向量。") 随后同时执行词法检索和异步融合检索，但硬断言只要求异步结果 Top 1 对应预期 fragment，且命中路由包含 `semantic`；词法是否正确仅记录到报告。[Top 1 与语义路由断言 ↗](../../../scripts/live-retrieval-smoke.ts#L21 "支持异步检索首位命中和 semantic 路由是硬断言，而词法正确性仅被记录。")

<a id="boundaries-and-evidence"></a>
## 可见性、模型约束与未覆盖边界

脚本额外传入 `visible` 谓词排除首个用例，并断言所有返回项都不含该 fragment，从行为上覆盖检索后的可见性约束。成功时写入验证 JSON 并打印报告；无论断言或索引是否失败，`finally` 都会关闭检索器、数据库并删除临时目录。[可见性过滤、报告与清理 ↗](../../../scripts/live-retrieval-smoke.ts#L30 "支持排除指定 fragment、生成验证报告及 finally 清理资源的行为说明。") 模型加载路径还会核对锁定仓库、revision 和文件哈希，禁止远程模型，并以中文 query 指令区分 query 与 passage；所以测试依赖本机已有且完整的 osdk 模型快照。[锁定的本地中文 embedding ↗](../../../apps/server/src/retrieval/embedding.ts#L17 "说明模型快照校验、禁止远程下载、查询指令和资源释放等运行约束。") 该文件没有断言后台 `start()` 的重试与降级状态，也没有覆盖空库、模型损坏、批次不匹配、长文本分窗、并发索引或排序并列。

<a id="module-relations"></a>
## 与其他模块的关系

从可见源码可以确认，脚本直接连接捕获合同、`Store`、embedding 加载器和 `SemanticRetrieval`，形成“输入校验→持久化→向量索引→查询→报告”的端到端检查。文本 part 合同要求非空且限制最大长度，为四条测试材料提供输入边界。[文本捕获 part 合同 ↗](../../../packages/contracts/src/index.ts#L20 "支持测试输入的文本部分必须非空且受长度上限约束。") 但材料没有展示 `Store.capture`、异步搜索融合排序及报告消费方的实现，因此不能仅凭这些片段确定 revision/fragment 的具体生成规则、词法与语义的融合权重，或该报告是否被持续集成自动读取。
