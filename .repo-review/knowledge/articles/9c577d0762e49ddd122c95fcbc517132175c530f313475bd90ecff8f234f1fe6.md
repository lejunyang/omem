# 中文语义检索现场冒烟验证

该脚本以临时 SQLite 和真实中文向量模型验证捕获、索引、异步语义检索、可见性过滤与报告落盘。先前“异步混合检索”的结论被替代：现有固定材料只证明脚本分别执行关键词检索与异步检索，并要求后者的首条结果经过 semantic 路由。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-setup"></a>
## 验证目标与真实依赖

脚本创建临时 `Store`，并通过 `loadChineseEmbedding` 构造 `SemanticRetrieval`，因此覆盖实际存储、模型加载和检索组件，而非测试替身。[冒烟脚本的真实组件初始化 ↗](../../../scripts/live-retrieval-smoke.ts#L1 "支持脚本使用临时 Store、中文 embedding loader 与 SemanticRetrieval 组成真实运行链路。") `Store` 初始化 SQLite、执行迁移并限制数据文件权限，使冒烟从完整存储基础启动。[Store 数据库初始化 ↗](../../../apps/server/src/store.ts#L36 "支持临时存储会创建 SQLite、执行迁移并设置本地文件权限。") 中文 embedding 还必须匹配锁定的 BGE 快照及文件校验和，且运行时关闭远程模型和文件缓存，可暴露模型未同步或快照损坏等环境问题。[中文向量模型快照校验 ↗](../../../apps/server/src/retrieval/embedding.ts#L14 "支持模型仓库与 revision 锁定、文件校验和验证以及禁止隐式联网加载。")

<a id="capture-index-search"></a>
## 捕获、建索引与查询流程

脚本准备诊疗、故障处理、语言学习和报销四类中文材料，经共享 `captureSchema` 校验后捕获，并保存各自首个 fragment 标识。[中文案例捕获与固定标识 ↗](../../../scripts/live-retrieval-smoke.ts#L11 "支持四类中文材料经 captureSchema 保存并记录预期 fragment 标识。") 文本 part 合同要求内容非空并限制长度，因此无效输入会在入库前被拒绝。[文本捕获合同 ↗](../../../packages/contracts/src/index.ts#L5 "支持文本 part 的非空、长度及可选来源信息约束。") 随后脚本反复执行 `indexBatch()`；索引器选择当前 head 中尚未按当前模型建索引的原始 fragment，按重叠窗口分批生成向量并检查批量数量一致。[语义索引批处理 ↗](../../../apps/server/src/retrieval/semantic.ts#L45 "支持当前 head 选择、重叠窗口、向量分批生成和输出数量检查。")

<a id="assertions-and-limits"></a>
## 断言、报告与覆盖边界

脚本分别调用同步关键词检索和异步检索，但只断言异步结果 top-1 命中预期 fragment，且路由包含 `semantic`；关键词是否命中仅写入报告。[关键词记录与语义结果断言 ↗](../../../scripts/live-retrieval-smoke.ts#L21 "支持同步关键词结果只进入报告，而异步结果必须 top-1 命中并包含 semantic 路由；也说明材料不足以断言混合排序。") 因而现有材料支持“异步语义检索”，不足以确认融合策略或混合排序，替代先前“完成异步混合检索”的表述。它还断言 `visible` 能排除指定证据，并将健康状态与案例结果写入验证文件。[可见性过滤与验证报告 ↗](../../../scripts/live-retrieval-smoke.ts#L30 "支持排除不可见 fragment 的断言，以及健康状态和案例结果落盘。") `finally` 无条件关闭检索器和数据库并删除临时目录。[检索资源与临时目录清理 ↗](../../../scripts/live-retrieval-smoke.ts#L35 "支持 finally 中关闭检索器和数据库并删除临时目录。")

当前用例未验证后台补建及故障恢复；实现中的 `start()` 会在成功后约一秒、出错后约三十秒再次尝试，而 `health()` 将状态区分为 indexing、ready 或 degraded。[后台重试与健康状态 ↗](../../../apps/server/src/retrieval/semantic.ts#L21 "支持索引健康状态的 indexing、ready、degraded 区分，以及后台成功和失败后的不同重试间隔。") 这些实现存在并不等于已经被本脚本现场验证。
