# 中文语义检索现场冒烟验证

通过中文 embedding 加载器和临时 Store 建立四类合成材料索引，验证意译式中文查询的语义 Top-1 命中、路线标记及可见性过滤；材料未证明模型一定本地加载。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="setup-and-cases"></a>
## 测试目的与语料设计

脚本用于观察关键词不完全重合时的检索效果：它在临时 Store 上创建 SemanticRetrieval，并通过 `loadChineseEmbedding` 延迟取得中文 embedding。四组语料覆盖就诊、熔断、语言学习和报销，查询使用“看牙医”“避免一直重试”“巩固外语词汇”“旅途花销凭证”等改写，以检验语义召回。[中文语义检索样例集 ↗](../../../scripts/live-retrieval-smoke.ts#L5 "支持中文 embedding 加载器的调用方式和四组意译式查询语料；不用于证明本地加载属性。") 仅凭导入和函数名无法确认模型是本地、离线或采用何种锁定版本。

<a id="index-and-assertions"></a>
## 索引与行为断言

所有材料先经 captureSchema 校验并捕获，随后循环 `indexBatch` 直到无待处理项。脚本对每个查询同时记录词法 Top-1 和异步检索结果，强制要求异步结果首项为对应 fragment，且 routes 包含 `semantic`。[批量索引与 Top-1 断言 ↗](../../../scripts/live-retrieval-smoke.ts#L17 "支持捕获后追平索引，并要求每个异步查询首项为预期 fragment 且包含 semantic 路线。") 因而它证明这些固定样例在当前运行环境中的 Top-1 行为；词法结果只作对照，并未要求词法路线失败。

<a id="visibility-and-limits"></a>
## 可见性与报告边界

脚本通过 visible 回调排除首个 fragment，并断言返回结果均不含该 fragment；成功后把 retrieval health 和逐案例信息写入 `.omem/verification`，最终关闭检索器和临时 Store。[可见性过滤与健康报告 ↗](../../../scripts/live-retrieval-smoke.ts#L30 "支持排除指定 fragment、输出健康和案例报告以及清理临时资源。") 未覆盖模型加载失败、向量身份变化、增量更新或删除、并列分数、低相关查询及 Top-1 之外的排序质量。
