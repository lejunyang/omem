# 统一的界面组件与阅读交互入口

该文件是 packages/ui 的公共导出入口，把基础界面组件、代码与 Markdown 阅读组件、关系图、证据轨迹以及哈希路由能力集中暴露给上层应用。它让调用方无需了解内部文件布局，但本身不实现组件行为，也不能证明具体交互已经过测试。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="public-entry"></a>
## 面向上层应用的统一入口

这个入口文件把按钮、图标、徽标、面板、空状态、对话框和应用外壳等通用组件汇总为统一的命名导出，同时提供引用、代码查看、Markdown 渲染、状态提示和关系图等阅读组件。上层模块可以从同一包入口选择所需能力，不必依赖各组件的内部路径。参考 [公共界面组件导出 ↗](../../../packages/ui/src/index.ts#L1 "支持基础界面组件和多种阅读组件由同一包入口统一命名导出的说明。")

<a id="typed-workflows"></a>
## 带类型约束的阅读流程

入口不仅导出可视组件，也公开关系图的模块与边类型、代码范围标记，以及证据轨迹的帧类型和栈操作函数。这些公共接口可用于组织“打开证据—继续深入—检测循环—限制轨迹长度”一类递归阅读流程；具体数据含义和算法行为仍需由对应实现文件确认。参考 [关系图与证据轨迹接口 ↗](../../../packages/ui/src/index.ts#L14 "支持关系图模块与边类型、代码范围标记、轨迹帧及轨迹操作函数属于公共 API 的论断。")

哈希路由的解析、写入函数及其路由类型也通过同一入口暴露，`useEvidenceTrail` 则提供证据轨迹的组合式接口。当前材料只能确认它们同属公共 API，不能据此认定路由与轨迹之间存在调用关系。参考 [路由与轨迹组合接口 ↗](../../../packages/ui/src/index.ts#L21 "支持哈希路由函数、路由类型和 useEvidenceTrail 被统一导出的说明，但不证明它们之间存在调用关系。")

<a id="boundaries"></a>
## 公共接口能够说明什么

该文件本质上是 **barrel export**：它确定公共 API 的名称和来源，却没有呈现组件属性、事件、可访问性、错误处理、滚动恢复或响应式布局等实现细节。`OmDisclosure` 作为通用展开组件被单独导出，但材料不足以判断它与证据抽屉、Markdown 或代码查看器之间是否存在调用关系。参考 [展开组件导出 ↗](../../../packages/ui/src/index.ts#L26 "支持 OmDisclosure 是独立公开组件的论断，同时说明入口本身不能揭示它与其他组件的内部关系。")

材料也不包含测试代码，因此能确认的是 TypeScript 层面的公开表面，不能进一步断言组件挂载、类型兼容、焦点归还或循环轨迹等行为已经得到验证。参考 [关系图与证据轨迹接口 ↗](../../../packages/ui/src/index.ts#L14 "支持关系图模块与边类型、代码范围标记、轨迹帧及轨迹操作函数属于公共 API 的论断。")
