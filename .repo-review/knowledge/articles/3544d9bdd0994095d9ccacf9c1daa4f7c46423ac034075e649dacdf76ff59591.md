# 开发端口选择的冲突与输入校验测试

该测试使用真实本机 TCP 监听制造端口占用，验证默认端口冲突时自动改用可用端口、显式指定端口冲突时明确失败，以及非法端口输入被拒绝；同时通过 finally 关闭测试服务器。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 测试目标与背景

该用例针对开发环境端口选择策略：默认端口允许在冲突时迁移，而用户显式指定的端口必须在冲突时明确报错。测试先在 `127.0.0.1` 上监听随机端口，并读取操作系统实际分配的端口，由此构造真实的 `EADDRINUSE` 场景，而不是模拟网络 API。[真实端口占用场景的建立 ↗](../../../apps/server/tests/dev-ports.test.ts#L5 "支持测试通过本机 TCP 监听和系统分配端口构造真实冲突场景的说明。") 这一行为对应 `selectDevPort` 对默认值与显式值采取不同处理的实现约定。[默认端口与显式端口策略 ↗](../../../scripts/dev-ports.ts#L3 "说明被测实现的设计背景：默认端口可迁移，显式端口冲突则失败。")

<a id="assertions"></a>
## 核心流程与断言

用例把已占用端口作为 fallback 且不提供 override，断言返回值大于零并且不同于冲突端口，覆盖“默认端口被占用后递归申请随机可用端口”的路径。[默认端口冲突迁移断言 ↗](../../../apps/server/tests/dev-ports.test.ts#L9 "支持测试对迁移结果为正数且不等于已占用端口的行为断言。") 随后将同一端口作为字符串显式传入，断言错误包含“已被占用”；又遍历非数字、负数、超过 65535 和小数四类输入，断言均抛出 `invalid port`。[显式冲突与非法输入断言 ↗](../../../apps/server/tests/dev-ports.test.ts#L13 "支持显式占用端口报错以及四类非法端口输入被拒绝的说明。") 这些断言分别对应实现中的整数范围校验、占用错误识别及显式端口失败分支。[端口校验和冲突处理实现 ↗](../../../scripts/dev-ports.ts#L6 "把测试断言关联到整数范围校验、EADDRINUSE 判断及默认端口迁移分支。")

<a id="boundaries"></a>
## 清理、边界与未覆盖行为

测试把全部断言放在 `try` 中，并在 `finally` 等待监听服务器关闭，确保断言失败时也释放端口资源。[监听服务器清理 ↗](../../../apps/server/tests/dev-ports.test.ts#L16 "支持测试无论成功或失败都会等待关闭占用端口服务器的说明。") 当前未覆盖空闲默认端口应原样返回、空闲显式端口成功、端口 `0` 的合法行为、非 `EADDRINUSE` 网络错误透传，以及迁移日志内容；也没有验证探测关闭后到实际服务绑定前可能出现的端口竞争窗口。实现仅短暂监听并关闭后返回端口，因此它提供的是可用性探测，不是端口预留。[端口探测后立即释放 ↗](../../../scripts/dev-ports.ts#L10 "说明实现取得分配端口后会关闭探测服务器，因此未提供持续端口预留。")
