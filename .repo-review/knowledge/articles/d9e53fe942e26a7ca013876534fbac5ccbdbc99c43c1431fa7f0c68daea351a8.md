# 飞书集成运行时宿主

统一装配实时连接、卡片动作、通知聚合、消息投递、质量标注和可选助手运行时，并以轮询循环协调连接生命周期与后台出站任务。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="composition"></a>
## 运行时装配与可见性

宿主以 Store、内存服务、入驻服务和秘密存储为基础，构造投递 worker、通知批处理器、卡片动作服务及质量标注服务；只有提供模型端口时才创建助手运行时，因此飞书采集与投递不强制依赖模型。[飞书运行时组件装配 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L35 "支持投递、批处理、卡片、质量服务及可选助手模型的依赖关系。")

助手检索采用关键词检索，并实施服务端可见性策略：私聊可读取证据，群聊只能读取 `conversationId` 与当前 chat ID 相同的证据。打开会话时，thread key 纳入应用 ID 与绑定版本，并校验会话可见性与当前聊天类型一致，以阻断伪造或跨绑定复用。[助手可见性与会话命名空间 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L84 "支持群聊证据隔离、绑定版本命名空间和可见性闭合校验。")

<a id="loop_recovery"></a>
## 连接同步、循环与恢复

每次处理先查询 active 或 awaiting-pair 连接，停止已失效管理器，并为新增连接装配租约、实时收件箱、助手钩子和卡片分流。质量协议卡片直接交给质量服务，其他卡片进入通用动作队列；随后依次准备聚合批次、处理卡片和消息投递。[连接同步与单轮处理 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L108 "支持连接增删、管理器装配、卡片协议分流以及后台任务处理顺序。")

启动时会恢复未完成的助手 turn：已有结果者补记完成，无结果者删除，使同一传输事件重投时可重新执行。主循环捕获并脱敏错误后继续轮询；停止会中止等待、关闭所有连接并停止入驻服务。该恢复逻辑假设进程启动时没有仍在运行的模型调用，不适用于多个共享同一会话表的活跃助手进程。[未完成 turn 恢复与宿主循环 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L212 "支持启动恢复假设、轮询错误处理和停止流程的说明。")
