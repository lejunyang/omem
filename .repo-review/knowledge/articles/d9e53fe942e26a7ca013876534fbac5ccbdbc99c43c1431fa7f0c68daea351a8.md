# 飞书运行时：连接、助手与可靠投递的统一编排

LarkRuntimeHost 是服务端飞书集成的生命周期与任务编排器：同步有效连接，将入站消息接入受可见性约束的助手会话，分流卡片动作，并持续聚合、投递待发送内容；同时负责崩溃恢复、状态观测和优雅停止。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 把分散的飞书能力装成一个运行时

`LarkRuntimeHost` 解决的是服务端如何长期运行飞书集成：它持有存储、记忆、入驻服务、密钥库以及可替换的实时/消息适配器，并对外提供一个统一生命周期。参考 [运行时依赖与可替换端口 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L39 "支持运行时统一持有存储、记忆、入驻、密钥及适配器等依赖的说明。")

构造时，它装配投递 worker、通知聚合器、卡片动作和质检服务；只有传入助手模型才创建 `AssistantRuntime`，否则仍可完成连接、卡片与通知投递。助手默认使用关键词检索，也允许注入统一检索端口。群聊证据只在来源会话 ID 与当前群一致时可见，私聊则沿用私有可见性。参考 [服务装配与证据可见性 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L72 "支持投递、卡片、质检、可选助手、默认检索以及群聊证据隔离的说明。")

<a id="flow"></a>
## 一轮处理怎样贯通连接与投递

代表性调用是后台循环执行 `processOnce(100)`。它先从数据库读取 `active` 或 `awaiting_pair` 连接：失效连接被停止并移出内存，新连接则创建连接管理器、租约仓储和事件收件箱，再启动尚未运行的连接。参考 [有效连接同步 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L118 "支持连接查询、停止失效连接、创建并启动新连接管理器的流程。")

```mermaid
flowchart LR
  A[同步有效连接] --> B[准备到期通知聚合]
  B --> C[处理卡片动作]
  C --> D[处理投递队列]
  D --> E[返回本轮统计]
```

每轮先聚合到期通知，再分别最多处理 `limit` 个卡片动作和 `limit` 个投递任务，输出卡片数、投递数、批次数、变更数及当前连接数；因此 `limit` 是两类队列各自的上限，不是合计上限。参考 [单轮队列处理 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L203 "支持通知聚合、两类队列各自限量处理及统计返回值的说明。")

当事件收件箱把一条助手消息路由进来时，运行时用应用 ID 与绑定版本组成 transport thread，按群聊或私聊打开会话；可见性不符即拒绝。随后调用助手 turn，并把回复、turn ID、重复标志和 outbox ID交回收件箱，由后续投递链处理。参考 [助手会话路由 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L149 "支持 transport thread 命名、可见性校验、助手 turn 调用和结果回传的代表性消息链路。") 卡片事件则按协议分给质检处理器或普通卡片队列。参考 [卡片协议分流 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L185 "支持质检协议事件与普通卡片动作走不同处理器的说明。")

<a id="boundaries"></a>
## 恢复、容错与停止边界

启动时会恢复飞书助手的未完成 turn：没有助手时直接空操作；已有结果但未终结的 turn 补记为完成，没有结果的陈旧 turn 删除，使同一传输事件重投后可以重新执行，而已生成回复的投递仍交给 delivery worker。参考 [未完成会话恢复 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L222 "支持按是否已有结果分别完成或重置陈旧 turn 的恢复语义。")

`start()` 可重复调用但只启动一个循环。单轮异常不会杀死循环，错误会去除常见密钥形态、压平换行并截断后保存；等待既受轮询间隔控制，也能被 abort 立即唤醒。参考 [循环与错误收敛 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L253 "支持单例启动、周期处理、异常留存和可中断等待的说明。") `status()` 只暴露运行态、活跃连接数、累计处理量和最近错误；`stop()` 中止循环、关闭全部连接与入驻服务并等待循环退出。参考 [状态与优雅停止 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L284 "支持运行状态字段以及停止连接、入驻服务和后台循环的说明。")
