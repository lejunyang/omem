# 飞书集成运行时编排

统一编排实时连接、助手、卡片动作、通知聚合和消息投递，并落实群聊证据隔离与崩溃恢复。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="composition"></a>
## 组件组装与可见性边界

运行时宿主是飞书集成的组合根：构造投递 worker、通知批处理器、卡片动作服务和质量标注服务，并按需创建助手运行时。默认检索为关键词检索，也允许注入模型、检索、媒体和消息适配器。群聊可见性策略会逐条读取证据，仅允许当前 chatId 实际采集的材料；私聊则按 private 可见，因此群聊不能看到所有者的私有或其他群证据。[运行时组件与群聊可见性 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L36 "支持宿主组装各飞书服务、助手依赖以及按会话来源隔离群聊证据的说明。")

连接同步从数据库读取 active 或 awaiting_pair 项，为每项建立带租约的连接管理器。助手会话键包含 appId 与 bindingVersion，并校验会话可见性；卡片协议属于质量标注时走 quality 服务，否则进入普通卡片队列。[连接同步与助手路由 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L110 "支持连接管理器创建、会话命名空间、可见性复核及卡片协议分流的说明。")

<a id="loop-recovery"></a>
## 轮询、恢复与停止

每轮先同步连接，再准备到期聚合批次，随后在上限内分别处理卡片动作和投递任务；主循环捕获并脱敏错误，按 pollMs 等待，避免一次失败终止整个宿主。状态接口只暴露运行状态、活动连接数、累计处理量和最近错误。[单轮处理与运行循环 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L195 "支持批处理、卡片和投递的执行顺序，以及错误隔离和状态统计。")

启动前会恢复未完成助手 turn：已有结果者补标完成，无结果者删除，使相同 transport event 重投后能够重新执行；已有 outbox 的投递仍由 delivery worker 接管。停止时先 abort 循环，再关闭全部实时连接和 onboarding，并等待循环退出。该恢复策略假定进程启动时没有仍在执行的旧模型调用。[未完成会话恢复 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L214 "支持启动时区分有结果和无结果 turn 的恢复行为及其假设。")
