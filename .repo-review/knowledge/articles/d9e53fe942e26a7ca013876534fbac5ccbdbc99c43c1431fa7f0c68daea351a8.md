# 飞书实时连接、助手应答与可靠投递编排

LarkRuntimeHost 是服务端飞书集成的常驻编排层：同步数据库中的有效连接，把实时消息路由到受可见性约束的助手会话，分派卡片动作，并周期性处理通知聚合与回复投递；同时提供重启恢复、状态观测和有序停机。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role_and_composition"></a>
## 解决什么问题

该宿主把飞书接入所需的多类组件装配成一个常驻运行时：回复投递 Worker、通知批处理器、卡片动作服务、质量标注服务，以及可选的助手运行时。若调用方未注入适配器或检索器，它会使用官方消息/实时适配器与关键词检索；若未提供 `assistantModel`，助手能力保持关闭，但连接、卡片和投递编排仍可工作。参考 [运行时组件装配 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L74 "支持宿主创建投递、批处理、卡片、质量服务，并仅在提供模型时创建助手运行时的说明。")

安全边界由服务端掌握：私聊可访问允许的个人证据，而群聊检索只接受来源会话 ID 与当前群一致的证据。这样飞书群内提问不会看到从私聊、其他群或无对应会话来源收集的内容。参考 [群聊证据可见性 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L92 "支持私聊与群聊采用不同证据可见性规则，群聊限定为同一会话来源。")

<a id="message_flow"></a>
## 一条消息如何变成回复

以绑定用户在群里触发助手为例：一次 `processOnce()` 先读取处于 `active` 或 `awaiting_pair` 的连接，停掉已失效实例，并为新连接创建带租约的 `LarkConnectionManager`。实时适配器收到事件后，经 `LarkEventInbox` 调用这里注入的助手回调。参考 [连接同步与事件入口 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L121 "支持有效连接筛选、失效连接停止、新连接管理器创建及事件收件箱装配流程。")

回调用 `appId + bindingVersion` 生成传输线程标识，再按群聊或私聊打开对应会话；若已存会话的可见性与当前绑定不一致，立即失败关闭。随后它把文本和飞书事件 ID 交给 `AssistantRuntime.turn()`，将回复文本、轮次 ID、去重状态及既有 outbox ID 返回给事件收件箱。参考 [助手消息路由 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L151 "支持传输线程命名、可见性校验、助手轮次调用及回复元数据返回的代表性调用链。")

下一轮 `processOnce()` 会先生成到期通知批次，再分别最多处理 `limit` 个卡片任务和 `limit` 个投递任务，返回本轮计数及连接数。卡片协议为 `omem.quality.v1` 时走质量标注，其余进入普通卡片队列。参考 [卡片分流与队列处理 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L189 "支持质量卡片协议分流，以及每轮通知聚合、卡片和投递任务的限量处理。")

<a id="recovery_and_lifecycle"></a>
## 恢复、错误与生命周期边界

启动具有幂等保护，并在进入轮询前恢复未完成轮次：已有结果但未终结的轮次补记为完成；没有结果的陈旧轮次直接删除，使同一传输事件重投时可以重新执行。助手未启用时恢复返回零计数。参考 [未完成轮次恢复 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L225 "支持有结果轮次补完成、无结果轮次清除，以及无助手时直接返回的恢复语义。")

循环默认每秒执行一次；单轮异常不会终止宿主，而是把错误去换行、截断到 1000 字符，并遮蔽常见密钥前缀后保存到状态中，下一轮成功会清空错误。`status()` 暴露运行状态、活跃连接数及累计处理量。停止时通过 `AbortController` 唤醒等待，关闭所有连接和 onboarding，最后等待循环退出。错误文本的清洗规则参考 [错误隔离与有序停机 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L34 "支持错误脱敏与截断、轮询不中断、状态暴露、Abort 唤醒及停机清理行为。")；轮询、状态与停机流程参考 [轮询状态与停止流程 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L262 "支持轮询捕获异常、状态统计以及关闭控制器、连接、onboarding 并等待循环结束的说明。")
