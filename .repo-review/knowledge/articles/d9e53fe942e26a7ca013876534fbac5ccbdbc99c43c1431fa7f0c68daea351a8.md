# Lark 运行时编排主机

该文件把 Lark 长连接、入站事件、助手问答、卡片动作、通知聚合和消息投递组合为一个可启动、可恢复、可观测的后台运行时，并在群聊场景实施基于会话来源的证据可见性隔离。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-composition"></a>
## 解决的问题与组件装配

`LarkRuntimeHost` 是服务端 Lark 集成的生命周期与任务编排入口：它持有连接管理器集合，并组装投递 worker、通知批处理器、卡片动作服务和质量标注服务。助手模型是可选依赖；未配置时仍可运行连接、卡片和投递流程，配置后则注入记忆、反馈、检索和 60 秒回合超时。检索默认使用 SQLite 关键词实现，也允许通过统一端口替换。[运行时组件构造与可选助手 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L36 "支持运行时装配投递、批处理、卡片、质量服务，以及可选助手、默认检索和超时配置的说明。")

它还定义服务端可见性边界：私聊可访问候选证据，群聊则只允许读取来源上下文中 `conversationId` 与当前群 `chatId` 一致的证据，不存在记录或来源不匹配时拒绝。检索端口本身要求结果回指不可变 fragment，因此该策略是在候选证据锚点上实施，而非信任派生摘要。[统一检索端口的证据锚点 ↗](../../../apps/server/src/retrieval/port.ts#L1 "说明检索实现可替换，且返回结果必须指向不可变 fragment，支撑可见性过滤的证据边界。")

<a id="event-and-worker-flow"></a>
## 连接同步与事件处理流程

每轮处理先从数据库读取 `active` 或 `awaiting_pair` 的连接：失活连接会停止并移出内存，新连接则创建租约仓库、实时适配器和事件收件箱后启动。助手消息使用包含 appId 与 bindingVersion 的命名空间线程键打开会话，并再次校验会话可见性；不一致时以 `LARK_CONVERSATION_VISIBILITY_MISMATCH` 失败关闭，避免伪造或旧绑定复用会话。[连接同步与助手消息路由 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L110 "支持连接增删启动、命名空间线程键、会话可见性校验及助手回合调用流程。")

卡片事件按 `protocol` 分流：`omem.quality.v1` 交给质量标注服务，其余进入普通卡片动作队列；质量模块给出的动作合同还要求 UUID、动作枚举、nonce、标签摘要和过期时间。[质量标注卡片动作合同 ↗](../../../apps/server/src/quality/lark-annotations.ts#L12 "支持质量协议名称及其动作、随机数、摘要和过期时间等输入约束。") `processOnce` 随后准备到期通知聚合，并分别最多处理 `limit` 个卡片和投递任务，累计计数后返回批次、变化数与连接数。两类循环按先卡片后投递顺序执行，并非并发消费。[单轮卡片与投递消费 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L195 "支持通知聚合、限量顺序消费、累计统计和单轮结果结构的描述。")

<a id="recovery-and-boundaries"></a>
## 恢复、错误处理与生命周期边界

启动时会恢复未完成的助手回合：已有结果的回合被补记为完成，回复 outbox 继续由投递 worker 负责；尚无结果的回合直接删除，使同一传输事件重投时能够重新执行，而不会永久返回陈旧的 pending 记录。没有助手模型时恢复是空操作。[未完成助手回合恢复 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L214 "支持有结果回合补完成、无结果回合删除以及无助手时空操作的恢复语义。")

后台循环持续调用单轮处理并按 `pollMs`（默认一秒）等待；异常只记录经过凭据模式脱敏、换行压平和长度截断的错误文本，循环仍继续。状态接口只暴露运行标志、实际运行连接数、累计处理量和最近错误。停止时中止等待、关闭全部连接和 onboarding，并等待主循环退出。[轮询、状态与停止流程 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L251 "支持循环容错、轮询等待、状态观测和完整停止顺序的说明。") 该文件提供了崩溃注入钩子，用于模拟回复 outbox 已提交但 inbox 尚未确认的窗口，但所给材料没有对应测试，因此无法从本材料确认该持久性承诺已被自动化断言覆盖。[回复提交后的崩溃测试接缝 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L49 "支持运行时显式提供崩溃注入点及其期望保留 outbox 的语义，同时界定当前材料未包含测试证据。")
