# 变更历史的筛选、比较与版本恢复入口

该页面把材料、知识、事项等变化集中为可筛选的时间记录，并为具备版本关联的材料或知识提供差异查看；对于材料版本，还可继续阅读或发起“恢复为新版本”。组件只负责展示与派发操作，差异读取及真正恢复由外部模块完成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 从变化记录找到可执行入口

页面解决“最近发生了什么、具体改了什么、能否回到旧内容”的问题。它接收 `Change[]`，将记录按材料、知识、恢复、事项、判断、问答和引用等类别显示，并以中文标签和本地化时间降低内部数据结构对读者的干扰。页面文案同时说明这里只呈现最近 200 条记录，并强调恢复不会覆盖现有版本，而是创建新版本。参考 [历史页面用途与分类 ↗](../../../apps/web/src/ChangeHistory.vue#L6 "支持页面面向用户的问题、记录范围说明、恢复语义以及变化类型中文标签。")

<a id="flow"></a>
## 筛选、展开差异与恢复流程

用户先通过下拉框选择全部变化或某一种实际存在的变化类型，`visible` 会据此过滤列表。每条记录展示标题、类型、时间和摘要；材料首次保存、材料更新以及缺少正文关联的旧知识记录会得到专门说明。具备 `afterId` 的材料、恢复或知识记录可展开差异，组件仅在首次展开后挂载 `ChangeComparison`，避免一开始就读取全部内容。参考 [筛选与按需展开差异 ↗](../../../apps/web/src/ChangeHistory.vue#L11 "支持过滤计算、摘要分支、记录渲染和展开后才挂载比较组件的流程。")

材料或恢复记录还提供两个动作：有新版本时可发出 `open(afterId)` 阅读该版本；同时具备前后版本时才可发出 `restore(change)`，由父级决定如何执行恢复。参考 [阅读与恢复动作条件 ↗](../../../apps/web/src/ChangeHistory.vue#L28 "支持阅读按钮和恢复按钮的显示条件，以及组件通过事件把动作交给父级处理。")

<a id="boundaries"></a>
## 职责边界与缺失状态

该组件不直接请求后端、不计算文本差异，也不实施恢复；它依赖 API 层导出的 `Change` 类型，并把具体比较交给 `ChangeComparison`。后者按变化 ID 请求固定版本内容，再用三行上下文生成补丁，因此这里的“展开”实际会触发另一个组件的数据读取。参考 [固定版本差异计算 ↗](../../../apps/web/src/ChangeComparison.vue#L2 "说明比较组件会按变化 ID 获取内容并使用带上下文的结构化补丁，界定历史列表与差异模块的关系。")

边界处理主要体现在条件展示：没有匹配记录时显示空状态；缺少 `afterId` 时不能阅读或比较；只有前后版本都存在时才允许恢复。知识记录虽可比较，但不出现恢复按钮。当前材料未提供父组件监听 `open`、`restore` 的实现，也未提供测试文件，因此无法确认恢复确认流程、请求失败后的页面级反馈，以及筛选和事件条件是否有自动化断言。参考 [条件展示与空状态 ↗](../../../apps/web/src/ChangeHistory.vue#L26 "支持可比较类型、版本条件、材料恢复限制和无记录时的空状态等边界行为。")
