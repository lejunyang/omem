# 学习上下文来源与依赖刷新测试

验证模型上下文保留多发言者标识、图片资产引用和非可信项目标志，并明确来源更新后系统目前只能记录待复核，不能声称已完成重新核验。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="fragment-context"></a>
## 已验证的逐分片上下文

测试构造含两位发言者、回复关系和图片的 capture，再运行提取角色。角色输出的诊断信息明确包含两位外部身份、一个图片资产引用以及 `projectTrusted=false`，说明多说话人没有被压扁为单一 actor，图片可通过资产引用进入材料，而会话号不会被提升为可信项目。[发言者、图片引用与项目信任断言 ↗](../../../apps/server/tests/learning-refresh.test.ts#L56 "仅支持两位 actor 标识、图片资产引用计数和 projectTrusted=false 已进入角色可见输出。")

输入本身还携带事件号、观测时间与回复关系，但当前输出断言没有逐项检查这些字段是否到达模型，因此本文只确认发言者标识、图片资产计数和项目信任标志。逐分片来源合同允许保存 actor、时间、事件和回复等信息，但合同存在并不等同于本测试已验证所有字段的端到端传递。

<a id="refresh-limit"></a>
## 依赖刷新只标记待复核

第二组测试先创建引用来源第一版的 memory，再以相同外部标识采集内容完全变化的第二版。来源推进会排入 `refresh_dependents` job；当前 `LearningPipeline` 尚未实现真正的重新核验，所以该 job 必须失败并包含 `NOT_IMPLEMENTED`，不能被记录为成功。[依赖刷新未实现的失败断言 ↗](../../../apps/server/tests/learning-refresh.test.ts#L152 "支持 refresh_dependents 不能虚报重新核验成功，而应以 NOT_IMPLEMENTED 失败。")

刷新记录同时保持 `needs_review`，保存受影响数量及具体 memory 标识，供后续人工或新 worker 接手。[受影响知识待复核记录断言 ↗](../../../apps/server/tests/learning-refresh.test.ts#L233 "支持刷新记录保存 needs_review、受影响数量和具体 memory 标识。") 这固定了当前能力边界：系统能追踪受影响知识，却不能判断旧结论仍受支持、应被替代还是需要用户决策。未来的状态迁移政策、级联依赖处理和用户可见行为仍未由这些测试定义。
