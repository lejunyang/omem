# 学习刷新与逐片段来源信息测试

该测试文件使用临时 SQLite 数据目录和固定 ACP fixture，验证逐片段来源信息能够抵达模型上下文、源修订会触发依赖刷新、证据不足时保持待复核，以及验证作业处理后原位更新记忆并保留旧修订证据。测试确认了状态与结果，但尚未证明 extractor 与 verifier 的角色隔离方式，也未覆盖连续修订竞争。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="test_setup"></a>
## 测试环境与隔离

每个用例创建独立临时目录，并在结束后递归清理；ACP profile 指向固定 fixture，使用当前 Node 进程启动，并设置 3 秒超时。这样的装配隔离了数据库与代理工作目录，使测试结果不依赖持久的本机状态。[临时目录与 ACP fixture 配置 ↗](../../../apps/server/tests/learning-refresh.test.ts#L15 "支持公共测试环境如何创建、清理临时目录，以及固定 ACP profile 的命令和超时配置；不用于证明后续服务组合。") `Store`、记忆服务和学习流水线的组合则分别出现在后续具体用例中，不能仅由这段公共初始化推出。

<a id="provenance_manifest"></a>
## 逐片段来源信息进入模型

多模态场景捕获 Alice、Bob 两段文本和一张由 Bob 提供的图片。各 part **可以**携带自己的 provenance：两个文本片段分别保存参与者、时间和事件信息，Bob 文本回复 Alice；图片仍保留 Bob 身份，但时间、事件与回复字段为空。处理抽取作业后，测试从角色输出确认 Alice、Bob、一个图片资产引用和 `projectTrusted=false` 已抵达模型侧上下文。[多参与者与图片来源传播场景 ↗](../../../apps/server/tests/learning-refresh.test.ts#L67 "支持 Alice、Bob 和图片各自实际携带的来源字段，以及角色输出对参与者、图片资产和非可信项目标记的断言。") 这证明了关键来源信息的传播结果，但没有断言每个片段都具备完整且彼此独立的事件字段。

<a id="refresh_abstention"></a>
## 刷新派发与诚实弃权

待刷新场景先创建依赖 v1 修订的记忆，再以相同外部来源捕获内容完全不同的 v2。系统产生 `refresh_dependents` 作业，并再次使用 `extract_claims` 路径处理新证据；当模型没有足够依据修复原记忆时，派发作业虽成功，刷新记录仍保持 `needs_review`，受影响数量及记忆标识继续可追踪。[源刷新派发与待复核状态 ↗](../../../apps/server/tests/learning-refresh.test.ts#L152 "支持 v1 到 v2 的单次源更新会派发刷新作业、复用抽取任务，并在证据不足时保留 needs_review 状态。") 因而队列处理成功只代表刷新流程已被调度，不能等同于知识已经重新应用。

<a id="verified_in_place_update"></a>
## 验证作业处理后的原位更新

成功路径把“重试上限为 3”更新为“重试上限为 5”。新修订到达后，原记忆先变为 `invalidated`；流水线继续处理后，同一记忆 ID 升至版本 2、恢复 `active`，正文包含新值，旧修订原文仍可读取，刷新记录转为 `applied`，并可见两项 `verify_proposals` 作业。[验证作业后的记忆版本更新 ↗](../../../apps/server/tests/learning-refresh.test.ts#L253 "支持记忆先失效、随后以相同 ID 升级版本并恢复 active，同时保留旧修订、应用刷新记录和产生验证作业的断言。") 这些断言证明了验证作业处理后的原位更新和证据保留，但没有证明 extractor 与 verifier 使用相互独立的角色，也未覆盖复核失败、连续修订、重试耗尽或事务中断。
