# 检索后端工厂

读取严格的检索配置，并在默认关键词检索与启用后的本地中文语义检索之间切换，同时向调用方统一暴露关闭钩子。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="configuration"></a>
## 配置合同

配置只允许 `enabled` 和 `osdkModel` 两项：前者默认关闭语义检索，后者默认指向 `memory-zh`，且别名只能包含字母、数字、下划线和连字符。读取函数直接解析 JSON 并交给严格 schema，因此未知字段、非法别名或格式错误都会在启动配置阶段暴露。[检索配置解析 ↗](../../../apps/server/src/retrieval/factory.ts#L9 "支持严格配置字段、默认值和模型别名格式的说明。")

<a id="selection"></a>
## 后端选择与生命周期

未提供配置或未启用时，工厂直接构造 SQLite 关键词检索，并返回无操作的异步关闭函数。启用后则构造 `SemanticRetrieval`，把中文 embedding 加载器作为延迟工厂传入，立即调用 `start()`，关闭时委托语义后端释放资源。[关键词与语义后端选择 ↗](../../../apps/server/src/retrieval/factory.ts#L14 "说明关闭时采用关键词检索，启用时启动语义检索并提供关闭钩子。") 因而该模块是后端装配点：它依赖统一 `RetrievalPort`、关键词实现、语义实现和模型加载器，但不参与排序算法或向量计算本身。

<a id="boundary"></a>
## 可见边界

这里的回退只由配置开关决定，并未出现“语义初始化失败后自动退回关键词检索”的处理。`start()` 是否同步抛错、后台失败如何反映到健康状态，取决于未提供的 `SemanticRetrieval` 实现，不能由本文件确认。[语义检索启动调用 ↗](../../../apps/server/src/retrieval/factory.ts#L14 "支持本文件没有捕获 start 异常或声明自动降级策略这一边界判断。")
