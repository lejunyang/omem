# 测试用确定性助手模型

该文件实现一个仅供测试注入的确定性 AssistantModelPort：不执行模型推理，而是把运行时已检索的证据裁剪、格式化并返回固定片段引用；无证据时给出诚实的空结果提示。生产环境应注入真实 ACP 模型，配置或传输失败由运行时明确报错。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决的问题与使用边界

`DeterministicAssistantModel` 为助手流程提供可重复的测试替身，使测试能够在不依赖真实 LLM、认证或网络状态的情况下观察“证据如何变成回答”。源码明确限定它只用于测试；生产装配应注入真实 `AcpAssistantModel`，模型不可用时应暴露错误，而不是用这段固定回答伪装成功。[测试替身的生产边界说明 ↗](../../../apps/server/src/assistant/default-model.ts#L7 "支持该类只为测试存在、生产必须注入真实 ACP 模型且不得伪降级的论断。") 这一定位也与运行时对 `ModelUnavailableError` 的说明一致，但所给材料没有展示实际装配代码，因此无法确认所有生产入口都已强制遵守该边界。[运行时模型不可用语义 ↗](../../../apps/server/src/assistant/runtime.ts#L66 "说明真实模型缺失、认证失败或超时时，运行时应明确报告不可用。")

<a id="flow"></a>
## 核心生成流程

`generate` 接收用户文本、历史轮次、可见性与已检索证据，但实际只消费前三者中的用户文本、历史轮次数量和证据；`visibility` 不参与二次过滤。它先截取最多 5 条证据：若为空，返回“没有直接相关内容”且引用列表为空；否则按顺序输出标题及每条正文前 160 个字符，并在存在历史轮次时附加当前轮次提示。[证据格式化与空结果流程 ↗](../../../apps/server/src/assistant/default-model.ts#L16 "支持最多取五条证据、空证据返回固定提示、正文截断及历史轮次提示的流程描述。") 最终 `citationIds` 直接取自这批截断后证据的 `fragmentId`，符合运行时将引用定义为回答实际依赖片段的合同。[回答引用合同与片段映射 ↗](../../../apps/server/src/assistant/runtime.ts#L54 "运行时合同定义 citationIds 为回答实际依赖的片段，测试替身则把入选证据的 fragmentId 映射到该字段。")

<a id="limits"></a>
## 边界条件、断言价值与模块关系

该实现的确定性来自固定的数量上限、字符截断和模板拼接，适合断言证据顺序、最多五条、空结果、轮次提示及引用映射；它不验证语义正确性，也没有展示处理 Unicode 截断、重复片段或超长标题的专门逻辑。[确定性输出的具体限制 ↗](../../../apps/server/src/assistant/default-model.ts#L22 "支持证据数量上限、每条文本长度上限和固定模板等可测试边界。") 它依赖 `runtime.ts` 提供的 `AssistantEvidence`、`AssistantModelPort` 与 `AssistantModelReply` 类型；运行时回复还允许工具调用和额外检索请求，但此替身始终不产生这些字段，所以不能证明任务创建、更新、二次检索或服务端权限复核行为已被覆盖。[助手回复的扩展能力 ↗](../../../apps/server/src/assistant/runtime.ts#L54 "说明完整运行时回复还可包含受服务端治理的工具调用和一次额外检索，而该替身未实现这些输出。")
