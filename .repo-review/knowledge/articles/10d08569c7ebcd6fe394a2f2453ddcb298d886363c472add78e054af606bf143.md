# learning · 模块理解

learning 模块把固定来源 revision 编排为可审计的提取、独立复核与整批记忆策略决策，并维护输入新鲜度、材料来源和作业运行边界；来源更新目前仅记录影响范围，workspace 隔离、零影响提示及自动重核对仍有明确限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-flow"></a>
## 职责与核心流程

learning 是捕获链与记忆策略之间的编排层，只领取提取、复核和依赖刷新三类持久化作业。启动时核对 extractor、verifier 的 profile；尝试指纹记录模型与 effort，但阶段哈希仅由管线配置和固定阶段名生成，不能视为真实提示词、技能或工具内容的摘要。[学习管线构造与尝试指纹 ↗](../../../apps/server/src/learning/pipeline.ts#L86 "支持作业种类、角色 profile 校验，以及阶段哈希仅由配置字段和固定阶段名生成的说明。")

提取阶段从固定 revision 构造上下文，运行 extractor 并保存结构化输出与观察记录；只有产生 proposal 时才创建 verifier 子作业。[提取结果与复核作业衔接 ↗](../../../apps/server/src/learning/pipeline.ts#L410 "支持提取输出、观察记录和仅在存在提议时创建 verifier 子作业的流程。") 复核阶段校验父子关系、输出 schema、摘要及 trace 中 bundleHash 的格式，但没有将其与当前角色包哈希比较；assessment 必须完整覆盖 proposal 且摘要一致，随后整个 ChangeSet 一次性交给批量策略评估，防止拆分绕过自动应用预算。[复核输入与追踪字段校验 ↗](../../../apps/server/src/learning/pipeline.ts#L443 "支持父子关系、schema、输出摘要及 bundleHash 格式检查，并表明未执行当前角色包哈希相等性校验。")[复核覆盖与整批策略评估 ↗](../../../apps/server/src/learning/pipeline.ts#L479 "支持 assessment 完整覆盖、proposal 摘要一致及整个变更集一次性进入批量策略评估。")

<a id="context-and-trust"></a>
## 材料映射与可信边界

输入 revision 必须仍是 source head，并与可选的 sourceId、validity epoch 一致，否则按陈旧输入拒绝。应用、会话和运行标识只说明捕获位置，不能替代已确认的项目关联，因此项目保持未知且不可信。[Revision 新鲜度与项目可信边界 ↗](../../../apps/server/src/learning/pipeline.ts#L172 "支持 source head、sourceId、validity epoch 校验，并说明捕获位置标识不能充当可信项目关系。")

上下文通过 `fragmentPairs` 镜像捕获时的拆分规则，再用 fragment ordinal 尝试定位原始 part，以携带参与者、回复、观察时间、引用、转发和生产者类型；文本按段落展开，链接和图片各形成一项，图片资产缺失会失败。[固定片段与原始材料的 ordinal 映射 ↗](../../../apps/server/src/learning/pipeline.ts#L212 "支持通过镜像捕获拆分规则和 ordinal 尝试恢复逐 part 来源，同时显示实现没有文本一致性或越界校验。") 但代码未比较重建文本与实际 fragment 文本，也未显式处理 ordinal 越界或规则漂移，因此不能无条件认定来源映射始终可靠。相关记忆按 workspace 范围召回，并保持项目不可信。

<a id="runtime-progress-limits"></a>
## 运行语义、刷新进展与限制

对外错误会遮蔽常见密钥及认证字段、移除换行并截断，再分类为坏输出、认证、暂时性、配置或永久错误。[错误清理与失败分类 ↗](../../../apps/server/src/learning/pipeline.ts#L30 "支持敏感字段遮蔽、单行化、长度限制及错误类型分类。") 运行器支持单步处理、有上限的排空、后台轮询、作业取消和停止；达到排空上限会失败，循环异常则保存清理后的最近错误。[作业排空与后台运行控制 ↗](../../../apps/server/src/learning/pipeline.ts#L553 "支持排空上限、轮询、最近错误、取消、状态查询和停止行为。")

来源刷新按 sourceId 查询依赖当前 head revision 的记忆，并写入新旧 revision、影响数量和记忆列表；SQL 本身没有 workspace 条件，workspaceId 只写入审计记录，因此在缺少 sourceId 全局隔离证明时，不能无条件称为当前 workspace 的影响集合。[按来源查询受影响记忆 ↗](../../../apps/server/src/learning/refresh.ts#L33 "支持查询依赖当前 head revision 的记忆，并显示查询只按 sourceId 过滤、未使用 workspaceId。") 有影响时记录 `needs_review`，空集合记录 `no_effect`。[刷新审计状态与字段 ↗](../../../apps/server/src/learning/refresh.ts#L53 "支持有影响时记录 needs_review、空集合记录 no_effect，以及 workspaceId 仅在插入审计记录时使用。") 确定性失效发生在捕获流程；这里不运行 verifier，管线记录后仍抛出未实现错误，故“已记录影响范围”取代任何“已完成重新复核”的旧结论。[重新复核尚未实现 ↗](../../../apps/server/src/learning/refresh.ts#L25 "说明确定性失效已在捕获流程发生，而刷新函数只记录范围，不执行 verifier 或重新复核。")[依赖刷新作业的阻塞语义 ↗](../../../apps/server/src/learning/pipeline.ts#L126 "证明管线记录影响范围后仍抛出未实现错误，并显示零影响时错误文本仍使用 needs_review 描述。") 此外，零影响时审计为 `no_effect`，但异常文本仍统一称“0 项 flagged needs_review”，存在可观察的语义不一致。
