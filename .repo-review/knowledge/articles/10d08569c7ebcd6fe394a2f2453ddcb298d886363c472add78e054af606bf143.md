# learning · 模块理解

learning 模块以持久化作业串联固定材料提取、独立复核、策略治理与来源更新后的记忆重核验。它强调当前原始证据、可审计运行记录和批量影响预算；批量批准、刷新来源限定及片段映射一致性仍有待补强。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-boundary"></a>
## 模块职责与证据边界

learning 是捕获材料进入长期记忆前的治理层，只领取提取、复核和依赖刷新三类作业。作业指纹中的三个具名哈希由相同的 pipeline、profile、model、effort 种子配合不同 stage 名称计算；这替代“已绑定实际提示词、技能和工具内容摘要”的旧结论。[学习流水线作业范围与指纹派生 ↗](../../../apps/server/src/learning/pipeline.ts#L65 "支持三类作业限定，并说明三个具名哈希由相同配置种子配合不同 stage 字符串派生。")

角色执行前会确认 revision 仍是来源当前 head，且来源标识与 validity epoch 未变化；会话位置不被当成可信项目绑定，材料则携带固定 fragment、人物、时间、转发状态及图片资产等 provenance。[当前修订与可信上下文构造 ↗](../../../apps/server/src/learning/pipeline.ts#L180 "支持来源 head、validity epoch、项目可信边界和逐片段 provenance 的说明。") part→fragment 映射按文本段落、链接、图片的捕获顺序重建，但必须与捕获侧长期同步，否则逐片段 provenance 可能错配。[片段顺序映射规则 ↗](../../../apps/server/src/learning/pipeline.ts#L311 "支持 part 到 fragment 的重建顺序必须镜像捕获拆分，并揭示 provenance 错配风险。")

<a id="learning-flow"></a>
## 提取、复核与策略应用

extractor 生成提案和观察记录，非空提案再派生 verifier 子作业；复核阶段校验父子关系、已存输出摘要、schema、覆盖率及逐项摘要，随后整批调用记忆服务。[提取、复核与刷新对账编排 ↗](../../../apps/server/src/learning/pipeline.ts#L421 "支持提案生成、复核子作业、输出一致性检查、整批评估，以及提取或复核各结果分支调用刷新对账。") 策略层还会确定性检查文字选择范围、精确引文、来源修订和图片资产。[固定证据定位校验 ↗](../../../apps/server/src/memory/service.ts#L236 "支持文字选择、精确引文、来源修订和图片资产的确定性校验。")

新 claim 仅在同工作区、同项目内匹配现行知识。重复或等价要求规范化后的 statement 完全相同，再以来源是否重叠区分；冲突识别还必须由 verifier 将 `reason_code` 标为 `contradicts_existing`，并要求双方有效时间窗口重叠、实体词有交集且谓词极性相反。[重复、等价与冲突匹配条件 ↗](../../../apps/server/src/memory/service.ts#L383 "支持工作区和项目过滤、完全相同的规范化 statement、来源重叠区分，以及冲突所需的 verifier 标记、时间重叠、实体词交集和相反谓词极性。") 治理结果可为拒绝、忽略噪声、等待决定、延后使用、仅保留来源或自动应用。[记忆治理策略分支 ↗](../../../apps/server/src/memory/service.ts#L739 "支持拒绝、忽略噪声、等待决定、延后使用、仅保留来源和自动应用等策略结果。")

批量评估先计算受影响记忆与新实体的去重并集；超出预算时，通常暂停原本会物化新状态的自动应用提案，并创建一个合并确认事项。[整批影响预算与暂停规则 ↗](../../../apps/server/src/memory/service.ts#L1295 "支持批量影响并集、默认预算、自动应用提案的暂停条件及合并确认创建流程。") 但同源重复即使超预算仍可返回 `auto_apply`，只保留链接结果而不新建 active 记忆；独立来源的等价结论才会随批次暂停。[重复与等价结论的批量例外 ↗](../../../apps/server/src/memory/service.ts#L1599 "支持同源重复在超预算批次中不新建 active 记忆，以及独立来源等价结论随批次暂停的差异。")

<a id="refresh-and-jobs"></a>
## 来源刷新与持久化执行

来源更新后先冻结当时所有 `stale` 且 `invalidated` 的依赖记忆，并以工作区、来源和新修订形成稳定刷新记录，避免重复投递缩小影响集合。[刷新影响集合快照 ↗](../../../apps/server/src/learning/refresh.ts#L6 "支持冻结首次发现的失效记忆集合、稳定刷新记录及重复投递复用。") 若新 revision 仍是当前 head，系统复用正常 extractor 身份重新入队；若来源已经前进，则直接触发对账。[刷新任务重新入队 ↗](../../../apps/server/src/learning/pipeline.ts#L126 "支持来源 head 检查、来源前进时对账以及复用 extractor 身份重新排队。") 提取无提案、提取失败、复核完成或复核失败也都会调用刷新对账。[提取、复核与刷新对账编排 ↗](../../../apps/server/src/learning/pipeline.ts#L421 "支持提案生成、复核子作业、输出一致性检查、整批评估，以及提取或复核各结果分支调用刷新对账。")

最终状态依据实际应用结果决定：指定来源 head 已前进时为 `superseded`，冻结记忆全部恢复时为 `applied`，否则保持 `needs_review`。不过修复查询没有用刷新记录的 `source_id` 限定依赖来源，因此尚不能断言命中的依赖必然属于该来源。[刷新记录状态判定 ↗](../../../apps/server/src/learning/refresh.ts#L27 "支持 applied、needs_review、superseded 的判定条件，并揭示修复查询未显式限定刷新记录来源。") 底层 worker 通过租约、心跳和取消信号执行处理器；心跳失效会中止运行，停机中断按瞬态失败记录。[持久化 worker 的租约与取消 ↗](../../../apps/server/src/jobs/worker.ts#L47 "支持作业领取、心跳续租、租约失效、主动取消和停机中断语义。")

<a id="traceability-and-limits"></a>
## 可追溯性与当前限制

每次角色运行都会保存实际模型、effort、运行哈希、会话、已加载技能、允许工具、用量、输出与完整 trace。[角色运行记录保存 ↗](../../../apps/server/src/learning/pipeline.ts#L332 "支持保存实际模型、effort、各类哈希、会话、技能、工具、用量、输出和完整运行 trace。") 流水线另有单次处理、限量 `drain`、后台轮询、状态查询、取消和停止能力。[流水线生命周期控制 ↗](../../../apps/server/src/learning/pipeline.ts#L572 "支持单次处理、限量 drain、轮询、状态、取消和停止能力。")

当前关键限制是批量批准：合并确认事项保存全部 parked 提案摘要，并提供“整体按提案应用”的语义，但决定行只锚定代表提案的摘要。[批量确认的代表提案锚点 ↗](../../../apps/server/src/memory/service.ts#L1522 "支持合并确认保存全部提案摘要、声明整体应用选项，但决定行只锚定代表提案摘要。") 已提供的通用批准路径仅按该锚点加载并应用一个提案，没有展示遍历整批或原子应用全部提案的逻辑。[通用决定的单提案应用路径 ↗](../../../apps/server/src/memory/service.ts#L1697 "支持批准流程按决定锚点加载单个提案并调用一次应用逻辑，未展示整批遍历。") 因而不能把该合并确认语义视为整批批准已经实现；刷新来源限定和捕获拆分映射也仍需数据库约束及端到端测试补证。
