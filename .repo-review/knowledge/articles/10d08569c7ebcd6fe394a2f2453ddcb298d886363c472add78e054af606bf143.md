# learning · 模块理解

learning 模块以持久作业串联记忆候选提取、独立复核、整批策略应用和来源变更重核验，通过固定修订、逐片段来源、运行指纹与稳定摘要维持可追溯性。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-context"></a>
## 职责与可信输入

该模块把原始捕获转化为可审查的记忆变更，而非直接把模型输出写成事实。`LearningPipeline` 只领取候选提取、提案复核和依赖刷新三类作业，并把模型、effort 及阶段哈希纳入执行指纹。[学习流水线的作业与可信上下文 ↗](5d7f1fb09279c4326beba8fb40838bf744a9aa7218a1f0c8a4d5e298830a201a.md#jobs-context "子知识解释了模块限定作业种类、执行指纹和可信上下文构造，用于概括模块定位。")[持久 worker 与执行指纹 ↗](../../../apps/server/src/learning/pipeline.ts#L65 "支持流水线只处理三类学习作业，并把模型、effort 和阶段哈希写入执行指纹。") 构造角色上下文时会确认修订仍是来源 head，且来源标识与 validity epoch 未漂移；会话位置不被当作可信项目。固定 fragment 还会重新对应原始 part，以保留说话人、时间、回复、引用、转发和图片资产等来源信息。[修订新鲜度与逐片段来源 ↗](../../../apps/server/src/learning/pipeline.ts#L180 "支持拒绝过期修订、区分会话位置与可信项目，并将原始 part 的来源信息和图片带入角色上下文。")

<a id="extract-verify-apply"></a>
## 提取、独立复核与整批应用

提取阶段调用 extractor，校验并保存 ProposalBatch、运行 trace 与观察记录；存在候选时才入列 verifier，没有候选则以 abstention 核对来源刷新状态。[候选提取阶段 ↗](../../../apps/server/src/learning/pipeline.ts#L420 "支持 extractor 执行、输出和观察保存、verifier 入列、无候选收敛及异常回写流程。") 复核阶段先验证父作业、已存输出的 schema、摘要、作业标识和角色 bundle 哈希，再生成稳定 proposal 标识并应用已确认纠正。verifier 必须逐项覆盖且摘要完全匹配，随后全部候选作为一个 ChangeSet 交给批量策略评估，统一决定自动应用、等待决策或拒绝，避免拆单绕过影响预算。[提取与独立复核流程 ↗](5d7f1fb09279c4326beba8fb40838bf744a9aa7218a1f0c8a4d5e298830a201a.md#extract-verify "子知识组织了提取、父输出完整性校验、独立复核和整批策略应用之间的关系。")[复核完整性与整批策略评估 ↗](../../../apps/server/src/learning/pipeline.ts#L457 "支持父作业及输出摘要核验、逐候选覆盖检查，并以完整 ChangeSet 调用批量策略评估。")

<a id="refresh-relations"></a>
## 来源更新与模块协作

来源更新先冻结受影响的失效记忆集合，并以工作区、来源和新修订生成幂等记录；其身份依赖递归规范化对象键后计算的 SHA-256 摘要。[冻结来源刷新影响集合 ↗](819a9f2861dfc7f9e280c99318c412655c30248d504b23e3367dc5edf2f0ef7e.md#purpose "解释刷新记录如何选择来源引用、冻结受影响记忆并以稳定键保证重复投递的一致性。")[规范化摘要实现 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持刷新记录及执行身份所用摘要基于规范化 JSON 和 SHA-256 计算。") 若新修订仍是当前 head，流水线以捕获阶段相同的 extractor 身份重新入列；若来源已经前进，则立即核对并把旧刷新记为 superseded。[来源刷新分支与重新入列 ↗](../../../apps/server/src/learning/pipeline.ts#L126 "直接支持流水线读取首项引用、判断来源是否前进、标记 superseded，并以相同 extractor 身份重新入列的论断。") **替代旧结论：**此前把刷新流程笼统描述为同时连接检索、反馈等服务，范围过宽；当前材料能直接确认的是刷新记录、来源状态、持久作业队列与提取角色之间的协作。检索和反馈参与通用上下文构造及纠正应用，但不是刷新分支自身的全部调用链。[修订新鲜度与逐片段来源 ↗](../../../apps/server/src/learning/pipeline.ts#L180 "支持拒绝过期修订、区分会话位置与可信项目，并将原始 part 的来源信息和图片带入角色上下文。")[复核完整性与整批策略评估 ↗](../../../apps/server/src/learning/pipeline.ts#L457 "支持父作业及输出摘要核验、逐候选覆盖检查，并以完整 ChangeSet 调用批量策略评估。")

<a id="progress-limits"></a>
## 运行能力、错误边界与未决限制

流水线提供单步处理、有限排空、后台轮询、取消、状态查询和停止能力；达到排空上限会显式报错。[轮询、排空与停止控制 ↗](../../../apps/server/src/learning/pipeline.ts#L571 "支持单步处理、排空上限、后台轮询、取消、状态报告和停止语义。") 错误在公开前会遮蔽令牌、凭据等敏感内容，并分类为坏输出、认证、暂态、配置或永久错误。[公开错误脱敏与分类 ↗](../../../apps/server/src/learning/pipeline.ts#L30 "直接支持敏感凭据遮蔽，以及坏输出、认证、暂态、配置和永久错误的分类规则。") “成功入列”不等于记忆已修复：只有受影响记忆恢复 active、依赖指向新修订且来源 head 一致时，记录才成为 applied；否则保持 needs_review，来源前进则成为 superseded。[刷新结果的状态边界 ↗](819a9f2861dfc7f9e280c99318c412655c30248d504b23e3367dc5edf2f0ef7e.md#reconciliation "子知识解释入列与实际应用成功的区别，以及 applied、needs_review 和 superseded 的判定。")[依据当前依赖核对刷新结果 ↗](../../../apps/server/src/learning/refresh.ts#L27 "支持仅在记忆状态、当前依赖和来源 head 全部吻合时标记 applied。") 当前刷新记录会寻找第一组有效来源，而流水线后续直接读取引用数组第一项；两者在多来源或排序异常输入下可能不一致。[冻结来源刷新影响集合 ↗](819a9f2861dfc7f9e280c99318c412655c30248d504b23e3367dc5edf2f0ef7e.md#purpose "解释刷新记录如何选择来源引用、冻结受影响记忆并以稳定键保证重复投递的一致性。")[来源刷新分支与重新入列 ↗](../../../apps/server/src/learning/pipeline.ts#L126 "直接支持流水线读取首项引用、判断来源是否前进、标记 superseded，并以相同 extractor 身份重新入列的论断。")
