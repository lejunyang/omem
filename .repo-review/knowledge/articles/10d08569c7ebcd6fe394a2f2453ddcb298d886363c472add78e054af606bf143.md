# learning · 模块理解

learning 模块连接原始捕获、角色运行时与记忆治理：它确认固定修订仍然有效，生成并独立复核提案，再把整批候选交给 MemoryService 决定应用、延后、保留、拒绝或请求确认；来源更新则触发失效记忆的重新核验。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role"></a>
## 作用、边界与可追溯性

learning 领取提取、提案复核和依赖刷新三类持久任务，并校验 extractor、verifier 的角色包是否匹配配置档。任务领取指纹包含模型、effort，以及由流水线版本、配置档和阶段名生成的 prompt、skill、tool 哈希；它不是实际运行内容的完整快照。[学习任务范围与领取指纹 ↗](../../../apps/server/src/learning/pipeline.ts#L73 "支持模块领取的任务种类、角色配置校验，以及领取指纹包含模型、effort和阶段摘要而非完整运行内容。") 角色执行后另行保存有效模型与 effort、各类哈希、输出 schema、会话、已加载技能与允许工具清单、用量、模型输出及运行 trace。此前“领取指纹直接覆盖完整提示词、技能和工具内容”的结论已被替代。[角色输出与运行轨迹保存 ↗](../../../apps/server/src/learning/pipeline.ts#L331 "支持实际持久化的模型、effort、哈希、清单、用量、输出及运行轨迹字段。") 当前底层仍是单用户 SQLite，不能据此宣称已有团队租户强制隔离。[单用户 SQLite 存储边界 ↗](../../../apps/server/src/store.ts#L1 "支持当前存储是单用户基础、团队级强制隔离仍属后续迁移的限制。")

<a id="flow"></a>
## 从固定证据到受治理记忆

运行前会确认任务引用的修订仍是来源 head，sourceId 与 validity epoch 均未变化；上下文保留逐部件作者、回复、时间、转发、引用和图片资产信息，同时不把会话标识当作可信项目。[当前修订与证据上下文校验 ↗](../../../apps/server/src/learning/pipeline.ts#L180 "支持来源 head、来源身份、有效期校验，以及逐部件来源信息、图片资产和不可信项目边界。") 捕获侧按文本段落、链接、图片的确定顺序生成 fragment，[捕获侧固定片段拆分规则 ↗](../../../apps/server/src/store.ts#L208 "给出文本段落、链接和图片生成 fragment 的实际顺序，支持两侧必须保持一致的说明。") learning 再手工镜像该顺序，把 fragment ordinal 回接到原始 part；两处若不同步，逐部件 provenance 可能错配。[逐部件映射的镜像约束 ↗](../../../apps/server/src/learning/pipeline.ts#L310 "支持 learning 手工复现捕获拆分顺序，以及规则漂移可能导致 fragment 与 part 来源错配的限制。")

提取器产出结构化候选与观察记录，有候选时创建独立 verifier 任务。复核阶段校验父任务、已存输出摘要、角色包摘要、候选覆盖和提案摘要绑定，并由宿主重建候选身份；随后所有候选连同各自 verdict 一次性交给 `evaluateBatch`。[提取、独立复核与整批评估入口 ↗](../../../apps/server/src/learning/pipeline.ts#L420 "支持提案生成、父子输出绑定、候选身份重建、复核覆盖与摘要校验，以及所有候选连同 verdict 进入整批评估。") MemoryService 按受影响记忆与新实体的去重并集计算整批影响。超预算时只暂停原本会自动应用的项；仅当确有被暂停项时，才创建一次合并确认。若所有条目最终均为拒绝、延后、仅保留来源、忽略噪声或不产生新应用的重复项，则不会生成该批量确认。此前“超预算必然生成合并确认”的结论已被替代。[整批影响预算与合并确认条件 ↗](../../../apps/server/src/memory/service.ts#L1471 "支持整批去重计算影响、暂停原本可自动应用的条目，并证明只有存在被暂停条目时才创建合并确认。")

<a id="refresh_limits"></a>
## 来源刷新、循环防护与限制

来源产生新修订后，旧依赖会标为 stale、相关记忆变为 invalidated，并排入依赖刷新任务。[新修订引发依赖失效与刷新入列 ↗](../../../apps/server/src/store.ts#L244 "支持来源更新后旧依赖置为 stale、记忆失效以及 refresh_dependents 任务入列。") 派生材料不会进入捕获后的 `extract_claims` 队列，以免模型总结自循环为独立证据；原始 Agent 会话仍可进入学习流程。[派生材料学习队列过滤 ↗](../../../apps/server/src/store.ts#L355 "支持派生材料不进入 extract_claims 队列，而原始 Agent 会话仍可进入学习流程的循环防护边界。")

刷新记录会冻结最初受影响集合；queued 只表示已入列。只有记忆重新 active、依赖指向新修订且来源 head 一致时才算 applied，来源继续前进则记为 superseded，否则保持 needs_review。[刷新影响冻结与结果协调 ↗](../../../apps/server/src/learning/refresh.ts#L6 "支持冻结最初影响集合，并依据当前记忆、依赖和来源 head 区分 applied、superseded 与 needs_review。") 流水线提供单步处理、有限排空、轮询、取消和停止，但这些实现分支本身不是端到端运行证明。[学习流水线运行控制 ↗](../../../apps/server/src/learning/pipeline.ts#L571 "支持单步处理、有限排空、轮询、取消、状态查询和停止等运行接口。")
