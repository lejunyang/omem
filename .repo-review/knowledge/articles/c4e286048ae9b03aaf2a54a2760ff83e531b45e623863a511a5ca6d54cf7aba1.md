# 批量补建语义检索索引脚本

该脚本是大量导入后的显式语义索引追赶入口：按普通或 repo-review 模式选择配置与 Store，评审模式先准备仓库材料、知识与代码数据，再以固定批次建立索引。它直接创建语义检索器，并传入中文 embedding 加载回调。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-setup"></a>
## 用途、模式与配置边界

该脚本用于大量导入后的显式索引追赶，服务器仍负责后续捕获的持续索引。它以 `--review` 区分普通与评审模式：前者使用应用配置和个人 Store，后者读取可由环境变量指定的检索配置并创建 repo-review Store；随后直接实例化 `SemanticRetrieval`，向其传入调用 `loadChineseEmbedding` 的回调。[索引脚本的模式选择与检索器初始化 ↗](../../../scripts/retrieval-index.ts#L1 "支持脚本用途、普通与评审配置和 Store 的选择，以及向语义检索器传入 embedding 加载回调的论断；不用于推断回调执行时机。") 现有材料未包含语义检索器实现，因此此前“仅在真正需要向量时才加载模型”的结论被替代，不能据此确认回调的实际执行时机。

标准工厂会严格解析 `enabled` 和模型别名；未启用时返回关键词检索，启用后才创建、启动语义检索器。[标准检索工厂的启用开关 ↗](../../../apps/server/src/retrieval/factory.ts#L9 "支持配置严格解析、未启用时使用关键词检索，以及启用后才创建并启动语义检索器的边界。") 补建脚本没有经过该工厂，因此是否有意绕过 `enabled=false` 仍需确认。

<a id="review-preparation"></a>
## 评审数据准备与隔离职责

评审模式在批量索引前依次调用仓库材料同步、知识恢复和代码同步。材料只能证明调用顺序，不能在缺少两个同步函数实现的情况下断言其具体写入效果。[评审预同步调用顺序 ↗](../../../scripts/retrieval-index.ts#L16 "支持评审模式在索引循环前依次调用仓库同步、知识恢复和代码同步，但不外推未提供实现的写入效果。") 已提供的知识恢复流程会载入保存的用户补充、捕获仓库材料、恢复知识文章，并为尚未参与重核对的回答记录失效原因，最后刷新知识仓库。[评审知识恢复流程 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持用户补充、仓库材料和知识文章的恢复，以及未参与重核对回答的失效记录与仓库刷新。")

repo-review 复用共享的 Store、capture 与 retrieval 原语，但数据目录、SQLite 和评审专属路径状态相互隔离，不接触个人工作区、Lark/学习 worker 或 secrets。[评审 Store 的隔离边界 ↗](../../../apps/server/src/review/store.ts#L1 "支持 repo-review 复用通用数据原语但隔离运行数据、个人工作区和评审专属元数据的论断。")

<a id="batching-and-cleanup"></a>
## 批处理、模型约束与清理限制

核心循环每次调用 `indexBatch(16)`：零值结束，非零则累计数量并输出健康状态；完成后打印包含 `completed: true` 的 JSON。`finally` 先等待检索器关闭，再关闭 Store；若前一关闭操作抛错，后一操作不会执行，故只能确认正常路径上的关闭顺序。[批次循环与资源关闭顺序 ↗](../../../scripts/retrieval-index.ts#L16 "支持固定批次、零值退出、完成输出，以及先关闭检索器再关闭 Store 的实际控制流与限制。")

中文 embedding 由 osdk 查询固定模型快照，校验仓库、revision 和文件哈希，禁止远程模型与文件缓存，并以本地 CPU、量化权重初始化。[中文向量模型的离线加载约束 ↗](../../../apps/server/src/retrieval/embedding.ts#L14 "支持固定模型快照、文件哈希校验、禁止远程模型，以及本地 CPU 量化初始化的运行边界。") 模型缺失、身份不符或校验失败都会使加载失败；现有材料未提供端到端测试结果，无法确认各失败路径的实际退出码与资源释放表现。
