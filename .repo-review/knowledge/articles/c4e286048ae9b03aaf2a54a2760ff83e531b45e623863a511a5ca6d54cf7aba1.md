# 检索索引补建脚本

该脚本为普通个人数据或隔离的 repo-review 数据执行显式语义索引追赶：按模式选择配置与存储，评审模式先同步和恢复材料，再循环批量索引。正常收尾会依次关闭检索器与 store，但若检索器关闭失败，store 关闭可能不会执行。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-mode"></a>
## 用途与运行模式

该脚本用于大批量导入后的显式索引追赶；注释同时说明，后续捕获还会由服务器继续索引。它根据 `review` 标志选择环境：评审模式读取仓库检索配置并创建隔离 store，普通模式沿用应用配置和数据目录，随后直接构造语义检索器。[检索补建入口与模式选择 ↗](../../../scripts/retrieval-index.ts#L2 "支持脚本的显式追赶用途，以及 review 与普通模式对配置、存储和语义检索器的选择。") `review` 标志既可来自 osdk 注入的环境变量，也可来自 Bun 命令行的 `--review`，使同一入口适用于任务系统与直接调用。[任务标志解析 ↗](../../../scripts/task-args.ts#L1 "支持 review 标志可由 osdk 环境变量或直接命令行参数提供。")

<a id="indexing-flow"></a>
## 同步与批量索引流程

评审模式开始索引前，会依次执行仓库材料同步、已发布知识恢复和代码同步，使这些来源先进入当前 store。[评审数据准备顺序 ↗](../../../scripts/retrieval-index.ts#L17 "支持评审模式在批量索引前依次执行材料同步、知识恢复和代码同步。") 主循环固定调用 `indexBatch(16)`，返回零时结束，并累计输出已索引片段数与健康状态；完成后打印包含 `completed: true` 的 JSON。`finally` 的正常关闭路径先等待 `retrieval.close()`，再调用 `store.close()`；但两者不是彼此隔离的清理步骤，若前者拒绝或抛错，后者可能不会执行，因此不能据此宣称所有失败场景都能可靠释放数据库资源。[批处理循环与关闭顺序 ↗](../../../scripts/retrieval-index.ts#L19 "支持批大小、终止条件、完成输出，以及先等待检索器关闭再关闭 store 的顺序和相应失败边界。")

<a id="dependencies-and-boundaries"></a>
## 模型依赖与已知边界

检索工厂在语义检索未启用时会回退到关键词检索，而本脚本直接实例化 `SemanticRetrieval`，所以它是语义索引维护入口，并不走该回退分支。[检索工厂的启用与回退规则 ↗](../../../apps/server/src/retrieval/factory.ts#L9 "说明通用工厂在未启用语义检索时回退关键词检索，用于界定补建脚本直接构造语义检索器的差异。") 中文 embedding 由 osdk 提供固定快照：加载时核对仓库、revision 与文件校验和，禁止远程模型和文件系统缓存下载，并把权重哈希纳入向量身份。[中文向量模型固定快照加载 ↗](../../../apps/server/src/retrieval/embedding.ts#L14 "支持模型来源与校验和验证、离线加载约束、向量身份组成和查询前缀处理。") 评审知识恢复会导入用户回答、捕获仓库材料、恢复文章并刷新知识仓库；这解释了其在索引前的位置。[评审知识恢复流程 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持索引前恢复用户回答、仓库材料和知识文章并刷新知识仓库的作用。") 不过现有材料没有展示 `indexBatch` 的事务、失败恢复或并发语义，也没有给出 review/code sync 的具体产物与失败保留策略。
