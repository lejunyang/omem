# 语义索引显式追平脚本

为普通数据目录或 repo-review 隔离环境补建语义索引；review 模式先同步仓库材料、恢复已发布知识并同步代码结构，再以固定批量索引至完成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="modes-and-dependencies"></a>
## 双运行模式

该脚本是大批量导入后的显式追平入口，补充服务器对后续捕获的常规索引。默认模式读取应用检索配置并打开普通 Store；`--review` 模式读取 review 检索配置并创建隔离 Store。两种模式都把各自配置中的可选 `osdkModel` 传给中文 embedding 加载器，再构造 SemanticRetrieval。[索引模式与可选模型配置 ↗](../../../scripts/retrieval-index.ts#L1 "支持普通和 review 两种配置、Store 选择，以及可选 osdkModel 被传给中文 embedding 加载器。") 可选链意味着材料没有证明每次运行都显式指定模型，也没有展示加载器缺省行为。

<a id="review-preparation"></a>
## 评审数据准备顺序

review 模式在索引前依次执行 review sync、恢复已发布知识和 code sync。[review 索引前同步流程 ↗](../../../scripts/retrieval-index.ts#L16 "支持 review 模式依次同步仓库材料、恢复知识并同步代码结构。") 因此待索引数据可包含仓库原始材料、已保存知识及代码派生结构；脚本只负责将这些已进入 Store 的内容追平到语义索引，本身不生成新知识或调用生成式模型。

<a id="batch-loop-and-boundaries"></a>
## 批处理与资源边界

索引以每批 16 条循环执行，`indexBatch` 返回空时结束；过程中输出累计 fragment 数与 health，完成后输出最终健康状态，`finally` 始终关闭检索器和 Store。[索引循环与关闭 ↗](../../../scripts/retrieval-index.ts#L18 "支持固定批量追平、进度和健康输出，以及最终资源关闭。") 脚本没有展示跨同步步骤的事务、断点恢复或搜索质量断言；任一步抛错会终止本次流程，是否可安全重跑取决于下层幂等合同。
