# 代码图的人类可读 DTO 投影

把快照、文件、符号和边的内部记录扩展为前端可展示、可深链的 DTO，同时保留内部动作键，并明确表达删除、缺失和过期状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="projection"></a>
## 投影原则

该模块解决“内部标识可用于路由、却不能直接充当界面文案”的问题。DTO 保留原始行的全部字段，以便前端继续使用文件、符号和边标识执行动作；同时补充 `displayTitle`、`displayPath`、`citationLabel`、`actionable` 与 `reason` 等人类可读字段。删除或不可解析对象不会被悄悄隐藏，而是显式变成不可操作状态。[DTO 展示字段约定 ↗](../../../apps/server/src/code/dto.ts#L1 "说明原始动作键与人类可读字段并存，以及缺失或过期对象的处理原则。")

<a id="nodes"></a>
## 快照、文件与符号

快照标题使用缩短后的提交号；无提交时区分脏工作区和无提交状态，并生成 API 与 trail 深链。[快照 DTO ↗](../../../apps/server/src/code/dto.ts#L13 "支持提交缩写、快照摘要及深链的生成方式。") 文件标题取路径末段，但完整路径仍用于展示和引用；已删除文件保留记录并附带原因。符号通常展示限定名，路由和测试则展示简短名称；若有文件上下文，源码链接会携带声明起止行，否则退回符号详情接口。[文件与符号 DTO ↗](../../../apps/server/src/code/dto.ts#L35 "支持文件删除状态、符号显示名称以及源码范围链接的说明。")

<a id="edges"></a>
## 关系展示与边界

边类型通过固定映射转成人类可读短语，再由两端标签组合标题。`confirmed` 与 `candidate` 均允许交互，`missing` 和 `stale` 则不可操作，并分别说明目标未解析或已被新快照取代。[边 DTO 与状态原因 ↗](../../../apps/server/src/code/dto.ts#L78 "支持边标签映射、可操作状态判定和缺失或过期原因。") 这里仅负责表现已有状态，不验证边是否真实，也不解析端点；若调用方没有提供标签，界面会显示问号，因此完整可读性依赖上游端点展开。
