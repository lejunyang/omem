# Code Wiki 视口与证据 Trail 浏览器验收

针对运行中的 Code Wiki Web/API，以稳定可见名称穿透真实界面，验证模块知识、源码帧、层栈导航、深链恢复、Markdown 清洗、内部标识隐藏、焦点结果和移动端布局。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="setup_contract"></a>
## 验收定位与运行前提

脚本不启动服务或同步数据，而是连接指定 Web 地址，先从代码图确认 `runtime.ts` 与 `memory/service.ts` 存在，再用 Playwright 在 1440、768、390 三种真实模拟视口检查页面无横向溢出。[稳定路径与多视口测试装配 ↗](../../../scripts/code-wiki-viewport.ts#L1 "支持脚本依赖运行中服务、按稳定路径确认代码图目标，并使用真实视口模拟检查布局的说明。") 因而健康的 review API、已同步代码图和模块知识都是前置条件；缺失目标会立即失败，不会自动生成或修复数据。

<a id="trail_flow"></a>
## 模块阅读与层栈流程

测试先确认 assistant 模块呈现足量知识正文，再从 `runtime.ts` 文件行打开源码帧，检查行号与高亮；随后点击明确命名的同文件 `governCreateTask` 调用边。[源码 Trail 推进与深链恢复 ↗](../../../scripts/code-wiki-viewport.ts#L74 "支持进入源码、点击明确同文件调用边、沿其他可用边推进，以及弹栈、跳转和刷新恢复的流程描述。") 返回文件帧后，它仅选择首个未禁用边继续推进，并验证 Esc 弹栈、面包屑跳转和 UI 生成 URL 的刷新恢复。由于后续选择器没有断言边类型或目标，注释中的“import edge”不足以证明特定导入关系，更不能证明任意跨文件调用已解析。

<a id="security_accessibility"></a>
## 安全、标签与可访问性边界

脚本把恶意 Markdown 注入实际挂载的组件实例，断言脚本、事件属性、危险协议及若干主动内容元素被移除；同时扫描 Trail 可见文字，禁止出现符号、文件、片段内部 ID 或 UUID。[Markdown 清洗与内部标识隐藏 ↗](../../../scripts/code-wiki-viewport.ts#L174 "支持实际挂载组件上的恶意 Markdown 清洗断言，以及可见 Trail 文本不展示内部标识的检查。") 关闭全部后，它只读取当前焦点元素文本并断言其中含 `assistant`，没有核验该元素就是先前的模块卡片或打开 Trail 的文件行，因此只能证明这一较弱的焦点结果。[关闭后的焦点文本与移动端抽屉 ↗](../../../scripts/code-wiki-viewport.ts#L229 "支持关闭全部后仅检查当前焦点元素文本含 assistant，以及 overview 基础内容和移动端抽屉宽度的收窄结论。") 此外，所谓模型不可用检查仅确认 overview 仍显示“可追溯的知识”，未主动配置模型故障；移动端则验证抽屉宽度超过视口的 95%。未覆盖完整 WCAG、跨浏览器差异、全部 XSS 绕过变体及超长深链上限。
