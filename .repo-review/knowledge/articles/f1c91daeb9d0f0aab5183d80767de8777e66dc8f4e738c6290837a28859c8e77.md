# Code Wiki 浏览器验收脚本

该 Playwright 脚本从真实 Code Wiki 页面验收响应式布局、知识正文、证据 Trail、深链重载后的基本可读性、Markdown 安全、内部标识隐藏和焦点归还，并保存截图与检查结果。它依赖已启动且含指定代码图数据的 review 服务；第四帧、深链恢复和所谓“模型不可用”检查均存在断言边界，不能视为对应能力的完整证明。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_setup"></a>
## 目标与运行前提

脚本是 Code Wiki 功能切片的外部浏览器验收入口：默认访问本机 5181，可由环境变量覆盖；截图写入实现文档目录，Chromium 以无头模式运行。执行前先通过代码图按稳定路径确认 `runtime.ts` 与 `memory/service.ts` 存在，不把数据库 ID 写死在脚本中。[浏览器与代码图初始化 ↗](../../../scripts/code-wiki-viewport.ts#L16 "支持默认地址、截图目录、无头浏览器配置以及按稳定路径确认前置代码图数据的说明。")

页面运行期间会收集页面异常以及高亮、动态导入相关的部分控制台警告或错误。[页面错误收集 ↗](../../../scripts/code-wiki-viewport.ts#L54 "支持页面异常监听及对高亮、动态导入相关控制台消息的筛选范围。") 全部检查结束后要求错误集合为空；无论检查成功还是抛错，`finally` 都会关闭浏览器并输出已通过检查与错误列表。[最终校验、浏览器清理与结果输出 ↗](../../../scripts/code-wiki-viewport.ts#L275 "支持错误集合最终断言，以及 finally 中关闭浏览器并输出检查和错误列表的论断。") 脚本本身不负责启动服务或构造测试数据库。

<a id="responsive_content"></a>
## 响应式布局与知识内容

脚本以 1440、768、390 三种真实 viewport 打开概览页，断言页面没有横向溢出并分别截图；随后进入 assistant 模块，要求职责文本可见、没有常见加载失败提示、知识正文或模块条目非空，且主内容长度超过 300 字，用于排除空壳页面。[多视口与模块正文断言 ↗](../../../scripts/code-wiki-viewport.ts#L61 "支持三种视口的横向溢出检查、截图，以及模块职责正文、加载错误和内容长度断言。")

移动端另行确认知识内容可见，并在点击 `runtime.ts` 后要求 Trail 抽屉宽度超过视口的 95%。[390 像素移动端抽屉检查 ↗](../../../scripts/code-wiki-viewport.ts#L259 "支持窄屏知识内容可见、点击文件行以及抽屉接近全宽的移动端断言。") 这些检查覆盖基本尺寸和内容可用性，但未验证断点排版细节、触控手势、纵向溢出或截图视觉差异。

<a id="trail_flow"></a>
## 证据 Trail 的核心交互流程

主流程从模块页打开 `runtime.ts` 文件帧，验证源码行、高亮关键字及字重；再沿同文件的 `governCreateTask` 边进入符号或范围帧，以面包屑和源码行数确认压栈。[文件帧与同文件调用边 ↗](../../../scripts/code-wiki-viewport.ts#L87 "支持从 runtime.ts 源码帧进入 governCreateTask 符号或范围帧，以及源码高亮和面包屑增长的流程。") 随后用 Escape 返回文件帧，沿可用边继续下钻，并检查弹栈与面包屑跳转。[弹栈、跳转与深链重载 ↗](../../../scripts/code-wiki-viewport.ts#L112 "支持 Escape 回退、边下钻、面包屑跳转及深链重载后的实际断言，并表明第四帧点击是条件执行、深链仅要求至少一个帧。")

深链检查保存 UI 生成的 `/trail/` URL 后重载，只断言重载后至少存在一个面包屑且没有获取失败，因此至多证明恢复了一个可读 Trail 帧，不能证明重载前后的完整帧数量、顺序和内容等价。第四帧点击也受可用边是否存在影响，最终仅要求不少于两个面包屑，尚未严格证明形成四层栈。

<a id="security_accessibility_limits"></a>
## 安全、可读标识、焦点与降级边界

安全检查先取得 fragment ID 并挂载真实 `OmMarkdown`，再通过 Vue 组件实例注入含脚本、事件处理器、`javascript:` 链接、SVG 和 iframe 的载荷；断言载荷没有执行，危险节点和属性也未保留。[真实 Markdown 组件 XSS 验收 ↗](../../../scripts/code-wiki-viewport.ts#L174 "支持通过已挂载 OmMarkdown 注入固定恶意载荷，并检查执行副作用、危险节点、事件属性和 javascript 链接。") 这验证了固定载荷的客户端清洗效果，但依赖 Vue 私有字段，不能代表所有编码方式或内容入口均已覆盖。

脚本还禁止抽屉可见文本暴露内部符号、文件、片段 ID 或 UUID，并要求关闭全部帧后焦点回到 assistant 触发卡片。[内部标识隐藏与焦点归还 ↗](../../../scripts/code-wiki-viewport.ts#L218 "支持可见抽屉文本不得出现内部 ID，以及关闭全部 Trail 后焦点回到 assistant 模块卡片的断言。") 所谓“模型不可用”步骤实际上只访问普通概览、检查通用文案并截图，没有构造模型故障，也没有断言降级原因或原始代码图仍可操作；它不能作为降级展示已经通过验收的证据。[所谓模型不可用场景的实际断言 ↗](../../../scripts/code-wiki-viewport.ts#L251 "支持该步骤实际只检查概览通用文案并截图，未构造故障或验证明确降级行为的限制判断。")
