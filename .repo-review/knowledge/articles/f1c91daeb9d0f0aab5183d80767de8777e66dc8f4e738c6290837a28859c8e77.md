# 知识库真实界面的浏览器验收

该 Playwright 脚本从统一应用入口验证仓库知识的目录、文章、引用阅读链、原始 Markdown 与多尺寸布局，并保存截图和结构化报告。它依赖已启动且已准备好知识文章、原始材料及引用数据的服务，覆盖关键阅读路径，但不等同于完整视觉回归或后端正确性验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 验证真实知识阅读场景

脚本连接已经运行的个人应用，通过可配置地址启动无头 Chromium，同时收集成功检查和页面脚本错误；访问 API 时，非成功响应会立即使检查失败。测试按可读名称寻找内容，固定标识则从真实 API 动态取得，因此验证的是**页面与实际知识数据的协作结果**。参考 [浏览器验收基础设施 ↗](../../../scripts/code-wiki-viewport.ts#L1 "支持脚本连接真实服务、使用无头浏览器、检查 HTTP 状态并收集页面错误的说明。")

首个场景从“知识库”入口确认知识目录、文章正文和本篇目录均可见，并通过目录 API 检查 README 原始材料及多篇主题文章已经接入。这覆盖了“仓库知识已进入统一应用并可阅读”的基础场景。参考 [知识库接入检查 ↗](../../../scripts/code-wiki-viewport.ts#L15 "支持知识目录、文章结构、README 材料和主题文章已接入的验收流程。")

<a id="navigation"></a>
## 导航状态与引用阅读链

脚本往返切换飞书机器人、日常助理、能力与连接和知识库，逐次核对页头与激活菜单一致，并要求飞书页面的局部错误不泄漏到其他页面、全局错误横幅不出现。参考 [菜单与错误隔离 ↗](../../../scripts/code-wiki-viewport.ts#L25 "支持菜单、页头、激活状态以及飞书局部错误不泄漏到其他页面的断言。")

引用场景按可读路径找到网关文章，再从 API 动态选择一个可操作的代码引用。打开抽屉后会核对固定行数和起始行，向上展开时验证新的首行；关闭抽屉后，焦点必须回到原引用链接。脚本也会点击“向下展开”，但尚未断言展开后的末行。参考 [固定代码引用阅读 ↗](../../../scripts/code-wiki-viewport.ts#L34 "支持动态发现文章与引用、精确代码行展示、上下文展开、关闭及焦点恢复的流程，也表明向下展开后没有范围断言。")

随后测试从代码证据进入知识解读的第二层阅读轨迹，验证 URL 深链、刷新恢复、逐层退出和最终关闭，并确认正文中的段落引用仍然可见。参考 [多层阅读轨迹 ↗](../../../scripts/code-wiki-viewport.ts#L54 "支持证据到知识解读的第二层导航、深链刷新恢复、逐层退出和段落引用可见性。")

<a id="documents-layout"></a>
## 原始文档与多尺寸可读性

原始材料场景确认 README 以连贯 Markdown 文档呈现：标题和代码围栏可见，界面不会暴露“片段 1”一类存储结构。参考 [README 连贯渲染 ↗](../../../scripts/code-wiki-viewport.ts#L67 "支持原始 Markdown 标题、代码围栏可见以及不暴露存储片段标签的断言。")

最后，脚本在 1440、768、390 像素宽度下检查页面没有横向溢出且标题、正文可见，并为每种尺寸保存整页截图；全部场景结束后还要求未捕获页面异常，再写出结构化报告。参考 [响应式布局与报告 ↗](../../../scripts/code-wiki-viewport.ts#L77 "支持三个视口宽度下的可读性检查、截图、页面错误汇总和报告写入，也说明截图没有视觉差异断言。")

这些检查依赖服务可访问，且知识文章、原始材料及引用数据已经准备好。截图目前只作为检查产物保存，没有像素差异断言或人工视觉结论，因此该脚本能发现关键元素缺失和明显溢出，却不能单独证明间距、遮挡等视觉细节没有退化。

<a id="scope"></a>
## 验收范围与使用边界

该脚本适合作为知识阅读主路径的浏览器冒烟验收：它覆盖入口、导航、证据抽屉、阅读轨迹、原文渲染和响应式可读性，并以页面异常和 HTTP 失败作为明确失败信号。参考 [浏览器验收基础设施 ↗](../../../scripts/code-wiki-viewport.ts#L1 "支持脚本连接真实服务、使用无头浏览器、检查 HTTP 状态并收集页面错误的说明。") [响应式布局与报告 ↗](../../../scripts/code-wiki-viewport.ts#L77 "支持三个视口宽度下的可读性检查、截图、页面错误汇总和报告写入，也说明截图没有视觉差异断言。")

它不调用搜索接口，也没有验证检索索引；同时，向下扩展范围和截图视觉差异仍缺少自动断言。因此其通过结果应理解为关键阅读流程可用，而不是检索、完整代码范围扩展或视觉表现均已得到全面验证。参考 [固定代码引用阅读 ↗](../../../scripts/code-wiki-viewport.ts#L34 "支持动态发现文章与引用、精确代码行展示、上下文展开、关闭及焦点恢复的流程，也表明向下展开后没有范围断言。")
