# 知识阅读界面的端到端验收

该脚本以真实浏览器和应用 API 验收个人知识库的关键阅读流程，覆盖章节浏览、递归证据追踪、原始材料、变更历史、连接设置、文章整理及多尺寸布局，并保存截图与结构化报告。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 用真实内容验证完整阅读体验

这是一份面向运行中 Web 应用的 **Playwright 端到端验收脚本**。它连接可配置的应用地址，启动无头 Chromium，并从真实知识目录中动态挑选当前文章，而不是依赖固定文章 ID；随后验证知识目录、文章正文、本篇目录及 README 材料确实可用。参考 [真实知识目录入口 ↗](../../../scripts/code-wiki-viewport.ts#L5 "支持脚本使用可配置服务地址、真实文章目录和动态选出的当前文章执行验收。")

脚本关注的是读者能否完成实际任务：在主菜单之间切换时，面包屑和激活菜单应保持一致；飞书页面的局部错误不得污染其他页面；原始 Markdown 应按完整文档呈现，代码围栏也必须保留。参考 [菜单与错误隔离 ↗](../../../scripts/code-wiki-viewport.ts#L32 "支持菜单、面包屑、激活状态一致以及飞书错误不扩散到其他页面的论断。") [原始文档阅读 ↗](../../../scripts/code-wiki-viewport.ts#L95 "支持 README 以完整 Markdown 文档呈现并保留代码围栏的说明。")

<a id="evidence-flow"></a>
## 递归证据阅读与状态恢复

证据验收从文章接口取得引用元数据，再点击可操作的代码引用，检查抽屉只展示引用声明的固定行段，并允许向上、向下扩展上下文。按 Esc 关闭后，焦点必须回到原触发链接，保证键盘读者能够继续操作。参考 [固定代码范围与焦点恢复 ↗](../../../scripts/code-wiki-viewport.ts#L53 "支持代码引用按固定行范围打开、扩展上下文、Esc 关闭及焦点归还的流程。")

随后脚本沿“材料的知识解读”和内部引用进入第二、第三层证据，验证层级标识、滚动位置恢复及逐层 Esc 返回。证据路径会进入 URL；刷新页面后仍应恢复到第二层，继续退出则回到第一层并最终关闭抽屉。这说明验收对象不仅是弹窗显示，还包括可分享路径和递归阅读状态。参考 [递归证据状态恢复 ↗](../../../scripts/code-wiki-viewport.ts#L67 "支持多层证据导航、滚动恢复、URL 持久化及刷新后逐层返回的说明。")

<a id="coverage-limits"></a>
## 响应式整理流程、产物与覆盖边界

脚本还验证变更历史能显示真实增删差异、Agent 能力会自动探测且本地连接无需令牌，并为关键页面保存截图。文章整理流程会在 1440、768、390 三种宽度下选择材料、进入主题步骤，检查按钮可见、对话框不横向溢出、主题输入自动聚焦，以及关闭后焦点归还。参考 [变更与连接验收 ↗](../../../scripts/code-wiki-viewport.ts#L106 "支持变更差异展示、Agent 能力自动探测、本地免令牌及截图产出的论断。") [多尺寸文章整理 ↗](../../../scripts/code-wiki-viewport.ts#L141 "支持桌面、平板和移动端文章整理对话框的可见性、无溢出、聚焦和焦点归还检查。")

最后，它在三种视口下确认页面无横向溢出、正文标题和段落可见，汇总浏览器页面错误并写出 JSON 报告；无论中途成功或失败，`finally` 都会关闭浏览器。参考 [布局报告与资源清理 ↗](../../../scripts/code-wiki-viewport.ts#L168 "支持多视口可读性检查、页面错误汇总、报告写入和浏览器最终关闭的说明。")

**边界条件**：脚本要求应用及其真实知识数据已经可访问；若目录里没有当前文章、目标网关文章、可操作引用或变更记录，断言会失败。分类展开则允许没有带主题路径的文章，恢复之前文章也仅在该文章仍存在时执行。它验证的是若干代表性页面与交互，并未证明所有文章、所有引用类型、网络失败提示或服务端写入流程都正确。参考 [数据依赖与条件分支 ↗](../../../scripts/code-wiki-viewport.ts#L129 "支持脚本依赖真实目录数据，以及分类文章和历史文章恢复采用条件执行的边界分析。")
