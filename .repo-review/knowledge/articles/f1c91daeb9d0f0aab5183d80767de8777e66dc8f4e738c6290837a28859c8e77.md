# Code Wiki 浏览器验收脚本

该脚本以无头 Chromium 和运行中的 review 服务验收 Code Wiki 功能切片，覆盖启动恢复、CDP 模拟视口布局、模块正文、证据 Trail 导航、深链重载、安全渲染、标识清洁与焦点恢复。它通过稳定名称操作界面；深链、跨文件关系和模型降级场景的结论均受现有断言范围限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_setup"></a>
## 目标与运行前提

脚本通过 Playwright 启动无头 Chromium，以 `OMEM_WEB_URL` 指定服务地址，并允许显式选择 Chromium 可执行文件；截图写入实现文档目录。运行前请求代码图，按稳定路径确认 `runtime.ts` 与 `memory/service.ts` 已同步，因此它依赖可访问的 review API、预置代码图和浏览器环境，并非自包含单元测试。[浏览器启动与代码图前置检查 ↗](../../../scripts/code-wiki-viewport.ts#L12 "支持浏览器配置、服务地址、截图目录，以及按稳定路径确认代码图前置数据的说明。")

运行期间收集页面异常，以及与高亮或动态导入有关的控制台警告和错误，最终要求错误集合为空。[页面异常与控制台消息收集 ↗](../../../scripts/code-wiki-viewport.ts#L54 "支持运行期间收集页面异常及特定高亮、动态导入警告或错误的论断。") 无论中途检查是否失败，`finally` 都会关闭浏览器并输出已完成检查和错误列表。[最终错误断言与浏览器清理 ↗](../../../scripts/code-wiki-viewport.ts#L296 "支持最终要求错误集合为空、关闭浏览器并输出检查结果的说明。")

<a id="startup_layout_content"></a>
## 启动恢复、布局与正文验收

启动场景暂时把 review 健康接口改写为 503，断言界面显示连接中和服务未就绪；等待恢复时不得轮询个人域接口，解除故障后仓库知识入口应自行出现。这验证了 review 模式对短暂 503 的独立恢复，但没有覆盖持续故障、超时上限或其他错误码。[Review API 启动恢复测试 ↗](../../../scripts/code-wiki-viewport.ts#L61 "支持模拟健康接口返回 503、禁止个人接口轮询以及恢复后显示仓库知识入口的说明。")

布局测试通过 `setViewportSize` 在 1440、768、390 三种 CDP 模拟的浏览器视口尺寸下检查文档级横向溢出并保存截图，不能据此推导真实设备或多浏览器兼容性。模块页还必须出现职责内容、足量正文及至少一个知识正文或模块条目，同时不得显示加载失败，以排除空壳和占位渲染。[CDP 模拟视口与模块正文检查 ↗](../../../scripts/code-wiki-viewport.ts#L82 "支持三种浏览器视口尺寸的横向溢出检查、截图和模块正文非空断言；结合文件注释说明这些尺寸来自 CDP 模拟。")

<a id="trail_flow"></a>
## 证据 Trail 的核心交互

脚本从模块页按可见文件名打开 `runtime.ts`，检查源码行、语法高亮及样式，再沿同文件的 `governCreateTask` 调用边进入符号范围帧。[文件帧与符号帧下钻 ↗](../../../scripts/code-wiki-viewport.ts#L108 "支持按 runtime.ts 打开源码、检查语法高亮并沿 governCreateTask 边进入符号帧的流程。") 随后验证 Escape 弹出一层、面包屑跳回旧帧，并重新加载界面生成的 `/trail/` 地址；重载断言只要求至少出现一个面包屑且没有抓取错误，因此仅证明深链恢复了可用 Trail 帧。先前关于恢复“同一完整阅读栈”的结论已被替代，因为脚本没有比较重载前后的帧数、类型、面包屑或源码内容。[Trail 回退、关系下钻与深链重载 ↗](../../../scripts/code-wiki-viewport.ts#L133 "支持 Escape 回退、关系边下钻、面包屑跳转及深链重载，也界定了完整栈等价和固定关系语义尚未被断言。")

关系下钻选择当前页面首个未禁用边，主要断言面包屑增长且没有抓取错误；它能证明 Trail 可导航，却不能确认所选边具有预期的跨文件来源、目标和关系语义。第四帧在没有可用边时还会跳过点击，只保留较弱的栈状态断言。[Trail 回退、关系下钻与深链重载 ↗](../../../scripts/code-wiki-viewport.ts#L133 "支持 Escape 回退、关系边下钻、面包屑跳转及深链重载，也界定了完整栈等价和固定关系语义尚未被断言。")

<a id="security_accessibility_limits"></a>
## 安全、可见性与未覆盖边界

安全检查通过搜索取得片段标识，在真实挂载的 `OmMarkdown` 中注入脚本、图片错误处理器、`javascript:` 链接、SVG、iframe 和鼠标事件载荷。断言确认载荷未执行，且检查结果中没有 `script`、`img`、`svg`、`iframe`、`onerror` 与 `javascript:`；但没有直接检查保留的 `<b>` 是否仍含 `onmouseover`，故不能概括为全部事件属性均已清除。[真实 Markdown 组件的安全检查 ↗](../../../scripts/code-wiki-viewport.ts#L195 "支持恶意载荷的注入方式和实际检查项目，并表明 onmouseover 属性未被单独读取断言。")

可见文本检查仅确认抽屉中未出现正则覆盖的 `sym_`、`file_`、`frag_` 或 `fragment_` 前缀标识、32 位以上十六进制串及标准 UUID 格式。先前“不会泄露任何内部标识或 UUID”的宽泛结论已被这一明确范围替代。脚本还验证关闭全部帧后焦点返回模块卡片，以及 390 像素视口下抽屉宽度超过视口的 95%。[标识格式、焦点、降级与移动抽屉检查 ↗](../../../scripts/code-wiki-viewport.ts#L239 "支持特定正则覆盖的标识格式检查、焦点恢复、概览文字检查和窄屏抽屉断言，同时界定模型故障未被显式模拟。") 所谓“模型不可用”场景只是重新打开概览并检查“可追溯的知识”文字，既未注入模型或知识接口故障，也未继续操作原始代码图，因此不能证明故障原因或降级后的图浏览能力。[标识格式、焦点、降级与移动抽屉检查 ↗](../../../scripts/code-wiki-viewport.ts#L239 "支持特定正则覆盖的标识格式检查、焦点恢复、概览文字检查和窄屏抽屉断言，同时界定模型故障未被显式模拟。")
