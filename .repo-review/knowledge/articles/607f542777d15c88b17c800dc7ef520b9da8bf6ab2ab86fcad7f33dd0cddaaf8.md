# 跨模块安全边界、派生知识与降级策略

本章梳理外部材料、代码知识、模型生成、会话隔离和开发运行之间的可靠性边界：内容先受控捕获并固定为修订与片段，代码结构和理解结果再从固定证据派生；模型属于可选增强，失败不能破坏基础浏览；群聊证据按命名空间过滤，研究标注与普通捕获保持隔离。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="capture-boundaries"></a>
## 外部内容先成为受控材料

文件连接器解析真实路径，只读取配置根目录内、大小受限且可严格解码的纯文本；Git 连接器还会校验 ref 与仓库相对路径，并从解析后的固定提交读取对象，避免把未提交工作区当作版本证据。参考 [文件读取边界 ↗](../../../apps/server/src/connectors.ts#L10 "支持真实路径归属、文本大小、严格 UTF-8 解码和二进制拒绝规则。") [Git 固定版本读取 ↗](../../../apps/server/src/connectors.ts#L36 "支持 Git ref、仓库相对路径、提交哈希校验及从固定对象读取正文的流程。")

捕获图片时会校验 Base64、五兆字节上限及 PNG、JPEG 或 WebP 文件头，再按内容摘要保存资源。随后捕获事务创建新修订，把文本、链接和图片说明转成固定片段并推进来源头部。参考 [图片资源校验 ↗](../../../apps/server/src/store.ts#L102 "支持图片大小、Base64 一致性、文件头校验及按内容摘要保存资源的说明。") [修订与片段写入 ↗](../../../apps/server/src/store.ts#L197 "支持捕获创建新修订、将各类内容转成片段并推进来源头部。") 普通业务捕获不会自动创建质量数据集、标注样本或外发卡片；研究切分器只有显式选择评测模式才可运行。参考 [普通捕获与评测隔离 ↗](../../../apps/server/tests/import-quality-isolation.test.ts#L42 "支持普通捕获不产生质量数据副作用，以及研究导入必须显式选择评测模式。")

<a id="derived-knowledge"></a>
## 代码理解建立在固定证据之上

代码同步读取捕获链的当前修订，而不把实时磁盘正文与旧片段混合；仓库状态和捕获内容摘要共同决定快照身份。参考 [捕获驱动的代码快照 ↗](../../../apps/server/src/code/sync.ts#L170 "支持代码分析只读取捕获修订，并以仓库状态和捕获内容摘要确定快照。")

```mermaid
flowchart LR
  A[受控捕获] --> B[不可变修订与片段]
  B --> C[代码快照与结构关系]
  C --> D[人工或模型理解]
  D --> E[合同与引用校验]
```

投影会生成声明、导入和单文件名称级调用关系；可解析的导入为确认状态，调用关系保持候选状态，跨文件类型解析尚未实现。参考 [代码结构关系投影 ↗](../../../apps/server/src/code/sync.ts#L250 "支持声明、导入和单文件名称级调用关系的生成方式及状态边界。") 理解结果还必须匹配角色、提示、Schema 和输入摘要，引用的节点、边、证据与行范围都要存在于固定快照，否则结果会被拒绝。参考 [理解结果确定性校验 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L502 "支持摘要封印、固定快照交叉引用、行范围、引用预算和 seed 诚实性校验。")

<a id="degradation-security"></a>
## 可选能力不能破坏基础浏览与隔离

评审服务默认不启用生成模型；没有模型时，原始代码图和人工种子仍可使用，显式生成请求返回不可用。模型传输或引用校验失败时，结果不会晋升为当前理解。参考 [模型可选生成入口 ↗](../../../apps/server/src/review/app.ts#L579 "支持无模型时返回不可用、基础图和种子继续可用，以及失败结果不晋升的边界。")

Web 会话入口拒绝伪造的 Lark 群聊渠道和群组可见性，并由服务端固定 Web、私有和 owner 身份。参考 [Web 会话身份收口 ↗](../../../apps/server/tests/conversation-security.test.ts#L64 "支持 Web 入口拒绝伪造群聊渠道与可见性，并强制使用 Web、私有和 owner 身份。") Lark 群聊另用带连接版本的命名空间会话，在模型输入前排除未绑定该群聊的私有证据。参考 [群聊命名空间与证据过滤 ↗](../../../apps/server/tests/conversation-security.test.ts#L270 "支持 Lark 群聊新建独立命名空间会话，并阻止私有证据进入模型输入。") 中文群聊召回已验证经过关键词分词链路，而非依赖整句包含匹配；现有证据只覆盖固定短语，不代表排序质量和总体召回率已经评估。参考 [中文群聊关键词召回 ↗](../../../apps/server/tests/conversation-security.test.ts#L337 "支持整句匹配无法命中而关键词检索可在群聊运行链召回中文片段。")

<a id="operational-limits"></a>
## 运行保障与验证边界

开发端口遵循“默认值冲突时迁移、显式端口冲突时失败”的策略。探测服务器取得端口后立即关闭，因此这是可用性检查，不能消除探测与正式绑定之间的竞争窗口。参考 [开发端口冲突策略 ↗](../../../scripts/dev-ports.ts#L3 "支持端口合法性校验、默认端口迁移、显式冲突失败及探测后释放监听的行为。")

角色 ACP fixture 明确是非生产测试代理，以进程内状态提供动态模型和推理强度选项。参考 [角色测试代理状态 ↗](../../../apps/server/tests/fixtures/role-acp-agent.mjs#L1 "支持该 fixture 的非生产定位、进程内状态以及动态模型与推理强度选项。") 它可以模拟会话初始化、超时不响应、取消以及危险工具权限请求等协议行为。参考 [角色协议场景模拟 ↗](../../../apps/server/tests/fixtures/role-acp-agent.mjs#L308 "支持会话初始化、超时、取消和危险工具权限请求等确定性协议行为。") 这些材料只能证明相应消息场景能够被构造，不能替代真实 Agent CLI 的能力发现、模型质量或 live 可用性验证。
