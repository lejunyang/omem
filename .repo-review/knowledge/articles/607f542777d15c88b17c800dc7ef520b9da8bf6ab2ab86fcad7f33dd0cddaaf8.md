# other · 模块理解 · 专题 2

本专题汇总仓库中若干跨模块保障能力：固定证据上的代码知识投影、严格合同与输入边界、会话可见性隔离、确定性 ACP 测试替身，以及普通捕获与研究标注的隔离。现有测试证明了关键行为切片，但真实模型链路、多租户授权和部分异常边界仍需单独验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence-projection"></a>
## 固定证据上的代码投影与理解

代码知识同步不另行捕获文件正文，而是解析已经捕获的 TypeScript/Vue Fragment，并在隔离侧表中形成文件、符号与关系快照；相同输入复用快照，未重产结构按实现约定进入过期状态。[代码知识同步职责 ↗](../../../apps/server/src/code/sync.ts#L1 "说明代码图建立在已捕获 Fragment 上，并解释快照复用和过期规则。")[代码知识同步测试理解 ↗](67ec31b75691ebe8fdb4678f43214793a5241bd4106feb298ec3c144907463e4.md#snapshot-lifecycle "引用子知识对解析、快照生命周期和证据边界的综合说明。") 人工理解种子再以路径、限定名和类型等稳定定位器解析到当前图，封存输入摘要并做严格交叉引用校验；无效种子留下拒绝记录但不遮蔽有效结果。[人工理解投影流程 ↗](../../../apps/server/src/code/understanding-store.ts#L1 "支持稳定定位器解析、摘要封存、严格校验及失败不遮蔽有效结果。")[代码理解种子投影理解 ↗](13652f9dcf302af08a7fc21435df88a3fc6c4ea9f8c431fcf6202e5c5df21cf9.md#projection-lifecycle "引用子知识对人工种子校验和版本生命周期的组织性说明。")

现有集成测试已覆盖种子幂等、幽灵符号拒绝、源码变化后的 stale 与 supersedes，以及无模型时仍可读取理解和原始图。[种子过期与替代断言 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L178 "支持源码变化后生成新当前理解、旧理解标记 stale 并建立 supersedes 关系。")[无模型只读服务断言 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L215 "支持模型不可用时理解列表、详情与原始代码图仍可读取。") 但真实仓库验收只明确检查五个必需模块，不能据此断言全部种子均已成功复核。

<a id="contracts-and-inputs"></a>
## 合同与外部输入边界

严格合同把“可解析的提议”与“已经应用的变更”分开：文档 Proposal 示例通过解析后仍没有状态字段，未知字段、正文类型不匹配及更新缺少预期版本都会被拒绝。[严格提议合同理解 ↗](156a253d822b9a810fab01892b40fbd333181d83e111a483f89f5ba86c104367.md#proposal-boundary "引用子知识对提议解析、应用边界和 CAS 前置条件的总结。")[提议合同拒绝反例 ↗](../../../apps/server/tests/contracts.test.ts#L22 "支持未知字段、类型与正文不匹配以及更新缺少预期版本时被拒绝。") 文件连接器则先解析真实路径并限制在配置根目录内，再执行大小、UTF-8 与空字节检查；Git 连接器校验 ref 和仓库相对路径后，从解析出的固定提交读取对象，因此不会把未提交工作区内容当成该版本证据。[连接器边界理解 ↗](965b4f1092dfb9c4c93df107f618b1dbaddf59d1f70c9a8a2d6c6ef759d544f3.md#git-flow "引用子知识对文件真实路径防护和 Git 固定版本流程的综合解释。")[文件与 Git 输入校验实现 ↗](../../../apps/server/src/connectors.ts#L10 "支持真实路径、纯文本限制、ref 与仓库路径校验及固定提交对象读取。")

这些保障目前主要证明单机文件与 Git 的关键成功、逃逸和二进制场景；Windows 路径、SHA-256 仓库、超时以及稳定错误分类仍未由材料确认。

<a id="conversation-and-runtime"></a>
## 会话隔离与运行时测试替身

Web 会话入口由服务器强制收口为 `web/private/owner`，不能通过客户端字段伪造 Lark 群聊身份。Lark 群聊还使用连接版本命名空间创建群组会话，并在召回后过滤无群聊绑定的私有证据；测试同时证明中文分词检索能召回整句 LIKE 无法命中的片段。[群聊隔离与证据过滤理解 ↗](ae57399388b59b1294185199de1fbe417809d14558b5e6d395cbde38ca8ffaa1.md#group-isolation "引用子知识对群聊命名空间和私有证据过滤的组织性说明。")[中文群聊召回断言 ↗](../../../apps/server/tests/conversation-security.test.ts#L367 "支持 Lark 群聊运行链将中文分词召回的目标片段送入模型证据。")

ACP 与角色运行时脚本是确定性协议替身：它们模拟动态模型/推理强度、超时、取消、权限请求和固定角色合同，便于测试宿主协议与解析流程。[通用 ACP 测试代理 ↗](../../../apps/server/tests/fixtures/acp-agent.mjs#L1 "支持测试替身的非生产定位、动态配置、超时与权限请求分支。")[角色运行时 ACP 代理理解 ↗](e8b6264512ac77f63ea215f7a18cd3ab30432b15cbcd3fe49ef7a1f590035dc1.md#scenarios-limits "引用子知识对角色合同、协议场景及 fixture 限制的综合说明。") 这些 fixture 明确不是生产模型，且自身使用简化的单会话状态与字符串分支，不能替代真实 Agent CLI/ACP 的能力协商、认证、推理质量或现场运行 trace。

<a id="progress-and-limits"></a>
## 进展、隔离策略与限制

普通 `Store.capture` 已有回归测试确认会保存 revision 与 fragment，同时不会创建质量数据集、质量样本或外发意图；研究导入器只有携带显式判别值时才可生成标注样本。[普通捕获隔离断言 ↗](../../../apps/server/tests/import-quality-isolation.test.ts#L42 "支持普通捕获保存 Fragment，同时三类质量或外发相关表保持零记录。")[研究导入显式准入 ↗](../../../apps/server/tests/import-quality-isolation.test.ts#L98 "支持缺少 opt-in 时失败、显式研究判别值存在时才生成样本。") 开发端口选择也经过真实 TCP 冲突测试：默认端口可迁移，显式冲突和非法输入会失败，但探测服务器随后关闭，所以该机制不提供持续端口预留。[开发端口冲突测试理解 ↗](3544d9bdd0994095d9ccacf9c1daa4f7c46423ac034075e649dacdf76ff59591.md#boundaries "引用子知识对默认端口迁移、显式冲突失败和未覆盖边界的总结。")[端口探测实现 ↗](../../../scripts/dev-ports.ts#L3 "支持端口范围校验、冲突处理及探测后立即释放端口的限制。")

整体上，这些切片已经把派生知识、输入安全、会话可见性和研究工具隔离到明确边界；底层 Store 仍是单用户 SQLite，团队级数据库与租户强制尚未实现。[单用户 SQLite 边界 ↗](../../../apps/server/src/store.ts#L4 "支持当前存储是单用户基础，团队级数据库和权限强制仍属后续迁移。") 当前最重要的验收缺口是：真实模型复核链路、全部种子覆盖、更多连接器入口及并发或跨平台边界，不能由协议 fixture 或局部测试替代。
