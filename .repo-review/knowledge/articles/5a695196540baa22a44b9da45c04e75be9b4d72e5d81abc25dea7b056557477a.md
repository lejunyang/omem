# 统一知识阅读与证据追溯

统一应用以主题文章为主要入口，把解释性知识、原始材料、固定引用和个人事项纳入同一阅读流程；同时保留历史证据、独立复核与待更新状态，避免把旧调研或失效引用误当成当前实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="reading_experience"></a>
## 从主题文章逐层追溯证据

统一知识阅读解决的是在日常助理、知识文章、原始材料和事项之间反复切换的问题。用户启动同一个应用后，先从可展开的知识目录进入完整文章，再通过页内导航定位章节；需要核实论断时，才沿句段末的引用进入代码或原始文档。旧文章若受来源变化影响，会明确标记为待更新。参考 [主题文章阅读流程 ↗](../../../docs/implementation/unified-knowledge-reading.md#L3 "支持统一入口、文章优先、页内导航、证据下钻及旧文章待更新状态的说明。")

阅读层次刻意区分“解释”与“证据”：代码引用先展示固定行范围，并允许向上下文展开；原始 Markdown 则连续呈现标题、段落、表格和代码围栏。流程图采用严格模式渲染并过滤 SVG，失败时保留文字说明，避免可视化失败破坏正文可读性。参考 [证据展示与图表降级 ↗](../../../docs/implementation/unified-knowledge-reading.md#L9 "说明代码固定行展示、原始文档连续渲染以及 Mermaid 的安全渲染和失败降级方式。")

<a id="data_and_generation"></a>
## 统一存储与可追溯生成

仓库材料并未进入独立的评审产品，而是接入个人库既有的 Store、Source、Revision、Fragment 与 KnowledgeRepository。捕获过程保持幂等，历史原文可从运行目录补入；已保存文章的固定引用继续指向当时版本，不能因源码更新而漂移，也不能为缺失证据补造内容。参考 [个人库数据复用 ↗](../../../docs/implementation/unified-knowledge-reading.md#L16 "支持仓库材料复用统一数据模型、幂等捕获、历史原文补入和固定引用不漂移等实现陈述。")

启动阶段只恢复已有知识，不调用生成式模型；真实生成结果和独立复核结果仍保存于仓库知识目录。刷新会产出可独立阅读的当前文章并保留修稿历史，复核负责拦截事实错误、证据不支持和关键条件缺失。新写作规范只适用于重新分析并复核的文章，历史调研中的旧状态不得直接宣称为现行能力。参考 [刷新与独立复核规则 ↗](../../../docs/implementation/unified-knowledge-reading.md#L20 "支持文章刷新、修稿历史、复核拒绝条件以及历史状态不得冒充当前能力的说明。")

<a id="validation_and_limits"></a>
## 验收范围与剩余边界

文档记录的验收覆盖依赖锁定、全量检查、浏览器工作流以及多视口阅读体验，包含 Markdown 表格、Mermaid、原文过滤、统一目录、导航一致性和代码上下文展开。参考 [浏览器验收范围 ↗](../../../docs/implementation/unified-knowledge-reading.md#L26 "支持依赖检查、全量检查、真实浏览器行为和多视口阅读覆盖已经执行的历史验收记录。")

浏览器实测还发现并修复了弹窗样式作用域问题，且截图必须在完整文章加载后取得，不能用空态页面冒充通过。这些实施记录属于文档所述时点的事实；最终状态仍以自动验证报告和知识覆盖记录为准。未通过的文章继续保留旧版并标记待更新，未覆盖材料不能计为完成，因此历史检查退出 0 不能单独证明当前知识仍是最新状态。参考 [实测修复与覆盖边界 ↗](../../../docs/implementation/unified-knowledge-reading.md#L33 "直接支持弹窗样式作用域修复、有效截图条件、验证记录位置以及失败和未覆盖材料的处理边界。")
