# 飞书接入验收测试

该测试以协议替身和服务层临时 SQLite 装置，验收飞书应用注册、能力核验、凭据保护、owner 配对、版本切换和既有应用导入。它主要证明本地参数映射、状态转换与持久化约束；真实飞书网络、Windows ACL 和外部事件入口仍缺少直接验收证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-fixtures"></a>
## 测试范围与隔离装置

这组测试回答“取得飞书应用凭据后，连接能否在能力核验、秘密保护和 owner 配对完成前保持不可用”。其中，服务层状态机相关用例通过 `setup()` 创建临时目录、独立 `Store`、32 字节秘密密钥，并注入注册器、探测器和时钟；资源在用例结束后关闭和清理。能力探测与 HTTP 重试两个适配器级用例不调用该装置，而是分别替换 `fetch` 与 SDK HTTP adapter。[测试替身、服务层装置与适配器级用例 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L34 "支持服务层用例可创建临时 Store 和可注入依赖，同时表明能力探测与重试用例采用各自的适配器替换方式，不能概括为每个用例都调用 setup。")

`Store` 初始化会执行迁移，创建受限的数据与资产目录，并把 SQLite 文件权限设为 `0600`，因此服务层测试使用真实的单用户持久化结构，而非纯内存状态。[单用户 SQLite 存储初始化 ↗](../../../apps/server/src/store.ts#L38 "支持 Store 执行数据库迁移、创建受限目录并设置 SQLite 文件权限的说明。")

## 注册、能力核验与秘密保护

注册适配测试核对 `createOnly`、应用预设和 addons 到官方 SDK 的映射，并验证默认配置覆盖消息、文档、日历、会议和任务能力，同时排除若干群成员变更、批量消息和 ACL 删除权限。[官方注册映射与默认权限断言 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L224 "支持 SDK 参数映射、默认能力集合及高风险权限排除的测试结论。") 瞬时 `ETIMEDOUT` 测试直接证明第二次请求复用了相同的 `device_code` 请求体。[相同设备码的超时重试测试 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L331 "支持一次瞬时超时后发生第二次请求，且两次使用相同注册轮询请求体的直接测试结论。") 注册模块还把该机制限定于注册地址、未中止请求、可重试的服务端或传输错误，并设置最多重试次数及最高 4 秒的指数退避。[注册轮询有限退避策略 ↗](../../../apps/server/src/integrations/lark/registration.ts#L33 "支持重试适用条件、最大次数、指数退避上限以及复用原请求的实现说明。")

凭据返回不等于连接可用：缺少事件或回调时，状态经历 `credentials_received`、`checking` 后进入 `failed`，且连接没有活动版本。[能力不足时的失败状态序列 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L407 "支持凭据在能力检查通过前不被视为可用，以及失败连接没有活动版本的结论。") 成功路径断言 `client_secret` 不出现在状态、连接或数据库行中，数据库只保存秘密引用；磁盘内容为密文，POSIX 下权限为 `0600`，并能经秘密仓库解密还原。[客户端秘密的加密持久化断言 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L445 "支持秘密不进入公开状态或数据库、磁盘只保存密文且可由秘密引用解密读取的论断。")

<a id="pairing-versioning"></a>
## 配对约束、终态与版本切换

扫码返回的 `user_info` 不会自动成为 owner，连接仍停留在 `awaiting_pair`。配对测试证明码值至少含 16 字节随机内容，并约束有效期、应用身份、发送者身份和一次性消费；错误应用、错误码、错误 actor、过期或重复确认都会失败。[配对码与 actor 绑定约束 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L488 "支持配对码随机长度、过期、同应用、同 actor 和一次性消费规则；也表明测试直接调用服务层配对方法。")

取消、拒绝和过期均保持终态且不创建连接；只有取消分支额外注入迟到凭据，证明其不会写入秘密，并标记 `late_credentials_needs_review`。[终态与取消后的迟到凭据处理 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L372 "支持取消、拒绝和过期的终态行为，并把无秘密写入和人工复核标记限定在取消后迟到凭据场景。") 更新既有应用时，新凭据先成为 staged version，owner 再次确认后活动版本切换为 2，旧连接版本与旧绑定被标为 `superseded`；Botmux 导入可跳过注册调用，但仍须配对且不得暴露原始秘密。[既有应用换版与 Botmux 导入 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L562 "支持活动版本切换、旧版本与旧绑定被替代，以及导入既有应用仍需配对且隐藏秘密的结论。")

<a id="assertion-limits"></a>
## 断言边界与待补证据

官方能力探测以伪造 HTTP 响应核对 token、bot 信息和应用详情请求，以及 scope、callback、缺失能力和运行时事件验证标记的归一化；它证明本地请求拼装和协议映射，不等同于真实飞书联调。[官方能力探测的模拟 HTTP 验证 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L157 "支持能力探测测试验证接口请求和结果转换，同时界定响应来自测试替身而非线上服务。") Windows 分支仅断言秘密路径是普通文件且当前进程可读取；严格权限位断言只在 POSIX 执行，源码注释提到的目录 ACL 未在本测试中验证。[跨平台秘密文件权限断言 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L42 "支持 POSIX 检查 0600，而 Windows 仅检查文件存在和可读取这一覆盖差异。")

此外，配对用例直接调用 `receivePairing` 和 `confirmPairing`，所以只能证明服务层状态机，不能确认留作外部事件入口的签名校验、重放去重与路由安全证据。[配对码与 actor 绑定约束 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L488 "支持配对码随机长度、过期、同应用、同 actor 和一次性消费规则；也表明测试直接调用服务层配对方法。")
