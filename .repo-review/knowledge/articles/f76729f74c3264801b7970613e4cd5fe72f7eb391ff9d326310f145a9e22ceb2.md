# Lark 接入验收测试

该测试以临时 SQLite、加密凭据目录及可控的注册和能力探测依赖，验收 Lark 应用接入、能力门禁、安全存储、配对绑定与版本切换。它证明本地协议映射和持久化不变量，但不等同于真实飞书环境联调；此前“已验证官方适配器暴露二维码元数据”的结论已被更精确的覆盖边界替代。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_fixture"></a>
## 目标与测试夹具

测试覆盖从应用注册到绑定激活的完整本地状态链，而不只检查能否取得凭据。每个用例结束后都会关闭数据库并删除临时目录。[临时资源清理 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L34 "支持每个用例关闭 Store 并删除临时测试目录的说明。") `setup` 创建真实 `Store` 和随机密钥的加密秘密目录，同时注入注册器、能力探针、时钟及既有应用提供者。[接入服务测试构造 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L111 "支持真实 Store、加密秘密目录以及注册器、探针、时钟和既有应用提供者的注入关系。") `Store` 会建立单用户 SQLite、执行迁移并收紧数据库和资产目录权限，因此后续断言面向实际持久化结构。[SQLite 存储初始化 ↗](../../../apps/server/src/store.ts#L36 "支持建库、迁移、目录权限收紧及持久化仓储初始化的说明。")

<a id="registration_and_verification"></a>
## 注册、能力门禁与重试

能力探针用预置 HTTP 响应模拟 tenant token、机器人身份和应用配置，断言已授予权限、回调、缺失能力及授权头。[官方能力探针断言 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L157 "支持通过模拟 HTTP 响应核对 token、机器人身份、应用能力、缺失项与授权头的结论。") SDK 适配测试确认 `createOnly`、应用预设、addons 和默认权限集合的映射，并排除若干群管理、批量发送与 ACL 高风险权限。注入的 SDK 函数确实触发 `onQRCodeReady`，但传给适配器的 `onQrCode` 是空函数，测试没有捕获或断言 URL 及 `expireIn` 到 `expiresInSeconds` 的转换；后半段二维码断言来自 `FakeRegistration`。[SDK 注册映射与二维码覆盖边界 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L224 "支持注册参数和默认能力集合断言，同时表明 SDK 回调虽被触发，但 onQrCode 为空函数，后续二维码状态来自测试替身，未验证官方适配器的元数据转换。") 因而此前“已验证官方适配器暴露二维码元数据”的结论被替代为“已驱动回调，但尚未验证映射”。设备码轮询则明确证明一次超时后复用相同请求体重试。[相同设备码请求重试 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L331 "支持瞬时超时后恰好重试一次，并复用完全相同请求体的测试结论。") 实现仅对注册路径、未取消且属于 5xx 或列明网络错误的请求在次数上限内重试。[注册轮询重试条件 ↗](../../../apps/server/src/integrations/lark/registration.ts#L29 "解释重试只适用于注册路径、未取消请求、可重试状态或网络错误且未超过次数上限。")

<a id="state_security_pairing"></a>
## 状态、安全与配对边界

取消、拒绝和过期保持终态，迟到凭据不会建立连接或写入秘密；能力缺失会留下从草稿到失败的事件序列。[终态与失败事件序列 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L372 "支持取消后隔离迟到凭据、拒绝与过期终态，以及能力缺失时的数据库状态序列。") client secret 不进入状态、连接列表或数据库行，只以秘密引用关联加密文件，并可由秘密存储恢复。[凭据加密与数据库防泄露 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L445 "支持 client secret 不出现在响应、连接或数据库行中，并能从加密秘密文件恢复的断言。") 即使注册结果带有用户信息，仍须完成同应用配对；测试覆盖随机码强度、过期、应用与操作者校验以及一次性消费。[配对身份与一次性消费 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L476 "支持注册后仍需配对，以及配对码强度、过期、应用与操作者绑定和一次性消费约束。") 既有应用更新先暂存新版本，确认配对后才把旧绑定和连接版本标为 superseded，并激活新目标。[既有应用版本切换 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L562 "支持新版本先暂存、确认后切换、旧版本被替代及新目标被激活的结论。")

<a id="coverage_limits"></a>
## 模块关系与覆盖限制

这些用例的主要边界是外部交互均可控：注册器与能力探针包含测试替身，[注册与能力测试替身 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L56 "说明注册器和能力探针是记录调用并返回预置结果的测试实现。") 能力查询依赖注入的模拟 `fetch`，[能力查询模拟响应 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L157 "支持能力探针测试通过注入 fetch 和预置响应模拟官方 HTTP 接口的覆盖限制。") 官方注册流程由注入函数代替，[SDK 注册函数替身 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L224 "支持注册映射测试以注入函数代替真实官方 SDK 注册过程的覆盖限制。") 瞬时超时也由自定义 Axios adapter 制造。[Axios 重试适配器 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L331 "支持瞬时超时测试通过自定义 Axios adapter 产生失败和成功响应的覆盖限制。") 因此结果证明协议映射和本地状态处理，不能替代真实租户的授权、回调配置与 WebSocket 投递验收。Windows 分支只确认秘密路径为可读文件，并未自动核验 NTFS ACL。[Windows 文件权限检查边界 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L42 "支持 Windows 仅断言秘密路径为文件，而 POSIX 才直接检查 0600 模式的结论。") 当前也只覆盖顺序配对、版本切换和单次瞬时失败，尚不能证明并发确认、重试耗尽、进程崩溃或持久化中断下的原子性。
