# Lark 接入、能力校验与配对验收测试

覆盖应用注册、实际能力探测、终态处理、密钥保护、配对约束、版本换绑及 Botmux 导入；替身和 HTTP 拦截测试不能替代真实飞书与 Lark 租户验收。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="registration"></a>
## 注册与能力校验

测试验证注册适配器把 `createOnly`、应用预设和 addons 传给官方 SDK并返回二维码元数据；默认配置检查了权限与事件集合、tenant/user 权限去重，并排除若干高风险权限，但没有断言事件列表去重。[SDK 注册参数与默认能力集合 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L224 "支持注册参数映射、二维码元数据、默认权限和事件集合、权限去重及危险权限排除。") 公共能力探测读取已授予 scope、回调和 bot 身份，并明确把事件订阅留给配对期间的 WebSocket 投递验证。[公共应用能力探测 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L158 "支持 scope、回调和 bot 身份探测，并说明事件订阅需由配对期间的 WebSocket 投递验证。") 若替身探测报告缺少消息事件或卡片回调，接入转为 failed，连接没有 active version，状态轨迹保留完整失败过程。[能力缺失时接入失败 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L407 "支持缺少事件和回调时 onboarding 与连接失败，以及状态迁移记录。")

<a id="pairing-secrets"></a>
## 配对与密钥边界

扫码返回的用户信息不能替代 owner 配对。配对码经 base64url 解码后至少 16 字节；测试还覆盖过期、应用不匹配、错误码、操作者不一致及一次性确认，但不能仅据长度证明随机性来源。[配对身份与一次性约束 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L476 "支持配对码最小解码长度、有效期、应用绑定、操作者绑定及一次性消费边界。") `client_secret` 不出现在状态、连接列表及 `lark_onboardings`、`lark_connections`、`lark_connection_versions` 三类表的序列化结果中；数据库保存引用，密文不含原值且可解密恢复。[客户端密钥加密与脱敏 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L445 "支持状态与连接列表脱敏、三类相关数据库表不含明文、secret_ref 和密文恢复行为。") POSIX 检查文件权限为 `0600`，Windows 仅断言目标是文件，未直接验证 ACL。[跨平台密钥文件权限检查 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L42 "限定真实覆盖范围：POSIX 检查 0600，Windows 只检查文件存在。")

<a id="versioning"></a>
## 终态、换绑与导入

取消、拒绝和二维码过期为终态；取消后迟到凭据不会创建连接或密钥文件。[取消、拒绝与过期终态 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L372 "支持终态不可被迟到凭据逆转，以及不创建连接或密钥。") 更新已有应用时，新版本在重新配对前保持 staged，旧版本继续 active；确认后旧 binding 与版本才 superseded，新群目标启用采集。Botmux 导入绕过注册适配器且不返回 secret，但仍需完成配对。[版本换绑与 Botmux 导入 ↗](../../../apps/server/tests/lark-onboarding.test.ts#L562 "支持确认前后版本切换、旧 binding 失效、新群采集目标及导入流程脱敏。")
