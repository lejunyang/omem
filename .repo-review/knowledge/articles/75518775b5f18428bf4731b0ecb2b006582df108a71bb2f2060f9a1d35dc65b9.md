# 前端工作区与依赖构建许可

该配置定义 pnpm 工作区包含的应用与共享包目录，并明确允许四个依赖执行构建步骤。它描述的是包管理边界和安装策略，不能单独证明各目录、依赖或相关功能已经实际存在并可运行。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="workspace-scope"></a>
## 工作区覆盖范围

该仓库采用 pnpm workspace 组织多包工程，将 `apps/*` 与 `packages/*` 纳入统一依赖管理。前者通常承载可运行应用，后者用于共享能力；这为应用复用公共组件或基础设施提供了目录层面的组织基础。参考 [工作区目录范围 ↗](../../../pnpm-workspace.yaml#L1 "支持工作区统一包含应用目录与共享包目录的配置事实。")

这份文件只声明包扫描范围：它不会证明匹配目录中当前有哪些项目，也不能证明任一应用已完成构建、测试或发布。判断实际实现状态仍需结合各包清单、源码和当前进展材料。

<a id="dependency-build-policy"></a>
## 依赖构建许可

配置显式允许 `esbuild`、`protobufjs`、`onnxruntime-node` 与 `sharp` 执行安装期构建。它们分别可能涉及代码构建、协议处理、模型推理和图像处理等技术场景，但此处只能确认构建许可，不能据此断言项目已经启用了这些能力。参考 [依赖构建许可 ↗](../../../pnpm-workspace.yaml#L5 "支持四个依赖被明确允许执行构建步骤的配置事实。")

显式许可有助于控制哪些依赖可以运行构建脚本，并让安装行为更可预期。实际安装是否成功、二进制是否适配运行平台，以及上层代码是否调用这些依赖，仍需通过锁文件、包清单和真实检查确认。
