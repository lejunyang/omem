# pnpm 工作区边界与依赖构建许可

该配置把 apps 与 packages 下的直接子目录纳入 pnpm 工作区，并允许 esbuild 和 protobufjs 执行依赖构建脚本。它定义包发现和安装期脚本许可边界，但不描述应用功能、启动流程或构建结果。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="workspace_scope"></a>
## 工作区包发现范围

工作区仅声明 `apps/*` 和 `packages/*` 两类路径，因此 pnpm 会把这两处的直接子目录作为候选工作区包。[工作区目录模式 ↗](../../../pnpm-workspace.yaml#L1 "直接支持工作区只覆盖 apps 与 packages 两类直接子目录的配置事实。") 该结构与锁文件中的 `apps/web`、`packages/ui` importer 相互印证，但配置本身没有列出具体包名，也不能证明这些包包含可运行实现。

<a id="build_policy"></a>
## 安装期构建脚本白名单

`allowBuilds` 只允许 `esbuild` 与 `protobufjs` 执行依赖构建脚本。[依赖构建脚本许可 ↗](../../../pnpm-workspace.yaml#L5 "支持安装期构建许可仅包含 esbuild 和 protobufjs 的结论。") 这是一项安装安全和可复现性边界：其他依赖若需要生命周期构建脚本，不能从本材料推断其已获许可。锁文件确实解析了 esbuild 的多平台可选二进制包，说明该许可与当前工具链存在关联。[esbuild 平台可选依赖 ↗](../../../pnpm-lock.yaml#L2103 "说明工作区构建许可与锁文件中实际解析的 esbuild 平台包之间的关联。")
