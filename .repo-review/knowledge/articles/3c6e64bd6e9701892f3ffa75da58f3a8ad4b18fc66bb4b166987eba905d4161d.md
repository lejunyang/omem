# Worker处理、分类与用户注意力策略

一份待实现的后台处理政策，定义多维分类、W0–W4渐进处理、交互类型、Attention Gate以及检索基础设施的职责边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="pipeline"></a>
## 多维分类与渐进处理

输入需分别记录载体、领域、话语行为、证据地位、时间、项目和与用户的关系，并保存provenance、版本、置信理由及unknown。低置信不阻断保存与搜索，代码TODO、历史问题或屏幕观察也不能自动解释为本人指令。[分类维度与低置信处理 ↗](../../../docs/implementation/assistant-v3/processing-policy.md#L9 "解释多维分类、来源身份区分及unknown不触发默认提问。")

处理从W0保真收录、W1可检索化、W2场景理解，推进到W3有目的提炼和W4巩固维护；新句子本身不是深度提炼理由，触发应来自真实任务、明确整理请求、来源变化或复用价值。[W0至W4处理矩阵 ↗](../../../docs/implementation/assistant-v3/processing-policy.md#L23 "支持渐进处理阶段、阶段产物和进入W3的价值触发条件。")

<a id="attention"></a>
## 交互与Attention Gate

澄清用于缺少执行参数，授权用于高影响或范围变化，权限内完成的正式变化直接通知，质量标注则必须独立opt-in。一次逻辑ChangeSet对应一条清楚通知，后台切片和向量更新不制造额外打扰。[四类用户交互 ↗](../../../docs/implementation/assistant-v3/processing-policy.md#L57 "支持澄清、授权、通知、质量标注的语义区分和通知聚合。")

worker不能直接发确认卡；只有问题与当前任务相关、确需owner选择、已完成可行补证且能解释后果时，才创建AttentionCase。[Attention Gate创建条件 ↗](../../../docs/implementation/assistant-v3/processing-policy.md#L68 "解释worker输出何时可以升级为用户可见问题，以及不满足条件时的内部处置。") MemPalace只位于统一RetrievalPort之后，不能解决说话人、任务归属或提问价值判断，并须映射回固定片段ID。[MemPalace职责边界 ↗](../../../docs/implementation/assistant-v3/processing-policy.md#L112 "支持MemPalace不能替代身份、任务归属和提问策略，并须映射固定片段ID。")
