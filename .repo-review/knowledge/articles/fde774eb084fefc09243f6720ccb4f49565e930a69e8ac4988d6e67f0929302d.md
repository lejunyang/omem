# 知识写作角色的配置边界

该清单定义 knowledge-writer 第 1 版使用的运行配置、内联技能、结构化输出名称、隔离策略与预算参数。它记录的是角色声明，尚不能单独证明运行时如何执行校验、限额或修复。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 面向结构化知识写作的角色

该清单将角色标识为 **knowledge-writer 第 1 版**，引用 `traex` 配置并加载 `prompt.md`，用于把知识写作任务交给一组固定的角色资源处理。参考 [角色与提示模板 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/manifest.json#L2 "支持角色标识、版本、运行配置引用和提示模板的说明。")

角色声明输出模式为 `KnowledgeBatch.v1`，表明产物应遵循这一命名合同；但仅凭清单无法确认合同包含哪些字段，也无法确认宿主怎样解析或校验结果。参考 [输出合同名称 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/manifest.json#L17 "支持角色声明采用 KnowledgeBatch.v1 输出模式，同时限定材料只提供模式名称。")

<a id="skill-and-isolation"></a>
## 固定技能与隔离运行

写作能力通过 `omem-knowledge-writer` 第 1 版技能包以内联方式装载，并用工件摘要标识对应内容，为识别角色依赖的技能版本提供配置依据。参考 [内联写作技能 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/manifest.json#L9 "支持技能包名称、版本、内联装载方式和工件摘要的说明。")

工具策略声明为 `none`，允许工具列表为空；会话不复用，也不继承用户技能或 MCP。因此，该角色无法通过清单声明的工具自行读取文件或补查资料，且不会从用户侧扩展这些能力。至于是否还有系统提示或其他运行时注入，材料没有说明。参考 [工具与会话隔离 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/manifest.json#L18 "支持无可用工具、会话不复用以及不继承用户技能和 MCP 的配置结论。")

<a id="budget-and-limits"></a>
## 上下文、输出与修复预算

清单为任务声明最多 96,000 个上下文 token、24,000 个输出 token，以及最多两次修复尝试。这些参数描述了期望的资源边界，可供运行时调度与约束角色执行。参考 [生成预算参数 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/manifest.json#L27 "支持上下文、输出和修复尝试三项预算声明，并说明这些只是配置值。")

不过，材料没有给出超限行为、修复触发条件或加载器实现；因此，两次修复不能直接解释为专门处理格式错误，也不能仅凭配置断言这些上限已被强制执行。
