# docs-decisions.md · 模块理解

该模块集中记录个人助手的产品方向、技术选型与自治边界，并明确区分长期目标、当前实施状态和须由配置及授权决定的外部集成范围。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-context"></a>
## 职责与背景

`docs-decisions.md` 是产品与实施方向的决策入口：系统首先服务个人，同时为未来团队场景保留模型设计；飞书机器人上的主 Agent 承担主要交互和知识治理入口，Web 是后台与第二入口。部署目标兼顾服务器长期运行与本地运行，因此后续实现不能只适配单一环境。[个人助手定位与入口决策 ↗](../../../docs/decisions.md#L7 "支持个人优先、保留团队设计、飞书主入口、Web 第二入口以及本地与服务器部署目标的说明。") 已有主题知识把这些选择归纳为统一的产品与技术方向，帮助首次阅读者理解各项决策的共同背景。[产品与技术方向 ↗](3d9dcd2cda0171189ad65dc88b7556f56e6ba30ac99dc5b91fc236fd4182b50a.md#direction "引用已有主题知识对分散决策的概念组织，用于解释这些选择如何共同构成产品方向。")

<a id="workflow-and-relations"></a>
## 输入、模型与自治流程

预期工作流从飞书文档、Git、纯文本、Agent 会话或 hooks、主动输入及外部观察材料开始，统一承载文本、图片和链接；助手据此记录需求、事项和待办，再主动整理、推进与提醒。[首批材料与助理目标 ↗](../../../docs/decisions.md#L12 "支持统一输入范围，以及助手记录、整理、推进和提醒需求与事项的预期流程。") 推理层先通过 Agent CLI/ACP 接入可配置的模型、effort 和上下文，暂不要求本地大语言模型；未来需要 embedding 或 reranker 时，小模型依赖由 osdk 管理。[模型接入与本地模型边界 ↗](../../../docs/decisions.md#L10 "支持先采用 Agent CLI/ACP、允许模型参数配置、不要求本地大模型及由 osdk 管理小模型依赖的路线。") 执行层允许高置信度变更自动发生，但每次都要通知；遇到歧义、背景不足、大范围或危险操作时可以询问，而非一律强制询问。通知方式与频率可配置，Vue、设计资产和公共组件则约束前端实现。[自治、通知与前端约束 ↗](../../../docs/decisions.md#L14 "支持高置信度自动变更须通知、特殊情形可以询问、通知可配置以及 Vue 和公共组件的实现约束。")

<a id="progress-and-limits"></a>
## 进展、约束与未决边界

这些决策描述方向，不代表相关能力均已落地：实际进展需另查实施状态；部分机器人完成联调也不能推出所有连接器均已启用，连接、采集和投递仍须服从现有配置及用户授权。[外部集成的实际范围 ↗](../../../docs/decisions.md#L19 "支持区分产品方向与当前能力，并说明连接、采集和投递范围受运行配置及用户授权约束。") 工具链方面，基础依赖由 osdk 管理，但容器尚未完整实测，能力不足或缺陷需要如实记录。[工具链验证限制 ↗](../../../docs/decisions.md#L17 "支持 osdk 依赖管理要求以及容器尚未完整实测这一实施限制。") 此外，低价值飞书质量标注已被叫停；后续 worker 分工与确认时机的 v3 方案仍是设计建议，不能表述为已经实现或通过真实用户验收。[质量标注停止与方案状态 ↗](../../../docs/decisions.md#L21 "支持低价值飞书质量标注已停止，以及 v3 处理策略不能视为已实现或已验收的判断。") 已有主题知识同样将其归入当前自治与集成限制。[自治与当前限制 ↗](3d9dcd2cda0171189ad65dc88b7556f56e6ba30ac99dc5b91fc236fd4182b50a.md#autonomy "引用已有主题知识对自治边界、外部集成和停止状态之间关系的整理。")
