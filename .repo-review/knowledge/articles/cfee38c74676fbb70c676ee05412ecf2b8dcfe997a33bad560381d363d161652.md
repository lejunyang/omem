# 代码高亮与逐行 HTML 拆分

为阅读界面的代码块提供按需语法高亮、安全降级和逐行渲染能力，并在拆分行号时延续跨行语法样式。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

阅读界面既要显示带语法颜色的代码，也要避免把所有语言定义打进初始资源。这里仅声明 TypeScript、JavaScript、XML、CSS、Markdown、JSON、INI 和 Bash 的动态加载器，并把 `tsx`、`vue`、`toml` 等常见标记映射到实际高亮器；字面量导入也便于 Vite 在开发和生产构建中解析代码块。参考 [语言加载与别名 ↗](../../../packages/ui/src/highlight.ts#L3 "支持按需加载的语言集合、常见语言别名以及字面量动态导入的构建目的。")

<a id="highlight-flow"></a>
## 从语言标记到安全 HTML

`highlightCode` 先将语言名转为小写并查询别名。无法识别时不尝试自动猜测，而是转义 `&`、`<`、`>` 后返回，从而保留原代码并防止其被当作 HTML。支持的语言按需加载且只在尚未注册时注册；XML 还会同时准备 JavaScript 和 CSS，以支持 HTML、Vue 一类混合内容。最后由 highlight.js 生成高亮片段，并允许非法词法内容继续渲染。参考 [高亮处理流程 ↗](../../../packages/ui/src/highlight.ts#L21 "支持未知语言转义降级、混合语言依赖加载、注册和最终高亮输出的流程说明。")

<a id="line-rendering"></a>
## 逐行展示如何保持跨行样式

行号或逐行定位要求每一行都是独立、合法的 HTML，但高亮器生成的 `<span>` 可能跨越换行。`highlightedLines` 因而维护开放标签栈：遇到换行时先补齐当前行的闭合标签，再让下一行重新带上仍处于开放状态的标签；普通标签则随遍历入栈或出栈。参考 [跨行样式恢复 ↗](../../../packages/ui/src/highlight.ts#L35 "支持输入前提、开放标签栈以及换行时闭合并重开标签的逐行拆分机制与限制。")

这个拆分器明确只接受 highlight.js 产生的已转义文本和 `span`，并非通用 HTML 解析器；若传入其他标签、属性中包含特殊片段或结构不平衡的 HTML，其结果没有保证。当前材料也没有展示调用方，因此只能确认它提供高亮与分行能力，不能据此断言具体页面如何添加行号、复制操作或证据定位。参考 [跨行样式恢复 ↗](../../../packages/ui/src/highlight.ts#L35 "支持输入前提、开放标签栈以及换行时闭合并重开标签的逐行拆分机制与限制。")
