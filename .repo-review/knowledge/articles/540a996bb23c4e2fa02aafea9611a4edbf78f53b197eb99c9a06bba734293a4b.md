# Lark Runtime Host 实时连接验证

在已有本地连接与加密凭据基础上，先执行发送安全门和官方能力探测，再启动 Lark Runtime Host，轮询事件直到确认 connected，并始终释放主机与数据库资源。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="guards"></a>
## 前置条件与安全门

脚本使用指定数据目录打开 Store，并要求从环境变量直接取得密钥，或从指定密钥文件读取；缺少密钥会立即终止。它还查询尚处于 pending、retry_wait 或 sending 的 Lark 投递，默认拒绝在存在待发送消息时启动，只有显式设置允许投递的环境开关才继续，避免冒烟测试意外发送业务通知。[密钥要求与待投递安全门 ↗](../../../scripts/live-lark-host-smoke.ts#L15 "支持密钥前置条件及默认拒绝发送积压 Lark 投递的安全边界。")

随后脚本读取最早创建的 active 连接，从加密 secret store 取凭据，并核对凭据 appId 与数据库连接记录一致；缺连接或不匹配都关闭 Store 后失败。[活动连接与凭据一致性检查 ↗](../../../scripts/live-lark-host-smoke.ts#L42 "支持选择 active 连接、读取加密凭据并核对 appId 的流程。")

<a id="capability"></a>
## 能力验证与主机组装

官方能力探针使用凭据和默认 Lark 配置检查 scopes、callbacks、事件验证及机器人身份等运行条件；探测异常会先关闭数据库再上抛，任何 missing 项也会阻止启动。[官方 Lark 能力探测 ↗](../../../scripts/live-lark-host-smoke.ts#L62 "支持能力探测失败或存在缺项时阻止 Runtime Host 启动的论断。") 通过后，脚本把 Store、MemoryService、onboarding、secret store 组合成 `LarkRuntimeHost`，使用 500 毫秒轮询间隔和独立 worker 标识，显示该验证覆盖连接注册、凭据、记忆服务与运行主机的集成关系。[Lark Runtime Host 依赖组装 ↗](../../../scripts/live-lark-host-smoke.ts#L77 "说明运行主机与 Store、MemoryService、onboarding、secret store 的关系。")

<a id="assertions"></a>
## 连接判定与未覆盖行为

启动后最多轮询 180 次、每次等待 500 毫秒，读取开始时间之后的连接事件；只有出现 `connected` 才通过，否则报告已观察到的状态。成功输出能力摘要、启动前待投递数和 host 状态。无论成功或异常，`finally` 都停止 host 并关闭 Store。[连接事件轮询与资源清理 ↗](../../../scripts/live-lark-host-smoke.ts#L93 "支持 connected 判定、超时窗口、诊断输出以及 finally 清理行为。")

该检查证明主机在约 90 秒窗口内建立连接，但没有注入或断言真实消息收发、重连、回调处理和投递完成；若显式允许已有投递，测试可能产生外部发送副作用。
