# 材料键如何定位数据库来源

解释外部材料键与内部来源 ID 的显式别名、结构化回退规则，以及无冒号、多冒号和未命中时的真实行为。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为什么需要身份映射

知识文章可以长期保留导入时的外部材料键，而本地数据库用 `source_id` 标识来源。这里用持久化别名表连接两者：`material_key` 是唯一键，`source_id` 必填并引用 `sources`；建表采用 `IF NOT EXISTS`，可在初始化时重复调用。设计意图是依赖明确保存的导入数据，而不是从生产者名称猜测材料身份。参考 [显式别名表 ↗](../../../apps/server/src/knowledge/material-identity.ts#L3 "支持外部键保留、显式持久化映射以及别名表字段约束的说明。")

<a id="resolution"></a>
## 从材料键解析来源

调用 `sourceForMaterialKey(db, key)` 时，函数先检查别名表是否存在；若存在，就按完整材料键精确查询，命中后立即返回字符串形式的来源 ID。这样，新数据库可使用显式别名，未创建别名表的旧数据库也不会因直接查询不存在的表而失败。参考 [别名优先解析 ↗](../../../apps/server/src/knowledge/material-identity.ts#L8 "支持先检查别名表、再按完整材料键查询并立即返回来源 ID 的流程。")

别名未命中后，函数以**第一个冒号**切分键：冒号前作为 `namespace`，其后全部内容作为 `external`。随后查询同命名空间的来源，既接受 `external_id` 等于外部部分，也兼容 `external_id` 为空且来源自身 `id` 等于外部部分的记录；命中返回 ID，否则返回 `null`。参考 [结构化回退查询 ↗](../../../apps/server/src/knowledge/material-identity.ts#L13 "支持首个冒号切分、无冒号时仍执行切片，以及按命名空间和外部标识查询来源的说明。")

<a id="boundaries"></a>
## 格式边界与修改入口

函数没有显式校验冒号。若键不含冒号，`indexOf` 得到 `-1`：按 JavaScript 的切片语义，`namespace` 会是去掉最后一个字符的键，`external` 则是完整键；函数仍用这两个值查询，查不到才返回 `null`，特殊数据组合也可能命中。若键含多个冒号，只有第一个是分隔符，其余冒号保留在 `external` 中。参考 [结构化回退查询 ↗](../../../apps/server/src/knowledge/material-identity.ts#L13 "支持首个冒号切分、无冒号时仍执行切片，以及按命名空间和外部标识查询来源的说明。")

因此，调整材料键格式时应同时审视切分语义与来源查询条件；若目标是拒绝无冒号输入，需要在切片前增加明确校验，而不能把当前的未命中结果当作格式验证。最终返回值只表达是否找到来源：找到时为字符串 ID，否则为 `null`。参考 [来源解析结果 ↗](../../../apps/server/src/knowledge/material-identity.ts#L14 "支持查询命中时返回字符串来源 ID、未命中时返回 null 的结论。")
