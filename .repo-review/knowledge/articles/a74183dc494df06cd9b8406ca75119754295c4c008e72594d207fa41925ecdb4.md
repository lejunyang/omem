# 个人模式与 Repo Review 的开发进程编排器

统一选择并传递 API/Web 端口，启动对应 API 与专用 Vite 子进程，以健康端点作为 API 就绪门禁，并在信号、启动超时或任一子进程退出时成组关闭和传播退出状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="mode_boot"></a>
## 模式选择与启动链路

编排器以 `OMEM_DEV_MODE` 区分 review 和 personal：前者默认 5180/5181、启动 review API，后者默认 4317/5173、启动个人 API并开启 Node watch。它先调用端口选择器并禁止 API 与 Web 端口相同，再将最终端口注入服务和 Vite 代理环境；两个子进程都由 Node 直接启动。[开发模式、端口与子进程启动 ↗](../../../scripts/dev-review.ts#L81 "支持 personal/review 分支、默认端口、入口文件、watch 差异及端口环境传递的说明。") 非 Windows 平台设置独立进程组，以便关闭时向整组发送信号。

<a id="readiness"></a>
## 就绪判定与失败传播

任一子进程触发 `error` 或 `exit` 都进入统一 shutdown，并依据退出码或信号计算父进程状态。编排器为 API 健康轮询设置 60 秒截止时间，单次 fetch 最多等待 2 秒，每次失败后间隔 500 毫秒；若请求在截止前已开始，在途请求和随后间隔可能使实际返回略超 60 秒。[子进程失败与 API 健康门禁 ↗](../../../scripts/dev-review.ts#L114 "支持失败传播、60 秒轮询截止、单次请求超时、轮询间隔和就绪地址输出的精确描述。") 只有 API 健康后才打印访问地址；Web 没有独立 HTTP 就绪探测，仅要求 Vite 子进程未提前退出。

<a id="shutdown"></a>
## 跨平台关闭与边界条件

关闭路径有重入保护：Windows 使用 `taskkill /T /F`，其他平台向子进程组发送 SIGTERM。两个 `waitForExit` 并行执行，各自最多约 5 秒，外层另有 6.5 秒竞速兜底。[跨平台有界进程树关闭 ↗](../../../scripts/dev-review.ts#L17 "支持重入保护、Windows 与非 Windows 的关闭方式，以及每个子进程等待上限和外层兜底。") 非 Windows 超时后不会升级为 SIGKILL，编排器也不自动重启子进程；顶层异常日志固定写作 `repo-review`，即使处于 personal 模式也是如此。
