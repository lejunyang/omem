# 个人模式与仓库评审模式的开发进程编排

该脚本统一启动个人 omem 与 repo-review 的 API、Web 开发进程，负责端口预检与传递、健康检查、子进程故障传播，以及跨平台的成组关闭；它解决双进程部分启动、代理错连和残留 watcher 等开发期生命周期问题。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-mode"></a>
## 作用与模式选择

脚本是个人模式和仓库评审模式共用的开发入口：`OMEM_DEV_MODE` 为 `personal` 时启动个人服务，否则进入 repo-review，并据此选择标签、默认端口、服务入口和健康检查路径。[开发模式与默认端口分支 ↗](../../../scripts/dev-review.ts#L6 "支持脚本按个人或仓库评审模式选择标签、端口变量和后续运行分支的说明。") 它把当前工作目录作为两个子进程的根目录，并直接使用当前 Bun 可执行文件，因而假定调用者已在仓库根目录用 Bun 启动此脚本。[仓库根目录与 Bun 运行时 ↗](../../../scripts/dev-review.ts#L10 "支持两个子进程共享当前工作目录并使用当前可执行文件的运行环境假设。")

<a id="startup-flow"></a>
## 端口预检、进程启动与就绪判定

启动前先通过端口模块检查 API 与 Web 端口；显式配置非法或被占用时快速失败，默认端口被占用时可改用系统分配端口。随后还拒绝 API 与 Web 选到同一端口，避免半启动后才暴露监听冲突。[启动前端口选择与冲突检查 ↗](../../../scripts/dev-review.ts#L81 "支持 API、Web 端口预检、模式相关默认值、同端口拒绝以及失败退出流程。")

预检通过后，脚本分别启动 API 和 Vite 包装脚本，并把选定端口同时注入后端、Web 代理环境。个人 API 带 `--watch`，评审 API 则直接运行专用入口。[API 与 Web 子进程启动 ↗](../../../scripts/dev-review.ts#L93 "支持个人模式 watch、评审专用入口以及端口环境变量传递给后端和代理的说明。") 启动并不等于就绪：它最多轮询健康端点 60 秒，每次请求限时 2 秒；成功后才打印访问地址，超时则按失败路径关闭全部子进程。[健康检查与就绪输出 ↗](../../../scripts/dev-review.ts#L131 "支持健康端点选择、60 秒等待窗口、请求超时、失败关闭和成功后输出地址的流程。")

<a id="shutdown-and-failure"></a>
## 关闭协同与故障传播

任一子进程报错或退出都会触发统一关闭，并把正常退出码或信号导致的失败转换为编排器退出码；收到 `SIGINT`、`SIGTERM` 时则以成功码收尾。[子进程退出及系统信号处理 ↗](../../../scripts/dev-review.ts#L114 "支持子进程错误或退出触发整体关闭，以及 SIGINT、SIGTERM 的退出码语义。") 关闭过程具备重入保护：首次调用终止 API 与 Web，后续并发关闭请求等待同一 Promise，防止重复清理和竞态。[可重入关闭编排 ↗](../../../scripts/dev-review.ts#L54 "支持关闭过程复用同一 Promise、终止两个子进程并最终退出父进程的论断。")

Windows 使用 `taskkill /T /F` 清理进程树；其他平台向负 PID 发送 `SIGTERM`，依赖子进程以独立进程组启动。等待子进程退出有单个 5 秒界限，整体另设 6.5 秒兜底，之后父进程直接退出。[跨平台进程树终止与有界等待 ↗](../../../scripts/dev-review.ts#L17 "支持 Windows 与非 Windows 的不同终止方式，以及子进程退出等待存在时间上限。")

<a id="boundaries"></a>
## 边界条件与模块关系

该脚本与 `dev-ports` 的关系有明确源码依据：导入并调用 `selectDevPort`，后者通过临时监听 `127.0.0.1` 验证端口；默认值冲突时递归请求端口 `0`，显式值冲突则报错。[开发端口选择器 ↗](../../../scripts/dev-ports.ts#L3 "解释被编排脚本调用的端口模块如何校验范围、探测占用，并区分默认端口与显式端口冲突。") 但端口检查和真正启动子进程之间仍存在竞态窗口，其他进程可能抢占刚释放的端口。

当前材料没有测试文件，因此无法确认关闭超时、信号传播、Windows 进程树、健康检查失败以及端口竞态是否有自动化断言。另一个可见限制是顶层异常日志固定写作 `repo-review: fatal`，即使处于个人模式也不会使用动态标签。[顶层异常处理 ↗](../../../scripts/dev-review.ts#L160 "支持未捕获异常会固定输出 repo-review 标签并以失败码退出这一边界说明。")
