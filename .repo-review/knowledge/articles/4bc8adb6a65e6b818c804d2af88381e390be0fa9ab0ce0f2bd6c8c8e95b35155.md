# 总体架构、数据主链与运行边界

omem 以统一 Capture 接收多类材料，经 Source、不可变 Revision 和固定 Fragment 建立证据主链，再由持久作业生成经复核的知识及受治理结果；检索、助手和 Code Wiki 都围绕该主链提供服务或派生视图。当前实现以单用户 SQLite 为基础，模块化单体仍是设计方向，语义检索、跨文件精确调用、跨修订身份续接及全面自动重核验尚未完成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence-chain"></a>
## 从采集到固定证据

手工、文件、Git、聊天、Hook 等输入先规范为统一 Capture，可包含文本、图片、链接、上下文及逐部分来源信息。[采集与证据基础 ↗](439de5f507fee66e8fe835c284be88fb9de9c14a25605109433a2c72974d6580.md#capture-evidence "解释统一 Capture 的多模态输入、逐部分来源信息以及 Revision、Fragment 的跨层数据形状。") Store 按来源命名空间和外部标识归并 Source：重复事件或相同内容复用既有结果，内容变化则追加 Revision、生成固定 Fragment 并切换当前 head。[来源归并与不可变修订写入 ↗](../../../apps/server/src/store.ts#L141 "支持事件幂等、相同内容复用、Source 归并及新 Revision、Fragment 追加的论断。") 聊天与屏幕事件还可先经暂存和聚合，再进入同一捕获入口，而不是另建事实系统。[外部输入暂存与聚合 ↗](fe2bd502927378e92217d69a28e09525ae3d1a2b898caa697823d01e20e5614d.md#responsibility "链接 inputs 子知识，解释 Hook 暂存和聊天、屏幕事件聚合如何衔接统一 Capture。")

Revision 与 Fragment 构成历史证据锚点；派生回答不是新的独立证据，普通高置信变更可自治处理，但歧义、缺少背景、范围过大或危险动作需要决策。[不可变证据与自治边界 ↗](../../../AGENTS.md#L8 "直接支持派生回答不是独立证据，并说明普通高置信变化与需人工决策情形的边界。") 这补正了旧稿中未给该规则直接依据的表述。

<a id="processing-flow"></a>
## 持久作业、知识与受治理结果

捕获后的异步处理进入持久任务：仓储负责去重、租约、尝试、重试和取消，Worker 按 kind 领取任务并选择处理器。[持久任务生命周期 ↗](f4f199e2abaf896ca67a8eb152d9c952d9c059d237fbbab48bf64c1233f3cc04.md#lifecycle "链接 jobs 子知识，说明任务仓储与执行器在租约、重试、取消和处理器运行中的分工。")[任务领取与处理器选择 ↗](../../../apps/server/src/jobs/worker.ts#L47 "支持 Worker 按 kind 和任务范围领取工作，并在缺少处理器时明确失败。") 知识流程明确遵循“分析原始材料—独立复核—组织模块、主题和概览”，引用贴近论断，失败或过期结果不得覆盖有效知识。[正文分析与独立复核流程 ↗](../../../AGENTS.md#L28 "直接支持先分析、再独立复核、最后组织知识，以及内联引用、调查项和失败结果保护规则。") 正文、引用、问题、依赖和复核 trace 的交换格式由共享合同承载。[知识制品与复核合同 ↗](c01c1ec26d70872800ea01fc48f7c0c5da86fc61bf8300f5041986e68a110baf.md#knowledge-flow "链接 contracts 子知识，说明知识正文、引用、依赖、生成 trace 与接受复核 trace 的合同关系。")

普通来源更新会推进有效性代次、使旧记忆依赖失效并排入刷新作业。[来源更新传播 ↗](../../../apps/server/src/store.ts#L221 "支持来源 head 和有效性代次更新、旧记忆依赖失效及刷新作业入队。") 记忆与待办采用版本化写入和乐观锁，记忆还能登记来源依赖；它们是受治理结果，不取代原始 Fragment。[记忆与待办版本化应用 ↗](../../../apps/server/src/storage/repository.ts#L400 "支持记忆和待办的版本化写入、乐观锁、修订追加及记忆来源依赖登记。") 自动提交可信变化、将冲突和高影响动作交由判断属于设计中的风险分层，不能仅凭合同推断已在所有入口强制执行。[自治闭环与风险分层设计 ↗](../../../docs/design.md#L108 "说明普通可信变更、高影响冲突、硬删、扩权和外发资料在设计中的不同处理等级。") 手工恢复目前主要复制旧修订与片段并切换 head，未展示与普通更新完全相同的派生状态刷新。[新修订式手工恢复 ↗](../../../apps/server/src/store.ts#L493 "支持恢复路径复制旧修订、片段和出边后切换 head，并据此指出其与普通更新传播流程的可见差异。")

<a id="retrieval-assistant-ui"></a>
## 检索、对话与阅读投影

统一检索端口把当前关键词基线与未来后端隔离；来源候选携带 Revision、Fragment 和来源信息，可回读固定原文，摘要与分数只是定位线索。[统一检索流程 ↗](08f25ff6e25e1918acb0892c2a3a12abd21c662ab179814edc853f516920ebfb.md#retrieval-flow "链接 retrieval 子知识，解释关键词检索、固定证据回读以及后端替换边界。")[检索候选与证据回读端口 ↗](../../../apps/server/src/retrieval/port.ts#L45 "支持来源候选携带 Revision、Fragment 与 provenance，并区分来源搜索、记忆召回和证据回读。") 服务组合根实际创建 Fastify、SQLite Store、知识路由、关键词检索、ACP 模型适配器和 AssistantRuntime。[服务端核心组件装配 ↗](../../../apps/server/src/app.ts#L44 "支持 Fastify、Store、知识路由、关键词检索、ACP 模型和 AssistantRuntime 的实际组合关系。") 启动时恢复未完成对话并启动提醒、输入聚合及可选 worker，关闭时再按顺序释放资源。[应用恢复与资源生命周期 ↗](../../../apps/server/src/app.ts#L589 "支持未完成助手回合恢复、周期任务及可选 worker 启动，以及关闭时资源释放顺序。")

阅读侧沿共享 Evidence Trail 打开知识、原文和代码，内部标识只用于路由；Code Wiki 与个人知识入口共用合同。[共享证据阅读流程 ↗](9565fe1ee6ab869d3330d0fbd8f7631ca5af19eb28aeb3f20850c337d6be4acd.md#workflow "链接项目子知识，说明知识、原文与代码阅读复用 Evidence Trail，Code Wiki 沿用统一证据链。") 代码快照、文件、符号、关系和理解结果属于隔离 review SQLite 的附加读视图，不替代 Source、Revision、Fragment；代码位置只在生成它的 head 快照内有效。[代码知识附加投影 ↗](../../../packages/contracts/src/index.ts#L884 "支持代码快照、符号、关系和理解结果是隔离 review 数据库的附加读视图，且位置只在对应快照内有效。")

<a id="runtime-boundaries"></a>
## 部署现状、恢复能力与限制

当前 Store 将迁移、作业、输入聚合、运行请求和来源画像装配到同一 SQLite 连接。[单用户 SQLite 存储装配 ↗](../../../apps/server/src/store.ts#L1 "支持 Store 创建 SQLite、执行迁移并向作业、输入、运行请求和来源画像服务共享连接。") “一个 API、一个 worker 代码库”的模块化单体是设计方向，而不是仅凭现有材料即可证明的完整部署拓扑；旧稿把它直接写成已实现运行形态，现已被此结论替代。[模块化单体设计方向 ↗](../../../docs/design.md#L91 "将一个 API、一个 worker 代码库及共享领域合同限定为设计建议，避免冒充已验证的完整部署拓扑。") 当前 SQLite/shared-token 明确是单用户基础，访问 token 不等于租户级身份、授权和数据隔离。[单用户与租户隔离边界 ↗](../../../AGENTS.md#L8 "直接支持当前 SQLite/shared-token 实现仅面向单用户，不能宣称已有租户强制隔离。")

repo-review 使用独立 SQLite且不起个人业务 worker；启动恢复已提交知识，模型分析与局部生成必须显式触发，索引可单独重建。[仓库评审隔离运行入口 ↗](../../../README.md#L24 "支持 review 的独立 SQLite、无个人业务 worker，以及知识恢复、模型分析和索引重建的入口差异。") 已复核正文可保存为 JSON 和内联链接 Markdown，启动及同步接入材料与知识恢复；因此这里只确认已提交知识与当前知识索引可恢复，不再泛称搜索结果和代码图都能恢复。[已复核知识产物与恢复 ↗](../../../docs/implementation/knowledge-pipeline.md#L31 "支持复核正文的可提交格式、材料和知识恢复、索引重建边界及失败项不冒充已生成。") 当前未完成 embedding 检索、跨文件调用的精确类型解析和所有来源自动重核验。[尚未交付的检索与重核验能力 ↗](../../../README.md#L52 "直接支持跨文件精确调用解析、embedding 检索及所有来源自动重核验尚未完成。") 跨修订符号与 Fragment 身份续接也未实现，代码变化后需重新同步定位；该限制由独立材料直接支持。[跨修订身份续接限制 ↗](../../../AGENTS.md#L23 "直接支持跨修订符号和 Fragment 身份续接未实现，并说明代码变化后需要重新同步定位。")
