# 总体架构、数据主链与运行边界

omem 以统一多模态 Capture 和 Source 与不可变 Revision／固定 Fragment 主链连接持久作业、知识复核、来源与记忆检索、助手及阅读界面；当前实现由 Fastify、共享合同和单用户 SQLite 组成，Code Wiki 是隔离但可追溯的派生视图。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence-mainline"></a>
## 从 Capture 到固定证据

手工、文件、Git、Lark、聊天、Hook 与屏幕观察统一进入 Capture；文本、图片、链接及逐部分参与者、时间、转发等来源信息使用同一合同。[统一多模态采集合同 ↗](../../../packages/contracts/src/index.ts#L1 "支持各类采集来源、文本图片链接 part 以及逐部分来源信息的架构说明。") Store 对事件与内容做幂等判断；内容变化时为 Source 追加 Revision、切换可变的 `head`，并生成固定 Fragment，旧修订仍保留。[Store 捕获、Source head 与修订流程 ↗](../../../apps/server/src/store.ts#L141 "支持 Source 的创建或复用、可变 head 更新、Revision 追加、固定 Fragment 及来源更新传播，并纠正把 Source 称为不可变对象的旧结论。") 因此 Source 是持续演进的材料身份与当前版本入口，不属于不可变对象；不可变的是历史 Revision，Fragment 则充当固定证据锚点。这取代了此前把 Source、Revision、Fragment 一并称为不可变主链的过宽结论。共享合同细节可继续下钻到“采集与证据基础”。[采集与证据基础 ↗](439de5f507fee66e8fe835c284be88fb9de9c14a25605109433a2c72974d6580.md#capture-evidence "提供 Capture、Source、Revision 与 Fragment 关系的共享合同子知识入口，便于逐层下钻。")

原始捕获会在同一数据库事务中排入声明提取作业；派生材料被排除，防止模型总结自循环成为独立证据。[派生材料的作业隔离 ↗](../../../apps/server/src/store.ts#L353 "支持原始捕获进入声明提取队列，而派生材料不自循环成为独立证据。") 知识正文和回答只能解释、组织或引用这些证据，不成为新的独立事实来源。

<a id="processing-retrieval"></a>
## 作业、知识与检索如何衔接

持久 jobs 将语义处理与请求生命周期解耦：worker 以租约领取任务、心跳续期，并提交成功或分类失败；更完整的重试、取消与租约限制可从 jobs 子知识下钻。[任务租约与执行流程 ↗](../../../apps/server/src/jobs/worker.ts#L72 "支持 worker 领取任务、心跳续租、调用处理器并分类完成或失败的运行流程。")[持久作业生命周期 ↗](f4f199e2abaf896ca67a8eb152d9c952d9c059d237fbbab48bf64c1233f3cc04.md#lifecycle "链接 jobs 子知识中有关入队、租约、重试、取消及当前限制的详细说明。") 知识流程先分析原始材料，再独立复核和组织章节；引用贴近论断，错误或过期结果不得覆盖有效知识。[知识分析、复核与组织规则 ↗](../../../AGENTS.md#L28 "支持先分析原始材料、独立复核、内联固定引用及失败结果不得覆盖有效知识。")

检索端口隔离具体后端，当前关键词实现分别搜索固定来源片段和 active memory。只有来源候选直接返回 Revision／Fragment 定位并可回读原文；记忆候选用于已应用记忆的冲突或复用召回，合同未直接携带固定证据定位。[来源与记忆候选合同 ↗](../../../apps/server/src/retrieval/port.ts#L45 "区分来源候选与记忆候选，支持只有来源候选直接携带 Revision 和 Fragment 定位的修正结论。")[检索与证据回读 ↗](08f25ff6e25e1918acb0892c2a3a12abd21c662ab179814edc853f516920ebfb.md#retrieval-flow "链接 retrieval 子知识，说明来源搜索、active memory 搜索及固定证据回读的不同边界。") 这取代了“全部关键词结果都返回固定证据定位”的过宽结论。

<a id="runtime-boundaries"></a>
## 组合根、派生视图与当前边界

服务端组合根装配 Fastify、Store、记忆与反馈服务、ACP 模型适配器、关键词检索和 AssistantRuntime；启动时恢复未完成对话并运行提醒、输入聚合，关闭时停止组件并释放存储。[服务端组合根 ↗](../../../apps/server/src/app.ts#L44 "支持 Fastify、Store、领域服务、ACP 模型、关键词检索与 AssistantRuntime 的装配关系。")[启动恢复与关闭流程 ↗](../../../apps/server/src/app.ts#L589 "支持对话恢复、提醒和输入聚合启动，以及关闭时停止组件和释放存储。") “一个 API 与 worker 代码库共享领域合同，确定性步骤直接执行、语义判断才调用模型”是架构设计原则，不应仅凭组合根代码视为完整实施证明。[模块化单体设计原则 ↗](../../../docs/design.md#L91 "支持一个 API 与 worker 代码库共享领域合同，以及确定性步骤和语义模型步骤的设计分工；同时将其限定为设计原则。")

Code Wiki 的知识正文与代码结构图均是统一 Capture→Source／Revision／Fragment 链上的派生视图；隔离 review SQLite 只是输入适配与运行配置。[Code Wiki 的统一派生视图定位 ↗](../../../AGENTS.md#L16 "支持知识正文、引用与代码结构图同属统一材料链派生视图，并说明 repo-review 只是隔离适配与运行配置。") 代码结构和理解类型也是附加读视图，不替代来源、修订、片段及关系，且代码位置仅对生成它的快照有效。[Code Knowledge 附加读视图 ↗](../../../packages/contracts/src/index.ts#L884 "支持代码结构和理解投影不替代统一来源链，以及代码位置仅在对应快照内有效。") 当前 SQLite/shared-token 明确为单用户实现，没有租户强制隔离。[单用户部署边界 ↗](../../../AGENTS.md#L8 "直接支持当前 SQLite/shared-token 实现是单用户且不存在租户强制隔离。") 跨文件调用解析和跨修订符号／片段身份续接尚未实现；embedding 检索及所有来源自动重核验也仍未交付。[代码解析与身份续接限制 ↗](../../../AGENTS.md#L26 "支持跨文件 calls 不解析及跨 Revision 符号、Fragment 身份续接未实现。")[尚未交付的检索与重核验能力 ↗](../../../README.md#L52 "直接支持精确跨文件类型解析、embedding 检索和所有来源自动重核验尚未完成。")
