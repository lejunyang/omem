# 总体架构、证据主链与运行边界

omem 以统一多模态捕获、不可变修订和固定原始片段构成可追溯证据基础，当前服务组合根在单用户 SQLite 上连接持久作业、混合检索、ACP 助手及可选学习管线。模块化单体是设计建议；源码已证明若干局部链路，但抽取到独立复核及实体应用、团队隔离、聚合事务补偿与跨快照代码身份仍有明确边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-shape"></a>
## 可追溯目标与当前服务形态

omem 面向个人长期复用文档、代码、聊天和任务经历：读者应能从结论回到固定原文，并沿引用继续阅读。成效关注旧问题能否更快解决、材料更新后是否停用旧结论，以及重要回答能否追溯到证据。参考 [可追溯记忆目标 ↗](../../../docs/design.md#L9 "支持系统解决的问题、引用阅读体验和效果型成功标准。")

架构提案建议采用模块化单体，由 API 与 worker 共享领域合同；该提案明确不等于当前运行代码。参考 [设计提案状态 ↗](../../../docs/design.md#L5 "说明架构文档是第一轮设计与原型提案，不等于当前运行实现。") [模块化单体建议 ↗](../../../docs/design.md#L91 "支持设计层建议 API 与 worker 共享领域合同，而非证明该部署形态已经完整落地。") 当前实现中，服务组合根创建 Fastify 与 Store，并装配知识路由、检索、ACP 助手及可选学习管线。参考 [服务组合根 ↗](../../../apps/server/src/app.ts#L47 "支持 Fastify、Store、运行记录和记忆服务的实际初始化。") [助手与检索装配 ↗](../../../apps/server/src/app.ts#L74 "支持知识路由、检索、ACP 助手与可选学习管线的实际连接关系。") Store 直接创建并迁移 SQLite 数据库，源码将其定位为单用户基础，团队级权限隔离仍属后续迁移。参考 [单用户 SQLite 基础 ↗](../../../apps/server/src/store.ts#L4 "证明 Store 创建并迁移 SQLite 数据库，同时明确当前是单用户基础而非团队级隔离。")

<a id="capture-and-refresh"></a>
## 统一捕获、修订与更新失效

手工、文件、Git、飞书、Hook，以及成熟的聊天或屏幕批次共享文本、图片、链接和部件级来源合同，并进入同一捕获入口。参考 [统一捕获合同 ↗](../../../packages/contracts/src/index.ts#L4 "支持文本、图片、链接、多来源入口和部件级来源信息共享同一合同。") [多来源捕获入口 ↗](../../../apps/server/src/app.ts#L202 "支持直接输入和成熟聚合批次进入 Store.capture。") 捕获会校验图片内容，以事件收据处理安全重放与冲突；新内容保存为递增修订和固定片段，来源更新后旧依赖失效并入列重核验。参考 [图片资产校验 ↗](../../../apps/server/src/store.ts#L102 "支持捕获时校验图片大小、编码和文件头，并按内容哈希保存资产。") [捕获幂等与修订更新 ↗](../../../apps/server/src/store.ts#L143 "支持事件冲突检测、内容去重、递增修订、片段创建和来源更新失效。")

原始材料会在捕获事务中入列 `extract_claims`，派生材料则被排除以防自循环；现有材料未展示抽取、独立复核到实体应用的完整状态机。参考 [原始材料抽取入列 ↗](../../../apps/server/src/store.ts#L357 "支持原始材料入列 extract_claims，并界定派生材料防自循环的边界。") 刷新作业入列不代表应用成功，只有相关记忆恢复有效且依赖指向当前修订，刷新记录才会成为已应用。参考 [来源更新重核验 ↗](../../../apps/server/src/learning/refresh.ts#L6 "支持冻结刷新影响集合，并以当前依赖和真实应用状态判断刷新是否完成。")

<a id="jobs-and-retrieval"></a>
## 可恢复作业与原始证据回读

通用作业层负责租约、尝试上限与运行留痕；活动 attempt 可记录模型、提示词、技能、上下文、输出结构和角色结果。参考 [作业领取与执行尝试 ↗](../../../apps/server/src/jobs/repository.ts#L261 "支持过期租约回收、尝试上限、条件领取和 attempt 创建。") [运行轨迹与角色输出 ↗](../../../apps/server/src/jobs/repository.ts#L404 "支持模型与运行指纹更新，以及结构化角色输出和 trace 的事务化保存。") 只有 `bad_output` 和 `transient` 错误会在同类次数及总尝试上限内按指数退避自动重试。参考 [失败重试规则 ↗](../../../apps/server/src/jobs/repository.ts#L581 "支持仅 bad_output 和 transient 错误可自动重试，并受同类次数、总尝试上限和指数退避约束。") 工作器通过心跳维持租约并传递取消信号，但外部副作用能否及时停止仍取决于处理器响应。参考 [心跳与协作式中断 ↗](../../../apps/server/src/jobs/worker.ts#L72 "支持工作器续租、传递 AbortSignal 和处理中断后的结果分类。")

检索把记忆和知识作为导航：记忆通过 evidence set 回到当前原始片段，知识文章检查依赖并沿引用映射到材料片段。参考 [记忆证据回溯 ↗](../../../apps/server/src/retrieval/keyword.ts#L81 "支持记忆命中通过 evidence set 回到当前原始片段。") [知识引用回溯 ↗](../../../apps/server/src/knowledge/retrieval.ts#L33 "支持知识依赖检查、文章引用递归及材料引用到原始片段的映射。") 关键词路径融合代码符号、全文、短关键词、记忆和知识候选；启用语义检索后再融合本地向量，异常时保留词法基线。参考 [五路证据融合 ↗](../../../apps/server/src/retrieval/keyword.ts#L97 "支持代码符号、全文、短关键词、记忆和知识候选的融合。") [语义融合与降级 ↗](../../../apps/server/src/retrieval/semantic.ts#L81 "支持本地语义结果与词法候选融合，并在语义异常时保留词法基线。")

<a id="boundaries"></a>
## 部署、代码视图与一致性边界

当前部署面向单用户；非回环访问需要强令牌，但共享令牌不构成团队租户权限系统。参考 [单用户访问边界 ↗](../../../README.md#L146 "支持非回环访问的令牌要求，并明确共享令牌不是团队权限系统。") 事项操作先保存为原始材料，再以对应片段作为状态变化证据；服务还会恢复未完成问答，并在关闭时依次停止后台组件。参考 [事项操作证据留痕 ↗](../../../apps/server/src/app.ts#L313 "支持事项命令先保存为原始材料，再以其片段作为状态变更证据。") [恢复与有序关闭 ↗](../../../apps/server/src/app.ts#L620 "支持未完成问答恢复、后台循环启动和关闭阶段的资源回收顺序。")

代码知识只是统一证据体系上的附加读视图，源码位置仅在对应快照有效；合同允许 `calls` 等图边并声明同步入口，却不能证明跨文件调用解析或跨快照身份续接已经实现。参考 [代码知识附加视图 ↗](../../../packages/contracts/src/index.ts#L887 "支持代码知识不替代统一来源、修订和片段，并说明源码位置只在对应快照有效。") [代码图边合同 ↗](../../../packages/contracts/src/index.ts#L962 "支持 calls 等图边类型、状态和证据字段，但不证明解析器实际生成这些边。") [代码知识同步端口 ↗](../../../packages/contracts/src/index.ts#L1020 "支持代码知识查询和同步入口，同时表明接口未规定具体同步行为。") 输入聚合还存在事务间隙：外部捕获先发生，本地事务随后才确认事件仍为待处理，并发变化后的补偿方式尚无材料说明。参考 [聚合批次事务间隙 ↗](../../../apps/server/src/inputs/aggregator.ts#L320 "支持外部 capture 先于本地批次事务，并在事件状态变化时拒绝本地提交。")
