# osdk 配置文件参考

说明项目与用户 TOML 配置的合并优先级、顶层段、信任边界，以及工具、源、任务、依赖、模型和 Agent skills 等声明格式；示例是配置语义，不证明项目已经采用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="layers-and-trust"></a>
## 配置层级与信任模型

osdk 使用字段结构相同的项目配置和用户全局配置：项目文件从当前目录向上查找，用户文件承载跨项目默认。覆盖顺序为 CLI、环境变量、项目配置、用户配置、内置默认。[配置文件类型与覆盖顺序 ↗](../../../.agents/skills/osdk-guide/reference/configuration.md#L1 "支持项目和用户配置的用途、查找方式及五级合并优先级。") 顶层段覆盖设置、工具、别名、源、Registry、容器、系统包、任务、依赖、模型和 skills；其中改变执行或下载来源的配置通常需要信任。受管数据与配置目录内的源或代理设置不应手写。[顶层段和信任边界 ↗](../../../.agents/skills/osdk-guide/reference/configuration.md#L13 "支持合法顶层段、各段用途、信任要求及禁止手写受管配置的说明。")

材料对信任规则有概括性与分段细则，实际是否触发仍应以当前 osdk 的逐键诊断为准。

<a id="tools-sources-platform"></a>
## 工具、设置与来源声明

`[settings]` 控制并发、校验、离线、语言、预发布和 shim 行为，其中 `shims.include` 是全局白名单式限制，补充命令更适合使用 `expose`。[设置项与 shim 风险 ↗](../../../.agents/skills/osdk-guide/reference/configuration.md#L37 "支持 settings 的主要字段以及 include 与 expose 的不同风险语义。") `[tools]` 可用字符串或结构化对象固定版本，结构化形式还能携带平台过滤和 backend 选项；动态工具键需要包含命名空间。[工具声明格式 ↗](../../../.agents/skills/osdk-guide/reference/configuration.md#L102 "支持字符串、结构化工具、动态命名空间和平台过滤的配置方式。")

`[sources]` 可定义测速、重试、缓存、固定源和自定义源，但建议通过 source 命令修改。Registry 镜像与工具下载源相互独立，Python 私有 index 不应被公共镜像覆盖。[来源与 Registry 配置 ↗](../../../.agents/skills/osdk-guide/reference/configuration.md#L147 "支持来源测速、自定义源、推荐修改入口以及 Registry 的依赖混淆防护。") 未识别的平台维度或 token 会直接报错，而非静默不匹配。[平台过滤词汇 ↗](../../../.agents/skills/osdk-guide/reference/configuration.md#L392 "支持跨配置段共用的 os、arch 过滤规则及非法值硬错误行为。")

<a id="tasks-and-dependencies"></a>
## 任务图与应用依赖

`[tasks]` 支持字符串、顺序命令数组和完整对象，可定义前置任务、并行子任务、环境、目录、超时、输入输出与新鲜度；数组默认失败即停，只有显式 `ignore_error` 才继续。[任务定义和执行语义 ↗](../../../.agents/skills/osdk-guide/reference/configuration.md#L244 "支持任务结构、前置与并行关系、失败处理和 runner 配置边界。") 根级 `[task_config]` 提供 runner 默认与 monorepo roots，子项目不能另行声明该段。

`[deps]` 与 `[tools]` 分工：前者安装项目依赖，声明 provider 即默认开启自动兑现。provider 可覆盖输入、输出、命令、目录、依赖和安装器，但自定义 index 或允许源码构建会提高信任要求；未知字段会硬报错。[应用依赖 provider ↗](../../../.agents/skills/osdk-guide/reference/configuration.md#L302 "支持 tools 与 deps 的职责划分、自动兑现、覆盖字段及提高信任等级的配置。") 这有助于复现，却不能证明某个 lockfile 完整或依赖已成功安装。

<a id="models-skills-and-example"></a>
## 模型、skills 与最小项目结构

`[models]` 把模型来源、筛选规则、变体、平台和消费者视图声明化；pull 或首次 sync 会结合声明写入锁并渲染视图，改变 endpoint 才进入额外信任边界。[声明式模型配置 ↗](../../../.agents/skills/osdk-guide/reference/configuration.md#L338 "支持模型同步、锁定、视图、平台过滤和自定义 endpoint 信任边界。") `[skills]` 以相似方式声明来源、版本引用、目标 Agent、作用域和链接模式；osdk 只搬运、锁定和链接内容，不执行其中脚本。[声明式 Agent skills ↗](../../../.agents/skills/osdk-guide/reference/configuration.md#L365 "支持 skill 来源、目标 Agent、版本锁定及 osdk 不执行脚本的边界。")

文末最小示例把工具、pnpm 依赖和任务图放进同一 `osdk.toml`。[典型项目最小示例 ↗](../../../.agents/skills/osdk-guide/reference/configuration.md#L423 "支持工具、依赖和任务可组合在一个项目配置中的说明。") 该示例仅展示合法结构，不是当前项目配置、执行历史或验收结果。
