# project · 模块理解 · 专题 1

该专题汇总项目级开发合同：界面以证据阅读为中心，osdk 统一工具链、依赖与任务执行，本地密钥和运行产物遵循明确的安全及版本控制边界。现有材料主要描述规范与配置语义，尚不能证明功能覆盖度或检查结果。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="responsibility"></a>
## 职责与背景

project 层负责把界面、工具链和本地运行边界组织成可复现的开发入口。界面采用 Vue 3 与 TypeScript，视觉依据来自根 `design.md`，公共能力优先复用 `packages/ui`，网络请求和应用状态留在应用层。[界面技术栈与组件边界 ↗](../../../.agents/skills/omem-design/SKILL.md#L8 "支持界面视觉来源、Vue 3 技术栈、公共组件复用，以及网络和状态留在应用层的论断。") 与之配套的 osdk 是跨平台 SDK 管理器，用于统一运行时、包管理器、开发工具和模型快照，并为团队及 CI 保存可复现的锁定结果。[osdk 的项目定位 ↗](../../../.agents/skills/osdk-guide/SKILL.md#L12 "说明 osdk 统一管理跨平台工具链、模型快照及可复现锁定结果的背景。")

两部分共同解决“界面如何保持一致”和“项目如何稳定构建运行”的问题，但这些材料属于规范和参考，并不等同于现有代码已经完整实现。

<a id="workflow"></a>
## 主要流程与跨模块关系

典型流程是先按项目声明兑现依赖，再通过 `osdk run <name>` 执行任务；`install` 管理工具，`deps` 读取项目清单安装应用依赖，二者职责分离。[任务与依赖职责 ↗](../../../.agents/skills/osdk-guide/SKILL.md#L39 "支持项目任务入口以及工具安装与应用依赖兑现相互分工的流程说明。") `deps --frozen` 要求原生锁文件存在且不被修改，`--verify` 则检查已安装环境，分别约束声明稳定性和落地完整性。[依赖冻结与环境核验 ↗](../../../.agents/skills/osdk-guide/reference/commands.md#L109 "支持依赖安装流程中 frozen 锁定和 verify 环境校验的不同作用。")

界面交付围绕固定证据片段展开：递归引用共用一个对话框并保存路径、滚动和草稿，Esc 逐层返回，关闭后恢复焦点；正文及模型输出按不可信内容处理。[证据阅读与安全边界 ↗](../../../.agents/skills/omem-design/SKILL.md#L11 "支持递归引用的状态管理、返回与焦点行为，以及不可信正文和模型输出的处理要求。") 页面必须连接真实 API，并通过项目检查及适用的浏览器检查验证；通用交互应先沉淀到公共 UI 包。[真实状态与界面验证 ↗](../../../.agents/skills/omem-design/SKILL.md#L14 "支持真实 API、诚实空态、检查流程以及公共交互优先沉淀到 UI 包的要求。")

<a id="boundaries"></a>
## 配置、安全与当前限制

配置按 CLI、环境变量、项目配置、用户配置、内置默认依次覆盖；执行代码或改写下载来源的设置进入信任边界，受管配置应通过 osdk 命令修改。[配置优先级与信任机制 ↗](../../../.agents/skills/osdk-guide/SKILL.md#L48 "支持配置覆盖次序、高风险设置需要信任以及受管配置不能手工修改的约束。") 本地 `OMEM_SECRET_KEY` 必须跨重启保持稳定，丢失或轮换会使既有密文不可读，并要求重新授权相关应用。[本地加密密钥生命周期 ↗](../../../.env.example#L1 "支持密钥需稳定保存，以及丢失或轮换会影响既有秘密可读性的说明。")

版本控制将依赖、构建产物、一般环境文件和测试产物排除在仓库外，同时明确保留 `.env.example`。[常规本地产物与环境模板边界 ↗](../../../.gitignore#L1 "支持依赖目录、构建输出、环境文件和测试产物被忽略，同时 `.env.example` 被明确保留的论断。") repo-review 则另行区分受控知识资产与实时运行数据：整理后的知识继续纳入版本控制，运行目录、缓存、临时文件、模型输出和嵌入被忽略。[repo-review 数据隔离 ↗](../../../.gitignore#L15 "支持实时运行目录、缓存和模型输出被忽略，而整理后的知识资产继续受版本控制的边界。") 这组双引用替代了此前仅凭 repo-review 规则概括全部忽略项的宽泛结论。当前材料仍未提供项目实际配置、功能清单、测试退出码或浏览器结果，因此只能确认目标合同，不能判断实现进度、当前 osdk 版本或部署密钥是否就绪。
