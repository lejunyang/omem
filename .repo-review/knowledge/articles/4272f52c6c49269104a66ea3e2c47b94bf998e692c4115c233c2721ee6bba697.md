# 基线 16d3aa6 的审计复现脚本

该脚本以临时 SQLite 和合成输入复现质量评估、记忆策略、聚合归因、Lark 接入及依赖刷新中的十组已知缺口。断言记录基线的实际行为而非产品期望，并明确排除真实 Agent、Lark 网络调用和正式数据写入。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-fixtures"></a>
## 用途与测试边界

该文件是针对基线 `16d3aa6` 的可执行审计复现，用断言记录已知缺口，而非定义正确产品行为。需要持久化状态的场景通过 `setup` 创建临时目录和 `Store`；部分相邻场景会复用同一实例，例如 R8 与 R10 共用 Lark 场景的 Store，而 R1 的规则导入样本并未调用 `setup`。[审计说明与临时 Store 创建 ↗](../../../docs/reviews/2026-09-27-batch2/reproduce.ts#L1 "支持脚本面向基线缺口、使用临时 SQLite，以及仅调用 setup 的持久化场景会登记临时 Store 的说明。") 脚本退出时会在 `finally` 中逐一关闭已登记的数据库并递归删除临时目录。[临时数据库关闭与目录清理 ↗](../../../docs/reviews/2026-09-27-batch2/reproduce.ts#L462 "直接支持 finally 会关闭所有已登记 Store 并递归删除对应临时目录的结论。")

辅助函数构造带固定 provenance 的捕获记录，并从首个 fragment 生成含精确引文、Unicode codepoint selector、个人工作区范围及派生来源的 Proposal；统一注入的 `supported` 判定是确定性夹具，不代表模型结论。因此脚本可隔离策略行为，但没有验证真实模型审核、多片段证据或外部 CLI。[合成捕获、Proposal 与审核判定夹具 ↗](../../../docs/reviews/2026-09-27-batch2/reproduce.ts#L40 "说明测试如何构造 provenance、证据 selector、Proposal 范围及非模型产生的 supported 判定。")

<a id="quality-and-memory-policy"></a>
## 质量指标与记忆决策缺口

质量场景证明，混合“当前事实”和“未来可能性”的整句会被规则导入为可自动应用的 claim。语义错误但沿用原始引文的预测仍得到满分 evidence support，空对象 abstain 也得到满分，说明该指标偏向引文包含关系而非语义蕴含。[质量样本与证据支持率断言 ↗](../../../docs/reviews/2026-09-27-batch2/reproduce.ts#L132 "支持混合时态句被自动应用，以及错误论断和空回答仍取得满 evidence support 的观察。")

记忆策略随后提交互相冲突和重复的 create Proposal，三者均为 `auto_apply`，暴露既有记忆检索、冲突识别和去重缺口；由于 supported verdict 是人工注入，不能将结果归因于模型。不充分且范围未知的提案则进入 `awaiting_decision` 并创建决策，但脚本未覆盖决策消解或重复待决项合并。[冲突、重复与不充分提案策略断言 ↗](../../../docs/reviews/2026-09-27-batch2/reproduce.ts#L207 "支持冲突及重复 create 均自动应用，而不充分提案进入待决状态的策略行为。")

<a id="identity-capture-and-lark"></a>
## 身份、聚合捕获与 Lark 边界

任务归属场景使用 `ou_*` 聊天身份，而 Proposal owner 是规范化的 `owner`，评估因 `owner_not_verified` 进入待决，说明此路径缺少身份映射；原始 agent 捕获同时返回空 job，不会自动触发学习任务。[任务 owner 校验与 agent 捕获结果 ↗](../../../docs/reviews/2026-09-27-batch2/reproduce.ts#L240 "支持 Lark 标识未映射导致 owner_not_verified，以及原始 agent 捕获未生成 job 的论断。")

Alice 与 Bob 的同会话消息聚合后，revision 级 actor 为空，fragment 也没有 actor 字段，因此聚合结果丢失逐片段归因；测试没有证明下游能否从原始 input event 恢复身份。[多人会话聚合归因断言 ↗](../../../docs/reviews/2026-09-27-batch2/reproduce.ts#L258 "支持聚合 revision 清空 actor 且 fragment 不携带 actorId，从而丢失逐片段归因的结论。") Lark 本地收件箱还断言 owner 私聊被忽略、群聊图片以含 `image_key` 的文本 part 入库。该场景未建立 SDK 连接或真实出站链路，不能证明线上 Lark 行为。[Lark 私聊过滤与图片文本化 ↗](../../../docs/reviews/2026-09-27-batch2/reproduce.ts#L298 "支持 owner 私聊被忽略、图片以文本 part 入库以及场景未调用真实 Lark 链路的描述。")

<a id="cancellation-and-refresh"></a>
## 取消语义、失效刷新与未覆盖行为

质量标注会话取消后，已排队投递仍被 worker 交给假发送适配器，发送计数为 1，说明该基线下取消状态没有阻止这条出站消息。断言仅覆盖单次假发送，未覆盖真实网络、重试、并发取消或撤回。[取消后的标注消息投递 ↗](../../../docs/reviews/2026-09-27-batch2/reproduce.ts#L359 "支持标注会话取消后，投递 worker 仍调用假发送适配器一次的断言。")

依赖刷新场景先应用一条记忆，再用相同 externalId 捕获新 revision，并取消 `extract_claims` 作业；pipeline 仍成功处理 `refresh_dependents`，最终将旧记忆标记为 `invalidated`。它验证了源修订后的失效传播，但未断言新规则是否重新提取、引用链是否完整保留或刷新失败如何恢复。[源修订后的依赖刷新与记忆失效 ↗](../../../docs/reviews/2026-09-27-batch2/reproduce.ts#L407 "支持 refresh_dependents 成功且旧记忆被标记 invalidated 的流程和结果。")
