# 改一条完整功能链：让搜索结果说清所属章节

以顶部搜索卡片的“所属章节”提示为贯穿例子，从开发环境、Vue 输入、HTTP API、统一检索、阅读结构投影一路定位到组件与样式，并说明怎样按改动范围选择入口、分层验证真实效果，以及按“先提交实现、再更新并提交知识资产”的顺序完成交付。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="start"></a>
## 先跑通一个可观察的场景

假设你要把搜索卡片里的“章节标题 · 第 10–24 行”改得更明确。先在仓库根目录执行：

```bash
osdk install
osdk deps --frozen
osdk run dev
```

打开**终端实际打印的 web 地址**，不要假定总是 5173；端口占用时开发脚本会另选端口。启动会在统一界面中载入仓库材料和已发布知识，但不会自动重写整库 Wiki。参考 [开发环境启动 ↗](../../../README.md#L7 "支持启动命令、动态端口、开发模式载入仓库材料且不自动生成整库知识。")

在顶部输入一个只出现在 Markdown 小节正文里的词。可观察结果应包含材料标题、所属小节及行号、摘录和“查看固定片段”。开发入口把当前目录设为 `OMEM_REPO_ROOT` 并采用 personal 模式；服务端据此在个人 Store 中导入开发知识。参考 [个人开发入口 ↗](../../../scripts/dev.ts#L1 "说明开发脚本如何设置仓库根目录并选择 personal 模式。") [服务端导入开发知识 ↗](../../../apps/server/src/app.ts#L58 "支持服务端在个人 Store 中根据仓库根目录导入开发知识并接入检索。") 恢复流程先捕获当前材料，再载入已提交文章，因此这是给同一个个人应用加入开发输入，不是切换到第二套产品。参考 [当前材料与文章恢复 ↗](../../../apps/server/src/review/knowledge.ts#L15 "说明恢复流程先捕获当前仓库材料，再恢复已提交知识文章。")

<a id="request-chain"></a>
## 从输入框跟到搜索响应

这条链路可以从用户动作反向追踪：

```mermaid
flowchart LR
  A[顶部搜索输入] --> B[250ms 防抖并取消旧请求]
  B --> C[GET /api/search]
  C --> D[统一检索返回固定片段]
  D --> E[API 补充所属章节]
  E --> F[搜索卡片显示提示与原文入口]
```

参考 [搜索防抖与取消 ↗](../../../apps/web/src/App.vue#L97 "支持查询变化时清理旧请求、设置搜索状态并等待 250ms。") [最新搜索响应 ↗](../../../apps/web/src/App.vue#L260 "支持通过请求版本与 AbortController 避免旧响应覆盖新结果。") [前端 API 请求封装 ↗](../../../apps/web/src/api.ts#L248 "支持统一添加 API 前缀、令牌、JSON 请求与错误处理。") [搜索 API 响应组装 ↗](../../../apps/server/src/app.ts#L273 "支持查询限制、异步或同步检索，以及固定片段和章节信息的响应组装。")

`App.vue` 监听 `query`：新输入会清除旧计时器、取消旧请求并递增版本号，250ms 后才搜索；只有仍属最新版本的响应能写回页面，所以慢请求不会覆盖新结果。参考 [搜索防抖与取消 ↗](../../../apps/web/src/App.vue#L97 "支持查询变化时清理旧请求、设置搜索状态并等待 250ms。") [最新搜索响应 ↗](../../../apps/web/src/App.vue#L260 "支持通过请求版本与 AbortController 避免旧响应覆盖新结果。") 前端 `api()` 统一添加 `/api` 前缀、连接令牌并处理非成功响应。参考 [前端 API 请求封装 ↗](../../../apps/web/src/api.ts#L248 "支持统一添加 API 前缀、令牌、JSON 请求与错误处理。")

服务端 `GET /api/search` 限制查询长度和结果数，优先调用异步检索；随后按 `fragmentId` 回读固定原文，组装标题、版本、摘录、分数、路由和 `section`。参考 [搜索 API 响应组装 ↗](../../../apps/server/src/app.ts#L273 "支持查询限制、异步或同步检索，以及固定片段和章节信息的响应组装。") 页面只在 `section` 存在时显示章节提示，同时保留加载、错误、空结果和打开固定片段的状态。参考 [搜索结果界面 ↗](../../../apps/web/src/App.vue#L539 "支持加载、错误、结果、章节提示、固定片段入口和空态的实际渲染。")

<a id="section-projection"></a>
## 理解“命中结果”和“所属章节”的分工

统一检索候选包含固定片段、来源修订、摘录、分数与来源路径，本身不包含章节字段。参考 [检索候选字段 ↗](../../../apps/server/src/retrieval/port.ts#L50 "说明基础检索候选保留固定片段、摘录、分数和来源，但没有章节展示字段。") 章节提示由 `evidenceSection` 在 API 层补充：它回读命中片段所属的固定修订，定位片段行号，再返回标题和起止行；找不到材料、位置或可见结构时返回 `null`。参考 [章节上下文补充 ↗](../../../apps/server/src/retrieval/context.ts#L21 "支持 evidenceSection 回读固定修订、定位命中并返回章节标题与行范围。")

“章节”也不是目录名。TS、JS 和 Vue 使用 AST 符号范围；Markdown 使用与阅读器一致的解析器，代码围栏里的伪标题不会成为章节；没有结构时退回整篇文档。参考 [材料结构投影 ↗](../../../apps/server/src/knowledge/structure.ts#L5 "支持代码使用 AST 符号、Markdown 使用解析器、无结构材料回退整篇文档，并说明现有 kind 字段。") 如果多层结构都覆盖命中行，系统选择跨度最小的一层，通常就是最具体的小节或符号。参考 [最具体结构选择 ↗](../../../apps/server/src/knowledge/structure.ts#L41 "支持在多个包含范围中选择跨度最小的章节或符号。")

因此先判断你改的是什么：**提示怎么写**属于前端，**片段归到哪一节**属于结构投影，**哪些片段排在前面**才属于检索。不要为一句展示文案修改召回与排序。

<a id="change-scope"></a>
## 按改动范围选择入口

最小改动是只改展示。例如把现有格式改为“所属章节：部署（10–24 行）”，只需调整 `App.vue` 的结果模板和 `styles.css` 的 `.search-section`；服务端返回的数据已经够用。保留 `v-if="r.section"`，避免无结构结果出现空标签。参考 [搜索结果界面 ↗](../../../apps/web/src/App.vue#L539 "支持加载、错误、结果、章节提示、固定片段入口和空态的实际渲染。") 当前提示的字号、颜色和下边距集中在 `.search-section`。参考 [章节提示样式 ↗](../../../apps/web/src/styles.css#L193 "支持当前提示的边距、颜色和字号，给出页面级样式入口。")

若要做一个真正的端到端小切片，例如显示“代码符号 / 文档章节 / 整篇文档”，现有 `MaterialSection` 已有 `kind`，但 `evidenceSection` 目前只返回标题和行号。可依次：

1. 在 `retrieval/context.ts` 的返回对象中带出 `kind`；
2. 检查 `app.ts` 的响应仍传递该对象；
3. 扩展 `App.vue` 的结果类型与模板；
4. 在页面样式中调整标签节奏。

这是**建议改动**，不是当前已显示的功能。只有要改变结构识别规则时才修改 `knowledge/structure.ts`。参考 [章节上下文补充 ↗](../../../apps/server/src/retrieval/context.ts#L21 "支持 evidenceSection 回读固定修订、定位命中并返回章节标题与行范围。") [材料结构投影 ↗](../../../apps/server/src/knowledge/structure.ts#L5 "支持代码使用 AST 符号、Markdown 使用解析器、无结构材料回退整篇文档，并说明现有 kind 字段。")

<a id="ui"></a>
## 复用组件并保持阅读节奏

搜索结果已经复用 `@omem/ui` 的 `OmPanel`、`OmCitation`、`OmEmpty` 和 `OmButton`。参考 [公共组件复用 ↗](../../../apps/web/src/App.vue#L5 "支持 App 已从公共 UI 包使用面板、引用、空态和按钮等组件。") 继续把结果卡片留在 `OmPanel` 中：它统一提供内边距、边线、圆角、标题间距，并在 700px 以下收紧布局。参考 [统一面板布局 ↗](../../../packages/ui/src/components/OmPanel.vue#L14 "支持 OmPanel 的内边距、边框、标题节奏和窄屏适配。") 页面专属的章节提示样式留在应用样式表；只有跨页面通用的新行为才进入 `packages/ui`。

新增间距时沿用 4/8/12/16/24/32/48px 阶梯，并保持正文行宽与可读字号。参考 [排版与间距规范 ↗](../../../design.md#L18 "支持界面应沿用的间距阶梯、字号、行高和正文行宽。") 实际页面要检查 1440、768、390px、长中文标题、键盘焦点以及 loading/error/empty；UI 验收要求真实查看，不能只确认元素存在。参考 [真实页面验收 ↗](../../../design.md#L44 "支持多尺寸、无障碍、真实行为和实际查看页面的验收要求。")

<a id="verify"></a>
## 把“代码通过”和“页面好用”分开确认

完成改动后先运行：

```bash
osdk deps --frozen
osdk run check
osdk run browser
```

`check` 依次执行类型检查、测试和生产构建，`browser` 运行浏览器检查。参考 [项目检查任务 ↗](../../../osdk.toml#L43 "说明 check 的类型检查、测试、构建组成，以及 browser 任务入口。") 然后保持 `osdk run dev` 运行，在终端给出的真实地址重复开头场景：输入真实词语，确认最具体章节、行号、摘录、固定片段入口以及窄屏布局；还应使用 viewport 脚本查看实际页面。参考 [运行与检查入口 ↗](../../../docs/reader-first/operations.md#L9 "支持索引补建、UI、检索、读者指南和完整报告各自的运行命令及边界。") [分层交付与页面验收 ↗](../../../AGENTS.md#L27 "支持功能切片检查后提交、模型资产分开提交，以及真实页面与内容验收。")

若只改文案或局部样式，不必扩大成检索算法验收；若动了结构投影、召回或排序，则应依次运行 `osdk run retrieval:verify`、`osdk run retrieval:index --review`，通过真实 HTTP 中文查询检查结果，并运行 `osdk run review:verify --full` 生成本轮报告。参考 [知识更新与检索验收顺序 ↗](../../../AGENTS.md#L37 "支持先提交检查通过的实现，再更新知识；同时列出检索索引、真实 HTTP 和完整报告的必做步骤。") 即使程序检查全部退出 0，也只说明类型、回归和构建通过；读者能否看懂提示、找到原文并完成任务仍需单独判断。参考 [分层交付与页面验收 ↗](../../../AGENTS.md#L27 "支持功能切片检查后提交、模型资产分开提交，以及真实页面与内容验收。")

<a id="refresh-knowledge"></a>
## 先提交实现，再更新知识

实现、相关检查和真实页面确认完成后，先只暂存本切片并完成本地提交；实现、阅读界面和模型派生资产按仓库约定分别提交，不 push。若本次改动涉及捕获、代码理解、知识生成或引用、检索、助手，必须先提交检查通过的实现，再更新受影响知识。参考 [分层交付与页面验收 ↗](../../../AGENTS.md#L27 "支持功能切片检查后提交、模型资产分开提交，以及真实页面与内容验收。") [知识更新与检索验收顺序 ↗](../../../AGENTS.md#L37 "支持先提交检查通过的实现，再更新知识；同时列出检索索引、真实 HTTP 和完整报告的必做步骤。")

本页用以下命令更新：

```bash
osdk run review:guides contributing
```

任务参数接受 `contributing` 或完整页面 key；脚本从页面计划选择目标，通过配置的 ACP 知识管线调查、写作、独立复核并发布文章，同时重写覆盖状态与目录。参考 [读者指南生成流程 ↗](../../../scripts/review-guides.ts#L17 "支持按 contributing 选择页面并通过真实 ACP 知识管线生成、发布和更新目录。") 生成后检查该页确实是 current，而不是 stale、pending 或 failed；打开实际引用，并在统一 dev 中重新阅读页面目的、案例、流程和修改入口。参考 [知识更新与检索验收顺序 ↗](../../../AGENTS.md#L37 "支持先提交检查通过的实现，再更新知识；同时列出检索索引、真实 HTTP 和完整报告的必做步骤。")

这些检查完成后，再把发布正文、覆盖记录和本轮验证报告作为模型派生资产单独提交。材料或模块说明使用 `review:generate <路径> --modules`，读者指南使用 `review:guides`；机器报告不能替代阅读验收。参考 [运行与检查入口 ↗](../../../docs/reader-first/operations.md#L9 "支持索引补建、UI、检索、读者指南和完整报告各自的运行命令及边界。") [知识更新与检索验收顺序 ↗](../../../AGENTS.md#L37 "支持先提交检查通过的实现，再更新知识；同时列出检索索引、真实 HTTP 和完整报告的必做步骤。")
