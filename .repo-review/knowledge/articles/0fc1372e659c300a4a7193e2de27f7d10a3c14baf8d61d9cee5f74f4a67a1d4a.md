# 改一条完整功能链：让搜索结果显示所属章节

以“搜索结果显示它属于哪一节”为例，从个人开发环境、前端搜索、HTTP API、检索上下文和章节结构投影一路定位到界面，并说明怎样选择修改层次、复用组件、更新相关知识，以及如何区分程序检查通过与真实阅读可用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="scenario"></a>
## 先看要完成的用户行为

假设你第一次修改 omem，希望用户在顶部搜索“搜索结果属于哪一节”时，不只看到命中的文字，还能看到类似“如何启动 · 第 3–7 行”的章节提示，并且仍能打开固定原文。现有结果卡片已经具备这个行为：有章节时显示标题和行范围，随后呈现摘要及“查看固定片段”；请求完成但没有结果时才显示空态。参考 [搜索结果界面 ↗](../../../apps/web/src/App.vue#L538 "支持结果卡片实际使用公共组件，并显示章节、摘要、固定片段入口及诚实空态。")

这项改动适合作为理解仓库的起点，因为它跨过了前端状态、HTTP 请求、统一检索、原文结构和视觉呈现，却不需要重构整个系统。页面计划也把它明确设为面向首次贡献者的贯穿场景。参考 [贡献指南页面计划 ↗](../../../config/wiki-pages.json#L108 "说明本页的目标读者、功能链场景与改动范围。")

## 启动个人开发环境并接入仓库材料

统一入口是 `osdk run dev`。入口脚本把当前目录声明为仓库根，将模式设为个人开发，再交给开发编排器；默认 API 和 Web 端口分别是 4317、5173，默认端口被占用时会选择空闲端口，因此应以终端打印的地址为准。参考 [个人开发入口 ↗](../../../scripts/dev.ts#L1 "支持开发入口设置仓库根和个人模式后加载编排器。") [端口选择行为 ↗](../../../apps/server/tests/dev-ports.test.ts#L5 "验证默认端口占用时选择其他端口，而显式指定的占用端口会失败。")

编排器分别启动服务端和 Vite，等待 API 健康后才报告可用地址，并让 Web 端的 `/api` 指向实际 API 端口。启动只接入当前仓库与已提交知识，不会自动重新生成整库文章。参考 [开发进程编排 ↗](../../../scripts/dev-review.ts#L81 "支持服务端与 Web 分别启动、健康检查以及 API 代理端口的说明。") [运行与启动说明 ↗](../../../docs/reader-first/operations.md#L3 "支持统一启动命令、端口约定、仓库知识接入及不自动生成整库知识的说明。")

服务端发现仓库根后，会把开发知识导入当前个人 Store，并用仓库输入适配器包装统一检索；知识路由和助手共用这套检索入口。导入时先从隔离评审 Store 补入发布文章所依赖的历史文章和历史材料；随后捕获当前仓库文件，使 live head 不会被较早材料倒退；再恢复历史及当前发布文章，最后刷新文章的 current、stale 等状态。整个过程是在个人数据库中追加仓库材料与知识，不会替换已有个人捕获。参考 [服务端开发知识接入 ↗](../../../apps/server/src/app.ts#L61 "支持服务端导入仓库知识并让知识路由和助手共用包装后的检索。") [开发知识导入顺序 ↗](../../../apps/server/src/review/development.ts#L36 "支持先补历史依赖材料、再捕获当前文件、随后恢复文章并刷新状态的准确顺序，也说明当前文件为何不会被历史材料倒退。")

<a id="search_flow"></a>
## 沿搜索链路定位数据

输入搜索词后，`App.vue` 会取消前一次请求、递增版本、清空旧结果，并等待 250ms 再发起搜索。真正请求 `/search?q=...` 时使用 `AbortController`；只有响应版本仍是最新版本才写入结果，被取消的旧请求也不会覆盖当前错误状态。参考 [搜索防抖与取消 ↗](../../../apps/web/src/App.vue#L96 "支持查询变化时取消旧请求、递增版本、清理状态并进行防抖。") [搜索请求竞态处理 ↗](../../../apps/web/src/App.vue#L259 "支持 URL 编码、AbortController、版本比较和取消请求不覆盖当前错误的说明。")

```mermaid
flowchart LR
  A[顶部搜索输入] --> B[App.vue 防抖与取消旧请求]
  B --> C[api 调用 /api/search]
  C --> D[统一检索返回固定片段]
  D --> E[evidenceSection 补充章节]
  E --> F[OmPanel 显示章节与原文入口]
```

通用 `api()` 负责添加 `/api` 前缀、浏览器令牌和取消信号，并把非成功响应转换成可显示的错误。服务端则限制查询长度和结果数，调用异步或同步检索，再从每个固定片段恢复标题、版本、分数、召回路径及章节信息。参考 [前端 API 封装 ↗](../../../apps/web/src/api.ts#L245 "支持 API 前缀、浏览器令牌、取消信号和错误转换的说明。") [顶部搜索服务端路由 ↗](../../../apps/server/src/app.ts#L273 "支持查询限制、统一检索调用以及固定片段与章节字段的结果装配。")

<a id="section_projection"></a>
## 理解“所属章节”从哪里来

章节提示不是模型生成的新事实，而是原材料阅读结构的投影。TS、JS、Vue 等文件使用现有解析器产生符号范围；Markdown 使用与阅读器一致的 lexer 提取标题层级，代码围栏里的伪标题不会成为章节；没有可识别结构时，整份材料作为一个文档范围。命中一行若同时落在多个范围中，会选择覆盖它的最小范围。参考 [材料章节结构投影 ↗](../../../apps/server/src/knowledge/structure.ts#L8 "解释代码符号、Markdown 标题、文档退化范围和最小覆盖章节的计算规则。")

`evidenceSection` 从片段恢复其修订和材料，计算片段所在行，再返回章节标题和起止行。材料、片段或章节不存在时返回 `null`；如果材料含当前调用者不可见的片段，也不暴露章节标签，因为标题本身同样属于内容。前端因此必须把“没有章节”当作正常状态，而不是猜一个标题补上。参考 [命中章节恢复 ↗](../../../apps/server/src/retrieval/context.ts#L21 "支持章节从固定材料恢复以及隐藏内容不暴露章节标签的限制。")

现有回归还验证了 Markdown 层级、围栏代码、相邻片段和可见性：命中“重试”段落时可以补到同节标题及相邻文字，但不会跨到下一节；不可见时不返回邻居。参考 [章节上下文回归 ↗](../../../apps/server/tests/reading-context.test.ts#L43 "验证 Markdown 章节、围栏伪标题、同节邻居和可见性行为。")

<a id="choose_layer"></a>
## 按改动意图选择入口

围绕这个例子，可以按责任边界选择修改位置：

| 想改变什么 | 主要入口 | 应保持的边界 |
| --- | --- | --- |
| 章节提示的文案、位置或显隐 | `apps/web/src/App.vue` | 保留加载、失败、空结果与无章节状态 |
| 提示的间距、字号或换行 | `apps/web/src/styles.css` | 使用既有 token 和间距节奏 |
| API 返回字段或结果装配 | `apps/server/src/app.ts` | 继续从固定片段恢复来源信息 |
| 代码或 Markdown 的章节边界 | `knowledge/structure.ts` | 这是通用阅读结构，不能按项目路径特判 |
| 可见性与章节恢复规则 | `retrieval/context.ts` | 不泄露隐藏内容 |

当前 `.search-section` 已使用次级文字色、13px 字号和 12px 下间距；只调整视觉节奏时通常无需触碰检索。参考 [章节提示样式 ↗](../../../apps/web/src/styles.css#L193 "支持当前章节提示的间距、颜色和字号说明。")

仓库专属的候选资格则属于 `developmentRetrieval`：它排除已移除材料和旧路径别名，同时保留个人材料原有行为；实际内容排序仍交给共享检索器。不要把仓库名、目录词或验收题写进通用章节判断。参考 [仓库检索输入适配 ↗](../../../apps/server/src/review/development.ts#L15 "解释仓库材料的候选可见性由输入适配器处理，而内容排序继续复用统一检索。")

## 复用组件并在真实页面观察结果

搜索结果区域已经使用 `OmPanel` 呈现每项结果、用 `OmCitation` 打开固定片段，并以 `OmEmpty` 表达确实没有命中的状态。新增通用交互时先检查 `packages/ui`；业务请求和搜索状态继续留在 `apps/web`，公共组件只通过 props、slots 和 events 接收数据。参考 [搜索结果界面 ↗](../../../apps/web/src/App.vue#L538 "支持结果卡片实际使用公共组件，并显示章节、摘要、固定片段入口及诚实空态。") [公共组件职责 ↗](../../../.agents/skills/omem-design/SKILL.md#L8 "支持先复用 packages/ui，并把业务网络请求和状态保留在 apps/web 的职责边界。")

视觉上沿用黑白灰阅读基线和统一 token。正文、元信息、代码及按钮组使用 4/8/12/16/24/32/48px 的节奏；错误不能只靠颜色表达，普通点击区域至少 44×44px。检查时不仅看元素是否存在，还要实际输入查询，观察加载、失败、重试、空结果、有章节和无章节，并覆盖 390、768、1440px、长标题及横向溢出。参考 [设计 token 与间距 ↗](../../../design.md#L5 "支持黑白灰视觉基线、字体、间距和阅读行宽要求。") [移动端与无障碍 ↗](../../../design.md#L44 "支持点击区域、异步状态、视口尺寸、长标题和无横向溢出的验收要求。")

## 验证实现、更新知识并认识当前限制

实现完成后先运行 `osdk deps --frozen` 和 `osdk run check`；涉及页面时再运行 `osdk run browser`，并用视口脚本查看实际开发页面。程序测试和构建通过只能说明实现层没有发现回归，不能证明搜索排序合理、章节提示易读或引用真的方便使用。参考 [分层检查方法 ↗](../../../docs/reader-first/operations.md#L15 "支持实现检查、浏览器实测以及机器报告不能代替阅读验收的区分。")

若改动影响这篇指南或其依据，页面计划中的 key 是 `guide:contributing`，可运行 `osdk run review:guides contributing`，让真实 ACP 重新调查、写作和独立复核该页。生成脚本会按目标筛选页面、发布成功产物、刷新目录，并把失败记录为失败而不是覆盖成成功；模型产物不应手工拼改。参考 [单页指南任务 ↗](../../../osdk.toml#L117 "支持通过 contributing 参数只更新本页的任务声明。") [指南生成与发布流程 ↗](../../../scripts/review-guides.ts#L16 "解释页面筛选、模型流水线、发布、失败记录和目录刷新的实际流程。")

最后在真实页面复现贯穿示例：输入查询，确认最新请求胜出、章节有依据时出现、没有依据时诚实省略，并打开固定片段核对行范围。当前系统已有结构投影和统一检索首片，但仍缺完整意图路由、跨文件调用与类型解析；一次结果卡片的小改动也不等于已经拥有任意功能的自动修改器或完整仓库功能目录。参考 [阅读验收口径 ↗](../../../docs/reader-first/validation.md#L35 "支持以场景、处理链、可见结果、修改入口及可操作引用检查页面，而非只看程序通过。") [功能链现状与限制 ↗](../../../docs/reader-first/validation.md#L52 "支持本页已串起搜索完整链，同时不代表自动修改任意功能或生成完整目录。")
