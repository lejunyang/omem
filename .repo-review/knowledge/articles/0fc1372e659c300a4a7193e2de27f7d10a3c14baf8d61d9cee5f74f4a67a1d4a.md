# 为搜索结果补上章节位置：走通 UI、API 与检索

以“搜索结果显示它属于哪一节”为贯穿例子，带第一次修改 omem 的 TypeScript 开发者从开发启动、仓库材料导入，走到结构投影、统一检索、HTTP API 和 Vue 呈现；同时区分显示文案、章节来源与排序三类改动，并给出组件复用、三档宽度检查、知识更新和阅读验收方法。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="observable-goal"></a>
## 先认准要改变的用户结果

假设仓库里有一份教学用 Markdown：

```md
# 手册
## 预约
先确认人数。
```

在顶部输入“确认人数”后，目标不是生成一段新答案，而是在“实际搜索命中”的卡片上看到类似“原始材料 · 手册 / 预约 · 第 3–3 行”的定位。卡片仍保留摘要和“阅读原文”等动作；章节路径只是帮助读者判断命中处境，不替代正文。参考 [搜索结果卡片 ↗](../../../apps/web/src/App.vue#L685 "支持实际搜索命中如何显示类型、章节路径、行号和阅读动作。")

页面上还有一个“综合回答”区。它只有点击按钮后才创建调查会话并整理带引用回答，而实际命中会随搜索词自动刷新。调试本例时先看后者，避免把 Agent 回答与检索结果混为一条链。参考 [综合回答入口 ↗](../../../apps/web/src/SearchAnswer.vue#L205 "说明综合回答需要显式点击，并与下方实际命中并列存在。")

## 启动开发环境，让仓库材料进入同一库

在仓库根目录执行 `osdk deps --frozen`，再执行 `osdk run dev`，打开终端实际打印的 Web 地址。默认端口会在占用时自动调整；启动会把本仓库和已提交知识接入个人库，但不会顺便重写整库 Wiki。参考 [开发启动方式 ↗](../../../docs/reader-first/operations.md#L3 "支持 osdk 启动、动态端口、仓库知识接入及启动不自动生成整库知识。")

`scripts/dev.ts` 把当前目录设为 `OMEM_REPO_ROOT`，选择 personal 开发模式，再交给共同的启动编排器。参考 [个人开发入口 ↗](../../../scripts/dev.ts#L1 "说明 dev 脚本设置仓库根与 personal 模式后复用启动编排器。")

仓库输入适配器用 Git 文件清单寻找受跟踪及未忽略文件，排除运行产物、依赖、私有环境与本地配置；普通文本按 `omem:<路径>` 保存为固定材料，内容哈希未变时不会重复捕获。参考 [仓库材料捕获 ↗](../../../apps/server/src/review/materials.ts#L16 "支持文件发现、排除、内容哈希与 omem 路径键的捕获流程。") 随后系统恢复材料说明与已发布文章，再刷新知识仓储，所以 dev 中看到的是当前原件、保留的历史依据和已发布知识的组合。参考 [知识恢复顺序 ↗](../../../apps/server/src/review/knowledge.ts#L10 "说明开发知识恢复会捕获仓库材料、恢复材料说明与文章并刷新仓储。")

<a id="request-chain"></a>
## 沿一次输入走完请求链

顶栏 `query`、查找用途或材料用途筛选变化时，`App.vue` 会取消旧请求、清空旧结果，并在 250 ms 后发起带版本号的搜索；较晚返回的旧响应不会覆盖新输入。参考 [搜索输入调度 ↗](../../../apps/web/src/App.vue#L189 "支持输入和筛选变化后的取消、版本保护、清空与 250ms 延迟搜索。")

```mermaid
flowchart LR
  A[顶部搜索框] --> B[App.vue search]
  B --> C[GET /api/search]
  C --> D[RetrievalPort.search]
  D --> E[RetrievalHit.headingPath]
  E --> F[结果卡片]
```

`search()` 组装 `/search?q=...&purpose=...`，公共 `api()` 再补上 `/api` 前缀、访问令牌和统一错误处理，因此浏览器实际请求的是 `GET /api/search`。参考 [浏览器搜索请求 ↗](../../../apps/web/src/App.vue#L376 "说明 App.vue 如何构造带查询、用途和筛选的搜索请求。") [API 请求封装 ↗](../../../apps/web/src/api.ts#L260 "支持公共 API 函数补 /api 前缀、令牌并统一处理失败。") 服务端在入口校验 `purpose`、`role` 和时间条件，把查询限制为 300 字、结果限制为 30 条，然后交给统一检索。参考 [搜索 API 边界 ↗](../../../apps/server/src/app.ts#L313 "支持服务端对查询条件、长度和结果数的校验以及统一检索调用。")

跨层合同是 `RetrievalHit`：除了标题、正文、固定目标和引用，还明确包含 `context` 与 `headingPath: string[]`。这意味着章节位置应由检索投影提供，而不是由 Vue 根据摘要猜测。参考 [统一命中合同 ↗](../../../apps/server/src/retrieval/port.ts#L43 "证明 RetrievalHit 正式携带 context、headingPath、目标与引用。")

<a id="heading-source"></a>
## 理解章节路径从哪里来

对 Markdown，`markdownPassages()` 用解析器维护标题栈；每个非空内容块记录当时的完整标题路径，并把紧随引导句的表格、列表或代码保留在同一段。上面的教学例子因此得到 `["手册", "预约"]`。参考 [Markdown 章节投影 ↗](../../../apps/server/src/retrieval/units.ts#L31 "支持标题栈、内容块行范围和表格列表代码合并的章节路径生成。")

对 TypeScript 和 Vue，`codePassages()` 读取 AST 符号范围，完整函数或方法携带父符号与自身的 qualified name；不属于符号的 import、初始化和配置统一落在“模块定义与初始化”。若文件没有可解析符号，路径可以为空，前端便不会显示章节提示。参考 [代码符号投影 ↗](../../../apps/server/src/retrieval/units.ts#L90 "支持 TS/Vue 按完整符号范围生成路径、空路径降级及模块初始化分组。")

`sourceUnits()` 选择代码或 Markdown 切分方式，把标题路径同时写进可检索的 `context` 和正式 `headingPath`，并保留对应原文行范围。参考 [原件检索单元 ↗](../../../apps/server/src/retrieval/units.ts#L265 "说明 source unit 选择代码或 Markdown passages，并写入 context、headingPath 和固定目标。") 检索完成时只是把单元的 `headingPath` 原样放回结果；最终由 `App.vue` 以“ / ”连接，并在原始材料后补行号。参考 [结果保留章节路径 ↗](../../../apps/server/src/retrieval/unified.ts#L564 "证明统一检索完成阶段把单元 headingPath 原样返回到 RetrievalHit。") [章节路径呈现 ↗](../../../apps/web/src/App.vue#L717 "支持前端用斜线连接 headingPath，并为原始材料补充精确行范围。")

所以这里的“章节”是**结构定位**：Markdown 标题、代码符号或模块初始化区，而不是模型判定的业务主题。它有助于导航，却不能代替跨文件业务理解。

<a id="change-map"></a>
## 按改动意图区分落点

| 想改变什么 | 首要修改处 | 不必先改什么 |
| --- | --- | --- |
| 分隔符、措辞、折行、徽标 | `App.vue` 搜索结果卡片及相邻样式 | 检索排序、AST |
| Markdown 或代码怎样判定“所属章节” | `retrieval/units.ts` 的 passage 与 source unit 投影 | 前端拼字符串 |
| 新增独立返回字段 | `RetrievalHit` 合同 → 投影/`finish()` → `App.vue` | 在 API 路由二次猜章节 |
| 让章节影响“搜得到、排得前” | 单元 `context`、全文/语义召回与用途排序 | 只改卡片展示 |

如果改变了结构预处理语义，应同步提升 `UNIT_VERSION`；检索单元身份使用这个版本，向量模型身份也把它作为前缀，避免新旧结构向量混用。参考 [结构投影版本 ↗](../../../apps/server/src/retrieval/units.ts#L16 "证明检索单元拥有显式 UNIT_VERSION，并作为单元类型定义的一部分。") [向量模型身份 ↗](../../../apps/server/src/retrieval/unified.ts#L64 "说明向量模型身份以结构投影版本作为前缀。")

做显示改动时继续使用现有 `OmPanel`、`OmButton`、`OmEmpty` 等公共组件；`App.vue` 已从 `@omem/ui` 引入它们。参考 [现有公共组件 ↗](../../../apps/web/src/App.vue#L7 "支持 App.vue 已复用 @omem/ui 的面板、按钮、空态与证据组件。") `OmPanel` 已提供边框、24px 内距、标题与操作区间距，并在 700px 以下收紧为 20px 16px，通常无需另造卡片外壳。参考 [统一面板间距 ↗](../../../packages/ui/src/components/OmPanel.vue#L14 "支持 OmPanel 的桌面与移动端内距、标题和操作区间距。")

## 在真实页面检查间距与行为

样式保持现有黑白灰阅读基线：正文 16px、约 46 个汉字宽，间距使用 4/8/12/16/24/32/48px 序列。参考 [阅读排版基线 ↗](../../../design.md#L18 "支持字体、正文行高、阅读行宽和统一间距序列。") 同时检查 1440、768、390px，尤其观察长章节路径是否自然换行、按钮是否仍可点击、页面是否横向溢出；700px 以下还要遵守导航折叠和全屏引用等现有行为。参考 [窄屏与无障碍 ↗](../../../design.md#L44 "支持 700px 响应式行为、最小点击区域及 390/768/1440px 检查。")

可借用 `scripts/code-wiki-viewport.ts` 的三档 viewport、无横向溢出断言和截图方式。参考 [多宽度截图框架 ↗](../../../scripts/code-wiki-viewport.ts#L168 "说明现有脚本如何在三档宽度检查横向溢出并保存截图。") 现有材料浏览器脚本还提供了更贴近本例的动作：真实输入搜索词、检查结果卡出现章节文字、切换用途筛选并截图；扩展本例时应把这一检查补到三档宽度，而不只确认 DOM 中存在一个字段。参考 [真实搜索页面检查 ↗](../../../scripts/material-catalog-browser.ts#L117 "提供真实输入搜索词、验证章节文本、切换材料筛选与截图的现有范例。")

<a id="finish-and-publish"></a>
## 把实现通过与阅读可用分开验收

完成代码后先运行 `osdk run check`；涉及界面再运行 `osdk run browser` 并实际查看 dev 页面。若修改结构投影或排序，再补建 review 索引、运行 `osdk run retrieval:verify`，用真实中文 HTTP 查询观察完整排名。机器报告能确认链路和引用合同，却不能替代人工阅读。参考 [分层验证命令 ↗](../../../docs/reader-first/operations.md#L17 "支持实现、浏览器、检索与完整报告的检查入口，并明确机器报告不替代阅读验收。")

实现确认后，用 `osdk run review:guides contributing` 只更新本页；任务配置接受 `contributing` 这个短名并通过真实 ACP 写作、复核。参考 [局部指南任务 ↗](../../../osdk.toml#L137 "支持 review:guides 任务接受 contributing 短名及 retry 标志。") 模型派生知识应在实现提交之后单独更新；最后再运行 `osdk run review:verify --full`，并人工确认新人能复述“输入 → 结构投影 → 检索 → API → UI”、找到正确修改点、打开固定原文且在三档宽度下读清结果。

当前边界要如实保留：长问题可能漏掉明确方法，宽泛说明可能排在实现前，跨文件业务链仍不完整；Agent 能继续补查，不代表首轮实际命中已经好用。参考 [当前检索边界 ↗](../../../docs/reader-first/progress.md#L33 "支持长问题、宽泛材料排序、跨文件业务链等当前缺口，以及实现与知识资产分开交付的要求。") 这篇指南教你完成一条小改动链，不是自动生成任意功能的完整仓库地图。
