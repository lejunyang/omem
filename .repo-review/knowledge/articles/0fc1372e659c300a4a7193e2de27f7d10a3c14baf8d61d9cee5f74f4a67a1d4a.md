# 改一条完整功能链：从搜索命中到章节提示

以“调整顶部搜索结果的所属章节提示”为贯穿示例，带第一次参与 omem 开发的人走过个人开发环境、仓库材料接入、前端请求、共享检索、章节上下文补全、Vue 呈现与分层验收，并说明不同改动应落在哪一层。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="start"></a>
## 先跑起包含真实仓库材料的开发环境

假设你希望把搜索结果中的“所属章节”提示改得更易读，例如保留章节名、弱化行号，并确认没有章节时页面仍自然显示。先在仓库根目录执行 `osdk deps --frozen`，再执行 `osdk run dev`。入口会把当前目录登记为仓库根，并选择个人开发模式；默认 API 与 Web 端口分别是 4317 和 5173，端口占用时以终端打印的实际地址为准。参考 [个人开发入口 ↗](../../../scripts/dev.ts#L1 "支持开发入口设置仓库根目录并选择个人开发模式的说明。") [开发环境启动方式 ↗](../../../docs/reader-first/operations.md#L3 "支持 osdk 启动命令、默认端口、仓库知识接入及启动不自动生成整库知识的说明。")

这里的 dev 不是一套只装演示数据的孤立页面。服务构建时会把仓库当前材料、已发布知识以及旧引用所需的历史版本接入个人库，同时保留个人原有捕获；随后用同一个开发检索适配器服务知识路由、助手和顶部搜索。启动只负责恢复和接入，不会自动重新生成整库知识。参考 [服务构建与共享检索 ↗](../../../apps/server/src/app.ts#L61 "支持服务启动时导入开发知识，并让知识路由和助手复用开发检索的说明。") [开发知识恢复流程 ↗](../../../apps/server/src/review/development.ts#L36 "支持恢复当前材料、已发布文章和引用依赖历史，同时不回退当前材料版本的说明。")

因此，开始修改前先在真实页面搜索一个能命中 Markdown 或代码章节的词，记录当前标题、章节名、行号和“查看固定片段”的行为。这是后续判断改动是否只影响显示、还是改变了数据链的基线。

## 沿用户动作找到完整调用链

顶部搜索的主链可以按下面顺序阅读：

```mermaid
flowchart LR
  A[用户输入查询] --> B[App.vue 防抖并取消旧请求]
  B --> C[GET /api/search]
  C --> D[共享检索返回片段命中]
  D --> E[从固定版本补出所属章节]
  E --> F[Vue 渲染章节提示与原文摘要]
```

参考 [搜索状态与防抖 ↗](../../../apps/web/src/App.vue#L85 "支持前端结果类型、取消旧请求、250 毫秒防抖和响应版本保护的说明。") [顶部搜索请求 ↗](../../../apps/web/src/App.vue#L260 "支持前端通过公共 API 请求搜索接口并只接纳当前版本响应的说明。") [搜索结果章节呈现 ↗](../../../apps/web/src/App.vue#L540 "支持当前模板已显示章节标题、行号、摘要和固定片段入口的说明。") [搜索 API 返回合同 ↗](../../../apps/server/src/app.ts#L273 "支持查询限制、共享检索调用以及服务端补充 section 字段的说明。")

`App.vue` 保存查询、结果、加载态和错误态。输入变化时，它会清空旧结果、取消前一次请求并等待 250 毫秒；递增的版本号保证较慢的旧响应不能覆盖较新的查询。实际请求通过公共 `api()` 封装发送到 `/api/search`。所以即使本次只改一行提示，也不应绕开现有防抖、取消和竞态保护。参考 [搜索状态与防抖 ↗](../../../apps/web/src/App.vue#L85 "支持前端结果类型、取消旧请求、250 毫秒防抖和响应版本保护的说明。") [顶部搜索请求 ↗](../../../apps/web/src/App.vue#L260 "支持前端通过公共 API 请求搜索接口并只接纳当前版本响应的说明。")

服务端把查询截到 300 个字符并限制为 30 个命中，再通过与助手共用的检索端口查找片段。每个命中结合固定 evidence 解析材料标题、版本、分数和路由，最后附加 `section`。当前模板已经在 `section` 存在时显示章节标题及起止行，并继续提供固定片段入口；本例是在既有能力上调整呈现，而不是从零增加字段。参考 [搜索 API 返回合同 ↗](../../../apps/server/src/app.ts#L273 "支持查询限制、共享检索调用以及服务端补充 section 字段的说明。") [搜索结果章节呈现 ↗](../../../apps/web/src/App.vue#L540 "支持当前模板已显示章节标题、行号、摘要和固定片段入口的说明。")

<a id="section-context"></a>
## 理解章节提示是什么，以及它不是什么

`section` 是**命中后的阅读上下文补全**，不是检索产生的新事实，也不是第二份知识。服务端先由命中片段找到所属 revision，将该版本还原为材料，再计算片段在全文中的行位置，选择包含它的最内层章节，返回标题和起止行。原始 Fragment 及其 ID 不会因结构投影而改变。参考 [章节上下文补全 ↗](../../../apps/server/src/retrieval/context.ts#L21 "支持章节由固定版本材料和片段位置计算、可见性不足时返回空值的说明。") [材料结构投影 ↗](../../../apps/server/src/knowledge/structure.ts#L8 "支持 Markdown、代码符号和整文档退路的章节识别方式，以及原始片段不变的说明。")

结构来源随材料类型而异：Markdown 使用与阅读器一致的解析方式识别标题；TypeScript、JavaScript 和 Vue 等代码材料使用现有解析器得到符号范围；无法识别更细结构时，整份文档就是退路。这个设计让页面可以回答“命中内容属于哪一节”，同时仍能沿固定片段回到原文。参考 [材料结构投影 ↗](../../../apps/server/src/knowledge/structure.ts#L8 "支持 Markdown、代码符号和整文档退路的章节识别方式，以及原始片段不变的说明。")

`section` 合法地可能为 `null`：例如 evidence 或 revision 无法还原、片段无法定位、没有包含结构，或者材料中存在当前不可见的片段。章节标题本身也是内容，因此可见性不完整时不会额外泄露标题。界面应安静省略章节提示，不能把它当成搜索失败，也不要从文件路径猜一个标题。参考 [章节上下文补全 ↗](../../../apps/server/src/retrieval/context.ts#L21 "支持章节由固定版本材料和片段位置计算、可见性不足时返回空值的说明。")

这项上下文能力还被助手复用：助手只对可见命中写入 `sectionTitle`，再从同章节补充标题或相邻原文。因此，若你改变章节识别或可见性合同，需要同时检查助手；若只改变提示文案和视觉层级，通常无需触碰助手。参考 [助手复用章节上下文 ↗](../../../apps/server/src/assistant/runtime.ts#L684 "支持助手在可见性检查后复用章节标题并补充相邻原文的说明。")

## 按改动性质选择落点

以“让章节名更突出、行号更克制”为例，最小修改位于 `App.vue` 的结果模板及相邻局部样式：保留 `v-if="r.section"`，把标题作为轻量元信息呈现，仍让摘要和固定片段入口承担主要阅读动作。缺少章节时不补占位错误。当前结果类型、请求和模板已经覆盖这一数据合同。参考 [搜索状态与防抖 ↗](../../../apps/web/src/App.vue#L85 "支持前端结果类型、取消旧请求、250 毫秒防抖和响应版本保护的说明。") [搜索结果章节呈现 ↗](../../../apps/web/src/App.vue#L540 "支持当前模板已显示章节标题、行号、摘要和固定片段入口的说明。")

| 想改变什么 | 主要入口 | 需要联动检查 |
| --- | --- | --- |
| 提示文字、位置、间距 | `App.vue` 模板与样式 | 空章节、长标题、窄屏 |
| 返回字段或章节范围 | `/api/search` 与 `retrieval/context.ts` | 前端类型、接口测试、助手上下文 |
| Markdown/代码怎样划分章节 | `knowledge/structure.ts` | 固定片段定位、不同材料类型 |
| 命中顺序和相关性 | 共享 retrieval/ranking 链 | 顶部搜索、知识搜索、助手 |

不要为了让本例排在前面而在页面、仓库路径或开发适配器里加入特定关键词规则。开发适配器只负责过滤已移除或旧别名仓库副本，内容排名仍交给共享检索；个人材料与归档材料也可以参与查询，历史材料仍可由固定引用读取。参考 [开发检索过滤边界 ↗](../../../apps/server/src/review/development.ts#L15 "支持开发适配器只处理仓库输入资格、内容排名仍由共享检索负责的说明。")

## 沿用阅读界面的组件与节奏

界面修改先在 `packages/ui` 搜索已有能力，并优先复用 `@omem/ui`。公共组件只处理 props、slots 和事件，网络请求与搜索状态继续留在 `apps/web`；本例已有 `OmPanel` 与 `OmCitation`，通常不需要为了一条章节元信息新建通用组件。参考 [界面实现约束 ↗](../../../.agents/skills/omem-design/SKILL.md#L8 "支持复用公共组件、业务状态留在应用层以及三个视口真实检查的说明。")

章节提示应保持黑白灰阅读层级：正文默认 16px，辅助元信息至少 12px；间距从 4、8、12、16、24、32、48px 的既有节奏中选择。关键状态不能只靠颜色表达，长章节名应允许换行，不能通过缩小字号塞进桌面布局。若新增了可点击行为，点击区域、键盘焦点和文本说明也必须符合现有可访问性合同。参考 [视觉与响应式规范 ↗](../../../design.md#L18 "支持字号、间距、组件复用、移动端与无障碍要求的说明。")

完成样式后至少观察 1440、768 和 390px：确认章节提示不会挤压摘要，不产生横向滚动，搜索中、搜索失败、无结果和 `section === null` 都有诚实表现。真实页面检查关注的是信息层级和可读性，不只是 DOM 中出现了某个元素。参考 [界面实现约束 ↗](../../../.agents/skills/omem-design/SKILL.md#L8 "支持复用公共组件、业务状态留在应用层以及三个视口真实检查的说明。") [视觉与响应式规范 ↗](../../../design.md#L18 "支持字号、间距、组件复用、移动端与无障碍要求的说明。")

<a id="verify"></a>
## 把工程通过、页面可用和知识更新分开验收

第一层是工程检查：运行 `osdk deps --frozen` 和 `osdk run check`，确认依赖、测试、类型检查与构建通过。如果改了服务端章节合同，应补充或调整针对 `/api/search`、结构投影及可见性的测试；只改模板时，则重点防止类型和构建回归。参考 [分层检查命令 ↗](../../../docs/reader-first/operations.md#L15 "支持工程检查、浏览器检查和机器报告不能代替阅读验收的说明。")

第二层是真实页面检查：运行 `osdk run browser`，并使用 `scripts/code-wiki-viewport.ts` 所采用的桌面、平板和手机视口思路检查实际页面。亲自搜索一条有章节的结果和一条无章节的结果，再打开固定片段，确认显示内容与原文位置一致。测试通过只能证明预设行为成立，不能替代对间距、换行、阅读顺序和真实搜索结果的观察。参考 [分层检查命令 ↗](../../../docs/reader-first/operations.md#L15 "支持工程检查、浏览器检查和机器报告不能代替阅读验收的说明。") [多视口页面检查 ↗](../../../scripts/code-wiki-viewport.ts#L139 "支持以 1440、768、390 三种宽度观察真实页面的说明。")

第三层才是知识更新。页面计划在 `config/wiki-pages.json` 中定义；本页可用 `osdk run review:guides contributing` 重新生成，失败任务才考虑使用 `--retry`。调查和运行 trace 保存在隔离 runtime，发布文章进入 `.repo-review/knowledge/`。生成及独立复核通过说明产物符合合同，但仍需在统一 dev 中阅读正文、打开引用并检查当前状态。参考 [单页指南生成任务 ↗](../../../osdk.toml#L117 "支持用 contributing 作为页面目标运行读者指南生成任务及 retry 标志的说明。") [阅读验收与现有限制 ↗](../../../docs/reader-first/validation.md#L35 "支持按场景抽读、区分机器检查与阅读可用，并说明当前检索和结构能力限制。")

最后记录仍未验证的边界。当前实现已经能把 App、API、共享检索、结构投影和样式串成一条可改链路，但这不是任意功能的自动修改器；全库自然问法的排序、复杂文档结构以及更完整的意图路由仍有限。不要用一次检查退出 0 或一次模型复核，替代对本次用户可见结果的判断。参考 [阅读验收与现有限制 ↗](../../../docs/reader-first/validation.md#L35 "支持按场景抽读、区分机器检查与阅读可用，并说明当前检索和结构能力限制。")
