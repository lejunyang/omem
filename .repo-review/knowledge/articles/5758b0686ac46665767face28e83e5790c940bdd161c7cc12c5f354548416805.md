# 仓库评审搜索的路径权重配置

该文件以八条静态规则为指定路径前缀声明数值权重。现有材料可确认规则数量、路径和值，但没有定义权重的运行语义、默认值、匹配算法或加载入口，因此不能据此断言真实搜索排序及各目录的资料角色。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="configured-rules"></a>
## 已声明的前缀与权重

配置通过 `rules` 数组列出八组 `prefix` 与 `weight`。其中，`docs/2026-10-01/README.md` 和 `docs/implementation/status.md` 的权重均为 1；`docs/implementation/`、`docs/2026-10-01/`、`docs/research/` 分别为 0.8、0.65、0.7。[主要文档路径的权重规则 ↗](../../../config/review-search.json#L2 "支持两个具体文件以及实施、日期和研究目录所声明的路径前缀与数值权重。")

其余三条规则将 `docs/prototype/`、`.agents/`、`.claude/` 分别设为 0.35、0.65、0.45。[原型与工具目录的权重规则 ↗](../../../config/review-search.json#L8 "支持原型、.agents 与 .claude 三个路径前缀及其权重，并与前一组规则共同说明配置使用了文件和目录两种粒度。") 这些内容能够支持对静态数值及其大小的比较，但路径名称本身不足以说明目录的用途、内容年代、维护责任或权威程度。

<a id="interpretation-limits"></a>
## 配置的解释边界

从文件整体可确认，它只包含八条路径前缀与数值权重规则，没有同时声明未匹配路径的默认权重、多个前缀同时命中时的选择或合并策略，也没有解释权重参与评分的方向。[完整路径权重配置 ↗](../../../config/review-search.json#L1 "覆盖完整规则数组，支持共有八条规则，并说明文件本身未包含默认值、匹配算法、评分方向或运行时加载信息。")

该材料还未展示由哪个运行组件加载此文件、何时加载，以及这些数值是否实际改变检索结果。因此，目前应把它理解为一份静态配置声明；若要进一步说明“数值越大排序越靠前”或某类资料具有更高搜索优先级，仍需结合配置加载器、评分逻辑及真实检索验证。[完整路径权重配置 ↗](../../../config/review-search.json#L1 "覆盖完整规则数组，支持共有八条规则，并说明文件本身未包含默认值、匹配算法、评分方向或运行时加载信息。")

<a id="relationship-to-materials"></a>
## 与仓库材料分类的关系

规则覆盖具体说明文件、实施目录、日期目录、研究目录、原型目录以及两个点号开头的目录，表明配置选择了不同粒度的路径作为匹配对象：既有精确文件路径，也有目录前缀。[主要文档路径的权重规则 ↗](../../../config/review-search.json#L2 "支持两个具体文件以及实施、日期和研究目录所声明的路径前缀与数值权重。") [原型与工具目录的权重规则 ↗](../../../config/review-search.json#L8 "支持原型、.agents 与 .claude 三个路径前缀及其权重，并与前一组规则共同说明配置使用了文件和目录两种粒度。")

不过，配置没有描述这些路径之间的继承关系，也不能单凭权重判断精确文件规则是否覆盖目录规则。要确认日期目录是否需要周期更新，或 `.agents/`、`.claude/`、`docs/prototype/` 各自承担什么资料角色，需要补充相应设计说明或维护文档。
