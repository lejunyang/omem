# 批次二严格合同测试

验证提议、评估与纠正合同的解析边界：文档夹具可被接受，未知字段、正文类型不匹配及缺少 CAS 版本的更新被拒绝；批次与纠正部分目前证明给定样例可解析，不足以证明样例中的每个字段均为必填。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="proposal-boundary"></a>
## 提议合同与应用边界

测试读取文档中的 Proposal v1 示例，确认其标识与 `task` 类型能够通过解析，并断言结果没有状态字段；因此合同解析成功不能解释为提议已经应用。[Proposal 示例解析与未应用边界 ↗](../../../apps/server/tests/contracts.test.ts#L10 "支持文档 Proposal 示例能够解析，且解析结果不包含状态字段，因此不能据此认定提议已应用。") 另一组反例明确拒绝额外的 `applied` 字段、类型与正文不匹配的对象，以及更新操作中缺少预期版本的情况。[严格解析反例 ↗](../../../apps/server/tests/contracts.test.ts#L22 "支持未知字段、类型与正文不匹配，以及更新缺少预期版本时会被拒绝。") 这些断言覆盖结构边界、类型一致性与并发更新前置条件，但没有验证数据库写入、评审结论或应用事务。

<a id="batch-envelopes"></a>
## 批次信封与纠正样例

ProposalBatch 测试以 schema 版本、作业、角色、观察、提议和弃权等字段构造批次并成功解析；AssessmentBatch 也以提议摘要、引文资产判断及语义判断构造评估，并得到 `supported`。[提议与评估批次样例 ↗](../../../apps/server/tests/contracts.test.ts#L42 "支持测试使用列出的字段构造 ProposalBatch 与 AssessmentBatch，并成功解析相应内容；不将其扩大为逐字段必填性证明。") CorrectionProposal 示例包含带预期版本的目标、个人工作区范围、停止使用内容、替代内容、证据、原因和来源，解析后保留目标版本。[纠正提议完整样例 ↗](../../../apps/server/tests/contracts.test.ts#L72 "支持 CorrectionProposal 测试样例包含目标版本、范围、替换信息、证据、原因与来源，并验证解析后的预期版本。") 这替代了此前“这些字段均被测试证明为必填”的过强结论：现有用例没有逐项删除字段并断言拒绝，只能证明完整样例与当前合同兼容。
