# Lark 应用接入与配对状态机

编排新建或导入应用、扫码注册、密钥保存、能力探测和 owner 配对，以版本化连接与绑定激活个人工作区的 Lark 集成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="registration"></a>
## 注册、导入与状态记录

服务把 onboarding 主记录及状态事件写入 SQLite，工作区固定为 `personal`。新建流程通过注册适配器启动并等待二维码或注册完成；二维码必须是 HTTPS，活跃控制器和完成 Promise 仅保存在进程内 Map。既有应用既可从注入的 Botmux 提供器取凭据，也可直接提交密钥。[接入启动与既有应用导入 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L24 "说明 personal 工作区记录、异步注册生命周期、进程内活动状态，以及 Botmux 或直接凭据导入路径。") 注册异常会映射为拒绝、过期、取消或失败；若取消后注册器才返回凭据，则不激活连接，而是记录需人工核查。[注册失败与迟到凭据 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L167 "支持注册异常状态映射，以及取消后迟到凭据只记录人工核查而不继续激活的边界。")

<a id="capability-versioning"></a>
## 凭据版本与能力探测

凭据校验后先写入加密密钥存储，再创建或复用连接，并新增状态为 `checking` 的连接版本；事务建档失败会移除刚写入的密钥。[连接版本和密钥落库 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L284 "说明密钥存储、连接复用、新候选版本创建，以及建档事务失败时移除密钥。") 随后能力探测器实测请求配置：缺失能力会使候选失败，否则进入等待配对；既有活动版本在候选探测失败时仍保持活动。若探测成功返回后事务发现 onboarding 已取消，候选版本会失败且新密钥被移除。[能力探测与取消竞态 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L365 "支持探测失败处理、缺失能力判定、成功返回后的取消清理，并揭示探测抛错分支未检查取消状态。") 但若探测在取消后抛错，异常分支未重新检查取消状态，也未移除密钥，并可能把 onboarding 从 `cancelled` 改成 `failed`，构成取消竞态边界。

<a id="pairing-and-activation"></a>
## 配对、换绑与激活边界

配对码由 24 字节随机值生成，数据库只保存哈希，默认五分钟有效；签发新码会消费旧码，无效尝试达到五次也会消费当前码。接收事件还校验应用、有效期以及候选操作者和聊天的一致性。[配对码签发与接收 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L569 "说明配对码哈希、有效期、旧码消费、错误尝试上限和候选身份绑定。") 最终确认要求预期 open ID 匹配，并在一个事务内替代旧绑定、取消旧卡片和待发通知、禁用旧目标、切换活动连接版本，再创建 owner 通知与决策目标。群聊还会直接新增 `capture_enabled=1` 的群监控目标。[确认配对与绑定切换 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L665 "支持旧绑定及待处理任务取消、新版本激活、目标创建，以及群聊默认开启捕获的论断。") 因而确认配对不仅绑定身份，也会改变既有投递状态和群聊捕获范围。
