# Lark 应用接入、能力检查与 owner 配对

编排新建或复用 Lark 应用的接入状态机：接收并加密保存凭据、建立连接版本、探测能力、通过一次性码确认 owner 与目标会话，并原子切换活动绑定。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="registration_entry"></a>
## 注册与既有应用入口

活动注册控制器只保存在进程内 Map；新流程先持久化 personal 工作区的 onboarding，再异步调用注册适配器，收到合法 HTTPS 二维码后转为 awaiting_scan。[进程内活动注册表 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L24 "支持活动注册控制器与完成 Promise 只保存在当前服务进程内的说明。")[注册启动与二维码状态 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L83 "支持 onboarding 持久化、异步注册、二维码状态转换和活动任务管理。") 既有应用可从配置提供器读取凭据，也可接收显式密钥，两条路径最终进入同一凭据验收流程。[既有应用导入 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L120 "支持从既有应用提供器或显式密钥导入，并汇入统一凭据验收流程。") 取消会中止当前控制器；若取消后才返回凭据，仅记录需要人工核查的外部应用，不继续激活。[取消后的迟到凭据 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L244 "支持取消后返回的凭据仅记录人工核查信息而不继续激活。")[取消活动注册 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L471 "支持取消状态转换及中止当前活动控制器。")

<a id="credentials_and_capabilities"></a>
## 凭据版本与能力门禁

凭据必须包含合法应用编号和非空密钥，复用模式还要求编号与请求一致。密钥写入加密存储后，为连接创建新的候选版本；事务失败会移除刚写入的密钥。能力探测失败会把候选版本置为失败，但已有活动版本可使连接继续保持 active；探测成功后对缺失能力去重排序，只有不存在缺失项时才进入 awaiting_pair。[凭据版本与能力探测 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L293 "支持凭据校验、候选版本创建、探测失败处置、保留既有活动版本及缺失能力门禁。")

<a id="pairing_security"></a>
## 一次性配对与操作者确认

仅 awaiting_pair 状态可签发随机配对码；数据库保存其哈希，并先消费同连接尚未使用的旧码。[配对码签发与旧码失效 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L569 "支持仅就绪状态签发随机配对码、保存哈希并消费同连接旧码。") 接收事件时核对应用、有效期、消费状态以及既有候选操作者和会话，错误代码会累计尝试，达到上限即消费。最终确认还要求候选身份存在且 open ID 与预期操作者一致。[配对事件与最终身份确认 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L604 "支持代码哈希查询、错误尝试、过期和候选一致性检查，以及 expectedOpenId 最终确认。")

<a id="activation_and_relations"></a>
## 原子激活与下游关系

确认配对在同一事务中废弃旧绑定，取消其待处理卡片和投递，禁用旧目标并切换连接版本，然后创建新绑定及 owner 通知、决策目标。若配对会话是群聊，当前实现还会直接创建 `capture_enabled=1` 的 group_monitoring 目标；最后更新活动版本和 owner、消费配对码并把 onboarding 标为 active。[绑定切换与目标创建 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L683 "支持旧绑定清理、新绑定和通知目标创建、群聊捕获默认启用及最终激活。")
