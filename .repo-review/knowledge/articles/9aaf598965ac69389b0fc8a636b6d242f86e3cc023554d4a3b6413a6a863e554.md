# 质量数据集与人工标注

记录质量评测基础设施、飞书人工标注流程和 dev 数据状态。材料声称基础设施已实现，但截至 2026-09-27，人工标注已停止、数据集尚未冻结、holdout 尚未建立，因此不能声称最终质量门已经通过。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="dataset-integrity"></a>
## 数据隔离与冻结条件

原始材料、样本文本、人工标签、预测和失败结果保存在被 Git 忽略的数据目录与 SQLite 中，仓库只保留 schema、runner、确定性 fixture 和聚合说明。每个 dataset 固定来源、revision、digest、split 与目标数量，相同 digest 不重复入集；holdout 只有达到目标数量并全部人工确认后才能冻结，且须保存和复核 manifest digest。文档称基础设施已实现，但同时明确 holdout 尚未建立。[数据隔离与冻结规则 ↗](../../../docs/implementation/batch2/quality-evaluation.md#L1 "支持质量数据保存位置、数据集去重、holdout 冻结完整性条件，并限定当前历史状态。")

<a id="annotation-flow"></a>
## 飞书标注与回调校验

标注卡经项目自己的飞书应用和正式 outbox 发给 active owner 私聊，一个会话只维护一张卡。callback 校验协议、应用、owner binding、会话、消息、样本、有效期、HMAC nonce、草稿 digest，并按 event ID 去重。按钮可确认标签、覆盖为 abstain、进入 needs_edit 或跳过；修订接口要求上一版 label digest，以避免并发覆盖。[飞书人工标注协议 ↗](../../../docs/implementation/batch2/quality-evaluation.md#L12 "说明标注卡发送渠道、callback 完整性校验、按钮状态转换及并发修订保护。")

<a id="current-state"></a>
## 当前 dev 集与已知问题

当前来源仅是一篇文档，目标为 40 条 dev 样本；40 条改进版草稿已经生成，但仍不是人工真值。按 owner 要求，live 标注和 annotation session 已停止，尚无冻结数据集。试验中首版 claim 因重复整段原文而被废弃；skip 与 skipped 的映射问题据文档称已修复并增加回归测试。一次通过校验的 abstain callback 仍不计入质量结果，发送或点击也不能证明数据集通过。[开发集历史状态 ↗](../../../docs/implementation/batch2/quality-evaluation.md#L33 "支持 40 条草稿、停止 live 标注、尚无冻结数据集，以及试验中发现和据称修复的问题。")

<a id="evaluation-gates"></a>
## 评测流程与未完成门槛

设计中的正式流程要求 `quality-run` 仅接受冻结 dataset，在隔离临时库中逐样本运行受控 extractor/verifier pipeline，并原子保存 predictions；随后评估自动应用 precision、证据支持 precision、明确样本 coverage、特定 false positives、缺失预测、失败明细和延迟。两个 precision 门槛均为至少 95%，coverage 至少 80%，歧义或转发 owner-task 假阳性须为 0。由于人工标注未完成且 holdout 未冻结，目前不得运行或声称通过最终 holdout 门。[正式评测门槛 ↗](../../../docs/implementation/batch2/quality-evaluation.md#L65 "支持冻结集运行前提、评测指标和阈值，并明确最终 holdout 门尚不能声称通过。")
