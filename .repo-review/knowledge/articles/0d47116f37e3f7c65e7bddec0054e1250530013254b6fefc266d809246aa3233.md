# 人类可读标签与边禁用测试

验证前端优先使用 DTO 展示字段，缺失时仅退化到可读名称，并依据 actionable 或旧状态决定边的原因文本和可用性。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="labels"></a>
## 避免内部标识泄漏

文件标签优先采用 `displayTitle`，否则取路径 basename，再缺失时显示“未命名文件”；文件路径优先采用 `displayPath`。符号同样优先 `displayTitle`，再退到 `name`，最后显示“未命名符号”。[文件与符号标签断言 ↗](../../../apps/web/src/codewiki/labels.test.ts#L10 "支持 DTO 展示字段优先、可读 fallback 以及不显示内部标识的合同。") 这些断言直接保护界面不把 fileId 或 symbolId 当作可见文本。实现只接受展示字段、路径或名称的窄类型输入，fallback 中也没有内部 id。[人类标签实现 ↗](../../../apps/web/src/codewiki/modules.ts#L222 "解释文件、路径与符号标签的具体回退次序。") 测试未覆盖仅提供内部 id 的对象，但从函数签名和分支看该 id 不参与输出。

<a id="edge_state"></a>
## 边状态兼容规则

边的原因文本以 DTO 的 `actionable=false` 和 `reason` 为最高优先级；可操作边返回空原因。对缺少新 DTO 字段的旧数据，则把 missing 映射为“仓库内未解析”、stale 映射为“已过期”。[边原因与禁用断言 ↗](../../../apps/web/src/codewiki/labels.test.ts#L28 "支持新 DTO 字段优先和旧状态兼容的行为。") 禁用判断也以显式 actionable 为准，所以 `actionable=true` 即便带 missing 状态仍可点击；只有字段缺失时才按 legacy missing 禁用。实现与该兼容策略一致。[边状态展示实现 ↗](../../../apps/web/src/codewiki/modules.ts#L239 "解释 reason 生成与 disabled 判定的优先级。") 尚未断言 `actionable=false` 且 reason 为空时的“不可解析”默认文案，也未覆盖未知状态。
