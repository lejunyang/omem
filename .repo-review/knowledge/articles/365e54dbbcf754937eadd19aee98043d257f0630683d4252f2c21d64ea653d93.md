# SQLite 并发写入等待测试

通过独立子进程持有真实 SQLite 写锁，验证知识存储会等待锁释放并完成捕获，而不是丢失操作。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="lock-fixture"></a>
## 真实并发写锁场景

测试先初始化数据库，再启动独立 Node 子进程，以 `BEGIN IMMEDIATE` 持有 SQLite 写锁约 250 毫秒。主测试等待子进程明确报告锁已建立后，才创建存储和知识仓库并执行手动材料捕获，因此覆盖的是实际进程间锁竞争，而非模拟异常。[并发写锁测试装置 ↗](../../../apps/server/tests/knowledge-concurrency.test.ts#L9 "支持子进程持有真实 SQLite 即时事务写锁以及主进程随后执行捕获的流程。")

<a id="outcome"></a>
## 完成条件与清理

断言要求捕获结果中的 fragment 保留完整固定文本，同时持锁子进程必须以状态码 0 正常退出，证明写操作等待后成功而未丢失。无论测试结果如何，清理逻辑都会终止仍存活的子进程、关闭存储并删除临时目录。[等待结果与资源清理 ↗](../../../apps/server/tests/knowledge-concurrency.test.ts#L19 "支持捕获内容、子进程退出状态以及测试结束时资源清理的断言。")
