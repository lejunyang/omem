# 仓库材料捕获与关联上下文适配器

该模块把仓库文件转换为统一知识管线可消费的固定材料，维护文件删除状态，并从显式本地文档链接中提供有限的分析上下文；它只负责输入适配和候选上下文选择，不负责解释内容或确认知识关系。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="capture"></a>
## 仓库捕获流程

模块解决的是“如何将仓库内容稳定接入通用知识管线”的问题：它依赖共享的 `Store`、捕获合同和 `KnowledgeRepository`，自身仅充当输入生产者，不建立独立的代码知识库。[仓库适配器职责与依赖 ↗](../../../apps/server/src/review/materials.ts#L1 "支持该模块仅生产输入并复用共享捕获、知识仓库和评审元数据能力的说明。") 捕获时优先通过 Git 枚举已跟踪及未忽略的未跟踪文件；Git 不可用时递归遍历，并跳过仓库元数据、派生运行目录、依赖与构建目录。[文件枚举与目录排除 ↗](../../../apps/server/src/review/materials.ts#L15 "说明 Git 枚举、递归回退以及基础目录过滤流程。")

对每个候选文件，流程会拒绝非普通文件、符号链接、越出真实仓库根目录的路径以及超过 5 MB 的文件。随后按字节计算 SHA-256；只有内容哈希或捕获格式变化时才创建新捕获。支持 PNG、JPEG、WebP，其余内容必须是无 NUL 的 UTF-8 文本，长文本按 18 万字符切片；空文件被排除。[文件校验与捕获构造 ↗](../../../apps/server/src/review/materials.ts#L32 "支持路径安全、大小限制、哈希去重、图像识别、UTF-8 校验、切片和分类捕获的描述。") 捕获输入的文本与图像形态对应共享合同，因此图片不是该适配器私设的数据结构。[共享文本与图像合同 ↗](../../../packages/contracts/src/index.ts#L18 "说明捕获部件采用共享合同支持的文本和三种图像格式。")

<a id="identity"></a>
## 身份、变更与删除协调

文件身份使用 `omem:<仓库相对路径>`，内容哈希只判断是否需要追加修订；这使同一路径修改后沿用同一来源，而不是随内容变化创建新来源。成功捕获会返回材料键与摘要，单文件异常则记录为 `failed`，不会中断整批扫描。[路径身份与捕获结果 ↗](../../../apps/server/src/review/materials.ts#L37 "支持外部身份由仓库相对路径构造、哈希用于变更检测且错误按文件记录的论断。")

扫描结束后，模块把本轮未处于 `captured` 状态的既有文件来源标记为 removed；创建评审知识仓库时，再过滤 removed 或 legacy alias 来源，只向通用知识仓库暴露当前材料。[移除状态协调与当前材料过滤 ↗](../../../apps/server/src/review/materials.ts#L57 "说明扫描后如何标记缺失来源，以及知识仓库如何排除 removed 和 legacy alias 材料。") 这里直接操作共享 `Store` 的 SQLite 连接，而评审侧元数据表由 review store 模块管理；共享 Store 本身是单用户 SQLite 基础并聚合 jobs、inputs 等仓储能力。[共享 Store 的 SQLite 基础 ↗](../../../apps/server/src/store.ts#L36 "支持材料适配器所依赖 Store 的数据库及仓储组件关系。")

<a id="linked-context"></a>
## 显式链接上下文与边界

`linkedMaterialOffers` 从目标文本的 Markdown 链接提取相对文件引用，并为 HTML 额外尝试常见的构建脚本、应用脚本和样式文件。它排除外部 URL、目标自身、重复项与不存在的路径；带锚点时按标题 slug 寻找起始行，每份材料最多提供约 80 行，总共最多四份。[本地链接候选选择 ↗](../../../apps/server/src/review/materials.ts#L79 "支持 Markdown 链接提取、HTML 补充引用、锚点定位、范围和数量上限的说明。")

这些结果只是供模型分析的候选上下文，不是已确认关系；含义仍需模型判断并由 verifier 核验。[候选上下文而非确认关系 ↗](../../../apps/server/src/review/materials.ts#L77 "明确链接只用于提供分析上下文，关系含义仍需模型与独立复核确认。") 当前实现只识别简单 Markdown 链接和少量 HTML 约定，未体现 import 解析、跨文件调用证明或引用存在性的语义校验，因此不能据此断言调用关系。所给材料也不含测试文件，无法确认上述失败、回退和删除路径已有何种行为断言。
