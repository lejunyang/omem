# 仓库材料捕获与上下文链接

该适配器把仓库中的普通文本和受支持图像转换为统一捕获输入，以稳定路径身份维护修订；同时记录排除、失败和删除状态，并从显式本地文档链接中提供有限上下文，但不把链接直接认定为知识关系。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 把仓库变成统一知识流水线的输入

该文件解决的是“如何让代码仓库进入个人知识系统”的问题：它只负责生产材料，分析仍由接受通用捕获源的知识流水线完成，因此仓库文件不会形成一套独立的事实权威。文件使用 `omem:<仓库相对路径>` 作为外部身份；同一路径内容变化时更新修订，而不是因哈希变化创建另一份来源。参考 [仓库适配器职责 ↗](../../../apps/server/src/review/materials.ts#L1 "支持该模块仅生产输入、分析由通用知识流水线承担的定位。") [稳定文件身份 ↗](../../../apps/server/src/review/store.ts#L29 "说明仓库来源按相对路径保持身份，并在内容变化时累积修订。")

<a id="capture_flow"></a>
## 发现、过滤与增量捕获

捕获优先读取 Git 已跟踪及未忽略文件；Git 命令失败时退回目录遍历，并跳过版本库、派生运行数据、依赖和构建目录。随后逐项拒绝私有环境配置、符号链接、越界路径、超出 5 MB 的文件、空文本及无法按 UTF-8 解码的二进制内容。参考 [文件发现回退 ↗](../../../apps/server/src/review/materials.ts#L15 "支持优先使用 Git 文件清单、失败后改为目录遍历的流程。") [仓库文件过滤 ↗](../../../apps/server/src/review/materials.ts#L27 "支持私有配置、非普通文件、符号链接、越界路径和尺寸限制等边界条件。")

文本按最多 180000 字符切分，PNG、JPEG、WebP 则以 Base64 图像部件保存。只有内容哈希或捕获格式变化时才调用统一 `store.capture`；成功、排除与失败都会形成覆盖记录，单个文件失败不会中止整批处理。参考 [增量内容捕获 ↗](../../../apps/server/src/review/materials.ts#L36 "支持哈希判重、文本和图像处理、分块捕获以及逐文件失败隔离的描述。")

捕获结束后，适配器把当前未捕获到的既有仓库来源标记为 removed；创建知识仓库时再过滤 removed 或旧身份别名对应的材料，从而保留历史来源记录但不让它们进入当前材料集合。参考 [删除状态协调 ↗](../../../apps/server/src/review/materials.ts#L57 "说明捕获完成后如何把不再存在于当前集合的仓库来源标记为 removed。") [当前材料过滤 ↗](../../../apps/server/src/review/materials.ts#L69 "支持知识仓库排除已删除来源和旧身份别名的行为。")

<a id="linked_context"></a>
## 显式链接只提供候选上下文

`linkedMaterialOffers` 扫描目标文本中的 Markdown 本地链接，并为 HTML 额外尝试同目录的构建脚本、应用脚本与样式表。它忽略外部 URL、目标自身、重复项和不存在的材料；若链接带标题锚点，则从匹配标题开始，最多提供 80 行，每批最多返回 4 份材料。参考 [本地链接上下文选择 ↗](../../../apps/server/src/review/materials.ts#L79 "支持本地链接解析、标题锚点定位、去重以及范围和数量上限。")

这些链接只是交给模型分析的上下文，不代表已确认关系；材料含义仍由模型判断，并由独立复核检查支持性。当前实现只识别 Markdown 链接及少量 HTML 邻接文件，没有证据表明它解析源码 import、动态链接或跨文件调用。参考 [链接不是确认关系 ↗](../../../apps/server/src/review/materials.ts#L77 "明确链接材料仅作为候选上下文，关系和支持性仍需模型分析与复核。")
