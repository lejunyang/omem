# 仓库材料捕获与关联上下文适配器

该模块把仓库文件转换为统一知识材料，记录捕获、排除和失败覆盖状态，并依据本轮成功捕获集合更新评审来源的 removed 标记；因此当前存在但被排除或捕获失败的既有来源也会暂时退出当前证据集，并不只代表文件已从仓库删除。模块还从显式本地文档链接中选取有限上下文，但不把链接直接认定为知识关系。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_capture"></a>
## 作用与捕获主流程

该模块是仓库到通用知识管线的输入适配器：它负责枚举、校验和保存固定材料，知识分析仍由共用管线处理。逐文件覆盖记录区分 `captured`、`excluded` 与 `failed`，供后续识别实际纳入情况。[仓库适配器职责与覆盖状态 ↗](../../../apps/server/src/review/materials.ts#L1 "支持该模块只生产统一知识材料输入，并以 captured、excluded、failed 三种状态记录逐文件处理结果。")

捕获优先通过 Git 枚举已跟踪及未忽略的新文件；命令失败后递归扫描，并跳过评审运行目录、依赖、构建目录、Git 元数据、私有环境文件和本地配置。候选路径还要通过普通文件、非符号链接、真实路径未逃逸仓库以及 5 MB 大小预算检查。[仓库枚举与文件安全检查 ↗](../../../apps/server/src/review/materials.ts#L15 "支持 Git 优先、递归回退、目录和私有文件排除、符号链接与仓库边界检查以及大小预算的流程说明。") 内容以 SHA-256 摘要判断是否需要重新捕获：支持 PNG、JPEG、WebP，其他输入必须是无 NUL 的 UTF-8 文本；空文件被排除，长文本按 18 万字符切片后交给共享 `Store.capture`。[内容解码与统一捕获 ↗](../../../apps/server/src/review/materials.ts#L36 "支持摘要比较、图像类型识别、UTF-8 校验、空文件排除、文本分片和 Store.capture 调用的说明。")

<a id="identity_and_availability"></a>
## 稳定身份与当前可用性协调

来源身份采用 `omem:<仓库相对路径>`。同一路径内容变化会推进该来源的修订，内容摘要只用于判断是否需要重新捕获；不同路径即使字节完全相同，也保持为独立来源。[路径稳定身份约定 ↗](../../../apps/server/src/review/store.ts#L27 "解释来源身份为何绑定仓库相对路径，以及同一路径修订和同内容不同路径之间的区别。")

扫描结束后，`present` 只收集本轮状态为 `captured` 的材料键；数据库中所有不在该集合内的既有 `omem:%` 来源都会被标记为 `removed`。因此这一标记不仅覆盖真正删除或迁移的文件，也会覆盖本轮仍存在但因空文件、规则排除、超限、读取或解码错误、捕获异常而成为 `excluded` 或 `failed` 的既有来源。知识仓库随后过滤 `removed` 和旧别名来源，使它们不再作为当前证据。[成功集合与来源可用性标记 ↗](../../../apps/server/src/review/materials.ts#L57 "支持 present 仅包含 captured 项、其余既有 omem 来源均被标记 removed，以及当前知识材料过滤 removed 和旧别名来源的关键语义。") 这替代了先前将该流程仅概括为“协调仓库中已删除来源”的较窄结论。

适配器依赖共享 `Store` 的 SQLite 连接和捕获能力；该存储明确以单用户 SQLite 为当前基础，并在初始化时迁移数据库、设置文件权限及创建各类仓储服务，团队级约束仍属于后续迁移。[共享 Store 的单用户 SQLite 基础 ↗](../../../apps/server/src/store.ts#L4 "支持当前存储的单用户 SQLite 定位，以及数据库迁移、权限设置和仓储服务初始化能力。")

<a id="linked_context_and_limits"></a>
## 链接上下文与待核验边界

`linkedMaterialOffers` 从目标材料的 Markdown 链接中选择本地上下文：外部协议被忽略，相对路径按目标文件目录归一化，目标自身、缺失材料和重复项不会加入。锚点命中标题 slug 时从该标题起提供最多 80 行，否则从首行开始；HTML 还会尝试约定的相邻资源，最终最多返回四项。[显式本地链接上下文选择 ↗](../../../apps/server/src/review/materials.ts#L79 "支持本地链接解析、相对路径归一化、锚点范围选择、去重以及最多四项候选的限制。")

这些链接只是提供给模型的候选上下文，并不自动形成已确认的依赖、调用或知识关系，含义仍需模型分析及独立复核。[链接不是确认关系 ↗](../../../apps/server/src/review/materials.ts#L77 "支持本地链接仅作为模型上下文、仍需分析和复核而不能自动确认关系的边界。") 当前固定材料未包含相关测试，也未展示 `Store.capture` 的完整实现，所以捕获边界的行为覆盖和单次捕获的事务原子性仍不能从现有证据确认。

<a id="coverage_semantics"></a>
## 覆盖状态的解释限制

覆盖记录描述的是本轮处理结果，而 `review_source_meta.removed` 描述的是来源是否属于本轮成功捕获集合，两者不能等同理解。一个路径可以在覆盖记录中明确显示为 `excluded` 或 `failed`，同时其过去已存在的来源被写成 removed；排查知识缺失时应先查看覆盖原因，而不能仅据 removed 推断仓库文件已物理删除。[仓库适配器职责与覆盖状态 ↗](../../../apps/server/src/review/materials.ts#L1 "支持该模块只生产统一知识材料输入，并以 captured、excluded、failed 三种状态记录逐文件处理结果。") [成功集合与来源可用性标记 ↗](../../../apps/server/src/review/materials.ts#L57 "支持 present 仅包含 captured 项、其余既有 omem 来源均被标记 removed，以及当前知识材料过滤 removed 和旧别名来源的关键语义。")
