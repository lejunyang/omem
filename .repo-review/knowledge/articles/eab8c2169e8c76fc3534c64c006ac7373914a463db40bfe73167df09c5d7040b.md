# 仓库材料捕获与关联上下文适配

把仓库文件转换为统一 KnowledgeMaterial，并在安全过滤、内容去重和显式文档链接发现之间建立边界；它只负责输入适配，不承担知识分析或关系确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="capture"></a>
## 捕获职责与流程

该模块把仓库视为统一知识流水线的一种输入源，而不是独立的代码知识库。捕获时优先通过 Git 枚举已跟踪与未忽略文件；Git 不可用时退化为目录遍历，并跳过依赖、构建产物和评审运行目录。随后逐文件校验普通文件、符号链接和真实路径，计算 SHA-256；仅当内容摘要或捕获格式变化时调用共享 `Store.capture`，从而让路径身份持续积累修订。[仓库文件枚举与增量捕获 ↗](../../../apps/server/src/review/materials.ts#L15 "支持模块通过 Git 或遍历枚举文件，并按路径身份和内容摘要调用共享捕获流程的说明。")

文本按输入上限切片，PNG、JPEG、WebP 以图像部件保存；空文本、二进制文本、超大文件和私有配置会被排除或记录失败，而不会中断其他文件。返回的覆盖结果明确区分 captured、excluded、failed，便于上层展示真实覆盖情况。[文件安全与输入预算 ↗](../../../apps/server/src/review/materials.ts#L28 "支持对私有路径、符号链接、文件大小、编码、空内容及图像类型的边界说明。")

## 材料读取与上下文扩展

`createReviewKnowledgeRepository` 复用通用 `KnowledgeRepository` 和当前材料查询，但过滤已删除来源及旧身份别名，因此评审知识只从当前有效原始材料生成。[评审知识仓库过滤 ↗](../../../apps/server/src/review/materials.ts#L60 "说明评审仓库复用通用知识仓库，同时排除删除来源和旧别名。")

`linkedMaterialOffers` 只把 Markdown 本地链接及特定 HTML 配套文件作为候选上下文：它解析相对路径，可按标题锚点定位起始行，每个候选最多提供约 80 行且总数最多四个。这里的链接只是模型可见的上下文，不会自动成为已确认关系；含义仍需分析与独立复核。[本地文档链接候选上下文 ↗](../../../apps/server/src/review/materials.ts#L68 "支持链接解析、锚点定位、候选数量限制以及链接不等同确认关系的边界。")
