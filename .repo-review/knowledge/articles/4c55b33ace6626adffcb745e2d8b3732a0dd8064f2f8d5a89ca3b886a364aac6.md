# omem：统一证据链上的个人记忆与助理

omem 统一接收多种个人材料，以不可变原始证据支撑知识整理、问答、事项跟进与仓库 Wiki；系统已具备本地服务、中文混合检索、独立复核和日常助理流程，但多租户、跨文件精确调用、自动监听回复及部分主动能力仍未实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 从材料留存到可追溯助理

omem 面向个人工作场景，把文本、图片、链接和上下文统一纳入一条不可变证据链。知识正文、个人问答、受治理记忆、待办与通知都沿用这条链；仓库 Wiki 只是代码材料的一种应用，而外部屏幕采集等能力仍需单独配置。参考 [系统定位与证据链 ↗](../../../README.md#L1 "支持 omem 的个人工作记忆定位、统一输入类型、不可变证据链以及仓库 Wiki 和外部采集器的边界说明。")

日常使用时，用户可以直接交办、查找记忆或回顾事项。系统会区分本人明确交办、他人承诺和开放问题：只有明确交办才创建本人事项，等待对象与下次跟进时间也不会被误当成截止时间。参考 [日常助理事项规则 ↗](../../../README.md#L107 "支持日常助理的使用场景，以及明确交办、他人承诺、开放问题和跟进时间之间的区别。")

<a id="knowledge_flow"></a>
## 知识整理、检索与证据回溯

材料先由专门角色分析，再交给独立角色复核，最后组织成模块、架构、需求、进展等可阅读章节。引用贴近具体论断，并指向固定的原文或代码位置；AST 负责定位与明确结构关系，语义解释仍由模型分析和复核。参考 [知识分析与复核流程 ↗](../../../README.md#L39 "说明材料分析、独立复核、章节组织、内联引用和 AST 定位在知识流程中的职责。")

中文检索可选本地 BGE-small-zh-v1.5，并与全文、记忆及 Wiki 引用召回合并。即使命中的是派生知识正文，最终提供给助手的依据仍是当前原始 Fragment，同时在截断前执行可见性和时间过滤。参考 [中文混合检索 ↗](../../../README.md#L20 "支持本地中文向量模型、混合召回、原始 Fragment 回溯及可见性过滤的描述。")

知识库以完整文章和功能目录为主要阅读入口，正文引用可在原处打开分层阅读窗；原始 Markdown 保持文档连续性，代码默认展示被引用行并允许扩展上下文。参考 [知识阅读体验 ↗](../../../README.md#L202 "支持完整文章、章节导航、分层引用阅读、代码上下文展开和原始 Markdown 连贯展示的说明。")

<a id="operation_limits"></a>
## 运行方式与当前边界

当前服务依赖 osdk 和可登录的 Agent CLI，不要求 Docker、Redis、本地大语言模型或 Python。开发入口会同时启动 API 与 Vue，并把仓库材料和已复核文章接入同一个个人知识库；启动只恢复既有知识，不会自动调用生成式模型。参考 [启动与开发入口 ↗](../../../README.md#L5 "支持运行依赖、开发服务行为、知识恢复方式以及启动时不调用生成式模型的陈述。")

系统已有 SQLite FTS5/BM25、中文短词保底和多路融合检索，但精确的跨文件调用类型解析、语义重排、周期巡检及跨来源冲突自动修订仍未完成。日常助理也不会自动监听对方回复、判断交付完成或执行周期回顾。上述内容属于明确的未交付边界，不能由旧计划或小样本验证推断为已实现。参考 [检索与知识流程限制 ↗](../../../README.md#L76 "明确列出已采用的检索机制，以及跨文件调用、语义重排、周期巡检和冲突修订等尚未完成的能力。") [主动助理未交付能力 ↗](../../../README.md#L113 "支持自动监听回复、交付判断、会前准备、周期回顾和重复提醒等仍未实现的边界。")

部署目前是单用户模型：默认只监听本机回环地址；即便配置网络监听和共享令牌，也不能把它视为具备团队租户隔离的权限系统。参考 [单用户部署边界 ↗](../../../README.md#L142 "支持默认网络监听、安全令牌要求及当前不具备多租户权限隔离的说明。")
