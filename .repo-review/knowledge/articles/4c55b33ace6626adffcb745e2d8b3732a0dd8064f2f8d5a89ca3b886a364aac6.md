# omem 项目总览与能力边界

omem 是个人优先的统一记忆与助理系统，以不可变原始证据贯通知识整理、问答、待办、通知及仓库 Wiki；README 同时区分已实现能力、验证层级与尚未完成的主动助理、跨文件分析和多租户边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="positioning"></a>
## 定位与统一证据链

omem 面向个人工作记忆与助理场景，统一接收文本、图片、链接和上下文，以不可变证据支撑 Agent 分析、独立复核和知识正文组织；个人问答、受治理记忆、待办、通知与仓库 Wiki 沿用同一证据链。外部屏幕采集等能力仍需单独配置，并非默认启用。[项目定位与默认接入边界 ↗](../../../README.md#L1 "支持统一输入、不可变证据、个人功能与仓库 Wiki 共用证据链，以及外部屏幕采集需另行配置的定位。")

知识整理复用 Capture → Source / Revision / Fragment、持久任务和共用角色运行时；代码 AST 负责定位及明确结构关系，语义解释由模型分析和复核。[统一知识流程与代码 AST 分工 ↗](../../../README.md#L41 "支持知识处理复用统一证据链、持久任务与角色运行时，并说明 AST 负责定位和结构、模型负责语义分析与复核。") 派生知识只引导召回，回答依据仍回到经过会话可见性过滤的原始 Fragment，不能把知识正文提升为新的独立事实来源。[派生知识回到原始证据 ↗](../../../README.md#L76 "支持知识正文仅引导召回、最终依据仍为经过可见性过滤的原始 Fragment，并区分派生解释与已应用事实。")

<a id="retrieval_wiki"></a>
## 检索与仓库 Wiki

中文语义检索可选用本地 BGE-small-zh-v1.5，并与全文、记忆及 Wiki 引用召回融合；未安装模型时保持全文检索，运行时只读取 osdk 校验的固定快照，不隐式下载。四条中文同义问法的结果只是小样本连通性验证，不能外推为全面召回率；英文和代码标识符仍依赖全文检索与模型补搜。[中文语义检索能力与验证限制 ↗](../../../README.md#L20 "支持本地中文向量模型、固定快照与全文降级机制，以及小样本验证和语言适用边界。")

仓库 review 是隔离运行配置，使用独立 SQLite，不启动个人业务 worker。阅读视图只恢复已提交知识；显式 analyze 或 generate 才调用模型，build 仅重建索引。知识正文、覆盖记录与验证报告可提交，数据库、任务和模型工作目录则位于可重建的 runtime。[仓库知识运行与资产边界 ↗](../../../README.md#L45 "支持 review 的显式模型调用入口、隔离数据库，以及可提交知识资产和可重建 runtime 的区分。")

<a id="assistant_governance"></a>
## 助理、记忆治理与外部接入

日常助理可保存会话，处理明确交办的事项，并区分截止提醒与跟进提醒；站内提醒不会自动催促外部人员。它尚不会自动监听回复、判定交付、准备会议或执行周期回顾，重复提醒、日历和英语学习卡仍待接入，因此不是完整主动助理。[日常助理能力与未完成事项 ↗](../../../README.md#L107 "支持事项和提醒的现有行为，并列明自动监听、周期回顾、日历和英语学习卡等尚未接入。")

材料更新后，旧记忆先停止作为有效依据，再经提炼、独立复核和确定性应用；任务入列或调度成功不等于修复已应用。[材料变更后的记忆重核验 ↗](../../../README.md#L101 "支持旧记忆失效、提炼与独立复核流程，以及排队成功不等于最终应用成功。") Agent 没有领域写权限，自动 worker 与 HTTP 提案最终都必须经过 MemoryService 的固定校验和写入边界。[MemoryService 确定性写入边界 ↗](../../../README.md#L148 "支持 Agent 无领域写权限，自动 worker 与 HTTP evaluate 均不能绕过 MemoryService 写入边界。") 飞书集成默认关闭，本地主密钥只用于加密 App Secret；启用配置不会自动读取任意群，飞书文档也仅在用户提供目标后读取，不会自动抓取全空间。[飞书集成启用与群读取边界 ↗](../../../README.md#L156 "支持飞书能力默认关闭、本地主密钥的用途，以及启用配置后仍不会自动读取任意群。")[飞书文档读取范围 ↗](../../../README.md#L127 "补充支持飞书文档只读取用户明确提供的目标，不会自动抓取整个空间。")

<a id="deployment_limits"></a>
## 部署、验证与边界

项目运行需要 osdk 与可登录的 Agent CLI，但不要求 Docker、Python、Redis 或本地大语言模型。[基础运行依赖 ↗](../../../README.md#L5 "支持运行需要 osdk 和 Agent CLI，同时不依赖 Docker、Python、Redis 或本地大模型。") 默认部署仅监听 loopback；对局域网或公网开放时必须设置强令牌，并建议使用 TLS 反向代理或 SSH 隧道。当前 shared token 不是团队级租户权限系统。[网络暴露与单用户限制 ↗](../../../README.md#L142 "支持默认 loopback、外部监听的强令牌要求、TLS 或 SSH 建议，以及 shared token 并非多租户权限系统。")

README 提供完整检查、浏览器流程及多种真实 Agent smoke 等分层验证入口。[项目验证入口 ↗](../../../README.md#L164 "支持完整检查、浏览器流程、真实 Agent smoke 和质量评估等不同层级的验证入口。") 协议 fixture 只证明流程，独立模型复核也不等于人工验收，真实全仓覆盖和失败需另行记录。[协议 fixture 的证明范围 ↗](../../../docs/implementation/knowledge-pipeline.md#L23 "支持协议 fixture 只能证明流程，真实模型全仓覆盖与失败必须另行记录的限制。")[模型复核不等于人工验收 ↗](../../../README.md#L76 "支持独立模型复核不能替代人工验收，避免把自动复核结果扩大为完整验收结论。") 跨文件调用精确解析、语义重排、周期巡检及跨来源冲突自动修订仍未完成，不能视为已交付。[仍未交付的分析与治理能力 ↗](../../../README.md#L78 "支持跨文件调用精确解析、语义重排、周期巡检及跨来源冲突自动修订仍未完成的边界。")
