# omem 项目能力与运行说明

README 将 omem 描述为个人工作记忆与助理系统，概述统一采集与知识整理、Agent 配置、单用户部署、外部集成和验证入口，并明确语义检索、多租户、跨轮会话及部分自动重核验能力仍有限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="product-and-knowledge"></a>
## 产品定位与知识流程

omem 面向个人工作记忆与助理场景，统一接收文本、图片、链接和上下文，保留不可变证据，再通过 Agent CLI/ACP 分析、独立复核并组织知识正文。个人问答、受治理记忆、待办、通知和仓库 Wiki 沿用同一证据链；外部屏幕采集仍需单独配置。[项目定位与统一输入 ↗](../../../README.md#L1 "支持个人助理定位、统一多模态输入、不可变证据链以及外部采集需单独配置的说明。")

知识处理复用 Capture→Source/Revision/Fragment、持久任务和 RoleRuntimeGateway；AST 用于定位及明确结构关系，语义说明由模型分析和复核。[知识整理与代码定位职责 ↗](../../../README.md#L20 "支持通用知识管线、独立复核、内联引用及 AST 只负责定位和明确结构关系的论断。") 派生正文只能引导召回，最终依据仍回到经过会话可见性过滤的原始 Fragment；疑问和用户回答进入重核对流程，独立模型复核也不等同于人工验收。[原始证据召回与人工验收边界 ↗](../../../README.md#L50 "直接支持派生正文仅作导航、召回仍返回可见性过滤后的原始 Fragment，以及独立复核不等于人工验收。")

<a id="runtime-and-review"></a>
## 运行方式与仓库评审

基础运行需要 osdk 和可登录的 Agent CLI，不要求 Docker、Python、Redis 或本地大模型；个人服务可通过默认启动或开发模式运行。[基础运行依赖与启动方式 ↗](../../../README.md#L5 "支持 osdk、Agent CLI、无需本地模型及默认和开发启动方式的说明。") 部署边界则更严格：默认只监听 loopback，开放到局域网或公网时必须设置强令牌，并建议使用 TLS 反向代理或 SSH 隧道；当前 shared-token 方案明确是单用户实现，不能视作团队权限系统。[单用户网络部署边界 ↗](../../../README.md#L92 "直接支持 loopback 默认监听、外部暴露所需令牌与加密通道，以及 shared token 不是团队权限系统。")

仓库阅读模式 `dev:review` 只恢复已提交知识，不调用模型；`review:analyze` 或定向 `review:generate` 才进行真实分析，`review:build` 仅重建索引。review 使用独立 SQLite 且不启动个人业务 worker。[Review 命令与隔离运行 ↗](../../../README.md#L24 "支持阅读启动不调用模型、显式分析与索引命令，以及 review 独立数据库和不启动业务 worker的说明。") 跨文件调用的精确类型解析、embedding 检索和所有来源的自动重核验仍未完成，不能写成已交付能力。[尚未完成的知识能力 ↗](../../../README.md#L52 "直接支持跨文件精确调用解析、embedding 检索及所有来源自动重核验尚未完成的结论。")

<a id="agents-data-integrations"></a>
## Agent、数据治理与外部集成

Agent profile 可配置 transport、命令、模型和 effort；服务会探测能力并拒绝不受支持的选项。CLI-only 模式不能附图，每次问答使用新会话，尚未实现跨轮 ACP session resume；保存的引用只表示曾提供给模型，不代表事实支持已经验证。[Agent 能力发现与会话限制 ↗](../../../README.md#L56 "支持模型能力校验、CLI 图片限制、新会话策略及引用不等同于事实验证的说明。")

SQLite 保存版本、片段、任务和治理记录；相同来源与内容可幂等重试，不同内容形成新版本。学习开启后，extractor 和独立 verifier 通过持久任务处理材料，最终写入仍受 MemoryService 的确定性门控，模型没有直接写库权限。[持久任务与 MemoryService 写入边界 ↗](../../../README.md#L88 "支持版本化存储、幂等捕获、extractor/verifier 流程及模型不能直接写库的论断。") 飞书是默认关闭的显式集成，需要本地主密钥、授权和同应用 pairing；主密钥丢失或轮换会使已有密文无法解密。[飞书启用与密钥治理 ↗](../../../README.md#L102 "支持飞书默认关闭、需要显式授权和本地主密钥，以及密钥丢失后的解密风险。")
