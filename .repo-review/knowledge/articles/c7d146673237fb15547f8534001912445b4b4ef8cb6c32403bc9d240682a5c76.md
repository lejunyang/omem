# Code Wiki 总容器与证据下探路由

组织知识首页、代码快照、模块依赖图和多类详情帧，并统一管理可深链的证据 trail。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role"></a>
## 页面职责与数据装载

该组件是 Code Wiki 垂直切片的编排层：维护 overview、structure、graph、module、file 五种主视图，加载当前快照、代码图和模块说明列表，并把文件、符号建立为映射供详情帧解析。模块节点与边由代码图聚合得到，首屏的三类请求并行执行；模块说明失败会退化为空列表，而快照或代码图失败会进入整体错误状态。[代码图并行装载 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L44 "支持组件状态、图聚合以及快照、图和说明列表的加载与降级策略。")

<a id="navigation"></a>
## 下探与深链流程

文件、符号和证据片段的下探统一转成共享 trail 帧；符号事件即使未携带 fileId，也会通过 symbolMap 补出所属文件后入栈。[统一下探目标转换 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L185 "说明文件、符号和片段如何解析并压入共享 trail。") 主视图和整个帧栈被编码进 URL hash，恢复时先还原页面，再重建 trail、修正人类可读标题并打开抽屉。[Hash 序列化与恢复 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L218 "支持主视图及 trail 深链的写入、恢复和当前帧定位流程。") 抽屉按 frame kind 分派到知识、模块、文件、符号或片段组件，因此各详情页只需发出 drill 事件，不各自维护导航栈。[Trail 抽屉的帧分派 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L371 "证明统一抽屉依据帧类型复用知识与各代码详情组件。")

<a id="boundaries"></a>
## 边界与降级行为

恢复标题时会优先使用文件名、符号名或模块标签，缺失实体则显示“文件”“符号”等类别名，避免把内部标识直接暴露给用户。[恢复帧的人类标题 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L165 "支持内部标识不直接作为可见标题以及缺失实体的退化标签。") 但 hash 中仍只保存 kind 与 id，部分帧附加的行号不会随 trail 序列化；恢复出的文件或符号若已不在当前图中，相应模板不会渲染详情。当前材料也只展示 `popstate` 监听，未证明手工修改 hash 时会触发恢复。
