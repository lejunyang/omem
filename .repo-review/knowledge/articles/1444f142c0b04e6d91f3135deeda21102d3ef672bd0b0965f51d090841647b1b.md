# 关键词检索与原始证据回溯

该模块以 SQLite 为统一检索基线，融合代码符号、全文、短关键词、记忆和知识正文等召回路径，同时把命中结果落回不可变的原始 fragment，并在可见性与时间过滤后完成融合和多样化排序。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 作用与证据边界

`KeywordRetrieval` 是统一检索端口的 SQLite 实现，用于让中文短词、代码标识符、已应用记忆和知识正文共同参与召回。源码以 `ORIGINAL` 条件排除派生 revision，输出保留 fragment、revision 与来源信息，使上层引用原始材料而不是把记忆或摘要当成独立事实。[原始证据过滤与检索实现入口 ↗](../../../apps/server/src/retrieval/keyword.ts#L16 "支持模块排除派生 revision，并将检索定位为始终返回原始证据的实现。") 这也落实了统一端口“结果必须回到不可变 fragment”的合同，并为后续替换检索后端保留稳定接口。[统一检索端口与固定证据合同 ↗](../../../apps/server/src/retrieval/port.ts#L1 "说明检索结果必须指向不可变 fragment，并允许后端在不改变调用方的情况下替换。")

<a id="source-flow"></a>
## 分词、召回与融合流程

查询先生成 ASCII 词、中文完整片段及过滤常见停用项后的重叠二元组；三字及以上词进入 trigram FTS，短词通过转义后的 `LIKE` 匹配。[查询分词与中文二元组规则 ↗](../../../apps/server/src/retrieval/keyword.ts#L210 "支持 ASCII 词、中文完整词、重叠二元组及停用二元组过滤的分词行为。") 搜索随后汇总代码符号、全文、短关键词、记忆证据和知识证据五条分支，并在每条分支中按 fragment 去重、执行资格过滤，再用倒数排名融合不同量纲的分数。[五路召回与倒数排名融合 ↗](../../../apps/server/src/retrieval/keyword.ts#L97 "支持五类候选分支、分支内资格过滤和去重，以及 reciprocal rank fusion 的实现流程。") 代码符号分支只有在 AST 投影表存在时才运行，并从查询提取合格名称，对符号名或限定名执行小写后的精确匹配；此前仅以融合分支范围支持该结论的引用已被本段更精确的实现范围替代。[代码符号表检查与名称精确匹配 ↗](../../../apps/server/src/retrieval/keyword.ts#L123 "支持仅在代码符号表存在时运行，并按符号名或限定名进行规范化精确匹配的论断。") 记忆命中通过 evidence set 回查原始 fragment；知识正文也只作为导航，并在依赖有效、引用范围和引文均可校验时返回覆盖到的原始片段。[知识正文回溯原始片段 ↗](../../../apps/server/src/knowledge/retrieval.ts#L33 "说明派生知识仅用于导航，依赖和引用校验通过后才映射回原始 fragment。") 融合结果最后由排序器应用来源权重、代码符号加权与可选的 MMR 冗余抑制，排序不会改变证据身份、可见性或来源。[融合结果的多样化排序 ↗](../../../apps/server/src/retrieval/ranking.ts#L3 "支持来源权重、代码符号加权、MMR 冗余惩罚以及排序不改变证据身份的行为。")

<a id="boundaries"></a>
## 过滤边界与失败方式

来源结果上限为 1–100。时间范围比较使用 revision 的捕获时间；宿主可见性回调与时间检查一起在各分支进入融合前执行，因此不可见候选不会参与最终排名。[捕获时间与可见性合同 ↗](../../../apps/server/src/retrieval/port.ts#L35 "界定 timeRange 使用 revision 捕获时间，并要求可见性策略在最终排序和截断前应用。") [融合前资格过滤 ↗](../../../apps/server/src/retrieval/keyword.ts#L53 "支持实现按 revision 创建时间检查范围，并在每条召回分支融合前调用可见性回调。") 记忆搜索只扫描 active 记录，且仅当项目关联被确认可信时才按项目排除，否则保持工作区范围召回。[活动记忆与可信项目过滤 ↗](../../../apps/server/src/retrieval/keyword.ts#L146 "支持仅搜索 active memory，并只在项目关联可信时执行项目范围过滤。") 无可用分词时，来源与记忆检索都会直接返回空数组；缺少代码符号表时符号分支为空，缺少知识表时知识分支为空。此前把这些不同路径统一归于 `readEvidence` 的结论已被替代；`readEvidence` 实际只负责按指定 fragment 读取证据，或默认返回 revision 中 ordinal 最小的一段。[空查询词的返回行为 ↗](../../../apps/server/src/retrieval/keyword.ts#L53 "支持来源检索在分词结果为空时立即返回空数组。") [证据读取与符号表缺失行为 ↗](../../../apps/server/src/retrieval/keyword.ts#L29 "区分 readEvidence 的实际职责，并支持代码符号表不存在或无合格名称时返回空结果。") [知识表缺失行为 ↗](../../../apps/server/src/knowledge/retrieval.ts#L8 "支持无查询词或缺少知识表时知识候选路径直接返回空数组。") 当前记忆证据路径会直接读取 `evidence_set` 并执行 `JSON.parse`，材料未展示异常捕获，因此坏数据的预期失败策略仍需确认。[记忆证据集合解析流程 ↗](../../../apps/server/src/retrieval/keyword.ts#L81 "支持当前流程直接读取 evidence_set、执行 JSON 解析并按引用回查原始 fragment，说明异常策略为何仍不确定。")
