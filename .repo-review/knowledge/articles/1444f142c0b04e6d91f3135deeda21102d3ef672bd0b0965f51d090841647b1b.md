# 基于 SQLite 的混合关键词检索

融合全文、短关键词、活跃记忆和派生知识四条召回路线；全文、短词与记忆回溯明确约束到当前 head 的原始 revision，知识路线在本文件中仅统一接受时间和可见性过滤，其证据边界仍待核验。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence"></a>
## 已验证的原始证据边界

全文路线连接 `sources.head` 指向的 revision，并用 `ORIGINAL` 排除 producerKind 或 context 标记为派生的内容。[原始 revision 判定条件 ↗](../../../apps/server/src/retrieval/keyword.ts#L15 "支持 ORIGINAL 对派生 producerKind 和 context 标记的排除规则。") [当前 head 的全文召回 ↗](../../../apps/server/src/retrieval/keyword.ts#L52 "支持全文检索连接 sources.head、应用 ORIGINAL 条件，并执行时间与可见性过滤。") 短关键词路线同样连接当前 head 并应用该条件。[当前 head 的短关键词召回 ↗](../../../apps/server/src/retrieval/keyword.ts#L122 "支持短关键词通过转义 LIKE 查询当前 source head，并应用 ORIGINAL 条件。") 活跃记忆命中不会把记忆正文当作独立证据，而是沿应用回执或记忆 revision 的证据集合回查当前 head 上的原始 fragment。[记忆证据回溯与四路融合 ↗](../../../apps/server/src/retrieval/keyword.ts#L80 "支持记忆路线回查当前 head 原始 fragment，以及四路候选过滤、去重和倒数排名融合。") 因而这三路具备明确的当前原始证据约束；知识路线由外部函数直接提供候选，本文件没有再次校验其 head 或 `ORIGINAL`，不能把前三路保证推广过去。

<a id="fusion"></a>
## 四路召回与融合

查询先分词并把结果上限约束在 1～100：长度至少三个字符的词走 trigram FTS5，短词走转义后的 `LIKE`。[当前 head 的全文召回 ↗](../../../apps/server/src/retrieval/keyword.ts#L52 "支持全文检索连接 sources.head、应用 ORIGINAL 条件，并执行时间与可见性过滤。") [当前 head 的短关键词召回 ↗](../../../apps/server/src/retrieval/keyword.ts#L122 "支持短关键词通过转义 LIKE 查询当前 source head，并应用 ORIGINAL 条件。") 全文、短词、记忆与知识四路候选统一经过时间范围和调用方 `visible` 过滤，再按 fragment 去重并用 reciprocal rank fusion 累加名次分，使每个片段在单条路线中最多贡献一次。[记忆证据回溯与四路融合 ↗](../../../apps/server/src/retrieval/keyword.ts#L80 "支持记忆路线回查当前 head 原始 fragment，以及四路候选过滤、去重和倒数排名融合。") 返回结果包含命中路线、摘要、revision、fragment 与来源元数据，但知识路线的当前性和原始性仍取决于外部实现。

<a id="scope_tokenization"></a>
## 范围规则与中文分词

记忆检索只遍历 active 记录；仅当查询携带可信项目标识且记忆明确绑定到另一项目时排除，未绑定项目的记忆仍在工作区可见。[可信项目范围过滤 ↗](../../../apps/server/src/retrieval/keyword.ts#L130 "支持仅用可信项目关联排除其他项目记忆，未绑定项目的记忆仍保持工作区可见。") 分词提取 ASCII token、中文完整串和重叠二元组，并过滤常见中文停用二元组，以兼顾精确短语与追问式短表达。[中文与 ASCII 查询分词 ↗](../../../apps/server/src/retrieval/keyword.ts#L194 "支持完整中文串、重叠二元组、ASCII token 及常见停用二元组过滤。") 这是启发式词法检索：没有有效词项时直接返回空，短词 `LIKE` 和内存扫描活跃记忆的成本会随数据规模增长。
