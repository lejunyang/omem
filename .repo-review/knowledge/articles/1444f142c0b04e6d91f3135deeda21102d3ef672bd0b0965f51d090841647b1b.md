# SQLite 关键词检索基线

以固定 fragment 和 active memory 为对象提供无 embedding 的统一检索端口，支持中英文分词、简易相关度、证据读取及谨慎的项目范围过滤。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="source-search"></a>
## 来源证据检索流程

`KeywordRetrieval` 是面向未来检索后端接口的 SQLite 基线，不依赖 embedding 或第三方引擎。`readEvidence` 可按 revision 与可选 fragment 精确读取固定片段；未指定 fragment 时返回 ordinal 最小的一项。[关键词后端与证据读取 ↗](../../../apps/server/src/retrieval/keyword.ts#L15 "支持无向量基线定位及按 revision/fragment 读取固定证据的说明。")

来源搜索把 limit 限制在 1–100，对每个 term 用转义后的 `LIKE` 查询当前 source head 下的 fragment，并按不同命中词累计分数，词越长权重越高；知识正文检索提供的 evidence candidate 也会并入结果。最终按分数排序，返回 snippet、revision、fragment 与 actor/time/source provenance。[来源 fragment 搜索与评分 ↗](../../../apps/server/src/retrieval/keyword.ts#L52 "说明逐词检索、去重计分、知识证据合并、排序和 provenance 输出。") 当前 fragment 没有持久化的可信项目关联，因此即使查询带项目上下文也不做项目过滤，避免把 application 或 conversationId 错当项目。

<a id="memory-tokenization"></a>
## 记忆范围与分词边界

记忆搜索只扫描 `status='active'` 的 head revision。只有查询同时携带 `project_id` 且 `project_trusted=true` 时，才排除明确属于其他项目的记忆；没有项目关联的记忆仍在 workspace 可见。正文目前以 JSON 字符串做大小写无关包含匹配，分数仅按命中的 term 长度累积，limit 被限制为 1–50。[Active memory 检索与项目过滤 ↗](../../../apps/server/src/retrieval/keyword.ts#L119 "支持只召回 active memory，并仅在可信项目条件下执行排除过滤的论断。")

分词保留 ASCII 单词；中文串既保留完整短语，也生成重叠二元组，同时过滤“这个、我们、可以”等高召回停用二元组。snippet 取第一个命中附近的定长窗口，没有命中时截取开头。[中英文分词与摘要窗口 ↗](../../../apps/server/src/retrieval/keyword.ts#L183 "解释 ASCII term、中文完整串与二元组、停用词及 snippet 生成规则。") 这是一种可解释但粗糙的基线：没有词频归一化、语义相似度或跨 revision 身份续接；`LIKE` 每词最多取 200 行，也可能使高频词结果被提前截断。材料未提供排序稳定性、转义字符或中英混合查询的测试。
