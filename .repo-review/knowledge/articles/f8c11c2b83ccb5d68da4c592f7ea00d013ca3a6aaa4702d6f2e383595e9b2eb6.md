# 实现文档体系：统一证据链、知识流程与 Code Wiki

说明实现文档如何围绕统一捕获与不可变证据链，记录知识整理、代码投影、共享阅读、验证进展及尚未完成的外部集成与架构边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责与设计背景

这一组实现文档的核心职责不是罗列功能，而是区分设计、已实现能力、验证结果和剩余限制。所有输入最终应落入 Capture、Source、Revision、Fragment；知识正文保存不可变修订，引用贴近论断，派生内容不会被重新当作独立原件。[正文与不可变证据合同 ↗](../../../docs/implementation/knowledge-pipeline.md#L3 "支持实现文档围绕固定引用、不可变知识修订及派生内容不成为独立证据展开。") Code Wiki 同样不是第二套知识库，而是这条证据链上的可重建代码投影：内部代码对象可以辅助导航，但正文、引用与检索仍锚定固定版本。[代码投影而非第二事实源 ↗](../../../docs/implementation/code-knowledge-design.md#L505 "支持 Code Wiki 是统一证据链上的可重建类型化投影，内部标识不得成为展示文本。")

<a id="flow"></a>
## 从输入到发布与阅读

手工、文件、Git、飞书、聊天和屏幕材料分别进入立即捕获或事件聚合入口；相同外部标识与相同内容幂等复用，变化产生新版本，链接只作为材料保存而不自动访问。[统一捕获与版本规则 ↗](../../../docs/implementation/inputs.md#L3 "支持捕获入口、载荷边界、幂等版本化以及链接不自动访问等输入规则。") 随后 KnowledgePipeline 运行材料分析和独立复核，宿主从固定范围复制引文，只有通过的章节才发布；仓库全量与局部生成只是同一流程的输入适配方式，索引重建不会再次调用模型。[分析、复核与仓库适配流程 ↗](../../../docs/implementation/knowledge-pipeline.md#L23 "支持独立复核发布门槛、用户回答回流、仓库全量或局部分析及索引重建边界。") 发布后的个人知识和仓库知识共用 Evidence Trail，可逐层进入章节、原始材料或代码目标，并恢复层级、滚动、焦点和深链；派生正文用于引导召回，最终仍返回原始 Fragment。[共享阅读与知识引导召回 ↗](../../../docs/implementation/knowledge-pipeline.md#L45 "支持个人知识和仓库知识共用递归阅读合同，并说明派生正文只用于导航到原始证据。")

<a id="progress"></a>
## 实现进展与验证强度

复审记录显示，代码正文和理解校验已改为读取同一批固定捕获版本，定位失败返回空而非伪造引用；启动与手动同步也已串联材料、代码投影和知识恢复。[固定快照与恢复链修复 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L5 "支持复审基线中代码正文、理解校验、知识恢复和构建发布流程的已修复事项。") 自动检查记录包括依赖冻结、类型检查、330 个测试、服务端与 Web 构建，以及真实 Vue/API/SQLite 下的三视口、多层引用、深链和焦点流程；但部分浏览器路径仍使用 fixture，模型语义校准也只是小型合成样本。[知识功能验证记录 ↗](../../../docs/implementation/knowledge-verification.json#L7 "支持依赖、测试、构建、浏览器流程及模型小样本校准的结果，同时界定 fixture 和外部集成边界。")

<a id="limits"></a>
## 边界、关联与后续方向

当前实现仍以本仓库和单用户 SQLite 为边界；跨文件类型感知调用、跨修订语义身份续接、嵌入检索和下游自动重核验尚未完成。模型说明属于派生资料，结构及引用存在性校验不能替代独立语义复核。[现存架构边界与验证结果 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L31 "支持单仓单用户、派生说明未充分语义复核、跨文件调用与检索限制，并将其与已有验证结果并列。") 因而这些文档共同形成一张演进地图：输入合同规定证据如何进入，知识流程规定如何复核和发布，Code Wiki 负责代码域投影，共享阅读器负责追溯，验证记录则限定哪些结论已经由退出码、浏览器或实机快照支持。
