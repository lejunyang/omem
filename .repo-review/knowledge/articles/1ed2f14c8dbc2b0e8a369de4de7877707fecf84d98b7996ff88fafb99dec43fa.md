# Web · 可追溯知识阅读与仓库评审接入

本专题说明 Web 端如何把知识文章、固定引用、原始材料和待核对问题组织为连续阅读流程，并区分个人知识 API 与仓库评审 API 的访问边界。当前已具备前端装配、请求竞态保护和深层 Trail 基础，但浏览器运行时行为、服务端写入语义及响应合同仍待验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 连续且可追溯的知识阅读

Web 端以主题正文为阅读起点，同时呈现材料覆盖、文章索引和显式分析入口；界面的“正在分析与复核”只表示前端取得运行状态，不能证明后台任务最终成功。[知识首页与分析入口 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L19 "支持材料覆盖、主题阅读、文章索引、分析请求和运行状态的前端职责。")

个人知识页是薄装配层：首页和活动阅读帧产生的导航都进入共享 Trail，抽屉统一承接返回、跳层和关闭事件。[个人知识页 Trail 装配 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L1 "支持首页和活动帧共用共享 Trail 状态及抽屉导航。") 因而知识模块复用公共证据阅读路径，而不是另建一套层级导航。

<a id="flow"></a>
## 从知识正文到固定原文

正文按文档键及可选修订加载，以请求代次防止旧响应覆盖新页面；页面展示分节 Markdown、来源状态与模型信息，并挂载待核对问题。只有可操作引用才会生成包含固定文档修订与引用键的 citation 帧。[知识正文加载与引用导航 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L10 "支持请求代次控制、来源状态与模型信息、分节正文、待核对问题装配及可操作引用生成固定 citation 帧。") 帧分派器解析该引用，展示关系和理由，再打开指定文章章节或携带 digest、起止行的原始材料。[知识帧与固定引用分派 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L9 "支持引用解析、关系说明、不可用状态，以及文章和材料目标的差异化定位。")

材料阅读器区分当前与历史版本，并在代码查看器、Markdown 和图片之间分派；相对内部链接会转换为材料键，重新进入统一导航。[原始材料阅读与关联导航 ↗](../../../apps/web/src/knowledge/KnowledgeSource.vue#L15 "支持版本标记、代码与 Markdown 分派、引用行展示及内部链接回到统一导航。") 用户也可向问题回答或待办端点发起请求，但现有材料只证明前端 POST、提示和刷新，不能证明服务端已经持久化或具备失败回滚。[待核对问题交互 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L5 "支持问题筛选、回答与待办请求、状态提示和重新加载，同时限定当前只能确认前端行为。")

<a id="boundaries"></a>
## 共享 Trail、双 API 边界与限制

Trail 以 `kind + id` 联合身份检测循环；渲染栈追加时不截断，`MAX_TRAIL=200` 是 URL 持久化预算。[共享 Trail 身份与深度预算 ↗](../../../packages/ui/src/trail.ts#L1 "支持帧的可序列化结构、联合循环检测、URL 深度预算及不截断的渲染栈追加行为。") 现有测试覆盖十二层链、五层钻取和回到既有层级，但未覆盖 URL 序列化、滚动恢复及真实抽屉交互。[Trail 深层导航测试 ↗](../../../apps/web/src/codewiki/trail.test.ts#L21 "支持十二层不截断、五层钻取、循环定位和切片回退的已覆盖行为。")

个人知识请求从会话存储读取令牌，并在令牌存在时附加 Bearer 认证。[个人知识 API 会话认证 ↗](../../../apps/web/src/knowledge/api.ts#L6 "支持个人知识客户端读取会话令牌，并在令牌存在时为请求添加 Bearer Authorization 头。") 仓库评审客户端则声明服务绑定 loopback、接口位于 `/api/review/*` 且不发送授权头。[仓库评审 API 访问边界 ↗](../../../apps/web/src/review-api.ts#L1 "支持评审客户端面向 loopback、使用 `/api/review/*` 且不发送授权头的边界说明。") 资料、检索、同步及关系读取由各自接口实现，[评审资料、关系与同步接口 ↗](../../../apps/web/src/review-api.ts#L188 "支持来源、修订、片段、检索、同步、代码路径材料及关系读取的具体接口范围。") 代码快照、结构图、符号、边和文件理解另走 `/code` 读取面，[代码图与文件理解读取 ↗](../../../apps/web/src/review-api.ts#L375 "支持代码快照、结构图、文件、符号、边和文件理解通过 `/code` 读取面的论断。") 结构化理解列表与详情也有独立入口。[结构化理解合同与详情入口 ↗](../../../apps/web/src/review-api.ts#L423 "支持结构化理解输出、复核信息、解析引用以及理解列表和详情读取入口。") 此前把访问边界、全部读取能力及校验方式压在同一引用上的表述已被替代：通用请求实际解析 JSON 后以 TypeScript 断言返回，没有在该处执行运行时 schema 校验。[评审通用 JSON 请求实现 ↗](../../../apps/web/src/review-api.ts#L174 "支持通用请求解析 JSON、转换失败响应，并以 TypeScript 类型断言返回成功结果；附近没有运行时 schema 校验。") Web 的严格类型检查纳入应用、共享 UI 与 contracts 源码，但 `noEmit` 表明生产构建仍由其他工具承担。[Web TypeScript 检查配置 ↗](../../../apps/web/tsconfig.json#L1 "支持严格检查、禁止直接输出以及应用、共享 UI 和契约源码的跨包检查范围。")
