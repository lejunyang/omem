# 查询变体控制与多路召回合并

该文件把 Agent 提供的查询变体整理成最多四条检索输入，并将各查询分支的命中按内容单元合并。合并时，同一路线只保留跨查询的最佳名次，查询次数单独留痕但不重复加权；结果还汇总命中范围和路线，再按路线级 RRF 分数排序。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_integration"></a>
## 解决的问题与接入位置

查询变体是调查 Agent 提供的阅读线索，不能取代原问题，也不能因为同一路线被多个改写命中就获得多份权重。这个文件用 `recallQueries` 控制变体，用 `mergeQueryRecall` 合并各次召回。参考 [查询变体定位 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L1 "说明变体只是阅读线索，不替代原问题，也不为同一路线取得独立投票。")

统一检索会先展开 `q.text` 与 `q.queryVariants`，对每条文本分别执行 `recall`；只有一个分支时直接使用结果，多个分支才合并，之后进入精确查询选择或重排。参考 [统一检索调用流程 ↗](../../../apps/server/src/retrieval/unified.ts#L728 "支持统一检索展开查询、逐分支召回、条件合并并继续选择或重排的流程。") 来源专用检索同样调用这两个函数，但分支内部走词面检索与符号检索。参考 [来源检索调用流程 ↗](../../../apps/server/src/retrieval/unified.ts#L1191 "支持来源专用检索复用查询展开和合并函数，并在分支内组合词面与符号结果。")

<a id="query_preparation"></a>
## 查询变体如何筛选

`recallQueries` 始终把原文本原样放在首位；变体会先去除首尾空白，再以 NFKC 归一化并转小写后的值判重。空字符串、超过 400 个字符的变体和重复项会被跳过，返回值最多四条。未传 `variants` 时只返回原文本。过滤规则不作用于原文本本身。参考 [变体筛选规则 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L3 "实现原文本保留、变体清理、归一化去重、长度过滤与总量上限。")

材料测试给出了一条代表性调用：原问题为“中文问题”，变体含带空白的同文、全角 `ＡＢＣ`、半角 `abc`、空串、401 字符文本及三个普通词。输出是 `中文问题`、`ＡＢＣ`、`four`、`five`；半角 `abc` 与已接纳的全角形式归一化后相同，后续的 `six` 则受四条总量上限约束。参考 [变体筛选示例 ↗](../../../apps/server/tests/retrieval-query-expansion.test.ts#L53 "用断言确认空白清理、NFKC 去重、超长过滤和最多四条的可观察结果。")

<a id="merge_mechanics"></a>
## 多分支命中的合并与计分

每个命中至少包含单元 ID、分数和路线，也可携带路线名次、查询分支名次及命中范围。参考 [召回命中结构 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L14 "界定合并函数所需的单元、分数、路线及可选追踪字段。") 合并函数以 `unit.id` 为键遍历所有分支。命中没有 `routeRanks` 时，以它在当前分支中的下标作为各路线名次；同一单元、同一路线跨查询只保留最小名次。`recallRanks` 仍用“查询序号:路线”记录各分支名次，便于追踪来源。参考 [路线名次合并 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L23 "支持按单元聚合、回退名次生成、同一路线取最佳名次及分支名次留痕。")

输出对象保留最佳路线名次更小的那份命中字段；名次相同时保留先出现者。路线取并集，命中范围按完全相同的 `start` 与 `end` 去重。传入的 `score` 会被路线级 RRF 重算为各路线 `1 / (60 + rank + 1)` 之和，最后按新分数降序排列。参考 [范围汇总与 RRF 排序 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L35 "支持命中范围去重、路线取并集、分数重算和最终降序排列。")

<a id="behavior_and_change_points"></a>
## 代表性结果与修改边界

测试中的三个分支都走 `bm25`：首个分支给 A 名次 0、B 名次 1，后续分支让 B 获得名次 0，第三个分支再次重复 B。合并后 A 与 B 都只有一条 `bm25` 路线且最佳名次都是 0，所以分数相同；B 的三次查询名次仍保存在 `recallRanks` 中。重复释义由此不会形成额外路线佐证。参考 [重复释义不增权 ↗](../../../apps/server/tests/retrieval-query-expansion.test.ts#L45 "测试断言表明重复查询只增加分支名次记录，不改变路线级合并结果与分数。")

需要调整输入规模或变体合法性时，可修改 `recallQueries` 的 400 字符与四条上限。需要改变合并身份、名次保留方式或计分公式时，则修改 `mergeQueryRecall` 中的单元键、最小名次逻辑与 RRF 常数。当前实现不按查询分支数量加权，也不沿用上游传入的分数。参考 [变体筛选规则 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L3 "实现原文本保留、变体清理、归一化去重、长度过滤与总量上限。") [路线名次合并 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L23 "支持按单元聚合、回退名次生成、同一路线取最佳名次及分支名次留痕。") [范围汇总与 RRF 排序 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L35 "支持命中范围去重、路线取并集、分数重算和最终降序排列。")
