# 查询变体控制与多分支召回合并

该文件先把原问题与候选变体整理成最多四条查询，再把各查询分支的命中按内容单元合并。变体会经过清理、长度检查和归一化去重；合并时，同一路线只采用跨查询的最佳名次，查询分支名次另行留痕，不因重复释义增加路线权重。结果还会合并路线与命中范围，并按路线级 RRF 分数降序排列。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_integration"></a>
## 解决的问题

这个文件负责两件事：把原问题和候选变体整理为有限的查询集合，再把各查询分支返回的命中按内容单元合并。查询变体只是调查时的阅读线索；原问题不会被替代，同一路线也不会因为多个改写命中而得到多份投票。参考 [查询变体的定位 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L1 "说明查询变体只是阅读线索，不替代原问题，也不为同一路线增加独立投票。")

`mergeQueryRecall` 在后续常规选择前完成合并。不同 `unit.id` 的候选各自保留为一项，同一 ID 的多次命中则收拢到同一结果中。参考 [候选与名次合并 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L21 "支持按单元聚合、缺省路线名次生成、路线最佳名次保留、查询分支名次留痕和基础命中选择。")

<a id="query_preparation"></a>
## 查询变体如何筛选

`recallQueries` 始终把原文本原样放在首位。判重时，原文本会先去除首尾空白，再做 NFKC 归一化并转成小写；这个处理只生成判重键，不改写返回的原文本。参考 [查询变体筛选 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L3 "实现原文本保留、变体清理、NFKC 与小写归一化判重、长度过滤及四条总量上限。")

每个变体先去除首尾空白，再用同样的归一化方式生成判重键。空字符串、超过 400 个字符的变体和重复项会被跳过，返回值最多四条；未传入 `variants` 时只返回原文本。长度与空值过滤不作用于原文本本身。参考 [查询变体筛选 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L3 "实现原文本保留、变体清理、NFKC 与小写归一化判重、长度过滤及四条总量上限。")

<a id="merge_mechanics"></a>
## 多分支命中的合并与计分

每个命中至少包含单元 ID、分数和路线，还可以携带路线名次、查询分支名次及命中范围。参考 [召回命中结构 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L14 "界定合并函数使用的单元、分数、路线以及可选名次和范围字段。") 合并函数以 `unit.id` 为键遍历所有查询分支。命中未提供 `routeRanks` 时，它在当前分支中的数组下标会成为所含各路线的名次；同一单元、同一路线跨查询只保留最小名次。`recallRanks` 以“查询序号:路线”为键记录各分支名次。参考 [候选与名次合并 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L21 "支持按单元聚合、缺省路线名次生成、路线最佳名次保留、查询分支名次留痕和基础命中选择。")

函数比较当前命中的最佳路线名次与此前累计的最佳名次。当前名次严格更小时，结果中的其他命中字段以当前项为基础；相同名次继续保留此前项。随后，路线取并集，命中范围按完全相同的 `start` 与 `end` 去重。输入的 `score` 会被路线级 RRF 重算：每条路线贡献 `1 / (60 + rank + 1)`，最终结果按新分数降序排列。参考 [候选与名次合并 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L21 "支持按单元聚合、缺省路线名次生成、路线最佳名次保留、查询分支名次留痕和基础命中选择。") [范围合并与 RRF 排序 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L35 "支持命中范围去重、路线并集、按路线名次重算 RRF 分数及最终降序排列。")

<a id="behavior_and_change_points"></a>
## 教学示例与修改入口

教学示例（由当前算法推导）：首个分支依次命中 A、B，二者都只有 `bm25` 路线；后两个分支各自再次命中 B。若这些命中没有预设 `routeRanks`，A 在首个分支的名次是 0，B 的三个查询分支名次依次是 1、0、0。合并后，A 与 B 的 `bm25` 最佳名次都是 0，分数同为 `1 / 61`；B 的三个查询分支名次仍分别记录在 `recallRanks` 中。重复查询没有给 B 增加第二条路线，也没有增加另一份路线分数。参考 [候选与名次合并 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L21 "支持按单元聚合、缺省路线名次生成、路线最佳名次保留、查询分支名次留痕和基础命中选择。") [范围合并与 RRF 排序 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L35 "支持命中范围去重、路线并集、按路线名次重算 RRF 分数及最终降序排列。")

需要调整输入规模或变体合法性时，可修改 `recallQueries` 中的 400 字符限制与四条总量上限。需要改变合并身份、名次保留方式或计分公式时，可检查 `mergeQueryRecall` 使用的 `unit.id`、最小名次逻辑和 RRF 常数。当前实现按路线的最佳名次计分，不按查询分支数量累加，也不沿用输入命中的原始 `score`。参考 [查询变体筛选 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L3 "实现原文本保留、变体清理、NFKC 与小写归一化判重、长度过滤及四条总量上限。") [候选与名次合并 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L21 "支持按单元聚合、缺省路线名次生成、路线最佳名次保留、查询分支名次留痕和基础命中选择。") [范围合并与 RRF 排序 ↗](../../../apps/server/src/retrieval/recall-queries.ts#L35 "支持命中范围去重、路线并集、按路线名次重算 RRF 分数及最终降序排列。")
