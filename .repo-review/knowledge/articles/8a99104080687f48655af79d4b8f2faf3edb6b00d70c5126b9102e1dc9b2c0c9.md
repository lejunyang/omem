# 角色运行的作业适配器

把标准耐久作业处理器调用转换为角色网关运行，并将成功结果及运行证据提交给作业仓储。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="flow"></a>
## 作业到角色运行

工厂注入固定角色、profile、作业仓储、可选托管工具以及按作业 ID 构造上下文的函数，返回标准 `JobHandler`。执行时先获取上下文，再把 worker 给出的取消信号和租约对应信息传给角色网关；领取、心跳和重试并不由这个适配器实现。[角色作业适配流程 ↗](../../../apps/server/src/agent-runtime/job-handler.ts#L9 "支持上下文构造、角色网关调用、取消信号和托管工具的传递。")[标准作业处理器合同 ↗](../../../apps/server/src/jobs/worker.ts#L18 "说明适配器遵循的作业租约、取消信号及返回值签名。")

<a id="persistence"></a>
## 结果提交与错误边界

网关成功后，处理器要求 trace 至少包含一个会话，并选取最后一个会话，以兼容输出修复产生多个会话的情况。随后以作业 ID 和 lease token 调用 `saveRoleOutput`，提交结构化结果、模型配置、各类摘要、指纹、usage 与完整 trace，最后向 worker 返回结果引用和用量。材料只能证明这里进行了一次保存调用，不能证明仓储内部具有事务原子性。[角色输出保存调用 ↗](../../../apps/server/src/agent-runtime/job-handler.ts#L28 "支持末次会话选择、租约绑定的保存参数和结果引用返回，同时限定不能据此推断仓储原子性。") 该函数没有捕获上下文构造、网关或保存错误，因此这些错误会向调用方传播；具体分类、重试或失败落库策略不由本文件证明。[处理器未捕获运行错误 ↗](../../../apps/server/src/agent-runtime/job-handler.ts#L18 "完整函数体没有 catch，支持错误向调用方传播，但不扩张为未展示的 worker 失败策略。")
