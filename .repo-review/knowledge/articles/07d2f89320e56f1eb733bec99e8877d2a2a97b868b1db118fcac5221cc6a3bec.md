# 关系核验输出合同

该 Schema 定义四类代码理解角色共享的 CodeUnderstanding.v1 结果外壳，约束必填信息、生命周期状态和可追溯字段。它能验证顶层结构与部分基础类型，但对流程、声明和证据引用仅有数组级约束；是否另有宿主侧元素校验仍待补证，但不阻碍对当前合同边界的判断。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="required_envelope"></a>
## 统一结果外壳与生命周期

合同禁止额外顶层属性，并要求结果携带职责、边界、流程、入口出口、风险、声明、节点与边引用、证据、未知项，以及模型和摘要等追踪信息。[CodeUnderstanding 必填信息 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/output.schema.json#L4 "支持结果必须包含理解内容、图引用、证据、未知项和生成追踪字段的论断。") `role` 枚举覆盖仓库画像、模块架构、符号解释和关系核验，`status` 则覆盖 seed、generated、verified、failed、rejected，表明这是多个角色共享的结果外壳。[角色与状态枚举 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/output.schema.json#L35 "支持该合同由四类角色共享，并定义五种结果生命周期状态。")

<a id="validation_depth"></a>
## 追踪约束与校验边界

置信度必须位于 0 至 1；prompt、schema 和 input 摘要均要求为 64 位小写十六进制字符串，并记录 seed 与外部核验元数据。[置信度与追踪字段 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/output.schema.json#L57 "支持置信度范围、摘要格式及 seed、外部核验元数据的结构要求。") 不过，`key_flows`、`claims` 与 `evidence_refs` 在本文件中只被规定为数组，未定义元素形状。[复杂数组的当前约束 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/output.schema.json#L46 "支持流程、声明和证据引用在此 Schema 中只有数组级约束的限制说明。") 因此当前 Schema 本身不能验证 claim 类型、流程内部结构或证据引用关系；此前将这一缺口视为阻塞项的结论已被替代，是否存在额外宿主校验应作为非阻塞补证事项。
