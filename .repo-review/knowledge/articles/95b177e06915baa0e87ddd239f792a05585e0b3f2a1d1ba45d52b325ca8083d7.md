# agent-runtime · 固定证据知识生产角色链

该专题呈现 agent-runtime 中材料分析、知识撰写与独立复核三类角色的合同化分工：前两者产出可追溯知识批次，复核者逐文档判断证据支持性。现有材料充分描述角色配置与静态格式，但不足以证明运行时编排、强制校验和发布门禁已经实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="roles"></a>
## 为什么拆分角色

这一组角色把知识生产拆成不同责任：材料分析者先区分文档陈述、实现事实和历史状态，避免把旧计划误写成现状；知识撰写者再围绕原因、机制、关联、进展与限制组织概念章节，并要求原始依据保持可追溯。[材料分析的状态区分要求 ↗](../../../packages/agent-runtime/roles/material-analyst/1/prompt.md#L1 "支持材料分析者需区分陈述、实现事实与历史状态，并禁止把旧计划写成已实现。")[知识撰写的概念组织目标 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/prompt.md#L1 "支持知识撰写者解释原因、工作方式、关联、进展和限制，并以原始依据维持可追溯性。") 独立复核者不代写正文，而是检查引用是否支持附近论断，以及时效、范围和约束是否准确；事实错误或无支持关系需要修订，明确保留的不确定性则可通过。[独立复核的职责与判定原则 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/skills/omem-knowledge-verifier/SKILL.md#L8 "支持复核者检查引用支持性、时效、范围和约束，并区分需要修订与可保留问题的草稿。")

<a id="contracts"></a>
## 如何工作与如何衔接

材料分析与知识撰写均输出 `KnowledgeBatch.v1`：文档由元数据、Markdown 章节、就地引用和结构化问题组成；引用可定位材料行范围或文章章节，`quote` 约定留给宿主从固定材料抽取。[知识批次的章节、引用与问题合同 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/output.schema.json#L48 "支持 KnowledgeBatch 文档由章节、可定位引用和结构化问题组成，以及 quote 由宿主抽取的约定。") 两个角色的清单都声明内联技能、无工具、会话不复用、不继承用户扩展以及相同预算，说明它们被设计成只消费宿主注入证据的隔离步骤。[知识撰写角色的隔离配置 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/manifest.json#L9 "支持 writer 绑定内联技能与 KnowledgeBatch 输出，并声明无工具、全新会话、不继承扩展和预算限制。")[材料分析角色的隔离配置 ↗](../../../packages/agent-runtime/roles/material-analyst/1/manifest.json#L9 "支持 analyst 采用与 writer 相似的技能绑定、输出合同、工具和会话隔离及预算配置。") 复核阶段使用不同的 `KnowledgeReview.v1`，按 `documentKey` 返回 `accepted` 或 `needs_revision`，并携带 issues 与 questions，从产物形态上形成“分析/写作—复核”的接口。[独立复核结果合同 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/output.schema.json#L9 "支持复核结果按文档给出二元判定、问题清单和结构化未决事项，形成与 KnowledgeBatch 不同的下游接口。")

<a id="progress_limits"></a>
## 当前进展、约束与关联

现有文件已经给出三类角色的提示、技能说明、角色清单和输出 Schema；其中材料分析与知识撰写的批次合同在字段结构上相同，便于前序子知识进入后续组织。[材料分析的知识批次合同 ↗](../../../packages/agent-runtime/roles/material-analyst/1/output.schema.json#L48 "与 writer 合同共同支持两类生产角色当前采用相同 KnowledgeBatch 字段结构，同时说明静态 Schema 的覆盖范围。") 但这些证据主要是静态声明：Schema 能限制字段形状，却不能独自保证目标全部覆盖、引用均在正文使用、行号属于授权范围，或引用在语义上真正支持论断。独立复核规范补充了语义检查原则，并要求问题指向可局部修正的位置。[复核中的语义错误处理 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/skills/omem-knowledge-verifier/SKILL.md#L10 "支持复核对范围错配、条件遗漏、计划冒充实现和不确定性肯定化进行修订判定，并要求给出局部修正线索。") 当前材料仍未展示角色实际编排、Schema 校验器、宿主提引、修订回流或发布门禁，因此不能将配置存在表述为这些运行能力已经完成。
