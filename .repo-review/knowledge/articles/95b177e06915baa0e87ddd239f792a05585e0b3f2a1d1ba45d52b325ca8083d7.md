# 固定证据驱动的知识角色与数据合同

材料分析、知识撰写与独立复核形成职责分明的知识处理设计：前两类角色用 KnowledgeBatch.v1 表达文章、章节、引用和未决问题，复核角色用 KnowledgeReview.v1 返回接受或修订结论。现有材料能够证明角色规范、清单和数据结构已经定义，但不足以确认宿主已完整执行角色编排、引文回填、语义复核和发布。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为什么拆分知识角色

项目材料可能同时包含需求、设计、研究、历史计划与实现陈述。材料分析角色首先负责区分这些语境，尤其避免把旧计划写成现有能力；固定子知识随后由撰写角色组织为面向读者的概念文章，但派生总结不能脱离原始依据成为新证据。参考 [材料分析的事实边界 ↗](9100b4732daccb4fa2cd83913a71c954e8a83e59342da496bb62bf13224fd228.md#purpose "该已复核子章节概括材料分析角色为何需要区分文档陈述、实现事实与历史状态。") [历史计划处理原则 ↗](../../../packages/agent-runtime/roles/material-analyst/1/prompt.md#L1 "原始提示明确要求区分材料类型和历史状态，并禁止把旧计划称为已实现。") [知识组织目标 ↗](3deca95c18c7331e92c5977d3676fc17363f22d024027cab065116756412b86d.md#purpose "该已复核子章节解释知识撰写角色需要回答作用、流程、关联、进展与限制。") [固定依据写作规则 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/prompt.md#L1 "原始提示规定引用子知识及原始依据，禁止把派生总结作为独立证据，并要求结构化记录疑点。")

独立复核角色承担另一项职责：它不代写正文，而是检查草稿引用能否支持附近论断，以及文章是否混淆时间、范围和关键约束。这样的拆分让“理解材料”“组织表达”和“判断能否发布”采用不同判断视角。参考 [独立复核职责 ↗](bb62e8df7ff8270cbbbabdf239371020f7f8f648436c553c5e3775224bed8cb8.md#purpose "该已复核子章节概括复核角色对引用支持性、时间、范围和约束的检查职责。") [复核输入与判断流程 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/skills/omem-knowledge-verifier/SKILL.md#L8 "原始技能规则说明复核以草稿和固定证据为输入、使用独立输出合同，并区分具体错误与待确认问题。")

<a id="roles"></a>
## 三个角色如何衔接

从合同意图看，三个角色形成以下分工；这是一种由现有规范推导出的职责关系，并非已经运行的编排证明。

| 角色 | 主要工作 | 结构化产物 |
| --- | --- | --- |
| 材料分析 | 从需求、设计、研究、进展和配置中形成带依据的子知识 | `KnowledgeBatch.v1` |
| 知识撰写 | 把固定子知识及原始依据组织为完整 Wiki 章节 | `KnowledgeBatch.v1` |
| 独立复核 | 对照固定材料或已复核章节检查草稿，指出实质性错误和未决事项 | `KnowledgeReview.v1` |

分析与撰写角色的清单都声明内联技能、统一的知识批次输出、无工具模式和不复用会话，以限制角色自行扩展证据范围；复核规范则要求逐篇核对草稿，并把具体错误与仍需补证的问题分开记录。参考 [知识撰写角色清单 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/manifest.json#L9 "支持撰写角色的内联技能、KnowledgeBatch 输出、无工具和会话隔离等声明性配置。") [材料分析角色清单 ↗](../../../packages/agent-runtime/roles/material-analyst/1/manifest.json#L9 "支持材料分析角色同样采用内联技能、KnowledgeBatch 输出及隔离策略。") [复核输入与判断流程 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/skills/omem-knowledge-verifier/SKILL.md#L8 "原始技能规则说明复核以草稿和固定证据为输入、使用独立输出合同，并区分具体错误与待确认问题。")

<a id="contracts"></a>
## 知识与复核合同如何保留追溯关系

`KnowledgeBatch.v1` 把每篇知识文档拆成元数据、Markdown 章节、引用和问题清单。引用不仅保存人读标签与关系，还能指向固定材料行或文章章节；`quote` 虽为必填字段，但合同说明应留空，由宿主按选定范围复制精确原文。这样可以把作者选择证据位置与原文抽取分开，不过该描述本身不能证明宿主已经完成回填。参考 [文章与引用结构 ↗](7e34e6bc930def3343d02b0e8eff1ca2141099f558a128802c8b57b5c72f162a.md#article_structure "该已复核子章节概括知识文档、章节、引用目标和宿主抽取引文之间的关系。") [固定证据定位合同 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/output.schema.json#L48 "原始 Schema 定义章节、引用关系、材料行号或文章章节目标，并说明 quote 由宿主抽取。")

无法确定的事项通过问题、原因、下一步、阻塞状态及关联引用键表达，避免在正文中升级为确定事实。复核侧的 `KnowledgeReview.v1` 则按文档返回 `accepted` 或 `needs_revision`，并携带问题说明与结构化待确认事项，从而为局部修订提供稳定接口。参考 [结构化未决问题 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/output.schema.json#L166 "原始 Schema 定义问题、原因、下一步、阻塞状态和关联引用键，并列出文档必填字段。") [逐文档复核结论 ↗](364d2c2aed49c672d6ef4bf3435f7aff5ef28b6bce5e9915287e35e884ac96d7.md#verdict-flow "该已复核子章节解释复核结果如何关联文档、表达二态结论并附带问题清单。") [复核结果数据结构 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/output.schema.json#L16 "原始 Schema 定义 documentKey、accepted 或 needs_revision 结论、issues、questions 及严格对象约束。")

<a id="status_limits"></a>
## 当前可确认的进展与限制

现有材料可以确认：分析与撰写角色已有版本化清单，知识批次与复核结果已有严格 JSON Schema，复核判断标准也明确要求关注会误导读者的实质性问题，并保留历史语境和不确定性。上层文章可以引用已复核子章节作可追溯概括，但新增事实仍需回到原材料。参考 [知识撰写角色清单 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/manifest.json#L9 "支持撰写角色的内联技能、KnowledgeBatch 输出、无工具和会话隔离等声明性配置。") [复核结果数据结构 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/output.schema.json#L16 "原始 Schema 定义 documentKey、accepted 或 needs_revision 结论、issues、questions 及严格对象约束。") [复核发布边界 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/prompt.md#L4 "原始提示规定以读者是否会被实质性误导为发布门槛，并说明历史材料与上层文章引用的证据边界。")

这些文件主要是**声明性合同**。材料未提供角色注册器、任务编排代码、真实运行 trace、引文回填结果或发布记录，因此尚不能据此确认“分析 → 撰写 → 独立复核 → 发布”已经端到端执行，也不能确认工具隔离、预算、跨字段引用一致性和失败处理都由宿主强制落实。复核角色的界面配置只进一步表明其预期使用固定材料，并不能替代运行证据。参考 [复核角色入口配置 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/skills/omem-knowledge-verifier/agents/openai.yaml#L1 "该界面配置仅表明复核角色的名称、固定证据定位和默认技能入口，用于说明其声明性边界。")
