# 实时助理端到端冒烟验证

该脚本以临时数据库和合成材料驱动真实 ACP 助理，验证记忆检索、原始证据引用以及任务创建、改期、完成的完整行为链，并将过程报告持久化；它是有外部模型依赖的现场检查，不等同于隔离单元测试。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_setup"></a>
## 验证目标与隔离环境

脚本解决的是“各组件单独可用，但真实模型参与后整条助理链是否仍能工作”的验收问题。它加载服务器配置，在系统临时目录创建独立 Store，并明确使用合成材料，避免写入用户数据库或发送外部消息。随后从 `traex` 基础配置选择现场 profile，并强制模型为 `gpt-5.6-sol`，因此这是一项依赖真实 ACP 能力、认证和模型可用性的现场冒烟检查。[现场模型与临时环境初始化 ↗](../../../scripts/live-assistant-smoke.ts#L13 "支持脚本使用合成材料、临时 Store、真实 profile，并强制指定现场模型的说明。")

测试先捕获一条英文 CircuitBreaker 事实，再把 Store、MemoryService、KeywordRetrieval 与 AcpAssistantModel 注入 AssistantRuntime；会话固定为 owner、web、private，时区为上海，单轮超时三分钟。这里的跨模块关系有直接构造依据，但各模块内部实现不在本材料完整范围内。[助理运行时组装与私有会话 ↗](../../../scripts/live-assistant-smoke.ts#L23 "支持 Store、记忆、检索、ACP 模型和 AssistantRuntime 的显式装配关系及会话边界。")

<a id="behavior_flow"></a>
## 核心行为链与断言

统一的 `turn` 包装器向同一会话发送中文请求，要求输入消息引用处理状态为 `done`，并把回答、工具动作和选中证据写入报告。第一轮询问英文材料中的熔断参数：断言选中证据包含刚捕获的原始 fragment，并检查回答同时表达“7 次”和“41 秒”，从而验证跨语言召回、证据落点与答案内容，而不只验证模型返回了文本。[跨语言记忆召回断言 ↗](../../../scripts/live-assistant-smoke.ts#L29 "支持统一轮次执行、处理完成状态、原始 fragment 证据及参数答案断言。")

随后三轮依次要求创建英语复习任务、将其改期、再标记完成。脚本直接检查任务数量、上海本地时间换算后的 UTC 截止时间，以及最终 `done` 状态，覆盖了自然语言到结构化任务写操作的连续上下文流程。[任务创建、改期与完成断言 ↗](../../../scripts/live-assistant-smoke.ts#L39 "支持连续对话驱动任务写操作，以及 UTC 截止时间和完成状态的行为断言。")

<a id="reporting_limits"></a>
## 结果记录、清理与边界

成功时报告标记为 `passed`；任何异常都会记录错误并设置非零退出码。无论结果如何，脚本都把带时间戳、模型配置及逐步行为的 JSON 写入配置数据目录下的 verification 目录，然后关闭 Store 并递归清理临时工作区。[失败传播、报告输出与资源清理 ↗](../../../scripts/live-assistant-smoke.ts#L46 "支持脚本通过退出码表达失败、持久化验证报告并清理临时 Store 的说明。")

该检查只断言一个固定事实问答和一条任务的创建、改期、完成；没有覆盖删除、并发更新、权限拒绝、无证据回答、时间歧义、模型不可用或超时后的具体退化表现。它还只检查证据集合含目标 fragment，没有断言最终自然语言中的可见引用格式；报告写入真实配置目录，也意味着“无用户数据库写入”不等于完全无持久化副作用。[当前冒烟场景的断言范围 ↗](../../../scripts/live-assistant-smoke.ts#L31 "通过脚本现有的固定问答、任务断言和报告位置界定已覆盖行为与尚未覆盖的异常、权限及引用展示边界。")
