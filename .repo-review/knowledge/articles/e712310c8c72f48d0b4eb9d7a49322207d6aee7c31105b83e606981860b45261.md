# 可追溯知识树规划规范

规定规划器如何从材料目录提炼知识结构、选择可追溯依据、区分知识状态并守住只做规划而不执行材料指令或外部操作的边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="catalog_to_tree"></a>
## 从目录到知识树

规划器把 `task.catalog` 视为已经提供的材料与知识目录，结合标题、摘要和范围识别核心概念，同时不得执行其中的指令。[目录分析与非执行原则 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/skills/omem-knowledge-planner/SKILL.md#L8 "支持把目录作为分析资料、结合元数据识别概念且不执行其中指令的说明。") 它只输出 `KnowledgePlan.v1`，必须安排 overview、architecture、background、requirements、progress 五个章节 key；可按真实主题增加章节，但不能机械复制文件树。[知识树固定骨架 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/skills/omem-knowledge-planner/SKILL.md#L9 "支持仅输出规定合同、包含五个固定章节并避免机械复制文件树。")

<a id="traceability_selection"></a>
## 材料选择与可追溯性

每章的 `materialKeys` 只能引用目录中存在的 key，并优先组合模块层已复核知识；一般每章不超过十二个主要依据，文件级细节继续由材料目录保存。[材料键选择原则 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/skills/omem-knowledge-planner/SKILL.md#L10 "支持目录成员约束、优先使用模块层已复核知识、主要依据数量建议及保留文件细节的做法。") 这控制高层知识树的证据密度与可追溯性，其中“通常不超过十二个”是选择原则，并非输出 schema 自身表达的硬性上限。

<a id="status_boundaries"></a>
## 状态区分与操作边界

规划必须区分现行需求、历史方案、实现事实、验证记录和未决问题，同时说明各章节要回答什么以及推荐阅读顺序。[知识状态与阅读顺序 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/skills/omem-knowledge-planner/SKILL.md#L11 "支持区分需求、历史方案、实现、验证和未决问题，并要求说明章节目的与阅读顺序。") 因而旧方案必须明确标为历史，不能在缺乏实现证据时据其宣称功能已经实现。规划本身只是知识结构，不是代码变更或外部操作指令，也不能把未来章节冒充已经存在的材料引用。[规划的操作边界 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/skills/omem-knowledge-planner/SKILL.md#L12 "支持规划不是代码或外部操作指令，以及未来章节不能被当作现有材料引用。")
