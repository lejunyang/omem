# 可配置的代码理解模型适配端口

把显式选择的 ACP、CLI 或 HTTP 传输统一为代码理解模型端口；默认关闭模型，并明确预算传递和模型身份标记在不同传输间的能力差异。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="boundary"></a>
## 默认关闭、溯源与身份边界

该模块只适配既有模型传输，不自行推理，也不读取环境变量、凭据或个人配置；宿主未传配置或选择 `none` 时返回 `null`，显式配置损坏则抛出专用错误。[模型适配器职责边界 ↗](../../../apps/server/src/code/understanding-model.ts#L1 "支持默认不启用模型、不读取秘密、不主动调用以及显式错误不静默降级的设计。") 模型标识并非总能证明实际模型身份：ACP 与 CLI 使用显式 `model`，缺失时分别回退为传输标签 `acp`、`cli`；HTTP 优先采用响应模型名，其次显式配置，二者都缺失时回退为 `http`。这些回退值只能视作传输类型标签，替代此前“模型标识均来自响应或显式配置”的不完整结论。[ACP 与 CLI 执行路径 ↗](../../../apps/server/src/code/understanding-model.ts#L80 "支持 ACP 传递生成预算、CLI 未使用请求预算，以及两者在缺少显式模型时返回传输标签的结论。")[HTTP 模型适配 ↗](../../../apps/server/src/code/understanding-model.ts#L125 "支持 HTTP 请求格式、错误处理、文本提取、未使用请求预算及模型名回退顺序。")

<a id="acp-cli"></a>
## ACP 与 CLI 适配

ACP 和 CLI 都要求显式命令，并构造成包含模型、effort、参数、固定上下文字符上限和请求超时的统一 Agent profile。[传输配置与 Agent Profile ↗](../../../apps/server/src/code/understanding-model.ts#L24 "说明显式命令、模型、effort、超时和固定上下文字符上限如何进入统一 profile。") ACP 会收集流式文本，并把本次生成预算换算为输出字符限制，同时传入上下文预算；CLI 也收集文本和响应取消信号，但其 `run` 分支没有接收或继续传递请求预算。两者默认工作目录都位于 repo-review 的隔离运行目录。[ACP 与 CLI 执行路径 ↗](../../../apps/server/src/code/understanding-model.ts#L80 "支持 ACP 传递生成预算、CLI 未使用请求预算，以及两者在缺少显式模型时返回传输标签的结论。")

<a id="http"></a>
## HTTP 协议与失败条件

HTTP 模式要求明确 endpoint，以 JSON POST 发送 prompt 和可选模型，并透传取消信号。非成功状态、响应缺少非空 `text` 或 `content` 都会抛出不可用错误。[HTTP 模型适配 ↗](../../../apps/server/src/code/understanding-model.ts#L125 "支持 HTTP 请求格式、错误处理、文本提取、未使用请求预算及模型名回退顺序。") 当前请求未携带 `GenerationBudget`，模块内也未实现鉴权头、重试或服务能力发现；因此 HTTP 的上下文和输出限制只能依赖端点自身，不能据此宣称与 ACP 等价。
