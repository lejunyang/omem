# 仓库评审环境的 Vite 子进程

该脚本为 dev:review 单独启动 Vue 前端开发服务器，隔离个人后端代理配置，支持可配置端口、端口冲突失败和受控退出；其与上层编排器的具体启动、清理及退出码传播关系仍需结合对应源码与集成测试确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决的问题与运行边界

该脚本用于为仓库评审环境建立独立的前端开发服务配置。它刻意不读取 `apps/web/vite.config.ts`，以免沿用指向个人后端 4317 端口的 `/api` 代理，而是在脚本中配置评审 API 代理和严格端口策略。脚本被设计为由 `scripts/dev-review.ts` 直接作为 Node 子进程启动，背景之一是便于上层编排器在 Windows 上终止整个进程树。[评审 Vite 子进程的设计背景 ↗](../../../scripts/dev-review-vite.ts#L1 "支持脚本绕过个人 Web 代理配置、为评审环境提供独立代理，并作为直接 Node 子进程便于 Windows 进程树清理的论断。")

<a id="startup"></a>
## 启动与请求流程

启动时从 `REVIEW_WEB_PORT` 与 `REVIEW_API_PORT` 读取端口，未设置时分别使用 5181 和 5180；随后以 `apps/web` 为根目录，通过 Vite 和 Vue 插件创建仅监听 `127.0.0.1` 的前端服务，并将 `/api` 请求代理到同机评审 API。材料能确认使用 Vue 插件，但不能据此断言 Vue 的具体主版本。[Vite 服务与评审 API 配置 ↗](../../../scripts/dev-review-vite.ts#L12 "支持端口来源、应用根目录、Vue 插件、本机监听地址以及 /api 代理目标等启动流程，并界定材料只能证明使用 Vue 插件。")

`strictPort` 禁止 Web 端口冲突时自动改用其他端口。监听成功后，脚本优先输出 Vite 解析出的本地地址；若没有解析结果，则使用配置端口拼出回环地址。注释声称端口冲突产生的非零退出码会由上层编排器传播，但该跨文件行为尚未在当前材料中得到实现证据。[严格端口与监听地址输出 ↗](../../../scripts/dev-review-vite.ts#L25 "支持端口冲突不自动回退、开始监听以及输出解析后或回退本地地址的行为，同时表明退出码传播目前只见于注释。")

<a id="shutdown_limits"></a>
## 退出处理与验证限制

进程收到 `SIGINT` 或 `SIGTERM` 时，会请求关闭 Vite，并在关闭完成后以成功状态退出，形成显式的信号清理路径。[开发服务器信号关闭处理 ↗](../../../scripts/dev-review-vite.ts#L37 "支持收到中断或终止信号后关闭 Vite，并在关闭完成后以成功状态退出的清理流程。") 不过，Windows 上由编排器强制终止进程树时是否会进入该处理器、启动异常能否可靠传递，以及代理、端口冲突和端口释放是否已有真实集成测试覆盖，都不能仅由本文件确认。
