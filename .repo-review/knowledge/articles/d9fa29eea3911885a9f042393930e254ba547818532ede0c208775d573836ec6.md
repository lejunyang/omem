# AssistantRuntime 治理、恢复与渠道接入测试

该文件以临时 SQLite、脚本化模型和合成 Lark 事件验证助手运行时的持久化行为，包括任务治理、证据检索与隔离、跨轮上下文、取消与重试、待办生命周期及渠道幂等。修订后不再把现有群成员用例视为已证明来源归属拒绝，也不再把已完成 turn 的恢复用例解释为 receipt 防重复执行；这些仍需更有针对性的测试。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_fixture"></a>
## 测试目标与夹具边界

测试为每个用例创建独立临时目录、真实 `Store` 和加密凭据目录，并在结束后关闭数据库、删除资源，因此主要断言落在实际 SQLite 状态，而非纯协议桩；模型响应则由脚本化端口控制。[临时数据库与资源清理 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L23 "支持每例使用真实临时 Store、加密目录并在结束后清理资源的说明。") 捕获夹具默认附带已验证的 owner provenance，为后续可见性与写入治理测试提供身份基线。[owner 来源捕获夹具 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L43 "支持捕获材料默认携带已验证 owner provenance 的身份基线。")

文件直接组合助手运行时、记忆服务、关键词检索、Lark 收件箱和密钥存储，定位是服务内跨模块集成测试。[跨模块测试依赖 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L6 "支持该测试组合助手、记忆、检索、Lark 与密钥存储模块的定位。") 这并不代表真实模型 CLI、网络连接或外部平台已经完成端到端验收。

<a id="governed_tasks"></a>
## 任务写入治理与生命周期

显式的 owner 委派可以创建任务；普通咨询即使模型返回 `create_task`，服务端仍以 `not_explicit_task_intent` 拒绝并保持零写入，体现“模型提出、服务端裁决”。[显式委派与咨询拒绝 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L114 "支持显式任务可写入，以及普通咨询中的模型写请求因缺少显式意图被拒绝。") 不存在的 fragment 也不能作为第二轮任务依据。[不存在证据的二轮拒绝 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L581 "支持不存在的 fragment 不能为第二轮任务提供依据且保持零写入。")

此前“群成员材料因来源归属而不能转成 owner 待办”的确定结论应被替代：现有用例虽然准备了群成员 provenance，但实际输入是咨询句，且只断言零任务，没有核对具体拒绝原因，因此尚不能区分意图门槛与 owner provenance 门槛。[群成员材料用例的实际边界 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L313 "显示用例虽设置群成员 provenance，但使用非显式咨询输入且未断言拒绝原因，支持收窄此前来源治理结论。")

日常流程覆盖含时区截止时间的创建、改期、完成、版本递增、完成后提醒抑制及三次 application receipt，并确认用户可见结果采用服务端确认文本。[待办完整生命周期 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L867 "支持创建、改期、完成、版本变化、提醒抑制和 application receipt 的持久化断言。") 相同 transport event 的顺序重放会复用原 turn，避免第二次创建任务。[传输事件顺序幂等 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L362 "支持相同 transport event 顺序重放时复用原 turn 且不重复创建任务。")

<a id="retrieval_context_and_visibility"></a>
## 检索、上下文与可见性

中文短语可通过关键词检索召回相关片段，而明显无关的查询返回零证据；这两项行为由独立用例直接断言。[中文短语召回与无关查询 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L466 "直接支持中文短语能够召回材料、无关查询不产生证据的两项断言。") 两轮指代场景则证明首轮选中的 fragment 会进入后续工作上下文，使“按这个记一下”仍能引用既有证据并创建任务。[两轮指代与证据复用 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L547 "支持首轮选中证据进入第二轮工作上下文并为显式任务提供依据。")

群聊在未注入策略时默认不提供证据；注入策略后，仅当前群上下文材料可见，私人内容及其 fragment 标识不会泄漏。[群聊默认拒绝证据 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L238 "支持未注入可见性策略时群聊证据为空、私聊仍可召回的默认行为。")[注入策略后的群聊隔离 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L267 "支持策略仅放行当前群材料，并阻止私人内容及其标识泄漏。") 当首轮证据不足时，模型最多触发一轮查询扩展，首轮携带的变更请求不会执行，第二轮可借跨语言检索命中原始材料。[受限查询扩展 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L895 "支持只执行一轮额外检索、忽略首轮变更请求并命中跨语言原始材料。") 超长 fragment 会围绕语义命中裁成预算内的原文子串并供下一轮复用，但现有用例只覆盖单命中情形。[长证据语义窗口 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L914 "支持预算外语义命中被裁成包含目标信息的原文子串并在下一轮复用，同时界定当前仅有单命中覆盖。")

<a id="failure_recovery_and_lark"></a>
## 故障恢复、并发栅栏与 Lark 接入

模型不可用时 turn 保持 `pending` 且不产生伪答案或任务；普通异常则明确返回降级结果。[模型不可用与普通异常 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L194 "支持模型不可用时保留 pending，以及其他异常诚实降级且均不创建任务。") 新消息能够中断在途生成，超时也能结束无视 abort 的模型调用。[新消息中断与模型超时 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L402 "支持新消息取消在途 turn，以及超时终止不响应 abort 的模型调用。") 即使取消后的模型迟到返回创建任务请求，取消栅栏仍保证零写入。[取消后的写入栅栏 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L598 "支持模型在取消后迟到返回 create_task 时仍保持零任务写入。") pending turn 在模型恢复后可通过 `retryTurn` 完成并创建任务。[pending turn 重试恢复 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L652 "支持模型不可用留下的 pending turn 可在模型恢复后重试并转为完成。")

receipt 恢复能力的既有表述也需收窄：当前用例只证明一次成功执行产生真实 application receipt，且已经完成的 turn 在新运行时中不会进入恢复队列、模型不会再次调用；它没有构造“未完成 turn 已有 receipt”的恢复路径，因而不能证明恢复时依靠 receipt 防止重复应用。[已完成 turn 与真实 receipt ↗](../../../apps/server/tests/assistant-runtime.test.ts#L621 "支持成功执行产生 receipt 且已完成 turn 不会被恢复；同时明确该用例没有进入未完成 turn 的恢复路径。")

Lark 用例明确采用确定性合成事件而非真实 socket，并验证已绑定 owner 私聊进入助手并关联 outbox、陌生发送者被忽略、群聊提及时回复、普通群消息仅捕获，以及相同 event id 顺序重投不新增投递意图。[Lark 确定性路由与幂等 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L709 "支持无真实 socket 的测试边界，以及私聊路由、安全忽略、群聊提及、背景捕获和顺序重复事件幂等。") 这些结果只覆盖服务内路由和持久化接线，不证明真实平台鉴权、验签、网络重试或最终送达。
