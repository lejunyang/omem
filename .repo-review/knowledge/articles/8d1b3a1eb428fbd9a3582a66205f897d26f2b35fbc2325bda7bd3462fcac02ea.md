# 评审片段与代码关系追踪帧

展示不可变的需求、决策或调研片段，并沿正向和反向关系在原始材料与代码文件之间继续下探。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="loading"></a>
## 原文与关系装载

片段帧并行读取片段详情和关系列表；关系读取失败时降级为空，但片段本身失败会显示错误和重试入口。fragmentId 变化会重新装载。[片段和关系列表读取 ↗](../../../apps/web/src/codewiki/FragmentFrame.vue#L26 "支持并行请求、关系降级、片段错误处理及参数变化重载。") 成功后以经过处理的 Markdown 展示仓库文档原文，并显式标注为不可变原始材料，使它与后续派生关系保持来源区分。[不可变片段原文 ↗](../../../apps/web/src/codewiki/FragmentFrame.vue#L93 "证明详情标题、原始材料状态和 Markdown 正文的展示方式。")

<a id="relation-groups"></a>
## 双向关系视角

关系被分为三组：`implemented_by`、`required_by`、`tested_for` 用于从规则反查实现或测试；`implements`、`requires`、`decided_by`、`researched_by`、`tested_by` 用于继续追踪正向依据；其余关系单独保留。状态色区分 confirmed 与 candidate，显示文本使用“被实现”“决策依据”等人类标签。[关系分组与人类标签 ↗](../../../apps/web/src/codewiki/FragmentFrame.vue#L31 "支持正反向关系集合、状态色和可读关系名称。")

<a id="drill"></a>
## 从材料返回代码

打开关系时优先检查另一端的代码路径，并用当前代码图解析到文件帧；无法解析为文件时，若另一端有 fragmentId，再进入另一个片段。[关系目标下探 ↗](../../../apps/web/src/codewiki/FragmentFrame.vue#L79 "说明代码路径优先解析为文件，随后才尝试片段导航。") 界面展示反向实现/测试和正向依据的数量、摘要及证据说明，但关系面板本身没有根据 missing 状态或无目标情况显示禁用样式，点击无可解析目标时会静默停留。[正反关系界面 ↗](../../../apps/web/src/codewiki/FragmentFrame.vue#L105 "支持关系数量、摘要和证据展示，也反映面板未声明禁用条件。")
