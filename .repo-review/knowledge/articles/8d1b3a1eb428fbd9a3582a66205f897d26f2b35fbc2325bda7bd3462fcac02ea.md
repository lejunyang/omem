# 评审片段与代码关系追踪帧

展示决策、调研或需求片段的原文，并按正向、反向关系连接相关代码或其他证据片段。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 片段读取与关系分类

该帧同时请求片段详情和关系列表：详情失败会使整帧进入错误态，关系请求失败则退化为空数组。[片段与关系加载 ↗](../../../apps/web/src/codewiki/FragmentFrame.vue#L26 "支持详情为必需数据、关系列表可降级以及重载行为。") 关系被分为反向的“被实现、被依赖、覆盖测试”、正向的“实现、决策依据、调研依据、测试覆盖、依赖”，以及当前模板未展示的其他关系；状态只区分 confirmed、candidate 与中性色。[关系方向分类 ↗](../../../apps/web/src/codewiki/FragmentFrame.vue#L31 "说明反向、正向及其他关系集合和状态色调规则。")

<a id="drill"></a>
## 从证据回到代码

点击关系时优先检查另一端的 filePath，并通过当前代码图的文件表解析到文件帧；找不到代码文件时，才尝试使用 fragmentId 继续进入另一证据片段。[关系目标下探 ↗](../../../apps/web/src/codewiki/FragmentFrame.vue#L79 "证明关系首先尝试解析代码文件，随后才回退到证据片段。") 页面把反向关系解释为“这条决策影响了哪些代码”，无登记项时明确提示需要补充关联，而正向关系用于继续追踪该片段所依赖的材料。[片段原文和双向关系界面 ↗](../../../apps/web/src/codewiki/FragmentFrame.vue#L93 "支持原文标识、反向代码追踪、空状态及正向关系展示的说明。")

<a id="boundaries"></a>
## 原文与失效边界

片段正文以 Markdown 呈现，并标记为仓库文档不可变原文；可见关系名称经过中文映射，不直接展示枚举值。[片段原文和双向关系界面 ↗](../../../apps/web/src/codewiki/FragmentFrame.vue#L93 "支持原文标识、反向代码追踪、空状态及正向关系展示的说明。") 不过 `otherRelations` 虽已计算，模板没有消费；关系卡片也未依据是否确实可跳转来禁用，因此 filePath 与 fragmentId 都无法解析时仍可能看似可点击却无响应。
