# 知识引用范围的安全修复与局部复核

该模块为知识生成管线提供受限的引用行号修复：它只接受独立复核给出的既有材料引用范围，验证范围后在文档副本上修改并重新提取原文 quote；同时生成围绕受影响引用的章节摘录，供下一轮独立复核缩小检查范围。任何正文、来源或引用关系变化仍回到常规写作流程。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 只修正可机械验证的引用范围

知识文章完成全文独立复核后，可能出现一种很窄的问题：论断和来源都正确，但引用行号没有覆盖所需证据。该模块把这种情况交给宿主做确定性的范围修复；新增论断、更换来源或改变引用关系仍由正常写作流程处理。参考 [修复职责边界 ↗](../../../apps/server/src/knowledge/citation-repair.ts#L6 "说明宿主只能修改独立复核指定的精确范围，新增论断、来源或关系仍需正常写作。")

`rangeRepair` 也受复核合同约束：它只随 `needs_revision` 出现，每个引用键必须唯一，起止行必须是正整数且结束行不早于开始行。若范围未知，或正文、关系、新引用需要变化，复核者应省略这一字段。参考 [范围修复合同 ↗](../../../packages/contracts/src/knowledge.ts#L50 "支持 rangeRepair 的合法形态、唯一性约束和只能用于纯范围问题的条件。")

<a id="repair_flow"></a>
## 从复核结果到重新绑定原文

一条代表性调用从知识管线开始：全文复核为文档返回 `rangeRepair`，管线把当前文档、修复项和材料映射传给 `repairCitationRanges`；函数成功后，管线再次校验文档。参考 [复核阶段调用 ↗](../../../apps/server/src/knowledge/pipeline.ts#L264 "证明知识管线把复核返回的范围修复交给该函数，并对修复结果再次执行批次校验。")

```mermaid
flowchart LR
  A[全文独立复核给出范围修复] --> B[复制知识文档]
  B --> C[逐项校验引用与行号]
  C --> D[更新起止行]
  D --> E[从固定材料重新提取 quote]
  E --> F[局部独立复核]
```
参考 [范围修复实现 ↗](../../../apps/server/src/knowledge/citation-repair.ts#L9 "支持复制文档、逐项校验、更新行号、无变化返回 null 以及重新绑定 quote 的流程。") [原文 quote 绑定 ↗](../../../apps/server/src/knowledge/repository.ts#L85 "说明行号校验后如何从固定材料复制原文，并给出 quote 的长度上限。") [局部复核切换 ↗](../../../apps/server/src/knowledge/pipeline.ts#L304 "说明所有拒绝项均为范围修复时，管线修复文档并安排下一轮引用范围复核。")

函数先用 `structuredClone` 保留调用方传入的原文档，再逐项定位引用及其材料。它拒绝重复引用键、缺失引用或材料、非材料引用、非整数行号、越界或空文本；修复列表为空，或所有范围都与原值相同，也返回 `null`。有效范围写入副本后，`bindKnowledgeQuotes` 按新行号从材料文本复制 quote，最长保留 320 个字符。参考 [范围修复实现 ↗](../../../apps/server/src/knowledge/citation-repair.ts#L9 "支持复制文档、逐项校验、更新行号、无变化返回 null 以及重新绑定 quote 的流程。") [原文 quote 绑定 ↗](../../../apps/server/src/knowledge/repository.ts#L85 "说明行号校验后如何从固定材料复制原文，并给出 quote 的长度上限。")

<a id="scoped_review"></a>
## 局部复核保留相关论证上下文

`citationReviewExcerpt` 先保留正文中直接出现待修复引用标记的章节，再扫描这些章节内所有双中括号引用标记，并据此筛选引用表。这样，同一章节里支撑该论证的其他引用仍会随摘录交给复核者；其余章节不进入这次局部检查，文档的其他顶层字段则通过展开运算保留。参考 [复核摘录构造 ↗](../../../apps/server/src/knowledge/citation-repair.ts#L26 "支持按待修复引用选择章节，再保留这些章节中全部引用的摘录规则。")

管线只有在本轮所有拒绝结果都带 `rangeRepair` 时才进入这条快速路径。它修正范围并重新校验，下一轮将复核模式设为 `citation_ranges`，只传入上述摘录。参考 [局部复核切换 ↗](../../../apps/server/src/knowledge/pipeline.ts#L304 "说明所有拒绝项均为范围修复时，管线修复文档并安排下一轮引用范围复核。") 测试中的示例把 `c1` 从错误范围改到第 2 行；局部复核只收到 `behavior` 章节，最终文章仍保留两个章节，quote 变为第 2 行原文。参考 [精确修复示例 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L66 "测试验证范围修复不重写文章、局部复核只接收受影响章节，并重新提取正确行的 quote。") 若局部复核发现正文把“必须”写成“建议”这类实质错误，流程会转回知识改写与全文复核。参考 [实质错误回退 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L100 "测试验证局部复核发现正文问题后会回到知识改写和全文复核。")
