# osdk.toml：工具链、模型与任务入口

该文件集中声明项目的固定工具版本、pnpm 依赖策略、中文向量模型，以及开发、检查、检索和仓库知识处理任务。它记录的是配置意图与可调用入口，并不能单独证明任务已执行、模型资产已锁定或验证已经通过。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="runtime-and-checks"></a>
## 运行环境与基础检查

配置固定 Node 24.18.1、pnpm 11 与 Bun 1.4.2，并明确 TypeScript 脚本由 Bun 执行、已编译服务端及构建工具使用 Node；pnpm 依赖启用自动处理并允许从源码构建，osdk 指南则固定到 `lejunyang/one-sdk` 的特定修订。[工具版本、依赖策略与 osdk 指南 ↗](../../../osdk.toml#L1 "支持运行时版本、Bun 与 Node 的职责划分、pnpm 依赖策略及 one-sdk 指南固定修订的说明。")

常规任务覆盖开发、构建、测试、类型检查和启动；`check` 依次组合 typecheck、test 与 build，形成统一检查入口。不过这里只能确认命令已经声明，不能据此断言某次检查实际成功。[基础任务与统一检查 ↗](../../../osdk.toml#L19 "支持常规任务入口以及 check 组合类型检查、测试和构建的论断。")

<a id="model-and-retrieval"></a>
## 中文向量模型与检索流程

`memory-zh` 指向 BGE-small-zh-v1.5 的固定 Hugging Face 修订，只纳入分词配置、词表及量化 ONNX 等明确文件，并标记为 embedding/bge。这为模型身份与所需资产提供了配置基础，但材料没有展示实际下载结果、锁定产物或现有索引的向量身份。[中文向量模型配置 ↗](../../../osdk.toml#L52 "支持模型的固定来源修订、纳入文件清单以及 embedding 和 BGE 类型说明。")

检索侧提供索引任务及 `--review` 仓库隔离数据库选项；`review:verify --full` 的帮助文本说明其目标包括依赖、完整项目检查和真实中文检索。它们仍是任务定义而非运行报告，不能替代退出码、索引状态和 HTTP 检索结果。[检索索引与完整验证任务 ↗](../../../osdk.toml#L60 "支持仓库隔离索引选项以及完整验证任务所声明覆盖范围的说明。")

<a id="review-workflow"></a>
## 仓库知识生成与复核入口

仓库知识流程由显式任务编排：`review:build` 调用 Wiki 构建脚本，并可通过 `--generate` 为缺失描述启用配置模型；`review:analyze` 调用知识脚本。[Wiki 构建与分析脚本入口 ↗](../../../osdk.toml#L72 "支持 review:build 的 Wiki 脚本、生成选项及 review:analyze 调用知识脚本的论断。") `review:generate` 也调用同一个 `review-knowledge.ts`，而两项任务都声明相同的目标参数及 `--modules`、`--files-only`、`--retry` 选项，可选择处理范围、更新受影响模块与既有祖先、限制为原始材料分析或重试未完成模型工作。[分析与生成任务的共同参数 ↗](../../../osdk.toml#L86 "支持 review:generate 调用同一知识脚本，并证明 analyze 与 generate 均声明目标、模块更新、仅分析材料及重试选项。") 配置本身没有说明同脚本如何识别 analyze 与 generate 语义，因此不能推断二者运行行为必然不同。

此外，文件还配置了 ACP、角色、学习、流水线、Lark 和质量评估等 live/quality 入口，显示项目预留了分层验证路径；但没有随附退出码、trace 或产物，不能把入口存在视为能力已验证。[实时检查与质量任务入口 ↗](../../../osdk.toml#L32 "支持 ACP、角色、学习、流水线、Lark 和质量评估等分层任务入口已经配置的论断。")

<a id="configuration-boundary"></a>
## 配置可证明的边界

整体上，该文件把工具版本、模型来源和操作入口收拢到 osdk 配置中，使开发、知识处理与验证命令具有统一发现位置。[工具版本、依赖策略与 osdk 指南 ↗](../../../osdk.toml#L1 "支持运行时版本、Bun 与 Node 的职责划分、pnpm 依赖策略及 one-sdk 指南固定修订的说明。") 然而，模型是否已经下载并锁定、索引是否由当前模型修订生成，以及完整验证是否真实通过，都需要结合锁定产物、运行 trace、验证报告和实际检索结果判断。[中文向量模型配置 ↗](../../../osdk.toml#L52 "支持模型的固定来源修订、纳入文件清单以及 embedding 和 BGE 类型说明。") [检索索引与完整验证任务 ↗](../../../osdk.toml#L60 "支持仓库隔离索引选项以及完整验证任务所声明覆盖范围的说明。")
