# osdk 工具链与任务配置

配置声明 Node 与 pnpm 工具链、来自 one-sdk 的固定版本 osdk-guide，以及开发、仓库分析、局部生成、构建、检查、浏览器、live 和质量任务入口。它描述命令编排；任务是否成功及外部服务是否可用仍取决于实际执行记录。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="toolchain"></a>
## 工具与技能配置

项目基础运行时声明 Node `24.18.1` 与 pnpm 主版本 `11`，依赖管理启用自动处理并允许源码构建。[基础工具配置 ↗](../../../osdk.toml#L1 "支持 Node、pnpm 的版本要求，以及 pnpm 自动依赖和允许源码构建的设置。") `osdk-guide` 来自 `github:lejunyang/one-sdk`，固定到指定 ref，面向 universal 与 claude-code agent。[osdk-guide 来源配置 ↗](../../../osdk.toml#L10 "支持技能来自 one-sdk、固定 ref 以及适用 agent 范围。") 锁文件进一步解析出 pnpm `11.28.2`、冻结锁安装命令及原生锁摘要；因此可复现性应以锁文件和 `osdk deps --frozen` 的实际退出状态共同判断。[工具链锁定结果 ↗](../../../osdk.lock#L3 "支持解析后的 Node、pnpm 安装器版本、冻结锁命令和 pnpm 锁文件摘要。")

<a id="review-tasks"></a>
## 仓库分析与局部生成入口

任务表将 `review:analyze` 与 `review:generate` 都映射到 `scripts/review-knowledge.ts`，并另设 Wiki 构建、开发、测试、类型检查和启动入口。[核心任务映射 ↗](../../../osdk.toml#L16 "支持开发、Wiki 构建、知识分析与生成、构建、测试、类型检查和启动任务的命令映射。") 两者并非未定义的重复命令：流程文档说明 `review:analyze` 处理全部 Git 可见材料，而 `review:generate -- --target=<path>` 是同一流程的局部入口；`review:build` 只重建知识索引，不调用模型。[全仓分析与局部生成语义 ↗](../../../docs/implementation/knowledge-pipeline.md#L31 "解释两个同脚本入口的已知区别，并支持 Wiki 构建不重新调用模型。") 区别来自传入范围和使用方式，而不是两个不同脚本。

<a id="verification-levels"></a>
## 聚合检查与专项验证

`check` 明确依次运行类型检查、测试和构建；浏览器检查、ACP、角色、学习、pipeline、飞书 host live 及质量任务则各有独立入口。[聚合检查与专项任务 ↗](../../../osdk.toml#L26 "支持 check 的三个命令序列，以及浏览器、live 和质量验证具有独立任务入口。") 因而 `osdk run check` 不能代替这些专项 live 验证，配置中存在任务也不代表它已经执行成功或外部 CLI、网络服务可用。实际能力结论应引用对应命令的退出状态和行为断言。
