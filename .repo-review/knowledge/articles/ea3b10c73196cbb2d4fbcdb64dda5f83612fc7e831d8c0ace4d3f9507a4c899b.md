# omem 当前实施状态与历史边界

状态页顶部记录截至 2026-10-01 的最新检索、来源更新、助手和知识流程进展；页面后部保留较早切片，阅读时必须以带日期的新记录替代已经失效的旧结论。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

## 2026-10-01 最新闭环

中文语义检索已使用固定版 BGE-small-zh-v1.5 q8，并按模型身份隔离原片段分窗向量；四条中文同义问法的 top-1 为 4/4，但这只是小样本，reranker、ANN 和历史时点检索仍未实现。[中文语义检索最新状态 ↗](../../../docs/implementation/status.md#L1 "支持固定模型、按身份隔离的向量索引、小样本结果及仍未实现的检索能力。")

来源更新方面，`refresh_dependents` 已不再是占位：Capture 同事务记录失效范围，调度复用 extractor，独立 verifier 后由 MemoryService 原子更新同一记忆；失败或缺证据时继续保持 `needs_review`。[来源更新闭环最新状态 ↗](../../../docs/implementation/status.md#L3 "证明 refresh_dependents 已由占位演进为 extractor、独立 verifier 和原子应用闭环，并说明失败状态。") 日常助手也已验证补搜、事项上下文、时区及创建—改期—完成流程，但重复提醒、外部到期投递和取消状态仍有缺口。[日常助手最新状态 ↗](../../../docs/implementation/status.md#L5 "支持补搜、事项生命周期和时区能力已经验证，同时界定提醒、外部投递与取消缺口。")

<a id="knowledge-and-review"></a>
## 统一知识与仓库评审

通用知识流程现已接入共用正文与引用合同、八种角色、持久分析、独立复核、个人知识入口、多层引用、问题与待办，以及由知识导航回原始证据的召回。实际完成度应读取覆盖记录，失败、过期或未生成的材料不能计为完成。[通用知识流程当前能力 ↗](../../../docs/implementation/status.md#L9 "说明共用知识合同、角色、复核、引用、问题和召回能力，并支持以覆盖记录衡量完成度。")

repo-review 默认读取实际模型配置，环境变量仍可覆盖；启动默认直接重建 runtime，不依赖旧 `.repo-review/data/`，遗留历史仅在显式启用导入时进入。[review 配置与 runtime 重建策略 ↗](../../../docs/implementation/status.md#L11 "支持实际模型配置、默认直接重建 runtime 和显式遗留导入的运行方式。") 另一条较新的复审记录说明，启动会恢复材料、代码和版本化知识，但默认启动仍不调用模型。[启动恢复与模型调用边界 ↗](../../../docs/implementation/status.md#L13 "支持启动自动恢复既有材料和知识，同时默认启动不调用模型的独立断言。") 因而“重建或恢复既有派生状态”与“自动发起生成式处理”是两个不同阶段。

## 旧记录与当前事实的冲突处理

页面后部保留了 2026-09-29 的历史限制，其中仍称 `refresh_dependents` 会记录影响后主动抛出未实现错误。[已被替代的重核验限制 ↗](../../../docs/implementation/status.md#L94 "展示历史段落曾把 refresh_dependents 标为未实现，支持将其明确标记为被新闭环替代。") 这一结论已被页首 2026-10-01 的真实 extractor、verifier 与原子应用闭环取代。[来源更新闭环最新状态 ↗](../../../docs/implementation/status.md#L3 "证明 refresh_dependents 已由占位演进为 extractor、独立 verifier 和原子应用闭环，并说明失败状态。") 旧段落可用于追溯当时状态，但不能继续充当当前能力说明。

G15—G20 的验收记录证明对应测试路径均为 pass，同时清楚限定：G15 使用 fake transport，G20 的进程恢复使用同一数据库上的新 runtime 实例模拟，并非真实飞书网络或真实 kill/restart。[G15 至 G20 验收及限制 ↗](../../../docs/implementation/status.md#L85 "支持 G15 至 G20 的通过状态，并明确 fake transport 与模拟进程恢复的验收边界。") 因此这些测试支持代码合同，却不能外推为外部系统边界已经完整验收。

<a id="enduring-boundaries"></a>
## 仍有效的架构边界

跨批次仍有效的底座包括 TypeScript/Fastify/SQLite/Vue、统一 Capture、版本化材料与不可变片段、引用链、事务化通知，以及 ACP 与多种 CLI adapter。[跨批次基础能力 ↗](../../../docs/implementation/status.md#L122 "支持仍有效的技术栈、统一 Capture、版本化证据、通知及 ACP/CLI 基础。")

实现仍是个人单用户方案，不具备多租户 ACL、分布式事务或 pgvector；所有原件与回答可追溯，也不等于每项主张都已通过正式语义支持评估。[长期实现取舍 ↗](../../../docs/implementation/status.md#L132 "支持个人单用户、非多租户边界，以及可追溯不等于每项主张均已完成语义验证。") 对后部旧限制应逐条核对：与页首新进展冲突的结论已经被替代，其余边界则需结合当前代码和最新验证记录判断，不能整段沿用。
