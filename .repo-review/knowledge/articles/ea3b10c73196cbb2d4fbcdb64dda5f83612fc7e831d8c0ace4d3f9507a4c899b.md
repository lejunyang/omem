# omem 当前能力、验证状态与边界

omem 已形成统一的个人知识阅读、可追溯助理、事项跟进和来源更新闭环。当前能力应以状态页顶部的 2026-10-01 记录及当次覆盖报告为准，较早的测试数字和环境结论仅用于历史追溯。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="current-experience"></a>
## 当前解决的问题与使用方式

omem 将日常助理、知识库、原始材料和事项放在同一个个人应用中。参考 [统一个人应用入口 ↗](../../../docs/implementation/unified-knowledge-reading.md#L5 "直接支持日常助理、知识库、原始材料和事项位于同一应用中的结论。") 仓库材料与已复核文章进入个人库，用户先阅读完整知识文章，再通过段末引用查看固定原文或代码；界面升级不会自动提升旧文章质量，受影响正文仍须经过真实分析和独立复核。参考 [统一知识阅读 ↗](../../../docs/implementation/status.md#L1 "支持仓库材料和已复核文章接入个人库、完整文章阅读、段末引用，以及旧正文仍需重新分析复核的说明。")

日常助理支持持久会话，以及等待对象的创建、暂缓、重启和取消；提醒与发生记录原子提交，离线恢复时只补发一次。通用事项还支持带时间创建、改期、完成和重新打开。参考 [日常消息与等待跟进 ↗](../../../docs/implementation/status.md#L3 "支持持久会话、等待对象的暂缓重启取消、原子提醒记录及尚未接入的自动跟进能力。")、[通用事项闭环 ↗](../../../docs/implementation/status.md#L13 "支持带时间事项的创建、改期、完成和重新打开。")

自动监听回复、周期回顾、重复提醒和外部到期投递尚未接入，因此当前形态更适合作为可追溯的个人工作台，而不是完整的跨渠道自动秘书。参考 [日常消息与等待跟进 ↗](../../../docs/implementation/status.md#L3 "支持持久会话、等待对象的暂缓重启取消、原子提醒记录及尚未接入的自动跟进能力。")

<a id="knowledge-and-retrieval"></a>
## 知识更新与检索闭环

知识处理沿统一证据链运行：正文、引用、疑问及角色任务供不同 Capture 材料共用。当前已经接入持久分析、独立复核、问题与待办、正文多层引用，以及由知识正文导航回原始证据的召回；未通过、过期或尚未生成的材料不能计为完成。参考 [统一知识流程 ↗](../../../docs/implementation/status.md#L17 "支持共用知识合同、持久分析、独立复核、问题待办和知识引导原始证据召回，并说明未完成材料不计入完成。")

统一检索融合 SQLite FTS5/BM25、中文短词、活跃记忆原证据和知识正文引用，并通过 RRF 汇总结果。固定版本的中文向量模型在此基础上提供语义召回；模型缺失时保留词法结果并报告降级。现有四条中文同义问法结果只是小样本，不能代表整体检索质量。参考 [统一词法检索 ↗](../../../docs/implementation/status.md#L15 "支持 FTS5/BM25、中文短词、活跃记忆原证据与知识引用的 RRF 融合，也说明早期检索和 CLI 结论已经过时。")、[中文语义检索 ↗](../../../docs/implementation/status.md#L9 "支持固定中文向量模型、模型缺失时的降级行为、小样本验证结果及 reranker、ANN、历史查询等限制。")

来源更新也已形成实际闭环：Capture 在同一事务中记录失效范围，调度重新提取并交由独立角色复核，随后原子更新同一记忆。失败或证据不足时保持待复核，只有全部受影响记忆真正应用后才标记完成。参考 [来源更新闭环 ↗](../../../docs/implementation/status.md#L11 "支持失效记录、重新提取、独立复核、原子应用，以及失败保持待复核和后续能力缺口。")

<a id="evidence-and-limits"></a>
## 如何解读验证记录与历史状态

状态页顶部的 2026-10-01 更新是较新的能力记录。后文保留的“只有 LIKE”“本机无真实 CLI”等描述属于早期快照，已经被新的检索与 ACP 验证记录明确标为过时；历史记录可用于追溯，但不能与当前能力混作同一时点的结论。参考 [统一词法检索 ↗](../../../docs/implementation/status.md#L15 "支持 FTS5/BM25、中文短词、活跃记忆原证据与知识引用的 RRF 融合，也说明早期检索和 CLI 结论已经过时。")

当前仍有明确边界：中文语义检索尚未实现 reranker、ANN 和历史时点查询；周期性全库巡检、跨来源冲突自动修订与学习卡也未完成。参考 [中文语义检索 ↗](../../../docs/implementation/status.md#L9 "支持固定中文向量模型、模型缺失时的降级行为、小样本验证结果及 reranker、ANN、历史查询等限制。")、[来源更新闭环 ↗](../../../docs/implementation/status.md#L11 "支持失效记录、重新提取、独立复核、原子应用，以及失败保持待复核和后续能力缺口。") 现有 TypeScript 与 SQLite 部署面向个人单用户，不具备多租户 ACL、分布式事务或 pgvector，团队范围仍只是架构预留。参考 [单用户部署边界 ↗](../../../docs/implementation/status.md#L142 "支持当前实现面向个人单用户且不具备多租户 ACL、分布式事务和 pgvector。")

全库知识尚未完整，reviewed、stale、pending 和 failed 的实际数量必须读取当次 `coverage.json` 与 `verification.json`；页面中的旧文件数、测试数或索引规模不能替代当前覆盖报告。参考 [覆盖与验证口径 ↗](../../../docs/implementation/status.md#L7 "支持全库知识尚未完整、实际覆盖与失败须以当前报告为准，以及历史报告不累加通过率。")
