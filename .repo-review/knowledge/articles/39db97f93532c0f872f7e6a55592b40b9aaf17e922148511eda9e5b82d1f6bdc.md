# 非阻塞 Hook 转发入口

从标准输入接收受限 Hook 事件，规范化后先写入本地 spool，再以短超时尝试投递到捕获 API；异常和未送达只记录错误，不阻塞宿主。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="flow"></a>
## 输入、规范化与投递

入口从 stdin 累积 JSON，原始输入超过 300000 字节即拒绝。环境变量只能从默认 Hook 字段白名单中选择字段，字符上限被限制在 1000–200000；随后调用 `hookInput` 完成字段提取、脱敏、事件身份和 provenance 构造。[Hook 输入预算与字段配置 ↗](../../../apps/server/src/hook-forward.ts#L9 "支持 stdin 大小限制、字段白名单、字符预算和 hookInput 规范化流程。")

规范化结果先写入 `HookSpool`，目录可显式配置，否则位于数据目录下。flush 回调向 `/api/captures` 发送 JSON，可选附带 Bearer token，并设置 1500 毫秒超时；仅 HTTP 成功时读取捕获确认。[Spool 与捕获 API 投递 ↗](../../../apps/server/src/hook-forward.ts#L39 "说明先入 spool、API 地址、鉴权头、请求体、超时及 flush 调用，但不推断第二参数语义。")

<a id="failure-boundary"></a>
## 失败语义与模块关系

存在未送达结果时，入口只向 stderr 报告已排队重试；解析、配置、spool 或网络异常也由顶层 catch 记录，既不写 stdout 协议内容，也不把异常抛回宿主。[宿主非阻塞失败处理 ↗](../../../apps/server/src/hook-forward.ts#L64 "支持未送达或异常只写 stderr、宿主继续运行的行为边界。") 先前将 `flush(..., 3)` 解释为“最多处理次数”的结论已撤回：当前材料没有 `HookSpool` 的签名，无法确定该参数表示批量上限、重试次数还是其他约束。[Spool 与捕获 API 投递 ↗](../../../apps/server/src/hook-forward.ts#L39 "说明先入 spool、API 地址、鉴权头、请求体、超时及 flush 调用，但不推断第二参数语义。")

该文件只是可选 transport，不调用模型，也不直接写知识数据库。内容筛选依赖 connector profile；持久化原子性、退避、清理及后续 flush 触发机制依赖未提供的 spool 实现。[Hook 输入预算与字段配置 ↗](../../../apps/server/src/hook-forward.ts#L9 "支持 stdin 大小限制、字段白名单、字符预算和 hookInput 规范化流程。") [宿主非阻塞失败处理 ↗](../../../apps/server/src/hook-forward.ts#L64 "支持未送达或异常只写 stderr、宿主继续运行的行为边界。")
