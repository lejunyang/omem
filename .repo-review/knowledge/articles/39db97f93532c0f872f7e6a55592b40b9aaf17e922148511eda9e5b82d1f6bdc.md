# 不阻塞宿主的 Hook 转发入口

从标准输入接收受限 Hook JSON，经字段白名单转换后交给 HookSpool，并以短超时请求捕获 API；失败仅写标准错误且不向宿主抛出。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="input-profile"></a>
## 输入预算与捕获档案

该入口是显式启用的 Hook 传输适配器，不调用模型，也不写标准输出。它累计 stdin 数据并设置 300000 字节上限；环境变量选择的字段必须属于默认 Hook 白名单，字符预算则必须是 1000 至 200000 的整数。通过检查后，JSON 才会交给 `hookInput` 转成统一捕获对象。[Hook 输入限制与档案构造 ↗](../../../apps/server/src/hook-forward.ts#L1 "支持 stdin 字节预算、字段白名单、字符预算以及调用统一 Hook 转换器的流程。")

<a id="delivery"></a>
## Spool 调用与短时投递

捕获对象会先传给 `HookSpool.enqueue`，随后调用 `flush`；回调向 `/api/captures` 发送 POST，可选附带 Bearer token，并用 1500 ms 超时限制网络等待，非成功 HTTP 状态会抛错。调用点向 `flush` 传入第三个参数 `3`，但本材料没有给出该参数合同，不能断言它代表重试次数。[Spool 调用与捕获 API 请求 ↗](../../../apps/server/src/hook-forward.ts#L39 "说明 enqueue、flush 调用事实以及目标 API、认证头、请求超时和响应处理；不推断未提供的 spool 合同。") 若结果含未送达项，代码只写 stderr；顶层异常同样被捕获并报告“queued or rejected”，不会继续抛给宿主。至于 enqueue 是否已可靠落盘、失败项是否保留以及如何退避或去重，需由 spool 实现证明。[失败不阻塞宿主 ↗](../../../apps/server/src/hook-forward.ts#L64 "支持未送达结果与顶层异常仅写标准错误、宿主继续运行的边界。")
