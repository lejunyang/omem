# Hook 捕获转发入口

这是一个显式启用的标准输入转发器：它限制输入规模与配置，经 hookInput 生成捕获对象，先写入本地 HookSpool，再以短超时提交到捕获 API。投递失败会记录到标准错误；代码提示未投递项已排队重试，但现有固定材料不足以验证记录是否始终保留以及后续重试如何触发。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-input"></a>
## 作用与输入约束

该入口用于把外部 hook 事件送入 omem，同时保持宿主的标准输出协议不被捕获日志干扰；文件声明其不调用模型、不写标准输出，并以捕获失败不阻塞宿主为设计目标。[Hook 转发器设计边界 ↗](../../../apps/server/src/hook-forward.ts#L1 "支持该入口不调用模型、不写标准输出，并以捕获失败不阻塞宿主为设计目标的说明。")

处理流程在 `try` 中逐块读取标准输入；累计读取量超过 300000 字节时抛错，此判断发生在读到导致越界的整个 chunk 后。随后代码把请求字段限制在默认 profile 的字段集合内，并要求最大字符数为 1000～200000 的整数。[输入预算与配置校验 ↗](../../../apps/server/src/hook-forward.ts#L9 "支持累计字节上限、字段白名单以及最大字符数范围的说明，并准确界定越界检查发生在读取 chunk 之后。")

<a id="delivery-flow"></a>
## 转换、落盘与投递

通过输入与配置校验后，代码解析 JSON，并将 profile id、字段集合和字符预算交给 `hookInput` 构造捕获对象。当前提供的 connectors 材料未包含该函数定义，因此不能进一步确认字段筛选、文本截断或上下文元数据的具体规则。[捕获对象构造调用 ↗](../../../apps/server/src/hook-forward.ts#L34 "支持 hookInput 接收已解析输入及 profile 配置，同时说明当前材料只能确认调用点、不能推导其内部转换规则。")

捕获对象先由 `HookSpool.enqueue` 入队，再由 `flush` 调用捕获 API；请求可携带 Bearer token，超时为 1500 毫秒，单次 flush 的数量参数为 3。[本地入队与 HTTP 投递 ↗](../../../apps/server/src/hook-forward.ts#L39 "支持捕获对象先入队、再提交到捕获 API，以及认证头、请求超时和 flush 数量参数的流程说明。") 队列构造器会创建目录并将权限设置为 `0700`，但现有 spool 行范围仅展示类型、容量错误和初始化，未展示入队、确认、删除及清理实现。[HookSpool 初始化边界 ↗](../../../apps/server/src/inputs/spool.ts#L39 "支持队列目录创建与权限设置，并表明当前固定范围尚未覆盖 enqueue 和 flush 的具体实现。")

<a id="failure-boundaries"></a>
## 失败语义与证据边界

HTTP 非成功响应会转成异常；若 flush 结果包含未投递项，入口向标准错误输出“queued for retry”。外围 `catch` 也会把其覆盖的读取、解析、配置、构造、入队、刷新和网络处理异常降级为标准错误提示，避免这些捕获失败主动阻断宿主。[未投递提示与异常降级 ↗](../../../apps/server/src/hook-forward.ts#L61 "支持 HTTP 错误转换、未投递提示及 try/catch 覆盖流程内的异常降级，同时用于限定“不阻塞宿主”不能外推到进程级故障。") 这一保证限于该 `try/catch` 覆盖的处理流程，不能扩展为模块加载、日志输出本身或进程级故障均不会影响宿主。

因此，调用结束不等于服务端已经接收或应用捕获。记录结构包含 producer、eventId 与 payloadDigest，确认结构也携带对应字段，说明队列具备进行身份核对所需的数据；然而当前材料没有给出实际核对、保留、重试或删除逻辑，不能断言所有失败都会保留记录，也不能断言恰好一次投递。[队列记录与确认结构 ↗](../../../apps/server/src/inputs/spool.ts#L20 "支持记录和确认包含身份核对字段，但不提供记录保留、确认匹配、删除或后续重试机制的实现证据。")
