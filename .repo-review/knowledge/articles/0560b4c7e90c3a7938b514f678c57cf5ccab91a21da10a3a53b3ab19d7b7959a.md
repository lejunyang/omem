# 持久化任务的并发、恢复与副作用验收测试

该测试文件以真实临时 SQLite 数据库验证持久化任务系统的关键可靠性语义：事务入列与重启恢复、竞争租约与 fencing token、分类重试、取消和补偿边界、业务应用幂等、代际重试及 worker 范围隔离。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_setup"></a>
## 问题背景与测试结构

这组测试针对任务已入列但 worker 可能尚未运行、崩溃或并发执行时的可靠性问题。测试通过 `Store` 创建真实临时数据库，并在结束后关闭连接、删除目录；辅助函数统一生成任务、执行指纹和数据库计数，因此断言覆盖持久化仓储与 worker 的组合行为，而非纯协议 fixture。[临时数据库测试夹具 ↗](../../../apps/server/tests/jobs.test.ts#L1 "支持测试使用真实 Store、临时目录、统一辅助函数并执行资源清理的说明。") `Store` 把 SQLite、业务应用仓储和任务仓储装配在同一数据目录中，使测试能够跨越任务调度与业务副作用边界。[Store 的仓储装配 ↗](../../../apps/server/src/store.ts#L38 "说明同一 SQLite Store 同时装配业务应用仓储、任务仓储和其他运行组件。")

<a id="durability_and_concurrency"></a>
## 持久化、并发与过期结果隔离

首个场景用数据库触发器制造入列失败，确认捕获材料、通知和任务整体回滚；正常捕获后关闭并重开数据库，则排队任务可由新 worker 恢复处理，原始片段也仍可读取。[事务回滚与重启恢复用例 ↗](../../../apps/server/tests/jobs.test.ts#L52 "支持捕获与入列原子回滚、持久化任务重启恢复及原始片段保留的论断。") 两个数据库连接争抢同一任务时，只有一个 worker 获得租约，并且只产生一次任务和应用回执。[双 worker 租约竞争用例 ↗](../../../apps/server/tests/jobs.test.ts#L107 "支持两个连接竞争时仅执行一次并只产生一份业务副作用的论断。") 租约过期并被重新领取后，旧 token 提交结果会触发 `STALE_JOB_LEASE`，只有新 token 能完成任务，尝试历史同时保留租约过期与成功结果。[过期租约 fencing 用例 ↗](../../../apps/server/tests/jobs.test.ts#L162 "支持旧租约结果被拒绝、新租约成功以及两次尝试结果可追踪的论断。")

<a id="failure_cancel_and_replay"></a>
## 失败分类、取消与崩溃重放

失败被分为 transient、bad_output 与 auth，测试分别限定为三次、两次和一次执行；认证错误里的密钥片段不会写入持久化错误文本。[分类重试与敏感错误清理用例 ↗](../../../apps/server/tests/jobs.test.ts#L207 "支持不同错误类别的有限重试次数以及认证密钥不进入持久化错误文本的断言。") 取消语义区分排队、运行和已应用三个阶段：排队任务立即取消，运行任务通过 `AbortSignal` 协作终止，已有业务效果的成功任务则要求补偿。[任务取消阶段用例 ↗](../../../apps/server/tests/jobs.test.ts#L253 "支持排队取消、运行中协作中止和应用后要求补偿三种边界。") 对业务应用完成但成功回执尚未落库时的崩溃，重试会识别重复应用，最终任务成功，而任务、回执、通知和投递意图仍各只有一份。[应用后崩溃重放用例 ↗](../../../apps/server/tests/jobs.test.ts#L325 "支持重试执行两次但业务任务、回执、通知和投递意图均不重复的论断。")

<a id="generation_scope_and_limits"></a>
## 代际重试、worker 隔离与覆盖边界

人工重试会创建新 generation；新 worker 使用变化后的模型、effort 和指纹执行，旧代际尝试保持原样，相同 requestId 的重复重试请求也保持幂等。[新代际与新指纹用例 ↗](../../../apps/server/tests/jobs.test.ts#L377 "支持显式重试创建新 generation、保留旧尝试并记录新执行配置的论断。") worker 实现会把 `kinds` 与 `jobIds` 两类领取范围传给仓储。[限定范围的 worker 实现 ↗](../../../apps/server/src/jobs/worker.ts#L32 "支持 worker 在领取任务时把任务种类和指定任务标识过滤条件传给仓储的实现说明。") 对应行为测试证明：限定为知识分析任务的 worker 完成目标任务后，无关的抽取任务仍保持排队，继续处理时返回未领取任务。[限定 worker 不处理无关任务的用例 ↗](../../../apps/server/tests/jobs.test.ts#L431 "直接支持知识分析任务完成后无关抽取任务仍保持排队、再次处理返回空结果的行为断言。") 当前材料未展示 `JobRepository` 的 SQL 与锁策略，且主要 worker 用例显式关闭 heartbeat，因此这些测试尚不能证明跨进程忙锁处理或长任务续租语义。
