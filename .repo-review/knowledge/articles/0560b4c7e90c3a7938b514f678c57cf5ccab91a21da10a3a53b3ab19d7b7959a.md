# 持久作业租约、重试与幂等应用验收测试

系统性验证作业与采集的事务一致性、重启恢复、竞争租约和 fencing、分类重试、取消补偿、崩溃重放、代际指纹及 worker 范围隔离。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="durability"></a>
## 事务持久性与重启恢复

用例通过 SQLite 触发器注入入队失败，断言采集材料和通知也全部回滚；移除故障后，采集与 `extract_claims` 作业一起提交。关闭并重开同一数据目录后，worker 能领取旧作业、写入成功结果，原始片段仍可读取。[采集事务与重启恢复 ↗](../../../apps/server/tests/jobs.test.ts#L52 "支持入队失败整体回滚、正常入队持久化以及重启后继续处理的核心保证。") 这验证“先持久化、后启动 worker”的恢复路径，也与 Store 将数据库、作业、应用和输入组件装配在同一基础设施中的关系一致。[Store 组件装配 ↗](../../../apps/server/src/store.ts#L35 "解释作业、应用、输入与 SQLite 数据库在同一 Store 中的模块关系。")

<a id="concurrency"></a>
## 并发租约与过期结果隔离

两个 Store 实例竞争同一作业时，只有一个 worker 获得租约并执行业务应用，另一个返回未处理；最终尝试、应用回执和任务都只有一条。[双 worker 租约竞争 ↗](../../../apps/server/tests/jobs.test.ts#L107 "支持并发 worker 仅执行一次并只产生一份业务效果的断言。") 另一用例让旧租约过期并由新 worker 取得不同 fencing token；旧 token 提交结果必须报 `STALE_JOB_LEASE`，只有替代租约可完成作业，尝试历史依次记录租约过期与成功。[租约过期与 fencing token ↗](../../../apps/server/tests/jobs.test.ts#L162 "支持旧租约结果被拒绝、新租约完成并保留两次尝试结果的说明。")

<a id="failure-control"></a>
## 失败分类、取消与幂等重放

暂时错误最多执行三次、坏输出两次、认证错误一次后停止，且持久化错误会移除示例令牌。[分类重试与错误脱敏 ↗](../../../apps/server/tests/jobs.test.ts#L207 "支持暂时错误、坏输出和认证错误采用不同重试上限，且秘密不落库。") 排队作业可直接取消，运行中作业通过 AbortSignal 进入取消状态；已经产生业务效果的成功作业则返回“需要补偿”，不会假装撤销任务。[取消与补偿语义 ↗](../../../apps/server/tests/jobs.test.ts#L253 "支持排队、运行中和已应用作业分别采用取消、正在取消和需要补偿的状态。") 若业务应用后、作业回执前崩溃，重试会命中重复应用回执，最终仍只有一个任务、通知与投递意图。[应用后崩溃的幂等重放 ↗](../../../apps/server/tests/jobs.test.ts#L325 "支持处理执行两次但任务、回执、通知及投递意图各只有一份。")

<a id="history-scope"></a>
## 代际历史与 worker 范围

人工重试把 generation 从 1 提升到 2；第二代尝试记录新的模型、推理强度和整体执行指纹，旧尝试保持原样，同一重试请求重复提交也保持幂等。[重试代际与执行指纹 ↗](../../../apps/server/tests/jobs.test.ts#L377 "支持新代际记录新模型、强度和不同整体指纹，同时不改写旧尝试历史。") 测试辅助函数表明该整体指纹由模型、强度以及提示、技能、工具摘要字段共同构造。[执行指纹字段构造 ↗](../../../apps/server/tests/jobs.test.ts#L27 "说明测试中的执行指纹包含模型、推理强度以及提示、技能和工具摘要哈希。") 最后的范围测试限定 worker 只处理指定 kind 和 job id；目标知识作业成功后，普通提取作业仍处于排队状态。[限定范围的知识 worker ↗](../../../apps/server/tests/jobs.test.ts#L431 "支持 worker 只领取指定知识作业并保留无关提取作业的隔离行为。") 未覆盖长期 heartbeat 续租、真实进程被强杀、数据库损坏、多主机时钟偏差和跨数据库分布式竞争。
