# Web 客户端数据合同与请求入口

集中定义个人知识、运行作业、提案决策、通知与飞书接入的数据形状，并提供统一的 JSON 请求封装；该封装只负责发送 Bearer Authorization 请求头，不足以证明后端鉴权效果。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="domain-contracts"></a>
## 核心领域合同

该文件是 Web 端共享的数据合同入口，并复用 contracts 包中的修订、片段、变更与运行事件类型。`Evidence` 把片段、修订、出向关系和反向关系组合为证据视图；任务则记录标题、详情、期限、关联证据、完成状态与版本，通知记录变更消息及已读时间。类型只能证明这些数据如何组织，不能单独证明片段身份固定或修订不可变。[证据、任务与通知类型 ↗](../../../apps/web/src/api.ts#L1 "支持证据由片段、修订和双向关系组成，以及任务、通知所记录的字段；同时限定这里只能确认数据组合。")

`Profile` 描述传输方式、可选模型与 effort 以及上下文上限；`Run` 保存运行状态、事件和可选回答。`Job` 进一步记录输入引用、角色及策略版本、排队到取消的状态、重试代次、结果引用和错误，并可附各次尝试使用的模型、effort 与时间。这里将其保守表述为运行和后台作业记录，不把类型定义等同于实际调度保证。[运行与后台作业记录 ↗](../../../apps/web/src/api.ts#L48 "支持配置档、运行状态、事件，以及作业状态机、版本、尝试、模型和错误信息等描述。")

<a id="proposal-flow"></a>
## 提案、决策与通知追踪

提案区分创建、更新和替代，携带作用域、材料证据、不确定项、来源摘要及策略结果；策略结果可为自动应用、等待决策或拒绝。`assessments` 保存引文或资产判定、语义判定、评估版本与原因，但这些字段本身不能证明评估角色相互独立。[提案与评估记录 ↗](../../../apps/web/src/api.ts#L101 "支持提案操作、证据、不确定项、策略结果和 assessments 评估字段的说明，同时不把字段存在扩大为独立性保证。")

决策记录提案摘要、预期版本、操作者、有效期、请求标识、动作和处理时间，并覆盖待处理、批准、拒绝、请求上下文、过期与陈旧状态；它证明信息被记录，不证明执行层必然校验这些字段。通知详情还可关联变更前后实体、投递尝试、聚合方式、回执及证据列表，用于呈现变更及投递结果。[人工决策与通知详情合同 ↗](../../../apps/web/src/api.ts#L138 "支持决策状态及其记录字段，并说明通知详情能够追踪投递、回执和关联证据；不据此推断执行层校验。")

<a id="integration-request"></a>
## 飞书接入与统一请求

飞书相关合同覆盖所需权限、事件和回调，以及新建或复用应用时的二维码、验证地址、配对候选、能力缺口、连接标识和版本，体现接入过程包含多个可观察状态，而非单一开关。[飞书接入数据结构 ↗](../../../apps/web/src/api.ts#L187 "说明应用配置、连接、扫码验证、配对、能力缺口和版本等接入状态。")

统一请求函数从会话存储读取令牌；存在令牌时附加 Bearer `Authorization` 请求头，同时设置 JSON 内容类型。无请求体默认使用 GET，有请求体默认使用 POST 并序列化为 JSON。此前把这一行为称为“鉴权”超出了客户端材料，现明确为发送请求头，是否验证和授权取决于后端。函数还会在检查 HTTP 成功状态前直接解析 JSON，因此空响应或非 JSON 错误可能先抛出解析异常，无法进入服务端 `error` 或“请求失败”的兜底路径。[统一 API 请求函数 ↗](../../../apps/web/src/api.ts#L240 "支持附加 Bearer Authorization 请求头、默认方法、JSON 序列化，以及先解析响应再检查状态的实际行为；不证明后端完成鉴权。")
