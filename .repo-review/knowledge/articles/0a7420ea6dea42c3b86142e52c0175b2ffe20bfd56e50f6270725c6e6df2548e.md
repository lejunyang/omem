# Web 前端的数据合同与统一请求入口

该文件集中描述 Web 界面消费的业务数据形状，并提供附带会话令牌、自动序列化请求体和统一处理服务端错误的轻量 API 客户端。它连接共享合同与界面层，但只提供 TypeScript 静态类型，不负责运行时响应校验。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为界面提供一致的数据视图

该文件是 Web 前端与服务端之间的**类型门面**：它复用共享合同中的修订、片段、变更和运行事件，同时补充来源、证据、通知、任务、模型配置与运行状态等界面所需的数据形状。这样，页面可以围绕证据的正反向关系、任务状态和运行事件组织展示，而不必在各组件内重复声明接口。参考 [前端核心数据视图 ↗](../../../apps/web/src/api.ts#L1 "支持该文件集中声明来源、证据、通知、任务、配置与运行状态等界面数据形状的说明。")

任务的 `followUp` 直接引用共享 `TaskFollowUp`，其等待对象、下次检查时间、暂缓时间和时区约束由合同包定义；这表明前端模型有意与任务流程合同保持一致。参考 [任务跟进共享合同 ↗](../../../packages/contracts/src/task-flow.ts#L3 "支持 Task.followUp 复用共享类型，以及共享合同对跟进时间、等待对象和时区进行约束的论断。")

<a id="business_views"></a>
## 覆盖审核、通知与飞书接入流程

除基础实体外，文件还为后台异步流程提供了较完整的读取模型：作业可处于排队、租约、运行、等待决定、重试或终止等状态，并可携带多次尝试；提案则记录操作类型、证据、不确定性、策略结论和独立评估，决定对象进一步封装审批生命周期。参考 [作业与提案审核状态 ↗](../../../apps/web/src/api.ts#L64 "支持异步作业状态、多次尝试、提案证据、策略评估和决定生命周期的描述。")

通知详情把变更、投递尝试、应用回执和关联证据聚合在一起；飞书相关类型则描述应用配置、连接、扫码接入、能力缺口与配对状态。这些都是供界面呈现流程状态的 DTO，材料中没有显示它们会主动驱动后台执行。参考 [通知与飞书接入视图 ↗](../../../apps/web/src/api.ts#L162 "支持通知投递和回执聚合，以及飞书配置、连接、接入和配对状态的数据结构说明。")

<a id="request_flow"></a>
## 统一请求与错误处理

`api<T>` 根据是否传入请求体选择默认方法：无请求体使用 GET，有请求体使用 POST；随后统一添加 JSON 内容类型，并从 `sessionStorage` 读取令牌组成 Bearer 认证头。请求体存在时会被 JSON 序列化，响应也始终按 JSON 解析；非成功状态优先抛出服务端 `error`，否则使用“请求失败”。参考 [统一 API 请求流程 ↗](../../../apps/web/src/api.ts#L244 "支持令牌读取、默认方法选择、JSON 序列化、响应解析和错误抛出方式及其边界说明。")

这一封装保持轻量，但边界也很明确：泛型 `T` 只提供编译期提示，没有对响应做运行时 schema 校验；空响应或非 JSON 响应会在 `r.json()` 阶段失败。默认方法也只区分 GET 与 POST，PUT、PATCH、DELETE 必须由调用方显式传入。参考 [统一 API 请求流程 ↗](../../../apps/web/src/api.ts#L244 "支持令牌读取、默认方法选择、JSON 序列化、响应解析和错误抛出方式及其边界说明。")
