# 个人工作区前端 API 合同与请求封装

集中定义个人工作区前端使用的数据形状，并提供带会话令牌、JSON 编解码和统一错误处理的通用请求函数。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="responsibility"></a>
## 解决的问题与合同范围

该文件是个人工作区前端的轻量 API 边界：一部分类型直接复用共享合同中的 Revision、Fragment、Change 与 RunEvent，另一部分在前端补充 Source、Evidence、Task、运行任务、提案审批、通知投递和飞书接入等响应形状。[共享合同导入与基础数据类型 ↗](../../../apps/web/src/api.ts#L1 "支持该文件复用共享合同并补充前端响应类型的说明。") 这些声明主要提供静态约束，本身不执行校验；例如 Proposal 明确记录证据、疑点、策略结论与评估结果，Decision 则表达待审批到过期或失效的状态变化。[提案与决策状态合同 ↗](../../../apps/web/src/api.ts#L101 "支持提案证据、策略评估以及审批状态建模的论断。")

<a id="request-flow"></a>
## 请求流程与认证

`headers` 从 `sessionStorage` 读取个人工作区令牌，存在时生成 Bearer Authorization；`api` 根据是否传入 body 默认选择 GET 或 POST，统一请求 `/api` 前缀，并以 JSON 发送和解析。响应非成功状态时，它优先抛出服务端 `error`，否则使用通用中文错误。[通用请求封装 ↗](../../../apps/web/src/api.ts#L240 "说明令牌来源、默认方法、JSON 编解码和错误处理流程及其限制。") 因而调用方得到的是已解析的泛型结果，而认证、序列化和基本错误转换被收敛在一处。

<a id="limits"></a>
## 边界与模块关系

该封装假定响应体始终可解析为 JSON，未处理空响应、非 JSON 错误页、超时、取消、重试或并发去重；泛型 `T` 也不会带来运行时验证。[通用请求封装 ↗](../../../apps/web/src/api.ts#L240 "说明令牌来源、默认方法、JSON 编解码和错误处理流程及其限制。") 与 Code Wiki 使用的评审接口不同：评审客户端材料明确说明其 loopback 浏览面不发送 Authorization，因此不能把这里的令牌策略直接套到 `/api/review/*`。[评审 API 的认证边界 ↗](../../../apps/web/src/review-api.ts#L1 "证明 repo-review 客户端与个人工作区 API 的认证策略不同。")
