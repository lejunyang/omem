# 聊天与屏幕输入聚合器

该模块把聊天或屏幕采集器产生的细粒度事件持久化，按静默时间、最大窗口或事件数形成批次，再交给统一 capture 流程。它提供事件级幂等、按内容摘要与 actorId 去重、分片预算、迟到标记和并发状态复核；但缺失 actorId 的事件会共同按 unknown 去重，分片外部身份可能回退为 actorId，且 capture 与本地归批不在同一事务中。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_ingest"></a>
## 问题与事件接入

`InputAggregator` 将连续的聊天或屏幕观察事件先持久化，再按流批量捕获。聊天以会话 ID 为流键，屏幕以应用名和窗口标题组合为键；其他来源会被拒绝，事件还必须提供采集器和事件 ID。[流键与接入前置条件 ↗](../../../apps/server/src/inputs/aggregator.ts#L39 "支持聚合器仅接受聊天和屏幕来源，以及会话、采集器和事件 ID 的必填约束。")

接入在 SQLite 即时事务中完成，并以个人工作区、采集器和事件 ID 判重：相同载荷重放返回已有事件，不同载荷复用同一事件键则报冲突。完整载荷摘要用于幂等冲突判断，内容摘要用于后续聚合去重；摘要工具会递归排序对象键、忽略 `undefined`，再对规范 JSON 计算 SHA-256。[事件判重与摘要计算 ↗](../../../apps/server/src/inputs/aggregator.ts#L58 "支持事件键判重、相同载荷重放、冲突处理及完整载荷摘要和内容摘要的用途。")[规范 JSON 与稳定摘要 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持递归排序对象键、忽略 undefined 并计算 SHA-256 的摘要规则。")

<a id="readiness_and_selection"></a>
## 成批时机与选择边界

待处理事件按工作区、来源和流分组；默认静默 15 秒、首事件滞留 5 分钟，或待处理数量达到默认 50 条时进入刷新候选。单次事件上限限制在 1–500，并按接收时间和行 ID 稳定选择。[流就绪判定与事件上限 ↗](../../../apps/server/src/inputs/aggregator.ts#L124 "支持静默窗口、最长等待、数量阈值、流分组方式及 1–500 的事件上限。")

选择阶段以“内容摘要 + actorId”判重：相同且非缺失的 actorId 所对应的重复内容不再占用 parts 预算，不同且非缺失的 actorId 即使内容相同仍分别保留。actorId 缺失时统一使用 `unknown`，因此多个身份未知、但现实中可能来自不同说话人的同内容事件可能被合并。每批最多容纳 50 个去重后的 parts；首个事件自身超限会报错，后续事件导致超限则留待下一批。[按 actorId 去重与分片预算 ↗](../../../apps/server/src/inputs/aggregator.ts#L158 "支持内容摘要与 actorId 联合判重、actorId 缺失时统一使用 unknown，以及 50-part 预算边界。")

<a id="envelope_and_provenance"></a>
## 聚合信封与身份边界

构造聚合信封时会按同一规则再次去重，并给每个 part 写入来源信息。`actorExternalId` 优先取事件的外部身份，缺失时回退到 actorId，再缺失才为 null；`actorPrincipalId`、观察时间和事件 ID按实现复制。`replyTo` 固定为 null，因此不会保留引用目标；只会复制 `quoted` 引用标志，以及转发标志和生产者类型。[聚合分片来源写入规则 ↗](../../../apps/server/src/inputs/aggregator.ts#L181 "支持分片外部身份回退到 actorId、replyTo 固定为空，以及引用标志、转发标志等字段的实际写入语义。") 分片合同允许文本、图片和链接携带这些可选 provenance 字段。[分片来源合同 ↗](../../../packages/contracts/src/index.ts#L4 "解释文本、图片和链接分片可以携带的可选 provenance 字段及其类型边界。")

批次顶层仅比较 `actorId`、`actorType` 和 `actorVerifiedBy` 是否分别一致；一致时从最后事件复制外部身份、主体身份和绑定版本，后三项自身并未参与一致性判断。若前三项不一致，顶层身份会清空或降为 unknown，但逐分片来源仍可保留。[批次顶层身份判定 ↗](../../../apps/server/src/inputs/aggregator.ts#L250 "支持仅比较 actorId、actorType 和验证方式，并从最后事件复制其他顶层身份字段的限制。") 批次 ID由工作区、来源、流键和有序事件键稳定计算；出现不晚于上一批末次观察时间的事件时，只记录迟到关系，不改写旧批次。[稳定批次标识与迟到关系 ↗](../../../apps/server/src/inputs/aggregator.ts#L217 "支持上一批查询、迟到时间比较以及由有序事件键生成稳定批次 ID。")

<a id="flush_and_consistency"></a>
## 捕获提交与一致性限制

刷新先选择事件、构造信封并调用外部 `capture`，取得 revision 与可选 job；随后才开启本地事务，复核事件仍全部为 pending，写入批次并将其更新为 batched。状态已被并发改变时会抛出 `INPUT_BATCH_CHANGED`，阻止本地重复归批。[刷新状态复核与本地归批 ↗](../../../apps/server/src/inputs/aggregator.ts#L320 "支持 capture 后复核 pending 状态、写入批次并更新事件状态的本地事务流程。")

该事务只覆盖本地批次表和事件状态，外部 `capture` 已在事务开始前完成。现有材料没有说明复核失败后已创建的 revision/job 会被幂等复用、清理还是成为孤立产物，因此这里仍存在待核实的最终一致性边界。[捕获调用与事务边界 ↗](../../../apps/server/src/inputs/aggregator.ts#L332 "支持外部 capture 发生在本地事务之前，并界定当前材料无法证明的失败补偿问题。")
