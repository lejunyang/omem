# PlanProposal.v1 输出结构

该 schema 定义规划提案的顶层身份、预期版本字段、步骤、未知项和来源信息，并把每一步限制为五种建议动作及一组可验证字段；它验证 JSON 结构，但不定义版本冲突处理，也不验证证据真实性或计划质量。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="proposal"></a>
## 提案身份与版本前提

PlanProposal.v1 是禁止额外顶层属性的对象，必须包含 schema 版本、提案与任务标识、预期版本、步骤、不确定性及来源。[提案必填顶层字段 ↗](../../../packages/agent-runtime/roles/planner/1/output.schema.json#L1 "支持 PlanProposal.v1 顶层结构、必填字段及禁止额外属性的说明。") `expected_version` 仅被定义为最小值为 1 的整数，即一个预期版本字段；此前将其概括为“并发版本”超出了材料，应由这一较窄结论替代。schema 本身没有规定冲突检测、拒绝、重试或过期处理语义。[提案标识与预期版本字段 ↗](../../../packages/agent-runtime/roles/planner/1/output.schema.json#L15 "支持 schema 版本、提案和任务标识，以及 expected_version 仅被约束为不小于 1 的整数；也说明不能从该字段单独推导并发处理语义。")

<a id="steps"></a>
## 受限动作与步骤闭环

每个步骤禁止额外属性，并要求动作、证据引用、预期产物、验证方式、是否需要所有者决策及停止条件齐全。[计划步骤必填字段 ↗](../../../packages/agent-runtime/roles/planner/1/output.schema.json#L21 "支持每一步必须包含证据、产物、验证、所有者决策标记和停止条件的论断。") 动作仅限收集上下文、起草文档、拆分任务、建议提醒和请求决策，因此结构层面把输出约束为有限类型的计划步骤。[允许的规划动作 ↗](../../../packages/agent-runtime/roles/planner/1/output.schema.json#L33 "支持步骤动作被限制为五种规划操作的说明。")

不过，`evidence_refs` 只要求是字符串数组，`uncertainties` 也是字符串数组，`origin` 仅要求为对象；schema 未给出非空标识、引用目标存在性或来源必填属性等约束。[步骤字段与宽松来源结构 ↗](../../../packages/agent-runtime/roles/planner/1/output.schema.json#L43 "支持 evidence_refs、产物、验证等字段的类型约束，并说明 uncertainties 与 origin 的结构约束较宽松。") 这些语义仍需宿主校验、接收流程或行为测试补足。
