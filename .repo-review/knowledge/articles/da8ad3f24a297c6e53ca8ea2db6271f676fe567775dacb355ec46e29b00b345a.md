# 统一助手运行时与受治理写入

统一承载 Web 与飞书助手的会话编排、证据检索、取消恢复和事项治理；本次修订明确事项改期才需要时间表达，并补充创建事项时原话捕获可能失败的边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="turn-flow"></a>
## 统一执行面与轮次上下文

`AssistantRuntime` 是 Web 与飞书共用的执行面，集中处理上下文组装、只读检索、受治理工具、轮次持久化与降级；模型能力通过端口注入。[主助手运行时职责 ↗](../../../apps/server/src/assistant/runtime.ts#L185 "支持运行时统一服务不同入口，并集中承担上下文、检索、治理、持久化和降级职责。") 输入先持久化并按外部事件去重，同一会话的新消息会取消旧轮次，随后沿会话 promise 链串行执行。[轮次入队与会话串行化 ↗](../../../apps/server/src/assistant/runtime.ts#L224 "支持模型调用前持久化、外部事件去重、新消息取消旧轮次及同会话串行执行。")

执行只读取当前会话已完成的历史，并合并上一轮工作证据与本轮检索结果；模型最多触发一轮补充检索。[历史上下文与补充检索 ↗](../../../apps/server/src/assistant/runtime.ts#L447 "支持仅使用当前会话已完成历史、合并上一轮工作证据并限制补充检索轮数。") 最终引用标识还会与运行时实际提供的证据集合求交集，防止模型引用未暴露材料。[引用标识过滤 ↗](../../../apps/server/src/assistant/runtime.ts#L593 "支持最终引用只能来自运行时实际提供的证据集合。")

<a id="cancel-recovery"></a>
## 取消、超时与恢复边界

外部取消、新消息抢占和运行时计时器会合并为统一中止信号，独立超时竞争则保证模型忽略中止时也不会无限等待。[取消信号与硬超时 ↗](../../../apps/server/src/assistant/runtime.ts#L419 "支持多种取消来源合并，并由独立超时竞争终止不响应中止的模型调用。") 模型明确不可用时，轮次被恢复为待处理状态以便重试，而不会生成伪造答案。[模型不可用时保留待处理轮次 ↗](../../../apps/server/src/assistant/runtime.ts#L515 "支持 ModelUnavailableError 将轮次标记为 pending，供后续重试。")

人工重试与重启恢复会查询真实 application receipt；但现有匹配依赖外部事件标识以及创建事项提案的固定前缀。[创建事项 receipt 恢复边界 ↗](../../../apps/server/src/assistant/runtime.ts#L301 "支持 receipt 查询、人工重试与重启恢复，并揭示其对外部事件标识和创建事项提案前缀的依赖。") 因此，被替代的是“所有工具变更都具有同等恢复防重能力”的宽泛结论：当前证据只直接覆盖这套创建事项 receipt 路径。

<a id="evidence-task-governance"></a>
## 证据可见性与事项治理

检索结果会补全为完整片段，再次执行可见性检查，并排除非当前 head 或派生材料；未注入策略时，群聊默认拒绝全部证据。[证据读取与可见性边界 ↗](../../../apps/server/src/assistant/runtime.ts#L654 "支持检索后的再次可见性过滤、当前 head 原始证据限制及群聊缺省拒绝策略。") 事项变更须匹配用户原文中的明确动作和可见事项版本；只有改期才调用时间校验，并要求用户原文含有对应表达且时间带有效时区。[事项变更与改期校验 ↗](../../../apps/server/src/assistant/runtime.ts#L697 "支持所有事项变更均校验明确动作和可见版本，而仅改期额外要求有效时间表达。")

创建事项还须先识别明确的 owner 记录意图。运行时会尝试捕获本轮 owner 原话作为原始证据；该捕获位于 `try/catch` 中，失败后仍会进入 `MemoryService` 评估，但证据数组可能为空，最终是否应用由治理结果决定。[受治理的事项创建 ↗](../../../apps/server/src/assistant/runtime.ts#L837 "支持原话证据捕获为尽力而为操作，并说明捕获失败后评估仍可能收到空证据。") 模型请求变更后，其推测性成功文本会被丢弃；成功回复的标题和提醒时间来自重新读取的持久化事项，动作措辞则取决于受治理 action。[依据治理动作与持久化事项生成回复 ↗](../../../apps/server/src/assistant/runtime.ts#L581 "支持丢弃模型推测性成功文本，并从治理动作和持久化事项构造最终反馈。")
