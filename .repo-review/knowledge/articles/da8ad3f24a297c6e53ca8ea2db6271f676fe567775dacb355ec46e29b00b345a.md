# 统一助手回合：检索、模型与事项治理

AssistantRuntime 是 Web 与飞书共用的助手回合协调器：它先持久化输入，按会话装配历史、可见原始证据、派生背景、纠正和事项，再调用可取消的模型；模型只能提出搜索或事项请求，真正的写入由服务端校验意图、时间、版本、证据和治理收据后执行。运行时还负责引用白名单、最终答复落库、重复投递、取消、超时与失败恢复。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 把多入口收束为一条可信回合

`AssistantRuntime` 解决的不是“如何调用一次模型”，而是如何让 Web 与飞书共享同一套会话、检索、权限和写入语义。它注入 `ConversationRouter`、模型端口、检索、记忆与反馈服务，自己负责上下文装配、证据可见性、低风险工具治理和回合持久化。参考 [统一运行时职责 ↗](../../../apps/server/src/assistant/runtime.ts#L229 "说明运行时是多入口共用的协调层，并列出会话、检索、治理、持久化和模型端口之间的职责边界。")

入口 `turn` 接收会话、用户文本和可选的传输事件号：先把回合写成待处理记录；同一事件重复送达会直接返回已有回合。每个会话只串行执行一个链，新消息会中止旧消息，完成后再从路由器读取持久化结果。参考 [回合入队与串行执行 ↗](../../../apps/server/src/assistant/runtime.ts#L268 "支持代表性调用从输入持久化、重复事件短路、新消息取消旧回合到返回持久化结果的入口流程。")

<a id="flow"></a>
## 一条提醒请求如何变成可信结果

以“提醒我 10 月 2 日上午 9 点英语复习”为例，主流程是：

```mermaid
flowchart LR
  A[输入先入队] --> B[检索可见证据与会话上下文]
  B --> C[模型生成回答或工具请求]
  C --> D[服务端校验意图、时间与治理策略]
  D --> E[依据持久化收据生成答复并完成回合]
```

运行时只取同会话已完成的历史，合并本轮检索、上一轮选中证据、纠正、可见事项和当前时钟，再调用模型。模型最多提出三条补查词；运行时并行补查、去重并限制证据规模，只再生成一轮，因此首轮提出的事项请求不会直接执行。参考 [上下文装配与首次生成 ↗](../../../apps/server/src/assistant/runtime.ts#L503 "支持同会话历史、检索证据、上一轮工作上下文、纠正、事项和时钟被装配后交给模型的说明。") [有界补查一轮 ↗](../../../apps/server/src/assistant/runtime.ts#L575 "说明模型补查词的数量、长度、并行检索、证据去重限额和第二轮生成边界。")

随后服务端独立识别用户是否明确要求建事项；咨询句即使被模型误判，也会拒绝写入。时间必须同时具有原消息中的表达、合法 ISO 时间和时区。明确指令会先捕获为所有者原始证据，再由 `MemoryService.evaluate` 返回收据；只有收据对应真实事项，最终答复才会写“已创建”，模型自报成功不能越过这一层。参考 [事项请求服务端治理 ↗](../../../apps/server/src/assistant/runtime.ts#L641 "支持取消栅栏、显式用户意图检查，以及创建和更新请求都由服务端治理而非模型自行授权。") [所有者指令形成原始证据 ↗](../../../apps/server/src/assistant/runtime.ts#L1195 "说明明确的所有者指令会被捕获为带来源信息的原始证据，并生成稳定提案标识。") [记忆治理与收据确认 ↗](../../../apps/server/src/assistant/runtime.ts#L1244 "支持创建事项通过 MemoryService 评估，并且只有真实 task 收据才返回成功事项标识的论断。") [明确时间校验 ↗](../../../apps/server/src/assistant/runtime.ts#L72 "说明提醒或改期时间必须来自原消息表达、包含时区且能够被解析。")

<a id="boundaries"></a>
## 证据边界、失败语义与修改入口

检索结果分成两类：原始材料引用被还原成可引用片段，知识或记忆等派生命中只作为背景；所有片段都经过 `isVisible`。未注入策略时，私聊可见而群聊默认看不到任何证据，宿主必须提供基于来源范围的策略。参考 [统一检索上下文 ↗](../../../apps/server/src/assistant/runtime.ts#L804 "说明统一检索如何把原始引用还原成证据、把非原始命中作为背景，并在过程中执行可见性过滤。") [群聊默认拒绝证据 ↗](../../../apps/server/src/assistant/runtime.ts#L1135 "支持没有宿主可见性策略时仅私聊可见、群聊拒绝证据的安全默认值。")

取消和超时使用合并的 `AbortSignal`，并在工具写入前、最终落库前设置提交栅栏；模型不可用时，回合保留为待处理状态，可由 `retryTurn` 再次执行。启动恢复会扫描未完成回合：对带传输事件号、且已存在 `assistant-task:${eventId}:...` 建事项收据的回合，直接标记完成以避免重复创建；其余未匹配收据的回合会进入重新执行路径。事项更新使用 `turnId` 作为请求标识，不属于这条建事项收据前缀检查。参考 [取消信号与提交栅栏 ↗](../../../apps/server/src/assistant/runtime.ts#L475 "说明外部取消、内部中止和墙钟超时会合并成信号，并由断言阻止后续提交。") [待处理回合重试 ↗](../../../apps/server/src/assistant/runtime.ts#L367 "说明 retryTurn 只接收待处理回合，在未命中建事项提交收据时重新执行该回合。") [建事项收据匹配范围 ↗](../../../apps/server/src/assistant/runtime.ts#L350 "限定恢复防重检查必须有传输事件号，且只匹配以该事件号组成的建事项提案前缀。") [未完成回合恢复路径 ↗](../../../apps/server/src/assistant/runtime.ts#L423 "说明恢复会扫描未完成回合，命中建事项收据则直接完成，否则重新执行并在失败时留待下次恢复。") [事项更新请求标识 ↗](../../../apps/server/src/assistant/runtime.ts#L1026 "说明事项更新调用 MemoryService 时使用回合标识作为 requestId，因此不属于按传输事件号匹配的建事项收据前缀。")

修改时可按职责定位：调整自然语言建事项判定看 `detectTaskIntent`；调整证据与派生背景装配看 `retrieveContext`；调整事项权限、版本、时间和回执看 `governCreateTask` / `governTaskUpdate`。不要把模型输出本身当授权，也不要绕过最终引用白名单与回合持久化。参考 [显式事项意图识别 ↗](../../../apps/server/src/assistant/runtime.ts#L213 "支持修改入口位于确定性的事项意图识别器，并说明咨询问题优先于弱事项动词。") [统一检索上下文 ↗](../../../apps/server/src/assistant/runtime.ts#L804 "说明统一检索如何把原始引用还原成证据、把非原始命中作为背景，并在过程中执行可见性过滤。") [事项请求服务端治理 ↗](../../../apps/server/src/assistant/runtime.ts#L641 "支持取消栅栏、显式用户意图检查，以及创建和更新请求都由服务端治理而非模型自行授权。") [明确时间校验 ↗](../../../apps/server/src/assistant/runtime.ts#L72 "说明提醒或改期时间必须来自原消息表达、包含时区且能够被解析。")
