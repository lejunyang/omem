# 统一助理回合运行时

该模块统一承载 Web 与 Lark 的助理回合：先持久化并串行处理输入，再组装历史与固定证据、调用可替换模型、治理事项写操作，最后保存可追溯结果。补充检索时才执行 24 条证据截断；恢复失败则按模型不可用、执行期失败和逃逸异常分别处理。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-contract"></a>
## 职责与依赖边界

`AssistantRuntime` 是 Web 与 Lark 共用的编排层，负责上下文、只读检索、事项治理、回合持久化和降级；真实模型通过注入端口接入。[主助理运行时职责 ↗](../../../apps/server/src/assistant/runtime.ts#L185 "支持统一运行时负责上下文、检索、治理、持久化和降级，并通过端口注入模型。") 模型只能使用宿主提供的历史、证据、可见性和受管工具，不能自行读取任意数据或授予写权限。[模型端口能力边界 ↗](../../../apps/server/src/assistant/runtime.ts#L82 "支持模型只能使用宿主提供的上下文、证据和受管工具。")

检索结果必须回指不可变 Fragment，使上层引用原始材料而非把摘要当成事实。[统一检索与固定证据锚点 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持检索候选回指不可变 Fragment、上层引用原始证据。") 当前持久化仍是单用户 SQLite 基础，团队级权限强制属于后续迁移范围。[单用户 SQLite 存储边界 ↗](../../../apps/server/src/store.ts#L2 "支持当前存储是单用户基础，团队权限强制尚未实现。")

<a id="turn-flow"></a>
## 回合流程与证据约束

输入会在模型调用前入队，并按外部事件 ID 识别重复投递；同一会话的新消息取消旧回合，再沿进程内 Promise 链顺序执行。正常与重复返回目前都向 `toResult` 传入空证据数组。[回合入队与串行执行 ↗](../../../apps/server/src/assistant/runtime.ts#L224 "支持入队去重、同会话取消和串行流程，也显示结果路径传入空证据数组。")

执行时只读取本会话已完成历史，并将初始检索结果与上一轮工作上下文按 Fragment 去重；这一步没有 24 条上限。只有模型提出补充查询时，运行时才执行最多三个查询，把额外结果与已有证据再次去重并截为 24 条，然后进行第二轮生成。[上下文合并与补充检索 ↗](../../../apps/server/src/assistant/runtime.ts#L456 "支持初始合并仅去重，而 24 条限制只发生在存在补充检索的分支。") 检索补全还拒绝非当前 head、派生或不可见材料；群聊在未注入策略时默认不返回证据。[证据补全与可见性校验 ↗](../../../apps/server/src/assistant/runtime.ts#L654 "支持检索结果经过当前 head、非派生材料和会话可见性检查。") 最终引用仅保留运行时实际提供的 Fragment，写操作答复则依据持久化后的真实事项重建。[动作回执答复与引用白名单 ↗](../../../apps/server/src/assistant/runtime.ts#L581 "支持写操作答复依据实际事项重建，并过滤模型未获提供的引用。")

<a id="task-governance"></a>
## 事项治理与证据来源

创建事项须先通过确定性意图检查：咨询式问句优先视为非授权，即使模型请求 `create_task` 也不会写入。[确定性事项创建意图 ↗](../../../apps/server/src/assistant/runtime.ts#L126 "支持咨询问句不构成写入授权，明确任务表达才允许继续创建。") 更新事项同样要求原消息含明确动作、目标可见且版本一致；改期时间必须来自原消息中的表达，并解析为带时区的有效时间。[事项更新与时间校验 ↗](../../../apps/server/src/assistant/runtime.ts#L693 "支持更新动作、可见性、版本和改期时间均由服务器重新校验。")

创建流程会解析并校验模型给出的本轮引用或上一轮工作上下文，但当前提交给 `MemoryService.evaluate` 的证据固定为新捕获的 owner 直接消息；因此不能声称已校验的上下文也实际进入提案。[创建事项的直接证据 ↗](../../../apps/server/src/assistant/runtime.ts#L821 "支持引用和上下文会被解析校验，但实际提案证据当前仅采用 owner 直接消息。") 只有评估产生真实 task receipt 才报告创建成功，否则返回治理拒绝或未自动应用结果。[提案评估与成功回执 ↗](../../../apps/server/src/assistant/runtime.ts#L890 "支持创建提案交由记忆服务评估，并以真实任务回执作为成功依据。")

<a id="failure-recovery-limits"></a>
## 失败恢复与接口限制

取消或超时会终止回合；模型不可用时明确将状态保持为 `pending`，普通模型异常则生成诚实的降级回复。[模型错误分流 ↗](../../../apps/server/src/assistant/runtime.ts#L487 "支持取消、模型不可用保持 pending，以及普通模型错误生成降级回复。") `executeTurn` 外层还会捕获后续执行错误：取消转为 `cancelled`，其余错误调用 `failTurn` 标为 `failed`。[执行期最终错误处理 ↗](../../../apps/server/src/assistant/runtime.ts#L605 "支持 executeTurn 将取消标为 cancelled，并把其他未处理错误标为 failed。")

重启恢复仅处理仍能找到所属会话的未完成回合；命中已提交事项回执时直接完成，否则调用 `executeTurn`。[未完成回合恢复流程 ↗](../../../apps/server/src/assistant/runtime.ts#L366 "支持恢复时跳过无所属会话的回合，并按回执命中或重新执行分流。") 由于该函数通常自行吞掉异常并落为 `failed`，不能笼统说重新执行失败都会保留待重试；只有模型不可用会保持 `pending`，真正逃逸到恢复层的异常才按该层注释留待后续尝试。回执检查本身还要求外部事件 ID，并只匹配 `assistant-task` 提案前缀。[已提交事项回执检查 ↗](../../../apps/server/src/assistant/runtime.ts#L301 "支持回执恢复仅适用于带外部事件 ID 且匹配 assistant-task 前缀的提案。")

公开结果虽包含 `evidence`，`toResult` 却只原样返回调用者传入的数组；结合当前 `turn()` 的空数组参数，该字段不能视为本轮实际选中证据，后者保存在持久化回合中。[公开回合结果映射 ↗](../../../apps/server/src/assistant/runtime.ts#L964 "支持公开 evidence 只是返回调用方参数，而事项和降级信息来自持久化回合。")

<a id="open-questions"></a>
## 待确认事项

仍需确认三项非阻塞合同：创建提案是否应纳入已校验上下文、跨进程重复投递是否有数据库级原子保证，以及公开结果是否应直接返回实际选中证据。它们分别影响事项可追溯性、并发幂等性与调用方理解。[创建事项的直接证据 ↗](../../../apps/server/src/assistant/runtime.ts#L821 "支持引用和上下文会被解析校验，但实际提案证据当前仅采用 owner 直接消息。")[已提交事项回执检查 ↗](../../../apps/server/src/assistant/runtime.ts#L301 "支持回执恢复仅适用于带外部事件 ID 且匹配 assistant-task 前缀的提案。")[公开回合结果映射 ↗](../../../apps/server/src/assistant/runtime.ts#L964 "支持公开 evidence 只是返回调用方参数，而事项和降级信息来自持久化回合。")
