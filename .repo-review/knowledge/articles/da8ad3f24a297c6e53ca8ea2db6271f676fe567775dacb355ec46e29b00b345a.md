# 统一助理运行时：证据约束、轮次治理与事项执行

AssistantRuntime 是 Web、Lark 等入口共享的助理编排层，统一承担会话上下文、可见性约束下的检索、模型调用、事项治理及轮次持久化。它通过会话串行、取消栅栏和持久化回执降低并发与重复执行风险；创建事项时会尝试把当前所有者消息捕获为直接证据，但捕获失败不会中止评估，最终是否应用仍取决于 MemoryService 的证据校验与策略结果。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-contract"></a>
## 职责与信任边界

该模块是不同消息入口共用的主助理运行时，负责组装上下文、只读检索证据、调用注入的模型端口、经 `MemoryService` 执行低风险事项操作，并持久化轮次及处理降级；生产模型和测试替身使用同一端口。[主助理运行时职责 ↗](../../../apps/server/src/assistant/runtime.ts#L192 "支持不同入口共用运行时，以及上下文、检索、事项治理、持久化、降级和模型端口注入等职责。")

模型返回的引用、搜索词和工具请求都只是候选结果，写操作仍须由服务端治理。证据可见性由宿主策略按规范主体及来源范围裁决，模型声明不能改变该边界；未注入策略时，运行时仅允许私聊读取证据，群聊拒绝全部证据。[证据可见性策略 ↗](../../../apps/server/src/assistant/runtime.ts#L119 "支持证据可见性由服务端依据规范主体及证据来源范围裁决，且群聊在缺少策略时拒绝证据。")[默认可见性实现 ↗](../../../apps/server/src/assistant/runtime.ts#L793 "支持未注入可见性策略时仅私聊返回可见、群聊默认拒绝的具体实现。")

<a id="turn-lifecycle"></a>
## 轮次并发、异常与恢复

轮次在模型调用前入列；提供外部事件号时，重复投递返回已有轮次。同一会话串行执行，新消息会中止并标记旧轮次，预取消信号也会阻止模型启动。[轮次入列与会话串行化 ↗](../../../apps/server/src/assistant/runtime.ts#L231 "支持外部事件号条件下的重复投递去重、新消息取代旧轮次、会话内串行和预取消栅栏。") 模型生成与补充检索共处同一内层异常边界：取消记为 `cancelled`，模型不可用使轮次保持 `pending`，其他生成或补充检索异常形成降级回复。[生成与补充检索异常分类 ↗](../../../apps/server/src/assistant/runtime.ts#L494 "支持初次模型生成、补充检索和第二轮生成共享异常边界，并区分取消、模型不可用与降级回复。") 工具治理、引用整理和最终持久化阶段的非取消异常则由外层处理为 `failed`。[工具及持久化阶段失败处理 ↗](../../../apps/server/src/assistant/runtime.ts#L540 "支持工具执行前取消栅栏、最终落库以及外层将后续非取消异常标记为失败。")

重试与重启恢复会查询持久化回执；若发现已提交的创建回执，就直接完成轮次而不再次执行。该判断要求存在 `transportEventId`，且只匹配 `assistant-task:${eventId}:%`，因此不能推断所有更新操作都具有同等恢复幂等性。[提交回执与未完成轮次恢复 ↗](../../../apps/server/src/assistant/runtime.ts#L308 "支持恢复时读取持久化回执避免重复创建，并明确查询依赖外部事件号且只匹配创建 proposal 前缀。")

<a id="evidence-and-model-flow"></a>
## 检索、上下文与引用约束

运行时只回放当前会话中已经完成的历史，并在历史预算内传给模型；本轮检索结果会与先前工作上下文按 fragment 去重合并。[当前会话历史与证据合并 ↗](../../../apps/server/src/assistant/runtime.ts#L463 "支持仅选择当前会话已完成历史，并将本轮检索结果与先前工作上下文按 fragment 去重合并。") 先前工作上下文来自最近一个具有非空已选证据的完成轮次；若较近的完成轮次没有证据，运行时会继续向前查找。[最近有证据的完成轮次 ↗](../../../apps/server/src/assistant/runtime.ts#L751 "支持向前寻找最近一个具有非空 selectedEvidence 的完成轮次，而非固定使用紧邻轮次。")

检索优先使用统一 `RetrievalPort`，其候选始终指向不可变 fragment，便于高层回到原始证据。[统一检索与固定片段合同 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持统一检索端口可替换，并要求结果指回不可变 fragment 以便引用原始证据。") 命中后还会确认来源仍是当前 head 且不是派生 revision；长片段中的语义命中只用于定位原文。[当前原始证据回读 ↗](../../../apps/server/src/assistant/runtime.ts#L770 "支持语义焦点只用于原文定位，并拒绝非当前 head 或派生 revision 作为助理证据。") 模型最多提出一轮补充检索：查询去重、截断并限为三条，证据按 fragment 去重并限制总量，再进行第二轮生成。[补充检索与第二轮生成 ↗](../../../apps/server/src/assistant/runtime.ts#L512 "支持查询去重、截断、限量，证据按 fragment 去重限量及最多一次补充生成。") 最终引用只保留运行时实际提供的 fragment；未注入统一端口的旧测试路径才回退到本地搜索。[引用过滤与检索回退 ↗](../../../apps/server/src/assistant/runtime.ts#L602 "支持最终只保留实际提供的证据引用，并说明统一检索端口缺失时的本地搜索回退。")

<a id="task-governance"></a>
## 事项创建、更新与限制

创建事项必须先通过确定性的明确意图检测；咨询标记优先于较弱的任务动词，因此即使模型请求 `create_task`，咨询式或非明确指令也会被拒绝。[确定性事项意图检测 ↗](../../../apps/server/src/assistant/runtime.ts#L130 "支持明确创建意图的模式检测、咨询标记优先级及非明确请求的拒绝。") 通过检查后，运行时验证模型引用，并尝试把当前所有者消息捕获为直接证据；捕获异常会被忽略，此时 proposal 的 `evidence` 可能为空，随后仍进入 `MemoryService.evaluate`。因此，先前“必然捕获原始证据并以该证据完成授权”的结论已被替代：当前指令是运行时选择的授权语境，但实际能否应用取决于后续证据校验和策略结果。已验证的引用材料不会加入 `allEvidence`；proposal 优先使用外部事件号，缺失时回退到本轮 requestId。[创建事项的证据捕获与评估 ↗](../../../apps/server/src/assistant/runtime.ts#L832 "支持验证模型引用、尝试捕获所有者当前消息、捕获失败后以空证据继续评估，以及由 MemoryService 的结果决定是否应用。")

更新事项要求原文包含与动作匹配的明确表达，目标事项必须可见且版本一致；改期时间必须来自原消息并包含时区。运行时捕获变更指令后，以 turnId 作为 requestId 调用 `commandTask`。[事项更新治理流程 ↗](../../../apps/server/src/assistant/runtime.ts#L695 "支持明确动作、可见性和版本检查、时间校验、变更指令捕获以及以 turnId 调用 commandTask。") 可用状态、动作、版本、时间和跟进字段由共享合同限定。[共享事项状态与动作合同 ↗](../../../packages/contracts/src/task-flow.ts#L3 "支持事项状态、跟进结构、动作枚举、版本号及时间字段的共同约束。") 最终成功话术根据实际工具结果及存储中的事项重新生成，不采信模型自行声称的执行成功。[依据真实结果生成回复 ↗](../../../apps/server/src/assistant/runtime.ts#L588 "支持存在事项变更时丢弃模型的推测性成功文本，改由工具结果和存储中的事项状态组织回复。")
