# ConversationRouter 会话身份与轮次持久化测试

验证会话路由按主体、渠道、聊天与线程形成稳定身份，写入有序轮次及所选证据，并断言输入文本、工具动作和当前目标可从存储中读取。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="identity-routing"></a>
## 会话身份与隔离维度

ConversationRouter 为不同入口提供统一的会话持久化层。测试使用临时 Store 构造路由器，并在每个用例后关闭数据库和删除目录，以隔离测试状态。[路由器测试资源生命周期 ↗](../../../apps/server/tests/conversation-router.test.ts#L8 "说明测试使用真实临时 Store，并在用例结束后关闭数据库和清理目录。") 相同 principal、channel、chat 与默认 thread 的重复 `open` 返回同一会话；只改变 chat 或 channel 就得到不同标识，同时保留 private 可见性，并把缺省 thread 规范化为空字符串。[会话组合键复用 ↗](../../../apps/server/tests/conversation-router.test.ts#L23 "支持相同组合键复用会话、不同聊天或渠道隔离，以及默认线程和可见性的行为。") 因而本文件证明了组合键复用，但尚未覆盖显式 threadId、不同 principal、group 可见性、并发打开或唯一约束冲突。

<a id="turns-goals"></a>
## 轮次顺序、历史与目标

记录轮次时，路由器从 1 开始分配单调 ordinal，两次写入后下一个序号推进到 3。首轮写入包含所选证据，次轮写入结构化工具动作；随后测试断言历史按顺序还原两条输入文本，并还原第二轮工具动作。[有序轮次写入与历史断言 ↗](../../../apps/server/tests/conversation-router.test.ts#L45 "支持 ordinal 单调递增、所选证据被传入记录接口，以及历史输入文本和工具动作被实际断言；同时界定未断言证据往返的限制。") 这替代了“已验证所选证据可从历史还原”的旧结论：当前用例只证明证据被传入写入接口，并未对历史中的 `selectedEvidence` 做往返断言。会话级当前目标则通过设置后再次读取获得验证。[会话当前目标 ↗](../../../apps/server/tests/conversation-router.test.ts#L83 "支持路由器能够持久化并读取会话级当前目标。") 测试未覆盖时间戳、事务回滚、重复消息幂等、并发顺序、会话删除或跨重启读取，也不证明工具动作真正执行。
