# 运行时交互请求仓储

该文件用 SQLite 持久化 Agent 运行期间的权限请求或信息征询，提供拒绝记录、请求决议和按任务查询，并以稳定摘要约束重复请求的一致性。当前材料仍无法确定并发决议、动作后续消费以及工作区隔离的完整语义。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_model"></a>
## 职责与数据模型

该仓储将权限请求与信息征询统一映射为 `RuntimeRequest`，保存工作区、任务、会话、轮次、供应方请求号、选项、状态和时间信息。状态类型包含 `pending`、`denied`、`expired`、`resolved`；`fromRow` 可读取并转换数据库中的任一声明状态。[运行时请求类型与行映射 ↗](../../../apps/server/src/agent-runtime/requests.ts#L7 "支持请求字段、完整状态集合，以及 fromRow 可把数据库状态转换为声明状态的论断。") 先前“本文件只转换 denied 与 resolved”的结论已被替代：准确边界是本文件的写操作只明确产生 `denied` 与 `resolved`。

<a id="denial_and_idempotency"></a>
## 拒绝记录与幂等约束

`recordDenied` 根据请求种类、选项和轮次生成载荷摘要，以随机 UUID 写入一条已拒绝记录，并把创建与解决时间设为当前时刻；未传 `ttlMs` 时，`expires_at` 默认为当前时间五分钟后。[拒绝记录与幂等校验 ↗](../../../apps/server/src/agent-runtime/requests.ts#L40 "支持拒绝记录的写入状态、默认过期时间、读取既有记录及摘要冲突检查流程。") 这只是默认过期时间，材料没有清理或删除逻辑，因此替代此前“默认保留期五分钟”的表述。插入采用 `INSERT OR IGNORE`，随后按会话号与供应方请求号读取记录；摘要不同则抛出幂等冲突。摘要会递归规范化数据、排序对象键、过滤 `undefined`，再计算 SHA-256，避免对象键顺序造成误判。[稳定摘要实现 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持摘要对数组和对象递归规范化、过滤未定义值、排序键并使用 SHA-256 的说明。")

<a id="resolution_query_boundaries"></a>
## 请求决议与查询边界

`resolve` 先按内部 ID 取出请求，仅允许仍为 `pending` 且未过期的记录继续；随后以 `state='pending'` 为条件更新为 `resolved`，并返回传入的 `approve` 或 `reject` 动作。[请求决议状态转换 ↗](../../../apps/server/src/agent-runtime/requests.ts#L88 "支持决议前的存在性、状态和过期校验，以及条件更新与动作返回的行为边界。") 因而此前“人工决议”已改为更准确的“请求决议”：本材料未证明调用者一定是人工。动作没有落入该表，更新结果也未检查影响行数，并发唯一成功及后续执行语义仍待调用链证据确认。`list` 仅支持全表或按 `job_id` 查询，并按创建时间排序，未显示工作区过滤或分页。[运行时请求列表查询 ↗](../../../apps/server/src/agent-runtime/requests.ts#L105 "支持列表仅按可选任务 ID 过滤、按创建时间排序且未体现工作区过滤和分页的说明。")
