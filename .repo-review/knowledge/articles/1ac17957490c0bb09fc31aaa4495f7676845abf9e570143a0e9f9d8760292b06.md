# memory · 模块理解

memory 模块把模型产出的记忆或任务提案转化为可审计的状态变更：固定证据、匹配既有知识、执行注意力政策、控制批量影响、处理用户决策，并将可信反馈沉淀为约束。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-boundary"></a>
## 职责与治理边界

memory 模块位于模型理解与持久化应用之间：模型提交提案和独立评估，但不直接改写记忆或任务。服务先按稳定摘要持久化提案、记录来源读取版本，再核验文本选择区间、固定修订和图片资产，使每次判断都能追溯到原始材料。[记忆治理子知识 ↗](4ae81d3b5a75b0ae57d4c4d8df64d8c1d53a47411a2329150e4152e5fab850e2.md#evidence-policy "概括模块以固定证据和政策分流约束模型写入的总体职责。")[提案持久化与证据校验 ↗](../../../apps/server/src/memory/service.ts#L161 "支持提案摘要去重、来源读取版本记录，以及文本区间、固定修订和图片资产校验。") `MemoryService`、`FeedbackService`、助手、学习流程和飞书运行时共用同一个 `Store`；服务器提供提案评估、决策、记忆恢复与反馈接口，因此该模块是多条运行流程共享的治理层，而非独立知识库。[服务装配与运行时复用 ↗](../../../apps/server/src/app.ts#L53 "支持记忆、反馈、助手、学习和飞书运行时共享 Store 与服务实例。")[记忆与反馈 API ↗](../../../apps/server/src/app.ts#L344 "支持服务器已经暴露提案评估、决策、记忆恢复和反馈访问入口。")

<a id="matching-and-policy"></a>
## 新建匹配与更新门控是两条路径

新建 claim 先在同一工作区、同一项目的活跃 claim 中匹配。只有**规范化后陈述完全相同**才进入重复或等价分支：来源重叠视为重复；独立来源的相同规范化陈述会应用为另一条记忆并建立等价关系，当前并不识别一般同义改写。[完全相同陈述的重复与等价判断 ↗](../../../apps/server/src/memory/service.ts#L495 "支持仅在规范化陈述完全相同时区分来源重叠的重复和独立来源的等价，不覆盖一般同义改写。") 冲突匹配还必须由上游评估先给出 `contradicts_existing`，之后才检查有效期重叠、中文内容词交集与相反极性，并选择重叠度最高的候选。[冲突匹配前提与中文启发式 ↗](../../../apps/server/src/memory/service.ts#L515 "支持冲突匹配必须先有 contradicts_existing 评估，并进一步检查时间、内容词交集和相反极性。")

一旦新建匹配命中，流程会提前交给专门处理器：冲突被记录为争议并固定为 `defer_until_use`，不会继续进入普通 AttentionGate，也不会依据当前任务阻塞状态创建决策。[新建冲突的提前返回处理 ↗](../../../apps/server/src/memory/service.ts#L1588 "支持新建 claim 命中冲突后记录争议并直接延迟使用，不再进入普通 AttentionGate 或创建决策。") AttentionGate 处理的是未命中新建匹配的提案，尤其是更新既有知识时的跨来源变化；它把证据错误拒绝、噪声忽略、低风险不确定性延迟，仅在影响超限，或跨来源更新触及活跃知识/当前任务时请求用户决定。[AttentionGate 政策分流 ↗](../../../apps/server/src/memory/service.ts#L730 "支持普通提案的拒绝、忽略、延迟、保留、自动应用和跨来源更新升级条件。") 这一区分替代了旧稿中“新 claim 冲突会继续经跨来源门控升级”的结论。

<a id="application-and-batch"></a>
## 应用新鲜度与批量影响控制

自动应用或用户批准前，服务都会复核来源 head、validity epoch 和决策状态，再通过 `Store` 的统一应用接口写入任务或记忆并生成收据；流程知识未经所有者批准不能自动应用。[应用前新鲜度检查与统一写入 ↗](../../../apps/server/src/memory/service.ts#L1167 "支持应用前复核来源和决策状态，并通过 Store 统一写入任务或记忆。") 批量评估先合并受影响记忆与新实体的去重集合，再一次性判断预算。超限时，原本可自动应用的提案全部停放，并生成一个汇总 AttentionCase，避免把大变更拆成多条低影响操作绕过阈值。[批量影响门控 ↗](../../../apps/server/src/memory/service.ts#L1431 "支持按受影响记忆与新实体的去重并集计算总影响，并在超限时停放整批可自动应用提案。")

不过汇总决策仅把全部提案摘要保存于 `attentionCase`，数据库决策行仍锚定代表提案的摘要；通用批准流程也只按该摘要加载并应用一条提案。[汇总批量决策 ↗](../../../apps/server/src/memory/service.ts#L1511 "支持汇总 AttentionCase 保存全部提案摘要，但决策行锚定代表提案摘要。")[单提案批准路径 ↗](../../../apps/server/src/memory/service.ts#L1686 "支持通用决定流程只按决策绑定的单个提案摘要加载并应用一条提案，形成批量整体批准能力的疑点。") 因而“批量门控和汇总提问已实现”可以确认，但“批准后整体应用全部停放提案”仍不能从现有材料确认。

<a id="feedback-and-limits"></a>
## 反馈约束与当前限制

反馈服务按工作区、生产者和事件 ID 去重，并用摘要发现同一事件的内容冲突。只有身份已验证、来源为 original 且证据完整的强反馈才会成为 active confirmed 约束；权限、预算、自动批准等受保护策略保持 shadow，普通有用性或结果反馈保持 weak。目前自动修正仅覆盖任务负责人。[反馈约束服务 ↗](../../../apps/server/src/memory/service.ts#L1895 "支持反馈事件去重、强度分级、受保护策略降级，以及当前仅对任务负责人应用 confirmed 修正。")

现有冲突匹配是可审计的确定性启发式：中文文本被压缩为内容二元词，极性由有限的否定模式判断，并且依赖上游先标记矛盾。[冲突匹配前提与中文启发式 ↗](../../../apps/server/src/memory/service.ts#L515 "支持冲突匹配必须先有 contradicts_existing 评估，并进一步检查时间、内容词交集和相反极性。") 它没有证明能可靠处理同义改写、同词多义、双重否定或复杂时态，因此不应被描述为完整的语义冲突检测。
