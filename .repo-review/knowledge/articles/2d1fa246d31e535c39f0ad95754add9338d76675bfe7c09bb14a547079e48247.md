# Web 前端 Vite 配置

该文件配置 Vite 的 Vue 单文件组件支持与本地开发服务器：服务仅监听回环地址，端口可由环境变量覆盖且禁止自动换端口，并将 `/api` 请求代理至可配置的本地后端端口。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决的问题与配置入口

该文件是 Web 前端的 Vite 配置入口，通过 `defineConfig` 声明配置，并注册 `@vitejs/plugin-vue`，为 Vue 及其单文件组件提供构建处理能力。现有材料没有依赖版本信息，因此不能仅凭该插件确认 Vue 的主版本；也无法判断页面入口、组件结构或生产部署方式。[Vite 与 Vue 插件配置 ↗](../../../apps/web/vite.config.ts#L1 "支持该文件作为 Vite 配置入口并启用 Vue/Vue 单文件组件处理能力，同时说明材料不足以确认 Vue 主版本。")

<a id="dev-flow"></a>
## 本地开发请求流程

开发服务器绑定 `127.0.0.1`，默认使用 `5173`；设置 `OMEM_WEB_PORT` 时，会将其经 `Number(...)` 转换后作为监听端口。`strictPort: true` 表示目标端口不可用时不自动改用其他端口。浏览器发往 `/api` 的请求则被代理至本机端口 `OMEM_PORT`，未配置时使用 `4317`，构成“浏览器 → Vite 开发服务器 → 本地 API”的开发链路。[开发服务器与 API 代理 ↗](../../../apps/web/vite.config.ts#L5 "解释前端监听地址、端口选择、严格端口策略，以及 `/api` 到本地后端的请求链路。")

<a id="boundaries"></a>
## 边界条件与模块关系

该配置建立了 Web 开发服务器与本地 HTTP API 的连接，但材料未提供后端启动或路由代码，无法确认服务归属、接口集合、是否保留 `/api` 前缀，以及是否存在路径重写。监听地址固定为回环地址，默认不直接向局域网开放；此外，非法的 `OMEM_WEB_PORT` 字符串经转换可能得到 `NaN`，本文件没有显式校验或回退策略。[本地绑定与环境变量边界 ↗](../../../apps/web/vite.config.ts#L5 "支持回环地址限制、两个端口环境变量的使用，以及本文件未显式校验端口值的边界分析。")
