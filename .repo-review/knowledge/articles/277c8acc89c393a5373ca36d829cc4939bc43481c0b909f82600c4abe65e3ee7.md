# 通用知识整理、复核与阅读流程

概述从固定材料分析、独立语义复核、不可变发布到阅读和助手召回的共用知识管线，并记录定向修订、疑问演进及输入隔离等后续完善。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence-model"></a>
## 正文、引用与不可变证据

知识正文按具名 Markdown 章节组织，引用紧贴论断，并携带可读名称、理由、关系和固定目标。模型只选择位置，宿主从固定版本复制精确引文，独立角色再判断语义支持性；位置有效不等于结论正确。知识修订不可变，原始事实仍来自 Capture、Source、Revision 和 Fragment，派生正文不会升级为新的独立证据。[正文与固定引用合同 ↗](../../../docs/implementation/knowledge-pipeline.md#L5 "支持内联引用、宿主复制引文、独立语义复核、不可变知识修订和原始证据边界。")

<a id="runtime-pipeline"></a>
## 共用角色运行时与发布门槛

材料、代码、对话和图像使用同一 RoleRuntimeGateway、任务存储和预算机制，worker 按任务种类领取，避免知识、学习与通知流程互相抢占。[共用 Agent 运行时 ↗](../../../docs/implementation/knowledge-pipeline.md#L15 "支持多类材料共用角色运行时、任务隔离和预算记录。")

KnowledgePipeline 先分析材料，再以独立会话复核；只有通过内容才能发布，同批合格结果可以先保存，失败部分继续修订。分析期间若来源改变，当前发布会被拒绝。个人知识 API 同时提供正文、引用、原文、搜索、问题、回答和显式待办，用户回答作为新原始材料进入下一轮核对。[通用分析复核与服务接口 ↗](../../../docs/implementation/knowledge-pipeline.md#L23 "支持先分析后独立复核、来源变化拒绝发布以及知识 API 和用户回答处理流程。")

<a id="repository-and-reader"></a>
## 仓库适配、阅读与召回

仓库入口只是统一流程的材料适配器：全量或局部分析均保留排除和失败原因，通过复核的结果保存为 JSON 与带内联链接的 Markdown；索引重建不会重新调用模型。[仓库材料适配与可移植产物 ↗](../../../docs/implementation/knowledge-pipeline.md#L31 "支持仓库作为输入适配器、局部生成入口、索引重建边界及可恢复知识产物。")

个人知识与仓库知识共用 Evidence Trail 阅读组件，可从正文逐层进入知识章节、原始材料或代码目标，并恢复返回层级、滚动、焦点和深链。助手检索可先命中派生正文，再沿固定引用返回原始 Fragment；正文只负责导航，原有可见性过滤及当前来源校验继续生效。[共用阅读组件与知识引导召回 ↗](../../../docs/implementation/knowledge-pipeline.md#L45 "支持 Evidence Trail 交互合同，以及派生正文只导航到原始 Fragment 的召回边界。")

<a id="revision-lifecycle"></a>
## 定向修订与知识演进

语义复核退回后由刷新角色依据具体意见局部修改，最终仍必须重新通过独立复核；持续无法确认的内容应降为有依据的问题，而不能绕过拒绝结果。[语义退回后的定向修订 ↗](../../../docs/implementation/knowledge-pipeline.md#L61 "支持根据复核意见局部刷新、有限轮次和不得绕过独立复核的要求。")

新修订不再提出的问题会标为被替代，已回答或已加入待办的记录保留。普通文件、Lark 文档和会话消息按载体身份分流，私有配置继续排除；草稿、摘要和反馈被隔离为不可信派生资料，不能提升为工具或策略指令。[疑问演进与输入隔离 ↗](../../../docs/implementation/knowledge-pipeline.md#L71 "支持问题被替代生命周期、载体分流、私有配置排除和派生资料不可信边界。")
