# docs-research.md · 模块理解

该文档记录自治记忆与检索组件的早期研究：由 omem 自持统一证据与记忆内核，把检索、解析和经历学习作为可替换能力，并以真实任务、硬性门槛和统一 PoC 决定是否采用；其结论尚非生产选型或已实现能力。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-boundary"></a>
## 职责与研究边界

`docs/research.md` 的作用是为自治记忆、文档检索和解析组件建立选型依据，而不是描述当前系统的实际能力。它把已经确认的产品方向、MemPalace 后续研究与第一轮 WeKnora/Hindsight 架构建议明确分开；现有结论来自资料和源码核验，尚未部署候选引擎，也未复现性能基准。[研究状态与实施边界 ↗](../../../docs/research.md#L3 "支持本节关于文档属于早期研究、未部署候选引擎且未复现性能基准的判断。") 子知识据此将这些推荐界定为待 PoC 验证的研究判断，而非生产承诺。[子知识中的研究定位 ↗](ee168961c9fafa031cdaba5bdb9a55d445a3b911c4384ac4c4f152f254bb86ac.md#status-boundary "引用已组织的子知识，说明其如何把原始状态声明解释为待 PoC 验证的研究判断；该引用不替代同段的原始材料依据。")

<a id="architecture-and-flow"></a>
## 核心思路与决策流程

研究建议由 omem 掌握材料到知识的版本化引用、变更语义、自治风险、结果验证和外部 Agent 协议，同时把文档检索与经历巩固交给可替换引擎。WeKnora 与 Hindsight 是首选 PoC；若前者的片段映射或部署成本不合格，可换用 Docling/LlamaIndex、pgvector 与 Hindsight，而核心数据模型和 UI 保持稳定。[统一内核与可替换引擎 ↗](../../../docs/research.md#L9 "支持 omem 自持核心治理合同、外围引擎可替换以及通过统一验收决定生产采用的架构关系。") 因而决策流程不是直接 fork 完整 RAG 产品，而是先固定内核合同，再用同一验收体系比较外围方案。

<a id="progress-and-limits"></a>
## 进展、硬门与跨模块约束

当前进展停留在候选路线、评分维度和翻转条件的定义。评估须采用项目真实任务，包括中文术语、历史与现行制度、跨材料证据链、纠错后的再次任务、冲突、撤权与无答案场景；无原文导出、权限不能隔离、删除后仍可注入或索引不可重建，任何一项都构成不可由总分抵消的硬失败。[选型硬门与待验证事实 ↗](../../../docs/research.md#L97 "支持真实任务评测、不可由评分抵消的硬失败条件，以及解析质量、资源上限等事项仍未验证的限制。") 尚待验证的跨模块问题包括结构导出与重放、巩固结果的证据映射及删除传播、中文切片定位、本地模型能力、资源费用和许可证组合，因此本文只能指导后续实现与验收，不能证明解析质量、推理正确率或生产可部署性。
