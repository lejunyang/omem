# 材料分析角色的运行配置

该清单定义 material-analyst 角色第 1 版的提示词、内联技能、结构化输出、工具隔离、会话隔离与令牌预算。它说明角色应如何被运行时装配，但仅凭配置文件不能证明宿主已完成加载、执行或结果校验。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 角色定位与结构化产出

这份清单把 `material-analyst` 标识为第 1 版材料分析角色，并指定使用 `traex` profile 与 `prompt.md` 提示模板。它解决的是运行时如何稳定识别和装配分析角色的问题，而不是记录某次分析任务的实际执行结果。参考 [角色基本配置 ↗](../../../packages/agent-runtime/roles/material-analyst/1/manifest.json#L2 "支持角色标识、版本、profile 与提示模板的配置说明。")

角色声明的输出合同为 `KnowledgeBatch.v1`，意味着预期产物应采用统一的知识批次结构，便于宿主继续保存、复核或展示；但清单只表达配置意图，不能单独证明输出已经通过 schema 校验。参考 [知识批次输出合同 ↗](../../../packages/agent-runtime/roles/material-analyst/1/manifest.json#L17 "支持该角色声明使用 KnowledgeBatch.v1 作为结构化输出 schema。")

<a id="skill_and_isolation"></a>
## 技能装配与隔离边界

清单配置了 `omem-material-analyst` 第 1 版技能包，并采用 `inline` 加载方式，同时用摘要固定技能制品身份。这有助于让角色提示与技能版本保持可追溯关系。参考 [内联技能配置 ↗](../../../packages/agent-runtime/roles/material-analyst/1/manifest.json#L9 "支持技能名称、版本、加载方式及制品摘要的说明。")

该角色被设为无工具模式，允许工具列表为空；会话也明确不复用，并且不继承用户技能或 MCP。由此可见，配置目标是让每次材料分析在隔离上下文中完成，避免外部工具和用户侧扩展影响分析边界。是否由宿主严格执行这些限制，仍需结合运行时实现或执行记录确认。参考 [无工具策略 ↗](../../../packages/agent-runtime/roles/material-analyst/1/manifest.json#L18 "支持角色禁用工具且没有允许工具项的隔离边界。") [会话隔离策略 ↗](../../../packages/agent-runtime/roles/material-analyst/1/manifest.json#L22 "支持会话不复用且不继承用户技能和 MCP 的配置说明。")

<a id="resource_limits"></a>
## 上下文、输出与修复预算

预算允许最多 96,000 个上下文 token、24,000 个输出 token，并设置最多 2 次修复尝试。这为较长材料和结构化 JSON 输出预留了空间，也限制了格式修复的重试次数。参考 [角色预算上限 ↗](../../../packages/agent-runtime/roles/material-analyst/1/manifest.json#L27 "支持上下文、输出 token 与修复尝试次数的具体配置。")

这些数值属于角色运行配置，不代表每次任务都会用满预算，也不说明修复触发条件、超限行为或失败后的状态处理；相关运行语义需要由宿主实现和执行 trace 补充。
