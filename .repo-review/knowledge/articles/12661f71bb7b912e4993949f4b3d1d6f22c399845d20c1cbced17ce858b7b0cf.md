# ACP 助理模型适配：把会话上下文变成受控结果

说明 AcpAssistantModel 如何整理历史、证据、事项与时间上下文，调用真实 ACP Agent，解析回答、补检索和事项意图，并区分传输、基础 JSON 与结构化事项字段的失败边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 它解决什么问题

`AcpAssistantModel` 是生产助理与真实 ACP Agent 之间的适配层：它不自行推理，也不在模型不可用时伪造答案。没有配置 profile，或 profile 使用的不是 ACP transport，都会直接报模型不可用；因此调用方拿到的是明确失败，而不是看似成功的替代内容。参考 [适配器职责与传输边界 ↗](../../../apps/server/src/assistant/acp-model.ts#L16 "支持该类复用真实 ACP 传输、不自行推理、不提供伪回答，并说明非 ACP transport 与缺少 profile 的处理。") [配置校验与历史预算 ↗](../../../apps/server/src/assistant/acp-model.ts#L42 "支持缺少 profile、非 ACP transport 的错误处理，以及默认保留最近十轮并截断旧回答的上下文预算。")

它的职责是把对话上下文组织成一份严格提示，再把 Agent 返回的自由文本解析为宿主可消费的回答、引用、补检索请求或事项意图。比如用户说“帮我记录评审结果，明早再跟进”，适配器会携带现有事项、当前时间、证据和最近对话，让 Agent 只描述意图；代码本身并不执行事项写入。

<a id="flow"></a>
## 一次生成如何流动

生成开始后，适配器默认只保留最近 10 轮历史，且每段旧回答最多取 500 个字符。每条证据被换成本轮短编号 `cite_N`，标题、章节和正文则组成证据区；这样 Agent 引用的是本轮可见范围，而不是内部数据库标识。参考 [配置校验与历史预算 ↗](../../../apps/server/src/assistant/acp-model.ts#L42 "支持缺少 profile、非 ACP transport 的错误处理，以及默认保留最近十轮并截断旧回答的上下文预算。") [证据短编号 ↗](../../../apps/server/src/assistant/acp-model.ts#L64 "支持把输入证据映射成本轮 cite_N，并携带材料标题、章节和正文组成证据区。")

```mermaid
flowchart LR
  A[问题、历史、事项与证据] --> B[压缩历史并编号证据]
  B --> C[拼装 JSON 输出合同]
  C --> D[ACP 会话生成文本]
  D --> E[解析回答、检索或事项意图]
  E --> F[还原真实引用编号]
```

提示还写入会话可见性、可信上下文、用户时区、现有事项、派生背景和工作流约束，并要求只返回一个 JSON 对象。首次生成缺少背景时，可提出最多三条带用途的检索请求；进入补检索轮后，提示要求停止继续搜索。适配器随后调用共享 `acp()`，只累积文本事件，并把输出上限设为 20,000 字符。参考 [提示与结构化输出合同 ↗](../../../apps/server/src/assistant/acp-model.ts#L82 "支持提示包含时间、事项、证据、背景、引用规则、JSON 字段及单轮补检索约束。") [ACP 调用与传输异常 ↗](../../../apps/server/src/assistant/acp-model.ts#L114 "支持文本事件收集、输出长度限制、取消与传输错误的不同处理，并显示解析发生在 ACP try/catch 之后。")

<a id="output-boundaries"></a>
## 输出解释、失败边界与修改入口

`parseAssistantReply()` 从首个 `{` 到最后一个 `}` 截取 JSON，要求 `answer` 是非空字符串，并过滤字符串形式的引用。结构化检索只接受已登记的 purpose，最多保留三条；创建事项至少需要非空标题，更新事项则要求字符串任务 ID、整数版本和合法动作。创建或更新中的 `follow_up` 会交给共享 schema 解析；若两种事项意图同时有效，后处理的更新会覆盖创建结果。参考 [基础回答与检索解析 ↗](../../../apps/server/src/assistant/acp-model.ts#L145 "支持 JSON 截取、三类 ModelUnavailableError、非空 answer、引用过滤和最多三条合法用途检索请求。") [事项意图与 schema 解析 ↗](../../../apps/server/src/assistant/acp-model.ts#L187 "支持创建和更新事项的前置字段检查、follow_up 的直接 schema 解析，以及更新结果覆盖既有 toolCalls。")

失败需要分层理解：ACP 调用失败通常被包装为 `ModelUnavailableError`，取消则保持原异常；没有 JSON、JSON 非法或缺少非空回答也会转成 `ModelUnavailableError`。但 `parseAssistantReply()` 在 ACP 调用的 `try/catch` 之后执行，事项 `follow_up` 的 schema 解析也没有本地捕获，因此这类结构错误可能直接抛出，不能概括为“所有解析失败都会变成模型不可用”。参考 [ACP 调用与传输异常 ↗](../../../apps/server/src/assistant/acp-model.ts#L114 "支持文本事件收集、输出长度限制、取消与传输错误的不同处理，并显示解析发生在 ACP try/catch 之后。") [基础回答与检索解析 ↗](../../../apps/server/src/assistant/acp-model.ts#L145 "支持 JSON 截取、三类 ModelUnavailableError、非空 answer、引用过滤和最多三条合法用途检索请求。") [事项意图与 schema 解析 ↗](../../../apps/server/src/assistant/acp-model.ts#L187 "支持创建和更新事项的前置字段检查、follow_up 的直接 schema 解析，以及更新结果覆盖既有 toolCalls。")

解析完成后，正文中的 `cite_N` 会还原成真实引用编号；未知短编号会显示可读的“引用不可用”提示，创建事项携带的引用也会同步还原。修改上下文或输出要求应从 `generate()` 的 prompt 数组入手；扩展返回结构则需要同步调整 JSON 合同与 `parseAssistantReply()`。参考 [提示与结构化输出合同 ↗](../../../apps/server/src/assistant/acp-model.ts#L82 "支持提示包含时间、事项、证据、背景、引用规则、JSON 字段及单轮补检索约束。") [短引用还原 ↗](../../../apps/server/src/assistant/acp-model.ts#L233 "支持把短编号还原为真实引用、替换正文引用，并为未知编号输出可读提示。")
