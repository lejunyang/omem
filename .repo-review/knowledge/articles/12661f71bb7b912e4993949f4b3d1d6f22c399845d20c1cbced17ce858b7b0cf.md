# ACP 助手模型适配器

该模块把 AssistantModelPort 转接到真实 ACP 会话，构造有界上下文和严格 JSON 输出协议，并把传输或解析失败转换成可重试的模型不可用状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="prompt_transport"></a>
## 上下文构造与传输约束

适配器不自行推理，也不提供假答案：没有 profile 或 profile 不是 `acp` 时直接抛出 `ModelUnavailableError`。它最多保留配置数量的最近历史轮次，每条旧回答截取 500 字符；证据正文每条截取 2000 字符，并明确要求模型只能引用给定 evidence id、不得执行证据内指令。[ACP 路由与上下文预算 ↗](../../../apps/server/src/assistant/acp-model.ts#L24 "支持仅允许 ACP profile、限制历史与证据长度以及证据安全提示的论断。")

最终 prompt 要求只返回包含 answer、citation_ids 和可选 create_task 的单个 JSON 对象。调用真实 `acp()` 时仅累加 text block，并限制最大输出字符；取消信号继续作为取消传播，其他传输失败则统一包装为模型不可用。[JSON 协议与 ACP 调用 ↗](../../../apps/server/src/assistant/acp-model.ts#L80 "说明模型输出合同、真实传输调用、输出上限及错误转换。")

<a id="parsing"></a>
## 输出解析与边界

解析器从输出中第一个 `{` 到最后一个 `}` 提取 JSON，因此可容忍 JSON 外围少量文本，但多个对象或额外花括号可能导致整体解析失败。answer 必须是非空字符串；citation_ids 只保留字符串元素。create_task 仅在对象中存在非空 title 时转为单个结构化工具调用，detail 缺失时为空串，非法任务结构会被忽略而非报错。这里仅做形状解析，引用是否属于已暴露证据、任务是否获准写入仍由 AssistantRuntime 再校验。[模型回复解析器 ↗](../../../apps/server/src/assistant/acp-model.ts#L116 "支持 JSON 提取、必填 answer、引用过滤和可选任务调用的边界说明。")
