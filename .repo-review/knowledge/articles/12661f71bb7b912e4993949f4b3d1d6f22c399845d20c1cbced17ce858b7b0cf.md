# ACP 助手模型适配器

把助手运行时的结构化请求转换为真实 ACP 会话，限定可用 transport、上下文预算和 JSON 回复合同，并把传输或解析失败明确暴露为模型不可用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="transport-prompt"></a>
## 传输边界与提示组装

`AcpAssistantModel` 是生产环境的模型端口适配器，本身不推理，也不生成兜底答案。只有配置了 `transport=acp` 的 profile 才会调用真实 ACP；缺少 profile 或使用一次性 CLI transport 时会抛出 `ModelUnavailableError`，让上层如实进入待重试或降级流程。[ACP transport 限制 ↗](../../../apps/server/src/assistant/acp-model.ts#L10 "支持生产适配器只接受 ACP profile、拒绝缺失配置和 CLI transport，且不提供伪回答的说明。")

适配器限制历史轮数和单条历史结果长度，并把可见证据、受信纠正、当前任务、时间与时区共同编入提示。材料被明确声明为不可执行指令，模型只能引用给定 evidence id；最多可提出三条补充检索词，且每次回复只能选择一种任务变更。[助手提示与上下文预算 ↗](../../../apps/server/src/assistant/acp-model.ts#L45 "支持历史裁剪、证据隔离、任务及时区上下文、补充检索和单次变更合同。")

<a id="execution-parse"></a>
## ACP 执行与结构化解析

生成阶段通过项目既有 `acp()` 传输发送文本块，仅累计文本输出，并设置输出字符上限。取消信号原样传播，其他传输失败统一包装为模型不可用，避免把基础设施异常伪装为正常回答。[真实 ACP 调用 ↗](../../../apps/server/src/assistant/acp-model.ts#L90 "支持适配器调用真实 ACP、限制输出并区分取消与传输不可用错误。")

解析器从输出中截取 JSON 对象，要求非空 `answer`，过滤 citation 与 search query 类型并限制检索词数量；合法的 `create_task` 或 `update_task` 被转换成结构化工具调用。这里仅完成语法和基本字段筛选，真正的可见性、意图、版本与写入权限仍由运行时治理。[回复 JSON 解析 ↗](../../../apps/server/src/assistant/acp-model.ts#L116 "支持回答、引用、搜索词以及创建或更新任务调用的解析规则，并说明此处仅做结构筛选。")
