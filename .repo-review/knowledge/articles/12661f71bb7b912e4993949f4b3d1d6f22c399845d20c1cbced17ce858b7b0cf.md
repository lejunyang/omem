# ACP 助手模型：受控调查与结构化回复

该适配器把助手运行时的提问、会话、证据和事项上下文交给真实 ACP Agent，并把返回内容收束为可引用的回答、补充检索请求及待宿主治理的事项操作；有知识仓库时优先启用可补读原文的自主调查。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-routing"></a>
## 它解决什么问题

这个类是助手运行时与 ACP Agent 之间的**模型适配层**：自身不推理，也不伪造降级答案，而是负责选择执行路径、约束上下文并把模型输出转成统一回复。它只接受 `transport === "acp"` 的配置；没有 profile 或传入一次性 CLI transport 时，立即抛出 `ModelUnavailableError`。参考 [适配器职责与传输边界 ↗](../../../apps/server/src/assistant/acp-model.ts#L23 "支持该类只复用真实 ACP 传输、不自行推理，并拒绝缺失配置或 CLI transport 的说明。")

`generate` 的关键分流由是否提供知识仓库决定：有仓库就进入可搜索、补读和精确引用原文的自主调查；没有仓库才使用当前文件内的直接提示词路径。调查准备错误会统一包装成模型不可用，取消信号则原样向上传递。参考 [生成入口分流 ↗](../../../apps/server/src/assistant/acp-model.ts#L49 "支持 profile 校验、仓库存在时转入 investigate，以及错误和取消的处理方式。")

<a id="research-flow"></a>
## 一次真实提问怎样完成

以“结合我的材料解释并给出下一步”为例，输入包含问题、历史轮次、初始证据、既有解释、事项、时间与取消信号。调查路径先加载 `daily-assistant` 角色包，建立独立工作区和研究环境，再把问题、模式、检索目的、时钟、历史、事项和初始命中写入权限为 `0600` 的上下文文件。参考 [调查工作区与问题上下文 ↗](../../../apps/server/src/assistant/acp-model.ts#L162 "支持角色包、独立工作区、研究环境及 question-context.json 内容和文件权限的说明。")

```mermaid
flowchart LR
  A[generate 输入] --> B[校验 ACP profile]
  B --> C[准备角色包与研究工作区]
  C --> D[ACP Agent 使用受控工具调查]
  D --> E[环境接收结构化提交]
  E --> F[回复 + researchTrace]
  F --> G[关闭研究环境]
```

随后它把角色技能、研究环境提供的 MCP 服务、权限判断和活动回调交给 `acp()`；Agent 必须通过环境提交完整结果，缺少结果即失败。成功后记录实际协商出的模型、推理强度、会话与工具轨迹，并无论成功失败都关闭环境。参考 [受控 ACP 调查调用 ↗](../../../apps/server/src/assistant/acp-model.ts#L203 "支持调查提示词、技能、MCP 服务、权限策略和 ACP 调用参数构成的流程。") [调查结果与清理 ↗](../../../apps/server/src/assistant/acp-model.ts#L246 "支持必须取得环境提交、记录实际运行轨迹并在 finally 中关闭环境的说明。")

<a id="direct-and-parse"></a>
## 直接路径、输出合同与边界

未提供仓库时，适配器默认只保留最近 10 轮历史，且每条旧回答最多取 500 字符；原始证据被编号为 `cite_N`，提示词同时注入可见性、可信上下文、时间、事项、背景和严格 JSON 形状，再通过 ACP 收集最多 20,000 字符的文本输出。参考 [历史与证据预算 ↗](../../../apps/server/src/assistant/acp-model.ts#L76 "支持直接路径对历史轮数、旧回答长度和证据短标识的处理。") [提示词合同与 ACP 输出 ↗](../../../apps/server/src/assistant/acp-model.ts#L105 "支持直接路径注入上下文、要求结构化 JSON、限制补充检索并调用 ACP 收集输出的说明。")

`parseAssistantReply` 会截取首个 `{` 到最后一个 `}` 之间的 JSON，要求非空 `answer`，过滤引用与最多三个合法检索请求，并把合法的创建或更新事项字段转为 `toolCalls`。这些只是候选操作，不会在本文件内执行。参考 [基础回复与检索解析 ↗](../../../apps/server/src/assistant/acp-model.ts#L283 "支持 JSON 提取、answer 校验、引用过滤和合法检索请求上限的说明。") [事项候选解析 ↗](../../../apps/server/src/assistant/acp-model.ts#L325 "支持创建和更新事项字段被转为单个 toolCalls 数组，以及更新分支可覆盖创建分支的边界。")

解析完成后，短引用会映射回宿主提供的真实证据标识；正文中不存在的短引用会替换为明确的“引用不可用”，创建事项携带的引用也同步映射。一个值得注意的边界是：若输出同时含有效创建和更新，后处理的更新会覆盖先前创建；因此单操作约束仍需上游合同或宿主治理保证。参考 [引用标识回写 ↗](../../../apps/server/src/assistant/acp-model.ts#L371 "支持短引用映射、未知引用降级文案及创建事项引用同步转换的说明。") [事项候选解析 ↗](../../../apps/server/src/assistant/acp-model.ts#L325 "支持创建和更新事项字段被转为单个 toolCalls 数组，以及更新分支可覆盖创建分支的边界。")
