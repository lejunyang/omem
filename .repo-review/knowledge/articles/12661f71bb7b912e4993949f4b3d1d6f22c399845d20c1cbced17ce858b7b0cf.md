# ACP 助手模型：受控回答与自主调查

该适配器把助手运行时的提问转换为真实 ACP 会话：注入知识仓库时进入可搜索、可补读并须结构化提交的自主调查环境；未注入仓库时，以受限提示完成一次性 JSON 回答。它把模型输出整理为回答、引用、补检索请求和事项操作候选，但自身不执行事项持久化。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-routing"></a>
## 把模型接入变成可失败、可治理的边界

这个适配器解决的不是“如何推理”，而是**怎样把助手运行时的上下文交给真实 Agent，并收回结构化结果**。它实现统一的助手模型端口，只接受 ACP profile；缺少 profile 或传入一次性 CLI transport 时立即抛出 `ModelUnavailableError`，不会伪造回答或偷偷换后备模型。参考 [ACP 适配器职责 ↗](../../../apps/server/src/assistant/acp-model.ts#L23 "支持该类只负责真实 ACP 路由、拒绝不支持的 transport，并且不自行推理或伪造回答。")

`generate` 以依赖中是否注入知识仓库为分界：有仓库时进入自主调查，没有仓库时走受限的一次性回答。取消信号保持原错误向上传递；调查准备中的其他异常会被整理为模型不可用错误。参考 [生成路径分流 ↗](../../../apps/server/src/assistant/acp-model.ts#L49 "支持 profile 校验、ACP transport 限制、按是否注入知识仓库分流，以及调查分支的异常处理。")

<a id="representative-flow"></a>
## 一条代表性调用如何完成自主调查

假设运行时传入“这个功能如何实现？”以及当前会话、初始证据、可见事项和时钟。**当依赖中注入知识仓库时**，适配器加载 `daily-assistant` 角色包，为本次请求创建独立工作区，并调用 `prepareAssistantResearch` 准备研究环境；随后把问题、模式、时间、历史轮次、事项、初始命中和已有解释整理成上下文。参考 [研究工作区准备 ↗](../../../apps/server/src/assistant/acp-model.ts#L162 "支持在注入仓库后加载角色包、创建工作区、准备研究环境并整理问题上下文。")

```mermaid
flowchart LR
  A[助手运行时输入] --> B[准备角色工作区与研究环境]
  B --> C[写入问题上下文]
  C --> D[ACP Agent 使用 skill 与 MCP 调查]
  D --> E[环境接收结构化提交]
  E --> F[返回回答、证据与研究轨迹]
```
参考 [研究工作区准备 ↗](../../../apps/server/src/assistant/acp-model.ts#L162 "支持在注入仓库后加载角色包、创建工作区、准备研究环境并整理问题上下文。") [自主调查 ACP 会话 ↗](../../../apps/server/src/assistant/acp-model.ts#L225 "支持 ACP 调用绑定 skills、MCP 服务、权限与会话更新，并要求环境产出提交结果。")

问题上下文会写入权限为 `0600` 的 `question-context.json`，然后发送“准备完成”的研究活动并记录准备耗时；这些动作发生在受保护的 `try` 之前。参考 [调查准备边界 ↗](../../../apps/server/src/assistant/acp-model.ts#L194 "支持上下文文件写入、研究活动通知和准备计时均发生在 try 开始之前。")

ACP 调用会绑定工作区、角色 skills、MCP 服务、权限回调和取消信号；对 Traex 命令还补入工作目录参数。Agent 必须通过研究环境提交完整结果，未提交就视为失败。参考 [自主调查 ACP 会话 ↗](../../../apps/server/src/assistant/acp-model.ts#L225 "支持 ACP 调用绑定 skills、MCP 服务、权限与会话更新，并要求环境产出提交结果。")

进入 `try` 后，ACP 调用、结果校验和轨迹写入无论正常返回还是抛错，`finally` 都会关闭研究环境；但此前的工作区准备、环境创建、上下文写入或活动通知不在这个 `finally` 的保护范围内。成功时，返回值还会带上实际模型、思考强度、会话、工具和耗时组成的 `researchTrace`。参考 [调查准备边界 ↗](../../../apps/server/src/assistant/acp-model.ts#L194 "支持上下文文件写入、研究活动通知和准备计时均发生在 try 开始之前。") [调查清理与轨迹 ↗](../../../apps/server/src/assistant/acp-model.ts#L251 "支持成功路径记录研究轨迹，以及进入 try 后通过 finally 关闭研究环境。")

<a id="direct-mode-and-limits"></a>
## 直连模式的输入收敛与输出边界

没有知识仓库时，适配器只保留最近若干轮历史（默认 10 轮，且每条旧回复截到 500 字符），把证据改写为当轮 `cite_N`，再在提示中声明可引用范围、事项候选合同和最多三条补检索请求。模型文本由 `acp()` 收集，输出上限为 20,000 字符，随后交给解析器。参考 [直连上下文预算 ↗](../../../apps/server/src/assistant/acp-model.ts#L76 "支持历史轮次和旧回复的截断、当轮引用别名及证据块构造。") [直连 ACP 输出 ↗](../../../apps/server/src/assistant/acp-model.ts#L105 "支持提示合同、ACP 文本收集、输出字符上限、取消传播和解析入口。")

解析器从首个 `{` 到最后一个 `}` 截取 JSON；缺少 JSON、JSON 非法或 `answer` 为空都会失败。它过滤非字符串引用，把合法的结构化检索意图限制为三条，并把创建或更新事项转换成 `toolCalls` 候选。`follow_up` 与任务动作还须通过共享 schema；这里仅解析候选，不调用任务存储。若输出同时包含创建与更新，后处理的更新会覆盖创建，因此提示合同要求每次只选一种变更。参考 [回答与检索解析 ↗](../../../apps/server/src/assistant/acp-model.ts#L293 "支持 JSON 边界、必需回答、引用过滤和最多三条结构化检索请求的解析。") [事项候选解析 ↗](../../../apps/server/src/assistant/acp-model.ts#L335 "支持创建和更新事项候选的字段转换、共享 schema 校验，以及更新分支覆盖 toolCalls 的行为；代码只构造返回候选。")

最后，已知 `cite_N` 会映射回固定证据 ID；正文里的未知短引用会被替换成清楚的“引用不可用”提示，创建事项携带的引用也同步映射。由此可见，解析器的职责止于生成和整形 `AssistantModelReply`，包括事项操作候选；它本身不执行事项持久化。参考 [事项候选解析 ↗](../../../apps/server/src/assistant/acp-model.ts#L335 "支持创建和更新事项候选的字段转换、共享 schema 校验，以及更新分支覆盖 toolCalls 的行为；代码只构造返回候选。") [固定引用回映射 ↗](../../../apps/server/src/assistant/acp-model.ts#L381 "支持短引用映射为固定证据 ID、未知正文引用显式失效，以及创建事项引用同步映射。")
