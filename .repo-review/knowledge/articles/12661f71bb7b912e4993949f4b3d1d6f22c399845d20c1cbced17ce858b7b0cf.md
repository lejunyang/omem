# ACP 助手模型：直接回答与自主调查编排

说明生产助手如何把对话、证据、任务与时间上下文交给 ACP 模型，并在知识仓库可用时升级为可补读、可复核的自主调查；同时解释结构化回复、引用回映、任务候选和失败边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-routing"></a>
## 它解决什么问题

这个适配器把上层统一的 `AssistantModelPort` 请求接到真实 ACP 会话，并把模型输出收敛为 `AssistantModelReply`；它自身不做推理，也不会在模型不可用时伪造答案。只有配置了 `transport: "acp"` 的 profile 才能运行，缺少 profile 或误配成一次性 CLI 都会明确报 `ModelUnavailableError`。参考 [ACP 适配器职责 ↗](../../../apps/server/src/assistant/acp-model.ts#L25 "支持适配器使用真实 ACP、拒绝不兼容传输且不伪造答案的说明。")

入口 `generate` 还按是否注入知识仓库分流：有仓库时进入自主调查；没有仓库时走受控的直接回答。这让同一接口既能服务轻量对话，也能在材料不足时使用检索、阅读与复核设施。参考 [入口分流规则 ↗](../../../apps/server/src/assistant/acp-model.ts#L53 "支持 generate 对 profile、transport 和知识仓库存在性进行校验与分流。")

<a id="representative-flow"></a>
## 一条代表性调用怎样完成

以一次无仓库的问答为例：输入含当前问题、历史轮次、证据、背景、任务、可见性和时间。代码只保留最近若干轮历史，并把每条证据换成本轮短引用名；随后将可信上下文、任务约束、时区、证据和严格 JSON 输出合同拼成提示词。参考 [提示词输入装配 ↗](../../../apps/server/src/assistant/acp-model.ts#L80 "支持历史裁剪、证据短 ID 映射以及对话、任务、时间和 JSON 合同的装配流程。")

```mermaid
flowchart LR
  A[AssistantModelPort 输入] --> B[裁剪历史并编号证据]
  B --> C[组装受约束提示词]
  C --> D[调用 ACP]
  D --> E[解析结构化回复]
  E --> F[答案、引用、检索请求或一个任务动作]
```

ACP 只累计文本事件，输出上限为 20000 字符；成功后交给 `parseAssistantReply`。因此这条调用的可观察输出不是原始模型文本，而是已解析的答案、引用、最多三条检索请求，以及可选任务动作候选。传输失败被包装为模型不可用，用户取消则保留取消语义继续上抛。参考 [ACP 调用与结果解析 ↗](../../../apps/server/src/assistant/acp-model.ts#L141 "支持文本事件累计、输出限制、取消传播、传输错误包装和最终解析步骤。")

<a id="research-and-boundaries"></a>
## 自主调查、协作关系与边界

注入仓库后，适配器会通过角色包注册表建立隔离工作区，把回答复核器、知识仓库与检索配置接入调查环境，并以 `question-context.json` 保存问题、历史、当前任务、初始证据和既有解释。这里与 `bundles`、`research`、`answer-review`、`reading-stage` 等模块的关系是**编排调用关系**；目标文件能确认调用和数据传递，但不能单凭这些调用推断各模块内部算法。参考 [调查环境装配 ↗](../../../apps/server/src/assistant/acp-model.ts#L166 "支持角色工作区、回答复核、知识仓库与检索配置的装配，以及问题上下文的写入。")

若配置了 material-first reader，它会先尝试回答。reader 正常结束却未提交结果、显式交接，或在尚无有效已保存答案时发生失败，主 profile 才接手同一快照继续研究；若失败前已经保存有效答案且没有显式交接，异常会继续上抛，不会启动第二位作者。参考 [阅读阶段交接条件 ↗](../../../apps/server/src/assistant/acp-model.ts#L328 "精确支持 reader 未提交、显式交接与异常时是否启动主 profile 的分支条件。")

调查最终必须取得已提交回复和对应 ACP 运行结果，随后记录模型、阶段、耗时和工具轨迹；无论成功还是失败，都会关闭调查与环境资源。参考 [调查结果与资源收尾 ↗](../../../apps/server/src/assistant/acp-model.ts#L401 "支持提交结果检查、轨迹记录，以及成功失败都会执行的资源关闭流程。")

解析器从首个 `{` 到末个 `}` 提取 JSON，要求 `answer` 是非空字符串；顶层引用数组只保留字符串项，检索请求则校验形态与用途并最多保留三条。参考 [回复解析与检索限制 ↗](../../../apps/server/src/assistant/acp-model.ts#L444 "支持 JSON 截取、答案必填、顶层引用仅过滤非字符串项，以及结构化检索请求的校验与数量限制。")

任务候选也有结构门槛：创建任务需要有效标题，更新任务需要任务 ID、整数版本和合法动作。提供引用映射时，已知短引用会还原为原始证据 ID；映射中不存在的字符串 ID 仍会保留在回复引用和创建任务引用中，不会被当作无效引用删除。答案正文中的未知 `cite_N` 标记则会改写为可读的“引用不可用”提示。参考 [任务校验与引用回映 ↗](../../../apps/server/src/assistant/acp-model.ts#L486 "支持任务动作结构门槛，并精确说明已知引用回映、未知字符串 ID 保留及正文未知短引用的替换行为。")
