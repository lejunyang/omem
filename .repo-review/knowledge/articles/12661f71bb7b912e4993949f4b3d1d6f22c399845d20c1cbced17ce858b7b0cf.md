# ACP 助手模型：直接回答与自主调查编排

说明生产助手如何把问题、证据以及历史与当前事项交给 ACP 模型，并在知识仓库可用时升级为可补读、可复核的自主调查；同时解释阅读者交接、结构化回复、项目与工作候选、引用回映和失败边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-routing"></a>
## 它解决什么问题

这个适配器把上层统一的 `AssistantModelPort` 请求接到真实 ACP 会话，并把模型输出收敛为 `AssistantModelReply`。它不自行推理，也不在模型不可用时生成替代答案。运行要求主 profile 使用 `transport: "acp"`；缺少 profile 或误配成一次性 CLI 都会抛出 `ModelUnavailableError`。进入 `generate` 后，代码会先复制 profile，避免后续调查环境对共享配置产生影响。参考 [适配器职责与入口分流 ↗](../../../apps/server/src/assistant/acp-model.ts#L28 "支持真实 ACP 传输要求、无替代答案、profile 复制、上下文策略和知识仓库分流。")

入口按知识仓库是否存在分流。有仓库时进入自主调查，没有仓库时使用调用方已经提供的证据直接回答；`contextStrategy` 也向上层报告同一选择。参考 [适配器职责与入口分流 ↗](../../../apps/server/src/assistant/acp-model.ts#L28 "支持真实 ACP 传输要求、无替代答案、profile 复制、上下文策略和知识仓库分流。")

<a id="representative-flow"></a>
## 一条代表性调用怎样完成

以一次未注入知识仓库的问答为例。输入包括当前问题和历史轮次，以及证据，也可带入背景以及已有事项和时间信息。代码默认只保留最近 10 轮历史，每轮旧答案最多取 500 个字符，并把证据换成本轮短引用名；随后将可信上下文、时区约束和严格 JSON 合同一起装入提示词。合同允许返回答案与引用，还可请求最多三条带用途的补充检索，或提出一项明确的事项动作。参考 [直接回答提示词装配 ↗](../../../apps/server/src/assistant/acp-model.ts#L87 "支持历史预算、证据短引用、背景与时间上下文、结构化输出合同和检索数量限制。")

```mermaid
flowchart LR
  A[AssistantModelPort 输入] --> B[裁剪历史并编号证据]
  B --> C[组装受约束提示词]
  C --> D[调用 ACP]
  D --> E[解析结构化回复]
  E --> F[答案、引用、检索请求或事项动作]
```

ACP 调用只累计文本事件，输出上限为 20000 字符；成功后交给 `parseAssistantReply`。传输失败会包装为模型不可用，用户取消则保留取消语义继续上抛。参考 [ACP 调用与错误传播 ↗](../../../apps/server/src/assistant/acp-model.ts#L148 "支持文本事件累计、20000 字符上限、取消传播、错误包装和解析入口。")

<a id="research-and-boundaries"></a>
## 自主调查、协作关系与边界

知识仓库存在时，适配器会建立隔离的调查环境，接入知识检索、答案复核和阅读阶段。请求属于所有者范围时，还可接入当前事项和消息，以及日程与项目读取能力；答案复核器只取得经过筛选的只读能力。这里与角色包装载、研究准备和答案复核模块的关系是编排与数据传递，目标文件本身没有展开这些模块的内部算法。参考 [调查能力装配 ↗](../../../apps/server/src/assistant/acp-model.ts#L173 "支持调查环境、阅读阶段、复核器及所有者范围内工作能力的装配和只读筛选。")

调查提示会带入当前问题、时间和历史，以及初始证据和已有解释，并要求代理从获准的原件开始补读。它还要求解析当前讨论所属项目，并允许在用户本轮明确授权时提交一个工作动作候选。动作仍需外部执行方确认，回复不能把候选写成已经完成。参考 [调查上下文与行为约束 ↗](../../../apps/server/src/assistant/acp-model.ts#L268 "支持调查所需上下文、原件补读、项目选择、工作动作授权边界和不得声称动作已完成。")

若配置了 material-first reader，它会先尝试回答。reader 正常结束却未提交结果、显式交接，或在尚无有效答案时发生失败，主 profile 才接手同一批固定材料继续调查。reader 失败前已经保存有效答案且没有显式交接时，异常会继续上抛，不会启动第二位作者。参考 [阅读阶段与调查交接 ↗](../../../apps/server/src/assistant/acp-model.ts#L341 "支持 reader 未提交、显式交接、失败及已有有效答案时是否启动主 profile 的分支条件。")

调查最终必须同时取得已提交回复和对应的 ACP 运行结果。返回值会附带实际模型配置和阶段，以及耗时与工具活动；成功或失败都会依次关闭调查环境及相关能力会话。参考 [调查结果与资源收尾 ↗](../../../apps/server/src/assistant/acp-model.ts#L460 "支持完整提交检查、研究轨迹内容，以及成功失败都会执行的资源关闭流程。")

解析器从首个 `{` 到末个 `}` 提取 JSON，并要求 `answer` 是非空字符串。引用数组只保留字符串项；旧式字符串检索词与带用途的结构化检索请求都最多保留三条。项目选择和工作动作存在时，会分别经过对应 schema 校验。参考 [基础回复与检索解析 ↗](../../../apps/server/src/assistant/acp-model.ts#L503 "支持 JSON 提取、答案必填、引用过滤、项目与工作候选校验，以及两种检索结果的数量限制。")

事项动作也有结构门槛：创建需要非空标题，更新需要字符串 ID、整数版本和合法动作。提供引用映射时，已知短引用会还原为原始证据 ID；映射中不存在的字符串 ID仍会保留在回复引用和创建事项引用中。答案正文里的未知 `cite_N` 标记则会改写为可读的“引用不可用”提示。参考 [事项动作与引用回映 ↗](../../../apps/server/src/assistant/acp-model.ts#L560 "支持创建和更新动作的结构门槛，以及已知、未知引用在数组与正文中的不同处理。")
