# 知识撰写角色的结构化输出合同

该文件声明 KnowledgeBatch.v1 的 JSON Schema：一批输出包含 1–16 个知识文档，每份文档由元数据、Markdown 章节、可追溯引用和待确认问题组成。它定义的是静态格式约束，不能单独证明运行时已经执行校验、引用抽取或语义复核。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="document_shape"></a>
## 文档与章节结构

合同将顶层数据限定为版本号和文档数组，并把单批文档数限制为 1–16。文档属性包括键、标题、摘要、分类以及章节；分类覆盖架构、需求、进展、实现、测试、配置和研究等用途。章节数量为 1–20，每节必须提供格式受限的 key、标题与 Markdown 正文，且章节对象不接受额外字段。[文档属性与章节约束 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/output.schema.json#L5 "支持附近关于批量数量、文档属性、分类枚举以及章节必填字段和额外属性限制的说明。")

文档级 required 列表进一步明确：每份文档都必须包含 key、title、summary、category、sections、citations 和 questions，并由 `additionalProperties: false` 排除未声明属性。顶层同样要求 schema_version 与 documents，且拒绝额外属性。[文档与顶层必填约束 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/output.schema.json#L208 "直接支持附近关于文档全部必填字段、文档级额外属性禁用，以及顶层必填字段和额外属性限制的论断。") 这些内容能证明合同如何声明有效数据形状，但不能据此断言实际生成结果已经过运行时验证。

<a id="evidence_and_questions"></a>
## 证据与不确定性表达

引用对象要求人读标签、引用理由、受限关系、目标与 quote；目标可以指向材料或文章，并可携带材料行号或文章章节。关系仅允许 supports、explains、implements、depends_on、calls、contradicts、background 和 tracks。quote 的描述要求留空，由宿主依据固定行范围抽取原文。[引用与问题结构 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/output.schema.json#L78 "支持附近关于引用关系、目标定位、quote 宿主抽取约定及 questions 必填结构的说明。")

questions 最多 20 项，每项必须表达问题、原因、下一步、是否阻塞以及关联引用键。它让未确认事项可以与证据一起结构化保存，而不必伪装成结论。不过，Schema 本身无法证明宿主确实抽取了原文，也不能证明引用语义足以支撑附近论断；这些仍需调用链与行为测试佐证。
