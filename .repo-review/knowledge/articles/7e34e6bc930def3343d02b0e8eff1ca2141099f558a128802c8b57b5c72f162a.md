# 知识文章批量输出合同

该 Schema 定义知识写作角色向宿主提交批量文章时的数据边界：一批包含 1–16 篇文档，每篇由基本信息、Markdown 章节、可追溯引用和待确认问题组成。它约束字段类型、数量、长度、枚举和未知字段，但仅能证明输出格式要求，不能单独证明宿主已完成引用抽取、独立复核或知识发布。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

该合同用于把模型生成的知识文章变成宿主能够稳定校验和处理的结构化数据。顶层固定为版本号与文档数组，一次允许提交 1–16 篇；每篇必须提供键、标题、摘要、类别、章节、引用和问题清单。类别覆盖概览、架构、需求、进展、实现、测试、配置、工作流等常见 Wiki 主题，方便后续按用途组织内容。参考 [批量文档基本结构 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/output.schema.json#L1 "支持顶层版本、文档批次规模以及每篇文档基本字段和类别范围的说明。")

<a id="article_structure"></a>
## 文章、章节与引用如何组织

文章正文由 1–20 个章节组成；章节包含稳定键、标题和 Markdown 正文，并禁止额外字段。引用是独立结构：除人读标签和引用理由外，还要声明关系类型以及材料或文章目标；材料目标可定位到固定行号，文章目标可定位到章节。`quote` 字段仍是必填项，但说明要求保持为空，精确引文由宿主依据固定范围抽取。这一设计把作者选择证据位置与宿主复制原文分开，有利于后续复核。参考 [章节与引用合同 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/output.schema.json#L48 "支持章节数量与字段、引用关系、目标定位方式以及 quote 由宿主抽取的说明。")

<a id="validation_boundary"></a>
## 校验范围与能力边界

合同同时定义待确认问题，可记录问题、原因、下一步、是否阻塞以及关联引用，适合保留证据不足或需要选择的事项。各层普遍设置长度、数量和格式限制，并通过 `additionalProperties: false` 拒绝未声明字段。参考 [问题字段与严格校验 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/output.schema.json#L166 "支持待确认问题的数据结构、文档必填字段和禁止额外属性的说明。")

需要注意：这份文件是输出结构规范，只说明什么 JSON 可以通过结构校验；它没有展示引用是否真实支持论断、行号是否存在、文档键是否覆盖任务目标，也不能据此认定独立 verifier、发布流程或运行时处理已经实现。
