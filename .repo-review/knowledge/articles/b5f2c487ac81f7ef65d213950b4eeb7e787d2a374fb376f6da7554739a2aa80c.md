# LearningPipeline 端到端实时冒烟验证

在临时数据库中捕获带可信 provenance 的任务文本，启动真实 LearningPipeline 排空作业，要求提取与复核两个作业成功、提案已应用且产生一个任务，并保存模型、尝试和通知诊断报告。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="setup"></a>
## 受控输入与流水线组装

脚本从配置选择 `traex` 实时 profile，在临时目录创建 Store，并捕获一条支付重试任务。输入带应用上下文以及经过本地测试标记的 owner、事件时间、时区和 original provenance，使流水线从真实 Capture/Revision 入口开始。[临时 Store 与任务捕获 ↗](../../../scripts/live-pipeline-smoke.ts#L13 "支持测试从真实捕获入口构造带上下文和 provenance 的受控输入。")

随后它组合 Store、MemoryService、FeedbackService、profile、工作区根目录和独立 worker id 来构造 `LearningPipeline`，体现流水线依赖持久化、记忆策略、反馈服务和 Agent 运行配置，而不是在脚本中手动调用 extractor/verifier。[LearningPipeline 依赖组装 ↗](../../../scripts/live-pipeline-smoke.ts#L46 "支持流水线与 Store、MemoryService、FeedbackService、profile 和 worker 的模块关系。")

<a id="assertions"></a>
## 排空与端到端断言

`drain(10)` 处理有限数量作业，随后主动停止流水线。脚本读取 jobs、每个 job 的 attempts、proposals 和 tasks，并联合断言：恰好处理 2 个作业、所有作业均 succeeded、恰好一个 proposal 且状态为 applied、恰好生成一个任务；任一条件不满足都会失败。[端到端状态断言 ↗](../../../scripts/live-pipeline-smoke.ts#L55 "支持处理两个作业、作业成功、单一提案已应用及生成一个任务的验收条件。") 这比手工角色脚本更侧重调度与持久状态，间接覆盖 capture 后的提取、复核和应用流程。

<a id="report"></a>
## 诊断证据与未覆盖行为

报告记录请求与实际模型/effort、捕获修订、作业及尝试、提案、任务和通知数量，并写入可配置路径；控制台输出压缩摘要。[流水线验证报告 ↗](../../../scripts/live-pipeline-smoke.ts#L69 "支持报告保存请求/实际模型、attempt、提案、任务和通知等诊断信息。") 最后无条件关闭 Store 并删除临时目录。[流水线临时数据清理 ↗](../../../scripts/live-pipeline-smoke.ts#L113 "支持测试结束时关闭 Store 并删除隔离目录的说明。")

测试没有断言任务具体字段、attempt 次数、通知数量或模型必须与请求一致，也没有覆盖失败重试、暂停恢复、重复 capture 幂等和超过 drain 上限的积压。它依赖真实模型输出稳定地产生单一可自动应用任务，因此失败既可能来自流水线缺陷，也可能来自外部模型或 Agent CLI 状态。
