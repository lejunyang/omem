# 真实模型学习流水线冒烟验证

该脚本以临时 SQLite 数据库和真实 TraeX 配置运行一次受控学习流水线，验证一条带负责人和截止时间的中文捕获能经过两个作业，形成并自动应用一个任务，同时保存模型、作业、提案和任务的可审计报告。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决的问题与验证范围

该脚本不是普通单元测试，而是面向真实 Agent 配置的端到端冒烟检查：加载配置后查找 `traex` profile，并通过 live profile 选择逻辑取得实际可运行的模型；缺少该配置时立即失败。随后创建隔离的临时 `Store`，避免污染正式数据。[真实配置选择与临时存储初始化 ↗](../../../scripts/live-pipeline-smoke.ts#L13 "支持脚本依赖 traex 配置、选择 live profile，并以临时目录隔离 Store 的论断。")

输入是一条人工捕获的中文任务陈述，包含负责人、明确截止时间、预备动作、应用上下文和完整来源信息。这使验证目标聚焦于“原始材料能否被学习链路识别为可执行事项”，而非只检查协议解析或固定 fixture。[中文任务捕获样本 ↗](../../../scripts/live-pipeline-smoke.ts#L20 "支持输入包含截止时间、动作、上下文和来源元数据，以及验证目标面向真实捕获链路的说明。")

<a id="flow"></a>
## 核心执行流程与模块关系

捕获写入后，脚本用同一 `Store` 构造 `MemoryService`、`FeedbackService` 和 `LearningPipeline`，并把选定 profile、工作区根目录及 worker 标识注入流水线。这里与配置、持久化、记忆策略和学习执行模块的关系均由显式导入与构造调用确认；材料未展示流水线内部如何拆分两个作业，因此不能进一步断言具体角色或调用顺序。[学习流水线依赖组装 ↗](../../../scripts/live-pipeline-smoke.ts#L46 "支持 MemoryService、FeedbackService、LearningPipeline、profile、工作区和 worker 共享同一 Store 运行的流程描述。")

脚本调用 `drain(10)` 主动处理队列并停止 pipeline，然后从存储中读取作业、尝试记录、提案和任务。验收条件要求恰好处理两个作业、所有作业成功、恰好一个提案且已应用，并最终生成一个任务；任一条件不满足都会抛错。[流水线执行与结果断言 ↗](../../../scripts/live-pipeline-smoke.ts#L55 "支持 drain、stop、结果查询及对两个成功作业、一个已应用提案和一个任务的硬性断言。")

<a id="evidence-limits"></a>
## 报告、清理与未覆盖边界

成功后生成审计报告，记录请求与实际生效的模型和 effort、捕获 revision、逐作业尝试、提案、任务及通知数量。报告路径可由环境变量覆盖，默认写入验证目录；目录和文件分别使用较严格权限，控制台只输出摘要。[验证报告生成与落盘 ↗](../../../scripts/live-pipeline-smoke.ts#L69 "支持报告记录模型、effort、作业尝试和业务产物，并允许覆盖输出路径及设置文件权限的说明。")

`finally` 无条件关闭数据库并递归删除临时目录，所以失败路径也会清理运行数据，而已写到临时目录之外的报告可保留。[临时资源清理 ↗](../../../scripts/live-pipeline-smoke.ts#L113 "支持无论成功或失败都会关闭 Store 并删除临时运行目录的边界说明。") 断言只验证数量和状态，没有核对任务标题、负责人、截止时间、证据引用或通知内容；通知数量也只是记录而非成功条件。因此它能证明受控 live 链路产出了一个已应用任务，但不能单独证明语义提取完全正确，也未覆盖缺少凭据、模型超时、坏输出、重试上限及多条输入等异常行为。
