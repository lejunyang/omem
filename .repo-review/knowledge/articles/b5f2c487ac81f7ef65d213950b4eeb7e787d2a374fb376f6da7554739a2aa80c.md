# 真实模型驱动的任务提取冒烟验证

该脚本在临时单用户存储中写入一条带截止时间的中文事项，调用实际 Agent 配置运行学习流水线，并以任务、提案和作业状态验证端到端链路，最后输出可审计报告并清理运行数据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 验证什么问题

脚本用于确认“捕获一句自然语言承诺后，系统能否经真实模型处理形成已应用任务”这一关键场景。它加载配置并选择 `traex` 实时 profile；若该 profile 不存在会立即失败。随后创建隔离的临时存储，写入一条“本周五 18:00 前补齐支付重试方案”的人工捕获，同时保留应用、时间、操作者与来源事件等上下文。参考 [受控中文事项输入 ↗](../../../scripts/live-pipeline-smoke.ts#L13 "支持脚本选择实时 profile、建立临时存储并捕获带上下文中文任务承诺的说明。")

这属于**受控的端到端冒烟验证**：它覆盖真实配置、持久化、学习流水线和任务落库之间的连接，但输入只有一个固定中文样例，不能代表所有表达方式、时区或模型输出都已验证。

<a id="flow"></a>
## 从捕获到任务的核心流程

脚本把同一个 `Store` 注入 `MemoryService`、`FeedbackService` 与 `LearningPipeline`，并把选中的模型 profile、工作目录和 worker 标识交给流水线。之后调用 `drain(10)` 消费当前作业并显式停止流水线，再从存储中读取作业、执行尝试、记忆提案和任务用于统一判定。参考 [学习流水线执行流程 ↗](../../../scripts/live-pipeline-smoke.ts#L46 "支持服务装配、作业消费、停止流水线以及读取提案和任务的核心流程。")

```mermaid
flowchart LR
  A[写入人工捕获] --> B[学习流水线处理]
  B --> C[生成并应用提案]
  C --> D[形成任务]
  D --> E[汇总执行报告]
```

这里与其他模块的关系有直接源码依据：`Store` 提供捕获和作业、任务、通知查询，`MemoryService` 提供提案读取，`LearningPipeline` 负责消费作业；但所给流水线材料未展示其构造器及任务生成分支，因此不能仅凭该脚本确定两个已处理作业各自对应的内部阶段。

<a id="assertions"></a>
## 成功条件、报告与边界

成功条件是：恰好处理两个作业、所有作业均为 `succeeded`、只产生一个提案且状态为 `applied`，并且最终只有一个任务；任一条件不满足都会抛错。这个断言证明固定样例形成了单个已应用任务，却没有核对任务标题、截止时间、证据引用、通知内容或重复运行的幂等性。参考 [端到端成功断言 ↗](../../../scripts/live-pipeline-smoke.ts#L61 "支持已处理作业数、作业状态、已应用提案和单个任务这组明确成功条件。")

通过后，脚本记录请求与实际生效的模型和 effort、作业尝试、提案、任务及通知数量；报告路径可由环境变量覆盖，文件和目录使用受限权限。控制台只输出摘要，详细数据保存在 JSON 报告中。参考 [模型执行报告 ↗](../../../scripts/live-pipeline-smoke.ts#L69 "支持报告包含模型、effort、作业尝试和产物，并写入可配置路径的说明。")

无论成功或失败，`finally` 都会关闭数据库并递归删除临时目录，因此运行数据不会作为长期状态保留；报告写在临时目录之外时仍可留作验收证据。参考 [临时数据清理 ↗](../../../scripts/live-pipeline-smoke.ts#L113 "支持脚本无论执行结果如何都会关闭存储并删除临时运行目录的边界说明。")
