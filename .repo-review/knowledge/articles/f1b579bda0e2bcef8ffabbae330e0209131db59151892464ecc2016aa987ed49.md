# 飞书运行宿主的装配、投递与事件接入测试

该测试验证飞书运行宿主在生产式配置下能够启动连接、投递待办通知、接收群聊事件并安全停止；同时检查健康接口暴露运行概要，并确认宿主运行状态不包含客户端密钥。它主要覆盖成功路径，尚未直接验证禁用、缺少主密钥、发送失败及重复事件等分支。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 验证生产宿主可以启用

这组测试面向“应用启用飞书集成后，运行宿主是否真正工作”的场景。第一项用临时目录和随机主密钥构建应用，明确开启飞书功能，随后断言宿主正在运行、连接数为零且没有错误；健康接口也应返回运行中和连接数等概要。参考 [应用启用与健康概要 ↗](../../../apps/server/tests/lark-runtime.test.ts#L59 "支持显式开启飞书并提供主密钥后宿主能够装配，以及健康接口返回运行概要的论断。")

测试通过 `buildApp` 进入应用装配层。运行宿主本身组合存储、记忆、接入服务、密钥仓库及可替换的实时和消息适配器，因此这里验证的是多个模块协作后的可运行性，而非单个类的孤立行为。参考 [运行宿主依赖组成 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L36 "说明运行宿主组合存储、记忆、接入、密钥及可替换适配器等模块。")

<a id="runtime-flow"></a>
## 从活跃绑定到通知投递

第二项预先写入活跃连接、连接版本、绑定和通知目标，再用伪实时适配器与伪消息适配器启动宿主。创建一项待通知任务并执行一次处理循环后，测试要求宿主建立一个连接、完成一次投递，并将消息发送到预置应用及会话，说明运行时会依据活跃绑定选择投递目标。参考 [通知处理循环 ↗](../../../apps/server/tests/lark-runtime.test.ts#L175 "支持任务进入处理循环后完成一次投递、建立一个连接并选择预置会话目标的论断。")

伪消息适配器遵循正式消息端口的 `send` 与 `update` 合同，记录应用、密钥、会话和卡片等出站参数，使流程可以在不访问真实飞书服务的情况下验证。参考 [消息适配器合同 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L35 "说明测试伪实现遵循发送与更新接口，并记录投递所需的应用、密钥、会话和卡片参数。")

<a id="events-and-limits"></a>
## 事件记录、动态目标与测试边界

测试随后经已建立的实时连接注入一条群聊消息，断言连接能力档案记录该事件类型，并为群聊建立启用捕获的监控目标；停止宿主时，底层连接还必须恰好关闭一次。参考 [入站事件与连接关闭 ↗](../../../apps/server/tests/lark-runtime.test.ts#L212 "支持群聊事件更新能力档案、创建捕获目标，并在宿主停止时关闭实时连接的断言。") 宿主状态序列化结果不得包含测试客户端密钥，覆盖了直接从运行状态泄密的风险。参考 [运行状态密钥保护 ↗](../../../apps/server/tests/lark-runtime.test.ts#L208 "支持宿主状态序列化结果不得包含测试客户端密钥的安全断言。")

现有用例主要证明正常启动、成功发送和单次事件接入。它没有直接覆盖飞书被禁用或缺少主密钥时的装配结果，也未验证鉴权失败、限流、投递重试、重复事件、消息更新和进程崩溃后的恢复，因此不能从这组成功路径推断这些语义。
