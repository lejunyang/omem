# 代码知识图的快照化 SQLite 投影

在同一评审数据库中维护可重建的仓库、快照、文件、符号、边和理解结果侧表，以内容寻址标识、复合快照主键和显式 head 指针保留历史状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="identity"></a>
## 定位与身份模型

该存储层不是新的源码事实库，而是已捕获 Revision/Fragment 之上的确定性投影，不自行保存权威文件正文。文件、符号、边和快照使用稳定哈希生成标识；符号身份刻意不含行号，使同一路径、限定名和种类在移动行位置后仍可对应。边未在当前解析重现或触及已删除文件时只标记为过期，不删除历史。[代码侧表身份规则 ↗](../../../apps/server/src/code/store.ts#L1 "说明侧表是捕获链投影、各类稳定标识的组成及过期而不删除的原则。")

<a id="schema-history"></a>
## 按快照保留历史

符号和边以“稳定标识＋快照标识”为复合主键，避免 A→B→A 时覆盖旧范围、片段和关系。旧单主键表会先改名、复制并核对数量，确认无丢失后才移除临时表。[符号与边的历史迁移 ↗](../../../apps/server/src/code/store.ts#L125 "支持复合快照主键和保留旧表数据的迁移流程。") 每个快照还固定关联 Capture revision、内容哈希及兼容用正文列；读取时优先从不可变 revision 还原精确文本，再回退到快照保存的正文。[快照文件固定绑定 ↗](../../../apps/server/src/code/store.ts#L446 "说明快照如何绑定评审 revision、哈希和固定文本，以及读取时的优先级。")

<a id="head-queries"></a>
## 当前视图与历史查询

仓库用显式 `current_snapshot_id` 表示当前 head，不能仅按捕获时间推断，因为重回旧内容会复用原快照。[显式当前快照指针 ↗](../../../apps/server/src/code/store.ts#L273 "支持不能按捕获时间判断 head、必须由同步显式切换的设计。") 文件符号、相邻边和整图查询默认限定到该 head；历史图仍展示当时存在而现在删除的文件，当前图则隐藏 removed 文件，过期边默认也被过滤。[快照范围查询 ↗](../../../apps/server/src/code/store.ts#L541 "支持符号、边和图查询按当前或指定快照过滤，以及历史删除文件的展示差异。") 这使 API 能在当前视图与指定快照间切换，而不破坏旧状态。

<a id="writes-and-understanding"></a>
## 幂等写入与理解记录

快照、文件、符号和边均采用 upsert；同一快照首次捕获时间保持不变，符号范围与片段只更新该快照内的记录。[快照与符号幂等写入 ↗](../../../apps/server/src/code/store.ts#L694 "支持首次捕获时间稳定以及符号按复合键更新的写入语义。") 未重现的边会在指定快照内变为 `stale`，其他快照不受影响。确定性理解只记录解析统计、未知项和证据引用，并明确使用 deterministic 角色、空模型与 `CodeUnderstanding.v1`，不会伪装成模型总结。[过期边与确定性理解 ↗](../../../apps/server/src/code/store.ts#L863 "支持边只在本快照失效，以及确定性理解不冒充模型输出的结论。")
