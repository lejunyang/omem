# 代码知识图谱的 SQLite 持久化与快照读取

该模块在主 SQLite 中维护代码仓库、快照、文件、符号、关系边与理解记录。代码图是 Capture 证据的派生视图，但快照层保存固定修订绑定及不可变文本副本；符号和边按快照保留，当前状态由显式 head 指针确定。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-model"></a>
## 作用与数据模型

该文件把已捕获代码投影为可查询的仓库、快照、文件、符号和关系边。文件、符号、边及快照身份由仓库、路径、符号定位、解析器版本与内容摘要确定，可在重复同步时稳定复用。[确定性代码身份规则 ↗](../../../apps/server/src/code/store.ts#L4 "支持代码图由捕获材料派生，以及文件、符号、边和快照使用确定性身份的论断。") 需要替代旧结论的是：代码图仍不是独立事实权威，但并非完全“不保存文件正文”；`code_snapshot_files` 包含固定修订、内容摘要和 `content_text` 字段，后者被明确作为逐快照的不可变源码副本。[逐快照源码副本字段 ↗](../../../apps/server/src/code/store.ts#L190 "支持快照文件表保存固定修订、摘要和文本副本，并证明该字段被定义为不可变的逐快照源码文本。") 写入采用冲突时不覆盖，读取固定修订失败时才使用该副本，因此它承担历史读取回退。[不可变快照文件写入与读取 ↗](../../../apps/server/src/code/store.ts#L446 "支持冲突时不覆盖的快照绑定写入，以及固定修订不可读时回退到 content_text 的具体行为。") 这些表使用应用主 `Store` 的数据库连接，仍属于统一 SQLite 存储，而非另一套代码知识库。[主 SQLite Store 初始化 ↗](../../../apps/server/src/store.ts#L38 "说明代码侧表使用应用主 Store 的数据库连接，属于统一存储上的附加视图。")

<a id="sync-and-history"></a>
## 同步、迁移与历史保留

符号和边以“实体 ID + 快照 ID”为联合主键。旧版单键表迁移时先重命名，再复制全部历史行并校验数量，避免范围、Fragment 或边在 A→B→A 状态往返中被覆盖。[符号与边的历史保留迁移 ↗](../../../apps/server/src/code/store.ts#L125 "支持联合快照主键、旧表复制、行数校验及历史不丢失的迁移流程。") 快照写入保持幂等：同一身份复用已有行并保留首次 `captured_at`，只更新计数、基线和 partial 等状态。[幂等快照写入与首次捕获时间 ↗](../../../apps/server/src/code/store.ts#L694 "直接支持同一快照身份复用已有 captured_at，并只更新部分状态字段的论断。") 当前状态则由每次同步显式切换仓库 head，不能按捕获时间推断。[显式当前快照指针 ↗](../../../apps/server/src/code/store.ts#L273 "解释快照复用时为何不能按捕获时间判断当前状态，以及同步应显式更新 head。") 图视图默认读取当前 head，也可指定历史快照；当前视图隐藏已删除文件，历史视图保留其快照绑定，并默认排除 stale 边。[按快照构建图视图 ↗](../../../apps/server/src/code/store.ts#L599 "支持当前与历史文件可见性差异，以及默认过滤 stale 边的读取规则。") 未在本轮解析中重现或连接已删除文件的边，仅在所属快照内标记 stale，不影响其他快照。[快照内失效边标记 ↗](../../../apps/server/src/code/store.ts#L863 "支持仅在指定快照内按 live seed 和已删除文件标记 stale、保留其他快照历史的说明。")

<a id="fixed-source-reading"></a>
## 固定源码读取与两类回退

`upsertSnapshotFile` 一次性绑定路径、评审修订、摘要和文本副本，并以 `ON CONFLICT ... DO NOTHING` 保持既有快照内容不变；`snapshotFileBinding` 会先尝试固定修订正文，失败后再回退到 `content_text`。[不可变快照文件写入与读取 ↗](../../../apps/server/src/code/store.ts#L446 "支持冲突时不覆盖的快照绑定写入，以及固定修订不可读时回退到 content_text 的具体行为。") 固定修订读取只接受 `verbatim-v1`，缺失或有损 Capture 返回空值，避免用当前工作树伪造历史证据。[固定 Capture 修订正文提取 ↗](../../../apps/server/src/source-text.ts#L3 "支持只接受 verbatim-v1 精确文本并拒绝从当前工作树重建旧证据的边界。") 另一入口 `snapshotSourceText` 的语义更严格：它先查询 `code_snapshot_sources`；只要该行存在，就直接返回 `revisionText` 的结果，即使结果为空也不会继续读取 `code_snapshot_files`。只有 sources 行不存在时，才走文件绑定及其文本副本回退。[双路径快照源码读取条件 ↗](../../../apps/server/src/code/store.ts#L950 "支持 sources 行存在时直接返回 revisionText、仅在该行不存在时才读取 snapshot files 的精确条件。") 因而“两套绑定之间的回退”与“单个文件绑定内部的修订到文本回退”是不同条件，不能合并描述。

<a id="query-boundaries"></a>
## 查询边界与待确认风险

多数查询显式限定快照：文件符号默认使用当前 head，也可传入历史快照；关系边同样按当前或指定快照隔离。[带快照约束的图查询 ↗](../../../apps/server/src/code/store.ts#L541 "支持文件符号和关系边通常按当前或指定快照隔离的说明。") 但 `symbolById` 只按符号 ID 查询，而联合主键允许同一符号在多个快照各有一行，故范围、签名和 Fragment 来自哪个版本没有确定顺序保证。[未限定快照的符号查询 ↗](../../../apps/server/src/code/store.ts#L559 "支持 symbolById 只按符号 ID 查询、在复合主键模型下可能返回不确定历史版本的风险判断。") 该模块负责持久化与读取，并不证明解析所得关系在语义上正确；提供材料也未包含测试文件，因此无法据此确认迁移、快照复用、固定源码回退和 stale 隔离已有自动化行为覆盖。
