# 代码知识存储：不可变快照、图投影与理解结果索引

该模块在隔离 review SQLite 中维护仓库、快照、文件、符号、边和理解结果；显式 head 区分当前图与历史图，Capture revision 与按快照固定文本共同保障历史源码读取。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="model"></a>
## 身份、历史与源码事实

文件、符号、边和快照采用确定性标识；符号标识不含范围，范围与 fragment 归属于具体快照。[代码图稳定身份规则 ↗](../../../apps/server/src/code/store.ts#L7 "支持文件、符号、边和快照的确定性标识，以及符号范围属于具体快照。") 符号和边使用包含 snapshot 的复合主键，旧单键表迁移时复制并核对行数，避免 A→B→A 往返覆盖旧状态。[符号与边的历史保留迁移 ↗](../../../apps/server/src/code/store.ts#L125 "支持复合快照主键、旧表复制核验及防止往返状态覆盖历史记录。")

此前“代码图完全不保存文件正文”的结论已被替代：Capture revision 仍是读取首选，但快照文件绑定也保存固定 `content_text`；revision 不可读时回退到该文本副本。[快照源码副本与回退 ↗](../../../apps/server/src/code/store.ts#L446 "支持按快照固定源码文本，并在 Capture revision 无法读取时回退到该副本。")

<a id="readWrite"></a>
## 幂等同步、head 与图读取

同步写路径对仓库、快照、文件、符号和边采用冲突更新；同一快照复用原有 `captured_at`，保留首次捕获时间。[仓库、快照与图元素写入 ↗](../../../apps/server/src/code/store.ts#L674 "支持冲突更新式幂等写入，并直接证明相同快照保留首次 captured_at。") 当前状态由仓库的 `current_snapshot_id` 显式切换，不能仅按捕获时间推断，因为工作树回到旧状态时会复用旧快照。[显式当前快照指针 ↗](../../../apps/server/src/code/store.ts#L273 "解释为何不能用捕获时间推断 head，以及同步应显式切换当前快照。")

图读取默认使用当前 head：当前图隐藏 removed 文件，指定历史快照则保留该快照绑定的文件；除非显式要求，stale 边会被过滤。[当前与历史图视图 ↗](../../../apps/server/src/code/store.ts#L599 "支持当前图隐藏 removed 文件、历史图保留快照文件，并默认过滤 stale 边。") 未在本轮重现或触及删除文件的边只在指定快照内标记 stale，不删除其他快照记录。[快照内过期边失效 ↗](../../../apps/server/src/code/store.ts#L863 "支持仅将指定快照中未重现或触及删除文件的边标为 stale。")

<a id="understanding"></a>
## 理解结果与接口边界

确定性 profiler 以明确角色写入结构化结果、unknowns 与证据引用，模型和 effort 留空，不把解析统计伪装成模型理解。[确定性理解记录 ↗](../../../apps/server/src/code/store.ts#L899 "支持无模型 profiler 的角色、未知项、证据记录和空模型字段。") 当前仓库标识由函数固定返回 `omem`，因此仍是单仓 PoC，而不是通用多仓隔离实现。[固定仓库标识 ↗](../../../apps/server/src/code/store.ts#L40 "直接支持当前代码使用固定 omem 标识、属于单仓 PoC 的边界。")

`symbolById` 只按 symbol id 查询，既不限定 snapshot 也不排序；复合主键允许同一符号跨快照存在，因此该接口返回当前 head、历史行还是任意行并无明确合同。[未限定快照的符号查询 ↗](../../../apps/server/src/code/store.ts#L559 "支持 symbolById 仅按符号标识查询且没有 snapshot 条件或排序。")
