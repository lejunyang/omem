# 版本化代码图的持久化与历史读取

该存储层在现有单用户 SQLite 中保存代码快照、文件、符号、关系边和理解结果。代码结构是捕获材料的派生视图，同时会为每个快照保存当时的不可变文件正文副本，以便固定 revision 不可用时仍能读取历史文本。它提供独立的写入、失效、指针切换和查询原语，但同步顺序、事务边界及关系边的上游解析可信度仍需结合编排模块确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-identity"></a>
## 解决代码变化后的可追溯阅读

该层把已捕获材料投影为代码结构，并以附加表形式与评审数据共处同一 SQLite，不改写来源、修订、片段或评审关系。参考 [派生表存储边界 ↗](../../../apps/server/src/code/store.ts#L1 "支持代码图是同一评审 SQLite 中的附加派生视图，且不改写原始捕获相关表。") 与早期概括不同，它确实在 `code_snapshot_files` 中保存每个快照捕获的正文副本；这不是读取当前工作树得到的临时内容，而是历史快照的一部分。参考 [快照正文表 ↗](../../../apps/server/src/code/store.ts#L197 "证明附加表包含每快照的 content_text 正文列，修正“不保存文件正文”的误导性概括。")

各种实体采用**确定性稳定标识**：仓库是固定 slug，文件由仓库与路径确定，符号由路径、限定名和类型确定，边由调用方提供的 seed 确定；只有快照身份明确结合解析器版本、提交状态和内容哈希。参考 [确定性身份规则 ↗](../../../apps/server/src/code/store.ts#L40 "分别说明仓库、文件、符号、边和快照标识的输入，支持仅将快照称为内容相关身份。") 底层 `Store` 当前明确是单用户 SQLite，团队级约束仍属于后续迁移。参考 [单用户存储边界 ↗](../../../apps/server/src/store.ts#L4 "支持当前 SQLite 实现为单用户基础、团队级约束尚未实现。")

<a id="snapshot-history"></a>
## 保留快照结构与迁移历史

符号和关系边都以“自身标识 + 快照标识”为复合主键，使相同符号或边可以在多个历史状态中并存。设计动机是避免工作树经历 A→B→A 时，旧实现按单一标识更新而覆盖历史记录。参考 [快照历史迁移动机 ↗](../../../apps/server/src/code/store.ts#L125 "解释单一主键曾覆盖 A→B→A 历史记录，以及迁移必须保留旧快照行的原因。") 参考 [符号与边复合主键 ↗](../../../apps/server/src/code/store.ts#L148 "支持符号和关系边均按自身标识与快照标识组成复合主键。")

旧符号表和旧边表会分别复制到复合主键结构，并在删除临时表前核对迁移行数；因此迁移目标是保留无法再次由当前解析器推导的历史数据，而不是重新生成它们。参考 [符号历史迁移 ↗](../../../apps/server/src/code/store.ts#L162 "支持旧符号行被复制、核对数量后才移除临时表。") 参考 [关系边历史迁移 ↗](../../../apps/server/src/code/store.ts#L206 "支持旧关系边被复制、核对数量后才移除临时表。")

<a id="storage-capabilities"></a>
## 写入、失效与历史读取能力

本文件提供若干可由同步编排器组合的存储原语：快照写入会复用相同身份并保留首次捕获时间；符号和边只在对应快照的复合键内更新。参考 [快照幂等写入 ↗](../../../apps/server/src/code/store.ts#L694 "支持相同快照身份复用既有记录并保留首次捕获时间。") 参考 [符号与关系边写入 ↗](../../../apps/server/src/code/store.ts#L789 "支持符号和边以快照复合键更新，并表明边标识取决于上游提供的 seed。") 未在本轮重新产生、或连接已删除文件的边，可在指定快照内标记为 `stale`，其他快照不受影响。参考 [快照内过期边处理 ↗](../../../apps/server/src/code/store.ts#L863 "支持仅在指定快照中将未重现或连接已删除文件的关系边标记为过期。") 这些函数彼此独立，现有材料不能据此断言它们的实际调用顺序或是否处在同一外层事务中。

当前版本由仓库上的显式头指针表示，不能简单按捕获时间推断，因为回到旧内容时可能复用既有快照。参考 [显式当前快照指针 ↗](../../../apps/server/src/code/store.ts#L273 "解释回到旧内容时为何不能按捕获时间推断当前版本，以及显式头指针的用途。") 文件符号、相邻边和整图查询默认使用当前快照，也允许指定历史快照；通常会过滤过期边。参考 [按快照查询代码图 ↗](../../../apps/server/src/code/store.ts#L541 "支持符号、关系边和整图默认按当前快照查询，也可读取指定历史快照并过滤过期边。")

快照文件绑定同时保存固定评审 revision 和不可变正文。读取时优先取固定 revision 的逐字文本，失败后回退到快照正文副本。参考 [快照文件正文绑定 ↗](../../../apps/server/src/code/store.ts#L446 "支持保存固定 revision 与正文副本，并在读取时优先使用 revision、失败后回退正文副本。") 固定 revision 只有采用逐字捕获格式时才返回文本，不会从当前工作树重建历史证据。参考 [固定修订文本读取 ↗](../../../apps/server/src/source-text.ts#L3 "支持仅返回逐字捕获的 revision 文本，避免从当前工作树重建历史证据。")

<a id="trust-boundaries"></a>
## 理解结果与查询边界

无模型 profiler 可以把实际解析结果、未知项和证据写为确定性理解记录，并明确使用确定性角色；这类记录不能等同于独立模型复核后的知识。参考 [确定性理解记录 ↗](../../../apps/server/src/code/store.ts#L899 "支持 profiler 只记录解析事实、未知项和证据，并明确使用确定性角色。") 本文件只负责关系边的持久化、查询与失效，没有展示 seed、状态和 evidence 如何由 AST 或跨文件解析产生，因此不能仅凭已入库关系判断调用目标已经正确解析。

两个单项查询需要调用方特别约束：`symbolById` 只按符号标识查询，没有快照条件；当同一符号在多个快照中存在时，返回版本并不由该函数明确保证。参考 [符号单项查询 ↗](../../../apps/server/src/code/store.ts#L566 "证明 symbolById 仅按符号标识查询，没有限定快照。") `understandingOf` 也只按目标与生成时间选取记录，没有过滤目标快照、状态或过期标记。参考 [理解结果选择规则 ↗](../../../apps/server/src/code/store.ts#L623 "证明 understandingOf 按目标与生成时间取一条记录，但未限定快照、状态或过期标记。") 需要版本精确性的入口应使用显式快照查询，或在上层核对返回记录的快照与状态。
