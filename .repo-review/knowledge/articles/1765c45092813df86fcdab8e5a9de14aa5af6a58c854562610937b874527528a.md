# 自包含离线原型构建脚本

使用 esbuild 将 React 入口压缩为 IIFE，并把脚本、样式、第三方声明和可编辑视觉参数内联到单个中文 HTML 文件。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="build-flow"></a>
## 构建流程

脚本以 `app.jsx` 为唯一 JavaScript 入口，调用 esbuild 完成依赖打包、生产环境常量替换和压缩，但先保留产物在内存中。[esbuild 打包配置 ↗](../../../docs/prototype/build.mjs#L2 "说明入口、内存输出、压缩、IIFE 格式及生产环境替换。") 随后读取样式表与第三方声明，转义打包脚本中的 `</script`，避免内联内容提前结束 HTML 脚本标签。[资源读取与脚本转义 ↗](../../../docs/prototype/build.mjs#L13 "支持构建读取外部资源并对内联 script 闭合标签进行防护的说明。") 最终写出 `index.html`，其中包含根挂载点、全部 CSS、默认字号与阅读密度配置，以及 IIFE 脚本。[自包含 HTML 模板 ↗](../../../docs/prototype/build.mjs#L19 "解释输出文件内联样式、调节配置与打包脚本的结构。")

<a id="scope-and-dependencies"></a>
## 用途与边界

生成物定位为可携带的离线交互演示，HTML 注释明确声明示例虚构、AI 为模拟且不发起网络请求。[离线演示声明 ↗](../../../docs/prototype/build.mjs#L1 "支持生成物不包含真实语料或凭据、AI 与数据均为演示的边界。") 它依赖同目录的应用入口、样式和第三方声明；应用入口又导入数据与调节面板，因此“单文件”描述的是构建产物，而不是构建输入。[应用的额外模块依赖 ↗](../../../docs/prototype/app.jsx#L6 "说明构建入口还依赖调节面板和数据模块，避免把构建输入误解为单文件。") 脚本没有显式配置 sourcemap、目标浏览器、错误恢复或构建后行为测试；成功标准目前只是构建调用和文件写入未抛错，并打印完成消息。[输出完成点 ↗](../../../docs/prototype/build.mjs#L18 "支持脚本以写入文件和打印消息结束、未展示额外验证步骤的判断。")
