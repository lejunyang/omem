# 仓库评审材料捕获与用户澄清恢复测试

验证评审同步捕获源码关联文档、部署示例和图片，同时排除私有配置；用户澄清则作为带来源信息的原始材料发布并可恢复到独立数据库。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="capture-boundary"></a>
## 仓库材料的捕获边界

测试构造 README、被其链接的部署示例、PNG 图片、`.env` 和本地设置文件。首次捕获只纳入 README、部署示例和图片，图片在知识仓库中具有图像内容，README 还能发现链接材料；重复捕获不会增加 revision 数量。私有 `.env` 与 `settings.local.json` 不出现在材料列表中，说明该用例同时检查多模态、链接发现、幂等性和私有配置排除。[仓库材料捕获与排除测试 ↗](../../../apps/server/tests/review-materials.test.ts#L9 "支持文档、部署配置和图片捕获，链接材料发现、重复捕获幂等，以及私有配置不导入。")

<a id="clarification"></a>
## 用户回答作为原始证据

另一用例先把职责澄清以 manual source 捕获，记录 owner、local-ui 验证、时区及 `producerKind: original`，再保存为评审知识资产。新的、无 legacy 数据库的 Store 恢复后，仍能按固定 key 找到原文和 actor，并保持原始材料 provenance。[用户澄清保存与恢复测试 ↗](../../../apps/server/tests/review-materials.test.ts#L31 "支持用户回答作为 original material 保存，并在独立运行数据库中恢复正文、actor 和 provenance。") 这验证了用户回答可跨运行库恢复，但只覆盖单条文本澄清，未展示冲突回答、撤回、图片回答或多个版本的裁决。
