# 仓库材料捕获与用户补充恢复测试

该测试验证 repo-review 的两条持久化链路：仓库中的文本、图片和配置经筛选后进入统一材料存储，并维持重复捕获、移除与恢复时的 revision 语义；用户澄清则可导出并恢复到另一数据库，同时保留原始材料的来源属性。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="repository-capture"></a>
## 仓库材料捕获与筛选

第一组用例创建 README、部署配置、私有配置和 PNG，再调用仓库材料适配器。断言当前材料只包含 README、部署文件和图片，`.env` 与本地配置不可见；PNG 保留一个可读取的图像部分，README 的相对链接还能产生指向部署文件的关联候选。[仓库材料场景断言 ↗](../../../apps/server/tests/review-materials.test.ts#L9 "支持附近关于临时目录设置、文本与 PNG 捕获、私有配置排除、图片断言及 README 链接关联的测试结论。")

适配器优先读取 Git 文件清单，失败时递归遍历目录；随后排除运行数据、依赖目录和私有配置，并把普通文本或受支持图片交给统一 `Store.capture`。因此这里验证的是通用知识管线之前的仓库输入适配，而非独立的代码事实库。[仓库材料枚举与捕获流程 ↗](../../../apps/server/src/review/materials.ts#L15 "解释测试调用的 Git 枚举、目录回退、输入筛选以及统一捕获流程。")

<a id="revision-lifecycle"></a>
## 重复捕获、协调移除与恢复

测试直接证明：内容未变时再次捕获不会增加 revision；部署文件移除后不再出现在当前材料视图，但原 revision 仍可查询；写回相同内容后，当前材料重新指向原 revision。[revision 生命周期断言 ↗](../../../apps/server/tests/review-materials.test.ts#L24 "支持重复捕获不增加 revision、移除后保留历史以及相同内容恢复复用 revision 的直接测试结论。") 内容哈希与 `captureFormat` 共同决定是否再次调用捕获，是实现层对上述幂等现象的解释。[内容幂等判断 ↗](../../../apps/server/src/review/materials.ts#L37 "说明内容哈希与捕获格式如何决定是否再次执行 Store.capture，为重复捕获现象提供实现依据。")

此前把 `removed` 概括为“文件从工作区删除”的结论过窄，应由当前实现语义替代：协调阶段以本轮 `state=captured` 的集合为准，所有未在该集合中的既有 `omem:%` 文件源都会被标记为 removed，因而 excluded 或 failed 项也可能受到影响。它保留历史 source 与 revision，只改变当前可见状态。[成功捕获集合协调逻辑 ↗](../../../apps/server/src/review/materials.ts#L57 "支持 removed 实际依据本轮 captured 集合协调，而非只代表文件从磁盘删除，并说明历史来源不会被直接删除。")

<a id="user-note-roundtrip"></a>
## 用户澄清的跨库恢复

第二组用例先以 `manual` 来源捕获一条职责澄清，将其导出到知识目录，再由另一份全新 SQLite Store 恢复。恢复后的正文、`actorId` 和 `producerKind=original` 均被断言保留，说明用户回答作为原始材料往返，而不是被保存成无来源的派生答案。[用户补充往返测试 ↗](../../../apps/server/tests/review-materials.test.ts#L39 "支持用户澄清能够导出、跨数据库恢复，并保留正文、用户身份和原始生产者属性。")

恢复入口还会校验 `knowledge-answer:` 标识、重新捕获仓库材料和已发布文章，并把对应问题更新为 answered；若文章尚未依赖这条回答，还会写入知识失效记录。当前用例没有为问题表、答案 revision、失效记录或文章恢复建立断言，因此这些副作用不能视为已由本文件完整验证。[知识恢复与回答状态处理 ↗](../../../apps/server/src/review/knowledge.ts#L9 "解释恢复入口除材料重建外还会更新问题状态、关联答案 revision，并可能写入知识失效记录。")

<a id="coverage-limits"></a>
## 覆盖范围与剩余边界

临时目录由用例直接创建且没有显式 Git 初始化，随后材料捕获成功；实现表明 Git 枚举抛错后会改走递归遍历，因此该场景与回退路径相容。不过测试没有显式制造或断言 Git 失败，也没有核对回退原因。[仓库材料场景断言 ↗](../../../apps/server/tests/review-materials.test.ts#L9 "支持附近关于临时目录设置、文本与 PNG 捕获、私有配置排除、图片断言及 README 链接关联的测试结论。")[材料适配器边界分支 ↗](../../../apps/server/src/review/materials.ts#L17 "支持对 Git 回退、路径检查、大小与编码限制、空文件、PNG/JPEG/WebP 分支、文本分片和失败记录等覆盖边界的归纳。") 当前已覆盖 PNG 的创建、捕获及图像部分断言；尚缺的是 JPEG、WebP 等 PNG 之外的图片格式，以及超限文件、非法 UTF-8、空文件、文本分片、失败 coverage、符号链接和越界路径等分支的针对性断言。[仓库材料场景断言 ↗](../../../apps/server/tests/review-materials.test.ts#L9 "支持附近关于临时目录设置、文本与 PNG 捕获、私有配置排除、图片断言及 README 链接关联的测试结论。")[材料适配器边界分支 ↗](../../../apps/server/src/review/materials.ts#L17 "支持对 Git 回退、路径检查、大小与编码限制、空文件、PNG/JPEG/WebP 分支、文本分片和失败记录等覆盖边界的归纳。")

测试使用真实 Store，因此会创建 SQLite、执行迁移、创建资产目录并设置文件权限；这足以支撑场景运行，却不等于验证迁移失败回滚、权限异常或团队隔离。Store 的声明边界仍是本地单用户 SQLite，团队级约束属于后续迁移。[Store 初始化与单用户边界 ↗](../../../apps/server/src/store.ts#L4 "说明测试中的真实 Store 会初始化 SQLite、迁移和资产目录，同时明确当前实现仍是单用户基础。")
