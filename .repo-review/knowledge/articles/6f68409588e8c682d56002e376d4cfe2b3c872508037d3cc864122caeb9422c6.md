# 飞书实时事件接入、路由与可靠交付

将飞书 WebSocket 事件规范化并持久化，按配对、助手回复、群聊采集和卡片动作分流，并以幂等收件箱、事务性发件箱及连接租约降低重复处理和崩溃丢消息风险。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="event_flow"></a>
## 事件接入与业务分流

模块把 SDK 的多种事件形态归一为统一结构：缺少事件 ID 时对负载计算稳定摘要，时间戳兼容秒与毫秒，消息正文则尝试从 JSON 提取。官方适配器注册消息、群成员变化和卡片动作处理器，并在连接失败后定期尝试恢复。[事件规范化与 WebSocket 适配 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L96 "支持事件字段归一、处理器注册、连接状态回调和失败后周期性恢复的说明。")

事件先按应用与事件 ID 写入收件箱；同 ID、同摘要视为重投，同 ID、不同摘要报冲突。机器人进退群会启停群采集目标；普通消息还会检查有效连接、绑定身份及是否为机器人自身消息。绑定所有者的私聊或群内提及进入助手路径，其余获准群消息被转换为统一 Capture parts 后交给输入聚合器。[收件箱幂等与消息路由 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L337 "支持事件去重、群目标维护、身份判断、助手分流及群消息采集流程。")

<a id="reply_delivery"></a>
## 助手回复与崩溃恢复

助手返回后，取消的 turn 不投递；并发重投遇到仍在运行的 turn 时不确认收件箱，也不重复入队。已存在发件箱记录的完成 turn 直接确认；若 turn 已完成但发件箱缺失，则进入恢复入队路径。回复必须先持久化，再将收件箱标为已处理，使入队失败时仍可依赖飞书重投。[回复重投与入队顺序 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L550 "支持取消、并发重投、既有发件箱和崩溃恢复分支，以及先持久化回复再确认收件箱的顺序。")

发件箱创建会在一个数据库事务内写入 change、delivery intent、关联表，并把 intent 关联回会话 turn。provider UUID 优先由频道、会话和 turn 共同生成，因此同一 turn 重投复用标识，而不同 turn 即使回复文字相同也得到独立投递；回复卡片正文截断为 8000 字符。[事务性回复发件箱 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L814 "支持确定性 provider UUID、不同 turn 独立发送，以及在同一事务中创建投递记录并关联会话 turn。")

<a id="connection_boundaries"></a>
## 连接、媒体与解析边界

连接管理器以数据库租约限制同一连接的活动实例，从加密存储读取凭据，并在记录错误前替换凭据和常见令牌；心跳还会核对连接版本，版本变化、租约失败或连接失效都会停止当前实例。[连接租约与版本心跳 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L894 "支持连接独占、凭据读取、错误脱敏、版本检查和失效停止流程。")

图片仅在存在 image key、消息 ID 和媒体端口时下载，否则退化为占位文本；富文本只处理标题、文本、链接、@ 与图片占位，其他节点被忽略。该文件仅规定媒体下载端口及调用方式，不能据此确认生产下载实现的大小、超时、鉴权或 MIME 校验。[媒体端口与 Capture parts 转换 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L719 "支持图片下载的前置条件、占位降级、逐 part 来源信息以及富文本节点解析范围。")
