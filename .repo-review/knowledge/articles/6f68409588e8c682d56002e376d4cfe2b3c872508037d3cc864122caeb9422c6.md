# 飞书实时事件接入、去重与可靠路由

该模块负责飞书 WebSocket 连接、事件规范化与分流：消息和群成员事件经持久化收件箱进入配对、助手或群聊捕获链路，卡片动作则直接交给动作队列；助手回复通过事务化 outbox 降低重投和崩溃造成的重复或丢失风险。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-connection"></a>
## 职责与连接生命周期

模块把飞书的消息、群成员变化和卡片动作归一为统一事件，补齐事件时间、发送者、会话、消息及回复关系；平台未提供事件 ID 时，以事件类型和原始载荷的稳定摘要兜底。[飞书事件规范化 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L96 "支持统一事件字段、时间处理以及缺少平台事件 ID 时以稳定摘要兜底的说明。") 官方适配器注册五类事件，按租户选择飞书或 Lark 域建立 WebSocket，并在连接失败后周期性尝试恢复。[官方 WebSocket 适配器 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L154 "支持事件类型注册、租户域选择、连接状态回调和失败恢复机制，也表明消息更新事件会被订阅。")

数据库租约限制同一连接只能由成功 claim 的 worker 持有。heartbeat 按连接 ID 与 token 续租，并不单独检查旧租约是否已过期；只有 token 已失效或被新的 claim 替换等导致更新不到记录时才失败。[连接租约仓库 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L223 "支持 claim、按连接与 token 续租以及释放语义，并证明 heartbeat 没有单独检查 expires_at。") 连接管理器读取加密凭据、启动适配器并定期核对配置版本；版本变化、续租异常或显式停止都会关闭连接和释放租约。[实时连接管理器 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L924 "支持凭据读取、卡片动作绕过收件箱、配对优先分派、版本检查、心跳和停止流程。") 凭据存储要求 32 字节环境密钥和限定格式的引用，避免由实时模块直接持久化明文密钥。[飞书凭据存储边界 ↗](../../../apps/server/src/integrations/lark/secret-store.ts#L24 "支持环境密钥长度要求、加密存储初始化和凭据引用格式限制。")

<a id="inbox-and-routing"></a>
## 收件箱去重与事件分流

进入 `LarkEventInbox` 的消息及群成员事件会先写入 `event_inbox`：同一应用和事件 ID 的重投若载荷摘要一致则复用记录，摘要冲突则报错，新事件还会更新连接版本观察到的能力集合。[事件收件箱持久化 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L337 "支持进入收件箱的事件按应用和事件 ID 去重、摘要冲突检测及能力画像更新。") 摘要由递归排序对象键后的规范 JSON 计算 SHA-256，使对象字段顺序不影响比较。[稳定摘要实现 ↗](../../../apps/server/src/storage/digest.ts#L3 "解释事件载荷去重依赖的递归键排序、规范 JSON 和 SHA-256 摘要。") 卡片动作是明确例外：连接管理器将其直接交给 `cardActions.enqueue`，不经过该收件箱。[实时连接管理器 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L924 "支持凭据读取、卡片动作绕过收件箱、配对优先分派、版本检查、心跳和停止流程。")

消息路由会处理机器人进群或退群、字段缺失、连接失效和机器人自发消息。助手只接收绑定所有者发出的消息：私聊可直接进入，群聊还必须明确提及机器人。[绑定身份与助手路由 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L503 "支持助手消息必须来自绑定所有者，且群聊还需明确提及机器人的联合条件。") 其他消息仅在启用的群监听目标中进入统一捕获；来源保留外部身份，只有发送者匹配绑定所有者时才填写规范 principal 与绑定验证信息。[群聊捕获与来源信息 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L602 "支持群监听目标检查、统一捕获 externalId 以及绑定身份来源字段的写入规则。") 这与公共捕获合同中“保留外部身份、无法可靠映射时不伪造 owner”的规则一致。[统一捕获来源合同 ↗](../../../packages/contracts/src/index.ts#L4 "支持逐 part 来源字段，以及外部身份始终保留、规范 principal 仅在可靠绑定时设置的约束。")

<a id="delivery-and-capture"></a>
## 可靠回复与富消息捕获

助手回复遵循“先提交 outbox，再完成 inbox”。并发重投遇到仍在运行的 turn 时不重复结束事件或投递；已有关联 outbox 时只确认重投；turn 已完成但 outbox 缺失时则恢复补写。[助手重投与 outbox 顺序 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L550 "支持并发重投、已有 outbox、恢复补写以及先入队后完成 inbox 的可靠性流程。") 回复变更、投递意图和 turn 的 outbox 引用在同一事务中写入，provider UUID 按 turn 稳定生成，使不同轮次的相同文本仍可分别发送，而同一轮重投可由平台去重。[回复投递意图事务 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L814 "支持卡片和摘要长度限制、按 turn 生成稳定 provider UUID，以及事务化关联回复 outbox。") 崩溃注入点位于 outbox 提交后、inbox 完成前，用于保留这一恢复边界。[崩溃恢复测试注入点 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L311 "支持 outbox 已提交但 inbox 尚未完成时模拟崩溃的设计边界。")

群消息转换会为每个 part 附加发送者、时间、事件及回复关系。图片具备 image key、媒体端口和 messageId 时下载为资源，否则回退为占位文本；下载调用本身没有局部异常降级。富文本会拆出标题、文本、链接显示和提及，解析失败则回落到普通文本。[富消息捕获转换 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L719 "支持图片下载与占位回退、下载异常缺少局部捕获、富文本拆分和逐 part 来源信息。") 结果交给 Store 中统一配置的 `InputAggregator`，说明这里是公共输入链路的飞书适配层，而非独立知识存储。[统一 Store 与输入聚合器 ↗](../../../apps/server/src/store.ts#L38 "支持该适配器依赖统一 SQLite Store 和 InputAggregator，而非建立独立存储链路。")

<a id="boundaries"></a>
## 配对与已知限制

配对仅接受私聊 `im.message.receive_v1` 中长度为 32 的字母数字、下划线或连字符代码；不符合格式的事件会完成为非配对消息，接收器异常则转为可记录的拒绝结果。[私聊配对处理 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L660 "支持配对事件类型、私聊限制、代码格式、完成状态和拒绝结果边界。") 连接管理器当前只要发现私聊消息且配置了 pairing 接收器，就优先调用配对流程；材料未展示 pairing 是否仅在等待配对阶段注入，因此普通私聊会不会被提前消费仍需结合创建位置确认。[实时连接管理器 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L924 "支持凭据读取、卡片动作绕过收件箱、配对优先分派、版本检查、心跳和停止流程。")

回复卡片正文限制为 8000 字符，变更摘要限制为 500 字符。[回复投递意图事务 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L814 "支持卡片和摘要长度限制、按 turn 生成稳定 provider UUID，以及事务化关联回复 outbox。") 图片下载异常会从 `downloadImage` 直接向上传播，而只有缺少下载前置条件时才生成占位文本。[富消息捕获转换 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L719 "支持图片下载与占位回退、下载异常缺少局部捕获、富文本拆分和逐 part 来源信息。") 此外，新增与更新事件都被订阅，但群聊捕获的 externalId 仅由应用和消息 ID 构成；当前材料只确认 Store 使用统一输入聚合器，尚不能确定同 externalId 更新最终形成新 revision、覆盖还是拒绝。[官方 WebSocket 适配器 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L154 "支持事件类型注册、租户域选择、连接状态回调和失败恢复机制，也表明消息更新事件会被订阅。")[群聊捕获与来源信息 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L602 "支持群监听目标检查、统一捕获 externalId 以及绑定身份来源字段的写入规则。")[统一 Store 与输入聚合器 ↗](../../../apps/server/src/store.ts#L38 "支持该适配器依赖统一 SQLite Store 和 InputAggregator，而非建立独立存储链路。")
