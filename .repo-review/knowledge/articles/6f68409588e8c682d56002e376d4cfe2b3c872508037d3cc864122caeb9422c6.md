# 飞书实时事件接入、去重与路由

实现飞书 WebSocket 事件标准化、连接租约、收件箱幂等、私聊配对、群消息捕获与助手回复 outbox；助手仅接受绑定所有者的消息，普通群消息会自动建立监控目标，图片下载异常的最终处理策略仍待明确。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="connection"></a>
## 事件入口与连接生命周期

模块将消息、机器人入退群和卡片动作等 WebSocket 回调归一为统一事件，提取发送者、会话、消息类型、回复关系和时间；平台缺少事件 ID 时，以载荷摘要生成稳定标识。适配器按租户品牌选择飞书或 Lark 域名，记录连接状态，并在连接失败后周期性尝试恢复。[实时事件归一化与 WebSocket 适配 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L96 "支持事件字段标准化、回调注册、租户域名选择、连接状态记录及失败后恢复的说明。")

多进程消费通过数据库租约互斥：只有空闲或已过期租约可被抢占，后续心跳和释放都必须携带原租约令牌。[连接租约仓库 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L223 "支持租约抢占、带令牌心跳以及释放机制的说明。") 连接管理器取得租约后读取加密凭据并启动适配器；错误入库前会清除当前密钥及常见令牌形态。心跳还会核对连接是否仍启用且版本未变化，配置换版、停用或心跳异常都会关闭旧连接并释放租约。[连接管理器与版本守护 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L924 "支持加密凭据读取、错误脱敏、事件分流，以及连接版本变化、停用或租约心跳异常时停止旧连接的说明。")

<a id="routing"></a>
## 幂等准入、自动群监控与配对

事件先按应用与事件 ID 写入收件箱；重复事件复用原记录，而同一标识对应不同载荷摘要时拒绝处理。机器人入群会启用群监控，退群则停用。助手准入同时要求发送者是当前绑定所有者：私聊可直接进入助手，群聊还必须明确提及机器人，不能由任意群成员仅凭提及触发。助手回复先写入 outbox 并关联 turn，之后才把 inbox 标为已处理，以便崩溃重投时恢复且避免重复投递。[收件箱幂等与消息路由 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L337 "支持收件箱去重、绑定所有者准入、助手回复先入 outbox 后确认 inbox、普通群消息自动建立监控目标及捕获来源信息的说明。")

未进入助手路径的普通群消息会先以 `INSERT OR IGNORE` 自动建立启用中的监控目标，再查询该目标并捕获消息；因此捕获并不只消费预先配置的群。捕获保留外部身份、绑定版本、事件时间和引用关系，只有发送者匹配绑定所有者时才写入规范化 owner 身份。[收件箱幂等与消息路由 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L337 "支持收件箱去重、绑定所有者准入、助手回复先入 outbox 后确认 inbox、普通群消息自动建立监控目标及捕获来源信息的说明。") 私聊中的 32 位配对码另走配对流程：仅接收消息、完整发送者与会话信息以及规定格式的代码才交给配对接收器，并将成功或拒绝结果完成入箱。[私聊配对处理 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L660 "支持配对消息的类型、会话、身份和代码格式校验，以及成功与拒绝结果处理的说明。")

<a id="capture-delivery"></a>
## 捕获部件与可靠回复

文本消息形成单一文本部件，富文本会把标题和段落拆成多个部件，并保留链接、提及、内嵌图片占位及逐部件来源信息。图片在同时具备 image key、媒体端口和 message ID 时下载为资源型图片；缺少任一下载条件时才降级为“[图片消息]”。这替代了此前“任何图片下载失败都会自动降级”的过宽结论：实际下载调用抛错时，本函数并未捕获。[捕获部件转换与图片下载 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L719 "支持文本、富文本、图片部件及逐部件来源信息的转换规则，并表明仅缺少下载条件时显式降级、下载异常未在此捕获。")

助手回复以事务创建变更、delivery intent，并在同一事务中把 outbox 关联到 turn；同一 turn 使用确定性的提供方 UUID，使事件重投可复用既有投递，而不同 turn 即使回复文本相同也仍会分别发送。[助手回复事务型 outbox ↗](../../../apps/server/src/integrations/lark/realtime.ts#L814 "支持回复变更与投递意图的事务创建、turn 关联和确定性提供方 UUID 的幂等设计。")

<a id="limits"></a>
## 当前限制与待确认行为

连接与事件层已有租约、幂等 inbox 和事务型 outbox，但媒体下载异常不在部件转换函数内处理；异常会沿调用链抛出，材料没有说明平台重投次数、永久失败状态或最终占位降级策略。[捕获部件转换与图片下载 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L719 "支持文本、富文本、图片部件及逐部件来源信息的转换规则，并表明仅缺少下载条件时显式降级、下载异常未在此捕获。") 因此，现阶段只能确认“下载条件缺失时降级”，不能声称“下载失败均可安全完成捕获”。
