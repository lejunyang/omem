# 真实 ACP 日常跟进流程冒烟验收

该脚本在隔离数据库中连接真实 ACP 模型，以连续中文对话验收跟进事项的创建、延后、重启补偿、只读回顾和取消。它验证关键状态与时间语义，但不覆盖真实外部通知、并发更新以及初始化和清理阶段的全部失败路径。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-setup"></a>
## 目标与真实运行环境

脚本用于发现“单元测试通过，但真实模型工作流不可用”的集成问题。它先创建临时目录和独立 Store，加载评审模型配置，经 ACP 探测选择实际可用模型，并明确断言模型为 `gpt-5.6-sol`；随后将 MemoryService、AcpAssistantModel 与 AssistantRuntime 装配成私有会话的完整运行链路。[冒烟脚本的真实运行时装配 ↗](../../../scripts/live-daily-smoke.ts#L13 "支持脚本创建隔离 Store、选择指定真实模型并装配 MemoryService、ACP 模型与 AssistantRuntime 的说明。") 模型选择以 ACP 实际暴露的候选项为准：环境变量可指定模型，但指定项不存在时会直接失败，因此这里检验的是实时传输能力，而非仅检查静态配置。[实时 ACP 模型选择规则 ↗](../../../scripts/live-model.ts#L4 "解释候选模型来自 ACP 探测，以及请求模型不可用时直接失败的边界。")

<a id="workflow-assertions"></a>
## 连续对话与核心断言

脚本在同一会话中依次模拟创建、延后、回顾和取消事项。首次输入明确“跟进时间不是截止时间”，并断言只产生一个 waiting 任务、`dueAt` 保持为空，同时把北京时间 2030-10-02 09:00 转换为 UTC 的 `next_check_at`。[跟进时间与截止时间断言 ↗](../../../scripts/live-daily-smoke.ts#L26 "支持 waiting 状态、空截止时间和带时区检查时间转换的具体行为。") 第二轮写入 `snoozed_until`，确认原检查时刻不会提醒；关闭并重开 Store 后，越过延后时刻的两次扫描依次返回 1 和 0，说明该串行恢复场景中持久化状态避免了重复提醒。[延后与重启补偿断言 ↗](../../../scripts/live-daily-smoke.ts#L37 "支持延后时刻、原时刻不提醒，以及重启后的串行扫描依次返回一次和零次提醒。") 随后的只读回顾不得增加任务版本，取消则将状态改为 cancelled，且未来扫描不再返回提醒。[只读回顾与取消断言 ↗](../../../scripts/live-daily-smoke.ts#L45 "证明状态回顾不改变任务版本，取消后任务停止后续提醒。")

<a id="boundaries"></a>
## 边界、报告与未覆盖行为

这是依赖真实模型行为的端到端冒烟验收，而非穷尽测试。ACP 适配器只接受 `acp` transport；缺少配置或使用 CLI transport 时会明确报告模型不可用，不会以伪造答案回退。[ACP 助手模型的传输边界 ↗](../../../apps/server/src/assistant/acp-model.ts#L12 "支持适配器仅使用真实 ACP、拒绝无配置和 CLI transport，并且不提供伪回退的说明。") 脚本只观察 Store 中的任务状态和提醒计数，文件也明确说明不会对外发送，因此尚不能证明通知实际送达，也未覆盖并发扫描、投递失败恢复、模型超时、认证失败、多任务消歧或夏令时等情况。对于已经进入 `try`、且收尾操作本身能够继续执行的成功或失败，`finally` 会尝试关闭运行时和 Store、删除临时目录，并把结果写入 `.omem/verification/live-daily.json`。[受条件约束的清理与报告输出 ↗](../../../scripts/live-daily-smoke.ts#L51 "支持进入 try 后由 catch 记录失败、finally 尝试清理并写报告，同时也显示这些收尾步骤是顺序执行且可能被自身异常中断。") 这替代了“无论任何成功失败都必然清理并写报告”的过强结论：临时目录创建、Store 初始化以及 `finally` 内任一步骤自身失败，均不在该保证范围内。

<a id="relation-semantics"></a>
## 与运行时治理的关系

冒烟脚本依赖模型生成结构化任务调用，但写入权限并不由模型自行授予；运行时合同要求服务端重新治理工具请求，并对时间值检查原消息中的时间表达、时区和可解析性。[任务时间与工具调用治理合同 ↗](../../../apps/server/src/assistant/runtime.ts#L23 "说明任务时间必须对应原消息中的明确表达并包含时区，以及模型提出的工具请求仍由服务端重新治理。") 因此脚本中的状态断言既验证模型理解，也间接覆盖运行时与存储服务的协作，不过它不能替代针对权限、冲突和异常事务边界的专门测试。
