# 统一输入、聚合与外部连接器边界

说明 Capture 与事件聚合入口、多模态载荷预算、版本及溯源规则，并区分已经实现的连接器能力与仍需外部授权、观察器或网络接入的部分。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="capture-contract"></a>
## 统一捕获与事件聚合

立即保存的材料进入 `/api/captures`，需要静默窗或最大窗口聚合的 chat/screen 事件进入 `/api/input-events`；私有或远程请求使用 Bearer token。载荷可携带文本、图片、链接、上下文和 provenance；图片及请求体有大小限制，URL 只保存为材料而不会自动访问。[捕获接口与多模态载荷限制 ↗](../../../docs/implementation/inputs.md#L3 "支持两个输入入口、鉴权方式、图片预算、链接保存方式及安全边界。")

来源覆盖 manual、file、git、lark、agent、hook、chat、screen；文本每项不超过 200k 字符且最多 50 个 part。相同来源、外部标识和规范内容可幂等复用，变化则创建新版本；聊天与屏幕事件按会话或窗口聚合，迟到事件形成补充批次。[输入版本与事件聚合规则 ↗](../../../docs/implementation/inputs.md#L42 "支持来源枚举、文本与 part 预算、幂等版本化、观察时间及事件聚合规则。")

<a id="connectors-and-limits"></a>
## 连接器能力与采集风险

飞书机器人已有 WebSocket 接收和群监控目标维护，但真实应用创建与授权仍需显式完成，历史消息补拉和图片下载在本文记录时尚未实现。屏幕观察器由外部提供；飞书文档尚无原生 block 到精确 selector 的映射，Git 导入也未建立全仓 AST、symbol 或 import 图。[飞书、屏幕与文件输入边界 ↗](../../../docs/implementation/inputs.md#L44 "支持飞书已有能力与授权、历史补拉、图片下载、精确 selector、屏幕观察和代码解析方面的限制。")

TraeX hook 采用显式项目配置和本地 spool：事件以受限权限原子落盘，只有服务 receipt 严格匹配后才删除，离线或超时时保留并放行宿主。字段白名单和基础 token 脱敏不是完整 DLP，应只在确定范围启用；任务提醒目前也仅在应用内生效。[Hook spool、采集范围与任务提醒 ↗](../../../docs/implementation/inputs.md#L52 "解释 hook 的可靠投递和隐私边界，并支持外部通知尚未启用的结论。")
