# omem 产品与系统架构设计

该设计提案描述版本化证据驱动的长期记忆系统、递归阅读体验、权威数据与可重建投影、自治闭环及首版验收目标；它不代表当前运行实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="goal"></a>
## 目标与证据体验

omem 计划让人和不同 Agent 共用长期记忆，把外部材料变成证据、任务过程变成经历，再把稳定经验组织成知识与方法。核心体验是从结论进入固定原文、沿引用继续深入、就地追问并返回原位置。成功以旧问题复用、及时停用旧结论和答案可追溯衡量，而非记忆数量；这些仍是设计目标。[设计状态与核心体验 ↗](../../../docs/design.md#L5 "支持文档属于设计提案，并说明证据阅读链和任务效果型成功标准。")

<a id="architecture"></a>
## 权威数据与按需引用图

设计以 PostgreSQL 和对象存储作为权威集合，搜索索引和外部框架只是可重建投影。WeKnora、Hindsight 可提供检索或反思候选，但不决定事实生效。引用图允许环且按一跳读取，避免抓取整图或把整条链塞入上下文；部署建议为 API 与 worker 共用领域合同的模块化单体。[权威数据、适配器与按需读取 ↗](../../../docs/design.md#L35 "支持权威存储与外部投影的边界，以及引用图按需展开。")[模块化单体建议 ↗](../../../docs/design.md#L91 "支持第一版以共享领域合同的 API 与 worker 实现，而不是拆分为多套微服务。")

<a id="autonomy"></a>
## 自治闭环和首版验收

闭环包括观察、选择、组织、验证、应用、使用、反馈和改进。普通可信变更可自动提交，高影响冲突、硬删、扩权和外发仍需判断或确认。P0/P1 验收覆盖深链、引用稳定、权限状态、真实问答、恢复及引擎降级，但文档明确原型只模拟交互，不能据此认定这些能力已经实现。[自治闭环与风险分层 ↗](../../../docs/design.md#L108 "支持学习流程、普通自动提交和高风险操作确认之间的分层。")[首版计划与验收目标 ↗](../../../docs/design.md#L155 "支持 P0/P1 的计划目标，同时证明原型不代表模型或生产数据库已经接通。")
