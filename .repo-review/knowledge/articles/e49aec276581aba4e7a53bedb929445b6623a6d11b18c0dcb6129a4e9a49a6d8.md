# omem 界面实现规范

面向 omem Vue 界面开发的设计与实现约束，规定视觉来源、组件复用、证据阅读交互、安全渲染、响应式与验证要求；它描述应遵循的工作方式，不等同于这些能力已经实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="scope-and-structure"></a>
## 适用范围与组件边界

该材料用于构建或修改 omem 的 Vue 界面，尤其覆盖公共组件、证据阅读、递归引用、主题、移动端与无障碍。视觉规范以仓库根 `design.md` 为准，`docs/design.md` 仅用于理解系统功能，不能替代视觉 token。实现应使用 Vue 3 与 TypeScript，优先复用 `packages/ui` 和 `@omem/ui`；公共组件只暴露 props、slots、emits，网络请求与应用状态留在 `apps/web`。[视觉来源与组件职责 ↗](../../../.agents/skills/omem-design/SKILL.md#L2 "支持视觉规范来源、Vue 技术栈、公共组件复用及应用状态边界的说明。")

这些内容是开发约束，并未提供组件清单、页面截图或测试结果，因此不能据此断言现有界面已经复用完毕或符合视觉规范。

<a id="evidence-interaction"></a>
## 证据交互与安全边界

交互中心是固定证据片段。递归引用应由单个 dialog 管理路径、逐层滚动位置和草稿；Esc 返回上一层，整体关闭后恢复焦点，遇到环则显示可跳回的目标，同时问答过程不得丢失当前证据。[递归证据阅读合同 ↗](../../../.agents/skills/omem-design/SKILL.md#L11 "说明单一对话框、路径与滚动保存、Esc 返回、焦点恢复和环路跳转要求。")

材料还把正文和模型输出视为不可信输入：正文只能作为文本或经审查的 AST 渲染，不能直接使用 `v-html`；图片须通过已验证的 asset ID 加载，模型响应不得直接操作 DOM 或触发工具。[不可信内容渲染边界 ↗](../../../.agents/skills/omem-design/SKILL.md#L12 "支持正文、图片和模型回包的安全处理要求。") 这说明证据阅读体验与内容安全必须共同设计，而不是在页面完成后再附加过滤。

<a id="accessibility-and-verification"></a>
## 响应式、真实状态与验证

可访问性基线包括至少 44px 的普通点击区域、输入框可见标签、尊重 reduced-motion，以及在 700px 以下切换为全屏引用和折叠导航；要求检查 390、768、1440px 三档且不得横向溢出。[无障碍与响应式基线 ↗](../../../.agents/skills/omem-design/SKILL.md#L13 "支持点击尺寸、标签、移动端布局、视口检查与 reduced-motion 要求。") 页面必须连接真实 API，并诚实展示未连接或无材料状态，不能用演示数据掩盖错误。[真实 API 与诚实空态 ↗](../../../.agents/skills/omem-design/SKILL.md#L14 "支持配置实际生效、真实状态展示以及禁止演示数据掩盖错误的论断。")

验证流程要求运行项目检查；涉及页面时还应执行已注册的浏览器任务并检查桌面和手机截图，同时记录未验证边界。通用行为应先沉淀到 `packages/ui` 并在设计系统页面验证。[页面验证与公共能力沉淀 ↗](../../../.agents/skills/omem-design/SKILL.md#L15 "支持检查命令、浏览器验证、边界记录以及优先扩展公共 UI 包的说明。") 这些是验收要求，材料没有给出任何命令执行结果。
