# Batch2 合同样例与校验边界

说明一组虚构的待实现合同样例如何表达可信上下文、提案、角色与飞书注册，并划清 JSON Schema、运行时支持度验证和平台实测之间的边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="status"></a>
## 样例定位

这些文件是 Batch2 待实现合同的虚构验收数据，不能直接调用当时的 API，也不能原样填入严格配置。README 将样例定位为设计与测试输入，而不是已实现能力或生产数据。context 中 fixture alias 必须由测试 harness 映射为真实 SourceRevision 与 FragmentRevision；身份元信息来自认证 receipt，不能接受客户端正文自报。[合同样例定位与可信上下文 ↗](../../../docs/implementation/batch2/examples/README.md#L1 "支持样例属于虚构的待实现合同，以及 revision 映射和身份元信息必须来自认证 receipt 的要求。")

<a id="contracts"></a>
## 提案、角色与飞书边界

proposal 只是从上下文提炼的 task 候选，并未批准或生效。Proposal v1 起稿描述严格 body 与图文 evidence，但运行时仍须校验引文、范围、日期、target、read_versions 和资产存在性；Schema 通过不等于证据支持充分。角色 manifest 的输出 schema、skill digest 和路径仍需构建器解析；飞书注册样例不含凭据，最小权限是否生效必须通过平台确认与实际探测。[样例合同的运行时校验边界 ↗](../../../docs/implementation/batch2/examples/README.md#L6 "解释提案尚未生效、Schema 不等于支持度验证，以及角色和飞书样例仍需构建器或平台确认。")

<a id="time-evidence"></a>
## 时间与引文语义

样例把观察时间固定为 2026-09-22 16:00 Asia/Shanghai，并将“本周五18:00前”解析为 2026-09-25 10:00 UTC。解析结果必须保留时区、观察时刻和原词，避免相对时间脱离采集背景。引文 selector 使用 Unicode 码点半开区间 `[0,30)`，约束候选证据与原文的精确对应。[样例时间与 Unicode 引文规则 ↗](../../../docs/implementation/batch2/examples/README.md#L11 "支持相对截止时间的具体换算，以及 selector 使用 Unicode 码点半开区间的要求。")
