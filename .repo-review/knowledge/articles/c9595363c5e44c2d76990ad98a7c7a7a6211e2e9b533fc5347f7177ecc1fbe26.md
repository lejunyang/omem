# docs-contracts · 模块理解

docs-contracts 规定证据对象、版本、关系、递归阅读、原位问答和可恢复变更的目标语义，使采集、知识组织、阅读交互与写入流程共享可追溯边界；现有材料不足以证明这些合同已全部实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role"></a>
## 职责与设计背景

该模块为证据链提供共同语义：Source、Fragment、Memory 等对象维持跨版本的稳定身份，Revision 则固定某一时刻的内容，避免标题、URL 或正文变化破坏引用。片段续接优先依靠上游标识、代码符号与结构邻域；遇到重复或大幅改写时保留候选继任，不擅自认定同一对象。有效时间与系统获知时间也被分开记录，使补录材料不会倒改过去的认知状态。[稳定对象与不可变修订 ↗](../../../docs/contracts/evidence-model.md#L9 "支持稳定身份负责跨版本追踪、修订负责固定可引用内容，以及关系边具有方向和版本的论断。")[片段续接与双轴时间 ↗](../../../docs/contracts/evidence-model.md#L21 "支持片段歧义时不强行续接，以及有效时间和获知时间需要分离的设计背景。")

<a id="flow"></a>
## 从证据关系到递归阅读

关系模型刻意区分“包含、提到、派生、相关”和真正的事实支持：只有经过评估的原子主张支持才能承担证据作用，多跳引用不会自动传递支持，多来源联合证据还必须同时满足权限约束。[证据关系与支持边界 ↗](../../../docs/contracts/evidence-model.md#L60 "支持不同关系类型不能混同为事实证据、支持不可沿引用链自动传递及多来源权限约束。") 阅读侧把引用展开为可进退的帧栈，并保存焦点、路径与循环位置；原位追问由服务端重新读取当前身份可访问的材料，生成引用必须经过目标、定位和版本校验，沉淀后的答案仍需挂回原始证据，不能把回答自身当作新增独立依据。[递归阅读与原位问答 ↗](../../../docs/contracts/evidence-model.md#L123 "支持帧栈导航、循环检测、授权上下文重读、引用验证以及答案必须回连原始证据的流程。")

<a id="change-progress"></a>
## 变更闭环、跨模块关系与当前限制

写入流程以 ChangeSet 连接策略校验、并发头检查、新修订、关系更新、不可变事件和 outbox，因此它既关联证据存储与知识投影，也关联后续通知或外部执行。恢复不是覆盖旧快照，而是生成补偿变更；若对象已有后续修改，就要求展示差异并重新计算，以保护后来工作。[ChangeSet 提交与补偿恢复 ↗](../../../docs/contracts/evidence-model.md#L147 "支持变更事务的组成、状态与事件一致性，以及存在后续修改时必须重算而不能覆盖的恢复语义。") 这些材料能够说明预期合同及模块间边界，但没有给出数据库迁移、公开 API、前端交互或行为测试的实际结果，因此无法据此判断各项能力的完成度。
