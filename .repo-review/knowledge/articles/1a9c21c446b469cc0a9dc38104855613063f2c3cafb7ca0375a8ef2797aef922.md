# 以 systemd 用户服务运行 omem

这是一份供人工配置的 systemd 用户服务模板，描述 omem 的启动顺序、工作目录、环境文件、启动命令、故障重启和用户会话挂接方式。文件中的绝对路径均为占位符，因此不能据此认定服务已经安装、启用或正在运行。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 适用场景与前置条件

该模板适合希望把 omem 作为个人后台进程交给 systemd 管理的场景。服务被安排在 `network-online.target` 之后启动，但这只是启动顺序约束，不表示模板会主动拉起该目标，也不保证届时网络实际可用。复制到用户级 systemd 目录前，必须先填写真实路径；因此它是**部署起点**，不是已完成部署的证明。参考 [用户服务模板与启动顺序 ↗](../../../deploy/omem.service.example#L1 "支持该文件是需要先填写真实路径的个人服务模板，并证明其仅声明位于 network-online.target 之后的启动顺序。")

<a id="runtime"></a>
## 启动与故障恢复

运行时，systemd 先进入指定的 omem 项目目录，加载单独的环境文件，再执行 `osdk run start`。进程因失败退出后会等待 5 秒重启，停止时最多等待 20 秒。这提供了基础守护能力，但材料没有说明环境变量清单、日志策略、网络依赖的就绪检测或应用健康检查。参考 [启动与重启配置 ↗](../../../deploy/omem.service.example#L6 "支持工作目录、环境文件、osdk 启动命令，以及失败重启和停止超时的说明。")

<a id="enablement"></a>
## 启用范围与限制

服务挂接到用户会话的 `default.target`，说明该示例按用户服务组织，而非系统级守护进程。实际使用仍需替换工作目录、环境文件和 `osdk` 可执行路径，并由部署者完成 systemd 的加载与启用；当前材料没有记录这些操作是否执行，也不能证明服务已在运行。参考 [用户会话安装目标 ↗](../../../deploy/omem.service.example#L15 "支持该服务挂接到用户级 default.target，以及仍需部署者另行加载和启用的判断。")
