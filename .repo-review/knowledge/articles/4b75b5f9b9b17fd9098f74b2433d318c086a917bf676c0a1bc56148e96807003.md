# 检索排序、仓库偏好与 AST 定义召回测试

该测试文件以三个行为场景验证检索链路：MMR 多样化优先保留互补证据；仓库路径偏好在 top-N 前生效，并可由显式历史意图覆盖；AST 符号可通过固定原始片段召回，而符号改名并重新捕获、同步后，旧名称停止获得 `code-symbol` 路由。现有覆盖仍未确认异常向量、损坏配置、同步失败和源码删除等边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="ranking"></a>
## 相关性与多样化排序

第一组测试构造高分实现片段、内容相同的镜像片段，以及分数略低但内容互补的设计背景。默认只取两条时，结果保留最强证据并优先纳入背景；扩大数量后镜像仍可返回，说明多样化只影响排序与截断，不会删除候选。关闭 `diversify` 后则恢复原始分数顺序。[多样化排序行为断言 ↗](../../../apps/server/tests/retrieval-ranking.test.ts#L11 "支持默认排序保留互补证据、扩大结果数仍返回镜像，以及关闭多样化后恢复分数顺序的说明。")

实现中，候选先乘来源权重和 `code-symbol` 加成，再以 0.85 的相关性和 0.15 的冗余惩罚迭代选择；文本完全相同、向量相似或来自同一 revision 都会产生冗余信号。[MMR 排序实现 ↗](../../../apps/server/src/retrieval/ranking.ts#L7 "解释来源权重、代码符号加成、相关性与冗余惩罚的选择流程，以及文本、向量和同 revision 冗余信号。") 当前测试覆盖相同文本和人工二维向量，但未覆盖空结果、limit 边界、同分稳定性及异常向量。

<a id="repository-policy"></a>
## 仓库偏好、显式历史意图与可见性

第二组测试建立临时仓库和 SQLite 存储，将 `docs/prototype/` 默认权重设为 0.2，再捕获原型文档与当前源码。查询只取一条时当前源码胜出，证明来源偏好在 top-N 截断前参与排序；中文“查原型”、直接输入路径或指定 `research` 分类都会恢复原型材料权重为 1。[仓库检索偏好测试 ↗](../../../apps/server/tests/retrieval-ranking.test.ts#L20 "支持原型路径默认降权、显式历史意图恢复权重，以及可见性过滤后的返回结果。")

搜索策略按最长前缀优先匹配，并把显式分类、路径命中以及中英文历史、调研、原型关键词视为覆盖默认降权的信号。[仓库搜索策略 ↗](../../../apps/server/src/review/search-policy.ts#L5 "说明配置约束、最长前缀优先，以及分类、路径和历史类关键词覆盖默认降权的规则。") 测试还通过 `visible` 排除当前源码，使仍有资格的原型材料返回；接口合同明确可见性应在最终排序与 limit 前应用，来源权重只改变排序，不改变候选资格。[检索查询策略合同 ↗](../../../apps/server/src/retrieval/port.ts#L25 "支持可见性在最终排序前过滤、来源权重不改变资格，以及多样化可关闭的接口语义。")

<a id="ast-and-limits"></a>
## AST 符号召回与失效边界

第三组是跨模块集成测试：先写入包含 `resolveWidget` 的源码和同名人工笔记，再执行仓库材料捕获与代码同步。[AST 定义召回场景搭建 ↗](../../../apps/server/tests/retrieval-ranking.test.ts#L41 "支持源码、同名人工笔记、仓库材料捕获与代码同步共同构成集成场景的说明。") 查询后的首项必须带有 `code-symbol` 路由，并能借助 revision 与 fragment 固定锚点读回包含函数定义的原文，说明 AST 命中仍落到原始证据，而不是独立派生摘要。[符号路由、原文读取与改名后失效断言 ↗](../../../apps/server/tests/retrieval-ranking.test.ts#L51 "支持首项携带代码符号路由、读回原始函数定义，以及成功改名并重新同步后旧名称停止获得该路由的结论。") 这也符合检索候选保存固定 fragment、revision、来源与可选路由的合同。[固定证据候选结构 ↗](../../../apps/server/src/retrieval/port.ts#L52 "说明检索结果携带固定 fragment、revision、来源和可选路由，使 AST 命中能够回到原始证据。")

测试随后排除首个符号命中，确认其他结果不会冒用 `code-symbol`；接着把函数从 `resolveWidget` 改名为 `replaceWidget`，重新捕获并同步后，旧名称不再获得该路由。[符号路由、原文读取与改名后失效断言 ↗](../../../apps/server/tests/retrieval-ranking.test.ts#L51 "支持首项携带代码符号路由、读回原始函数定义，以及成功改名并重新同步后旧名称停止获得该路由的结论。") 这里验证的是“成功改名并重新同步后的旧符号加权失效”，不是源码删除。测试也没有证明跨文件调用关系、跨 revision 符号身份续接或同步失败恢复，并且未断言人工笔记是否仍能按旧词召回。
