# 事项跟进控制组件

为开放或等待中的事项提供记录等待、稍后提醒和取消操作；组件在提交前校验输入，携带事项版本与随机请求标识调用命令接口，并通过事件要求父组件刷新或展示错误。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-state"></a>
## 作用与状态边界

该组件为事项进入“等待外部结果”或需要延后提醒提供轻量操作入口。它只在事项状态为 `open` 或 `waiting` 时显示，展开后收集等待对象和本地日期时间；界面明确说明跟进时间不会修改截止时间，也不会自动联系对方，因此其职责是记录跟进信息，而不是执行外部通知。[跟进入口与表单说明 ↗](../../../apps/web/src/TaskFollowUpControls.vue#L24 "支持组件仅面向开放或等待事项，并说明跟进时间不改变截止时间、不会自动联系对方。")

组件通过本地 `expanded`、`busy`、`waitingOn` 和 `when` 管理交互。`busy` 既阻止命令函数重复进入，也禁用三个操作按钮；请求成功后只收起表单，并未清空已填写的等待对象和时间。[本地交互状态与忙碌保护 ↗](../../../apps/web/src/TaskFollowUpControls.vue#L7 "说明展开、输入和忙碌状态的声明，以及命令期间的重复调用保护与状态恢复。")

<a id="command-flow"></a>
## 命令构造与父组件协作

三种操作统一进入 `command`：记录等待必须填写等待对象，稍后提醒必须设置时间，校验失败则通过 `error` 事件交由父组件展示。日期会从 `datetime-local` 值转换成 ISO 时间；随后组件向事项命令端点发送操作、当前事项版本、随机生成的请求标识以及跟进字段。`wait` 写入等待对象，`snooze` 写入延后时间，`cancel` 将 `followUp` 置空。成功后收起表单并发出 `refresh`，失败时发出字符串化错误，最后恢复可操作状态。[跟进命令执行流程 ↗](../../../apps/web/src/TaskFollowUpControls.vue#L8 "支持输入校验、时间转换、随机请求标识生成、命令载荷构造、成功刷新和失败上报流程。")

组件依赖 API 模块中的 `Task` 合同，直接使用事项标识、状态和版本字段。该合同还表明事项可处于完成或取消状态，但这两种状态不会渲染本组件的控制入口。[事项数据合同 ↗](../../../apps/web/src/api.ts#L40 "说明组件依赖的事项标识、状态、跟进信息和版本字段，以及完整合法状态集合。")

<a id="limits-and-coverage"></a>
## 边界与验证缺口

现有材料只证明客户端发送 `expectedVersion` 和随机 `requestId`，不能据此确认服务端一定执行版本冲突检测或幂等去重；同样，定时调度、状态合并以及 `next_check_at` 与 `snoozed_until` 的持久化语义均不在该组件中。此前把请求标识直接称为“幂等请求标识”的结论已被更正为“随机请求标识”，其服务端用途仍待验证。[命令接口载荷边界 ↗](../../../apps/web/src/TaskFollowUpControls.vue#L14 "证明前端发送当前版本、随机请求标识及跟进时间字段，同时支持对服务端冲突、去重和调度语义保持不确定。")

三个操作按钮位于会提交 `wait` 的表单内，其中只有“记录等待”显式声明 `type="submit"`。“稍后提醒”和“取消事项”的最终按钮类型取决于未提供的 `OmButton` 实现，因此仅凭当前材料无法排除一次点击同时触发对应命令和表单提交；材料也未提供行为测试来证明按钮动作、忙碌态防重、时间转换和失败路径。[表单按钮行为 ↗](../../../apps/web/src/TaskFollowUpControls.vue#L27 "指出两个非提交操作按钮位于表单中但未显式声明类型，其真实提交行为依赖未提供的按钮组件实现。")
