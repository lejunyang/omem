# 代码材料分析角色的 OpenAI 展示配置

该文件为代码材料分析技能声明面向 OpenAI 代理界面的名称、简介与默认提示语。它说明角色如何被展示和引导，但不能单独证明技能实现、运行时注册或实际执行链路已经完成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role_presentation"></a>
## 角色如何呈现

该配置把角色的人类可见名称设为“分析代码材料”，用于让使用者识别其面向代码证据分析的用途。这里记录的是界面或代理元数据，而非分析算法本身；仅凭这份声明，不能推断代码解析、引用生成或复核流程已经实现。参考 [角色展示名称 ↗](../../../packages/agent-runtime/roles/code-analyst/1/skills/omem-code-analyst/agents/openai.yaml#L1 "支持附近关于该配置声明人类可见角色名称、但不等同于算法实现的说明。")

英文短描述进一步将目标概括为：从固定证据构建相互关联的知识。这体现了角色的预期方向——知识结论应依附于给定材料，而不是脱离证据自由生成；但它仍属于能力描述，不是运行结果。参考 [角色能力简介 ↗](../../../packages/agent-runtime/roles/code-analyst/1/skills/omem-code-analyst/agents/openai.yaml#L3 "支持附近关于角色以固定证据构建关联知识这一预期目标的概括。")

<a id="default_invocation"></a>
## 默认调用引导与边界

默认提示语要求调用指定的代码分析技能处理已提供的固定材料，说明该配置承担的是**调用引导**：把宿主传入的材料交给相应技能，而不是在 YAML 中定义具体处理步骤。参考 [默认技能调用提示 ↗](../../../packages/agent-runtime/roles/code-analyst/1/skills/omem-code-analyst/agents/openai.yaml#L4 "支持附近关于默认提示语引导宿主调用代码材料分析技能的说明。")

从现有五行内容无法确认宿主是否会读取此文件、技能是否已注册，也无法判断默认提示语是否会在真实运行中被采用。因此，这份材料最多证明存在一项角色配置意图；实际可用性仍需结合运行时加载代码、技能正文或真实执行记录验证。
