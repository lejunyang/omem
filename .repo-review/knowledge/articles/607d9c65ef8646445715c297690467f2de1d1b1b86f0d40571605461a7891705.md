# 关联知识的增量刷新规范

该角色规范定义了如何依据新旧固定材料和用户回答刷新受影响的知识正文、引用与疑问，同时保留未受影响内容。它强调当前结论优先、证据可追溯和面向读者的独立可读性；文档描述的是角色行为要求，本身不能证明刷新流程已经接入运行时或完成端到端实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决知识更新后的内容一致性

当固定材料发生变化或用户补充回答后，既有知识可能部分过期。知识刷新角色的职责是只更新受影响的正文、引用和疑问，保留仍然有效的内容，并产出一篇无需查阅旧版本也能理解的最新文章。正文直接表达当前有依据的结论；修订过程和被替代版本通过运行记录与文章历史追溯，只有主题本身涉及历史决策时才叙述演变。参考 [知识刷新职责 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/skills/omem-knowledge-refresher/SKILL.md#L2 "支持刷新角色只更新受影响知识、保留有效内容，并以当前有依据的结论组织最新文章。")

这是一份**角色行为规范**，说明期望的刷新结果与写作原则。材料没有展示队列触发、影响范围计算、版本保存或发布机制，因此不能仅据此断言增量刷新已在系统中运行。

<a id="evidence_contract"></a>
## 以固定证据维护正文、引用与疑问

刷新输出必须覆盖任务指定的全部目标，并保持文档键精确一致。正文中的论断应就近放置引用，每节至少包含一处；引用只能指向任务提供的材料或文章，并使用真实材料行号或文章章节。引用标签需要面向读者，理由则说明证据支持附近哪项结论。无法确认、背景不足或需要用户选择的事项应进入结构化疑问，写明原因、下一步、是否阻塞及关联证据。参考 [证据与疑问合同 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/skills/omem-knowledge-refresher/SKILL.md#L10 "支持目标覆盖、正文内联引用、固定材料定位以及结构化记录不确定事项等约束。")

这些约束使宿主能够从固定材料复制精确短引文，也能避免把缺少依据的推断包装成确定事实。

<a id="reader_experience"></a>
## 让刷新后的文章可以独立阅读

最终文章面向首次接触项目的读者，应先交代问题和使用场景，再解释流程、关键概念、限制以及与其他材料的关系。标题按功能命名，内部标识、日志和校验计数不应成为叙事主线。多阶段流程可在证据充分时使用简洁图示，但不应为形式而堆砌表格或图。参考 [面向读者的写作要求 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/skills/omem-knowledge-refresher/SKILL.md#L16 "支持文章组织、功能化标题、图表使用和引用可读性方面的要求。")

即使移除引用标记，正文也必须保持语义完整；直接证据放在相关句段末，只有提供背景而不直接支持论断的材料才作为延伸阅读。这使文章兼顾证据定位与连续阅读体验。
