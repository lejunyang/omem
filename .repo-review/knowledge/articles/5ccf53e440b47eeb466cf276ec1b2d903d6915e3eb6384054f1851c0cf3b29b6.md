# Code Wiki 通用纵向切片：Vue 3 交互与组件设计

这是一份 2026-09-28 的界面与组件设计稿，不是生产实现。它基于当时仓库 HEAD 描述 ReviewApp 的五态页面、已有 UI 组件和关系 API，并提出仓库总览、确定性关系图、源码查看器、证据 trail、安全 Markdown、统一状态表达及响应式验收方案。后端行号与精确符号边、模型摘要不在本切片内；服务端同步 hash 与跨设备深链也明确不在范围内，且文档认为当前单用户本地场景没有这项需求。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

## 文档性质、历史现状与主要缺口

本文明确标为“设计稿 v1”，只规定界面与组件合同，不修改生产代码；其中“当前”仅代表 2026-09-28、仓库 HEAD `46d808a` 的历史状态，“拟实现”和验收脚本都不能视作已经交付。[设计稿状态与标记约定 ↗](../../../docs/implementation/code-wiki-ui-design.md#L1 "支持本文只是界面和组件合同，并界定“当前”“拟实现”“后续”的时间与事实边界。")

当时 ReviewApp 以五个内存 `ref` 状态组织浏览、阅读、搜索、代码追溯与同步，没有路由或可恢复深链；关系状态虽已由服务端归一化，但下探仍会替换主视图。[ReviewApp 历史信息架构 ↗](../../../docs/implementation/code-wiki-ui-design.md#L15 "说明当时五态内存视图、各入口和数据流，以及关系状态由服务端处理的事实。") 文档归纳的核心体验缺口包括：没有仓库总览和架构图、源码无行号与锚点、证据路径无法返回或刷新恢复、Markdown 裸显示、内容来源与关系状态混杂，以及移动端尚未验收。[界面缺口清单 ↗](../../../docs/implementation/code-wiki-ui-design.md#L42 "支持总览、架构图、源码阅读、trail、深链、状态表达和响应式等问题定义。")

<a id="proposed_experience"></a>
## 拟议的信息架构与证据表达

新入口拟改为仓库总览，通过已有健康、分类和关联接口展示同步 commit、材料规模、关系健康及分类矩阵；从未同步或没有登记关系时使用真实空态，不填演示数据。[仓库总览与空态设计 ↗](../../../docs/implementation/code-wiki-ui-design.md#L61 "解释拟议首页的数据来源、展示内容及禁止使用演示数据的空态原则。") 关系浏览拟采用手写 SVG 的固定分层布局，以代码、意图及决策／调研／测试构成两跳邻域；确认、候选、过期和缺失边具有不同线型，并在渲染失败或无关系时退化为分组列表。该方案是设计选择，尚无实现验证。[确定性关系图方案 ↗](../../../docs/implementation/code-wiki-ui-design.md#L83 "支持手写 SVG、四列关系布局、状态样式、两跳邻域和列表降级方案。")

详情内容被划分为不可变原文、人工 seed 派生说明和关键词候选三层；raw、derived、candidate 属于内容来源，不能与 confirmed、missing、stale 等关系状态混为一谈。缺失目标应展示原因且不可伪装成可跳转对象。[原文、派生与候选分层 ↗](../../../docs/implementation/code-wiki-ui-design.md#L125 "说明三种内容层的来源和视觉区别，以及证据行对缺失关系的处理。")

<a id="trail_and_rendering"></a>
## 证据 Trail、源码与安全渲染合同

核心交互是一个非模态右侧 `OmTrailDrawer`：单个抽屉承载帧栈，支持 push、pop、面包屑跳转、环检测、逐层滚动恢复与关闭后的焦点归还。选择 drawer 是为了在桌面端保留背景源码可见；需要焦点陷阱的追问或新增关系仍由 `OmDialog` 承担。[单浮层 Trail 交互 ↗](../../../docs/implementation/code-wiki-ui-design.md#L209 "支持 drawer 与 dialog 的职责边界，以及帧栈、返回、环检测、焦点和滚动恢复合同。") 深链拟使用 `location.hash` 顺序恢复视图和帧，损坏或 404 时降级到总览；该切片不引入 vue-router。服务端同步 hash 与跨设备深链明确不做，原文将其解释为单用户本地工具当前没有此需求，而非已规划的后续能力。[Hash 深链与范围边界 ↗](../../../docs/implementation/code-wiki-ui-design.md#L236 "说明无 vue-router 的路径恢复、错误降级和浏览器后退，并明确跨设备深链当前没有需求且不在本切片范围内。")

源码查看器拟提供行号、锚点与按需语法高亮，但当前 fragment 没有真实行范围，过渡期只能按段落顺序推算并显式标注；符号跳转也只是名称匹配，精确调用点依赖后续 AST 工作。[源码查看器的过渡限制 ↗](../../../docs/implementation/code-wiki-ui-design.md#L157 "支持当前缺少真实行号和精确符号边，以及客户端推算和名称匹配仅为临时兜底。") Markdown 与高亮生成的 HTML 必须经过严格白名单净化，围栏代码交由源码查看器处理，相对文档链接则转成内部导航。[Markdown 与高亮安全配置 ↗](../../../docs/implementation/code-wiki-ui-design.md#L281 "支持白名单净化、代码块分流、内部链接拦截和按需加载要求。")

## 实施边界、响应式与验收条件

设计要求通用能力下沉到 `packages/ui`，新增 trail、源码查看、Markdown、状态行、关系图和 hash 路由薄封装，同时继续复用既有 Shell、Badge、Panel、Empty、Dialog 与 Citation。[通用组件复用与新增清单 ↗](../../../docs/implementation/code-wiki-ui-design.md#L332 "支持哪些现有组件直接复用，以及哪些能力计划下沉到 packages/ui。") 桌面端保留三栏和 560px 抽屉，中屏加宽抽屉，700px 以下改为全屏 trail、关系分组列表和窄行号栏；键盘操作、屏幕阅读器播报、减弱动画及非纯颜色状态表达均属于验收范围。[响应式与无障碍要求 ↗](../../../docs/implementation/code-wiki-ui-design.md#L365 "说明三个断点的布局变化及 trail、SVG、异步播报和触屏操作的无障碍合同。")

完成定义包括桌面五层下探与环检测、深链刷新、390px 移动端流程以及空态和断网错误；文档同时说明这些步骤在当时 HEAD 上跑不通。[真实消费闭环验收脚本 ↗](../../../docs/implementation/code-wiki-ui-design.md#L388 "支持桌面下探、深链刷新、移动端和错误空态是拟实现后的完成定义，而非当前已通过能力。") 明确不在本切片内的内容有后端字段或精确符号边、模型与 ACP、第三方图布局库、个人助理模式改造；并且本文件自身不写生产代码。[切片明确边界 ↗](../../../docs/implementation/code-wiki-ui-design.md#L422 "界定不改后端、不接模型、不引入第三方路由或图布局库、不改个人助理和不写生产代码。") 真实包体积、SVG 展示效果、浏览器历史一致性和完整测试仍待实现阶段验证。[验证状态与剩余限制 ↗](../../../docs/implementation/code-wiki-ui-design.md#L432 "支持包体积、SVG 效果、浏览器历史一致性和测试仍需在实现阶段验证。")
