# 可审计的角色 Agent 运行时

agent-runtime 将版本化角色资产、固定证据上下文、模型传输、结构化结果校验和持久任务衔接为受控执行链。它已实现资产校验、信任分层、预算限制、有限修复与运行追踪；结果保存和任务完成之间仍存在恢复窗口，运行时请求的并发决议与作用域边界也需继续确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为什么需要角色运行时

该模块让代码分析、对话分析等角色在统一边界内运行，而不是由业务代码临时拼接模型调用。角色清单声明提示模板、技能版本、输出合同、工具策略、会话隔离与资源预算；代码分析角色例如被配置为不使用工具、不复用会话，并输出知识批次。参考 [角色运行配置 ↗](../../../packages/agent-runtime/roles/code-analyst/1/manifest.json#L2 "支持角色清单声明提示、技能、输出合同、隔离策略和预算边界。")

加载器会核对角色身份、输出 Schema、技能名称和制品摘要，再将清单、提示、Schema 与技能内容汇总为稳定的角色包身份。参考 [角色包加载与身份生成 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L105 "支持清单身份、输出 Schema、技能名称和摘要校验，以及稳定角色包身份的生成。") 路径安全由更前置的检查承担：资产必须存在且位于角色根目录，真实路径不得越界，候选文件本身不能是符号链接；递归枚举技能目录时直接遇到符号链接也会拒绝。参考 [角色资产路径检查 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L41 "直接支持根目录归属、真实路径越界、候选文件符号链接和技能目录枚举符号链接的安全边界。")

<a id="execution"></a>
## 从固定材料到结构化结果

提示组装时，角色说明、内联技能、输出合同与来源元数据进入可信区，派生文章和材料正文则标为非可信数据；文本、图片及上下文还要经过大小、摘要与类型检查。参考 [提示信任分层 ↗](../../../apps/server/src/agent-runtime/gateway.ts#L106 "支持可信角色配置和来源索引与非可信派生知识、材料正文的分层及上下文检查。")

执行前会合并预算、核对 profile 和工具能力、准备工作区。每次尝试重新渲染提示并估算输入量；ACP 可携带图片和托管工具，并从会话配置回读有效模型与推理强度，CLI 只接收文本且继续使用 profile 初始化值。输出随后接受预算、单一 JSON 对象、共享合同及调用方附加校验。参考 [执行前校验、传输分支与结果验证 ↗](../../../apps/server/src/agent-runtime/gateway.ts#L258 "支持预算合并、profile 与工具能力校验、工作区准备，以及模型配置初始化、ACP 配置回读、CLI 文本限制、输入输出预算和结构化结果校验流程。") 只有执行块内的输出类错误、`SyntaxError` 或 `ZodError` 才会在未取消且仍有次数时修复，次数耗尽则明确失败。参考 [有限输出修复 ↗](../../../apps/server/src/agent-runtime/gateway.ts#L396 "直接支持可修复错误类型、取消状态和修复次数耗尽时的判定。")

成功 trace 保存模型、会话、用量、修复次数及各类摘要；运行指纹只由角色包、提示、上下文、技能、工具摘要和有效 model、effort 组成。参考 [运行追踪与指纹 ↗](../../../apps/server/src/agent-runtime/gateway.ts#L368 "支持 trace 的记录字段及运行指纹的限定组成。") 知识合同统一约束文档、章节、引用和问题的结构，但正文引用键等跨字段语义仍需附加校验落实。参考 [知识输出共享合同 ↗](../../../packages/contracts/src/knowledge.ts#L3 "支持知识文档、章节、引用和问题的统一结构，并界定静态合同的约束范围。")

<a id="jobs-and-persistence"></a>
## 与持久任务系统协作

角色任务处理器按任务生成上下文、调用运行网关、确认会话标识，再把结构化结果和完整 trace 保存为可引用的角色输出。参考 [角色任务适配器 ↗](../../../apps/server/src/agent-runtime/job-handler.ts#L18 "支持按任务构造上下文、调用网关、检查会话并保存角色输出的衔接流程。") Worker 负责领取租约、维持心跳、传递取消信号，并在处理器返回后另行把任务标记为成功；异常则进入取消、失败或有限重试流程。参考 [持久任务执行循环 ↗](../../../apps/server/src/jobs/worker.ts#L47 "支持租约领取、心跳、处理器调用、任务成功更新及失败分类处理。")

仓库保存角色输出时，会在一个事务内验证运行租约、更新本次尝试的 trace 并插入输出；任务成功状态由随后独立的 `succeed` 事务更新。参考 [输出保存与任务完成 ↗](../../../apps/server/src/jobs/repository.ts#L452 "支持角色输出保存和任务成功更新由两个独立事务完成，据此说明两阶段恢复窗口。") 因而两部分都可追踪，但进程若在两次事务之间退出，可能留下“输出已保存、任务尚未成功”的恢复窗口。

<a id="limits"></a>
## 当前边界与待完善能力

令牌量按 UTF-8 字节近似估算并增加余量，不是模型专用 tokenizer；预算构造只校验各字段为规定范围内的安全整数，不能证明组合一定适配具体模型。参考 [令牌估算与预算边界 ↗](../../../apps/server/src/agent-runtime/budget.ts#L1 "支持 UTF-8 近似估算、余量、默认预算和单字段数值校验的能力与限制。")

运行时请求仓库能够记录被拒绝的权限或信息征询，并提供请求决议与查询；但决议更新未检查受影响行数，批准或拒绝动作没有写入该表，列表也未显示工作区过滤或分页。参考 [运行时交互请求仓储 ↗](../../../apps/server/src/agent-runtime/requests.ts#L40 "支持拒绝记录、请求决议和列表查询的实现范围，以及并发、动作持久化与作用域限制。") 此外，所给材料没有展示角色工作区清理策略，也没有证明崩溃窗口会复用已有输出。
