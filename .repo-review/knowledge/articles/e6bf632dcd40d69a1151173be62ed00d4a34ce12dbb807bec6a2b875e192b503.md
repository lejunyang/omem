# 中文语义检索嵌入模型加载器

该模块定义统一的嵌入接口，并从 osdk 管理的不可变本地快照加载 BGE-small-zh-v1.5。加载过程校验仓库、版本与关键文件哈希，禁止运行时联网；查询和正文采用不同输入形式，输出经 CLS 池化与归一化。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-contract"></a>
## 作用与接口边界

该文件为中文语义检索提供统一的嵌入能力。`EmbeddingModel` 暴露模型身份、按 `query` 或 `passage` 用途批量生成向量，以及释放资源三个操作；接口注释要求身份涵盖权重、分词器、池化、查询指令和窗口版本，以便调用方识别不兼容的向量配置。[嵌入模型接口契约 ↗](../../../apps/server/src/retrieval/embedding.ts#L7 "支持模型接口包含身份、按用途生成向量和资源释放能力，并说明身份设计需要覆盖哪些向量配置。")

当前材料只呈现加载器本身，没有展示索引建立、查询或加载旧索引的调用路径，因此不能确认模型身份是否会被端到端强制校验，也不能据此断言模型变化一定会阻止旧向量混用。

<a id="verified-loading"></a>
## 受校验的本地加载流程

加载器通过 `osdk model show` 获取指定别名的快照元数据，并限定命令超时和输出大小；若仓库不是指定的 BGE-small-zh-v1.5，或 revision 与代码锁定值不一致，该加载过程会抛错并拒绝加载该快照。[快照发现与版本校验 ↗](../../../apps/server/src/retrieval/embedding.ts#L14 "支持加载器从 osdk 获取快照，并在仓库或固定 revision 不符合要求时让当前加载过程失败。") 随后它读取配置、分词器、词表和量化 ONNX 模型，逐项计算 SHA-256，与 osdk 清单核对；缺少预期哈希或内容不一致同样会失败。[关键模型文件完整性校验 ↗](../../../apps/server/src/retrieval/embedding.ts#L22 "支持逐项读取关键文件、计算 SHA-256，并在清单缺失或校验不一致时抛错的说明。")

校验完成后才创建特征提取流水线。实现关闭远程模型与文件系统缓存，要求仅从本地快照加载，并固定使用 CPU、q8 精度和两个推理线程；这保证本函数不会隐式联网下载，同时要求运行环境预先具备完整快照及推理依赖。[离线量化推理配置 ↗](../../../apps/server/src/retrieval/embedding.ts#L29 "支持禁止远程模型和文件系统缓存，并仅使用本地快照、CPU 与 q8 精度创建流水线的边界。")

<a id="embedding-behavior"></a>
## 向量生成、身份与资源释放

返回对象的 `id` 由固定配置标签与全部受检文件哈希派生；受检内容变化会产生不同身份，可供调用方识别向量配置不兼容，但本文件没有证明索引侧一定保存并强制核对该身份。[内容绑定的向量身份 ↗](../../../apps/server/src/retrieval/embedding.ts#L35 "支持模型身份由配置标签和受检文件哈希派生；该引用仅证明身份生成，不证明调用方必然强制隔离索引。") 标签包含 `window400-v1`，然而当前材料未显示明确的长度切分、截断参数或窗口单位，因此其与实际输入处理的一致性仍需从调用层或 tokenizer 配置确认。

生成向量时，仅 `query` 会添加中文检索指令，`passage` 保持原文；两者随后统一使用 CLS 池化并归一化，调用方必须正确传入用途。`close` 显式释放 extractor，说明资源生命周期由调用者负责；空输入、超长文本、关闭后复用及推理错误的处理未在本文件中说明。[查询指令、池化与资源释放 ↗](../../../apps/server/src/retrieval/embedding.ts#L37 "支持查询与正文的不同预处理、CLS 池化、向量归一化及显式释放 extractor 的行为。")
