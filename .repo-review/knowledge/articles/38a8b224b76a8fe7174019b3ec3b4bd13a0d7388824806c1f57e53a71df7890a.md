# Extractor 与 Verifier 的实时角色冒烟流程

该脚本选择可用的 TraeX 实时配置，以固定上下文串联 extractor 与 verifier，并保存两阶段结果和 trace；它验证显式编排能完成，不构成语义质量验收。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="setup"></a>
## 配置与输入

脚本从应用配置中查找 `traex` profile，再通过实时能力选择取得可运行配置；缺少该 profile 会立即失败。固定示例 context 经合同 schema 解析，随后实例化 `RoleBundleRegistry` 与 `RoleRuntimeGateway`。[实时角色运行初始化 ↗](../../../scripts/live-role-smoke.ts#L10 "支持 TraeX profile 选择、固定 context 校验，以及两个运行时类的实例化。") 本文件没有进一步说明网关内部采用哪种 CLI 或 ACP 传输实现。

<a id="flow"></a>
## 提取到复核

第一阶段调用 `extractor` 并读取 proposals；第二阶段复制 context，更换 verifier 的 job 与 role，为每项 proposal 计算稳定摘要并放入 candidates，然后调用 `verifier`。[提取与复核串联 ↗](../../../scripts/live-role-smoke.ts#L26 "说明 extractor 的 proposals 如何生成摘要并作为 verifier 的候选输入。") 这证明脚本显式串联了两次角色调用，但没有断言 proposal 数量、复核 verdict、引用支持性或 trace 完整性。

<a id="report"></a>
## 报告与脚本边界

报告保存固定 fixture、生成时间，以及提取和复核两阶段的 result 与 trace；默认写入本地验证路径，也允许环境变量覆盖，并把主要结果打印到标准输出。[实时冒烟报告持久化 ↗](../../../scripts/live-role-smoke.ts#L48 "支持报告内容、可覆盖输出路径、文件模式和标准输出行为，并界定脚本显式执行的步骤。") 新建目录和文件时分别请求 `0700`、`0600` 模式。本脚本未显式写入知识库、应用 proposal，也未显式配置重试、超时或语义门禁；这些行为是否存在于 `gateway.run` 内部无法由本文件判断。
