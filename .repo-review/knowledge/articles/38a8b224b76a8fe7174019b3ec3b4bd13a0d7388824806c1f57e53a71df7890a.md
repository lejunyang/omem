# Extractor 与 Verifier 的实时角色冒烟流程

该脚本选择可用的 TraeX 实时配置，以固定上下文串联 extractor 与 verifier，并保存两阶段结果和 trace；它验证实时配置与编排可运行，不构成语义质量验收。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="setup"></a>
## 配置与输入

脚本从应用配置中寻找 `traex` profile，再经实时能力选择得到可运行配置；缺少 profile 会立即失败。固定示例 context 通过合同 schema 解析，角色包由生产 `RoleBundleRegistry` 和 `RoleRuntimeGateway` 加载执行。[实时角色运行初始化 ↗](../../../scripts/live-role-smoke.ts#L1 "支持 TraeX profile 选择、固定 context 校验和生产角色网关初始化；附近表述已收窄为实时运行配置。") 因此它依赖外部实时角色运行配置，但仅凭本材料不能进一步确认网关具体采用何种传输后端。

<a id="flow"></a>
## 提取到复核

第一阶段运行 `extractor` 并取得 proposals；第二阶段复制 context、更换 verifier 的 job 与 role，为每个 proposal 计算稳定摘要并放入 candidates，然后调用 `verifier`。[提取与复核串联 ↗](../../../scripts/live-role-smoke.ts#L26 "说明 extractor 产物如何加摘要并作为 verifier 的候选输入。") 这证明两个角色可以串联、提取结果可成为复核输入，但没有断言 proposal 数量、复核 verdict、引用有效性或 trace 完整性；当前成功条件主要是调用未抛错。

<a id="report"></a>
## 报告与边界

报告保存提取和复核的 result、trace、fixture 与生成时间，默认写入本地验证路径，也允许环境变量覆盖，并把结果打印到标准输出。脚本仅在创建目录和报告文件时请求 `0700` 与 `0600` 模式，没有显式收紧既有路径权限。[实时冒烟报告持久化 ↗](../../../scripts/live-role-smoke.ts#L48 "支持报告内容、可覆盖路径、创建时请求的权限模式及标准输出行为。") 它不写入知识库、不自动应用 proposal，也未设置显式重试或语义门禁，更适合人工检查实时调用。
