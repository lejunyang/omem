# 服务端 TypeScript 配置

该配置定义 NodeNext、ES2023、严格类型检查及服务端相关源码范围，是服务端应用、共享契约与若干开发和评审脚本的共同 TypeScript 基线；仅凭配置不能证明这些入口均已实现或能成功运行。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="compiler-baseline"></a>
## 编译与类型检查基线

配置以 ES2023 为输出目标，同时把模块格式和解析策略设为 `NodeNext`，并启用 Node 类型、`strict` 与 `noUncheckedIndexedAccess`。这些设置面向现代 Node.js 环境，并要求索引访问显式处理可能缺失的值；`esModuleInterop` 提供 CommonJS 互操作便利，`skipLibCheck` 则跳过依赖声明文件检查。[服务端编译器选项 ↗](../../../tsconfig.server.json#L1 "支持 ES2023、NodeNext、严格检查、Node 类型及相关互操作选项的配置说明。")

<a id="source-scope"></a>
## 纳入范围与事实边界

检查范围覆盖服务端源码、共享 contracts，以及开发、review 启动、wiki 和 knowledge 等脚本；输出目录声明为 `dist`，根目录为项目当前目录。[服务端项目源码范围 ↗](../../../tsconfig.server.json#L1 "支持该 TypeScript 项目涵盖服务端、共享契约及多类开发和评审脚本的论断。") 这只能证明文件被纳入 TypeScript 项目，不能证明对应功能已实现、已执行或测试通过。根 `tsconfig.json` 继承本配置并关闭输出，因此经根入口检查时不会生成 `dist` 文件。[根配置关闭输出 ↗](../../../tsconfig.json#L1 "说明服务端配置虽声明 `dist`，但通过根配置入口运行时会被 `noEmit` 限制为只检查。")
