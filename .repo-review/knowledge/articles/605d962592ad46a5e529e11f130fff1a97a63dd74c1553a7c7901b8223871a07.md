# Code Wiki 原型视觉与交互 P0 差异审计

一份截至 2026-09-29 的只读历史审计，分级对照离线原型、当时前端实现和运行截图。它将 Code Wiki 定位为统一证据模型的代码投影，记录递归证据阅读在容器、栈深、证据呈现、状态语义、响应式与无障碍方面的整改要求，但不证明这些要求已经实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="positioning"></a>
## 定位与证据边界

该审计把 Code Wiki 定义为 omem 统一证据模型在代码域上的类型化投影：仓库采集、提交快照、文件或符号片段、关系与检索分别映射到既有 Source、Revision、Fragment、Relation 与 Retrieval；`repo-review` 只是隔离配置和视图层，不应形成第二套知识库或视觉体系。[Code Wiki 的统一证据模型定位 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L6 "支持 Code Wiki 是统一证据模型的代码投影、repo-review 仅为配置与视图层的论断。")

文档自身标注为 2026-09-29 的只读审计草案，并区分原型、当时实现和运行截图三类证据。它没有修改代码或运行全量检查，截图也来自带未提交工作树的既有服务，因此只能记录历史差距与整改依据，不能据此认定当前实现已经完成。[审计草案与证据分级 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L1 "说明文档日期、只读性质，以及原型、实现和截图三类证据的边界。")[审计未执行实现与全量检查 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L268 "证明本文没有改代码或运行全量检查，截图也不是整改后的新验证。")

<a id="p0-gaps"></a>
## 核心交互差距

P0 核心合同是用单个居中模态对话框承载递归证据路径：共享焦点陷阱，提供层级顶条、可跳转面包屑、父层预览、四类标签页、原文证据区和底栏追问；逐帧保留滚动及交互状态，Esc 逐层返回，循环目标不重复压栈，实际渲染深度不设硬上限。[递归证据对话框合同 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L50 "支持单一模态容器、路径导航、标签页、证据区与底栏追问的原型合同。")[栈状态与深层导航行为 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L65 "支持焦点归还、滚动保存、Esc 返回、循环检测以及不限制渲染深度的行为要求。")

审计时 Code Wiki 仍使用右侧非模态 drawer，缺少遮罩与焦点陷阱，且栈在多个位置被截为 8 层。帧内未优先呈现“被引用的原文”，路径导航、tabs、footer 和诚实状态也不完整；引用行还存在技术枚举直出、缺少版本与路径提示、错误解释 missing 状态等问题。[非模态抽屉偏差 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L90 "支持当时实现使用右侧 drawer、缺少遮罩和焦点陷阱，并需回归共享模态合同的判断。")[八层截断与帧结构缺失 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L100 "支持栈被截断，以及路径顶条、父层预览、底栏、tabs 和诚实状态缺失的审计结论。")[原文区与引用行偏差 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L119 "支持帧内未突出被引用原文，以及引用行缺少人类标签、版本和正确 missing 语义的问题。")

<a id="shared-design"></a>
## 共享实现方向与状态语义

整改方向是复用 `OmDialog`、既有基础组件和 trail 类型，并把 open、push、back、jump、loop、逐帧滚动及焦点恢复下沉为 `packages/ui` 的共享能力，供 Code Wiki 与 EvidenceReader 共用；路径顶条、单行面包屑、父层预览、四标签页、状态横幅和块级引用行也应作为通用构件提供。[共享组件与 trail 抽取方案 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L164 "说明应复用的现有组件、需要新增的通用构件，以及由 Code Wiki 和 EvidenceReader 共用 trail 能力的方向。")

界面必须展示人类标题、业务版本和中文关系词，隐藏 fragment、edge 等内部标识。技术详情可以折叠，但 stale、candidate、missing 等关键状态必须留在主行；restricted、deleted、anchor_unresolved、superseded 应分别诚实说明，missing 或 external 不可下钻，且任何引用都不得静默改指其他目标。[人类可读引用与技术详情规则 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L190 "支持引用使用人类短语、业务版本和中文关系词，并折叠非关键技术元信息的要求。")[缺失、过期与受限状态规则 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L207 "支持不可用或历史状态的诚实呈现、可操作性边界和禁止静默重定向的要求。")

<a id="acceptance"></a>
## 验收范围与剩余限制

验收覆盖桌面、中屏、移动端和键盘操作：桌面需验证八层以上真实栈、四标签页、逐层 Esc、循环提示、焦点归还和原文优先展示；768 像素下不得横向溢出，且除内联 cite 外，触控或点击目标至少为 44×44 像素；390 像素下对话框全屏、追问纵向堆叠，并禁止页面横向滚动。无障碍还要求切层聚焦标题、面包屑与 tabs 具备正确 ARIA 状态，并可感知异步和错误状态。[桌面与中屏验收条件 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L220 "支持深层栈、tabs、footer、焦点、代码展示、中屏溢出及触控尺寸验收，并明确内联 cite 不受 44×44 像素要求约束。")[移动端与无障碍验收条件 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L241 "支持移动端全屏与无横向滚动，以及键盘焦点、ARIA 和状态播报等无障碍要求。")

文档没有覆盖真实 LLM 追问接入，也没有提供整改后的检查、截图或提交证据；迁移期内 `OmDialog` 与 `OmTrailDrawer` 仍并存。因此后续必须依据当前代码、真实浏览器检查和项目全量检查重新核验，不能把清单目标当作完成记录。[迁移状态与未覆盖事项 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L268 "说明 drawer 与 dialog 尚处迁移并存期、真实 LLM 追问不在本切片，且需要后续重新验证。")
