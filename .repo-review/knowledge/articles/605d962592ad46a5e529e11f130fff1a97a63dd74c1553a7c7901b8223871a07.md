# Code Wiki 原型视觉与交互 P0 差异审计

只读差异审计：指出当时 Code Wiki 的非模态 drawer、八层截断、技术标签和诚实状态与共享递归证据合同不一致；本文没有实施修复或完成全量验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="trail"></a>
## 递归 trail 的核心差异

原型要求单个模态 dialog，而当时 Code Wiki 使用无 backdrop、无焦点陷阱的右侧 drawer；审计要求改回共享 OmDialog 合同。[非模态抽屉差异 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L92 "支持当时 Code Wiki trail 与原型及 EvidenceReader 共享合同不一致。") 当时栈又被硬截到八层，会静默丢失祖先；URL 可以压缩或分页，但渲染栈和面包屑必须保留真实层数。[八层截断缺口 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L100 "支持渲染栈静默丢失祖先及取消硬截断的要求。")

<a id="truth"></a>
## 人类标签与诚实状态

引用行当时直接显示 calls、imports 等技术枚举，缺少版本和“已在当前路径”，并把 missing 错标成外部包。[引用行展示缺口 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L130 "支持技术枚举直出、缺少版本与路径提示以及 missing 状态误标的判断。") 修订规则要求内部标识不进入可见文本、关系映射为人类词；restricted、deleted、anchor_unresolved、superseded、missing、candidate、stale 均需明确呈现，不能静默重定向。[标签与状态呈现规则 ↗](../../../docs/implementation/code-wiki-prototype-gap.md#L190 "支持内部标识不得展示、关系应人类化以及不可操作或历史状态必须诚实呈现。")
