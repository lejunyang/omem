# 飞书质量标注会话服务

该服务把质量数据集中的待审样本组织成仅绑定 owner 可操作的飞书卡片，通过持久化投递意图发送，并在严格校验回调身份、消息上下文、标签版本、有效期和随机 nonce 后，原子记录人工标注、推进样本及更新会话状态。它依赖质量仓储、飞书事件收件箱、加密秘密存储和 SQLite Store；发送执行与 message_id 回填不在本文件中。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-card"></a>
## 解决的问题与交互载体

该服务把质量数据集的人工复核变成连续的飞书卡片流程：卡片展示截断后的原始材料、建议处置、提炼对象与当前进度，并提供“正确、不提炼、需修改、稍后处理”四种动作。按钮值携带协议版本、会话与样本标识、标签摘要、有效期和随机 nonce，使一次 UI 操作具有可验证的业务上下文；完成后则切换为汇总卡片。[标注卡片结构与动作协议 ↗](../../../apps/server/src/quality/lark-annotations.ts#L42 "支持卡片展示内容、四类人工动作及按钮携带校验上下文的说明。")

它并不自行定义样本和标签的业务结构，而是通过 `QualityRepository` 读取进度、当前样本并写入人工结果；仓储侧约束了样本来源、类别、证据文本以及标签对象类型，因此卡片只是既有质量数据模型的人工确认入口。[质量样本与标签数据约束 ↗](../../../apps/server/src/quality/repository.ts#L8 "说明服务依赖的样本来源、类别、证据和标签对象模型由质量仓储定义。")

<a id="start-cancel-delivery"></a>
## 会话启动、重发与取消

启动时先检查同一数据集是否已有活动会话：普通重复请求直接返回已有会话；显式重发会为当前样本生成新 nonce 和到期时间，清空旧 `message_id`，并在同一事务中写入变更记录与新的飞书投递意图。新会话则要求存在待处理样本和有效的个人 owner 私聊目标，再原子创建会话、变更及投递意图。[会话启动与投递意图创建 ↗](../../../apps/server/src/quality/lark-annotations.ts#L180 "支持活动会话去重、显式重发、owner 目标选择以及事务内创建会话和投递意图的流程。")

这里采用 outbox 式边界：服务只把卡片 JSON、摘要、目标、绑定版本和去重标识写入 `delivery_intents`，没有直接调用飞书网络接口。底层 `Store` 提供 SQLite 数据库与事务基础，当前明确是单用户实现。[SQLite 单用户存储基础 ↗](../../../apps/server/src/store.ts#L1 "支持该服务直接依赖 Store 数据库和事务，以及当前存储属于单用户基础的边界说明。") 取消只撤销尚处于 `pending` 或 `retry_wait` 的意图；已经发送、正在发送或已交付的记录不会被伪装成已召回，这是对不可逆外部发送的诚实处理。[取消会话与未发送意图撤销 ↗](../../../apps/server/src/quality/lark-annotations.ts#L151 "支持取消仅处理尚未发送的投递意图，并保留在途及已交付历史的边界。")

<a id="callback-validation"></a>
## 回调校验、状态推进与边界

回调仅接受 `card.action.trigger`。事件先进入 `LarkEventInbox` 持久化；已经处理过的重复事件直接返回幂等成功。随后严格解析按钮协议，并联合检查活动会话、当前样本、owner、会话聊天、原消息、应用、服务端有效期、按钮有效期、标签摘要以及 nonce 哈希；nonce 比较使用定时安全比较，任一条件不符都会把 inbox 记录标为失败。[卡片回调的完整校验链 ↗](../../../apps/server/src/quality/lark-annotations.ts#L355 "支持事件类型、幂等、协议解析、身份上下文、有效期、标签摘要和 nonce 校验的说明。") 飞书事件合同提供了这些身份与上下文字段，但事件持久化和去重的具体实现位于实时集成模块的未提供部分，不能仅凭导入关系推断更多细节。[飞书入站事件合同 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L14 "说明回调校验所依赖的应用、事件、发送者、聊天和消息字段来自实时集成模块公开类型。")

校验通过后，服务在一个数据库事务内写入人工标签、审计事件、收件箱处理状态，查询下一待审样本，并轮换 nonce、推进或完成会话；响应返回成功提示以及下一张卡片或完成卡片。[标注事务与下一样本推进 ↗](../../../apps/server/src/quality/lark-annotations.ts#L395 "支持标注、审计、收件箱处理和会话推进在同一事务内完成，并返回下一卡片或完成卡片。") 边界上，按钮最长有效 30 天，旧标签摘要、旧 nonce、错误消息或非 owner 操作都会失效；`skip` 是否再次成为待处理样本取决于 `QualityRepository.nextPending` 的实现，当前提供的仓储片段不足以确认。
