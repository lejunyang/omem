# 飞书交互卡片驱动的质量标注会话

该服务把质量数据集中的待审样本组织为仅限已绑定 owner 操作的飞书卡片会话，并通过协议校验、事件去重、上下文绑定和事务更新，逐条记录确认、放弃、待修改或跳过结果。它负责生成投递意图与处理回调，不直接证明卡片已成功发送；当前目标选择和存储边界明确面向 personal 单用户场景。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 把质量复核变成连续的卡片任务

服务解决的是“让数据所有者在飞书中逐条复核自动提炼建议”的问题。卡片同时展示原始材料、建议处置、提炼对象和当前进度，并提供“标注正确、应不提炼、需要修改、稍后处理”四种动作；按钮值携带会话、样本、随机 nonce、标签摘要和过期时间，供回调时核验。参考 [质量标注卡片结构 ↗](../../../apps/server/src/quality/lark-annotations.ts#L42 "支持卡片展示内容、四种人工动作以及回调值所携带校验字段的说明。")

这里的进度来自质量仓库，服务只负责编排交互；样本输入本身包含固定来源位置、材料类别和来源可信度信息，因此人工判断仍能回到原始上下文。延伸阅读：[质量样本输入约束 ↗](../../../apps/server/src/quality/repository.ts#L8 "说明质量样本保存来源定位、类别、正文和来源可信度信息。")

<a id="session_flow"></a>
## 启动、续发与取消如何落库

启动时先查找同一数据集的活动会话：默认重复调用只返回既有会话；显式续发则为当前样本换新 nonce、清空消息标识，并在同一事务内写入变更记录和新的飞书投递意图。若没有活动会话，系统取得下一条待审样本，只选择 personal 工作区中处于活动状态的 owner 私聊目标，再创建会话和首个投递意图。参考 [活动会话续发流程 ↗](../../../apps/server/src/quality/lark-annotations.ts#L180 "支持重复启动判定、续发时轮换 nonce，以及事务写入变更和投递意图的流程。")

```mermaid
flowchart LR
  A[待审样本] --> B[活动 owner 私聊目标]
  B --> C[标注会话]
  C --> D[变更记录与投递意图]
  D --> E[飞书交互卡片]
```
参考 [新建标注会话流程 ↗](../../../apps/server/src/quality/lark-annotations.ts#L265 "支持从待审样本和 owner 私聊目标创建会话、变更记录与投递意图的流程图。")

取消操作仅撤销尚未发送或等待重试的投递意图；已经发送、正在发送或结果未知的请求不会被伪装成已撤回，从而保留真实投递历史。参考 [取消会话的投递边界 ↗](../../../apps/server/src/quality/lark-annotations.ts#L151 "说明取消与待发送意图在同一事务更新，并保留发送中及已送达历史。")

<a id="callback_validation"></a>
## 回调的身份绑定、幂等与推进

回调只接受卡片动作事件，并先写入事件收件箱。已处理过的重复事件会直接返回“已经记录”；新事件必须通过严格协议解析，再同时匹配活动会话、当前样本、owner 身份、会话聊天、消息、应用、有效期、标签摘要和 nonce。任何一项不符都会把收件记录标为失败并返回统一的无效提示。参考 [卡片回调完整校验 ↗](../../../apps/server/src/quality/lark-annotations.ts#L355 "支持事件类型限制、收件箱去重、协议解析及会话上下文多条件校验。")

校验通过后，服务在事务中写入人工标签和审计事件，将收件记录标为已处理，取得下一条待审样本并轮换 nonce；有下一条时返回更新后的卡片，没有时结束会话并显示汇总。这样一次点击同时推进样本状态、事件状态和会话游标。参考 [标注事务与下一条卡片 ↗](../../../apps/server/src/quality/lark-annotations.ts#L395 "支持标签、审计事件、收件状态和会话游标在事务中更新，并返回下一张或完成卡片。")

<a id="boundaries"></a>
## 职责边界与已知限制

该类依赖 `QualityRepository` 读取进度、样本并写入标签，依赖 `LarkEventInbox` 持久化入站事件，依赖加密秘密存储派生 nonce 哈希；数据库事务由共享 `Store` 提供。参考 [标注服务依赖关系 ↗](../../../apps/server/src/quality/lark-annotations.ts#L3 "支持该服务对 Store、飞书事件收件箱、秘密存储和质量仓库的直接依赖。")

当前实现具有明确边界：只选择 personal 工作区的活动 owner 私聊绑定；会话动作默认三十天过期；没有待审样本或合适目标时直接报错。底层 Store 也明确以 SQLite 单用户为现阶段基础，不能据此推断已有团队租户隔离。参考 [owner 私聊与有效期限制 ↗](../../../apps/server/src/quality/lark-annotations.ts#L265 "支持 personal 工作区、owner 私聊目标筛选、活动状态要求和三十天有效期限制。") [单用户 SQLite 基础 ↗](../../../apps/server/src/store.ts#L4 "说明当前共享存储明确是单用户基础，团队权限执行仍属于后续迁移。")

此外，本文件生成的是 `delivery_intents`，并未包含实际网络发送过程；回调却要求数据库中的 `message_id` 与事件一致，因此消息发送后如何回填该字段属于其他模块职责，仅凭当前材料无法确认具体实现。参考 [消息标识的创建与校验 ↗](../../../apps/server/src/quality/lark-annotations.ts#L289 "启动时会话消息标识为空，而回调要求其与入站事件一致，支持指出发送后的回填职责不在当前文件中。")
