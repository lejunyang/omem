# 上游研究来源清单与内容摘要

机器可读地登记17个上游仓库的固定提交、提交时间、许可证核验结果，以及被检查文件的 URL 和 SHA-256；用于复查研究输入，不代表运行 benchmark、依赖锁定或集成完成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="method"></a>
## 记录方法与覆盖范围

该清单记录2026年9月26日的检查结果，方法包括 GitHub API 提交元数据、不可变提交下的 README 与许可证内容，以及少量 API 或源码抽查；材料明确没有执行运行时 benchmark。[来源清单方法 ↗](../../../docs/research/sources.json#L1 "支持检查日期、固定源码检查方法及未进行运行时 benchmark 的边界。") 配套索引逐项列出的17个项目与该机器清单相对应。[17个项目的人读索引 ↗](../../../docs/research/source-index.md#L5 "配套索引逐项列出17个项目，支持机器清单覆盖数量和项目范围的说明。") 每个条目保存分支、完整 commit SHA、提交时间、归档状态、正文核验许可证，以及检查文件的 URL 和 SHA-256，用于复核当时输入和发现内容漂移。

<a id="depth"></a>
## 核验深度并不相同

多数项目只登记许可证与 README，例如 LightRAG 保存了固定提交及两个文件的摘要和链接。[LightRAG 固定来源记录 ↗](../../../docs/research/sources.json#L5 "以具体条目说明仓库元数据、固定提交、文件 URL 与 SHA-256 的记录结构。") WeKnora 则额外检查处理器、路由和类型定义，并区分项目核心 MIT 与第三方 notices，说明部分候选接受了更深的接口和实现抽查。[WeKnora 深度源码抽查 ↗](../../../docs/research/sources.json#L49 "支持 WeKnora 除许可证和 README 外还检查处理器、路由及类型源码，并记录第三方 notices 边界。") LangMem 还纳入概念指南，Hindsight 纳入 Go 客户端 OpenAPI；文件集合随研究问题变化，不能把所有条目理解为同等深度的审计。[LangMem 概念文档记录 ↗](../../../docs/research/sources.json#L235 "支持 LangMem 条目额外纳入概念指南，而非只检查 README 和许可证。")[Hindsight OpenAPI 记录 ↗](../../../docs/research/sources.json#L387 "支持 Hindsight 条目额外检查 Go 客户端 OpenAPI 文件的说明。")

<a id="interpretation"></a>
## 许可证消歧与结论边界

`license` 字段可以保留平台返回的 `NOASSERTION`，同时由 `verified_license` 或补充说明记录许可证正文结论。memU 通过 `LICENSE.txt` 确认为 Apache-2.0，[memU 许可证消歧 ↗](../../../docs/research/sources.json#L26 "支持平台许可证字段为 NOASSERTION，但通过 LICENSE.txt 正文确认 Apache-2.0 的事实。") pgvector 则通过许可证正文确认为 PostgreSQL 许可证。[pgvector 许可证记录 ↗](../../../docs/research/sources.json#L303 "支持 pgvector 将平台 NOASSERTION 与正文核验出的 PostgreSQL 许可证分开保存。")

这些记录能够证明哪些固定源码和文件被查看，却不包含运行结果、性能数据、契约兼容性或生产配置。因此不能据此声称项目已经接入、能够替换现有组件，或满足真实工作负载。
