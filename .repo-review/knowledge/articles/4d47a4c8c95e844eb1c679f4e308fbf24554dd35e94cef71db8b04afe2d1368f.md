# 知识文章导出与恢复

该模块把已复核知识导出为稳定命名的 JSON 与 Markdown，并按依赖恢复文章；JSON 解析失败仅返回 rejected，而进入 pending 后处理出的状态才写入导入状态表。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="render"></a>
## Markdown 投影

`articleMarkdown` 把正文内联引用转换为链接：文章目标使用文档 key 摘要命名的 Markdown 和可选章节锚点，仓库材料链接到源文件行，其他材料退化到证据锚点。引用定义缺失时显示“引用不可用”。输出还标注生成与独立复核模型，并提醒模型解释仍可被原始证据纠正。[文章 Markdown 渲染 ↗](../../../apps/server/src/knowledge/artifacts.ts#L8 "支持内联引用替换、目标链接、章节锚点、不可用提示及生成和复核来源说明。")

<a id="write"></a>
## 稳定命名与幂等写出

发布时创建目标目录，从文章对象排除运行态的 `current` 与 `revision`，再用文档 key 摘要作为稳定文件名，同时生成 JSON 与 Markdown。文件不存在或内容变化时才写盘，可减少无意义改写。[知识文件写出 ↗](../../../apps/server/src/knowledge/artifacts.ts#L21 "支持稳定文件名、JSON 与 Markdown 双输出，以及仅在内容变化时分别写盘。") 两个文件仍是顺序、分别写入；实现没有事务、临时文件重命名或目录切换来保证二者原子成对可见。

<a id="restore"></a>
## 依赖有序恢复与状态边界

恢复先读取排序后的 JSON。这里需要区分两类 rejected：JSON 解析失败的文件直接加入返回结果，从未进入 pending，也不会写入 `knowledge_imports`。[JSON 读取与解析失败 ↗](../../../apps/server/src/knowledge/artifacts.ts#L32 "直接支持解析失败文件只加入 rejected 返回结果、未进入 pending 的边界。") 可解析条目才进入最多 100 轮的 pending 处理；文章依赖未就绪时等待，其余条目校验版本、accepted 复核、生成与复核来源、文档结构和固定依赖。来源变化记为 stale，合法且内容变化的条目才发布。pending 内得出的 restored、stale 或校验 rejected 会写入导入状态表。[Pending 校验与状态持久化 ↗](../../../apps/server/src/knowledge/artifacts.ts#L40 "支持依赖等待、来源校验、stale/rejected/restored 判定，并证明进入 pending 后移除的条目会写入 knowledge_imports。")

循环停止后仍未解决依赖的条目只以 missing 加入本次返回，不持久化导入状态；最后刷新 current 标记。[未解依赖与最终刷新 ↗](../../../apps/server/src/knowledge/artifacts.ts#L56 "支持剩余 pending 仅追加 missing 返回结果而不写入状态表，随后刷新仓库。") 因而先前“所有 rejected 和 missing 都会持久化”以及笼统的“所有已处理条目状态均持久化”结论，均被上述范围限定所替代。
