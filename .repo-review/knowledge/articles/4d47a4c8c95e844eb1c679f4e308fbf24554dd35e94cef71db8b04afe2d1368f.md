# 知识文章的可读发布与可信恢复

该模块把复核通过的知识文章发布为结构化 JSON 和可读 Markdown，并从发布目录恢复文章。它负责渲染内联引用、按依赖顺序处理产物，以及依据来源摘要、子文章修订和复核来源判定恢复、过期、拒绝或依赖缺失。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 发布机器产物与阅读页面

知识文章需要同时服务程序恢复和人工阅读。发布时以文档键的摘要作为文件名，分别生成 JSON 与 Markdown；目标内容未变化时不会重复写入。Markdown 顶部展示生成模型和独立复核模型，并提醒模型解释仍可由原始证据纠正。参考 [双格式文章发布 ↗](../../../apps/server/src/knowledge/artifacts.ts#L21 "支持文章以稳定名称输出 JSON 和 Markdown、避免无变化重写，并在可读页面标明模型来源。")

<a id="rendering"></a>
## 把内联证据转换为可追溯链接

渲染器先建立引用键索引，再逐节替换正文中的 `[[引用键]]`。文章引用会链接到对应 Markdown 及章节锚点，`omem:` 材料会链接到仓库相对路径和起始行；未知引用显示为不可用。引用标签会去除方括号，引用理由则作为链接提示。参考 [内联引用渲染 ↗](../../../apps/server/src/knowledge/artifacts.ts#L8 "支持引用索引、文章与源码链接转换、章节锚点以及不可用引用的展示方式。")

每节生成稳定锚点，但该模块只负责输出链接，不判断引用在语义上是否支持论断。文档验证会检查每节存在内联引用、引用确实被正文使用、目标与行范围有效；语义正确性由独立模型角色复核。延伸阅读：[引用结构校验 ↗](../../../apps/server/src/knowledge/repository.ts#L41 "说明内联引用的使用、目标和行范围由仓库验证，语义正确性另由独立角色检查。")

<a id="restore"></a>
## 按文章依赖恢复已发布知识

恢复时遍历目录中名称以 `.json` 结尾的条目并尝试读取、解析；读取或解析失败的条目只在本次返回结果中标为 rejected。其余产物进入待处理队列，最多扫描 100 轮；当父文章依赖的子文章尚不可用，或匹配修订的子产物仍在队列中时，父文章会暂缓处理。参考 [依赖优先恢复 ↗](../../../apps/server/src/knowledge/artifacts.ts#L32 "支持恢复过程筛选以 .json 结尾的条目、记录解析失败，并对待处理产物进行多轮依赖扫描。")

实际进入处理分支的产物必须具备版本、accepted 复核结论以及生成和复核模型来源，并通过文档结构校验。来源或子文章摘要不一致时标为 stale；依赖一致且仓库修订不同才发布。每个实际处理完成的产物会写入导入记录；最初解析失败的 rejected 项，以及最终仍在队列并返回 missing 的项，不会由该函数写入该记录。参考 [恢复状态与记录范围 ↗](../../../apps/server/src/knowledge/artifacts.ts#L52 "支持来源校验、结构校验、过期与发布判定，并明确只有实际处理完成的产物写入导入记录。")

<a id="boundaries"></a>
## 稳定身份与当前限制

文档键文件名采用字符串 SHA-256；完整产物修订则基于递归排序对象键、忽略 `undefined` 后的规范化 JSON 计算稳定摘要，避免键顺序制造无意义差异。参考 [稳定摘要规则 ↗](../../../apps/server/src/storage/digest.ts#L3 "解释完整知识产物如何通过规范化对象结构获得稳定摘要。")

该模块依赖知识合同完成结构校验，并通过知识仓库查询材料摘要、文章修订、发布和刷新视图。剩余待处理项统一返回“引用的子知识尚不可用”，因此现有材料不能区分依赖环、永久缺失与扫描上限等原因；文件发布也未展示原子替换或跨进程锁。参考 [文章仓库依赖 ↗](../../../apps/server/src/knowledge/artifacts.ts#L4 "支持该模块直接依赖知识合同、摘要函数、知识仓库和文章类型的说明。")
