# 持续项目理解的状态与生命周期

ContextViews 为每个项目或主题维护一份稳定的知识页身份，统一处理首次建立、手动刷新、暂停、恢复和当前性判断。它把页面内容与生成作业交给 KnowledgePageService 及其仓储、维护器，自己负责范围到页面的映射和面向调用方的聚合状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 把项目范围绑定到一份长期知识页

`ContextViews` 为项目或主题提供稳定的“当前理解”入口。构造时创建 `context_views` 表：`context_id` 指向材料范围，`page_key` 指向知识页且保持唯一，因此一个范围只绑定一份页面，同一页面也不会被多个范围复用。这里只保存身份映射，正文、来源和生成任务继续使用通用知识页设施。参考 [范围与知识页映射 ↗](../../../apps/server/src/knowledge/context-views.ts#L6 "支持 ContextViews 仅记录范围到知识页身份，以及两端唯一约束的说明。")

读取前会按 ID 查找现有项目或主题；找不到就直接报错。页面键则从映射表查询，尚未建立时返回 `null`。参考 [范围校验与页面键查询 ↗](../../../apps/server/src/knowledge/context-views.ts#L14 "支持未知范围报错和未建立映射时返回空页面键的边界。")

<a id="start-flow"></a>
## 从 start 调用到返回聚合状态

代表性调用是 `apply(contextId, "start")`。它先校验范围，再在事务中查页面键；首次启动会生成 `context-view:<UUID>`，用范围信息构造阅读目标，调用页面服务保存，并写入范围与页面的绑定。随后启用自动维护、触发一次观察，最后调用 `read` 返回页面键、维护状态、版本、正文及当前性。参考 [生命周期操作流程 ↗](../../../apps/server/src/knowledge/context-views.ts#L33 "支持 start、refresh、pause、resume 的分支、事务处理和返回状态流程。")

```mermaid
flowchart LR
  A[contextId + start] --> B[校验项目或主题]
  B --> C[生成页面键与阅读目标]
  C --> D[保存知识页并写入绑定]
  D --> E[启用维护并观察]
  E --> F[读取聚合状态]
```
参考 [生命周期操作流程 ↗](../../../apps/server/src/knowledge/context-views.ts#L33 "支持 start、refresh、pause、resume 的分支、事务处理和返回状态流程。")

阅读目标固定使用 `project-understanding` 工作流，标题来自范围名称，材料范围写入 `contextIds`；目标问题覆盖已确认安排、变化依据、未决事项和下一步。范围描述存在时用作场景，否则使用默认的继续讨论场景。参考 [项目理解阅读目标 ↗](../../../apps/server/src/knowledge/context-views.ts#L90 "支持自动创建页面时所用工作流、受众、场景、问题和材料范围。")

<a id="freshness-and-modes"></a>
## 当前性判断与四种操作边界

`read` 默认先刷新仓储，再汇总文章、阅读计划与维护状态。只有文章自身为当前版本、文章仍覆盖计划的现有材料范围，并且维护状态不处于 `queued`、`writing` 或 `failed`，结果中的 `current` 才为真；否则返回相应原因，提醒调用方尚未建立、尚未生成，或需要补读变化后的原文。`list` 先统一刷新，再逐个执行不重复刷新的读取。参考 [聚合状态与当前性 ↗](../../../apps/server/src/knowledge/context-views.ts#L27 "支持列表读取、仓储刷新、当前性组合条件和原因提示。")

四种模式并不对称：没有绑定时只有 `start` 合法；已有绑定时，`refresh` 直接请求重写，不改自动维护开关。`pause` 关闭维护；`start` 与 `resume` 都会启用维护并触发观察，而且要求 Agent 可用。所有分支都在同一事务内完成并返回最新聚合状态。参考 [生命周期操作流程 ↗](../../../apps/server/src/knowledge/context-views.ts#L33 "支持 start、refresh、pause、resume 的分支、事务处理和返回状态流程。")
