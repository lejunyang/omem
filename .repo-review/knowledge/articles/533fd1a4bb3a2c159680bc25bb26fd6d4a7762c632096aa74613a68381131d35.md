# 代码知识投影与仓库评审

Code Wiki 在统一 Capture 材料边界上组织仓库知识、快照化代码结构、人工关系和派生理解，并提供可深链的阅读界面；当前限制集中在关系定位、失败状态、失效深链及模型传输能力差异。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 统一材料边界与快照投影

Code Wiki 不建立第二套源码事实库：评审知识仓库只接纳当前且未删除、非历史别名的材料，代码侧表则把已经捕获的 Fragment 确定性投影为文件、符号、边和快照，不另存权威文件正文。[评审知识仓库材料过滤 ↗](../../../apps/server/src/review/materials.ts#L60 "支持评审知识仓库只返回当前且未删除、非历史别名的材料。")[代码图的 Capture 投影边界 ↗](../../../apps/server/src/code/store.ts#L1 "支持代码侧表是已捕获片段的确定性投影且不另存权威文件正文。") 此处仅能确认知识仓库与代码图共享 Capture 材料边界；旧稿关于“知识文章和问答都已能回到同一固定材料”的更强结论缺少直接材料支持，现已被替代。

评审 Store 与个人工作区隔离，旧历史仅在显式配置时导入。[隔离评审运行库 ↗](../../../apps/server/src/review/store.ts#L100 "支持评审数据与个人工作区隔离以及旧历史仅显式导入。") 代码同步读取 Capture 当前 head 的不可变文本，快照身份包含解析器版本、仓库、提交、dirty 状态和排序内容哈希。[Capture 驱动的代码同步 ↗](../../../apps/server/src/code/sync.ts#L147 "支持代码分析读取不可变 head 修订并据此构造快照。")[代码快照身份组成 ↗](../../../apps/server/src/code/store.ts#L34 "支持解析器版本、仓库、提交、dirty 状态及排序内容哈希共同决定快照标识。") 当前 head 由同步显式切换；源码接口读取指定快照绑定的文本，不回退实时工作树。[显式当前快照指针 ↗](../../../apps/server/src/code/store.ts#L273 "支持同步显式切换当前 head，不能按捕获时间推断。")[固定快照源码接口 ↗](../../../apps/server/src/review/app.ts#L397 "支持源码端点读取快照绑定文本并拒绝回退实时工作树。")

<a id="relations"></a>
## 人工关系与理解复核

代码与需求、决策、调研和测试的 confirmed 关系只来自人工 association，词面相似结果不得自动提升。[人工关联治理合同 ↗](../../../apps/server/src/review/associations.ts#L1 "支持 confirmed 关系来自人工种子且自动相似匹配不得提升状态。") 每条 association 先生成派生意图片段，再形成“代码 implements 意图、意图关联原始依据”的两级链。代码或意图无法定位时，只会写入一条 missing 的 implements 边；若意图缺失，后续下游边不会生成。仅当意图存在而需求、决策、调研或测试材料无法解析时，对应下游边才写为 missing。[两级关系链与缺失分支 ↗](../../../apps/server/src/review/sync.ts#L766 "支持代码或意图缺失只写 missing implements，意图缺失时跳过下游边，而下游材料缺失仅在意图存在时写 missing。") 这替代了旧稿把所有定位失败统一描述为“相应边均写入 missing”的结论。

关系标识按 seed 确定性生成并幂等更新，读取时还会根据对端是否为当前修订、是否已删除计算有效 stale 状态。[关系幂等与有效状态 ↗](../../../apps/server/src/review/store.ts#L430 "支持确定性关系身份、幂等更新、动态 stale 判定及空 seed 集合不触发失效的限制。") 但有效 seed 集合为空时不会失效旧关系。人工模块理解的节点、证据文件或引用别名解析失败会留存 rejected 记录；默认列表只呈现未过期的有效 seed 或 generated 结果。[人工理解定位失败留痕 ↗](../../../apps/server/src/code/understanding-store.ts#L304 "支持节点、证据文件和证据别名解析失败被持久化为 rejected。")[当前理解列表过滤 ↗](../../../apps/server/src/code/understanding-store.ts#L521 "支持默认列表排除 failed、rejected 和 stale 结果，避免其遮蔽有效理解。")

<a id="reading"></a>
## 确定性阅读、模型生成与深链

无模型时仍可读取仓库、快照、文件、符号、边和整图；模型理解属于显式可选能力，未配置模型、校验拒绝或传输失败都不会晋升为当前理解。[确定性代码读取接口 ↗](../../../apps/server/src/review/app.ts#L343 "支持无模型时仍可浏览快照、文件、符号、边和代码图。")[显式代码理解生成入口 ↗](../../../apps/server/src/review/app.ts#L576 "支持模型不可用和生成失败的响应规则，并证明失败不会晋升当前理解。")

前端把知识、模块、文件、符号和片段放入同一 Trail 抽屉，共用返回、跳转、循环、关闭和焦点归还；主视图及完整 Trail 栈可序列化到 URL hash 并恢复。[统一 Trail 抽屉 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L371 "支持多类阅读对象共用返回、跳转、循环、关闭及焦点归还控制。")[Trail 栈的 Hash 恢复 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L218 "支持主视图和完整 Trail 栈写入 URL 并在加载时恢复。") 但恢复后的模块、文件或符号只有在当前图能解析实体时才渲染。目标删除、重命名或脱离当前快照后，内容区可能为空而没有专门的 missing/stale 原因页。[失效 Trail 帧渲染条件 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L383 "支持模块、文件和符号帧依赖当前图解析，说明失效深链的反馈缺口。")

<a id="limits"></a>
## 尚未收敛的可信度边界

解析器仅提供单文件 TypeScript AST、Vue SFC 和保守正则，调用关系仍是名称级 candidate。[离线解析能力边界 ↗](../../../apps/server/src/code/parse.ts#L1 "支持单文件 AST、Vue SFC、保守正则和名称级候选调用的限制。") association 的符号定位另行依赖有限声明正则及最早同名 token 回退，普通方法、重载或同名符号可能误绑定。[关联符号定位实现 ↗](../../../apps/server/src/review/sync.ts#L581 "支持有限声明匹配和最早同名 token 回退，说明其尚非可靠 AST locator。") 完整同步中关系重建异常只进入 warnings，随后仍持久化同步结果，因此“同步完成”不等于关系链完整成功。[关系重建失败语义 ↗](../../../apps/server/src/review/sync.ts#L997 "支持关系构建异常只写入 warnings，随后仍会持久化同步结果。")

模型配置层只校验配置文件、JSON 和 transport 类型并透传 model、effort 与预算字段，不能单独证明后端支持该组合。[评审模型配置边界 ↗](../../../apps/server/src/review/model-config.ts#L14 "支持配置层仅验证文件、JSON 和 transport，并透传模型及预算字段。") 各传输消费预算的方式也不同：ACP 接收请求预算，CLI 与 HTTP 分支未接收该参数。[模型传输预算差异 ↗](../../../apps/server/src/code/understanding-model.ts#L80 "支持 ACP 接收请求预算，而 CLI 与 HTTP 分支未消费该预算参数。") 生成宿主仍会检查输入、输出、引用范围及运行期间 head 移动；未确认的是各后端是否具有统一的能力发现与提前拒绝。[生成宿主的验证栅栏 ↗](../../../apps/server/src/code/understanding-store.ts#L741 "支持输入输出预算、引用范围、取消超时和 head 移动检查，界定未确认能力发现的范围。")
