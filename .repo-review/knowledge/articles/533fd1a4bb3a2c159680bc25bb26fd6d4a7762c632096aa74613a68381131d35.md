# 代码知识投影与仓库评审

repo-review 将仓库文件接入通用 Capture 证据链，在隔离存储中形成不可变代码快照、解析结构图、人工评审关系和经校验的模块理解，并通过共享 Trail 下探代码、需求、决策、研究与测试依据；确定性结构事实、人工判断和模型解释分层保存。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 定位与运行边界

Code Wiki 不是独立事实库，而是通用 Capture→Source→Revision→Fragment 链上的仓库投影：review 负责生产仓库输入，分析仍由通用知识流程消费固定材料。[仓库材料输入适配器 ↗](../../../apps/server/src/review/materials.ts#L1 "支持 repo-review 只生产仓库输入、分析仍属于通用知识流程的定位。") 评审模块的隔离边界与知识过滤规则可继续下钻查看。[评审模块运行边界 ↗](1d40b7d26d0e45f48020a86c0a04e64e7c23827274441b6e238dee9f39308cd0.md#purpose-boundary "提供隔离运行、知识过滤与通用知识链关系的相邻子知识入口。") 运行数据使用独立 Store，默认不导入旧历史，只有显式开启遗留导入才执行播种。[隔离评审存储 ↗](../../../apps/server/src/review/store.ts#L100 "支持独立 Store、默认不依赖旧历史以及显式遗留导入条件。") 服务不装配助手、Lark、学习或通知 worker，并受回环地址、同源或令牌规则保护。[评审服务安全边界 ↗](../../../apps/server/src/review/app.ts#L5 "支持服务未装配业务 worker，并说明回环、同源和令牌访问限制。")

<a id="capture_graph"></a>
## 从仓库材料到不可变代码图

仓库同步按白名单读取文件，以相对路径保持来源身份；内容摘要相同则复用当前 revision，新内容追加不可变 revision，并记录提交、dirty 与同步时间。[仓库文件固定捕获 ↗](../../../apps/server/src/review/sync.ts#L427 "支持路径来源身份、内容摘要去重、不可变 revision 与同步上下文的形成。") 随后的代码同步只读取 Capture 当前固定修订，不把实时工作树正文与旧片段混合；完整的输入和快照协调流程可下钻到代码同步子知识。[Capture 驱动的代码同步 ↗](77a2bfa010fcb7c75cfc06e221def951343d041b819f5adf30ede8d0dcd8a178.md#input_snapshot "提供固定输入、快照身份与同步协调流程的相邻子知识入口。") 文件、符号、边和快照采用确定性身份，符号范围与 fragment 归属于具体快照，旧状态继续保留。[代码图确定性身份 ↗](../../../apps/server/src/code/store.ts#L7 "支持文件、符号、边及快照的确定性身份，并说明符号身份包含路径、限定名和类型。")

代码图的结构边由解析器产生：可解析的 import、route 和 test_of 可成为 confirmed，单文件名称级 call 与组件使用则保持 candidate。[解析器结构关系投影 ↗](../../../apps/server/src/code/sync.ts#L291 "证明代码图仍可由解析器产生 confirmed 的 imports、route、test_of 边，同时 calls 与组件使用保持 candidate。") 因而“所有 confirmed 代码关系都只能来自人工种子”的旧结论已被替代；人工治理只适用于下节所述代码—意图—依据评审链。

<a id="relations_understanding"></a>
## 人工评审关系与经校验的模块理解

代码—意图—依据的 confirmed 评审关系由人工 association seed 治理；未登记的词面相似命中不得自动提升为 confirmed。[人工评审关系合同 ↗](../../../apps/server/src/review/associations.ts#L1 "限定人工种子治理的是代码与意图、需求、决策、研究、测试之间的评审关系，并禁止词面相似自动确认。") 同步为每条 seed 建立意图片段，在当前 head 定位代码以及需求、决策、研究和测试锚点，并确定性写入 implements、requires、decided_by、researched_by 与 tested_by；无法定位的端点保留为 missing。[人工评审关系构建 ↗](../../../apps/server/src/review/sync.ts#L699 "支持意图片段建立、当前 head 定位、确定性关系写入及无法解析端点保留为 missing。")

模块理解则是另一层派生投影：人工 seed 引用固定代码图与证据，通过严格合同校验，但不会改写原始文件、符号或边。[理解投影的数据边界 ↗](../../../apps/server/src/code/understanding-store.ts#L1 "支持人工模块理解是引用固定图与证据的派生投影，不改写原始代码图。") locator、证据文件或引用提示无法解析时会持久化 rejected 结果，不静默丢弃，也不覆盖有效理解。[定位失败的拒绝记录 ↗](../../../apps/server/src/code/understanding-store.ts#L304 "支持当前快照中 locator、证据或引用提示无法解析时持久化 rejected 结果。") 更细的投影、交叉引用校验和失败隔离规则可下钻到理解存储子知识。[代码理解投影与校验 ↗](b3371593c4922018b730c855f682b8fe880f0633812ad1d353f218a718c4abc2.md#projection "提供人工种子、固定证据、严格合同及失败隔离的相邻子知识入口。")

<a id="reading_model_limits"></a>
## 共享阅读、显式模型与当前限制

文件、符号和证据片段统一转换为共享 Trail 帧，[统一证据下探 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L185 "支持文件、符号和证据片段统一转换为共享 Trail 帧。") 页面编排、整栈导航与详情分派可下钻到 Code Wiki 子知识。[Code Wiki 下探与深链 ↗](c7d146673237fb15547f8534001912445b4b4ef8cb6c32403bc9d240682a5c76.md#navigation "提供页面编排、Trail 入栈、整栈深链和详情分派的相邻子知识入口。") 模型端口默认关闭，启动只提供结构图和人工 seed；生成必须显式请求，无配置时返回不可用。[默认关闭与显式模型生成 ↗](../../../apps/server/src/review/app.ts#L645 "支持模型端口默认关闭、不会在启动时调用实时模型，以及生成必须显式请求。") 输入输出预算、取消、超时、传输失败及畸形输出会留下失败记录，不能晋升为当前理解。[模型运行与预算防线 ↗](../../../apps/server/src/code/understanding-store.ts#L674 "支持输入输出预算检查、取消、超时、传输失败及畸形输出的失败持久化。") 合同校验后还会拒绝模型未实际看到的越界引用；若生成期间代码 head 移动，则结果作为失败尝试保存，而不发布为当前理解。[引用范围与 head 移动防线 ↗](../../../apps/server/src/code/understanding-store.ts#L834 "支持模型引用必须来自实际展示范围，并证明生成期间 head 移动会留下失败记录而不会发布为当前理解。")

当前 calls 只在单文件名称表中匹配并始终标为 candidate，不能证明跨文件真实调用。[单文件候选调用关系 ↗](../../../apps/server/src/code/sync.ts#L311 "证明调用关系只在当前文件的名称表内匹配并写为 candidate，不能作为跨文件调用证据。") Trail hash 只保存帧类型和标识，行号不会随整栈往返；[Trail 深链序列化 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L218 "支持 Trail hash 只保存帧类型和标识，没有保存帧携带的行号。") 当前图中找不到模块、文件或符号时，对应详情组件也不会显示明确的失效原因。[Trail 详情帧分派 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L371 "支持模块、文件或符号不存在于当前图时，相应详情组件因条件不满足而不渲染。") 路径、限定名或符号类型变化会改变身份，当前快照中无法解析的 locator 只会形成 rejected，现有材料未显示跨版本身份续接机制。[代码图确定性身份 ↗](../../../apps/server/src/code/store.ts#L7 "支持文件、符号、边及快照的确定性身份，并说明符号身份包含路径、限定名和类型。")[定位失败的拒绝记录 ↗](../../../apps/server/src/code/understanding-store.ts#L304 "支持当前快照中 locator、证据或引用提示无法解析时持久化 rejected 结果。") 另一个已确认边界是：有效 association 集合为空时失效逻辑直接返回，删除最后一条人工关联后，历史 seed 关系不一定转为 stale。[空关联集合的失效边界 ↗](../../../apps/server/src/review/store.ts#L485 "证明有效人工 seed 集合为空时失效函数直接返回，旧关系不会由该调用转为 stale。")
