# 从固定源码到可追溯 Code Wiki

Code Wiki 是统一捕获证据链上的代码投影与阅读入口：仓库文件形成不可变修订后，被解析为版本化文件、符号和关系图，并与人工维护的需求、决策、调研和测试依据连接。界面提供知识文章、模块图、固定源码和证据轨迹；当前主要面向本地单用户，跨文件调用、模型成果复核、历史单项查询和失效深链仍有明确限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为什么需要代码知识投影

普通代码浏览难以说明结论依据哪个版本、为何存在以及由什么材料验证。Code Wiki 将仓库适配器限定为统一知识流水线的输入端；文件以路径维持来源身份，修改时追加不可变修订，而不是建立另一套事实库。参考 [仓库适配器职责 ↗](../../../apps/server/src/review/materials.ts#L1 "支持仓库文件只是统一知识流水线的输入，Code Wiki 不构成独立事实系统。") [路径来源与不可变修订 ↗](../../../apps/server/src/review/sync.ts#L1 "支持以仓库相对路径维持来源身份，并通过追加修订记录文件变化。")

代码分析只读取捕获链中的固定修订，并据此建立可复用快照。知识文章、结构导航和源码引用因而可以指向同一历史证据，不会把当前工作树内容拼接到旧快照。参考 [固定修订生成代码快照 ↗](../../../apps/server/src/code/sync.ts#L170 "支持代码分析读取捕获链中的不可变修订，并据此建立幂等快照和文件绑定。")

<a id="pipeline"></a>
## 从仓库变化到关系图

```mermaid
flowchart LR
  A[仓库文件变化] --> B[不可变修订]
  B --> C[版本化代码快照]
  C --> D[符号与关系投影]
  D --> E[人工关联或显式模型理解]
  E --> F[文章与证据阅读]
```
解析在固定输入上离线进行：TypeScript 使用单文件 AST，Vue 使用 SFC 解析，路由和测试采用保守规则。参考 [离线解析能力边界 ↗](../../../apps/server/src/code/parse.ts#L1 "支持单文件 TypeScript AST、Vue SFC、保守规则和名称级候选调用的解析范围。") 同步会写入定义、相对导入、路由和测试关系；调用仅在同文件名称命中时形成候选，Vue 组件使用也不会被冒充为已确认目标。参考 [符号与关系投影 ↗](../../../apps/server/src/code/sync.ts#L250 "支持定义、导入、调用、路由、测试和 Vue 组件关系的状态及目标解析规则。")

人工清单把代码定位到实现意图，再连接需求、决策、调研和测试片段。词面相似度不能自动提升关系，定位失败的目标按缺失状态保存。参考 [人工关系治理原则 ↗](../../../apps/server/src/review/associations.ts#L1 "支持关系由人工登记具体依据，词面相似度不能自动提升为确认关系。") [代码到依据的关系构建 ↗](../../../apps/server/src/review/sync.ts#L699 "支持代码、实现意图、需求、决策、调研和测试之间的边结构，以及定位失败时的缺失状态。")

<a id="reading"></a>
## 结构、文章与原文如何关联

服务端提供仓库、快照、模块、文件列表和当前文件符号列表；固定源码接口可通过 `snapshotId` 精确读取当前或历史快照绑定的文本。参考 [快照、文件与固定源码接口 ↗](../../../apps/server/src/review/app.ts#L351 "支持仓库、快照、模块、文件列表、当前文件符号列表及可指定快照的固定源码区间读取。") 整图接口同样显式接受 `snapshotId`，可以组织历史结构视图；但单个符号接口只按符号标识查询，符号相邻边接口也没有暴露等价的历史快照参数，因此它们不能被视为精确的历史快照查询入口。参考 [符号、相邻边与整图接口 ↗](../../../apps/server/src/review/app.ts#L438 "支持区分接口的版本能力：单符号按标识查询，相邻边未暴露快照参数，只有整图明确接受 snapshotId。") 返回界面的数据保留导航所需内部键，同时增加人读标题、路径和不可操作原因，内部标识不作为可见标签。参考 [人读数据投影 ↗](../../../apps/server/src/code/dto.ts#L1 "支持内部操作键与展示字段分离，并要求缺失或过期目标提供不可操作原因。")

前端以完整知识文章为入口，结构图、模块详情和文件详情构成补充阅读面。参考 [Code Wiki 阅读入口 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L275 "支持知识首页、代码结构、模块依赖图、模块详情和文件详情共同构成阅读入口。") 知识、模块、文件、符号和片段共用一条证据轨迹，抽屉统一处理返回、跳转、循环提示和焦点归还。参考 [统一证据轨迹 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L371 "支持多类证据共用同一轨迹抽屉，并说明缺失代码目标的正文渲染条件。") URL Hash 会恢复主视图和轨迹帧；若旧模块、文件或符号已不在当前代码图中，帧仍可能存在，但对应正文组件不会渲染。参考 [Hash 深链恢复 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L236 "支持从 URL Hash 恢复主视图和轨迹，并说明轨迹帧恢复时未统一校验目标是否仍存在。")

派生文章只有在生成与独立复核来源齐备、且材料及子知识摘要仍匹配时才恢复为当前内容；依赖变化会标记过期。参考 [文章恢复与过期判断 ↗](../../../apps/server/src/knowledge/artifacts.ts#L40 "支持文章必须具备生成和独立复核来源，并在材料或子知识变化后标记过期。")

<a id="progress_limits"></a>
## 当前进展与可信边界

固定材料捕获、版本化代码图、人工关系、知识文章和证据轨迹已经贯通；模型理解是显式可选能力，配置缺失时不会在启动阶段推理。参考 [显式模型配置 ↗](../../../apps/server/src/review/model-config.ts#L1 "支持模型配置来自仓库或明确覆盖，配置缺失时不启用模型，启动阶段也不自动推理。")

可信度仍需分层：合同区分模型生成的 `generated` 与独立代理复核后的 `verified`。参考 [生成与独立复核状态 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L228 "支持 generated 与 verified 的语义区别，以及只有独立代理复查后才能声明已验证。") 默认理解列表会展示未过期的模型 `generated` 记录，因此引用和结构校验通过并不代表内容已经完成独立语义复核。参考 [默认理解读取规则 ↗](../../../apps/server/src/code/understanding-store.ts#L521 "支持默认读取面包含未过期的模型 generated 记录，而失败、拒绝和过期结果不作为当前内容。")

部署目前是本地单用户 SQLite。API 可校验 Bearer Token；未配置令牌时依赖回环 Host 和允许的浏览器 Origin，这些门禁不能替代团队租户授权。参考 [单用户存储边界 ↗](../../../apps/server/src/store.ts#L4 "支持当前 SQLite 只提供单用户基础，团队级权限执行尚未实现。") [本地访问门禁 ↗](../../../apps/server/src/review/app.ts#L97 "支持令牌模式以及无令牌时的回环 Host 与浏览器 Origin 校验。")
