# 代码知识投影与仓库评审

Code Wiki 将仓库白名单材料接入通用 Capture 链，在隔离数据库中形成不可变代码快照、确定性结构图、人工证据关系与经严格校验的模块理解，并通过统一 Trail 下探源码及需求、决策、研究和测试证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="capture_projection"></a>
## 从通用 Capture 到代码投影

repo-review 是仓库输入适配器而非独立事实库。扫描器只遍历 `apps`、`packages`、`docs`、`scripts` 和少量根级文件，并排除依赖、构建产物、私有环境及评审运行目录。[仓库扫描白名单与排除规则 ↗](../../../apps/server/src/review/sync.ts#L94 "直接支持扫描目录、根级文件白名单、排除目录与可捕获内容类别的范围限定。") 被接纳的文件以路径形成 Source 身份，内容变化追加 Revision，再按代码声明、测试或 Markdown 边界形成 Fragment；摘要相同则不重复创建版本。[评审模块的运行与捕获边界 ↗](1d40b7d26d0e45f48020a86c0a04e64e7c23827274441b6e238dee9f39308cd0.md#purpose-boundary "解释 repo-review 如何复用通用知识链、使用隔离运行目录和路径型来源身份。")[不可变修订捕获 ↗](../../../apps/server/src/review/sync.ts#L460 "支持路径来源身份、内容摘要去重、分片和快照上下文写入。")

Code Wiki 从 Capture 当前修订读取源码，以提交、工作树状态和内容摘要建立可复用快照。[代码模块的快照职责 ↗](d8e08ba54848a2eb68345034e492827765b3a9a6e8e57c4758fc499db7d5d280.md#purpose "解释代码视图如何从固定 Capture 修订建立确定性快照和结构图。")[快照创建与复用 ↗](../../../apps/server/src/code/sync.ts#L188 "说明快照身份由提交、脏状态和内容摘要构成，旧状态复用后仍会重新协调当前 head。") 文件、符号和边属于确定性代码投影，显式 head 区分当前图与历史图；历史源码读取快照绑定文本，不回退到实时工作树。此前仅凭路径身份说明捕获范围的论证不完整，现由扫描白名单与排除规则补足。

<a id="relations_understanding"></a>
## 结构事实、人工关系与模块理解

解析器确定性地产生声明、导入、路由和测试结构；可解析导入为 confirmed，调用则只在同文件按名称匹配并保持 candidate，不能据此宣称跨文件真实调用。[代码图关系投影规则 ↗](../../../apps/server/src/code/sync.ts#L291 "支持区分已解析导入、名称级候选调用、路由、测试和组件候选关系。") 代码与意图、需求、决策、研究、测试的关系只来自人工维护的 association 清单，词面相似度不得自动晋升为 confirmed。[人工关系治理 ↗](8d8fdbda9fe727716d9419cb22df60f344e719b53c8b7e60016e5b626908654a.md#purpose-and-governance "解释关联清单的人工权威边界，以及 confirmed 对文档和测试锚点的要求。") 同步为每条登记项创建派生意图片段，并在当前 head 解析代码和材料端点；无法解析的端点保留为 missing。[人工种子关系构建 ↗](../../../apps/server/src/review/sync.ts#L682 "支持派生意图索引、当前 head 端点解析以及 confirmed、candidate、missing 状态写入。") 删除种子通常会使旧边失效，但有效清单为空时当前失效函数直接返回，因此“清空清单必然令全部旧关系 stale”的结论不成立。[空种子集合的失效行为 ↗](../../../apps/server/src/review/store.ts#L485 "证明有效 association 集合为空时旧种子关系不会由该函数统一标为 stale。")

模块知识是代码图之上的派生解释：人工 seed 通过路径、限定名和类型定位符号，证据必须来自固定材料，并经严格合同校验。[代码理解种子投影 ↗](b3371593c4922018b730c855f682b8fe880f0633812ad1d353f218a718c4abc2.md#projection "解释固定证据、稳定 locator、严格合同及派生理解不改写原始代码图的边界。") locator、证据文件或引用提示失效时会保存 rejected 记录，不静默省略，也不覆盖已有有效理解。[定位失败的拒绝记录 ↗](../../../apps/server/src/code/understanding-store.ts#L304 "证明节点 locator、证据或引用提示无法解析时会持久化 rejected 结果。") 因而解析结构、人工关系和人工或模型解释具有不同来源与状态，派生正文不能替代原始 Fragment 成为独立事实证据。

<a id="reading_generation_limits"></a>
## 统一阅读、显式生成与当前边界

前端把知识文章、模块、文件、符号和原始片段放入同一 Trail 抽屉，统一处理返回、跳层、关闭、循环提示与焦点归还，并以人类可读标题代替内部标识。[统一证据 Trail ↗](c7d146673237fb15547f8534001912445b4b4ef8cb6c32403bc9d240682a5c76.md#trail-navigation "解释 Code Wiki 如何用同一抽屉承载知识、模块、文件、符号和片段的逐层阅读。") 完整帧栈可写入 URL hash；但同步后若目标已删除或改名，帧虽可恢复，内容区仍可能缺少明确的 missing 或 stale 原因。[Trail 深链恢复限制 ↗](c7d146673237fb15547f8534001912445b4b4ef8cb6c32403bc9d240682a5c76.md#deep-link "支持 URL 恢复依赖当前代码图，以及失效对象可能缺少专门原因反馈的现状。")

启动流程只同步材料、恢复知识和重建代码投影，没有模型生成步骤。[评审启动顺序 ↗](../../../apps/server/src/review/main.ts#L17 "证明启动只执行材料同步、知识恢复和代码投影，没有调用模型生成。") 评审应用的模型端口默认关闭，只有显式传入配置才创建；生成还必须调用专门的 POST 端点，无模型时返回不可用，失败或拒绝结果不会晋升为 current。[默认关闭的评审模型端口 ↗](../../../apps/server/src/review/app.ts#L60 "直接支持模型默认关闭、只有显式配置才创建端口且默认不调用实时模型。")[显式代码理解生成端点 ↗](../../../apps/server/src/review/app.ts#L645 "直接证明生成必须经专门 POST 入口触发，无模型返回不可用且失败结果不晋升。") 生成过程具备目标裁剪、输入输出预算、取消、超时、传输失败和畸形输出隔离。[模型生成的预算与失败防线 ↗](../../../apps/server/src/code/understanding-store.ts#L674 "支持目标范围、输入输出预算、取消、超时、传输失败和畸形输出的隔离处理。") 通过合同校验后，服务端还会拒绝模型未实际看到的引用；若运行期间 head 已移动，也不会把旧快照结果发布为当前理解。[引用范围与快照移动防线 ↗](../../../apps/server/src/code/understanding-store.ts#L834 "直接支持模型引用必须来自实际展示范围，以及生成期间 head 改变时拒绝发布当前结果。")

当前仍不是完整程序分析：调用解析只收集简单名称，跨文件 caller/callee 绑定未实现。[名称级调用解析 ↗](../../../apps/server/src/code/parse.ts#L167 "证明解析器只收集简单被调用名称和有限调用者上下文，不能形成跨文件符号绑定。") 仓库标识仍是单仓 PoC；符号虽按稳定定位要素生成标识并保留快照历史，但未限定快照的单符号查询语义不明确，也不构成跨 revision 的语义身份续接。[代码存储的身份与查询边界 ↗](6d7798d48631440ff518a72a9b36c01b933e3d320d2f8aedc0497fe75c3f37a9.md#understanding "说明单仓 PoC、快照历史及按稳定符号标识查询未限定当前快照的限制。")
