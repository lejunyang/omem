# 代码知识投影与仓库评审

Code Wiki 将仓库文件接入通用 Capture 证据链，在隔离数据库中形成不可变代码快照、确定性结构图、人工关系和经校验的派生理解，并通过共享 Trail 串联代码与需求、决策、研究及测试依据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="capture_projection"></a>
## 从仓库证据到代码投影

repo-review 是仓库输入适配器，而非独立事实库：文件以路径形成稳定 Source，内容变化追加 Revision，并记录提交、脏状态和摘要；代码同步随后只读取 Capture 当前修订，不混用实时工作树正文与旧 Fragment。[仓库文件不可变捕获 ↗](../../../apps/server/src/review/sync.ts#L460 "支持路径身份、内容摘要去重及 Git 快照元数据进入 Capture 修订的流程。")[代码同步的固定修订输入 ↗](../../../apps/server/src/code/sync.ts#L152 "支持代码分析只读取 Capture 当前修订正文，不直接混用实时工作树。") 快照由提交、脏状态和内容哈希确定，文件、符号与边采用确定性身份并按快照保留历史；显式 head 指针决定当前图，避免代码回到旧状态时按捕获时间误判。[代码图确定性身份 ↗](../../../apps/server/src/code/store.ts#L7 "支持文件、符号、边和快照的确定性标识，以及范围和 Fragment 按快照保存。")[显式当前快照指针 ↗](../../../apps/server/src/code/store.ts#L273 "说明当前状态不能按捕获时间推断，并支持旧快照继续按标识读取。") 更细的输入、快照及存储合同可继续下钻到同步与存储子知识。[Capture 驱动的代码同步 ↗](77a2bfa010fcb7c75cfc06e221def951343d041b819f5adf30ede8d0dcd8a178.md#input_snapshot "提供固定修订输入、快照身份和图投影流程的相关子知识入口。")[代码知识存储模型 ↗](6d7798d48631440ff518a72a9b36c01b933e3d320d2f8aedc0497fe75c3f37a9.md#model "提供不可变快照、显式 head 与历史结构保存合同的相关子知识入口。")

<a id="structure_relations"></a>
## 确定性结构与人工关系

解析层投影声明、导入、路由、测试和组件使用：可解析导入为 confirmed，缺失目标为 missing；调用只在同文件按名称匹配，因此保持 candidate，不能证明跨文件真实调用。[结构关系投影规则 ↗](../../../apps/server/src/code/sync.ts#L291 "支持导入关系、同文件名称级候选调用、路由、测试及组件边的状态区别。") 需求、决策、研究和测试关系只来自人工维护的 association seed，词面相似度不得自动提升为 confirmed。[人工关系的权威边界 ↗](../../../apps/server/src/review/associations.ts#L1 "证明关系种子由人工维护，未登记的语义相似命中不得成为确认关系。") 同步为每条 seed 建立派生意图片段，并在当前 head 定位代码及材料端点；解析失败仍保存 missing 关系，重复同步则依靠确定性关系身份幂等更新。[人工关系重建流程 ↗](../../../apps/server/src/review/sync.ts#L682 "支持派生意图索引、当前 head 定位、确定性关系写入及无法解析端点保留为 missing。")

<a id="understanding_reading"></a>
## 派生理解与证据阅读

模块理解位于结构图之上，不改写原始代码事实。人工 seed 用路径、限定名和类型重新定位当前快照符号，并从固定源码或文档取得证据；locator、证据或引用提示无法解析时保存 rejected 结果，不让失败尝试遮蔽有效理解。[代码理解投影边界 ↗](../../../apps/server/src/code/understanding-store.ts#L1 "说明人工理解种子如何引用固定图与证据，并强调派生理解不改写原始代码图。")[定位失败的拒绝记录 ↗](../../../apps/server/src/code/understanding-store.ts#L304 "支持 locator、证据或引用提示解析失败时持久化 rejected 结果，而非静默丢失。") 其投影与校验细节可下钻到相关子知识。[理解结果投影与校验 ↗](b3371593c4922018b730c855f682b8fe880f0633812ad1d353f218a718c4abc2.md#projection "提供人工种子定位、固定证据和严格交叉引用校验的相关子知识入口。") Code Wiki 将文件、符号和 Fragment 转为共享 Trail 帧，由同一抽屉分派知识、模块、文件、符号及片段详情，使读者可沿代码继续查看需求、决策、研究与测试依据。[Code Wiki 证据下探 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L185 "支持文件、符号和 Fragment 被转换为统一 Trail 帧，并保留运行时行号。")[共享 Trail 抽屉 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L371 "证明同一抽屉按帧类型承载知识、模块、文件、符号和 Fragment 阅读。")

<a id="progress_limits"></a>
## 进展、模型边界与限制

原始图和人工 seed 无需模型即可使用；评审模型默认关闭且只读取项目配置或显式覆盖，生成必须由专门端点触发。[显式模型配置与调用 ↗](../../../apps/server/src/review/model-config.ts#L1 "支持模型默认关闭、仅使用项目配置或显式覆盖，并由显式生成入口传递预算。") 模型生成会按目标模块裁剪文件与符号，检查输入、输出预算，以超时或外部取消中止运行，并把传输失败或畸形 JSON 保存为失败结果而不晋升为 current。[模型生成预算与失败防线 ↗](../../../apps/server/src/code/understanding-store.ts#L674 "支持目标范围裁剪、输入输出预算检查、超时与取消处理，以及传输失败和模型 JSON 解析失败不会晋升为当前结果。") 通过合同校验后，系统还会检查引用是否确实展示给模型，并在提交前阻止 head 已移动的结果成为 current。[模型引用范围与 head 防线 ↗](../../../apps/server/src/code/understanding-store.ts#L834 "直接支持模型引用必须属于实际展示范围，以及生成期间 head 移动时拒绝提交的两项防线。")

当前边界包括跨文件调用尚未解析。[名称级调用解析 ↗](../../../apps/server/src/code/parse.ts#L167 "证明当前调用解析只收集简单被调用名称与有限调用者上下文，不能确认跨文件调用。") 符号表按快照保存同一稳定身份，但单符号查询只按 symbol id，未限定或排序 snapshot，因此当前态与历史态语义仍不明确。[未限定快照的符号查询 ↗](../../../apps/server/src/code/store.ts#L559 "直接证明单符号读取只按稳定 symbol id 查询，未提供 snapshot 条件或确定排序。") Trail 运行时帧可带行号，hash 却只序列化类型与标识；失效文件或符号在抽屉中也可能不渲染详情。[Trail 帧中的行号 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L185 "证明文件和符号下探帧在运行时可以携带目标行号。")[Trail 深链序列化 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L218 "支持 hash 仅保存 Trail 帧类型与标识、恢复时重建帧栈的限制说明。")[失效实体的抽屉渲染条件 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L371 "支持文件或符号不在当前图中时对应详情组件不会渲染的现状。") 此外，空 association 集合会让旧 seed 失效逻辑直接返回，尚需明确清空语义。[空关系种子集合行为 ↗](../../../apps/server/src/review/store.ts#L485 "证明有效 association 集合为空时旧 seed 关系失效逻辑直接返回。")
