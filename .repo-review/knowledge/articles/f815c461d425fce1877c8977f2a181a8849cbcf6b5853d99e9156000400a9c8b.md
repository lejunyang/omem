# 搜索前后的小模型只读决策对照

说明 decision:inspect 如何用同一常驻本地模型比较检索前后的下一步建议，如何构造输入、调用真实搜索和保存报告，并明确输出文件权限与只读实验的边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 它解决什么问题

`decision:inspect` 用来观察：给小模型补充真实检索材料后，它对下一步工作的建议是否变化。脚本接收当前问题，可另设检索词、对话背景、API、模型、后端和输出路径；问题不能为空，检索词最多 300 个字符。它只给出建议并记录结果，不会自动回答、执行动作或更新记忆。参考 [只读入口与输入初始化 ↗](../../../scripts/decision-inspect.ts#L1 "支持脚本的只读定位、问题与检索词校验、可选背景、模型后端、搜索地址和输出路径的构造。")

<a id="flow"></a>
## 一次代表性调用怎样流转

例如输入“导入文档后会自动整理吗？”：脚本先用问题、可选背景和空材料执行检索前判断。候选动作包括直接回答、继续搜索、深入调查、向用户澄清和进入动作核对；同一阶段轮换候选顺序判断两次，并记录两次选择是否一致。参考 [双轮动作建议 ↗](../../../scripts/decision-inspect.ts#L44 "支持五类候选动作、同一阶段轮换两次选项顺序，以及顺序一致性的计算方式。")

随后脚本无论第一次建议为何，都会请求真实 `/api/search`，校验响应并截取前六条命中；第二轮只把标题、章节、正文和材料适用性送给同一 worker。完整命中保留在报告里，但整文件概念列表和内部修订信息不进入第二轮上下文。参考 [搜索前后主流程 ↗](../../../scripts/decision-inspect.ts#L99 "支持先判断、再执行真实 HTTP 搜索、截取六条命中、整理适用性后再次判断的流程。")

```mermaid
flowchart LR
  A[问题与可选背景] --> B[检索前判断两次]
  B --> C[真实 HTTP 搜索]
  C --> D[前六条可见材料]
  D --> E[检索后判断两次]
  E --> F[报告与控制台摘要]
```

<a id="boundaries"></a>
## 输出、权限与判断边界

报告在检索前先保存一次，成功后补上完整标记，失败时写入错误并重新抛出。新建报告文件时，脚本请求以 `0600` 模式创建；若 `--output` 指向已存在且权限更宽的文件，覆盖内容不会自动收紧其既有权限，因此敏感报告仍需确认目标文件权限。参考 [报告写入模式 ↗](../../../scripts/decision-inspect.ts#L71 "支持保存函数创建父目录，并在写入报告时传入 0600 模式；附近正文同时说明该模式对既有输出文件权限的边界。")

成功时，控制台只输出报告路径、前后建议、检索耗时和材料数；无论成功或失败，worker 最终都会关闭。两次选项顺序一致只表示这次建议对顺序较稳定，并不证明建议正确。参考 [完成、异常与资源清理 ↗](../../../scripts/decision-inspect.ts#L150 "支持成功后的摘要输出、异常写入与重新抛出，以及最终关闭 worker 的行为。")
