# review 开发编排器集成测试

该测试以临时端口和最小仓库夹具启动真实 dev-review 编排器，验证端口预检、API 与 Web 联合启动、跨平台终止、资源释放及重复启停稳定性；同时通过等待进程退出和重试删除夹具，处理 Windows 上 SQLite/WAL 句柄延迟释放问题。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 测试目标与隔离策略

该文件针对开发编排器可能遗留子进程、占用端口或锁住 SQLite 文件的问题。测试直接启动 `scripts/dev-review.ts`，但为每次运行分配临时端口，并用仅含一个 TypeScript 文件的临时仓库作为输入，因此不会触碰真实 `.repo-review` 数据。子进程输出会被持续读取并保留，便于失败诊断。[临时仓库与编排器启动 ↗](../../../apps/server/tests/review-dev.test.ts#L104 "支持测试使用最小夹具仓库、真实脚本入口、环境变量隔离及输出采集的说明。")

清理操作只针对测试自己启动的编排器 PID，不按端口或进程名宽泛终止。具体行为取决于平台：Windows 使用 `taskkill /T /F` 回收该 PID 的进程树，POSIX 则向该 PID 发送 `SIGTERM`。[按平台终止精确进程 ↗](../../../apps/server/tests/review-dev.test.ts#L115 "支持仅针对已启动 PID，并区分 Windows 强制回收进程树与 POSIX 发送 SIGTERM 的论断。")

<a id="boot-flow"></a>
## 启动、探活与关闭流程

公共流程注入 API 端口、Web 端口和夹具根目录，再轮询 `/api/review/health`。探活成功后断言模式为 `review`、来源与片段数量均大于零，并确认 Web 根路径返回 200；这覆盖后端、仓库同步和前端服务的联合启动，但没有核对具体片段内容或 SPA 页面结构。[健康检查与 Web 可用性断言 ↗](../../../apps/server/tests/review-dev.test.ts#L209 "支持启动流程验证 review 模式、非空来源与片段以及 Web 200 响应，并揭示断言粒度。")

执行关闭动作后，流程先等待编排器自身的 `exit` 事件并记录真实退出码和信号，再轮询两个端口是否释放。无论中途断言是否失败，`finally` 都会再次按精确 PID 清理并等待退出，以降低资源泄漏对后续用例的影响。[退出等待与端口释放 ↗](../../../apps/server/tests/review-dev.test.ts#L228 "支持关闭后先取得真实退出结果、再检查端口，并在 finally 中兜底清理的流程。")

<a id="assertions"></a>
## 主要断言与平台差异

端口预检分别覆盖 API 和 Web 端口已被占用的情况，当前实际断言是编排器在限定时间内以非零状态退出，尚未验证所谓“清晰错误”的具体内容。[双端口冲突预检用例 ↗](../../../apps/server/tests/review-dev.test.ts#L255 "支持 API 与 Web 端口占用均导致非零退出，并表明当前未断言具体错误信息。") 正常路径覆盖一次完整启动，并按平台调用 `killTree`：Windows 强制回收进程树，POSIX 发送 `SIGTERM`；这取代了把所有平台都概括为“强制关闭”的旧结论。[单次端到端启停 ↗](../../../apps/server/tests/review-dev.test.ts#L289 "支持正常路径调用 killTree 完成一次端到端启动、关闭和夹具清理的说明。")[按平台终止精确进程 ↗](../../../apps/server/tests/review-dev.test.ts#L115 "支持仅针对已启动 PID，并区分 Windows 强制回收进程树与 POSIX 发送 SIGTERM 的论断。") 此外还使用全新端口和夹具连续执行三轮启动关闭，以暴露竞争条件和残留资源。[三轮重复启停 ↗](../../../apps/server/tests/review-dev.test.ts#L338 "支持使用新端口和新夹具连续执行三轮启动关闭以发现竞争和资源残留的说明。")

另一项终止合同测试直接调用 `child.kill("SIGTERM")`：POSIX 上应触发编排器的关闭处理器并以 0 退出；Windows 上该调用可能只终止 Bun 编排器，因此不要求退出码为 0，最终保障由进程树清理和端口释放构成。[跨平台 SIGTERM 合同 ↗](../../../apps/server/tests/review-dev.test.ts#L305 "支持 POSIX 要求优雅退出码为零，而 Windows 仅保证后续进程树清理和端口释放的差异。")

<a id="cleanup-limits"></a>
## 清理语义与未覆盖边界

夹具清理发生在等待编排器退出之后，并在 20 秒内反复尝试递归删除，以容忍 Windows 异步释放 SQLite/WAL 文件句柄。若主要断言与清理同时失败，两者会合并为 `AggregateError`，避免清理异常掩盖原始失败。[夹具删除重试与错误合并 ↗](../../../apps/server/tests/review-dev.test.ts#L163 "支持文件锁释放等待，以及同时保留主要断言错误和清理错误的行为。")

删除重试只能证明目录最终可删除，不能证明每个后代进程都被确定性跟踪。测试也没有直接断言端口冲突错误文本、健康响应对应的具体夹具材料、Web 页面交互或内部子服务的独立退出顺序。因此它属于进程级集成保障，不等同于完整 UI、数据正确性或所有外部 CLI 行为验收。[清理保证的明确边界 ↗](../../../apps/server/tests/review-dev.test.ts#L22 "支持删除轮询不是确定性后代进程跟踪保证，并界定该集成测试的证明范围。")
