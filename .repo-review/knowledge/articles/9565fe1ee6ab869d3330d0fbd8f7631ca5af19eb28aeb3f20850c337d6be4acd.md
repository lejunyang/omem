# 运行配置、依赖锁定与部署边界

本章说明 omem 如何通过 osdk 统一开发与验证入口、锁定中文检索模型和应用依赖，并分别配置个人助手与仓库知识生成使用的 Agent。系统可在本机或服务器运行，但当前仍是单用户服务；外部监听、systemd 守护及 TraeX Hook 均需显式配置，模板或命令入口本身不代表集成已经启用或验证成功。参考 [[c9]]

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="runtime-baseline"></a>
## 统一而可复现的运行环境

omem 的基础运行只要求 osdk 和可登录的 Agent CLI，不依赖 Docker、Redis、Python 或本地大语言模型；开发入口会同时启动 API 与 Vue，并把仓库知识接入个人知识库，启动过程只恢复既有知识，不主动调用生成式模型。参考 [启动与开发入口 ↗](../../../README.md#L5 "支持运行前提、开发服务组成、仓库知识接入以及启动时不调用生成式模型的说明。")

工具链由 osdk 统一声明：Node、pnpm 与 Bun 分工承担服务运行、依赖管理和 TypeScript 脚本执行，`check` 汇总类型检查、测试与构建。中文向量模型则锁定到指定的 BGE-small-zh-v1.5 修订和文件摘要，pnpm 安装也绑定清单及原生锁文件，从而减少环境与模型身份漂移。参考 [osdk 工具与检查任务 ↗](../../../osdk.toml#L1 "说明 Node、pnpm、Bun 的版本声明以及统一检查任务的组成。") [模型与依赖锁定 ↗](../../../osdk.lock#L25 "支持中文嵌入模型的固定修订、文件完整性记录及 pnpm 冻结安装边界。")

<a id="agent-and-review"></a>
## 个人助手与仓库生成的 Agent 配置

个人助手通过配置文件选择 ACP 或 CLI 运行器；TraeX 可动态发现模型和推理强度，Codex 与 Claude 则通过各自命令接入。不支持的模型或 effort 应明确报错，图片也只能交给声明支持图像的 ACP，不能静默丢弃。每次问答使用新会话并显式传入固定证据，当前尚未实现跨轮 ACP 会话恢复。参考 [Agent 能力与会话边界 ↗](../../../README.md#L84 "支持不同 Agent 接入方式、能力发现、不支持选项报错、图片处理和会话恢复限制。")

仓库知识生成使用独立的实际配置：通过只读模式启动 `traex acp serve`，选择 `gpt-5.6-sol` 与 `medium`，并设置调用超时、输入输出令牌和上下文预留预算。配置表达预期执行边界；一次生成是否真正成功，仍须结合能力校验和运行 trace 判断。参考 [仓库评审模型配置 ↗](../../../config/review-code-model.json#L2 "支持仓库生成所用 ACP 命令、模型、推理强度及调用预算。")

<a id="deployment"></a>
## 从本机启动到服务器守护

部署模板默认监听 `127.0.0.1:4317`，数据目录和应用配置需要替换为实际绝对路径。若改为非回环监听，必须另设高强度令牌。参考 [部署环境与访问保护 ↗](../../../deploy/omem.env.example#L1 "支持默认监听端点、绝对路径配置及非回环监听需要强令牌的部署要求。") 当前 SQLite 与共享令牌实现明确属于单用户部署，不能被解释为具备团队租户隔离的权限系统。参考 [单用户部署与租户边界 ↗](../../../README.md#L146 "支持当前 SQLite 与共享令牌实现明确为单用户服务，且不能把共享令牌视为团队租户权限系统。")

systemd 示例把 omem 组织为用户服务：进入项目目录、加载环境文件、执行 `osdk run start`，失败后等待五秒重启，并在停止时保留二十秒退出窗口。模板中的项目目录、环境文件与 osdk 路径都是占位符，因此复制、启用和健康检查仍需部署者完成。参考 [systemd 用户服务模板 ↗](../../../deploy/omem.service.example#L1 "说明用户服务的工作目录、环境文件、启动命令、失败重启和停止超时设置。")

<a id="explicit-integrations"></a>
## 外部捕获必须显式启用

TraeX Hook 示例覆盖提示提交、工具使用后和会话停止三个事件，统一异步调用转发脚本并设置五秒超时。它被明确标为 opt-in 配置，命令中仍含绝对路径占位符；启用前必须审阅捕获字段和范围，并验证构建产物、接收服务及失败处理，不能因为模板存在就宣称端到端捕获已经运行。参考 [TraeX 可选捕获 Hook ↗](../../../integrations/traex/hooks.example.json#L1 "支持 Hook 的显式启用边界、三个触发事件、异步转发方式及待替换路径。")
