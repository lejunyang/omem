# project · 模块理解 · 专题 2

本专题说明 omem 项目层如何把个人助理、知识整理与仓库评审统一到可追溯证据链，并梳理其处理流程、工程治理、单用户部署边界及尚未交付的能力。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责与设计背景

omem 是个人工作记忆与助理的总体入口：文本、图片、链接和上下文先形成不可变证据，问答、受治理记忆、待办、通知与仓库 Wiki 再沿用同一证据链；外部屏幕采集仍是需单独配置的集成。[个人助理与统一证据链 ↗](../../../README.md#L1 "支持项目面向个人工作记忆、统一接收多类输入，并让问答、记忆、待办、通知和 Wiki 共用证据链的论断。")

知识整理复用 Capture→Source/Revision/Fragment、持久任务和角色运行网关。不同材料由专门角色分析，经独立复核后组织为模块、主题和概览；AST 负责代码定位及明确结构关系，语义说明则由模型分析和复核。[知识整理与代码定位流程 ↗](../../../README.md#L20 "支持通用知识处理链、独立复核、章节组织，以及 AST 定位与模型语义分析之间的职责划分。") Code Wiki 因而是这条通用链路的派生阅读视图，而非第二套捕获系统或事实权威。[Code Wiki 的派生视图定位 ↗](../../../AGENTS.md#L16 "支持 Code Wiki 复用通用知识管线、仅作为仓库输入适配器和隔离运行配置，而非独立产品或事实系统。")

<a id="workflow"></a>
## 主要流程与跨模块关系

正文生产遵循“分析原始材料—独立复核—组织章节”的顺序；引用应贴近论断并指向固定目标，无法确认的事项保留为调查项，用户回答作为新原始材料触发重核对，错误或过期结果不得覆盖有效知识。[正文分析、复核与调查流程 ↗](../../../AGENTS.md#L28 "支持先分析再复核和组织、内联固定引用、疑问重核对，以及失败结果不得覆盖有效知识。") 阅读侧复用共享证据 Trail：内部标识只用于路由，界面显示可读名称；缺失或过期目标不可操作并说明原因，帧栈还需保留层级、滚动位置与关闭后的焦点恢复。[可读标签与共享证据 Trail ↗](../../../AGENTS.md#L20 "支持内部标识与可见文本分离、失效目标显示原因，以及 Code Wiki 和个人阅读入口复用同一帧栈合同。")

仓库阅读启动只恢复已有知识；全仓分析、局部生成和索引重建分别通过显式入口执行，review 使用独立 SQLite 且不启动个人业务 worker。[仓库评审运行入口 ↗](../../../README.md#L24 "支持阅读恢复、全仓分析、局部生成与索引重建的差异，并说明 review 的独立数据库和业务 worker 边界。") 已复核正文保存为可提交的 JSON 和内联链接 Markdown，运行数据、私有环境与派生知识不重新充当独立证据，失败项也不能冒充已完成。[仓库材料适配与可提交产物 ↗](../../../docs/implementation/knowledge-pipeline.md#L31 "支持材料排除规则、复核后保存、知识恢复，以及失败条目不得冒充已经生成。")

<a id="constraints-progress"></a>
## 工程约束、进展与限制

工程治理要求使用 osdk 冻结依赖并运行项目检查，以真实退出码和行为断言判断结果；UI 还需浏览器检查。完成的功能切片应连同测试、文档和剩余限制及时独立提交，共享工作区只暂存目标改动。[工程验证与切片提交规则 ↗](../../../AGENTS.md#L5 "支持 osdk 依赖检查、真实行为验证、浏览器检查、按功能切片提交及共享工作区暂存边界。") review 的模型调用必须显式触发，模型与 effort 经过 ACP 校验；运行数据库和构建暂存留在忽略提交的目录，只有明确保存的知识资产进入发布区域。跨文件调用解析及跨修订符号、片段身份续接仍未实现。[模型、发布与解析边界 ↗](../../../AGENTS.md#L23 "支持显式模型触发、ACP 参数校验、运行数据与发布资产分离，以及跨文件和跨修订身份能力的当前限制。")

当前还没有精确的跨文件类型调用解析、embedding 检索和所有来源的自动重核验。[尚未交付的知识能力 ↗](../../../README.md#L52 "直接支持跨文件精确类型解析、embedding 检索和所有来源自动重核验尚未完成。") 此外，现有 SQLite/shared-token 实现被明确限定为单用户，不能宣称已有租户强制隔离；若未来面向团队，需要另行设计身份、授权和数据隔离。[单用户与租户隔离边界 ↗](../../../AGENTS.md#L8 "直接支持当前 SQLite/shared-token 实现是单用户模型且不存在租户强制隔离，并为附近的团队扩展限制提供依据。") 这项结论取代先前缺少直接引文支撑的单用户边界表述。
