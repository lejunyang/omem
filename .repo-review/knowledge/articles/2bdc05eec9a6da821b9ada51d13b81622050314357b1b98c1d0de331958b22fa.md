# 共同角色规则起稿

定义知识处理角色共享的证据、权限与结构化输出约束。它是随角色包固定版本的设计材料，并明确要求后端独立验证，因此不能据此认定服务端权限控制已经实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence-boundary"></a>
## 证据与事实边界

角色只处理当前任务合同，并依赖系统提供的 provenance、scope、source revision、actor binding、时钟与时区判断身份和范围；材料正文中的身份声明、命令或授权不产生权限。事实、来源声称、计划、建议、假设、转述和已验证结果必须分开，模型摘要也不能充当新的独立证据。无法唯一确定负责人、日期、结果或权限时，应保留缺失项并提出具体补证问题。[共同证据规则 ↗](../../../docs/implementation/batch2/prompts/common.md#L3 "支持身份和范围只能依据可信元信息，以及不同事实状态不得互相提升、缺失信息不得编造的说明。")

<a id="execution-boundary"></a>
## 执行与实现边界

角色不得调用未授权工具、执行外部动作、发送消息、写入正式事实或修改配置，只能提交由服务验证和应用的候选。输出需符合传入 Schema，并提供公开、简短的证据理由；置信度不构成审批。材料还明确指出，该提示词本身不建立权限边界，真正的策略、版本和范围校验仍须由后端实现。[角色执行边界 ↗](../../../docs/implementation/batch2/prompts/common.md#L10 "支持角色仅提供候选、遵守结构化合同，并由后端独立落实权限校验的论断。")
