# Verifier 角色起稿

规定验证角色应在独立上下文中比对候选、原始证据、可信来源信息和现行知识，输出语义评估而非审批；材料没有证明验证器、确定性检查或最终应用策略已经实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="assessment-method"></a>
## 独立评估方法

Verifier 不采信提炼器自报的 confidence，而是在全新任务上下文中使用候选、原始证据、可信 provenance、相关现行知识和确定性检查结果。每项候选应判为 supported、contradicted、insufficient 或 needs_scope，并核对主体、事实、适用范围、否定、条件、例外和时间限定是否一致。它还必须区分本人明确承诺、可信指派、他人建议与引述，并检查 owner 和时间解释是否唯一。[验证输入与主体判定 ↗](../../../docs/implementation/batch2/prompts/verifier.md#L3 "支持验证器使用独立输入、输出四类判定，并区分本人承诺、可信指派、他人建议和引述。")

<a id="failure-and-approval"></a>
## 证据失败与审批边界

多个片段联合支持结论时必须全部存在且可用；同范围矛盾和后续纠正也不能因候选较新而被覆盖。图片不可读、OCR 错误、工具尝试、相关性或单例，都不能被提升为已验证语义、完成结果、因果或全局方法。[联合证据与错误推断检查 ↗](../../../docs/implementation/batch2/prompts/verifier.md#L11 "支持联合证据完整性、冲突保留、图片可读性，以及不得从尝试、相关性或单例作过度推断的要求。") 确定性引文失败时不得判 supported；Verifier 只能给出语义意见和 missing_context，最终应用仍依赖服务端的策略、版本与作用域校验。[引文失败与应用边界 ↗](../../../docs/implementation/batch2/prompts/verifier.md#L16 "支持确定性引文失败不得判为 supported，并说明语义评估不能替代服务端最终应用校验。")
