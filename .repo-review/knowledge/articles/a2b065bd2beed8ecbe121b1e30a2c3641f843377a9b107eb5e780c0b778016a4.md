# 任务脚本参数兼容层

该文件为 osdk 声明参数与直接 Bun 命令行执行提供统一、轻量的读取方式：布尔开关可来自环境变量或命令行，目标选择可同时汇集环境变量和多个命令行参数。实现只做字符串匹配与前缀清理，不负责参数校验、去重或复杂解析。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="flag-resolution"></a>
## 布尔开关解析

`taskFlag` 解决同一任务既由 osdk 注入参数、又可被开发者直接通过 Bun CLI 调用时的兼容问题。它先将参数名中的连字符替换为下划线，依次读取对应的 osdk 环境变量名称，并把字符串 `"1"` 或 `"true"` 视为启用；此外，只要命令行中存在完全匹配的 `--参数名`，也会启用开关。[布尔任务参数解析 ↗](../../../scripts/task-args.ts#L1 "支持关于环境变量命名兼容、真值集合、命令行精确开关及其边界条件的说明。")

这里采用严格、区分大小写的字符串判断，因此 `TRUE`、`yes`、`--name=true` 均不会被识别。环境变量通过空值合并选择：若下划线形式的变量已定义但内容为空，就不会继续尝试原始连字符形式；不过命令行开关仍可独立使结果为真。该函数也不处理否定开关或冲突优先级。

<a id="target-collection"></a>
## 目标参数汇集与边界

`taskTargets` 汇集任务的处理目标：环境变量 `osdk_arg_target` 至多贡献一个字符串，并清除开头可能携带的 `--only=` 或 `--target=`；命令行则收集所有具有这两个前缀的参数，截取等号后的内容，最后移除空字符串。[任务目标参数解析 ↗](../../../scripts/task-args.ts#L3 "支持关于环境变量与命令行目标的汇集顺序、前缀清理、空值过滤及未做复杂解析的说明。")

返回顺序固定为环境变量目标在前、命令行目标在后。实现不会按逗号拆分、去除空白、规范化路径或消除重复项，也不会识别 `--only value` 这种分离写法。文件中没有调用方或测试材料，因此只能确认这是参数读取工具，无法据此判断哪些任务消费这些目标、重复目标是否会在上层合并，以及非法目标如何报告。
