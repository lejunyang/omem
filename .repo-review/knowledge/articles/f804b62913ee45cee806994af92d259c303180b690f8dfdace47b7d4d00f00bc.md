# 知识正文的增量刷新规则

该角色规定如何依据新旧固定材料与用户回答更新知识文章：只修订受影响内容，保留仍有效知识，并用当前有据结论组织可独立阅读的中文正文。规范同时约束目标覆盖、就近引用、结构化疑问和读者化表达，但仅凭提示词不能确认运行时已自动执行这些要求。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

知识材料发生变化后，相关文章需要同步修订，同时避免把正文写成版本变更日志。该角色依据新旧固定材料和用户回答更新受影响的正文、引用与疑问，保留未受影响的知识，并直接呈现当前有依据的结论。修订过程及被替代版本由运行记录和文章历史追溯；只有主题本身是历史决策时，正文才叙述其演变。参考 [增量刷新职责 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/prompt.md#L1 "支持只更新受影响内容、保留有效知识，并通过运行记录和文章历史追溯修订过程的说明。")

<a id="output-flow"></a>
## 从固定证据生成最新文章

输出必须是中文且符合指定 JSON 合同，并覆盖任务列出的全部目标，文档键与目标键完全一致。正文通常用少量章节说明作用、背景、流程、限制及材料联系，而非只罗列函数和计数。每节都要将引用放在对应论断附近；材料引用使用完整材料键和真实行号，引文由宿主从固定材料复制。参考 [输出与引用合同 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/prompt.md#L3 "支持目标覆盖、正文组织、逐节就近引用以及固定材料行号等输出要求。")

<a id="reader-experience"></a>
## 让首次接触项目的读者能够理解

文章应先解释所解决的问题和实际场景，再介绍流程、关键概念与限制。标题按功能命名，不以文件路径、内部标识、日志或校验计数作为叙事主线。只有多阶段关系确有证据支持时，才使用简洁的流程图或时序图，并让图后的引用直接支撑其中关系，不为形式刻意添加图表。参考 [读者化写作要求 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/prompt.md#L9 "支持先说明场景与概念、使用功能化标题，并仅在有证据时采用流程图的写作要求。")

<a id="traceability"></a>
## 引用与疑问如何保持可核验

每条引用都应在正文中出现，使用人可读标签，并说明其支持附近哪项论断。证据不足、背景缺失或需要用户选择的事项应记录为具体的结构化疑问，写明原因、下一步、是否阻塞及关联证据。参考 [引用与具体疑问 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/prompt.md#L5 "支持引用就近出现、采用人读标签，以及将不确定事项记录为结构化疑问的要求。")

移除引用标记后，正文仍应语句通顺；相关但不直接支持论断的材料应标为延伸阅读。引用代码时，应选择真正支持论断的最小连续行范围，不能为方便而引用整个大文件。参考 [代码引用范围 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/prompt.md#L15 "支持正文移除引用后仍然通顺、间接材料作为延伸阅读，以及代码引用采用最小连续范围的要求。")

这些内容描述的是角色的输出规范，并未提供运行时代码、调用记录或验收结果，因此不能仅据此断言宿主已经自动执行目标覆盖、引文提取或结构校验。

<a id="scope-boundary"></a>
## 规范与已实现能力的边界

提示词能够证明角色被要求遵循目标覆盖、引用格式和疑问结构等规则，却不能单独证明这些规则已由运行时强制校验。判断实际能力仍需结合装载逻辑、Schema 校验结果和真实刷新记录；在这些证据缺失时，应保留明确疑问，而不把预期行为写成已验证事实。参考 [角色输出约束 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/prompt.md#L3 "表明材料内容是对角色输出方式的规范，可据此区分提示词要求与尚待验证的运行时强制能力。")
