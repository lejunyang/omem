# 个人工作记忆的 Web 工作区总入口

App.vue 是 omem Web 端的应用外壳与流程编排层：它负责工作区导航、启动模式识别、全局数据同步、材料采集与搜索，并把知识阅读、学习、判断、通知和递归证据查看交给专门组件。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 把多条记忆工作流收进一个入口

`App.vue` 解决的是个人工作记忆功能分散的问题：侧栏把日常助理、知识库、原始材料、输入、处理、待判断、待办、历史、通知和连接设置组织成稳定入口；URL hash 决定当前页面，无效地址回落到知识库，并用会话存储保留最近视图。它本身更像**应用协调器**，通过响应式状态维持材料、任务、通知、处理作业和决策的当前快照，再把具体界面交给子组件。参考 [工作区导航与视图选择 ↗](../../../apps/web/src/App.vue#L51 "支持 App.vue 统一组织主要产品入口，并以 hash 和会话状态选择当前页面。")

<a id="startup"></a>
## 启动时先识别服务，再同步工作区

组件挂载后调用 `boot()`。它先探测 `/api/review/health`：明确返回评审模式时只展示迁移提示；404 才继续按个人服务启动，其他状态视为尚未就绪或需要令牌，并每两秒重试。个人模式随后读取健康状态、Agent 配置和业务数据，首次进入还会打开最新材料，并以 2.5 秒周期刷新。参考 [启动模式识别 ↗](../../../apps/web/src/App.vue#L297 "支持启动时区分评审服务与个人服务、处理连接错误、初始化配置并启动轮询的流程。")

`refresh()` 并行拉取材料、通知、事项、变更、作业、提案和决策，同时用互斥标记避免轮询重叠；若正在读某个版本，还会依据最新 source head 更新“当前/历史版本”标志。参考 [全局数据刷新 ↗](../../../apps/web/src/App.vue#L243 "支持并行刷新多类工作区数据、避免刷新重入并校正当前版本状态的说明。")

<a id="capture-flow"></a>
## 代表性调用：保存一段材料并进入阅读

以用户提交“文本＋图片＋链接”为例：表单触发 `capture()`，函数把非空文本、链接和已校验图片组装成 `parts`，补充来源身份、事件时间、时区及 original 生产者等 provenance，再调用 `/captures`。成功后依次刷新全局列表、用返回的 revision id 打开版本、提示“新建”或“内容未变而复用”，最后只清空标题、正文和图片；链接、来源类型、来源标识及各连接器字段会保留。参考 [材料采集主流程 ↗](../../../apps/web/src/App.vue#L416 "支持文本采集时组装多模态 parts、记录 provenance、保存后刷新并打开新版本，以及仅清空标题、正文和图片的代表性调用。")

```mermaid
  A[用户提交材料] --> B[组装 parts 与 provenance]
  B --> C[调用 captures API]
  C --> D[刷新工作区]

  E --> F[展示正文和固定片段入口]
```
参考 [材料采集主流程 ↗](../../../apps/web/src/App.vue#L416 "支持文本采集时组装多模态 parts、记录 provenance、保存后刷新并打开新版本，以及仅清空标题、正文和图片的代表性调用。")、[版本打开流程 ↗](../../../apps/web/src/App.vue#L364 "支持由 revision id 切换材料页、读取版本详情、设置首个片段焦点并加载历史的说明。")、[原始材料阅读出口 ↗](../../../apps/web/src/App.vue#L797 "支持依据材料类型渲染正文，并将固定片段用于聚焦提问或打开证据阅读器。")

`openRevision()` 是这条链的阅读出口：它切到原始材料页，取得完整 revision，以首个 fragment 作为提问焦点，并加载同一 source 的历史。模板按扩展名选择代码或 Markdown 阅读器；片段既可设为助手焦点，也可交给全局 `EvidenceReader.open()` 查看来源。参考 [版本打开流程 ↗](../../../apps/web/src/App.vue#L364 "支持由 revision id 切换材料页、读取版本详情、设置首个片段焦点并加载历史的说明。")、[原始材料阅读出口 ↗](../../../apps/web/src/App.vue#L797 "支持依据材料类型渲染正文，并将固定片段用于聚焦提问或打开证据阅读器。")

<a id="boundaries"></a>
## 搜索防竞态与模块边界

顶部查询一旦非空就暂时替代当前业务页。查询、用途或材料角色变化时，旧定时器和请求会被取消，250 ms 后发起新搜索；递增版本号保证迟到响应不能覆盖新结果。参考 [搜索输入防抖 ↗](../../../apps/web/src/App.vue#L189 "支持搜索条件变化时清空旧状态、取消请求、延迟执行并递增版本号的机制。")、[搜索响应防竞态 ↗](../../../apps/web/src/App.vue#L376 "支持 AbortController 与搜索版本共同阻止取消请求或迟到结果覆盖当前查询。")

命中后的去向由目标类型决定：事项切到待办页，记忆优先追到第一条原始依据，知识与原始材料则压入证据轨迹；知识引用还会作为单独 citation frame 打开。抽屉使用 `useEvidenceTrail` 管理前进、返回、跳层和循环提示，而 `KnowledgeFrame` 负责实际内容加载。参考 [命中结果导航 ↗](../../../apps/web/src/App.vue#L151 "支持事项、记忆、知识和引用分别进入业务页、原始依据或证据轨迹的分流逻辑。")、[递归阅读抽屉 ↗](../../../apps/web/src/App.vue#L1230 "支持 App.vue 将轨迹状态交给抽屉，并由 KnowledgeFrame 加载当前知识或引用框架。")

边界也很清楚：知识库、材料处理、待判断、日常助理等业务由子组件实现，`App.vue` 只下发状态并接收 `refresh/open/error/notice` 事件；卸载时会移除 hash 监听、停止轮询和搜索请求，避免页面离开后继续更新。参考 [业务子页编排 ↗](../../../apps/web/src/App.vue#L961 "支持 App.vue 向知识处理、待判断和日常助理子组件传递状态并响应刷新、打开与错误事件。")、[组件卸载清理 ↗](../../../apps/web/src/App.vue#L600 "支持页面卸载时移除监听、清理定时器并取消搜索请求的边界行为。")
