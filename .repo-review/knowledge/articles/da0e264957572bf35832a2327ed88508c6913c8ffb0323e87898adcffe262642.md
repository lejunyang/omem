# 个人工作记忆 Web 应用总入口

App.vue 是个人工作区与仓库评审模式的顶层编排组件，负责启动探测、周期刷新、材料采集和版本阅读，并协调证据阅读、问答、判断、通知及并发更新。本文已替代把界面文案当作后端保证、把恢复提示当作服务端历史语义证明，以及用不匹配引用说明问答配置传递的旧结论。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-boot"></a>
## 入口职责与双模式启动

该组件集中维护材料、版本、任务、通知、变更、提案与判断等页面状态。启动时先探测 `/api/review/health`：确认是仓库评审服务便切换到 `ReviewApp` 并停止个人业务初始化；否则读取个人工作区健康状态、Agent profiles 和业务集合，再默认打开首份材料。[双模式启动流程 ↗](../../../apps/web/src/App.vue#L157 "支持先识别仓库评审模式、否则初始化个人工作区并打开首份材料的论断。")

普通模式的 `refresh` 并行读取七类集合，以 `refreshing` 阻止重入，同时更新当前版本是否仍为 head，并根据通知模式生成即时提示。任一请求失败会使本轮 `Promise.all` 无法完成整组赋值，当前实现没有局部成功结算。[全局集合刷新 ↗](../../../apps/web/src/App.vue#L104 "支持并行加载七类状态、防止刷新重入、更新 head 状态及生成通知提示的说明。") 挂载完成后每 2.5 秒刷新，卸载时清理轮询和提示计时器；评审模式不会启动这套业务轮询。[轮询生命周期 ↗](../../../apps/web/src/App.vue#L401 "支持普通模式启动定时刷新、评审模式跳过轮询以及卸载清理计时器的说明。")

<a id="capture-and-evidence"></a>
## 材料采集、版本与证据阅读

采集按飞书、服务器文件、Git 文件和通用输入分流。通用输入把文本、链接与图片组成 parts，并附带来源主体、事件时间、时区和生产者等 provenance；成功后刷新集合、打开接口返回的版本，并按 `duplicate` 提示复用原版本或生成固定片段。[多来源采集与固定版本 ↗](../../../apps/web/src/App.vue#L230 "支持采集模式分流、通用 parts 和 provenance 构造，以及成功后的刷新、打开版本与重复提示流程。") 图片上传在前端限制为 PNG、JPEG、WebP 且不超过 5 MB。[图片上传校验 ↗](../../../apps/web/src/App.vue#L209 "支持图片 MIME、大小限制和读取方式的论断。")

此前“界面说明足以证明后端导入安全限制”的结论已被替代：`captureRoots`、只读指定 commit、不执行仓库脚本、UTF-8 与 500 KB 都是当前页面展示的约束，仅凭该组件不能确认服务端已完整强制执行。[文件与 Git 导入说明 ↗](../../../apps/web/src/App.vue#L653 "支持页面所展示的 Git 只读、captureRoots、UTF-8 和 500 KB 约束，并用于明确这些文案不能单独证明后端强制执行。") 阅读固定证据时，`EvidenceReader` 从 `/evidence/:id` 加载内容、压入帧栈并保存上一层滚动位置；若目标已在栈中，则记录循环位置而不重复压栈。[证据阅读帧栈 ↗](../../../apps/web/src/EvidenceReader.vue#L9 "支持证据加载、循环目标识别、帧栈压入和滚动位置保存的论断。")

<a id="coordination"></a>
## 子模块协作与状态回流

App 通过 props 下发服务端状态，并统一接收学习、判断和日常助理发出的刷新、证据打开、错误与通知事件。[业务子视图事件编排 ↗](../../../apps/web/src/App.vue#L675 "支持学习、判断和日常助理通过事件请求刷新、打开证据或报告状态的说明。") 底部装配进一步明确父子合同：`EvidenceReader` 和 `ChatPane` 接收 profile、model、effort，二者的 `saved` 都连接到全局 `refresh`；`NotificationDetail` 的证据事件进入阅读器，版本事件会关闭详情并调用 `openRevision`。[阅读器、通知与问答装配 ↗](../../../apps/web/src/App.vue#L887 "支持 App 对 EvidenceReader、NotificationDetail、ChatPane 的参数和事件绑定关系。")

`ChatPane` 创建运行时仅在配置非空时发送 model 和 effort，随后约每 450 毫秒轮询；只有运行进入 `done` 才发出 `saved`。因此空值由宿主采用默认配置、完成后触发全局刷新，分别由请求构造和父级事件绑定共同体现。[问答运行创建与轮询 ↗](../../../apps/web/src/ChatPane.vue#L33 "支持仅发送非空 model 和 effort、轮询运行，并在成功完成时发出 saved 的论断。") 判断提交携带 proposal digest、随机 request ID 与 actor ID，并在成功或失败后要求父级刷新。[判断提交与状态刷新 ↗](../../../apps/web/src/DecisionsView.vue#L28 "支持判断请求携带摘要、请求身份和 actor，并在成功或失败后通知父组件刷新的说明。")

通知详情负责展示 application receipt，并发出查看变更前后版本的事件；它本身不负责加载详情或标记已读。[通知回执与版本事件 ↗](../../../apps/web/src/NotificationDetail.vue#L27 "支持通知详情展示 application receipt，并仅通过事件请求打开变更前后版本的职责边界。") 这些职责位于 App：打开详情时请求通知详情，未读通知随后调用已读接口并刷新集合。[通知详情加载与已读处理 ↗](../../../apps/web/src/App.vue#L323 "支持 App 请求通知详情、为未读通知调用已读流程及维护加载状态的论断。")

<a id="boundaries"></a>
## 并发、能力协商与已知边界

搜索用递增版本号防止旧响应覆盖较新的结果，但不会取消已发请求；界面同时声明当前仍是精确文本检索。[搜索乱序保护 ↗](../../../apps/web/src/App.vue#L198 "支持递增版本门控搜索响应且不取消旧请求的实现说明。") 乐观并发由独立参数体现：任务状态切换携带任务的 `expectedVersion`。[任务乐观并发参数 ↗](../../../apps/web/src/App.vue#L308 "支持任务状态变更携带 expectedVersion 的论断。") 恢复操作则由前端携带 `expectedHead` 调用恢复接口；接口成功后，页面刷新数据、打开返回的版本，并显示“已恢复为新版本，历史保留”的提示。该材料只能证明这些前端请求与可观察行为，不能独立证明服务端必然创建新版本或完整保留历史。[恢复请求与前端后续行为 ↗](../../../apps/web/src/App.vue#L346 "支持恢复请求携带 expectedHead，并在接口成功后刷新、打开返回版本和显示历史保留提示；不将其扩张为服务端实现保证。")

Agent 能力通过 profile probe 动态读取，并只整理 select 类型选项；访问令牌写入 `sessionStorage` 后重新执行启动流程。[Agent 能力探测与会话令牌 ↗](../../../apps/web/src/App.vue#L359 "支持动态发现 select 类型能力、保存会话级令牌并重新启动连接的说明。") 设置界面把空 model 和 effort 描述为使用宿主默认，并说明上下文超限应明确拒绝；实际问答请求也只在二者非空时附带相应字段，因此支持范围和默认值由宿主及服务端决定，而不是前端固定枚举。[模型与连接设置界面 ↗](../../../apps/web/src/App.vue#L783 "支持 model 和 effort 留空使用宿主默认、上下文超限拒绝，以及令牌仅保存在当前浏览器会话的页面说明。") [问答运行创建与轮询 ↗](../../../apps/web/src/ChatPane.vue#L33 "支持仅发送非空 model 和 effort、轮询运行，并在成功完成时发出 saved 的论断。")
