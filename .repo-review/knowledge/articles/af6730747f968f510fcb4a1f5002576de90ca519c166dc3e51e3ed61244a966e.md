# 证据阅读界面与知识整理设计

这份设计规范确立 omem 的黑白灰阅读基线，规定页面布局、公共组件、递归引用、响应式与无障碍行为，并补充分类阅读、两步整理文章和公共折叠组件的交互合同。它描述的是界面实施要求；具体完成度仍需结合进展记录和实际页面核验。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-layout"></a>
## 为阅读、追问与行动提供统一工作区

这套设计服务于“阅读材料—核对证据—继续追问—形成行动”的连续场景。文档把黑白灰证据阅读风格定为产品基线，并指定 Vue 3、TypeScript 与 `packages/ui` 为实现方向；这是实施规范的陈述，不等同于所有界面已经完成。参考 [设计基线与实现入口 ↗](../../../design.md#L1 "支持该文件是界面实施规范、采用黑白灰证据阅读风格并以 Vue 3 和 packages/ui 为实现方向的说明。")

桌面工作区由顶栏、材料入口、正文与基于固定片段的追问区域组成。需求和待办可以进入个人助理流程，但材料本身不会自动成为执行指令；引用还应贴近论断，并显示固定版本、来源和关系，使读者能区分原文、模型回答与已验证事实。参考 [工作区与证据呈现 ↗](../../../design.md#L22 "支持三栏信息架构、材料不自动成为指令以及引用和事实状态应明确展示的论断。")

<a id="visual-and-components"></a>
## 用公共组件保持证据阅读的一致性

视觉层以近黑文字、白色面板、灰色引用背景和明确的警告文字构成，正文强调舒适行高与约 46 个汉字的阅读宽度；颜色不能成为状态的唯一载体。参考 [视觉与排版规则 ↗](../../../design.md#L7 "支持中性色视觉 token、状态表达、字体字号、间距和正文行宽等阅读规范。")

业务页面应复用 `@omem/ui` 的按钮、弹窗、引用、空状态、面板和外壳，通过 props、slots 与 events 接入数据，UI 包自身不连接 API 或读取密钥。`Shell` 负责桌面三栏与窄屏切换，`Dialog` 和 `Citation` 则明确键盘操作与焦点恢复合同。参考 [公共组件合同 ↗](../../../design.md#L28 "支持业务页面复用 UI 组件、数据注入边界以及 Shell、Dialog、Citation 等组件职责。")

引用弹窗采用可回退的层级栈：进入下一级时保存当前滚动和草稿，Esc 返回上一层，循环引用跳回已有层级，关闭后背景文章仍保持原状态。参考 [递归引用交互 ↗](../../../design.md#L40 "支持引用弹窗的入栈、回退、循环处理、状态保存和背景文章保持规则。")

<a id="responsive-and-organization"></a>
## 让分类阅读和整理流程适应不同屏幕

布局在桌面、平板和手机间逐级收拢：右栏先变侧栏，手机上导航折叠、引用全屏；字号不能为了塞入桌面结构而缩小。点击区域、标签、焦点轮廓、Tab 顺序及减少动画偏好都有明确要求。参考 [响应式与无障碍 ↗](../../../design.md#L44 "支持三个屏幕范围的布局变化及点击区域、焦点、键盘和减少动画要求。")

分类页以阅读为主，目录按持久化的人读分类组织，不根据文件路径、内部 key 或引用关系猜测层级。创建内容通过两步 `OmDialog` 完成，先选材料，再说明阅读目标；草稿在返回或重开时保留，只有提交成功才清空。公共 `OmDisclosure` 统一折叠行为，并在标题导航与展开箭头并存时分离两种操作。参考 [阅读目录组织原则 ↗](../../../design.md#L56 "支持目录按持久分类路径组织、阅读区节奏和实际视觉验收要求。") [分类整理与折叠组件 ↗](../../../design.md#L62 "支持分类页结构、两步整理流程、草稿保留以及 OmDisclosure 的交互和无障碍合同。")

相关架构进一步说明：分类只负责组织，引用依赖负责关联与更新；跨领域选材和已有文章归类仍需要用户或后续治理能力，因此当前设计不能被理解为自动完成全库分类。延伸阅读：[分类与引用边界 ↗](../../../docs/reader-first/architecture.md#L33 "补充说明分类、来源、引用依赖和调查范围的不同职责，以及自动分类治理尚未完成的限制。")
