# 证据阅读界面的设计规范

该文档是 omem 当前界面的实施规范，规定黑白灰视觉基线、三栏证据阅读布局、共享组件合同、引用深入交互、响应式与无障碍要求，以及真实行为验收边界。它描述应如何实现界面，不等同于证明所有功能已经完成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-visual-language"></a>
## 为可追溯阅读建立统一视觉语言

omem 的界面服务于“阅读结论、核对原文、继续追问”的证据工作流。当前规范明确采用 Vue 3 与 TypeScript，并以 `packages/ui` 作为实现入口；黑白灰证据阅读风格是产品基线，而系统架构另见架构文档。参考 [界面规范定位 ↗](../../../design.md#L1 "支持该文件是当前视觉实施规范、技术栈为 Vue 3 与 TypeScript，并与系统架构文档分工的说明。")

视觉上使用中性近黑文字、白色面板、灰色引用背景和克制的警告色；正文保持较宽行距与约 46 个汉字的阅读宽度，避免彩色渐变、在线字体和用 emoji 充当操作图标。这些约束旨在让证据、状态和操作层级清楚可辨，而不是制造装饰性界面。参考 [视觉与排版基线 ↗](../../../design.md#L5 "支持黑白灰 token、字体、字号、间距、阅读宽度和图标风格等视觉要求。")

<a id="layout-and-components"></a>
## 三栏阅读与共享组件合同

桌面布局由材料导航、当前正文与片段、基于固定片段的追问区域组成；需求、待办和观察记录可以进入助理工作流，但采集到的材料本身不能自动被当作执行指令。引用应贴近论断，并展示固定版本、来源、原文和关系；外部 HTML 不能未经审查直接渲染。参考 [证据阅读布局 ↗](../../../design.md#L22 "支持三栏信息架构、材料不等于指令、固定引用展示及安全渲染边界。")

业务页面应复用 `@omem/ui` 的按钮、弹窗、引用、徽标、空状态、面板和外壳组件。组件只通过 props、slots 与 events 接收业务数据，不直接访问 API 或密钥；焦点、键盘操作、状态文本和关闭后的焦点恢复属于统一合同。参考 [共享组件合同 ↗](../../../design.md#L30 "支持组件复用范围，以及按钮、弹窗、引用、空状态和响应式外壳的交互约束。")

<a id="evidence-trail-and-acceptance"></a>
## 可深入又可返回的证据路径

引用阅读采用帧栈式路径：点击下一级进入，Esc 或返回键退层，循环引用跳回已有层级；每层保留滚动位置与局部草稿，关闭引用后仍能回到原文章状态。移动端则把引用切换为全屏，并让问答在当前视图展开，同时维持可点击尺寸、标签、焦点轮廓和辅助技术提示。参考 [引用路径与无障碍 ↗](../../../design.md#L40 "支持引用帧栈、循环处理、状态保留、移动端适配及无障碍要求。")

规范还要求界面反映真实运行结果：按钮必须执行动作或明确禁用，服务和模型错误不得用模拟成功掩盖，配置必须真正传入执行器，知识修改失败也不能显示成功。文档要求通过项目检查和浏览器行为检查验收，但这些要求本身不是“已经通过验收”的实现证据。参考 [真实行为验收 ↗](../../../design.md#L50 "支持真实动作、错误状态、模型配置传递、通知语义和检查要求，同时表明这些属于验收规范。") 架构文档也明确其早期内容属于设计提案而非当前运行代码，因此判断完成度仍需结合实施状态。延伸阅读：[架构提案状态说明 ↗](../../../docs/design.md#L5 "说明架构文档明确区分早期设计提案与当前运行实现，避免把旧计划表述为已完成能力。")
