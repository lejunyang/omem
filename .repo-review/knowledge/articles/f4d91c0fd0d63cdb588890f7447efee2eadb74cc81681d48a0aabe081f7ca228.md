# 知识疑问、用户补充与调查请求

展示未被替代的疑问，并允许用户向回答或待办端点发起请求；当前材料仅证明前端请求、刷新和提示行为。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="question-lifecycle"></a>
## 疑问筛选与状态表达

组件加载全部疑问，可按 documentKey 限定文档，并排除 superseded 项。界面区分 open、answered、task 与 blocking 状态，展示问题、缘由和下一步；摘要数量只统计 open 项，使尚待处理内容与已补充或已转待办内容分开呈现。[疑问加载与操作请求 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L5 "支持疑问过滤、answer 与 task 请求、成功提示、状态清理及重新加载流程。")[疑问状态与操作界面 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L17 "支持状态标签、原因、下一步、回答表单、待办按钮及共享消息区域的描述。")

<a id="answer-task"></a>
## 回答与待办端点交互

用户提交回答时，前端向该疑问的 answer 端点发送文本；成功后显示“作为原始材料保存”的提示、清空编辑状态并刷新列表。加入待办则向 task 端点 POST，成功后提示并刷新。这里仅能确认请求和界面文案，不能据此断言服务端确已持久化原始材料或待办。[疑问加载与操作请求 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L5 "支持疑问过滤、answer 与 task 请求、成功提示、状态清理及重新加载流程。")[疑问状态与操作界面 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L17 "支持状态标签、原因、下一步、回答表单、待办按钮及共享消息区域的描述。")

<a id="interaction-limits"></a>
## 反馈与并发限制

初次加载失败和两类操作结果共用一条 message；代码未呈现逐问题 pending 状态、按钮禁用或重复提交防护。列表仅在挂载和操作成功后刷新，没有轮询，因此慢请求、并发操作及服务端失败时的细粒度反馈仍未定义。[疑问加载与操作请求 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L5 "支持疑问过滤、answer 与 task 请求、成功提示、状态清理及重新加载流程。")[疑问状态与操作界面 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L17 "支持状态标签、原因、下一步、回答表单、待办按钮及共享消息区域的描述。")
