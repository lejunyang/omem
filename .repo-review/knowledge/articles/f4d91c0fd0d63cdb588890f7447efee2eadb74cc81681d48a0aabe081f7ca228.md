# 知识疑问的展示与前端操作入口

展示未被替代的知识疑问，并提供补充背景与加入待办的请求入口；组件只能证明前端请求、提示及刷新行为，不能单独证明服务端持久化结果。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="question-lifecycle"></a>
## 疑问筛选与状态表达

组件加载疑问列表，可用 `documentKey` 限定所属文档，并从可见结果中排除 `superseded` 项；摘要数量只统计 `open` 状态。界面把其余状态显示为“已补充背景”“已加入待办”“需要判断”或“后续调查”，同时呈现原因与建议下一步，使尚不能从材料确认的事项继续保持可见。[疑问加载与可见范围 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L5 "支持组件加载疑问、按文档筛选、排除已被替代项，以及共享消息状态等论断。")[疑问状态与操作界面 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L17 "支持状态标签、开放疑问的两个操作入口、回答表单和统一状态消息的界面行为。")

<a id="answer-and-task"></a>
## 补充背景与待办请求

对开放疑问，用户可填写必填文本并提交；前端向该疑问的 `answer` 端点发送回答，成功返回后显示“作为原始材料保存”的提示、清空输入并重新加载列表。另一按钮会向 `task` 端点发送 POST，随后显示“已加入待办”并刷新。这里描述的是请求和界面反馈，不能据此断言服务端已经创建原始材料或待办；此前把两者直接表述为已持久化语义的结论由此替代。[回答与待办请求处理 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L11 "支持前端向 answer 和 task 端点发起请求、设置成功提示并刷新列表的限定性论断。")[疑问状态与操作界面 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L17 "支持状态标签、开放疑问的两个操作入口、回答表单和统一状态消息的界面行为。")

<a id="interaction-limits"></a>
## 反馈边界与待验证能力

初次加载错误、回答结果和待办结果共用同一个 `message`；组件未展示逐问题 pending 状态、按钮禁用或重复提交防护，也只在挂载及操作完成后主动刷新。成功文案依赖请求正常返回，但当前材料没有服务端路由、存储实现或行为测试，因此持久化内容、失败后的状态一致性与重试语义仍需另行核验。[疑问加载与可见范围 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L5 "支持组件加载疑问、按文档筛选、排除已被替代项，以及共享消息状态等论断。")[回答与待办请求处理 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L11 "支持前端向 answer 和 task 端点发起请求、设置成功提示并刷新列表的限定性论断。")
