# 知识疑问、补充请求与调查入口

展示尚未被替代的知识疑问，并允许用户向回答或待办端点发起请求；界面会刷新状态并显示结果提示，但本组件不足以证明服务端持久化语义。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="question-lifecycle"></a>
## 疑问筛选与状态表达

组件从 questions 接口读取疑问，可用 documentKey 限定所属文档，并排除 superseded 项。摘要只统计 open 状态；每项依据 state 和 blocking 显示“已补充背景”“已加入待办”“需要判断”或“后续调查”，同时呈现问题、原因与建议下一步。这里的状态来自接口返回，组件本身不推导知识结论是否已经更新。[疑问加载与操作请求 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L5 "支持疑问过滤、answer 与 task 请求、成功提示、表单清理和列表刷新等前端行为。")[疑问状态与操作界面 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L17 "支持 open 数量、状态标签、原因和下一步展示，以及补充背景和加入待办两个入口。")

<a id="answer-and-task"></a>
## 回答与待办请求

对 open 疑问，用户可展开表单并向 answer 端点 POST 输入内容；请求成功后，界面显示“回答已作为原始材料保存”的提示、清空输入并重新加载列表。另一按钮向 task 端点发起独立 POST，成功时提示“已加入待办”并刷新。上述材料只能证明前端请求及提示行为，不能独立证明服务端确实创建了原始材料或待办。[疑问加载与操作请求 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L5 "支持疑问过滤、answer 与 task 请求、成功提示、表单清理和列表刷新等前端行为。")[疑问状态与操作界面 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L17 "支持 open 数量、状态标签、原因和下一步展示，以及补充背景和加入待办两个入口。")

<a id="interaction-limits"></a>
## 交互与反馈限制

初次加载失败以及两个操作的成功或失败都写入同一条 message；回答文本和当前展开项也是组件级单一状态。提交期间没有可见的 pending 标记、按钮禁用或重复提交防护，列表只在挂载及操作成功后重新请求，没有实时订阅。因而慢请求或并发操作时的反馈隔离尚不明确，也无法从本组件判断服务端失败后如何保持疑问状态一致。[疑问加载与操作请求 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L5 "支持疑问过滤、answer 与 task 请求、成功提示、表单清理和列表刷新等前端行为。")[疑问状态与操作界面 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L17 "支持 open 数量、状态标签、原因和下一步展示，以及补充背景和加入待办两个入口。")
