# 待判断决策交互界面

该 Vue 组件集中呈现需要人工判断的提案，并允许用户请求补充背景、拒绝或确认应用。前端会随动作提交提案摘要和独立请求标识，供后端实施版本校验与幂等处理；组件本身只提供过期状态提示和操作入口，不能证明服务端已经完成相应校验。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-presentation"></a>
## 作用与信息呈现

组件接收决策数组，把歧义、冲突或影响较大的提案集中为待判断面板。标题依次取提案正文的 `title`、`statement` 或提案种类，并将常见状态转换为中文。[标题与中文状态映射 ↗](../../../apps/web/src/DecisionsView.vue#L6 "支持组件输入、事件合同、标题回退规则以及状态中文名称的说明。") 状态徽标按 pending、approved、stale/expired 选择警告、成功或危险色调，同时展示有效期及已有处理回执。[状态徽标、有效期与回执 ↗](../../../apps/web/src/DecisionsView.vue#L58 "支持不同状态的徽标色调以及有效期和处理回执的界面呈现。")

每个面板展示提案原因、动作、对象、影响范围、正文和不确定项；具体变化位于默认展开但可由用户收起的 `details` 中。证据项截取短引文作为标签，点击后仅向父级发出固定 fragment revision 标识，原文读取与核验不在本组件内完成。[提案详情与证据入口 ↗](../../../apps/web/src/DecisionsView.vue#L93 "支持可折叠变更详情、正文、不确定项和证据打开事件的说明。")

<a id="decision-flow"></a>
## 提交决策的核心流程

动作处理函数调用组件从本地模块导入的 `api`；所给材料能够确认这一依赖，但没有提供该请求函数的封装实现。[组件导入的 API 函数 ↗](../../../apps/web/src/DecisionsView.vue#L1 "支持组件调用从本地 API 模块导入的函数，同时不扩展为对请求封装内部实现的断言。") 用户触发动作后，组件以“决策 ID + 动作”记录忙碌状态，并向 `/decisions/{id}` 提交动作、`proposalDigest`、随机 `requestId` 与 `actorId`。成功时发送对应通知并刷新，失败时上报错误后也刷新，最终清理忙碌状态。[决策请求处理流程 ↗](../../../apps/web/src/DecisionsView.vue#L28 "支持请求载荷、通知与错误事件、刷新行为及忙碌状态清理流程，同时限定前端材料只能证明参数被提交。")

这里应以新结论替代旧稿中的“通过摘要校验”：材料只证明前端提交摘要供后端校验，并未证明服务端一定拒绝来源变化后的旧提案。`requestId` 同样只是请求身份输入，幂等、冲突响应和事务边界仍需结合后端实现确认。

<a id="boundaries"></a>
## 状态保护与界面限制

只有 `pending` 状态会渲染补充背景、拒绝和确认应用按钮；`stale` 还会明确提示原件已更新、旧判断不能提交。其他非 pending 状态同样没有动作入口，空数组则显示无待判断变化。[过期提示与待处理动作 ↗](../../../apps/web/src/DecisionsView.vue#L120 "支持 stale 阻断提示、仅 pending 状态渲染动作按钮以及空列表呈现。")

忙碌状态只匹配当前决策的单个动作，代码没有显式禁用同一面板中的其他按钮，是否可能并发提交还取决于 `OmButton` 和后端。提案正文以格式化 JSON 显示，可滚动、换行，并能随整个 `details` 收起；因此旧稿所称“没有折叠”被替代为更准确的限制：没有字段级结构化展示或单字段折叠。窄屏下三列摘要会改为单列。[正文样式与窄屏布局 ↗](../../../apps/web/src/DecisionsView.vue#L150 "支持 JSON 正文的滚动换行行为以及小屏幕下变更摘要改为单列的限制说明。")
