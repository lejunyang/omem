# docs/README.md · 模块理解

该模块是 omem 设计与实施资料的导航入口：交代长期记忆系统的产品方向，指引读者区分当前实现、设计系统与后续交接方案，并明确原型和研究结论的证据边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role"></a>
## 职责与背景

`docs/README.md` 的首要职责是建立项目认知入口，而不是罗列已交付功能。它把 omem 定位为支持 Agent 自治、自学习的长期记忆系统，核心机制是可深入阅读的版本化证据引用；当前产品方向则以飞书主 Agent 为第一入口、Web 为后台及第二入口。与此同时，已有 90 项测试只能说明阶段性工程进展，不能直接证明语义质量或助手体验达标。[产品方向与长期记忆定位 ↗](../../../docs/README.md#L3 "支持该模块对系统目标、版本化证据核心、飞书与 Web 入口关系，以及测试数量不能代表体验达标的说明。")

<a id="reading-flow"></a>
## 阅读与协作流程

首次阅读应先从本页识别资料层级，再转到“当前实施状态”和项目运行指南核实现有能力；涉及视觉设计时查看根级设计文档。后续 Agent 可从 Batch 2 交接包了解详细方案、ACP 提示词与 Skills、飞书扫码绑定、验收合同及专项调研，但这些内容属于待实现计划，不能据此宣称运行能力已经增加。[实施资料阅读路径与交接边界 ↗](../../../docs/README.md#L7 "支持先核对实施状态和运行指南的阅读流程，并说明 Batch 2 交接材料仍是待实现方案。")

<a id="relations-limits"></a>
## 跨材料关系与使用限制

该页连接产品方向、实施状态、运行方式、设计系统、交接方案和研究材料，作用是帮助读者沿正确证据链继续核验，而非替代各专题正文。公司故事、任务、规范和数值样本均是原型演示，不能当作真实业务政策；开源能力也必须区分资料或源码核验与待 PoC 项，未实测的性能和生产可用性不得被承诺。[原型与未实测能力边界 ↗](../../../docs/README.md#L28 "支持原型样本不得视为真实政策、待 PoC 能力不得转述为性能或生产可用性承诺。")
