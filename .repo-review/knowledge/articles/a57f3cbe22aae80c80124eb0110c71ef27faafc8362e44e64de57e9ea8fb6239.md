# 代码评审知识库的增量同步与关系构建

将白名单仓库文本按稳定路径身份捕获为不可变修订；常规模式结合 Git 状态增量同步并重建人工关系，指定路径模式则作为不落同步状态的局部导入。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-capture"></a>
## 捕获目标与分片规则

该模块把仓库文本投影为评审知识库。来源身份采用仓库相对路径，内容哈希仅检测变化，因此同一路径编辑会追加修订，而内容相同的不同文件仍保持独立；常规同步捕获时记录实际 HEAD、工作区脏状态、内容哈希与同步时间，`only` 模式则使用 `{commit:null, dirty:false}` 的空快照。[路径身份与常规捕获快照 ↗](../../../apps/server/src/review/sync.ts#L1 "支持来源以路径保持身份、内容哈希仅用于变更检测，并说明常规同步的快照字段。") [指定路径导入模式 ↗](../../../apps/server/src/review/sync.ts#L863 "支持 only 模式使用空快照、只分类指定路径并绕过常规 Git 分支。")

扫描范围由固定目录、根级白名单和分类规则共同限制。`architecture` 材料按代码声明边界切片，其中仅 `apps/server/tests/*.test.ts` 按测试用例边界；其他类别按 Markdown 标题切片，所以归入 `architecture` 的 Markdown 仍走代码分片。[分类与分片规则 ↗](../../../apps/server/src/review/sync.ts#L126 "支持扫描分类、测试文件范围以及代码、测试和 Markdown 的分片分支。")

单文件捕获拒绝越界链接、不可读文件、超限内容和非法 UTF-8，空文本直接跳过。头修订内容哈希相同则不再调用 `Store.capture`；否则附加分类、快照和符号等上下文后写入共享存储。[单文件捕获流程 ↗](../../../apps/server/src/review/sync.ts#L427 "支持文件安全与编码检查、内容哈希幂等、分片选择、上下文构造和 Store 捕获流程。")

<a id="incremental-flow"></a>
## 增量扫描与状态边界

常规同步读取 HEAD、上次基线、porcelain 工作区状态及基线到当前提交的差异。首次运行、基线缺失或失效、旧捕获格式、上次脏同步，以及 Git 状态或差异命令失败都会转为全量扫描；只有 `git status` 或 `git diff` 失败会在此处显式禁止推进基线。`rev-parse HEAD` 失败导致 `current` 为空并全量扫描，但未单独关闭基线推进；`cat-file` 判定基线无效同样只触发全量扫描和警告。[Git 增量与降级条件 ↗](../../../apps/server/src/review/sync.ts#L878 "支持各类全量重扫条件，并精确区分 status/diff 失败会禁止推进基线，而 HEAD 或基线校验异常没有同样赋值。")

`only` 模式只导入明确给出的且仍可分类的路径，绕过 Git 增量判断，返回空提交和非脏快照，也不重建关系或持久化同步状态。[指定路径导入模式 ↗](../../../apps/server/src/review/sync.ts#L863 "支持 only 模式使用空快照、只分类指定路径并绕过常规 Git 分支。") [关系重建与状态持久化 ↗](../../../apps/server/src/review/sync.ts#L990 "支持 only 模式跳过关系重建和状态持久化，以及常规模式在脏树或文件失败时不推进基线。") 常规模式还会协调删除与移动：不存在的真实路径来源标记为 removed，重命名记录目标路径；同步生成的虚拟来源不会按文件缺失处理。[删除、移动与虚拟来源协调 ↗](../../../apps/server/src/review/sync.ts#L506 "支持真实路径来源的 removed、movedTo 状态，以及虚拟派生来源不会被误判为删除。")

<a id="relation-graph"></a>
## 人工关系图与定位限制

完整同步读取人工维护的关联种子，为每项种子生成独立的派生意图片段，再建立代码到意图的 `implements`，以及意图到需求、决策、调研和测试材料的关系。确定性种子身份使重复构建幂等；目标无法解析仍写为 `missing`，移除的种子会失效，而不是由语义相似度自动确认为关系。[人工关联图构建 ↗](../../../apps/server/src/review/sync.ts#L682 "支持派生意图索引、确定性种子身份、关系边类型、missing 状态和移除种子的失效处理。")

符号定位优先匹配声明或带修饰符的方法，失败后退回包含同名 token 的最早片段；普通引用锚点依赖子串匹配。需求定位会拒绝只在共享总表中出现的编号。这里没有完整 TypeScript AST，也没有跨文件调用分析，因此复杂声明、重载与同名引用可能误定位，现有材料不能据此证明跨文件调用关系。[文本式符号与需求定位 ↗](../../../apps/server/src/review/sync.ts#L581 "支持声明优先、token 回退、子串锚点及专属需求片段判断，并界定非 AST 定位带来的误配风险。")
