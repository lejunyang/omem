# 仓库材料的增量捕获与关系同步

该同步器把仓库代码与文档持续接入评审知识库：以仓库相对路径维持来源身份，用内容摘要避免重复修订，结合数据库身份、Git 基线和工作树状态选择增量或全量扫描，并把人工关联投影为代码、实现意图与原始材料之间的可追溯关系。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-scope"></a>
## 把变化中的仓库变成可追溯证据

同步器解决“仓库内容持续变化时，引用如何稳定指向来源和修订”的问题。仓库相对路径决定来源身份；同一文件内容变化会在原来源下追加修订，内容相同的不同文件仍是独立来源，内容摘要只负责检测变化。参考 [来源身份与同步边界 ↗](../../../apps/server/src/review/sync.ts#L1 "支持路径身份、内容摘要用途、快照字段和同步器的安全边界。")

常规同步读取当前 HEAD，捕获时把提交、工作树状态、内容摘要和同步时间写入修订上下文。参考 [指定捕获与工作树状态 ↗](../../../apps/server/src/review/sync.ts#L876 "支持 only 分支、常规 HEAD 读取、dirty 计算、未跟踪目录展开和重命名映射来源。") [修订捕获上下文 ↗](../../../apps/server/src/review/sync.ts#L482 "支持捕获上下文字段、符号与决策日期补充，以及导入和更新结果的区分。") 临时 `only` 捕获直接按指定路径选择目标，不进入 Git 差异逻辑，也不写同步状态，因此返回的 `lastSyncCommit` 为 `null`。参考 [指定捕获与工作树状态 ↗](../../../apps/server/src/review/sync.ts#L876 "支持 only 分支、常规 HEAD 读取、dirty 计算、未跟踪目录展开和重命名映射来源。") [关系重建与基线推进 ↗](../../../apps/server/src/review/sync.ts#L1009 "支持完整同步重建关系、脏工作树或文件失败时不推进基线，以及 only 模式不持久化同步状态。") 常规同步计算 `dirty` 时会排除 `.repo-review` 内的变化；这个字段描述捕获时整个相关工作树的状态，不能单独证明某个文件来自 HEAD。参考 [指定捕获与工作树状态 ↗](../../../apps/server/src/review/sync.ts#L876 "支持 only 分支、常规 HEAD 读取、dirty 计算、未跟踪目录展开和重命名映射来源。")

扫描范围限定为 `apps`、`packages`、`docs`、`scripts` 和五个根文件。排除目录、环境文件、本地配置与测试夹具后，只有符合分类规则的文本文件会进入候选集合。参考 [扫描范围与材料分类 ↗](../../../apps/server/src/review/sync.ts#L94 "支持固定扫描根、根文件白名单、排除规则及候选文件分类。")

<a id="incremental-flow"></a>
## 从 Git 变化到不可变修订

```mermaid
flowchart LR
  A[核对数据库身份与 Git 基线] --> B[读取工作树变化]
  B --> C[合并已提交差异]
  C --> D[选择全量或增量目标]
  D --> E[校验并切分文件]
  E --> F[写入修订并更新同步状态]
```
参考 [全量与增量目标选择 ↗](../../../apps/server/src/review/sync.ts#L848 "支持数据库身份、基线有效性、旧格式捕获、前次脏状态和 Git 失败共同决定扫描范围。") [单文件校验与分类切分 ↗](../../../apps/server/src/review/sync.ts#L430 "支持文件安全校验、大小与编码限制、摘要去重、按材料类别分派切分器、片段上限和超大片段分块。")

同步先为当前数据库读取或生成身份，再与上次状态中的数据库身份比较。数据库身份不一致、旧格式捕获仍存在、基线缺失或失效、前次同步为脏工作树时，目标会扩大为全部候选文件；基线有效、HEAD 未变且没有相关工作树变化时，目标可以为空。Git 状态或差异读取失败也会退化为全量扫描，并禁止推进基线。参考 [全量与增量目标选择 ↗](../../../apps/server/src/review/sync.ts#L848 "支持数据库身份、基线有效性、旧格式捕获、前次脏状态和 Git 失败共同决定扫描范围。")

单文件先验证链接边界和可读性，再检查 500,000 字节上限与 UTF-8 编码。空文件会跳过；内容摘要与当前头修订相同则记为未变化。其余内容按类别切分，片段数量不超过 1,500 时，单个片段还会按 190,000 字符分块，然后调用共享捕获接口。参考 [单文件校验与分类切分 ↗](../../../apps/server/src/review/sync.ts#L430 "支持文件安全校验、大小与编码限制、摘要去重、按材料类别分派切分器、片段上限和超大片段分块。") 捕获会区分首次导入和后续更新。完整同步还会重建人工关系；工作树存在相关变化或任一文件捕获失败时，当前结果仍会保存，但提交基线不推进，下一次运行可以重新收敛。参考 [关系重建与基线推进 ↗](../../../apps/server/src/review/sync.ts#L1009 "支持完整同步重建关系、脏工作树或文件失败时不推进基线，以及 only 模式不持久化同步状态。")

<a id="fragment-and-relations"></a>
## 定位片段并连接实现意图

服务器测试目录中的 `.test.ts` 按 `describe`、`it`、`test` 边界切分；其余 architecture 材料按常见声明边界切分；非 architecture 材料按 Markdown 标题切分。符号提取同样依赖声明正则，最多保留 200 个去重符号。参考 [单文件校验与分类切分 ↗](../../../apps/server/src/review/sync.ts#L430 "支持文件安全校验、大小与编码限制、摘要去重、按材料类别分派切分器、片段上限和超大片段分块。") [片段与符号边界 ↗](../../../apps/server/src/review/sync.ts#L218 "支持代码、测试和 Markdown 各切分器的边界定义，以及符号提取规则与数量上限。") 这些边界适合提供可引用的粗粒度位置，但没有执行完整 AST 分析。

完整同步把每条人工关联投影成一份独立的派生意图片段，并用代码路径与符号生成稳定关联身份。片段写入意图标题、需求编号、代码路径和生成的稳定关联 ID，后续再用该 ID 回查各自的片段。该索引明确标记为派生内容，不能作为独立原始证据。参考 [派生意图索引与关系构建 ↗](../../../apps/server/src/review/sync.ts#L687 "支持每条关联的独立派生意图片段、实际写入字段、稳定关联 ID、按 ID 回查片段、关系状态处理及已删除种子的失效。") 代码符号解析优先匹配声明或方法，再退回到普通词项命中；代码或意图片段缺失时，`implements` 关系记为 `missing`。参考 [代码符号与引用解析 ↗](../../../apps/server/src/review/sync.ts#L567 "支持代码符号优先匹配定义、普通词项回退及材料锚点缺失时返回空结果。") [派生意图索引与关系构建 ↗](../../../apps/server/src/review/sync.ts#L687 "支持每条关联的独立派生意图片段、实际写入字段、稳定关联 ID、按 ID 回查片段、关系状态处理及已删除种子的失效。")

关系链从“代码→意图”继续连接到需求、决策、调研和测试材料。需求编号必须成为片段标题或列表主题，或者是该片段唯一出现的需求编号；只在共享总表中出现时不会被绑定。参考 [需求片段精确锚定 ↗](../../../apps/server/src/review/sync.ts#L627 "支持需求编号必须对应片段主题或成为片段唯一需求编号，共享总表不会被误绑定。") 其他带锚点的引用找不到对应片段时同样返回缺失。已解析关系沿用种子的状态，无法解析的目标记为 `missing`；种子被删除后，旧关系会转为失效状态。参考 [派生意图索引与关系构建 ↗](../../../apps/server/src/review/sync.ts#L687 "支持每条关联的独立派生意图片段、实际写入字段、稳定关联 ID、按 ID 回查片段、关系状态处理及已删除种子的失效。")

<a id="boundaries-and-migration"></a>
## 失败隔离与来源迁移边界

目录发现会跳过符号链接，不沿链接继续遍历；扫描根本身也必须通过仓库边界检查。参考 [目录发现安全边界 ↗](../../../apps/server/src/review/sync.ts#L156 "支持仓库边界检查、目录遍历跳过符号链接和候选集合构建。") 进入捕获流程后，不安全链接、读取失败、文件超限或非法 UTF-8 都按文件记录失败，其余目标继续处理。参考 [逐文件失败隔离 ↗](../../../apps/server/src/review/sync.ts#L430 "支持捕获阶段对链接、读取、大小和 UTF-8 失败逐文件记录。") 同步代码还明确不访问网络和密钥，也不启动其他工作进程。参考 [来源身份与同步边界 ↗](../../../apps/server/src/review/sync.ts#L1 "支持路径身份、内容摘要用途、快照字段和同步器的安全边界。")

只有当前工作树被 `git status --porcelain -z` 识别出的重命名条目，才会生成旧路径到新路径的映射。协调阶段把已消失的路径来源标记为 removed，并在映射存在时为旧来源记录移动目标；新路径仍使用自己的路径身份。派生意图索引没有对应磁盘文件，因此会被排除在删除判断之外，并修复此前可能留下的 removed 标记。参考 [指定捕获与工作树状态 ↗](../../../apps/server/src/review/sync.ts#L876 "支持 only 分支、常规 HEAD 读取、dirty 计算、未跟踪目录展开和重命名映射来源。") [来源删除与移动协调 ↗](../../../apps/server/src/review/sync.ts#L509 "支持消失路径的 removed 状态、重命名移动指针，以及派生虚拟来源的删除豁免。")

基线到当前 HEAD 的已提交变化通过 `git diff --name-only` 加入扫描集合。这条路径只提供发生变化的文件名，不会建立旧路径到新路径的移动映射。来源协调在一个事务内完成，未变化的元数据不会写入新记录。参考 [已提交差异与协调事务 ↗](../../../apps/server/src/review/sync.ts#L950 "支持已提交变化只按文件名加入集合，并在事务中协调来源元数据。")
