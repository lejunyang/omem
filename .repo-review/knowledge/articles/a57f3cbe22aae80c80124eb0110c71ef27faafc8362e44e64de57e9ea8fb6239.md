# 仓库代码评审知识的增量同步与关系构建

该模块把受控范围内的仓库文件捕获为路径身份稳定的知识来源，依据 Git 状态进行增量同步，并将人工关联种子转换为可追溯关系。失败、脏工作树和无法定位的关系会被如实记录；此前关于顶层声明切分、路径原样保留及种子完整格式校验的结论已由更精确的实现描述替代。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-scope"></a>
## 作用与输入边界

模块让仓库自身成为持续更新的知识来源：来源身份取仓库相对路径，内容哈希只用于识别修订变化；捕获记录 HEAD、脏状态、哈希和同步时间，并明确不联网、不读秘密、不启动 worker。[同步器的路径身份与快照原则 ↗](../../../apps/server/src/review/sync.ts#L1 "支持路径作为来源身份、记录真实快照以及不联网、不读取秘密和不启动 worker 的边界。") 扫描仅进入固定目录和少量根文件，按代码、进度、决策、调研分类，并排除构建目录、运行数据、环境文件及 fixture。[扫描白名单与材料分类 ↗](../../../apps/server/src/review/sync.ts#L94 "支持固定扫描根、根文件白名单、排除规则和材料分类。") 遍历和单文件捕获还会拒绝符号链接或越界路径、超大文件及非 UTF-8 内容，使坏文件形成独立失败记录。[安全遍历与候选收集 ↗](../../../apps/server/src/review/sync.ts#L153 "支持符号链接、真实路径越界检查以及候选文件的受控收集。")

<a id="capture-flow"></a>
## 从文件到不可变修订

代码并非按 AST 或严格“顶层声明”切分，而是遇到匹配声明正则的行就建立边界；该正则允许任意前导空白，因此嵌套声明也可能触发切分。测试按 `describe`、`it`、`test` 行切分，Markdown 按标题切分，符号同样由正则提取。此前“代码以顶层声明切分”的结论被此限制替代。[正则驱动的片段切分 ↗](../../../apps/server/src/review/sync.ts#L210 "证明代码边界允许任意前导空白并按匹配行切分，支持其并非 AST 或严格顶层声明切分的限制。")

`captureOne` 校验文件后计算 SHA-256；若当前 head 已有相同 `verbatim-v1` 哈希则保持幂等，否则生成文本 parts，写入分类、路径、提交、脏状态和同步时间，再调用共享 `Store.capture`。[单文件捕获流程 ↗](../../../apps/server/src/review/sync.ts#L427 "支持文件校验、内容哈希幂等、片段生成、上下文记录及共享捕获入口。") 文本 part 复用统一 Capture 合同的非空与长度约束，而不是建立独立的代码捕获模型。[共享文本捕获合同 ↗](../../../packages/contracts/src/index.ts#L20 "支持同步器文本 part 复用通用合同的非空和最大长度约束。") 当前提供的 Store 材料仅展示初始化，尚不足以确认捕获内部的事务边界。

<a id="incremental-sync"></a>
## 增量选择、路径规范化与收敛

同步解析 `git status --porcelain -z`，NUL 分隔可避免 Git 的 C-style quoting；但实现会对重命名目标执行 `trim()`，并由 `normPath` 将反斜杠转换为斜杠。因此此前“中文、空格和反斜杠路径原样保留”的结论被替代：只能确认避免引号转义，不能保证首尾空格或反斜杠保持不变。[Git porcelain 路径解析与规范化 ↗](../../../apps/server/src/review/sync.ts#L281 "支持 NUL 分隔、重命名目标 trim 以及反斜杠转斜杠的实际行为，用于替代路径原样保留的旧结论。")

数据库身份变化、Git 失败、基线丢失、旧捕获格式或上次脏同步都会触发全量扫描；正常情况下则合并提交差异与工作树变化选择目标。[增量目标选择与全量降级 ↗](../../../apps/server/src/review/sync.ts#L838 "支持数据库身份、Git 状态、基线有效性和上次脏状态共同决定扫描目标。") 消失来源被标为 removed，重命名记录 moved-to，虚拟派生来源不会按磁盘缺失处理。[删除、恢复与重命名协调 ↗](../../../apps/server/src/review/sync.ts#L506 "支持真实文件来源的 removed 状态、旧路径 moved-to 记录及虚拟来源保护。") 扫描后仅非 `only` 模式重建关系；工作树脏或存在失败文件时不推进基线，以便下次重新收敛。[同步收尾与基线推进条件 ↗](../../../apps/server/src/review/sync.ts#L974 "支持逐文件统计、关系重建条件，以及脏状态或失败时不推进基线。")

<a id="relations-and-limits"></a>
## 人工关系图及验证边界

关系只来自人工维护的 associations 文件，词语相似不会自动成为确认关系。合同声明了代码路径、符号、意图、各类引用、状态和证据字段。[人工关联种子的类型合同 ↗](../../../apps/server/src/review/associations.ts#L1 "说明关联由人工维护，列出种子的预期字段，并确认不会由语义相似自动升级为确认关系。") 现有加载实现能明确保证：文件缺失时返回空列表，无效 JSON 或根对象缺少 `associations` 数组时抛错；提供范围不足以证明每条 seed 的全部字段均经过运行时校验，因此此前笼统的“格式错误都会显式抛错”已被收窄。[关联文件的最小运行时校验 ↗](../../../apps/server/src/review/associations.ts#L55 "支持文件缺失返回空列表，以及无效 JSON或缺少 associations 数组时抛错的有限保证。")

构建时先生成派生意图片段，再定位当前 head 的代码符号，建立代码到意图及意图到需求、决策、调研和测试的边；无法定位时写入 `missing`，删除种子会失效，确定性身份保证重复同步幂等。[评审关系构建主流程 ↗](../../../apps/server/src/review/sync.ts#L699 "支持派生意图索引、关系边形、missing 状态、确定性身份和移除种子失效流程。") 符号定位优先声明或方法行后再回退到 token；普通锚点依赖子串，需求锚点则避免把包含多个编号的总表绑定为单项需求。[符号、锚点与需求片段定位 ↗](../../../apps/server/src/review/sync.ts#L581 "说明符号定位回退、普通锚点匹配及避免需求总表误绑定的限制。") 这些关系表达人工种子在当前 head 上的重新定位结果，不能推导未登记的跨文件调用或完整语义依赖。
