# 仓库源码的增量捕获与关系同步

该同步器把仓库代码和文档接入统一记忆存储：以仓库相对路径维持来源身份，以内容摘要避免重复修订，根据 Git 状态选择增量或全量扫描，并把人工维护的实现关联转换为可追溯关系。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-scope"></a>
## 把变化中的仓库变成可追溯证据

同步器解决的是“源码持续变化，但引用仍需明确来自哪个文件、哪个修订”的问题。仓库相对路径是稳定的来源身份；编辑同一文件会追加修订，内容相同的不同文件仍是独立来源。参考 [路径来源身份 ↗](../../../apps/server/src/review/sync.ts#L1 "支持以仓库相对路径作为稳定来源身份，并将内容摘要仅用于检测修订变化。")

常规的非 `only` 同步会读取当前 HEAD，捕获时再把提交、内容摘要、同步时间和 `dirty` 状态写入上下文。参考 [常规同步与指定捕获 ↗](../../../apps/server/src/review/sync.ts#L867 "支持 only 模式直接选择目标且保持空快照，以及常规同步读取 HEAD 并设置提交值的区别。") [捕获上下文字段 ↗](../../../apps/server/src/review/sync.ts#L479 "支持捕获时把提交、脏状态、内容摘要和同步时间写入修订上下文。") 临时 `only` 捕获直接按指定路径选择目标，不读取 HEAD，因此其 `gitCommit` 保持为 `null`。参考 [常规同步与指定捕获 ↗](../../../apps/server/src/review/sync.ts#L867 "支持 only 模式直接选择目标且保持空快照，以及常规同步读取 HEAD 并设置提交值的区别。") `dirty` 仅根据 Git 状态中排除 `.repo-review` 后的工作树变化计算，不能单独证明某个文件属于 HEAD 版本。参考 [脏状态计算 ↗](../../../apps/server/src/review/sync.ts#L899 "支持从 Git 状态中排除 .repo-review 路径后，再以剩余工作树变化计算 dirty。")

扫描范围限定为 `apps`、`packages`、`docs`、`scripts` 和少量根文件，并排除依赖、构建产物、运行数据、环境配置及测试夹具；只有符合分类规则的文本文件会成为候选材料。参考 [扫描范围与分类 ↗](../../../apps/server/src/review/sync.ts#L94 "支持固定扫描根、根文件白名单、排除项及候选材料分类规则。")

<a id="incremental-flow"></a>
## 从 Git 变化到不可变修订

```mermaid
flowchart LR
  A[读取 HEAD 与 Git 状态] --> B[过滤评审运行数据]
  B --> C[合并工作区和提交差异]
  C --> D[选择全量或增量目标]
  D --> E[校验并切分文件]
  E --> F[写入修订并更新同步状态]
```
参考 [增量目标选择 ↗](../../../apps/server/src/review/sync.ts#L881 "支持依据数据库身份、Git 状态、基线有效性和前次脏状态选择全量、增量或空扫描。")

同步会检查数据库身份、上次基线、当前 HEAD、前次脏状态和 Git 差异。数据库重建、基线缺失或失效、前次脏同步及 Git 失败会触发全量扫描；基线有效、HEAD 未变且没有相关工作树变化时可以不捕获文件。参考 [增量目标选择 ↗](../../../apps/server/src/review/sync.ts#L881 "支持依据数据库身份、Git 状态、基线有效性和前次脏状态选择全量、增量或空扫描。")

单文件先进行链接安全、读取、大小与 UTF-8 校验，再比较内容摘要；只有内容变化时才切分文本并调用共享捕获接口。参考 [单文件捕获流程 ↗](../../../apps/server/src/review/sync.ts#L427 "支持文件安全校验、严格解码、内容摘要去重、片段切分及共享捕获接口调用。") 完整同步还会重建人工关系；若工作树存在评审运行路径以外的变化，或任一文件捕获失败，则不推进基线，使后续运行仍能重新收敛。参考 [关系重建与基线推进 ↗](../../../apps/server/src/review/sync.ts#L997 "支持完整同步后重建关系，以及工作树脏或文件失败时不推进同步基线。")

<a id="fragment-and-relations"></a>
## 定位片段并连接实现意图

片段边界依赖轻量正则而非完整 AST：普通代码按常见声明切分，服务器测试目录中的 `.test.ts` 还可按 `describe`、`it`、`test` 切分。因此它适合提供可引用的粗粒度位置，但不能证明复杂语法结构或跨文件调用。参考 [代码与测试切分 ↗](../../../apps/server/src/review/sync.ts#L215 "支持声明正则切分，以及仅对指定服务器测试文件启用测试用例边界。")

完整同步会把人工种子转换为“代码→实现意图→需求、决策、调研或测试”的关系。目标无法解析时记录为 `missing`，被删除的种子会失效，避免旧关系继续显示为有效。参考 [评审关系构建 ↗](../../../apps/server/src/review/sync.ts#L699 "支持代码到意图及下游材料的关系结构、缺失目标处理和已删除种子失效。") 种子文件缺失可视为空集合；JSON 损坏或缺少 `associations` 数组则抛错，防止错误数据静默清空关系。参考 [关联种子加载 ↗](../../../apps/server/src/review/associations.ts#L55 "支持种子文件缺失时返回空集合，以及格式错误或缺少 associations 数组时抛错。")

<a id="boundaries-and-migration"></a>
## 失败隔离与来源迁移边界

目录发现会直接跳过符号链接，不会沿链接继续遍历。参考 [目录遍历规则 ↗](../../../apps/server/src/review/sync.ts#L172 "支持目录发现阶段跳过符号链接且不继续遍历链接目标。") 对已进入捕获流程的目标，不安全链接、不可读文件、超限内容和非法 UTF-8 会按文件记录失败，其余目标仍可继续处理。参考 [捕获安全校验 ↗](../../../apps/server/src/review/sync.ts#L435 "支持捕获阶段对不安全链接、读取失败、超限内容和非法 UTF-8 逐文件记录失败。") 评审同步复用共享 `Store` 的捕获与检索能力，但不触碰个人工作区数据库，也不启动 Lark 或学习 worker。参考 [评审存储隔离 ↗](../../../apps/server/src/review/store.ts#L1 "支持评审运行复用共享 Store 能力，同时隔离个人数据库并避开非评审 worker。") 其在线数据库、同步状态和资源位于仓库内被忽略的 `.repo-review/runtime`，与历史快照和受版本控制的知识资产分开。参考 [评审运行目录 ↗](../../../apps/server/src/review/store.ts#L17 "支持 .repo-review/runtime 的实际路径、用途，以及它与历史快照和知识资产的目录边界。")

只有当前工作树中被 `git status --porcelain -z` 识别为重命名的条目，才会产生旧路径到新路径的映射。参考 [工作树重命名识别 ↗](../../../apps/server/src/review/sync.ts#L899 "支持重命名映射只来自当前 Git 状态中识别出的重命名条目。") 协调阶段会把已消失的路径来源标记为 removed，并在该映射存在时为旧来源记录移动目标；新路径仍采用独立的路径身份。参考 [来源删除与移动 ↗](../../../apps/server/src/review/sync.ts#L506 "支持消失路径标记 removed，并仅依据传入的重命名映射为旧来源设置移动目标。") 基线到当前 HEAD 的已提交变化仅通过文件名差异加入扫描集合，不提供旧路径，也不会单独建立移动指针。参考 [已提交文件差异 ↗](../../../apps/server/src/review/sync.ts#L940 "支持基线到当前 HEAD 的变化只按文件名加入扫描集合，不生成旧路径到新路径的映射。")
