# 仓库代码知识增量同步

该模块把白名单内的仓库文件捕获为路径身份稳定、修订不可变的知识来源，并结合 Git 状态选择增量或全量扫描。扫描规则、HEAD 缺失、重命名、关系重建和失败收敛均有明确边界：文件失败或脏工作区阻止基线推进，关系失败则仅形成 warning 并仍保存同步结果。此前关于排除所有构建目录、始终记录真实 HEAD、仅在完整扫描后重建关系的宽泛结论已被具体实现条件替代。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-scope"></a>
## 用途、扫描范围与文件安全

模块以仓库相对路径作为来源身份；同一路径修改会追加修订，相同内容的不同文件仍是独立来源。捕获上下文保存可取得的 Git 提交、工作区脏状态、内容摘要和同步时间，而不是文件修改时间。[路径身份与快照原则 ↗](../../../apps/server/src/review/sync.ts#L1 "支持路径稳定来源身份，以及捕获上下文记录提交、脏状态、摘要和同步时间的设计目标。")

扫描仅从 `apps`、`packages`、`docs`、`scripts` 四个根和五个根级白名单文件收集候选项。实际通用目录排除项只有 `node_modules`、`dist`、`.git`、`.repo-review`；另外排除 `*.local.json`、文件名以 `.env` 开头的文件，以及 `apps/server/tests/fixtures/`。因此此前“排除所有构建目录和所有测试 fixture”的说法被替代，其他名为 `build` 或 `fixtures` 的目录不会仅因名称自动排除。[候选扫描与具体排除规则 ↗](../../../apps/server/src/review/sync.ts#L94 "支持固定扫描根、根级白名单、四类目录排除项和三类额外文件路径排除条件。")

候选路径还须通过真实路径检查：符号链接、解析失败或解析后越出仓库均视为不安全；目录遍历也不会跟随符号链接。[真实路径与目录遍历安全 ↗](../../../apps/server/src/review/sync.ts#L153 "支持符号链接、真实路径解析失败、越出仓库以及遍历时不跟随链接的安全边界。")

<a id="capture-flow"></a>
## 行级分片、捕获与幂等

代码捕获采用允许前导空白的声明行正则切分，并非 AST 或严格的顶层声明切分，因此嵌套声明也可能开启新片段。服务端测试按 `describe`、`it`、`test` 行切分，Markdown 按标题切分；符号列表同样由声明正则提取。此前“按顶层声明边界分片”的结论由此被替代。[行级分片与符号提取 ↗](../../../apps/server/src/review/sync.ts#L215 "支持代码、测试和 Markdown 的正则分片方式，并说明代码规则允许前导空白而非严格限定顶层。")

单文件先拒绝不安全路径、不可读、超过 500000 字节或非 UTF-8 的内容，空文本计为 skipped。其余内容计算 SHA-256；若当前 head 已保存相同 `verbatim-v1` 摘要，则不再创建修订。发生变化时按类别构造文本 parts 和上下文，再调用共享 `Store.capture`，架构材料附带符号，决策材料只采用正文明确写出的日期。[单文件校验与共享捕获 ↗](../../../apps/server/src/review/sync.ts#L427 "支持文件拒绝条件、空文件跳过、摘要幂等、分类分片、上下文构造及共享捕获调用。")

<a id="incremental-sync"></a>
## Git 降级、增量选择与状态收敛

非 `only` 同步先尝试取得 `HEAD`；若 `rev-parse` 失败，快照提交值保持 `null`。由于后续在当前提交缺失时选择全部候选文件，这种情况仍会全量扫描，而不能表述为每次捕获都必然记录真实 HEAD。[HEAD 获取与空提交快照 ↗](../../../apps/server/src/review/sync.ts#L881 "支持 rev-parse 失败时 current 和 snapshot.commit 保持 null，而非保证始终取得真实 HEAD。") [缺少当前提交时全量扫描 ↗](../../../apps/server/src/review/sync.ts#L932 "支持 current 缺失或基线无效时选择全部候选文件，说明 HEAD 获取失败后的实际降级结果。")

工作区变化来自 `git status --porcelain -z`，其中 rename 同时提供旧、新路径并形成 `movedTo` 映射；已提交差异使用 `git diff --name-only`，通常只表现为旧来源 removed 与新路径捕获。Git status 或 diff 失败、数据库身份变化、旧格式捕获、无有效基线或前次脏同步都会触发全量扫描或重新收敛。[工作区重命名解析 ↗](../../../apps/server/src/review/sync.ts#L283 "支持 porcelain 的 NUL 分隔解析以及只有工作区 rename 记录同时携带旧路径和新路径。") [Git 变化合并与重扫描条件 ↗](../../../apps/server/src/review/sync.ts#L899 "支持 status 失败降级、工作区 rename 映射、已提交 name-only 差异及多种全量扫描条件。")

处理完目标文件后，文件失败或脏工作区会阻止基线推进；`only` 模式既不保存同步状态，也不重建关系。非 `only` 模式无论本次文件选择是全量、增量还是空集合，都会尝试关系重建；关系异常仅追加 warning，随后仍保存结果并正常返回。此前“完整扫描后才构建关系”的限定因此被替代。[关系重建、警告与基线推进 ↗](../../../apps/server/src/review/sync.ts#L974 "支持每次非 only 同步在文件处理后尝试关系构建、异常转 warning、失败或脏状态阻止基线推进，以及结果继续持久化返回。")

<a id="relations-and-limits"></a>
## 人工关系构建与未确认边界

关系由人工 association seed 驱动：每条 seed 先生成稳定身份的派生意图片段，再建立代码到意图以及意图到需求、决策、调研、测试材料的边；无法解析的端点记为 missing，被删除的 seed 会失效。关系不是由语义相似度自动确认。[人工关系图构建流程 ↗](../../../apps/server/src/review/sync.ts#L682 "支持派生意图索引、确定性 seed 身份、各类关系边、missing 端点和已删除 seed 失效的完整流程。")

代码符号定位优先匹配声明或方法行，但失败后会退化为首个普通词元命中的片段；只要代码端和意图端均存在，关系状态便沿用 seed.status。因此调用点、注释或同名符号可能成为端点，现有材料不足以证明这类退化命中应当形成 confirmed 关系。[符号定位的普通词元退化 ↗](../../../apps/server/src/review/sync.ts#L581 "支持符号定位先匹配声明或方法、失败后选取首个普通词元命中这一未消歧边界。")

association 文件不存在时返回空列表；JSON 损坏或缺少 `associations` 数组时抛错。该异常会在同步层转为 relation-build warning，但材料没有展示 API、任务状态、重试或覆盖记录如何解释这种结果。[Association 加载失败语义 ↗](../../../apps/server/src/review/associations.ts#L55 "支持文件缺失返回空列表，以及 JSON 损坏或缺少 associations 数组时抛错。") [关系重建、警告与基线推进 ↗](../../../apps/server/src/review/sync.ts#L974 "支持每次非 only 同步在文件处理后尝试关系构建、异常转 warning、失败或脏状态阻止基线推进，以及结果继续持久化返回。")
