# 评审模型配置的显式加载边界

集中确定 repo-review 的模型配置来源、无模型默认值和错误报告策略，并把经过基础结构筛选的配置交给通用模型端口构造器。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="source"></a>
## 配置来源与默认行为

评审模型只从显式环境变量路径或仓库内 `config/review-code-model.json` 读取；环境变量优先，仓库配置不存在时返回无配置。缺少配置被视为正常的“无模型”状态，因此启动本身不会被迫依赖生成式模型，也不会回退读取个人 profile 或秘密。[评审模型配置路径 ↗](../../../apps/server/src/review/model-config.ts#L1 "支持环境变量覆盖、仓库配置回退以及缺失配置代表无模型的说明。")

<a id="validation"></a>
## 解析、校验与端口构造

加载器区分“没有配置”和“明确配置损坏”：前者返回 `transport: none`，后者在不可读、JSON 非法或 transport 不受支持时抛出 `CodeModelUnavailableError`，避免拼写错误被静默吞掉。允许的传输仅为 none、ACP、CLI、HTTP，其余预算、命令、模型、effort、超时和端点字段被转交给通用构造器。[配置解析与传输白名单 ↗](../../../apps/server/src/review/model-config.ts#L22 "支持损坏配置显式报错、允许的 transport 以及传递配置字段的说明。")

本文件只做来源选择和传输类型的浅层检查；模型与 effort 是否受实际后端支持，以及命令参数是否可执行，应由 `buildUnderstandingModelPort` 及其下游能力发现负责，当前材料没有展示该实现。[通用模型端口构造 ↗](../../../apps/server/src/review/model-config.ts#L65 "表明本模块最终依赖通用 understanding model 端口构造器，能力校验细节不在本材料内。")
