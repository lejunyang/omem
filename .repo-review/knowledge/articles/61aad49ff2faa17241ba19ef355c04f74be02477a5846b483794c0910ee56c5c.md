# 评审代码模型配置入口

该模块把仓库级显式配置转换为代码理解模型端口：支持环境变量覆盖与仓库默认路径，在未配置时安全返回无模型状态，对显式但损坏的配置立即报错，并将经过基础校验的传输参数交给通用模型适配层。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决的问题与配置边界

该文件为 repo-review 提供单一、可追踪的模型配置入口，避免隐式读取个人 Agent 配置或凭据。路径解析优先采用 `REVIEW_CODE_MODEL_CONFIG`，否则在 `REVIEW_REPO_ROOT` 或当前目录下寻找仓库内的 `config/review-code-model.json`；默认文件不存在时返回未配置，而不是启动模型。[评审模型配置路径规则 ↗](../../../apps/server/src/review/model-config.ts#L1 "支持附近关于环境变量优先级、仓库默认配置路径以及缺失配置不启用模型的说明。") 这与通用代码理解端口的原则一致：模型默认不可用，只有宿主显式传入传输配置后才运行，适配层自身不读取环境变量或主动发起推理。[代码理解模型端口的显式启用原则 ↗](../../../apps/server/src/code/understanding-model.ts#L1 "说明通用模型适配层默认不运行模型，也不会自行读取环境或凭据。")

<a id="loading"></a>
## 加载、校验与失败语义

加载流程先把缺失路径映射为 `transport: "none"`，使无模型成为正常状态。若路径已明确给出，则读取失败、JSON 语法错误或未知 transport 都抛出 `CodeModelUnavailableError`，从而区分“没有配置”和“配置损坏”。[配置加载与错误处理 ↗](../../../apps/server/src/review/model-config.ts#L20 "支持无配置返回 none，以及读取失败、JSON 错误和不支持 transport 时显式报错的流程。") 当前基础校验只限定 transport 为 `none/acp/cli/http`，其余预算、命令、模型、effort、超时和 endpoint 字段按原值透传；不同 transport 所需字段的进一步检查属于下游端口构建逻辑，例如通用模块通过 `requireField` 要求非空字符串。[传输配置字段要求 ↗](../../../apps/server/src/code/understanding-model.ts#L24 "支持配置字段由通用类型承载、部分必填字段在下游通过 requireField 进一步校验的论断。")

<a id="integration"></a>
## 与模型适配层的关系及限制

`buildReviewCodeModel` 组合路径解析、配置加载与 `buildUnderstandingModelPort`，最终返回可运行端口或 `null`，因此本模块负责配置边界，不负责执行推理。[模型端口构建入口 ↗](../../../apps/server/src/review/model-config.ts#L51 "说明该模块将加载后的配置交给通用构建器，并以端口或 null 作为结果。") 配置类型还承载生成预算，并约定 ACP、CLI 与 HTTP 的模型标识、命令、超时和端点；模型身份应来自显式配置或传输响应，不能把 seed 结果伪装成模型产物。[模型配置类型与来源约束 ↗](../../../apps/server/src/code/understanding-model.ts#L11 "支持预算和各传输参数的字段范围，以及模型标识不得凭空生成的边界。") 现有材料未展示端口构建函数后半段，因而无法确认各 transport 的全部运行时校验、effort 能力发现及错误映射细节。
