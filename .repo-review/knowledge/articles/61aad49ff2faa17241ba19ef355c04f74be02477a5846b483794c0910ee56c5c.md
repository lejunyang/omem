# 评审代码模型配置入口

为 repo-review 从项目级 JSON 显式装配代码理解模型；默认无模型，区分“未配置”与“配置损坏”，并避免读取个人配置或在启动时隐式推理。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 配置边界与默认行为

该模块负责为评审环境选择项目级模型配置：优先使用 `REVIEW_CODE_MODEL_CONFIG` 指定的文件，否则查找评审仓库中的 `config/review-code-model.json`；两者都不存在时进入无模型状态。它不借用个人 Agent profile 或秘密，配置存在也只代表显式生成可用，不会在启动时自动推理。[评审模型配置约束 ↗](../../../apps/server/src/review/model-config.ts#L1 "支持项目配置优先、缺省无模型、不得读取个人配置以及不会在启动时自动推理的说明。")

职责与代码理解模型端口保持分离：本模块定位并解析配置，底层端口才适配 ACP、CLI 或显式 HTTP 服务。端口本身也声明不会自行读取环境凭据、个人秘密或主动发起推理。[代码理解模型端口边界 ↗](../../../apps/server/src/code/understanding-model.ts#L1 "说明底层端口只适配显式选择的传输，不自行读取秘密或执行推理。")

<a id="flow"></a>
## 加载、校验与失败方式

加载器同步读取 UTF-8 JSON。没有配置路径时返回 `transport: "none"`；明确指定的文件不可读、JSON 无效或 transport 不属于 `none/acp/cli/http` 时，则抛出 `CodeModelUnavailableError`，让部署和拼写错误保持可见。预算、命令、参数、model、effort、超时与 endpoint 等已知字段随后被原样整理。[配置解析与错误处理 ↗](../../../apps/server/src/review/model-config.ts#L20 "支持缺省返回、文件读取、JSON 解析、transport 枚举校验及字段铺开的流程。")

`buildReviewCodeModel` 把整理后的配置交给 `buildUnderstandingModelPort`，构建结果允许为空，因此人工 seed 和原始代码图不依赖模型。已提供的下游实现还能确认 ACP、CLI 配置必须包含非空 `command`；当前材料不足以进一步断言 HTTP endpoint 校验、模型能力发现或 effort 兼容性检查。[模型端口构建入口 ↗](../../../apps/server/src/review/model-config.ts#L65 "证明解析后的项目配置被交给代码理解端口，并且构建结果允许为空。")[ACP 与 CLI 命令要求 ↗](../../../apps/server/src/code/understanding-model.ts#L52 "支持下游对 ACP、CLI 的非空 command 字段进行检查；该引用不扩展为 HTTP endpoint 或能力发现结论。")
