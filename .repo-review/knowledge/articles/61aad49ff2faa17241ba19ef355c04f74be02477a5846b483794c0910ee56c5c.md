# 评审代码模型配置入口

从项目级 JSON 显式装配代码理解模型；默认无模型，区分未配置与配置损坏，且本文件只确认传输枚举，不证明模型能力兼容性。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 配置边界与默认行为

该模块为 repo-review 选择独立的模型配置：环境变量 `REVIEW_CODE_MODEL_CONFIG` 优先，否则在评审仓库根目录寻找 `config/review-code-model.json`；两者都没有时不启用模型。文件注释同时声明不读取个人 profile 或秘密，配置存在也只允许后续显式生成，不会在启动时自动推理。[评审模型配置边界 ↗](../../../apps/server/src/review/model-config.ts#L1 "支持项目配置查找顺序、缺省无模型、不读取个人配置以及启动不自动推理的论断。")

<a id="flow"></a>
## 加载、校验与装配

加载器同步读取 UTF-8 JSON。缺少配置路径会返回 `transport: "none"`；但已指定文件不可读、JSON 无效或 transport 不属于 `none/acp/cli/http` 时，会抛出 `CodeModelUnavailableError`。通过枚举检查后，预算、命令、参数、model、effort、超时和 endpoint 等字段被原样整理。[配置读取与基础校验 ↗](../../../apps/server/src/review/model-config.ts#L20 "支持缺省返回、文件与 JSON 错误处理、transport 枚举检查及已知字段铺开的流程。")

`buildReviewCodeModel` 再把该配置交给 `buildUnderstandingModelPort`，其返回值允许为空。此前“传输专属必填项均由下游检查”的宽泛结论已被替代：现有材料只能证明调用发生，不能确认 CLI 命令、HTTP endpoint、模型能力发现或 effort 兼容性如何校验。[模型端口构建入口 ↗](../../../apps/server/src/review/model-config.ts#L65 "仅证明加载后的配置被传入代码理解端口，并支持对下游校验能力保持审慎。")
