# 中文候选段落的离线交叉编码重排

把检索问题与候选段落成对送入锁定的 BGE 序列分类模型，输出稳定、可追踪的相关性分数；本模块只负责模型可信加载和批量评分，候选召回、融合、阈值与降级由检索调用层处理。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-contract"></a>
## 解决什么问题

词法或向量召回先找到一批“可能相关”的材料，但它们未必真正回答问题。这个适配器让 BGE cross-encoder **同时阅读一个查询和一段候选文本**，为每段返回一个分数，使上层能重新排序候选。它对外只暴露模型身份、`score(query, passages)` 和 `close()`：不负责召回候选，也不决定最终展示多少条。参考 [重排模型公共契约 ↗](../../../apps/server/src/retrieval/reranker.ts#L1 "支持本模块的职责边界：模型提供身份、成对评分和关闭能力。")

跨文件核对显示，配置工厂和知识调查运行时会按需创建它，统一检索在候选融合后调用评分，再把结果与原有分数结合；因此这里是可替换的模型边界，而不是第二套检索入口。

<a id="load-and-score"></a>
## 从模型别名到候选分数

代表性调用是：上层传入问题“海边度假怎么去？”及若干候选段落。加载阶段先向 osdk 查询别名对应的本地快照，只接受代码登记的仓库与固定 revision；随后逐个校验配置、分词器和量化 ONNX 文件的 SHA-256。任一仓库、版本或文件摘要不符都会直接拒绝加载。参考 [支持的锁定快照 ↗](../../../apps/server/src/retrieval/reranker.ts#L13 "支持只接受两个登记仓库及其固定 revision，并列出需要校验的模型文件。") [别名解析与摘要校验 ↗](../../../apps/server/src/retrieval/reranker.ts#L31 "说明加载器如何从 osdk 获取本地快照，并在仓库、revision 或文件摘要不符时拒绝加载。")

```mermaid
flowchart LR
  A[问题与候选段落] --> B[本地分词器成对编码]
  B --> C[q8 CPU 序列分类]
  C --> D[logit 温度缩放与 sigmoid]
  D --> E[与候选等长的分数数组]
```

模型与分词器都从已校验的快照路径加载，明确关闭远程模型和文件系统缓存，并限定为本地 q8、CPU 推理。参考 [离线量化模型加载 ↗](../../../apps/server/src/retrieval/reranker.ts#L61 "支持禁止远程模型、仅从本地路径加载，以及 q8 CPU 推理参数。") 评分时每批最多 4 段，同一查询复制为每个文本对；输入统一 padding、截断到 512 token，首个 logit 经 `sigmoid(logit / 3)` 变成 0 到 1 的排序分数。参考 [串行成对批量评分 ↗](../../../apps/server/src/retrieval/reranker.ts#L78 "支持模型身份、串行队列、四段批次、512 token 截断、logit 变换及输出完整性检查，并区分身份标记与未编码的批量大小。")

<a id="boundaries-and-lifecycle"></a>
## 并发、错误与生命周期边界

所有评分调用通过一条 Promise 链串行执行，避免多个 CPU 推理互相争抢，也降低长输入批次 padding 的开销。某次评分失败后，链上的 `catch` 会吞掉仅用于排队的拒绝状态，所以后续调用仍可继续；但当前调用仍收到原始错误。空候选自然得到空数组，非有限 logit 或输出数量与输入段落数不一致则抛错。参考 [串行成对批量评分 ↗](../../../apps/server/src/retrieval/reranker.ts#L78 "支持模型身份、串行队列、四段批次、512 token 截断、logit 变换及输出完整性检查，并区分身份标记与未编码的批量大小。")

`close()` 会先等待已排队工作结束，再释放模型，适合由上层检索服务统一关停。参考 [模型资源释放 ↗](../../../apps/server/src/retrieval/reranker.ts#L115 "支持关闭时等待排队评分完成并释放底层模型。") 生成的 `id` 包含模型标签、`q8-pair512-temp3-v1` 参数标记和已校验文件摘要，因此 512 token 截断与温度 3 有明确身份标记。每批最多 4 段只是当前推理实现参数，并未编码进 `id`；若调整批量大小被认为会影响结果的可复现性，需要人工同步升级身份版本。这里的 sigmoid 值用于排序，不能解释成经过业务校准的正确率。参考 [串行成对批量评分 ↗](../../../apps/server/src/retrieval/reranker.ts#L78 "支持模型身份、串行队列、四段批次、512 token 截断、logit 变换及输出完整性检查，并区分身份标记与未编码的批量大小。")
