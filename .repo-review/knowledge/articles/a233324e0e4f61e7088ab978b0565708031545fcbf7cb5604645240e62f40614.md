# 离线 BGE 交叉编码重排评分器

该材料实现一个面向中英文检索候选的本地交叉编码评分器：验证 osdk 管理的锁定模型快照，加载 CPU q8 ONNX 模型，把长段落切成符合查询配对 token 上限的重叠窗口，并以可取消、有截止时间的串行小批次返回相关度分数。它只提供窗口化和评分能力，最终候选排序由调用方完成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_contract"></a>
## 为检索候选补充成对相关度

该模块用 BGE 中英文交叉编码器同时读取查询与候选段落，为上游召回结果补充语义相关度。`RerankerModel` 暴露稳定的模型身份，以及长文本分窗、批量评分和资源释放接口。`score` 返回与 `passages` 顺序对应的数值数组；接口中没有候选排序或分数融合方法，因此这些工作由消费该接口的检索流程负责。参考 [评分器接口边界 ↗](../../../apps/server/src/retrieval/reranker.ts#L2 "支持该模块以模型身份、分窗、评分和关闭四类能力向检索流程提供服务，并说明接口本身不包含排序方法。")、[批量推理与分数转换 ↗](../../../apps/server/src/retrieval/reranker.ts#L100 "支持实例内串行小批次、输入顺序对应的输出数组、取消和截止检查、禁止截断、logit 转换及输出校验。")

<a id="trusted_local_loading"></a>
## 从受控快照加载本地模型

代表性初始化调用是 `loadChineseReranker()`。它默认解析 `relevance-zh` 别名；非开发检出环境会把工作目录切到模型工作区，再通过 `osdk model show ... --json` 取得快照位置。仓库名或 revision 不在内置白名单时，加载立即失败。参考 [快照解析与版本锁定 ↗](../../../apps/server/src/retrieval/reranker.ts#L52 "支持默认别名、工作目录选择、osdk 快照查询以及仓库和 revision 白名单校验。")

随后，加载器逐个读取配置、tokenizer 与量化 ONNX 文件，用 SHA-256 对照快照清单。校验通过后才动态加载 Transformers，并禁止远程模型，限定从本地路径以 CPU、q8 和两个推理线程初始化。参考 [文件校验与离线加载 ↗](../../../apps/server/src/retrieval/reranker.ts#L45 "支持关键文件清单、哈希校验、禁止远程模型以及 CPU q8 推理参数。")

返回对象的 `id` 由模型标签、推理参数标识和关键文件哈希共同组成，调用方可以据此区分实际加载的模型资产。参考 [模型身份生成 ↗](../../../apps/server/src/retrieval/reranker.ts#L75 "支持返回模型身份包含标签、推理配置标识和关键文件哈希。")

<a id="windowing_and_scoring"></a>
## 长文本分窗与串行评分

一次典型使用先调用 `windows(query, passage)`。分窗函数保留原字符，用已安装 tokenizer 计算查询与片段的配对长度，再以二分查找取每个不超过 512 token 的最长窗口；相邻窗口通常最多回退 32 个字符，并保证至少前进 1 个字符，避免边界内容完全割裂。空段落返回一个空窗口。查询本身已占满预算，或连一个段落字符也放不下时，会直接报错。参考 [配对 token 分窗 ↗](../../../apps/server/src/retrieval/reranker.ts#L15 "支持按 tokenizer 配对长度二分取窗、窗口通常最多回退 32 个字符且至少前进 1 个字符、空输入行为和无可用预算时的错误。")

```mermaid
flowchart LR
  A[查询与候选段落] --> B[按配对 token 长度分窗]
  B --> C[每 4 条组成批次]
  C --> D[CPU 交叉编码推理]
  D --> E[logit 经温度 3 的 sigmoid]
  E --> F[同序相关度数组]
```
同一模型实例的评分请求进入串行队列，每批最多 4 条。每批开始前检查取消信号与截止时间，并拒绝超过 512 token 的配对输入；tokenizer 明确关闭截断，因此不会静默丢掉尾部。模型输出的首个 logit 经 `1 / (1 + exp(-logit / 3))` 转成 0 到 1 之间的分数，同时检查有限值和结果数量。参考 [批量推理与分数转换 ↗](../../../apps/server/src/retrieval/reranker.ts#L100 "支持实例内串行小批次、输入顺序对应的输出数组、取消和截止检查、禁止截断、logit 转换及输出校验。")

某次评分失败不会阻塞后续队列，但当前调用仍收到原错误。`close()` 会等待已排队工作结束，再释放模型。参考 [错误隔离与资源释放 ↗](../../../apps/server/src/retrieval/reranker.ts#L141 "支持失败后继续维护串行队列，以及关闭时等待队列并释放模型。")
