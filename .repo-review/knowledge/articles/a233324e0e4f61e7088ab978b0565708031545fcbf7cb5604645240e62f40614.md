# 本地中英文交叉编码重排器

把检索问题与候选段落成对送入锁定的 BGE cross-encoder，在本地 CPU 上生成可追踪的相关性分数；说明其按配置接入查询链、离线装载、评分流程、成对截断边界与资源生命周期。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-contract"></a>
## 为什么在召回之后再判断一次

词法与向量检索先找出一批候选，但“主题相近”不一定“能回答当前问题”。这个文件封装 BGE 中英文交叉编码器，让模型同时读取一个查询和每个候选段落，再返回与输入段落一一对应的分数。对上游只暴露 `id`、`score(query, passages)` 与 `close()`，因此候选生成和最终排序仍由检索模块负责，重排器专注于成对相关性判断。参考 [重排器接口 ↗](../../../apps/server/src/retrieval/reranker.ts#L1 "说明交叉编码器的用途，以及上游只依赖模型身份、批量评分和关闭三个能力。")

普通检索工厂只有在语义检索已启用且配置含 `reranker` 别名时，才把延迟加载函数交给 `SemanticRetrieval`；否则使用纯关键词检索，或使用不带重排器的语义检索。参考 [检索工厂配置 ↗](../../../apps/server/src/retrieval/factory.ts#L10 "支持语义检索和重排器按配置启用、未配置重排别名时不注入加载器的说明。") 知识调查工作区采用同样的可选注入方式，其默认配置只启用 `memory-zh` 向量模型，不默认启用重排器。参考 [调查工作区检索配置 ↗](../../../apps/server/src/knowledge/agent-research.ts#L169 "支持知识调查工作区的默认向量配置，以及重排器同样按可选别名注入的说明。")

重排发生在查询阶段：词法与向量候选融合后，最多取前 40 项交给交叉编码器，再把交叉编码分数与原候选分数结合。这条路径只读取候选及标题，不写入向量索引，因此开启重排本身不要求重建已有向量。参考 [查询阶段候选重排 ↗](../../../apps/server/src/retrieval/semantic.ts#L127 "说明重排发生在候选融合后的查询阶段，最多处理前 40 项，并与原候选分数混合后进入最终排序。")

<a id="load-and-score"></a>
## 一次代表性评分如何完成

以 `score("如何到岛上", [段落甲, 段落乙])` 为例，调用前先由 `loadChineseReranker` 完成装载。它调用 `osdk model show` 解析本地快照，并要求仓库名与固定 revision 完全一致；不匹配就立即失败。参考 [锁定快照检查 ↗](../../../apps/server/src/retrieval/reranker.ts#L21 "支持通过 osdk 查询本地模型，并严格校验仓库和固定 revision 的装载流程。")

随后实现逐个读取配置、分词器和量化 ONNX 权重，核对清单中的 SHA-256；Transformers.js 被禁止远程取模和文件缓存，只从快照目录加载 q8、CPU 模型。模型身份还包含这些文件哈希，权重变化会形成不同的可观察身份。参考 [文件校验与离线加载 ↗](../../../apps/server/src/retrieval/reranker.ts#L45 "支持逐文件哈希校验、禁用远程模型和文件缓存，以及使用本地 q8 CPU 模型的说明。")

```mermaid
flowchart LR
  Q[查询 + 候选段落] --> B[每 4 段组成一批]
  B --> T[成对编码，总长最多 512 token]
  T --> M[本地 cross-encoder 推理]
  M --> S[logit 转为 0 到 1 分数]
```

评分请求按队列串行执行；每批复制同一查询，与最多四个段落组成 `text_pair`，统一 padding，并把成对编码的总长度限制为 512 token。参考 [串行成对编码 ↗](../../../apps/server/src/retrieval/reranker.ts#L70 "支持评分请求串行、四段一批、query-passage 成对编码，以及 512 token 总长度截断的流程。") 输出的每个首位 logit 经 `sigmoid(logit / 3)` 压缩后，按原段落顺序返回。参考 [分数转换与异常检查 ↗](../../../apps/server/src/retrieval/reranker.ts#L90 "支持模型推理、logit 有效性检查、温度缩放 sigmoid、长度一致性和失败后队列恢复。")

<a id="boundaries-and-lifecycle"></a>
## 边界、失败处理与修改入口

512-token 上限覆盖查询、段落及特殊 token 组成的完整编码序列，并不是每个段落单独拥有 512 token；过长输入由 tokenizer 按成对截断策略处理，因此段落尾部证据可能丢失。参考 [串行成对编码 ↗](../../../apps/server/src/retrieval/reranker.ts#L70 "支持评分请求串行、四段一批、query-passage 成对编码，以及 512 token 总长度截断的流程。")

实现会拒绝缺失或非有限的 logit，也会检查结果数是否等于段落数。任何一批失败都会让当前 `score` 拒绝，但内部队列用已捕获的 Promise 继续承接后续请求，避免一次失败永久堵住评分器；空段落数组则自然返回空数组。参考 [分数转换与异常检查 ↗](../../../apps/server/src/retrieval/reranker.ts#L90 "支持模型推理、logit 有效性检查、温度缩放 sigmoid、长度一致性和失败后队列恢复。")

关闭时先等待已排队评分结束，再释放底层模型，避免推理中途销毁资源。参考 [安全释放模型 ↗](../../../apps/server/src/retrieval/reranker.ts#L106 "支持关闭时等待串行任务完成后再释放底层模型资源。") 若要调整吞吐量、最大编码长度或分数温度，入口分别是批大小 `4`、`max_length: 512` 与除数 `3`；这些改动会影响延迟、截断或分数分布，还需连同查询阶段的候选阈值和混合权重评估。模型仓库、revision 或文件集合变化则要同步更新锁定声明与校验，否则加载会按设计失败。参考 [锁定快照检查 ↗](../../../apps/server/src/retrieval/reranker.ts#L21 "支持通过 osdk 查询本地模型，并严格校验仓库和固定 revision 的装载流程。") [文件校验与离线加载 ↗](../../../apps/server/src/retrieval/reranker.ts#L45 "支持逐文件哈希校验、禁用远程模型和文件缓存，以及使用本地 q8 CPU 模型的说明。") [查询阶段候选重排 ↗](../../../apps/server/src/retrieval/semantic.ts#L127 "说明重排发生在候选融合后的查询阶段，最多处理前 40 项，并与原候选分数混合后进入最终排序。")
