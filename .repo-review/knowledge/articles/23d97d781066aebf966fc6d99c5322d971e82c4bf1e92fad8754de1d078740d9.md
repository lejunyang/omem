# 代码与意图的人工关联种子

该文件是 repo-review 中代码符号与需求、决策、研究及测试锚点的人工维护清单，包含 confirmed 与 candidate 状态；它记录治理关系和维护者证据，不等同于对当前代码重新执行测试后的实时证明。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="governance-contract"></a>
## 人工治理合同

清单要求关联点名代码路径、符号、需求、决策或研究资料及测试，并禁止用词面相似度将关系自动提升为 confirmed。首项把主助手运行时关联到会话路由、检索注入、任务治理和恢复测试，体现其连接“实现位置—设计意图—验证锚点”的用途。[关联治理说明与主运行时条目 ↗](../../../docs/repo-review/associations.json#L1 "说明 confirmed 关联所需的具体文档和测试锚点，并展示主运行时条目的组织方式。")

<a id="status-semantics"></a>
## 状态不等于一律完成

条目必须逐项按状态理解：来源刷新被标为 candidate，证据说明当前只记录刷新影响后抛出未实现错误，完整 consolidation 重跑仍待实现。因此不能依据文件中大量 confirmed 条目，笼统宣称清单覆盖的所有能力都已完成。[来源刷新候选条目 ↗](../../../docs/repo-review/associations.json#L171 "支持附近关于 candidate 状态、当前失败行为以及完整重核验尚未实现的限制说明。")

<a id="review-sync-link"></a>
## 与仓库同步的关系

同步条目描述路径身份、revision 追加、removed/dirty 标记和测试锚点，并声明关系在扫描后由人工清单构建。它提供同步设计的可追踪依据，但仍是维护快照；代码变化后需重新同步，并以实际检查结果确认当前状态。[仓库评审同步关联 ↗](../../../docs/repo-review/associations.json#L289 "说明同步的路径身份与版本策略，以及关系由人工关联清单构建这一边界。")
