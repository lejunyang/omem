# AttentionGate 与按需知识整合的行为测试

该测试用临时 SQLite Store 组装 MemoryService 与关键词检索，验证证据不足、重复、冲突、来源修订和批量影响预算下的分流。它证明超预算 ChangeSet 在正常调用路径中被整体门控，但不覆盖真实模型判断、异常回滚、并发竞争或重试幂等性。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_fixture"></a>
## 测试目标与隔离夹具

每个场景使用独立临时目录和 `Store`，结束后关闭数据库并递归清理目录，避免用例状态相互污染。[临时数据库清理夹具 ↗](../../../apps/server/tests/attention-gate.test.ts#L11 "支持每个测试使用临时目录，并在结束后关闭 Store、删除测试数据的隔离说明。") `setup` 将自动应用上限设为 10，并装配 SQLite 关键词检索器；辅助函数捕获带 actor、事件时间及时区的 revision，以首个 fragment 构造 Unicode code point selector、固定作用域 claim，并注入确定性的 verifier assessment。[捕获辅助函数与服务装配 ↗](../../../apps/server/tests/attention-gate.test.ts#L25 "支持 actor、事件时间、证据 selector、确定性评估、自动应用上限及检索器装配的说明。") 因此，这组测试关注门控消费既定评估后的行为，不代表真实 Agent 或 ACP verifier 的判断质量。

<a id="routing_conflicts"></a>
## 延迟、重复与冲突分流

提议同时包含 `scope_unknown` 且评估为 `insufficient` 时，结果为 `defer_until_use`：既不生成决策卡，也不形成活跃记忆，但原始来源仍可通过关键词检索找到。[未知作用域与证据不足场景 ↗](../../../apps/server/tests/attention-gate.test.ts#L117 "证明证据不足的未知作用域提议被延迟，不生成决策或活跃记忆，而原始来源仍可检索。") 跨来源 supersede 活跃知识时则进入 `awaiting_decision`，原记忆仍保持版本 1 和活跃状态，避免静默覆盖。[跨来源覆盖保护 ↗](../../../apps/server/tests/attention-gate.test.ts#L135 "证明跨来源 supersede 活跃知识会等待决策，既有记忆不会被静默覆盖。")

相关用例还区分重复与冲突：同一来源证据、相同陈述但新 proposal id 会链接既有记忆，不增加活跃行；相反陈述不会自动提升，原记忆保持活跃，双方陈述被写入争议表，且以“重试”为查询词时相关原始来源仍有可检索结果。该断言只证明至少存在一个命中，并未逐一确认冲突双方都出现在结果中。[重复链接与相反陈述争议 ↗](../../../apps/server/tests/attention-gate.test.ts#L165 "支持重复陈述链接既有记忆，以及相反陈述保留原活跃记忆、记录双方陈述并仅以结果非空验证相关来源检索的论断。") 非活跃且不阻塞当前任务的跨来源冲突被延迟；只有阻塞当前任务时才生成包含问题、选项、尝试解决过程和关联目标的 AttentionCase。[任务相关性驱动的冲突策略 ↗](../../../apps/server/tests/attention-gate.test.ts#L290 "支持不阻塞任务的冲突被延迟，而阻塞冲突生成带上下文 AttentionCase 的分流。")

<a id="refresh_impact"></a>
## 来源刷新与影响面门控

同一 externalId 产生新 revision 后，刷新记录被置为 `needs_review`；用例通过服务返回与直接 SQL 分别核对受影响记忆、数量和刷新表状态，并确认旧记忆已退出活跃检索。该状态仅表示需要复核，不能视作 extractor 与独立 verifier 已完成。[来源修订后的待复核记录 ↗](../../../apps/server/tests/attention-gate.test.ts#L209 "证明刷新记录进入 needs_review，持久化影响数量和状态，并使旧记忆退出活跃检索；不代表复核已经完成。")

影响面门控不要求调用方显式传入数量：在一个来源已支撑十一条活跃记忆的布置下，对其中一个目标执行同源 supersede 会触发 `impact_limit_exceeded` 并请求决策；测试没有直接断言服务计算出的具体影响数或实体集合。[未显式传入影响数量时的门控 ↗](../../../apps/server/tests/attention-gate.test.ts#L265 "支持十一条同源活跃记忆的测试布置，以及调用方未传影响数量时仍触发超预算门控；该范围不证明服务返回的具体影响数。") 批量用例则明确断言十二个独立新增提议的总影响为 12、返回十二个受影响实体，并让全部结果作为一个 ChangeSet 进入 `awaiting_decision`；正常返回路径中没有活跃记忆物化。[超预算批次的整体门控 ↗](../../../apps/server/tests/attention-gate.test.ts#L341 "证明十二个独立提议被合并计算影响、整体延迟，并在一次正常调用路径中未物化活跃记忆；也界定其不支持故障回滚或重试保证。") 整批只生成一张包含所检查关键字段的 AttentionCase，随后另一个预算内单条新增可自动应用且不会增加决策卡。[批量决策卡与预算内应用 ↗](../../../apps/server/tests/attention-gate.test.ts#L371 "支持单次超预算批次生成一张包含已检查字段的 AttentionCase，以及随后预算内单条变更自动应用且不新增决策卡。")

<a id="limits"></a>
## 断言层次与未覆盖边界

这些相关用例同时包含服务层行为断言和直接持久化断言：记忆状态、策略结果及关键词检索主要经服务接口核对，争议表与刷新表则通过 SQL 明确检查。[重复链接与相反陈述争议 ↗](../../../apps/server/tests/attention-gate.test.ts#L165 "支持重复陈述链接既有记忆，以及相反陈述保留原活跃记忆、记录双方陈述并仅以结果非空验证相关来源检索的论断。") [来源修订后的待复核记录 ↗](../../../apps/server/tests/attention-gate.test.ts#L209 "证明刷新记录进入 needs_review，持久化影响数量和状态，并使旧记忆退出活跃检索；不代表复核已经完成。") AttentionCase 仅检查主题、问题、选项、尝试解决、证据引用和去重键等字段的存在性或部分内容，不能等同于依据完整合同逐字段验证。[批量决策卡与预算内应用 ↗](../../../apps/server/tests/attention-gate.test.ts#L371 "支持单次超预算批次生成一张包含已检查字段的 AttentionCase，以及随后预算内单条变更自动应用且不新增决策卡。")

测试环境是同步、单进程、临时 SQLite，评估结果也是预设值。批量场景只证明一次正常调用中整批被门控且未产生活跃记忆，没有注入事务中途故障，也没有重复提交同一 ChangeSet。[超预算批次的整体门控 ↗](../../../apps/server/tests/attention-gate.test.ts#L341 "证明十二个独立提议被合并计算影响、整体延迟，并在一次正常调用路径中未物化活跃记忆；也界定其不支持故障回滚或重试保证。") 因而尚不能推出异常回滚、并发唯一约束、跨进程一致性、重试幂等性或决策文案的语义质量。
