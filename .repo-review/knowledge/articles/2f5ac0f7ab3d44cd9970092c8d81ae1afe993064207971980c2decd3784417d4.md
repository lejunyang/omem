# 注意力门禁与按需知识整合测试

验证知识提案按证据充分性、冲突、来源更新、任务阻塞性和影响规模在自动应用、延后与请求决策之间分流，并覆盖批量超限时的零物化边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="defer-conflict"></a>
## 延后、冲突与去重

当夹具同时给出 `scope_unknown` 和 `semantic_verdict: insufficient` 时，策略为 `defer_until_use`：不生成决策卡、不提升活跃知识，但原始来源仍可检索；该用例没有单独验证“仅缺少时间”会得到相同结果。同源重复陈述链接既有 memory，不新增活跃行；相反且均受支持的陈述记录 dispute 而不覆盖。跨来源 supersede 若改写活跃知识，则等待用户决策。[不确定作用域材料延后 ↗](../../../apps/server/tests/attention-gate.test.ts#L117 "支持 `scope_unknown` 加证据不足时延后、保持可检索且不生成决策卡；不支持单独推断时间缺失行为。") [跨来源覆盖需决策 ↗](../../../apps/server/tests/attention-gate.test.ts#L135 "支持活跃知识不会被跨来源 supersede 静默覆盖，并产生上下文化决策记录。") [重复与争议处理 ↗](../../../apps/server/tests/attention-gate.test.ts#L165 "支持同源重复链接既有知识，以及相反主张记录 dispute 而不自动提升。")

<a id="refresh-impact"></a>
## 来源更新与影响计算

来源 revision 前进后，`recordSourceRefresh` 记录受影响 memory 和 `needs_review`，并明确返回 `blocked/not_implemented`，因此不能声称已完成复核；失效 memory 随即退出活跃检索。单项 supersede 即使未传 impactCount，也会按同一来源的真实依赖数量计算波及面，超过阈值便进入决策门禁。[来源刷新失效链 ↗](../../../apps/server/tests/attention-gate.test.ts#L209 "支持记录受影响知识、明确标记重验证未实现，并将失效 memory 移出活跃检索。") [真实波及面门禁 ↗](../../../apps/server/tests/attention-gate.test.ts#L266 "支持调用方未提供 impactCount 时由服务计算依赖数量，并对超限变更设置门禁。")

<a id="attention-policy"></a>
## 只在必要时打扰

跨来源冲突若目标知识已非活跃且不阻塞当前任务，会延后而不生成卡片；若冲突正在阻塞，则生成包含问题、选项、尝试解决过程和关联目标的 AttentionCase。测试体现的核心策略是：冲突本身不必然打扰用户，是否阻塞当前工作会改变分流结果。[阻塞感知的注意力策略 ↗](../../../apps/server/tests/attention-gate.test.ts#L291 "支持非阻塞冲突延后，以及阻塞冲突生成完整 AttentionCase 的分流。")

<a id="batch-gate"></a>
## 批量超限与零物化

`evaluateBatch` 汇总 12 个独立新实体的去重影响，超过自动应用上限后将整批标为 `awaiting_decision`，所有结果均为 batch deferred，并只生成一张汇总 AttentionCase。测试通过 SQL 明确断言活跃 memory 数量为零，但没有查询 `application_receipts`，所以只能确认零活跃知识物化，不能把零 receipt 写成已验证事实。随后单个低影响创建可直接 auto-apply，且不会新增决策卡。[批量影响与零活跃知识 ↗](../../../apps/server/tests/attention-gate.test.ts#L342 "支持整批超限时统一等待决策、零活跃 memory 和单张汇总卡；材料未实际查询 application receipts。")
