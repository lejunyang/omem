# 注意力门控与按需知识整合的行为验证

该测试验证记忆提案在信息不足、知识冲突、重复事实、来源更新及大范围变更下的处理策略，重点确保系统只在真正需要用户介入时生成统一决策卡，同时保留原始证据、避免静默覆盖，并保证超预算批次不会部分落库。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="test_setup"></a>
## 从原始证据构造可追溯提案

测试为每个用例创建隔离的临时 SQLite 存储，并在结束后关闭数据库、删除目录，避免状态互相污染。参考 [隔离测试环境 ↗](../../../apps/server/tests/attention-gate.test.ts#L11 "支持每个用例使用临时目录，并在测试后关闭存储和清理文件的说明。")

辅助流程先通过 `Store.capture` 写入带来源、参与者、时间和上下文的文本，再从首个固定片段生成精确证据选择器，最后组装作用域明确的 claim 提案。`MemoryService` 负责评估与应用，`KeywordRetrieval` 用于检查原始材料或有效记忆是否仍可检索。参考 [提案与服务装配 ↗](../../../apps/server/tests/attention-gate.test.ts#L25 "支持从捕获修订构造证据和提案，以及装配存储、记忆服务和关键词检索的流程。")

<a id="policy_routing"></a>
## 按风险区分自动应用、延后与人工决策

材料缺少时间或作用域且证据不足时，提案被标记为“使用时再处理”：它不会成为活跃记忆或决策卡，但原始来源仍可搜索，说明延后不等于丢弃。参考 [信息不足时延后处理 ↗](../../../apps/server/tests/attention-gate.test.ts#L118 "支持证据不足的材料不生成记忆或决策卡、但仍保留来源检索能力的断言。")

跨来源更新若会覆盖现有活跃知识，则进入等待决策状态，并保留旧版本为活跃状态；决策记录关联被门控的提案摘要，防止冲突被静默覆盖。参考 [跨来源覆盖门控 ↗](../../../apps/server/tests/attention-gate.test.ts#L135 "支持冲突更新进入等待决策、旧知识不被静默覆盖并生成上下文化决策记录的断言。")

同一来源、同一陈述会链接到已有记忆而不新增活跃行；相反陈述则记录为可追溯争议，保留原知识并让双方来源继续可搜索，但非阻塞冲突不会自动打扰用户。参考 [重复链接与争议记录 ↗](../../../apps/server/tests/attention-gate.test.ts#L165 "支持重复事实复用现有记忆，以及相反事实记录争议而不自动生成非阻塞决策卡的说明。")

<a id="refresh_and_impact"></a>
## 来源更新与变更影响控制

来源产生新修订后，刷新记录会列出受影响记忆并标记为待复核，而不会把“已发现影响”冒充“已完成复核”；失效记忆随即退出活跃证据检索。参考 [来源刷新后的失效处理 ↗](../../../apps/server/tests/attention-gate.test.ts#L209 "支持来源修订只登记待复核影响范围，并让失效记忆退出活跃检索的断言。")

门控还会自行计算真实波及范围：即使调用者没有传入影响数量，同一来源牵连十一条记忆的替换仍因超过自动应用预算而生成决策。参考 [自动计算波及范围 ↗](../../../apps/server/tests/attention-gate.test.ts#L265 "支持门控在未提供批次影响值时自行计算依赖数量并拦截超预算替换的说明。")

<a id="batch_and_limits"></a>
## 批次原子性与测试边界

批量评估会对影响实体去重汇总。十二个独立新增超过预算时，整批统一进入等待决策，只产生一个包含问题、选项、尝试解决方案与证据引用的 AttentionCase，且数据库中没有任何活跃记忆被部分写入；预算内的单条新增仍可直接应用。参考 [批量门控与原子应用 ↗](../../../apps/server/tests/attention-gate.test.ts#L341 "支持批次影响汇总、单一决策卡、超预算时零写入以及预算内自动应用的行为断言。")

这些用例使用确定性注入的语义评审结果，因此证明的是门控、持久化和检索之间的行为合同，不代表真实模型或外部 Agent CLI 已完成端到端验证。参考 [确定性评审替身 ↗](../../../apps/server/tests/attention-gate.test.ts#L98 "说明测试直接注入固定的 supported 或 insufficient 评审结果，因此未覆盖真实评审器调用。") 本文件也未断言用户选择决策选项后的应用流程、并发评估、进程重启恢复或数据库故障下的事务行为。
