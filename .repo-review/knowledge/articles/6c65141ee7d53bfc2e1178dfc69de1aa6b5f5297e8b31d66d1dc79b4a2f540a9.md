# 仓库评审前端 API 客户端

该文件是 Web 前端访问 `/api/review/*` 的类型化适配层，覆盖资料浏览、历史版本、检索与同步，以及代码快照、结构图、理解结果和源码切片。它统一请求路径、参数编码与错误转换；现有材料只证明客户端合同与调用行为，不足以断言版本不可变或仓库内不存在其他契约校验。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-contract"></a>
## 职责与数据合同

该模块集中封装仓库评审知识库的前端访问。文件将其界定为绑定 loopback 的读取、浏览与同步表面，并说明它没有 token 门禁，因此不发送个人工作区客户端使用的 `Authorization` 头。[评审 API 的访问边界 ↗](../../../apps/web/src/review-api.ts#L1 "支持客户端面向 loopback 的读取、浏览和同步接口，并且不发送授权头的说明。")

资料域类型覆盖来源、历史版本、片段、检索命中与关系。历史版本包含当前标志、内容哈希及可选 Git 快照信息；此前称其为“不可变版本”的结论已被替代，因为这里仅能证明历史版本可被读取。[来源历史版本合同 ↗](../../../apps/web/src/review-api.ts#L37 "支持历史版本可读字段及可选 Git 快照信息，同时限定不能据此断言版本不可修改。") 关系 DTO 还提供方向、有效状态及关联端当前性，使界面可以解释 `stale`、`missing` 等状态。[片段关系 DTO ↗](../../../apps/web/src/review-api.ts#L112 "说明关系方向、有效状态以及关联端当前性和删除状态如何供界面解释关系。")

<a id="request-flows"></a>
## 请求流程与同步分支

通用 `get`、`post` 在 `/api/review` 前缀下请求并解析 JSON；失败时优先采用服务端 `error`，成功结果则通过 TypeScript 类型断言返回，本文件未在此处执行运行时 schema 校验。[通用 GET 与 POST 封装 ↗](../../../apps/web/src/review-api.ts#L174 "支持统一路径、JSON 解析、错误转换以及成功响应通过类型断言返回的流程。") 来源查询会编码筛选参数，资料同步入口通过 POST 调用 `/sync` 并声明返回 `SyncResult`。[来源查询与同步入口 ↗](../../../apps/web/src/review-api.ts#L194 "支持查询参数编码、POST 调用同步入口及其声明的 SyncResult 返回类型。") `SyncResult` 由扫描、导入、更新、未变、跳过等统计以及最近同步提交和时间组成。[资料同步结果字段 ↗](../../../apps/web/src/review-api.ts#L153 "直接支持同步结果包含扫描、导入、更新、未变、跳过统计及最近同步信息的论断。")

按代码路径查询资料时，404 被转换为 `null`，让追踪界面呈现“没有对应材料”；其他错误仍会抛出。[按代码路径查找资料 ↗](../../../apps/web/src/review-api.ts#L231 "支持将 404 转换为 null、其他失败继续抛出的特殊处理。") 代码知识读取统一追加 `/code`，覆盖快照、结构图、文件、符号、边及文件理解。[代码知识读取入口 ↗](../../../apps/web/src/review-api.ts#L375 "支持代码接口统一添加前缀，以及快照、结构图、文件符号、文件边和理解结果的读取范围。")

<a id="boundaries-and-integration"></a>
## 合同、理解结果与源码读取边界

注释声明代码知识形状镜像共享 contracts 与服务端模块；本文件随后直接声明快照、文件、符号、边和基础理解类型，并通过通用请求函数的类型断言接收响应。[基础代码知识类型声明 ↗](../../../apps/web/src/review-api.ts#L257 "支持镜像共享合同的注释、本地展开的基础 DTO，以及这些 DTO 与通用请求断言之间的实现关系。") 结构化理解合同也在本地展开，包含职责、边界、流程、声明、证据、未知项和复核信息；列表及详情请求返回这些声明的类型。[结构化理解合同与读取接口 ↗](../../../apps/web/src/review-api.ts#L423 "支持理解输出、列表、详情、复核状态、替代关系及解析引用均在本文件中声明并由接口返回。") 因此此前“完全依赖人工同步”或“仓库内不存在自动一致性校验”的结论均被替代：给定材料只能描述本文件的实现，无法排除其他文件中的生成或契约测试。

源码全文读取先请求第 1 行取得 `totalLines`，不超过一行时直接返回，否则再请求完整范围。[源码全文探测流程 ↗](../../../apps/web/src/review-api.ts#L498 "支持先探测总行数、不超过一行直接返回、否则再次读取完整范围的流程。") 这取代了“客户端未处理空文件”的旧结论，但服务端是否接受空文件的第 1 行请求、是否限制全文大小，以及两次请求是否绑定同一快照，仍无法从本材料确认。代码同步另行发送带空 JSON 对象的 POST，并使用英文兜底错误。[代码同步请求 ↗](../../../apps/web/src/review-api.ts#L513 "支持代码同步使用带空 JSON 对象的独立 POST，并采用英文兜底错误文本。")
