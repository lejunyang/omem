# 飞书机器人接入与 owner 配对界面

该 Vue 组件承载飞书应用的新建授权、已有应用更新、凭据导入、能力核验、owner 配对及连接状态展示，并通过轮询把服务端 onboarding 流程映射为可操作界面。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-entry"></a>
## 作用与接入入口

组件提供三条接入路径：创建新应用、授权已有应用和直接导入凭据；导入时还可选择复用本机 botmux 配置或手工输入 App Secret。[接入方式与凭据来源界面 ↗](../../../apps/web/src/LarkSetup.vue#L213 "支持创建、更新、导入三种接入方式，以及导入时选择 botmux 或手工 Secret 的论断。") 初始化会并行读取默认能力配置、已有连接和可复用应用，并用已有 App ID 预填表单。[基础数据初始化 ↗](../../../apps/web/src/LarkSetup.vue#L58 "支持并行加载默认配置、连接和可复用应用，并预填 App ID 的说明。")

提交时，更新与导入模式先校验 `cli_…` 格式；导入调用已有应用接口，仅手工来源携带 Secret，其他模式进入统一 onboarding 接口。Secret 在请求结束后无论成功或失败都会从组件状态清空。[接入提交与 Secret 清理 ↗](../../../apps/web/src/LarkSetup.vue#L94 "支持 App ID 校验、不同模式的请求分流、手工 Secret 传递及 finally 清空敏感字段。") 这取代了旧正文中由初始化引用同时证明接入模式的宽泛表述。

<a id="state-machine"></a>
## 状态推进与配对流程

页面依据 onboarding 状态展示扫码授权、凭据核验、等待 owner 配对、启用成功或失败终态；“收到凭据不等于可用”和 capability probe 的约束目前属于界面呈现的服务端语义。[接入状态展示分支 ↗](../../../apps/web/src/LarkSetup.vue#L314 "支持扫码、核验、配对、成功和失败界面由 onboarding 状态驱动，并限定安全及能力语义为前端呈现。") 非终态每 1.5 秒刷新 onboarding 并重新加载连接，进入终态或卸载时清除定时器。[状态轮询生命周期 ↗](../../../apps/web/src/LarkSetup.vue#L188 "支持非终态定时刷新、终态停止及组件卸载时清理定时器的说明。")

owner 绑定先申请一次性配对码，待状态返回候选 Open ID 后，再提交 pairing ID 与预期 Open ID确认绑定。[owner 配对申请与确认 ↗](../../../apps/web/src/LarkSetup.vue#L150 "支持申请配对码、等待候选 Open ID，并提交配对身份确认的流程。") 旧结论所称“取消、刷新和重新配置都只改变前端流程”已被替代：取消会请求服务端 cancel 接口；刷新会读取服务端状态；只有 reset 明确仅清空本地 onboarding、配对码和 Secret。[取消与本地重置行为 ↗](../../../apps/web/src/LarkSetup.vue#L139 "证明取消会调用服务端接口，而 reset 仅清空组件内的流程和敏感状态，用于替代旧结论。") 失败页也并非始终声明不会删除平台应用，只有服务端未返回错误消息和错误码时才显示该默认说明。[终态默认错误说明与操作入口 ↗](../../../apps/web/src/LarkSetup.vue#L406 "支持“不自动删除平台应用”仅在缺少服务端错误消息和错误码时作为默认文案，并说明刷新、取消与重置按钮的状态条件。")

<a id="relations-and-limits"></a>
## 模块关系与边界

组件依赖 Vue 生命周期、二维码组件、共享 `@omem/ui` 控件及同目录 API 类型，因此自身属于表现与流程编排层，不负责凭据加密、权限探测或事件采集的底层实现。[组件依赖与事件合同 ↗](../../../apps/web/src/LarkSetup.vue#L1 "支持该文件依赖 Vue、共享 UI、二维码组件和本地 API 合同，并通过事件向父组件报告结果。")

错误处理应按调用范围理解：基础数据、状态刷新与连接加载失败会向父组件发出字符串错误；提交、取消、配对码申请和绑定确认也分别在各自异常分支发出错误。[加载与刷新错误分支 ↗](../../../apps/web/src/LarkSetup.vue#L58 "支持基础数据加载、onboarding 刷新和连接加载分别捕获异常并发出字符串错误。")[提交、取消与配对错误分支 ↗](../../../apps/web/src/LarkSetup.vue#L94 "支持接入提交、取消、配对码申请和绑定确认各自在异常分支向父组件报告错误。") 这取代了旧正文仅凭 start 分支概括“所有请求错误”的证据不足说法。窄屏样式把能力摘要改为两列、授权区域改为单列，并限制二维码宽度。[窄屏布局适配 ↗](../../../apps/web/src/LarkSetup.vue#L556 "支持移动端能力摘要、授权区域和二维码尺寸调整的说明。") 当前材料未包含测试或服务端实现，因而不能确认轮询竞态、安全承诺及状态转换是否已有端到端保障。
