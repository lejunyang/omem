# 飞书应用接入与 owner 配对流程

管理新建、更新或导入飞书应用的完整接入状态机，包括授权、权限探测、一次性配对、连接展示及凭据清理。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="entry-modes"></a>
## 三种接入入口与敏感信息边界

组件支持创建新应用、授权已有应用，以及直接导入凭据；导入又可选择复用本机 botmux 配置或手工输入 secret。启动前会校验非新建模式的 App ID 格式，然后按模式调用不同端点，并始终在请求结束后清空 `clientSecret`。[接入启动与凭据清理 ↗](../../../apps/web/src/LarkSetup.vue#L94 "支持模式分流、App ID 校验、不同接入端点以及 secret 清空行为。") 页面只展示可复用应用的名称和 App ID，并声明 secret 不返回浏览器；不过“服务端加密保存、日志不泄露”属于界面表达，单凭此文件不能验证后端实现。[接入方式与凭据说明 ↗](../../../apps/web/src/LarkSetup.vue#L204 "支持三种入口、手工 secret 输入和 botmux 复用时的前端可见范围。")

<a id="state-machine"></a>
## 授权、核验与轮询状态机

接入对象从等待扫码、收到凭据、权限核验推进到等待 owner 配对或终态。非终态期间每 1.5 秒刷新接入状态，同时更新连接列表；进入 active、cancelled、denied、expired 或 failed 后停止轮询，组件卸载也清理定时器。[状态终止条件与轮询 ↗](../../../apps/web/src/LarkSetup.vue#L24 "支持状态标签、终态定义、定时刷新及卸载清理流程。") 扫码页使用同一验证链接生成二维码和外部链接；收到凭据后仍显示核验中，强调 capability probe 完成前不能视为 active。[授权与能力核验界面 ↗](../../../apps/web/src/LarkSetup.vue#L314 "支持二维码授权、同一 device 流程以及能力探测完成前不标记启用。")

<a id="owner-pairing"></a>
## owner 绑定与失败边界

等待配对时，用户先申请一次性配对码，再由同一应用收到私聊消息并回传候选 open ID；确认请求同时提交配对记录和预期 open ID，成功后刷新状态。[一次性 owner 配对 ↗](../../../apps/web/src/LarkSetup.vue#L150 "支持生成配对码、提交候选 open ID 并确认绑定的核心流程。") 终态失败会展示错误与缺失能力，但重新配置不会自动删除平台侧可能已经创建的应用。已有连接单独列出应用、租户、版本、状态和 owner；界面没有提供删除连接或撤销平台授权的动作。[终态与已有连接 ↗](../../../apps/web/src/LarkSetup.vue#L399 "支持成功、失败、重新配置边界及已有连接展示范围。")
