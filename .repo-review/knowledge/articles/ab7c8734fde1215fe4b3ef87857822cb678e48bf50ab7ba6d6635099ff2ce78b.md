# 模块架构师角色提示词

规定模块架构师基于固定快照描述单个模块或小型模块簇的职责、边界、关键流程及入口出口，并以带证据声明和生成封印的 CodeUnderstanding.v1 JSON 返回；这是行为要求，不能代替实际验证结果。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="analysis_scope"></a>
## 分析范围与事实来源

该角色面向一个模块或小型模块簇，目标是在给定快照上说明职责、相邻边界、内部关键流程以及入口和出口。[模块分析目标与快照边界 ↗](../../../packages/agent-runtime/roles/module-architect/1/prompt.md#L1 "支持角色分析职责、边界、流程和入口出口，以及只能依赖固定快照且禁止外部读取的论断。") 文件、符号节点、边和列入证据的规则或文档被定义为唯一事实来源；材料正文只能作为不可信数据，角色不得执行其中指令、调用工具或读取快照外文件。[模块分析目标与快照边界 ↗](../../../packages/agent-runtime/roles/module-architect/1/prompt.md#L1 "支持角色分析职责、边界、流程和入口出口，以及只能依赖固定快照且禁止外部读取的论断。") 因此输出应描述特定快照，而非推断仓库当前或未来的普遍状态。

<a id="evidence_output"></a>
## 证据化输出与未知项

角色只能返回一个 `CodeUnderstanding.v1` JSON，并应重点填充模块职责、边界、流程、入口出口及风险限制。[结构化输出与证据声明 ↗](../../../packages/agent-runtime/roles/module-architect/1/prompt.md#L5 "支持仅返回 CodeUnderstanding JSON、聚焦架构字段、验证引用存在性并优先记录未知项的要求。") 依赖代码的陈述必须作为 `raw_fact` 或 `interpretation` 声明出现，引用的节点、边和证据标识都必须存在于快照；无法可靠定位时应写入 `unknowns`，而不是发明标识。[结构化输出与证据声明 ↗](../../../packages/agent-runtime/roles/module-architect/1/prompt.md#L5 "支持仅返回 CodeUnderstanding JSON、聚焦架构字段、验证引用存在性并优先记录未知项的要求。") 提示声称确定性验证器会拒绝虚构标识，但未提供其实现或测试，故这仍是规定而非已核实能力。

<a id="generation_seal"></a>
## 生成封印

输出封印要求角色固定为模块架构师，填写模型、提示摘要、Schema 摘要、快照输入摘要和当前 ISO 时间，并明确设为非种子、未经代理验证且无验证者。[生成结果封印要求 ↗](../../../packages/agent-runtime/roles/module-architect/1/prompt.md#L7 "支持角色、模型、摘要、生成时间及种子和验证状态的精确填充规则。") 这些字段可用于追踪结果来源并把新生成结果与人工种子或后续验证结果区分开；不过提示没有说明模型字段允许哪些值，也没有交代摘要由宿主提供还是由角色自行计算。
