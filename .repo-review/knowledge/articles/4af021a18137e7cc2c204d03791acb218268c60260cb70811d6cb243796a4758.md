# 研究标注数据集导入与规则候选生成

该模块是显式启用的评估工具：从 CaptureInput 的文本部分生成规则切分、排序并校验的标注草稿，再交由 QualityRepository 持久化。它刻意隔离于普通捕获与学习流程，生成的 extract/claim 与 autoApply 仅供人工研究标注，不能视为生产知识。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决的问题与安全边界

模块为人工质量评估准备可复现的候选样本，把 Lark/HTML 转换后的捕获文档切成便于标注的短句；它不是通用导入器，也不得被 HTTP、CLI 捕获或学习流程调用。规则结果统一标成 `explicit/claim` 且 `autoApply=true`，只是待人工判断的草稿，不能作为生产知识自动生效。[评估专用用途声明 ↗](../../../apps/server/src/quality/import.ts#L1 "支持该模块只服务人工标注、不得进入普通捕获及生产知识流程的论断。")

调用方还必须传入精确的评估 opt-in 字面量，否则在创建数据集前立即抛错。这道运行时门禁与文件注释共同表达了隔离意图，但无法单凭本材料证明仓库其他调用路径均未引用该模块。[评估导入门禁 ↗](../../../apps/server/src/quality/import.ts#L156 "支持导入必须携带专用 opt-in，错误调用会在数据集创建前失败。")

<a id="pipeline"></a>
## 候选生成核心流程

函数只汇集 `CaptureInput.parts` 中的文本部分，图片和链接不会进入样本文本；随后按空行分块，用 Markdown 标题维护当前章节，并跳过白板、网格、列、表格及图片块。[文本汇集与分块过滤 ↗](../../../apps/server/src/quality/import.ts#L41 "支持仅消费文本部分、维护章节并跳过复杂视觉块的流程说明。") 长文本按中文句末符号继续拆分，候选长度限定为 24–500 字；章节与正文的稳定摘要同时用于去重和派生 fragment 标识。摘要实现会递归规范化对象键、忽略 `undefined` 后计算 SHA-256，因此相同规范化输入可得到稳定结果。[稳定摘要实现 ↗](../../../apps/server/src/storage/digest.ts#L3 "解释候选去重、片段标识和源摘要所依赖的规范化 SHA-256 算法。")

每个候选经仓库层 schema 校验，来源记录 URI、文档、修订、片段和章节，标签则保存原句作为 claim 与证据，并明确禁止把文档描述解释成外部操作授权。规则词、否定词和数字提高评分，最终按分数降序、原文块顺序升序取前 `limit` 条；数量不足时整体失败。[样本构造、评分与数量校验 ↗](../../../apps/server/src/quality/import.ts#L83 "支持候选长度限制、schema 校验、草稿标签、规则评分、排序截取及数量不足报错的说明。")

<a id="persistence"></a>
## 持久化关系、限制与测试证据

导入入口先生成样本及覆盖源 URI、文档版本和完整文本的 source digest，再调用 `QualityRepository.createDataset` 建立数据集，继而用 `addSamples` 写入样本，返回数据集信息、插入结果和生成数量。[数据集创建与样本写入 ↗](../../../apps/server/src/quality/import.ts#L172 "支持生成结果如何交给 QualityRepository 持久化以及返回值如何组成的说明。") 这说明模块依赖质量仓库承担实际存储，并依赖 contracts 中的 `CaptureInput` 作为输入合同；该合同允许文本、图片和链接，但本实现有意只消费文本。[捕获内容部分合同 ↗](../../../packages/contracts/src/index.ts#L18 "支持 CaptureInput 可包含文本、图片和链接，而导入模块只选取文本的模块关系说明。")

边界上，标题只有在整个分块匹配 Markdown 标题时才更新章节；表格和图片块会整块跳过，短句、超长句及重复句也会丢弃。提供材料没有测试文件，因此只能确认源码中的显式分支与异常，不能确认排序稳定性、HTML 清洗、持久化原子性或异常回滚已被自动化测试覆盖。
