# 持久化任务状态机与审计仓库

以 SQLite 事务实现任务去重、租约执行、尝试审计、分类重试以及幂等取消和人工重试。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="enqueue-claim"></a>
## 入列、去重与租约领取

仓库以 workspace、kind、输入摘要、角色版本和策略版本形成幂等任务；同一组合重复入列时返回已有记录。捕获流程还可在外层事务中调用无嵌套版本，使证据与首个任务一起提交。输入摘要来自规范化 JSON，降低对象键顺序导致的伪差异。[任务幂等入列 ↗](../../../apps/server/src/jobs/repository.ts#L187 "支持输入摘要、版本化唯一性以及与捕获事务共同提交的说明。")

领取任务使用 `BEGIN IMMEDIATE` 串行化竞争，只选择已到期且未取消的 queued、retry_wait 或过期 leased/running 任务。旧租约过期时先结束原 attempt，再检查当前 generation 的次数上限；成功领取会生成新 token、到期时间和带模型指纹的 attempt。后续运行、心跳、保存结果和完成都必须匹配租约。[任务领取与租约防护 ↗](../../../apps/server/src/jobs/repository.ts#L261 "支持过期任务回收、尝试上限、租约 token 和 attempt 指纹创建流程。")

<a id="result-control"></a>
## 结果、失败与控制操作

角色运行 trace 和输出分开保存：attempt 记录模型、effort、提示词、技能、工具、上下文及会话身份，role output 保存输出摘要、JSON 与 trace。成功会原子结束 attempt、写 resultRef 并清除租约；失败先脱敏错误，再按类型决定退避，bad_output 最多进入两次计数窗口、transient 最多三次，其他类型直接终止，同时仍受 generation 的 maxAttempts 限制。[输出审计与失败策略 ↗](../../../apps/server/src/jobs/repository.ts#L404 "支持运行 trace、角色输出、成功提交、错误脱敏和分类退避规则。")

取消和显式重试都要求 expectedGeneration，并以 requestId 加载先前响应；同一 requestId 若载荷不同会报幂等冲突。运行中取消仅置标志，由 worker 协作中断；已成功任务要求补偿而非回滚。显式重试只接受失败、取消或等待决策状态，并递增 generation，保留历史 attempts 作为审计。[幂等取消与代际重试 ↗](../../../apps/server/src/jobs/repository.ts#L674 "支持请求幂等、generation 乐观并发控制、协作取消和显式重试边界。")
