# 持久化任务状态机与租约仓储

以 SQLite 事务实现任务入队、租约领取、尝试审计、结果保存、分类重试、取消和人工重试，是 DurableJobWorker 的持久化并发控制层。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="enqueue_claim"></a>
## 入队、复用与领取

入队先对输入引用计算稳定摘要，再按工作区、任务类型、输入摘要、角色版本和策略版本查询任务。代码使用 `INSERT OR IGNORE` 并通过是否插入判断 duplicate；相同工作单元能否真正幂等复用，仍依赖材料未展示的数据库唯一约束与查询维度一致。当前事务内入口允许 Capture 证据与首个任务一起提交。[任务入队与既有任务查询 ↗](../../../apps/server/src/jobs/repository.ts#L187 "支持输入摘要、版本查询维度、INSERT OR IGNORE 的 duplicate 判断及 Capture 同事务入队；同时表明幂等性仍需唯一约束配合。")

领取在立即事务中选择到期的 queued、retry-wait 或租约过期任务。旧尝试记为 `lease_expired`；达到 generation 尝试上限时任务失败，否则通过 generation、状态和过期条件更新租约并创建 attempt 审计记录。运行、心跳和完成操作继续校验 lease token，防止过期 worker 覆盖新结果。[任务租约领取与尝试审计 ↗](../../../apps/server/src/jobs/repository.ts#L261 "支持过期租约回收、generation 尝试上限、条件更新、租约令牌和 attempt 创建流程。")

<a id="completion_failure"></a>
## 输出、完成与分类失败

角色输出及运行 trace 在事务内保存，输出另计算摘要；成功操作会结束当前 attempt、保存结果引用并清除租约。失败消息先脱敏和截断，再按错误种类决定重试：bad output 上限为两次、transient 上限为三次，同时受 generation 的 `maxAttempts` 约束；退避随同类错误次数指数增长，认证、配置和永久错误不自动重试。[输出保存与分类失败策略 ↗](../../../apps/server/src/jobs/repository.ts#L452 "支持输出摘要、成功终结、错误脱敏、按错误类型限制重试及指数退避规则。")

<a id="control"></a>
## 取消、人工重试与 Worker 关系

取消和人工重试以 request ID 与负载摘要保证控制请求幂等，并校验工作区和预期 generation。运行中任务只设置取消标志，需 worker 协作中止；已成功任务要求补偿。手动重试仅允许 failed、cancelled 或 awaiting-decision，递增 generation 并清理当前终态，但历史 attempts 保留。[取消与人工重试状态机 ↗](../../../apps/server/src/jobs/repository.ts#L674 "支持控制请求幂等、generation 校验、运行中协作取消、成功态补偿边界和新 generation 重试。")

`DurableJobWorker` 调用该仓储完成领取、转为 running、心跳、成功或失败；心跳丢失会中止处理，停止 worker 则把中断归为 transient，以便按仓储策略重试。由此仓储负责持久状态与并发门禁，worker 负责执行和协作取消。[持久任务执行器 ↗](../../../apps/server/src/jobs/worker.ts#L47 "说明 Worker 如何调用仓储的领取、心跳、成功、失败和取消接口，支持两模块之间的职责关系。")
