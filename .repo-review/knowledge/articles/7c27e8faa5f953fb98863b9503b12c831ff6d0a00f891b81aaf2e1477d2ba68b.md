# 共享 Trail 栈循环与深层导航测试

验证 trail 使用 kind 与 id 联合识别循环，允许超过旧八层限制的导航链，并支持五层钻取与回退场景。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="loop"></a>
## 循环身份判定

`findLoop` 的合同是按 `kind + id` 联合身份查找已有帧：不存在返回 -1，任意深度存在则返回索引，相同 id 但不同 kind 不应误判。[循环检测断言 ↗](../../../apps/web/src/codewiki/trail.test.ts#L8 "支持无匹配、深层匹配及跨 kind 不混淆的行为合同。") 共享实现采用 `findIndex` 完成这一精确比较，因此容器可据返回索引决定跳回已有层级，而无需把文件和片段等不同实体混为一谈。[循环检测实现 ↗](../../../packages/ui/src/trail.ts#L44 "解释联合比较 kind 和 id，并返回首个匹配索引。") 测试没有覆盖栈中出现重复联合身份时选择哪个索引；按实现会返回最早一项。

<a id="depth"></a>
## 深链与回退边界

测试连续压入 12 个文件帧，确认不会沿用旧的八层静默截断，并以“模块→文件→片段→文件→片段”验证五层链和回到第二层时的循环位置。随后通过数组切片模拟回退，确认剩余栈顶是第二个文件。[长链与五层导航断言 ↗](../../../apps/web/src/codewiki/trail.test.ts#L21 "支持超过八层不截断、五层钻取、循环定位及切片回退结果。") 共享实现的 `pushFrame` 实际只是返回追加后的新数组，渲染栈不受 `MAX_TRAIL` 限制；常量 200 被描述为 URL 持久化预算。[Trail 深度预算与压栈实现 ↗](../../../packages/ui/src/trail.ts#L37 "说明 MAX_TRAIL 是 URL 预算，而 pushFrame 本身不截断渲染栈。") 当前测试未覆盖第 200/201 层、URL 序列化、scroll 恢复，也没有验证真实抽屉的 pop/jump 行为。
