# 个人记忆服务的 HTTP 组合入口

该文件是服务端组合根：创建 Fastify 应用，连接单用户 SQLite 存储、统一捕获、知识与检索、助理、学习流水线和飞书集成，并集中处理访问控制、HTTP 路由、后台任务及资源回收。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="composition"></a>
## 把存储、知识与助理组装成服务

`buildApp` 把分散的能力组装成一个可运行的个人记忆服务。它创建 Fastify、`Store`、运行记录、记忆与反馈服务，注册知识接口和检索服务，并以固定的个人所有者和 60 秒轮次超时初始化助理。非回环地址若未配置令牌，应用会拒绝启动。参考 [服务依赖装配 ↗](../../../apps/server/src/app.ts#L47 "支持应用创建、非回环访问前置条件，以及存储、知识、检索和助理运行时的组装说明。")

`Store` 是共享的持久化基础：它创建单用户 SQLite 数据库、执行迁移，并提供任务、输入聚合、运行时请求和来源画像等仓储。由此，组合入口主要负责协议适配和生命周期协调，具体数据规则仍由各服务承担。参考 [单用户存储基础 ↗](../../../apps/server/src/store.ts#L38 "说明 Store 初始化 SQLite、执行迁移并提供多个共享仓储服务。")

<a id="capture_api"></a>
## 从多种入口汇入统一证据链

服务接受规范化捕获，也支持文件、Git、飞书链接、TraeX hook 和输入事件。连接器先把外部内容转换成统一捕获结构，再交给 `store.capture`；输入事件则经过聚合器，在批次就绪后写入。参考 [统一捕获入口 ↗](../../../apps/server/src/app.ts#L204 "支持直接捕获、各类连接器转换及输入事件聚合后写入 Store 的流程。")

连接器执行的是**显式且有边界的读取**：文本中的 URL 只作为材料保留，不会被自动抓取；文件必须位于配置的根目录内，大小不超过 500 KB，并能以严格 UTF-8 解码且不含空字节。参考 [连接器读取边界 ↗](../../../apps/server/src/connectors.ts#L1 "支持 URL 不自动抓取，以及文件根目录、大小、UTF-8 和非二进制文本限制。")

捕获后可通过接口读取来源画像、固定修订、历史、证据、关系、搜索结果和资源，并查看或恢复变化。参考 [证据与变化接口 ↗](../../../apps/server/src/app.ts#L240 "支持来源画像、修订、历史、证据、关系、搜索、资源以及变化查看和恢复能力。") 此外，服务还暴露通知、事项、作业、运行时请求、提案与决策、记忆版本及反馈接口，使后续处理仍围绕同一份材料和持久化边界展开。参考 [记忆与处理接口 ↗](../../../apps/server/src/app.ts#L316 "支持通知、事项、作业、运行时请求、提案、决策、记忆版本和反馈接口的概括。")

<a id="assistant_security"></a>
## 助理操作由服务器重新约束

Web 调用方不能自行声明飞书通道、群组可见性或其他主体；服务端把会话固定为个人所有者、Web 通道和私有可见性。会话随后支持执行、查询、取消和重试轮次，并对缺失会话或不可重试状态返回对应错误。参考 [Web 会话信任边界 ↗](../../../apps/server/src/app.ts#L575 "支持 Web 调用方不能伪造飞书通道或群组可见性，以及轮次执行、取消和重试行为。")

模型回复可以包含引用、补充检索词以及创建或更新事项的结构化请求，但这些请求并不自动获得写权限。运行时合同要求服务器重新检查证据可见性、所有者来源和事项约束。参考 [助理结构化调用合同 ↗](../../../apps/server/src/assistant/runtime.ts#L23 "说明模型产生的引用、检索词和事项工具调用仍须由服务器重新治理。")

用户控制已有事项时，服务先生成一条带来源信息的手动捕获，再以其证据片段执行完成、改期、等待、暂缓或取消等命令，使操作依据可以回溯。参考 [事项操作留证 ↗](../../../apps/server/src/app.ts#L333 "支持事项命令先形成带来源信息的捕获修订，再以证据片段驱动记忆服务执行。")

<a id="boundaries_lifecycle"></a>
## 可选集成、访问边界与生命周期

学习流水线只在启用且指定 profile 存在时创建；飞书启用后会装配密钥存储、注册与能力探测、已有应用提供器和运行宿主。初始化失败会关闭存储并终止启动。参考 [学习与飞书初始化 ↗](../../../apps/server/src/app.ts#L89 "支持学习 profile 校验、飞书组件装配以及初始化失败时关闭存储的行为。")

所有 `/api/` 请求统一经过访问检查：配置令牌时采用定时安全比较；没有令牌时仅接受本机 Host 与本机 Origin。输入错误通常映射为 400，重基、过期或冲突映射为 409，重复活动映射为 429。参考 [API 访问与错误处理 ↗](../../../apps/server/src/app.ts#L138 "支持令牌或本机来源校验，以及冲突、限流和输入错误的统一状态码映射。")

应用启动末尾会恢复未完成的助理轮次，周期性派发提醒和刷新输入批次，再启动学习及飞书运行时；关闭时停止定时器和各运行组件，最后关闭检索与数据库。构建后的静态前端仅在目录存在时注册。参考 [启动与关闭流程 ↗](../../../apps/server/src/app.ts#L640 "说明静态资源、未完成轮次恢复、周期任务、可选运行时启动及资源回收顺序。")
