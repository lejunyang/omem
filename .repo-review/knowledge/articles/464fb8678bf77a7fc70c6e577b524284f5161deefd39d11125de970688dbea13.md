# 服务端应用装配与 HTTP 边界

构建并连接存储、检索、助手、知识、学习与飞书运行时，集中定义 API、安全边界、后台循环和资源释放。此前由单一生命周期片段支撑全部路由的概括已被分段引用替代。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="assembly"></a>
## 应用装配与模块关系

`buildApp` 是服务端组合根：非回环地址未配置令牌时拒绝启动，随后创建 Fastify、SQLite Store、运行记录、记忆与反馈服务，注册知识路由，并以可用 ACP profile 装配检索和主助手。学习流水线与飞书服务按配置启用；飞书初始化失败会先关闭存储再抛出错误。[应用依赖装配 ↗](../../../apps/server/src/app.ts#L44 "支持组合根创建存储、知识路由、检索、ACP 助手以及可选学习和飞书运行时的论述。")

该文件负责连接能力而非承载各领域算法。健康接口集中报告 SQLite、personal 模式、检索、通知、学习和飞书运行状态，使调用方能够区分服务存活与可选子系统是否启用。[健康状态汇总 ↗](../../../apps/server/src/app.ts#L179 "支持健康接口公开当前存储模式及检索、学习、飞书运行状态的说明。")

<a id="http-lifecycle"></a>
## HTTP 边界、路由与生命周期

所有 `/api/` 请求先经过统一安全钩子：配置令牌时以定时安全比较校验 Bearer token；无令牌时仅接受本机 Host 和本机 Origin。输入、冲突与并发探测错误也在此统一映射为 HTTP 状态。[API 安全与错误映射 ↗](../../../apps/server/src/app.ts#L134 "支持令牌、本机来源限制和统一错误状态码边界的说明。")

捕获、connector、原文与证据、搜索、变更恢复、通知、任务、作业和运行时请求集中暴露在前半段路由；记忆提案、反馈、质量标注、飞书接入、profile 探测和普通运行则由后续路由承接。[捕获、证据与任务路由 ↗](../../../apps/server/src/app.ts#L198 "直接覆盖捕获、connector、证据、搜索、通知、任务、作业及运行时请求等前半段 API，修正旧稿引用覆盖不足。")[记忆、质量与集成路由 ↗](../../../apps/server/src/app.ts#L344 "直接覆盖记忆、反馈、质量、飞书接入、profile 探测和运行管理等后半段 API。") 这组分段依据替代了此前仅凭助手与生命周期代码概括全部路由的结论。

Web 助手会话由服务端固定为 owner、web 和 private，拒绝客户端伪造飞书频道或群可见性。启动时恢复未完成轮次并启动提醒、输入聚合、学习及飞书循环；关闭时中止助手并依次释放后台服务、运行、检索和数据库资源。[助手路由与进程生命周期 ↗](../../../apps/server/src/app.ts#L534 "支持 Web 会话身份约束、轮次操作、未完成轮次恢复、后台循环及关闭清理流程。")
