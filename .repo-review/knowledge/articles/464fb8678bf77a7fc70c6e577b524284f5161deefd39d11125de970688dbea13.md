# 个人记忆服务的 HTTP 应用装配与运行入口

该文件是服务端组合根，集中装配单用户 SQLite 存储、知识与检索、助手、学习和飞书能力，并统一暴露捕获、记忆、事项及会话 API。更新后的结论把飞书初始化失败关闭 Store 严格限定在启用飞书且未注入 onboarding 服务的内建装配分支，并把未配置错误限定为调用 requireLark 的接入入口。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-bootstrap"></a>
## 服务装配与当前存储边界

`buildApp` 在非回环监听时强制要求访问令牌，随后创建 Fastify、`Store`、运行记录和记忆服务，并连接知识路由、检索、ACP 助手及可选学习管线。未配置可运行 ACP 或真实传输失败时，助手应明确报告不可用，而非生成伪造回答。[服务初始化入口 ↗](../../../apps/server/src/app.ts#L47 "支持非回环监听必须配置令牌，以及 Fastify、Store、运行记录和记忆服务的初始化关系。") [助手与检索装配 ↗](../../../apps/server/src/app.ts#L74 "支持知识路由、ACP 助手模型、检索服务、AssistantRuntime 和可选学习管线的连接关系。")

当前持久化基础是单用户 SQLite：初始化过程创建受限权限的数据目录和数据库文件、执行迁移，并装配任务、输入聚合、运行请求和来源画像仓库。不可变修订、变更和通知 outbox 属于 Store 的总体设计；团队数据库及租户强制隔离仍是后续迁移。[单用户 SQLite 存储基础 ↗](../../../apps/server/src/store.ts#L4 "支持当前单用户 SQLite 边界、不可变修订的总体设计，以及数据库迁移和持久化组件初始化。")

<a id="capture-and-actions"></a>
## 统一捕获入口与可追溯操作

手工、文件、Git、飞书和 Hook 输入均经合同校验后交给 `Store.capture`。输入事件先进入聚合器，`flushReady` 产生的成熟批次也交给 `Store.capture`；现有范围只能确认这条调用链，不能据此断言 `capture` 内部如何创建固定修订。[多来源捕获与输入聚合 ↗](../../../apps/server/src/app.ts#L202 "支持各类捕获入口调用 Store.capture，并将结论准确限定为成熟输入批次由 flushReady 交给 Store.capture。")

文件连接器限定真实路径必须位于配置根目录内，并约束大小、UTF-8 和纯文本；Git 连接器还校验 ref、仓库内相对路径与解析后的 commit，再以参数数组执行 `git show`。[文件读取边界 ↗](../../../apps/server/src/connectors.ts#L10 "支持文件连接器对配置根目录、文件大小、UTF-8 解码和纯文本内容的限制。") [Git 输入约束 ↗](../../../apps/server/src/connectors.ts#L36 "支持 Git ref、仓库内路径、commit 摘要和受限 git show 参数的校验流程。") 事项状态命令先捕获为来源证据，再携带首个证据片段调用记忆服务，使操作依据可追溯。[事项操作留痕 ↗](../../../apps/server/src/app.ts#L313 "支持事项命令先被捕获为来源证据，再将证据片段交给 MemoryService 执行状态变化。")

<a id="security-boundaries"></a>
## 访问控制与会话信任边界

API 配置令牌时使用定时安全比较校验 Bearer token；未配置令牌时只接受本地主机，并拒绝非本地 Origin。冲突、活动占用和输入校验错误由统一错误处理映射为 HTTP 状态。[API 访问控制 ↗](../../../apps/server/src/app.ts#L138 "支持令牌、本地主机和 Origin 校验，以及冲突、占用和输入错误的统一状态映射。")

Web 调用方不能伪造飞书频道、群组可见性或主体，服务器固定以 `owner`、`web`、`private` 建立会话；可信飞书会话只能由飞书运行宿主打开。[Web 会话信任边界 ↗](../../../apps/server/src/app.ts#L555 "支持 Web 请求不得声明飞书频道、群组可见性或任意主体，并由服务器固定会话作用域。") 先前“飞书组件初始化失败都会关闭 Store”的宽泛结论已被替代：只有启用飞书且未注入 onboarding 服务、因而进入内建飞书装配的分支，初始化异常才会关闭已创建的 Store；没有可用 onboarding 服务时，仅调用 `requireLark` 的飞书接入入口会明确报未配置错误。[飞书内建装配与配置检查 ↗](../../../apps/server/src/app.ts#L105 "支持收窄后的飞书结论：仅启用飞书且未注入 onboarding 服务的内建初始化分支会在异常时关闭 Store；requireLark 在服务不可用时抛出明确的未配置错误。")

<a id="runtime-lifecycle"></a>
## 恢复、后台循环与有序关闭

路由装配完成后，服务先恢复遗留的未完成助手轮次，再启动提醒和输入聚合定时器，并按配置启动学习与飞书运行时。聚合异常按消息去重记录，避免重复刷屏。关闭时清理定时器，停止助手、学习、飞书、运行管理与检索，最后关闭数据库，以降低后台任务访问已释放资源的风险。[服务生命周期管理 ↗](../../../apps/server/src/app.ts#L620 "支持未完成轮次恢复、后台定时任务启动、可选运行时启动及关闭阶段的资源回收顺序。")

这些材料能够确认编排路径，但未提供相应测试文件，因此不能据此认定权限异常、轮次恢复、取消分支和关闭顺序均已有自动化行为验证。
