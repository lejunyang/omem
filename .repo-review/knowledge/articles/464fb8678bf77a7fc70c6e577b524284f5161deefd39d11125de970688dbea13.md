# 服务端应用装配与 HTTP API 边界

该文件是服务端组合根：创建 Fastify 与单用户 SQLite 存储，装配记忆、检索、助手、学习及飞书能力，集中注册输入、任务、知识和对话接口，并负责访问控制、错误映射、后台循环及资源关闭。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="bootstrap"></a>
## 应用装配与能力启用

`buildApp` 首先限制非回环监听必须配置令牌，随后创建 Fastify、Store、记忆与反馈服务，并把已配置的 ACP profile、检索服务注入助手运行时；学习管线只有在启用且能找到指定 profile 时才创建，否则启动直接失败。[应用初始化与助手装配 ↗](../../../apps/server/src/app.ts#L46 "支持 buildApp 的监听限制、核心服务创建、ACP profile、检索和学习管线装配说明。") Store 是底层单用户 SQLite 基础，构造时完成数据库迁移、资产目录权限设置，并初始化作业、输入聚合、运行请求和来源画像仓库，因此本文件承担的是模块装配而非数据规则实现。[单用户 SQLite Store 构造 ↗](../../../apps/server/src/store.ts#L38 "说明 Store 的单用户定位、数据库迁移、权限设置及子仓库初始化。")

飞书能力支持依赖注入；未注入且配置启用时，应用才创建加密密钥存储、注册适配器、onboarding 与运行宿主。初始化异常会先关闭 Store 再抛出，质量仓库则优先复用飞书运行时中的实例。[飞书服务条件装配 ↗](../../../apps/server/src/app.ts#L103 "支持飞书 onboarding、运行宿主、异常清理和质量仓库选择流程。")

<a id="security"></a>
## 访问控制与输入边界

所有 `/api/` 请求统一经过访问控制：有 token 时用等长检查和恒定时间比较验证 Bearer token；无 token 时只接受本机 Host，并拒绝来自非回环 Origin。错误处理把重基、过期和冲突映射为 409，并把并发探测映射为 429，Zod 校验错误返回字段级说明。[API 鉴权与错误映射 ↗](../../../apps/server/src/app.ts#L136 "支持 token、本机来源限制以及 HTTP 错误码转换规则。")

捕获入口既接受通用 Capture，也提供文件、Git、飞书链接、TraeX hook 和输入事件聚合接口；各入口先做 schema 校验，再交给 Store 持久化。[捕获与输入聚合接口 ↗](../../../apps/server/src/app.ts#L200 "支持通用捕获、各类连接器及输入事件批处理的路由流程。") 文件连接器还会解析真实路径并限制在配置根目录内，同时拒绝超过 500 KB、非 UTF-8 或包含空字节的内容，说明路由层依赖连接器落实读取安全边界。[文件连接器读取限制 ↗](../../../apps/server/src/connectors.ts#L10 "支持文件导入的根目录、大小、编码和二进制内容边界。")

<a id="api_orchestration"></a>
## 任务、作业与助手编排

任务控制不会直接改状态，而是先把用户操作、等待对象和时间表达捕获为带 provenance 的手工证据，再以首个 fragment 作为 evidence 调用记忆服务；普通任务更新则携带 expectedVersion，作业取消在学习管线存在时交由其处理，否则落到作业仓库。[任务控制与作业路由 ↗](../../../apps/server/src/app.ts#L310 "支持任务操作先形成证据、版本化更新以及作业取消分流的说明。")

助手模型合同允许返回自然语言、引用片段、受服务端重新治理的任务工具调用，以及最多一轮补充检索词；不过这些内部执行步骤不在当前文件中展开。[助手模型回复合同 ↗](../../../apps/server/src/assistant/runtime.ts#L54 "说明助手回复可包含引用、受治理工具调用和有限补充检索，但未展示内部执行实现。") Web 端只能创建 owner、web、private 会话，显式拒绝伪造飞书频道或群可见性；后续接口负责执行、查询、取消和重试 turn，并分别处理会话不存在与重试冲突。[Web 会话与 turn 接口 ↗](../../../apps/server/src/app.ts#L553 "支持 Web 身份边界，以及 turn 执行、查询、取消和重试流程。")

<a id="lifecycle"></a>
## 运行周期与已知边界

静态前端仅在构建目录存在时挂载。应用返回前会恢复上次进程遗留的未完成 turn，启动提醒与输入聚合定时器，并按配置启动学习和飞书运行时；关闭时依次停止定时器、助手、后台管线、运行任务、检索服务和数据库。[应用启动恢复与关闭清理 ↗](../../../apps/server/src/app.ts#L618 "支持静态资源挂载、未完成 turn 恢复、后台循环启动和资源关闭顺序。") 由此可见它是统一生命周期管理器，但各服务的事务语义、检索算法与模型降级细节仍属于被注入模块。
