# 服务端应用如何装配并承接一次请求

buildApp 是 omem 服务端的组合根：它根据配置创建存储、检索、助手与可选后台能力，统一挂载 API 的访问保护和错误转换，并在启动、恢复与关闭阶段管理资源。理解这里，能快速判断一项功能应改路由边界、业务服务还是运行时生命周期。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="composition"></a>
## 它解决的是“把能力组装成可运行服务”

`buildApp(config, dependencies)` 接收运行配置和可注入的飞书依赖，先拒绝“非回环地址却没有令牌”的危险启动方式，再创建 Fastify、SQLite 存储、运行任务、记忆与反馈服务。它本身不实现这些领域算法，而是把对象放进同一个进程并让路由调用它们，因此是查找服务端依赖关系和新增入口的第一站。参考 [应用核心对象装配 ↗](../../../apps/server/src/app.ts#L49 "支持 buildApp 的输入、安全启动条件，以及 Fastify、Store、Runs、MemoryService、FeedbackService 的创建关系。")

助手侧由配置中的 ACP profile、检索服务和 `AssistantRuntime` 组成；学习流水线只有在启用且找到指定 profile 时才创建，否则配置错误会直接阻止启动。参考 [助手与学习流水线 ↗](../../../apps/server/src/app.ts#L77 "说明 ACP 模型、检索、AssistantRuntime 和条件启用的 LearningPipeline 如何由配置组装。") 飞书接入同样是条件装配：可由调用者注入，也可在启用时从环境构建密钥、注册、探测和运行时；构建失败会先关闭存储再抛错。参考 [飞书条件装配 ↗](../../../apps/server/src/app.ts#L108 "支持飞书服务可注入或按配置创建，以及初始化失败时关闭存储的行为。")

<a id="representative-flow"></a>
## 代表性调用：从 Web 消息到助手结果

一次典型使用分两步。客户端先 `POST /api/assistant/conversations`，输入 `chatId` 和可选 `threadId`；服务端固定把主体设为个人 owner、渠道设为 web、可见性设为 private，并拒绝网页伪造飞书渠道或群可见性。输出是已打开的会话。参考 [Web 会话身份边界 ↗](../../../apps/server/src/app.ts#L587 "支持创建 Web 私人会话的输入输出，以及网页不能伪造飞书渠道和群可见性的限制。")

```mermaid
flowchart LR
  A[Web 创建私人会话] --> B[提交 text 与可选 requestId]
  B --> C[AssistantRuntime.turn]
  C --> D[返回回合结果或 404]
```

随后客户端向该会话的 `/turns` 提交文本；路由校验正文，把 `requestId` 转成带 `web:` 前缀的传输事件标识并调用 `assistant.turn`。若会话不存在返回 404，否则原样返回运行时结果；同一区域还提供历史读取、取消与重试，重试冲突返回 409。参考 [助手回合调用链 ↗](../../../apps/server/src/app.ts#L613 "支持文本校验、事件标识转换、AssistantRuntime.turn 调用及读取、取消、重试结果处理。")

<a id="boundaries-lifecycle"></a>
## 边界保护与生命周期

所有 `/api/` 请求先经过统一保护：配置令牌时用定时安全比较验证 Bearer token；无令牌时只接受本机 Host，并拒绝非本机 Origin。静态页面不走这条 API 判断。参考 [API 访问保护 ↗](../../../apps/server/src/app.ts#L141 "支持令牌比较、本机 Host 限制和跨域来源限制。") 输入校验主要由 Zod 完成；冲突类错误映射为 409、重复活动映射为 429，其余校验或业务错误为 400。参考 [统一错误映射 ↗](../../../apps/server/src/app.ts#L166 "说明冲突、重复活动、Zod 校验和普通业务错误对应的 HTTP 状态。")

路由注册结束后，服务会挂载已有的前端构建、恢复上次进程未完成的助手回合，并启动提醒、输入聚合以及可选的学习和飞书运行时。关闭时按顺序停定时器、助手、后台流水线、运行任务、检索与存储，避免数据库或子进程悬挂。修改启动恢复、后台轮询或资源释放，应集中查看这一段；具体业务行为则应进入对应 service/runtime，而不是继续堆在路由里。参考 [启动恢复与关闭清理 ↗](../../../apps/server/src/app.ts#L652 "支持静态页面挂载、未完成回合恢复、后台定时任务启动，以及关闭时的资源释放顺序。")
