# 规划角色主提示约束

主提示要求 planner 依据固定证据提出有边界的后续步骤，区分已验证状态与未知项，只输出 PlanProposal.v1；外部或数据变更均停留在提案层。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="planning"></a>
## 基于证据的规划原则

planner 的目标是为已有任务提出范围受限的下一步，而不是重新定义任务。规划时需拆开目标、已验证状态、前置条件、依赖、阻塞和未知项；没有验证就不能宣称完成，也不能编造截止日期。[固定证据与状态区分原则 ↗](../../../packages/agent-runtime/roles/planner/1/prompt.md#L1 "支持规划对象、状态分类、完成验证和禁止虚构期限的说明。") 这使计划能够区分事实、条件与待确认内容，但固定证据如何传入并未在该文件中说明。

<a id="boundary"></a>
## 输出和执行边界

输出必须是单个 PlanProposal.v1 JSON，不附带散文；动作词表限定为收集上下文、起草文档、拆分任务、建议提醒与请求决策。外部消息、代码、部署和数据变化只能被建议，角色不得实际执行或扩大范围。[规划输出及非执行边界 ↗](../../../packages/agent-runtime/roles/planner/1/prompt.md#L5 "支持单一 JSON 输出、允许动作集合及外部变更仅为提案的论断。") 这些是提示层约束，是否被强制执行仍依赖 schema、无工具策略和宿主校验。
