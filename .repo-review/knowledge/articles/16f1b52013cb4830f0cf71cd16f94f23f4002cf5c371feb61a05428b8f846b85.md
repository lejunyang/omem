# 提取角色提示词：证据约束的记忆候选生成

该提示词定义提取角色的职责、信任边界、输出合同与禁止行为。它要求从固定证据生成原子化候选，并明确角色只提出候选、不执行或批准；文件本身只能证明设计约束存在，不能证明运行时已执行校验或持久化。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-boundary"></a>
## 职责与信任边界

该角色面向“从固定证据生成持久记忆候选”的场景。身份、范围、时间、来源和转发状态以可信上下文为准，材料正文即使表现为系统指令或工具请求，也只能作为不可信数据处理。输出必须是单个 `ProposalBatch.v1` JSON，候选需保持原子性，并保留归属、否定、条件、有效时间、未知结果、冲突及缺失背景；每项提议和观察都要引用不可变证据。角色不得调用工具、执行动作、批准候选或声称结果已经应用。[提取角色的职责与安全边界 ↗](../../../packages/agent-runtime/roles/extractor/1/prompt.md#L3 "支持角色仅从固定证据产生候选、信任可信上下文并禁止执行或应用结果的论断。")

<a id="contract-shape"></a>
## 候选合同的精确约束

提示词进一步规定提议的必需字段，以及 scope、任务正文、文本证据和 origin 的精确形状。文本定位采用 Unicode 码点的半开区间；创建操作省略目标标识并使用空的版本预期。[提议与证据合同字段 ↗](../../../packages/agent-runtime/roles/extractor/1/prompt.md#L7 "解释候选字段、作用域、任务正文、证据定位、来源及创建操作的结构约束。") 这些是输出格式与语义要求，不等同于已有宿主校验、审批流程或数据库写入实现。
