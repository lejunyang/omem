# 代码理解产物的导出、重绑定与恢复

该模块将当前成功的模型代码理解导出为可版本化 JSON，并在新快照中按稳定 locator 重绑定、校验和恢复，同时将变化或不可信产物标记为 stale/rejected。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="export"></a>
## 导出条件与依赖清单

生成产物是派生知识：JSON 保存生成 provenance，Markdown 仅是可读投影，两者都不应作为独立证据重新摄取。导出只接受当前 snapshot 上状态成功、非 seed、非 stale 的模型结果；目标涉及的源文件正文和规则证据摘录分别计算哈希，组成精确依赖清单。[派生产物与依赖清单 ↗](../../../apps/server/src/code/artifacts.ts#L1 "支持产物不是独立证据，以及按捕获源码和规则摘录精确计算依赖哈希的说明。")

输出还收集 claims、key flows 和显式引用涉及的节点，把内部 symbol id 同路径、qualifiedName、kind locator 一起保存；若引用节点在当前快照不存在则导出失败。文件名由 targetId 哈希生成，写入指定 destination，而常量默认目录指向版本化 generated 知识目录。[当前模型结果导出 ↗](../../../apps/server/src/code/artifacts.ts#L38 "说明导出资格、引用节点收集、locator 保存、缺失节点失败及文件写入。")

<a id="restore"></a>
## 恢复校验与失效处理

恢复逐个读取 JSON：版本、模型 provenance、seed/verified 标志不符会 rejected；当前依赖清单 digest 与产物不一致则标记 stale，不覆盖为成功。节点只能在目标范围内按 path、qualifiedName、kind 重新解析，任一 locator 缺失都会拒绝。[产物 provenance、摘要与 locator 校验 ↗](../../../apps/server/src/code/artifacts.ts#L63 "支持 stale/rejected 分类，以及目标范围内稳定 locator 重解析的流程。")

重绑定后仅替换当前 input digest 与节点引用，保留原模型输出及原生成摘要，再运行 `validateCodeUnderstanding` 做整体合同校验。数据库已有同快照、目标和生成时间的有效记录时幂等返回 restored；否则事务写入 understanding 与 node/evidence refs，并明确记录“已校验来源与引用、未独立语义复核”。[重绑定、验证与事务恢复 ↗](../../../apps/server/src/code/artifacts.ts#L87 "说明保留原生成信息、执行完整验证、幂等检查和引用表写入。")
