# omem：从统一材料到可追溯助理

omem 将文档、代码、聊天和图片纳入统一证据链，在此基础上提供可追溯问答、知识阅读和事项跟进。当前已验证中文语义召回、来源更新重核验及部分日常事项闭环，但跨文件调用、检索增强、外部提醒和学习系统仍待完善。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 它解决什么问题

omem 面向“资料很多，但答案、决定和待办容易失去上下文”的个人场景。文档、代码、聊天与图片进入同一材料库；代码额外借助 AST 定位符号和依赖，Code Wiki、回答及学习卡仍是材料的派生视图，而不是各自维护事实。参考 [统一材料与派生视图 ↗](../../../docs/2026-10-01/README.md#L1 "支持所有输入共用材料库，以及代码 AST、Wiki、回答和学习卡不另建事实库的产品定位。")

产品沿两条主线推进：回答能够逐层回到固定原文，明确交办能够持续跟进到提醒、变更与完成。来源变化时，系统会记录受影响范围，重新提取并独立复核相关记忆；阅读深度与模型处理预算则分开管理。参考 [问答引用与代码边界 ↗](../../../docs/2026-10-01/README.md#L9 "支持可逐层打开引用、阅读预算独立管理，以及精确跨文件调用尚未实现的说明。") [来源更新闭环 ↗](../../../docs/implementation/status.md#L13 "支持来源变化后的失效记录、重新提取、独立复核、原子更新和真实模型验证范围。")

<a id="current-capabilities"></a>
## 目前已经能够做什么

当前已有三个可运行切片，但验证环境各不相同。中文语义检索使用固定版中文 BGE 模型和按模型身份隔离的分窗向量；真实仓库索引上的四条中文同义问法均命中目标原文，不过样本很小，不能代表整体检索质量。参考 [中文语义检索现状 ↗](../../../docs/implementation/status.md#L11 "支持中文向量模型、真实仓库索引、小样本检索结果，以及 reranker、ANN 和历史时点检索缺口。")

来源更新闭环已用真实 ACP 模型验证同一记忆从“3 次”更新为“5 次”，旧原文继续保留，且只有全部受影响记忆实际应用后才算完成。日常助手的中文召回及事项创建、改期、完成也经过真实模型验证，但该项使用隔离数据库和合成材料，没有外部发送。参考 [来源更新闭环 ↗](../../../docs/implementation/status.md#L13 "支持来源变化后的失效记录、重新提取、独立复核、原子更新和真实模型验证范围。") [日常助手验证范围 ↗](../../../docs/implementation/status.md#L15 "支持中文召回及事项创建、改期、完成已经验证，并明确隔离数据库、合成材料和无外部发送的边界。")

这些结果不能合并解释为生产环境全面验收。审查口径区分实码事实、本轮行为验证、历史记录和推断建议，旧测试或旧 live 记录不能直接充当当前状态。参考 [审查证据口径 ↗](../../../docs/2026-10-01/02-审查范围与证据口径.md#L7 "支持区分实码事实、行为验证、历史记录和推断建议，避免把旧记录解释为当前生产验收。")

<a id="remaining-work"></a>
## 尚未完成的关键能力

检索已有词法融合、中文 embedding 和原片段分窗索引，但仍缺少 reranker、ANN 与历史时点检索；代码侧的精确跨文件调用也未实现。参考 [中文语义检索现状 ↗](../../../docs/implementation/status.md#L11 "支持中文向量模型、真实仓库索引、小样本检索结果，以及 reranker、ANN 和历史时点检索缺口。") [问答引用与代码边界 ↗](../../../docs/2026-10-01/README.md#L9 "支持可逐层打开引用、阅读预算独立管理，以及精确跨文件调用尚未实现的说明。")

主动跟进当前包括来源更新重核验和站内提醒，自动监听回复、周期回顾、重复提醒及外部到期投递仍需接入。英语学习已确定复用 Capture、固定原文引用、FSRS 调度和稳定 Anki 标识，但卡片、评分与复习页面尚未实现。参考 [后续能力重点 ↗](../../../docs/2026-10-01/README.md#L16 "支持更强召回、主动跟进和英语学习三条主线的现状、设计方向及未完成功能。")

因此，“超强记忆”是可观察的行为目标：支持同义及跨语言召回、跨材料补证、时间与说话人归属、结论替代关系，并在证据不足时明确说明缺口，而不是简单堆叠图数据库或模型框架。参考 [超强记忆的行为定义 ↗](../../../docs/2026-10-01/01-决策摘要.md#L13 "支持用同义召回、跨材料补证、时间归属和证据缺口等真实行为界定目标。")

<a id="reading-guide"></a>
## 如何阅读这套资料

这份目录保存的是完整调研档案，用于解释技术路线与机制取舍，并不等同于当前功能清单。判断现状时应先看实施进度和代码，再通过决策摘要、统一证据内核、检索、事项及学习章节理解背景。参考 [调研档案阅读说明 ↗](../../../docs/2026-10-01/README.md#L22 "说明目录材料用于解释方案，实际能力应以当前实施进度和代码为准。")

统一证据内核把 Source、SourceRevision、FragmentRevision、Claim、Memory、Artifact 与 Action 作为七类核心对象：原始来源及其不可变版本负责追溯，主张和记忆承载治理后的认识，文章与学习卡属于派生产物，事项则具有责任和触发语义。这是一条渐进演进路线，文档明确说明相关字段并非都已落地。参考 [统一证据核心对象 ↗](../../../docs/2026-10-01/03-统一证据内核.md#L5 "支持七类核心对象的具体名称、职责，以及该模型属于渐进建议而非全部现成功能。")
