# omem 产品定位、当前能力与阅读指南

omem 将文档、代码、聊天和图片纳入统一证据链，在可追溯问答之上支持来源更新、事项跟进和未来的学习能力；本文说明已验证闭环、尚存限制及调研文档的阅读方式。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="product-purpose"></a>
## 从记住材料到协助行动

omem 是面向个人知识与日常行动的助手：文档、代码、聊天和图片进入同一材料库，代码额外使用 AST 定位结构；回答、Code Wiki 和学习卡则是从材料生成的视图，不另建事实库。用户可以追问代码为何如此实现、用中文检索英文资料、管理带时间的事项，也可以在来源变化后重新核验已有结论。参考 [统一材料与使用场景 ↗](../../../docs/2026-10-01/README.md#L1 "支持 omem 的产品定位、统一材料库设计以及代码问答、跨语言检索、事项和来源更新等使用场景。")

统一并不意味着所有对象同形。原始版本、可核验主张、长期记忆、派生文章和可执行事项各自承担不同职责，但都应回到固定证据；派生内容不能因此成为新的独立来源。参考 [证据对象分层 ↗](../../../docs/2026-10-01/03-统一证据内核.md#L9 "解释原始来源、主张、记忆、派生产物和行动对象共享证据但保持不同语义职责。")

<a id="current-capabilities"></a>
## 已跑通的闭环与现实边界

现有材料记录了多条真实闭环：中文问题能召回英文原文中的具体阈值；一次性事项可以创建、改期和完成；来源由“重试 3 次”更新为“5 次”后，同一记忆会重新分析、独立复核并更新，同时保留旧原文。参考 [已验证的日常闭环 ↗](../../../docs/2026-10-01/README.md#L7 "支持跨语言召回、一次性事项变更完成以及来源更新后重核验并保留历史的结论。")

主动跟进已不止于普通到期提醒：系统能够保存等待对象、独立跟进时间和暂缓状态，并验证了“等待创建→暂缓→重启→取消”的流程。当前缺口是**自动监听对方回复**、周期回顾、重复提醒和外部到期投递，而不是尚未具备等待事项跟进。参考 [等待事项跟进状态 ↗](../../../docs/implementation/status.md#L3 "证明等待对象、跟进时间、暂缓与取消流程已经实现，并明确尚缺自动回复监听、周期回顾、重复提醒和外部投递。")

检索已经加入中文向量和原片段分窗索引，但仍缺语义重排、近似向量索引和历史时点检索；英语卡片、评分与复习页面也尚未实现。因此，单项实测只能证明对应场景成立，不能外推为完整产品已经交付。参考 [检索与学习能力边界 ↗](../../../docs/implementation/status.md#L7 "支持中文向量检索的当前能力和重排、历史检索等限制，并说明英语学习功能仍未交付。")

<a id="reading-guide"></a>
## 如何使用这组调研文档

本目录的十三章与两份附录是基于旧代码基线形成的方案与证据档案，解释统一证据、检索、Code Wiki、主动事项、学习和质量治理等取舍；它们不是当前实现清单，判断现有能力应优先查看实施状态与代码。参考 [调研档案定位 ↗](../../../docs/2026-10-01/README.md#L16 "说明这组文档基于旧基线，实际能力应以当前实施状态和代码为准。")

首次阅读可从决策摘要进入，再结合迁移、风险和证据口径理解推进边界；关注知识主线时阅读第 3 至 7 章，关注日常跟进或英语学习时分别进入第 8、9 章。验证附录和固定版本证据索引用于区分本轮实测、历史记录与设计建议。参考 [章节阅读顺序 ↗](../../../docs/2026-10-01/README.md#L49 "支持按决策、知识主线、日常事项、英语学习和验证边界组织阅读路径。")
