# omem 目标、当前能力与调研导航

该文档以日常场景说明 omem 的统一证据系统定位，区分已验证的检索、事项、手动等待和来源更新闭环，以及仍待实现的语义重排、自动监听回复、周期治理、外部投递和英语学习能力；后半部分是旧基线调研目录，不能视为当前实现清单。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="product_direction"></a>
## 产品定位与统一证据主线

omem 是“先记得住、再帮你办事”的个人助手：文档、代码、聊天和图片进入同一材料库，代码只增加 AST 定位能力；回答、Code Wiki 和学习卡都是原始材料的派生视图，不另建事实库。引用可以逐层阅读，而检索和模型预算独立控制。[统一材料库与引用阅读原则 ↗](../../../docs/2026-10-01/README.md#L1 "支持多类输入汇入同一材料库、派生内容不另建事实库，以及阅读深度与计算预算分离的产品定位。") 这与总体决策一致：记忆、事项、学习和代码知识共享证据底座，但保留各自的对象语义与操作流程。[统一证据系统总体决策 ↗](../../../docs/2026-10-01/01-决策摘要.md#L3 "说明 Code Wiki、记忆、事项和学习共享证据系统，但不被强行建模为同一种对象。")

<a id="verified_and_limited"></a>
## 已验证场景与能力边界

四个场景体现当前切片：代码问答已有统一引用链，但精确跨文件调用仍缺失；中文问法召回英文材料已有真实结果；带时间事项已验证创建、改期、完成；来源内容变化后可更新同一记忆并保留旧原文，且只有实际应用成功才算闭环。[四个日常场景及进展 ↗](../../../docs/2026-10-01/README.md#L5 "支持代码问答、跨语言召回、事项闭环和来源更新四类场景的已验证范围及限制。") 最新状态还记录了中文向量检索和来源重核验，但 reranker、历史时点检索、周期全库巡检等仍未完成，因此这些结果不能外推为完整产品验收。[检索与来源更新最新状态 ↗](../../../docs/implementation/status.md#L5 "补充中文向量检索、来源重核验的当前实现证据，并限定尚未交付的重排、历史检索和周期巡检能力。")

<a id="remaining_work"></a>
## 后续工作与被替代的旧概括

主动跟进已不再只是“来源变更和站内提醒”：网页日常助理现已支持手动创建等待事项、记录等待对象、暂缓、取消，并在重启后离线补发一次；这部分已通过真实 ACP 流程验证。仍未接入的是**自动监听对方回复**、周期回顾、重复提醒和外部到期投递。[手动等待事项闭环 ↗](../../../docs/implementation/status.md#L1 "支持等待对象、暂缓、取消、离线补发一次已经实现，并准确列出自动监听回复等剩余缺口。") 因而旧 README 将“等待别人回复”整体列为待接入的概括已被上述结论收窄，不再代表当前边界。[主动跟进旧概括 ↗](../../../docs/2026-10-01/README.md#L16 "标出 README 中将等待回复整体列为待接入的旧表述，说明其已被最新实施状态收窄和替代。") 其余主线仍包括语义重排与英语学习卡；后半部分十三章和附录是基于 `94aafe9` 的调研档案，当前能力应以实施状态和代码为准。[调研档案目录与当前状态入口 ↗](../../../docs/2026-10-01/README.md#L22 "说明后半部分是旧基线调研档案，选型背景与当前已实现能力需要分开判断。")
