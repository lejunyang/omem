# OmMarkdown：安全的 Markdown 与内联证据引用渲染

该组件把 Markdown、代码高亮和证据引用转换为经过清洗的 HTML，并将引用、站内链接和外部链接分流为不同交互；它同时处理异步竞态、失败回退和不可用引用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-flow"></a>
## 作用与核心流程

组件解决“富文本可读性”与“不可信 HTML 安全性”并存的问题。`source` 或引用表变化后异步加载 Markdown 解析器和清洗器，将 `[[引用键]]` 替换为带人类标签的链接或不可用提示，再调用共享代码高亮器处理代码块。最终 HTML 只允许有限标签、属性和 URI 协议，并仅由最新一轮渲染写入视图，避免快速切换材料时旧结果覆盖新结果。[Markdown 编译、引用替换与清洗流程 ↗](../../../packages/ui/src/components/OmMarkdown.vue#L25 "支持组件如何异步解析引用、突出显示代码、限制 HTML 能力并用 generation 防止旧结果覆盖的说明。")

渲染成功后使用事件委托区分三类点击：证据引用发出 `cite`，HTTP、邮件和电话链接在新窗口打开并补充隔离属性，其余相对路径发出 `navigate-internal`，因此路由和证据抽屉仍由父组件控制。[链接点击分流逻辑 ↗](../../../packages/ui/src/components/OmMarkdown.vue#L69 "支持引用、外部链接和内部路径分别交给不同交互出口的论断。")

<a id="boundaries"></a>
## 边界与退化行为

空正文直接清空结果；依赖加载、解析、高亮或清洗任一步失败时，组件不继续展示残留 HTML，而是显示原始 Markdown。未知引用不会变成可点击目标；已知但不可操作的引用会显示原因。[加载状态与失败回退界面 ↗](../../../packages/ui/src/components/OmMarkdown.vue#L84 "支持渲染失败后显示原文以及正常结果通过 v-html 呈现的说明。")

该组件依赖 `highlightCode` 的语言映射与转义策略；未知语言只转义代码，已知语言才动态加载语法包。这里没有材料证明外部链接是否应在点击前就带 `target`，也没有提供测试文件，因而异步竞态、清洗规则及键盘激活引用的覆盖情况无法确认。[共享代码高亮实现 ↗](../../../packages/ui/src/highlight.ts#L21 "说明 OmMarkdown 所调用高亮模块对已知语言动态加载、对未知语言安全转义的边界。")
