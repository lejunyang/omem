# 对话分析角色的知识输出合同

该文件定义 KnowledgeBatch.v1 的封闭 JSON 结构，约束批次、文档、章节、引用和疑问的字段及数量边界。修订后不再把 Markdown、运行时校验或修复重试归因于 Schema 本身；这些能力需分别由角色提示或运行时实现证明。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="batch-document"></a>
## 批次、文档与章节结构

合同把顶层版本固定为 1，并要求批次包含 1–16 个文档；文档可归入概览、架构、需求、进展、实现、测试、配置、对话等类别。[批次规模与知识类别 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L1 "支持版本常量、文档数量范围以及文档类别枚举的说明。") 每个文档必须具有键、标题、摘要、类别、章节、引用和问题，文档对象及顶层对象都拒绝未声明字段；这证明输出结构是封闭的，但不能单独证明运行时如何解析或校验它。[文档必填字段与封闭对象 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L209 "支持文档必填字段、文档对象拒绝额外属性以及顶层必填字段和封闭结构的论断；同时界定这些只是声明性约束。")

每篇文档需包含 1–20 节，章节键须以字母开头且只能使用字母、数字、下划线和连字符；标题最长 200 字符，正文字段是最长 24000 字符的非空字符串。[章节字段约束 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L48 "支持章节数量、键命名规则、标题长度、正文字符串长度以及章节对象封闭性的说明。") 正文采用 Markdown 并将引用贴近论断，是角色提示规定的生成要求，而不是该 JSON Schema 对字符串格式的验证。[角色正文与引用编排要求 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/prompt.md#L4 "支持正文使用 Markdown、引用贴近对应论断以及每节至少放置引用的生成要求，并表明该要求来自角色提示而非 Schema 字符串格式。")

<a id="evidence-questions"></a>
## 证据链接与显式不确定性

每篇文档至少要有一条引用。引用包含人读标签、理由、关系和目标；目标可以指向材料或文章，材料目标可记录固定行号。`quote` 字段的描述要求留空，并声明由宿主依据固定范围提取精确引文后再独立复核，但这只是合同中的行为约定，尚不能证明对应宿主流程已经实现。[引用目标与引文约定 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L78 "支持引用关系、材料或文章目标、固定行号以及 quote 留空并由宿主提取的合同描述。")

问题数组最多包含 20 项，每项必须记录具体问题、提出原因、下一步、是否阻塞及关联引用键，用于显式保存尚未确认的事项。[疑问项结构 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L166 "支持疑问数量上限及 question、why、nextStep、blocking、citationKeys 等必填追踪字段的说明。") 先前把封闭对象结构解释为有利于“修复重试”的结论已被替代：本文件只能证明必填字段和额外属性限制，重试策略仍需角色清单、运行网关或行为测试佐证。[文档必填字段与封闭对象 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L209 "支持文档必填字段、文档对象拒绝额外属性以及顶层必填字段和封闭结构的论断；同时界定这些只是声明性约束。")
