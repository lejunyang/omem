# 会话分析角色的知识批次输出合同

该文件定义 KnowledgeBatch.v1 的 JSON Schema：一次输出包含 1–16 篇结构化知识文档，每篇文档包含摘要、分类、正文小节、引用和待确认问题。它约束输出形态与字段边界，但不能单独证明引用定位方式、跨字段一致性检查或独立复核已在运行时执行。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="batch_structure"></a>
## 批次与文档结构

该合同采用 JSON Schema 2020-12，顶层版本固定为 `1`，并要求 `documents` 至少一项、至多十六项。[顶层版本与文档批次约束 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L1 "支持 schema 版本固定为 1，以及 documents 数量限制为 1 至 16 项。") 每篇文档必须提供 `key`、`title`、`summary`、`category`、`sections`、`citations` 与 `questions`，文档对象禁止未声明字段。[文档必填字段与封闭边界 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L208 "支持每篇文档的七个必填组成，以及文档对象禁止未声明字段。")

分类枚举覆盖概览、架构、背景、需求、进展、实现、测试、配置、工作流、研究、会话和视觉材料，说明同一合同可承载多类知识文档；这只是输出分类能力，不代表相应分析流程均已实现。[知识文档分类枚举 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L31 "说明合同允许表达的十二类知识文档。")

<a id="content_and_evidence"></a>
## 正文与证据引用

正文由一至二十个小节组成；每节必须包含键、标题和正文，小节键遵循固定格式，且对象禁止额外字段。[正文小节结构约束 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L48 "支持小节数量、键格式、正文类型、必填字段及小节对象封闭性的说明。") 引用列表要求至少一项、最多一百六十项；每条引用必须包含键、人读标签、理由、关系、目标和引文内容，关系值限于合同列出的枚举。[引用条目的关系与必填字段 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L78 "支持引用数量、关系枚举，以及引用条目的必填组成。")

引用目标的 `kind` 可标记为 `material` 或 `article`，目标还可携带起止行或章节字段；但 schema 没有按目标类型建立条件约束，因此此前“材料使用行号、文章使用章节”的结论被替代，不能仅凭本文件认定这种对应关系。[引用目标字段与引文抽取描述 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L112 "支持目标类型、可选定位字段和 quote 描述，同时表明 schema 未按目标类型条件限制定位字段。") `quote` 的描述约定宿主从固定行范围抽取精确引文，但不证明抽取与语义复核已经执行。[引用目标字段与引文抽取描述 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L112 "支持目标类型、可选定位字段和 quote 描述，同时表明 schema 未按目标类型条件限制定位字段。")

<a id="questions_and_limits"></a>
## 问题记录与合同边界

每篇文档可以记录至多二十个问题，每项必须包含问题、原因、下一步、阻塞状态和关联引用键；这使未确认事项能够结构化保留，而不必混入已确认结论。[结构化问题字段 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L166 "支持问题数量上限、必填信息和对象封闭规则，并显示 citationKeys 仅定义为字符串数组。")

顶层仅要求 `schema_version` 与 `documents`，禁止其他顶层属性，并以 `KnowledgeBatch.v1` 标识合同。[顶层合同标识与封闭边界 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L220 "支持顶层必填字段、禁止额外顶层属性以及 KnowledgeBatch.v1 合同标识。") 同时，正文只是普通字符串，`citationKeys` 也只是字符串数组；schema 没有表达正文标记或问题引用键必须匹配本篇 `citations.key` 的跨字段约束。[正文小节结构约束 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L48 "支持小节数量、键格式、正文类型、必填字段及小节对象封闭性的说明。")[引用条目的关系与必填字段 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L78 "支持引用数量、关系枚举，以及引用条目的必填组成。")[结构化问题字段 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/output.schema.json#L166 "支持问题数量上限、必填信息和对象封闭规则，并显示 citationKeys 仅定义为字符串数组。") 若需避免悬空引用，仍要由消费端或独立验证器补充检查。
