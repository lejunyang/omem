# 现行产品原则、信任边界与工程约束

系统当前以个人助手和单用户实现为边界，统一接收多模态材料及上下文信息，并以不可变修订、固定引用、能力协商和风险分级自治维持信任。外部集成必须获得明确授权；设计合同和 v3 验收方案提供评价尺度，但不能替代当前实现、真实行为测试和 live 检查证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="product-boundary"></a>
## 个人优先、统一输入与执行边界

系统先服务个人并保留团队化架构，飞书主 Agent 是主要入口，Web 是后台与第二入口；模型先经 Agent CLI／ACP 接入，不要求本地大模型。[已确认的个人助手与自治方向 ↗](../../../docs/decisions.md#L7 "支持个人优先、飞书主入口、CLI／ACP 模型接入、文本图片链接输入，以及高置信变更自动执行并逐次通知的已确认方向。") 当前 SQLite／共享令牌实现明确属于单用户，不能据此宣称租户隔离；执行器还应发现模型与 effort 能力，并明确拒绝不支持的组合。采集入口统一容纳文本、图片、链接及上下文元数据，而采集内容只是资料，不能自动成为工具指令。[模型、单用户、采集与证据边界 ↗](../../../AGENTS.md#L7 "支持模型能力协商、当前单用户限制、包含上下文元数据的统一采集格式、材料非指令、派生回答非独立证据及自治风险分级。") 已确认的产品方向可从相关子知识继续下钻。[产品与技术方向子知识 ↗](3d9dcd2cda0171189ad65dc88b7556f56e6ba30ac99dc5b91fc236fd4182b50a.md#direction "提供已确认产品方向的可读下钻入口；事实依据仍由相邻原始决策记录承担。")

<a id="evidence-trust"></a>
## 不可变证据与阅读体验

Source、Fragment 等稳定身份用于跨版本追踪，Revision 固定某一时刻的内容；正文和引用不得以原地修改方式抹去历史。[稳定身份与不可变修订 ↗](../../../docs/contracts/evidence-model.md#L9 "支持稳定对象身份与固定内容修订相分离，以及引用目标具有明确版本和建立原因。") “提到、派生、相关”与事实支持必须分开，支持关系不能沿多跳引用自动传递，多来源结论仍受证据可见性约束。[关系类型与支持边界 ↗](../../../docs/contracts/evidence-model.md#L60 "支持引用、派生、相关和事实支持不可混同，以及多跳引用不能自动传递支持、多来源结论仍受权限约束。") 派生回答不是新的独立证据；即使沉淀为候选，也必须回连原始材料。该约束由现行实施规范直接规定，而不是由对象字段本身自动保证。[模型、单用户、采集与证据边界 ↗](../../../AGENTS.md#L7 "支持模型能力协商、当前单用户限制、包含上下文元数据的统一采集格式、材料非指令、派生回答非独立证据及自治风险分级。") 身份与关系语义可继续阅读证据合同子知识。[身份、修订与时间子知识 ↗](50da9c46d13d25d85f422c347556156e681b21cca601ede71decbc47663425dc.md#identity "提供稳定身份、不可变修订和证据关系语义的分层阅读入口，不把派生概括视为新的事实依据。")

阅读侧要求引用贴近论断并固定到 FragmentRevision；共享 trail 支持逐层进入、返回、循环跳回、滚动与草稿记忆，关闭后恢复焦点，同时保留背景文章状态。[固定引用与层级阅读合同 ↗](../../../design.md#L24 "支持材料非指令、固定版本引用、逐层导航、循环返回、局部状态保存以及背景文章状态保留。") 对应组件和引用链规范可从界面子知识继续下钻。[共享组件与引用阅读链 ↗](af6730747f968f510fcb4a1f5002576de90ca519c166dc3e51e3ed61244a966e.md#components-trail "提供共享 UI 组件和引用 trail 交互要求的子知识下钻入口。")

<a id="autonomy-integrations"></a>
## 自治变更与外部授权

普通、高置信且小范围的变更可以自主执行，但每次都应通知修改内容；歧义、背景不足、范围过大或危险操作需要用户决策。[已确认的个人助手与自治方向 ↗](../../../docs/decisions.md#L7 "支持个人优先、飞书主入口、CLI／ACP 模型接入、文本图片链接输入，以及高置信变更自动执行并逐次通知的已确认方向。")[模型、单用户、采集与证据边界 ↗](../../../AGENTS.md#L7 "支持模型能力协商、当前单用户限制、包含上下文元数据的统一采集格式、材料非指令、派生回答非独立证据及自治风险分级。") 这取代了此前仅由工程验证条款支撑自治分级的宽泛表述，使自治依据与通知要求直接对应已确认决策。

外部通知、采集范围变化、屏幕观察、全局 hooks 和操作系统服务属于独立集成，必须具有具体范围并保留用户配置；真实连接、采集和投递还取决于当前配置与授权。[验证、提交与外部集成纪律 ↗](../../../AGENTS.md#L11 "支持真实行为验证、切片提交、共享工作区暂存纪律，以及外部通知、采集范围和系统服务必须单独授权。") 因此，“允许助理主动工作”不等于默认授权其扩大观察范围、向外发送消息或执行不可逆操作。

<a id="progress-acceptance"></a>
## 进展判断、验证与发布纪律

能力只能依据实施状态和真实行为判断，早期架构或原型不能当作已交付证明；后续应按带测试的具体垂直切片推进。[能力判断与垂直切片原则 ↗](../../../AGENTS.md#L3 "支持设计提案不等于已实现，并要求后续工作以带测试的具体垂直切片推进。") 每个切片须用真实退出码、行为断言及必要的浏览器检查验证，协议 fixture 不能代替外部 CLI 的 live 检查；通过后应连同测试和文档独立提交，共享工作区只暂存目标改动，推送仍需明确请求。[验证、提交与外部集成纪律 ↗](../../../AGENTS.md#L11 "支持真实行为验证、切片提交、共享工作区暂存纪律，以及外部通知、采集范围和系统服务必须单独授权。")

v3 的 G01–G20、Scenario 指标和初始硬门被明确标为待实现验收，覆盖主体身份、隐私、多模态材料、停止语义、降级和引用回查，不能把当前缺陷行为或设计文本算作通过。[待实现回归场景与任务指标 ↗](../../../docs/implementation/assistant-v3/migration-and-acceptance.md#L84 "支持 G01–G20 属于待实现验收，并说明 Scenario 评估、分项指标和初始硬门的范围。") 相关验收子知识提供逐项下钻入口，但仍不是完成证明。[主助手 v3 验收子知识 ↗](a887b2703426a0e4e972df13e531db16ecbfacac9c5f22ebb07a792c1872a095.md#acceptance "提供回归场景和价值评估的可读下钻入口，同时保持其待实现状态，不将派生总结当作完成证明。")
