# 现行产品原则、信任边界与工程约束

omem 以个人助理为当前落点，把多来源材料、记忆、任务和代码知识纳入同一可追溯证据链。系统允许低风险自治，但严格区分材料、派生结果与已验证事实；当前实现仍是单用户边界，部分主助手 V3 能力处于待实现或待验收状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="product-purpose"></a>
## 个人助理与统一证据体系

omem 首先服务个人：飞书主 Agent 承担对话和知识治理入口，Web 作为后台与第二入口；系统既要长期运行，也要支持本地部署，并通过可配置的 Agent CLI/ACP 使用大模型。首批输入覆盖飞书、Git、文本、Agent 会话等来源，统一承载文本、图片和链接。参考 [已确认的产品方向 ↗](../../../docs/decisions.md#L7 "支持个人优先、飞书主入口、部署方式、模型接入以及首批材料范围。")

这些输入不是彼此割裂的知识库。代码可以使用 AST 做专门解析，但 Code Wiki、文章与结构图仍应落在统一的来源、修订和片段证据链上。现有捕获合同已经为多种来源、三类内容部件及部件级来源信息定义了共同数据形状。参考 [统一记忆目标 ↗](../../../AGENTS.md#L1 "支持代码 AST 特化仍属于统一记忆体系，且调研方案不能视为已实现能力。")、[统一捕获合同 ↗](../../../packages/contracts/src/index.ts#L4 "支持多来源捕获、文本图片链接部件以及部件级来源信息的数据形状。")

<a id="trust-boundary"></a>
## 材料、推断与事实的信任边界

采集内容始终是**待理解的数据**，不能因为其中出现命令、待办或断言就直接执行或认定为事实。可信工作区、主体绑定和来源属性由宿主提供，并与模型读取的材料分开；多参与者内容应保留各片段的身份与时间，而不是拍平成未知主体。参考 [可信上下文与材料分离 ↗](../../../packages/contracts/src/index.ts#L755 "支持宿主可信上下文、主体绑定与模型材料分离，并保留片段级来源属性。")

引用、语义相关、派生和事实支持也具有不同含义：提到某材料或由它生成摘要，并不自动证明结论；只有经过证据评估的原子主张支持才能承担事实依据，多跳引用不能自动传递支持。参考 [证据关系语义 ↗](../../../docs/contracts/evidence-model.md#L58 "支持引用、派生、相关与事实支持的区别，以及支持不能沿引用链自动传递。")

系统以稳定对象身份追踪同一来源或片段，以不可变修订固定“当时看到的内容”；遇到重复段落或大幅改写时保留候选继任，而不是偷偷续接。有效时间与系统获知时间分开，避免后补材料篡改历史认知。参考 [身份、修订与双轴时间 ↗](../../../docs/contracts/evidence-model.md#L9 "支持稳定身份和固定修订分工、歧义续接处理以及有效时间与获知时间分离。")

<a id="autonomy-and-safety"></a>
## 自治、权限与可恢复变更

普通且高置信度的变化可以自动完成，但每次都要向用户说明；歧义、背景不足、大范围或危险操作需要用户决定。扩大采集范围、安装系统监听器和外部通知属于独立集成，不能从一般自治授权中推导出来。当前 SQLite 与共享令牌方案明确是单用户实现，尚不能宣称具备租户隔离。参考 [自治与权限边界 ↗](../../../AGENTS.md#L8 "支持单用户现状、高置信度自治、例外决策及外部集成需要明确范围。")

变更必须区分“已排队”“已提议”和“已应用”。事实更新应产生新修订并保留历史，失败不能显示成功；界面同样必须呈现真实的服务、模型和操作状态，不能用模拟回答掩盖未连接能力。参考 [真实界面行为 ↗](../../../design.md#L50 "支持动作、服务、模型和通知必须反映真实结果，失败不得伪装为成功。")

迁移还要保护原件、固定片段、正式记忆、任务、变更和投递历史。已取消的会话不得自动重启，旧作用域也不能未经业务依据就转换为项目归属。参考 [迁移与历史保护 ↗](../../../docs/implementation/assistant-v3/migration-and-acceptance.md#L19 "支持保留权威历史、维持取消状态并禁止静默转换旧作用域。")

<a id="progress-and-verification"></a>
## 当前进展口径与工程验收

现行材料明确把主助手 V3 的停止控制、保真输入、检索、飞书主入口、注意力门控和反馈评测列为待实现改造；其中检索与主入口可在接口稳定后并行，外部检索 PoC 不是主助手的前置条件。因此设计方案、合同类型或原型都不能单独作为功能已经交付的证明。参考 [主助手改造状态 ↗](../../../docs/implementation/assistant-v3/migration-and-acceptance.md#L1 "支持 V3 工作仍标为待实现、各切片顺序及检索 PoC 不是主入口前置条件。")

仓库知识本身也是验收材料。捕获、AST、知识生成、引用、检索或助理运行发生变化后，应先检查并提交实现，再由真实模型生成、独立复核和更新知识资产；覆盖状态需区分已复核、过期、待处理和失败，检索还要通过真实 HTTP 查询验证。参考 [仓库知识验收流程 ↗](../../../AGENTS.md#L16 "支持实现与知识资产分开提交，以及真实生成、复核、覆盖检查和检索验证要求。")

Code Wiki 当前还有明确限制：跨文件调用尚不解析，跨修订符号和片段身份续接未实现，代码变化后需要重新同步定位。内部标识只能用于路由，缺失或过期目标必须禁用并给出人读原因。参考 [Code Wiki 现行边界 ↗](../../../AGENTS.md#L28 "支持内部标识展示限制、统一知识运行时，以及跨文件调用和跨修订续接尚未实现。")
