# other · 模块理解

该模块集合是个人助手的服务器共用层：采集形成固定证据，单用户 SQLite 承载修订、作业与投递状态，受控学习、助手治理和仓库适配在其上生成可追溯视图。已验证多项幂等与恢复路径，但团队权限、依赖自动复核、真实外部服务兼容性及跨修订代码身份仍未闭环。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-foundation"></a>
## 职责与设计背景

“other”并非单一业务模块，而是采集、存储、作业、知识、助手与代码评审的共用底座。当前以单用户 SQLite 保存固定证据、变更和通知 outbox，不能据此宣称具备团队租户隔离。[服务器可靠性底座 ↗](739ea31d68edbd56041f02c23fac65549a179fc6d4e76a67dcc9b55a47416e9c.md#foundation "支持单用户 SQLite、固定证据链以及团队能力仍属后续迁移的范围说明。") 原始材料进入提取队列，模型生成的派生材料被排除，避免总结再次成为独立证据。[采集与入队流程 ↗](739ea31d68edbd56041f02c23fac65549a179fc6d4e76a67dcc9b55a47416e9c.md#capture-flow "支持 hook 暂存、聊天与屏幕聚合、来源更新、采集回执，以及原始材料入队和派生材料不回流的边界。")

受控学习的身份、冲突、影响门禁和依赖刷新状态可沿学习流程核对；检索画像与质量评测属于另一条验收链，不能由存储章节一并代表。[受控学习与依赖刷新 ↗](7d1bb9f9cbb3c559e15a31a7d7725d78adb5d7aaea8b427f4958665b70282738.md#learning-flow "支持提案的身份、证据、冲突和影响分流，以及依赖刷新尚未实现的当前状态。")[检索与质量闭环 ↗](7d1bb9f9cbb3c559e15a31a7d7725d78adb5d7aaea8b427f4958665b70282738.md#retrieval-quality "支持来源画像、有效记忆过滤和分维度质量评测，作为独立于存储迁移的下钻入口。")

<a id="main-flow"></a>
## 从输入到知识与行动

hook 输入可先离线暂存；聊天与屏幕事件经过有界聚合、正文去重和迟到事件处理，再由采集流程保存回执、更新来源状态，并按原始或派生属性决定是否进入提取队列。[采集与入队流程 ↗](739ea31d68edbd56041f02c23fac65549a179fc6d4e76a67dcc9b55a47416e9c.md#capture-flow "支持 hook 暂存、聊天与屏幕聚合、来源更新、采集回执，以及原始材料入队和派生材料不回流的边界。") 固定材料随后由耐久作业处理，租约、fencing token、分类重试和独立复核约束结果发布；来源变化会令依赖失效，但自动复核尚未完成。[耐久作业与知识形成 ↗](739ea31d68edbd56041f02c23fac65549a179fc6d4e76a67dcc9b55a47416e9c.md#durability-and-knowledge "支持租约竞争、fencing token、分类重试、独立复核和来源变化后的知识失效。")[受控学习与依赖刷新 ↗](7d1bb9f9cbb3c559e15a31a7d7725d78adb5d7aaea8b427f4958665b70282738.md#learning-flow "支持提案的身份、证据、冲突和影响分流，以及依赖刷新尚未实现的当前状态。")

助手侧另设写入治理：群聊证据受范围过滤，明确任务与咨询分流。模型不可用时不会生成伪答案；现有中断和超时测试直接证明的是零任务写入，不能扩大为所有场景都不会产生任何回答。[助手写入治理 ↗](eea921ee27b870dfaf9d99e2df74fef56ed462e810c64b69a871b7c7a6917fe8.md#assistant-governance "支持任务与咨询分流、群聊证据隔离、模型不可用不生成伪答案，以及已测中断和超时保持零任务的精确边界。") 原始路由测试明确验证缺少 profile 和 CLI transport 均被拒绝；所给范围不证明 ACP 子进程成功启动或完整运行。[ACP 路由拒绝测试 ↗](../../../apps/server/tests/acp-model.test.ts#L25 "原始测试直接证明未配置 profile 和 CLI transport 被拒绝；该范围不用于声称 ACP 子进程成功启动或完整失败行为。")

<a id="code-and-relations"></a>
## 代码知识与跨模块关系

仓库适配器将固定代码快照投影为文件、符号、关系和理解结果。人工 seed 与模型结果都须解析到当前代码图并通过确定性引用校验；异常输出不会替代有效理解，快照变化则使旧理解陈旧。[代码理解生成与替代 ↗](607f542777d15c88b17c800dc7ef520b9da8bf6ab2ab86fcad7f33dd0cddaaf8.md#understanding_flow "支持 seed 定位、模型结果校验、失败隔离，以及快照变化后旧理解陈旧和新结果替代的流程。")

此前“正文引用、repo-review 关系和个人知识已经端到端共用同一关系及阅读合同”的结论已被替代。现有证据分别覆盖普通片段链接与专用评审关系，[统一关系能力的证据边界 ↗](a39b9cdb1225ba6c8bef555f5a7fa616adddef9a1dcdcb378deacc882d541142.md#evidence-foundation "支持收窄旧结论：现有材料只证明普通片段链接和 repo-review requirement 关系，尚未证明三类入口端到端共用同一存储与阅读合同。") 也覆盖知识角色运行时中的宿主绑定固定引用；[受控角色运行时 ↗](a39b9cdb1225ba6c8bef555f5a7fa616adddef9a1dcdcb378deacc882d541142.md#role-runtime "支持知识角色由宿主绑定固定引用，并说明能力协商与故障隔离结论来自本地夹具而非真实 ACP CLI 验收。") 但尚未证明三者共享目标解析、失效投影和 Evidence Trail 导航。
