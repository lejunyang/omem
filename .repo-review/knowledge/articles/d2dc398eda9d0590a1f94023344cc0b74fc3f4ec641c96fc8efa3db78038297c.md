# 飞书凭据加密存储

以环境主密钥和 AES-256-GCM 在本地持久化飞书凭据，提供受限引用、原子写入、认证解密与配对码 HMAC 摘要能力；调用方如何保存配对码尚未由材料证明。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="key-and-reference"></a>
## 密钥与引用约束

该模块把应用 ID 和 client secret 保存到独立秘密文件，并向调用方返回形如 `lark:<UUID>` 的引用。主密钥可使用 64 位十六进制或 Base64 表示，但解码后必须恰好 32 字节；生产构造要求环境变量存在。目录权限被收紧为仅所有者访问，引用还需通过严格格式校验后才能映射为文件路径，以限制任意路径访问。[主密钥与安全引用 ↗](../../../apps/server/src/integrations/lark/secret-store.ts#L22 "支持主密钥长度校验、环境变量要求、秘密目录权限和引用格式限制的说明。")

<a id="persistence"></a>
## 认证加密与持久化边界

每次写入生成随机 12 字节 IV，使用 AES-256-GCM 保存格式版本、算法、IV、认证标签和密文。内容先写入独占临时文件并 fsync，再原子重命名、设置 0600 权限并尽力同步目录；读取时检查格式，并由 GCM 认证标签检测错误密钥或内容篡改。删除文件后也会尝试同步目录。[AES-GCM 原子持久化 ↗](../../../apps/server/src/integrations/lark/secret-store.ts#L59 "支持认证加密、临时文件写入、fsync、原子重命名、格式校验、解密和删除流程。")

模块另提供带 `omem-lark-pairing-v1` 用途域分隔的 HMAC-SHA256 配对码摘要方法。[配对码 HMAC 方法 ↗](../../../apps/server/src/integrations/lark/secret-store.ts#L134 "支持该模块能够以当前主密钥和用途域分隔生成配对码摘要，但不证明调用方的保存策略。") 这仅证明可生成摘要，不能证明配对流程只保存摘要、更不能据此断言明文码绝不落盘；该限定替代了此前过强的持久化结论。密文虽含格式版本，但接口只持有一个当前主密钥，尚未展示旧密钥回退或轮换事务。
