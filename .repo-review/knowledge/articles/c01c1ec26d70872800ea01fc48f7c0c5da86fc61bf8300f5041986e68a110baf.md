# contracts · 模块理解

contracts 模块集中定义捕获、证据提案、任务流、Agent 运行与知识流水线的运行时交换边界，并为 repo-review 提供普通 TypeScript 读视图及共享路径分组。它能证明数据形状与局部不变量，但不能证明阶段编排、持久化、状态迁移、过期处理或 AST 同步的实际行为。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-background"></a>
## 职责与背景

该模块位于捕获入口、Agent 角色、任务跟进、知识生成与 repo-review 之间，用共享合同统一各端可交换的数据。捕获支持文本、图片与 HTTP(S) 链接，并可保留部件级参与者、事件和转发等来源信息；Agent 上下文进一步把可信信封与待分析材料分开，且每项材料至少含文本或图片。[统一捕获与部件来源合同 ↗](../../../packages/contracts/src/index.ts#L4 "支持捕获输入统一承载文本、图片、链接以及部件级来源信息。")[可信上下文与材料边界 ↗](../../../packages/contracts/src/index.ts#L755 "支持可信信封与材料数组分离，并要求每项材料至少包含文本或图片。")

路径分组函数则**设计用于** Wiki 索引与 Vue 阅读器共享：它依次识别固定模块、Lark、服务端目录、脚本与兜底类别。现有材料只有用途注释和分类实现，不能据此确认两个消费端已经实际调用同一函数。[共享路径分组的设计意图 ↗](../../../packages/contracts/src/code-modules.ts#L1 "支持该函数设计用于 Wiki 索引和 Vue 阅读器共享，并说明分类分支顺序；不作为实际调用证据。")

<a id="contract-families"></a>
## 证据、提案与任务合同

合同分别定义多个阶段的数据形状，而非证明一条已经运行的固定流程：文本证据绑定修订、精确引文与 Unicode 区间，图片证据绑定资产哈希、观察和可选区域；任务、事实、经历、流程四类提案共享作用域、证据、不确定项和版本前置条件。[证据与四类提案合同 ↗](../../../packages/contracts/src/index.ts#L214 "支持证据锚点、四类提案、任务提案复用跟进 Schema，以及更新和取代的版本前置条件。") 证据评估又分别记录引文或资产有效性与语义裁决，人工决策绑定动作、提案摘要、请求和操作者；这些定义仍需运行时材料补证其调用顺序和应用条件。[证据评估合同 ↗](../../../packages/contracts/src/index.ts#L415 "支持引文或资产有效性和语义裁决被分别记录。")[人工评估与决策输入 ↗](../../../packages/contracts/src/index.ts#L497 "支持人工评估字段及 approve、reject、request_context 决策所绑定的摘要、请求和操作者信息。")

任务子合同独立限定状态、动作、跟进时间与 IANA 时区，并为命令提供 `expectedVersion`、`requestId` 等字段。[任务状态与动作 ↗](../../../packages/contracts/src/task-flow.ts#L3 "支持任务状态和完整动作集合，并界定两者只是合同词汇。")[任务跟进与命令边界 ↗](../../../packages/contracts/src/task-flow.ts#L5 "支持跟进时间、IANA 时区校验，以及命令中的版本和请求字段。") 主入口导入并重新导出任务流定义，而任务提案的 `follow_up` 明确复用 `taskFollowUpSchema`；这说明静态 Schema 共享关系，不代表状态迁移、乐观锁或幂等已经实现。[任务流导入与重新导出 ↗](../../../packages/contracts/src/index.ts#L1 "证明主入口导入并重新导出任务流定义，与提案中的直接复用共同构成静态合同关联。")[证据与四类提案合同 ↗](../../../packages/contracts/src/index.ts#L214 "支持证据锚点、四类提案、任务提案复用跟进 Schema，以及更新和取代的版本前置条件。")

<a id="knowledge-and-runtime"></a>
## 知识与 Agent 运行边界

知识流水线用版本化 Schema 表达引用、疑问、文档批次、章节规划和独立复核；材料引用可定位固定行，原文约定由宿主抽取。[知识引用、文档与复核合同 ↗](../../../packages/contracts/src/knowledge.ts#L3 "支持知识引用、疑问、文档批次、规划和独立复核采用受约束的版本化结构。") 已验收制品保存依赖摘要、生成模型与复核元数据，并提供无结构约束的 trace 容器，因此具备追溯字段基础，但不能断言 trace 足以重现全过程，亦未定义依赖变化后的过期策略。[知识制品的依赖与复核元数据 ↗](../../../packages/contracts/src/knowledge.ts#L73 "支持制品记录依赖摘要、生成与复核元数据及开放结构的 trace 容器，同时界定其未规定过期行为。")

Agent 角色合同约束角色标识、输出 Schema、工具策略、会话继承和预算，并禁止无工具角色声明允许工具；它是宿主与角色之间的数据边界，不等同于调度或权限执行实现。[Agent 角色运行边界 ↗](../../../packages/contracts/src/index.ts#L675 "支持角色清单、输出结构、工具策略、会话政策和预算约束。")

<a id="repo-review-and-limits"></a>
## repo-review 关系与实现限制

repo-review 的仓库、快照、文件、符号、图边与理解结果在此被定义为附加读视图，不替代统一的来源、修订、片段和关系数据；源码位置只在产生它的快照中有效。`CodeKnowledgePort` 同时声明查询与同步入口，但这些普通 TypeScript 类型不能证明具体 AST 覆盖、边证据生成或陈旧结果处理。[代码知识附加读视图 ↗](../../../packages/contracts/src/index.ts#L887 "支持代码知识不替代统一证据数据，并说明源码位置仅在对应快照有效。")[代码知识访问与同步端口 ↗](../../../packages/contracts/src/index.ts#L1020 "支持端口包含查询和同步入口，同时表明接口本身不能证明具体同步实现。")

这替代了“任务、知识与代码知识均受严格运行时校验”的过强结论：部分 Zod 合同确有严格对象、枚举和格式校验，但代码知识主要是类型与接口，系统行为仍须追到实现和测试。路径分组也仅做前缀判断与 `/` 分割，不规范化反斜杠、前导 `./` 或重复分隔符，异常输入可能改变分类甚至形成空分组。[路径分类的输入边界 ↗](../../../packages/contracts/src/code-modules.ts#L2 "支持分类仅依赖前缀和字符串分割，重复或非标准分隔符可能导致非预期结果。")
