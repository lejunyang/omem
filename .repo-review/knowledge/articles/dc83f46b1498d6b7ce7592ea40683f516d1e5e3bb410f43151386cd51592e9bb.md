# 复核角色的批量评估输出合同

该 Schema 定义复核角色批量返回提案核验结果的数据格式：顶层绑定任务与角色，逐项表达提案身份、引文资产有效性、语义支持程度、判断原因及缺失上下文。它只约束输出结构与取值，不能单独证明复核流程已经接入或实际运行。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

这份合同为复核角色提供稳定的结构化输出边界，使宿主能够把一批评估关联到具体任务与角色。顶层必须包含协议版本、任务标识、角色标识和评估数组，并禁止未声明字段；其中协议版本固定为 `1`，任务与角色标识必须是非空字符串。参考 [顶层字段约束 ↗](../../../packages/agent-runtime/roles/verifier/1/output.schema.json#L5 "支持协议版本固定值、任务与角色标识非空、评估数组上限及数组未设置最小项数的论断。")、[顶层必填与封闭合同 ↗](../../../packages/agent-runtime/roles/verifier/1/output.schema.json#L84 "支持四个顶层字段均为必填、禁止额外属性及固定合同标识；同时表明当前材料是一份结构合同。")

评估数组没有声明 `minItems`，因此合同允许返回空数组；“必填”只表示该字段必须存在，并不表示其中至少有一项评估。参考 [顶层字段约束 ↗](../../../packages/agent-runtime/roles/verifier/1/output.schema.json#L5 "支持协议版本固定值、任务与角色标识非空、评估数组上限及数组未设置最小项数的论断。")

<a id="assessment"></a>
## 每条提案如何表达判断

每项评估通过提案标识定位对象，并携带格式限定为 **64 个小写十六进制字符**的摘要。判断分为两个维度：引文资产可判为有效、无效或有歧义；语义关系可判为支持、矛盾、证据不足或需要收窄范围。参考 [提案摘要与双维度判断 ↗](../../../packages/agent-runtime/roles/verifier/1/output.schema.json#L25 "支持提案标识、摘要格式，以及引文资产和语义判断允许值的说明。")

此外，每项评估都必须提供原因码、人类可读的解释和缺失上下文列表，便于调用方分类处理问题并补充材料。这七个评估字段均为必填项，评估对象也不接受合同之外的属性。参考 [原因、上下文与必填字段 ↗](../../../packages/agent-runtime/roles/verifier/1/output.schema.json#L51 "支持原因码、解释、缺失上下文的数量与字符串长度约束，以及每条评估七个字段必填且对象封闭的论断。")

<a id="limits"></a>
## 容量与合同边界

单批最多容纳 100 条评估。参考 [单批评估容量 ↗](../../../packages/agent-runtime/roles/verifier/1/output.schema.json#L19 "支持评估数组单批最多包含 100 项的容量限制。") 每条评估的缺失上下文最多包含 50 项，每项均为长度受限的非空字符串。参考 [原因、上下文与必填字段 ↗](../../../packages/agent-runtime/roles/verifier/1/output.schema.json#L51 "支持原因码、解释、缺失上下文的数量与字符串长度约束，以及每条评估七个字段必填且对象封闭的论断。")

该文件只定义数据结构，没有展示提案来源、摘要计算方式、引文资产检查、语义判定模型、调用链或持久化过程，也没有提供实际运行记录。因此，它能够说明复核结果应当长什么样，却不能单独证明运行时严格校验并执行了这份合同。参考 [顶层必填与封闭合同 ↗](../../../packages/agent-runtime/roles/verifier/1/output.schema.json#L84 "支持四个顶层字段均为必填、禁止额外属性及固定合同标识；同时表明当前材料是一份结构合同。")
