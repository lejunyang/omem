# 仓库评审存储、迁移与关系追踪

该模块在共享 Store 上建立隔离的 repo-review 运行存储，维护路径来源的删除、移动与旧身份迁移，并持久化代码到需求、决策、研究和测试的关系。更新后的说明进一步区分指定来源端与关系另一端的失效判定，撤回“指定来源被标记删除会由本函数直接检查”的过宽结论。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="scope-and-storage"></a>
## 职责与隔离存储

模块让 repo-review 复用统一的捕获、修订和检索设施，同时把 SQLite、状态与资源放在 `.repo-review/runtime`，不接触个人工作区；创建时仍使用共享 `Store` 完成数据库迁移及各仓储初始化。[评审运行目录与隔离边界 ↗](../../../apps/server/src/review/store.ts#L1 "支持 repo-review 复用共享能力、使用隔离目录且不触碰个人工作区的职责说明。") [共享 Store 初始化 ↗](../../../apps/server/src/store.ts#L36 "支持评审适配层复用共享 Store 的数据库迁移、资源目录和仓储初始化流程。") 默认启动直接创建独立运行库，只有设置显式开关才尝试从受版本管理的旧快照种入。[评审 Store 创建与旧历史开关 ↗](../../../apps/server/src/review/store.ts#L100 "支持默认创建独立运行库、仅在显式环境开关启用时导入旧历史。")

种入先复制旧 SQLite 及 WAL 文件到临时目录，再以 `VACUUM INTO` 生成一致快照。数据库快照失败时会删除目标数据库以便重试；随后同步状态与 assets 的投影发生在该清理块之后，因此这些步骤失败时运行数据库可能已经保留。[旧快照种入的失败边界 ↗](../../../apps/server/src/review/store.ts#L51 "支持临时复制、VACUUM INTO、一致快照及数据库清理仅覆盖快照阶段的限定。")

<a id="source-identity-migration"></a>
## 来源身份与旧数据迁移

文件以 `omem:<仓库相对路径>` 作为稳定外部身份，使同一路径内容变化形成连续修订，而不同路径即使字节相同也保持独立。[稳定路径来源身份 ↗](../../../apps/server/src/review/store.ts#L29 "支持同一路径跨内容修订连续、不同路径不因相同内容合并的身份设计。") 评审侧元数据补充删除、移动、迁移及旧来源别名状态；更新采用读取现值后的局部覆盖，被标记删除的来源可供检索层统一排除。[评审来源元数据 ↗](../../../apps/server/src/review/store.ts#L115 "支持删除、移动、迁移和旧别名字段，以及删除来源集合的查询用途。")

旧身份迁移从各来源最新修订中解析 `filePath` 并分组：没有既存路径身份时选取更新的来源作为当前身份，其余来源降级；已有路径身份时，旧来源全部降级。[旧来源按最新修订路径迁移 ↗](../../../apps/server/src/review/store.ts#L282 "支持按最新修订解析路径、选择当前来源并在事务内降级其余旧来源。") 降级只断开 head 并记录别名，不删除历史修订或片段；无法解析路径的来源被保守跳过。[旧来源降级与历史保留 ↗](../../../apps/server/src/review/store.ts#L229 "支持降级时仅断开 head、记录路径别名且保留历史修订与片段。")

<a id="relation-write-and-read"></a>
## 关系写入与查询范围

评审关系保存六种前向类型，反向名称在读取时派生；确定性关系 ID 与 seed identity 唯一约束使重复同步保持幂等。[关系类型与幂等写入 ↗](../../../apps/server/src/review/store.ts#L367 "支持前向关系类型、反向显示名、seed identity 唯一约束和确定性关系 ID。") 片段查询同时构造入边和出边，并根据关系另一端是否仍为当前 head、是否已删除计算展示状态；默认过滤 stale，但未解析的空端点仍作为 missing 关系保留。[片段双向关系视图 ↗](../../../apps/server/src/review/store.ts#L506 "支持入边出边读取、对端当前性与删除状态形成有效展示状态，以及默认 stale 过滤。")

代码路径查询的实际范围较宽：最终 SQL 会返回代码片段及可达意图片段的全部出边，并未把代码片段自身的边限定为 `implements`。意图片段集合由 `implements` 边产生，但其子查询未过滤 stale；因此历史 implements 仍可能把某意图片段纳入集合，再返回该意图片段的有效出边。[代码路径查询实际范围 ↗](../../../apps/server/src/review/store.ts#L680 "支持最终查询包含代码片段和意图片段的全部出边，以及意图片段子查询未过滤 stale implements 的限制。") 这替代了“只沿当前有效 implements 边扩展”的旧结论。

<a id="invalidation-and-risks"></a>
## 失效判定与待确认边界

`invalidateStaleRelations` 对指定来源的两种方向分别处理：指定来源这一端只检查片段是否仍属于该来源的当前 head；关系另一端则同时检查当前 head 与 `removed` 标记。[来源关系失效的非对称检查 ↗](../../../apps/server/src/review/store.ts#L753 "支持指定来源端只校验当前 head，而关系另一端额外校验 removed；用于纠正此前扩大删除检查范围的结论。") 因而此前“任一端来源被删除都会由该函数直接判 stale”的表述不准确：若被标记删除的正是传入的指定来源，固定代码中没有读取其自身元数据，是否会先通过其他流程断开 head 尚无法由本材料证明。

种子移除逻辑在有效关联集合为空时直接返回，故从非空种子变为空是否应全量失效仍取决于调用方合同。[空关联集合的失效边界 ↗](../../../apps/server/src/review/store.ts#L485 "支持有效关联 ID 集合为空时直接返回，不由该函数失效既有种子关系。") 状态类型包含 stale，但汇总仅暴露 confirmed、candidate、missing，其他状态均累计到 missing，因此 stale 会混入 missing。[关系状态与汇总分类 ↗](../../../apps/server/src/review/store.ts#L847 "支持状态包含 stale，而汇总把所有非 confirmed、非 candidate 状态计入 missing。")

<a id="current-limitations"></a>
## 当前可见限制

关系读取将存储状态与展示状态分开：只要关系另一端存在但已非当前或已删除，展示状态会被强制降为 stale；显式请求历史视图时才保留这些死链。[存储状态与展示状态分离 ↗](../../../apps/server/src/review/store.ts#L506 "支持关系另一端非当前或已删除时展示状态强制降为 stale，以及默认隐藏死链。") 但当前固定材料没有同步调用方、接口合同和行为测试，无法确定空种子、汇总分类以及代码路径宽查询是否都是产品有意设计；这些事项应通过调用链与真实断言确认，而不能仅凭注释推定。[代码注释描述的追踪链 ↗](../../../apps/server/src/review/store.ts#L680 "说明代码路径功能宣称的追踪目标，并与实际 SQL 范围共同界定仍需接口和测试确认的差异。")
