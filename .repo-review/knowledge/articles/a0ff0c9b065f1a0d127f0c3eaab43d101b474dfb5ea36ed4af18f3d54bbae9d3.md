# repo-review 隔离存储、来源迁移与关系读取

在共享 Store 之上建立隔离的评审运行库，维护稳定的路径来源身份、旧来源迁移和确定性关系边；同时明确旧快照投影、全部 seed 移除、代码路径 stale 过滤及汇总统计的现有限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="isolation"></a>
## 运行数据隔离与来源身份

repo-review 复用业务 `Store`，但把数据库和资源放在 `.repo-review/runtime/data`，与个人工作区分开；默认直接创建运行库，仅在 `REVIEW_IMPORT_LEGACY=1` 时导入旧快照。导入会复制 SQLite 文件并通过 `VACUUM INTO` 生成一致快照；只有这一快照生成阶段失败时，代码才会移除不完整的目标数据库。随后进行的同步状态和 assets 投影位于该异常处理之外，因此不能扩展为“整个导入流程失败都会清理运行库”。[评审运行库与旧快照导入 ↗](../../../apps/server/src/review/store.ts#L17 "支持运行目录、显式旧数据导入、SQLite 一致快照失败时的目标数据库清理，并显示后续状态和资源投影位于该异常处理之外。")

文件来源使用 `omem:<仓库相对路径>` 作为稳定身份，使同一路径的内容变化累积为修订，同时避免相同内容的不同文件被合并。评审侧元数据补充 removed、movedTo、migrated 和 legacyAliasOf，用来表达删除、移动和历史别名。[路径来源身份与评审元数据 ↗](../../../apps/server/src/review/store.ts#L29 "支持稳定路径身份以及 removed、movedTo、migrated、legacyAliasOf 等评审侧元数据。")

<a id="migration"></a>
## 旧内容哈希来源迁移

迁移从旧来源最新修订的上下文恢复文件路径，并按路径分组。若路径身份尚不存在，最新旧来源会改写为当前路径身份，其余来源取消 head、保留原有修订和片段，并登记为历史别名；若路径身份已经存在，旧来源全部降级为别名。整个分组改写在事务内完成，标记文件用于避免无意义的重复扫描，但发现仍挂有 live head 的异常旧来源时会再次修复。[旧来源迁移算法 ↗](../../../apps/server/src/review/store.ts#L229 "支持按最新修订路径分组、选择当前来源、降级历史别名并保留既有修订片段的事务化迁移过程。")

<a id="relations"></a>
## 关系写入、读取与失效边界

关系表只保存正向类型，反向名称在读取时派生。边以 seed identity 生成确定性 ID，重复构建会 upsert 同一行并更新端点、状态和修订信息，因此不会为被替换端点保留独立历史行。`invalidateRemovedSeeds` 能把不在有效集合中的旧边标为 stale，但有效 association 集合为空时直接返回；所以先前“删除全部 seed 也一定会失效旧边”的结论已被替代。[确定性关系写入与 seed 失效例外 ↗](../../../apps/server/src/review/store.ts#L367 "支持关系的确定性 upsert，并证明有效 association 集合为空时不会把既有 seed 边标为 stale。")

片段关系读取会结合持久化状态、目标是否为 current 以及是否 removed 计算有效状态，并在默认模式滤掉有效 stale。代码路径查询的边界更窄：虽然函数构造了包含 current、removed 条件的 `where` 数组，最终 SQL 却没有使用它；默认查询只直接排除持久化为 stale 的行，动态计算出的 stale 结果仍可能返回。先前关于该查询默认排除全部 stale 的结论已被替代。[关系有效状态与代码路径查询 ↗](../../../apps/server/src/review/store.ts#L506 "支持动态 stale 状态的计算，并显示代码路径查询最终 SQL 仅直接过滤持久化 stale，未采用已构造的完整过滤条件。")

模块提供了按来源把非当前关系标为 stale 的函数。[按来源失效关系 ↗](../../../apps/server/src/review/store.ts#L753 "支持模块确实提供按来源检查两端 current 状态并将过期关系标为 stale 的独立函数。") 然而给出的完整同步收尾流程仅调用 `buildReviewRelations`，没有调用该按来源失效函数，因此旧端点何时被主动失效仍缺少流程保证。[完整同步的关系重建步骤 ↗](../../../apps/server/src/review/sync.ts#L997 "支持完整同步收尾阶段实际调用的是关系重建函数，并据此界定按来源失效函数未接入该流程的现状。") 此外，关系汇总没有单独的 stale 字段，而把 confirmed、candidate 之外的所有状态都累计到 missing，导致过期关系与未解析关系在统计上混合。[关系状态汇总 ↗](../../../apps/server/src/review/store.ts#L847 "支持汇总合同没有 stale 字段，且 confirmed、candidate 之外的状态统一累计到 missing。")
