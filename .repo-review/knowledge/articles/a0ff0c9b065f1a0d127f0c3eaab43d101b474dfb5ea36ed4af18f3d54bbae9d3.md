# Repo-review 隔离存储与关系索引

在共享 Store 上建立隔离的评审运行库，维护路径身份、可选遗留导入、历史迁移以及代码到需求、决策、研究和测试的关系视图。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="isolation-migration"></a>
## 隔离运行库与身份迁移

评审数据位于 `.repo-review/runtime/data`，与个人工作区分离；文件源以 `omem:<仓库相对路径>` 为稳定身份，因此同一路径的内容修改累积 revision，而相同字节的不同路径仍是独立 source。[评审运行目录与路径身份 ↗](../../../apps/server/src/review/store.ts#L17 "支持隔离运行目录以及以仓库相对路径建立稳定 source 身份的说明。") 默认启动直接创建该运行 Store，只有 `REVIEW_IMPORT_LEGACY=1` 时才调用旧快照播种；这取代了此前仅凭目录注释推断导入条件的结论。[显式遗留导入开关 ↗](../../../apps/server/src/review/store.ts#L100 "直接证明只有环境变量取值为 1 时才播种旧快照，默认启动无历史数据依赖。")

遗留内容哈希身份按最新 revision 中的 `filePath` 分组。没有现存路径源时选最新快照改为路径身份，其余行卸下 head 并记录别名；已有路径源时则保留它并降级全部遗留行。revision 与 fragment 不被删除，迁移标记使正常重复运行趋于幂等。[遗留源迁移流程 ↗](../../../apps/server/src/review/store.ts#L229 "支持按路径分组、选择最新快照、保留 revision 与 fragment、记录别名和迁移幂等策略。")

<a id="relations"></a>
## 关系写入与双向读取

关系表保存六类前向边，反向显示名在查询时派生；seed identity 经摘要生成稳定边 ID，重复同步通过 upsert 更新原行。[评审关系表与确定性写入 ↗](../../../apps/server/src/review/store.ts#L367 "支持关系类型、反向名称、稳定 ID 和 upsert 写入规则。") 对已移除 seed 的失效并非无条件：只有有效 association ID 集合非空时，集合外旧边才会改为 stale；空集合会直接返回，故“所有消失关系都会失效”的旧结论已被收窄。[移除 seed 的条件化失效 ↗](../../../apps/server/src/review/store.ts#L485 "证明有效 ID 集合为空时函数直接返回，以及非空时才将集合外 seed 关系标为 stale。")

按 fragment 查询会合并出边和入边，以左连接保留 unresolved 的 missing 行；若另一端不再位于当前 head 或其 source 已删除，有效状态强制为 stale，默认读取会隐藏它。按代码路径还可展开代码到 intent，再到需求、决策、研究和测试的链路。[关系视图与路径链查询 ↗](../../../apps/server/src/review/store.ts#L506 "支持双向读取、有效 stale 判定、missing 保留及代码路径关系链展开。")

<a id="lifecycle"></a>
## 失效与汇总限制

源 head 更新或删除时，失效函数检查关系两端是否仍属于当前 head、另一端 source 是否存活，并把旧边标为 stale；空字符串端点代表尚未解析的 missing 关系，不按历史边处理。[源级关系失效检查 ↗](../../../apps/server/src/review/store.ts#L753 "支持两端 head 与删除状态检查，以及 unresolved 空端点不被按 stale 处理的规则。") 当前汇总 DTO 只有 confirmed、candidate、missing 三个桶，循环会把 stale 也计入 missing，因此汇总数字不能直接区分“定位失败”和“历史失效”。[关系状态汇总 ↗](../../../apps/server/src/review/store.ts#L847 "证明汇总仅设置三个状态桶，并将 confirmed、candidate 以外的状态统一累计为 missing。")
