# 飞书独立机器人接入与可靠投递

记录独立飞书应用从扫码注册、密钥保存、账号配对到 WebSocket 收件、通知投递和卡片决策的设计与实现状态，并明确实际授权、幂等投递和回调竞态的边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="onboarding"></a>
## 独立应用与安全绑定

文档推荐 omem 使用独立企业自建应用，不复用 botmux 的隐式会话或另一应用的 open_id；新建优先走官方 registerApp()，已有应用可经明确选择后导入凭据并再次探测能力。[独立应用与复用路径 ↗](../../../docs/implementation/batch2/lark.md#L5 "支持采用独立应用、官方扫码注册和显式复用已有 app 的设计。") 完整流程将“创建应用”和“绑定 owner”分开：扫码取得凭据后先加密保存和核验，再经同一应用内的一次性 pairing code、飞书事件及 Web 确认固定 owner 与通知目标。[扫码创建与绑定时序 ↗](../../../docs/implementation/batch2/lark.md#L30 "支持凭据接收、能力检查、WebSocket、配对和首次通知分阶段完成的流程。") 配对码要求高熵、短时有效、只存哈希且一次消费，避免把转发的二维码或短验证码当作充分身份凭据。[绑定身份与配对规则 ↗](../../../docs/implementation/batch2/lark.md#L57 "支持应用相关 open_id、实际联系验证及高熵一次性配对码要求。")

<a id="runtime_delivery"></a>
## 运行时、投递与回调

状态文档记载，消息运行时已由连接管理、持久 inbox、outbox worker 和卡片动作服务组成，并已接入服务生命周期；外部集成默认关闭，只有显式启用且具备密钥时启动。[飞书运行时组件与启用条件 ↗](../../../docs/implementation/batch2/lark.md#L92 "支持运行时组件职责、服务生命周期接入和默认关闭条件的实现状态说明。") 投递以业务 intent 为核心，同一次重试保持 provider UUID；超时超过去重窗口且无法对账时必须保留 unknown，不能宣称 exactly-once。[通知幂等与未知状态 ↗](../../../docs/implementation/batch2/lark.md#L100 "支持同 UUID 重试、投递状态及无法对账时不得承诺恰好一次的限制。") 卡片回调只应快速持久化并 ACK，之后异步校验 app、tenant、operator、消息归属、nonce、digest 和 expected versions，以 CAS 保证竞态下最多一次业务效果。[卡片回调与竞态控制 ↗](../../../docs/implementation/batch2/lark.md#L108 "支持快速持久化、身份与版本校验以及 CAS 最多一次业务效果。")

<a id="status"></a>
## 已记录验收与剩余限制

文档称注册、密钥、配对、绑定以及消息连接和回调核心已经实现，并记载 2026-09-27 通过独立测试应用完成权限回读、WebSocket、私聊配对、主动通知、卡片回调和入群消息验证；这些是材料中的进展陈述，不是本次分析独立复验。[真实测试应用验证记录 ↗](../../../docs/implementation/batch2/lark.md#L1 "追踪文档声明的实现范围、验证日期及尚未逐项触发的事件类别。") API 已覆盖 onboarding、取消、配对、确认、状态和已有应用复用，但测试发送、断开连接及设置界面尚未提供。[飞书 API 完成与缺口 ↗](../../../docs/implementation/batch2/lark.md#L118 "支持已经提供的 onboarding API 以及测试、断连和设置 UI 尚缺失的说明。") 文档/日历/会议事件尚未逐项触发，断网恢复、移群、密钥轮换和发送故障也仍主要依赖故障注入。[本地故障测试与 live 验收边界 ↗](../../../docs/implementation/batch2/lark.md#L122 "支持已覆盖的确定性测试、真实验收项目和仍未进行 live 验证的故障场景。")
