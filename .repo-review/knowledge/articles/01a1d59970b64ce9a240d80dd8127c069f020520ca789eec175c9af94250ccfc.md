# Web 模块：个人记忆与仓库知识的统一交互层

Web 模块是基于 Vue 3 与共享 UI 包构建的浏览器交互层，同时承载个人工作记忆和 repo-review 仓库知识两种工作区。它编排材料捕获、证据阅读、Agent 问答、学习任务、人工判断、通知回执与代码知识浏览；持久化、核验、权限和幂等语义仍主要由服务端保证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role_and_boundaries"></a>
## 双工作区入口与职责边界

Web 模块不是单一页面，而是个人工作区与仓库评审工作区共用的 Vue 应用壳。启动时先探测 review 健康接口：确认评审模式便进入 `ReviewApp`；只有接口明确返回 404 才继续连接个人服务，其他异常会进入重试。[工作区模式探测与启动重试 ↗](../../../apps/web/src/App.vue#L161 "支持应用先识别评审模式、仅在评审路由为 404 时回退个人服务以及异常重试的启动流程。") 个人模式由顶层组件集中协调阅读、知识整理、日常助理、学习、判断、待办与通知等页面，但各页面接收的数据和事件并不完全相同。[个人工作记忆 Web 总入口 ↗](da0e264957572bf35832a2327ed88508c6913c8ffb0323e87898adcffe262642.md#role-and-state "说明顶层组件集中维护业务状态并向不同子页面分发不同数据和事件。")

它是私有 ESM 工作区包，以 Vue 3 和 `@omem/ui` 为基础，并声明 Markdown、高亮、净化及二维码依赖；依赖存在不等于相应功能或安全配置已经完成。[Web 包配置与依赖 ↗](../../../apps/web/package.json#L1 "支持私有 ESM 包、Vue、共享 UI 及内容渲染相关依赖的技术背景。") 两种工作区使用不同请求边界：个人 API 从会话存储附加访问令牌并统一发送 JSON，[个人工作区请求封装 ↗](../../../apps/web/src/api.ts#L242 "支持个人 API 读取会话令牌、附加授权头、发送 JSON 并统一处理失败响应。") repo-review 客户端则面向本机读取、浏览和同步，不发送个人工作区授权头。[仓库评审 API 边界 ↗](../../../apps/web/src/review-api.ts#L1 "支持 repo-review 客户端面向本机读取、浏览和同步且不发送个人工作区授权头。")

<a id="personal_evidence_flow"></a>
## 个人工作区的证据闭环

材料录入分为两类路径：飞书、服务器文件和 Git 分别向连接器提交 URL、文件路径或仓库路径与 ref；文本、链接和图片才会在通用 `/captures` 分支中组成统一 parts，并由该分支记录来源主体、事件时间、时区及转发状态等 provenance。保存成功后刷新列表并打开固定修订，内容未变化时复用原版本。[连接器分派与通用捕获请求 ↗](../../../apps/web/src/App.vue#L256 "准确区分三类连接器的参数与仅在通用捕获分支构造 parts 和 provenance 的流程。") 这替代了此前“所有连接器请求同时携带同一组 provenance”的过宽结论。

阅读侧以证据帧栈保存片段、标签页、追问开关和滚动位置，[证据阅读器的帧状态模型 ↗](12a5295cb1a5cb2774b5de2f3f8084513b5cf0fe3b2974118aa9b84fe8246672.md#purpose-and-model "支持每个阅读帧保存证据、标签页、追问状态和滚动位置。") 并允许沿出向或反向引用继续下钻；重复目标不会再次入栈，而是提示返回既有层级。[证据下钻、返回与循环检测 ↗](12a5295cb1a5cb2774b5de2f3f8084513b5cf0fe3b2974118aa9b84fe8246672.md#navigation-and-relations "支持沿引用打开证据、保存和恢复阅读位置，并在重复路径出现时回到既有层级。") 完整材料中的图片由资源组件加载，追问面板则接收当前片段及整条帧路径作为可选上下文。[证据阅读器的组件协作 ↗](12a5295cb1a5cb2774b5de2f3f8084513b5cf0fe3b2974118aa9b84fe8246672.md#module-connections "支持 EvidenceReader 组合图片加载、路径追问和共享界面组件的模块关系。") `ChatPane` 会创建异步运行并轮询结果，但完成态只保证本次输入依据可回查，明确没有自动核验回答中每个主张的支持度。[固定依据回查与核验限制 ↗](../../../apps/web/src/ChatPane.vue#L95 "支持回答完成后可打开本次提供的依据，同时明确逐主张支持度尚未自动核验。")

<a id="actions_and_review"></a>
## 学习、判断与可追溯变化

学习页面把持久任务、模型尝试、关联提案和任务控制集中呈现；取消或重试会提交当前 generation 与独立 requestId，但前端调用点不能证明服务端已经提供事务性冲突检查或持久化幂等。[学习任务详情与控制 ↗](399fd81737b1307c33305e67ce2ef86ab650309a1700954702118077d789f8c4.md#details-and-actions "支持任务提案关联、尝试详情以及携带 generation 和 requestId 的取消、重试流程。")

待判断页面将自身定位为处理歧义、冲突和较大影响的变化，并提示来源变化或判断过期后不会沿用旧批准；这是界面表达的工作流边界，不能据此扩展出未提供的低置信路由策略。[待判断页面的适用范围说明 ↗](../../../apps/web/src/DecisionsView.vue#L58 "支持界面将待判断事项描述为歧义、冲突和较大影响的变化，并提示来源变化或过期后不沿用旧批准。") 用户可要求补充背景、拒绝或确认应用，前端随动作提交 `proposalDigest`、requestId 与执行者。[人工判断动作提交 ↗](../../../apps/web/src/DecisionsView.vue#L28 "支持补充背景、拒绝和批准动作随提案摘要、请求标识及执行者提交，并界定其只是前端请求。") 当状态为 `stale` 时，页面明确提示原件已更新且不能再提交；操作按钮也只为 `pending` 状态渲染。[过期判断提示与操作门禁 ↗](../../../apps/web/src/DecisionsView.vue#L120 "支持 stale 状态显示原件更新提示，并证明只有 pending 状态渲染补充背景、拒绝和确认应用按钮。") 摘要比较、重复请求处理和实际应用仍需服务端实现佐证。通知详情又把通知正文、application receipt、前后版本、原始证据和外部投递状态分开；没有回执时不会把通知本身当作事实已经生效。[通知回执、版本与原始证据 ↗](../../../apps/web/src/NotificationDetail.vue#L34 "支持通知详情区分实际应用回执、前后版本和原始证据，避免将通知误作生效证明。")

<a id="review_progress_limits"></a>
## 仓库知识入口、当前进展与限制

repo-review 工作区提供 Wiki、分类浏览、固定版本阅读、搜索、代码追溯和同步。`CodeWiki` 根据代码图中的文件、符号和边聚合模块节点及模块间边，[代码图的模块聚合 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L57 "直接支持从文件、符号和边聚合模块节点及模块间图边。") 启动时并行加载当前快照、代码图和模块理解列表；这说明它读取并组合这些数据，但不应仅凭加载代码推断图的构造语义。[代码快照、图与理解列表加载 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L116 "支持 CodeWiki 并行加载当前快照、代码图和模块理解列表，并与共享 trail 状态配合。") 界面另明确把依赖图描述为模块间 import 关系，并区分 confirmed 边与候选边。[模块依赖图的 import 语义 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L320 "支持依赖图展示模块间 import 关系，并区分确认边与候选边。") 这些引用替代了此前由单一加载范围同时证明“模块聚合和 import 图”的不足结论。

`ReviewApp` 的职责应拆开理解：分类材料与历史版本阅读由浏览流程承担，[分类浏览与历史版本阅读 ↗](e694f81e24ca1befefb3b3cf89616921d8d35f97fdadd4ce6166e250e70a5bc4.md#browse_read "支持 ReviewApp 的分类查询、删除项过滤、固定修订打开及历史版本加载职责。") 登记关系、关键词候选、全文搜索和代码追溯由关系与搜索流程承担，[登记关系、候选搜索与代码追溯 ↗](e694f81e24ca1befefb3b3cf89616921d8d35f97fdadd4ce6166e250e70a5bc4.md#relations_search "支持 ReviewApp 对人工登记关系、关键词候选、全文搜索和代码路径追溯的编排。") 同步入口则在完成后刷新同步状态、分类和健康统计。[同步流程与异步限制 ↗](e694f81e24ca1befefb3b3cf89616921d8d35f97fdadd4ce6166e250e70a5bc4.md#sync_limits "支持同步后的状态刷新，并说明版本、片段、搜索和追溯流程缺少统一竞态控制。") 这替代了此前仅用关系章节概括全部职责的宽泛表述。当前个人搜索仍明确是精确文本检索，语义检索尚未接入；[个人工作区搜索现状 ↗](../../../apps/web/src/App.vue#L543 "直接支持个人页面当前使用精确文本检索且语义检索尚未接入。") 多处版本、片段、搜索和追溯请求也尚未展示统一的取消或“最后请求获胜”机制。[同步流程与异步限制 ↗](e694f81e24ca1befefb3b3cf89616921d8d35f97fdadd4ce6166e250e70a5bc4.md#sync_limits "支持同步后的状态刷新，并说明版本、片段、搜索和追溯流程缺少统一竞态控制。")
