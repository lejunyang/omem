# web · 模块理解 · 专题 1

Web 模块是 omem 的 Vue 3 客户端总装层：同一入口按服务能力切换个人工作记忆与仓库评审界面，并围绕固定证据串联采集、阅读、追问、学习、决策与通知。当前基础链路已具备，但语义检索、逐项回答核验及若干服务端安全和并发保证仍不能由前端材料确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-entry"></a>
## 职责与双模式入口

该模块是私有 Vue/Vite 工作区应用，复用共享 UI，并声明 Markdown、净化和二维码等依赖；依赖存在不等于相应功能已经调用。[Web 包配置与依赖 ↗](../../../apps/web/package.json#L1 "支持模块采用私有 Vue/Vite 工作区包、复用共享 UI，并声明 Markdown、净化和二维码依赖；附近正文同时限定依赖声明不等于调用事实。") HTML 外壳只提供挂载节点并加载 TypeScript 主入口。[浏览器挂载入口 ↗](../../../apps/web/index.html#L1 "支持 HTML 入口仅提供 Vue 挂载容器并加载 TypeScript 主入口的职责边界。") 启动时先探测评审服务：命中后进入仓库评审；否则读取个人工作区健康状态与配置档，并调用 `refresh` 并行加载材料、通知、待办、变更、任务、提案和决策。[评审探测与个人工作区初始化 ↗](../../../apps/web/src/App.vue#L102 "完整覆盖 refresh 中七类业务集合的并行读取，以及 boot 的评审探测、配置档加载和 refresh 调用，修复旧稿引用范围不足。") 这修正了旧稿仅引用启动函数后半段、却直接列举七类集合的证据范围不足。普通模式每 2.5 秒刷新，评审模式不启动该轮询。[普通模式定时刷新 ↗](../../../apps/web/src/App.vue#L399 "直接支持组件挂载后仅在非评审模式启动 2.5 秒轮询，并在卸载时清理定时器。")

<a id="evidence-workflow"></a>
## 从采集到证据化交互

个人工作区把手工文本、链接、图片以及飞书、Git、服务器文件接入统一采集入口，并记录来源元数据。保存后会刷新集合并打开服务端返回的修订；仅当服务端响应 `duplicate` 时，界面才提示“复用原版本”，前端材料不能证明后端如何判重或是否真正复用。[统一材料采集与重复响应提示 ↗](../../../apps/web/src/App.vue#L228 "支持多来源分流、手工多模态采集和保存后刷新；同时准确限定只有服务端返回 duplicate 时前端才显示复用提示。") 这替代了旧稿把提示语直接写成系统保证的结论。EvidenceReader 以帧栈处理去重、循环和逐层滚动恢复，[证据帧栈导航 ↗](../../../apps/web/src/EvidenceReader.vue#L9 "支持打开去重、循环检测、加载互斥、滚动位置保存、压栈和退栈恢复。") 并提供片段、完整材料、反向引用及沿关系继续阅读的路径；追问侧栏接收当前焦点和整条帧路径。[证据视图与路径追问 ↗](../../../apps/web/src/EvidenceReader.vue#L104 "支持引用片段、完整材料、反向引用和出边阅读，并证明追问面板接收当前焦点及完整帧路径。") Agent 运行据此选择单片段或路径上下文，但完成界面明确说明尚未逐项核验回答主张。[Agent 运行与核验边界 ↗](../../../apps/web/src/ChatPane.vue#L49 "支持按固定焦点或引用路径创建运行、轮询结果，并直接说明完成后的回答尚未逐项核验主张支持度。")

<a id="learning-decisions-notifications"></a>
## 学习、判断与结果追踪

学习视图把材料保存、模型尝试、形成提案、应用通知分阶段呈现；没有尝试或处理失败不会显示为成功，取消与重试还提交当前代次和请求标识。[学习阶段与任务控制 ↗](../../../apps/web/src/LearningView.vue#L43 "支持学习进度的分阶段语义、失败不等于成功，以及取消和重试提交 generation 与 requestId。") 人工判断卡展示影响范围、不确定项和原始证据，可确认、拒绝或请求背景；来源变化形成 `stale` 状态时，界面明确禁止继续提交旧判断。[人工判断与失效限制 ↗](../../../apps/web/src/DecisionsView.vue#L58 "支持人工判断卡的状态、影响和不确定项展示、三类处理动作，以及 stale 状态禁止继续提交旧判断。") 通知详情则把应用回执、原始证据和渠道投递拆开：没有 application receipt 时不会把通知本身解释为事实已经生效。[通知回执、证据与投递状态 ↗](../../../apps/web/src/NotificationDetail.vue#L27 "支持通知详情区分事实应用回执、原始证据和外部投递结果，并明确无回执时不把通知视为事实已生效。") 这些字段和界面限制为服务端并发、幂等校验提供输入与提示，但不能代替服务端实现证据。

<a id="review-progress-limits"></a>
## 评审能力、进展与限制

仓库评审组件把初始视图设为 Wiki，[Code Wiki 初始视图 ↗](../../../apps/web/src/ReviewApp.vue#L37 "直接支持 ReviewApp 的视图类型包含 Wiki，且初始 view 值设为 wiki，从而证明其默认入口状态。") 并在该视图实际装配 Code Wiki；因此“默认知识入口”现在由状态初始化和模板渲染共同支撑。[Code Wiki 视图装配 ↗](../../../apps/web/src/ReviewApp.vue#L409 "支持评审导航和模板在 wiki 状态下实际渲染 CodeWiki，与初始状态引用共同证明默认知识入口。") 评审界面还覆盖固定快照、历史版本、全文搜索、代码追溯、人工登记关系、关键词候选与同步状态。[评审阅读、追溯与同步界面 ↗](../../../apps/web/src/ReviewApp.vue#L495 "支持固定快照和历史版本阅读、关系展示、搜索、代码追溯、关键词候选及同步状态等评审能力。") 当关系缺少对端或对端修订时，`openRelation` 会提示无法跳转并返回；这修正了旧稿用阅读模板范围证明“不静默跳转”的不足。[缺失关系的跳转保护 ↗](../../../apps/web/src/ReviewApp.vue#L281 "直接支持关系对端或其修订不存在时显示人读提示并停止跳转，修复旧稿引用范围不足。") 个人工作区仍明确标注为精确文本检索，语义检索及从观测自动提炼待办尚未接入。[检索与待办自动化限制 ↗](../../../apps/web/src/App.vue#L505 "直接支持个人工作区当前使用精确文本检索、语义检索尚未接入，以及自动从观测提炼待办仍属后续能力。") 统一请求封装会附加会话中的 Bearer 请求头，但在检查 HTTP 状态前直接解析 JSON；这既不能证明后端鉴权，也可能让空响应或非 JSON 错误只表现为解析异常。[统一请求封装 ↗](../../../apps/web/src/api.ts#L240 "支持会话令牌附加、JSON 请求与响应处理顺序，并说明客户端发送请求头不能证明服务端鉴权。")
