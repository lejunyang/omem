# web · 模块理解 · 专题 1

Web 模块是基于 Vue 3、Vite 与共享 UI 包构建的浏览器交互层，同时承载个人工作记忆和仓库评审两套界面。它编排多来源捕获、固定证据阅读、Agent 问答、学习与人工决策，也提供通知核验、飞书接入、Code Wiki、代码追溯和同步入口；当前仍受精确文本检索、前端轮询及尚待服务端验证的安全、并发和响应合同边界限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-modes"></a>
## 职责、背景与双模式入口

该模块是两套 Web 表面的总装层：启动时先探测评审健康接口，命中 review 模式便停止个人工作区初始化；否则加载健康信息、Agent profiles、材料、通知、任务、提案与决策。[评审探测与个人工作区启动 ↗](../../../apps/web/src/App.vue#L155 "支持启动时优先识别评审服务、命中后提前返回，否则初始化个人工作区集合的流程。") 根模板据此在仓库评审应用与个人工作区壳层之间切换。[双模式根界面分支 ↗](../../../apps/web/src/App.vue#L409 "直接支持根模板在评审应用和个人工作区壳层之间二选一。") 技术上它是私有 Vue 3 ESM 包，使用 Vite 开发和构建，并复用共享 UI；Markdown、高亮、净化和二维码库只是已声明依赖，不能据此断言所有能力均已实际调用。[Web 包脚本与依赖 ↗](../../../apps/web/package.json#L1 "支持私有 ESM 包、Vite 脚本、Vue、共享 UI 和内容呈现相关依赖的技术背景。")

<a id="personal-flow"></a>
## 个人工作记忆的证据链流程

个人模式围绕“捕获—固定版本—证据阅读—后续行动”展开：手工输入可组合文本、链接与图片，也可从飞书、Git 或服务器文件导入，保存后刷新集合并打开对应修订。[多来源捕获与修订打开 ↗](../../../apps/web/src/App.vue#L207 "支持图片限制、连接器分流、手工多模态输入、来源元数据以及保存后打开修订的完整流程。") EvidenceReader 以帧栈保存阅读路径和滚动位置，检测循环并支持逐层返回；片段、完整材料和反向引用可分别查看，路径还能传给追问侧栏。[证据帧栈导航 ↗](../../../apps/web/src/EvidenceReader.vue#L9 "支持帧栈去重、循环检测、滚动记忆、压栈和返回流程。")[证据视图与路径追问 ↗](../../../apps/web/src/EvidenceReader.vue#L104 "支持片段、完整材料、反向引用三种视图，以及将完整路径传给追问组件。") 图片请求的取消和对象 URL 回收实际由 AssetImage 负责，取代了此前将这部分资源管理宽泛归因于阅读器的结论。[图片请求取消与资源回收 ↗](../../../apps/web/src/AssetImage.vue#L3 "直接支持图片标识切换和组件卸载时取消请求、撤销对象 URL，说明资源管理职责属于图片组件。") 固定片段可作为 Agent 问答焦点，但界面明确提醒：材料可回查不等于回答中的每项主张已经自动核验。[固定焦点问答与核验提示 ↗](../../../apps/web/src/ChatPane.vue#L49 "支持固定片段和可选路径作为问答上下文，并明确生成回答尚未逐项自动核验。")

<a id="review-and-api"></a>
## 仓库评审与接口边界

评审应用将 Wiki 设为初始视图，并在该分支实际渲染 Code Wiki；其余视图覆盖分类浏览、固定修订、全文搜索、代码追溯和同步状态。[评审应用默认 Wiki 状态 ↗](../../../apps/web/src/ReviewApp.vue#L37 "直接支持评审应用的初始视图为 Wiki。")[Code Wiki 渲染分支 ↗](../../../apps/web/src/ReviewApp.vue#L459 "证明 Wiki 状态会实际渲染 Code Wiki 组件，而不只是声明一个状态值。") 关系对端缺失或没有修订标识时，`openRelation` 会提示并提前返回，因此“缺失对端不会跳转”现在由实际保护条件直接支持。[缺失关系对端跳转保护 ↗](../../../apps/web/src/ReviewApp.vue#L281 "直接支持关系对端为空或缺少修订标识时提示并拒绝跳转。") 追溯页把人工登记关系与关键词候选分区呈现，同步页显示扫描统计并声明当前只读浏览、检索不依赖模型。[追溯候选与同步状态界面 ↗](../../../apps/web/src/ReviewApp.vue#L644 "支持人工关系和关键词候选分区、同步统计以及只读浏览检索不依赖模型的界面边界。") 评审客户端文件还声明该接口绑定 loopback、无需个人工作区令牌；这是客户端边界说明，不等同于服务端安全审计。[评审客户端认证边界声明 ↗](../../../apps/web/src/review-api.ts#L1 "支持评审客户端关于 loopback、只读浏览同步和不发送个人 Authorization 请求头的自述边界。")

<a id="progress-and-limits"></a>
## 当前进展、被替代结论与限制

飞书界面声明 App Secret 只提交服务端加密保存且不出现在响应、日志或页面结果中，[飞书凭据安全界面说明 ↗](../../../apps/web/src/LarkSetup.vue#L208 "支持前端关于 App Secret 提交、加密保存及不出现在响应、日志或页面中的明确说明，同时不将其冒充后端验证结果。") 并说明手工 secret 提交后清除、botmux 只向浏览器暴露应用名称与 App ID。[手工 Secret 与 botmux 浏览器边界 ↗](../../../apps/web/src/LarkSetup.vue#L263 "支持手工 secret 的表单清理说明，以及复用 botmux 时浏览器只获得应用名称和 App ID 的界面边界。") 这些仍是前端流程与文案，不能替代后端存储和泄露测试。通知详情则区分应用回执、原始证据和投递状态，没有回执时不把通知本身视为事实已生效。[通知回执、证据与投递状态 ↗](../../../apps/web/src/NotificationDetail.vue#L27 "支持通知和事实生效的区分，以及原始证据和外部投递结果的展示。")

个人搜索仍是精确文本检索，语义检索尚未接入；自动从观测提炼待办也被明确列为后续能力。[精确文本检索限制 ↗](../../../apps/web/src/App.vue#L505 "直接支持个人搜索目前使用精确文本检索、语义检索尚未接入。")[待办自动提炼限制 ↗](../../../apps/web/src/App.vue#L687 "直接支持从观测自动提炼待办仍是后续能力。") 通用个人 API 无条件解析 JSON，空响应或非 JSON 错误页可能掩盖真实状态。[个人 API 请求与 JSON 解析 ↗](../../../apps/web/src/api.ts#L240 "支持会话令牌、统一 JSON 请求流程，以及响应体被无条件解析的限制。") 待办与恢复、学习任务、人工决策分别提交版本、generation、摘要或请求标识，[待办版本与历史恢复前提 ↗](../../../apps/web/src/App.vue#L306 "支持待办更新提交 expectedVersion、历史恢复提交 expectedHead。")[学习任务控制字段 ↗](../../../apps/web/src/LearningView.vue#L50 "支持任务取消和重试请求提交 expectedGeneration 与随机 requestId。")[人工决策提交字段 ↗](../../../apps/web/src/DecisionsView.vue#L28 "支持决策请求提交 proposalDigest、requestId、actorId 和动作。") 但这些字段只为服务端校验提供输入，不能证明并发、幂等或防重放已落实。仓库同步仅维护当前组件的忙碌状态并调用同步接口，取代了“同步也提交版本或请求标识”的旧概括。[评审同步调用与本地忙碌状态 ↗](../../../apps/web/src/ReviewApp.vue#L364 "支持同步界面只设置组件本地忙碌状态、调用同步并刷新数据，未提交版本、摘要或请求标识。")
