# web · 模块理解 · 专题 1

Web 模块是 omem 的 Vue 3 交互层，在同一入口分流个人工作记忆与仓库评审两种运行模式。它串联材料采集、固定证据阅读、问答、学习提案、人工判断、通知、日常助理和飞书接入，并为 repo-review 提供知识阅读、代码结构与关系追溯。当前主要限制是前端不能独立证明服务端安全和幂等语义，部分异步流程缺少统一竞态门控，且所给材料没有关键交互测试。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-boundary"></a>
## 模块定位与双模式边界

Web 包是私有的 Vue 3/Vite 应用，复用 `@omem/ui`，并声明 Markdown、净化、高亮和二维码等依赖；依赖存在只表示能力可用，不能单独证明业务已经接入。[Web 包配置与依赖 ↗](../../../apps/web/package.json#L1 "支持 Web 模块采用 Vue 3、Vite、共享 UI 和展示类依赖，并限定依赖声明不等于功能实现。") 顶层 `App` 启动时先探测仓库评审健康接口，命中 review 模式便交给 `ReviewApp`；否则初始化个人工作区、Agent profiles、业务集合和首份材料。[个人工作区与评审模式启动 ↗](../../../apps/web/src/App.vue#L157 "支持顶层应用先探测 review 模式、否则初始化个人工作区的双模式启动流程。")

两种模式共享浏览器入口但通信边界不同：个人工作区统一请求会从当前会话读取令牌并附加 Bearer 认证，[个人工作区请求认证 ↗](../../../apps/web/src/api.ts#L242 "支持个人 API 从 sessionStorage 读取令牌并为统一请求加入 Authorization 头。") repo-review 客户端则面向本机读取、浏览和同步，不发送个人工作区授权头。[仓库评审 API 通信边界 ↗](../../../apps/web/src/review-api.ts#L1 "支持 repo-review 客户端面向本机读取、浏览和同步且不发送个人工作区授权头的边界。") 因而这里实现的是运行模式分流，并不能据此推断评审接口具备多租户鉴权。

<a id="capture-read-answer"></a>
## 从材料采集到证据问答

个人模式把文本、链接和图片组成通用 parts，并附带主体、时间、时区和 producer 等 provenance；飞书文档、服务器文件与 Git 文件走独立 connector。保存成功后刷新集合、打开接口返回的固定修订，并区分内容复用与新证据生成。[多来源材料采集流程 ↗](../../../apps/web/src/App.vue#L230 "支持 connector 分流、通用 parts 与 provenance 构造，以及成功后的刷新和固定修订打开。") 阅读页展示修订状态、固定片段、图片和版本历史，片段既可作为提问焦点，也可进入引用阅读。[固定修订阅读界面 ↗](../../../apps/web/src/App.vue#L523 "支持阅读页展示版本状态、固定片段、图片和历史版本，并允许选择片段提问或打开引用。")

证据阅读器用帧栈保存片段、修订、标签页、追问状态和滚动位置；遇到已经存在于路径中的目标时提示回跳，新目标才压栈。[证据阅读帧栈导航 ↗](../../../apps/web/src/EvidenceReader.vue#L9 "支持证据加载、循环检测、帧栈压入以及滚动位置保存和恢复。") `ChatPane` 可围绕当前片段或整条阅读路径创建异步运行，按配置附带 model、effort，并轮询运行结果。[基于证据的运行创建与轮询 ↗](../../../apps/web/src/ChatPane.vue#L33 "支持问答提交焦点、可选路径上下文及模型配置，并轮询异步运行结果。") 完成后可以回查本次固定依据，但界面明确说明尚未自动核验回答中每个主张的支持度，因此“固定上下文”等同于“逐主张语义验证”的旧结论已被替代。[证据回查与核验限制 ↗](../../../apps/web/src/ChatPane.vue#L115 "支持完成后回到本次固定依据，同时明确逐主张支持度尚未自动核验。")

<a id="workflows-and-integrations"></a>
## 学习、判断、通知与外部接入

材料进入后台后，学习页以“保存、提炼与核验、形成提案、应用并通知”四段轨迹展示进度，并提供携带 generation 与 requestId 的取消或重试入口；尝试详情另行展示模型、effort、结果和错误。[学习轨迹、尝试与任务控制 ↗](../../../apps/web/src/LearningView.vue#L50 "支持四段学习轨迹、模型尝试呈现及携带 generation 和 requestId 的取消或重试流程。") 歧义、冲突或影响较大的提案进入判断页，前端提交动作、proposal digest、requestId 和 actorId；这只能证明校验输入被发送，不能证明服务端已实现摘要冲突拒绝或幂等。[人工判断提交合同 ↗](../../../apps/web/src/DecisionsView.vue#L28 "支持判断动作携带 proposal digest、requestId 和 actorId，并限定前端只能证明字段被提交。")

通知详情通过 application receipt 区分事实是否已生效，并保留原始证据、版本入口和各渠道投递状态。[通知回执、证据与投递状态 ↗](../../../apps/web/src/NotificationDetail.vue#L34 "支持通知详情以 receipt 区分事实是否生效，并展示原始证据、版本入口和投递状态。") 日常助理维护固定 Web 会话、轮次、失败重试和证据入口，把交办、回顾与记忆查询接回全局刷新。[日常助理会话与轮次 ↗](../../../apps/web/src/DailyAssistant.vue#L19 "支持固定 Web 会话初始化、消息发送、轮次重试、轮询和证据入口。") 飞书界面覆盖新建、更新、凭据导入、状态轮询和 owner 配对，且请求结束后清空表单 Secret；但加密保存、日志脱敏和 capability probe 的最终保证仍需服务端材料验证。[飞书接入与 owner 配对流程 ↗](../../../apps/web/src/LarkSetup.vue#L94 "支持飞书接入分流、Secret 清理、取消、配对和状态轮询等前端流程。")

<a id="review-progress-limits"></a>
## 仓库评审能力、共享 Trail 与限制

repo-review 的顶层状态明确包含 Wiki、浏览、阅读、搜索、追溯和同步六类视图，侧栏则提供仓库知识、材料浏览、全文搜索、代码追溯和同步状态入口。[评审顶层视图状态 ↗](../../../apps/web/src/ReviewApp.vue#L37 "直接支持 ReviewApp 维护 Wiki、浏览、阅读、搜索、追溯和同步六类视图及其共享状态。")[评审侧栏能力入口 ↗](../../../apps/web/src/ReviewApp.vue#L145 "支持仓库知识、材料浏览、全文搜索、代码追溯和同步状态五个用户可见导航入口。") 对应模板实际装配 Code Wiki、分类材料与固定版本阅读、搜索、代码追溯和同步页面，因此此前仅用关系状态映射证明整套能力的结论已被替代。[评审页面实际装配 ↗](../../../apps/web/src/ReviewApp.vue#L459 "支持 Code Wiki、分类浏览、固定版本阅读、全文搜索、代码追溯和同步页面均存在对应模板分支。") 关系状态本身另行映射为确认、候选、缺失和过期；人工登记关系才是确认链路，关键词匹配只产生候选。[评审关系状态映射 ↗](../../../apps/web/src/ReviewApp.vue#L112 "支持 confirmed、candidate、missing 与 stale 的人读状态映射。")[人工登记关系与候选说明 ↗](../../../apps/web/src/ReviewApp.vue#L566 "支持确认关系来自人工维护清单、词相似结果仅作为候选，并展示缺失目标。")

Code Wiki 从共享 UI 导入 `OmTrailDrawer`、`TrailFrame` 和 `useEvidenceTrail`，[共享 Trail 组件与组合式函数 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L7 "直接支持 Code Wiki 从共享 UI 导入抽屉、帧类型、哈希工具和 useEvidenceTrail。") 并以该 composable 统一维护帧、当前层、循环位置、焦点触发器以及 push/back/jump/close。[统一 Trail 状态合同 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L116 "支持同一 useEvidenceTrail 实例提供帧栈、当前层、循环、焦点恢复及 push、back、jump、close 操作。") 同一个抽屉按知识、模块、文件、符号和片段帧渲染相应阅读组件，所有下钻继续写入同一 trail。[多类型 Trail 抽屉渲染 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L371 "支持同一抽屉按知识、模块、文件、符号和片段类型渲染，并把各类下钻继续交给统一 Trail。") 这替代了此前仅凭组件导入便断言“所有阅读面共享同一 Trail”的证据不足结论。

仍有明确限制：个人模式七类集合由单个 `Promise.all` 整组刷新，任一接口失败会放弃本轮整体赋值。[个人工作区整组刷新 ↗](../../../apps/web/src/App.vue#L104 "支持七类集合通过 Promise.all 整组赋值，说明单项失败会使本轮整体更新无法完成。") 评审模式的版本、片段和关系请求完成后直接写共享状态，[评审版本与片段异步写入 ↗](../../../apps/web/src/ReviewApp.vue#L219 "支持版本、片段和关系请求完成后直接写共享状态，材料中未见请求版本门控。") 搜索同样没有显示请求序号、取消或旧响应丢弃机制。[评审搜索异步写入 ↗](../../../apps/web/src/ReviewApp.vue#L290 "支持搜索结果直接写入共享状态，并说明该流程未显示请求取消或旧响应丢弃机制。") 个人 EvidenceReader 的滚动恢复依赖特定对话框 DOM 选择器，[滚动位置的 DOM 选择器依赖 ↗](../../../apps/web/src/EvidenceReader.vue#L27 "支持个人证据阅读器通过特定对话框类名保存和恢复滚动位置的实现限制。") 手动创建关系还要求用户复制并输入片段内部 ID。[片段内部 ID 关联表单 ↗](../../../apps/web/src/EvidenceReader.vue#L148 "直接支持界面展示当前片段 ID，并要求用户复制目标片段 ID 后建立引用。") 所给材料不含测试文件，因此竞态、卸载清理、冲突响应和深链恢复只能确认实现，不能确认已经通过真实行为测试。
