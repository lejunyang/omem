# Claude 侧 omem 界面实现规范

Claude 侧的 omem 界面设计与实现规范，覆盖视觉来源、Vue 组件边界、证据阅读交互、不可信内容处理、无障碍和验收流程。提供材料显示其当前文本与 Agent 侧版本一致，但未说明两者的生成关系、权威来源或持续同步机制；规范陈述的是实现要求，并不能单独证明现有界面已经满足这些要求。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="design-contract"></a>
## 视觉来源与组件边界

该规范要求以仓库根 `design.md` 为视觉依据，将 `docs/design.md` 视为系统功能资料而非视觉 token。界面使用 Vue 3 `<script setup lang="ts">`，先检索并复用 `packages/ui`、`@omem/ui` 与既有 tokens；公共组件只处理 props、slots 和 emits，网络及应用状态留在 `apps/web`。[Claude 侧视觉来源与 Vue 分层 ↗](../../../.claude/skills/omem-design/SKILL.md#L8 "支持根设计文件与系统架构文档的用途区分，以及 Vue 3、公共组件复用和应用状态边界。") 视觉语言限定为近黑主色、浅灰目录、白色面板以及衬线标题与无衬线正文，错误和冲突还必须有文字说明。[Claude 侧阅读界面视觉语言 ↗](../../../.claude/skills/omem-design/SKILL.md#L10 "支持黑白灰阅读风格、字体分工以及错误和冲突必须包含文本的要求。")

<a id="evidence-safety"></a>
## 证据交互与安全边界

证据阅读围绕固定片段展开：递归引用共用一个 dialog，保存路径、当前层滚动和草稿；Esc 退回一层，关闭后恢复焦点，遇到引用环时提供回跳目标，问答过程不能丢失当前证据。[Claude 侧递归证据交互 ↗](../../../.claude/skills/omem-design/SKILL.md#L11 "支持单一对话框、路径与滚动保存、逐层返回、焦点恢复、环路回跳和证据连续性要求。") 正文应作为不可信资料，以文本或审查后的 AST 渲染，不得直接使用 `v-html`；图片只通过已验证的 asset ID 加载，模型回包也不能直接操作 DOM 或触发工具。[Claude 侧不可信内容边界 ↗](../../../.claude/skills/omem-design/SKILL.md#L12 "支持受控正文渲染、已验证图片资源以及模型回包不能直接操作页面或工具的安全限制。") 这些内容属于目标约束，不是相关功能已经实现的事实证明。

<a id="acceptance-and-alignment"></a>
## 响应式、验收与双侧材料关系

交付要求包括至少 44px 的普通点击区域、输入可见标签、700px 以下全屏引用与折叠导航，并在 390、768、1440px 视口检查横向溢出及 reduced-motion。页面还应连接真实 API，在未连接或无材料时展示诚实空态。[Claude 侧响应式与真实状态要求 ↗](../../../.claude/skills/omem-design/SKILL.md#L13 "支持点击尺寸、可见标签、移动端断点、指定视口、真实 API 和诚实空态等交付条件。") 完成后运行项目检查；页面变更需在任务已注册时执行浏览器检查并查看桌面、手机截图，未验证边界必须记录，通用行为优先沉淀到 `packages/ui`。[Claude 侧检查与公共组件原则 ↗](../../../.claude/skills/omem-design/SKILL.md#L15 "支持项目检查、浏览器截图验证、记录未验证边界及通用行为优先进入公共组件的要求。")

所提供的 Agent 侧文件在相同行号给出了同样的组件、安全、响应式与验收条款，因此只能确认两份材料在本次快照中的内容一致。[Agent 侧 omem 界面规范 ↗](../../../.agents/skills/omem-design/SKILL.md#L2 "与 Claude 侧材料共同支持两份文件在当前提供快照中内容一致；该引用不证明存在自动同步机制。") 材料没有交代复制方向、共同来源或自动一致性检查，不能据此断言未来会持续同步。

<a id="status-boundary"></a>
## 规范与实现状态的区分

本文是一份面向界面工作的规范：它规定真实 API、空态、通知和验证应如何处理，不能替代代码检查、测试退出码或浏览器行为验证。[Claude 侧响应式与真实状态要求 ↗](../../../.claude/skills/omem-design/SKILL.md#L13 "支持点击尺寸、可见标签、移动端断点、指定视口、真实 API 和诚实空态等交付条件。") 同理，“新增通用行为先进入公共组件”描述的是后续实现和评审原则，不能作为现有公共组件已经覆盖递归引用、移动端或无障碍行为的证据。[Claude 侧检查与公共组件原则 ↗](../../../.claude/skills/omem-design/SKILL.md#L15 "支持项目检查、浏览器截图验证、记录未验证边界及通用行为优先进入公共组件的要求。")
