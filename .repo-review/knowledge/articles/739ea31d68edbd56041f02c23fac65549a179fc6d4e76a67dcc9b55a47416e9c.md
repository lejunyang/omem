# other · 模块理解 · 专题 3

该专题呈现服务器端的共用可靠性底座：多源输入通过单用户 SQLite Store 形成固定材料与耐久作业。知识流水线在此底座上执行生成、独立复核和依赖失效；Lark 集成则复用采集与存储基础设施，并另行实现连接、事件去重和外部投递流程。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="foundation"></a>
## 职责与设计背景

这一组代码不是单一业务模块，而是个人助手的服务器可靠性底座。`Store` 以单用户 SQLite 装配应用、作业、输入聚合、运行请求与来源画像，并以立即事务统一提交或回滚；团队级数据库与租户 enforcement 仍是后续迁移。[统一存储与事务基础 ↗](../../../apps/server/src/store.ts#L1 "说明 Store 的单用户 SQLite 定位、组件装配及立即事务边界，支持本节对可靠性底座和团队能力限制的描述。") 统一采集会校验图片、按内容摘要保存资产，再创建新修订，把文本、链接和图片说明写成固定片段；片段数设有上限。[统一采集、资产、修订与片段写入 ↗](../../../apps/server/src/store.ts#L99 "覆盖图片校验与资产落盘、修订创建以及 fragment 实际写入，支持采集形成固定证据链的完整论断。") 因而当前能保证个人场景中的固定证据链，但不能据此宣称已经具备多租户隔离。

<a id="capture-flow"></a>
## 从外部输入到耐久作业

输入侧先吸收不稳定性：hook 离线时写入暂存区，发送失败或回执不匹配都保留事件，只有匹配回执才清除；重复重放最终仍只形成一份材料和作业。[脱机暂存与匹配回执清除 ↗](../../../apps/server/tests/inputs.test.ts#L48 "支持 hook 离线排队、重启恢复、失败保留、匹配回执清除及重复重放幂等。") 聊天按五分钟窗口聚合并去除重复正文，迟到事件另建修订并关联原批次；屏幕事件也可按数量阈值刷新。[聊天与屏幕聚合窗口 ↗](../../../apps/server/tests/inputs.test.ts#L193 "支持聊天时间窗口、正文去重、迟到批次关联和屏幕事件按数量刷新。") 新修订写入后，来源头与有效性代际被更新，旧依赖标记过期并排入刷新作业。[来源头更新与依赖失效 ↗](../../../apps/server/src/store.ts#L228 "覆盖来源 head 更新、有效性代际递增、旧知识依赖失效及刷新作业入队。") 事件型采集还会保存包含载荷摘要和修订定位的回执，用于识别重复与冲突。[采集回执持久化 ↗](../../../apps/server/src/store.ts#L290 "覆盖采集回执的字段构造和数据库写入，支持事件摘要、修订定位及幂等回执机制的说明。") 原始材料随后进入提取队列，而模型生成的派生材料被明确排除，避免总结自循环成独立证据。[提取作业与派生材料边界 ↗](../../../apps/server/src/store.ts#L353 "直接说明原始采集排入提取作业，而 producerKind 为 derived 的材料被排除以避免证据自循环。")

<a id="durability-and-knowledge"></a>
## 作业执行与知识形成

耐久作业允许先落库、后启动 worker，进程重启后继续处理；两个 worker 竞争时只有一个取得租约并产生业务效果。[作业重启恢复与租约竞争 ↗](../../../apps/server/tests/jobs.test.ts#L52 "支持采集和作业的事务持久化、重启后继续处理，以及两个 worker 竞争时仅应用一次。") 租约过期后，新 worker 会获得替代 token，旧 token 的迟到结果被 `STALE_JOB_LEASE` 拒绝。[过期租约与 fencing token ↗](../../../apps/server/tests/jobs.test.ts#L162 "直接支持替代租约取得新 token、旧 token 结果被拒绝及尝试历史保留。") 暂时错误、坏输出与认证错误采用不同重试上限；业务应用后崩溃的重放则依靠应用回执，避免重复创建任务、通知和投递意图。[分类重试与应用后崩溃重放 ↗](../../../apps/server/tests/jobs.test.ts#L207 "支持不同错误类别的有界重试、错误脱敏，以及应用后崩溃重放不重复产生业务效果。") 知识流水线另行执行生成与独立复核：拒绝结果或分析期间已变化的来源不发布，投影丢失可复用耐久结果；上层文章记录派生依赖，底层材料变化会使其失效。[知识生成、独立复核与失效传播 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L39 "支持独立会话复核、拒绝和输入变化不发布、耐久结果复用及文章依赖随底层变化失效。") 并发写测试只证明写事务出现后，Store 初始化、知识仓库初始化和采集这一整段操作最终成功，未定位实际等待发生在哪一步；此前把等待明确归因于 `capture` 的结论已被替代。[知识存储并发写事务测试 ↗](../../../apps/server/tests/knowledge-concurrency.test.ts#L9 "支持并发写事务出现后 Store、知识仓库和采集的整个操作序列最终成功，同时表明材料未测量具体等待阶段。")

<a id="integrations-and-limits"></a>
## Lark 集成进展与限制

Lark 富文本、图片和回复被适配为统一分片，图片经通用采集落为内容寻址资产，回复关系和逐分片来源也得到保留；这些结论来自行为测试，而非生产实现定位。[Lark 富消息统一分片测试 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L112 "验证富文本、图片与回复消息进入统一 Capture parts，并保留资产及来源关系；作为测试证据使用而非声称其实现定位。") 运行宿主的成功路径已贯通活动连接、outbox 投递、入站能力记录、群监听建立与连接停止。[Lark 运行宿主成功路径 ↗](../../../apps/server/tests/lark-runtime.test.ts#L103 "支持活动连接启动、outbox 投递、入站能力更新、群监听建立和已建立连接停止。") 独立投递测试证明本地 outbox 可跨 Store 重启恢复，并在模糊失败时复用 UUID 重试。[Lark 投递重启恢复与模糊失败 ↗](../../../apps/server/tests/lark-delivery.test.ts#L172 "支持持久 outbox 跨 Store 重启恢复，以及模糊发送失败时复用同一 UUID 重试的本地行为。") 会话恢复测试还覆盖入队后崩溃重放、相同事件的并发去重以及模糊失败后的本地重试。[Lark 会话崩溃恢复、并发去重与重试 ↗](../../../apps/server/tests/lark-delivery-recovery.test.ts#L172 "支持回复入队后崩溃重放、相同事件并发去重和模糊失败后的本地重试状态。") 这些材料仍主要使用伪适配器，不能证明真实供应商按 UUID 去重，也未定义损坏富文本或媒体下载失败时的降级策略。
