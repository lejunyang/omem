# other · 模块理解 · 专题 3

本专题汇总服务器侧跨模块可靠性边界：统一采集进入单用户 SQLite 修订与作业链，知识经独立复核发布，Lark 负责统一输入适配、实时事件和持久投递；现有证据以本地状态机和替身适配器测试为主。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="foundation"></a>
## 统一采集与持久化基础

`Store` 把应用、作业、输入聚合、运行请求和来源画像装配到同一 SQLite；当前定位明确是单用户基础，团队级约束仍待迁移。[Store 单用户持久化基础 ↗](../../../apps/server/src/store.ts#L1 "说明 Store 的组件装配、SQLite 单用户定位，以及团队级约束仍属后续迁移。") 采集事务校验事件回执，创建不可变修订与固定片段、更新来源 head，并只为非派生材料排入提取作业，避免总结反过来成为独立证据。[采集修订与派生材料边界 ↗](../../../apps/server/src/store.ts#L141 "支持采集回执校验、不可变修订、来源换头、依赖刷新以及派生材料不进入提取队列。")

输入侧另有两组边界：脱机 hook 只有收到匹配采集回执才清除暂存项，重启与重复重放仍保持幂等；[脱机 hook 暂存与匹配回执 ↗](../../../apps/server/tests/inputs.test.ts#L48 "支持脱机暂存、重启恢复、回执不匹配时保留及成功重放后的幂等清除。") 聊天输入按五分钟窗口落库，迟到事件形成关联原批次的新修订，屏幕重复正文则在达到事件上限时去重。[聊天窗口、迟到事件与屏幕去重 ↗](../../../apps/server/tests/inputs.test.ts#L193 "支持五分钟聊天窗口、迟到事件关联旧批次，以及屏幕事件按数量刷新并去重正文。")

<a id="knowledge-jobs"></a>
## 异步作业与知识发布

采集与作业入队共同提交，worker 可在进程重启后继续处理；共享 SQLite 上的竞争领取由租约约束，过期 fencing token 不能提交结果。[作业事务、重启与租约隔离 ↗](../../../apps/server/tests/jobs.test.ts#L52 "支持采集和入队事务一致、重启恢复、竞争 worker 单次领取及过期 fencing token 被拒绝。") 失败分类具有不同重试上限且错误会脱敏；若业务应用后、作业回执前崩溃，重放通过既有应用回执避免重复任务、通知和投递意图。[分类重试与崩溃幂等重放 ↗](../../../apps/server/tests/jobs.test.ts#L207 "支持不同失败类别的重试上限和错误脱敏，并证明应用后崩溃重放不会重复业务效果。")

知识管线在生成后交由独立会话复核，仅当复核接受且输入未变化时发布；语义拒绝后的续跑会把原草稿和反馈交给 refresher。[知识生成、独立复核与退回续跑 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L39 "支持独立复核后发布、输入变化拒绝、持久结果复用，以及携带旧草稿和反馈的 refresher 续跑。") 材料换头会使直接及上层知识失效，但旧材料与旧知识仍可固定读取；派生标题只辅助检索，返回的仍是当前原始片段。[知识依赖失效与原始证据召回 ↗](../../../apps/server/tests/knowledge-repository.test.ts#L47 "支持材料更新导致上下层知识失效、旧修订保留，以及派生知识只引导原始证据召回。")

<a id="lark-boundary"></a>
## Lark 入口、投递与限制

Lark 将富文本、图片和回复关系转换为统一 Capture parts，图片在刷新后复用内容寻址资产存储，因此它是通用采集链的适配器。[Lark 富消息统一分片 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L112 "支持富文本、图片和回复来源进入统一分片，并由通用采集路径保存图片资产。") 实时入口以连接租约限制消费者，按事件标识去重并保留身份与时间；卡片重复或竞态操作最多产生一次业务效果，机器人退群后相关目标立即停采。[实时事件、卡片竞争与退群停采 ↗](../../../apps/server/tests/lark-realtime.test.ts#L254 "支持连接租约、事件去重和身份时间保留，并覆盖卡片一次性业务效果及机器人退群后停止采集。")

通知 outbox 可跨重启恢复并在模糊失败时复用发送标识；[通知重启恢复与模糊失败重试 ↗](../../../apps/server/tests/lark-delivery.test.ts#L172 "支持 outbox 跨进程恢复、不重复应用业务，以及模糊失败期间复用同一发送标识。") 短窗口聚合保留全部变更映射，旧 binding 的待投递通知被取消且不会转发到新会话。[短窗口聚合与旧绑定隔离 ↗](../../../apps/server/tests/lark-delivery.test.ts#L330 "支持聚合后保留全部变更映射，并证明旧 binding 的通知不会转发到替代会话。") 这些结论取代此前用不足行范围笼统覆盖聚合、换绑、卡片和停采的表述。当前证据仍主要验证本地数据库与伪适配器，不能推出真实飞书/Lark 的供应商级 UUID 幂等、网络乱序或跨主机互斥。[Lark 发送替身的能力边界 ↗](../../../apps/server/tests/lark-delivery-recovery.test.ts#L41 "显示回复恢复测试使用脚本化消息适配器，支持现有结论仅覆盖本地调用与状态、不能证明供应商级幂等。")
