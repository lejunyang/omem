# Lark 富消息统一 parts 适配测试

该测试以临时 SQLite、加密凭据和 Lark 连接绑定构造接近真实的数据入口，验证富文本、图片及引用回复被转换为统一 parts，并保留来源信息；它覆盖适配后的持久化结果，但不证明真实 Lark 网络下载、异常输入处理或全部消息类型可用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-fixture"></a>
## 测试目标与运行夹具

这组测试解决的是 Lark 不同消息形态能否进入统一捕获合同的问题。每个用例创建独立临时目录、`Store` 与使用随机 32 字节密钥的加密凭据仓库，并直接写入有效连接、版本和群聊绑定；结束后清理目录，从而隔离 SQLite 与资产副作用。[临时存储与 Lark 绑定夹具 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L14 "支持测试为每个用例创建隔离 Store、加密凭据以及有效连接和群聊绑定的说明。") `groupEvent` 再提供群消息默认值，各用例仅覆盖消息类型、内容和回复关系。[群消息事件默认构造 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L68 "支持各用例基于统一群消息模板覆盖少量字段的说明。") 这里能确认测试依赖 `LarkEventInbox`、`EncryptedSecretStore` 和 `Store`，但材料没有展示 `processMessage` 的实现体，因此不能据此断言其跨文件内部调用链。

<a id="asserted-flow"></a>
## 已断言的核心流程

富文本用例把 post 标题、文本、链接和 @成员组合成三个有序文本 part，并逐项检查发送者、事件号和观察时间，验证内容转换没有丢失基本来源。[富文本转换与来源断言 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L112 "支持 post 被转换为标题、正文、链接和提及文本，并携带 actor、事件及时间来源的论断。") 图片用例通过注入的媒体端口确认下载参数，随后检查生成单个 PNG image part；批次经 `flushReady` 交给 `store.capture` 后，再按固定字节的 SHA-256 查询资产，覆盖了“事件入箱—统一 part—资产落库”的可观察结果。[图片下载与资产落库断言 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L161 "支持图片下载参数、统一 image part 以及经捕获后形成哈希资产的流程说明。") 回复用例则确认 part 级 `replyTo/quoted` 与 envelope 级 quoted 标志同步存在，保证下游聚合仍能识别引用语境。[引用回复来源断言 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L202 "支持回复关系同时保存在 part 与 envelope 来源字段中的论断。")

<a id="boundaries"></a>
## 边界与未覆盖行为

测试中的 `FakeMedia` 只返回固定 PNG 字节，不访问网络；这与媒体端口允许生产实现调用 Lark 资源 API、测试注入替身的合同一致。[Lark 媒体下载端口合同 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L38 "说明生产下载与测试替身之间的接口边界，支持真实网络行为未被本测试覆盖的判断。") 因而当前断言没有覆盖鉴权、超时、限流、下载失败、错误 MIME、超大图片或重试。富文本也只覆盖一种结构良好的 JSON，没有验证畸形 JSON、空标题、未知 tag、多语言 post 结构及消息更新。测试直接插入连接与绑定数据，也未覆盖凭据环境变量解析、连接建立或权限校验；加密仓库要求 32 字节密钥这一边界仅由被测夹具满足，并未在本文件中断言失败路径。[加密凭据密钥约束 ↗](../../../apps/server/src/integrations/lark/secret-store.ts#L24 "支持凭据仓库要求精确 32 字节密钥，而目标测试只覆盖有效密钥路径的边界说明。")

<a id="test-limitations"></a>
## 测试强度与可解释限制

图片断言先确认内存 envelope 中存在字符串数据，再推进聚合静默窗口并验证哈希资产存在，因此验证了最终副作用，而非仅检查模拟调用。[图片数据与哈希资产验证 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L181 "支持图片测试不仅检查模拟调用，还推进聚合并验证最终资产副作用的说明。") 不过测试没有断言输入事件的幂等性、重复事件处理、数据库中 part 的完整字段、资产内容回读或关闭过程中的错误；临时目录清理还明确容忍 Windows 短暂占用 SQLite 文件，意味着清理失败不会令用例失败。[临时目录容错清理 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L14 "支持 Windows 文件占用导致清理异常被忽略，以及清理失败不构成断言的说明。") 这些缺口不否定现有三个场景，但限制了它们对生产可靠性的证明范围。
