# Lark 富消息统一分片测试

验证富文本、图片与回复消息被转换为通用 Capture parts，并在转换、批处理和资产落盘过程中保留来源信息。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="rich-text"></a>
## 富文本到统一文本分片

该测试解决 Lark `post` 消息不能直接进入通用采集合同的问题。它构造包含标题、段落、链接和 @ 提及的富文本，经过 `LarkEventInbox` 后读取持久化输入信封，断言标题成为独立文本分片，链接保留可读文字与 URL，提及和相邻正文按原段落组合。每个分片同时携带外部发送者、事件号和观测时间，避免聚合后丢失发言人及事件上下文。[富文本解析与逐分片来源断言 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L112 "支持标题、段落、链接、提及转换及来源保留的说明。")

<a id="image-and-reply"></a>
## 图片资产与回复关系

图片消息通过注入的媒体端口下载，先进入信封成为带 MIME 类型和数据的 image part；批次刷新调用通用 `store.capture` 后，原始字节按 SHA-256 寻址并可从资产仓库取回。这证明 Lark 只负责输入适配，最终仍复用统一采集和资产存储路径。[图片下载与资产寻址断言 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L161 "支持图片通过媒体端口进入统一分片并在 capture 阶段落为内容寻址资产的说明。")

回复消息则把父消息号写入分片的 `replyTo`，并同时设置分片与信封级 quoted 标志，为后续会话聚合保留引用语义。[回复与引用来源断言 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L202 "支持 replyTo 和 quoted 在分片及信封层保存的说明。") 边界上，测试只覆盖一种 post 结构、PNG 图片和直接父消息；没有断言 malformed JSON、下载失败、超限媒体、其他富文本标签、多语言 post 变体或嵌套回复的降级行为。
