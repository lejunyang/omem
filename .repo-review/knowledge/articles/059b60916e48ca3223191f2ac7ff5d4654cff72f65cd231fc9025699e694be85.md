# 飞书富消息统一内容部件的行为验证

该测试验证飞书富文本、图片和引用回复进入实时收件箱后，会被转换为统一 parts，并保留参与者、时间、事件及回复关系等来源信息；图片还会在聚合刷新后落为按内容哈希寻址的资产。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

飞书消息不只有纯文本，还包含富文本段落、链接、提及、图片和引用回复。该测试关注这些异构输入能否统一转换成下游捕获流程可消费的 `parts`，同时保留发送者、事件时间和消息关系。测试使用临时目录、真实 `Store`、加密凭据存储以及连接和绑定记录搭建隔离环境，并在用例结束后清理数据库。参考 [隔离测试环境 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L14 "支持测试使用临时目录、真实存储、加密凭据及飞书连接和绑定记录构造隔离运行环境的说明。")

<a id="rich_text"></a>
## 富文本转为连续可读文本

富文本用例把标题转换成带“标题”标记的文本部件，把同一段中的普通文字与链接拼接，并在可读文本中保留链接地址；提及节点则转换成 `@用户名`。每个转换结果还携带发送者、事件编号和观测时间，使正文能够追溯到原始事件。参考 [富文本转换断言 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L112 "支持标题、段落、链接和提及的转换结果，以及每个部件保留事件来源信息的论断。")

当前断言覆盖标题、文本、链接和提及的组合，但没有说明其他富文本节点、空内容或格式错误载荷的处理方式。

<a id="image_flow"></a>
## 图片下载、聚合与资产落盘

图片消息通过可注入的媒体端口下载；测试替身接收应用、消息和图片键并返回固定 PNG 字节，因此无需实际联网。参考 [可注入媒体下载端口 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L38 "说明生产媒体下载与测试替身通过同一端口隔离，测试可以使用固定字节而无需联网。") 下载结果先保存为带 MIME 类型和 Base64 数据的图片部件，随后经输入聚合刷新与 `store.capture`，按 SHA-256 内容哈希写入资产存储，并确认资产可查询。参考 [图片资产化流程 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L161 "支持图片下载参数、统一图片部件、聚合刷新以及按 SHA-256 内容哈希确认资产落盘的论断。")

这验证了成功路径上的“远端图片 → 统一部件 → 内容资产”链路，但未覆盖下载失败、超时、错误 MIME 类型或重复图片。

<a id="reply_provenance"></a>
## 引用回复的来源追踪

回复消息会在部件级来源信息中记录父消息标识与 `quoted=true`，同时在信封级设置引用标志，供下游聚合识别引用状态，而不必重新解析原始飞书载荷。参考 [引用回复来源信息 ↗](../../../apps/server/tests/lark-rich-parts.test.ts#L202 "支持部件级父消息标识和引用状态，以及信封级引用标志供下游聚合使用的论断。")

测试仅确认父消息标识和引用状态得到保留，并未证明父消息会被抓取、解析，或被建立为可检索、可导航的消息关系。
