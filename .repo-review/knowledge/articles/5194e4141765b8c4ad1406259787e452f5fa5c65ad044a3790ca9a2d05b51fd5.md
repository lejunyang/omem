# osdk 使用指引总览

该材料把 osdk 描述为跨平台 SDK 管理器，并作为命令与配置文档的导航索引；它明确区分工具安装、项目依赖兑现、任务运行、配置优先级与信任边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="scope"></a>
## 定位与资料边界

文档将 osdk（仓库名 one-sdk）定位为统一管理语言运行时、包管理器、开发工具、Android SDK 和模型快照的跨平台工具，并强调为团队与 CI 保存区分平台的可复现锁定结果。本页只是速查索引，具体命令仍以对应版本的 `--help` 为权威来源。[osdk 定位与权威来源 ↗](../../../.claude/skills/osdk-guide/SKILL.md#L14 "说明 osdk 的用途、跨平台复现目标，以及本指南不能替代当前版本命令帮助。")

<a id="routing"></a>
## 命令与配置的分流

查询子命令、参数及功能分类时应转向命令参考；编写 `osdk.toml` 或全局 `config.toml` 时则应查配置参考。材料声称两份参考分别与 CLI 命令枚举和核心配置结构对齐，但这属于文档的维护声明，不能替代对当前二进制或源码的独立核验。[参考资料导航 ↗](../../../.claude/skills/osdk-guide/SKILL.md#L22 "支持命令问题与配置问题应分别查阅不同参考文件，并标明文档所声称的源码对齐关系。")

<a id="operating-model"></a>
## 关键操作模型

指南区分 `install` 与 `deps`：前者准备工具或包管理器，后者读取项目清单并兑现应用依赖；项目任务必须通过 `osdk run <name>` 执行。配置按 CLI、环境变量、项目配置、用户配置、内置默认的次序覆盖，而可能执行代码或削弱校验的配置需要先建立信任。[任务、依赖、信任与配置优先级 ↗](../../../.claude/skills/osdk-guide/SKILL.md#L39 "支持任务入口、工具与应用依赖分工、信任要求及配置覆盖顺序的说明。")
