# 服务端关键链路的集成测试

该测试文件以临时数据目录和可控 ACP 代理启动真实 Fastify 应用，通过 HTTP 注入与存储查询验证鉴权、捕获、生成回答、证据链接、文件导入限制、图片传递、持久任务控制、提案自动应用、通知回执及对话取消等关键链路。它证明的是单进程测试环境中的接口行为，不等同于外部 CLI、真实模型或生产部署验收。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-fixture"></a>
## 测试目标与隔离环境

这组测试关注服务端多个能力能否在同一应用实例中连贯工作，而非逐个隔离函数。`setup` 为每个用例创建临时数据目录，调用 `buildApp`，配置仅监听回环地址、空文件捕获根目录、即时通知以及 fixture ACP 代理；结束时关闭应用并删除临时目录，从而隔离持久化状态。参考 [隔离测试环境 ↗](../../../apps/server/tests/app.test.ts#L8 "支持临时目录、fixture ACP 配置以及测试结束后关闭应用并清理数据的说明。")

应用构建入口会创建 Fastify、Store、Runs 与记忆服务，并要求非回环绑定必须配置令牌；因此测试既覆盖 HTTP 路由，也间接穿过实际存储和运行编排，但 ACP 行为来自测试代理，不代表真实 Agent CLI 可用。参考 [应用构建入口 ↗](../../../apps/server/src/app.ts#L47 "说明测试所调用的 buildApp 会建立 Fastify、存储与运行服务，并执行非回环令牌约束。")

<a id="security-and-capture"></a>
## 输入边界与隐私保护

安全断言覆盖两层入口约束：配置令牌时，私有接口拒绝匿名请求并接受 Bearer 令牌；无令牌模式下，来自异源站点的匿名请求仍被拒绝。参考 [接口鉴权断言 ↗](../../../apps/server/tests/app.test.ts#L36 "支持私有接口令牌鉴权以及异源匿名请求被拒绝的测试结论。")

捕获侧验证了文件导入不能越过配置根目录，失败时不会写入数据；选中文本也必须能在焦点证据中匹配，伪造引文会得到 400。连接器源码进一步表明路径在解析真实路径后与允许根目录比较，文本文件还受 500 KB、UTF-8 与非二进制限制。参考 [导入与选文校验 ↗](../../../apps/server/tests/app.test.ts#L100 "支持越界文件导入不落库、伪造选中文本被拒绝的行为说明。") [文件连接器边界 ↗](../../../apps/server/src/connectors.ts#L10 "解释文件导入为何受真实路径、允许根目录、大小、UTF-8 和文本格式约束。")

Hook 用例则确认只保留规范化字段，未知的私密思考和 secret 不会进入序列化结果。它验证的是给定隐藏字段样例，未穷举所有嵌套载荷或其他事件类型。参考 [Hook 隐私过滤 ↗](../../../apps/server/tests/app.test.ts#L180 "支持 Hook 事件保留规范字段且丢弃未知私密载荷的断言及其样例边界。")

<a id="evidence-and-workflows"></a>
## 证据驱动的生成与事项落地

回答链路先捕获一条原始证据，再提交运行请求并等待完成；断言生成的回答修订存在一条显式出向证据关系，同时原始材料与派生回答都保存在 Store 中。这说明回答不会脱离来源成为无关联文本。参考 [回答与证据链接 ↗](../../../apps/server/tests/app.test.ts#L65 "支持生成回答被持久化并带有显式证据关系的端到端断言。")

多模态用例确认 PNG 字节可原样取回，并且以该捕获为焦点启动 ACP 后，代理收到一张图片。它证明了存储到提示构造的图片贯通，但没有验证图像语义理解、损坏图片处理或真实模型兼容性。参考 [图片存储与提示传递 ↗](../../../apps/server/tests/app.test.ts#L136 "支持图片字节保持不变并进入 ACP 提示的测试结论，同时界定测试代理的覆盖范围。")

事项流程覆盖“捕获承诺—评估提案—自动应用—查询任务与通知”的完整 HTTP 路径：具有已验证 owner 来源、精确引文和 `supported` 评估的任务被自动创建，提案记录为已应用，通知回执保存实体版本、证据及待投递的站内渠道。参考 [事项自动应用链路 ↗](../../../apps/server/tests/app.test.ts#L247 "支持 owner 承诺经提案评估自动落为任务，并生成含证据与投递状态的通知回执。")

<a id="jobs-and-cancellation"></a>
## 持久任务控制与对话取消边界

捕获接口会返回持久任务；测试随后读取其排队状态和代次，以相同请求重复取消并获得相同结果，再从预期代次重试，使 generation 从 1 增至 2。这验证了控制操作的幂等性与代次推进，但没有覆盖错误代次、并发竞争、进程重启恢复或 worker 实际消费。参考 [任务幂等控制 ↗](../../../apps/server/tests/app.test.ts#L194 "支持持久任务初始状态、重复取消幂等以及重试推进 generation 的说明。")

对话取消用例从创建会话、发送一轮消息到调用取消端点，确认已有 turn 返回成功、未知 turn 返回 404。由于 fixture ACP 响应很快，测试只证明 HTTP 路由已接到运行时接口，没有断言运行中的模型进程确实停止、事件流终止或取消状态持久化。参考 [对话取消接口 ↗](../../../apps/server/tests/app.test.ts#L370 "支持会话创建、turn 发送、取消成功与不存在 turn 返回 404 的断言，并揭示未检查运行时终止状态。")
