# 服务端 API 集成测试

该测试文件以临时数据目录和 ACP fixture 构建 Fastify 应用，通过注入 HTTP 请求验证认证、捕获与问答证据、连接器边界、图片传递、持久任务控制、提案成功应用、通知查询及助手取消接口。它覆盖多条关键纵向链路，但不能据此证明真实外部 CLI、并发竞争、重启恢复、失败回滚或完整输入净化语义。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="fixture-and-boundaries"></a>
## 测试夹具与安全边界

`setup` 为每个用例创建独立临时目录，以回环地址、空捕获根目录和 ACP fixture 构建应用，结束时关闭服务并删除数据；因此这些用例主要验证进程内集成，不代表生产部署或真实模型环境。[测试应用夹具 ↗](../../../apps/server/tests/app.test.ts#L8 "支持临时目录、回环地址、空捕获根目录、ACP fixture 以及测试结束清理方式的说明。") 配置 token 后，匿名访问私有接口返回 401，Bearer token 可正常访问；未配置 token 时，带恶意跨域来源的匿名请求返回 403。[私有接口认证与跨域拒绝测试 ↗](../../../apps/server/tests/app.test.ts#L36 "支持匿名请求 401、Bearer token 成功访问及恶意跨域匿名请求 403 的断言。")

文件连接器用例在捕获根目录为空时拒绝导入 `/etc/passwd`，且不产生捕获；这与连接器先解析真实路径、再确认目标位于允许根目录中的实现相符。[文件导入与选中文本校验测试 ↗](../../../apps/server/tests/app.test.ts#L100 "支持越界文件导入不落库以及伪造选中文本被拒绝的安全边界。")[捕获根目录路径校验 ↗](../../../apps/server/src/connectors.ts#L10 "解释文件导入测试所依赖的真实路径解析和允许根目录检查。") 同一用例还拒绝与焦点证据不匹配的选中文本，避免把伪造引文带入问答上下文。

<a id="capture-run-and-jobs"></a>
## 捕获、问答与持久任务流程

问答链路先捕获文本证据，再提交 profile、焦点片段和问题；测试等待运行完成，并确认答案 revision 存在且答案片段具有显式证据出边。[答案持久化与证据链接测试 ↗](../../../apps/server/tests/app.test.ts#L65 "支持捕获证据、提交运行、等待完成及检查答案证据出边的流程。") 图片用例验证保存后的字节与输入一致，并以运行事件中的 `images=1` 确认图片进入 ACP 提示上下文。[图片保存与 ACP 上下文测试 ↗](../../../apps/server/tests/app.test.ts#L136 "支持图片字节保持一致并通过事件确认图片进入 ACP 上下文的断言。") 应用初始化时共同创建 `Store` 与 `Runs`，但这些断言没有验证真实 ACP CLI、认证配置或模型输出质量。[应用存储与运行器初始化 ↗](../../../apps/server/src/app.ts#L51 "说明集成测试中的持久化和运行状态由应用初始化的 Store 与 Runs 承载。")

捕获 API 返回初始为 `queued`、generation 为 1 的任务；携带相同期望代次和 requestId 的重复取消得到相同结果，随后重试使任务回到队列并推进至 generation 2。[持久任务控制 API 测试 ↗](../../../apps/server/tests/app.test.ts#L194 "支持任务初始状态、相同请求取消的幂等结果及重试推进 generation 的断言。") 这覆盖顺序调用下的幂等响应和代际控制结果，尚未覆盖 worker 领取、进程重启恢复或并发竞争。

<a id="policy-and-assistant"></a>
## 提案成功路径、通知与助手取消

策略用例从带已验证 owner 来源信息的中文承诺构造任务提案，证据明确指向固定 fragment、source、精确引文和 Unicode codepoint selector，并提供 `supported` 复核结论。[Owner 任务提案输入 ↗](../../../apps/server/tests/app.test.ts#L247 "支持已验证来源、固定证据定位、精确引文和 supported 复核输入的描述。") 成功请求返回 `auto_apply` 与版本 1 回执；后续查询可观察到版本 1 任务、状态为 `applied` 的提案，以及包含提案回执、证据片段和待发送站内渠道的通知。[任务应用与通知成功结果 ↗](../../../apps/server/tests/app.test.ts#L328 "仅支持成功路径中 auto_apply、任务版本、提案状态和通知回执的最终可观察结果，不用于证明事务原子性。") 先前将这些结果表述为“原子地产生”超出了测试证据；现改为仅确认成功路径的最终可观察状态，是否跨任务、提案和通知事务回滚仍待失败用例或实现证据确认。

助手取消用例创建会话、发送一轮消息，再调用含 conversation 与 turn 标识的取消路由：已有轮次返回成功，不存在的轮次返回 404。[助手轮次取消端到端测试 ↗](../../../apps/server/tests/app.test.ts#L370 "支持创建会话、发送轮次、取消已有轮次成功及取消不存在轮次返回 404 的行为。") 由于 fixture 响应很快，它只证明路由接入及返回约定，不能证明长任务中的底层进程终止、事件停止或重复取消语义。

<a id="normalization-and-contracts"></a>
## Hook 最小断言与合同关系

Hook 单元测试只明确断言输出上下文中的事件名为 `PostToolUse`，且序列化结果不含输入中的 `thoughts` 和 `secret` 值。[Hook 事件最小化断言 ↗](../../../apps/server/tests/app.test.ts#L180 "仅支持事件名等于 PostToolUse，以及结果不包含两个指定敏感值；不支持会话和工具字段已被保留的结论。") 先前声称会话和工具信息也被归一化到公开上下文缺少断言支持，现已被替代；现有材料不能确认 `session_id`、`tool_name` 或 `tool_input` 是否保留、转换或丢弃。

测试文件直接导入应用构建器、共享合同和连接器入口，说明这些是实际测试依赖。[被测模块直接导入 ↗](../../../apps/server/tests/app.test.ts#L1 "证明测试直接依赖应用构建器、共享合同和连接器入口。") 捕获合同对文本、图片和链接 part 使用严格对象校验，并限制图片 MIME 类型与数据长度。[捕获内容 Part 合同 ↗](../../../packages/contracts/src/index.ts#L18 "解释文本、图片和链接输入所受的严格 schema、MIME 类型及长度约束。") 不过这不能替代 `hookInput` 的完整实现证据，也未覆盖所有已知 hook 字段、畸形输入、超长负载或嵌套敏感字段。
