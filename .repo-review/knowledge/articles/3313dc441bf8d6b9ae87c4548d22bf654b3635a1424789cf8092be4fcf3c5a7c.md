# 服务端 API 集成测试：安全边界、证据链与运行控制

该文件用临时目录和 fixture ACP 代理装配完整 Fastify 应用，覆盖来源接口认证、捕获与问答证据、文件和图片输入、任务控制、提案应用、通知记录及助手取消入口。证据仅支持进程内 fixture 集成行为；不证明全部私有接口、真实 Agent CLI、过期代次冲突、并发与重启恢复，也不证明取消确实终止底层 ACP。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="fixture-and-security"></a>
## 测试夹具与已验证的安全边界

`setup` 为每个用例创建临时数据目录，通过 `buildApp` 装配服务端、存储与运行器，并让 ACP profile 执行仓库内 fixture 脚本，关闭后清理目录。因此这些是隔离的进程内 HTTP 集成测试，并非真实外部 Agent CLI 的现场验收。[隔离应用与 fixture ACP 测试夹具 ↗](../../../apps/server/tests/app.test.ts#L1 "支持临时目录、完整应用装配、仓库内 fixture ACP 脚本及关闭后清理的说明。")

认证断言应限定为实际访问的 `/api/sources`：配置令牌时匿名请求返回 401、正确 Bearer 令牌返回 200；无令牌时，来自恶意 Origin 的匿名请求返回 403。此前“所有私有接口均已验证”的宽泛结论由此被替代。[来源接口认证与跨来源断言 ↗](../../../apps/server/tests/app.test.ts#L36 "支持 `/api/sources` 的匿名拒绝、Bearer 令牌访问和恶意 Origin 拒绝，并限定结论只覆盖该路由。") 应用还要求非回环监听必须配置令牌，但这项装配约束不能替代对其他路由逐项测试。[非回环监听的令牌前置条件 ↗](../../../apps/server/src/app.ts#L46 "说明应用在非回环地址监听时必须配置令牌，并界定其与逐路由认证测试的区别。")

<a id="capture-and-evidence"></a>
## 捕获、证据链与输入边界

问答用例先捕获文本，再启动 fixture 运行并等待完成，随后确认答案形成新修订、答案片段保留一条出站证据链接，且原材料与答案均在存储中，证明派生答案仍连接原始证据。[答案持久化与显式证据链接 ↗](../../../apps/server/tests/app.test.ts#L65 "支持 fixture 运行完成、答案修订写入以及答案片段保留出站证据链接的论断。") 文件及选中文本用例验证：未配置捕获根目录时导入 `/etc/passwd` 失败且不落库，无法匹配原文的伪造 selection 也被拒绝。[文件导入与选中文本拒绝 ↗](../../../apps/server/tests/app.test.ts#L100 "支持越界文件导入失败且不落库，以及伪造 selection 因不匹配原文而被拒绝。") 连接器实现进一步要求真实路径位于配置根目录内，并限制文件大小、UTF-8 解码与二进制内容。[文件连接器路径与内容限制 ↗](../../../apps/server/src/connectors.ts#L10 "解释文件导入断言背后的真实路径、配置根目录、大小、UTF-8 和二进制内容限制。")

图片用例确认解码字节被原样保存，并由 fixture 运行事件中的 `images=1` 判断图片进入该提示流程；这只覆盖仓库内 fixture 的协议装配，不能外推真实 CLI 的多模态兼容性。[图片字节保存与 fixture 提示输入 ↗](../../../apps/server/tests/app.test.ts#L136 "支持图片资产字节一致及 fixture 事件报告包含一张图片，同时限定其不能证明真实外部 CLI。")

<a id="jobs-policy-and-notifications"></a>
## 任务控制与提案应用链路

捕获接口返回状态为 `queued`、generation 为 1 且 attempts 为空的任务；携带 `expectedGeneration` 与 requestId 的取消请求重复提交得到同一结果，随后用正确期望代次重试，任务重新入队并升至 generation 2。[任务取消幂等与正确代次重试 ↗](../../../apps/server/tests/app.test.ts#L194 "支持任务初始状态、相同取消请求的重复结果及使用正确期望代次重试后 generation 增加，也显示未覆盖错误代次。") 这证明单进程顺序场景中的重复取消幂等和成功重试，但没有验证错误或过期代次会被拒绝。

提案链路中的捕获请求携带**声明为 owner**且填写验证方式字段的 provenance；随后同一次评估请求直接提交标为 `supported` 的 assessment，并断言策略结果为 `auto_apply`，任务、已应用提案及待处理的应用内通知均已落库。此前关于“可信身份已独立认证”和“独立 verifier 已运行”的结论被替代，因为材料只显示请求字段，没有证明认证或独立复核过程。[Owner 提案请求与自动应用断言 ↗](../../../apps/server/tests/app.test.ts#L247 "支持请求自行声明 owner provenance、随评估请求提交 supported assessment，以及任务、提案和通知记录的落库断言；不将其解释为独立认证或独立复核。") 来源合同确实为主体类型、验证方式、时间、转发状态及原始或派生属性提供结构化字段，但字段存在本身不等于其真实性已获验证。[捕获来源信息合同 ↗](../../../packages/contracts/src/index.ts#L49 "说明主体类型、验证方式、事件时间、转发状态和 producerKind 等结构化来源字段，但不证明字段值已认证。")

<a id="hooks-cancel-and-limits"></a>
## Hook 归一化、取消入口与限制

Hook 用例只确认事件名被归一化为 `PostToolUse`，并确认序列化后的结果不含未知 `thoughts` 与 `secret` 的值；它没有断言 `tool_input.command` 是否保留或如何转换，也没有执行持久化。此前关于“工具输入已归一化”和“未知字段不会进入持久对象”的结论均被更窄表述替代。[Hook 事件与未知字段过滤断言 ↗](../../../apps/server/tests/app.test.ts#L180 "支持事件名归一化及结果不含 thoughts、secret 值，并明确该用例未断言工具输入转换或持久化。")

助手取消用例创建会话与 turn，调用取消端点并断言成功，同时确认不存在的 turn 返回 404，因而只能证明 HTTP 路由接入基本取消入口。[助手 turn 取消 HTTP 入口 ↗](../../../apps/server/tests/app.test.ts#L370 "支持取消端点成功及不存在 turn 返回 404，同时表明 fixture 响应很快且未验证底层执行终止。") fixture 响应很快，材料未观察取消发生时 turn 是否仍在运行、最终状态与事件流是否停止、资源是否释放或底层 ACP 是否终止。全文件也未覆盖过期 generation、并发控制、服务重启后的幂等恢复及真实 Agent CLI 能力。
