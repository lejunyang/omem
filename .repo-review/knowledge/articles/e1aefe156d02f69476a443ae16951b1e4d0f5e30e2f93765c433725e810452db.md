# 统一检索端口与证据回读合同

定义来源与记忆两类搜索、固定证据回读及健康检查。只有来源候选直接携带 Revision 和 Fragment 定位；记忆候选尚未在本接口中建立回到原始证据的映射。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 后端替换目标与保证边界

端口旨在隔离调用方与具体检索后端，使当前 SQLite 关键词实现未来可替换为其他服务。文件头注释提出所有结果都应回到不可变 Fragment 的设计目标，[检索端口设计目标 ↗](../../../apps/server/src/retrieval/port.ts#L1 "说明后端可替换及回到不可变证据的总体设计意图，同时为现有类型保证的边界提供背景。") 但现有类型只对 `SourceCandidate` 落实该保证：它同时携带来源 Revision 和 Fragment 标识；`MemoryCandidate` 只有记忆标识、分数、摘要、种类、状态和 provenance。[来源与记忆候选结构 ↗](../../../apps/server/src/retrieval/port.ts#L45 "证明只有来源候选含 sourceRevisionId 和 fragmentId，而记忆候选没有固定证据定位字段。") 因而不能把“所有候选均可直接回读原证据”视为当前合同已经实现的事实。

<a id="scope"></a>
## 范围与项目信任边界

查询可表达项目、主题或工作区范围，并附带时间和数量限制。项目过滤具有强制信任条件：应用、会话和运行标识只描述捕获场景，不能推导真实项目关系；若项目关联未经确认，调用方必须传空项目且标记不可信，端口也必须执行工作区级召回。[项目范围信任规则 ↗](../../../apps/server/src/retrieval/port.ts#L17 "支持不得从上下文载体推断项目、未确认时必须工作区级召回的要求。")

<a id="operations"></a>
## 核心操作与未定义语义

接口分别搜索原始来源与已应用记忆，并提供按 Revision、可选 Fragment 回读证据以及后端健康检查。[统一检索接口操作 ↗](../../../apps/server/src/retrieval/port.ts#L77 "支持两类搜索、证据回读和健康检查的接口说明，并显示回读所需参数。") `readEvidence` 的参数并不能直接接受仅含 memory id 的记忆候选；记忆如何解析为 Revision／Fragment 需要接口外的步骤，而本文件没有规定该步骤。合同也未定义 score 的范围、跨后端可比性、同分稳定顺序、时间格式校验或故障传播方式。
