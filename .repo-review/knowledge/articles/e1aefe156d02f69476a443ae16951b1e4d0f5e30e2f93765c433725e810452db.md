# 统一检索端口：让原件、知识与记忆共享查询语言

RetrievalPort 是读者搜索、助手取证和 Agent 工具之间的检索边界：它统一查询意图、可见性与时间等约束，同时用不同结果类型保留原件、派生讲解、记忆和事项的身份。本文沿一次代码调用方搜索说明入口、实现与返回值，并标出项目范围、时间语义和 AST 候选的真实边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 一个端口服务多种阅读场景

`RetrievalPort` 解决的是“不同消费者如何用同一种查询合同检索、又不混淆知识层次”的问题。原始证据用带版本、摘要和行号的 `SourceAnchor` 定位；知识章节、记忆与事项则保留各自目标身份。富结果 `RetrievalHit` 同时携带正文、上下文、得分、命中路线、原始引用和来源信息，因此讲解可以参与召回，却仍能回到固定原文。参考 [统一检索职责 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持该端口供读者、助手和 Agent 共用，并区分原始结构、派生讲解与已应用状态。") [结果与固定目标 ↗](../../../apps/server/src/retrieval/port.ts#L25 "支持 SourceAnchor、不同 RetrievalTarget 及富结果中上下文、路线、引用和来源信息的结构。")

接口还保留较窄的 `SourceCandidate`，供只需要 Fragment 锚点的处理流程使用；这不是另一套知识产品，而是同一检索服务面向旧式原件消费者的投影。参考 [端口能力分层 ↗](../../../apps/server/src/retrieval/port.ts#L165 "支持富搜索、同步和异步原件搜索、记忆搜索、固定证据回读与健康状态的接口划分。")

<a id="representative-flow"></a>
## 一次“查找调用方”的代表性流程

例如网页请求携带查询文本、`purpose=implementation` 与 `codeIntent=callers`。入口先校验用途和代码意图并组装 `SearchQuery`，若端口提供富搜索便调用 `search`；否则退回异步或同步原件搜索。参考 [网页搜索入口 ↗](../../../apps/server/src/app.ts#L313 "证明 HTTP 入口校验查询参数、构造查询，并优先调用富搜索后再按异步和同步原件搜索降级。")

```mermaid
flowchart LR
  A[网页搜索请求] --> B[构造 SearchQuery]
  B --> C[RetrievalPort.search]
  C --> D[调用方候选定位]
  D --> E[排序并返回 RetrievalHit]
```

统一实现收到显式调用方意图后，不再走普通概念检索，而是按查询中的符号名寻找包含调用位置的代码单元，优先较小的外围操作，并把行号作为 `candidate` 命中保留下来；随后完成可见性、用途偏好、多样化和数量限制，输出可阅读结果。参考 [调用方候选定位 ↗](../../../apps/server/src/retrieval/unified.ts#L339 "证明调用方模式按符号名定位代码单元、优先较小外围操作，并保留候选调用行。") [意图分流与混合检索 ↗](../../../apps/server/src/retrieval/unified.ts#L476 "证明显式代码意图直接进入调用方或定义分支，普通查询才融合词面、符号与可选语义结果。")

<a id="boundaries"></a>
## 约束、降级与修改入口

`SearchQuery` 把过滤和排序意图显式化：`visible` 必须在最终排序与截断前生效，`timeRange` 指捕获版本时间而非事件时间或历史时点；材料角色、知识分类、用途和有效日期也由调用者明确传入。最重要的安全边界是：只有来自已确认关系的 `project_id` 且 `project_trusted=true` 才能按项目过滤，否则必须维持工作区范围召回。参考 [查询边界 ↗](../../../apps/server/src/retrieval/port.ts#L88 "支持项目可信关系、可见性、捕获时间、用途、代码意图和分类筛选的明确语义。")

两类能力是有意可选的：富 `search` 允许旧实现只提供原件搜索，`searchSourcesAsync` 允许语义分支异步加载，并由调用方回退到同步词面搜索。助手正是优先异步、再同步，并把会话可见性函数随查询传入，之后补齐标题与相邻原文。参考 [端口能力分层 ↗](../../../apps/server/src/retrieval/port.ts#L165 "支持富搜索、同步和异步原件搜索、记忆搜索、固定证据回读与健康状态的接口划分。") [助手取证调用 ↗](../../../apps/server/src/assistant/runtime.ts#L984 "证明助手优先调用异步原件搜索、回退同步方法，传入会话可见性并补读相邻证据。")

扩展查询字段或结果结构先改本端口；改变候选、融合、重排或投影则改统一实现；改变 HTTP 参数校验与默认值改搜索入口。运行时由工厂创建 `UnifiedRetrieval`，按配置装入中文向量与重排器，所以端口只定义能力，不决定具体算法。参考 [统一检索装配 ↗](../../../apps/server/src/retrieval/factory.ts#L14 "证明工厂以 RetrievalPort 暴露 UnifiedRetrieval，并按配置装入中文向量和重排能力。")
