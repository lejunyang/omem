# 统一检索端口：让原件、知识与已应用状态共享查询合同

RetrievalPort 是服务端检索能力的边界：它把原始证据、知识讲解、记忆和任务统一为可定位结果，同时保留面向旧处理器的原始片段检索、证据回读与健康检查接口。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-model"></a>
## 解决什么问题

读者搜索、助手调查和 Agent 工具需要共用检索，却不能把原件、派生讲解和已经应用的状态混成同一种数据。这个端口因此把可返回目标建模为四类：固定原件、知识章节、记忆和任务；其中原件锚点携带版本、摘要、行号与片段 ID，知识目标保留文章修订和章节。旧处理器若仍依赖 Fragment，也可继续使用只检索原件的方法。参考 [统一检索职责 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持统一服务读者、助手和 Agent，并区分原件、讲解、状态及保留原件兼容接口的论断。")、[可定位结果类型 ↗](../../../apps/server/src/retrieval/port.ts#L25 "支持原件、知识章节、记忆和任务四类固定目标及其版本定位字段。")

`RetrievalHit` 是供读者直接消费的统一结果：除标题、正文、上下文、分数和命中路径外，还带固定目标、原始引用、来源与事件时间。代码调用位置只标为名称级 AST **候选**，不能解释成已经类型解析的跨文件调用边。参考 [统一命中结构 ↗](../../../apps/server/src/retrieval/port.ts#L45 "支持统一结果携带正文、上下文、目标、引用、来源，并限定代码调用只为 AST 候选。")

<a id="representative-call"></a>
## 一次代表性调用如何流动

以查询“谁调用 `searchSourcesAsync`”为例，调用方可传入 `text`，把 `purpose` 设为 `implementation`、`codeIntent` 设为 `callers`，并给出 `limit`。这是教学示例；端口只规定输入输出，不规定具体排序算法。实现收到 `SearchQuery` 后，按显式用途、代码意图、结果种类、主题或材料用途等条件检索，返回 `Promise<RetrievalHit[]>`；调用方再通过每项的 `target` 打开知识章节、固定原件或已应用状态，通过 `references` 回到原始证据。参考 [查询意图与筛选 ↗](../../../apps/server/src/retrieval/port.ts#L96 "支持代表性查询中的文本、用途、调用方意图、限制数及正式分类筛选。")、[结果回到固定证据 ↗](../../../apps/server/src/retrieval/port.ts#L34 "支持调用方通过目标与原始引用定位结果和证据的流程。")

若实现未提供统一 `search`，合同仍要求同步原件检索、记忆检索、固定片段回读和健康状态；本地语义分支则是可选异步能力。`readEvidence` 找不到对应固定片段时返回 `null`。参考 [端口方法与回退能力 ↗](../../../apps/server/src/retrieval/port.ts#L165 "支持统一搜索可选、原件与记忆检索必需、语义分支可选、证据回读可空以及健康检查的说明。")

<a id="boundaries-and-relations"></a>
## 关键边界与其他模块关系

项目范围不能从应用名、会话或运行 ID 猜测。只有项目关联已确认时，调用方才可同时传入 `project_id` 与 `project_trusted=true`；否则端口必须保持工作区级召回，避免误删结果。参考 [可信项目范围 ↗](../../../apps/server/src/retrieval/port.ts#L88 "支持只有确认的项目关联才能触发项目过滤，否则必须保持工作区召回的边界。")

时间范围针对**捕获修订时间**，不是事件发生时间或历史时点查询；`visible` 必须在最终排序和截断前生效；`diversify=false` 用于保留原始融合顺序。用途由读者或 Agent 明示，不能根据仓库路径推断；主题路径与材料角色也是正式持久分类，而非目录猜测。代码意图虽可覆盖保守的自然语言捷径，但返回的调用匹配仍只是候选。参考 [时间与可见性边界 ↗](../../../apps/server/src/retrieval/port.ts#L106 "支持捕获时间、可见性、融合顺序、用途、代码意图和正式分类的具体语义。")

该文件依赖材料说明合同提供 `MaterialDescriptionRecord` 与 `MaterialRole`，说明检索层消费正式材料分类，但不在端口中实现分类、索引或排序。具体算法由实现类负责，调用者只依赖这里的稳定合同。参考 [材料说明合同依赖 ↗](../../../apps/server/src/retrieval/port.ts#L8 "支持端口从共享合同引入材料说明记录与材料角色，检索层消费正式分类的关系。")
