# 统一检索端口：从查询条件到可回读证据

RetrievalPort 是服务端检索能力的稳定边界。它统一查询固定原件、知识讲解与已应用状态，明确结果定位、排序元数据、可信项目范围和证据回读方式，同时保留旧处理器所需的原始片段检索接口。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-model"></a>
## 检索合同如何组织结果

这个端口给读者搜索、助手调查和 Agent 工具提供同一份检索合同，同时把原件、派生讲解与已应用状态保留为不同结果。旧处理器若仍依赖 Fragment 锚点，也可以继续使用只检索原件的方法。参考 [统一检索职责 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持读者、助手和 Agent 共用检索，同时区分原件、派生讲解、已应用状态并保留原件兼容方法。")

可返回的固定目标分为四类。`SourceAnchor` 指向原件，带有材料键、修订 ID、摘要、行号和片段 ID；知识目标记录文章修订与章节，还可标记 `needs-review`；记忆和任务则用 ID 与版本定位。参考 [四类固定目标 ↗](../../../apps/server/src/retrieval/port.ts#L25 "支持原件、知识章节、记忆和任务的定位字段及知识复核状态。")

`RetrievalHit` 是读者可直接消费的统一结果。正文与上下文之外，它区分实际返回的 `readingRange`、真正参与匹配的 `matchedRanges` 和完整结构目标，避免把局部命中误当成整段已返回。参考 [正文与命中范围 ↗](../../../apps/server/src/retrieval/port.ts#L45 "支持统一结果的正文、上下文、实际返回范围、匹配范围和结构目标之间的区分。")

排序信息也分层保存。`reranking.relevance` 是未经校准的模型输出，不是答案正确概率；`rankingStatus` 可记录预算不足或失败导致的未评分状态；`assessment` 是独立的本地判断，其中选项偏好同样不代表校准后的正确率。参考 [排序与本地评估 ↗](../../../apps/server/src/retrieval/port.ts#L66 "支持重排分数、未评分原因、本地评估以及这些数值并非校准正确概率的边界。")

结果还可携带名称级 AST 调用候选、固定目标、原始引用、文章引用、来源和事件时间。`codeMatches` 只表示候选调用位置，不能解释成已经类型解析的跨文件调用边。参考 [候选调用与证据定位 ↗](../../../apps/server/src/retrieval/port.ts#L103 "支持名称级调用候选、固定目标、原始引用、文章引用、来源和事件时间等结果字段。")

<a id="representative-call"></a>
## 一次代表性调用如何流动

以查询“谁调用 `searchSourcesAsync`”为教学示例，调用方可以把 `purpose` 设为 `implementation`，把 `codeIntent` 设为 `callers`，再给出 `limit`。需要扩展查询时，`queryVariants` 最多容纳三个由 Agent 提出的改写或子问题，每项不超过 400 个字符；原始 `text` 仍是重排和选择使用的问题。`signal` 则允许宿主取消处理，推理会在模型批次之间停止。端口只规定这些输入条件，不规定具体排序算法。参考 [查询扩展与显式意图 ↗](../../../apps/server/src/retrieval/port.ts#L143 "支持查询改写、取消信号、用途、代码意图、正式分类和生效日期等输入条件。")

统一 `search` 返回 `Promise<RetrievalHit[]>`。调用方通过 `target` 打开知识章节、固定原件或已应用状态，通过 `references` 回到原始证据；可选的 `citations` 还保留引用关系及是否可直接行动。原件候选另行保存固定片段、来源修订和可选的结构化阅读范围。参考 [候选调用与证据定位 ↗](../../../apps/server/src/retrieval/port.ts#L103 "支持名称级调用候选、固定目标、原始引用、文章引用、来源和事件时间等结果字段。")、[原件候选结构 ↗](../../../apps/server/src/retrieval/port.ts#L186 "支持原件候选携带固定锚点、阅读范围、来源修订、片段和来源信息。")

实现可以不提供统一 `search`，但仍须提供同步原件检索、记忆检索、固定片段回读和健康状态。本地异步语义分支 `searchSourcesAsync` 是可选能力；`readEvidence` 找不到指定固定片段时返回 `null`。参考 [端口方法与回退能力 ↗](../../../apps/server/src/retrieval/port.ts#L222 "支持统一搜索可选、原件与记忆检索必需、异步语义分支可选、证据回读可空及健康检查。")

<a id="boundaries-and-relations"></a>
## 范围、时间与分类边界

项目范围只能来自已经确认的项目关联。项目关联尚未确认时，调用方须传 `project_id=null` 和 `project_trusted=false`，端口也须保持工作区级召回；应用名、会话 ID 或运行 ID 不能代替项目关联。参考 [可信项目范围 ↗](../../../apps/server/src/retrieval/port.ts#L135 "支持只有确认的项目关联才能触发项目过滤，否则必须保持工作区级召回。")

`timeRange` 筛选的是捕获修订时间，不是事件时间或历史时点；`effectiveAt` 只在读者明确要求按生效日期搜索时使用。`visible` 必须在最终排序和截断前生效。`diversify=false` 会关闭仅用于浏览的来源上限，以及章节和文本去重；排序、显式范围与可见性过滤仍然有效。用途由读者或 Agent 明示，主题路径和材料角色采用已持久化的正式分类，不能从仓库路径猜测。参考 [时间、可见性与去重 ↗](../../../apps/server/src/retrieval/port.ts#L158 "支持捕获时间、生效日期、可见性、diversify 现行语义、用途和正式分类的具体边界。")

该文件从共享材料说明合同引入 `MaterialDescriptionRecord` 与 `MaterialRole`。检索层据此消费材料说明和材料角色，但分类、索引与排序的具体实现不属于这个端口。参考 [材料说明合同依赖 ↗](../../../apps/server/src/retrieval/port.ts#L8 "支持端口从共享合同引入材料说明记录与材料角色。")
