# 统一检索端口与证据回读合同

该文件定义来源片段与已应用记忆的统一检索边界，强调可信项目过滤、宿主可见性控制和不可变原始证据回读，并为同步关键词检索及可选异步语义检索提供稳定接口。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决的问题与设计目标

该端口把检索调用方与具体后端隔离：当前可以使用 SQLite 上的关键词基线，未来也能替换为实现相同合同的语义检索侧车，而无需改变管线或助手工具。更关键的是，候选结果必须保留不可变 fragment 定位，使上层最终引用原始证据，而不是把重排摘要当作事实。[统一检索端口设计说明 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持端口隔离具体检索后端、允许未来替换实现，并要求结果回指不可变原始证据的设计目标。")

<a id="query-policy"></a>
## 查询范围与可信过滤

`SearchQuery` 统一承载文本、范围、数量、捕获修订时间区间以及排序选项。项目归属不能从 application、conversationId 或 runId 等上下文载体推断；只有经确认的 ContextLink 才能同时提供可信 `project_id` 与 `project_trusted=true`。否则实现必须执行工作区级召回，不能进行项目过滤。宿主还可在最终排序和截断前通过 `visible` 控制资格，通过 `sourceWeight` 调整偏好；`diversify=false` 则保留原始融合顺序。[查询参数与项目可信规则 ↗](../../../apps/server/src/retrieval/port.ts#L17 "支持项目过滤必须来自已确认关系，以及可见性、来源权重、时间范围和多样化等查询策略。")

<a id="results-and-evidence"></a>
## 候选结构与证据闭环

来源候选包含分数、摘要、来源修订、固定片段、来源信息及可选路由；记忆候选则面向已应用记忆，额外暴露类型和状态。二者用途不同：前者定位捕获材料，后者支持冲突检查或记忆复用。`EvidenceFragment` 返回片段序号与原文，形成“召回候选—固定锚点—原文回读”的证据闭环。[候选结果与证据片段类型 ↗](../../../apps/server/src/retrieval/port.ts#L52 "说明来源候选、记忆候选和证据片段分别携带的数据及其证据定位关系。")

<a id="port-boundaries"></a>
## 端口能力与边界条件

接口提供来源检索、记忆检索、证据回读和健康状态；来源检索既有同步入口，也允许后端选择性实现异步语义分支，因此调用方不能假定所有实现都具备本地语义能力。`readEvidence` 可能返回 `null`，调用方需处理修订或片段无法读取的情况。该文件只定义类型和行为合同，没有展示排序算法、时间字符串格式校验、默认 limit、融合去重策略或健康检查判定逻辑。[检索端口接口定义 ↗](../../../apps/server/src/retrieval/port.ts#L80 "支持同步与可选异步来源检索、记忆检索、可空证据回读和健康状态等能力边界。")
