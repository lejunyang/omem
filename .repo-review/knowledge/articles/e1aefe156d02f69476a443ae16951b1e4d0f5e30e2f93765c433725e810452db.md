# 统一检索端口与证据回读合同

定义原始来源与已应用记忆的统一检索接口；SourceCandidate 明确绑定固定 Fragment 和 Revision，而 MemoryCandidate 只携带记忆标识与来源摘要，端口本身未规定其如何解析为原始证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 后端替换与证据边界

该端口让检索调用方与后端解耦：当前可以使用 SQLite 关键词基线，未来可替换为向量或侧车服务，而上层流水线与助手工具无需改变接口。文件注释提出结果应回到不可变 Fragment，以便引用原始证据。[检索端口设计说明 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持后端可替换和以不可变原始证据为目标的设计意图。") 但具体类型中只有 `SourceCandidate` 明确携带 `sourceRevisionId` 和 `fragmentId`；`MemoryCandidate` 只有记忆 id、分数、摘要、状态及 provenance，当前接口没有展示把记忆候选解析回 Fragment 的步骤。[候选类型与统一接口 ↗](../../../apps/server/src/retrieval/port.ts#L45 "区分 SourceCandidate 与 MemoryCandidate 字段，并支持搜索、证据回读和健康检查的接口说明。")

<a id="scope"></a>
## 范围与信任边界

查询支持项目、主题、工作区范围，以及时间和数量参数。项目过滤有强制信任条件：应用、会话或运行标识只是捕获上下文，不能推导项目关系；只有项目 id 来自已确认关联且 `project_trusted=true` 时才可缩小范围，否则实现必须执行工作区级召回。[项目范围信任规则 ↗](../../../apps/server/src/retrieval/port.ts#L17 "说明项目关系不得由捕获上下文推断，未确认时必须进行工作区级召回。")

<a id="contract"></a>
## 核心操作与未定义语义

接口分别提供原始来源搜索与已应用记忆搜索，后者用于冲突或复用召回。`readEvidence` 只能按 Revision id 与可选 Fragment id 回读不可变正文，因此它能直接承接 `SourceCandidate` 的定位字段，却不能仅凭当前 `MemoryCandidate` 完成同样回读。`health` 则暴露后端名称及可用性。[候选类型与统一接口 ↗](../../../apps/server/src/retrieval/port.ts#L45 "区分 SourceCandidate 与 MemoryCandidate 字段，并支持搜索、证据回读和健康检查的接口说明。") 本文件没有规定分数范围、跨后端可比性、同分顺序、时间格式校验或故障语义。
