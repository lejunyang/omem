# 统一检索端口与证据返回合同

定义来源检索、记忆召回与证据读取的统一边界；明确只有来源候选直接携带固定片段锚点，并约束项目过滤、可见性与后端替换方式。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 作用与被替代结论

该文件以稳定端口隔离检索调用方和具体后端，使关键词基线或后续实现可以替换，而流水线与助手无需同步改写。[统一检索端口设计说明 ↗](../../../apps/server/src/retrieval/port.ts#L1 "说明端口用于隔离调用方与可替换的关键词或后续检索实现。")

此前“所有检索结果都能直接回到不可变片段”的结论已被替代：类型合同只保证 **来源候选**携带 `sourceRevisionId` 与 `fragmentId`；**记忆候选**仅含记忆 ID、类型、状态和 provenance，没有直接证据锚点。文件头注释对“所有返回结果”的概括比实际接口更宽，不能据此扩大合同。[来源候选与记忆候选字段 ↗](../../../apps/server/src/retrieval/port.ts#L48 "支持只有来源候选直接携带修订和片段锚点，而记忆候选没有这些字段的类型区分。")

<a id="scope"></a>
## 查询范围与信任边界

`SearchQuery` 统一承载文本、范围、数量、捕获修订时间和可见性策略。项目关系不得从 application、conversationId 或 runId 等上下文载体推断；只有确认过的 ContextLink 才能提供可信项目标识，否则实现必须执行工作区级召回，不能擅自增加项目过滤。可见性过滤还应先于最终排序和数量截断。[项目可信与查询过滤规则 ↗](../../../apps/server/src/retrieval/port.ts#L17 "支持可信项目来源、未知项目时的工作区回退、时间范围及可见性过滤约束。")

<a id="contract"></a>
## 接口流程与实现限制

端口提供同步来源检索、可选的异步来源检索、已应用记忆召回、证据读取和健康检查。`readEvidence` 接收修订 ID 与可选片段 ID，因此可直接承接 `SourceCandidate` 的定位字段；接口本身没有定义从 `MemoryCandidate.id` 解析到修订或片段的步骤。[检索端口方法合同 ↗](../../../apps/server/src/retrieval/port.ts#L81 "说明来源检索、记忆检索和证据读取的参数与返回类型，并揭示记忆候选缺少直接读取证据所需的修订标识。")

异步钩子允许语义实现先取得词法结果，再融合向量候选；语义分支异常时返回词法结果，并继续输出带修订与片段标识的来源候选。这说明后端可以演进，但排序算法、向量存储及记忆到原始证据的映射都不由本端口合同保证。[语义来源检索的融合与降级 ↗](../../../apps/server/src/retrieval/semantic.ts#L80 "说明可选异步实现如何保持来源候选结构、融合词法与向量结果，并在失败时退回词法检索。")
