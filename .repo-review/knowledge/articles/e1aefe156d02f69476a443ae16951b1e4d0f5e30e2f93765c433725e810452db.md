# 统一检索端口与证据回读合同

定义原始来源与已应用记忆的统一搜索合同，并严格约束项目过滤的信任来源。只有来源候选直接携带 Fragment 与 Revision 定位；记忆候选如何解析回原证据不在本接口中体现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 后端替换与证据边界

该端口使调用方不依赖具体检索后端：当前可使用 SQLite 关键词基线，未来可换成向量或侧车服务。接口注释要求结果能够追溯固定证据，但具体类型中只有 `SourceCandidate` 直接带有 `sourceRevisionId` 和 `fragmentId`；`MemoryCandidate` 仅含记忆标识、摘要、状态和 provenance，不能据本文件断言它可直接回读 Fragment。[统一检索端口说明 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持后端可替换及设计上追溯固定证据的目标，同时需结合具体候选类型限定保证。")[候选类型与检索接口 ↗](../../../apps/server/src/retrieval/port.ts#L45 "区分来源候选和记忆候选字段，并支持搜索、证据回读及健康检查的接口描述。")

<a id="scope"></a>
## 范围与项目信任

查询支持项目、主题或工作区范围，并可携带数量和时间条件。项目关系不得从应用、会话或运行标识推断；只有来自已确认关联的项目标识才能把 `project_trusted` 设为真，否则端口必须保持工作区级召回，不得实施项目过滤。[项目范围信任规则 ↗](../../../apps/server/src/retrieval/port.ts#L17 "说明项目过滤只能来自已确认关系，未确认时必须进行工作区级召回。")

<a id="contract"></a>
## 核心操作与未定义语义

`searchSources` 返回可由 Revision 与 Fragment 定位的来源候选，`readEvidence` 按这些定位读取不可变正文；`searchMemories` 则召回已应用记忆以支持冲突检查或复用，`health` 报告后端可用性。[候选类型与检索接口 ↗](../../../apps/server/src/retrieval/port.ts#L45 "区分来源候选和记忆候选字段，并支持搜索、证据回读及健康检查的接口描述。") 当前合同未说明记忆候选到原始证据的解析步骤，也未约束 score 的范围、跨后端可比性、同分顺序及故障语义，调用方不能自行假设这些性质。[候选类型与检索接口 ↗](../../../apps/server/src/retrieval/port.ts#L45 "区分来源候选和记忆候选字段，并支持搜索、证据回读及健康检查的接口描述。")
