# 统一数据、Agent 流程与代码知识合同

该文件以 Zod 校验与 TypeScript 类型统一捕获输入、修订视图、证据提案、独立评估、人工决策、Agent 上下文及 repo-review 代码知识访问端口；它规定数据边界与不变量，但不证明持久化、调度、AST 解析或提案应用的具体行为。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="capture-contracts"></a>
## 统一捕获与修订结构

捕获合同统一接收文本、图片和 HTTP(S) 链接，并允许每个部件保留说话者、事件、回复、转发及原始或派生属性；manual、file、git、Lark、chat、screen 等入口共享同一信封和上下文结构。[捕获部件与来源合同 ↗](../../../packages/contracts/src/index.ts#L4 "支持多模态捕获、部件级来源信息以及统一入口和上下文结构的说明。")

存储视图把图片内容替换为资产标识，通过 `Revision.previousId` 和 `current` 表达修订链，`Fragment.revisionId` 则表示片段隶属的修订。此前关于“固定片段及跨修订身份续接”的结论已被替代：这些类型只规定数据形状，并未承诺分片、去重或跨修订身份保持规则。[修订与片段数据结构 ↗](../../../packages/contracts/src/index.ts#L113 "支持修订链和片段隶属关系，同时表明合同未声明跨修订身份续接。")

<a id="proposal-verification"></a>
## 证据提案、独立评估与人工决策

文本证据绑定 source/fragment revision、精确引文及 Unicode codepoint 区间；图片证据绑定资产哈希、观察说明与可选区域。[文本与图片证据锚点 ↗](../../../packages/contracts/src/index.ts#L204 "支持文本区间、修订标识、资产哈希及图片区域边界的论断。") task、claim、episode、procedure 四类提案共享作用域、证据、不确定项和版本前置条件，update 与 supersede 还要求目标及预期版本。[分类型提案与并发前置条件 ↗](../../../packages/contracts/src/index.ts#L273 "支持四类提案共享证据和版本字段，以及更新或取代操作的目标与预期版本约束。")

评估分别记录引文或资产有效性与语义裁决，避免把位置有效直接等同于论断成立。[证据评估合同 ↗](../../../packages/contracts/src/index.ts#L415 "支持引文或资产有效性与语义裁决被分别记录。") 人工决策另行绑定 approve、reject 或 request_context，以及提案摘要、请求和操作者。[人工决策操作合同 ↗](../../../packages/contracts/src/index.ts#L497 "支持人工决策绑定操作、提案摘要、请求标识和操作者。") 此前“任务提案复用状态”的结论已被替代：任务领域另定义状态和动作，但提案的 `follow_up` 只复用等待对象、复查时间、暂停时间、时间表达式和时区结构。[任务状态、跟进与动作合同 ↗](../../../packages/contracts/src/task-flow.ts#L3 "支持任务领域独立定义状态和动作，并明确任务提案实际复用的跟进结构只包含等待、复查、暂停、时间表达式与时区。")

<a id="agent-boundary"></a>
## Agent 角色与受信上下文边界

角色清单约束角色版本、模型配置引用、输出 schema、工具策略、会话继承和预算；无工具模式不得声明允许工具。[Agent 角色清单约束 ↗](../../../packages/contracts/src/index.ts#L675 "支持角色配置、输出类型、工具权限、会话策略和预算边界。") 上下文合同把可信信封与待分析材料分开：可信部分记录工作区、身份绑定、来源纪元和项目可信度，材料部分保存文本或图片及片段级来源，并要求至少有一种内容。[上下文信封与材料合同 ↗](../../../packages/contracts/src/index.ts#L755 "支持可信上下文和材料分层、片段来源保留及材料非空约束。") 这些是运行输入边界，不等于模型调度、权限隔离或输出落库已经实现。

<a id="code-knowledge-view"></a>
## repo-review 代码知识投影

代码知识被定义为隔离侧表中的附加读视图，不替代统一的 source、revision、fragment 和 review relation；源码位置只对生成它的快照有效，不构成稳定身份。[代码知识投影与快照定位 ↗](../../../packages/contracts/src/index.ts#L887 "支持代码知识作为附加读视图，以及源码位置只在对应快照中有效。") 图边可表达 imports、defines、calls、test_of 等关系，并携带状态、来源和证据字段，但类型声明不能证明解析器实际生成某条跨文件调用边。[代码图边状态与来源 ↗](../../../packages/contracts/src/index.ts#L962 "支持图边类型、状态、生成来源和证据字段，同时界定类型声明不能证明实际解析行为。")

`CodeKnowledgePort` 是暴露给 review HTTP 层的访问端口：它既包含快照、文件、符号、图和理解结果查询，也包含 `sync` 同步入口。此前将其整体称为“读取接口”的结论已被替代；合同本身仍不能证明具体 AST 覆盖、证据生成、陈旧边处理或同步实现。[代码知识 HTTP 访问端口 ↗](../../../packages/contracts/src/index.ts#L1020 "支持该端口同时声明查询方法和同步入口，并表明接口合同没有给出具体实现。")
