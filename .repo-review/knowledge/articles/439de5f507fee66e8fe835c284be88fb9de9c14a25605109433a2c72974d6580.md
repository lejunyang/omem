# 跨层数据合同与 Code Knowledge 读取端口

该文件集中定义采集输入、证据提案、代理运行上下文、集成配置及 Code Knowledge 投影视图，是运行时、存储适配器和 HTTP 层共享的数据边界；它描述数据形状与局部一致性约束，不实现持久化、模型调用或任务编排。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="capture-evidence"></a>
## 采集与证据基础

采集合同统一接收文本、图片和 HTTP(S) 链接，并可按 part 保留说话者、事件、时间、回复、转发及原始或派生属性；`Revision` 与 `Fragment` 在这里仅是数据形状，并无只读或存储层不可变保证。[多模态采集与来源结构 ↗](../../../packages/contracts/src/index.ts#L1 "支持多模态输入、逐 part 来源信息，以及 Revision、Fragment 只是类型形状的说明。") 批处理提案携带作用域、文本或图像证据、不确定项和派生来源；更新或取代还要求目标标识与预期版本，表达并发更新前提。[证据提案与并发更新约束 ↗](../../../packages/contracts/src/index.ts#L202 "支持提案作用域、证据、来源，以及更新和取代操作所需的目标与预期版本。")

<a id="agent-boundary"></a>
## 代理角色与合同层信任隔离

角色清单约束 profile、提示模板、技能、输出 schema、工具策略、会话隔离和预算，并禁止无工具角色列出允许工具。上下文清单把 `trusted_context` 与 `materials` 分成不同字段，材料至少包含文本或图片。[角色清单与上下文清单 ↗](../../../packages/contracts/src/index.ts#L672 "支持角色资产和执行策略约束，并证明可信上下文与材料在合同结构中分离。") 这提供合同层面的结构性隔离，但 schema 本身不能证明所有下游执行器都不会把材料内容解释为指令；实际执行安全仍需运行时处理规则和测试支撑。

<a id="code-projection"></a>
## 代码知识附加投影

代码知识类型覆盖仓库、快照、文件、符号、边和理解结果。位置仅对生成它的 head 快照有效，符号可锚定不可变 review Fragment；边记录 parser、seed 或 LLM 来源及 confirmed、candidate、stale、missing 状态。[代码快照、符号、关系与理解状态 ↗](../../../packages/contracts/src/index.ts#L891 "支持快照局部位置、Fragment 锚点、边的来源和状态，以及理解投影的状态集合。") `CodeKnowledgePort` 暴露当前快照、文件、符号、图、理解结果与同步入口；注释明确它们是隔离 review SQLite 的附加读视图，不替代统一材料链。[Code Knowledge 读取端口 ↗](../../../packages/contracts/src/index.ts#L884 "支持代码知识是附加投影，并说明 HTTP 层可查询文件、符号、图和理解结果及触发同步。") 文件同时定义了投影状态，但没有给出其与运行时理解输出状态的转换。
