# web · 模块理解

Web 模块是 omem 面向中文用户的浏览器交互入口，以 Vue/Vite 承载个人工作记忆和本地仓库评审两种模式。它串联采集、固定证据阅读、知识整理、用户决策与 Code Wiki 下钻，并复用共享 UI 的证据 Trail。主要待核实项包括服务端持久化语义、异步竞态、超长深链、生产部署和真实浏览器验收。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

## 定位、背景与运行边界

Web 页面以 `#app` 为挂载点，由 `/src/main.ts` 启动模块脚本，HTML 语言与产品标题均面向中文个人工作记忆场景。[Web 页面入口 ↗](../../../apps/web/index.html#L1 "直接支持浏览器挂载点、模块脚本入口、中文语言和产品标题等基础定位。") 顶层应用启动时先探测仓库评审环境，未命中才初始化个人工作区；两种模式共享前端外壳，但个人接口使用会话令牌，repo-review 则是面向本机的读取、浏览与同步表面，不能据此推断二者共享认证或租户隔离。[双模式启动与通信边界 ↗](01a1d59970b64ce9a240d80dd8127c069f020520ca789eec175c9af94250ccfc.md#role-and-boundary "支持个人工作区与仓库评审模式的启动分流、认证差异和运行边界。")[个人知识认证与评审边界 ↗](1ed2f14c8dbc2b0e8a369de4de7877707fecf84d98b7996ff88fafb99dec43fa.md#questions-and-boundaries "支持个人请求使用会话令牌、评审接口限定为本地读取浏览同步的概括，也界定疑问回答与转待办只能由前端材料确认到请求和状态反馈。")

开发基础设施由 Vite 配置注册 Vue 插件，使 Vue 单文件组件进入开发与构建流程；现有材料不能进一步确认 Vue 的主版本。[Vue 与 Vite 配置入口 ↗](ad84fde4ee0e2a675dfab86d12516ff51be2c50134d04ce3bbb72ecdd301e1d5.md#role "支持 Vite 配置注册 Vue 插件及其属于开发基础设施的论断，同时明确现有证据不能确认 Vue 主版本。") 本地开发服务器监听回环地址，并把 `/api` 代理到本地后端；该配置仅描述开发链路，不能证明生产部署方式、后端路由归属或多租户保障。[Vite 本地请求链路 ↗](ad84fde4ee0e2a675dfab86d12516ff51be2c50134d04ce3bbb72ecdd301e1d5.md#request-flow "支持回环监听、本地端口和开发期 API 代理流程，并限定其不代表生产部署合同。")

<a id="personal-workflow"></a>
## 个人记忆的采集、阅读与行动闭环

个人模式把文本、图片、链接及来源上下文组织为采集输入，保存后进入固定修订阅读。用户可以查看片段与历史版本，以当前片段或整条阅读路径作为问答上下文，并在完成后回查依据；界面同时明确，材料可回查不等于回答中的每项主张都已自动核验。[采集、固定阅读与证据问答 ↗](01a1d59970b64ce9a240d80dd8127c069f020520ca789eec175c9af94250ccfc.md#capture-read-answer "支持从多来源采集到固定修订阅读、证据问答及逐主张核验限制的流程概括。")

知识整理页把主题正文、材料覆盖、固定引用和原始材料接入阅读栈；证据不足的内容保留为疑问，而非被正文强行补全。[个人知识与固定证据阅读 ↗](1ed2f14c8dbc2b0e8a369de4de7877707fecf84d98b7996ff88fafb99dec43fa.md#knowledge-reading "支持知识首页、固定引用和原始材料组成连续阅读体验。") 学习轨迹、人工判断、通知回执、日常助理和飞书接入进一步连接后台处理与用户决策，但前端提交成功只能证明请求已经发出，不能独立证明服务端持久化、幂等、加密保存或后续重核验最终成功。[学习、判断、通知与外部接入 ↗](01a1d59970b64ce9a240d80dd8127c069f020520ca789eec175c9af94250ccfc.md#workflows-and-integrations "支持学习轨迹、人工判断、通知、日常助理和飞书接入的前端职责及服务端证据边界。")

<a id="review-workflow"></a>
## 仓库评审、代码关系与统一下钻

repo-review 提供仓库知识、材料浏览、固定版本阅读、全文搜索、代码追溯和同步状态等视图。确认关系来自人工维护的关联清单，词语相近只形成候选；界面可区分确认、候选、缺失和过期状态，并展示缺失目标。此前把所有缺失或过期目标概括为必然同时展示人类可读原因，超出了现有证据，现已由这一较窄结论替代。[仓库评审视图、关系状态与前端限制 ↗](01a1d59970b64ce9a240d80dd8127c069f020520ca789eec175c9af94250ccfc.md#review-progress-limits "支持评审视图范围、人工确认与候选关系、状态呈现，以及整组刷新、滚动选择器和内部片段标识等具体限制。")

Code Wiki 将文件、符号和边聚合为模块结构，再由模块知识下钻到源码、符号范围、固定片段及其关系。知识、模块、文件、符号和片段共用 Trail 抽屉；片段关系还能继续进入可定位的代码文件或其他片段，展示标签优先采用人类可读字段。[Code Wiki 可追溯下钻 ↗](94218fbf87841cfe339659af5d4b326fd0c168331762f84c04923ee3c1b8985b.md#evidence-trail "支持从模块进入源码、符号和片段，通过统一 Trail 与关系继续下钻，并记录关系边下钻的纯函数测试。") 这些文章是对固定材料的组织和下钻入口，不是新的独立事实证据，具体论断仍应沿子章节中的源码引用回查。
