# web · 模块理解

Web 模块是 omem 的浏览器交互入口，在同一 Vue 应用中承载个人记忆与 repo-review 仓库知识两种工作区。它围绕共享证据阅读链组织捕获、知识正文、问答、判断、学习任务和代码追溯；当前主要限制集中在异步竞态、深链持久化、运行时合同校验及服务端写入语义的验证不足。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role_boundaries"></a>
## 定位与双工作区边界

入口 HTML 只提供中文页面元信息、`#app` 挂载点和 `/src/main.ts` 模块脚本，是浏览器应用的轻量启动壳。[Web 页面启动壳 ↗](../../../apps/web/index.html#L1 "支持入口页面仅声明挂载点、中文元信息和主模块脚本的论断。") 上层应用会探测运行模式：repo-review 健康接口可用时进入仓库评审界面，明确返回 404 才回退个人工作区；两种模式共用 Vue 与共享 UI，但 API 边界不同，个人请求携带会话令牌，评审请求面向本机 `/api/review/*`。[双工作区入口与职责边界 ↗](01a1d59970b64ce9a240d80dd8127c069f020520ca789eec175c9af94250ccfc.md#role_and_boundaries "下钻说明评审模式探测、个人模式回退以及两类 API 的认证边界。")

开发期由 Vite 接入 Vue，监听回环地址并把 `/api` 代理到本地后端；这解释了本地联调关系，却不是生产部署合同。[Vite 开发请求链路 ↗](ad84fde4ee0e2a675dfab86d12516ff51be2c50134d04ce3bbb72ecdd301e1d5.md#request-flow "支持开发期 Vue 入口、回环监听和本地 API 代理，并限定这些材料不能证明生产部署方式。")

<a id="personal_flow"></a>
## 个人记忆的捕获、阅读与行动

个人工作区把文本、链接、图片和连接器输入送入相应捕获路径，保存后回到固定修订；阅读侧以证据帧保存片段、标签页、追问状态和滚动位置，并沿引用继续下钻。Agent 回答可以回查本次提供的依据，但尚不能据此认为每项回答主张都经过独立支持度核验。[个人证据闭环 ↗](01a1d59970b64ce9a240d80dd8127c069f020520ca789eec175c9af94250ccfc.md#personal_evidence_flow "下钻说明连接器与通用捕获分支、固定修订阅读、证据帧和回答核验限制。")

知识正文、固定引用和原始材料复用共享 Trail：引用帧能够定位文章章节或带修订、摘要和行号的材料，待核对问题则提供回答和加入待办的前端入口。[从知识正文到固定原文 ↗](1ed2f14c8dbc2b0e8a369de4de7877707fecf84d98b7996ff88fafb99dec43fa.md#flow "下钻说明知识文章、引用帧、原始材料和待核对问题如何组成连续阅读流程。") 学习任务、人工判断和通知详情进一步把请求代次、提案摘要、过期门禁、应用回执与原始证据分开呈现；这些界面状态有助于追溯，但服务端幂等和事务保证仍需后端材料证明。[学习、判断与可追溯变化 ↗](01a1d59970b64ce9a240d80dd8127c069f020520ca789eec175c9af94250ccfc.md#actions_and_review "下钻说明学习任务控制、人工判断门禁、提案摘要和通知回执的前端职责及证据边界。")

<a id="review_flow"></a>
## 仓库知识、代码图与证据下钻

repo-review 工作区把分类材料、历史修订、关系、搜索、同步和代码知识组织在同一入口；个人搜索目前仍是精确文本，而仓库评审已有独立检索与追溯流程。[仓库知识入口与检索现状 ↗](01a1d59970b64ce9a240d80dd8127c069f020520ca789eec175c9af94250ccfc.md#review_progress_limits "下钻说明分类浏览、历史版本、关系、同步、追溯以及个人精确搜索的当前进展。") Code Wiki 从快照、文件、符号和边聚合模块视图，再由模块进入文件、符号、固定片段及其关系；模块知识正文优先展示，结构化理解和文件分组作为补充。[从仓库结构到模块阅读 ↗](94218fbf87841cfe339659af5d4b326fd0c168331762f84c04923ee3c1b8985b.md#overview-flow "下钻说明快照和代码图加载、模块聚合、知识正文优先级与文件分组流程。")

知识、模块、源码、符号和片段共用受控 Trail，关系目标可转向代码文件或另一固定片段，人类可读标签与内部标识分离。现有证据只能确认这些视图在界面上进入同一证据阅读链，不能进一步证明底层不存在独立事实存储；此前关于统一 Capture→Revision→Fragment 数据归属的结论已被这一较窄表述替代。[源码关系与统一证据 Trail ↗](94218fbf87841cfe339659af5d4b326fd0c168331762f84c04923ee3c1b8985b.md#evidence-trail "支持文件、符号、片段和关系目标在界面上进入统一阅读链，以及展示标签与内部标识分离；不据此推断底层数据存储归属。")

<a id="progress_limits"></a>
## 进展、约束与待完善事项

现有实现已覆盖共享 Trail 的深层压栈、循环定位和部分关系下钻测试，但 Code Wiki 的页面写出与共享 Hash 工具并不完全一致：超长内存栈可能完整写入 URL，刷新恢复时只保留预算内帧且没有明确截断提示。模块、文件、符号和片段请求也缺少统一的过期响应保护，辅助关系失败有时会降级为空集。[深链与异步能力边界 ↗](94218fbf87841cfe339659af5d4b326fd0c168331762f84c04923ee3c1b8985b.md#deeplink-progress "跟踪超长 Hash 恢复、请求竞态、辅助关系降级和现有测试覆盖的限制，并支持超长 Trail 截断问题。")

严格 TypeScript 检查只能约束编译期形状；个人知识与评审客户端仍主要依赖泛型或类型断言解析响应，不能替代运行时 schema 和前后端契约测试。浏览器级焦点归还、滚动恢复、服务端持久化及重复提交防护仍需补证。[共享 Trail 与 API 合同边界 ↗](1ed2f14c8dbc2b0e8a369de4de7877707fecf84d98b7996ff88fafb99dec43fa.md#boundaries "下钻说明 Trail 已验证范围、双 API 访问边界、静态类型检查和运行时合同缺口。") 生产部署链路同样缺少材料：现有配置知识只覆盖 Vite 开发服务器及本地代理，不能证明生产环境沿用相同连接方式。[开发配置与生产边界 ↗](ad84fde4ee0e2a675dfab86d12516ff51be2c50134d04ce3bbb72ecdd301e1d5.md#relations-limits "支持现有配置材料只覆盖本地开发服务器和代理，生产构建与部署链路仍缺少证据。")
