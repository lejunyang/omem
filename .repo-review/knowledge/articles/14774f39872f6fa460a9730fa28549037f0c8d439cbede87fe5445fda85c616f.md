# web · 模块理解

Web 模块是 omem 的 Vue 浏览器交互层：同一入口按后端模式切换个人工作记忆与仓库评审，串联多来源捕获、固定证据阅读、学习与决策、Code Wiki 及知识 Trail。当前主要限制涉及服务端并发与安全合同、响应运行时校验、超长深链恢复和失效对象交互一致性。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-boundary"></a>
## 职责与双模式边界

Web 启动时先探测评审健康接口；命中评审模式便停止个人工作区初始化，否则加载 profiles、材料、通知、任务、提案和决策。[启动模式探测 ↗](../../../apps/web/src/App.vue#L155 "支持先识别评审服务、未命中后再初始化个人工作区数据的启动流程。") 根模板据此在仓库评审应用与个人工作区壳层之间切换。[双模式根界面 ↗](../../../apps/web/src/App.vue#L409 "支持根模板在评审应用与个人工作区壳层之间二选一。") Vue 入口先加载共享设计令牌和应用样式，再挂载根组件。[Vue 入口与共享样式 ↗](../../../apps/web/src/main.ts#L1 "支持共享设计令牌、应用样式的导入顺序及根组件挂载。") repo-review 客户端不发送个人令牌，并把回环、无令牌门禁作为部署前提；这只是客户端声明，不能替代服务端监听和鉴权审计。[评审客户端边界声明 ↗](../../../apps/web/src/review-api.ts#L1 "说明评审客户端不发送个人令牌，并界定回环、无令牌门禁属于其依赖的部署前提。")

<a id="personal-flow"></a>
## 个人工作记忆流程

个人模式可组合文本、链接和图片，也可从飞书、Git 或服务器文件导入；保存后刷新集合并打开固定修订。[多来源捕获与固定修订 ↗](../../../apps/web/src/App.vue#L207 "支持图片限制、连接器分流、多模态输入、来源元数据以及保存后打开修订的流程。") 旧 EvidenceReader 用帧栈记录标签页、循环和滚动位置，支持逐层返回；[证据阅读帧栈 ↗](../../../apps/web/src/EvidenceReader.vue#L9 "支持循环检测、滚动位置记录、压栈和逐层返回，不再用该范围证明路径传递。") 阅读路径传给追问组件则由独立的 aside 接线直接证明，替代此前用帧栈范围同时承接“路径追问”的不充分引用。[阅读路径传给追问组件 ↗](../../../apps/web/src/EvidenceReader.vue#L161 "直接支持 EvidenceReader 将当前全部片段标识作为 pathIds 传给 ChatPane。") 新知识入口复用共享 Trail composable 与抽屉。[个人知识共享 Trail ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L1 "支持个人知识首页与阅读帧复用共享 Trail composable 和抽屉组件。") 问答可选择固定片段或当前路径作为上下文，并提示回答主张尚未逐项自动核验。[固定证据问答与核验提示 ↗](../../../apps/web/src/ChatPane.vue#L49 "支持固定片段、可选阅读路径作为问答上下文，并明确回答主张尚未逐项自动核验。")

待办更新与历史恢复分别提交 expectedVersion、expectedHead，[待办版本与历史恢复字段 ↗](../../../apps/web/src/App.vue#L306 "直接支持待办更新提交 expectedVersion、历史恢复提交 expectedHead。") 学习任务控制提交 expectedGeneration 和 requestId，[学习任务控制字段 ↗](../../../apps/web/src/LearningView.vue#L50 "支持取消和重试请求提交 expectedGeneration 与随机 requestId。") 人工决策提交 proposalDigest、requestId 与 actorId。[人工决策请求字段 ↗](../../../apps/web/src/DecisionsView.vue#L28 "支持人工决策提交动作、提案摘要、请求标识和操作者字段。") 这些字段只是服务端校验的输入，不能证明并发、过期或重放保护已经落实。

<a id="review-and-relations"></a>
## Code Wiki 与关系阅读

评审应用把 `wiki` 设为初始视图，[评审应用默认视图 ↗](../../../apps/web/src/ReviewApp.vue#L37 "直接支持评审应用初始化时将 Wiki 设为当前视图。") 模板也在该分支实际渲染 Code Wiki；因此“默认入口”不再由数据装载代码间接推断。[Code Wiki 默认分支渲染 ↗](../../../apps/web/src/ReviewApp.vue#L459 "证明 Wiki 状态会实际渲染 Code Wiki 组件，而不只是声明状态。") Code Wiki 随后并行读取当前快照、代码图和已保存模块理解。[代码快照与模块理解装载 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L120 "支持 Code Wiki 并行读取当前快照、代码图和已保存模块理解列表。") 共享路径规则形成稳定模块桶，聚合逻辑过滤已删除文件，并只汇总两端可解析的跨模块 import。[共享模块路径归类 ↗](../../../packages/contracts/src/code-modules.ts#L1 "支持 Web、UI、contracts、服务端目录和兜底路径形成稳定模块桶。")[模块与依赖聚合规则 ↗](../../../apps/web/src/codewiki/modules.ts#L56 "支持过滤已删除文件、统计模块内容，并仅聚合两端文件均可解析的跨模块 import 边。") 正文引用只有在 `actionable` 时才生成固定引用帧；[知识引用导航门槛 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L20 "证明只有可操作引用才会生成包含文档、版本和引用键的导航帧。") 标签测试验证优先使用人读字段，并为 missing、stale 提供禁用或原因回退。[人读标签与失效边测试 ↗](../../../apps/web/src/codewiki/labels.test.ts#L10 "验证 DTO 展示字段优先、可读回退以及 missing、stale、actionable 的原因和禁用规则。")

关系 DTO 描述方向反转、有效状态和可为空的缺失对端；[评审关系状态合同 ↗](../../../apps/web/src/review-api.ts#L112 "支持入向关系类型反转、过期状态判定以及未解析对端为空的语义。") 真正的交互保护来自 `openRelation` 对空对端及缺少 revisionId 的检查。[缺失关系跳转保护 ↗](../../../apps/web/src/ReviewApp.vue#L281 "直接支持关系对端为空或缺少修订标识时提示并拒绝跳转。") 这替代了把 DTO 定义本身视为跳转保护实现的旧结论。

<a id="progress-and-limits"></a>
## 进展、被替代结论与限制

Trail 测试确认十二层内存栈不会沿用旧的八层截断。[Trail 长链与循环测试 ↗](../../../apps/web/src/codewiki/trail.test.ts#L21 "支持十二层内存栈不截断、五层压栈和按 kind、id 检测循环。") 但 Code Wiki 当前手工把全部帧写入 hash，[Code Wiki 当前 Hash 写入 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L219 "证明容器当前手工序列化全部 Trail 帧，写入时没有应用 MAX_TRAIL 截取。") 解析时才保留前 200 层，并只恢复 kind、id 和临时标题。[Hash 恢复与 200 层限制 ↗](../../../packages/ui/src/OmHashRoute.ts#L27 "证明解析阶段仅恢复 kind、id、临时标题并截取前 200 层，未持久化 line 或 scroll。") 因而旧结论“URL 写入始终限制为 200 层”被替代：当前可能先写入超预算路径，刷新后再截断，line、scroll 等状态也不会随帧恢复。

模块说明中的 evidence 仍是静态行，而传入 ModuleFrame 的 removed 文件仍保留点击处理。[模块证据与文件入口 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L131 "支持 evidence 引用为静态行，以及组件对传入的 removed 文件仍显示并发出下探事件。") 个人搜索仍是精确文本检索，语义检索尚未接入。[精确文本搜索限制 ↗](../../../apps/web/src/App.vue#L505 "直接支持个人搜索仍使用精确文本检索，并明确语义检索尚未接入。") 自动从观测提炼待办则明确属于后续能力。[待办自动提炼限制 ↗](../../../apps/web/src/App.vue#L687 "直接支持自动从观测中提炼待办尚未接入、被列为后续能力。") review 客户端成功体只作泛型断言，[评审请求解析边界 ↗](../../../apps/web/src/review-api.ts#L174 "支持 review 客户端解析错误 JSON，但对成功响应仅作 TypeScript 泛型断言。") 个人知识客户端则假设成功响应可直接解析为 JSON；[个人知识响应解析 ↗](../../../apps/web/src/knowledge/api.ts#L6 "支持个人知识客户端对成功响应直接调用 response.json，说明其依赖成功体为合法 JSON。") 两者都缺少材料可见的运行时 schema 校验。飞书页面会清空手工 Secret，并声明 botmux 不把 Secret 返回浏览器，但不能据此确认后端加密存储和日志脱敏。[飞书 Secret 浏览器边界 ↗](../../../apps/web/src/LarkSetup.vue#L263 "支持手工 Secret 提交后清除及 botmux 不向浏览器返回 Secret，同时界定其不能证明后端存储安全。")
