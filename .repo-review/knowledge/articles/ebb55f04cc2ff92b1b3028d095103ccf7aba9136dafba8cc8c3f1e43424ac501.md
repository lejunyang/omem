# omem 技术实施提案与验收路线

该文档是2026-09-26的第一轮实施提案，描述早期工程栈、权威存储、摄入、适配、检索和分阶段测试方案。React 已被后续 Vue 决策取代，其余技术选择及阶段完成度仍需实施证据确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="storage-ingestion"></a>
## 权威存储与摄入边界

提案让 PostgreSQL 保存身份、修订、关系、变更、任务与投影水位，并通过事务把当前状态、追加事件及 outbox 协调起来；原件和规范化快照进入对象存储，跨两者不假定分布式事务。连接器事件只是变化线索，必须读取上游真实版本后去重；Git 不执行仓库脚本，AgentRun 不采集隐藏推理，主动发现不得越出已登记范围，撤权优先阻止知识注入。[权威存储与事务建议 ↗](../../../docs/implementation.md#L29 "直接支持 PostgreSQL、SQLAlchemy/Alembic、对象存储、事务事件和可重建投影均属于提案中的存储设计。")[摄入流程和采集边界 ↗](../../../docs/implementation.md#L72 "支持连接器重读真实版本、禁止执行仓库脚本或采集隐藏推理，以及不自动扩大采集范围。")

<a id="retrieval"></a>
## 适配一致性与检索安全

适配器以版本化 manifest 协商能力，缺少能力应明确拒绝。外部命中必须映射并 hydrate 权威片段，复核 ACL、哈希、状态、来源 head 和 generation。检索流程再按 canonical revision 去重、统一重排，并组装有 token 预算的 Context Packet；焦点与支持证据应成对保留，无答案时拒答并说明缺失证据。[适配器能力和投影一致性 ↗](../../../docs/implementation.md#L102 "支持能力协商、权威片段复核以及查询时检查 ACL、generation 与来源状态。")[检索与预算化上下文组装 ↗](../../../docs/implementation.md#L134 "直接支持路由、去重、权威 hydrate、统一重排、Context Packet 预算以及无答案拒答流程。")

<a id="roadmap"></a>
## 路线与测试性质

P0 至 P3 是按验收推进的粗估计划，不是完成记录。目标依次覆盖合同和引擎 PoC、证据工作台、经历自治闭环、团队 ACL 与评估，以及按收益扩展。测试要求包含引用解析与支持准确率、越权或陈旧注入、拒答、恢复、投毒和选区错位；原型验证不能替代服务端及锁定上游版本的适配器契约测试。[阶段退出条件与测试边界 ↗](../../../docs/implementation.md#L184 "支持路线属于粗估计划，并列明验收指标、故障测试及原型不能替代服务端测试。")
