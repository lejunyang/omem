# 通知与变化详情对话框

该 Vue 组件把通知关联的已生效记录、原始证据和外部投递状态集中展示，并通过事件把关闭、证据阅读和版本查看交给父组件处理；它明确区分“收到通知”与“事实已应用”，同时覆盖加载态、空数据、合并投递和错误状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-contract"></a>
## 作用与组件合同

该组件是通知详情的只读对话框，接收开关、详情对象与加载状态，并向父组件发出关闭、打开证据、打开版本三个事件；自身不获取数据、不改变通知状态。它复用 UI 包中的对话框、徽标、按钮、引用和空状态组件，以统一交互与视觉语义。[组件输入、事件与 UI 依赖 ↗](../../../apps/web/src/NotificationDetail.vue#L1 "支持该组件是受控只读视图、复用公共 UI，并把导航动作交由父组件处理的说明。") `NotificationDetail` 从 API 类型模块导入，但给定 API 片段只展示了通知摘要类型，因此详情对象的完整静态合同无法从当前材料独立核对。[前端 API 类型模块 ↗](../../../apps/web/src/api.ts#L26 "说明详情类型来自 API 模块，同时当前所给范围只明确展示通知摘要等基础类型。")

<a id="detail-flow"></a>
## 详情呈现与证据跳转

渲染流程先显示“读取持久状态”的加载提示，随后在详情存在时展示变化类型、创建时间、标题与正文。组件把 application receipt 作为“已生效”的明确凭据；没有 receipt 时直接声明不能把通知本身视为事实已经生效。变更前版本始终按 `beforeId` 条件开放，变更后版本还会排除 `decision` 类型。[已生效记录与版本入口 ↗](../../../apps/web/src/NotificationDetail.vue#L34 "支持加载流程、receipt 语义以及变更前后版本按钮的条件判断。") 原始证据按 `evidenceIds` 逐项生成可打开的引用入口，列表为空则显示“没有提案证据”，实际阅读行为由父组件收到事件后完成。[原始证据列表 ↗](../../../apps/web/src/NotificationDetail.vue#L66 "支持证据引用逐项发出打开事件以及无证据时展示空状态的说明。")

<a id="delivery-states"></a>
## 投递状态与边界条件

投递记录逐项展示渠道、尝试次数和状态。状态映射将失败、未知及普通取消标为危险，等待、发送中与重试等待标为警告，成功投递标为成功；若取消记录带有 `supersededBy`，则显示“已合并”并采用中性色，避免把摘要合并误报为失败。[投递状态色调规则 ↗](../../../apps/web/src/NotificationDetail.vue#L15 "支持失败、等待、成功、取消及已合并状态的视觉语义映射。") 批次包含多条变化时会显示数量；只有未被合并的记录才呈现最后错误，完全没有投递则显示空状态。[投递记录条件渲染 ↗](../../../apps/web/src/NotificationDetail.vue#L81 "支持投递渠道、尝试次数、批次数量、错误隐藏规则与空投递状态的说明。") 当前材料没有测试文件，因而无法确认日期本地化、未知状态回退、事件参数及这些条件分支是否已有自动化断言。
