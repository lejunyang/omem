# 通知、变化与投递结果详情

该组件用统一对话框展示通知的持久状态、内容变化、原始证据和外部提醒投递结果，并通过事件把关闭、阅读证据与打开固定版本交给父组件处理。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 把通知还原为可追溯详情

组件接收打开状态、通知详情和加载状态，在对话框中区分知识更新、材料更新、事项与待判断通知；关闭和返回都交由父层处理。它还按通知时间、标题、正文和记忆更新回执组织信息，并明确“已读”不会改变待办或判断结果，从而把消息阅读与业务状态变更分开。参考 [详情组件输入与事件 ↗](../../../apps/web/src/NotificationDetail.vue#L6 "支持组件接收打开、详情、加载状态，并将关闭、证据和版本阅读操作交给父层的说明。") [通知基础信息展示 ↗](../../../apps/web/src/NotificationDetail.vue#L29 "支持通知类型、时间、正文、回执以及已读语义的界面行为。")

<a id="change-flow"></a>
## 按变化类型展示固定版本差异

当通知带有变化标识、更新后版本，并且属于知识、材料或恢复类型时，组件嵌入变化比较器；非知识更新还可请求父层打开该固定版本。比较器会依据变化标识读取前后快照，生成保留三行上下文的补丁；缺少完整版本关联、请求失败或正文无文字变化时分别给出说明。参考 [变化详情入口 ↗](../../../apps/web/src/NotificationDetail.vue#L44 "支持按变化类型嵌入比较器，以及非知识更新可打开固定版本的流程。") [固定版本差异生成 ↗](../../../apps/web/src/ChangeComparison.vue#L9 "说明变化比较器如何请求快照、生成补丁并处理错误、缺失版本和无文字差异。")

<a id="evidence-delivery"></a>
## 追溯证据与判断外部投递状态

通知携带证据时，每条证据显示为可打开的引用入口，但这里只上报证据标识，具体阅读界面由外层提供。外部投递按渠道列出尝试次数、合并状态、批量变化数量和未被合并的错误；等待、成功、失败等状态映射为不同徽标语气。两个空状态组件位于各自的非空条件块内，因此在当前模板条件下不会显示，这是现有界面边界。参考 [原始证据入口 ↗](../../../apps/web/src/NotificationDetail.vue#L49 "支持证据列表只发出打开事件，并揭示空状态被外层非空条件包围的边界。") [外部提醒投递状态 ↗](../../../apps/web/src/NotificationDetail.vue#L64 "支持渠道、尝试次数、合并、批量数量、错误信息和投递空状态的展示说明。")
