# 通知、应用回执与投递状态详情

在对话框中拆分展示通知内容、事实应用回执、条件化的前后版本入口、原始证据和各渠道投递结果，避免把通知本身误当作事实落库。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="fact-boundary"></a>
## 通知与事实生效的边界

组件本身不读取详情，而由父层传入打开状态、数据与加载状态，并通过事件请求关闭、打开证据或打开修订。[详情组件输入输出合同 ↗](../../../apps/web/src/NotificationDetail.vue#L1 "支持该组件由父层供数，并以事件委托关闭、证据和修订打开行为。") 详情展示变化类型、时间、标题和正文；只有存在 application receipt 时才呈现实体现状和版本，否则明确说明通知本身不代表事实已生效。存在 `beforeId` 时可打开变更前版本；变更后入口同时要求存在 `afterId` 且类型不是 `decision`。材料没有解释排除 decision 的领域原因，因此不能把它确定为长期业务规则。[应用回执与版本入口 ↗](../../../apps/web/src/NotificationDetail.vue#L27 "支持通知与事实生效的区分，以及 beforeId、afterId 和 decision 类型控制版本入口的条件。")

<a id="evidence-delivery"></a>
## 证据与多渠道投递

原始证据逐条委托父组件打开，没有证据时显示空态。投递记录按渠道展示尝试次数和状态；批次包含多项变化时显示数量，最后错误只在该投递未被其他记录替代时呈现。[证据和投递明细 ↗](../../../apps/web/src/NotificationDetail.vue#L66 "支持证据入口、空态、投递尝试、批次数量及错误显示条件。") 状态色调将等待、发送和等待重试归为警告，已送达归为成功，失败、未知及普通取消归为危险；若取消项带有 `supersededBy`，则使用中性色并显示“已合并”。[投递状态色调规则 ↗](../../../apps/web/src/NotificationDetail.vue#L15 "支持不同投递状态以及被替代取消项的视觉语义。") 本组件没有重试、重新发送或标记已读入口，只负责解释父层提供的持久状态。
