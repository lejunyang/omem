# 服务端命令行捕获与 Agent 探测入口

该 CLI 加载本地配置并确定服务地址，将五类命令行输入校验后提交到统一捕获接口，或通过 probe 调用指定 Agent profile；同时约束连接器读取范围、成功输出和失败退出语义。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-dispatch"></a>
## 作用与命令分派

CLI 从进程参数取得命令，加载配置，并优先使用 `OMEM_URL`、否则使用配置端口组成服务地址。[CLI 初始化与共享合同导入 ↗](../../../apps/server/src/cli.ts#L1 "支持命令参数拆分、配置加载、服务地址确定，以及 CLI 使用共享 captureSchema 的论断。") `capture`、`file`、`git`、`lark`、`hook` 五条分支都会构造输入，经共享 `captureSchema` 校验后提交到 `/api/captures`；其中 `capture` 读取文件或标准输入中的 JSON，其余分支调用对应连接器。[五类捕获命令的统一提交入口 ↗](../../../apps/server/src/cli.ts#L29 "支持 capture、file、git、lark、hook 构造输入、执行合同校验并提交统一捕获 API 的论断。")

`probe` 是独立的 Agent 路径：它按参数或默认值 `traex` 查找 profile，以配置的 Agent 工作目录调用 `acp`，profile 不存在则报错。[Agent profile 探测入口 ↗](../../../apps/server/src/cli.ts#L57 "支持 probe 的默认 profile、profile 查找、工作目录传递及缺失 profile 报错的说明。") 未识别的命令只打印用法并立即以成功状态退出。[用法输出、hook 隔离与失败退出码 ↗](../../../apps/server/src/cli.ts#L67 "支持未知命令打印用法并成功退出、hook 保持标准输出为空，以及异常写入标准错误并设置失败退出码的说明。")

<a id="request-and-agent-flow"></a>
## 请求与 Agent 进程边界

请求辅助函数固定发送 JSON，并在配置 token 时附加 Bearer 鉴权；响应先解析为 JSON，HTTP 状态非成功时再把响应内容序列化为异常。[JSON 请求与响应错误处理 ↗](../../../apps/server/src/cli.ts#L14 "支持 JSON 请求、可选 Bearer 鉴权、响应解析和非成功状态抛错的说明。") 因此网络错误、非法 JSON 响应和服务端错误都会进入外层异常处理。

Agent 启动基础设施会过滤部分宿主环境变量，以 `shell: false` 和管道标准流启动子进程；非 Windows 平台使用独立进程组，并在终止后超时升级为强制结束。[Agent 子进程启动与终止边界 ↗](../../../apps/server/src/agents.ts#L32 "支持环境过滤、禁用 shell、独立进程组及分阶段终止行为的说明。") 当前材料只展示 `probe` 调用点和进程基础设施，不能据此确定 ACP 返回的能力结构或模型、effort 的协商规则。

<a id="boundaries-and-failures"></a>
## 读取边界与失败语义

文件连接器先把路径解析为真实路径并限制在允许根目录内，随后执行 500 KB 上限、严格 UTF-8 解码和空字节检查，最终生成文本 part。[文件连接器的读取限制 ↗](../../../apps/server/src/connectors.ts#L10 "支持允许根目录、文件大小、UTF-8 解码、二进制拒绝及文本 part 产出的说明。") Git 连接器还拒绝危险 ref 与仓库路径，先把 ref 解析为固定提交哈希，再从该提交读取指定文件；所以 CLI 默认传入的 `HEAD` 会在连接器内落实为具体提交。[Git 输入校验与固定提交读取 ↗](../../../apps/server/src/connectors.ts#L36 "支持 Git ref、仓库路径校验以及先解析固定提交再读取文件的流程。")

成功时，除 `hook` 外的命令会输出格式化 JSON；`hook` 刻意保持标准输出为空，避免结果被宿主误当作指令。异常会写入标准错误，并将 `process.exitCode` 设为 1。[用法输出、hook 隔离与失败退出码 ↗](../../../apps/server/src/cli.ts#L67 "支持未知命令打印用法并成功退出、hook 保持标准输出为空，以及异常写入标准错误并设置失败退出码的说明。")

<a id="contract-relationship"></a>
## 与共享内容合同的关系

CLI 直接导入共享 `captureSchema`，并在五类捕获请求发送前统一执行解析校验，因而手写 JSON 与连接器产物共用同一入口约束。[CLI 初始化与共享合同导入 ↗](../../../apps/server/src/cli.ts#L1 "支持命令参数拆分、配置加载、服务地址确定，以及 CLI 使用共享 captureSchema 的论断。")[五类捕获命令的统一提交入口 ↗](../../../apps/server/src/cli.ts#L29 "支持 capture、file、git、lark、hook 构造输入、执行合同校验并提交统一捕获 API 的论断。") 提供的合同片段还分别定义了带可选逐 part 来源信息的文本、图片和仅限 HTTP(S) 的链接结构。[共享内容 part 定义 ↗](../../../packages/contracts/src/index.ts#L4 "支持文本、图片、HTTP(S) 链接及可选逐 part 来源信息分别存在对应 schema 的收窄结论。")

不过材料在 `captureSchema` 声明处即结束，尚未展示它如何组合这些 part 定义；因此这里不再沿用“捕获合同已明确允许全部三类 part”的旧结论，只确认各类可复用 schema 存在，是否全部纳入当前捕获输入仍需查看后续合同代码。
