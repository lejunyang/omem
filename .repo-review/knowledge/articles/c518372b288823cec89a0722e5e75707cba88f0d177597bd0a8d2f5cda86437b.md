# 捕获与 ACP 探测命令行入口

该模块把文件、Git、Lark、Hook 和原始 Capture 输入转换为服务端捕获请求，并提供直接 ACP profile 探测；它是薄客户端，不承担持久化。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="dispatch"></a>
## 命令分派与数据路径

CLI 从本地配置推导服务地址，也允许 `OMEM_URL` 覆盖；`send` 统一发送 JSON POST，并在配置 token 时附带 Bearer 认证。`capture` 从指定 JSON 文件或 stdin 读取；`file`、`git`、`lark` 和 `hook` 先调用对应 connector 生成 CaptureInput，再用共享 captureSchema 校验，最终都提交到 `/api/captures`。[HTTP 发送与捕获命令 ↗](../../../apps/server/src/cli.ts#L6 "支持服务地址、认证头、输入读取、connector 转换及统一捕获 API 的说明。")

`probe` 是例外：它不经过 HTTP，而是从本地 profile 配置中选择目标并直接调用 `acp()`。因此 probe 验证的是当前进程的 Agent transport 条件，不等同于服务端 API 或完整助手回合可用性。[本地 ACP profile 探测 ↗](../../../apps/server/src/cli.ts#L57 "说明 probe 直接读取本地 profile 并调用 ACP，而非请求服务端。")

<a id="boundaries"></a>
## 输出与失败边界

缺失必要参数会立即报错；Git 未给 ref 时默认 HEAD，probe 未给 profile 时默认查找 `traex`。未知命令打印帮助并以成功状态退出。成功结果通常格式化输出到 stdout，但 hook 特意保持 stdout 为空，避免其输出被宿主误当成指令；异常写 stderr 并设置退出码 1。[帮助、Hook 静默与退出码 ↗](../../../apps/server/src/cli.ts#L67 "支持未知命令、hook stdout 约束以及异常退出行为。")

CLI 自身没有重试、超时或响应结构校验，除 captureSchema 外的路径、文件大小和 Git ref 安全边界由 connector 实现；服务端认证、持久化和领域规则则由目标 API 承担。[HTTP 发送与捕获命令 ↗](../../../apps/server/src/cli.ts#L6 "支持服务地址、认证头、输入读取、connector 转换及统一捕获 API 的说明。")
