# 本机可选能力的交互式设置流程

该模块承接无组件参数的 `omem setup`，读取现有配置与本机资源，收集可复核的安装计划，依次准备所选能力，并在全部准备成功后保存开关。用户可以取消、稍后重启或立即让本机服务加载新配置；资源探测失败会降级为“未发现”，准备失败则保留已下载资源但不写功能配置。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

`setupInteractive` 是本机可选能力设置的编排入口。它先读取配置快照和资源状态，再把当前的向量检索开关、模型名与决策模式交给向导生成计划。用户在确认计划前退出时，函数返回 `cancelled`，并明确标记配置未变化。参考 [向导入口与取消 ↗](../../../apps/server/src/cli/setup-interactive.ts#L69 "支持入口读取配置、生成计划，以及用户取消时不修改配置的行为。") [计划生成 ↗](../../../apps/server/src/cli/setup-interactive.ts#L69 "支持配置状态和资源状态作为向导输入，以及空计划表示取消。")

该文件通过 `setup-wizard` 收集选择，通过 `setupOptional` 准备资源，通过 `setup-config` 保存配置；只有用户选择立即重启时，才动态加载服务管理模块。职责边界使交互选择、安装动作、配置持久化和进程管理可以分别演进。参考 [计划生成 ↗](../../../apps/server/src/cli/setup-interactive.ts#L69 "支持配置状态和资源状态作为向导输入，以及空计划表示取消。") [准备后保存配置 ↗](../../../apps/server/src/cli/setup-interactive.ts#L84 "支持按顺序准备组件、决策模型参数传递，以及全部成功后才应用配置。") [服务重启与返回值 ↗](../../../apps/server/src/cli/setup-interactive.ts#L115 "支持稍后或立即重启的选择、健康状态退出码和最终返回结构。")

<a id="workflow"></a>
## 一条代表性调用如何执行

以“启用中文向量检索并立即重启”为例，输入来自现有配置快照和本机资源探测。向导返回包含 `embedding` 的计划后，循环调用 `setupOptional` 准备组件；`manualGuidance: false` 表示由当前向导统一给出后续提示。全部组件成功后，代码才把 `retrieval.enabled` 与固定模型名 `memory-zh` 交给配置模块，并允许缺少配置文件时创建它。参考 [准备后保存配置 ↗](../../../apps/server/src/cli/setup-interactive.ts#L84 "支持按顺序准备组件、决策模型参数传递，以及全部成功后才应用配置。")

```mermaid

  A[读取配置与资源] --> B[生成并确认计划]
  B --> C[依次准备组件]
  C --> D[保存所选开关]
  D --> E{现在重启?}
  E -->|是| F[重启并检查服务]
  E -->|否| G[返回已准备结果]
```
参考 [计划生成 ↗](../../../apps/server/src/cli/setup-interactive.ts#L69 "支持配置状态和资源状态作为向导输入，以及空计划表示取消。") [准备后保存配置 ↗](../../../apps/server/src/cli/setup-interactive.ts#L84 "支持按顺序准备组件、决策模型参数传递，以及全部成功后才应用配置。") [服务重启与返回值 ↗](../../../apps/server/src/cli/setup-interactive.ts#L115 "支持稍后或立即重启的选择、健康状态退出码和最终返回结构。")

若选择重启，模块调用服务管理器、输出状态，并在服务不在线或健康检查失败时设置非零退出码。最终返回 `prepared`、计划、各组件结果、配置路径和变更标记；执行过重启时还附带服务状态。参考 [服务重启与返回值 ↗](../../../apps/server/src/cli/setup-interactive.ts#L115 "支持稍后或立即重启的选择、健康状态退出码和最终返回结构。")

<a id="boundaries"></a>
## 资源探测与失败边界

资源发现刻意保持离线和轻量。文档解析与本地决策能力只检查各自虚拟环境里的 Python 是否存在；模型工作区不存在时直接返回这两项结果。参考 [轻量资源检查 ↗](../../../apps/server/src/cli/setup-interactive.ts#L15 "支持虚拟环境检查以及模型工作区不存在时提前返回的边界。")

模型探测并发执行六个 `osdk model show --json --offline`，单项限制为 5 秒，并同时验证返回的快照路径存在。任一命令失败、超时或 JSON 解析失败都会被记为 `false`，不会中断整个向导；PDF 文档模型只有布局与表格两个别名都存在时才算已安装。参考 [离线模型探测 ↗](../../../apps/server/src/cli/setup-interactive.ts#L25 "支持并发离线查询、超时与失败降级，以及组合模型判定规则。")

资源准备按计划顺序执行。某一组件失败时，异常会说明停止位置和此前完成项；功能配置尚未保存，已经准备的运行环境或下载缓存则保留，重跑可以复用。这个顺序避免配置先启用、资源却没有准备完整。参考 [准备失败语义 ↗](../../../apps/server/src/cli/setup-interactive.ts#L85 "支持失败时保留已完成资源、禁止提前保存配置并报告停止阶段。")
