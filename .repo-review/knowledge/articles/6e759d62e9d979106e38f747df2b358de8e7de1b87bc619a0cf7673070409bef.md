# 整理文章，以及原文更新后怎么处理

从知识库选材、填写阅读目标，到检查文章、处理失败与原文换版的完整操作。以“预算八十元、图书馆集合”为教学示例，说明无关导读变化为何可以继续阅读、预算改为一百二十元后怎样核对受影响内容，以及如何在同一篇文章上重新整理并回看写作时的旧原文。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="first-draft"></a>
## 从材料和一个明确问题开始

先把活动约定保存为原始材料，再进入**知识库**点击**整理文章**。如果你已经在某个分类里，文章会沿用这个分类；从知识库根部开始，则会按内容归类。

以下是贯穿本文的教学示例。为了让后续变化容易判断，原材料用清楚的小节保存：

```markdown
# 活动约定

## 预算
预算是八十元。

## 地点
在图书馆集合。
```

弹窗分两步：

1. 在**选择材料**中按标题或路径查找并勾选这份活动约定。可以切换“已选 N 项”复查，也可以跨分类选择其他相关材料。参考 [选择整理材料 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L124 "支持材料搜索、勾选、查看已选项、继续显示和跨分类选择等第一步操作。")
2. 进入**说明阅读目标**，填写：
   - 文章主题：例如“参加活动前要知道什么”
   - 想弄懂什么：例如“参加者读完能知道要准备多少钱、到哪里集合”
   - 写给谁看：例如“活动参加者”
3. 确认页面显示的材料数量和保存位置，点击**开始整理**。系统会调查材料、撰写并复核，完成后文章出现在知识库。参考 [填写阅读目标并开始整理 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L209 "支持主题、问题、读者字段，以及材料数量、保存位置和开始整理按钮的可见行为。")

问题要写成读完后能检查的结果，而不是只写“整理一下”。“要准备多少钱、到哪里集合”能直接用于验收；系统也更容易围绕读者真正要做的事组织文章。

<a id="wait-and-retry"></a>
## 看懂整理状态，失败后从原计划重试

提交后，知识库顶部会显示“正在整理”，并说明文章要经过调查、撰写与复核；完成后会显示“已完成”和**阅读文章**。等待页面显示结果即可，不需要反复提交。参考 [整理中与完成后的可见状态 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L311 "支持正在整理、调查撰写复核说明、失败原因、完成提示和阅读文章入口。")

如果整理失败：

- 新文章不会出现一份未通过的正文；它会留在**准备整理**区域，显示“上次整理未完成，阅读目标已保留”。先看页面顶部的失败原因，再点击**重试整理**。参考 [失败计划与重试入口 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L419 "支持准备整理区域保留失败计划、显示阅读目标已保留，并提供重试整理按钮。")
- 如果是在重新整理已有文章，原来可用的正文仍保留，失败结果不会把它覆盖。你仍可打开旧文，确认材料和目标后再次点击**重新整理这篇**。
- 若页面提示尚未配置 Agent，先去**能力与连接**完成配置；若已有知识整理正在运行，则等它结束后再试。参考 [配置、并发与重试提示 ↗](../../../apps/server/src/knowledge/api.ts#L169 "支持缺少 Agent 配置、已有整理运行、保存计划后发起整理等用户可见失败条件。")

失败后不必从头重建阅读目标。系统保留计划；新结果只有完成调查、写作和复核后才会替换当前展示的版本。参考 [失败保留计划和旧文 ↗](../../../docs/reader-first/publication-lifecycle.md#L5 "说明失败计划可以重试，重新整理失败不会覆盖原有有效正文。")

<a id="reader-check"></a>
## 用自己的问题验收文章

打开文章后，先看顶部的**读完这一篇**。它就是你填写的阅读目标。对本例，可以按下面四项检查：

- 不回看原材料，文章能否直接回答“准备八十元、在图书馆集合”？
- 金额和地点附近是否有可点击的引用？
- 点击引用后，原话和引用范围是否真的支持该结论？
- 页面是否出现“部分内容需要核对”或某一章节的具体提醒？

文章底部的“来源与生成记录”能告诉你生成和复核信息，但“已完成”或“已复核”不等于你已经读懂，也不能代替上述检查。参考 [文章阅读目标与章节提醒 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L87 "支持文章顶部阅读目标、局部待核对提示、引用入口和来源与生成记录的页面表现。") [读者验收不同于模型复核 ↗](../../../docs/reader-first/writing.md#L34 "明确区分事实检查、读者是否完成页面问题和独立模型复核。")

如果页面出现**待核对与后续调查**，先看未知问题为什么重要以及建议的下一步：

- 缺少你掌握的背景时，点**补充背景**，填写内容并**保存为材料**。
- 需要以后调查时，点**加入待办**。
- 保存补充只把它加入下次调查，不会立即改写正文；随后还要点击**重新整理这篇**并再次验收。参考 [补充背景或加入待办 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L31 "支持补充背景、保存为材料、加入待办，以及保存后提示需在重新整理时结合补充调查和改写。") [调整目标并维护同一篇 ↗](../../../docs/reader-first/publication-lifecycle.md#L37 "支持重新整理、补充背景进入下次选材、调整材料与目标、保持文章身份和旧版引用，以及运行中计划变化时保护新计划。")

当目标中的关键事实没回答、结论没有可打开的来源、章节提示来源变化或不可读，或者未知事项会影响你的行动时，应继续补材料。若事实齐全但文章答非所问，则用**调整材料与目标**把读者和问题写得更具体。

<a id="change-example"></a>
## 先只改导读，再把预算改为一百二十元

下面继续使用教学示例，并假设生成结果把费用与集合说明分成不同章节。实际文章的章节数由内容和阅读目标决定；短文章也可能合并成一节。参考 [文章结构由读者目的决定 ↗](../../../docs/reader-first/writing.md#L16 "说明简单材料可短写、复杂页面才展开，章节和篇幅没有固定配额。")

**第一次变化：只在“预算”和“地点”之前增加一段导读。**

只要原材料仍有可识别的小节，而且“预算”“地点”小节的标题与内容没有变化，行号移动不会使对应解释失效。文章仍可阅读，引用仍指向写作时的原文。参考 [无关导读变化不影响原章节 ↗](../../../apps/server/src/knowledge/lifecycle.ts#L40 "支持完整 Markdown 章节内容未变时允许行号移动，并继续使用原解释。")

**第二次变化：把“预算是八十元”改成“预算是一百二十元”。**

知识库目录会给文章显示**待更新**；打开文章后，费用相关章节会提示需要核对，并在下方保留原有解释。集合章节没有变化时仍可阅读。系统不会因为同一份原文中的一个小节变化就删除整篇文章。参考 [预算变化只影响相关章节 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L93 "教学测试验证导读移动后文章仍可用；预算改为一百二十元后费用节待核对、集合节仍为当前。")

这里有两个边界：

- 如果生成文章把预算与地点写在同一节，这个合并章节会一起等待核对；“费用变、集合不变”是帮助理解的分节示意，不是固定版式。
- 如果集合安排实际上依赖预算，文章整理时把预算记录为集合节的重要背景后，预算变化也会让集合节等待核对。反过来，不能仅因为两个事实在同一文件里，就默认它们互相依赖。参考 [背景前提也会触发核对 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L166 "验证集合方案若以预算为明确背景前提，预算变化也会使集合章节待核对。")

这种局部判断依赖可识别的 Markdown 小节或代码结构。没有清楚结构的普通文本发生变化时，系统可能只能把整份原文视为已变化。

<a id="refresh-same-article"></a>
## 在同一篇文章上更新，并回看旧来源

看到**待更新**后，先打开文章阅读每一节的提示。未受影响的章节可以继续使用；当前系统不会在原文换版后自动重写文章。

接着按需要选择：

- 材料和阅读目标都不变：点击文章底部的**重新整理这篇**。
- 要增删材料，或修改主题、问题、读者：点击**调整材料与目标**。弹窗会预选现有材料；完成两步后点击**保存并重新整理**。

这两种操作都维护同一篇文章。旧正文会一直保留到新结果成功发布；失败时仍显示旧文。文章身份、旧版及其固定引用也会保留。参考 [调整目标并维护同一篇 ↗](../../../docs/reader-first/publication-lifecycle.md#L37 "支持重新整理、补充背景进入下次选材、调整材料与目标、保持文章身份和旧版引用，以及运行中计划变化时保护新计划。")

想确认旧解释当时依据什么，点击正文中紧邻论断的引用。引用面板先说明这条来源为何支持该段，再打开写作时固定的原文。原文页会标明**当前版本**或**历史版本**并显示引用位置；即使当前预算已经是 120 元，旧文章的引用也不会悄悄跳到新文字。参考 [引用打开固定目标 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L83 "支持引用面板先展示引用理由，再按固定文章版本解析并打开对应材料范围。") [原文显示当前或历史版本 ↗](../../../apps/web/src/knowledge/KnowledgeSource.vue#L33 "支持原文页面的版本徽标、引用位置、引用片段和完整 Markdown 阅读。")

完成重新整理后，再用原来的问题验收：金额是否已变为 120 元、地点是否仍是图书馆、两项是否都有匹配的新引用、页面是否还有待核对提示。

目前要记住的操作边界是：

- 原文换版会触发核对状态，**不会自动重写**所有受影响文章。
- 整理失败会保留计划和有效旧文，**不会发布失败草稿**。
- 局部保留依赖原文具有可识别的结构，不能对任意文本保证同样精细。
- 模型复核是发布步骤，**最终是否回答你的问题仍由你验收**。参考 [变化处理与当前自动化边界 ↗](../../../docs/reader-first/publication-lifecycle.md#L27 "概括章节级变化、普通文本边界、显式重新整理、失败保留和用户验收要求。")
