# 把材料整理成文章，并在原文变化后继续维护

面向个人用户的知识整理操作指南：用“预算八十元、图书馆集合”的教学示例，说明如何选材、填写阅读目标、判断生成结果、处理失败、辨认受影响章节、回看写作时的旧来源，并在当前能力边界内维护同一篇文章。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="scenario"></a>
## 先看一个要持续维护的例子

假设你有一份教学材料，写着“预算是八十元”“地点在图书馆”。你想把它整理成一篇《春游安排》，既让参加者马上找到费用和集合地点，也希望以后原文变化时，不必把整篇文章推倒重来。这里的春游是**教学示例**，不是用户真实事件。参考 [春游教学材料 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L38 "支持教学示例的初始输入：预算八十元、地点在图书馆，以及文章分成费用和集合两节。")

完成后，你应能在知识库读到“费用”和“集合”两部分；以后只改导读，两部分仍可使用；把预算改成一百二十元时，费用部分会提示核对，集合说明则尽量继续可读。系统保存写作时的来源，因此旧解释仍能追溯，但“能打开旧来源”不等于旧数字今天仍适用。参考 [材料变化后的文章目标 ↗](../../../docs/reader-first/publication-lifecycle.md#L1 "说明只改导读、修改预算和固定旧引用时，文章应呈现的用户可见结果。")

<a id="create"></a>
## 两步整理：先选材料，再说清读者问题

在**知识库**进入合适的分类，保持在“主题文章”，点击右上角的**整理文章**。如果从某个分类发起，文章会沿用该位置；从知识库根部发起，则按内容归类。参考 [知识库整理入口 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L344 "支持主题文章入口、分类页和“整理文章”按钮的位置与分类行为。")

第一步“选择材料”：按标题或路径查找，勾选相关文档、代码或记录；可以切换到“已选 N 项”、继续显示更多结果，也可以跨分类选择。未选择材料时不能进入下一步。参考 [选择材料 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L107 "支持材料搜索、勾选、查看已选、分批显示、跨分类选择和未选择时禁止下一步。")

第二步“说明阅读目标”，填写：

- **文章主题**：春游安排
- **想弄懂什么**：预算是多少、在哪里集合；材料变化后哪些说明仍能使用
- **写给谁看**：参加春游的人

页面会再次显示材料数量和保存分类。确认后点**开始整理**。参考 [填写阅读目标 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L173 "支持文章主题、想弄懂的问题、阅读对象、保存分类和开始整理的第二步操作。")

```mermaid
flowchart LR
  A[选择材料] --> B[说明阅读目标]
  B --> C[调查、撰写与复核]
  C --> D[在知识库阅读]
```

这个流程的重点是：点击开始只表示任务已经提交，文章要在调查、撰写和复核完成后才会出现。参考 [整理进度与完成入口 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L302 "支持提交后的正在整理状态，以及完成后才出现“阅读文章”的可见结果。")

<a id="read-and-check"></a>
## 看到“已完成”后，先按阅读目标验收

整理过程中，页面顶部显示“正在整理”；成功后才显示“已完成”和**阅读文章**。打开文章，先看顶部“读完这一篇”的目标，再读正文。若文章部分依据已变化，顶部会提示“部分内容需要核对”，具体章节前还会说明原因，并保留原有解释；正文中的引用可以点开原文。参考 [文章目标与章节状态 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L69 "支持文章顶部阅读目标、整篇待核对提示、逐节原因、保留旧解释和点击引用查看原文。")

不要只看“已完成”或“经过复核”就结束。请回到最初问题，用自己的话回答：预算是多少、在哪里集合、哪些说明在原文变化后仍可用、下一步该在哪里操作；再点击关键数字和地点旁的引用，确认来源确实支持附近说法。独立复核帮助检查事实与页面目标，但不能代替你判断文章是否真的好用。参考 [读者验收原则 ↗](../../../docs/reader-first/writing.md#L28 "支持以是否回答阅读问题、能否找到下一步来验收，而不把独立模型复核当成用户验收。")

<a id="retry"></a>
## 生成失败时，保留目标并重试

首次整理失败时，知识库会显示失败原因；“准备整理”区域保留文章主题和阅读目标，并提供**重试整理**。若任务只是尚未开始，则显示**开始整理**。参考 [失败后重试 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L412 "支持准备整理区域保留阅读目标，并按状态提供重试整理或开始整理。")

如果已经有一版文章，重新整理失败不会用失败结果覆盖旧正文：旧版和原来的阅读目标都会保留，直到新结果完成复核并发布。先阅读页面给出的错误；确认 Agent 已配置、材料仍可用后，再重试。若提示所选材料已经更新，刷新页面后重新提交。参考 [失败保留与材料更新提示 ↗](../../../docs/reader-first/operations.md#L39 "说明失败时旧正文不会被覆盖、错误会显示，以及所选材料变化时需要刷新重试。")

<a id="changes"></a>
## 原文变化后，按章节判断是否还能用

原文变化不会简单地让整篇文章消失。系统会比较引用所在的完整章节或代码上下文，尽量只标出需要核对的部分；整篇仍留在目录，当前搜索只使用仍可用的章节。这个判断用于缩小复查范围，不是对语义完全不变的保证。参考 [按章节判断变化 ↗](../../../docs/reader-first/publication-lifecycle.md#L27 "说明变化判断按引用章节或代码上下文进行、整篇留在目录、未受影响章节继续可用，以及当前语义分析的限制。")

| 原文变化 | “费用”节 | “集合”节 | 你应怎么做 |
| --- | --- | --- | --- |
| 只在开头增加一句导读，预算和地点正文未变 | 仍可读 | 仍可读 | 正常阅读，必要时抽查引用 |
| 预算从八十元改为一百二十元，地点未变 | 需要核对 | 仍可读 | 不再沿用旧费用；集合说明可继续使用 |
| 集合方案实际上依赖旧预算 | 需要核对 | 也需要核对 | 两节都重新判断 |

前两种结果由同一教学场景验证：无关导读移动不影响文章；预算实质变化后，费用节退出当前使用，集合节仍保留。参考 [导读与预算变化示例 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L93 "支持无关导读变化后两节仍可用，以及预算改为一百二十元后仅费用节需要核对、集合节继续可读。") 如果文章明确记录了“集合方案以旧预算为前提”，预算变化也会让集合节提示核对。参考 [章节之间的实际依赖 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L166 "支持当集合方案明确依赖旧预算时，预算变化也会使集合节需要核对。")

普通文本若没有稳定章节，或含有系统无法识别的跨文件条件和运行环境，可能需要更大范围复查。因此，即使页面写着“仍可读”，也要结合自己的用途确认。

<a id="refresh-and-history"></a>
## 维护同一篇，并回看写作时的旧来源

要更新现有文章，打开它，在底部点击**重新整理这篇**。系统沿用这篇文章保存的阅读目标，使用当前版本的原有材料重新运行；成功后更新同一篇入口，不会另建一篇同名文章。更新仍需经过调查、写作和复核；失败时旧版继续保留。现在是显式更新，后台不会在原文变化后自动重写所有文章。参考 [重新整理同一篇 ↗](../../../docs/reader-first/publication-lifecycle.md#L37 "说明重新整理沿用同一文章身份、失败保留旧版，并明确当前不会后台自动重写所有受影响页面。")

要理解旧解释当时依据什么，点击正文附近的引用。引用页会显示引用理由、原材料标题、引用位置，并标明“原始材料 · 当前版本”或“原始材料 · 历史版本”；代码可向上或向下展开，Markdown 可同时查看引用片段和完整原文。参考 [固定来源阅读 ↗](../../../apps/web/src/knowledge/KnowledgeSource.vue#L33 "支持引用页标识当前或历史版本、显示引用位置，以及展开代码上下文或查看完整 Markdown 原文。")

看到“历史版本”时，把它理解为**写作时的证据**：它能解释旧文章为什么那样写，却不能证明旧结论现在仍然有效。回到文章顶部和对应章节，查看是否已有“需要核对”提示。

<a id="fill-gaps"></a>
## 文章还答不全时，补背景或留下待办

如果文章底部出现“待核对与后续调查”，说明材料里仍有影响理解或使用、但尚不能确定的问题。每项都会说明为什么重要和下一步是什么。你可以选择**补充背景**，把自己的回答保存成新的原始材料；也可以选择**加入待办**，以后继续调查。参考 [补充背景与待办 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L17 "支持待核对问题的说明、补充背景、保存为材料和加入待办等用户动作。")

适合继续补材料的信号包括：正文明确写着未知；后续调查列出具体缺口；某节提示固定来源已变化或不完整；你对照“读完这一篇”仍回答不了核心问题。不要因为文章没有穷举所有边界，就机械地继续加材料。补充背景后，相关文章会等待重新核对。参考 [补充后等待核对 ↗](../../../apps/server/src/knowledge/repository.ts#L284 "支持用户回答被保存为原始材料，并使相关文章进入等待重新核对状态。")

<a id="current-limits"></a>
## 当前还需要手动处理的两件事

第一，**原文变化后要由你显式重新整理**。系统会提示受影响范围并保留可读部分，但不会在后台自动改写全部文章。参考 [重新整理同一篇 ↗](../../../docs/reader-first/publication-lifecycle.md#L37 "说明重新整理沿用同一文章身份、失败保留旧版，并明确当前不会后台自动重写所有受影响页面。")

第二，**同一篇文章目前不能在界面中增选新的材料范围**。“重新整理这篇”复用原来保存的阅读目标和材料集合；运行时只会在当前材料中重新找到这些原有材料。参考 [重新整理复用旧计划 ↗](../../../apps/server/src/knowledge/api.ts#L177 "支持“重新整理这篇”只取文章已保存的阅读计划，而首次整理才接收新的材料选择。") [原有材料范围 ↗](../../../apps/server/src/knowledge/pipeline.ts#L266 "支持重新运行时按阅读计划保存的材料集合，从当前可用材料中选择同一范围。") 因此，“补充背景已保存”为材料，并不表示它已经自动进入这篇文章的下一版。若新材料必须纳入同一篇，当前普通界面还没有完整闭环；不要寻找并不存在的“编辑材料”按钮。

最终可用性的判断仍在你手里：文章应回答最初的问题，关键事实能沿引用核对，待更新提示得到处理，并且你知道下一步是继续阅读、补背景，还是重新整理。
