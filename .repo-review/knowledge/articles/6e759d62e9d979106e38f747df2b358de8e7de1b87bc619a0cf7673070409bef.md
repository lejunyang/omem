# 把材料整理成文章，并在原文变化后继续维护

从知识库选材和说明阅读目标开始，用“预算八十元、图书馆集合”的活动材料演示首次整理、失败重试、文章验收、固定原文阅读，以及预算变化后维护同一篇文章的完整操作。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="start"></a>
## 先明确这次要解决什么

假设你手里有一份活动说明：参加者准备 **八十元预算**，并在 **图书馆集合**。你希望把它整理成一篇参加前就能直接使用的文章，而不是得到一份笼统摘要。

在知识库首页或某个分类中点击“整理文章”。参考 [知识库整理入口 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L367 "支持知识库首页或分类页均提供“整理文章”入口。") 从分类内开始时，当前分类路径会传给整理弹窗，并随文章计划保存；从知识库首页开始、没有分类路径时，界面会提示按内容归类。参考 [当前分类传入整理弹窗 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L469 "支持分类页把当前分类路径传给整理弹窗；编辑已有文章时则沿用文章计划中的分类路径。")、[分类路径写入文章计划 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L90 "支持整理弹窗在分类路径非空时把该路径随文章计划提交保存。")、[阅读目标与归类提示 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L209 "支持文章主题、想弄懂的问题、读者，以及有无分类路径时分别显示保存到当前分类或按内容归类。")

<a id="compose"></a>
## 选择材料，并把问题写得可检查

第一步，在“选择材料”中用标题或路径查找活动说明，勾选真正包含预算和集合地点的原文。可以跨分类选择，也可以切到“已选材料”检查是否漏选；没有选择材料时不能进入下一步。参考 [选择材料步骤 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L132 "支持两步流程、材料搜索、勾选、查看已选项和跨分类选材。")

第二步填写三个字段：

- **文章主题**：例如“参加活动前要准备什么”。
- **想弄懂什么**：例如“带多少钱、在哪里集合，这些信息适用于谁或哪次活动？”
- **写给谁看**：例如“第一次参加活动的人”。

这样写的好处是，文章生成后可以逐项验收：金额、地点和适用范围缺一项，都说明结果还没完整回答问题。确认所选材料数量和保存分类后，点击“开始整理”；若是在编辑已有文章，按钮会变为“保存并重新整理”。参考 [阅读目标与归类提示 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L209 "支持文章主题、想弄懂的问题、读者，以及有无分类路径时分别显示保存到当前分类或按内容归类。")、[开始或重新整理 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L268 "支持未选材料时不能继续，以及新文章和已有文章对应的提交动作。")

整理依赖已配置的 Agent；若页面提示“请先在能力与连接中配置 Agent”，先完成该连接再重试。参考 [Agent 配置提示 ↗](../../../apps/server/src/knowledge/api.ts#L177 "支持整理前需要配置 Agent，以及缺少配置时用户会看到的提示。")

<a id="run-and-retry"></a>
## 等待结果；失败时从原计划重试

开始后，知识库会显示“正在整理”，并说明文章要经过调查、撰写与复核。成功时会出现“已完成”和“阅读文章”，点击即可打开正文。参考 [整理中的状态与完成入口 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L311 "支持运行中、失败和发布完成时页面展示的状态，以及阅读文章入口。")

如果第一次整理失败，前往知识库的“准备整理”区域。这里会显示“上次整理未完成，阅读目标已保留”，点击“重试整理”即可继续，不必重新填写同一套目标。参考 [失败计划与重试 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L419 "支持首次整理失败后阅读目标仍保留，并可在准备整理区域重试。")

如果是在重新整理已有文章，新结果失败也不会抹掉原来的可读版本：旧正文和当前计划会保留，直到新的结果完成复核并发布。参考 [旧正文保留规则 ↗](../../../docs/reader-first/publication-lifecycle.md#L5 "支持生成失败保留计划、重新整理时旧正文持续可用，直到新结果发布。") 失败信息通常会直接显示原因；若所选材料在整理期间发生变化，较早的结果不会发布，刷新材料后再重试。参考 [生成期间材料变化 ↗](../../../docs/reader-first/operations.md#L39 "支持固定材料在整理期间变化会阻止较早结果发布，并向用户保留旧正文。")

<a id="accept"></a>
## 判断文章是否真的可用

打开文章后，先看“读完这一篇”的目标，再逐项检查正文是否回答了最初问题。对于本例，至少应明确金额、集合地点和适用条件；只有文字流畅、或者页面显示完成，并不等于这些问题都得到了回答。每个需要核对的章节会显示具体提示，未受影响的章节仍可继续阅读。参考 [阅读目标与章节提示 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L88 "支持文章目标、部分内容待核对、章节原因提示和其他章节继续阅读。")

接着点击金额、地点等关键结论旁的引用。引用抽屉会先解释这条来源为什么支持附近说法，再打开对应原文位置。参考 [引用理由与原文跳转 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L83 "支持引用抽屉先显示理由，再按已解析的固定来源打开原文位置。") 原文页会明确标出“当前版本”或“历史版本”，并显示引用行；因此以后预算改变时，旧文章中的“八十元”仍能回到写作当时的文字，而不会静默跳成“一百二十元”。参考 [当前与历史原文 ↗](../../../apps/web/src/knowledge/KnowledgeSource.vue#L34 "支持原文页区分当前版本和历史版本，并展示引用行和可展开内容。")

如果文章显示“待核对与后续调查”，再展开它查看材料还不能确定的问题、原因和下一步；没有可显示事项时，这个区域不会出现。能由你确认的事实可点“补充背景”并保存为材料，需要另行查证的事项可加入待办。参考 [未决事项区域的显示条件 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L120 "支持文章只有在记录了问题时才挂载待核对区域，避免暗示每篇文章都有该入口。")、[补充背景与待办 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L60 "支持该区域仅在存在可显示事项时出现，并允许读者查看问题、补充背景或加入待办。") 独立复核是发布前的一道检查，不代替你按自己的使用场景验收文章。参考 [变化判断的边界 ↗](../../../docs/reader-first/publication-lifecycle.md#L27 "支持章节按引用和重要前提复查、未变章节继续使用，以及该判断并非完整语义证明和复核不代替读者验收。")

<a id="source-change"></a>
## 原文变化后，先看哪些章节受影响

现在沿用同一篇活动文章观察两次变化：

1. **只改导读**：预算仍是八十元，集合地点仍是图书馆。文章不应仅因原文行号移动就整篇失效；两节解释可以继续使用。
2. **把预算改为一百二十元**：目录中的文章会标为“待更新”。打开后，“费用准备”应提示需要核对；“集合地点”若其依据未变，仍可阅读。旧文章不会消失，原引用仍打开写作时的版本。参考 [活动材料变化示例 ↗](../../../docs/reader-first/publication-lifecycle.md#L1 "支持只改导读不应使两节消失、预算变化只提示受影响解释，并保留写作时版本。")、[目录待更新状态 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L398 "支持原文变化后文章仍留在目录，并以待更新标签提示读者。")

不过，不要把这理解成“预算变化永远只影响费用一节”。如果集合安排明确以前一预算为重要前提，集合节也会被提示复查；对于无法识别清晰章节结构的普通文本，变化范围也可能更大。系统是在缩小复查范围，并不是自动证明其余语义完全不变。参考 [变化判断的边界 ↗](../../../docs/reader-first/publication-lifecycle.md#L27 "支持章节按引用和重要前提复查、未变章节继续使用，以及该判断并非完整语义证明和复核不代替读者验收。")

目录里的“待更新”和正文中的章节提示，都是让你决定先读什么、重整什么的路标。需要核对的旧解释仍会展示，但在重新整理前不应把它当成已经适用于新原文的结论。参考 [阅读目标与章节提示 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L88 "支持文章目标、部分内容待核对、章节原因提示和其他章节继续阅读。")

<a id="maintain"></a>
## 在同一篇文章上重新整理或补材料

文章末尾有两个维护动作：

- **重新整理这篇**：沿用当前材料和阅读目标，用最新原文重新调查、撰写、复核；成功后更新的是同一篇文章。
- **调整材料与目标**：重新打开两步弹窗，已有材料会预选。你可以增删材料，修改主题、问题或读者，再点击“保存并重新整理”。参考 [文章维护入口 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L444 "支持已有文章底部的重新整理和调整材料与目标两个动作。")

编辑界面会明确说明：重新整理后仍是同一篇文章，旧版引用继续保留。参考 [同篇文章编辑说明 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L124 "支持调整时预期仍为同一篇文章，并继续保留旧版引用。") 如果文章漏答是因为少选了材料，就补选材料；如果材料够但文章偏题，就把“想弄懂什么”改得更具体；如果原文根本没有答案，先补充新的原始材料，不要让文章用常识猜预算、地点或适用时间。

“补充背景”保存的回答会进入这篇文章下一次整理所用的材料，但保存本身不会立刻改正文；仍需点击“重新整理这篇”，并再次检查结果。当前维护是**显式触发**的：系统会标出可能受影响的章节，却不会在后台自动重写所有文章。参考 [显式维护与补充材料 ↗](../../../docs/reader-first/publication-lifecycle.md#L37 "支持重新整理不新建同名文章、补充背景进入下次选材，以及当前不会后台自动改写。")
