# 整理文章，以及原文更新后怎么处理

从统一知识库选择材料、说明阅读目标，到查看生成结果、重试失败任务、判断原文变化影响并重新整理同一篇文章的完整操作指南；同时说明固定旧版引用与显式更新的边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="start"></a>
## 从一份活动约定开始

先运行 `osdk run dev`，打开终端给出的网页地址，再进入主应用的“知识库”。开发模式会载入仓库材料和已经发布的知识，但启动本身不会自动生成整库文章。参考 [开发模式启动 ↗](../../../docs/reader-first/operations.md#L3 "支持从统一 dev 入口进入知识库，以及启动不会自动生成整库文章。")

下面用一个**教学示例**贯穿流程：原始材料《活动约定》写着“预算是八十元”“地点在图书馆”。在知识库点击“整理文章”，第一步按标题或路径找到并勾选这份材料；材料可以跨分类选择。参考 [活动教学材料 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L23 "给出预算八十元、图书馆集合这组教学输入，明确它是测试中的示例。") [选择材料步骤 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L94 "支持按标题或路径筛选、勾选材料并允许跨分类选择的用户操作。")

第二步填写“文章主题”“想弄懂什么”“写给谁看”。例如主题写“春游安排”，目标写“参加者需要知道费用和集合地点”，读者写“参加春游的人”。当前网页没有分开的“场景”和问题列表控件：“想弄懂什么”会同时保存为目标、场景和唯一问题；从某个分类发起会沿用该分类，否则按内容归类。参考 [阅读目标表单 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L173 "支持第二步的主题、目标、读者字段和分类提示。") [新文章计划映射 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L58 "说明网页新建文章使用随机 key，并把同一目标写入 goal、scenario 和 questions。")

<a id="publish"></a>
## 提交后怎样得到可读文章

点击“开始整理”时，浏览器提交的是所选材料的当前版本。服务端会确认这些版本仍有效，再把选择保存为稳定的材料身份；若选择后原文已经换版，会提示刷新后重试。参考 [提交与版本校验 ↗](../../../apps/server/src/knowledge/api.ts#L184 "支持服务端校验阅读计划、所选版本并转换为稳定材料 key，换版时拒绝旧选择。")

```mermaid
flowchart LR
  A[选择材料与阅读目标] --> B[保存页面计划]
  B --> C[调查相关原文]
  C --> D[撰写文章]
  D --> E[独立复核]
  E -->|通过| F[发布到知识库]
  E -->|仍需修改| D
```

页面计划先保存，状态随后进入写作；研究者完成自主调查后，写作者生成全文，独立复核者检查结果。只有被接受的文档才会发布，未通过的草稿会在本轮交给刷新角色精确修订。参考 [页面写作主链 ↗](../../../apps/server/src/knowledge/pipeline.ts#L251 "支持先保存计划、进入写作、完成自主调查并在成功或异常后记录页面状态。") [独立复核发布门槛 ↗](../../../apps/server/src/knowledge/pipeline.ts#L161 "支持写作、独立复核、修订循环以及只发布 accepted 文档。")

知识库每五秒读取一次文章、页面计划和当前运行状态。参考 [状态轮询 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L179 "支持每五秒读取文章、页面计划、材料和运行状态。") 运行中会说明文章将在调查、撰写与复核完成后进入目录；发布完成后会显示“阅读文章”按钮。参考 [运行结果提示 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L301 "支持运行中说明处理阶段，以及发布后显示阅读文章按钮。") 打开文章后，可以看到阅读目标、正文、行内引用，以及生成模型和独立复核者信息。参考 [文章阅读内容 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L69 "支持文章页展示阅读目标、行内引用、更新提示及生成和复核信息。")

<a id="retry"></a>
## 失败后保留什么，怎样重试

生成失败不会丢掉阅读目标：计划独立保存在页面记录中，状态改为失败并保留错误。若这是首次整理、还没有正文，“准备整理”区域会显示“上次整理未完成，阅读目标已保留”，点击“重试整理”即可。参考 [计划与失败状态持久化 ↗](../../../apps/server/src/knowledge/repository.ts#L127 "支持计划独立保存以及 writing、published、failed 状态和错误记录。") [失败重试与重新整理 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L411 "支持失败计划提示、重试按钮和已有文章的重新整理按钮。")

如果是重新整理已有文章时失败，旧正文仍可阅读。原因是新版本只有在独立复核接受后才会写成新修订并替换当前版本；失败结果不会执行发布。文章底部的“重新整理这篇”与失败页的“重试整理”都调用同一刷新入口。参考 [独立复核发布门槛 ↗](../../../apps/server/src/knowledge/pipeline.ts#L161 "支持写作、独立复核、修订循环以及只发布 accepted 文档。") [失败重试与重新整理 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L411 "支持失败计划提示、重试按钮和已有文章的重新整理按钮。") [同计划刷新接口 ↗](../../../apps/server/src/knowledge/api.ts#L169 "支持刷新读取同一 key 保存的 brief，并说明无计划时拒绝。")

重试会沿用同一个文章 key 和已经保存的阅读计划，并在本轮解析这些材料的当前版本。当前网页还没有“编辑同一篇文章的选材和阅读目标”表单：新建弹窗总是生成新的文章 key，而刷新只读取旧计划。若要改变既有文章的范围，开发者需用同一 key 更新页面计划后显式重跑。参考 [新文章计划映射 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L58 "说明网页新建文章使用随机 key，并把同一目标写入 goal、scenario 和 questions。") [同计划刷新接口 ↗](../../../apps/server/src/knowledge/api.ts#L169 "支持刷新读取同一 key 保存的 brief，并说明无计划时拒绝。")

<a id="changes"></a>
## 原文变化后，哪些章节需要处理

继续教学示例。文章已有“费用”和“集合”两节，分别引用预算与地点。若只在原文开头增加导读，而两个命名章节内容不变，系统会认出引用所在章节仍相同：两节继续是 current，行号移动也不会把固定引用改到新版。参考 [无关导读变化 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L92 "教学示例证明只改导读时章节仍可用，固定引用仍指向原版本。")

再把预算从八十元改为一百二十元：“费用”变为 needs-review，“集合”仍为 current。参考 [预算变化的章节状态 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L107 "教学示例证明预算变化只使费用节待核对，集合节保持 current。") 整篇仍留在目录并显示“待更新”；阅读页说明部分内容需要核对，在费用节上方显示原因并保留旧解释，其他章节仍可阅读。参考 [目录待更新标识 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L390 "支持文章非 current 时在知识库目录显示待更新。") [章节核对提示 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L76 "支持阅读页说明部分内容待核对，并在对应章节显示原因、保留原解释。") 集合节仍可继续进入当前知识检索，而费用节暂时退出。参考 [可用章节继续检索 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L119 "支持集合节仍可被检索而变化的费用节被排除。")

还有一种情况：集合方案虽然没有直接引用预算，却以原预算为前提。作者应在集合节的 `reviewSources` 中登记这个前提；预算变化后，集合节也会提示“背景前提已有变化”，并暂时退出检索。参考 [背景前提变化 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L165 "教学示例说明 reviewSources 可让未直接引用预算的集合节随前提变化而待核对。")

这套判断比较的是引用所在的完整 Markdown 章节或代码结构，而不是只看旧行号；只有结构能唯一匹配且内容未变，才把变化视为无关。它用于缩小复查范围，不是代码语义证明，也没有自动跨文件影响分析；无法可靠定位结构时会保守地要求核对。参考 [结构上下文比较 ↗](../../../apps/server/src/knowledge/lifecycle.ts#L40 "说明系统比较唯一匹配的包围章节或符号，并列出图片、缺行号等保守分支。") [维护机制边界 ↗](../../../docs/reader-first/publication-lifecycle.md#L27 "支持章节级变化判断的用途和限制，以及当前仍为显式更新。")

<a id="refresh-and-history"></a>
## 更新同一篇文章，并查看写作时原文

确认需要更新后，在文章底部点击“重新整理这篇”。服务端用同一 key 和已保存计划重新运行，并读取所选来源的当前版本。参考 [失败重试与重新整理 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L411 "支持失败计划提示、重试按钮和已有文章的重新整理按钮。") [同计划刷新接口 ↗](../../../apps/server/src/knowledge/api.ts#L169 "支持刷新读取同一 key 保存的 brief，并说明无计划时拒绝。") 新结果通过复核后，仓储会在相同 document key 下写入新的知识修订，并把该文章的 head 指向新修订；旧修订仍可按文章 key 与 revision 读取。参考 [同文章发布新修订 ↗](../../../apps/server/src/knowledge/repository.ts#L192 "支持在相同 document key 下写入新修订、更新 head，并保留修订记录。") [读取历史文章修订 ↗](../../../apps/server/src/knowledge/repository.ts#L183 "支持按文章 key 与指定 revision 读取非 head 的历史知识修订。")

打开文章列表或正文时，服务端会重新计算各节是否 current；这一步只是更新“待核对”的提示，不会在后台自动改写正文。当前更新仍需用户显式点击重新整理，或由开发者显式运行页面生成。参考 [读取时刷新状态 ↗](../../../apps/server/src/knowledge/api.ts#L59 "支持文章列表和正文读取前刷新章节适用状态，但不触发写作。") [维护机制边界 ↗](../../../docs/reader-first/publication-lifecycle.md#L27 "支持章节级变化判断的用途和限制，以及当前仍为显式更新。")

要核对旧解释，点击正文旁的行内引用。阅读页把**当前文章修订**和引用 key 一起交给服务端；服务端再从这篇修订保存的依赖中取固定 digest。若当前材料已不同，它会沿同一来源的历史修订寻找该 digest，而不是悄悄跳到新文本。参考 [固定引用解析 ↗](../../../apps/server/src/knowledge/api.ts#L45 "说明引用从指定文章修订的依赖解析固定 digest，不可用时返回明确原因。") [历史原件查找 ↗](../../../apps/server/src/knowledge/repository.ts#L262 "支持当前 digest 不匹配时沿同一来源历史修订查找固定版本。")

引用抽屉会标明“当前版本”或“历史版本”，显示引用行并允许展开上下文；固定历史不可用时会给出原因。因此，“查看写作时的依据”和“用当前原文重新整理”是两个独立动作。参考 [原文版本标识 ↗](../../../apps/web/src/knowledge/KnowledgeSource.vue#L33 "支持引用阅读界面显示当前或历史版本、引用行和可展开上下文。")

<a id="developer"></a>
## 开发者从哪里修改这条流程

按用户动作找入口最省力：

- **选材、字段和提交**：`ArticleComposer.vue`；目录轮询、失败重试和“重新整理这篇”：`KnowledgeHome.vue`。
- **章节提示与引用阅读**：`KnowledgeDocument.vue`、`KnowledgeFrame.vue`、`KnowledgeSource.vue`。
- **HTTP 边界**：`knowledge/api.ts`；调查、写作、刷新角色、独立复核与发布门槛：`knowledge/pipeline.ts`。
- **文章修订与固定历史**：`repository.ts`；章节级 current / needs-review / unavailable 判断：`lifecycle.ts`。这些职责也在维护设计中列为正式修改入口。参考 [维护修改入口 ↗](../../../docs/reader-first/publication-lifecycle.md#L41 "汇总合同、发布更新、检索调查和阅读操作的正式修改入口。")

本仓库的稳定页面计划位于 `config/wiki-pages.json`；其中本页 key 为 `guide:knowledge-maintenance`，并保存了读者、场景、问题和入口文件。要更新这篇而不是新建文章，应保留该 key。参考 [本页稳定计划 ↗](../../../config/wiki-pages.json#L169 "支持本页固定 key、阅读目标、场景、问题、入口路径和主题分类。")

脚本会按完整 key 或 `knowledge-maintenance` 这样的短目标筛选页面，再调用同一条 `KnowledgePipeline.writePage`。没有 `--retry` 时，只有已有文章仍为 current、阅读计划相同且写作者版本未变，流水线才直接复用旧结果；否则会进入生成路径。参考 [仓库指南运行脚本 ↗](../../../scripts/review-guides.ts#L17 "支持按目标筛选页面、仅在 retry 时设置新的 retryTag、调用相同流水线，并记录失败和非零退出状态。") [已有文章复用条件 ↗](../../../apps/server/src/knowledge/pipeline.ts#L266 "说明未设置 retryTag 时仅在已有 current 文章、阅读计划相同且 writer 版本相同时直接复用，否则进入生成路径。")

如果生成路径命中同一身份下已经失败、取消或等待用户处理的持久角色任务，普通重跑不会再次执行，而会报告该角色 `requires retry`。此时应运行 `osdk run review:guides <目标> --retry`：脚本会设置新的重试标记，使失败任务获得新的运行身份；该标记也会绕过上述 current 文章复用，适合需要强制重新生成时使用。脚本仍会记录失败并以非零状态退出。这个命令是仓库自验证入口，不是普通用户整理个人材料的必经步骤。参考 [仓库指南运行脚本 ↗](../../../scripts/review-guides.ts#L17 "支持按目标筛选页面、仅在 retry 时设置新的 retryTag、调用相同流水线，并记录失败和非零退出状态。") [持久失败任务重试 ↗](../../../apps/server/src/knowledge/pipeline.ts#L102 "说明同一任务已失败、取消或等待用户时普通运行会直接要求 retry，而不会再次执行。")
