# 整理文章，以及原文更新后怎么处理

从固定选材或项目/主题范围开始，说明怎样填写阅读目标、看懂排队与失败、验收文章、补充材料，并在原文或材料范围变化后维护同一篇文章。沿“预算八十元、图书馆集合”的教学示例解释局部待核对、手动更新、自动维护，以及让后来聊天进入文章所需的明确归属条件。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="choose-scope"></a>
## 先决定固定选材还是持续跟踪

要让后来的聊天更新同一篇文章，**只把聊天保存进知识库还不够**。完整链路是：把聊天保存为材料，明确归入同一个项目或主题，让文章持续跟踪这个范围，并在文章生成后开启自动更新。系统不会仅凭文件路径、会话 ID、相似标题或材料内容自动判断归属。参考 [项目或主题的使用边界 ↗](../../../docs/reader-first/project-contexts.md#L3 "说明明确归属、动态范围、自动更新、整组加入、错误归属与模型理解边界。") [内容不会自动判断归属 ↗](../../../docs/reader-first/project-contexts.md#L51 "明确当前尚未实现从内容自动判断归属，并列出外部会话自动归属尚未完成。")

整理前先按用途选择材料范围：

- **固定选择几份材料**：适合一次性问题，或文章只讨论项目的一部分。以后新增材料时，需要通过“调整材料与目标”加入。
- **持续跟踪项目或主题**：适合后续还会增加文档、聊天、代码或图片的事项。范围里的现有材料整组参加调查；以后明确归入该范围的材料也能进入同一篇文章。
- 两种方式可以并用：持续跟踪一个范围，同时另选几份固定背景材料。

这些是根据当前选材行为给出的使用建议，不是强制分类。

以下用一份虚构的“活动约定”贯穿操作：

```markdown
# 活动约定

## 预算
预算是八十元。

## 地点
在图书馆集合。
```

如果只想解释这份约定，直接固定选择它即可。如果希望后来的报名和场地消息也进入文章，可以先到**输入材料**，新建“阅读小组”项目，把范围说明写成“本次活动的报名、费用与场地安排”，再把“活动约定”保存到这个项目。项目选择器会显示名称、项目或主题类型、已有材料数和范围说明，也可以就地创建并自动选中。参考 [创建并选择项目或主题 ↗](../../../apps/web/src/ContextPicker.vue#L27 "支持选择器展示项目或主题信息，以及填写名称、类型、范围说明后创建并选中。")

把后来收到的聊天纳入范围时，在**输入材料**选择“群聊材料”，填写标题、正文和必要的来源标识，选中“阅读小组”，再点击**保存材料与证据**。这是当前页面提供的保存与归属方式；保存后仍以你明确选择的项目或主题为准，系统不会从内容自动判断归属。参考 [手动保存群聊材料并选择归属 ↗](../../../apps/web/src/App.vue#L909 "支持在输入材料页选择群聊材料、填写正文与来源标识，并选择项目或主题后保存。") [内容不会自动判断归属 ↗](../../../docs/reader-first/project-contexts.md#L51 "明确当前尚未实现从内容自动判断归属，并列出外部会话自动归属尚未完成。")

项目/主题、文章分类和正文引用是三件事：项目/主题决定本次调查包含哪些材料，分类决定文章在知识库里放在哪里，引用仍指向生成时使用的固定原文版本。

<a id="compose-article"></a>
## 选择材料并写下可验收的阅读目标

进入**知识库**并点击**整理文章**。第一步“选择材料”可以同时做两件事：

1. 在“持续跟踪项目或主题（可选）”中选择“阅读小组”；范围内现有材料会自动选中，并标为“随项目或主题加入”。
2. 另外按标题或路径查找并勾选固定背景材料；可以切换“已选 N 项”、继续显示更多结果，也可以跨分类选择。参考 [固定材料与动态范围可以并用 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L163 "支持选择持续跟踪范围、自动勾选范围成员、另选背景材料、筛选及跨分类选择。")

项目或主题中的成员是整组加入的，不能在这个弹窗里单独取消某一项。如果文章只讨论其中一部分，应取消整个动态范围，再明确勾选所需材料；如果是材料本身归属错了，应回到原文调整“所属项目与主题”。一个材料可以属于多个范围，移出范围不会删除原件或旧引用。参考 [项目或主题的使用边界 ↗](../../../docs/reader-first/project-contexts.md#L3 "说明明确归属、动态范围、自动更新、整组加入、错误归属与模型理解边界。")

第二步“说明阅读目标”填写：

- **文章主题**：例如“参加活动前要知道什么”；
- **想弄懂什么**：例如“参加者读完能知道要准备多少钱、到哪里集合”；
- **写给谁看**：例如“活动参加者”。

界面会同时显示当前材料数和保存位置。从具体分类发起时沿用该分类；从知识库根部发起时按内容归类。确认后点击**开始整理**，系统会调查、撰写并复核。编辑已有文章计划时，对应按钮是**保存并重新整理**。参考 [填写阅读目标并开始整理 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L230 "支持文章主题、目标、读者、材料数量、保存分类，以及开始整理或保存并重新整理。")

“参加者能知道要准备多少钱、到哪里集合”只是教学写法，它的价值是整理完成后可以直接检查，不是产品要求的固定模板。固定材料和动态范围都没选时不能提交；只选了一个空项目或主题时，也要先向其中保存至少一份材料。若提示没有配置 Agent，先到**能力与连接**完成配置；同一篇文章已经排队或写作时，要等这一轮结束后再调整材料与目标。参考 [提交条件与忙碌限制 ↗](../../../apps/server/src/knowledge/api.ts#L194 "支持未配置 Agent、没有选材、空项目范围以及同篇正在整理时的可见限制。")

<a id="wait-and-retry"></a>
## 看懂排队、整理与失败状态

提交后，页面先可能显示**已排队整理**，轮到执行时变为**正在整理**。完成调查、撰写与复核后显示“已完成”，并提供**阅读文章**。看到排队或整理中时，不要为同一篇文章重复提交。参考 [排队、整理和完成状态 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L319 "支持已排队、正在整理、完成及阅读文章等用户可见状态。")

失败时按是否已有正文处理：

- 首次整理失败、还没有正文时，计划留在**准备整理**区域，页面提示“上次整理未完成，阅读目标已保留”，并提供**重试整理**。参考 [首次失败保留计划 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L427 "支持首次失败后计划留在准备整理区域、阅读目标保留及重试整理入口。")
- 更新已有文章失败时，旧正文仍可阅读，文章更新区域显示“本次更新未完成，旧文章已保留”，并提供**重试更新**。参考 [已有文章更新失败保留旧文 ↗](../../../apps/web/src/knowledge/ArticleMaintenance.vue#L32 "支持更新失败时保留旧文章并提供重试更新入口。")
- 若提示这篇文章正在整理，等当前任务结束后再刷新或修改计划。

只有新结果完成调查、写作和复核后，才会替换当前展示的正文。自动维护不会对同一份失败输入无休止重试；明确重试，或材料版本、范围成员再次变化后，才会进入下一次处理。参考 [自动维护的范围、队列和失败边界 ↗](../../../docs/reader-first/publication-lifecycle.md#L45 "说明默认关闭、固定选材与动态范围差异、队列合并、关闭取消、失败重试和旧文保留。")

<a id="reader-check"></a>
## 用自己的问题验收文章

打开文章后，先看顶部的**读完这一篇**，它对应整理时填写的阅读目标。对本例，可以做四项人工检查：

- 不回看原材料，文章能否直接回答“准备八十元、在图书馆集合”？
- 金额和地点附近是否有可点击的引用？
- 打开引用后，固定原话和范围是否真的支持结论？
- 页面是否出现“部分内容需要核对”或某一章节的具体提醒？

页面会把需要核对的影响标到对应章节，其他章节仍可阅读；“来源与生成记录”说明固定原始材料、生成模型、独立复核模型和时间。参考 [阅读目标、章节提醒与生成记录 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L87 "支持文章顶部目标、局部待核对提示、旧解释保留，以及来源与生成记录。") 但“已完成”或“已复核”不等于读者已经验收。还要确认文章回答了计划中的问题、必要概念已解释、案例能跟下来，并且知道下一步怎么做。参考 [模型复核不等于读者验收 ↗](../../../docs/reader-first/writing.md#L40 "明确读者还要检查页面是否回答目标、解释术语、贯穿案例并给出下一步。")

如果出现**待核对与后续调查**，先阅读问题、重要性和建议的下一步：

- 你掌握缺失背景时，点击**补充背景**，填写后**保存为材料**；
- 需要以后调查时，点击**加入待办**。参考 [补充背景或加入待办 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L59 "支持查看未知问题、补充背景并保存为材料，或将下一步加入待办。")

保存补充不会立即改写当前正文。补充会加入这篇文章的选材计划；开启自动维护时由后台排队，否则要点击**重新整理这篇**。两条路径完成后都要重新验收。参考 [补充背景后的更新方式 ↗](../../../docs/reader-first/publication-lifecycle.md#L61 "说明补充背景加入选材计划但不立即改写正文，自动维护或手动整理后仍需验收。")

操作上可以这样判断：关键事实没回答、引用打不开、来源已变化，或未知事项会影响行动时，继续补材料；事实齐全但文章答非所问时，用**调整材料与目标**把问题和读者写得更具体。这是读者的验收方法，不是系统自动给出的质量结论。

<a id="change-example"></a>
## 先只改导读，再把预算改为一百二十元

下面继续使用教学示例，并假设生成结果把费用与集合说明分成两个章节。实际文章可能合并成一节，章节数由内容和阅读目标决定。

**第一次变化：只在“预算”和“地点”之前增加一段导读。**

系统用引用实际覆盖的完整结构部分来定位需要复查的范围。若“预算”“地点”的标题和内容未变，只是增加导读造成行号移动，对应解释仍可继续使用，引用仍固定指向写作时的版本。引用若横跨导读和多个章节，范围外的后续“筹备记录”变化不会自动牵连前面的安排；但引用范围内新增或重排章节、下级标题中的条件变化，仍会要求核对。这个判断只是缩小复查范围，不是自动证明语义完全不变。参考 [引用实际覆盖的结构范围 ↗](../../../docs/reader-first/publication-lifecycle.md#L29 "说明跨导读和多个章节时比较引用实际涉及的完整部分，并保留嵌套条件、范围内新增与重排等复查边界。")

**第二次变化：把“预算是八十元”改成“预算是一百二十元”。**

费用章节会等待核对；地点章节在内容未变时仍可阅读，旧文章版本也继续保留。机制测试用同一份教学材料验证了增加导读、预算变化、范围外记录变化和嵌套条件变化这些分支。参考 [导读、预算与嵌套条件的教学验证 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L93 "教学测试验证增加导读仍可用、预算变化只影响相关节、范围外记录不牵连，而范围内嵌套条件或新增章节会触发核对。")

还要注意两个边界：

- 如果实际文章把预算和地点写在同一节，合并后的整节会一起等待核对。
- 如果集合安排明确以预算为背景前提，预算变化也会让集合章节等待核对；不能仅因为两个事实在同一文件中，就推断它们相互依赖。参考 [背景前提变化也会触发核对 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L193 "教学测试验证集合方案若明确依赖预算，预算变化也会使集合章节待核对。")

无法识别小节或代码结构的普通文本发生变化时，系统可能只能按整份材料处理。**待更新表示旧解释需要核对，不等于正文已经自动改写**；是否自动排队取决于文章有没有开启自动维护。

<a id="maintain-same-article"></a>
## 在同一篇文章上手动更新或持续跟踪

看到**待更新**后，先阅读每一节的提示；未受影响的章节可以继续使用。接下来有两条路径，它们都维护原来的文章。

**手动更新**

- 材料和阅读目标不变：点击文章底部的**重新整理这篇**。
- 要增删固定材料、改用或取消项目/主题范围，或者修改主题、问题、读者：点击**调整材料与目标**，完成两步后保存并重新整理。参考 [重新整理与调整目标入口 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L452 "支持在同一篇文章底部重新整理，或打开调整材料与目标的编辑流程。")

**持续跟踪**

文章末尾的**随所选材料自动更新**默认关闭。开启后：

- 跟踪项目或主题时，后来明确归入该范围的新材料、已有材料换版或材料移出，都会触发同一篇文章重新调查、写作和复核；
- 只选择固定材料时，新材料不会自行进入文章，仍要通过“调整材料与目标”加入；
- 排队期间的连续变化会合并，执行时读取最新范围；关闭开关会取消尚未完成的自动任务，但不会取消你明确点击发起的手动整理。参考 [自动维护的范围、队列和失败边界 ↗](../../../docs/reader-first/publication-lifecycle.md#L45 "说明默认关闭、固定选材与动态范围差异、队列合并、关闭取消、失败重试和旧文保留。")

因此，后来收到“场地改为东侧阅读室，小周负责签到”的聊天时，要把它保存为材料并明确归入“阅读小组”。文章还必须正在跟踪“阅读小组”且已开启自动更新，才会自动排队。同名但没有归入该范围的另一场活动不会进入；范围正确也不保证模型一定能判断新旧安排、时间和角色，完成后仍要人工验收。参考 [项目或主题的使用边界 ↗](../../../docs/reader-first/project-contexts.md#L3 "说明明确归属、动态范围、自动更新、整组加入、错误归属与模型理解边界。")

若发现归属错误，打开该原文的**所属项目与主题**，重新勾选后点击**保存归属**。归属调整适用于这份材料的所有版本，不会删除原文或历史引用；跟踪相关范围的文章会按自己的更新设置处理。若材料归属本来正确，只是这篇文章题目较窄，不要为了文章删改真实归属，应取消整组跟踪并改为固定选择少数材料。参考 [调整原文的项目与主题归属 ↗](../../../apps/web/src/SourceContexts.vue#L25 "支持重新选择并保存归属，且说明归属适用于所有版本、不会删除原文或历史引用。")

无论使用哪条更新路径，新结果成功发布前，旧正文和写作时的固定引用都继续保留。点击论断旁的引用，面板会显示支持理由并打开固定目标；原文页会标明**当前版本**或**历史版本**以及引用位置。因此预算已经改为 120 元时，旧文中“80 元”的引用不会悄悄跳到新文字。参考 [引用打开固定目标 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L83 "支持引用面板显示理由，并按固定解析目标打开文章或材料范围。") [原文标明当前或历史版本 ↗](../../../apps/web/src/knowledge/KnowledgeSource.vue#L34 "支持原文页面展示当前或历史版本、引用位置和对应片段。")

“更新同一篇文章”保证页面身份和历史延续，不保证新正文的标题与章节布局逐字不变。旧路线仍清楚时，更新可以保留原有案例和结构；阅读目标变化或旧结构妨碍理解时，新结果可以按当前材料重新组织，同时重新核对引用。参考 [同一文章可以局部维护或重组 ↗](../../../docs/reader-first/publication-lifecycle.md#L53 "说明维护时可保留清楚的旧路线，也可在旧结构妨碍理解时重新组织，同时保留页面身份和历史并重新核对引用。")

更新完成后，再按原问题验收：预算是否已变为 120 元、地点是否仍为图书馆或已经被新消息替代、各项结论是否有匹配引用，以及页面是否还留有会影响行动的待核对提示。
