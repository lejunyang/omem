# 整理文章，以及原文更新后怎么处理

从知识库选材、填写阅读目标，到看懂排队与失败状态、验收文章、补充材料和维护同一篇文章的完整操作。以“预算八十元、图书馆集合”为教学示例，说明无关导读变化为何不影响原解释、预算改为一百二十元后哪些内容需要核对，并区分手动重新整理与默认关闭的自动维护。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="first-draft"></a>
## 从材料和一个明确问题开始

要整理一篇以后还能维护的文章，先在**知识库**点击**整理文章**，选定原始材料，再把“读完要解决什么问题”写成可以检查的结果。如果你已进入某个分类，文章沿用该分类；从知识库根部开始，则按内容归类。

下面使用一个贯穿全文的教学示例。为了便于观察局部变化，原始材料有清楚的小节：

```markdown
# 活动约定

## 预算
预算是八十元。

## 地点
在图书馆集合。
```

弹窗分两步：

1. 在**选择材料**中按标题或路径查找并勾选“活动约定”。可以切换“已选 N 项”复查、继续显示更多结果，也可以跨分类选择其他相关材料。参考 [选择整理材料 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L124 "支持按标题或路径筛选、查看已选项、继续显示、跨分类选择，以及编辑时预选现有材料。")
2. 进入**说明阅读目标**，填写：
   - 文章主题：例如“参加活动前要知道什么”
   - 想弄懂什么：例如“参加者读完能知道要准备多少钱、到哪里集合”
   - 写给谁看：例如“活动参加者”
3. 确认选中材料数和保存位置，点击**开始整理**。系统随后调查材料、撰写并复核。参考 [填写阅读目标并开始整理 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L209 "支持主题、问题、读者字段，以及材料数量、保存位置和开始整理按钮。")

“参加者能知道要准备多少钱、到哪里集合”是使用建议，不是产品强制模板；它比“整理一下”更容易在完成后验收。

<a id="wait-and-retry"></a>
## 看懂排队、整理与失败状态

提交后，页面先可能显示**已排队整理**，轮到执行时变为**正在整理**。完成调查、撰写与复核后，页面显示“已完成”，并提供**阅读文章**。这是一条排队执行的流程；看到排队或整理中时，不要重复提交。参考 [排队、整理和完成状态 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L314 "支持已排队整理、正在整理、完成后阅读文章等用户可见状态。")

失败时按文章是否已有可用正文处理：

- 首次整理失败且还没有正文时，计划留在**准备整理**区域，显示“上次整理未完成，阅读目标已保留”。查看失败原因后点击**重试整理**，不必重新填写阅读目标。参考 [首次失败保留计划 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L422 "支持准备整理区域保留失败计划、提示阅读目标已保留，并提供重试整理。")
- 更新已有文章失败时，旧正文仍可阅读；文章的更新区域显示“本次更新未完成，旧文章已保留”，并提供**重试更新**。参考 [自动维护开关和更新状态 ↗](../../../apps/web/src/knowledge/ArticleMaintenance.vue#L31 "支持默认界面中的选材范围说明、排队与写作状态、失败保留旧文和重试入口。")
- 若提示尚未配置 Agent，先到**能力与连接**完成配置。若同一篇文章已在排队或整理中，等这一轮结束后再重新整理或调整材料与目标。新建、调整与手动重新整理都会进入同一排队流程。参考 [整理统一排队与可见错误 ↗](../../../apps/server/src/knowledge/api.ts#L190 "支持新建、编辑、手动刷新均进入排队，并说明未配置 Agent 与同篇正在整理时的错误条件。")

只有新结果完成调查、写作和复核后，才会替换当前展示的正文；失败结果不会覆盖原来可用的文章。自动维护也不会对同一份失败输入无限重试，明确重试或材料出现新版本后才会再执行。参考 [手动与自动维护边界 ↗](../../../docs/reader-first/publication-lifecycle.md#L41 "说明默认关闭、只跟踪明确选材、持久排队、关闭时的取消边界、失败重试和当前未自动关联新来源等事实。")

<a id="reader-check"></a>
## 用自己的问题验收文章

打开文章后，先看顶部的**读完这一篇**，它对应整理时填写的阅读目标。对本例，可以做四项人工检查：

- 不回看原材料，文章能否直接回答“准备八十元、在图书馆集合”？
- 金额和地点附近是否有可点击的引用？
- 打开引用后，原话和范围是否真的支持结论？
- 页面是否出现“部分内容需要核对”或某一章节的具体提醒？

文章底部的“来源与生成记录”会显示固定材料、生成模型、独立复核模型和时间；局部来源变化时，页面也会标明受影响章节并保留旧解释。参考 [阅读目标、章节提醒与生成记录 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L87 "支持文章顶部阅读目标、局部待核对提示、旧解释保留和来源与生成记录。") 但“已完成”或“已复核”不等于读者已经验收：读者仍要确认文章回答了计划中的问题、必要概念已解释，并且知道下一步怎么做。参考 [读者验收不同于模型复核 ↗](../../../docs/reader-first/writing.md#L34 "明确读者检查关注是否回答计划问题，并说明独立模型判断不能冒充用户验收。")

如果出现**待核对与后续调查**，先阅读问题、重要性和建议的下一步：

- 你掌握缺失背景时，点击**补充背景**，填写后**保存为材料**。
- 需要以后调查时，点击**加入待办**。参考 [补充背景或加入待办 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L59 "支持待核对问题的说明、保存背景为材料和加入待办等操作。")

保存补充不会立刻改写正在看的正文。若文章已经开启**随所选材料自动更新**，补充进入选材计划后会由后台排队；若没有开启，则点击**重新整理这篇**。两种方式完成后，都要重新检查新结果。参考 [补充背景后的两条更新路径 ↗](../../../docs/reader-first/publication-lifecycle.md#L57 "说明补充背景加入选材后，开启持续维护时由后台排队，否则需要手动重新整理，并且两者都要验收。")

作为操作判断：关键事实没回答、引用打不开、来源已变化或未知事项会影响行动时，继续补材料；事实齐全但文章答非所问时，使用**调整材料与目标**把问题和读者写得更具体。这是验收建议，不是系统自动给出的质量判定。

<a id="change-example"></a>
## 先只改导读，再把预算改为一百二十元

下面继续使用教学示例，并假设生成结果把费用与集合说明分成两个章节。实际文章的章节数由内容和阅读目标决定，短文章也可能合并成一节。

**第一次变化：只在“预算”和“地点”之前增加一段导读。**

系统比较引用所在的完整 Markdown 小节或代码结构。如果“预算”“地点”的标题和内容未变，只是插入导读造成行号移动，对应解释仍可继续使用，引用仍固定指向写作时的原文。这个比较用于定位复查范围，不是自动证明所有语义都没有变化。参考 [结构未变时允许行号移动 ↗](../../../apps/server/src/knowledge/lifecycle.ts#L40 "支持引用所在完整结构内容未变时继续使用原解释，同时固定引用不被语义重映射。")

**第二次变化：把“预算是八十元”改成“预算是一百二十元”。**

文章会显示需要更新；费用章节等待核对，地点章节在内容未变时仍可阅读，旧文章和旧版本不会被删除。相关测试用同一教学材料验证了费用节变为待核对、地点节保持可用。参考 [预算变化只影响相关章节 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L93 "教学测试验证插入导读后章节仍可用，而预算改为一百二十元后费用节待核对、地点节仍可用。")

还要注意两个边界：

- 如果文章把预算和地点写在同一节，合并后的整节会一起等待核对；分成两节只是本例的讲解方式。
- 如果集合安排明确以预算为背景前提，预算变化也会让集合章节等待核对。不能仅因为两个事实在同一文件中，就假定它们互相依赖。参考 [背景前提变化也会触发核对 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L166 "教学测试验证集合方案若明确依赖预算，预算变化也会使集合章节待核对。")

没有可识别小节或代码结构的普通文本发生变化时，系统可能只能按整份材料变化处理。**待更新说明旧解释需要核对，不等于正文已经自动改写**；是否自动排队取决于文章有没有开启自动维护。

<a id="refresh-same-article"></a>
## 在同一篇文章上手动或自动更新

看到**待更新**后，先打开文章阅读每一节的提示；未受影响的章节可以继续使用。接下来可选择手动更新或自动维护，它们都维护同一篇文章。

**手动更新**

- 材料和阅读目标不变：点击文章底部的**重新整理这篇**。
- 要增删材料，或修改主题、问题、读者：点击**调整材料与目标**。弹窗会预选现有材料；完成两步后点击**保存并重新整理**。参考 [重新整理与调整目标入口 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L447 "支持在同一文章底部重新整理，或打开调整材料与目标的编辑流程。")

**自动维护**

文章末尾的**随所选材料自动更新**默认关闭。开启前必须已有明确选材；开启后，它只跟踪页面列出的已选材料。这些材料出现新版本时，后台自动排队、更新并复核，期间旧版仍可读。新材料不会因为项目名、路径或相似内容而自动加入，仍需通过**调整材料与目标**添加。参考 [自动维护开关和更新状态 ↗](../../../apps/web/src/knowledge/ArticleMaintenance.vue#L31 "支持默认界面中的选材范围说明、排队与写作状态、失败保留旧文和重试入口。") [手动与自动维护边界 ↗](../../../docs/reader-first/publication-lifecycle.md#L41 "说明默认关闭、只跟踪明确选材、持久排队、关闭时的取消边界、失败重试和当前未自动关联新来源等事实。")

自动更新排队时会显示“更新已排队”，执行时显示正在调查变化、更新正文并独立复核；失败时保留旧文章并提供重试。关闭开关会停止后续自动跟踪，并取消尚未完成的自动任务，但不会取消你明确点击发起的手动整理。它也不等于持续理解整个项目、自动关联所有新来源，或同步修改个人记忆与事项。参考 [手动与自动维护边界 ↗](../../../docs/reader-first/publication-lifecycle.md#L41 "说明默认关闭、只跟踪明确选材、持久排队、关闭时的取消边界、失败重试和当前未自动关联新来源等事实。")

无论使用哪条路径，新结果成功发布前，旧正文和写作时的固定引用都继续保留。点击论断旁的引用，面板先说明来源为何支持该段，再打开固定的材料版本；原文页会标明**当前版本**或**历史版本**并显示引用位置。因此当前预算已改为 120 元时，旧文章中“80 元”的引用不会悄悄跳到新文字。参考 [引用打开固定目标 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L83 "支持引用面板显示理由，并按固定解析目标打开文章或材料范围。") [原文标明当前或历史版本 ↗](../../../apps/web/src/knowledge/KnowledgeSource.vue#L33 "支持原文页面展示当前或历史版本、引用位置和对应片段。")

更新完成后，再按原问题验收：预算是否已变为 120 元、地点是否仍为图书馆、两项是否都有匹配的新引用，以及页面是否还留有会影响行动的待核对提示。模型复核是发布环节，最终是否回答了你的问题仍由你判断。
