# 整理文章，以及原文更新后怎么处理

从固定选材或持续跟踪项目/主题开始，说明怎样填写可验收的阅读目标、看懂排队与失败、检查引用和待核对内容，并在原文或材料范围变化后维护同一篇文章。沿“预算八十元、图书馆集合”的教学示例，解释无关导读与预算变化为何影响不同章节，也说明后来聊天要自动更新文章所需的归属、动态范围和自动更新条件。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="choose-scope"></a>
## 先决定固定选材还是持续跟踪

要让后来的聊天更新同一篇文章，完整链路是：**把聊天保存为材料 → 让它最终归入正确的项目或主题 → 让文章持续跟踪这个范围 → 开启文章自动更新**。只保存材料，或只建立项目，都不会直接改写文章。参考 [项目或主题的使用边界 ↗](../../../docs/reader-first/project-contexts.md#L3 "说明动态范围、自动更新链路、整组加入、错误归属与只选部分材料时的处理。")

整理前先按用途选择范围：

- **固定选择几份材料**：适合一次性问题，或文章只讨论项目的一部分。以后有新材料时，需要通过“调整材料与目标”加入。
- **持续跟踪项目或主题**：适合后续还会增加文档、聊天、代码或图片的事项。范围里的现有材料整组参加调查，以后归入该范围的材料也能进入同一篇文章。
- 两种方式可以并用：持续跟踪一个范围，同时另选几份固定背景材料。

以下使用一个虚构的教学示例：

```markdown
# 活动约定

## 预算
预算是八十元。

## 地点
在图书馆集合。
```

如果只想解释这份约定，固定选择它即可。如果希望后来的报名和场地消息也进入文章，可以到**输入材料**新建“阅读小组”项目，把范围说明写成“本次活动的报名、费用与场地安排”，再把“活动约定”放入该项目。选择器会显示名称、项目或主题类型、已有材料数和范围说明，也可以就地创建并选中。参考 [创建并选择项目或主题 ↗](../../../apps/web/src/ContextPicker.vue#L27 "支持选择器展示范围信息，并可填写名称、类型和范围说明后创建并选中。")

保存后来收到的聊天时，在**输入材料**选择“群聊材料”，填写标题、正文和必要的来源标识。知道它属于“阅读小组”时，直接选中该项目再点击**保存材料与证据**，这是最确定的路径。参考 [保存群聊材料并选择归属 ↗](../../../apps/web/src/App.vue#L909 "支持填写群聊材料的标题、来源、正文和项目或主题后保存。")

暂时不确定归属时也可以不选项目。只有后台自动处理已启用、使用原生 ACP、已有项目或主题可供比较，并且这份材料没有手动归属时，系统才会调查已有范围和相关原文：明确匹配会在独立补查同意后保存；含糊时材料仍保留，但不会先加入项目，而会显示候选、原因和需要补充的问题；没有合适范围时也不会自动新建项目。人工选择始终优先，包括明确不选任何项目。参考 [未指定归属时的调查边界 ↗](../../../docs/reader-first/project-contexts.md#L53 "说明自动调查的启用前提、明确匹配、含糊候选、人工选择优先以及不会自动创建项目。") [查看并人工修正材料归属 ↗](../../../apps/web/src/SourceContexts.vue#L33 "支持展示自动、含糊或无匹配结果，以及保存人工选择和触发相关更新。")

项目/主题、文章分类和正文引用是三件事：项目/主题决定调查会纳入哪些材料，分类决定文章在知识库里的位置，引用仍指向写作时使用的固定原文版本。

<a id="compose-article"></a>
## 选择材料并写下可验收的阅读目标

进入**知识库**并点击**整理文章**。第一步“选择材料”可以同时完成两类选择：

1. 在“持续跟踪项目或主题（可选）”中选择“阅读小组”。范围内现有材料会自动选中，并标为“随项目或主题加入”。
2. 另外按标题或路径查找并勾选固定背景材料；可以切换“已选 N 项”、继续显示更多结果，也可以跨分类选择。参考 [固定材料与动态范围可以并用 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L142 "支持选择持续跟踪范围、自动包含其成员，并另外筛选固定背景材料。")

项目或主题中的成员是整组加入的，不能在这个弹窗里单独取消某一项。如果文章只讨论其中一部分，应取消整个动态范围，再明确勾选所需材料；如果材料的真实归属错了，应到原文的“所属项目与主题”修正。一个材料可以属于多个范围，移出范围不会删除原件或旧引用。参考 [项目或主题的使用边界 ↗](../../../docs/reader-first/project-contexts.md#L3 "说明动态范围、自动更新链路、整组加入、错误归属与只选部分材料时的处理。")

第二步“说明阅读目标”填写：

- **文章主题**：例如“参加活动前要知道什么”；
- **想弄懂什么**：例如“参加者读完能知道要准备多少钱、到哪里集合”；
- **写给谁看**：例如“活动参加者”。

界面会显示当前材料数和保存位置。确认后点击**开始整理**；调整已有文章时，按钮是**保存并重新整理**。参考 [填写阅读目标并开始整理 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L230 "支持填写主题、目标和读者，查看材料数与分类，并开始或重新整理。")

这个目标只是教学写法，重点是让完成后的文章能够直接验收。固定材料和动态范围都没选时不能继续；只选了空项目或主题时，要先保存至少一份材料。若提示尚未配置 Agent，先到**能力与连接**完成配置；同一篇文章正在排队或整理时，要等当前任务结束再改计划。参考 [提交条件与忙碌限制 ↗](../../../apps/server/src/knowledge/api.ts#L222 "支持未配置 Agent、没有选材、空范围及同篇正在整理时的用户可见限制。")

<a id="wait-and-retry"></a>
## 看懂排队、整理与失败状态

提交后，页面可能先显示**已排队整理**，轮到执行时变为**正在整理**。完成调查、撰写与复核后显示“已完成”，并提供**阅读文章**。看到排队或整理中时，不必为同一篇文章重复提交。参考 [排队、整理和完成状态 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L319 "支持已排队、正在整理、完成以及阅读文章等可见状态。")

失败时按是否已经有正文处理：

- 首次整理失败、还没有正文时，计划留在**准备整理**区域，阅读目标仍保留，并提供**重试整理**。参考 [首次失败保留计划 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L427 "支持首次失败后保留阅读目标并从准备整理区域重试。")
- 更新已有文章失败时，旧正文仍可阅读，文章更新区域显示“本次更新未完成，旧文章已保留”，并提供**重试更新**。参考 [更新失败保留旧文 ↗](../../../apps/web/src/knowledge/ArticleMaintenance.vue#L32 "支持自动更新状态、旧文保留和重试更新入口。")
- 若提示这篇文章正在整理，等当前任务结束后再刷新或修改计划。

只有新结果完成调查、写作和复核后，才会替换当前展示的正文。自动维护不会对同一份失败输入无休止重试；手动重试，或材料版本、范围成员再次变化后，才会进入下一次处理。参考 [自动维护的范围和失败边界 ↗](../../../docs/reader-first/publication-lifecycle.md#L45 "说明自动更新默认关闭、固定选择与动态范围的差别、队列合并、关闭取消和失败重试。")

<a id="reader-check"></a>
## 用自己的问题验收文章

打开文章后，先看顶部的**读完这一篇**，它对应整理时填写的阅读目标。对本例，可以做四项人工检查：

- 不回看原材料，文章能否直接回答“准备八十元、在图书馆集合”？
- 金额和地点附近是否有可点击的引用？
- 打开引用后，固定原话和范围是否真的支持结论？
- 页面是否出现“部分内容需要核对”或某一章节的具体提醒？

页面会把影响标到对应章节，其他章节仍可阅读；“来源与生成记录”说明固定原始材料、生成模型、独立复核模型和时间。参考 [阅读目标、章节提醒与生成记录 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L87 "支持文章顶部目标、局部核对提示、未受影响章节继续阅读和来源记录。") 但“已完成”或“已复核”不等于读者已经验收。还要确认文章是否回答了计划中的问题、必要概念是否解释清楚、案例是否能跟下来，以及下一步是否明确。参考 [模型复核不等于读者验收 ↗](../../../docs/reader-first/writing.md#L42 "明确读者还要检查文章是否回答目标、解释概念、贯穿案例并给出下一步。")

如果出现**待核对与后续调查**，先阅读问题、重要性和建议的下一步：

- 你掌握缺失背景时，点击**补充背景**，填写后**保存为材料**；
- 需要以后调查时，点击**加入待办**。参考 [补充背景或加入待办 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L59 "支持查看未知问题、补充背景并保存为材料，或把后续调查加入待办。")

保存补充不会立即改写当前正文。它会成为原始材料并加入这篇文章的选材计划；开启自动维护时由后台排队，否则要点击**重新整理这篇**。两条路径完成后都要重新验收。参考 [补充背景后的更新方式 ↗](../../../docs/reader-first/publication-lifecycle.md#L61 "说明补充背景会加入选材计划，但仍需自动维护或手动重新整理并再次验收。")

操作上可以这样判断：关键事实没回答、引用打不开、来源已变化，或未知事项会影响行动时，继续补材料；事实齐全但文章答非所问时，用**调整材料与目标**把问题和读者写得更具体。这是读者的验收方法，不是系统自动给出的质量结论。

<a id="change-example"></a>
## 先只改导读，再把预算改为一百二十元

继续使用前面的教学示例，并假设生成结果把费用与集合说明分成两个章节。实际文章可能合并成一节，章节数由内容和阅读目标决定。

**第一次变化：只在“预算”和“地点”之前增加一段导读。**

系统按引用实际覆盖的完整结构定位需要复查的范围。若“预算”“地点”的标题和内容未变，只是增加导读造成行号移动，对应解释仍可继续使用，固定引用仍指向写作时的版本。范围外的后续记录变化不会自动牵连前面的安排；但引用范围内新增或重排章节、下级标题中的条件变化，仍会要求核对。这个判断只是缩小复查范围，不等于自动证明语义完全不变。参考 [按引用实际覆盖范围判断变化 ↗](../../../docs/reader-first/publication-lifecycle.md#L27 "说明行号移动、完整章节、范围内外变化、嵌套条件和普通文本的复查边界。")

**第二次变化：把“预算是八十元”改成“预算是一百二十元”。**

费用章节会等待核对；地点章节在自身内容和前提未变时仍可阅读，旧文章版本也继续保留。当前机制用同一教学材料覆盖了增加导读、预算变化、范围外记录变化和嵌套条件变化等情况。参考 [导读与预算变化的教学验证 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L93 "验证新增导读后仍可用、预算变化只影响预算节，以及范围内嵌套变化会触发核对。")

如果实际文章把预算和地点写在同一节，合并后的整节会一起等待核对；如果集合安排明确以预算为背景前提，预算变化也会让地点章节等待核对。参考 [背景前提变化也会触发核对 ↗](../../../apps/server/tests/knowledge-lifecycle.test.ts#L215 "验证地点说明显式依赖预算时，预算变化也会使地点章节待核对。") 无法识别小节或代码结构的普通文本发生变化时，系统可能只能按整份材料处理。

**待更新只表示旧解释需要核对，不表示正文已经自动改写。** 是否自动排队，还取决于文章是否开启了自动更新。

<a id="maintain-same-article"></a>
## 在同一篇文章上手动更新或持续跟踪

看到**待更新**后，先阅读各节提示；未受影响的章节可以继续使用。接下来有两条手动路径，它们都维护原来的文章：

- 材料和阅读目标不变：点击文章底部的**重新整理这篇**。
- 要增删固定材料、改用或取消项目/主题范围，或者修改主题、问题、读者：点击**调整材料与目标**，完成两步后保存并重新整理。参考 [重新整理与调整目标入口 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L452 "支持在同一篇文章上重新整理，或打开调整材料与目标的两步流程。")

文章末尾的**随所选材料自动更新**默认关闭。开启后：

- 跟踪项目或主题时，后来归入该范围的新材料、已有材料换版或材料移出，都会改变文章的维护输入；
- 只选择固定材料时，新材料不会自行进入文章，仍要通过“调整材料与目标”加入；
- 排队期间的连续变化会合并，执行时读取最新范围；关闭开关会取消尚未完成的自动任务，但不会取消你明确发起的手动整理。参考 [自动维护的范围和失败边界 ↗](../../../docs/reader-first/publication-lifecycle.md#L45 "说明自动更新默认关闭、固定选择与动态范围的差别、队列合并、关闭取消和失败重试。")

因此，后来收到“场地改为东侧阅读室，小周负责签到”的聊天时，自动更新同一篇文章需要同时满足三项条件：

1. 聊天已经手动归入“阅读小组”，或自动调查已经明确确认该归属；
2. 文章选择了持续跟踪“阅读小组”；
3. 文章开启了“随所选材料自动更新”。

归属含糊时，材料不会先进入范围。可以在**材料处理**页看到“待补充归属”并进入选择，也可以打开原文的**所属项目与主题**查看原因、候选和问题；勾选后点击**保存归属**。归属适用于该材料的所有版本，不会删除原文或历史引用，跟踪相关范围的文章会按各自更新设置处理。参考 [未指定归属时的调查边界 ↗](../../../docs/reader-first/project-contexts.md#L53 "说明自动调查的启用前提、明确匹配、含糊候选、人工选择优先以及不会自动创建项目。") [查看并人工修正材料归属 ↗](../../../apps/web/src/SourceContexts.vue#L33 "支持展示自动、含糊或无匹配结果，以及保存人工选择和触发相关更新。") [材料处理页的待补充归属入口 ↗](../../../apps/web/src/LearningView.vue#L83 "支持在材料处理页看到待补充归属，并进入项目或主题选择。")

若材料归属本来正确，只是这篇文章题目较窄，不要为了迁就文章删改真实归属；应取消整组跟踪，改为固定选择少数材料。范围正确也只决定哪些材料参加调查，不保证模型已经正确理解新旧安排、时间和角色，更新后仍要人工验收。参考 [项目或主题的使用边界 ↗](../../../docs/reader-first/project-contexts.md#L3 "说明动态范围、自动更新链路、整组加入、错误归属与只选部分材料时的处理。")

新结果成功发布前，旧正文和写作时的固定引用继续保留。点击论断旁的引用，面板会显示支持理由并打开固定目标；原文页会标明**当前版本**或**历史版本**以及引用位置。因此预算已经改为 120 元时，旧文中“80 元”的引用不会悄悄跳到新版文字。参考 [引用打开固定目标 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L83 "支持引用面板显示理由，并打开生成时固定的文章或材料目标。") [原文标明当前或历史版本 ↗](../../../apps/web/src/knowledge/KnowledgeSource.vue#L34 "支持原文页面显示当前或历史版本、引用位置和对应片段。")

“更新同一篇文章”保证页面身份和历史延续，不保证标题与章节布局逐字不变。旧路线仍清楚时，新稿可以保留原有案例和结构；阅读目标变化或旧结构妨碍理解时，也可以按当前材料重新组织，并重新核对引用。参考 [同一文章可以局部维护或重组 ↗](../../../docs/reader-first/publication-lifecycle.md#L53 "说明维护时可保留清楚的旧路线，也可按当前目标重组，同时保留页面身份和历史并核对引用。")

更新完成后，再按原问题验收：预算是否已变为 120 元，地点是否仍为图书馆或已被新消息替代，各项结论是否有匹配引用，以及页面是否还留有会影响行动的待核对提示。
