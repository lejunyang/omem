# repo-review 服务启动入口

在回环地址启动独立评审服务，依次同步仓库关系、恢复知识、更新代码投影，并以显式模型配置构建 API。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="startup-sequence"></a>
## 同步与恢复顺序

入口从环境变量或当前目录确定仓库根目录，API 默认监听 5180 且固定绑定回环地址。创建独立评审存储后，启动流程先执行评审增量同步，再恢复仓库材料和知识文章，随后更新代码投影并汇总文章恢复状态；因此启动会恢复既有知识，但这段流程没有触发知识生成。[评审启动同步链路 ↗](../../../apps/server/src/review/main.ts#L13 "支持仓库根目录、回环端口以及同步、知识恢复和代码投影的实际执行顺序。")

<a id="model-and-server"></a>
## 模型选择与服务装配

该入口明确只承载评审 API，不接入个人工作区服务。[独立评审入口边界 ↗](../../../apps/server/src/review/main.ts#L5 "直接支持评审入口不装配个人工作区服务的边界声明。") 代码理解模型采用显式可选配置，构建出的模型端口可以为空并记录为 `none`；应用装配接收仓库根目录、API 端口和默认 5181 的 Web 端口，完成后才在回环地址监听。[模型与应用配置 ↗](../../../apps/server/src/review/main.ts#L27 "支持模型为显式可选配置，以及 API、Web 端口传入应用构建器后开始监听。")

<a id="shutdown"></a>
## 退出与失败处理

收到中断或终止信号时，入口先异步关闭应用再退出进程；启动阶段若抛出错误，则关闭存储并继续抛出原错误，避免失败后遗留已打开的数据库连接。[服务关闭与异常清理 ↗](../../../apps/server/src/review/main.ts#L45 "支持信号关闭应用以及启动失败时关闭存储并重新抛错的行为。")
