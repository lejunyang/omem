# repo-review 服务启动入口

在回环地址启动独立评审服务，先同步并恢复固定知识，再更新代码投影；模型为显式可选配置，入口不装配个人工作区服务。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="startup-sequence"></a>
## 同步与恢复顺序

入口从环境变量或当前进程目录确定仓库根目录，API 默认使用 5180 端口并固定绑定回环地址。创建评审专用存储后，它先执行增量同步，再恢复仓库材料与知识文章，随后更新代码投影并汇总恢复结果；因此启动阶段负责重建已有视图，并未在这里主动触发新的模型分析。[评审启动同步与知识恢复流程 ↗](../../../apps/server/src/review/main.ts#L13 "支持仓库根目录、回环监听参数，以及同步、知识恢复和代码投影的实际先后顺序。")

<a id="model-and-server"></a>
## 隔离边界与服务装配

该文件明确把 repo-review 定义为独立入口：同步完成后仅在回环地址提供评审 API，不接入个人工作区服务。[评审入口隔离说明 ↗](../../../apps/server/src/review/main.ts#L5 "入口注释直接支持 repo-review 仅提供回环评审 API、不会装配个人工作区服务这一边界。") 代码理解模型采用显式启用方式，未配置时模型端口为 `none`；应用构建器接收存储、仓库根目录、API 端口、默认 5181 的 Web 端口及模型配置，装配完成后才开始监听。[可选模型与应用配置 ↗](../../../apps/server/src/review/main.ts#L27 "支持模型仅按评审配置显式启用，以及 API、Web 端口和模型配置传入应用构建器的装配过程。")

<a id="shutdown"></a>
## 退出与失败处理

收到 `SIGINT` 或 `SIGTERM` 时，入口异步关闭应用后退出进程；若启动或监听阶段抛错，则关闭底层存储并重新抛出原错误。这两条路径分别处理正常终止与初始化失败，降低数据库连接在异常启动后遗留的风险。[服务关闭与异常清理 ↗](../../../apps/server/src/review/main.ts#L45 "支持信号触发应用关闭，以及启动失败时关闭存储并继续抛出错误的处理。")
