# repo-review 服务启动入口

该入口把仓库材料同步、评审知识恢复、代码投影、模型与检索配置以及 HTTP 服务装配为串行启动流程。它固定监听回环地址并使用隔离的 review Store；模型仅为显式生成操作提供配置，检索实现则按配置在关键词与语义模式间切换。正常信号关闭的资源托管范围及两个未使用导入的用途仍需结合应用装配代码确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 作用与隔离边界

该文件是 repo-review 的进程入口：从环境变量取得仓库根目录和端口，固定监听 `127.0.0.1`，创建 review Store，并注册知识仓库适配。它负责启动当前代码仓库的评审 API，不接入个人工作区服务。[评审入口与基础初始化 ↗](../../../apps/server/src/review/main.ts#L7 "支持入口面向仓库评审 API、固定回环监听并创建 review Store 的论断。") Review Store 复用通用捕获与检索能力，但数据位于 `.repo-review/runtime`，不触碰个人工作区 SQLite，也不启动 Lark 或学习 worker。[评审 Store 的隔离约定 ↗](../../../apps/server/src/review/store.ts#L1 "说明 review 运行数据与个人工作区数据库及后台 worker 的隔离边界。")

<a id="startup"></a>
## 启动与应用装配

入口先执行仓库增量同步，再恢复评审知识，随后生成代码结构投影，完成后才构建并监听 HTTP 应用。[同步、恢复与代码投影序列 ↗](../../../apps/server/src/review/main.ts#L19 "支持监听 HTTP 前依次执行同步、评审知识恢复和代码投影，并限定恢复对象的可证实表述。") 先前正文所称“恢复已发布的评审知识”缺少材料支持，现由固定代码能确认的“恢复评审知识”替代；其具体状态范围仍由恢复模块决定。

增量同步以仓库相对路径作为稳定 Source 身份，以内容哈希判断 revision 变化；它覆盖已提交、未提交和未跟踪内容，并在 Git 检测失败时退化为全量扫描。[仓库增量同步语义 ↗](../../../apps/server/src/review/sync.ts#L1 "解释 Source 身份、revision 变更检测、工作树覆盖以及 Git 失败时的退化策略。") 应用装配还接收 Web 端口、代码理解模型配置和可选检索配置；未启用时使用关键词检索，启用后才启动中文向量语义检索。[检索实现选择 ↗](../../../apps/server/src/retrieval/factory.ts#L9 "支持未启用配置时采用关键词检索、启用后启动语义检索及其后台资源的说明。")

<a id="models_and_lifecycle"></a>
## 模型配置与生命周期

入口读取代码理解模型配置传给应用，并另行构造模型端口以记录 transport；启动本身没有展示自动生成知识的调用。[模型与应用装配 ↗](../../../apps/server/src/review/main.ts#L29 "支持入口加载模型配置、记录 transport，并将模型和检索配置交给应用的流程。") 实际配置优先使用 `REVIEW_CODE_MODEL_CONFIG`，否则查找仓库内配置文件；缺少配置时回退为 `none`，显式文件不可读、JSON 非法或 transport 不受支持时抛错。[评审模型配置规则 ↗](../../../apps/server/src/review/model-config.ts#L1 "说明仓库配置、环境变量覆盖、无配置回退及错误校验，并表明入口注释不是完整现行规则。") 因此入口中“只读取环境变量”的注释已被配置实现所替代，不能视为当前完整规则。

监听成功后，`SIGINT` 与 `SIGTERM` 调用 `app.close()` 并退出；启动异常则直接关闭 Store 后重新抛错。[监听、信号关闭与异常清理 ↗](../../../apps/server/src/review/main.ts#L46 "支持正常信号路径关闭应用、启动异常路径直接关闭 Store 的生命周期描述。") 现有材料尚不能证明正常信号路径是否同时释放 Store、数据库连接与语义检索后台资源，也不能确认多次信号下的清理幂等性。

<a id="limits"></a>
## 输入限制与待确认依赖

入口只做流程编排，不实现扫描、索引或生成算法。同步器仅读取固定根目录下的白名单纯文本，并逐文件拒绝路径逃逸、非 UTF-8 和超大文件；单文件失败不会中止整个同步。[同步输入安全边界 ↗](../../../apps/server/src/review/sync.ts#L9 "说明扫描输入白名单以及对路径逃逸、编码和文件大小异常的逐文件拒绝策略。") 文件还导入了 `captureRepositoryMaterials` 与 `restoreKnowledgeArticles`，但可见入口代码没有调用它们。[入口导入与实际调用范围 ↗](../../../apps/server/src/review/main.ts#L1 "支持两个符号已导入但在所示入口流程中没有被直接调用的观察。") 仅凭当前材料无法判断它们是遗留导入、模块副作用依赖，还是为尚未完成的装配预留。
