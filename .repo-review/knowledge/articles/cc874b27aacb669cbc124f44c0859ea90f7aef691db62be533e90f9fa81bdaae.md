# docs-implementation · 模块理解

该模块记录 omem 从 Batch 2 工程基础向个人主助手、渐进记忆、统一知识整理与 Code Wiki 演进的设计、实现和验收边界。其核心是让各类输入沿固定证据链被检索、复核和治理；历史材料显示部分学习、飞书、知识阅读与检索能力已经落地，但持久主助手、完整质量发布门和跨版本身份续接等仍需当前证据确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责、背景与核心取舍

`docs-implementation` 不是单一功能说明，而是连接产品设计、工程切片、状态记录和验收证据的实施地图。v3 将飞书设为主要助理入口、Web 作为管理及第二对话入口，并替换“普通材料全量提炼、非自动通过即询问用户”的旧默认路径，同时保留 Batch 2 已建的数据、任务、ACP、飞书和界面基础设施。[主助手 v3 定位与路径替换 ↗](../../../docs/implementation/assistant-v3/README.md#L3 "支持飞书与 Web 的入口定位，以及 v3 替换旧普遍确认路径但复用既有基础设施的背景。")

新的核心取舍是先保真保存并找回原材料，再按实际任务、反复使用、纠正和来源变化渐进整理；材料描述不会自动成为用户任务，低置信内容通常先保留并补证。[渐进记忆的核心判断 ↗](../../../docs/implementation/assistant-v3/README.md#L7 "支持先保存原材料、轻量分类、按价值渐进整理及低置信内容不必立即询问用户。") 上层专题进一步把这一原则落实为统一 Capture 证据链、不可变知识修订和派生正文不充当独立证据的合同，可由此下钻查看知识流程的完整边界。[统一证据链与知识合同 ↗](8cacd4aed1115e3d8ab47054816bd07d2ac3d155756ba0127a3028ac0c880fd6.md#purpose "提供知识整理职责、固定引用和派生内容证据边界的下钻入口；其结论仍沿章节引用回到原始材料。")

<a id="workflow"></a>
## 主要流程与跨模块协作

规划中的主助手通过会话路由接收本人私聊、明确提及和 Web 对话，构建当前事项、原件、记忆与纠正上下文，再经检索端口和受管理工具进入确定性的授权、版本及证据策略；群聊、屏幕、Git 和文档等被动输入则先进入保真采集、索引和后台整理，只有通过 Attention Gate 才回到交互路径。[主助手与后台整理流程 ↗](../../../docs/implementation/assistant-v3/README.md#L23 "支持会话路由、上下文构建、检索、受管理工具、确定性策略、后台整理和 Attention Gate 的协作关系。")

实施层面由统一知识流程承担材料分析、固定引用、独立复核、定向修订和分层发布，Code Wiki 只是代码域投影，个人知识与仓库知识共用阅读链。[生成复核与跨模块协作 ↗](8cacd4aed1115e3d8ab47054816bd07d2ac3d155756ba0127a3028ac0c880fd6.md#pipeline "提供分析、独立复核、定向修订、共享阅读和 Code Wiki 定位的下钻入口。") 受控学习专题则说明持久任务、独立 verifier、事务应用、飞书投递和反馈回流如何构成较早的工程基础。[Batch 2 受控学习链路 ↗](b26b2801da1ba59559f15d4a295604f7de76247ed1018609fce4d74427fd36cc.md#purpose_flow "提供持久任务、Proposal、独立验证、飞书治理及质量边界的专题下钻入口。")

<a id="routing_constraints"></a>
## 路由、治理与证据约束

消息路由必须区分交互与采集：已绑定 owner 私聊可检索、治理或提醒，群内明确提及只能使用群可见范围，被动群消息和观察数据默认不回复也不创建本人任务。会话按主体、渠道、聊天和线程区分，项目身份不得由聊天或应用标识替代；跨 Web 与飞书只有显式关联才共享同一会话。重启、取消和超时还要区分已投递与未投递内容，不能在后台继续产生未授权动作。[消息与会话路由规则 ↗](../../../docs/implementation/assistant-v3/README.md#L43 "支持私聊、群聊、采集和控制意图的不同处理方式，以及会话隔离、恢复与取消约束。")

迁移与验收专题补充了历史保护、停止语义和分层 live 验证要求；固定原件、修订、任务、receipt 与 outbox 历史不得被新设计抹去。[迁移治理与验收约束 ↗](3d8bcd6d032e82be0c09f76762de7b216dd197fd8e859d1d4d828cbee0f41987.md#constraints "提供历史保护、统一服务、停止合同和分层验收要求的专题下钻入口。") 所有派生总结仅提供导航，最终依据仍应沿内联引用回到固定原始 Fragment。

<a id="progress_limits"></a>
## 进展、限制与未决事项

现有专题记录表明，Batch 2 的受控学习主链、部分生产飞书能力和回归检查已有历史验证，但 v3 文档在当时仍明确指出普通 owner 私聊未接通，需要持久 AssistantRuntime。[历史进展与主助手缺口 ↗](3d8bcd6d032e82be0c09f76762de7b216dd197fd8e859d1d4d828cbee0f41987.md#progress "提供 Batch 2 已验证范围、v3 主助手未接通及质量发布门缺口的汇总下钻入口。") 另一专题将当前知识整理能力概括为共用角色运行时、共享 Evidence Trail、知识引导原始证据召回及中文语义检索和来源更新闭环，同时保留单用户 SQLite、跨文件调用和跨 revision 身份续接等限制。[当前能力演进与架构边界 ↗](8cacd4aed1115e3d8ab47054816bd07d2ac3d155756ba0127a3028ac0c880fd6.md#progress_limits "提供共享知识运行时、检索与来源刷新进展，以及单用户和跨版本限制的下钻入口。")

因此，“历史切片通过”不能等同于“当前模块完整验收”：全库 reviewed、stale、pending、failed 覆盖，冻结质量集、真实通知聚合，以及主助手跨入口会话续接，仍须以最新状态和验证工件分别确认。
