# docs-implementation · 模块理解

本模块记录 omem 从 Batch 2 受控学习基础设施向个人主助手、渐进记忆、统一知识流水线和 Code Wiki 演进的设计与实施状态。共同原则是保存固定原始证据、渐进组织知识，并由确定性策略治理变更。现有材料支持知识整理、来源更新、中文检索及部分日常跟进已形成可运行切片；截至 2026-09-27 的设计记录仍将飞书主助手入口列为缺口，但其当前实现状态尚需同版本证据核验。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 模块职责与设计演进

`docs-implementation` 汇集设计、实施切片、迁移约束和验收记录。Batch 2 奠定持久任务、角色化提炼、飞书投递和界面基础；v3 随后明确替代“普通材料全量提炼、非自动通过就询问用户”的默认路径，转向原材料可找回、上下文保留、渐进整理以及只对影响行动的选择提问。[v3 产品路径调整 ↗](../../../docs/implementation/assistant-v3/README.md#L3 "支持旧有普遍提炼确认路径被替代，以及原材料优先、渐进整理和按行动相关性提问的设计背景。") 子专题进一步梳理这段演进及四层信息边界，但其正文属于派生知识，结论仍须沿引用回查固定材料。[Batch 2 与渐进记忆演进 ↗](3d8bcd6d032e82be0c09f76762de7b216dd197fd8e859d1d4d828cbee0f41987.md#purpose "提供 Batch 2 历史基础、v3 产品转向和信息边界的子知识下钻入口。")

统一知识流水线沿用同一事实边界：权威原始材料属于 Capture、Source、Revision 和 Fragment，知识正文、检索索引与代码图都是可失效、可重建的派生视图。Code Wiki 因而是代码材料在统一证据链上的类型化投影，而非独立知识库。[统一证据与 Code Wiki 定位 ↗](f8c11c2b83ccb5d68da4c592f7ea00d013ca3a6aaa4702d6f2e383595e9b2eb6.md#purpose_and_evolution "支持知识正文和代码图均为统一不可变证据链上的派生视图。")

<a id="workflow"></a>
## 主助手、知识整理与治理流程

v3 规划由飞书本人私聊、明确提及或 Web 对话进入 Conversation Router 和持久 AssistantRuntime；上下文构建器组合事项、原件、记忆与纠正，受管理工具提出事项、关系或提醒操作，再经确定性的授权、版本和证据策略写入权威状态及 Outbox。被动群聊、屏幕、Git 和文档进入采集与后台整理路径，由 Attention Gate 决定自动处理、推迟或发起交流。[主助手端到端结构 ↗](../../../docs/implementation/assistant-v3/README.md#L23 "支持交互入口、上下文构建、受管理工具、确定性策略、Outbox、后台整理和 Attention Gate 的关系。")

知识侧复用统一运行时：材料先形成带内联引用的正文，再由独立会话核验引用是否支持附近论断；来源变化或复核失败时不得发布旧结果，退回内容须定向修订并再次复核。[统一知识生成与独立复核 ↗](8cacd4aed1115e3d8ab47054816bd07d2ac3d155756ba0127a3028ac0c880fd6.md#generation-and-review "支持材料分析、独立语义复核、来源变化拒绝发布和退回后的定向修订。") 阅读与召回也保持证据闭环：个人知识和仓库知识共用 Evidence Trail，派生正文只帮助导航，助手最终取得当前固定原始片段。[知识阅读与原始证据召回 ↗](8cacd4aed1115e3d8ab47054816bd07d2ac3d155756ba0127a3028ac0c880fd6.md#reading-and-retrieval "支持共用 Evidence Trail、派生正文仅用于导航以及召回最终返回原始 Fragment。")

<a id="relations"></a>
## 输入路由、跨模块关系与一致性约束

主助手维护当前任务、项目归属、纠正、未完成承诺和最近对话目的，但不会把所有捕获内容视为指令：私聊与明确提及进入交互路径，背景观察进入记忆采集，内部状态只形成有限建议。[主助手职责与输入边界 ↗](../../../docs/implementation/assistant-v3/README.md#L15 "支持主助手维护工作上下文，并区分交互消息、被动采集和有限主动建议。") 会话按主体、渠道、聊天和线程区分；Web 与飞书可共享 owner 的记忆和事项，却只有用户显式关联后才共用同一 conversation。持久 turn、取消和投递状态还要防止重启或超时后继续产生未授权动作。[消息路由与会话一致性 ↗](../../../docs/implementation/assistant-v3/README.md#L43 "支持不同输入的路由、跨渠道 conversation 显式关联，以及持久恢复和取消约束。")

日常交办、等待跟进与知识整理沿用既有助手模型、MemoryService 和原始材料规则，而非各自建立事实来源；代码关系同样只是统一流水线中的材料适配和派生关系。[日常助理与知识流程共用关系 ↗](f8c11c2b83ccb5d68da4c592f7ea00d013ca3a6aaa4702d6f2e383595e9b2eb6.md#pipeline_and_connections "支持日常交办复用既有助手模型、MemoryService 和证据规则，并说明代码关系不形成新的事实来源。")

<a id="progress_limits"></a>
## 进展、验证口径与限制

子专题记录 Batch 2 的受控学习主链、部分生产飞书能力、真实 ACP 小样本和浏览器回归已有历史验证。[Batch 2 历史进展与限制 ↗](b26b2801da1ba59559f15d4a295604f7de76247ed1018609fce4d74427fd36cc.md#progress_limits "支持受控学习、飞书能力、质量数据集和通知聚合的历史完成度及限制。") 后续材料分别记录了共用知识角色和独立复核流程、中文混合与向量检索，以及来源更新重核验和网页日常助理的若干闭环。[共用知识角色与复核流程 ↗](8cacd4aed1115e3d8ab47054816bd07d2ac3d155756ba0127a3028ac0c880fd6.md#generation-and-review "支持材料、代码、对话和图像角色共用运行时，以及独立复核和来源变化保护已经形成实现切片。")[中文混合与向量检索 ↗](8cacd4aed1115e3d8ab47054816bd07d2ac3d155756ba0127a3028ac0c880fd6.md#reading-and-retrieval "支持知识引导原始证据召回、中文混合检索和固定向量模型的阶段进展。")[来源更新与日常助理闭环 ↗](8cacd4aed1115e3d8ab47054816bd07d2ac3d155756ba0127a3028ac0c880fd6.md#progress-and-limits "支持来源更新重核验和网页日常助理已验证的部分闭环，同时限定尚未接入的能力。")

这些进展不能反向证明飞书主助手已经接通：2026-09-27 的 v3 设计仍明确写明当时普通 owner 私聊被忽略、需要新增持久 AssistantRuntime；其当前状态缺少同一版本的端到端证据，仍待核验。[2026-09-27 飞书主助手缺口 ↗](../../../docs/implementation/assistant-v3/README.md#L15 "直接支持截至该设计记录时普通 owner 私聊尚未接通，并需要新增持久 AssistantRuntime；不用于推断当前状态。") 其他限制还包括冻结 holdout 与质量发布门未完成、完整通知聚合及部分飞书现场场景缺少实证，以及跨文件调用和跨 revision 符号身份尚未完善。[质量与平台能力限制 ↗](b26b2801da1ba59559f15d4a295604f7de76247ed1018609fce4d74427fd36cc.md#progress_limits "支持冻结质量集、通知聚合和飞书现场验证仍存在未完成范围。")[验证与代码分析边界 ↗](f8c11c2b83ccb5d68da4c592f7ea00d013ca3a6aaa4702d6f2e383595e9b2eb6.md#verification_and_limits "支持区分确定性测试、浏览器和小规模 live check，并说明跨文件调用及跨版本身份限制。") 工程检查、浏览器流程和单次 live check 只能证明各自范围，完整覆盖应以当前源码指纹对应的报告为准。
