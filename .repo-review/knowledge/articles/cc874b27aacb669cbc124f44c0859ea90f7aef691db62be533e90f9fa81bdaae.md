# docs-implementation · 模块理解

该模块用于区分 omem 的设计目标、当前实现、验证强度与剩余边界，并把统一输入、不可变证据、知识整理、主助手治理、飞书交互和 Code Wiki 投影串成可追溯链路。渐进记忆已替代 Batch 2 的普遍确认路线，但 W0–W4 仍是目标策略而非全部完成；来源更新后的自动重核验、部分真实外部链路、语义检索及多租户能力仍未交付。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责、背景与判断口径

本模块是实现事实与演进边界的入口，阅读时必须区分设计、代码接线、确定性测试、真实外部验证和历史记录；失败、过期或未生成的知识不能算作完成。最新记录显示通用正文、固定引用、持久分析、独立复核、个人知识入口和递归证据阅读已经接入，但真实模型说明仍不能因生成成功而视为完成语义核验。[当前实现与复审基线 ↗](../../../docs/implementation/status.md#L1 "支持当前能力、复审退出结果、真实模型说明未独立语义核验及完成口径。")

产品路线已经明确替代 Batch 2 的“普通材料全量提炼、非自动通过就确认”路径，转向以飞书为主要交互入口、Web 为管理与第二入口的渐进记忆设计；原有数据、事务、任务、ACP、飞书和界面基础继续复用。[渐进记忆路线替换 ↗](../../../docs/implementation/assistant-v3/README.md#L3 "支持 v3 替代 Batch 2 的普遍提炼和确认路径，以及飞书与 Web 的入口定位。") Evidence、派生索引、WorkingContext 与正式 Knowledge/Commitments 是并存视图，派生摘要不能循环成为独立证据。[四层信息模型 ↗](../../../docs/implementation/assistant-v3/README.md#L77 "解释原件、派生索引、工作上下文与正式知识的职责，以及派生摘要不得成为独立证据。")

<a id="workflow"></a>
## 从输入到知识与行动

手工、文件、Git、飞书、聊天和屏幕事件进入统一捕获或聚合入口；相同来源与外部标识的相同内容幂等复用，变化产生新修订，URL 只保存为材料而不自动访问。[统一输入与版本规则 ↗](../../../docs/implementation/inputs.md#L3 "支持捕获入口、内容边界、幂等版本化、事件聚合和链接不自动访问等输入约束。") W0 收录、W1 可检索化、W2 场景理解、W3 有目的提炼、W4 巩固维护是 v3 的目标处理策略，原文明确标为待实现，不能表述为当前已完整执行。[处理策略的实现状态 ↗](../../../docs/implementation/assistant-v3/processing-policy.md#L1 "明确处理策略被标为待实现，防止把后续阶段矩阵整体描述成已经落地。")[W0 至 W4 目标矩阵 ↗](../../../docs/implementation/assistant-v3/processing-policy.md#L23 "解释五阶段的目标产物、交互方式和进入有目的提炼的触发条件。")

已经落地的通用 KnowledgePipeline 会分离材料分析和独立复核，由宿主复制固定引文，只有通过复核的正文才发布；用户回答作为新原始材料回流，代码关系不获得额外事实权威。[通用知识分析与复核 ↗](../../../docs/implementation/knowledge-pipeline.md#L23 "支持已实现的分析、独立复核、固定引文复制、发布门槛和用户回答回流。") 低风险变化可按策略处理，只有与当前目的相关、确需 owner 选择、补证已尽且能说明后果时，Attention Gate 才创建用户可见问题。[用户注意力门槛 ↗](../../../docs/implementation/assistant-v3/processing-policy.md#L68 "支持低风险自动处理，以及创建用户可见问题必须满足的相关性、选择必要性、补证和后果说明。") 当前尤其不能把 W4 视为完成：来源更新后的完整 extractor 与 verifier 重跑仍未实现。

<a id="relations"></a>
## 主助手、角色、飞书与 Code Wiki 的关系

当前 Web 与飞书生产路径已装配 ACP 模型适配器、关键词检索和限定范围的纠正服务；模型不可用时应留下诚实失败，不生成虚假引用或任务。[主助手生产接线 ↗](../../../docs/implementation/status.md#L25 "支持 Web 与飞书已接 ACP、关键词检索和纠正服务，并说明模型异常时不得伪造回答、引用或任务。") 后台角色通过版本化 manifest、严格输出合同、工具策略、预算和隔离会话运行，角色定义“做什么”，工具策略限定“能做什么”。[角色运行合同 ↗](../../../docs/implementation/batch2/agent-runtime.md#L25 "支持角色清单、模型请求解析、工具策略、预算、会话限制和实际运行记录之间的职责分离。") 模型仅提出结构化建议；权限、并发、证据与版本校验以及最终事实提交由领域服务承担，因此角色输出本身不构成授权。[领域服务授权边界 ↗](../../../docs/implementation/batch2/README.md#L40 "支持模型只生成结构化建议，而领域服务负责权限、并发、证据与版本校验和事实提交。")

飞书承担身份绑定、对话、通知和决策回调，而不是事实权威。正式变化与投递意图保持可追踪关系，重试复用 provider UUID，无法对账时保留 unknown；卡片回调先持久化，再异步进行版本和业务核验。[飞书投递与回调合同 ↗](../../../docs/implementation/batch2/lark.md#L92 "支持事务化投递意图、固定 UUID 重试、unknown 状态，以及回调先持久化再异步核验的规则。") Code Wiki 则是统一 Capture→Source/Revision/Fragment→Relation/Retrieval 链上的可重建类型化投影；内部标识不得作为展示文本，missing 或 stale 目标必须不可操作并说明原因，源码读取锚定固定快照。[代码投影而非第二事实源 ↗](../../../docs/implementation/code-knowledge-design.md#L505 "支持 Code Wiki 的可重建投影定位、展示字段与内部标识分离、缺失目标处理和固定快照读取。")

<a id="limits"></a>
## 验证、迁移与剩余边界

当前主要缺口包括：`refresh_dependents` 只记录受影响对象并主动以未实现错误结束；跨文件类型感知调用、跨修订符号或片段身份续接和 embedding 检索仍未交付。[自动重核验与代码能力缺口 ↗](../../../docs/implementation/status.md#L86 "支持 refresh_dependents 尚未完成完整重核验，并说明跨文件调用、跨修订身份续接和语义检索限制。") 外部验证也需分级：主助手真实 ACP 对话、飞书真实图片下载、断网恢复、移群、密钥轮换和真实限流窗口尚缺完整现场证据。[能力矩阵与外部验证边界 ↗](../../../docs/implementation/status.md#L47 "支持主助手、输入、飞书投递与质量评估的真实验证范围及剩余外部链路缺口。") 当前实现采用 TypeScript 与 SQLite 的个人单用户模式，不具备多租户 ACL、分布式事务或租户隔离保证；此前紧邻外部验证矩阵推导这一结论的引用方式已被替代，现改由明确的实现取舍记录支持。[个人单用户实现边界 ↗](../../../docs/implementation/status.md#L124 "直接支持当前采用 TypeScript 与 SQLite 的个人单用户实现，并明确缺少多租户 ACL、分布式事务和跨版本语义片段续接。")

迁移必须保留原件、固定片段、正式修订、绑定、任务、receipt、outbox 与已发送历史；已取消会话不得复活，旧 chat、run 或 application 标识不能静默解释为项目范围。[迁移与历史保护 ↗](../../../docs/implementation/assistant-v3/migration-and-acceptance.md#L19 "支持保留证据和运行历史、维持取消状态，并禁止静默转换 legacy scope。") 验收应分别记录基线回归、确定性 fixture、真实 ACP、真实飞书和固定质量样本，mock 或协议通过不能冒充现场可用。[分层验收方法 ↗](../../../docs/implementation/batch2/acceptance.md#L5 "支持分别记录基线、确定性测试、真实 ACP、真实飞书与质量观察，避免 mock 冒充 live。") 所有展示引用都应回查固定原文；精度、覆盖率和零误建承诺等阈值只是发布目标，只有冻结样本、明确分母和真实结果齐备后才能声明达到。[质量发布目标 ↗](../../../docs/implementation/batch2/acceptance.md#L118 "支持固定引用回查、精度、覆盖率和误建约束，并明确阈值是目标而非已达到结果。")
