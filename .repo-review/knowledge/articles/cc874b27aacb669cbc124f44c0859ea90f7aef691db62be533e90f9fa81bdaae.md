# docs-implementation · 模块理解

本模块汇集 omem 的实施合同、设计演进与验证边界。v3 以渐进记忆替代普遍确认路径，并计划复用既有基础设施；统一知识流程则以固定原始证据、独立复核和可重建投影连接日常助理、飞书与 Code Wiki。当前仍有全库覆盖、质量发布门、外部现场验收及跨版本代码身份等未决事项。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责、背景与设计主线

`docs-implementation` 用于串联产品方向、工程合同和阶段性验证。v3 文档明确标为“待实现”，其可确认的历史关系是：它替换 Batch 2 中“普通材料全量提炼、非自动通过即询问”的默认路径，并计划继续使用既有数据、事务、任务、ACP、Lark 与 UI 基础设施；该材料本身不能证明这些基础设施的具体实现程度。[v3 定位与渐进记忆原则 ↗](../../../docs/implementation/assistant-v3/README.md#L3 "支持 v3 被标为待实现、替换旧默认确认路径、计划复用既有基础设施，以及原材料优先和渐进整理原则。") Batch 2 的实现状态应下钻到专项子知识及其固定引用核对。[Batch 2 历史进展专题 ↗](3d8bcd6d032e82be0c09f76762de7b216dd197fd8e859d1d4d828cbee0f41987.md#progress "为 Batch 2 的实现状态提供下钻入口，避免仅凭 v3 设计稿推断具体能力已经实现。")

新的设计主线是先保存并找回原材料，再以轻量分类和实际使用价值渐进整理；低置信或缺背景通常先保留来源、按需补证，而非立即打扰用户。[v3 定位与渐进记忆原则 ↗](../../../docs/implementation/assistant-v3/README.md#L3 "支持 v3 被标为待实现、替换旧默认确认路径、计划复用既有基础设施，以及原材料优先和渐进整理原则。") 各类知识正文、代码图、索引和摘要都位于统一 Capture→Source→Revision→Fragment 证据链之上，是可重建投影而不是新的独立事实来源。[统一知识流程的事实边界 ↗](8cacd4aed1115e3d8ab47054816bd07d2ac3d155756ba0127a3028ac0c880fd6.md#purpose "支持原始证据链、派生知识非独立原件以及共用角色运行时的模块原则。")

<a id="workflow"></a>
## 主要流程与跨模块关系

材料先保真收录并建立检索入口，在任务使用、纠正或来源变化等触发下进入有目的提炼；角色提出候选后，由独立 verifier 核对主体、范围、时间和固定证据，再由确定性策略决定自动应用、继续补证或形成用户问题。[渐进处理与受控应用流程 ↗](3d8bcd6d032e82be0c09f76762de7b216dd197fd8e859d1d4d828cbee0f41987.md#workflow "支持分阶段处理、独立复核、低风险应用和 Attention Gate 的主要流程。") 通过复核的正文按材料、模块和概览逐层组织；个人知识与仓库知识共用 Evidence Trail，检索即使先命中派生正文，最终仍沿引用回到固定原始片段。[知识生成、阅读与原始证据召回 ↗](f8c11c2b83ccb5d68da4c592f7ea00d013ca3a6aaa4702d6f2e383595e9b2eb6.md#pipeline_and_connections "支持复核后分层发布、共享 Evidence Trail，以及检索最终返回固定原始片段。")

飞书私聊和 Web 路由到持久 AssistantRuntime、上下文构建器、检索端口、受管理工具及 Outbox，是 v3 描述的目标架构。原文同时说明当时普通 owner 私聊仍被忽略，尚无可用飞书主助手，因此不能把该流程图当作已实现证明。[v3 主助手职责与目标架构 ↗](../../../docs/implementation/assistant-v3/README.md#L15 "支持 AssistantRuntime 的规划职责、飞书与 Web 路由关系，并明确当时尚无可用飞书主助手。") 日常助理和 Code Wiki 均应复用统一证据与服务边界，不另建事实权威。[知识生成、阅读与原始证据召回 ↗](f8c11c2b83ccb5d68da4c592f7ea00d013ca3a6aaa4702d6f2e383595e9b2eb6.md#pipeline_and_connections "支持复核后分层发布、共享 Evidence Trail，以及检索最终返回固定原始片段。")

<a id="progress"></a>
## 进展、被替代结论与验证边界

子知识记录了统一知识角色、中文语义检索、来源更新后的 extractor→verifier→apply 闭环，以及网页日常助理等较新进展；因此“只有关键词检索”或“来源重核验仍是占位”的旧说法已被替代。[较新能力进展与覆盖限制 ↗](8cacd4aed1115e3d8ab47054816bd07d2ac3d155756ba0127a3028ac0c880fd6.md#progress "支持中文检索、来源更新闭环和网页日常助理等较新进展，同时说明全库覆盖仍须查看当前报告。") 但全库知识是否完整仍须读取当前 coverage 与 verification 报告，不能沿用历史统计。[较新能力进展与覆盖限制 ↗](8cacd4aed1115e3d8ab47054816bd07d2ac3d155756ba0127a3028ac0c880fd6.md#progress "支持中文检索、来源更新闭环和网页日常助理等较新进展，同时说明全库覆盖仍须查看当前报告。")

验证证据必须分层解释：确定性测试主要证明合同和状态机，真实浏览器证明可消费流程，小规模 live check 只证明特定配置与样本可连通；协议夹具不能替代全部真实 Agent CLI、飞书事件或外部观察器验收。[验证证据的适用范围 ↗](f8c11c2b83ccb5d68da4c592f7ea00d013ca3a6aaa4702d6f2e383595e9b2eb6.md#verification_and_limits "支持区分确定性测试、真实浏览器和小规模 live check，防止外推为全部外部集成已验收。") 同样，专项子知识将通知能力收窄为逐条即时投递，并指出冻结 holdout、短窗合并、定时摘要及若干平台故障现场验证仍未完成；这替代了把“通知聚合已接入”理解为完整聚合能力的宽泛结论。[质量集、通知与现场验证限制 ↗](b26b2801da1ba59559f15d4a295604f7de76247ed1018609fce4d74427fd36cc.md#progress_limits "支持 dev 草稿尚非冻结 holdout、通知仅完成逐条投递，以及部分平台场景仍缺现场验证。")

<a id="limits"></a>
## 治理约束与未完成能力

当前实现仍以个人单用户、TypeScript 与 SQLite 为边界，workspace 字段不等于多租户 ACL。代码域尚缺可靠的跨文件调用解析，名称级调用只能作为候选；跨 revision 的符号与 Fragment 身份续接也未实现。[代码知识与单用户运行边界 ↗](8cacd4aed1115e3d8ab47054816bd07d2ac3d155756ba0127a3028ac0c880fd6.md#limits "支持个人单用户实现、跨文件调用及跨版本符号和 Fragment 身份续接等限制。")

迁移和停止操作必须保留原件、固定片段、正式修订、取消状态、receipt 与 outbox 历史，不得静默把 legacy scope 转成项目范围，也不能把“可追溯”误写成每条论断已经通过语义验证。[迁移、停止与历史保护约束 ↗](3d8bcd6d032e82be0c09f76762de7b216dd197fd8e859d1d4d828cbee0f41987.md#constraints "支持保留证据和运行历史、禁止静默转换作用域，并要求停止操作保持端到端语义。") 质量发布结论还依赖冻结数据集、明确的标注责任与真实指标；现有材料足以把这些列为限制，但不足以判定其当前数值或最新完成状态。[质量集、通知与现场验证限制 ↗](b26b2801da1ba59559f15d4a295604f7de76247ed1018609fce4d74427fd36cc.md#progress_limits "支持 dev 草稿尚非冻结 holdout、通知仅完成逐条投递，以及部分平台场景仍缺现场验证。")
