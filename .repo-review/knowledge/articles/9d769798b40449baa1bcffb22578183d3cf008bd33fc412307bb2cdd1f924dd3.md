# Batch 2验收合同与执行方法

待实现而非已通过的验收合同，覆盖迁移、任务恢复、ACP角色、证据提炼、飞书、通知、Vue和质量发布门，强调真实执行证据及fixture/live分离。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence"></a>
## 验收证据与执行分层

本文明确不是通过记录。每项验收应关联实现commit、schema与角色版本、测试命令、fixture hash、实际输出或receipt、结果和trace；未做真实扫码或投递时只能标为skipped或blocked，不能用mock冒充live。[待实现验收声明 ↗](../../../docs/implementation/batch2/acceptance.md#L1 "支持该文件不是通过记录以及每项验收所需的可审计证据。")

执行顺序分为基线回归、确定性fixture与故障注入、真实CLI/ACP、独立飞书测试应用和固定质量样本五层，各层回答不同风险，不能相互替代。[五层验收顺序 ↗](../../../docs/implementation/batch2/acceptance.md#L11 "解释确定性检查、真实Agent、真实飞书和质量观察为何必须分层。")

<a id="quality"></a>
## 运行安全与发布目标

ACP与角色验收要求证明实际加载的role和skill、模型切换后的effort协商、多模态上下文完整性、会话隔离及恶意材料不会获得工具或配置权限；仅有文件或握手不足以证明能力。[ACP与角色安全验收 ↗](../../../docs/implementation/batch2/acceptance.md#L43 "支持运行配置、上下文完整性、会话隔离和不可信材料不得越权的要求。")

发布门提出零未授权外部写、展示引用全部可回查、自动应用和证据支持精度门槛、有效覆盖、通知闭环与学习效果，但文档明确这些只是初始目标，不是已达到指标。[初始发布质量门 ↗](../../../docs/implementation/batch2/acceptance.md#L124 "支持发布目标的具体维度，并强调这些阈值尚未被证明达到。")
