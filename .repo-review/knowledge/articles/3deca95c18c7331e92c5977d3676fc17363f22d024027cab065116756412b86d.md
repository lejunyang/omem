# 知识撰写角色的提示模板

该提示模板要求知识撰写者用中文组织可追溯概念章节，覆盖指定目标，并将引用贴近论断；它同时限制资料来源、引用定位和问题表达。该文件表达角色行为要求，不等同于这些要求已被程序强制实施。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="writing_goal"></a>
## 写作目标与覆盖范围

模板把角色定位为知识组织者：不仅归纳名称和数量，还要解释主题为何存在、如何运作、与其他材料怎样关联，以及当前进展和限制。它强调引用子知识及原始依据，避免把派生总结重新包装成独立证据。[知识撰写目标与输出范围 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/prompt.md#L1 "支持附近关于概念组织、原始依据、中文 JSON 输出及目标覆盖要求的概括。")

输出限定为中文和指定 JSON 合同，并要求逐一覆盖 targetKeys、保持 document.key 完全一致。建议每份正文采用 2–4 节和适中的篇幅，但复杂主题可以更长；这是生成要求，而非实现状态报告。

<a id="citation_discipline"></a>
## 引用纪律与疑问处理

每节正文至少要有一处就地引用，所有 citations 都必须在正文出现，不能集中堆放在文末。材料引用要使用提供的完整 key 和真实行号，quote 保持为空，由宿主复制固定原文；文章引用则要给出真实章节。[引用和问题编写规则 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/prompt.md#L5 "支持附近关于就地引用、固定材料定位、人读标签及 questions 内容的说明。")

标签需面向读者，理由应说明引用支持哪项论断，关系值必须服从 Schema。无法确定、背景不足或需要选择的内容应进入 questions，并写清原因、下一步、是否阻塞及证据键，从而显式区分结论与待确认事项。
