# 知识文章的组织与证据引用规范

该角色规范面向知识文章组织者，要求以首次接触项目的读者为中心，将已有子知识整理为解释问题、流程、关联、进展与限制的中文 Wiki，并通过就近引用保留到原始依据的追溯链。它描述的是写作与输出约束，不能单独证明相关能力已在运行时完整实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

这份规范用于把分散的子知识组织成可阅读、可追溯的概念文章。文章不应只是函数名、数量或日志的汇总，而要回答“为什么需要、如何工作、与什么相关、目前到哪一步、还有什么限制”。派生总结只承担组织作用，关键论断仍应指向子知识及其原始依据，避免摘要在传播中被误当成新的事实来源。参考 [知识组织目标 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/prompt.md#L1 "支持知识文章应解释作用、流程、关联、进展和限制，并保持原始证据权威性的论断。")

<a id="reader_flow"></a>
## 从使用场景到关键限制

面向首次接触项目的读者，正文应先交代要解决的问题和实际场景，再逐步解释流程、概念及边界。标题按功能命名，不以文件路径或内部治理名称充当主题；小标题、表格或 Mermaid 图只在确实有助于理解时使用，多阶段图中的关系也必须有材料支持。参考 [读者导向写作 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/prompt.md#L9 "支持文章应从问题和使用场景展开，并按功能命名、审慎使用表格或流程图的说明。")

<a id="citation_contract"></a>
## 就近引用与不确定事项

正文采用 Markdown，并把证据标签放在所支持的句子或段落末尾，使移除标签后语句仍然通顺。材料引用必须使用完整键和真实行号，精确引文由宿主从固定材料复制；标签面向人阅读，理由则说明证据支持了哪项论断。无法确认、背景不足或需要选择的事项进入结构化 questions，而不能用含糊追问掩盖。参考 [引用与提问合同 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/prompt.md#L5 "支持引用必须就近出现、使用固定材料范围，以及不确定事项应结构化记录的要求。")

这些内容规定了期望输出与引用方式，但材料没有给出执行器、校验器或实际运行结果，因此应理解为角色配置，而非已经落地并验证的实现事实。延伸阅读：[证据标签表达 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/prompt.md#L15 "补充说明证据标签的句末位置、可读名称和最小引用范围；该规范本身未提供运行实现证据。")
