# docs-repo-review · 模块理解

docs/repo-review 通过人工维护的关联清单，把代码符号与设计意图、需求、研究资料和测试锚点连接起来，为仓库评审提供可审计的关系种子；清单区分 confirmed 与 candidate，但不等同于当前提交已经过实时验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-governance"></a>
## 作用与治理原则

该模块的核心职责是维护可审计的“代码—意图—依据”关系，而不是根据代码文本自动猜测事实。每项关联应点名代码路径与符号，并连接真实需求、决策或研究资料及具体测试；缺少文档和测试锚点时不得标为 confirmed，词面相似度也不能自动促成确认。[人工关联清单治理说明 ↗](../../../docs/repo-review/associations.json#L1 "支持清单由人工维护、confirmed 必须具有具体文档与测试锚点，以及词面相似度不得自动提升关系的论断。") 这使首次阅读者能够追溯实现为何存在、受何种约束以及预期如何验证。

<a id="coverage-and-flow"></a>
## 覆盖范围与同步关系

清单覆盖助手运行时、任务治理、模型适配、知识门控、学习流水线、检索、飞书接入、会话路由、仓库同步和数据库迁移等环节。以主助手运行时为例，条目把会话路由、检索注入、任务治理、多轮回指及取消或超时处理连接到需求、设计资料与测试名称，形成从实现入口到验证依据的追踪链。[主助手运行时关联 ↗](../../../docs/repo-review/associations.json#L5 "展示代码路径和符号如何连接设计意图、需求、决策、研究资料、测试与确认状态。") repo-review 同步条目则说明来源以路径区分身份、revision 采用追加方式，内容哈希用于变基检测，扫描后再由人工关联清单构建关系。[仓库评审增量同步关联 ↗](../../../docs/repo-review/associations.json#L289 "支持路径来源身份、revision 追加、内容哈希用途，以及扫描后由人工清单构建关系的流程说明。") 因此该文件是同步图谱的治理输入，并不直接执行这些业务能力。

<a id="progress-and-limits"></a>
## 状态、进展与限制

confirmed 表示维护者为条目登记了具体锚点和证据摘要，不能替代针对当前仓库提交实际执行测试或重新核对文档。清单也明确保留未完成能力：来源刷新目前只记录受影响记忆，随后抛出 `NOT_IMPLEMENTED`，完整 consolidation 重跑仍为 candidate。[来源刷新候选能力 ↗](../../../docs/repo-review/associations.json#L171 "支持来源刷新当前仅记录影响后抛出未实现错误、完整重核验仍待实现的限制说明。") 先前关于“代码变化后必须重新解析 locator，且无法定位时应标为 missing”的结论缺少本材料支持，现已被替代；本材料只能确认人工清单参与扫描后的关系构建，以及相似度不得把关系静默提升为 confirmed。[人工关联清单治理说明 ↗](../../../docs/repo-review/associations.json#L1 "支持清单由人工维护、confirmed 必须具有具体文档与测试锚点，以及词面相似度不得自动提升关系的论断。")[仓库评审增量同步关联 ↗](../../../docs/repo-review/associations.json#L289 "支持路径来源身份、revision 追加、内容哈希用途，以及扫描后由人工清单构建关系的流程说明。")
