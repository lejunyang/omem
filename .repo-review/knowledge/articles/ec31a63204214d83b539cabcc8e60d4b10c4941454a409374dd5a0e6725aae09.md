# Lark 实时接入与卡片回调验收测试

该测试以临时数据库、加密凭据仓库和伪造消息、实时适配器，验收 Lark 长连接租约、群聊捕获、事件幂等、决策卡片安全校验及来源变化后的失效保护。它覆盖服务器内部业务语义，但不能替代真实 Lark 网络、SDK 重连、ACK 时序或卡片兼容性验收。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-fixtures"></a>
## 测试目标与夹具边界

每个用例创建隔离的 Store 和 32 字节密钥仓库，预置连接、版本、绑定及通知与决策目标，结束后关闭数据库并清理临时目录；消息发送和实时连接则由内存 Fake 记录调用。[隔离夹具、伪适配器与预置数据 ↗](../../../apps/server/tests/lark-realtime.test.ts#L31 "支持测试创建临时资源和内存伪实现，并预置连接、版本、绑定及通知与决策目标，界定其测试环境边界。") 因此，这组测试证明的是服务编排与持久化结果，而非真实 Lark API 或 WebSocket 行为。决策夹具还从固定证据构造高影响提案，确认其进入 `awaiting_decision` 并成功投递决策卡片。[高影响决策准备流程 ↗](../../../apps/server/tests/lark-realtime.test.ts#L198 "支持夹具从证据捕获、提案评估到决策卡片投递的准备过程。")

<a id="realtime-capture"></a>
## 实时连接与消息捕获

A-L08 验证同一连接仅有一个 worker 持有租约，首个 manager 停止后第二个才能接管，并覆盖配对码路由、连接状态历史和卡片事件归一化。[连接租约与状态验收 ↗](../../../apps/server/tests/lark-realtime.test.ts#L254 "支持单消费者租约、配对路由、连接状态记录、接管和事件归一化等断言。") A-L09 验证入群后启用监控、事件去重、冲突重放报错、自身消息忽略，以及发送者类型与观测时间保留。[群聊启用与消息捕获验收 ↗](../../../apps/server/tests/lark-realtime.test.ts#L366 "支持入群启用、事件去重与冲突检测、身份时间保留和自身消息忽略，不用于支撑退群行为。") A-L14 则验证机器人退群会立即禁用该群的全部目标，后续消息不再允许捕获；此前将退群行为归入 A-L09 的结论已由这一独立用例替代。[机器人退群后的捕获停用验收 ↗](../../../apps/server/tests/lark-realtime.test.ts#L632 "独立支持退群事件立即禁用群内全部目标，并使后续消息不再被捕获的结论。")

<a id="card-action-safety"></a>
## 决策卡片的幂等与防伪

卡片回调值要求协议、动作、nonce、提案摘要、过期时间和版本摘要满足严格结构，其中动作允许批准、拒绝或请求补充上下文。[卡片回调值协议 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L13 "说明卡片动作负载的字段、动作枚举、nonce、摘要和时间格式约束。") 测试伪造操作者、会话、消息及各关联字段，断言请求被拒且原待处理动作不会被消费。[伪造回调拒绝验收 ↗](../../../apps/server/tests/lark-realtime.test.ts#L517 "支持操作者、会话、消息、nonce、摘要、过期时间和版本摘要异常均不会消费合法动作。") 对重复或竞争操作，系统保证至多一次业务效果；若网页端已先行拒绝，卡片 worker 不创建任务，并按真实拒绝状态更新卡片。[重复与竞争决策验收 ↗](../../../apps/server/tests/lark-realtime.test.ts#L452 "支持重复入列幂等、单次任务创建，以及外部竞争决策后按真实状态回显。")

<a id="durability-staleness"></a>
## 持久化顺序、失效保护与未覆盖项

A-L12 以数据库触发器制造命令写入失败，确认事件保持可重投的 `received` 状态；故障解除后命令才进入 `queued`，且入列本身不会创建任务。[命令持久化失败恢复验收 ↗](../../../apps/server/tests/lark-realtime.test.ts#L563 "支持命令持久化先于确认、失败事件可重投，以及入列不等于业务应用。") A-L13 在命令入列后更新原始来源，执行阶段因依据变化而将决策标为 stale、更新卡片并阻止任务产生，体现应用前仍会重验依据。[来源变化后的陈旧决策验收 ↗](../../../apps/server/tests/lark-realtime.test.ts#L593 "支持执行前来源变化时拒绝应用、标记 stale、更新卡片且不创建任务。") 当前材料未覆盖真实 SDK、网络 ACK 时序、跨进程竞争以及 `request_context` 的完整业务效果。
