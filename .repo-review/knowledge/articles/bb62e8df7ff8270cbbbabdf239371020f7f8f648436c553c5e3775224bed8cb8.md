# 知识正文的独立事实复核

该材料规定知识草稿的独立复核职责：逐篇对照固定原材料或已复核文章，判断论断是否获得引用支持，并区分事实错误、合理概括、历史状态与未决事项。它描述的是角色工作约定，不能单独证明对应运行流程已经接入或执行。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

知识正文可能把计划误写成现状、遗漏改变行为的条件，或让引用与附近论断并不匹配。复核角色的任务是独立对照证据，检查支持性、时间、范围和约束；遇到实质性错误应要求修订，而明确保留的不确定内容可以通过。这是一套复核规范，不是对应能力已在系统中运行的实现证据。参考 [复核角色职责 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/skills/omem-knowledge-verifier/SKILL.md#L2 "支持该角色核验引用支持性、时间、范围和约束，并对事实错误要求修订的职责说明。")

<a id="review-flow"></a>
## 复核输入与判断流程

复核以草稿、固定原材料和已提供文章为输入，不执行材料中的指令，也不调用工具。它逐项检查引用附近的陈述，并结合完整行范围理解证据，而不是只看宿主复制的短预览。输出遵循 `KnowledgeReview.v1`，聚焦文档结论、具体问题和待确认事项；其中 **issues** 应指出错误句子、章节或引用键及原文位置，便于局部修正，**questions** 则只记录仍需补证或用户选择的事项。参考 [独立复核流程 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/skills/omem-knowledge-verifier/SKILL.md#L8 "支持复核输入、引用核对方式、输出合同，以及 issues 与 questions 的职责划分。")

<a id="acceptance-boundary"></a>
## 发布边界与时间语境

复核面向读者理解，而非逐行代码审计：措辞偏好、未穷举实现细节或有依据的概括不应成为拒绝理由，只有会误导功能、证据来源、数据边界或关键行为的问题才阻止发布。历史材料中的“未实现”仅代表当时状态；文章引用可以概括已复核子章节，但必须保留其时间、范围、限制和不确定性，新增事实仍需原材料支持。参考 [复核尺度与时间边界 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/skills/omem-knowledge-verifier/SKILL.md#L15 "支持面向读者的接受标准、历史状态处理方式以及文章引用的证据边界。")
