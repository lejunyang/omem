# 角色运行包的可信装载与工作区准备

RoleBundleRegistry 负责把版本化角色目录装载为可执行的 RoleBundle：校验角色清单和提示词，并检查输出契约与技能资产，生成稳定内容摘要，再把 native 技能安全复制到单次运行工作区。它是静态角色资产与 RoleRuntimeGateway 执行阶段之间的边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 把角色资产变成可执行配置

`RoleBundleRegistry` 读取角色目录中的 manifest、提示词模板和输出 schema，再载入技能内容，合成一个 `RoleBundle`。返回值同时带有源目录与 `bundleHash`，调用方可以据此创建隔离的运行目录。参考 [角色包结构 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L28 "支持 RoleBundle 的组成及其源目录和内容摘要字段。")

默认角色根目录指向内置角色资产，项目级技能则从单独的 `.agents/skills` 根目录读取。参考 [角色与项目技能默认目录 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L109 "支持内置角色资产和项目级技能的默认根目录说明。")

代表性调用可以写成 `registry.load("code-analyst", "1")`：输入是角色标识和版本，输出包含已解析的 manifest、拼接后的 prompt、输出 schema、技能列表及内容摘要。随后调用 `prepareWorkspace(bundle, base, profile, runId)`，才会把需要原生发现的技能放进本次运行目录。

<a id="load_flow"></a>
## 装载、校验与摘要流程

```mermaid
flowchart LR
  A[角色 ID 与版本] --> B[定位并解析 manifest]
  B --> C[读取提示词与输出 schema]
  C --> D[校验每个技能]
  D --> E[生成 RoleBundle 与 bundleHash]
```
参考 [角色清单入口校验 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L115 "支持角色和版本字符限制、目录约束、manifest 解析及身份一致性校验。") [提示词与输出契约 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L127 "支持提示词模板读取和输出 schema 名称一致性校验流程。") [技能资产完整性 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L139 "支持技能来源选择、重名拒绝、SKILL.md 名称和目录摘要校验。")

`load` 先限制角色 ID 和版本的字符集，再确认角色目录没有越出根目录。manifest 必须通过共享契约解析，且其中的角色 ID、版本和输出 schema 名称要与实际请求及 schema 的 `$id` 一致。技能按 `source` 选择角色内目录或项目技能目录；规范名不能重复，`SKILL.md` 的 frontmatter 名称必须吻合，整个技能目录的摘要也必须等于 manifest 声明值。最后，提示词模板按清单顺序用空行连接，`bundleHash` 覆盖 manifest、prompt、outputSchema 以及技能名、声明摘要和正文。参考 [角色包内容摘要 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L162 "支持提示词拼接、RoleBundle 返回结构和 bundleHash 覆盖字段的说明。")

<a id="boundaries"></a>
## 可移植摘要与工作区边界

目录摘要先按相对路径排序，并统一路径分隔符与 CRLF 换行，因此相同文本资产在 Windows 和 POSIX 环境中可得到相同 SHA-256；安装器元数据与 ignore 文件不参与摘要。目录遍历会拒绝符号链接。参考 [跨平台目录摘要 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L60 "支持文件排序、元数据排除、符号链接拒绝、路径与换行归一化及 SHA-256 输出。")

单文件读取同样拒绝符号链接，解析后的真实路径也必须留在允许的根目录内。参考 [安全单文件读取 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L42 "支持单文件读取时的路径边界、真实路径检查与符号链接拒绝。")

`prepareWorkspace` 使用 `base/roles/<bundleHash>/<runId>` 隔离每次执行。创建工作区时，`mkdirSync` 接收 `mode: 0o700`；这不是对已有目录无条件重设权限，新建目录的实际权限还会受进程 umask 影响。它只复制 `load_mode` 为 `native` 的技能。native 技能要求 ACP transport；其他 transport 会直接报错。参考 [原生技能工作区 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L182 "支持工作区命名、创建 mode、native 技能筛选、ACP 限制和复制位置。")

复制采用幂等策略：目标文件已存在且字节一致时跳过，不一致时抛出内容冲突，避免复用工作区时静默覆盖。参考 [复制冲突保护 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L96 "支持目标内容一致时跳过、不一致时抛出冲突的复制策略。")
