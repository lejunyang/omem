# 角色运行包的安全加载与工作区准备

该模块将磁盘中的角色清单、提示词、输出 Schema 与技能目录校验并组装为可复现的 RoleBundle，再为 ACP 原生技能创建隔离工作区。路径安全结论需精确限定：实现拒绝候选文件本身及递归枚举项中的符号链接，并拒绝真实路径逃出根目录，但不能据此断言所有根内中间目录符号链接都被禁止。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-boundary"></a>
## 职责与路径安全边界

角色资产路径来自清单，因此加载前先检查解析后的候选路径是否位于角色根目录且真实存在；随后解析真实路径，拒绝真实路径越界以及候选文件本身为符号链接的情况。递归枚举技能目录时，遇到枚举项为符号链接也会立即失败。[候选文件与真实路径校验 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L41 "支持候选路径存在性、根目录归属、候选文件符号链接检查及真实路径越界拒绝，并用于限定中间目录符号链接的结论。") [技能目录递归枚举 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L59 "支持递归枚举会拒绝其直接遇到的符号链接目录项，并按相对路径稳定排序。")

这取代了“所有经过符号链接的资产都会被拒绝”的宽泛结论：若路径经过一个指向根目录内部的中间目录符号链接，而最终候选文件本身不是链接，现有代码没有明确拒绝该情形。能够确认的边界仅是候选文件、递归目录项和 realpath 后越界路径。

<a id="load-and-identity"></a>
## 加载、校验与稳定身份

`load` 限制角色标识和版本字符集，确认目标目录仍在注册表根目录内，再解析清单并核对清单身份。随后读取提示词和输出 Schema，检查 Schema 名称；技能还要通过名称去重、目录存在性、`SKILL.md` frontmatter 以及目录摘要校验，任一步失败都会中止构造。[角色入口与清单身份检查 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L105 "支持角色标识、版本、目录归属以及清单身份一致性的加载前校验。") [提示词、输出合同与技能校验 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L120 "支持提示词和输出 Schema 的读取，以及技能去重、frontmatter 名称和目录摘要校验流程。")

技能摘要按排序后的相对路径和内容计算 SHA-256，并统一路径分隔符与 CRLF/LF，以降低跨平台检出差异。最终 `bundleHash` 汇总清单、提示词、Schema 和技能信息；其底层稳定摘要会递归排序对象键并忽略 `undefined`。[跨平台技能目录摘要 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L73 "支持路径分隔符与文本换行归一化后计算 SHA-256 的跨平台稳定性说明。") [稳定 JSON 摘要 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持最终摘要对对象键排序、过滤 undefined、递归规范化并计算 SHA-256。")

<a id="workspace-and-limits"></a>
## 工作区准备与实现限制

`prepareWorkspace` 以 `bundleHash` 和 `runId` 组成运行目录，并检查结果仍位于给定基目录。只有 `native` 技能会复制到 `.trae/skills`，且存在原生技能时要求 transport 为 ACP。复制遇到同名文件会比较原始字节：一致则复用，不一致则报冲突，避免静默覆盖运行现场。[冲突检测式目录复制 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L92 "支持目标文件相同时复用、字节不同时拒绝覆盖的工作区复制行为。") [原生技能工作区准备 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L170 "支持工作区路径组成、基目录约束、ACP transport 要求及原生技能复制位置。")

该流程使用同步文件系统 API，材料中未见文件数量、体积、递归深度或工作区清理策略。摘要的换行归一化只影响身份校验，复制仍保留源文件字节；此外，当前材料没有测试与上层调用代码，不能确认安全边界的自动化覆盖、失败传播方式或 `runId` 来源。

<a id="module-relations"></a>
## 模块依赖与证据范围

模块直接从共享 contracts 包取得角色清单解析器及 `AgentProfile`、`RoleManifest` 类型，并从存储层取得 `stableDigest`，因此角色资产格式、transport 信息和 bundle 身份计算分别依赖这两个模块。[角色合同与摘要依赖 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L20 "支持该模块直接依赖共享角色合同解析器、相关类型和存储层稳定摘要函数。") 现有证据只支持这些直接导入与本文件内调用，不能进一步推断注册表由任务队列、HTTP 路由还是其他 Agent 启动器驱动。
