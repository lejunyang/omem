# 提取角色的提案批次合同

该文件定义 ProposalBatch.v1：顶层包含作业和角色身份、观察、提案及弃权；每项提案描述知识类型、操作、证据、不确定性、版本预期和来源。多个内部对象仅约束为普通对象，语义细节仍依赖其他合同或运行时验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="batch-envelope"></a>
## 批次信封与角色绑定

合同采用封闭顶层对象，要求版本、作业标识、角色标识、观察、提案和弃权全部存在；版本固定为 1，角色固定为 `extractor`。[提案批次顶层结构 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L1 "支持顶层封闭性、必填字段、版本和角色绑定的说明。") 观察和弃权只被约束为数组，当前文件没有进一步规定其元素结构，因此不能从这里推断观察或弃权的标准字段。

<a id="proposal-model"></a>
## 提案类型与变更操作

每项提案同样禁止额外字段，并要求提案标识、知识类型、操作、范围、正文、证据、不确定性、理由、预期版本和来源。知识类型限定为任务、主张、事件和流程，操作限定为创建、更新和取代。[提案必填字段与枚举 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L21 "支持提案封闭结构、知识类型及变更操作范围的说明。") 这说明输出是待处理的变更提案，而不是已经写入知识库的事实。

<a id="evidence-concurrency"></a>
## 证据、不确定性与并发信息

提案必须至少含一项证据，同时显式携带不确定性、理由、预期版本和来源；可选目标标识允许字符串或空值。[提案证据与版本字段 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L44 "支持证据最小数量、不确定性、预期版本、来源和可选目标标识的说明。") 这些字段为证据追溯和更新冲突处理预留位置，但 `scope`、`body`、`expected_versions` 与 `origin` 仅声明为对象，没有在本文件中限定内部结构，也未展示提案后续验证或应用流程。
