# 提取器输出合同：观察、提案与弃权

该 JSON Schema 定义提取器角色的版本 1 输出合同：批次携带任务与角色身份，并将结果分成观察、四类记忆变更提案和弃权。合同严格限定作用域、证据定位、版本预期与派生来源，但不能单独证明提取、复核或应用已经成功执行。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="batch-contract"></a>
## 批次结构与观察结果

该合同的顶层对象必须包含版本、任务与角色标识，以及 `observations`、`proposals`、`abstentions` 三类结果集合，并禁止额外字段；它约束的是角色输出形状，而非一次任务已经成功完成。[顶层批次必填字段 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L647 "支持顶层必须包含版本、任务与角色标识以及三类结果集合，并禁止额外字段的描述。")

每条观察记录必须包含观察标识、可空主体、可空时间与意图、作用域、结果、至少一项证据及来源类型；结果限定为未知、部分成功、成功或失败。[观察记录完整结构 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L23 "支持观察记录的主体、时间、意图、作用域、结果、证据、来源类型及其必填关系。") 作用域要求始终给出工作区，项目和主题字段也必须出现但允许为空，因此能表达个人或项目上下文，却不能据此推断租户权限隔离已经实现。[观察作用域定义 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L657 "支持工作区、项目和主题字段的必填性以及后两者允许为空的边界。")

<a id="proposal-variants"></a>
## 提案类型与变更语义

提案是以 `kind` 区分的联合结构，覆盖任务、主张、事件和流程。四个分支都把版本、提案标识、操作、作用域、证据、不确定项、理由、预期版本、来源、类型和正文列为必填，但 `target_id` 均未进入必填列表。[任务提案必填字段 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L274 "支持任务分支共享字段均为必填而 target_id 未列入必填列表的判断。")[主张提案必填字段 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L373 "支持主张分支共享字段均为必填而 target_id 未列入必填列表的判断。")[事件提案必填字段 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L470 "支持事件分支共享字段均为必填而 target_id 未列入必填列表的判断。")[流程提案必填字段 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L588 "支持流程分支共享字段均为必填而 target_id 未列入必填列表的判断。") 操作只允许创建、更新或取代；证据至少一项，预期版本是名称到正整数版本号的映射。[提案操作与公共约束 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L829 "支持三种操作枚举、至少一项证据、不确定项、理由和预期版本映射的说明。") 来源对象还必须记录任务、角色包，并把产物类型固定为 `derived`。[派生来源标识 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L880 "支持来源必须记录任务、角色包并固定标记为派生产物的论断。")

不同正文承载不同语义：任务记录负责人、期限和下一步，并定义了一个未被正文必填列表纳入的跟进对象；主张记录陈述、归因及有效期；事件记录触发、动作、验证引用与结果；流程记录触发条件、前置条件、步骤、验证、反例和不适用情形。[四类提案正文 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L150 "支持任务、主张、事件和流程正文的差异，并显示任务 follow_up 已定义但未进入正文必填列表。") 这替代了先前“所有已定义正文属性均必填”的宽泛理解，也仍不能证明提案已通过独立复核或被成功应用。

<a id="evidence-and-abstention"></a>
## 证据可追溯与拒绝生成

证据支持文本和图像两种形态。文本证据绑定片段修订、来源修订、精确引文及 Unicode 码点范围；图像证据绑定资源哈希、可选归一化区域和观察描述，并固定标记为推断。[文本与图像证据 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L697 "支持两类证据的修订标识、精确文本定位、资源哈希、区域和推断标记说明。") 这些字段为回到固定材料提供定位基础，但引用对论断的语义支持仍需另行核验。

当材料没有持久价值、证据不足、身份或范围含糊、包含不安全指令，或与既有内容重复时，角色可以输出弃权记录，并附原因细节与证据标识。[弃权原因合同 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L606 "支持角色因价值、证据、身份、范围、安全或重复问题拒绝生成提案。") 因而该合同既允许提出结构化变更，也允许在依据不足时明确不生成提案。
