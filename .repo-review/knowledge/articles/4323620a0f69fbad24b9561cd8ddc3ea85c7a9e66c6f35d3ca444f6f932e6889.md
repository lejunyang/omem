# Vitest 测试配置

该文件集中定义仓库的 Vitest 测试发现范围、单例超时和执行环境，将服务端、Web 与共享 UI 包的测试纳入同一次测试运行。配置本身不包含覆盖率、初始化脚本、浏览器模拟或项目拆分设置。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-scope"></a>
## 作用与测试范围

该配置通过 Vitest 的 `defineConfig` 导出统一测试设置，是测试命令发现用例的入口。`include` 仅匹配三类 `*.test.ts`：服务端测试、Web 源码内测试和共享 UI 包测试，因此其他目录、不同后缀或 JavaScript 测试不会由这里显式纳入。[测试文件匹配范围 ↗](../../../vitest.config.ts#L1 "支持该配置统一收集服务端、Web 和共享 UI 三处 TypeScript 测试，并说明显式匹配的目录及文件后缀边界。")

从目录关系看，它把 `apps/server`、`apps/web` 与 `packages/ui` 的测试聚合到同一配置中；但材料只证明文件匹配关系，不能据此确认三个模块之间存在运行时调用或依赖。

<a id="runtime-and-boundaries"></a>
## 执行约束与边界

每个测试的超时上限设为 15 秒，适合为可能包含异步流程的用例提供统一边界；超过该时限的测试将受 Vitest 超时机制约束。所有匹配用例统一使用 Node 环境执行。[超时与运行环境设置 ↗](../../../vitest.config.ts#L5 "支持单例超时为 15 秒且所有匹配测试默认运行于 Node 环境的论断。")

这一选择对服务端测试较自然，但 Web 与 UI 测试若依赖 DOM、浏览器 API 或真实页面交互，单凭此配置无法获得 `jsdom`、浏览器运行器或 Playwright 能力。文件也未声明 `setupFiles`、覆盖率、并发策略和环境按目录拆分，因此这些能力是否由命令行、其他配置或测试文件自行提供，现有材料无法确定。
