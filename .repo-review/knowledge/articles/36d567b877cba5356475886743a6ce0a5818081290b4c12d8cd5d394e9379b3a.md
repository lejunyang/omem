# 模块架构分析角色配置

该清单声明了模块架构分析角色的版本、结构化输出合同、提示词与技能包依赖，并为单次分析设置上下文、输出和引用节点上限。它描述的是角色运行配置，不能单独证明对应提示词、技能包或预算限制已被运行时正确加载和执行。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role_contract"></a>
## 角色定位与输出合同

这份清单把角色标识为 `module-architect`，版本为 `1`，并要求结果遵循 `CodeUnderstanding.v1`。因此，它的用途是让运行时选择模块架构分析角色，并以统一的结构化合同接收结果；`prompt.md` 则是该角色声明使用的提示模板。这里记录的是**配置意图**，仅凭清单不能确认模板加载、模型调用或结果校验已经实际发生。参考 [角色与输出声明 ↗](../../../packages/agent-runtime/roles/module-architect/1/manifest.json#L2 "支持角色标识、版本、结构化输出合同及提示模板均由该清单声明的论断。")

<a id="skill_and_budget"></a>
## 技能依赖与运行边界

角色依赖固定版本的 `omem-code-module-architect` 技能包，并通过摘要绑定具体制品，有助于避免同名技能更新后产生不可追溯的行为变化。一次任务允许最多 96,000 个上下文 token、24,000 个输出 token，并限制最多引用 200 个节点；这些参数共同约束分析规模和结果复杂度。它们仍属于声明值，是否被运行时强制执行、超限时如何失败，需要结合加载器与执行记录确认。参考 [技能包与预算边界 ↗](../../../packages/agent-runtime/roles/module-architect/1/manifest.json#L9 "支持技能制品绑定、上下文和输出预算以及引用节点上限的配置说明。")
