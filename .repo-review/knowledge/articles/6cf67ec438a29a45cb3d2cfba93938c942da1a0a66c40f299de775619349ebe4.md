# Repo-review 运行时数据迁移与启动隔离测试

验证默认启动忽略旧数据库，而显式种子流程可首次备份旧快照与状态到运行时目录，并保证幂等、失败清理和旧文件不变。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="default-startup"></a>
## 默认启动与旧数据隔离

测试构造不可用的旧数据库后直接创建 review Store，期望得到空的可重建运行时，同时原损坏文件内容保持不变。[默认启动忽略损坏旧库 ↗](../../../apps/server/tests/review-runtime-seed.test.ts#L97 "支持默认创建运行时 Store 不读取不可用旧库，并保持旧文件原样。") 这表明默认启动不会读取或修复历史 `.repo-review/data`，旧数据也不会因新运行时初始化而被覆盖。该行为与显式导入路径分离：它保障启动安全，但不会自动恢复旧知识。

<a id="first-seed"></a>
## 首次种子复制与状态投影

显式种子流程以包含 source、revision、fragment 和旧同步状态的快照为输入。首次执行后，运行时数据库存在且关键表行数保持一致，旧同步标记被投影到新状态目录；与此同时，旧数据库和旧状态文件的摘要不变。[首次备份与状态投影 ↗](../../../apps/server/tests/review-runtime-seed.test.ts#L108 "支持数据库行数和状态文件被复制到运行时目录，同时旧快照保持不变。") 因而迁移采用复制并保留来源的策略，而非原地移动或改写。

<a id="retry-safety"></a>
## 幂等、空启动与失败恢复

运行时数据库一旦存在，第二次种子调用不会重新复制；测试写入 marker 后仍能读到它，证明已有运行时状态未被重置。[重复种子的幂等性 ↗](../../../apps/server/tests/review-runtime-seed.test.ts#L137 "支持第二次调用不会覆盖已修改的运行时数据库。") 没有旧快照时，流程不会凭空创建数据库。对于损坏旧库，种子会抛错并删除部分目标，使后续仍可重试，同时旧文件摘要保持不变。[新启动与失败清理 ↗](../../../apps/server/tests/review-runtime-seed.test.ts#L159 "支持无旧快照时不创建数据库，以及损坏快照失败后删除部分目标并保留旧文件。") 本文件验证本地复制一致性与清理边界，但未覆盖超大数据库、进程中断或并发种子调用。
