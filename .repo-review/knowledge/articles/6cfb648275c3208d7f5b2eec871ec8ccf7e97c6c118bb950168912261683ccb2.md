# 个人知识库入口与递归证据阅读

该组件把知识首页、URL 路由和递归引用抽屉组合为个人知识库入口，使读者可以选择文章、沿引用继续查看知识或原始材料，并通过地址栏恢复阅读路径。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 统一知识浏览与证据追溯入口

`PersonalKnowledge` 是个人知识库页面的装配层：它保存当前文章键，向 `KnowledgeHome` 提供知识接口前缀，并接收首页发出的文章选择与证据导航事件。首页组件明确以 `selectedKey` 为输入，并通过 `select`、`navigate` 两类事件把用户操作交回父层，因此该入口负责页面级状态和导航协调，而非文章内容本身。参考 [个人知识页装配 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L2 "支持该组件持有页面选择状态、引入首页与证据帧组件并协调导航的说明。")、[首页交互合同 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L10 "说明 KnowledgeHome 接收选中键，并通过 select 与 navigate 事件将操作交给父组件。")

<a id="route-trail"></a>
## 把阅读位置写入地址并恢复

选择文章后，组件把当前文章和证据栈编码进 `location.hash`；没有选中文章时回到 `#/knowledge`。证据层数超过 `MAX_TRAIL` 时不会继续保存完整链接，但已有阅读状态仍保留，并向用户显示提示。参考 [阅读地址保存 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L8 "支持空选择路由、文章与证据栈编码，以及路径过长时仅提示而不影响当前阅读的边界行为。")

恢复时只处理 `#/knowledge/` 路由，将其转换为共享模块路由格式后解析；恢复出的轨迹还会过滤为 `knowledge`、`citation`、`source` 三种受支持帧，并把最后一帧设为当前位置。组件在挂载期间监听 `hashchange`，卸载时移除监听。参考 [阅读路径恢复 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L17 "支持知识路由解析、帧类型过滤、当前位置恢复和 hashchange 生命周期管理的说明。")

<a id="drawer-flow"></a>
## 递归引用抽屉如何工作

页面正文始终由 `KnowledgeHome` 承载；证据导航则进入共享的 `useEvidenceTrail`，再由 `OmTrailDrawer` 提供返回、跳转、关闭、循环提示和焦点归还。抽屉内部通过 `KnowledgeFrame` 展示当前帧，并用 `KeepAlive` 保留已打开内容的组件状态；内容加载完成后，临时的“正在读取引用…”会被真实标题替换。参考 [证据抽屉组合 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L28 "支持首页与抽屉并存、当前证据帧渲染、导航事件传递和加载后更新标题的流程。")

`KnowledgeFrame` 遇到引用帧时，会根据文章、修订和引用标识请求固定引用；切换帧后仅接纳当前一代请求的结果，成功时更新引用数据与标题，失败时记录错误。参考 [固定引用请求 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L12 "支持引用帧根据解析出的标识请求固定引用，并通过请求代次避免旧结果覆盖当前帧的说明。")

解析期间页面显示等待提示；引用不可用或无法操作时给出可读原因，成功解析后则按目标类型打开文章章节或原始材料行段。由此可以看出入口与证据展示组件之间的主流程，但具体接口响应、滚动恢复和循环判定规则不在这些材料中。参考 [引用结果分派 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L23 "支持解析等待、错误与不可操作提示，以及成功后打开文章章节或材料行段的说明。")
