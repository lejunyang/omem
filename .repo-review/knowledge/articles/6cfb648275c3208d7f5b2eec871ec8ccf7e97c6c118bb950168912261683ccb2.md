# 个人知识页与共享证据 Trail 的装配

PersonalKnowledge 以薄装配层连接知识首页、活动知识帧和共享 Trail 抽屉；现有材料能确认数据与事件接线，但不足以证明共享组件的全部运行时交互。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="composition"></a>
## 页面装配与连续阅读路径

该文件的脚本和模板只承担组件装配：KnowledgeHome 与活动 KnowledgeFrame 都接收 `/api/knowledge` 前缀，两者产生的导航都交给共享 `push`。因此，从首页进入正文后，再沿引用或原始材料继续阅读，会使用同一帧栈入口；文件本身未声明额外的数据请求或解析逻辑。[个人知识页完整装配 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L1 "完整文件支持该组件仅导入并装配首页、知识帧和共享 Trail，同时证明两处统一使用知识 API 前缀和 push 导航。")

帧内具体内容由 KnowledgeFrame 分派：知识帧进入正文组件，原始材料帧进入材料组件，引用帧则请求固定引用并依据解析结果打开文章或材料；不可操作或无法解析的引用会显示原因。[知识帧内容分派 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L20 "说明知识、原始材料与固定引用由 KnowledgeFrame 分别处理，并展示不可操作引用的原因。")

<a id="trail"></a>
## Trail 接线合同与证据边界

`useEvidenceTrail` 在此提供帧集合、当前位置、开关状态、循环位置、焦点目标、活动帧及 push、back、jump、close 操作。[共享 Trail 状态来源 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L2 "界定 composable 向页面提供的状态和操作，为区分抽屉属性与活动帧插槽状态提供依据。") 抽屉实际接收 open、frames、current、loopAt，并把 trigger 配置为 `return-focus-to`；active 用于默认插槽中的 KnowledgeFrame，而不是作为抽屉属性传入。

close、back、jump 和清除循环状态分别绑定到抽屉事件。活动帧触发 `loaded` 后，`active.title` 会直接更新为事件载荷。[抽屉事件与活动帧接线 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L9 "支持抽屉属性、焦点目标配置、事件处理及 loaded 事件载荷写入活动帧标题的说明。") 这些代码证明了状态和事件接线，但不能单独确认 URL 深链、滚动恢复、Esc 退层、循环栈处理或关闭后的实际焦点归还。
