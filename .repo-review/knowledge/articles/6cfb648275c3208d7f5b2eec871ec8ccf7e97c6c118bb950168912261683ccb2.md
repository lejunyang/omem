# 个人知识页与共享证据 Trail 的装配

以薄装配层连接知识首页、活动阅读帧和共享 Trail 抽屉；现有材料证明具体接线，但不证明共享组件的全部运行时行为。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="composition"></a>
## 页面装配与连续导航

PersonalKnowledge 将 `/api/knowledge` 前缀分别传给 KnowledgeHome 和 KnowledgeFrame。首页与活动帧产生的 navigate 事件都接入 `push`，因此两处入口沿同一 Trail 状态继续阅读；活动帧触发 loaded 后，`active.title` 被更新为该事件载荷。[首页与活动帧装配 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L7 "支持统一 API 前缀、两处 navigate 接入 push，以及 loaded 事件载荷更新活动帧标题。")

<a id="trail"></a>
## Trail 状态与抽屉接线

页面从 `useEvidenceTrail` 取得帧栈、当前位置、打开状态、循环位置、焦点目标、活动帧以及 push、back、jump、close 操作。抽屉实际接收 open、frames、current、loopAt 和 `return-focus-to`，并连接关闭、返回、跳转和清除循环事件；active 只用于插槽内决定是否渲染 KnowledgeFrame。[共享 Trail 状态来源 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L1 "支持 composable 实际返回的状态与导航操作。")[抽屉属性与事件接线 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L9 "支持抽屉接收的属性、焦点目标配置、事件处理及活动帧插槽用法。")

这些代码能证明配置与事件接线，但不能单独确认 URL 深链、滚动恢复、Esc 退层、循环处理或关闭后实际焦点归还。

<a id="responsibility"></a>
## 组件责任边界

该文件完整内容只有共享组件导入、Trail 解构和模板装配，没有在本层定义知识请求、帧解析或内容渲染逻辑。具体正文、引用和原文如何分派由 KnowledgeFrame 承担，PersonalKnowledge 的可见责任是组织首页与抽屉阅读入口。[个人知识页完整实现 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L1 "完整文件支持将本层责任限定为导入、状态解构和模板组合，避免把下层请求逻辑归于此组件。")
