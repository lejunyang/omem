# 固定修订的父级阅读上下文

readParentContext 将原始材料检索命中的局部片段扩展为同一固定修订中的最小外层结构，并在扩展前校验材料身份；若提供 `q.visible`，还会校验整段可见性。它保留原命中的评分等字段，只替换正文、来源锚点、引用和标题路径；无法安全扩展时返回 undefined。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为什么需要父级上下文

`readParentContext(db, hit, q)` 解决局部检索命中缺少上下文的问题：命中可能只包含一句规则或一段实现，而阅读与后续判断还需要它所在的完整章节或代码结构。扩展范围限定在同一个固定原始材料修订中，并选取严格包住命中范围的最小结构；父结构只补充阅读内容，不参与检索计分。参考 [阅读上下文定位 ↗](../../../apps/server/src/retrieval/reading-context.ts#L7 "说明该函数只补充同一固定来源的最小外层结构，并明确父结构不是新的搜索计分。")

<a id="flow"></a>
## 从命中片段到可读结构

函数先接受数据库、检索命中和查询。它只处理 `source` 目标，再按 `revisionId` 读取修订，将数据库行还原为材料，并核对材料 `key` 与摘要；任一步失败都停止扩展。参考 [固定修订校验 ↗](../../../apps/server/src/retrieval/reading-context.ts#L14 "支持仅处理 source 目标、按修订读取材料并核对 key 与 digest 的流程和提前返回条件。")

```mermaid
flowchart LR
  A[source 命中] --> B[读取固定修订并核对身份]
  B --> C[寻找最小外层结构]
  C --> D[检查覆盖片段可见性]
  D --> E[生成新锚点与正文]
```

层级筛选会排除整篇文档节点，要求候选节点覆盖命中且至少向前或向后多包一行，再按跨度升序取第一个，因此结果是严格更大的最小结构。参考 [最小外层结构选择 ↗](../../../apps/server/src/retrieval/reading-context.ts#L29 "支持排除文档节点、要求严格包含命中范围并按跨度选择最小节点的论断。")

<a id="example_and_limits"></a>
## 代表性调用与安全边界

**教学示例：** 查询命中退款说明中的“提交入口”片段后，调用方可传入该命中和查询；函数会返回包含条件与入口的最小章节。若提供 `q.visible`，扩展章节所交叠的全部片段都必须通过该函数；没有交叠片段，或其中任一片段不可见时，结果为 `undefined`，避免借父章节越过可见性边界。参考 [整段可见性检查 ↗](../../../apps/server/src/retrieval/reading-context.ts#L39 "支持父结构交叠片段必须全部可见，否则拒绝扩展的安全边界。")

成功时，函数按节点行号截取正文，生成覆盖该节点的新来源锚点，并用它替换 `target` 和 `references`。返回值通过展开原命中保留其余字段；节点标题仅在标题路径末尾尚未出现时追加。参考 [扩展结果构造 ↗](../../../apps/server/src/retrieval/reading-context.ts#L47 "支持正文截取、新锚点替换、引用更新及标题路径去重追加的输出说明。")
