# 结构化数据的规范化摘要

递归排序普通对象键并移除对象属性中的 undefined，生成规范 JSON 后计算 SHA-256，使键插入顺序不影响摘要。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="canonicalization"></a>
## 规范化规则

`normalize` 对数组保持原次序并逐项递归；对非空对象读取可枚举项，删除值为 `undefined` 的属性，按键名排序后继续递归；其他值直接返回。随后 `canonicalJson` 调用 `JSON.stringify`，所以键插入顺序不同但结构和值相同的普通 JSON 对象会得到一致文本。[递归规范化实现 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持数组顺序保留、对象 undefined 属性过滤、键排序和递归处理规则。")

<a id="digest"></a>
## 摘要用途与输入边界

`stableDigest` 对规范 JSON 计算无密钥 SHA-256，并输出十六进制字符串，适合作为确定性内容指纹或幂等键的组成部分。此前“共享 Store 明确导入该函数”的调用关系说明已删除，因为所给材料只有该模块本身，不能证明具体调用方或实体用途。[稳定 SHA-256 摘要 ↗](../../../apps/server/src/storage/digest.ts#L15 "支持规范 JSON 经 SHA-256 生成十六进制摘要；不延伸推断未提供的调用关系。")

数组重排会改变摘要；对象属性中的 `undefined` 被移除，而数组中的 `undefined` 仍交由 JSON 序列化语义处理。函数签名接受 `unknown`，但没有循环检测，也未为 Date、Map、Set、BigInt、NaN 等特殊值定义独立规范，因此稳定性保证应限于无循环、可序列化的 JSON 型输入。[规范化输入边界 ↗](../../../apps/server/src/storage/digest.ts#L3 "对象与数组分支及最终 JSON.stringify 支持对 undefined、顺序和非 JSON 值限制的分析。")
