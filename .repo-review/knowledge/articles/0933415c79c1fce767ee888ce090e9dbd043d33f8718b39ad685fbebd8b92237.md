# 稳定 JSON 规范化与摘要生成

该模块递归整理数组与对象后尝试进行 JSON 序列化，并以成功得到的字符串计算 SHA-256 摘要。对象键按 locale 顺序排列，值为 undefined 的对象属性被移除，数组次序保留；部分根值不能产生字符串，循环、BigInt 与特殊对象也存在边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 作用与背景

模块提供 `canonicalJson` 与 `stableDigest`：前者规范化输入后调用 `JSON.stringify`，后者仅在该调用得到可供 `hash.update` 接收的结果时，生成 SHA-256 十六进制摘要。这里替代先前笼统的“总会生成 JSON 文本及摘要”结论：根值为 `undefined`、函数或 Symbol 时，规范化会原样返回，而 `JSON.stringify` 可能返回 `undefined`；该结果继续传给摘要入口还可能触发类型错误。[规范序列化与摘要入口 ↗](../../../apps/server/src/storage/digest.ts#L12 "支持 canonicalJson 调用 JSON.stringify、stableDigest 将其结果直接传给 SHA-256 更新入口，并据此说明根级不可序列化值的返回边界。")

<a id="normalization"></a>
## 规范化流程

数组保持元素次序并逐项递归；非空对象通过 `Object.entries` 读取可枚举自有属性，先移除值严格等于 `undefined` 的属性，再按键名的 locale 顺序排序，递归处理属性值并由 `Object.fromEntries` 重建。其他值原样返回。因此对象属性插入顺序通常不会影响规范结果，但数组换序仍会改变序列化结果。[递归规范化规则 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持数组保序递归、对象属性过滤与排序、递归重建以及其他值原样返回的流程说明。")

<a id="boundaries"></a>
## 边界、替代结论与影响

`stableDigest` 直接依赖 `canonicalJson` 的返回值。先前“规范化规则变化就会改变摘要”的结论应收窄为：规则调整只有在改变某个输入最终得到的字符串时，才会改变其摘要；材料尚未说明摘要是否承担持久化身份、索引、缓存或去重职责。[摘要对序列化结果的依赖 ↗](../../../apps/server/src/storage/digest.ts#L15 "支持 stableDigest 直接消费 canonicalJson 返回值，并限定摘要变化取决于最终规范字符串是否变化。")

对象分支并未限定普通对象，只沿可枚举自有属性递归并重建普通对象，因而 Date、Map、Set 或依赖原型与 `toJSON` 的实例可能丢失原语义。循环仅在被实际遍历的路径上导致递归问题；BigInt 等 JSON 不支持的值也未被显式处理。根级 `undefined`、函数和 Symbol 不会形成 JSON 字符串，这是本次对旧正文的重要补充。[对象重建与值处理边界 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持对象仅按可枚举自有属性重建、其他值原样返回，以及据此识别特殊对象、循环和 JSON 不支持值的处理限制。")
