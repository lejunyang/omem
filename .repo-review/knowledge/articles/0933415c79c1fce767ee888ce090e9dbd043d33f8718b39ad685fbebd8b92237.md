# 结构化数据的稳定摘要

先递归规范化对象键顺序和 undefined 字段，再以规范 JSON 计算 SHA-256，使逻辑等价的结构得到一致摘要。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="normalization"></a>
## 规范化规则

该模块解决普通 `JSON.stringify` 受对象属性插入顺序影响的问题。`normalize` 递归处理数组元素；对普通对象过滤值为 `undefined` 的属性、按键名字典序排序，再递归规范化各值。数组顺序不会被重排，因此列表的语义次序仍会影响结果。[递归规范化实现 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持对象去除 undefined、排序键以及数组保持次序的规则说明。")

<a id="digest-and-usage"></a>
## 摘要生成与模块关系

`canonicalJson` 对规范化结果序列化，`stableDigest` 再计算十六进制 SHA-256。仓储模块直接导入它，用于飞书卡片 payload 的摘要；这让对象键顺序变化不会制造不同的投递摘要。[规范 JSON 与 SHA-256 ↗](../../../apps/server/src/storage/digest.ts#L15 "支持摘要的具体生成算法。") [投递负载摘要调用 ↗](../../../apps/server/src/storage/repository.ts#L326 "支持仓储模块使用 stableDigest 计算飞书 payload 摘要的关系。")

边界上，该实现仍受 JSON 数据模型约束：循环引用、`BigInt` 等不可序列化值会抛错；对象原型、`Map`、`Set` 或类实例也没有专门的语义编码。材料中没有测试文件，无法确认这些输入是被禁止、接受还是应另行规范化。[JSON 序列化边界 ↗](../../../apps/server/src/storage/digest.ts#L15 "支持实现最终依赖 JSON.stringify、未提供额外类型编码的限制判断。")
