# 结构化数据的规范化摘要

通过递归排序对象键并过滤 undefined 属性生成规范 JSON，再计算 SHA-256，使普通 JSON 对象不受属性插入顺序影响。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="canonicalization"></a>
## 规范化与摘要流程

该模块解决对象属性插入顺序不同导致序列化文本不稳定的问题。`normalize` 保留数组次序并递归处理元素；对非空对象过滤值为 `undefined` 的属性、按键名排序，再递归规范化属性值，其他值原样返回。`canonicalJson` 随后执行 `JSON.stringify`，所以键顺序不同但结构和值相同的普通 JSON 对象可得到相同文本。[递归规范化规则 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持数组顺序保留、对象键排序、undefined 属性过滤及非 JSON 值边界的分析。")

`stableDigest` 对该规范文本计算无密钥 SHA-256，并输出十六进制摘要。共享 `Store` 确实导入了此函数，但给定的 Store 片段没有展示调用位置，因而只能确认依赖关系，不能断言它具体用于哪个实体或流程。[稳定 SHA-256 摘要 ↗](../../../apps/server/src/storage/digest.ts#L15 "支持规范 JSON 经无密钥 SHA-256 生成十六进制摘要及其安全语义边界。")[共享 Store 的摘要依赖 ↗](../../../apps/server/src/store.ts#L20 "直接证明共享 Store 导入 stableDigest，同时也表明给定片段未展示具体调用用途。")

<a id="boundaries"></a>
## 数据边界与安全语义

数组顺序被保留，因此元素重排会改变摘要；对象属性中的 `undefined` 被过滤，而数组中的 `undefined` 仍交给 JSON 序列化处理。函数签名接受 `unknown`，但未定义循环引用、Date、Map、Set、BigInt、NaN 等值的规范合同：部分值可能折叠为相同结构，部分则可能抛错。[递归规范化规则 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持数组顺序保留、对象键排序、undefined 属性过滤及非 JSON 值边界的分析。")

该函数没有密钥、实体类型标签或域分离。代码只能证明它生成稳定内容摘要，不能证明其适合认证、签名或跨实体防混淆；这些用途需由调用方合同另行限定。[稳定 SHA-256 摘要 ↗](../../../apps/server/src/storage/digest.ts#L15 "支持规范 JSON 经无密钥 SHA-256 生成十六进制摘要及其安全语义边界。")
