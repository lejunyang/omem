# 工作区依赖锁定与运行环境基线

该锁文件以 pnpm 9 格式固定根项目、Web 应用和共享 UI 包的依赖解析结果。它可用于复现安装环境并识别版本与平台约束，但只能证明依赖图存在，不能单独证明相关功能已接入或通过运行验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="workspace-layout"></a>
## 依赖如何在工作区中组织

这份锁文件用于把依赖声明解析为确定版本，减少不同机器安装时的结果漂移。工作区包含根项目、`apps/web` 和 `packages/ui` 三个导入单元；根项目集中声明服务端、协议与工程工具依赖，Web 应用则通过 `workspace:*` 链接共享的 `@omem/ui` 包。参考 [根项目依赖入口 ↗](../../../pnpm-lock.yaml#L1 "支持锁文件采用 9.0 格式、存在工作区导入单元，并说明根项目直接声明协议、服务端、模型与校验依赖。") [Web 与共享界面依赖 ↗](../../../pnpm-lock.yaml#L58 "支持 Web 应用通过工作区链接复用共享 UI 包，并说明两个界面单元锁定 Vue、Markdown、净化、高亮和 Mermaid 等依赖。")

这种结构表明界面能力以共享包复用，锁文件同时保留每个单元的直接依赖及其完整传递依赖。它描述的是**安装配置**，不能据此断言某项业务功能已经调用这些库或在实际环境中运行成功。

<a id="runtime-stack"></a>
## 运行时与界面依赖基线

根项目直接锁定 Fastify、静态资源插件、ACP SDK、Zod 和 Transformers，可确认这些组件进入了依赖图，但具体 HTTP 路由、Agent 交互和数据校验流程仍需代码或运行材料证明。参考 [根运行时依赖 ↗](../../../pnpm-lock.yaml#L10 "支持 Fastify、静态资源插件、ACP SDK、Transformers 与 Zod 已作为根项目直接依赖进入锁定图。")

Transformers 的解析链包含 Jinja、Node 与 Web 版 ONNX Runtime，以及 Sharp，说明本地模型相关依赖具备多种运行后端和图像处理基础。参考 [模型运行依赖链 ↗](../../../pnpm-lock.yaml#L2428 "支持 Transformers 解析到 Jinja、Node 与 Web 版 ONNX Runtime 以及 Sharp 的论断。") Web 应用及共享 UI 包采用 Vue，并锁定 Markdown 解析、代码高亮、内容净化与 Mermaid；这同样只代表具备依赖基础，不代表所有页面已经使用相应能力。参考 [Web 与共享界面依赖 ↗](../../../pnpm-lock.yaml#L58 "支持 Web 应用通过工作区链接复用共享 UI 包，并说明两个界面单元锁定 Vue、Markdown、净化、高亮和 Mermaid 等依赖。")

<a id="toolchain-constraints"></a>
## 构建测试工具与兼容边界

工程工具固定为 TypeScript 5.9.3、Vite 7.3.1、Vitest 3.2.4、Vue 类型检查和 Playwright 1.58.2，使安装时采用一致的构建、单元测试、类型检查与浏览器测试版本。参考 [工程工具锁定版本 ↗](../../../pnpm-lock.yaml#L29 "支持 Playwright、TypeScript、Vite、Vitest、Vue 编译器和 Vue 类型检查工具的直接锁定版本。")

其中 Vite 7.3.1 明确要求 Node.js `^20.19.0` 或 `>=22.12.0`；这是主要构建链的包级约束，但锁文件没有声明仓库正式支持的 Node.js 范围。参考 [Vite 的 Node.js 要求 ↗](../../../pnpm-lock.yaml#L2046 "支持 Vite 7.3.1 对 Node.js 版本的明确包级约束，并用于说明仓库级支持政策仍不能由锁文件确定。") Sharp 还通过可选依赖覆盖 macOS、Linux、Windows、WASM 及多种处理器组合，表示安装器可按平台选择二进制产物，并不等同于这些平台都经过项目级验证。参考 [Sharp 跨平台可选包 ↗](../../../pnpm-lock.yaml#L3890 "支持 Sharp 为多种操作系统、运行库和处理器提供可选二进制依赖，同时不把依赖覆盖误写为项目验证结论。")
