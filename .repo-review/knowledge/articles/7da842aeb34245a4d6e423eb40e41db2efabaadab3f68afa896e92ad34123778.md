# 隔离运行冻结质量样本并生成预测

该脚本使用实时 TraeX profile 逐项运行冻结质量样本，在独立临时 Store 中执行学习流水线，将 proposal 转换为结构化预测，并逐样本持久化以支持恢复。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="setup"></a>
## 冻结输入与断点续跑

命令要求冻结数据集标识，打开配置的 Store 并验证冻结状态，再选择可用的 `traex` 实时 profile。已有预测逐项通过 schema 解析，其 sampleId 构成跳过集合。处理上限默认取样本总数；环境变量能解析为数值时通过 `Math.max` 将下限设为 1，但非数字值会产生 `NaN`，当前没有显式拒绝。预测通过临时文件重命名原子替换，最终权限收紧为 `0600`。[冻结数据集与预测持久化 ↗](../../../scripts/quality-run.ts#L27 "支持冻结验证、实时 profile 选择、已有结果恢复、运行上限计算及原子持久化行为。")

<a id="isolated-run"></a>
## 逐样本隔离执行

每个未完成样本使用唯一临时目录和独立 Store，以人工来源捕获文本，并保存来源 URI、转发状态和时区等 provenance；其中 actor 类型与验证来源由 `actorVerified` 布尔值映射为固定值。[隔离样本与学习流水线 ↗](../../../scripts/quality-run.ts#L63 "支持每样本独立 Store、provenance 字段及 actorVerified 的固定映射、流水线执行和 proposal 状态筛选。") 随后构造 MemoryService 与 LearningPipeline，使用所选实时 profile drain 作业，只收集 applied、awaiting_decision 或 approved 状态的 proposal。这种隔离减少样本间状态污染，但仍依赖外部实时模型配置。

<a id="prediction"></a>
## 预测映射、用量与错误

有 proposal 时 disposition 为 `extract`，否则为 `abstain`；对象包含类型、归一化陈述和证据引文，任务还附带 owner 与期限字段，autoApply 由是否存在 applied proposal 决定。脚本汇总作业尝试中的输入、输出 token，并记录耗时。[预测对象与用量映射 ↗](../../../scripts/quality-run.ts#L114 "支持 proposal 到结构化预测、任务字段、自动应用标志、耗时和 token 用量的转换。") 单样本异常不会终止整批，而会生成 `needs_context`、空对象和截断错误信息；每轮关闭并删除临时 Store、持久化预测并输出进度。[失败降级与逐项清理 ↗](../../../scripts/quality-run.ts#L157 "支持异常统一转为 needs_context 预测、临时目录清理、逐项持久化和最终 Store 关闭。")
