# 知识发布、失效与证据回溯的集成测试

这组测试以临时 SQLite 数据库串联材料捕获、知识发布、引用校验、版本失效、产物恢复、问题行动和关键词检索，验证派生知识能够回到当前有效的原始证据，同时保留不可变历史。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 测试解决什么风险

该文件围绕 `Store`、`KnowledgeRepository`、知识产物读写与关键词检索建立临时数据库，模拟“捕获原文—发布知识—恢复或检索”的完整链路；每个用例结束后关闭数据库并清理目录，避免状态串扰。参考 [临时仓储测试环境 ↗](../../../apps/server/tests/knowledge-repository.test.ts#L11 "支持测试使用临时目录、Store、KnowledgeRepository 和捕获函数组成隔离集成环境的说明。")

引用校验确保每节正文含有内联引用、引用键已声明、声明的引用确实被使用，并检查材料行号范围；固定范围还会绑定原文引文。它不能判断引用是否在语义上支持附近论断，这项工作由独立模型角色完成。参考 [内联引用测试 ↗](../../../apps/server/tests/knowledge-repository.test.ts#L33 "支持精确引文绑定、缺失内联引用、未知引用和越界行号均受到检查的说明。") [引用结构校验规则 ↗](../../../apps/server/src/knowledge/repository.ts#L44 "说明校验器检查内联引用、引用使用情况与材料范围，同时明确语义正确性由独立模型角色检查。")

进入知识材料集合前，revision 还会经过来源过滤：标记为派生内容或由派生生产者生成的 revision 不会被转换成材料。参考 [派生材料过滤 ↗](../../../apps/server/src/knowledge/repository.ts#L12 "支持派生 revision 不会被转换为知识材料的说明。")

<a id="lifecycle"></a>
## 知识版本如何失效与恢复

子文章可以被上层文章按章节引用。当来源出现新内容并刷新后，子文章和依赖它的上层文章都会转为非当前状态；旧材料仍可按摘要解析，旧知识 revision 仍可读取，但依赖旧输入的产物不能再次作为当前知识发布。参考 [依赖失效与历史保留 ↗](../../../apps/server/tests/knowledge-repository.test.ts#L47 "支持来源更新使上下层知识失效、旧 revision 仍可解析且旧输入不能重新发布的说明。")

持久化用例把已评审产物写入文件，再在全新数据库中恢复。合法文件可以恢复，损坏的 JSON 会被拒绝且不会覆盖有效 revision。恢复后的调查问题可创建幂等任务；回答会形成原始输入 revision，并将问题标为已回答。参考 [产物恢复与问题行动 ↗](../../../apps/server/tests/knowledge-repository.test.ts#L62 "支持合法产物恢复、损坏文件隔离、任务幂等创建和回答状态变化的说明。")

<a id="retrieval"></a>
## 派生知识只做检索桥梁

文章标题中的关键词可以帮助找到其引用的原始 fragment，但返回结果仍是原始证据，而非文章正文。来源更新后，即使知识投影尚未刷新，旧关键词也不能召回已经过期的来源。参考 [知识辅助原证据检索 ↗](../../../apps/server/tests/knowledge-repository.test.ts#L82 "支持派生标题命中原始 fragment，以及来源更新后旧知识不再召回的说明。")

一个引用范围跨越多个段落时，知识关键词会召回范围覆盖的全部原始片段；而相同 external ID 分属 `file` 与 `manual` 载体时，材料键保持独立，避免不同来源被错误合并。参考 [跨段引用召回 ↗](../../../apps/server/tests/knowledge-repository.test.ts#L119 "支持引用范围跨越多个段落时返回所有相关原始 fragment 的说明。") [材料载体身份隔离 ↗](../../../apps/server/tests/knowledge-repository.test.ts#L98 "支持相同 external ID 在不同来源命名空间下仍生成不同材料键的说明。")

<a id="boundaries"></a>
## 状态收敛与当前覆盖边界

重复发布完全相同的产物不会新增通知；新 revision 删除旧问题时，旧问题会转为 `superseded`，并且只增加一次通知。这验证了顺序发布下的幂等行为和问题生命周期。参考 [通知幂等与问题退役 ↗](../../../apps/server/tests/knowledge-repository.test.ts#L104 "支持重复发布不通知、新 revision 退役旧问题并仅新增一次通知的说明。")

当前用例覆盖引用结构、依赖失效、文件恢复、问题行动、来源隔离及知识到原证据的回溯，但未直接验证并发发布、事务中途失败、后续文章删除被引用章节，以及时间范围、可见性和多候选排序的组合效果。检索入口虽提供时间、可见性与数量限制，仍需专门的行为测试确认这些条件如何共同作用。参考 [检索过滤入口 ↗](../../../apps/server/src/retrieval/keyword.ts#L53 "说明检索实现提供数量限制、时间范围与可见性过滤，从而界定当前测试尚未直接覆盖的组合行为。")
