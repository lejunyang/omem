# CorrectionProposal.v1 的顶层输出结构

该 JSON Schema 定义反馈纠正候选的封闭顶层对象，要求版本、纠正标识、目标、范围、停止使用内容、替代内容、证据、原因与来源。当前材料只对部分字段给出宽泛类型，因此能约束字段存在性，却不足以证明内部对象语义和证据定位得到严格验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="closed-contract"></a>
## 封闭对象与必需字段

Schema 使用 JSON Schema 2020-12，标识自身为 `CorrectionProposal.v1`，要求输出是对象且禁止未声明的顶层属性。九个字段均为必需项，覆盖版本、纠正目标与范围、被停止采用的内容、替代内容、证据、原因及来源。[纠正候选顶层合同 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/output.schema.json#L1 "支持 schema 版本、封闭顶层对象以及九个必需字段的说明。") 这与角色清单声明的输出合同相呼应，构成静态格式入口。

<a id="validation-depth"></a>
## 字段类型与校验深度限制

版本固定为 1；纠正标识、停止使用内容、替代内容和原因是字符串，目标、范围与来源仅被约束为对象，证据仅要求是至少含一项的数组。[纠正候选字段类型 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/output.schema.json#L17 "支持字段当前仅具基础类型和证据最小项数约束，并揭示嵌套校验深度有限。") 因此当前材料未显示这些嵌套结构的必需字段、引用定位格式、字符串最小长度或对象附加属性限制，不能据此认定语义级纠正合同完整。
