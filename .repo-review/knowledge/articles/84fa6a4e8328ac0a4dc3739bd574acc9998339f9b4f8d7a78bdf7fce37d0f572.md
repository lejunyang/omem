# TraeX 可选捕获 Hook 示例

这是版本 1 的 opt-in 配置模板，为用户提示提交、工具使用后和停止三个事件配置同一转发命令、5 秒超时及异步标志。模板尚含绝对路径占位符，也未规定字段范围、宿主调度语义和失败处理，因此不代表已经安装、授权或验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="intent"></a>
## 用途与启用边界

配置说明将该集成定义为 opt-in capture，并要求合并前审查字段和捕获范围。[可选捕获说明 ↗](../../../integrations/traex/hooks.example.json#L1 "支持该模板需由用户选择启用，并在合并前审查字段和捕获范围。") 因此它只是供用户选择的接入模板，不能证明配置已写入 TraeX、用户已经授权，或敏感字段、文件内容及工具结果已经完成最小化处理。实际启用属于独立外部集成，应先确定捕获边界并保留用户现有配置。

<a id="events"></a>
## 事件与命令配置

样例为 `UserPromptSubmit`、`PostToolUse` 和 `Stop` 配置相同的 command Hook：调用构建目录中的 `hook-forward.js`，设置 `timeout` 为 5 秒，并写入 `async:true`。[三个 Hook 事件配置 ↗](../../../integrations/traex/hooks.example.json#L4 "支持事件名称、转发命令、5 秒超时和异步标志；不扩张解释宿主的实际执行语义。") 材料只能证明这些字段存在，不能推导 TraeX 是否等待、如何调度异步任务或怎样呈现超时与失败。命令中的绝对路径仍是占位符，也没有证明目标机器上的 Node 与构建产物可用。
