# PDF 与 DOCX 的解析及捕获输入构造

该模块把 PDF 或 DOCX 字节转换为统一的 CaptureInput：先校验格式、大小与 Docling 运行环境，再在临时目录调用 Python 解析器，最后以内容哈希保存原件、结构化结果和内嵌图片，并返回 Markdown 正文及文档元数据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_boundary"></a>
## 解决什么问题

`documentInput` 位于文件接入与统一捕获之间：调用方交给它文件字节、文件名、数据目录和外部标识，它返回 `CaptureInput`。模块只接收扩展名为 PDF 或 DOCX 的文件；空文件和超过 20,000,000 字节的文件会立即失败。解析依赖本地 `docling` 运行时中的 Python，环境未准备时会给出安装提示。参考 [输入校验与运行时依赖 ↗](../../../apps/server/src/imports/documents.ts#L24 "支持 documentInput 的参数、返回类型，以及文件格式、字节大小和 Docling 环境限制。")

<a id="conversion_flow"></a>
## 一次 PDF 导入如何完成

以 `documentInput(pdfBytes, "guide.pdf", dataDir, externalId)` 为例，处理过程如下：

```mermaid
flowchart LR
  A[校验扩展名与大小] --> B[创建临时目录并写入文件]
  B --> C[调用 Docling 转换脚本]
  C --> D[校验 Markdown]
  D --> E[保存图片、原件与结构数据]
  E --> F[返回 CaptureInput]
```

转换脚本最多运行 180 秒，标准输出缓冲上限为 50,000,000 字节。返回内容必须含非空 Markdown，且长度不超过 200,000；否则导入终止。参考 [临时转换与正文校验 ↗](../../../apps/server/src/imports/documents.ts#L31 "支持临时目录、Python 转换进程的执行限制，以及 Markdown 内容校验。")

解析结果中的图片先从 Base64 解码并独立保存，块内原始图片字段随后被资产 ID 取代。原文件和更新后的完整解析结构也分别保存。最终结果以 Markdown 作为文本 part，同时携带解析器版本、原件与结构资产 ID、原始文件名、MIME 类型、页数和警告。参考 [图片资产与捕获结果 ↗](../../../apps/server/src/imports/documents.ts#L42 "支持图片外置、原件及结构保存，以及最终 CaptureInput 的正文和文档元数据。")

<a id="storage_and_failure"></a>
## 资产复用、错误与清理

同步与异步资产保存函数都以字节的 SHA-256 十六进制摘要作为 ID，将内容写入 `dataDir/assets`。写入采用独占创建；同一内容已经存在时忽略 `EEXIST`，因此原件、结构和图片可以按内容复用。目录权限设为 `0700`，文件权限设为 `0600`。参考 [内容寻址资产存储 ↗](../../../apps/server/src/imports/documents.ts#L10 "支持同步和异步保存均使用 SHA-256 ID、独占写入、重复内容复用及文件权限设置。")

转换阶段发生异常时，函数优先取标准错误的最后一个非空行作为对外消息，否则保留原错误信息。不论成功或失败，临时转换目录都会在 `finally` 中递归删除。需要注意，格式判断来自文件名扩展名，正文上限按 JavaScript 字符串长度执行；解析器输出还必须是可解析 JSON，并包含可遍历的 `blocks`。参考 [错误转译与临时目录清理 ↗](../../../apps/server/src/imports/documents.ts#L39 "支持标准错误提取、异常重新抛出和 finally 清理临时目录；结合 JSON 解析与 blocks 遍历说明输出结构要求。")
