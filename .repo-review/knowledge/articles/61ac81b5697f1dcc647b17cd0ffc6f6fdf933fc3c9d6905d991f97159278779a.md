# 可复现的运行时、依赖与中文向量模型锁定

该锁文件固定项目在不同平台使用的工具版本、中文嵌入模型资产、pnpm 安装输入及 osdk 指南来源，用校验和与提交号降低环境漂移风险。它描述的是已解析的供应链配置，不等同于证明这些资产已下载、依赖已安装或应用功能已验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 锁文件解决什么问题

`osdk.lock` 记录了解析后的工具、模型、应用依赖和技能来源，使开发机或自动化环境能够围绕同一组版本与完整性信息准备运行条件。当前格式版本为 4；配置分别覆盖 Linux x64 的 Node.js 24.18.1，以及 macOS ARM64 的 Bun 1.4.2，并为下载产物保存地址和校验和。参考 [跨平台工具锁定 ↗](../../../osdk.lock#L1 "支持锁文件格式版本，以及 Linux Node.js 与 macOS Bun 的解析版本、下载产物和完整性信息。")

这些内容是**环境锁定事实**，不是运行状态证明：文件能够说明预期获取什么，却不能单独证明工具已安装、产物可访问，或项目检查已经成功。

<a id="embedding"></a>
## 中文记忆检索模型的固定资产

中文记忆向量模型被固定为 `Xenova/bge-small-zh-v1.5`，类型为 embedding，并追溯到 `BAAI/bge-small-zh-v1.5`。仓库修订号被精确锁定，所需文件包括分词配置、词表和量化 ONNX 模型，适合在准备阶段按清单下载，避免运行时临时选择不同模型。参考 [中文嵌入模型身份 ↗](../../../osdk.lock#L25 "支持 memory-zh 的仓库、固定修订、模型类型、来源家族及所需资产清单。")

每个模型文件还记录大小与 SHA-256，可用于确认本地资产是否与锁定版本一致；其中量化 ONNX 文件约 24 MB。该锁定只表明模型身份和文件完整性要求，未说明向量维度、索引兼容策略或实际检索质量。参考 [模型文件完整性 ↗](../../../osdk.lock#L43 "支持模型各资产具有独立大小和 SHA-256 记录，以及量化 ONNX 模型的文件规模。")

<a id="dependencies"></a>
## 应用依赖与开发指南来源

应用依赖由 pnpm 11.28.2 管理，运行时绑定 `node@24.18.1`，安装动作采用 frozen lockfile；同时固定 `package.json` 与 `pnpm-lock.yaml` 的摘要，从而把依赖清单和原生锁文件纳入一致性检查。参考 [pnpm 依赖锁定 ↗](../../../osdk.lock#L73 "支持 pnpm 版本、Node.js 运行时、冻结安装命令以及清单和原生锁文件摘要。")

osdk 指南来源明确指向 `github:lejunyang/one-sdk`，以解析后的提交和内容哈希锁定，并采用复制安装模式提供给指定代理环境。参考 [osdk 指南来源 ↗](../../../osdk.lock#L87 "支持技能实际来源、解析提交、内容哈希、目标代理和复制安装模式。")

因此，该文件可作为环境复现与供应链核验的入口，但仍需实际执行依赖准备和项目检查，才能确认当前机器上的安装结果与代码行为。
