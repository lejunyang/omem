# osdk 锁定工具链与依赖快照

锁文件固定 Linux x64 的 Node 24.18.1、pnpm 11.28.2 安装器、原生 pnpm 锁摘要和 osdk-guide 的解析提交，用于可复现依赖恢复。它记录解析结果与校验信息，不单独证明下载、安装或项目检查已经成功。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="runtime"></a>
## 运行时与安装输入

锁文件 schema 为 4，并将 Linux x64 的 Node 请求与解析版本都固定为 `24.18.1`，同时记录官方归档地址、文件名和 SHA-256 校验值；该工具配置关闭 corepack。[Node 锁定记录 ↗](../../../osdk.lock#L1 "支持 Linux x64 Node 版本、归档来源、校验值和 corepack 配置。") pnpm 依赖解析使用安装器版本 `11.28.2` 和 Node 24.18.1，输入清单为 `package.json`，安装命令带 frozen lockfile，并允许从源码构建。[pnpm 安装快照 ↗](../../../osdk.lock#L16 "支持 pnpm 安装器版本、运行时、manifest、冻结安装命令与源码构建设置。") 这些字段共同限定可复现安装输入，但执行成功仍应依据真实命令退出码。

<a id="locks"></a>
## 原生锁与技能来源

依赖快照进一步固定 `pnpm-lock.yaml` 的路径和摘要，使 manifest 或原生锁变化能够被检测，而不是静默沿用旧解析结果。[pnpm 原生锁摘要 ↗](../../../osdk.lock#L25 "支持原生锁文件种类、路径和摘要的可复现性约束。") `osdk-guide` 技能来自 `github:lejunyang/one-sdk`，解析到明确提交并记录内容哈希，面向 universal 与 claude-code agent。[osdk-guide 解析结果 ↗](../../../osdk.lock#L30 "支持技能的真实上游、内容哈希、固定提交和适用 agent。") 因而实际上游是 one-sdk；锁文件只描述当前解析快照，不表示远端永久可达，也不代替 `osdk deps --frozen` 与项目检查。
