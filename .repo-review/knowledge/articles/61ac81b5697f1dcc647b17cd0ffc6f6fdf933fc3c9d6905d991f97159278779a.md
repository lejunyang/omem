# osdk.lock：工具链、中文向量模型与依赖锁定

该锁文件固定了 Linux x64 的 Node.js 工具链、中文 embedding 模型及其制品、pnpm 安装输入，并记录 osdk-guide 技能来源。它能证明期望版本与完整性约束已被声明，但不能单独证明依赖已经安装、模型已下载或运行检查已经通过。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="runtime-and-dependencies"></a>
## 运行时与应用依赖

锁文件采用 schema 4，并为 Linux x64 固定 Node.js 24.18.1、架构及关闭 Corepack 的选项，同时记录下载地址和 SHA-256 校验值。这些字段用于让工具链解析与制品校验可复现，但属于锁定配置，不等同于当前机器已经成功安装该运行时。[Node.js 工具链锁定 ↗](../../../osdk.lock#L1 "支持 schema、Linux x64、Node.js 版本、平台选项以及制品地址和校验值均已在锁文件中声明的论断。")

应用依赖由 pnpm 11.28.3 管理，绑定 `node@24.18.1`，以 `package.json` 为清单并要求执行冻结锁安装；同时保存清单与 `pnpm-lock.yaml` 的摘要。由此可判断依赖解析输入被固定，但不能据此宣称安装命令或项目检查已实际成功运行。[pnpm 依赖锁定 ↗](../../../osdk.lock#L64 "支持 pnpm 版本、Node.js 运行时、冻结安装命令及原生锁文件摘要的配置说明。")

<a id="memory-model"></a>
## 中文记忆向量模型

`memory-zh` 被配置为 Hugging Face 上的 `Xenova/bge-small-zh-v1.5`，用途为 embedding，且请求版本与解析版本固定到同一提交；配置还说明其源模型家族为 BGE，并派生自 `BAAI/bge-small-zh-v1.5`。这建立了明确的模型身份，可用于避免不同修订的向量结果被无意混用。[中文向量模型身份 ↗](../../../osdk.lock#L16 "支持 memory-zh 的提供方、仓库、固定修订、embedding 类型和 BGE 来源关系。")

锁文件限定了配置、分词器、词表和量化 ONNX 模型等所需文件，随后逐项记录大小与 SHA-256，其中量化模型约 24 MB。该信息支持下载后完整性验证和离线运行准备，但文件清单本身不能证明这些制品已存在于本地缓存，也不能证明索引已用该模型生成。[模型制品清单与校验 ↗](../../../osdk.lock#L25 "支持模型包含量化 ONNX、分词器和词表等文件，并逐项锁定大小与摘要的说明。")

<a id="skill-provenance"></a>
## osdk 指南来源

配置还锁定 `osdk-guide` 技能来自 `github:lejunyang/one-sdk`，解析到具体提交并以复制模式安装，目标代理包括 universal 与 claude-code。这说明仓库期望使用的指南来源及版本边界，而不是指南内容已被执行或所有相关流程已经验收。[osdk-guide 技能来源 ↗](../../../osdk.lock#L78 "支持技能的真实上游、解析提交、适用代理与复制安装模式的配置事实。")
