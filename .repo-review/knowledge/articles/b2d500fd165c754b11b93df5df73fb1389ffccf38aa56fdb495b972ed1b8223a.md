记录 2026 年 9 月 26 日首轮设计材料和离线交互原型的验证方法、浏览器覆盖及明确缺口。它是历史验收证据，不代表当前运行代码或生产集成已经实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

## 验证对象与历史定位

这份记录回答的是“首轮方案和离线交互原型能否自洽运行、主要阅读交互是否成立”。当时的验证对象仅为设计材料与离线原型，真实模型、开源引擎和服务端尚未部署，因此不能据此判断当前产品能力。参考 [首轮验证定位 ↗](../../../docs/validation.md#L3 "支持验证对象仅为设计材料与离线原型，以及真实模型、开源引擎和服务端当时尚未部署的结论。")

其中原型采用 React 与 CSS 打包为自包含 HTML，不依赖远程字体、CDN 或 API；这是当时的演示实现，并非现行产品技术栈。参考 [自包含 React 原型 ↗](../../../docs/validation.md#L11 "直接支持原型由 React 与 CSS 打包成自包含 HTML且不依赖远程资源的描述。") 后续实施状态已记录统一知识阅读等新切片，当前能力应以实施状态为入口。参考 [统一知识阅读进展 ↗](../../../docs/implementation/status.md#L3 "说明后续实施状态已经记录新的统一知识阅读切片，支持将当前能力与早期原型验证区分。")

## 原型验证覆盖了什么

验证过程包括材料和上游项目核验、离线构建、多个视口的 Chromium 测试、人工视觉检查与静态一致性检查。参考 [首轮验证方法 ↗](../../../docs/validation.md#L7 "支持材料核验、离线构建、浏览器测试、人工视觉检查与静态一致性检查的验证范围。")

浏览器覆盖围绕证据阅读体验展开，包括多层引用下钻、循环检测、固定历史版本、弹窗内追问、返回后恢复位置、权限与删除状态、搜索、同步状态、刷新恢复以及移动端布局。参考 [浏览器交互覆盖 ↗](../../../docs/validation.md#L16 "支持多层引用、循环、历史版本、追问、状态恢复、异常状态和移动端等交互覆盖。") 测试脚本明确限定自己只检查主要交互合同，不推导任何后端行为。参考 [脚本验证边界 ↗](../../../docs/prototype/smoke.mjs#L1 "直接支持浏览器脚本只检查主要交互合同、不代表后端行为已经验证的限定。")

<a id="limits"></a>
## 不能由本次验证推出的结论

本次验证没有测量引用支持准确率、中文检索召回、事实幻觉率或学习后的任务成功率，也没有验证真实连接器、鉴权、团队权限、数据库并发、灾备和后端学习流程。原型中的“可点击”和调研中的“存在某字段”都不能视为生产能力。参考 [明确未验证事项 ↗](../../../docs/validation.md#L45 "支持质量指标、真实部署、外部集成、权限、可靠性和后端流程未被本次验证覆盖的结论。")

因此，这套原型适合作为视觉与交互对照，而不是现行产品代码依赖或当前验收基线。当前界面仍需围绕真实服务连接、错误态、引用层级、焦点恢复和窄屏行为重新执行项目检查与浏览器验证。参考 [现行界面验收要求 ↗](../../../design.md#L50 "说明历史离线原型仅供视觉对照，现行界面仍须通过真实行为、错误态和浏览器检查。")
