# 助理回答的证据链接适配

说明日常助理如何把回答中的临时证据标识转换为可读、可点击且能回到固定原文范围的引用，并处理重复证据、未引用补充材料与失效标识。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-contract"></a>
## 把模型引用变成读者可操作的证据

`readAssistantAnswer` 位于助理结果与阅读组件之间，解决模型回答里的片段 ID、行范围别名不适合直接展示的问题。输入是回答 Markdown 与 `AnswerEvidence[]`；每条证据至少带片段、修订标题，可选章节名、引用别名和固定原文锚点。锚点沿用检索层的 `SourceAnchor`，包含材料键、修订、摘要、行范围和片段集合，因此点击后可以定位到特定版本的原文，而非只打开一个模糊文件。参考 [助理证据输入 ↗](../../../apps/web/src/assistant-reader.ts#L1 "说明适配器接收的证据字段、可选引用别名与固定原文锚点。") [固定原文锚点合同 ↗](../../../apps/server/src/retrieval/port.ts#L19 "说明 SourceAnchor 包含材料、修订、摘要、行范围与片段集合，可支持精确回到固定原文。")

上游运行时先把模型声明的引用限制在本轮实际提供的证据内，再形成 `selectedEvidence`；`DailyAssistant` 对每个会话轮次调用本函数，并按返回引用找到原证据：有固定锚点时导航到原文范围，否则退回打开片段。参考 [服务端筛选已选证据 ↗](../../../apps/server/src/assistant/runtime.ts#L755 "说明运行时仅接受本轮已提供的引用标识，并据此生成 selectedEvidence。") [页面调用与证据导航 ↗](../../../apps/web/src/DailyAssistant.vue#L32 "证明 DailyAssistant 实际调用适配器，并根据 sourceTarget 在原文导航与片段打开之间选择。")

<a id="representative-flow"></a>
## 一次回答如何完成引用转换

例如回答含 `[[e:original:6:8]]`，证据同时给出该别名、章节名 `releaseParcel` 和第 6–8 行锚点。函数先按完整 `sourceTarget` 去重；没有锚点时才按 `fragmentId` 去重。随后依次生成 `answer_0` 等页面键，标签优先用章节名，其次取修订标题的文件名，说明文字则补上行号。这样同一片段的两个不同固定范围仍是两条引用。参考 [证据去重与可读标签 ↗](../../../apps/web/src/assistant-reader.ts#L16 "支持按固定锚点或片段去重、生成 answer_n、选择标签及行号说明的流程。")

```mermaid
flowchart LR
  A[回答与已选证据] --> B[按固定锚点去重]
  B --> C[生成可读引用]
  C --> D[别名改写为 answer_n]
  D --> E[正文链接或补充证据]
```

接着代码为 `citationId` 与 `fragmentId` 建立别名表，转义正则特殊字符后，只替换确实由本轮证据提供的方括号标识。一个片段若对应多个固定范围，使用片段 ID 会展开为多个 `answer_n`，而带行号的 `citationId` 可精确落到一个范围。转换时同时记录正文实际提到的引用。参考 [引用别名改写 ↗](../../../apps/web/src/assistant-reader.ts#L33 "支持别名映射、正则转义、精确替换以及记录正文已提及引用的说明。")

<a id="outputs-and-boundaries"></a>
## 输出、展示与边界

返回值分工明确：`source` 是改写后的 Markdown，`citations` 是供渲染器解析的可读元数据，`references` 保留与引用下标一致的原证据，`additional` 收集存在于证据集合但正文未提到的项目。`DailyAssistant` 将前三者接入 Markdown 与点击导航，并把 `additional` 作为面板操作区里的独立证据入口。参考 [适配结果结构 ↗](../../../apps/web/src/assistant-reader.ts#L67 "说明 source、citations、references 与 additional 四类输出及未提及引用的筛选。") [回答渲染与补充证据 ↗](../../../apps/web/src/DailyAssistant.vue#L182 "证明页面把改写后的正文和引用交给 Markdown，并单独渲染 additional 证据。")

边界处理偏向显式失败：若回答残留本轮没有提供的 `e:片段:起始:结束` 或 UUID 形式标识，会改成“引用不可用”，不会伪造链接；普通 Markdown 链接不会因通用替换而被改写。证据为空时跳过别名正则，但仍会清理这两类失效标识。去重依赖 `JSON.stringify(sourceTarget)` 的结果，因此它比较的是完整序列化锚点；若调用方构造语义相同但属性插入顺序不同的对象，代码本身不会规范化它们，这是实现层面的限制。参考 [失效引用处理 ↗](../../../apps/web/src/assistant-reader.ts#L46 "支持未知行范围标识或 UUID 被显式替换，并结合函数前段说明空证据和序列化去重边界。")
