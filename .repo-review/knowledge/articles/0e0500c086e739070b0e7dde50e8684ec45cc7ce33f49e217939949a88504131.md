# 概念向量的窗口映射与语义候选召回

该模块把源材料描述中的概念标签和别名转换为可嵌入的概念文本，并记录其在检索单元正文中的字符范围；查询时按传入的 modelId 从 retrieval_unit_vectors 读取概念向量，计算点积分数，按概念身份与检索单元两级去重，输出带源码摘录和 semantic-concept 路由的候选。独立版本常量表达了让概念文本避开正文向量缓存的设计意图。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_dependencies"></a>
## 解决什么问题

该模块为概念文本设置独立向量身份 `range-concepts-v1`，使其不进入正文向量缓存；它只处理 `target.kind === "source"` 的检索单元。参考 [概念向量身份与适用对象 ↗](../../../apps/server/src/retrieval/concept-vectors.ts#L4 "支持概念向量采用独立版本身份以避免概念文本进入正文向量缓存，并且窗口生成只接受 source 检索单元。")

模块从检索单元读取正文、固定材料范围及 `materialDescription.description.concepts`，查询接口另接收 SQLite、模型标识、已筛选的单元映射和查询向量。调用方提供合格单元，本模块只在传入单元内召回。参考 [概念候选输入边界 ↗](../../../apps/server/src/retrieval/concept-vectors.ts#L40 "支持调用方提供合格单元，以及候选函数所依赖的数据库、模型标识、单元映射和查询向量。")

<a id="representative_flow"></a>
## 一条代表性调用

假设一个源码单元覆盖第 10—20 行，其中概念“费用登记”覆盖第 12—14 行，并带有别名。`conceptWindows` 先建立逐行字符偏移，只选取与单元范围相交的概念，再把概念标签和别名用中文分号拼成嵌入文本；窗口起止位置会裁剪到当前单元正文内。概念身份同时包含材料键、修订、标签、别名和原始行范围。参考 [概念窗口映射 ↗](../../../apps/server/src/retrieval/concept-vectors.ts#L10 "支持重叠概念筛选、字符偏移换算、概念身份组成、嵌入文本拼接及空窗口过滤。")

```mermaid
flowchart LR
  A[源材料检索单元] --> B[生成概念文本与字符窗口]
  B --> C[按 modelId 读取已存向量]
  C --> D[与查询向量计算点积]
  D --> E[概念级去重]
  E --> F[单元级最高分候选]
```

`conceptCandidates` 用数据库行的 `part` 找回对应窗口，把二进制向量恢复为 `Float32Array` 并计算点积；最终候选携带原单元、分数、`semantic-concept` 路由以及窗口内的正文摘录。参考 [向量读取与点积评分 ↗](../../../apps/server/src/retrieval/concept-vectors.ts#L56 "支持按传入的模型标识读取向量、跳过失配单元或窗口、恢复浮点向量、检查维度并计算点积。") [两级候选去重 ↗](../../../apps/server/src/retrieval/concept-vectors.ts#L77 "支持概念级的分数及跨度取舍、候选摘录与路由生成，以及单元级最高分保留。")

<a id="boundaries_and_deduplication"></a>
## 边界与去重规则

非源码单元、没有相交概念的单元以及裁剪后长度为零的窗口不会产生概念卡片。读取索引时，数据库中的单元已不在调用方映射内，或 `part` 找不到窗口，都会被跳过；已存向量和查询向量维度不同则直接抛错，提示模型身份没有随维度变化而更新。参考 [概念窗口映射 ↗](../../../apps/server/src/retrieval/concept-vectors.ts#L10 "支持重叠概念筛选、字符偏移换算、概念身份组成、嵌入文本拼接及空窗口过滤。") [向量读取与点积评分 ↗](../../../apps/server/src/retrieval/concept-vectors.ts#L56 "支持按传入的模型标识读取向量、跳过失配单元或窗口、恢复浮点向量、检查维度并计算点积。")

同一概念可能因跨检索单元投影而出现多次。模块先用完整概念身份合并这些投影：保留分数更高者，同分时保留字符跨度更长者；随后每个检索单元只留下最高分概念候选。返回数组本身没有在此处排序，后续排序或融合属于上层检索流程。参考 [两级候选去重 ↗](../../../apps/server/src/retrieval/concept-vectors.ts#L77 "支持概念级的分数及跨度取舍、候选摘录与路由生成，以及单元级最高分保留。")
