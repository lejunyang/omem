# 概念描述如何变成语义召回候选

该模块把材料描述中的概念标签与别名投影到来源检索单元的字符范围，读取独立存储的概念向量，与查询向量计算相似度，再按概念和检索单元两层去重。它补充正文向量召回，同时保持独立缓存身份和可隔离的失败边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 用概念名称弥补正文措辞差异

这个模块让检索能够利用材料描述中的概念标签及别名。概念文本采用独立版本标识，避免与正文向量共用缓存身份。参考 [概念向量独立身份 ↗](../../../apps/server/src/retrieval/concept-vectors.ts#L4 "支持概念文本使用独立版本标识、避免进入正文向量缓存的说明。")

`conceptWindows` 只处理目标类型为 `source` 的检索单元。它选择与单元行段相交的概念，把 `label` 和 `aliases` 拼成待嵌入文本，同时把概念行号换算成单元正文里的字符起止位置。没有交集或字符范围为空的概念不会进入后续索引。参考 [概念窗口投影 ↗](../../../apps/server/src/retrieval/concept-vectors.ts#L7 "支持 source 限定、行段交集筛选、概念文本拼接、字符偏移换算与空窗口过滤。")

<a id="representative_flow"></a>
## 一条查询的处理流程

以查询“递归证据追踪”为例，统一检索先把查询文本嵌入成向量。索引端此前已调用 `conceptWindows`，按最多 16 个窗口一批生成概念向量，并用独立模型标识写入向量表。参考 [概念向量索引 ↗](../../../apps/server/src/retrieval/unified.ts#L233 "说明统一检索如何调用概念窗口、批量嵌入并准备写入独立模型标识对应的向量记录。")

```mermaid
flowchart LR
  A[查询向量] --> B[读取同模型的概念向量]
  B --> C[按 part 找回概念窗口]
  C --> D[点积计算分数]
  D --> E[返回概念摘录候选]
```

查询端把数据库、概念模型标识、已通过资格筛选的单元映射和查询向量交给 `conceptCandidates`。函数按 `unit_id` 与 `part` 还原窗口，将字节数据解释为 `Float32Array`，校验维度后计算点积；输出包含原检索单元、分数、`semantic-concept` 路由、概念对应的正文摘录及匹配字符范围。参考 [概念召回接入与隔离 ↗](../../../apps/server/src/retrieval/unified.ts#L713 "支持统一检索传入数据库、模型标识、候选单元和查询向量，并在概念表示失败时保留正文向量结果。") [向量读取与打分 ↗](../../../apps/server/src/retrieval/concept-vectors.ts#L57 "支持数据库行筛选、窗口还原、向量维度校验、点积计算及候选字段构造。")

<a id="boundaries"></a>
## 去重规则与失败边界

数据库行找不到当前单元，或 `part` 对不上概念窗口时，该行会被跳过。向量维度与查询不一致则直接报错，提示模型身份没有随维度变化更新。参考 [向量读取与打分 ↗](../../../apps/server/src/retrieval/concept-vectors.ts#L57 "支持数据库行筛选、窗口还原、向量维度校验、点积计算及候选字段构造。")

同一概念可能投影到多个检索单元。模块先按由材料 key、revision、概念名称、别名和行段组成的稳定 key 去重：分数更高者优先；同分时保留覆盖范围更长的投影。随后每个检索单元只留下最高分概念，因此一个单元最多返回一个概念候选。参考 [两层候选去重 ↗](../../../apps/server/src/retrieval/concept-vectors.ts#L78 "支持按概念稳定 key 比较分数与跨度，再按检索单元保留最高分候选。")

概念召回属于统一检索的可选表示。调用方捕获这里的错误并清空概念候选，健康的正文向量结果仍可继续参与融合。参考 [概念召回接入与隔离 ↗](../../../apps/server/src/retrieval/unified.ts#L713 "支持统一检索传入数据库、模型标识、候选单元和查询向量，并在概念表示失败时保留正文向量结果。")
