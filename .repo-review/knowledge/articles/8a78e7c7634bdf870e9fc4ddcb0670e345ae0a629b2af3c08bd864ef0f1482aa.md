# 把材料写成一篇能用的文章

多份材料先形成可编辑的目录草案，读者检查每页目的、范围、顺序与分类，合并重复讲解并保存；只有明确确认后，系统才把各页变成正式计划并排队写作。本文用一份活动约定贯穿整个过程，再沿其中一页说明研究者补背景、作者按读者问题重组、独立复核者自行取证以及发布与后续维护。文中同时区分原件、草案、页面计划、正文，说明固定引用、参考页、内部笔记和项目动态范围的作用，并列出网页与 CLI 的当前边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="plan-route"></a>
## 先规划读者要走的路线

面对多份材料，先规划阅读路线，再启动单页写作。omem 把保存单位、检索单位和讲解单位分开：原件保留历史，结构块帮助检索，页面围绕一个读者问题跨材料解释。目录草案负责把多页组织成有顺序、可修改的路线；单篇文章仍可直接建立页面计划。参考 [问题驱动的知识生成流程 ↗](../../../docs/reader-first/architecture.md#L7 "支持从材料、可编辑目录、正式页面计划到发布的总体路线，以及单篇可直接建计划的边界。")

**教学示例**：活动约定写着预算八十元、图书馆集合，后来又加入报名须知。按文件各写一页，会把参加者真正要做的事拆散。更合适的初稿可以先放两页：

- “参加活动如何准备”，回答预算、集合地点和报名条件怎样共同影响准备。
- “组织者如何确认报名”，说明组织者需要核对什么。

这两页是阅读路线的候选。读者发现报名条件在两页重复，可以合并讲解；如果参加者准备和组织者操作确有不同任务，也可以保留两页并调整顺序。目录由读者目标决定，材料数量不决定文章数量。参考 [网页目录草案操作 ↗](../../../docs/reader-first/knowledge-outlines.md#L3 "支持选材、填写目标、AI 建议、页面编辑、保存与确认的用户流程。")

<a id="edit-outline"></a>
## 在网页里把草案改到可以确认

网页的“规划知识目录”已经提供完整入口。一次操作可以这样走：

1. 选择已保存的文档、代码或会话材料，也可以选择正式项目或主题。额外选择的来源可作为明确背景。
2. 填写目录标题、读者、整体阅读目标和分类路径。
3. 让 AI 建议目录，或手工添加页面。AI 返回的是页面候选和调查理由，不会改动正式知识。
4. 逐页检查标题和用途，补足场景、目标与问题。页面顺序就是将来的阅读顺序；修改 `topicPath` 会改变分类位置。
5. 合并重复页。系统保留目标页的身份，把双方的目标、场景、问题与材料范围去重合并，再移除源页；标题和用途仍以目标页为准，因此合并后要人工复查讲解范围。若目标页复用已发表文章，该文章身份会保留。参考 [目录草案页面合同 ↗](../../../packages/contracts/src/knowledge-outline.ts#L7 "支持草案是阅读计划、正式身份在确认时分配，以及页面字段与 32 页上限。") [移动分类与合并页面 ↗](../../../apps/web/src/knowledge/outline-editing.ts#L18 "支持根分类移动只影响继承页面，以及合并保留目标身份并汇总目标、场景、问题和范围。")
6. 保存草案。此时只持久化可编辑路线，页面正文还没有开始生成。
7. 检查整条路线和每页目的，明确选择“确认目录并开始写作”。各页随后才进入调查、撰写与独立补查。参考 [网页目录草案操作 ↗](../../../docs/reader-first/knowledge-outlines.md#L3 "支持选材、填写目标、AI 建议、页面编辑、保存与确认的用户流程。")

保存和确认之间的停顿很重要。可以在 Agent 尚未配置或页面尚未补全时先保存；发起 AI 建议或确认写作前，才需要满足相应的目标、读者与材料条件。AI 建议会先保存当前编辑，再排队调查。跨窗口编辑由版本保护，旧窗口不能覆盖较新的人工修改。

CLI 是另一个已实现入口。具备 `omem-cli` 技能的外部 Agent 可以执行 list、show、create、save、propose、apply 和 delete；apply 前仍需展示路线并取得用户明确确认。当前主助手的自然语言 `work_action` 尚未注册目录操作，现有入口是网页和具备 CLI 能力的外部 Agent。参考 [网页与 CLI 当前入口 ↗](../../../docs/reader-first/knowledge-outlines.md#L54 "支持外部 Agent 的 CLI 操作需要用户明确确认，并说明主助手自然语言目录操作尚未注册。")

<a id="four-objects"></a>
## 四类对象分别承担什么

| 对象 | 它保存什么 | 何时影响正式知识 |
| --- | --- | --- |
| 原始材料 | 稳定来源身份和历次内容版本 | 进入原有捕获与版本流程后 |
| 目录草案 | 整体目标、读者、范围，以及有顺序的页面候选 | 编辑、保存和 AI 提议都不改变正式页面计划 |
| 页面计划 | 每页用途、问题、分类、范围、正式身份与顺序 | 用户确认整个草案时保存，并安排写作 |
| 正文版本 | 章节、固定引用、生成记录与独立复核记录 | 写作和复核完成后发布 |

草案中的材料键指向来源当前内容，并未锁定某次修订。目录调查开始时会固定一份调查快照；确认以后，每篇文章在自己的调查开始时重新解析当前范围，再固定该页快照。原件在目录建议之后发生变化，正文仍会按写作时的材料重新调查。参考 [草案、计划、正文与快照 ↗](../../../docs/reader-first/knowledge-outlines.md#L21 "支持四类对象的保存边界、两次快照时机、确认后旧正文和固定引用继续保留。")

确认可以先改变正式目录中的标题、分类和顺序。已有正文继续可读，旧引用仍指向原来的固定版本，直到新结果通过复核并发布。新页在确认时取得正式身份；复用已有页则沿用原身份和历史。确认动作把全部页面计划与队列项放在同一事务中，避免只应用一部分目录。参考 [草案、计划、正文与快照 ↗](../../../docs/reader-first/knowledge-outlines.md#L21 "支持四类对象的保存边界、两次快照时机、确认后旧正文和固定引用继续保留。") [确认草案的原子应用 ↗](../../../apps/server/src/knowledge/outlines.ts#L346 "支持确认时按顺序创建或复用页面计划、统一排队，并保留旧正文和引用。")

<a id="write-one-page"></a>
## 确认后，一页文章怎样形成

沿“参加活动如何准备”这一页看，正式页面计划已经给出读者、目标、场景、问题和材料范围。后面的三个角色共享获准范围，各自解决不同问题：

1. **研究者补齐回答所需的背景。** 它围绕预算、集合地点和报名条件搜索材料，读取完整章节或相关历史。已有文章可以帮助理解，新增事实仍回原件核对。原件在任务内固定，调查期间不会悄悄切换到新版本。
2. **作者按读者问题重组材料。** 作者接收调查结论，也能继续读取相同范围。成稿可以把分散在活动约定和报名须知里的事实组织成准备步骤，不必沿文件顺序复述。
3. **独立复核者自行取证。** verifier 在新的会话中拿到完整草稿、相同材料范围和调查工具，会自己搜索与补读。它检查事实，也检查文章是否回答页面目的；复核范围不局限于作者已经挑出的引文。参考 [自主调查和独立补查 ↗](../../../docs/reader-first/agent-research.md#L9 "支持研究者按需调查、作者继续读取、verifier 在独立会话自行补查，以及固定材料快照。") [复核与发布前检查 ↗](../../../docs/reader-first/agent-research.md#L34 "支持结构化提交后仍需独立复核和材料、计划有效性检查，并说明复核者自行读取原件。")

复核未通过，草稿进入返修；通过后才组装依赖并发布。已有文章重新整理失败时，旧正文和计划继续保留。维护任务还可以选择局部更新或重新组织；重新组织会保留文章身份与历史，同时要求新稿依据当前原件重新核对。参考 [变化影响与维护历史 ↗](../../../docs/reader-first/publication-lifecycle.md#L27 "支持固定引用、章节级复查、自动维护默认关闭、失败保留旧文和维护时重组。")

<a id="reader-results"></a>
## 读者最后得到什么

生成结果按阅读用途分成三类：

| 产物 | 面向谁 | 在哪里出现 |
| --- | --- | --- |
| 正式讲解 | 需要入门、理解机制或完成操作的读者 | 主题目录、搜索和助手背景 |
| reference | 需要查字段、接口或规则的读者 | 独立参考目录，也可被搜索 |
| 内部笔记 | 后续调查与整理过程 | 不进入读者目录和知识召回 |

用途来自保存的阅读目标。目录分类负责安排人怎么读，引用负责把解释连回依据，两者承担不同关系。参考 [发布用途与三种来源关系 ↗](../../../docs/reader-first/publication-lifecycle.md#L5 "支持正式文章、参考资料、内部笔记的展示差异，以及引用、reviewSources、调查轨迹的分工。")

正文里的引用打开写作时固定的原件版本。当前材料换版不会把旧引用悄悄改指新版。章节还可以记录 `reviewSources`：某项配置、约定或调用条件没有直接写进正文，但它变化后仍要求复查该节。调查轨迹只记录角色实际读过什么，偶然读过的材料变化不会直接判正文失效。参考 [发布用途与三种来源关系 ↗](../../../docs/reader-first/publication-lifecycle.md#L5 "支持正式文章、参考资料、内部笔记的展示差异，以及引用、reviewSources、调查轨迹的分工。")

材料更新后，系统按完整 Markdown 章节或代码结构定位需要复查的部分。行号移动且所引结构未变，原解释可以继续使用；预算所在章节变化，可以只标记费用说明待核对，集合地点说明仍可查阅。这个定位缩小了复查范围，无法证明代码语义或自然语言含义一定未变，作者和复核者仍要检查关键前提。参考 [变化影响与维护历史 ↗](../../../docs/reader-first/publication-lifecycle.md#L27 "支持固定引用、章节级复查、自动维护默认关闭、失败保留旧文和维护时重组。")

<a id="keep-current"></a>
## 新聊天怎样进入已有文章

材料范围决定下一次调查能看到什么。活动文章若持续跟踪“阅读小组”项目，后来明确归入该项目的报名聊天会进入后续调查；只选择几份固定材料，新增聊天需要手工加入文章范围。项目归属来自显式的来源关系，系统不会根据文件名、会话 ID 或相似标题猜测。参考 [项目动态范围 ↗](../../../docs/reader-first/project-contexts.md#L3 "支持项目显式归属、后来材料进入调查、固定选材的差异，以及范围正确仍需内容判断。")

动态范围解决的是“哪些材料可供调查”。模型仍要判断新报名须知与旧约定的关系。目录草案选择项目范围，也只安排确认时的各页写作；以后是否随成员加入、移出或换版自动维护，由正式文章自己的更新设置决定。自动更新默认关闭，失败时保留旧正文。参考 [变化影响与维护历史 ↗](../../../docs/reader-first/publication-lifecycle.md#L27 "支持固定引用、章节级复查、自动维护默认关闭、失败保留旧文和维护时重组。") [项目动态范围 ↗](../../../docs/reader-first/project-contexts.md#L3 "支持项目显式归属、后来材料进入调查、固定选材的差异，以及范围正确仍需内容判断。")

当前边界会直接影响操作选择：

- 一个草案最多 32 页，确认会安排全部页面写作，目前没有只更新导航的选项。
- 合并或移除草案页不会退役、删除已发表文章，也不会迁移其历史。
- 已确认草案不能继续编辑；要调整路线，可复制草案，或从文章入口调整材料与目标。
- 主助手自然语言目录操作尚未接入。网页和具备相关技能的 CLI Agent 是当前入口。
- AI 建议与独立复核都不能证明文章已经易懂，仍需读者检查案例、问题覆盖和实际修改入口。

这些限制来自当前实现状态。参考 [目录草案当前限制 ↗](../../../docs/reader-first/knowledge-outlines.md#L72 "支持 32 页、确认安排全部写作、草案合并不退役文章及质量仍需人工检查等边界。")
