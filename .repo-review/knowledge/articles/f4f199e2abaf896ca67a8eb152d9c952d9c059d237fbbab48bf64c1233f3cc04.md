# jobs · 模块理解

jobs 模块由 SQLite 仓储与进程内工作器组成持久化任务执行层：仓储管理入队身份、租约、执行尝试、重试和幂等控制，工作器按类型调用处理器、续租并传递取消信号。已确认中断分类优先于处理器声明的错误类别；唯一约束、心跳到期语义及真实并发测试仍缺少证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role_and_background"></a>
## 模块职责与状态边界

jobs 模块把异步执行保存为可恢复、可审计的持久化状态机。作业记录输入身份、版本、generation、租约和结果；每次尝试另存模型配置、运行指纹、用量与错误，角色输出还能保存摘要和 trace。[作业仓储的职责与持久化模型 ↗](9d5c793b6d7b58169c99020cd4b43385481ae6f4993191ce0ede652222f5b3e7.md#purpose_and_model "子知识解释作业、执行尝试和角色输出的分层保存，支持模块的恢复与审计定位。") 原始类型也体现了作业、执行尝试与角色输出的分层。[作业、尝试与角色输出类型 ↗](../../../apps/server/src/jobs/repository.ts#L11 "原始类型定义支持作业状态、租约、执行指纹、用量和角色输出分别持久化的论断。")

工作器在进程内维护活跃任务的取消控制器；运行中取消仅在仓储返回 `cancelling` 时中断对应处理器，停机则中断全部活跃处理器，因此这些控制器用于协作式中断，而非持久事实来源。[活跃任务取消与停机 ↗](../../../apps/server/src/jobs/worker.ts#L137 "支持运行中取消会中断对应活跃处理器、停机会中断全部活跃处理器，并说明进程内取消控制器的实际用途。") 入队输入会先规范化：对象键排序、过滤 `undefined`、保留数组顺序，再计算 SHA-256。[稳定摘要规范化 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持对象键排序、过滤 undefined、保留数组顺序并计算 SHA-256 的输入规范。") **被替代的结论**是“相同工作必然不会重复创建”；目前只能确认 `INSERT OR IGNORE` 与按身份字段回查，数据库级去重仍依赖未提供的唯一约束。[事务化入队与身份回查 ↗](../../../apps/server/src/jobs/repository.ts#L175 "支持入队使用 INSERT OR IGNORE 并按工作区、类型、输入摘要和版本回查，也说明去重仍依赖未展示约束。")

<a id="execution_flow"></a>
## 领取、执行与结果收敛

仓储在事务中领取到期的排队、重试或租约过期任务：先把旧 attempt 记为 `lease_expired`，检查当前 generation 的尝试上限，再以条件更新取得新 token 并创建 attempt。[任务领取与过期租约回收 ↗](../../../apps/server/src/jobs/repository.ts#L261 "支持候选筛选、旧 attempt 收尾、尝试上限、条件领取及新 attempt 创建流程。") 工作器随后按 `kind` 查找处理器；缺少处理器是独立配置错误路径，会先标记 running，再提交 `config` 失败。[缺少处理器的配置失败路径 ↗](../../../apps/server/src/jobs/worker.ts#L47 "支持未注册处理器时先标记运行，再单独提交 config 类型失败。")

正常路径会标记 running、周期续租，并把 `AbortSignal` 传给处理器。成功结果交由仓储收尾。**被替代的结论**是“`JobExecutionError` 总会保留声明类别”：只有未发生中断时才使用 `failure.kind`；停机中断优先归为 `transient`，其他中断优先归为 `cancelled`，即使处理器抛出显式 `JobExecutionError` 也会被覆盖。[工作器执行与中断优先分类 ↗](../../../apps/server/src/jobs/worker.ts#L72 "支持未中断时采用处理器声明类别，以及停机中断和其他中断分别优先覆盖为 transient 与 cancelled。") 失败也并非一律重跑，只有 `bad_output` 与 `transient` 在同类阈值及 `maxAttempts` 内进入指数退避重试。[失败重试阈值与退避 ↗](../../../apps/server/src/jobs/repository.ts#L581 "支持仅 transient 和 bad_output 可自动重试，并受同类次数、generation 上限和指数退避约束。")

<a id="control_progress_limits"></a>
## 控制、留痕与当前限制

取消和人工重试使用 `requestId` 载荷摘要实现幂等，并以 generation 阻止旧请求控制新一代作业；运行中取消先设置标记，成功作业要求补偿，失败、取消或等待决策的作业才可人工重试。[幂等取消与代次重试 ↗](../../../apps/server/src/jobs/repository.ts#L674 "支持请求载荷冲突检测、generation 校验、不同状态的取消语义及人工重试范围。") 活动 attempt 可记录模型、提示词与技能指纹、会话和用量，角色输出与 trace 则事务化保存。[运行轨迹与角色输出保存 ↗](../../../apps/server/src/jobs/repository.ts#L404 "支持活动 attempt 元数据更新，以及输出摘要和 trace 的事务化持久化。")

租约语义仍有待确认：`markRunning` 要求原租约未到期，但 heartbeat 只校验 token、状态和取消标记，没有检查原到期时间，因而可能续回已过期但尚未被重新领取的租约。[运行转换与心跳条件 ↗](../../../apps/server/src/jobs/repository.ts#L375 "支持 markRunning 检查租约到期时间、heartbeat 却未检查原到期时间这一差异。") `AbortSignal` 也只是协作式通知，处理器是否及时停止外部副作用取决于具体实现。现有材料未包含表结构与测试，无法确认并发去重、双 worker 竞争、旧 token 防覆盖及事务回滚已有真实行为保障。
