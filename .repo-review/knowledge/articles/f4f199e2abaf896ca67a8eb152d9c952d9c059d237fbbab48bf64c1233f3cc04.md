# jobs · 模块理解

jobs 模块以 SQLite 仓储和单任务执行器组成耐久任务系统：仓储维护入队、租约、尝试审计、结果、重试和控制状态，执行器驱动处理器、心跳与协作取消。需注意角色输出写入与任务成功提交的租约校验强度不同；数据库唯一约束、停机排空及处理器取消合同仍待其他材料确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 作用与职责边界

jobs 模块把捕获后的异步工作保存为可恢复、可审计的持久任务。仓储承担状态机、租约和并发门禁，执行器负责领取任务、选择处理器并回报结果；没有注册对应处理器时，任务会转为运行态后以配置错误终结，避免永久悬挂。[持久任务仓储子知识 ↗](9d5c793b6d7b58169c99020cd4b43385481ae6f4993191ce0ede652222f5b3e7.md#enqueue_claim "概括仓储的持久状态机职责，并为模块职责划分提供子知识导航。")[耐久任务执行器子知识 ↗](1d70075b60c7660214e91309d7365796a2cb2e28e87cd2a80353598c7007a359.md#execution "概括执行器领取并运行单个任务的职责，支持仓储与执行器的分工说明。")[任务领取与处理器选择 ↗](../../../apps/server/src/jobs/worker.ts#L47 "直接支持执行器领取任务、无任务返回及缺失处理器以配置错误终结的流程。")

<a id="lifecycle"></a>
## 从入队到完成的主要流程

入队会对输入引用生成稳定摘要，并按工作区、类型、摘要及角色、策略版本查询重复任务；事务内入口允许证据与首个任务共同提交。[任务入队与重复查询 ↗](../../../apps/server/src/jobs/repository.ts#L187 "支持稳定输入摘要、版本化重复查询、事务内入队和 INSERT OR IGNORE 的实现说明。") 领取过程会回收过期租约、记录旧 attempt 的过期结果，并为新尝试创建令牌和审计记录；转为 running 时还会检查租约尚未到期，执行器随后周期心跳并调用 handler。[租约领取与尝试审计 ↗](../../../apps/server/src/jobs/repository.ts#L261 "支持过期租约回收、尝试上限、条件领取、令牌生成及 attempt 审计记录。")[处理器执行与心跳续租 ↗](../../../apps/server/src/jobs/worker.ts#L72 "支持 AbortController、运行态转换、周期心跳、handler 调用和成功提交的执行路径。")

处理结果存在两层校验：角色输出与运行 trace 在 lease token 匹配且任务仍为 running 时写入，并不检查 `lease_expires_at`；任务最终成功提交则额外要求租约未过期且未被取消。因此，旧执行者在租约刚过期但尚未被重新领取的窗口内可能写入输出，却不能据此完成任务；这取代了“输出始终在有效租约下持久化”的旧结论。[角色输出与成功提交校验 ↗](../../../apps/server/src/jobs/repository.ts#L452 "直接展示角色输出只校验令牌与 running 状态，而 succeed 额外校验租约到期时间，支持修正两者校验强度相同的旧结论。") 失败路径会脱敏错误，并仅对 transient、bad output 在次数上限内指数退避重试。[分类失败与退避重试 ↗](../../../apps/server/src/jobs/repository.ts#L581 "支持错误脱敏、失败类别计数、重试上限、指数退避和终态选择。")

<a id="control_limits"></a>
## 控制、跨模块关系与限制

取消与人工重试通过 request ID、负载摘要和 generation 校验抵御重复或过期控制。运行中取消由仓储设置标志，再由 Worker 中止当前进程内的 controller；成功任务要求补偿，失败、取消或等待决策的任务才能递增 generation 后重新排队。[取消与人工重试状态机 ↗](../../../apps/server/src/jobs/repository.ts#L674 "支持控制请求幂等、generation 校验、成功态补偿要求以及新 generation 重试规则。")[运行中取消传播与停机 ↗](../../../apps/server/src/jobs/worker.ts#L137 "说明 Worker 在仓储返回 cancelling 后中止活跃处理器，并显示 stop 仅广播中止信号。")

当前 `processOne` 每次只领取一个任务，吞吐量依赖上层并发或多个 worker。心跳失败、显式取消和 `stop` 都主要依靠 `AbortSignal` 协作；`stop` 只广播中止而不等待排空。[处理器执行与心跳续租 ↗](../../../apps/server/src/jobs/worker.ts#L72 "支持 AbortController、运行态转换、周期心跳、handler 调用和成功提交的执行路径。")[运行中取消传播与停机 ↗](../../../apps/server/src/jobs/worker.ts#L137 "说明 Worker 在仓储返回 cancelling 后中止活跃处理器，并显示 stop 仅广播中止信号。")[异常分类与失效租约处理 ↗](../../../apps/server/src/jobs/worker.ts#L97 "支持停机中断转为 transient、取消异常分类以及失败落库遭遇失效租约时不覆盖新状态。") 此外，`INSERT OR IGNORE` 的完整幂等语义取决于未提供的表唯一索引，不能仅凭本模块断言终态任务再次入队的行为。[任务入队与重复查询 ↗](../../../apps/server/src/jobs/repository.ts#L187 "支持稳定输入摘要、版本化重复查询、事务内入队和 INSERT OR IGNORE 的实现说明。")
