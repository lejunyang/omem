# jobs · 模块理解

jobs 模块以 SQLite 保存任务、generation、attempt 与租约，worker 负责按 kind 分派、心跳和协作取消。仓库通过 token 阻止旧租约写回本地状态，但成功与失败提交的期限校验不对称，worker 的初始化与成功收尾也并非都统一转换为 stale；外部副作用仍依赖具体 handler 的取消、幂等或补偿设计。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-boundary"></a>
## 职责、持久化边界与审计

该模块把持久化状态机与业务执行分开：`JobRepository` 管理任务、generation、attempt、租约和结果，`DurableJobWorker` 每次领取一项任务并调用对应 kind 的 handler。入列会规范化输入摘要，按 workspace、kind、摘要及角色与策略版本执行 `INSERT OR IGNORE`，并可嵌入捕获事务，使证据与首个任务共同提交；但缺少表结构材料，不能仅据此确认数据库级唯一约束。[任务入列与捕获事务 ↗](../../../apps/server/src/jobs/repository.ts#L187 "支持输入摘要、版本组合插入与查询，以及捕获证据和首个任务共同提交；该范围未展示表级唯一约束。")

领取时创建的 attempt 保存模型、effort 和各类哈希。仓库另提供运行 trace 与结构化角色输出保存接口，并要求当前 lease token；其中输出保存还要求任务处于 running。给出的通用 worker 没有调用这些接口，因此是否形成完整角色审计取决于具体 handler 或上层运行时。[租约领取与尝试创建 ↗](../../../apps/server/src/jobs/repository.ts#L261 "支持候选筛选、过期 attempt 回收、次数限制、租约签发、过滤参数拼接和 attempt 指纹保存。")[运行追踪与角色输出接口 ↗](../../../apps/server/src/jobs/repository.ts#L404 "支持仓库可按当前租约补充运行 trace，并仅为 running 任务保存角色输出；用于限定这些能力并非通用 worker 自动执行。")

<a id="execution-flow"></a>
## 领取、执行与收尾边界

仓库筛选到期且未取消的任务，结束过期 attempt、检查当前 generation 次数上限，再签发 token 和新 attempt。worker 随后查找 handler、登记本地控制器、标记 running 并设置周期心跳；未注册 handler 会按 config 失败处理。需要注意，正常 handler 分支中的 `active.set` 与 `markRunning` 位于 `try/finally` 之前：若 `markRunning` 抛出，当前实现会直接向外抛错，且不会由该 finally 清理 active 记录。[租约领取与尝试创建 ↗](../../../apps/server/src/jobs/repository.ts#L261 "支持候选筛选、过期 attempt 回收、次数限制、租约签发、过滤参数拼接和 attempt 指纹保存。")[worker 分派、心跳与收尾 ↗](../../../apps/server/src/jobs/worker.ts#L47 "支持 handler 分派、markRunning 位于 try/finally 之前、心跳、成功与失败路径，以及仅在失败收尾捕获 stale lease 的具体控制流。")

成功写回要求 token、状态和租约期限有效且未取消；失败写回只校验 token 与 leased/running 状态，再脱敏错误并决定退避或终止。由此替代旧结论“成功和失败受相同租约期限约束”：租约仅过期而未被重领时，成功会被拒绝，失败仍可能更新；重新领取改变 token 后，两条仓库写回路径才都会失效。[成功与失败写回规则 ↗](../../../apps/server/src/jobs/repository.ts#L538 "支持成功路径检查租约期限和取消状态、失败路径仅检查 token 与状态，以及错误脱敏和分类重试。")

<a id="control-and-recovery"></a>
## 取消、重试、停机与 stale 处理

取消与人工重试使用 expectedGeneration 防止旧请求修改新一代任务，并按 workspace、requestId 与载荷摘要尝试重放响应或报告冲突。运行中取消先持久化意图，再中断当前进程内的 handler；成功任务要求补偿，显式重试递增 generation 并保留历史 attempt。材料未给出控制请求表约束，不能确认并发重复请求的最终行为。[取消与代际重试控制 ↗](../../../apps/server/src/jobs/repository.ts#L674 "支持响应重放、载荷冲突、generation 校验、取消状态转换和显式重试；该范围不包含数据库唯一约束。")

`stop()` 只设置停机标志并中断活动控制器，调度方仍须停止后续 `processOne()` 调用并等待在途 Promise。还需收窄旧结论“所有失租收尾都直接报告 stale”：仓库 token 校验确实阻止旧租约写回；但 worker 只在异常处理中的 `fail` 抛出 `STALE_JOB_LEASE` 时返回 stale。若 handler 正常返回后 `succeed` 抛错，它会先被包装为执行失败并再次调用 `fail`，只有后者也报 stale 才转为 stale，其他收尾错误仍会继续抛出。[worker 分派、心跳与收尾 ↗](../../../apps/server/src/jobs/worker.ts#L47 "支持 handler 分派、markRunning 位于 try/finally 之前、心跳、成功与失败路径，以及仅在失败收尾捕获 stale lease 的具体控制流。")[worker 取消与停止接口 ↗](../../../apps/server/src/jobs/worker.ts#L137 "支持先持久化取消意图再中断本地 handler，以及 stop 只设置标志并发送中断信号。")

<a id="limits-and-relations"></a>
## 跨模块关系与保证范围

handler 通过 `AbortSignal` 接收心跳失效、取消或停机信号，但该合同只是协作机制；若具体处理器不检查信号，外部写入仍可能继续。仓库的 token 校验只能保护本地任务状态，不能撤销外部副作用，也不能据此声称 exactly-once，业务侧仍需稳定幂等键或补偿。[成功与失败写回规则 ↗](../../../apps/server/src/jobs/repository.ts#L538 "支持成功路径检查租约期限和取消状态、失败路径仅检查 token 与状态，以及错误脱敏和分类重试。")[处理器取消信号合同 ↗](../../../apps/server/src/jobs/worker.ts#L18 "支持 handler 接收 AbortSignal，并说明 worker 可配置 kinds 与 jobIds 领取过滤条件。")

此外，显式空 `kinds` 或 `jobIds` 会进入空 `IN` 列表拼接分支，其业务语义没有定义；失败写回是否也应拒绝已过期但尚未重领的租约，同样需要明确合同并以真实 SQLite 行为测试验证。[租约领取与尝试创建 ↗](../../../apps/server/src/jobs/repository.ts#L261 "支持候选筛选、过期 attempt 回收、次数限制、租约签发、过滤参数拼接和 attempt 指纹保存。")[成功与失败写回规则 ↗](../../../apps/server/src/jobs/repository.ts#L538 "支持成功路径检查租约期限和取消状态、失败路径仅检查 token 与状态，以及错误脱敏和分类重试。")
