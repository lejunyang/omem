# 单用户 SQLite 存储门面与捕获主流程

负责单用户数据库生命周期，并编排多模态捕获、不可变修订、来源更新传播、当前版本检索、恢复、通知和旧式待办。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="composition"></a>
## 定位与事务边界

Store 是当前单用户 SQLite 基础的聚合入口：它创建私有数据目录和数据库、执行迁移、限制文件权限，并把同一连接交给应用、作业、输入聚合、运行时请求和来源画像服务。由 `tx` 包裹的数据库操作使用 `BEGIN IMMEDIATE`，成功提交、异常回滚；这并不覆盖所有写入，例如图片资产在事务前落盘，读取通知状态也直接更新数据库。团队数据库与租户强制隔离仍是后续能力。[Store 初始化与事务方法 ↗](../../../apps/server/src/store.ts#L1 "支持单用户 SQLite 定位、共享仓储连接和 tx 的提交回滚语义，同时将该语义限定为显式调用 tx 的流程。")

<a id="capture"></a>
## 捕获与更新传播

捕获先计算稳定摘要。图片必须是可往返编码的非空 Base64，解码后不超过 5 MB，并按 PNG、JPEG 或当前兜底的 WebP 字节签名检查；通过后按内容哈希保存。由于文件写入发生在数据库事务开始前，后续数据库失败可能留下未被修订引用的资产。捕获最多生成 2000 个固定片段。[图片校验与片段预算 ↗](../../../apps/server/src/store.ts#L99 "支持图片在事务前校验和落盘、内容寻址保存，以及每次捕获最多生成 2000 个片段的边界。") producer 与 eventId 回执提供事件幂等；内容指纹相同也复用当前 head，否则追加不可变 revision。[捕获幂等与不可变修订 ↗](../../../apps/server/src/store.ts#L141 "支持事件回执冲突检查、相同内容复用，以及新 revision 和 fragment 的追加流程。")

新修订会容错生成来源画像、切换 head、推进 validity epoch，并在已有来源更新时使旧依赖和相关记忆失效、排入刷新作业。[来源状态与更新传播 ↗](../../../apps/server/src/store.ts#L221 "支持画像容错、head 与有效性代次更新、旧记忆依赖失效及刷新作业入队。") 原始材料进入声明提取队列，而 `producerKind=derived` 被排除，避免派生内容自循环成为独立证据。[声明提取队列边界 ↗](../../../apps/server/src/store.ts#L353 "支持派生材料不进入声明提取队列，而其他捕获携带来源有效性代次排队。")

<a id="retrieval_restore"></a>
## 检索与恢复边界

搜索会转义 LIKE 特殊字符，最多返回 50 行，并通过 source head 连接限定当前修订。[当前版本搜索 ↗](../../../apps/server/src/store.ts#L469 "证明搜索转义 LIKE 通配符、通过 source head 限定当前修订并设置 50 行上限。") 恢复要求 expectedHead 同时等于当前 head 和目标变更的 after，随后把旧修订、片段及出边复制为更高版本并切换 head，历史不会被删除。[新修订式恢复 ↗](../../../apps/server/src/store.ts#L493 "支持恢复的并发前置条件、旧内容复制、出边重映射，并显示该路径只直接更新 sources.head。") 该路径没有展示普通 capture 所执行的 source_state 更新、画像生成、依赖失效和刷新作业，因此恢复后的派生状态是否应同步仍不能确定。

<a id="tasks"></a>
## 旧式待办与提醒

`createTask` 校验可选证据后写入当前任务及首个 `task_revisions`；状态切换以 expectedVersion 乐观加锁，并追加下一版修订。到期扫描只处理开放且已经到期的任务，通知去重键包含任务与版本。[待办版本与到期提醒 ↗](../../../apps/server/src/store.ts#L640 "支持首个任务修订、状态乐观锁、后续修订及按任务版本生成去重提醒的实现说明。") 这些代码说明了实现意图，但本批材料没有对应数据库行为测试，尚不能确认默认列、双表一致性及提醒去重均已被实际断言。
