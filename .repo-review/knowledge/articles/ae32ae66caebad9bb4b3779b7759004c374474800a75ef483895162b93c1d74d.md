# 个人记忆的持久化与版本生命周期

Store 是服务端单用户 SQLite 数据层的统一入口，负责捕获材料、生成不可变修订与片段、维护证据关系和历史恢复，并将来源更新、学习任务、通知及待办状态纳入可追踪的事务流程。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="foundation"></a>
## 单用户存储与事务边界

`Store` 以 SQLite 作为当前单用户持久化基础；团队级权限隔离仍属于后续迁移范围。参考 [单用户存储边界 ↗](../../../apps/server/src/store.ts#L4 "支持 SQLite 是当前单用户基础、团队级权限留待后续迁移的说明。")

启动时会迁移数据库、创建受限权限的资源目录，并装配应用、作业、输入聚合、Agent 请求和来源画像等仓储服务。参考 [存储服务初始化 ↗](../../../apps/server/src/store.ts#L45 "支持数据库迁移、资源目录创建和各仓储服务装配的论断。") 写操作可由 `BEGIN IMMEDIATE` 事务包裹，成功时提交、异常时回滚；变更记录还会同步生成站内通知，形成统一追踪入口。参考 [事务与变更通知 ↗](../../../apps/server/src/store.ts#L74 "支持事务提交回滚，以及变更记录与站内通知同步写入的论断。")

<a id="capture-flow"></a>
## 从捕获输入到不可变修订

捕获会先校验图片大小、Base64 内容和文件签名，再以内容哈希保存资源。参考 [图片校验与资源保存 ↗](../../../apps/server/src/store.ts#L102 "支持图片大小、编码和文件签名校验，以及按内容哈希写入资源目录的说明。") 相同采集器事件通过载荷摘要识别重复或冲突；未命中事件回执时，只与来源的**当前头修订**比较指纹，因此内容即使等同于更早历史版本，也仍可能形成新修订。参考 [事件回执与当前头去重 ↗](../../../apps/server/src/store.ts#L143 "支持事件冲突检测，以及未命中回执时仅比较来源当前头指纹的去重边界。")

```mermaid
flowchart LR
  A[捕获输入] --> B[校验事件与当前头]
  B --> C[创建不可变修订]
  C --> D[拆分证据片段]
  D --> E[更新来源头版本]
  E --> F[记录变更并入列任务]
```

新内容按文本段落、链接或图片说明生成片段，单次上限为 2000 个；来源画像采用尽力而为策略，画像失败会留痕但不阻断材料入库。参考 [修订、片段与来源画像 ↗](../../../apps/server/src/store.ts#L197 "支持不可变修订创建、片段预算、画像失败不阻断以及来源头更新的流程。")

<a id="refresh-and-learning"></a>
## 来源更新与学习队列

已有来源产生新版本时，旧依赖会被标为过期，相关记忆被置为失效，同时创建刷新记录并入列后续作业。参考 [来源更新传播 ↗](../../../apps/server/src/store.ts#L246 "支持旧依赖失效、记忆作废、刷新记录创建及后续作业入列。")

刷新记录会在重新处理前冻结本次受影响的记忆集合，避免重复投递时因部分记忆已经修复而缩小核验范围。作业成功入列仅表示等待处理；是否真正应用，要依据当前依赖和独立核验后的实际状态判断。参考 [受影响集合与刷新核对 ↗](../../../apps/server/src/learning/refresh.ts#L6 "解释刷新模块如何冻结受影响记忆，并区分任务入列和实际修复完成。")

普通原始材料会进入声明抽取队列；模型摘要、反思等派生材料被排除，避免把派生结论再次当作独立证据形成自循环。参考 [学习任务入列规则 ↗](../../../apps/server/src/store.ts#L348 "支持派生材料跳过抽取、原始材料携带有效性纪元进入声明抽取队列。")

<a id="evidence-history-tasks"></a>
## 证据浏览、历史恢复与待办

读取接口可返回修订、顺序片段及双向引用关系，文本搜索仅查询各来源的当前头版本。人工建立的引用关系只表达关联，不自动证明目标内容支持来源论断。参考 [证据关系与当前版本搜索 ↗](../../../apps/server/src/store.ts#L387 "支持修订和片段读取、双向引用查询、人工引用语义及仅搜索当前头版本。")

恢复操作不会覆盖历史，而是在确认当前头仍是待撤销版本后，把旧修订复制为新的头版本。修订内部引用会借助新旧片段映射迁移；映射之外的跨修订或外部目标则保留原片段标识。参考 [保留历史的恢复流程 ↗](../../../apps/server/src/store.ts#L488 "支持恢复前的头版本校验、旧修订片段映射，以及未映射目标继续保留原引用。")

待办创建时可以关联**已存在的证据片段**，这里只检查片段能否读取，并不校验它是否属于当前头修订、是否仍然有效或是否支持待办内容。状态更新使用期望版本进行乐观并发保护，并为创建和状态变化追加待办修订及通知。参考 [待办证据检查与版本化更新 ↗](../../../apps/server/src/store.ts#L645 "支持待办创建时只检查证据片段存在性，以及状态更新的乐观并发控制、修订和通知记录。")
