# Hook 捕获暂存队列

以本地文件队列承接带来源事件标识的捕获输入，通过稳定摘要、原子写入、容量限制和严格回执校验，实现可重放且避免静默丢失的投递。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-enqueue"></a>
## 用途与入队流程

`HookSpool` 解决外部 Hook 已到达、下游捕获服务却暂不可用时的可靠暂存问题。记录保留生产者、事件标识、完整捕获输入、内容摘要和创建时间；目录与记录分别限制为 `0700`、`0600`。文件名由生产者和事件标识的稳定摘要确定，因此同一事件重复到达时可直接返回原记录；若事件标识相同而负载摘要不同，则明确报冲突，避免覆盖证据。写入先落随机临时文件并 `fsync`，再重命名和同步目录，以降低半写文件风险。[暂存记录与安全目录 ↗](../../../apps/server/src/inputs/spool.ts#L20 "说明暂存记录保存的幂等字段、捕获内容以及目录权限初始化。") [幂等入队与原子写入 ↗](../../../apps/server/src/inputs/spool.ts#L69 "支持稳定键、负载冲突检测以及临时文件同步后重命名的写入流程。")

<a id="capacity-and-flush"></a>
## 容量、保留期与投递边界

入队前会统计 JSON 记录数量与字节数，默认上限为 1000 条和 50 MB；超限只追加受大小约束的告警并抛出专用容量错误，不会淘汰旧记录。保留期默认七天，但超期记录也只是产生告警，并不会自动删除。[容量与保留期处理 ↗](../../../apps/server/src/inputs/spool.ts#L139 "说明默认容量阈值、超限告警，以及超期记录仅告警而不清理。") 刷新按创建时间顺序、受 `limit` 限制地串行发送；只有回执中的生产者、事件标识和负载摘要全部吻合才删除文件。任一发送或校验失败都会记录结果并停止本轮，因此后续事件不会越过失败项。该实现没有并发消费者锁，材料也未展示损坏 JSON 的隔离恢复。[顺序刷新与回执校验 ↗](../../../apps/server/src/inputs/spool.ts#L197 "支持刷新时严格匹配回执、成功后删除、失败即停止的行为。")
