# Hook 捕获持久缓冲与可靠投递

以生产者、事件号和内容摘要建立本地磁盘缓冲，在上游暂不可用时保存 CaptureInput；通过容量保护、原子写入、回执核验和顺序停止降低静默丢失或错误确认风险。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_identity"></a>
## 事件身份与幂等入列

`HookSpool` 用生产者和事件号的稳定摘要确定记录路径，使事件身份与随机生成的记录编号分离。[稳定事件路径 ↗](../../../apps/server/src/inputs/spool.ts#L69 "支持文件路径由生产者和事件号的稳定摘要确定。") 入列要求捕获来源同时提供 `collectorId` 和 `eventId`；已有同路径记录且载荷摘要一致时返回重复结果，摘要不同时拒绝为事件冲突。该检查提供单进程常规幂等，但不能据此推断多进程竞争下严格的先写者胜出。[入列校验与重复检测 ↗](../../../apps/server/src/inputs/spool.ts#L126 "支持缺少事件身份时拒绝、相同载荷返回重复以及不同载荷报冲突。")

<a id="durability_and_capacity"></a>
## 持久性与容量边界

构造时把缓冲目录设为 `0700`；写入使用 `0600` 随机临时文件，完成文件级 `fsync` 后重命名并尝试同步目录。目录同步在部分平台不受支持时会被忽略，因此持久性仍受文件系统语义影响。[目录权限与原子写入 ↗](../../../apps/server/src/inputs/spool.ts#L61 "支持目录和文件权限、文件同步、重命名及目录同步降级的说明。") 入列还会统计现有 JSON 记录数量和字节数，默认限制为 1000 条与 50 MB；超限时写容量告警并抛出专用错误。[容量统计与告警 ↗](../../../apps/server/src/inputs/spool.ts#L139 "支持默认条目数和字节上限、容量告警内容及超限错误。")

<a id="flush_semantics"></a>
## 投递、回执与失败顺序

待投递记录按创建时间排序，超过默认七天只产生告警而不自动删除。刷新逐条调用发送器，只有回执中的生产者、事件号和载荷摘要均与本地记录一致才删除文件；首个异常会终止本轮处理，保留失败项及后续项目供重试，因此保证顺序的同时存在队头阻塞。[保留期与顺序刷新 ↗](../../../apps/server/src/inputs/spool.ts#L174 "支持超期告警、按时间排序、回执核验、成功删除及失败后停止。")
