# 检索候选段落的决策筛选

`assessPassages` 位于常规检索与后续阅读之间。它把问题和候选段落交给决策服务，用多维概率计算省略、判断、优先级与注入风险；需要父级上下文时，还可扩读并重新评估。默认共享 8 秒预算，`budgetMs: 0` 则不限时。有限预算下，服务未就绪、首条决策不可用或预算耗尽会触发保守回退；取消信号会在关键节点中止处理。小模型或混合模型批次只提供建议，全部候选拟被删除时也放弃过滤。非仅建议批次的排序由 `promotedOrder` 承接，未评估尾部保持原顺序。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-input"></a>
## 作用与输入边界

`assessPassages` 接收决策服务、用户问题和已经召回的 `RetrievalHit[]`。可选项 `sourceIdFor` 为日志补充来源标识；`onInput` 在每次正式决策前收到该命中；`readContext` 提供扩展上下文；`budgetMs` 控制整批共享的延迟预算；`signal` 用于取消处理。后台预热首条命中时不会触发 `onInput`。参考 [评估状态与调用选项 ↗](../../../apps/server/src/decision/passages.ts#L45 "支持 passageState 的输入结构、材料判断说明，以及 assessPassages 的可选项、返回状态与默认预算。") [预算模式与未就绪回退 ↗](../../../apps/server/src/decision/passages.ts#L88 "支持默认 8 秒预算、budgetMs 为 0 时不限时，以及有限预算下未就绪时后台预热首条命中并原样返回候选。")

`passageState` 为每条命中组装正文、标题和标题路径，并附上周边上下文、命中范围、原始定位、材料类型与材料描述。随状态发送的说明要求模型只依据材料原文判断；标题、概念和用途属于检索元数据，摘录没有覆盖完整实现时应按缺少背景处理。这里处理的是检索后的候选，不负责原始召回。函数最终返回命中列表、逐条决策和服务状态。参考 [评估状态与调用选项 ↗](../../../apps/server/src/decision/passages.ts#L45 "支持 passageState 的输入结构、材料判断说明，以及 assessPassages 的可选项、返回状态与默认预算。") [汇总日志与最终返回 ↗](../../../apps/server/src/decision/passages.ts#L248 "支持全删弃权、未评估尾部拼接，以及 assessment 和最终返回值的组成。")

<a id="policy-flow"></a>
## 从多维概率到筛选策略

`passagePolicy` 从各维度概率派生省略标记、判断、优先级和潜在注入标记。候选受保护的条件是以下任一概率达到 0.2：前提矛盾、需要父级上下文、相关性不确定。只有模型不是 0.8B、候选不受保护，且“无关”概率至少为 0.98、“无答案”和“无证据”概率都至少为 0.95 时，`omit` 才为真。参考 [段落策略与四态判断 ↗](../../../apps/server/src/decision/passages.ts#L8 "支持上下文保护、省略阈值、判断顺序、优先级和潜在注入标记的计算条件。")

判断共有四种。需要父级上下文的概率达到 0.5 时为 `needs_context`；否则，满足省略条件时为 `strong_unrelated`。若“直接回答”概率至少为 0.9，且“陈述证据”与“条件证据”的概率之和至少为 0.9，则为 `strong_answer`；其余情况为 `uncertain`。上下文需求在判断顺序中优先于省略和强答案。优先级取“直接回答”和“前提矛盾”的较大值，再加背景相关概率的 0.35 倍。注入尝试概率达到 0.8 时标记 `possibleInjection`，本文件没有据此删除候选。参考 [段落策略与四态判断 ↗](../../../apps/server/src/decision/passages.ts#L8 "支持上下文保护、省略阈值、判断顺序、优先级和潜在注入标记的计算条件。")

<a id="degradation-output"></a>
## 上下文扩读、延迟控制与保守回退

默认情况下，整批评估共享 8 秒预算。若服务未就绪，函数会原样返回全部命中；服务处于空闲且存在首条命中时，还会在后台发起一次预热。`budgetMs` 可改写预算，设为 `0` 表示不限时：函数不再因服务未就绪而提前回退，并向决策请求传入 `timeoutMs: 0`。参考 [预算模式与未就绪回退 ↗](../../../apps/server/src/decision/passages.ts#L88 "支持默认 8 秒预算、budgetMs 为 0 时不限时，以及有限预算下未就绪时后台预热首条命中并原样返回候选。")

函数在开始处理、进入每个候选以及发起每次正式决策前检查 `signal`，并把它继续传给决策服务。有限预算下，候选按原顺序逐条评估，每次决策都与整批剩余时间的计时器竞争；不限时模式直接等待决策结果。结果为 `needs_context` 且提供了 `readContext` 时，函数会在允许的情况下读取扩展命中；扩展正文与原文不同才会再次决策。重新决策成功后，扩展命中替代原命中，并将 `contextRead` 记为 `expanded`；找不到可用扩展时记为 `unavailable`，有限预算不足或重新决策未返回时记为 `budget`。首条评估没有结果会直接退回原列表；后续没有结果的已评估项仍会保留。参考 [取消、延迟预算与上下文扩读 ↗](../../../apps/server/src/decision/passages.ts#L108 "支持取消信号检查与传递、限时或不限时决策、逐项处理、needs_context 扩读和重新评估，以及首条决策不可用时的回退。")

只要批次含 0.8B 结果或出现多个模型身份，所有结果就降为 `advisoryOnly`，既不省略也不重排。其他批次先排除满足省略条件的项，再调用 `promotedOrder`。调用时会传入策略优先级，并把 `strong_answer` 判断作为提升信号；该函数内部如何排序不在本文件中。未评估的尾部命中仍按原顺序接在后面。若所有已评估项都拟被删除，函数放弃过滤并返回原始 `hits`。参考 [仅建议模式与决策数组 ↗](../../../apps/server/src/decision/passages.ts#L171 "支持小模型或混合模型批次不执行省略和重排，以及 decisions 与 kept 的组装方式。") [逐项日志与排序交接 ↗](../../../apps/server/src/decision/passages.ts#L195 "支持弃权状态、逐项记录内容，以及向 promotedOrder 传入优先级和强答案提升信号。") [汇总日志与最终返回 ↗](../../../apps/server/src/decision/passages.ts#L248 "支持全删弃权、未评估尾部拼接，以及 assessment 和最终返回值的组成。")

在 `kept` 非空的正常组装分支中，最终保留且成功评估的命中会增加 `decision` 路由和 `assessment`。其中包括模型、优先级、判断、输入摘要与字符数、输入目标、上下文读取结果、仅建议状态及各维答案。`decisions` 为每个已评估项保留结果和最终策略。逐项日志记录保留或省略原因及评估维度，汇总日志记录评估数量、未评估尾部数量和回退状态。若 `kept` 为空，函数直接返回未增强的原始 `hits`，不会由本函数附加上述路由和评估字段。参考 [仅建议模式与决策数组 ↗](../../../apps/server/src/decision/passages.ts#L171 "支持小模型或混合模型批次不执行省略和重排，以及 decisions 与 kept 的组装方式。") [逐项日志与排序交接 ↗](../../../apps/server/src/decision/passages.ts#L195 "支持弃权状态、逐项记录内容，以及向 promotedOrder 传入优先级和强答案提升信号。") [汇总日志与最终返回 ↗](../../../apps/server/src/decision/passages.ts#L248 "支持全删弃权、未评估尾部拼接，以及 assessment 和最终返回值的组成。")
