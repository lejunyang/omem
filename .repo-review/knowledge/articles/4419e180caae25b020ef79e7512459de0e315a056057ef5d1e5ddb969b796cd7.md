# assistant · 模块理解

assistant 模块是 Web 与 Lark 共用的可追溯助理编排层：它持久化并串行处理回合，从统一检索端口取得固定原始片段，通过真实 ACP 生成结构化回复，再由服务器独立校验引用、可见性和事项变更。当前具备补充检索、取消、重试及有限范围的回执恢复，但仍受单用户存储、ACP-only 传输以及证据返回和跨实例幂等合同未确认等限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-boundaries"></a>
## 作用与边界

assistant 并非单纯的模型调用封装，而是 Web 与 Lark 共用的执行边界，统一负责会话上下文、只读检索、低风险事项治理、回合持久化与降级。[统一助理运行时职责 ↗](../../../apps/server/src/assistant/runtime.ts#L185 "说明 Web 与 Lark 共用的运行时承担上下文、检索、治理、持久化和降级职责。") 模型只能引用宿主提供的证据并请求声明过的受管工具，不能自行扩大数据可见范围或取得写权限。[模型端口权限边界 ↗](../../../apps/server/src/assistant/runtime.ts#L82 "支持模型只能使用宿主提供的上下文、证据和受管工具。")

生产适配器目前只接受 ACP profile；缺少配置或使用 CLI transport 时会明确报告模型不可用，不生成伪兜底答案。[ACP 生产传输约束 ↗](../../../apps/server/src/assistant/acp-model.ts#L10 "支持生产模型只接受 ACP profile，并在配置缺失或传输不支持时明确失败。") 确定性模型仅供测试编排与引用链路，不能证明真实模型质量或外部传输可用。[确定性测试模型边界 ↗](../../../apps/server/src/assistant/default-model.ts#L7 "说明固定模型仅供测试，生产不得用它替代真实 ACP 或掩盖模型不可用。")

<a id="turn-and-evidence-flow"></a>
## 回合与证据流程

输入先持久化，并按外部事件标识识别重复投递；同一会话的新消息会取消旧回合，再沿进程内 Promise 链顺序执行。正常和重复返回目前都向公开结果传入空证据数组。[回合入队与会话内串行 ↗](../../../apps/server/src/assistant/runtime.ts#L224 "支持输入先持久化、重复投递识别、取消旧回合、顺序执行以及结果路径传入空证据数组。") 运行时读取本会话已完成历史，将初始检索与上一轮工作上下文按片段去重；只有模型请求补充检索时，宿主才再检索一轮并把合并结果截为最多 24 条。[上下文合并与补充检索 ↗](../../../apps/server/src/assistant/runtime.ts#L456 "说明历史读取、上一轮工作上下文、单次补充检索及 24 条截断的实际位置。")

检索候选必须回指不可变 Fragment，供回答返回原始证据。[统一检索与固定证据锚点 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持检索候选回指不可变 Fragment，使上层能够引用原始证据。") 运行时还会确认当前 head、排除派生材料并执行会话可见性过滤；群聊未配置策略时默认不暴露证据。[证据补全与可见性过滤 ↗](../../../apps/server/src/assistant/runtime.ts#L654 "支持运行时排除非当前 head、派生或不可见证据，并在群聊缺少策略时默认拒绝暴露。") 最终引用以本轮实际提供的证据建立白名单，写操作答复则根据持久化事项和真实执行结果重建。[真实回执答复与引用白名单 ↗](../../../apps/server/src/assistant/runtime.ts#L581 "支持写操作答复依据实际事项重建，并只保存本轮允许集合中的模型引用。")

<a id="governed-actions-and-recovery"></a>
## 事项治理与失败恢复

事项写入采用“模型建议、服务器裁决”。创建前以确定性规则确认用户确有记录或指派意图，咨询问句不能成为写入授权。[确定性事项创建意图 ↗](../../../apps/server/src/assistant/runtime.ts#L126 "支持咨询式问句不构成写入授权，只有明确记录或指派表达才允许创建事项。") 更新事项还需重新核对原消息中的动作、事项可见性、版本和带时区的明确时间。[事项更新与时间校验 ↗](../../../apps/server/src/assistant/runtime.ts#L693 "支持更新动作、可见性、版本和改期时间均由服务器重新校验。") 创建流程虽会验证模型引用及上一轮上下文，当前治理提案的 evidence 实际只采用新捕获的 owner 直接消息；这替代了“已校验上下文也会进入提案”的旧结论。[创建事项的实际证据来源 ↗](../../../apps/server/src/assistant/runtime.ts#L821 "支持引用和上一轮上下文会被验证，但治理提案当前只提交 owner 直接消息作为 evidence。") 只有记忆服务返回真实 task receipt 才能报告创建成功。[事项提案评估与成功回执 ↗](../../../apps/server/src/assistant/runtime.ts#L890 "支持创建提案交由记忆服务评估，且只有真实任务回执才能确认创建成功。")

回执恢复范围也有限：检查只适用于带外部事件 ID、且提案标识匹配 `assistant-task` 前缀的应用回执。[已提交事项回执检查范围 ↗](../../../apps/server/src/assistant/runtime.ts#L301 "限定恢复检查只处理带外部事件 ID 且匹配 assistant-task 提案前缀的应用回执。") 对未完成回合，恢复流程首先查找所属会话；找不到会话便直接跳过，不重新执行，也不计入 recovered。只有仍能找到会话的回合才会按“命中回执则完成，否则尝试执行”分流。[未完成回合恢复流程 ↗](../../../apps/server/src/assistant/runtime.ts#L366 "支持恢复先检查所属会话、跳过无所属会话的回合，再对其余回合按已提交回执或重新执行分流。") 因此，旧稿中“其余未完成回合都会尝试重新执行”的结论已被上述条件化表述替代。

<a id="progress-and-limits"></a>
## 当前进展、关联与限制

该模块已贯通会话路由、统一检索、ACP 模型与记忆治理，并以固定 Fragment 串联回答和事项证据。不过底层 SQLite 明确仍是单用户基础，团队级权限强制属于后续迁移，不能把当前可见性机制描述成完整租户隔离。[单用户 SQLite 基础 ↗](../../../apps/server/src/store.ts#L2 "界定当前存储面向单用户，团队级权限强制仍属于未来迁移。")

公开 `AssistantTurnResult.evidence` 仍有合同疑点：结果映射只返回调用方传入的数组，而正常与重复路径都传入空数组，实际选中证据则保存在回合记录中。[公开回合结果映射 ↗](../../../apps/server/src/assistant/runtime.ts#L964 "支持公开 evidence 仅原样返回调用参数，而事项和降级信息来自持久化回合。") 此外，现有材料只能证明进程内会话串行及有限范围的回执查询，尚不足以确认跨实例重复投递和事项创建全过程具有数据库级原子保证。
