# assistant · 模块理解

assistant 模块编排会话回合、证据检索、ACP 调用与受治理的任务写入；服务器控制可见性、引用、取消和副作用。外部事件可提供去重及有限的 receipt 恢复能力，但无事件标识的回合不具备同等恢复保证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role_and_boundaries"></a>
## 职责与信任边界

模块会在调用模型前持久化回合，并按外部事件标识去重；同一会话的新消息会取消旧回合，再沿队列串行执行。[回合入队与会话串行化 ↗](../../../apps/server/src/assistant/runtime.ts#L198 "支持模型调用前持久化、外部事件去重，以及同一会话中新消息取消旧回合并串行执行。") 证据是否可见及用户是否明确交办任务均由服务器判定，而非听从模型声明；未注入策略时群聊默认看不到证据，咨询句式也会优先排除任务意图。[可见性与任务意图规则 ↗](../../../apps/server/src/assistant/runtime.ts#L90 "支持群聊证据默认拒绝、服务器掌握可见性判断及咨询表达优先于任务词的边界。")

<a id="context_and_model"></a>
## 上下文检索与模型协议

执行时只回放当前会话已完成的近期历史，把本轮检索、上一轮选中证据和会话范围内的 owner 纠正组合为模型上下文；模型不可用会令回合保持 pending，取消则记录为 cancelled。[回合上下文与模型失败处理 ↗](../../../apps/server/src/assistant/runtime.ts#L421 "支持当前会话历史、检索证据、上一轮上下文和纠正的组合，并区分取消、模型不可用与普通错误。") 检索优先使用统一 `RetrievalPort`，旧测试才回退到 Store，检索结果与上一轮证据都须再次经过可见性过滤。[检索、纠正与上一轮证据 ↗](../../../apps/server/src/assistant/runtime.ts#L604 "支持统一检索端口优先、Store 回退、纠正容错、上一轮证据复用及可见性过滤。")

ACP 适配器仅接受 ACP profile，并限制历史和证据长度、声明证据不是指令。[ACP 上下文构造 ↗](../../../apps/server/src/assistant/acp-model.ts#L24 "支持 ACP profile 限制、历史与证据预算，以及不得执行证据内指令的约束。") 模型必须返回包含回答、引用及可选任务请求的 JSON；实际调用设有输出长度上限，非取消的传输错误转为模型不可用。[ACP 输出协议与调用 ↗](../../../apps/server/src/assistant/acp-model.ts#L80 "支持 JSON 输出合同、真实 ACP 调用、输出长度限制和传输失败转换。")

<a id="governed_actions"></a>
## 引用与任务副作用治理

运行时只保留实际提供给模型的引用；创建任务还须通过明确意图检查和 `MemoryService` 治理，并在工具执行与最终持久化前设置取消栅栏。[任务调用与持久化栅栏 ↗](../../../apps/server/src/assistant/runtime.ts#L494 "支持明确任务意图复核、MemoryService 治理、引用白名单、取消栅栏及有限的答复改写条件。") 无既有引用的直接 owner 交办可先捕获本轮原话；模型指定的引用若在当前证据和上一轮上下文均无法解析，则拒绝写入。[任务证据与治理结果 ↗](../../../apps/server/src/assistant/runtime.ts#L701 "支持引用解析、直接消息捕获、提案标识规则，以及不会统一触发答复改写的多种治理拒绝结果。")

此前“所有治理拒绝都会改写答复”的结论已被替代：目前只有缺少明确任务意图且未创建任务时追加未创建提示；缺少治理服务、证据不可解析、未自动应用或治理异常仍可能保留模型原答复。[任务调用与持久化栅栏 ↗](../../../apps/server/src/assistant/runtime.ts#L494 "支持明确任务意图复核、MemoryService 治理、引用白名单、取消栅栏及有限的答复改写条件。")[任务证据与治理结果 ↗](../../../apps/server/src/assistant/runtime.ts#L701 "支持引用解析、直接消息捕获、提案标识规则，以及不会统一触发答复改写的多种治理拒绝结果。")

<a id="recovery_and_limits"></a>
## 取消、恢复与实现限制

外部信号、会话控制器和回合定时器会合并为取消信号，模型等待另以独立 `Promise.race` 超时避免永久挂起。[合并取消信号 ↗](../../../apps/server/src/assistant/runtime.ts#L393 "支持外部信号、会话控制器与回合定时器的合并取消行为。")[独立模型等待超时 ↗](../../../apps/server/src/assistant/runtime.ts#L576 "支持模型调用通过独立计时器竞速，并在中止时快速结束等待。")

此前“恢复机制能识别所有已提交副作用”的结论已被替代：receipt 检查只在回合带外部事件标识时执行，并按该标识匹配任务提案；只有匹配到已提交 receipt 的回合才直接补齐完成状态，其他未完成回合会重新执行。因此，无外部事件标识的回合不具备同等的副作用恢复识别保证。[有限的 receipt 恢复机制 ↗](../../../apps/server/src/assistant/runtime.ts#L261 "证明只有带外部事件标识的回合才查询匹配的 application receipt，并据此决定补齐完成或重新执行。") 确定性模型仅供测试，生产缺少 ACP 模型时必须如实报告不可用。[确定性模型的测试限定 ↗](../../../apps/server/src/assistant/default-model.ts#L7 "证明确定性模型只用于测试，生产缺少真实模型时不得用固定答案伪装成功。")
