# assistant · 模块理解

assistant 模块是多消息入口共享的证据型助理编排层，统一处理会话、检索、模型调用、引用约束和事项治理。模型仅能提出候选回答与操作，证据可见性、写入许可和成功回执均由服务端控制；真实生产装配情况仍需入口代码验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role_and_boundary"></a>
## 职责与信任边界

assistant 模块以 `AssistantRuntime` 收敛 Web、Lark 等入口，负责上下文组装、只读检索、模型端口调用、事项治理、轮次持久化与降级。[统一助理运行时职责 ↗](../../../apps/server/src/assistant/runtime.ts#L192 "支持多个消息入口共享运行时，以及上下文、检索、事项治理、持久化和降级等职责。") 但“生产入口已经装配真实 ACP 模型”并非本批材料可确认的事实：当前只能确认架构要求生产装配**应**注入 `AcpAssistantModel`，而确定性模型只应作为测试替身；此前把预期装配写成既成事实的结论由此被替代。[确定性测试模型的装配边界 ↗](../../../apps/server/src/assistant/default-model.ts#L7 "支持确定性模型只用于测试、生产装配应注入真实 ACP 模型；该注释表达设计要求而非实际入口装配证据。")

模型只能引用宿主传入的证据并请求受管工具，不能自行读取任意数据或取得权限。证据可见性由服务端根据会话及来源策略判断；未注入策略时，群聊默认拒绝全部证据。[模型端口与证据可见性合同 ↗](../../../apps/server/src/assistant/runtime.ts#L86 "支持模型只能使用宿主提供的证据和受管工具，以及群聊在缺少可见性策略时默认拒绝证据。") 每日消息配方也只是交办、讨论、等待和回顾的处理策略，捕获内容本身不授予执行权限。[每日消息工作流策略 ↗](../../../apps/server/src/assistant/message-workflows.ts#L1 "支持四类消息处理策略及捕获消息不构成操作授权的边界。")

<a id="turn_and_evidence_flow"></a>
## 轮次、检索与引用流程

请求先持久化轮次；外部事件号用于重复投递去重，同一会话串行执行，新消息会取消旧轮次，预先取消的请求不会启动模型。[轮次入列、去重与串行执行 ↗](../../../apps/server/src/assistant/runtime.ts#L231 "支持先持久化轮次、外部事件去重、新消息取消旧轮次和预取消栅栏。") 运行时只回放当前会话中已完成的历史，并把本轮检索结果与先前工作上下文按 fragment 去重合并。[当前会话历史与证据合并 ↗](../../../apps/server/src/assistant/runtime.ts#L463 "支持只选择当前会话已完成历史，并合并本轮检索结果和先前工作上下文。") 该工作上下文来自最近一个具有非空已选证据的完成轮次，而非机械使用紧邻轮次。[最近有效工作上下文 ↗](../../../apps/server/src/assistant/runtime.ts#L751 "支持向前寻找最近一个具有非空已选证据的完成轮次。")

统一检索端口要求候选始终指向不可变 fragment，使回答能够回到原始材料。[统一检索与不可变证据锚点 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持检索实现可替换，同时要求结果指回不可变 fragment。") 运行时回读时还会拒绝非当前 head、派生 revision 或标记为派生的内容；语义片段只作为长原文中的定位线索。[当前原始证据回读 ↗](../../../apps/server/src/assistant/runtime.ts#L770 "支持拒绝非当前 head 和派生 revision，并说明语义焦点只用于定位长原文。") 最终引用再经过白名单过滤，只保留实际提供给模型的 fragment。[最终引用白名单 ↗](../../../apps/server/src/assistant/runtime.ts#L602 "支持最终只保留运行时实际提供给模型的证据引用。") 首轮可提出最多三条补充检索词，宿主补检、去重并限量后只再生成一次；取消、模型不可用和普通生成异常分别进入取消、待重试和降级路径。[补充检索与生成异常分类 ↗](../../../apps/server/src/assistant/runtime.ts#L494 "支持检索词去重限量、最多一次补检，以及取消、待重试和降级的不同处理。")

<a id="model_and_task_governance"></a>
## 模型适配与事项治理

`AcpAssistantModel` 负责裁剪历史与证据、组装可信上下文、当前任务、时间及工作流规则，再调用 ACP；缺少 Profile 或配置为非 ACP transport 时会明确报告不可用，不返回伪造答案。[ACP 助手模型适配器 ↗](../../../apps/server/src/assistant/acp-model.ts#L12 "支持提示词组装职责，以及缺少 Profile 或非 ACP transport 时明确拒绝。") ACP 底层另行负责超时和取消：超时会终止子进程，取消信号会请求会话取消并停止进程。[ACP 超时与取消处理 ↗](../../../apps/server/src/agents.ts#L121 "支持 ACP 子进程的超时终止、取消请求传播和预取消检查。") 权限请求和补充输入请求不会自动获准，文本输出也受字符上限约束。[ACP 权限拒绝与输出限制 ↗](../../../apps/server/src/agents.ts#L180 "支持权限和补充输入请求不会自动获准，并说明文本输出字符上限。") 模型与推理强度则依据会话实际暴露的配置选项校验，不支持的值直接拒绝；这替代了此前把能力校验、权限、输出和超时笼统归入同一代码范围的表述。[模型与推理强度能力校验 ↗](../../../apps/server/src/agents.ts#L301 "支持根据会话配置选项校验模型和推理强度，并拒绝不受支持的设置。")

事项写入仍需服务端二次治理。创建必须匹配用户明确交办意图，咨询式问题不能仅凭模型请求落库。[确定性创建意图检测 ↗](../../../apps/server/src/assistant/runtime.ts#L130 "支持创建事项不能只信任模型请求，咨询式或缺少明确交办意图的输入应被拒绝。") 更新要求原消息包含对应动作表达，目标事项可见且版本一致；改期时间必须来自原消息并带时区，随后才捕获变更指令并调用任务命令。[事项更新治理流程 ↗](../../../apps/server/src/assistant/runtime.ts#L702 "支持动作表达、任务可见性、版本、时间来源校验以及捕获变更指令后调用任务命令。") 状态、动作、版本及跟进时间由共享合同严格约束。[共享事项动作与跟进合同 ↗](../../../packages/contracts/src/task-flow.ts#L3 "支持事项状态、动作、版本、带偏移时间和 IANA 时区等严格约束。") 只要存在 mutation，最终回复就丢弃模型的推测性成功文本，改用真实工具结果和存储状态生成回执。[依据真实结果生成操作回执 ↗](../../../apps/server/src/assistant/runtime.ts#L588 "支持发生写操作时丢弃模型的推测性成功文本，改由真实工具结果和存储状态组织回复。")

<a id="progress_and_limits"></a>
## 恢复能力与尚未闭环的边界

运行时已实现创建事项回执驱动的重试和重启恢复：发现匹配的持久化回执时直接完成轮次，否则重新执行。当前查询依赖外部事件号，并只匹配 `assistant-task` 创建 proposal 前缀，因此材料不足以证明更新事项具有相同的崩溃恢复幂等性。[创建回执恢复机制 ↗](../../../apps/server/src/assistant/runtime.ts#L308 "支持恢复时查询持久化回执避免重复创建，同时揭示查询依赖事件号和创建 proposal 前缀。")

创建事项会验证模型引用，并尝试把当前所有者消息捕获为直接证据；捕获失败被视为非致命，最终提交给 `MemoryService.evaluate` 的 `evidence` 只取直接消息证据，已验证的背景引用不会随 proposal 提交。[创建事项的直接证据处理 ↗](../../../apps/server/src/assistant/runtime.ts#L832 "支持验证模型引用、捕获失败继续评估，以及最终 proposal 只提交直接消息证据。") 这意味着“创建必然携带成功捕获的原始证据”这一旧结论也应被替代：捕获可能失败，空证据时是否拒绝、等待确认或自动应用，仍取决于未提供的 `MemoryService` 策略实现。现有材料也未包含测试源码或真实 ACP 检查报告，不能据实现分支宣称取消、恢复、群聊拒绝及双 mutation 输出均已获得行为验证。
