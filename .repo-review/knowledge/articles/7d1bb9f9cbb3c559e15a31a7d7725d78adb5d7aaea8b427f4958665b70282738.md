# 服务端基础能力与跨域验收

本专题汇集持久化、受控学习、检索评测与仓库关系能力。材料明确当前是单用户 SQLite 基础，团队级权限与依赖自动重新核验尚未实现；跨进程迁移、任务竞争和崩溃接管则仅属尚未验证，不能据现有测试断言其能力状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="foundation"></a>
## 存储、迁移与事务基础

`Store` 以单用户 SQLite 为当前基础，承载不可变修订、变更与通知 outbox；团队级权限执行仍属于后续迁移。[单用户 SQLite 存储边界 ↗](../../../apps/server/src/store.ts#L1 "支持当前为单用户 SQLite 基础、团队权限执行仍属后续迁移的范围说明。") 旧库升级保留来源、片段、引用、资产和任务并维持旧 API 读取；未来版本数据库会被拒绝且不受修改。[旧数据库数据与 API 兼容 ↗](../../../apps/server/tests/migrations.test.ts#L148 "支持旧数据库迁移后保留数据身份、历史内容、资产、引用和旧 API 读取能力。")[未来数据库版本保护 ↗](../../../apps/server/tests/migrations.test.ts#L616 "支持拒绝高于程序支持版本的数据库且保持文件和未知结构不变。")

memory 在 change 写入失败、task 在 outbox 写入失败时，实体、修订、回执与通知相关记录整体回滚；测试还明确证明成功的 **task** 请求重放只保留一份落库效果。[应用事务回滚与 task 重放 ↗](../../../apps/server/tests/migrations.test.ts#L647 "支持 memory 与 task 故障路径整体回滚，并将成功重放幂等严格限定为该测试实际覆盖的 task application。") 这取代了旧稿将成功重放幂等同时泛化到 memory 与 task 的结论。

<a id="learning-flow"></a>
## 捕获、策略与依赖刷新

HTTP capture 经独立提取、核验会话处理，受支持提案可自动形成任务；持久核验工作可顺序重启续跑，人工重放不增加任务或回执。[学习流水线与顺序重启续跑 ↗](../../../apps/server/tests/learning-pipeline.test.ts#L65 "支持独立提取和核验、自动应用、顺序重启续跑及重放去重；不用于证明跨进程竞争。") 策略依据负责人身份、转发、证据完整性、语义范围和冲突进行自动应用、保留、拒绝或待决策分流；批量超预算时整体停放，同实体重复项按一次影响处理。[提案证据与风险分流 ↗](../../../apps/server/tests/proposal-policy.test.ts#L160 "解释明确负责人、未知身份、转发、证据异常、语义泛化和跨来源冲突的策略结果。")[批量影响门禁与去重 ↗](../../../apps/server/tests/learning-pipeline.test.ts#L285 "支持不同实体批量超预算时整体待决策，以及同实体重复项按一次影响处理。")

来源更新会排入依赖刷新任务，但当前任务以 `NOT_IMPLEMENTED` 失败并记录 `needs_review`、受影响数量和对象，因此自动重新核验尚未实现。[依赖刷新尚未实现 ↗](../../../apps/server/tests/learning-refresh.test.ts#L152 "支持来源更新后的刷新任务以未实现失败并记录待复核对象，界定自动重新核验的当前缺口。")

<a id="retrieval-quality"></a>
## 检索与质量闭环

业务文档捕获后生成轻量画像，原始片段可用于关键词检索；画像区分当前事实、未来计划、回指和代码示例，覆盖不足时保留 partial 状态与可读片段。[来源画像与话语分类 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L64 "支持捕获后的关键词检索，以及当前事实、未来计划、回指和代码示例的分类。")[部分画像与原始片段 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L250 "支持画像覆盖不足时记录 partial 和缺口，同时 revision 仍有可读片段。") 检索只返回 active 记忆，会话字段不是项目边界，只有标为受信的项目才收窄结果；但这不是团队权限保证。[项目可信门控与有效记忆 ↗](../../../apps/server/tests/retrieval-keyword.test.ts#L38 "支持会话上下文不作为项目过滤、仅受信项目收窄记忆，以及 invalidated 记忆被排除。")

质量数据集经人工确认后冻结并可检出篡改，评测分别衡量引文定位、语义支持、事实槽、证据覆盖、任务完成和不必要打扰。[冻结数据集与分维度评测 ↗](../../../apps/server/tests/quality-evaluation.test.ts#L50 "支持数据集人工确认、摘要防篡改和六类质量维度的独立统计。") 引文即使能定位，若结论与原文相反，仍会被判为 contradicted，避免把“找到原文”误当成“论断受支持”。[定位与语义支持分离 ↗](../../../apps/server/tests/quality-evaluation.test.ts#L201 "支持引文可定位但结论相反时，定位通过而语义判为 contradicted。")

<a id="review-progress"></a>
## 仓库关系与已知边界

association seed 携带代码路径、符号、意图及多类文档引用；同步生成独立意图片段和关系，支持幂等、missing 保留、seed 移除后失效及双向查询。[关系 seed 结构 ↗](../../../apps/server/tests/review-relations.test.ts#L57 "支持 seed 明确包含代码路径、符号、意图及需求、决策、研究和测试引用。")[关系同步与 API 投影 ↗](../../../apps/server/tests/review-relations.test.ts#L207 "支持独立意图片段、多引用建边、幂等、缺失边、失效和双向查询，同时界定尚未逐条核对符号来源。") 代码换头后旧关系默认隐藏但可历史追溯，新 head 不自动继承旧边；固定证据可按 revision 与 fragment 读取。[代码换头后的关系失效 ↗](../../../apps/server/tests/review-migration.test.ts#L306 "支持旧关系转 stale、默认隐藏和历史可查，并说明新 head 不自动继承关系。")[固定证据读取 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L232 "支持按 revision 和 fragment 读取固定文本，未知目标返回空结果。")

现有材料明确团队级权限与自动重新核验尚未实现；对于多进程迁移、worker 竞争、租约接管和阶段间崩溃，只能说尚未验证，不能断言功能不存在。跨 revision 的符号重定位及 seed 到声明符号的一一对应也仍缺直接测试。
