# 记忆提取、复核与来源更新流水线

以持久作业串联记忆候选提取、独立复核、批量策略应用和来源更新重核验，并保留模型运行证据与错误分类。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="jobs-context"></a>
## 作业角色与可信上下文

构造函数强制 extractor、verifier 的 bundle profile 与配置一致，并让一个持久 worker 只处理提取、复核和依赖刷新三类作业；模型、effort 与阶段哈希组成执行指纹。[学习流水线角色与 worker 初始化 ↗](../../../apps/server/src/learning/pipeline.ts#L65 "支持 profile 一致性校验、限定作业种类和执行指纹构造。") 上下文会验证输入 revision 仍是 source head、sourceId 与 validity epoch 均未漂移，否则以 `STALE_JOB_INPUT` 拒绝旧任务。会话或应用上下文不会被冒充为可信项目，因此 `project_id` 保持空且 `project_trusted=false`。[修订新鲜度与项目可信边界 ↗](../../../apps/server/src/learning/pipeline.ts#L180 "支持输入 head、sourceId、epoch 校验，以及不把会话上下文当作可信项目。") 每个 fragment 再按 ordinal 对回原始 part，使说话人、回复关系、时间、引用/转发和 producer kind 随材料进入模型；图片必须能从资产库读取。[逐片段 provenance 上下文 ↗](../../../apps/server/src/learning/pipeline.ts#L220 "支持 fragment 对回 part、传递逐部分来源信息和加载图片资产。")

<a id="extract-verify"></a>
## 提取、独立复核与批量应用

提取阶段调用 extractor，校验 ProposalBatch、保存 trace 和 observations；有 proposal 才入列 verifier，无 proposal 则以 abstentions 收敛来源刷新记录。错误会先脱敏、分类，再写回刷新状态。[候选提取阶段 ↗](../../../apps/server/src/learning/pipeline.ts#L420 "支持 extractor 调用、输出保存、观察记录、verifier 入列及异常回写。") 复核阶段不信任队列里裸传的候选，而是校验父作业关系、已存输出 schema、内容摘要、job_id 和 bundle 哈希，再规范化 proposal 标识并应用已确认纠正。[提取输出完整性校验 ↗](../../../apps/server/src/learning/pipeline.ts#L457 "支持复核前核验父作业、输出 schema、摘要、job 和 bundle provenance。") verifier 必须逐项覆盖且 proposal_digest 完全匹配；之后整批调用 `evaluateBatch`，统一去重影响范围并决定自动应用、等待决策或拒绝，避免把超预算变更拆成多个小操作绕过策略。[独立复核与整批策略评估 ↗](../../../apps/server/src/learning/pipeline.ts#L498 "支持复核覆盖和摘要校验，以及 ChangeSet 级批量评估和结果分类。")

<a id="refresh-runtime"></a>
## 来源更新和运行边界

来源更新先记录受影响记忆；若目标 revision 已不再对应有效 source state，则直接把此次刷新标为 superseded，否则用与捕获阶段相同身份入列 extractor，避免产生第二套重复记忆。[来源更新重核验入列 ↗](../../../apps/server/src/learning/pipeline.ts#L126 "支持记录依赖刷新、处理已过期 revision，并复用提取身份避免重复记忆。") 后台循环按轮询间隔处理作业并保存公开化错误；`drain` 最多处理指定数量，达到上限会报错。停止操作中止循环并停止 worker，状态仅报告是否运行、累计处理数和最近错误。[轮询、排空与停止控制 ↗](../../../apps/server/src/learning/pipeline.ts#L571 "支持处理计数、排空上限、后台轮询、错误状态及停止语义。")

该流水线与知识流水线共享角色网关和持久作业基础设施，但本文件处理的是结构化 memory proposal 及策略应用，不负责发布知识文章；两者不能从相似类名推断为互相调用。
