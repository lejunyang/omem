# 学习提取、复核与刷新流水线

该模块在持久任务系统上编排记忆提取、独立复核和来源更新后的重核验。它先确认固定修订仍是当前有效输入，再构造包含逐部件来源信息的模型上下文；复核输出通过结构、覆盖和摘要绑定校验后，全部候选及其 verdict 会交给 MemoryService 整批决策，结果可能是自动应用、等待决定或拒绝，并非只有事实有效的候选才进入评估。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责、指纹与可追溯性

`LearningPipeline` 只领取提取、复核和依赖刷新三类任务，并要求 extractor、verifier 角色包与所选配置档一致。领取任务时构造的指纹包含模型、effort，以及由流水线版本、配置档和阶段名生成的三个哈希；先前关于这些哈希直接纳入实际提示词、技能包和工具内容的结论已被替代。[流水线任务范围与领取指纹 ↗](../../../apps/server/src/learning/pipeline.ts#L73 "支持角色配置校验、任务种类以及领取指纹仅由配置档、模型、effort和固定阶段种子构造的修正说明。") 实际角色运行产生的 prompt、skill、tool、bundle、context 摘要及技能和工具清单，会在保存运行输出时另行写入轨迹。[角色运行轨迹保存 ↗](../../../apps/server/src/learning/pipeline.ts#L331 "支持实际运行产生的提示词、技能、工具及上下文摘要和清单被另行持久化。") 错误在交给持久 worker 前会脱敏、压平并分类，但租约和任务状态由 worker 与仓库负责。[错误脱敏与分类 ↗](../../../apps/server/src/learning/pipeline.ts#L30 "支持公开错误清理、截断和故障类型分类的职责边界。")

<a id="context"></a>
## 输入有效性与证据上下文

模型执行前必须能解析任务引用的修订，并确认它仍是来源 head、sourceId 相符且 validity epoch 未变化，否则以过期输入中止。[当前修订与有效期校验 ↗](../../../apps/server/src/learning/pipeline.ts#L180 "支持模型运行前对来源 head、来源身份和 validity epoch 的一致性检查。") 会话等场景字段不被冒充为可信项目；上下文按 fragment ordinal 对齐原始 part，携带作者、回复、观察时间、转发或引用状态，图片还需从资产存储取得内容。[可信上下文与逐部件来源 ↗](../../../apps/server/src/learning/pipeline.ts#L206 "支持项目不可信边界、fragment 到 part 的对齐及图片资产装载流程。") 相关记忆限定在 workspace 且项目不可信的检索范围，失效记忆只可依据当前原始材料重核验。part 与 fragment 的对应规则手工镜像捕获层拆分顺序，若两侧规则漂移，逐部件 provenance 可能错配。[相关记忆检索与片段映射 ↗](../../../apps/server/src/learning/pipeline.ts#L284 "支持 workspace 范围召回和手工镜像捕获拆分顺序所形成的维护限制。")

<a id="stages"></a>
## 提取、独立复核与整批决策

提取阶段校验角色版本和 `ProposalBatch`，保存运行轨迹与 observations；有候选时创建 verifier 子任务，无候选或异常时则协调来源刷新记录。[提取阶段与复核入列 ↗](../../../apps/server/src/learning/pipeline.ts#L420 "支持提取输出校验、轨迹和观察记录保存、复核任务创建及刷新协调。") 复核前还验证父子任务关系、已存输出的 schema 与摘要、提取任务标识和角色包摘要，并由宿主重建候选身份、应用已确认纠正。[提取输出绑定与候选规范化 ↗](../../../apps/server/src/learning/pipeline.ts#L457 "支持复核前验证父任务、输出摘要和角色包摘要，并由宿主重建候选身份。")

verifier 返回后，宿主检查 assessment schema、候选一一覆盖以及 proposal digest 绑定。这里通过的是输出结构和绑定完整性，并不表示每个候选的事实或引用 verdict 都有效；所有候选都会连同各自 verdict 进入一次 `evaluateBatch`，由该服务产生自动应用、等待决定、拒绝等策略结果。先前“复核通过后才评估并应用”的表述因此被替代，整批评估本身也不保证发生应用。[复核覆盖校验与整批评估 ↗](../../../apps/server/src/learning/pipeline.ts#L498 "支持结构、覆盖和摘要绑定才是调用前门槛，以及所有候选连同各自 verdict 一并进入 evaluateBatch 的修正结论。") MemoryService 的结果合同同样明确区分多种策略，并允许超预算候选不应用而转入统一决策。[记忆评估策略结果 ↗](../../../apps/server/src/memory/service.ts#L16 "支持整批评估可返回自动应用、等待决定、拒绝等不同结果，且超预算项可以不应用。")

<a id="refresh-runtime"></a>
## 刷新、运行控制与当前限制

来源更新先记录受影响依赖；若目标修订已不是 head，则刷新被结算为 superseded，否则用与捕获链一致的身份重新入列提取。刷新记录变为 queued 只表示已排队，不代表复核或应用成功。[来源刷新记录与重新入列 ↗](../../../apps/server/src/learning/pipeline.ts#L126 "支持来源已前进时结算刷新、仍有效时排入提取，以及 queued 仅表示入列。") 运行接口支持单步、有限 drain、轮询、取消和停止；processed 只表示 worker 处理过任务，达到 drain 上限会明确报错。[流水线运行控制 ↗](../../../apps/server/src/learning/pipeline.ts#L571 "支持单步处理、有限排空、轮询、取消、状态统计与停止语义。") 当前 Store 以 SQLite 为单用户基础，不能据此宣称已有团队租户强制隔离。[单用户 SQLite 存储边界 ↗](../../../apps/server/src/store.ts#L1 "支持当前存储实现是单用户基础、团队约束仍属后续迁移的限制。") 给定材料未包含测试文件或真实 Agent CLI 检查记录，因此实现分支不能替代端到端验收证据。
