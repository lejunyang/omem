# 学习提取、复核与来源刷新流水线

该文件以持久化作业串联固定材料、角色模型运行、独立复核和记忆批量评估，并负责来源更新后的重核验、运行记录、错误归类及进程内生命周期管理。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-routing"></a>
## 职责与作业路由

`LearningPipeline` 编排提取、复核和来源依赖刷新。构造时核对 extractor、verifier 角色包所需 profile，并用模型、effort及提示词、技能、工具哈希形成作业指纹；worker 只领取三种指定作业。[流水线构造与任务限定 ↗](../../../apps/server/src/learning/pipeline.ts#L65 "支持角色配置核对、三类作业路由及运行指纹的说明。") `DurableJobWorker` 根据作业 kind 查找处理器，缺少处理器时以配置错误结束该次处理。[持久化 worker 的处理器选择 ↗](../../../apps/server/src/jobs/worker.ts#L47 "支持按作业类型选择处理器以及缺失处理器时记录配置错误的论断。") 流水线还会遮蔽常见密钥、压平错误文本并将异常归为输出、认证、瞬态、配置或永久错误；现有材料只证明分类本身，不能据此断言各分类如何决定重试。[公开错误清洗与分类 ↗](../../../apps/server/src/learning/pipeline.ts#L30 "支持错误脱敏、限长和失败类型划分，同时限定证据未展示分类对重试的具体影响。")

<a id="context-and-evidence"></a>
## 上下文与证据边界

角色运行前会解析 revision，并核对当前来源 head、sourceId 和 validity epoch；不一致即以 `STALE_JOB_INPUT` 拒绝，防止旧作业使用过期材料。[作业输入时效校验 ↗](../../../apps/server/src/learning/pipeline.ts#L180 "支持对 revision、来源 head、sourceId 和 validity epoch 的一致性检查。") conversationId 等上下文载体不会被当成可信项目绑定；材料携带固定 fragment、逐 part 的人物与时间等 provenance，图片还须从资产存储成功读取。[可信上下文与材料构造 ↗](../../../apps/server/src/learning/pipeline.ts#L206 "支持项目可信边界、逐片段 provenance 以及图片资产读取规则。") part 到 fragment 的序号映射按“文本段落、链接、图片”重建，并明确要求镜像 `Store.capture` 的拆分规则。[part 与 fragment 顺序映射 ↗](../../../apps/server/src/learning/pipeline.ts#L311 "支持映射必须镜像捕获拆分顺序，并说明规则变化可能导致 provenance 错配。") 但当前提供的 `store.ts` 范围未包含捕获实现，因此尚不能独立确认两端始终同步。

<a id="extract-verify-apply"></a>
## 提取、独立复核与批量应用

`saveRun` 将模型、effort、各类哈希、会话、技能、工具、用量、输出及完整 trace 交给作业仓储保存。[角色运行记录保存 ↗](../../../apps/server/src/learning/pipeline.ts#L332 "支持保存模型、哈希、会话、技能、工具、用量、输出和完整运行 trace 的论断。") 提取阶段解析 `ProposalBatch`、保存运行输出并记录 observations；存在 proposal 时派生 verifier 子作业，否则以 abstentions 收敛刷新记录。[提取阶段与复核任务派生 ↗](../../../apps/server/src/learning/pipeline.ts#L421 "支持提取输出解析、运行保存、观察记录以及有无 proposal 时的分支。") 复核前检查父子作业、输出 schema 和摘要，并仅验证已存 `bundleHash` 是否符合 64 位十六进制格式；这里不证明它与当前角色包身份或版本一致。[提取输出与哈希格式校验 ↗](../../../apps/server/src/learning/pipeline.ts#L458 "支持父子关系、输出摘要和 schema 检查，并准确限定 bundleHash 只接受格式校验。") verifier 必须覆盖全部 proposal 且摘要吻合，随后整批调用 `MemoryService.evaluateBatch`，再记录评估策略统计。[全覆盖复核与批量评估 ↗](../../../apps/server/src/learning/pipeline.ts#L505 "支持逐 proposal 覆盖及摘要检查、整批调用 MemoryService 和记录策略结果。") 结果合同区分自动应用、等待决定、拒绝等策略，并可标记整批预算导致的延迟；具体预算与事务规则仍不在当前材料中。[记忆评估结果合同 ↗](../../../apps/server/src/memory/service.ts#L18 "支持评估策略、冲突关联及整批预算延迟等返回语义。")

<a id="refresh-and-lifecycle"></a>
## 刷新闭环与运行边界

来源刷新先登记受影响项；若目标 revision 已不是当前 head，只能确认刷新记录以 `source_advanced` 原因收敛，不能由此推断关联记忆的具体推进方式。当前 head 则按与捕获相同的提取身份排队，避免启动另一套独立 extractor。[来源刷新排队与过期收敛 ↗](../../../apps/server/src/learning/pipeline.ts#L126 "支持 source_advanced 收敛、复用提取身份排队和刷新记录更新；不扩张解释内部关联记忆处理。") stale 且 invalidated 的依赖记忆会被召回为刷新上下文，[失效依赖记忆召回 ↗](../../../apps/server/src/learning/pipeline.ts#L146 "支持 stale 且 invalidated 的现有记忆进入刷新上下文。") 任务说明进一步要求仍受支持或已变化的结论更新同一 `memory_id`，不得复制既有目标。[同一记忆刷新约束 ↗](../../../apps/server/src/learning/pipeline.ts#L277 "支持更新同一 memory_id、保留作用域且不得复制既有刷新目标的明确任务要求。") `drain` 有明确上限；后台循环在空闲或出错后轮询，取消委托给 worker，状态仅反映本进程，停止时会中止循环并等待退出。[处理循环、取消与停止 ↗](../../../apps/server/src/learning/pipeline.ts#L572 "支持 drain 上限、轮询行为、进程内状态、取消委托和停止流程。")
