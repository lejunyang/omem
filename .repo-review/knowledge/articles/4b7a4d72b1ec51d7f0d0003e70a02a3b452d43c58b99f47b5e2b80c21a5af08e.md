# 可追溯知识章节的写作规范

该规范说明如何把固定材料组织成面向首次读者的中文 Wiki：正文需要解释问题、流程、关联与限制，将证据放在所支持的论断附近，并把无法确认的事项结构化记录。它规定的是知识作者的输出合同，不能单独证明宿主的引文提取、独立复核或发布能力已经实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

这套写作规范用于把零散材料整理成可独立阅读、能够追溯依据的知识文章。章节应解释功能为何存在、如何工作、与其他材料如何关联，以及当前进展和限制；派生总结只用于组织理解，不能脱离原始依据成为新的证据。参考 [可追溯章节目标 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/skills/omem-knowledge-writer/SKILL.md#L6 "支持知识章节需要解释作用、流程、关联、进展和限制，并且不能把派生总结当作独立证据。")

文章面向首次接触项目的读者，应先交代实际问题和使用场景，再说明流程与关键概念；标题按功能命名，不以文件路径、内部标识、日志或测试计数作为叙述主线。参考 [面向读者的表达要求 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/skills/omem-knowledge-writer/SKILL.md#L18 "支持首次读者导向、功能化标题、按需使用图表、证据标签位置以及选择最小连续代码范围等要求。")

<a id="writing-flow"></a>
## 从材料到可追溯正文

作者先覆盖任务指定的全部目标，再围绕概念组织少量章节。每节至少要有一处引用，每项引用也必须出现在对应句段中；引用材料时使用完整材料键和真实行号，正文保持 Markdown 形式。参考 [目标覆盖与引用规则 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/skills/omem-knowledge-writer/SKILL.md#L11 "支持目标覆盖、章节内就近引用、材料键与真实行号要求，也说明材料仅陈述宿主复制引文的合同。")

证据标签应放在其支持的论断附近，并且移除标签后句子仍然通顺。引用代码时，应选择足以支持论断的最小连续行范围；表格或 Mermaid 流程图只在确有助于说明关系时使用，不能为了形式堆砌结构。参考 [面向读者的表达要求 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/skills/omem-knowledge-writer/SKILL.md#L18 "支持首次读者导向、功能化标题、按需使用图表、证据标签位置以及选择最小连续代码范围等要求。")

<a id="boundaries"></a>
## 不确定性与能力边界

遇到歧义、背景缺失或需要用户选择的事项，应写入结构化问题，说明提出原因、下一步、是否阻塞以及关联证据；引用标签采用人读名称，并明确解释它支持附近哪项论断。参考 [问题与引用说明 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/skills/omem-knowledge-writer/SKILL.md#L13 "支持使用人读标签解释引用理由，并将歧义、背景缺失或待选择事项记录为结构化问题。")

这份材料描述的是知识作者应遵循的输入边界和输出规则。虽然规则提到宿主会从固定范围复制引文，但没有提供宿主代码、真实运行记录或独立复核结果，因此不能仅据此确认引文提取、语义核验和知识发布链路已经投入运行。参考 [目标覆盖与引用规则 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/skills/omem-knowledge-writer/SKILL.md#L11 "支持目标覆盖、章节内就近引用、材料键与真实行号要求，也说明材料仅陈述宿主复制引文的合同。")
