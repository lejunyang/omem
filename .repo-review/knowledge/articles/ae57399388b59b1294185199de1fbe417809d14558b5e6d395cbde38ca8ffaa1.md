# 会话渠道、可见性与群聊检索安全测试

以 Web API 和飞书运行时的集成场景验证服务端身份收口、群聊会话命名空间隔离、证据可见性过滤及中文关键词召回。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="web-hardening"></a>
## Web 入口不能伪造渠道身份

第一组测试从真实应用 HTTP 接口验证信任边界：客户端不能把 Web 会话伪造成飞书渠道或群组可见性，相关请求返回 400；即使提交攻击者 principal，合法 Web 请求最终仍由服务端固定为 `web`、`private` 和 `owner`。[Web 会话入口收口 ↗](../../../apps/server/tests/conversation-security.test.ts#L64 "支持伪造飞书渠道或群可见性被拒绝、服务端固定 Web 私有 owner 身份的论断。") 这防止不可信请求自行扩大检索作用域或冒充外部传输身份。测试使用本地应用与临时密钥，但未覆盖令牌认证、跨站请求、其他 API 路由、反向代理头或多用户租户隔离；现有断言体现的是单用户入口收口。

<a id="group-isolation-retrieval"></a>
## 群聊命名空间与证据过滤

第二组测试故意直接植入一个同 chatId 的伪造私有 `lark_group` 会话，并同时捕获无群聊绑定的私有证据与合法群聊证据。飞书事件到达后，运行时创建带连接版本线程命名空间的新 group 会话，不复用旧私有行；传给模型的证据只包含群聊片段。[群聊会话与私有证据隔离 ↗](../../../apps/server/tests/conversation-security.test.ts#L173 "支持运行时不复用伪造私有会话，并只向模型交付群聊范围证据的完整集成断言。") 这条链路联结 ConversationRouter、LarkRuntimeHost、MemoryService、Store 与模型端口，证明隔离发生在实际事件处理和检索交付路径，而非仅检查数据库字段。

<a id="cjk-boundaries"></a>
## 中文召回与剩余边界

第三组测试用不包含完整查询字面串的中文材料作为控制：基础整句搜索无法命中，而飞书群聊运行时通过关键词分词仍把该片段交给模型，说明中文召回依赖 KeywordRetrieval，而不是旧式整句 LIKE。[群聊中文关键词召回 ↗](../../../apps/server/tests/conversation-security.test.ts#L337 "支持整句 LIKE 控制失败而 KeywordRetrieval 路径成功召回中文片段的结论。") 当前覆盖均使用内存伪适配器与单个已绑定群聊；未验证真实飞书网络、消息发送失败、非 owner 发送者、线程回复、多绑定冲突、重复事件幂等、群聊证据误标后的处置，以及模型返回 citationIds 的授权复核。它也不证明语义检索或中文分词在所有短词、标点和混合语言下的质量。
