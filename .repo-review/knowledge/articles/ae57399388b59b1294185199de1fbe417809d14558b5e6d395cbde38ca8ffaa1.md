# 会话渠道、可见性与群组检索安全测试

覆盖 Web 会话参数收口、Lark 群聊会话命名空间隔离、私有证据过滤及中文关键词召回，验证伪造渠道或可见性不会绕过群组边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="web-boundary"></a>
## Web 入口的服务器端身份收口

Web 创建会话接口拒绝伪造的 Lark 群聊渠道和 `group` 可见性；即使同时篡改 principal，群组可见性仍返回 400。合法请求可以携带伪造 principal，但响应由服务器强制为 `channel=web`、`visibility=private`、`principalId=owner`。[Web 会话参数强制策略 ↗](../../../apps/server/tests/conversation-security.test.ts#L64 "支持伪造渠道和群组可见性被拒绝，以及服务器强制 Web、私有和 owner 身份。") 这验证了 Web 入口不信任客户端提交的渠道、可见性和主体字段，不过测试使用单用户 owner 语义，并不证明多租户授权已经实现。

<a id="group-isolation"></a>
## 群聊命名空间与证据过滤

测试先直接植入同一聊天下伪造的私有 `lark_group` 会话，再分别捕获无群聊绑定的私有证据和绑定该聊天的群组证据。[伪造会话与双范围证据夹具 ↗](../../../apps/server/tests/conversation-security.test.ts#L132 "说明测试如何设置同聊天的私有伪造会话、私有证据与合法群组证据。") Lark 事件处理后实际使用的是新建的群组会话，其 thread 带连接与版本命名空间，伪造私有行保持不变；送入模型的证据排除了私有片段，只包含群组片段。[群聊会话隔离与证据过滤断言 ↗](../../../apps/server/tests/conversation-security.test.ts#L232 "支持运行时新建群组范围会话、保留伪造行，并阻止私有证据进入模型。") 因而这里同时验证了会话复用隔离和检索结果的可见性过滤，而不是仅检查路由字段。

<a id="cjk-retrieval"></a>
## 中文关键词召回路径

另一用例构造不含字面查询串“复盘 周三”的中文群组片段，并先证明旧式整句 LIKE 搜索无法命中。[中文片段与整句搜索对照 ↗](../../../apps/server/tests/conversation-security.test.ts#L296 "支持固定查询并非材料原文子串，且旧式整句搜索不能召回该片段。") 相同查询经 Lark 群聊运行链进入 KeywordRetrieval 后，模型收到的证据包含该片段。[Lark 中文关键词召回断言 ↗](../../../apps/server/tests/conversation-security.test.ts#L367 "支持群聊事件经过运行链后，模型证据中确实包含目标中文片段。") 这说明中文分词检索参与了真实群聊召回路径；测试只验证一个固定短语和单个群组片段，未衡量排序质量、召回率或更复杂语言组合。
