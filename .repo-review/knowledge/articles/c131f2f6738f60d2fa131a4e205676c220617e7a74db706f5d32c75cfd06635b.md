# 统一检索如何连接知识、代码导航与助手证据

这组集成测试验证统一检索不只返回相关文本，还必须保留固定原文范围、版本与可见性；代码查询能区分定义和名称级调用候选；助手获得可读的知识背景，同时只用原始材料生成可落地引用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 它解决什么问题

同一问题可能同时命中原始材料、知识文章、代码结构和语义向量。测试用临时数据库装配 `Store`、`KnowledgeRepository` 与 `UnifiedRetrieval`，发布一篇带固定原文行号的“可靠配送”解释，并在结束时关闭索引、清理目录。参考 [统一检索测试装配 ↗](../../../apps/server/tests/retrieval-unified.test.ts#L20 "支持测试以临时存储、知识仓储和统一检索器建立真实集成环境，并负责资源清理。")

核心合同是：读者看到的是可读解释，但仍能回到文章修订版和精确原文范围；若引用所需片段对当前会话不可见，或主题路径不匹配，整条知识命中不能泄露。参考 [知识命中与可见性 ↗](../../../apps/server/tests/retrieval-unified.test.ts#L90 "支持知识解释保留文章定位、精确原文范围，并受片段可见性与主题路径约束。") 目标文件还直接连接 Markdown 分段、符号识别、局部重排和助手运行时，因此改检索投影看 `units`，改排序看 `relevance`/`rerank-passages`，改问答证据装配看 `AssistantRuntime`。参考 [检索相关模块入口 ↗](../../../apps/server/tests/retrieval-unified.test.ts#L5 "说明目标测试直接依赖检索器、分段、符号相关性、局部重排与助手运行时，是读者定位修改入口的依据。")

<a id="caller-flow"></a>
## 代表性调用：查找 reserveParcel 的调用方

测试先捕获一个定义文件，再捕获含导入、注释和三个真实调用的 `checkout.ts`，另加一个移动端调用；输入“哪些地方调用 `reserveParcel`”后，`search` 返回四个调用位置，前两项来自不同文件，匹配状态统一标为 `candidate`，路线为 `code-call-candidate`。显式传入 `codeIntent: callers` 得到同一结果，而 `definition` 会回到函数定义。参考 [调用方查询流程 ↗](../../../apps/server/tests/retrieval-unified.test.ts#L650 "支持代表性输入从捕获定义与调用文件，到自动或显式 callers 意图，再到候选行号、文件交错与 definition 分流的完整结果。")

这里的输出是**名称级调用候选**，不是类型解析后的完整调用图。测试还确认可见性过滤会限制结果范围，不存在的符号返回空；源文件换版删除调用后，当前结果只剩移动端，但旧目标仍可按旧修订读取。参考 [调用候选的范围与历史 ↗](../../../apps/server/tests/retrieval-unified.test.ts#L702 "支持调用方结果受可见范围约束、未知符号为空，并在源文件换版后保留旧修订证据但更新当前命中。")

<a id="boundaries"></a>
## 结构、版本与助手之间的边界

代码检索单位以完整操作为阅读边界：类方法命中会包含局部状态、分支和返回值，Markdown 则保留标题路径与表格结构，并忽略代码围栏里的伪标题。参考 [完整操作与文档结构 ↗](../../../apps/server/tests/retrieval-unified.test.ts#L466 "支持方法命中保留局部状态、分支和返回值，以及 Markdown 分段保留标题和表格语义。") 长方法不会只拿开头参与重排；测试让语义窗口命中末尾提交动作，确认局部片段进入重排且最终结果仍指向完整方法范围，中文概念别名也能定位英文写操作。参考 [长操作的局部重排 ↗](../../../apps/server/tests/retrieval-unified.test.ts#L734 "支持长函数末尾语义窗口进入重排、结果仍锚定完整方法范围，以及中文概念别名定位英文写操作。")

知识版本与当前投影分离：被引用原件变化后，旧文章修订仍可读取，但不再作为当前知识命中；未直接引用的研究输入变化会把文章标为 `needs-review`，显式失效则彻底移出召回。参考 [知识新鲜度与失效 ↗](../../../apps/server/tests/retrieval-unified.test.ts#L149 "支持引用原件变更会更新当前投影但保留历史修订，并区分待复核知识与显式失效知识。") 进入助手时，知识正文只作为可读背景，原始字节另行形成证据；测试断言模型能读到“只安排一次运输”，但可引用证据仍是 `seen(event.id)`，避免把派生解释冒充原始事实。参考 [助手背景与原始证据分离 ↗](../../../apps/server/tests/retrieval-unified.test.ts#L859 "支持助手接收知识解释作为背景，同时将固定原始字节作为独立可引用证据。")
