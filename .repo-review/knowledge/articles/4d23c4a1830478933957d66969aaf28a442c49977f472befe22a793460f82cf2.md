# 本地快速决策服务

DecisionService 是阅读和材料接入流程共享的可选本地决策侧车：它接收业务状态与多组选择题，串行交给常驻的 StartLux Python worker，并在校验返回结构后交还答案、置信度和模型运行信息。服务不写业务数据；服务关闭、运行环境未准备好或模型缺失，以及发生超时或协议异常时，原流程仍有降级空间。调用方还可为单次请求设置超时和取消信号，其中取消会以异常结束调用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_entry"></a>
## 解决什么问题

该服务是阅读和材料接入流程共享的可选本地决策侧车。调用方提交可 JSON 序列化的 `state` 和按名称分组的 `ChoiceQuestion`，服务返回判断结果，不写业务数据。配置为 `off`、服务已经关闭或运行条件不可用时，调用方可以继续原有流程。`status()` 提供当前状态、模型和生效模式，便于调用方观察侧车是否可用。参考 [服务定位与入口状态 ↗](../../../apps/server/src/decision/service.ts#L51 "支持该组件是无写入的可选侧车，以及关闭模式、状态读取和 decide 输入输出边界。")

<a id="request_flow"></a>
## 一次决策如何完成

调用 `decide` 后，服务先对 `{ state, questions }` 做 JSON 序列化并生成请求摘要，再把任务接到内部 Promise 队列。摘要计算发生在入队和内部 `try/catch` 之前，因此循环引用、`BigInt` 等不可 JSON 序列化的输入会直接拒绝，不会转成 `null`。轮到该任务时，服务启动或复用 worker，以一行 JSON 写入同一对象，再等待 stdout 的下一行 JSON。参考 [排队、传输与答案校验 ↗](../../../apps/server/src/decision/service.ts#L76 "支持请求摘要在入队前生成、队列内发送 JSON 行、逐题检查答案和候选概率，以及校验通过后更新状态并返回结果。")

原始响应先通过 Zod 模式校验。服务随后逐题确认答案存在、选择属于调用方给出的 `criteria`，并检查每个已定义候选项都有数值概率；全部通过后才返回 `DecisionResult`。参考 [排队、传输与答案校验 ↗](../../../apps/server/src/decision/service.ts#L76 "支持请求摘要在入队前生成、队列内发送 JSON 行、逐题检查答案和候选概率，以及校验通过后更新状态并返回结果。") [结果数值模式 ↗](../../../apps/server/src/decision/service.ts#L29 "支持置信度和概率值的范围，以及结果包含答案与模型运行信息。")

```mermaid
flowchart LR
  A[业务状态与选择题] --> B[串行队列]
  B --> C[启动或复用 worker]
  C --> D[JSON 行请求与响应]
  D --> E[结构和选项校验]
  E --> F[DecisionResult 或 null]
```

服务逐行尝试解析 worker 的 stdout；不可解析的行会被忽略。如果之后没有有效 JSON，当前等待不会因此立即失败，而会继续等待；超时、请求取消或进程退出时才会结束。启动阶段必须先收到 `{ ready: true }`。进程错误会拒绝当前等待；进程退出会清除 worker 引用并附带截取的 stderr 拒绝当前等待；ready 握手失败会释放 worker。参考 [worker 就绪协议 ↗](../../../apps/server/src/decision/service.ts#L246 "支持 stdout 逐行尝试 JSON 解析并忽略解析失败、进程错误与退出处理，以及 ready 等待和握手失败后的释放行为。")

<a id="runtime_boundaries"></a>
## 运行条件与降级边界

配置模式接受 `off`、`auto` 或 `decisionModelSizes` 中定义的固定尺寸。启动时只检查本地虚拟环境及已安装模型，`auto` 只枚举较小型号；未安装的模型不会在运行期下载。找到模型后，服务用 Python 启动 StartLux worker，并通过环境变量接入可选运行时。参考 [决策服务配置模式 ↗](../../../apps/server/src/decision/service.ts#L22 "支持 mode 仅接受 off、auto 和 decisionModelSizes 中定义的固定尺寸。") [本地模型发现与启动 ↗](../../../apps/server/src/decision/service.ts#L193 "支持运行时检查、自动模式的模型范围、离线模型发现、查询前后的取消检查、向离线查询传入信号，以及后续 Python worker 创建。")

请求由队列串行执行，同一时间只保留一个待响应请求。等待时间依次采用单次请求的 `timeoutMs`、服务配置的 `timeoutMs` 和默认值 120 秒；值为 `0` 时不设置超时定时器。超时会释放 worker，随后记录不可用状态并返回 `null`。只要服务尚未关闭，内部执行流程结束后都会设置 180 秒空闲回收。参考 [超时与取消等待 ↗](../../../apps/server/src/decision/service.ts#L165 "支持单次超时覆盖、配置超时、120 秒默认值、零值关闭计时，以及 ready 或响应等待建立后的取消监听与注册后复查。") [错误降级与空闲回收 ↗](../../../apps/server/src/decision/service.ts#L124 "支持取消时立即释放 worker、重置状态并重新抛出，其他内部错误返回 null，以及服务尚未关闭时在内部执行结束后设置 180 秒空闲释放。")

单次请求还可传入 `AbortSignal`。排队期间发生的取消，会在该请求轮到执行时检查。模型发现阶段会在每轮离线查询前检查信号，离线查询本身也接收该信号，枚举结束后还会再次检查，因此取消后不会继续创建 worker。ready 或响应等待建立后，取消监听会释放 worker；监听注册后还会立即复查信号，覆盖注册前后的竞态。异常进入 `decide` 的处理分支后，服务会再次释放 worker、把状态重置为 `idle`，再向调用方抛出取消异常。调用方需要单独处理取消。其他进入内部 `try/catch` 的错误会记录状态并返回 `null`，包括启动错误与 worker 错误，以及协议错误和结果校验错误。`close()` 会停止接收新请求，清理空闲定时器，释放当前 worker，并等待已串接的队列结束。参考 [超时与取消等待 ↗](../../../apps/server/src/decision/service.ts#L165 "支持单次超时覆盖、配置超时、120 秒默认值、零值关闭计时，以及 ready 或响应等待建立后的取消监听与注册后复查。") [本地模型发现与启动 ↗](../../../apps/server/src/decision/service.ts#L193 "支持运行时检查、自动模式的模型范围、离线模型发现、查询前后的取消检查、向离线查询传入信号，以及后续 Python worker 创建。") [worker 就绪协议 ↗](../../../apps/server/src/decision/service.ts#L246 "支持 stdout 逐行尝试 JSON 解析并忽略解析失败、进程错误与退出处理，以及 ready 等待和握手失败后的释放行为。") [错误降级与空闲回收 ↗](../../../apps/server/src/decision/service.ts#L124 "支持取消时立即释放 worker、重置状态并重新抛出，其他内部错误返回 null，以及服务尚未关闭时在内部执行结束后设置 180 秒空闲释放。") [worker 释放与服务关闭 ↗](../../../apps/server/src/decision/service.ts#L276 "支持拒绝待处理请求、强制终止子进程，以及 close 等待队列完成。")

结果模式要求置信度和每个概率值位于 0 到 1，但不检查概率总和是否等于 1。逐题校验要求所有已定义选项都有概率，也没有禁止 `probabilities` 出现 `criteria` 之外的键。这些数值适合排序或策略判断，单凭该服务的校验不能视为归一化概率分布。参考 [结果数值模式 ↗](../../../apps/server/src/decision/service.ts#L29 "支持置信度和概率值的范围，以及结果包含答案与模型运行信息。") [排队、传输与答案校验 ↗](../../../apps/server/src/decision/service.ts#L76 "支持请求摘要在入队前生成、队列内发送 JSON 行、逐题检查答案和候选概率，以及校验通过后更新状态并返回结果。")
