# 本地快速决策服务

DecisionService 是服务端共享的可选本地决策侧车：接收业务状态和多组选择题，串行交给常驻 StartLux Python worker，校验返回结构后交还答案、置信度及模型运行信息。它不负责写入业务数据；关闭或环境未准备，以及模型缺失、超时或协议异常时返回 null，让原有流程继续运行。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_entry"></a>
## 解决什么问题

该服务为材料接入、检索阅读等流程提供本地多选判断。调用方提交可 JSON 序列化的 `state` 和以名称分组的 `ChoiceQuestion`；服务只返回判断结果，不写业务数据，失败也不会阻断原流程。以材料接入接口为例，应用读取指定材料版本，拼接文本并截取前 12,000 个字符，再把标题、正文和是否截断交给 `decide`，最后连同服务状态返回。参考 [材料接入调用 ↗](../../../apps/server/src/app.ts#L702 "支持材料接入接口如何构造 state、调用 decide 并返回结果与状态。") [可选侧车定位 ↗](../../../apps/server/src/decision/service.ts#L47 "支持该服务不写业务数据、失败时保留原有流程以及关闭模式返回 null。") [序列化、请求队列与传输 ↗](../../../apps/server/src/decision/service.ts#L71 "支持输入在进入队列前生成 JSON 摘要，以及队列内再次序列化并发送请求的执行边界。")

<a id="request_flow"></a>
## 一次决策如何完成

代表性调用进入 `decide` 后，服务先对 `{ state, questions }` 做 JSON 序列化并生成请求摘要，再把任务接到内部 Promise 队列。摘要序列化发生在队列和内部 `try/catch` 之前，因此循环引用、`BigInt` 等不可 JSON 序列化的输入会直接拒绝，不会进入状态记录与 `null` 降级。轮到该任务时，它启动或复用 worker，以一行 JSON 写入同一对象，再等待 stdout 的下一行 JSON。原始响应先通过 Zod 校验；随后逐题确认答案存在、选项属于调用方给出的 `criteria`，且每个候选项都有数值概率，验证通过才返回 `DecisionResult`。参考 [序列化、请求队列与传输 ↗](../../../apps/server/src/decision/service.ts#L71 "支持输入在进入队列前生成 JSON 摘要，以及队列内再次序列化并发送请求的执行边界。") [答案完整性校验 ↗](../../../apps/server/src/decision/service.ts#L87 "支持逐题检查答案、合法选项和候选概率后才返回结果，也支持概率键边界的说明。")

```mermaid
flowchart LR
  A[业务状态与选择题] --> B[串行队列]
  B --> C[启动或复用 worker]
  C --> D[JSON 行请求与响应]
  D --> E[结构和选项校验]
  E --> F[DecisionResult 或 null]
```

进程的 stdout 只承载可解析 JSON；启动阶段必须先收到 `{ ready: true }`。进程错误会拒绝当前等待；进程退出会清除 worker 引用并拒绝当前等待；ready 握手失败会释放 worker。参考 [worker 就绪协议 ↗](../../../apps/server/src/decision/service.ts#L220 "支持 stdout JSON 行解析、进程错误与退出处理，以及 ready 握手失败后的释放行为。")

<a id="runtime_boundaries"></a>
## 运行条件与降级边界

配置模式接受 `off`、`auto` 或 `decisionModelSizes` 中定义的固定尺寸；`off` 或服务已关闭时直接返回 `null`。启动时只查找本地虚拟环境及已安装模型，`auto` 只枚举较小型号，未安装的模型不会在运行期下载。找到模型后，服务用 Python 启动 StartLux worker，并通过环境变量接入可选运行时。参考 [决策模式配置 ↗](../../../apps/server/src/decision/service.ts#L22 "支持配置模式接受 off、auto 和 decisionModelSizes 提供的固定尺寸。") [本地模型启动条件 ↗](../../../apps/server/src/decision/service.ts#L171 "支持本地运行时检查、自动模式的模型范围、离线模型发现和 Python worker 启动方式。")

服务同一时间只保留一个待响应请求，因此用队列串行化调用，避免多个导入任务同时把模型装入统一内存。单次等待超过 120 秒会强制结束进程；每次调用结束后设置 180 秒空闲回收。队列内的启动或 worker/协议错误，以及超时与结果校验错误会记录状态并返回 `null`，调用方需要保留原有路径作为降级方案；`close()` 则停止新请求、清理定时器，并等待队列收尾。参考 [队列内错误降级与空闲回收 ↗](../../../apps/server/src/decision/service.ts#L118 "支持队列内错误记录并返回 null，以及 180 秒空闲释放；结合 next 的超时逻辑说明 120 秒等待边界。") [显式关闭流程 ↗](../../../apps/server/src/decision/service.ts#L250 "支持释放待处理请求、强制终止子进程并等待队列完成。")

结果模式要求置信度和各概率位于 0 到 1，但没有检查概率总和是否等于 1。逐题校验要求所有已定义选项都有概率，也没有要求概率键只能来自 `criteria`。这些数值因此适合排序或策略判断，不能仅凭此服务视为归一化概率分布。参考 [结果数值模式 ↗](../../../apps/server/src/decision/service.ts#L26 "支持置信度和概率的取值范围，以及模式未声明概率必须归一化。") [答案完整性校验 ↗](../../../apps/server/src/decision/service.ts#L87 "支持逐题检查答案、合法选项和候选概率后才返回结果，也支持概率键边界的说明。")
