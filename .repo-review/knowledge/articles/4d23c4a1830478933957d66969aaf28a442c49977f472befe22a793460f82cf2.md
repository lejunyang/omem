# 本地快速决策服务的串行执行与降级机制

DecisionService 为阅读和材料接入流程提供可选的本地选择题决策能力。它按配置发现已安装的 StartLux 模型，启动 Python worker，以逐行 JSON 协议发送状态和问题，并校验返回选项。请求被串行化，成功结果短期缓存；环境缺失或超时，进程退出或结果不完整时返回 null，使调用方能够沿原有流程继续。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role_and_contract"></a>
## 解决什么问题

该服务给阅读与材料接入流程提供一个**可选的本地决策旁路**。配置可关闭服务，也可选择 `auto`、`2b`、`4b` 或 `9b`；返回值包含各问题的选项、置信度、概率，以及模型和耗时信息。实现声明不写数据、不自动准备环境，失败后原工作流仍可继续。参考 [服务配置与返回契约 ↗](../../../apps/server/src/decision/service.ts#L11 "支持服务的可选定位、配置模式、返回结构以及失败不影响既有流程的说明。")

它从 `paths.js` 获取运行时、模型工作区和 worker 资源路径，问题类型来自 `questions.js`。这说明 TypeScript 服务负责进程编排与协议校验，实际推理由 Python worker 承担。参考 [路径与问题类型依赖 ↗](../../../apps/server/src/decision/service.ts#L8 "支持服务与路径辅助模块、问题类型模块之间的静态依赖关系。")

<a id="representative_flow"></a>
## 一次代表性调用怎样完成

教学示例中，调用方把当前 `state` 和一个以问题名为键的 `questions` 对象交给 `decide`。服务先对两者的 JSON 表示做 SHA-256 摘要，再把任务接到内部 Promise 队列上；缓存未命中时启动 worker，将请求编码成一行 JSON 写入标准输入，并解析标准输出返回的一行 JSON。参考 [决策请求主流程 ↗](../../../apps/server/src/decision/service.ts#L30 "支持摘要键、串行队列、缓存检查、worker 启动和逐行 JSON 请求的代表性调用流程。")

```mermaid
flowchart LR
  A[state 与 questions] --> B[串行队列]
  B --> C[发现本地模型]
  C --> D[启动 Python worker]
  D --> E[逐行 JSON 请求与响应]
  E --> F[结构及选项校验]
  F --> G[DecisionResult 或 null]
```

`auto` 只探测已经安装的 2B 和 4B 模型；9B 只有显式选择时才会探测。模型查询使用离线模式，运行时不会下载缺失模型，随后服务把模型路径和模式交给 `scripts/startlux/worker.py`。参考 [模型发现与 worker 启动 ↗](../../../apps/server/src/decision/service.ts#L71 "支持自动模式的模型范围、离线发现、禁止运行时下载和 Python worker 启动参数。") worker 必须先发出 `ready` 消息；后续每行标准输出会尝试解析为 JSON，并完成当前等待中的请求。参考 [就绪握手与输出解析 ↗](../../../apps/server/src/decision/service.ts#L91 "支持 worker 就绪握手、标准输出逐行解析和进程错误处理的说明。")

结果先经过 Zod 结构校验，再逐题确认答案存在、所选项属于调用方给出的 `criteria`，且每个候选项都有数值概率。成功时返回 `DecisionResult`；worker 报错、返回无效结构或缺少选项时，服务记录 `unavailable` 状态并返回 `null`。参考 [结果校验与失败降级 ↗](../../../apps/server/src/decision/service.ts#L44 "支持逐题校验、成功状态更新、异常转 unavailable 并返回 null，以及概率约束边界的说明。")

<a id="boundaries_and_lifecycle"></a>
## 缓存、超时与进程生命周期

相同输入的成功结果缓存 5 分钟，判断依据是 `state` 与 `questions` 序列化后的摘要。缓存命中直接返回结果。参考 [五分钟缓存命中 ↗](../../../apps/server/src/decision/service.ts#L32 "支持相同摘要键的成功结果在 5 分钟内直接复用，并说明缓存命中发生在 try/finally 之前。") 缓存超过 128 项时删除最早插入的键。只有通过队列内 `stopped` 检查且缓存未命中、进入 `try` 的调用，才会在执行结束后设置 3 分钟空闲计时；到期会结束 worker 并把状态改回 `idle`。缓存命中和队列内因 `stopped` 提前返回都不会刷新该计时器。参考 [五分钟缓存命中 ↗](../../../apps/server/src/decision/service.ts#L32 "支持相同摘要键的成功结果在 5 分钟内直接复用，并说明缓存命中发生在 try/finally 之前。") [缓存上限与空闲回收 ↗](../../../apps/server/src/decision/service.ts#L49 "支持 128 项缓存上限，以及进入 try 的执行在 finally 中设置 3 分钟空闲回收计时。")

请求等待上限为 120 秒。超时会释放进程并拒绝当前等待；由于 `decide` 通过同一条队列串行运行，单个 `pending` 槽不会同时承载两次决策。参考 [单请求等待与超时 ↗](../../../apps/server/src/decision/service.ts#L64 "支持单个 pending 请求槽、120 秒超时和超时释放进程的说明。") 显式 `close()` 会阻止新请求并清除空闲计时，强制结束 worker 后等待已排入的任务收尾。参考 [进程释放与服务关闭 ↗](../../../apps/server/src/decision/service.ts#L103 "支持强制结束 worker、拒绝当前等待以及 close 等待队列收尾。")

边界上，`off` 模式和已关闭实例直接返回 `null`。环境中没有虚拟环境 Python 或符合模式的本地模型，worker 未就绪或提前退出，也都会走相同降级路径。概率字段只检查数值范围与题目中每个候选项是否存在，没有在本文件内检查概率总和是否为 1。参考 [结果校验与失败降级 ↗](../../../apps/server/src/decision/service.ts#L44 "支持逐题校验、成功状态更新、异常转 unavailable 并返回 null，以及概率约束边界的说明。")
