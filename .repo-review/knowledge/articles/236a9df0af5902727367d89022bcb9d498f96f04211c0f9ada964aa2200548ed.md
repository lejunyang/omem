# 反馈整理角色运行清单

该清单定义 feedback-curator 第 1 版角色的模型配置入口、内联技能、结构化输出、工具与会话隔离策略，以及上下文和修复预算。它描述的是角色运行配置，不足以单独证明提示词逻辑、宿主校验和纠正提案应用流程已经实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-contract"></a>
## 角色与输出合同

该文件把角色标识为 `feedback-curator` 第 1 版，并通过 `traex` profile 与 `prompt.md` 组装运行输入；这说明它是反馈整理流程中的一个专用角色配置，而不是反馈处理逻辑本身。[角色身份与提示词入口 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/manifest.json#L2 "支持角色版本、模型 profile 入口及提示模板来源的说明。") 角色声明输出 `CorrectionProposal.v1`，意图是让反馈被整理为可校验的纠正提案，便于后续复核或应用；但仅凭清单无法确认该 schema 的字段语义、宿主是否严格校验，以及提案是否会自动进入应用流程。[纠正提案输出合同 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/manifest.json#L17 "支持该角色声明生成 CorrectionProposal.v1 结构化结果的论断。")

<a id="skill-and-isolation"></a>
## 技能装载与隔离边界

清单固定装载 `omem-feedback-curation` 的 `feedback-1` 版本，并记录制品摘要，表明运行时应使用可追踪的内联技能版本。[反馈整理技能制品 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/manifest.json#L9 "支持内联技能名称、版本和摘要用于固定运行制品身份的说明。") 同时，工具策略为 `none` 且允许列表为空；会话从不复用，也不继承用户技能或 MCP。[工具与会话隔离策略 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/manifest.json#L18 "支持角色禁用工具、禁止会话复用并关闭用户技能及 MCP 继承的边界说明。") 因而该角色被配置为只依据宿主提供的上下文生成提案，不能自行读取外部资料或调用工具。这是配置期安全边界，是否被运行时实际执行仍需结合加载器和集成测试判断。

<a id="execution-budget"></a>
## 执行预算与失败恢复

该角色允许最多 96,000 个上下文 token、24,000 个输出 token，并设置最多两次修复尝试。[上下文、输出与修复预算 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/manifest.json#L27 "支持 token 上限和最大修复次数的配置说明。") 这些值为处理较长反馈材料和修复不合规结构化输出预留空间，但清单没有说明 token 能力如何与实际模型协商、何种错误触发修复，以及两次修复均失败后的持久化或告警行为。
