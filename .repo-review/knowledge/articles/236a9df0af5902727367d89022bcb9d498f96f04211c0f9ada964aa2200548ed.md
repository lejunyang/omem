# 反馈整理角色清单：隔离策略、输出合同与预算

该清单声明 feedback-curator v1 的角色标识、提示词与内联技能绑定，输出采用 `CorrectionProposal.v1`。配置禁止工具、禁用会话复用及用户技能/MCP 继承，并设置上下文、输出和修复尝试预算；这些是静态运行配置，不是实际隔离效果的证明。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-binding"></a>
## 角色、技能与输出绑定

清单把角色标识为 `feedback-curator`、版本设为 1，并引用 `traex` profile 与 `prompt.md`。其内联技能包为 `omem-feedback-curation`，带固定版本和制品摘要；输出合同声明为 `CorrectionProposal.v1`。[反馈整理角色装配信息 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/manifest.json#L2 "支持角色版本、profile、提示词、内联技能制品与输出合同之间的配置关系。") 这些字段描述宿主应如何装配角色，但材料未展示摘要核验、技能内容或装配成功记录。

<a id="isolation-budget"></a>
## 工具隔离、会话策略与预算

工具策略为 none 且允许工具列表为空；会话从不复用，也不继承用户技能或 MCP。预算上限为 96,000 个上下文 token、24,000 个输出 token，并允许最多两次修复尝试。[角色隔离与预算配置 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/manifest.json#L18 "支持无工具、无会话复用、无用户扩展继承及 token/修复预算的静态配置论断。") 这体现了把反馈整理限制为纯结构化推导的设计意图，但不能单凭清单断言运行时确实拒绝工具或严格执行预算。
