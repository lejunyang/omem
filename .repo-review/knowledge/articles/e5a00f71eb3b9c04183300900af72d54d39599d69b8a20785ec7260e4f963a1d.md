# 知识仓储：材料绑定、发布与失效传播

该模块把不可变的原始捕获修订投影为可引用材料，校验知识文档的结构和引用完整性，由宿主绑定固定引文，并管理文章发布、依赖失效、历史材料解析及疑问闭环。它依赖 Store 的单用户 SQLite 基础和稳定摘要，但语义复核门禁与历史扫描性能仍需结合调用链和实际规模确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="material_projection"></a>
## 从原始修订投影知识材料

`materialFromRevision` 将指定修订转换为知识生成可消费的稳定材料，并按 Store 实例与修订号缓存结果。它排除上下文或 provenance 标为 derived 的修订，避免派生正文再次充当原始证据；文本与链接按捕获格式拼接，图片保留资产、类型和人读标签。材料键优先沿用文件来源已有的 `omem:` 标识，否则由来源类型和外部标识组成；摘要同时纳入正文、图片、作者、引用及转发状态，因此关键语境变化会形成新的内容身份。[原始修订到知识材料的投影 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持派生修订过滤、内容部件拼接、材料键生成、上下文保留和稳定摘要计算的说明。")

`currentMaterials` 只读取具有 head 的来源，并投影其当前修订；被过滤的派生修订不会进入当前材料集合。历史版本不在该集合中，而由历史解析流程按需恢复。[当前材料枚举 ↗](../../../apps/server/src/knowledge/repository.ts#L36 "支持仅从来源 head 收集当前可用、非派生材料的说明。")

<a id="validation_binding"></a>
## 结构校验与固定引文绑定

发布前先以共享合同解析文档，再检查 citation key 和 section key 唯一。每节必须出现至少一个 `[[引用键]]`，正文中的键必须已声明，并且每个已声明引用都必须在某节正文中以内联标记出现；该实现只检查“是否在任意章节出现”，不会判断标记与具体论断的距离或归属。材料目标、行号范围、文章目标与疑问所引用的键也会被校验，而语义上是否真正支持附近论断仍交给独立模型角色。[知识文档与内联引用校验 ↗](../../../apps/server/src/knowledge/repository.ts#L41 "支持结构解析、键唯一性、章节必须含引用、声明引用必须在正文出现、目标与行范围校验，以及语义复核独立进行的边界说明。")

`bindKnowledgeQuotes` 落实“模型选择定位范围、宿主复制固定原文”：宿主根据材料行号写入最多 320 个字符的 quote，纯图片材料允许空引文。它降低模型转抄代码造成的偏差，但截断可能只保留长范围的前部，函数本身也不承担语义支持性判断。[宿主绑定固定引文 ↗](../../../apps/server/src/knowledge/repository.ts#L74 "支持按模型给出的材料行范围复制原文、纯图片例外和 320 字符截断规则的说明。")

<a id="publication_invalidation"></a>
## 版本发布与依赖失效传播

仓储初始化时设置 30 秒 SQLite 忙等待，并建立知识修订、当前头、疑问、失效和导入状态表，支持生成端与阅读端共享数据库。[知识仓储初始化 ↗](../../../apps/server/src/knowledge/repository.ts#L90 "支持 SQLite 忙等待设置及知识修订、头、疑问、失效和导入表初始化的说明。") 发布时先比较 artifact 声明的材料摘要或文章修订；输入已变化则拒绝。随后执行文档校验，以 artifact 的稳定摘要生成不可变 revision：相同版本幂等返回，新版本则在事务中保存、切换 head、清除失效，并同步疑问。旧的开放疑问若不再出现会标为 superseded，再次出现时可恢复为 open。这里能确认 `publish` 自身执行结构与新鲜度检查，但源码未显示“独立语义复核已通过”的状态门禁。[知识产物发布事务 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持依赖新鲜度检查、不可变 revision、head 切换、疑问状态同步和变更记录；同时表明 publish 中未出现可见的语义复核状态检查。")

`refresh` 汇总显式失效和直接依赖摘要不匹配的文章，再迭代传播文章依赖造成的间接失效，直到集合稳定，最后更新各 head 的 current 标志。它负责标记过期，不负责自动重新生成正文。[依赖失效传播 ↗](../../../apps/server/src/knowledge/repository.ts#L144 "支持直接依赖检查、文章间失效传播和 current 状态更新的说明。")

<a id="historical_resolution_actions"></a>
## 历史证据解析与疑问闭环

`resolveMaterial` 先查找摘要匹配的当前材料；未命中时按创建时间倒序扫描全部修订，以同一投影函数寻找固定历史版本，并返回 `current:false`。这保证旧引用仍可回到原始证据，但实现是全表逐条投影，修订规模增长后的查询成本尚无数据或索引设计可判断。[当前与历史材料解析 ↗](../../../apps/server/src/knowledge/repository.ts#L159 "支持优先解析当前材料、随后倒序扫描历史修订及返回 current 标志的说明。")

疑问回答会作为 manual 来源的新原始捕获写入 Store，将问题标为 answered，并把所属文章标记为需要重新核对；创建任务则把问题、原因和下一步写入待办，已有 taskId 时幂等复用。用户补充因此进入证据链并触发失效，而不是直接改写派生正文。[疑问回答与任务化 ↗](../../../apps/server/src/knowledge/repository.ts#L169 "支持把回答捕获为原始材料、触发文章失效，以及创建并复用任务的说明。")

该仓储依赖 Store 暴露的数据库、事务、捕获与任务能力；Store 当前明确以本地 SQLite 作为单用户基础，未体现团队租户强制隔离。[Store 的单用户 SQLite 基础 ↗](../../../apps/server/src/store.ts#L2 "支持知识仓储依赖本地 SQLite，且当前实现尚非团队租户强制隔离的边界说明。") 内容身份使用稳定摘要：对象键递归排序并忽略 undefined 后进行 SHA-256，数组顺序仍被保留。[稳定摘要规范化 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持对象键排序、undefined 过滤、数组顺序保留和 SHA-256 内容身份计算的说明。") 文档、引用、疑问和材料的基本形状由共享 Zod 合同定义，仓储再增加目标存在性、行范围、内联使用和依赖新鲜度等运行时约束。[知识共享合同 ↗](../../../packages/contracts/src/knowledge.ts#L3 "支持引用、疑问、文档及材料基础结构由共享 Zod 合同定义的说明。")
