# 知识材料、修订与失效管理仓库

从非派生 Revision 构造固定知识材料，验证正文内联引用，按内容生成不可变文章修订并维护 current head；依赖变化和用户回答会使相关知识失效，供后续分析纳入回答并重新核对。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="materials-validation"></a>
## 固定材料与引用合同

仓库从 Revision 的文本、链接和图片部件构造材料，并把正文、图片、作者及转发属性纳入摘要；明确标记为 derived 的 Revision 不会成为原始材料。[Revision 转固定材料 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "说明派生 Revision 的排除条件，以及文本、链接、图片和来源属性如何组成固定材料及摘要。") 文档校验要求章节键和引用键唯一、每节至少包含一处内联引用、每项引用都实际出现在正文中，并核验材料行范围或文章章节目标。宿主再按模型选定的范围复制精确短引文，避免要求模型复写长代码。[正文引用验证与引文绑定 ↗](../../../apps/server/src/knowledge/repository.ts#L41 "支持内联引用、引用目标和行范围的验证规则，以及由宿主从固定材料复制精确引文的机制。")

<a id="publication"></a>
## 不可变发布与问题演进

发布前会重新核对材料摘要和依赖文章修订，输入变化时拒绝发布；文章内容与生成、复核记录共同决定修订哈希，相同修订直接复用，否则插入不可变 revision 并原子切换 current head。[发布前依赖核对与不可变修订 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前检查输入身份、计算修订哈希、复用相同修订以及事务性切换文章 head。") 新正文中的问题会新增或更新；此前处于 `superseded` 且再次出现的问题会重开。只有仍为 `open`、但已从新正文移除的问题才会被标记为 `superseded`；已经是 `answered` 或 `task` 的问题不受这段淘汰逻辑影响。[开放问题的替代与重开 ↗](../../../apps/server/src/knowledge/repository.ts#L130 "精确说明只有已移除的 open 问题会变为 superseded，并说明 superseded 问题再次出现时会重开。")

<a id="invalidation-answer"></a>
## 依赖失效与用户回答

刷新会比较 current 材料摘要及派生文章修订，并沿文章依赖递归传播失效；历史修订仍被保留，但失效文章的 head 不再标为 current。[依赖失效传播 ↗](../../../apps/server/src/knowledge/repository.ts#L144 "说明材料或子文章身份变化如何使文章失效，并沿派生文章依赖继续传播。") 用户回答疑问时，答案先作为带来源元数据的手工捕获保存，问题改为 `answered`，对应文章登记失效原因并触发刷新。[回答保存与待办创建 ↗](../../../apps/server/src/knowledge/repository.ts#L169 "说明用户回答被保存为原始捕获、问题转为 answered 并使文章失效，以及显式创建待办时状态转为 task。") 该操作本身不创建复核任务；后续分析运行时才会把关联的回答 Revision 作为原始材料加入输入并重新核对。[后续分析纳入用户回答 ↗](../../../apps/server/src/knowledge/pipeline.ts#L161 "说明知识分析仅在后续运行时读取问题关联的回答 Revision，并把它作为固定材料加入复核输入。") 用户也可另行把问题转换为现有任务系统中的待办，此时问题状态变为 `task`。[回答保存与待办创建 ↗](../../../apps/server/src/knowledge/repository.ts#L169 "说明用户回答被保存为原始捕获、问题转为 answered 并使文章失效，以及显式创建待办时状态转为 task。")
