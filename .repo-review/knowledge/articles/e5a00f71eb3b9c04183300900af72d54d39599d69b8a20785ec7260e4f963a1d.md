# 知识材料、修订与失效管理仓库

把原始修订转换为可分析材料，严格校验正文内联引用，以内容寻址修订发布知识，并在原始材料或派生依赖变化后传播失效状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="material-boundary"></a>
## 原始材料边界

仓库从固定 Revision 重建文本、链接与图片，并结合正文、图片及来源属性计算稳定摘要。标为 derived 的修订会被排除，因此派生知识不能作为新的独立证据循环进入分析；当前材料列表只读取各 Source 的 head。[原始修订材料化 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持排除派生修订、构造材料摘要以及只读取当前 Source head 的说明。")

<a id="validation-publication"></a>
## 引用校验与内容寻址发布

文档校验要求章节键和引用键唯一、每节含内联引用、每项引用实际出现在叙述中，并检查文章章节或材料行范围。模型选择定位范围后，宿主从固定材料复制短引文，避免依赖模型转录源码。[知识文档与引文校验 ↗](../../../apps/server/src/knowledge/repository.ts#L41 "支持内联引用完整性、目标范围检查和宿主绑定精确引文的规则。") 发布前会重新核对依赖摘要，再以完整 artifact 计算修订号并事务化切换 head；仍存在的问题被写入或重新打开，正文中消失的开放问题则标记为已替代。[知识修订发布事务 ↗](../../../apps/server/src/knowledge/repository.ts#L115 "支持依赖复核、内容寻址修订、head 更新及开放问题替代流程。")

<a id="refresh-answer"></a>
## 依赖失效与用户回答

刷新过程比较当前材料摘要和派生文章修订，并把失效沿文章依赖逐层传播；它只调整知识 head 的 current 状态，历史修订仍被保留。[知识依赖失效传播 ↗](../../../apps/server/src/knowledge/repository.ts#L141 "支持材料或文章依赖变化会逐层取消 current 状态的论断。") 用户回答会保存为 manual 原始修订，问题改为已回答，对应文章被标记失效并刷新；问题也可显式转换为待办。[问题回答与待办转换 ↗](../../../apps/server/src/knowledge/repository.ts#L166 "支持回答被捕获为原始修订、文章失效刷新以及问题转为待办的流程。") 后续分析命中该文档时，流水线会读取 answerRevision，将回答作为固定补充材料加入 offers 后重新写作和复核。[回答进入后续分析 ↗](../../../apps/server/src/knowledge/pipeline.ts#L161 "支持已回答问题的修订被材料化，并在分析对应文档时加入固定材料 offers。")
