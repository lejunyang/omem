# 知识材料、版本与问题仓库

把不可变捕获修订转换为知识材料，校验并发布带固定依赖的知识版本，传播过期状态，同时管理待澄清问题的回答与任务。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="materials-validation"></a>
## 原始材料身份与引用约束

`materialFromRevision` 拒绝派生修订，把文本与链接按捕获格式聚合并保留图片和来源元数据；材料摘要实际只包含聚合文本、图片，以及 provenance 中的 actorId、quoted、forwarded。先前“内容、图片和 provenance 共同纳入摘要”的宽泛结论已被替代：eventAt、actorVerifiedBy、sourceId 等其他来源字段虽保存在材料对象中，却未进入该摘要。文件来源的 `omem:` 外部键保持为材料键，结果按 Store 与 revisionId 缓存。[修订到知识材料的转换 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持排除派生修订、材料字段构造，并精确界定摘要只包含文本、图片、actorId、quoted 和 forwarded。")

文档校验要求 citation 和 section 键唯一、每节至少一个内联引用、每项引用实际出现在正文且目标已提供；材料引用还要有合法行区间与精确引文，文章引用要指向存在的文章及章节。[知识文档结构与引用校验 ↗](../../../apps/server/src/knowledge/repository.ts#L41 "支持内联引用覆盖、目标存在、行区间和精确引文等硬约束。") 模型只选择定位范围，`bindKnowledgeQuotes` 由宿主从固定原文复制最多 320 个字符，避免模型自行复写证据。[宿主绑定原文引文 ↗](../../../apps/server/src/knowledge/repository.ts#L74 "支持模型选择行号、宿主从固定原文复制有限长度引文的证据绑定机制。")

<a id="publish-refresh"></a>
## 发布与新鲜度传播

发布前再次比较全部材料摘要和子文章修订，输入变化会报 `KNOWLEDGE_INPUT_CHANGED`。通过校验后，以完整 artifact 的稳定摘要生成不可变 revision，在事务中更新 head、清除失效标记并同步问题：消失的开放问题变为 superseded，再出现时可重新打开。[知识版本发布事务 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持依赖并发校验、内容寻址修订、head 更新以及问题生命周期同步。") `refresh` 检查直接依赖并迭代传播上层失效，最终只更新 head 的 `current` 标志，不删除历史修订。固定材料解析可按摘要回查历史 revision，所以旧引用仍可能打开但会标为非当前。[依赖刷新与历史材料解析 ↗](../../../apps/server/src/knowledge/repository.ts#L144 "支持过期状态逐层传播，以及按摘要解析当前或历史材料版本。")

<a id="questions"></a>
## 用户补充与后续调度边界

回答问题时，仓库把答案捕获为 `manual` 来源的原始修订，将问题置为 answered，为对应文档写入失效原因并立即刷新状态。仓库自身不会在这里启动重新分析。[答案捕获与知识失效 ↗](../../../apps/server/src/knowledge/repository.ts#L169 "支持答案保存为原始捕获、问题状态更新和文档失效；该范围也表明仓库方法本身没有启动分析流水线。") API 层在保存成功后仅调用可选的 `onAnswer` 回调；当前材料没有说明该回调一定存在，也没有证明它必然执行重新分析或另有调度，因此先前“由 API 回调或其他调度触发重新分析”的确定性结论已被替代。[回答后的可选通知 ↗](../../../apps/server/src/knowledge/api.ts#L76 "支持 API 在仓库保存答案后仅调用可选 onAnswer 回调，不能据此断言后续重新分析必然发生。")

问题转任务时会复用已有 taskId；否则使用问题、原因和下一步创建无截止日期任务，并把问题状态改为 task。[问题转任务 ↗](../../../apps/server/src/knowledge/repository.ts#L181 "支持复用既有任务，或按问题、原因与下一步创建无截止日期任务并更新状态。")
