# 知识文章的版本发布、引用校验与失效管理

知识仓库把原始捕获转换为可引用材料，并负责文章的结构校验、不可变版本发布、历史恢复、依赖失效传播与问题跟进，使派生知识能够追溯到固定输入。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 把原始捕获变成可追溯知识

知识仓库连接捕获存储与阅读界面：它从不可变 revision 提取文本、链接、图片及来源信息，排除标记为派生的内容，再用稳定摘要标识实际材料状态。文件来源可保留 `omem:` 键，其他来源按命名空间组成键，供文章依赖和引用定位。参考 [材料转换流程 ↗](../../../apps/server/src/knowledge/repository.ts#L15 "支持从原始 revision 组装文本、图片、来源键和稳定材料摘要，并排除派生内容。")

`currentMaterials` 只遍历具有当前 head 的来源。底层存储明确以单用户 SQLite 为基础，团队级数据库与租户强制隔离仍属于后续迁移范围。参考 [当前材料枚举 ↗](../../../apps/server/src/knowledge/repository.ts#L36 "支持只从具有当前 head 的来源构造当前知识材料集合。")，延伸阅读：[单用户存储边界 ↗](../../../apps/server/src/store.ts#L4 "说明 SQLite 是当前单用户基础，团队级存储与强制隔离仍待后续迁移。")

<a id="publishFlow"></a>
## 发布前校验与不可变版本写入

发布时先读取当前材料与文章，并核对成果记录的依赖摘要；原始材料发生变化或被依赖文章换版，都会以输入已变化为由拒绝发布。随后检查文档合同、章节中的内联引用、目标是否存在以及材料行号范围。模型只负责选择引用位置，实际引文由宿主从固定材料复制，供独立复核查看。参考 [发布依赖检查 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前比较材料摘要和文章版本，并在固定输入变化时拒绝成果。")、[内联引用校验 ↗](../../../apps/server/src/knowledge/repository.ts#L43 "支持对文档结构、重复键、章节内联引用、目标存在性和材料行号范围进行检查。")、[原文片段绑定 ↗](../../../apps/server/src/knowledge/repository.ts#L74 "说明模型选择引用位置，宿主从固定材料复制实际引文并交给独立复核。")

```mermaid
flowchart LR
  A[读取当前材料与文章] --> B[核对依赖摘要]
  B --> C[校验正文与内联引用]
  C --> D[计算稳定版本摘要]
  D --> E[事务写入版本与当前指针]
  E --> F[刷新依赖有效性]
```

版本摘要基于递归规范化、属性排序并忽略 `undefined` 的 JSON，避免对象属性顺序改变知识身份。新版本在事务中写入不可变记录、更新 head、同步开放问题并记录章节变化；相同版本则直接复用。参考 [稳定摘要算法 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持对象递归规范化、属性排序、忽略未定义值及基于规范 JSON 计算摘要的描述。")、[知识版本事务发布 ↗](../../../apps/server/src/knowledge/repository.ts#L123 "支持稳定版本身份、幂等复用、不可变版本写入、head 更新、问题同步和发布后刷新流程。")

<a id="staleness"></a>
## 历史恢复、失效传播与用户补充

历史恢复只接受版本正确、复核结论为通过，并同时带有生成模型与复核模型来源的成果。它会尝试按依赖摘要解析历史材料或指定文章版本；未找到的历史目标可以跳过，之后以允许历史目标缺失的模式完成文档结构和已有目标校验，因此恢复本身不保证所有固定输入仍可解析。参考 [历史成果恢复校验 ↗](../../../apps/server/src/knowledge/repository.ts#L152 "支持历史恢复的版本、复核及模型来源要求，并表明依赖会被尝试解析而缺失历史目标可在结构校验时放行。")

恢复的版本记录采用幂等写入。只有 `asHead=true` 时，系统才尝试为尚无 head 的文档插入 `current=0` 的 head；已有 head 不会被覆盖，而 `asHead=false` 时完全不创建 head。参考 [历史版本写入条件 ↗](../../../apps/server/src/knowledge/repository.ts#L167 "支持历史版本幂等写入，并说明只有启用 asHead 时才为无既有 head 的文档插入 current 为假的记录。")

刷新阶段会把材料摘要或文章版本不匹配的页面标为过期，并沿文章依赖继续传播。历史材料解析先检查当前版本，再倒序搜索旧 revision，但只返回键与预期摘要均匹配的材料。参考 [依赖失效传播 ↗](../../../apps/server/src/knowledge/repository.ts#L174 "支持依据材料摘要、文章版本和上游失效状态计算文章是否仍为当前版本。")、[固定历史材料解析 ↗](../../../apps/server/src/knowledge/repository.ts#L189 "支持先检查当前材料，再从历史 revision 中查找键与预期摘要匹配的版本。")

调查问题也参与知识更新：用户答案被保存为新的原始捕获，相关文章随即失效并等待重新核对；问题还可幂等转换为待办。参考 [问题回答与待办转换 ↗](../../../apps/server/src/knowledge/repository.ts#L202 "支持将用户答案保存为原始捕获、触发文章失效重核验，并把问题幂等转换为待办。")
