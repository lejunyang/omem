# 知识正文的材料解析、发布与失效管理

该仓库把不可变捕获修订转换为知识材料，校验并发布带固定引用的知识正文，同时维护正文版本、问题状态和依赖失效传播；它负责引用的结构与来源定位一致性，但不判断引用是否在语义上支持附近论断。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="material_identity"></a>
## 原始修订到知识材料

模块将 Store 中的修订转换为统一知识材料：派生修订被排除，文本和链接按捕获格式组合，图片保留资源信息，来源、会话及行为者元数据一并传递。文件来源优先沿用 `omem:` 键；材料摘要覆盖文本、图片及引用、转发身份。转换结果按 Store 和修订号缓存，而默认生成输入只取每个来源的当前 head，因此历史版本不会混入当前材料。[修订材料转换与当前材料选择 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持派生修订过滤、内容与元数据组装、材料身份摘要、缓存以及仅从来源 head 选择当前材料的说明。") 摘要由规范化 JSON 计算：对象键递归排序并忽略 `undefined`，从而避免字段顺序产生无意义的身份变化。[稳定摘要规范化 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持递归排序对象键、忽略未定义字段并以规范化 JSON 计算 SHA-256 摘要的说明。")

<a id="validation_binding"></a>
## 引用结构校验与原文绑定

发布前先执行共享文档合同，再检查章节键和引用键唯一性。每节必须含内联引用，正文出现的引用必须已声明，且每项声明引用必须在某个章节正文中被使用；文章目标需存在并可选校验章节，材料目标需具有有效行号，绑定后的引文也必须来自指定范围。[知识文档引用校验 ↗](../../../apps/server/src/knowledge/repository.ts#L41 "支持共享合同解析、键唯一性、内联引用使用、目标存在性和材料范围校验，并表明语义正确性由独立角色检查。") **此前“该函数保证引用贴近相应论断”的结论已被替代**：实现只做引用是否出现在正文中的结构检查，不测量相邻程度，也不判断语义支持性；“贴近论断”属于生成规范和独立模型复核要求。

模型仅选择材料与行号，宿主再从固定材料复制最多 320 个字符，避免模型自行誊写源码；无文本的纯图片材料允许空引文。[固定原文引文绑定 ↗](../../../apps/server/src/knowledge/repository.ts#L74 "支持由模型选择定位、宿主复制固定材料短引文以及纯图片材料例外的说明。")

<a id="publication_refresh"></a>
## 版本发布与依赖失效

仓库初始化时设置 SQLite 写等待上限，并建立正文修订、当前 head、问题、显式失效和导入状态表，以支持生成 CLI 与阅读端共享数据库。[知识仓库初始化与数据表 ↗](../../../apps/server/src/knowledge/repository.ts#L90 "支持 SQLite 写等待策略以及正文修订、head、问题、失效和导入状态表的说明。") 发布前会重新核对材料摘要和上游文章修订，输入已变化时拒绝写入；随后校验文档、计算稳定修订号，并在事务中保存修订、切换 head、清除失效标记和同步问题状态。消失的开放问题会标为 `superseded`，再次出现时可恢复为 `open`，最后记录知识整理事件。[知识正文发布流程 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持依赖复检、稳定修订计算、事务写入、head 切换、问题状态同步和用户事件记录的说明。")

刷新过程把显式失效和直接依赖变化加入集合，再沿文章依赖逐层传播，最终只切换各 head 的 `current` 状态而不删除历史正文。[知识依赖刷新传播 ↗](../../../apps/server/src/knowledge/repository.ts#L144 "支持显式失效、直接依赖变化、文章依赖逐层传播及 current 状态更新的说明。")

<a id="history_questions_boundaries"></a>
## 历史追溯、用户补充与实现边界

按键读取默认返回 head，也可指定修订；材料解析优先匹配当前版本，必要时遍历历史修订并返回 `current:false`，使旧引用仍可追溯。用户回答问题时，回答会被捕获为新的原始修订，而不是直接改写派生正文；原文档随后被标记为需要重新核对。问题还可转为 Store 任务，重复创建会复用已有任务。[历史材料解析与问题处理 ↗](../../../apps/server/src/knowledge/repository.ts#L159 "支持历史修订追溯、用户回答捕获为原始材料、正文失效刷新以及问题转任务的说明。") 共享合同统一限定文档、章节、引用关系、定位字段和问题结构，仓库是在该合同之上补充运行时来源校验，并未另建知识模型。[共享知识数据合同 ↗](../../../packages/contracts/src/knowledge.ts#L3 "支持知识引用、问题、文档结构及允许关系由共享合同统一约束的说明。")

当前材料显示的基础设施是单用户 SQLite；30 秒 busy timeout 只能缓解写竞争。该文件不负责生成正文或执行独立语义复核，也未给出同一文档并发发布的比较交换条件、文章依赖无环约束及相应测试，因此这些行为不能由现有实现推定。
