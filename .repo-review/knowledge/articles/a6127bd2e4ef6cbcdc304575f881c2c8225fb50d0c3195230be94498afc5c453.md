# 人工维护的代码—依据关联种子

定义并读取代码实现与需求、决策、研究及测试材料之间的人工关联；同步层可据此建立关系，但本模块不执行语义匹配或目标解析。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="authority"></a>
## 关系来源与用途

关联种子是代码 Fragment 与意图、决策、研究、测试依据之间的人工维护入口，不是自动语义匹配器。只有 JSON 中明确列出的条目才可在同步时转成评审关系；词面相似但未登记的命中不能成为 confirmed。数据放在仓库内的固定 JSON 文件中，TypeScript 模块负责声明并读取其形状。[人工关联种子的权威边界 ↗](../../../apps/server/src/review/associations.ts#L1 "支持关联必须人工列举、不得由语义相似度自动确认及文件位置的说明。")

<a id="schema"></a>
## 种子结构与证据表达

每条种子用仓库相对代码路径和符号定位实现点，附带意图、需求标签、决策／研究／测试引用、关系状态以及解释实现关系的 evidence。需求引用只是标签，不直接作为 Fragment 目标；其他引用可使用 `path::anchor` 指向目标材料中的具体锚点。[关联种子数据结构 ↗](../../../apps/server/src/review/associations.ts#L19 "说明代码定位、意图、各类引用、状态和证据字段的职责。") 该结构保留了代码定位、关系理由和外部依据的分工，但真正解析到 head 图与 Fragment 的工作不在本文件中。

<a id="loading"></a>
## 加载、容错与限制

文件缺失时加载器返回空列表，适用于新检出仓库或测试夹具；JSON 无法解析、根节点缺少 associations，或条目没有字符串形式的 codePath／symbol 时会抛错，避免损坏文件静默清空已有关系。[关联文件加载与最小校验 ↗](../../../apps/server/src/review/associations.ts#L51 "支持缺失文件返回空、损坏文件抛错及字段默认化的行为。") 其余字段采用较宽松的默认值，尤其未知 status 会落为 confirmed；引用拆分也只按首个双冒号机械分割。[关联引用锚点拆分 ↗](../../../apps/server/src/review/associations.ts#L92 "说明 path 与 anchor 仅按首个双冒号进行拆分。") 因而本层属于最小结构校验，不能替代同步阶段的 locator 解析、状态降级和交叉引用验证。
