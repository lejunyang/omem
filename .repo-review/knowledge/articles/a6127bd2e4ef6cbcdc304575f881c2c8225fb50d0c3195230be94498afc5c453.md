# 评审关系种子的加载与引用解析

该模块定义人工维护的代码—依据关系种子格式，从仓库固定 JSON 文件加载并做最低限度校验，同时解析带锚点的文档引用。它刻意不执行语义匹配；缺失文件返回空集合，损坏 JSON 或缺少关键定位字段则显式失败。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-model"></a>
## 解决的问题与数据模型

该模块为 repo-review 提供人工策划的关联入口：代码由仓库相对路径和符号定位，关联意图、需求标签、决策、研究及测试依据，并附关系状态和证据说明。其目的不是根据词义自动猜测关系；只有明确写入种子的数据才有资格在后续同步中成为确认关系。[人工关联种子的职责边界 ↗](../../../apps/server/src/review/associations.ts#L1 "支持附近关于人工策划、非自动语义匹配及确认关系来源的论断。") 数据保存在 `docs/repo-review/associations.json`，TypeScript 文件负责声明结构，使构建后的服务可以直接读取普通 JSON，同时保持编译期类型约束。[关联文件位置与类型约束 ↗](../../../apps/server/src/review/associations.ts#L9 "说明数据为何存为普通 JSON，以及本模块承担的类型定义职责。")

<a id="loading-flow"></a>
## 加载与规范化流程

`associationsPath` 组合仓库根目录、固定目录和文件名。加载时若文件不存在便返回空数组，适配新检出仓库或自备夹具；若文件存在，则同步读取并解析 JSON，解析错误会携带路径抛出，避免损坏配置被误当成“没有关系”。[关联文件加载与错误处理 ↗](../../../apps/server/src/review/associations.ts#L51 "支持路径组合、缺失文件返回空集合以及 JSON 损坏时显式抛错的流程描述。") 根对象必须含 `associations` 数组，每项至少需要字符串形式的 `codePath` 与 `symbol`；其余字符串或数组字段缺失时归一化为空值。状态仅明确接受 `candidate`、`missing`，其他输入都会落为 `confirmed`。[种子条目校验与默认值 ↗](../../../apps/server/src/review/associations.ts#L67 "支持最低限度字段校验、可选字段归一化和关系状态默认规则。") 这种校验属于最低限度结构校验，并未验证数组元素类型、路径存在性、符号能否解析或引用目标是否有效。

<a id="reference-boundaries"></a>
## 引用语法、模块关系与边界

引用采用 `path` 或 `path::anchor`：解析器只按首次出现的 `::` 切分，未出现时锚点为 `null`，出现时保留其后的全部文本；它不负责路径标准化、锚点查找或目标存在性验证。[路径锚点解析规则 ↗](../../../apps/server/src/review/associations.ts#L92 "支持对 path::anchor 首处分隔行为及解析器职责边界的说明。") 模块从评审存储层仅导入 `RelationStatus` 类型，说明状态词汇与关系存储合同保持一致，但材料未展示同步函数如何把种子写入关系表，因此不能据此确认具体 upsert、去重及失败保留行为。[关系状态类型依赖 ↗](../../../apps/server/src/review/associations.ts#L12 "证明该模块与评审存储层共享 RelationStatus 类型，但不证明运行时写表流程。") 评审存储本身使用隔离运行目录，不触碰个人工作区状态；这是该种子文件所服务的 repo-review 边界背景，而非本模块直接实施的数据隔离。[评审存储隔离边界 ↗](../../../apps/server/src/review/store.ts#L1 "提供 repo-review 使用独立数据目录且不触碰个人工作区状态的模块背景。")
