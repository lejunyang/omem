# 模块理解与文件入口帧

在互斥的知识文章或结构化模块说明之下，持续提供按语言分组的模块文件入口和符号证据导航。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="content"></a>
## 两类模块说明

组件按模块标识尝试读取已保存的知识文章，同时接收父组件提供的结构化理解；模块文件按语言分组，并按组内文件数排序。[知识读取与文件分组 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L31 "支持知识文章异步读取、模块详情输入和文件语言分组流程。") 当没有文章时，结构化详情才依次展示职责、边界、关键流程、入口、出口、风险、未决问题和引用，并用人工 seed、模型派生、stale、模型名及策展者字段标识来源。[结构化模块理解 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L82 "说明模块职责、流程、风险及来源和过期状态如何呈现。")

<a id="display-priority"></a>
## 互斥展示与稳定文件入口

文章、加载提示、空状态和结构化详情位于同一条 `v-if / v-else-if / v-else` 条件链，因此文章存在时不会同时显示结构化详情；这替代了“文章优先但详情仍可能继续显示”的旧结论。[模块说明条件分支 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L68 "精确证明知识文章、加载、空状态和结构化详情互斥显示。") 文件列表位于条件链之后，无论上方采用哪种说明路径仍会展示，并直接发出 file drill。[引用区与文件入口 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L131 "支持 evidence 静态展示、文件始终位于说明分支之后，以及删除态文件仍可点击。")

<a id="references"></a>
## 引用解析与未完成下探

详情引用按 node 和 evidence 分流。符号引用优先从 symbolMap 取得名称，其次使用策展备注，避免显示内部标识；点击时只发出 symbolId，所属 fileId 交由父容器从全局图补齐。[符号引用的人类标签 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L46 "说明内部符号标识如何解析为可读名称并由父组件补齐所属文件。") evidence 引用当前仅为静态行，不会进入 FragmentFrame；已删除文件虽有醒目标记，按钮仍保持可点击，最终读取失败时的体验未在本组件中处理。[引用区与文件入口 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L131 "支持 evidence 静态展示、文件始终位于说明分支之后，以及删除态文件仍可点击。")
