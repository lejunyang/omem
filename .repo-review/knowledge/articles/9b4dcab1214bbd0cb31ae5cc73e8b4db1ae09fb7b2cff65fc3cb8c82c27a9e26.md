# 模块架构说明与文件下探界面

该 Vue 组件汇集模块级知识正文、结构化模块理解、证据引用和按语言分组的文件入口。替代此前“知识读取由其他模块完成”的结论：模块元数据读取由本组件发起，完整正文的再次加载与渲染交给 KnowledgeDocument；符号归属解析和实际下探仍由父级处理。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-states"></a>
## 职责与展示优先级

组件面向 Code Wiki 的单个模块，展示人读模块名、文件与解析符号数量，并协调已保存知识、结构化说明和文件入口。模块 id 变化时，它会先清空旧元数据，再主动请求 `module:<模块 id>` 对应的 `ArticleMeta`；因此此前“知识读取均由其他模块完成”的表述已被替代。当前实现捕获并忽略请求中的全部异常。[模块变化时读取文章元数据 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L31 "支持 ModuleFrame 主动监听模块标识、清空旧值并请求模块文章元数据，以及当前静默忽略请求异常的论断。")

主体按“已取得知识元数据—外部加载状态—无结构化说明空态—结构化说明”的顺序互斥展示，文件列表则始终位于说明区域之后。[主体状态分支与文件入口 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L68 "说明知识正文、加载提示、空态和结构化说明的展示优先级，并证明文件列表位于这些分支之后。") 这使组件在缺少已保存说明时明确提示用户浏览文件和原始证据，而不会根据文件或符号计数临时生成摘要。

<a id="structured-flow"></a>
## 结构化说明、引用与导航意图

进入结构化说明分支后，组件呈现职责、边界、关键流程、入口、出口、风险和未决问题，并以状态行和徽标区分人工 seed、模型派生、模型名称、整理者及过期结果。[结构化模块说明与来源状态 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L82 "支持组件展示模块职责、边界、流程、风险与未知项，并标注人工、模型和过期状态。")

引用分为符号和证据两类。符号标签优先使用 `symbolMap` 中的人读名称，其次使用说明注记，最后退化为“符号”，避免展示内部标识；点击后组件发出 symbol 下探意图，并将符号所属文件的解析留给父级。[符号标签与下探事件 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L46 "支持隐藏原始符号标识、采用人读标签，并由父级解析符号所属文件的描述。") 证据引用目前仅以静态行呈现，虽然面板标题写有“可下探”，却没有发出 fragment 事件；文件行则会直接发出带 `fileId` 的下探事件。[证据引用和文件下探 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L131 "证明证据引用当前为静态展示、文件行会发出下探事件，并可显示调用方传入的已删除文件。") 因而本组件负责生成部分导航意图，不负责阅读栈和最终目标解析。

<a id="knowledge-and-module-boundaries"></a>
## 知识加载链路与模块边界

模块标题和聚合数据来自模块辅助层；常规聚合会跳过已删除文件，并只把已确认、可解析到仓库文件的 import 纳入模块依赖。[模块聚合合同与过滤规则 ↗](../../../apps/web/src/codewiki/modules.ts#L36 "说明人读模块标签、聚合数据结构、依赖边纳入条件及已删除文件的常规过滤行为。") 本组件本身不计算依赖，但若调用方仍传入带 `removed` 标记的文件，它会保留该行并显示“已删除”徽标。[证据引用和文件下探 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L131 "证明证据引用当前为静态展示、文件行会发出下探事件，并可显示调用方传入的已删除文件。")

知识链路分为两级：本组件先读取文章元数据，随后把文章 key 与 revision 交给通用 `KnowledgeDocument`；后者再次请求完整文章，处理竞态、加载失败、分节正文、问题区以及可操作引用的导航。[完整知识正文加载器 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L11 "支持 KnowledgeDocument 负责完整文章的再次请求、异步竞态控制、错误状态、分节渲染和引用导航。") 底层 `knowledgeApi` 会附带会话令牌，并把任何非成功 HTTP 响应转换为异常。[知识接口错误处理 ↗](../../../apps/web/src/knowledge/api.ts#L6 "说明知识请求携带会话令牌，并在 HTTP 响应失败时抛出包含服务错误或状态码的异常。") 由于元数据阶段吞掉所有异常，文章不存在、网络失败和服务故障目前都会回退为 `knowledge` 为空，现有材料不足以确认这是否是最终产品约定。
