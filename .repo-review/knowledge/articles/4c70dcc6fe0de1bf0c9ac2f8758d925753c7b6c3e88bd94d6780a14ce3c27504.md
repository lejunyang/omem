# 来源修订画像服务

该服务为已捕获的来源修订生成可追溯、确定性的导航画像：识别文本载体、标题层级、语言、主题、时态、话语类型、显式链接与覆盖缺口，并按代次写入 SQLite。画像属于派生元数据，失败时原则上不应阻断原始证据读取。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-contract"></a>
## 作用与数据合同

服务为原始修订补充可用于导航和问答范围判断的结构信息。`SourceProfile` 汇集载体类型、标题路径、语言、主题候选、话语片段、时间提示、链接、证据引用、处理状态及画像版本；`derived: true` 明确它是派生视图而非新的事实来源。[来源画像数据结构 ↗](../../../apps/server/src/source-profile/service.ts#L35 "支持画像所含派生字段、状态、证据引用及版本信息。") `latest` 按画像代次倒序读取指定修订的最近记录，允许历史代次继续留存。[最新画像读取 ↗](../../../apps/server/src/source-profile/service.ts#L119 "支持按画像代次倒序返回指定修订的最近记录。")

<a id="analysis-flow"></a>
## 核心分析流程

持久化入口读取修订正文和按序排列的固定片段，调用分析函数后查询已有最大代次、递增编号并写库。[画像生成与持久化入口 ↗](../../../apps/server/src/source-profile/service.ts#L131 "支持读取修订和片段、执行分析、递增画像代次并写入数据库的流程。") 分析先维护 Markdown 标题栈，让非标题片段关联最近父标题，同时记录时态和父标题指代；图片标记、含竖线文本及超长片段会形成覆盖缺口。[标题关联与覆盖缺口 ↗](../../../apps/server/src/source-profile/service.ts#L265 "支持标题栈、父标题关联、时态记录，以及图片、表格样式和超长片段的缺口检测。")

段落分类是有优先级的规则流程：代码或命令样式先归为示例，之后依次判断问题、约束、示例、定义、计划、历史和指令，未命中时归为普通论断。[话语分类规则 ↗](../../../apps/server/src/source-profile/service.ts#L75 "直接支持代码优先及问题、约束、定义、计划、历史、指令等分类的匹配顺序。") 这取代了旧稿中仅凭分类调用范围推断具体规则的表述。

<a id="topics-and-relations"></a>
## 主题提取与模块关系

主题候选由标题文本和片段高频词合并产生：内容通过共享的 `tokenize` 分词，过滤停用词与短词后按频次截取。[主题候选提取 ↗](../../../apps/server/src/source-profile/service.ts#L305 "支持通过共享分词器统计高频词，并与标题合并形成主题候选。") 关键词检索也使用该分词入口，并将长度至少为三个字符的词项送入 FTS 路径；由于材料未给出 `tokenize` 本体，仍不能断言完整的中英文切词规则。[关键词检索的查询分词 ↗](../../../apps/server/src/retrieval/keyword.ts#L53 "证明检索模块同样调用 tokenize，并说明较长词项进入 FTS 路径；该范围不包含分词器内部实现。") 正文上下文中的 application、conversationId、runId 会形成项目候选，结构化 parts 中的 URL 则形成显式链接。[上下文候选与显式链接 ↗](../../../apps/server/src/source-profile/service.ts#L337 "支持从正文上下文提取项目候选，并从结构化 parts 收集 URL。")

<a id="failure-and-boundaries"></a>
## 失败策略与边界

画像器同步、确定且尽力而为；修订缺失会抛错，正文 JSON 解析及数据库操作也可能失败。注释要求调用方隔离这些异常，使画像失败不妨碍原始证据捕获和阅读，但当前文件不能证明所有入口均已遵守。[尽力而为的调用边界 ↗](../../../apps/server/src/source-profile/service.ts#L131 "支持画像失败应由调用方隔离，以及修订缺失和正文解析位于持久化入口中的判断。") `recordFailure` 尝试保存截断后的错误，并吞掉失败记录本身的写库异常。[失败画像记录 ↗](../../../apps/server/src/source-profile/service.ts#L168 "支持错误信息截断保存、二次写库异常被吞掉以及来源继续可读的设计意图。")

语言只按中日韩统一表意字符和拉丁字母计数判定，覆盖缺口存在时状态降为 `partial`。[语言识别与结果状态 ↗](../../../apps/server/src/source-profile/service.ts#L320 "支持字符计数阈值、画像结果字段及覆盖缺口决定 partial 状态的结论。") 图片不解析、表格仅凭竖线启发式识别的结论则来自缺口生成逻辑，而非语言与状态代码。[标题关联与覆盖缺口 ↗](../../../apps/server/src/source-profile/service.ts#L265 "支持标题栈、父标题关联、时态记录，以及图片、表格样式和超长片段的缺口检测。") 因此画像适合导航提示，不应替代原始片段或完整语义理解。
