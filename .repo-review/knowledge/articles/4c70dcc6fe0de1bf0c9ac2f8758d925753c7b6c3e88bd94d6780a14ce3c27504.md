# 来源修订的确定性导航画像

以规则方式从固定修订及有序片段生成结构、主题、语言、时态和覆盖缺口等导航元数据；画像按来源修订与生成代次存储并可读取最新版，但不是经过独立核验的事实，画像失败也不应阻断原始证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-model"></a>
## 作用与数据定位

该服务为固定来源修订生成导航画像，记录载体类型、标题路径、话语分类、候选主题、时间提示、显式链接、覆盖缺口和证据片段引用，并区分正常、部分和失败状态。[来源画像字段与状态 ↗](../../../apps/server/src/source-profile/service.ts#L35 "支持画像包含派生导航字段、证据引用以及正常、部分、失败三种状态。") 迁移说明明确画像是可重新派生、可能包含未知项的导航信息，而不是经过独立核验的新事实；画像失败不得阻碍原始证据读取。[画像的派生信息边界 ↗](../../../apps/server/src/storage/migrations.ts#L766 "支持画像不是已核验事实、允许重新派生且失败不得阻断原始证据读取。")

画像表以“来源修订 + 生成代次”为复合主键，并为同一修订建立代次倒序索引。[画像表主键与索引 ↗](../../../apps/server/src/storage/migrations.ts#L770 "直接支持画像以来源修订和生成代次为复合主键，并建立代次倒序索引。") 服务的 `latest` 查询与此结构一致，按生成代次降序取第一条。[最新版画像查询 ↗](../../../apps/server/src/source-profile/service.ts#L122 "支持服务按来源修订查询，并按生成代次降序读取第一条画像。") 这替代了此前仅用查询代码同时证明主键和索引结构的不充分论证。

<a id="analysis-flow"></a>
## 分析与持久化流程

`persistForRevision` 读取指定修订及其按 ordinal 排序的片段；修订不存在时抛错。分析完成后，它读取该修订已有最大代次、递增 generation，并写入完整画像。[画像生成与代次持久化 ↗](../../../apps/server/src/source-profile/service.ts#L131 "支持读取固定修订和有序片段、执行分析、递增生成代次并持久化的流程。") 分类器先识别图片占位和过短噪声，再按代码形态、问句、约束词、示例词、定义词、未来或历史提示及指令词分类，未命中时归为一般论断。[话语分类规则 ↗](../../../apps/server/src/source-profile/service.ts#L75 "直接支持问题、约束、计划、历史、示例、定义、指令和一般论断等分类规则。") 分析阶段维护 Markdown 标题栈，把正文关联到最近父标题；标题文本与去停用词后的高频词共同形成主题候选。[标题关联与主题候选 ↗](../../../apps/server/src/source-profile/service.ts#L251 "支持标题栈、父标题关联、分类结果写入及标题和高频词共同形成主题候选。")

<a id="boundaries"></a>
## 识别边界与失败降级

语言识别只统计汉字区间与拉丁字母，粗略输出中文、英文、混合或未知；项目候选来自正文上下文，显式链接来自带 URL 的内容部件。[语言、项目与链接候选 ↗](../../../apps/server/src/source-profile/service.ts#L320 "支持语言按汉字和拉丁字母计数粗判，并说明项目候选和显式链接的来源。") 图片占位、含竖线的疑似表格及超长片段会登记 coverage gap，使画像成为 `partial`，但当前实现不会理解图片、表格或长文的内部语义。[覆盖缺口判定 ↗](../../../apps/server/src/source-profile/service.ts#L271 "支持图片、疑似表格和长片段被登记为覆盖缺口，以及缺口影响画像状态。")

`recordFailure` 会尝试写入失败画像，并吞掉失败记录自身的数据库异常，以维持画像只是可选导航元数据的边界。[画像失败记录与降级 ↗](../../../apps/server/src/source-profile/service.ts#L168 "支持失败画像写入以及二次写库异常不影响来源可读性的降级设计。") 不过材料没有展示生产调用方如何捕获 `persistForRevision` 的异常，因此尚不能确认每条捕获路径都落实了该隔离。
