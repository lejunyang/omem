# 来源修订的规则化内容画像

从固定 revision 的片段派生结构、语言、话语类型、主题、时间提示和覆盖缺口，并把可重建画像按 generation 写入 SQLite。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="lifecycle"></a>
## 画像生命周期与容错

该服务把画像作为固定 revision 上的派生导航数据。`latest` 按 generation 读取最近一代；`persistForRevision` 查询 revision 与有序 fragments，执行规则分析、递增 generation 后写库。[画像读取与代次持久化 ↗](../../../apps/server/src/source-profile/service.ts#L119 "支持从固定修订及有序片段分析、递增 generation 并写库的生命周期。") 画像失败不应阻断原始证据：`recordFailure` 尽力插入 failed 行，连失败记录自身的写入异常也会被吞掉，使来源仍可读取。[画像失败隔离 ↗](../../../apps/server/src/source-profile/service.ts#L168 "支持失败元数据尽力写入以及画像异常不影响来源可读性的说明。")

<a id="analysis"></a>
## 结构与话语分析

标题识别要求整个 trimmed fragment 完整匹配一行 Markdown 标题；只有这种片段才进入标题栈并跳过话语分类。此前“只要片段以标题开头即可识别”的结论已被替代：标题后同片段仍带正文时不会匹配，会整体作为普通话语段处理。[完整片段标题匹配 ↗](../../../apps/server/src/source-profile/service.ts#L251 "正则的首尾锚点及分析循环共同证明只有整个 trimmed 片段为标题时才建立标题节点。")

普通片段继承最近父标题，再分类为定义、主张、约束、历史、计划、问题、指令、示例或噪声。代码、SQL、TODO 和 shell 命令优先归为示例，避免把材料命令误当执行指令；规则还提取时态和段内指称。[话语分类规则 ↗](../../../apps/server/src/source-profile/service.ts#L75 "支持代码材料优先、时态与指称识别，以及各话语类型的规则分类。")

<a id="coverage"></a>
## 主题、语言与覆盖限制

图片占位、表格样式及超长片段形成 coverage gap，并令画像状态变为 partial。主题候选合并标题与高频词，语言只按中英文字符阈值判断；项目候选仅读取少数 context 字段，显式链接只从带 `url` 的 parts 提取。所有 fragment ID 写入 evidenceRefs，表示可追溯而非人工确认。[主题、语言与覆盖分析 ↗](../../../apps/server/src/source-profile/service.ts#L265 "支持覆盖缺口、主题频率、语言阈值、项目候选、链接提取和 evidenceRefs 生成。")
