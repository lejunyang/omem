# 代码知识 DTO 的字段兼容与人类可读展示测试

该集成测试在临时 Git 仓库中生成 TypeScript 文件，依次执行评审捕获、代码结构投影并启动评审 HTTP 应用；它验证快照、文件和符号 DTO 保留内部操作键并提供人类可读字段，在图响应确实包含边时进一步检查图边 DTO。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 测试目标与背景

测试针对 DTO 演进中的兼容风险：查询与深链仍需 `fileId`、`symbolId` 等内部操作键，但界面标签不能直接暴露内部 ID 或长哈希。测试定义坏标签检测规则，并以“保留合同字段、增加展示及 trail 链接”为目标。[DTO 合同测试定义 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L25 "支持测试同时保留操作字段、增加展示与 trail 链接，并检测内部 ID 标签的目标。") 场景会初始化临时 Git 仓库，写入并提交 `greet.ts`，因此使用的不是手写 DTO fixture。[临时 Git 仓库与示例源码 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L33 "支持测试动态创建、提交真实 greet.ts 文件，而非使用手写 DTO fixture。")

<a id="flow"></a>
## 同步与查询流程

测试创建独立 `Store` 后，依次运行评审捕获、代码同步和评审应用，再通过进程内 HTTP 注入查询接口。[同步与应用启动顺序 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L44 "支持 Store、评审同步、代码同步和评审应用依次执行的流程说明。") 这一顺序具有数据依赖：代码同步只投影 TS/Vue 结构，不捕获文件正文，并从已捕获的当前 fragment 关联符号。[代码知识投影的数据前置条件 ↗](../../../apps/server/src/code/sync.ts#L1 "说明代码同步不捕获正文，并依赖评审同步已生成的 fragment 来关联符号。") 随后依次请求当前快照、文件列表、文件符号和代码图，覆盖从仓库输入到对外序列化的主要成功路径。[HTTP 查询序列与状态断言 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L52 "支持测试依次查询快照、文件、符号和图；该范围也显示只有快照请求显式断言状态码。")

<a id="assertions"></a>
## 实际断言覆盖

快照检查合同字段及七位短提交号；文件检查身份、路径、语言等字段，以及展示标题、展示路径和 trail 链接。[快照与文件 DTO 断言 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L52 "支持快照合同字段、短提交号，以及文件字段、展示路径和 trail 链接的检查。") 符号列表明确要求非空，再逐项检查身份、范围、展示名称、引用标签和深链，并排除内部 ID 作为标题。[符号 DTO 非空与字段断言 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L72 "支持符号列表非空、合同字段、人类标签、引用标签和深链格式的断言。")

图边检查位于对 `gBody.edges` 的循环中：仅当响应存在边时，才会验证端点、状态、来源、时间、`actionable`、展示标题与深链。因此，此处替代此前“已经验证图边 DTO”的无条件结论，应表述为条件性检查。[条件执行的图边 DTO 断言 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L87 "支持图边检查全部位于循环内且没有边数组非空断言，因此只能视为存在边时的条件性验证。")

<a id="limits"></a>
## 限制、响应检查与清理风险

该用例只覆盖单文件、干净提交的 TypeScript 成功路径；同步器声明的未提交文件、Git 失败退化、非 UTF-8、超限文件及路径逃逸等边界并未在此触发。[评审同步的异常边界 ↗](../../../apps/server/src/review/sync.ts#L7 "说明同步器还处理工作区变化、Git 失败、路径逃逸、编码和大小限制，但本测试未覆盖这些分支。") 图接口未断言边数组非空，文件、符号和图请求也没有像快照请求那样逐一显式断言 HTTP 200。[HTTP 查询序列与状态断言 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L52 "支持测试依次查询快照、文件、符号和图；该范围也显示只有快照请求显式断言状态码。")[条件执行的图边 DTO 断言 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L87 "支持图边检查全部位于循环内且没有边数组非空断言，因此只能视为存在边时的条件性验证。")

`afterEach` 统一关闭 Store 并删除登记的数据库目录，[Store 资源的 afterEach 清理 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L11 "支持 afterEach 只统一关闭已登记 Store，并删除对应数据库临时目录。") 但临时 Git 仓库只在测试主体末尾删除；若此前断言或应用关闭失败，可能遗留该目录。[测试末尾的仓库目录清理 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L100 "支持临时 Git 仓库 root 仅在测试主体末尾删除，因而中途失败可能绕过该清理。")
