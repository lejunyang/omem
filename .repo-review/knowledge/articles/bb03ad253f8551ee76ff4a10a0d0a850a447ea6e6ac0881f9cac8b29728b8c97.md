# 代码知识 API 的 DTO 合同验证

该集成测试用临时 Git 仓库和隔离数据库跑通仓库捕获、代码解析与 HTTP 查询，验证快照、文件、符号和图边既保留内部操作键，又提供适合界面展示与阅读轨迹跳转的人类可读字段；同时暴露了图边断言可能空跑及部分响应状态未覆盖的限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-scenario"></a>
## 防止 DTO 演进破坏界面与深链

测试解决的是代码知识 DTO 在演进中“可操作但不可读”或“可读但丢失路由键”的兼容问题。它创建只含 `greet` 函数的临时 Git 仓库，初始化隔离 Store，依次执行仓库材料同步、代码结构同步并启动评审 HTTP 应用，因而覆盖的是接近真实服务链路的集成场景，而非单独构造 DTO。参考 [临时仓库与服务链路 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L31 "支持测试通过真实 Git 仓库、Store、两阶段同步和 HTTP 应用建立集成场景的说明。")

其中 Store 会创建并迁移单用户 SQLite 数据库；评审应用则显式接入代码知识服务及文件、符号、边和快照 DTO 转换器。延伸阅读：[单用户 SQLite 初始化 ↗](../../../apps/server/src/store.ts#L38 "说明测试所用 Store 会初始化、迁移并保护本地 SQLite 数据库。")、[代码 DTO 接入点 ↗](../../../apps/server/src/review/app.ts#L41 "说明评审应用依赖代码知识服务以及文件、符号、边和快照 DTO 转换器。")

<a id="assertion-flow"></a>
## 从快照到文件、符号和关系图

验证按读取层级展开：先查询当前快照，要求提交、脏状态、解析器版本、文件数量等合同字段仍存在，并检查七位短提交号；再查询文件列表，确认内部定位字段未丢失，同时展示名、仓库相对路径和 trail 链接可直接供 UI 使用。参考 [快照合同断言 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L52 "支持快照基础字段与短提交号格式的验证说明。")、[文件展示字段断言 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L61 "支持文件内部键、可读标题、展示路径和 trail 链接同时保留的说明。")

随后通过文件标识查询符号，逐项检查名称、范围、导出状态等结构字段，并要求 `symbolName`、引用标签、API 深链和 trail 链接有效，展示标题不能是内部 ID 或长哈希。最后读取关系图：每条边需保留端点、状态和来源；`missing` 或 `stale` 边必须不可操作，展示标题也不得泄露内部标识。参考 [符号可读性与链接断言 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L72 "支持符号结构字段、引用标签、深链及内部 ID 不得作为标题的说明。")、[关系图边断言 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L87 "支持边合同、不可操作状态规则，也表明断言位于可能不执行的边遍历中。")

<a id="boundaries"></a>
## 测试边界与未覆盖行为

这项测试明确验证 DTO 字段形状和标签卫生，但没有断言文件、符号、图接口的 HTTP 状态码，也没有验证链接实际打开后的内容或前端交互。更关键的是，测试仓库只有一个无调用关系的函数，图边断言位于遍历循环中；若 `edges` 为空，端点、状态、`actionable` 与深链检查会全部跳过，因此不能据此证明边 DTO 已被实际覆盖。参考 [关系图边断言 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L87 "支持边合同、不可操作状态规则，也表明断言位于可能不执行的边遍历中。")

代码同步自身声明：结构行是已捕获原文之上的投影，符号通过声明行关联当前 Fragment；输入变化会创建新快照，并把未重新生成的结构标为 stale。当前测试只跑一次同步，未覆盖幂等复用、修改后重建及 stale 转换。参考 [代码结构投影与快照语义 ↗](../../../apps/server/src/code/sync.ts#L1 "解释代码同步依赖已捕获 Fragment、快照幂等及旧结构转为 stale 的设计边界。")
