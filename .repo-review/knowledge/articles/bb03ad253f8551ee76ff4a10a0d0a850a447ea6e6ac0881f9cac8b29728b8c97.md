# 代码知识 DTO 展示与导航合同测试

该集成测试确保 review API 在保留内部操作键的同时提供人类可读标签、深链和 trail 链接，并禁止失效图边被标记为可操作。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="setup-and-snapshot"></a>
## 真实 Git 快照下的接口合同

测试创建并提交一个包含 `greet` 函数的临时 Git 仓库，执行 review/code 同步后直接注入 HTTP 请求。当前快照响应必须保留 snapshotId、commit、dirty、解析器版本、文件统计、repoId 与 baselineCommit 等合同字段，并额外提供七位 shortCommit。[快照 API 字段合同 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L31 "支持测试使用真实同步后的 HTTP 接口，并校验快照原始字段及短提交展示值的说明。")

这种搭建验证了同步结果到 API DTO 的集成，而不只是独立格式化函数；但只覆盖单文件、单次提交和成功响应，没有测试脏工作树、部分快照或不存在资源的错误 DTO。

<a id="labels-and-actions"></a>
## 内部标识与可见文本分离

文件 DTO 必须同时保留 fileId、路径、语言、哈希等操作字段，并提供文件名、展示路径和 trail 链接。符号 DTO 保留定位与范围字段，同时提供 symbolName、citationLabel、API 深链和 trail 链接；测试用正则防止内部 ID 或长哈希成为 displayTitle。[文件与符号展示字段 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L61 "支持内部动作键被保留、同时补充人类标签和导航链接的论断。")

图边同样保留端点、状态、来源和时间字段，并提供布尔 `actionable`；当状态为 missing 或 stale 时必须不可操作，展示标题也不能泄露内部标识。[图边可操作性合同 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L87 "支持图边端点字段完整、失效或过期边不可操作且展示文本不能使用内部 ID 的说明。") 测试未断言 reason 的具体人读内容，也未覆盖前端是否错误渲染原始 ID。
