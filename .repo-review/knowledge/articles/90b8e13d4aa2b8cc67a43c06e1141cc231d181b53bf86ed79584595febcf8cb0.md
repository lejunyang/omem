# Store 的版本化证据与事务行为测试

该测试套件以临时目录中的真实 Store 实例验证单用户 SQLite 基础链路，覆盖捕获去重、不可变历史、恢复并发保护、循环引用、图片拒绝、待办提醒幂等及字面量搜索等关键行为。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="setup-and-contract"></a>
## 测试环境与输入合同

测试为每个场景创建独立临时目录和 `Store`，并在用例后关闭数据库、递归清理目录，从而隔离持久状态。输入并非随意拼装，而是先通过共享的 `captureSchema` 解析，携带已验证 owner、采集器、事件时间和原始材料标记；这同时验证测试数据符合应用捕获合同。[临时 Store 与合法捕获输入 ↗](../../../apps/server/tests/store.test.ts#L1 "支持测试隔离方式以及输入经过共享合同校验的说明。")

<a id="revision-and-relations"></a>
## 版本、恢复与关系断言

捕获相同内容会被识别为重试并复用版本，而内容变化生成 v2；旧片段仍返回原文且旧 revision 被标为非当前，说明历史证据不随 head 改写。恢复操作继续创建 v3，并保留被恢复前的 v2；再次基于旧 head 恢复会抛出 `REBASE_REQUIRED`。[不可变版本与恢复断言 ↗](../../../apps/server/tests/store.test.ts#L40 "支持内容去重、历史固定、恢复创建新版本及陈旧回滚被拒绝。") 关系测试进一步建立双向循环，再重复写入同一边，断言 outgoing/backlink 都只保留一条，表明循环可导航而重复边幂等。[循环关系与重复边测试 ↗](../../../apps/server/tests/store.test.ts#L68 "支持循环引用可导航且重复关系写入幂等的结论。")

<a id="validation-and-state"></a>
## 发布前校验与状态版本

伪造为 PNG 的非图片字节会在发布 revision 前失败，且材料列表和通知均保持为空，验证失败不会留下半完成状态。[图片类型不匹配测试 ↗](../../../apps/server/tests/store.test.ts#L79 "支持无效图片在 revision 和通知发布前被整体拒绝。") 过期待办在同一状态版本内重复扫描只提醒一次；状态更新要求期望版本，旧版本写入被拒绝，重新打开后才产生新一轮提醒。搜索 `%` 只命中字面包含百分号的片段，避免 SQL LIKE 通配符扩大结果。[提醒版本与百分号搜索测试 ↗](../../../apps/server/tests/store.test.ts#L98 "支持提醒幂等、乐观并发控制及字面量百分号搜索行为。")

<a id="coverage-boundary"></a>
## 覆盖边界

这些是 Store 的真实行为断言，但只覆盖列出的代表性路径：未验证进程崩溃后的事务恢复、并发连接竞争、资产文件落盘失败、外部通知实际投递，也没有证明所有 schema 边界和搜索转义字符都正确。测试使用本地临时数据库，因此不能作为团队租户隔离或其他数据库后端的证据。[当前测试用例范围 ↗](../../../apps/server/tests/store.test.ts#L40 "界定该文件实际只有六组 Store 行为测试，不能外推到未出现的并发、崩溃和外部集成场景。")
