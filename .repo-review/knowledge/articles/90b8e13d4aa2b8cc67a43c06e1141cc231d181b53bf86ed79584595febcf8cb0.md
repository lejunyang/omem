# Store 的版本化证据、事务通知与任务状态测试

该测试以临时 SQLite 数据目录实例化真实 Store，验证捕获重试去重、不可变历史修订、恢复冲突、循环引用、图片校验失败、任务提醒幂等与搜索转义。它主要证明可观察行为；现有 Store 源码只展示定位说明和构造过程，具体方法的事务与 SQL 实现仍待核对。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="setup-and-contract"></a>
## 测试装配与输入合同

测试为每个场景创建独立临时目录和 `Store`，并在用例结束后关闭数据库、清理目录，以隔离持久化状态。输入先经共享 `captureSchema` 解析，携带文本、来源、操作者、时间及生产者类型等 provenance，因此测试同时覆盖服务端存储入口与捕获合同的运行时约束。[临时 Store 装配与清理 ↗](../../../apps/server/tests/store.test.ts#L1 "支持测试使用隔离临时目录、真实 Store 实例并在每个用例后释放资源的说明。") [捕获测试输入及来源信息 ↗](../../../apps/server/tests/store.test.ts#L20 "支持测试输入通过共享合同解析，并携带文本和 provenance 元数据的说明。")

`Store` 构造时创建 SQLite 文件、执行迁移、建立资产目录并初始化仓储和服务。源码明确将 SQLite 定位为单用户基础，团队级 Postgres 与租户强制仍属后续迁移，所以这些测试不能作为团队隔离已经实现的证据。[Store 的单用户 SQLite 定位与初始化 ↗](../../../apps/server/src/store.ts#L4 "支持 SQLite 是当前单用户基础，以及构造阶段创建数据库、迁移、资产目录和各仓储服务的论断。")

<a id="evidence-behavior"></a>
## 版本证据、恢复与引用关系

相同输入重试会被标记为重复，内容变化则生成版本 2；旧 fragment 仍保留原文，旧 revision 不再是当前版本，同时保存 actor provenance。有效发布增加通知，体现“当前状态可演进、历史证据保持固定”的外部合同。[捕获去重与不可变历史断言 ↗](../../../apps/server/tests/store.test.ts#L40 "支持重复捕获、版本递增、旧证据固定、来源保留和通知数量的行为结论。")

恢复不会覆盖历史，而是把旧内容发布为版本 3；再次基于过期版本恢复会抛出 `REBASE_REQUIRED`。循环引用测试还表明双向边可导航，同一方向的重复链接会被去重，通知只随有效关系写入增长。[恢复生成新版本与过期恢复拒绝 ↗](../../../apps/server/tests/store.test.ts#L54 "支持恢复生成版本 3、历史内容不被覆盖以及陈旧恢复触发重基错误的结论。") [循环引用与重复边去重 ↗](../../../apps/server/tests/store.test.ts#L68 "支持双向循环仍可导航、同向重复链接被去重及通知数量变化的结论。")

<a id="atomicity-tasks-search"></a>
## 失败原子性、任务提醒与搜索边界

把普通字节伪装成 PNG 会在 revision 对外发布前失败，公开列表和通知均为空；这证明没有留下可见记录，但尚未直接验证资产文件或底层数据库中间行是否残留。[图片类型不匹配时拒绝发布 ↗](../../../apps/server/tests/store.test.ts#L79 "支持无效图片导致捕获失败且不产生公开列表记录或通知的可见原子性结论。")

过期任务连续提醒两次只产生一次对应提醒；状态更新使用旧版本号会抛出 `STALE_TASK_VERSION`，完成态不再提醒，重新打开并递增状态版本后才可再次提醒，说明提醒去重至少与任务状态版本相关。[按任务状态版本去重提醒 ↗](../../../apps/server/tests/store.test.ts#L98 "支持提醒幂等、任务状态乐观并发以及重新打开后允许再次提醒的行为说明。") 搜索 `%` 仅命中正文确实含百分号的记录，证明百分号按字面量处理；其他通配符与转义字符不在本用例覆盖范围内。[百分号按字面量搜索 ↗](../../../apps/server/tests/store.test.ts#L118 "支持百分号不会被解释为搜索通配符的断言，并界定该用例只覆盖百分号。")
