# 仓库评审关系的同步与查询验证

该测试通过临时 Git 仓库和隔离 SQLite Store，验证关联种子如何生成独立意图片段及代码、需求之间的关系，并覆盖重复同步、缺失目标、种子移除和 HTTP 查询等边界。它验证的是关系同步与查询合同，不等同于真实业务能力的端到端验收。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-fixture"></a>
## 测试要解决的问题

这组测试用于防止仓库评审关系在同步时相互覆盖或连接到错误材料。每个用例创建临时 Git 仓库和独立 Store，并在结束后关闭数据库、删除临时目录，避免测试状态串扰。参考 [隔离仓库与存储夹具 ↗](../../../apps/server/tests/review-relations.test.ts#L15 "支持测试创建独立 Store、临时 Git 仓库并在每例后清理资源的说明。")

夹具安排两个不同符号共享需求，其中一个引用多个需求；同时放入一个未登记、但含同名符号的文件。测试由此确认：未登记文件不会仅因存在同名符号而被建立关系。参考 [未登记同名符号夹具 ↗](../../../apps/server/tests/review-relations.test.ts#L69 "支持夹具刻意加入未登记的同名符号文件，以及测试不为该文件生成关系的结论。") 关联清单则明确记录代码路径、符号、需求、决策和测试引用，作为同步输入。参考 [人工关联清单 ↗](../../../apps/server/tests/review-relations.test.ts#L133 "支持夹具写入关联清单，并为不同代码符号声明需求、决策和测试引用的说明。")

<a id="sync-invariants"></a>
## 同步后的关系不变量

每条关联种子会形成独立的短意图片段，代码以 `implements` 指向它，而不是指向包含多个需求编号的整张表；共享需求的两个种子也不会互相覆盖。参考 [独立意图片段断言 ↗](../../../apps/server/tests/review-relations.test.ts#L207 "支持每条种子生成独立意图片段、避免绑定整张需求表以及 implements 端点有效的论断。")

每个需求引用都会生成一条 `requires`，重复同步复用既有关系标识；未登记的同名文件没有关系记录。参考 [多引用与幂等同步 ↗](../../../apps/server/tests/review-relations.test.ts#L245 "支持多需求引用生成多条关系、重复同步复用关系标识，以及未登记同名文件不产生关系的说明。") 对于无法解析的目标，测试实际确认的是：来自不同种子的缺失关系保持为互不合并的记录，避免空端点碰撞；种子从清单移除后，其旧关系会转为 `stale`。参考 [缺失关系与过期处理 ↗](../../../apps/server/tests/review-relations.test.ts#L294 "支持不同种子的缺失关系不会因空端点合并，以及种子移除后旧关系转为 stale 的结论。")

<a id="api-contract"></a>
## 关系查询接口的验证

测试先运行同步，再构建本地 HTTP 应用，通过注入请求检查关系查询。代码片段应返回出向 `implements`；意图片段应返回反向 `implemented_by` 和出向 `requires`。列表接口支持按状态、类型过滤，关联摘要能够报告种子数量。参考 [关系查询接口断言 ↗](../../../apps/server/tests/review-relations.test.ts#L338 "支持片段关系方向、状态与类型过滤、关联摘要，以及使用 Fastify 注入请求验证接口的说明。")

评审应用是隔离的读取、浏览和同步入口，复用记忆服务与检索能力，但不承载完整助理运行时、通知 worker 或业务状态；因此这里证明的是同步、存储和路由之间的合同。延伸阅读：[评审应用职责边界 ↗](../../../apps/server/src/review/app.ts#L6 "解释评审 HTTP 应用复用检索能力，但不承载完整助理运行时、业务 worker 或业务状态。")

<a id="coverage-limits"></a>
## 断言范围与限制

夹具中的“跨轮证据复用”和“未完成轮次恢复”测试只有恒真断言，所以关系测试只能证明这些测试标题可被定位，不能证明相应业务行为已经正确执行。参考 [占位业务测试 ↗](../../../apps/server/tests/review-relations.test.ts#L122 "支持夹具中的跨轮复用与恢复测试仅为恒真占位、不能证明真实业务行为的限制说明。")

此外，用例没有覆盖关联文件语法错误、并发同步、事务中途失败、真实网络监听或前端对 `missing`、`stale` 状态的展示。HTTP 注入适合验证路由响应，但不能替代浏览器交互和安全边界验收。参考 [关系查询接口断言 ↗](../../../apps/server/tests/review-relations.test.ts#L338 "支持片段关系方向、状态与类型过滤、关联摘要，以及使用 Fastify 注入请求验证接口的说明。")
