# 仓库评审关系构建与查询测试

通过临时 Git 仓库验证 associations seed 驱动的关系投影：独立意图片段、多引用建边、缺失边保留、幂等同步、seed 移除后的失效和 API 双向查询；现有断言不证明精确符号级来源定位。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="fixture-model"></a>
## 显式关系 seed 与夹具边界

夹具建立两个指向同一代码文件但不同 symbol 的 association seed，二者共享 G08，其中一个还引用 G09；仓库同时含未列出的同名诱饵文件、需求表、决策和测试文档。seed 显式携带 `codePath`、`symbol`、intent 及引用。[关系夹具与显式 seed ↗](../../../apps/server/tests/review-relations.test.ts#L57 "说明 seed 字段、共享需求、不同 symbol、异路径诱饵及文档材料的夹具结构，并界定占位测试文本。") 当前断言证明关系由 seed 驱动、未列出的异路径诱饵不会产生关系，且不同 seed 不会互相覆盖；但没有逐一核对 `implements` 来源 fragment 是否落在各自函数符号上，因此不能据此宣称精确符号定位。[多引用、幂等与诱饵排除 ↗](../../../apps/server/tests/review-relations.test.ts#L245 "支持每个 requirementRef 独立建边、重复同步复用关系 ID，以及未列出的异路径同名文件不产生关系。")

<a id="sync-invariants"></a>
## 同步生成的不变量

每条 seed 生成独立短意图片段，`implements` 指向该意图而非整张需求表；两个 seed 的 intent fragment 不同。[每条 seed 的独立意图片段 ↗](../../../apps/server/tests/review-relations.test.ts#L207 "支持每条 seed 生成独立短意图，implements 指向意图且不会绑定整张需求表。") 每个 requirementRef 都产生一条从意图出发的 `requires`，重复同步复用关系 ID。[多引用、幂等与诱饵排除 ↗](../../../apps/server/tests/review-relations.test.ts#L245 "支持每个 requirementRef 独立建边、重复同步复用关系 ID，以及未列出的异路径同名文件不产生关系。") 无法解析的决策或测试引用仍分别保存为 missing，借助不同 seed identity 避免空端点记录互相覆盖。[缺失关系独立保存 ↗](../../../apps/server/tests/review-relations.test.ts#L294 "支持多个无法解析的引用分别保留为 missing 行，而不会因空端点互相覆盖。")

<a id="lifecycle-api"></a>
## 生命周期与 API 投影

从 associations 清单移除 seed 并重新同步后，相关旧边转为 stale。[移除 seed 后关系失效 ↗](../../../apps/server/tests/review-relations.test.ts#L313 "支持 associations 清单移除条目并重新同步后相关旧边转为 stale。") fragment API 在代码端返回正向 `implements`，在意图端派生 `implemented_by`，并暴露 `requires`；列表支持按状态和类型过滤，摘要返回 seed 数量。[关系 API 查询与过滤 ↗](../../../apps/server/tests/review-relations.test.ts#L338 "支持正向 implements、反向 implemented_by、requires、状态与类型过滤及 seed 数量摘要。") 这些用例未验证鉴权、多用户隔离、跨文件 calls、跨 revision 身份续接、恶意 seed 或并发同步；夹具测试文档中的 `expect(true)` 也只是定位文本，不能证明对应业务行为。[关系夹具与显式 seed ↗](../../../apps/server/tests/review-relations.test.ts#L57 "说明 seed 字段、共享需求、不同 symbol、异路径诱饵及文档材料的夹具结构，并界定占位测试文本。")
