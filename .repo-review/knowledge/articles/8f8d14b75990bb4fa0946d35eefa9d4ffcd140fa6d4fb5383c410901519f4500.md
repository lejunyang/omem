# Proposal v1 草案 Schema

以 JSON Schema 约束任务、主张、经历和方法四类提案，统一证据、作用域、来源与乐观并发字段，并针对更新或替代操作要求目标及预期版本。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="common_contract"></a>
## 公共合同与证据

该文件自称“Proposal v1 draft”，要求提案携带版本、ID、种类、操作、作用域、正文、证据、不确定性、理由、预期版本及来源，并拒绝顶层未知字段。[提案公共必填字段 ↗](../../../docs/implementation/batch2/examples/proposal.schema.json#L1 "支持 Schema 的草案性质、顶层必填字段及禁止未知属性的说明。") 证据至少一项，可为带精确引文和 Unicode 选择器的文本证据，也可为绑定资源哈希、推断标记、可选归一化区域及观察描述的图片证据。[文本与图片证据分支 ↗](../../../docs/implementation/batch2/examples/proposal.schema.json#L73 "支持两类证据结构及其固定修订、哈希、区域和观察约束。") 这是合同草案本身，不能据此断言所有生产入口都已采用或完整验证它。

<a id="typed_bodies"></a>
## 分类正文与并发约束

Schema 按 kind 收紧正文：task 要求标题、负责人、截止时间、原始日期表达和下一步；claim 保存陈述、归因及有效期；episode 保存触发、动作、核验引用和结果；procedure 则要求前置条件、步骤、验证、反例及不适用范围。[分类正文约束 ↗](../../../docs/implementation/batch2/examples/proposal.schema.json#L240 "支持任务、主张、经历和方法各自采用不同必填正文的论断。") 当操作为 update 或 supersede 时，必须提供非空 target_id，且 expected_versions 至少包含一项，用于阻止对过期目标的无条件覆盖。[更新与替代前置条件 ↗](../../../docs/implementation/batch2/examples/proposal.schema.json#L472 "说明更新或替代操作必须指定目标并携带至少一个预期版本。")
