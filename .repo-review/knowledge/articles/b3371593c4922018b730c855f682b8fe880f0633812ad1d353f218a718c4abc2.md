# 代码理解结果的投影、校验与生成存储

把当前代码快照、人工维护的模块理解种子与可选模型输出转换为可追溯、严格校验的派生结果，并确保失败或过期结果不会覆盖有效理解。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="responsibility"></a>
## 作用与数据边界

该模块连接当前代码图、固定源码文本与 `CodeUnderstanding.v1`：同步时构造快照、解析人工种子的稳定 locator、封装摘要并校验交叉引用；理解正文及引用侧表属于派生投影，不改写原始文件、符号或关系图。[固定快照与派生数据边界 ↗](../../../apps/server/src/code/understanding-store.ts#L1 "说明模块如何从当前图和固定文本解析种子、执行严格校验，并强调理解结果及引用是不会改写原始代码图的派生投影。") 快照仅纳入合同支持的符号类型，未建模的类型不能被理解结果引用。[快照符号筛选 ↗](../../../apps/server/src/code/understanding-store.ts#L98 "支持快照仅保留合同允许的符号类型、其他解析符号不能被理解结果引用的限制。") 现有解析调用只有名称级信息且 caller 为空，因此这里明确使用空边集；这不能证明存在已确认的符号间或跨文件调用。[空调用边的明确依据 ↗](../../../apps/server/src/code/understanding-store.ts#L262 "直接支持解析调用缺少 caller、因此快照采用空边集而不宣称已确认符号调用关系的论断。")

<a id="projection"></a>
## 种子投影与失败隔离

证据文本必须从固定快照取得：selector 截取指定源码行，裸 ref 读取真实文档；文件无法解析时登记证据错误，不能用种子作者的摘要自证。[固定证据解析与缺失记录 ↗](../../../apps/server/src/code/understanding-store.ts#L213 "说明证据必须来自固定源码或文档内容，以及 selector 文件或裸 ref 文档缺失时如何产生可拒绝的错误。") 投影还会把路径、限定名和类型转换为当前快照符号，并检查 claim 中的 evidence hint；节点、证据文件或 hint 缺失都会累积为错误，最终持久化为 rejected 行并继续处理其他种子。[定位解析与拒绝持久化 ↗](../../../apps/server/src/code/understanding-store.ts#L304 "支持节点 locator、证据错误和 evidence hint 的解析，以及任一解析错误都会写入 rejected 结果而非静默丢弃引用。") 成功输出被固定为 `seed=true`、无模型且未经代理验证，通过共享校验后写入当前结果、镜像规范化引用，并将此前结果保留为 stale 历史。[种子校验、引用镜像与历史保留 ↗](../../../apps/server/src/code/understanding-store.ts#L420 "说明种子真实性字段、严格合同校验、接受结果写入、规范化引用镜像及旧结果 stale 标记的流程。")

<a id="generation"></a>
## 可选模型生成的约束

模型路径只有在显式提供端口且存在 head 快照时可运行。它按目标路径筛选文件和符号，完整组装提示后检查输入预算，并以超时或外部取消信号中止；未知目标、传输失败、输出超限及畸形 JSON 都只形成失败记录。[模型范围、预算与中止处理 ↗](../../../apps/server/src/code/understanding-store.ts#L674 "说明模型生成的前置条件、目标范围裁剪、提示及预算检查，并覆盖取消、超时、传输和输出解析失败的处理。") 服务端重新封装模型名、角色摘要和输入摘要，随后执行合同校验及“引用必须实际展示给模型”的范围检查；提交前若 head 已变化也拒绝发布，只有通过全部防线的结果才替换同目标的当前模型理解并镜像引用。[来源封装与提交前防线 ↗](../../../apps/server/src/code/understanding-store.ts#L834 "支持服务端封装不可伪造的来源字段、检查引用可见范围、阻止 head 移动后的过期提交并镜像成功引用。")
