# 代码理解结果的生成、校验与持久化

该模块把固定代码快照、人工维护的理解种子或显式模型输出转换为可追溯记录，并负责定位引用、合同校验、失败隔离和读取。人工种子与模型结果采用不同的淘汰规则：种子投影会把同模块最新的任意来源记录标为过期，而模型提交只淘汰旧模型结果。原始代码图不被改写。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 从固定代码证据生成模块说明

该模块解决“模块说明如何绑定到确定源码证据”的问题。人工种子以仓库路径、限定符号名和类型描述引用对象；宿主将定位器解析到当前代码快照，封存角色、输入和结构摘要，再执行统一校验。正文及其引用属于派生数据，不会改写原始文件、符号或代码边。参考 [派生理解职责 ↗](../../../apps/server/src/code/understanding-store.ts#L1 "支持种子定位、摘要封存、严格校验、引用镜像及不改写原始代码图的职责说明。")

快照中的文件正文来自指定代码快照，文档类证据也会作为固定文件加入，因此符号位置和行号选择器都针对同一份输入验证。参考 [固定快照输入 ↗](../../../apps/server/src/code/understanding-store.ts#L143 "说明代码正文和文档证据如何从指定快照组装为可校验输入。")

<a id="seed-flow"></a>
## 人工种子的定位、拒绝与来源交互

种子投影会逐一解析符号定位器和证据提示。找不到当前快照中的符号、证据文件或提示目标时，该种子会保存为 `rejected`，不会以缺失引用的形式进入当前结果。参考 [符号定位门禁 ↗](../../../apps/server/src/code/understanding-store.ts#L300 "支持无法解析的符号定位器被记录为错误，而非静默删除引用。") [拒绝结果持久化 ↗](../../../apps/server/src/code/understanding-store.ts#L378 "说明投影如何选择同模块此前记录，并把定位失败保存为拒绝结果。")

通过定位与共享合同校验后，宿主保存低置信度的 `seed` 结果，并把节点和证据引用镜像到规范化关系表。投影随后只把同模块查询到的最新一条其他记录标为过期；查询并不区分人工种子和模型来源，因此接受新种子时，最新模型结果也可能被标记为历史。相反，模型提交只淘汰旧模型结果，两类来源并非对称、互相独立地维护版本。参考 [种子接受与过期规则 ↗](../../../apps/server/src/code/understanding-store.ts#L447 "支持接受种子的写入、引用镜像以及不区分来源地将最新其他记录标为过期的行为。")

种子目录缺失时不会产生结果，非目标后缀会被忽略。畸形 JSON 在加载阶段被捕获后直接跳过，当前可见路径无法为该文件建立可查询的拒绝记录。参考 [种子文件加载 ↗](../../../apps/server/src/code/understanding-store.ts#L123 "说明目录、后缀及畸形 JSON 的实际加载行为，并支持畸形文件会被直接跳过的判断。")

<a id="model-flow"></a>
## 受预算和快照门禁约束的模型生成

模型生成需要宿主显式注入运行端口并已有当前代码快照。缺少端口会直接返回 `unavailable`，缺少快照会直接返回失败；这两个前置分支尚未建立运行标识，也不会写入失败历史。完成初始化后，预取消、未知目标等失败才通过统一持久化函数留档。参考 [模型前置检查 ↗](../../../apps/server/src/code/understanding-store.ts#L674 "支持缺少模型端口或代码快照时直接返回且不持久化，以及初始化后失败开始留档的边界。")

宿主把角色提示、目标范围内的完整文件正文、可引用符号和规则证据组成输入，并在调用前检查输入预算；超限会保存失败记录而不启动模型。预算计算复用服务端统一实现。参考 [输入与预算门禁 ↗](../../../apps/server/src/code/understanding-store.ts#L758 "说明完整输入的组装、预算估算及输入超限时保存失败结果的流程。") [统一预算实现 ↗](../../../apps/server/src/code/budget.ts#L1 "说明代码理解直接复用服务端 Agent Runtime 的预算估算和限制能力。")

运行阶段通过超时和外部取消信号竞速。模型只能返回叙事字段，来源摘要和模型身份由宿主封存；输出还要经过合同、实际展示范围及提交前快照检查。进入这些分支后的传输错误、格式错误、越界引用或快照移动都会保存为失败或拒绝历史。成功事务只负责淘汰旧模型结果并写入正文，规范化引用在事务结束后另行写入。参考 [运行校验与提交 ↗](../../../apps/server/src/code/understanding-store.ts#L790 "支持超时取消、来源封存、引用范围检查、快照移动保护、模型来源淘汰规则及引用在事务后写入的说明。")

<a id="boundaries"></a>
## 读取方式与能力边界

默认读取面展示未过期的有效人工种子和模型结果，查询全部历史时才包含失败、拒绝及旧记录；详情接口解析正文并另取规范化引用。模型是否可用完全取决于宿主是否注入端口，确定性代码图本身不要求模型。参考 [理解结果读取 ↗](../../../apps/server/src/code/understanding-store.ts#L521 "说明默认与历史查询范围、详情读取方式以及模型端口可用性判断。")

底层代码存储以仓库路径、限定名和内容摘要形成稳定身份，并在新快照中保留而非删除旧符号和边。参考 [代码图身份规则 ↗](../../../apps/server/src/code/store.ts#L1 "解释理解投影所依赖的文件、符号、边和快照身份及历史保留规则。") 理解合同、角色资源和交叉引用校验由 Agent Runtime 提供，SQLite 生命周期则由通用存储宿主管理。参考 [理解合同与固定输入 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L1 "说明 Agent Runtime 提供版本化输出合同、固定输入和确定性交叉引用校验。")

当前理解快照没有确认的符号调用边：现有解析结果只有名称级调用信息且缺少调用者，因此这里明确输出空边集合。模块说明不能据此证明跨文件调用关系。参考 [调用边能力边界 ↗](../../../apps/server/src/code/understanding-store.ts#L255 "支持因调用者信息缺失而输出空边集合，不能证明跨文件调用关系的限制。")
