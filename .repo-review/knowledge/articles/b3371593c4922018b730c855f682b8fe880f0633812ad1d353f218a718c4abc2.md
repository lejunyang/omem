# 代码理解结果的投影、生成与可信持久化

把固定代码快照、人工种子或模型输出转换为可查询的代码理解，并通过严格定位、引用范围、预算、取消和 head 快照栅栏阻止无依据或过期结果成为当前知识。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责与数据边界

该模块位于当前代码图与阅读接口之间：它从 head 图和固定源码构造 `CodeSnapshot`，解析人工 seed 的稳定定位器，并保存派生理解；原始文件、符号和边表不被改写。[代码理解投影的数据边界 ↗](../../../apps/server/src/code/understanding-store.ts#L1 "支持固定快照、稳定定位器、严格校验以及不改写原始代码图的职责说明。") 人工 seed 的输出被明确封装为 `confidence: 0.1`、无模型且未经过 Agent 独立验证；这取代了先前仅凭模块说明推断“低置信度”的表述。[人工种子的可信属性 ↗](../../../apps/server/src/code/understanding-store.ts#L420 "直接支持人工 seed 的低置信度、无模型和未独立验证属性。")

快照只接纳合同支持的符号类型。解析器调用边只有名称级信息且 caller 为空，因此当前快照诚实地使用空边集合，不能据此宣称已确认的符号调用链。[调用边的诚实边界 ↗](../../../apps/server/src/code/understanding-store.ts#L262 "支持因名称级调用缺少 caller 而使用空确认边集合的限制。")

<a id="seed-flow"></a>
## 人工种子投影流程

投影从固定快照读取证据文本：选择器截取真实源码行，裸引用读取真实文档；文件不存在会记录证据解析错误。[固定证据文本解析 ↗](../../../apps/server/src/code/understanding-store.ts#L213 "说明证据必须来自固定内容，以及证据文件缺失时如何记录错误。") 节点定位器会重新解析到当前 snapshot，引用了不存在的 evidence hint 也会形成错误；节点、证据文件和证据别名失败是三类不同来源，任一项都会拒绝该 seed，而不是静默删去引用。[节点与证据别名解析 ↗](../../../apps/server/src/code/understanding-store.ts#L304 "支持节点 locator、证据文件错误和 evidence hint 分别进入拒绝原因的流程。")

通过共享合同校验后，理解正文及规范化节点、证据引用写入侧表；旧结果保留但标记 stale。失败或 rejected 行会留痕，却不会遮蔽既有有效结果。[有效结果与历史结果持久化 ↗](../../../apps/server/src/code/understanding-store.ts#L447 "支持合同校验、规范化引用写入以及旧结果保留并标记过期。")

<a id="model-flow"></a>
## 模型生成与防护栅栏

模型路径首先要求宿主显式提供运行端口，并要求已有当前代码快照；缺少任一条件都会直接返回 unavailable 或 failed。[模型运行前置条件 ↗](../../../apps/server/src/code/understanding-store.ts#L684 "支持必须显式提供模型端口且必须存在当前代码快照。") 随后按仓库相对目标路径筛选文件和符号，限制展示节点数，完整组装提示后估算预算；目标没有符号或输入超预算时记录失败。[目标范围与提示预算 ↗](../../../apps/server/src/code/understanding-store.ts#L741 "支持路径前缀筛选、展示节点限制、无符号失败及输入预算检查。")

运行使用超时及外部取消信号竞速，宿主再封装模型身份、摘要和生成时间，校验模型仅引用实际展示的对象；提交前若 head 已移动，结果同样不会晋升为当前知识。[取消、引用范围与 head 栅栏 ↗](../../../apps/server/src/code/understanding-store.ts#L790 "支持超时取消、输出与引用范围校验以及提交前的快照移动检查。")

<a id="read-boundaries"></a>
## 读取面与限制

列表默认只返回未过期的有效人工结果和已生成模型结果，详情同时返回规范化引用与解析后的输出；模型可用性取决于宿主是否显式注入端口，原始代码图本身不依赖模型。[代码理解读取接口 ↗](../../../apps/server/src/code/understanding-store.ts#L521 "说明当前列表、详情内容和模型端口的可用性语义。")

目标路径前缀和最大展示符号数属于模型生成范围控制，空边集合则源自当前解析器缺少可靠 caller，二者不再归因于代码图身份说明。跨模块真实调用若要进入理解，仍需更可靠的 caller-to-callee 分析。[目标范围与提示预算 ↗](../../../apps/server/src/code/understanding-store.ts#L741 "支持路径前缀筛选、展示节点限制、无符号失败及输入预算检查。") [调用边的诚实边界 ↗](../../../apps/server/src/code/understanding-store.ts#L262 "支持因名称级调用缺少 caller 而使用空确认边集合的限制。")
