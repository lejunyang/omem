# omem 项目清单与运行入口

该清单定义了 omem 的 Node.js 运行基线、开发与验证脚本，以及服务端、Vue 构建、ACP、Lark、测试和格式化所需的直接依赖。它能说明项目声明的工具链和入口，但不能单独证明脚本已成功执行、能力已完整实现，或传递依赖已被锁定。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="runtime-and-entrypoints"></a>
## 运行基线与主要入口

项目是版本 0.1.0 的私有 ESM 包，要求 Node.js 24 或更高版本，这是运行各入口的基础兼容条件。[包元数据与 Node.js 版本要求 ↗](../../../package.json#L2 "支持项目为私有 ESM 包、当前清单版本及 Node.js 最低运行版本的说明。") 开发脚本分别覆盖统一开发、服务端监听、Web 前端和 repo-review；构建流程先编译服务端 TypeScript，再构建 Web 应用，生产入口执行编译后的服务端文件。[开发、构建与启动脚本 ↗](../../../package.json#L9 "说明各类开发入口，以及服务端编译、Web 构建和生产启动之间的配置关系。") 这些只是预期调用链的配置声明，不能证明对应服务已经启动或通过验收。

<a id="verification-workflows"></a>
## 验证、质量与维护流程

清单提供服务端与 Vue 的联合类型检查、Vitest、浏览器冒烟测试，以及角色、学习、流水线和 Lark Host 的独立现场检查入口。[类型检查与测试入口 ↗](../../../package.json#L16 "支持类型检查、Vitest、浏览器测试和多类现场集成检查被分别声明的论断。") 此外还有 Lark 标注、质量评估、组合质量运行、服务端 CLI 与 Prettier 格式化命令。[质量评估、CLI 与格式化脚本 ↗](../../../package.json#L23 "说明质量处理、服务端 CLI 和代码格式化所对应的维护入口。") 这种拆分体现了静态检查、自动化测试和外部集成检查的不同边界；由于材料没有退出码、行为断言或凭据状态，它只能作为命令目录，不能作为验证通过的证据。

<a id="dependency-profile"></a>
## 依赖结构与技术边界

运行依赖包括 ACP SDK、Fastify 及其静态资源插件、Lark SDK 和 Zod，表明服务端预期涉及协议接入、HTTP 服务、飞书集成和数据校验。[应用运行依赖 ↗](../../../package.json#L29 "支持 ACP、Fastify、Lark 与数据校验构成主要服务端直接依赖面的分析。") 开发依赖覆盖 Vue 单文件组件编译、Vite、TypeScript、Vitest、Playwright 和 vue-tsc，构成前端构建、类型检查、单元测试与浏览器自动化工具链。[开发与测试工具依赖 ↗](../../../package.json#L36 "支持 Vue 构建、TypeScript 检查、Vitest 测试和 Playwright 浏览器自动化工具链的说明，并限定明确版本结论仅适用于清单所列直接开发依赖。") 清单中的直接依赖与开发依赖均声明为明确版本；这不等于传递依赖全部锁定，而且文件未声明包管理器版本或展示锁文件状态，冻结解析规则仍需另行核实。
