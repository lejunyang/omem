# 项目运行入口与依赖配置

该清单定义了 omem 的 Node.js 版本约束、开发与构建脚本、测试和质量评估入口，以及服务端、模型处理、飞书接入和 Vue 工具链所需依赖。它能说明项目预期如何运行，但不能单独证明任何命令已成功执行或外部集成当前可用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="runtime-and-entrypoints"></a>
## 运行环境与入口

项目声明为私有 ESM 包，版本为 0.1.0，并要求 Node.js 24 及以上版本；这些是安装和执行时的配置约束，不代表目标环境已经满足。开发流程主要由 Bun 启动，同时分别提供服务端监听、Web 开发和仓库评审环境入口；生产启动则指向编译后的 Node.js 文件。[包信息与运行入口 ↗](../../../package.json#L2 "支持附近关于 ESM、Node.js 版本要求，以及 Bun 开发入口和 Node.js 生产入口的配置描述。")

<a id="build-and-verification"></a>
## 构建与验证脚本

构建脚本先编译服务端 TypeScript，再构建 Web 包；类型检查同时覆盖服务端与 Vue 前端，常规测试由 Vitest 执行。清单还列出浏览器冒烟、角色、学习、流水线和飞书宿主等 live 检查，以及质量标注与评估入口。[构建、测试与质量脚本 ↗](../../../package.json#L14 "支持附近关于构建、类型检查、常规测试、浏览器及 live 检查和质量评估入口的说明。") 这些名称表明项目设计了分层验证路径，但 package.json 只声明命令，无法证明测试已经运行、退出码为零或真实外部 CLI 与服务可用。

<a id="dependency-profile"></a>
## 依赖能力与技术边界

运行依赖体现出 Fastify 服务端、Agent Client Protocol、Hugging Face Transformers、飞书 SDK 和 Zod 校验等能力组合。[应用运行依赖 ↗](../../../package.json#L29 "支持附近对服务端、ACP、模型处理、飞书接入和数据校验能力构成的判断。") 开发依赖则包含 Playwright、Vue 3 编译器、Vite、TypeScript、Vitest 与 vue-tsc，支持 Vue 前端构建、静态检查、单元测试和浏览器验证。[前端与测试开发依赖 ↗](../../../package.json#L37 "支持附近关于 Vue、Vite、TypeScript、Vitest、Playwright 和 vue-tsc 工具链的说明。") 依赖版本被精确固定，但仅凭清单不能确认锁文件一致性、模型资源是否已下载，或飞书凭据与外部服务是否已配置。
