# 代码理解产物的可移植性与失效保护

该测试验证代码快照、模型生成的派生理解和可提交 JSON 产物能否在全新数据库中一致恢复，并确保伪造符号定位或源码变化不会让旧理解继续冒充当前有效结果。它覆盖固定快照证据、导出前置条件、恢复幂等性、定位校验与依赖失效，但使用 fixture 模型，不能证明真实 Agent CLI、复杂依赖图或异常文件处理均可用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

代码理解属于可再生成的派生知识，但仍需跨数据库保存模型、预算和引用来源，同时不能脱离生成时的源码快照继续生效。本测试创建临时仓库和两个独立 `Store`：第一个数据库负责捕获源码并生成理解，第二个数据库模拟从零重建。它还确认快照绑定保存完整文本、普通文件表不重复存正文，而符号证据能够回到固定片段。参考 [固定快照与符号证据 ↗](../../../apps/server/tests/code-artifacts.test.ts#L12 "支持测试使用两个数据库，并断言快照正文、文件表去重存储和符号证据可追溯。")

`Store` 在各自数据目录中初始化 SQLite、迁移表并建立运行时仓储，因此这里的双数据库确实构成相互独立的持久化环境，而不是共用内存状态。参考 [独立 SQLite 存储初始化 ↗](../../../apps/server/src/store.ts#L38 "解释两个 Store 如何分别创建数据库、迁移结构并初始化仓储组件。")

<a id="flow"></a>
## 生成、导出与恢复流程

```mermaid
flowchart LR
  A[临时源码] --> B[评审与代码同步]
  B --> C[固定代码快照]
  C --> D[fixture 生成代码理解]
  D --> E[导出 JSON 产物]
  E --> F[全新数据库同步并恢复]
  F --> G[校验模型与预算元数据]
```
流程由测试中的真实存储与同步组件串接，但生成阶段注入的是返回固定 JSON 的 fixture。恢复后断言只有一条模型产物，并保留模型名、非 seed、未独立验证及生成预算信息。参考 [fixture 生成与新库恢复断言 ↗](../../../apps/server/tests/code-artifacts.test.ts#L28 "支持从固定模型输出生成、导出，并在第二个数据库恢复模型及预算元数据的流程。")

导出实现只接受属于当前快照、成功且非 seed、未过期的模型结果；它把目标依赖哈希和被引用符号的路径、限定名、类型一起写入产物，用于后续重新定位和一致性检查。参考 [产物导出约束与定位清单 ↗](../../../apps/server/src/code/artifacts.ts#L38 "说明导出仅接受当前有效模型结果，并记录依赖哈希及引用符号定位信息。") 恢复入口则以当前快照、符号集合和文件映射为校验上下文，说明恢复并非简单反序列化。参考 [恢复所用快照上下文 ↗](../../../apps/server/src/code/artifacts.ts#L63 "支持恢复过程读取当前快照、理解输入、符号和文件映射，而非无条件导入 JSON。")

<a id="boundaries"></a>
## 防伪、失效条件与未覆盖范围

测试先重复恢复并确认没有新增重复记录；随后把导出节点的限定名改成不存在的 `ghost`，结果必须为 `rejected`。恢复原文件后，仅修改磁盘不会篡改第一个数据库已经固定的旧快照；第二个数据库重新同步新源码后，同一产物应标为 `stale`，且不再出现在有效模型理解列表中。参考 [重复恢复、防伪与过期断言 ↗](../../../apps/server/tests/code-artifacts.test.ts#L44 "支持幂等恢复、伪造限定名被拒绝、磁盘修改不改旧快照以及新快照使旧产物过期。")

覆盖范围仍然有限：模型传输明确使用 fixture，因此没有验证真实 ACP/Agent CLI、模型能力协商或失败重试；用例也只包含单文件、单符号和一次字面量修改。产物模块还声明 JSON 是带生成溯源的可移植形式、Markdown 只是可读投影且不会作为独立证据重新接入，但本测试没有断言 Markdown 输出。参考 [派生产物的证据边界 ↗](../../../apps/server/src/code/artifacts.ts#L1 "说明 JSON 与 Markdown 都是派生知识表现，不会被重新接入为独立原始证据，并据此指出测试未覆盖 Markdown 投影。")
