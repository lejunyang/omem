# 代码理解产物的可移植恢复与失效保护测试

该测试以两个全新 SQLite 数据库模拟代码理解从生成、导出到恢复的生命周期，验证固定快照保留原始源码、派生理解可跨库重建、重复恢复保持幂等，并确保伪造定位器或源码变化不会让无效产物继续充当当前知识。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_setup"></a>
## 测试目标与隔离环境

测试在临时仓库写入包含 `alpha` 函数的源码，并创建两个相互独立的 `Store`：第一个负责生成和导出理解，第二个验证产物能否在新数据库恢复。[双数据库测试环境 ↗](../../../apps/server/tests/code-artifacts.test.ts#L12 "支持测试创建临时仓库、两个独立 Store 以及待分析源码的环境设置。") `Store` 会创建 SQLite 文件、执行迁移并初始化各应用仓储，因此两个实例构成隔离的持久化环境。[Store 的 SQLite 初始化 ↗](../../../apps/server/src/store.ts#L38 "解释每个 Store 如何创建 SQLite、执行迁移并初始化应用仓储。") 无论断言成功与否，测试最终都会关闭数据库并递归清理临时目录。[数据库与临时目录清理 ↗](../../../apps/server/tests/code-artifacts.test.ts#L58 "支持 finally 块关闭两个数据库并删除临时目录的清理行为。")

<a id="fixed_snapshot_flow"></a>
## 固定证据与生成导出流程

首轮 review/code 同步后，`snapshotFileBinding` 能从固定快照证据取得源码全文，而 `code_snapshot_files` 对应行的 `content_text` 为 `null`；符号 `alpha` 的证据片段仍可回到函数文本。[快照源码与符号证据断言 ↗](../../../apps/server/tests/code-artifacts.test.ts#L21 "支持 code_snapshot_files 行的 content_text 为 null，同时快照绑定可取得源码全文、符号证据可回到函数文本；不再将该表泛称为文件主表。") 此结论替代此前不准确的“文件主表不重复保存正文”：现有材料只能直接证明快照文件表该列为空，不能把它泛化为未提供结构的“文件主表”。随后 fixture 模型生成结构化理解并导出，第二个数据库同步后能恢复模型名、非 seed 标记和生成预算。[理解生成、导出与跨库恢复 ↗](../../../apps/server/tests/code-artifacts.test.ts#L28 "支持 fixture 理解的生成与导出，以及第二个数据库中的恢复结果、模型元数据和预算断言。") 导出实现只接受当前快照中成功、非 seed、未过期的模型结果，并记录依赖摘要与稳定符号定位。[当前成功结果的导出约束 ↗](../../../apps/server/src/code/artifacts.ts#L38 "解释导出对结果状态和当前快照的限制，以及依赖清单与稳定符号定位的记录。")

<a id="rejection_staleness_and_limits"></a>
## 幂等、拒绝与过期边界

重复恢复后仍只有一条模型理解，说明恢复具备幂等效果；把节点的 `qualifiedName` 篡改为不存在的 `ghost` 后，产物会被拒绝。磁盘文件的单独修改也不会反向改变第一个数据库中已经固定的快照证据。[伪造定位拒绝与快照不变性 ↗](../../../apps/server/tests/code-artifacts.test.ts#L44 "支持重复恢复幂等、伪造 qualifiedName 被拒绝，以及磁盘编辑不会污染既有固定快照。") 当第二个数据库重新捕获变化并形成新输入后，旧产物被判为 `stale`，当前模型理解列表随之清空，避免过期知识继续生效。[源码变化后的过期处理 ↗](../../../apps/server/tests/code-artifacts.test.ts#L51 "支持重新捕获源码变化后旧产物被标记 stale，并从当前模型理解列表移除。") 现有用例尚未覆盖损坏 JSON、缺失依赖或多个产物部分失败，也不能以 fixture 证明真实外部模型 CLI 可用。

<a id="module_relationships"></a>
## 恢复入口及跨模块关系

该用例串联仓库捕获、代码图同步、理解生成以及产物导出与恢复。恢复入口要求当前快照和产物目录存在，并基于快照构造理解输入、符号映射与文件映射，以重新核对依赖和定位器。[产物恢复依赖当前快照 ↗](../../../apps/server/src/code/artifacts.ts#L63 "说明恢复入口要求当前快照和产物目录，并初始化快照、符号及文件映射。") 但提供材料未包含 `runCodeSync` 的实现，因此目前只能确认第二个数据库在依次执行 review/code 同步后出现恢复结果，不能确定自动恢复具体由哪一层触发。
