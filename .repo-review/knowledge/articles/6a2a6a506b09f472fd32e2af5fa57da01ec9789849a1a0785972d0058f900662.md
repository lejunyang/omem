# 代码快照与模型理解制品重建测试

该端到端测试验证代码证据固定在快照中，模型生成理解可导出并在新数据库恢复，同时篡改定位符或改变输入会使制品被拒绝或判为过期。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="rebuild-flow"></a>
## 从固定代码证据到可移植理解

测试在临时仓库写入源码，依次调用 review sync 与 code sync，确认快照绑定保存原始文本，而快照文件表本身不重复存放正文；符号对应的 evidence fragment 能返回函数代码。随后注入 fixture 模型生成理解、导出制品，再同步到第二个全新数据库，断言模型、非 seed 状态、未由 agent 验证状态及生成预算均被恢复。[固定证据、生成与跨库恢复流程 ↗](../../../apps/server/tests/code-artifacts.test.ts#L12 "支持源码固定、符号证据生成以及模型理解制品可在新数据库重建的说明。")

这串调用提供了跨模块源码依据：同步、理解生成、制品导出和恢复均由测试直接导入并执行，而非仅凭 AST 推断。

<a id="integrity-boundaries"></a>
## 定位校验与快照不可变边界

重复恢复同一制品不会增加记录，体现恢复幂等性。若把制品中的 qualified name 篡改为不存在的定位符，恢复结果必须为 `rejected`；若磁盘源码改变，旧数据库再次 code sync 仍读取原固定快照，而新数据库基于变更后的输入会把旧制品标成 `stale`，且不把它加入有效模型理解列表。[伪造定位与输入变化处理 ↗](../../../apps/server/tests/code-artifacts.test.ts#L44 "支持错误定位被拒绝、磁盘编辑不改旧快照、变更输入使制品过期的边界描述。")

测试覆盖了定位伪造和源码变化，但未覆盖制品截断、并发导出、写入中断、版本升级或恶意超大 JSON；fixture transport 也不证明真实模型 CLI 可用。
