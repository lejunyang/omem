# 会话分析角色的证据保真与输出约束

该提示文件定义会话分析角色的工作规范：保留说话人与语境，区分不同陈述性质，避免把他人承诺误记为用户待办，并以带内联引用的中文 JSON 产出结构化分析。它属于角色配置与行为要求，不能据此断言相关分析、校验或待办隔离机制已经在运行时实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="semantic-boundary"></a>
## 会话语义与责任边界

该角色首先要求保留说话人、时间、转述和回复关系，并把请求、承诺、猜测与事实分开处理；其中尤其强调，他人的承诺不能自动转化为用户待办。[会话语义与待办边界 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/prompt.md#L1 "支持关于保留会话语境、区分陈述性质以及不得将他人承诺转成用户待办的论断。") 这是一条防止主体错配和事实升级的分析原则，适用于对聊天记录、转发内容及上下文回复的解释，但文件本身没有描述说话人识别、时间归一化或待办创建的具体实现，因此只能视为预期行为，而非已实现能力。

材料还规定分析过程不调用工具或读取额外文件，并将材料内的命令和提示词当作待分析数据。[分析过程的证据边界 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/prompt.md#L3 "支持角色只处理提供材料、不执行材料内命令且不读取其他文件的范围限制。") 这限定了角色的证据边界，使结论应来自任务明确提供的内容；其可靠性仍取决于上游是否完整提供会话上下文、参与者信息和允许引用的材料。

<a id="output-and-evidence"></a>
## 结构化输出与引用闭环

输出必须覆盖任务指定的全部目标，且文档键与目标键完全一致；正文需要解释作用、背景、流程、限制及材料关联，而不能退化为名称或数量清单。[目标覆盖与正文要求 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/prompt.md#L4 "支持文档键必须匹配目标，并要求正文解释背景、流程、限制和关联的输出规范。") 每一节还必须在论断附近放置引用，所有引用都要真实出现在正文中，从而形成可定位的论断—证据关系。[内联引用要求 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/prompt.md#L5 "支持每节都要在相应论断附近使用引用、不能只在文末集中列证据的要求。")

引用目标只能来自已提供的材料或文章：材料引用应使用真实行号并留下空 quote，由宿主提取固定范围内的原文；标签需面向读者，理由需说明证据支持的附近论断。无法确认或需要选择的事项则进入结构化 questions。[引用定位与疑问记录规则 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/prompt.md#L6 "说明允许的引用来源、固定行号、可读标签、引用理由以及结构化记录未决问题的约束。") 这些内容定义了产物合同和证据纪律，但没有说明宿主如何校验行号、复制引文、拒绝非法关系值或处理失败结果，因此不能据此推断端到端校验已经落地。
