# Agent 运行时的协议、安全与生命周期测试

该测试文件以临时工作目录和可控 ACP fixture 验证 Agent 运行时的关键合同：模型与推理强度协商、思考内容过滤、权限拒绝、超时和取消，以及 CLI 参数的无 shell 安全构造。它覆盖的是受控替身行为，并不证明真实外部 Agent CLI、不同平台进程终止或完整输出边界均可用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="harness"></a>
## 测试夹具与资源生命周期

测试构造一个通过 `profileSchema` 校验的 ACP 配置，以当前 Node 进程启动固定 fixture；`run` 为每次调用创建独立临时目录，收集 `text/status/permission` 事件，并把文本输入交给 `acp`。无论成功或失败，`finally` 都递归清理目录；注释明确 `acp()` 返回前已经等待子进程 close，因而单次删除失败应被视为真实清理错误，而不是用重试掩盖。[ACP 测试夹具与清理流程 ↗](../../../apps/server/tests/agents.test.ts#L7 "支持临时目录、事件收集、ACP 调用以及等待子进程退出后执行单次清理的说明。")

这组测试直接依赖服务端 Agent 适配器导出的 `acp`、`cliArgs`，同时依赖共享的 profile 校验合同。当前提供的 contracts 范围只显示导入位置，未包含 `profileSchema` 定义，因此不能据此确认其全部字段限制。[测试模块依赖入口 ↗](../../../apps/server/tests/agents.test.ts#L1 "说明测试直接导入 Agent 适配器和共享 profile 校验合同，同时界定当前 contracts 材料未展示 schema 定义。")

<a id="protocol"></a>
## 协商、输出过滤与交互边界

协议用例要求先切换到 `beta` 模型，再校验并采用 `high` effort，最终文本包含该组合；事件序列不得泄露 fixture 的私有思考标记。若当前模型不支持 `high`，调用必须明确抛出 `Unsupported reasoning_effort`，不能静默降级。[模型与推理强度协商断言 ↗](../../../apps/server/tests/agents.test.ts#L41 "支持先协商模型、采用受支持 effort、过滤私有思考以及拒绝不支持 effort 的行为。")

权限请求会被暴露为 `permission` 事件，并得到 `Permission declined`，确认默认路径不会替 Agent 授权。实现文件也声明丢弃 thought chunk、权限回调不得静默授权；但本文件没有覆盖自定义运行时请求回调、elicitation、MCP 或 skill discovery。[权限请求默认拒绝 ↗](../../../apps/server/tests/agents.test.ts#L56 "支持权限事件可见且默认返回拒绝，并与实现声明的非静默授权边界相对应。")

<a id="termination"></a>
## 超时、取消与平台化终止策略

当 fixture 保持空闲时，较短的 `timeoutMs` 必须产生包含 `timed out` 的拒绝；活动请求被 `AbortController` 中止时，错误则需包含 `CANCELLED`。[超时与主动取消断言 ↗](../../../apps/server/tests/agents.test.ts#L61 "支持空闲超时和 AbortSignal 主动取消分别产生可识别错误的结论。") 这分别验证运行预算耗尽和调用方主动取消的可观察结果。

终止实现先尝试 `SIGTERM`，1.5 秒后再升级为 `SIGKILL`：非 Windows 平台针对负 PID 向进程组发信号，Windows 则对单个子进程调用 `kill`。[跨平台子进程终止策略 ↗](../../../apps/server/src/agents.ts#L40 "解释非 Windows 进程组与 Windows 单进程的 SIGTERM、SIGKILL 分支，支持修正后的平台化终止描述。") 与之对应，启动时也只有非 Windows 平台设置 `detached: true`；Windows 不创建独立进程组。[无 shell 与平台化进程启动 ↗](../../../apps/server/src/agents.ts#L56 "支持 argv 不经 shell 插值，并明确只有非 Windows 平台使用 detached 独立进程组，Windows 不使用。") 这替代了此前“所有子进程均以独立进程组启动”的过度概括。现有测试只观察 Promise 拒绝和目录清理，尚未直接证明信号升级、后代进程回收或 Windows 分支的实际效果。

<a id="cli-safety"></a>
## CLI 参数安全合同与未覆盖范围

CLI 用例把带有 `$(pwd)` 的模型名作为字面值传入，要求生成参数保留该字符串、包含 `read-only`，并且不出现绕过审批与沙箱的危险开关。[安全 CLI 参数断言 ↗](../../../apps/server/tests/agents.test.ts#L72 "支持只读沙箱、危险开关缺失以及特殊模型字符串保持为字面参数的结论。") 实现通过 `spawn` 的参数数组启动进程并设置 `shell: false`，因此该字符串不会被 shell 展开。[无 shell 与平台化进程启动 ↗](../../../apps/server/src/agents.ts#L56 "支持 argv 不经 shell 插值，并明确只有非 Windows 平台使用 detached 独立进程组，Windows 不使用。")

不过，这里没有实际启动 Codex CLI，也未断言完整 argv 顺序、命令退出码、stderr、环境过滤、输出上限或真实供应商的能力发现。因此它属于协议 fixture 与参数构造测试，不能替代外部 CLI 的 live check。
