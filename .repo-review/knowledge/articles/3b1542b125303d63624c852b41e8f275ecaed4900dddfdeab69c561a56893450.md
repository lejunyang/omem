# 可追溯知识的规划、刷新与独立复核

知识规划、文章刷新与独立复核被定义为三个互补角色：分别组织知识树、依据固定证据更新文章，以及在隔离配置下给出结构化审查结果。现有材料说明了职责、输出合同和证据边界，但尚不能证明三者已由实际任务编排串联。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为什么拆分知识维护职责

材料目录可能同时包含现行需求、历史方案、实现事实和未决问题，因此需要先按读者关心的主题组织知识，而不是照搬文件树；材料变化后，又要只刷新受影响的正文、引用与疑问，保留仍然有效的内容。参考 [知识树规划职责 ↗](e712310c8c72f48d0b4eb9d7a49322207d6aee7c31105b83e606981860b45261.md#catalog_to_tree "说明规划器如何从材料目录识别概念、建立知识树并避免机械复制文件结构。") [关联知识刷新职责 ↗](607d9c65ef8646445715c297690467f2de1d1b1b86f0d40571605461a7891705.md#purpose "说明刷新器只更新受影响内容、保留有效知识并输出可独立阅读的最新文章。")

独立复核则由单独的角色配置承担，使用不同的技能和输出合同。三者体现的是**规划、刷新、审查的职责分工**；当前证据没有展示任务调度或状态迁移，不能据此断言系统已经把它们自动串成完整流水线。参考 [独立复核角色配置 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/manifest.json#L3 "支持独立复核角色的身份、技能绑定及 KnowledgeReview.v1 输出声明。")

<a id="contracts"></a>
## 三类结构化产物

规划角色声明输出 `KnowledgePlan.v1`，用于描述知识章节及其材料依据；刷新角色声明输出 `KnowledgeBatch.v1`，用于承载最新文章、正文引用和待确认问题；复核角色声明输出 `KnowledgeReview.v1`。参考 [规划结果合同 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/manifest.json#L17 "直接支持知识规划角色声明输出 KnowledgePlan.v1。") [刷新结果合同 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/manifest.json#L17 "直接支持知识刷新角色声明输出 KnowledgeBatch.v1。") [独立复核角色配置 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/manifest.json#L3 "支持独立复核角色的身份、技能绑定及 KnowledgeReview.v1 输出声明。")

规划合同约束章节键、标题、用途和 `materialKeys` 的形状与数量，但“固定包含哪些语义章节”以及“材料键必须属于目录”主要来自角色规范，不能仅靠 Schema 保证。参考 [规划章节结构 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/output.schema.json#L19 "说明 KnowledgePlan.v1 对章节字段和材料键列表的结构约束，并据此界定 Schema 的能力范围。")

<a id="expected_workflow"></a>
## 角色规范建议的处理顺序

按现有职责，可将三类角色理解为一条建议链路：规划器先从目录识别核心概念，安排五个基础章节并区分需求、历史、实现、验证与未决事项；刷新器再依据新旧固定材料和用户回答更新目标文章，把引用放在对应论断附近，并将证据不足之处保留为结构化疑问。参考 [规划材料选择规范 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/skills/omem-knowledge-planner/SKILL.md#L8 "支持规划器的基础章节、目录内材料选择、知识状态区分及非执行边界。") [刷新正文与引用要求 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/prompt.md#L3 "支持目标覆盖、就近引用、固定材料定位及结构化记录疑问等刷新规范。")

刷新结果中的引用可指向材料或既有文章，关系类型受枚举约束，固定材料原文预期由宿主根据行号提取。参考 [文章引用合同 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/output.schema.json#L99 "支持刷新结果中的引用关系、目标类型、材料定位以及由宿主提取原文的设计。") 复核角色被配置为独立新会话、禁用工具且不继承用户技能或 MCP，这为隔离审查提供了配置基础，但本批材料没有给出具体审查标准。参考 [复核会话隔离 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/manifest.json#L18 "支持复核角色禁用工具、不复用会话且不继承用户技能和 MCP 的配置边界。")

<a id="progress_limits"></a>
## 当前能够确认的边界

现有材料能够确认三类角色的清单、技能绑定、输出合同名称，以及规划和刷新的写作与引用规范；它们足以描述预期分工，却不足以证明材料变更触发、阶段串联、文章保存、引用语义核验或失败后保护旧知识已经实际运行。参考 [规划结果合同 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/manifest.json#L17 "直接支持知识规划角色声明输出 KnowledgePlan.v1。") [刷新结果合同 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/manifest.json#L17 "直接支持知识刷新角色声明输出 KnowledgeBatch.v1。") [独立复核角色配置 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/manifest.json#L3 "支持独立复核角色的身份、技能绑定及 KnowledgeReview.v1 输出声明。")

同样，结构化合同可以拒绝字段形状错误，却不能自行判断引用是否真正支持论断，也不能证明目录成员关系等语义规则已被宿主执行。复核会话虽有隔离与预算配置，失败状态和结果应用方式仍需运行时实现及真实轨迹佐证。参考 [规划章节结构 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/output.schema.json#L19 "说明 KnowledgePlan.v1 对章节字段和材料键列表的结构约束，并据此界定 Schema 的能力范围。") [文章引用合同 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/output.schema.json#L99 "支持刷新结果中的引用关系、目标类型、材料定位以及由宿主提取原文的设计。") [复核会话隔离 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/manifest.json#L18 "支持复核角色禁用工具、不复用会话且不继承用户技能和 MCP 的配置边界。")
