# agent-runtime · 知识组织、刷新与复核角色

该专题描述面向固定材料的知识角色配置：规划器设计可追溯知识树，刷新器增量维护正文、引用与疑问，复核器清单另行声明独立角色和 KnowledgeReview.v1 输出类型。现有证据主要是规范、结构合同与静态清单，尚不能证明角色调度顺序、复核语义或端到端运行效果。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="responsibilities"></a>
## 角色职责与设计边界

规划器负责从材料目录识别核心概念，组织概览、架构、背景、需求和进展等固定章节，并区分需求、历史方案、实现事实、验证记录与未决问题；其产物是知识结构，而非代码操作。[可追溯知识树规划规范 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/skills/omem-knowledge-planner/SKILL.md#L8 "支持规划器从目录提炼主题、安排固定章节、区分知识状态并保持非操作性边界的论述。") 刷新器则被规范为根据新旧固定材料和用户回答更新受影响正文、引用及疑问，同时保留未受影响知识。[关联知识刷新规范 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/skills/omem-knowledge-refresher/SKILL.md#L8 "支持刷新器的增量维护目标、固定材料边界、就近引用和疑问记录要求。") 复核器的清单仅能证明存在单独角色及 `KnowledgeReview.v1` 输出声明，不能据此断定其复核语义或调用时序。[知识复核角色清单 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/manifest.json#L2 "仅支持存在单独的知识复核角色、KnowledgeReview.v1 输出类型及相应运行配置，不用于证明复核语义或调度顺序。") 反馈整理入口另被描述为把有作用域的所有者纠正转成可复用约束，但这仍只是界面配置。[反馈整理入口说明 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/skills/omem-feedback-curation/agents/openai.yaml#L1 "支持反馈整理入口被描述为把有作用域的所有者纠正转化为可复用约束，同时限定该证据只是界面元数据。")

<a id="data_flow"></a>
## 结构化知识与引用定位

规划结果采用 `KnowledgePlan.v1`，章节包含键、标题、用途和材料键列表，用于把主题结构连接到目录内依据。[知识规划章节合同 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/output.schema.json#L14 "支持 KnowledgePlan 章节包含键、标题、用途和材料键列表的结构说明。") 刷新结果采用 `KnowledgeBatch.v1`，正文由 Markdown 章节、引用和疑问组成；引用目标可以定位到材料行或文章章节，并携带标签、理由及关系。[知识批次的引用目标合同 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/output.schema.json#L78 "支持 KnowledgeBatch 的章节、引用关系和材料或文章两类引用目标，同时说明合同中没有专门的替代关系。") 刷新规范要求引用贴近对应论断，无法确认的事项进入带原因、下一步和阻塞状态的问题结构。[关联知识刷新规范 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/skills/omem-knowledge-refresher/SKILL.md#L8 "支持刷新器的增量维护目标、固定材料边界、就近引用和疑问记录要求。") 当前材料只说明文章与材料都可作为引用目标，并未规定两者的事实权威关系或是否必须继续回溯原始材料。

<a id="status_limits"></a>
## 运行配置与尚未证实的能力

规划器与刷新器清单均声明内联技能、结构化输出、禁用工具、不复用会话、不继承用户技能或 MCP，以及相同的令牌和修复预算。[知识规划角色运行清单 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/manifest.json#L9 "支持规划器内联技能、输出合同、工具与会话隔离以及预算均已在静态清单中声明。")[知识刷新角色运行清单 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/manifest.json#L9 "支持刷新器内联技能、KnowledgeBatch 输出、无工具隔离、独立会话与预算上限的配置声明。") 复核器清单也采用类似配置。[知识复核角色清单 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/manifest.json#L2 "仅支持存在单独的知识复核角色、KnowledgeReview.v1 输出类型及相应运行配置，不用于证明复核语义或调度顺序。") 这些是预期装配边界，不证明宿主实际执行了摘要校验、能力协商、工具禁令或修复循环。现有 schema 能约束字段形状，却不能独立验证引用是否支持论断、材料键是否属于输入目录，亦未展示角色编排和真实运行记录。刷新规范要求标明被替代结论，但批次合同没有专门的替代关系字段，其表示方式仍待明确。[关联知识刷新规范 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/skills/omem-knowledge-refresher/SKILL.md#L8 "支持刷新器的增量维护目标、固定材料边界、就近引用和疑问记录要求。")[知识批次的引用目标合同 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/output.schema.json#L78 "支持 KnowledgeBatch 的章节、引用关系和材料或文章两类引用目标，同时说明合同中没有专门的替代关系。")
