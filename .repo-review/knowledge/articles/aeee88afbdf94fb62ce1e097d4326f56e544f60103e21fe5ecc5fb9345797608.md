# 问答运行编排与证据约束

Runs 负责把固定证据、模型配置和问题组装为可取消的 Agent 运行，限制并发、上下文、图片及输出规模，维护事件流，并将有效回答作为派生材料保存且关联回原证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-input"></a>
## 职责与输入校验

`Runs` 是服务端问答任务的内存编排器：每次运行保存状态、事件、取消控制器和最终回答标识，并支持查询、取消以及关闭时等待任务收束。它最多允许两个运行并发；记录达到 100 条后仅清理一个已结束项，因此属于轻量运行缓存，而不是可恢复的持久任务队列。[运行状态、并发限制与缓存清理 ↗](../../../apps/server/src/runs.ts#L11 "支持 Runs 的内存状态、查询取消、关闭等待、双并发限制和已结束记录清理行为。")

启动时先按请求选择配置档案，并允许覆盖模型与推理强度；随后对焦点证据和上下文证据去重并从 Store 读取。证据不存在、选区不属于首个固定证据，或文本与选区总长度超过档案预算时，运行会在创建前失败。[档案、证据、选区与文本预算校验 ↗](../../../apps/server/src/runs.ts#L52 "支持启动前解析档案、覆盖模型参数、读取并去重证据、核对固定选区和限制上下文字符数。") 档案来自服务端配置中至少包含一项的 `profiles`，但给定范围没有展示模型与 effort 的能力协商。[服务端档案配置入口 ↗](../../../apps/server/src/config.ts#L1 "说明 Runs 使用的 profiles 来自服务端配置且至少需要一项；当前范围未展示 profileSchema 的详细约束。")

<a id="context-and-transport"></a>
## 上下文构造与传输选择

运行将每条证据序列化为包含证据标识、标题、版本、当前状态和正文的材料行，再与档案指令、选区及问题组合成提示。提示要求只能引用列出的证据标识，但这一约束本身不等于论断支持度已经核验。[固定证据提示构造 ↗](../../../apps/server/src/runs.ts#L70 "支持证据元数据和正文被序列化进提示，并要求回答只使用列出的证据标识。")

图片从固定修订的 parts 中收集，按资产标识去重并读取字节；全部图片累计不得超过 10 MB，缺失资产直接报错。非 ACP 档案遇到图片时也会拒绝执行，不会静默退化为纯文本。[图片收集与 ACP 限制 ↗](../../../apps/server/src/runs.ts#L88 "支持图片按资产去重、累计字节预算、缺失报错，以及非 ACP 传输不得静默忽略图片。") `Runs` 在自身执行分支中明确调用导入的 `acp` 或 `cli`，并把工作目录、内容、事件回调和同一取消信号交给传输层；这条依据替代了旧稿中由 `agents.ts` 进程基础设施推断调用关系的结论。[事件累计、权限记录与传输分派 ↗](../../../apps/server/src/runs.ts#L110 "直接支持事件预算、权限关注记录，以及 Runs 按 transport 调用 ACP 或 CLI 并传递取消信号的论断。") `agents.ts` 的当前可见范围只能进一步说明子进程会过滤敏感环境变量、以非 shell 方式启动，并在停止时先 TERM 后 KILL。[Agent 子进程启动基础 ↗](../../../apps/server/src/agents.ts#L32 "仅支持 agents 模块对子进程环境、启动方式与终止流程的处理，不用于证明 Runs 对 ACP 或 CLI 的调用关系。")

<a id="execution-and-persistence"></a>
## 事件、取消与回答保存

运行创建后立即返回标识，实际工作保存在异步 promise 中。统一的 `emit` 为事件分配递增序号、累积文本回答，并将事件字符总量限制为 250,000；权限事件还会通过 Store 记录为需要关注的事项。取消后新的 emit 被忽略，传输层同时收到对应的 `AbortSignal`。[事件累计、权限记录与传输分派 ↗](../../../apps/server/src/runs.ts#L110 "直接支持事件预算、权限关注记录，以及 Runs 按 transport 调用 ACP 或 CLI 并传递取消信号的论断。")

传输结束后仍会检查取消状态和空回答。有效回答通过 `Store.capture` 保存为来源为 agent、生产者为 derived 的材料，并将新片段逐一关联至本次输入证据；随后状态变为完成，同时明确提示“引用不等于支持度已验证”。异常则统一转为 cancelled 或 error 终态。[回答捕获、证据关联与终态处理 ↗](../../../apps/server/src/runs.ts#L157 "支持非空回答作为派生材料保存、关联输入证据，并区分完成、取消和错误终态。") 这套流程建立在当前单用户 SQLite 与不可变修订基础上，但给定 Store 范围没有展示 capture、link、record 的具体事务边界。[Store 的单用户持久化基础 ↗](../../../apps/server/src/store.ts#L1 "说明 Runs 依赖的 Store 使用 SQLite 和不可变修订作为当前单用户存储基础；具体写入方法不在给定范围。")

<a id="boundaries"></a>
## 边界条件与未覆盖行为

运行表仅存在于进程内，重启后不能恢复；`get` 直接返回累计事件，也没有展示分页或订阅机制。关闭流程会取消仍在运行的任务并等待全部 promise 收束。清理策略每次只删除一个非运行项，而正常入口的双并发限制约束了活跃任务数量。[内存运行查询与关闭行为 ↗](../../../apps/server/src/runs.ts#L19 "支持运行状态由类内 Map 保存，以及查询、取消、关闭等待和缓存清理的边界判断。")

材料中没有相关测试，因此尚不能确认并发拒绝、取消竞态、输出超限、图片累计、空回答和持久化失败是否已有自动化行为断言。回答虽然关联原证据，仍被明确标记为派生内容；合同层也区分 `original` 与 `derived`，避免把模型回答当成新的独立原始事实。[原始与派生内容合同 ↗](../../../packages/contracts/src/index.ts#L5 "支持合同层显式区分 original 和 derived，说明 Agent 回答不应被视为独立原始证据。")
