# osdk 使用指引与参考索引

概述 one-sdk 的适用范围、文档路由、复现与信任原则，并把具体命令和配置字段分别引导到两份参考材料；它是速查索引，不替代当前版本命令帮助。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-authority"></a>
## 定位与权威边界

osdk 是跨 Windows、macOS、Linux 的统一 SDK 管理器，用来管理语言运行时、包管理器、开发工具、Android SDK 和模型快照，并通过项目锁定结果支持团队与 CI 复现。[osdk 定位与文档权威性 ↗](../../../.agents/skills/osdk-guide/SKILL.md#L12 "支持跨平台工具链管理、锁定复现以及当前版本帮助优先的说明。") 此材料定位为命令与配置的速查索引；具体版本的命令面仍以 `osdk --help` 为权威，因此文档陈述不能替代对当前二进制的实际检查。

<a id="reference-routing"></a>
## 按意图选择参考材料

查询子命令、参数和功能分类时应进入 `reference/commands.md`；编写 `osdk.toml` 或全局 `config.toml` 时应进入 `reference/configuration.md`。两份参考分别声称对齐 CLI 的命令枚举和核心配置结构，并要求能力变化后同步更新相关文档。[命令与配置参考路由 ↗](../../../.agents/skills/osdk-guide/SKILL.md#L22 "支持按意图选择 reference，并说明参考材料声称对齐的实现来源及同步要求。") 这是维护目标，不构成当前实现已逐项核验的独立证据。

<a id="core-rules"></a>
## 任务、依赖、信任与配置分层

项目任务必须通过 `osdk run <name>` 执行；`install` 面向工具，`deps` 面向项目应用依赖，单个动态工具使用带命名空间的标识。[任务与依赖职责区分 ↗](../../../.agents/skills/osdk-guide/SKILL.md#L39 "支持 osdk run、install、deps 及动态工具命名空间的关键规则。") 会执行代码或改变校验、下载来源的配置需要先建立信任；配置优先级由 CLI、环境变量、项目配置、用户配置到内置默认逐级降低。受管数据或配置目录不应手写，应通过 `osdk source`、`osdk config` 等入口修改。[信任门槛与配置优先级 ↗](../../../.agents/skills/osdk-guide/SKILL.md#L48 "支持高风险配置的信任要求、配置覆盖次序和禁止手写受管目录的边界。")
