# 开发仓库知识接入与检索隔离

该适配层把仓库中的现行材料、已审核文章及其历史依赖接入个人知识库，同时为开发材料施加检索可见性规则。它保留旧引用所需的精确版本，并避免历史导入把现行文件头指针回退。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决开发知识与个人存储并存的问题

这个文件提供两层适配：`importDevelopmentKnowledge` 把仓库知识加入现有 `Store`，`developmentRetrieval` 则限制哪些仓库材料能进入搜索结果。它依赖统一检索端口，以及知识仓储、仓库材料恢复和历史修订转换，因此处在“文件快照进入个人库”与“助手读取证据”之间。文件头明确要求保留被引用的历史证据，同时不能替换个人数据库。参考 [开发知识适配职责 ↗](../../../apps/server/src/review/development.ts#L1 "支持该文件把仓库材料接入个人存储，并列出它与存储、知识仓储、恢复及检索端口的直接依赖。")

<a id="retrieval_policy"></a>
## 只在材料搜索上过滤失效仓库副本

`developmentRetrieval(store, retrieval)` 每次搜索前查询当前头修订下、键以 `omem:` 开头的文件片段，并读取 `removed` 与 `legacy_alias_of` 标记。它把这些记录按片段 ID 建成映射，再组合调用方原有的 `visible` 条件：已移除或已成为旧别名的仓库片段不可见，其余片段仍须通过调用方条件。参考 [仓库片段可见性策略 ↗](../../../apps/server/src/review/development.ts#L15 "支持按当前文件头、移除标记和旧别名标记过滤片段，并与调用方已有 visible 条件组合。")

包装器把同一策略用于可选的 `search`、必有的 `searchSources` 和可选的异步源搜索；记忆搜索、证据读取及健康检查直接转发。因此这里改变的是开发文件的候选资格，内容排序仍由底层检索实现负责。参考 [检索端口包装范围 ↗](../../../apps/server/src/review/development.ts#L27 "支持文件搜索接口应用策略，而记忆搜索、证据读取和健康检查保持直接转发。")

<a id="import_flow"></a>
## 按依赖补齐历史，再让现行文件成为头版本

一条代表性调用是 `importDevelopmentKnowledge(personalStore, repoRoot)`。函数先创建面向仓库材料的知识仓储，读取 `.repo-review/knowledge/articles` 中的 JSON 产物，并按文档摘要登记历史文章；只有目标存储目录不同于仓库评审目录且旧数据库存在时，才打开旧库。参考 [导入入口与旧库存取条件 ↗](../../../apps/server/src/review/development.ts#L37 "支持代表性调用的输入、文章目录读取方式，以及只在独立旧库存在时打开它的边界条件。")

```mermaid
flowchart LR
  A[读取已审核文章] --> B[递归补齐文章依赖]
  B --> C[按摘要寻找缺失材料修订]
  C --> D[捕获到个人 Store]
  D --> E[恢复现行仓库文件]
  E --> F[恢复文章并刷新状态]
```

遍历文章依赖时，新发现的旧版子文章会加入待处理集合；缺失的 `omem:` 材料依赖则按键查询旧库修订，只复制摘要完全匹配的版本。图片部件会从旧资产读取并转成 Base64，捕获过程关闭学习与通知，旧库最终在 `finally` 中关闭。参考 [历史依赖和材料补齐 ↗](../../../apps/server/src/review/development.ts#L46 "支持递归收集文章依赖、按摘要匹配材料修订、转换图片并无通知捕获，以及可靠关闭旧库。")

现行文件在历史材料之后恢复，避免历史导入把实时头版本回退。随后函数分两轮恢复文章。第一轮遍历 `historical`；这个集合既含目录中的当前产物，也含从旧库补入的历史子文章。`restoreHistorical(artifact, false)` 允许旧源不可用的历史文章继续被读取；无法解析的引用由 API 禁用，`refresh` 后文章会标记为陈旧。只有第一轮调用实际抛出的异常才会加入 `historyFailures`，并在末尾统一告警。第二轮只重试目录中的当前产物，调用 `restoreHistorical(artifact)`；这轮异常由空 `catch` 忽略，以免不可用版本进入可读目录。最后，函数刷新仓储，返回恢复结果、仓储实例和 `historyFailures`。目录不存在会得到空文章集合，而 JSON 解析本身没有局部容错，格式错误会中断调用。参考 [现行恢复与两阶段失败处理 ↗](../../../apps/server/src/review/development.ts#L70 "支持现行文件最后恢复、历史集合与当前产物的两轮文章恢复、缺失旧源时的读取语义、刷新、告警和返回值。")
