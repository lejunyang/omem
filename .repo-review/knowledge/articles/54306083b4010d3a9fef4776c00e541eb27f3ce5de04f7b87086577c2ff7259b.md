# 开发仓库知识接入与检索隔离

该适配层把仓库现行材料、已审核文章及其历史文章依赖接入同一存储，并过滤已移除或已成为旧别名的仓库片段。当前实现沿文章修订补齐历史文章，但不再重建已退役的原始材料版本。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 让仓库知识遵循现行原件策略

`developmentRetrieval` 和 `importDevelopmentKnowledge` 分别处理搜索资格与知识导入。前者在统一检索端口前增加仓库片段的可见性条件；后者先从目录收集已审核文章并从旧库补齐可找到的历史文章修订，再恢复仓库现行材料，最后把历史集合与目录中的当前文章分两轮写入知识仓储。参考 [仓库片段可见性条件 ↗](../../../apps/server/src/review/development.ts#L15 "支持查询当前仓库文件片段，并把移除、旧别名和调用方原有可见性条件组合起来。") [文章目录与旧库开启条件 ↗](../../../apps/server/src/review/development.ts#L65 "支持文章产物的读取、退役清单排除、摘要登记，以及只读打开旧库的边界条件。") [历史文章依赖与退役原件边界 ↗](../../../apps/server/src/review/development.ts#L85 "支持按摘要补齐历史文章修订、释放旧库读取资源，并明确已退役原始版本不会被已发布文章重建。") [恢复顺序与失败处理 ↗](../../../apps/server/src/review/development.ts#L101 "支持现行材料恢复、两轮文章恢复、刷新、告警和最终返回值。") 文件头把原则写得很明确：仓库输入与用户文档采用同一套最新原件策略。参考 [适配器职责与现行原件原则 ↗](../../../apps/server/src/review/development.ts#L1 "支持仓库输入采用最新原件策略，并给出本文件连接的存储、知识恢复和检索组件。")

<a id="retrieval_policy"></a>
## 只在材料搜索中排除失效仓库片段

`developmentRetrieval(store, retrieval)` 在每次材料搜索前查询当前头修订下、键以 `omem:` 开头的文件片段，并读取 `removed` 与 `legacy_alias_of` 标记。它按片段 ID 建立映射，再与调用方已有的 `visible` 条件组合：已移除或已成为旧别名的仓库片段不可见，其余片段仍须通过原有条件。参考 [仓库片段可见性条件 ↗](../../../apps/server/src/review/development.ts#L15 "支持查询当前仓库文件片段，并把移除、旧别名和调用方原有可见性条件组合起来。")

同一策略应用于可选的 `search`、必有的 `searchSources` 和可选的 `searchSourcesAsync`。`searchMemories`、`readEvidence` 与 `health` 直接转发给底层端口，所以这里改变的是仓库文件能否成为材料候选，内容排序仍由底层检索负责。参考 [检索端口包装范围 ↗](../../../apps/server/src/review/development.ts#L47 "支持材料搜索应用可见性策略，而记忆搜索、证据读取和健康检查直接转发。")

<a id="import_flow"></a>
## 补齐历史文章，再恢复现行仓库材料

`importDevelopmentKnowledge(store, root)` 先创建知识仓储，读取 `.repo-review/knowledge/articles` 下除 `.retirements.json` 外的 JSON 产物，并用稳定摘要登记文章。目标存储目录与仓库评审目录不同且旧数据库存在时，函数才会取得读取锁并以只读方式打开旧库。参考 [文章目录与旧库开启条件 ↗](../../../apps/server/src/review/development.ts#L65 "支持文章产物的读取、退役清单排除、摘要登记，以及只读打开旧库的边界条件。")

旧库补齐的对象限于文章修订。函数遍历现有文章的依赖，遇到尚未登记的文章摘要，便从 `knowledge_revisions` 读取对应产物并加入集合；读取结束后关闭数据库并释放锁。以父文章引用旧版子文章为例，即使子文章已有较新的当前版本，父文章依赖的旧修订仍可按摘要找回。已退役原始版本保持不可用，导入已发布文章不会重建这些版本。参考 [历史文章依赖与退役原件边界 ↗](../../../apps/server/src/review/development.ts#L85 "支持按摘要补齐历史文章修订、释放旧库读取资源，并明确已退役原始版本不会被已发布文章重建。")

文章集合准备完成后，函数调用 `restoreReviewKnowledge` 恢复仓库材料，并关闭学习与通知。随后分两轮恢复文章：第一轮处理包含旧修订在内的 `historical` 集合，允许旧源不可用；失败会记录标题与原因。第二轮重试目录中的当前产物，不可用版本会被留在可读目录之外。最后刷新仓储；历史恢复失败时输出汇总告警，并返回恢复结果、仓储实例和失败列表。目录不存在时文章集合为空；目录中的 JSON 解析没有局部容错，格式错误会直接中断这次调用。参考 [恢复顺序与失败处理 ↗](../../../apps/server/src/review/development.ts#L101 "支持现行材料恢复、两轮文章恢复、刷新、告警和最终返回值。")
