# 取消标注会话后的飞书卡片投递回归测试

该测试以临时 SQLite 和伪消息适配器验证双层取消保障：取消完成后，原有待发送意图不会被 worker 投递；取消后重新出现的待发送意图也会在发送侧被拦截。已投递历史与发送中的记录保持原状态。此前把全部装置归于数据集引用、以及把随机 32 字节 Buffer 描述成密钥约束测试的结论已被更精确的分段证据替代。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_setup"></a>
## 问题背景与测试装置

这组回归测试针对“质量标注会话已经取消，关联飞书卡片仍可能发出”的问题。它使用临时 SQLite 数据库和伪消息适配器观察持久化状态与发送决策，不产生真实飞书或网络调用。[测试目标与隔离范围 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L1 "支持该回归测试的目标，并说明它使用临时数据库和伪消息适配器、不调用真实飞书网络。")

装置首先创建临时存储与凭据文件，写入有效的飞书连接、连接版本、绑定及通知目标。[飞书连接与通知目标装置 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L70 "支持测试装置创建凭据、连接、连接版本、绑定和通知目标，修正此前由数据集代码承载全部装置说明的引用范围。") 随后另行创建含一个样本的质量数据集和标注服务。[质量数据集与标注服务装置 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L116 "支持装置创建含一个样本的数据集并初始化标注服务，与飞书连接预置证据分开。") 这两段引用替代了此前由数据集代码一并支持全部飞书预置装置的宽泛结论。

测试实际通过 `randomBytes(32)` 向凭据存储传入随机 32 字节 Buffer。[随机 32 字节 Buffer 调用 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L70 "直接证明本测试向凭据存储传入 randomBytes(32)，支持有效 Buffer 初始化路径的准确表述。") 凭据存储实现要求最终密钥长度恰为 32 字节，并另有字符串解析及环境变量构造路径。[凭据密钥构造约束 ↗](../../../apps/server/src/integrations/lark/secret-store.ts#L24 "说明凭据存储要求 32 字节密钥，并展示字符串解析和环境变量构造分支，从而界定测试未覆盖的路径。") 因而本测试只走通有效 Buffer 初始化，不验证非法长度、字符串编码或缺失环境变量等错误分支；此前“该测试覆盖 Buffer 长度约束”的结论已被替代。

<a id="fixtures_and_digest"></a>
## 样本与投递意图构造

数据集来源摘要使用稳定摘要函数生成；该函数递归规范化数组和对象，过滤值为 `undefined` 的对象项、按键排序，再对规范化 JSON 计算 SHA-256。[稳定摘要实现 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持稳定摘要的递归规范化、过滤未定义字段、对象键排序和 SHA-256 计算行为。") 这些性质来自摘要实现，而非仅由测试调用推断。

为模拟服务本身没有创建的排队或发送中卡片，辅助函数直接写入变更和投递意图，并为载荷摘要、提供方标识设置稳定摘要结果，同时按状态配置下一次尝试时间、租约和消息 ID。[手工投递意图构造 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L150 "支持辅助函数直接插入变更与投递意图，并设置摘要、状态、调度时间、租约和消息 ID。") 这种直接数据库构造适合覆盖特定状态边界，但也绕过了部分正常生产入口。

<a id="cancel_and_state_boundaries"></a>
## 取消后的状态与诚实边界

第一条用例启动会话并确认初始意图为 `pending`；取消返回后，会话和意图均为 `cancelled`，意图记录“发送前取消”的原因。随后 worker 返回未处理，伪适配器发送次数保持为零。[取消后的最终状态与不发送断言 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L191 "支持取消返回后会话和待发送意图均为 cancelled、worker 不处理且伪适配器没有发送；仅作为最终状态证据。") 这些断言证明取消完成后的最终状态以及之后运行的消费者不会发送，但测试名称本身不足以证明会话更新和意图清扫由同一事务原子提交。

第二条用例先把原卡片设为 `delivered` 并保留消息 ID，再加入租约尚未到期的 `sending` 意图。取消后，已投递历史及消息 ID不变，发送中记录也仍为 `sending`。[已投递和发送中记录保留断言 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L217 "支持取消不会改写 delivered 历史或消息 ID，也不会立即改变仍处于 sending 的投递意图。") 这体现了诚实边界：系统不会把用户已看到的历史伪装成已撤回，也不声称能在网络请求途中召回卡片；但该用例没有继续推进租约或提供方结果，不能证明发送中意图最终如何收敛。

<a id="sender_guard_limits"></a>
## 发送侧兜底与覆盖限制

第三条用例在会话取消后手工插入新的 `pending` 意图，模拟重试记录重新浮现或绕过先前取消清扫。worker 未调用消息适配器，并使关联取消会话的意图进入 `cancelled`，形成发送侧第二道守卫。[取消后重现意图的发送侧抑制 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L257 "支持 worker 拦截取消后重新出现的 pending 意图、不调用消息适配器并留下 cancelled 记录。")

整体测试直接组合投递仓库与 worker、加密凭据存储、飞书标注服务、质量仓库、稳定摘要和 Store。[被测模块依赖关系 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L7 "证明测试直接引入投递仓库与 worker、凭据存储、标注服务、质量仓库、稳定摘要和 Store，但不用于推断其未展示的内部实现。") 当前材料因此支持排队记录取消、已投递历史保留、发送中记录不被虚假召回，以及取消后重现意图的抑制；它仍不覆盖真实飞书 API、跨进程竞争、事务故障注入、租约到期、失败重试或多个 worker 同时争抢。
