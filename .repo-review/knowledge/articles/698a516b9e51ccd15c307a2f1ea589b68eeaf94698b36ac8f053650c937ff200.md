# 标注会话取消与 Lark 投递隔离测试

回归验证取消质量标注会话后的最终状态与发送抑制：尚未发送的卡片不再投递，取消后重新入队的意图也会被拦截；已投递及发送中的记录保持真实状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="fixture"></a>
## 隔离环境与关联数据

测试以临时 SQLite、加密密钥仓库和假消息适配器构造无网络的 Lark 环境，并建立连接、版本、绑定、通知目标、质量数据集和标注样本。辅助函数还能手工插入 `pending` 或带租约的 `sending` 意图，用来模拟服务正常创建流程之外的队列状态。[无网络 Lark 测试环境 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L1 "说明该回归测试使用临时数据库和假消息适配器，不发起真实 Lark 或网络调用。") [会话与投递夹具 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L70 "支持测试所需连接、绑定、通知目标、数据集以及手工投递意图的构造方式。")

<a id="cancel-guards"></a>
## 取消后的状态与双重发送防线

第一个场景在 `cancel` 返回后读取最终状态，确认会话和原 `pending` 意图均为 `cancelled`，错误原因注明发送前取消；worker 随后没有可处理任务，假适配器零发送。该断言验证最终一致状态，但没有并发观察或失败注入，不能单凭测试证明两个更新的事务原子性。取消后若又出现新的 `pending` 意图，发送端仍会拒绝投递并将其置为取消，形成消费侧补充防线。[取消后的最终状态 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L191 "支持 cancel 返回后会话和排队意图均为取消状态，以及 worker 零发送；不将测试名称中的事务性表述当作已独立验证的原子性。") [发送端抑制迟到意图 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L254 "支持取消后重新出现的 pending 意图仍被 worker 拦截并转为取消。")

<a id="honest-boundary"></a>
## 不可撤回边界

取消不会改写已经 `delivered` 的历史及其消息标识，也不会把租约仍有效的 `sending` 行伪装成已撤回。测试因此只保证尚未发送的卡片不再发送；它没有覆盖发送中意图在租约到期后究竟收敛为已投递、失败还是去重窗口后的未知状态。[保留已投递与发送中状态 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L217 "支持不召回已投递历史、不伪改发送中状态，并界定租约到期后的收敛行为尚未覆盖。")
