# 证据阅读、引用追踪与上下文追问

该组件把单个证据片段组织成可逐层深入并返回原位的阅读对话框，集中呈现材料上下文、双向引用、图片与追问入口。它负责前端状态和交互编排，关系校验、问答执行以及底层对话框能力由其他模块承担。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 从引用进入可追溯的阅读现场

组件服务于“从一条引用继续查证”的场景：外部调用公开的 `open(id)` 后，前端获取证据并建立阅读帧；证据对象同时包含当前片段、所属修订、出向引用和反向引用。参考 [证据打开与加载 ↗](../../../apps/web/src/EvidenceReader.vue#L16 "支持通过片段标识获取证据、保存滚动位置、压入阅读帧、阻止并发请求及记录失败的说明。") [证据数据合同 ↗](../../../apps/web/src/api.ts#L26 "说明证据对象由片段、修订、出向引用和反向引用组成。")

对话框以修订标题作为标题，并在正文上方明确展示来源、版本号以及现行或历史状态，帮助读者判断证据所处版本，而不是把不同修订混作同一材料。参考 [阅读对话框状态 ↗](../../../apps/web/src/EvidenceReader.vue#L67 "支持对话框标题、层级、侧栏状态、关闭清栈和返回事件的说明。") [修订来源与版本标识 ↗](../../../apps/web/src/EvidenceReader.vue#L98 "直接支持界面展示材料来源、版本号及现行或历史状态的论断。")

<a id="navigation"></a>
## 分层导航与阅读位置恢复

打开下一条引用前，组件保存当前滚动位置，再将新证据压入帧栈并滚到顶部；返回上一层时弹出当前帧并恢复原来的位置。参考 [证据打开与加载 ↗](../../../apps/web/src/EvidenceReader.vue#L16 "支持通过片段标识获取证据、保存滚动位置、压入阅读帧、阻止并发请求及记录失败的说明。") [返回与滚动恢复 ↗](../../../apps/web/src/EvidenceReader.vue#L41 "支持弹出当前帧并恢复上一层滚动位置的说明。")

路径栏可直接回到任意已访问层。若目标片段已经存在于栈中，组件不会再次请求或压栈，而是提示其层级并允许回跳，以避免引用环无限展开。`loading` 阻止同时发起新的打开请求；请求失败时记录错误，已有帧保持不变。参考 [证据打开与加载 ↗](../../../apps/web/src/EvidenceReader.vue#L16 "支持通过片段标识获取证据、保存滚动位置、压入阅读帧、阻止并发请求及记录失败的说明。") [路径回跳与循环提示 ↗](../../../apps/web/src/EvidenceReader.vue#L75 "支持路径裁剪、重复目标提示以及回到既有阅读层的交互说明。")

关闭对话框会清空全部帧。当前材料只展示了组件内的帧栈处理，没有展示 URL 深链、Esc 行为或关闭后的焦点归还规则。参考 [阅读对话框状态 ↗](../../../apps/web/src/EvidenceReader.vue#L67 "支持对话框标题、层级、侧栏状态、关闭清栈和返回事件的说明。")

<a id="views"></a>
## 查看上下文并维护引用关系

阅读区提供三种视角：**引用片段**显示精确文本及其下级引用，**完整材料**按修订中的片段顺序连续展示并加载图片部件，**反向引用**列出直接指向当前片段的来源。界面明确提示，记录了引用关系并不等于自动判定其语义支持度。参考 [三种证据视角 ↗](../../../apps/web/src/EvidenceReader.vue#L104 "支持引用片段、完整材料、图片部件和反向引用的展示方式，以及引用不自动代表支持度的提示。")

用户可以输入另一个片段标识并向 `/relations` 提交来源与目标；成功后，组件重新获取当前证据、清空输入并通知父组件刷新。目标是否合法、重复关系如何处理以及最终采用何种关系类型，取决于未提供的服务端实现，不能从本组件确认。参考 [人工添加引用 ↗](../../../apps/web/src/EvidenceReader.vue#L48 "支持前端提交来源与目标、刷新当前证据、清空输入及发出保存通知的流程说明。")

<a id="followup"></a>
## 沿证据路径发起追问

每个阅读帧独立保存追问侧栏状态；当前层的 `ChatPane` 会接收焦点片段、模型配置和整条阅读路径。`ChatPane` 发出的 `open` 事件被转交给阅读器的同一个 `open` 方法，因此组件接口允许后续引用继续进入现有帧栈，但现有材料没有展示答案引用在何处实际触发该事件。参考 [证据侧栏接口 ↗](../../../apps/web/src/EvidenceReader.vue#L161 "支持每层追问状态、焦点证据、路径上下文以及 ChatPane 的 open 事件接入阅读器的组件关系。")

追问默认聚焦当前片段；只有选择路径范围时，路径中的片段标识才作为 `contextIds` 提交给 `/runs`。问答运行、轮询和答案生成属于 `ChatPane` 及服务端职责，并非阅读器自身完成。参考 [追问范围与运行创建 ↗](../../../apps/web/src/ChatPane.vue#L49 "说明追问如何以当前片段为焦点，并仅在选择路径范围时提交路径上下文。")
