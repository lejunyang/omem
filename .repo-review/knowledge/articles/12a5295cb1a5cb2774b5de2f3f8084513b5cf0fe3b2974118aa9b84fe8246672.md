# 递归证据阅读与就地追问

证据阅读器以栈式对话框串联引用片段、完整材料和反向引用，并保留逐层滚动位置；读者还可查看图片、添加显式引用，或围绕当前证据路径发起追问。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 从引用片段回到材料上下文

组件解决的是“看到一条证据后如何继续读懂来源”的问题。打开片段时，它请求包含片段、所属修订、下级引用和反向引用的证据对象，并将其压入阅读栈；界面同时标出来源、版本及是否现行，避免把历史内容误当成当前版本。参考 [证据加载与阅读栈 ↗](../../../apps/web/src/EvidenceReader.vue#L16 "支持打开证据时请求数据并压入栈的流程说明。") [证据数据结构 ↗](../../../apps/web/src/api.ts#L18 "说明证据对象包含片段、修订、下级引用和反向引用。")

读者可在**引用片段、完整材料、反向引用**之间切换。完整材料按修订中的片段连续展示，并把其中的图片交给图片组件加载，因此文本上下文和非文本附件仍处于同一阅读入口。参考 [材料视图与图片展示 ↗](../../../apps/web/src/EvidenceReader.vue#L104 "支持三种阅读标签及完整材料中图片渲染的描述。")

<a id="navigation"></a>
## 递归展开而不丢失阅读位置

点击下级引用会再次调用 `open`：组件先保存当前层滚动位置，再把新证据加入栈并滚到顶部；返回时弹出一层并恢复上一层位置。路径导航也允许直接裁剪到任意已访问层。参考 [逐层返回与滚动恢复 ↗](../../../apps/web/src/EvidenceReader.vue#L27 "支持入栈前保存滚动位置、返回后恢复上一层位置的说明。")

若目标片段已经存在于栈中，组件不会重复压栈，而是提示它位于第几层，让读者回到该层，从而避免循环引用造成无限嵌套。并发打开请求由单个 `loading` 标志拦截；这意味着加载期间的其他打开动作会被直接忽略，而不是排队。参考 [循环与并发打开处理 ↗](../../../apps/web/src/EvidenceReader.vue#L15 "支持已在栈中的片段只提示所在层，以及加载期间忽略新打开请求的边界说明。")

<a id="actions"></a>
## 关联证据与围绕路径追问

读者可输入另一个片段 ID 建立显式关系；保存成功后，当前证据会重新获取，并向父级发出 `saved` 事件。界面明确说明这种关系只是“明确引用”，不会自动判断支持度。参考 [显式引用保存 ↗](../../../apps/web/src/EvidenceReader.vue#L48 "支持创建关系、刷新当前证据并通知父级的流程，以及界面对关系含义的限定。")

每一层可独立展开追问侧栏。阅读器把当前片段、模型配置以及整个栈中的片段 ID 交给 `ChatPane`；后者仅在选择路径范围时把这些 ID 作为上下文提交，因此“就这段问”和“沿证据路径问”具有不同范围。参考 [证据路径追问 ↗](../../../apps/web/src/ChatPane.vue#L49 "支持阅读器向追问组件传递当前片段和路径，以及追问组件按范围提交上下文的说明。")

错误会显示为警告；但当前材料未展示后端对无效、重复或自引用关系的约束，也没有测试文件可证明循环提示、滚动恢复和加载期点击等交互已被自动化覆盖。

<a id="boundaries"></a>
## 实现边界与可见限制

组件自身只管理前端阅读状态，并依赖 API 返回完整的 `Evidence` 结构；引用关系的持久化、权限和有效性判断都不在本文件中。关闭对话框会清空整个阅读栈，而返回按钮在首层会弹出最后一帧，从而回到外部阅读界面。参考 [对话框关闭与返回 ↗](../../../apps/web/src/EvidenceReader.vue#L67 "支持关闭时清空栈、返回时弹出一层及首层返回阅读界面的说明。")
