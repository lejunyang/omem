# 质量数据集与样本状态仓库

定义质量样本和标签合同，管理数据集创建、样本去重、人工处置、标签修订、冻结及冻结后完整性复核。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="contracts-lifecycle"></a>
## 数据合同与数据集生命周期

仓库用严格 schema 约束样本来源、类别、正文和 provenance，并约束标签处置、对象类型、证据、自动应用及禁止副作用。`extract` 必须至少有一个对象，非 extract 标签不得 `autoApply`，从入口阻止自相矛盾的标注。[质量样本与标签 schema ↗](../../../apps/server/src/quality/repository.ts#L8 "支持输入类别、标签对象及 extract/autoApply 交叉约束的说明。")

数据集以 name、split、source digest 判重；新增样本只允许在 draft 或 labeling 状态。每个 input 与草稿 label 都计算摘要，样本通过 `INSERT OR IGNORE` 写入，并在事务末把 draft 数据集推进到 labeling；失败会回滚整批。[数据集创建与样本批量写入 ↗](../../../apps/server/src/quality/repository.ts#L118 "说明数据集判重、可写状态、摘要计算、事务提交和回滚。") 查询接口提供数据集汇总、顺序样本、下一 pending 项和按状态进度，供 Lark 标注服务构建会话与卡片。[样本查询与进度接口 ↗](../../../apps/server/src/quality/repository.ts#L217 "支持仓库向标注服务提供顺序样本、下一待处理项和状态计数的关系。")

<a id="review-freeze"></a>
## 人工处置、并发保护与冻结

`label` 只接受 pending 样本，并用 expected label digest 检查调用者看到的草稿仍为最新版。confirm 直接固化 draft；abstain 生成无对象、禁止自动应用的确认标签；skip 与 needs_edit 不产生 confirmed label。更新语句再次同时限制 pending 状态与摘要，形成乐观并发保护。[人工标签状态转换 ↗](../../../apps/server/src/quality/repository.ts#L278 "解释四种动作的确认标签、目标状态和乐观并发检查。")

`revise` 允许 pending、needs_edit、skipped 样本修改草稿，重新计算摘要并清除审核人和审核时间，使其回到 pending；已 confirmed 的样本不可改。[草稿标签修订 ↗](../../../apps/server/src/quality/repository.ts#L328 "支持可修订状态、摘要轮换及恢复 pending 的说明。") 数据集只有在样本数恰好等于 target count 且全部 confirmed 时才能冻结。冻结摘要覆盖每项 ordinal、input digest 与 confirmed label digest，`verifyFrozen` 会重算并拒绝任何不一致。[冻结与完整性校验 ↗](../../../apps/server/src/quality/repository.ts#L358 "说明完全确认前置条件、manifest digest 内容及冻结后复核。") 代码未显示数据库唯一索引，`INSERT OR IGNORE` 的实际去重粒度仍需迁移定义佐证。
