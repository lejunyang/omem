# 质量评测数据集仓储

定义质量样本和标签合同，并管理数据集从草稿、人工标注到冻结校验的完整 SQLite 生命周期，使用摘要和条件更新防止重复与并发覆盖。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="contracts"></a>
## 输入与标签约束

仓储首先用严格 schema 固定样本来源、类别、正文和来源身份信息；标签则区分提取、放弃和需要上下文，并约束任务、事实、经历、流程四类对象。[质量样本与标签 schema ↗](../../../apps/server/src/quality/repository.ts#L8 "支持样本来源、类别、来源身份以及标签对象类型的合同描述。") 交叉校验要求 `extract` 至少有一个对象，同时禁止非提取标签自动应用，避免出现语义矛盾的标注。[标签交叉约束 ↗](../../../apps/server/src/quality/repository.ts#L61 "说明提取标签必须有对象且非提取标签不得自动应用。")

<a id="dataset_flow"></a>
## 数据集与样本写入

数据集以名称、分组和来源摘要查重；相同来源再次创建会返回既有标识。[来源摘要级数据集去重 ↗](../../../apps/server/src/quality/repository.ts#L118 "支持相同名称、分组和来源摘要复用既有数据集。") 加样本只允许草稿或标注中数据集，逐条校验并计算输入、标签摘要，通过 `INSERT OR IGNORE` 去重；整批操作由显式事务保护，成功后把草稿转为 labeling，异常则回滚。[事务化样本插入 ↗](../../../apps/server/src/quality/repository.ts#L155 "说明状态门禁、稳定摘要、忽略重复和事务回滚行为。")

<a id="review_integrity"></a>
## 人工变更与冻结完整性

标注要求样本仍为 pending 且调用方持有当前标签摘要；确认会固化草稿标签，不提炼会生成明确的 abstain 标签，而修改或跳过保留后续处理状态。SQL 再次以状态和摘要做条件更新，防止检查后并发变化。[样本标注乐观并发控制 ↗](../../../apps/server/src/quality/repository.ts#L278 "支持动作到标签及状态的映射，以及基于 pending 状态和摘要的条件更新。") `revise` 同样采用摘要乐观锁，写入新草稿后清空旧审核信息并重新排队。[草稿修订与重新排队 ↗](../../../apps/server/src/quality/repository.ts#L328 "说明可修订状态、摘要校验以及清理旧审核结果的流程。") 只有样本数等于目标数且全部 confirmed 才能冻结；冻结清单摘要覆盖顺序、输入和已确认标签，`verifyFrozen` 会重算并检测篡改。[冻结清单与完整性复核 ↗](../../../apps/server/src/quality/repository.ts#L358 "支持全量确认门槛、manifest 摘要生成和冻结后重算校验。")
