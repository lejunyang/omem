# 质量评审数据集仓储与冻结校验

该仓储管理质量样本从数据集创建、草稿入库、人工确认、标签修订到冻结校验的生命周期。规范化摘要用于标签乐观并发和冻结清单比较；样本判重、并发入库、修订竞态与重复冻结的精确语义仍受数据库约束和写阶段条件影响。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-model"></a>
## 数据合同与持久化边界

该模块为质量评测提供 SQLite 仓储。样本输入保留来源定位、类别、正文和身份来源信息；标签区分提取、弃权与缺少上下文，并可描述任务、主张、经历或流程。Zod 合同限制字段、长度与枚举，还要求提取结果至少包含一个对象、非提取结果不得自动应用，从入口阻止语义矛盾数据。[输入与标签校验合同 ↗](../../../apps/server/src/quality/repository.ts#L8 "支持样本输入字段、标签类型及跨字段语义约束的说明。")

持久化记录同时保存草稿标签、人工确认标签、输入与标签摘要、评审状态及评审人。数据库行读回时会重新解析 JSON，因此不符合当前合同的历史数据会显式失败，而不会被静默当作有效样本。[质量样本持久化映射 ↗](../../../apps/server/src/quality/repository.ts#L79 "支持草稿与确认标签分离、状态元数据保存及读回时重新校验 JSON 的论断。")

<a id="dataset-flow"></a>
## 数据集创建与样本入库

创建数据集时先按名称、划分和来源摘要查询已有记录；未命中则生成新标识并以 `draft` 状态写入。加入样本时，数据集状态检查和当前最大序号读取发生在 `BEGIN IMMEDIATE` 之前；事务只覆盖逐项校验与写入、将数据集转为 `labeling` 以及提交或回滚。[批量入库与事务边界 ↗](../../../apps/server/src/quality/repository.ts#L155 "支持状态和最大序号在事务前读取、逐项写入与状态更新位于立即事务中的并发边界说明。") 这替代了“整个批次从状态检查起都受立即事务保护”的旧结论：并发 `addSamples` 可能基于同一事务前状态和起始序号继续执行，最终行为还取决于表约束与冲突处理。

每项样本会计算输入和标签摘要，并通过 `INSERT OR IGNORE` 写入。摘要模块递归规范化对象、忽略值为 `undefined` 的字段并排序键，再对规范 JSON 计算 SHA-256，使属性顺序不同的等价对象获得稳定摘要。[规范化摘要实现 ↗](../../../apps/server/src/storage/digest.ts#L3 "解释稳定摘要如何通过递归规范化、键排序和 SHA-256 生成，并支持对其判重能力边界的判断。") 但材料未提供表结构，不能确认输入摘要或序号是否具有唯一约束，也不能断言重复样本必然被忽略。

<a id="review-lifecycle"></a>
## 人工评审、修订与并发控制

人工评审只接受读取时为 `pending` 且标签摘要匹配的样本。确认采用草稿标签，弃权构造空对象标签，跳过与需编辑不产生确认标签；最终更新再次约束 `state='pending'` 和摘要，并要求恰好更新一行，从而检测读取后的并发变化。[人工标签状态转换 ↗](../../../apps/server/src/quality/repository.ts#L278 "支持评审动作映射以及最终更新同时约束待审状态和标签摘要的乐观并发机制。")

修订入口在读取阶段仅允许 `pending`、`needs_edit` 或 `skipped`，随后校验新标签、重算摘要并清空确认信息，使样本回到 `pending`。[标签修订与写阶段竞态 ↗](../../../apps/server/src/quality/repository.ts#L328 "支持修订的读取时状态检查、摘要检查，以及最终更新缺少状态约束所形成的并发覆盖风险。") 这替代了“已确认样本绝对不能通过该入口修改”的旧结论：写入条件只有样本标识和旧标签摘要，没有再次约束状态。若读取后另一请求确认了样本但未改变标签摘要，修订仍可能覆盖确认状态；因此这里的保护只在读取时成立。

<a id="freeze-integrity-and-limits"></a>
## 冻结清单、校验范围与限制

冻结要求样本数量等于目标数且全部为 `confirmed`。清单按序号、已存储输入摘要和重新计算的确认标签摘要生成；校验按相同结构复算，可发现集合、顺序、存储摘要或确认标签导致的清单差异。[冻结清单与完整性复算 ↗](../../../apps/server/src/quality/repository.ts#L358 "支持冻结前置条件、清单组成及校验仅使用已存输入摘要和重算确认标签摘要的范围说明。") 但它不会从 `input_json` 重算输入摘要，因此正文和已存摘要若被不一致地修改，未必能被发现。

冻结更新只匹配 `labeling` 状态，却不检查受影响行数，随后无条件返回本次计算的时间和摘要。[冻结状态条件与返回值 ↗](../../../apps/server/src/quality/repository.ts#L376 "支持冻结更新仅匹配 labeling、未检查更新行数却直接返回新冻结信息这一限制。") 因而重复冻结可能返回并未写入数据库的新结果。数据库唯一约束、仓储错误的 API 映射以及这些并发边界的测试均未出现在材料中，仍需结合迁移、调用方和集成测试确认。
