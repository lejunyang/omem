# 从符号查询定位候选调用位置

说明 CodeNavigation 如何基于固定源码版本的整文件 AST，把“谁调用某符号”的检索请求转换为带行号的候选结果，并解释其与统一检索、解析器和阅读界面的关系及名称级匹配边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决定义命中替代不了调用方的问题

普通关键词搜索能找到符号定义、导入和注释，却不能可靠回答“哪些地方调用了它”。`CodeNavigation` 专门检查代码检索单元：非代码或非原始材料立即跳过，并坚持从该单元所指向的固定版本读取整份文件，避免把方法片段单独解析后丢失类语法，也避免误读当前工作区的新版本。参考 [固定版本与适用范围 ↗](../../../apps/server/src/retrieval/code-navigation.ts#L6 "支持该类只处理源码代码单元，并通过整份固定版本文件保留正确语法上下文的说明。")

统一检索会把含明确符号且带“调用方／谁调用”等措辞的问题转成 `callers` 意图；调用者也可以显式传入该意图，因此这里承担的是导航候选确认，而不是通用相关性排序。参考 [调用方意图识别 ↗](../../../apps/server/src/retrieval/unified.ts#L339 "支持统一检索把带符号的明确调用方问法转换为 callers 意图。")

<a id="flow"></a>
## 一次 reserveParcel 查询如何得到行号

以“哪些地方调用 `reserveParcel`？”为例，流程如下：

```mermaid
flowchart LR
  Q[调用方查询] --> U[筛出含符号的代码单元]
  U --> R[按 revisionId 读取整份固定源码]
  R --> A[解析 AST 调用表达式]
  A --> M[限定在单元行范围内匹配末级名称]
  M --> H[返回 candidate 行号与局部摘录]
```

统一检索先按文本缩小代码单元，并优先检查更小的包围操作；随后调用 `matches`，去重同一版本、行号和符号，围绕最早命中行生成上下文摘录。参考 [调用候选装配 ↗](../../../apps/server/src/retrieval/unified.ts#L346 "支持候选代码单元筛选、最小包围操作优先、调用导航、去重和局部摘录的完整调用方流程。")

`matches` 首次遇到某个版本时从数据库恢复完整材料并调用 `parseFile`，之后复用该版本的调用列表。参考 [固定源码解析与缓存 ↗](../../../apps/server/src/retrieval/code-navigation.ts#L18 "支持按 revisionId 从数据库恢复完整材料、解析调用列表并缓存的说明。") 解析器只把标识符调用或属性访问的末级名称及其位置记录为调用，因此导入和注释不会成为调用点。参考 [AST 调用提取 ↗](../../../apps/server/src/code/parse.ts#L167 "支持解析器只记录标识符调用和属性访问末级名称及源码位置的说明。") 最后，导航器忽略限定名的前缀、按小写末级名称比较，并只保留落在当前检索单元起止行内的位置，输出 `kind: call`、`status: candidate` 和去重后的行号。参考 [名称与行范围匹配 ↗](../../../apps/server/src/retrieval/code-navigation.ts#L35 "支持末级名称比较、单元行范围过滤以及 candidate 结果结构。")

测试中的 `checkout` 三个函数与 `mobile` 一个函数分别调用该符号；查询得到第 1、3、4、5 行，且所有结果都保持候选状态，直观展示了输入与输出。参考 [代表性调用结果 ↗](../../../apps/server/tests/retrieval-unified.test.ts#L661 "支持 reserveParcel 示例最终返回四个真实调用行且全部保持候选状态。")

<a id="limits"></a>
## 候选语义、版本边界与读者入口

这里得到的不是类型解析后的跨文件调用图。结果合同明确把 `codeMatches` 定义为**名称级 AST 调用位置**并固定标记为 `candidate`；因此同名对象方法可能误合并，导入别名、动态调用或无法解析的语法也可能漏掉。参考 [名称级候选合同 ↗](../../../apps/server/src/retrieval/port.ts#L56 "支持 codeMatches 并非类型解析调用边，而是名称级 AST 候选的边界说明。")

缓存最多保存 64 个版本的调用列表，超限时删除最早插入项；它只是加速层，淘汰后会重新从固定快照解析，不改变读取的版本。参考 [缓存淘汰语义 ↗](../../../apps/server/src/retrieval/code-navigation.ts#L30 "支持 64 项缓存上限以及淘汰不改变固定快照读取结果的说明。") 源文件换版后，当前搜索只返回新版本仍存在的调用，但旧结果携带的版本锚点仍可读取原调用文本。参考 [换版后的历史可读性 ↗](../../../apps/server/tests/retrieval-unified.test.ts#L716 "支持新搜索遵循当前版本，而旧结果仍能按原 revisionId 读取历史调用文本。")

统一检索负责意图识别、候选单元、摘录与排序，`parseFile` 负责 AST 提取，`CodeNavigation` 负责在固定版本和当前单元范围内确认候选行。网页会提示名称匹配的不确定性，并为每个行号提供“查看第 N 行调用”按钮；需要提高准确度时，应从解析器的别名或接收者类型解析入手，而不是把此处的 `candidate` 改称已确认关系。参考 [调用候选风险提示 ↗](../../../apps/web/src/App.vue#L711 "支持网页向读者说明同名方法、别名和动态调用的候选边界。") [按行打开调用位置 ↗](../../../apps/web/src/App.vue#L747 "支持网页为每个候选行提供直接查看调用位置的读者入口。")
