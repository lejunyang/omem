# 代码分析角色的证据化写作规范

该材料定义代码分析角色的分析目标、结构化输出、证据引用和读者导向写作要求。它属于角色行为配置，只能说明预期输出，不能单独证明运行时已经实现合同校验或引文抽取。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 把代码事实转化为功能解释

这份角色配置用于把代码材料整理成首次接触项目的人也能理解的 Wiki。分析应先说明代码解决的问题和实际作用，再解释核心流程、边界条件及其与其他模块的关系，而不是停留在函数名、符号或计数清单上。AST 只是定位代码事实的线索；跨文件调用必须得到源码支持，无法确认时需要明确标注。测试文件则用于说明已有断言和未覆盖行为。参考 [代码分析目标 ↗](../../../packages/agent-runtime/roles/code-analyst/1/prompt.md#L1 "支持代码分析需要解释问题、流程、边界与模块关系，并谨慎陈述跨文件调用和测试覆盖。")

文章标题和叙述应围绕功能展开，避免让文件路径、日志、内部标识或校验细节成为阅读主线。参考 [读者导向写作 ↗](../../../packages/agent-runtime/roles/code-analyst/1/prompt.md#L9 "支持文章面向首次接触项目的读者、按功能命名并避免内部信息主导叙述。")

<a id="evidence_contract"></a>
## 让结构和引用服务于论断

输出必须使用中文并符合指定 JSON 合同，同时覆盖任务列出的全部目标。正文通常组织为 2—4 节，每节都应在相关句子或段落中放置引用；引用只能指向任务提供的完整材料键或文章键。材料引用须填写真实行范围并将 `quote` 留空，由宿主从固定材料复制精确短引文。参考 [结构与引用合同 ↗](../../../packages/agent-runtime/roles/code-analyst/1/prompt.md#L3 "说明目标覆盖、正文分节、就近引用、完整材料键以及真实行范围和空引文等输出要求。")

正文应采用语义清晰的小标题，可在确有比较需要时使用对照表；只有涉及多阶段流程时，才使用简洁的 Mermaid 流程图或时序图，而且图中的关系必须有证据支持。引用标签应简短可读，移除引用标记后正文仍需通顺；引用代码时还应选择足以支持论断的最小连续行范围。参考 [图表与精确引用 ↗](../../../packages/agent-runtime/roles/code-analyst/1/prompt.md#L13 "支持对照表和 Mermaid 图各自的使用条件、正文可读性以及代码引用采用最小连续行范围的要求。")

<a id="status_boundary"></a>
## 区分角色约定与运行时能力

该文件规定分析角色**应当如何输出**：例如关系值必须服从 schema，不确定或缺少背景的事项进入 questions，并且不得读取任务范围之外的材料。它没有提供执行器、Schema 校验器、固定引文抽取器或模型调用实现，因此不能仅凭这份配置断言相关机制已经在运行时落地。参考 [角色行为边界 ↗](../../../packages/agent-runtime/roles/code-analyst/1/prompt.md#L3 "表明材料规定的是输出、疑问与证据边界，但未提供这些约定的运行时实现证据。")
