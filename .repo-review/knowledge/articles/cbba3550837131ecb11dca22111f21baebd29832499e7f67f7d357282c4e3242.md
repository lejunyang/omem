# 代码材料分析提示模板

该提示模板规定代码分析的关注点、固定材料边界、中文 JSON 输出、逐目标覆盖、就近引用和显式问题记录。它属于模型行为要求，不等同于宿主侧强制验证或已实现能力。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="analysis-scope"></a>
## 分析目标与证据边界

模板要求解释代码解决的问题、核心流程、边界条件及模块关系，并把 AST 仅视为定位线索；跨文件调用必须由源代码支持，不确定内容要明确标记，测试材料则需区分已断言与未覆盖行为。[代码分析关注点 ↗](../../../packages/agent-runtime/roles/code-analyst/1/prompt.md#L1 "支持问题、流程、边界、模块关系、跨文件证据和测试覆盖的分析要求。")

同时要求只处理已提供材料，不调用工具或读取其他文件。由此形成封闭证据分析流程，但也意味着缺失的调用链或背景只能作为疑问保留，不能自行补全。[固定材料与无工具边界 ↗](../../../packages/agent-runtime/roles/code-analyst/1/prompt.md#L3 "支持分析仅限提供材料且不得调用工具或读取额外文件的限制。")

<a id="output-discipline"></a>
## 结构化写作与引用纪律

输出须使用中文并遵守指定 JSON 合同，覆盖全部目标且保持 document.key 完全一致；正文应解释作用、背景、流程、限制和材料关系，而非只罗列符号与计数。[目标覆盖与正文要求 ↗](../../../packages/agent-runtime/roles/code-analyst/1/prompt.md#L4 "支持逐目标覆盖、键一致以及解释性正文的要求。")

引用必须贴近对应论断，每节至少一处，所有 citations 都应在正文出现。材料目标须使用完整 key 与真实行号，quote 留空供宿主抽取；不能确定或需要选择的内容应进入带原因、下一步、阻塞状态和引用键的问题列表。[就近引用与问题记录规则 ↗](../../../packages/agent-runtime/roles/code-analyst/1/prompt.md#L5 "支持引用放置、固定材料定位、空 quote 和问题字段的写作流程。")
