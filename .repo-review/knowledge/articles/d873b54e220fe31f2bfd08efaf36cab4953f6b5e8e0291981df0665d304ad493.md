# 符号解释角色提示词

规定 symbol-explainer 只能依据固定快照解释目标符号的签名、读写与调用关系，必须区分直接事实和行为推断，并生成带 provenance 的 CodeUnderstanding.v1。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="scope"></a>
## 符号级分析目标

提示词要求解释固定快照中的特定符号，包括签名、读写对象、调用者以及被调用对象，并把快照中的文件、符号节点、边和随附证据视作唯一事实来源。[符号解释范围与事实来源 ↗](../../../packages/agent-runtime/roles/symbol-explainer/1/prompt.md#L3 "支持角色分析签名、读写及调用关系，并以固定快照为唯一事实来源的论断。") 输出必须是单个 `CodeUnderstanding.v1` JSON；每个目标符号的说明进入 `claims`，声明的签名、范围和已存在边属于 `raw_fact`，行为推断属于 `interpretation`。[符号声明与引用规则 ↗](../../../packages/agent-runtime/roles/symbol-explainer/1/prompt.md#L5 "说明原始事实和解释的分类、节点与边引用要求以及未知项处理。")

这定义了符号解释的预期粒度和证据边界，但没有证明读写关系一定存在于快照，也没有证明某次解释已经完成。

<a id="provenance"></a>
## 引用纪律与结果封印

角色必须引用目标符号自身的节点标识及其所依赖的边标识，且这些标识都必须存在于快照；无法确定的内容应放入 `unknowns`，而非虚构关联。[符号声明与引用规则 ↗](../../../packages/agent-runtime/roles/symbol-explainer/1/prompt.md#L5 "说明原始事实和解释的分类、节点与边引用要求以及未知项处理。")

结果封印需明确角色为 symbol-explainer，记录模型、提示词模式与输入摘要、当前 ISO 时间，并标注结果不是 seed、也未由自身验证。[符号解释结果封印 ↗](../../../packages/agent-runtime/roles/symbol-explainer/1/prompt.md#L7 "支持角色、模型、摘要、时间和未自证状态等 provenance 要求。") 这种自证隔离有利于后续独立复核，但是否真正存在独立验证角色和状态推进流程，不能从提示词本身确认。
