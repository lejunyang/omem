# 个人开发模式入口

极薄的兼容入口：先标记 personal 模式，再加载共享开发编排器，使个人应用复用 review 编排器的端口、生命周期与健康检查能力。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="delegation"></a>
## 模式注入与职责委托

该文件唯一的运行职责是把 `OMEM_DEV_MODE` 强制设为 `personal`，然后动态导入共享的 `dev-review` 编排模块；空导出用于保持模块语义。[个人模式入口委托 ↗](../../../scripts/dev.ts#L1 "支持入口设置 personal 模式并动态加载共享编排器的说明。") 因此它本身不启动服务器、不选择端口也不处理信号，实际行为完全取决于被导入模块读取该环境值后的 personal 分支。

<a id="boundary"></a>
## 覆盖与边界

赋值是无条件的，所以通过此入口启动时，调用者预先设置的其他模式会被覆盖；这与专门的 review 启动路径形成明确分工。[无条件 personal 模式覆盖 ↗](../../../scripts/dev.ts#L1 "支持此入口会覆盖既有 OMEM_DEV_MODE 值这一边界判断。") 从现有四行只能确认模式切换和模块加载，无法单独证明包脚本如何调用它，也没有针对该入口的直接断言材料。
