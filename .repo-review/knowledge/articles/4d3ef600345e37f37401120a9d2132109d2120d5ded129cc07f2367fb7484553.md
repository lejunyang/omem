# 需求跟进与项目理解的执行状态材料

该模块把实际事项和编码执行记录保存为页面的固定输入。需求跟进页读取本页记录；项目理解页还汇总同一项目下各需求跟进页的编码执行记录。后续生成与复核阶段通过只读入口读取同一版材料，避免把讨论计划、模型意见、代码检查和正式发布混为一谈。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_scope"></a>
## 哪些页面会生成这份材料

这个模块为需求跟进页和项目理解页保存实际执行状态，其他页面不会触发捕获。材料来自系统对执行状态的直接观察，生成文章不参与捕获，以免文章维护反过来成为自己的输入。设计约定还要求同一页面只保留一个来源，内容未变时沿用原版本。参考 [适用页面与捕获约定 ↗](../../../apps/server/src/assistant/followup-state.ts#L10 "支持捕获仅覆盖需求跟进页和项目理解页，并排除生成文章以避免自触发的说明。")

一次捕获会先查出直接绑定到页面的事项，再读取全部事项。只有归属当前使用者，并且满足“直接绑定到本页”或“所属项目位于页面上下文”任一条件的记录才会保留。参考 [实际事项筛选 ↗](../../../apps/server/src/assistant/followup-state.ts#L25 "支持按页面直接绑定、项目上下文和当前使用者筛选事项的规则。")

<a id="project_rollup"></a>
## 项目理解页怎样汇总编码进展

需求跟进页只选择页面标识与自身一致的编码执行记录。项目理解页会先找出上下文项目有交集的需求跟进页，再同时选择本页记录和这些需求跟进页的记录。因此，项目理解页能够在一份材料里看到项目自身以及相关需求的编码进展。参考 [项目相关需求与编码记录选择 ↗](../../../apps/server/src/assistant/followup-state.ts#L42 "支持项目理解页识别同一上下文中的需求跟进页，并汇总相关编码执行记录。")

每条记录保留队列状态、运行阶段、错误、是否已应用、评审指纹和检查结果，并关联运行产出的结果材料。运行尚未建立时，阶段记为排队中，检查列表为空，结果材料为空；发布标记始终为否，因此检查通过或代码已应用都不能据此写成已经发布。参考 [编码执行状态投影 ↗](../../../apps/server/src/assistant/followup-state.ts#L60 "支持运行阶段、错误、应用状态、检查结果和结果材料的映射及缺省值。")

<a id="storage_and_reading"></a>
## 后续阶段如何读取并判断状态

捕获结果由实际事项和编码执行记录组成，写入带稳定外部标识的材料，再以执行状态的角色挂接到对应页面。材料正文明确区分几类容易混淆的状态：等待表示仍在等待，下一检查时间不是截止日期，检查结果只证明所列命令及受检版本，已经应用也不代表正式发布。已有事项继续沿用原编号和版本，不能重复创建。参考 [状态材料保存与挂接 ↗](../../../apps/server/src/assistant/followup-state.ts#L83 "支持材料正文中的状态边界、来源属性、稳定外部标识和页面输入挂接流程。")

读取入口只选择这类执行状态材料。没有匹配材料时不会注册读取工具；存在材料时，工具以只读方式返回材料标识、版本、正文和完整行号范围。生成阶段和独立复核因此可以读取同一份固定输入，无需重新查询随时可能变化的执行状态。参考 [固定状态的只读入口 ↗](../../../apps/server/src/assistant/followup-state.ts#L115 "支持执行状态材料的筛选、缺省行为、只读属性和返回字段。")
