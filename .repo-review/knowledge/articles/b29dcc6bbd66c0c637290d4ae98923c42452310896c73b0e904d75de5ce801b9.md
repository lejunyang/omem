# 统一按钮的状态、语义与视觉样式

OmButton 是一个轻量 Vue 3 按钮组件，统一普通、主要和弱化操作的外观，并把加载状态转换为原生禁用与无障碍语义。组件保留默认插槽承载按钮内容，但未在本文件中封装点击事件、焦点样式或完整加载提示。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-api"></a>
## 解决重复按钮实现的问题

`OmButton` 为页面提供一致的按钮入口：调用方通过 `variant` 选择主要、次要或幽灵样式，通过 `type` 决定普通按钮还是表单提交按钮。默认采用 `secondary` 和 `button`，可避免按钮放进表单后意外触发提交；按钮文字或其他内容则由默认插槽传入。参考 [按钮属性与默认值 ↗](../../../packages/ui/src/components/OmButton.vue#L2 "支持组件提供的变体、加载、禁用和按钮类型接口，以及 secondary、button 两项默认行为。")

组件只定义展示与状态属性，没有在这里声明点击事件或业务动作，因此业务模块仍需在使用处绑定事件。当前材料也没有展示具体调用方，无法据此确认它被哪些页面使用。

<a id="state-flow"></a>
## 加载与禁用状态如何生效

加载状态同时影响交互和辅助技术：当 `loading` 或 `disabled` 任一为真时，原生 `button` 会被禁用；`aria-busy` 向辅助技术声明操作正忙。加载时会在插槽内容前显示一个旋转符号式占位字符，该字符通过 `aria-hidden` 避免被单独朗读，而原有插槽内容仍然保留。参考 [按钮状态与插槽渲染 ↗](../../../packages/ui/src/components/OmButton.vue#L13 "支持加载或禁用时设置原生 disabled、声明 aria-busy，并在保留插槽内容的同时显示隐藏于辅助技术的加载符号。")

这意味着组件依赖浏览器原生禁用行为阻止点击和表单提交，没有实现取消、进度百分比或加载文案替换等更复杂流程。

<a id="visual-boundaries"></a>
## 视觉层级与现有边界

基础样式使用行内弹性布局、8 像素间距和至少 44 像素高度，使图标与文字居中并保留较稳定的点击区域；颜色、边框和面板背景依赖 `--om-line`、`--om-panel`、`--om-ink` 等外部 CSS 变量，因此完整视觉效果取决于上层主题是否定义这些变量。参考 [基础尺寸与主题变量 ↗](../../../packages/ui/src/components/OmButton.vue#L24 "支持组件的布局、最小高度、间距以及对外部 CSS 主题变量的依赖。")

`primary` 使用深色底和白字，`ghost` 去除背景与边框；`secondary` 没有独立规则，实际沿用基础样式。文件只提供普通悬停效果，没有显式的禁用、加载、键盘焦点或旋转动画样式，所以禁用按钮仍可能匹配悬停背景，加载符号也只是静态字符。参考 [按钮变体与悬停样式 ↗](../../../packages/ui/src/components/OmButton.vue#L37 "支持主要按钮、幽灵按钮和通用悬停效果的说明，也表明此处没有 secondary 专属规则及状态化悬停处理。")
