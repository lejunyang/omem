# 通用按钮组件

提供统一的按钮外观、原生类型与加载禁用行为，是对话框等上层界面的基础交互控件。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 作用与接口

组件把原生按钮封装为 primary、secondary、ghost 三种视觉变体；默认使用 secondary，并把 HTML 类型默认设为 button，降低按钮位于表单中时意外提交的风险。调用方仍可显式选择 submit，并通过默认插槽提供按钮内容。[按钮属性与默认值 ↗](../../../packages/ui/src/components/OmButton.vue#L1 "支持按钮变体、加载与禁用属性，以及默认使用 button、允许显式 submit 的接口说明。") 基础样式统一最小高度、间距、边框和颜色，primary 与 ghost 仅覆盖部分视觉属性，因此它主要承担共享设计原语，而不包含具体业务动作。[按钮基础与变体样式 ↗](../../../packages/ui/src/components/OmButton.vue#L23 "支持组件统一基础尺寸和颜色，并通过 primary、ghost 类覆盖视觉表现的论断。")

<a id="state"></a>
## 状态流程与边界

loading 为真时，组件设置 disabled 与 aria-busy，并在插槽内容前显示一个对辅助技术隐藏的“◌”占位字符；显式 disabled 或 loading 任一成立都会阻止交互。[加载与禁用渲染 ↗](../../../packages/ui/src/components/OmButton.vue#L12 "说明 loading 如何联动 disabled、aria-busy，并渲染无动画定义的占位字符。") 材料没有为该字符定义旋转动画，也没有自动生成状态文案或可访问名称；这些仍依赖插槽文字或调用方传入的 aria-label。组件也不支持 reset 类型。OmDialog 的关闭操作复用了 ghost 按钮和图标，表明按钮合同被上层弹窗交互直接依赖。[对话框关闭按钮 ↗](../../../packages/ui/src/components/OmDialog.vue#L43 "证明上层 OmDialog 使用 ghost 变体的 OmButton 承载关闭全部操作，并由调用方提供可访问名称。")
