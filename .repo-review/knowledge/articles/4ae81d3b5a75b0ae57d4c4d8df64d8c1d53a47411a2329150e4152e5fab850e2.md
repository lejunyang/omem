# 记忆提案治理与反馈服务

围绕提案持久化、证据校验、知识匹配、策略裁决、人工决定和不可变修订应用构成记忆治理主流程，并附带反馈约束的记录与召回。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="proposal-evidence"></a>
## 提案持久化与证据约束

`MemoryService` 以 Store 的 SQLite 连接和事务能力为基础。提案先按稳定摘要去重：同一提案 ID 对应不同摘要会报冲突，同工作区相同摘要则复用已有记录；写入时还保存证据读取对应的来源版本与 validity epoch。[提案去重与来源读取快照 ↗](../../../apps/server/src/memory/service.ts#L135 "支持稳定摘要去重、冲突检测及记录来源版本和有效性纪元的流程。") 证据校验逐条确认 fragment、source revision、精确引文的 Unicode 码点区间，或图片资产是否同时存在于修订和资产存储中，最终给出 valid、invalid 或 ambiguous。[确定性证据校验 ↗](../../../apps/server/src/memory/service.ts#L201 "支持文本区间、来源修订及图片资产校验和三态 verdict 的说明。") 后续应用与决定前会重新比较来源 head 和 epoch，变化即视为陈旧决定。[来源新鲜度检查 ↗](../../../apps/server/src/memory/service.ts#L255 "说明通过 head 与 validity epoch 防止依据过期来源执行决定。")

<a id="matching-policy"></a>
## 知识匹配与自动治理

创建 claim 前只召回同工作区、同项目的活跃 claim。规范化陈述完全相同时，共享来源记为重复，独立来源记为等价；只有评估明确标为冲突时，才以实体词重叠、相反谓词极性和有效期重叠选择冲突对象，并返回双方证据链。该方法是确定性启发式，不是完整语义推理。[创建 claim 的知识匹配 ↗](../../../apps/server/src/memory/service.ts#L417 "支持同域候选过滤、重复与等价区分，以及冲突候选选择和证据链生成。") 策略层把无效证据或被语义评估否定的提案拒绝，把噪声忽略；跨源冲突仅在覆盖活跃知识或阻塞当前任务时升级，图片推断、procedure、未验证任务归属等通常只保留或延后。满足条件且未超影响预算时才自动应用。[AttentionGate 策略 ↗](../../../apps/server/src/memory/service.ts#L704 "支持拒绝、忽略、延后、保留、请求决定与自动应用等治理分支。")

<a id="application-decisions"></a>
## 应用、人工决定与批处理

实际应用通过 Store 的 application 接口生成任务或记忆修订，并在前置钩子检查来源仍为当前版本；procedure 必须得到所有者批准，不能直接自动应用。[任务与记忆应用 ↗](../../../apps/server/src/memory/service.ts#L1141 "支持通过 Store 应用实体、执行前置新鲜度检查，以及 procedure 的审批限制。") 需要人工确认时，决定记录绑定提案摘要、操作者、过期时间和预期版本；审批接口校验摘要、身份、幂等 requestId、状态及期限，来源变旧会同时把决定和提案标记为 stale。[人工决定处理 ↗](../../../apps/server/src/memory/service.ts#L1660 "支持决定的摘要、操作者、幂等、过期与陈旧来源校验，以及批准后的应用流程。") 批处理先对受影响记忆集合与新实体键集合去重求并集；超过预算时，原本可自动应用的项目全部停放，只创建一个汇总确认，避免把大变更拆成多个低影响操作绕过预算。[批量影响门控 ↗](../../../apps/server/src/memory/service.ts#L1405 "支持按去重并集计算整体影响，并在超预算时统一停放和汇总确认。")

<a id="feedback"></a>
## 反馈约束与限制

`FeedbackService` 以工作区、生产者和事件 ID 保证反馈幂等，同键不同载荷会报冲突。只有身份已验证、来源为 original、且全部证据存在的非弱反馈，才可能成为 active confirmed 约束；权限、预算、自动批准等受保护策略始终进入 shadow。[反馈可信度分级 ↗](../../../apps/server/src/memory/service.ts#L1869 "支持反馈幂等、证据与身份检查，以及 confirmed、weak、shadow 强度划分。") 当前自动改写只覆盖 task 的 `task_assignment`：按 scope 召回 confirmed 约束并替换 owner；其他提案类型直接原样返回。[确认约束应用 ↗](../../../apps/server/src/memory/service.ts#L1957 "支持当前仅对任务所有者分配约束执行自动改写的边界说明。") 因而反馈不是任意策略自学习机制，也没有从本材料看出冲突约束的排序、撤销或合并规则。
