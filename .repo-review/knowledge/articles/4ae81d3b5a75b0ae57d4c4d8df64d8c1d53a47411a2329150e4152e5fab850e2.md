# 记忆提案治理、应用与反馈服务

该文件是记忆与任务变更的治理中枢：持久化并验证提案，复查固定证据及时效，匹配重复、等价和冲突知识，控制批量影响，再委托 Store 应用修订；同时处理人工决定、任务命令、历史恢复与反馈约束。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="proposal_pipeline"></a>
## 提案验证与策略分流

`MemoryService.evaluate` 解析提案和评估输入，持久化提案并优先复用已有应用回执；没有回执时，依次执行确定性证据校验、评估留档、知识匹配或通用策略分流。代码本身不证明提案一定由模型产生，也不证明评估必由独立复核者完成。[单提案评估主流程 ↗](../../../apps/server/src/memory/service.ts#L1282 "支持提案解析、持久化、回执复用、证据评估以及匹配或策略分流的执行顺序。")

提案读取来源时保存 source revision 与 validity epoch，应用或决定前再读取当前 head 和 epoch；任一变化都会拒绝陈旧结果。文本证据还校验 fragment、字符范围和精确引用，图片证据校验资产。[证据校验与来源时效复查 ↗](../../../apps/server/src/memory/service.ts#L170 "支持保存 source revision 和 validity epoch、校验精确引用，并在后续与当前 head、epoch 比较。") 这替代了“持久化时保存来源 head”的旧结论。通用策略会拒绝无效证据或语义反驳，并将噪声、软不确定性、图片推断、procedure、未验证任务归属及非关键跨来源变化分别忽略、延后或仅保留为来源。[通用策略与注意力门控 ↗](../../../apps/server/src/memory/service.ts#L739 "支持无效输入拒绝以及噪声、不确定性、图片、procedure、任务归属和跨来源变化的分流规则。")

<a id="matching_batch"></a>
## 知识匹配与批量影响控制

有效的新建 claim 会先在同 workspace、同 project 的活跃知识中匹配。规范化陈述相同且来源重叠视为 duplicate，独立来源得出同一陈述视为 equivalent；只有评估明确标记 `contradicts_existing` 时，才结合实体词重叠、相反谓词极性及有效期交集选择冲突对象。[新建知识匹配规则 ↗](../../../apps/server/src/memory/service.ts#L452 "支持作用域过滤、重复与等价判定，以及冲突匹配所需的理由码、词项、极性和有效期条件。") 冲突不会自动覆盖既有知识；争议表保存双方陈述、关联对象和 source id 集合，但未保存返回值中的完整 fragment 证据链与匹配理由。[争议记录持久化 ↗](../../../apps/server/src/memory/service.ts#L632 "支持争议表实际保存双方陈述、关联对象和 source id 集合，并揭示未持久化的返回字段。") duplicate 不生成新记忆或回执，proposal 状态改为 `retained`，返回策略仍为 `auto_apply`；equivalent 在预算内会生成独立记忆并登记等价关系。[重复、等价与冲突的处理结果 ↗](../../../apps/server/src/memory/service.ts#L1599 "支持三类匹配的不同策略、状态、应用行为和等价关系记录。")

批量门控以受影响记忆和新实体的去重并集计算总影响；超过预算时，原本会物化状态的提案被统一停放，只有确有停放项才创建一个批量决定。[批量影响计算与停放 ↗](../../../apps/server/src/memory/service.ts#L1442 "支持按去重并集计算批量影响、统一门控、收集停放项并仅在需要时创建批量决定。") 批量卡保存全部停放提案的 `batchProposalDigests`、聚合后的证据引用、至多前三个 topic 的展示文本，并以代表提案的 digest 和 expected versions 锚定决定。[批量确认事项的实际字段 ↗](../../../apps/server/src/memory/service.ts#L1522 "支持批量卡保存所有提案 digest、聚合证据引用、有限 topic 展示及代表提案锚点，纠正“保存全部摘要”的旧表述。") 这替代了“批量卡保存全部提案摘要”的旧结论：材料未显示其保存每份提案正文、完整摘要或全部 topic。

<a id="application_decision"></a>
## 应用边界、人工决定与任务命令

`apply` 在写入前通过 hooks 复查来源时效和待决状态，再把 hooks 传给 Store 的任务或记忆应用接口；after hook 更新 proposal 状态，并在人工批准场景更新决定状态。所给文件没有展示 Store 内部事务实现，因此不能仅据此断言实体写入、proposal 更新与 decision 更新必然处于同一原子事务。procedure 只有经所有者批准才允许应用。[记忆与任务的应用边界 ↗](../../../apps/server/src/memory/service.ts#L1176 "支持应用前复查、Store 应用调用、after hook 的状态更新及 procedure 的所有者批准限制；同时表明此文件仅传递 hooks，不能单独证明 Store 内部原子事务范围。") 提案及应用身份使用稳定摘要：对象键递归排序、忽略值为 `undefined` 的字段，再对规范 JSON 计算 SHA-256。[稳定摘要实现 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持递归排序对象键、忽略 undefined 并对规范 JSON 计算 SHA-256。")

`decide` 校验 digest、actor、requestId、期限和来源时效；重复请求可幂等返回，来源变化会把决定及锚定提案标为 stale。批准路径只按决定行的 `proposal_digest` 重建并应用一个代表提案，未遍历批量卡中的其余 `batchProposalDigests`。[人工决定处理 ↗](../../../apps/server/src/memory/service.ts#L1697 "支持决定的身份、幂等、期限及时效校验，并表明批准只应用决定行锚定的单个提案。")

显式任务命令要求证据来自经验证的所有者原始材料，并限制已完成或取消事项直接进入等待、稍后提醒或改期。[所有者任务命令 ↗](../../../apps/server/src/memory/service.ts#L86 "支持所有者证据要求、任务状态限制、跟进校验及统一任务应用调用。") 等待对象和时间原始表达必须出现在当前用户文本中，之后才规范化时间；任务状态、动作及 follow-up 字段由共享合同约束。[跟进内容校验 ↗](../../../apps/server/src/tasks/follow-up.ts#L5 "支持等待对象和时间原始表达必须来自当前用户文本，并在校验后规范化时间。")[共享任务流合同 ↗](../../../packages/contracts/src/task-flow.ts#L3 "支持任务状态、动作及 follow-up 字段和时区约束由共享合同定义。")

<a id="recovery_feedback"></a>
## 恢复、反馈学习与存储边界

历史恢复要求当前版本匹配、目标修订存在且依赖未 stale，并通过记忆应用接口创建新的活跃修订，而不是覆盖旧历史；事务前置检查还会再次确认依赖状态。[历史记忆恢复 ↗](../../../apps/server/src/memory/service.ts#L1789 "支持版本与依赖检查，以及通过应用接口生成新修订而保留历史。")

`FeedbackService` 在 Store 事务中按事件幂等记录反馈。`useful` 与 `outcome` 固定降为 weak signal；受保护策略或 `policy_suggestion` 进入 shadow；只有身份已验证、来源为 original、证据有效且并非弱反馈时才形成 confirmed 约束。目前自动应用 confirmed 修正仅处理任务 owner 的替换。[反馈约束记录与应用 ↗](../../../apps/server/src/memory/service.ts#L1906 "支持反馈幂等、强度分级、反馈与约束分表保存，以及当前只自动修改任务 owner。")

服务通过 Store 访问共享数据库和事务入口，但治理数据并不都成为记忆或任务修订：反馈及其约束分别保存在 `feedback`、`feedback_constraints`，争议、评估、策略和决定也有各自记录；只有实际调用 `applyMemory` 或 `applyTask` 的变更进入相应修订与应用链。[Store 数据库与应用接口边界 ↗](../../../apps/server/src/memory/service.ts#L119 "支持服务通过 Store 使用数据库和事务入口；结合各治理表写入及 applyMemory、applyTask 调用，限定只有被实际应用的变更进入记忆或任务修订链。") 这替代了“所有治理结果最终都落入统一记忆或任务修订链”的过宽结论。
