# 受边界约束的多来源捕获连接器

该模块为本地文件、Git 固定版本文件、飞书文档和 Agent Hook 事件构造 CaptureInput。各入口具有不同的读取、校验和来源记录边界；它们仅在 TypeScript 返回类型与对象字段上呈现共同形状，现有材料不能证明返回后必然经过 captureSchema 的运行时校验，因此超长文本的最终处置仍待确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 入口职责与静态输出形状

连接器执行显式、有限的材料读取：本地文件受配置根目录约束，捕获文本中的 URL 只被保留而不会自动爬取。文件、Git、飞书和 Hook 均构造带来源、标题、分片与上下文的 `CaptureInput` 形状，并分别补充版本、原文链接或事件来源信息。[连接器读取原则与文件返回对象 ↗](../../../apps/server/src/connectors.ts#L1 "支持显式有限读取、URL 不自动爬取、文件根目录约束以及文件入口构造 CaptureInput 形状的说明。")[固定版本的 Git 文件读取 ↗](../../../apps/server/src/connectors.ts#L36 "支持 Git 参数校验、提交解析、按 SHA 读取、500000 字节缓冲和直接构造文本分片的说明。")[飞书捕获内容组装 ↗](../../../apps/server/src/connectors.ts#L113 "支持正文、原文链接、引用映射侧车和标题组成返回对象，并说明正文未经本函数内 schema 解析即进入文本分片。")[Hook 事件身份与来源记录 ↗](../../../apps/server/src/connectors.ts#L196 "支持外部事件 ID、回退哈希、时间规范化以及 CaptureInput 与 provenance 的构造流程。")

这里的“共同形状”仅由返回类型与对象构造直接支持，不能等同于已经满足公共捕获合同的运行时校验。合同中的文本分片上限是 20 万字符，但材料未显示这些连接器调用 `captureSchema`；文件、Git 与飞书自身采用的规模边界也不等于该字符上限。[公共文本分片合同 ↗](../../../packages/contracts/src/index.ts#L20 "支持公共 textPart 的 20 万字符上限，并用于区分 schema 约束与连接器自身限制。")[本地文件安全读取 ↗](../../../apps/server/src/connectors.ts#L10 "支持真实路径根目录校验、500000 字节限制、严格 UTF-8 解码、NUL 检查及直接返回文本的流程。")[固定版本的 Git 文件读取 ↗](../../../apps/server/src/connectors.ts#L36 "支持 Git 参数校验、提交解析、按 SHA 读取、500000 字节缓冲和直接构造文本分片的说明。")[飞书地址校验与 CLI 调用 ↗](../../../apps/server/src/connectors.ts#L76 "支持飞书 URL 白名单、外部 CLI 调用、60 秒超时、2 MB 输出缓冲和响应正文检查。")

<a id="file-git-flow"></a>
## 文件与 Git 的确定性读取

文件入口先解析目标和允许根目录的真实路径，再通过相对路径判断归属，以限制普通越界与符号链接绕行；随后检查 500000 字节上限，使用严格 UTF-8 解码，并拒绝含 NUL 的内容。[本地文件安全读取 ↗](../../../apps/server/src/connectors.ts#L10 "支持真实路径根目录校验、500000 字节限制、严格 UTF-8 解码、NUL 检查及直接返回文本的流程。") 这仍不保证文本一定少于合同规定的 20 万字符，因为这里限制的是字节数，且返回前没有展示 schema 解析。[公共文本分片合同 ↗](../../../packages/contracts/src/index.ts#L20 "支持公共 textPart 的 20 万字符上限，并用于区分 schema 约束与连接器自身限制。")[本地文件安全读取 ↗](../../../apps/server/src/connectors.ts#L10 "支持真实路径根目录校验、500000 字节限制、严格 UTF-8 解码、NUL 检查及直接返回文本的流程。")

Git 入口复用仓库根目录校验，拒绝危险的 ref 与仓库内路径；它先把 ref 解析成提交 SHA，再从该提交读取目标路径，并把 SHA 保存为上游版本。[固定版本的 Git 文件读取 ↗](../../../apps/server/src/connectors.ts#L36 "支持 Git 参数校验、提交解析、按 SHA 读取、500000 字节缓冲和直接构造文本分片的说明。") 需要保留更正：此路径未显式进行严格 UTF-8、NUL 或文本性质检查，500000 字节的子进程缓冲也可能容纳超过 20 万字符的输出。

<a id="lark-flow"></a>
## 飞书文档与引用侧车

飞书入口仅接受 HTTPS 的 docx/wiki 地址，并把主机限制在飞书、Lark 及其子域；随后调用外部 CLI 获取 Markdown 与节点 ID 明细，检查成功标志和正文是否存在。调用受 60 秒超时与 2 MB 输出缓冲约束，但该缓冲限制并非正文字符合同。[飞书地址校验与 CLI 调用 ↗](../../../apps/server/src/connectors.ts#L76 "支持飞书 URL 白名单、外部 CLI 调用、60 秒超时、2 MB 输出缓冲和响应正文检查。")

返回结果包含正文、原文链接及可选引用映射；引用映射作为来源上下文文本保存，不作为可执行标记或自动推断链接。标题来自 title 标签、首行或默认名称。[飞书捕获内容组装 ↗](../../../apps/server/src/connectors.ts#L113 "支持正文、原文链接、引用映射侧车和标题组成返回对象，并说明正文未经本函数内 schema 解析即进入文本分片。") 由于正文直接放入 text part，现有材料无法确认超过 20 万字符时是在下游被拒绝，还是继续以未校验对象流转。[公共文本分片合同 ↗](../../../packages/contracts/src/index.ts#L20 "支持公共 textPart 的 20 万字符上限，并用于区分 schema 约束与连接器自身限制。")[飞书捕获内容组装 ↗](../../../apps/server/src/connectors.ts#L113 "支持正文、原文链接、引用映射侧车和标题组成返回对象，并说明正文未经本函数内 schema 解析即进入文本分片。")

<a id="hook-flow"></a>
## Hook 字段收敛、脱敏与事件身份

Hook 按 profile 从会话、轮次、工具、提示、输入、响应和错误中选择顶层字段；被选中的嵌套对象不会再按键名过滤。序列化只替换字符串中符合长度条件的 `sk-` 与 `ghp_` 形式，并按 profile 检查总字符数；默认预算恰为 20 万字符，但自定义 profile 可改变该值，因此仍不能据此断言公共合同已执行。[Hook 字段选择与字符预算 ↗](../../../apps/server/src/connectors.ts#L137 "支持顶层字段白名单、有限令牌格式脱敏、嵌套值保留及可配置总字符预算的结论。")[公共文本分片合同 ↗](../../../packages/contracts/src/index.ts#L20 "支持公共 textPart 的 20 万字符上限，并用于区分 schema 约束与连接器自身限制。")

事件优先使用外部事件 ID，否则结合会话、工具、事件名与正文摘要生成哈希；有效时间会被规范化，并连同采集器、主体、事件和生产者信息写入 provenance。[Hook 事件身份与来源记录 ↗](../../../apps/server/src/connectors.ts#L196 "支持外部事件 ID、回退哈希、时间规范化以及 CaptureInput 与 provenance 的构造流程。")[捕获级来源合同 ↗](../../../packages/contracts/src/index.ts#L49 "说明 Hook provenance 字段与公共合同中的采集器、主体、事件、时间及生产者字段相对应。") 这表明字段能与公共来源合同对应，但对应关系本身不证明对象经过该合同解析。
