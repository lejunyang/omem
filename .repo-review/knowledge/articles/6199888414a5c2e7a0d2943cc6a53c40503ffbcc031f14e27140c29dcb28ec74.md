# 受边界约束的外部捕获连接器

将本地文件、Git 固定提交、飞书文档和 Agent Hook 事件规范化为统一 CaptureInput，并通过路径、大小、URL、字段和部分凭据脱敏限制捕获边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="local-inputs"></a>
## 文件与 Git 的固定读取

文件导入先解析真实路径，并要求目标位于配置的捕获根目录内，以防符号链接或相对路径绕过；随后限制为 500 KB，执行严格 UTF-8 解码并拒绝含空字节的内容。产物统一为文本 part，规范化后的路径同时作为外部身份。[本地文件导入边界 ↗](../../../apps/server/src/connectors.ts#L10 "支持真实路径必须位于配置根目录内，以及大小、UTF-8、空字节和统一文本输入等约束。")

Git 导入复用仓库根目录约束，但对 ref 与仓库路径采用不同规则：ref 使用保守字符白名单，并拒绝前导连字符和 `..`；路径则拒绝绝对路径、父目录段、冒号和前导连字符。它先把 ref 解析为 commit SHA，再以该 SHA 读取文件，因此记录的是固定来源版本。此表述取代此前笼统称“Git ref 与路径均采用保守字符规则”的结论。[Git 固定提交读取 ↗](../../../apps/server/src/connectors.ts#L36 "支持 ref 的字符白名单、仓库路径的独立拒绝条件，以及先解析 commit SHA 再读取文件的固定版本流程。")

<a id="lark"></a>
## 飞书文档读取

飞书连接器只接受 HTTPS、无内嵌用户凭据、路径格式受限且属于允许域名的 docx/wiki URL，再调用外部 `lark-cli` 获取带 ID 的 Markdown。正文和原文链接成为捕获 parts；可选 reference map 被序列化为标注“来源引用元信息”的文本 part，而 `context` 保持为空。[飞书文档连接器 ↗](../../../apps/server/src/connectors.ts#L76 "支持 URL 协议、路径及域名限制，外部 CLI 调用，以及正文、链接和 reference map 的 parts 组织方式。")

<a id="hooks"></a>
## Hook 字段选择与来源身份

Hook 捕获仅选择 profile 明确列出的会话、工具、提示、输入、响应和错误字段，未知扩展及隐藏转录不会自动纳入。字符串中的 `sk-`、`ghp_` 形态会被替换，序列化结果还受字符预算约束。[Hook 捕获字段与脱敏 ↗](../../../apps/server/src/connectors.ts#L137 "支持字段白名单、字符预算，以及仅针对 sk- 和 ghp_ 两类前缀的替换边界。")

事件身份优先采用显式 event ID；缺失时，由会话、轮次、工具调用、事件名称和内容摘要生成稳定身份。合法时间戳会被规范化，并连同采集器、转发状态和 producer kind 写入 provenance。[Hook 事件身份与来源 ↗](../../../apps/server/src/connectors.ts#L196 "支持显式事件 ID、摘要回退身份、时间规范化和 provenance 字段的构造流程。")

<a id="limits"></a>
## 已知边界

这些连接器执行显式、有限的读取，捕获文本中的普通 URL 只会保留而不会被自动抓取。[显式有限读取原则 ↗](../../../apps/server/src/connectors.ts#L1 "支持连接器不会自动爬取捕获文本中的 URL，并要求服务端文件导入受配置根目录约束。") 文件入口只接受有限大小的纯 UTF-8 文本；Git 路径检查并非通用字符白名单；飞书能力依赖外部 CLI 及其授权。Hook 当前替换式只覆盖两类密钥前缀，不能视为通用秘密扫描器。[Hook 捕获字段与脱敏 ↗](../../../apps/server/src/connectors.ts#L137 "支持字段白名单、字符预算，以及仅针对 sk- 和 ghp_ 两类前缀的替换边界。")
