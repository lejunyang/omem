# Botmux 既有 Lark 应用导入提供器

从经过基础结构、字段和大小校验的 Botmux JSON 文件发现可复用应用，并按应用标识向 onboarding 提供应用密钥、平台品牌及可选 owner 身份线索。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="source-validation"></a>
## 配置来源与输入校验

提供器用于复用 Botmux 保存的 Lark 应用。配置路径依次取构造参数、两个环境变量和用户目录下的默认文件；配置值会经 `resolve` 形成绝对路径。文件不存在时返回空集合，存在时必须是普通文件、大小不超过 5 MB且顶层为数组。每项应用标识必须符合 `cli_` 格式并具有非空密钥；同一标识若对应不同密钥会报凭据冲突，JSON 解析错误则向上传播。[Botmux 路径解析与文件校验 ↗](../../../apps/server/src/integrations/lark/existing-apps.ts#L26 "支持配置路径优先级、文件存在性、普通文件和大小限制、JSON 数组结构、应用标识与密钥校验以及凭据冲突处理。") 这些检查覆盖基础格式与冲突，但材料未显示文件权限、所有者或符号链接目标校验。

<a id="listing-credentials"></a>
## 应用展示与凭据交付

`list` 按应用标识去重，返回应用标识、名称、平台品牌和 Botmux 来源；名称缺失时用标识末六位生成回退名称，只有品牌值严格等于 `lark` 才归为 Lark，其余统一归为飞书。[可复用应用列表 ↗](../../../apps/server/src/integrations/lark/existing-apps.ts#L63 "说明列表按应用标识去重，并公开应用标识、名称、平台品牌和来源，以及名称与品牌的回退规则。") `credentials` 会再次读取配置并按应用标识查找，找不到时报错；找到后向接入流程返回 client ID、密钥、可选 owner open ID 和平台品牌。[既有应用凭据读取 ↗](../../../apps/server/src/integrations/lark/existing-apps.ts#L81 "说明凭据接口重新查找目标应用，并返回应用标识、密钥、可选 owner 身份线索和平台品牌。") onboarding 的导入分支确实调用该接口取得 Botmux 凭据，再进入统一的凭据接受流程。[Botmux 导入接入流程 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L124 "提供跨文件源代码依据，证明 onboarding 在 Botmux 导入模式下调用既有应用提供器获取凭据并交给统一接入流程。") 文件没有缓存，因此列表与凭据读取可能看到不同时间点的磁盘内容；其可信边界仍依赖部署环境对该配置文件的保护。
