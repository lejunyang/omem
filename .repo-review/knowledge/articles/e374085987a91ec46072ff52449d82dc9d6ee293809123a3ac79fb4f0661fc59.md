# 复用 Botmux 飞书应用配置

该模块把本机 Botmux 配置转换为可枚举、可提取凭据的飞书应用来源，并校验文件形态、应用标识与密钥冲突；它只负责本地配置适配，不执行应用注册、联网验证或持久化。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-contract"></a>
## 作用与模块合同

该文件解决已有 Botmux 飞书应用如何被 omem 复用的问题：`ExistingLarkAppProvider` 提供应用列表和按应用标识取得凭据两项能力；公开列表只包含名称、租户品牌与固定的 `botmux` 来源，不携带密钥。[现有应用提供者合同 ↗](../../../apps/server/src/integrations/lark/existing-apps.ts#L6 "支持模块用于枚举可复用应用、按标识取得凭据，以及列表对象不包含密钥的论断。")

实现通过类型导入复用注册模块的凭据合同，输出 `clientId`、`clientSecret` 和可选用户信息。现有材料没有实例化位置或调用链，因此不能断定这些凭据会跳过注册，还是进入另一条连接流程。[注册凭据类型合同 ↗](../../../apps/server/src/integrations/lark/registration.ts#L5 "说明该适配器输出与注册模块凭据结构之间的静态类型依赖，且不将其夸大为运行时调用。")

<a id="load-and-validate"></a>
## 配置定位、读取与校验

构造时依次采用显式参数、`OMEM_BOTMUX_CONFIG`、`BOTS_CONFIG` 或用户目录下的默认文件，并将路径解析为绝对路径。文件不存在时返回空集合；存在时必须是普通文件、不得超过 5 MB，且 JSON 顶层必须为数组。[Botmux 配置定位与文件约束 ↗](../../../apps/server/src/integrations/lark/existing-apps.ts#L29 "支持配置路径优先级、默认位置、文件不存在行为、文件大小限制和顶层数组校验。")

条目显式要求应用标识符合 `cli_` 格式、密钥为非空字符串；同一应用若出现不同密钥则拒绝整份配置。[应用条目与凭据冲突校验 ↗](../../../apps/server/src/integrations/lark/existing-apps.ts#L47 "支持应用标识、非空密钥和重复应用密钥冲突的显式校验，并准确区分 null 与其他 JSON 原始值在属性读取时的行为。") 此处替代旧结论：数组中的 `null` 会在读取 `entry.larkAppId` 时触发运行时 `TypeError`；字符串、数字或布尔值的属性读取通常得到 `undefined`，随后进入 `BOTMUX_CONFIG_INVALID`。损坏 JSON 则会传播解析异常。

<a id="projection-and-boundaries"></a>
## 列表投影、凭据查询与边界

列举应用时按应用标识去重并保留首项；名称缺失则以标识末六位生成回退名称，品牌仅在值严格等于 `lark` 时归为 Lark，其余统一归为飞书。[可复用应用列表映射 ↗](../../../apps/server/src/integrations/lark/existing-apps.ts#L63 "支持按应用标识去重、名称回退、租户品牌归一化和来源标记的流程说明。") 查询凭据时取首个匹配项，未找到则报 `BOTMUX_APP_NOT_FOUND`，并映射密钥、所有者 openId 与品牌。[按应用标识提取凭据 ↗](../../../apps/server/src/integrations/lark/existing-apps.ts#L81 "支持未找到应用时的错误行为，以及 clientId、clientSecret、openId 和品牌的返回映射。")

每次调用都会同步重读整个文件，没有缓存、锁或读取快照；模块也不验证密钥有效性、不访问网络。材料未包含调用层的异常映射与测试，因此并发改写、权限失败及异常条目的产品表现仍待确认。
