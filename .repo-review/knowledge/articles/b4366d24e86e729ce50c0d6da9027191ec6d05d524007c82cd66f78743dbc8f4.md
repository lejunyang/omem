# 记忆更新与历史保留的在线冒烟验证

该脚本通过真实 ACP 模型配置和临时 SQLite 存储，验证同一来源从“重试 3 次”更新为“重试 5 次”后，旧记忆会先失效，再以相同身份形成新版本，同时保留旧原文并记录刷新成功。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 验证什么问题

该脚本验证一个关键使用场景：用户已经形成的记忆所依赖的来源发生变化时，系统应更新现有记忆，而不是并存两条互相冲突的有效结论。它创建临时存储，组合 `Store`、记忆与反馈服务、学习流水线，并从 ACP 能力探测结果中选择运行配置；随后明确断言实际模型为 `gpt-5.6-sol`。参考 [在线流水线装配 ↗](../../../scripts/live-refresh-smoke.ts#L5 "支持脚本创建临时存储、装配学习相关服务并断言实际模型配置的说明。")

模型选择会优先采用环境变量指定的可用模型，否则尝试基础配置或 ACP 当前默认值；请求了不可用模型时直接报错。因此，这是一项依赖外部 Agent CLI/ACP 可用性的在线冒烟检查，不是完全隔离的单元测试。参考 [ACP 模型选择规则 ↗](../../../scripts/live-model.ts#L12 "解释在线检查如何从 ACP 暴露的选项中选择模型，以及不可用请求为何会失败。")

<a id="refresh-flow"></a>
## 从旧结论到新版本

脚本以相同外部来源标识捕获两次声明。第一次写入“重试上限是 3 次”，排空流水线后要求数据库中恰有一条有效记忆；第二次改为“5 次”，并在再次处理前断言旧记忆已进入 `invalidated` 状态。参考 [首次捕获与失效断言 ↗](../../../scripts/live-refresh-smoke.ts#L20 "支持首次生成有效记忆以及来源变化后旧记忆立即失效的流程描述。")

再次排空后，它要求记忆数量仍为一条、记忆 ID 不变、版本升至 2、状态恢复为 `active`，且新正文包含 5；与此同时，旧来源修订中的原始片段仍包含 3，刷新记录必须标记为 `applied`。这些断言共同覆盖了**身份续接、版本推进、旧证据保留和刷新落地**，但没有证明流水线内部每个抽取或复核步骤的具体实现。参考 [刷新应用与历史保留 ↗](../../../scripts/live-refresh-smoke.ts#L31 "支持相同记忆身份升级到版本 2、新正文生效、旧原文保留及刷新记录成功的断言。")

<a id="reporting-limits"></a>
## 结果留痕与覆盖边界

无论成功还是失败，脚本都会停止流水线，收集任务、刷新记录和提案，向配置数据目录写入 `verification/live-refresh.json`；失败时设置非零退出码。最后关闭数据库并递归删除临时工作目录，因此业务测试数据不会长期残留，而验证报告会保留供人工检查。参考 [验证报告与资源清理 ↗](../../../scripts/live-refresh-smoke.ts#L38 "支持失败退出、报告持久化、流水线停止以及临时目录清理的说明。")

现有断言只覆盖一次从 3 到 5 的顺序更新。它没有覆盖模型不可用、验证结果含糊或拒绝、连续多次刷新、并发捕获、报告写入失败等行为；`drain(8)` 中数字 8 的语义以及“独立复核”如何执行，也无法仅由该脚本确认。
