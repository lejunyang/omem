# 来源更新与记忆重核验冒烟验证

通过真实模型配置下的 LearningPipeline 验证同一来源由重试上限 3 更新为 5 后，旧记忆即时失效，经流水线处理后沿用原身份生成新版本，并保留旧原始证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-fixture"></a>
## 问题与测试夹具

脚本针对“新修订已捕获，但旧派生记忆是否及时失效并由新版本接续”的风险。它在临时 Store 中选择 `gpt-5.6-sol` profile，组装 LearningPipeline、MemoryService 与 FeedbackService；捕获函数以固定 externalId 和完整所有者 provenance 生成 Aurora 重试上限事实。[学习流水线与来源夹具 ↗](../../../scripts/live-refresh-smoke.ts#L10 "支持真实模型 profile、LearningPipeline 装配，以及同一来源两次捕获的身份和 provenance 设置。") 材料只能确认这些组件参与流水线，不能据此单独证明其内部角色必然相互独立。

<a id="refresh-flow"></a>
## 失效、处理与版本续接

首次捕获“上限 3 次”并经 LearningPipeline drain 后，数据库应只有一条 active memory；同一来源更新为“5 次”时，在第二次 drain 前原记忆立即变为 `invalidated`。[旧记忆即时失效 ↗](../../../scripts/live-refresh-smoke.ts#L24 "支持首次处理后存在一条有效记忆，并在来源更新后、再次处理前转为 invalidated。") 处理完成后，记忆数量仍为一、ID 不变、版本升至 2、状态恢复 active，正文包含 5；旧 source revision 的 fragment 仍含 3，且新 revision 对应的刷新记录为 `applied`。[版本续接与原文保留 ↗](../../../scripts/live-refresh-smoke.ts#L32 "支持处理后沿用记忆 ID、版本递增、正文更新、旧原文保留及刷新记录 applied。") 这些是可观察的成功结果，不足以断言内部具体提取和复核角色的独立性。

<a id="reporting-and-limits"></a>
## 诊断产物与覆盖边界

成功或失败后，脚本都会停止流水线，收集 jobs、refresh records 和 proposals，写入验证报告，并关闭及删除临时环境。[刷新诊断报告 ↗](../../../scripts/live-refresh-smoke.ts#L38 "支持收集任务、刷新记录与提案，写入报告并清理资源。") 覆盖范围限于单一来源、单一明确数值变化和成功处理路径；含糊冲突、模型失败、多个候选、批量预算、重启恢复及失败结果不得覆盖旧有效知识等语义尚未由该脚本证明。
