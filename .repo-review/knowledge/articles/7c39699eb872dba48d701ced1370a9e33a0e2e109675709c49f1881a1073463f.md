# 实时 ACP 模型配置选择

该脚本在实时检查前通过 ACP 获取模型配置项，再依次考虑环境变量、基础配置和 ACP 提供的回退值。它会拒绝不可用的显式模型请求，但不会重新验证 ACP 当前值，也未校验 effort 能力或在本层提供可触发的取消机制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 作用与模块关系

`selectLiveProfile` 接收基础 AgentProfile 与工作目录，调用服务端 agents 模块的 `acp` 获取能力探测结果，并用 `optionValues` 解释配置项；它负责运行前的配置选择，而不是执行模型推理。其 AgentProfile 类型来自 contracts 包，但给定范围没有展示该类型定义，因此不能据此推断全部字段约束。[实时配置选择入口与依赖 ↗](../../../scripts/live-model.ts#L1 "支持函数参数、AgentProfile 类型来源，以及对 acp 和 optionValues 的依赖关系。")

<a id="selection-flow"></a>
## 模型发现与选择流程

函数在探测结果中查找 id 为 `model` 且类型为 `select` 的配置项；ACP 未公开可选模型时立即报错，随后将选项转换为候选模型值。[ACP 模型配置发现 ↗](../../../scripts/live-model.ts#L12 "支持查找 model 选择项、拒绝缺失或错误类型配置并提取候选值的流程。") 选择顺序为：显式 `OMEM_LIVE_MODEL`、仍在候选集内的 `base.model`、ACP 的 `currentValue`，最后是首个候选；显式请求不可用或最终无模型都会失败。[模型选择优先级与错误处理 ↗](../../../scripts/live-model.ts#L20 "支持环境变量、基础模型、ACP 当前值和首个候选的选择次序，以及无结果和显式请求不可用时的错误分支。") `currentValue` 仅作为回退来源，代码没有再次确认它属于候选集；此前“最终模型均已验证”的结论由这一更精确的描述替代。

<a id="boundaries"></a>
## 输出与当前边界

成功后函数返回原始 `probe` 与更新后的 profile：保留基础字段、写入所选模型，并用 `OMEM_LIVE_EFFORT` 覆盖 effort。环境变量未设置时，基础 effort 可能被改为 `undefined`，当前材料也未显示 effort 支持范围校验。[探测结果与 Profile 输出 ↗](../../../scripts/live-model.ts#L29 "支持返回 probe、保留基础 profile，并覆盖 model 与 effort 的实际行为。") 探测使用函数内部新建但不会在本层主动触发的 AbortSignal，因此接口本身没有外部取消或超时参数。[探测调用的取消信号 ↗](../../../scripts/live-model.ts#L4 "支持函数向 acp 传入内部新建的 AbortSignal，且自身没有接收外部超时或取消参数。") agents 模块会过滤传给子进程的环境变量，再按 profile 命令启动进程；独立进程组只在非 Windows 平台启用。该材料仅证明通用启动机制，不能确定 `acp` 的完整调用、清理及错误传播关系。[Agent CLI 环境过滤与跨平台启动 ↗](../../../apps/server/src/agents.ts#L32 "支持 agents 模块过滤敏感或内部环境变量、按 profile 命令启动外部进程，以及仅在非 Windows 平台启用独立进程组的论断。")
