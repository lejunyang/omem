# 可追溯 Agent 的受控运行与证据边界

agent-runtime 以版本化角色包、固定证据、结构化合同和运行追踪约束模型执行，并把会话理解、知识生成、代码分析、规划和独立复核拆为专职角色。部分确定性校验和持久任务衔接已有实现依据，但完整角色编排、语义复核、崩溃恢复及视觉能力校验仍需真实运行材料确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

模型既要从对话、文档、图片和代码中形成可用知识，又不能把历史计划、材料中的指令或自身推断当成事实。agent-runtime 因而把角色说明、技能、输出合同、工具策略、会话隔离和资源预算固化为版本化角色包，并在提示中区分可信来源元数据与不可信材料正文。参考 [角色运行与审计链 ↗](9cd3e2947013942d4f294ddb825ed1a6473e47a3e93a76181869089723b74456.md#execution "支持角色包、信任分层、预算执行、结果校验、有限修复和运行追踪构成受控运行链。")

专职角色分别承担会话语境保真、记忆候选提取、知识撰写、代码快照解释、任务规划与独立复核；它们共享“固定证据进入、结构化结果输出”的原则，但现有子知识没有证明所有角色已按固定顺序自动编排。参考 [会话与记忆角色边界 ↗](d15afa4015ffb950edb1654b7cff09246dc02b90d12c285af86c4565b1fda39a.md#role-boundaries "支持会话分析、记忆候选提取和反馈纠正的专职职责，以及尚未证明固定编排的限制。") [知识角色职责分工 ↗](3b1542b125303d63624c852b41e8f275ecaed4900dddfdeab69c561a56893450.md#purpose "支持知识规划、刷新、撰写和独立复核按职责拆分，且当前证据不足以证明完整自动流水线。")

<a id="execution"></a>
## 从固定材料到可审计结果

```mermaid
flowchart LR
  E[固定材料或代码快照] --> B[加载并校验角色包]
  B --> P[组装可信配置与不可信材料]
  P --> M[受预算约束的模型运行]
  M --> V[结构与引用校验]
  V --> T[保存结果与运行追踪]
  V -.独立判断支持性.-> R[复核角色]
```

角色加载会检查资产路径、清单、Schema 与技能摘要；执行前合并预算、核对传输能力并限制输入输出，成功后记录角色包、提示、上下文、技能、工具及模型配置摘要。结构错误只在规定次数内修复。参考 [角色运行与审计链 ↗](9cd3e2947013942d4f294ddb825ed1a6473e47a3e93a76181869089723b74456.md#execution "支持角色包、信任分层、预算执行、结果校验、有限修复和运行追踪构成受控运行链。")

知识角色用内联引用和问题清单保留论断与依据的联系；代码理解还以固定文件、符号、关系和证据快照校验引用，未知标识或越界选择器会被拒绝。无模型时只能生成机械事实 seed，不能冒充分析结论。参考 [生成与复核边界 ↗](719cf0f877f8c4ad3ac5731c246ab34e43d642cde39cd8bd9001951a63dd8a6e.md#role-flow "支持固定材料到结构化知识提案、独立证据评估的职责分层及其尚未完全接线的边界。") [代码引用确定性校验 ↗](719cf0f877f8c4ad3ac5731c246ab34e43d642cde39cd8bd9001951a63dd8a6e.md#code-validation "支持固定代码快照、角色资产校验、摘要封印和引用越界拒绝等确定性防线。")

<a id="roles_and_jobs"></a>
## 角色分工与持久任务协作

知识维护侧把材料分析、章节规划、文章撰写或刷新以及独立复核分开，使历史状态识别、面向读者的组织和发布判断采用不同视角。代码侧则提供仓库画像、模块架构、符号解释与关系核验，并要求把快照事实、解释和未知项明确区分。参考 [知识角色职责分工 ↗](3b1542b125303d63624c852b41e8f275ecaed4900dddfdeab69c561a56893450.md#purpose "支持知识规划、刷新、撰写和独立复核按职责拆分，且当前证据不足以证明完整自动流水线。") [代码理解角色体系 ↗](47f029fe2df4e4d9cb68836b244dd4d17e1ae1cbc5b16794c9cb685640ee2c30.md#evidence_flow "支持仓库、模块、符号和关系等代码理解职责，以及事实、解释和未知项的区分。")

任务处理器按任务构造上下文、调用运行网关并保存结构化输出；Worker 通过租约、心跳和失败分类维持持久执行。输出保存与任务成功更新目前是两个事务，因此具备追踪能力的同时，也留下进程在两步之间退出时的恢复窗口。参考 [任务与输出持久化 ↗](9cd3e2947013942d4f294ddb825ed1a6473e47a3e93a76181869089723b74456.md#jobs-and-persistence "支持任务处理器、Worker 租约及输出保存与任务完成分事务所产生的恢复窗口。")

<a id="progress_limits"></a>
## 当前进展与限制

已能确认的实现包括角色资产安全加载、提示信任分层、预算合并、有限修复、运行指纹、任务租约，以及代码快照与引用的确定性校验。预算中的令牌量按 UTF-8 字节除以 3 再增加 25% 余量估算，并非模型专用 tokenizer；数值合法也不代表组合一定适合具体模型。参考 [令牌预算估算 ↗](../../../apps/server/src/agent-runtime/budget.ts#L1 "直接支持预算采用 UTF-8 近似估算、增加余量，以及预算字段数值校验的能力边界。")

仍不能仅凭现有材料确认生成、独立语义复核和发布已形成强制端到端闭环，也不能确认崩溃重领会复用已保存输出。运行时权限或信息请求的并发决议、CLI 最终模型配置、视觉模型的图片能力，以及若干宽松合同字段的宿主级交叉校验，也需要调用方代码、行为测试或真实 trace 补证。参考 [角色运行与审计链 ↗](9cd3e2947013942d4f294ddb825ed1a6473e47a3e93a76181869089723b74456.md#execution "支持角色包、信任分层、预算执行、结果校验、有限修复和运行追踪构成受控运行链。") [生成与复核边界 ↗](719cf0f877f8c4ad3ac5731c246ab34e43d642cde39cd8bd9001951a63dd8a6e.md#role-flow "支持固定材料到结构化知识提案、独立证据评估的职责分层及其尚未完全接线的边界。") [任务与输出持久化 ↗](9cd3e2947013942d4f294ddb825ed1a6473e47a3e93a76181869089723b74456.md#jobs-and-persistence "支持任务处理器、Worker 租约及输出保存与任务完成分事务所产生的恢复窗口。")
