# 文件与 Git 输入连接器安全测试

验证文件连接器仅读取允许根内的普通文本，并验证 Git 连接器固定读取指定 revision 而非未提交工作区内容。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="file_input"></a>
## 文件输入边界

文件连接器读取配置根目录内的普通文本并生成 text part；指向根外文件的符号链接被拒绝，含 NUL 的内容被视为二进制并失败。[允许根与文件类型限制 ↗](../../../apps/server/tests/connectors.test.ts#L9 "支持根内普通文本成功、逃逸符号链接失败和二进制内容失败。") 该用例证明普通文本成功路径、real-path 边界和二进制拒绝，但没有构造超大文本，因此不能证明大小上限。编码异常、权限错误、符号链接竞态和多个允许根重叠也未覆盖。

<a id="git_input"></a>
## 固定 Git revision 读取

Git 用例先提交 `committed`，再将工作区改为 `uncommitted`；以 `HEAD` 读取仍返回已提交文本，并返回 40 位提交标识。传给连接器的仓库目录仍是临时目录，真正被拒绝的是仓库内相对文件参数 `../outside`，因为它试图越出允许路径。[固定 Git revision 与相对路径限制 ↗](../../../apps/server/tests/connectors.test.ts#L32 "支持读取 HEAD 已提交内容、返回提交标识，并准确说明被拒绝的是越界相对文件参数。") 材料未覆盖不存在的 revision、子模块、重命名、大文件、非文本 blob 或仓库自身位于允许根外的情形。
