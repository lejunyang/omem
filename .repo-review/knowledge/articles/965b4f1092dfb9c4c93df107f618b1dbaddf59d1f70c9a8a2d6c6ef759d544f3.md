# 连接器的文件边界与 Git 固定版本测试

该测试通过真实临时文件、符号链接和临时 Git 仓库，验证文件连接器只读取配置根目录内的纯文本，以及 Git 连接器按固定提交读取内容并拒绝路径逃逸。它覆盖了关键安全边界和主要返回字段，但未覆盖大小限制、编码错误、非法 ref、Git 命令超时等分支。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 测试解决的问题

连接器会把服务器文件系统或 Git 内容转换为捕获输入，因此测试重点不是一般的文本读取，而是确认外部输入不能越过授权边界。第一项用临时目录建立根目录、正常中文文本、根外文件及指向根外的符号链接，断言普通文本可被读取，同时符号链接逃逸会失败；随后写入含空字节的数据，确认其被视为二进制内容并拒绝。[文件连接器边界测试 ↗](../../../apps/server/tests/connectors.test.ts#L9 "支持正常中文文本可读取、符号链接逃逸与含空字节内容会被拒绝的测试结论。")

这些断言对应实现中的两层防护：`allowedPath` 先对目标和根目录求真实路径，再用相对路径判断归属，因此符号链接不能绕过根目录；`fileInput` 还限制文件大小、执行严格 UTF-8 解码并拒绝空字节。[文件路径与纯文本校验实现 ↗](../../../apps/server/src/connectors.ts#L10 "解释测试所验证的真实路径归属、文件大小、UTF-8 解码和空字节检查机制。")

<a id="git-flow"></a>
## Git 固定版本流程

第二项测试初始化真实 Git 仓库、提交 `note.txt`，再把工作区内容改为未提交版本。调用 `gitInput` 读取 `HEAD` 后仍得到已提交文本，并返回 40 位提交哈希，证明读取来源是解析后的固定提交，而非当前工作区文件。测试还传入 `../outside`，确认仓库内路径不能通过父目录片段逃逸。[Git 固定提交读取测试 ↗](../../../apps/server/tests/connectors.test.ts#L32 "支持测试通过提交后修改工作区来区分固定版本内容，并断言提交哈希及路径逃逸拒绝。")

源代码依据表明，流程先验证仓库位于允许根目录，再校验 ref 与仓库相对路径；之后通过 `git rev-parse` 得到提交 SHA，并以 `git show <sha>:<path>` 读取对象内容。测试对这一跨进程 Git 调用提供了实际行为证据。[Git 引用解析与对象读取实现 ↗](../../../apps/server/src/connectors.ts#L36 "说明 gitInput 校验 ref 和仓库路径、解析提交 SHA，再以 git show 读取固定对象的核心流程。")

<a id="coverage"></a>
## 覆盖边界与未覆盖行为

测试覆盖了成功读取中文纯文本、符号链接越界、空字节二进制、固定提交读取、提交哈希形状及 `..` 路径拒绝，并通过 `finally` 递归清理临时目录，避免测试残留。[临时资源清理与已覆盖断言 ↗](../../../apps/server/tests/connectors.test.ts#L17 "支持测试覆盖范围以及两项用例均在 finally 中清理临时目录的说明。")

尚未直接断言 500 KB 上限、无效 UTF-8、空或不存在的允许根、绝对路径、冒号或前导连字符路径、非法 ref、提交解析失败、目标文件不存在，以及 Git 命令的超时和缓冲区上限。实现虽明确设置了相关校验与执行限制，但仅凭当前测试不能确认这些失败分支的错误表现或跨平台一致性。[连接器尚未逐项测试的限制分支 ↗](../../../apps/server/src/connectors.ts#L23 "支持关于大小上限、路径与 ref 校验、Git 超时及缓冲限制存在于实现但未被当前测试逐项断言的判断。")
