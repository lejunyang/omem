# 文件与 Git 输入连接器边界测试

验证本地文件连接器的根目录约束、符号链接逃逸和二进制拒绝，以及 Git 连接器按固定 revision 读取内容而不混入工作区改动。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="file-boundary"></a>
## 文件输入的安全边界

文件连接器解决的是把受控本地材料转换为统一文本输入，同时防止调用方借路径访问配置根之外的数据。测试在临时根目录内创建普通中文文本、根外文件及指向根外的符号链接：合法文本被转换成 text part，逃逸链接因解析后的真实位置不在允许根内而失败；含空字节的文件则按二进制拒绝。[文件输入根目录与类型检查 ↗](../../../apps/server/tests/connectors.test.ts#L9 "支持普通文本成功、符号链接逃逸和二进制内容被拒绝的说明。") 这说明边界判断不能只检查表面路径，也表明当前合同聚焦纯文本。测试未覆盖最大文件尺寸、无权限文件、非 UTF-8 文本、多个允许根及链接仍落在根内的情况。

<a id="git-snapshot"></a>
## Git 快照读取与限制

Git 输入用于从明确仓库和 revision 获取可复现材料。测试先提交 `note.txt`，随后把工作区内容改为另一值，再以 `HEAD` 读取；返回内容仍是已提交版本，并附带 40 位提交标识，证明采集绑定固定 Git 对象而不是当前工作树。[固定 Git Revision 读取 ↗](../../../apps/server/tests/connectors.test.ts#L32 "支持连接器忽略未提交修改、返回提交哈希并拒绝仓库外相对路径的论断。") `../outside` 被判为非法仓库内路径，覆盖了直接的相对路径逃逸。该测试没有证明分支移动时的并发一致性，也未覆盖不存在的 revision、子模块、符号链接 blob、大文件、Git 命令失败或仓库自身位于允许根之外时的行为。
