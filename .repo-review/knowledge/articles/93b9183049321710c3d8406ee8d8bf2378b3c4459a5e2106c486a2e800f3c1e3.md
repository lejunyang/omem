# 浏览器端到端验收：从材料捕获到故障恢复

该脚本在临时 SQLite 工作区中启动真实应用与无头 Chromium，以确定性 Agent、飞书注册及能力探测夹具稳定复现用户流程。它覆盖材料捕获、提案应用、证据阅读、待办跟进、人工决策、飞书接入、响应式布局、故障展示、重启恢复及富文本安全渲染；但不等价于真实 Agent CLI、飞书网络或通知渠道的在线验收。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="test_scope"></a>
## 真实应用边界内的确定性浏览器验收

脚本解决的是“各模块单测通过，但用户完整操作仍可能断裂”的问题：它直接引入应用构建、存储、飞书接入和共享合同，并明确采用真实 Vue、API 与 SQLite，同时用协议夹具稳定 Agent 输出。参考 [浏览器验收范围 ↗](../../../scripts/browser-smoke.ts#L1 "说明脚本使用真实 Vue、API、SQLite，并列出其直接依赖的应用、存储、飞书及合同模块。")

测试在临时目录中组装 `Store`、飞书接入服务和加密凭据存储；注册二维码、已有应用及能力结果由内存夹具提供。随后启动真实 HTTP 服务和 Chromium，监听页面异常及关键控制台错误。参考 [注册流程夹具 ↗](../../../scripts/browser-smoke.ts#L18 "支持二维码注册由确定性适配器模拟，并通过中止信号结束，而非调用真实授权服务。") [飞书测试服务组装 ↗](../../../scripts/browser-smoke.ts#L37 "支持已有应用、能力探测、存储、加密密钥库和接入服务在测试中的组合关系。") [应用与浏览器启动 ↗](../../../scripts/browser-smoke.ts#L75 "支持脚本使用确定性 ACP 夹具配置启动真实应用服务器及无头 Chromium，并采集页面错误。")

<a id="main_flow"></a>
## 从原始材料到可追溯结果

主路径先通过界面保存材料，并从存储确认捕获成功；辅助函数再以固定 Fragment 原文构造提案和独立评估结果，检查服务端接受该证据。参考 [固定证据提案评估 ↗](../../../scripts/browser-smoke.ts#L127 "说明测试如何从固定 Fragment 构造提案、证据定位和审核结论，并调用评估 API。") [材料捕获入口 ↗](../../../scripts/browser-smoke.ts#L193 "支持用户通过真实界面保存材料，并由底层 Store 确认捕获结果。")

```mermaid
flowchart LR
  A[界面保存材料] --> B[生成版本与处理任务]
  B --> C[评估并应用提案]
  C --> D[学习流程显示结果]
  D --> E[查看原证据与通知详情]
```

脚本随后完成任务租约、刷新页面，并验证“已生效”、原文证据和通知详情均可追溯。它还构造循环引用，检查层级跳转与追问保存；再次捕获同一来源后确认新版本成为当前内容，而旧版本仍可阅读。参考 [提案应用与证据回看 ↗](../../../scripts/browser-smoke.ts#L228 "支持任务完成、提案生效、学习流程展示、原证据打开和通知详情检查组成完整闭环。") [循环证据与版本历史 ↗](../../../scripts/browser-smoke.ts#L283 "支持循环引用导航、基于原文追问，以及新旧版本并存和历史版本可读的断言。")

<a id="decisions_and_integrations"></a>
## 待办、人工判断与飞书接入

待办流程覆盖创建、完成、等待回复、暂缓提醒、取消以及跨页面保留的日常助理会话，并检查窄屏下无横向溢出和页面不暴露内部标识。参考 [待办与日常跟进 ↗](../../../scripts/browser-smoke.ts#L333 "支持待办状态变更、持久会话、等待与暂缓控制，以及不同视口和内部标识隐藏的验证。")

对于会改变既有声明的提案，脚本验证其进入待判断状态，并分别走补充背景、拒绝、确认应用三条分支；若来源已更新，旧判断必须失效且不能继续提交。参考 [人工判断分支 ↗](../../../scripts/browser-smoke.ts#L399 "支持冲突提案需人工判断，以及补背景、拒绝、批准和来源过期失效四类行为。")

飞书路径覆盖生成二维码与外部授权链接、取消重配、复用已有应用、生成配对码和确认 owner；同时断言客户端页面及状态接口均不泄露夹具密钥。这里证明的是接入编排与 UI 合同，而非真实飞书网络可用性。参考 [飞书授权与配对 ↗](../../../scripts/browser-smoke.ts#L490 "支持二维码授权、复用应用、owner 配对及密钥不向页面和状态接口泄露的断言。")

<a id="boundaries"></a>
## 布局、容量、故障与安全边界

界面边界包括 768 像素键盘操作、390 像素全屏对话框，以及连续打开 100 层证据后仍只渲染当前正文；这些断言覆盖可见性、焦点留在对话框内和渲染规模，但没有直接断言关闭后焦点回到原触发器。参考 [响应式与深层证据 ↗](../../../scripts/browser-smoke.ts#L567 "支持平板、手机的溢出和对话框焦点检查，以及 100 层证据导航的容量边界。")

故障场景通过写入失败任务和通知投递状态，验证模型不可用、投递失败、API 离线提示及应用重启后的数据恢复；因此它验证故障呈现和持久化结果，不覆盖生产渠道实际失败的产生过程。参考 [故障展示与重启恢复 ↗](../../../scripts/browser-smoke.ts#L653 "支持模型失败、通知失败、API 离线和服务重启后持久数据仍可读取的结论。")

最后，真实阅读器需渲染 Markdown 表格和 Mermaid SVG，同时移除 `foreignObject` 与脚本标签；全程收集的页面错误必须为空。参考 [富文本安全渲染 ↗](../../../scripts/browser-smoke.ts#L727 "支持 Markdown 表格、Mermaid SVG 正常呈现，同时危险脚本及 foreignObject 不进入阅读器。")
