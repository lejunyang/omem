# 多路召回候选池的公平准入

candidatePool 在模型评分前按各召回前沿轮询候选，以 route/recall rank 决定各队列次序，并用全局分数处理同名次候选。它限制输出规模、按 ID 去重，同时保留输入数组；当前统一检索调用点主要借它调整评估顺序。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 控制模型评估的候选范围

候选池把多路召回命中整理为一个有上限的模型评估队列。它只决定哪些候选先进入池以及进入顺序，不重新计算相关性；函数复制 `hits` 后再排序，因此不会改动调用方的数组，池外候选仍由调用方保留。每个命中至少提供 `id`、`score` 和 `routes`，还可携带按路由记录的名次。参考 [候选池接口与职责 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L1 "支持候选池属于准入而非相关性评分、输入字段约束以及复制后排序的说明。")

统一检索的 `select` 在模型排序前调用它：传入由检索命中补上 `id` 的对象，当前上限取 `hits.length`，随后再交给 `finish` 和模型评分。这个调用点主要利用候选池重排召回前沿，通用函数仍支持更小的 `limit` 来截断结果。参考 [统一检索调用位置 ↗](../../../apps/server/src/retrieval/unified.ts#L962 "说明统一检索在模型评分前调用 candidatePool，并把结果继续交给 finish 与 rank。")

<a id="flow"></a>
## 从路由名次到轮询输出

函数先按 `score` 降序生成副本，再为每个 ID 选择名次表，优先级依次是 `recallRanks`、`routeRanks`、按全局位置生成的退化名次。接着收集所有名次表中的路由，为每条路由建立队列；队列先按该路由的名次升序，同名次再按 `score` 降序。参考 [名次表与路由队列 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L12 "支持名次来源优先级、路由收集方式以及队列按路由名次和分数排序的流程。")

```mermaid
flowchart LR
  A[命中列表] --> B[按 score 排序]
  B --> C[建立各 route 队列]
  C --> D[每轮每个队列取一个]
  D --> E[按 id 去重并受 limit 限制]
```

轮询会跳过已经输出的 ID，每条路由每轮最多贡献一个候选，直到达到上限或所有队列耗尽。参考 [轮询、上限与去重 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L24 "支持按路由轮询、跳过重复 ID、达到 limit 或队列耗尽时停止等行为。")

代表性调用中，80 个高分候选都位于 `0:bm25` 前沿，一个总分仅为 `0.001` 的答案位于 `1:bm25` 前沿；`limit=2` 时输出为 `head-0`、`answer`。低总分答案能进入第二个位置，是因为两个前沿共享预算，而非由第一条路由耗尽名额。参考 [跨召回前沿示例 ↗](../../../apps/server/tests/retrieval-model-admission.test.ts#L14 "提供低总分答案仍在两席候选池中被选中的真实调用与断言。")

<a id="boundaries"></a>
## 去重规则与输入边界

`result.length < limit` 同时控制循环和写入，所以输出不会超过上限；`seen` 以 `id` 去重。由控制条件可推得，空输入、非正上限或没有任何名次键时返回空数组。测试中的多路候选也验证了前几个位置覆盖不同路由，并且 40 个结果的 ID 互不重复。参考 [轮询、上限与去重 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L24 "支持按路由轮询、跳过重复 ID、达到 limit 或队列耗尽时停止等行为。") [多路覆盖与唯一性断言 ↗](../../../apps/server/tests/retrieval-unified.test.ts#L1598 "验证候选池前部覆盖不同路由，并保证指定规模结果中的 ID 唯一。")

调用方应保证 ID 唯一。名次表用 ID 作为 `Map` 键，重复 ID 会让后出现对象覆盖此前的名次表，而输出阶段又只保留一个同 ID 候选。另一个细节是空的 `recallRanks` 仍会阻止回退到 `routeRanks`，因为代码使用空值合并运算符；这样的命中不产生路由队列。若上限在一轮中途达到，较早发现的路由先占位置，路由发现顺序来自全局分数顺序及名次表键顺序。参考 [名次表与路由队列 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L12 "支持名次来源优先级、路由收集方式以及队列按路由名次和分数排序的流程。") [轮询、上限与去重 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L24 "支持按路由轮询、跳过重复 ID、达到 limit 或队列耗尽时停止等行为。")
