# 多路召回候选池的公平准入

candidatePool 在模型处理候选前覆盖不同查询或路由前沿。它优先采用 recallRanks，其次采用 routeRanks；两者都没有时，以全局分数顺序生成退化名次。各前沿队列轮流提交候选，结果按 ID 去重。调用方若要把 limit 当作严格的数量上限，应传入非负整数，并保证 ID 唯一。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 控制模型处理的候选范围

候选池把多路召回命中整理成一个受 `limit` 控制的准入序列。它覆盖查询或路由前沿后限制后续模型工作量，相关性分数仍由输入提供，池外候选保持可用。每个命中必须带有 `id`、`score` 和 `routes`，也可提供 `routeRanks` 或 `recallRanks`。参考 [候选池职责与输入约束 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L1 "支持候选池用于准入、限制模型工作量、保留池外候选，以及输入字段要求。")

函数通过 `[...hits]` 复制数组，再按 `score` 降序排序。它不会重排调用方传入的数组；返回值中的候选对象仍是原对象。参考 [名次表与前沿队列 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L12 "支持复制排序、名次来源优先级、前沿发现顺序和队列内部排序规则。")

<a id="flow"></a>
## 从前沿名次到轮询输出

每个 ID 的名次表优先取 `recallRanks`，没有时取 `routeRanks`；两者都未提供时，函数用该候选的全局排序位置为 `routes` 中的每个名称生成名次。所有名次表的键按首次出现顺序组成前沿列表。每个前沿队列先按对应名次升序排列，同名次候选再按 `score` 降序排列。参考 [名次表与前沿队列 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L12 "支持复制排序、名次来源优先级、前沿发现顺序和队列内部排序规则。")

```mermaid
flowchart LR
  A[命中列表] --> B[按 score 降序复制排序]
  B --> C[为每个前沿建立队列]
  C --> D[逐轮访问各队列]
  D --> E[按 id 去重并写入结果]
```

每一轮按前沿顺序各取一个尚未出现的候选；同一候选出现在多个队列时，后续队列会越过它寻找下一个未选候选。循环在结果达到整数上限或所有队列都无法再提供候选时结束。参考 [轮询、去重与终止条件 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L24 "支持写入上限检查、按 ID 去重、逐前沿轮询和无新增候选时终止。")

**教学示例。** 假设 `A`、`B` 属于前沿 `q0:bm25`，名次分别为 0 和 1；低分候选 `C` 属于前沿 `q1:bm25`，名次为 0。`limit=2` 时，第一轮先从 `q0:bm25` 取 `A`，再从 `q1:bm25` 取 `C`，得到 `[A, C]`。这个例子展示的是轮询准入，不表示 `C` 的相关性分数高于 `B`。参考 [名次表与前沿队列 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L12 "支持复制排序、名次来源优先级、前沿发现顺序和队列内部排序规则。") [轮询、去重与终止条件 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L24 "支持写入上限检查、按 ID 去重、逐前沿轮询和无新增候选时终止。")

<a id="boundaries"></a>
## 去重规则与输入边界

`seen` 以 `id` 去重，写入前同时检查结果长度。调用方传入非负整数 `limit` 时，结果不会超过该数量；`limit` 为 0 或负数时返回空数组。参数类型只约束为 `number`，若传入小数，例如 `1.5`，长度为 1 时仍可再写入一个候选，所以调用方要把它当作候选数量上限时应先保证它是非负整数。参考 [轮询、去重与终止条件 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L24 "支持写入上限检查、按 ID 去重、逐前沿轮询和无新增候选时终止。")

`recallRanks` 和 `routeRanks` 通过空值合并运算符选择。显式传入空对象 `{}` 会阻止后续回退，同时不会生成任何前沿；所有候选都没有名次键时，函数返回空数组。重复 ID 也需要由调用方避免：名次表以 ID 为键，后写入的同 ID 项会覆盖此前名次表，而结果阶段只保留一个同 ID 候选。参考 [名次表与前沿队列 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L12 "支持复制排序、名次来源优先级、前沿发现顺序和队列内部排序规则。") [轮询、去重与终止条件 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L24 "支持写入上限检查、按 ID 去重、逐前沿轮询和无新增候选时终止。")

前沿顺序来自按分数排序后的候选及其名次表键顺序。若结果在一轮中途达到上限，排在前面的前沿会先取得剩余名额。参考 [名次表与前沿队列 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L12 "支持复制排序、名次来源优先级、前沿发现顺序和队列内部排序规则。") [轮询、去重与终止条件 ↗](../../../apps/server/src/retrieval/candidate-pool.ts#L24 "支持写入上限检查、按 ID 去重、逐前沿轮询和无新增候选时终止。")
