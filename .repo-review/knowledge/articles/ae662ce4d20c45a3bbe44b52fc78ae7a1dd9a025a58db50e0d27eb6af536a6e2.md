# 视觉材料分析角色 v1 运行清单

该清单声明 visual-analyst 的角色包、KnowledgeBatch 输出、隔离策略和预算，但未定义图像载荷通道、模型视觉能力协商或这些策略的实际执行情况。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="visual_role_contract"></a>
## 角色包与知识输出

清单定义 `visual-analyst` v1，引用 `traex` profile 与 `prompt.md`，并以内联方式加载固定版本和制品摘要的 `omem-visual-analyst` 技能。其输出合同为 `KnowledgeBatch.v1`，说明配置期望该角色产生结构化知识批次。[视觉角色、技能与知识输出配置 ↗](../../../packages/agent-runtime/roles/visual-analyst/1/manifest.json#L2 "支持视觉角色身份、profile、内联技能制品及 KnowledgeBatch 输出合同的配置说明。")

现有材料只有运行清单，没有提供视觉提示词、技能正文、输出 Schema 或执行记录。因此可以确认角色及输出合同的声明，但不能进一步认定 OCR、图像理解、视觉引用定位或制品摘要验证已经由运行时实现。

<a id="visual_isolation"></a>
## 隔离、输入边界与预算

该角色的工具策略为 `none`，允许工具列表为空；会话声明永不复用，并禁止继承用户技能和 MCP。[视觉角色工具与会话配置 ↗](../../../packages/agent-runtime/roles/visual-analyst/1/manifest.json#L18 "支持无可调用工具、会话不复用以及不继承用户技能和 MCP 的配置事实，同时说明清单并未定义图像载荷通道。") 这些字段仅表明可用工具和可继承上下文受到限制。此前“图像必须由宿主随上下文提供”的结论由此替代：清单没有定义图像载荷通道，无法区分上下文、任务附件或其他宿主管理机制。

预算配置为 96,000 个上下文 token、24,000 个输出 token和最多两次修复尝试。[视觉分析任务预算配置 ↗](../../../packages/agent-runtime/roles/visual-analyst/1/manifest.json#L27 "支持上下文、输出 token 和修复尝试次数的配置上限。") 它没有说明所选 profile 是否支持视觉输入、如何拒绝不兼容模型，也未证明预算计量及修复行为已经生效。
