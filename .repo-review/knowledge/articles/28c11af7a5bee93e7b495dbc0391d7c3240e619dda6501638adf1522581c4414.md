# 普通材料捕获与质量标注导入的隔离回归测试

该测试验证普通 Store.capture 保存含预期文本的 revision 与 fragment，同时不创建质量数据集、质量样本或外发意图；研究导入器必须获得显式 opt-in 才能运行。此前由单一引用概括两个用例均采用独立临时目录的表述，现已替换为分别引用两个用例的准确说明。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 回归目标与隔离策略

该文件防止普通业务材料被误送入人工质量标注流程。测试构造 40 段足以被研究拆分器选中的中文文本；第一个用例创建并登记自己的临时目录，公共 `afterEach` 会递归清理所有已登记目录。[首例临时目录与统一清理 ↗](../../../apps/server/tests/import-quality-isolation.test.ts#L22 "支持公共 afterEach 清理已登记目录、40 段测试文本构造及第一个用例创建独立临时目录的说明。") 第二个用例另行创建并登记独立临时目录。[第二例独立临时目录 ↗](../../../apps/server/tests/import-quality-isolation.test.ts#L98 "补充证明第二个研究导入器用例也单独创建并登记临时目录，修正此前引用覆盖不足。") 这替代了此前仅凭第一个用例的引用便概括“每个用例均使用独立目录”的结论，使隔离策略的证据覆盖两个用例。

<a id="ordinary_capture"></a>
## 普通捕获的实际行为断言

第一例把经 `captureSchema` 校验的手工材料传给 `store.capture`，确认返回 revision 含 fragment，且首段包含“三方核对”。随后直接查询数据库，断言 `quality_datasets`、`quality_samples` 与 `delivery_intents` 的记录数均为零；这能证明本次捕获未创建质量数据集、草稿样本或外发意图，但不能证明材料已通过检索接口召回，也未穷尽其他副作用。[普通捕获与三张表零记录断言 ↗](../../../apps/server/tests/import-quality-isolation.test.ts#L42 "支持普通捕获产生 fragment、保留预期文本，并且质量数据集、质量样本和外发意图计数均为零的结论。") Store 会创建 SQLite 文件、执行迁移并初始化仓储，因此这些断言针对实际数据库而非模拟对象。[Store 的 SQLite 初始化 ↗](../../../apps/server/src/store.ts#L38 "说明测试使用的 Store 会创建真实 SQLite 数据库、执行迁移并初始化相关仓储。") 第一例最终关闭 Store，避免数据库句柄残留。[首例关闭 Store ↗](../../../apps/server/tests/import-quality-isolation.test.ts#L93 "支持第一个普通捕获用例在 finally 中关闭数据库句柄的说明。")

<a id="eval_guard"></a>
## 研究导入器的显式准入与覆盖边界

第二例直接创建 `QualityRepository`：缺少 `optIn` 时调用研究导入器会抛出 `QUALITY_IMPORT_IS_EVAL_ONLY`；传入固定判别值后才允许运行，并断言返回的 `sampleCount` 为 40，最后关闭 Store。[研究导入器准入与成功路径 ↗](../../../apps/server/tests/import-quality-isolation.test.ts#L102 "支持缺少 opt-in 时抛错、显式 opt-in 后返回 40 条样本以及第二例关闭 Store 的陈述。") 这与模块声明的研究专用边界一致：规则拆分器仅服务显式人工标注实验，普通 HTTP、CLI、输入聚合和学习捕获链路不应调用它。[质量导入模块的研究专用边界 ↗](../../../apps/server/src/quality/import.ts#L1 "解释研究拆分器只用于显式人工标注实验，以及普通捕获、CLI、输入聚合和学习链路不得调用它的设计约束。") 不过，设计声明不能代替各入口的端到端验证，本文件也没有检查导入样本的定位、标签、数据集内容、幂等性或外发意图。
