# 知识正文阅读与引用导航组件

该组件按文档键及可选修订加载知识文章，呈现来源状态、目录、Markdown 正文和待核对问题，并把可操作引用交给上层阅读轨迹。请求代次可避免旧响应覆盖新页面；同文档章节跳转、目录选择器边界和自动化测试覆盖仍需确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-rendering"></a>
## 阅读结构与问题入口

组件区分错误、加载和成功状态；文章加载后展示标题、摘要、当前或历史来源标记与模型信息，再按章节交给共享 `OmMarkdown` 渲染。章节超过两项时才出现页内目录，以减少短文的导航噪声。[知识正文模板结构 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L26 "支持错误、加载、文章元数据、目录和分节 Markdown 的条件化呈现。")

正文末尾挂载按当前文章键过滤的待核对问题，使已形成的知识与仍需补充的背景处于同一阅读上下文。[文章待核对问题入口 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L37 "支持正文末尾按当前文章键挂载待核对问题组件。")

<a id="load-and-position"></a>
## 加载、竞态控制与章节定位

组件监听 `documentKey` 和 `revision`，变化时清空旧状态并请求指定文章；`generation` 只允许最后一代请求写入结果或错误，避免快速切换时旧响应覆盖当前页面。[文章请求与代次校验 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L10 "解释监听文档与修订、构造请求及阻止过期响应覆盖当前状态的流程。")

加载完成并等待 DOM 更新后，组件按 `section` 滚动到目标章节。不过监听源不含 `section`，因此仅改变章节属性时是否会立即定位，仍取决于父级是否重建组件。[加载完成后的章节滚动 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L11 "支持章节定位发生在加载与 DOM 更新之后，并说明监听源不包含章节属性。")

<a id="citation-navigation"></a>
## 引用导航与相邻模块

点击正文引用时，组件先查找引用并检查 `actionable`；有效引用被编码成包含文档、固定修订和引用键的导航帧，再交给父级管理阅读轨迹。[引用点击到导航帧 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L20 "支持引用可操作性检查以及向父级发送固定文档修订导航信息。") API 层统一附加会话令牌、处理失败响应，并定义文章、引用与导航帧类型。[知识接口与文章类型 ↗](../../../apps/web/src/knowledge/api.ts#L1 "解释组件依赖的文章、引用、导航帧类型及统一鉴权和错误处理。")

问题组件通过同一接口读取问题、保存用户回答或加入待办；回答会作为原始材料保存，并提示相关知识等待重新核对。[问题补充与待办流程 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L5 "支持问题读取、回答保存为原始材料以及加入待办的相邻交互流程。")

<a id="boundaries"></a>
## 边界与被替代的判断

初始章节定位使用 `CSS.escape`，目录点击却直接把章节键插入属性选择器；两条路径对引号、反斜杠等特殊字符的处理不一致。此前仅引用初始定位便比较两条路径的依据不足，现已由同时覆盖两处实现的引用替代。[两种章节选择器路径 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L17 "同时覆盖初始定位与目录点击实现，支持两条路径在 CSS 转义处理上不一致的判断。")

`OmButton` 在本文件中被导入但未使用。[未使用的按钮导入 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L2 "支持本组件导入 OmButton、但模板与脚本中未使用该组件的观察。") 另有 `.knowledge-open-questions` 样式未对应当前模板中的 `knowledge-questions` 类名；此前用导入范围同时支持该样式判断的结论已被拆分并替代。[开放问题遗留样式 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L54 "支持文件末尾存在 knowledge-open-questions 样式规则，而当前模板未使用该类名的判断。") 这些现象可能是遗留代码，但现有材料不能证明其清理计划，也未提供测试文件来确认竞态、历史修订、引用禁用和滚动行为的覆盖情况。
