# 知识文章的加载、阅读与证据导航

该组件是知识文章的阅读入口：按文档与修订加载内容，组织摘要、阅读目标、章节、待核对问题和生成来源，并把正文引用转换为上层可处理的证据导航事件。它同时处理异步请求竞态、章节定位、过期提示和响应式目录。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-loading"></a>
## 从指定版本加载可阅读文章

组件接收文档键、可选修订和章节位置，并请求对应的知识文章。加载期间旧正文会被清空，页面显示读取状态；请求失败则呈现可读的错误提示。每次加载都会递增 `generation`，只有最新请求可以写入页面，因此快速切换文档时，较慢的旧响应不会覆盖当前文章。成功后组件通知上层更新标题，并在渲染完成后定位到指定章节。参考 [文章加载与章节定位 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L6 "支持按文档和修订触发加载、避免旧响应覆盖，以及渲染后读取 section 并定位章节的流程和边界。")

请求由共享 API 封装完成：它拼接服务前缀、按需携带会话令牌，并把非成功响应转换成包含服务端错误信息或 HTTP 状态的异常。参考 [知识接口请求封装 ↗](../../../apps/web/src/knowledge/api.ts#L6 "说明文章请求如何携带会话令牌、解析响应并处理非成功状态。")

<a id="reading-and-evidence"></a>
## 围绕阅读任务组织正文与证据

文章页依次呈现标题、摘要和可选阅读目标，再按文档中的章节顺序渲染 Markdown。若原始材料已有变化，页面会提示正文等待更新且引用仍固定在写作版本；末尾的折叠区域展示生成模型、独立复核者和生成时间，帮助读者判断内容来源。参考 [知识正文阅读结构 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L28 "支持标题、摘要、阅读目标、过期提示、章节渲染和生成来源展示的描述。")

正文引用先在文章引用表中按键查找。只有引用被标记为可操作时，组件才会把当前文档、文章修订和引用键封装成 `citation` 导航帧交给上层；不可操作或文章尚未加载的引用不会触发导航。参考 [引用导航事件 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L21 "支持引用查找、可操作性判断，以及向上层发出 citation 导航帧的流程。")

文章存在待核对问题时，页面会挂载限定到当前文档的问题组件。该组件排除已被替代的问题，允许用户补充背景或加入待办；回答会保存为原始材料并等待后续知识核对，而不是直接改写正文。参考 [待核对问题处理 ↗](../../../apps/web/src/knowledge/KnowledgeQuestions.vue#L5 "说明问题的文档过滤、状态排除、补充背景和加入待办行为，以及回答保存后的用户提示。")

<a id="layout-and-boundaries"></a>
## 长文目录、窄屏适配与实现边界

章节超过两个时才显示篇内目录。目录点击会按章节的 `data-section` 定位并平滑滚动；桌面布局将正文限制在约 760 像素宽并配合粘性侧栏，较窄视口改为顶部目录，手机上则通过展开按钮显示或隐藏目录链接。证据抽屉中的文章会隐藏目录，避免嵌套阅读空间过窄。参考 [篇内目录与响应式布局 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L43 "支持目录出现条件、章节跳转、桌面侧栏、窄屏重排、手机展开行为及证据抽屉隐藏目录的说明。")

当前实现的初始章节定位只发生在文档或修订触发加载之后；如果外部只改变 `section`，这个监听不会自行重新定位。目录点击会直接查找已有章节键，而引用原文如何打开、返回及恢复阅读状态则由接收导航事件的上层负责。参考 [文章加载与章节定位 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L6 "支持按文档和修订触发加载、避免旧响应覆盖，以及渲染后读取 section 并定位章节的流程和边界。")、[引用导航事件 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L21 "支持引用查找、可操作性判断，以及向上层发出 citation 导航帧的流程。")

样式中的换行不会终止选择器：第 54—55 行会形成后代选择器 `.knowledge- .knowledge-provenance`，第 76—77 行会形成 `.knowledge- .outline-toggle`。两者都是有效但可疑的选择器；前者只匹配位于 `.knowledge-` 后代中的来源区域，后者也不会普遍隐藏桌面端目录按钮，而移动端媒体查询中的 `.outline-toggle` 仍会把按钮显示出来。参考 [后代选择器与目录按钮样式 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L54 "支持两个跨行选择器会被解析为有效后代选择器，并说明桌面隐藏规则的实际匹配范围及移动端覆盖行为。")
