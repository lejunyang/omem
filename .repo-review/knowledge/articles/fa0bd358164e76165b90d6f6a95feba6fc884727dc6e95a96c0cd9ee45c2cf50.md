# 知识文章阅读与证据导航

该组件负责读取并呈现一篇知识文章，展示知识时效、章节目录与待确认问题，并把正文引用转换为上层可处理的证据导航事件。它通过请求代次避免旧响应覆盖新文章，但章节参数单独变化时不会重新定位，引用能否打开也依赖服务端返回的 actionable 状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-reading"></a>
## 面向阅读的知识正文

组件把知识文章组织为标题、摘要、来源状态、分节正文和待确认问题，使读者先理解结论，再沿引用查看证据。正文交给共享的 Markdown 组件渲染，并同时传入引用数据；文章超过两个章节时显示页内目录，点击目录项会滚动到对应章节。参考 [正文与页内目录 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L31 "支持文章按章节渲染 Markdown、传递引用数据，并在章节较多时提供页内目录的说明。")

界面还明确区分“当前知识”和“待更新”：后者表示原文发生变化或部分证据缺失。待确认问题默认折叠，并交给问题组件按当前文章键加载，用户可在阅读上下文中补充背景或安排调查。参考 [知识状态与待确认问题 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L33 "支持界面展示知识时效、模型复核信息，并嵌入当前文章问题列表的说明。")

<a id="loading-and-navigation"></a>
## 加载、竞态控制与引用跳转

当文章键或指定修订变化时，组件清空旧内容并请求文章接口；每次请求都会递增代次，只有最后一次请求可以写入状态，从而避免快速切换文章时较慢的旧响应覆盖新页面。加载成功后，它通知上层更新标题，并在存在章节参数时等待 DOM 更新后滚动到目标章节。参考 [文章加载与竞态保护 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L10 "支持按文章键和修订请求数据、用 generation 丢弃过期响应，以及加载后定位章节的流程。")

引用点击并不直接打开原文。组件先在当前文章中按引用键查找记录，仅当引用可操作时，才发出包含文章键、固定修订和引用键的导航帧；真正的抽屉、路由或证据阅读行为由父级处理。参考 [引用导航事件 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L20 "支持引用必须可操作才会生成包含文章、修订和引用键的导航帧并交给上层处理。") API 类型也说明导航帧可表示知识、引用或来源，而引用解析结果可能指向文章或材料。参考 [文章与导航类型 ↗](../../../apps/web/src/knowledge/api.ts#L2 "说明文章包含引用集合，引用解析目标可以是文章或材料，导航帧由知识、引用和来源三类组成。")

<a id="states-and-limits"></a>
## 状态反馈与已知边界

请求失败时页面展示错误空态，等待响应时提供状态文本；成功后才渲染正文。接口层会携带会话令牌，并把非成功响应转换为包含服务端错误或 HTTP 状态的异常，因此这里显示的是统一请求层提供的错误信息。参考 [统一请求错误处理 ↗](../../../apps/web/src/knowledge/api.ts#L6 "支持接口读取会话令牌、附加认证头，并将非成功响应转换为异常的说明。")

当前监听项只有文章键和修订号：如果父组件只改变 `section`，既不会重新请求，也不会再次执行滚动定位。目录点击使用当前 DOM 查询章节；初始深链对章节名使用 CSS 转义，而目录查询直接插入章节键，因此章节键若包含特殊选择器字符，目录定位的可靠性取决于上游键格式。参考 [章节监听与定位 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L11 "支持监听项不包含 section、初始定位使用 CSS.escape，而目录点击采用另一种选择器拼接方式的边界分析。") 此外，材料中没有该组件的测试文件，无法确认快速切换、特殊章节键、不可用引用及窄屏布局是否已有自动化覆盖。
