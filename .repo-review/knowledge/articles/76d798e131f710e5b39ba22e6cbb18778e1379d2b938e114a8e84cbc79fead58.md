# 围绕命中位置生成可信的阅读摘录

readingExcerpt 把较长的原始材料裁成围绕命中位置的连续摘录，同时保留原文偏移、完整性标记和尽量完整的行边界。它供统一检索把排序命中转换为可阅读结果，并明确区分评分窗口、实际返回内容与完整结构目标。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决评分窗口与阅读范围不一致的问题

检索评分只需关注命中附近的窗口，交给读者或 Agent 的内容则要保持为可核对的连续原文。`readingExcerpt` 接收全文、字符锚点和长度预算；全文不超过预算时原样返回，并用 `complete: true` 表明没有省略。文件注释还规定不得从关键词推断条件，也不重构原文。参考 [阅读范围契约 ↗](../../../apps/server/src/retrieval/reading-excerpt.ts#L1 "支持评分窗口与阅读上下文分离、短文本完整返回以及不重构原文的说明。")

统一检索只对 `source` 类型的单元调用它。其余结果中，正文长度不超过 1200 的知识条目使用整段正文；其他结果优先使用 `h.excerpt`，缺失时才调用 `bestSnippet`。输出进入 `RetrievalHit.text`，同时另设 `readingRange` 描述实际返回行，避免把命中范围或完整结构目标误当成已读内容。参考 [统一检索调用 ↗](../../../apps/server/src/retrieval/unified.ts#L1192 "证明普通检索结果只对原始材料单元生成阅读摘录，并说明其他知识结果的文本选择路径。") [阅读范围类型 ↗](../../../apps/server/src/retrieval/port.ts#L45 "说明 RetrievalHit 将实际返回文本范围与匹配窗口、完整结构目标分开表达。")

<a id="flow"></a>
## 从锚点到连续摘录

长文本先把锚点夹在有效下标内，再建立一个不越过全文边界的窗口。默认预算为 6000 个 JavaScript UTF-16 代码单元；窗口未受全文首尾夹紧时，初始布局在锚点前预留约三分之一，后方获得其余空间。锚点靠近开头或结尾时，前后空间会随边界重新分配。随后仅在不丢失锚点且相应换行位于当前窗口内时，边界才向内对齐：起点侧找到的行首须不晚于锚点，终点侧找到的换行须晚于锚点。若锚点所在行跨过窗口某一侧边界，该侧会保留这行的部分内容；即使整行未超过总预算，函数也不会重新分配另一侧空间来容纳整行。调整后的摘录仍不超过初始长度上限。参考 [锚点窗口计算 ↗](../../../apps/server/src/retrieval/reading-excerpt.ts#L11 "支持锚点夹紧、未触及全文边界时的三分之一前向初始配额，以及长度受限窗口的流程说明。") [行与字符边界处理 ↗](../../../apps/server/src/retrieval/reading-excerpt.ts#L17 "支持仅在相应换行不越过锚点时向内调整边界、锚点所在行跨界时保留部分内容，以及 UTF-16 代理对保护。")

```mermaid
  A[全文、锚点、预算] --> B{全文可完整容纳?}
  B -->|是| C[返回全文 complete=true]
  B -->|否| D[夹紧锚点并计算窗口]
  D --> E[条件满足时向内对齐换行<br/>否则保留锚点所在行的部分内容]

```

代表性调用把 900 行文本和 `step(500)` 的位置交给函数。结果不超过 6000，包含该行，内容严格等于原文的 `slice(start, end)`，首尾也落在完整行上；测试同时断言 `complete` 为 `false`。参考 [长文本行为断言 ↗](../../../apps/server/tests/retrieval-reading-input.test.ts#L100 "提供 900 行代表性输入，验证长度上限、锚点保留、原文切片一致性和部分读取标记。")

<a id="boundaries"></a>
## 完整性、字符边界与调用方换算

`complete` 只表示是否返回了整个输入。所有超预算文本都标为 `false`，即使裁出的片段恰好由完整行组成。起点若落在低代理项上会右移，终点前若是高代理项会左移，从而不把 UTF-16 代理对切成孤立半个字符；这项保护也可能让极小的自定义预算进一步缩短。参考 [行与字符边界处理 ↗](../../../apps/server/src/retrieval/reading-excerpt.ts#L17 "支持仅在相应换行不越过锚点时向内调整边界、锚点所在行跨界时保留部分内容，以及 UTF-16 代理对保护。")

函数不验证 `maxCharacters` 是否为正，当前两个生产调用都使用默认值。若要调整阅读长度，应修改默认参数或在调用处显式传入正预算，并保留 `start`、`end` 与 `complete` 的语义。调用方会用字符偏移重新计算材料行号；补充父级上下文的路径还先依据匹配行生成锚点，再返回固定目标和对应的 `readingRange`。参考 [参数与返回值实现 ↗](../../../apps/server/src/retrieval/reading-excerpt.ts#L4 "支持默认预算、未设置额外参数校验以及返回字符偏移和完整性标记的说明。") [补充上下文换算 ↗](../../../apps/server/src/retrieval/unified.ts#L1012 "证明补充父级上下文路径从匹配行计算字符锚点，并把摘录偏移换算成 readingRange 行号。")
