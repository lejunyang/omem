# 开发启动与分层真实链路验收

开发脚本用统一编排器启动个人或仓库评审模式的 API 与 Web，并负责端口传递、健康检查和进程清理。验收分为确定性浏览器流程、真实仓库知识阅读及依赖外部环境的 live 检查；各层证明范围不同，源码存在也不能替代实际命令、退出码和报告。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="dev-startup"></a>
## 一个入口拉起 API 与 Web

个人开发入口先补充仓库根目录、固定为个人模式，再把启动交给共用编排器。参考 [个人开发入口 ↗](../../../scripts/dev.ts#L1 "支持个人模式先准备运行环境，再将具体启动交给共用编排器。") 编排器预检 API 与 Web 端口、拒绝两者相同，随后启动对应 API 和独立 Vite 子进程，并把选定端口同时传给后端与代理。参考 [端口预检与子进程启动 ↗](../../../scripts/dev-review.ts#L81 "支持模式相关端口选择、同端口拒绝、API 与 Vite 启动及端口传递。") 延伸阅读：[开发进程编排 ↗](a74183dc494df06cd9b8406ca75119754295c4c008e72594d207fa41925ecdb4.md#startup-flow "补充端口预检、双进程启动与就绪判定的整体背景。")

```mermaid
flowchart LR
  A[开发入口] --> B[端口预检]
  B --> C[启动 API]
  B --> D[启动 Vite]
  D -->|API 代理| C
  C --> E[健康检查通过后公布地址]
```

Vite 使用独立配置和严格端口策略，避免沿用个人后端代理或在冲突时静默换址。参考 [独立 Vite 代理 ↗](../../../scripts/dev-review-vite.ts#L18 "支持独立 Vite 配置、严格端口、API 代理和信号关闭流程。") 编排器最多等待健康端点 60 秒，成功后才公布访问地址，超时则关闭子进程。参考 [API 健康检查 ↗](../../../scripts/dev-review.ts#L131 "支持健康端点选择、等待窗口、超时关闭和就绪后公布地址。")

<a id="browser-layers"></a>
## 确定性浏览器验收覆盖产品与知识阅读

产品浏览器验收运行真实 Vue、API 与 SQLite，但 Agent 使用协议 fixture。参考 [浏览器验收运行栈 ↗](../../../scripts/browser-smoke.ts#L1 "支持脚本采用真实 Vue、API、SQLite，同时使用协议 fixture Agent 稳定断言。") 提案评估还直接提交预设为 `supported` 的确定性 assessment，并未在该流程中运行独立 verifier。参考 [确定性评估输入 ↗](../../../scripts/browser-smoke.ts#L129 "支持浏览器验收直接提交固定提案和预设为 supported 的 assessment，而非运行独立 verifier。") 飞书注册器、既有应用提供器和能力探测器同样由脚本内替身提供。参考 [飞书能力替身 ↗](../../../scripts/browser-smoke.ts#L19 "支持浏览器验收中的注册器、既有应用凭据和能力探测均由脚本内 fixture 提供。") 因此这层适合稳定检查材料录入、提案生效、任务、通知及原证据阅读，不证明模型质量或飞书平台可用。参考 [材料到通知流程 ↗](../../../scripts/browser-smoke.ts#L194 "支持从材料录入到提案应用、任务完成、通知和原证据阅读的产品路径。") 延伸阅读：[真实浏览器验收 ↗](93b9183049321710c3d8406ee8d8bf2378b3c4459a5e2106c486a2e800f3c1e3.md#purpose "补充真实应用栈与确定性 Agent fixture 的验收分工。")

知识阅读另有两条路径：临时仓库脚本验证多层引用、深链恢复、焦点归还、源码导航、待办转化和安全渲染；参考 [隔离知识阅读链路 ↗](../../../scripts/knowledge-browser.ts#L49 "支持临时知识文章的多层导航、深链刷新、焦点恢复、源码跳转、待办和安全渲染断言。") 已运行应用上的视口脚本则检查真实仓库知识中的固定代码区间、上下文展开、分层轨迹和滚动恢复。参考 [真实仓库证据轨迹 ↗](../../../scripts/code-wiki-viewport.ts#L36 "支持固定代码区间、上下文展开、知识解读、内层引用、滚动恢复和 URL 深链行为。") 两者分别提供可复现 fixture 与真实知识资产验收。延伸阅读：[知识阅读断言 ↗](5ef71b2c76cc144c5bd5b4ddf3a6f860924bd6e2d060a8a70675f934ca0f5e13.md#assertions "补充多层引用、深链、源码导航和焦点归还的验收意义。")

<a id="live-validation"></a>
## 真实外部链路按风险分层验证

live 检查把外部依赖与浏览器 fixture 分开。ACP 冒烟会探测模型、发起真实中文问答并收集流式文本；参考 [真实 ACP 最小问答 ↗](../../../scripts/live-acp-smoke.ts#L5 "支持在线模型选择、真实 ACP 会话、流式文本收集和最小答案检查。") 学习冒烟进一步串联 extractor、独立 verifier 和策略评估，只有自动应用并取得回执才成功。参考 [真实学习闭环 ↗](../../../scripts/live-learning-smoke.ts#L73 "支持 extractor 产出、稳定摘要、独立 verifier 复核以及自动应用与回执断言。")

飞书连接器先校验受限 URL，再调用 `lark-cli`，将正文、原文链接和引用元信息转换为统一捕获输入。参考 [飞书文档受限读取 ↗](../../../apps/server/src/connectors.ts#L76 "支持飞书 URL 校验、lark-cli 调用和统一捕获输入的构造方式。") 宿主冒烟要求真实加密密钥，并在存在待投递消息时默认拒绝启动。参考 [飞书宿主启动保护 ↗](../../../scripts/live-lark-host-smoke.ts#L15 "支持真实密钥要求、待投递消息保护以及默认拒绝潜在外部发送。") 它还会选取一条活动连接、读取对应密钥并核对应用标识，不满足条件则在启动前失败。参考 [活动连接与凭据检查 ↗](../../../scripts/live-lark-host-smoke.ts#L42 "支持宿主冒烟选择活动连接、读取密钥引用并校验凭据中的应用标识。") 成功条件是观察到 `connected` 事件；脚本会输出能力和运行状态，但没有发送测试消息，也未验证入站捕获、记忆落库或出站送达。参考 [飞书连接成功条件 ↗](../../../scripts/live-lark-host-smoke.ts#L93 "支持宿主以 connected 事件作为成功条件，并界定输出与资源清理范围。")

<a id="progress-limits"></a>
## 如何解读当前进展与限制

当前验收结构覆盖启动生命周期、确定性产品流程、仓库知识阅读以及真实 Agent 和飞书连接。判断结果时必须保留层级：浏览器 fixture 通过不能证明外部服务可用，live 脚本存在也不代表当前环境已经执行成功，仍需核对实际命令、退出码与报告。

端口预检通过临时监听发现冲突，但会在返回前释放端口；默认端口被占用时改用动态端口，显式端口冲突则报错。参考 [开发端口占用处理 ↗](../../../scripts/dev-ports.ts#L9 "支持临时绑定探测、默认端口动态回退和显式端口冲突报错，并揭示释放监听后的竞态。") 因而预检结束到子进程真正绑定之间仍有抢占窗口。现有浏览器检查主要使用 Chromium，ACP 最小问答断言较宽松，学习冒烟未核对任务字段，飞书宿主也只证明连接状态，这些都是扩展验收时需要单独补齐的边界。
