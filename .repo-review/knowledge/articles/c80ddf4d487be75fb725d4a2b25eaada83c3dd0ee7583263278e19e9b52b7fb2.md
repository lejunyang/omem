# 开发启动与分层真实链路验收

开发脚本用同一套编排管理个人应用与仓库评审环境的端口、API、Web 和进程生命周期；验收脚本分为确定性浏览器检查、仓库知识阅读检查和依赖外部 Agent、Lark 的在线冒烟。脚本源码证明检查入口与断言已定义，但不等同于当次执行成功或外部服务长期可用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="development_startup"></a>
## 统一启动个人应用与评审环境

个人开发入口补充仓库根目录、固定 `personal` 模式，再把启动交给共享编排器。编排器按模式选择 API 入口和默认端口，预检 API、Web 端口后启动两个子进程，并把选定端口传给后端与前端代理。参考 [个人开发入口 ↗](../../../scripts/dev.ts#L1 "支持入口设置仓库根目录与 personal 模式，并将启动交给共享编排器。") [双进程启动与端口传递 ↗](../../../scripts/dev-review.ts#L81 "支持端口预检、模式相关 API 入口、API 与 Web 子进程创建及端口环境变量传递。")

```mermaid
flowchart LR
  A[探测 API 与 Web 端口] --> B[启动 API]
  A --> C[启动 Vite]
  C --> D[/api 代理到 API]
  B --> E[轮询健康端点]
  E --> F[输出访问地址]
```

评审前端采用独立 Vite 配置、回环监听和严格端口；编排器最长等待健康端点 60 秒，子进程报错或退出会触发整体关闭。参考 [健康检查与故障传播 ↗](../../../scripts/dev-review.ts#L114 "支持子进程退出触发整体关闭、健康端点轮询、超时失败及成功地址输出。") [独立 Vite 代理 ↗](../../../scripts/dev-review-vite.ts#L18 "支持评审前端使用独立配置、严格端口、回环监听、API 代理及信号关闭。")

关闭流程可重入，并在 Windows 调用 `taskkill` 清理进程树、在其他平台向子进程组发送 `SIGTERM`，同时设置退出等待上限。参考 [跨平台有界关闭 ↗](../../../scripts/dev-review.ts#L17 "支持退出等待上限、Windows 进程树终止、非 Windows 进程组信号和可重入关闭流程。") 端口探测会先关闭临时监听再返回，因此真实服务绑定前仍存在端口被抢占的竞态。参考 [开发端口探测 ↗](../../../scripts/dev-ports.ts#L5 "支持端口输入校验、占用处理及探测服务器关闭后返回端口，由此说明真实绑定前的竞态边界。")

<a id="deterministic_browser"></a>
## 确定性数据下验证完整用户闭环

主浏览器验收在临时目录中组装真实应用、Store、HTTP 服务和无头 Chromium；文件明确将其界定为 Vue、API、SQLite 的真实测试，同时使用确定性 ACP、飞书注册、既有应用与能力探测夹具稳定外部输出。因此它验证应用编排和界面合同，不代表真实 Agent CLI 或飞书网络可用。参考 [真实应用与确定性夹具 ↗](../../../scripts/browser-smoke.ts#L1 "支持临时目录、真实 Vue/API/SQLite 边界、Store 与应用启动、确定性 Agent 和飞书夹具及 Chromium 初始化。")

测试从界面保存材料开始，继续检查提案评估与应用、学习状态、原证据和通知详情，形成从捕获到可追溯结果的闭环。参考 [材料到可追溯结果 ↗](../../../scripts/browser-smoke.ts#L193 "支持界面捕获材料、提案评估与应用、学习状态、原证据和通知详情组成的主闭环。") 后续场景覆盖多视口布局、百层证据轨迹、模型与投递失败展示、API 离线、重启恢复，以及 Markdown、Mermaid 和危险标签过滤。参考 [布局、容量与故障边界 ↗](../../../scripts/browser-smoke.ts#L567 "支持多视口、百层证据、故障展示、重启恢复及富文本安全渲染的验收范围。")

<a id="knowledge_reading"></a>
## 仓库知识阅读的两类浏览器验收

面向已运行个人应用的脚本从真实 API 动态取得文章和固定引用，检查代码行展开、焦点归还、多层阅读轨迹、深链刷新、README 连贯渲染及三种视口下的基本可读性，并保存截图与报告。参考 [真实仓库知识界面 ↗](../../../scripts/code-wiki-viewport.ts#L34 "支持动态取得真实文章与引用，并检查代码展开、阅读轨迹、README 渲染、多视口和报告产物。")

另一项隔离验收即时创建小型源码仓库，执行仓库、材料和代码同步，发布固定知识文章，再启动真实 Store、Review 应用和 Chromium；这些数据由脚本构造，不依赖 LLM。参考 [隔离知识环境构造 ↗](../../../scripts/knowledge-browser.ts#L1 "支持创建临时源码仓库、同步材料与代码、发布固定知识，并启动真实 Store、Review 应用和 Chromium。") 它进一步检查五层引用导航、源码到知识文章的跳转、问题由用户显式转为待办，以及 HTML 原文只展示而不执行。参考 [隔离阅读交互验收 ↗](../../../scripts/knowledge-browser.ts#L49 "支持多层引用导航、深链与焦点恢复、源码跳转、待办创建和 HTML 转义检查。")

两类检查相互补充：前者验证当前仓库知识在统一应用中的真实阅读路径，后者用可控材料深入验证阅读组件。现有断言不比较截图像素，也没有验证语义检索索引。

<a id="live_validation"></a>
## 外部 Agent、学习与 Lark 的在线检查

在线模型辅助函数先通过 ACP 读取可选模型，再依次考虑显式环境变量、基础配置、ACP 当前值和首个候选；显式请求不可用时失败。推理强度则直接由环境变量覆盖，辅助函数本身没有发现其允许值。参考 [ACP 模型能力选择 ↗](../../../scripts/live-model.ts#L4 "支持运行前探测可选模型、模型选择优先级及推理强度覆盖行为。") 最小 ACP 冒烟发送一道答案为 12 的中文题，收集流式文本并输出实际配置。参考 [最小 ACP 在线对话 ↗](../../../scripts/live-acp-smoke.ts#L10 "支持真实 ACP 中文问题、流式文本收集、答案检查和实际运行配置输出。")

真实学习脚本先在临时 Store 捕获中文责任承诺，再依次运行 extractor、独立 verifier 和策略评估；只有安全自动应用且产生回执才通过，并保存角色 trace、评估及任务报告。参考 [真实模型学习闭环 ↗](../../../scripts/live-learning-smoke.ts#L17 "支持临时材料捕获、extractor、独立 verifier、策略应用、回执检查和审计报告的完整在线流程。")

Lark 连接器冒烟读取固定 Wiki 页面，并用统一捕获合同解析后输出摘要。参考 [Lark 文档在线读取 ↗](../../../scripts/live-connectors-smoke.ts#L1 "支持连接器冒烟读取固定 Wiki 页面、用统一捕获合同解析并输出摘要字段。") 其底层实现限制文档主机和路径，通过 `lark-cli` 获取 Markdown，并保留原文链接及引用元信息。参考 [Lark 文档捕获实现 ↗](../../../apps/server/src/connectors.ts#L76 "支持 Lark URL 限制、lark-cli 调用、响应校验及原文、链接和引用元信息的捕获。") Lark 宿主检查则要求真实密钥与活动连接，防止默认发送待投递消息，完成官方能力预检后等待 `connected` 事件，并在结束时停止宿主、关闭存储。参考 [Lark 宿主在线验证 ↗](../../../scripts/live-lark-host-smoke.ts#L15 "支持密钥与活动连接要求、待投递保护、官方能力预检、connected 等待和资源清理。")

这些脚本定义了外部链路的检查入口，但材料没有提供本次运行报告；“返回可解析”或“产生 connected 事件”也不能证明完整消息送达、全部任务字段正确或长期稳定运行。
