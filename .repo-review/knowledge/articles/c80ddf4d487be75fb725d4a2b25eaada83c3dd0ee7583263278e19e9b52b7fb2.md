# scripts · 模块理解 · 专题 1

scripts 模块连接开发环境编排、确定性浏览器验收与依赖真实外部能力的实时冒烟检查：前者保证 personal/review 服务正确启动和退出，中间层验证真实 UI、API、SQLite 与证据 Trail，后者探测 ACP、学习流程及 Lark 集成；三类脚本的证明边界不可混同。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="responsibility"></a>
## 职责分层与设计背景

该模块不是单一运行库，而是三类可执行入口的集合。开发编排层让 personal 与 repo-review 共用端口选择、健康门禁和进程生命周期；极薄的 personal 入口只设置模式，再委托共享编排器。[个人开发入口说明 ↗](95f1e4345cf426421db1dc51b11fff13b7cf14649dccb2589f0a89adf2339372.md#delegation "说明 personal 入口只注入模式并委托共享开发编排器，支持职责分层。")[个人模式入口实现 ↗](../../../scripts/dev.ts#L1 "入口代码直接显示模式赋值与动态导入，是委托关系的固定依据。") review 的 Vite 子进程则绕开个人应用代理配置，严格绑定选定端口并把 `/api` 指向同次启动的 review 后端。[Review 前端配置隔离 ↗](../../../scripts/dev-review-vite.ts#L1 "说明专用 Vite 不读取个人代理配置，并从环境取得 review 前后端端口。")

验收层以真实 Vue、API、SQLite 和 Chromium 检查产品行为，但用固定 Agent、知识或外部适配器换取可重复结果。[个人助手浏览器测试装配 ↗](93b9183049321710c3d8406ee8d8bf2378b3c4459a5e2106c486a2e800f3c1e3.md#purpose_setup "支持真实 Vue、API、SQLite 与 Chromium 配合确定性外部 fixture 的验收定位。")[固定知识链浏览器回归 ↗](../../../scripts/knowledge-browser.ts#L14 "支持临时仓库、固定知识发布和真实浏览器组成不依赖模型的集成测试链。") 实时层另行接触 Agent CLI、Lark CLI、真实凭据和网络，用来回答“外部集成此刻是否可用”，不能替代确定性回归。

<a id="development_flow"></a>
## 开发启动与生命周期

共享编排器先校验并探测 API、Web 端口：显式端口占用会失败，默认端口占用则申请系统分配端口；探测后会释放监听，因此再次绑定前仍有竞态。[开发端口选择逻辑 ↗](../../../scripts/dev-ports.ts#L3 "支持端口范围校验、回环监听探测、显式占用失败和默认端口回退行为。") 随后按模式启动不同 API 入口及专用 Vite，把最终端口同时传给后端和代理，并禁止二者相同。[开发模式启动链 ↗](../../../scripts/dev-review.ts#L81 "支持按模式选择端口和 API 入口、禁止端口相同并传递最终环境变量。") API 最多等待约 60 秒健康响应，Web 只要求子进程未提前退出。[API 就绪门禁与失败传播 ↗](a74183dc494df06cd9b8406ca75119754295c4c008e72594d207fa41925ecdb4.md#readiness "支持子进程失败传播、API 健康轮询时限以及 Web 没有独立 HTTP 就绪探测的结论。")

任一子进程失败都会触发统一关闭。Windows 使用进程树强制终止，其他平台向独立进程组发送 SIGTERM；关闭有等待上限，但非 Windows 超时后不会升级为 SIGKILL，也没有自动重启。[跨平台有界进程关闭 ↗](a74183dc494df06cd9b8406ca75119754295c4c008e72594d207fa41925ecdb4.md#shutdown "直接支持重入保护、Windows 进程树终止、非 Windows 进程组 SIGTERM、等待上限及无强制升级的限制。") Vite 自身只负责严格端口、代理和信号关闭，不承担健康探测。[Vite 严格端口与信号处理 ↗](../../../scripts/dev-review-vite.ts#L22 "支持 Vite 仅负责本地监听、严格端口、API 代理及收到信号后的关闭。")

<a id="acceptance_flow"></a>
## 确定性浏览器验收

个人助手浏览器脚本覆盖材料捕获、提案与决策、通知、不可变历史、待办及飞书接入。[个人助手核心产品流程 ↗](93b9183049321710c3d8406ee8d8bf2378b3c4459a5e2106c486a2e800f3c1e3.md#core_flows "支持材料、提案、证据、历史版本、待办、决策和飞书接入等核心浏览器验收范围。") 失败状态展示、服务重启后的持久化和百层证据链属于另一组边界验收。[失败、持久化与深证据链验收 ↗](93b9183049321710c3d8406ee8d8bf2378b3c4459a5e2106c486a2e800f3c1e3.md#boundaries "专门支持多视口和百层证据链、失败状态展示以及重启后数据持久化的论断。") 其中提案评估与任务完成由脚本直接驱动，ACP 使用协议 fixture，所以结论是产品链路可工作，而不是真实模型已执行。[提案与任务的确定性驱动 ↗](../../../scripts/browser-smoke.ts#L216 "显示提案经内部接口注入、任务由脚本直接领取并完成，界定其不等于真实 ACP 执行。")

知识阅读脚本以临时仓库和固定五层知识链验证内联引用、Esc 回退、深链恢复、焦点归还、响应式、显式创建待办及 HTML 原文不执行。[知识 Trail 交互断言 ↗](../../../scripts/knowledge-browser.ts#L46 "支持五层阅读、Esc 回退、深链恢复、焦点归还以及响应式和源码安全检查。") Code Wiki 视口脚本检查多视口、Markdown 清洗和可见文本不泄露内部标识；但后续边只取首个可用项，焦点也主要按文本判断，不能扩大为任意跨文件调用或完整无障碍合规。[Code Wiki 安全与标签检查 ↗](../../../scripts/code-wiki-viewport.ts#L174 "支持实际挂载 Markdown 组件的恶意输入清洗，以及 Trail 可见文本隐藏内部标识。")[Code Wiki Trail 验收边界 ↗](f1c91daeb9d0f0aab5183d80767de8777e66dc8f4e738c6290837a28859c8e77.md#security_accessibility "解释边选择器、焦点结果和模型降级检查的实际断言强度，避免扩大测试结论。")

<a id="live_integrations"></a>
## 实时检查、进展与限制

实时 ACP 检查先探测可选模型，再发起受控算术会话；显式模型不可用时拒绝降级，但 effort 仅写入 profile，探测也没有本地超时。[实时模型能力选择 ↗](../../../scripts/live-model.ts#L4 "支持 ACP 模型候选探测、选择优先级、显式不可用失败及 effort 未在此处校验的限制。") 算术脚本的硬条件只是答案包含 `12`，事件类型和实际配置仅作诊断。[ACP 实时算术判定 ↗](../../../scripts/live-acp-smoke.ts#L19 "支持文本事件聚合、答案包含 12 的硬断言，以及模型和事件仅用于诊断输出。") 实时学习则串起 extractor、独立 verifier 与 `MemoryService`，要求单提案得到 `auto_apply` 回执，但任务字段尚无行为级断言。[实时学习角色链 ↗](../../../scripts/live-learning-smoke.ts#L73 "支持 extractor、verifier、策略评估与回执检查，并显示任务列表只被写入报告。")

Lark 内容脚本只确认固定 Wiki 可转成 Capture 合同。[Lark 内容连接器检查 ↗](../../../scripts/live-connectors-smoke.ts#L1 "支持固定 Wiki 经 larkInput 读取并由统一 Capture Schema 校验，同时说明结果仅输出诊断摘要。") Runtime Host 检查先要求密钥、活动连接并通过待投递安全门，[Lark 主机启动安全门 ↗](540a996bb23c4e2fa02aafea9611a4edbf78f53b197eb99c9a06bba734293a4b.md#guards "支持密钥要求、积压投递默认阻断、活动连接读取及凭据一致性检查等启动前置条件。") 再完成官方能力探测和主机依赖组装，[Lark 能力验证与主机组装 ↗](540a996bb23c4e2fa02aafea9611a4edbf78f53b197eb99c9a06bba734293a4b.md#capability "支持官方能力探测必须无缺项，并说明 Runtime Host 与 Store、记忆服务、onboarding 和密钥存储的组合关系。") 最后轮询 `connected` 并清理资源。[Lark 连接判定与清理 ↗](540a996bb23c4e2fa02aafea9611a4edbf78f53b197eb99c9a06bba734293a4b.md#assertions "支持 connected 事件轮询、约九十秒窗口、诊断输出和 finally 中停止主机与关闭 Store。") 它仍未验证真实消息收发、重连或投递完成；显式放行积压投递还可能产生外部副作用。
