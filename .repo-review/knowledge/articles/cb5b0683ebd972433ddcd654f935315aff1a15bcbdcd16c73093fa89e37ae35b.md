# project · 模块理解

omem 是以不可变证据为基础的个人工作记忆与助理系统；项目层统一组织知识管线、仓库评审适配、Vue 共享界面与 osdk 工程流程。仓库材料适配和可提交知识产物已有实现记录，但跨文件调用解析、语义检索、全面自动重核验、多租户隔离及部分运行验收仍有限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责与设计背景

omem 面向个人工作记忆与助理场景，将文本、图片、链接和上下文保存为不可变证据，问答、受治理记忆、待办、通知及仓库 Wiki 沿用同一证据链。[个人助理与统一证据链 ↗](../../../README.md#L1 "支持多类输入形成不可变证据，并让问答、记忆、待办、通知和 Wiki 沿用同一证据链。") 派生答案不作为新的独立证据；召回派生正文时仍回到原始 Fragment，并保留原有可见性过滤。[派生答案与原始证据边界 ↗](../../../AGENTS.md#L10 "直接支持派生答案不是独立证据，以及派生正文召回仍返回原始 Fragment 的论断。")

知识处理复用 Capture→Source/Revision/Fragment、持久任务和角色运行网关；代码、文档、对话与图像经专门角色分析和独立复核后，组织成模块、主题与概览。AST 提供代码定位及明确结构关系，语义解释仍依赖模型分析与复核。[通用知识整理流程 ↗](../../../README.md#L20 "支持通用证据处理链、独立复核、章节组织，以及 AST 定位与模型语义分析的职责划分。") Code Wiki 因而只是统一管线上的仓库输入适配器和派生阅读视图，而非独立产品或另一套事实权威。[Code Wiki 的派生视图定位 ↗](../../../AGENTS.md#L16 "支持 Code Wiki 复用通用知识管线并仅作为仓库适配器和隔离运行配置。")

<a id="structure"></a>
## 工程结构与跨模块关系

pnpm 工作区以 `apps/*` 和 `packages/*` 为边界组织应用与共享包。[pnpm 工作区范围 ↗](../../../pnpm-workspace.yaml#L1 "支持应用与共享包由 apps 和 packages 两类直接子目录组织。") Web 应用通过工作区链接复用 `packages/ui`，两者共享 Vue、Markdown 渲染、代码高亮和 HTML 净化依赖。[Web 与共享界面依赖 ↗](../../../pnpm-lock.yaml#L58 "支持 Web 通过工作区链接复用共享 UI，并共享富文本展示相关依赖。") UI 约定要求公共组件只承载 props、slots 与 emits，网络和状态留在 Web 应用层。[界面组件职责边界 ↗](../../../.agents/skills/omem-design/SKILL.md#L8 "支持 Vue 共享组件复用及网络、应用状态留在 Web 层的边界。")

运行时与应用依赖由 osdk 统一管理：任务通过 `osdk run` 执行，工具安装和项目依赖兑现分别由 `install` 与 `deps` 承担。[osdk 任务与依赖分工 ↗](../../../.agents/skills/osdk-guide/SKILL.md#L39 "解释项目任务、工具安装和应用依赖兑现分别使用的 osdk 能力。") `--frozen` 约束原生锁文件存在且不被修改，`--verify` 则核验实际安装环境，两者分别保障声明可复现性和落地完整性。[冻结依赖与环境核验 ↗](../../../.agents/skills/osdk-guide/reference/commands.md#L109 "支持 frozen 锁文件约束和 verify 已安装环境校验的不同职责。")

<a id="workflow"></a>
## 知识生产与阅读流程

正文生产遵循“分析原始材料—独立复核—组织章节”的顺序；引用贴近论断并携带可读名称、理由和固定目标。无法确认的内容保留为调查项，错误或过期结果不得覆盖有效知识。[正文分析、复核与调查合同 ↗](../../../AGENTS.md#L28 "支持先分析再复核和组织、内联固定引用、保留调查项及失败结果不得覆盖有效知识。") 阅读侧复用共享 Evidence Trail：内部标识只服务路由和深链，界面展示可读标签；帧栈保存层级与滚动位置，Esc 退层，关闭后恢复焦点。[共享证据阅读 Trail ↗](../../../AGENTS.md#L20 "支持可读标签与内部标识分离，以及帧栈、滚动、Esc 退层和焦点恢复行为。") 交互规范还要求递归阅读保存当前草稿，且问答不得丢失当前证据。[证据阅读草稿与上下文保存 ↗](../../../.agents/skills/omem-design/SKILL.md#L11 "直接支持递归引用保存路径、滚动与草稿，并保证问答不丢失当前证据。")

仓库评审将阅读恢复、全仓分析、局部生成和索引重建分成不同入口，只有显式分析或生成才调用模型；隔离运行使用独立 SQLite，且不启动个人业务 worker。[仓库评审运行入口 ↗](../../../README.md#L24 "解释阅读恢复、全仓分析、局部生成、索引重建和隔离运行之间的区别。") 已复核正文保存为 JSON 和带内联链接的 Markdown，运行数据、私有环境与派生知识不重新充当独立证据；已有记录覆盖仓库材料、知识恢复和开发生命周期的十个用例。[仓库材料适配与已验证产物 ↗](../../../docs/implementation/knowledge-pipeline.md#L31 "支持已复核正文保存、派生内容不作为独立证据，以及相关用例的进展记录。")

<a id="progress_limits"></a>
## 进展、治理与限制

工程治理要求用真实退出码和行为断言验证功能，UI 另做浏览器检查；完成的垂直切片需连同测试、文档及剩余限制及时独立提交。当前 SQLite/shared-token 实现明确是单用户系统，不能视为已有租户强制隔离。[工程验证与单用户边界 ↗](../../../AGENTS.md#L5 "支持真实行为验证、浏览器检查、切片提交要求，并直接说明当前没有租户强制隔离。") review 的模型与 effort 需经 ACP 校验，运行数据库和构建暂存留在忽略目录，只有明确保存的知识资产进入发布区域；跨文件调用和跨修订符号、片段身份续接尚未实现。[模型、发布与解析限制 ↗](../../../AGENTS.md#L23 "支持显式模型配置、ACP 校验、运行数据与知识发布分离，以及跨文件和跨修订身份限制。")

仓库还明确列出三项未交付能力：跨文件调用的精确类型解析、embedding 检索，以及所有来源的自动重核验。[尚未交付的知识能力 ↗](../../../README.md#L52 "直接支持精确跨文件调用解析、embedding 检索和所有来源自动重核验仍未完成。") 因而当前可确认的是统一证据管线、仓库材料适配和可提交知识产物已有基础，不能据此推断语义检索、全面增量维护或团队权限体系已经完成。

<a id="runtime_boundary"></a>
## 配置与数据安全边界

osdk 配置按 CLI、环境变量、项目配置、用户配置和内置默认依次覆盖；会执行代码或削弱校验的设置需要显式信任，受管源和配置应通过 osdk 命令修改。[osdk 配置优先级与信任边界 ↗](../../../.agents/skills/osdk-guide/SKILL.md#L48 "支持配置覆盖次序、高风险设置需要信任及受管配置应通过 osdk 修改。") 本地加密密钥必须跨重启保持稳定，丢失或轮换会使已有秘密文件不可读，并要求重新授权相关应用。[本地加密密钥生命周期 ↗](../../../.env.example#L1 "支持密钥需稳定保存，以及丢失或轮换将导致已有秘密不可读。")

版本控制区分可发布知识与实时状态：整理后的知识资产继续受版本控制，repo-review 的运行目录、缓存、临时文件、模型输出和 embedding 数据被排除。[仓库评审数据与知识边界 ↗](../../../.gitignore#L15 "支持实时运行数据、缓存和模型产物被忽略，而整理后的知识资产继续受版本控制。") 这些规则说明预期的数据生命周期，但不能单独证明当前部署已经正确配置密钥、处理历史运行数据或完成恢复演练。
