# 统一检索单位的生成与增量投影

该实现把原始材料与知识文章，以及待办事项和记忆转换成统一、可替换的检索单位，保留固定版本的证据锚点与可见性范围。它负责内容切分和准入过滤，也处理增量失效与事务替换，并用独立版本维护中文及代码标识符的词面索引。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为什么需要检索投影

这段代码维护一层可替换的检索投影，把材料与知识文章纳入同一种单位表示，也为待办事项和记忆构造对应单位。`RetrievalUnit` 在命中结构上增加 `owner`、`visibilityIds`、`topicPath` 与 `subtype`；四类单位还会各自写入 `target`、`references` 和可见性范围，用来保留命中对象及其证据关联。参考 [检索单位结构与版本 ↗](../../../apps/server/src/retrieval/units.ts#L1 "说明检索投影的定位、检索单位附加字段以及结构版本常量。") [源材料单位生成 ↗](../../../apps/server/src/retrieval/units.ts#L343 "支持无 fragment 段落被排除，以及检索单位正文、上下文、目标、引用、可见性和来源信息的构造。") [知识章节投影 ↗](../../../apps/server/src/retrieval/units.ts#L686 "支持只投影受支持章节、标注复核状态并构造知识检索单位。") [待办事项检索单位 ↗](../../../apps/server/src/retrieval/units.ts#L753 "支持事项文本、状态上下文、目标、证据引用与可见性字段的生成方式。") [记忆检索单位 ↗](../../../apps/server/src/retrieval/units.ts#L821 "支持只处理 active 记忆、展开结构化正文并构造目标，以及从证据集还原引用与可见性。")

原始材料从 revision 的 `body.parts` 还原文本；文本与链接会按捕获格式拼接。材料标为派生内容时，`materialFromRow` 直接返回 `null`，避免生成内容再次冒充原始证据。参考 [材料正文还原 ↗](../../../apps/server/src/retrieval/units.ts#L199 "支持从 revision body 还原文本、图片和来源信息，并排除派生材料。")

<a id="source_flow"></a>
## 一份源文件如何变成可搜索结果

以当前 source 头版本的一份 TypeScript 文件为例，`sync` 或 `syncAsync` 先驱动 `changes`，再检查词面索引版本。`changes` 会对材料头、知识状态、待办事项和记忆状态计算总签名；签名没变便停止投影工作，但词面版本检查仍会执行。材料版本或描述版本变化时，它调用 `sourceUnits` 重建该 owner；owner identity 未变化时，如果上下文记录的材料 revision 或层级版本不匹配，则保留单位与向量 ID，只回填层级。参考 [同步、总签名与词面刷新 ↗](../../../apps/server/src/retrieval/units.ts#L443 "支持同步和异步驱动 changes、总签名未变化时跳过投影工作，并在其后检查词面索引版本。") [材料增量重建 ↗](../../../apps/server/src/retrieval/units.ts#L515 "支持按材料 revision 与描述版本替换 owner，并在 owner identity 未变化而上下文记录的材料 revision 或层级版本不匹配时回填层级，保留已有单位与向量 ID。")

```mermaid
flowchart LR
  A[sync / syncAsync] --> B[changes 检查签名与 owner identity]
  B --> C[materialFromRow 还原当前材料]
  C --> D[sourceUnits 选择切分器]
  D --> E[codePassages 或 markdownPassages]
  E --> F[sourceAnchor 绑定版本、行号与片段]
  F --> G[replace 原子替换单位、FTS 与层级]
  G --> H[refreshLexicalIndex 检查词面版本]
```
参考 [同步、总签名与词面刷新 ↗](../../../apps/server/src/retrieval/units.ts#L443 "支持同步和异步驱动 changes、总签名未变化时跳过投影工作，并在其后检查词面索引版本。") [材料增量重建 ↗](../../../apps/server/src/retrieval/units.ts#L515 "支持按材料 revision 与描述版本替换 owner，并在 owner identity 未变化而上下文记录的材料 revision 或层级版本不匹配时回填层级，保留已有单位与向量 ID。") [原子替换与失效清理 ↗](../../../apps/server/src/retrieval/units.ts#L905 "支持清理失效 owner、裁剪缓存，并在事务内同步替换结构化单位、FTS 和层级。") [标识符分词与词面索引刷新 ↗](../../../apps/server/src/retrieval/units.ts#L981 "支持中文词边界、小写化、标识符组成词展开，以及按独立版本重建 FTS 而保留其他索引身份。")

代码材料按 AST 符号切分，函数或方法中的局部常量留在所属操作内；类条目不重复索引整段方法体，未被符号覆盖的 import、初始化与配置仍会形成独立段落。参考 [代码符号筛选 ↗](../../../apps/server/src/retrieval/units.ts#L92 "支持 AST 符号切分时将局部常量保留在所属函数、方法或容器内。") [代码段落构造 ↗](../../../apps/server/src/retrieval/units.ts#L127 "支持类与方法去重、注释归属、标题路径和未覆盖模块内容的补充索引。") 文档材料按 Markdown 块切分，并记录标题路径；冒号结尾的说明可与紧随的表格、列表、代码块或引用合并，只有标题的文档也能形成结果。参考 [Markdown 切分 ↗](../../../apps/server/src/retrieval/units.ts#L33 "支持按块和标题路径切分、合并引导段与复杂块，以及标题-only 文档的回退行为。")

`sourceUnits` 根据扩展名选择代码或文档切分；纯图片材料以图片标签形成段落。每段必须能映射到至少一个 fragment，随后写入正文和标题路径，并附上上下文、来源信息及固定 `SourceAnchor`。该锚点包含材料 key 与 revision，也记录 digest、行号及相交片段 ID，因此一次检索命中可以返回确切版本和范围。参考 [证据锚点与切分选择 ↗](../../../apps/server/src/retrieval/units.ts#L263 "支持 SourceAnchor 固定材料版本、行号和片段，并说明代码、文档及图片材料的切分分支。") [源材料单位生成 ↗](../../../apps/server/src/retrieval/units.ts#L343 "支持无 fragment 段落被排除，以及检索单位正文、上下文、目标、引用、可见性和来源信息的构造。")

`replace` 在一个事务中删除 owner 的旧单位，再写入结构化表、FTS5 表和材料层级；写 FTS 前会移除引用标记。`indexText` 使用中文词边界并统一为小写，还会保留标识符整体并补充 camelCase、下划线、点号或连字符分出的组成词。`LEXICAL_VERSION` 与检索单位版本分开；版本变化时，`refreshLexicalIndex` 只重建 FTS 行，保留原单位身份、向量头和嵌入预处理版本。替换或刷新失败时，相应事务或保存点会回滚。参考 [原子替换与失效清理 ↗](../../../apps/server/src/retrieval/units.ts#L905 "支持清理失效 owner、裁剪缓存，并在事务内同步替换结构化单位、FTS 和层级。") [标识符分词与词面索引刷新 ↗](../../../apps/server/src/retrieval/units.ts#L981 "支持中文词边界、小写化、标识符组成词展开，以及按独立版本重建 FTS 而保留其他索引身份。")

<a id="boundaries"></a>
## 不同来源的准入规则与修改位置

知识文章不会无条件进入索引。调查材料与递归依赖必须仍可取得，章节状态必须为 `current`；note、retired、planned 文章被排除。可用文章只投影受支持章节，并递归收集原始片段作为可见性范围；文章还有其他章节需要复核时，命中目标会带 `needs-review`。参考 [文章有效性、引用与可见性 ↗](../../../apps/server/src/retrieval/units.ts#L603 "支持递归检查输入，排除不发布状态，并从材料依赖计算文章引用和可见片段范围。") [知识章节投影 ↗](../../../apps/server/src/retrieval/units.ts#L686 "支持只投影受支持章节、标注复核状态并构造知识检索单位。")

待办事项按当前版本生成一个单位，正文包含详情、下一步、到期时间与跟进状态；事项绑定证据 fragment 时，会反查材料行号并建立引用。记忆只处理 `active` 项，将结构化 body 展开为可搜索文本，并把证据集中的 fragment 或 source revision 转成可见性与引用。参考 [待办事项检索单位 ↗](../../../apps/server/src/retrieval/units.ts#L753 "支持事项文本、状态上下文、目标、证据引用与可见性字段的生成方式。") [记忆检索单位 ↗](../../../apps/server/src/retrieval/units.ts#L821 "支持只处理 active 记忆、展开结构化正文并构造目标，以及从证据集还原引用与可见性。")

边界处理分为三层。`markdownPassages` 与 `codePassages` 决定切分粒度，`sourceUnits` 和文章有效性判断控制来源是否可见，`replace` 与 `indexText` 决定索引字段和词面预处理。投影结构或切分规则变化时应更新 `UNIT_VERSION`，使 owner identity 失效并触发单位重建；只改词面预处理时应更新 `LEXICAL_VERSION`，让全文索引单独刷新。已不再需要的 owner 会被清空，材料缓存也只保留当前 source 头版本。参考 [检索单位结构与版本 ↗](../../../apps/server/src/retrieval/units.ts#L1 "说明检索投影的定位、检索单位附加字段以及结构版本常量。") [原子替换与失效清理 ↗](../../../apps/server/src/retrieval/units.ts#L905 "支持清理失效 owner、裁剪缓存，并在事务内同步替换结构化单位、FTS 和层级。") [标识符分词与词面索引刷新 ↗](../../../apps/server/src/retrieval/units.ts#L981 "支持中文词边界、小写化、标识符组成词展开，以及按独立版本重建 FTS 而保留其他索引身份。")
