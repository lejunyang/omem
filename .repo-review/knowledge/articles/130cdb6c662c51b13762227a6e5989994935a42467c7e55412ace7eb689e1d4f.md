# 统一检索单位：把异构记忆投影成可搜索上下文

该文件把当前原件、知识文章、事项和已应用记忆转换为统一的 RetrievalUnit，并以 owner 和版本身份增量刷新 SQLite 正文表与 FTS 表。它负责结构切分、来源锚点、可见性和上下文保真；最终相关性排序不在这个文件中完成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为什么需要检索单位

原始修订要保持不可变，阅读页又按人的问题组织；搜索不能直接把二者当成同一种大文本。这个文件因此建立一层**可替换的检索投影**，并用统一字段保存正文、上下文、定位目标、原文引用、可见性、主题和来源信息。参考 [可替换检索投影 ↗](../../../apps/server/src/retrieval/units.ts#L1 "说明该文件建立独立于不可变存储和阅读页面的可替换检索单位。") [统一单位字段 ↗](../../../apps/server/src/retrieval/units.ts#L14 "支持检索单位携带 owner、可见性、主题路径和子类型等统一元数据。")

原件进入投影时会按类型分流：代码交给 AST 结构切分，普通文本按 Markdown 块切分，纯图片至少以图片标签形成可搜索单位。这样搜索面对的是函数、段落或图片入口，而固定原始修订仍由原存储保存。参考 [原件类型分流 ↗](../../../apps/server/src/retrieval/units.ts#L243 "支持代码、Markdown 文本和纯图片采用不同的 passage 构造方式。")

<a id="flow"></a>
## 一次同步怎样形成可搜索投影

以“某来源产生了新 head 修订”为例：调用方执行 `syncAsync()`，投影器先计算来源、知识、事项、记忆及材料别名的整体签名；若有变化，再读取当前 source head，并以 `UNIT_VERSION + revisionId` 判断该 owner 是否需要重建。参考 [异步同步入口 ↗](../../../apps/server/src/retrieval/units.ts#L407 "说明 syncAsync 会复用进行中的工作，并在各批变化之间让出事件循环。") [签名与来源增量 ↗](../../../apps/server/src/retrieval/units.ts#L415 "支持整体变化签名、当前 source head 读取，以及按 owner 和 revision identity 增量替换。")

```mermaid
flowchart LR
  A[当前数据库 head] --> B[还原材料]
  B --> C[按结构生成 passage]
  C --> D[绑定原文锚点与上下文]
  D --> E[事务替换 owner 的检索单位与 FTS 行]
```

材料还原会合并文本或链接、保留图片与 fragments，并计算稳定摘要；每个 passage 随后绑定行范围，无法对应任何 fragment 的段落不会进入结果。产出的单位包含标题、正文、章节路径、来源时间、参与者及可见 fragment。参考 [数据库行还原材料 ↗](../../../apps/server/src/retrieval/units.ts#L161 "支持正文、链接、图片、别名、摘要和 fragments 如何还原为 KnowledgeMaterial。") [段落绑定原文 ↗](../../../apps/server/src/retrieval/units.ts#L298 "说明 passage 会转换为 source anchor，且没有 fragment 覆盖时会被过滤。") [原件单位上下文 ↗](../../../apps/server/src/retrieval/units.ts#L304 "支持检索单位保存正文、上下文、原文引用、可见性、主题、时间与来源字段。")

最后，`replace` 在同一事务内删除该 owner 的旧单位和 FTS 行，再写入新的结构化单位与 FTS 行；写入 FTS 前用中文 ICU 分词，并从正文中去掉引用标签。这一步的产物是供后续检索读取的持久检索单位及全文索引行。参考 [事务替换检索表 ↗](../../../apps/server/src/retrieval/units.ts#L750 "支持按 owner 删除旧投影，并在事务中写入结构化检索单位与对应 FTS 行。") [中文全文预处理 ↗](../../../apps/server/src/retrieval/units.ts#L811 "说明 FTS 文本通过中文 ICU 分词、过滤非词项并统一为小写。")

<a id="boundaries"></a>
## 结构保真、依赖关系与边界

代码切分依赖 `parseFile` 的符号范围：局部常量留在所属函数或方法内，避免把完整控制流拆碎；类中已有可调用成员时保留成员而不再重复索引整类，未被符号覆盖的 import、配置和顶层初始化也会补成单位。AST 在这里用于结构定位，不代表完整调用图。参考 [代码结构切分 ↗](../../../apps/server/src/retrieval/units.ts#L68 "支持保留完整可调用操作、附带相邻注释，并补齐未被符号覆盖的顶层内容。")

派生来源不会再次被当作原件导入；知识文章只有在材料摘要和文章版本依赖仍匹配时才进入投影，文章引用还会递归还原到原文锚点。事项和 active 记忆各自成为独立 owner，并保留状态或证据关联。参考 [排除派生原件 ↗](../../../apps/server/src/retrieval/units.ts#L161 "说明标记为 derived 的捕获内容不会再次还原为原始材料。") [知识依赖有效性 ↗](../../../apps/server/src/retrieval/units.ts#L470 "支持知识文章必须匹配当前材料摘要与文章修订，并递归剔除失效的文章依赖。") [事项检索单位 ↗](../../../apps/server/src/retrieval/units.ts#L589 "说明事项按自身 owner、版本和状态建立检索投影，并关联可用的原文证据范围。") [活动记忆检索单位 ↗](../../../apps/server/src/retrieval/units.ts#L657 "说明只有 active 记忆被读取，并按当前记忆修订建立独立 owner 与证据关联。")

同步完成后，不再需要的 owner 会从可重建投影中移除，旧 source revision 对应的材料缓存也会回收；这些操作针对检索表和内存缓存，不是删除原始历史。参考 [过期投影清理 ↗](../../../apps/server/src/retrieval/units.ts#L741 "支持移除不再需要的 owner，并清理由旧 source revision 留下的材料缓存。")
