# 统一检索单位的结构化投影与增量更新

说明系统如何把不可变原件、知识文章、事项与活动记忆转换成统一检索单位，保持代码与 Markdown 的可读结构、原文锚点和可见性，并通过 owner/identity 增量替换 SQLite 与 FTS 索引。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-shape"></a>
## 为什么需要独立的检索单位

原始修订适合保真保存，却不一定适合直接搜索：整份代码太大，知识文章、事项和记忆又有不同的状态与证据。这里定义的 `RetrievalUnit` 在命中文本之外统一携带 owner、可见片段、主题路径和子类型；投影可以重建，而旧版本仍留在原始表中。参考 [检索单位合同 ↗](../../../apps/server/src/retrieval/units.ts#L1 "支持检索投影可替换、并统一携带 owner、可见性、主题路径与子类型的说明。")

数据库修订先被还原成 `KnowledgeMaterial`：派生来源被排除，文本、链接、图片、别名、摘要身份和 Fragment 一并整理。代码材料按 AST 符号切片：函数和方法保留完整操作，接口、类型、枚举以及合格的顶层 `const` 等其他符号也可独立成片；局部常量留在所属操作内，带可调用成员的类或组件则由成员片段承载。相邻注释随声明进入片段，未被符号覆盖的 imports、顶层初始化和配置另组成“模块定义与初始化”片段；只有过滤后完全没有符号时才退回全文。参考 [材料行还原 ↗](../../../apps/server/src/retrieval/units.ts#L161 "支持派生来源过滤，以及文本、图片、别名、摘要身份和 Fragment 的还原流程。") [代码符号筛选 ↗](../../../apps/server/src/retrieval/units.ts#L81 "支持完整操作、顶层常量与类或组件的筛选规则，以及过滤后无符号才退回全文的说明。") [代码片段补全 ↗](../../../apps/server/src/retrieval/units.ts#L107 "支持保留相邻注释、为过滤后的各类符号生成片段，并把未覆盖的模块定义与初始化另行成片。")

<a id="representative-flow"></a>
## 一条代码原件如何进入搜索

以新捕获的 `processor.ts` 当前修订为例，流程如下：

```mermaid
flowchart LR
  A[当前修订行] --> B[还原材料]
  B --> C[按代码结构切片]
  C --> D[绑定原文行与 Fragment]
  D --> E[按 owner 原子替换检索单位]
  E --> F[结构表与全文索引]
```

`sourceUnits` 依据扩展名选择代码或 Markdown 切分；图片材料则用图片标签形成可检索文本。每个片段生成稳定 ID，并把标题、层级路径、会话上下文、原文锚点和 provenance 装进结果；若行范围没有对应 Fragment，该片段不会公开。参考 [材料类型分流 ↗](../../../apps/server/src/retrieval/units.ts#L243 "支持代码、Markdown 和纯图片材料采用不同片段生成方式的说明。") [原件单位装配 ↗](../../../apps/server/src/retrieval/units.ts#L298 "支持片段必须绑定 Fragment，并输出稳定 ID、上下文、锚点、可见性与来源信息的流程。")

增量同步为来源建立 `source:<sourceId>` owner，以投影版本和修订号组成 identity；未变化的 owner 被跳过。发生变化时，`replace` 在同一事务中删除旧单位与 FTS 行、写入新单位，再用中文 ICU 分词后的标题、上下文和正文更新全文索引。参考 [来源增量身份 ↗](../../../apps/server/src/retrieval/units.ts#L443 "支持来源 owner 以投影版本和当前修订构成 identity，未变化时跳过重建的说明。") [事务替换与中文索引 ↗](../../../apps/server/src/retrieval/units.ts#L845 "支持 owner 级事务替换、FTS 同步和 ICU 中文分词的说明。")

<a id="boundaries-and-relations"></a>
## 知识状态、证据与其他数据类型

知识文章不是无条件进入索引：它必须已通过复核、未被显式失效、所有输入仍可取得，而且正文引用的固定依赖仍匹配。若引用依据仍受支持但当前依赖已变化，文章仍可召回，不过目标会标记 `needs-review`；文章引用还会递归还原为原始材料锚点，并把全部研究输入纳入可见范围。参考 [文章支持与新鲜度 ↗](../../../apps/server/src/retrieval/units.ts#L533 "支持文章准入条件、显式失效处理，以及 current 状态递归判断的说明。") [文章证据投影 ↗](../../../apps/server/src/retrieval/units.ts#L589 "支持递归还原文章引用、传播可见范围并为非当前文章标记 needs-review 的说明。")

同一投影器也把事项的当前版本、状态与证据范围，以及仅处于 active 状态的记忆及其 evidence set，变成相同结果形态；已不再需要的 owner 会从投影删除。模块边界因此很清楚：AST 解析负责代码定位，Fragment 结构负责原文范围，摘要函数负责材料身份；本文件负责把这些信息装配和持久化，不负责最终相关性排序。参考 [事项与记忆投影 ↗](../../../apps/server/src/retrieval/units.ts#L684 "支持事项当前状态、活动记忆证据及失去 owner 后清理投影的说明。")
