# 统一检索单位的生成与增量投影

该实现把原始材料、知识文章、任务和记忆转换成统一、可替换的检索单位，保留固定版本的证据锚点与可见性范围，并同步写入结构化表、全文索引和材料层级。它同时负责内容切分、有效性过滤、增量失效判断、原子替换及中文分词。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为什么需要检索投影

这段代码维护一层可替换的检索投影，使检索不必直接扫描不可变的材料、知识文章、任务和记忆表。`RetrievalUnit` 在命中结构上增加 `owner`、`visibilityIds`、`topicPath` 与 `subtype`：`owner` 用来成组替换，`visibilityIds` 把结果约束到原始片段，目标和引用则负责把命中带回可阅读的固定内容。原始数据仍留在各自表中，投影只承担检索与导航。参考 [检索单位结构 ↗](../../../apps/server/src/retrieval/units.ts#L1 "说明该文件的投影职责、版本常量以及检索单位新增的 owner、可见性、主题和子类型字段。")

原始材料从 revision 的 `body.parts` 还原文本；文本与链接会按捕获格式拼接。若材料标为派生内容，`materialFromRow` 直接返回 `null`，避免生成内容再次冒充原始证据。参考 [材料正文还原 ↗](../../../apps/server/src/retrieval/units.ts#L199 "支持从 revision body 还原文本并排除派生材料的说明。")

<a id="source_flow"></a>
## 一份源文件如何变成可搜索结果

以当前 source 头版本的一份 TypeScript 文件为例，`sync` 或 `syncAsync` 驱动 `changes`。后者先对材料头、知识状态、任务和记忆状态计算总签名；签名没变便停止。材料版本或描述版本变化时，它调用 `sourceUnits` 重建该 owner，只有上下文层级版本变化时则保留单位与向量 ID，仅回填层级。参考 [同步与总签名 ↗](../../../apps/server/src/retrieval/units.ts#L456 "支持同步和异步驱动 changes，以及总签名未变化时跳过投影工作的说明。") [材料增量重建 ↗](../../../apps/server/src/retrieval/units.ts#L530 "支持按材料 revision 与描述版本替换 owner，并在仅层级版本变化时回填上下文。")

```mermaid
flowchart LR
  A[sync / syncAsync] --> B[changes 检查签名与 owner identity]
  B --> C[materialFromRow 还原当前材料]
  C --> D[sourceUnits 选择切分器]
  D --> E[codePassages 或 markdownPassages]
  E --> F[sourceAnchor 绑定版本、行号与片段]
  F --> G[replace 原子替换单位、FTS 与层级]
```
代码材料按 AST 符号切分，函数或方法中的局部常量留在所属操作内；类条目不重复索引整段方法体，未被符号覆盖的 import、初始化与配置仍会形成独立段落。参考 [代码符号筛选 ↗](../../../apps/server/src/retrieval/units.ts#L92 "支持 AST 符号切分时将局部常量保留在所属函数、方法或容器内。") [代码段落构造 ↗](../../../apps/server/src/retrieval/units.ts#L127 "支持类与方法去重、注释归属、标题路径以及未覆盖模块内容的补充索引。") 文档材料按 Markdown 块切分，并记录标题路径；冒号结尾的说明可与紧随的表格、列表、代码块或引用合并，只有标题的文档也能形成结果。参考 [Markdown 切分 ↗](../../../apps/server/src/retrieval/units.ts#L33 "支持按块和标题路径切分、合并引导段与复杂块，以及标题-only文档回退行为。")

`sourceUnits` 根据扩展名选择代码或文档切分；纯图片材料以图片标签形成段落。每段必须能映射到至少一个 fragment，随后写入正文、标题路径、上下文、来源信息和固定 `SourceAnchor`。该锚点包含材料 key、revision、digest、行号及相交片段 ID，因此一次检索命中可以返回确切版本和范围。参考 [证据锚点与切分选择 ↗](../../../apps/server/src/retrieval/units.ts#L263 "支持 SourceAnchor 固定材料版本、行号和片段，并说明代码、文档及图片材料的切分分支。") [源材料单位生成 ↗](../../../apps/server/src/retrieval/units.ts#L343 "支持无 fragment 段落被排除，以及检索单位正文、上下文、目标、可见性和来源信息的构造。")

`replace` 在一个事务中删除 owner 的旧单位，再写入结构化表、FTS5 表和材料层级；写 FTS 前会移除引用标记。标题、上下文与正文都经过 ICU 中文分词和小写化，所以标准 BM25 可以按中文词搜索。失败会回滚整个替换。参考 [原子替换与清理 ↗](../../../apps/server/src/retrieval/units.ts#L903 "支持清理失效 owner、裁剪缓存，以及在事务内同步替换结构化单位、FTS 和层级。") [中文索引与解码 ↗](../../../apps/server/src/retrieval/units.ts#L979 "支持 ICU 中文分词、小写化以及数据库行还原为 RetrievalUnit 的说明。")

<a id="boundaries"></a>
## 不同来源的准入规则与修改位置

知识文章不会无条件进入索引。调查材料与递归依赖必须仍可取得，章节状态必须为 `current`；note、retired、planned 文章被排除。可用文章只投影受支持章节，并递归收集原始片段作为可见性范围；若文章还有其他章节需要复核，命中目标会带 `needs-review`。参考 [文章有效性与可见性 ↗](../../../apps/server/src/retrieval/units.ts#L601 "支持递归检查输入、排除不发布状态，并从材料依赖计算文章可见片段范围。") [知识章节投影 ↗](../../../apps/server/src/retrieval/units.ts#L684 "支持只投影受支持章节、标注复核状态并构造知识检索单位。")

任务按当前版本生成一个单位，正文包含详情、下一步、到期时间与跟进状态；若任务绑定证据 fragment，会反查材料行号并建立引用。记忆只处理 `active` 项，将结构化 body 展开为可搜索文本，并把证据集中的 fragment 或 source revision 转成可见性与引用。参考 [任务检索单位 ↗](../../../apps/server/src/retrieval/units.ts#L751 "支持任务文本、状态上下文、证据引用和可见性字段的生成方式。") [记忆检索单位 ↗](../../../apps/server/src/retrieval/units.ts#L819 "支持只处理 active 记忆、展开结构化正文并从证据集还原引用与可见性。")

边界处理集中在三处：切分粒度由 `markdownPassages`、`codePassages` 调整；来源是否可见由 `sourceUnits` 和文章有效性判断控制；索引字段与中文分词由 `replace`、`indexText` 控制。修改投影结构或切分规则时还应更新 `UNIT_VERSION`，使 owner identity 失效并触发重建。已不再需要的 owner 会被清空，材料缓存也只保留当前 source 头版本。参考 [检索单位结构 ↗](../../../apps/server/src/retrieval/units.ts#L1 "说明该文件的投影职责、版本常量以及检索单位新增的 owner、可见性、主题和子类型字段。") [原子替换与清理 ↗](../../../apps/server/src/retrieval/units.ts#L903 "支持清理失效 owner、裁剪缓存，以及在事务内同步替换结构化单位、FTS 和层级。")
