# 仓库评审知识服务的 HTTP 入口

该文件是隔离仓库评审服务的组合根：复用通用记忆、检索与知识管线，提供材料浏览、关系查询、同步、代码图谱、固定源码和可选模型理解接口，并以本地来源或令牌限制访问。它主要负责路由、鉴权与资源生命周期，材料捕获、代码解析和知识持久化由其他模块完成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-security"></a>
## 定位与访问边界

`buildReviewApp` 是 repo-review 的 Fastify 组合根。它面向隔离的评审 Store，复用 `MemoryService` 和检索能力，同时明确不装配业务助手、Lark、学习与通知 worker，因此是仓库知识的 HTTP 外壳，而非完整个人助理运行时。[评审服务职责说明 ↗](../../../apps/server/src/review/app.ts#L6 "说明评审服务复用通用记忆与检索，并界定其不承担业务助手和 worker 职责。") 初始化时会创建评审元数据与关系表，组装检索、代码服务和可选理解模型端口，并把通用知识路由接入评审材料仓库、回答保存及文章发布回调。[评审应用初始化与知识路由装配 ↗](../../../apps/server/src/review/app.ts#L75 "支持 Store、检索、代码服务、可选模型端口以及知识保存和发布回调的组装流程。")

所有 `/api/review` 请求共享前置门禁：配置 `REVIEW_TOKEN` 时使用 Bearer token 和恒定时间比较；未配置时检查 loopback Host，并把浏览器 Origin 限制在本地 API、Web 开发端口或同源地址。[评审 API 请求门禁 ↗](../../../apps/server/src/review/app.ts#L97 "支持令牌模式以及无令牌时的 loopback Host 和 Origin 校验行为。") 这一边界仍依赖实际监听与代理部署方式；当前材料只给出应用构建和“绑定 loopback”的设计声明，没有展示调用 `listen` 的启动入口。

<a id="materials-search-sync"></a>
## 材料浏览、检索与同步

材料浏览与关系查询具有不同数据路径：来源列表读取当前 head，版本接口枚举历史 revision，revision 与 fragment 接口返回固定证据及 provenance；关系接口查询已存关系，可按 fragment、状态、类型或代码路径筛选，而 association seed 数量由另一端点单独统计。[材料证据与关系查询路由 ↗](../../../apps/server/src/review/app.ts#L195 "支持来源、版本、固定证据和关系查询的不同数据路径，并表明 seed 数量与关系统计分别取得。") 因此，先前将全部关系查询结果统称为“人工维护关系”的结论已被替代：当前路由本身不能证明每条关系都来自人工 seed。

检索始终把候选限定为来源当前 revision，并在 top-N 前应用可见性与类别过滤。默认情况下会排除 `removed` 来源；只有调用者显式传入 `includeRemoved=true` 时，已移除材料才可进入候选集合，类别过滤则仅在给出 category 时启用。之后通用 retrieval 负责排序，路由再补回标题、版本、片段和路径信息。[检索候选过滤与结果组装 ↗](../../../apps/server/src/review/app.ts#L290 "支持检索始终限定当前 revision、默认排除 removed、显式允许包含 removed，并在 top-N 前按类别和可见集合过滤的结论。") 这替代了此前“搜索总是筛出未移除 fragment”的不完整结论。

完整同步以应用实例内状态位避免两类同步重叠，并依次执行材料捕获、知识恢复和代码投影构建。[完整评审同步入口 ↗](../../../apps/server/src/review/app.ts#L319 "支持实例内同步互斥以及材料同步、知识恢复、代码同步的执行顺序。") 材料适配器枚举仓库文件、排除派生目录和敏感或不安全输入，并按内容哈希保存固定材料；同步末尾只有本轮成功 `captured` 的来源被视为仍存在，其他既有 file source 会被标记 removed。[仓库材料捕获与 removed 对账 ↗](../../../apps/server/src/review/materials.ts#L15 "说明文件筛选、固定捕获和 removed 标记规则：只有本轮成功 captured 的来源被视为仍存在。")

<a id="code-surface"></a>
## 代码图谱与固定源码

代码读取面提供仓库、快照、当前快照、模块、文件、文件内符号、单个符号及边查询；文件可按语言和移除状态过滤，边查询默认不包含 stale 数据。[代码仓库与结构查询端点 ↗](../../../apps/server/src/review/app.ts#L351 "支持仓库、快照、模块、文件、符号和边端点的清单及过滤行为。") 整图接口汇总指定快照的文件、符号与边，并用符号名或文件名生成可读标签。[代码图谱响应组装 ↗](../../../apps/server/src/review/app.ts#L474 "支持整图接口读取代码服务结果，并通过 DTO 和人读标签组织文件、符号与边。")

这些结构来自确定性同步：TypeScript/Vue 解析结果投影到评审 SQLite，声明位置关联已捕获 fragment；相同输入复用快照，未在新解析中重现的旧结构转为 stale。[确定性代码同步设计 ↗](../../../apps/server/src/code/sync.ts#L1 "解释代码图谱的捕获依赖、快照幂等性和 stale 更新语义。") 源码范围接口读取指定或当前快照绑定的固定文本，而不是实时工作树；文件、快照或捕获绑定缺失时返回 404，非法或越界行号返回 400。[快照固定源码范围接口 ↗](../../../apps/server/src/review/app.ts#L400 "支持源码读取固定快照文本及文件、快照、捕获绑定和行号范围的错误边界。") 因而旧快照仍可返回历史字节，未进入捕获链的源码也不会被临时猜测补全。

<a id="understanding-lifecycle"></a>
## 模型理解与资源生命周期

代码理解列表与详情是只读接口：即使没有模型端口，也能读取投影到当前图谱的 seed 或已保存结果，并查看状态、来源、验证信息、替代关系、未知项、输出与引用。[代码理解列表与详情接口 ↗](../../../apps/server/src/review/app.ts#L513 "支持不触发模型即可读取既有理解、seed、状态、替代关系、未知项和引用。") 生成是独立的显式操作；未配置模型返回 503，缺少目标返回 400，拒绝或传输失败映射为 422 或 502，失败记录不会晋升为当前理解。[显式代码理解生成入口 ↗](../../../apps/server/src/review/app.ts#L579 "支持模型可选、目标与预算参数传递、错误状态映射以及失败结果不晋升的行为。") 因此确定性图谱和既有理解可独立使用，实时生成只是可选派生层。

代码专用同步与完整同步共享实例内互斥状态，并同样先刷新材料、恢复知识，再构建代码投影。静态前端仅在构建目录存在时挂载；应用关闭时会关闭检索服务和 Store。[代码同步与关闭清理 ↗](../../../apps/server/src/review/app.ts#L607 "支持代码同步编排、静态资源条件挂载以及检索服务和 Store 的关闭生命周期。") 最近结果与互斥标志都位于单个 `buildReviewApp` 实例内，现有材料没有显示跨进程锁、任务租约或异常退出后的共享恢复机制。
