# 仓库评审知识库的本地 HTTP 应用

该文件是 repo-review 的本地 HTTP 组合根：它在隔离 Store 上提供材料浏览、证据检索、关系查询、同步、确定性代码图、固定快照源码与显式启用的代码理解生成，并负责请求门禁、同步互斥和资源关闭。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-security"></a>
## 定位、模型配置与访问边界

`buildReviewApp` 复用统一的记忆、检索和知识路由，但不启动业务助手、Lark、学习或通知运行时，因此它是仓库评审的隔离入口，而不是另一套事实系统。[评审应用的职责边界 ↗](../../../apps/server/src/review/app.ts#L6 "支持评审服务复用统一记忆与检索，同时不启动业务助手、Lark、学习和通知运行时的说明。") 代码理解模型必须显式传入；默认只提供原始代码图和策展 seed，agent 工作区位于 `.repo-review/runtime`。[代码理解模型的显式配置 ↗](../../../apps/server/src/review/app.ts#L61 "支持模型依赖显式提供、默认不调用实时模型及 agent 工作区位置的论断。")

所有评审 API 都经过请求门禁：配置 token 时使用定时安全比较；否则仅接受回环 Host，并限制浏览器 Origin。[评审 API 请求门禁 ↗](../../../apps/server/src/review/app.ts#L97 "支持 token 定时安全比较、回环 Host 和允许 Origin 的请求限制。") 这只是本地访问边界，不等于租户隔离。静态前端仅在构建目录存在时挂载；关闭时先等待检索服务关闭，再关闭 Store，但若前一步抛错，代码未保证后一步仍执行。[静态资源与关闭流程 ↗](../../../apps/server/src/review/app.ts#L620 "支持静态目录存在时才挂载，以及关闭时先关闭检索服务、随后关闭 Store 的实际顺序。")

<a id="evidence-search-sync"></a>
## 证据检索、知识恢复与同步

搜索先筛选当前 head 中未移除且类别匹配的 fragment，再交给统一 retrieval 排序并补充标题、版本和路由信息，因此可见性过滤发生在 top-N 之前。[评审证据搜索流程 ↗](../../../apps/server/src/review/app.ts#L290 "支持先筛选可见材料，再执行统一检索并补充结果字段的说明。")

全库 `/sync` 与代码 `/code/sync` 都依次捕获材料、恢复知识并同步代码图，且通过两种运行状态互斥；但前者返回材料同步结果 `lastSync`，[全库同步入口 ↗](../../../apps/server/src/review/app.ts#L319 "支持全库同步的互斥检查、三个内部阶段及最终返回 lastSync。") 后者返回代码同步结果 `lastCodeSync`。[代码同步入口 ↗](../../../apps/server/src/review/app.ts#L607 "支持代码同步入口执行相同内部阶段，但最终返回 lastCodeSync 的差异。") 这取代了“两个入口行为完全相同”的旧结论。知识恢复还会重载用户回答与文章；若回答尚未进入文章依赖，就记录失效原因，说明保存回答并不代表正文已经重核对。[评审知识恢复与失效记录 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持恢复用户回答和文章，并在回答尚未进入文章依赖时标记待重核对。")

<a id="code-graph-source"></a>
## 代码图接口与固定源码

代码读取面公开 repository、snapshot、module、file、symbol、edge 和 graph，并在多类响应中补充 DTO 或可读标签。[代码图 HTTP 读取面 ↗](../../../apps/server/src/review/app.ts#L346 "支持 repository、snapshot、module、file、symbol、edge 与 graph 路由及可读 DTO 的说明。") 底层同步是已捕获 fragment 上的确定性投影：相同输入复用 snapshot；树变化时创建新 snapshot，前次解析的 edge 与 symbol 被重新 upsert，未再次产生的解析项转为 stale。[确定性代码知识投影 ↗](../../../apps/server/src/code/sync.ts#L1 "支持代码结构依附于已捕获 fragment、snapshot 身份幂等，以及前次解析 edge 和 symbol 的重新投影与 stale 规则。") 这一结论取代“所有旧结构都会转为 stale”的过度概括。

源码接口按 snapshot-file binding 读取同步时固定的文本，不回退实时工作树；文件、快照或绑定缺失返回 404，非法或越界范围返回 400。[快照固定源码范围接口 ↗](../../../apps/server/src/review/app.ts#L400 "支持源码读取绑定 snapshot 的固定文本、不回退工作树，以及 400 和 404 错误边界。") 历史跳转因此保留固定上下文，但调用边的解析精度仍需解析器材料才能确认。

<a id="understanding-lifecycle"></a>
## 代码理解生成与存储生命周期

理解列表提供状态、置信度、seed、验证、stale、来源和替代关系等摘要；详情接口才进一步提供模型、哈希、unknowns、输出与引用，不存在的详情返回 404。[代码理解列表与详情接口 ↗](../../../apps/server/src/review/app.ts#L513 "支持区分列表的摘要字段与详情独有的模型、unknowns、输出和引用字段。") 这取代了此前把详情字段归给列表接口的结论。生成必须显式启用：无模型返回 503、无目标返回 400；失败状态为 `rejected` 时返回 422，其余失败返回 502，成功才附带完整详情。[显式代码理解生成 ↗](../../../apps/server/src/review/app.ts#L579 "支持模型缺失、目标缺失、预算传递，以及按实际结果状态映射 422 或 502 的流程。")

Store 明确以单用户 SQLite 为当前基础，团队级 Postgres 权限执行仍是后续迁移；初始化会创建私有目录、迁移数据库、收紧文件权限并装配各仓库，异常时关闭数据库后重新抛出。[单用户 SQLite 存储边界 ↗](../../../apps/server/src/store.ts#L4 "支持当前存储是单用户 SQLite、团队权限执行仍待迁移，以及 Store 初始化、权限收紧和异常关闭流程的论断。") 因而本地请求门禁不能被解释为团队级权限控制。
