# 仓库评审服务的 HTTP 组合层

构建隔离的本地 Fastify 应用，组合材料知识、统一检索、关系与代码图接口，并通过令牌或回环来源限制访问。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="composition"></a>
## 服务职责与组件装配

`buildReviewApp` 面向仓库评审场景，在独立 Store 上组合 MemoryService、统一检索、代码知识服务和通用知识路由，不接入个人助手、Lark、通知 worker 或业务令牌体系。代码理解模型必须显式传入；默认只提供确定性代码图与既有知识，不主动调用生成模型。知识回答会保存为材料，发布结果则写入评审知识资产。[评审应用依赖装配 ↗](../../../apps/server/src/review/app.ts#L74 "支持应用复用通用知识与检索组件、模型默认关闭以及知识发布回调的说明。")

<a id="security"></a>
## 访问、健康与数据边界

所有 `/api/review` 请求在设置 `REVIEW_TOKEN` 时以定时安全比较校验 Bearer token；未设置时只接受回环 Host，并将浏览器 Origin 限制在本地 API、Web 端口或同源地址。该门禁适合本地单用户评审服务，不能据此宣称已实现租户级授权。[评审 API 请求门禁 ↗](../../../apps/server/src/review/app.ts#L96 "说明 token 校验、回环 Host 与本地 Origin 限制。")

健康接口的数据目录使用相对路径，同时返回运行模式、端口、最近同步提交、来源数、片段数及检索健康状态。此前“仅暴露相对数据目录和检索状态”的结论已被这一完整返回范围替代。[健康接口返回内容 ↗](../../../apps/server/src/review/app.ts#L154 "支持健康响应包含相对数据目录、端口、同步状态、材料计数和检索健康信息的修正结论。")

<a id="flow"></a>
## 检索、同步与固定源码流程

搜索先从当前修订计算符合 category 和 removed 条件的候选集合，再把片段 ID 集合作为 `visible` 条件交给统一检索，确保过滤先于 top-N。同步端点以互斥状态拒绝并发任务，依次更新仓库材料、恢复知识并同步代码投影。[检索过滤与同步编排 ↗](../../../apps/server/src/review/app.ts#L289 "支持先筛选可见片段再检索，以及材料、知识和代码投影的同步顺序。")

源码读取绑定到指定或当前快照保存的固定文本；文件未捕获时返回不可用，而不会回退到实时工作树。因此历史快照读取保持可追溯，但行号非法、快照缺失和绑定缺失会形成不同失败响应。[快照固定源码读取 ↗](../../../apps/server/src/review/app.ts#L397 "说明源码端点读取快照绑定文本、拒绝工作树回退以及行号和缺失状态的处理。")

<a id="understanding"></a>
## 生成失败语义与资源关闭

代码理解生成是显式 POST：未配置模型返回 503，缺少目标返回 400，校验拒绝与传输失败分别映射为 422 和 502；失败记录不会晋升为当前理解。[代码理解生成失败语义 ↗](../../../apps/server/src/review/app.ts#L576 "支持显式生成入口、模型不可用、参数缺失和生成失败的响应规则。") 应用关闭时，`onClose` 钩子先等待检索服务关闭，再关闭 Store，统一承担正常关停时的资源回收。[应用关闭钩子 ↗](../../../apps/server/src/review/app.ts#L617 "支持应用关闭时依次关闭检索服务和 Store 的资源回收行为。")

这些实现能说明路由语义，却不能证明每条分支已有请求级测试；鉴权、并发冲突、历史源码及模型失败仍需结合测试材料验证。
