# 仓库材料接入个人记忆

说明统一开发入口如何把仓库材料和已复核文章接入个人 Store，并在保留个人数据的前提下处理历史文章、固定版本引用与失效状态；同时区分已通过的自动检查和另文记录的浏览器验收。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="unified-entry"></a>
## 统一入口与数据边界

该能力解决的是仓库知识与个人记忆分散的问题：启动 `osdk run dev` 时明确传入仓库目录，将仓库材料幂等捕获到个人 Store，并恢复 `.repo-review/knowledge` 中的文章。接入过程保留已有个人材料、事项和配置，且启动阶段不调用生成式模型；面向用户的入口已统一，隔离的 review 数据库仅继续承担生成与检索验收。参考 [统一开发入口 ↗](../../../docs/implementation/repository-in-personal-memory.md#L3 "支持仓库材料进入个人 Store、保留个人数据、启动不调用模型及 review 数据库用途的说明。")

<a id="history-and-evidence"></a>
## 历史文章与固定证据

迁移复用既有材料 key 和内容摘要。旧文章依赖的原文会先从已有 review 运行数据补入，再把当前文件重新捕获为 head；文章历史按照固定依赖版本恢复，但过去的复核不会自动获得“当前有效”状态。若旧原文缺失，对应引用仍不可用，界面也不能跳到新版本冒充历史依据；已有有效知识不会被历史导入覆盖。参考 [历史证据迁移 ↗](../../../docs/implementation/repository-in-personal-memory.md#L5 "支持旧原文补入、当前文件成为 head、固定依赖恢复以及历史复核不自动视为当前有效的流程。")

引用解析按对应 source 定位历史材料，避免对每条引用扫描全部历史记录。这使“当前材料”和“历史证据”可以并存，同时保持引用目标与其实际版本一致。参考 [历史引用解析 ↗](../../../docs/implementation/repository-in-personal-memory.md#L5 "支持按 source 查找历史引用并避免逐条扫描全库历史的实现约束。")

<a id="verification-status"></a>
## 已验证范围与剩余验收

文档记录的实现验证包括 `osdk run check`：测试、类型检查和构建均已通过；行为检查还覆盖个人材料保留、重复导入不新增 revision、来源变化后知识失效，以及旧原文仍可阅读。参考 [自动检查结果 ↗](../../../docs/implementation/repository-in-personal-memory.md#L7 "支持测试、类型检查、构建及新增行为检查已经通过的进展陈述。")

真实仓库的统一阅读入口还需要结合另一份浏览器检查记录判断；当前材料只给出其文档指向，因此不能仅凭这里的自动检查宣称浏览器端已经完成全量验收。参考 [浏览器验收指向 ↗](../../../docs/implementation/repository-in-personal-memory.md#L7 "说明真实仓库浏览器检查记录位于另一材料中，限定当前文档能够证明的验收范围。")
