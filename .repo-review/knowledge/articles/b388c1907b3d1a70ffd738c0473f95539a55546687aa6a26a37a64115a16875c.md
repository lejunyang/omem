# Feedback Curator 角色起稿

规定如何把用户纠正整理成同范围可复用的修订候选，同时限制身份确认、证据关联和策略泛化；文档只描述角色预期行为，没有证明反馈整理器或发布流程已经实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="correction-scope"></a>
## 纠正类型与身份条件

Feedback Curator 应先区分事实纠正、负责人或时间调整、方法范围调整，以及单纯满意或不满。只有通过可信 actor binding 的本人反馈才能视为用户确认；转述或群内其他参与者的话不能冒充 owner 决策。修订候选还需同时关联被纠正的 proposal 或 revision 与新的纠正证据，并明确停用内容、替代内容及适用范围。[纠正身份与引用规则 ↗](../../../docs/implementation/batch2/prompts/feedback.md#L3 "支持反馈分类、可信本人确认以及修订必须关联新旧证据和适用范围的说明。")

<a id="generalization-limit"></a>
## 验证和泛化限制

一次“有用”或重复点击不能证明事实正确，也不能形成多个独立成功；任务结果必须有 outcome 或 verification。若新纠正与其他权威证据冲突，应保留分歧并请求背景，而非直接覆盖。角色不得借反馈修改权限、采集范围、预算或自动审批规则；策略变更建议应携带正反例进入离线评测，不能直接发布。[反馈泛化与权限限制 ↗](../../../docs/implementation/batch2/prompts/feedback.md#L8 "说明正面反馈不等于事实验证，冲突必须保留，策略改变只能进入评测而不能直接发布。")
