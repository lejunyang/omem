# omem 实施与维护约定

该文件是仓库的实施治理规范，规定能力判断依据、工程验证边界，以及 Code Wiki 在统一证据链中的交互、关系、模型调用和发布约束；规范本身不等于功能已经实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="capability-governance"></a>
## 能力判断与工程治理

该文件要求以 README 和实施状态文档判断真实能力，早期架构提案不能视为已交付功能；开发应按带测试的具体垂直切片推进。[能力判断与垂直切片原则 ↗](../../../AGENTS.md#L3 "支持不能把架构提案当作实现，以及应按带测试的具体切片推进的论断。") 工程基线包括 Vue 3、TypeScript、共享 UI 和 osdk 依赖管理，并要求以真实退出码、行为断言及必要的浏览器检查验证结果；协议 fixture 不能代替外部 CLI 的 live 检查。每个完成的功能切片应连同测试和必要文档及时独立提交，共享工作区只暂存目标改动，未经请求不推送。[工程验证与提交规则 ↗](../../../AGENTS.md#L5 "支持技术栈、osdk 检查、真实行为验证、切片提交及共享工作区协作要求。")

<a id="evidence-architecture"></a>
## 统一证据链与知识流程

Code Wiki 不是独立产品或新的事实权威，而是统一 Capture→Source/Revision/Fragment 链上的派生视图；repo-review 只承担本仓库输入适配和隔离运行，通用处理继续使用 KnowledgePipeline、RoleRuntimeGateway 与既有任务机制。[Code Wiki 的统一证据链定位 ↗](../../../AGENTS.md#L16 "解释 Code Wiki、通用知识管线与 repo-review 隔离运行配置之间的关系。") 原始修订和固定片段身份不可变，派生答案不能重新冒充独立证据；高置信小范围变化可自主处理，但歧义、背景不足、范围过广或危险操作需要用户决策。[不可变证据与决策边界 ↗](../../../AGENTS.md#L10 "直接支持修订与片段身份不可变、派生答案不是独立证据，以及不同风险操作的决策边界。")

正文流程依次分析原始材料、独立复核并组织主题；引用必须贴近论断，且位置存在不代表语义支持已经成立。无法确认的事项保留为调查项，错误或过期结果不得覆盖有效知识。[正文分析、复核与疑问流程 ↗](../../../AGENTS.md#L28 "支持分析—独立复核—组织的顺序、内联引用语义要求及失败结果不得覆盖有效知识。")

<a id="review-contracts"></a>
## 评审交互、Seed 与关系约束

前端必须区分内部标识和人类可读标签：内部 ID 只供路由与深链使用，缺失或过期目标应不可操作并显示原因。知识、原文和代码阅读共用 packages/ui 的 trail 合同，深链长度预算不得导致渲染栈被静默截断。[人类标签与共享阅读 Trail ↗](../../../AGENTS.md#L20 "支持可见文本不得泄露内部 ID、失效目标需解释，以及各阅读入口共用完整帧栈合同。")

评审边只能来自手工 association seed；理解 locator 同步到当前代码图时若解析失败，应保留 rejected 行，不能覆盖已有好结果，也不能靠语义相似度自动补边。[Seed Locator 校验规则 ↗](../../../AGENTS.md#L22 "支持 association 是评审边来源、locator 解析失败保留 rejected 行及禁止语义相似度自动加边。") 关系目标无法解析则必须单独标为 missing，不能伪装成 confirmed；新增关系须先登记 association，再通过同步构建确定性边。[关系缺失状态与同步入口 ↗](../../../AGENTS.md#L37 "直接支持不可解析关系目标记为 missing，以及通过 association 和同步建立确定性关系的规则。") review 默认只恢复知识，模型生成需显式触发；运行数据库和暂存留在 runtime，明确保存的知识资产才可发布。跨文件 calls 和跨 revision 身份续接仍是已声明边界。[模型触发、发布与解析边界 ↗](../../../AGENTS.md#L23 "支持显式模型调用、runtime 与可发布资产的区分，以及跨文件调用和跨修订身份续接尚未实现。")
