# omem 实施与仓库知识验证约定

该文件定义 omem 的实施边界、依赖与模型管理、证据链原则、提交纪律，以及 repo-review 作为统一记忆系统自应用的维护和验证流程。它属于约束与目标说明，不能单独证明相关能力已经实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="product-boundaries"></a>
## 产品目标与实施边界

omem 的目标是把个人记忆、可追溯问答和主动事项跟进统一在同一套证据体系中，未来学习卡也复用原始证据；代码分析虽需 AST 特化，但不能形成独立事实库。文件明确提醒应以当前进展为准，调研和旧方案不能直接视为已实现能力。[目标与调研状态边界 ↗](../../../AGENTS.md#L1 "支持 omem 的统一记忆目标、AST 不得独立建库，以及调研方案不能视作已实现能力的说明。")

架构以个人使用优先，同时保留团队范围，但文档明确将当前 SQLite 与共享令牌方案界定为单用户实现，不能宣称已经具备租户隔离。统一捕获输入覆盖文本、图片、链接和上下文元数据，且捕获内容不得被当作工具指令；修订与片段身份应保持固定，派生回答也不成为新的独立证据。[用户范围、捕获与证据原则 ↗](../../../AGENTS.md#L7 "说明当前单用户限制、通用捕获输入、安全边界和固定证据身份要求。")

<a id="delivery-verification"></a>
## 交付、验证与提交纪律

验证必须依据真实退出码和行为断言，协议 fixture 不能替代外部 CLI 的现场检查；UI 还需要浏览器验证，并记录残余限制。每个可运行功能切片应在相关检查通过后及时形成独立、连贯的本地提交，共享工作树中只暂存所属文件或 hunk，推送仍需明确请求。[测试与提交规范 ↗](../../../AGENTS.md#L11 "支持真实行为验证、浏览器检查、功能切片提交和共享工作树暂存纪律。")

对捕获、AST、知识生成、引用、检索或助手运行的修改，流程要求先检查并提交实现，再单独更新知识资产。知识更新必须经过真实 ACP 分析与独立 verifier，覆盖状态需区分 reviewed、stale、pending、failed；完整验证报告记录命令退出码、指纹、索引、引用与真实 HTTP 检索，不能手填结果，也不能把一般检查等同于全库覆盖或模型复核。[知识资产更新流程 ↗](../../../AGENTS.md#L16 "解释实现提交之后如何通过真实模型生成、覆盖检查和固定原文引用更新仓库知识。")[检索与完整验证报告 ↗](../../../AGENTS.md#L23 "支持语义检索实测、真实 HTTP 查询以及自动生成完整验证记录的要求。")

<a id="repo-review-architecture"></a>
## repo-review 的统一架构与运行边界

Code Wiki 被定义为统一 Capture→Source/Revision/Fragment 证据链上的派生视图，而非独立产品；通用处理复用知识管线、角色运行时和现有任务，repo-review 只承担仓库输入适配与隔离运行配置。[Code Wiki 统一证据链定位 ↗](../../../AGENTS.md#L26 "说明 Code Wiki 与代码结构图均为统一证据链派生视图，以及 repo-review 的适配器边界。") 前端 DTO 必须区分供路由使用的内部 ID 与可见的人类标签；不可操作或过期目标应显式说明原因。阅读交互则复用 `packages/ui` 的证据 trail 合同，避免另造一套抽屉体系。[DTO 展示与证据 Trail 合同 ↗](../../../AGENTS.md#L30 "支持内部标识不直接展示、失效目标可解释，以及 Code Wiki 复用公共阅读交互的要求。")

评审关系只能来自人工维护且可解析的 locator，解析失败需保留 rejected 记录，禁止通过语义相似度自动造边。模型配置来自专用 review 配置，启动阶段只恢复知识，显式分析或生成操作才调用生成模型；运行数据写入 gitignored runtime，明确发布的派生知识才可提交。[Seed、模型与数据发布边界 ↗](../../../AGENTS.md#L32 "解释关系来源校验、显式模型调用、运行数据隔离和派生知识发布规则。") 当前还存在跨文件调用不解析、跨修订符号及片段身份不能续接等限制，因此代码变化后需要重新同步定位。[代码图谱现有限制 ↗](../../../AGENTS.md#L36 "支持跨文件调用和跨修订身份续接尚未实现、变更后需重新同步的限制说明。")

<a id="knowledge-and-relations"></a>
## 知识生产、引用与关系模型

知识生产遵循“材料分析—独立复核—模块或主题组织”的顺序，不同材料类型共享合同和运行时。正文引用必须贴近论断，模型只选择定位范围，由宿主复制固定原文，再由独立角色核验支持性；仅验证位置并不能证明语义成立。无法确认的内容应保留为有证据的问题或调查项，失败或过期结果不得覆盖有效知识。[正文知识与独立复核流程 ↗](../../../AGENTS.md#L38 "说明材料分析、独立复核、内联引用、调查项和失败结果保护的知识生产原则。")

关系表规定了有限的前向类型和 `confirmed / candidate / missing` 状态；无法解析的目标必须标记为 missing。同步过程从 association seed 幂等生成实现及引用关系，因此新增关系需要先修改 associations 文件，再触发 review sync。[评审关系类型与同步方式 ↗](../../../AGENTS.md#L47 "支持关系类型、状态语义、不可解析目标处理及从 association seed 幂等同步的规定。")
