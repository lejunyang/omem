# Code Wiki 的轻量 Hash 路由与 Trail 深链

该模块以轻量 Hash 格式表示 Code Wiki 的概览、结构、关系图、模块和文件视图，并附带可刷新恢复的 trail 栈。解析采用防御性回退；文件行号与 trail 可以同时往返。URL 仅保存帧的 kind/id，且序列化深度受预算限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="views"></a>
## 视图模型与防御性解析

路由模型覆盖概览、结构、关系图、模块与文件视图；文件视图还可携带行号，trail 则作为独立帧数组返回。解析器会先移除 Hash 前缀，空值回退到概览；URI 解码失败时保留原段。[Hash 视图模型与基础解析回退 ↗](../../../packages/ui/src/OmHashRoute.ts#L1 "支持路由支持的视图种类、文件行号结构、URI 解码失败时的保留策略以及空 Hash 回退到概览的论断。") 对于无法识别的主路由，解析器同样回退到概览；若主路由头恰为 `trail`，则落到关系图。[行号、Trail 与主路由解析流程 ↗](../../../packages/ui/src/OmHashRoute.ts#L30 "支持行号提取、trail 分离、查询串移除、帧恢复，以及未知路由回退到概览和单独 trail 路由落到关系图的行为。") 这种实现不依赖完整路由框架，适合状态集合较小的 Code Wiki，同时避免损坏深链使页面失去可用入口。

<a id="roundtrip"></a>
## 行号与 Trail 的组合往返

文件路由写入时先形成 `#/file/<文件>?line=<行号>`，再追加 `/trail/<kind>/<id>...`。[文件路由与 Trail 写入顺序 ↗](../../../packages/ui/src/OmHashRoute.ts#L67 "支持文件行号查询串先进入基础路由、随后追加 trail 后缀的实际序列化格式。") 解析并不会把查询串混入文件标识：它先在完整字符串中提取行号，随后按 `/trail/` 分离帧后缀，再通过 `split("?")[0]` 从主路由移除查询串，最后才切分文件路径。[行号、Trail 与主路由解析流程 ↗](../../../packages/ui/src/OmHashRoute.ts#L30 "支持行号提取、trail 分离、查询串移除、帧恢复，以及未知路由回退到概览和单独 trail 路由落到关系图的行为。") 因而文件标识、行号和 trail 可以从该格式共同恢复；此前关于三者无法可靠往返的结论已被替代。

<a id="trail"></a>
## Trail 编码、恢复与信息边界

trail 以 kind/id 成对编码，每段均进行 URI 编码；解析时按相邻两段恢复帧，并暂用 id 作为标题。读写两端只持久化前 `MAX_TRAIL` 帧。[行号、Trail 与主路由解析流程 ↗](../../../packages/ui/src/OmHashRoute.ts#L30 "支持行号提取、trail 分离、查询串移除、帧恢复，以及未知路由回退到概览和单独 trail 路由落到关系图的行为。") 共享定义将该常量说明为 URL 长度预算，实际渲染栈并不受此上限约束，超限应由调用方明确提示。[共享 Trail 数据与 URL 预算 ↗](../../../packages/ui/src/trail.ts#L16 "说明帧的完整字段范围、kind/id 序列化方式，以及 MAX_TRAIL 仅限制深链 URL 而非渲染栈。") 同时，Hash 不保存标题、滚动位置以及 fileId、symbolId 等附加字段，刷新后的完整展示信息仍需由上层根据 kind/id 重新加载。
