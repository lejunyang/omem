<a id="workspace_foundation"></a>
## 工作区职责与依赖组织

这一层承担仓库的工程组织职责：pnpm 只发现 `apps/*` 与 `packages/*` 下的直接子包，形成应用与共享包并存的工作区边界。[pnpm 工作区目录范围 ↗](../../../pnpm-workspace.yaml#L1 "支持仓库只从 apps 与 packages 的直接子目录发现工作区包这一组织边界。") 锁文件进一步显示根项目、Web 应用和共享 UI 分别作为 importer，Web 通过工作区链接直接复用 UI 包。[Web 与共享 UI 的工作区链接 ↗](../../../pnpm-lock.yaml#L1 "支持根、Web、共享 UI 作为锁文件 importer，以及 Web 直接复用共享 UI 的论断。") 因而它连接了服务端依赖、前端应用和可复用展示能力，但这些配置只能证明依赖图存在，不能证明对应功能已经可运行。

<a id="toolchain_flow"></a>
## 检查、构建与测试流程

根 TypeScript 配置继承服务端基线并设置 `noEmit`，典型作用是复用统一规则做静态检查而不生成产物。[根 TypeScript 无输出检查入口 ↗](../../../tsconfig.json#L1 "支持根配置继承服务端规则并通过 noEmit 禁止生成编译产物。") 服务端基线采用 ES2023、NodeNext 和严格类型检查，覆盖服务端、共享契约以及开发、评审、Wiki、知识处理脚本；它声明 `dist`，但从现有材料无法确认真正的产物生成入口。[服务端 TypeScript 基线与源码范围 ↗](../../../tsconfig.server.json#L1 "支持 ES2023、NodeNext、严格检查、输出目录声明，以及服务端、契约和评审脚本的纳入范围。")

测试侧由单一 Vitest 配置发现服务端、Web 与共享 UI 的 `*.test.ts`，把三个区域纳入共同检查流程。[统一测试发现范围 ↗](../../../vitest.config.ts#L1 "支持 Vitest 同时发现服务端、Web 和共享 UI 三处 TypeScript 测试的流程描述。") 每例超时为 15 秒且默认运行在 Node 环境，这对服务端自然，但涉及 DOM 的前端测试可能需要额外环境或浏览器检查。[测试超时与 Node 环境 ↗](../../../vitest.config.ts#L5 "支持单例 15 秒超时和统一 Node 执行环境，并据此说明前端 DOM 测试的潜在限制。")

<a id="constraints_progress"></a>
## 当前基础、约束与事实边界

依赖已经锁定到具体版本，根工具链包含 TypeScript、Vite、Vitest、Playwright 等；Web 与共享 UI 共同使用 Vue、Markdown 渲染、代码高亮和 HTML 净化组件，体现出富文本展示的共享技术基础。[Web 与共享 UI 展示依赖 ↗](../../../pnpm-lock.yaml#L58 "支持 Web 和共享 UI 共同采用 Vue、Markdown、高亮及净化依赖这一跨模块技术关系。") 安装期脚本只明确许可 esbuild 与 protobufjs，约束了依赖构建行为。[安装期构建许可 ↗](../../../pnpm-workspace.yaml#L5 "支持仅明确允许 esbuild 与 protobufjs 执行依赖构建脚本的安全边界。")

运行环境仍有硬边界：锁定的 Vite 要求 Node `^20.19.0 || >=22.12.0`。[Vite 的 Node 版本要求 ↗](../../../pnpm-lock.yaml#L1372 "支持工具链对 Node 运行时存在明确最低版本限制。") 此外，配置或测试依赖“存在”不等于命令执行成功；材料没有提供实际退出码、覆盖率、浏览器结果、CI 环境或生产构建证据，因此进展应理解为工程基线已配置，而非完整验收。
