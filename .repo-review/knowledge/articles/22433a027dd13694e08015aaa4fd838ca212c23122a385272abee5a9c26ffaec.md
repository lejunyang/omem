# 知识生成、复核与制品的共享合同

该文件以严格 Zod schema 约束知识引用、疑问、文档、批次、独立复核和章节规划的数据形状，并导出对应 TypeScript 类型；另以普通类型描述输入材料和已验收知识制品携带的来源、依赖摘要、生成轨迹与复核信息。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 作用与合同边界

该模块为知识流水线提供共享合同。知识生成结果被组织为文档与版本 1 批次，文档包含摘要、分类、章节、引用和问题；这些 Zod 对象均使用严格模式，并限制键格式、字段长度及数组规模。[知识文档与批次结构 ↗](../../../packages/contracts/src/knowledge.ts#L25 "支持知识文档的字段组成、严格校验、数量约束以及批次版本和文档上限。") 独立复核和章节规划另有版本 1 结构：前者记录逐文档判定，后者约束章节用途及所需材料。[独立复核与章节规划合同 ↗](../../../packages/contracts/src/knowledge.ts#L41 "支持复核和规划各自采用版本化结构、复核判定范围及规划章节数量和材料关联方式。") `KnowledgeMaterial` 与 `KnowledgeArtifact` 则只是 TypeScript 类型，本文件没有展示它们的运行时校验，也不负责生成、持久化或任务编排。

<a id="citation_flow"></a>
## 引用与疑问如何表达

引用要求提供人读标签、支持理由、关系类型，以及材料或文章目标；材料目标可以精确到行，文章目标可以指向章节。`quote` 默认留空，并注明由宿主从所选行范围抽取原文后再进行独立复核，从合同层降低生成方自行改写引文的风险。无法确认的事项通过问题对象保存原因、下一步、是否阻塞和相关引用键，使不确定性能够随文档或复核结果继续流转。[引用与待确认问题合同 ↗](../../../packages/contracts/src/knowledge.ts#L3 "支持引用目标、关系、宿主抽取原文的约定，以及问题对象保存原因、下一步和阻塞状态的论断。")

<a id="document_review_plan"></a>
## 文档、复核与规划的衔接

知识批次最多容纳 16 篇文档。复核合同同样采用版本 1，按文档键给出 `accepted` 或 `needs_revision`，并携带问题与待修订事项；规划合同则要求 4 至 32 个章节，每章以稳定格式的键、标题、用途和材料键描述预期覆盖范围。[独立复核与章节规划合同 ↗](../../../packages/contracts/src/knowledge.ts#L41 "支持复核和规划各自采用版本化结构、复核判定范围及规划章节数量和材料关联方式。") 这些定义说明各阶段交换什么数据，但没有给出规划、生成、宿主引文抽取和独立复核的实际调用顺序、重试方式或失败处理。

<a id="material_artifact"></a>
## 输入材料、产物溯源与限制

`KnowledgeMaterial` 描述输入材料的来源与修订标识、命名空间、会话和参与者上下文、摘要、正文、片段及受限图片格式，并未在此声明材料不可变或禁止更新。[知识输入材料类型 ↗](../../../packages/contracts/src/knowledge.ts#L66 "支持输入材料包含来源、修订、上下文、摘要、正文、片段和图片信息，同时说明该类型本身未表达不可变语义。") `KnowledgeArtifact` 把最终文档绑定到材料或文章依赖的摘要，同时记录生成模型、努力级别、时间、运行轨迹和独立复核信息；其复核结论只能为 `accepted`，表明该类型面向已验收制品。[已验收知识制品类型 ↗](../../../packages/contracts/src/knowledge.ts#L73 "支持制品记录依赖摘要、生成轨迹和独立复核信息，且复核结论类型仅允许 accepted。") 但本文件没有定义依赖摘要变化后的过期检测、状态转换或旧制品保留策略。
