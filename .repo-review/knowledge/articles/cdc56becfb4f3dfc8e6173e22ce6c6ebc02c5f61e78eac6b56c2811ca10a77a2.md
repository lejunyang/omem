# omem 通用配置示例

展示可选 Agent CLI/ACP 配置，以及通知、学习、飞书轮询和文件采集的配置形状。示例值不代表相关外部 CLI、worker 或集成已在实际环境启用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="agent-profiles"></a>
## Agent 执行配置

示例列出 TraeX、Codex 和 Claude 三类执行配置。TraeX 通过 ACP 调用 `traecli`，附带只读沙箱参数、上下文长度、超时和固定证据约束；其余两项只声明 CLI transport 与命令。[Agent profiles 示例 ↗](../../../config/omem.example.json#L2 "支持三类执行配置的 transport、命令，以及 TraeX 的只读沙箱、上下文和超时设置。") 这些字段说明系统预留了多执行器入口，但不能证明外部 CLI 已安装、协议兼容，或模型与 effort 已通过运行时校验。

<a id="runtime-features"></a>
## 通知、学习与采集开关

通知采用即时模式，外部通知配置了五分钟窗口、本地计划时间和上海时区。学习功能在示例中启用，绑定 TraeX profile，并设置一秒轮询。[通知与学习配置 ↗](../../../config/omem.example.json#L27 "支持通知模式、外部通知窗口，以及学习功能启用、profile 绑定和轮询间隔的描述。") 飞书轮询则被关闭，`captureRoots` 为空，说明此示例没有列出文件采集目录。[飞书与采集目录配置 ↗](../../../config/omem.example.json#L41 "支持飞书轮询关闭及采集目录列表为空的论断。") 这些都只是模板声明；实际是否运行，还取决于本地配置、凭据、采集授权和对应 worker。
