# omem 应用示例配置

示例配置集中展示检索、Agent 运行档案、通知、学习任务、飞书轮询和采集范围的默认形态；它描述可配置入口，不代表部署环境已经启用或实时验证全部集成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="retrieval-and-agents"></a>
## 检索与模型运行档案

示例默认启用检索，并选择名为 `memory-zh` 的 osdk 模型；独立检索配置也采用相同取值。[示例中的检索选择 ↗](../../../config/omem.example.json#L1 "支持示例默认启用检索并选择 memory-zh 模型这一配置事实，不扩展解释其下载策略。")[独立检索配置 ↗](../../../config/retrieval.json#L1 "说明独立检索配置同样启用检索并使用 memory-zh，与应用示例保持一致。") 这些字段只能证明配置选择，不能单独推出模型资产的下载、锁定或运行时联网策略。

配置还列出 TraeX ACP、Codex CLI 与 Claude CLI 三类运行档案。其中 TraeX 明确使用只读沙箱参数，并设置上下文长度、超时和“仅依据固定证据”的约束；另外两类只给出传输与命令。[Agent 运行档案示例 ↗](../../../config/omem.example.json#L3 "支持三类运行档案及 TraeX ACP 的只读参数、上下文限制、超时和固定证据约束。") 因而该文件表达的是可选运行入口，不证明三个外部 CLI 均已安装或通过实时验证。

<a id="automation-boundaries"></a>
## 自动化入口及其边界

通知默认采用即时模式，外部通知另设五分钟窗口、每日时间和上海时区；学习轮询启用并绑定 TraeX 档案。飞书接入默认关闭，采集根目录为空。[通知、学习与接入开关 ↗](../../../config/omem.example.json#L28 "支持通知调度、学习轮询、飞书默认关闭和空采集范围等配置事实。") 这些配置提供调度参数和开关，却没有给出外部凭据、投递目标或获准采集的目录。

当前实现状态进一步表明，一次性到期站内提醒已有验证，但重复提醒、外部到期投递和取消状态仍未实现。[主动提醒的当前边界 ↗](../../../docs/implementation/status.md#L5 "用于区分配置入口与已验证行为，并支持重复提醒、外部投递和取消状态尚未实现的结论。") 因此不能把示例中的通知或飞书字段解释为完整的外部主动跟进能力。
