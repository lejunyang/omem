# 知识阅读链路的真实浏览器验收

该脚本以临时仓库、真实 SQLite、服务端 API 和 Vue 页面组成端到端环境，验证知识文章的内联引用可逐层打开、深链可恢复、代码材料安全展示、待确认问题可转为任务，并检查多种视口下的基本布局表现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-fixture"></a>
## 解决什么问题

该脚本验证的不是孤立组件，而是用户从知识总览进入文章、沿引用阅读其他文章和固定源码的完整体验。它先创建包含三级调用关系和一份 HTML 材料的临时仓库，再依次执行仓库同步、材料捕获与代码同步，随后发布带内联引用、问题项及生成/复核元数据的固定知识文章；因此测试结果不依赖 LLM 输出。参考 [临时仓库与固定知识 ↗](../../../scripts/knowledge-browser.ts#L14 "支持脚本构造三级源码关系、同步材料并发布固定知识文章且不依赖模型的说明。")

脚本使用真实 `Store`、知识仓库和 Review Web 应用，并通过随机端口启动服务、用无头 Chromium 访问页面，覆盖 Vue、HTTP API 与 SQLite 的集成边界。参考 [真实应用启动 ↗](../../../scripts/knowledge-browser.ts#L20 "支持测试连接 Store、知识仓库、Review 应用和无头 Chromium 的集成范围。")

<a id="reading-flow"></a>
## 引用阅读与导航状态

测试从总览页点击“架构说明”，依次沿模块 A、B、C 到源码，断言引用理由可见、面包屑形成五层阅读轨迹，最终代码视图展示固定源码。按 Esc 后应退回一层；刷新页面仍恢复四层轨迹，URL 中保留深链状态；关闭全部后再次打开和关闭，焦点回到原入口。参考 [多层引用阅读 ↗](../../../scripts/knowledge-browser.ts#L49 "支持引用理由、五层轨迹、源码展示、Esc 回退、深链刷新恢复及焦点归还等断言。")

另一条路径从模块 A 的知识卡进入其源码，再点击代码中的 `b.ts` 行引用，断言目标打开为“模块 B”的知识文章。这证明导入引用能够连接源码阅读和已有知识，但这里只验证 fixture 中明确构造的单个跨文件 import，并不能证明任意跨文件调用都可解析。参考 [导入引用跳转 ↗](../../../scripts/knowledge-browser.ts#L70 "支持从 A 的源码行引用打开模块 B 知识文章的行为，并界定该断言只覆盖当前 fixture。")

<a id="safety-and-actions"></a>
## 布局、安全与用户操作

脚本把视口依次调整为 1440、768 和 390 像素，并以页面总宽不超过视口为断言，检查桌面、平板和手机宽度下没有横向溢出。该检查覆盖基础响应式布局，但未断言触控手势、视觉截图或各断点的具体排版。参考 [多视口无溢出 ↗](../../../scripts/knowledge-browser.ts#L75 "支持三个视口宽度下仅检查页面横向溢出的测试范围。")

知识问题默认不会自动执行：测试展开问题区、点击“加入待办”，同时核对页面状态和 SQLite 中新增的一项任务。最后直接深链打开含 `<script>` 的 HTML 原文，确认代码视图显示文本但未设置页面全局变量，并要求运行期间没有页面异常，从而验证原始 HTML 被转义而非执行。参考 [待办与源码转义 ↗](../../../scripts/knowledge-browser.ts#L80 "支持用户显式创建待办、数据库落库，以及 HTML 原文显示但脚本不执行的安全断言。")

<a id="boundaries"></a>
## 测试边界与清理

这是单进程、无头 Chromium 下的固定数据验收；材料和知识均由脚本即时构造，未覆盖真实模型生成质量、其他浏览器、网络故障、并发访问、超长轨迹上限或服务重启后的持久恢复。脚本无论断言成功与否都会关闭浏览器和应用，并删除临时仓库，避免测试数据残留。参考 [资源清理 ↗](../../../scripts/knowledge-browser.ts#L45 "支持 finally 阶段关闭浏览器、应用并删除临时目录的说明；同时该文件显示测试仅启动 Chromium。")
