# 知识阅读链路的浏览器验收

该脚本用临时仓库、真实 SQLite、服务端 API、Vue 页面与无头浏览器，端到端验证知识文章、内联引用、源码阅读、深链恢复、待办转化及安全渲染；它使用固定 fixture，不验证模型生成质量。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

这是一条面向知识阅读体验的浏览器验收脚本。它不调用大模型，而是在临时目录创建三层 TypeScript 依赖和一份带脚本的 HTML 原文，再初始化真实存储、仓库同步、代码同步与知识仓库，从而检查前端、API 和 SQLite 串联后是否仍保持一致行为。参考 [浏览器验收定位 ↗](../../../scripts/knowledge-browser.ts#L1 "说明脚本使用真实 Vue、API、SQLite 导航并明确不调用大模型。")

测试使用独立临时数据目录，适合在不污染个人知识库的情况下复现导航、引用与任务交互。其关注点是**用户最终看到并操作的结果**，不是单个组件或协议 fixture。参考 [临时仓库与同步初始化 ↗](../../../scripts/knowledge-browser.ts#L14 "支持临时目录、测试源码、独立 Store 以及同步和材料仓库初始化的描述。")

<a id="fixture-flow"></a>
## 固定知识如何形成可导航链路

`publish` 辅助函数构造带内联引用的知识文档，绑定材料原文，并把材料摘要或文章版本记录为依赖；每篇 fixture 都带已接受的生成与复核元数据。模块 A 还额外加入源码引用和一个“责任人未知”的问题，用于覆盖原文阅读与待办入口。参考 [知识 fixture 发布流程 ↗](../../../scripts/knowledge-browser.ts#L24 "支持内联引用、问题、原文绑定、依赖记录及生成复核元数据的构造流程。")

```mermaid
flowchart LR
  总览 --> 架构说明
  架构说明 --> 模块A
  模块A --> 模块B
  模块B --> 模块C
  模块C --> 固定源码
```

脚本按上述关系发布文章，随后启动真实 review 应用与 Chromium，形成从知识总览逐层进入章节、模块和固定源码的完整阅读路径。参考 [文章链与应用启动 ↗](../../../scripts/knowledge-browser.ts#L37 "支持总览到模块源码的固定文章关系，以及真实服务和浏览器的启动过程。")

<a id="assertions"></a>
## 关键交互与行为断言

浏览器从总览进入架构说明后，连续打开四级引用，检查引用理由、五层面包屑和源码内容；按 Esc 应退回一层，刷新后仍能从 URL 深链恢复栈状态。关闭全部后再次打开并关闭，还断言焦点归还原入口，覆盖键盘导航与可恢复阅读上下文。参考 [多层阅读与深链恢复 ↗](../../../scripts/knowledge-browser.ts#L49 "支持引用理由、面包屑层级、源码显示、Esc 回退、刷新恢复和焦点归还等断言。")

脚本还从模块 A 的源码视图点击 `b.ts` 行引用，并断言目标是模块 B 的知识文章。这证明当前 UI 能依据 fixture 中的真实 `import` 导航到目标模块；它没有证明任意跨文件函数调用都已被解析。参考 [导入引用导航 ↗](../../../scripts/knowledge-browser.ts#L70 "支持从模块 A 的源码行引用进入模块 B 知识文章的具体断言。")

<a id="boundaries"></a>
## 边界、安全性与未覆盖范围

同一页面分别在 1440、768 和 390 像素宽度下检查无横向溢出；未解决问题只有在用户点击“加入待办”后才进入存储。HTML 材料则以源码文本展示，并明确断言其中的脚本没有在页面执行，覆盖了原文阅读的基本注入风险。参考 [响应式、待办与安全渲染 ↗](../../../scripts/knowledge-browser.ts#L75 "支持多视口无溢出、用户主动创建待办以及 HTML 原文不执行脚本的行为。")

最后，脚本要求页面运行期间没有未捕获错误，并在 `finally` 中关闭浏览器、服务端并删除临时目录。由于全部数据在单进程临时环境中构造，该验收没有覆盖真实模型生成、鉴权、多用户隔离、服务重启后的持久化恢复，也没有遍历所有引用循环或极深 trail。参考 [错误检查与资源清理 ↗](../../../scripts/knowledge-browser.ts#L91 "支持未捕获页面错误断言及浏览器、服务端、临时目录的最终清理。")
