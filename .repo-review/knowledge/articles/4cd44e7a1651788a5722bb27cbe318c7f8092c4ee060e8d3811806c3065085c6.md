# 统一输入、外部接入与可靠投递

omem 通过统一 Capture 入口接收文件、Git、Hook、聊天、屏幕和飞书材料；Hook 先持久缓冲，高频事件先聚合，飞书侧再以应用接入、幂等收件箱、事务型 outbox 和租约队列完成双向处理。当前实现固定为 personal 工作区，群聊自动捕获授权、聚合跨事务补偿、接入任务重启恢复及真实平台故障语义仍未闭合。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="unified_boundary"></a>
## 统一捕获合同与连接器边界

立即材料和需成批的 chat/screen 事件分别进入统一捕获与事件入口；合同覆盖 manual、file、git、lark、agent、hook、chat、screen，并规定相同来源与外部标识的版本复用、变化建新版本。[统一捕获入口与版本规则 ↗](../../../docs/implementation/inputs.md#L3 "支持统一捕获与事件聚合入口、来源枚举、载荷预算及相同外部标识的版本化规则。") 文件读取受真实路径、大小和 UTF-8 限制，Git 固定到解析后的提交，飞书文档只接受受限 HTTPS 地址；材料中的 URL 只保留而不自动抓取，引用侧车也明确作为来源上下文处理。[文件、Git 与飞书文档读取边界 ↗](../../../apps/server/src/connectors.ts#L1 "支持显式有限读取、真实路径约束、固定提交、受限飞书 URL，以及链接和引用侧车只作为材料保存。") Hook 仅选择配置字段并生成稳定事件身份，但脱敏只覆盖部分令牌形态，不能视为完整 DLP。[Hook 字段选择与事件来源 ↗](../../../apps/server/src/connectors.ts#L137 "支持 Hook 字段白名单、有限令牌脱敏、字符预算和稳定事件身份构造。") 因此可确认的是各连接器产出统一捕获载荷及版本化输入，而不是笼统声称任何外部内容都已由独立执行隔离机制自动判定为“非指令”。

<a id="buffer_and_aggregation"></a>
## 缓冲、聚合与来源保留

HookSpool 以生产者和事件号确定记录，相同摘要视为重复、不同摘要报冲突，并经受限权限临时文件、同步和重命名落盘。[Hook 缓冲幂等与落盘 ↗](../../../apps/server/src/inputs/spool.ts#L61 "支持稳定事件路径、摘要冲突检查、容量保护和受限权限原子写入流程。") 刷新按创建时间顺序发送，只有生产者、事件号和摘要均匹配回执才删除；首个失败即停止，因此支持重试但可能队头阻塞。[Hook 顺序投递与回执核验 ↗](../../../apps/server/src/inputs/spool.ts#L174 "支持按创建时间投递、严格核对回执、成功删除及首个失败后停止。")

聚合器只接受 chat 与 screen，分别按会话或应用加窗口划流；事件身份要求 eventId 与 collectorId，表记录明确固定在 personal 工作区。[聊天与屏幕流及个人工作区 ↗](../../../apps/server/src/inputs/aggregator.ts#L39 "直接支持 chat 和 screen 的流键规则、事件身份校验、冲突检查及固定 personal 工作区写入。") 流在静默期、最大等待或数量阈值到达后成批，并按 actor 与内容联合去重、限制 part 预算。[聚合触发与同说话者去重 ↗](../../../apps/server/src/inputs/aggregator.ts#L124 "支持静默期、最大窗口、数量阈值、接收顺序、actor 加内容去重及 part 预算。") 聚合 envelope 为每个 part 保留 actor、观察时间、事件号和转发属性，迟到事件通过 lateForBatchId 关联上一批而不改写历史。[逐部件来源与迟到批次 ↗](../../../apps/server/src/inputs/aggregator.ts#L181 "支持聚合结果保留逐 part 来源、观察时间和事件号，并通过 lateForBatchId 关联迟到事件。")

<a id="lark_end_to_end"></a>
## 飞书接入、实时处理与投递

新建或复用注册由异步接入流程启动；Botmux 凭据与显式密钥导入也汇入同一凭据验收入口。[注册与既有应用入口 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L83 "支持新建或复用注册流程，以及 Botmux 凭据和显式密钥汇入统一凭据验收。") 验收会创建候选连接版本、执行能力探测，并在探测失败或能力缺失时阻止候选进入配对。[候选版本与能力门禁 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L244 "支持凭据校验、候选连接版本创建、能力探测、失败处置和缺失能力门禁。") 密钥引用经过格式限制，内容以 AES-256-GCM 认证加密并通过临时文件同步、重命名持久化。[凭据认证加密存储 ↗](../../../apps/server/src/integrations/lark/secret-store.ts#L53 "支持受限秘密引用、AES-256-GCM、认证解密及同步后原子重命名的持久化流程。") 配对码只保存 HMAC 摘要并绑定连接版本；确认时核对应用、操作者、会话和期限，随后尝试把仍处于 awaiting_pair 的该版本置为 active，再替换绑定和创建目标。这里替代旧稿中“显式确认其仍是唯一候选版本”的过强结论，因为版本更新结果未被单独检查。[配对版本绑定与目标激活 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L569 "支持配对码摘要、身份与期限核验、配对记录绑定连接版本，以及尝试激活 awaiting_pair 版本和创建群监控目标。")

实时事件先按应用和事件号进入幂等收件箱；助理仅接受绑定 owner 的私聊，群聊还要求明确提及机器人，普通群消息则可创建监控目标并转换为带来源信息的 Capture。[收件箱准入与群消息捕获 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L337 "支持事件幂等、绑定 owner 的助理准入、机器人入群和普通群消息启用监控，以及统一捕获来源字段。") 回复 outbox 与 turn 关联在同一事务中创建，随后才确认 inbox；同一 turn 复用稳定平台 UUID。[助理回复事务型 outbox ↗](../../../apps/server/src/integrations/lark/realtime.ts#L814 "直接支持回复投递意图与 turn 的事务关联，以及按 turn 生成稳定平台 UUID。") 通知队列以租约领取，检查连接、绑定和去重窗口，有限重试并在认证失败时停用相关连接与目标；工作器发送前还复核密钥归属、摘要和卡片大小。[通知租约与失败处置 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L178 "支持连接和绑定门禁、投递租约、一小时本地去重窗口、有限重试及认证失败停用。")[投递前完整性复核 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L598 "支持发送前核对秘密所属应用、载荷摘要和卡片大小，并回写投递状态。") 决策卡动作则联合核验操作者、会话、消息、nonce、摘要、版本与期限后一次性消费，再由独立租约命令执行和更新原卡片。[决策卡动作联合校验 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L119 "支持卡片动作的应用、绑定、操作者、会话、消息、nonce、摘要、版本和期限联合校验及一次性消费。")[决策命令租约与重试 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L240 "支持决策命令租约领取、业务执行、原卡更新、终止错误识别和有限重试。")

<a id="progress_and_limits"></a>
## 当前进展与未闭合边界

运行时已装配实时连接、助理、通知聚合、投递和决策组件，并限制群聊只能检索该会话实际采集的证据。[运行时组合与群聊可见性 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L36 "支持实时连接、助理、投递和决策组件的组装，并限制群聊检索为当前会话采集的证据。") 但默认权限表实际包含文档权限读取和日历 ACL 读取，配置注释中的“排除权限管理”不能替代最小授权审计。[默认权限实际范围 ↗](../../../apps/server/src/integrations/lark/defaults.ts#L3 "支持权限表包含文档成员与权限设置读取以及日历 ACL 读取，说明设计注释不能替代授权审计。") 聚合器先调用 capture，再事务复查 pending 并写批次；capture 成功后的事务失败尚无补偿协议。[聚合捕获与批次事务边界 ↗](../../../apps/server/src/inputs/aggregator.ts#L320 "支持外部 capture 先执行，随后才复查事件状态、写入批次并更新事件的非原子边界。")

能力探针固定访问飞书开放平台，[能力探针固定飞书域名 ↗](../../../apps/server/src/integrations/lark/registration.ts#L135 "支持能力探针固定访问 open.feishu.cn 的 token、机器人信息和应用能力端点。") 而实时连接和消息发送均按 tenantBrand 选择飞书或 Lark 域名，国际版探测兼容性仍需真实租户验证。[实时连接品牌域名切换 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L154 "支持 WebSocket 适配器按 tenantBrand 选择飞书或 Lark SDK 域名。")[消息发送品牌域名切换 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L113 "支持消息发送与更新适配器按 tenantBrand 选择飞书或 Lark SDK 域名。") onboarding 的活动控制器只存在进程内，[进程内接入任务表 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L24 "支持注册控制器和完成任务只保存在当前服务进程内。") 当前启动恢复仅处理未完成助理 turn，未覆盖 awaiting_scan 或 checking 接入任务。[启动时助理轮次恢复 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L214 "支持现有启动恢复只遍历未完成助理轮次，未展示接入任务重新附着或状态收敛。") 图片具备下载条件时若媒体调用抛错，没有最终占位或永久失败状态机。[图片下载与降级边界 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L719 "支持只有缺少下载条件时降级为占位文本，而真实媒体下载抛错未在该函数内处理。") 更关键的是，群聊配对、机器人入群和首次普通群消息都可能启用群监控，但材料未展示独立的捕获范围授权步骤。[配对版本绑定与目标激活 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L569 "支持配对码摘要、身份与期限核验、配对记录绑定连接版本，以及尝试激活 awaiting_pair 版本和创建群监控目标。")[收件箱准入与群消息捕获 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L337 "支持事件幂等、绑定 owner 的助理准入、机器人入群和普通群消息启用监控，以及统一捕获来源字段。")
