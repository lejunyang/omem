# 统一输入、外部接入与可靠投递

手工、文件、Git、Lark、Agent Hook、聊天与屏幕事件被约束为统一 CaptureInput，并依靠稳定外部身份、内容版本规则、暂存或聚合实现可追踪投递；Lark 进一步提供应用接入、能力核验、配对、实时收件、可靠发件与决策卡。当前代码可证明本地持久化和状态机行为，但真实平台授权、媒体下载、群聊采集同意与异常对账仍待闭合。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="unified-capture"></a>
## 统一输入合同与有界转换

手工、文件、Git、Lark、Agent Hook、聊天和屏幕事件共享统一 CaptureInput，用相同结构表达文本、图片、链接、观察时间、上下文与来源信息。相同 source、externalId 和规范内容会复用当前版本，内容变化才创建下一版本；URL 仅作为材料保存，不自动访问。这里能确认的是统一载荷与版本规则，不据此扩展为 Fragment 创建或修订不可变性的结论。[统一捕获合同与版本规则 ↗](../../../docs/implementation/inputs.md#L3 "支持多来源统一载荷、图片与文本预算、相同规范内容复用版本、内容变化创建下一版本及 URL 不自动访问；也限定本文不扩展声称 Fragment 或不可变修订。")

连接器负责收窄外部读取边界：文件须位于配置根目录并是有界 UTF-8 文本；Git 固定到已解析提交后读取指定路径；Hook 只选择 profile 明示字段，生成稳定事件身份，且不把未知 actor 强行绑定到用户。[文件、Git 与 Hook 有界转换 ↗](../../../apps/server/src/connectors.ts#L10 "支持真实路径限制、固定提交读取、Hook 字段白名单、稳定事件身份及未知 actor 的来源表达。") 更细的职责与风险可下钻至 inputs 模块理解和外部来源转换器。[输入可靠性模块理解 ↗](fe2bd502927378e92217d69a28e09525ae3d1a2b898caa697823d01e20e5614d.md#responsibility "提供暂存、聚合职责及跨事务风险的子知识入口。")[外部来源转换器 ↗](6199888414a5c2e7a0d2943cc6a53c40503ffbcc031f14e27140c29dcb28ec74.md#hook "提供文件、Git、飞书文档与 Hook 转换为统一捕获输入的实现子知识。")

<a id="reliability-flow"></a>
## 暂存、聚合与提交边界

即时材料可直接捕获；连续 chat／screen 事件则按会话或应用窗口分流，在静默 15 秒、最长等待 5 分钟或数量阈值到达时封包。聚合按“内容摘要＋说话者”去重，保留不同说话者的相同内容，并记录事件集合、观察窗口、part 来源与迟到批次关系。[聊天与屏幕聚合流程 ↗](../../../apps/server/src/inputs/aggregator.ts#L39 "支持流划分、就绪窗口、按说话者去重、part 来源、观察窗口和迟到批次的论断。")

Hook 下游不可用时先写本地 spool：生产者和事件 ID 形成稳定键，同键异载荷拒绝覆盖；临时文件同步后重命名。刷新严格核对 producer、eventId、payloadDigest，匹配回执才删除，失败即停止本轮。[Hook 暂存与严格回执 ↗](../../../apps/server/src/inputs/spool.ts#L69 "支持稳定事件键、冲突拒绝、原子写入、顺序刷新及回执匹配后删除的可靠投递流程。") 这提供单机可重放性，但没有证明多消费者协调；聚合器又在批次事务和 pending 复核前调用 capture，后续失败时缺少对已产生外部效果的显式补偿。[暂存与聚合剩余风险 ↗](fe2bd502927378e92217d69a28e09525ae3d1a2b898caa697823d01e20e5614d.md#progress-limits "提供多消费者认领、跨事务补偿和身份继承问题的子知识入口。")[聚合捕获提交边界 ↗](../../../apps/server/src/inputs/aggregator.ts#L320 "支持 capture 发生在批次事务与 pending 状态复核之前，说明提交失败时可能遗留外部效果。")

<a id="lark-integration"></a>
## Lark 接入、交互闭环与现有限制

Lark 把应用注册或既有凭据导入、加密存储、能力探测和 owner 配对串成版本化连接。公开接口核验 scopes、callbacks 与机器人身份，事件订阅由 WebSocket 实际投递确认；未配置真实探针时保守拒绝激活。[Lark 能力实测与保守拒绝 ↗](../../../apps/server/src/integrations/lark/registration.ts#L135 "支持公开接口能力核验、事件订阅由运行时确认，以及未配置真实探针时拒绝激活。") 实时事件按应用和事件 ID 幂等入收件箱，允许的群消息转为统一 chat 捕获；助手回复先写事务性发件箱，再确认收件事件。[Lark 收件、采集与回复发件箱 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L337 "支持事件幂等、身份分流、群聊统一捕获，以及先持久化回复再确认收件的顺序。") 注册信任链与回复恢复细节可分别下钻到 Lark 模块理解和实时事件章节。[Lark 接入与信任链 ↗](6f0934cde8ff03ab01e9f910df270b18de6f6a358ea684b35cdb2552f7f17f31.md#onboarding-and-trust "提供应用注册、能力核验、配对、凭据保护和采集范围边界的模块级子知识。")[Lark 实时事件与回复交付 ↗](6f68409588e8c682d56002e376d4cfe2b3c872508037d3cc864122caeb9422c6.md#reply_delivery "提供 WebSocket 收件、助手回复、重投处理和事务性发件箱的子知识入口。")

出站通知使用租约、平台去重 UUID、错误分类与有限重试，超出去重窗口且结果不明确时转为 `unknown`。决策卡联合核验操作者、绑定、消息、摘要、随机数、版本与有效期，再以租约执行幂等决策并更新原卡片。[通知租约与不明确投递 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L190 "支持租约认领、平台去重窗口、有限重试、unknown 状态及鉴权失败级联停用。")[决策卡核验与租约执行 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L152 "支持卡片动作的上下文联合校验、一次性消费、幂等决策和结果卡片更新流程。") 凭据采用 AES-256-GCM 和受限权限原子落盘，但格式未展示主密钥轮换。[Lark 凭据认证加密 ↗](../../../apps/server/src/integrations/lark/secret-store.ts#L22 "支持 32 字节主密钥、AES-256-GCM、受限文件权限和原子落盘，同时显示存储格式中没有密钥标识。") 真实应用创建与授权仍须显式进行，屏幕观察器由外部提供；现有代码和 fixture 不能替代真实租户验收。[外部接入实施边界 ↗](../../../docs/implementation/inputs.md#L44 "支持真实 Lark 应用创建与授权仍需显式进行、屏幕观察器由外部负责，以及部分连接器能力尚有限制。") 图片下载仅展示可注入媒体端口，测试替身也不能证明生产下载已具备大小、超时与 MIME 防护。[图片媒体端口与测试替身 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L38 "支持图片下载通过抽象端口完成且测试可注入 fixture，因此不能据此认定真实网络下载已经验收。")
