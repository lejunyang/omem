# 证据、知识生成与递归阅读

原始 Capture 修订是事实依据，派生知识负责组织理解和引导召回。系统通过固定行范围、宿主绑定引文、独立语义复核、不可变发布与共享 Evidence Trail，把正文论断逐层带回当前或历史原文。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence_boundary"></a>
## 为什么区分证据与知识

系统把原始 Capture 修订视为证据，把知识正文视为可失效、可追溯的解释层。材料转换会排除派生修订，默认只取各来源当前 head；材料身份覆盖文本、图片、行为者及转述状态。[原始修订到知识材料 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持派生修订排除、当前 head 选择以及材料身份覆盖文本、图片和来源状态。") 文档、章节、内联引用和疑问受共享合同约束，发布产物还明确记录依赖、生成 trace 与 accepted 复核 trace。[共享知识与产物合同 ↗](../../../packages/contracts/src/knowledge.ts#L25 "支持文档章节、引用、疑问以及产物依赖、生成记录和 accepted 复核记录的统一结构。")

这种分层避免“总结引用总结”逐步脱离原文：派生正文可以组织复杂主题，但不会成为新的独立原件。模型选择定位范围，宿主复制固定引文，独立角色再判断语义支持性；位置有效并不等于结论正确。[正文与固定引用原则 ↗](../../../docs/implementation/knowledge-pipeline.md#L5 "解释派生正文和原始证据的边界，以及模型定位、宿主绑定引文和独立语义复核的职责分工。")

<a id="generation_flow"></a>
## 如何生成、复核与发布

流水线依据图片、会话来源和代码扩展名，在视觉、会话、代码与通用材料分析角色之间分流。[材料分析角色分流 ↗](../../../apps/server/src/knowledge/pipeline.ts#L15 "支持依据图片、会话来源和代码扩展名选择视觉、会话、代码或通用材料分析角色。") 随后把获准行段、图片和来源元数据组成固定上下文；子文章被明确标为辅助知识而非独立证据。[固定材料上下文 ↗](../../../apps/server/src/knowledge/pipeline.ts#L30 "支持材料分块、图片装载、来源元数据传递及派生文章不是独立证据的说明。") 输出必须完整且唯一覆盖目标，材料引用不得越过本次提供的行段。[批次与引用范围校验 ↗](../../../apps/server/src/knowledge/pipeline.ts#L96 "支持目标完整唯一、文档合同校验以及材料引用不得超出已提供行段。")

草稿进入最多四轮的独立复核；已有反馈会切换到刷新角色定向修改，只有 accepted 文档才会连同生成、复核 trace 和依赖发布。[独立复核与修订循环 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "支持最多四轮定向修订、独立 verifier、仅发布通过文档及发布时记录生成和复核 trace。") 仓库发布前再次核对材料摘要和子文章修订，随后以事务保存不可变修订、切换当前 head，并同步疑问状态。[知识正文事务发布 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前依赖复检、不可变修订保存、head 切换和疑问状态同步，也显示目标 head 没有比较交换条件。") 角色执行本身还会创建持久任务、启动按任务限定的租约 worker，并在租约令牌约束下保存角色输出；因此“任务已入列”或“模型已返回”都不等于正文已经成功发布。[持久角色任务与租约执行 ↗](../../../apps/server/src/knowledge/pipeline.ts#L60 "支持知识角色任务入列、既有输出读取、租约 worker 创建、角色输出保存、心跳配置和任务状态轮询；同时界定当前材料未包含任务仓库内部恢复语义。")

<a id="recursive_reading"></a>
## 如何从正文递归回到原始证据

正文组件只为可操作引用生成 citation 帧，并把文档键、实际文章修订和引用键编码进帧身份。[固定引用帧编码 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L20 "支持可操作引用被编码为包含文档键、实际文章修订和引用键的 citation 帧。") 引用帧解析这些字段，先展示关系与理由，再进入指定知识章节，或携带材料摘要与行范围打开固定原文。[引用解析与固定目标分派 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L9 "支持解析 citation 帧、展示引用关系与理由，并按文章章节或材料行范围打开固定目标。")

个人知识页把首页导航、活动帧、共享状态组合式函数和共享抽屉接在一起，因此知识、引用与来源沿同一栈下钻。[个人知识页共享 Trail 装配 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L1 "支持个人知识首页和活动帧复用共享 Trail 状态、抽屉及导航事件。") 抽屉提供 Escape 退层或关闭、面包屑跳回、滚动记忆、循环提示和关闭后的焦点归还。[共享证据路径交互 ↗](../../../packages/ui/src/components/OmTrailDrawer.vue#L35 "支持 Escape 退层、面包屑跳回、滚动记忆、循环提示以及关闭后的焦点归还。") 助手召回也遵循相同证据边界：正文命中只确定相关章节与引用键，遍历重新核对依赖，并把有效材料引用映射回与行区间重叠的原始 Fragment；派生文章本身不作为候选证据返回。[知识引导的原始 Fragment 召回 ↗](../../../apps/server/src/knowledge/retrieval.ts#L27 "支持依赖有效性检查、文章引用递归、材料行区间核验和原始 Fragment 映射，也界定递归深度、数量阈值及调用契约限制。")

<a id="progress_limits"></a>
## 当前进展与限制

实现记录显示固定引用合同、独立复核、仓库适配、共用阅读组件和知识引导召回已经接通；真实浏览器检查覆盖五层引用链、理由、Esc、深链、焦点与多视口，同时仍把 fixture 与真实模型产物分开说明。[知识阅读与召回验证进展 ↗](../../../docs/implementation/knowledge-pipeline.md#L45 "支持共享阅读组件、真实浏览器验证、知识引导召回以及 fixture 与真实模型产物分离的进展说明。")

边界仍需保持清楚：用户回答会保存为新的原始修订，使相关正文失效并等待重核对，但回答方法本身不会自动启动下一轮生成。[用户回答触发知识失效 ↗](../../../apps/server/src/knowledge/repository.ts#L169 "支持回答被保存为原始修订、问题状态更新和相关正文失效，并说明该方法没有直接启动生成流水线。") 检索递归深度限制为 8，数量阈值只在进入遍历时检查，并非严格最终上限；现有函数也不足以单独证明所有调用路径都统一规范化检索词并执行后续可见性过滤。[知识引导的原始 Fragment 召回 ↗](../../../apps/server/src/knowledge/retrieval.ts#L27 "支持依赖有效性检查、文章引用递归、材料行区间核验和原始 Fragment 映射，也界定递归深度、数量阈值及调用契约限制。") 同一文档并发发布的覆盖策略，以及持久任务在崩溃、租约过期或重复消费后的端到端幂等性，仍需结合任务存储实现和行为测试确认。[知识正文事务发布 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前依赖复检、不可变修订保存、head 切换和疑问状态同步，也显示目标 head 没有比较交换条件。")[持久角色任务与租约执行 ↗](../../../apps/server/src/knowledge/pipeline.ts#L60 "支持知识角色任务入列、既有输出读取、租约 worker 创建、角色输出保存、心跳配置和任务状态轮询；同时界定当前材料未包含任务仓库内部恢复语义。")
