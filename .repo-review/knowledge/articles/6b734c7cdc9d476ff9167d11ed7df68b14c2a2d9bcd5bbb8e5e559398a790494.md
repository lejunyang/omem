# 从原始证据到可递归阅读的知识

系统把不可变原始修订组织成带固定内联引用的知识文章，经独立角色复核后发布；文章既支持读者逐层回查，也能引导助手召回原始 Fragment。来源变化会传播失效，用户补充则作为新证据进入下一轮核对。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence-foundation"></a>
## 知识始终建立在原始证据之上

普通摘要容易丢失出处，也难以判断是否仍适用于当前版本。系统把原始修订中的文本、链接、图片和来源信息转换为具有稳定摘要的材料，并排除派生内容。参考 [原始修订转知识材料 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持排除派生内容、合并文本与链接、保留图片和来源字段并计算稳定材料摘要。") 捕获更新会创建新修订及固定 Fragment，不覆盖旧证据。参考 [不可变修订与固定片段 ↗](../../../apps/server/src/store.ts#L197 "支持捕获更新创建新修订并生成固定 Fragment，而不是覆盖旧版本。")

知识文章只是便于理解和导航的派生视图：论断旁保留可读引用，宿主从固定版本复制精确引文，再由独立角色判断语义支持性；原始事实仍来自 Capture、Source、Revision 与 Fragment。参考 [正文与固定引用合同 ↗](../../../docs/implementation/knowledge-pipeline.md#L5 "解释派生正文、宿主绑定引文、独立语义复核以及原始证据边界。")

<a id="review-publish"></a>
## 分析、复核、发布与失效闭环

```mermaid
flowchart LR
  A[固定原始材料] --> B[分析与写作]
  B --> C[带内联引用的草稿]
  C --> D[独立语义复核]
  D -->|通过| E[发布不可变文章]
  D -->|退回| B
  E --> F[来源变化后传播失效]
```
角色只能读取获准的固定行段、图片和来源元数据，子文章会被明确标为派生知识。参考 [固定材料上下文 ↗](../../../apps/server/src/knowledge/pipeline.ts#L30 "支持按获准范围装载原始材料、图片和来源元数据，并标明子文章不是独立证据。") 草稿最多经历四轮写作与独立复核；仅通过的目标发布，持续被拒的内容不会进入当前知识。参考 [独立复核与有限修订 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "支持最多四轮写作复核、仅发布通过目标以及持续拒绝时不发布。")

发布前会重新核对依赖、正文结构与精确引文，通过后在事务中保存不可变版本、切换当前指针并同步疑问。参考 [事务化知识发布 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前依赖与正文校验、不可变版本保存、当前指针切换及疑问同步。") 材料摘要或子文章版本变化时，失效状态会沿文章依赖向上传播，历史版本仍保留。参考 [依赖失效传播 ↗](../../../apps/server/src/knowledge/repository.ts#L166 "支持材料或文章依赖变化后标记失效，并沿文章依赖传播到上层知识。")

<a id="recursive-reading"></a>
## 从论断逐层回到固定原文

阅读接口按文章生成时记录的依赖版本解析引用；固定文章或材料缺失时，引用保留理由并显示为不可操作，不会悄悄改指向最新内容。参考 [固定引用解析 ↗](../../../apps/server/src/knowledge/api.ts#L20 "支持按记录的依赖版本解析文章或材料引用，并在目标不可用时提供不可操作原因。")

读者点击正文中的可操作引用后，页面以文章修订和引用键创建引用帧。参考 [正文引用触发导航 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L20 "支持读者点击可操作引用后，以文章修订和引用键创建引用导航帧。") 引用帧先展示关系与理由，再按固定目标打开指定知识章节或原始材料；目标不可用时显示原因。参考 [引用理由与目标分流 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L21 "支持展示引用关系和理由，并按固定解析结果进入指定知识章节或原始材料。") 个人知识页面把文章、引用和来源帧接入同一 Trail，并保存、恢复当前文章与路径；超过 200 层时保留当前阅读状态，但停止保存完整链接并显示提示。参考 [个人知识路径接入 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L8 "支持知识、引用与来源帧的压栈、路径保存恢复、超长提示以及共享抽屉事件接线。")

共享抽屉在切层时恢复滚动并聚焦标题，Esc 会返回上一层或关闭，完整关闭后归还焦点。参考 [切层、滚动与焦点恢复 ↗](../../../packages/ui/src/components/OmTrailDrawer.vue#L35 "支持切层聚焦、滚动恢复、Esc 返回以及完整关闭后的焦点归还。") 面包屑可跳回已有层，父层入口和底部动作也能逐层返回。参考 [面包屑与逐层返回 ↗](../../../packages/ui/src/components/OmTrailDrawer.vue#L107 "支持面包屑跳转、父层入口和返回动作，完整覆盖抽屉的层级导航论断。")

<a id="retrieval-and-feedback"></a>
## 引导助手召回并吸收用户补充

派生正文可以扩大关键词入口，但最终返回的仍是原始 Fragment。检索会先校验依赖，再沿命中章节实际出现的引用递归，核对固定行区间并映射到重叠片段。参考 [引用回溯原始片段 ↗](../../../apps/server/src/knowledge/retrieval.ts#L33 "支持依赖校验、文章引用递归、固定行区间核对以及映射回原始 Fragment。") 原有会话可见性过滤继续生效，来源变化后也会重新核对材料身份。参考 [知识引导助手召回 ↗](../../../docs/implementation/knowledge-pipeline.md#L55 "明确派生正文只负责导航，最终返回原始 Fragment，并继续执行可见性过滤和来源身份核对。")

材料不足时，文章保留带原因和下一步的调查问题。用户回答先保存为新的原始修订并触发重核对；加入待办则复用现有任务系统。参考 [回答与待办闭环 ↗](../../../apps/server/src/knowledge/repository.ts#L194 "支持把用户回答保存为原始捕获、触发知识失效，并将调查问题幂等转换为待办。") 角色执行进入持久化任务并保存输出，但知识接口展示的运行实例和最近结果仍由当前路由进程维护。参考 [持久化角色任务执行 ↗](../../../apps/server/src/knowledge/pipeline.ts#L60 "支持角色任务入列、结果复用、专用 worker 执行及任务状态轮询。")、[整理状态接口 ↗](../../../apps/server/src/knowledge/api.ts#L82 "支持知识接口中的运行实例和最近结果由当前路由进程变量维护。")
