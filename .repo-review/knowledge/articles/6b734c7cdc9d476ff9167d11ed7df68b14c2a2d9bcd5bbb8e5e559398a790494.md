# 证据、知识生成与递归阅读

系统以不可变原始修订为证据根，将其投影为固定材料，经受限上下文写作、宿主绑定引文和独立语义复核形成版本化知识；阅读与检索可沿固定引用回到历史材料和原始 Fragment。当前闭环已覆盖生成、失效、恢复、服务接口与浏览器阅读，但发布门禁、多实例互斥、历史扫描和超长深链仍有待确认的边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence-boundary"></a>
## 原始证据与派生知识的边界

原始 Capture 修订保存“发生过什么”，知识正文负责解释其意义与关联，两者不能互换。仓储只把非 `derived` 修订投影为材料，并将正文、图片、作者及转述状态纳入稳定摘要，因此模型总结不会反过来成为新的原始事实。[原始修订的材料投影 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持排除派生修订、组合文本与图片，并将作者和转述语境纳入稳定材料摘要。") 文档还必须满足章节内联引用、目标存在和材料范围有效等结构要求，而语义是否真正支持论断由独立角色判断。[知识仓储的结构与引用校验 ↗](e5a00f71eb3b9c04183300900af72d54d39599d69b8a20785ec7260e4f963a1d.md#validation_binding "解释章节内联引用、目标和范围校验，以及结构校验与独立语义复核的职责边界。")

模型只选择材料及行范围，宿主从固定版本复制短引文，避免模型转抄原文。[宿主绑定固定原文 ↗](../../../apps/server/src/knowledge/repository.ts#L74 "支持模型选择材料范围、宿主复制短引文以及纯图片材料的例外处理。") 发布产物保存材料摘要或子文章版本作为依赖；来源变化会使当前知识及上层依赖失效。[知识发布与依赖失效传播 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持依赖新鲜度检查、不可变修订、head 切换、疑问同步和文章依赖的级联失效。") 阅读旧引用时，仓储可按材料键和预期摘要回查历史修订，因此“识别变化”和“追溯旧版本”分别由依赖校验与历史解析承担。[历史固定材料解析 ↗](../../../apps/server/src/knowledge/repository.ts#L159 "支持先查当前材料、未命中时倒序扫描历史修订以寻找固定摘要版本。")

<a id="generation-and-publication"></a>
## 生成、复核与发布流程

流水线依据图片、会话来源和代码扩展名选择视觉、会话、代码或一般材料角色。[材料分析角色选择 ↗](../../../apps/server/src/knowledge/pipeline.ts#L15 "直接支持按图片、会话来源及代码扩展名选择不同分析角色。") 随后只把获准行段与图片装入上下文，并把材料摘要、子文章版本、模型、effort、预算和运行轨迹写入持久任务。[固定上下文与持久化角色任务 ↗](../../../apps/server/src/knowledge/pipeline.ts#L30 "支持受限行段和图片装载、原始材料要求，以及模型配置、预算和运行轨迹进入持久任务。") 模型输出必须完整覆盖指定目标 key；宿主绑定引文后还会拒绝未提供的目标及越过开放范围的材料引用。[批次目标与引用范围校验 ↗](../../../apps/server/src/knowledge/pipeline.ts#L96 "直接支持完整覆盖目标 key、引用仅限已提供对象，以及禁止访问未开放材料行段。")

草稿交给独立 verifier，只有 `accepted` 文档才发布；被退回目标改由刷新角色定向修订，最多四轮，仍不确定的内容在最后一轮降为调查问题，持续未通过则不覆盖有效知识。[独立复核与定向修订循环 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "支持仅发布 accepted 文档、拒绝目标继续修订、最多四轮及最终失败不覆盖有效知识。") 仓储发布时检查依赖新鲜度和文档结构，以稳定摘要形成不可变 revision，并同步 head、疑问和级联失效。[知识发布与依赖失效传播 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持依赖新鲜度检查、不可变修订、head 切换、疑问同步和文章依赖的级联失效。") 文件恢复还要求版本、生成与复核来源齐备且结论为 accepted；依赖变化记为 stale，未满足的子知识依赖暂记 missing。[知识产物恢复规则 ↗](../../../apps/server/src/knowledge/artifacts.ts#L32 "支持恢复时校验版本、生成与复核来源、accepted 结论，并区分 restored、stale、rejected 和 missing。")

<a id="recursive-reading"></a>
## 固定引用如何形成阅读与召回链

知识 API 根据文章保存的依赖版本解析引用：文章目标定位到固定知识版本和章节，材料目标定位到固定摘要与行范围；目标不可用时返回人读原因，而不是悄悄跳到当前版本。[固定版本引用与材料导航 ↗](../../../apps/server/src/knowledge/api.ts#L20 "支持依据保存的依赖版本解析历史文章或材料，并为不可用目标返回明确原因。") 前端复用共享 Evidence Trail，把知识、引用和原始材料组织成可返回的帧栈，并由模态抽屉处理逐层返回、循环提示、滚动与焦点恢复。[共享证据路径交互 ↗](d0fcf9886faf1de0d644844fc62fbc9b2be84f92855abbf93bf51eac8f6753fc.md#trail-and-routing "解释 Trail 帧栈、模态抽屉、退层、滚动、焦点恢复和深链之间的协作。")

派生正文可以扩大召回入口，但不会作为最终证据。检索命中文章后先核对依赖，再沿命中章节实际使用的引用递归；材料引文须仍存在于固定行段，最终只返回与该区间重叠的原始 Fragment。[文章引用递归到原始 Fragment ↗](../../../apps/server/src/knowledge/retrieval.ts#L27 "支持依赖核验、章节引用递归、固定引文确认、原始 Fragment 映射及遍历阈值。") 用户回答未决问题时，回答会成为新的原始修订并使所属知识失效；问题也可幂等转成待办，使补充背景继续进入同一证据链。[疑问回答与待办闭环 ↗](../../../apps/server/src/knowledge/repository.ts#L169 "支持用户回答成为新的原始材料、触发知识失效，以及问题幂等转为待办。")

<a id="progress-and-limits"></a>
## 当前进展、替代结论与能力边界

通用流程已经实现材料分析、独立复核、通过后发布，以及正文、固定引用、原文、搜索、问题、回答和待办接口。[通用分析、复核与知识服务 ↗](../../../docs/implementation/knowledge-pipeline.md#L23 "支持先分析后独立复核、通过后发布，以及知识 API 覆盖正文、引用、原文、搜索、问题、回答和待办。") 阅读侧另有独立证据表明，个人与仓库知识共用组件，并完成多层引用、Esc、深链、焦点、多视口以及知识引导原始 Fragment 召回的验证。[阅读与召回验证进展 ↗](../../../docs/implementation/knowledge-pipeline.md#L45 "支持共享阅读组件、多层引用浏览器验证，以及派生正文引导回到原始 Fragment 的召回边界。") 先前把角色复核、不可变发布、失效、完整 API 和阅读验证统归于单一阅读记录的表述已被上述分项证据替代。

边界仍然存在：Store 当前是单用户 SQLite，团队租户强制隔离尚未实现。[单用户 SQLite 基础 ↗](../../../apps/server/src/store.ts#L2 "支持当前存储面向单用户，团队或租户强制隔离仍属后续迁移。") `/analyze` 仅以进程内变量互斥，搜索也是小写词项的子串匹配，材料未证明多实例间存在工作区级租约。[知识搜索与分析入口 ↗](../../../apps/server/src/knowledge/api.ts#L82 "支持简单子串搜索、进程内运行互斥、材料版本校验和后台分析启动的实现边界。") 历史材料解析会倒序扫描修订。[历史固定材料解析 ↗](../../../apps/server/src/knowledge/repository.ts#L159 "支持先查当前材料、未命中时倒序扫描历史修订以寻找固定摘要版本。") Trail 的 Hash 解析与写入最多保留 200 帧，而内存栈不受同等上限约束，刷新后可能丢失超限路径。[Trail 深链截断行为 ↗](../../../packages/ui/src/OmHashRoute.ts#L27 "支持 Hash 解析与写入仅保留前 200 帧，说明内存栈与刷新恢复范围不一致。")
