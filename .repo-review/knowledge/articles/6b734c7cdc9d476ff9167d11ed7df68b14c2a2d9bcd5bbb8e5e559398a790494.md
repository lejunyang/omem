# 从原始证据到可递归阅读的知识

系统把不可变的原始材料组织成经独立复核、带固定版本引用的知识文章。读者可以沿正文引用逐层进入子知识或历史原文，助手也能借助派生正文找到原始 Fragment；来源变化、用户补充和依赖换版会触发失效与重新核对，而派生总结始终不被提升为独立证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidenceFoundation"></a>
## 为什么知识必须建立在固定证据上

捕获层保存 Source、Revision 与 Fragment，知识层只把未标记为派生的 revision 转换为可阅读材料，汇集文本、链接、图片和来源信息，并用稳定摘要标识内容状态。参考 [原始材料转换 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持知识材料排除派生内容、汇集多种原始载体信息并以稳定摘要标识内容状态。") 因而知识文章承担的是**解释、组织和导航**，证明责任仍属于固定原文；已有文章只能作为带版本的子知识参与综合。延伸阅读：[知识层的证据边界 ↗](2f86ae461d460808ce726b593c6879fbc61be66d00c6f13a6b8e766d0b6ffd0a.md#purpose "提供原文负责证明、派生文章负责解释和组织这一概念的子知识入口。")

正文引用必须指向获准材料的真实行段或子文章章节。模型选择位置，宿主复制固定原文，独立角色再判断引文是否支持附近论断，避免把“能够定位”误当成“语义正确”。参考 [内联引用与原文绑定 ↗](../../../apps/server/src/knowledge/repository.ts#L41 "支持正文引用完整性、材料行段校验，以及宿主复制精确原文供独立复核。")

<a id="generationAndPublication"></a>
## 分析、复核与不可变发布

系统依据图片、会话来源和代码文件特征选择视觉、会话、代码或通用材料分析角色。参考 [材料分析角色选择 ↗](../../../apps/server/src/knowledge/pipeline.ts#L15 "支持依据图片、会话来源和代码文件特征选择分析角色。") 随后进入写作、独立复核和定向修订流程；复核最多进行四轮，只有通过的目标才会记录生成与复核来源并发布，持续无法确认的内容应收敛为有依据的问题。参考 [写作与独立复核循环 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "支持有限轮次修订、逐目标独立复核以及只发布通过文档的流程。")；延伸阅读：[独立复核与发布流程 ↗](b22d52764b13721657e246604945c1dd1a082a38d3efee3d14e3d808709bcad5.md#review-and-publication "提供定向修订、独立复核和发布门槛的子知识说明。")

```mermaid
flowchart LR
  A[固定原始材料] --> B[选择角色并分析写作]
  B --> C[独立语义复核]
  C -->|需修改| B
  C -->|通过| D[核对依赖与内联引用]
  D --> E[发布不可变知识版本]
```

发布前仓库重新比较材料摘要和子文章版本，并校验正文引用；通过后才在事务中写入不可变版本、更新当前指针并清除失效标记。参考 [发布依赖与事务写入 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前核对材料和子文章版本，并事务写入不可变知识版本及当前指针。") 新修订还会同步开放问题并记录发生变化的章节，使知识演进能够被读者感知。参考 [问题与知识变更记录 ↗](../../../apps/server/src/knowledge/repository.ts#L130 "支持新版本同步问题生命周期、识别章节变化并形成知识更新记录。")

<a id="recursiveReading"></a>
## 沿引用递归阅读，而不丢失原文

阅读接口按文章生成时保存的依赖版本解析每条引用。目标仍可取得时，接口返回固定文章修订或材料摘要及其章节、行号；历史目标缺失时则保留引用说明并明确标为不可操作，不会悄悄跳到其他版本。参考 [固定版本引用解析 ↗](../../../apps/server/src/knowledge/api.ts#L20 "支持引用按生成时依赖版本解析，并在固定目标不可用时给出明确原因。")

个人知识页把主文章留在原处，并在共享 Trail 抽屉中打开引用。面包屑、上一层和关闭按钮用于返回，重复目标会显示循环提示。参考 [证据路径导航 ↗](../../../packages/ui/src/components/OmTrailDrawer.vue#L107 "支持面包屑、逐层返回、完整关闭和循环目标提示等阅读交互。") 按 Esc 时，多层路径退回一层、根层关闭；抽屉还会在打开和关闭时管理焦点，并为每一帧保存、恢复滚动位置。参考 [焦点与滚动恢复 ↗](../../../packages/ui/src/components/OmTrailDrawer.vue#L35 "支持 Esc 分层退出、打开和关闭时的焦点管理，以及逐帧滚动位置恢复。")

路径可以写入 URL 供刷新恢复；超过 200 层时运行中的阅读不被截断，但页面停止保存完整深链并显示提示。参考 [阅读路径保存与恢复 ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L8 "支持个人知识页保存和恢复 Trail，并在超过 URL 预算时保留当前阅读且显示提示。") 原文视图同时标明当前或历史版本，代码可围绕引用行展开，Markdown 保持连续阅读，并允许返回该材料的知识解读。延伸阅读：[固定原文阅读 ↗](../../../apps/web/src/knowledge/KnowledgeSource.vue#L33 "支持当前或历史版本提示、代码行段展开、Markdown 连续阅读及返回知识解读。")

<a id="retrievalEvolutionLimits"></a>
## 助手召回、用户补充与当前边界

派生正文可以扩大关键词入口，但不会直接作为助手证据。召回过程先检查文章全部依赖，再沿文章引用递归到固定材料行段，最终只返回与该行段重叠的原始 Fragment。参考 [引用回溯到原始片段 ↗](../../../apps/server/src/knowledge/retrieval.ts#L33 "支持依赖有效性检查、文章引用递归、材料行段核对及原始 Fragment 映射。")；延伸阅读：[知识引导的证据召回 ↗](c1d016bfceaa9ad6e811622ceb90acc5a8a4c40816edc2c9bb6689fa263f00e1.md#flow "提供派生正文只引导检索、最终仍返回原始 Fragment 的子知识说明。")

无法确认的事项会保留为调查问题。用户回答后，系统把答案保存为新的原始捕获并使相关文章等待重新核对；用户也可以明确把问题转换为待办。参考 [用户回答与待办转换 ↗](../../../apps/server/src/knowledge/repository.ts#L202 "支持把回答保存为原始捕获、触发知识失效重核对，并将调查问题幂等转换为待办。")

开发环境合流时，系统先从旧评审库补入当前知识所需的历史原文版本，随后接入 live files，避免历史捕获把源码 source head 倒退；历史文章和当前产物则在此之后通过历史恢复接口载入。参考 [开发环境知识合流顺序 ↗](../../../apps/server/src/knowledge/development.ts#L14 "支持先补入所需旧原文、再捕获 live files，之后恢复历史与当前知识文章的实际顺序。") 历史文章恢复采用幂等写入，不会替换已有 head；只有允许建立 head 且文档尚无 head 时，才插入非当前状态的指针。参考 [历史知识恢复边界 ↗](../../../apps/server/src/knowledge/repository.ts#L152 "支持历史文章幂等写入、不覆盖已有 head，以及可选建立非当前 head 的条件。")

正文、共享 Trail、固定原文和原始 Fragment 召回已经形成完整阅读链，并有浏览器与助手召回验证记录。参考 [阅读与召回进展 ↗](../../../docs/implementation/knowledge-pipeline.md#L45 "支持共享阅读组件、真实浏览器链路以及知识引导助手召回的验证进展。") 当前底层仍是单用户 SQLite，团队级数据库和租户强制隔离尚未实现。参考 [单用户存储边界 ↗](../../../apps/server/src/store.ts#L4 "支持当前 SQLite 实现是单用户基础，而团队数据库和租户强制隔离仍待迁移。") 此外，角色任务虽进入持久化队列，知识 API 的运行中标记和最近结果仍保存在路由进程内；现有材料不足以确认服务重启后的自动恢复与状态查询语义。参考 [持久化角色任务执行 ↗](../../../apps/server/src/knowledge/pipeline.ts#L60 "支持知识角色任务入列、worker 执行和运行结果读取，同时显示流程在进程内轮询任务状态。")、[进程内整理状态 ↗](../../../apps/server/src/knowledge/api.ts#L87 "支持知识 API 的运行实例和最近结果位于路由闭包，并由异步分析流程更新。")
