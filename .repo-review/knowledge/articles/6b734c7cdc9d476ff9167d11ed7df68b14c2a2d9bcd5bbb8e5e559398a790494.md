# 证据、知识生成与递归阅读

固定原始材料经角色化分析、引用绑定、独立语义复核和不可变发布形成派生知识；来源或用户回答变化会触发失效与重核对，阅读和检索最终沿固定引用回到原始 Fragment。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence_boundary"></a>
## 知识正文与事实依据的边界

知识正文用于解释和导航原始材料，而不取代事实依据。仓库从非派生 Revision 的文本、链接、图片及来源属性构造固定材料；标记为派生的 Revision 不会再次成为原始证据。[固定材料的来源边界 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持非派生 Revision 才能构成固定材料，以及材料内容和来源属性参与身份计算的论断。") 正文中的引用必须贴近论断，模型选择固定行范围，宿主复制精确短引文；结构与位置校验不能代替独立角色的语义判断。[内联引用与语义复核分工 ↗](../../../apps/server/src/knowledge/repository.ts#L41 "支持内联引用、范围验证、宿主绑定精确引文以及结构校验不替代独立语义复核。") 材料身份、引用合同及修订边界可继续下钻到“知识材料、修订与失效管理仓库”。[知识材料、修订与失效管理仓库 ↗](e5a00f71eb3b9c04183300900af72d54d39599d69b8a20785ec7260e4f963a1d.md#materials-validation "提供固定材料、引用合同和证据边界的相关子知识下钻入口。")

<a id="generation_lifecycle"></a>
## 角色分析、复核与不可变发布

流水线先按图片、会话、代码或普通材料选择分析角色。[分析角色选择 ↗](../../../apps/server/src/knowledge/pipeline.ts#L15 "支持图片、会话、代码和普通材料分别选择对应分析角色。") 角色上下文只包含获准的固定范围、图片和来源元数据，并明确把子文章标为非独立证据。[固定角色上下文 ↗](../../../apps/server/src/knowledge/pipeline.ts#L30 "支持仅提供获准行范围、图片和来源元数据，并明确标注派生文章的证据身份。") 批次必须完整覆盖目标键，随后绑定引文并检查文档结构、目标可见性和引用行范围。[知识批次与引用范围检查 ↗](../../../apps/server/src/knowledge/pipeline.ts#L96 "支持目标键完整性、引文绑定、文档验证及引用不得越出提供范围。") 初稿再交给独立 verifier；只有通过的文档才发布，退回目标由刷新角色定向修改，最多四轮，最后一轮把仍不确定的结论降为有依据的问题。[独立复核与定向修订 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "支持独立复核发布门槛、最多四轮定向修订，以及最终将不确定结论转为问题。") 此处替代此前把角色路由、范围约束和批次检查一并归因于复核循环的过宽表述。

发布前仓库重新核对材料摘要和子文章修订，再保存不可变修订并切换 current 指针；依赖变化会递归使上层正文失效，但不删除历史。[不可变发布与依赖失效 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前依赖核验、不可变修订、current 指针切换和递归失效传播。") 完整编排可从“知识生成、复核与发布流水线”继续阅读。[知识生成、复核与发布流水线 ↗](b22d52764b13721657e246604945c1dd1a082a38d3efee3d14e3d808709bcad5.md#review-publication "提供角色路由、固定上下文、独立复核和分层综合的相关子知识入口。")

<a id="questions_and_retrieval"></a>
## 疑问、用户回答与原始证据召回

无法确认的事项会在最终修订轮次保留为带依据的问题，而不是写成确定事实。[独立复核与定向修订 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "支持独立复核发布门槛、最多四轮定向修订，以及最终将不确定结论转为问题。") 用户回答由服务端保存为新的手工原始 Revision，并将对应知识标记为待重新核对。[用户回答保存与失效登记 ↗](../../../apps/server/src/knowledge/repository.ts#L171 "支持把回答保存为原始手工捕获，并将相关知识登记为需要重新核对。") 后续分析会把该回答 Revision 加入固定输入，再经过相同的生成与独立复核流程。[回答进入后续分析 ↗](../../../apps/server/src/knowledge/pipeline.ts#L176 "支持后续分析读取回答 Revision，并将其作为固定材料加入输入。") 这替代了此前仅凭前端疑问界面推断服务端持久化与重核对行为的结论。

派生正文可以引导助手检索，但返回候选始终是原始固定 Fragment，之后仍执行可见性规则。[派生导航与原始证据边界 ↗](../../../apps/server/src/knowledge/retrieval.ts#L1 "支持派生正文只用于引导检索，最终候选仍为原始固定 Fragment。") 召回会核验整条依赖链，并沿命中章节实际出现的引用递归到子文章或精确引文所在 Fragment；失效依赖、空引文或无法定位的引文不会成为证据。[引用链与 Fragment 回溯 ↗](../../../apps/server/src/knowledge/retrieval.ts#L33 "支持依赖核验、子文章递归、精确引文定位和无效投影隔离的召回流程。") 当前关键词、递归深度、数量检查和精确引文定位等限制可在“派生知识引导的原始证据召回”继续下钻。[派生知识引导的原始证据召回 ↗](c1d016bfceaa9ad6e811622ceb90acc5a8a4c40816edc2c9bb6689fa263f00e1.md#limits "提供递归深度、数量检查及精确引文定位限制的相关子知识入口。")

<a id="recursive_reader"></a>
## 共享 Evidence Trail 与阅读限制

个人知识与仓库代码知识共用 Evidence Trail：正文引用先展示人读理由，再逐层进入子知识、固定原文或代码位置；共享帧栈支持返回、循环跳回、滚动与焦点恢复以及深链。真实浏览器验证覆盖了五层引用链、Esc、深链、焦点和多视口。[共享 Evidence Trail 与浏览器验证 ↗](../../../docs/implementation/knowledge-pipeline.md#L45 "支持个人知识和仓库知识共用逐层阅读合同，以及五层链、Esc、深链、焦点和多视口验证。") 阅读界面的来源状态还能明确区分原始证据、派生说明、候选、过期、错误和人工整理，避免把导航内容误认作事实依据。[内容来源状态提示 ↗](../../../packages/ui/src/components/OmStatusLine.vue#L2 "支持阅读界面区分原始证据、派生说明、候选、过期、错误和人工整理等来源层级。")

当前限制是哈希深链只序列化帧种类与身份，标题在刷新后可能退化；超过 200 帧时序列化会截断，而内存渲染栈不受同一上限约束。相关实现与不一致之处可从 UI 模块的 Trail 子章节继续核对。[Trail 深链与路由限制 ↗](d0fcf9886faf1de0d644844fc62fbc9b2be84f92855abbf93bf51eac8f6753fc.md#trail-and-routing "提供内存栈与 URL 预算分离、标题恢复和 200 帧静默截断限制的相关子知识入口。")
