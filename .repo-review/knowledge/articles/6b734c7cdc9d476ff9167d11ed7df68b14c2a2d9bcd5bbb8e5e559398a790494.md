# 证据、知识生成与递归阅读

从不可变原始材料出发，经宿主绑定引用、独立语义复核和内容寻址发布形成派生知识；阅读与检索可沿固定依赖递归回到历史原文，同时保留过期、不可用和待核验边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence-boundary"></a>
## 为什么知识不能替代证据

知识正文把分散材料组织成解释，但事实权威仍是 Capture 链上的固定修订与 Fragment。材料转换会排除派生输入；正文要求每节都有内联引用、引用目标存在且材料行区间有效。[固定材料与引用硬约束 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持排除派生修订、构造固定材料，以及每节内联引用、目标存在和材料行区间校验等证据边界。") 模型只选择证据位置，短引文由宿主从固定材料复制，随后交给独立角色判断语义支持性，因此“位置正确”不等于“结论正确”。[宿主复制固定短引文 ↗](../../../apps/server/src/knowledge/repository.ts#L74 "支持模型选择定位范围、宿主复制原文，并将语义支持性留给独立复核角色。") 派生文章可以被原始证据纠正，却不能反过来成为独立原件。

<a id="generation-lifecycle"></a>
## 从材料到可发布知识

流水线按图片、会话来源或代码形态选择分析角色，只装入获准行段、图片、固定来源元数据，并标明子文章是派生知识。[角色选择与限定上下文 ↗](../../../apps/server/src/knowledge/pipeline.ts#L15 "支持按材料形态选择分析角色，并仅装载获准范围、固定元数据和带派生标记的文章。") 草稿须完整覆盖目标键，经宿主绑定引文和可见范围校验后，再由独立 verifier 复核；一次流程最多四次写作，初稿被拒后至多三次定向重写。先前“刷新角色最多修订四轮”的结论已被替代。只有 accepted 文档才能发布。[写作、校验与独立复核循环 ↗](../../../apps/server/src/knowledge/pipeline.ts#L96 "支持目标完整覆盖、引用范围校验、独立 verifier、最多四次写作以及仅发布通过文档。") 发布前还会比较材料摘要与子文章修订；成功结果形成内容寻址的不可变版本，依赖变化则逐层标为非当前而保留历史。[不可变发布与失效传播 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前依赖一致性检查、内容寻址修订、head 更新及依赖变化后的逐层过期传播。")

<a id="recursive-reading"></a>
## 递归阅读与原文回溯

阅读接口按文章保存时的依赖版本解析引用，可进入固定知识章节或固定材料；目标缺失时返回不可操作原因。[固定版本引用解析 ↗](../../../apps/server/src/knowledge/api.ts#L20 "支持按保存的依赖版本解析文章或材料引用，并在目标不可用时返回明确原因。") 个人知识页确实把首页导航和活动阅读帧接入共享 Trail，阅读帧再分派知识正文、固定引用与来源材料；这替代了此前仅凭抽屉组件推断三类业务帧均已接入的结论。[个人知识页接入共享 Trail ↗](../../../apps/web/src/knowledge/PersonalKnowledge.vue#L1 "支持首页与活动阅读帧共同使用共享 Trail 状态、抽屉及导航事件。")[知识、引用与来源帧分派 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L9 "支持活动帧分派到知识正文、固定引用解析或来源材料阅读，证明三类业务帧的消费方接线。") 抽屉本身提供逐层返回、面包屑回跳、循环提示、滚动恢复和关闭后的焦点归还。[共享证据路径交互 ↗](../../../packages/ui/src/components/OmTrailDrawer.vue#L30 "支持模态抽屉的分层返回、面包屑跳转、循环提示、滚动记忆和焦点归还。") Markdown 会区分可操作引用、已解析但不可操作引用和未知引用键，并在高亮后执行白名单净化。[安全内联引用阅读 ↗](../../../packages/ui/src/components/OmMarkdown.vue#L38 "支持三类引用呈现，以及 Markdown 高亮、白名单净化和点击分流。")

<a id="retrieval-progress-limits"></a>
## 召回、实施进展与现有限制

助手可先命中当前知识正文，再沿文章与材料引用回到原始 Fragment；实现会核对依赖、引用范围和绑定引文，派生段落只负责导航，后续仍需执行可见性规则。[由知识回溯原始片段 ↗](../../../apps/server/src/knowledge/retrieval.ts#L8 "支持仅遍历当前知识、递归核对固定依赖和引用，并最终返回原始 Fragment。") 实施记录分别确认：各分析、规划、写作、复核和刷新角色共用既有 Agent 运行时；[共用 Agent 运行时 ↗](../../../docs/implementation/knowledge-pipeline.md#L15 "支持多类分析与知识角色复用既有网关、任务存储、预算和运行 trace。") 仓库适配会把通过复核的正文保存为 JSON 与带内联链接的 Markdown；[仓库适配与可移植制品 ↗](../../../docs/implementation/knowledge-pipeline.md#L31 "支持统一仓库材料流程，以及通过复核的正文导出为 JSON 和带内联链接的 Markdown。") 个人与仓库共用阅读组件，且真实浏览器已验证多层链路、深链、焦点与多视口。[共用阅读组件与浏览器验证 ↗](../../../docs/implementation/knowledge-pipeline.md#L45 "支持个人和仓库共用阅读组件，并记录多层引用链、深链、焦点与多视口的真实浏览器验证。")

仍需区分章节搜索与证据回溯：前者直接遍历文章做正文子串匹配，未在入口刷新或过滤 `current`；[章节子串搜索入口 ↗](../../../apps/server/src/knowledge/api.ts#L82 "支持章节搜索直接遍历文章、按正文子串匹配并限制结果数，也表明入口未刷新或过滤 current。") 用户回答虽会保存为新原始修订并使知识失效，但 API 之后只调用可选 `onAnswer`，不能证明重核验、通知和重试必然发生。[回答捕获与知识失效 ↗](../../../apps/server/src/knowledge/repository.ts#L169 "支持将用户回答捕获为原始修订、更新问题状态并使关联知识失效。")[回答后的可选回调 ↗](../../../apps/server/src/knowledge/api.ts#L75 "支持 API 保存回答后仅调用可选 onAnswer，不能据此确认后续重核验必然发生。") 此外，Hash 读写会把 Trail 截至 200 帧，超限后的完整恢复与可见提示仍未落实。[Trail 深链截断边界 ↗](../../../packages/ui/src/OmHashRoute.ts#L27 "支持 Hash 解析与写入均仅保留前 200 帧，据此界定刷新恢复可能静默丢失超限路径。")
