# 证据、知识生成与递归阅读

固定原始材料经角色化分析、结构校验和独立语义复核形成不可变知识修订；正文只承担解释与导航，来源变化和用户回答会触发失效与重核对，阅读和助手召回最终都回到原始证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence_boundary"></a>
## 为什么知识正文不能成为新的事实来源

知识整理的起点是 Capture 链上的固定 Revision：系统组合其中的文本、链接、图片和来源属性，并明确排除标记为派生的 Revision。[固定原始材料构造 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持知识材料来自非派生 Revision，并由文本、链接、图片和来源属性共同确定内容身份。") 因而正文是可修订的解释层，而事实依据仍是 Source、Revision 与 Fragment；更完整的材料合同及失效规则可下钻阅读“知识材料、修订与失效管理仓库”。[材料、修订与失效管理 ↗](e5a00f71eb3b9c04183300900af72d54d39599d69b8a20785ec7260e4f963a1d.md#materials-validation "链接到相关子知识，进一步解释固定材料、不可变修订和失效传播的实现合同。")

正文用 `[[引用]]` 把论断就近连接到材料行范围或子知识章节。模型负责选择位置，宿主从固定材料复制精确短引文；结构校验只能证明引用存在、范围合法，语义上是否真正支持论断还要由独立角色判断。[内联引用与宿主绑定 ↗](../../../apps/server/src/knowledge/repository.ts#L41 "支持每节引用、目标范围校验、宿主复制原文和独立语义复核之间的职责分离。") 子知识引用用于递归组织和导航，不会因为被高层章节再次概括就成为独立证据。

<a id="generation_review"></a>
## 从角色化分析到不可变发布

流水线按图片、会话、源码或普通材料选择分析角色，只向角色提供获准范围、图片和可信捕获元数据，并把随附文章标成“派生知识、非独立证据”。[角色分派与固定上下文 ↗](../../../apps/server/src/knowledge/pipeline.ts#L15 "支持按材料形态选择角色、限制可见范围，并将子文章明确标注为非独立证据。") 每次运行登记持久任务和 trace；草稿必须完整覆盖目标并通过引用范围、结构合同与独立语义复核。仅通过项发布，退回项由刷新角色依据具体意见定向修订，最多经历有限轮次，最后仍不允许绕过复核。相关角色分派、任务追踪和修订流程可继续阅读“知识生成、复核与发布流水线”。[生成、复核与发布流水线 ↗](b22d52764b13721657e246604945c1dd1a082a38d3efee3d14e3d808709bcad5.md#execution-review "链接到相关子知识，解释持久任务、结构校验、独立复核及有限次定向修订。")

发布前仓库重新比较材料摘要和子文章修订，输入已经变化便拒绝发布；通过后按内容形成不可变 revision，并在事务中切换 current head。[发布前依赖核对 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前比较材料摘要和子文章修订，以及不可变写入和 current head 切换。") 高层主题综合记录对子知识和原始材料的双重依赖，因此既能逐层阅读，又能在任何一层变化时识别旧解释。

<a id="questions_feedback"></a>
## 疑问、回答与失效传播

无法由现有材料确认的事项不会被补成结论，而以带原因、下一步和阻塞状态的问题保留。用户可选择把问题加入待办，或提交背景；回答会作为新的手工原始捕获保存，问题转为已回答，并使关联正文进入失效状态。[用户回答与待办转化 ↗](../../../apps/server/src/knowledge/repository.ts#L169 "支持回答作为原始捕获保存、文章失效，以及用户显式将问题转为待办。") 后续分析才会把该回答 Revision 转为固定材料，连同原材料重新生成和复核。[回答进入后续分析 ↗](../../../apps/server/src/knowledge/pipeline.ts#L161 "支持后续分析读取问题关联的回答 Revision，并将其作为固定材料加入新一轮输入。")

刷新过程比较 current 材料摘要和文章依赖，并把失效沿子知识关系向上传播；历史修订仍可读取，但过期 head 不再被标作 current。[依赖失效传播 ↗](../../../apps/server/src/knowledge/repository.ts#L144 "支持材料或子文章身份变化沿知识依赖链传播，并更新 current 状态。") 这形成“发现缺口—用户补充—正文失效—重新分析—独立复核—发布新修订”的闭环，而不是直接用回答覆盖旧证据。

<a id="recursive_reading"></a>
## 递归阅读、原始证据召回与当前边界

个人知识和代码知识共用 Evidence Trail：读者可从正文引用进入子章节、引用理由、固定原文或代码位置，再逐层返回；抽屉保存路径、滚动位置并处理 Escape、循环跳回和关闭后的焦点归还。[共享 Evidence Trail 抽屉 ↗](../../../packages/ui/src/components/OmTrailDrawer.vue#L30 "支持逐层返回、面包屑跳转、循环提示、滚动恢复及关闭后的焦点归还。") 这套交互的组件合同和已验证阅读链可下钻到“通用知识整理、复核与阅读流程”。[通用知识阅读流程 ↗](277c8acc89c393a5373ca36d829cc4939bc43481c0b909f82600c4abe65e3ee7.md#repository-and-reader "链接到相关子知识，提供个人知识与仓库知识共用阅读组件及浏览器验证的背景。")

助手召回同样区分导航与依据：关键词可以先命中派生正文，但系统会核对整条依赖链，并沿正文中实际出现的引用回到固定原始 Fragment；之后仍执行可见性规则。[派生知识引导的原始证据召回 ↗](c1d016bfceaa9ad6e811622ceb90acc5a8a4c40816edc2c9bb6689fa263f00e1.md#verification "链接到相关子知识，解释正文匹配、依赖核验和沿引用链返回原始 Fragment 的机制。") 当前证据回溯最多进入九个文章层级，入口处以三十条输出作停止检查，且依赖精确短引文定位，不提供语义重定位或跨修订位置续接。[证据回溯边界 ↗](../../../apps/server/src/knowledge/retrieval.ts#L33 "支持递归深度、入口数量检查、精确引文定位和解析失败隔离等当前限制。") 此外，分析互斥目前只存在于单个路由实例内，不能据此推断多进程部署已避免重复运行。[分析运行状态边界 ↗](../../../apps/server/src/knowledge/api.ts#L13 "支持分析互斥由路由实例内存状态维护，因而尚不能证明多进程互斥。")
