# 写操作前的独立交办判定

该文件为事项更新和项目理解等候选写操作提供独立的请求解释器，并在执行前用可核对的对象依据与用户原话做二次校验。它通过角色运行时取得结构化结论，保存判定轨迹；只有 execute 结论、有效目标依据和当前消息中的明确指令同时成立时，调用方才可继续。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为何需要独立解释

助手可能先生成一个“创建事项”或“维护项目上下文”的候选动作，但候选内容本身不能证明用户已经授权。这里定义统一的 `RequestInterpreter`：输入包含已确认的操作者、候选动作和实际目标，也可带入最近对话、当前项目及最近一次真实事项标识；输出必须是结构化的 `RequestInterpretation`。这样，业务流程可以把“模型建议做什么”与“用户是否明确交办”分开处理。参考 [解释器输入合同 ↗](../../../apps/server/src/assistant/request-interpretation.ts#L15 "支持输入包含操作者、候选、目标及可选上下文，并定义统一异步解释器输出。")

该实现依赖共享合同来校验上下文与解释结果，并通过角色包注册表、角色运行网关接入已配置的 Agent；可选的运行请求仓库用于承接运行时请求。它位于 assistant 业务层与 agent-runtime 之间，向上提供解释函数，向下复用统一角色执行设施。参考 [合同与运行时依赖 ↗](../../../apps/server/src/assistant/request-interpretation.ts#L4 "支持该模块与共享合同、角色包注册表、运行网关及请求仓库的关系。")

<a id="flow"></a>
## 代表性调用的处理链

以“把刚才那个事项标记完成”为例，上游会把当前用户消息放进 `actor`，把拟议的事项更新放进 `candidate`，把可见事项及目标对象放进 `target`，并按需附上近期轮次与已持久化的事项标识。工厂函数先取得主助手配置并响应取消信号；缺少配置时直接报错。随后它以 `request-interpreter` 角色启动一次新运行，并转发活动回调。参考 [角色运行初始化 ↗](../../../apps/server/src/assistant/request-interpretation.ts#L45 "支持配置缺失和取消处理，以及 request-interpreter 角色通过运行网关启动。")

```mermaid
flowchart LR
  A[当前消息与候选动作] --> B[构造可信上下文]
  B --> C[独立角色解释]
  C --> D[结构校验]
  D --> E[保存结果与轨迹]
  E --> F[执行前断言]
```

上下文把当前用户原文作为材料，同时携带候选、目标、最近四轮对话及既有事项标识；角色得到的是克隆后的配置。参考 [判定上下文构造 ↗](../../../apps/server/src/assistant/request-interpretation.ts#L70 "支持可信上下文、当前原文材料和最近四轮草稿信息如何交给独立角色。") 运行结果经合同解析后，会写入随机命名的 JSON 文件；其中记录请求标识，并保存候选、目标和 trace。创建 `interpretations` 目录时会请求 `0700` 权限，并以 `0600` 模式创建审计文件；如果目录已经存在，这次调用不会重设其权限。参考 [结果审计落盘 ↗](../../../apps/server/src/assistant/request-interpretation.ts#L101 "支持结构化结果解析、创建目录时请求 0700 模式，以及以 0600 模式创建结果与运行轨迹审计文件。")

<a id="guards"></a>
## 可执行边界

`assertRequestInterpretation` 只接受 `execute`。目标还必须有来源：活跃项目与实际项目 ID 一致，或既有事项与最近真实事项 ID 一致；若依据来自当前请求或先前轮次，`targetQuote` 必须逐字包含在相应用户文本中。结论缺少指令，或指令不在当前用户消息中，也会抛出“尚未收到本人明确交办”。参考 [执行前目标校验 ↗](../../../apps/server/src/assistant/request-interpretation.ts#L31 "支持 execute、目标依据和当前原话指令必须同时成立的执行边界。")

解释器返回前还会再次检查 `instruction` 是否是当前原话的子串；不匹配时拒绝操作。参考 [当前原话复核 ↗](../../../apps/server/src/assistant/request-interpretation.ts#L119 "支持返回前再次要求 instruction 是当前用户消息中的连续原文。") 这套保护采用字面包含关系，能阻止模型凭空改写授权语句，也意味着指令字段必须保留当前消息中的连续原文。`prior_turn` 可以为对象消歧，但最终执行指令仍须落在当前消息中。解释器只返回判断结果，真正的业务写入由调用方在断言通过后继续完成。
