# docs-implementation · 模块理解 · 专题 1

该模块汇集个人助理从 Batch 2 工程基础转向 v3 渐进记忆的设计、迁移与历史验证记录。记录中的受控学习、飞书集成和界面流程已有部分验证；旧有逐句提炼与普遍确认结论已被替代，但当前主助手入口、质量发布门及若干真实平台场景仍需新证据确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责、背景与边界

本模块不是单一功能说明，而是工程合同、设计演进和验收记录的集合。Batch 2 的历史状态记录覆盖合同、持久任务、角色运行时、飞书投递、Vue 流程及集成回归，并将 B2-01 至 B2-07 列为完成、B2-08 列为部分完成；当前能力仍须结合状态页和任务验证记录判断。[Batch 2 历史状态 ↗](../../../docs/implementation/batch2/README.md#L3 "支持 Batch 2 覆盖领域、各切片历史完成度及当前能力仍需依据状态页和验证记录判断。") v3 随后替代“全量提炼后普遍确认”的旧产品路径，规划以飞书为主要入口、Web 为管理和第二入口，同时复用既有基础设施。[主助手 v3 产品定位 ↗](../../../docs/implementation/assistant-v3/README.md#L3 "支持飞书与 Web 的入口定位、旧默认确认路径被替代及既有基础设施继续复用。")

信息模型将原始 Evidence、派生 SourceProfile、临时 WorkingContext 与正式 Knowledge/Commitments 分开：原件始终可检索引用，派生摘要不成为独立证据，线索也不自动变成本人承诺。[四层信息模型 ↗](../../../docs/implementation/assistant-v3/README.md#L77 "解释原件、派生索引、工作上下文和正式知识的职责及证据边界。")

<a id="workflow"></a>
## 主要流程与跨模块关系

材料按 W0 保真收录、W1 可检索化、W2 场景理解、W3 有目的提炼和 W4 巩固维护逐步处理；进入深度提炼取决于明确请求、实际使用、事项更新或复用价值，而非出现新句子。[渐进处理矩阵 ↗](../../../docs/implementation/assistant-v3/processing-policy.md#L23 "支持 W0 至 W4 的处理流程及进入有目的提炼的触发条件。") 低风险变化可按策略自动应用并通知，只有问题关联当前任务、确需用户选择、补证已尽且能说明后果时，Attention Gate 才创建用户可见问题。[Attention Gate 条件 ↗](../../../docs/implementation/assistant-v3/processing-policy.md#L68 "支持低风险自动处理和创建用户可见问题所需满足的相关性、补证与后果说明条件。")

历史记录中的受控学习链路由 capture 创建提炼任务，独立 verifier 读取固定证据与规范化提案 digest；assessment 完整覆盖提案且 digest 一致后，才交由领域服务评估。Agent 无直接写任务、记忆或通知的权限，并通过 receipt 去重、stale 拒绝和 transient retry 保持一致性。[受控学习流水线 ↗](../../../docs/implementation/batch2/b2-08-learning-verification.md#L5 "支持 verifier 读取固定证据与规范化提案 digest、覆盖校验、写权限隔离、去重及 stale 防护。")

<a id="progress"></a>
## 进展、验证与限制

截至 2026 年 9 月 27 日的汇总记录称 B2-01 至 B2-07 完成，B2-08 已接通受控学习主链、生产飞书 Host、通知聚合和质量评测基础设施，但最终发布门尚未完成。[Batch 2 切片完成度 ↗](../../../docs/implementation/batch2/README.md#L3 "支持 B2-01 至 B2-07 与 B2-08 的历史状态，以及质量发布门仍未完成的结论。") B2-08 的实现记录进一步列出生产 Host、三种通知策略和本地质量数据结构。[生产飞书与质量基础设施 ↗](../../../docs/implementation/batch2/b2-08-learning-verification.md#L14 "支持生产飞书 Host、通知聚合模式和本地质量数据结构已进入 B2-08 实现范围。") 一次真实 ACP smoke 使用 gpt-5.4 与 medium effort，完成提炼、验证、应用、任务及通知闭环；它只证明该次运行结果。[真实 ACP 流水线结果 ↗](../../../docs/implementation/batch2/b2-08-learning-verification.md#L44 "专门支持一次 gpt-5.4、medium effort 的真实提炼、验证、应用、任务和通知结果。")

这些历史成果不等于 v3 主助手已接通：v3 设计仍称普通 owner 私聊被忽略，并要求新增持久 AssistantRuntime。[持久主助手入口缺口 ↗](../../../docs/implementation/assistant-v3/README.md#L15 "支持普通 owner 私聊尚未接通及需要新增持久 AssistantRuntime 的设计时状态。") 同期角色记录还将 answerer/planner 的话题续接及只读检索 provider 列为未实现。[会话续接与只读工具缺口 ↗](../../../docs/implementation/batch2/agent-runtime.md#L72 "支持 answerer/planner 话题续接和只读检索 provider 在记录时尚未实现。") 虽有 90 项测试和 12 组浏览器检查通过，开发草稿确认、冻结 holdout、真实等待窗口后的摘要投递及团队化 worker 仍未完成。[回归结果与剩余发布门 ↗](../../../docs/implementation/batch2/b2-08-learning-verification.md#L82 "支持 90 项测试、12 组浏览器检查，以及 holdout、真实摘要投递和团队化部署的剩余限制。")

<a id="constraints"></a>
## 治理、迁移与验收约束

迁移必须保留原件、固定片段、正式修订、绑定、任务、receipt 与 outbox 历史；已取消会话不得复活，legacy scope 不能静默转成项目范围。[迁移与历史保护 ↗](../../../docs/implementation/assistant-v3/migration-and-acceptance.md#L19 "支持保留证据和运行历史、维持取消状态，并禁止静默转换 legacy scope。") Web 与飞书应共用服务端绑定主体的 CommandService；停止控制须阻止新任务和问题、取消未发投递，并如实记录在途外部调用。[统一服务与停止合同 ↗](../../../docs/implementation/assistant-v3/migration-and-acceptance.md#L68 "支持 Web 与飞书共用服务、服务端主体绑定以及端到端停止语义。")

验收要分开记录基线回归、确定性 fixture、真实 ACP、真实飞书和质量样本，mock 结果不能冒充 live。[分层验收方法 ↗](../../../docs/implementation/batch2/acceptance.md#L11 "支持基线、确定性测试、真实 ACP、真实飞书与质量观察必须分层记录。") 发布目标还要求所有展示的支持引用能够回查固定原文，并明确精度与覆盖阈值只是目标、不是既成指标。[证据与质量发布目标 ↗](../../../docs/implementation/batch2/acceptance.md#L124 "支持展示引用须回查固定原文，并说明精度、覆盖等阈值是初始目标而非已达到指标。")
