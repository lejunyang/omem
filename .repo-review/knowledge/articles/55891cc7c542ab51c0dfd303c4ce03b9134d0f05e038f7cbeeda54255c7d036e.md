# Code Wiki 方案与实现复审

该复审以提交 1063d9a 为基线，纠正了“通用 typed projection 已实现”的过度表述，记录固定版本证据链、可提交 Wiki、运行隔离、模型预算与验证结果，同时明确多仓库、多租户、统一编排、语义复核、跨文件调用和语义检索仍未完成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="review-positioning"></a>
## 复审定位与证据一致性

复审认可统一 Capture / Source / Revision / Fragment 的方向，但明确 repo-review 目前只是本仓库的隔离运行配置和阅读视图，可提交 Wiki 属于证据链上的派生物，不能据此宣称通用 typed projection 已经实现。[复审基线与核心判断 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L1 "支持复审认可统一证据链、同时否定通用 typed projection 已实现的定位。")

本轮已修正固定证据错配：代码图只解析捕获时的精确文本，定位失败返回空；代码与文档 revision 同时固定，理解构建和引用校验读取同一批材料。这样可避免磁盘后续变化污染旧快照，也避免用新文档“验证”旧理解。[固定代码正文与引用定位修复 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L7 "说明代码投影改为读取已捕获固定版本，并在定位失败时不再伪造引用。")[代码与文档快照一致性 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L10 "支持理解构建和引用校验使用同一批固定 revision 的事实。")

<a id="delivery-and-runtime"></a>
## 可提交资产与运行边界

Wiki 的交付物分为可读目录、真实模型生成物和人工 seed：模型产物记录模型、时间、输入摘要、依赖 hash 与符号 locator；人工说明仍保持 seed 身份。SQLite、索引、临时模型目录和构建暂存仅位于 runtime，旧 data 目录只是冻结历史，不是当前更新入口。[Wiki 资产与本地缓存分层 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L21 "解释可提交模型产物、人工 seed、运行缓存和冻结旧资产之间的职责边界。")

“跟代码提交走”指源码、人工关系和派生 Wiki 进入 Git，而不是提交持续变化的 WAL。本地索引可由这些资产重建；启动可以恢复知识和构建索引，但默认不重新调用模型。[Git 交付与启动行为 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L29 "支持 Git 保存派生知识而运行索引可重建、默认启动不调用模型的说明。")

<a id="known-limits"></a>
## 仍未完成的能力

当前实现范围仍是 omem 单仓库与单用户 SQLite，review 适配和默认仓库标识尚未抽象为任意多仓库或多租户能力。个人助手材料学习与 CodeUnderstanding 也只复用了 ACP 传输，尚未完全纳入统一的持久任务与独立复核流水线。[仓库范围与编排限制 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L31 "证明当前仅覆盖本仓库、单用户 SQLite，且代码角色尚未完全进入统一材料流水线。")

模型说明只是派生资料；结构校验和引用存在性校验不能证明语义正确，本次亦没有独立 verifier。解析层目前支持 imports，但跨文件 calls、类型解析及跨 revision 语义身份续接均未实现；检索仍是关键词方式，依赖变化后的自动重核验也未完成。[派生说明缺少语义复核 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L35 "支持结构和引用存在性通过不等于语义正确、独立 verifier 尚未执行的限制。")[解析与检索未完成项 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L36 "列明跨文件调用、类型解析、跨 revision 身份、语义检索及自动重核验仍未实现。")

<a id="verification-and-budget"></a>
## 验证证据与预算调整

历史验证记录显示，第一切片的全量检查与多尺寸浏览器流程通过；随后六个目标完成真实模型生成，最终记录为 51 个测试文件、312 个用例及两套浏览器脚本退出码均为 0。不过这些结果证明的是当时基线上的检查与生成成功，不等于上述架构边界已被消除。[检查、浏览器与真实模型验证记录 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L39 "支持当时切片检查、真实模型生成和最终测试退出码的历史进展陈述。")
