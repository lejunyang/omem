# 固定快照上的代码理解角色

agent-runtime 定义了仓库画像、符号解释和关系核验三类并列的代码理解角色。它们共享固定快照、证据纪律和 CodeUnderstanding.v1 输出外壳，但现有材料未证明角色之间存在顺序编排或数据传递；独立 verifier 也采用另一套评估合同。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role_scope"></a>
## 三类并列的理解视角

这组角色用于从不同尺度解释同一份固定代码快照。**仓库画像**描述顶层模块、职责边界、关键流程及控制入口出口；**符号解释**聚焦具体符号的签名、读写和调用关系；**关系核验**针对已提供的符号或决策关系，脱离前序推理重新检查图边与证据。参考 [仓库画像范围 ↗](../../../packages/agent-runtime/roles/repo-profiler/1/prompt.md#L3 "支持仓库画像负责仓库尺度的模块、职责边界、流程和入口出口。")[符号解释范围 ↗](../../../packages/agent-runtime/roles/symbol-explainer/1/prompt.md#L3 "支持符号解释聚焦签名、读写和调用关系，并以固定快照为事实边界。")[关系核验范围 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/prompt.md#L3 "支持关系核验只对已提出的关系进行独立重查，不继承其他代理推理。")

三者是并列的角色能力：材料分别规定了任务范围，却没有给出它们之间的调用顺序、候选关系生成方或结果传递方式，因此不能据此视为一条已定义或已实现的流水线。

<a id="evidence_rules"></a>
## 事实、解释与未知项

代码理解结果共享 `CodeUnderstanding.v1` 顶层结构，需携带职责、边界、流程、声明、图引用、未知项、置信度和生成溯源信息，并允许多种生命周期状态。参考 [统一理解结果合同 ↗](../../../packages/agent-runtime/roles/repo-profiler/1/output.schema.json#L4 "支持 CodeUnderstanding.v1 的必填内容、角色范围和生命周期状态。")

各角色都要求区分快照直接呈现的 `raw_fact` 与分析者判断的 `interpretation`。符号调用只能依据现存边；缺边表示未知，不能断言不存在关系。关系核验还须从图重新推导，区分“边存在”的机械事实与“关系语义正确”的判断，无法落地的内容进入 `unknowns`。参考 [符号事实与推断 ↗](../../../packages/agent-runtime/roles/symbol-explainer/1/skills/omem-code-symbol-explainer/SKILL.md#L8 "支持节点锚定、调用边来源、事实与推断分类及未知项处理。")[关系语义核验 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/skills/omem-code-relation-verifier/SKILL.md#L8 "支持从图重新推导关系，并区分边存在与语义正确。") 角色置信度只是自评，顶层验证身份留给外层复核运行。参考 [外层验证边界 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/prompt.md#L5 "支持无法落地的关系进入未知项，以及角色不得以自评替代外层验证。")

<a id="configuration_limits"></a>
## 版本装配与可确认边界

三个代码理解角色都通过版本化清单绑定提示词、技能制品和统一输出合同，并配置相同的上下文与输出预算；最大引用节点数分别为仓库画像 300、关系核验 150、符号解释 100。该差异只说明静态配置不同，不能证明实际覆盖范围或设计意图。参考 [仓库画像配置 ↗](../../../packages/agent-runtime/roles/repo-profiler/1/manifest.json#L2 "支持仓库画像的版本化装配、资源预算和最大引用节点数。")[关系核验配置 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/manifest.json#L2 "支持关系核验的版本化装配、资源预算和最大引用节点数。")[符号解释配置 ↗](../../../packages/agent-runtime/roles/symbol-explainer/1/manifest.json#L2 "支持符号解释的版本化装配、资源预算和最大引用节点数。")

另有一个 `verifier` 角色使用 `AssessmentBatch.v1` 和版本化证据复核技能，配置为无工具、会话不复用且不继承用户扩展。参考 [独立复核合同 ↗](../../../packages/agent-runtime/roles/verifier/1/manifest.json#L9 "支持 verifier 绑定版本化证据复核技能并输出 AssessmentBatch.v1。")[复核隔离配置 ↗](../../../packages/agent-runtime/roles/verifier/1/manifest.json#L18 "支持 verifier 的无工具、会话隔离、扩展隔离和资源上限配置。") 但材料没有说明它是否负责推进代码理解结果状态，也未证明宿主会执行摘要、快照引用和预算校验。共享 Schema 对 `key_flows`、`claims`、`evidence_refs` 也只有数组级约束，元素语义是否另由宿主验证仍待确认。参考 [复杂字段约束 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/output.schema.json#L46 "支持共享 Schema 对流程、声明和证据引用只提供数组级结构约束。")
