# agent-runtime · 模块理解 · 专题 6

agent-runtime 以仓库画像、符号解释、关系核验和通用证据核验提供不同层次的分析能力。前三者共享代码理解合同，但现有材料未证明它们已按固定顺序编排；静态配置、证据纪律和预算已经明确，宿主语义校验、状态推进及超限策略仍待确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role_layers"></a>
## 角色分工与共同事实边界

仓库画像描述顶层模块、职责边界和控制入口出口；符号解释下钻到签名、读写及调用关系；关系核验则从固定快照重新检查候选关系，不继承前序推理。[仓库画像任务范围 ↗](../../../packages/agent-runtime/roles/repo-profiler/1/prompt.md#L3 "支持仓库画像负责模块职责、边界以及控制入口出口的说明。")[符号解释任务范围 ↗](../../../packages/agent-runtime/roles/symbol-explainer/1/prompt.md#L3 "支持符号解释关注签名、读写对象和调用关系，并以固定快照为事实边界。")[关系独立复核职责 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/prompt.md#L3 "支持关系核验从快照重新判断、不继承前序推理，以及无法落地的关系进入未知项。") 通用 `verifier` 使用另一输出合同，负责比较提案与原始证据的主体、范围、时间和条件，只评估支持性而不执行变更。[通用证据核验职责 ↗](../../../packages/agent-runtime/roles/verifier/1/prompt.md#L3 "支持通用核验者独立比较提案与原始证据，并且只评估支持性而不执行变更。")

<a id="capability_composition"></a>
## 可组合能力，而非已证实的流水线

三类代码角色可以组合为由全局画像到局部解释、再到关系复核的分析路径，但现有材料只分别规定各自方法，没有调度器或运行记录证明固定先后顺序。画像从文件和节点归组，符号解释以节点及已有边锚定，关系核验从图和证据重推导。[仓库画像组织方法 ↗](../../../packages/agent-runtime/roles/repo-profiler/1/skills/omem-code-repo-profiler/SKILL.md#L8 "支持从快照文件和节点归组职责、区分事实与解释的画像方法，但不证明其在固定流水线中的顺序。")[符号节点与调用边规则 ↗](../../../packages/agent-runtime/roles/symbol-explainer/1/skills/omem-code-symbol-explainer/SKILL.md#L8 "支持符号解释以节点锚定身份、从已有边读取调用关系并把缺边视为未知。")[关系重推导与解释规则 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/skills/omem-code-relation-verifier/SKILL.md#L8 "支持从图重新推导关系，并允许仍属合理判断但没有现存边支持的内容作为低置信度解释。")

关系核验还存在需保留的口径边界：技能允许“看似合理但无现存边支持”的判断作为低置信度 `interpretation`，提示词却要求完全无法落地的关系进入 `unknowns`。[关系重推导与解释规则 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/skills/omem-code-relation-verifier/SKILL.md#L8 "支持从图重新推导关系，并允许仍属合理判断但没有现存边支持的内容作为低置信度解释。")[关系声明与外层验证边界 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/prompt.md#L5 "支持无法落地的关系进入未知项，以及角色不得自行占用顶层外部验证身份。") 因而不能笼统地把所有证据不足项都归为未知；两者的确定性分界尚待明确。

<a id="contract_and_configuration"></a>
## 共享合同与静态装配

三类代码角色共享 `CodeUnderstanding.v1`，必须携带职责、流程、声明、图引用、未知项、置信度及溯源字段，状态覆盖 seed、generated、verified、failed 和 rejected。[代码理解共享结果结构 ↗](../../../packages/agent-runtime/roles/repo-profiler/1/output.schema.json#L4 "支持代码角色共享的必填字段、角色枚举与结果生命周期状态。") 清单分别绑定版本化提示词与技能制品，统一设置 96,000／24,000 token 预算，而最大引用节点数依次为仓库画像 300、符号解释 100、关系核验 150。[仓库画像装配与预算 ↗](../../../packages/agent-runtime/roles/repo-profiler/1/manifest.json#L2 "支持仓库画像角色、技能制品、token 预算及最大引用节点数的静态配置。")[符号解释装配与预算 ↗](../../../packages/agent-runtime/roles/symbol-explainer/1/manifest.json#L2 "支持符号解释角色、技能制品、token 预算及最大引用节点数的静态配置。")[关系核验装配与预算 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/manifest.json#L2 "支持关系核验角色、技能制品、token 预算及最大引用节点数的静态配置。") 这些数值证明静态装配和规模上限存在，但不说明超限时是拆分、截断还是拒绝。

<a id="limits"></a>
## 验证边界与未完成事项

共享 Schema 能检查顶层字段、枚举、置信度和摘要格式，但 `key_flows`、`claims`、`evidence_refs` 只有数组级约束，生成时间也仅要求字符串；引用存在性和声明语义是否由宿主强制，材料尚不能证明。[共享合同的校验深度 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/output.schema.json#L46 "支持复杂数组缺少元素级结构、生成时间仅按字符串约束的限制判断。") 关系核验者只能用置信度表达自评，顶层验证身份须留给外层运行。[关系声明与外层验证边界 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/prompt.md#L5 "支持无法落地的关系进入未知项，以及角色不得自行占用顶层外部验证身份。") 通用 verifier 虽声明无工具、会话不复用及两次修复预算，也仍只是配置证据。[通用核验隔离与预算配置 ↗](../../../packages/agent-runtime/roles/verifier/1/manifest.json#L17 "支持通用核验角色的无工具、会话隔离及修复预算声明，同时不把静态配置冒充运行验证。") 因此此前关于固定流水线和统一 unknowns 分流的结论已被替代，状态推进、覆盖保护与端到端执行仍需实现或测试材料佐证。
