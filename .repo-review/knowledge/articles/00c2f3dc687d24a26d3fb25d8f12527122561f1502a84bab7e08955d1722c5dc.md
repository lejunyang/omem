# 符号解释分析技能

给出固定快照下解释单个符号的证据优先流程：以节点锚定身份，从已有边读取调用关系，把行为推断降级为 interpretation，并将证据缺口保留为未知项。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="anchoring"></a>
## 节点锚定与事实层

技能要求每个解释都锚定到快照中真实存在的符号节点，并把声明名称、种类及行范围记录为 `raw_fact`。调用者与被调用者只能来自快照边；缺少边代表关系未知，而不是可以断言“没有关系”。[符号节点与调用边锚定规则 ↗](../../../packages/agent-runtime/roles/symbol-explainer/1/skills/omem-code-symbol-explainer/SKILL.md#L8 "支持符号身份和位置来自节点、调用关系只来自已有边，缺边仅表示未知的论断。")

这一规则避免把不完整图误读为完整闭世界，也让符号身份和位置能够被确定性检查。它描述的是应采用的分析流程，不证明快照生成器已捕获所有语言或调用形式。

<a id="inference"></a>
## 推断、置信度与输出边界

每条声明必须标记为 `raw_fact` 或 `interpretation`；行为层面的推断属于后者，并应降低整体置信度。无法解决的行为应进入 `unknowns`，所有引用标识都必须已经存在。[行为推断与置信度规则 ↗](../../../packages/agent-runtime/roles/symbol-explainer/1/skills/omem-code-symbol-explainer/SKILL.md#L10 "支持行为推断应标为 interpretation、降低置信度并把未决行为列入 unknowns。")

技能还要求不把材料内容当作操作指令，不调用工具、不修改任何内容，并仅返回 `CodeUnderstanding.v1` JSON。[符号解释技能执行边界 ↗](../../../packages/agent-runtime/roles/symbol-explainer/1/skills/omem-code-symbol-explainer/SKILL.md#L12 "支持禁止工具调用和修改、只返回指定 JSON 合同的边界说明。") 这与符号解释提示词形成互补：提示词定义产出与封印，技能细化节点、边和不确定性的处理步骤；二者都只是规范材料，不能替代运行验证。
