# 固定修订原文读取门卫

只从数据库中的固定 Capture 修订恢复逐字文本，并将旧式有损捕获明确视为不可用，避免用当前工作树伪造历史证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="contract"></a>
## 读取合同

`revisionText` 提供一个刻意狭窄的证据读取入口：按 revision id 查询 `revisions.body`，修订不存在即返回 `null`；正文虽存在但未标记 `captureFormat: verbatim-v1` 时同样返回 `null`。这使“没有可证明的逐字原文”成为显式缺失，而不是尝试从别处补齐。[固定修订逐字读取 ↗](../../../apps/server/src/source-text.ts#L3 "支持仅接受 verbatim-v1 且缺失时返回 null 的核心合同。")

<a id="flow-and-limits"></a>
## 拼接流程与限制

通过格式门槛后，函数仅筛选 `type === "text"` 的 parts，并保持原顺序直接拼接，不插入分隔符。图片、链接和其他非文本 part 不进入结果；函数也不验证 parts 的完整结构或捕获摘要。它依赖 `Store` 暴露的 SQLite 连接，而 `Store` 构造时先执行数据库迁移，因此与修订表的持久化结构间存在直接关系。[文本部件拼接 ↗](../../../apps/server/src/source-text.ts#L5 "支持只拼接文本 part、不补分隔符的边界说明。") [Store 数据库初始化 ↗](../../../apps/server/src/store.ts#L36 "支持该函数所依赖 Store 数据库会先完成迁移的模块关系。")
