# 固定捕获修订的原文读取

该模块从 Store 管理的 SQLite 修订记录中提取逐字捕获的文本，只接受明确标记为 verbatim-v1 的固定修订；缺失记录和旧式有损捕获均作为未命中处理，避免用当前工作区内容重构历史证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决的问题与证据边界

`revisionText` 为需要引用历史证据的上层流程提供固定修订原文。其核心约束是：证据必须来自捕获时保存的 revision，而不能回读可能已经变化的当前工作树；旧式有损捕获也不会被猜测性还原，而是明确返回 `null`。[固定修订原文约束 ↗](../../../apps/server/src/source-text.ts#L3 "支持该函数只读取固定 Capture revision、拒绝从当前工作树重构证据以及对旧式有损捕获返回未命中的论断。") 这使调用方能够区分“存在可核验逐字原文”与“无法可靠取证”。

<a id="flow"></a>
## 核心读取流程

函数接收 `Store` 和修订 ID，直接查询 `revisions` 表的 `body` 字段；查无记录立即返回 `null`。随后解析 JSON，仅当 `body.context.captureFormat` 为 `verbatim-v1` 时继续处理，筛选 `body.parts` 中类型为 `text` 的片段，并按原顺序无分隔拼接。[修订文本提取实现 ↗](../../../apps/server/src/source-text.ts#L5 "支持查询修订、校验逐字捕获格式、筛选文本片段并拼接返回的核心流程说明。") 因而图片或其他非文本 part 不会进入返回值，而多个文本 part 的边界也不会额外插入换行。

<a id="relations_limits"></a>
## 模块关系与边界条件

该模块通过类型导入依赖 `Store`，并使用其公开的 SQLite 连接；`Store` 负责创建数据库、执行迁移以及初始化各类仓储服务，因此这里是建立在统一持久化层之上的窄读取辅助函数，而非独立存储实现。[Store 数据库初始化 ↗](../../../apps/server/src/store.ts#L36 "说明 Store 暴露 SQLite 连接，并负责迁移和仓储组件初始化，支持本模块与统一持久化层的关系判断。") 当前材料未显示对损坏 JSON、缺失 `parts` 或异常 part 结构的防御：这些情况可能抛错而非返回 `null`。材料也没有提供调用点或测试文件，因此无法确认哪些上层模块消费该函数，以及异常路径是否已有覆盖。
