# 固定修订文本读取

从 SQLite 按修订标识读取捕获正文，仅接受 verbatim-v1 格式并顺序拼接文本部件；记录不存在或格式不匹配时返回 null，且不会用当前工作树内容重建历史证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决的问题与证据边界

`revisionText` 用于读取某个固定 Capture 修订中保存的精确文本，服务于需要引用历史证据的场景。它明确把旧式有损捕获视为未命中，并禁止通过读取当前工作树来补造旧修订内容，从而避免文件后续变化导致历史引用与当时证据不一致。[固定修订的证据约束 ↗](../../../apps/server/src/source-text.ts#L3 "支持函数读取固定 Capture 修订，并明确禁止从当前工作树重建历史证据的设计边界。")

<a id="flow"></a>
## 核心流程

函数接收 `Store` 和 `revisionId`，以参数化 SQL 查询 `revisions.body`；找不到记录时直接返回 `null`。命中后解析正文 JSON，仅在 `context.captureFormat` 等于 `verbatim-v1` 时继续，再筛选 `type === "text"` 的部件，按原顺序提取 `text`，用空分隔符拼成结果。[正文查询、格式校验与文本拼接 ↗](../../../apps/server/src/source-text.ts#L6 "直接支持查询流程、两类 null 返回、文本筛选拼接，以及依据表达式可确定的异常和空值边界。") 查询能力来自 `Store.db`：该字段连接数据目录下的 `omem.sqlite`，并在构造期间完成迁移及相关仓储初始化。[Store 的 SQLite 连接与初始化 ↗](../../../apps/server/src/store.ts#L35 "说明 revisionText 依赖的数据库字段、SQLite 文件位置，以及连接后执行的迁移和仓储初始化。")

<a id="boundaries"></a>
## 边界条件与模块关系

“记录不存在”和“捕获格式不支持”都被折叠为 `null`；合法格式但没有文本部件时，`filter`、`map`、`join` 会产生空字符串。若 `body` 不是合法 JSON，或 `body.parts` 缺失、为 `null`、非数组，则解析或 `filter` 调用会抛错；但单个文本部件缺少 `text` 并不必然抛错，映射得到的 `undefined` 通常会被 `join("")` 拼为空串。[正文查询、格式校验与文本拼接 ↗](../../../apps/server/src/source-text.ts#L6 "直接支持查询流程、两类 null 返回、文本筛选拼接，以及依据表达式可确定的异常和空值边界。") `revisionText` 不负责数据库生命周期；`Store` 在初始化失败时关闭连接并重抛异常，正常关闭则由 `close` 完成。[数据库连接生命周期 ↗](../../../apps/server/src/store.ts#L63 "支持 Store 在初始化失败时关闭数据库并重抛异常，以及提供正常关闭入口的说明。") 所给材料没有调用点和测试，无法确认上层如何解释 `null`，也不能证明畸形数据或图文混合输入已有行为断言。
