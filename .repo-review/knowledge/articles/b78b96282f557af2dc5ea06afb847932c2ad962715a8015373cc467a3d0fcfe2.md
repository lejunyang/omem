# 固定修订原文读取

该模块从统一 SQLite 存储中读取指定 Capture 修订的原始文本，仅接受 verbatim-v1 格式，并以 null 表示记录缺失或不满足无损格式要求，避免从当前工作树重建历史证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 作用与证据边界

`revisionText` 用于取得某个固定 Capture revision 保存时的精确文本。其设计把历史证据限定在不可变修订中，并明确将旧式有损捕获视为缺失，禁止根据可能已经变化的当前工作树反推原文。这样，后续知识生成、引用和复核所依赖的是固定材料，而不是事后重建的近似内容。[固定修订原文的证据约束 ↗](../../../apps/server/src/source-text.ts#L3 "支持函数面向固定 Capture 修订读取精确文本、将旧式有损捕获视为缺失且不从当前工作树重建证据的设计目的。")

<a id="flow"></a>
## 读取与文本提取流程

函数接收 `Store` 与修订 ID，通过参数化查询读取 `revisions.body`；记录不存在时返回 `null`。取得记录后会解析 JSON，只有 `body.context.captureFormat` 为 `verbatim-v1` 才继续，否则也返回 `null`。最终按原有顺序筛选 `type === "text"` 的 part，并以空分隔符拼接其 `text`；图片和其他类型不会进入结果。[修订查询、格式校验与文本拼接 ↗](../../../apps/server/src/source-text.ts#L5 "支持记录缺失返回 null、解析修订正文、筛选 verbatim-v1、拼接文本 part，以及可由实现直接确认的异常和空字符串边界。")

异常边界需要谨慎描述：JSON 损坏会在解析时抛错，`parts` 缺失或为非数组也可能因调用 `filter` 而抛错；但缺少 `type` 的普通对象只会被过滤，某些缺少 `text` 的文本 part 则可能产生非预期拼接结果。因此不能概括为所有结构异常都会抛出。合法但没有文本 part 的修订会得到空字符串，这与表示缺失的 `null` 不同。[修订查询、格式校验与文本拼接 ↗](../../../apps/server/src/source-text.ts#L5 "支持记录缺失返回 null、解析修订正文、筛选 verbatim-v1、拼接文本 part，以及可由实现直接确认的异常和空字符串边界。")

<a id="store_relation"></a>
## 与统一存储的关系及限制

本模块直接使用 `Store` 暴露的数据库连接，没有建立另一套证据来源。`Store` 构造时创建数据目录和 SQLite 文件、执行迁移、准备资源目录，并初始化应用、任务、输入、运行请求和来源档案等组件；初始化失败时会关闭数据库并重新抛出错误。[Store 初始化与失败清理流程 ↗](../../../apps/server/src/store.ts#L38 "支持 Store 创建 SQLite 连接、执行迁移、初始化相关仓储和服务，并在初始化失败时关闭数据库的模块关系说明。") 当前存储被明确界定为单用户 SQLite 基础，团队级约束和 Postgres 支持仍属于后续迁移范围，因此这里的读取能力不代表已经具备多租户隔离。[单用户 SQLite 存储边界 ↗](../../../apps/server/src/store.ts#L4 "支持当前存储以单用户 SQLite 为基础、团队级约束和 Postgres 迁移尚未实现的限制说明。")
