# other · 模块理解 · 专题 5

本专题梳理 Store、仓库同步、运行时数据迁移和角色网关之间已被测试确认的协作边界。Store 提供版本化证据与普通片段链接；repo-review 维护文件来源、修订和专用关系；知识角色通过共享网关受能力、会话和输出合同约束。此前关于三类关系已统一连通及普遍失败原子性的结论被收窄，端到端阅读合同、真实 ACP 兼容性和并发故障恢复仍待验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence-foundation"></a>
## 版本化证据基础与已收窄的结论

Store 对相同捕获进行重试去重，内容变化和恢复都会追加修订，旧片段保持原文；基于陈旧 head 的再次恢复被拒绝。普通片段链接允许循环导航，重复写边保持幂等。[不可变修订与普通片段链接 ↗](../../../apps/server/tests/store.test.ts#L40 "支持捕获去重、历史片段固定、恢复追加新版本，以及循环关系可导航和重复写边幂等。")

此前“代码关系、正文引用与个人知识已共享同一种证据图”的结论被替代。现有材料只分别证明普通片段链接，以及 repo-review 的 requirement 关系能定位到指定标题片段，尚未证明正文引用、专用评审关系与个人知识链接共用同一存储和阅读合同。[需求关系的精确片段锚点 ↗](../../../apps/server/tests/review-sync.test.ts#L573 "支持 requirement 关系指向各自需求标题片段，同时界定该测试只覆盖一种专用关系锚定行为。") 失败安全也不能泛化为所有上层流程的事务保证；目前只能确认图片类型不匹配时不会发布 revision 或通知。[无效图片的发布前拒绝 ↗](../../../apps/server/tests/store.test.ts#L79 "支持图片类型不匹配时不产生 revision 或通知，不能外推为所有失败路径的事务原子性。")

<a id="review-sync"></a>
## 仓库同步、修订与运行时隔离

仓库适配器以路径区分来源：相同内容的不同文件仍保持独立；文件变化追加修订，旧版退出默认召回，删除来源默认隐藏。[文件来源身份与修订历史 ↗](../../../apps/server/tests/review-sync.test.ts#L139 "支持按路径保持独立来源、内容变化追加修订、旧版退出默认召回及删除来源默认隐藏。") 增量同步结合基线、HEAD 与脏工作树；缺失基线会全扫，非 UTF-8 文件局部失败，白名单外的符号链接不会被跟随。[增量快照与异常文件处理 ↗](../../../apps/server/tests/review-sync.test.ts#L233 "支持干净基线零扫描、脏工作树覆盖、缺失基线全扫，以及非 UTF-8 文件和符号链接边界。") 脏树或文件失败时不推进基线，恢复或修复后重新扫描。[脏树与失败文件的基线控制 ↗](../../../apps/server/tests/review-sync.test.ts#L527 "支持脏同步和单文件失败不推进基线，并在工作树恢复或文件修复后重新同步。")

运行时数据与旧目录隔离：默认启动忽略损坏旧库；显式种子才复制数据库和同步状态。重复种子不覆盖已有运行时，无旧快照时不创建数据库，复制失败会清除部分目标并保留旧数据。[运行时启动与显式种子迁移 ↗](../../../apps/server/tests/review-runtime-seed.test.ts#L97 "支持默认启动与旧库隔离，以及显式复制、幂等、空启动和失败清理行为。")

<a id="role-runtime"></a>
## 知识角色的受控执行流程

角色网关加载版本化提示与技能，并将角色包摘要、输出合同和实际技能写入作业 attempt；inline/native 技能、模型、reasoning effort 与图片能力均经过校验。[角色包、技能与能力协商 ↗](../../../apps/server/tests/role-runtime.test.ts#L95 "支持角色配置差异、作业追踪、inline/native 技能校验，以及模型、effort 和图片能力检查。") 格式错误、输出超限、异常结束或超时不会生成任务或应用回执。不同项目使用独立会话，材料中的工具或权限文字仅作为数据，拒绝后的请求不能迟到转化为业务决定。[运行失败与会话权限隔离 ↗](../../../apps/server/tests/role-runtime.test.ts#L293 "支持异常输出和超时不应用、跨项目会话隔离、材料命令无工具权限，以及迟到批准被拒绝。")

知识角色复用同一网关，宿主可在输出校验阶段绑定固定引用；模型草稿与目录被隔离在不可信派生知识区。[知识角色的共享网关合同 ↗](../../../apps/server/tests/role-runtime.test.ts#L436 "支持知识角色复用运行网关、宿主绑定固定引用，并将模型草稿与可信任务指令隔离。") 这些结论来自本地夹具，尚不能证明所有真实 ACP CLI 都兼容。[知识网关验证范围 ↗](95ae13abb50fd46f58f67e746f6ea576d1fad11ac3ce5b6b5b072f9e2501bf1c.md#knowledge-gateway "说明共享网关结论来自本地夹具测试，不能外推为全部真实 ACP CLI 的兼容性证明。")

<a id="verified-boundaries"></a>
## 已验证关联与剩余边界

Review API 已测试类别预过滤、跨源同步拒绝、健康信息脱敏和修订 current 标记。[检索预过滤与 Review API 安全 ↗](../../../apps/server/tests/review-sync.test.ts#L369 "支持类别过滤、跨源写请求拒绝、健康信息脱敏及修订 current 状态接口。") requirement 关系能够指向各自需求标题片段，而不是共享概览表。[需求关系的精确片段锚点 ↗](../../../apps/server/tests/review-sync.test.ts#L573 "支持 requirement 关系指向各自需求标题片段，同时界定该测试只覆盖一种专用关系锚定行为。") 新数据库即使复用另一数据库留下的干净同步状态，也会因自身缺少来源而重新扫描并补齐文件；该结论由独立重建用例直接支持。[新数据库按自身内容重建 ↗](../../../apps/server/tests/review-sync.test.ts#L687 "直接支持新数据库不能仅依赖其他数据库留下的干净同步基线，而会重新扫描并补齐自身缺失来源。")

这些协作点不等于三类知识关系已经端到端统一。当前 Store 用例也未验证进程崩溃、并发连接、资产落盘和外部通知。[Store 测试覆盖边界 ↗](90b8e13d4aa2b8cc67a43c06e1141cc231d181b53bf86ed79584595febcf8cb0.md#coverage-boundary "明确现有 Store 用例未覆盖崩溃恢复、并发竞争、资产落盘失败、外部通知和团队隔离。") 跨文件调用解析、跨修订符号续接及统一阅读导航在本组材料中均缺少直接验收证据。
