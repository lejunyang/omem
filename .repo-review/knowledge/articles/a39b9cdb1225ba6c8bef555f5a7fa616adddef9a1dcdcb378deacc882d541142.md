# 运行时可信边界与可追溯状态演进

本专题串联单用户 Store、仓库同步、角色运行时和旧数据迁移：原始材料以不可变修订保存，派生处理经隔离角色与固定引用执行，仓库增量同步以失败不推进基线保障可重试，旧数据库仅在显式种子流程中复制。现有证据主要来自源码与夹具测试，尚不能证明团队租户隔离、真实外部 ACP 兼容性或并发迁移安全。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence-foundation"></a>
## 不可变证据与单用户事务基础

系统以 SQLite `Store` 作为当前单用户基础，初始化数据库、迁移、资产目录及作业、输入、运行时请求等仓储；团队级数据库与租户强制仍是后续能力。[Store 的单用户定位与初始化 ↗](../../../apps/server/src/store.ts#L4 "支持当前以 SQLite 为单用户基础、构造时初始化数据库和各仓储，以及团队级强制仍待迁移的论断。") 捕获在事务中按来源定位当前版本：相同指纹视为重复，变化则追加 revision、生成固定 fragment、更新 head，并将依赖旧修订的记忆标为过期后入列刷新。派生材料不会再次进入抽取队列，避免总结自循环成为独立证据。[捕获修订与派生队列边界 ↗](../../../apps/server/src/store.ts#L102 "支持捕获去重、追加修订、固定片段、依赖失效与刷新入列，并说明派生材料不再自循环抽取。") 测试进一步证明旧 fragment 保留原文、恢复产生新版本且基于过期 head 的恢复被拒绝，体现“状态可演进、历史不改写”。[历史保留与恢复冲突测试 ↗](../../../apps/server/tests/store.test.ts#L40 "支持旧证据保持固定、恢复创建新修订以及基于过期 head 的恢复被拒绝。")

<a id="review-sync"></a>
## 仓库同步的身份、增量与失败基线

Repo-review 将文件路径作为稳定来源身份：相同内容的不同路径保持独立，内容更新追加修订，删除来源默认不再召回。[文件来源身份与修订历史 ↗](../../../apps/server/tests/review-sync.test.ts#L143 "支持路径独立身份、内容变化追加历史修订、删除来源默认排除和重复同步幂等。") 增量同步同时考虑提交漂移、已跟踪修改和未跟踪文件，并记录提交、dirty、内容摘要与同步时间；无效基线退回全扫，非 UTF-8 文件只造成局部失败，白名单外符号链接不会被跟随。[增量快照与异常文件边界 ↗](../../../apps/server/tests/review-sync.test.ts#L237 "支持提交漂移和脏文件扫描、快照上下文、无效基线全扫、非 UTF-8 局部失败及符号链接限制。") 脏工作树或失败文件不会推进干净基线，恢复或修复后会再次扫描。[脏同步与失败文件的基线控制 ↗](../../../apps/server/tests/review-sync.test.ts#L527 "支持脏工作树和文件失败时不推进干净基线，并在恢复或修复后重新扫描。") 此外，新数据库会检查自身是否缺少来源：即使共享状态目录已有干净基线，也仍会重扫并补齐内容。[新数据库依据自身内容重建 ↗](../../../apps/server/tests/review-sync.test.ts#L687 "直接支持新数据库不能仅凭另一数据库留下的共享同步基线跳过扫描，而会补齐自身缺失来源。") 这一独立证据替代了先前把“新库重建”与失败基线共用同一引用范围的表述。

<a id="role-runtime"></a>
## 角色运行时的隔离与不应用原则

知识处理复用版本化角色网关，不同角色拥有不同 prompt、skill 与 bundle 摘要。作业成功后，角色输出另行持久化；attempt 记录角色包摘要、输出合同和实际加载技能，用于追溯有效执行配置。[角色输出与 attempt 追踪分离 ↗](../../../apps/server/tests/role-runtime.test.ts#L95 "支持角色输出通过 roleOutputs 另行持久化，而 attempt 记录角色包摘要、输出合同和已加载技能。") 这替代了“执行结果写入 attempt”的不准确结论。网关先协商模型再校验 reasoning effort，并检查图片能力；格式错误、超量输出、非正常结束或超时均不会产生任务或应用回执。[能力协商与失败不应用 ↗](../../../apps/server/tests/role-runtime.test.ts#L226 "支持模型及 effort 协商、图片能力检查，以及异常输出和超时不会形成业务应用。") 不同项目使用独立会话，verifier 只接收固定输入；材料中夹带的工具或权限命令被当作数据，拒绝的运行时请求不能迟到批准为业务决定。[会话隔离与材料指令防护 ↗](../../../apps/server/tests/role-runtime.test.ts#L338 "支持跨项目新会话、verifier 输入隔离、嵌入命令按数据处理及拒绝请求不能转为业务决定。") 知识引用由宿主校验阶段绑定回固定材料，模型草稿与目录则留在不可信派生区。[知识引用绑定与草稿隔离 ↗](../../../apps/server/tests/role-runtime.test.ts#L436 "支持知识角色经共享网关执行、引用由宿主绑定固定证据，并将草稿和目录置于不可信派生区。")

<a id="migration-limits"></a>
## 旧数据迁移、当前进展与限制

默认启动与历史 `.repo-review/data` 隔离，即使旧数据库损坏也会得到空的可重建运行时且不改写旧文件。[默认启动隔离损坏旧库 ↗](../../../apps/server/tests/review-runtime-seed.test.ts#L97 "支持默认启动不读取或改写不可用旧数据库，而创建可重新同步的空运行时。") 只有显式种子流程才复制旧数据库并投影同步状态；已有运行时不会被二次覆盖，无旧快照时不动作，失败时删除部分目标以便重试，同时保留旧快照。[显式种子的复制、幂等与失败清理 ↗](../../../apps/server/tests/review-runtime-seed.test.ts#L108 "支持首次复制和状态投影、重复调用不覆盖运行时、无旧快照时不动作及失败后清理部分目标。") 这些材料覆盖单进程事务行为、同步恢复、角色失败隔离和首次迁移安全，但夹具测试不能证明真实外部 ACP CLI、生产代理认证、超大数据库、进程中断或并发种子调用；当前 SQLite 实现也不能视为团队租户隔离已经完成。
