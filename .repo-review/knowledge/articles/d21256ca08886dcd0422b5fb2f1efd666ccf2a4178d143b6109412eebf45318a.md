# 仓库 Wiki 构建与代码理解生成入口

该脚本串联仓库捕获、代码图投影、代码理解生成和 Markdown Wiki 输出，并区分显式生成与复用共享知识两条路径。它依赖隔离的 repo-review 运行数据、当前代码快照和理解存储，但不负责 AST 解析、独立语义复核或事务化发布。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-input"></a>
## 作用与输入边界

脚本在仓库根目录创建 review store 与临时构建目录，依次执行材料捕获和代码图投影，再消费这些结果生成 Wiki；因此它是流程编排入口，而不是直接扫描源码的独立知识库。[捕获与代码投影编排 ↗](../../../scripts/review-wiki.ts#L15 "支持脚本先运行仓库捕获和代码同步，再进入知识生成或 Wiki 构建的流程描述。") review store 与个人工作区隔离，实际运行数据位于 `.repo-review/runtime`，其中数据库进一步落在 `runtime/data`；历史 `.repo-review/data` 仅作为只读种子来源。[repo-review 运行数据布局 ↗](../../../apps/server/src/review/store.ts#L17 "支持隔离运行目录位于 `.repo-review/runtime`、数据库位于其 data 子目录，以及历史数据仅作种子的边界。")

生成模式必须显式提供仓库相对目标，否则立即报错。脚本加载模型配置后逐项生成理解，任一结果失败即抛错；成功结果先导出至 staging，再复制到 `GENERATED_DIR`。[显式目标生成与结果复制 ↗](../../../scripts/review-wiki.ts#L16 "支持生成必须限定目标、逐项失败即终止、结果经 staging 复制到 `GENERATED_DIR`；同时表明当前范围未展开该常量的实际目录。") 先前把该目标直接称为“受版本管理的知识目录”的结论已撤回：当前材料只显示常量导入和复制行为，没有给出常量值或 Git 跟踪状态。

<a id="branching-and-rendering"></a>
## 分支流程与 Wiki 组织

非生成模式若恢复到已有共享知识，只重建知识索引并跳过 Markdown Wiki 渲染；否则读取当前快照、有效文件和符号，构造当前 head 的模块视图。[共享知识分支与当前快照读取 ↗](../../../scripts/review-wiki.ts#L25 "说明已有共享知识时仅重建索引，否则通过非空断言读取当前快照并构造文件、符号视图。") 文件按共享路径规则归入 web、ui、contracts、agent-runtime、服务端子域、scripts 或 other，使命令输出与阅读端采用一致分组。[仓库路径模块分类规则 ↗](../../../packages/contracts/src/code-modules.ts#L1 "支持 Wiki 与其他读取端共享按路径划分模块的规则。")

每个模块只展示每个目标的最新理解，模型结果排在人工 seed 前；脚本明确标示语义复核状态，并把可识别的内部符号替换为限定名。只有同时定位到符号和文件时才生成源码链接；没有理解记录的模块退化为确定性文件目录。[理解记录选择与可读化渲染 ↗](../../../scripts/review-wiki.ts#L52 "支持每目标去重、模型结果优先、复核状态提示、符号名替换及源码链接生成逻辑。")

<a id="limits-and-relations"></a>
## 边界条件与发布限制

代码图是已捕获 Fragment 的确定性投影，不另存文件正文；符号范围属于具体快照，未在最新解析中重现的边只会标为 stale。因此 Wiki 仅反映当前 head，不能证明跨 revision 身份连续性。[代码图投影与快照身份边界 ↗](../../../apps/server/src/code/store.ts#L1 "说明代码图不保存独立正文、符号范围依附快照，以及未重现的边仅转为 stale。") 人工理解 seed 则通过稳定 locator 解析、摘要封存和严格交叉引用校验进入当前结果，失败记录不会遮蔽已有有效结果。[人工理解 seed 的解析与校验 ↗](../../../apps/server/src/code/understanding-store.ts#L1 "支持稳定 locator 解析、摘要封存、严格交叉引用校验及失败结果不覆盖有效结果的机制。")

最终 Markdown 先写入 staging，仅在内容变化时复制到 `.repo-review/wiki.md`，数据库始终在 `finally` 中关闭。[Wiki 分阶段写入与资源关闭 ↗](../../../scripts/review-wiki.ts#L71 "支持 Markdown 先写 staging、按变化复制至最终路径并在 finally 中关闭 store，也揭示这些写入未显示统一事务。") 材料没有显示知识文件复制、索引重建和 Wiki 写入之间存在统一事务；同时，脚本对当前快照使用非空断言，尚不能确认同步成功但未形成快照时的受控行为。同步或捕获若直接抛错，则控制流不会进入该断言场景。

<a id="open-questions"></a>
## 待确认事项

目前仍需确认 `GENERATED_DIR` 的实际发布边界，才能判断生成理解是否属于明确提交的知识资产。[显式目标生成与结果复制 ↗](../../../scripts/review-wiki.ts#L16 "支持生成必须限定目标、逐项失败即终止、结果经 staging 复制到 `GENERATED_DIR`；同时表明当前范围未展开该常量的实际目录。") 还需用空仓库或无可投影文件的命令级测试验证：同步成功后若没有 current snapshot，入口应报出受控错误还是生成空 Wiki。[共享知识分支与当前快照读取 ↗](../../../scripts/review-wiki.ts#L25 "说明已有共享知识时仅重建索引，否则通过非空断言读取当前快照并构造文件、符号视图。") 此外，分阶段写入意味着后续失败可能留下部分产物，其一致性要求仍需由测试或发布约定明确。[Wiki 分阶段写入与资源关闭 ↗](../../../scripts/review-wiki.ts#L71 "支持 Markdown 先写 staging、按变化复制至最终路径并在 finally 中关闭 store，也揭示这些写入未显示统一事务。")
