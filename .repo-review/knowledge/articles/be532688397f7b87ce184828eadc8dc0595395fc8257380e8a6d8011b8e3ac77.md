# 交互原型的目录忽略配置

该配置仅确认 `node_modules/`、`.build/` 与 `test-results/` 三个目录不纳入版本控制。结合 README 可知原型具有 npm 构建和浏览器检查流程，但材料未说明 `.build/` 的用途，也未证明验证产物实际写入 `test-results/`。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="scope"></a>
## 忽略范围

配置明确忽略 `node_modules/`、`.build/` 和 `test-results/` 三个目录。[目录忽略规则 ↗](../../../docs/prototype/.gitignore#L1 "支持三个目录被忽略的直接配置事实，不为目录用途作额外推断。") README 另有 `npm ci` 与 `npm run build` 的操作说明，并称 `build.mjs` 会将源码打包成单个 `index.html`；但它没有交代 `.build/` 是否参与该过程，因此不能把这个目录确定解释为构建中间产物。[原型构建说明 ↗](../../../docs/prototype/README.md#L20 "说明文档定义了 npm 构建流程和单文件打包结果，同时未解释 `.build/` 在流程中的角色。")

<a id="evidence_boundary"></a>
## 测试产物与证据边界

`test-results/` 被排除在版本控制之外，这是配置能够直接证明的唯一相关事实。[测试结果目录规则 ↗](../../../docs/prototype/.gitignore#L3 "支持 `test-results/` 被忽略这一有限结论。") README 表示浏览器检查会输出 `verification.json` 和截图，却没有给出这些文件的具体落盘目录。[浏览器检查产物说明 ↗](../../../docs/prototype/README.md#L32 "说明 README 声称检查会产生验证摘要和截图，但未给出它们与 `test-results/` 的路径对应关系。") 因而不能仅凭目录名称断定这些验证产物均写入 `test-results/`；忽略规则本身也不能证明构建或测试已经执行成功。
