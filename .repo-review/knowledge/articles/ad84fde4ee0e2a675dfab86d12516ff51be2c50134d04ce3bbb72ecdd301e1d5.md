# Web 前端的开发与类型检查基础

Web 模块以 Vite 和 Vue 插件提供前端开发入口，通过本地代理连接 API；TypeScript 配置负责严格的跨包源码检查，但不直接产出 JavaScript。现有材料覆盖开发与检查基础，尚不足以确认生产部署、浏览器兼容范围及后端路由契约。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

Web 前端需要同时处理 Vue 单文件组件、浏览器类型和共享包源码。Vite 配置注册 Vue 插件，承担开发及构建入口；TypeScript 则采用 ESNext 模块和 Bundler 解析方式，并提供 DOM、Vite 客户端等类型环境。两者共同构成“构建工具处理页面、类型系统提前发现问题”的基础。参考 [Vue 构建入口 ↗](../../../apps/web/vite.config.ts#L1 "支持 Vite 配置注册 Vue 插件并作为 Web 前端构建入口的说明。")、[TypeScript 编译环境 ↗](../../../apps/web/tsconfig.json#L1 "支持 ES2023、ESNext、Bundler、DOM 与 Vite 客户端类型共同构成前端类型环境的论断。")

<a id="development-flow"></a>
## 本地开发请求如何流转

开发服务器仅监听 `127.0.0.1`，默认端口为 `5173`，可由 `OMEM_WEB_PORT` 覆盖；`strictPort` 要求端口冲突时直接失败。页面访问 `/api` 时，请求被转发到本机 `OMEM_PORT` 指定的服务，默认端口为 `4317`。

```mermaid
flowchart LR
  Browser[浏览器页面] --> Vite[Vite 开发服务器]
  Vite -->|/api| API[本地 API 服务]
```

这条链路只证明开发期代理关系，不能据此确认后端是否保留 `/api` 前缀或生产环境是否采用同一拓扑。参考 [开发服务器与 API 代理 ↗](../../../apps/web/vite.config.ts#L5 "支持本地监听地址、端口覆盖、严格端口策略及浏览器到本地 API 的代理链路。")

<a id="type-boundary"></a>
## 跨包检查边界与当前限制

类型检查覆盖应用自身的 `.ts`、`.vue` 文件，并直接纳入共享 UI 与契约包源码；`strict` 开启严格检查，`noEmit` 表明 TypeScript 不在此配置下生成 JavaScript。因此，生产转译仍依赖其他构建流程，Vue 单文件组件的完整检查效果也取决于实际调用工具。参考 [跨包类型检查范围 ↗](../../../apps/web/tsconfig.json#L1 "支持严格检查、禁止直接输出以及应用、共享 UI 和契约源码被统一纳入检查范围的说明。")

当前材料没有给出依赖版本、构建脚本、浏览器兼容策略或运行结果，因而不能确认 Vue 主版本、生产部署方式及 ES2023 的最终运行要求。直接跨包包含源码是长期设计还是阶段性安排，也仍需架构材料说明。

<a id="relationships"></a>
## 与其他模块的关系
