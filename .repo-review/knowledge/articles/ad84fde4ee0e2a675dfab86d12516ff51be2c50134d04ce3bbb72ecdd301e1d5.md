# web · 模块理解 · 专题 4

本专题说明 Web 模块的 Vite 开发入口：它接入 Vue 构建插件，在仅限本机访问的固定端口启动开发服务器，并把 `/api` 请求代理到本地后端；现有证据尚不足以覆盖页面结构、生产部署及后端路由契约。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role"></a>
## 职责与背景

这一专题覆盖 Web 模块的开发期基础设施，而非页面业务本身。Vite 配置以 `defineConfig` 为入口，并注册 Vue 插件，使前端源码及 Vue 单文件组件能够进入开发与构建流程。子知识将其归纳为 Web 前端配置入口，但该归纳仍依赖配置源码，不能据此推断具体页面、组件层次、Vue 主版本或生产部署方式。[Web 前端配置入口说明 ↗](2d1fa246d31e535c39f0ad95754add9338d76675bfe7c09bb14a547079e48247.md#purpose "引用子知识对该文件职责与证据边界的组织，帮助首次阅读者理解其属于开发基础设施而非页面业务；具体事实另由原始源码引用支持。")[Vite 与 Vue 插件配置 ↗](../../../apps/web/vite.config.ts#L1 "原始配置直接支持 Vite 配置入口及 Vue 插件注册的论断。")

<a id="request-flow"></a>
## 启动与请求流程

开发服务器固定监听 `127.0.0.1`，默认端口为 `5173`，可由 `OMEM_WEB_PORT` 覆盖；`strictPort: true` 使端口冲突直接暴露，而不会静默切换端口。浏览器访问 `/api` 时，请求由 Vite 转发至 `127.0.0.1` 上的 `OMEM_PORT`，其默认值为 `4317`，形成“浏览器 → Web 开发服务器 → 本地 API”的链路。[本地开发请求流程说明 ↗](2d1fa246d31e535c39f0ad95754add9338d76675bfe7c09bb14a547079e48247.md#dev-flow "引用子知识对浏览器、Vite 开发服务器与本地 API 之间流程的组织；端口和代理细节由相邻原始材料引用核实。")[开发服务器与 API 代理配置 ↗](../../../apps/web/vite.config.ts#L5 "原始配置支持监听地址、端口覆盖、严格端口策略及 `/api` 代理目标等具体事实。")

<a id="relations-limits"></a>
## 跨模块关系与限制

这段配置把 Web 模块与一个本地 HTTP 后端连接起来，同时将开发服务限制在回环地址，默认不向局域网开放。现有材料只显示代理目标，没有后端启动、路由注册或路径重写配置，因此无法确认哪个模块提供 API、后端是否保留 `/api` 前缀，也不能把该代理视为生产部署合同。端口值通过 `Number(...)` 直接转换，非法环境变量可能产生无效数值，而配置中没有显式校验或回退逻辑。[配置边界与模块关系说明 ↗](2d1fa246d31e535c39f0ad95754add9338d76675bfe7c09bb14a547079e48247.md#boundaries "引用子知识对本地绑定、后端证据缺口和端口转换风险的归纳，用于说明当前专题的已知边界。")[本地绑定与环境变量边界 ↗](../../../apps/web/vite.config.ts#L5 "原始配置支持回环地址限制、两个端口环境变量及缺少显式端口校验的分析。")
