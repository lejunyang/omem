# conversation · 模块理解

conversation 模块以 SQLite 持久化会话身份和回合生命周期：会话由工作区、主体、渠道、聊天与线程共同定位，回合在模型调用前写入，并可借助外部事件的稳定摘要辅助去重与重启恢复。它提供的是持久化机制；权限过滤、并发唯一性、合法状态迁移和重复事件跳过仍依赖数据库约束及上层运行器。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-identity"></a>
## 职责与身份边界

该模块是助理运行时的会话账本：会话保存工作区、主体、渠道、聊天、线程、可见性、当前目标与待处理事项，回合记录输入、证据、工具动作、结果及可选回复发件箱。[会话与回合数据合同 ↗](../../../apps/server/src/conversation/router.ts#L7 "支持会话身份、可见性、目标字段以及回合输入、证据、动作、结果和可选发件箱字段的说明。")

会话实际由 `workspace_id + principal_id + channel + chat_id + thread_id` 共同定位；工作区缺省为 `personal`，线程缺省为空串，未命中时才创建。[会话定位与创建流程 ↗](../../../apps/server/src/conversation/router.ts#L81 "支持工作区、主体、渠道、聊天和规范化线程共同参与查询，以及默认个人工作区和未命中后创建的论断。") 因此，旧稿中“会话键由主体与聊天上下文共同组成”的表述已被替代，工作区也是隔离会话身份的必要部分。这里虽然持久化了 `private/group` 可见性，但没有执行证据授权过滤；`setGoal` 也只是按会话 ID 更新目标和时间戳，权限与调用身份仍须由上层保证。[会话目标更新 ↗](../../../apps/server/src/conversation/router.ts#L124 "支持目标更新只是按会话 ID 执行数据库写入、方法内没有权限检查的边界说明。")

<a id="turn-flow"></a>
## 回合入队、去重与状态流转

核心流程是“先持久化、后执行”。存在外部事件标识时，模块用规范化 JSON 的 SHA-256 摘要派生确定性回合 ID；若记录已经存在，仅返回既有回合及 `duplicate: true`。[确定性回合去重 ↗](../../../apps/server/src/conversation/router.ts#L146 "支持外部事件标识派生回合 ID、已有记录时返回 duplicate 信号的流程。")[稳定摘要算法 ↗](../../../apps/server/src/storage/digest.ts#L3 "解释确定性回合 ID 所依赖的键排序、规范化 JSON 与 SHA-256 摘要机制。") 这替代了“重复事件必然不会再次执行或回复”的旧结论：本模块只提供去重信号，是否停止模型执行和消息投递取决于调用方。

新回合使用当前最大序号加一，初始写入空证据、空工具动作和空结果。默认 refs 包含 `pending` 状态与事件标识，但随后展开的调用方 refs 可以覆盖同名键。[回合序号与初始持久化 ↗](../../../apps/server/src/conversation/router.ts#L137 "支持最大序号加一、回合初始值写入，以及调用方 refs 位于默认状态和事件标识之后、可覆盖同名键的判断。") 后续方法通过合并 refs 写入运行、完成、失败、待重试或取消状态；完成时保存结果、证据与工具动作，且仅在传入 `replyOutboxId` 时更新发件箱关联，也可另行绑定发件箱。这些写入没有检查前置状态。[回合状态、结果与发件箱更新 ↗](../../../apps/server/src/conversation/router.ts#L220 "支持 refs 合并更新、各状态写入、完成结果保存，以及 replyOutboxId 为可选参数且状态更新不检查前置状态的说明。") 已有完整结果的调用方还可使用同步记录路径，串联入队与完成。[同步回合记录路径 ↗](../../../apps/server/src/conversation/router.ts#L195 "支持已有完整结果时复用入队与完成方法形成一次性记录流程。")

<a id="recovery-and-limits"></a>
## 恢复能力与实现限制

模块可按序读取某个会话的回合，并跨会话查找仍为 `pending` 或 `running` 的记录，供重启后恢复。当前筛选通过 SQL `LIKE` 匹配序列化 JSON，读取时又直接解析 refs、证据和工具动作；格式变化或损坏数据可能造成漏恢复或抛错，尚无降级路径。[未完成回合恢复与反序列化 ↗](../../../apps/server/src/conversation/router.ts#L286 "支持按序读取、通过 JSON 文本匹配恢复未完成回合，以及多个 JSON 字段被直接解析的限制分析。")

并发与状态一致性也不能由本文件单独证明：会话创建采用先查后插，序号分配采用查询最大值再加一，而材料未包含唯一约束或外层事务；完成、取消、失败和重新待处理之间也没有状态机校验。由此，“必定以 pending 入队”“取消后绝不完成”等旧结论均应视为已被限定，需结合迁移、worker、取消协调与 outbox 投递代码验证。
