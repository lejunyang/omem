# conversation · 模块理解

conversation 模块负责确定会话身份，并将每轮交互持久化为可恢复、可去重的状态记录；它衔接渠道事件、模型执行、证据选择、工具动作与回复发件箱，但不在本模块内完成证据授权、恢复调度或消息投递。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="identity"></a>
## 职责与会话边界

该模块是会话身份与持久化边界。会话由 workspace、主体、渠道、聊天及线程共同定位，不能从聊天标识推断项目身份；private/group 可见性随会话保存，为后续限制证据范围提供上下文，但材料未证明这里直接执行授权过滤。[会话身份与可见性边界 ↗](../../../apps/server/src/conversation/router.ts#L67 "支持会话组合键、禁止从聊天标识推断项目身份，以及 private/group 可见性用于限定证据范围的论断。") 打开会话时，缺省 workspace 为 `personal`，空线程被统一处理；系统按完整组合键复用记录，否则创建新会话，因此同一聊天中的不同线程可以保持独立上下文。[会话打开与创建流程 ↗](../../../apps/server/src/conversation/router.ts#L81 "支持 personal 默认 workspace、线程归一化，以及按完整组合键复用或创建会话的说明。")

<a id="lifecycle"></a>
## 先持久化、再执行

轮次在模型调用前先以 `pending` 状态写入，使崩溃或重启后仍有可检查记录。若携带传输事件标识，系统以其稳定摘要生成轮次标识；再次投递同一事件会复用已有记录并标记重复，从入口抑制二次执行和重复回复。[轮次入队与事件去重 ↗](../../../apps/server/src/conversation/router.ts#L146 "支持模型调用前持久化 pending 轮次、由事件标识生成稳定轮次标识、重复投递复用记录，并揭示 ordinal 计算与插入流程。") 执行状态可转为 `running`、`done`、`failed`、重新 `pending` 或 `cancelled`。完成时保存结果、证据、工具动作和可选发件箱关联；取消会更新状态并记录原因，但不写回复正文或绑定发件箱。[轮次状态与取消语义 ↗](../../../apps/server/src/conversation/router.ts#L220 "支持运行、完成、失败、重试和取消等状态变化，并确认取消会记录原因但不会写回复正文或关联发件箱。") 这替代了旧稿中“取消只改变状态”的不完整结论。

<a id="recovery-limits"></a>
## 恢复能力与实现限制

模块能够按 ordinal 返回某个会话的全部轮次，并跨会话找出仍为 `pending` 或 `running` 的记录，为重启恢复提供候选集合。[轮次查询与重启恢复 ↗](../../../apps/server/src/conversation/router.ts#L286 "支持按 ordinal 读取会话轮次、查找未完成轮次，并揭示恢复查询依赖 JSON 文本匹配的实现限制。") 不过状态嵌在 JSON 文本中，未完成查询依赖 `LIKE` 匹配固定序列化片段；材料也只展示先检查轮次、计算下一 ordinal、再插入的过程，未显示事务、唯一约束或并发冲突处理。[轮次入队与事件去重 ↗](../../../apps/server/src/conversation/router.ts#L146 "支持模型调用前持久化 pending 轮次、由事件标识生成稳定轮次标识、重复投递复用记录，并揭示 ordinal 计算与插入流程。") 因而并发入队、恢复任务的原子领取，以及会话可见性如何传递到证据检索，仍需结合数据库定义和调用方确认。
