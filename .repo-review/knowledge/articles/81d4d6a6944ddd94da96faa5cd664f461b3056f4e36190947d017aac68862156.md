# conversation · 模块理解

conversation 模块以复合身份持久化会话，并用先写入、可幂等的轮次状态衔接模型执行、证据记录与回复投递；它只提供未完成轮次查询，完整恢复调度和取消后的投递抑制仍依赖其他模块。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-identity"></a>
## 职责与身份边界

该模块负责会话身份与轮次持久化。会话由 workspace、principal、channel、chat 和 thread 共同定位，默认 workspace 为 `personal`，且不会从 chat ID 推断项目身份。private/group 可见性、当前目标和待处理事项会随会话保存，为上层检索范围和任务连续性提供上下文；真正的证据权限过滤不在本文件中实施。[会话复合身份与可见性 ↗](../../../apps/server/src/conversation/router.ts#L67 "支持会话复合定位规则、默认工作区、项目身份边界及持久化上下文职责。")

<a id="turn-lifecycle"></a>
## 入队、执行与结果记录

轮次在模型调用前以 `pending` 写入。存在 transport event ID 时，稳定摘要生成确定性轮次 ID，重复投递会返回已有记录，从而为渠道事件提供幂等入口；序号则取同一会话当前最大值加一。[轮次幂等入队与序号分配 ↗](../../../apps/server/src/conversation/router.ts#L137 "支持模型调用前写入 pending、外部事件确定性轮次 ID、重复投递处理及最大序号加一流程。")

执行方可将轮次标为 running，完成时保存结果、所选证据、工具动作、降级标记和可选 outbox；已有完整结果的调用方可通过 `recordTurn` 连续完成入队与结束。[轮次完成与结果持久化 ↗](../../../apps/server/src/conversation/router.ts#L195 "支持同步记录捷径以及完成时保存结果、证据、工具动作、降级状态和回复 outbox。") 失败、暂缓重试和取消均通过 JSON 元数据更新状态。需要修正旧结论：`cancelTurn` 本身只写 cancelled 状态，既不清除已有 outbox，也未证明投递方必然检查该状态，因此不能单凭此方法断言取消一定阻止后续通知。[失败、暂缓与取消状态 ↗](../../../apps/server/src/conversation/router.ts#L262 "支持各状态更新的实际操作，并界定 cancelTurn 只修改状态、未展示投递抑制保证。")

<a id="relations-and-limits"></a>
## 恢复能力与实现限制

该模块连接渠道事件、模型执行、证据选择、工具动作和回复 outbox，但只持久化相关状态与结果，不负责模型调用、检索过滤或实际消息投递。`unfinishedTurns` 能跨会话列出 pending/running 记录，为进程重启后的恢复调度提供输入；它没有展示重新调度、执行接管或状态协调，因此替代此前“已经实现完整重启恢复”的结论。[未完成轮次查询 ↗](../../../apps/server/src/conversation/router.ts#L303 "支持该方法仅查询 pending/running 轮次并为恢复提供输入，而非证明完整重启恢复流程。")

状态保存在 `input_message_refs` JSON 中，未完成轮次依赖固定文本片段的 `LIKE` 查询，可靠性受序列化形态约束。另一个未决边界是序号分配：最大值查询与插入分离，当前材料没有显示事务、唯一约束或上层串行保证，不能认定并发入队安全。[序号计算实现 ↗](../../../apps/server/src/conversation/router.ts#L137 "支持序号通过 MAX(ordinal)+1 计算，并说明当前材料没有展示查询与插入之间的并发保护。")
