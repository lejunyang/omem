# 从 Capture 修订构建代码知识快照

同步服务读取已捕获的不可变文件修订，离线解析结构并投影为快照化代码图，生成符号与多类关系，处理删除和过期状态，最后切换当前 head 并恢复派生理解。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="input-snapshot"></a>
## 输入来源与快照身份

同步不直接把工作树正文当作分析事实，而从 `sources.head` 指向的 Capture revision 读取已捕获文本，只纳入指定目录和扩展名；无法取得精确文本或内容为空的材料会跳过。[Capture 修订输入筛选 ↗](../../../apps/server/src/code/sync.ts#L170 "支持同步只读取捕获链 head revision、筛选路径类型并跳过不可用文本的说明。") Git 仅提供提交、远端、分支和 dirty 元数据。快照标识组合仓库、提交、dirty 状态及排序后的捕获内容哈希，因此相同输入可复用旧快照，但每次仍会重新对账当前 head。[快照生成与复用 ↗](../../../apps/server/src/code/sync.ts#L188 "支持快照身份、Git dirty 元数据及复用后仍需对账的流程。")

<a id="projection"></a>
## 符号与关系投影

每个文件先写入文件记录和快照绑定，再将解析符号按稳定限定名生成标识，并尝试用声明行短文本定位其 Capture fragment。[文件、快照与符号绑定 ↗](../../../apps/server/src/code/sync.ts#L220 "说明文件记录、固定 revision 绑定、符号标识及片段定位的写入过程。") 文件到符号的 `defines` 边为 confirmed；相对导入仅在已捕获路径集合内解析，无法解析时保留 missing。调用只在同一文件的名称映射中连边，并明确标为 candidate，源码没有提供跨文件调用解析依据。[定义、导入与调用边 ↗](../../../apps/server/src/code/sync.ts#L272 "支持定义边确认、相对导入缺失状态和单文件调用候选语义。")

<a id="special-symbols"></a>
## 路由、测试与 Vue 线索

路由和测试被提升为独立符号：路由关系确认其由当前文件暴露；测试边目前指回测试文件自身，并不证明它覆盖某个生产符号。Vue 模板的大写组件标签生成 `uses_component` 候选边，但没有解析到目标组件。[路由测试和组件关系 ↗](../../../apps/server/src/code/sync.ts#L332 "说明三类特殊结构如何成为符号或边，以及候选和未解析边界。") 因而这些结构适合导航和后续核验，不应直接等同于经过类型分析或行为测试证实的依赖图。

<a id="reconciliation"></a>
## 删除、过期与后续理解

本轮未出现的已有文件会标为 removed；未重现或触及删除文件的边在当前快照变成 stale。随后服务显式设置仓库 head，将其他快照的模型生成理解标为过期，投影人工 seed，并恢复可验证的已生成知识产物。[同步收尾与理解恢复 ↗](../../../apps/server/src/code/sync.ts#L435 "支持删除文件、过期理解、显式 head、seed 投影和知识产物恢复流程。") 返回值统计当前快照的文件、符号、非过期边和新失效边，并注明快照是否复用；入库成功本身不代表候选关系已被语义确认。
