# Capture 驱动的代码知识同步流程

从固定 Capture head 修订读取源码，生成内容寻址快照，解析并投影文件、符号和多类关系，处理删除与失效后显式切换当前快照并恢复派生理解。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="input_snapshot"></a>
## 输入来源与快照身份

同步首先读取 Git 提交、远端和分支元数据，但源码字节只来自 `sources.head` 指向的 Capture 修订，不把实时工作树正文与旧片段混用。它仅纳入 `apps`、`packages`、`scripts` 下的指定扩展名文件，空或无法恢复精确正文的修订会跳过。[Capture 修订输入筛选 ↗](../../../apps/server/src/code/sync.ts#L152 "支持同步只从固定 Capture head 读取正文及文件范围筛选的描述。") 快照 ID 由仓库、提交、脏状态及排序后的捕获内容哈希决定；相同输入复用快照，但仍执行完整协调并最终更新显式 head。[快照创建与复用协调 ↗](../../../apps/server/src/code/sync.ts#L188 "说明快照身份输入、复用检测及复用后仍继续协调。")

<a id="projection"></a>
## 图投影主流程

每个文件先写文件与快照绑定，再为解析符号生成不含范围的稳定 ID，并尝试用声明行短文本定位所属评审 fragment。[文件、符号与片段绑定 ↗](../../../apps/server/src/code/sync.ts#L220 "支持快照文件写入、稳定符号 ID 及声明片段定位流程。") `defines` 为确认边；相对导入只在本次捕获文件集合内解析，解析不到记为 `missing`；调用只在同文件名称表中匹配，命中后也仅记 `candidate`，没有跨文件调用推断。路由和测试建立符号及确认边，Vue 模板组件使用则保持候选且没有目标节点。[关系投影规则 ↗](../../../apps/server/src/code/sync.ts#L291 "支持导入解析、同文件候选调用以及路由测试关系状态的说明。")

<a id="reconcile"></a>
## 删除、失效与派生知识

未出现在当前输入的旧文件会标记 removed；随后仅对当前快照中未重现或接触删除文件的边标记 stale，并把删除文件的理解置旧。同步显式设置当前快照，再失效其他快照的模型生成结果、投影 curated seeds，并尝试恢复可移植生成产物。[同步收尾与理解恢复 ↗](../../../apps/server/src/code/sync.ts#L435 "支持删除文件、边失效、显式 head、curated seed 和生成产物恢复流程。") 返回值统计当前快照的文件、符号、非 stale 边以及本轮失效边，并标明快照是否复用。[同步结果统计 ↗](../../../apps/server/src/code/sync.ts#L475 "说明返回统计的口径及快照复用标志。")
