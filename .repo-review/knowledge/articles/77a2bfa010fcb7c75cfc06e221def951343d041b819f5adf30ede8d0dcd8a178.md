# 代码知识同步与快照投影

该模块把 Capture 链中的固定仓库修订投影为代码快照、文件、符号和关系图。有效且受支持的修订进入代码解析，但快照内容身份覆盖查询得到的全部 captured 行；导入解析仅覆盖捕获集合内的相对路径，调用与 Vue 组件关系仍是受限候选信息。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责与证据边界

该服务把已经捕获的仓库材料稳定投影为 Code Wiki 的文件、符号、关系和理解记录；文件正文仍由 Capture→Revision→Fragment 链持有，代码表只是可重建的派生视图。快照身份由仓库、Git commit、dirty 布尔值与排序后的捕获内容哈希共同组成，相同输入会复用同一快照行。[同步职责与快照身份 ↗](../../../apps/server/src/code/sync.ts#L1 "支持代码表是固定捕获材料的派生投影，并说明快照身份的组成与相同输入的幂等复用。")

分析读取数据库中的固定 head revision，不回读当前工作区来补证据。`revisionText` 只接受无损 `verbatim-v1` 捕获；旧式有损修订或不存在的修订会返回缺失，避免把旧 Fragment 与当前磁盘文本错误拼接。[固定修订文本读取规则 ↗](../../../apps/server/src/source-text.ts#L3 "支持同步只接受无损固定修订文本，且不会从当前工作区重构证据。")

<a id="snapshot-flow"></a>
## 输入筛选、快照身份与幂等协调

主流程查询全部未删除、外部标识以 `omem:` 开头的文件 Source。只有路径位于 `apps`、`packages`、`scripts`，扩展名受支持，且固定修订文本非空的行，才进入 `files`、离线解析和后续文件投影。[捕获筛选与快照计算 ↗](../../../apps/server/src/code/sync.ts#L170 "支持有效文件的筛选、解析条件，并证明快照内容身份使用全部 captured 行且缺失文本按空字符串哈希。")

需要替代此前“有效修订参与快照计算”的结论：快照内容身份实际基于全部 `captured` 行，而非仅基于 `files`。不支持的路径或格式、空文本以及 `revisionText` 返回 `null` 的行仍参与身份计算；其中缺失文本按空字符串求哈希。因此，解析输入集合与快照身份输入集合并不相同。[捕获筛选与快照计算 ↗](../../../apps/server/src/code/sync.ts#L170 "支持有效文件的筛选、解析条件，并证明快照内容身份使用全部 captured 行且缺失文本按空字符串哈希。")

新快照和复用快照都会重新协调固定来源、文件、符号、边和理解。可读取文本的 captured 行会登记为快照来源，有效文件才写入文件投影；复用只表示快照行及其捕获时间保持不变，并不跳过本次同步。[新旧快照协调流程 ↗](../../../apps/server/src/code/sync.ts#L211 "支持新快照与复用快照都会重新登记来源和文件投影，而复用不会跳过同步。")

<a id="graph-projection"></a>
## 符号和关系图的实际范围

符号身份由仓库、路径、限定名和种类确定，并尝试用声明行绑定固定 Fragment。`defines` 为确认边；`imports` 只解析以 `.` 开头的 specifier，并仅在有效文件集合中按有限扩展名寻找目标。因此非相对导入，以及未按这些规则命中的相对导入，都会写成 `missing`。调用关系只做单文件名称匹配，命中后仍标为 `candidate`。[符号、导入与调用投影 ↗](../../../apps/server/src/code/sync.ts#L250 "支持稳定符号身份、仅相对且限有效文件集合的导入解析、missing 状态及单文件候选调用边。")[离线解析能力边界 ↗](../../../apps/server/src/code/parse.ts#L1 "解释调用为何仅作单文件名称级候选解析，以及 Vue、路由和测试信息的解析基础。")

路由会形成专门符号和确认边。测试的 `test_of` 确认边从测试符号指向测试所在的同一文件，只表示测试归属，不能据此证明它覆盖某个实现。Vue 模板使用写成带文本 evidence 的候选边，但目标 symbol/file 未解析，因此当前材料不能支持可导航的组件间关系。[路由、测试与组件候选边 ↗](../../../apps/server/src/code/sync.ts#L332 "支持路由投影、测试边只指向自身文件，以及 Vue 组件使用边未解析目标并保持候选状态。")

<a id="reconciliation"></a>
## 删除、失效与派生成果恢复

同步结束时，未进入本次有效文件集合的已有文件会被标为 removed；这不仅可能表示文件从 Capture 中消失，也可能由路径、格式、空文本或固定文本不可用导致。未重现的边被置旧，removed 文件的理解和非当前快照的模型理解被标记 stale。随后设置显式当前快照，投影人工 seed，并调用生成式成果恢复；恢复报告中非 `restored` 状态会输出告警。[删除失效与恢复调用顺序 ↗](../../../apps/server/src/code/sync.ts#L435 "支持以有效文件集合判定 removed、陈旧边和理解失效、当前快照设置、seed 投影及恢复告警的收尾流程。")

给定的 artifacts 材料只能确认恢复入口会定位生成目录、取得当前快照，并读取理解快照、符号和文件映射；其后续校验、状态判定与写入条件不在允许范围内，不能据此断言依赖摘要一定被核验，或失败结果绝不覆盖有效知识。[生成式理解恢复入口 ↗](../../../apps/server/src/code/artifacts.ts#L63 "仅支持恢复入口读取生成目录、当前快照、理解快照、符号与文件映射，不延伸推断未提供的后续校验逻辑。") 另外，公开 `sync` 虽接收 `only`，当前仍直接执行全量同步。[同步服务公开入口 ↗](../../../apps/server/src/code/sync.ts#L147 "支持 `only` 参数当前未传入执行函数，公开入口始终调用全量同步。")
