# 代码知识同步与快照投影

该模块从固定捕获的代码原件生成代码快照及派生图。快照身份覆盖全部捕获来源，解析集合则受路径、扩展名和文本可用性限制。已有且正是当前的快照会跳过解析与图重写；回到已存在的旧快照仍会重新协调文件、符号和关系。导入仅在有效文件集合内解析相对路径，调用和 Vue 组件关系保留为候选信息。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责与证据绑定

该模块从已经捕获的代码原件生成文件、符号、关系和理解记录。文件正文由捕获链持有，代码表保存可重建的派生投影；快照身份包含仓库、提交、工作区是否有改动，以及捕获修订的身份和内容哈希。相同捕获可复用已有快照。参考 [同步职责与快照身份 ↗](../../../apps/server/src/code/sync.ts#L1 "支持代码表是捕获原件的派生投影，并说明快照身份的组成和相同捕获的复用行为。")

符号证据采用尽力绑定。同步先取得文件当前 head 修订及其 fragments，再用声明行去首尾空白后的前 60 个字符查找包含该文本的 fragment；没有 head、没有 fragments 或没有命中时，`fragmentId` 保持为空。参考 [符号与 fragment 的绑定方式 ↗](../../../apps/server/src/code/sync.ts#L87 "支持从当前 head 修订读取 fragments，并按声明行文本进行尽力匹配。")

<a id="snapshot-flow"></a>
## 输入筛选与两层快照复用

同步查询所有尚未移除、命名空间为 `file` 且外部标识以 `omem:` 开头的来源。每个来源的 head 修订文本只读取一次；文本缺失时按空字符串计算内容哈希。快照 ID 由仓库 ID、Git commit、dirty 状态，以及排序后的“外部标识、修订 ID、内容哈希”共同计算。参考 [来源读取、快照计算与解析筛选 ↗](../../../apps/server/src/code/sync.ts#L154 "支持捕获来源查询、内容哈希、快照 ID 输入、有效文件筛选和解析缓存处理。")

进入解析的集合更窄：路径必须位于 `apps`、`packages` 或 `scripts`，扩展名必须在支持清单中，固定文本还必须存在且非空。解析缓存按路径、内容哈希和解析器版本查询，并用输出哈希检查缓存内容；缓存缺失或损坏时才重新解析。参考 [来源读取、快照计算与解析筛选 ↗](../../../apps/server/src/code/sync.ts#L154 "支持捕获来源查询、内容哈希、快照 ID 输入、有效文件筛选和解析缓存处理。")

复用分成两种情况。已有快照同时也是当前快照时，`projectionReused` 为真，本轮保留现有图，不执行 AST 解析和投影事务。目标快照虽已存在、但当前指针在别处时，返回值中的 `reused` 仍为真，系统却会通过缓存或解析器重建投影并重新协调绑定。快照行及其捕获时间在这两种情况下都保持不变。参考 [当前投影复用与旧快照重建 ↗](../../../apps/server/src/code/sync.ts#L191 "支持只有已是当前的快照才跳过投影，并说明旧快照返回时的协调及快照来源登记条件。")

快照来源登记与解析集合也有区别：只要修订文本不为 `null`，来源就会登记到快照；只有通过目录、扩展名和非空文本筛选的来源才会生成文件投影。参考 [当前投影复用与旧快照重建 ↗](../../../apps/server/src/code/sync.ts#L191 "支持只有已是当前的快照才跳过投影，并说明旧快照返回时的协调及快照来源登记条件。")

<a id="graph-projection"></a>
## 符号和关系图的解析范围

符号 ID 由仓库、文件路径、限定名和种类生成，文件到符号的 `defines` 边标为 `confirmed`。导入只解析以 `.` 开头的 specifier，并依次尝试原路径、`.ts`、`.tsx`、`.vue`、`/index.ts`、`.mjs` 和 `.js`；目标还必须位于本轮有效文件集合中。命中后导入边为 `confirmed`，否则为 `missing`。调用只在同一文件的名称映射中寻找目标，命中后仍标为 `candidate`。参考 [符号、导入和调用边 ↗](../../../apps/server/src/code/sync.ts#L79 "支持稳定符号身份、confirmed defines、限捕获集合的相对导入解析，以及单文件名称级候选调用。")

路由会生成 route 符号和 `confirmed` 边。测试生成 test 符号，`test_of` 边指向测试所在文件，因此它表示文件归属，不能单独证明对某个实现的覆盖。Vue 模板组件使用边不解析目标 symbol 或 file，状态保持 `candidate`。每个有效文件还会写入确定性理解，内容包含语言、符号数和导入数，并明确记录调用解析只限单文件名称级、没有跨文件类型信息。参考 [路由、测试、组件与确定性理解 ↗](../../../apps/server/src/code/sync.ts#L352 "支持路由和测试投影、未解析目标的 Vue 组件候选边，以及文件理解记录的内容与未知项。")

<a id="reconciliation"></a>
## 删除、失效与同步结果

投影事务执行时，本轮未进入有效文件集合的已有文件会标为 removed。事务之后，系统清理已移除文件的解析缓存；非当前投影会把未重现的边置旧，已复用的当前投影则把本轮 stale 数记为 0。已移除文件的理解会失效，其他快照上的模型生成理解也会失效。系统随后显式设置当前快照，再投影人工 seed 并恢复生成式理解；恢复结果不是 `restored` 时会输出告警。参考 [移除、失效、恢复与返回指标 ↗](../../../apps/server/src/code/sync.ts#L455 "支持文件移除、缓存和旧边处理、理解失效、当前快照设置、派生成果恢复及同步结果字段。")

返回值同时给出 `reused` 和 `analysis.projectionReused`。前者表示快照行此前已经存在，后者表示它在调用开始时就是当前投影；解析数、缓存命中数、跳过文件数和各阶段耗时也一并返回。公开的 `sync({ only })` 目前没有把 `only` 传给执行函数，调用仍是全量 `runCodeSync`。参考 [移除、失效、恢复与返回指标 ↗](../../../apps/server/src/code/sync.ts#L455 "支持文件移除、缓存和旧边处理、理解失效、当前快照设置、派生成果恢复及同步结果字段。")[公开同步入口 ↗](../../../apps/server/src/code/sync.ts#L149 "支持 `only` 参数当前未传入 `runCodeSync`，公开入口执行全量同步。")
