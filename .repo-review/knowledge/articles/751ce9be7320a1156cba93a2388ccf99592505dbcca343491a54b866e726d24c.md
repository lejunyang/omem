# 外部检索与记忆工具集成准备度

报告以只读方式评估 WeKnora、Hindsight 与 MemPalace 的环境、隐私、部署和身份映射条件；结论倾向先做 MemPalace 本地检索 PoC，但任何安装、权重下载和真实接入均尚未发生。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="audit-scope"></a>
## 核验范围与环境事实

报告没有安装软件、下载权重、修改项目配置或发送 omem 数据。2026-09-27 的环境实测显示 Docker 未安装，Node 由 osdk 管理，osdk Python 已存在但尚未在项目配置中激活；因此依赖 Docker 的多容器平台当时不具备直接部署条件。[只读核验范围与本机环境 ↗](../../../docs/research/integration-readiness.md#L1 "证明本次仅做调研，并支持 Docker、Node 和 Python 在核验日期的状态说明。")

<a id="tool-boundaries"></a>
## 三类工具的不同边界

MemPalace 的检索路径无需生成式 LLM；Hindsight retain 需要 LLM endpoint，但可使用本地端点；WeKnora 也支持本地模型，不过它是与现有系统重叠的完整多服务平台。三者对固定片段身份的适配方式不同，接口存在不等于身份映射与集成已经完成。[候选工具事实对比 ↗](../../../docs/research/integration-readiness.md#L18 "支持三种工具在 LLM、embedding、固定片段映射及部署形态上的差异说明。")

<a id="recommended-route"></a>
## 建议路线与待授权事项

路线建议先做 MemPalace PoC，再在本地 LLM 就绪后评估 Hindsight，WeKnora 因 Docker 缺失和平台重叠而优先级最低。启动 PoC 涉及项目配置、依赖和模型权重变更；模型选择、远程端点边界、Docker 计划及脱敏语料均需明确决定。[推荐集成顺序与待决事项 ↗](../../../docs/research/integration-readiness.md#L111 "说明三个候选的建议优先级，以及启动 PoC 前尚需用户决定的配置、模型、部署与隐私事项。")
