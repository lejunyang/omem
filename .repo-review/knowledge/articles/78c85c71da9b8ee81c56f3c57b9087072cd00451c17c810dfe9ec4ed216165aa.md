# 质量标注持久化与飞书交互测试

该测试验证质量样本从草稿标注、人工处置到数据集冻结的关键闭环，并覆盖飞书卡片投递、操作者鉴权和事件幂等。它证明了若干可观察行为，但未直接覆盖并发写入、投递失败、密钥轮换及异常事务恢复。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-fixtures"></a>
## 测试目标与夹具边界

文件以临时目录创建真实 SQLite `Store`，并在每例结束后清理；`FakeMessages` 只记录发送参数并返回固定消息 ID，因此数据库行为是真实的，而飞书网络投递仍是进程内替身。样本夹具包含来源定位、显式事实、证据文本、自动应用标志与禁止外部操作约束，用来驱动后续标注状态机。[临时存储、消息替身与样本夹具 ↗](../../../apps/server/tests/quality-annotation.test.ts#L18 "支持测试使用真实临时数据库、伪造消息适配器以及样本输入和草稿标签结构的说明。")

从导入关系可确认测试协作了质量仓储、飞书标注服务、投递 worker、加密密钥存储和稳定摘要模块；但仅凭本文件不能确认这些模块内部的跨文件调用顺序。[质量标注测试的模块依赖 ↗](../../../apps/server/tests/quality-annotation.test.ts#L6 "说明测试显式依赖投递、实时事件、密钥存储、质量服务、仓储、摘要和 Store。")

<a id="skip-revise"></a>
## 跳过与修订状态转换

第一项断言先建立单样本数据集，使用当前 `labelDigest` 执行 `skip`，要求持久化结果为 `skipped`、确认标签为空，进度也只计一个跳过项。随后以同一预期摘要修订草稿，关闭 `autoApply` 并修改备注；断言样本重新进入 `pending`、摘要发生变化、进度恢复为待处理。[跳过后修订的状态断言 ↗](../../../apps/server/tests/quality-annotation.test.ts#L68 "支持 skipped 持久化、进度统计、修订后重新 pending 以及标签摘要变化的论断。") 这覆盖了跳过后返工以及摘要随标签内容变化的行为，也间接体现乐观并发参数的存在，但没有制造旧摘要冲突，因而未证明冲突会被拒绝。

<a id="lark-flow"></a>
## 飞书卡片闭环与安全断言

第二项测试直接写入连接、版本、绑定和通知目标，再创建两个样本并启动标注会话。投递 worker 应只发出一张卡片；卡片动作携带 `omem.quality.v1` 与 `confirm`，序列化内容不得泄露客户端密钥。[卡片投递与密钥防泄露断言 ↗](../../../apps/server/tests/quality-annotation.test.ts#L162 "支持启动标注会话、处理一次投递、检查动作协议以及卡片不包含客户端密钥的说明。")

伪造操作者的动作必须以 `QUALITY_ACTION_REJECTED` 拒绝且不改变进度；合法事件确认首个样本，相同事件 ID 重放只标记为重复。第二张卡片选择另一动作后，两条样本均计为 confirmed，会话转为 completed 且清空当前样本，数据集最终可冻结。[鉴权、重放保护与完成冻结 ↗](../../../apps/server/tests/quality-annotation.test.ts#L197 "支持伪造用户被拒、合法事件推进、重复事件幂等、会话完成和数据集冻结的论断。") 测试未覆盖错误载荷、错误协议、群聊来源、发送或更新失败、事务中断，以及多个 worker 或多个合法操作者竞争同一样本的行为。
