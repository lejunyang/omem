# 飞书质量标注会话验收测试

该测试验证质量样本的跳过、修订和进度状态，以及飞书标注卡从连接数据准备、投递、身份校验、事件去重到完成后冻结的会话路径。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="repository-state"></a>
## 标注状态机

仓库级用例创建 dev 数据集并加入待标注样本，`skip` 操作会持久化为 `skipped` 且不产生 confirmed label；随后修改 draft label 会更新摘要、把样本重新置为 `pending`，并重新计算进度。label digest 在调用中被作为预期摘要传入且会随修订变化；这替代了旧稿中“已证明错误摘要会触发乐观并发冲突”的过强结论，因为本用例没有提交过期摘要并断言拒绝。[跳过与修订状态转换 ↗](../../../apps/server/tests/quality-annotation.test.ts#L68 "支持 skipped、pending、预期摘要传入、摘要变化和进度重新计算，同时显示未测试摘要冲突。")

<a id="lark-flow"></a>
## 飞书投递、鉴权与防重放

集成用例先在临时数据库中建立活动连接、连接版本、owner 私聊绑定和通知目标，再创建两条质量样本并启动标注服务。[飞书连接与 owner 绑定准备 ↗](../../../apps/server/tests/quality-annotation.test.ts#L111 "支持集成用例预先建立连接、版本、owner 私聊绑定和通知目标。") 投递 worker 发送一张项目卡，动作携带 `omem.quality.v1` 与 confirm 操作，序列化卡片不包含客户端密钥。[质量卡启动与安全投递 ↗](../../../apps/server/tests/quality-annotation.test.ts#L162 "支持数据集创建、会话启动、worker 投递、协议动作及卡片不泄露 secret。")

入站动作必须来自绑定 owner：攻击者身份被拒且进度不变；合法事件确认首个样本，相同 eventId 重放只标记 duplicate。第二个动作完成剩余样本后，会话进入 completed、当前样本清空，随后冻结成功。这里证明的是“完成后可成功冻结”，而非本文件单独证明未完成会话一定禁止冻结。[身份校验、幂等与完成后冻结 ↗](../../../apps/server/tests/quality-annotation.test.ts#L197 "支持伪造动作被拒、合法事件推进、事件重放去重、会话完成以及完成后的冻结成功。")

<a id="test-boundaries"></a>
## 测试边界

消息适配器只记录 `send`，其 `update` 是空实现，因此本文件证明的是出站任务、卡片结构和服务端状态推进，不证明真实飞书 API、消息更新、网络重试或限流恢复。[伪消息适配器能力 ↗](../../../apps/server/tests/quality-annotation.test.ts#L24 "说明测试适配器的 send 永远成功且 update 为空，界定外部投递故障覆盖范围。") 连接数据也是直接写入数据库，未覆盖连接建立与 capability 校验流程；外部投递发生部分成功时，会话和 delivery intent 的一致性仍需专门故障测试。
