# 验证体系、质量评测与证据强度

验证证据分为代码基线、受控浏览器纵向流程、真实外部调用快照和隔离质量评测。各层只能证明其实际执行与断言覆盖的范围；fixture、历史快照或单次冒烟不能替代完整生产验收。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence-layers"></a>
## 不同验证分别证明什么

类型检查、全量 Vitest 与构建用于发现类型、合同、回归和打包问题。现有记录显示依赖冻结及完整检查退出码为 0，覆盖 TypeScript/Vue、55 个测试文件、330 个用例和服务端、Web 构建；这只证明对应提交在记录环境中通过代码基线。[知识功能基线检查记录 ↗](../../../docs/implementation/knowledge-verification.json#L7 "支持依赖冻结、完整检查的退出码、测试规模及类型检查、全量测试和构建范围。")

浏览器验收以真实 Fastify、SQLite 和 Chromium 运转，但 Agent 是确定性 ACP fixture。[浏览器验证环境与清单 ↗](../../../docs/implementation/browser-verification.json#L4 "支持浏览器检查采用真实 Fastify、SQLite，同时使用确定性 ACP fixture，并列出覆盖的产品行为。") 具体脚本分别断言递归 Evidence Trail、循环返回与追问，[递归证据阅读流程 ↗](../../../scripts/browser-smoke.ts#L283 "支持 Evidence Trail 的递归引用、环路返回、层级跳转、追问保存和关闭行为。") 以及桌面、768px、390px 布局和键盘焦点；[多视口与键盘交互检查 ↗](../../../scripts/browser-smoke.ts#L512 "支持桌面、768px、390px 无横向溢出、焦点约束、Esc 关闭和移动端全屏对话框断言。") 另通过关闭并重建服务检查材料与待办仍可见。[失败展示与服务重启检查 ↗](../../../scripts/browser-smoke.ts#L610 "支持脚本展示模型及投递失败、模拟接口离线，并在重建服务后检查材料与待办持久化。") 因而此前把这些结果概括为“完整真实端到端验收”的结论已被替代：它们证明受控输入下的页面、存储和导航装配，不证明真实模型或飞书网络。测试装配与未覆盖行为可继续下钻。[个人助手浏览器验收说明 ↗](93b9183049321710c3d8406ee8d8bf2378b3c4459a5e2106c486a2e800f3c1e3.md#purpose_setup "链接相关子知识，供读者下钻真实服务装配、受控驱动方式和未覆盖外部行为。")

<a id="live-evidence"></a>
## 实机检查的强度与边界

实时 ACP 检查会先探测模型候选，显式请求不可用模型时失败；但选择函数只是把环境中的 effort 写入 profile，没有在此校验该强度是否受支持。[ACP 模型候选选择 ↗](../../../scripts/live-model.ts#L4 "支持模型候选探测、显式不可用模型报错，并显示 effort 仅从环境写入 profile。") 算术冒烟随后发起一次文本调用，硬断言仅为回答包含“12”，实际模型、推理强度和事件类型主要作为诊断输出。[ACP 实时算术冒烟 ↗](../../../scripts/live-acp-smoke.ts#L5 "支持算术输入、回答包含“12”的硬断言，以及实际配置和事件类型仅进入输出记录。") 现存快照又缺少输入、时间、退出码和完整会话状态，因此只能作为窄范围现场观察。[ACP 实机快照的证据边界 ↗](cf5a2e0a6f409814a283e4db5c2ac3e7769fee9f836ce993b715ca2741389a47.md#evidence-boundary "链接子知识，解释当前快照为何不足以证明完整会话成功或回答正确。")

飞书快照仅记录 `lark-cli`、文档版本、`text`/`link` part 和字符数，没有固定 Source/Revision、授权主体、退出码或关键内容断言。[飞书文档导入实机快照 ↗](../../../docs/implementation/live-lark-verification.json#L1 "支持快照仅包含连接器、文档版本、part 类型和字符数，缺少完整验收上下文。") 它不能替代机器人 WebSocket、卡片回调、图片下载及幂等导入验收；实时 ACP、Lark 标注、隔离预测和 fixture 浏览器检查的职责边界可从脚本模块继续下钻。[脚本模块的实时与质量流程 ↗](97762e76cba3d5e9bc19883e9db79e5f8ed0afd3e77c4114d9fc9ae68437691e.md#live_and_quality "链接相关子知识，解释实时 ACP、Lark 标注、隔离预测和质量门禁之间的职责分工。")

<a id="quality-loop"></a>
## 隔离数据集与人工评测闭环

质量评测与普通捕获隔离：研究导入器要求显式评测标识，规则切分结果只是待人工判断的草稿，不得进入生产知识。[评测专用导入边界 ↗](../../../apps/server/src/quality/import.ts#L1 "支持质量草稿生成与普通捕获、导入和学习链路隔离，且草稿不得成为生产知识。") 数据集只有在达到目标数量且全部确认后才能冻结，manifest 摘要绑定顺序、输入摘要和确认标签，并可重算发现篡改。[数据集冻结与完整性复核 ↗](../../../apps/server/src/quality/repository.ts#L358 "支持目标数量和全部确认是冻结前置条件，以及 manifest 摘要生成与重算验证。") 候选生成、人工修订和冻结的完整生命周期可继续下钻质量模块。[质量数据集生命周期 ↗](9f9a271cae333333972dbf1ee63356a0627defffcf9b624072cdb0dec804fe38.md#dataset-lifecycle "链接相关子知识，供读者下钻候选样本、人工修订和冻结流程。")

预测 runner 先验证冻结数据集，再为每个样本建立独立临时 Store、运行学习流水线并清理目录。[逐样本隔离预测运行 ↗](../../../scripts/quality-run.ts#L63 "支持每个样本创建独立临时 Store、执行学习流水线并提取预测的流程。") 若执行抛错，它仍保存带错误信息的 `needs_context` 预测，随后清理临时 Store；这可能把基础设施故障与业务上的背景不足混入同一分布。[预测异常转换与清理 ↗](../../../scripts/quality-run.ts#L157 "直接支持运行异常被保存为带 error 的 needs_context 预测，并在 finally 中关闭 Store、删除临时目录。") 评估器只纳入 confirmed 标签，逐对象区分引文定位、语义支持、数字事实槽和必要证据覆盖，并计算完成度与不必要打扰。[确认样本与逐对象评估 ↗](../../../apps/server/src/quality/evaluator.ts#L234 "支持只评估已确认样本，并计算定位、语义、事实槽、覆盖率、完成度和打扰。") 评估命令复验冻结摘要，并以多项阈值及缺失预测决定退出码。[质量评估退出门禁 ↗](../../../scripts/quality-evaluate.ts#L14 "支持评分前复验冻结数据集、各质量阈值以及任一门禁失败时设置非零退出码。")

<a id="progress-limits"></a>
## 已有覆盖与解释限制

当前代码路径已经形成“候选生成—人工标注—冻结—隔离预测—确定性评分—退出门禁”，但现有自动化材料不能证明整条路径均被执行。质量测试直接覆盖评测专用导入、重复导入、人工确认、冻结摘要及篡改检测；[数据集生命周期自动化测试 ↗](../../../apps/server/tests/quality-evaluation.test.ts#L50 "支持自动化测试覆盖评测导入、去重、人工确认、摘要冻结、复验和篡改检测。") 还覆盖引文可定位但结论相反、空答案、同义改写、限定遗漏、时间错配、否定翻转和数值变化等规则样例。[分维度质量规则测试 ↗](../../../apps/server/tests/quality-evaluation.test.ts#L201 "支持引文定位与语义支持分离，并覆盖反向结论、空答案、同义改写、限定、时间、否定和数值样例。") 所给测试没有直接执行 Lark 回调服务或逐样本 runner，因此先前“自动化测试已完整覆盖质量闭环”的结论被替代。

确定性规则的少量中文样例不能代表跨句限定、双重否定、单位换算或多时间区间的泛化质量；研究导入也会跳过图片、表格和白板。完整检查、浏览器 fixture、单次 ACP 冒烟、飞书摘要快照和质量门禁必须分别陈述，不能相互替代或合并包装为生产验收。
