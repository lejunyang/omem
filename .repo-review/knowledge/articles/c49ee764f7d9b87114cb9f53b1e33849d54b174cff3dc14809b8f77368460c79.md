# 验证体系、质量评测与证据强度

以分层证据解释类型检查、全量测试、构建、真实浏览器、协议夹具和实时外部检查各自能证明什么，并说明隔离质量数据集、人工标注、冻结与确定性指标组成的评测闭环及其当前限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence-layers"></a>
## 验证证据应分层解读

类型检查证明静态合同可成立，Vitest 证明已编码断言在测试环境通过，构建证明服务端与 Web 产物可生成。现有记录并未为三者分别登记退出码，而是记录包含 TypeScript/Vue 类型检查、全量 Vitest 和服务端/Web 构建的完整检查命令退出码为 0；这仍不等于真实浏览器、模型或外部连接器已经可用。记录也明确限定其不是所有外部集成的验收。[知识功能实现验证记录 ↗](../../../docs/implementation/knowledge-verification.json#L5 "支持完整检查命令退出码为 0、检查包含类型检查、全量 Vitest 和构建，并限定记录不覆盖所有外部集成。")

真实浏览器检查进一步覆盖 Vue、API、SQLite、层栈导航、响应式布局与故障展示，但 Agent 使用确定性 ACP 协议夹具；因此它能证明夹具路径上的产品接线和交互回归，不能证明真实模型执行。[浏览器验证环境 ↗](../../../docs/implementation/browser-verification.json#L4 "支持浏览器检查使用真实 Fastify 与 SQLite，同时明确 Agent 是确定性 ACP 协议夹具。") 开发与浏览器验收子知识进一步解释了真实装配、直接驱动的测试步骤及其证明边界。[开发与浏览器验收流程 ↗](97762e76cba3d5e9bc19883e9db79e5f8ed0afd3e77c4114d9fc9ae68437691e.md#development_and_acceptance "提供相邻子知识入口，解释真实浏览器装配、确定性驱动方式及 fixture 对证据范围的限制。")

<a id="quality-loop"></a>
## 隔离数据集与确定性质量闭环

质量评测不直接生产知识：研究文档必须通过显式评测入口生成候选，再由人工确认；只有样本数达到目标且全部确认的数据集才能冻结，并可依据摘要复验、防止标签被静默篡改。[质量数据集生命周期测试 ↗](../../../apps/server/tests/quality-evaluation.test.ts#L50 "支持评测专用入口、重复导入、人工确认前拒绝冻结、冻结摘要复验与篡改检测。") 质量模块子知识串联了候选生成、Lark 标注、冻结和评分的完整生命周期及其限制。[质量模块的评测流程 ↗](9f9a271cae333333972dbf1ee63356a0627defffcf9b624072cdb0dec804fe38.md#evaluation-progress-limits "提供相邻子知识入口，串联隔离候选、人工标注、数据集冻结、指标计算和已知限制。")

评分把“引文能在原文找到”与“结论受引文支持”分开，并另算数字事实槽、必要证据覆盖、任务完成、自动应用精度、打扰和延迟。反向结论即使引用可定位也不会获得语义支持，空答案则形成覆盖缺失而非免费满分。[分维度质量指标测试 ↗](../../../apps/server/tests/quality-evaluation.test.ts#L201 "支持引用定位与语义支持分离，并覆盖反向结论、空答案、限定条件、时间和数字事实槽等确定性行为。") 门禁脚本先复验冻结数据，再对语义支持、引用定位、证据覆盖等阈值逐项判断；任一门禁失败都会设置非零退出状态，使结果可进入持续回归，而不只是保存报告。[质量评估门禁 ↗](../../../scripts/quality-evaluate.ts#L14 "支持冻结数据复验、各项质量阈值以及任一门禁失败时设置非零退出码。")

<a id="live-scope"></a>
## 实时检查、进展与限制

实时 ACP 的模型选择会先读取 ACP 暴露的可选模型；若显式请求的模型不在候选中则报错，而不是静默降级。该选择函数只是把环境中的 effort 写入 profile，所示范围没有验证推理强度是否受支持。[实时 ACP 模型选择 ↗](../../../scripts/live-model.ts#L4 "支持从 ACP 配置选项探测可用模型、拒绝不可用的显式模型，并显示 effort 在此处仅被写入 profile。") 随后的基础冒烟以回答包含“12”为硬断言，有效模型、推理强度和事件类型主要进入诊断输出。[实时 ACP 冒烟判定 ↗](../../../scripts/live-acp-smoke.ts#L5 "支持基础实机冒烟以答案包含 12 为硬断言，而有效配置和事件类型主要进入诊断输出。") 已保存的 ACP 快照也只记录 Agent、模型、effort、回答和事件类型，缺少固定输入关联、执行时间与退出码，因而只是窄范围实机证据。[ACP 实机结果快照 ↗](../../../docs/implementation/live-acp-verification.json#L1 "支持快照字段仅包含 Agent、模型、effort、回答与事件类型，从而限定其证据强度。")

Lark 实机快照确认 `lark-cli` 返回指定文档版本、text/link 两类内容和字符规模，但没有绑定固定 Source/Revision、退出码或关键内容断言，不能推广为 WebSocket、图片下载、幂等导入和引用定位均已验收。[飞书文档导入实机快照 ↗](../../../docs/implementation/live-lark-verification.json#L1 "支持快照记录连接器、文档版本、part 类型和字符规模，同时显示未记录运行状态与固定版本映射。") 当前可确认的是：包含类型检查、全量测试和构建的完整检查、真实浏览器夹具路径以及确定性质量闭环已有证据；真实外部系统仍需按授权主体、固定输入、时间、退出状态和行为断言分别验收，配置、测试夹具、历史快照或单次冒烟都不能替代完整生产验收。
