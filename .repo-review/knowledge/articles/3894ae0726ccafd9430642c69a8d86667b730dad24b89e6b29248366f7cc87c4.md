# 边目标解析与下钻行为测试

验证 Code Wiki 如何把导入、调用和模块理解记录转换为可导航目标，并覆盖同文件符号、跨文件目标、外部依赖及陈旧理解等关键边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 测试解决的问题

该测试为代码关系的“能否点击、点击后打开什么”建立行为合同。`resolveEdgeTarget` 需要把仓库内导入解析到文件，把调用解析到符号所在文件、行号和名称；外部包、缺失目标以及指向当前文件的普通文件边必须不可交互。[边解析断言 ↗](../../../apps/web/src/codewiki/edges.test.ts#L12 "支持导入、调用、缺失目标和同文件目标的可解析性合同。") 这防止关系图把无目标的边伪装成有效链接，也避免文件视图对自身做无意义跳转。实现中该函数优先检查目标文件，其次检查目标符号，并以目标文件是否存在及是否不同于当前文件决定 `resolvable`。[边目标解析实现 ↗](../../../apps/web/src/codewiki/modules.ts#L124 "解释目标文件与目标符号的解析顺序及不可导航条件。")

<a id="drill"></a>
## 同文件与跨文件下钻

更细的 `edgeDrillTarget` 合同区别于一般可解析性：同文件的**符号边**仍应打开符号/范围帧，跨文件符号边则打开文件帧，真正的外部或未解析目标才返回 `none`。测试分别断言同文件符号保留符号标识和第 715 行、跨文件符号进入目标文件、外部包不产生下钻。[下钻目标断言 ↗](../../../apps/web/src/codewiki/edges.test.ts#L45 "支持同文件符号、跨文件符号与外部目标的不同下钻结果。") 这与实现的分支一致：符号目标优先，同文件返回 `symbol`，异文件返回带行号的 `file`；纯文件目标若仍是自身则拒绝。[边下钻实现 ↗](../../../apps/web/src/codewiki/modules.ts#L184 "解释符号帧、文件帧及 none 三种返回路径。")

<a id="understanding"></a>
## 模块理解匹配及覆盖边界

测试还确认模块说明按目录前缀匹配，并在多个候选中选择最长、最具体的目录；陈旧记录不会被采用。[模块理解匹配断言 ↗](../../../apps/web/src/codewiki/edges.test.ts#L77 "支持最长目录前缀优先以及忽略陈旧行的结论。") 实现实际允许 `curated-seed` 与 `model-generated` 两类来源，并接收 seed、generated、verified 状态，再以模块内任意文件是否被前缀覆盖来挑选最长目标。[模块理解选择实现 ↗](../../../apps/web/src/codewiki/modules.ts#L149 "说明候选来源、状态过滤、任意文件覆盖和最长前缀规则。") 当前测试没有覆盖模型生成记录、被拒绝状态、同长度候选的时间与 seed 排序，也未验证缺少符号对应文件时的下钻结果。
