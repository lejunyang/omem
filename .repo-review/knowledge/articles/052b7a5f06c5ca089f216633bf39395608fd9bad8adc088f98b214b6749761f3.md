# 固定快照上的 Agent 自主研究环境

该模块为一次知识生成任务搭建隔离、可审计、可校验的本地研究环境：导出固定原件与目录，复制只读检索快照，通过临时 MCP 服务提供材料、知识、记忆和代码导航工具，并只接受符合任务输出合同的最终提交。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 把自主调查限制在一次固定快照中

`prepareAgentResearch` 接收知识仓储、获准材料、已有文章、任务工作区、输出 schema 与校验函数，返回一个供 Agent 运行时使用的 `NativeResearchEnvironment`。它解决的不是“替 Agent 写文章”，而是让 Agent 能主动查资料，同时把可见范围、最终输出和生命周期控制在一次任务内。参考 [研究环境输入合同 ↗](../../../apps/server/src/knowledge/agent-research.ts#L50 "支持函数接收仓储、材料、文章、工作区、输出 schema 与校验器，并返回运行时研究环境。")

初始化时，材料正文按相对目录导出到 `originals/`；绝对路径、越界路径或文件名冲突会改用材料摘要分目录，图片也只从仓储资产导出。随后生成 `catalog.json`、`knowledge.json`，同步检索投影并用 `VACUUM INTO` 制作只读 SQLite 快照。这样原生文件阅读与内部检索面对的是同一批固定版本，而不是持续变化的主库。参考 [固定原件导出 ↗](../../../apps/server/src/knowledge/agent-research.ts#L90 "支持路径约束、冲突处理、材料与图片导出，以及目录文件的生成。")、[只读检索快照 ↗](../../../apps/server/src/knowledge/agent-research.ts#L163 "支持先同步检索投影、复制 SQLite、只读打开并装配语义检索器。")

<a id="representative-flow"></a>
## 一条代表性调用如何完成研究与交付

以代码分析任务为例：调用方传入目标材料和 `KnowledgeBatch.v1` 校验器后，函数先导出原件与只读快照，再启动仅监听 `127.0.0.1`、带随机路由的无会话 MCP HTTP 服务；返回值把服务地址、工具清单和任务说明交给运行时。参考 [本地 MCP 服务出口 ↗](../../../apps/server/src/knowledge/agent-research.ts#L725 "支持随机路由、本机监听、无会话传输，以及返回服务地址、工具清单和环境控制接口。")

```mermaid
flowchart LR
  A[材料、文章、输出合同] --> B[导出目录与只读快照]
  B --> C[Agent 按需读取和检索]
  C --> D[submit_result 校验]
  D --> E[result 返回已规范化结果]
```

研究过程中，`read_material` 会校验行范围、记录已读材料，并返回带真实行号、结构提纲和来源信息的文本；`search_materials` 首次使用时才建索引，索引失败会记录为仅词法模式，同时仍以材料 key、类型和 fragment 可见性过滤结果。参考 [按行读取固定材料 ↗](../../../apps/server/src/knowledge/agent-research.ts#L206 "支持材料范围校验、已读记录，以及真实行号、提纲、图片和来源信息的返回。")、[受限混合检索 ↗](../../../apps/server/src/knowledge/agent-research.ts#L350 "支持懒初始化索引、词法降级记录、可见性过滤和带上下文命中的输出。")

最后 Agent 调用 `submit_result`。服务用调用方传入的校验函数处理完整对象；成功后保存内存结果与 `result.json`，失败则在同一轮返回可修正的错误。因此环境的主要输出不是搜索命中，而是经合同校验、可由 `result()` 取回的候选知识结果。参考 [结果提交与校验 ↗](../../../apps/server/src/knowledge/agent-research.ts#L687 "支持 submit_result 使用任务 schema 和校验函数、保存候选结果，并在失败时返回可修复错误。")

<a id="tools-and-boundaries"></a>
## 工具分工、模块关系与边界

工具层分为三类：原件读取与混合检索；既有知识、活动记忆和历史版本的背景读取；代码 AST 定义、导入、候选调用及显式材料关系导航。知识搜索可能补入快照中的旧文章，但会标为 `needs-review`；AST 调用明确标作 `candidate`，不能据此声称得到完整跨文件调用图。参考 [知识与记忆背景读取 ↗](../../../apps/server/src/knowledge/agent-research.ts#L420 "支持搜索和读取派生知识、标识复核状态，以及只读取活动记忆及其证据集。")、[代码与关系导航 ↗](../../../apps/server/src/knowledge/agent-research.ts#L539 "支持 AST 定义、导入、候选调用和显式关系查询的职责及其候选边界。")

实现直接依赖 `KnowledgeRepository` 读取资产，借 `RetrievalProjection` 与 `UnifiedRetrieval` 建立只读检索面，并用 `parseFile` 提取代码结构；环境返回的 `update` 把原生读取和工具调用写入审计，`allowPermission` 只放行本地快照内的读/搜操作及本环境注册的 omem 工具。参考 [审计与权限边界 ↗](../../../apps/server/src/knowledge/agent-research.ts#L783 "支持原生读取追踪、提交参数脱敏式审计，以及仅放行任务工作区内读取和已注册 omem 工具。")

关闭是幂等的：先停止 HTTP、语义检索和数据库句柄，再删除可重建的 `originals`、图片与 SQLite 副本；目录、提交结果和审计记录保留，仓储中的不可变原件不受影响。若初始化任一步失败，也会走相同清理路径。参考 [幂等资源清理 ↗](../../../apps/server/src/knowledge/agent-research.ts#L60 "支持关闭服务、检索器和数据库后删除可重建副本，并在初始化异常时复用清理流程。")
