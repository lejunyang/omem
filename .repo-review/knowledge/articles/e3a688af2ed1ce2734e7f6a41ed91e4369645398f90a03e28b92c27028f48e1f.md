# 先认识 omem：把材料变成能找回的工作记忆

omem 把文档、代码、聊天、图片和个人经历放进同一个工作记忆中。本页用“保存项目评审约定、找回批准规则、跟进评审回复”的例子，说明原始材料、知识文章、个人记忆与事项各自解决什么问题，以及目前可以依赖的能力边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="scenario"></a>
## 从一份项目约定开始

假设你收到一份项目约定，其中写着：“评审必须由模块负责人批准，回复期限为周五。”几周后，你需要确认由谁批准；提交评审后，又要等张三回复并在次日上午检查。

omem 要解决的正是这类跨越时间的日常问题：把文档、代码、聊天、图片和个人经历组织到一起，让你以后不仅能找到原话，还能读懂背景并继续行动。它已经具备输入、检索、记忆、问答和事项的基础，但高质量知识整理与更主动的助理能力仍在推进。参考 [产品目标与当前基础 ↗](../../../README.md#L3 "支持 omem 将多种个人材料组织为可读懂、可找回、可行动的记忆，并说明完整主动能力仍在推进。")

<a id="getting-started"></a>
## 启动并保存第一份材料

本地使用时，先运行：

```bash
osdk install
osdk deps --frozen
osdk run dev
```

随后打开终端显示的 Web 地址。开发模式会载入本仓库材料和已经发布的知识，同时保留个人数据；启动本身不会自动生成整库知识。参考 [本地启动方式 ↗](../../../README.md#L7 "支持启动命令、打开 Web 地址、保留个人数据以及启动不自动生成整库知识的说明。")

进入“输入材料”，选择“文本＋图片＋链接”，填写标题“项目评审约定”，粘贴约定正文并保存。这里也可以改用飞书文档、Git 文件或服务器文本文件作为输入。参考 [材料输入入口 ↗](../../../apps/web/src/App.vue#L613 "支持文本、图片、链接、飞书文档、Git 文件和服务器文件等用户可见输入方式。")

若希望以后用同一个来源持续更新，可以填写稳定的“来源标识”；相同标识的新内容会形成后续版本。保存完成后，界面会打开原始材料：内容没变时复用原版本，内容变化时形成新的固定版本。参考 [来源标识与材料正文 ↗](../../../apps/web/src/App.vue#L650 "支持相同来源标识产生新版本，以及用户粘贴材料正文的操作说明。") [保存后的用户反馈 ↗](../../../apps/web/src/App.vue#L327 "支持保存后打开原始材料，以及内容未变化时复用原版本的可观察结果。")

```mermaid
flowchart LR
  A[保存项目评审约定] --> B[形成可回看的原始材料]
  B --> C[搜索或阅读知识]
  C --> D[找到批准规则]
  D --> E[记录等待评审回复的事项]
```

这条主线把“保存、找回、行动”连在一起；材料的当前版本和历史版本都能从阅读页打开。参考 [原始材料与版本历史 ↗](../../../apps/web/src/App.vue#L565 "支持当前或历史版本的标识、文档和代码阅读方式，以及打开版本历史的说明。")

<a id="four-concepts"></a>
## 材料、知识、记忆和事项有什么区别

同一份项目约定可以同时参与四种用途，但四者不能互相替代：

| 对象 | 回答的问题 | 本例中的样子 |
| --- | --- | --- |
| **原始材料** | 当时到底写了什么？ | 保存下来的“项目评审约定”及其历史版本 |
| **知识文章** | 这些材料合起来该怎样理解？ | 跨约定、讨论和代码整理出的“如何完成项目评审” |
| **个人记忆** | 哪些事实或经验以后仍会用到？ | “评审需要模块负责人批准”这一可复用背景 |
| **事项** | 下一步做什么，何时再检查？ | “等待张三的评审回复，明早检查” |

原始材料保留历史和原话；知识文章围绕读者问题跨材料解释，但不会变成一份取代原文的新事实。参考 [一个来源体系与多种用途 ↗](../../../docs/reader-first/architecture.md#L5 "支持代码和普通材料共用来源体系，以及原件、检索结构和讲解页面承担不同用途。") 知识库会把入门指南放在“从这里开始”，也能按主题、功能或材料名称查找章节；文章正文中的引用可以继续打开对应来源。参考 [知识库阅读入口 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L48 "支持知识库从入门指南开始，并可按主题、功能或材料名称查找文章。") [知识正文与引用 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L31 "支持文章展示阅读目标和分节正文，并从正文引用继续导航到对应来源。")

个人记忆来自材料中提炼出的事实、经历、流程或经验。保存或更新原文后，相关处理任务可能先进入队列；只有启用自动处理并配置可用的 Agent，后台才会实际提炼和核验。明确可靠的结果可以写入记忆，需要用户判断的内容会进入“待判断”。自动处理未启用时，原文保存与检索仍然可用，因此“材料已保存”不等于“记忆已经形成”。参考 [材料处理与记忆形成 ↗](../../../apps/web/src/LearningView.vue#L81 "支持材料任务排队、自动处理的启用条件、可靠结果写入记忆及待判断入口，并说明未启用时原文仍可保存和检索。")

事项则是需要推进的行动对象，可以记录背景、截止时间并关联当前选中的原文。它不是对约定的解释，也不是一条静态事实。参考 [事项创建与状态 ↗](../../../apps/web/src/App.vue#L726 "支持手动记录事项、背景和到期时间，关联当前材料，并查看事项状态及来源。")

<a id="finding"></a>
## 找回决定，并围绕原文继续提问

几周后想确认“评审由谁批准”，可以直接在顶部搜索“评审谁批准”或约定中的关键词。搜索会结合原文、代码名称、已有知识以及已启用的中文语义索引；结果显示相关章节或行范围，并提供“查看固定片段”。参考 [统一搜索结果 ↗](../../../apps/web/src/App.vue#L530 "支持搜索结合原文、代码名称、已有知识和中文语义索引，并能打开固定片段。")

也可以进入“原始材料”，按名称筛选“项目评审约定”，打开当前版本或历史版本。找到相关段落后，选择“就这段提问”，例如询问：“这条规则对本次评审意味着什么？”参考 [选择原文继续提问 ↗](../../../apps/web/src/App.vue#L580 "支持从原始材料中选定具体段落提问，并打开该段原文。")

从原始材料进入的这次问答，会以当前选中的片段作为固定依据。回答完成后可以重新打开本次提供的依据；不过系统目前不会自动核验回答中的每一个主张，因此重要决定仍应回到原文确认。参考 [当前片段问答请求 ↗](../../../apps/web/src/ChatPane.vue#L49 "支持问答必须具有当前选中的片段，并将该片段作为请求焦点；引用路径仅在另有路径数据时才可加入。") [问答依据与核验边界 ↗](../../../apps/web/src/ChatPane.vue#L115 "支持查看本次问答提供的片段依据，并说明系统尚未自动核验回答中的每个主张。")

<a id="code"></a>
## 代码与其他材料共用一条阅读路线

代码没有被放进另一套知识产品。它与文档、聊天、图片使用同一个材料体系、知识库和搜索入口，只是额外利用结构和符号信息帮助精确定位。参考 [产品目标与当前基础 ↗](../../../README.md#L3 "支持 omem 将多种个人材料组织为可读懂、可找回、可行动的记忆，并说明完整主动能力仍在推进。") [一个来源体系与多种用途 ↗](../../../docs/reader-first/architecture.md#L5 "支持代码和普通材料共用来源体系，以及原件、检索结构和讲解页面承担不同用途。")

例如，项目约定说明“评审必须由模块负责人批准”，知识文章可以把这条规则与讨论记录、相关实现一起讲清楚；沿文章引用打开代码时，页面会显示对应行，并允许向上或向下展开上下文。参考 [代码原文阅读 ↗](../../../apps/web/src/knowledge/KnowledgeSource.vue#L37 "支持代码引用按行展示、展开上下文并沿关联继续阅读的体验。")

当前可以依赖的是代码与其他材料的共同保存、搜索、定位、阅读和引用。完整的意图路由与跨文件功能链仍在扩展，因此不能把一次代码命中理解成系统已经稳定还原了完整调用图。参考 [检索与跨文件能力边界 ↗](../../../README.md#L31 "支持原文、检索片段和讲解章节用途不同，以及完整意图路由和跨文件功能链仍待扩展。")

<a id="follow-up"></a>
## 把评审回复变成可跟进的事项

提交评审后，可以在“日常助理”输入：“帮我跟进张三的评审回复，明天上午 9 点提醒我检查。”会话会保留这条消息，展示处理状态和结果；若处理失败，原消息仍会保存并可重试，所用材料也能从结果旁打开。参考 [日常助理会话 ↗](../../../apps/web/src/DailyAssistant.vue#L48 "支持评审跟进示例、持久消息、处理状态、失败重试和打开所用材料。")

也可以进入“事项与待办”手动填写事项、背景和到期时间。若此前选中了约定原文，新事项可以关联该来源，之后仍能从事项回看依据。事项支持待推进、等待回复、已完成和已取消等状态。参考 [事项创建与状态 ↗](../../../apps/web/src/App.vue#L726 "支持手动记录事项、背景和到期时间，关联当前材料，并查看事项状态及来源。")

“跟进设置”可以登记等待对象、下次检查时间、暂缓提醒或取消事项。**跟进时间与截止时间是两回事**：前者表示何时再看一次，后者表示事情最迟何时完成；不填写检查时间时，也可以只记录正在等待谁。参考 [等待与跟进设置 ↗](../../../apps/web/src/TaskFollowUpControls.vue#L24 "支持登记等待对象、设置检查时间、暂缓提醒和取消事项，并说明跟进时间不改变截止时间及不会自动联系对方。")

这里的“等待张三回复”不会自动联系张三，也不会自动判断回复是否已经到达。通知标为已读只会清除未读状态，不会批准变更、完成事项或取消后续提醒。参考 [运行与主动跟进边界 ↗](../../../docs/reader-first/operations.md#L23 "支持 SQLite 单用户服务、外部集成需明确范围、现有事项操作，以及尚未自动监听回复等能力边界。") [通知已读的实际含义 ↗](../../../apps/web/src/App.vue#L768 "支持标为已读只清除未读提醒，不会批准变更、完成待办或取消后续提醒。")

<a id="limits"></a>
## 现在可以依赖什么，哪些仍在路上

目前已有一条可用的基础链路：统一输入与固定版本、全文和中文检索、代码符号定位、知识阅读及递归引用、基于原文的问答、来源变化后的记忆重核验、持久事项和站内提醒。统一搜索、问题驱动的 Wiki 与阅读界面已经完成首个可用切片，但覆盖范围和实际阅读质量仍在继续扩展。参考 [当前实施进度 ↗](../../../docs/reader-first/progress.md#L5 "支持统一搜索、问题驱动 Wiki 和阅读界面的首片状态，列出可复用基础，并明确当前单用户实现不具备团队隔离。")

尚未完成的主动能力包括持续维护人物、项目和主题的综合理解、自动监听他人回复、周期回顾、日历和学习卡。因此，omem 现在更像一个能保存来路、协助找回并管理行动的个人工作记忆，而不是会自行观察所有外部变化的全自动助理。参考 [运行与主动跟进边界 ↗](../../../docs/reader-first/operations.md#L23 "支持 SQLite 单用户服务、外部集成需明确范围、现有事项操作，以及尚未自动监听回复等能力边界。") [记忆与主动事项路线 ↗](../../../docs/reader-first/architecture.md#L25 "支持从原始记录到记忆再到行动的目标关系，并区分已有重核验和仍属后续的主动能力。")

当前服务使用 SQLite，面向单用户，不具备团队隔离。飞书、外部通知、全局 hooks 和屏幕监听都需要单独、明确地启用或界定范围；系统不会默认采集这些外部信息。参考 [运行与主动跟进边界 ↗](../../../docs/reader-first/operations.md#L23 "支持 SQLite 单用户服务、外部集成需明确范围、现有事项操作，以及尚未自动监听回复等能力边界。") [当前实施进度 ↗](../../../docs/reader-first/progress.md#L5 "支持统一搜索、问题驱动 Wiki 和阅读界面的首片状态，列出可复用基础，并明确当前单用户实现不具备团队隔离。") [单用户与显式集成 ↗](../../../README.md#L55 "支持当前为单用户服务，并说明飞书、外部通知和屏幕监听是独立的显式集成。")
