# 先认识 omem：把材料变成能找回的工作记忆

以“评审前必须更新接口说明”为贯穿示例，说明如何保存项目约定、整理知识、形成可找回的个人记忆，并把等待评审回复登记为持续跟进的事项；同时区分原始材料、知识文章、个人记忆和事项，介绍代码材料的使用方式与当前能力边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 从一份容易遗忘的项目约定开始

假设团队约定：“评审前必须更新接口说明。”几周后，你既要确认当时的原话和理由，又要查看相关实现，还要记得等待评审人的回复。普通收藏可以留下文件，却很难把理解、找回和后续行动连起来。

omem 把文档、代码、聊天、图片和个人经历放进同一个个人工作记忆，使这些材料可以被阅读、追溯、搜索和用于行动。代码会获得额外的结构定位能力，但不会被隔离成另一套知识产品。参考 [统一工作记忆目标 ↗](../../../README.md#L1 "支持 omem 将多种个人材料统一用于读懂、找回和行动，并说明代码只增加结构定位能力。")

```mermaid
flowchart LR
  A[保存项目约定] --> B[保留原始材料]
  B --> C[整理知识与个人记忆]
  C --> D[搜索或询问助理]
  D --> E[登记评审跟进事项]
```

系统已有输入、检索、记忆、问答和事项基础；高质量知识整理与主动助理仍在继续完善。参考 [当前产品阶段 ↗](../../../README.md#L5 "支持输入、检索、记忆、问答和事项已有基础，而知识整理与主动助理仍在推进。")

<a id="start"></a>
## 启动后先保存项目约定

首次使用时，依次运行 `osdk install`、`osdk deps --frozen` 和 `osdk run dev`，再打开终端打印的网址。参考 [首次启动步骤 ↗](../../../README.md#L7 "支持首次启动命令以及打开终端输出网址的操作。")

统一界面通常进入知识库，导航中还提供日常助理、原始材料、输入材料、材料处理、待判断、事项与待办、通知中心等入口。参考 [统一界面入口 ↗](../../../apps/web/src/App.vue#L39 "支持默认知识库视图及日常助理、材料、待判断和事项等导航入口。")

在示例中，打开“输入材料”，选择“文本＋图片＋链接”，填写标题“评审前接口说明约定”，粘贴约定正文，再点击“保存材料与证据”。材料也可从飞书文档、Git 文件或服务器文本文件导入；Git 入口读取指定版本的文件。参考 [材料输入表单 ↗](../../../apps/web/src/App.vue#L623 "支持文本、图片、链接、飞书文档、Git 文件和服务器文本文件等输入方式及保存操作。")

对于手工输入，如果以后要把修改后的约定保存为**同一来源的新版本**，应再次填写同一个“来源标识”。界面明确说明相同标识会产生新版本；若把标识留空，每次提交都会自动分配新的标识，因此再次粘贴相同标题或相近内容也可能成为另一份来源。参考 [同一来源的版本标识 ↗](../../../apps/web/src/App.vue#L653 "支持手工输入需要沿用相同来源标识才能把后续内容归入同一来源的新版本。") [留空时自动分配标识 ↗](../../../apps/web/src/App.vue#L311 "支持手工输入未填写来源标识时会为本次提交自动生成新标识，不能仅凭标题或相似内容续接来源。")

在来源身份相同的前提下，内容未改变时系统会复用已有修订；内容改变时则保存该来源的新修订并生成固定证据片段。保存后可以在原始材料中查看当前版本和版本历史，从而核对某次评审实际采用的原文。参考 [同一来源下的修订反馈 ↗](../../../apps/web/src/App.vue#L335 "支持保存后打开对应修订，并根据同一来源下内容是否重复提示复用原修订或生成固定证据片段。")

<a id="concepts"></a>
## 四类内容分别解决什么问题

同一份约定可以参与多种用途，但四类内容不能混为一谈：

| 类型 | 回答的问题 | 示例 |
| --- | --- | --- |
| **原始材料** | 当时原话是什么？ | 保存下来的约定、讨论或代码版本 |
| **知识文章** | 这件事应该怎样理解？ | 把约定、代码和讨论整理成说明 |
| **个人记忆** | 以后遇到类似情况应想起什么？ | 可被检索和助理找回的稳定决定或经验 |
| **事项** | 接下来要做什么？ | 等待评审回复，并在明天再次检查 |

原始材料负责保留版本，检索片段负责找到相关上下文，知识文章则按读者问题重新组织讲解。文章中的结论仍应能回到原文，而不是把派生讲解当成另一份独立事实。参考 [保存检索讲解分工 ↗](../../../AGENTS.md#L7 "支持原件、检索片段和讲解章节用途不同，并要求派生知识仍可追溯原文。")

个人记忆可以从材料处理产生：系统对新材料提炼事实、经历、流程和待办，再进行核验。明确可靠的结果可写入记忆；需要判断的内容进入“待判断”。即使自动处理没有启用，原文保存和检索仍然可用。参考 [材料提炼记忆流程 ↗](../../../apps/web/src/LearningView.vue#L81 "支持材料处理提炼并核验候选记忆、可靠结果写入记忆及未启用处理时仍可保存和检索原文。")

在“待判断”中，用户可以补充背景、拒绝候选，或确认并应用。来源已经变化的旧判断不能继续提交。参考 [待判断操作 ↗](../../../apps/web/src/DecisionsView.vue#L120 "支持用户为不确定候选补充背景、拒绝或确认应用，并说明来源变化后的旧判断失效。")

<a id="organize"></a>
## 把约定整理成可读的知识

如果不只想核对一句原话，还想弄清“为什么评审前必须更新接口说明，以及哪些实现会受影响”，可以在知识库进入“全部分类”，展开“从材料整理文章”。勾选项目约定、相关代码和讨论，填写文章主题、想弄懂的问题及阅读对象，然后开始整理。参考 [从材料整理文章 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L19 "支持选择原始材料并填写主题、问题和阅读对象后启动文章整理。")

系统会调查所选材料、撰写并独立复核，完成后把文章放入主题目录。若固定材料在生成期间变化，旧结果不会直接发布；生成失败也不会覆盖已有正文。参考 [文章生成与保护 ↗](../../../docs/reader-first/operations.md#L27 "支持调查、写作、复核流程，以及材料变化阻止旧结果发布、失败不覆盖旧正文。")

代码和普通材料共用这条流程。代码额外利用 TypeScript、Vue 等结构和符号定位来寻找实现，但结构关系本身不能替代对功能、业务背景和设计原因的理解。参考 [代码结构定位边界 ↗](../../../docs/reader-first/review.md#L13 "支持代码具有专用结构定位能力，但结构关系不能代替功能、业务和设计理解。")

<a id="retrieve"></a>
## 后来怎样找回这个决定

几周后准备送审时，可以在顶部搜索“评审前 接口说明”。搜索会结合原文、代码名称、已有知识以及已经启用的中文语义索引，结果展示命中文字和章节范围，并允许打开固定片段核对原话。参考 [顶部搜索结果 ↗](../../../apps/web/src/App.vue#L538 "支持顶部搜索结合原文、代码名称、已有知识和中文语义索引，并可打开固定片段。")

如果想阅读完整解释，可以进入知识库搜索全部知识，或先进入某个主题分类再搜索；结果以文章为单位呈现。参考 [知识库分类搜索 ↗](../../../apps/web/src/knowledge/KnowledgeHome.vue#L53 "支持在全部知识或当前分类中搜索，并以文章为单位浏览结果。")

若问题更接近日常工作，例如“这次评审前我需要记得什么？”，可以询问日常助理。助理用于查找记忆和回顾事项，回答旁会列出本次采用的材料依据，点击即可回到原文。参考 [助理查找记忆与依据 ↗](../../../apps/web/src/DailyAssistant.vue#L48 "支持日常助理用于查找记忆、回顾事项，并在回答旁打开所选依据。")

三个入口各有侧重：顶部搜索适合快速核对原文，知识库适合系统理解，日常助理适合结合当前任务提问。它们共享召回基础，但完整意图路由和跨文件功能链扩展仍未完成。参考 [共享召回与检索限制 ↗](../../../README.md#L31 "支持顶部搜索、知识检索和助手共享召回基础，同时说明完整意图路由与跨文件链路仍待实现。")

<a id="followup"></a>
## 把等待评审回复变成事项

发起评审后，不要只把“等回复”写进知识文章，因为它是需要继续推进的工作。你可以直接对日常助理说：“帮我跟进张三的评审回复，明天上午 9 点提醒我检查。”参考 [助理自然语言交办 ↗](../../../apps/web/src/DailyAssistant.vue#L49 "支持用户通过日常助理自然语言登记评审跟进，并提供相应的界面示例。")

也可以进入“事项与待办”，填写事项名称、补充背景和到期时间。在事项的“跟进设置”中，再填写等待对象“张三的评审回复”和下次跟进时间。参考 [事项页录入 ↗](../../../apps/web/src/App.vue#L736 "支持在事项页填写事项名称、补充背景和到期时间。")

跟进时间与最终截止时间分开；系统会记录等待并安排站内提醒，但不会自动联系对方。收到回复后可标为完成，决定不再推进时可取消；完成或取消后停止提醒。参考 [等待与跟进设置 ↗](../../../apps/web/src/TaskFollowUpControls.vue#L24 "支持登记等待对象和下次跟进时间，并说明跟进不改变截止时间且不会自动联系对方。")

通知中心的“标为已读”只表示看过提醒，不等于事项已经完成，也不会自动取消后续跟进。参考 [提醒不等于完成 ↗](../../../apps/web/src/App.vue#L778 "支持通知已读不会完成待办或取消后续提醒。")

<a id="limits"></a>
## 现在可用的范围与尚未实现的能力

目前可使用的主链包括：输入并保留固定版本、全文和中文短词检索、代码符号定位、记忆与知识召回、基于材料问答、来源变化后的记忆重核验，以及持久事项和站内提醒。统一搜索和问题驱动的知识整理已有首个可用版本。参考 [当前已实现基础 ↗](../../../docs/reader-first/progress.md#L5 "支持统一捕获、固定修订、结构定位、混合检索、记忆重核验和持久事项等现有能力。")

日常助理会恢复并持续刷新同一日常会话，便于接着查看已有消息。参考 [日常会话恢复 ↗](../../../apps/web/src/DailyAssistant.vue#L38 "支持日常助理创建或恢复固定日常会话、加载既有消息并持续刷新。") 问答页面可以保存回答并回看本次提供的依据，但系统尚未自动核验回答中每一项主张的支持程度。参考 [问答核验边界 ↗](../../../apps/web/src/ChatPane.vue#L95 "支持回答可以保存、依据可以回查，同时说明回答中的主张尚未逐项自动核验。")

当前仍没有完整意图路由和跨文件功能链扩展，也没有持续维护项目、人物和主题的整体理解。系统不会自动监听评审人是否回复，周期回顾、日历和学习卡也尚未实现。参考 [主动能力边界 ↗](../../../docs/reader-first/operations.md#L23 "支持尚无自动监听回复、周期回顾、日历和学习卡等主动能力。")

因此，现阶段较稳妥的用法是：让 omem 保存来源、帮助整理和找回背景，再把明确的下一步登记成事项；重要决定通过引用回看原文，外部沟通结果则由你确认后完成或更新事项。
