# 检索证据的相关性与多样化排序

解释 rankEvidence 如何在融合候选进入阅读或回答前，保留高相关证据、合并重复候选摘录、提升代码符号，并限制冗余或同源结果占满返回列表。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 排序层解决什么问题

`rankEvidence` 接收已经带有融合相关性分数的候选证据、查询参数和可选的归一化向量，返回适合阅读或回答的候选列表。它只调整顺序、分数与返回数量，不改变候选原有的身份、可见性和来源信息；返回上限默认是 20，并被限制在 1–100。参考 [排序职责与数量上限 ↗](../../../apps/server/src/retrieval/ranking.ts#L3 "支持该函数基于融合相关性和可选向量调整候选排序、保留身份与来源信息，以及默认和最大返回数量。")

它的目标是在高相关性之外保留内容差异，避免重复摘录或同一来源修订占满结果，同时让精确的代码符号命中更容易靠前。

<a id="flow"></a>
## 一组候选如何完成排序

例如，上游传入三条候选：两条 `snippet` 只有空白差异，另一条分数稍低但内容互补。开启多样化时，函数先压缩 `snippet` 中的连续空白并去除首尾空白，以规范化后的候选摘录为键，只保留同键中原始分数最高的一条；随后把带 `code-symbol` 路由的候选分数乘以 1.5，并按分数、ID 排序。参考 [摘录去重与符号加权 ↗](../../../apps/server/src/retrieval/ranking.ts#L10 "支持以规范化后的 snippet 为键保留最高分候选，并对 code-symbol 路由加权后排序。")

```mermaid
flowchart LR
  A[融合候选] --> B[候选摘录去重]
  B --> C[代码符号加权]
  C --> D[相关性减冗余]
  D --> E[限制同源数量]
  E --> F[排序结果]
```

选择阶段逐轮计算 `0.85 × 归一化相关性 - 0.15 × 最大冗余度`，取当前最佳项，再用它更新其余候选的冗余度。同一 `sourceRevisionId` 最多入选两条；因此示例会留下最强的重复摘录代表，并倾向把互补内容排在镜像内容之前。若候选全来自同一修订，结果可能少于请求上限。参考 [多样化选择循环 ↗](../../../apps/server/src/retrieval/ranking.ts#L18 "支持 85/15 的选择公式、逐轮更新冗余度、同一来源修订最多两条及可能提前结束的行为。")

<a id="boundaries"></a>
## 相似度降级、关闭多样化与修改入口

冗余度有三种来源：规范化后的候选摘录完全相同记为 1；两边都有向量时使用点积，并把负值截为 0；缺少任一向量时，同一来源修订记为 0.8，不同来源记为 0。这样即使向量尚不可用，多样化路径仍能压制同源候选堆叠。参考 [冗余度降级规则 ↗](../../../apps/server/src/retrieval/ranking.ts#L38 "支持候选摘录完全相同、向量点积以及缺向量时按来源修订判断的三级冗余度计算。")

设置 `diversify: false` 会跳过候选摘录去重、MMR 冗余惩罚和每个来源修订最多两条的限制，但仍会执行代码符号 1.5 倍加权，按修改后的分数与 ID 排序并截断。因此它适合查看未多样化但仍含代码符号加权的排序结果，或把该结果交给后续融合；它并不保留传入候选的原始次序。参考 [关闭多样化的排序路径 ↗](../../../apps/server/src/retrieval/ranking.ts#L8 "支持 diversify=false 时仍执行代码符号加权、按分数和 ID 排序并按 limit 截断，而不进入后续多样化流程。")

调整策略时，可在 `limit` 计算处修改数量边界，在候选池构造处修改代码符号权重，在选择循环中修改 85/15 权重与同源上限，在 `similarity` 中修改冗余降级规则。
