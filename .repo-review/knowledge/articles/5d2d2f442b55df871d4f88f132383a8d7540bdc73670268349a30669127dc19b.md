# 检索证据的相关性加权与多样化排序

该模块在不改变证据身份、可见性和来源信息的前提下，对上游候选进行来源加权、代码符号加权和 MMR 式去冗余，并把结果数量限制在 1–100。它依赖统一检索端口定义的查询与候选合同，但不负责召回、权限过滤或向量生成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-contract"></a>
## 解决的问题与输入合同

`rankEvidence` 处理已经召回的原始证据候选，目标是在保留固定证据身份、可见性与来源链的同时改善顺序，而不是删除或改写证据。[排序模块的职责声明 ↗](../../../apps/server/src/retrieval/ranking.ts#L3 "支持该模块只改变候选顺序，并保留身份、可见性和来源信息的论断。") 它直接依赖统一检索端口的 `SearchQuery` 与 `SourceCandidate`：候选包含分数、片段文本、修订标识、固定片段标识、来源信息及可选路由；查询则提供数量上限、来源权重和是否多样化等排序参数。[统一检索查询与证据候选合同 ↗](../../../apps/server/src/retrieval/port.ts#L25 "说明排序函数所依赖的查询选项、候选字段和代码符号路由来自统一检索端口。") 因而该模块属于召回后的排序层；端口所述的可见性策略应在最终排序与截断前由宿主落实，本文件自身没有调用 `visible`。[可见性与来源权重约定 ↗](../../../apps/server/src/retrieval/port.ts#L36 "支持可见性是排序截断前的宿主策略，而来源权重仅影响排名偏好的边界说明。")

<a id="ranking-flow"></a>
## 核心排序流程

流程先把 `limit` 约束到 1–100，随后复制候选并将原分数乘以可选来源权重；带有 `code-symbol` 路由的候选再乘 1.5。候选按分数降序排列，同分时按标识稳定排序。若候选为空或显式关闭多样化，直接截取前 `limit` 项。[预排序与快速返回 ↗](../../../apps/server/src/retrieval/ranking.ts#L7 "支持数量钳制、来源和代码符号加权、稳定排序以及关闭多样化时直接截断的流程。") 启用多样化时，算法循环选择 `0.85 × 归一化相关性 − 0.15 × 最大冗余度` 最高的候选；每次选中后，再更新剩余候选相对已选集合的最大相似度，形成轻量 MMR。[MMR 式候选选择循环 ↗](../../../apps/server/src/retrieval/ranking.ts#L13 "支持相关性与冗余度按 0.85/0.15 组合，并逐轮更新最大相似度的核心算法说明。")

<a id="redundancy-and-limits"></a>
## 冗余判定、边界与模块关系

相似度优先比较压缩空白后的片段文本，完全一致即视为冗余；否则若两项都有向量，就使用点积并把负值截为零；缺少向量时，同一源码修订返回 0.8，不同修订返回 0。该回退让向量索引尚未补齐时仍能抑制镜像片段，但不会移除任何来源。[候选相似度与缺向量回退 ↗](../../../apps/server/src/retrieval/ranking.ts#L26 "支持文本完全相同、向量点积及同修订回退三层冗余判定规则。") 此实现假定传入向量已经归一化，且没有在本地校验维度一致性；它也只读取外部提供的向量映射，不负责 embedding、融合召回或权限判断。端口说明更高层始终应回到不可变片段引用原始证据，这与本模块仅重排 `SourceCandidate`、不生成摘要的边界一致。[固定证据锚点设计 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持排序结果仍应指回不可变片段、由上层引用原始证据而非信任派生摘要的模块关系。")
