# 视觉分析角色的结构化输出合同

该文件以 JSON Schema 规定视觉分析结果的批量文档、章节、引用和待确认问题结构，是声明性的输出规范；它能够描述合法数据形态，但本身不证明视觉分析、Schema 校验、引文抽取或独立复核已经接入运行时。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="document-structure"></a>
## 批量文档结构

合同将 `schema_version` 固定为 1，并把顶层 `documents` 限制为 1 至 16 项。每份文档包含标题、摘要、类别和章节；类别覆盖概览、架构、需求、进展、实现、测试、配置、研究与视觉等知识类型，章节则要求稳定键、标题和非空正文。[文档类别与章节结构 ↗](../../../packages/agent-runtime/roles/visual-analyst/1/output.schema.json#L5 "支持批量文档数量、类别枚举，以及章节键、标题和正文约束的说明。")

文档对象必须同时提供键、标题、摘要、类别、章节、引用和问题，顶层必须提供版本与文档数组；这两层均拒绝未声明字段。[文档与顶层必填约束 ↗](../../../packages/agent-runtime/roles/visual-analyst/1/output.schema.json#L209 "支持文档对象和顶层对象的必填字段及禁止额外属性，并用于界定这两层的合同边界。") 这些内容规定的是结果格式，而非视觉能力或处理流程已经实现。

<a id="evidence-and-questions"></a>
## 证据与不确定性表达

引用项以人读标签和理由说明证据用途，并通过限定枚举表达支持、解释、依赖或矛盾等关系。目标可以指向材料或文章；材料目标可携带固定行范围，而 `quote` 的描述约定由宿主在独立复核前抽取精确引文。问题项用于记录疑问、原因、下一步、阻塞状态和关联引用键。[引用与问题结构约束 ↗](../../../packages/agent-runtime/roles/visual-analyst/1/output.schema.json#L78 "支持引用目标、关系、宿主抽取引文的字段约定，以及引用项和问题项各自的必填字段与封闭对象约束。")

因此，该合同既能连接论断与证据，也能保留尚未解决的不确定性；但“由宿主抽取”仍只是字段说明中的约定，不能单凭 Schema 认定相应运行逻辑已经存在。

<a id="contract-boundary"></a>
## 合同边界

引用项、问题项和文档对象分别通过 `required` 列表规定最低完整性，并各自禁止额外属性；顶层对象也采用相同的封闭结构。[引用与问题结构约束 ↗](../../../packages/agent-runtime/roles/visual-analyst/1/output.schema.json#L78 "支持引用目标、关系、宿主抽取引文的字段约定，以及引用项和问题项各自的必填字段与封闭对象约束。")[文档与顶层必填约束 ↗](../../../packages/agent-runtime/roles/visual-analyst/1/output.schema.json#L209 "支持文档对象和顶层对象的必填字段及禁止额外属性，并用于界定这两层的合同边界。") 这有助于拒绝缺字段或携带未知字段的结果，但只能校验结构，不能判断图片是否真实可见、不可读文字是否被虚构，或引用在语义上是否确实支持附近论断。后续仍需运行入口、校验器、引文抽取和独立复核流程提供实现与测试证据。
