# 当前实现进展、已知限制与未决问题

omem 已形成统一证据链上的知识整理、混合检索、来源重核验、日常助理与仓库 Wiki 功能切片，并完成分层工程、浏览器及真实模型验证；当前仍受单用户部署、知识覆盖不完整、质量数据发布门未完成、跨版本身份与语义重排缺失，以及外部跟进尚未接入等限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="current-baseline"></a>
## 当前能力基线

omem 已把文本、图片、链接和上下文统一纳入不可变证据链，个人问答、受治理记忆、待办、通知与仓库 Wiki 共用 Capture→Source/Revision/Fragment，而不是各自建立事实库。[项目总览中的统一证据链 ↗](4c55b33ace6626adffcb745e2d8b3732a0dd8064f2f8d5a89ca3b886a364aac6.md#positioning "引用项目总览对子系统共用不可变证据链的组织说明，支持当前能力基线的总体定位。")[omem 项目定位 ↗](../../../README.md#L1 "原始 README 直接说明统一输入、不可变证据，以及个人功能与仓库 Wiki 共用证据基础。")

统一检索先接入 FTS5/BM25、中文短词、活跃记忆原证据与知识正文引用的 RRF 融合；随后加入固定版 BGE-small-zh-v1.5 向量、按模型身份隔离的分窗索引和缺模型时的词法降级，并以 MMR 降低结果重复。[FTS5 与 RRF 融合进展 ↗](../../../docs/implementation/status.md#L13 "直接支持 FTS5/BM25、中文短词、活跃记忆原证据和知识正文引用参与 RRF 融合；其中“尚无向量”是该阶段旧结论，已由较新的中文向量记录替代。")[中文向量与检索维护进展 ↗](../../../docs/implementation/status.md#L5 "支持固定中文向量模型、模型身份隔离、词法降级、MMR、小样本结果及 reranker、ANN、历史检索缺口。") 四条中文同义问法 top-1 为 4/4 只证明小样本连通性，reranker、ANN 和历史时点检索仍未实现。[中文向量与检索维护进展 ↗](../../../docs/implementation/status.md#L5 "支持固定中文向量模型、模型身份隔离、词法降级、MMR、小样本结果及 reranker、ANN、历史检索缺口。")

来源更新也已由占位发展为实际闭环：Capture 记录失效范围，复用 extractor、独立 verifier，并由 MemoryService 原子更新同一记忆；失败或缺证据时维持 `needs_review`，只有全部受影响记忆应用成功才记为 `applied`。[来源更新重核验闭环 ↗](../../../docs/implementation/status.md#L9 "支持失效范围记录、extractor、独立 verifier、原子应用及失败时保持待复核的当前实现。")

<a id="knowledge-and-assistant"></a>
## 知识流程与日常助理

知识正文采用具名章节组织 Markdown，并把固定引用放在对应论断附近；宿主从固定 Revision 复制引文，独立角色另行核验语义支持性。原始材料仍是证据权威，派生知识只负责组织和导航，来源变化会使相关正文及其上层章节过期。[正文与固定引用合同 ↗](../../../docs/implementation/knowledge-pipeline.md#L5 "直接支持知识正文使用具名章节、内联引用、固定版本引文及不可变知识修订的结构合同。")

仓库材料、个人材料和用户补充复用同一持久任务与角色运行时。只有通过独立复核的正文才发布，未通过内容进入定向修订；分析期间若来源变化则拒绝发布，不能用旧输入生成当前结论。[知识流程阶段进展 ↗](8cacd4aed1115e3d8ab47054816bd07d2ac3d155756ba0127a3028ac0c880fd6.md#generation-and-review "引用子知识对统一运行时、生成复核和定向修订流程的综合说明。")[通用分析与独立复核流程 ↗](../../../docs/implementation/knowledge-pipeline.md#L23 "支持正文发布条件、固定引文、独立复核以及来源变化时拒绝发布。")

网页日常助理已支持持久会话、明确交办、事项改期与完成，以及等待对象、跟进时间、暂缓、取消和重启后单次补发。提醒与发生回执原子保存，但目前只进入站内通知，不会自动催促外部人员；自动监听回复、交付判定、周期回顾、重复提醒、日历和外部到期投递仍未接入。[日常助理与提醒边界 ↗](../../../README.md#L107 "支持持久会话、交办和等待事项操作、站内提醒行为，以及自动监听、周期回顾和外部投递等缺口。")

<a id="review-and-verification"></a>
## 仓库评审与验证口径

Code Wiki 是统一证据链在代码域的派生视图。当前切片已覆盖固定 Capture 文本、TS/Vue AST、人工关系 seed、可提交知识资产、共享证据 trail 和多视口浏览器流程；启动可从仓库材料及已提交知识恢复，不默认调用模型。跨文件 calls 和类型解析仍未完成，名称级调用只能作为候选；跨 revision 的符号与 Fragment 身份也不能自动续接，代码变化后需重新同步定位。[Code Wiki 当前定位与边界 ↗](../../../docs/implementation/status.md#L46 "支持 Code Wiki 属于统一证据链投影，并列明跨文件调用和跨版本身份续接尚未实现。")[Wiki 资产与恢复方式 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L21 "说明模型产物、人工 seed、runtime 缓存和 Git 资产的职责，以及默认启动不重新调用模型。")

验证证据必须按层级解释：协议 fixture 证明编排与持久语义，但不证明任意外部 Agent 可用；真实 ACP smoke 证明指定模型链路成功，真实 Lark Host 只覆盖只读能力探测和 WebSocket 启停，且该次没有发送消息。[受控学习验证范围 ↗](../../../docs/implementation/batch2/b2-08-learning-verification.md#L19 "支持协议 fixture 只能证明持久编排语义，不能证明任意外部 Agent 均可用。")[真实 ACP 与飞书 Host 验证 ↗](../../../docs/implementation/batch2/b2-08-learning-verification.md#L44 "支持真实 ACP 的模型链路结果，以及飞书 Host 只读探测、WebSocket 启停和未发送消息的验证边界。") 中文同义问法的 4/4 结果仅是小样本，不能代表整体检索质量；独立模型复核也不等于人工验收。[中文向量与检索维护进展 ↗](../../../docs/implementation/status.md#L5 "支持固定中文向量模型、模型身份隔离、词法降级、MMR、小样本结果及 reranker、ANN、历史检索缺口。")[模型复核与人工验收的区别 ↗](../../../README.md#L76 "支持派生解释与已应用事实需要区分，独立模型复核不能替代人工验收。")

全库知识仍未完整，reviewed、stale、pending、failed 及真实 HTTP 检索结果必须以同一源码指纹下最新的 coverage 与 verification 报告为准，不能累计历史通过率。[知识覆盖与验证报告口径 ↗](../../../docs/implementation/status.md#L5 "支持全库知识尚未完整、最新报告与历史报告分离且通过率不能累计的结论。")

<a id="limits-and-gates"></a>
## 仍然成立的限制与发布门

当前仍是 TypeScript、SQLite 的个人单用户实现，不具备多租户 ACL、分布式事务或团队级权限隔离。[单用户实现取舍 ↗](../../../docs/implementation/status.md#L138 "支持 SQLite 个人单用户边界、多租户与分布式事务缺失，以及可追溯不等于完成语义验证。") 服务对外暴露虽要求强令牌，但当前 shared token 不是团队租户权限系统。[网络暴露与 shared token 边界 ↗](../../../README.md#L142 "支持服务默认仅监听 loopback、外部监听需要强令牌，以及 shared token 不是团队租户权限系统。") Agent 没有领域写权限，所有事实、任务、通知和回执仍须经过 MemoryService 的确定性边界。[MemoryService 写入边界 ↗](../../../README.md#L148 "支持 Agent 无领域写权限，自动 worker 与 HTTP evaluate 均须经过确定性领域写入边界。")

质量评测基础设施已规定数据与标签隔离、飞书人工标注回调校验、冻结 manifest 和并发修订保护。[质量数据隔离与人工标注合同 ↗](../../../docs/implementation/batch2/quality-evaluation.md#L5 "支持质量数据隔离、冻结 manifest、飞书标注回调校验、按钮语义和并发修订保护。") 但 40 条 dev 草稿尚未形成完整人工真值，跨来源 holdout 尚未建立；正式评测要求冻结数据集，并检查自动应用与证据支持精度至少 95%、明确样本覆盖率至少 80%、特定误建为零。在人工确认和冻结完成前，不能声称质量发布门通过。[质量数据状态与正式门槛 ↗](../../../docs/implementation/batch2/quality-evaluation.md#L33 "支持 dev 草稿尚非人工真值、holdout 尚未建立，以及冻结前提、指标阈值和不得提前宣称通过。")

下一阶段需要按最新报告补齐全库知识覆盖，并完成 dev 标注与跨来源 holdout。[知识覆盖与验证报告口径 ↗](../../../docs/implementation/status.md#L5 "支持全库知识尚未完整、最新报告与历史报告分离且通过率不能累计的结论。")[质量数据状态与正式门槛 ↗](../../../docs/implementation/batch2/quality-evaluation.md#L33 "支持 dev 草稿尚非人工真值、holdout 尚未建立，以及冻结前提、指标阈值和不得提前宣称通过。") 代码侧仍需解决跨 revision 身份续接；检索与治理侧仍缺语义重排、周期巡检和跨来源冲突自动修订。[Code Wiki 当前定位与边界 ↗](../../../docs/implementation/status.md#L46 "支持 Code Wiki 属于统一证据链投影，并列明跨文件调用和跨版本身份续接尚未实现。")[仍未交付的知识与检索能力 ↗](../../../README.md#L76 "支持跨文件精确解析、语义重排、周期巡检和跨来源冲突自动修订仍未完成。") 外部提醒投递和自动回复监听则必须先由用户明确渠道、会话范围及授权边界，再进行真实集成验收。[日常助理与提醒边界 ↗](../../../README.md#L107 "支持持久会话、交办和等待事项操作、站内提醒行为，以及自动监听、周期回顾和外部投递等缺口。")
