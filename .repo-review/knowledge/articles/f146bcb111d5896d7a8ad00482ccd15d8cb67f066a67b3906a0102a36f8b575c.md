# 当前能力、验证进展与交付边界

omem 已形成统一的个人知识入口、可追溯知识处理、中文混合检索、来源更新和事项跟进闭环；当前仍是单用户系统，全库知识覆盖、完整主动助理、跨来源自动修订及正式质量发布门尚未完成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="current-experience"></a>
## 已经可用的个人工作入口

omem 已将日常助理、知识库、原始材料和事项放入同一个个人应用，仓库也作为个人库中的真实材料使用。知识库以完整文章为主，读者可通过页内导航理解功能，再从句段末引用回看固定原文或代码；来源变化的旧文章会显示待更新。参考 [统一知识阅读入口 ↗](../../../docs/implementation/unified-knowledge-reading.md#L5 "支持统一个人应用、完整文章阅读、页内导航、固定引用回看及旧文章待更新状态。")

日常助理支持持久会话，以及等待对象的创建、暂缓和取消；提醒与发生记录原子提交，服务重启后到期提醒只补发一次。参考 [日常消息与等待跟进 ↗](../../../docs/implementation/status.md#L3 "支持持久会话、等待对象的创建暂缓取消、提醒记录原子提交，以及服务重启后的离线提醒仅补发一次。") 带时间事项还可创建、改期、完成和重新打开。参考 [带时间事项闭环 ↗](../../../docs/implementation/status.md#L13 "支持带时间事项的创建、改期、完成和重新打开。") 当前提醒只进入站内通知中心，不会自动催促对方；自动监听回复、判断交付完成、会前准备、周期回顾、重复提醒和日历仍待接入。参考 [提醒方式与主动助理边界 ↗](../../../README.md#L113 "支持站内提醒不会自动催促对方，以及自动监听回复、交付判断、会前准备、周期回顾、重复提醒和日历尚未实现。")

<a id="knowledge-loop"></a>
## 知识、检索与来源更新如何闭环

材料沿统一的 Capture → Source / Revision / Fragment 证据链处理：专门角色分析固定材料，独立角色复核，再组织成可阅读章节；正文引用贴近论断，并能逐层返回子知识、原文或代码。参考 [知识分析与复核流程 ↗](../../../README.md#L41 "支持统一证据链、专门角色分析、独立复核、章节组织和内联固定引用。") 知识正文可以引导召回，但提供给助手的依据仍是原始 Fragment，并继续经过会话可见性过滤。参考 [知识召回与词法检索 ↗](../../../README.md#L76 "支持知识正文引导原始 Fragment 召回、会话可见性过滤、FTS5/BM25 与 RRF 融合，以及跨文件解析、周期巡检和冲突修订限制。") 未通过、过期或尚未生成的材料不能计入完成。参考 [覆盖与自动验证口径 ↗](../../../docs/implementation/unified-knowledge-reading.md#L28 "支持以当前覆盖和验证报告判断完成度，并说明未通过文章保留旧版、标记待更新且未覆盖材料不计入完成。")

检索融合 SQLite FTS5/BM25、中文短词以及原文、记忆和知识正文的 RRF 召回，命中派生内容后回查固定原文。参考 [知识召回与词法检索 ↗](../../../README.md#L76 "支持知识正文引导原始 Fragment 召回、会话可见性过滤、FTS5/BM25 与 RRF 融合，以及跨文件解析、周期巡检和冲突修订限制。") 固定版本的中文向量模型提供语义召回；模型缺失时保留词法结果并报告降级。四条中文同义问法的首位命中只是小样本，不能代表整体检索质量。参考 [中文语义检索状态 ↗](../../../docs/implementation/status.md#L9 "支持固定中文向量模型、模型缺失时的降级、小样本验证结果及 reranker、ANN、历史时点查询限制。")

来源出现新版本后，系统会记录受影响范围，重新提取并交由独立 verifier 复核，再原子更新同一记忆。证据不足或执行失败时保持 `needs_review`；只有全部受影响记忆实际应用后，刷新才标记完成。参考 [来源更新闭环 ↗](../../../docs/implementation/status.md#L11 "支持失效范围记录、重新提取、独立复核、原子更新，以及失败保持待复核的状态语义。")

<a id="limits-and-status"></a>
## 如何判断当前完成度

当前切片已有检查和浏览器验收记录，但全库完成度必须以当次 `coverage.json` 和 `verification.json` 为准；历史报告单独保存，未通过文章保留旧版并标记待更新，未覆盖材料不算完成。参考 [覆盖与自动验证口径 ↗](../../../docs/implementation/unified-knowledge-reading.md#L28 "支持以当前覆盖和验证报告判断完成度，并说明未通过文章保留旧版、标记待更新且未覆盖材料不计入完成。")

检索仍缺少 reranker、ANN 和历史时点查询；跨文件调用的精确类型解析、周期巡检及跨来源冲突自动修订也尚未完成。参考 [中文语义检索状态 ↗](../../../docs/implementation/status.md#L9 "支持固定中文向量模型、模型缺失时的降级、小样本验证结果及 reranker、ANN、历史时点查询限制。")、[知识召回与词法检索 ↗](../../../README.md#L76 "支持知识正文引导原始 Fragment 召回、会话可见性过滤、FTS5/BM25 与 RRF 融合，以及跨文件解析、周期巡检和冲突修订限制。") 当前部署是 TypeScript 与 SQLite 的个人单用户实现，不具备多租户 ACL、分布式事务或 pgvector，团队范围仍只是架构预留。参考 [单用户部署边界 ↗](../../../docs/implementation/status.md#L140 "支持当前实现不具备多租户 ACL、分布式事务和 pgvector，团队范围仍属架构预留。")

质量评测已规定数据冻结和指标门槛，但 40 条 dev 内容仍是待确认草稿，live 标注已经停止，也没有冻结数据集；单篇文档不能拆分成正式跨来源 holdout。参考 [质量数据集当前状态 ↗](../../../docs/implementation/batch2/quality-evaluation.md#L33 "支持 40 条 dev 草稿尚未成为人工真值、live 标注已停止、数据集未冻结及跨来源 holdout 尚未建立。") 在人工标注完成并冻结数据集前，不得运行或声称通过最终 holdout 门。参考 [正式质量评测门槛 ↗](../../../docs/implementation/batch2/quality-evaluation.md#L65 "支持冻结数据集的运行前提、正式指标门槛，以及人工标注完成前不得声称通过最终 holdout 门。")
