# 当前实现进展、已知限制与未决问题

截至2026-10-01，omem已形成统一证据链、混合及中文向量检索、来源更新重核验、日常助理和Code Wiki纵向切片。工程检查、浏览器流程与真实ACP链路已有分级证据，但全库知识覆盖、正式质量发布门、跨版本身份、跨文件调用、周期巡检和外部提醒投递仍未完成；2026-09-29区块中的部分结论已被较新记录替代。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="current-capabilities"></a>
## 最新能力基线

网页日常助理已支持持久会话、等待对象、跟进时间、暂缓、取消及重启后单次补发；真实 ACP 流程验证了等待创建到取消的闭环，但自动监听回复、周期回顾、重复提醒和外部到期投递仍未接入。[日常消息与跟进最新状态 ↗](../../../docs/implementation/status.md#L1 "支持持久会话、等待事项操作、重启后单次补发，以及自动监听、周期回顾、重复提醒和外部投递尚未接入。")

统一检索已接入 SQLite FTS5/BM25、中文短词、活跃记忆原证据和知识正文引用的 RRF 融合。[统一词法与知识检索融合 ↗](../../../docs/implementation/status.md#L13 "支持FTS5/BM25、中文短词、活跃记忆原证据和知识正文引用的RRF融合，并限定真实ACP连通性验证的范围。") 固定中文向量模型进一步提供按模型身份隔离的分窗索引，模型缺失时保留词法结果；AST 标识符召回与 MMR 用于补充代码定位并降低重复。四条同义问法只是小样本，reranker、ANN 与历史时点检索仍未实现。[检索维护与中文向量状态 ↗](../../../docs/implementation/status.md#L5 "支持AST标识符召回、MMR、固定中文向量模型、模型身份隔离、小样本边界，以及reranker、ANN和历史时点检索缺口。") 来源更新也已具备 extractor、独立 verifier 和 MemoryService 原子应用闭环，失败或缺证据时继续保持待复核。[来源更新重核验闭环 ↗](../../../docs/implementation/status.md#L9 "支持refresh_dependents已发展为提炼、独立复核和原子应用闭环，并列明周期巡检和跨来源冲突自动修订等后续缺口。")

<a id="knowledge-review-flow"></a>
## 统一知识与仓库评审流程

知识正文、固定引用、疑问和任务记录复用 Capture→Source/Revision/Fragment 权威链；只有独立复核通过的正文才发布，分析期间来源变化会拒绝发布。仓库分析只是通用流程的输入适配器，失败、过期或排除项不会冒充已生成。[通用分析、复核与仓库材料适配 ↗](../../../docs/implementation/knowledge-pipeline.md#L23 "支持独立复核后发布、来源变化时拒绝发布、仓库输入适配，以及失败和过期结果不得冒充完成。")

个人知识与仓库知识共用证据阅读栈，派生正文只引导召回，最终仍返回重新核对来源 head、经过可见性过滤的原始 Fragment。[共享证据阅读与原片段召回 ↗](../../../docs/implementation/knowledge-pipeline.md#L45 "支持个人和仓库知识共用阅读栈，以及派生正文只作导航、最终回到当前原始Fragment。") Code Wiki 因而不是独立知识库：它已覆盖固定 Capture 文本、AST 代码图、人工关系 seed 和多层阅读交互，但跨文件 calls、类型解析及跨 revision 符号或片段身份续接仍未实现，名称级调用只能作为候选。[Code Wiki定位与边界 ↗](../../../docs/implementation/status.md#L46 "支持Code Wiki属于统一证据链投影，并说明跨文件调用和跨revision身份续接尚未实现。")[代码解析尚未完成的能力 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L36 "直接支持跨文件calls、类型解析和跨revision语义身份续接尚未实现，并说明名称级调用只能作为候选。") Review 启动竞态也已修复，API 暂未就绪时页面保持连接并重试，不再直接误切个人模式。[Review启动模式修复 ↗](../../../docs/implementation/review-startup.md#L3 "支持启动竞态成因、连接重试行为、模式切换条件及API暂停恢复后的浏览器验证。")

## 仍然成立的边界与发布门

系统仍是个人优先的 TypeScript、SQLite 单用户实现，shared token 不是多租户 ACL；Agent 没有领域写权限，提案必须经过 MemoryService 的确定性写入边界。[单用户部署与确定性写入边界 ↗](../../../README.md#L142 "支持当前单用户部署限制、shared token并非租户权限系统，以及Agent不能绕过MemoryService直接写领域数据。") 材料还明确记录当前不具备分布式事务，[个人单用户实现取舍 ↗](../../../docs/implementation/status.md#L138 "直接支持SQLite个人单用户实现不具备多租户ACL和分布式事务。") 学习侧则仍是单进程单 worker，尚无团队或分布式部署。[单进程学习worker部署边界 ↗](../../../docs/implementation/batch2/b2-08-learning-verification.md#L85 "支持当前仅有单进程单学习worker、尚未部署团队或分布式worker。")
