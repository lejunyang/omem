# 当前实现进展、已知限制与未决问题

当前基线已形成统一知识处理、主助手治理和 Code Wiki 阅读等可运行闭环，并通过全量检查与浏览器验证。仍未完成的重点包括真实外部链路验收、语义检索、自动重核验、多租户隔离、跨文件调用和跨修订身份续接；Batch 2 清单及旧环境结论仅供追溯。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="evidence-levels"></a>
## 局部支持与证据等级

Code Wiki 是统一证据链上的代码投影，不是第二套事实权威；子知识说明了它与通用知识流程的关系。[Code Wiki 子知识 ↗](8cacd4aed1115e3d8ab47054816bd07d2ac3d155756ba0127a3028ac0c880fd6.md#code-wiki "链接 Code Wiki 子知识，解释代码投影与统一证据链的关系。") 代码图只解析已捕获版本，理解构建与引用校验读取同批固定材料，定位失败不会伪造引用。[固定捕获快照修复 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L7 "支持代码、文档、理解构建和引用校验读取同一固定材料，以及定位失败不伪造引用。") 可提交 Wiki、真实模型产物和人工 seed 与可重建的 SQLite、索引及临时目录分开管理；默认启动用仓库材料和已提交知识重建视图，不重新调用模型。[Wiki 资产与本地缓存边界 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L21 "支持可提交 Wiki、模型产物、人工 seed 与可重建运行库的职责划分，以及默认启动不重新调用模型。")

确定性代码图和手工关系已形成纵向切片，但模型说明仍是派生资料，结构及引用存在性校验不等于逐句语义支持；跨文件调用、类型解析、跨修订身份续接、embedding 检索及自动重核验仍未完成。[代码知识架构边界 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L31 "支持模型说明未独立语义复核、跨文件调用与类型解析未实现、跨修订身份续接缺失、检索仍为关键词及自动重核验未完成。") 图片链路主要由 fake transport 验证，进程恢复也只是同数据库的新 runtime 模拟，不能直接外推到真实外部环境。[行为验证的有限外推 ↗](../../../docs/implementation/status.md#L77 "支持图片仅由 fake transport 验证、进程级恢复仍为模拟，因此通过项不能直接外推到真实外部环境。") 质量侧已经生成40条 dev 草稿，但尚未全部人工确认，live 标注已停止且没有冻结数据集；跨来源 holdout 尚未建立，因此不能宣称质量发布门通过。[质量数据集当前状态 ↗](../../../docs/implementation/batch2/quality-evaluation.md#L33 "支持40条 dev 草稿已生成但 live 标注停止、尚无冻结数据集，以及跨来源 holdout 仍需更多授权来源。")

## 已被替代的历史结论

2026-09-27 的 Batch 2 审查证明当时已有迁移、租约、幂等和飞书基础设施，同时指出入口、上下文保真、召回及治理策略缺口；其隔离复现使用临时 SQLite、合成输入、注入判定和假适配器。后续子知识已将这些历史反例与新的 G01–G20 回归场景关联。[历史审查与当前回归 ↗](c3b75320d6427aac23b82436d5a4467229c02a59a87c1d2331547af21e1f6b56.md#relations-progress "链接子知识对历史反例与后续 G 场景关系的整理，供读者查看修复脉络。") 原报告明确要求修复后把案例改写为正确行为断言，不能让常规 CI 持续要求旧缺陷存在。[历史复现维护原则 ↗](../../../docs/reviews/2026-09-27-batch2/README.md#L115 "支持隔离脚本只断言旧基线缺口、修复后应改写为正确行为测试且不得在常规 CI 中固化旧缺陷。")

状态页后部“无 traecli”“没有模型 live”和“固定端口”等旧环境记录，已被顶部关于真实模型生成、动态端口和恢复验证的新复审结果替代；但真实模型生成仍不等于主助手及飞书全链路验收。[被新复审替代的环境结论 ↗](../../../docs/implementation/status.md#L5 "支持真实模型生成和动态端口等新状态替代无 traecli、无模型 live 和固定端口等旧环境记录。") Batch 2 清单也被明确标为历史记录，只用于追溯，不能充当当前交付清单。[Batch 2 历史记录声明 ↗](../../../docs/implementation/status.md#L99 "直接支持 Batch 2 仅供追溯、不能作为当前已交付清单。") 其中“人工确认正在进行”的旧说法亦被更具体的质量记录所替代：40条草稿已生成，但标注会话已取消。[质量数据集当前状态 ↗](../../../docs/implementation/batch2/quality-evaluation.md#L33 "支持40条 dev 草稿已生成但 live 标注停止、尚无冻结数据集，以及跨来源 holdout 仍需更多授权来源。")

<a id="remaining-work"></a>
## 真实限制与下一步

尚未完成的核心能力包括 embedding 语义检索、跨文件调用及类型解析、跨 revision 的符号与 Fragment 身份续接，以及覆盖所有来源的自动重核验。当前 `refresh_dependents` 只记录影响后主动以未实现错误失败，尚无 extractor 与 verifier 的 consolidation 重跑；代码变化后仍需重新同步 locator 到新 head。[自动重核验与代码身份缺口 ↗](../../../docs/implementation/status.md#L86 "支持 refresh_dependents 主动报告未实现，以及跨文件调用、跨修订身份和 embedding 检索仍有缺口。")

部署仍是个人单用户 SQLite 边界，不具备多租户 ACL、分布式事务或 pgvector；对外监听使用的 shared token 也不是团队权限系统。[单用户 SQLite 实现边界 ↗](../../../docs/implementation/status.md#L124 "支持当前实现不具备多租户 ACL、分布式事务、pgvector 和跨修订语义身份续接。")[Shared token 部署边界 ↗](../../../README.md#L92 "直接支持当前不是多租户服务，单一 shared token 不能视作团队权限系统。") 当前 README 只确认启用学习后启动一个受 lease/fencing 保护的单消费者，不据此把更早 Batch 2 的全部拓扑说明当作现行交付结论。[现行学习消费者说明 ↗](../../../README.md#L94 "支持启用学习后服务启动一个受 lease 与 fencing 保护的单消费者，并说明 extractor、独立 verifier 与 MemoryService 的写入边界。") 外部集成方面，真实飞书图片下载、reply 引用、断网恢复、真实限流窗口，以及主助手 ACP 与飞书端到端范围仍需独立验收，不能与 fixture、fake transport 或历史 live smoke 混为一谈。[真实外部集成缺口 ↗](../../../docs/implementation/status.md#L49 "支持真实飞书图片下载、reply 引用、断网恢复、真实限流窗口和端到端外部链路仍需验收。")
