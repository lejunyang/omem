# 代码快照生命周期与固定版本源码测试

该集成测试用真实临时 Git 仓库验证代码知识快照的不可变性、显式当前指针、相同内容复用、历史图可读性，以及 HTTP 源码接口按指定快照返回固定内容；同时确认被移除文件的理解会标记为过期。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决的问题与测试场景

该测试针对一个容易混淆的生命周期：仓库先处于已提交版本 A，随后产生包含文件修改和临时文件的脏工作树 B，最后又恢复到与 A 完全相同的内容。它要证明“当前快照”由显式指针决定，而不是简单选择最近捕获时间；相同输入应复用旧快照，已经产生的 B 则继续作为不可变历史存在。测试通过临时目录创建真实 Git 仓库，并用真实提交构造基线，而非只伪造数据库记录。[临时 Git 仓库与测试基线 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L22 "支持测试使用真实临时仓库、Git 配置和提交来构造快照输入的说明。")

这一场景对应代码同步的内容寻址设计：快照身份综合仓库、提交、脏状态和排序后的内容哈希，相同输入可幂等复用；树发生变化时才生成新快照。[代码同步的快照身份规则 ↗](../../../apps/server/src/code/sync.ts#L1 "解释快照为何在相同输入下复用、在工作树变化时新增。")

<a id="flow"></a>
## 核心流程与断言

流程依次执行 `runReviewSync` 和 `runCodeSync`：A 首次生成且成为当前快照；修改 `a.ts` 并增加 `temp.ts` 后生成不同的 B；恢复原内容并删除临时文件后，第三次同步复用 A，同时保持 A 的捕获时间不变。当前图不再包含临时文件，但文件列表将其标为 removed；显式查询 B 的图仍能看到它。[A-B-A 快照切换断言 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L68 "支持新建 B、复用 A、移动当前指针并保留历史图的核心流程。")

随后测试通过 Fastify 注入请求读取源码：同一文件在 A 返回 `return 1`，在 B 返回 `return 2`；已经从磁盘删除的 `temp.ts` 仍可从 B 的固定源码对象读取，而它在从未包含该文件的 A 中返回 404，不会猜测或退回实时磁盘内容。[按快照固定读取源码 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L113 "支持 HTTP 接口分别返回 A、B 内容，并对 A 中不存在的临时文件返回 404。") 最后直接查询 `code_understandings`，断言被移除文件的理解记录存在且 `stale=1`，验证历史保留与当前知识失效是两条独立语义。[移除文件的理解过期断言 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L153 "支持被移除文件对应理解记录被标记为 stale 的论断。")

<a id="relations_limits"></a>
## 模块关系、边界与未覆盖行为

测试把通用 `Store`、评审材料同步、代码图同步、代码存储查询和评审 HTTP 应用串成一个集成切片；这些依赖由测试文件直接导入，说明断言横跨持久层、投影层和接口层。[测试涉及的服务模块 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L11 "测试导入直接表明 Store、两类同步、代码存储查询和评审应用之间的集成关系。") 代码图自身被定义为已捕获 fragment 的确定性投影，旧符号和边通过快照过滤或 stale 状态保留，这为测试中的历史可读与当前移除行为提供背景。[代码图存储与历史保留规则 ↗](../../../apps/server/src/code/store.ts#L1 "解释代码图作为捕获材料投影，以及消失符号和旧边通过过滤或 stale 状态保留的设计背景。")

覆盖范围仍有限：只有单文件 TypeScript、一次脏树往返和顺序执行；没有断言并发同步、跨进程重启、快照内容损坏、非法行号或未知文件标识。HTTP 部分使用本地 Host/Origin，只验证成功响应与缺失源码 404，没有覆盖令牌模式、非同源拒绝或其他安全分支；评审应用文档明确这些访问控制另有行为。[评审 HTTP 应用安全边界 ↗](../../../apps/server/src/review/app.ts#L6 "支持测试未覆盖的令牌与同源访问控制确实属于该 HTTP 应用的既定边界。") 清理逻辑会关闭应用、数据库并递归删除临时目录，但异常中途发生时仓库目录并非由统一 `afterEach` 注册，因此失败路径下的资源回收也未被断言。[测试清理路径 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L22 "支持常规清理由 afterEach 和测试末尾分别承担，以及异常路径清理未被专门验证的判断。")
