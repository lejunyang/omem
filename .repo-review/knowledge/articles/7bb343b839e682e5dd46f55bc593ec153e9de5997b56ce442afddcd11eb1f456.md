# 代码快照生命周期与固定源码测试

该集成测试验证显式 head 指针、内容相同时的快照复用、历史快照不可变，以及源码 API 必须按指定快照返回固定内容而不能猜测当前磁盘状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="head-lifecycle"></a>
## A→脏 B→A 的显式 head 切换

测试从已提交的 V1 建立干净快照 A，再修改函数并添加临时文件形成脏快照 B。B 获得不同 ID、包含两个文件并成为当前 head；工作树恢复为 V1 且删除临时文件后，同步结果复用 A，而不是因 B 的 capturedAt 更晚就继续选择 B。A 的 capturedAt 保持不变，证明复用不会改写历史快照。[快照创建、脏态与复用流程 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L60 "支持 A、B 的建立以及恢复工作树后显式 head 回到不可变 A 的说明。")

当前 head 图不再显示临时文件，但文件目录将其标为 removed；显式查询 B 仍能看到该文件。这区分了“当前视图移除”和“历史数据删除”。[当前图与历史图的文件状态 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L102 "支持临时文件从当前 head 消失但仍作为 removed 文件并保留在 B 历史图中的说明。")

<a id="pinned-source"></a>
## 按快照固定的源码读取

HTTP `/source` 接口携带 snapshotId 后，A 返回 `return 1`，B 返回 `return 2`。即便临时文件已从磁盘删除，查询 B 仍返回固定 blob；查询从未包含该文件的 A 则返回 404，不会退回实时磁盘或猜测其他快照内容。移除文件对应的 understanding 还必须被标记为 stale。[固定源码与过期理解断言 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L113 "支持源码按快照返回、缺失时不猜测，以及被移除文件理解标记为 stale 的论断。")

测试覆盖单文件修改、未提交新增、回退和源码读取，但未覆盖 rename、二进制文件、并发同步、Git 分支切换、指定非法行号或未知 snapshotId，也没有断言过期理解的后续清理策略。
