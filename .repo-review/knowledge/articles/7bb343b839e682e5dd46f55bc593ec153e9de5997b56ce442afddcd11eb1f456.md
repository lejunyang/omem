# 代码快照复用、历史保留与固定源码读取测试

该集成测试用临时 Git 仓库模拟“已提交基线—脏工作区—恢复基线”的完整周期，验证相同代码状态会复用原快照并重新成为当前头，同时保留中间快照及其固定源码。测试还覆盖当前图的移除语义、按快照读取源码，以及被移除文件的理解结果过期处理。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-setup"></a>
## 解决什么风险

代码知识不能单凭快照的创建时间判断当前版本：工作区恢复旧内容后，较晚创建的脏快照并不代表当前状态。该测试验证**显式当前头、不可变历史和固定源码**能够同时成立。它为每个用例创建临时 Git 仓库与独立存储，并在结束后关闭数据库、清理目录，避免依赖真实仓库状态。参考 [临时仓库与资源清理 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L22 "支持测试创建隔离存储，并在每个用例后关闭数据库和清理目录的说明。")

用例在基线和脏工作区阶段都先执行材料捕获同步，再执行代码同步，并通过代码图检查临时文件是否进入快照；后续还经 Review HTTP 接口读取指定快照的源码。因此，它验证的是同步、图查询与读取接口协作后的生命周期行为。参考 [同步与图查询流程 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L68 "支持用例实际依次执行材料捕获同步、代码同步，并通过代码图检查脏快照内容的论断。")

<a id="snapshot-lifecycle"></a>
## 三阶段快照生命周期

流程先提交只含 `alpha → 1` 的基线并生成干净快照 A；随后将函数改为 `alpha → 2`、加入未提交的临时文件，生成新的脏快照 B。B 含两个文件并成为当前头，图中也能找到临时文件。参考 [脏快照生成 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L76 "支持工作区修改函数、加入临时文件后生成独立快照 B，并使其成为当前头的过程。")

当工作区恢复为 A 的内容后，再次同步会复用 A，而不是制造第三份快照；当前头重新指向 A，A 的捕获时间保持不变。当前图不再展示临时文件，文件列表将其标记为已移除，但显式查询 B 仍能看到它，说明当前状态切换不会破坏历史快照。参考 [恢复基线与保留历史 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L88 "支持恢复内容后复用 A、重设当前头、保持捕获时间，并继续读取 B 历史图的结论。")

复用来自内容寻址规则：快照身份由仓库、提交、脏状态和排序后的内容哈希共同确定，相同输入会得到相同身份。参考 [快照内容寻址规则 ↗](../../../apps/server/src/code/store.ts#L7 "解释快照身份包含仓库、提交、脏状态和排序后的内容哈希，为相同输入的幂等复用提供依据。")

<a id="source-and-boundaries"></a>
## 固定源码与覆盖边界

HTTP 读取由 `snapshotId` 固定版本：同一文件在 A 中返回 `return 1`，在 B 中返回 `return 2`；已经从磁盘删除的临时文件仍能从 B 的不可变内容读取，而在从未包含它的 A 中请求会得到 404。参考 [按快照读取固定源码 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L113 "支持 A 与 B 返回不同版本源码、删除后的临时文件仍可从 B 读取，以及 A 返回 404 的 HTTP 行为。")

测试还确认，被移除临时文件对应的文件级理解会标记为过期，避免旧解释继续作为当前事实。参考 [移除文件理解过期 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L153 "支持被移除文件的文件级理解记录存在并被标记为过期的结论。")

覆盖范围限于单进程顺序执行的 A→B→A 生命周期、头指针切换、历史图和固定源码读取，不代表并发或跨进程恢复已经验证。Review 应用的访问策略另分两种情况：未设置 `REVIEW_TOKEN` 时只接受 loopback Host 与本地开发源请求；设置后则以令牌保护全部 `/api` 路由。延伸阅读：[Review 接口访问策略 ↗](../../../apps/server/src/review/app.ts#L6 "说明未设置令牌时的本地访问限制，以及设置令牌后全部 API 路由受令牌保护的两个安全分支。")
