# 统一打开知识、原文与固定引用

KnowledgeFrame 是证据阅读界面的统一分派层：它解析导航帧，直接打开知识文章或原始材料；遇到固定引用时先向服务端解析目标，再显示引用理由并进入对应内容，同时避免迟到请求覆盖当前页面。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 一个入口承接三种阅读对象

读者从文章继续查看证据时，可能打开另一篇知识文章、原始材料，或一条需要先解析的固定引用。`KnowledgeFrame` 用统一的 `frame` 承接这三种导航对象，并向父级回传后续导航和已加载标题。帧的 `id` 是 JSON 字符串，组件将它还原为键、修订、章节或行号等参数；解析失败时返回空对象，避免 JSON 解析异常直接打断渲染。参考 [帧输入与标识解析 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L7 "支持统一帧输入、导航与加载事件，以及 JSON 帧标识的容错解析。")

<a id="citationFlow"></a>
## 点击引用后的解析流程

以读者点击正文引用为例：当帧类型为 `citation` 时，监听器先清空旧内容并递增 `generation`，再用文章键、文章修订和引用键请求 `/citation`。只有仍属于最新一代的响应才能更新界面，较早请求即使稍后返回也会被忽略；请求失败则显示“引用不可用”。参考 [引用请求与竞态保护 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L22 "支持仅为 citation 帧发起解析请求、重置状态、使用 generation 忽略迟到响应及处理错误。")

解析成功后，界面先展示引用关系和引用理由。若引用不可操作或目标缺失，会说明无法打开；可用目标若是文章，就交给 `KnowledgeDocument`，否则交给 `KnowledgeSource`，并传递解析结果中的修订、章节，或 digest 与行范围。子视图产生的新导航会继续上抛，读者可以沿证据深入。参考 [引用目标分派 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L83 "支持引用理由和不可用状态的展示，以及解析后的文章或材料目标进入相应子视图。")

<a id="directDispatch"></a>
## 直接打开与修改入口

`knowledge` 帧直接把文章键、可选修订和章节交给文章视图；`source` 帧把材料键、可选 digest 和起止行交给材料视图。未提供 digest 时，本层传入 `undefined`，不在此组件中决定具体版本。两类直接帧加载后都会把真实标题和当前帧 ID 回传。参考 [文章与材料直接打开 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L63 "支持 knowledge 与 source 帧分别传递文章定位参数和材料定位参数，并回传加载标题。")

扩展时要分清两组概念：新增**帧类型**至少要增加模板分派；只有当该类型也需要由本层异步解析时，才相应扩展监听逻辑。当前模板把 `knowledge`、`source` 之外的类型都放进引用分支，所以只增加类型声明而不增加模板分支，会显示引用加载状态。新增**引用关系**则应扩展 `relationLabels`；未知关系目前回退显示为“引用”。参考 [引用请求与竞态保护 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L22 "支持仅为 citation 帧发起解析请求、重置状态、使用 generation 忽略迟到响应及处理错误。") [引用目标分派 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L83 "支持引用理由和不可用状态的展示，以及解析后的文章或材料目标进入相应子视图。") [引用关系标签 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L52 "支持已知引用关系的人读标签映射；模板对未知关系回退显示通用“引用”。")
