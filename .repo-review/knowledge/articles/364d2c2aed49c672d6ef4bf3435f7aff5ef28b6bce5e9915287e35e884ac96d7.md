# 知识复核结果的数据合同

该 Schema 定义知识复核角色的结构化输出：一次可返回多个文档的接受或修订结论，并附带问题清单和需要进一步确认的事项。它约束输出格式，但不能单独证明复核流程已经运行或复核结果已被应用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

知识生成后需要稳定、可校验的复核结果格式，供宿主接收逐文档结论。该合同以 `schema_version: 1` 标识版本，要求顶层包含 `verdicts`，一次输出至少覆盖一个、最多覆盖十六个文档。它描述的是**复核输出的数据形状**，并不代表复核器已经执行，也不能证明某篇知识文章已经通过审核。参考 [复核输出顶层结构 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/output.schema.json#L1 "支持合同版本、顶层 verdicts 字段及单批文档数量范围的说明。")

<a id="verdict-flow"></a>
## 逐文档记录结论与问题

每条结果通过 `documentKey` 对应被复核文档，`verdict` 只能取 `accepted` 或 `needs_revision`。`issues` 是相关问题细节的文本数组：每项必须非空、最长 1600 个字符，单个文档最多记录三十项。Schema 没有规定 `issues` 与某一种结论之间的条件关系，因此不能仅据此断言接受结论必须没有问题，或问题只用于解释修订结论。参考 [文档结论与问题清单 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/output.schema.json#L16 "支持 documentKey、二态 verdict 以及 issues 的数量和文本约束，并表明 Schema 未声明二者的条件关系。")

<a id="clarification"></a>
## 把不确定事项结构化

复核结果还可携带结构化 `questions`。每个问题必须同时给出问题内容、提出原因、下一步行动、是否阻塞和相关引用键，使缺少背景或证据的事项能够被后续流程明确处理。参考 [待确认问题结构 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/output.schema.json#L37 "支持结构化问题的字段组成、长度限制和必填要求。")

`documentKey`、`verdict`、`issues` 和 `questions` 都是每条结果的必填字段；结果对象与顶层对象均禁止额外属性。若要增加新状态或元数据，需要先演进 Schema，而不能直接写入未声明字段。参考 [必填字段与严格对象约束 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/output.schema.json#L79 "支持逐条结果的必填字段，以及结果对象和顶层对象禁止额外属性的结论。")
