# KnowledgeReview.v1 输出结构

该 JSON Schema 约束独立复核结果：每批包含 1–16 个逐文档 verdict，结论只能是 accepted 或 needs_revision，并可附带问题清单和结构化未决事项。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="batch-verdicts"></a>
## 批次与判定单位

`KnowledgeReview.v1` 的顶层对象固定 `schema_version` 为 1，并要求提供 `verdicts`。批次必须包含 1–16 项，每项用最长 500 字符的 `documentKey` 对应一份草稿；`verdict` 只能取 `accepted` 或 `needs_revision`。[复核批次与判定枚举 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/output.schema.json#L1 "支持 schema 版本、批次数量、documentKey 以及两种 verdict 取值的说明。") 因而该合同表达的是逐文档二元复核结果，不包含评分、部分通过或自动改写正文的字段。

<a id="issues-questions"></a>
## 问题与未决事项

每个 verdict 可列最多 30 条、每条最长 1,600 字符的 `issues`。`questions` 最多 20 项，每项必须同时给出问题、原因、下一步、是否阻塞及引用键列表，且禁止额外属性。[问题与未决事项字段 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/output.schema.json#L28 "支持 issues 数量和长度，以及 questions 必填结构与约束的说明。") 顶层和 verdict 同样关闭额外属性并要求关键字段齐全，使宿主可进行严格结构校验；但 schema 只保证形状，不能证明结论在语义上正确。[严格必填与顶层合同 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/output.schema.json#L79 "支持 verdict 必填字段、禁止额外属性以及顶层 KnowledgeReview.v1 标识的说明。")
