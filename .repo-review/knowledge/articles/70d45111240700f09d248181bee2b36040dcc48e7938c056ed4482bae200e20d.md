# SQLite 模式迁移与历史校验

定义并原子执行 1–14 版 SQLite 模式演进，校验版本、迁移名称与校验和，拒绝由较新程序创建的数据库，并在成功后启用 WAL。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决的问题与数据边界

该模块把捕获材料、不可变修订、任务与记忆版本、作业、治理决策、通知投递、会话和来源画像等持久化能力组织为顺序迁移；当前支持的最高模式版本是 14。基础表先建立 Source→Revision→Fragment、变化记录和通知，再逐版加入可靠作业、受治理记忆、飞书接入、质量标注及注意力案例等能力。[模式版本与迁移清单 ↗](../../../apps/server/src/storage/migrations.ts#L920 "支持最高版本以及各功能切片按版本顺序演进的说明。")

它也明确数据库兼容边界：若磁盘模式比当前程序更新，就拒绝继续写入，避免旧程序破坏新结构。[新版本数据库保护 ↗](../../../apps/server/src/storage/migrations.ts#L1096 "支持数据库模式超前时拒绝写入的兼容边界。")

<a id="migration_flow"></a>
## 迁移流程与一致性

每组 SQL 先按固定分隔符计算 SHA-256，并与版本、名称一起登记。启动时读取 `PRAGMA user_version`，核对迁移历史不存在超前、未知、缺失或校验和漂移；仅对旧版顺序升级。[迁移历史校验 ↗](../../../apps/server/src/storage/migrations.ts#L1024 "说明历史记录的超前、未知、校验和和缺失检查。")

单次迁移使用 `BEGIN IMMEDIATE`，要求当前版本恰为目标版本减一；执行全部语句、写迁移记录、调用验收钩子并更新 `user_version` 后才提交，任一步失败均回滚。全部完成后再次校验历史并启用 WAL。[原子迁移执行 ↗](../../../apps/server/src/storage/migrations.ts#L1057 "支持顺序执行、提交前钩子、版本更新和失败回滚流程。")

<a id="limits"></a>
## 特殊兼容与边界条件

版本 1 允许旧式固定校验和，升级到版本 2 时会补写历史记录，这是对早期无完整迁移账本数据库的窄兼容。若数据库既无迁移表又声明版本大于 1，或历史记录与本构建不一致，会直接报错。[旧版迁移账本兼容 ↗](../../../apps/server/src/storage/migrations.ts#L1007 "说明版本 1 旧校验和及版本 2 补录历史的特殊处理。")

版本 13 通过建新表、复制、删除和改名扩展提案及策略状态，并同步重建外键子表；这依赖整次迁移事务保证中间结构不外露。该文件只定义结构演进，实际业务写入由 Store 和各 Repository 完成。[注意力治理表重建 ↗](../../../apps/server/src/storage/migrations.ts#L819 "支持版本 13 通过复制和重命名改变约束、并同时处理外键子表的论断。")
