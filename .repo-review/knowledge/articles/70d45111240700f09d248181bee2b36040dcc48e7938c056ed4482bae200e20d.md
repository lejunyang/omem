# SQLite 模式演进与历史完整性保护

通过按版本登记、以 SQL 语句集合校验和核对的顺序迁移，将 SQLite 模式推进到版本 17；迁移在独立事务中更新历史和 user_version，并拒绝缺失、未知、篡改、超前或高于程序支持范围的模式历史。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="schema-scope"></a>
## 模式覆盖范围

迁移文件集中定义服务器持久化结构：基础版本建立来源、修订、片段、关系、变更、通知和任务等表。该材料只能证明表结构及唯一约束，不能据此断言数据库机制禁止更新修订；这替代此前直接把基础 `revisions` 表称为“不可变修订”的结论。[基础持久化表 ↗](../../../apps/server/src/storage/migrations.ts#L30 "支持基础版本的核心表与唯一约束，同时表明该范围未提供禁止更新修订的数据库机制。") 迁移清单按版本逐步加入作业与输入缓冲、角色运行时、治理式记忆、飞书连接与投递、质量标注、会话、来源画像、刷新结果和检索索引，当前支持版本为 17。[迁移版本清单 ↗](../../../apps/server/src/storage/migrations.ts#L959 "支持数据库能力按迁移演进至版本 17，并界定各版本的功能范围。") 版本 13 还建立知识争议表，用于保留相互矛盾的来源归属，而不自动应用或隐藏任一方。[知识争议存储 ↗](../../../apps/server/src/storage/migrations.ts#L860 "支持版本 13 建立争议记录结构，并保留相互矛盾来源归属的论断。")

版本 15 把 FTS5 定义为可重建的片段投影，并用触发器同步片段变化。[全文检索投影 ↗](../../../apps/server/src/storage/migrations.ts#L915 "支持 FTS 被明确设计为可重建投影，并由触发器同步片段变化。") 版本 17 定义按模型、片段和分片区分的向量表及 head 表，但本文件没有描述语义索引的重建流程。[语义向量存储结构 ↗](../../../apps/server/src/storage/migrations.ts#L948 "支持向量按模型、片段和分片存储及 embedding head 的结构，同时限定材料没有说明重建流程。") 因此旧结论“词法与语义索引都在此明确可重建”被替代为：只有 FTS 在当前材料中被明确声明可重建。

<a id="migration-flow"></a>
## 校验和与事务迁移

每组迁移 SQL 以固定分隔符拼接后计算 SHA-256，因此校验和绑定的是语句集合。[迁移语句校验和算法 ↗](../../../apps/server/src/storage/migrations.ts#L943 "支持仅将迁移 SQL 语句集合以固定分隔符拼接后计算 SHA-256，不包含迁移名称。") 历史校验按版本寻找预期迁移并核对该校验和；它没有比较已存储名称与当前名称，所以“版本、名称、语句和校验和全部绑定”的旧结论被替代。校验还会拒绝历史记录超前、未知版本、校验和不匹配及当前 schema 所需记录缺失；schema 0 或 1 缺少迁移表可继续，版本 1 另有旧校验和兼容例外。[迁移历史完整性校验 ↗](../../../apps/server/src/storage/migrations.ts#L1054 "支持按版本定位预期迁移并核对校验和，以及历史缺失、超前、未知版本和旧版例外规则。")

单次迁移使用 `BEGIN IMMEDIATE`，只允许从目标版本的前一版本推进。SQL 执行后写入迁移历史、调用提交前钩子、更新 `user_version` 并提交；任一步失败都会回滚。升级到版本 2 时还会补写旧基础迁移记录。[事务化迁移执行 ↗](../../../apps/server/src/storage/migrations.ts#L1104 "支持相邻版本约束、迁移历史写入、提交前钩子、user_version 更新及失败回滚流程。")

<a id="runtime-boundaries"></a>
## 入口保护与验证边界

迁移入口先开启外键约束并拒绝高于程序支持版本的数据库；随后校验当前历史，依次应用高于初始版本的迁移，再按版本 17 复核历史并启用 WAL。[迁移入口与版本保护 ↗](../../../apps/server/src/storage/migrations.ts#L1143 "支持拒绝过新模式、迁移前后验证历史、顺序执行待应用版本及完成后启用 WAL。") 这些实现证明了顺序推进、单次迁移回滚和历史完整性保护机制，但不能单独证明所有旧数据库形态均经过真实升级验证。

尤其是表重建、外键关系、FTS5 触发器、向量表及旧版兼容分支仍需结合迁移测试和数据库夹具确认。提交前钩子被明确设计为验收测试接缝，抛错应使整次迁移回滚，但该声明本身并不等于行为已经被测试覆盖。[迁移验收测试接缝 ↗](../../../apps/server/src/storage/migrations.ts#L25 "支持提交前钩子被设计为测试回滚行为的接缝，但不把设计声明当作实际测试结果。")
