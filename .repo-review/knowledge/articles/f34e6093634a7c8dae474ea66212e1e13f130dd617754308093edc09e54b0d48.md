# ACP 实时接入冒烟验证

使用实际 Agent 配置发起受控算术请求，验证 ACP 会话、文本事件聚合以及模型与推理强度配置的回报；它是依赖外部 Agent CLI 的实时检查，不是隔离单元测试。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 验证目标与依赖

脚本从服务端配置中取得 `traex` 基础档案，再通过共享的实时模型选择器探测 ACP 能力并生成本次使用的 profile。随后它调用服务端 `acp` 入口，因此覆盖的是“配置加载—能力探测—真实会话”这一整段集成链，而非模拟协议响应。[配置探测与 ACP 调用准备 ↗](../../../scripts/live-acp-smoke.ts#L1 "支持脚本使用服务端配置、实时 profile 选择器和 ACP 入口组成真实集成链的说明。")

测试提示只要求计算 3 组、每组 4 件，并明确禁止工具和文件访问，使检查重点落在基本文本应答能力上；但是否真正遵守权限约束，仅凭最终答案无法完整证明。[受控算术测试材料 ↗](../../../scripts/live-acp-smoke.ts#L13 "说明请求内容、禁止工具操作的约束以及预期算术结果来源。")

<a id="flow"></a>
## 核心流程与判定

回调记录所有事件类型，并只把 `text` 事件拼接成答案。会话结束后，答案必须包含字符串 `12`，否则脚本直接失败；通过后则输出 Agent 信息、ACP 实际回报的模型与推理强度、答案及去重事件类型，便于人工核对运行环境。[文本聚合与结果输出 ↗](../../../scripts/live-acp-smoke.ts#L19 "支持事件收集、文本拼接、答案断言及诊断字段输出的流程描述。")

这里的断言较宽松：包含 `12` 即算成功，没有校验答案是否只有数字、是否出现权限请求，也没有断言配置模型等于请求模型。因此它能发现基本链路或明显回答错误，却不能证明事件顺序、内容纯净度和配置一致性。[ACP 冒烟测试唯一硬断言 ↗](../../../scripts/live-acp-smoke.ts#L25 "支持测试只要求答案包含 12、未严格验证其他行为的边界分析。")
