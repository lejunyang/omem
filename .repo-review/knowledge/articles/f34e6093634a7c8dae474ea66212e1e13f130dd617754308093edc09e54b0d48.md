# ACP 真实链路冒烟脚本

该脚本通过真实 ACP 会话验证配置加载、模型探测与选择、流式文本接收以及最终答案检查能否串联运行。它适合作为外部 Agent CLI 的在线冒烟检查，但断言较宽松，不能替代协议细节、权限行为或完整模型配置测试。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决的问题与测试性质

脚本用于确认 omem 到外部 Agent CLI 的 ACP 接入在真实环境中能够完成一次最小对话：它加载服务配置，固定寻找 `traex` profile，再根据 ACP 暴露的能力生成实际运行 profile。[配置加载与在线 profile 选择 ↗](../../../scripts/live-acp-smoke.ts#L1 "支持脚本加载配置、寻找 traex profile，并调用在线模型选择逻辑的说明。") 随后发送一道答案应为 12 的简单中文题，并明确要求模型不使用工具，以便把检查重点限制在会话启动、配置应用和文本返回链路。[ACP 冒烟测试提示内容 ↗](../../../scripts/live-acp-smoke.ts#L10 "支持测试发送中文算术问题并要求不调用工具的论断。") 这是依赖本机 CLI、可用模型及环境配置的在线冒烟测试，不是隔离的单元测试。

<a id="flow"></a>
## 核心执行流程

模型选择并非直接相信静态配置：`selectLiveProfile` 先用空 prompt 建立探测会话，读取类型为 `select` 的 model 配置项，再依次考虑 `OMEM_LIVE_MODEL`、profile 默认模型、ACP 当前值和首个可用值；显式请求不存在时会失败。[在线模型探测与选择规则 ↗](../../../scripts/live-model.ts#L4 "解释模型能力探测、候选优先级以及显式请求不可用时的失败行为。") 主脚本把选出的 profile、工作目录、文本内容、回调和取消信号传给 `acp`。回调记录所有事件类型，但只有 `text` 事件会拼入答案；会话结束后检查答案包含 `12`，再输出 Agent 信息、ACP 实际模型与推理强度、答案及去重后的事件类型，便于人工追踪运行配置。[流式结果收集与输出断言 ↗](../../../scripts/live-acp-smoke.ts#L19 "支持文本拼接、答案检查和诊断信息输出这一核心流程。")

<a id="boundaries"></a>
## 边界条件与模块关系

该脚本与配置模块、ACP 运行模块和在线模型选择模块直接相连，跨文件关系由三个显式 import 及对应调用给出。[脚本的直接模块依赖 ↗](../../../scripts/live-acp-smoke.ts#L1 "证明脚本直接依赖配置加载、ACP 运行和在线模型选择三个模块。") 配置中的 profiles 至少有一项，但所示 schema 并不保证一定存在 id 为 `traex` 的项；脚本使用非空断言，因此缺失时不会得到友好的前置错误。[profile 数组约束与 traex 假设 ↗](../../../apps/server/src/config.ts#L18 "配置 schema 只保证 profiles 非空；结合脚本对 traex 的非空断言，支持缺失指定 profile 的边界分析。") 断言只要求拼接文本包含字符串 `12`，没有核验答案是否仅为 12，也没有断言事件种类、模型或 effort 等于期望值；此外，新建的 AbortSignal 没有主动取消路径。因而它能证明一次基本链路成功，却未覆盖工具权限、超时/中止、流式顺序、错误恢复及错误答案中偶然含有 12 的情况。
