# 知识文章的独立事实复核规则

这份角色配置规定了知识草稿的独立复核方法：以固定原材料或已复核文章章节为依据，判断引用能否支持论断，并重点识别事实错误、时间混淆、范围越界和关键约束缺失。它描述的是复核角色应遵守的合同，不能单独证明对应运行流程已经实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 复核解决什么问题

该配置面向准备发布的知识文章，要求复核者把草稿与原材料独立对照，检查引用是否真正支持附近论断，以及文章有没有混淆时间、适用范围和约束。存在事实错误或证据不支持时应返回修订结论；明确保留为不确定的问题可以接受，不应仅因写作风格偏好拒绝。输出被限定为结构化的 `KnowledgeReview.v1`，包含文档结论、问题和待确认事项。参考 [独立复核职责与输出 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/prompt.md#L1 "支持复核目标、判定原则以及结构化输出合同的说明。")

这是一份**角色行为规范**：它说明复核应该怎样进行，但材料本身没有提供执行入口、实现代码或运行记录，因此不能据此断言复核流程已经在系统中可用。

<a id="review_threshold"></a>
## 以读者是否会被误导为门槛

复核对象是面向读者的知识文章，而不是逐行代码审计。正常输入和材料声明的类型合同下，可以概括功能，无需在每句话重复所有保护分支、回退机制与运行前提。只有会让读者误判功能、证据来源、数据边界或关键行为的实质性问题才应阻止发布；无关边界未展开、措辞不够形式化，或缺少某个假设场景的测试，都不是当然的拒绝理由。参考 [面向读者的发布门槛 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/prompt.md#L4 "解释哪些实质性问题应阻止发布，以及哪些非关键差异不应导致拒绝。")

因此，`questions` 应聚焦理解或使用文章所必需的未知项，而不是演变成泛化的测试覆盖清单。

<a id="evidence_and_time"></a>
## 保留证据的时间与层级边界

材料必须按时间语境解读：历史调研里“当时未实现”的结论不能自动推翻较新的实现或验证材料。若证据出现实质矛盾，应指出冲突依据及其影响；无法确认的能力继续标为不确定，不能为了叙述顺畅补造事实。参考 [历史状态与不确定性 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/prompt.md#L6 "支持按材料时代区分历史状态、处理证据冲突并禁止补造事实的要求。")

上层文章可以引用已经独立复核的固定子章节，作为可追溯概括，但这种文章引用不是新的独立事实来源。复核时应确认上层论断忠实保留子章节的时间、范围、限制和不确定性；只有出现具体矛盾、越界推断或子章节不支持论断时才要求修订。新增事实仍须由原材料直接支持。参考 [上层文章引用边界 ↗](../../../packages/agent-runtime/roles/knowledge-verifier/1/prompt.md#L8 "说明已复核子章节作为可追溯概括时的证据地位、核验重点与新增事实限制。")
