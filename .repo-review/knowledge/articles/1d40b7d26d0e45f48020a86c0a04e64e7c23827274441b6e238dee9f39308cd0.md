# review · 模块理解

repo-review 的仓库适配与服务编排模块：把代码、文档和用户补充捕获为统一证据，在隔离运行库中维护修订、人工关系、知识文章与代码投影，并通过本地 API 提供可追溯检索和显式模型生成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 定位、存储与启动边界

`review` 不是独立的代码知识库，而是 omem 面向当前仓库的输入适配与运行组合层。仓库文件进入共享捕获和知识流水线，评审仓库复用通用 `KnowledgeRepository`，同时排除已删除来源与历史别名；分析、复核及引用仍遵循统一证据模型。[仓库材料与知识仓库适配 ↗](../../../apps/server/src/review/materials.ts#L60 "支持 review 复用统一知识仓库，并过滤删除来源与历史别名的模块定位。") 运行数据库位于 `.repo-review/runtime/data`，与个人工作区隔离，旧快照只在显式启用导入时参与初始化，因此当前能力属于本地单用户评审环境，不能视为租户隔离。[隔离评审运行库 ↗](../../../apps/server/src/review/store.ts#L100 "支持运行数据目录、个人工作区隔离及旧快照仅显式导入的边界。")

服务启动时先创建评审 Store，依次完成仓库同步、知识恢复和代码投影，之后才构建应用并监听回环地址。[评审服务启动顺序 ↗](../../../apps/server/src/review/main.ts#L15 "证明同步、知识恢复与代码投影均在应用监听前完成。") 增量同步根据 Git 基线、工作树脏状态和数据库身份决定扫描范围；脏工作树或文件失败时保存结果但不推进基线，Git 异常则降级为全量扫描。[增量同步与基线策略 ↗](../../../apps/server/src/review/sync.ts#L838 "支持 Git 降级、全量扫描条件、脏状态及文件失败时不推进基线的流程。")

<a id="traceability"></a>
## 从材料捕获到可追溯阅读

知识恢复会重新捕获用户回答和仓库材料、载入已发布文章，并检查回答修订是否已经成为正文依赖；尚未用于重核验的回答会留下 invalidation，明确区分“已保存”和“结论已更新”。[知识恢复与待重核验标记 ↗](../../../apps/server/src/review/knowledge.ts#L9 "证明用户回答恢复后会检查文章依赖，未消费的回答会触发知识失效记录。") HTTP 同步流程随后串联材料同步、知识恢复与代码投影，并以互斥状态拒绝并发同步。[同步端点编排 ↗](../../../apps/server/src/review/app.ts#L316 "支持同步互斥以及材料、知识和代码投影的执行顺序。")

搜索先从当前修订中筛选分类及删除状态符合要求的片段，再把可见集合交给统一检索，保证过滤发生在 top-N 之前。[检索可见性过滤 ↗](../../../apps/server/src/review/app.ts#L289 "证明当前修订、分类和删除状态过滤发生在统一检索的 top-N 之前。") 代码源码阅读则绑定指定或当前快照保存的固定文本；未捕获文件不会回退到实时工作树，历史快照因而可以回到当时的字节与行号。[固定快照源码读取 ↗](../../../apps/server/src/review/app.ts#L397 "支持源码读取绑定快照文本、拒绝工作树回退及行号范围校验。")

<a id="relations"></a>
## 人工关系、派生意图与过期语义

代码到需求、决策、调研和测试的 confirmed 关系只来自人工维护的 association seed，语义相似命中不会自动升级为已确认关系。[人工关联种子合同 ↗](../../../apps/server/src/review/associations.ts#L1 "证明 confirmed 关系只能来自人工列明的 association，而非自动语义相似匹配。") 完整同步为每条 seed 创建 derived、curated 的意图片段，再形成“代码 implements 意图、意图 requires/decided_by/researched_by/tested_by 原始材料”的两级链；定位失败保留为 missing，而不是猜测目标。[两级关系构建流程 ↗](../../../apps/server/src/review/sync.ts#L682 "支持派生意图索引、两级关系链、missing 定位结果及 seed 失效调用。")

关系以确定性 seed identity 幂等 upsert，读取片段关系时会结合另一端是否仍属当前修订、是否已删除计算有效 stale 状态。[关系写入与有效状态 ↗](../../../apps/server/src/review/store.ts#L430 "证明确定性关系身份、幂等端点更新、动态 stale 计算及空 seed 集合的失效例外。") 但全部 seed 被移除时，失效函数因有效集合为空而直接返回；“删除全部 seed 也会自动失效旧边”的旧结论已被替代。关系端点被同一 seed 更新时也不会自然产生独立历史行，历史保留策略仍需明确。

<a id="progress_limits"></a>
## 当前能力、限制与模块协作

模块已分别实现本地访问门禁、统一证据检索、确定性代码图浏览和显式代码理解生成：访问控制由 token 或回环 Host 与本地 Origin 约束。[评审 API 本地访问门禁 ↗](../../../apps/server/src/review/app.ts#L96 "支持 token 校验以及无 token 时回环 Host 和本地 Origin 限制。") 检索通过可见片段集合过滤结果。[统一检索入口 ↗](../../../apps/server/src/review/app.ts#L289 "单独支持模块已实现统一证据检索及查询过滤的能力陈述。") 代码端点提供快照、文件、符号、边和图读取。[确定性代码图读取接口 ↗](../../../apps/server/src/review/app.ts#L343 "支持快照、文件、符号、边、图和既有理解的浏览能力，不依赖模型生成。") 生成入口仅在显式配置模型后可用，失败或校验拒绝不会晋升为当前理解。[显式代码理解生成入口 ↗](../../../apps/server/src/review/app.ts#L576 "支持无模型响应、目标参数检查以及拒绝或传输失败不会晋升当前理解的语义。") 模型配置缺失是正常的无模型状态；配置层只校验来源、JSON 和 transport，不能证明 model、effort 与预算组合已通过后端能力发现。[评审模型配置边界 ↗](../../../apps/server/src/review/model-config.ts#L14 "支持无配置即无模型、损坏配置报错和 transport 白名单，同时界定能力发现不在本模块内。")

当前代码切片与 association symbol 定位仍依赖有限正则及同名 token 回退，并非 AST 级可靠定位；关系构建异常也只写入 warnings，不增加文件失败数，仍会保存同步状态。[同步定位与关系失败限制 ↗](a57f3cbe22aae80c80124eb0110c71ef27faafc8362e44e64de57e9ea8fb6239.md#limits "支持有限正则定位、only 模式边界以及关系构建异常仅写入 warnings 的结论。") 此外，代码路径查询虽然构造了包含当前修订和目标存活条件的 `where`，最终 SQL 默认只直接过滤持久化 `stale`，动态判定出的 stale 仍可能返回；先前“默认排除全部 stale”的结论已被替代。[代码路径关系查询实现 ↗](../../../apps/server/src/review/store.ts#L694 "证明函数构造的完整 where 条件未用于最终 SQL，默认只直接排除持久化 stale。") 关系汇总又把 confirmed、candidate 之外的状态全部计入 missing，因此 stale 与未解析关系会混在同一统计项中。[关系状态汇总实现 ↗](../../../apps/server/src/review/store.ts#L847 "证明汇总结构没有 stale 字段，confirmed 和 candidate 之外的状态均累计到 missing。")

向下，模块依赖共享 Store、知识仓库、检索工厂、知识路由和代码知识服务；向上，它为 Code Wiki 与仓库问答提供固定材料、关系链和快照源码。文章同时写入运行时 staging 与可提交目录，导航索引只展示 current 页面。[知识资产发布与导航索引 ↗](../../../apps/server/src/review/knowledge.ts#L28 "支持文章写入 staging 和发布目录，以及导航只纳入 current 页面。") 应用关闭时会先等待检索服务结束，再关闭隔离 Store。[应用关闭资源回收 ↗](../../../apps/server/src/review/app.ts#L617 "证明正常关闭会等待检索服务停止并关闭评审 Store。")
