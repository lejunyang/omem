# review · 模块理解

review 模块是 omem 在当前仓库上的隔离应用适配层：它把仓库文件捕获为统一、不可变的证据，恢复可追溯知识，构建人工策划的关系链与确定性代码图，并通过本地 HTTP 接口提供检索、浏览、同步和显式模型生成能力。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-boundary"></a>
## 模块定位与运行边界

review 不是独立事实库，而是将 omem 的 Store、捕获、检索和知识能力组合成仓库评审入口；它不装配个人助手、Lark、学习或通知运行时。[评审 HTTP 应用职责 ↗](../../../apps/server/src/review/app.ts#L6 "支持 review 复用统一能力且不启动个人业务运行时的模块定位。") 评审数据写入独立运行目录，不触碰个人工作区 SQLite；评审专用元数据补充来源删除、重命名和旧身份迁移状态。[评审数据隔离与来源元数据边界 ↗](../../../apps/server/src/review/store.ts#L1 "支持评审 Store 使用独立数据目录，并补充来源删除、重命名及旧身份迁移元数据；不用于证明关系状态。") 当前底层仍是单用户 SQLite，团队级权限执行尚未实现，因此 token、回环 Host 与 Origin 检查属于本地访问保护，不能解释为租户隔离。[单用户 SQLite 基础 ↗](../../../apps/server/src/store.ts#L4 "支持当前为单用户存储且团队权限仍待迁移的限制。")

<a id="capture-to-knowledge"></a>
## 从仓库捕获到知识恢复

增量同步以 `omem:<相对路径>` 作为稳定 Source 身份，内容变化追加 revision；它记录真实提交与脏状态，覆盖未提交材料，并在 Git 失败时退化为全量扫描，同时逐文件拒绝路径逃逸、非 UTF-8 与超限输入。[增量捕获与输入安全 ↗](../../../apps/server/src/review/sync.ts#L1 "支持稳定路径身份、工作树覆盖、Git 失败降级和逐文件安全拒绝规则。") 两个 HTTP 同步入口都按“材料同步→知识恢复→代码同步”执行并相互互斥，但 `/sync` 返回材料同步结果，[材料同步 HTTP 入口 ↗](../../../apps/server/src/review/app.ts#L319 "支持 `/sync` 的互斥检查、三个执行阶段以及返回材料同步结果。") `/code/sync` 返回代码同步结果。[代码同步 HTTP 入口 ↗](../../../apps/server/src/review/app.ts#L607 "支持 `/code/sync` 执行相同阶段并返回代码同步结果。")

恢复阶段重新装入用户补充、仓库材料和文章；回答会把问题标为 answered，但若尚未进入目标文章依赖，仍记录待重核验状态。[知识恢复与回答重核验 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持恢复材料和文章、更新回答状态并在依赖未纳入时记录失效。") 派生 revision 被知识仓库排除，不会因总结或意图索引而获得新的原始证据地位。[原始材料筛选规则 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持派生 revision 不被转换为独立知识材料。")

<a id="relations-search-and-code"></a>
## 关系、检索与代码视图

关系图只接受人工维护的 association seed，未登记的语义相似结果不会成为 confirmed。[人工关联种子原则 ↗](../../../apps/server/src/review/associations.ts#L1 "支持关系由人工维护且未登记的相似命中不会升级为确认关系。") 同步把代码片段连接到派生意图片段，再连接需求、决策、调研和测试材料；目标无法定位时保留 missing，确定性种子身份保证重复构建幂等。[评审关系构建流程 ↗](../../../apps/server/src/review/sync.ts#L699 "支持代码到意图及原始依据的边形、missing 处理和幂等构建。") 关系状态存储在 `review_relations` 中；查询会把指向非当前 revision 或已移除来源的关系视为 stale，默认隐藏 stale，同时保留另一端为空的 missing 行。[关系存储与有效状态视图 ↗](../../../apps/server/src/review/store.ts#L506 "支持关系状态由 review_relations 行承载，并说明非当前或已移除目标转为 stale、默认隐藏 stale 及保留 missing 行。")

搜索在 top-N 前筛选当前 head、移除状态和可选类别，再交给统一检索排序；这里实施的是当前性、移除状态与类别过滤，不是用户权限过滤。[检索前材料筛选 ↗](../../../apps/server/src/review/app.ts#L290 "支持检索前按当前 head、移除状态和类别筛选，并明确该范围不包含用户权限。") 代码图则是在已捕获 fragment 上生成的确定性投影；相同输入复用 snapshot，树变化后未重新产生的结构转为 stale。[确定性代码知识投影 ↗](../../../apps/server/src/code/sync.ts#L1 "支持代码图依附已捕获 fragment、相同输入复用快照及未再产生结构转为 stale。") 源码接口读取 snapshot 绑定的固定文本，不回退实时工作树。[固定快照源码读取 ↗](../../../apps/server/src/review/app.ts#L400 "支持源码接口使用 snapshot 固定文本且不回退实时工作树。")

<a id="progress-and-limits"></a>
## 生成能力、已替代结论与限制

模型能力保持显式启用：仓库配置或明确覆盖不存在时即为无模型，配置只开放显式生成，不会在启动时自动推理。[显式模型配置入口 ↗](../../../apps/server/src/review/model-config.ts#L1 "支持仓库级配置、缺省无模型以及配置不会触发启动推理。") 当前材料捕获侧的代码分片基于正则而非完整 AST，允许前导空白，因此嵌套声明也可能形成边界；这替代了“只按顶层声明切分”的旧结论。[正则代码分片边界 ↗](../../../apps/server/src/review/sync.ts#L210 "支持当前捕获侧按允许前导空白的正则切分，而非完整 AST 或严格顶层声明切分。") association 的符号定位会优先声明或方法行，再回退到普通 token，但这种定位不能证明跨文件调用解析能力。[关联符号定位回退 ↗](../../../apps/server/src/review/sync.ts#L581 "支持符号定位优先声明或方法行、随后回退到普通 token 的具体行为。")

关系生命周期仍有明确缺口：有效 association 集合为空时，旧种子关系不会被全量标为 stale；[空种子集合失效边界 ↗](../../../apps/server/src/review/store.ts#L485 "支持有效 association 集合为空时直接返回、不失效旧关系的当前实现。") 汇总又把 confirmed、candidate 以外的状态统一计入 missing，因此 stale 也落入 missing 桶。[关系状态汇总规则 ↗](../../../apps/server/src/review/store.ts#L847 "支持 confirmed、candidate 以外的状态均计入 missing，因此 stale 也进入该桶。") 知识发布依次写入运行期 staging 与可提交目录，现有代码未展示跨目录事务或回滚；这只说明可能出现部分写入，不代表该失败已经被行为测试证实。[知识双目录发布顺序 ↗](../../../apps/server/src/review/knowledge.ts#L35 "支持文章依次写入 staging 和正式目录，并据此说明代码未展示跨目录事务。")
