# review · 模块理解

review 模块把当前仓库接入统一的 Capture→Revision→Fragment→Knowledge 链路，以隔离 SQLite、增量同步、可追溯关系、检索、代码图谱和显式模型生成组成 repo-review 服务。它是仓库输入与 HTTP 编排层，不是独立知识库；过期、缺失或生成失败的结果不能冒充当前事实。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-boundary"></a>
## 定位与运行边界

review 复用通用 Store、捕获和检索能力，但将数据库与运行状态放在 `.repo-review/runtime`，不接入个人工作区、Lark 或学习 worker。[评审存储隔离职责 ↗](../../../apps/server/src/review/store.ts#L1 "支持 review 复用通用能力、使用独立运行目录且不接入个人工作区和业务 worker 的定位。") 进程固定监听回环地址，并在提供 HTTP 服务前依次执行材料同步、知识恢复和代码投影。[评审服务启动顺序 ↗](../../../apps/server/src/review/main.ts#L15 "支持回环监听以及材料同步、知识恢复和代码投影先于 HTTP 服务启动。") 请求配置令牌时校验 Bearer token；未配置时限制 loopback Host 与本地 Origin。[评审请求访问门禁 ↗](../../../apps/server/src/review/app.ts#L97 "支持令牌校验以及无令牌时的 loopback Host 与本地 Origin 限制。") 因此当前实现适合本机单用户评审，不能据此宣称具备租户隔离或任意远程部署能力。

<a id="capture-and-retrieval"></a>
## 材料、知识恢复与检索

增量扫描只遍历固定根目录和根级白名单文件，并按扩展名与文档位置分类；`.repo-review`、依赖、部分构建输出、私有环境文件及指定 fixture 会被排除。[扫描白名单与分类规则 ↗](../../../apps/server/src/review/sync.ts#L94 "支持固定扫描根、根级白名单、目录排除和材料分类规则。") 单文件还须通过真实路径、大小和 UTF-8 校验，随后按正则边界分片并以路径作为稳定来源身份捕获；这不是完整 AST 分片。[单文件校验与捕获 ↗](../../../apps/server/src/review/sync.ts#L427 "支持真实路径、大小、UTF-8、正则分片、内容摘要及共享捕获流程。")

知识恢复先捕获材料再导入文章；文章依赖的材料 digest 或子文章 revision 不一致时才标记 stale。[文章依赖与过期判定 ↗](../../../apps/server/src/knowledge/artifacts.ts#L40 "支持文章恢复时按材料 digest 或子文章 revision 判断 stale。") 用户回答会更新问题状态，但正文尚未依赖该回答的当前 digest 时仍登记待重核验。[知识恢复与回答失效 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持材料捕获、文章恢复、问题回答状态更新以及尚未用于正文时的失效登记。") 这补足并替代了旧稿仅凭恢复入口概括 stale 判定的表述。搜索只使用当前 revision 候选，默认排除 removed，并在 top-N 前应用类别、可见性和路径权重；语义检索未启用时使用关键词检索。[当前证据候选与搜索过滤 ↗](../../../apps/server/src/review/app.ts#L290 "支持检索限定当前 revision、默认排除 removed，并在检索前应用类别、可见性与路径权重。")[关键词与语义检索选择 ↗](../../../apps/server/src/retrieval/factory.ts#L9 "支持未启用配置时使用关键词检索，启用后才启动语义检索及其后台资源。")

<a id="relations-and-code"></a>
## 关系追踪、代码视图与理解结果

关系由人工 association seed 驱动，词义相似但未登记的命中不会自动成为 confirmed。[人工关联种子原则 ↗](../../../apps/server/src/review/associations.ts#L1 "支持关系必须由人工 seed 明确登记，语义相似不会自动成为 confirmed。") 同步构造“代码片段→派生意图片段→需求、决策、调研、测试材料”的确定性关系链，解析不到的端点保留为 missing。[关系链构建流程 ↗](../../../apps/server/src/review/sync.ts#L682 "支持派生意图索引、代码到意图及意图到原始依据的关系形状、确定性身份和 missing 处理。") 读取时还会依据对端是否仍属当前 revision、是否 removed 计算展示状态，默认隐藏 stale 而保留 missing。[关系有效展示状态 ↗](../../../apps/server/src/review/store.ts#L506 "支持依据对端当前性和删除状态计算 stale，以及默认隐藏 stale、保留 missing 的读取规则。")

代码图谱是已捕获 fragment 上的确定性投影；相同输入复用快照，未重现结构转为 stale。[确定性代码投影 ↗](../../../apps/server/src/code/sync.ts#L1 "支持代码图谱依赖已捕获 fragment、快照幂等及旧结构转 stale。") 源码接口读取快照绑定的固定文本，而不是实时工作树。[固定快照源码读取 ↗](../../../apps/server/src/review/app.ts#L400 "支持源码来自快照绑定的固定文本，并对缺失绑定和越界范围显式报错。") 理解列表和详情能够读取 seed 与已保存结果；生成则是另一条显式入口，未配置模型返回不可用，失败或拒绝结果不会晋升为当前理解。[代码理解读取接口 ↗](../../../apps/server/src/review/app.ts#L513 "支持列表和详情接口读取 seed、状态、已保存输出、替代关系、未知项与引用。")[显式代码理解生成 ↗](../../../apps/server/src/review/app.ts#L579 "支持无模型时返回不可用，以及生成失败或拒绝不会晋升为当前理解。") 这替代了旧稿用生成接口单独支持“可读取已保存结果”的不充分论证。

<a id="progress-and-limits"></a>
## 已串联流程与可见限制

应用层分别装配材料与关系查询、检索、同步、代码图谱、固定源码和理解接口；代码同步完成后还可挂载静态站点，关闭时释放检索服务与 Store。[代码同步与资源关闭 ↗](../../../apps/server/src/review/app.ts#L607 "支持代码同步编排、可选静态站点挂载以及关闭时释放检索服务和 Store；其他能力由前文各自引用支持。") 该结论由各流程的就近证据共同支持，而不再把单一关闭片段扩张成全部能力证明。

当前限制包括：符号定位在声明或方法匹配失败后会退化为首个普通词元命中，可能把同名调用或注释当作端点。[符号定位退化规则 ↗](../../../apps/server/src/review/sync.ts#L581 "支持符号定位在声明和方法匹配失败后退化为首个普通词元命中的限制。") 关系重建异常只追加 warning，随后仍持久化并返回同步结果；旧稿错误地用符号定位引用支持这一行为，现已改由实际同步收尾逻辑证明。[关系构建警告与同步返回 ↗](../../../apps/server/src/review/sync.ts#L997 "支持关系构建异常只追加 warning，随后仍形成、持久化并返回同步结果。") 此外，有效 association 集合为空时，旧 seed 关系不会由失效函数自动转为 stale；汇总又把 stale 等非 confirmed、非 candidate 状态计入 missing。[空种子失效边界 ↗](../../../apps/server/src/review/store.ts#L485 "支持有效 association 集合为空时旧 seed 关系不会由该函数自动失效。")[关系状态汇总 ↗](../../../apps/server/src/review/store.ts#L847 "支持汇总只有 confirmed、candidate、missing 三个桶，其他状态会累计到 missing。") 这些语义仍需由接口合同和真实行为测试确认。
