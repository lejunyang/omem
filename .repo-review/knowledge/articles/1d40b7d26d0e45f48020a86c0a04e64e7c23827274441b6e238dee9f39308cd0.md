# review · 模块理解

review 模块把仓库内容接入通用 Capture→Revision→Fragment 知识链，在隔离运行环境中提供增量同步、知识恢复、人工关系投影、固定代码图读取与显式模型生成；其核心边界是本地优先、证据固定、关系来源可追溯且失败不冒充成功。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-boundary"></a>
## 作用与运行边界

review 是仓库评审输入适配器和隔离服务，而非另一套知识系统：它复用 Store、记忆与关键词检索，但不装配助手运行时、Lark、学习或通知 worker，也不持有业务状态。[评审应用职责边界 ↗](../../../apps/server/src/review/app.ts#L5 "支持模块复用通用存储与检索、但不启动个人助手及业务 worker 的运行边界。") 评审 Store 的数据库与 assets 写入 `.repo-review/runtime/data`，同步状态则直接位于 `.repo-review/runtime/`；模型工作区和知识 Agent 工作区也分别使用该运行目录下的专用子目录。[评审 Store 与同步状态目录 ↗](../../../apps/server/src/review/store.ts#L17 "区分数据库及 assets 所在的 runtime/data 与同步状态所在的 runtime 根目录，并支持路径型 source 身份。")[Agent 与知识运行工作区 ↗](../../../apps/server/src/review/app.ts#L73 "支持代码理解模型工作区和知识 Agent 工作区位于 .repo-review/runtime 下，而非 Store 的 runtime/data 目录。") 文件以仓库相对路径形成稳定身份，同一路径修改累积 revision，不同路径即使内容相同也保持独立。默认启动不依赖历史快照，只有 `REVIEW_IMPORT_LEGACY=1` 时才显式播种旧数据。[显式遗留导入开关 ↗](../../../apps/server/src/review/store.ts#L100 "直接支持默认不导入旧快照、仅在遗留导入环境变量为 1 时播种的结论。")

访问控制面向本地单用户运行：未配置令牌时限制回环 Host 和允许的本地 Origin，配置令牌后评审 API 需 Bearer token。[本地请求访问控制 ↗](../../../apps/server/src/review/app.ts#L94 "支持无令牌时的回环 Host 与 Origin 限制，以及配置令牌后的 Bearer 校验。") 这只是本地访问保护，不代表多租户或业务权限隔离。

<a id="capture-sync"></a>
## 从仓库到固定证据

完整同步只遍历固定目录和少量根级白名单，并按路径类别选择代码声明、测试用例或 Markdown 标题边界。[扫描白名单与内容分类 ↗](../../../apps/server/src/review/sync.ts#L94 "支持固定扫描根、根级白名单、排除规则及同步内容类别的判定。") 遍历时遇到符号链接或不安全扫描根会直接跳过，不形成逐文件失败；根级白名单及显式候选进入捕获后，才会因链接越界、不可读、超过预算或无效 UTF-8 被记录为 `failed`，其余文件继续处理。[目录遍历中的链接跳过 ↗](../../../apps/server/src/review/sync.ts#L172 "证明遍历阶段直接跳过符号链接与不安全扫描根，并不会为这些路径建立逐文件失败记录。")[捕获阶段的逐文件失败 ↗](../../../apps/server/src/review/sync.ts#L427 "支持已进入捕获阶段的候选因链接越界、不可读、过大或无效 UTF-8 被记录为失败。") 捕获以路径作为 source 身份，以内容摘要去重，并把 HEAD、dirty 状态、摘要和同步时间写入 revision 上下文。[不可变修订捕获上下文 ↗](../../../apps/server/src/review/sync.ts#L460 "支持路径身份、摘要去重、分片方式和 Git 快照字段写入 revision 上下文。")

完整同步结合 Git HEAD、工作区状态、旧基线和数据库身份选择增量或全量扫描。[Git 增量扫描决策 ↗](../../../apps/server/src/review/sync.ts#L881 "支持依据 HEAD、工作区状态、旧基线和数据库身份选择全量或增量扫描。") dirty 工作区或文件捕获失败会阻止基线推进；关系构建失败目前只追加 warning，不在该阻止条件内。[关系重建与基线推进条件 ↗](../../../apps/server/src/review/sync.ts#L997 "直接支持关系构建失败仅写 warning，以及 dirty 或文件失败阻止基线推进的实际条件。") 启动流程依次执行评审同步、恢复知识材料与文章、更新代码投影，本身不调用模型生成。[评审启动恢复顺序 ↗](../../../apps/server/src/review/main.ts#L17 "展示启动时评审同步、知识恢复和代码投影的执行顺序，并证明没有模型生成调用。")

<a id="knowledge-relations"></a>
## 知识恢复与关系链

知识恢复先重新捕获已保存的用户回答和仓库材料，再恢复发布文章；回答会关闭对应疑问，但若文章依赖尚未纳入该回答的当前摘要，目标知识会被标记为需要重核对。[知识恢复与回答重核对 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持用户回答恢复、文章恢复、疑问关闭及回答尚未纳入文章时的失效标记。") 已移除来源和遗留别名不会进入当前知识材料视图；`.repo-review/` 下的派生知识与运行数据在仓库材料捕获中也被排除，不作为新的独立证据。[派生材料与运行数据排除 ↗](../../../apps/server/src/review/materials.ts#L26 "说明评审目录下的派生知识和历史运行数据不作为新的独立证据，同时展示文件安全检查。")

代码到意图、需求、决策、研究和测试的关系只由人工维护的 association seed 建立，未登记的词语相似命中不会成为 confirmed。[人工关系种子的权威边界 ↗](../../../apps/server/src/review/associations.ts#L1 "支持关系由人工登记，且未登记的语义相似命中不得成为 confirmed。") 同步为每条 seed 创建标明 `derived` 的意图片段，再在当前 head 中定位代码符号和原始材料；无法解析的端点保留为 missing。[派生意图与关系构建流程 ↗](../../../apps/server/src/review/sync.ts#L682 "支持意图索引的派生证据地位、当前 head 定位、关系类型及 unresolved 端点保留为 missing。") 关系使用确定性 ID 并可重复 upsert；查询时派生反向名称，若另一端不再属于当前 head 或来源已移除，有效状态变为 stale，默认读取隐藏 stale 但保留 unresolved missing。[确定性关系写入 ↗](../../../apps/server/src/review/store.ts#L367 "支持前向关系类型、反向名称、稳定关系 ID 和幂等 upsert。")[关系有效状态与双向读取 ↗](../../../apps/server/src/review/store.ts#L506 "支持另一端非当前或已移除时显示 stale、默认隐藏 stale 并保留 unresolved missing。")

<a id="progress-limits"></a>
## 现有能力与限制

材料读取面提供来源、版本、revision、Fragment、关系和搜索接口，搜索在同一 SQL 中限制当前 head、类别与 removed 状态。[材料证据与搜索接口 ↗](../../../apps/server/src/review/app.ts#L191 "支持来源版本、revision、Fragment、关系和搜索读取面，以及搜索对当前材料的 SQL 过滤。") 独立的代码读取面提供仓库、快照、模块、文件、符号、边和图；源码区间严格来自快照绑定文本，缺少绑定或越界时明确失败，不回退到实时工作树。[代码快照与结构图读取面 ↗](../../../apps/server/src/review/app.ts#L412 "支持仓库、快照、模块、文件、符号、边和图接口，并证明源码严格读取快照绑定文本。")

模型配置默认关闭，只从项目配置或显式覆盖路径读取，并在本模块校验 transport 枚举；现有材料尚不能证明具体 model、effort 的能力发现与兼容性拒绝。[评审模型配置入口 ↗](../../../apps/server/src/review/model-config.ts#L1 "支持项目级显式配置、默认无模型、transport 枚举检查和损坏配置报错，并限定现有可证明范围。") 生成只能由专门端点显式触发，无模型时返回不可用，传输或校验失败只记录失败或拒绝结果，不提升为 current。[显式理解生成端点 ↗](../../../apps/server/src/review/app.ts#L645 "支持无模型拒绝、预算参数传递，以及失败或拒绝结果不晋升为当前理解。") 目前仍有两项关系生命周期限制：有效 seed 集合为空时移除失效函数直接返回；关系汇总又把 stale 计入 missing，调用方无法区分历史失效与定位失败。[空种子集合的失效行为 ↗](../../../apps/server/src/review/store.ts#L485 "证明有效 association ID 集合为空时函数直接返回，旧 seed 关系不会在此处统一失效。")[关系汇总状态桶 ↗](../../../apps/server/src/review/store.ts#L847 "证明汇总只暴露 confirmed、candidate 和 missing，并把 stale 等其他状态累计进 missing。")
