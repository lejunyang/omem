# review · 模块理解

review 模块把仓库文件接入通用捕获与知识流程，在隔离存储中提供增量同步、人工关系、知识恢复、固定代码图和可选模型生成，并通过本地 HTTP 接口形成可追溯的仓库评审视图。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-boundary"></a>
## 定位与运行边界

review 是仓库输入适配器与隔离运行入口，而非另一套事实系统：文件捕获后仍交给通用知识流程处理。[仓库材料输入适配器 ↗](../../../apps/server/src/review/materials.ts#L1 "支持 review 只负责生产仓库输入、分析仍由通用知识流程完成的定位。") 评审知识仓库排除已移除来源和遗留别名，避免失效材料继续作为当前知识输入。[评审知识仓库过滤 ↗](../../../apps/server/src/review/materials.ts#L60 "支持当前知识输入会排除已移除来源和遗留别名。") 数据库与资产位于 `.repo-review/runtime/data`；默认不依赖旧快照，只有显式设置遗留导入开关才执行播种。[隔离存储与显式遗留导入 ↗](../../../apps/server/src/review/store.ts#L100 "支持评审 Store 的隔离位置以及只有显式开关才导入旧快照。") HTTP 服务不装配个人助手、Lark、学习或通知 worker；未配置令牌时限制为回环 Host 和本地 Origin，配置令牌后则门控全部评审 API。[评审 API 本地安全边界 ↗](../../../apps/server/src/review/app.ts#L5 "支持服务不装配业务 worker，并采用回环、Origin 或令牌访问控制。")

<a id="capture-sync"></a>
## 从仓库到固定证据

完整扫描只遍历固定目录和根级白名单，并在收集候选时跳过链接、不安全扫描根及排除目录。[扫描目录与候选收集 ↗](../../../apps/server/src/review/sync.ts#L94 "支持固定扫描根、根级白名单、链接跳过及候选分类范围。") 单文件捕获再次检查越界链接、大小与 UTF-8，按类别分片，以仓库相对路径维持 source 身份；内容摘要相同时不创建重复 revision，新 revision 记录提交、dirty 状态和同步时间。[单文件固定捕获 ↗](../../../apps/server/src/review/sync.ts#L427 "支持安全检查、内容摘要去重、分类分片、稳定路径身份及 revision 快照字段。") Git HEAD、基线、工作区变化及上次 dirty 状态共同决定全量或增量范围，Git 异常会扩大扫描而非静默成功。[Git 增量同步决策 ↗](../../../apps/server/src/review/sync.ts#L881 "支持依据 HEAD、基线、dirty 状态、数据库身份与 Git 失败选择增量或全量扫描。") dirty 工作区或文件失败会阻止基线推进；关系重建失败目前只写入 warning，不在该阻止条件内。[关系重建与基线推进条件 ↗](../../../apps/server/src/review/sync.ts#L997 "支持关系异常只形成 warning，以及 dirty 或文件失败才阻止基线推进。")

<a id="knowledge-relations"></a>
## 知识恢复与人工关系链

恢复流程先导入合规的用户回答，再捕获仓库材料并恢复文章。回答会把疑问标为已回答；仅当当前文章尚未精确依赖该回答材料及其 digest 时，正文才被标记为待重核对。文章发布同时写入运行暂存区和可提交目录。[知识恢复与回答持久化 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持回答状态更新、基于精确依赖 digest 的条件化失效，以及文章双位置发布。") 代码关系的权威输入是人工维护的 association seed，不允许仅凭语义相似度产生 confirmed 边。[人工关系种子合同 ↗](../../../apps/server/src/review/associations.ts#L1 "支持 association seed 的人工权威性、禁止语义相似自动确认及其字段结构。") 同步为每条 seed 建立派生意图片段，定位当前 head 中的代码、需求、决策、研究和测试目标，并以确定性身份写入关系；无法定位的端点保留为 missing。[人工关系构建流程 ↗](../../../apps/server/src/review/sync.ts#L699 "支持派生意图索引、当前 head 定位、确定性写入以及无法解析时保留 missing。") 查询可沿代码路径展开代码到意图及下游依据，默认隐藏 stale 历史，但保留 unresolved 关系。[代码路径关系链查询 ↗](../../../apps/server/src/review/store.ts#L680 "支持从代码到意图及需求、决策、研究、测试的链式读取和 stale 过滤语义。")

<a id="api-model-limits"></a>
## 读取面、模型能力与当前限制

基础读取面分别提供 Source 版本、Revision、Fragment、关系与检索，检索只匹配当前 head，并在 SQL 中应用类别和移除状态过滤。[固定证据与搜索接口 ↗](../../../apps/server/src/review/app.ts#L191 "支持 Source、Revision、Fragment、关系接口以及当前 head 内的 SQL 过滤检索。") 代码读取面提供快照、文件、符号、边、图和理解结果；源码严格来自指定快照绑定文本，不回退到实时工作树。[代码图、快照源码与理解读取 ↗](../../../apps/server/src/review/app.ts#L412 "支持快照、文件、符号、边、图和理解结果读取，并证明源码不回退到实时工作树。") 模型只读取项目级配置或显式覆盖路径，默认关闭且不读取个人 profile；当前配置模块仅明确校验传输枚举并把其余字段交给模型端口。[项目级模型配置入口 ↗](../../../apps/server/src/review/model-config.ts#L1 "支持模型配置来源、默认关闭、不读取个人 profile、传输枚举校验及模型端口装配。") 生成必须显式请求，无模型时返回不可用，失败或拒绝结果不会晋升为 current。[显式代码理解生成 ↗](../../../apps/server/src/review/app.ts#L645 "支持无模型时拒绝生成、预算字段传递以及失败结果不晋升为当前理解。") 当前已确认的限制是：空 seed 集合不会触发历史 seed 边失效，[空种子集合的失效限制 ↗](../../../apps/server/src/review/store.ts#L485 "支持有效 seed 集合为空时直接返回，因此历史 seed 边不会由该函数失效。") 且关系重建异常可能与已推进的文件同步基线并存。[关系失败与同步状态持久化 ↗](../../../apps/server/src/review/sync.ts#L997 "支持关系构建失败只记录 warning，而基线仍可能在文件同步成功且工作区干净时推进。")

<a id="superseded-conclusions"></a>
## 被替代结论

旧稿中“所有消失的 seed 都会自动失效”的结论已被更窄的实现事实替代：只有有效 seed 集合非空时，集合外关系才会转为 stale。[空种子集合的失效限制 ↗](../../../apps/server/src/review/store.ts#L485 "支持有效 seed 集合为空时直接返回，因此历史 seed 边不会由该函数失效。") “保存回答必然使正文失效”也被条件化结论替代：文章已经精确依赖同一回答 digest 时不会新增失效记录。[知识恢复与回答持久化 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持回答状态更新、基于精确依赖 digest 的条件化失效，以及文章双位置发布。") 此外，固定材料没有直接证明跨文件 calls 或跨 revision 身份续接的实现状态，因此不再把它们列为已确认限制。
