# 代码高亮行为测试

验证 TypeScript 多行语法状态、按行拆分结果以及已知和未知语言下的 HTML 转义安全性；尚未覆盖全部语言别名、并发加载和复杂嵌套标签。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="tested-behavior"></a>
## 断言覆盖的行为

测试先把包含跨行注释与 TypeScript 声明的源码交给 `highlightCode`，再用 `highlightedLines` 拆成编号行；它断言结果正好有三行，第二行仍处于注释样式，第三行能识别关键字。这证明拆行没有丢失跨行 lexer 样式状态，并覆盖了高亮与逐行展示的组合路径。[跨行注释与关键字测试 ↗](../../../packages/ui/src/highlight.test.ts#L4 "支持多行注释状态在拆行为编号行后仍被保留，以及 TypeScript 关键字被识别的论断。")

另一用例分别传入 `ts` 和未知语言，并以形似 `<img onerror>` 的文本检查输出：两条路径都不得保留真实 `<img` 标签，且必须出现转义后的尖括号。因此测试同时约束了 highlight.js 已知语言输出和未知语言降级分支的基本注入防护。[已知与未知语言转义测试 ↗](../../../packages/ui/src/highlight.test.ts#L11 "支持两类语言输入都不会把恶意标记作为真实 HTML 输出的安全断言。")

<a id="coverage-boundary"></a>
## 覆盖边界

这些断言关注结果片段而非完整 HTML，因此允许高亮库调整无关的标签结构；但它没有验证空输入、大小写语言名、所有别名、XML 所需的多语言加载、并发注册，或不平衡 span 输入的拆行行为。测试也没有挂载真实代码查看器，不能证明行号、复制、滚动或 CSS 主题在浏览器中的表现。当前证据仅能支持两个独立测试用例所列的行为边界。[当前测试文件范围 ↗](../../../packages/ui/src/highlight.test.ts#L1 "用完整测试范围说明现有材料只包含两个用例，从而界定尚未覆盖的行为。")
