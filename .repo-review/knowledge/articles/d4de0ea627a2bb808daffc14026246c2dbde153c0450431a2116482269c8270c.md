# 记住约定，跟进变化：一次活动从保存到提醒

用一个明确标注的阅读小组教学示例，带你走完保存约定、立即找回、确认新版、维护活动说明、继续或切换项目、设置检查提醒，以及在收到外部结果后完成事项。重点说明原文、当前记忆、文章和事项各自解决什么问题，并区分项目事实与个人待办、消息时间与截止及状态有效期、检查时间与完成期限。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="route"></a>
## 先看结果：四种对象，四个用途

保存一条约定后，**原文会立刻可读、可搜索**；当前记忆和活动说明可能稍后才更新。材料中他人的职责、截止和转述不会自动成为你的个人待办；可信用户自己的承诺，或明确要求跟进，才可能提议个人事项。若要在助理中创建、改期、完成或取消事项，仍要由你明确表达操作意图。参考 [项目事实与个人待办分开 ↗](../../../docs/reader-first/project-contexts.md#L49 "说明他人的职责和截止作为项目事实保存，而可信用户自己的承诺或明确跟进请求才可提议个人待办。") [日常助理中的明确交办与修改 ↗](../../../apps/server/src/assistant/message-workflows.ts#L1 "说明讨论、转述和回顾本身不会修改事项，直接记录或修改事项依赖本人明确要求。")

下面用一个教学示例贯穿全文：你把“阅读小组预算 80 元，周日在图书馆集合”保存到“阅读小组”项目；后来沿用同一来源，把预算改为 120 元、集合点保持不变；接着交办“明天上午九点提醒我找组织者确认报名结果”，最后主动告诉助手已经确认并完成事项。这里的金额、地点和报名情节只是示例，不是你个人库中的现实记录。

| 想解决的问题 | 应该看什么 |
| --- | --- |
| 当时原话和以前版本怎么写 | 原文与版本历史 |
| 现在要准备多少钱、去哪里 | 当前记忆；尚未整理好时直接读最新版原文 |
| 多份材料怎样组成完整活动说明 | 知识文章 |
| 下一步何时检查、是否已经完成 | 事项与通知 |

最重要的边界是：**项目事实与个人待办分开**。材料中“组织者负责报名”“周五截止”可以成为可查询、可修订的项目事实，但不会自动变成你的个人事项；你转述他人的任务，也不会把责任转到自己身上。相对地，材料记录了你自己的承诺，或你明确要求系统跟进某个动作时，系统才可以提议属于你的事项。参考 [项目事实与个人待办分开 ↗](../../../docs/reader-first/project-contexts.md#L49 "说明他人的职责和截止作为项目事实保存，而可信用户自己的承诺或明确跟进请求才可提议个人待办。")

<a id="save-find"></a>
## 第一步：保存约定，并立即找回原文

在“输入材料”中填写标题和正文，选择“阅读小组”项目或主题，然后保存。若希望以后修改成为**同一份材料的新版**，请填写并继续使用同一个来源标识；留空会自动分配标识，不适合拿来主动关联下一次更新。界面会直接提示“相同标识产生新版本”。参考 [输入材料、来源标识与项目选择入口 ↗](../../../apps/web/src/App.vue#L909 "支持填写标题正文、复用来源标识产生新版并选择项目或主题的操作。")

保存完成后，页面会刷新并打开实际保存的版本；内容没有变化时会复用原版本。此时你已经可以阅读原文，不必等待后续整理。参考 [保存后打开实际版本 ↗](../../../apps/web/src/App.vue#L423 "支持保存后刷新并打开实际版本，以及内容未变时复用原版本。")

要找回它，可以：

1. 在顶部搜索预算、活动名或集合地点；搜索范围包括材料、讲解、记忆与事项。
2. 打开命中的原文。
3. 或在日常助理中提问，让助理围绕问题补读材料。参考 [统一搜索与助理补读 ↗](../../../apps/web/src/App.vue#L695 "支持搜索材料、讲解、记忆与事项，并让助理补读材料整理回答。")

**“材料已保存”不等于“当前记忆已经整理好”。** 材料处理页会分别显示等待处理、处理完成、候选、已生效、等待判断或失败等可见结果。即使处理步骤已经结束，也要看需要的金额、地点等事实是否真的出现在当前记忆中。若自动处理未启用，原文保存和检索仍然可用，但系统不会自行完成记忆整理；这时直接读最新版原文，或让助理在本次回答中补读。参考 [材料处理的可见结果 ↗](../../../apps/web/src/LearningView.vue#L22 "说明等待、处理完成、候选和已生效是不同结果，不能把任务结束等同于当前记忆已经更新。") [自动处理关闭时原文仍可用 ↗](../../../apps/web/src/LearningView.vue#L81 "说明自动处理关闭时原文保存与检索仍可使用，但页面不会自动开启模型处理。")

项目归属也要明确保存。你可以在输入时选择，也可以稍后到原文的“所属项目与主题”调整；归属适用于这份材料的所有版本，修改归属不会删除原文或历史引用。参考 [原文的项目归属 ↗](../../../apps/web/src/SourceContexts.vue#L16 "说明归属适用于所有版本，且调整归属不会删除原文或历史引用。")

<a id="confirm-change"></a>
## 第二步：约定变化后，逐项确认“现在”

现在把同一来源更新为：“预算 120 元，周日在图书馆集合。”这里有两个操作要点：

1. 继续使用原来的来源标识，让这次保存成为同一材料的新版。
2. 在新版正文中把未变化的集合地点也保留下来，不要只写变化的金额。

随后问日常助理：“**现在我要准备多少钱，去哪里集合？**”金额和地点一起问，是一种核对方法：它能让回答同时检查变化项和未变化项，避免把“预算变了”误解为“所有安排都变了”。

同一来源出现新版后，系统会把新版设为当前原文，使依赖旧版的当前记忆失效，并安排重新检查；旧的 80 元结论不会继续冒充当前结果。参考 [同一来源换版与旧记忆失效 ↗](../../../apps/server/src/store.ts#L240 "支持新版成为来源当前版本、旧依赖失效并安排重新检查。")

如果材料处理还没完成、当前记忆缺少金额或地点，或者自动处理未启用，就直接以最新版原文为准，也可以让助理补读后再回答。想确认以前怎么写，打开原文的“版本历史”：页面会标明“当前版本”和“历史版本”，可以进入任意一版查看。因此旧的 80 元记录仍然可追溯，但回答“现在”时应先依据最新版 120 元。参考 [当前版本与版本历史 ↗](../../../apps/web/src/App.vue#L818 "支持页面区分当前和历史版本，并允许进入任意版本查看。")

还有一种可能：你没有改写旧文件，而是把另一条“预算改为 120 元，地点不变”的新消息明确保存到同一项目。输入来源共同属于唯一项目时，后台可以结合该项目的旧原件和旧记忆，调查这条消息是否在修订已有记忆；同一范围、版本正确并通过复核的明确修订，可以更新同一条记忆。**同项目、内容相似或时间更晚都不等于自动覆盖**：关系不清、有真实矛盾或归属在处理中变化时，结果不应直接应用。参考 [同一项目的新消息可经调查复核修订记忆 ↗](../../../docs/reader-first/project-contexts.md#L41 "说明跨来源消息更新当前记忆所需的唯一项目范围、修订关系、复核与范围稳定条件。")

复核也会区分“会改变这条事实的缺口”和“与这条窄事实无关的旁支疑问”。例如，原文明说“周五截止”，但没有解释完整验收口径：若缺少的口径不改变“存在周五截止约定”这一事实，复核可以判定它不阻塞保存；若连这是哪个项目的截止都不知道，适用范围不明，仍要等待补充。正文有依据、所有疑问都不影响主体、范围、时间、条件或行动授权，并且没有必要背景缺口时，窄事实才可能保存；原始疑问和复核解释仍会留下。最终仍应查看所需事实是否真的出现在当前记忆中。参考 [旁支疑问与必要缺口分开判断 ↗](../../../docs/reader-first/project-contexts.md#L55 "说明不影响窄事实的疑问可在独立复核后不阻塞保存，必要背景、范围和授权缺口仍会阻塞，并保留原始疑问与解释。")

判断“现在”时，还要分开三种时间：**消息何时出现、事情何时到期、某个状态何时开始或停止成立**。“周五交稿”中的周五是截止；周五过去不等于已经交稿，也不会自动证明负责人、地点或规则已经失效。只有原文明说“小周只负责至周五，此后结束”，才明确给出了职责结束时间。旧记录不会因此自动修正；若要确认当前状态，应找后续完成或变更记录，必要时回读最新版原文。参考 [消息时间、截止与状态有效期 ↗](../../../docs/reader-first/project-contexts.md#L61 "说明截止已过不等于事情完成或相关状态自动失效，状态起止必须由原文明确支持。")

<a id="article-update"></a>
## 第三步：决定活动说明怎样跟进变化

当前记忆和活动说明文章不是同一件事：

- **当前记忆**适合快速回答“现在多少钱、在哪里”。保存新版或明确归入项目的变更消息后，系统需要重新调查和核对；是否能自动继续处理，取决于材料处理服务是否启用并运行。
- **活动说明文章**把多份材料组织成一篇完整说明，有自己的选材范围和更新设置。

整理文章时，可以选择“持续跟踪项目或主题”。这样，“阅读小组”项目里的现有材料，以及以后**明确加入**该项目的材料，都会进入文章范围；你仍可另选背景材料。参考 [文章持续跟踪项目材料 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L163 "说明文章可跟踪项目或主题的现有材料及以后加入的材料，并另选背景材料。")

选择整个项目后，其中的材料会随范围整体加入，不能在这篇文章里单独取消某一项。若材料归属错了，到原文调整归属；若文章只需要项目的一部分，就取消跟踪整个项目，改用明确选材。一个材料可以属于多个项目或主题，移出项目不会删除原文或旧文章引用。参考 [项目范围整体加入与明确选材 ↗](../../../docs/reader-first/project-contexts.md#L3 "说明项目材料必须明确归入、整个范围不能逐项取消，以及只需部分材料时应改用明确选材。")

“随所选材料自动更新”默认关闭。开启后，项目中材料新增、移出或换版会让文章重新整理并复核；处理期间旧文章仍可阅读，更新失败时也会保留旧文。**旧文仍可读不代表它已经反映最新材料**，应查看页面显示的维护状态。参考 [文章自动更新的启用条件与失败保留 ↗](../../../docs/reader-first/publication-lifecycle.md#L43 "说明自动更新默认关闭、跟踪明确选材、失败保留旧文以及手动重新整理的规则。") [文章维护状态与旧文保留 ↗](../../../apps/web/src/knowledge/ArticleMaintenance.vue#L31 "说明材料变化后的自动重新整理、复核、状态提示及失败时保留旧文。")

若关闭自动更新，进入“调整材料与目标”，核对选材后点击“保存并重新整理”，即可手动更新同一篇文章。参考 [手动保存并重新整理 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L230 "支持调整选材和目标后手动重新整理同一篇文章。")

这里不要依赖“内容看起来相似”：仅仅保存一条新消息，并不等于它已经属于阅读小组。系统不会从相似标题或正文自动判断归属；应在保存时选择项目，或到原文的“所属项目与主题”补正。即使范围正确，复杂消息里哪些条件被替换仍需要核对，不能把自动整理当作必然正确。参考 [项目范围整体加入与明确选材 ↗](../../../docs/reader-first/project-contexts.md#L3 "说明项目材料必须明确归入、整个范围不能逐项取消，以及只需部分材料时应改用明确选材。")

<a id="project-conversation"></a>
## 第四步：继续谈同一活动，换题时说清对象

连续讨论阅读小组时，可以沿用同一私人会话。系统会保存已经辨认的正式项目，让下一轮先从该项目的材料开始。第一次提到、出现歧义，或切换回来时，直接说“阅读小组”比只说“它”“这次”更稳妥。

换到无关话题时，明确说“换个话题”。系统可以清空当前项目；如果要比较多个项目，也不应把其中一个当作唯一对象。项目只是在检索时缩小阅读起点，**不是事实认证，也不是创建事项的授权**；助手仍可在获准范围内补查其他材料。参考 [会话项目与事项归属 ↗](../../../docs/reader-first/project-contexts.md#L31 "说明会话如何选择或清空项目、项目只是阅读起点，以及新旧事项如何保留各自项目。")

当你在助手里明确交办一个新事项时，它会采用本轮已确认的项目，当前交办原文也会加入该项目。以后即使聊天切到别的项目，对旧事项改期、完成、等待或延后时，事项和相关指令仍保留原项目，不随当前话题迁移。参考 [会话项目与事项归属 ↗](../../../docs/reader-first/project-contexts.md#L31 "说明会话如何选择或清空项目、项目只是阅读起点，以及新旧事项如何保留各自项目。")

会话正在谈哪个项目、材料被保存到哪个项目、文章跟踪哪些材料、事项属于哪个项目，是相关但不同的选择。复杂或含糊时，创建事项后应查看回执和事项列表，确认项目、内容和时间都符合你的原话。

<a id="create-reminder"></a>
## 第五步：把检查提醒与完成期限分开

现在明确交办：“**明天上午九点提醒我找组织者确认报名结果。**”这句话授权创建一条属于你的检查事项，并给出下一次检查时间。它与材料里单纯写着“组织者负责报名”不同：前者是你明确要求跟踪自己的下一步，后者只是项目事实。创建后先核对事项卡片或助手回执中的标题、日期、时间和时区。事项页会把“下次跟进”和“到期时间”分开显示。参考 [项目事实与个人待办分开 ↗](../../../docs/reader-first/project-contexts.md#L49 "说明他人的职责和截止作为项目事实保存，而可信用户自己的承诺或明确跟进请求才可提议个人待办。") [事项页分开展示跟进与到期 ↗](../../../apps/web/src/App.vue#L1006 "支持核对等待对象、下次跟进、时区、到期时间和完成操作。")

这个例子中：

- 明天上午九点是**检查时间**，意思是到时提醒你去确认。
- 它不自动等于“报名必须在九点前完成”。只有你另外明确给出完成期限，才应出现到期时间。
- 如果活动材料另有“周五报名截止”，那是项目约定或事项真正期限，不是这次检查提醒；日期经过也不会自动表示事情已经完成。
- “组织者”出现在行动描述里，也不必自动写成“正在等待组织者回复”。只有你明确说正在等谁或什么结果，才登记等待对象。参考 [检查时间不是完成期限 ↗](../../../packages/contracts/src/assistant.ts#L4 "说明只要求提醒时到期时间为空，新提醒可以没有等待对象，检查时间单独记录。") [消息时间、截止与状态有效期 ↗](../../../docs/reader-first/project-contexts.md#L61 "说明截止已过不等于事情完成或相关状态自动失效，状态起止必须由原文明确支持。")

到检查时间，只要事项仍在进行或等待中，系统会生成站内通知。通知会显示本次触发的检查时间；只有截止也在这次派发中到达且尚未提醒时，才一并显示当前截止时间。若已记录等待对象，通知还会显示等待状态和下一步，并明确不会自动联系他人；同一事项版本的同一触发时刻不会因重复检查而反复提醒。参考 [站内提醒的触发与内容 ↗](../../../apps/server/src/tasks/follow-up.ts#L17 "说明只提醒进行中或等待中的事项；通知按本次触发显示检查时间，并仅在截止也属于本次新触发时显示截止时间，同时记录等待状态、下一步和不自动联系他人的边界。")

<a id="finish"></a>
## 第六步：收到外部结果后，明确完成事项

omem 不会自动监听组织者的回复，也不会替你联系对方。外部结果到达后，需要你主动告诉助手，例如：“**阅读小组报名已经确认，完成这件事。**”当前能力支持交办、等待、改期、完成、取消和站内提醒，但不包含自动监听对方回复。参考 [外部回复仍需用户告知 ↗](../../../docs/reader-first/operations.md#L37 "说明当前支持的事项动作与站内提醒，以及尚未自动监听对方回复。")

看到通知后点“标为已读”，只会清除未读提示；它不会批准变更、完成待办或取消后续提醒。参考 [已读不会完成事项 ↗](../../../apps/web/src/App.vue#L1074 "说明标为已读只清除未读提示，不会完成待办或取消后续提醒。")

真正结束流程，要明确要求完成事项，或在事项页点“标为完成”。完成会把事项状态改为已完成并清除跟进信息；提醒只为仍在进行或等待中的事项生成，因此完成后不会继续提醒。参考 [完成事项并清除跟进 ↗](../../../apps/server/src/memory/service.ts#L102 "支持明确完成命令将事项设为已完成并清除跟进信息。") [站内提醒的触发与内容 ↗](../../../apps/server/src/tasks/follow-up.ts#L17 "说明只提醒进行中或等待中的事项；通知按本次触发显示检查时间，并仅在截止也属于本次新触发时显示截止时间，同时记录等待状态、下一步和不自动联系他人的边界。")

走完这个示例后，可以用一句话判断下一步：**旧话看原文，现状问记忆或读最新版，完整说明看文章，下一步看事项。**
