# 记住约定，跟进变化：一次活动从保存到提醒

用一个明确标注的阅读小组教学示例，带你走完保存约定、立即找回、同源换版、确认当前安排、维护活动说明、继续同一项目、设置检查提醒和完成事项。第一次保存就设置可复用的来源标识，后续保持来源类型和标识一致；同时说明何时看最新版原文、何时相信当前记忆，以及检查时间、截止时间、通知已读和事项完成分别意味着什么。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="save-and-find"></a>
## 先保存，再确认能从哪里找回

下面贯穿全文的是一个**教学示例**，不是你资料库里的现实安排：阅读小组原约定为“预算 80 元，周日在图书馆集合”；后来把预算改为 120 元，集合点不变。你要保存两版约定、问回当前安排，再让 omem 在明天上午九点提醒你确认报名结果。

第一次保存时，进入“输入材料”，选择“文本＋图片＋链接”，把来源类型保持为“主动输入”，并把来源标识明确填成容易复用的 `reading-group-rules`。界面允许来源标识留空自动分配，但本例稍后还要把新安排保存为同一材料的新版本，所以第一次就写下固定标识更稳妥。参考 [主动输入与来源标识 ↗](../../../apps/web/src/App.vue#L895 "支持选择文本输入、将来源类型设为主动输入，以及相同来源标识产生新版本的界面操作。")[留空标识与保存结果 ↗](../../../apps/web/src/App.vue#L447 "支持来源标识留空时临时自动生成、保存后打开实际版本，以及重复内容复用原版本的可见结果。")

填写标题和完整约定，选择“阅读小组”项目，然后点“保存材料与证据”。如果还没有这个项目，可以填写名称、类型和范围说明，再点“创建并选中”。范围说明写清“哪些事情属于这里”，以后继续查这场活动会更容易。参考 [选择或新建项目 ↗](../../../apps/web/src/ContextPicker.vue#L28 "支持保存前选择已有项目，或填写名称、类型和范围说明后创建并选中。")

保存成功后，页面会刷新并打开服务端实际保存的版本；如果内容未改变，页面会提示复用原版本。参考 [留空标识与保存结果 ↗](../../../apps/web/src/App.vue#L447 "支持来源标识留空时临时自动生成、保存后打开实际版本，以及重复内容复用原版本的可见结果。") 此时可以直接读原文，也可以在顶部搜索“阅读小组”。搜索会同时查材料、讲解、记忆与事项，还可以让助理补读材料后围绕问题整理回答。参考 [统一搜索与助理补读 ↗](../../../apps/web/src/App.vue#L695 "支持搜索材料、讲解、记忆与事项，以及让助理补读材料后围绕问题作答。")

但**原文已保存，不等于当前记忆已经整理好**。到“材料处理”看结果：等待处理表示原文已经入库，但整理尚未完成；显示候选记忆时，还要看其中多少条已经应用。即使自动处理没有启用，原文仍可阅读和检索；这时询问现状，应让助理读取最新版原文，而不是把尚未应用的候选记忆当成答案。参考 [原文与处理结果分开 ↗](../../../apps/web/src/LearningView.vue#L23 "支持等待处理、候选记忆应用数量、自动处理未启用时原文仍可保存与检索等判断。")

主线里你已经主动选好了项目。若保存时忘了选择，只有材料处理页后来实际出现“待补充归属”时，才点“选择所属项目或主题”进入对应原文。这个提示不是每次保存后的必经步骤。参考 [待补充归属的可见入口 ↗](../../../apps/web/src/LearningView.vue#L83 "支持只有任务实际带有归属问题时显示待补充状态和进入对应原文的按钮。") 进入原文后，在“所属项目与主题”中选择并保存；调整归属不会删除原文或历史引用，页面若显示已排队，会在后台处理启用后继续整理。参考 [在原文中补充归属 ↗](../../../apps/web/src/SourceContexts.vue#L20 "支持保存材料归属、触发后续整理，以及调整归属不会删除原文或历史引用。")

<a id="update-and-check"></a>
## 预算变化后，同时核对变化项和保留项

收到新安排后，把正文写成一份完整的当前说明，例如：“阅读小组预算 120 元，周日在图书馆集合。”这里把未变化的地点也写进新版，是为了以后能一次核对完整安排；这是一种使用建议，不表示系统会自动从旧版补全你省略的内容。

第二次仍从“文本＋图片＋链接”输入，来源类型仍选“主动输入”，来源标识仍填 `reading-group-rules`。**来源类型和来源标识都要与第一次一致**：服务端用这两项共同找到原来的材料身份，命中后才会在其后生成下一版。参考 [主动输入与来源标识 ↗](../../../apps/web/src/App.vue#L895 "支持选择文本输入、将来源类型设为主动输入，以及相同来源标识产生新版本的界面操作。")[来源类型与标识共同定位材料 ↗](../../../apps/server/src/store.ts#L176 "支持服务端以来源类型和来源标识共同查找既有来源，命中后按当前头版本生成下一版。")

保存后，原文页会把版本标为“当前版本”或“历史版本”，并提供“版本历史”入口。要追溯最初的 80 元就看历史版；要确认现在的安排则看当前版。参考 [当前版本与历史版本 ↗](../../../apps/web/src/App.vue#L819 "支持原文页区分当前版本和历史版本，并提供版本历史入口。")

换版后，系统会让依赖旧版本的记忆退出当前状态，并安排依赖复查。参考 [换版使旧依赖退出当前状态 ↗](../../../apps/server/src/store.ts#L256 "支持材料换版后标记旧依赖、使相应记忆失效并排入依赖复查。") 此时问助理：“阅读小组现在要准备多少钱、去哪里？”按可见处理结果选择依据：

1. 新版已经整理且相应记忆已应用：教学示例中的当前答案应是 **120 元、周日去图书馆**。
2. 新版仍在等待处理，或自动处理未启用：让助理直接补读最新版原文，并说明当前记忆尚未完成更新。参考 [原文与处理结果分开 ↗](../../../apps/web/src/LearningView.vue#L23 "支持等待处理、候选记忆应用数量、自动处理未启用时原文仍可保存与检索等判断。")

把金额和地点放在同一个问题里，可以同时核对“发生变化的预算”和“保持不变的集合点”。旧版仍然有用，但用途是追溯，不应与当前安排混在一起。

<a id="article-maintenance"></a>
## 当前记忆变了，活动说明文章不一定已经变

当前记忆适合回答“现在预算多少、在哪里集合”这类当前事实；活动说明文章则把多份材料组织成一篇可读说明。两者有各自的更新过程，**记忆更新不等于文章已经更新**。

如果希望文章长期跟随“阅读小组”，在调整文章材料时选择“持续跟踪项目或主题”。这样，该项目现有材料和以后明确加入的材料都会进入文章范围；你仍可另选背景材料。参考 [文章持续跟踪项目 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L163 "支持文章纳入所选项目的现有材料和以后加入的材料，并允许另选背景材料。")

接着检查文章上的“随所选材料自动更新”：

- 已开启：项目成员新增、移出或材料换版后，文章会重新整理并复核。
- 未开启：进入“调整材料与目标”，确认选材后点“保存并重新整理”。
- 更新正在排队或失败：旧文章仍可读，但这只表示旧版被保留，不表示它已经反映 120 元；查看维护状态，失败时可点“重试更新”。参考 [文章自动更新状态 ↗](../../../apps/web/src/knowledge/ArticleMaintenance.vue#L31 "支持文章自动更新开关、材料变化后的重整、旧版保留和失败重试。")[手动保存并重新整理 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L289 "支持未开启自动更新时通过同一文章的调整流程手动重新整理。")

项目归属回答“哪些材料属于这场活动”，文章维护开关回答“这些材料变化后是否自动重整文章”。如果打开旧活动说明仍看到 80 元，先看维护状态，再决定等待自动更新或手动重新整理。

<a id="continue-and-remind"></a>
## 继续谈同一活动，再明确交办一次检查

继续提问时，直接说出项目名会更稳妥，例如：“继续说阅读小组，现在还缺什么？”个人会话可以保留已经辨认的项目，后续先从该项目材料中找答案；切换到另一件事时，明确说出新项目或“换个话题”，有歧义时再补充。项目只是找材料的起点，不会自动替你创建事项。参考 [会话中的项目连续性 ↗](../../../docs/reader-first/project-contexts.md#L31 "支持会话保留已辨认项目、切换或清空项目，并说明项目只是阅读起点。")

材料里写了“报名截止”或“组织者负责确认”，保存的是项目事实，不会自动变成你的个人待办。只有你明确要求跟进，系统才应创建或修改事项。参考 [事实不自动成为个人待办 ↗](../../../docs/reader-first/project-contexts.md#L49 "支持只有用户自己的承诺或明确跟进要求才形成个人事项。")

在本例中，可以直接说：

> 明天上午九点提醒我找组织者确认阅读小组报名结果。

创建后核对事项标题、日期、时间和时区。“明天上午九点”是**下次检查时间**；如果你只要求提醒，没有另外给出完成期限，就不应把它保存成截止时间，也不应从活动材料里继承一个截止日期。参考 [提醒时间与截止时间分开 ↗](../../../packages/contracts/src/assistant.ts#L4 "支持仅要求提醒时把时间保存为下次检查，并保持完成期限为空。")

检查时间回答“什么时候回来看看进展”，截止时间回答“事情最晚什么时候完成”。事项页会分别显示下次跟进时间（含时区）和到期时间。参考 [事项页分别显示跟进与到期 ↗](../../../apps/web/src/App.vue#L1037 "支持事项页分别显示下次跟进时间及其时区，并单独显示到期时间。") 到检查点时，omem 会生成站内通知，提醒你检查进展；它不会自动联系组织者。参考 [到点生成站内提醒 ↗](../../../apps/server/src/tasks/follow-up.ts#L20 "支持到点扫描未结束事项并生成站内通知，同时说明不会自动联系他人。")

<a id="finish-followup"></a>
## 收到外部结果后，主动结束跟进

omem 当前不会自动监听组织者的外部回复。报名结果到了以后，你需要主动告诉助手，例如：

> 阅读小组报名已经确认，请完成这件事。

也可以到“需求与待办”中点“标为完成”。当前日常消息支持交办、等待、改期、完成、取消和站内提醒，但外部回复监听尚未提供。参考 [外部回复需要主动告知 ↗](../../../docs/reader-first/operations.md#L37 "支持当前日常事项操作范围，并明确没有自动监听对方回复。")

“通知已读”和“事项完成”是两件事。把通知标为已读只会清除未读提示，不会完成待办，也不会取消后续提醒。参考 [通知已读不等于完成 ↗](../../../apps/web/src/App.vue#L1075 "支持标为已读只清除未读提醒，不会完成待办或取消后续提醒。") 明确完成后，事项会进入已完成状态并清除跟进安排；提醒调度只检查仍在进行或等待中的事项，因此后续不再提醒。参考 [完成会清除跟进安排 ↗](../../../apps/server/src/memory/service.ts#L118 "支持明确完成后把事项设为已完成并清除跟进信息。")[只提醒未结束事项 ↗](../../../apps/server/src/tasks/follow-up.ts#L20 "支持提醒调度只扫描进行中或等待中的事项，因此完成后不会继续触发。")

回顾这条路线：**找旧说法看历史原文，确认现状看最新版原文或已应用的当前记忆，阅读完整说明看文章，推进下一步看事项。** 不必预先背诵这四类对象；在一次活动里按需要使用即可。
