# 记住约定，跟进变化：一次活动从保存到提醒

用一个明确标注的阅读小组教学示例，带你走完保存约定、立即找回、确认新版、维护活动说明、继续或切换项目、设置检查提醒，以及在收到外部结果后完成事项。重点说明原文、当前记忆、文章和事项各自解决什么问题，以及自动处理或自动更新未启用时该怎样判断当前状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="route"></a>
## 先看结果：四种对象，四个用途

保存一条约定后，**原文会立刻可读、可搜索**；当前记忆和活动说明可能稍后才更新；只有你明确交办，系统才会创建事项。

下面用一个教学示例贯穿全文：你把“阅读小组预算 80 元，周日在图书馆集合”保存到“阅读小组”项目；后来沿用同一来源，把预算改为 120 元、集合点保持不变；接着交办“明天上午九点提醒我找组织者确认报名结果”，最后主动告诉助手已经确认并完成事项。这里的金额、地点和报名情节只是示例，不是你个人库中的现实记录。

| 想解决的问题 | 应该看什么 |
| --- | --- |
| 当时原话和以前版本怎么写 | 原文与版本历史 |
| 现在要准备多少钱、去哪里 | 当前记忆；尚未整理好时直接读最新版原文 |
| 多份材料怎样组成一份完整活动说明 | 知识文章 |
| 下一步何时检查、是否已经完成 | 事项与通知 |

最重要的边界是：**材料里的事实不是行动授权**。保存或转述“需要提醒”不会自动生成你的待办；你在当前消息中明确要求记录、提醒、改期或完成，才会改变事项。参考 [明确交办才会改变事项 ↗](../../../apps/server/src/assistant/message-workflows.ts#L1 "说明讨论、转述与当前用户明确交办的权限边界，以及已读不等于完成。")

<a id="save-find"></a>
## 第一步：保存约定，并立即找回原文

在“输入材料”中填写标题和正文，选择“阅读小组”项目或主题，然后保存。若希望以后修改成为**同一份材料的新版**，请填写并继续使用同一个来源标识；留空会自动分配标识，不适合拿来主动关联下一次更新。界面也会直接提示“相同标识产生新版本”。参考 [输入材料、来源标识与项目选择入口 ↗](../../../apps/web/src/App.vue#L891 "支持填写标题正文、复用来源标识产生新版并选择项目或主题的操作。")

保存完成后，页面会刷新并打开刚保存的版本；内容没有变化时会复用原版本。此时你已经可以阅读原文，不必等待后续整理。参考 [保存后打开当前版本 ↗](../../../apps/web/src/App.vue#L447 "支持保存后刷新并打开该版本，以及内容未变时复用原版本。")

要找回它，可以：

1. 在顶部搜索预算、活动名或集合地点；搜索范围包括材料、讲解、记忆与事项。
2. 打开命中的原文。
3. 或在日常助理中提问，让助理围绕问题补读材料。参考 [统一搜索与助理补读 ↗](../../../apps/web/src/App.vue#L695 "支持搜索材料、讲解、记忆与事项，并让助理补读材料整理回答。")

**“材料已保存”不等于“当前记忆已经整理好”。** 保存后，材料处理页会显示它是在等待处理、已有候选，还是已有结果实际生效。若自动处理未启用，原文保存和检索仍然可用，但系统不会自行完成记忆整理；这时确认安排应直接读原文，或让助理在本次回答中补读，不能只凭“保存成功”断言当前记忆已经更新。参考 [保存状态与自动处理限制 ↗](../../../apps/web/src/LearningView.vue#L20 "说明已保存原文、等待处理、候选应用结果，以及自动处理关闭时原文仍可保存和检索。")

项目归属也要明确保存。你可以在输入时选择，也可以稍后到原文的“所属项目与主题”调整；归属适用于这份材料的所有版本，修改归属不会删除原文或历史引用。参考 [原文的项目归属 ↗](../../../apps/web/src/SourceContexts.vue#L16 "说明归属适用于所有版本，且调整归属不会删除原文或历史引用。")

<a id="confirm-change"></a>
## 第二步：约定变化后，逐项确认“现在”

现在把同一来源更新为：“预算 120 元，周日在图书馆集合。”这里有两个操作要点：

1. 继续使用原来的来源标识，让这次保存成为同一材料的新版。
2. 在新版正文中把未变化的集合地点也保留下来，不要只写变化的金额。

随后问日常助理：“**现在我要准备多少钱，去哪里集合？**”金额和地点一起问，能避免把“预算变了”误解为“所有安排都变了”。

同一来源出现新版后，系统会把新版设为当前原文，并使依赖旧版的当前记忆失效，随后安排重新检查；旧的 80 元结论不会继续冒充当前结果。只有新版经过处理并实际应用后，当前记忆才算推进到新版本。参考 [同一来源换版与旧记忆失效 ↗](../../../apps/server/src/store.ts#L176 "支持相同来源形成新版本，并在换版后使依赖旧版的记忆失效、安排重新检查。") [记忆应用保留版本与依据 ↗](../../../apps/server/src/storage/repository.ts#L403 "支持只有实际应用后记忆才推进版本，并保留前版关系和新依据。")

如果材料处理还没完成，或自动处理未启用，直接以最新版原文为准。想确认以前怎么写，打开原文的“版本历史”：页面会标明“当前版本”和“历史版本”，可以进入任意一版查看。因此旧的 80 元记录仍然可追溯，但回答“现在”时应以最新版 120 元为依据。参考 [当前版本与版本历史 ↗](../../../apps/web/src/App.vue#L818 "支持页面区分当前和历史版本，并允许进入任意版本查看。")

<a id="article-update"></a>
## 第三步：决定活动说明怎样跟进变化

当前记忆和活动说明文章不是同一件事：

- **当前记忆**适合快速回答“现在多少钱、在哪里”。保存新版后，系统会重新核对；是否能继续自动处理，取决于材料处理服务是否启用并运行。
- **活动说明文章**把多份材料组织成一篇完整说明，有自己的选材范围和更新设置。

整理文章时，可以选择“持续跟踪项目或主题”。这样，“阅读小组”项目里的现有材料，以及以后**明确加入**该项目的材料，会进入文章范围；你仍可另选背景材料。参考 [文章持续跟踪项目材料 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L169 "说明文章可跟踪项目或主题的现有材料及以后加入的材料，并另选背景材料。")

若开启“随所选材料自动更新”，项目中材料新增、移出或换版后，文章会重新整理并复核，期间旧文章仍可阅读；更新失败时旧文章也会保留。若关闭自动更新，进入“调整材料与目标”，核对选材后点击“保存并重新整理”即可手动触发。参考 [文章自动更新与失败保留 ↗](../../../apps/web/src/knowledge/ArticleMaintenance.vue#L31 "说明材料变化后的自动重新整理、复核、旧版可读及失败保留旧文。") [手动保存并重新整理 ↗](../../../apps/web/src/knowledge/ArticleComposer.vue#L230 "支持调整选材和目标后手动重新整理同一篇文章。")

这里不要依赖“内容看起来相似”：仅仅保存一条新消息，并不等于它已经属于阅读小组。系统尚不会从相似标题或正文自动判断归属；应在保存时选择项目，或到原文的“所属项目与主题”补正。参考 [项目归属不会从相似内容自动产生 ↗](../../../docs/reader-first/project-contexts.md#L3 "说明项目材料必须明确归入，文章范围和自动更新如何工作，以及内容相似不会自动建立归属。")

<a id="project-conversation"></a>
## 第四步：继续谈同一活动，换题时说清对象

连续讨论阅读小组时，可以沿用同一私人会话。系统会保存已经辨认的正式项目，让下一轮先从该项目的材料开始。第一次提到、出现歧义，或切换回来时，直接说“阅读小组”比只说“它”“这次”更稳妥。

换到无关话题时，明确说“换个话题”。系统可以清空当前项目；如果要比较多个项目，也不应把其中一个偷偷当作唯一对象。项目只是在检索时缩小阅读起点，**不是事实认证，也不是创建事项的授权**。参考 [会话项目只缩小阅读起点 ↗](../../../docs/reader-first/project-contexts.md#L31 "说明会话如何保存、切换或清空项目，并强调项目不是权限或事实更新。")

项目身份还会保护事项归属：新事项采用本轮已确认的项目；以后即使聊天切到别的项目，修改、延期或完成原事项时，仍保留事项自己的原项目。参考 [事项保持自己的项目 ↗](../../../apps/server/src/storage/repository.ts#L559 "支持新事项采用本轮项目、旧事项修改仍保留原项目。")

这仍不代表所有新消息都会自动归入阅读小组。会话正在谈哪个项目、材料被保存到哪个项目、文章跟踪哪些材料，是相关但不同的选择。复杂或含糊的场景中，创建事项后应查看回执和事项列表，确认项目、内容和时间都符合你的原话。

<a id="create-reminder"></a>
## 第五步：把检查提醒与完成期限分开

现在明确交办：“**明天上午九点提醒我找组织者确认报名结果。**”这句话授权创建一条事项，并给出下一次检查时间。创建后先核对事项卡片或助手回执中的标题、日期、时间和时区。事项页会把“下次跟进”和“到期时间”分开显示。参考 [事项页分开展示跟进与到期 ↗](../../../apps/web/src/App.vue#L1006 "支持核对等待对象、下次跟进、时区、到期时间和完成操作。")

这个例子中：

- 明天上午九点是**检查时间**，意思是到时提醒你去确认。
- 它不自动等于“报名必须在九点前完成”。只有你另外明确给出完成期限，才应出现到期时间。
- “组织者”出现在行动描述里，也不必自动写成“正在等待组织者回复”。只有你明确说正在等谁或什么结果，才登记等待对象。参考 [检查时间不是完成期限 ↗](../../../packages/contracts/src/assistant.ts#L4 "说明只要求提醒时到期时间为空，新提醒可以没有等待对象，检查时间单独记录。")

到检查时间，只要事项仍在进行或等待中，系统会生成站内通知。通知会说明当前检查时间、真正的截止时间（若有）、等待对象（若有）和下一步，并明确不会自动联系他人；同一事项版本的同一时刻不会因重复检查而反复提醒。参考 [站内提醒的触发与内容 ↗](../../../apps/server/src/tasks/follow-up.ts#L17 "说明只提醒进行中或等待中的事项、去重方式、通知内容及不会自动联系他人。")

<a id="finish"></a>
## 第六步：收到外部结果后，明确完成事项

omem 不会自动监听组织者的回复，也不会替你联系对方。外部结果到达后，需要你主动告诉助手，例如：“**阅读小组报名已经确认，完成这件事。**”当前能力支持交办、等待、改期、完成、取消和站内提醒，但不包含自动监听对方回复。参考 [外部回复仍需用户告知 ↗](../../../docs/reader-first/operations.md#L37 "说明当前支持的事项动作与站内提醒，以及尚未自动监听对方回复。")

看到通知后点“标为已读”，只会清除未读提示；它不会批准变更、完成待办或取消后续提醒。参考 [已读不会完成事项 ↗](../../../apps/web/src/App.vue#L1074 "说明标为已读只清除未读提醒，不会批准变更、完成待办或取消后续提醒。")

真正结束流程，要明确要求完成事项，或在事项页点“标为完成”。完成会把事项状态改为已完成并清除跟进信息；提醒只为仍在进行或等待中的事项生成，因此完成后不会继续提醒。参考 [完成事项并清除跟进 ↗](../../../apps/server/src/memory/service.ts#L102 "支持明确完成命令将事项设为已完成并清除跟进信息。") [站内提醒的触发与内容 ↗](../../../apps/server/src/tasks/follow-up.ts#L17 "说明只提醒进行中或等待中的事项、去重方式、通知内容及不会自动联系他人。")

走完这个示例后，可以用一句话判断下一步：**旧话看原文，现状问记忆或读最新版，完整说明看文章，下一步看事项。**
