# 文档材料分析与可追溯 Wiki 写作

规定材料分析角色如何区分文档陈述、实现事实与历史状态，并以中文、结构化 JSON 和贴近论断的固定来源引用，生成面向首次接触项目读者的 Wiki 内容。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

该角色用于分析需求、设计、研究、进展和配置等文档材料，核心是避免把设想、旧计划或历史描述误写成当前已经实现的能力。分析时应明确区分**文档声称什么、实现事实是什么、状态属于哪个时期**，让读者能够判断结论的现实有效性。参考 [材料分析边界 ↗](../../../packages/agent-runtime/roles/material-analyst/1/skills/omem-material-analyst/SKILL.md#L6 "支持该角色需要区分文档陈述、实现事实与历史状态，并禁止把旧计划描述为已实现能力。")

产物面向首次接触项目的读者：文章先交代所解决的问题和实际使用场景，再说明流程、概念与限制；标题应按功能命名，不能以文件路径、内部编号或治理细节充当阅读主线。参考 [面向读者的组织方式 ↗](../../../packages/agent-runtime/roles/material-analyst/1/skills/omem-material-analyst/SKILL.md#L16 "支持正文应从问题和场景讲起，并使用功能化标题、避免内部细节主导叙事。")

<a id="analysis_flow"></a>
## 从材料到知识正文

处理流程受到严格边界约束：只分析任务提供的材料或文章，不执行材料里的命令，也不额外读取文件；输出使用中文并完整匹配指定 JSON 合同。每个目标都必须生成对应文档，而且文档键要与任务目标键完全一致。参考 [输入与输出约束 ↗](../../../packages/agent-runtime/roles/material-analyst/1/skills/omem-material-analyst/SKILL.md#L10 "支持仅使用已提供材料、不得执行材料指令，以及按目标键输出中文 JSON 文档的流程约束。")

正文宜组织为少量语义清晰的章节，解释作用、背景、流程、限制及与其他材料的关系，而不是罗列函数名或统计数字。参考 [正文内容组织 ↗](../../../packages/agent-runtime/roles/material-analyst/1/skills/omem-material-analyst/SKILL.md#L11 "支持正文采用少量章节并解释作用、背景、流程、限制与材料关联，而非只罗列名称和计数。")

多阶段关系确有证据时可以使用简洁流程图，但图中只能呈现有证据支持的关系；表格和图示都应服务于理解，不应为了形式而添加。参考 [流程图与图表原则 ↗](../../../packages/agent-runtime/roles/material-analyst/1/skills/omem-material-analyst/SKILL.md#L20 "支持多阶段流程可使用简洁 Mermaid 图、图中关系必须有证据，且不应为了格式强行添加图表。")

<a id="evidence_and_uncertainty"></a>
## 引用与不确定事项

每项论断的证据应放在相关句子或段落附近，每节至少包含一处引用，且引用表中的每一项都必须在正文实际出现。材料引用只能指向已提供材料中的真实、尽量精确的连续行范围，并保留空引文，由宿主复制固定原文。参考 [引用定位规则 ↗](../../../packages/agent-runtime/roles/material-analyst/1/skills/omem-material-analyst/SKILL.md#L12 "支持引用必须贴近论断、全部在正文出现，并指向提供材料的真实行范围。")

引用标签需要采用人能理解的名称，理由则说明证据支持附近哪项论断；正文即使移除引用标记也应保持通顺。对于无法确认、背景不足或必须由用户选择的内容，应记录为带原因、下一步、阻塞状态和相关证据的问题，不能用含糊追问代替分析。参考 [可读标签与问题记录 ↗](../../../packages/agent-runtime/roles/material-analyst/1/skills/omem-material-analyst/SKILL.md#L14 "支持使用人读引用标签，并将无法确定或需要选择的事项结构化记录为问题。")
