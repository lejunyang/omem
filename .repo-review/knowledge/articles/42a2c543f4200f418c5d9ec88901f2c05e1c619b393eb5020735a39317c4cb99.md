# 运行环境、依赖管理与部署边界

记录 2026-09-26 的 Node/SQLite 运行基线、osdk 实测、容器诊断以及前台部署和备份要求；这些结论是当时快照，不代表当前主机状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="runtime"></a>
## 轻量运行基线

首版采用 Node 24、Vue、Fastify、官方 ACP SDK 与内置 SQLite，依赖由 osdk 管理。普通 Web/API、宿主 CLI、飞书材料及 Git/文本输入均不要求 Docker，也不下载本地大模型；SQLite 是个人模式的明确选择，不能把未来 PostgreSQL、多用户 ACL 或混合索引理解为仅替换连接串。[首版运行栈与数据库取舍 ↗](../../../docs/implementation/environment.md#L3 "支持 Node/Vue/Fastify/SQLite 基线、Docker非必需以及个人模式数据库边界。")

WeKnora 与 Hindsight 是尚未部署的可选引擎，需要额外服务、数据库及模型配置。模型只能经 CLI/ACP 使用时，应先建设统一推理入口或经过验证的适配器，不能把 CLI 命令直接冒充 OpenAI endpoint。[外部知识引擎接入限制 ↗](../../../docs/implementation/environment.md#L14 "解释 WeKnora、Hindsight 的额外依赖，以及 CLI/ACP 不能直接冒充通用模型 API。")

<a id="operations"></a>
## 运行、持久化与备份

开发、构建和生产均通过 osdk 脚本启动，生产进程保持前台以交给 supervisor 或 systemd 管理。数据目录应持久化并限制读取权限；SQLite 备份需使用在线备份 API，或停服后完整复制并包含 WAL 状态，图片 assets 也必须一并保存。[长期运行与备份要求 ↗](../../../docs/implementation/environment.md#L33 "支持前台运行、环境配置、SQLite/WAL 及图片资产备份要求。")

仓库提供的 systemd 和环境文件只是部署模板，并未安装系统服务；记录时进程仅监听本机端口，可通过 SSH 隧道远程访问，不承诺开机自启、容器编排或 PostgreSQL PITR。[systemd 模板与监听状态 ↗](../../../docs/implementation/environment.md#L39 "支持模板未安装、本机监听、SSH 隧道及未配置开机自启等限制。")
