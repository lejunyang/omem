# CodeUnderstanding 严格合同与引用校验测试

验证代码理解角色资产、密封输出、确定性引用检查、无模型 seed 降级及独立核验语义，防止幻觉引用或人工 seed 冒充模型成果。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="contract-validation"></a>
## 角色合同与确定性校验

测试以包含文件、符号、调用/导入边和决策证据的自洽快照作为固定事实集，再构造带 prompt、schema、input 三类摘要的完整输出。[自洽代码快照与密封输出 ↗](../../../apps/server/tests/code-understanding.test.ts#L25 "支持测试以固定文件、符号、关系、证据和摘要构造有效基线的说明。") 角色注册表只允许四个代码理解角色，检查输出合同、上下文与输出预算、技能内容和摘要格式，并拒绝白名单外角色。[代码角色白名单与资产摘要 ↗](../../../apps/server/tests/code-understanding.test.ts#L94 "支持四类允许角色、预算和摘要检查以及白名单拒绝行为。") 校验器既执行严格结构解析，也逐层检查节点、边、证据、文件和行范围；顶层引用或 claim 内嵌引用只要不存在即被拒绝，三类密封摘要不一致也会失败，从而把模型叙述绑定到特定角色资产与代码快照。[引用与密封摘要校验 ↗](../../../apps/server/tests/code-understanding.test.ts#L151 "证明未知节点、边、证据、越界选择器和摘要不匹配会被确定性拒绝。")

<a id="seed-verification-boundaries"></a>
## Seed 降级、核验语义与覆盖边界

无模型时允许生成仅含骨架的 seed，但它必须声明无模型、未经代理核验且状态为 seed；普通 generated 输出不能借无模型路径通过。[无模型 Seed 降级 ↗](../../../apps/server/tests/code-understanding.test.ts#L229 "支持无模型只接受受限 seed、拒绝普通生成结果的结论。") 测试进一步禁止 seed 携带解释性主张或自称已核验，并要求真正的 verified 输出填写核验代理身份；符合条件的独立核验结果才被接受。[Seed 与独立核验边界 ↗](../../../apps/server/tests/code-understanding.test.ts#L254 "支持 seed 不得携带解释或自我核验，以及 verified 结果必须声明核验者。") 临时角色目录还证明超出清单预算的 manifest 会被加载器拒绝。[角色预算保护 ↗](../../../apps/server/tests/code-understanding.test.ts#L307 "支持角色 manifest 超出节点预算时加载失败的说明。") 尚未覆盖实际模型调用、数据库持久化、HTTP 状态映射、跨 revision 身份续接，以及多个代理之间如何调度独立复核；本文件验证的是运行时合同和纯校验行为，而非外部 CLI 或模型质量。
