# CodeUnderstanding 角色资产与确定性校验测试

验证代码理解角色白名单、资产摘要、严格输出结构、引用范围、seed 降级样例，以及 agent 验证标记与角色预算守卫。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="roles_schema"></a>
## 角色资产与封存契约

测试以包含文件、符号、边和决策证据的自洽快照构造封存输出。注册表只允许四种角色，要求输出契约为 `CodeUnderstanding.v1`，并检查现有四个合法角色的 context token 均不少于 256、output token 均不少于 128，同时验证摘要格式和 skill 装载；这些断言描述现有资产，不能单独推出 schema 的通用下限。[角色白名单与资产摘要 ↗](../../../apps/server/tests/code-understanding.test.ts#L94 "支持四个允许角色、输出契约、现有资产的 token 预算取值、摘要及 skill 装载规则，但不把样例取值提升为 schema 边界。") 严格结构接受完整结果，而当前失败样例实际只加入未知字段，没有独立验证错误角色。[严格结构成功与未知字段失败 ↗](../../../apps/server/tests/code-understanding.test.ts#L127 "支持完整封存输出成功及加入未知字段后失败，并界定该反例没有实际修改角色字段。")

<a id="reference_validation"></a>
## 引用与摘要校验

确定性校验将叙述约束到输入快照：未知节点、边或证据，越界 selector、未知文件，以及 claim 内嵌的虚构节点都会被拒绝；prompt、schema 或 input 任一摘要不匹配也失败。[确定性引用和摘要校验 ↗](../../../apps/server/tests/code-understanding.test.ts#L151 "支持虚构引用、越界选择器、未知文件、claim 内引用及三类 digest 不匹配被拒绝。") 这些检查证明引用存在性、位置范围和输入封存关系，却不能单独证明自然语言论断在语义上受到材料支持。

<a id="seed_verification"></a>
## seed 降级与验证语义

已测试的成功样例是构建器生成的 seed 骨架在无模型时通过；失败样例包括无模型时提交普通 generated 输出、seed 携带 interpretation claim，以及 seed 冒充 agent 验证。材料没有证明所有由其他方式构造但满足契约的 seed 都会失败，因此此前“只能接受构建器生成”的结论被替代。[seed 与无模型降级样例 ↗](../../../apps/server/tests/code-understanding.test.ts#L229 "支持构建器 seed 成功，以及普通 generated 输出、带解释性 claim 的 seed 和冒充 agent 验证的 seed 失败。") 对生成结果，`verified_by_agent=true` 要求非空 `verified_by`，填写 `relation-verifier@1` 的样例可通过。[验证者字段要求 ↗](../../../apps/server/tests/code-understanding.test.ts#L282 "支持 agent 验证标记要求 verified_by，并记录一个可通过但未证明角色独立性的示例。") 但生成 bundle 同样属于 relation-verifier，尚不能证明验证者必须不同、属于白名单或匹配版本。

<a id="budget_guard"></a>
## 角色预算守卫的实际证据

临时 manifest 测试只断言整个角色资产装载失败，没有检查具体错误。该反例同时设置 `max_context_tokens=100` 与 `max_referenced_nodes=5`，而前一节仅说明现有合法角色的 token 取值，并未证明 256 是 schema 下限；因此失败不能被可靠归因于任一单独字段，此前关于“100 违反已证实下限”的结论被替代。[临时坏 manifest ↗](../../../apps/server/tests/code-understanding.test.ts#L307 "证明同时改变 token 与节点预算的临时角色资产装载失败且未断言具体错误，因而反驳将失败归因于单一字段的结论。") 若要确认节点预算边界，需要保持其他字段合法并逐一测试边界值与错误原因。
