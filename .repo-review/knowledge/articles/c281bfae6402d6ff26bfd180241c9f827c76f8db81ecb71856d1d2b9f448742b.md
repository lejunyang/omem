# Code Understanding 合同与校验器测试

该测试以固定代码快照和可控输出为基准，验证代码理解角色资产的白名单、预算与摘要封印，以及输出对节点、边、证据、seed 降级和独立复核状态的约束。它证明确定性合同校验的行为，但不证明真实模型、外部 Agent CLI 或完整 AST 生成链路可用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-fixture"></a>
## 解决的问题与测试基准

该文件为 `CodeUnderstanding.v1` 建立可重复的合同测试：先构造包含两个文件、三个符号、两条关系边和一条决策证据的最小快照，再由 `validOutput` 生成与角色提示、Schema 及输入快照摘要绑定的合法结果。各用例随后通过定点构造无效字段或引用来验证约束；部分场景会同时修改多个相关集合，因此不能把所有失败都理解为严格的单字段变异。[最小代码快照与合法输出夹具 ↗](../../../apps/server/tests/code-understanding.test.ts#L25 "支持测试基准由固定文件、符号、边和证据组成，并说明合法输出可通过 patch 定点构造无效字段；相关用例也显示某些场景会同时修改多个集合。")

测试直接使用 agent-runtime 暴露的角色注册表、稳定摘要、seed 构造器和验证器，检查的是运行时公开合同，而非服务端另写的一套等价逻辑。[agent-runtime 代码理解接口导入 ↗](../../../apps/server/tests/code-understanding.test.ts#L4 "说明测试直接依赖代码理解运行时公开的注册表、Schema、摘要、seed 和验证接口。")

<a id="validation-flow"></a>
## 核心校验流程与断言

角色资产部分确认四种白名单角色可加载，并检查输出合同、上下文与输出预算下限、提示和 Schema 摘要、技能内容及 bundle 摘要的稳定性；白名单外角色会被明确拒绝。[角色白名单与资产摘要测试 ↗](../../../apps/server/tests/code-understanding.test.ts#L94 "支持四种允许角色、预算下限、技能装载、稳定摘要以及白名单拒绝等断言。")

输出验证覆盖严格 Schema、固定快照交叉引用和摘要封印：未知节点、边或证据，越界或未知文件的 selector，以及 claim 内不存在的节点都会失败；输入、提示或 Schema 摘要不一致也会被拒绝。[引用与 selector 确定性校验 ↗](../../../apps/server/tests/code-understanding.test.ts#L151 "支持未知节点、边、证据以及越界和未知文件 selector 会被拒绝的论断。") [摘要封印与 claim 内引用校验 ↗](../../../apps/server/tests/code-understanding.test.ts#L191 "支持输入、提示和 Schema 摘要不匹配，以及 claim 内虚构节点引用会触发拒绝。")

模型不可用时，只允许 `buildSeedOutput` 产生的 seed 骨架通过；普通 generated 输出、包含解释性 claim 的 seed，以及冒充代理复核的 seed 均失败。对于非 seed 结果，`verified_by_agent` 为真时必须给出复核者，材料也展示了填写独立复核者后可通过的路径。[无模型 seed 降级规则 ↗](../../../apps/server/tests/code-understanding.test.ts#L229 "支持无模型时合法 seed 可通过，而 generated 输出、解释性 seed 和冒充复核的 seed 会失败。") [独立代理复核状态测试 ↗](../../../apps/server/tests/code-understanding.test.ts#L282 "支持代理复核状态必须带复核者，并展示正确填写独立复核者的输出可以通过。")

<a id="boundaries-and-coverage"></a>
## 边界条件、模块关系与未覆盖行为

最后一组用例在临时角色目录写入一套未通过 manifest Schema 的资产并断言加载抛错，随后递归清理临时目录。该夹具同时包含较低的上下文预算等字段，且断言没有核对具体错误原因；因此它只能证明这份 manifest 会被拒绝，不能单独证明 `max_referenced_nodes: 5` 超出节点预算，也不能视为节点预算上限的精确覆盖。[无效角色 manifest 加载测试 ↗](../../../apps/server/tests/code-understanding.test.ts#L307 "支持临时角色资产加载会抛错及目录清理行为；断言未限定具体错误，因此仅能证明该 manifest 未通过加载。")

运行时说明表明该模块刻意自包含，只负责固定快照、版本化输出合同、角色资产装载和确定性交叉引用校验；它不调用真实模型，并通过独立摘要实现避免耦合存储层。故本文件能够证明 fixture 与验证规则协同工作，却不能证明外部 Agent CLI、真实模型输出、完整仓库 AST 快照生成、并发加载或路径与软链接安全边界已经通过集成验证。[代码理解运行时的自包含边界 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L1 "说明运行时负责版本化合同、角色资产和确定性引用校验，不调用真实模型且避免耦合存储层。")
