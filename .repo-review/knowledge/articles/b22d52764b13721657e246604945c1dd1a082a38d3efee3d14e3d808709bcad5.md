# 知识生成、复核与发布流水线

把固定材料路由给专门分析角色，通过持久任务执行生成与独立复核，只发布通过复核且依赖未变的知识；同时支持用户回答、失败反馈和分层综合。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="routing-context"></a>
## 材料路由与固定上下文

流水线按材料特征选择角色：含图片的材料交给视觉分析，对话或 hook 交给会话分析，常见代码扩展名交给代码分析，其余由通用材料分析处理。[分析角色选择 ↗](../../../apps/server/src/knowledge/pipeline.ts#L15 "说明图片、会话、代码和普通材料如何选择对应分析角色。") 构造角色上下文时只提供明确选定的行范围和图片资产，并附上来源 Revision、参与者及转发属性；若没有任何固定原始材料则拒绝运行。派生文章会标明其不是独立证据，角色只能引用本次明确提供的材料或文章。[角色固定上下文构造 ↗](../../../apps/server/src/knowledge/pipeline.ts#L30 "支持材料按可见范围切片、图片读取、原始来源元数据和派生文章身份标记。")

<a id="durable-run"></a>
## 持久任务与可追踪执行

每次角色调用先以模型、effort、预算、材料摘要、文章修订和角色包哈希入队；成功任务可复用既有输出，失败、取消或等待用户的任务则要求重试。worker 保存模型实际配置、提示与上下文指纹、token 用量及完整 trace，使生成过程可以复查。[持久角色任务执行 ↗](../../../apps/server/src/knowledge/pipeline.ts#L60 "说明任务入队、结果复用、worker 执行以及运行 trace 的保存。") 批量输出还必须完整覆盖目标键，并经过引文绑定、结构校验和可见行范围检查。[知识批次验证 ↗](../../../apps/server/src/knowledge/pipeline.ts#L96 "支持目标键完整性、引文绑定、文档验证和提供范围限制。")

<a id="review-publication"></a>
## 独立复核与渐进修订

正文生成后由独立 verifier 逐篇复核；只有 accepted 文档才会组装依赖、生成记录和复核记录并发布。未通过的目标保留上一稿及具体问题，最多进行四轮定向修订，最后一轮要求把仍不确定的内容降为有依据的问题。[生成复核发布循环 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "说明独立复核、仅发布 accepted 文档及失败目标的定向修订机制。") 已有复核失败记录也会在材料摘要未变时重新提供，避免后续分析遗忘先前纠正。

<a id="analysis-synthesis"></a>
## 增量分析与分层综合

增量分析跳过已有 current 文章，把同类且规模受控的材料分批并发处理；相关问题已有用户回答时，会将回答 Revision 作为新的原始材料加入。单批失败被记录，不阻断其他批次。[增量材料分析 ↗](../../../apps/server/src/knowledge/pipeline.ts#L161 "支持 current 文章复用、批处理、并发、用户回答补充和逐批失败隔离。") 综合流程只采用 current 子文章，数量过多时先分片；上层综述保留对子文章的固定引用，必要时依据预算选择完整来源或有限引文范围。[分层知识综合 ↗](../../../apps/server/src/knowledge/pipeline.ts#L201 "说明 current 子文章选择、分片综合、文章引用保留与上下文预算控制。")
