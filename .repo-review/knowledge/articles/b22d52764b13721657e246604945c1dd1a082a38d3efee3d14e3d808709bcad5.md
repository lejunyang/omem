# 知识生成、复核与发布流水线

该模块把固定原始材料组织成受合同约束的角色上下文，通过持久化任务执行分析、写作与独立复核，并负责单材料分析、历史反馈复用、知识树规划和分层综合。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-context"></a>
## 职责与输入组织

`KnowledgePipeline` 是知识生产的编排层：它依据图片、会话来源和代码扩展名，选择视觉、会话、代码或通用材料分析角色。[分析角色选择规则 ↗](../../../apps/server/src/knowledge/pipeline.ts#L15 "支持依据图片、会话来源和代码扩展名选择分析角色的说明。") 固定材料按获准行段装入上下文，较长文本会被分块，图片则必须能从资产存储中取得；上下文同时保留 revision、来源、时间与转发状态。若没有任何原始材料，构造过程会直接失败；派生文章仅作为带版本的辅助知识传入，并明确不是独立证据。[固定材料上下文构造 ↗](../../../apps/server/src/knowledge/pipeline.ts#L30 "支持材料分块、图片装载、来源元数据、原始材料必需性及派生文章证据边界的说明。")

<a id="durable-run-and-validation"></a>
## 持久化执行与结构校验

角色运行前会加载 bundle，并把材料摘要、文章 revision、模型、effort、预算和 bundle hash 固化到任务输入；已成功任务可直接复用结果，失败、取消或等待用户的任务则要求重试。[角色任务入列与结果复用 ↗](../../../apps/server/src/knowledge/pipeline.ts#L60 "支持 bundle 加载、输入引用固化、持久化任务创建以及既有任务状态处理的说明。") worker 通过运行网关执行角色，保存模型、会话、用量和各类 trace 字段，并循环处理指定任务直至成功、停止或异常。[角色 worker 执行循环 ↗](../../../apps/server/src/knowledge/pipeline.ts#L73 "支持网关调用、运行 trace 保存及任务成功或中断前的处理循环。") bundle 本身汇集 prompt、输出 schema、skills 与 bundle hash。[角色 bundle 结构 ↗](../../../apps/server/src/agent-runtime/bundles.ts#L27 "说明流水线加载的 bundle 包含 prompt、输出 schema、skills 和 bundle hash。") worker 指纹回调对技能清单和空工具列表调用 `stableDigest`；该摘要函数会递归规范化对象键序并计算 SHA-256，但现有材料不足以据此断言完整任务指纹的全部生成规则。[稳定摘要实现 ↗](../../../apps/server/src/storage/digest.ts#L3 "支持 stableDigest 对规范化 JSON 计算 SHA-256；附近正文仅陈述代码明确展示的用途。") 最终输出必须完整且唯一覆盖所有目标，材料引用只能落在本次提供的行段内，并通过引用绑定与文档合同校验。[批量输出与引用校验 ↗](../../../apps/server/src/knowledge/pipeline.ts#L96 "支持目标键完整唯一、文档合同校验以及材料引用不得越过已提供行段的说明。")

<a id="review-and-publication"></a>
## 独立复核、修订与发布

写作与复核最多执行四轮。没有既有修订反馈时，首轮使用调用方指定的分析或写作角色；只要 `repair` 已有内容——包括调用方传入的历史反馈——当前轮次就改用 `knowledge-refresher`。因此，旧稿中“首轮总是使用指定角色，后续才使用 refresher”的结论已被替代。每轮草稿随后都交给独立的 `knowledge-verifier`，最后一轮还会要求仅保留直接受支持的陈述。[写作角色选择与独立复核循环 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "支持最多四轮写作、依据 repair 是否存在选择 refresher、最后一轮保守约束以及逐目标 verifier 复核；也直接支持对旧结论的修正。") 只有 accepted 文档才会合并复核问题、记录材料与文章依赖，并连同生成及复核 trace 发布；被拒目标进入下一轮，四轮后仍未通过则整体报错。[通过后发布与拒绝后收敛 ↗](../../../apps/server/src/knowledge/pipeline.ts#L126 "支持仅发布 accepted 文档、记录依赖与生成复核 trace，并继续修订被拒目标。") 历史反馈仅在目标 digest 相同，且旧任务依赖的全部材料仍以相同 digest 存在于当前 offers 时复用；当前上下文可以增加新材料，因此此前“新旧上下文必须完全一致”的结论同样被替代。[历史反馈材料子集校验 ↗](../../../apps/server/src/knowledge/pipeline.ts#L145 "支持旧反馈仅在目标 digest 匹配且旧任务依赖材料仍存在于当前 offers 时复用，并说明新增材料不会自动阻止复用。")

<a id="analysis-and-synthesis-boundaries"></a>
## 分析、规划、综合与证据边界

`analyze` 跳过已有 current 文章的材料，让每个待处理材料单独成批，再补入已回答问题和显式 supplements；并发受限，各批失败分别记录。[单材料并发分析流程 ↗](../../../apps/server/src/knowledge/pipeline.ts#L164 "支持跳过已有 current 文章、逐材料成批、补入回答与 supplements，并分别收集失败。") `plan` 选择 README 或首份材料的前 100 行作为固定输入，以 current 且非 topic 的文章构造目录，并强制规划结果包含概览、架构、背景、需求和进展章节，同时拒绝未知目录键。[知识树规划流程 ↗](../../../apps/server/src/knowledge/pipeline.ts#L189 "支持规划输入的材料与文章目录选择、必需章节约束以及目录键有效性检查。") `synthesize` 仅筛选 current 子文章：无可用项时报错，超过十二篇时递归分片，依赖 revision 未变化时复用已有结果。代码在此没有直接检查 review verdict，因此原先“只接受已复核子文章”的表述应收窄为“只使用 current 子文章”。[current 子文章选择与缓存 ↗](../../../apps/server/src/knowledge/pipeline.ts#L202 "支持综合仅选择 current 子文章、无可用子文章时报错、超过十二篇分片及依赖未变时复用；该范围不直接证明文章已通过复核。") 普通综合会沿子文章引用收集原始材料并合并行段，预算允许时扩展到全文；组合上层章节时则保留 article 下钻关系，并携带有限原始材料以维持 provenance。[综合来源选择与预算扩展 ↗](../../../apps/server/src/knowledge/pipeline.ts#L217 "支持上层文章引用、普通综合的原始材料行段合并、来源兜底以及预算允许时扩展至全文。")
