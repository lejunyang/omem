# SQLite 中的词法与语义混合检索

这份实现为个人 SQLite 材料库补上后台向量索引、词法与向量候选融合、可选交叉编码器重排和失败降级。它适合用来理解旧式混合检索的完整闭环；当前应用工厂已改为装配 UnifiedRetrieval，修改现行行为前应先确认统一实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决自然语言与原文措辞不一致

`SemanticRetrieval` 在同步词法检索之上增加向量召回与可选的交叉编码器重排，目标是让“意思相近但字面不同”的查询仍能找到原始材料。它直接复用 SQLite 中的当前原件、固定版本和来源信息，不建立另一套证据权威；模型则通过注入的加载函数按需创建。参考 [混合检索的依赖与状态 ↗](../../../apps/server/src/retrieval/semantic.ts#L1 "支持本类继承词法检索、依赖向量与重排模型，并以 SQLite 当前原件为数据基础。")

需要注意代码所处的当前关系：在这份快照里，应用工厂创建并启动的是 `UnifiedRetrieval`，不是本类。因此本文件更适合作为一条完整机制和兼容实现来阅读；若要修改当前默认检索，应先对照统一检索实现。参考 [当前检索工厂装配 ↗](../../../apps/server/src/retrieval/factory.ts#L14 "说明当前应用工厂实际创建、启动并关闭 UnifiedRetrieval，帮助读者判断修改入口。")

<a id="indexing"></a>
## 后台补齐可持久复用的向量索引

调用 `start()` 后，定时任务分批寻找“当前、非派生且尚无该模型索引”的片段；同一时刻只允许一个 `indexBatch` 工作，成功后约 1 秒继续，失败后约 30 秒重试，不阻塞查询。参考 [后台索引调度 ↗](../../../apps/server/src/retrieval/semantic.ts#L40 "支持自动补齐、单任务复用以及成功和失败后的不同轮询间隔。")

长片段按 **400 字窗口、320 字步长**切分，标题前 64 字会加到每个 passage；每 16 个窗口送入 embedding。向量先归一化，再在一个事务中写入各窗口及完成标记，所以重启后可跳过已完成片段，写入中途失败则整体回滚。参考 [窗口编码与事务写入 ↗](../../../apps/server/src/retrieval/semantic.ts#L60 "支持重叠窗口、批量 embedding、向量归一化及事务性完成标记的流程。")

```mermaid
flowchart LR
  A[当前原始片段] --> B[重叠窗口]
  B --> C[passage 向量]
  C --> D[窗口向量表]
  D --> E[片段完成标记]
```

索引身份包含模型 ID；查询只读取同一 ID 的向量，维度变化却未更换模型身份时会报错，避免把不兼容向量混算。参考 [模型身份与维度检查 ↗](../../../apps/server/src/retrieval/semantic.ts#L93 "支持查询只读取同模型 ID 的索引，并在向量维度不一致时拒绝计算。")

<a id="search-flow"></a>
## 一次查询如何产生结果

以 `searchSourcesAsync({ text: "海边度假 交通", visible })` 为例：先由父类取最多 100 个词法候选；再把查询前 400 字编码并归一化，对可见且位于时间范围内的窗口计算余弦点积。同一片段只保留最高分窗口，其 snippet 也取自该窗口。参考 [词法与向量召回 ↗](../../../apps/server/src/retrieval/semantic.ts#L87 "支持代表性查询从词法候选开始，再应用可见性、时间范围、余弦评分和最佳窗口选择。")

语义候选必须同时通过 0.35 的绝对下限和“距第一名不超过 0.07”的相对带宽，然后与词法候选做按名次衰减的融合。若配置重排器，只取融合分最高的 40 条，用“标题 + 片段”与查询成对打分；低于 0.1 的普通候选会被丢弃，但代码符号候选保留，最后交给公共 `rankEvidence` 做去重、分散和数量限制。参考 [候选融合与交叉重排 ↗](../../../apps/server/src/retrieval/semantic.ts#L113 "支持语义阈值、双路融合、40 条重排池、弱候选过滤、异常降级及最终公共排序。")

边界行为是有意保守的：纯标识符或路径只走精确词法结果，避免语义猜测；embedding 尚未加载时仍可走词法与可选重排。参考 [精确查询与未加载模型 ↗](../../../apps/server/src/retrieval/semantic.ts#L86 "支持纯标识符绕过语义猜测，以及向量模型尚未加载时继续使用词法候选。") 向量查询或重排异常会记录为 degraded，并退回词法候选或重排前候选。参考 [候选融合与交叉重排 ↗](../../../apps/server/src/retrieval/semantic.ts#L113 "支持语义阈值、双路融合、40 条重排池、弱候选过滤、异常降级及最终公共排序。") `close()` 会停掉定时器、等待在途索引，并关闭已加载模型。参考 [关闭检索资源 ↗](../../../apps/server/src/retrieval/semantic.ts#L150 "支持停止调度、等待索引任务并关闭向量模型与重排模型。")
