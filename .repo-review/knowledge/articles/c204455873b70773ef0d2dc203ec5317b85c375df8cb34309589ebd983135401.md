# 以证据阅读为中心的交互设计

文档提出个人助理第一轮交互架构：以知识阅读、逐层证据导航和原位追问为主链，并规定变更恢复、异常状态及无障碍原则。它同时明确自身属于早期架构与原型设计，不能作为当前功能已经实现的证明；实际能力仍应以实施状态、决策记录和正式视觉规范为准。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="positioning"></a>
## 定位与信息架构

本文将产品重心放在“读懂知识及其依据”，而非后台配置。主界面采用目录、纸面阅读区和 AI 侧栏的克制层级，面向普通用户展示材料名称、版本、出处与适用范围，隐藏向量库等内部实现细节。页面规划覆盖知识阅读、经验方法、材料来源、变更学习、能力连接和搜索，但正式版应优先保证阅读主链不被设置与诊断打断。[视觉层级与页面结构 ↗](../../../docs/interaction-design.md#L7 "支持产品以材料阅读和人读信息为中心，以及优先保障阅读主链的论断。")

需要特别区分状态：文档自称第一轮架构/原型设计，并明确“不等于当前运行代码”；表格中的“原型实现”只能说明演示范围，不能据此认定生产功能已经交付。[文档实施状态声明 ↗](../../../docs/interaction-design.md#L1 "明确该文档是早期架构与原型设计，不能作为当前运行代码已经实现的证据。")

<a id="evidence-trail"></a>
## 证据路径与原位追问

引用必须贴近其支持的句子，以人读标题和局部编号呈现；点击后在同一对话框容器内逐层切换材料，并保存每层滚动位置、页签和草稿。路径没有固定业务层数上限，但遇环需提示并允许跳回，重复标识不得继续压栈，服务端则按一跳读取并逐次执行权限与预算检查。[引用层级与循环处理 ↗](../../../docs/interaction-design.md#L38 "说明同一对话框中的状态保存、深路径展示、循环检测和逐跳读取约束。")

证据阅读包含引用片段、上下文、反向引用和版本四类视图，尤其要求旧引用固定到历史版本，不能被新正文静默替换。[四类证据视图 ↗](../../../docs/interaction-design.md#L54 "支持引用片段、上下文、反向引用和固定历史版本共同构成证据阅读面的描述。") 追问保持当前阅读位置和固定选区，模型范围不会因导航链变长而无限扩大；生成回答只能沉淀为带 evidence refs 的候选，不能直接成为独立证据，且原型并未执行真实模型验证。[追问范围与候选沉淀 ↗](../../../docs/interaction-design.md#L61 "说明原位追问的范围控制、局部会话隔离，以及生成回答不能直接成为独立证据。")

<a id="changes-and-boundaries"></a>
## 变更治理、边界状态与验收属性

常规更新进入按 ChangeSet 聚合的变更流，而不是形成逐片段审批噪声；恢复操作应先展示前后差异与影响范围，再创建新修订。发生后续编辑时必须重新合并，物理删除或已外发动作也不能承诺完全恢复。冲突证据、过度泛化及批量或不可逆动作进入例外队列，用户暂缓不等于超时同意。[变更恢复与例外队列 ↗](../../../docs/interaction-design.md#L71 "支持 ChangeSet 聚合、恢复生成新修订、后续编辑重新合并和高风险例外需用户判断的要求。")

边界设计强调证据可核验：上游不可用时只展示带同步时间的授权快照，原文更新时保留旧引用，OCR 或锚点不可靠时不得伪装成精确定位，模型失败也不能把半成品记为知识。[异常与不可靠证据状态 ↗](../../../docs/interaction-design.md#L81 "说明权限、删除、上游失效、版本更新、定位不可靠和模型失败时不得误导用户的边界。") 无障碍目标是 WCAG 2.2 AA；原型仅验证了原生对话框和主要键盘路径，完整读屏与对比度自动审计仍未完成，因此它们属于待验证要求而非现成能力。[无障碍目标与未完成验证 ↗](../../../docs/interaction-design.md#L95 "支持键盘焦点规则、移动端要求及完整读屏和对比度审计尚未完成的状态判断。")
