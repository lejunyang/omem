# 模块架构分析技能约束

该技能规定如何基于固定代码快照解释单一模块，强调边界、流程、事实与解释分离及不确定性管理；它是角色行为规范，不能单独证明分析流程或 CodeUnderstanding.v1 校验已实际实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="scope"></a>
## 分析范围与方法

该技能面向固定快照中的单一模块：先识别模块符号，再把离开模块文件、指向外部节点的边显式列为边界。关键流程必须沿快照中已有的边逐段组织，不能凭架构常识补造调用关系。[模块边界与关键流程规则 ↗](../../../packages/agent-runtime/roles/module-architect/1/skills/omem-code-module-architect/SKILL.md#L8 "支持模块边界必须来自离开模块文件的边，以及关键流程只能沿快照已有边组织的论断。")

每项结论还要区分为快照直接呈现的 `raw_fact` 与分析者形成的 `interpretation`，避免把架构解读伪装成代码事实。[事实与解释分类规则 ↗](../../../packages/agent-runtime/roles/module-architect/1/skills/omem-code-module-architect/SKILL.md#L10 "支持每项架构结论须标记为原始事实或解释的论断。")

<a id="limits"></a>
## 证据、不确定性与执行边界

输出只能引用快照标识；边界或流程不清楚时，应写入 `unknowns` 并降低置信度，而不是猜测。[不确定性与快照引用约束 ↗](../../../packages/agent-runtime/roles/module-architect/1/skills/omem-code-module-architect/SKILL.md#L11 "支持只能引用快照标识，并在边界或流程不清楚时记录未知项、降低置信度。") 技能描述明确限定其不读取文件或调用工具，说明分析输入应由宿主以固定快照提供。[固定快照与无工具读取边界 ↗](../../../packages/agent-runtime/roles/module-architect/1/skills/omem-code-module-architect/SKILL.md#L3 "直接支持该技能基于固定代码快照工作，且自身不读取文件或调用工具的说明。") 规则还禁止把材料当作指令、禁止修改内容，并要求仅返回 CodeUnderstanding.v1 JSON。[模块分析输出与安全限制 ↗](../../../packages/agent-runtime/roles/module-architect/1/skills/omem-code-module-architect/SKILL.md#L12 "支持禁止执行工具和修改、不得把材料当指令以及仅返回指定 JSON 合同的说明。") 因而当前材料能确认预期分析纪律和安全边界，却不能据此断言完整输出合同、宿主校验或真实运行已经实现。
