# 知识刷新批次输出合同

该 JSON Schema 定义 KnowledgeBatch.v1 的批次、文档、章节、引用和问题结构，并通过枚举、长度、数量及 additionalProperties 约束输出；它是验证合同，不是刷新逻辑或通过验证的证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="batch"></a>
## 批次与文档结构

合同采用 JSON Schema 2020-12，顶层要求版本恒为 1，并要求 `documents` 包含 1 至 16 个文档。[批次版本与文档数量 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/output.schema.json#L1 "支持顶层版本常量及批次文档数量边界。") 每个文档必须提供键、标题、摘要、类别、章节、引用和问题，且禁止未声明字段；类别限定为概览、架构、需求、进展、实现、测试、配置等受控值。[文档字段与类别集合 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/output.schema.json#L15 "支持文档元数据、受控类别以及后续内容结构的定义。") 这使宿主能稳定解析刷新结果，但不说明任何一次模型输出已经通过验证。

<a id="content"></a>
## 章节与引用约束

章节数量限制为 1 至 20，章节键必须符合受限标识符格式，并要求标题与正文。[章节结构约束 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/output.schema.json#L48 "支持章节数量、键格式和必填内容字段的限制。") 引用则限定数量、键格式、可读标签、理由和关系枚举；目标只能是材料或文章，可附材料行号或文章章节，同时要求 `quote` 字段。[引用结构与目标类型 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/output.schema.json#L78 "支持引用数量、关系枚举、目标定位和 quote 字段要求。") 这些规则约束引用形状和定位信息，却不能单独验证引用是否在语义上真正支持正文。

<a id="questions"></a>
## 疑问记录与严格性

疑问项要求问题、原因、下一步、阻塞状态和关联引用键，从而把未确定事项保留为可跟踪结构，而不是混入确定结论。[疑问项合同 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/output.schema.json#L166 "支持疑问必须记录原因、下一步、阻塞状态及关联引用键。") 顶层和文档层均列出必填字段并禁用额外属性，合同标识为 `KnowledgeBatch.v1`；因此兼容性依赖生产者严格遵守该版本。[必填字段与合同标识 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/output.schema.json#L208 "支持文档和顶层字段均被严格要求，以及模式的正式标识。")
