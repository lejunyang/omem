# 服务启动与优雅退出入口

该入口负责加载运行配置、构建并监听 Fastify 应用，同时为 SIGINT 和 SIGTERM 注册关闭处理。具体业务能力、依赖装配与非本机监听的安全校验由应用构建层负责；当前材料未展示启动失败及关闭失败的统一兜底策略。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

该文件是服务进程的最外层启动入口，把“读取配置—构建应用—开始监听”串成可执行流程。它本身不注册业务路由，也不直接创建存储、检索或助理服务，而是将这些职责交给 `buildApp`，从而让入口保持为薄编排层。参考 [入口职责 ↗](../../../apps/server/src/main.ts#L1 "支持该文件依次加载配置、构建应用并启动监听，是服务进程的薄编排入口。")

应用构建层接收配置并初始化 Fastify、数据存储及运行服务，因此 `main.ts` 与配置模块、应用装配模块形成明确分工：前者管理进程生命周期，后两者分别提供运行参数和服务实例。参考 [应用装配职责 ↗](../../../apps/server/src/app.ts#L47 "支持 buildApp 接收配置并初始化 Fastify、存储及相关运行服务，说明入口与应用装配层的关系。")

<a id="startup-flow"></a>
## 启动流程与安全边界

启动时先同步调用 `loadConfig()`，随后等待 `buildApp(config)` 完成，再使用配置中的主机和端口调用 `listen`；只有监听成功后才打印可访问地址。任一步骤抛错都会阻止后续步骤执行，但当前入口没有捕获、重试或定制错误输出。参考 [监听启动顺序 ↗](../../../apps/server/src/main.ts#L3 "支持配置加载、应用构建、监听和成功日志之间的执行顺序。")

非回环地址的安全约束并不在入口重复实现：应用构建阶段发现监听地址不是本机地址且没有令牌时会直接拒绝启动。这意味着入口依赖 `buildApp` 在真正监听前完成安全校验。参考 [非本机监听保护 ↗](../../../apps/server/src/app.ts#L47 "支持非回环地址必须配置令牌，且校验发生在应用构建阶段。")

<a id="shutdown"></a>
## 信号关闭与已知限制

进程为 `SIGINT` 和 `SIGTERM` 注册相同处理器：收到信号后调用 `app.close()`，待 Fastify 关闭完成再以状态码 0 退出。这为终端中断和常见容器停止流程提供了优雅关闭机会。参考 [进程信号关闭 ↗](../../../apps/server/src/main.ts#L7 "支持 SIGINT、SIGTERM 触发应用关闭，并说明当前可见实现缺少拒绝处理和超时兜底。")

这里没有防止重复信号触发多次关闭，也没有为 `app.close()` 设置超时或失败分支；若关闭 Promise 拒绝，代码中看不到保证进程退出的兜底。材料也未包含对应测试文件，因此无法确认启动异常、重复信号和关闭失败是否在其他测试中覆盖。参考 [进程信号关闭 ↗](../../../apps/server/src/main.ts#L7 "支持 SIGINT、SIGTERM 触发应用关闭，并说明当前可见实现缺少拒绝处理和超时兜底。")
