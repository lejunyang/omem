# 服务进程启动入口

加载运行配置、构建 Fastify 应用并开始监听，同时为常见终止信号注册优雅关闭处理。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="startup"></a>
## 启动链路

该文件是服务进程的最薄入口：先调用 `loadConfig` 得到主机、端口及其他运行配置，再把配置交给 `buildApp` 完成应用和依赖组装，最后监听指定地址并输出可访问 URL。[服务启动入口 ↗](../../../apps/server/src/main.ts#L1 "支持配置加载、应用构建、网络监听和启动日志这一完整入口链路。") `buildApp` 会创建 Fastify、Store、Runs、MemoryService 与 FeedbackService；非回环地址若没有令牌会直接拒绝启动，因此入口本身依赖应用工厂执行安全检查和模块装配。[应用工厂的安全检查与服务装配 ↗](../../../apps/server/src/app.ts#L44 "说明 main 调用的应用工厂负责非回环令牌检查，并实例化存储、运行和记忆服务。")

<a id="shutdown"></a>
## 终止处理与边界

进程收到 `SIGINT` 或 `SIGTERM` 时调用 `app.close()`，待关闭完成后以状态码 0 退出，意图让 Fastify 释放监听器及其生命周期资源。[进程信号关闭逻辑 ↗](../../../apps/server/src/main.ts#L7 "支持 SIGINT、SIGTERM 下等待应用关闭后正常退出的说明。") 这里没有为配置加载、构建、监听或关闭失败设置显式恢复逻辑，也没有注册其他终止事件；错误如何记录及退出由顶层运行环境和 Fastify 的 Promise 行为决定。
