# 服务端进程入口

加载配置、构建并监听 Fastify 应用，同时为 SIGINT 与 SIGTERM 提供基础的优雅关闭处理。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="startup"></a>
## 启动流程与模块关系

该文件是服务端进程的薄入口：先调用配置模块取得主机、端口等运行参数，再调用应用装配模块的 `buildApp`，最后让返回的 Fastify 实例开始监听。[入口启动序列 ↗](../../../apps/server/src/main.ts#L1 "支持入口依次加载配置、构建应用并监听指定地址的说明。") `buildApp` 内部负责创建 Store、运行管理器、记忆服务及反馈服务，因此入口本身不承载业务逻辑，只负责把配置交给应用层并启动进程。[应用装配初始化 ↗](../../../apps/server/src/app.ts#L44 "说明 buildApp 创建存储与记忆相关服务，支撑入口和应用装配模块的关系。")

<a id="shutdown"></a>
## 关闭行为与边界

进程收到 `SIGINT` 或 `SIGTERM` 时会异步调用 `app.close()`，成功后以状态码 0 退出，可让 Fastify 停止接收请求并执行其关闭流程。[进程信号处理 ↗](../../../apps/server/src/main.ts#L7 "支持收到两类终止信号后关闭应用并退出的描述。") 这里没有展示关闭失败的捕获、超时强退或重复信号保护；若 `app.close()` 拒绝，材料不足以确认进程最终如何退出。
