# 仓库评审搜索权重策略

该模块从仓库配置中加载路径前缀权重，生成一个查询期评分函数；它通过显式类别、历史研究意图和查询中的路径命中保护用户意图，避免仓库偏好压低明确相关的结果。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-config"></a>
## 作用与配置加载

该模块解决仓库评审搜索中的结果偏好问题：允许按文件路径前缀配置正权重，同时明确这些偏好只适用于仓库场景，不应扩展为个人数据的全局规则。配置结构由 Zod 校验，每条规则要求非空前缀，权重必须大于 0 且不超过 1；缺少 `rules` 时使用空数组。[搜索策略配置结构与作用边界 ↗](../../../apps/server/src/review/search-policy.ts#L5 "支持仓库偏好不应成为个人数据全局规则，以及前缀和权重的校验约束。")

`loadReviewSearchPolicy` 在传入根目录下寻找 `config/review-search.json`。文件存在时同步读取、解析 JSON 并校验；不存在时解析空对象，从而得到默认空规则。文件损坏、JSON 非法或字段不合约时没有降级分支，错误会直接由解析过程抛出。[评审搜索配置加载逻辑 ↗](../../../apps/server/src/review/search-policy.ts#L7 "支持配置文件位置、缺省空配置及同步读取和校验流程的说明。")

<a id="matching-flow"></a>
## 匹配与优先级流程

规则加载后按前缀长度降序排列，使更具体的路径优先于较宽泛的目录规则。返回的闭包接收候选路径、查询文本和可选类别：若调用方已指定类别，查询表达历史、调研、原型或早期版本意图，或者查询文本直接包含候选路径，则立即返回中性权重 `1`，显式意图优先于默认偏好。[具体前缀优先与显式意图覆盖 ↗](../../../apps/server/src/review/search-policy.ts#L10 "支持规则排序，以及类别、历史研究问题和路径命中返回中性权重的核心流程。")

其余情况采用第一个能匹配 `path.startsWith(prefix)` 的规则权重；没有匹配规则也返回 `1`。因此该策略本质上只能保持或降低候选权重，不能用大于 1 的系数提升结果，也不负责计算文本相关性、排序或可见性过滤。[路径前缀权重回退 ↗](../../../apps/server/src/review/search-policy.ts#L5 "支持首个前缀匹配规则生效、无匹配时回退为 1，并结合配置上限说明该策略不会放大评分。")

<a id="boundaries-relations"></a>
## 边界与模块关系

匹配是区分大小写的字符串前缀判断，没有路径规范化或目录边界判断；例如相似前缀也可能命中。查询中的路径检测则统一转为小写，但仍是简单子串包含。历史意图依赖固定的中英文关键词，未覆盖的同义表达不会触发保护分支。[字符串匹配边界 ↗](../../../apps/server/src/review/search-policy.ts#L11 "支持路径采用 startsWith、查询路径采用小写子串匹配，以及历史意图依赖固定正则关键词的边界分析。")

从当前材料只能确认该文件向外暴露策略加载函数，并依赖 Node 文件系统、路径工具和 Zod；没有提供调用方源码，无法断言它具体接入哪个检索阶段，也无法确认返回权重如何与其他评分合并。材料中亦无测试文件，因而配置异常、前缀冲突和意图覆盖等行为虽可由实现推断，但没有可见的自动化断言证据。[模块导入与公开入口 ↗](../../../apps/server/src/review/search-policy.ts#L1 "支持该模块依赖文件系统、路径和 Zod并仅显示一个公开加载函数；调用方和测试在当前材料中不可见。")
