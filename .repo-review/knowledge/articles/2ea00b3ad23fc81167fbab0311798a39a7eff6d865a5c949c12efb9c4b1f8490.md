# Web 应用 TypeScript 配置

该文件定义以 ES2023 为编译目标、采用打包器式模块解析的严格 TypeScript 检查配置，并将应用及共享 UI、契约源码纳入范围。它仅能说明静态检查配置，不能单独证明 Vue 主版本、单文件组件检查工具、生产构建结果、运行环境原生能力或具体浏览器兼容范围。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="compiler-baseline"></a>
## 编译目标与检查职责

配置将 TypeScript `target` 设为 `ES2023`、模块格式设为 `ESNext`，并采用 `Bundler` 模块解析；`DOM` 与 `DOM.Iterable` 加入浏览器 API 类型声明，`vite/client` 加入 Vite 环境类型。准确地说，这是**以 ES2023 作为 TypeScript 编译目标**，而非证明最终代码必须运行在原生支持 ES2023 的环境中；后续构建工具仍可能继续转译，具体兼容范围无法从本文件确定。[编译目标与环境类型 ↗](../../../apps/web/tsconfig.json#L1 "支持 ES2023 编译目标、ESNext 模块、Bundler 解析及浏览器和 Vite 类型配置，同时说明这些字段不足以确定最终运行环境与浏览器兼容范围。")

`strict: true` 开启严格类型检查，`skipLibCheck: true` 跳过声明文件（`.d.ts`）的类型检查，并不限于外部依赖；`noEmit: true` 表示此配置不让 TypeScript 直接输出 JavaScript。因此，本文件承担的主要是类型检查配置，而生产转译与打包由什么工具完成仍属未知。[严格检查与禁止输出 ↗](../../../apps/web/tsconfig.json#L1 "支持严格模式、跳过所有声明文件类型检查以及不直接生成 JavaScript的说明，并界定该文件未提供生产构建工具或执行结果。")

## 源码检查范围与限制

`include` 覆盖应用自身的 TypeScript 与 `.vue` 文件，还直接纳入共享 UI 包的 TypeScript、`.vue` 源码和共享契约源码，形成跨包的源码级检查范围。是否能真正检查 Vue 单文件组件，仍取决于调用该配置的工具；仅凭这份配置不能证明使用了 `vue-tsc`、某个 Vue 主版本或任何检查已经成功执行。[应用与共享源码范围 ↗](../../../apps/web/tsconfig.json#L1 "支持应用源码、共享 UI 源码与共享契约源码被纳入同一 include 范围，并为 Vue 单文件组件仍依赖外部检查工具的限制提供配置依据。")

当前文件没有声明项目引用、输出目录、增量编译或路径别名，但这只描述本文件可见的配置，不能排除其他配置或脚本补充这些能力。同样，直接包含共享包源码究竟是长期架构选择还是阶段性状态，也缺少设计材料佐证。[当前文件未声明的能力 ↗](../../../apps/web/tsconfig.json#L1 "完整配置支持判断本文件未声明项目引用、输出目录、增量编译和路径别名，但不能排除仓库其他文件另有定义。")
