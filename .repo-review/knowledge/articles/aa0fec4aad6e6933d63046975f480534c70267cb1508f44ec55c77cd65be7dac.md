# source-profile · 模块理解

该模块以确定性的规则分析固定来源修订，将片段组织成可追溯、可重建的内容画像，并以代次保存；它服务于导航与后续检索，不取代原始证据，分析失败也不应妨碍来源读取。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-lifecycle"></a>
## 职责与生命周期

`source-profile` 为已捕获的来源修订生成派生导航元数据，包括载体类型、语言、标题路径、话语段、主题候选、时间提示、链接、覆盖缺口和证据引用；`derived: true` 明确了画像不是新的独立证据。[来源画像数据结构 ↗](../../../apps/server/src/source-profile/service.ts#L35 "说明画像包含的导航字段、派生属性、证据引用以及成功、部分和失败状态，支持其作为派生视图而非独立证据的定位。")

服务按修订读取原文信息及有序片段，执行同步规则分析，再以递增的 `profileGeneration` 写入 SQLite；读取时选择该修订最新一代。因此同一份固定证据可以重建、升级画像规则，同时保留代次边界。[画像生成与代次保存 ↗](../../../apps/server/src/source-profile/service.ts#L119 "支持服务从固定修订及有序片段生成画像、递增代次并持久化的完整生命周期。") 若分析失败，服务尽力记录失败状态，并刻意吞掉失败记录自身的写入异常，使原始来源继续可读，体现“证据优先、画像可选”的容错关系。[画像失败隔离 ↗](../../../apps/server/src/source-profile/service.ts#L168 "证明画像失败被尽力记录，但记录失败不会影响原始来源继续读取。")

<a id="analysis-flow"></a>
## 规则分析如何工作

分析首先检查是否存在完整匹配的 Markdown 标题片段，以决定载体类型。遍历片段时，标题会维护层级栈；普通段落继承最近的父标题，再被归类并截取摘要。标题正则锚定整个去空白后的片段，所以“标题与正文共处一个 fragment”不会建立标题节点，而会整体进入普通话语分析。[标题栈与片段遍历 ↗](../../../apps/server/src/source-profile/service.ts#L251 "支持载体判定、完整片段标题匹配、标题层级栈以及普通段落继承父标题的流程和限制。")

话语分类按优先级识别图片占位、短噪声、代码或命令、问题、约束、示例、定义、计划、历史、指令和默认主张；代码、SQL、TODO 与 shell 命令优先作为材料示例，避免误当成待执行指令。规则还标记过去、现在、未来及对父标题的指称依赖。[话语类型与时态规则 ↗](../../../apps/server/src/source-profile/service.ts#L75 "支持代码材料优先、话语类型分类、时态识别及父标题指称标记的说明。")

<a id="relations-limits"></a>
## 跨模块关系、进展与限制

模块复用检索侧的 `tokenize` 统计非停用词，并将高频词与标题合并为主题候选；语言则只依据中英文字符数量阈值。它还从捕获正文的少数 context 字段推断项目候选，只从带 `url` 的 parts 收集显式链接，说明其输入依赖既有 Revision、Fragment 与统一捕获结构。[主题、语言与捕获上下文分析 ↗](../../../apps/server/src/source-profile/service.ts#L305 "说明模块与检索分词器及统一捕获正文结构的关系，并支持主题、语言、项目候选和链接提取的规则边界。")

图片占位、含竖线的表格式片段和超长片段会形成覆盖缺口，使状态变为 `partial`；全部 fragment ID 被写入 `evidenceRefs`，提供回到原始材料的路径，但不代表人工确认或语义核验。当前实现是 `rule-based@1`，可确定性运行，但标题识别依赖上游分片形态，语言、主题、表格和链接判断也都是启发式规则。[覆盖缺口与证据回链 ↗](../../../apps/server/src/source-profile/service.ts#L297 "支持覆盖缺口的触发条件、partial 状态、片段证据引用以及画像最终输出字段。")
