# source-profile · 模块理解

source-profile 为来源修订生成确定性的派生画像，把固定片段整理为标题层级、话语类型、语言、主题、上下文候选和覆盖缺口，供导航与问答范围判断使用。它复用检索分词，但不取代原始证据；画像失败原则上也不应阻断来源捕获和阅读。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-contract"></a>
## 职责与设计背景

该模块解决的是“原始材料已经保存，但缺少可导航结构”的问题。画像记录载体类型、标题路径、语言、主题、话语片段、时间提示、链接、覆盖缺口与固定片段引用，并以 `derived: true` 表明其只是原始证据的派生视图。[来源画像数据合同 ↗](../../../apps/server/src/source-profile/service.ts#L35 "支持画像包含的派生字段、证据引用、状态和版本信息，并说明其不是独立证据。") 子知识将这一定位概括为面向导航和问答范围判断的结构信息；这可帮助首次阅读者理解模块边界，但事实依据仍应回到源码。[来源画像服务子知识 ↗](4c70dcc6fe0de1bf0c9ac2f8758d925753c7b6c3e88bd94d6780a14ce3c27504.md#purpose-and-contract "提供模块职责的已有组织视角，用于解释背景和阅读入口；附近事实仍由原始源码引用支撑。")

<a id="generation-flow"></a>
## 生成、分类与持久化流程

服务按修订读取正文及有序片段，运行同步分析，再以当前最大代次加一写入画像；`latest` 则返回指定修订的最高代次。[画像读取与代次持久化 ↗](../../../apps/server/src/source-profile/service.ts#L119 "支持读取有序片段、执行分析、递增画像代次并返回最新画像的主要流程。") 分析过程中维护 Markdown 标题栈，使普通段落关联最近父标题，并识别时态、父标题指代及图片、表格样式、超长文本等覆盖缺口。[标题栈与主题候选生成 ↗](../../../apps/server/src/source-profile/service.ts#L265 "支持父标题关联、时态记录、覆盖缺口检测，以及标题和高频词共同形成主题候选。") 话语分类具有明确优先级：代码或命令样式先作为示例处理，其后才判断问题、约束、定义、计划、历史和指令，避免把材料中的命令误当成应执行操作。[话语分类优先级 ↗](../../../apps/server/src/source-profile/service.ts#L75 "支持代码优先以及问题、约束、定义、计划、历史和指令等规则分类顺序。")

<a id="retrieval-relations"></a>
## 与检索及上下文的关联

主题候选由标题和高频词合并产生，画像直接复用检索模块的 `tokenize`。该分词器保留英文词、中文完整词串及过滤常见虚词后的中文二元组，因此画像主题与关键词检索共享基础词项语义。[共享中文关键词分词器 ↗](../../../apps/server/src/retrieval/keyword.ts#L210 "解释画像所依赖分词器对英文词、中文完整词串、二元组和停用二元组的处理方式。") 项目候选来自正文上下文中的 application、conversationId、runId，显式链接来自结构化 parts；这些值目前只是候选或导航线索，并不等于已确认的项目归属。语言则由中日韩字符与拉丁字母数量阈值启发式判断。[语言、上下文候选与画像状态 ↗](../../../apps/server/src/source-profile/service.ts#L320 "支持语言阈值、项目候选、显式链接、证据引用及覆盖缺口决定 partial 状态的论断。")

<a id="progress-and-limits"></a>
## 当前进展、失败策略与限制

当前实现已经具备确定性分析、代次化保存、最近画像读取和失败记录入口。画像出现覆盖缺口时状态为 `partial`；图片不解析、表格仅按竖线识别、语言与话语类型均依赖规则，因此结果适合辅助导航，不能替代完整语义理解或原始片段。[语言、上下文候选与画像状态 ↗](../../../apps/server/src/source-profile/service.ts#L320 "支持语言阈值、项目候选、显式链接、证据引用及覆盖缺口决定 partial 状态的论断。") `recordFailure` 会尝试保存截断后的错误，并吞掉失败记录自身的写库异常，以维持来源可读性。[失败画像记录策略 ↗](../../../apps/server/src/source-profile/service.ts#L168 "支持错误截断保存、失败写库异常被吞掉及来源保持可读的设计意图。") 不过材料没有提供表约束、跨模块调用点和测试，尚不能确认失败历史一定可写入，也不能证明所有入口都正确隔离画像异常。
