# 代码理解生成预算的兼容出口

将通用 Agent Runtime 的令牌估算、生成预算函数及类型重新导出，使代码理解模块复用统一预算合同；本文件自身不实现预算算法。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 作用与实现边界

该文件是代码理解命名空间中的兼容出口，只把 `estimateTokens`、`generationBudget` 和 `GenerationBudget` 从通用 Agent Runtime 重新导出。它解决的是依赖入口统一与类型复用问题，自身没有令牌估算、默认预算、超限处理或截断算法；这些行为由未提供的上游模块决定。[预算能力重新导出 ↗](../../../apps/server/src/code/budget.ts#L1 "支持该文件仅转发通用预算函数和类型、自身不包含算法实现的判断。")

<a id="model_relationship"></a>
## 与模型适配层的关系

代码理解模型端口允许请求携带生成预算和估算输入令牌数，使调用方可以把统一预算交给具体 transport。[模型请求预算合同 ↗](../../../apps/server/src/code/understanding-model.ts#L41 "说明统一模型端口允许请求携带生成预算及估算输入令牌数。") ACP 分支会读取预算，将最大输出令牌乘以 3 转为字符上限，并继续把预算作为上下文约束传给 `acp`；没有预算时使用固定字符上限。[ACP 预算传递 ↗](../../../apps/server/src/code/understanding-model.ts#L88 "支持 ACP 分支读取预算、换算输出字符上限并传入上下文预算的流程。") 相比之下，CLI 与 HTTP 的 `run` 实现只解构提示词和取消信号，没有在该适配层消费预算参数。[CLI 与 HTTP 请求实现 ↗](../../../apps/server/src/code/understanding-model.ts#L110 "支持 CLI 和 HTTP 的运行函数没有解构或使用请求预算参数这一适配层边界。") 因而本文件只统一能力入口，不保证各 transport 对预算具有相同执行语义。
