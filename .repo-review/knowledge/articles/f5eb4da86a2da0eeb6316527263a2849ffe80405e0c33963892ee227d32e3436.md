# 飞书质量数据集人工标注流程

该脚本是显式启动的研究评测入口：从飞书文档生成待人工判断的质量样本，启动卡片标注会话，并观察当前会话的卡片消息与数据库全局标注事件计数。由于全局计数增长会先于投递终态检查触发退出，它只能验证有限的在线链路信号，不能单独确认本次会话已成功收到有效标注。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

该脚本用于联通一次真实的**飞书人工质量标注实验**：操作者提供飞书文档地址和加密密钥，脚本读取文档、准备本地运行环境，并通过飞书卡片发起人工标注。它适合观察外部应用、卡片投递和反馈数据库是否产生了链路信号。参考 [运行输入与凭据要求 ↗](../../../scripts/quality-lark-annotate.ts#L19 "支持脚本需要飞书文档地址、加密密钥，并校验可选应用 ID 的前置条件。")

样本生成器被明确限定为评测用途：规则切分得到的候选内容和草拟标签只供人工判断，不属于普通捕获、学习或知识生产链路，也不能直接作为可信知识写入。参考 [评测样本隔离边界 ↗](../../../apps/server/src/quality/import.ts#L1 "说明文档切分与草拟标签仅服务人工研究评测，不得进入普通捕获、学习和知识生产流程。")

<a id="flow"></a>
## 从文档到在线观察信号

```mermaid
flowchart LR
  A[读取飞书文档] --> B[初始化本地存储与密钥]
  B --> C[组装飞书接入和运行宿主]
  C --> D[导入 dev 评测数据集]
  D --> E[启动标注会话并发送卡片]
  E --> F[轮询会话、全局事件数与投递状态]
```
参考 [标注运行环境组装 ↗](../../../scripts/quality-lark-annotate.ts#L32 "支持读取文档后初始化存储、密钥、飞书接入服务与运行宿主的流程关系。")

脚本将数据集导入 `dev` 分片，样本上限可配置；随后记录整个 `quality_annotation_events` 表的初始行数，创建会话并启动运行宿主。参考 [数据集与会话启动 ↗](../../../scripts/quality-lark-annotate.ts#L52 "支持导入 dev 评测数据集、配置目标样本数、记录事件基线并启动标注会话。") 当前会话出现消息 ID 时，可确认该会话已有卡片消息；但“收到标注”仅由全表事件总数增长触发，查询没有按会话、数据集或当前样本过滤。其他并发标注活动也可能满足条件，因此该信号不能证明新增事件属于本次会话。参考 [卡片与全局事件判定 ↗](../../../scripts/quality-lark-annotate.ts#L76 "支持当前会话消息 ID 的观察方式，并表明成功退出判据是未按会话或数据集过滤的全表事件计数增长。")

<a id="boundaries"></a>
## 失败条件与验收边界

启动前必须提供文档地址和加密密钥，可选飞书应用 ID 还需符合格式要求。参考 [运行输入与凭据要求 ↗](../../../scripts/quality-lark-annotate.ts#L19 "支持脚本需要飞书文档地址、加密密钥，并校验可选应用 ID 的前置条件。") 轮询先检查全局事件计数，再检查当前会话关联投递的状态；因此，只有在未先因全局事件增长而退出的轮询中，检测到投递进入失败、未知或取消终态才会报错。等待结束时，若始终没有消息 ID，则判为卡片未送达；到达截止时间则判为等待超时。运行宿主和本地存储最终都会关闭。参考 [投递检查与资源清理 ↗](../../../scripts/quality-lark-annotate.ts#L125 "支持投递终态检查位于全局事件成功判定之后，以及卡片未送达、等待超时和最终资源清理的处理顺序。")

一次零退出最多说明：当前会话曾出现卡片消息，并且等待期内全局标注事件数有所增加。并发事件增长甚至可能掩盖本会话的投递失败；脚本也不确认当前样本完成标注、标签合法、重复提交幂等或整批数据集处理完毕。参考 [卡片与全局事件判定 ↗](../../../scripts/quality-lark-annotate.ts#L76 "支持当前会话消息 ID 的观察方式，并表明成功退出判据是未按会话或数据集过滤的全表事件计数增长。")
