# Lark 质量数据集的实时人工标注入口

该脚本导入 Lark 文档为仅评估用途的开发集，启动加密凭据支持的 Lark 标注运行时，等待卡片送达及首个标注事件，并明确处理投递失败、超时和资源清理。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="configuration"></a>
## 输入与运行配置

命令要求提供 Lark 文档 URL，并从环境变量或密钥文件取得加密存储密钥；可选应用 ID 必须符合 `cli_` 前缀格式。随后读取 Lark 文档，打开数据 Store，构造加密 Secret Store、官方注册与能力探测、已有应用提供器以及轮询间隔为 500 毫秒的运行主机。[Lark 输入、密钥与运行主机配置 ↗](../../../scripts/quality-lark-annotate.ts#L19 "支持文档 URL、密钥、应用 ID 校验，以及 Store、加密秘密和 Lark 运行主机的初始化。")

<a id="session"></a>
## 数据导入与标注会话

文档以 `QUALITY_EVAL_ONLY` 明确选择评估用途，导入为 `dev` split；数据集名称和目标样本数可由环境变量调整。脚本记录既有标注事件数量，启动指定数据集的会话与运行主机，并可通过配置要求重发卡片。[评估数据导入与会话启动 ↗](../../../scripts/quality-lark-annotate.ts#L52 "支持仅评估导入、dev split、样本目标、重发选项和运行主机启动流程。") 这条链路面向真实 Lark 交互，不是离线 fixture。

<a id="waiting"></a>
## 等待、失败与清理

循环读取会话状态；首次取得消息 ID 时报告卡片已发送，发现新增标注事件后输出数据集进度并成功结束。[卡片送达与标注事件检测 ↗](../../../scripts/quality-lark-annotate.ts#L76 "支持卡片发送状态、首个新增标注事件和标注进度的输出逻辑。") 若最近投递进入失败、未知或取消状态，脚本携带最近错误抛错；未送达或超过等待期限也会失败。无论结果如何，最终都会停止运行主机并关闭 Store。[投递失败、超时与资源清理 ↗](../../../scripts/quality-lark-annotate.ts#L125 "支持失败状态判断、未投递和等待超时错误，以及最终停止主机和关闭 Store。")
