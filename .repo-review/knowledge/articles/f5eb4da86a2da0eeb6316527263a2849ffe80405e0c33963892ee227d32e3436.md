# 飞书质量数据集的人工标注联调入口

该脚本把指定飞书文档转换为研究用质量样本，启动真实飞书卡片标注会话，并持续等待卡片送达及首次人工标注。它是显式运行的联调与评测工具，不属于普通材料捕获链路。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-boundary"></a>
## 解决的问题与使用边界

该脚本用于验证“飞书文档生成研究样本—发送标注卡片—接收人工判断”整条真实链路。操作者必须提供文档 URL 和密钥；可选应用 ID 还会经过格式校验，避免以明显无效的凭据启动会话。参考 [启动参数校验 ↗](../../../scripts/quality-lark-annotate.ts#L19 "支持脚本要求文档地址、密钥并校验可选飞书应用 ID 的说明。")

这里生成的样本只服务人工评测：导入器会用规则拆分文本并产生待审核草稿，明确不得接入普通 capture、CLI 导入或学习流程。因此它不是生产知识摄取入口，人工标注结果也不能被理解为普通材料已自动形成可信知识。参考 [评测导入边界 ↗](../../../apps/server/src/quality/import.ts#L1 "说明规则拆分器仅用于人工标注研究集，禁止进入普通捕获与学习流程。")

<a id="runtime-flow"></a>
## 从文档到标注事件的运行流程

脚本先读取飞书文档，建立 SQLite Store、加密密钥仓库、记忆服务和飞书运行宿主；Onboarding 同时接入官方注册能力与已有 Botmux 应用提供器，使运行时既可处理注册，也可复用已有应用凭据。参考 [运行依赖组装 ↗](../../../scripts/quality-lark-annotate.ts#L32 "支持脚本创建 Store、密钥仓库、Onboarding、记忆服务和飞书运行宿主的流程。") [已有飞书应用接入 ↗](../../../apps/server/src/integrations/lark/existing-apps.ts#L26 "说明 Botmux 提供器负责读取和校验可复用飞书应用凭据，是 Onboarding 的可选依赖。")

```mermaid
flowchart LR
  A[读取飞书文档] --> B[导入评测数据集]
  B --> C[创建标注会话]
  C --> D[启动飞书运行宿主]
  D --> E[等待卡片送达]
  E --> F[等待人工标注事件]
```

导入固定使用评测专用标识，随后记录事件表初始数量、创建会话并启动宿主。轮询中一旦会话获得消息 ID，就输出卡片已发送；事件总数增加后，再输出数据集进度并结束等待。参考 [数据集与会话启动 ↗](../../../scripts/quality-lark-annotate.ts#L52 "支持评测专用导入、创建标注会话并启动运行宿主的顺序。") [卡片送达检测 ↗](../../../scripts/quality-lark-annotate.ts#L73 "支持脚本轮询会话并在获得消息 ID 后报告卡片已发送。")

<a id="failure-and-limits"></a>
## 失败处理、清理与未覆盖行为

等待过程有三类显式失败：会话记录消失、最近一次投递进入 failed／unknown／cancelled，以及卡片始终未送达或等待超时。无论成功还是抛错，finally 都会停止运行宿主并关闭 Store，避免遗留轮询任务或数据库连接。参考 [标注事件与投递失败 ↗](../../../scripts/quality-lark-annotate.ts#L102 "支持通过事件数变化判定收到标注，并处理投递终态和等待超时。") [运行资源清理 ↗](../../../scripts/quality-lark-annotate.ts#L141 "说明脚本无论正常完成还是失败都会停止宿主并关闭存储。")

该文件是可执行联调脚本而非测试文件：它以真实消息 ID、数据库事件增长和退出码作为行为信号，但没有断言标注内容、标签正确性或多会话隔离。Store 的材料只证明底层为单用户 SQLite 基础，不能据此推断团队租户隔离已经实现。参考 [单用户 SQLite 基础 ↗](../../../apps/server/src/store.ts#L4 "支持 Store 使用 SQLite、执行迁移并初始化仓储组件，同时明确团队权限仍属后续迁移。")
