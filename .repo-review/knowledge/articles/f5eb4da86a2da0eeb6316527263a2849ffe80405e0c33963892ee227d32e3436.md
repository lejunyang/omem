# 通过 Lark 卡片进行质量集实时标注

该脚本导入只用于评估的 Lark 数据集，启动带加密凭据的 Lark 运行主机，发送标注卡片并等待首个新增事件，同时区分投递失败、未送达和等待超时。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="configuration"></a>
## 输入、密钥与运行组件

命令要求提供 Lark 文档 URL，并从环境变量或密钥文件取得加密密钥；可选 App ID 必须符合 `cli_` 前缀格式。随后读取 Lark 文档，创建 Store、加密密钥库、注册与能力探测组件、已有应用提供器，以及绑定 MemoryService 的 Lark 运行主机。[Lark 标注运行配置 ↗](../../../scripts/quality-lark-annotate.ts#L19 "支持文档 URL、密钥和 App ID 校验，以及 Store、onboarding 与运行主机的组装。") 这是依赖真实外部配置的集成流程。

<a id="session"></a>
## 数据集导入与会话启动

脚本以明确的 `QUALITY_EVAL_ONLY` opt-in 导入 dev split，默认数据集名为 `merchant-center-dev-v1`、目标数量为 40，并允许环境变量覆盖。它先记录已有标注事件数，再启动质量标注会话和运行主机；`resend` 仅在对应环境变量为 `1` 时启用。[评估数据集与标注会话 ↗](../../../scripts/quality-lark-annotate.ts#L52 "支持只用于评估的导入、dev split、目标数量、事件基线与会话启动配置。")

<a id="wait-and-failure"></a>
## 等待、进度与失败边界

轮询默认最长一小时，每 500 毫秒读取会话、事件和最新投递意图。获得 message id 时报告卡片已发送；检测到事件总数增加时输出仓库进度并成功结束。[投递与标注事件轮询 ↗](../../../scripts/quality-lark-annotate.ts#L73 "支持卡片就绪、首个新增事件、投递终态错误，以及未送达和已送达后等待超时的区别。") 投递进入 failed、unknown 或 cancelled 会立即报错；截止前始终没有 message id 时抛出未送达错误，已经送达但始终没有新增事件则抛出等待超时。最终始终停止 host 并关闭 Store。当前成功条件只是收到至少一个新增事件，并不等同于整份数据集完成。
