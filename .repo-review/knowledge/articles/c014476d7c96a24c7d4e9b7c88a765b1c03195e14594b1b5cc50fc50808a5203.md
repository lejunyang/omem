# SQLite 迁移与应用事务验收测试

验证旧数据库无损升级、迁移中断回滚与重启幂等、未来版本拒绝写入，以及知识或任务应用失败时整组业务记录原子回滚。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="preservation"></a>
## 旧数据无损升级与兼容读取

测试手工创建版本 1 数据库，包含两版 source、固定 fragment、跨版本引用、图片资产和带版本号的任务，再由 `Store` 自动迁移到版本 14。断言标识、不可变旧正文、资产字节、引用边、任务版本、head 与 validity epoch 全部保留，且外键检查无错误；随后通过旧有 revision 和 task API 再次读取，确认迁移不只满足表结构，还维持应用层兼容性。[版本 1 数据无损迁移与 API 兼容断言 ↗](../../../apps/server/tests/migrations.test.ts#L148 "支持旧标识、字节、修订、引用、资产、任务和 API 读取均被保留的说明。")

<a id="migration-safety"></a>
## 中断、重启与版本边界

迁移钩子在提交前制造中断时，当前版本的结构变化和迁移记录整体回滚；重新启动可从版本 1 以及多个中间可部署版本继续升级，多次打开不会重复扩张 schema。测试还抽查 Lark 目标状态、delivery intent 关联和后续新增表的数据修复结果。[迁移中断回滚、续升与幂等断言 ↗](../../../apps/server/tests/migrations.test.ts#L252 "支持事务回滚、从多个中间版本继续升级及数据修复的说明。") 若数据库版本高于程序支持值，`Store` 抛出专用错误，文件字节、版本号和未知表保持原样，避免旧程序破坏新数据。[未来数据库版本拒绝修改断言 ↗](../../../apps/server/tests/migrations.test.ts#L616 "支持不受支持的新版本数据库保持逐字节不变的安全边界。")

<a id="application-atomicity"></a>
## 业务应用与 outbox 原子性

应用 memory 或 task 时，实体、修订、应用回执、change、通知和 delivery intent 属于同一事务。触发器在 change 或 outbox 写入处故障，所有前序写入均回滚；移除故障后首次应用成功，相同请求重放返回同一回执并标记 duplicate，各表仍只有一行。[业务应用和 outbox 原子回滚断言 ↗](../../../apps/server/tests/migrations.test.ts#L647 "支持实体、修订、回执、通知与投递意图同事务，以及成功重放幂等的说明。") 这些测试覆盖 SQLite 单库事务与固定版本 1–14 的迁移路径，但未覆盖真实超大库的耗时、磁盘写满、进程在 fsync 时被杀、备份恢复及两个应用实例同时执行迁移。
