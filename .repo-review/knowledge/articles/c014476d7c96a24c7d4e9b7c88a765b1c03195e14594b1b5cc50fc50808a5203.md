# 数据库升级与事务一致性验收

该测试以真实 SQLite 文件覆盖旧库升级、迁移中断恢复、多个中间版本续升、未来版本拒写，以及记忆与任务应用的原子提交和幂等重放，确保历史证据不被破坏且失败不会留下部分写入。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 保护历史数据与既有读取能力

这组验收测试关注数据库演进是否会损坏个人记忆。它构造带真实数据的版本 1 旧库，再通过 `Store` 启动升级；升级后核对固定修订与片段身份、原始正文 bytes、图片资产、引用边、任务版本、当前源状态和外键完整性，确认不可变证据及其关联仍被保留。参考 [旧库数据保留断言 ↗](../../../apps/server/tests/migrations.test.ts#L149 "支持升级后固定身份、历史正文、图片资产、引用关系、任务版本、源状态和外键完整性均被验证。")

测试还通过应用 HTTP 路由读取旧修订和任务，证明验收不止检查底层表结构，也覆盖历史数据在升级后仍能被现有接口访问。参考 [历史数据接口读取 ↗](../../../apps/server/tests/migrations.test.ts#L219 "支持旧修订和旧任务在升级后仍可通过现有 HTTP API 读取。")

<a id="migration-recovery"></a>
## 迁移中断后的回滚与续跑

测试借助提交前钩子在版本 2 前主动抛错，随后确认数据库仍处于版本 1，迁移记录表和新增任务字段均未残留；重新创建 `Store` 后可完整升级到版本 18，再次启动时迁移数量和 schema 对象数量保持不变，验证事务回滚与重启幂等。参考 [中断回滚与重启幂等 ↗](../../../apps/server/tests/migrations.test.ts#L252 "支持迁移失败不遗留部分 schema，并且后续启动可完成升级、重复启动不重复扩张结构。")

它进一步从多个已部署中间版本续升：版本 2、3、4、5、6 路径分别抽查 jobs 字段、运行请求、策略评估、飞书接入与卡片动作结构；版本 7、8、10 路径又验证飞书目标状态修正、投递意图关联回填和会话表创建。该结论替代先前仅用后半段引用概括全部中间版本的表述；这些用例证明明确列出的升级路径可续跑，但不代表所有历史数据组合均被穷举。参考 [版本二至六续升检查 ↗](../../../apps/server/tests/migrations.test.ts#L303 "支持从版本 2 至 6 继续升级，并分别检查 jobs、运行请求、策略评估、飞书接入和卡片动作结构。") [版本七至十续升检查 ↗](../../../apps/server/tests/migrations.test.ts#L464 "支持版本 7 的飞书目标修正、版本 8 的投递关联回填，以及版本 10 升级后的会话表创建。")

<a id="safety-boundaries"></a>
## 拒绝未来库与保证业务原子性

当数据库版本高于程序支持范围时，`Store` 会抛出专用错误；测试同时比较文件 bytes、版本号、标记数据及迁移表不存在，确认拒绝打开不会改写未来数据库。参考 [未来版本无损拒写 ↗](../../../apps/server/tests/migrations.test.ts#L616 "支持高于受支持版本的数据库被拒绝，且文件内容、版本和既有数据保持不变。")

业务写入测试则用 SQLite 触发器分别制造变更记录和投递 outbox 失败，断言记忆或任务、修订、应用回执、变更、通知及投递意图整体回滚；故障移除后，同一任务首次应用成功，重复应用返回同一实体与变更并标记重复，数据库只保留一组记录。参考 [应用事务与幂等重放 ↗](../../../apps/server/tests/migrations.test.ts#L647 "支持记忆或任务应用在变更和 outbox 失败时整体回滚，并在成功后对重复请求去重。")

这些场景通过构造 `Store` 触发迁移；源码显示迁移成功后才初始化应用、任务、输入、运行请求和来源配置仓储，初始化失败时会关闭数据库并继续抛错。参考 [存储启动迁移流程 ↗](../../../apps/server/src/store.ts#L38 "解释测试为何通过创建 Store 触发迁移，以及只有迁移成功后才初始化各业务仓储。")
