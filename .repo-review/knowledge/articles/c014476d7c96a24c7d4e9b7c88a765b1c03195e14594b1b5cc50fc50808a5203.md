# 数据库迁移与事务一致性验收

该测试以真实 SQLite 文件验证旧数据库升级到当前版本时的数据兼容、迁移原子性与重启幂等性，同时覆盖未来版本拒写和应用写入的整事务回滚。它连接 Store、迁移器、应用仓储与 HTTP 读取接口，但不等同于覆盖每个迁移版本的全部数据语义。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="legacy-fixture"></a>
## 从真实旧库形态开始验收

测试先定义版本 1 的旧表结构以及固定的修订、片段、引用、任务和图片标识，形成可重复核对的升级基线。参考 [版本 1 旧库基线 ↗](../../../apps/server/tests/migrations.test.ts#L37 "支持测试定义旧表结构以及固定修订、片段、引用、任务和图片标识的说明。")

夹具随后创建真实 SQLite 文件与图片资产，写入前后两代修订、对应片段、跨片段引用边和关联旧证据的任务。因此，迁移验收能够发现历史身份重建、原始正文或图片丢失、引用断裂及任务版本变化。参考 [历史数据夹具 ↗](../../../apps/server/tests/migrations.test.ts#L60 "支持夹具实际创建图片资产，并写入两代修订、固定片段、引用边和任务的论断。")

每个场景使用独立临时目录，并在用例结束后递归清理，避免测试之间共享数据库状态。参考 [隔离临时数据库 ↗](../../../apps/server/tests/migrations.test.ts#L25 "支持每个测试创建独立临时目录并在用例结束后清理的说明。")

<a id="compatibility"></a>
## 升级后仍可读取历史证据

打开旧库后，`Store` 将模式升级到版本 18。测试不只检查版本号，还核对旧修订与片段身份、原始正文、图片字节、引用边、任务版本、当前修订、来源状态及外键完整性。参考 [旧数据升级断言 ↗](../../../apps/server/tests/migrations.test.ts#L162 "支持升级至版本 18 后核验历史身份、正文、资产、引用、任务、来源状态及外键完整性。")

升级后的数据库还会交给真实应用实例，通过 HTTP 路由读取旧修订与任务。这说明兼容目标覆盖仓储层和既有接口，而不只是让旧表继续存在。参考 [旧接口兼容读取 ↗](../../../apps/server/tests/migrations.test.ts#L219 "支持通过应用 HTTP 路由继续读取迁移后的旧修订和任务。")

<a id="migration-safety"></a>
## 迁移失败、重启与版本边界

迁移在提交前被注入异常时，本轮新增结构和版本号必须整体回滚；重新打开数据库可继续完成升级，再次启动则保持迁移记录和结构数量不变。参考 [回滚与重启幂等 ↗](../../../apps/server/tests/migrations.test.ts#L252 "支持迁移中断回滚、重新启动完成升级以及再次启动不重复改变结构的论断。")

```mermaid
flowchart LR
  A[旧数据库] --> B[逐版本迁移]
  B -->|提交失败| A
  B -->|提交成功| C[版本 18]
  C --> D[再次启动保持不变]
```

中间版本场景还核验了飞书目标由绑定状态推导出的启用或禁用结果，参考 [飞书目标状态迁移 ↗](../../../apps/server/tests/migrations.test.ts#L464 "支持从版本 7 升级后依据绑定状态调整飞书目标启用状态的数据变换。")；版本 8 的投递意图则在升级后补建与变更记录的关联，参考 [投递关联迁移 ↗](../../../apps/server/tests/migrations.test.ts#L543 "支持从版本 8 升级后为既有投递意图补建变更关联的说明。")。如果数据库版本高于程序支持值，系统会拒绝打开，并保持文件字节、版本号和原有标记表不变。参考 [未来版本拒写 ↗](../../../apps/server/tests/migrations.test.ts#L616 "支持高于当前支持版本的数据库被拒绝且文件内容、标记表和版本号保持不变。")

<a id="application-atomicity"></a>
## 业务写入与通知必须同成同败

测试用 SQLite 触发器分别让变更记录和投递发件箱写入失败，确认记忆或任务、修订、应用回执、变更、通知及投递意图都不会留下部分结果。移除故障后，同一任务首次应用成功，重复应用返回重复回执，并且各业务表只保留一组记录，从而验证应用级事务与幂等性。参考 [应用事务与重复提交 ↗](../../../apps/server/tests/migrations.test.ts#L647 "支持记忆和任务应用失败时整体回滚，以及成功重放只产生一组业务记录的断言。")

该场景只模拟同一数据库连接上的两个写入故障点；进程崩溃、磁盘耗尽、多连接竞争以及外部通知实际发送失败不在本文件的证明范围内。
