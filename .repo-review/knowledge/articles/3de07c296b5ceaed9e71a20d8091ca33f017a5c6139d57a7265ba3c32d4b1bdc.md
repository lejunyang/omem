# Lark 通知投递、聚合与重试状态机

该模块消费数据库中的 Lark 投递意图，负责飞书或 Lark 互动卡片的窗口聚合、租约抢占、凭据读取、发送与结果落库。限流错误在五次尝试上限内重试；结果不明仅在首次发送后一小时的提供方去重窗口内重试，超窗后进入 unknown。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="adapter-and-errors"></a>
## 外部适配与错误分类

官方适配器按租户品牌选择飞书或 Lark 域名，将调用方传入的卡片、会话目标和 UUID 交给 SDK；响应缺少消息 ID 时按结果不明处理。它也实现了消息原位更新接口。[官方 Lark 消息适配器 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L113 "支持适配器选择平台域名、接受调用方 UUID、发送互动卡片、处理缺失消息 ID，并实现消息更新接口的论断。") 当前 Worker 从租约取得 `providerUuid` 并传给适配器，因此可确认实际发送沿用投递记录中的 UUID；但材料未说明普通意图最初如何生成该值。[单任务投递 Worker ↗](../../../apps/server/src/integrations/lark/delivery.ts#L598 "支持 Worker 从租约读取 providerUuid 并传给发送适配器，以及凭据读取、校验和结果回写的端到端编排。") 聚合摘要是已确认的例外：聚合器依据模式、绑定、目标及变更集合重新计算 UUID，稳定摘要算法通过递归排序对象键、忽略 `undefined` 并计算 SHA-256 保证确定性。[通知窗口聚合器 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L461 "支持聚合分组、摘要卡生成、成员取消、载荷限制，以及聚合时按模式、绑定、目标和变更集合重建提供方 UUID。")[稳定摘要算法 ↗](../../../apps/server/src/storage/digest.ts#L3 "解释聚合载荷摘要与确定性 UUID 所依赖的规范化 JSON 和 SHA-256 算法。") 这替代了“所有新消息都由本模块现场生成稳定 UUID”的过宽结论。

错误分为限流、认证、永久失败和结果不明，并解析 `Retry-After`；5xx 与常见传输异常归入结果不明，错误消息中的客户端密钥会被清除。[Lark 错误分类与脱敏 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L56 "支持限流、认证、结果不明和永久失败的分类，以及 Retry-After 解析和敏感信息清除。")

<a id="lease-and-retry"></a>
## 租约并发与重试状态机

仓储在即时事务中选择到期任务或租约已过期的发送中任务，经带旧状态条件的更新抢占任务，生成租约令牌并记录尝试；连接、绑定或标注会话失效时会先失败或取消相应意图。[投递租约抢占事务 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L190 "支持到期任务选择、失效状态抑制、条件抢占、租约生成及尝试记录流程。") 成功回写必须匹配当前租约令牌，并把平台消息 ID 传播到投递记录、卡片动作和标注会话。[投递成功回写 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L353 "支持当前租约令牌校验，以及消息 ID 向投递记录、卡片动作和标注会话传播。")

失败策略区分两类重试：限流错误只受尝试次数少于五次约束；结果不明还必须处于首次发送后一小时内。超窗的歧义结果进入 `unknown`。认证错误会停用目标、将连接标为失败，并终止同一连接中处于 `pending` 或 `retry_wait` 的其他意图；它不会在这里批量改写其他正在 `sending` 的意图。[失败重试与认证故障处置 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L389 "支持限流与歧义结果的不同重试条件，并准确限定认证错误只批量终止同连接中 pending 或 retry_wait 的其他意图。") 这同时更正了“认证错误终止同连接全部未完成任务”和“一小时窗口也约束限流重试”的旧表述。

<a id="aggregation"></a>
## 通知窗口聚合

聚合器按工作区、绑定、目标和聚合模式收集到期意图。单个意图且仅关联一项变更时转为即时发送；多项变更则以最早意图为主记录生成摘要卡，重写变更映射，并把其余成员标为已聚合取消。映射缺失或卡片超过 30 KB 会使事务回滚。[通知窗口聚合器 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L461 "支持聚合分组、摘要卡生成、成员取消、载荷限制，以及聚合时按模式、绑定、目标和变更集合重建提供方 UUID。")

摘要卡的载荷摘要和聚合场景的提供方 UUID 都依赖稳定摘要。规范化过程递归排序对象键并过滤 `undefined`，随后对规范 JSON 计算 SHA-256，因此结果不受对象键插入顺序影响。[稳定摘要算法 ↗](../../../apps/server/src/storage/digest.ts#L3 "解释聚合载荷摘要与确定性 UUID 所依赖的规范化 JSON 和 SHA-256 算法。")

<a id="worker-and-boundaries"></a>
## Worker 编排、安全边界与验证缺口

Worker 每次领取一个租约，通过其中的 `secretRef` 读取凭据，核对 appId、载荷摘要和 30 KB 上限后调用发送接口，再由仓储写入成功或失败状态。[单任务投递 Worker ↗](../../../apps/server/src/integrations/lark/delivery.ts#L598 "支持 Worker 从租约读取 providerUuid 并传给发送适配器，以及凭据读取、校验和结果回写的端到端编排。") 凭据存储要求 32 字节主密钥、受限目录权限和固定引用格式。[加密凭据存储初始化约束 ↗](../../../apps/server/src/integrations/lark/secret-store.ts#L22 "支持主密钥长度、环境变量来源、目录权限和凭据引用格式的安全边界。") 当前材料只能证明这条投递路径以引用读取凭据，不能据此断言数据库其他位置绝不保存密钥。

材料未展示调度循环、意图创建入口、表结构或测试，因而不能确认运行频率，也不能声称并发与故障路径已有自动化覆盖。条件抢占和非活动标注会话守卫说明应重点验证双 Worker 竞争、租约过期重领、旧令牌回写及取消竞态。[租约竞争与会话抑制守卫 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L272 "为需要验证的条件抢占、租约竞争和非活动标注会话发送抑制行为提供源码依据。")
