# docs-implementation · 模块理解 · 专题 4

本专题以文档顶部更新和最新复审为当前基线，说明主助手、知识治理与 Code Wiki 的已实现流程，并区分真实验证、fixture 覆盖和历史记录；独立语义复核、下游自动重核验及真实外部链路仍待完成。

<a id="baseline"></a>
## 职责与当前基线

本模块回答“当前实际实现并验证了什么”，不能把架构设想、历史统计或生成成功直接视为交付。现行能力包括共用正文与引用合同、持久分析和独立复核、个人知识入口、多层引用及原始证据召回；失败、过期或未生成的结果不计完成。[当前能力与完成口径 ↗](../../../docs/implementation/status.md#L1 "支持本模块采用页面顶部的现行能力作为基线，并说明失败、过期或未生成内容不得计为完成。") 2026-09-29 的复审中，冻结依赖、全量检查、浏览器场景和全新 SQLite 重建均取得成功退出结果；但六份真实模型说明仍为 `verified_by_agent=false`，生成成功不等于语义核验完成。[最新本机复审结果 ↗](../../../docs/implementation/status.md#L7 "支持依赖、全量检查、浏览器和全新数据库重建的实际退出结果，同时说明真实模型说明尚未独立核验。")

<a id="assistant-governance"></a>
## 助手与知识治理流程

Web 与飞书生产路径已装配 ACP 模型适配器、关键词检索和限定范围的纠正服务；模型不可用时记录异常并保持零伪引用、零伪任务，任务创建还受意图识别与 MemoryService 治理。[主助手生产装配 ↗](../../../docs/implementation/status.md#L29 "支持 Web 与飞书路径已接 ACP、关键词检索和纠正服务，以及模型异常和任务意图的治理行为。") 知识治理的当前能力包括整批 ChangeSet 影响门禁、冲突与刷新记录，以及 proposal、policy、receipt 的原子应用。[知识治理能力矩阵 ↗](../../../docs/implementation/status.md#L51 "直接支持整批影响门禁、冲突与刷新记录，以及 proposal、policy、receipt 原子应用这一组合论断。") 具体到来源修订，系统会建立 `needs_review` 刷新记录并停用受影响的 active evidence。[来源更新影响处理 ↗](../../../docs/implementation/status.md#L73 "支持来源修订会生成 needs_review 刷新记录，并使受影响记忆停止作为 active evidence。") 不过 `refresh_dependents` 随后仍主动以未实现错误失败，extractor 与 verifier 的完整重跑尚未交付。[下游重核验缺口 ↗](../../../docs/implementation/status.md#L86 "说明 refresh_dependents 当前仅记录影响后主动失败，不能视为已经完成 extractor 与 verifier 重跑。")

<a id="code-wiki"></a>
## Code Wiki 与统一证据链

Code Wiki 不是独立事实系统，而是统一 Capture→Source/Revision/Fragment→Relation/Retrieval 链上的代码投影。确定性代码图、手工登记关系和多层引用阅读已形成纵向切片；解析不到的锚点保留为 missing，未登记的词语相似不会自动变成 confirmed。[Code Wiki 定位与关系规则 ↗](../../../docs/implementation/status.md#L32 "说明 Code Wiki 属于统一证据链，并支持确定性代码图、手工关系状态和缺失锚点可见的当前行为。") 当前仍不解析跨文件调用，也没有跨 revision 身份续接、embedding 检索或完整下游重核验；代码变化后需要重新同步，使 locator 在新 head 上重新定位。[代码知识切片边界 ↗](../../../docs/implementation/status.md#L41 "支持跨文件调用、跨版本身份续接、语义检索及下游重核验尚未交付。")

<a id="verification-limits"></a>
## 验证边界与被替代结论

顶部新记录确认本机已有 traecli，并完成指定范围的真实模型生成，因此后文“本机无 traecli”“没有模型 live”和固定端口等环境结论已被替代。[最新模型环境记录 ↗](../../../docs/implementation/status.md#L5 "顶部记录明确替代后文关于无 traecli、无模型 live 和固定端口的旧环境结论。") 这不自动证明主助手 ACP 对话或飞书 WebSocket 已端到端验收：图片下载目前仅由 fake transport 验证，断网恢复与真实限流窗口仍是缺口。[飞书真实网络验证边界 ↗](../../../docs/implementation/status.md#L52 "支持图片仅由 fake transport 验证，以及断网恢复和真实限流窗口仍未验收。") Batch 2 清单只用于历史追溯；当前仍是 TypeScript 与 SQLite 的个人单用户实现，不具备多租户 ACL、分布式事务或跨版本语义片段续接。[历史记录与实现取舍 ↗](../../../docs/implementation/status.md#L99 "支持 Batch 2 仅供追溯，并说明个人单用户实现、多租户能力和跨版本身份续接的边界。")
