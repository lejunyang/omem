# docs-implementation：通用知识整理与仓库知识闭环

该模块把仓库文件、代码、图像、对话等材料纳入统一 Capture 证据链，通过材料分析、固定引用、独立复核、定向修订和分层组织形成可追溯知识。派生正文只负责解释与导航，事实依据始终回到固定原始材料；当前主要边界是全库覆盖尚未完成、跨文件调用和跨版本身份续接仍有限。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责与设计背景

本模块不是独立的代码知识库，而是面向多种 Capture 材料的共用知识整理层；仓库只承担输入适配，正文、引用、疑问、角色运行和任务记录复用同一机制。[通用知识整理的共用范围 ↗](../../../docs/implementation/knowledge-pipeline.md#L1 "支持仓库只是输入适配器，知识正文、引用、疑问、角色和任务记录供各类 Capture 材料共用。") `KnowledgeDocument` 以具名 Markdown 章节承载解释，引用紧贴对应论断；模型选择固定范围，宿主复制原文，独立角色判断语义支持性，因此定位正确并不等于论断已经成立。[正文与固定引用合同 ↗](../../../docs/implementation/knowledge-pipeline.md#L5 "支持内联引用、宿主复制固定原文以及独立角色负责语义复核的职责划分。") 原始事实仍归属于 Source、Revision 和 Fragment，派生知识不会再次成为独立原件；来源变化会使相关正文及其依赖章节过期，同时保留旧固定版本以供追溯。[不可变修订与原始证据边界 ↗](../../../docs/implementation/knowledge-pipeline.md#L9 "支持派生知识不成为独立原件、来源变化触发级联过期且历史固定版本仍可读取。")

<a id="pipeline"></a>
## 生成、复核与演进流程

流程先由材料角色分析，再交给独立会话复核；只有通过的正文才能发布，同批已通过内容可先保存，未通过内容继续修订，分析期间若来源变化则拒绝当前发布。[分析、独立复核与发布门槛 ↗](../../../docs/implementation/knowledge-pipeline.md#L23 "支持先分析后独立复核、通过后发布、未通过内容继续修订以及来源变化时拒绝发布。") 复核退回后会切换到专门的刷新角色，依据具体反馈局部修改；有限轮次结束时只保留有直接依据的陈述，其余转成明确问题，并且仍须重新通过独立复核。[复核退回后的定向修订 ↗](../../../docs/implementation/knowledge-pipeline.md#L61 "直接支持刷新角色依据复核反馈局部修改、保留有依据陈述并再次接受独立复核。") 仓库适配器处理 Git 可见材料并记录排除或失败原因，通过的结果保存为 JSON 与内联引用 Markdown，再组合为模块、主题和概览；局部生成、索引重建与模型调用边界明确分开。[仓库材料适配、恢复与可提交产物 ↗](../../../docs/implementation/knowledge-pipeline.md#L31 "支持仓库材料处理、分层产物、局部生成与索引重建的区别，并说明恢复测试及 coverage 口径。") 用户回答保存为新的有来源原始材料，并使相关知识进入重核对；疑问只有在用户明确选择后才转成待办。[用户回答触发知识重核对 ↗](../../../docs/implementation/knowledge-pipeline.md#L27 "直接支持用户回答作为原始材料保存、相关知识进入重核对，以及显式待办动作的边界。")

<a id="relations"></a>
## 跨模块协作、阅读与检索

材料、代码、对话、图像、规划、写作、复核和刷新角色共用既有运行时、版本化合同及任务存储；worker 按任务种类领取，避免知识整理、学习和通知任务互相抢占。[共用角色运行时与任务隔离 ↗](../../../docs/implementation/knowledge-pipeline.md#L15 "支持八类角色复用运行时和持久任务存储，并通过任务类型过滤避免不同 worker 抢占。") 个人知识与仓库知识共用证据阅读组件，引用可以逐层进入固定知识章节或原始材料，并保留返回、深链、滚动和焦点恢复等交互。[共享证据阅读链与浏览器验证 ↗](../../../docs/implementation/knowledge-pipeline.md#L45 "支持个人知识和仓库知识共用阅读组件，以及五层引用链、深链、视口和焦点行为的真实浏览器验证。") 检索可先命中派生正文，再沿固定引用返回原始 Fragment；正文只作导航，会话可见性过滤和当前来源复查仍然生效。[知识引导的原始证据召回 ↗](../../../docs/implementation/knowledge-pipeline.md#L55 "支持派生正文只用于检索导航，最终返回原始 Fragment，并继续执行可见性和来源新鲜度检查。") 因此 Code Wiki 是统一证据链在代码域的派生视图，而 repo-review 是隔离运行配置与阅读入口，不是新的事实权威。[Code Wiki 的统一证据链定位 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L1 "支持 repo-review 是隔离运行与阅读视图、可提交 Wiki 是统一证据链派生产物，而非第二套事实权威。")

<a id="progress_limits"></a>
## 验证范围、现存边界与被替代结论

材料记录了全量检查及真实浏览器对五层引用链、深链、视口和焦点行为的验证。[共享证据阅读链与浏览器验证 ↗](../../../docs/implementation/knowledge-pipeline.md#L45 "支持个人知识和仓库知识共用阅读组件，以及五层引用链、深链、视口和焦点行为的真实浏览器验证。") 仓库材料、知识恢复与开发生命周期也有回归覆盖，但全仓模型处理的完成数必须以当前 coverage 报告为准，失败项不能计作已生成。[仓库材料适配、恢复与可提交产物 ↗](../../../docs/implementation/knowledge-pipeline.md#L31 "支持仓库材料处理、分层产物、局部生成与索引重建的区别，并说明恢复测试及 coverage 口径。") 代码 Wiki 的历史切片还记录了真实模型生成、知识重建、依赖失效和两套浏览器脚本通过；这些只证明相应切片，不代表当前全库覆盖完整。[Code Wiki 历史验证记录 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L39 "支持历史切片曾完成真实模型生成、知识重建、依赖失效回归、全量检查和两套浏览器脚本验证。")

现有边界包括跨文件调用不解析、跨 revision 符号及 Fragment 身份不续接，以及单用户 SQLite 不具备多租户 ACL、分布式事务或 pgvector。[代码投影的技术边界 ↗](../../../docs/implementation/code-wiki-review-2026-09-29.md#L31 "支持跨文件调用、类型解析和跨 revision 语义身份续接尚未实现。")[单用户实施取舍 ↗](../../../docs/implementation/status.md#L124 "支持当前实现是个人单用户 SQLite，并明确不具备多租户 ACL、分布式事务和 pgvector。") 2026-09-29 复审中“仅关键词检索、下游自动重核验未完成”的结论已被后续中文向量检索与来源刷新闭环取代：当前固定中文向量模型和共享检索已经落地，`refresh_dependents` 也已进入 extractor、独立 verifier 与原子应用流程；旧结论仅保留为历史时点证据。[中文语义检索的后续进展 ↗](../../../docs/implementation/status.md#L3 "支持固定中文向量模型、共享检索和小样本验证已经落地，从而替代早期仅关键词检索的状态结论。")[来源更新重核验闭环 ↗](../../../docs/implementation/status.md#L5 "支持 refresh_dependents 已从未实现占位发展为 extractor、独立 verifier 和原子更新闭环，从而替代早期限制描述。")
