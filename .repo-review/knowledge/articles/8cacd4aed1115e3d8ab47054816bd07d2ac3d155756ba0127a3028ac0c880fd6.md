# 实施状态：能力闭环、验收边界与历史解释

本专题说明状态文档中的最新能力、统一知识流程、仓库评审定位及验收边界，并区分仍有效的架构限制与已被新实现替代的历史结论。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="current-capabilities"></a>
## 最新能力闭环

状态页首先承担当前事实入口的职责。中文检索已采用固定版 BGE-small-zh-v1.5 q8，按模型身份隔离分窗向量，并由个人助手、飞书助手与 repo-review 共用；四条同义问法 top-1 为 4/4 只证明小样本可行，reranker、ANN 与历史时点检索仍未实现。[中文语义检索最新进展 ↗](../../../docs/implementation/status.md#L1 "支持固定中文向量模型、共享检索、小样本结果及 reranker、ANN、历史时点检索等剩余限制。")

来源更新现已形成 Capture 记录失效范围、extractor 重提取、独立 verifier 核验及 MemoryService 原子应用的闭环；失败或证据不足继续保持 `needs_review`。日常助手也覆盖补搜、时区与事项创建、改期、完成、重新打开，但重复提醒和外部到期投递仍是缺口。[来源更新与日常助手闭环 ↗](../../../docs/implementation/status.md#L3 "支持来源重核验的提取、独立复核、原子应用流程，以及助手事项能力和提醒缺口。")

<a id="knowledge-review-flow"></a>
## 知识流程与仓库评审的关系

通用知识流程将正文、内联引用、角色分析、独立复核、问题与待办纳入共同合同，并允许派生知识引导回原始证据。逐文件处理结果记录在覆盖文件中，未通过、过期或未生成的材料不能算作完成；材料没有进一步保证固定的状态枚举。[通用知识流程当前能力 ↗](../../../docs/implementation/status.md#L9 "支持共用知识合同、独立复核、问题待办、原始证据召回及覆盖记录的完成度边界。")

Code Wiki 是统一 Capture→Source/Revision/Fragment→Relation/Retrieval 证据链在代码域上的投影，repo-review 只是隔离的开发配置和视图，并非另一套知识库。[Code Wiki 与统一证据链定位 ↗](../../../docs/implementation/status.md#L42 "直接支持 Code Wiki 属于统一证据链的代码投影，以及 repo-review 仅为隔离配置和视图的定位。") 启动负责重建或恢复已有材料、代码投影和版本化知识，默认不调用模型；遗留数据也仅在显式选择导入时进入。[评审配置与启动恢复策略 ↗](../../../docs/implementation/status.md#L11 "支持实际模型配置、runtime 重建、显式遗留导入，以及启动恢复与模型生成相互分离。")

<a id="verification-boundaries"></a>
## 验收结果与历史记录

真实模型曾生成限定范围的模块说明，但这些结果标记为未经过独立 agent 复核，不能等同于完整语义核验；当时记录的跨文件调用等能力也仍有限制。[模型说明与语义核验边界 ↗](../../../docs/implementation/status.md#L20 "支持真实模型说明仅覆盖指定范围、未经过独立 agent 复核，以及模型结果不等同于语义核验。") G15—G20 虽均有行为测试通过，但图片与富文本依赖 fake transport，进程恢复则由同一数据库上的新 runtime 实例模拟，不能外推为真实飞书网络或真实 kill/restart 已验收。[G15 至 G20 验收记录 ↗](../../../docs/implementation/status.md#L85 "支持相关场景通过，同时限定 fake transport 与模拟进程恢复的证据范围。")

页面保留的 2026-09-29 限制曾称 `refresh_dependents` 会主动抛出未实现错误。[已被替代的重核验限制 ↗](../../../docs/implementation/status.md#L94 "记录历史上 refresh_dependents 尚未实现的状态，用于说明该结论已被页首最新闭环替代。") 该结论已被 2026-10-01 的 extractor、verifier 与原子应用闭环替代；旧文字仅用于追溯，不应继续参与当前能力判断。

<a id="architecture-limits"></a>
## 长期底座与仍有效的边界

跨批次保持稳定的底座包括 TypeScript、Fastify、SQLite、Vue、统一 Capture 输入、版本化材料与不可变片段、引用链、事务化通知，以及 ACP 和多种 CLI 适配器。[跨批次基础能力 ↗](../../../docs/implementation/status.md#L122 "支持技术栈、统一 Capture、版本化证据、事务化通知与 ACP、CLI 适配等长期底座。") 当前实现明确面向个人单用户，不具备多租户 ACL、分布式事务或 pgvector；原件与回答可追溯，也不代表每项 Claim 已完成正式语义支持评估。[个人单用户实现取舍 ↗](../../../docs/implementation/status.md#L132 "支持单用户架构、多租户与分布式能力边界，并区分可追溯性和正式语义验证。")

跨 revision 的符号或 Fragment 身份续接仍未实现，代码变化后需重新同步，使 locator 在新 head 上重新定位；跨文件 calls 也尚不解析。[代码图跨版本边界 ↗](../../../docs/implementation/status.md#L51 "直接支持跨文件 calls 不解析、跨 revision 身份续接未实现及变更后重新同步的当前限制。") 历史行中“原文刷新依赖自动重核验未实现”的部分已经被最新闭环替代，不能与这些仍有效的限制混为一谈。
