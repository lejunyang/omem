# Repo-review 同步、修订与检索可靠性测试

系统性验证仓库文件同步的稳定来源身份、不可变修订、增量与脏工作树处理、检索和 API 安全、失败基线控制、关系锚点及新数据库重建。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="identity-revisions"></a>
## 来源身份、修订与删除

显式 `only` 同步可以导入真实代码文件，重复执行保持修订数不变，并能通过关键词检索。[显式文件同步与幂等检索 ↗](../../../apps/server/tests/review-sync.test.ts#L112 "支持单文件导入、重复同步不追加修订及关键词可检索。") 在夹具仓库中，内容相同但路径不同的文件仍是独立来源；内容变化会追加修订，旧版不再是 current，也不进入默认召回。删除文件则被标记为 removed，默认搜索排除它，只有显式 `includeRemoved` 才返回。[稳定来源、修订历史与删除状态 ↗](../../../apps/server/tests/review-sync.test.ts#L139 "支持相同内容不同路径保持独立、内容变更追加修订，以及删除来源默认不召回。") 这些断言确立了以路径来源为身份、以修订保存历史、以当前状态控制默认可见性的基本模型。

<a id="incremental-snapshot"></a>
## 增量范围与快照上下文

基线等于 HEAD 且工作树干净时不扫描；脏树会同时处理已修改跟踪文件和新文件，基线落后时还会覆盖已提交漂移与当前未提交内容。[增量与脏工作树扫描 ↗](../../../apps/server/tests/review-sync.test.ts#L233 "支持干净基线零扫描，以及提交漂移、跟踪修改和未跟踪文件均被覆盖。") 每个快照记录真实提交、dirty、内容摘要和同步时间；缺失基线提交触发全量重扫并产生警告，非 UTF-8 文件只记失败而不阻断其他文件，白名单外的符号链接目标不会被跟随。[快照元数据与异常文件安全 ↗](../../../apps/server/tests/review-sync.test.ts#L283 "支持提交和摘要上下文、缺失基线全扫、非 UTF-8 局部失败及符号链接边界。") 因此增量优化不能以静默漏扫或越界读取为代价。

<a id="retrieval-api"></a>
## 检索预过滤与 API 边界

类别过滤在大量架构结果占据关键词池时仍能返回唯一 decision，后续用超过 200 个干扰项的用例进一步证明过滤发生在受限候选池之前。[类别检索预过滤 ↗](../../../apps/server/tests/review-sync.test.ts#L465 "支持类别结果在大量其他类别命中占优时仍可返回，包括超过候选池上限的压力场景。") API 还拒绝无 token 时的跨源同步 POST，健康接口仅返回相对运行时目录，版本接口列出全部修订及 current 标记。[Review API 安全与版本接口 ↗](../../../apps/server/tests/review-sync.test.ts#L396 "支持跨源同步被拒绝、健康接口隐藏绝对路径，并列出修订 current 状态。") 这些测试覆盖检索正确性和接口信息暴露边界，但没有证明生产网络代理或外部认证配置。

<a id="baseline-relations"></a>
## 失败基线、关系锚点与重建

脏同步不会推进基线，恢复到 HEAD 后会重新扫描并撤销脏内容；存在失败文件时基线保持为空，修复后才推进到当前提交。[脏同步与失败文件的基线控制 ↗](../../../apps/server/tests/review-sync.test.ts#L527 "支持脏树或文件失败时不推进基线，并在恢复或修复后重新同步。") requirement 关系会落到各自标题片段，而不是共享概览表；决策日期取自文档，缺失时为 `unknown`，与同步时间相互独立。[需求锚点与决策日期 ↗](../../../apps/server/tests/review-sync.test.ts#L573 "支持关系指向各自需求标题片段，并区分文档决策日期和同步时间。") 最后，新数据库即使共享状态目录中已有干净基线，也会检测自身缺失来源并完整重建，避免把另一数据库的同步状态误当成本库完成。[新数据库强制重建 ↗](../../../apps/server/tests/review-sync.test.ts#L687 "支持同步状态不能替代数据库自身内容检查，新库缺少来源时仍会重新扫描。")
