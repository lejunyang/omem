# 统一检索的索引、混合召回与结果排序

UnifiedRetrieval 是读取器与 Agent 共用的检索编排层。它维护正文与概念向量索引，先执行访问范围过滤，再组合词法、代码导航和语义候选，经倒数排名融合、可选重排及结果多样化后输出 RetrievalHit；语义组件不可用时保留非语义路径，并兼容旧的原始证据接口。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 统一检索解决的问题

UnifiedRetrieval 是读取器与 Agent 的共同检索入口。它让 SQLite 中的检索单元共用过滤和排序逻辑；旧 source 接口再把结构化结果投影回不可变证据，避免维护另一套搜索结果。构造函数装配 RetrievalProjection 与 CodeNavigation，也允许注入 embedding 模型、交叉编码器和决策排序器。参考 [统一入口与依赖装配 ↗](../../../apps/server/src/retrieval/unified.ts#L66 "支持统一检索服务的职责、旧接口定位，以及构造函数注入和创建的协作组件。")

<a id="query-flow"></a>
## 一条查询如何经过多路召回

以 `search({ text: "统一检索如何融合语义和关键词", purpose: "implementation", limit: 20 })` 为讲解用输入：方法先同步投影，再取得词法、符号与材料概念候选；模型就绪时还会计算正文向量和概念向量候选，最后合并各路结果。参考 [普通查询召回编排 ↗](../../../apps/server/src/retrieval/unified.ts#L682 "支持普通查询同步投影、启动词法和结构化召回，并在语义可用时融合五类候选。")

```mermaid
flowchart LR
  Q[SearchQuery] --> F[范围过滤]
  F --> R[多路召回]
  R --> X[RRF 融合]
  X --> C[可选交叉编码器]
  C --> D[可选决策排序]
  D --> O[RetrievalHit]
```

RRF 只使用每条路线中的名次，避免直接比较 BM25、余弦相似度和符号命中的不同分值尺度，同时合并路线与命中范围。参考 [倒数排名融合 ↗](../../../apps/server/src/retrieval/unified.ts#L482 "支持按各路线名次累加 RRF 分数，并合并路线、摘录和命中范围。") 若调用方显式传入 `codeIntent`，查询会直接走定义或调用点导航并完成输出；自然语言推断出的 callers 若没有命中，则回到普通召回。参考 [代码导航分流 ↗](../../../apps/server/src/retrieval/unified.ts#L419 "支持显式代码意图的短路行为，以及推断 callers 无结果时回落普通检索。")

<a id="filter-and-ranking"></a>
## 范围约束与最终排序

候选进入排名前会检查材料角色、生效时间、任务状态、可信项目、类型、主题、可见性和时间范围；被排除的单元不会占用候选名额。参考 [候选资格过滤 ↗](../../../apps/server/src/retrieval/unified.ts#L305 "支持材料角色、生效区间、状态、项目、类型、主题、可见性和时间范围的过滤条件。") 材料角色与状态还会形成适用性权重，但未知角色仍可参与，显式角色查询也不会被该权重削弱。参考 [材料适用性权重 ↗](../../../apps/server/src/retrieval/unified.ts#L359 "支持角色和状态作为排序先验，以及未知或显式角色查询的例外。")

最终优先级会结合查询目的、代码定义命中、知识的新鲜度和适用性。默认结果还按来源限制条数，并按知识章节和正文指纹去重；调用点查询改为让不同文件的入口优先出现。输出保留目标、引用、来源路线、匹配行和可选重排信息。参考 [目的偏好与最终优先级 ↗](../../../apps/server/src/retrieval/unified.ts#L996 "支持查询目的、定义命中、新鲜度、适用性和跟进时效共同调整优先级。") [来源限制、去重与命中输出 ↗](../../../apps/server/src/retrieval/unified.ts#L1049 "支持调用点分散展示、普通来源条数限制、知识章节与正文指纹去重，以及 RetrievalHit 中保留的结构化字段。") 可选决策排序器只能从已过滤的候选池中选择；若返回 `advisoryOnly`，评估会附在原有排序上。参考 [决策排序约束 ↗](../../../apps/server/src/retrieval/unified.ts#L909 "支持决策排序仅处理已准入池、advisoryOnly 不改序，以及失败后回退。")

<a id="indexing-and-fallback"></a>
## 索引、降级与兼容边界

后台索引先补正文向量，再补带描述单元的概念向量；文本按窗口切分并分批嵌入，写入前在写锁内复核单元仍存在，向量与完成标记在同一事务提交。参考 [分批向量索引 ↗](../../../apps/server/src/retrieval/unified.ts#L221 "支持正文优先、概念随后、分窗嵌入和事务写入的索引流程。") 没有语义模型时仍可使用词法、符号和材料概念候选；正文语义失败会回退到这些路径，概念向量失败只清空该可选分支。参考 [语义召回降级 ↗](../../../apps/server/src/retrieval/unified.ts#L703 "支持未加载模型时继续非语义检索、概念向量局部降级和正文语义失败回退。") 交叉编码器加载或评分失败时保留既有候选。参考 [交叉编码器降级 ↗](../../../apps/server/src/retrieval/unified.ts#L819 "支持交叉编码器对候选段落评分、合成新分数，以及异常时保留既有结果。")

同步旧接口先处理代码导航；显式 `codeIntent` 会走 definitions 或 callers，自然语言推断的 callers 在有命中时也会短路普通召回。未命中导航时，同步旧接口只组合词法与符号检索；异步旧接口复用完整 `search`。两者最终从每个 reference 的可见片段中选出最相关的一项。参考 [代码导航分流 ↗](../../../apps/server/src/retrieval/unified.ts#L419 "支持显式代码意图的短路行为，以及推断 callers 无结果时回落普通检索。") [旧证据接口投影 ↗](../../../apps/server/src/retrieval/unified.ts#L1149 "支持同步旧接口先处理代码导航、未命中时组合词法与符号检索，并说明同步与异步旧接口的差异及证据片段投影。") `close()` 会停止定时器，等待投影与索引工作以及嵌入模型加载收尾，然后关闭当时已经赋给实例的嵌入模型和重排器；尚未完成的重排器加载不在等待范围内。参考 [检索资源关闭 ↗](../../../apps/server/src/retrieval/unified.ts#L1218 "支持停止后台工作，等待投影、索引与嵌入模型加载，并关闭当时已赋值的模型资源；该流程没有等待重排器加载。") 本文件调用的窗口切分、概念候选、候选池等算法由外部模块实现；目标材料只能说明它们在此处的接线方式，不能据此断言各模块的内部策略。参考 [外部检索组件 ↗](../../../apps/server/src/retrieval/unified.ts#L1 "支持本文件依赖窗口切分、概念候选、候选池、重排段落等外部模块的边界说明。")
