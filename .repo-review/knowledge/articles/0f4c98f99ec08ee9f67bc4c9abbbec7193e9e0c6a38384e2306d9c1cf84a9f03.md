# 统一检索：多路召回、分级排序与兼容投影

UnifiedRetrieval 是阅读器与 Agent 共用的检索编排器。它把内容投影为 RetrievalUnit，组合词法、代码符号和材料概念候选，并纳入正文与概念两类向量召回；候选可经过交叉编码器和外部决策排序，再按用途及多样性生成结构化命中。可选模型不可用或执行失败时，系统保留已有召回结果；旧 source 接口则把统一命中投影为不可变证据片段。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_index"></a>
## 统一检索解决什么问题

`UnifiedRetrieval` 让阅读器与 Agent 共用 `RetrievalUnit`，旧的 source 接口把同一套检索结果投影为不可变证据片段，供仍使用旧接口的处理器读取。构造函数连接 SQLite、检索单元投影和代码导航；嵌入模型、交叉编码器与外部决策排序器都是可选依赖。参考 [统一检索职责与依赖 ↗](../../../apps/server/src/retrieval/unified.ts#L84 "支持共用 RetrievalUnit、旧接口兼容投影，以及构造时连接投影和代码导航的说明。")

后台循环先同步投影，再补建向量索引。`indexBatch()` 默认取 8 个尚未完成当前模型索引的单元；正文向量补齐后，才会处理带材料描述的概念向量。一个单元的窗口按 16 个一组送入模型，返回数量须与输入一致。向量通过非零范数和有限数值检查并完成单位化，随后在写锁事务内落库；若写入前对应单元 ID 已不存在，本轮写入会回滚。参考 [后台同步与索引调度 ↗](../../../apps/server/src/retrieval/unified.ts#L139 "支持后台循环先同步投影、再分批索引，以及失败后退避重试的说明。")、[分窗嵌入与事务写入 ↗](../../../apps/server/src/retrieval/unified.ts#L227 "支持默认单元批量、正文与概念分阶段建索引、每组 16 个窗口及写锁事务行为。")、[向量校验与单位化 ↗](../../../apps/server/src/retrieval/unified.ts#L77 "支持嵌入向量的非零范数和有限数值检查，以及逐项单位化。")

## 一次普通查询如何得到结果

下面用 `{ text: "统一检索如何融合语义与关键词", purpose: "implementation", limit: 10 }` 作为教学示例。`search()` 先同步投影并检查代码导航捷径。普通查询会处理原查询及显式查询变体，每个文本分别召回，最后合并各次结果。空查询与精确查询不进入语义召回或交叉编码器；嵌入模型尚未加载时，检索继续使用词法、符号和材料概念候选。参考 [查询入口与变体召回 ↗](../../../apps/server/src/retrieval/unified.ts#L717 "支持代码导航捷径、查询变体逐次召回与合并，以及空查询、精确查询的分支。")

```mermaid
flowchart LR
  Q[SearchQuery 与查询变体] --> F[资格过滤]
  F --> R[词法/符号/材料概念/向量召回]
  R --> M[RRF 融合]
  M --> X[可选交叉编码器与决策排序]
  X --> O[多样化 RetrievalHit]
```

词法路线从 BM25 结果中保留最多 250 个通过资格检查的候选，并按材料适用性加权。后续行的分数上界已经无法超过池尾时，读取可以提前停止；未通过资格检查的行不会占用这 250 个位置。参考 [词法候选池与上界剪枝 ↗](../../../apps/server/src/retrieval/unified.ts#L613 "支持 BM25 候选的资格过滤、材料适用性加权、250 项上限和安全的提前停止条件。")

嵌入模型可用时，查询文本截到 400 个字符后生成向量。正文和概念语义路线都以 0.4 为准入线，按适用性重排后各保留最多 100 项。概念向量失败只清空该路线，正文向量仍可使用。最终融合纳入词法前 100 项、正文语义、符号、材料概念和概念语义候选。BM25、余弦相似度与符号查找的分数不可直接比较，融合只采用各路线中的名次，并合并路线、命中范围和片段。参考 [正文与概念语义召回 ↗](../../../apps/server/src/retrieval/unified.ts#L739 "支持模型未加载时的词面回退、查询截断、两类向量召回、独立降级、0.4 准入线与每路 100 项上限。")、[倒数排名融合 ↗](../../../apps/server/src/retrieval/unified.ts#L502 "支持各召回路线按名次融合，并合并片段、范围和路线信息。")

<a id="boundaries_and_outputs"></a>
## 过滤、降级与输出边界

候选首先按材料角色与有效期筛选，随后检查跟进事项状态和可信项目范围，并核对内容种类、主题前缀、可见性及时间范围。`follow-up` 会排除状态不再是 `open` 或 `waiting` 的事项。材料角色和状态还会形成导航权重，但未知来源保持完整资格；显式指定材料角色或请求背景材料时，不应用这层权重。参考 [候选资格与材料适用性 ↗](../../../apps/server/src/retrieval/unified.ts#L325 "支持范围过滤、follow-up 状态限制，以及材料角色和状态的导航权重边界。")

交叉编码器用 `candidatePool` 整理候选，每批最多处理 8 项，默认预算为 20 秒。它先给每个候选一个窗口的评分机会，再处理长内容的后续窗口。取消信号继续向外抛出；预算耗尽或评分失败时，已经完成的评分得到保留，未评分项保留原召回信息，并记录未评分原因。模型加载或整段重排失败时，也会返回进入该阶段前的候选。参考 [交叉编码器预算与多窗口回退 ↗](../../../apps/server/src/retrieval/unified.ts#L872 "支持候选池整理、每批 8 项、默认 20 秒预算、多轮窗口评分、部分结果保留及未评分状态。")

外部决策排序器只接收本地已经准入的候选。存在交叉编码器结果时，送审池采用本地整理后的顺序；否则先用 `candidatePool` 遍历召回前沿，再按该顺序装配送审池。建议式结果只附加评估，不改变本地最终顺序。普通决策结果只能引用送审池中的 ID，陌生 ID 会被丢弃；最终只保留排序器实际返回且属于送审池的项目，再执行去重、多样化和限额。排序器抛错时回退到本地结果。参考 [受控决策排序 ↗](../../../apps/server/src/retrieval/unified.ts#L952 "支持送审池的组成、建议式评估、池内 ID 校验、普通决策结果筛选和异常回退。")

最终装配会按查询用途调整知识、代码、事项和记忆的优先级，并考虑代码定义、知识新鲜度与事件时间。普通结果中，同一 owner 的 source、task 和 memory 命中默认最多两项；knowledge 按 `${revision}:${section}` 去重，因此一个知识章节最多一项，同一知识文档仍可贡献多个章节。调用方查询改用跨材料轮转，先展示入口广度。知识命中只携带当前返回正文实际引用到的 citation；原始材料命中还会把字符范围换算为行范围。参考 [用途排序与结果装配 ↗](../../../apps/server/src/retrieval/unified.ts#L1028 "支持用途优先级、多样化规则、调用方轮转、原始材料命中的行范围和知识引用装配。")

同步旧接口会先尝试代码导航；其余路径按查询变体组合词法与符号候选，不使用材料概念、向量语义或模型排序。异步旧接口复用完整 `search()`，随后从每个结构化命中的可见证据片段中选取最相关的一项。参考 [旧版来源接口投影 ↗](../../../apps/server/src/retrieval/unified.ts#L1185 "支持同步旧接口的代码导航及词法、符号路线，以及异步接口复用完整搜索和证据片段挑选规则。")
