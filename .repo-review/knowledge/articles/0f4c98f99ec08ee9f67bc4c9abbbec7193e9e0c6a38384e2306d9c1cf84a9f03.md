# 统一检索的混合召回、降级与结果选择

UnifiedRetrieval 先同步检索单元，再完成词面检索和代码导航，并召回正文及概念语义候选。后续经过 RRF 融合、可选重排与结果多样化，形成统一管线；同一实现也向旧处理器投影不可变证据片段，并在语义或排序组件不可用时保留可用检索路径。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_index"></a>
## 统一入口与索引准备

## 解决的问题

`UnifiedRetrieval` 是读者和 Agent 共用的检索入口。它继承关键词检索能力，在构造时接入 SQLite、检索单元投影与代码导航；嵌入模型与交叉编码重排器，以及主机排序函数都由外部注入，因此部署可以只启用词面检索，也可以逐步开启语义与决策层。旧版 source 接口继续使用同一批命中，再投影到不可变证据片段。参考 [统一检索入口 ↗](../../../apps/server/src/retrieval/unified.ts#L63 "支持统一入口、依赖注入以及旧 source 接口共用命中的说明。")

## 数据如何就绪

后台任务先同步 `RetrievalProjection`，再分批补正文向量；正文完成后才补带材料描述的概念向量。每个单元按窗口嵌入，写入前在 `BEGIN IMMEDIATE` 锁内复查单元是否仍存在，防止维护过程替换材料后写入过期向量。只读模式不建索引，没有嵌入加载器时仍会同步词面检索单元。参考 [索引调度 ↗](../../../apps/server/src/retrieval/unified.ts#L204 "支持无嵌入加载器、并发批次与只读模式下的索引行为。")、[向量写入一致性 ↗](../../../apps/server/src/retrieval/unified.ts#L222 "支持正文和概念窗口嵌入、锁内复查以及事务写入的说明。")

<a id="representative_search"></a>
## 一条普通查询如何产生结果

## 代表性调用

以教学输入 `search({ text: "统一检索如何降级", purpose: "implementation", limit: 5 })` 为例。方法先同步检索单元并检查是否应走代码导航；普通查询随后产生 BM25、符号定义和材料概念候选。嵌入模型已加载时，查询文本最多取 400 个字符生成向量，再从每个单元保留余弦分数最高的正文窗口，同时尝试概念向量召回。参考 [普通查询入口 ↗](../../../apps/server/src/retrieval/unified.ts#L651 "支持同步、代码导航判断、基础召回以及无模型时降级的调用流程。")、[语义召回与降级 ↗](../../../apps/server/src/retrieval/unified.ts#L679 "支持查询向量、正文和概念语义召回、固定阈值及异常降级的说明。")

```mermaid
flowchart LR
  Q[SearchQuery] --> A[资格过滤]
  A --> B[词面/符号/概念/两类语义召回]
  B --> C[RRF 融合]
  C --> D[交叉编码器重排]
  D --> E[主机排序与多样化]
  E --> F[RetrievalHit]
```

各路分数尺度不同，`fuse` 只按分支内名次累加倒数排名，并合并命中路线；语义正文窗口不会被同单元的符号摘要覆盖。随后，交叉编码器最多处理 40 个单元的候选段落，以 70% 重排相关性和 30% 归一化检索分合成新分数。可选的 `rank` 在最终阅读名额截断前处理候选池，其容量上限为 `max(q.limit ?? 20, 40)`；已有候选不足该上限时，池的实际数量会更少。排序后按来源和知识章节做多样化，并去除重复文本。最终返回不超过 5 条结果，其中包含目标位置和来源引用，并保留命中路线及可选重排信息。参考 [倒数排名融合 ↗](../../../apps/server/src/retrieval/unified.ts#L479 "支持跨评分尺度按分支名次融合、保留摘要和合并路线的说明。")、[交叉编码器重排 ↗](../../../apps/server/src/retrieval/unified.ts#L785 "支持候选池规模、段落评分、分数合成以及异常保留原结果的说明。")、[主机排序与多样化 ↗](../../../apps/server/src/retrieval/unified.ts#L878 "支持最终名额截断前按容量上限构造候选池、调用可选排序、执行来源多样化和失败回退。")、[最终结果构造 ↗](../../../apps/server/src/retrieval/unified.ts#L933 "支持查询目的优先级、再次资格检查、多样化和 RetrievalHit 输出字段。")

<a id="filters_and_fallbacks"></a>
## 范围约束、快捷路径与降级边界

## 查询边界

候选首先受材料角色和生效时间约束；follow-up 查询还会排除非 open、waiting 状态的 task。受信项目查询只对 memory 候选执行项目 scope 检查：仅当 `q.project_id`、`q.project_trusted` 同时成立且候选目标为 `memory` 时才读取 scope，并且只在 scope 中存在不同的 `project_id` 时排除该候选。这项检查不会直接约束 source、knowledge 或 task 候选。随后，候选按类型和主题前缀过滤，并检查可见性及时间范围。材料角色和历史状态还会形成适用性权重；该权重影响导航顺序，不会把未知来源排除。读者若要改变访问范围，应按候选类型选择 `SearchQuery` 的筛选条件，不能把 `project_id` 当作所有候选的通用范围条件；若要调整计划、研究或历史材料的优先级，入口在 `applicability`。参考 [候选资格过滤 ↗](../../../apps/server/src/retrieval/unified.ts#L302 "支持材料、受信项目 memory scope、类型、可见性与时间等查询边界。")、[材料适用性权重 ↗](../../../apps/server/src/retrieval/unified.ts#L356 "支持角色与状态只影响排序权重、未知来源仍可进入候选的说明。")

显式 `codeIntent` 会绕过普通混合召回：定义请求查 AST 投影出的标题，调用者请求先做文本预筛，再由 `CodeNavigation.matches` 确认调用位置，并优先返回最小包围操作。根据自然语言推断出的调用者快捷路径只有实际命中时才生效，避免不支持的语言失去普通召回结果。参考 [代码导航快捷路径 ↗](../../../apps/server/src/retrieval/unified.ts#L389 "支持显式或推断代码意图、AST 调用位置确认及最小包围操作优先。")

空查询和精确查询不做语义召回。嵌入模型尚未加载或查询嵌入失败时，流程退回词面、符号与概念候选；概念向量失败只清空该分支；重排器或主机排序异常则保留进入该阶段前的结果。最终 `finish` 仍会再次检查资格，并按查询目的和代码定义命中计算优先级，同时结合知识新鲜度与材料适用性。同步旧接口会先尝试显式或成功推断的 callers 导航；没有导航快捷路径时，才走词面与符号路线。异步旧接口可复用完整 `search`。两者在投影证据时，都会遍历每个结构化命中的每条引用，从该引用中选出一个可见且相关性最高的 fragment，最后再施加查询的总 `limit`。参考 [普通查询入口 ↗](../../../apps/server/src/retrieval/unified.ts#L651 "支持同步、代码导航判断、基础召回以及无模型时降级的调用流程。")、[语义召回与降级 ↗](../../../apps/server/src/retrieval/unified.ts#L679 "支持查询向量、正文和概念语义召回、固定阈值及异常降级的说明。")、[交叉编码器重排 ↗](../../../apps/server/src/retrieval/unified.ts#L785 "支持候选池规模、段落评分、分数合成以及异常保留原结果的说明。")、[主机排序与多样化 ↗](../../../apps/server/src/retrieval/unified.ts#L878 "支持最终名额截断前按容量上限构造候选池、调用可选排序、执行来源多样化和失败回退。")、[最终结果构造 ↗](../../../apps/server/src/retrieval/unified.ts#L933 "支持查询目的优先级、再次资格检查、多样化和 RetrievalHit 输出字段。")、[旧证据接口投影 ↗](../../../apps/server/src/retrieval/unified.ts#L1067 "支持同步接口先尝试导航、无快捷路径时使用词面与符号路线，以及按每条引用选择证据片段并施加总 limit。")
