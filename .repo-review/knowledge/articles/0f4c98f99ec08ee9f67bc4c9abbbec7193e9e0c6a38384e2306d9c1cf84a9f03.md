# 统一检索的召回、融合与结果选择

UnifiedRetrieval 是服务端统一检索的编排层：它把 SQLite 中的检索单元同步为可搜索投影，组合词面、代码导航、材料概念和语义向量召回，以 RRF 统一不同分数量纲，再按需执行交叉编码器与外部决策排序，最终应用范围过滤、用途偏好、去重和多样化。语义或排序能力不可用时保留词面路径，并兼容旧的原始材料候选接口。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_index"></a>
## 统一不同检索能力

`UnifiedRetrieval` 面向阅读器和 Agent 的统一查询，把 `RetrievalProjection`、`CodeNavigation`、嵌入模型和重排模型接在同一入口；旧接口只把同一批结果重新投影为不可变证据。参考 [统一检索职责与依赖 ↗](../../../apps/server/src/retrieval/unified.ts#L67 "支持统一入口服务阅读器和 Agent，并连接投影、代码导航、嵌入及重排能力的说明。")

后台任务先同步检索单元，再分批补正文向量；正文完成后才处理带描述的概念向量。一个单元可以生成多个窗口，每批最多 16 个窗口送入模型，写入前在事务锁内再次确认单元仍存在，避免并发维护期间提交失效向量。只读模式或未配置嵌入模型时不会写向量。参考 [向量索引事务 ↗](../../../apps/server/src/retrieval/unified.ts#L209 "支持一个检索单元先生成多个窗口、每批最多发送 16 个窗口，并在写入前于事务锁内检查单元是否仍存在。")

<a id="representative_search"></a>
## 一次普通查询如何得到结果

例如输入一条自然语言查询，并把 `purpose` 设为 `implementation`：`search` 先同步投影；若没有命中代码导航快捷路径，便生成 BM25、符号定义和材料概念候选。有可用嵌入模型时，还会计算查询向量，分别召回正文窗口与概念窗口。各路线的原始分数尺度不同，因此 `fuse` 只按路线内名次做 RRF 累加，同时合并命中范围和路线标记。参考 [多路召回编排 ↗](../../../apps/server/src/retrieval/unified.ts#L685 "支持代表性 search 调用中的同步、快捷路径、词面与语义分支以及最终选择流程。") [RRF 融合 ↗](../../../apps/server/src/retrieval/unified.ts#L484 "支持不同路线按名次累加、合并命中范围和保留路线标记的说明。")

```mermaid
flowchart LR
  Q[SearchQuery] --> F[范围过滤]
  F --> R[多路召回]
  R --> U[RRF 融合]
  U --> X[可选重排与决策]
  X --> O[RetrievalHit 列表]
```

融合结果可由交叉编码器按 8 个候选一批重排，默认受 20 秒预算约束；已评分项以重排分数占 70%、归一化召回分数占 30%，未评分项只保留归一化召回分数的 30%，并标明原因。最终结果包含文本片段、分数、路线、目标、引用与来源信息。参考 [交叉编码重排 ↗](../../../apps/server/src/retrieval/unified.ts#L822 "支持分批、时间预算、评分混合，以及未评分项仅保留归一化召回分数的 30% 并记录原因。") [最终结果结构 ↗](../../../apps/server/src/retrieval/unified.ts#L1057 "支持最终 RetrievalHit 携带片段、分数、路线、目标、引用和来源信息。")

<a id="boundaries"></a>
## 过滤、降级与兼容边界

候选在召回和最终输出阶段都会检查材料角色、生效时间、任务状态、可信项目范围、种类、主题路径、可见性和时间区间；这些条件决定能否进入结果。材料状态只调整排序先验。用途通常影响排序，但 `follow-up` 还会排除状态不是 `open` 或 `waiting` 的任务。参考 [候选资格与适用性 ↗](../../../apps/server/src/retrieval/unified.ts#L307 "支持硬性范围过滤、材料状态排序先验，以及 follow-up 用途排除非 open 或 waiting 任务的例外。")

空查询或精确查找不走语义召回；显式 `codeIntent` 直接走定义或调用候选，自动推断的调用查询若没有 AST 候选则回到普通检索。正文向量失败会降级到词面路线，概念向量失败不会丢掉健康的正文向量，重排或外部决策失败也会回退到已有候选。外部决策器只能选择已准入池中的结果。参考 [代码导航边界 ↗](../../../apps/server/src/retrieval/unified.ts#L421 "支持显式代码意图的快捷路径，以及自动推断无候选时回落普通召回的行为。") [检索降级路径 ↗](../../../apps/server/src/retrieval/unified.ts#L696 "支持精确查询跳过语义、模型不可用或异常时保留词面结果，以及概念向量独立降级。")

`finish` 再按查询用途、代码定义命中、知识新鲜度和材料适用性排序，并限制同一材料或知识章节的重复结果。同步旧接口只使用词面与符号路线；异步旧接口复用完整统一搜索，再把结构化段落映射到最相关且可见的证据片段。参考 [用途排序与多样化 ↗](../../../apps/server/src/retrieval/unified.ts#L973 "支持按用途和状态调整优先级，并对材料、章节和重复文本做多样化裁剪。") [旧接口证据投影 ↗](../../../apps/server/src/retrieval/unified.ts#L1127 "支持同步与异步旧接口的不同检索路径，以及结构化结果到可见证据片段的映射。")
