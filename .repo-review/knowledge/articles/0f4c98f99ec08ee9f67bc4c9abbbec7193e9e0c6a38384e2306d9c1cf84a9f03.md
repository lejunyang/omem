# 统一检索：多路召回、分级排序与兼容投影

UnifiedRetrieval 是阅读器与 Agent 共用的检索编排器。它把内容投影为 RetrievalUnit，组合词法和代码符号候选，以及材料概念与两类向量召回，再经过可选的交叉编码器和决策排序，最后按用途与多样性生成结构化命中。嵌入或排序能力不可用时，已有召回路线仍可返回结果；旧 source 接口则从统一命中投影出不可变证据片段。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_index"></a>
## 统一检索解决什么问题

`UnifiedRetrieval` 让阅读器与 Agent 共用 `RetrievalUnit`，旧的 source 接口则把同一批结果投影为不可变证据片段，供仍使用旧接口的处理器读取。构造函数连接 SQLite、检索单元投影与代码导航；嵌入模型、交叉编码器和外部决策排序器均为可选依赖。参考 [统一检索职责与依赖 ↗](../../../apps/server/src/retrieval/unified.ts#L81 "支持共用 RetrievalUnit、旧接口兼容投影，以及构造时连接投影和代码导航的说明。")

后台循环先同步投影，再补建向量索引。`indexBatch()` 默认取 8 个尚未完成当前模型索引的单元；正文向量补齐后，才会处理带材料描述的概念向量。一个单元的窗口按 16 个一组送入模型，返回数量须与输入一致，向量经过合法性检查与单位化后在写锁事务内落库。若写入前该检索单元已被其他维护过程替换或删除，本轮结果会回滚。参考 [后台同步与索引调度 ↗](../../../apps/server/src/retrieval/unified.ts#L135 "支持后台循环先同步投影、再分批索引，以及失败后退避重试的说明。")、[分窗嵌入与事务写入 ↗](../../../apps/server/src/retrieval/unified.ts#L223 "支持默认单元批量、正文与概念分阶段建索引、每组 16 个窗口及写锁事务行为。")、[向量校验与单位化 ↗](../../../apps/server/src/retrieval/unified.ts#L74 "支持嵌入向量的非零范数和有限数值检查，以及逐项单位化。")

<a id="representative_search"></a>
## 一次普通查询如何得到结果

以 `{ text: "统一检索如何融合语义与关键词", purpose: "implementation", limit: 10 }` 为教学示例，`search()` 先同步投影并检查代码导航捷径。普通查询会生成原查询及显式查询变体，每个文本分别召回，最后合并各次结果。空查询与精确查询不进入语义召回或交叉编码器；模型尚未加载时，检索继续使用已有的词法、符号和材料概念候选。参考 [查询入口与变体召回 ↗](../../../apps/server/src/retrieval/unified.ts#L713 "支持代码导航捷径、查询变体逐次召回与合并，以及空查询、精确查询和模型未加载时的分支。")

```mermaid
flowchart LR
  Q[SearchQuery 与查询变体] --> F[资格过滤]
  F --> R[词法/符号/材料概念/向量召回]
  R --> M[RRF 融合]
  M --> X[可选交叉编码器与决策排序]
  X --> O[多样化 RetrievalHit]
```

词法路线从 BM25 结果中保留最多 250 个已通过资格检查的候选，并按材料适用性加权；当后续行的分数上界已无法超过池尾时，可以提前停止读取。隐藏或超出范围的行不会占用这 250 个位置。参考 [词法候选池与上界剪枝 ↗](../../../apps/server/src/retrieval/unified.ts#L609 "支持 BM25 候选的资格过滤、材料适用性加权、250 项上限和安全的提前停止条件。")

嵌入模型可用时，查询文本截到 400 个字符后生成向量。正文和概念语义路线都以 0.4 为准入线，按适用性重排后各保留最多 100 项；概念向量失败只清空该路线，正文向量仍可使用。最终融合纳入词法前 100 项及其他召回路线。由于 BM25、余弦相似度与符号查找的分数不可直接比较，融合只采用各路线中的名次，并合并路线、命中范围和片段。参考 [正文与概念语义召回 ↗](../../../apps/server/src/retrieval/unified.ts#L753 "支持查询截断、两类向量召回、概念路线独立降级、0.4 准入线与每路 100 项上限。")、[倒数排名融合 ↗](../../../apps/server/src/retrieval/unified.ts#L498 "支持各召回路线按名次融合，并合并片段、范围和路线信息。")

<a id="boundaries_and_outputs"></a>
## 过滤、降级与输出边界

候选首先按材料角色与有效期筛选。随后还会检查跟进事项状态和可信项目范围，并核对内容种类与主题前缀；可见性和时间范围也在检查之列。`follow-up` 会排除状态已非 `open` 或 `waiting` 的事项。材料角色及状态还会形成导航权重，但未知来源保持完整资格；显式指定材料角色或请求背景材料时，不应用这层权重。参考 [候选资格与材料适用性 ↗](../../../apps/server/src/retrieval/unified.ts#L321 "支持范围过滤、follow-up 状态限制，以及材料角色和状态的导航权重边界。")

交叉编码器使用多样化候选池，每批最多 8 个候选，默认预算为 20 秒。它先给每个候选一个窗口的评分机会，再处理长内容的后续窗口。取消信号继续向外抛出；预算耗尽或评分失败时，已完成的评分得到保留，未评分项沿用缩放后的召回分，并记录未评分原因。参考 [交叉编码器预算与多窗口回退 ↗](../../../apps/server/src/retrieval/unified.ts#L868 "支持多样化候选池、每批 8 项、默认 20 秒预算、多轮窗口评分及部分结果保留。")

外部决策排序器只接收本地已准入的有限候选池。候选池先取本地结果前 6 项，再补最多 6 项覆盖候选，随后补足到请求上限与 40 两者中的较大值。建议式返回只附加评估，不改变本地顺序。普通返回只能重排池内已有项目，陌生 ID 会被丢弃；未送入候选池的本地结果仍会接在决策结果之后，继续参与去重、多样化和最终限额。排序器抛错时直接回退到本地结果。参考 [受控决策排序 ↗](../../../apps/server/src/retrieval/unified.ts#L949 "支持有限候选池的组成、建议式评估、池内 ID 校验、未送审本地结果保留和异常回退。")

最终装配会按查询用途调整知识和代码的优先级，也会调整事项或记忆的优先级，并考虑代码定义、新鲜度与事件时间。普通结果中，同一 source、task 或 memory owner 默认最多两项；knowledge 按 `${revision}:${section}` 去重，因此一个知识章节最多一项，同一知识文档仍可贡献多个章节。调用方查询改用跨材料轮转，以先展示入口广度。知识命中只携带当前返回正文实际引用到的 citation；原始材料命中还会把字符范围换算为行范围。参考 [用途排序与结果装配 ↗](../../../apps/server/src/retrieval/unified.ts#L1039 "支持用途优先级、多样化规则、调用方轮转、原始材料命中的行范围和知识引用装配。")

同步旧接口会先尝试代码导航；其余路径按查询变体组合词法与符号候选，不使用材料概念、向量语义或模型排序。异步旧接口复用完整 `search()`，随后从每个结构化命中的可见证据片段中选取最相关的一项。参考 [旧版来源接口投影 ↗](../../../apps/server/src/retrieval/unified.ts#L1195 "支持同步旧接口的代码导航与词法、符号路线，以及异步接口复用完整搜索和证据片段挑选规则。")
