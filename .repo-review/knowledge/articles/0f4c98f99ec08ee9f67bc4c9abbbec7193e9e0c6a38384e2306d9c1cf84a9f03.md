# 统一检索的多路召回、重排与证据投影

UnifiedRetrieval 为读者与 Agent 提供同一套检索入口：先按查询范围过滤结构化检索单元，再组合词法与代码导航，以及材料概念和可选语义召回，经重排、用途加权与多样化后返回 RetrievalHit；旧处理器可把同一结果投影回不可变证据片段。模型不可用或排序失败时，流程会退回已有候选。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role_and_call"></a>
## 解决什么问题

这个类把读者检索与 Agent 检索统一到 `RetrievalUnit` 上，同时保留向旧版证据接口投影的能力。构造时接入 SQLite、检索单元投影和代码导航；嵌入模型、交叉编码器及宿主排序器均为可选依赖，因此同一入口可以按部署能力逐级增强。参考 [统一检索器依赖 ↗](../../../apps/server/src/retrieval/unified.ts#L57 "说明统一检索单元的定位、可选模型依赖以及投影和代码导航组件的初始化。")

一条说明性调用可以写成 `search({ text: "统一检索如何降级", purpose: "implementation", limit: 5 })`。输入是 `SearchQuery`，输出是 `RetrievalHit[]`；`purpose` 影响最终偏好，`limit` 控制返回槽位。实际调用方不在本材料范围内，这里只解释公开 `search` 方法内部可确认的行为。

<a id="hybrid_pipeline"></a>
## 从查询到结果的核心流程

普通查询先同步投影，再生成 BM25、符号和材料概念候选。空查询或精确查找跳过语义分支；未加载嵌入模型时，已有候选仍可进入重排与选择。参考 [主搜索入口 ↗](../../../apps/server/src/retrieval/unified.ts#L570 "支持同步、导航短路、多路候选生成，以及空查询、精确查询和无语义模型时的分支行为。")

```mermaid
flowchart LR
  Q[SearchQuery] --> F[范围与可见性过滤]
  F --> R[词法、符号、概念与可选语义召回]
  R --> U[RRF 融合]
  U --> X[可选交叉编码器重排]
  X --> H[可选宿主排序]
  H --> O[用途加权、多样化并生成 RetrievalHit]
```

语义分支把查询限制为前 400 个字符，按余弦点积为每个检索单元保留最佳窗口，再用动态阈值和最多 100 个候选控制规模；异常时回退到词法侧候选。参考 [语义召回与降级 ↗](../../../apps/server/src/retrieval/unified.ts#L596 "支持查询截断、向量相似度、最佳窗口、候选阈值，以及语义异常后回退的说明。") 不同召回分数不能直接比较，所以融合只使用各分支名次，并保留已有的相关摘录。参考 [名次融合 ↗](../../../apps/server/src/retrieval/unified.ts#L430 "说明各召回分支通过 RRF 按名次合并，并保留先前摘录和路由。")

交叉编码器只处理排序靠前的 40 个单元，把上下文与局部片段送入模型；相关度低于 0.1 的普通候选会被剔除，代码定义候选例外。随后可选宿主排序在已过滤的候选池上运行；抛错时回到内置 `finish`。参考 [交叉编码器重排 ↗](../../../apps/server/src/retrieval/unified.ts#L679 "支持重排候选池、局部片段输入、分数校验、阈值筛选和失败保留原候选的说明。")、[宿主排序与回退 ↗](../../../apps/server/src/retrieval/unified.ts#L757 "说明宿主排序只看到已完成内置筛选的候选池，并在异常时回到内置完成流程。") 最终阶段先按用途和定义匹配调整优先级，再结合材料状态与适用性排序，并对同一来源和重复文本做限额，组装目标、引用、路由及来源信息。参考 [用途与优先级 ↗](../../../apps/server/src/retrieval/unified.ts#L812 "支持按查询用途、代码定义、知识新鲜度和材料适用性调整最终排序的论断。")、[结果去重与装配 ↗](../../../apps/server/src/retrieval/unified.ts#L878 "说明来源限额、文本去重、摘要选择、知识引用恢复以及 RetrievalHit 字段装配。")

<a id="boundaries_and_relations"></a>
## 过滤边界、代码导航与兼容接口

候选会按查询给出的角色、有效期、种类、主题路径、可见性和时间范围接受检查；任务状态检查只在 `purpose="follow-up"` 且候选为 task 时启用，只保留 open 或 waiting，项目范围检查则只在查询同时给出 `project_id`、`project_trusted=true` 且候选目标为 memory 时启用，并仅在该 memory 的 `scope.project_id` 是字符串且与查询值不同时排除。材料角色与历史状态通常只改变排序先验；显式角色筛选或背景检索不会套用这组默认降权。参考 [候选资格过滤 ↗](../../../apps/server/src/retrieval/unified.ts#L253 "支持角色、时效、任务状态、项目范围、种类、主题、可见性和时间过滤的触发条件与边界说明。")

代码查询有独立短路：显式 `codeIntent` 直接选择定义或调用者候选；自然语言被识别为“查调用者”时，只有找到 AST 匹配才短路，否则继续普通召回。调用点结果优先选择最小包围操作，并标记为候选，因此它用于导航，不等同于类型解析后的完整调用图。参考 [代码导航候选 ↗](../../../apps/server/src/retrieval/unified.ts#L367 "说明显式和推断式代码导航分支，以及调用点候选的最小包围操作和去重逻辑。")

旧版 `searchSources` 只检索源码，并把结构化命中的引用恢复为不可变片段。实现会遍历每个结构化命中的 `references`，按每个 reference 选择至多一个尚未使用且可见的片段；一个命中包含多个 reference 时，可以投影出多个 `SourceCandidate`。片段按结果正文包含度和查询词命中数排序，最后生成 `SourceCandidate`；异步版本则复用完整统一检索。参考 [旧来源接口投影 ↗](../../../apps/server/src/retrieval/unified.ts#L946 "支持同步与异步来源检索如何复用统一结果，并按每个 reference 至多选择一个可见证据片段生成 SourceCandidate。")
