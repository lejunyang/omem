# 统一检索：从多路召回到可降级排序

UnifiedRetrieval 是服务端面向阅读器与 Agent 的统一检索编排器。它先把不同内容投影成同一种检索单元，再组合词法与代码导航，并加入材料概念和向量召回。候选经过可选的交叉编码器、决策排序与多样化后，输出带来源、命中范围和引用信息的结果。索引与模型能力可以渐进启用；部分模型失败时，查询仍会使用已有召回路线。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_index"></a>
## 统一检索解决什么问题

`UnifiedRetrieval` 让阅读器与 Agent 共用一种 `RetrievalUnit`，并把旧的 source 接口作为同一批结果到不可变证据片段的兼容投影。构造时，它连接 SQLite、检索单元投影和代码导航；嵌入模型、交叉编码器与外部决策排序器都是可选依赖。参考 [统一检索职责与依赖 ↗](../../../apps/server/src/retrieval/unified.ts#L67 "支持统一检索单元、旧接口兼容投影，以及构造时连接投影与代码导航的说明。")

后台 `start()` 先同步投影，再按批次补正文向量；正文完成后才处理材料概念向量。每批最多 16 个窗口送入模型，返回数量须与输入一致，向量经校验和单位化后，在写锁事务内落库。如果写入前检索单元已不存在，该单元本轮写入会回滚。参考 [后台同步与索引调度 ↗](../../../apps/server/src/retrieval/unified.ts#L121 "支持后台循环先同步投影、再分批索引以及错误退避的说明。")、[分窗嵌入与事务写入 ↗](../../../apps/server/src/retrieval/unified.ts#L223 "支持正文和概念分阶段建索引、每批最多 16 个窗口、向量校验及写锁事务行为。")

## 一次普通查询如何得到结果

以 `{ text: "统一检索如何融合语义与关键词", purpose: "implementation", limit: 10 }` 为例，`search()` 先同步投影。没有显式代码导航捷径时，它取得 BM25、符号和材料概念候选；空查询或精确查询跳过语义阶段，模型尚未就绪时也直接使用现有候选，但仍可进入可选的交叉编码器与决策排序。参考 [查询入口与现有候选路径 ↗](../../../apps/server/src/retrieval/unified.ts#L685 "支持普通查询的初始召回、精确查询分支，以及模型未就绪时继续使用现有候选并进入可选排序的路径。")

```mermaid
flowchart LR
  Q[SearchQuery] --> F[资格过滤]
  F --> R[词法/符号/概念/语义召回]
  R --> M[RRF 融合]
  M --> X[可选交叉编码器与决策排序]
  X --> O[多样化 RetrievalHit]
```

模型可用时，查询文本截到 400 个字符后生成向量；正文与概念语义候选以 0.4 为准入线，各保留最多 100 项。各路线的分数尺度不同，因此融合只使用路线内名次，并合并路线、命中范围与片段。参考 [语义召回与准入线 ↗](../../../apps/server/src/retrieval/unified.ts#L713 "支持查询向量截断、正文及概念语义召回、失败降级、0.4 阈值与候选上限。")、[倒数排名融合 ↗](../../../apps/server/src/retrieval/unified.ts#L484 "支持各召回路线按名次融合，并合并片段、范围和路线信息的说明。")

<a id="boundaries_and_outputs"></a>
## 过滤、降级与输出边界

候选进入排序前会按材料角色和有效期筛选，并检查跟进事项状态与可信项目范围；内容种类与主题前缀、可见性和时间范围也参与过滤。用途不会绕过这些资格判断；`follow-up` 会排除已非 `open` 或 `waiting` 的事项，其余用途主要通过优先级生效。参考 [候选资格过滤 ↗](../../../apps/server/src/retrieval/unified.ts#L307 "支持材料角色、有效期、事项状态、项目、种类、主题、可见性和时间范围过滤，以及 follow-up 对非 open/waiting 事项的排除。")

交叉编码器按 8 个候选一批运行，默认预算 20 秒。它先让每个候选获得一个窗口的评分机会，再处理长内容的后续窗口；取消信号继续抛出，预算耗尽或评分失败则保留已经完成的评分，未评分项沿用缩放后的召回分，并标记未评分原因。参考 [交叉编码器预算与多窗口回退 ↗](../../../apps/server/src/retrieval/unified.ts#L822 "支持候选分批、先覆盖首个窗口再评估后续窗口、默认预算、取消处理，以及保留已评分候选和标记未评分候选。")

外部决策排序器只查看本地已准入的有限候选池。池中先放本地排序靠前的 6 项，再从其余候选补最多 6 项覆盖结果，随后补足到请求上限与 40 两者中的较大值。建议式结果只附加评估；返回池外项目会被丢弃，异常时回退到本地排序。参考 [受控决策排序 ↗](../../../apps/server/src/retrieval/unified.ts#L903 "支持有限候选池的组成、池外结果排除、建议式评估和异常回退。")

最终结果按用途、代码定义、新鲜度或事件时间调整优先级，并去掉重复正文。普通 source、task 和 memory owner 默认各最多两项；knowledge 按 `${revision}:${section}` 去重，因此每个知识章节最多一项，同一知识文档可以超过两项。调用方查询取消 owner 上限，改用跨材料轮转，以先展示入口广度。知识结果只携带当前结果正文实际引用到的 citation。参考 [用途排序与结果装配 ↗](../../../apps/server/src/retrieval/unified.ts#L993 "支持用途优先级、普通 owner 上限、知识章节去重、调用方轮转、命中行范围和知识引用装配。")

除代码导航捷径外，同步旧接口不走材料概念、向量语义和重排路线，只组合词法与符号候选；异步旧接口复用完整 `search()`，随后为每个结构化段落挑选最相关且可见的证据片段。参考 [旧版来源接口投影 ↗](../../../apps/server/src/retrieval/unified.ts#L1147 "支持同步接口先尝试代码导航、其余同步路线只含词法与符号候选，以及异步接口复用完整搜索和证据片段挑选规则。")
