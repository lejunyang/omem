# 仓库验收报告生成与知识检索验证脚本

该脚本执行一次可复现的仓库验收：记录源码与题集指纹，按模式运行依赖、项目和检索检查，恢复并校验当前知识文章，启动临时 Review HTTP 服务验证中文检索，最终归档旧报告并以退出码表达结果。它只描述本次运行，不继承历史通过率，也不调用生成式模型。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-evidence"></a>
## 目标与证据固定

脚本把验收限定为“本次运行”：确定仓库根目录、报告、历史与日志位置，并对 Git 已跟踪及未忽略文件计算摘要，同时固定检索题集摘要。每条外部命令的标准输出和错误输出都会合并落盘，检查结果保存实际命令、退出码、日志路径及内容哈希，因此报告可追溯到本次执行证据，而不只是布尔结论。[验收输入指纹与命令日志 ↗](../../../scripts/review-verify.ts#L18 "支持脚本固定源码与题集摘要，并记录实际命令、退出结果和日志哈希的说明。")

<a id="execution-modes"></a>
## 执行模式与核心流程

默认 repository 模式会把依赖冻结、全项目检查和实时中文检索标为 skipped；只有 `--full` 才实际执行，其中检索烟测直接使用当前 Bun 可执行文件，避免递归进入 osdk shim。报告记录当前提交、源码与题集指纹，并声明不继承旧通过率、不调用生成式模型。[完整模式与报告范围 ↗](../../../scripts/review-verify.ts#L47 "说明 full 模式的条件执行、默认跳过语义，以及报告仅描述本次运行。") 随后脚本同步评审材料和代码、恢复知识仓库，逐篇校验文档结构、独立复核 verdict 与依赖摘要；过期或未接受文章会进入错误列表，未覆盖材料只标记为 incomplete，不会冒充全库完成。[知识恢复与当前文章校验 ↗](../../../scripts/review-verify.ts#L55 "支持同步、恢复、文档校验、独立复核 verdict、依赖新鲜度和覆盖统计流程。")

<a id="retrieval-check"></a>
## 索引与真实 HTTP 检索断言

脚本读取检索配置并构建 Review 应用；若后端为语义检索，会循环补齐索引并记录健康状态，否则把语义索引检查标为 skipped。之后在随机本地端口启动真实 HTTP 服务，对题集逐条调用 `/api/review/search`，同时以 `diversify:false` 调用当前检索实现，记录底层检索基线。每题仅断言期望路径进入接口结果前五名，并记录排名、去重路径数、耗时、路由和截断片段。[语义索引与 HTTP 检索流程 ↗](../../../scripts/review-verify.ts#L76 "支持语义索引补齐、临时服务启动、题集解析、真实搜索接口调用及底层检索基线记录。") 因而该检查覆盖接口可用性与有限的中文召回回归；源码明确说明，top-5 命中不等于回答正确，六条公开问题也不是完整相关性评测。[检索回归判定边界 ↗](../../../scripts/review-verify.ts#L98 "支持前五名命中断言，并明确该题集不代表完整相关性评测或回答正确性。")

<a id="boundaries-and-output"></a>
## 边界、清理与模块关系

仓库同步、知识恢复、索引和 HTTP 验证由统一异常处理包围；失败会形成 `repositoryRun`，最终无论成功与否都关闭应用或存储。脚本结束时再次计算源码和题集摘要，以检测验证期间输入是否发生变化；变化会使该检查失败。随后脚本以所有检查均无 failed 决定总结果，按时间和旧文件哈希归档上一份报告，写入新报告，并在失败时设置进程退出码 1。[资源清理、输入变化检测与报告归档 ↗](../../../scripts/review-verify.ts#L103 "支持异常处理、资源关闭、运行结束时的输入摘要复核、旧报告归档及失败退出码逻辑。") 它直接编排 Review/Code Sync、知识恢复与文档校验、Review HTTP App、检索配置及 SemanticRetrieval；这些关系只能证明到显式导入和本文件调用，各模块的内部行为仍需对应实现材料说明。[验收脚本的模块依赖 ↗](../../../scripts/review-verify.ts#L9 "支持脚本与同步、知识恢复、文档校验、Review 应用及语义检索模块之间的显式依赖关系。")
