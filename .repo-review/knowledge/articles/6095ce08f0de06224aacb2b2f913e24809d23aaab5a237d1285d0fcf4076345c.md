# 仓库验收与真实检索回归

该脚本把外部项目检查、知识有效性、语义索引和真实 HTTP 检索汇总为本次运行的验收报告；运行前固定源码与题集摘要，结束时检查输入漂移，但提交版本在外部检查之后采集。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

脚本为仓库生成**仅代表本次运行**的可追溯验收报告。启动阶段计算源码与检索题集摘要，并为日志和历史报告建立独立目录，使检查结果能够关联到明确输入。参考 [验收输入快照 ↗](../../../scripts/review-verify.ts#L18 "支持脚本在启动阶段计算源码和题集摘要，并创建本次运行的日志与历史目录。")

报告中的提交版本并非与这些摘要同时固定：它在可选的外部检查完成后才读取。因此，`implementationCommit` 表示报告构造时的 HEAD，不能单独证明检查开始时也处于同一提交。参考 [提交版本采集时点 ↗](../../../scripts/review-verify.ts#L47 "支持外部检查先执行、随后才读取 HEAD 构造报告，以及报告不调用生成式模型的边界说明。")

<a id="execution"></a>
## 分层执行验收

开启 `--full` 后，流程执行冻结依赖、全项目检查和中文检索冒烟，并保存真实命令、退出码、日志路径及日志摘要；普通模式则明确标记这些项目为 `skipped`，不会继承旧结果。参考 [外部检查与日志 ↗](../../../scripts/review-verify.ts#L35 "支持子进程检查依据真实退出码判定状态，并保存命令、日志位置及内容摘要。")

随后脚本同步仓库材料和代码结构，恢复当前知识文章，检查内联引用、独立复核结论与依赖摘要。未覆盖材料只计入不完整状态，过期依赖或未获接受的文章会形成错误。参考 [知识有效性检查 ↗](../../../scripts/review-verify.ts#L55 "支持材料和代码同步、文章恢复、引用与依赖校验，以及未覆盖材料不计为完整通过。")

<a id="retrieval"></a>
## 验证真实检索链路

配置语义检索时，脚本先补齐索引，再启动临时 review 服务，通过真实 `/api/review/search` 执行公开回归问题；预期路径进入前五名才算通过，同时记录底层检索基线。该结果验证基本召回链路，不等同于回答正确性或完整相关性评测。参考 [真实 HTTP 检索回归 ↗](../../../scripts/review-verify.ts#L76 "支持语义索引补齐、临时服务查询、top-5 命中判定及评测范围限制。")

<a id="boundaries"></a>
## 输入稳定性与结果边界

运行结束后，脚本重新计算源码与题集摘要以发现期间漂移，归档旧报告，再写入本次结果；任一检查失败都会令总体失败并设置非零退出状态。参考 [漂移检查与报告归档 ↗](../../../scripts/review-verify.ts#L105 "支持结束时复核输入摘要、归档旧报告、写入新结果并以非零退出码表示失败。")

这套验收不调用生成式模型，知识语义复核结论来自已保存文章。由于提交号在外部检查后采集，即使输入摘要最终未变化，也应把提交号和起始输入摘要视为两个不同时间点的记录。参考 [提交版本采集时点 ↗](../../../scripts/review-verify.ts#L47 "支持外部检查先执行、随后才读取 HEAD 构造报告，以及报告不调用生成式模型的边界说明。")
