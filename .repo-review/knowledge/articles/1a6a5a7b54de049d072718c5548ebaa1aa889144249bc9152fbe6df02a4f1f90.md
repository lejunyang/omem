# 反馈整理角色 v1 的职责与边界

该提示词规定如何把已认证所有者的反馈整理为可追溯的修正候选，并严格限制输出、权限与执行边界。它描述角色应遵循的合同，不足以证明相应流程已经实现或投入运行。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-purpose"></a>
## 角色目的与反馈分类

该角色面向已认证所有者的反馈，目标是形成绑定原始目标与证据的修正候选。处理时需区分强修正、任务调整、范围约束、弱有用性信号和结果证据，避免把性质不同的反馈压成同一种结论。重复反馈或生成式摘要不能因此升级为独立权威来源，修正仍须保持对原始证据的可追溯性。[反馈整理角色的目标与证据原则 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/prompt.md#L1 "支持角色需要分类所有者反馈、绑定原始目标与证据，并防止重复反馈或生成摘要成为独立权威的论断。")

这是一份角色提示词所声明的行为要求，而非运行记录、测试结果或实现代码；仅凭该材料无法确认认证校验、证据绑定、冲突保存等能力已经在宿主流程中落地。

<a id="output-and-safety"></a>
## 输出合同与不可越界事项

角色必须只返回一个 `CorrectionProposal.v1` JSON 对象，不附带说明文字。候选修正只能处于调用方提供的范围内，未解决的冲突需要原样保留；角色不得改变权限、捕获范围、预算或自动批准规则，也不得直接应用修正。[修正候选的输出与权限边界 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/prompt.md#L5 "支持仅输出修正提案 JSON、保留冲突、不得改变关键控制项且不得直接应用修正的约束。")

因此，该角色承担的是“整理并提出候选”，而不是“裁决并执行”。实际生效应由后续校验或应用流程负责，但本材料没有描述该流程的组件、审批条件、失败处理及审计方式。
