# osdk 配置结构与安全边界

该材料说明项目配置与用户配置采用同一套 TOML 结构，定义覆盖优先级、任务和依赖模型，并强调执行代码或改写来源的配置受信任机制约束。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="layers"></a>
## 配置来源与覆盖顺序

osdk 同时读取项目级 `osdk.toml`（或 `.osdk.toml`）和用户全局 `config.toml`：前者从当前目录向上查找并承载项目声明，后者保存跨项目个人默认。冲突时，CLI 参数优先于环境变量，随后依次是项目配置、用户配置和内置默认。这里描述的是配置合同，并不证明某个项目实际采用了全部配置段。[配置文件类型与优先级 ↗](../../../.claude/skills/osdk-guide/reference/configuration.md#L3 "支持项目配置、用户配置的职责，以及 CLI 到内置默认的覆盖顺序。")

<a id="tasks"></a>
## 任务定义与执行语义

`[tasks]` 可用字符串、命令数组或完整对象定义任务，且运行时需要信任。[项目任务定义入口 ↗](../../../.claude/skills/osdk-guide/reference/configuration.md#L244 "支持 `[tasks]` 的三种定义形式，并限定这是运行时需要信任的项目任务配置。") 数组步骤按顺序执行并在失败时停止，也可显式容忍某一步失败，或并行运行一组子任务；完整对象还能声明前置依赖、清理步骤、平台条件、超时以及新鲜度输入输出。`[task_config]` 提供 runner 级默认并整体替换，子项目不能自行覆盖根配置中的该段。[任务步骤、完整字段与 runner 默认 ↗](../../../.claude/skills/osdk-guide/reference/configuration.md#L248 "支持任务数组的顺序、容错与并行语义，完整对象的常用控制字段，以及子项目不得声明 `[task_config]` 的限制。")

<a id="dependencies"></a>
## 工具与应用依赖的分层

`[tools]` 负责准备包管理器等工具，`[deps.<provider>]` 才负责安装项目自身依赖；空 provider 表即可启用内置实现和自动兑现。自定义索引会改变来源，允许源码构建则可能执行代码，二者需要相应信任。未知字段会直接报错，因此拼写错误不会被静默接受。[应用依赖配置与信任条件 ↗](../../../.claude/skills/osdk-guide/reference/configuration.md#L302 "支持工具和应用依赖的职责分离，以及自定义来源、源码构建与未知字段的安全约束。")
