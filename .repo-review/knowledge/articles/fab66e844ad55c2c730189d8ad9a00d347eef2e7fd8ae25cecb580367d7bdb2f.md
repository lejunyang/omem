# 批次二：从材料到可治理记忆的实施方案

描述持久提炼、证据核验、自动应用、用户决策、来源刷新和反馈学习的目标架构，并记录批次二的实现进展。状态摘要与飞书专项材料对通知聚合完成度存在口径差异，不能据计划性描述推断全部能力已落地。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="scope_flow"></a>
## 进展口径与端到端流程

状态摘要称 B2-01～07 已实现，B2-08 已接入受控学习 worker、生产飞书 host 和 A-N04 通知聚合，但 40/120 质量集及其余发布门仍未完成。[批次二状态摘要 ↗](../../../docs/implementation/batch2/plan.md#L1 "支持文档记录的已实现、已接入及质量集和发布门待完成状态。") 飞书专项记录却限定 A-N04 仅通过逐条即时投递，短窗合并与定时外发摘要仍待实现；因此“聚合已接入”不能解释为完整聚合能力可用。[通知聚合实际完成度 ↗](../../../docs/implementation/batch2/lark.md#L122 "指出 A-N04 目前仅逐条即时投递通过，直接限定并纠正“通知聚合已接入”的可能误读。") 方案目标流程是捕获原件后由持久 worker 调用角色化 CLI/ACP 提炼，经合同、引文、版本和语义核验，再按风险自动应用、请求补证或终结，并将反馈送回后续处理。[材料到反馈的数据流 ↗](../../../docs/implementation/batch2/plan.md#L11 "解释捕获、提炼、验证、策略分流、应用、通知和反馈之间的端到端关系。")

<a id="governance"></a>
## 可靠执行与证据治理

任务以短事务租约认领，LLM 与网络调用不占用数据库事务；迟到结果提交还需核验租约、generation、取消状态和输入修订，避免旧 worker 覆盖新状态。[租约与迟到提交保护 ↗](../../../docs/implementation/batch2/plan.md#L50 "支持短事务认领、外部调用不持锁以及结果提交需重新校验的可靠性要求。") 提案必须经过严格 Schema、固定修订精确引文、图片来源、独立语义支持、冲突和时间解析检查；模型自报置信度不能跳过这些门。[提案证据验证门 ↗](../../../docs/implementation/batch2/plan.md#L72 "支持 Schema、精确引文、图片、语义、冲突和时间解析等多层核验要求。") 自动应用还要求身份、范围、证据和副作用均明确，并在同一事务内完成 CAS、不可变修订、变更记录、通知和投递意图。[自动应用与事务顺序 ↗](../../../docs/implementation/batch2/plan.md#L87 "支持多条件自动应用、CAS、不可变修订、通知、投递意图和幂等提交的设计。")

<a id="limits_learning"></a>
## 刷新、学习与现阶段边界

来源更新以 revision 和 validity epoch 驱动：旧引用保留固定快照，依赖刷新完成前，陈旧结果也应标记待复核或从现行检索排除。[来源更新与固定快照 ↗](../../../docs/implementation/batch2/plan.md#L106 "支持 revision 级依赖、有效性 epoch、陈旧结果处理及旧快照不可修改的说明。") 用户纠正作为带来源的新输入，只在同主体、同范围召回；策略学习先走 offline/shadow，模型不能自行调整 ACL、预算或自动审批条件。[反馈与受控策略学习 ↗](../../../docs/implementation/batch2/plan.md#L112 "支持纠正作为新输入、限制召回范围及 offline/shadow 学习的权限边界。") 当前所有实体虽保留 workspace_id，但实现仍只有一个已认证 owner，不能据此宣称已有逐人 ACL；屏幕监听、自动改代码和外部业务写入也仍是后续范围。[单一认证用户边界 ↗](../../../docs/implementation/batch2/plan.md#L48 "直接支持 workspace 字段仅为未来迁移预留、当前不具备逐人访问控制的限制。")[批次范围之外的能力 ↗](../../../docs/implementation/batch2/plan.md#L7 "支持屏幕捕获、自动改代码和外部业务系统操作仍属于后续工作的说明。")
