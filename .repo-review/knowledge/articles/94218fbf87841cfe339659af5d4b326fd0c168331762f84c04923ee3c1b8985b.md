# web · 模块理解 · 专题 2

Web 模块把代码结构、模块知识、源码与原始证据组织为同一阅读路径，并借助共享 Trail 实现跨层下探、回退与深链；核心流程已有单元测试支撑，但失效目标、超长深链及刷新后的附加状态恢复仍待补齐。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role"></a>
## 职责与设计背景

这一专题关注 Web 端的可追溯阅读：Code Wiki 容器装载快照、代码图和模块理解，将概览、依赖图、模块与文件视图组织为入口。[Code Wiki 页面职责 ↗](c7d146673237fb15547f8534001912445b4b4ef8cb6c32403bc9d240682a5c76.md#role "概括容器对主视图、代码图和模块理解装载的编排职责，支持对 Web 阅读入口的定位。") 模块、文件、符号、片段和知识证据统一表示为 Trail 帧，由共享抽屉承担回退、循环识别及阅读历史，而非让各详情页分别维护导航。[共享 Trail 帧合同 ↗](../../../packages/ui/src/trail.ts#L1 "说明 Trail 覆盖模块、文件、符号、片段和知识证据，并定义阅读恢复所需的帧字段。")

<a id="flow"></a>
## 从结构到证据的工作流程

用户从模块进入文件，再沿符号大纲、调用边或规则关联继续下探。容器把文件、符号和片段事件转换为 Trail 帧；符号缺少所属文件时会从代码图补全，并采用人读标题。[统一下探转换 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L185 "证明文件、符号和片段事件如何补全目标信息并压入共享 Trail。") 边解析区分同文件符号、跨文件目标与不可解析目标：同文件符号仍打开独立范围帧，外部或缺失目标不产生导航。[边解析与下探合同 ↗](6251edd95b446e10ed7d54358454b802fd4c2c515d8b85eca507e8f98cf2b16b.md#navigation-and-labels "解释同文件符号、跨文件目标和缺失目标采用不同导航结果，支持流程边界。") 知识正文也只有在引用标记为可操作时才生成包含文档、版本和引用键的帧，使派生正文能够回到固定证据。[知识引用导航门槛 ↗](../../../apps/web/src/knowledge/KnowledgeDocument.vue#L20 "证明只有可操作引用才会生成包含文档、版本和引用键的导航帧。")

<a id="relations"></a>
## 跨模块关系与可信展示

模块桶首先由 contracts 中的共享路径规则确定，Web、UI、contracts、服务端子目录等获得稳定归类。[共享模块路径归类 ↗](../../../packages/contracts/src/code-modules.ts#L1 "支持 Web、UI、contracts、服务端目录和兜底路径形成稳定模块桶的论断。") Web 侧纯函数随后统计文件与符号，并聚合两端均可解析的跨模块 import；同模块、外部或缺失目标不会形成模块依赖。[模块节点与依赖聚合 ↗](../../../apps/web/src/codewiki/modules.ts#L56 "证明已删除文件过滤、文件与符号计数，以及跨模块 import 的聚合和排除条件。") 模块说明另按所有文件覆盖范围选择最长、最具体且未过期的理解记录。[最具体模块理解匹配 ↗](../../../apps/web/src/codewiki/modules.ts#L149 "支持候选状态过滤、检查模块全部文件及最长目录前缀优先的选择流程。") 展示层则优先采用 DTO 的标题、路径与原因字段，并为旧 missing/stale 状态提供人读回退，避免内部标识成为可见文本。[人读标签与边状态测试 ↗](../../../apps/web/src/codewiki/labels.test.ts#L10 "验证 DTO 展示字段优先、可读回退，以及 actionable、missing、stale 的原因和禁用规则。") 模块帧目前可下探符号和文件，但 evidence 仍为静态行，已删除文件仍会发出下探事件。[模块证据与文件入口 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L131 "证明符号引用可点击、evidence 引用保持静态，并且已删除文件仍保留点击入口。")

<a id="progress_limits"></a>
## 验证进展与现有限制

内存 Trail 测试确认十二层栈不会沿用旧的八层截断，并覆盖五层压栈、循环定位及数组切片模拟回退。[Trail 内存栈测试 ↗](../../../apps/web/src/codewiki/trail.test.ts#L21 "仅支持长链不截断、五层压栈、循环定位及切片模拟回退，不将其误作 hash 往返证据。") 独立的 hash 测试才负责证明损坏路径回退概览，以及五层 Trail 写入后可按 kind 与 id 恢复。[Hash 回退与五层往返测试 ↗](../../../apps/web/src/codewiki/hashroute.test.ts#L36 "直接验证损坏 hash 回退概览，以及五层 Trail 写入、解析后的身份和顺序保持。") 刷新恢复时，路由仅重建 kind、id 和以 id 暂代的标题，并按 200 层预算切片；它没有持久化帧的 line 或 scroll。[Hash 帧恢复与长度预算 ↗](../../../packages/ui/src/OmHashRoute.ts#L33 "证明 Trail 恢复只构造 kind、id 和临时标题，并按 MAX_TRAIL 限制序列化栈。") 容器随后只会重新计算人读标题，因此标题可在运行时修正，而行号和滚动位置会丢失，替代此前“这些状态均会重建”的结论。[恢复后的标题修正 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L246 "证明容器恢复 Trail 后仅调用标题修正并设置当前帧，没有重建 line 或 scroll。") 此外，片段帧尚未展示其他关系，完全无法解析的关系也可能看似可点击却没有反馈。[片段关系的失效边界 ↗](8d1b3a1eb428fbd9a3582a66205f897d26f2b35fbc2325bda7bd3462fcac02ea.md#boundaries "指出其他关系未渲染、无法解析的关系仍可能表现为可点击，支持当前限制判断。")
