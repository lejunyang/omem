# web · 模块理解 · 专题 2

Web 模块把知识正文、确定性代码结构与仓库原文组织成统一阅读体验：以模块和文件为入口，通过共享 Trail 下探符号、关系与材料，并用哈希保存阅读路径。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-structure"></a>
## 职责与内容分层

这一专题负责分层呈现已保存知识、解析器结构和仓库原文。容器并行读取快照、代码图与模块理解；理解列表失败可局部降级，显式同步后重新装载。[快照、代码图与模块理解装载 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L120 "支持三类数据并行读取、理解列表失败局部降级，以及显式同步后重新装载。") 路径合同把 Web、共享 UI、contracts、agent-runtime 等归入稳定模块；聚合层排除已删除文件，累计符号，并合并两端可解析的跨模块 import。[共享仓库路径归类规则 ↗](../../../packages/contracts/src/code-modules.ts#L1 "支持 Web、共享 UI、contracts、agent-runtime、Lark、服务端目录、脚本及兜底模块的具体映射。")[模块节点与依赖聚合 ↗](../../../apps/web/src/codewiki/modules.ts#L56 "支持已删除文件过滤、模块文件与符号计数，以及跨模块 import 边的聚合条件。")

模块页在知识文章、加载态、空态和结构化说明之间互斥选择，但文件入口始终保留。[模块说明、证据与文件入口 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L68 "支持模块说明的互斥展示、稳定文件入口，并证明 evidence 引用当前仅为静态行。") 因而知识负责解释背景，计数、文件、符号和源码仍是可核查的事实入口。

<a id="evidence-flow"></a>
## 从概览到证据的阅读流程

用户可从模块进入文件；文件帧加载不可变源码、符号、关系与确定性说明，并用可操作状态和原因约束下探。[文件源码与关系列表 ↗](../../../apps/web/src/codewiki/FileFrame.vue#L216 "支持不可变源码、关系可操作状态与原因，并证明可下探边和其他边分别切片为 60 条与 20 条。") 符号帧校验当前图对象，读取固定范围前后约六行的源码窗口。[符号上下文源码读取 ↗](../../../apps/web/src/codewiki/SymbolFrame.vue#L55 "支持符号和文件校验、总行数探测、上下文窗口计算、源码切片及关系降级读取。")

符号列表同时收集当前符号作为起点或终点的边，[触及当前符号的边筛选 ↗](../../../apps/web/src/codewiki/SymbolFrame.vue#L97 "支持符号帧同时收集当前符号作为起点或终点的关系，并标记入向或出向。") 但下探函数只解析关系的目标端。[关系下探仅解析目标端 ↗](../../../apps/web/src/codewiki/modules.ts#L184 "说明下探函数只检查关系的目标符号与目标文件，支持入向边可能指回当前符号的限制判断。") 因此旧有“入向、出向都会走向另一端”的结论已被替代：入向边可能再次指回当前符号，而非来源端。符号关联片段时可进入规则原文；片段帧按正反关系分组，优先把代码路径解析回文件，否则尝试进入另一片段。[片段关系分组与下探 ↗](../../../apps/web/src/codewiki/FragmentFrame.vue#L53 "支持正反关系分组、代码路径优先解析、片段后备导航，也证明无可解析目标时没有反馈分支。")

<a id="shared-trail-and-limits"></a>
## 共享 Trail、深链与当前限制

知识、模块、文件、符号和片段共用同一 Trail 抽屉；代码对象失效时，对应帧仍可恢复身份，但内容组件可能不渲染。[统一证据抽屉与条件渲染 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L371 "支持同一抽屉承载知识、模块、文件、符号和片段，并说明代码帧依赖当前图解析后才渲染。") 内存栈按 `kind + id` 识别循环且不截断，`MAX_TRAIL=200` 只定义为 URL 预算。[Trail 身份与 URL 深度预算 ↗](../../../packages/ui/src/trail.ts#L37 "支持联合身份循环检测、完整追加内存栈，并说明最大深度只针对 URL 持久化。") 共享哈希解析与写出都会按预算截取，[共享哈希解析与写出 ↗](../../../packages/ui/src/OmHashRoute.ts#L27 "支持防御性路由恢复，并证明共享解析器和写出函数均按 MAX_TRAIL 限制序列化栈。") 页面实际却手工写出完整栈，因此刷新后可能只恢复前 200 层。[页面实际哈希写出流程 ↗](../../../apps/web/src/codewiki/CodeWiki.vue#L218 "证明 Code Wiki 当前手工序列化完整 Trail，没有调用共享 writeHash，与共享深度预算形成不一致。")

关系界面仍不统一：模块 evidence 只是静态文本，[模块说明、证据与文件入口 ↗](../../../apps/web/src/codewiki/ModuleFrame.vue#L68 "支持模块说明的互斥展示、稳定文件入口，并证明 evidence 引用当前仅为静态行。") 片段关系在没有可解析文件或片段时会静默停留；[片段关系分组与下探 ↗](../../../apps/web/src/codewiki/FragmentFrame.vue#L53 "支持正反关系分组、代码路径优先解析、片段后备导航，也证明无可解析目标时没有反馈分支。") 文件帧只显示可下探边前 60 条和其他边前 20 条，[文件源码与关系列表 ↗](../../../apps/web/src/codewiki/FileFrame.vue#L216 "支持不可变源码、关系可操作状态与原因，并证明可下探边和其他边分别切片为 60 条与 20 条。") 符号帧也只显示前 60 条，且没有截断提示。[符号关系列表上限 ↗](../../../apps/web/src/codewiki/SymbolFrame.vue#L165 "直接支持符号边标题显示总数、实际只渲染前 60 条且没有截断提示的结论。") 这些限制与失效帧缺少 missing/stale 空态共同构成当前待完善边界。
