# lark · 模块理解

Lark 模块是 omem 的飞书/Lark 接入适配层，覆盖应用注册与复用、能力核验、所有者配对、实时事件、统一捕获、助手回复、决策卡片和通知投递。它复用公共输入、检索与记忆链路，并用收件箱、outbox、稳定标识和租约处理重投与故障；当前仍是 personal 单用户实现，群采集授权、消息修订语义、决策幂等和真实联调尚待补证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-boundary"></a>
## 作用、范围与安全边界

该模块不是独立知识库，而是 omem 与飞书/Lark 之间的接入层。默认应用配置面向消息、文档、日历、会议和任务等个人助理能力，并声明排除批量消息、会话成员变更及权限管理等高风险范围。[个人助理默认能力边界 ↗](../../../apps/server/src/integrations/lark/defaults.ts#L3 "支持默认配置面向个人助理能力，并明确排除部分高风险权限范围。") 捕获复用公共 `Store` 的 `InputAggregator`，检索结果继续回指不可变 fragment，使后续知识与回答能够追溯原始证据。[统一存储与输入聚合器 ↗](../../../apps/server/src/store.ts#L38 "支持 Lark 捕获复用公共 Store 和 InputAggregator，而非建立独立输入存储。")[统一检索证据边界 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持检索结果回指不可变 fragment，使回答能够追溯原始证据。")

接入记录当前固定写入 `personal` 工作区，因此只能视为单用户实现。Botmux 复用和直接凭据导入会调用统一的凭据接受流程；新建或 SDK 注册取得凭据后也汇入该流程。[接入记录与已有应用导入 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L83 "支持接入记录固定使用 personal 工作区，并证明 Botmux 与直接凭据导入进入统一凭据接受流程。")[注册凭据进入统一接受流程 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L167 "证明 SDK 注册返回凭据后调用统一凭据接受流程，补全新建注册与导入路径的汇合关系。") 凭据库要求 32 字节主密钥，以受限引用定位文件，并将目录权限收紧为仅所有者可访问。[凭据存储初始化与引用边界 ↗](../../../apps/server/src/integrations/lark/secret-store.ts#L22 "支持主密钥长度、受限目录、环境变量入口和凭据引用格式等安全边界。") 凭据写入采用 AES-256-GCM，经临时文件同步、重命名和权限收紧后落盘。[凭据认证加密与原子落盘 ↗](../../../apps/server/src/integrations/lark/secret-store.ts#L72 "支持 AES-256-GCM 加密、随机 IV、临时文件同步、重命名和文件权限收紧等密文写入过程。") 这些证据只覆盖所展示的 Lark 路径，不能外推为全仓库不存在其他明文凭据路径。

<a id="onboarding-flow"></a>
## 接入、能力核验与所有者绑定

官方能力探针先换取租户令牌，再并行查询机器人与应用信息，将实际权限和卡片回调与申请配置比较。公开应用接口不提供事件订阅列表，因此事件能力仍标为运行时核验，需要 WebSocket 的真实投递补证。[真实能力探针 ↗](../../../apps/server/src/integrations/lark/registration.ts#L141 "支持令牌获取、机器人与应用查询、权限和回调缺项计算，以及事件采用运行时核验标记。")[事件订阅运行时核验边界 ↗](../../../apps/server/src/integrations/lark/registration.ts#L135 "说明公开应用接口不暴露事件列表，事件订阅需由首次匹配的 WebSocket 投递确认。") onboarding 根据缺项把候选版本置为 `failed` 或 `awaiting_pair`；已有活动版本存在时，失败候选不会自动取代它。[候选版本能力判定 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L293 "支持凭据保存、候选版本创建、能力探测，以及依据缺项决定 failed 或 awaiting_pair。")

能力满足后，服务签发默认五分钟有效的随机配对码，仅保存 HMAC 摘要并消费同连接旧码。[短期配对码签发与接收 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L569 "支持配对码随机生成、默认有效期、HMAC 摘要保存、旧码消费和候选身份记录。") 管理端确认配对时，在事务中替换旧绑定、激活候选版本并创建通知与决策目标；若候选会话是群聊，还会创建已启用的群监控目标。[配对确认与绑定激活 ↗](../../../apps/server/src/integrations/lark/onboarding.ts#L665 "支持替换旧绑定、激活候选版本、创建业务目标及群聊监控目标。") 这条自动启用行为是否已获得明确采集授权，现有材料没有说明。

<a id="runtime-flow"></a>
## 实时事件、统一捕获与可靠回复

运行时用连接租约限制同一连接的持有者，并以 token 续租或释放。[连接租约仓库 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L223 "支持按连接抢占、过期替换、令牌续租和释放的连接所有权机制。") 消息先按应用和事件 ID 写入收件箱：重复载荷复用原记录，同 ID 不同摘要则拒绝，同时把实际事件类型加入能力画像。[事件收件箱去重 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L337 "支持按应用与事件 ID 去重、摘要冲突检查和实际事件能力画像更新。") `LarkRuntimeHost` 为连接管理器装配卡片处理器；在这套装配中，卡片事件直接进入卡片队列，但管理器本身只有配置处理器时才走该分支。[运行时连接与卡片处理器装配 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L110 "支持当前 LarkRuntimeHost 为连接管理器装配卡片动作处理器和配对服务。")[连接管理器的条件分派 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L924 "支持只有配置卡片处理器时卡片事件才直接入队，并说明配对优先级和普通消息回落路径。")

消息通过活动连接与绑定检查后，绑定 owner 的私聊可进入助手，群聊还必须明确提及机器人。[绑定身份与助手路由 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L503 "支持活动连接和绑定前置检查，以及 owner 私聊或明确提及机器人的群聊进入助手路径。") 未进入助手路径的群消息会自动插入启用的群监控目标并经公共输入聚合器捕获，因此并非所有首次群消息都会走捕获分支。[其余群消息捕获路径 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L602 "支持未进入助手路径的群消息自动创建监控目标，并调用统一输入聚合器捕获。") 文本、富文本和图片被转换为带发送者、事件时间及回复关系的统一 parts；图片下载调用没有局部异常降级。[富消息统一捕获转换 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L719 "支持文本、富文本和图片转换为带逐片来源信息的捕获输入，并显示图片下载异常边界。") 助手回复的变更、投递意图及 turn 关联在同一事务中写入，同一 turn 使用稳定平台 UUID。[助手回复事务 outbox ↗](../../../apps/server/src/integrations/lark/realtime.ts#L814 "支持按 turn 生成稳定平台 UUID，并事务化写入投递意图及回合关联。") outbox 提交后才完成 inbox；并发重投、既存 outbox 和恢复分支用于避免重复入队或补写缺失 outbox。[回复入队与收件箱完成顺序 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L550 "支持回复 outbox 先入队、再完成 inbox 的调用顺序，以及并发重投和恢复分支。")

<a id="decisions-delivery-limits"></a>
## 卡片决策、通知投递与限制

决策卡片不会直接执行业务。回调值必须符合固定协议，动作限于批准、拒绝或请求上下文，并携带 UUID、nonce、提案摘要、期限和预期版本摘要；未知字段也会被拒绝。[决策卡片回调协议 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L13 "直接支持协议字面量、动作枚举、UUID、nonce、摘要、期限、预期版本摘要及拒绝未知字段的严格输入约束。") 随后入口再核对应用、操作者、消息位置、连接、绑定、摘要、期限、nonce 与决策状态，条件消费成功后才创建命令。[卡片动作快照核验与入队 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L119 "支持回调在应用、操作者、消息位置、连接、绑定、摘要、期限、nonce 和决策状态核验后才被一次性消费并创建命令。") 这替代了此前仅用入队实现范围支撑“严格协议”的证据不足表述。

worker 领取到期或租约过期的命令，递增尝试次数并生成 lease token；完成写回必须仍持有该 token。[卡片命令租约 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L240 "支持命令领取、尝试计数、租约令牌和陈旧写回保护。") 执行阶段以稳定 requestId 调用记忆决策，再读取凭据并原位更新卡片。普通异常以及限流或结果不明错误可在五次以内重试；认证错误只可确认会调用 `disableBinding`，所给范围未展示该方法实现，不能断言其具体改写哪些绑定状态。[卡片决策执行与错误分支 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L355 "支持稳定 requestId、记忆决策、凭据读取、卡片更新、重试规则及认证错误调用 disableBinding；所选范围不包含该方法实现。")

普通通知也通过条件抢占取得租约，连接、绑定或标注会话失效时抑制发送。[通知投递租约抢占 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L190 "支持到期任务选择、失效状态抑制、条件抢占、尝试记录和一小时结果不明窗口。") 限流可在五次上限内重试；结果不明还受首次发送后一小时去重窗口约束。通知投递路径中的认证错误会禁用该连接的采集目标、将连接置为失败，并终止同连接中仍处于待发送或等待重试的其他意图。[通知重试与认证处置 ↗](../../../apps/server/src/integrations/lark/delivery.ts#L389 "支持限流与结果不明的重试边界，以及认证失败后对目标、连接和其他待处理意图的具体处置。") 运行时每轮先同步连接和准备聚合，再顺序消费卡片与投递任务，而非并发执行。[单轮任务处理顺序 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L195 "支持每轮先同步连接和准备聚合，再顺序消费卡片与通知投递任务。")
