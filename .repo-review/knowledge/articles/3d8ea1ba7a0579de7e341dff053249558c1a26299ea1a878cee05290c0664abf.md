# 评审来源迁移与关系失效测试

验证旧内容哈希来源迁移到路径身份时的碰撞处理、历史数据保留与幂等性，并验证代码修订换头后旧关系转为 stale、默认隐藏而历史查询仍可追溯。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="path-migration"></a>
## 从内容哈希迁移到路径身份

测试直接构造旧式 source、revision 和 fragment，文件路径仅位于 revision context，用来模拟迁移前数据库。[旧来源夹具结构 ↗](../../../apps/server/tests/review-migration.test.ts#L40 "说明如何直接构造迁移前的内容哈希来源、修订和片段。") 同一路径碰撞夹具中，胜者同时具有更高 version 和更晚 createdAt；迁移后它取得 `omem:<path>` 身份并保留 head，另一来源保留旧 external id、解除 head 且记录为历史别名，fragment 总量不变。[同路径碰撞与历史保留 ↗](../../../apps/server/tests/review-migration.test.ts#L111 "支持胜者同时具有更高版本和更晚时间时取得路径身份、旧来源降为别名且数据仍可读。") 这只能证明该组合下的结果，不能单独判断版本与时间戳各自的优先级。相同正文处在不同路径时则保留为两个当前来源。

<a id="idempotency"></a>
## 幂等性与历史数据

旧 external id 仍可解析到被降级来源，其 revision、fragment 和 history 均可读取。[同路径碰撞与历史保留 ↗](../../../apps/server/tests/review-migration.test.ts#L111 "支持胜者同时具有更高版本和更晚时间时取得路径身份、旧来源降为别名且数据仍可读。") 首次迁移稳定后，第二次执行返回零变更，external id、head 与 alias 快照一致；独立断言再次确认 fragment 总数不减少。[重复迁移与片段守恒 ↗](../../../apps/server/tests/review-migration.test.ts#L220 "支持第二次迁移无变更，以及迁移不减少 fragment 总量。") 尚未覆盖三个以上碰撞候选、版本与时间戳方向冲突、事务中断恢复或跨数据库版本兼容。

<a id="relation-lifecycle"></a>
## 修订换头后的关系生命周期

关系用例让代码来源从 v1 更新到 v2，再把 v1 fragment 与仍为当前的决策 fragment 建立 confirmed `implements`。执行失效处理后旧边转为 stale，默认 fragment 与 code-path 查询隐藏它，显式 historical/stale 查询仍可追溯；新 head 不会自动继承旧边。[旧关系失效与历史查询 ↗](../../../apps/server/tests/review-migration.test.ts#L306 "支持修订换头后关系转 stale、默认隐藏并可在历史模式中查询。") 测试只覆盖代码侧换头，未覆盖目标侧换头、双侧变化或同步重建 locator。
