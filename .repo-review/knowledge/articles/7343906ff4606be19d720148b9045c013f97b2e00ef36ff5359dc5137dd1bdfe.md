# 真实链路验证、质量评测与仓库知识维护

项目以真实 ACP 冒烟检查验证角色和任务链路，以人工标注、冻结数据集及离线门禁衡量提取质量，并通过共享知识流水线持续更新仓库 Wiki。各流程分别证明连通性、质量与知识时效，不能相互替代。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="validation-layers"></a>
## 真实链路验证什么

验证分为两个互补场景。角色冒烟先调用 extractor，再把提案及其稳定摘要交给 verifier，最终保存两阶段结果和运行轨迹；轨迹包含角色版本、上下文指纹、实际模型、推理强度、会话及修复次数。参考 [抽取与复核串联 ↗](../../../scripts/live-role-smoke.ts#L22 "支持真实角色冒烟依次执行抽取、构造带稳定摘要的候选并调用复核角色。")、[角色运行轨迹 ↗](../../../apps/server/src/agent-runtime/gateway.ts#L43 "支持运行轨迹记录角色版本、上下文、实际模型、推理强度、会话和修复次数。")

任务冒烟则把一条带应用、时间、操作者和来源上下文的中文承诺写入临时存储。参考 [中文任务捕获 ↗](../../../scripts/live-pipeline-smoke.ts#L20 "支持任务冒烟写入中文承诺及其应用、时间、操作者和来源上下文。") 随后运行学习流水线，并要求恰好处理两个作业、所有作业成功、唯一提案已应用且最终形成一个任务。参考 [任务冒烟成功条件 ↗](../../../scripts/live-pipeline-smoke.ts#L46 "支持学习流水线执行及处理数、作业状态、提案状态和任务数量断言。") 这些断言证明固定场景能够连通并落库，但未覆盖任务字段准确性、更多语言表达、时区边界或重复运行。

<a id="quality-evaluation"></a>
## 从人工标注到质量门禁

质量基准可从飞书文档启动人工标注：脚本导入评测数据、创建会话、启动运行宿主并等待卡片获得消息标识。参考 [标注会话与卡片送达 ↗](../../../scripts/quality-lark-annotate.ts#L52 "支持导入评测数据、创建会话、启动宿主并通过消息标识判断卡片送达。") 此后继续轮询标注事件；事件数增加时报告已收到标注，投递失败或等待超时则明确报错。参考 [标注事件与等待失败 ↗](../../../scripts/quality-lark-annotate.ts#L102 "支持轮询标注事件、报告接收状态以及处理投递失败和超时。") 规则拆分器仅用于研究标注，不属于普通捕获或学习流程。参考 [评测专用导入边界 ↗](../../../apps/server/src/quality/import.ts#L1 "支持规则拆分器仅服务人工研究标注，不得进入普通捕获和学习流程。")

在线 runner 验证冻结数据集并选择实际 ACP profile。参考 [冻结输入与在线模型 ↗](../../../scripts/quality-run.ts#L27 "支持 runner 验证冻结数据集并选择实际 ACP profile。") 每个样本在独立临时存储中重新捕获上下文，再调用学习流水线。参考 [样本隔离执行 ↗](../../../scripts/quality-run.ts#L63 "支持每个样本使用独立临时存储重新捕获上下文并调用学习流水线。") 有效提案被映射为预测对象及自动应用状态；已有预测支持按样本续跑和临时文件替换保存。参考 [提案映射为预测 ↗](../../../scripts/quality-run.ts#L109 "支持依据有效提案形成预测对象、自动应用状态、耗时和令牌用量。")、[预测续跑与替换保存 ↗](../../../scripts/quality-run.ts#L40 "支持跳过已完成样本并通过临时文件重命名保存预测。") 单样本失败会降级为 `needs_context`，清理临时数据后继续整批运行。参考 [失败预测与清理 ↗](../../../scripts/quality-run.ts#L157 "支持单样本失败时生成 needs_context 预测并清理临时存储。")

离线评估检查自动应用精确率、语义支持、引用位置、证据覆盖及预测完整性。参考 [质量门禁集合 ↗](../../../scripts/quality-evaluate.ts#L21 "支持评估报告中的精确率、语义支持、引用、证据覆盖和完整性门禁。") 任一门禁失败都会设置非零退出码并保留报告。参考 [评估报告与退出状态 ↗](../../../scripts/quality-evaluate.ts#L51 "支持保存评估报告并在门禁失败时设置非零退出码。") 语义支持采用确定性规则识别否定、限制条件丢失和时间错配，并非 LLM 裁判。参考 [确定性语义规则 ↗](../../../apps/server/src/quality/evaluator.ts#L33 "支持语义支持使用显式规则识别否定、反义、范围扩张和时间错配，而非调用 LLM。")

<a id="knowledge-refresh"></a>
## 仓库知识如何更新

仓库维护复用共享 `KnowledgePipeline`，按图片、会话属性和文件类型选择分析角色。参考 [材料分析角色选择 ↗](../../../apps/server/src/knowledge/pipeline.ts#L15 "支持共享知识流水线依据图片、会话属性和文件类型选择分析角色。") 角色请求会作为持久任务入列，记录材料、文章版本、模型、预算和角色包摘要；完成后从角色输出表读取结果与 trace，并执行调用方提供的校验（如有）。参考 [持久知识角色任务 ↗](../../../apps/server/src/knowledge/pipeline.ts#L60 "支持角色请求入列、依赖与配置记录、结果和轨迹读取，以及可选调用方校验。")

入口先同步捕获材料与代码投影，再选择受影响材料、补充有限的 import 邻接上下文并记录覆盖状态；分析失败会留下记录并使进程返回非零状态。参考 [知识分析与覆盖记录 ↗](../../../scripts/review-knowledge.ts#L41 "支持同步、材料选择、有限邻接上下文补充、覆盖记录及分析失败的退出语义。") 模块合成只在组内子知识均为 current 时进行；定向更新逐层修复受影响的既有祖先，只有无前置失败的全库运行才重新规划主题和总览，最终索引仅收录 current 页面。参考 [分层合成与当前索引 ↗](../../../scripts/review-knowledge.ts#L82 "支持模块合成门槛、定向祖先修复、全库规划条件和仅收录 current 页面的索引生成。")

<a id="limits"></a>
## 证据边界与验收限制

三类流程留下不同证据：角色冒烟保存运行轨迹，质量流程保存预测、用量、错误和门禁报告，知识维护保存持久输出、覆盖记录及合成失败。因此，命令结束、任务入列或文件写出都不能单独代表业务正确或知识复核完成。

代码图只是已捕获 Fragment 上的确定性投影；输入树变化会形成新快照，最新解析未重现的关系转为 stale。参考 [代码投影快照边界 ↗](../../../apps/server/src/code/sync.ts#L1 "支持代码图依附已捕获 Fragment、按输入形成快照，并将未重现关系标为 stale。") 它适合辅助选材和定位，但不能证明跨版本符号身份连续，也不能把 import 邻接直接解释成完整的跨文件调用关系。
