# 真实链路验证、质量评测与仓库知识维护

这些脚本把真实模型冒烟验证、冻结数据集评测、飞书人工标注和仓库知识重建组织为显式运维入口。它们复用应用的角色、学习、存储与代码投影能力，并通过隔离数据、可追溯报告和失败退出码区分“链路可运行”与“业务质量已证明”。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="live-validation"></a>
## 用真实模型检查关键链路

真实链路检查分为两个层次。角色冒烟脚本从 ACP 选择可用模型，先运行抽取角色，再把提案及稳定摘要交给复核角色，最后保存两阶段结果和运行轨迹；它证明角色协议、模型调用与结构化输出可以串联，但没有应用提案或断言语义质量。参考 [抽取与复核角色冒烟 ↗](../../../scripts/live-role-smoke.ts#L10 "支持真实 ACP profile 下先抽取、再以稳定摘要组织候选并独立复核，最后保存结果与轨迹的流程。")

学习流水线冒烟捕获一条含负责人、截止时间和应用上下文的中文任务，复用记忆、反馈与学习服务处理队列，并要求两个作业成功、一个提案已应用且形成一个任务。其成功条件仍偏向数量和状态，未核对任务字段及证据链。参考 [学习流水线行为断言 ↗](../../../scripts/live-pipeline-smoke.ts#L20 "支持中文任务捕获、学习服务组装以及对作业、提案和任务数量与状态的成功条件。")

两类检查共同回答“真实配置下能否跑通”，不能替代质量评测；运行轨迹记录实际模型、推理强度、输入指纹和修复次数，为失败追查提供依据。参考 [角色运行追踪字段 ↗](../../../apps/server/src/agent-runtime/gateway.ts#L43 "支持运行轨迹记录角色版本、上下文指纹、实际模型、推理强度、使用量和修复次数。")

<a id="quality-loop"></a>
## 从人工样本到离线质量门禁

质量流程把人工判断与在线预测分开：飞书入口把指定文档转成仅供评测的草拟样本，普通捕获、学习与知识生产不得调用这套规则切分器。参考 [评测样本隔离规则 ↗](../../../apps/server/src/quality/import.ts#L1 "支持飞书文档切分器只用于人工评测，不得进入普通捕获、学习或知识生产。") 标注脚本启动卡片会话并轮询消息与事件，但当前“收到标注”依据全局事件表计数增长，未限定到本次会话，并发活动可能造成误判。参考 [飞书标注等待判据 ↗](../../../scripts/quality-lark-annotate.ts#L52 "支持标注会话启动、卡片消息观察以及以全局事件总数增长作为成功信号的当前实现。")

冻结数据集运行器逐样本创建临时存储，把来源和可信度重新捕获后调用真实学习流水线；已有预测会按样本标识跳过，结果以临时文件替换方式持续保存，便于中断续跑。参考 [预测续跑与原子保存 ↗](../../../scripts/quality-run.ts#L40 "支持已有预测校验、按样本跳过、批次限额以及通过临时文件重命名保存结果。") [隔离样本执行 ↗](../../../scripts/quality-run.ts#L63 "支持每个冻结样本使用独立临时存储重新捕获，并调用学习流水线形成预测。") 单样本失败会降级为 `needs_context`，不会终止整批运行。参考 [失败样本降级 ↗](../../../scripts/quality-run.ts#L157 "支持单样本异常转为 needs_context、清理临时存储并继续持久化批量结果。")

预测完成后，离线评估器校验冻结集并计算自动应用精确率、语义支持、引用位置、证据覆盖和完整性等指标；门禁失败仍写出报告，但进程返回非零状态。参考 [离线质量门禁 ↗](../../../scripts/quality-evaluate.ts#L14 "支持冻结集校验、预测摘要、质量阈值以及缺失预测门禁。") 其中语义支持使用确定性规则区分否定翻转、限制丢失和时间错配，并明确区别于“引文是否出现在原文中”。参考 [确定性语义支持判定 ↗](../../../apps/server/src/quality/evaluator.ts#L33 "支持语义支持与引用位置分离，并说明否定、反义、限制、时间和词汇重合等规则边界。")

<a id="knowledge-maintenance"></a>
## 按变更重建仓库知识

仓库知识生成要求显式配置 ACP profile，并把并发数限制为 1–6；路径目标及是否合成模块由运行参数决定。参考 [知识生成配置与并发 ↗](../../../scripts/review-knowledge.ts#L21 "支持知识生成必须使用显式 ACP 配置、并发范围为 1–6，以及路径和模块相关参数的读取。") 主流程先同步原始材料和代码图，再分析选定目标；分析上下文可补充链接材料和最多四个 import 邻接文件，但这些邻接信息不能解释为完整的跨文件调用证据。参考 [知识材料选择与分析 ↗](../../../scripts/review-knowledge.ts#L41 "支持仓库同步、代码投影、目标扩展及通过 imports 边有限补充分析上下文的流程。")

分析结果会记录 reviewed、stale、pending 与失败状态。启用模块合成时，只处理受影响分组，且组内全部子材料都有当前知识才会合成；模块任务按配置的有限并发执行。定向更新沿既有依赖修复祖先，全库无前置失败时才重新规划主题和总览，最终索引只纳入 current 页面。参考 [分层合成与覆盖记录 ↗](../../../scripts/review-knowledge.ts#L71 "支持失败状态记录、受影响模块的合成门槛、按配置并发合成、祖先修复、全库规划及 current 页面索引规则。")

底层代码同步只是已捕获 Fragment 上的确定性投影：相同输入复用快照，代码树变化产生新快照，未重现的符号和边转为旧状态；它不捕获文件正文，也不证明跨 revision 身份连续。参考 [代码投影快照边界 ↗](../../../apps/server/src/code/sync.ts#L1 "支持代码同步不捕获正文、相同输入复用快照以及未重现结构转为旧状态的能力边界。")

<a id="wiki-boundaries"></a>
## Wiki 输出与发布边界

Wiki 构建入口同样先执行捕获和代码投影。显式生成必须指定目标；若已有共享知识且未请求生成，则只重建共享索引，否则才从当前快照组织文件、符号和模块视图。参考 [Wiki 构建分支 ↗](../../../scripts/review-wiki.ts#L15 "支持捕获与投影先行、显式生成目标约束，以及共享知识索引和当前快照两条分支。")

阅读输出优先展示每个目标的最新理解，模型结果排在人工 seed 前，并用限定符号名和源码链接替换内部标识；没有理解记录时退化为确定性文件目录。参考 [可读 Wiki 组织 ↗](../../../scripts/review-wiki.ts#L52 "支持理解记录去重排序、内部符号可读化、源码链接以及无说明时退化为文件目录。") Markdown 先写入运行时 staging，内容变化后再复制到最终 Wiki。参考 [Wiki 分阶段写入 ↗](../../../scripts/review-wiki.ts#L71 "支持 Markdown 先写 staging、内容变化时复制到最终位置及最终关闭存储。") 当前材料没有显示理解文件、索引和 Wiki 之间存在统一发布事务，因此中途写入失败是否允许保留部分产物仍需明确。
