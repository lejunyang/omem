# 可追溯 Agent 的角色协作与模型治理

Agent 运行时通过版本化角色包、可信配置与不可信材料分层、模型能力发现、预算约束、结构化合同和运行追踪，把知识维护与代码理解组织为受控但彼此边界清晰的能力。现有实现已覆盖多项确定性防线，但知识发布闭环、代码理解结果的外层复核、崩溃恢复及部分真实模型能力仍需运行证据确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为什么需要受控的 Agent 运行时

项目希望模型理解对话、文档、图片与代码，同时避免把材料中的命令、历史计划或模型推断误当成当前事实。运行时因此把角色说明、技能、输出合同和来源元数据放入可信区，把材料正文及派生知识明确视为不可信数据；材料可以影响分析结果，但不能取得指令权限。参考 [受控运行与证据边界 ↗](ce3ad4fc88f2b92811c88b3fb866eb2747d1ebcbc3d8833fbc8c7668ab989463.md#purpose "说明版本化角色、固定证据、结构化结果和专职角色用于限制材料指令及推断越界。") [可信提示与材料分层 ↗](402a146c3874836a69ae98ef2a63453025eeec309fa0869430e72fb5582bf565.md#purpose_and_prompt "说明角色配置和来源索引进入可信区，而派生知识及材料正文被包装为不可信数据。")

治理还要求区分材料陈述、实现事实和历史状态，尤其不能把旧计划直接写成已实现能力。参考 [材料时态与事实边界 ↗](../../../packages/agent-runtime/roles/material-analyst/1/prompt.md#L1 "直接支持材料分析必须区分文档陈述、实现事实和历史状态。") 由此，模型输出不只是自然语言回答，而是限定在固定证据范围内、能够追踪来源与运行配置的结构化产物。

<a id="roles"></a>
## 知识维护与代码理解的不同角色边界

知识侧把职责拆为材料分析、章节规划、文章撰写或刷新、独立复核：分析者澄清事实与时态，规划器组织知识树，作者把依据放在论断附近，复核者判断引用是否支持正文。规范给出了建议处理顺序，但现有角色定义没有证明任务状态机已强制串联这些阶段。参考 [知识角色职责分工 ↗](95b177e06915baa0e87ddd239f792a05585e0b3f2a1d1ba45d52b325ca8083d7.md#roles "解释材料分析、知识撰写和独立复核的不同职责及共享证据纪律。") [知识维护建议流程 ↗](3b1542b125303d63624c852b41e8f275ecaed4900dddfdeab69c561a56893450.md#expected_workflow "支持规划、刷新和独立复核的建议处理顺序，并保留尚未证明实际编排的限制。")

代码侧的仓库画像、符号解释和关系核验是并列视角：它们分别回答模块边界、局部行为和候选关系是否能由固定图支撑；现有材料没有规定这些结果进入知识复核或发布流程的接口。参考 [代码理解角色范围 ↗](ed88eabf12186f63b86a50684a369439d99d9a40fdbb951f59e9290769a059d2.md#role_scope "说明仓库画像、符号解释和关系核验的尺度差异、并列关系及尚未证明的阶段衔接。") 符号解释只能从快照中的边确定调用关系，缺少边表示未知，不能据此断言不存在关系。参考 [缺失图边的解释规则 ↗](ed88eabf12186f63b86a50684a369439d99d9a40fdbb951f59e9290769a059d2.md#evidence_rules "直接支持调用关系只能来自固定快照中的边，缺少边应记为未知而非断言无关系。")

因此，知识正文复核与代码关系核验应视为两种不同职责：前者检查文章论断及引用，后者重新核对代码图中的候选关系；二者是否由外层任务进一步衔接仍待实现证据确认。

<a id="runtime"></a>
## 模型、权限与运行过程如何受约束

执行前，运行时加载并校验角色包，匹配指定 profile、工具白名单和会话策略。ACP 会根据实际会话选项校验模型与推理强度；输入包含图片时，还要求 Agent 声明图片能力，不支持的配置会在发送提示前失败。参考 [模型配置与图片能力检查 ↗](../../../apps/server/src/agents.ts#L301 "直接支持 ACP 根据实际配置选项校验模型和推理强度，并在图片输入前检查多模态能力。")

文本预算按 UTF-8 字节数除以 3 估算 token，再增加 25% 余量。它是面向代码和中英文混合内容的安全近似，并非具体模型的 tokenizer，不能代表精确用量或计费。参考 [令牌预算估算规则 ↗](../../../apps/server/src/agent-runtime/budget.ts#L1 "直接支持按 UTF-8 字节近似估算 token 并增加 25% 预算余量。")

成功运行会记录角色包、提示、上下文、技能和工具摘要，以及有效模型、推理强度、会话、用量和修复次数；运行指纹只组合关键摘要与模型配置。参考 [运行追踪与指纹 ↗](../../../apps/server/src/agent-runtime/gateway.ts#L368 "直接支持成功运行记录的追踪字段，以及指纹由关键摘要、模型和推理强度组成。") Agent 发起的权限或补充输入请求可被记录为已拒绝，相同会话请求若携带不同载荷则报告幂等冲突，不会静默授权。参考 [运行时请求拒绝记录 ↗](../../../apps/server/src/agent-runtime/requests.ts#L40 "直接支持权限和补充输入请求以 denied 状态幂等持久化，并检查载荷冲突。")

<a id="progress_limits"></a>
## 当前进展与尚未闭合的环节

代码理解已经具备固定快照、角色资产摘要、输入封印、引用存在性和行号范围等确定性校验；结构错误返回失败，封印或引用错误返回拒绝。参考 [代码结果确定性校验 ↗](1d33a8899c49964fac8dab4b336aa8e90afd1bd833fed7e3735c3b028a0051ff.md#asset-validation-flow "解释代码理解输出如何核对角色、资产摘要、快照摘要、引用和选择器范围。") 无模型时只能生成低置信度的机械事实 seed，不能携带解释性结论；校验器也不负责判断自由文本语义是否真实或决定是否发布。参考 [无模型降级边界 ↗](1d33a8899c49964fac8dab4b336aa8e90afd1bd833fed7e3735c3b028a0051ff.md#fallback-boundaries "说明无模型 seed 只能包含机械事实，以及校验器不负责自由文本语义和发布决策。")

更广义的运行时已经具备角色包加载、信任分层、预算、有限输出修复、模型能力检查和运行追踪，但现有依据仍不足以确认知识生成、独立语义复核和发布已形成强制闭环，也未证明任务重领必然复用已保存结果。参考 [运行时进展与未闭环部分 ↗](ce3ad4fc88f2b92811c88b3fb866eb2747d1ebcbc3d8833fbc8c7668ab989463.md#progress_limits "汇总已实现的确定性治理能力，并支持完整角色编排、发布闭环和崩溃恢复仍待补证的判断。") 最终知识制品可以记录依赖摘要、生成轨迹和已接受的复核信息，但类型定义本身没有说明依赖变化后的过期处理或失败结果覆盖策略。参考 [知识制品溯源字段 ↗](../../../packages/contracts/src/knowledge.ts#L73 "直接支持最终知识制品记录依赖摘要、生成轨迹及已接受的独立复核信息。")
