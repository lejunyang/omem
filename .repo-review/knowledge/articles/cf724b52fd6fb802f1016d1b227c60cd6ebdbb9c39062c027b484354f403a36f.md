# 知识库阅读与整理入口重设计

说明知识库界面如何分离日常阅读与知识整理，改进分类导航、材料选择、响应式弹窗和折叠交互，并明确截至 2026-10-02 的验证范围与尚未覆盖的能力。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="reader_problem"></a>
## 从拥挤的分类页回到阅读任务

这次重设计解决的核心问题，是整理表单、重复导航和错位的材料勾选框干扰了读者浏览文章。此前的检查只确认控件存在，没有验证表单展开后的真实页面状态，因此布局缺陷仍进入了实际界面。参考 [改版问题背景 ↗](../../../docs/reader-first/ui-redesign.md#L1 "支持分类页首屏拥挤、重复导航、勾选框错位以及既有检查未覆盖真实展开状态的说明。")

新的分类首页首先呈现标题、摘要和文章列表，把“阅读已有知识”作为默认任务；创建入口则打开独立的两步弹窗，使整理知识成为明确但不抢占首屏的操作。分类名称用于进入列表，箭头只负责展开目录，分类结构仍取自持久化数据。参考 [阅读与整理分流 ↗](../../../docs/reader-first/ui-redesign.md#L5 "支持分类首页、两步弹窗、目录交互、材料筛选以及继续使用原有生成流程的描述。")

<a id="composition_flow"></a>
## 两步整理与大量材料选择

整理流程允许用户搜索材料、只查看已选项并分批显示，适合材料达到数百项时缩小选择范围。最终提交的仍是**已选材料范围与阅读目标**，后续继续进入原有的调查、写作和独立复核流程；因此这轮改变的是入口和选材体验，并未另造一套知识生成机制。参考 [阅读与整理分流 ↗](../../../docs/reader-first/ui-redesign.md#L5 "支持分类首页、两步弹窗、目录交互、材料筛选以及继续使用原有生成流程的描述。")

草稿在步骤切换以及关闭后重新打开时保留，成功提交后才清空。弹窗在手机上转为全屏，底部操作按钮固定可见；文档同时要求在桌面、768px 和 390px 宽度下检查长标题、选材行对齐和展开后的间距。参考 [草稿与响应式弹窗 ↗](../../../docs/reader-first/ui-redesign.md#L7 "支持草稿生命周期、手机全屏、固定底部按钮及多视口检查要求。")

<a id="shared_interactions"></a>
## 统一折叠交互与能力边界

公共 `OmDisclosure` 取代了业务页面中的原生折叠元素，并用于分类目录。普通标题可整行展开，而分类目录将“进入分类”和“展开子项”分成两个操作；组件支持受控状态、默认展开、标题与元信息插槽，并保留收起内容。变更对比和运行详情仍在展开事件发生时加载。参考 [公共折叠组件 ↗](../../../docs/reader-first/ui-redesign.md#L13 "支持 OmDisclosure 的适用范围、交互差异、组件能力和延迟加载行为。")

截至 2026-10-02，浏览器检查覆盖了键盘 Enter、ARIA 状态及其关联内容、草稿保留、标题导航与展开分离、减少动画和窄屏布局；实际开发页面的交互检查和组件展示的桌面、手机截图也已完成。参考 [交互与可访问性检查 ↗](../../../docs/reader-first/ui-redesign.md#L17 "支持键盘 Enter、ARIA 状态、草稿保留、导航与展开分离、窄屏布局以及实际截图检查等验证结果。")

整理提交检查拦截了生成请求，只验证材料范围和目标，并不等同于真实模型生成；固定引用首次在 5 秒内未完成，改用 30 秒等待后通过，也不能据此宣称服务性能改善。此次 UI 调整同样不能证明检索相关性或文章质量已经提高。参考 [验证边界与性能现象 ↗](../../../docs/reader-first/ui-redesign.md#L9 "支持真实页面的部分验证范围，并明确真实模型生成、服务性能、检索相关性和文章质量未被本轮证明。")
