# 服务端配置加载与运行时参数组装

该模块以 Zod 校验本地配置文件，补齐通知、学习、飞书与捕获目录等默认值，再叠加数据目录、鉴权令牌、监听地址和端口等环境变量，形成服务端统一运行时配置。它复用共享 profile 合同与检索配置 schema，并阻止重复 profile 标识。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-schema"></a>
## 配置边界与默认策略

模块集中定义服务端配置：至少需要一个 agent profile；通知支持即时或摘要模式，外部通知可按窗口或本地时间调度；学习和飞书默认关闭，轮询周期受上下限约束。时区会通过 `Intl.DateTimeFormat` 验证 IANA 名称，定时时刻限定为 `HH:mm`。根对象、`notifications.external`、`learning` 和 `lark` 明确使用严格 schema，会拒绝未声明字段；但 `notifications` 对象本身未调用 `.strict()`，其额外字段按 Zod 默认行为被剥离，这是严格边界中的例外。[服务端配置结构与严格边界 ↗](../../../apps/server/src/config.ts#L6 "支持通知、时区、学习和飞书的约束及默认值，并准确区分显式 strict 的对象与未启用 strict 的 notifications 层。")

检索配置复用 retrieval factory 导出的严格 schema，统一约束启用标志、模型名格式及默认模型；未提供 retrieval 时保持可选。[检索配置定义 ↗](../../../apps/server/src/retrieval/factory.ts#L9 "说明检索配置的字段、默认模型、模型名格式及严格对象边界来自检索模块。")

<a id="load-flow"></a>
## 加载流程与运行时补充

`loadConfig` 优先解析 `OMEM_CONFIG` 指向的文件；若该路径不存在，则回退到示例配置。内容先经过 JSON 解析与 schema 校验，再检查 profile ID 是否重复，重复时立即失败，避免后续按 ID 选择代理配置产生歧义。[配置文件解析与 profile 去重 ↗](../../../apps/server/src/config.ts#L95 "支持配置文件选择、JSON 与 schema 解析，以及重复 profile ID 被拒绝的加载流程。")

校验完成后，函数解析 `OMEM_DATA_DIR` 或默认 `.omem`，递归创建权限模式为 `0700` 的目录，并派生 agent 工作目录。令牌、监听地址和端口来自环境变量，默认监听回环地址与 4317 端口。[运行时环境参数组装 ↗](../../../apps/server/src/config.ts#L107 "支持数据目录创建、工作目录派生，以及令牌、主机和端口的环境变量来源与默认值。")

<a id="relations-and-limits"></a>
## 模块关系与边界条件

profiles 由共享 contracts 中的 `profileSchema` 校验，表明其结构权威位于跨包合同层；但当前获准材料只覆盖 contracts 文件前 70 行，未展示该 schema 的定义，因而无法确认 profile 的完整字段、默认值及约束。[共享 profile 合同依赖 ↗](../../../apps/server/src/config.ts#L1 "证明服务端配置导入共享 profileSchema，同时界定当前材料无法核验其具体定义。") 检索配置关闭或缺失时创建关键词检索，启用后才加载中文 embedding、启动语义检索，并提供关闭生命周期。[检索实例创建分支 ↗](../../../apps/server/src/retrieval/factory.ts#L14 "解释 retrieval 配置如何决定关键词检索或语义检索，并支持语义检索的启动与关闭生命周期。")

`OMEM_PORT` 目前只经过 `Number` 转换，没有整数、有限值或合法端口范围校验；非法字符串可能得到 `NaN`。此外，文件存在但 JSON 或 schema 无效时不会回退示例配置，读取、解析和目录创建错误也会直接抛出。[加载函数失败边界 ↗](../../../apps/server/src/config.ts#L95 "支持端口仅经过 Number 转换，并说明文件回退、解析和目录创建所在的执行边界。")
