# 服务端配置加载与运行环境派生

使用严格 schema 校验用户配置，并从环境变量派生数据目录、Agent 工作目录、鉴权令牌和监听地址；显式配置文件不存在时直接使用示例配置。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="schema"></a>
## 配置合同与默认值

配置以 Zod 严格对象定义，至少需要一个 Agent profile，并覆盖通知、检索、捕获根目录、学习任务和飞书轮询。外部通知支持即时、时间窗或定时模式；当地时间和 IANA 时区在加载阶段校验。学习与飞书集成默认关闭，体现这些外部能力需要显式启用。[服务配置 schema ↗](../../../apps/server/src/config.ts#L6 "支持通知策略、时区校验、捕获根目录以及学习和飞书默认关闭等配置合同。")

<a id="loading"></a>
## 文件选择与运行时字段

加载器只先确定一个候选文件：若设置 `OMEM_CONFIG` 就使用该路径，否则使用工作目录的 `omem.local.json`；该候选不存在时直接读取示例配置。它不会在“显式路径不存在”后再尝试本地配置，这一表述取代此前的三级顺序说法。JSON 通过 schema 后还会检查 profile ID 唯一性。[配置文件选择与 profile 去重 ↗](../../../apps/server/src/config.ts#L95 "支持单一候选配置文件、候选不存在时使用示例配置及 profile ID 唯一性检查。")

数据目录、Agent 工作目录、token、host 和 port 从环境派生，数据目录会以私有权限创建。[运行环境字段派生 ↗](../../../apps/server/src/config.ts#L107 "支持数据目录、工作目录、token、host 和 port 的具体派生方式。") 数据库打开、迁移、资源目录创建及数据库文件权限收紧由 `Store` 构造过程负责，而不是本配置模块。[存储初始化与权限 ↗](../../../apps/server/src/store.ts#L43 "支持数据库创建、迁移、资产目录建立及数据库文件权限收紧由 Store 完成。")

<a id="boundaries"></a>
## 边界条件

schema 使用 `.strict()`，未知顶层键以及学习、飞书子项中的未知键会被拒绝。`captureRoots` 本身只是字符串数组；实际导入时，connector 会解析目标与根目录的真实路径并检查包含关系。[文件导入根目录约束 ↗](../../../apps/server/src/connectors.ts#L10 "说明 captureRoots 的安全语义在 connector 中通过真实路径解析实施。")

端口目前仅经 `Number(...)` 转换，材料中没有显示有限数、整数或 1–65535 范围校验，因此配置成功并不等同于监听端口一定有效。[运行环境字段派生 ↗](../../../apps/server/src/config.ts#L107 "支持数据目录、工作目录、token、host 和 port 的具体派生方式。")
