# 服务启动配置：从本地 JSON 到运行时上下文

服务端配置入口读取本地 JSON，统一校验 Agent、通知、检索、学习与飞书选项，补齐默认值，并把数据目录、工作区、访问令牌和监听地址组装成应用可直接消费的 Config。它是启动前的失败边界，也是多个运行模块共享配置的汇合点。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

`config.ts` 把“用户写下的配置”转换成“服务可以直接使用的运行时上下文”。文件配置至少要有一个 Agent profile；通知、材料采集根目录、检索、后台学习和飞书开关在这里获得结构约束或默认值。这样下游不必各自解析 JSON，也不会各自发明默认行为。参考 [核心配置结构 ↗](../../../apps/server/src/config.ts#L18 "支持配置层统一约束 Agent、通知、检索和采集根目录，并为通知提供默认值。") [可选运行模块 ↗](../../../apps/server/src/config.ts#L58 "支持学习与飞书的字段、轮询范围、默认关闭行为及严格对象校验。")

Agent profile 与检索配置并非在本文件重复定义：前者复用公共合同，后者复用检索工厂的 schema。因此 profile 的传输方式、命令、超时等限制，以及语义模型名和重排器格式，都与真正的运行模块保持同一套约束。参考 [Agent 配置合同 ↗](../../../packages/contracts/src/index.ts#L159 "说明 profileSchema 的字段和限制来自公共合同，而非由服务配置文件自行重复定义。") [检索配置合同 ↗](../../../apps/server/src/retrieval/factory.ts#L9 "说明检索开关、模型名和重排器的校验由检索工厂提供，并由实际检索创建逻辑消费。")

<a id="startup-flow"></a>
## 一次服务启动如何经过配置层

以直接启动服务为例，入口先调用 `loadConfig()`，再把结果交给 `buildApp`，最后用其中的 `host`、`port` 监听端口。参考 [服务启动调用 ↗](../../../apps/server/src/main.ts#L1 "证明主入口调用 loadConfig，将结果传给 buildApp，并以配置的主机和端口监听。")

```mermaid
flowchart LR
  A[读取 OMEM_CONFIG 或默认路径] --> B[读取 JSON]
  B --> C[Zod 校验并补默认值]
  C --> D[检查 profile ID 唯一]
  D --> E[创建数据目录并派生运行字段]
  E --> F[buildApp 装配服务]
  F --> G[监听 host 与 port]
```

`loadConfig` 优先解析 `OMEM_CONFIG` 指向的路径，否则看当前目录的 `omem.local.json`；目标不存在时读取示例配置。校验通过后检查 profile ID 不重复，创建权限模式为 `0700` 的数据目录，并派生 Agent 工作区、令牌、主机与端口。参考 [配置加载与派生 ↗](../../../apps/server/src/config.ts#L95 "支持配置路径回退、JSON 解析、profile 去重、数据目录创建和环境变量派生的完整主流程。")

应用装配会把这些结果继续分发：数据目录和通知策略进入存储，ACP profile 与 Agent 工作区进入助手，检索配置进入检索服务。由此可见本文件只负责形成配置，不负责启动这些子系统。参考 [应用装配消费点 ↗](../../../apps/server/src/app.ts#L54 "证明配置结果被存储、助手、知识研究工作区和检索服务实际消费。")

<a id="boundaries"></a>
## 校验边界与修改入口

通知时区必须是运行环境认可的 IANA 时区；外部通知窗口限制在 1 秒到 24 小时，计划时间采用 `HH:mm`。学习轮询限制为 50–60000 毫秒，飞书轮询限制为 100–60000 毫秒；两者默认关闭。顶层、外部通知、学习和飞书对象拒绝未声明字段。参考 [通知时间约束 ↗](../../../apps/server/src/config.ts#L6 "支持 IANA 时区验证、通知窗口范围和计划时间格式等边界。") [可选运行模块 ↗](../../../apps/server/src/config.ts#L58 "支持学习与飞书的字段、轮询范围、默认关闭行为及严格对象校验。")

需要留意两个边界：指定的配置文件不存在时会静默回退到示例文件；`OMEM_PORT` 只经 `Number(...)` 转换，本文件没有检查整数、范围或有限值。`agentCwd` 也只是拼出路径，实际目录由使用它的运行模块按需处理。若监听非回环地址，安全要求不在配置解析器中，而是在应用装配时强制必须提供 `OMEM_TOKEN`。参考 [配置加载与派生 ↗](../../../apps/server/src/config.ts#L95 "支持配置路径回退、JSON 解析、profile 去重、数据目录创建和环境变量派生的完整主流程。") [非本机监听保护 ↗](../../../apps/server/src/app.ts#L54 "说明非回环地址必须配置令牌的安全检查发生在应用装配阶段。")

修改配置字段时，应把通用结构放在对应公共 schema，把启动期环境覆盖和派生路径留在 `loadConfig`；新增字段还要沿 `buildApp` 的真实消费点接入，避免出现“校验通过但无人使用”的配置。
