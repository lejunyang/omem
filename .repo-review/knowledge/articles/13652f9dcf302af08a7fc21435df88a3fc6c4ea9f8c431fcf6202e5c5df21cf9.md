# 代码理解种子投影集成测试

该测试验证人工维护的代码理解种子从仓库捕获、代码图同步到持久化查询的完整投影过程，覆盖幂等同步、无效定位器拒绝、源码变化后的过期续接、无模型时的只读 HTTP 服务、原始数据隔离，以及真实仓库中五个必需模块的当前种子可用性。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="fixture-and-flow"></a>
## 夹具与同步流程

测试为每个用例创建独立的临时 SQLite Store，并在结束时关闭数据库、删除目录，避免状态互相污染。[临时 Store 的创建与清理 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L20 "支持每个测试使用独立数据库目录并在用例后完成清理的说明。") 最小 Git 仓库包含 `Alpha` 类、方法与辅助函数；人工种子用仓库相对路径、限定符号名、类型及行号描述流程、声明和证据。[最小源码与人工种子夹具 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L55 "支持夹具源码结构以及种子通过路径、限定名和证据选择器描述理解内容的说明。")

用例先执行 review 捕获，再执行代码同步并读取理解结果。这符合代码图作为既有 Fragment 派生投影的边界：同步解析源码并关联当前原文，但不另行捕获文件正文。[代码同步的派生投影职责 ↗](../../../apps/server/src/code/sync.ts#L1 "解释代码同步基于已捕获 Fragment 建图、不另行捕获文件正文及按快照更新的边界。")

<a id="projection-lifecycle"></a>
## 投影校验与版本生命周期

有效种子会成为唯一当前记录，保留人工种子来源、低置信度及“未由模型或独立代理验证”的元数据；相同快照再次同步仍保持单条当前结果，并能读取已解析的节点引用。[有效种子的幂等投影断言 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L110 "支持当前种子的状态、来源、验证标志、置信度、重复同步幂等和节点引用断言。") 投影过程会解析稳定定位器、封存输入摘要并执行严格交叉引用校验，同时不改写原始代码图。[人工理解投影的严格边界 ↗](../../../apps/server/src/code/understanding-store.ts#L1 "解释稳定定位器解析、摘要封存、交叉引用校验、失败不遮蔽有效结果及原始图只读约束。")

引用不存在符号的种子会留下 `rejected` 审计记录，却不会进入默认当前列表或遮蔽有效结果。[不存在符号的拒绝行为 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L147 "支持错误符号种子保留 rejected 历史记录但不污染默认当前列表的结论。") 源码变化后则生成新的当前理解，把旧记录标为 stale，并通过替代关系保留版本链，而非原地覆盖。[源码变化后的过期与替代关系 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L178 "支持输入快照变化产生新理解、旧理解标记 stale 并记录 supersedes 关系。")

<a id="http-isolation-and-scope"></a>
## HTTP 降级、数据隔离与验收范围

未配置模型时，状态接口明确返回不可用，但理解列表、详情和原始代码图仍可读取，说明只读浏览不依赖生成式模型。[无模型配置时的只读 HTTP 行为 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L215 "支持模型不可用时理解列表、详情与原始代码图仍然可读的降级行为。") 重复投影前后 `sources` 与 `fragments` 数量不变，也证明派生理解不会污染原始 review 数据。[原始 review 行隔离断言 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L251 "支持理解投影重复运行不会增加 sources 或 fragments 行数的结论。")

真实仓库用例确认同步得到一定规模的代码文件，并检查 assistant、memory、retrieval、Lark 集成和 Web 五个必需模块存在可用的当前人工种子，同时核对返回种子的基础元数据。[真实仓库五个必需模块验收 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L272 "支持真实仓库用例仅确认五个指定模块存在当前种子及基础元数据，并界定其未覆盖全部种子的范围。") 这替代了此前“已提交种子可整体解析”的过强结论：该用例没有枚举全部种子，也未通过 `all:true` 排除其他种子被拒绝、失败或缺失。
