# 人工代码理解 seed 的投影与陈旧化集成测试

验证人工维护的代码理解 seed 经 locator 解析后成为当前投影，坏引用被隔离，快照变化产生替代行，并在无模型时保持只读图可用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="projection"></a>
## seed 投影与幂等

夹具把人工 seed 与代码一同提交；seed 以 path、qualified name 和 kind 描述节点，并带模块职责、流程、claim 与 evidence selector。同步后它被投影为低置信度的 `curated-seed`：状态为 seed、无模型且未由 agent 验证；同一快照再次同步仍只保留一个当前理解，详情中可读取解析后的节点引用。[人工 seed 的当前投影 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L55 "支持 locator 形式的 seed 经同步成为当前低置信度投影并保持幂等。")

<a id="rejection_staleness"></a>
## 拒绝坏引用与替代旧结论

当 seed 指向不存在的符号时，它会保存为 rejected 历史行，却不会污染默认当前列表，原有好 seed 仍可见。[幽灵符号引用隔离 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L147 "证明无法解析的符号 seed 被记录为 rejected，且不会进入当前理解列表。") 代码内容变化形成新快照和 input digest 后，旧理解被标为 stale，新行通过 `supersedes_id` 指向旧行；这明确表达结论被替代，而不是覆盖或删除先前结果。[快照变化与结论替代 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L178 "支持旧理解标为 stale、新理解显式 supersede 旧行而不删除历史。")

<a id="api_real_repo"></a>
## 无模型读取与真实仓库覆盖

未配置模型时，状态接口明确返回不可用，但理解列表、详情和原始代码图仍可读取；详情保留 seed 与未验证标记。[无模型只读接口 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L215 "支持模型不可用时 seed 详情和原始代码图仍然可读。") 隔离用例在首次同步和投影完成后记录 sources、fragments 数量，只证明相同输入再次同步不会改变这两项计数，不能证明首次投影从未改动它们；这替代了先前更强的结论。真实仓库检查则要求五个核心模块存在当前人工 seed，且均保持 seed、无模型、未验证状态。[重复投影计数与真实 seed 覆盖 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L251 "支持同一输入再次同步时 sources、fragments 计数不变，并验证真实仓库五个核心模块的当前 seed 状态。")
