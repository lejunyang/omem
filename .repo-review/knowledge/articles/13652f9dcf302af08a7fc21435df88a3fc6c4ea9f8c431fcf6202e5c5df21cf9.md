# 人工代码理解投影集成测试

验证 curated seed 经代码图定位、复合无效输入拒绝、快照失效和只读 HTTP 展示的生命周期，并明确人工 seed 不是模型生成或 Agent 复核成果。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="seed-projection"></a>
## Seed 定位、投影与拒绝

测试夹具定义模块级 understanding seed：流程和 claim 通过 `path + qualified + kind` 定位 `Alpha` 类与方法，并以源码行 selector 提供证据。成功投影后只有一条 current 记录，状态为 seed、来源为 curated-seed、低置信度，且未经过 Agent 验证、没有模型标识；相同快照重复同步仍保持单条记录，详情包含解析后的 node 引用。[有效人工理解 seed 投影 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L55 "支持 locator 与证据结构、成功投影字段、幂等性及已解析 node 引用的断言。")

拒绝用例同时把 claim locator 改为不存在的符号，并清空必需的流程节点。结果是该复合无效 seed 不进入默认 current 列表，但会以 rejected 状态保留在全量视图中，证明坏 seed 不会污染当前好结果。由于两个错误同时出现且未断言拒绝原因，该用例不能单独证明究竟是哪一个校验触发拒绝。[复合无效 seed 拒绝用例 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L147 "证明同时含幽灵符号和空流程节点的 seed 被保留为 rejected 且不污染 current；也界定该测试无法隔离具体失败原因。")

<a id="staleness-http"></a>
## 快照更新与无模型读取

文件内容变化并形成新快照后，测试要求生成新的 understanding ID；旧记录继续保留但标记 stale，新记录通过 `supersedes_id` 指向旧记录。这表明理解结果绑定输入 snapshot 与 digest，而不是假设符号身份跨 revision 自动续接。[理解结果失效与继任 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L178 "支持代码快照变化后旧理解变 stale、新理解通过 supersedes_id 继任的生命周期。")

未配置模型时，HTTP model-status 返回 unavailable，但 understanding 列表、详情和原始 graph 仍可读取；详情继续标明结果来自 seed 且未由 Agent 验证。重复投影也不会改变既有 sources 与 fragments。[无模型 HTTP 与投影隔离 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L215 "支持模型不可用时 seed 和原始图仍可读，并证明重复投影不改动基础 source 与 fragment 行。")

<a id="coverage-limits"></a>
## 覆盖范围与待补验证

真实仓库用例只确认五个目标模块存在 current curated-seed 记录，并检查 seed、未验证和无模型等 provenance 字段。[真实仓库 seed 覆盖 ↗](../../../apps/server/tests/code-understanding-integration.test.ts#L272 "说明真实仓库用例只检查目标模块集合及 seed provenance 字段，界定其验证粒度。") 因而整组测试覆盖人工 seed 的投影、复合无效输入隔离、版本失效及只读接口，但不证明真实 ACP、CLI 或 HTTP 生成可运行，也未验证预算 trace、能力发现、超时、输出语义复核，或各种 schema 错误各自对应的拒绝原因。
