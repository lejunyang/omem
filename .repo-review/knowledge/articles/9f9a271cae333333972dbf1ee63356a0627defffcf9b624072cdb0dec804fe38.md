# quality · 模块理解

quality 模块构成与生产捕获隔离的研究评测链：从文档生成候选样本，经 SQLite 仓储和 Lark owner 人工确认形成可冻结基准，再以确定性规则分别评估处置、引用定位、语义支持、事实槽、证据覆盖与打扰情况。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责与隔离边界

quality 模块服务于知识抽取的研究评测，不是生产知识入口。导入器把研究文档切成默认 `explicit/claim`、`autoApply=true` 的待审草稿；这些结果必须经过人工判断，不能直接视为可靠知识。[研究评测导入用途 ↗](../../../apps/server/src/quality/import.ts#L1 "支持该导入器只服务人工研究标注、草稿默认自动应用且不得进入普通捕获流程的论断。") 被替代的结论是“整个模块均由运行时哨兵强制隔离”：公开切分函数没有哨兵参数，可被直接调用；真正的 `EVAL_ONLY_RESEARCH` 校验只位于落库入口。[公开文档切分函数 ↗](../../../apps/server/src/quality/import.ts#L39 "支持公开切分函数签名不包含评测哨兵参数，从而界定其运行时保护范围。") [评测落库入口保护 ↗](../../../apps/server/src/quality/import.ts#L156 "支持固定评测哨兵由数据集导入入口校验，值不匹配时显式拒绝。") 因而生产隔离同时依赖入口保护和调用关系约束。

<a id="dataset-flow"></a>
## 从候选到冻结基准

仓储以严格 schema 固定样本来源、类别、处置、对象和自动应用语义；提取标签必须包含对象，非提取标签不得自动应用。[质量样本与标签合同 ↗](../../../apps/server/src/quality/repository.ts#L8 "支持样本来源、类别、对象类型及提取和自动应用之间的交叉约束。") 数据集按名称、分组与来源摘要复用；批量加样本仅允许草稿或标注中状态，逐条校验并计算摘要，以事务提交或整体回滚。[数据集复用与事务写入 ↗](../../../apps/server/src/quality/repository.ts#L118 "支持数据集按名称、分组和来源摘要查重，以及样本批量写入的状态门禁、去重和事务回滚。") 人工标注还以 pending 状态和标签摘要实施乐观并发控制；修订会清除旧审核结果并重新排队。只有样本达到目标数量且全部确认后才能冻结，清单摘要可重算以检测篡改。[人工标注与冻结完整性 ↗](../../../apps/server/src/quality/repository.ts#L278 "支持摘要乐观锁、修订重新排队、全量确认门槛和冻结清单重算校验。")

<a id="human-review"></a>
## Lark 人工复核闭环

Lark 服务把原文、建议对象、进度和四种人工动作组成卡片；按钮携带会话、样本、标签摘要、nonce 与有效期，没有下一条样本时展示汇总。[质量标注卡片 ↗](../../../apps/server/src/quality/lark-annotations.ts#L42 "支持卡片展示原文、建议对象、进度、四种动作及完成状态汇总。") 启动会话要求活跃的个人 owner 点对点目标；默认避免重复会话，显式重发会轮换凭据并新增投递意图，取消则只撤销尚未发送或等待重试的意图。[会话启动、重发与取消 ↗](../../../apps/server/src/quality/lark-annotations.ts#L151 "支持活跃会话幂等、重发凭据轮换、owner 目标选择、投递意图创建及取消边界。") 回调持久化并去重后，联合核验 owner、聊天、消息、应用、时效、摘要和 nonce，再在事务中记录标注并推进样本。[回调验证与状态推进 ↗](../../../apps/server/src/quality/lark-annotations.ts#L355 "支持事件去重、身份和消息等联合校验，以及事务内记录标注并推进下一样本。") 当前材料仍未展示实际发送成功后如何回写 Lark 消息标识。

<a id="evaluation"></a>
## 评估方式与能力限制

评估器只纳入 confirmed 且有标签的样本，将处置、自动应用和对象集合与预测比较，并分别汇总引用定位、语义支持、事实槽一致性、必要证据覆盖、任务完成、不必要打扰与延迟；空预测对象不会获得虚假的支持分。[确认样本评估与指标汇总 ↗](../../../apps/server/src/quality/evaluator.ts#L234 "支持只评估已确认样本，并将引用定位、语义、事实槽、覆盖、完成、打扰和延迟拆分衡量。") 语义支持采用可重复的确定性规则，识别否定翻转、反义、历史状态冒充当前、限制条件遗漏及低文本重叠，数字与数量界限另行核对。[确定性语义与事实槽规则 ↗](../../../apps/server/src/quality/evaluator.ts#L33 "支持语义判定的规则类型、四种结果、数字界限检查及非 LLM 的能力边界。") 这是一条易审计的基线，并非复杂中文推理或真实模型效果的证明。
