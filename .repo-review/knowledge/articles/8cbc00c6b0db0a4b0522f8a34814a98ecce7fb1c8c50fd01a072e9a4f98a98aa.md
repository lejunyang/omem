# 输入缓冲、持久化与聚合的行为测试

该测试文件验证外部输入在服务不可达、重复投递、容量受限以及高频聊天或屏幕事件场景下，仍能受控进入 Capture→Revision→Job 流程。覆盖磁盘 spool 恢复与基础权限、事件幂等和冲突检测、字段裁剪与脱敏，以及聚合窗口、噪声去重和迟到事件追踪；结论仅限于实际断言，不代表所有平台权限、并发故障或外部协议均已验收。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="offline-spool"></a>
## 离线缓冲与回执驱动的清理

测试把 hook 事件交给真实转发入口，并将服务地址指向不可连接的本机端口；预期进程仍正常退出、标准输出为空，并提示事件已排队重试。再次入列同一 Capture 会被判定为重复，发送函数抛出离线错误后记录仍保留，证明暂时不可达不会直接丢弃输入。[离线转发与首次重试断言 ↗](../../../apps/server/tests/inputs.test.ts#L48 "支持服务不可达时转发仍成功退出、事件进入重试队列、重复入列被识别以及发送失败后记录继续保留。")

重新创建 `HookSpool` 模拟进程重启，重复判断依然成立。空 receipt 会产生 `CAPTURE_RECEIPT_MISMATCH` 且保留待处理项；改由 `Store.capture` 返回有效回执后才清理记录。再次投递同一事件，数据库仍只有一条回执、一份捕获结果和一个作业，覆盖跨重启恢复及成功路径的端到端幂等。[重启后的空回执与有效回执行为 ↗](../../../apps/server/tests/inputs.test.ts#L87 "支持跨实例恢复、空回执不清理、Store 返回有效回执后清理，以及相同事件重复投递只产生单份持久化结果和作业。") 生产者、事件或负载摘要分别失配的非空回执未在本文件中逐项构造，不能视为已直接验证。

<a id="limits-security"></a>
## 采集边界、秘密保护与冲突处理

第二组用例按只保留 `prompt` 的 profile 构造输入：令牌样式内容被替换为 `[REDACTED]`，工具响应、思维字段和额外 secret 均未进入序列化结果。相同事件身份若对应不同负载，spool 会报事件冲突；达到条目上限后抛出容量异常，并写入不含敏感正文的容量警告。[字段裁剪、脱敏、冲突与容量限制 ↗](../../../apps/server/tests/inputs.test.ts#L127 "支持 profile 白名单、令牌脱敏、spool 负载冲突、条目容量异常及警告不泄露敏感正文。")

权限检查落在实际对象上：测试检查 spool 目录为 POSIX `0700`、待处理 JSON 文件为 `0600`。辅助断言同时说明，Windows 分支只确认对象存在且当前用户可访问，并未直接读取或验证 ACL 的仅所有者语义。[跨平台权限断言的边界 ↗](../../../apps/server/tests/inputs.test.ts#L32 "说明 POSIX 模式位检查及 Windows 分支只能确认对象存在和可访问，支持对平台权限结论的限定。")[目录与待处理文件的权限检查 ↗](../../../apps/server/tests/inputs.test.ts#L124 "支持测试对 spool 目录调用 0700 断言，并对写入后的 JSON 文件调用 0600 断言。") 持久化层也拒绝不同负载复用同一事件身份，冲突后捕获和作业数量仍各为一。[存储层事件冲突与数量保持 ↗](../../../apps/server/tests/inputs.test.ts#L180 "支持 Store 拒绝不同负载复用事件身份，且冲突后捕获记录和作业数量仍各为一。")

<a id="aggregation"></a>
## 有界聚合、去噪与迟到事件

聚合测试构造带来源、参与者、事件时间和会话上下文的 chat/screen 输入。四条聊天事件在五分钟边界前不刷新，到达边界时合成一批；全部事件标识被保留，而重复文本被折叠，因此四个事件形成三个正文 part。窗口起止时间也写入聚合上下文，使内容去重不会抹掉事件级追踪信息。[聊天窗口强制刷新与噪声折叠 ↗](../../../apps/server/tests/inputs.test.ts#L193 "支持五分钟边界、边界前不刷新、事件身份完整保留、重复文本折叠以及聚合窗口上下文记录。")

观察时间属于旧窗口但实际晚到的消息会形成新 revision，并以 `lateForBatchId` 关联原批次，而非改写既有 revision。两条内容相同的屏幕事件在 `maxEvents: 2` 时立即成批，保留两个事件标识但只生成一个 part；最终没有待处理输入，三个批次对应三个作业。[迟到补充与屏幕事件聚合 ↗](../../../apps/server/tests/inputs.test.ts#L281 "支持迟到事件生成独立 revision 并关联原批次，以及屏幕重复内容按事件数成批但正文去重。")

<a id="module-relations"></a>
## 模块关系与测试未覆盖范围

该测试直接导入合同校验、hook 转换、磁盘缓冲和 `Store`，并据此串联输入转换、重试与落库场景；导入关系本身不证明这些模块的全部职责。[输入测试的直接模块依赖 ↗](../../../apps/server/tests/inputs.test.ts#L12 "证明测试直接导入合同校验、hook 转换、spool 和 Store；附近文字据此仅陈述依赖与串联关系。") 合同材料在已提供范围内明确展示了严格的 part provenance、文本、图片、链接和 capture provenance schema；其中 `captureSchema` 仅出现声明起点，因此这里不据此断言其完整字段或整体严格性。[部件与来源字段约束 ↗](../../../packages/contracts/src/index.ts#L4 "支持合同层对 part provenance、文本、图片、链接及 capture provenance 的字段和严格性约束，同时限定所给范围只展示了 captureSchema 的声明起点。") 连接器材料则证明文件适配器经路径、大小、UTF-8 与二进制检查后返回 `CaptureInput`。[连接器产生文件采集输入 ↗](../../../apps/server/src/connectors.ts#L19 "支持文件连接器经过路径、大小、文本编码和二进制检查后返回 CaptureInput。") `Store` 在同一 SQLite 初始化中装配作业仓库和输入聚合器，为测试中的 `store.jobs` 与 `store.inputs` 调用提供实现依据。[Store 对聚合器和作业仓库的装配 ↗](../../../apps/server/src/store.ts#L38 "支持 Store 在同一 SQLite 初始化中创建 JobRepository 与 InputAggregator，并将其暴露给测试调用。")

这些用例没有展示 spool 损坏隔离、跨进程并发刷新、保留期限淘汰、字节上限临界值或崩溃中断恢复，也未验证远程服务成功响应时的协议兼容性。聚合部分仅覆盖给定的单会话 chat/screen 样例与成功回调，不能外推到多分区交错、任意乱序或部分提交失败。
