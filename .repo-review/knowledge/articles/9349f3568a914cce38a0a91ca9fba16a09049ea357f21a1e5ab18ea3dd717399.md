# Agent 角色配置、连接探测与安全保存

AgentSettings 是服务端的 Agent 配置门面：它汇总可选 ACP 客户端，报告安装与当前角色绑定状态，在隔离临时目录中探测连接，并把五类角色的模型与推理强度选择安全写入配置文件。保存前会复用连接探测、校验完整配置并检查并发修改；成功后同步更新内存配置，使新任务立即读取新角色。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_entry"></a>
## 统一管理五类 Agent 角色

`AgentSettings` 解决服务端“选哪个本地 ACP 客户端、给每类工作用什么模型”的配置问题。应用装配时创建一个实例，并将状态查询、候选探测和设置保存分别暴露为 GET、POST、PUT 接口；请求体先经过对应的 Zod schema，再进入类方法。参考 [设置接口入口 ↗](../../../apps/server/src/app.ts#L105 "支持应用层创建 AgentSettings，并将状态、探测、保存方法绑定到三个 HTTP 接口的说明。")

设置覆盖主助手、知识整理、记忆整理、编码和评审五类角色。每个角色必须给出候选 ID，模型与推理强度可选；对象采用严格校验，多余字段不会被静默接受。角色种类或输入格式要调整时，应从 `agentRoles` 与两个 schema 入手。参考 [角色与输入约束 ↗](../../../apps/server/src/agent-settings.ts#L20 "支持五类角色、必填候选 ID、可选模型和推理强度，以及严格对象校验的说明。")

<a id="save_flow"></a>
## 一次保存如何落盘并立即生效

以 PUT 设置请求为例，输入包含五个角色的选择。`save` 先用实例级标志拒绝重入，读取原配置，再逐角色查找候选；相同选择只探测一次。它为每个角色生成稳定的 `omem-<role>` profile，并写入对应的角色引用。保存阶段调用的是 `test: false` 探测，因此确认 ACP 可连接并能读取配置选项，不执行提示词推理。参考 [角色配置构造 ↗](../../../apps/server/src/agent-settings.ts#L254 "支持保存锁、原配置读取、候选解析、重复探测合并和角色 profile 构造的流程。")

```mermaid
flowchart LR
  A[五类角色选择] --> B[校验候选与 ACP 连接]
  B --> C[生成角色 profiles]
  C --> D[解析并校验完整配置]
  D --> E[临时文件写入并重命名]
  E --> F[更新内存配置并返回状态]
```
参考 [角色引用更新 ↗](../../../apps/server/src/agent-settings.ts#L286 "支持新 profiles 替换同 ID 旧项，并更新五类角色配置引用的说明。") [并发检查与原子替换 ↗](../../../apps/server/src/agent-settings.ts#L306 "支持完整配置解析、外部修改检测、受限权限临时文件、重命名落盘及内存配置更新的说明。")

落盘前会再次读取目标文件；内容已变化就终止，避免覆盖外部更新。新内容先以独占方式写入权限为 `0600` 的随机临时文件，再重命名到正式路径，最后才把解析后的配置合并进运行中的对象。失败路径会清理临时文件并释放保存锁。参考 [并发检查与原子替换 ↗](../../../apps/server/src/agent-settings.ts#L306 "支持完整配置解析、外部修改检测、受限权限临时文件、重命名落盘及内存配置更新的说明。")

<a id="discovery_probe_limits"></a>
## 候选发现、探测结果与边界

候选来源包括已有的自定义 ACP profile，以及未被同命令覆盖的 Traex、Codex ACP 和 Claude Code ACP 默认项；默认项只登记启动方式，不负责安装或登录。状态接口通过服务进程的 `PATH` 判断命令是否可执行，并把当前 profile 反查为候选 ID。`configured` 只表示存在配置时间戳，`installed` 也只是当前可执行文件检查，不代表模型推理已经成功。参考 [候选发现规则 ↗](../../../apps/server/src/agent-settings.ts#L97 "支持自定义 ACP profile、三个默认适配器、同命令去重以及默认项不负责安装登录的说明。") [公开状态结构 ↗](../../../apps/server/src/agent-settings.ts#L141 "支持配置时间、候选安装状态、角色绑定和学习开关等状态字段的解释。")

探测会拒绝未知候选或找不到可执行文件的候选。每次新探测使用权限为 `0700` 的临时工作区，相同参数的并发请求共享同一个 Promise，结束后删除工作区和缓存项。`test: true` 时才发送只回复 `OK` 的连接检查，并在 ACP 调用成功后返回 `inference: passed`；代码没有比对回复正文。模型与推理强度选项只接受 ACP 返回的 select 类型，并展开分组选项。参考 [候选可执行性校验 ↗](../../../apps/server/src/agent-settings.ts#L190 "支持未知候选和命令不可执行时立即报错，以及探测超时参数构造的说明。") [隔离探测流程 ↗](../../../apps/server/src/agent-settings.ts#L208 "支持临时工作区、并发探测复用、测试提示、返回状态和清理行为的说明。")

Traex 探测还会把临时目录设为工作区，并关闭项目文档发现；这控制提示上下文的发现范围，不等同于操作系统文件沙箱。参考 [Traex 工作区约束 ↗](../../../apps/server/src/agents.ts#L46 "解释 withAgentWorkspace 对 Traex 增加工作区和关闭项目文档发现参数的具体作用与边界。")
