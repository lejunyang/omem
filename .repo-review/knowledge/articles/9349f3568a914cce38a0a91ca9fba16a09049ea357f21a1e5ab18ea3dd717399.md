# Agent 角色配置、连接探测与安全保存

AgentSettings 是服务端的 Agent 配置门面：它汇总可选 ACP 客户端，报告安装情况与当前角色绑定，在临时工作区中探测连接，并把五类角色的模型和推理强度选择写入配置文件。保存前会复用相同选择的连接探测，校验完整配置并检查并发修改；成功后同步更新内存配置。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_entry"></a>
## 统一管理五类 Agent 角色

`AgentSettings` 集中处理候选 ACP 客户端发现、当前设置查询、连接探测和配置保存。角色或输入格式需要调整时，可以先查看 `agentRoles`、`agentProbeSchema` 与 `agentSetupSchema`。参考 [角色与输入约束 ↗](../../../apps/server/src/agent-settings.ts#L20 "支持五类角色、必填候选 ID、可选模型和推理强度、探测开关默认值，以及严格对象校验的说明。")

设置覆盖主助手、知识整理、记忆整理、编码和评审五类角色。保存请求必须为每个角色提供候选 ID，模型与推理强度可选；探测请求沿用同一选择结构，并增加默认值为 `false` 的 `test`。两层设置对象都采用严格校验，多余字段不会被静默接受。参考 [角色与输入约束 ↗](../../../apps/server/src/agent-settings.ts#L20 "支持五类角色、必填候选 ID、可选模型和推理强度、探测开关默认值，以及严格对象校验的说明。")

<a id="save_flow"></a>
## 一次保存如何落盘并立即生效

以一次设置保存为例，`save` 先用实例级标志拒绝重入，读取原配置，再逐角色查找候选。相同选择只探测一次。每个角色会得到稳定的 `omem-<role>` profile，并保留所选模型与推理强度。保存阶段使用 `test: false`，因此会连接 ACP 并读取配置选项，但不会发送测试提示。参考 [临时工作区探测 ↗](../../../apps/server/src/agent-settings.ts#L79 "支持并发探测复用、临时工作区、测试提示、返回状态、配置选项提取和清理行为的说明。") [角色 profile 构造 ↗](../../../apps/server/src/agent-settings.ts#L254 "支持保存锁、原配置读取、重复探测合并和五类角色 profile 构造的流程。")

```mermaid
flowchart LR
  A[五类角色选择] --> B[校验候选与 ACP 连接]
  B --> C[生成角色 profiles]
  C --> D[解析并校验完整配置]
  D --> E[临时文件写入并重命名]
  E --> F[更新内存配置并返回状态]
```
参考 [角色引用更新 ↗](../../../apps/server/src/agent-settings.ts#L286 "支持新 profiles 替换同 ID 旧项，并更新五类角色配置引用的说明。") [并发检查与原子替换 ↗](../../../apps/server/src/agent-settings.ts#L306 "支持完整配置解析、外部修改检测、受限权限临时文件、重命名落盘、内存配置更新及清理行为的说明。")

新 profiles 会替换同 ID 的旧项，并更新五类角色对应的配置引用。落盘前，完整配置先经过 `parseConfig`；目标文件内容已经变化时，保存会终止，避免覆盖外部更新。新内容写入权限为 `0600` 的随机临时文件，再重命名到正式路径，成功后才合并进运行中的配置对象。失败路径会清理临时文件并释放保存锁。参考 [角色引用更新 ↗](../../../apps/server/src/agent-settings.ts#L286 "支持新 profiles 替换同 ID 旧项，并更新五类角色配置引用的说明。") [并发检查与原子替换 ↗](../../../apps/server/src/agent-settings.ts#L306 "支持完整配置解析、外部修改检测、受限权限临时文件、重命名落盘、内存配置更新及清理行为的说明。")

<a id="discovery_probe_limits"></a>
## 候选发现、探测结果与边界

候选来源包括已有的自定义 ACP profile，以及未被同命令覆盖的 Traex、Codex ACP 和 Claude Code ACP 默认项。默认 Traex 候选以只读沙箱参数启动；这些默认项只登记启动方式，不负责安装或登录。参考 [候选发现规则 ↗](../../../apps/server/src/agent-settings.ts#L97 "支持自定义 ACP profile、三个默认适配器、同命令去重、Traex 默认启动参数，以及发现不负责安装登录的说明。")

状态查询通过服务进程的 `PATH` 判断命令是否可执行，并把当前 profile 反查为候选 ID。`configured` 只表示存在配置时间戳，`installed` 也只是当前可执行文件检查，不能证明模型推理已经成功。状态还会给出原生 Codex 与 Claude CLI 的可用性、五类角色绑定，以及学习功能是否启用。参考 [公开状态结构 ↗](../../../apps/server/src/agent-settings.ts#L141 "支持配置时间、候选安装状态、原生 CLI 可用性、角色绑定和学习开关等状态字段的解释。")

探测会拒绝未知候选或找不到可执行文件的候选，并根据是否执行推理测试设置不同超时。每次新探测使用权限为 `0700` 的临时工作区，相同参数的并发请求共享同一个 Promise，结束后删除工作区和缓存项。`test: true` 时才发送只回复 `OK` 的连接检查；ACP 调用成功后返回 `inference: passed`，代码没有比对回复正文。模型与推理强度选项只接受 ACP 返回的 select 类型，分组选项会被展开。参考 [候选可执行性与超时 ↗](../../../apps/server/src/agent-settings.ts#L190 "支持未知候选和命令不可执行时立即报错，以及测试与非测试探测采用不同超时的说明。") [临时工作区探测 ↗](../../../apps/server/src/agent-settings.ts#L79 "支持并发探测复用、临时工作区、测试提示、返回状态、配置选项提取和清理行为的说明。")
