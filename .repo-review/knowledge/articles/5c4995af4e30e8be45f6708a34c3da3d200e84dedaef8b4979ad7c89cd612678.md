# 来源画像与统一关键词检索验收测试

该测试验证文档捕获后生成轻量来源画像并保留原始 fragment 可检索；画像区分标题、时态、计划、回指与代码示例，并在部分解析时记录覆盖缺口。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="capture-profile-recall"></a>
## 捕获、画像与检索衔接

业务 Markdown 经 `Store.capture` 后会产生 derived 来源画像，记录 carrier 类型、标题路径和话语片段；原始 fragments 随即可由 `KeywordRetrieval` 搜索。导入不会逐句创建确认卡或质量数据集，只产生一次通知，体现先保留可检索原文、再派生理解的低打扰路径。[导入后画像与即时检索 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L64 "支持 Markdown 画像、原文关键词召回、零逐句确认及单次通知的流程。")

用例还直接 seed 一条 active memory，再以复用其词项的查询调用 `searchMemories`，能够召回该记忆并排除无关查询。它没有实际捕获一份“新材料”并由材料自动触发召回，因此该表述替代旧稿中的自动衔接结论。[已应用记忆的关键词查询 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L189 "支持直接 seed 的 active memory 可由复用词项的查询召回，并显示该用例未捕获新的材料。") `readEvidence` 则按 revision 与可选 fragment 返回固定文本，未知标识返回 null。[固定证据读取 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L232 "支持按 revision 和 fragment 读取固定文本，以及未知 revision 或 fragment 返回 null。")

<a id="discourse-boundaries"></a>
## 话语分类与安全边界

画像区分当前事实和未来计划，并为“上述三种”保留父标题回指，避免把整篇文档压成单一事实桶。[时态、计划与父级回指 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L117 "支持画像对 present、future plan 和 anaphora parent context 的区分。") SQL、TODO 和代码对象被标记为 code/example，而非 owner instruction，也不会生成任务，防止资料中的命令式文本被当成用户授权。[代码资料不成为指令 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L161 "支持 SQL、TODO 和代码被分类为 example 且不创建 owner task。")

表格类内容会让画像状态变为 partial 并记录 coverage gap；测试同时确认该 revision 仍至少有 fragment 可读取。[部分画像不遮蔽来源 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L250 "支持表格覆盖缺口、partial 状态及原始来源仍有 fragment 可读取，同时界定未验证逐段完整性。") 这替代了旧稿“原始 fragments 仍完整存在”的过强结论，因为用例没有逐段核对表格及普通段落的完整文本，也没有模拟画像服务抛异常或数据库写入中断。
