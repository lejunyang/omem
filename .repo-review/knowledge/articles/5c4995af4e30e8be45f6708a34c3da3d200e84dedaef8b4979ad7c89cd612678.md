# 统一检索与轻量来源画像的行为测试

该测试以临时 SQLite Store 为真实边界，验证原始材料捕获后自动生成来源画像、进入关键词检索，并覆盖语篇时态、代码示例隔离、已应用记忆召回、固定证据读取、可见性与时间过滤、派生答案排除等关键行为。它证明的是当前规则画像与 SQLite 关键词检索的集成语义，不代表外部检索后端、模型画像或所有排序策略均已验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="fixture_and_primary_flow"></a>
## 测试夹具与主流程

测试为每个用例创建独立临时目录和 `Store`，结束后关闭数据库并递归清理；捕获辅助函数先用共享 `captureSchema` 校验输入，再携带固定来源信息写入文本材料。由此测试贯穿合同校验、持久化、画像与检索，而非只验证孤立函数。[临时 Store 与捕获夹具 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L1 "支持测试使用隔离数据库、清理资源，并通过共享捕获合同写入带来源信息的文本。")

G01 断言业务 Markdown 捕获后立即产生派生画像，识别标题层级和语篇片段；原始 fragment 同时可按“仓储系统”检索。流程不会按句创建决策或质量数据集，只产生一次通知，并报告 SQLite FTS5/RRF 后端可用。[业务文档画像与即时检索断言 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L64 "支持 G01 对 Markdown 画像、原始片段检索、零逐句确认、单次通知及健康状态的断言。") Store 构造时初始化迁移、应用仓库、任务、输入聚合、运行请求和来源画像服务，说明该集成路径依赖统一存储装配。[Store 服务装配 ↗](../../../apps/server/src/store.ts#L38 "说明测试中的 Store 会初始化 SQLite、迁移及来源画像等相关仓库和服务。")

<a id="profile_semantics"></a>
## 来源画像的语义边界

G02 用“当前”“未来可能”和“上述三种”验证规则画像不会把全文压平成同一种事实：当前陈述标为 present，规划标为 plan/future，回指段落保留最近标题“重试策略”，并在 temporalNotes 中留下时态线索。[时态、规划与父标题断言 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L117 "支持画像区分当前状态、未来规划和回指父上下文的行为。") 这与 `SourceProfile` 明确定义的语篇类别、时态、父标题、覆盖缺口和状态字段相对应。[来源画像数据结构 ↗](../../../apps/server/src/source-profile/service.ts#L6 "解释测试所断言的语篇类别、时态、父标题、覆盖缺口与状态字段来自何种服务合同。")

G03 进一步要求 SQL、TODO 和代码字面量带 `code` 标签且归为 example，不能解释成 owner instruction，也不能生成待办；普通客服要求在该夹具中同样未触发任务。[代码示例不得成为指令或任务 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L161 "支持 SQL、TODO、代码字面量均归为 example，且不生成 owner task 的断言。") 表格样式材料则被记录为 coverage gap，使画像状态成为 partial，但原始 fragments 仍可读取；这里验证的是降级保留证据，并未实际构造画像服务抛错或 `failed` 状态。[部分画像仍保留原始证据 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L250 "支持表格覆盖缺口导致 partial 状态，但原始 fragments 不被隐藏的降级行为。")

<a id="memory_and_evidence"></a>
## 记忆召回与固定证据读取

G12 先通过应用仓库写入 active claim，再以复用词语检索，要求返回 claim、active 状态及相关摘要，同时排除无关查询。它覆盖“已应用记忆可被词法召回”，但没有断言多条候选的具体排序或分数。[已应用记忆的关键词召回 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L189 "支持 active claim 能以复用词语召回、无关查询不命中的行为。")

`readEvidence` 用 revision 与可选 fragment 定位固定文本：给定 fragment 返回对应段落，不给 fragment 时返回该 revision 的首段，未知 revision 或 fragment 返回 null。[固定片段读取断言 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L232 "支持指定片段、默认首片段及未知标识返回 null 的测试结论。") 实现侧确实直接查询 fragments，并按 ordinal 选择首段，说明测试覆盖的是原始固定证据读取接口，而不是派生答案读取。[证据读取实现 ↗](../../../apps/server/src/retrieval/keyword.ts#L21 "说明 readEvidence 如何按 revision、fragment 和 ordinal 查询原始 fragments。")

<a id="fusion_filters_limits"></a>
## 融合路由、过滤与未覆盖范围

后续用例验证 active memory 可作为别名路由召回其证据集所指向的原始 fragment：查询 “Aurora” 返回含 E42 的原文，并标记 memory 路由；可见性和时间范围过滤都在结果限额前生效。当同一外部来源捕获新 revision 后，旧证据不再从当前 source head 返回。[记忆路由融合与过滤 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L268 "支持别名记忆指向原始证据、可见性和时间过滤，以及新 head 使旧证据退出结果的断言。")

最后一组断言覆盖标题检索、两个汉字的中文查询、派生 capture 排除，以及大量不可见同名结果不会挤占 `limit: 1`。[标题、短中文与派生排除测试 ↗](../../../apps/server/tests/retrieval-source-profile.test.ts#L289 "支持标题和短中文可检索、派生答案被排除、过滤先于 limit 生效；同时暴露未显式执行 restore 的范围。") 检索实现也明确先限制 limit、分词，并以时间和 fragment 可见性判定候选资格，同时声明只返回 original evidence。[原始证据检索入口与资格过滤 ↗](../../../apps/server/src/retrieval/keyword.ts#L16 "解释关键词检索的 limit 约束、分词、时间范围、可见性过滤及只返回原始证据的设计。") 不过测试名中的 “restore” 未在所给用例正文中出现显式关闭并重开 Store 的步骤，因此不能据此认定数据库恢复路径已被行为验证。
