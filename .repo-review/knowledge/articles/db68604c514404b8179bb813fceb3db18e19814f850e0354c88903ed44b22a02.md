# 会话身份与回合持久化路由

该模块以 SQLite 持久化会话和回合，按工作区、主体、渠道、聊天及线程识别会话，并提供确定性回合 ID、状态写入与重启恢复能力。旧稿关于“必定以 pending 入队”和“重复事件必然不会再次执行或回复”的结论已被限定：调用方 refs 可覆盖初始元数据，而 duplicate 仅为上层提供跳过处理的信号。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="identity"></a>
## 会话身份与隔离边界

`ConversationRouter` 保存工作区、主体、渠道、聊天、线程及 `private/group` 可见性，并记录当前目标和待处理事项。[会话与回合数据合同 ↗](../../../apps/server/src/conversation/router.ts#L7 "支持会话身份、可见性、目标字段及回合持久化结构的说明。") `open` 使用这些身份字段查询会话，缺省工作区为 `personal`、缺省线程为空串；未命中时创建记录，因此不会仅凭聊天标识推断项目身份。[会话打开与创建逻辑 ↗](../../../apps/server/src/conversation/router.ts#L81 "支持复合身份查询、默认工作区和线程处理以及未命中时创建记录的流程。")

这里持久化了可见性边界，但没有执行证据权限过滤；实际检索仍需上层遵守该字段。`setGoal` 也只是更新目标与时间戳，未在本方法内验证记录存在性或调用者权限。[会话目标更新 ↗](../../../apps/server/src/conversation/router.ts#L124 "支持目标更新只是直接数据库写入，方法内没有权限或存在性检查的边界判断。")

<a id="turn-lifecycle"></a>
## 回合入队、去重与状态流转

传入外部事件标识时，模块用稳定摘要派生确定性回合 ID；若该 ID 已存在，只返回既有回合及 `duplicate: true`，供调用方跳过再次执行或回复。[确定性回合标识与重复返回 ↗](../../../apps/server/src/conversation/router.ts#L146 "支持外部事件生成确定性回合 ID，以及命中既有回合时仅返回 duplicate 标志的准确限定。") 摘要实现会规范化对象键后计算 SHA-256，使相同输入得到稳定结果。[稳定摘要实现 ↗](../../../apps/server/src/storage/digest.ts#L3 "说明规范化 JSON 和 SHA-256 如何为确定性回合 ID 提供稳定摘要。") 旧稿所称“重复投递必然避免二次执行和回复”已被替代：本类自身只报告重复，端到端幂等取决于调用方是否处理该标志。

新回合按当前最大序号加一并写入空证据、空工具动作和空结果。虽然构造 refs 时先放入 `pending` 与外部事件标识，但随后展开的 `input.refs` 可以覆盖这两个键，因此只有调用方未传入同名字段时，初始状态和事件标识才保持默认值。[回合序号与初始元数据写入 ↗](../../../apps/server/src/conversation/router.ts#L137 "支持最大序号加一、初始持久化流程，并证明 input.refs 位于默认状态和事件标识之后、可覆盖同名键。") 后续方法通过合并 JSON 元数据写入 `running`、`done`、`failed`、`pending` 或 `cancelled`，完成时另写结果、证据、工具动作及可选发件箱；这些更新没有校验前置状态。[回合状态与结果更新 ↗](../../../apps/server/src/conversation/router.ts#L220 "支持状态通过 JSON 合并更新、完成结果写入及各更新方法未检查前置状态的说明。")

<a id="recovery-boundaries"></a>
## 恢复机制与实现限制

模块可按序读取会话回合，并跨会话查找状态文本为 `pending` 或 `running` 的记录，作为重启恢复候选。[未完成回合恢复查询 ↗](../../../apps/server/src/conversation/router.ts#L286 "支持按序读取回合以及通过 JSON 文本 LIKE 匹配恢复 pending、running 记录的说明。") 查询使用 SQL `LIKE` 匹配序列化 JSON，依赖紧凑且固定的文本格式；读取时又直接解析多个 JSON 列，损坏内容会抛错，当前没有降级路径。[数据库行反序列化 ↗](../../../apps/server/src/conversation/router.ts#L320 "支持多个 JSON 列被直接解析且没有损坏数据兜底的限制分析。")

序号采用“查询最大值再加一”，会话创建也采用“先查后插”，本文件未展示唯一约束或外层事务，并发安全仍需结合迁移与调用方确认。状态更新、完成及发件箱绑定同样未限制合法迁移，因此取消后是否还能完成、重复回合是否会继续运行，都不能仅由本模块证明。

<a id="direct-recording"></a>
## 同步记录路径

`recordTurn` 将入队与完成串联，适合调用方已经拥有完整结果、不需要异步队列的场景。它仍复用相同的入队和状态更新逻辑，因此也继承 refs 可覆盖默认元数据、状态迁移无条件以及并发序号分配等边界。[同步回合记录路径 ↗](../../../apps/server/src/conversation/router.ts#L195 "支持 recordTurn 复用 enqueueTurn 与 completeTurn、将入队和完成串联的说明。")
