# 会话身份与轮次状态持久化路由

以主体、渠道、聊天和线程确定会话，把每轮输入先持久化再执行，并提供去重、状态迁移、取消、结果与发件箱关联及重启恢复查询。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="identity"></a>
## 会话身份与可见性

路由器拥有会话和轮次的 SQLite 持久化。会话键由 workspace、principal、channel、chat 和 thread 共同决定；chat ID 不被当作项目身份。新会话默认落在 personal workspace，并保存 private/group 可见性，为上层限制证据范围提供状态，但本文件本身没有执行证据授权。[会话键与可见性设计 ↗](../../../apps/server/src/conversation/router.ts#L67 "支持会话身份组成、项目身份不从聊天推断及可见性边界说明。") `open` 先按完整键查找，存在则复用，否则创建 UUID 会话，因此线程差异会形成不同会话。[打开或创建会话 ↗](../../../apps/server/src/conversation/router.ts#L81 "说明完整会话键查询、personal 默认 workspace 与新会话创建流程。")

<a id="turn-lifecycle"></a>
## 先入队、再执行与幂等

轮次在模型或工具执行前以 pending 状态写入。若有外部 transport event ID，轮次 ID 由稳定摘要生成；重复投递返回已有记录并标记 duplicate，避免再次执行或重复回复。[轮次入队与事件幂等 ↗](../../../apps/server/src/conversation/router.ts#L146 "支持外部事件摘要生成轮次 ID、重复投递复用已有记录及 pending 初始状态。") 状态可依次改为 running、done、failed、pending 或 cancelled；完成时同时保存结果、证据、工具动作和可选 outbox ID，取消则不写回复正文或绑定发件箱。错误字符串在失败或重试状态下被截为 500 字符。[轮次完成、失败与取消 ↗](../../../apps/server/src/conversation/router.ts#L220 "说明状态更新、结果字段、发件箱关联及取消不产生回复的行为。")

<a id="recovery"></a>
## 查询与恢复边界

路由器可按序返回会话全部轮次，也可扫描仍为 pending/running 的记录，供重启后恢复。[未完成轮次恢复查询 ↗](../../../apps/server/src/conversation/router.ts#L286 "支持按 JSON 状态寻找 pending/running 轮次以供恢复的说明。") 不过状态保存在 JSON 文本列中，未完成查询通过 `LIKE` 匹配序列化片段，而不是结构化状态列；其可靠性依赖本模块固定的 JSON 序列化形式。`nextOrdinal` 的“读最大值再加一”和插入在此处未显示显式事务，并发写入时是否由数据库唯一约束兜底，材料无法确定。
