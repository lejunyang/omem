# 会话身份与可恢复轮次状态机

在 SQLite 中管理按主体、渠道、聊天和线程区分的会话，并以先入队、可幂等、可恢复的轮次状态支撑异步助理执行与回复投递。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="identity"></a>
## 会话身份与可见性

路由器以 workspace、principal、channel、chat 和 thread 的组合查找或创建会话；默认 workspace 为 personal，空线程被规范化为空字符串。项目身份不会从 chat ID 推断。会话另存 private/group 可见性、当前目标和待处理 case，为后续检索范围与任务连续性提供状态，但本文件本身不执行证据过滤。[会话复合身份规则 ↗](../../../apps/server/src/conversation/router.ts#L67 "支持会话键、可见性含义以及不从聊天 ID 推断项目身份的说明。")

<a id="enqueue"></a>
## 先持久化与幂等入队

轮次在任何模型调用前以 `pending` 状态写入，序号取当前会话最大值加一。若外部 transport event ID 存在，轮次 ID 由其稳定摘要生成；重复投递会返回既有记录并标记 duplicate，避免再次执行或重复回复。没有外部事件 ID 时使用随机 UUID。[轮次幂等入队 ↗](../../../apps/server/src/conversation/router.ts#L146 "说明 pending 先持久化、外部事件确定性 ID 和重复投递处理。")

`recordTurn` 是已经持有完整结果的同步捷径，本质仍先 enqueue 再 complete；异步调用方则可分别切换 running、done、failed、pending 或 cancelled。完成时写入证据选择、工具动作、结果和可选 outbox ID。[轮次完成流程 ↗](../../../apps/server/src/conversation/router.ts#L195 "支持同步记录捷径以及完成时写入结果、证据、工具动作和 outbox 的行为。")

<a id="recovery"></a>
## 失败、取消与恢复边界

模型暂不可用时可把轮次重新标为 pending，普通失败记录截断后的错误；取消不会写回复正文或绑定 outbox，从状态层阻止被中断轮次产生通知。重启恢复通过查询 JSON 文本中仍为 pending/running 的记录实现，并按创建时间返回。[轮次失败、待重试与取消 ↗](../../../apps/server/src/conversation/router.ts#L262 "说明各终态或待重试状态，以及取消轮次不产生通知的设计。")

状态存于 `input_message_refs` JSON 而非独立列，这避免本模块拥有额外迁移，却使恢复查询依赖序列化文本形态。`nextOrdinal` 的读取与插入未在本文件中显式包裹事务；是否存在并发序号冲突，要结合表约束和上层串行策略判断。[未完成轮次恢复查询 ↗](../../../apps/server/src/conversation/router.ts#L303 "支持 pending/running 恢复依赖 JSON 文本查询的实现边界。")
