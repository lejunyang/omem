# Lark 会话回复的持久投递与崩溃恢复测试

从实时入站事件贯穿模型与回复 outbox，验证崩溃重放、并发事件去重、相同正文区分、模糊失败重试及未完成 turn 重置，并明确供应商级幂等和恢复后重投尚未验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="harness"></a>
## 运行时夹具与事件边界

夹具在临时 Store 中植入活动连接、版本和 owner 群聊 binding，再以假的实时适配器、消息适配器和模型组装 `LarkRuntimeHost`。消息端可按次数抛出模糊网络失败，模型 gate 可暂停执行；入站事件则固定为已绑定 owner 在群聊中 @ 机器人，因而测试能控制并发和崩溃时序。[Lark 恢复测试夹具 ↗](../../../apps/server/tests/lark-delivery-recovery.test.ts#L77 "支持连接、binding、可脚本化消息失败、模型 gate 与 owner 群聊事件的夹具说明。")

<a id="dedupe"></a>
## 崩溃窗口与事件去重

回复已写入 outbox、但 inbox 尚未确认时发生模拟崩溃，唯一投递行仍为 pending，事件仍为 received；同一事件重放后不会创建第二行，inbox 转为 processed，worker 最终发送一次。[入队后崩溃与事件重放 ↗](../../../apps/server/tests/lark-delivery-recovery.test.ts#L172 "支持 outbox 已提交而 inbox 未确认时保留状态，以及同事件重放不新增投递行并最终只发送一次。") 两个并发到达的相同 transport event 也只产生一个 turn、一个 outbox 行和一次发送，说明此处验证的是事件级并发去重。[并发重复事件去重 ↗](../../../apps/server/tests/lark-delivery-recovery.test.ts#L218 "支持两个并发相同事件只建立一个 turn、一个 outbox 行并发送一次。")

<a id="retry"></a>
## 回复区分、重试与恢复限制

两个不同事件即使生成相同回复正文，仍拥有不同 provider UUID 并分别发送，避免按文本误合并。[相同回复文本分别投递 ↗](../../../apps/server/tests/lark-delivery-recovery.test.ts#L241 "支持不同 turn 即使正文一致也使用不同 provider UUID，并产生两次发送。") 模糊发送失败会让唯一 outbox 行进入 retry_wait，退避后转为 delivered；另一个场景仅证明 `recoverUnfinishedTurns` 会重置未完成的 pending turn，并未执行事件重投或断言模型重新运行。[模糊失败重试与 pending turn 重置 ↗](../../../apps/server/tests/lark-delivery-recovery.test.ts#L256 "支持 retry_wait 到 delivered 的本地状态变化，并限定恢复场景只断言未完成 turn 被重置。")

因此，恢复后重投能否重新完成模型与回复流程，以及远端已接收但本地未记录 delivered 时 provider UUID 是否实现供应商侧幂等，仍需独立验证。

## 待验证风险
