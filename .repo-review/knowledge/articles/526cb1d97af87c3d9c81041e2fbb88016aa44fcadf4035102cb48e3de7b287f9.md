# 支持证据分层阅读的响应式对话框

OmDialog 封装原生模态对话框，为证据阅读等场景提供标题、层级提示、正文滚动区、可选侧栏和操作区，并区分返回当前层与关闭全部两种意图。组件负责同步显示状态、恢复焦点及适配桌面和移动端，但具体的层级导航与状态保存由调用方实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为分层内容提供统一阅读容器

组件解决的是在不离开当前页面的情况下集中阅读较长内容，并允许附带第二栏补充信息。调用方传入 `open`、标题、可选层级和侧栏状态；默认插槽承载正文，`aside` 与 `actions` 插槽分别提供补充面板和底部操作区。标题通过 `aria-labelledby` 与原生 `dialog` 关联，层级大于零时显示“证据路径”提示。参考 [对话框输入与语义标题 ↗](../../../packages/ui/src/components/OmDialog.vue#L5 "支持组件接收打开状态、标题、层级和侧栏状态，并为标题建立无障碍关联的说明。")

它只定义展示容器和交互出口，不保存证据路径或正文数据，因此可复用于证据阅读之外的模态阅读场景。参考 [正文、侧栏与操作区 ↗](../../../packages/ui/src/components/OmDialog.vue#L44 "支持组件通过默认、aside 和 actions 插槽组织阅读内容的说明。")

<a id="interaction"></a>
## 打开、返回与关闭的事件流程

当 `open` 变化时，组件先等待 Vue 完成 DOM 更新；打开前记录当前焦点并调用 `showModal()`，关闭时调用原生 `close()`，再把焦点还给仍存在的原元素。卸载时也会关闭对话框，避免残留打开状态。参考 [显示同步与焦点恢复 ↗](../../../packages/ui/src/components/OmDialog.vue#L15 "支持打开时记录焦点、关闭时恢复焦点以及卸载清理的流程说明。")

Esc 触发原生 `cancel`，但默认行为被阻止并改为发送 `back`；点击遮罩或右上角按钮则发送 `close`。这使上层可以把“退回一层”和“关闭全部”实现成不同动作，不过本组件本身不会修改 `open`，父组件必须响应事件并更新状态。参考 [返回与关闭事件 ↗](../../../packages/ui/src/components/OmDialog.vue#L32 "支持 Esc、遮罩点击和关闭按钮分别发出 back 或 close 事件的说明。")

<a id="layout"></a>
## 双栏布局与移动端退化

桌面端对话框限制在视口内，正文区独立滚动；存在侧栏插槽且 `sideOpen` 为真时，容器扩宽并显示固定宽度侧栏。参考 [桌面双栏布局 ↗](../../../packages/ui/src/components/OmDialog.vue#L129 "支持侧栏开启时扩大容器并形成固定宽度双栏布局的说明。")

在 700px 以下，对话框铺满屏幕，双栏改为纵向排列，正文限制高度、侧栏占据更大的阅读区域。该规则适合上下分区浏览，但侧栏设置了 500px 最小高度，在较矮设备上可能产生额外滚动。参考 [移动端纵向布局 ↗](../../../packages/ui/src/components/OmDialog.vue#L146 "支持窄屏下全宽显示、纵向排列及侧栏最小高度限制的说明。")

关闭控件复用 `OmButton` 的幽灵样式和 `OmIcon` 的关闭图形；源文件中的显式导入与模板使用证明了这一依赖关系。参考 [按钮与图标依赖 ↗](../../../packages/ui/src/components/OmDialog.vue#L2 "源代码显式导入 OmButton 和 OmIcon，支持跨文件组件依赖关系。") [关闭控件组合 ↗](../../../packages/ui/src/components/OmDialog.vue#L50 "支持关闭入口由幽灵按钮与关闭图标组合实现的说明。")
