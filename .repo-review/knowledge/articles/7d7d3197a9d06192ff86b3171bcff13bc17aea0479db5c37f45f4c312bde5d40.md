# 代码分析角色的运行配置

该清单声明代码分析角色的身份、提示词与技能装配方式、结构化输出合同、工具和会话隔离策略，以及上下文、输出和修复预算。它描述的是运行时应采用的配置，不单独证明宿主已经完整执行或强制校验这些约束。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-contract"></a>
## 角色定位与输出合同

该配置把角色标识为版本 1 的“代码分析员”，并指定通过 `traex` 配置运行。角色加载 `prompt.md`，同时以内联方式装配固定版本及摘要的代码分析技能包，使提示模板与技能制品可以被明确追踪。参考 [角色与技能装配 ↗](../../../packages/agent-runtime/roles/code-analyst/1/manifest.json#L2 "支持角色版本、运行配置、提示模板以及内联技能包的声明。")

分析结果被要求符合 `KnowledgeBatch.v1`，意味着角色的职责不是返回任意文本，而是生成可由宿主继续校验、复核和发布的结构化知识批次。这里是**声明的输出合同**；仅凭清单无法确认每次实际响应均已通过该合同验证。参考 [结构化输出合同 ↗](../../../packages/agent-runtime/roles/code-analyst/1/manifest.json#L17 "支持代码分析结果被声明为 KnowledgeBatch.v1 结构化输出。")

<a id="isolation"></a>
## 无工具执行与会话隔离

角色的工具策略设为 `none`，允许列表为空，因此预期分析过程只处理宿主提供的上下文，不主动读取文件或调用外部工具。参考 [工具禁用策略 ↗](../../../packages/agent-runtime/roles/code-analyst/1/manifest.json#L18 "支持该角色配置为不使用工具且没有允许调用的工具。")

每次任务都要求新建会话，并禁止继承用户技能和 MCP 能力。这种隔离有助于减少历史会话、个人扩展或外部能力对材料分析的隐性影响，也使结果更容易追溯到本次输入；但配置本身不能证明运行时已经落实这些隔离措施。参考 [会话隔离策略 ↗](../../../packages/agent-runtime/roles/code-analyst/1/manifest.json#L22 "支持不复用会话、不继承用户技能和 MCP 能力的配置。")

<a id="budget"></a>
## 上下文、输出与修复预算

预算允许最多 96,000 个上下文 token 和 24,000 个输出 token，并为结构或内容不合格的结果预留最多两次修复尝试。较大的输入窗口适合分析代码材料，输出上限则为成体系的知识文档留出空间；修复次数仍是有限资源，连续失败后如何记录或降级需由宿主流程决定。参考 [分析预算限制 ↗](../../../packages/agent-runtime/roles/code-analyst/1/manifest.json#L27 "支持上下文、输出 token 上限以及最多两次修复尝试的预算说明。")
