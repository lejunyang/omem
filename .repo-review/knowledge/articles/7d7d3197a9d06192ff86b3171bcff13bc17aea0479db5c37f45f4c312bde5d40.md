# 代码分析角色运行清单

该清单声明代码分析角色的版本、提示模板、内联技能、结构化输出合同、工具与会话隔离策略以及运行预算。它是运行配置证据，不证明角色调度、模型调用或结果校验流程已经实际执行。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-contract"></a>
## 角色与产出合同

该文件把角色标识为第一版代码分析器，并引用 `prompt.md` 作为提示模板；同时绑定第一版内联技能及其制品摘要，用摘要帮助宿主识别固定技能制品。输出被声明为 `KnowledgeBatch.v1`，说明角色预期生成可校验的批量知识文档，而非自由格式回答。[代码分析角色身份与输出配置 ↗](../../../packages/agent-runtime/roles/code-analyst/1/manifest.json#L2 "支持角色版本、提示模板、内联技能和 KnowledgeBatch 输出合同的配置性描述。")

这些字段只构成静态清单：材料没有展示清单加载器、摘要核验或输出 schema 校验的实现，因此不能据此断言相应运行链路已经落地。

<a id="isolation-budget"></a>
## 隔离策略与预算边界

工具策略明确为禁用且允许列表为空；每次会话均不复用，也不继承用户技能和 MCP。这与固定证据分析场景相符，可降低外部环境影响，但清单本身不能证明运行时确实执行了隔离。[工具与会话隔离策略 ↗](../../../packages/agent-runtime/roles/code-analyst/1/manifest.json#L18 "支持禁用工具、禁止会话复用以及不继承用户扩展能力的论断。")

预算允许最多 96000 个上下文 token、24000 个输出 token，并配置两次修复尝试。它表达宿主可采用的上限及结构化输出修复容忍度，不代表每次任务都会用满预算，也没有说明超限、修复失败后的状态处理。[代码分析运行预算 ↗](../../../packages/agent-runtime/roles/code-analyst/1/manifest.json#L27 "支持上下文、输出及修复次数上限的说明。")
