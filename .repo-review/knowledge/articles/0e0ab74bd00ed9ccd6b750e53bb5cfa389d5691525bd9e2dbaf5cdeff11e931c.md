# KnowledgePlan.v1 输出结构

定义知识规划结果的顶层必填字段、章节数量、章节字段格式与封闭对象约束；它负责校验结构，但不覆盖材料目录成员关系或固定章节语义。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="plan_shape"></a>
## 顶层结构

该文件以 JSON Schema 2020-12 描述 `KnowledgePlan.v1`：输出必须是对象，`schema_version` 为数值且固定为 1。[版本与对象类型约束 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/output.schema.json#L1 "支持附近关于 JSON Schema 方言、顶层对象类型以及版本固定为 1 的说明。") 标题是 1–240 字符的字符串，`chapters` 是包含 4–32 项的数组。[标题和章节数组限制 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/output.schema.json#L9 "支持附近关于标题长度以及章节数组数量和类型的说明。") 顶层明确要求同时提供版本、标题和章节数组，并禁止出现未声明属性。[顶层必填与封闭属性 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/output.schema.json#L56 "直接支持顶层版本、标题、章节数组均为必填项，并禁止额外属性的论断。")

<a id="chapter_contract"></a>
## 章节合同与校验边界

每个章节对象包含 key、标题、用途和材料键列表：key 必须以字母开头并遵循限定字符格式，标题与用途均为受长度限制的非空字符串。[章节标识、标题与用途 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/output.schema.json#L19 "支持章节 key 的格式，以及标题和用途字段的类型与长度限制。") `materialKeys` 每章至少 1 项、最多 400 项；四个章节字段全部必填，且章节对象同样禁止额外属性。[材料键与章节必填项 ↗](../../../packages/agent-runtime/roles/knowledge-planner/1/output.schema.json#L35 "支持 materialKeys 的数量及字符串约束、四个章节必填字段和章节对象禁止额外属性。") 这些规则只验证形状与基数，不能单独确认材料键属于目录，也没有枚举必须出现的五个语义章节。
