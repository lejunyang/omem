# agent-runtime · 模块理解 · 专题 2

本专题并列说明对话整理、记忆候选提取和反馈纠正三类角色规范。它们都强调固定证据、可信上下文或原始目标的权威性，并产出结构化派生结果；现有材料未证明三者被编排为固定先后流程，也不足以确认加载、深层校验、复核与应用链路均已实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-separation"></a>
## 并列的角色职责

这一组材料描述三种彼此区分的职责，而非一条已证实的顺序流水线。对话分析关注说话人、时间、转述与回复语境，区分请求、承诺、猜测和事实，并避免把他人的承诺误记为用户待办。[对话语境与待办归属规则 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/prompt.md#L1 "支持对话分析负责保留语境、区分话语类型并避免错误待办归属的并列职责说明。") 提取角色从固定证据生成原子化、带作用域的持久记忆候选，身份、范围、时间和来源以可信上下文为准，材料正文始终视为不可信数据。[证据绑定的候选提取职责 ↗](../../../packages/agent-runtime/roles/extractor/1/prompt.md#L3 "支持提取角色依赖可信上下文、把材料视为不可信数据且只产出候选的职责边界。") 反馈整理则把已认证的所有者反馈转成绑定原目标与证据的纠正候选，且不允许重复反馈或生成摘要成为独立权威。[认证反馈到纠正候选 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/prompt.md#L3 "支持反馈整理绑定原目标与证据、区分反馈类型且禁止派生摘要成为独立权威。")

<a id="contracts-and-isolation"></a>
## 装配、合同与隔离边界

提取角色清单将提示模板、内联技能、`ProposalBatch.v1`、无工具策略、独立会话及预算绑定为静态配置。[提取角色运行清单 ↗](../../../packages/agent-runtime/roles/extractor/1/manifest.json#L2 "说明提取角色静态绑定配置档、提示模板、内联技能、输出合同、隔离策略与预算。") 其合同要求批次包含作业与角色身份，提案携带类型、操作、范围、正文、证据、不确定性、版本预期和来源，因此输出是待后续处理的变更候选，而不是已经成立或写入的事实。[提案批次结构 ↗](../../../packages/agent-runtime/roles/extractor/1/output.schema.json#L6 "支持 ProposalBatch 是包含身份、证据、不确定性、版本信息与来源的待处理提案合同。")

反馈角色采用 `CorrectionProposal.v1`；其规范要求核对参与者绑定和目标版本，明确停用内容与替代内容，并限制在原主题或项目范围内。[反馈纠正处理流程 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/skills/omem-feedback-curation/SKILL.md#L8 "支持参与者与目标版本核验、停用项和替代项绑定以及作用域限制的规范。") 对应清单同样声明禁用工具、不复用会话且不继承用户扩展。[反馈角色隔离与预算配置 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/manifest.json#L17 "支持反馈角色静态声明无工具、会话不复用、不继承用户扩展及预算上限。") 这些共同体现证据可追溯和派生结果不自成权威，但没有证明两个角色之间存在直接产物传递。

<a id="progress-limits"></a>
## 可确认进展、被替代结论与限制

当前可确认的是角色提示、技能、界面入口、清单与顶层 Schema 等静态制品已经存在。此前将三类角色写成“对话分析先、提取再、反馈整理则”的连续流程结论应停止采用；替代结论是：材料只证明三类并列职责，尚无角色注册、作业依赖或端到端测试证明固定编排。

实现边界也仍不完整。`CorrectionProposal.v1` 虽封闭顶层字段，但 `target`、`scope`、`origin` 与证据内部结构仍是宽泛类型；提取合同也对多个嵌套对象采取类似约束。[纠正合同的校验深度 ↗](../../../packages/agent-runtime/roles/feedback-curator/1/output.schema.json#L4 "支持 CorrectionProposal 顶层封闭、但关键嵌套对象与证据仅受宽泛类型约束的限制说明。") 对话分析仅见提示、技能和界面默认入口，未见 manifest、输出 Schema 或加载记录。[对话分析技能界面入口 ↗](../../../packages/agent-runtime/roles/conversation-analyst/1/skills/omem-conversation-analyst/agents/openai.yaml#L1 "支持对话分析已有静态展示与默认调用入口，同时不构成实际发现、加载或执行的证据。") 因而不能据此断言外部 Agent CLI/ACP 已发现全部技能、强制执行预算和隔离策略，或候选已经过独立复核并安全应用。
