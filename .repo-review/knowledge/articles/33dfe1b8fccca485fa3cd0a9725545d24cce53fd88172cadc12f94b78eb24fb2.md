# 知识页面的请求与阅读栈适配

为 Web 知识阅读界面组合共享知识类型、前端引用状态、鉴权请求封装与知识阅读帧，并明确请求头合并和错误解析的适用边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 组织知识页面的数据

该文件是知识阅读界面的轻量适配层：它复用共享合同中的知识文档、引用和页面规划类型，再补充当前修订、生成信息、问题数量以及引用是否可操作等前端状态。`Article` 将文章元数据、正文和解析后的引用组合起来，供页面展示知识内容并定位证据。参考 [文章与引用前端模型 ↗](../../../apps/web/src/knowledge/api.ts#L1 "支持该文件复用共享知识类型，并组合文章元数据、正文与解析后引用状态的说明。")

共享合同统一规定引用关系、目标类型、材料行号和文章章节等字段；前端的 `Citation` 在此基础上增加解析结果、可操作性、不可用原因与当前版本状态，没有另建一套引用格式。参考 [共享引用合同 ↗](../../../packages/contracts/src/knowledge.ts#L4 "说明共享合同约束引用关系、目标、行号和章节字段，而前端引用类型在其上扩展展示状态。")

<a id="request-flow"></a>
## 统一请求、令牌与错误处理

`knowledgeApi` 接收服务前缀、路径和可选的 `RequestInit`，从会话存储读取令牌。请求带正文时会默认添加 JSON 内容类型，有令牌时会添加 Bearer 鉴权；当 `init.headers` 是普通键值对象时，其中的同名字段会覆盖这些默认值。当前通过对象展开合并请求头，因此不能据此认为 `Headers` 实例或键值对数组也能被正确合并。参考 [鉴权请求组装 ↗](../../../apps/web/src/knowledge/api.ts#L6 "支持令牌读取、条件默认请求头以及通过对象展开合并调用方请求头，并据此界定 HeadersInit 形式的限制。")

成功响应被直接解析为 JSON。失败响应也会先尝试解析 JSON，并在结果是包含 `error` 字段的对象时优先采用该信息，否则通常以 HTTP 状态码生成中文异常；若 JSON 成功解析为 `null`，当前代码访问 `body.error` 时会产生类型错误。泛型 `T` 只提供编译期约束，本函数自身不执行共享 Zod schema 的运行时校验。参考 [响应解析与失败处理 ↗](../../../apps/web/src/knowledge/api.ts#L9 "支持成功响应直接解析、失败响应读取 error 或状态码回退，并揭示 null 响应与缺少运行时校验的边界。")

<a id="navigation-boundaries"></a>
## 标识阅读位置与适用边界

`KnowledgeFrame` 定义 `knowledge`、`citation` 和 `source` 三类阅读帧。现有 `knowledgeFrame` 构造器只创建知识帧，并把知识键、可选修订号和章节序列化进字符串 `id`，用于表达具体知识版本或阅读位置。参考 [阅读帧类型 ↗](../../../apps/web/src/knowledge/api.ts#L5 "支持阅读帧包含知识、引用和来源三种类别以及通用标识与标题字段。") [知识帧构造器 ↗](../../../apps/web/src/knowledge/api.ts#L12 "支持构造器固定创建知识帧，并将知识键、修订号和章节编码进字符串标识。")

该封装直接依赖浏览器的 `sessionStorage` 与 `fetch`，因此不是服务端通用客户端。解析后的引用可以记录文章或材料目标的标题、修订、摘要和位置，并通过 `actionable`、`unavailableReason` 与 `current` 告诉界面目标能否打开、为何不可用以及是否为当前版本。参考 [引用解析状态 ↗](../../../apps/web/src/knowledge/api.ts#L3 "支持解析后引用记录目标信息、可操作性、不可用原因和当前版本状态。")
