# 知识前端 API 与阅读帧合同

该模块衔接共享知识合同与前端阅读体验：定义文章、引用及帧类型，封装带会话令牌的 JSON 请求，并为知识文章生成可恢复的帧标识；成功体与错误字段的服务端约束仍待确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="contracts"></a>
## 文章、引用与解析目标

模块复用共享合同中的知识正文与引用类型，并为前端引用增加可操作状态、不可用原因、当前性及解析结果。解析目标区分文章和材料，可携带 revision、digest（内容摘要标识）、section 与行范围；这些字段为阅读组件定位固定版本、章节或原文片段提供依据，但多为可选值，下游仍需处理目标缺失和不可操作状态。[引用解析目标类型 ↗](../../../apps/web/src/knowledge/api.ts#L1 "支持引用解析结果区分文章与材料，并可携带 revision、digest、section 和行范围等定位字段的论断。")

阅读帧由 `kind`、字符串 `id` 和展示标题组成，种类包括知识、引用与原始材料。这里只规定三类帧共享相同外形，并未规定每种 `id` 都必然包含可解析的导航参数；具体解析和分派由阅读组件按帧种类完成。[阅读帧基础结构 ↗](../../../apps/web/src/knowledge/api.ts#L5 "支持三类阅读帧共享 kind、字符串 id 与标题结构，同时说明该类型本身未约束 id 内容。")

<a id="request"></a>
## 认证请求与响应处理

`knowledgeApi` 从会话存储取得令牌，存在时加入 Bearer 认证；请求包含 body 时补充 JSON 内容类型，再合并调用方 headers。该合并方式对普通对象形式最直观，但 `RequestInit.headers` 也允许 `Headers` 实例或元组数组，因此不能据此保证所有合法形式都按预期展开。[认证与请求头合并 ↗](../../../apps/web/src/knowledge/api.ts#L6 "支持会话令牌、JSON 内容类型以及调用方 headers 合并方式的说明。")

失败响应会尝试读取 JSON，并优先用其中 truthy 的 `error` 构造异常，否则回退到状态码信息；成功响应则无条件调用 `response.json()`。这意味着封装隐含依赖后端返回 JSON 成功体，也尚未在现有材料中确认 `error` 一定是适合展示的字符串。[响应与错误处理 ↗](../../../apps/web/src/knowledge/api.ts#L9 "支持失败体解析、状态码回退及成功响应无条件按 JSON 解析的说明。")

<a id="frame"></a>
## 知识帧的可恢复导航

`knowledgeFrame` 专门构造 knowledge 帧：它把文章 key、可选 revision 和 section 序列化进字符串 `id`，同时保留调用方提供的可读标题。[知识帧构造函数 ↗](../../../apps/web/src/knowledge/api.ts#L12 "支持仅对 knowledge 帧将文章键、版本和章节序列化进 id 的限定性结论。") 阅读组件随后解析该 `id`，并把其中的文章键、版本与章节交给正文组件；source 与 citation 帧也在同一分派入口处理，但它们的参数来源和构造方式不由本函数定义。[阅读帧解析与分派 ↗](../../../apps/web/src/knowledge/KnowledgeFrame.vue#L7 "支持阅读组件解析帧 id，并按 knowledge、source、citation 种类分别加载内容的说明。")

因此，先前将“三类帧都使用字符串 id 保存导航参数”视为统一保证的表述已被替代：当前可以明确确认的是 `knowledgeFrame` 生成的知识帧具有可序列化导航参数，以及阅读入口能够按帧种类解释已有参数。
