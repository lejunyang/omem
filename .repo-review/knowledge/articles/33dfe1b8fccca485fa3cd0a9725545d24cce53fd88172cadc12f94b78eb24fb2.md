# 知识阅读界面的请求与导航适配

该适配层连接共享知识合同与前端阅读界面，组合文章及引用的展示状态，统一发送带会话令牌的请求，并生成可传递的文章阅读帧。响应运行时校验、认证失效恢复和完整阅读栈行为仍需结合调用方确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 连接知识合同与阅读界面

知识阅读界面既要展示文章，也要判断引用当前能否打开。该适配层复用共享的知识文档与引用类型，为文章补充版本、复核信息和疑问数量，并为引用增加可操作状态、不可用原因与解析目标，使组件能够区分“存在引用”和“当前可跳转的引用”。参考 [文章与引用展示类型 ↗](../../../apps/web/src/knowledge/api.ts#L1 "支持前端为文章补充元数据、为引用补充解析结果与可操作状态，并组合界面文章类型的说明。")

共享合同统一约束文档分类、章节、引用和待确认问题，因此界面类型与知识生成、复核流程使用同一套基础数据结构。参考 [知识文档合同 ↗](../../../packages/contracts/src/knowledge.ts#L25 "支持共享合同统一约束文档分类、章节、引用与问题结构的说明。")

<a id="request-flow"></a>
## 发送请求并转换错误

`knowledgeApi` 接收服务前缀、路径和标准请求选项，从会话存储读取令牌。请求带正文时默认加入 JSON 内容类型，存在令牌时加入 Bearer 认证，调用方提供的同名请求头最后合并，因而可以覆盖这些默认值。参考 [认证与请求头合并 ↗](../../../apps/web/src/knowledge/api.ts#L6 "支持令牌读取、JSON 内容类型注入、Bearer 认证及调用方请求头覆盖顺序的说明。")

非成功响应先尝试解析 JSON。仅当解析结果不是 `null` 且其 `error` 属性为真值时，才会把该值交给 `Error`；字符串、数字、布尔值或不含真值 `error` 的对象可安全读取属性，并回退为包含状态码的中文提示。若 JSON 结果为 `null`，访问 `body.error` 会直接产生属性访问异常，绕过该后备提示；JSON 解析失败则以空对象回退。成功响应直接返回 JSON 解析结果。参考 [响应错误处理 ↗](../../../apps/web/src/knowledge/api.ts#L9 "支持错误响应解析、error 属性读取、状态码后备提示、null 属性访问例外及成功响应直接解析 JSON 的说明。")

<a id="navigation"></a>
## 生成文章阅读帧

阅读帧用统一结构表示知识文章、引用或原始材料，并携带标识与人读标题。参考 [阅读帧类型 ↗](../../../apps/web/src/knowledge/api.ts#L5 "支持阅读帧可表示知识文章、引用或原始材料并携带标识和标题的说明。")

`knowledgeFrame` 创建知识文章帧，把文章键、可选版本和章节序列化进 `id`，供调用方传递具体阅读位置。现有材料只能确认帧的形状与构造方式，尚不能确定由哪个模块恢复该标识，以及如何完成深链、返回和关闭等阅读栈交互。参考 [文章帧构造 ↗](../../../apps/web/src/knowledge/api.ts#L12 "支持文章键、可选版本和章节被序列化进知识文章帧标识的说明。")

<a id="boundaries"></a>
## 适配层的责任边界

泛型 `T` 只表达编译期预期；成功响应在此处没有经过共享 Zod schema 的运行时校验。该封装也只负责读取并发送会话令牌，再把非成功响应转换为异常，没有展示令牌刷新或针对 401、403 的恢复策略。参考 [请求封装边界 ↗](../../../apps/web/src/knowledge/api.ts#L7 "支持成功响应未经运行时 schema 校验、令牌仅被读取发送以及非成功响应统一抛错的边界说明。")

共享 schema 约束引用关系、目标类型、材料行号和文章章节；前端则在这些基础字段上增加解析结果、可操作状态与当前性信息。参考 [共享引用字段约束 ↗](../../../packages/contracts/src/knowledge.ts#L3 "支持引用关系、目标类型、材料行号和文章章节由共享 schema 约束的说明。")
