# 知识前端 API 与阅读帧合同

定义知识文章、引用和阅读帧的前端类型，封装带会话令牌的 JSON 请求，并构造可序列化的知识阅读帧。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="contracts"></a>
## 文章、引用与帧类型

模块复用共享合同中的知识正文与引用类型，并为前端引用补充可操作性、不可用原因、当前状态和解析目标。解析目标可指向文章或材料，并携带 revision、digest（内容摘要标识）、section 及起止行等可选定位信息。KnowledgeFrame 则规定 knowledge、citation、source 三类帧均具有字符串 id 和展示标题，但该类型本身不保证所有 id 都含 JSON 导航参数。[知识前端类型合同 ↗](../../../apps/web/src/knowledge/api.ts#L1 "支持文章、引用解析目标的可选定位字段，以及三类阅读帧的结构边界。")

<a id="request"></a>
## 认证请求与错误传播

`knowledgeApi` 从 sessionStorage 读取令牌，存在时加入 Bearer 认证；请求包含 body 时补 JSON 内容类型。自定义 headers 通过对象展开合并，这只足以描述普通对象形式，不能证明 `Headers` 实例或元组数组都可靠保留。非成功响应尝试读取 JSON 的 error，否则使用状态码；成功响应无条件调用 `response.json()`。[知识 API 请求封装 ↗](../../../apps/web/src/knowledge/api.ts#L6 "支持令牌、JSON 请求头、响应解析和错误传播流程，并界定请求头合并限制。")

<a id="frame-construction"></a>
## 知识帧构造

`knowledgeFrame` 专门构造 knowledge 帧，将文章键、可选 revision 和 section 序列化进 id，并保留调用方给出的标题。[知识帧构造函数 ↗](../../../apps/web/src/knowledge/api.ts#L12 "支持知识帧把文章键、可选版本与章节 JSON 序列化进 id。") 因而可以确认由该函数生成的知识帧保存了可恢复导航参数；citation 与 source 帧是否采用同样编码方式，需要其各自构造处的证据。
