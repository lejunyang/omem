# 代码图谱同步与 HTTP 合同测试

通过临时 Git 仓库和真实仓库验证 TypeScript/Vue 投影、快照生命周期、历史保留、表隔离及代码读取接口；其重点是确定性结构图，而非跨文件语义调用证明。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="parser-lifecycle"></a>
## 解析能力与快照生命周期

测试先构造临时 Git 仓库，执行 review capture 后再执行 code sync。小型夹具断言 TypeScript 函数、类方法限定名、源码行范围、导出标记和 fragment 锚点，并确认 Vue SFC 会产生 component symbol。虽然用例名称提到 imports 与同文件 calls，实际断言没有直接检查对应 edge 的类型或端点，因此不能据此证明跨文件调用解析正确。[TypeScript 与 Vue 解析夹具 ↗](../../../apps/server/tests/code-knowledge.test.ts#L70 "支持符号、范围、限定名、fragment 锚点和 Vue component 的实际断言，并揭示 edge 缺少直接断言。")

生命周期用例覆盖重复同步复用 snapshot、不重复增加 symbol；相同字节但不同路径生成独立 file/symbol ID；删除文件后标 removed，同时保留旧 snapshot 的 edge 行而从当前图隐藏；源码改变形成新 snapshot，旧 snapshot 仍可读取。未先 capture 的脏工作树修改不会成为新证据，补做 review sync 后才产生新快照。[代码同步生命周期用例 ↗](../../../apps/server/tests/code-knowledge.test.ts#L139 "支持幂等、路径身份、删除历史、快照更新和脏工作树捕获边界。")

<a id="integration-http"></a>
## 共享表隔离、真实仓库与接口

附加性测试记录 sources、revisions、fragments、review_relations 的行数，确认 code sync 不改动通用捕获与评审关系表，说明代码图是既有证据链上的派生投影。[代码表附加性断言 ↗](../../../apps/server/tests/code-knowledge.test.ts#L261 "证明 code sync 前后通用捕获表与评审关系表行数保持一致。")

真实仓库用例要求文件数超过 50，并覆盖 assistant、memory、retrieval、Lark 和 Vue 区域，同时只断言图中存在文件、符号和非空边；它是广度烟雾测试，并未核对每条边的源码语义。HTTP 用例验证文件、符号、图接口和合法单行源码切片返回成功，越界范围返回 400，但没有覆盖鉴权、分页、removed/historical 过滤或错误 DTO 的完整内容。[真实仓库与 HTTP 路由测试 ↗](../../../apps/server/tests/code-knowledge.test.ts#L286 "支持真实区域覆盖、图非空及源码范围校验，同时界定这些断言的粒度。")
