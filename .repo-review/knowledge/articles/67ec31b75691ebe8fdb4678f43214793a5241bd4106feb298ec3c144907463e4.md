# 代码知识同步与查询的行为测试

该测试验证 review 捕获后的代码知识投影：包括 TypeScript/Vue 文件与符号解析、快照复用和历史保留、统一证据表行数约束、真实仓库图生成及 HTTP 查询。修订后的结论不再推断 fixture 使用比例，也不把边存在等同于关系语义正确；旧边转为 stale 目前主要是实现声明，测试尚未直接断言其状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="fixture-and-parsing"></a>
## 测试基座与解析范围

`setup` 在临时目录中创建 SQLite Store，`afterEach` 负责关闭数据库并清理这些目录；`makeFixtureRepo` 则提供独立的临时 Git 仓库及提交身份配置。这里仅说明辅助设施的职责，不再对各用例使用临时仓库的数量或比例作判断。[临时 Store 与 fixture 仓库辅助设施 ↗](../../../apps/server/tests/code-knowledge.test.ts#L29 "支持临时 Store 的创建清理方式，以及 fixture Git 仓库和提交身份配置的职责；不用于推断调用比例。")

解析用例先执行 review 捕获，再运行代码同步；后者不会捕获文件正文，而是把代码结构投影到隔离侧表，并将符号定位到已捕获的当前 fragment。[代码知识投影职责 ↗](../../../apps/server/src/code/sync.ts#L1 "说明代码同步不捕获正文，而是在已捕获 fragment 之上建立文件和符号投影。") 测试直接确认了 TypeScript 函数、类方法限定名、行范围、导出标记、fragment 锚点及 Vue component；虽然用例名称提到 import 和同文件调用，却没有断言相应边的类型、端点或状态。[TypeScript 与 Vue 解析断言 ↗](../../../apps/server/tests/code-knowledge.test.ts#L74 "支持函数、方法、范围、导出、fragment 锚点和 Vue component 的实际断言，并显示未直接检查关系边。")

<a id="snapshot-lifecycle"></a>
## 快照生命周期与证据边界

生命周期用例确认相同输入会复用快照且不增加符号行，相同字节位于不同路径时仍具有不同文件和符号身份。删除文件后，其历史边行仍保留，而当前 head 图不再展示该文件的边。[幂等、路径身份与删除行为 ↗](../../../apps/server/tests/code-knowledge.test.ts#L143 "支持相同输入复用、相同内容不同路径保持独立，以及删除后历史边保留但当前图移除相关边。") 另一个代码变更用例独立证明新旧快照身份不同、旧快照记录仍可读取，并且新快照存在非 stale 边；它没有查询旧边的具体 `status`。[代码变更后的快照断言 ↗](../../../apps/server/tests/code-knowledge.test.ts#L217 "支持代码变更生成新快照、旧快照记录仍可读取，以及新快照具有非 stale 边；同时界定未断言旧边状态。")

实现注释声明：输入变化会生成新快照，未重新产出的边会转为 stale。该规则是实现设计说明，不能表述为上述生命周期断言已经逐边验证。[快照失效实现说明 ↗](../../../apps/server/src/code/sync.ts#L7 "支持未重产边转为 stale 是代码同步的实现声明，而非现有测试已逐边验证的结论。") 脏编辑用例还表明，磁盘变化只有重新经过 review 捕获后才形成新的代码快照。[脏工作区证据边界 ↗](../../../apps/server/tests/code-knowledge.test.ts#L242 "支持磁盘编辑在重新执行 review 捕获之前不会改变代码快照，重新捕获后才产生新快照。")

<a id="storage-and-repository"></a>
## 存储约束与真实仓库集成

“additive”用例仅比较代码同步前后 `sources`、`revisions`、`fragments` 和 `review_relations` 的行数，并确认计数相等。[统一证据表行数断言 ↗](../../../apps/server/tests/code-knowledge.test.ts#L265 "支持代码同步前后四张表的行数相等，并限定该断言不能证明行内容完全不变。") 因此它支持“本场景未增删这些表的行”，但不能证明既有行内容绝无更新。底层 Store 当前是单用户 SQLite，团队级数据库与权限约束仍属于后续迁移范围。[单用户 SQLite 存储边界 ↗](../../../apps/server/src/store.ts#L4 "说明当前 Store 的单用户基础及团队级约束尚未实现。")

真实仓库用例检查主要服务路径、Lark 文件和 Vue 文件存在，并要求图中的文件、符号及边均非空。[真实 omem 仓库覆盖 ↗](../../../apps/server/tests/code-knowledge.test.ts#L290 "支持实际仓库中的目标路径、Vue 文件以及非空文件、符号和边断言，同时限定其不能证明关系语义。") 这证明实际仓库可形成代码图，但只支持“存在非空边”，不能进一步证明每条 import 或调用关系的端点、类型和状态均正确；此前将关系语义列为已验证范围的结论由此收窄。

<a id="http-surface"></a>
## HTTP 查询面与覆盖缺口

HTTP 用例通过 review 应用请求文件列表、文件符号、代码图和合法源码切片，并验证超过文件末尾的范围返回 400。[代码知识 HTTP 路由断言 ↗](../../../apps/server/tests/code-knowledge.test.ts#L328 "支持文件、符号、图、合法源码切片成功响应及一种超出文件末尾的范围返回 400。") 当前直接覆盖的是浏览成功路径和一种越界情形。

review 应用声明：未配置 token 时只接受 loopback Host 与本地同源浏览器请求；配置 `REVIEW_TOKEN` 后，全部 `/api` 路由均受 token 保护。[Review 应用访问边界 ↗](../../../apps/server/src/review/app.ts#L6 "说明 loopback、同源和 REVIEW_TOKEN 的声明性安全约束，用于界定当前 HTTP 测试尚未覆盖的访问路径。") 现有用例始终使用允许的本地 Host 和 Origin，尚未覆盖非本地 Host、错误 Origin、token 校验、未知文件、反向范围及非整数参数。
