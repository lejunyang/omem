# 代码知识投影的解析、快照与接口验证

该测试套件验证代码知识功能能否基于已捕获材料建立稳定投影：从 TypeScript、Vue 提取符号并锚定原始片段，以快照保存当前状态和历史，再通过查询函数及 HTTP 接口提供文件、符号、图关系与源码切片。测试覆盖幂等、删除、脏工作区、同内容不同路径和表隔离，但调用边精度、旧边陈旧状态及接口安全拒绝路径仍缺少直接断言。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-fixtures"></a>
## 从捕获材料验证代码知识投影

测试围绕一条核心约束展开：代码结构必须是原始材料的派生视图，不能脱离捕获内容成为新的事实来源。夹具类用例才会创建临时 Git 仓库，并在各用例结束前显式删除；独立 Store 的数据目录统一由 `afterEach` 关闭数据库后清理。真实仓库烟雾测试则直接使用实际仓库根目录，只为测试建立隔离 Store，不会清理真实仓库。参考 [测试资源隔离 ↗](../../../apps/server/tests/code-knowledge.test.ts#L29 "支持真实仓库根目录、临时 Store、统一 Store 清理以及夹具仓库创建方式之间的区别。") 参考 [TypeScript 夹具断言 ↗](../../../apps/server/tests/code-knowledge.test.ts#L74 "支持夹具仓库的创建和显式清理，以及函数、方法、范围和片段锚定断言。") 参考 [真实仓库覆盖检查 ↗](../../../apps/server/tests/code-knowledge.test.ts#L290 "支持烟雾测试直接使用真实仓库根目录和隔离 Store，并覆盖多个业务区域。")

代码同步不捕获文件正文，而是在已有头部片段上定位声明行，并用仓库状态与内容摘要形成可复用快照。因此，先执行材料捕获、再执行代码投影，是这些测试共同验证的功能合同。参考 [代码投影与快照合同 ↗](../../../apps/server/src/code/sync.ts#L1 "解释代码同步依赖已捕获片段，并以仓库状态和内容摘要建立幂等快照。")

<a id="parser-contract"></a>
## 解析器保证的结构信息

最小 TypeScript 夹具验证函数种类、声明起始行、导出状态、类方法限定名，以及符号能否锚定真实片段；Vue 夹具则确认单文件组件会生成以文件名命名的组件符号。参考 [TypeScript 夹具断言 ↗](../../../apps/server/tests/code-knowledge.test.ts#L74 "支持夹具仓库的创建和显式清理，以及函数、方法、范围和片段锚定断言。") 参考 [Vue 组件解析 ↗](../../../apps/server/tests/code-knowledge.test.ts#L113 "支持 Vue 单文件组件被识别为组件符号及其命名规则。")

这些断言主要证明 AST 能提供稳定定位和展示结构。首个用例名称虽包含 import 与同文件调用，但断言没有读取相应边的类型、方向或目标，因此尚不足以证明调用图关系正确。

<a id="snapshot-lifecycle"></a>
## 快照如何保存当前状态与历史

生命周期测试覆盖多项身份边界：相同输入再次同步会复用快照且不增加符号记录；内容相同但路径不同的文件仍具有独立文件和符号身份；删除文件后历史边记录继续存在，而当前图不再展示该文件的边。参考 [重复同步幂等性 ↗](../../../apps/server/tests/code-knowledge.test.ts#L143 "支持相同输入复用快照且不产生重复符号记录。") 参考 [同内容文件身份隔离 ↗](../../../apps/server/tests/code-knowledge.test.ts#L164 "支持文件和符号身份包含路径语义，而不是只由内容决定。") 参考 [删除文件的历史保留 ↗](../../../apps/server/tests/code-knowledge.test.ts#L181 "支持删除文件被标记移除、历史边行继续存在且当前图不再显示其边。")

新提交会产生不同快照，旧快照记录仍可读取；不过现有断言只统计新快照中的非陈旧边，没有直接读取旧边并确认其状态为 `stale`。参考 [历史快照可读性 ↗](../../../apps/server/tests/code-knowledge.test.ts#L217 "支持新旧快照身份不同、旧快照仍可读取，同时揭示陈旧边状态缺少直接断言。") 工作区磁盘修改在重新捕获前不会改变代码快照，完成捕获后才形成新快照；代码侧表也是附加投影，不会改动来源、修订、片段和评审关系的数量。参考 [捕获驱动的脏树快照 ↗](../../../apps/server/tests/code-knowledge.test.ts#L242 "支持磁盘修改须先进入材料捕获，之后代码同步才生成新快照。") 参考 [代码表的附加性 ↗](../../../apps/server/tests/code-knowledge.test.ts#L265 "支持代码投影不会改变来源、修订、片段及评审关系表。")

<a id="integration-boundaries"></a>
## 真实仓库与 HTTP 接口的覆盖边界

真实仓库用例检查助手、记忆、检索、Lark 和 Vue 区域能够进入投影，并要求图中存在文件、符号和有效边。这是一项广度烟雾测试，证明实际仓库的多个区域可被处理，但不验证每个符号或跨文件关系的语义精度。参考 [真实仓库覆盖检查 ↗](../../../apps/server/tests/code-knowledge.test.ts#L290 "支持烟雾测试直接使用真实仓库根目录和隔离 Store，并覆盖多个业务区域。")

接口用例验证文件列表、文件符号、代码图和源码切片：合法范围返回源码，越界范围返回 400。参考 [代码查询接口断言 ↗](../../../apps/server/tests/code-knowledge.test.ts#L328 "支持文件、符号、图和源码切片接口的成功路径及越界错误行为。") 当前材料没有覆盖错误令牌、非回环 Host 或跨源 Origin 等拒绝路径；应用入口虽声明了这些访问边界，仍需专门测试才能视为已验证。延伸阅读：[评审接口访问边界 ↗](../../../apps/server/src/review/app.ts#L6 "说明回环 Host、同源浏览器请求和令牌门禁策略，用于界定当前接口测试缺口。")
