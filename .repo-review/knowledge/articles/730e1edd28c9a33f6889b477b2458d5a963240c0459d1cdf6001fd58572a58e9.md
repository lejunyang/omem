# 材料分析角色的 KnowledgeBatch 输出合同

该文件定义 material-analyst 的 KnowledgeBatch.v1 输出形状：一个批次包含带章节、引用和问题的知识文档。与 knowledge-writer 对应文件逐段比较可见，两者当前采用相同的字段结构、约束与 Schema 标识；但静态合同本身不能证明运行时已实施跨字段语义校验，也不能证明两份文件由单一来源生成或持续同步。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="batch_contract"></a>
## 批次与知识文档结构

该 Schema 将顶层版本固定为 1，并要求 `documents` 包含 1–16 个文档。每个文档具有键、标题、摘要、受限分类和 1–20 个章节；章节必须提供键、标题和正文，且不接受未声明属性。[材料分析合同的批次与章节定义 ↗](../../../packages/agent-runtime/roles/material-analyst/1/output.schema.json#L5 "支持附近关于版本、文档数量、文档基本属性、分类枚举、章节数量及章节必填字段的说明。") 文档还必须同时包含引用和问题，顶层只允许 `schema_version` 与 `documents`，Schema 标识为 `KnowledgeBatch.v1`。[材料分析合同的必填项与标识 ↗](../../../packages/agent-runtime/roles/material-analyst/1/output.schema.json#L208 "支持附近关于文档必填字段、顶层必填字段、额外属性限制和 KnowledgeBatch.v1 标识的说明。")

对照 knowledge-writer 的合同，其批次、文档和章节约束相同，文档与顶层必填项及最终 Schema 标识也一致。[知识撰写合同的批次与章节定义 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/output.schema.json#L5 "作为跨文件比较的另一侧证据，支持 knowledge-writer 当前具有相同批次、文档属性和章节约束的论断。")[知识撰写合同的必填项与标识 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/output.schema.json#L208 "支持跨文件比较中关于 knowledge-writer 文档必填项、顶层约束及 KnowledgeBatch.v1 标识一致的论断。") 这只能说明两份给定文件在当前材料中的静态结构一致，不能据此断言二者由生成流程自动同步，或相关运行时功能已经实现。

<a id="provenance_contract"></a>
## 证据定位、未决问题与校验边界

引用条目要求人读标签、理由、限定关系、目标和 `quote`；目标可指向材料或文章，并可携带材料行范围或文章章节。`quote` 的描述约定由宿主从固定行范围提取原文。问题条目则记录问题、原因、下一步、阻塞状态和关联引用键。[材料分析合同的引用与问题定义 ↗](../../../packages/agent-runtime/roles/material-analyst/1/output.schema.json#L78 "支持附近关于引用字段、关系枚举、目标定位、原文抽取约定以及未决问题结构的说明。") knowledge-writer 的对应区段具有同样的引用目标、关系枚举、宿主抽取约定和问题结构，进一步支持两份合同当前一致的判断。[知识撰写合同的引用与问题定义 ↗](../../../packages/agent-runtime/roles/knowledge-writer/1/output.schema.json#L78 "作为跨文件比较的另一侧证据，支持 knowledge-writer 当前具有相同引用、目标定位、原文抽取和问题结构的论断。")

不过，JSON Schema 主要约束单个字段与对象形状：它不能单独保证任务目标全部覆盖、正文实际使用每个引用、材料行号落在授权范围内，或 `citationKeys` 均指向真实引用。是否已有宿主验证器、修复流程和端到端测试补足这些跨字段规则，仍需检查实现证据。
