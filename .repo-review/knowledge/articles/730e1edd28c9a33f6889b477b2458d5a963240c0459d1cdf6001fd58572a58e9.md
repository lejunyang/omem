# 材料分析结果的结构化输出合同

该 JSON Schema 定义 KnowledgeBatch.v1 的输出结构：一个批次包含 1–16 篇文档，每篇文档由元数据、分节正文、引用和待确认问题组成，并受到字段类型、数量、长度、枚举值及附加字段规则约束。它能够证明格式要求已经声明，但不能单独证明生成、引文提取或语义复核流程已经实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="batch_contract"></a>
## 批次与文档包含什么

该合同把一次材料分析输出定义为 `schema_version` 固定为 `1` 的文档批次，批次必须包含 1–16 篇文档。参考 [批次入口与数量约束 ↗](../../../packages/agent-runtime/roles/material-analyst/1/output.schema.json#L1 "支持固定模式版本以及每批文档数量范围的说明。")

每篇文档必须提供键、标题、摘要、分类、正文分节、引用和问题清单；分类只能从概览、架构、背景、需求、进展、实现、测试、配置、工作流、研究、对话和视觉材料等枚举值中选择。参考 [文档元数据与分类 ↗](../../../packages/agent-runtime/roles/material-analyst/1/output.schema.json#L15 "支持文档键、标题、摘要及允许分类枚举的说明。")

<a id="document_structure"></a>
## 正文与对象如何约束

正文由 1–20 个分节组成。每节包含键、标题和 Markdown 正文；分节键必须以字母开头，后续只能使用字母、数字、下划线或连字符，且各文本字段都有长度限制。分节对象不接受未声明字段。参考 [分节正文规则 ↗](../../../packages/agent-runtime/roles/material-analyst/1/output.schema.json#L48 "支持分节数量、键格式、字段长度、必填字段及禁止附加字段的说明。")

文档对象要求七个核心字段全部出现，并拒绝额外字段；引用对象、引用目标和问题对象也分别声明了必填项及 `additionalProperties: false`。这些是严格的结构约束，但模式本身没有说明界面导航或自动处理行为。参考 [文档必填字段 ↗](../../../packages/agent-runtime/roles/material-analyst/1/output.schema.json#L208 "支持文档必须包含内容、引用和疑问字段，并拒绝未声明字段的说明。") [引用结构与目标定位 ↗](../../../packages/agent-runtime/roles/material-analyst/1/output.schema.json#L78 "支持引用数量、关系类型、可选定位字段、各层必填项、附加字段限制及 quote 描述的说明。") [待确认问题结构 ↗](../../../packages/agent-runtime/roles/material-analyst/1/output.schema.json#L166 "支持问题数量、必填字段、关联引用键的字符串数组形式及问题对象禁止附加字段的说明。")

<a id="evidence_and_questions"></a>
## 引用与疑问如何表达

每篇文档必须包含 1–160 条引用。引用记录人读标签、理由、关系类型和目标；目标可携带材料或文章键，并可选带起止行或章节。模式没有按目标种类强制限定这些定位字段。`quote` 虽是必填字符串，但其描述要求留空，由宿主从选定的固定行范围提取原文。参考 [引用结构与目标定位 ↗](../../../packages/agent-runtime/roles/material-analyst/1/output.schema.json#L78 "支持引用数量、关系类型、可选定位字段、各层必填项、附加字段限制及 quote 描述的说明。")

疑问清单最多包含 20 项，每项记录问题、原因、下一步、是否阻塞以及关联引用键。该数组没有最小数量限制，因此可以为空；其中 `citationKeys` 仅被定义为字符串数组，模式未表达它与本篇引用之间的交叉一致性。参考 [待确认问题结构 ↗](../../../packages/agent-runtime/roles/material-analyst/1/output.schema.json#L166 "支持问题数量、必填字段、关联引用键的字符串数组形式及问题对象禁止附加字段的说明。")

<a id="scope_and_limits"></a>
## 合同能证明什么

顶层对象只允许 `schema_version` 与 `documents` 两个字段，并以 KnowledgeBatch.v1 作为模式标识。参考 [顶层版本合同 ↗](../../../packages/agent-runtime/roles/material-analyst/1/output.schema.json#L220 "支持顶层必填字段、禁止附加字段及 KnowledgeBatch.v1 模式标识的说明。")

这份文件证明的是输出格式及其静态校验边界。它没有描述由谁生成文档、宿主如何执行引文复制、引用是否真正支持附近论断，也没有给出独立复核的运行证据。因此，不能仅凭该模式断言分析流水线或语义验证已经实现；关于宿主行为仍需结合实现代码和行为测试确认。参考 [引用结构与目标定位 ↗](../../../packages/agent-runtime/roles/material-analyst/1/output.schema.json#L78 "支持引用数量、关系类型、可选定位字段、各层必填项、附加字段限制及 quote 描述的说明。")
