# 关系核验技能规范

该技能把关系核验流程压缩为从图重新推导、分类事实与解释、精确引用、区分机械存在与语义正确，以及保持只读输出五项规则。它与角色提示词一致，属于执行规范而非已完成核验的证明。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="verification_method"></a>
## 核验方法与证据纪律

技能要求逐项从快照的图边和证据重新推导，不接受前序代理结论作为依据。已有边对应 `raw_fact`；看似合理但缺少支持的关系可作为较低置信度的 `interpretation`，并在标识缺失时优先进入 `unknowns`。[关系重推导与引用纪律 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/skills/omem-code-relation-verifier/SKILL.md#L6 "支持从快照重新推导、区分 raw_fact 与 interpretation，并对缺失标识转入 unknowns 的方法。") 这形成“图结构事实—语义判断—未知项”的分层，降低把推测写成既成事实的风险。

<a id="semantic_boundary"></a>
## 机械事实不等于语义正确

规范特别区分“边存在”的机械事实与“关系语义正确”的判断，禁止角色仅凭自己的判断将后者提升为 verified。[结构存在与语义正确的边界 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/skills/omem-code-relation-verifier/SKILL.md#L11 "支持不能把机械存在的边直接等同于已经验证的语义关系。") 技能同时规定只返回 `CodeUnderstanding.v1` JSON、不得调用工具或修改内容。[只读与结构化输出要求 ↗](../../../packages/agent-runtime/roles/relation-verifier/1/skills/omem-code-relation-verifier/SKILL.md#L12 "支持技能要求不调用工具、不修改材料并仅输出指定 JSON 合同。") 这些约束与提示词互相解释，但材料未提供技能执行器或合规测试，不能推断所有模型输出都会遵守。
