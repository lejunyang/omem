# Code Knowledge 领域模型与首个纵向切片设计

历史设计提案，规划在权威证据链上增加可重建的代码类型投影、TS/Vue 确定性解析、结构边和派生理解。设计项不能当作当前实现事实。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="positioning"></a>
## 定位与事实边界

文档明确自称历史设计，并用“事实／设计／未实现”区分提案时的状态；当前能力应以后续复审与状态记录为准。[历史设计声明 ↗](../../../docs/implementation/code-knowledge-design.md#L1 "支持本文是历史提案且设计项不能视作当前实现。")

<a id="model"></a>
## 领域模型与生命周期

方案规划仓库、快照、文件、符号、结构边和派生理解，且不替换既有 Source、Revision、Fragment；符号仍锚定不可变 fragment。[领域模型叠加原则 ↗](../../../docs/implementation/code-knowledge-design.md#L82 "支持代码领域对象是既有证据链上的叠加模型。") 结构边区分 parser、seed、llm 来源及 confirmed、candidate、stale、missing 状态。[结构边状态与来源 ↗](../../../docs/implementation/code-knowledge-design.md#L154 "支持 CodeEdge 的端点、生命周期状态和 parser、seed、llm 来源区分。") 端点无法解析时保留 missing，快照、文件或 seed 变化时翻 stale，不静默删除。[锚定与失效生命周期 ↗](../../../docs/implementation/code-knowledge-design.md#L214 "支持 fragment 固定、无法解析保留 missing，以及变化后翻 stale 而非删除。")

<a id="delivery"></a>
## 解析选择与阶段交付

PoC 选择已安装的 TypeScript Compiler API 与 Vue SFC 编译器进行单文件确定性解析；跨文件类型感知调用、SCIP 和多语言解析明确未实现。[确定性解析选择 ↗](../../../docs/implementation/code-knowledge-design.md#L366 "支持 TS/Vue PoC 的工具选择、单文件范围及跨文件与多语言限制。") 交付被拆为存储、API、Web、派生理解及助手/Lark 阶段；Stage 5 在该设计中仍是后续。[阶段化交付计划 ↗](../../../docs/implementation/code-knowledge-design.md#L441 "支持各层被规划为分阶段交付，且助手、检索与 Lark 通路当时仍未实现。")
