# KnowledgeBatch.v1 输出结构合同

该 JSON Schema 定义代码分析角色输出的批次、文档、章节、引用与问题结构，通过必填字段、枚举、长度、正则和额外属性限制约束结果形态。它是格式合同，不足以证明宿主已执行语义复核或交叉引用校验。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="batch-document"></a>
## 批次、文档与章节边界

根对象把 `schema_version` 固定为 1，`documents` 数量限定为 1 至 16；文档分类覆盖架构、进展、实现、测试、配置、研究和对话等知识视图。[批次规模与文档属性 ↗](../../../packages/agent-runtime/roles/code-analyst/1/output.schema.json#L1 "支持根版本、文档数量、基础字段定义及分类枚举的说明。") 每个文档必须包含 key、标题、摘要、分类、章节、引用和问题，并禁止未声明字段；根对象也只允许版本和文档列表。[文档与根对象必填约束 ↗](../../../packages/agent-runtime/roles/code-analyst/1/output.schema.json#L209 "直接支持每个文档的七个必填字段、文档禁止额外属性，以及根对象必填字段和额外属性限制。")

章节数量为 1 至 20，章节 key 使用受限标识符格式，标题和正文均有长度上限，且章节对象禁止额外属性。[章节结构约束 ↗](../../../packages/agent-runtime/roles/code-analyst/1/output.schema.json#L48 "支持章节数量、键格式、正文长度、必填字段和禁止额外属性的论断。") 这些约束提供稳定的机器接口，但只能验证形状，不能证明内容真实、完整或与材料一致。

<a id="evidence-contract"></a>
## 引用合同与证据定位

每份文档至少包含一个引用。引用关系只能取预定义枚举，目标限于材料或文章，并可记录材料行号或文章章节；`quote` 必须存在，约定由宿主根据固定范围抽取原文。[引用对象与目标定位 ↗](../../../packages/agent-runtime/roles/code-analyst/1/output.schema.json#L78 "支持引用数量、关系枚举、目标类型、定位字段、必填项及空 quote 约定的说明。")

因此该合同能表达“论断指向何处”，却不能单独判断选定行段是否真正支持附近论断，也不能证明宿主已完成原文复制和独立语义复核。

<a id="uncertainty"></a>
## 问题与未决事项

`questions` 最多二十项，每项必须包含问题、原因、下一步、阻塞状态和关联引用键，使不确定性能够显式进入后续工作流。[待确认问题结构 ↗](../../../packages/agent-runtime/roles/code-analyst/1/output.schema.json#L166 "支持问题条目的数量、字段类型及必填项要求，并表明 citationKeys 仅被定义为字符串数组。") 不过 `citationKeys` 在 schema 中只是字符串数组，没有声明其值必须匹配同一文档中的 citation key；目标覆盖、正文标记与引用使用情况也需要宿主另行校验。
