# Code Wiki 模块图聚合与导航辅助函数

modules.ts 是无 Vue/DOM 依赖的纯函数层：将代码文件归入稳定模块、聚合可信 import 边、匹配模块理解、解析下钻目标，并统一生成人读标签与不可操作原因。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="graph-aggregation"></a>
## 模块图聚合

文件路径先交给 contracts 中的 `moduleForPath` 映射到稳定桶；已删除文件不进入图，符号数按所属文件累计，模块及文件按名称排序以获得确定输出。[稳定模块归类与节点统计 ↗](../../../apps/web/src/codewiki/modules.ts#L7 "支持已删除文件过滤、路径归类、符号计数及确定性排序流程。") 模块依赖只采纳 `edgeKind=imports` 且两端文件都已解析的仓库内边，同模块边和外部/缺失目标被丢弃。相同模块对合并计数与 evidence；若后续边为 candidate 或 missing，聚合状态会被该值覆盖，但这里没有定义多种非确认状态的严格优先级。[模块依赖边聚合规则 ↗](../../../apps/web/src/codewiki/modules.ts#L89 "支持只采纳已解析 imports、过滤同模块边并合并证据和状态。")

<a id="understanding-and-outline"></a>
## 大纲与模块理解匹配

文件大纲只保留函数、类、方法、组件、路由、测试、接口和类型，并按起始行排序；变量等符号不会进入该紧凑视图。[紧凑符号大纲 ↗](../../../apps/web/src/codewiki/modules.ts#L117 "支持符号种类筛选和按源码起始行排序的说明。") 模块理解候选限定为 module 类型、curated-seed 或 model-generated 来源、未 stale，且状态为 seed/generated/verified。匹配会检查模块内每一个文件，并选覆盖路径的最长 targetId 前缀，避免浅层文件遮蔽更具体的目录理解；同前缀选择还受 seed 标记和生成时间排序影响。[模块理解最长前缀匹配 ↗](../../../apps/web/src/codewiki/modules.ts#L149 "支持候选过滤、检查所有文件及最长目录前缀优先策略。")

<a id="navigation-and-labels"></a>
## 边下钻与人读展示

`resolveEdgeTarget` 把同文件目标视为不可解析跳转，而较新的 `edgeDrillTarget` 会把同文件符号解析成 symbol frame，跨文件符号则转成带行号的 file frame；同文件的纯文件边仍不下钻，缺失映射返回 none。[关系目标与下钻目标解析 ↗](../../../apps/web/src/codewiki/modules.ts#L124 "支持两种解析函数对同文件符号、跨文件和缺失目标的不同处理。") 标签函数优先 DTO 的 display 字段，再退回文件名、路径或符号名，绝不以内部 id 充当可见文本；不可操作原因优先使用服务端 reason，否则为 missing/stale 给出人读回退。[DTO 优先的人读标签 ↗](../../../apps/web/src/codewiki/modules.ts#L222 "支持显示字段回退策略以及 missing/stale 的不可操作原因。")

<a id="boundaries"></a>
## 能力边界

本文件只聚合解析器已经提供的结构，不读取源码，也不证明 calls 或 imports 的语义正确性；外部包依赖被有意排除在模块图外。`fileByPath` 还是线性精确匹配，不处理路径别名或 revision 间身份续接。两套 target 解析函数对同文件符号的语义不同，调用方必须选择正确合同，不能互换推断。[文件路径精确查找与下钻合同 ↗](../../../apps/web/src/codewiki/modules.ts#L184 "支持路径查找仅为精确线性匹配，并界定下钻只基于已有 CodeEdge 数据。")
