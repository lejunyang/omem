# Code Wiki 模块图与导航辅助逻辑

该文件提供与 Vue、DOM 解耦的纯函数：按共享路径规则构建稳定的模块依赖图，整理符号提纲，匹配模块理解，解析代码边的下钻目标，并确保界面使用人类可读标签。当前仍有聚合状态优先级、stale 边交互语义和测试覆盖范围等待确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="module-aggregation"></a>
## 模块归类与依赖图聚合

文件先把未删除的仓库文件按共享的 `moduleForPath` 规则归入模块桶，建立文件到模块的映射并统计符号数；桶内文件按路径排序，模块按标识排序，因此相同输入会形成稳定的模块列表。[模块节点构建与稳定排序 ↗](../../../apps/web/src/codewiki/modules.ts#L60 "支持过滤已删除文件、统计模块文件与符号数量以及稳定排序的流程说明。") 路径分组并非本文件私有逻辑：web、ui、contracts、agent-runtime、Lark、服务端子目录和 scripts 等映射由 contracts 包统一提供，其他路径归入 `other`。[共享仓库路径分组规则 ↗](../../../packages/contracts/src/code-modules.ts#L1 "支持模块归类由 contracts 包统一提供及各主要路径的映射与兜底行为。")

模块依赖只聚合具备源、目标文件定位的 `imports` 边，并排除模块内部边；相同模块对之间的导入会合并计数和证据。[跨模块导入边聚合 ↗](../../../apps/web/src/codewiki/modules.ts#L89 "支持仅聚合可定位的跨模块 imports 边、合并计数与证据，以及状态覆盖行为的说明。") 未解析的外部包导入不会进入模块图，而应保留在文件级视图。聚合时 candidate 或 missing 会直接覆盖已有状态，二者并存时尚无显式严重度规则。

<a id="outline-understanding"></a>
## 代码提纲与模块理解匹配

`outlineSymbols` 仅保留函数、类、方法、组件、路由、测试、接口和类型等适合构成阅读提纲的符号，并按源码起始行排序；变量、字段等其他节点不会出现在该提纲中。[符号提纲筛选与排序 ↗](../../../apps/web/src/codewiki/modules.ts#L117 "支持提纲允许的符号类别及按源码起始行排序的说明。")

模块理解先过滤出未过期、来源为策展 seed 或模型生成、且状态为 seed、generated 或 verified 的记录，再检查模块内任一文件是否落在目标目录前缀下，最终选择最长匹配前缀。[模块理解选择算法 ↗](../../../apps/web/src/codewiki/modules.ts#L149 "支持理解项的资格过滤、全部文件前缀匹配、最长前缀选择和同长度候选决胜方式。") 这避免浅层文件遮蔽更具体的目录说明。候选会先按 seed 标记和生成时间排序；相同前缀长度不会替换既有结果，因此排序同时决定同长度候选的选择。

<a id="navigation-labels"></a>
## 边下钻、路径回查与可见标签

边下钻优先解析目标符号：同文件符号进入具体 symbol/range 帧，跨文件符号进入目标文件并携带行号；只有跨文件的文件目标可直接下钻，纯同文件文件边及外部或缺失目标返回 `none`。[边的下钻目标解析 ↗](../../../apps/web/src/codewiki/modules.ts#L184 "支持符号优先、同文件符号下钻、跨文件导航以及不可导航目标边界。") 另一个 `resolveEdgeTarget` 会把同文件目标统一标为不可解析，因此两个辅助函数对同文件符号边的语义不同，调用方需按界面场景选择。[基础边目标解析 ↗](../../../apps/web/src/codewiki/modules.ts#L131 "支持 resolveEdgeTarget 将同文件目标标为不可解析，并说明其与 edgeDrillTarget 的语义差异。") `fileByPath` 则以精确仓库相对路径把关系记录恢复为代码文件。[按仓库路径回查文件 ↗](../../../apps/web/src/codewiki/modules.ts#L215 "支持通过精确仓库相对路径把关系目标恢复为代码文件的说明。")

可见文本遵循 DTO 优先策略：文件、路径和符号优先使用服务端提供的 display 字段，再退回 basename、原始路径或名称，最终使用“未命名”占位，避免把内部 ID 渲染为标签。[人类可读标签回退 ↗](../../../apps/web/src/codewiki/modules.ts#L222 "支持 display 字段优先、可读原始字段回退和禁止内部 ID 成为界面标签的合同。") 边的原因与禁用状态优先采用 `actionable` 和 `reason`；兼容旧 DTO 时，missing 和 stale 都可推导提示，但只有 missing 会被 `edgeDisabled` 自动禁用。[边原因与禁用判定 ↗](../../../apps/web/src/codewiki/modules.ts#L239 "支持新旧 DTO 的兼容逻辑，以及 stale 有原因提示但不会自动禁用的边界判断。")

<a id="api-context"></a>
## 输入 DTO 的接口背景

这些纯函数依赖 review API 的代码文件、符号、边和理解项 DTO；该 API 客户端服务于本机 repo-review 的读取、浏览和同步界面，类型形状与服务端保持一致。[仓库评审 API 客户端边界 ↗](../../../apps/web/src/review-api.ts#L1 "说明输入 DTO 所属客户端面向本机 repo-review 读取、浏览与同步，并与服务端类型保持一致。") 这也解释了本文件为何同时兼容较新的 display/actionable 字段与旧状态回退：辅助逻辑处在服务端数据和 Code Wiki 展示、导航之间。
