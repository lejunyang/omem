# 任务流状态、跟进信息与操作命令合同

该文件以 Zod 统一描述任务状态、后续跟进信息和任务操作命令的运行时数据边界，并仅为状态、跟进信息和动作导出对应的 TypeScript 类型；命令本身未在此导出推导类型。它负责枚举、字段形状、长度、时间格式及时区合法性校验，不实现状态迁移、调度、并发冲突处理或请求去重。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="status-and-actions"></a>
## 状态与动作词汇

合同将任务状态限定为 `open`、`waiting`、`done`、`cancelled`，并将操作动作限定为 `complete`、`reopen`、`reschedule`、`wait`、`snooze`、`cancel`。状态 Schema 与动作 Schema 分别导出了 `TaskStatus` 和 `TaskAction` 类型，使这两组运行时枚举与静态类型保持同源。[任务状态与操作动作定义 ↗](../../../packages/contracts/src/task-flow.ts#L3 "支持任务状态和动作的允许值，并证明仅分别导出了 TaskStatus 与 TaskAction 类型。") 不过，状态与动作是不同维度；本文件没有规定动作允许从哪些状态发起，也没有定义非法迁移的处理方式。

<a id="follow-up"></a>
## 跟进与时间语义

`taskFollowUpSchema` 描述等待对象、下次检查时间、暂停截止时间、原始时间表达式及时区，并导出 `TaskFollowUp` 类型。两个时间点必须是带偏移量的 ISO 日期时间或 `null`；时区须为非空、长度受限且能被运行环境识别的 IANA 时区。严格对象模式还会拒绝额外字段。[任务跟进字段及校验规则 ↗](../../../packages/contracts/src/task-flow.ts#L5 "支持跟进字段、ISO 时间格式、IANA 时区校验、严格对象边界以及 TaskFollowUp 类型导出的说明。") 该合同只校验表示形式，不负责解析自然语言时间、安排提醒，也未约束多个时间字段的先后关系。

<a id="command-boundary"></a>
## 命令输入边界与未定义语义

任务命令必须包含动作、最小为 1 的整数 `expectedVersion` 和非空 `requestId`；`dueAt` 与 `dueExpression` 缺省为 `null`，`followUp` 可省略或显式为 `null`，且整个对象拒绝未声明字段。[任务命令结构 ↗](../../../packages/contracts/src/task-flow.ts#L17 "支持命令必需字段、默认空值、可选跟进信息和严格校验，并表明文件末尾没有导出由命令 Schema 推导的类型。") 这里导出了 `taskCommandSchema`，但没有像前三类合同那样声明由其推导的 `TaskCommand` 类型。字段名称暗示版本控制与请求识别用途，但仅凭本材料无法确认乐观锁、幂等去重、动作相关字段组合或状态迁移矩阵的消费端行为。
