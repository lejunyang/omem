# 其他模块专题 1：服务端治理与代码知识验证

本专题串联助手模型接入、受控写入、记忆变更门控、Lark 消息入口与代码知识快照。当前服务层已具备可运行的证据、收据和投递切片，但主要验证仍依赖进程内模型、协议夹具、临时 SQLite 与本地 HTTP 注入；真实外部 CLI、平台网络、并发恢复及迁移故障仍需独立验收。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="assistant-runtime"></a>
## 助手接入与运行时治理

助手模型适配层只接受 ACP profile；缺少配置或误用一次性 CLI 传输时明确报告模型不可用，不生成伪答案。历史上下文默认保留最近十轮，并把每轮助手结果裁到 500 字符。[ACP 模型路由边界 ↗](../../../apps/server/src/assistant/acp-model.ts#L12 "支持仅允许 ACP profile，以及缺配置或 CLI 传输时诚实失败且不生成伪答案。")[助手历史上下文裁剪 ↗](../../../apps/server/src/assistant/acp-model.ts#L47 "支持默认保留最近十轮及每轮助手结果最多 500 字符的规则。") 模型返回的回答、引用与任务请求只是结构化提案，服务端仍会重新检查证据可见性和所有者来源。[助手回复与工具调用合同 ↗](../../../apps/server/src/assistant/runtime.ts#L23 "说明模型引用和任务调用仍需服务端重新治理，不能自行取得写权限。")

运行时测试进一步证明，明确的“记一下”可以产生任务，而普通咨询即使收到模型的创建请求也保持零写入；跨轮证据可支撑后续任务，不存在的引用或取消后迟到的请求都会被拒绝。[任务意图、跨轮证据与取消栅栏 ↗](d9fa29eea3911885a9f042393930e254ba547818532ede0c208775d573836ec6.md#intent-and-write-governance "支持明确任务意图与咨询零写入，并证明跨轮证据、不存在引用和取消后迟到写入的治理结果。") ACP fixture 还覆盖模型与推理强度协商、思考过滤、权限默认拒绝、超时及主动取消，但不代表真实外部 CLI 已通过相同验收。[ACP 协议与生命周期测试 ↗](../../../apps/server/tests/agents.test.ts#L41 "支持模型协商、思考过滤、权限拒绝、超时和主动取消，同时界定其为受控 fixture。")

<a id="memory-and-messaging"></a>
## 记忆门控与消息入口

记忆层保留原始材料并谨慎晋升：信息不足的题外材料仍可检索但不进入活动记忆；重复陈述链接既有记录，相反主张则记录为争议。[延后、去重与争议保留 ↗](2f5ac0f7ab3d44cd9970092c8d81ae1afe993064207971980c2decd3784417d4.md#defer-deduplicate-dispute "支持题外材料延后、重复陈述链接既有记忆以及相反主张记录为争议。") 当新来源试图覆盖另一来源支撑的活动知识时，测试明确要求进入 `awaiting_decision`，旧知识保持活动且不被静默改写；这替代了此前缺少直接证据的概括。[跨来源覆盖决策门控 ↗](../../../apps/server/tests/attention-gate.test.ts#L135 "直接支持跨来源 supersede 活动知识时进入待决、旧知识不被静默覆盖。") 同源变化若实际波及 11 条依赖，也会因超过自动应用上限进入待决。[大范围依赖影响门控 ↗](../../../apps/server/tests/attention-gate.test.ts#L265 "支持系统自行算出同源变更影响 11 条记忆，并因超过上限进入待决。") 来源 revision 更新后仅登记为 `needs_review`，受影响旧记忆退出活动检索，不能把失效登记视为复核完成。[来源更新后的待复核状态 ↗](../../../apps/server/tests/attention-gate.test.ts#L209 "支持刷新记录进入 needs_review、列出影响范围并使旧记忆退出活动检索。")

Lark 入口只有在有效绑定下才把外部身份映射为规范 owner，未绑定成员不会被当作所有者任务来源。[Lark 所有者身份映射 ↗](0f653da3e4b41e6c666f9d7f3d27761507400cd89d13f91540cf0ab4548ad751.md#lark-owner-resolution "支持已绑定身份映射为规范 owner，未绑定成员不获得所有者自动应用权限。") 已绑定私聊会创建并关联一条回复投递意图。[Lark 私聊回复投递意图 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L773 "支持已绑定私聊进入助理、创建一条飞书投递意图并关联会话轮次 outbox。") 相同事件再次投递后，测试仅确认 `delivery_intents` 数量仍为一，因此证据支持“回复投递意图未重复创建”，不能据此断言模型调用、会话轮次、任务或整个入口的其他副作用均具幂等性；此前“直接证明入口幂等”的结论已被替代。[Lark 重复事件的投递意图断言 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L847 "仅支持相同事件重复处理后 delivery_intents 数量仍为一；未断言模型调用、轮次、任务或其他副作用不重复。") 这些场景使用本地确定性接线，没有真实 socket 或平台送达证据。

<a id="code-knowledge"></a>
## 代码知识作为固定证据的派生视图

代码知识不是第二套事实库：评审同步先捕获正文，代码同步再解析 TS/Vue，并把结构投影到同一隔离 SQLite；相同仓库、提交、脏状态与内容哈希组合会复用快照。[代码同步与快照身份 ↗](../../../apps/server/src/code/sync.ts#L1 "说明代码结构依赖已捕获 fragment，并支持内容寻址快照的幂等复用。") 结构失效方式需要区分：消失的符号保留旧 `snapshot_id`，只是从当前 head 视图中过滤；最新解析未重新产生或触及已移除文件的边才标记为 `stale`，而不是所有旧结构统一转为 stale。[符号与边的不同失效语义 ↗](../../../apps/server/src/code/store.ts#L1 "直接区分消失符号从当前视图过滤与未重新产生或触及移除文件的边标记 stale。")

A→B→A 用例证明当前指针可回到旧快照，同时保留 B 的历史图；源码 HTTP 接口按指定快照返回固定内容，缺少对应固定材料时返回 404，不回退读取实时磁盘。[代码快照与固定源码读取 ↗](7bb343b839e682e5dd46f55bc593ec153e9de5997b56ce442afddcd11eb1f456.md#flow "支持 A-B-A 快照回切、历史保留，以及 HTTP 按指定快照读取不可变源码的流程。") 导出只接受当前快照中状态成功、非 seed 且未过期的模型理解，并记录依赖与稳定符号定位。[代码理解产物导出约束 ↗](../../../apps/server/src/code/artifacts.ts#L38 "支持仅导出当前、成功、非 seed、未过期的模型结果，并记录依赖和符号定位。") 产物测试还覆盖跨库恢复、重复恢复幂等、伪造定位拒绝及重新捕获源码变化后的过期处理。[代码理解产物恢复测试 ↗](../../../apps/server/tests/code-artifacts.test.ts#L28 "支持成功导出、跨库恢复、重复恢复、伪造定位拒绝及输入变化后的过期处理。")

<a id="progress-and-limits"></a>
## 当前进展与验证边界

现有测试已经分别验证若干可运行切片：任务写入会产生真实 `application_receipts`，已完成轮次不会在恢复时重复调用模型；[应用收据与未完成轮次恢复 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L621 "直接支持任务写入生成 application_receipts，且已完成轮次不会被恢复或再次调用模型。") Lark 私聊回复会写入 `delivery_intents` 并把 outbox 标识关联回会话轮次；[Lark 私聊回复投递意图 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L773 "支持已绑定私聊进入助理、创建一条飞书投递意图并关联会话轮次 outbox。") 代码快照与固定源码可经评审 HTTP 接口读取。[代码快照与固定源码读取 ↗](7bb343b839e682e5dd46f55bc593ec153e9de5997b56ce442afddcd11eb1f456.md#flow "支持 A-B-A 快照回切、历史保留，以及 HTTP 按指定快照读取不可变源码的流程。") 因而“收据、投递意图和快照接口”各自有直接证据，而不再由无关引用合并推断。

边界仍然明确：模型侧主要使用进程内脚本或仓库 ACP fixture，Lark 侧是无真实网络的本地装置；[ACP 协议与生命周期测试 ↗](../../../apps/server/tests/agents.test.ts#L41 "支持模型协商、思考过滤、权限拒绝、超时和主动取消，同时界定其为受控 fixture。")[Lark 重复事件的投递意图断言 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L847 "仅支持相同事件重复处理后 delivery_intents 数量仍为一；未断言模型调用、轮次、任务或其他副作用不重复。") 代码产物测试只覆盖单个合法、伪造或过期产物，快照往返也发生在同一 Store 生命周期内。[代码理解产物恢复测试 ↗](../../../apps/server/tests/code-artifacts.test.ts#L28 "支持成功导出、跨库恢复、重复恢复、伪造定位拒绝及输入变化后的过期处理。")[代码快照与固定源码读取 ↗](7bb343b839e682e5dd46f55bc593ec153e9de5997b56ce442afddcd11eb1f456.md#flow "支持 A-B-A 快照回切、历史保留，以及 HTTP 按指定快照读取不可变源码的流程。") 真实 Agent CLI 鉴权与能力发现、飞书最终送达、跨进程竞争、重启后的快照恢复、混合坏产物隔离及迁移失败回滚，均不能由当前材料宣称完成。
