# other · 模块理解 · 专题 1

本专题汇集服务器中模型进程、助手治理、知识变更、外部投递与 Code Wiki 的基础保障。修订后的结论区分了已直接验证的行为与仍缺少夹具的边界：显式取消可阻止迟到任务落库，但新消息和超时尚未验证同等强度的迟到提交；代码 DTO 也只是对实际返回的失效边施加不可操作断言。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="agent-boundary"></a>
## 模型与进程边界

Agent 进程在过滤部分敏感环境变量后以 `shell:false` 启动，并为进程退出、空闲超时和 AbortSignal 取消建立收敛路径。[Agent 子进程生命周期 ↗](../../../apps/server/src/agents.ts#L32 "支持敏感环境过滤、无 shell 启动、进程退出错误、超时和取消的具体实现边界。") ACP 线协议总输出和回答文本分别受预算限制；权限请求不会自动授权，补充输入请求也会被拒绝。[ACP 请求与输出限制 ↗](../../../apps/server/src/agents.ts#L151 "支持线协议输出预算、权限和补充输入默认拒绝，以及回答字符上限。") 会话建立后，配置的模型与推理强度必须出现在服务端发现的选项中，随后才会设置配置并提交 prompt。[模型能力协商 ↗](../../../apps/server/src/agents.ts#L301 "支持模型和推理强度从会话选项中发现、校验并设置，以及提交 prompt 前的能力检查。")

助手模型适配器只接受 ACP profile；缺少配置或传入 CLI transport 时返回模型不可用，不生成伪答案。它截取有限历史与证据、要求单一 JSON 回答，并解析引用和可选任务调用。[助手 ACP 模型适配器 ↗](../../../apps/server/src/assistant/acp-model.ts#L42 "支持 ACP 专用路由、历史与证据裁剪、结构化请求、取消传播和回答解析流程。") 这替代了旧稿把所有进程约束归入单一启动代码范围的宽泛结论。

<a id="assistant-governance"></a>
## 从回答到受治理写入

助手先区分明确任务请求与普通咨询：明确的 owner 指派可创建任务，咨询即使收到模型的 `create_task` 也保持零写入；模型不可用则把轮次保留为可重试状态。[任务意图与模型失败测试 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L98 "验证明确任务可写入、咨询保持零写入，以及模型不可用轮次可重试且不生成伪答案。") 群聊默认不提供证据，注入策略后仅允许当前群范围材料，私人内容不会进入群聊回答。[群聊证据隔离测试 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L238 "验证群聊默认无证据、注入策略后的范围过滤，以及私人材料不进入群聊回答。") 会话修正另有独立作用域测试，只有同一会话能看到修正。[会话修正作用域测试 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L519 "直接支持修正只进入同一会话 trusted context、不会泄漏到其他会话。") Lark 身份链路还证明绑定 owner 可规范化并自动应用，而普通成员材料因 owner 未验证不能自动应用。[Lark owner 身份解析测试 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L253 "支持绑定 owner 的规范身份可自动应用，而普通群成员因 owner 未验证不能自动应用。")

相同传输事件保持幂等；新消息可中断会响应 abort 的旧模型调用，忽略 abort 的永久挂起模型也会超时收敛，两者均保持零任务。[幂等、新消息取消与超时测试 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L362 "支持事件幂等、新消息中断会响应取消的模型，以及永久挂起模型超时后零任务收敛；同时界定这些用例未构造迟到工具调用。") 只有显式取消场景直接构造了模型迟到返回任务调用并验证零写入；因此不能把同等强度的迟到提交围栏推广到新消息或超时场景。模型恢复后，pending 轮次可由重试推进完成。[显式取消围栏与重试恢复 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L598 "直接验证取消后迟到返回的任务调用无法落库，并支持模型恢复后重试 pending 轮次。")

<a id="change-delivery"></a>
## 知识变更与外部投递

知识提案按证据充分性和冲突分流：不充分材料延后但仍可检索，重复事实链接既有知识，相反主张记录争议，跨来源覆盖不会静默替换活跃结论。[知识延后、去重与冲突测试 ↗](../../../apps/server/tests/attention-gate.test.ts#L117 "验证不充分材料延后、重复事实复用既有知识、相反主张记录争议及跨来源覆盖需决策。") 来源 revision 更新会记录受影响知识并使其退出活跃检索，但结果明确停在 `needs_review` 与 `not_implemented`；高波及变更或整批超限会进入决策门禁。[来源刷新与影响门禁测试 ↗](../../../apps/server/tests/attention-gate.test.ts#L209 "支持来源更新使知识失效、自动复核尚未实现，以及单项和批量高影响变更进入门禁。") 这意味着旧结论已被标为失效，而自动复核、引用迁移和重新激活仍未闭环。

外部投递采用取消扫描与发送端复核两层防线：未发送卡片被撤销，取消后重新出现的 pending 意图也不会发送；已投递历史和仍在发送的记录保持原状，不伪装成已撤回。[取消后的投递隔离测试 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L191 "验证未发送卡片撤销、迟到队列项由发送端拦截，并保留已投递及发送中状态。")

<a id="code-knowledge"></a>
## 代码知识的不可变依据

Code Wiki 通过显式 head 管理不可变快照：工作树从 A 变为脏 B 再恢复 A 时会复用原快照，历史 B 仍可读取；源码接口按指定 snapshot 返回固定内容，不回退到实时磁盘猜测。[代码快照生命周期测试 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L60 "支持显式 head、快照复用、历史可读性和源码按指定快照固定返回。") 模型理解制品可跨数据库恢复，但伪造定位会被拒绝，输入变化会令制品过期。[代码理解制品重建测试 ↗](../../../apps/server/tests/code-artifacts.test.ts#L12 "验证固定源码证据、理解制品跨库恢复、伪造定位拒绝及输入变化后的过期处理。")

API 同时保留内部操作键和人类展示字段；DTO 测试会对其实际返回的 `missing` 或 `stale` 图边断言 `actionable=false`，但夹具没有明确证明一定生成了这两类边，因此不把它表述为完整状态覆盖。[代码知识展示合同测试 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L31 "支持内部操作键与人类标签分离，并准确限定为对当前响应中出现的 missing 或 stale 边执行不可操作断言。") 旧单主键侧表迁移后，符号、关系和历史图仍可查询。[代码侧表历史迁移测试 ↗](../../../apps/server/tests/code-knowledge-migration.test.ts#L22 "验证旧符号和图边迁入新结构后记录未丢失，历史快照图仍可查询。") 生成预算则按 UTF-8 保守估算输入，并把输出及预留共同纳入已发现模型窗口校验。[代码生成上下文预算测试 ↗](../../../apps/server/tests/code-budget.test.ts#L5 "支持 UTF-8 保守估算、宿主配置校验，以及输入、输出与预留共同受模型窗口约束。")
