# 服务端治理与代码知识的可追溯验证

服务端通过运行时合同、注意力门控和发送侧守卫约束模型及外部副作用；代码知识建立在已捕获原文、不可变快照和可校验产物之上。现有测试覆盖主要单进程流程，但真实外部 CLI、并发故障、决策执行和部分恢复场景仍需独立验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="assistant-governance"></a>
## 模型只能提议，服务端决定是否写入

助理回复将自然语言回答、实际依赖的证据片段与结构化任务请求分开；任务请求还要由服务端重新检查证据可见性和所有者来源，模型不能自行取得写权限。参考 [助理回复与任务请求合同 ↗](../../../apps/server/src/assistant/runtime.ts#L23 "支持回答、引用与工具请求分离，以及任务写入必须由服务端重新治理的论断。")

明确的“记一下”可以创建任务，而普通咨询即使收到模型的创建请求也保持零写入，使“生成内容”和“改变用户数据”成为两条不同的信任路径。参考 [任务意图与零写入测试 ↗](../../../apps/server/tests/assistant-runtime.test.ts#L98 "支持明确指令可以创建任务，而普通咨询中的模型写入请求会被拒绝。") Agent 传输层还验证模型与推理强度协商、过滤私有思考、默认拒绝权限请求，并为超时和主动取消提供可观察错误。参考 [Agent 协商与取消测试 ↗](../../../apps/server/tests/agents.test.ts#L41 "支持能力协商、思考过滤、权限拒绝、超时及主动取消的可观察行为。")

<a id="change-and-delivery-gates"></a>
## 高风险变化与外部投递采用双层门控

知识更新不会因模型判断“受支持”就无条件覆盖现有内容。跨来源替换活动知识时，旧知识继续保持有效，新提案进入待决状态，避免静默改写。参考 [跨来源覆盖门控 ↗](../../../apps/server/tests/attention-gate.test.ts#L135 "支持冲突更新进入待决状态且不静默覆盖现有活动知识。") 来源产生新 revision 后，受影响记忆会进入待复核范围并退出活动检索；失效登记本身不代表 extractor 与独立 verifier 已经完成。参考 [来源刷新与知识失效 ↗](../../../apps/server/tests/attention-gate.test.ts#L209 "支持来源更新记录影响范围、标记待复核并让旧记忆退出活动检索。")

外部通知采用相似的诚实边界：取消标注会话后，尚未发送的意图被取消，worker 不再调用消息适配器。参考 [取消后停止卡片发送 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L191 "支持会话取消后待发送意图进入取消状态，worker 不再发送消息。") 如果取消后又出现待发送记录，发送侧仍会检查会话状态并抑制投递，形成取消清扫与消费检查两道防线。参考 [发送侧取消兜底 ↗](../../../apps/server/tests/annotation-cancel-delivery.test.ts#L257 "支持取消后重新出现的待发送意图仍会被消费者拦截。")

<a id="code-knowledge-flow"></a>
## 代码知识依附固定原文与不可变快照

代码结构不是第二套事实库：同步器解析 TypeScript 与 Vue，并将结构投影到已经捕获的 fragment；快照身份由仓库、提交、脏状态和内容哈希共同决定，相同输入复用快照，输入变化才产生新快照。参考 [代码结构投影与快照身份 ↗](../../../apps/server/src/code/sync.ts#L1 "支持代码结构依赖已捕获 fragment，并说明相同输入复用快照、变化输入产生新快照。")

结构对象具有不同的历史语义：最新解析未重新生成的边会转为 `stale`，消失的符号则保留在旧快照中并退出当前 head 视图，而不是统一改成过期状态。参考 [符号与边的历史保留规则 ↗](../../../apps/server/src/code/store.ts#L13 "支持区分结构对象的失效语义：消失符号留在旧快照并退出当前视图，未重新生成或关联已移除文件的边转为过期。") A→B→A 测试进一步证明当前版本由显式指针决定：回到相同输入时复用 A，较晚产生的 B 仍可作为历史图读取。参考 [A-B-A 快照生命周期 ↗](../../../apps/server/tests/code-knowledge-snapshot.test.ts#L68 "支持显式当前指针、相同输入复用及历史快照继续可读。")

生成式代码理解的导出入口只接受当前快照中状态为成功、非 seed 且未过期的模型结果，并记录依赖和稳定符号定位。参考 [代码理解导出约束 ↗](../../../apps/server/src/code/artifacts.ts#L38 "直接支持导出只接受当前快照中的成功、非 seed、未过期模型结果，并记录依赖及符号定位。") 恢复测试证明合法产物可跨库重建，伪造定位会被拒绝，源码变化后旧产物会转为过期并退出当前模型理解列表。参考 [理解产物恢复与失效 ↗](../../../apps/server/tests/code-artifacts.test.ts#L21 "支持固定源码证据、跨库恢复、伪造定位拒绝及源码变化后的过期处理。")

<a id="progress-and-limits"></a>
## 当前可用切片与验证边界

对外 DTO 同时保留路由所需的操作键和人类可读字段：快照、文件与符号具有展示名称和深链；缺失或过期图边在被检查到时必须不可操作。不过图边断言只在响应确实含边时执行，尚不能证明最小源码场景稳定产生边。参考 [代码知识 DTO 检查 ↗](../../../apps/server/tests/code-knowledge-dto.test.ts#L52 "支持快照、文件、符号的人类可读字段与深链，同时表明图边检查是条件执行。")

服务端 HTTP 测试已走通“原始承诺—注入 `supported` assessment 后的策略评估—自动应用—任务查询—通知回执”的单进程链路；语义结论由测试请求直接提供，并未运行 extractor 或独立 verifier。该用例证明来源已验证的所有者事项在此评估前提下可以形成任务实体、证据关联和通知回执。参考 [注入评估后的事项应用链路 ↗](../../../apps/server/tests/app.test.ts#L247 "支持测试直接提供 supported assessment，随后验证策略评估、任务应用、证据关联和通知回执。") 当前证据仍主要来自临时 SQLite、fixture 模型和伪消息适配器；真实 Agent CLI、飞书网络、多 worker 竞争、决策批准后的批量应用及崩溃恢复不能由这些用例直接推出。
