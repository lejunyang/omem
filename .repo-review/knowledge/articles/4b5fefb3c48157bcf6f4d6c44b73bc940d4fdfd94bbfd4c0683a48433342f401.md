# 仓库知识分析、综合与发布编排

该脚本把仓库材料接入共享 KnowledgePipeline，使用显式 ACP 模型配置完成文件分析、模块与主题综合，发布已复核文章并维护覆盖报告、知识计划和索引。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="configuration"></a>
## 模型配置与运行边界

脚本从 Review 专用模型配置建立 profile，明确要求 ACP transport 与命令；并把并发限制在 1–6。可用 `--only` 或 `--target` 缩小路径范围，指定目标时也会进入 files-only 模式。[Review 模型与目标配置 ↗](../../../scripts/review-knowledge.ts#L20 "支持 ACP 配置要求、profile 构造、并发边界和目标筛选模式。") 运行数据和 staging 位于 `.repo-review/runtime`，发布文章则复制到知识资产目录。

<a id="pipeline"></a>
## 共享知识管线与发布

`KnowledgePipeline` 组合 Review 知识仓库、角色网关、运行请求仓库和预算配置；每次发布先写 staging，再复制 JSON 与 Markdown 资产。[共享知识管线与文章发布回调 ↗](../../../scripts/review-knowledge.ts#L32 "支持角色运行时、预算、并发、运行请求仓库和 staging 到资产目录的发布流程。") 启动后先执行 Review 同步、恢复知识、代码同步和文章恢复，再从捕获材料中筛选目标；没有匹配材料会立即失败。[同步、恢复与材料清单 ↗](../../../scripts/review-knowledge.ts#L38 "支持 Review 同步、代码同步、文章恢复、目标过滤和空目标失败等准备过程。")

<a id="analysis"></a>
## 分析上下文与综合层级

文件分析的附加上下文来自显式文档链接，以及代码图中触及目标文件的 import 边；额外 import 材料最多取四项，这些只是提供给模型的候选上下文。[关联材料与 import 上下文 ↗](../../../scripts/review-knowledge.ts#L50 "支持分析阶段从显式链接和代码 import 边补充有限候选材料。") 文件分析无失败且未限定 files-only 时，脚本先按模块分组综合，再规划主题章节、生成各主题和最终总览。[模块、主题与总览综合 ↗](../../../scripts/review-knowledge.ts#L70 "支持分析成功后按模块综合、规划章节、生成主题文章和总览的层级流程。")

<a id="outputs"></a>
## 覆盖记录与完成语义

覆盖报告把每个捕获项标记为 reviewed、stale、pending 或 not-applicable，并同时记录分析失败；报告写入运行目录后复制为发布知识资产。[知识覆盖报告 ↗](../../../scripts/review-knowledge.ts#L60 "支持覆盖状态计算、失败记录以及运行报告向发布资产的复制。") 有分析失败时设置非零退出码并跳过后续综合；最后仅为 current 页面生成索引，输出已复核数、问题数和失败数，并始终停止管线、关闭 Store。[索引、完成统计与资源清理 ↗](../../../scripts/review-knowledge.ts#L83 "支持 current 页面索引、最终统计，以及 finally 中停止管线和关闭 Store。")
