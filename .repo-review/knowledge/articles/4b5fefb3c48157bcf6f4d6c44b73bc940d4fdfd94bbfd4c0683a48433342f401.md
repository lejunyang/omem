# 仓库知识生成、复核与发布流程

将 repo-review 捕获材料接入共享 KnowledgePipeline，经配置的 ACP 角色运行时分析并发布文件知识；随后按受影响模块和祖先依赖合成上层文章，维护覆盖记录、知识索引及失败状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="runtime-setup"></a>
## 模型合同与运行时装配

脚本把仓库评审作为共享材料知识流水线的一个应用入口。它要求 review 模型配置采用 ACP 且包含命令，再由 schema 校验 profile；并发度只能为 1 至 6，选择器支持 `--only`/`--target`，是否合成模块由 `--modules` 与 `--files-only` 控制。[评审模型与选择参数 ↗](../../../scripts/review-knowledge.ts#L20 "支持 ACP 配置要求、profile 校验、并发边界及目标和模块选择规则。") KnowledgePipeline 复用 RoleRuntimeGateway、角色 bundle、请求仓库和知识仓库；发布时先写 staging，再复制 JSON 与 Markdown 到知识资产目录。[共享知识流水线与资产发布 ↗](../../../scripts/review-knowledge.ts#L30 "支持 KnowledgePipeline、角色运行时和请求仓库的装配，以及 staging 到知识资产的发布路径。")

<a id="material-analysis"></a>
## 材料同步、选择与关联补充

运行开始后依次执行 review sync、恢复覆盖信息、code sync 和既有知识恢复，再从 `omem:` 材料中按路径选择目标。[同步、恢复与材料筛选 ↗](../../../scripts/review-knowledge.ts#L40 "支持运行前同步代码和评审材料、恢复知识，并按 omem 键和路径筛选目标。") 分析时会加入已链接材料，并根据代码图中触及目标文件的 imports 边补充至多四个被导入文件，每项只提供前 70 行；这扩大了局部上下文，但不是全库任意搜索。[分析关联材料选择 ↗](../../../scripts/review-knowledge.ts#L52 "支持利用已链接材料和 imports 边补充有限上下文后调用流水线分析。") 分析失败会被记录并令进程失败，旧知识是否仍 current 由仓库状态而非控制台文字决定。

<a id="composition-and-coverage"></a>
## 模块合成与祖先重建

覆盖文件区分被排除、捕获失败以及知识的 reviewed、stale、pending 等状态，并同时保存分析失败和合成失败。[知识覆盖记录 ↗](../../../scripts/review-knowledge.ts#L62 "支持覆盖文件记录选择范围、知识状态、分析失败与合成失败，并发布到知识目录。") 非 files-only 模式按路径分组；只要某组存在未复核子项就跳过模块合成。限定范围更新时，脚本读取既有文章的依赖定位，只重建依赖已更新且所有子项 current 的祖先，并循环传播影响。[模块与祖先依赖重建 ↗](../../../scripts/review-knowledge.ts#L73 "支持未复核子项阻断模块合成、局部更新传播至已有祖先，以及无失败全量运行时的主题规划。") 全量且无失败时才重新规划主题章节，先合成各主题，再用主题文章合成 overview。

<a id="publication-boundary"></a>
## 发布结果与失败边界

流程结束前再次记录覆盖；存在合成失败时设置非零退出码，只把仓库中仍为 current 的页面写入 review 知识索引，并输出目标数、当前页面数、开放问题及失败计数。无论结果如何都会停止流水线并关闭 Store。[索引发布与最终状态 ↗](../../../scripts/review-knowledge.ts#L120 "支持最终覆盖更新、失败退出、仅索引 current 页面、汇总问题和关闭运行时资源。") 因此“文件已捕获”“分析已完成”“模块已合成”和“当前索引已发布”是不同状态，局部失败不能被概括为全库知识已刷新。
