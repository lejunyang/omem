# 仓库知识生成与分层重建脚本

该脚本把仓库捕获材料、代码结构投影和共享知识流水线编排成一次显式知识更新：按路径筛选并补充失效目标，调用真实 ACP 角色分析，按需合成模块、既有祖先章节或全库主题，记录覆盖与失败，最后发布当前知识索引。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-setup"></a>
## 作用与运行准备

该脚本是 repo-review 对共享知识流水线的显式应用入口，解决代码或文档变化后如何依据真实材料重建派生知识的问题。它从评审模型配置构造 ACP profile，拒绝缺少 ACP 命令的配置，并把并发限制在 1–6；目标路径、`modules`、`files-only` 与 `retry` 可由 osdk 环境参数或直接 CLI 参数提供。[模型配置与并发约束 ↗](../../../scripts/review-knowledge.ts#L21 "支持脚本使用显式 ACP 配置构造角色 profile、校验并发范围并解析主要运行开关。") [任务参数解析 ↗](../../../scripts/task-args.ts#L1 "说明目标和布尔开关同时兼容 osdk 环境参数与直接命令行参数。")

运行时使用隔离的 review store、知识仓库和角色网关；发布结果先写 staging，再按文档键摘要复制到受版本管理的知识资产目录。SIGINT 或 SIGTERM 会请求流水线停止，最终块仍负责关闭流水线和数据库。[知识流水线与发布目录初始化 ↗](../../../scripts/review-knowledge.ts#L31 "支持隔离 store、角色网关、staging 发布目录及停止信号处理的描述。")

<a id="selection-and-analysis"></a>
## 材料选择与分析流程

主流程先同步评审捕获、读取覆盖状态、同步代码图，再恢复已有知识文章。目标选择以捕获材料路径为准；若旧多材料批次中的原文知识已经失效，且其依赖的本次目标摘要发生变化，脚本会把该原文补入刷新范围，避免遗留保守的兄弟依赖；没有匹配材料则直接失败。[同步、恢复与失效材料扩展 ↗](../../../scripts/review-knowledge.ts#L41 "解释同步顺序、路径选择、旧批次失效依赖扩展以及空选择报错。")

脚本随后调用共享 `KnowledgePipeline.analyze`。除链接材料外，它还依据当前文件的 `imports` 边，最多补充四个被导入文件的前 70 行；这些内容只是分析上下文，并不能证明跨文件调用关系。[分析上下文补充规则 ↗](../../../scripts/review-knowledge.ts#L58 "支持组合链接材料与有限 import 邻接材料，并明确最多四项、每项前 70 行的边界。") 共享流水线按图片、会话和文件类型选择分析角色；角色运行会把材料、文章、模型、预算和角色版本写入持久任务，并从角色输出表读取结果、执行指定校验。因此，本脚本负责仓库选材与编排，角色选择、任务入列和输出规范化由共享流水线承担。[材料分析角色选择 ↗](../../../apps/server/src/knowledge/pipeline.ts#L15 "说明共享流水线根据图片、会话属性和文件类型选择不同分析角色。") [持久角色任务与输出校验 ↗](../../../apps/server/src/knowledge/pipeline.ts#L60 "支持共享流水线将角色请求入列为持久任务，并从角色输出记录读取、解析和规范化结果。")

<a id="composition-and-boundaries"></a>
## 分层合成、失败语义与边界

分析后脚本写出覆盖记录，将材料标为 reviewed、stale、pending 或 not-applicable，并分别保存分析失败和章节合成失败；任一失败都会使进程返回非零状态，因此任务入列或部分产出不代表整次更新成功。[覆盖记录与分析失败处理 ↗](../../../scripts/review-knowledge.ts#L71 "支持覆盖状态计算、失败记录及分析失败导致非零退出状态的论断。")

未启用 `files-only` 时，脚本按应用、包、脚本、文档或项目分组。只有组内全部子材料都有当前知识时才合成模块；定向更新会沿已有文章依赖逐层修复受影响祖先，但不会凭空规划新体系。只有全库运行且没有前置失败时，才重新规划主题、逐章合成并生成总览。[模块分组与合成门槛 ↗](../../../scripts/review-knowledge.ts#L82 "解释仅处理受影响分组、子知识未全部当前时跳过模块合成，以及并发合成方式。") [祖先修复与全库主题规划 ↗](../../../scripts/review-knowledge.ts#L102 "支持定向更新逐层修复既有祖先，以及只有无失败的全库运行才规划主题和总览。")

最终索引只收录仓库中标记为 current 的页面。代码图在这里仅提供文件和 import 定位辅助：代码同步是已捕获 fragment 上的确定性投影，不负责捕获文件正文；现有材料也不足以把 imports 边解释成完整的跨文件调用证据。[最终索引与资源清理 ↗](../../../scripts/review-knowledge.ts#L129 "说明合成失败影响退出状态、索引仅采用 current 页面，并在最终块关闭资源。") [代码同步投影边界 ↗](../../../apps/server/src/code/sync.ts#L1 "佐证代码同步只投影已捕获 fragment、不会捕获文件正文，限制对代码图证据的解释范围。")
