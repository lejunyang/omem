# 仓库知识分析与发布脚本

该脚本是仓库评审知识流程的显式入口：同步评审材料与代码图，恢复既有文章，调用共享知识管线分析目标材料并发布覆盖率和索引；只有分析无失败且未启用 files-only 时，才继续生成模块、主题与总览知识。跨文件补充仅提供 imports 目标材料的有限源码，不能证明具体调用关系。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-setup"></a>
## 职责与运行前提

脚本把 repo-review 接入共享的 `KnowledgePipeline`，并以显式评审模型配置构造 ACP profile；非 ACP、缺少命令或超出 1–6 的并发值会被拒绝。`--only`、`--target` 不仅筛选路径，还会隐式启用 files-only；运行时目录保存暂存内容，正式文章发布到知识资产目录。信号处理器会请求停止管线，但停止的具体保证不在本材料中。[模型配置、目标范围与管线初始化 ↗](../../../scripts/review-knowledge.ts#L20 "支持 ACP 配置校验、并发限制、路径筛选会启用 files-only、暂存与发布目录以及信号停止处理的说明。")

<a id="analysis-flow"></a>
## 同步、恢复与上下文补充

主流程依次同步评审材料、恢复覆盖信息、同步代码结构并载入已有文章，然后从 `omem:` 材料中筛选目标；没有匹配材料时直接失败。[同步、恢复与目标筛选流程 ↗](../../../scripts/review-knowledge.ts#L39 "支持评审同步、覆盖恢复、代码同步、已有文章载入以及无匹配材料时失败的流程说明。") 分析阶段会合并已有材料关联，并沿目标文件的 `imports` 边最多补充四个被导入文件，每份只开放第 1 行至最多第 70 行。此前“没有被导入文件源码内容”的结论已被替代：角色能看到有限源码，但这里没有调用关系证据或具体调用点，因此仍不能据此断言跨文件函数调用。[导入材料的有限上下文扩充 ↗](../../../scripts/review-knowledge.ts#L50 "支持沿 imports 边补充最多四份被导入材料且每份仅开放前 70 行，并说明该数据不包含具体调用关系证据。")

<a id="publication-and-limits"></a>
## 覆盖、综合与发布限制

分析后会记录 reviewed、stale、pending 或 not-applicable 等覆盖状态；若存在失败，脚本设置非零退出码。模块、主题及总览综合还受另一条件约束：只有**无分析失败且非 files-only**时才执行，因此此前“无失败即生成全局知识”的表述已被替代。[覆盖记录与综合触发条件 ↗](../../../scripts/review-knowledge.ts#L60 "支持覆盖率写入、失败退出以及综合必须同时满足非 files-only 和无失败两个条件的论断。") 满足条件后，材料先按模块分组综合，再规划主题并生成总览；最后写入索引，并在 `finally` 中停止管线、关闭存储。[分层综合、索引与资源收尾 ↗](../../../scripts/review-knowledge.ts#L71 "支持模块、主题、总览的生成顺序，以及索引写入和 finally 中资源关闭的说明。") 当前材料只能确认这些控制流，不能证明分步复制的原子性、重跑幂等性或中断时的一致性。
