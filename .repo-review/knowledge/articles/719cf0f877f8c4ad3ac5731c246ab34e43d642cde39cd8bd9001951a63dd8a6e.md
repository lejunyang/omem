# 受约束的知识角色与证据校验

agent-runtime 通过角色清单、固定材料、结构化输出和独立复核划分知识生成与证据判断；代码理解子系统进一步以快照、摘要封印和交叉引用校验约束结果，并在无模型时只生成机械事实 seed。现有材料能证明合同与部分确定性实现，但不足以证明所有角色已端到端接入或自由文本语义已被验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为什么要拆分生成与复核

知识角色面对的核心风险，不只是输出格式错误，还包括真实材料被扩大解释、转述被误认成用户承诺，以及一次工具成功被写成整体成功。复核角色因此不沿用提取者的推理，而是重新核对引文或图片身份，再比较主体、范围、时间、归属、否定、条件和论断强度；冲突与缺失背景必须保留。参考 [独立复核原则 ↗](../../../packages/agent-runtime/roles/verifier/1/prompt.md#L3 "支持复核阶段重新核对证据身份、语义范围并保留冲突和缺失背景的说明。")

复核者只判断证据是否支持提案，不负责批准、应用或执行变更。其输出把资产有效性与语义判断分开：前者区分有效、无效和歧义，后者区分支持、矛盾、证据不足和需要收窄范围。参考 [复核权限边界 ↗](../../../packages/agent-runtime/roles/verifier/1/prompt.md#L5 "支持复核角色只评估证据支持程度，不批准、应用、执行或修改策略的职责边界。")、[批量评估字段 ↗](../../../packages/agent-runtime/roles/verifier/1/output.schema.json#L25 "支持引文资产判断、语义判断、原因和缺失上下文共同构成逐项评估结果。")

<a id="role-flow"></a>
## 角色如何形成可追溯结果

视觉分析角色负责把截图或图表中的**可见内容**组织成知识，同时明确区分观察与推断，不虚构无法辨认的文字。参考 [视觉观察边界 ↗](../../../packages/agent-runtime/roles/visual-analyst/1/prompt.md#L1 "支持视觉角色描述可见结构、区分观察与推断且不得虚构不可读文字。") 角色清单将提示词、内联技能及其摘要、`KnowledgeBatch.v1` 输出合同、工具禁用和会话隔离策略绑定在一起，使一次运行在声明上具有固定能力边界。参考 [视觉角色运行清单 ↗](../../../packages/agent-runtime/roles/visual-analyst/1/manifest.json#L5 "支持视觉角色绑定提示词、技能摘要、输出合同、工具策略和会话隔离策略的说明。")

生成结果以文档、章节、内联引用和待确认问题表达；引用目标可定位材料行范围，精确引文预期由宿主复制，以便后续独立复核。参考 [知识引用与问题合同 ↗](../../../packages/agent-runtime/roles/visual-analyst/1/output.schema.json#L78 "支持知识文档通过章节、材料定位引用和结构化问题表达可追溯结论与不确定性。") 与之对应，复核结果采用 `AssessmentBatch.v1`，逐项绑定提案摘要、资产判断、语义判断、原因和缺失上下文。参考 [批量评估字段 ↗](../../../packages/agent-runtime/roles/verifier/1/output.schema.json#L25 "支持引文资产判断、语义判断、原因和缺失上下文共同构成逐项评估结果。") 由此形成“固定材料 → 结构化知识提案 → 独立证据评估”的职责分层，但提供的角色配置尚不能单独证明整条链路已经运行。

<a id="code-validation"></a>
## 代码理解的确定性防线

代码理解子系统采用更强的确定性边界：运行前固定文件、符号、关系边和证据集合，所有可引用对象都必须来自该快照。快照检查标识唯一性以及符号到文件、关系边到符号的引用完整性。参考 [固定代码快照 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L114 "支持快照限定文件、符号、关系和证据规模，并检查标识与交叉引用完整性。")

角色资产加载会限制允许的角色，拒绝越界路径与符号链接，并核对提示词、输出 Schema 和技能摘要。输出进入校验器后，还要匹配角色、提示词摘要、Schema 摘要和输入快照摘要；未知节点、关系、证据或越界行选择器会导致拒绝。参考 [安全加载角色资产 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L412 "支持角色白名单、目录边界、符号链接拒绝、Schema 和技能摘要校验流程。")、[输出封印与引用校验 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L502 "支持校验器核对运行封印、固定快照引用和证据行选择器，并对错误结果执行拒绝。") 这些检查能阻止虚构引用进入后续知识图，但不会判断自由文本解释本身是否真实。

<a id="progress-limits"></a>
## 当前进展与限制

在没有模型时，代码理解模块只允许生成确定性的 seed：列出受预算限制的机械事实，保持职责、边界和流程叙事为空，置信度为零；校验器也禁止 seed 携带解释性声明。参考 [无模型 seed 降级 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L620 "支持无模型时仅生成机械事实、空叙事、零置信度的确定性 seed，并说明其诚信字段。") 这提供了诚实降级路径，但 seed 不是经过模型分析的模块知识。

当前材料已经展示结构合同、角色声明和代码理解的确定性校验实现，却没有展示谁构造快照、谁调用真实模型与独立复核、成功结果如何持久化，也没有端到端运行记录。校验器返回可区分的失败或拒绝结果，是否真正阻止无效知识被发布仍取决于调用方正确处理。参考 [校验结果边界 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L489 "支持校验器只返回成功或失败、拒绝结果，而结果记录和知识提升仍属于调用方职责。")
