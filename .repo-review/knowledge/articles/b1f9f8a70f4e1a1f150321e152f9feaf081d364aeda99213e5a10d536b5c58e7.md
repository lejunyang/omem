# 可选本地能力的显式准备流程

说明 omem setup 如何在服务机器上准备文档解析、PDF 模型、决策模型或中文向量模型，并保护用户定制、保留可重跑的下载缓存；该流程只准备依赖，不会替用户开启功能。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_and_entry"></a>
## 解决什么问题

`omem setup <component>` 是可选本地能力的显式安装入口，适合管理员在服务所在机器准备 `documents`、`document-models`、`decisions` 或 `embedding`。CLI 拒绝通过远端 URL 安装，把组件名和 `--model` 交给 `setupOptional`；JSON 模式下再显示结构化结果。参考 [CLI 本机安装入口 ↗](../../../apps/server/src/cli.ts#L1552 "支持 setup 命令的组件参数、模型选项、远端安装限制及对 setupOptional 的真实调用关系。")

`setupOptional` 先限制组件取值，且只允许 `decisions` 使用 `--model`。决策能力还要求 Darwin/ARM64，因为当前 StartLux 运行层依赖 MLX；随后才检查 `osdk` 并准备个人工作区。参考 [输入与平台校验 ↗](../../../apps/server/src/cli/setup.ts#L21 "支持组件白名单、--model 使用范围、Apple Silicon 限制以及先检查 osdk 的流程。")

<a id="decision_walkthrough"></a>
## 一次决策模型准备怎样执行

以 `omem setup decisions --model both` 为例，`both` 会映射成 `decision-startlux2b` 和 `decision-startlux4b`；默认值则只映射 2B。参考 [决策模型别名映射 ↗](../../../apps/server/src/cli/setup.ts#L5 "支持默认、both 和 all 等选择如何转换为可同步的 StartLux 模型别名。")

```mermaid
flowchart LR
  A[CLI 传入 decisions + both] --> B[校验平台与 osdk]
  B --> C[准备 optional 工作区]
  C --> D[运行 StartLux 环境脚本]
  D --> E[逐个 sync 并 verify 模型]
  E --> F[返回 prepared 结果]
```

首次准备时，工作区模块直接创建随包的 `osdk.toml`。若已有配置且需要更新模型声明，则先在暂存目录修改；替换前会复查原配置是否在准备期间发生变化。这一并发变更复查只在该暂存更新分支执行。参考 [工作区首次创建与暂存更新 ↗](../../../apps/server/src/cli/optional-workspace.ts#L265 "支持首次准备直接创建随包配置，以及仅在已有配置需要模型更新时使用暂存目录、复查并替换原配置。") 随后主流程在该工作区执行 StartLux 准备脚本，并对两个别名依次调用 `osdk model sync` 和 `verify --json`；`both` 对应的建议运行模式是 `auto`。参考 [StartLux 下载与校验 ↗](../../../apps/server/src/cli/setup.ts#L66 "支持 decisions 分支运行环境脚本、逐个同步和验证别名，以及 both 对应 auto 建议模式和配置重启提示。")

<a id="branches_and_boundaries"></a>
## 能力分支、输出与失败边界

`documents` 运行文档环境脚本但不下载 PDF 模型，`document-models` 单独准备布局与表格模型；`embedding` 同步并校验 `memory-zh`。参考 [文档能力分支 ↗](../../../apps/server/src/cli/setup.ts#L53 "支持 documents 与 document-models 被拆为环境准备和模型下载两个独立步骤。") [向量模型分支 ↗](../../../apps/server/src/cli/setup.ts#L87 "支持 embedding 分支同步和校验 memory-zh，并提示后续开启检索配置和重启服务。") 成功结果包含工作区和模型别名，也列出保留项，同时明确 `configurationChanged: false`。`setup` 不自动改配置；`decisions` 与 `embedding` 仍需按提示配置并重启服务。参考 [StartLux 下载与校验 ↗](../../../apps/server/src/cli/setup.ts#L66 "支持 decisions 分支运行环境脚本、逐个同步和验证别名，以及 both 对应 auto 建议模式和配置重启提示。") [向量模型分支 ↗](../../../apps/server/src/cli/setup.ts#L87 "支持 embedding 分支同步和校验 memory-zh，并提示后续开启检索配置和重启服务。") [准备结果与配置边界 ↗](../../../apps/server/src/cli/setup.ts#L95 "支持成功结果包含工作区、模型和保留项，并明确能力配置没有被自动修改。")

已有定制会留在原位，新包候选写入更新目录供人工合并。参考 [用户定制保留与清单写入 ↗](../../../apps/server/src/cli/optional-workspace.ts#L299 "支持将新包候选写入更新目录、保留已有定制，并把随包数据写入工作区清单。") 工作区清单记录当前随包版本、模型声明和资源文件摘要，作为后续更新基线；它不盘点保留的本地定制内容。参考 [用户定制保留与清单写入 ↗](../../../apps/server/src/cli/optional-workspace.ts#L299 "支持将新包候选写入更新目录、保留已有定制，并把随包数据写入工作区清单。") [随包清单数据来源 ↗](../../../apps/server/src/cli/optional-workspace.ts#L134 "支持清单中的包版本、模型声明、资源文件摘要及整体摘要来自当前随包内容，而不是对本地定制的盘点。") 子进程模块把输出直接交给终端，并把启动失败、信号中断或非零退出码转成异常。参考 [可见子进程执行 ↗](../../../apps/server/src/cli/osdk.ts#L39 "支持命令在指定工作区运行、输出直达终端，并按启动错误、信号或退出码报告失败。") 主流程再补充组件上下文，说明缓存会保留，可修复网络或权限后重跑同一命令。参考 [失败后的重跑路径 ↗](../../../apps/server/src/cli/setup.ts#L106 "支持异常保留原始 cause，并说明已完成环境和缓存会保留，可在修复后重跑。")
