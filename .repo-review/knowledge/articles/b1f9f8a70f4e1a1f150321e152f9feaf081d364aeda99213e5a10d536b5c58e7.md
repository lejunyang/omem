# 可选能力的本地资源准备

说明 omem 如何为文档解析、PDF 模型、快速决策和中文向量检索准备本机运行环境，以及参数校验、平台约束、可关闭的操作提示、配置边界与分阶段失败恢复方式。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-inputs"></a>
## 统一准备入口与输入约束

`setupOptional` 为四类可选能力提供统一的本机资源准备入口：`documents`、`document-models`、`decisions` 和 `embedding`。未知组件会立即报错；模型选择只适用于 `decisions`，单项 `model` 与多项 `models` 也不能同时传入。决策模型默认选择 2B，`both` 展开为 2B 与 4B，`all` 展开为三个尺寸，数组输入还会校验并去重。`manualGuidance` 用于控制准备完成后的手动配置和检查提示；未显式设为 `false` 时才输出这些提示。参考 [组件、模型与提示选项校验 ↗](../../../apps/server/src/cli/setup.ts#L5 "支持四类组件、模型参数互斥、默认模型、组合展开、数组去重、通用别名模板和 manualGuidance 选项。")

`decisions` 使用 MLX 运行层，因此只接受 Apple Silicon Mac。所有合法分支在改动工作区前都会先确认 `osdk` 可用，并显示版本和模型工作区位置。参考 [平台与 osdk 前置检查 ↗](../../../apps/server/src/cli/setup.ts#L58 "支持 decisions 的 Apple Silicon 限制、工作区变更前的 osdk 检查，以及这些步骤位于 try 包装之外。")

<a id="representative-flow"></a>
## 以准备两个决策模型为例

代表性调用 `setupOptional("decisions", { model: "both" })` 会得到 `decision-startlux2b` 与 `decision-startlux4b` 两个别名。通过基础检查后，函数准备可选能力工作区；若发现用户定制文件，会保留原文件并提示候选更新目录。后续外部命令都在该工作区中执行。参考 [工作区准备与命令目录 ↗](../../../apps/server/src/cli/setup.ts#L67 "说明用户定制的保留提示，以及所有后续命令使用准备后的工作目录。")

```mermaid
flowchart LR
  A[校验组件与模型] --> B[检查 osdk]
  B --> C[准备可选工作区]
  C --> D[准备 StartLux MLX 环境]
  D --> E[逐个同步模型]
  E --> F[逐个校验模型]
  F --> G[提示配置 decisions.mode]
```

StartLux 环境脚本先运行，两个模型再按顺序执行 `sync` 和 `verify`。因为选择了多个别名，建议模式为 `auto`；默认情况下，函数只给出后续配置提示，不会在这里启用能力。传入 `manualGuidance: false` 时，这条模式提示和统一完成提示都不会输出。参考 [决策模型准备流程 ↗](../../../apps/server/src/cli/setup.ts#L90 "支持 StartLux 环境准备、模型逐个同步与校验，以及受 manualGuidance 控制的配置模式提示。")

<a id="branches-and-results"></a>
## 其他分支、返回值与失败恢复

`documents` 运行文档环境准备脚本，只准备 Python、uv 与 Docling；PDF 布局和表格模型交给独立的 `document-models` 分支下载、校验。默认情况下，`documents` 完成后会提示单独准备这些模型。参考 [文档能力分支 ↗](../../../apps/server/src/cli/setup.ts#L76 "支持 documents 与 document-models 分开准备环境和 PDF 模型，并显示 documents 的提示受 manualGuidance 控制。") `embedding` 则同步并校验 `memory-zh`；默认完成提示会要求将 `retrieval.enabled` 设为 `true`。未显式关闭 `manualGuidance` 时，各分支最后还会建议用 `omem doctor --local` 检查依赖，并说明能力开关不会自动修改。参考 [向量模型与完成提示 ↗](../../../apps/server/src/cli/setup.ts#L108 "支持 memory-zh 的同步校验，以及受 manualGuidance 控制的 retrieval 开关提示、doctor 检查提示和配置不自动修改的边界。")

成功结果包含组件、工作区、已选模型和保留的用户定制，`configurationChanged` 固定为 `false`。参考 [准备结果 ↗](../../../apps/server/src/cli/setup.ts#L121 "支持成功返回的状态、组件、工作区、模型、保留项和配置未改变标记。") 从工作区准备开始，第 67–128 行内的异常会被包装：错误会附带原始原因，并提示保留已完成的运行环境与下载缓存，用户可在修复网络或权限后重跑同一命令。输入校验、决策平台检查与 `requireOsdk()` 位于 `try` 之外，其错误不会经过这层包装。参考 [平台与 osdk 前置检查 ↗](../../../apps/server/src/cli/setup.ts#L58 "支持 decisions 的 Apple Silicon 限制、工作区变更前的 osdk 检查，以及这些步骤位于 try 包装之外。") [工作区准备后的失败恢复提示 ↗](../../../apps/server/src/cli/setup.ts#L129 "支持 try 范围内错误的包装、缓存保留和修复后重跑语义。")

新增组件时，需要同步修改组件白名单和执行分支。新增遵循现有命名规则的决策模型尺寸时，别名仍可由 `decision-startlux${size}` 模板生成；需要修改的是相关类型和合法值集合，并按产品语义决定是否调整 `both`、`all` 的展开范围。这是由当前实现结构推得的维护要求。参考 [组件、模型与提示选项校验 ↗](../../../apps/server/src/cli/setup.ts#L5 "支持四类组件、模型参数互斥、默认模型、组合展开、数组去重、通用别名模板和 manualGuidance 选项。")
