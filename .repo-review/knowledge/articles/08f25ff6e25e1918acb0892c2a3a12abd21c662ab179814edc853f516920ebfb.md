# retrieval · 模块理解

retrieval 模块以统一端口隔离上层调用与检索后端，当前提供 SQLite 关键词基线，召回当前来源片段和 active memory，并支持按固定 Revision、Fragment 回读原始证据。它坚持项目关系必须可信，但尚未形成租户隔离、跨后端分数语义及记忆候选回溯原文的完整合同。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-boundary"></a>
## 作用与设计背景

retrieval 位于知识流水线、助手工具与具体检索引擎之间。统一端口让当前 SQLite 关键词实现未来可替换为向量或侧车后端，而上层调用方式保持稳定；检索摘要只是定位线索，最终引用目标仍应是不可变的 Revision 与 Fragment。[统一检索端口设计 ↗](../../../apps/server/src/retrieval/port.ts#L1 "说明检索后端可替换、调用方接口保持稳定，以及结果应回到不可变原始片段的设计目标。")[统一检索端口与证据边界 ↗](e1aefe156d02f69476a443ae16951b1e4d0f5e30e2f93765c433725e810452db.md#purpose "引用子知识对后端替换与证据边界的组织说明，并由相邻原始端口材料共同支撑。")

端口区分原始来源候选与已应用记忆候选：前者携带 revision、fragment 和 provenance，后者服务于冲突检查或知识复用。接口还提供证据回读与后端健康状态。[候选类型与端口操作 ↗](../../../apps/server/src/retrieval/port.ts#L45 "支持来源候选、记忆候选、证据片段，以及搜索、回读和健康检查之间的合同关系。")

<a id="retrieval-flow"></a>
## 主要检索流程

来源检索先对查询分词，再逐词搜索当前 source head 下的片段；同一片段按不同命中词去重累分，较长词权重更高，并合并知识正文提供的证据候选。结果按分数截断，返回摘要窗口、固定定位和来源信息。[来源片段检索流程 ↗](../../../apps/server/src/retrieval/keyword.ts#L52 "支持逐词查询、去重计分、知识证据合并、结果排序截断及 provenance 输出的流程描述。") `readEvidence` 可精确读取指定 revision 与 fragment；未给 fragment 时读取 ordinal 最小的片段。[固定证据回读 ↗](../../../apps/server/src/retrieval/keyword.ts#L28 "说明按 revision 与可选 fragment 读取固定证据，以及缺省时选择首个 ordinal 片段的行为。")

记忆检索只扫描 active memory，在正文 JSON 中执行大小写无关的包含匹配。中文查询保留完整串并产生重叠二元组，同时过滤常见停用二元组；摘要取首个命中附近的窗口。[Active memory 检索与项目过滤 ↗](../../../apps/server/src/retrieval/keyword.ts#L119 "支持只检索 active memory、正文包含匹配，以及仅在可信项目条件成立时排除其他项目记忆的论断。")[中英文分词与摘要窗口 ↗](../../../apps/server/src/retrieval/keyword.ts#L183 "说明 ASCII 词、中文完整串和二元组、停用词过滤及命中附近摘要窗口的规则。") 该实现无需模型且容易解释，但不具备语义相似度、词频归一化或成熟的相关度排序。

<a id="trust-progress-limits"></a>
## 信任边界、进展与限制

项目关系不能由应用、会话或运行标识推断；只有来自已确认 ContextLink 的项目标识才可信，否则必须保持工作区级召回。[项目关系信任规则 ↗](../../../apps/server/src/retrieval/port.ts#L17 "说明捕获上下文不能推导项目关系，未确认关联时必须执行工作区级召回。") 当前来源片段尚无持久化的可信项目关联，因此不执行项目过滤。[来源片段的当前范围策略 ↗](../../../apps/server/src/retrieval/keyword.ts#L60 "支持来源片段因缺少持久化可信 ContextLink 而暂不执行项目过滤的现状。") 记忆侧则仅在查询同时提供项目 id 和可信标志时排除明确属于其他项目的记忆，未关联项目的记忆仍保持工作区可见。[Active memory 检索与项目过滤 ↗](../../../apps/server/src/retrieval/keyword.ts#L119 "支持只检索 active memory、正文包含匹配，以及仅在可信项目条件成立时排除其他项目记忆的论断。") 这取代了旧稿中以来源检索代码同时支撑记忆过滤的错误引用关系。

模块已具备统一合同、关键词召回、基础 provenance 与固定证据回读，但尚不构成项目或租户隔离。每词片段查询最多读取 200 行且没有 SQL 排序；端口也未规定同分次序或跨后端 score 的可比性。[关键词基线的已知边界 ↗](1444f142c0b04e6d91f3135deeda21102d3ef672bd0b0965f51d090841647b1b.md#memory-tokenization "引用子知识对高频词截断、粗粒度相关度和排序限制的归纳，相关事实由同段原始代码引用共同约束。") 此外，`MemoryCandidate` 不含 revisionId 或 fragmentId，不能仅凭候选直接调用 `readEvidence` 回到原始片段。[记忆候选定位缺口 ↗](../../../apps/server/src/retrieval/port.ts#L55 "支持 MemoryCandidate 缺少 Revision、Fragment 定位字段，而证据回读接口要求这些字段的结构性限制。")
