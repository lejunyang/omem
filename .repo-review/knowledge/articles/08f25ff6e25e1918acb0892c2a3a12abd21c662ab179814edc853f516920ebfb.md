# retrieval · 模块理解

retrieval 模块以统一端口隔离调用方与检索后端，当前提供 SQLite 关键词基线，覆盖固定来源片段、active memory 与证据回读；项目范围坚持确认后才收紧，但评分合同、超限排序及记忆到原始证据的映射仍待明确。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-boundary"></a>
## 作用与设计背景

retrieval 位于知识流水线、助手工具与具体搜索技术之间。调用方依赖统一端口，当前使用 SQLite 关键词实现，未来可替换为向量或侧车后端；设计目标是让上层回到不可变 Fragment 引用原文，而非把摘要或排序结果当作事实。[统一检索端口设计 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持模块隔离具体检索后端、允许未来替换实现，并要求上层引用不可变证据的架构作用。")

模块区分来源与记忆两类候选：来源候选直接携带 Revision、Fragment 和 provenance，可用于固定证据回读；记忆候选表示已应用知识，服务冲突检查与复用，但其类型没有直接给出原始 Revision/Fragment。[来源与记忆候选合同 ↗](../../../apps/server/src/retrieval/port.ts#L45 "支持两类候选字段的区别，以及只有来源候选直接携带 Revision 与 Fragment 定位。")

<a id="retrieval-flow"></a>
## 检索与回读如何工作

来源检索将查询分成去重 term，逐词搜索当前 source head 下的片段；同一片段按不同命中词累积分数，长词权重更高，并合并知识正文产生的证据候选，随后按分数截取，返回摘要、固定定位与 provenance。[来源搜索、评分与结果组装 ↗](../../../apps/server/src/retrieval/keyword.ts#L52 "支持逐词检索、去重计分、知识证据合并、分数排序及 provenance 输出流程。") `readEvidence` 可按 Revision 与 Fragment 精确读取；未给 Fragment 时取 ordinal 最小的片段。[固定证据回读 ↗](../../../apps/server/src/retrieval/keyword.ts#L28 "支持按 Revision 与可选 Fragment 读取证据，以及未指定 Fragment 时按 ordinal 选择首项。")

分词保留小写 ASCII 词；中文既保留完整串，也生成重叠二元组，并过滤常见高召回二元词。[中英文查询分词 ↗](../../../apps/server/src/retrieval/keyword.ts#L183 "支持查询 term 去重、ASCII 小写化、中文完整串与二元组生成及停用二元词过滤。") 记忆检索只扫描 active head revision，在序列化正文中做包含匹配并按命中词计分。[Active memory 检索 ↗](../../../apps/server/src/retrieval/keyword.ts#L119 "支持只扫描 active memory head、执行正文包含匹配并按命中 term 累积分数的说明。") 该基线无需本地模型且易解释，但没有语义相似度或词频归一化。

<a id="scope-progress-limits"></a>
## 范围约束、进展与限制

项目范围遵循“确认后才收紧”：应用名、会话号和运行号只是捕获上下文，不能推断为项目；没有已确认 ContextLink 时，调用方必须传入不可信项目状态，后端保持工作区级召回。[项目关系信任合同 ↗](../../../apps/server/src/retrieval/port.ts#L17 "支持不得从捕获上下文推断项目，以及项目关联未确认时必须保持工作区级召回。") 来源 Fragment 目前没有持久化的可信项目关联，因此不执行项目过滤；记忆搜索则仅在项目标识可信、且记忆明确属于另一项目时排除该记忆，无项目关联的记忆仍可见。[来源检索的项目边界 ↗](../../../apps/server/src/retrieval/keyword.ts#L60 "支持来源 Fragment 尚无可信项目关联，因此当前不做项目过滤的实现边界。")[记忆检索的可信项目过滤 ↗](../../../apps/server/src/retrieval/keyword.ts#L133 "支持仅在项目标识可信且记忆明确属于其他项目时排除，并保留无项目关联记忆。") 这避免未知关联导致漏召回，但不等同于租户隔离。

当前已具备统一端口、固定证据回读、中英文词面召回和 active memory 搜索。仍有限制：每个来源 term 最多读取 200 行且 SQL 未规定行序；端口也未约束 score 范围、跨后端可比性或同分顺序，并且没有说明记忆候选如何稳定追溯到原始证据。[来源候选截断与排序 ↗](../../../apps/server/src/retrieval/keyword.ts#L85 "支持每词查询最多返回 200 行、SQL 未声明行序，以及最终仅按分数排序的限制。")[端口操作与未定义语义 ↗](../../../apps/server/src/retrieval/port.ts#L45 "支持端口只声明候选分数和证据读取参数，未规定跨后端评分语义，也未提供记忆到固定证据的转换关系。")
