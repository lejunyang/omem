# retrieval · 模块理解

检索模块以统一端口连接关键词、记忆、知识与本地语义召回，并把候选落回不可变原始片段。代码材料显示已实现中文分词、多路融合、离线向量索引、异常降级和多样化排序；这些是源码能力描述，不代表已经通过运行或行为测试验证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 统一检索层的职责

检索模块负责从捕获材料、已应用记忆和派生知识线索中寻找可引用证据，而不生成新的事实权威。统一端口隔离具体后端，并要求候选携带固定 fragment 与 revision，供上层回读原文。[统一检索端口的设计目标 ↗](e1aefe156d02f69476a443ae16951b1e4d0f5e30e2f93765c433725e810452db.md#purpose "支持检索后端隔离以及候选必须回到固定原始证据的模块职责。") [固定证据锚点合同 ↗](../../../apps/server/src/retrieval/port.ts#L1 "直接支持所有检索结果应指向不可变片段、供上层引用原文的论断。")

查询合同还规定时间、可见性和来源偏好；项目范围不能从会话或应用上下文推断，只有确认过的关联才能收窄，否则必须保持工作区召回。[可信项目与宿主过滤策略 ↗](../../../apps/server/src/retrieval/port.ts#L17 "支持项目关系不得从上下文载体推断，以及时间、可见性和来源权重的查询边界。")

<a id="lexical-flow"></a>
## 关键词召回与证据回溯

默认配置关闭语义能力，工厂装配 SQLite 关键词实现；启用后才创建语义实现、启动后台索引并返回关闭回调。[检索后端装配入口 ↗](../../../apps/server/src/retrieval/factory.ts#L9 "支持默认选择关键词实现，以及启用配置后创建并启动语义实现、返回关闭回调的流程。") 关键词路径汇总代码符号、全文、短关键词、记忆证据和知识证据五路候选，经资格过滤与去重后使用倒数排名融合。[五路召回与倒数排名融合 ↗](../../../apps/server/src/retrieval/keyword.ts#L97 "支持代码符号、全文、短关键词、记忆和知识五条分支及其去重融合过程。")

记忆命中通过解析 evidence set 回查原始片段。[记忆证据集合解析路径 ↗](../../../apps/server/src/retrieval/keyword.ts#L81 "支持记忆命中通过 evidence set 回查原始片段，并说明直接 JSON 解析使坏数据处理策略仍需确认。") 知识正文则作为导航：系统检查知识依赖和引用范围，递归解析文章引用，并把有效引用映射回当前原始 fragment。[知识正文回溯原始片段 ↗](../../../apps/server/src/knowledge/retrieval.ts#L33 "仅用于支持知识 artifact 的依赖检查、递归引用解析和原始 fragment 映射，不用于证明记忆 evidence set 行为。") 这两条路径职责不同；此前用知识引用同时证明记忆 evidence set 行为的结论已被替代。

<a id="semantic-flow"></a>
## 本地语义索引、融合与排序

语义实现继承关键词基线，仅为当前 head 的非派生片段建立可重建向量视图。正文按 400 字符窗口、320 字符步长切分，向量及完成标记按模型身份在单片段事务中写入。[语义分窗与事务写入 ↗](../../../apps/server/src/retrieval/semantic.ts#L51 "支持按当前片段选择待索引内容、重叠分窗、批量嵌入、向量校验及单片段事务写入。") 模型从 osdk 管理的固定快照加载，核对仓库、revision 和关键文件哈希，并禁止远程模型加载；查询与正文使用不同输入形式。[中文模型的离线校验加载 ↗](../../../apps/server/src/retrieval/embedding.ts#L14 "支持固定模型版本、关键文件哈希校验、禁止远程加载及查询专用输入处理。")

异步搜索先取得词法候选，再计算当前模型身份下已有窗口的语义分数并融合。模型尚未加载时直接排序词法候选；当前身份没有向量、或语义行经时间与可见性过滤后为空时，融合只保留已有词法候选；语义处理抛错也回退到词法排序。若词法候选本身为空，结果仍为空。[词法与语义融合及异常回退 ↗](../../../apps/server/src/retrieval/semantic.ts#L81 "支持词法预取、语义行过滤、两路融合，以及无当前向量、过滤后语义分支为空或异常时保留已有词法候选的准确边界。") 最终排序应用来源权重、代码符号加权和 MMR 式去冗余，只改变顺序，不改变证据身份与溯源。[相关性加权与多样化排序 ↗](../../../apps/server/src/retrieval/ranking.ts#L3 "支持来源和代码符号加权、MMR 冗余抑制，以及排序不改变证据身份的边界。")

<a id="progress-limits"></a>
## 代码进展与待验证边界

材料显示代码实现了“统一合同—关键词召回—后台向量追赶—混合融合—原文回读”流程，并通过健康状态报告索引中、就绪或降级。[语义索引健康状态与后台追赶 ↗](../../../apps/server/src/retrieval/semantic.ts#L21 "支持代码中的索引进度统计、健康状态、正常轮询和错误退避；不用于声称这些行为已经实际运行验证。") 此处仅描述源码实现；此前“已形成可运行切片”及“当前已具备经验证能力”的结论已被替代，因为材料未提供实际运行、测试退出码或行为断言。

尚不能确认服务器是否只启动一次并在退出或重载时关闭模型，也未展示模型换代、head 迁移、片段删除或分窗缩短后的旧索引回收。记忆路径会直接解析 evidence set，缺失值、损坏 JSON 或不完整关联应跳过还是中断请求也没有明确合同。[记忆证据集合解析路径 ↗](../../../apps/server/src/retrieval/keyword.ts#L81 "支持记忆命中通过 evidence set 回查原始片段，并说明直接 JSON 解析使坏数据处理策略仍需确认。")
