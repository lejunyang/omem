# retrieval · 模块理解

检索模块以统一端口连接上层调用方与 SQLite 证据库，默认融合中文关键词、记忆证据和知识证据，可选加载锁定的本地 BGE 模型建立语义索引；来源候选可回读固定片段，语义未就绪或异常时仍保留词法召回。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责、范围与证据边界

模块通过统一端口隔离流水线、助手与具体检索后端，使关键词基线和后续实现可以替换。[统一检索端口 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持检索后端可替换且流水线与助手调用方无需随实现改写的架构职责。") 查询合同约束时间、可见性及项目范围：项目关系只能来自已确认的关联，不能根据会话或运行上下文推断；没有可信项目时必须保持工作区级召回。[查询范围与可信项目规则 ↗](../../../apps/server/src/retrieval/port.ts#L17 "支持可信项目来源、工作区回退、捕获时间范围和排序前可见性过滤约束。")

此前“所有返回结果都直接指向不可变片段”的结论已被替代。`SourceCandidate` 明确携带 revision 与 fragment 锚点，而 `MemoryCandidate` 只有记忆 ID 和 provenance；`readEvidence` 也只接受 revision 与可选 fragment 标识。[来源与记忆候选类型 ↗](../../../apps/server/src/retrieval/port.ts#L48 "支持只有来源候选直接携带 revision 与 fragment 锚点，而记忆候选没有这些字段的判断。") [证据读取接口 ↗](../../../apps/server/src/retrieval/port.ts#L81 "支持证据回读需要 revision 与可选 fragment 标识，且端口没有定义从记忆 ID 到证据锚点的解析步骤。") 因而公开合同目前只保证来源候选可直接回读原文，记忆候选仍需额外的证据映射。

<a id="selection"></a>
## 后端选择与模型装配

工厂使用严格配置选择后端：默认关闭语义能力并创建关键词检索；启用后创建 `SemanticRetrieval`、启动后台追赶，并向调用方暴露关闭钩子。[检索后端工厂 ↗](../../../apps/server/src/retrieval/factory.ts#L9 "支持严格配置、默认关键词后端、语义后端启动及关闭生命周期的说明。") 中文向量模型由 osdk 提供固定快照，应用校验仓库、revision 和关键文件摘要后，才以禁止远程模型、仅本地文件、CPU q8 的方式加载；查询附加中文检索指令，材料保持原样，并统一采用 CLS pooling 和归一化。[本地中文向量加载器 ↗](../../../apps/server/src/retrieval/embedding.ts#L14 "支持锁定快照及摘要校验、禁止远程模型、CPU 量化加载和查询特化策略。") 这使运行期不隐式下载模型，并把权重与分词资产摘要纳入向量身份。

<a id="lexical_flow"></a>
## 关键词、记忆与知识召回

词法查询先拆出 ASCII 词、中文完整串和重叠二元组，并过滤常见中文停用二元组。[中文与 ASCII 分词规则 ↗](../../../apps/server/src/retrieval/keyword.ts#L194 "支持 ASCII token、中文完整串、重叠二元组及常见停用二元组过滤的说明。") 长度至少三字符的词进入 trigram FTS5，查询显式连接当前 source head 并排除派生 revision；[当前原始片段的全文检索 ↗](../../../apps/server/src/retrieval/keyword.ts#L52 "支持长词使用 trigram FTS5，并通过 source head 连接和 ORIGINAL 条件限定当前非派生 revision。") 较短词则走转义后的 `LIKE`，同样限定当前 head 与非派生材料。[当前原始片段的短词检索 ↗](../../../apps/server/src/retrieval/keyword.ts#L122 "支持短词使用转义后的 LIKE，并同样连接当前 source head、应用 ORIGINAL 条件。")

候选还包括活跃记忆和知识两路。记忆命中不会把记忆正文当作独立证据，而会沿证据集合回查当前 head 的原始片段；四路结果统一执行时间、可见性过滤，按 fragment 去重后用倒数排名融合。[记忆证据回溯与四路融合 ↗](../../../apps/server/src/retrieval/keyword.ts#L80 "支持记忆回查当前原始片段、知识路线接入、统一过滤、去重和倒数排名融合流程。") 但知识路线由外部函数提供，本模块未再次检查其 head、原始性或知识时效，因此不能把其他路线的证据保证自动推广到知识候选。

<a id="semantic_flow"></a>
## 语义索引、融合与限制

语义实现继承关键词基线，后台只追赶当前 head 的非派生片段；长文本按 400 字窗口、320 字步长重叠切分，分批生成 passage 向量，并在一个片段全部完成后事务性写入窗口及模型 head。索引按 `model.id` 判断缺失项，避免把另一模型身份的完成标记当作当前索引。[后台语义索引流程 ↗](../../../apps/server/src/retrieval/semantic.ts#L34 "支持按模型身份追赶缺失片段、重叠切窗、批量嵌入及事务性写入索引的说明。")

查询先取得词法候选。空查询或模型尚未加载时会直接返回词法结果，此路径不设置错误，健康状态仍可能是 `indexing`；模型可用后才扫描当前模型 ID 的向量，计算各窗口精确余弦并与词法结果做 RRF 融合。查询嵌入、向量读取或维度校验失败时才记录错误并返回词法结果，使健康状态表现为降级。[词法与语义融合及异常降级 ↗](../../../apps/server/src/retrieval/semantic.ts#L80 "支持模型未加载时直接返回词法结果，以及按模型 ID 扫描、维度检查、精确余弦、RRF 融合和异常时记录错误后降级。") 当前实现明确以个人 SQLite 资料规模为前提，采用全量精确余弦而非独立向量服务；健康信息区分 ready、indexing 与 degraded。[个人 SQLite 规模与健康状态 ↗](../../../apps/server/src/retrieval/semantic.ts#L10 "支持全量精确余弦适用于个人 SQLite 资料规模，以及 indexing、ready、degraded 健康状态的区分。")
