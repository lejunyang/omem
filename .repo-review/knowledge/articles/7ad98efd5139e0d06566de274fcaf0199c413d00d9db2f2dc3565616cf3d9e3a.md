# ACP 助手模型的路由与回复解析测试

该测试覆盖助手模型在未配置、CLI 与 ACP profile 下的路由结果，以及结构化回复、任务调用和引用 ID 的基础解析；现有历史预算用例仅验证构造参数可接受，尚未观测真实提示词截断。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="transport-routing"></a>
## 传输路由与失败边界

测试分别构造 ACP 与 `codex-cli` profile。未配置 profile 时，`generate` 应以 `ModelUnavailableError` 失败；CLI profile 同样失败，且错误消息必须包含“CLI transport”，从而确认 CLI 不会被误送入 ACP 通道。[缺失配置与 CLI 路由测试 ↗](../../../apps/server/tests/acp-model.test.ts#L25 "支持未配置 profile 会失败，以及 CLI profile 被明确识别并拒绝的论断。")

ACP profile 用例最终也得到 `ModelUnavailableError`，但消息不含“CLI transport”。这只能证明它没有命中 CLI 拒绝分支；当前断言没有观测进程、传输调用或具体错误来源，因此不能确认失败一定发生在外部命令启动阶段。此前“已尝试启动”的结论由这一更窄的边界说明替代。[ACP profile 失败断言 ↗](../../../apps/server/tests/acp-model.test.ts#L58 "支持 ACP profile 的结果为模型不可用且错误消息不含 CLI transport，同时限定断言无法证明具体失败阶段。")

<a id="reply-parsing"></a>
## 结构化回复解析

合法 JSON 中的答案、字符串引用 ID 与 `create_task` 会被转换成运行时回复及单个工具调用，任务标题、详情和依据引用均受到断言。[合法回复与创建任务解析 ↗](../../../apps/server/tests/acp-model.test.ts#L81 "支持答案、引用 ID 和合法 create_task 被转换为预期运行时结构。") 当输入省略 `create_task` 时，解析结果不产生 `toolCalls`；非 JSON 文本或缺少 `answer` 的对象会抛错。[缺省任务与错误输出处理 ↗](../../../apps/server/tests/acp-model.test.ts#L104 "支持省略 create_task 时不生成工具调用，并支持非 JSON 与缺少 answer 时抛错；输入未覆盖显式 null。") 此处没有传入显式的 `create_task: null`，因此此前关于“任务值为 null”的已验证结论被删除。

混合类型的 `citation_ids` 会过滤掉数字和空值，仅保留字符串。[引用 ID 类型过滤 ↗](../../../apps/server/tests/acp-model.test.ts#L119 "支持解析器仅保留 citation_ids 中字符串元素的容错行为。") 现有覆盖仍未确定畸形任务对象、任务时间字段、空答案或未知字段应整条拒绝还是局部忽略。

<a id="history-budget"></a>
## 历史预算测试的实际覆盖

名为“截断历史到 `maxPriorTurns`”的用例仅以 `maxPriorTurns: 3` 构造模型，并断言实例类型。注释承认没有拦截 ACP 调用，实际也未调用 `generate` 或检查生成提示词。[历史预算占位用例 ↗](../../../apps/server/tests/acp-model.test.ts#L129 "支持该用例只验证模型构造成功、没有观测 generate 内历史截断行为的结论。") 因而它只能证明构造参数被接受，不能证明只保留最后三轮、轮次顺序正确，或单轮回复长度限制生效。
