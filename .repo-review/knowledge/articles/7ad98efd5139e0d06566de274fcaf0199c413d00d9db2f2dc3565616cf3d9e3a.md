# ACP 助手模型适配器测试

验证助手模型只接受 ACP 配置、对缺失或 CLI 配置诚实报不可用，并覆盖结构化回复解析；历史截断仅验证了构造参数，未形成行为断言。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="transport-routing"></a>
## 传输路由与失败语义

测试构造无 profile、CLI profile 与 ACP profile 三种情形。无配置必须抛出 `ModelUnavailableError`；CLI 不得被误送入 ACP，并要求错误消息明确包含 CLI transport；ACP 配置则应越过路由检查，随后因不存在的命令在启动阶段失败。这样区分“配置不支持”和“真实传输不可用”，且不生成伪答案。[传输路由测试 ↗](../../../apps/server/tests/acp-model.test.ts#L25 "支持无配置、CLI 与 ACP 三类路由结果及错误语义的说明。") [ACP 模型路由实现 ↗](../../../apps/server/src/assistant/acp-model.ts#L11 "说明生产适配器仅允许 ACP，且缺少配置或 CLI transport 时抛出模型不可用错误。")

<a id="reply-parsing"></a>
## 结构化回复解析

解析夹具覆盖回答、引用列表及可选 `create_task`：合法 JSON 被映射为回答、字符串引用和单个工具调用；`create_task` 缺失时不产生工具调用。非 JSON、缺少 answer 会抛错，混合类型的引用数组会过滤非字符串项。[助手回复解析断言 ↗](../../../apps/server/tests/acp-model.test.ts#L81 "支持合法 JSON、可选任务、非法 JSON、缺失回答与引用过滤等解析行为。")

<a id="coverage-limit"></a>
## 覆盖边界

所谓历史预算测试只确认传入 `maxPriorTurns: 3` 后对象可构造，并未拦截 ACP 调用或检查最终 prompt；注释也承认截断逻辑仍属内部行为。因此它不能证明旧轮次确实被截断，也未覆盖回答字段类型错误、畸形工具调用、多工具调用或 ACP 成功返回的端到端路径。[历史预算占位测试 ↗](../../../apps/server/tests/acp-model.test.ts#L129 "证明该用例只断言实例构造成功，没有验证 prompt 的实际截断结果。")
