# 任务提案合同示例

展示提炼器如何把一段有明确负责人、期限和下一步的材料转换为结构化任务提案，并保留固定证据、作用域、并发版本及派生来源信息。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="proposal_shape"></a>
## 任务提案内容

示例提案采用版本 1 合同，操作为创建任务，作用域限定在个人工作区、payments 项目和 owner 主体。任务正文同时保存规范化截止时间与原始时间表达，并给出下一步动作，使后续验证既能使用绝对时间，也能回看提炼依据。[任务范围与正文示例 ↗](../../../docs/implementation/batch2/examples/proposal.json#L1 "支持创建操作、个人作用域、负责人、截止时间和下一步等字段说明。") 这是一份 fixture 数据，展示期望形状，不单独证明生产提炼、校验或应用流程已经运行。

<a id="evidence_origin"></a>
## 证据与派生来源

提案引用固定 fragment/source revision，并保存原文、Unicode code point 半开区间选择器；这让系统能够确定性检查引文确实存在于指定修订。[固定修订引文 ↗](../../../docs/implementation/batch2/examples/proposal.json#L18 "支持证据绑定修订、精确原文和 Unicode 选择范围的说明。") 示例还记录空的不确定项、生成理由、预期版本集合，以及 job 和角色包来源，并明确 producer 为 derived，意味着提案是由材料推导出的候选结果，而不是新增的独立证据。[不确定性与派生来源 ↗](../../../docs/implementation/batch2/examples/proposal.json#L30 "说明示例如何记录判断理由、并发版本和派生任务来源。")
