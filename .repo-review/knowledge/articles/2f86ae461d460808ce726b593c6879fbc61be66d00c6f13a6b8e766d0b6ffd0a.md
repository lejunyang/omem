# 可追溯知识：从原始材料到可复核回答

知识模块把不可变原始修订组织成带固定引用的文章，经独立角色复核后发布，并在来源变化时传播失效。文章既服务于阅读，也可引导检索回到原始 Fragment；开发环境还能在不替换个人数据库的前提下接入仓库知识及历史证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

普通摘要容易脱离来源，也难以判断内容是否仍然有效。该模块把文件、对话、图片等原始修订转换为具有稳定摘要和溯源字段的知识材料；派生内容被排除，正常读取只采用各来源的当前版本。参考 [原始修订转知识材料 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持派生内容排除、文本与链接合并、溯源字段保留以及稳定材料摘要的论断。")；完整的材料身份与历史解析见子知识 [证据绑定与版本管理 ↗](e5a00f71eb3b9c04183300900af72d54d39599d69b8a20785ec7260e4f963a1d.md#material_identity "提供材料身份、历史解析和版本发布机制的子知识下钻入口。")。

目标不是建立第二套事实库，而是生成便于阅读的派生文章，同时让每项论断仍能沿固定版本、行号和引文回到原始材料。当前基础是单用户 SQLite 与不可变修订，团队级权限隔离仍属于后续演进范围。参考 [单用户存储边界 ↗](../../../apps/server/src/store.ts#L4 "说明当前以单用户 SQLite 和不可变修订为基础，团队级约束尚未实现。")

<a id="generation"></a>
## 生成、复核与发布闭环

```mermaid
flowchart LR
  A[固定原始材料] --> B[按来源选择分析角色]
  B --> C[生成带内联引用的草稿]
  C --> D[独立角色复核]
  D -->|接受| E[发布不可变文章版本]
  D -->|需修订| C
  E --> F[来源变化后标记失效]
```
参考 [固定材料上下文 ↗](../../../apps/server/src/knowledge/pipeline.ts#L30 "支持按固定行段组织原始材料、图片和来源元数据，并禁止无原始材料运行。") [独立复核与发布 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "支持最多四轮写作复核、仅发布接受文档以及记录依赖和运行 trace 的流程。")

流水线按图片、会话或代码材料选择角色，把获准的固定行段、来源元数据和必要图片组成上下文；材料、文章版本、模型、预算与角色包摘要会写入持久化任务输入。草稿必须完整覆盖目标，且引用不得越过提供范围。完整编排见子知识 [知识生成流水线 ↗](b22d52764b13721657e246604945c1dd1a082a38d3efee3d14e3d808709bcad5.md#durable-run-and-validation "提供角色选择、持久化任务、结构校验和综合边界的完整子知识说明。")。

写作与独立复核最多循环四轮，只有被接受的文档才会记录依赖与生成、复核 trace 并发布。发布前仓库再次核对依赖、引用结构和精确引文，然后在事务中保存新版本、切换当前版本并同步问题；上游材料或子文章变化后，失效会沿文章依赖传播。参考 [独立复核与发布 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "支持最多四轮写作复核、仅发布接受文档以及记录依赖和运行 trace 的流程。") [事务发布与失效传播 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前依赖校验、事务保存、问题同步，以及来源变化沿文章依赖传播失效。")

<a id="reading-retrieval"></a>
## 阅读入口与证据召回

阅读 API 提供文章、固定版本引用、原始材料、图片、问题和整理任务。引用按生成时记录的依赖摘要解析：旧版本缺失时仍保留说明，但会标为不可操作，而不会悄悄跳到当前内容。代码材料还能根据相对 import 形成确定性的模块导航；这不等于跨文件调用分析，因为解析器只做单文件 AST，名称级调用仅是候选。参考 [固定引用与材料导航 ↗](../../../apps/server/src/knowledge/api.ts#L20 "支持引用按依赖版本解析、不可用状态以及相对 import 导航的论断。")；接口细节见子知识 [知识阅读 API ↗](475058334ffc659aacefe4563ad15d0681a233ebb9f997fe364aa9919e3c79b3.md#reading "提供文章、材料、问题、搜索和异步整理入口的子知识下钻说明。")。

派生文章也能扩大召回入口，但不会作为最终证据返回。检索先匹配当前文章，再验证材料摘要和子文章版本，沿正文实际引用递归到固定材料，并把行区间映射回原始 Fragment。参考 [引用回溯原始片段 ↗](../../../apps/server/src/knowledge/retrieval.ts#L27 "支持校验依赖后沿文章引用递归，并把固定材料行区间映射回原始 Fragment。")；完整边界见子知识 [知识引导的证据召回 ↗](c1d016bfceaa9ad6e811622ceb90acc5a8a4c40816edc2c9bb6689fa263f00e1.md#flow "提供派生文章只用于导航、最终返回原始证据及遍历限制的子知识说明。")。因此文章负责解释与导航，原始 Fragment 仍是回答的证据基础。

<a id="progress-limits"></a>
## 已有能力与当前限制

模块已经覆盖材料身份、精确引文绑定、独立复核、不可变发布、历史恢复、失效传播、阅读接口以及由知识引导的原始证据召回。发布资产可同时生成 JSON 与 Markdown，恢复时会检查复核声明、文档结构和依赖摘要，并按子文章依赖顺序处理。参考 [文章资产发布与恢复 ↗](4d47a4c8c95e844eb1c679f4e308fbf24554dd35e94cef71db8b04afe2d1368f.md#restore-dependency-order "支持双格式发布、按依赖恢复以及 stale、rejected、missing 状态处理。")

开发环境可把仓库文章及其引用的旧材料接入个人 Store，同时保持评审运行库隔离，并最后捕获实时文件以避免历史版本重新成为 head。参考 [仓库知识合流 ↗](4dcfa483c1b628991ef1a9cdfcbf46eb7846e2565ac6b42033cede0cce268fbd.md#history-flow "支持评审知识和历史证据接入个人 Store、保持数据库隔离并避免历史覆盖实时版本。") 仍需注意：整理接口的 `running` 与 `lastRun` 是进程内状态；当前材料不能证明进程重启后会恢复正在执行的整理任务。轻量文章搜索也只是大小写无关的包含匹配，不等同于语义检索。参考 [整理状态与轻量搜索 ↗](../../../apps/server/src/knowledge/api.ts#L82 "支持整理状态位于路由进程内，以及搜索采用简单包含匹配而非语义检索的限制。")
