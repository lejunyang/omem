# knowledge · 模块理解

knowledge 模块把不可变捕获修订转成可追溯知识：以固定材料和子知识为输入，经角色化分析、独立复核与版本发布形成正文；来源变化会传播失效，派生正文可引导检索，但最终回答仍回到原始 Fragment。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责与证据边界

知识模块连接原始捕获与可解释回答：它把非派生修订转换为包含文本、图片、来源元数据和稳定摘要的知识材料，默认只选择各来源的当前 head。[知识材料解析与身份 ↗](e5a00f71eb3b9c04183300900af72d54d39599d69b8a20785ec7260e4f963a1d.md#material_identity "支持从原始修订构造材料、排除派生来源、计算稳定身份并仅选择当前材料。") 章节、内联引用、疑问、依赖以及生成与复核来源均受共享合同约束。[共享知识合同 ↗](../../../packages/contracts/src/knowledge.ts#L25 "支持文档、章节、引用、疑问、依赖以及生成和复核来源的统一数据结构。")

派生正文用于组织理解和扩大召回，并不成为新的独立证据。知识引导检索会从当前正文命中章节，再沿固定引用递归回到与行区间重叠的原始 Fragment。[知识引导的原始证据召回 ↗](c1d016bfceaa9ad6e811622ceb90acc5a8a4c40816edc2c9bb6689fa263f00e1.md#flow "支持派生正文只引导召回，最终结果映射回原始 Fragment。")

<a id="workflow"></a>
## 从材料到已复核正文

流水线按图片、会话来源或代码扩展名选择分析角色，把获准行段、图片及来源信息装入上下文；没有原始材料时拒绝运行，子文章仅作为带版本的辅助知识。[流水线输入组织 ↗](b22d52764b13721657e246604945c1dd1a082a38d3efee3d14e3d808709bcad5.md#purpose-and-context "支持分析角色选择、固定材料上下文以及派生文章不是独立证据的边界。") 角色任务会固化材料摘要、文章修订、模型、预算和 bundle 身份，输出还必须完整覆盖目标且不得引用未提供的材料范围。[持久化执行与批次校验 ↗](../../../apps/server/src/knowledge/pipeline.ts#L60 "支持任务输入固化、角色运行及目标完整性和材料引用范围校验。")

草稿交给独立 verifier，最多经历四轮写作与修订；只有 accepted 文档才会记录依赖、生成与复核 trace 并发布，停止标记出现时发布前会取消。[独立复核与发布循环 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "支持最多四轮修订、逐目标独立复核、仅发布 accepted 文档及停止时取消发布。") 仓库随后复检上游身份，在事务中保存不可变正文修订、切换 head，并同步疑问状态。[知识正文事务发布 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前复检依赖、保存不可变修订、切换 head 和同步疑问状态。")

<a id="lifecycle"></a>
## 失效、阅读与文件产物

材料或子文章变化会沿依赖传播失效，仅把对应 head 标为非 current，历史正文仍可按修订追溯。用户回答疑问时，回答被保存为新的原始捕获，并将相关正文标记为需要重新核对后刷新 current 状态；这里不会自动启动 Pipeline，后续仍需再次执行整理。[用户回答与正文失效 ↗](../../../apps/server/src/knowledge/repository.ts#L169 "支持回答被保存为原始修订、写入失效记录并刷新 current；也表明该方法没有自动调用生成流水线。")

HTTP 层提供文章、固定引用、材料、图片、问题、搜索和异步整理入口；固定版本不可用时保留引用并说明不可操作原因。[知识服务路由与固定引用 ↗](475058334ffc659aacefe4563ad15d0681a233ebb9f997fe364aa9919e3c79b3.md#responsibility "支持文章阅读、引用解析以及目标版本不可用时保留不可操作引用。") 文件产物可输出 JSON 与带内联链接的 Markdown，并按子文章依赖恢复；过期、无效或缺少生成复核来源的产物不会发布为当前知识。[知识产物恢复 ↗](4d47a4c8c95e844eb1c679f4e308fbf24554dd35e94cef71db8b04afe2d1368f.md#restoration "支持双格式发布、按依赖恢复以及过期或无效产物不发布。")

<a id="limits"></a>
## 当前限制与验收关注点

预算以 UTF-8 字节除以三并增加 25% 余量估算，属于工程近似而非模型专用 tokenizer。[生成预算估算 ↗](../../../apps/server/src/agent-runtime/budget.ts#L1 "支持预算估算是带 25% 余量的 UTF-8 字节近似，而非模型 tokenizer。") 代码阅读使用单文件 AST，不做跨文件类型解析，名称级调用只能视为候选。[单文件 AST 边界 ↗](../../../apps/server/src/code/parse.ts#L1 "支持解析器不做跨文件类型解析，名称级调用仅为候选。")

流水线仍需用行为测试覆盖四轮修订、停止时禁止发布、历史反馈复用及任务恢复幂等。[流水线复核与反馈复用 ↗](b22d52764b13721657e246604945c1dd1a082a38d3efee3d14e3d808709bcad5.md#review-and-publication "支持四轮 verifier 修订、停止前发布检查和历史反馈复用等流水线验收范围。") 文件恢复还需区分依赖缺失、依赖环和超过百轮的深链。[文件恢复的依赖边界 ↗](4d47a4c8c95e844eb1c679f4e308fbf24554dd35e94cef71db8b04afe2d1368f.md#boundaries "支持剩余 pending 统一记为 missing，因而无法区分缺失、依赖环和过深依赖链。") 仓库发布未展示目标 head 的比较交换条件，并发策略尚待明确。[仓库发布并发边界 ↗](e5a00f71eb3b9c04183300900af72d54d39599d69b8a20785ec7260e4f963a1d.md#history_questions_boundaries "支持发布事务的现有行为，并指出材料未给出同一文档 head 的乐观并发条件。") 检索实现本身也未证明所有调用路径都会统一小写 terms 并在返回前执行可见性过滤。[检索调用链待确认契约 ↗](c1d016bfceaa9ad6e811622ceb90acc5a8a4c40816edc2c9bb6689fa263f00e1.md#limits "支持查询词规范化和后续可见性过滤仍缺少调用方与行为测试证明。")
