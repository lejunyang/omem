# knowledge · 从原始材料到可追溯知识

knowledge 模块把不可变原始修订投影为固定材料，经角色分析、宿主引用绑定、独立语义复核和版本化发布形成可追溯文章；文章既服务阅读与疑问闭环，也可引导检索回到原始 Fragment。当前实现已覆盖生成、恢复、失效和 HTTP 阅读链路，但仍受单用户 SQLite、进程内并发控制、历史扫描及简单文本检索等边界约束。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为什么需要独立的知识层

原始捕获适合保存证据，却不天然提供面向主题的解释；直接保存模型回答又会混淆事实与派生总结。knowledge 模块因此把非派生修订投影为带稳定摘要的材料，并明确排除 `derived` 内容，保证知识正文只能组织证据，不能反过来成为新的原始事实。[知识仓储的材料投影说明 ↗](e5a00f71eb3b9c04183300900af72d54d39599d69b8a20785ec7260e4f963a1d.md#material_projection "子知识概括原始修订如何投影为材料及为何排除派生内容，作为进一步下钻入口。")[原始修订材料投影实现 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "直接支持过滤派生修订、拼接文本与链接、保留图片和计算内容摘要的论断。")

共享合同规定文档、章节、内联引用、疑问和知识批次的结构；仓储进一步要求每节实际使用引用、目标存在且材料行范围有效。引用原文由宿主依据模型选择的行号复制，语义支持性则留给独立角色复核，从而分离“定位正确”“原文准确”和“论断成立”三类责任。[知识文档共享合同 ↗](../../../packages/contracts/src/knowledge.ts#L3 "直接支持文档、章节、引用、疑问和知识批次的结构约束。")[文档与内联引用校验 ↗](../../../apps/server/src/knowledge/repository.ts#L41 "直接支持章节必须使用引用、目标存在性和材料行范围校验，并界定语义复核另行执行。")[宿主绑定固定原文 ↗](../../../apps/server/src/knowledge/repository.ts#L74 "直接支持由模型选择定位范围、宿主复制原文以及图片材料例外的机制。")

<a id="generation"></a>
## 如何生成、复核与发布

流水线先按图片、会话或代码材料选择分析角色，将允许读取的固定行段和图片装入上下文；角色任务通过持久化作业运行，并记录模型、effort、预算、提示词、技能、上下文指纹及用量。[知识生成流水线概览 ↗](b22d52764b13721657e246604945c1dd1a082a38d3efee3d14e3d808709bcad5.md#responsibility-context "子知识解释材料分类、可信上下文、持久化角色执行与复核发布的整体关联，供读者下钻。")[固定上下文与持久化角色任务 ↗](../../../apps/server/src/knowledge/pipeline.ts#L30 "直接支持固定行段装载、原始材料要求、任务指纹、作业复用及运行 trace 保存。") 模型输出还必须精确覆盖全部目标 key；宿主会绑定引文、校验文档，并拒绝引用未提供的目标或超出可见行段的材料。[知识批次目标与引用范围校验 ↗](../../../apps/server/src/knowledge/pipeline.ts#L96 "直接支持输出完整覆盖目标 key、引用仅限已提供材料或文章，并拒绝访问未开放行段。")

草稿随后交给独立 verifier；只有 `accepted` 文档才会连同材料及子文章依赖、生成 trace 和复核 trace 发布。被拒目标最多进行四轮定向修订，最终仍未通过便报错，不覆盖已有有效知识。[独立复核与修订循环 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "直接支持 verifier 独立复核、仅发布 accepted 文档、最多四轮修订及失败不发布。") 发布以稳定摘要形成不可变 revision，并在事务中切换当前 head、同步疑问和记录变更；依赖摘要变化则通过刷新流程向上层文章传播失效。[知识发布与失效子知识 ↗](e5a00f71eb3b9c04183300900af72d54d39599d69b8a20785ec7260e4f963a1d.md#publication_invalidation "子知识解释不可变 revision、当前 head、疑问同步和依赖失效传播之间的关系。")[知识发布和失效传播实现 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "直接支持依赖新鲜度检查、事务发布、疑问同步以及文章依赖的迭代失效传播。")

<a id="reading-and-retrieval"></a>
## 如何关联阅读、检索与用户补充

HTTP 层提供文章与引用解析、固定材料阅读和代码依赖导航。读取引用时先查文章保存的依赖摘要，再解析相应历史材料或文章版本；目标缺失时返回不可操作原因，而不是静默跳到当前版本。[知识服务阅读入口 ↗](475058334ffc659aacefe4563ad15d0681a233ebb9f997fe364aa9919e3c79b3.md#purpose-and-reading "子知识概括文章读取、固定版本引用解析与不可操作目标提示的职责。")[固定版本引用解析与材料导航 ↗](../../../apps/server/src/knowledge/api.ts#L20 "直接支持依赖摘要解析、历史版本状态以及相对 import 导航的行为。") 图片路由只返回已登记、字节存在且类型为 PNG、JPEG 或 WebP 的资产；疑问接口支持列出问题、提交 1–20000 字回答和转成任务。[图片与疑问 HTTP 接口 ↗](../../../apps/server/src/knowledge/api.ts#L69 "直接支持图片资产的登记、类型和字节检查，以及疑问列表、回答长度校验和任务化入口。") 代码材料的底层解析器只有单文件 AST、无跨文件类型解析，名称级调用只能视为候选。[单文件代码解析边界 ↗](../../../apps/server/src/code/parse.ts#L1 "直接支持解析器离线、单文件、无跨文件类型解析且调用仅为名称级候选的限制。")

知识正文也能扩大检索入口：系统先命中文章，再沿有效引用递归回溯，最终返回与引用行区间重叠的原始 Fragment，而非派生文章本身。[知识引导的证据召回 ↗](c1d016bfceaa9ad6e811622ceb90acc5a8a4c40816edc2c9bb6689fa263f00e1.md#flow "子知识解释派生正文只作为召回入口、最终结果仍为原始 Fragment 的设计。")[引用递归与 Fragment 映射 ↗](../../../apps/server/src/knowledge/retrieval.ts#L27 "直接支持依赖校验、文章引用递归、材料引文核对和字符区间映射回原始 Fragment。") 用户回答未决问题时，回答会被捕获为新的原始修订，并使所属文章失效以等待重核；问题也可幂等转成待办，因此补充背景进入同一证据链，而不是直接改写知识正文。[疑问回答与任务闭环 ↗](../../../apps/server/src/knowledge/repository.ts#L169 "直接支持把用户回答捕获为原始材料、使文章失效，并将问题幂等转为待办。")

<a id="progress-limits"></a>
## 当前进展与限制

当前切片已具备结构合同、固定引文绑定、独立复核、不可变发布、依赖失效、文件产物恢复和阅读 API。文件产物只有在版本、生成与复核来源、复核结论及依赖均满足要求时才恢复；依赖变化标为 stale，缺少子文章则暂不发布。[知识产物发布与恢复 ↗](4d47a4c8c95e844eb1c679f4e308fbf24554dd35e94cef71db8b04afe2d1368f.md#restoration "子知识说明 JSON 与 Markdown 发布、依赖顺序恢复、过期判定和复核来源校验。")[产物恢复实现 ↗](../../../apps/server/src/knowledge/artifacts.ts#L32 "直接支持版本、生成与复核来源及 accepted 结论校验、stale 判定、条件发布和剩余依赖标记 missing。")

边界仍然明确：底层 Store 是单用户 SQLite，团队租户强制隔离尚未实现。[单用户 SQLite 边界 ↗](../../../apps/server/src/store.ts#L2 "直接支持当前 Store 是单用户 SQLite 基础、团队租户强制隔离留待后续迁移的限制。") `/analyze` 的互斥由进程内 `running` 变量承担，材料未证明跨实例锁；文章搜索只是小写分词后的子串匹配。[整理入口与进程内运行状态 ↗](../../../apps/server/src/knowledge/api.ts#L82 "直接支持 analyze 参数校验、进程内 running 互斥、后台启动以及简单文章搜索行为。") 历史固定材料解析会倒序扫描修订，恢复流程又把真实缺失、依赖环和超过轮次上限统一归为 missing。[历史固定材料解析 ↗](../../../apps/server/src/knowledge/repository.ts#L159 "直接支持先查当前材料、再倒序扫描历史修订以恢复固定摘要版本的实现边界。")[产物恢复故障分类边界 ↗](4d47a4c8c95e844eb1c679f4e308fbf24554dd35e94cef71db8b04afe2d1368f.md#boundaries "子知识指出依赖环、过深依赖链和真实缺失目前会收敛为同一 missing 状态。") 这些限制不否定当前闭环，但意味着多实例部署、大规模历史和更精确的恢复诊断仍需额外设计与验证。
