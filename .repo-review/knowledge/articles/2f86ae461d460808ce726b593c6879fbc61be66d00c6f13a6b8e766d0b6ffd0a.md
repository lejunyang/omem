# knowledge · 模块理解

knowledge 模块把不可变原始 Revision 转为固定材料，经角色化分析、持久任务、结构校验和独立复核发布知识文章，并维护失效传播、回答回流、导入导出及原始证据召回；当前仍有进程级互斥、简单搜索与非原子文件发布等边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_model"></a>
## 职责与证据边界

该模块位于捕获存储与助手使用之间：它把非派生 Revision 中的文本、链接、图片及来源属性整理为带摘要的固定材料，明确排除派生 Revision，避免总结反过来冒充事实来源。[固定材料构造 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持从非派生 Revision 组合文本、链接、图片和来源属性，并据此计算固定材料摘要。") 知识正文采用章节内联引用；模型选择材料位置，宿主绑定固定范围内的精确引文，结构校验保证引用存在且范围合法，语义支持性另由独立角色复核。[引用校验与精确引文绑定 ↗](../../../apps/server/src/knowledge/repository.ts#L41 "支持内联引用、目标和范围校验，以及由宿主从固定材料复制精确短引文的职责划分。")

文章因此是可纠正的解释与导航层，而非独立事实来源。用于检索时，派生正文只负责选中引用链，最终候选仍回到原始 Fragment，并继续经过助手可见性规则。[原始证据召回边界 ↗](../../../apps/server/src/knowledge/retrieval.ts#L1 "支持派生正文仅引导检索、返回候选仍是固定原始 Fragment 且后续继续执行可见性规则。")

<a id="generation_flow"></a>
## 生成、复核与发布流程

流水线先按材料形态分派视觉、对话、代码或通用分析角色，并只提供获准的固定行范围、图片和可信捕获元数据。[角色分派与固定上下文 ↗](../../../apps/server/src/knowledge/pipeline.ts#L15 "支持按图片、会话、源码和普通材料选择角色，并限制角色只接收获准材料范围与可信上下文。") 每次角色运行会登记持久任务，输入引用记录材料摘要、文章修订、模型、effort、预算与角色包哈希，执行结果及 trace 随后持久化。[持久角色任务与运行追踪 ↗](../../../apps/server/src/knowledge/pipeline.ts#L60 "支持角色运行登记持久任务，并记录材料摘要、文章修订、模型、effort、预算、角色包信息及执行 trace。") 输出必须完整覆盖目标且引用不得越界；独立角色逐篇复核，仅发布通过项，未通过目标最多经历四次定向生成或修订尝试。[输出校验、独立复核与有限修订 ↗](../../../apps/server/src/knowledge/pipeline.ts#L96 "支持目标完整覆盖、引用范围检查、独立复核、选择性发布，以及最多四次生成或修订尝试。")

发布前仓库重新核对材料摘要与子文章修订；输入变化即拒绝写入，通过后生成不可变 revision 并事务性切换 current head。[依赖核对与不可变发布 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前重新核对输入身份、生成内容修订，并在事务中切换 current head。") 高层主题只从 current 子知识综合，汇集其原始材料范围并记录文章、材料依赖；子项超过十二个时分段处理。[多层知识综合 ↗](../../../apps/server/src/knowledge/pipeline.ts#L201 "支持从 current 子文章分段综合、汇集原始材料范围，并记录子知识和材料依赖。")

<a id="reading_feedback"></a>
## 阅读接口、反馈与失效传播

API 提供文章、材料、引用、图片、疑问、搜索和显式分析入口。引用缺少固定依赖或目标版本不可用时会返回不可操作状态及原因；分析请求还校验 Agent、进程内运行状态和所选 revision 的当前可解析性。[知识 API 与分析生命周期 ↗](../../../apps/server/src/knowledge/api.ts#L13 "支持引用可操作性、阅读与简单搜索接口，以及显式分析的 Agent、进程内互斥和固定 revision 校验。") 用户回答疑问后，答案保存为新的手工原始捕获，问题转为 answered，并使关联文章失效；用户也可显式将问题转为任务。[用户回答与任务转化 ↗](../../../apps/server/src/knowledge/repository.ts#L169 "支持把回答保存为原始捕获、将问题标记为 answered、使文章失效，以及显式创建任务。") 后续分析处理该文章对应材料时，会读取问题的回答 Revision，将其转换成固定材料加入输入，再重新生成和复核。[后续分析纳入用户回答 ↗](../../../apps/server/src/knowledge/pipeline.ts#L161 "支持后续分析读取关联问题的回答 Revision，将其转换为固定材料并加入本轮 offers。")

仓库刷新会比较 current 材料摘要与文章依赖，并沿子知识关系传播失效，保留历史修订但取消过期 head 的 current 状态。[依赖失效传播 ↗](../../../apps/server/src/knowledge/repository.ts#L144 "支持材料或子文章身份变化沿依赖链传播，并更新各文章 head 的 current 状态。") 由此形成“补充背景—失效—后续分析—复核发布”的反馈闭环。

<a id="progress_limits"></a>
## 现有能力与限制

模块已覆盖固定引用、角色化生成、独立复核、不可变发布、依赖失效、回答回流、JSON/Markdown 导出恢复及原始证据召回。导入会等待子知识并区分 restored、stale、rejected 与 missing，但 JSON 解析失败和最终未解依赖只进入本次返回，后者不写入导入状态表。[知识导入状态边界 ↗](../../../apps/server/src/knowledge/artifacts.ts#L32 "支持恢复时的依赖等待和状态分类，并说明解析失败与最终未解依赖的持久化边界。")

当前分析互斥仅由路由实例内存变量维护，章节搜索也只是派生正文的词项包含匹配。[知识 API 与分析生命周期 ↗](../../../apps/server/src/knowledge/api.ts#L13 "支持引用可操作性、阅读与简单搜索接口，以及显式分析的 Agent、进程内互斥和固定 revision 校验。") JSON 与 Markdown 按顺序分别写入，尚无成对原子发布保证。[文章文件发布方式 ↗](../../../apps/server/src/knowledge/artifacts.ts#L21 "支持 JSON 与 Markdown 使用稳定名称、仅在变化时分别写入，也显示当前没有成对原子切换。") 证据回溯在深度大于八或入口检查时输出已达三十便停止，依赖精确引文定位；三十并非严格结果上限，也未提供语义匹配或跨修订位置续接。[引用链回溯限制 ↗](../../../apps/server/src/knowledge/retrieval.ts#L33 "支持召回深度与数量入口检查、精确引文定位、依赖核验和解析失败隔离等当前边界。")
