# knowledge · 模块理解

knowledge 模块把不可变原始 Revision 转为固定材料，经专门角色生成、独立复核和版本化发布，形成可阅读、可失效、可追溯的派生知识；派生正文只引导检索，最终证据仍回到原始 Fragment。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 作用与证据边界

该模块解决“原始捕获难以直接阅读，但总结又不能取代证据”的矛盾：仓库从非派生 Revision 组合文本、链接和图片，并把内容及来源属性纳入摘要；派生 Revision 不会再次成为原始材料。[固定材料与来源摘要 ↗](e5a00f71eb3b9c04183300900af72d54d39599d69b8a20785ec7260e4f963a1d.md#materials-validation "支持模块只从非派生 Revision 构造固定材料，并以内容和来源属性确定材料身份。") 知识正文以章节和内联引用组织，引用范围由模型选择、精确短引文由宿主绑定，结构校验与独立语义复核分开执行。[引用校验与精确引文绑定 ↗](../../../apps/server/src/knowledge/repository.ts#L41 "支持内联引用合同、宿主绑定精确短引文以及结构校验与语义复核的职责分离。") 因而文章是可追溯的阅读与导航层，而不是新的事实 authority。

<a id="generation"></a>
## 生成、复核与发布流程

显式分析开始后，流水线依图片、会话、代码等特征选择分析角色，只把获准的固定行范围、图片和来源元数据交给角色；派生子文章会明确标注为非独立证据。[材料路由与固定上下文 ↗](b22d52764b13721657e246604945c1dd1a082a38d3efee3d14e3d808709bcad5.md#routing-context "支持按材料类型选择分析角色，并限制角色只能看到明确提供的固定材料和标注过的派生文章。") 角色调用进入持久任务系统，记录实际模型、effort、预算、上下文指纹和 trace；批次还必须完整覆盖目标键，且引用不能越出提供范围。[持久任务与批次约束 ↗](../../../apps/server/src/knowledge/pipeline.ts#L60 "支持生成任务的可追踪执行、目标键完整性、引用绑定及可见范围检查。") 初稿随后由独立 verifier 逐篇复核，只有 accepted 文档才发布；失败目标最多进行四轮定向修订。[独立复核与定向修订 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "支持只有通过独立复核的文档才能发布，以及失败目标最多四轮定向修订。") 发布前仓库再次核对所有依赖，随后写入不可变文章修订并原子切换 head。[不可变文章发布 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前依赖复核、内容寻址修订、事务内 head 切换及问题状态更新。")

<a id="lifecycle"></a>
## 失效、回答与分层知识

材料摘要或子文章修订变化时，`refresh` 会沿文章依赖递归传播失效，使受影响 head 不再 current，但保留历史修订。[依赖失效传播 ↗](../../../apps/server/src/knowledge/repository.ts#L144 "支持材料或子知识变化递归使相关 head 失去 current 状态，同时不删除历史修订。") 用户回答未决问题时，回答先作为新的手工原始 Revision 保存，再使对应知识失效；后续分析会把该回答加入固定输入重新核对。[用户回答进入再分析 ↗](e5a00f71eb3b9c04183300900af72d54d39599d69b8a20785ec7260e4f963a1d.md#invalidation-answer "支持回答先保存为原始捕获、标记知识失效，并在后续分析中作为固定补充材料使用。") 多篇已复核知识可继续综合为模块或主题章节，数量较多时分片处理，并保留对子文章的固定引用，而不是把派生总结冒充独立依据。[分层知识综合 ↗](../../../apps/server/src/knowledge/pipeline.ts#L201 "支持仅选择 current 子文章、分片综合、保留文章引用并按上下文预算选择原始材料范围。")

<a id="interfaces_limits"></a>
## 阅读、恢复、检索与当前限制

API 提供文章、材料、引用、问题、搜索和显式分析入口；分析要求 Agent 可用、所选 revision 仍可解析，并以进程内状态避免同一路由对象重复启动。[知识 API 与分析生命周期 ↗](475058334ffc659aacefe4563ad15d0681a233ebb9f997fe364aa9919e3c79b3.md#analysis_lifecycle "支持文章、材料、问答、搜索和显式分析接口，并揭示当前互斥仅由进程内运行变量承担。") 发布资产可输出稳定命名的 JSON 与 Markdown，并按文章依赖顺序恢复；解析失败和未解依赖的诊断并非都写入导入状态表。[知识资产导出与恢复 ↗](4d47a4c8c95e844eb1c679f4e308fbf24554dd35e94cef71db8b04afe2d1368f.md#restore "支持 JSON、Markdown 双输出和依赖有序恢复，同时界定解析失败与未解依赖诊断的持久化范围。") 检索只在 current 知识中匹配文字，再核验整条依赖链并沿引用定位原始 Fragment；递归深度、初始文章数和精确引文定位均有限，且没有语义匹配或跨修订位置续接。[派生知识引导原始证据召回 ↗](c1d016bfceaa9ad6e811622ceb90acc5a8a4c40816edc2c9bb6689fa263f00e1.md#limits "支持 current 文章匹配、依赖核验、原始 Fragment 回溯，并说明深度、数量和精确引文定位限制。")

<a id="progress"></a>
## 已具备能力与演进重点

目前已经形成从固定材料、角色生成、独立复核、不可变发布、依赖失效，到阅读与原始证据回溯的闭环，并支持把有依据的问题交给用户回答或转为待办。[问题回答与待办创建 ↗](../../../apps/server/src/knowledge/repository.ts#L169 "支持把知识中的未决问题保存为用户回答或显式转换为现有任务系统待办。") 仍需明确多进程互斥、导出原子性及搜索定位：这些不阻塞当前单实例工作流，但会影响多副本部署、发布消费者的一致性，以及事实召回能否统一走原始证据合同。[知识 API 与分析生命周期 ↗](475058334ffc659aacefe4563ad15d0681a233ebb9f997fe364aa9919e3c79b3.md#analysis_lifecycle "支持文章、材料、问答、搜索和显式分析接口，并揭示当前互斥仅由进程内运行变量承担。")[知识资产导出与恢复 ↗](4d47a4c8c95e844eb1c679f4e308fbf24554dd35e94cef71db8b04afe2d1368f.md#restore "支持 JSON、Markdown 双输出和依赖有序恢复，同时界定解析失败与未解依赖诊断的持久化范围。")[派生知识引导原始证据召回 ↗](c1d016bfceaa9ad6e811622ceb90acc5a8a4c40816edc2c9bb6689fa263f00e1.md#limits "支持 current 文章匹配、依赖核验、原始 Fragment 回溯，并说明深度、数量和精确引文定位限制。")
