# knowledge · 模块理解

knowledge 模块把不可变捕获修订组织为可追溯、可复核、可失效的知识文章；派生正文服务于阅读和召回导航，最终仍回到固定原始证据。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责与证据边界

该模块位于原始捕获与助理使用之间：它排除派生修订，将文本、链接、图片和有限来源属性整理成带摘要的固定材料；知识文档必须让每节包含内联引用，并校验引用目标、材料行区间及精确引文。[固定材料与引用校验 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持排除派生修订、构造固定材料，以及正文内联引用、目标存在、行区间和精确引文等证据约束。") 模型只选择证据位置，宿主从固定材料复制短引文，再由独立角色检查语义支持性，因此派生正文可以组织解释，却不是新的独立事实权威。[宿主绑定固定原文 ↗](../../../apps/server/src/knowledge/repository.ts#L74 "支持由模型选择定位范围、宿主复制固定短引文，并将语义正确性交给独立角色复核。")

<a id="generation"></a>
## 生成、复核与版本发布

流水线按图片、会话来源或代码扩展名选择分析角色，并构造只含获准行段、图片、固定修订元数据及派生文章标记的上下文。[分析角色与限定上下文 ↗](../../../apps/server/src/knowledge/pipeline.ts#L15 "支持按材料形态选择分析角色，以及只装载指定行段、图片和固定来源元数据。") 每次 `runRole` 请求会入列或复用持久作业；若同输入作业已成功则直接读取既有输出，只有尚未成功的待处理作业才由 worker 调用网关，并保存输出与完整 trace。[持久作业复用与运行追踪 ↗](../../../apps/server/src/knowledge/pipeline.ts#L60 "支持请求入列、成功作业直接复用、待处理作业调用网关，以及输出和 trace 的保存。")

草稿必须恰好覆盖目标键；宿主绑定引文后校验正文引用、目标和可见行段范围。[知识批次与可见范围校验 ↗](../../../apps/server/src/knowledge/pipeline.ts#L96 "支持目标键完整覆盖、宿主绑定引文、文档校验及材料引用不得越过所见行段。") 随后独立 verifier 复核，整个写作与复核循环最多四轮；只有 accepted 文档才发布，初稿被拒后最多重写三次。先前“被拒内容最多修订四轮”的结论已被替代。[四轮写作与独立复核 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "支持最多四轮写作复核、独立 verifier、仅发布 accepted 文档，以及拒绝后继续修订的边界。") 发布前仓库再次比较全部依赖，以内容摘要形成不可变修订并更新 head；依赖变化会逐层标记过期，但历史修订仍被保留。[不可变发布与过期传播 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前比较依赖、生成内容寻址修订、更新 head，并在依赖变化后逐层传播失效状态。")

<a id="reading"></a>
## 阅读、制品与检索关系

阅读 API 提供文章、固定版本引用和材料详情；引用目标缺失时返回不可操作原因。代码材料页从相对 import 建立确定性模块链接，但这只能证明文件依赖。[文章引用与材料阅读接口 ↗](../../../apps/server/src/knowledge/api.ts#L20 "支持文章和固定材料读取、按保存的依赖版本解析引用，以及相对 import 形成确定性模块依赖链接。") 问题 API 提供列表、回答和转任务入口；回答的实际持久化与失效行为由仓库完成。[问题 HTTP 入口 ↗](../../../apps/server/src/knowledge/api.ts#L75 "支持问题列表、回答和转任务三个接口；附近表述只据此确认入口存在。") 显式分析入口校验 Agent 配置、运行互斥及材料版本，再异步启动流水线。[显式知识分析入口 ↗](../../../apps/server/src/knowledge/api.ts#L87 "支持 Agent 配置检查、运行互斥、材料版本校验、异步启动和关闭清理。")

制品层以稳定名称导出 JSON 与 Markdown，并按子文章依赖恢复；不合规或依赖变化分别记录 rejected、stale 或 missing。[知识制品导出与恢复 ↗](../../../apps/server/src/knowledge/artifacts.ts#L21 "支持 JSON、Markdown 双格式导出、按文章依赖恢复，以及 rejected、stale、missing 状态处理。") 检索桥接只查询当前知识 head，沿引用递归回到固定原始片段，并受候选数、深度和输出数限制。[当前知识的证据回溯 ↗](../../../apps/server/src/knowledge/retrieval.ts#L8 "支持只查询当前 head、限制候选数量，并沿文章和材料引用递归回到原始片段的流程与上限。") 派生正文仅用于召回导航，最终候选仍是原始 fragment，助手可见性过滤还需后续执行。[派生正文的召回边界 ↗](../../../apps/server/src/knowledge/retrieval.ts#L1 "支持派生正文只引导召回、返回值始终是原始固定片段，且助手可见性规则仍需后续执行。")

<a id="limits"></a>
## 搜索差异与待核验流程

需要区分两条搜索路径：阅读 API 的章节搜索遍历仓库返回的 head 正文，做大小写无关的分词子串匹配并最多返回 50 条；它未先刷新，也未按 `current` 过滤，可能返回尚未刷新或已非当前的正文。[API 章节子串搜索 ↗](../../../apps/server/src/knowledge/api.ts#L82 "支持章节搜索遍历仓库 head、最多返回 50 条，并表明该路径没有刷新或 current 过滤。") 这不同于只从当前 head 回溯原始证据的检索桥接。

用户回答会被捕获为新的原始修订，问题转为 answered，并立即使关联知识失效；仓库方法本身没有启动重新分析。[回答捕获与知识失效 ↗](../../../apps/server/src/knowledge/repository.ts#L169 "支持将答案保存为原始修订、更新问题状态并使关联文档失效，同时界定仓库方法本身未启动重新分析。") API 保存答案后仅调用可选的 `onAnswer` 回调，因此自动重核验、重试及失败通知仍取决于当前材料未展示的应用装配。[回答后的可选回调 ↗](../../../apps/server/src/knowledge/api.ts#L76 "支持 API 在保存答案后仅调用可选 onAnswer 回调，无法据此确认重核验一定被调度。")
