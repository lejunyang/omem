# 可追溯知识的生成、阅读与证据回查

知识模块把不可变原始材料组织成经独立复核、带固定版本引用的文章，并负责版本发布、历史恢复、阅读接口与证据召回。派生正文用于解释和引导检索，最终依据仍回到固定材料或原始 Fragment；当前实现以单用户 SQLite 为基础，任务重启恢复、检索调用契约及文件发布语义仍需进一步确认。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为什么需要知识层

知识层把捕获系统中的不可变 revision 转换为适合阅读和问答的材料视图，汇集文本、链接、图片及来源信息，同时排除已标记为派生的内容，并以稳定摘要固定材料身份。参考 [原始 revision 转换为知识材料 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "支持知识材料排除派生内容、汇集文本和图片，并以稳定摘要固定材料身份。")

角色上下文必须包含原始材料；已有文章只能作为带版本的辅助知识，并明确不是独立证据。因此，**原文负责证明，文章负责解释和组织**，所有结论都能沿引用回到固定输入。参考 [固定材料上下文 ↗](../../../apps/server/src/knowledge/pipeline.ts#L30 "支持角色上下文必须包含原始材料，并把已有文章明确标为派生辅助知识。")；延伸阅读：[可追溯知识仓库 ↗](e5a00f71eb3b9c04183300900af72d54d39599d69b8a20785ec7260e4f963a1d.md#purpose "提供材料转换、原始证据边界和知识仓库职责的子知识下钻入口。")

<a id="generation"></a>
## 从材料分析到独立复核发布

系统先根据图片、会话来源或代码文件类型选择分析角色，再把材料范围、模型配置、预算和角色包版本固化到任务中，由持久化 worker 执行并保存运行记录。参考 [分析角色选择 ↗](../../../apps/server/src/knowledge/pipeline.ts#L15 "支持依据图片、会话来源和代码文件类型选择分析角色。")、[持久化角色任务执行 ↗](../../../apps/server/src/knowledge/pipeline.ts#L60 "支持任务输入固化、既有结果复用、worker 执行及运行记录保存。")

```mermaid
flowchart LR
  A[固定原始材料] --> B[角色分析与写作]
  B --> C[独立语义复核]
  C -->|通过| D[校验依赖与内联引用]
  D --> E[发布不可变知识版本]
```

写作与复核最多迭代四轮，只有通过的文档才会记录固定依赖、生成来源和复核来源并进入发布。参考 [写作与独立复核循环 ↗](../../../apps/server/src/knowledge/pipeline.ts#L113 "支持最多四轮修订、逐目标独立复核以及仅发布通过文档。") 仓库在发布前重新比较材料摘要和子文章版本，校验正文引用，再以事务写入不可变版本、当前指针、开放问题和变更记录。参考 [知识版本事务发布 ↗](../../../apps/server/src/knowledge/repository.ts#L118 "支持发布前核对固定依赖、校验文档，并事务写入不可变版本、当前指针和问题记录。")；延伸阅读：[独立复核与发布流程 ↗](b22d52764b13721657e246604945c1dd1a082a38d3efee3d14e3d808709bcad5.md#review-and-publication "提供写作、复核、修订和发布关系的子知识下钻入口。")

<a id="reading"></a>
## 阅读、历史恢复与原始证据召回

阅读接口提供文章和单条引用，并按文章生成时保存的依赖版本解析目标；固定文章或材料版本不可用时，引用仍保留说明，但会被标记为不可操作。参考 [固定版本引用解析 ↗](../../../apps/server/src/knowledge/api.ts#L20 "支持文章和单条引用按生成时保存的依赖版本解析，并在目标不可用时禁用操作。") 材料接口返回原文、图片和关联知识，并对代码中的相对 import 做路径规范化和有限扩展名匹配，生成确定性的模块导航。参考 [材料读取与模块导航 ↗](../../../apps/server/src/knowledge/api.ts#L46 "支持材料响应字段，以及相对 import 经路径规范化和扩展名候选匹配后形成模块导航。") 用户还可查看问题、提交回答或把问题转为待办。参考 [问题回答与待办入口 ↗](../../../apps/server/src/knowledge/api.ts#L75 "支持查看问题、校验并保存用户回答，以及把问题转换为待办。")

文章可发布为 JSON 与 Markdown，内联引用会转换为章节或源码链接。参考 [文章发布与内联链接 ↗](../../../apps/server/src/knowledge/artifacts.ts#L8 "支持 JSON、Markdown 双格式发布、内联引用链接转换及直接写入目标文件的当前实现。") 启动恢复会扫描 JSON 产物，并等待匹配版本的子文章先恢复；通过来源和复核校验后，产物被归类为 restored、stale、rejected 或 missing。参考 [知识产物依赖恢复 ↗](../../../apps/server/src/knowledge/artifacts.ts#L32 "支持恢复时优先处理匹配版本的子文章、校验产物并分类记录恢复状态。")

派生正文参与召回时，系统先核对依赖，再沿文章引用递归定位固定材料行段及与其重叠的原始 Fragment，不直接把文章当作最终证据。参考 [知识引导的原始证据召回 ↗](../../../apps/server/src/knowledge/retrieval.ts#L33 "支持依赖有效性检查、文章引用递归及固定材料行段到原始 Fragment 的映射。")；延伸阅读：[引用回溯流程 ↗](c1d016bfceaa9ad6e811622ceb90acc5a8a4c40816edc2c9bb6689fa263f00e1.md#flow "提供依赖校验与原始 Fragment 召回机制的子知识下钻入口。") 开发环境还能把仓库知识及其历史依据接入个人 Store，同时保持评审运行库与个人数据库分离。参考 [开发环境知识合流 ↗](../../../apps/server/src/knowledge/development.ts#L14 "支持仓库当前知识、历史文章和被引用旧材料接入个人 Store，同时保持评审运行库隔离。")

<a id="progressLimits"></a>
## 当前能力与边界

轻量搜索只对章节标题和正文做分词后的包含匹配；异步整理入口会校验 Agent 配置、固定 revision 和并发状态，并把最近结果保存在路由进程内。参考 [搜索与异步整理入口 ↗](../../../apps/server/src/knowledge/api.ts#L82 "支持轻量文本搜索、固定 revision 校验、异步整理以及路由进程内运行状态的受限结论。") 当前底层明确是单用户 SQLite，团队级租户强制隔离仍属于后续迁移。参考 [单用户存储边界 ↗](../../../apps/server/src/store.ts#L4 "支持当前 SQLite 实现是单用户基础，团队级存储和租户强制隔离仍待迁移。")

代码导航虽然能确认相对 import 指向已收录模块，但底层解析器按单文件 AST 工作，不做跨文件类型求解，名称级调用只属于候选，不能据此宣称跨文件调用已经确认。参考 [材料读取与模块导航 ↗](../../../apps/server/src/knowledge/api.ts#L46 "支持材料响应字段，以及相对 import 经路径规范化和扩展名候选匹配后形成模块导航。")、[单文件代码解析边界 ↗](../../../apps/server/src/code/parse.ts#L1 "支持解析器不做跨文件类型解析，名称级调用只能标记为候选。") 发布文件当前直接写入目标路径；恢复循环也会把无法继续处理的依赖统一报告为“子知识尚不可用”，尚不能区分循环依赖、永久缺失或扫描上限。参考 [文章发布与内联链接 ↗](../../../apps/server/src/knowledge/artifacts.ts#L8 "支持 JSON、Markdown 双格式发布、内联引用链接转换及直接写入目标文件的当前实现。")、[知识产物依赖恢复 ↗](../../../apps/server/src/knowledge/artifacts.ts#L32 "支持恢复时优先处理匹配版本的子文章、校验产物并分类记录恢复状态。")
