# 知识 API 的固定引用与历史材料回归测试

该测试以临时单用户存储和真实 Fastify 路由验证一条完整知识读取链路：手工材料被发布为带行内引用和待确认问题的知识文章；材料更新后，文章仍能解析到原固定版本；问题可转成任务；缺少模型配置时分析请求明确失败；被新版本替代的图片资产仍可读取。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="scenario"></a>
## 模拟从手工材料到知识文章的使用场景

测试创建临时目录、真实 `Store` 与 Fastify 实例，并注册知识路由，因此验证的是 HTTP 接口、知识仓库和存储协作，而非孤立函数。它捕获一条“发布前核对回滚步骤”的手工材料，再构造包含行内引用和“由谁核对”问题的知识文档，经引用绑定后发布为已复核文章。参考 [手工材料发布流程 ↗](../../../apps/server/tests/knowledge-api.test.ts#L11 "支持测试使用临时存储注册路由、捕获手工材料并发布带引用和问题的知识文章这一场景。")

测试直接依赖存储、路由、仓库引用绑定及知识合同，说明这些模块共同组成被测链路；但仅凭导入与本文件调用，不能推断它们内部更深的跨文件调用关系。参考 [被测模块依赖 ↗](../../../apps/server/tests/knowledge-api.test.ts#L6 "支持测试文件显式依赖 Store、知识路由、引用绑定函数和知识文档合同。")

<a id="citation_and_action"></a>
## 验证固定引用与问题转任务

读取文章时，测试要求引用同时具有可操作状态、人类可读标签和引用理由；随后通过引用接口确认它解析到材料的固定摘要。即使同一外部来源后来捕获了新计划，携带旧摘要读取时仍返回原文，并标记为非当前版本。这验证了“当前材料更新”不会破坏既有知识所依赖的历史证据。参考 [固定版本引用断言 ↗](../../../apps/server/tests/knowledge-api.test.ts#L19 "支持文章引用可操作、引用解析到固定材料摘要，以及材料更新后旧原文仍可读取且非当前的论断。")

同一 API 还列出知识问题，并允许把问题显式转为任务；断言既检查响应含任务标识，也检查存储中确实新增任务。对于分析入口，本测试只覆盖未配置模型时返回 503，未证明配置模型后的生成、复核或发布流程可用。参考 [问题任务与无模型响应 ↗](../../../apps/server/tests/knowledge-api.test.ts#L26 "支持问题可转为真实任务，并明确限定分析接口只验证无模型时返回 503。")

<a id="historical_assets"></a>
## 保留被替代版本中的图片资产

测试先捕获一张 PNG 图片并取得资产标识，再用文本材料更新相同外部来源。之后旧图片仍可通过资产接口读取，响应状态为 200，且媒体类型保持 `image/png`。这说明历史版本中的二进制证据不会因来源头版本变化而立即失效。参考 [历史图片读取 ↗](../../../apps/server/tests/knowledge-api.test.ts#L31 "支持图片来源被新版本替代后，旧 PNG 资产仍能成功读取并保留媒体类型。")

边界上，该用例只检查单个 PNG 的成功读取，没有覆盖不存在的资产、其他图片格式、权限隔离、损坏文件或并发更新。临时目录、应用和数据库在 `finally` 中关闭并删除，使测试之间保持隔离，但也意味着它没有验证服务重启后的持久化行为。参考 [测试资源清理 ↗](../../../apps/server/tests/knowledge-api.test.ts#L37 "支持测试最终关闭 Fastify 与存储并删除临时目录，从而保持用例隔离。")
