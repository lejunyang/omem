# 来源归属、飞书身份与派生内容隔离的回归测试

这组服务端回归测试验证三条安全边界：聚合对话仍保留逐片段来源，飞书外部身份只有在有效绑定下才映射为资料所有者，以及派生的 Agent 内容不会再次触发事实提取。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="part-provenance"></a>
## 聚合时保留每位说话者的证据身份

多人对话会被合并为同一修订，但不能因此把整段内容错误归给某一个人。测试先写入两位说话者的消息，再触发聚合，断言顶层身份为空，同时每个文本片段仍保留各自的外部身份、事件时间和事件编号。参考 [多人消息的逐片段来源 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L60 "支持聚合后顶层身份为空、各片段仍保留说话者与事件时间的断言。")

即使两个人说出完全相同的“同意”，两份证据也必须同时存在，不能按文本去重后丢失说话者。参考 [相同文本不合并证据 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L109 "支持不同说话者表达相同内容时仍保留两份片段的行为。") 这一行为与公共合同中为文本、图片和链接片段提供可选来源信息的设计一致；字段允许为空，也兼容缺少元数据的历史内容。延伸阅读：[片段来源数据合同 ↗](../../../packages/contracts/src/index.ts#L4 "说明逐片段来源字段适用于多种内容类型，并允许历史数据缺少这些字段。")

<a id="owner-resolution"></a>
## 外部身份决定任务能否自动处理

飞书场景通过测试夹具建立连接、版本、所有者绑定和群聊采集目标，再把群消息交给实时事件入口。夹具还创建加密凭据引用，但并未连接真实飞书网络。参考 [飞书绑定测试夹具 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L142 "支持测试通过数据库记录和加密凭据引用构造连接、所有者绑定及群聊目标。")

绑定所有者发送消息时，捕获信封同时保留外部身份并解析出规范所有者，后续任务提案评估得到自动应用策略，且不出现“所有者未验证”原因。参考 [绑定所有者的策略评估 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L253 "支持外部身份解析为规范所有者后获得自动应用策略的完整断言链。") 相同内容若由普通群成员发送，则只保留其外部用户身份，不伪装成所有者；策略不得自动应用，并明确记录身份未验证。参考 [普通群成员的安全边界 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L299 "支持未绑定成员不映射为所有者、任务线索不能自动应用的结论。")

<a id="derived-isolation"></a>
## 阻止派生内容形成重复提取回路

Agent 会话既可能是用户交互形成的原始材料，也可能是系统生成的派生结果。测试分别捕获两类输入：原始会话会创建提取任务，派生会话不创建任务，并最终确认队列中只有一个事实提取作业。参考 [原始与派生会话分流 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L349 "支持只有原始 Agent 会话创建事实提取作业、派生会话不入列的断言。") 这条边界用于避免系统把自身产物再次当成独立证据反复提取。

测试直接组合了存储、输入聚合、实时事件入口和记忆评估服务；`Store` 构造时确实装配数据库迁移、任务仓库、输入聚合器及运行请求等组件。参考 [存储组件装配 ↗](../../../apps/server/src/store.ts#L38 "说明测试所用 Store 与数据库迁移、任务仓库、输入聚合器和运行请求仓库之间的源代码关系。") 不过现有断言只覆盖任务是否入列和策略评估结果，没有证明提取任务被实际执行，也没有验证任务实体最终写入。
