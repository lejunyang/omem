# 批次二修复：来源保真、身份解析与派生隔离测试

该测试集验证聚合输入不会丢失逐段说话人信息，Lark 外部身份只有经绑定后才映射为规范 owner，并确保派生 Agent 内容不会再次触发事实提取。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="part-provenance"></a>
## 聚合后的逐段来源保真

测试先构造带说话人、事件时间和事件编号的聊天输入，再通过 `InputAggregator` 聚合并交给 `Store.capture`。当两名说话人进入同一修订时，顶层 actor 被置空，但每个 part 仍保存各自的外部身份、时间与事件编号；即使两人文本都为“同意”，也不得按文本去重而损失一份证据。[逐段说话人与重复文本断言 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L60 "支持多说话人聚合时顶层身份置空、逐段 provenance 保留以及相同文本不去重的说明。")

这覆盖了多说话人聚合的关键回归，但没有验证图片、链接、引用或转发 part，也未覆盖历史数据缺少逐段 provenance 时的兼容表现。

<a id="lark-owner-resolution"></a>
## Lark 身份与自动应用策略

测试直接写入连接、版本、绑定和目标记录，然后让 `LarkEventInbox.processMessage` 处理群消息。绑定 owner 的 `ou_*` 身份会同时保留外部标识并解析为规范主体，随后任务提案可进入 `auto_apply`；普通群成员只保留外部用户身份，主体为空，策略必须包含 `owner_not_verified` 且不能自动应用。[Lark owner 与群成员策略对照 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L253 "支持绑定 owner 可规范化并自动应用、普通成员必须保持未验证状态的论断。")

这证明收件箱、捕获聚合与 `MemoryService.evaluate` 之间的身份链路，但数据库夹具绕过了真实建连流程，也未验证 Lark SDK 网络事件、绑定轮换、伪造签名或失效连接。

<a id="derived-loop"></a>
## 原始与派生 Agent 会话隔离

同样内容分别以 `producerKind=original` 和 `derived` 捕获：原始会话产生处理 job，派生会话不产生 job，最终仅存在一个 `extract_claims` 作业。该断言用于阻断模型生成内容被重新当作独立原始证据而形成递归提取。[原始与派生会话作业断言 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L349 "支持只有 original Agent 会话进入 extract_claims、derived 会话被隔离的说明。")

测试只检查作业数量及是否为空，没有断言作业载荷、幂等键、重试行为，也没有覆盖其他来源类型的 derived 输入。
