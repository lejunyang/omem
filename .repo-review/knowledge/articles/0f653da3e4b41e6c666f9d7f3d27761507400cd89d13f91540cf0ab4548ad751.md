# Batch2 来源保真、Lark 身份绑定与派生会话回流测试

该测试文件验证三项关键边界：聚合输入保留逐片段来源；仅将已绑定的 Lark 身份解析为规范 owner；派生 Agent 会话不再次触发事实抽取。测试向策略评估直接注入 fixture 复核结果，并未运行真实 verifier、执行任务应用或验证通知发送。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="part-provenance"></a>
## 聚合时保留每位说话者的证据身份

测试将两名说话者的聊天输入聚合为同一 revision。聚合后顶层 `actorId` 为空，各 part 分别保留外部身份、事件时间和事件号，避免多人内容被错误归给单一主体。[多人聚合来源断言 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L60 "支持多人输入聚合后顶层身份为空、各 part 分别保留说话者和事件信息。") 即使两人说出完全相同的“同意”，系统仍留下两个 part，说明证据不能只按文本去重。[同文不同说话者断言 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L109 "支持文本相同时仍按不同证据主体保留两个 part。")

合同为文本、图片和链接 part 提供可选的逐片段来源字段，并允许历史数据缺少这些元数据，从而兼顾来源保真与向后兼容。[逐片段来源合同 ↗](../../../packages/contracts/src/index.ts#L4 "解释各类 part 的来源字段及其历史兼容设计。")

<a id="lark-owner-resolution"></a>
## Lark 外部身份到规范所有者的安全映射

fixture 以随机 32 字节本地密钥创建加密凭据，并直接写入 active connection、版本 1、active binding 和群目标。[Lark 绑定测试装配 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L144 "支持测试使用随机本地密钥并手工建立 active connection、版本、绑定和群目标的范围说明。") 已绑定的 `ou_owner` 被解析为规范主体 `owner`，同时保留外部身份和绑定验证来源；随后测试向 `MemoryService.evaluate` 直接注入一份 `semantic_verdict: supported` 的 fixture 复核结果，得到 `auto_apply` 策略。[已绑定所有者策略评估 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L253 "支持已绑定身份解析为 owner，并明确测试直接向 evaluate 注入 fixture 复核结果、只断言策略而未调用 verifier 或 apply。")

这替代此前“经 fixture verifier 判为 supported”的不准确结论：该用例只是模拟 supported 复核结论，没有实例化或调用 verifier。未绑定成员仍保留普通用户身份，但规范主体与验证来源为空，并因 `owner_not_verified` 不能自动应用。[未绑定群成员安全边界 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L299 "支持未绑定成员不获得规范主体，且策略包含 owner_not_verified 的对照结论。") 该边界符合合同中“始终保留外部身份，仅在确认绑定后填写规范主体”的约束。[外部身份与规范主体合同 ↗](../../../packages/contracts/src/index.ts#L49 "解释外部身份保留与规范主体仅在绑定确认后写入的设计约束。")

<a id="agent-loop-boundary"></a>
## 阻断派生内容回流并明确测试范围

Agent capture 仅改变 `producerKind`：原始会话创建 `extract_claims` 作业，派生会话不创建，最终作业列表只有一项。[原始与派生会话作业断言 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L349 "支持只有原始 Agent 会话创建 extract_claims 作业、派生会话不重复入列。") 这可阻止模型或 Agent 的派生内容再次被当作独立原始证据抽取，降低自我强化风险。

本文件覆盖临时 SQLite、手工 seed、合成事件以及注入复核结果后的策略评估；它没有执行 proposal apply，也未查询任务实体或通知 outbox。[已绑定所有者策略评估 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L253 "支持已绑定身份解析为 owner，并明确测试直接向 evaluate 注入 fixture 复核结果、只断言策略而未调用 verifier 或 apply。") Lark 模块虽定义真实连接适配器和媒体下载端口，但这些接口未在本测试中实例化。[Lark 实时连接与媒体端口 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L38 "说明生产连接和媒体下载另有独立接口，从而界定本测试未覆盖真实网络适配器。") 环境密钥加载由 `fromEnvironment` 提供，而 fixture 直接向构造器传入随机密钥，因此该用例也不证明环境密钥加载可用。[环境密钥加载入口 ↗](../../../apps/server/src/integrations/lark/secret-store.ts#L47 "支持环境变量密钥由 fromEnvironment 读取，并与测试直接传入随机密钥的做法区分。")

## 尚待验证的行为边界

现有断言能确认身份解析和策略选择，却不能证明 `auto_apply` 后的任务写入、通知发送及失败状态处理。[已绑定所有者策略评估 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L253 "支持已绑定身份解析为 owner，并明确测试直接向 evaluate 注入 fixture 复核结果、只断言策略而未调用 verifier 或 apply。") 此外，fixture 只覆盖 active、版本 1 且目标存在的绑定，未展示 inactive、superseded、连接版本不匹配或目标缺失时应采用哪个绑定快照。[Lark 绑定测试装配 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L144 "支持测试使用随机本地密钥并手工建立 active connection、版本、绑定和群目标的范围说明。")[未绑定群成员安全边界 ↗](../../../apps/server/tests/batch2-fixes.test.ts#L299 "支持未绑定成员不获得规范主体，且策略包含 owner_not_verified 的对照结论。")
