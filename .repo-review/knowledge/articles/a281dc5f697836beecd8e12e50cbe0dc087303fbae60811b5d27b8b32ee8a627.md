# 知识生成管线的发布、恢复与失效测试

该测试以临时 SQLite 数据库和受控角色运行器验证知识管线：知识必须经独立复核才能发布；拒绝结果、分析期间变化的输入不得晋升；已保存产物可恢复；材料或文章依赖变化会使下游知识失效。它还覆盖分析角色路由、修订续跑以及分层综合，但不证明真实 ACP、并发和进程崩溃场景可用。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 测试解决什么风险

知识文章由原始材料推导而来，若未经复核、引用未绑定固定来源或输入已变化，就可能把过期解释当成事实。本测试创建临时存储、知识仓库与角色网关，并以受控返回值模拟分析、复核和修订，使发布约束能够稳定断言。参考 [受控测试环境 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L14 "说明测试创建临时数据库、替换角色运行方法并把管线并发固定为一，支持测试范围与局限的判断。")

仓库层校验每节必须包含行内引用，且所有声明的引用都必须进入叙述；两类目标随后分别处理：文章引用校验目标文章及可选章节存在，材料引用才校验行号范围与引文确实位于原材料。语义支持性则由独立模型角色复核。延伸阅读：[知识引用校验边界 ↗](../../../apps/server/src/knowledge/repository.ts#L41 "支持行内引用通用约束，以及文章目标与材料目标采用不同校验规则的准确表述。")

<a id="publication"></a>
## 复核后发布与失败续跑

主流程是固定材料先生成草稿，再由独立会话复核；接受后才发布，拒绝则保留草稿与反馈供后续修订。测试确认生成与复核使用不同会话，宿主会绑定精确原文；即使知识头投影被删除，再次分析仍复用持久结果和原修订，不重复运行角色。参考 [复核发布与持久恢复 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L39 "支持独立会话复核、引文绑定、投影丢失后复用持久结果等断言。")

被语义复核拒绝的草稿不会进入知识列表；下一次尝试会把旧草稿及反馈交给刷新角色。若分析期间原始材料产生新修订，管线以输入变化失败并阻止发布，避免旧结论覆盖新证据。参考 [拒绝、输入变化与修订恢复 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L53 "支持拒绝结果不发布、输入变化阻断发布，以及携带旧草稿和反馈继续修订的行为。")

<a id="dependencies"></a>
## 依赖隔离、综合与级联失效

同级文章默认只依赖各自材料，因此一份笔记变化不会使无关文章过期；若调用方明确提供另一材料作为背景，该依赖会被记录，背景变化便使文章失效。参考 [文章依赖隔离 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L81 "支持同级文章默认隔离、显式背景依赖被记录并参与失效判断。")

模块综合可从完整固定材料中引用此前未使用但真实存在的新行；综合章节被拒后，也会从匹配的已审草稿继续修订。更高层概览接收已复核文章而不展开全部深层原文，同时保留文章依赖；底层来源变化后，失效状态沿依赖传播。参考 [固定材料综合与修订 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L101 "支持综合阶段读取固定全文中的新引用行，以及被拒综合章节从匹配草稿继续修订。")、[分层综合与失效传播 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L123 "支持概览使用已复核文章而不展开深层原文，并保留文章依赖和级联失效。")

<a id="routing_limits"></a>
## 角色路由与测试边界

路由断言区分普通 Lark 文档与带会话标识的 Lark 对话，并把常见 Git 或文件来源代码扩展名交给代码分析角色；实际规则还优先把含图片的材料分派给视觉分析角色。参考 [材料分析角色断言 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L73 "支持 Lark 文档、对话以及普通导入代码被分派到不同分析角色。")、[分析角色选择规则 ↗](../../../apps/server/src/knowledge/pipeline.ts#L15 "补充测试对应的实际路由优先级，包括图片、对话和代码扩展名判断。")

这些用例验证的是单并发、受控角色输出和数据库行为。角色网关已被 mock，因此没有证明真实 ACP 进程、模型能力协商、CLI 故障或输出修复链路可用；也未覆盖多 worker 竞争、进程中断、图片资产异常以及非法引用输出的完整管线行为。参考 [受控测试环境 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L14 "说明测试创建临时数据库、替换角色运行方法并把管线并发固定为一，支持测试范围与局限的判断。")
