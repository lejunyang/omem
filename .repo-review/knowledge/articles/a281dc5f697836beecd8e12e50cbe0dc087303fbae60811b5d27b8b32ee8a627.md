# 知识分析、独立复核与恢复流程测试

用可控角色运行时覆盖分析与独立复核、固定引文绑定、过期输入拒绝、语义退回续跑、角色选择及综合章节恢复。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="fixture-contract"></a>
## 可控双角色运行环境

测试夹具建立临时存储、知识仓库和角色运行网关，并用模拟运行结果区分知识生成者与复核者。夹具可在分析中途改变材料，也可切换复核接受或拒绝；每次运行产生独立会话标识，并仍经过角色输出校验，使测试能够观察真实管线状态转换而不依赖外部模型。[知识管线测试夹具 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L14 "支持材料变更、复核切换、角色输出校验和独立运行追踪的测试设计。")

<a id="publish-safety"></a>
## 发布、复用与过期保护

正常分析必须经过两次角色调用后才发布，材料引用的精确原文由宿主绑定，生成与复核会话必须不同。删除知识 head 投影后再次分析会复用持久输出，不重复调用模型。复核拒绝或分析期间来源发生变化时均不得发布：前者返回失败，后者以输入已变化错误终止。[发布与过期输入保护 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L39 "支持独立复核后发布、固定引文绑定、持久结果复用以及拒绝和输入变化不晋升的断言。")

<a id="revision-and-routing"></a>
## 退回续跑与分析角色选择

语义复核失败后再次分析，会把精确旧草稿和复核反馈交给 `knowledge-refresher`，接受后才形成当前文章。角色路由还区分普通 Lark 文档、带会话标识的 Lark 对话，以及从 Git 或文件来源导入的常见代码文件，避免不同材料类型共用错误分析合同。[语义退回与角色路由 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L62 "支持以原草稿和反馈续跑 refresher，并区分文档、对话及代码分析角色。")

<a id="synthesis"></a>
## 综合章节的证据与恢复

当固定来源大小允许时，综合阶段可获得完整材料并引用新增的第二行，发布结果保存由宿主提取的精确引文。综合章节若被语义复核拒绝，后续重试同样从匹配的已审草稿进入 refresher；只有复核改为接受后，结果才成为当前版本。[综合章节引用与恢复 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L81 "支持综合阶段读取完整固定来源、绑定新增行引文以及从被拒草稿恢复后发布。")
