# 知识流水线的发布、恢复与依赖失效测试

该测试以临时 SQLite 存储和模拟角色网关验证知识流水线的关键语义：知识须经独立复核才发布；拒绝或输入变化不得晋升；被拒任务可携旧草稿恢复，合成任务也可走刷新角色；派生章节保持依赖边界并随底层证据变化失效。它还覆盖角色分派及固定原文引用绑定，但不证明真实 Agent CLI、并发执行或跨 revision 身份续接。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="fixture"></a>
## 测试夹具与验证范围

夹具为每个用例创建独立临时目录、SQLite `Store`、知识仓库、角色注册表和运行网关，并捕获一条手工原始材料；用例结束后关闭数据库并删除目录。[临时存储与原始材料夹具 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L12 "支持测试为每个用例建立隔离 SQLite、捕获固定材料并注册清理逻辑的说明。") 网关的 `run` 被 mock：分析或刷新角色返回带行号引用的知识文档，复核角色按开关接受或拒绝，同时构造不同 session id 的运行追踪。[模拟角色结果与运行追踪 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L20 "支持 mock 网关区分生成和复核输出、执行结构校验并构造会话追踪，因此界定测试证据范围。") 因而本文件主要验证流水线编排、持久化和合同校验，不代表外部 ACP/CLI 已完成真实联调。

<a id="promotion"></a>
## 独立复核、拒绝恢复与输入竞态

首组断言确认分析依次调用生成与独立复核；发布时空 `quote` 被绑定为固定原文，两个阶段的会话不同。即使知识头投影被删除，再次分析仍复用耐久输出和原 revision，不重复调用角色。[复核后发布与耐久复用 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L39 "支持独立复核、原文绑定、会话隔离以及投影丢失后复用既有 revision 的论断。") 若语义复核拒绝，仓库不发布文章；若分析期间材料产生新 revision，则以 `KNOWLEDGE_INPUT_CHANGED` 失败，避免旧输入结果晋升。[拒绝与输入变化阻止晋升 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L53 "支持语义拒绝和分析期间输入变化均不会产生已发布文章的边界行为。")

被拒的材料任务再次运行时，下一次生成角色为 `knowledge-refresher`，且任务上下文包含 `revisionRequest.previousDrafts`；现有断言没有进一步比较草稿或复核反馈的具体内容。[材料任务的拒绝恢复 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L62 "支持重试时使用 knowledge-refresher 且上下文具有 previousDrafts；该范围也表明测试未比较草稿和反馈的具体值。") 被拒的合成任务在重试时同样切换为 `knowledge-refresher`，成功结果被标记为当前版本。[合成任务的拒绝恢复 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L110 "支持合成失败后再次运行切换至 knowledge-refresher，并产生当前结果的说明。") 这替代了此前“已验证精确旧草稿与反馈”的较强结论。

<a id="routing-dependencies"></a>
## 角色路由与依赖隔离

角色分派测试区分普通 Lark 文档与带 `conversationId` 的会话，并将 Git 或文件来源中具有常见代码扩展名的标题识别为代码材料。[材料分析角色分派 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L73 "支持 Lark 文档、Lark 会话以及普通导入代码采用不同分析角色的说明。") 依赖测试说明文章默认只依赖自身材料：第一条材料更新不会让兄弟文章过期；只有显式提供 background 后才记录跨材料依赖，其后 background 更新会使引用方失效。[兄弟文章隔离与显式背景依赖 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L81 "支持默认依赖隔离、显式 background 依赖记录及其变化触发失效的论断。") 这里仅覆盖给定路由样例和串行场景，未验证图像优先级、全部扩展名或多 worker 竞争。

<a id="synthesis"></a>
## 分层合成、引用与失效传播

当固定原文可完整放入上下文时，模块合成能够引用新增的第二行，仓库将该行精确绑定进 `quote`。[完整固定原文支持新增行引用 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L101 "支持合成阶段引用第二行并由仓库绑定精确原文 quote 的行为。") 更高层 overview 合成接收已复核模块文章，并标注其为“派生知识而非独立证据”；测试确认深层原文尾部未被摊平进上层上下文，同时记录 article 依赖、调用独立 verifier，并在底层原文变化后使 overview 失效。[派生章节组合与失效传播 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L123 "支持上层合成不摊平深层原文、显式携带派生文章、独立复核及底层变化向上失效的说明。") 尚未覆盖超长材料分块边界、多个章节冲突、并发合成或跨 revision 身份续接。
