# 知识分析与独立复核流水线测试

通过模拟角色运行验证分析后复核、拒绝与输入漂移保护、失败续跑、持久成果复用及材料类型到分析角色的分派。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="fixture"></a>
## 受控角色运行环境

测试环境捕获一条手工材料，建立通用知识仓库、角色注册表和运行网关，并把网关调用替换为可控制的分析者或复核者结果；流水线并发度固定为一。[流水线模拟环境 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L14 "支持测试如何构造材料、仓库、角色网关以及可控分析和复核结果。") 模拟 trace 为生成和复核提供不同 session id，同时允许在首轮运行中修改来源或让复核者拒绝，从而精确触发关键保护分支。

<a id="promotion"></a>
## 发布、复用与拒绝保护

成功分析必须调用两个角色，引用 quote 被绑定为固定原文，生成与复核会话不同；删除知识 head 投影后重跑不会再次调用模型，并恢复相同文章修订。[复核后发布与耐久复用 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L37 "支持双角色调用、固定引用、独立会话和投影丢失后不重跑模型的断言。") 若独立复核拒绝，或分析期间材料 head 变化，流水线都不得发布文章；后一情形明确返回 `KNOWLEDGE_INPUT_CHANGED`。[拒绝和输入变化保护 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L51 "直接断言复核拒绝及分析期间来源变化都不会晋升知识。")

<a id="resume-routing"></a>
## 续跑和角色分派边界

语义拒绝后再次运行会调用 `knowledge-refresher`，且任务携带先前草稿与复核反馈，接受后才产生文章。[语义拒绝续跑 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L60 "支持 refresher 使用先前草稿和反馈继续处理，而非丢弃失败上下文。") 分派测试还确认普通 Lark 文档走材料分析，带 conversation id 的 Lark 输入走会话分析，而 Git 或 file 来源的常见代码文件走代码分析。[分析角色选择 ↗](../../../apps/server/tests/knowledge-pipeline.test.ts#L71 "支持 Lark 文档、会话及普通导入代码到不同分析角色的映射。") 未覆盖并发大于一、网关异常、输出修复耗尽、图片材料及多目标批次。
