# ui · 模块理解

共享 UI 模块提供统一视觉原语、应用外壳、安全正文与源码阅读、关系图及可回溯 Evidence Trail。主要局部能力已经实现，但深链超限、关系图异常状态、移动覆盖层语义和浏览器级端到端验证仍有明确缺口。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-and-boundary"></a>
## 职责、背景与边界

`@omem/ui` 是以 Vue 为对等依赖的私有 ESM 包，包内集中管理 Markdown 净化、解析和代码高亮依赖。[共享 UI 包配置 ↗](../../../packages/ui/package.json#L1 "支持私有 ESM 包、Vue 对等依赖、公开入口以及富文本相关运行依赖的包配置说明。") 根入口统一导出基础控件、应用外壳、正文与源码查看器、关系图、Trail 抽屉、组合式状态及路由类型，为上层应用提供可共享的公开出口；现有材料未证明具体消费范围。[共享 UI 公共出口 ↗](../../../packages/ui/src/index.ts#L1 "支持根入口统一导出组件、组合式函数、Trail、关系图和 Hash 路由公共合同的论断。") 设计令牌规定颜色、中文字体、键盘焦点、减少动态效果和共享语法主题；[视觉令牌与无障碍基线 ↗](../../../packages/ui/src/tokens.css#L1 "支持统一颜色与字体、键盘焦点、减少动态效果及正文和源码共享语法主题的说明。") 来源提示另行区分原始证据、派生说明、候选、过期、错误和人工整理，避免与关系状态混淆。[内容来源状态提示 ↗](../../../packages/ui/src/components/OmStatusLine.vue#L2 "支持六种内容来源层级及其与关系状态徽标职责分离的论断。") 模块因此主要负责呈现、交互和序列化原语，不负责判定知识事实或加载业务数据。此前仅凭入口文件推断包配置与实际消费关系的结论已被上述分证据、限范围的表述替代。

<a id="reading-flow"></a>
## 正文与源码如何形成证据入口

Markdown 会识别 `[[引用键]]`：已解析且可操作的引用生成入口；已解析但不可操作的引用显示标签并以不可用原因或引用理由作提示；未知引用键只显示通用“引用不可用”，并不附具体原因。[内联引用解析规则 ↗](../../../packages/ui/src/components/OmMarkdown.vue#L38 "支持可操作引用、已解析但不可操作引用和未知引用键三种呈现方式的精确区别。") 随后正文异步解析、代码高亮并经白名单净化，generation 检查阻止旧结果覆盖新正文，点击再分流到引用、外链或站内导航。[Markdown 解析、净化与点击分流 ↗](../../../packages/ui/src/components/OmMarkdown.vue#L44 "支持异步解析、代码高亮、白名单净化、防竞态以及引用、外链和站内链接分流流程。") 这替代了此前“所有不可用引用都带原因”的过宽结论。

源码查看器对全文异步高亮后按稳定行号展示，支持锚点滚动、范围命中和逐行引用，高亮失败时以转义文本回退。[源码查看与行级导航 ↗](../../../packages/ui/src/components/OmCodeViewer.vue#L29 "支持异步代次控制、稳定行号、锚点滚动、范围导航、逐行引用和转义回退的说明。") 底层只懒加载有限语言，未知语言直接转义，并在拆行时重建活动 `span` 以保留跨行词法状态。[语法高亮与安全拆行 ↗](../../../packages/ui/src/highlight.ts#L3 "支持有限语言懒加载、未知语言转义以及跨行高亮状态保持的实现说明。") 当前测试覆盖 TypeScript 跨行注释及已知、未知语言的标签转义，但不能据此认定恶意 Markdown、完整组件或大文件行为均已验证。[代码高亮测试范围 ↗](../../../packages/ui/src/highlight.test.ts#L1 "支持当前测试已验证跨行注释和标记转义，同时界定其尚未覆盖完整组件与 Markdown 流程。")

<a id="trail-and-routing"></a>
## 证据路径、对话框与深链协作

Trail 将模块、文件、符号、知识、引用和来源表示为含稳定身份、人读标题、滚动位置及加载线索的帧。[Trail 帧数据合同 ↗](../../../packages/ui/src/trail.ts#L1 "支持帧种类、稳定身份、人读标题、滚动位置和数据加载线索的结构说明。") 组合式状态负责查环、压栈、返回、跳层、关闭和变更通知，内存渲染栈不设 URL 同等上限。[共享 Trail 状态管理 ↗](../../../packages/ui/src/useEvidenceTrail.ts#L4 "支持查环、压栈、返回、跳层、关闭、触发元素记录和变更回调流程，并说明内存渲染不受 URL 预算限制。") 抽屉以原生模态对话框展示整栈：Escape 可逐层返回，面包屑可回跳，切层恢复滚动并聚焦标题，完全关闭或卸载时尝试归还焦点。[Trail 抽屉交互生命周期 ↗](../../../packages/ui/src/components/OmTrailDrawer.vue#L30 "支持模态打开、分层 Escape、滚动恢复、标题聚焦、面包屑跳转及关闭或卸载后的焦点归还。")

Hash 路由负责主视图、文件行号和帧身份的往返，但只持久化帧的 kind 与 id，刷新后标题会退化为 id；解析和写入都会把路径截到 200 帧。[Hash 路由往返与深度截断 ↗](../../../packages/ui/src/OmHashRoute.ts#L27 "支持主视图、文件行号和 Trail 身份恢复，并证明解析与写入均静默截断到最大深度。") 这与 Trail 注释所述“超限时明确提示而非静默丢弃”尚不一致，因为压栈本身仍会无界追加。[Trail 深链预算与压栈实现 ↗](../../../packages/ui/src/trail.ts#L37 "支持 200 帧仅作为 URL 持久化预算，同时揭示压栈函数未实施上限或明确超限结果。")

<a id="progress-and-limits"></a>
## 关系阅读进展与当前限制

关系图以固定排序和最多十二轮迭代分层生成稳定坐标，并对外区分节点与边选择事件。[关系图确定性布局 ↗](../../../packages/ui/src/components/OmRelationGraph.vue#L48 "支持关系图过滤缺失边、固定排序、有限轮次分层并生成稳定坐标的论断。") 但 `missing` 边没有专用绘制分支：缺失端点会产生空路径并把标签置于原点；边标签鼠标选择边，而 Enter 或空格却复用节点处理器。[关系边绘制与键盘处理 ↗](../../../packages/ui/src/components/OmRelationGraph.vue#L107 "支持缺失端点回退、missing 状态没有专用样式，以及边标签键盘误发节点选择的限制。") 应用外壳已提供桌面三栏，以及在 1100px、700px 阈值下切换的右、左覆盖侧栏；这些覆盖层仅由本地状态和 CSS 驱动，材料没有证明遮罩、Escape、焦点约束或展开状态属性。[响应式应用外壳 ↗](../../../packages/ui/src/components/OmShell.vue#L8 "支持桌面三栏、窄屏固定覆盖侧栏及其当前仅由本地状态和 CSS 驱动的交互边界。")

因此当前进展可确认到共享原语及其局部交互，尚不能仅凭这些文件证明消费方已经完成“关系选择—Trail 入栈—Hash 同步—证据加载—返回复位”的端到端流程。关系图异常状态、移动覆盖层语义和真实浏览器回归仍是主要验证边界。
