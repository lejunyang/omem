# 共享知识阅读与证据导航

`@omem/ui` 是个人记忆与仓库知识共用的 Vue 3 界面层，统一正文、源码、关系图和证据路径的呈现。它已覆盖安全富文本渲染、逐层证据导航、响应式页面骨架与代码定位；深链异常处理、窄屏侧栏交互、关系图边界和浏览器回归仍需完善。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 让不同知识入口共享阅读体验

`@omem/ui` 以 Vue 3 为运行边界，公开组件入口和视觉令牌，并集中使用 Markdown、代码高亮、HTML 净化与 Mermaid 等阅读依赖。参考 [共享界面包配置 ↗](../../../packages/ui/package.json#L1 "支持共享 UI 包的 Vue 运行边界、公开入口以及富文本阅读相关依赖。") 它面向个人知识、仓库文章、源码和原始证据等共同场景：共享层负责页面外壳、正文呈现和证据导航，上层应用负责数据加载、引用目标与页面路由。参考 [阅读器与宿主职责 ↗](1b40261c65b451f408e0ccbf7d88005ab4224d221aceb724a01f04d81f067d44.md#purpose "支持共享层负责呈现，而引用打开、站内导航和具体目标解释交由宿主处理。")

<a id="content-flow"></a>
## 把捕获内容变成安全且可追溯的正文

正文阅读器先识别内联引用，再解析 Markdown、处理代码块并净化输出；流程图采用严格模式渲染，失败时保留原始描述，避免捕获内容直接成为可执行页面标记。参考 [安全正文渲染流程 ↗](1b40261c65b451f408e0ccbf7d88005ab4224d221aceb724a01f04d81f067d44.md#reading-flow "概括引用替换、Markdown 解析、代码高亮、内容净化、流程图渲染及空正文状态边界。")

```mermaid
flowchart LR
  A[正文与引用清单] --> B[Markdown 和代码处理]
  B --> C[内容净化]
  C --> D[可阅读正文]
  D --> E[请求打开证据]
```

引用点击与站内导航通过事件交给宿主，具体引用目标也由宿主提供。参考 [阅读器与宿主职责 ↗](1b40261c65b451f408e0ccbf7d88005ab4224d221aceb724a01f04d81f067d44.md#purpose "支持共享层负责呈现，而引用打开、站内导航和具体目标解释交由宿主处理。") 内容来源状态则用于提示原始证据、派生说明、候选或过期等阶段，并不决定证据身份。参考 [内容来源状态 ↗](6607c2c3bf5f37d90f40dbb9be65efb451562d2e65e1b7437d9c1a7e6198dfcc.md#shared-reading-surface "支持来源状态用于区分内容所处阶段，并与引用目标或关系状态保持概念分离。") 当前代次隔离能阻止旧渲染覆盖新内容，但正文切换为空时仍可能残留加载状态。参考 [安全正文渲染流程 ↗](1b40261c65b451f408e0ccbf7d88005ab4224d221aceb724a01f04d81f067d44.md#reading-flow "概括引用替换、Markdown 解析、代码高亮、内容净化、流程图渲染及空正文状态边界。")

<a id="evidence-navigation"></a>
## 沿证据路径深入并返回原处

证据 Trail 将模块、文件、符号、知识、引用和来源组织为可序列化帧栈。重复目标会被识别为循环，读者可以逐层返回、跳转面包屑或关闭全部；抽屉还保存滚动位置，并在条件允许时归还焦点。参考 [证据路径导航 ↗](6607c2c3bf5f37d90f40dbb9be65efb451562d2e65e1b7437d9c1a7e6198dfcc.md#evidence-trail "解释 Trail 帧栈、循环检测、滚动与焦点恢复，以及 URL 深链预算的职责边界。")

渲染栈本身不限制深度，200 帧只是 URL 持久化预算。刷新后仍需路由和宿主补全上下文，因此超限截断、未知帧类型及失效目标的可见提示仍属于待明确的集成合同。参考 [证据路径导航 ↗](6607c2c3bf5f37d90f40dbb9be65efb451562d2e65e1b7437d9c1a7e6198dfcc.md#evidence-trail "解释 Trail 帧栈、循环检测、滚动与焦点恢复，以及 URL 深链预算的职责边界。")

<a id="progress-and-limits"></a>
## 已有能力与待补齐边界

共享层已实现源码按行高亮与引用，以及输入稳定时可重复的关系图布局；关系图对超长依赖链和循环尚无严格分层保证，边标签的键盘行为也可能与点击不一致。参考 [源码与关系图边界 ↗](1b40261c65b451f408e0ccbf7d88005ab4224d221aceb724a01f04d81f067d44.md#implemented-limits "支持源码定位能力，以及关系图长链分层和键盘交互的当前限制。") 页面骨架支持桌面多栏、窄屏固定侧栏和独立滚动区域，但导航与助理是否互斥、如何关闭及归还焦点仍缺少明确依据。参考 [响应式页面骨架 ↗](6607c2c3bf5f37d90f40dbb9be65efb451562d2e65e1b7437d9c1a7e6198dfcc.md#shell-and-foundation "解释桌面与窄屏布局、独立滚动区域、视觉基础及尚未明确的侧栏交互。") 当前材料也不足以证明 Trail、响应式布局和跨组件焦点管理已经通过真实浏览器端到端验证。参考 [集成验证边界 ↗](6607c2c3bf5f37d90f40dbb9be65efb451562d2e65e1b7437d9c1a7e6198dfcc.md#questions-and-limits "说明现有材料尚未覆盖完整调用接线和浏览器端到端验证。")
