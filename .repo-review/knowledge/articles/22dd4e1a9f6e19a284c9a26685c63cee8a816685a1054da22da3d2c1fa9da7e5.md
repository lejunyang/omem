# Review 启动模式修复与环境恢复记录

该材料记录了 2026-10-01 的一次启动竞态修复：前端不再因 Review API 暂未就绪而误入个人工作区，而是保留连接界面并重试；同时记载了真实实例、浏览器回归和全项目检查结果。文末另行说明中文模型不可用属于用户服务数据目录差异，处理方式是恢复锁定快照，而非改变应用的模型下载原则。以上均为文档所述进展，材料本身不等同于对当前代码状态的独立核验。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="problem"></a>
## 启动竞态与错误模式判定

`dev:review` 启动时，Vite 可能早于 API 开始监听；旧入口会把首次 Review health 失败误判为应进入个人工作区，随后持续请求 Review 服务并不提供的个人任务与作业接口，即使 API 后续恢复也不会重新识别运行模式。该问题本质上是“服务尚未就绪”与“当前不是 Review 模式”被混为一谈。[旧入口的启动竞态现象 ↗](../../../docs/implementation/review-startup.md#L3 "支持关于首次 health 失败导致错误退回个人工作区、后续无法重新识别模式的描述。")

<a id="startup_flow"></a>
## 修复后的探测与恢复流程

材料记载的新流程会先显示连接状态，只有 Review health 明确返回 404、且个人 health 成功时，才启动个人页面及其业务轮询。网络错误、超时、代理 5xx 或鉴权失败不会触发模式降级，而是继续等待并重试；界面同时提供令牌输入和手动重连，Review 探测也会携带已有会话令牌。[运行模式探测与重连规则 ↗](../../../docs/implementation/review-startup.md#L5 "支持修复后的判定条件、失败分类、令牌携带以及重试交互流程。") 这使运行模式判定依赖明确的服务证据，而不是一次瞬时失败。

<a id="verification_and_environment"></a>
## 行为验证与独立环境问题

文档报告：在指定实例中暂停 API 30 秒后，页面先保持等待，API 恢复后自动进入仓库视图；浏览器回归覆盖 503→恢复，并断言等待及恢复阶段均未发起个人业务 API 请求，同时保留多视口、递归引用与深链检查。材料还声称 351 项测试、类型检查和构建通过，但未附当前源码指纹或命令输出。[真实实例与浏览器回归结果 ↗](../../../docs/implementation/review-startup.md#L7 "支持 API 暂停恢复场景、个人接口请求断言以及文档报告的全项目检查结果。")

另一个问题被明确归为独立环境差异：用户服务采用 `Desktop/osdk-home`，而原中文模型位于默认 osdk 目录。处理是在该服务的 `OSDK_DATA_DIR` 中同步并校验 `memory-zh` 锁定快照，重启后 health 为 ready；应用仍禁止运行时隐式下载，也未修改用户路径或锁文件。[中文模型数据目录恢复 ↗](../../../docs/implementation/review-startup.md#L9 "支持将模型不可用识别为独立环境问题，并说明锁定快照恢复及不隐式下载的边界。")
