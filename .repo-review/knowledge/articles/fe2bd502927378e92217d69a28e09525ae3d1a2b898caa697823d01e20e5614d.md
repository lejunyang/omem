# inputs · 输入接入与可靠成批

inputs 模块在统一捕获链前提供两种机制：HookSpool 持久保存并顺序投递 CaptureInput，InputAggregator 将聊天或屏幕事件按流暂存、去重并重新封装成批量 CaptureInput。当前聚合数据固定属于 personal workspace；跨进程缓冲竞争以及 capture 与聚合事务间的补偿策略仍未确定。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role"></a>
## 职责、输入合同与实现边界

模块包含磁盘缓冲和事件聚合两条路径，但现有材料只证明其行为，不能把“服务不可用”或“突发输入”写成已确认的设计动机。`HookSpool` 的记录明确保存完整 `CaptureInput`，并附带生产者、事件号、内容摘要和创建时间；`enqueue` 从输入来源中取得 `collectorId` 与 `eventId`，校验重复或冲突后才落盘。[缓冲记录的 CaptureInput 合同 ↗](../../../apps/server/src/inputs/spool.ts#L20 "支持 HookSpool 记录直接包含完整 CaptureInput 及其事件身份、摘要和创建时间。")[Hook 入列与重复冲突判断 ↗](../../../apps/server/src/inputs/spool.ts#L126 "支持 enqueue 接收 CaptureInput、提取稳定事件身份、检查既有记录并保存新记录的完整流程，也界定并发竞争问题。") `InputAggregator` 同样接收 `CaptureInput`，但只允许 chat 与 screen，分别按会话或应用与窗口划流；事件表读写固定使用 `personal` workspace，不能据此宣称已有多租户隔离。[聊天与屏幕流键规则 ↗](../../../apps/server/src/inputs/aggregator.ts#L39 "说明聚合器只接受 chat 和 screen，并展示会话、应用及窗口的流划分规则。")[聚合事件接收与 personal 工作区 ↗](../../../apps/server/src/inputs/aggregator.ts#L53 "支持聚合器接收 CaptureInput、校验事件身份、处理重复冲突，并固定写入 personal workspace。")

<a id="flow"></a>
## 从可靠落盘到批量捕获

Hook 缓冲先写入权限为 `0600` 的随机临时文件，完成文件同步后重命名，并尝试同步目录；目录同步失败会被忽略，因此最终持久性仍取决于平台文件系统语义。[缓冲文件原子写入 ↗](../../../apps/server/src/inputs/spool.ts#L80 "支持临时文件权限、文件同步、重命名以及目录同步的降级行为。") 入列默认受 1000 条和 50,000,000 字节限制，超限会记录容量告警并拒绝新记录。[缓冲容量保护 ↗](../../../apps/server/src/inputs/spool.ts#L139 "支持现有记录容量统计、默认条目数和字节上限，以及超限告警与拒绝行为。") 刷新按创建时间逐条发送，只有回执中的生产者、事件号和摘要全部匹配才删除本地文件；首个失败即停止本轮，既保留顺序重试，也可能造成队头阻塞。[顺序投递与回执核验 ↗](../../../apps/server/src/inputs/spool.ts#L174 "支持按创建时间投递、核验回执、成功删除以及首个失败后停止的处理语义。")

聚合流在静默 15 秒、最早事件等待 5 分钟或事件数达到阈值时就绪。候选按接收时间选择，以内容摘要和 actor ID 联合去重，单批最多容纳 50 个 part；不同 actor 的相同内容仍作为独立证据保留。[聚合触发、选择与去重 ↗](../../../apps/server/src/inputs/aggregator.ts#L124 "支持静默期、最大等待、数量阈值、接收顺序、同 actor 内容去重及 part 预算。")

<a id="provenance_limits"></a>
## 来源保留、替代结论与一致性限制

批量 envelope 把 actor 外部标识、观察时间、事件号、转发状态等信息下沉到每个 part。[逐 part 来源复制 ↗](../../../apps/server/src/inputs/aggregator.ts#L181 "支持批量 envelope 为各 part 保存 actor 外部标识、观察时间、事件号、转发及生产者属性。") 顶层 actor 的稳定性只比较 `actorId`、`actorType` 和 `actorVerifiedBy`；一致时，其他顶层 actor 字段取最后一条事件。[迟到关联与顶层 actor 判定 ↗](../../../apps/server/src/inputs/aggregator.ts#L224 "支持迟到批次关联、确定性批次身份，以及顶层 actor 稳定性实际比较的字段范围。") 这替代了旧稿中“全部 actor 信息一致才保留顶层身份”的过宽结论。

迟到事件不会改写旧批：只要本批任一观察时间不晚于上一批末尾，就通过 `lateForBatchId` 建立关联。[迟到关联与顶层 actor 判定 ↗](../../../apps/server/src/inputs/aggregator.ts#L224 "支持迟到批次关联、确定性批次身份，以及顶层 actor 稳定性实际比较的字段范围。") 聚合刷新先调用外部 capture，之后才在数据库事务中复查 pending 状态、写入批次并更新事件，因此只能确认聚合表内部事务一致，不能认为 revision、job 与批次原子提交。[捕获调用与批次事务边界 ↗](../../../apps/server/src/inputs/aggregator.ts#L320 "支持 capture 在数据库事务外先执行，随后才复查 pending、写批次并更新事件状态。") HookSpool 也采用“先检查正式路径、后重命名临时文件”的流程，尚不足以证明多个进程共享目录时具有严格的先写者胜出语义。[Hook 入列与重复冲突判断 ↗](../../../apps/server/src/inputs/spool.ts#L126 "支持 enqueue 接收 CaptureInput、提取稳定事件身份、检查既有记录并保存新记录的完整流程，也界定并发竞争问题。")[缓冲文件原子写入 ↗](../../../apps/server/src/inputs/spool.ts#L80 "支持临时文件权限、文件同步、重命名以及目录同步的降级行为。")
