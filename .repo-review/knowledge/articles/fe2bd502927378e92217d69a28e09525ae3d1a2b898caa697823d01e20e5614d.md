# inputs · 模块理解

inputs 模块提供两种可验证的输入整形能力：InputAggregator 将聊天与屏幕事件写入 SQLite，按流聚合后交给统一 capture；HookSpool 将具备采集器与事件标识的 CaptureInput 持久化到受限磁盘目录，并由显式 flush 顺序交付。二者共享事件身份和稳定摘要语义，但材料不能证明 HookSpool 仅服务于 Hook、存在自动调度或实现了重试机制；跨事务补偿、多进程并发、过期清理与回执追踪仍待明确。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role_and_boundaries"></a>
## 职责与设计边界

inputs 位于外部采集结果与统一 capture 之间。`InputAggregator` 明确只接受 chat 与 screen：聊天按会话 ID、屏幕按“应用名 + 窗口标题”划分流，并要求采集器与事件 ID。[聊天与屏幕流划分 ↗](../../../apps/server/src/inputs/aggregator.ts#L39 "支持聚合器只接受聊天和屏幕来源、流键规则以及事件身份前置条件。") `HookSpool` 则为任意满足条件的 `CaptureInput` 提供本地落盘与显式刷新能力；它要求 `collectorId` 和 `eventId`，但没有检查 `source === "hook"`。因此，先前“它专用于暂时交付失败的 Hook 输入并实现重试”的结论被收窄，类名和错误码只能说明设计倾向，不能证明调用范围或调度机制。[本地队列入列规则 ↗](../../../apps/server/src/inputs/spool.ts#L126 "支持队列要求采集器和事件标识、处理重复与冲突，同时表明实现未校验输入 source。")[共享捕获来源合同 ↗](../../../packages/contracts/src/index.ts#L49 "说明 eventId 在基础合同中可为空，且 CaptureInput 支持多种来源，从而界定 Spool 的附加约束和无法确认的 Hook 专用定位。")

两条路径仍复用共享捕获合同，输入可包含文本、图片与链接；聚合后的逐分片来源可保留身份、观察时间、事件 ID、引用与转发属性，避免批处理完全抹平原始归属。[逐分片来源合同 ↗](../../../packages/contracts/src/index.ts#L4 "支持文本、图片和链接分片携带身份、时间、事件、引用及转发来源。")

<a id="identity_and_flow"></a>
## 事件身份与主流程

两种实现都以采集器和事件 ID 表达事件身份，并用稳定摘要区分安全重放与冲突。摘要先递归规范化对象键并忽略 `undefined`，再对 JSON 计算 SHA-256。[规范化稳定摘要 ↗](../../../apps/server/src/storage/digest.ts#L3 "解释两条输入路径用于幂等与冲突判断的规范 JSON 和 SHA-256 摘要算法。") 聚合器把事件写入 SQLite，同键同载荷返回已有记录，同键异载荷拒绝；待处理流在达到静默时间、最长滞留时间或数量阈值后进入刷新候选。[聚合事件幂等写入 ↗](../../../apps/server/src/inputs/aggregator.ts#L53 "支持 SQLite 接入、相同载荷重放、不同载荷冲突和内容摘要生成。")[聚合流就绪条件 ↗](../../../apps/server/src/inputs/aggregator.ts#L124 "支持静默窗口、最长滞留时间和事件数量阈值共同决定刷新候选。")

Spool 以生产者和事件 ID 的摘要生成确定文件名，经临时文件写入、文件同步与重命名落盘；`flush` 仅在被显式调用时按创建时间顺序发送，回执的生产者、事件 ID 和载荷摘要匹配后删除文件，首次失败即停止本轮。材料没有展示定时器、退避器或其他自动重试触发。[队列文件身份与耐久写入 ↗](../../../apps/server/src/inputs/spool.ts#L69 "支持确定文件路径、临时文件写入、文件同步与重命名流程。")[显式顺序刷新 ↗](../../../apps/server/src/inputs/spool.ts#L197 "支持 flush 被调用后才顺序发送、校验回执、成功删除和首次失败停止；附近结论据此不推断自动调度或重试器。")

<a id="aggregation_and_provenance"></a>
## 聚合、来源与迟到事件

聚合器以“内容摘要 + actorId”去除同一说话人的重复内容，不同已知 actorId 的相同内容仍分别保留；每批最多 50 个分片。actorId 缺失时统一视为 `unknown`，所以现实中不同但身份未知的说话人可能被合并。[说话人判重与分片预算 ↗](../../../apps/server/src/inputs/aggregator.ts#L158 "支持内容摘要和 actorId 联合判重、unknown 回退及每批 50 个分片的限制。")

生成批次时，每个分片会写入外部身份、主体身份、观察时间和事件 ID，但 `replyTo` 固定为空。[聚合分片来源写入 ↗](../../../apps/server/src/inputs/aggregator.ts#L181 "支持逐分片复制身份、时间和事件信息，并证明 replyTo 固定为空。") 批次顶层身份只比较 actorId、actorType 与验证方式；外部身份、主体身份和绑定版本未参与一致性判断，而是在前三项稳定时取最后事件的值。批次 ID 由有序事件键稳定生成，迟到事件通过 `lateForBatchId` 关联既有批次，不回写旧批次。[批次身份与迟到关系 ↗](../../../apps/server/src/inputs/aggregator.ts#L217 "支持稳定批次标识、迟到批次关联和顶层身份仅比较部分字段的限制。")

<a id="progress_and_limits"></a>
## 耐久性与一致性限制

Spool 将目录权限设为 `0700`，记录文件设为 `0600`；默认容量为 1000 条或约 50 MB。七天 `retentionMs` 只触发告警，过期记录仍会被返回并参与后续显式刷新，并非自动清理期限。[队列目录与记录权限 ↗](../../../apps/server/src/inputs/spool.ts#L51 "支持队列目录设为 0700、记录经原子写入后设为 0600。")[容量与过期告警 ↗](../../../apps/server/src/inputs/spool.ts#L139 "支持默认容量条件，并证明 retentionMs 仅触发告警、过期记录仍会返回。") 目录同步过程中的异常会被统一忽略，告警写入异常却可能传播；实现也未展示损坏 JSON 隔离、遗留临时文件清扫或共享目录的进程间锁。[队列故障可见性 ↗](../../../apps/server/src/inputs/spool.ts#L80 "支持目录同步异常被统一忽略、告警写入可能传播异常，以及实现未展示失败临时文件清扫。")

聚合刷新先调用外部 capture，再开启本地事务复核事件仍为 pending；并发变化会触发 `INPUT_BATCH_CHANGED`，但材料没有说明此前创建的 revision/job 如何补偿。[捕获与本地事务边界 ↗](../../../apps/server/src/inputs/aggregator.ts#L320 "证明外部 capture 发生在本地事务之前，并支持 pending 状态复核和 INPUT_BATCH_CHANGED 限制。") Spool 回执合同包含 `revisionId`，刷新时却只校验另外三个身份字段，也不返回或持久化该值。[捕获回执字段 ↗](../../../apps/server/src/inputs/spool.ts#L20 "证明回执包含 revisionId，并与刷新逻辑只校验生产者、事件 ID 和载荷摘要形成对照。")
