# server-root · 模块理解

server-root 是 omem 当前单用户服务端的组合与运行边界：它把统一捕获合同、受限连接器、SQLite 不可变证据、知识与记忆流水线、可追溯 Agent 问答、通知待办及可选飞书集成连接为 HTTP 服务，并通过显式配置、本机或令牌访问限制及 Agent 拒绝自动获权来控制风险。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role"></a>
## 职责与设计背景

该模块是个人记忆服务的组合根，而非单一业务算法：`buildApp` 创建 Store、问答运行、记忆与反馈、知识路由、检索和助手，并按配置启用学习与飞书运行时。[应用组合根与可选服务装配 ↗](../../../apps/server/src/app.ts#L44 "支持服务端创建存储、问答、记忆、知识、检索、助手、学习与飞书运行时，并要求非回环监听配置令牌。") 健康接口明确返回 `sqlite` 和 `personal`，同时报告检索、通知、学习与飞书状态，说明当前交付是可运行的单用户基础，不代表已经具备团队租户隔离。[服务健康状态 ↗](../../../apps/server/src/app.ts#L179 "支持健康接口报告 SQLite、personal 模式以及检索、通知、学习和飞书状态。")

跨模块输入遵循共享 Capture 合同，可包含文本、图片、链接、上下文及来源信息；`producerKind` 明确区分原始材料和派生结果，防止模型回答被误当成新的独立事实。[统一捕获与来源合同 ↗](../../../packages/contracts/src/index.ts#L5 "支持文本、图片、链接、上下文和来源信息的统一结构，以及 original 与 derived 的区分。")

<a id="capture-flow"></a>
## 从外部输入到固定证据

文件、Git、飞书和 Hook 连接器把异构输入规范化为 CaptureInput。读取均为显式有限操作：文件须位于配置根目录，普通 URL 不自动抓取；Git 固定到解析后的提交，飞书依赖外部 CLI，Hook 仅选择允许字段并执行有限的凭据替换。[受边界约束的连接器 ↗](../../../apps/server/src/connectors.ts#L1 "支持文件根目录、Git 固定提交、飞书文档和 Hook 字段选择等显式有限读取边界。") CLI 提供人工捕获及 ACP profile 探测，非 Hook 命令输出结果，失败设置非零退出码。[命令行捕获与档案探测 ↗](../../../apps/server/src/cli.ts#L27 "支持 CLI 的人工捕获命令、ACP profile 探测、输出约束和失败退出状态。") 独立 Hook 转发器则先写 spool，再以短超时尝试投递；未送达或异常只写 stderr，不阻塞宿主。[非阻塞 Hook 投递 ↗](../../../apps/server/src/hook-forward.ts#L9 "支持 Hook 输入限制、spool 入列、短超时 API 投递及失败不阻塞宿主的流程。")

Store 先在 SQLite 事务外校验图片的 Base64、大小与文件头，并把资源写入资产目录；这些文件系统操作不受后续数据库事务的原子保护。[图片校验与资产落盘 ↗](../../../apps/server/src/store.ts#L100 "支持图片校验及资产文件写入发生在调用 SQLite 事务之前，说明文件系统操作不受该事务原子保护。") 随后才进入 SQLite 事务，处理事件幂等、创建不可变修订与固定片段、更新来源 head，并在来源变化时递增有效性 epoch、标记旧依赖和记忆失效、记录刷新及入列后续任务。原始材料进入抽取队列，派生材料被排除以避免自循环。[捕获事务与来源更新 ↗](../../../apps/server/src/store.ts#L142 "支持事务内的事件幂等、不可变修订、固定片段、来源 head、依赖失效、刷新记录和任务入列。") 这明确替代了此前“Store 在事务中校验资源”的结论；任务入列也不等于抽取、复核或刷新已经成功应用。

<a id="answer-runtime"></a>
## HTTP、固定证据问答与 Agent 边界

HTTP 层集中提供捕获、证据、搜索、恢复、任务、作业、记忆、质量、集成及运行接口。配置令牌时校验 Bearer token，否则限制为本机 Host 与 Origin；启动后恢复未完成助手轮次并启动后台循环，关闭时停止助手、学习、飞书和 Runs，再释放检索及数据库。[HTTP 安全、路由与生命周期 ↗](../../../apps/server/src/app.ts#L134 "支持 API 访问限制、主要业务路由、助手恢复、后台循环以及关闭时的资源释放顺序。")

`Runs` 校验固定证据、选区以及文本和图片预算，再选择 ACP 或 CLI；有效回答以 `derived` 来源保存并逐片段链接回输入证据，同时声明引用不自动证明论断得到支持。[固定证据问答运行 ↗](../../../apps/server/src/runs.ts#L39 "支持证据及预算校验、ACP 或 CLI 分派、事件和取消处理，以及回答作为派生材料保存并链接原证据；也显示 ACP 调用未传 contextBudget。") ACP 适配器会校验模型和推理强度、检查图片能力、记录但拒绝权限或补充输入请求，并限制输出和清理子进程；上下文窗口校验以调用方传入 `contextBudget` 为前提。[ACP 能力协商与可选上下文校验 ↗](../../../apps/server/src/agents.ts#L180 "支持模型、推理强度、图片、权限、输出和子进程清理边界，并说明上下文窗口校验以提供 contextBudget 为条件。") 当前 `Runs` 调用 ACP 时没有传递该选项，因此不能把上下文窗口发现视为这条问答路径必然执行的校验。[固定证据问答运行 ↗](../../../apps/server/src/runs.ts#L39 "支持证据及预算校验、ACP 或 CLI 分派、事件和取消处理，以及回答作为派生材料保存并链接原证据；也显示 ACP 调用未传 contextBudget。")

<a id="status-limits"></a>
## 当前进展、替代结论与限制

当前代码已形成从配置加载、监听、捕获持久化、证据导航到 Agent 回答保存的完整切片；非回环监听缺少令牌会被应用工厂拒绝，`SIGINT` 和 `SIGTERM` 会触发应用关闭。[应用组合根与可选服务装配 ↗](../../../apps/server/src/app.ts#L44 "支持服务端创建存储、问答、记忆、知识、检索、助手、学习与飞书运行时，并要求非回环监听配置令牌。")[服务启动与信号关闭 ↗](../../../apps/server/src/main.ts#L1 "支持配置加载、应用构建、监听，以及 SIGINT 和 SIGTERM 下调用应用关闭的入口链路。")

限制仍然清晰：基础搜索只是当前 head 上的 SQLite `LIKE`；Runs 状态保存在进程内，重启不可恢复。历史 restore 会复制旧内容形成新修订、重建片段并切换 head，但可见路径没有执行普通更新中的 source_state epoch 递增、依赖失效或任务入列，因此“恢复自动触发完整重核验”的旧结论已被替代，是否存在上层补偿仍待确认。[搜索与历史恢复实现 ↗](../../../apps/server/src/store.ts#L377 "支持基础搜索仅针对当前 head 执行 LIKE，以及 restore 创建新修订、复制片段和边但未显示普通更新的有效性与刷新步骤。") 给定材料也没有测试文件，无法据此确认并发、取消、恢复一致性及外部 CLI 的真实行为覆盖。
