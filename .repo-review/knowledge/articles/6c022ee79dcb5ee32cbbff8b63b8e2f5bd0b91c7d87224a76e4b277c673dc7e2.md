# server-root · 模块理解

服务端根模块围绕单用户 SQLite 组装捕获、不可变证据、检索、记忆、问答、学习与飞书能力，并通过 HTTP、CLI 和 Hook 提供入口。主助手选取首个配置为 ACP transport 的 profile，但装配阶段不验证其命令、认证或实际可运行性；普通问答则遵循请求所选 profile 的传输类型。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role"></a>
## 定位与组合关系

`server-root` 是 omem 的服务端组合层，而不是单一领域算法：`buildApp` 连接 Store、运行管理、记忆、反馈、知识、检索和助手，并按配置启用学习流水线与飞书运行时。[服务端应用装配 ↗](464fb8678bf77a7fc70c6e577b524284f5161deefd39d11125de970688dbea13.md#assembly "子知识概括组合根如何连接存储、检索、助手、学习和飞书能力，支持模块定位。") 非回环监听必须配置令牌，Web 助手的 owner、时区、检索与反馈依赖也由服务端注入。[应用工厂与助手依赖 ↗](../../../apps/server/src/app.ts#L44 "原始代码支持非回环令牌检查、核心服务创建以及助手依赖注入。")

持久化中心是单用户 SQLite Store：它负责迁移、资产目录和专用仓储的组装，事务使用立即锁并在异常时回滚。[Store 事务与单用户基础 ↗](../../../apps/server/src/store.ts#L36 "支持 SQLite 单用户定位、组件初始化和事务提交回滚边界。") 因而当前实现提供的是个人模式下的一致数据边界，不能据此声称已经具备团队租户隔离。

<a id="capture-flow"></a>
## 从外部输入到固定证据

文件、Git、飞书和 Hook 连接器把异构来源规范化为统一捕获输入，并坚持显式、有限读取；正文中的普通 URL 不会被自动爬取。[受限连接器设计 ↗](6199888414a5c2e7a0d2943cc6a53c40503ffbcc031f14e27140c29dcb28ec74.md#limits "子知识说明连接器采用显式有限读取并统一生成捕获输入。") 文件路径受真实根目录约束，Git 先解析固定提交，飞书限制协议、域名和文档路径。[文件、Git 与飞书读取边界 ↗](../../../apps/server/src/connectors.ts#L10 "支持真实路径根目录检查、固定 Git 提交读取和飞书 URL 限制。") Hook 通过字段白名单、字符预算和有限凭据替换控制内容，并构造稳定事件身份与 provenance。[Hook 字段与事件身份 ↗](../../../apps/server/src/connectors.ts#L137 "支持字段白名单、字符预算、有限脱敏和稳定来源身份的构造。")

Store 对采集事件和来源内容执行幂等检查，新内容写成递增的不可变修订和固定片段，再切换 source head。来源更新会提高有效性 epoch、将旧依赖标为 stale、失效关联记忆并入列刷新与抽取任务；派生材料不进入声明抽取队列，以免总结反过来成为独立证据。[不可变捕获与重核验入列 ↗](../../../apps/server/src/store.ts#L100 "支持幂等捕获、不可变修订、固定片段、依赖失效、任务入列和派生材料防自循环。") 入列只表示后续处理已登记，不等于刷新或应用已经成功。

<a id="agent-flow"></a>
## 基于固定证据的 Agent 运行

应用装配仅按 `transport === "acp"` 选取第一个配置项作为主助手 profile；完全没有 ACP profile 时传入 `null`。这一步不探测命令是否存在、认证是否有效或后端是否可运行，实际失败须由后续适配器或调用过程暴露。该结论替代此前“选取首个可用 ACP profile”的表述。[主助手 ACP transport 配置选择 ↗](../../../apps/server/src/app.ts#L60 "代码仅按 transport 选取首个 ACP profile，不在装配阶段验证命令、认证或实际可运行性，支持修正被替代的“可用 profile”结论。")

ACP 路径负责协议与会话初始化、模型和推理强度合法值校验、技能与图片能力检查，并声明无文件读写和终端能力；权限及补充输入请求会被记录后拒绝。[ACP 能力协商与请求边界 ↗](../../../apps/server/src/agents.ts#L180 "支持 ACP 请求处理、只读能力声明、模型配置校验、图片能力检查和进程清理。") 普通 `Runs` 则按 `profileId` 选择配置，校验固定证据、选区和文本图片预算，[普通问答的 profile 与证据准备 ↗](../../../apps/server/src/runs.ts#L39 "支持 Runs 按 profileId 选取配置并校验固定证据、选区及上下文预算。") 再严格依据该 profile 的 transport 调用 ACP 或 CLI；图片上下文明确要求 ACP。非空回答会作为 derived 材料保存并链接输入证据，但引用关系不代表支持度已经核验。[按 profile transport 执行并保存回答 ↗](../../../apps/server/src/runs.ts#L139 "支持普通问答根据 profile.transport 分支执行，并把非空回答保存为派生材料。") 固定原文读取只接受数据库中的 `verbatim-v1` 修订，不会从当前工作树重建历史。[固定修订原文门卫 ↗](../../../apps/server/src/source-text.ts#L3 "支持只从数据库读取 verbatim-v1 文本，避免从当前工作树重建历史证据。")

<a id="progress-limits"></a>
## 当前进展与限制

应用启动后会恢复未完成的助手轮次，运行提醒、输入聚合、学习及飞书循环；关闭时依次停止后台服务、问答运行和检索并关闭数据库。[后台循环与关闭顺序 ↗](../../../apps/server/src/app.ts#L598 "支持未完成轮次恢复、周期任务启动及资源有序释放。") 当前传统搜索只对 source head 的标题和片段执行 SQLite `LIKE`，不是语义检索。[当前版本文本搜索 ↗](../../../apps/server/src/store.ts#L471 "查询仅连接 source head，并对标题和片段执行转义后的 LIKE，支持传统搜索限制。") 普通问答的状态、事件和 answerId 映射仅存在进程内 Map 中，服务重启后无法从该结构继续查询。[内存运行状态 ↗](../../../apps/server/src/runs.ts#L19 "Runs 使用进程内 Map 保存状态、事件和 answerId，支持其短生命周期限制。") CLI 兼容路径提供只读、无工具或临时会话参数和 JSON 输出解析，但不具备 ACP 的能力发现与会话协商。[CLI 兼容传输 ↗](../../../apps/server/src/agents.ts#L377 "展示 CLI 参数约束、JSON 事件解析和失败条件，并支持其缺少 ACP 能力协商的边界。")

历史恢复会复制旧内容形成新 head并保留历史，但可见路径没有执行普通更新中的有效性 epoch、依赖失效和重新抽取操作。[历史恢复实现 ↗](../../../apps/server/src/store.ts#L495 "显示恢复通过新修订切换 head，但未呈现普通更新路径中的依赖失效和任务入列。") Hook 转发会先写 spool、短超时投递且失败不阻塞宿主，不过给定材料未包含 spool 的持久化、清理和进程退出后再次触发机制。[Hook spool 投递边界 ↗](../../../apps/server/src/hook-forward.ts#L39 "入口只展示入列、一次有限 flush、短超时和失败不中断宿主，支持指出后续重试语义仍缺材料。")
