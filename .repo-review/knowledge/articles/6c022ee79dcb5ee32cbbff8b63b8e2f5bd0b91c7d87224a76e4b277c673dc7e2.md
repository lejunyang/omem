# server-root · 模块理解

服务端根模块是 omem 的单用户运行中枢：它把统一捕获合同、SQLite 不可变修订、检索与助手、受控 Agent、任务治理及外部连接器装配到同一 Fastify 应用，并集中管理访问控制与生命周期。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role"></a>
## 组合根与当前架构边界

`buildApp` 创建 Fastify、Store、记忆与反馈服务，并按配置装配知识接口、检索、助手、学习和飞书能力；非回环监听未配置令牌时会在启动前失败。[服务端应用装配与安全前置条件 ↗](../../../apps/server/src/app.ts#L46 "支持组合根创建核心服务、装配可选能力以及非回环绑定必须配置令牌的说明。") 捕获的文本、图片、链接、来源信息以及 Agent profile 均由共享合同约束，使 HTTP、CLI 和连接器能够汇入同一数据模型。[统一捕获与 Agent 合同 ↗](../../../packages/contracts/src/index.ts#L70 "支持捕获联合类型、来源信息和 Agent profile 由共享合同定义。")

当前持久层仍是个人优先的单用户 SQLite，主要写入由同步事务包围；Postgres 与团队级约束被明确留作后续迁移。因此，现有 workspace、principal 和 visibility 字段不能被解释为已经实现租户隔离。[单用户 SQLite 与事务边界 ↗](../../../apps/server/src/store.ts#L4 "支持当前存储的单用户定位，以及同步事务的提交和回滚边界。")

<a id="capture"></a>
## 捕获、不可变修订与重核验

文件、Git、飞书和 Hook 连接器执行有限读取，服务端路由会把其结果再次交给 `captureSchema`，验证后才进入 Store。[连接器结果的运行时校验 ↗](../../../apps/server/src/app.ts#L200 "支持文件、Git、飞书和 Hook 连接器产物经 captureSchema 解析后才进入 Store。") Store 校验图片，按采集器与事件号处理幂等冲突，并把内容变化保存为递增的不可变修订和固定片段；来源更新会使旧依赖过期、相关记忆失效并创建重核验任务。[捕获、修订与刷新入列 ↗](../../../apps/server/src/store.ts#L102 "支持图片校验、幂等去重、不可变修订、固定片段、依赖失效和刷新任务入列流程。")

刷新会预先冻结影响集。任务入列只表示等待处理；只有记忆恢复为 active、依赖指向新修订且状态为 current，刷新记录才成为 applied，来源再次变化则成为 superseded。[来源刷新状态判定 ↗](../../../apps/server/src/learning/refresh.ts#L6 "支持冻结影响集，并区分任务入列与依赖真正修复后的 applied 状态。") 派生材料不会再次进入声明抽取，避免模型产物自循环成为独立证据；助手取证时也排除派生修订。[派生材料防止抽取自循环 ↗](../../../apps/server/src/store.ts#L357 "支持派生材料跳过声明抽取、避免再次作为独立证据进入学习队列。")[当前原始证据与可见性限制 ↗](../../../apps/server/src/assistant/runtime.ts#L770 "支持助手只使用当前 head 的非派生证据，以及群会话无策略时默认拒绝证据访问。") 这替代了旧稿中“派生知识当前用于召回”的结论：现有材料只证明两条排除规则，没有证明派生知识参与当前服务端检索。

<a id="assistant"></a>
## 助手、检索与受治理写操作

主助手先持久化 turn，再按会话串行执行；同一会话的新消息会取消先前运行。[Turn 持久化、串行与中断 ↗](../../../apps/server/src/assistant/runtime.ts#L231 "支持 turn 先入列持久化、同会话链式串行以及新消息取消旧 turn。") 执行阶段读取同会话历史，检索并过滤可见证据，合并上一轮工作上下文，并允许至多一轮补充检索；最终引用仅保留运行时实际提供的片段。[助手检索、补充检索与引用过滤 ↗](../../../apps/server/src/assistant/runtime.ts#L454 "支持会话历史、初次检索、上一轮上下文、补充检索、治理工具调用和引用白名单过滤的执行顺序。") 证据还必须属于当前来源 head 且不是派生材料；群会话未注入真实可见性策略时默认不提供证据。[当前原始证据与可见性限制 ↗](../../../apps/server/src/assistant/runtime.ts#L770 "支持助手只使用当前 head 的非派生证据，以及群会话无策略时默认拒绝证据访问。")

任务更新要求用户文本包含明确动作、任务可见且版本匹配，改期与跟进还要验证原消息中的时间表达。[任务更新治理条件 ↗](../../../apps/server/src/assistant/runtime.ts#L702 "支持明确动作、任务可见性、版本匹配和时间表达校验等更新条件。") 创建任务会捕获当前输入并标记为 owner 原始证据，但 `governCreateTask` 自身未核验会话 principal 或真实发送者，因此旧稿中“owner 指令已经可靠核验”的结论已被替代。[任务创建证据标记与身份缺口 ↗](../../../apps/server/src/assistant/runtime.ts#L815 "支持运行时捕获当前输入并标记为 owner 原始证据，同时表明该函数没有核验会话 principal 或实际发送者身份。")

ACP 的权限与补充输入请求先等待运行时回调，回调成功后才提示并返回拒绝结果；回调异常会阻断后续显式拒绝流程，故不能再概括为“请求始终被提示并固定拒绝”。[ACP 权限与补充输入处理顺序 ↗](../../../apps/server/src/agents.ts#L183 "支持运行时回调先于提示和拒绝结果执行，并说明回调异常会阻断后续显式拒绝流程。") model 与 effort 会依据会话选项校验，图片会检查 Agent 能力；上下文预算只有调用方提供预算且模型元数据含有限窗口时才实际比较。[上下文预算元数据条件 ↗](../../../apps/server/src/agents.ts#L74 "支持只有发现所选模型的有限 contextWindow 元数据时才实际比较预算，否则返回 null。")[ACP 会话配置与能力检查 ↗](../../../apps/server/src/agents.ts#L301 "支持 model、effort 按会话选项校验，按需检查上下文预算和图片能力。")

<a id="progress_limits"></a>
## 运行周期与尚未解决的限制

应用启动时恢复未完成的助手 turn，并启动提醒、输入聚合、学习及飞书运行时；关闭时停止这些后台能力、独立运行、检索和数据库。[应用恢复、后台循环与关闭 ↗](../../../apps/server/src/app.ts#L618 "支持未完成 turn 恢复、后台能力启动以及关闭时的资源清理顺序。") Hook 采用先写本地 spool、再短超时投递的方式；只有回执中的 producer、eventId 和摘要全部匹配才删除记录，失败项会保留并中止本轮后续发送。[Hook 队列确认与失败保留 ↗](../../../apps/server/src/inputs/spool.ts#L197 "支持回执完全匹配后才删除记录，以及投递失败时保留记录并停止本轮后续发送。")

检索配置关闭时使用关键词实现，启用后才加载中文 embedding 并启动语义检索。[检索实现选择 ↗](../../../apps/server/src/retrieval/factory.ts#L9 "支持关闭配置时使用关键词检索、启用后加载中文 embedding 并启动语义检索。") 仍有明确限制：`OMEM_PORT` 只经过 `Number` 转换，没有有限整数和合法端口范围校验；进程入口只展示成功监听及收到两个终止信号后关闭成功并以零状态退出；精确原文读取只接受 `verbatim-v1`，旧式有损捕获会成为显式缺失，不能从当前工作树补造证据。[运行配置与端口转换 ↗](../../../apps/server/src/config.ts#L95 "支持端口来自环境变量且当前只经过 Number 转换的限制。")[服务端进程入口 ↗](../../../apps/server/src/main.ts#L1 "支持入口只覆盖成功监听和两个终止信号下关闭成功后的零状态退出。")[固定修订原文读取 ↗](../../../apps/server/src/source-text.ts#L3 "支持只读取 verbatim-v1 固定修订，并把旧式有损捕获视为显式缺失。")
