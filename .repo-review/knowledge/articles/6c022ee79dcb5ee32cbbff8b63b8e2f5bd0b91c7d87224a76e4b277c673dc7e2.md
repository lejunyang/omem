# 个人记忆服务的运行核心

服务端根模块把多来源捕获、不可变修订、证据检索、Agent 问答、受治理事项操作和可选外部集成组装为单一个人记忆服务，并统一负责访问控制、后台处理与资源回收。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="service_boundary"></a>
## 统一服务入口与当前产品边界

服务端根模块解决“材料如何进入同一证据链，并被助理安全使用”的问题。`buildApp` 组装 HTTP 服务、SQLite 存储、知识接口、检索、问答运行、记忆与反馈服务；学习流水线和飞书运行时按配置启用。子知识提供了组合关系的分层说明，实际装配由组合入口源码支撑。参考 [服务组合关系 ↗](464fb8678bf77a7fc70c6e577b524284f5161deefd39d11125de970688dbea13.md#composition "作为子知识说明服务端组合根如何连接存储、知识、检索和助理；附近同时引用原始源码，避免把派生总结当作独立证据。") [核心服务装配 ↗](../../../apps/server/src/app.ts#L47 "支持 Fastify、Store、记忆、反馈、检索和主助理在组合入口中被实际创建并连接。")

当前实现明确面向个人使用：SQLite 保存修订、变化和通知，团队级租户权限仍属于后续迁移范围。因此，服务虽保留主体和可见性等合同，也不能据此宣称已具备多人数据隔离。参考 [单用户存储边界 ↗](../../../apps/server/src/store.ts#L4 "支持当前 SQLite 实现是单用户基础、团队权限仍待迁移的限制。")

<a id="capture_flow"></a>
## 从外部输入到不可变证据

文件、Git、飞书、Hook、直接捕获和输入事件都会先转换并通过共享捕获合同，再交给 `Store.capture`，从而让不同入口共享文本、图片、链接及来源信息的校验边界。参考 [统一捕获路由 ↗](../../../apps/server/src/app.ts#L204 "支持直接捕获、连接器和输入事件均经过捕获合同并进入 Store 的流程。")

```mermaid
flowchart LR
  A[多来源输入] --> B[捕获合同校验]
  B --> C[不可变修订与顺序片段]
  C --> D[来源头与变化记录]
  D --> E[抽取或更新复核任务]
```

新内容会形成不可变修订、顺序片段和变化记录；来源更新还会令旧依赖过期并安排刷新。子知识概括了版本生命周期，具体写入与任务入列由原始实现支撑。参考 [不可变修订生命周期 ↗](ae32ae66caebad9bb4b3779b7759004c374474800a75ef483895162b93c1d74d.md#capture-flow "作为子知识概括捕获到修订、片段及来源头的流程，并与原始写入代码配合阅读。") [修订与更新传播 ↗](../../../apps/server/src/store.ts#L197 "支持创建不可变修订和片段、更新来源头、记录变化并为来源更新安排刷新任务。") 只有输入来源信息同时提供采集器标识和事件标识时，系统才写入事件回执并据此进行事件级重复或冲突判断；缺少任一字段时，回执为 `null`。参考 [事件回执写入条件 ↗](../../../apps/server/src/store.ts#L311 "支持只有来源信息同时含采集器和事件标识时才写入回执，否则返回空值的限定。")

模型摘要等派生材料不会再次进入声明抽取队列，避免把总结当作新的独立证据。参考 [派生材料隔离 ↗](../../../apps/server/src/store.ts#L348 "支持派生材料不进入声明抽取队列、原始材料携带有效性版本进入后续处理。")

<a id="assistant_governance"></a>
## 检索、问答与受治理操作

检索关闭时使用关键词实现，启用后才启动中文语义检索及其关闭生命周期。参考 [检索模式选择 ↗](../../../apps/server/src/retrieval/factory.ts#L14 "支持未启用时使用关键词检索、启用后启动语义检索及其关闭生命周期。") 主助理按会话读取历史、检索可见证据，并允许模型提出至多一轮补充检索；检索词只是查找线索，不能直接充当事实。参考 [助理检索与补充查询 ↗](../../../apps/server/src/assistant/runtime.ts#L463 "支持按会话组装历史与可见证据，并允许受限的第二轮检索。")

模型产生的事项请求不会直接获得写权限。运行时重新检查用户是否明确要求操作、事项版本、时间表达和证据范围；最终回复依据实际执行结果生成，引用也被限制为运行时确实提供的证据。参考 [事项治理与引用收敛 ↗](../../../apps/server/src/assistant/runtime.ts#L540 "支持明确意图检查、受治理工具调用、按实际执行结果生成回复以及限制引用范围。") 证据还必须来自来源当前头且不能是派生材料；群聊若没有注入真实可见性策略，默认看不到任何证据。参考 [当前证据与可见性门禁 ↗](../../../apps/server/src/assistant/runtime.ts#L770 "支持过滤旧头和派生证据，并说明未配置策略时群聊采用拒绝默认值。")

<a id="lifecycle_limits"></a>
## 访问边界、生命周期与尚未收敛之处

所有 API 统一经过访问检查：配置令牌时验证 Bearer token，否则只接受本机 Host 和本机 Origin；输入、冲突和并发错误再映射为对应 HTTP 状态。参考 [API 访问控制 ↗](../../../apps/server/src/app.ts#L138 "支持令牌或本机来源校验，以及输入、冲突和活动过多等错误的统一处理。") 启动末尾会恢复未完成对话、周期刷新提醒与输入批次，并启动可选学习和飞书运行时；关闭时停止这些组件、旧式问答运行、检索和数据库。参考 [启动恢复与关闭顺序 ↗](../../../apps/server/src/app.ts#L640 "支持未完成对话恢复、周期任务、可选运行时启动及关闭时的资源回收顺序。")

目前同时存在内存态证据问答 `Runs` 与持久化会话式 `AssistantRuntime`。前者最多并行两个运行，记录仅保存在进程内；后者具有取消、重试和重启恢复语义。两套接口仍同时公开，长期定位尚未由材料说明。参考 [内存态问答运行 ↗](../../../apps/server/src/runs.ts#L19 "支持 Runs 的并发限制、内存记录和有限淘汰策略。") [两类问答接口 ↗](../../../apps/server/src/app.ts#L562 "支持应用同时暴露证据问答运行接口和持久化会话轮次接口。") 配置加载覆盖 profile、数据目录、监听地址和端口，但端口只经过数值转换，未显式校验整数及合法范围。参考 [运行参数组装 ↗](../../../apps/server/src/config.ts#L107 "支持数据目录、Agent 工作目录、令牌、监听地址和端口的来源，并显示端口仅经 Number 转换。")
