# 开发端口选择与冲突处理

集中校验和探测开发端口：显式端口非法或占用时快速失败，默认端口占用时申请系统临时端口，供 API 与代理共享确定结果。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="selection"></a>
## 选择流程

`selectDevPort` 将环境变量或默认值转成整数，拒绝负数、超出 TCP 范围和非整数；随后在 `127.0.0.1` 临时监听目标端口，读取实际分配值后关闭探测服务器。[端口校验与本地监听探测 ↗](../../../scripts/dev-ports.ts#L1 "支持输入范围校验、回环地址探测及系统分配端口的流程说明。") 传入 `0` 时由操作系统分配空闲端口，这也是默认端口冲突后的回退机制。

<a id="boundaries"></a>
## 冲突语义与边界

只有 `EADDRINUSE` 会被特殊处理：用户显式指定的端口冲突会抛出可操作错误，而默认端口冲突则递归探测端口 `0` 并记录替代值；权限不足等其他错误原样传播。[占用端口的显式失败与默认回退 ↗](../../../scripts/dev-ports.ts#L18 "支持 EADDRINUSE 分支及其他错误传播边界的说明。") “探测后关闭、子进程稍后再绑定”存在竞态窗口，因此它降低误连风险但不能原子保留端口；是否被调用方再次以 strict-port 方式校验取决于编排模块。
