# Code Wiki 的仓库路径分组规则

该模块提供一个共享、确定性的路径到模块名称映射，供 Wiki 索引与 Vue 阅读器采用同一分组口径；未命中的路径统一归入 other。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="mapping"></a>
## 固定前缀与服务端细分

`moduleForPath` 按路径前缀把 Web、UI、合同、代理运行时、Lark 集成和脚本归入固定模块。[共享路径分组规则 ↗](../../../packages/contracts/src/code-modules.ts#L1 "支持各主要目录前缀、Lark 特例及服务端路径片段分组的具体行为。") 服务端路径另按第四个路径片段细分；位于 `apps/server/src/` 根部或缺少该片段时回退到 `server-root`。这是一套顺序敏感的字符串规则，例如 Lark 必须先于一般服务端规则匹配。

<a id="boundary"></a>
## 用途与限制

所有未覆盖路径返回 `other`，函数本身不读取仓库、检查文件是否存在，也不做路径正规化。[未匹配路径兜底 ↗](../../../packages/contracts/src/code-modules.ts#L8 "支持未知或未覆盖路径统一归入 other，并界定该函数只是字符串映射。") 因而它适合让索引与阅读器稳定共享展示分组，但新增顶层目录或重命名路径时必须同步修改规则，否则内容只会进入兜底组。
