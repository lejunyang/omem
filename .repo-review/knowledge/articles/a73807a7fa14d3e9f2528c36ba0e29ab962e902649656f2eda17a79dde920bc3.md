# 仓库路径的共享模块分组

该文件提供确定性的仓库路径分类函数，供 Wiki 索引与 Vue 阅读器共享；它优先识别固定模块和 Lark 集成，再细分服务端路径，并以 scripts 或 other 收束其余输入。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-flow"></a>
## 作用与核心流程

`moduleForPath` 是 Wiki 索引与 Vue 阅读器共用的路径分组合同：它接收字符串路径并返回模块名称，使两个消费端能够采用一致的仓库结构视图。[Wiki 与 Vue 阅读器共享分组 ↗](../../../packages/contracts/src/code-modules.ts#L1 "支持该函数被定义为 Wiki 索引和 Vue 阅读器共享路径分类合同的判断。")

匹配按代码顺序执行：Web、共享 UI、契约和 Agent Runtime 使用固定前缀；Lark 集成在通用服务端规则之前识别，因此不会被归入普通服务端子目录。[固定模块与 Lark 优先映射 ↗](../../../packages/contracts/src/code-modules.ts#L2 "支持固定模块前缀的映射，以及 Lark 在通用服务端分支之前被优先识别的流程说明。") 其余 `apps/server/src/` 路径按层级处理，根级内容返回 `server-root`，更深路径取第四个分段；`scripts/` 单独映射为 `scripts`，其他输入最终归入 `other`。[服务端、脚本与兜底分类 ↗](../../../packages/contracts/src/code-modules.ts#L8 "解释服务端动态分组、scripts 固定映射及 other 最终兜底的完整分类流程。")

<a id="boundaries-and-relations"></a>
## 输入边界与潜在异常

该函数只做前缀判断和 `/` 分割，不验证文件存在性，也不规范化反斜杠、前导 `./`、大小写或重复分隔符。因此，非标准输入可能进入 `other`，也可能得到空字符串或其他非预期分组。例如 `apps/server/src//foo.ts` 已命中服务端分支，但第四个分段为空，返回值会是空字符串；空字符串并不会触发 `?? "server-root"` 的兜底。[服务端路径分段逻辑 ↗](../../../packages/contracts/src/code-modules.ts#L8 "支持重复分隔符可能使第四个路径分段为空，并产生空字符串等非预期结果的边界分析。")

现有固定材料只展示共享用途注释与分类实现，没有调用点、输入前置条件或测试证据。因此可以确认设计意图是让 Wiki 与 Vue 阅读器共享规则，但不能确认两端是否都实际复用它，也不能确认上游是否已统一路径格式。[Wiki 与 Vue 阅读器共享分组 ↗](../../../packages/contracts/src/code-modules.ts#L1 "支持该函数被定义为 Wiki 索引和 Vue 阅读器共享路径分类合同的判断。")
