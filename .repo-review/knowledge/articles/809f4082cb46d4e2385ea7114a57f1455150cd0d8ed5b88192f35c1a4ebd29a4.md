# 每日消息工作流配方与提示词组装

该模块以静态、版本化配方统一四类日常消息处理策略，并组装供既有助理与工具合同使用的提示词。它明确捕获内容本身不授予权限，并分别约束任务记录、讨论归属、等待跟进和只读回顾。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 作用与权限边界

模块把日常消息的处理规则集中为版本化配方，并明确这些规则只是处理策略：被捕获的消息是待分析的材料，本身不构成调用工具或修改事项的授权。[工作流的策略与授权边界 ↗](../../../apps/server/src/assistant/message-workflows.ts#L1 "支持该模块属于消息处理策略，并说明捕获消息本身不授予操作权限。") 各配方进一步限定可采取的动作，例如讨论中他人的承诺不自动成为当前用户的任务，等待流程不得自动对外联系或声称回复已经到达，回顾询问也不能直接改变任务状态或虚构进展。[四类每日消息工作流定义 ↗](../../../apps/server/src/assistant/message-workflows.ts#L3 "支持四类工作流的触发条件、输出形态及任务归属、等待跟进、延后提醒和只读回顾等行为边界。")

<a id="workflow"></a>
## 四类消息处理流程

`messageWorkflows` 定义四条路径：本人明确交办时记录或修改有来源的事项；讨论材料中区分决定、各方承诺和待确认问题；等待场景把复查时间与真实截止时间分开；事项回顾则依据当前任务状态和引用证据呈现逾期、等待、完成、取消及最小下一步。[四类每日消息工作流定义 ↗](../../../apps/server/src/assistant/message-workflows.ts#L3 "支持四类工作流的触发条件、输出形态及任务归属、等待跟进、延后提醒和只读回顾等行为边界。") 每条配方同时保存标识、人读标题、触发条件、预期输出和执行指令，使分类语境与行为约束维护在同一份声明中。

<a id="contract"></a>
## 类型合同、提示词生成与限制

工作流标识由只读常量数组推导为联合类型；`dailyWorkflowPrompt` 按数组顺序把标识、标题和指令拼接为带 `Daily message workflows v1` 前缀的文本，供既有助理与工具合同使用。[工作流类型与提示词组装 ↗](../../../apps/server/src/assistant/message-workflows.ts#L9 "支持工作流标识类型从配方数组推导，以及全部配方被拼接为版本化提示词的实现说明。") 当前文件没有展示工作流选择、模型调用、任务工具执行或持久化链路。配方层已明确：改期应复用准确任务 ID，未知复查时间保持为空，处于延后提醒期（`snoozed_until`）的事项不应被催促，读取通知也不等于任务完成。[四类每日消息工作流定义 ↗](../../../apps/server/src/assistant/message-workflows.ts#L3 "支持四类工作流的触发条件、输出形态及任务归属、等待跟进、延后提醒和只读回顾等行为边界。")
