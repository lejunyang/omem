# 仓库知识的恢复、发布与索引维护

该模块连接仓库评审适配器与通用知识仓库，负责启动时恢复用户补充和已复核文章、持久化问答材料，以及将当前知识发布为文章文件和 Wiki 导航。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="restore-flow"></a>
## 启动时恢复可追溯知识

`restoreReviewKnowledge` 解决服务重启后知识状态如何重新接续的问题。它先读取用户补充，只接受 `manual` 来源且标识以 `knowledge-answer:` 开头的输入，并再次经过捕获合同校验；随后捕获当前仓库材料、创建通用知识仓库并恢复文章。参考 [知识恢复入口 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持启动时依次恢复用户补充、捕获仓库材料、创建知识仓库并载入文章的流程说明。")

恢复后，函数把已存在的回答材料关联回问题记录；若对应知识文档尚未依赖该回答的当前摘要，就写入“尚未用于知识重核对”的失效原因，最后刷新仓库视图并返回覆盖情况、文章恢复结果与仓库实例。这个流程表明：**回答被保存不等于知识已经完成重核对**。参考 [回答状态与重核对失效 ↗](../../../apps/server/src/review/knowledge.ts#L18 "支持回答材料回写问题状态、缺少当前依赖时登记知识失效，以及最终刷新仓库的论断。")

文章恢复本身由通用知识层完成：只有具备生成与独立复核来源、且复核已接受的产物才可恢复；材料或子知识摘要变化时会标记为过期，而不会把旧结果当作当前知识。延伸阅读：[文章恢复与过期判定 ↗](../../../apps/server/src/knowledge/artifacts.ts#L40 "说明通用产物恢复层会检查复核来源、依赖摘要及子知识可用性，并区分 restored、stale、rejected 与 missing。")

<a id="answer-persistence"></a>
## 用户补充的可移植持久化

`saveReviewAnswerMaterials` 从数据库中选取当前版本的知识回答来源，保留标题、内容片段、上下文与来源信息，并统一写入仓库内的 `user-notes.json`。因此，该文件保存的是可重新捕获的原始回答材料，而不是把回答直接改写成派生知识正文；下次恢复时仍需重新走捕获与失效检查。参考 [用户回答材料保存 ↗](../../../apps/server/src/review/knowledge.ts#L28 "支持仅导出知识回答的当前版本，并保留片段、上下文和来源后写入用户补充文件的说明。")

<a id="publish-index"></a>
## 文章双写与 Wiki 导航生成

发布文章时，同一知识产物会同时写入运行期暂存目录和可提交的知识文章目录。索引生成只选择 `current` 文章，以概览文章摘要作为说明，并把主题文章与模块、材料文章分组列出；仅当内容变化时才重写根级 Wiki 文件。参考 [知识文章与索引发布 ↗](../../../apps/server/src/review/knowledge.ts#L35 "支持文章双目录写入、仅汇总当前文章以及按主题和模块生成 Wiki 导航的说明。")

该模块只负责文件发布和导航编排，不负责判断引用的语义是否正确，也未在这里提供跨多个文件写入的事务保障。文章文件如何转换为 Markdown、引用如何变成可跳转链接，属于通用知识产物层。延伸阅读：[文章 Markdown 渲染 ↗](../../../apps/server/src/knowledge/artifacts.ts#L8 "说明通用产物层负责把章节与内联引用转换为 Markdown 文件和可跳转链接。")
