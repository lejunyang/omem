# 仓库知识资产的恢复、持久化与索引发布

连接运行时知识仓库与可提交的 repo-review 资产，恢复用户回答和文章、标记待重核验依赖，并生成知识导航页。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="restore"></a>
## 启动恢复与失效标记

`restoreReviewKnowledge` 先读取用户回答文件，强制其为 manual 来源且 externalId 使用 knowledge-answer 前缀，再通过 Store 捕获为固定材料。随后捕获仓库材料、恢复文章，并把对应问题标为 answered。若回答材料的 digest 尚未出现在文章依赖中，则写入 invalidation，明确表示“已入库”不等于知识正文已重核验；最后刷新仓库视图。[评审知识恢复流程 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持回答捕获、文章恢复、问题状态更新及未消费回答触发失效标记的说明。")

<a id="persist"></a>
## 回答与文章持久化

`saveReviewAnswerMaterials` 从当前 manual 来源中筛选 knowledge-answer，重建 CaptureInput 并写入 `.repo-review/knowledge/user-notes.json`。`publishReviewArticle` 同时写运行时 staging 和可发布 articles 目录，使生成过程与提交资产均有落点。写文件前仅知识目录被显式创建；文章目录是否自动创建取决于被调用的 `writeKnowledgeArticle`，本材料不能进一步确认。[回答和文章资产写入 ↗](../../../apps/server/src/review/knowledge.ts#L28 "说明用户补充与知识文章分别写入哪些评审目录。")

<a id="index"></a>
## Wiki 索引生成边界

索引只纳入 `current` 文章，以 `topic:overview` 摘要作为介绍；其他 topic 页面和模块/材料页面分组输出，并以 document key 的 digest 形成链接。内容无变化时不重写 wiki。该函数只负责导航文件，不执行模型分析、独立复核或覆盖率判定；这些能力来自其调用链上的通用知识组件。[知识 Wiki 索引生成 ↗](../../../apps/server/src/review/knowledge.ts#L40 "支持 current 页面筛选、主题分组、摘要和 digest 链接规则。")
