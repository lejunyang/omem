# 评审知识的恢复、持久化与索引发布

负责从仓库知识目录恢复用户补充和已复核文章，标记尚待重核对的回答，并将回答、文章及可追溯知识索引持久化到约定位置。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="restore-flow"></a>
## 恢复顺序与失效标记

启动恢复时，模块只接受来源为手动输入且标识以 `knowledge-answer:` 开头的用户笔记，随后捕获仓库材料、建立带评审过滤的知识仓库并恢复文章。已保存回答会把对应疑问改为已回答；如果当前文章尚未依赖该回答的精确摘要，则写入失效原因，提醒后续重核对，而不会把回答直接视为正文结论。最后刷新仓库投影并返回覆盖率、恢复结果和仓库实例。[评审知识恢复流程 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持用户回答校验、材料与文章恢复、问题状态更新、失效标记及最终刷新顺序。")

<a id="persistence"></a>
## 回答与文章的持久化边界

用户回答从数据库当前 revision 重建为捕获输入，按外部标识排序后写入 `.repo-review/knowledge/user-notes.json`。文章发布同时写入运行时暂存区和可提交的知识文章目录，使运行产物与发布资产拥有相同文章内容但不同生命周期。[回答保存与文章发布 ↗](../../../apps/server/src/review/knowledge.ts#L28 "支持用户回答序列化位置以及文章同时写入暂存区和发布目录的说明。")

<a id="wiki-index"></a>
## 可追溯知识入口

索引仅纳入当前文章，以 `topic:overview` 的摘要作为导语，并把主题页与模块、材料页分组链接到按文档键摘要命名的 Markdown 文件。只有生成内容发生变化时才改写根级 wiki，从而减少无意义变更。[知识索引生成 ↗](../../../apps/server/src/review/knowledge.ts#L40 "支持当前文章筛选、主题与模块分组以及仅在内容变化时写入索引。")
