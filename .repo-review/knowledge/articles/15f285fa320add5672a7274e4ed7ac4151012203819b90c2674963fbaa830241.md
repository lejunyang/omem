# 仓库评审知识的恢复、持久化与发布编排

该模块连接仓库材料捕获、通用知识仓库与磁盘知识资产，负责恢复用户补充和已复核文章、衔接问题状态与失效记录、导出回答、双目录发布文章并生成 Wiki 入口。它是 repo-review 的编排层，不承担代码分析、模型生成或引用语义复核。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="responsibility"></a>
## 模块定位与统一知识链路

该文件是 repo-review 接入通用知识系统的编排层：恢复时先捕获仓库材料，再创建通用 `KnowledgeRepository` 并导入文章，没有建立代码专用的知识存储。[评审知识恢复的组装入口 ↗](../../../apps/server/src/review/knowledge.ts#L15 "支持该模块依次连接仓库材料捕获、通用知识仓库创建与文章恢复的定位。") 材料适配器把普通文件按内容哈希捕获为稳定的 `omem:*` 来源；内容或捕获格式未变化时可复用已有 revision，从而让文章依赖能够对照当前材料。[仓库材料的内容哈希捕获 ↗](../../../apps/server/src/review/materials.ts#L36 "支持文件按哈希判断是否重新捕获，并以 omem 文件键形成稳定材料来源。")

文章的 Markdown 渲染、文档键摘要命名以及 JSON/Markdown 双格式写入由通用 artifacts 模块实现；依赖检查和恢复状态则由该模块的另一段恢复流程负责。[通用文章渲染与双格式写入 ↗](../../../apps/server/src/knowledge/artifacts.ts#L8 "支持内联引用 Markdown 渲染、文档键摘要命名以及 JSON 和 Markdown 文件生成。")[文章恢复、来源记录与状态判定 ↗](../../../apps/server/src/knowledge/artifacts.ts#L32 "支持生成和复核模型记录要求、accepted 复核结论、依赖过期判定以及 rejected 和 missing 状态；同时表明实现未校验生成者与复核者身份不同。") 本文件主要选择 repo-review 的目录并串联这些通用能力。

<a id="restore-flow"></a>
## 启动恢复与回答触发的重核验

`restoreReviewKnowledge` 先读取 `user-notes.json`，只接受 `source=manual` 且 `externalId` 以 `knowledge-answer:` 开头的记录，并交由捕获 schema 校验；解析、身份检查或 schema 校验失败都会从当前函数抛出。[用户补充的恢复约束 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持 user-notes 的同步读取、manual 来源限制、外部标识检查和捕获 schema 校验。") 随后它捕获仓库材料并恢复已发布文章。恢复要求资产具有生成模型记录、复核模型记录且复核结论为 `accepted`；这替代了旧稿中“实现保证生成者与复核者独立”的过强结论，因为所给实现并未核验两者身份是否不同。材料摘要或子文章 revision 变化时，导入结果标记为 stale。[文章恢复、来源记录与状态判定 ↗](../../../apps/server/src/knowledge/artifacts.ts#L32 "支持生成和复核模型记录要求、accepted 复核结论、依赖过期判定以及 rejected 和 missing 状态；同时表明实现未校验生成者与复核者身份不同。")

已恢复的用户回答会把对应问题更新为 answered 并记录回答 revision；若目标文章尚未依赖该回答的当前 digest，则登记“尚未用于知识重核对”的 invalidation。[回答状态与知识失效衔接 ↗](../../../apps/server/src/review/knowledge.ts#L18 "支持用户回答更新问题状态，并在文章未依赖当前回答时登记重核验失效原因。") 因此，回答被捕获和问题被标记为已回答，并不代表正文已经完成重新分析。

<a id="persistence-boundaries"></a>
## 回答导出、文章发布与 Wiki 索引

`saveReviewAnswerMaterials` 仅导出 manual 命名空间下 `knowledge-answer:*` 来源的当前 revision，将其中的 parts、context 和 provenance 写回 `user-notes.json`。[用户回答材料导出 ↗](../../../apps/server/src/review/knowledge.ts#L28 "支持仅导出指定 manual 来源的当前内容，并保存 parts、context 与 provenance。") `publishReviewArticle` 连续调用同一通用写入器，把文章分别发布到运行期 staging 与版本化 articles 目录。[文章向两个目录发布 ↗](../../../apps/server/src/review/knowledge.ts#L35 "支持同一文章依次写入运行期 staging 与可发布 articles 目录，也揭示该函数未提供跨目录事务。") 通用写入器以文档键摘要作为文件名，并为每个目录生成 JSON 资产和带内联引用链接的 Markdown。[通用文章渲染与双格式写入 ↗](../../../apps/server/src/knowledge/artifacts.ts#L8 "支持内联引用 Markdown 渲染、文档键摘要命名以及 JSON 和 Markdown 文件生成。")

`writeReviewKnowledgeIndex` 只从调用方传入列表中筛选 `current=true` 的文章：主题文章与模块文章分别列出，概览摘要用作导语，并仅在文本变化时重写 Wiki 文件。[基于 current 字段的 Wiki 索引 ↗](../../../apps/server/src/review/knowledge.ts#L40 "支持索引仅筛选传入列表中的 current 文章、按主题分组并在内容变化时写入文件；它不读取导入状态。") 双目录写入和索引写入均为同步的顺序操作，所给代码没有展示跨文件事务或失败补偿。

<a id="limits"></a>
## 校验边界与被替代的状态结论

该模块不分析代码、不调用生成模型，也不判断引用是否在语义上支持论断。通用仓库校验负责文档 schema、引用键、目标、章节和材料行号等结构约束，并明确把语义正确性留给独立模型角色。[知识文档结构校验边界 ↗](../../../apps/server/src/knowledge/repository.ts#L41 "支持通用仓库校验内联引用、目标和材料范围，而语义正确性由独立模型角色检查。")

旧稿关于“stale、rejected 或 missing 的导入结果不会生成入口”的结论应被替代：当前索引函数只检查传入文章的 `current` 字段，并不读取 `knowledge_imports` 的导入状态。[基于 current 字段的 Wiki 索引 ↗](../../../apps/server/src/review/knowledge.ts#L40 "支持索引仅筛选传入列表中的 current 文章、按主题分组并在内容变化时写入文件；它不读取导入状态。") 恢复流程确实会记录 restored、stale、rejected 或 missing，但现有材料不足以证明某次新资产导入失败时，数据库里已有的 current 文章一定被撤销。[文章恢复、来源记录与状态判定 ↗](../../../apps/server/src/knowledge/artifacts.ts#L32 "支持生成和复核模型记录要求、accepted 复核结论、依赖过期判定以及 rejected 和 missing 状态；同时表明实现未校验生成者与复核者身份不同。")

<a id="open-risks"></a>
## 尚待确认的运行策略

当前恢复入口将用户补充文件的读取、JSON 解析、身份检查与捕获校验串在同一同步流程中，未展示坏记录隔离策略。[用户补充的恢复约束 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持 user-notes 的同步读取、manual 来源限制、外部标识检查和捕获 schema 校验。") 同样，文章发布依次写入两个目录，未展示原子替换或回滚。[文章向两个目录发布 ↗](../../../apps/server/src/review/knowledge.ts#L35 "支持同一文章依次写入运行期 staging 与可发布 articles 目录，也揭示该函数未提供跨目录事务。") 这些都属于上层运行策略与容错要求，不能仅凭本文件判断其预期行为。
