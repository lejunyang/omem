# 评审知识的恢复、持久化与发布

衔接仓库材料捕获、已复核知识恢复、用户补充保存和静态索引发布，使 repo-review 的知识可跨运行复用并保持来源失效提示。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="restore"></a>
## 恢复与重核对状态

`restoreReviewKnowledge` 先读取用户补充，只接受 `manual` 且标识以 `knowledge-answer:` 开头的捕获输入，校验后写入 Store；随后捕获当前仓库材料、创建评审专用知识仓库，并恢复已发布文章。[恢复评审知识入口 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持恢复顺序、用户补充约束以及通用仓库和文章恢复的说明。") 对恢复出的回答材料，它会把对应问题标为已回答；若文章依赖中尚未包含该回答及其摘要，则登记失效原因，提示补充内容还没有进入重核对。最后刷新仓库投影并同时返回覆盖率、恢复结果和仓库实例。[回答状态与失效登记 ↗](../../../apps/server/src/review/knowledge.ts#L18 "直接说明回答材料如何更新问题状态，并在文章未吸收补充时登记失效。")

<a id="persistence"></a>
## 用户补充与文章落盘

`saveReviewAnswerMaterials` 从当前 source head 中筛选知识回答，重建捕获输入并写入 `user-notes.json`，因此保存的是可再次捕获的原始补充，而不是派生正文。[用户补充保存逻辑 ↗](../../../apps/server/src/review/knowledge.ts#L28 "支持从当前修订重建 CaptureInput 并写入 user-notes 文件的描述。") 文章发布同时写入运行期 staging 和版本化知识目录；索引则只列出 `current` 文章，以概览摘要作为说明，并按主题页与模块材料分组生成 wiki 链接。[文章发布与知识索引 ↗](../../../apps/server/src/review/knowledge.ts#L35 "支持双目录发布、仅索引当前文章以及主题和模块分组的说明。")

<a id="boundaries"></a>
## 边界与模块关系

该模块不负责分析或语义复核，而是调用通用材料适配器、知识仓库及 artifact 读写层完成恢复和发布。用户补充在恢复时经过统一捕获 schema 校验，文章恢复规则则由通用 artifact 模块执行。[通用知识模块依赖 ↗](../../../apps/server/src/review/knowledge.ts#L3 "导入关系表明本文件复用 artifact、repository 与材料适配器，而非自行实现分析流程。") 当前实现使用同步文件 I/O；用户笔记 JSON 损坏、输入不符合约束或写入失败都会直接抛出，代码中没有原子替换、局部跳过或备份恢复机制。
