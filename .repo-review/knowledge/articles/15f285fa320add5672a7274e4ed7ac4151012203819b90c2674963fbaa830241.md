# 仓库知识的恢复、补充保存与发布

该模块连接仓库材料与通用知识仓库：恢复用户回答和已复核文章，标记尚未吸收回答的知识，持久化用户补充，将文章发布到运行时暂存区与可提交目录，并生成当前知识的阅读索引。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="restore-flow"></a>
## 恢复材料与知识状态

该模块负责把仓库中的用户补充、当前材料和已发布知识重新接入统一知识仓库。恢复时，它先读取用户补充文件，只接受手工来源且外部标识符合知识回答前缀的输入，并再次通过捕获合同校验；随后捕获当前仓库材料、建立知识仓库，再从文章目录恢复制品。参考 [知识恢复流程 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持恢复时校验用户补充、捕获仓库材料、创建知识仓库并装载文章的说明。")

已保存的回答会把对应问题更新为已回答，并记录回答修订。如果文章依赖中还没有相同材料及摘要，则登记“尚未用于知识重核对”的失效原因，避免把回答入库误认为正文已经更新；完成后刷新仓库，并返回材料覆盖、文章恢复结果和仓库实例。参考 [回答状态与重核对 ↗](../../../apps/server/src/review/knowledge.ts#L18 "支持回答更新问题状态、检查文章依赖并登记重核对失效原因的说明。")

<a id="persist-publish"></a>
## 保存用户补充与发布文章

用户回答与派生文章采用不同的持久化路径。回答从手工命名空间读取，保留正文分片、上下文和来源信息，再写入用户补充文件；后续恢复仍通过统一捕获流程处理，而不是直接改写文章。参考 [用户补充持久化 ↗](../../../apps/server/src/review/knowledge.ts#L28 "支持从手工来源提取回答字段并写入用户补充文件的说明。")

发布文章时，协调层按顺序调用同一个制品写入器：先写运行时暂存目录，再写可提交的文章目录。参考 [双目录发布顺序 ↗](../../../apps/server/src/review/knowledge.ts#L35 "直接支持文章先写运行时暂存目录、再写可提交知识目录，并说明该协调层未展示原子事务。") 通用写入器以文档键摘要命名文件，同时生成 JSON 和 Markdown，并仅在内容发生变化时覆盖文件；Markdown 渲染会把正文中的引用标记转换为指向文章、代码或原始证据的链接。参考 [文章制品与引用链接 ↗](../../../apps/server/src/knowledge/artifacts.ts#L8 "支持生成 JSON、Markdown、按变化写入，以及将内联引用渲染为可点击链接的说明。")

<a id="index-boundaries"></a>
## 阅读索引与恢复边界

阅读索引只纳入当前版本文章：概览摘要作为导语，主题文章与模块材料分别列出，并按文档键摘要链接到 Markdown 文件；内容未变化时不会重复写入索引。参考 [当前知识阅读索引 ↗](../../../apps/server/src/review/knowledge.ts#L40 "支持索引筛选当前文章、组织主题与模块链接并避免无变化覆盖的说明。")

文章恢复并非无条件导入。制品层要求版本、已接受的独立复核结论及生成与复核模型来源完整；材料或子知识摘要变化时标记为过期，格式或来源不合格时拒绝，依赖的子知识不可用时标记缺失。参考 [文章恢复判定 ↗](../../../apps/server/src/knowledge/artifacts.ts#L32 "支持恢复时检查复核来源、依赖摘要，并区分恢复、过期、拒绝和缺失状态的说明。") 当前发布函数只是连续执行两次文件写入，所给材料未显示事务或失败补偿，因此不能保证暂存区与正式目录始终原子一致。参考 [双目录发布顺序 ↗](../../../apps/server/src/review/knowledge.ts#L35 "直接支持文章先写运行时暂存目录、再写可提交知识目录，并说明该协调层未展示原子事务。")
