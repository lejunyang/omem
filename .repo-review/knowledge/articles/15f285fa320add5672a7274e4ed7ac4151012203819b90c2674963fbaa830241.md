# 仓库评审知识的恢复、持久化与发布适配

该模块连接通用捕获、知识仓库和文件制品层，负责恢复仓库评审知识、持久化用户补充、发布文章，并生成面向阅读者的知识索引。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决的问题与模块位置

该文件是 repo-review 与通用知识系统之间的编排适配层：它不分析代码内容，而是把仓库材料、用户补充和已复核文章装入同一个 `KnowledgeRepository`，并将结果发布为可追踪的文件制品。其依赖关系清晰地指向捕获合同、通用制品读写、知识仓库以及仓库材料适配器 [评审知识适配层依赖 ↗](../../../apps/server/src/review/knowledge.ts#L1 "支持该模块连接捕获合同、知识制品、知识仓库和仓库材料适配器的定位。")。底层仓库会排除派生 revision，并把当前原始 revision 转成带稳定摘要、行数和 fragment 的材料，因而这里恢复的知识仍以原始证据为基础 [原始材料转换规则 ↗](../../../apps/server/src/knowledge/repository.ts#L11 "说明通用知识仓库排除派生 revision，并为原始材料建立摘要、行数和 fragment。")。

<a id="restore-flow"></a>
## 启动恢复与补充答案重核验

`restoreReviewKnowledge` 先读取 `user-notes.json`；每条记录必须是 `manual` 来源且外部标识以 `knowledge-answer:` 开头，再经过捕获 schema 校验后写入 Store，否则恢复直接抛错 [用户补充恢复校验 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持用户补充必须满足来源、标识前缀和捕获 schema 的约束。")。随后它捕获当前仓库材料、创建知识仓库并恢复文章制品 [仓库材料与文章恢复流程 ↗](../../../apps/server/src/review/knowledge.ts#L15 "支持材料捕获、知识仓库创建和文章恢复的执行顺序。")。对已捕获的回答材料，流程把对应问题标为 answered；若目标文档的依赖尚未包含该回答及其当前摘要，则写入 invalidation，明确表示“保存答案”不等于“知识已重核验”，最后刷新仓库视图 [回答状态与知识失效标记 ↗](../../../apps/server/src/review/knowledge.ts#L18 "说明回答材料会更新问题状态，并在尚未成为文档依赖时触发重核验标记。")。文章恢复层还会依据材料或子文章摘要判断 stale，并拒绝缺少生成、复核来源的制品 [文章恢复与过期判定 ↗](../../../apps/server/src/knowledge/artifacts.ts#L40 "解释恢复层如何校验生成复核来源、识别依赖变化并保留 stale 或 rejected 状态。")。

<a id="persist-publish"></a>
## 持久化、发布与索引生成

`saveReviewAnswerMaterials` 只导出 manual 命名空间中当前 head 且标识匹配 `knowledge-answer:%` 的来源，将 revision body 中的 parts、context、provenance 还原为捕获输入并写入固定 JSON 文件 [用户答案材料导出 ↗](../../../apps/server/src/review/knowledge.ts#L28 "支持导出范围、字段映射以及 user-notes.json 的写入行为。")。`publishReviewArticle` 则把同一文章分别写到运行期 staging 和可提交的知识目录；通用写入器按 document key 的摘要命名，同时生成 JSON 与把内联引用转换为链接的 Markdown [知识文章制品写入 ↗](../../../apps/server/src/knowledge/artifacts.ts#L8 "说明文章以摘要命名并同时生成 JSON 与带可读引用链接的 Markdown。")。索引生成仅选取 `current` 文章，以 `topic:` 区分主题页和模块材料，并在内容变化时更新 `.repo-review/wiki.md` [知识发布与 Wiki 索引 ↗](../../../apps/server/src/review/knowledge.ts#L35 "支持双目录发布、current 过滤、主题分类和按内容变化写入索引的论断。")。

<a id="boundaries"></a>
## 边界条件与测试缺口

恢复路径采用同步文件与数据库操作：不存在用户补充文件时可继续，但文件存在而 JSON 损坏、条目来源非法或 schema 不匹配时会抛错；发布到 staging 与正式目录也是两次独立写入，没有从现有代码看到事务性回滚 [同步恢复与发布边界 ↗](../../../apps/server/src/review/knowledge.ts#L9 "支持恢复过程中的同步解析和双目标独立写入，用于指出异常传播及非事务性边界。")。索引只展示当前文章，且 overview 缺失时使用默认说明，因此 stale 或历史 revision 不会进入导航 [当前文章筛选与默认概览 ↗](../../../apps/server/src/review/knowledge.ts#L40 "支持索引只纳入 current 文章，并在 overview 缺失时使用默认摘要。")。所给材料未包含对应测试文件，无法确认部分写入失败、损坏用户补充、问题记录缺失以及索引无变化时不改写等行为是否有自动化断言。
