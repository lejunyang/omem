# 持久化任务执行器

在 JobRepository 的租约状态机之上执行按 kind 分派的处理器，维持心跳并协调取消、停机和失败分类。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="execution"></a>
## 领取、分派与心跳

worker 每次只领取一个符合可选 kinds/jobIds 过滤条件的任务，并把当前模型指纹交给仓库创建 attempt。没有注册对应 kind 的处理器时，任务仍会进入 running，再以 config 错误完成失败记录，避免无声卡在队列。正常任务建立 AbortController、标记运行并按默认租期三分之一的间隔续租；心跳失去租约便触发 abort，提示处理器尽快退出。[任务领取、处理器分派与心跳 ↗](../../../apps/server/src/jobs/worker.ts#L47 "支持单任务领取、缺失处理器失败、运行标记及租约心跳的说明。")

处理器成功后由仓库校验 token 并提交 resultRef 与 usage。普通异常默认归为 permanent；显式 `JobExecutionError` 可声明失败类型。若信号因 worker 停机而中断，则改记 transient 以便恢复；其他 abort 记 cancelled。收尾若发现租约已失效，只报告 stale，绝不会用旧 worker 的结果覆盖新 owner。[执行结果与失败分类 ↗](../../../apps/server/src/jobs/worker.ts#L87 "支持成功提交、异常分类、停机中断转瞬时失败以及 stale lease 防覆盖。")

<a id="cancellation"></a>
## 协作取消与边界

外部取消先调用仓库的 generation 与 requestId 幂等控制；只有仓库返回 cancelling 时，worker 才中止当前进程内对应控制器。stop 会标记停机并 abort 所有活动任务，但不等待 handler 真正结束，也不主动停止继续调用 processOne；调用方必须负责停止调度并等待在途 Promise。[取消与停止接口 ↗](../../../apps/server/src/jobs/worker.ts#L137 "支持先持久化取消意图、再中断本地 handler，以及 stop 仅发送中断信号的边界。")

该设计依赖 handler 正确监听 AbortSignal。若处理器忽略信号，它可能继续产生外部副作用，最终只能靠租约检查阻止旧结果写回数据库；材料并未证明外部动作本身具备幂等或补偿能力。因此租约提供的是持久化状态所有权，不等同于对任意外部副作用的 exactly-once 保证。[仓库租约完成校验 ↗](../../../apps/server/src/jobs/repository.ts#L538 "支持旧租约不能提交成功结果，说明 worker 对数据库结果所有权的保护范围。")
