# 耐久任务执行器

从 JobRepository 领取单个任务，管理运行态、租约心跳、处理器调用、成功或分类失败落库，并将取消和停机信号传递给活跃处理器。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="execution"></a>
## 单任务执行流程

`processOne` 先携带 worker ID、任务过滤条件、运行指纹和租约时长向仓储领取任务；无任务时立即返回。若任务类型没有注册处理器，仍先进入 running，再以 config 错误终结，避免任务永久悬挂。[领取任务与缺失处理器分支 ↗](../../../apps/server/src/jobs/worker.ts#L47 "支持领取参数、空队列返回以及未注册任务类型按配置错误终结。")

正常路径为任务创建 AbortController、登记活跃映射并标记 running。定时心跳延长租约；心跳失败即中止 signal，提示处理器停止。处理器返回后由仓储在租约校验下保存成功状态、结果引用和 usage。无论成功失败，finally 都清除心跳和活跃记录。[运行、心跳与成功提交 ↗](../../../apps/server/src/jobs/worker.ts#L72 "支持 AbortController、活跃任务登记、租约心跳、处理器调用和资源清理流程。")

<a id="failure_cancel"></a>
## 失败分类、取消与停机

处理器可抛出 `JobExecutionError` 明确 transient、bad-output、auth、config、permanent 或 cancelled；普通异常默认视为 permanent，但若 signal 已中止则视为 cancelled。停机引起的中止会改记 transient，使任务可按仓储策略重试；记录失败时若租约已经失效，则返回 stale 而不覆盖新持有者的状态。[执行异常与过期租约处理 ↗](../../../apps/server/src/jobs/worker.ts#L97 "支持异常分类、停机转瞬态失败以及失去租约后不覆盖状态的行为。")

显式取消先调用仓储写入控制状态，仅当结果为 cancelling 时才中止当前进程中的活跃 controller。`stop` 只设置 stopping 并广播 abort，没有等待所有 handler 退出的 Promise；因此处理器必须协作响应 signal，进程关闭顺序也需由上层保证。该文件不并行领取多个任务，调用方若需吞吐量必须并发调用或创建多个 worker。[取消传播与停止 ↗](../../../apps/server/src/jobs/worker.ts#L137 "支持控制请求后中止活跃处理器以及 stop 广播取消的边界说明。")
