# Code Wiki 哈希路由往返测试

验证概览、模块、文件行号与多层 trail 可通过 URL hash 解析和恢复，并确认损坏路由安全回退。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="routing"></a>
## 视图解析合同

测试覆盖空 hash 默认进入概览、模块路径解析、文件标识与行号查询参数解析，以及未知路径回退概览。[基础哈希路由断言 ↗](../../../apps/web/src/codewiki/hashroute.test.ts#L4 "支持默认视图、模块、文件行号和损坏路由回退行为。") 对应路由器采用小型判别联合而非完整路由框架：先提取行号和 trail 后缀，再识别 overview、structure、graph、module、file；无法识别的 head 不抛错，而是返回 overview。[哈希路由解析器 ↗](../../../packages/ui/src/OmHashRoute.ts#L27 "解释行号提取、视图分派和未知路径回退流程。") 这让评审页面刷新和外部深链在输入损坏时仍有稳定落点。

<a id="trail_roundtrip"></a>
## Trail 深链往返

测试证明 trail 以成对的 `kind/id` 段保存，可解析模块、文件、片段，并验证“写出后再解析”的文件视图和两层 trail 保持稳定；另以五层链确认顺序与身份不丢失。[Trail 往返断言 ↗](../../../apps/web/src/codewiki/hashroute.test.ts#L20 "支持 trail 段解析、写后再读稳定及五层链顺序保持。") Trail 标题没有被编码，解析后由 id 暂代，因此这些断言只保证导航身份，不保证刷新后的展示标题、滚动位置或附加字段恢复。路由解析还会按 `MAX_TRAIL` 截取 URL 中的栈，但本测试只到五层，未覆盖达到 200 层后的显式提示或截断体验。[Trail 解析与长度限制 ↗](../../../packages/ui/src/OmHashRoute.ts#L33 "说明解析时只重建 kind、id、title，并对 URL 栈应用最大长度。")
