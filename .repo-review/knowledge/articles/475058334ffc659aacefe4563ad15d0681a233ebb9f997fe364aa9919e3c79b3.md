# 知识阅读与整理 API

为知识文章、固定材料、引用、问题回答和显式分析提供 HTTP 接口，并在接口层维护单次知识整理任务的运行状态。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-flow"></a>
## 职责与核心流程

该模块把知识仓库暴露为 Fastify 路由。文章列表和详情会先刷新新鲜度；详情中的引用按文章保存的依赖摘要解析到固定文章版本或原始材料版本，目标缺失时保留引用并返回不可操作原因。[文章与固定引用解析 ↗](../../../apps/server/src/knowledge/api.ts#L18 "支持文章读取时刷新状态，以及引用按保存的依赖版本解析并显式返回不可用原因。") 材料详情会对代码文件做单文件解析，仅将相对 import 转成确定性的模块链接；这说明文件依赖，不证明被导入函数实际发生调用。[代码材料的 import 链接 ↗](../../../apps/server/src/knowledge/api.ts#L46 "支持材料页仅依据相对 import 建立确定性模块依赖链接、不据此断言调用关系。")

显式分析接口要求已配置 Agent、当前没有另一分析任务，并校验 1–500 个 revisionId 都仍对应可用材料。通过后构造 `KnowledgePipeline` 异步执行并立即返回 202；结果或错误写入进程内的 `lastRun`，服务关闭时停止仍在运行的流水线。[显式知识分析入口 ↗](../../../apps/server/src/knowledge/api.ts#L87 "支持分析请求的配置、互斥与材料校验，以及异步状态记录和关闭清理流程。")

<a id="boundaries"></a>
## 输入边界与检索限制

问题回答要求请求体中的 `answer` 是字符串、原始字符串长度不超过 20000，并且 `trim()` 后非空；保存时使用去除首尾空白后的文本，再通知可选的 `onAnswer` 回调。[问题回答接口 ↗](../../../apps/server/src/knowledge/api.ts#L75 "支持按原始字符串判断长度、按 trim 结果判断非空，并以去空白文本保存和通知可选回调。") 因而先前“去空白后 1–20000 字”的结论已被替代：即使去空白后未超限，原始字符串超过 20000 仍会被拒绝。

搜索端点对 `repository.list()` 返回的所有 head 文章逐节做大小写无关的空白分词子串匹配，最多返回 50 条派生正文结果；它没有先调用 `refresh()`，也没有按 `current` 过滤，因此结果可能包含尚未刷新或已标为非当前的 head，并不等同于语义检索或原始证据召回。图片接口则只返回数据库记录且资产存在的 PNG、JPEG 或 WebP。[图片与章节搜索接口 ↗](../../../apps/server/src/knowledge/api.ts#L69 "支持图片类型限制，以及搜索遍历全部 head、未刷新也未按 current 过滤的实际边界。")
