# 一次提问如何找到答案：搜索、补读与回答

沿“这次活动要准备多少钱、到哪里集合？”这一教学问题，说明已保存材料怎样变成全文与向量候选，候选怎样在同一固定版本中补回完整章节与上级条件，助手怎样发现跨章节缺口、核对旧记录并组织有条件的引用答案；最后用召回、补读、调查和回答四层定位遗漏。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="example"></a>
## 先明确什么才算回答了问题

先给结论：一次可用回答不是“找到一段相关文字”，而是依次完成三件事：**找出能回答问题的候选，补回会改变结论的上下文，再逐项写进答案**。任何一步都可能遗漏。

下面是贯穿全文的**教学示例**，只用于解释机制，不代表一次真实运行或固定排名：

| 已保存的材料 | 内容 |
| --- | --- |
| 当前活动说明的“费用”章 | 参加预算八十元；仅限已报名者；不含交通费；周三 18 点前确认 |
| 同一说明的“集合”章 | 在图书馆集合 |
| 旧活动记录 | 也出现“八十元” |
| 主题介绍 | 讨论活动内容，但没有金额、集合点或适用条件 |

用户问：“这次活动要准备多少钱、到哪里集合？”

可用答案至少要覆盖**金额**与**集合点**，并保留会改变行动或适用范围的条件。例如：

> 若这份当前活动说明确实对应你说的这次活动，并且你已经报名，预算为八十元，不含交通费，需在周三 18 点前确认；集合点是图书馆。

金额、报名资格、费用范围、截止时间和集合点应分别贴近对应原件引用。若材料不能把“这次”唯一绑定到某个活动或版本，就应明确尚不能确认，而不是按相似度、上传时间或新旧印象替用户做决定。系统的设计说明也把遗漏分成“没找到必要条件、命中后没读上下文、读到后没写进结论”，并要求普通约定保留会改变结果的适用对象、时间和例外。参考 [语义遗漏与可用答案 ↗](../../../docs/reader-first/answer-investigation.md#L5 "说明必要条件可能在召回、补读或写入答案时遗漏，并要求保留改变结果的适用对象、时间和例外。")

这个例子给出全文的排错框架：

1. 金额或地点没有进入候选：**召回遗漏**。
2. 命中“八十元”，但同章的报名、交通费或截止条件没进入阅读材料：**补读遗漏**。
3. 地点在另一章，初始没命中，助手也没继续找：**调查遗漏**。
4. 金额、地点和条件都已读到，最终仍漏写或用错旧记录：**回答遗漏**。

格式正确、引用合法或复核完成，都不能单独排除这些语义缺口。

<a id="candidates"></a>
## 问题怎样变成候选

材料保存后不会总以整文件参与搜索。Markdown 会按块形成检索段并保留章节路径；表格、列表和代码块尽量与前面的引导句保持在一起。这样，“参加预算八十元”和“图书馆集合”可以分别成为可排序的线索，同时仍知道它们属于哪个章节。参考 [Markdown 检索段保留结构 ↗](../../../apps/server/src/retrieval/units.ts#L33 "支持 Markdown 按块形成检索段、保留章节路径，并让表格列表代码与引导句保持完整。")

**全文路线**先把查询拆成词，再用 FTS5/BM25 找原文中直接出现的内容。中文查询使用 `Intl.Segmenter`，过滤常见停用词，并为 2～8 个汉字的短查询保留完整词形；在案例里，“八十元”“图书馆”“集合”等字面命中适合走这条路线。参考 [中文查询分词与短词保留 ↗](../../../apps/server/src/retrieval/relevance.ts#L1 "支持中文查询使用 Intl.Segmenter、停用词过滤和 2 至 8 个汉字的完整短词。") [BM25 全文候选 ↗](../../../apps/server/src/retrieval/unified.ts#L427 "支持全文路线用查询词构造 FTS5 查询并按 BM25 形成候选池。")

**向量路线**在 embedding 可用时比较问题与检索段的语义接近程度，因此“准备多少钱”也可能找到写着“参加预算”的段落。向量失败时实现会回退到全文与符号候选；不同路线的原始分数不可直接比较，所以全文、向量和符号候选按各自名次融合为一张清单。参考 [向量召回、回退与名次融合 ↗](../../../apps/server/src/retrieval/unified.ts#L408 "支持全文、向量和符号路线按名次融合，以及 embedding 失败时回退到全文和符号候选。")

候选只是“值得读的线索”。只谈活动主题的段落可能因词面或语义接近而进入清单，但它没有金额或集合点，不能据此回答。当前实现也没有一个确定性的“金额、地点都覆盖才算召回完成”算法；相关性分数不等于材料能够回答问题。

顶部阅读列表和助手看到的形态可能不同，并不表示有两套事实库。共享检索合同为阅读器、助手和 Agent 工具提供统一命中，并让命中保持固定目标。助手首轮取候选时明确关闭浏览用的来源/章节去重，再把结果交给回答上下文装配；界面列表仍可为阅读体验做去重。因此，不能因为页面只展示同一来源的少数段落，就推断助手也只能读取这些段落。参考 [共享检索合同 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持阅读器、助手和 Agent 工具共享检索，并保留固定目标和原件引用。") [助手候选池与上下文装配 ↗](../../../apps/server/src/assistant/runtime.ts#L940 "支持助手首轮取 48 条、关闭浏览去重并交给 assembleAnswerContext。") [候选、上下文与展示列表分离 ↗](../../../docs/reader-first/retrieval-redesign.md#L19 "说明助手和调查搜索关闭展示去重，界面仍可去重，且有限候选与上下文不是找全保证。")

这就是本页所说的 RAG 第一步：Retrieval 负责召回候选。它提高“可能找到”的机会，但还没有完成对材料的理解。

<a id="context"></a>
## 命中预算后怎样补回条件

假设全文或向量先命中“参加预算八十元”。回答阶段不会只把这一小段交给模型。

对原件命中，当前实现只在**同一固定 revision** 内恢复包住命中的最小完整 Markdown 章节或代码操作。没有可靠结构时保留原命中，不默认附上整份文件；扩展范围中的片段必须全部可见，否则也不扩展。参考 [原件命中恢复同版完整上下文 ↗](../../../apps/server/src/retrieval/context.ts#L13 "支持命中只在同一固定版本中扩为最小完整章节或操作，并要求扩展范围可见。")

系统还会沿结构向上读取父章节在第一个子节之前的真实引言，并把它作为独立固定范围加入。例如，“仅限已报名者”若写在费用子节的上级引言中，可以随费用章进入阅读材料。这个规则不会自动拼接兄弟章节或任意后文，所以另一章的“图书馆集合”仍需要自己的候选，或由助手围绕缺口继续搜索。参考 [父章节引言独立补入 ↗](../../../apps/server/src/retrieval/context.ts#L43 "支持补入父章节首个子节前的真实说明，同时不自动拼接兄弟章节。")

回答上下文装配按恢复后的固定范围去重，并限制不同阅读上下文的数量；已选章节所需的原件引用会一起保留。知识文章命中也只尝试恢复同一固定文章版本的相关完整章节，并合并该节实际使用的原件引用。换句话说，搜索排序的是细段，回答读取的是获准的完整上下文。参考 [回答上下文按完整范围装配 ↗](../../../apps/server/src/assistant/context.ts#L74 "支持知识整节恢复、原件完整范围去重、不同阅读上下文限制及引用合并。")

连续追问也会复用上轮已选证据，但不是保存一段脱离来源的松散文本。若上轮引用的费用章横跨多个 Fragment，运行时会校验固定版本、摘要、行范围与可见性，再按原范围重读整段；版本或可见性不满足时不会把旧范围悄悄改指当前版本。参考 [连续追问重读上轮固定范围 ↗](../../../apps/server/src/assistant/runtime.ts#L1161 "支持跨 Fragment 的上轮证据按固定版本、摘要、行范围和可见性重新读取。")

这些机制能补回**结构中明确相邻或继承的条件**，不能保证找全：地点在兄弟章、条件在其他文件，或者模型没有识别缺口时，仍需要下一步调查。当前的有限候选和有限阅读入口也不是答案要点覆盖保证。

<a id="investigation"></a>
## 地点在另一章、旧记录也命中时怎样继续查

初始命中会连同问题、已有解释、前文和事项写入助手上下文；运行提示明确把初始命中称为 leads，而不是完整答案或强制阅读顺序，并要求采用材料前检查用途、状态、范围和有效期。参考 [初始命中只是线索 ↗](../../../apps/server/src/assistant/acp-model.ts#L209 "支持助手上下文包含初始命中，并明确要求按问题选择阅读、检查材料说明而不把命中视为完整答案。")

下面是**建议性的助手策略**，用于解释现有工具怎样配合；它不是检索器内置的确定性算法：

1. 从问题列出待回答项：金额、集合点，以及为什么这些信息适用于“这次”。
2. 检查当前阅读材料逐项覆盖了什么。若费用章没有地点，就围绕材料中的业务词继续搜“集合、地点、图书馆、本次活动”。
3. 命中后读取完整节点；需要时沿父节点找适用范围，或沿子节点看具体规则。
4. 若跨文件关系、冲突或关键前提仍未解决，把“已知事实”和“具体缺口”交给深入调查，而不是提交半份答案。

先读阶段的当前指引正是按对象、时间、关键前提和用户所需结果判断是否可以直接回答；它要求区分“同一主题”和“能支持这句话”，条件未知时使用简短的条件式答案。参考 [先读阶段检查关键前提 ↗](../../../apps/server/src/assistant/reading-stage.ts#L59 "支持直接回答、条件式回答，以及围绕跨文件或冲突缺口交接调查的判断规则。") 调查工具则让助手搜索固定快照中的原件，并按搜索结果的 contextId、行号或精确标题读取完整章节；节点的 parentId/children 可用于继续补读。参考 [按节点补读与继续搜索 ↗](../../../apps/server/src/knowledge/agent-research.ts#L451 "支持 search_materials 关闭展示去重，并用 read_section 按 contextId、行号或标题读取完整节点。")

旧活动记录出现同样的“八十元”时，应按以下顺序核对：

- 先读原件标题和正文中的活动名称、日期、版本与适用对象。
- 再看版本绑定的材料说明中的 role、status、scope、validFrom/validUntil；这些是阅读辅助，不是权威事实。
- 需要比较版本时，查看同一 source 的历史列表，并在必要时读取指定旧 revision；旧正文必须保持自己的版本身份。
- 只有查询明确传入 `effectiveAt` 时，检索才按 validFrom/validUntil 过滤。默认的计划、研究、示例、historical 或 superseded 标注只是导航排序先验，不能代替真伪判断。参考 [有效期过滤与材料排序先验 ↗](../../../apps/server/src/retrieval/unified.ts#L231 "支持 effectiveAt 仅在显式提供时过滤，并说明材料用途和状态是导航偏好而非真伪裁决。") [历史版本保持独立身份 ↗](../../../apps/server/src/knowledge/agent-research.ts#L860 "支持列出同一来源版本，并在指定 revision 时读取对应旧正文和行数。")

如果这些信息仍不能确认哪条记录代表“这次”，**未知项就是活动身份或日期**。此时应并列说明找到的候选与差异，并询问一个最小澄清问题，或像开篇示例那样给出条件式答案；不能因为某条记录捕获较早、排名较低或标成 historical 就直接断言它错误。

<a id="diagnosis"></a>
## 组织答案，并按遗漏所在层修改

最后一步是把已确认的金额、报名资格、费用范围、截止时间和集合点直接写入答案，并让引用贴近所支持的句子。提交时，宿主会校验引用是否来自本次授权材料或其同 source 的历史版本、行范围是否可读，并把短引用映射回固定证据；正文中的引用标记也必须有原文定位。这个门禁保证“引用来自哪里”，不保证答案已经覆盖所有问题。参考 [提交时校验固定原件引用 ↗](../../../apps/server/src/assistant/research.ts#L105 "支持校验授权材料、同来源历史版本、可见性和行范围，并要求正文引用有原文定位。")

跨来源机制、冲突或会改变结论的重要推断可以交给独立答案复核；简单的原文直接查值不必为了形式再启动一次复核。复核使用同一固定材料快照。一旦要求复核，运行时会阻止在复核仍进行、意见未读取，或有实质问题却原样提交时结束。参考 [独立复核适用范围 ↗](../../../apps/server/src/assistant/answer-review.ts#L107 "说明独立复核用于复杂解释或重要前提，简单直接查值不必触发。") [复核后的提交门禁 ↗](../../../apps/server/src/assistant/answer-review.ts#L204 "支持复核运行中、意见未读取或有实质问题但答案未修改时阻止提交。")

发现坏答案时，先保留同一次问题的**候选、展开后的阅读上下文和最终答案**，再定位修改入口：

| 观察 | 所在层 | 首要实现入口 |
| --- | --- | --- |
| 金额或地点没进候选 | 召回 | `retrieval/units.ts`（检索单位）、`retrieval/relevance.ts`（查询词）、`retrieval/unified.ts`（全文、向量与融合） |
| 命中预算，但同章报名、交通费或截止条件没进入模型材料 | 补读 | `retrieval/context.ts`（完整章与父引言）、`assistant/context.ts`（回答上下文装配） |
| 地点在另一章，初始没中且助手没继续搜 | 调查 | `assistant/reading-stage.ts`、`assistant/acp-model.ts`、`knowledge/agent-research.ts` |
| 金额、地点和条件都在输入里，答案仍漏项或误用旧记录 | 回答与复核 | `assistant/research.ts`（引用提交）、`assistant/answer-review.ts`（独立复核） |

工具日志只能证明某次读取发生过，不能证明模型理解并使用了条件。修改后仍应回到同一个真实问题，逐层确认：必要材料是否进入候选、展开上下文是否保留改变结论的条件、最终答案是否逐项回应用户。参考 [按三层材料验收回答 ↗](../../../docs/reader-first/answer-investigation.md#L35 "支持对照候选、读取记录和最终答案区分没找到、没补读和最后遗漏，并说明工具记录不证明理解。")
