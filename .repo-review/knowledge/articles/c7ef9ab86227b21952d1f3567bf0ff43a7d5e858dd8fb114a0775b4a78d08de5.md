# 一次提问如何找到答案：搜索、上下文与 RAG

用一条“群消息进入系统后，先找整体讲解、再定位实现”的路线，解释顶部搜索、知识搜索和助手如何共享召回基础，又如何分别展示、补读和回答；并给出中文召回、结构上下文、固定引用、答案复核及故障定位的实际边界。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="scenario"></a>
## 从一条群消息开始：先分清采集与回答

假设你想弄清“群里的消息什么时候会交给助理处理”。这里有两件不同的事：**采集**把消息保存成可检索原件，**回答**则针对当前提问寻找材料、补读并组织结论。

当前实现中，只有已绑定 owner 发出的消息，并且群聊里明确提及机器人时，才会直接路由给助手；其余已允许监控的群消息会作为 `chat` 原件保存，带会话、事件时间和发言人信息。构造采集 part 时，父消息 ID 还会写入 `replyTo`，并用 `quoted` 标记它包含引用内容。不要把“被采集”理解成“立刻触发助手”。参考 [群消息直达助手条件 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L524 "支持只有绑定 owner 且群聊明确提及机器人时才进入助手路由的说明。") [群消息采集流程 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L602 "支持未直达助手的允许监控群消息被保存为 chat 原件，并记录会话和事件出处。") [回复与引用来源信息 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L741 "支持父消息 ID 被写入采集 part 的 replyTo，并以 quoted 标记引用内容。")

直接路由时，Lark 运行时按应用、绑定版本和聊天建立隔离会话，核对群聊/私聊可见性后调用 `AssistantRuntime.turn`。因此要改“哪些消息触发回答”，先看收件箱处理；要改“进入哪个会话以及如何调用助手”，再看运行时连接。参考 [飞书会话与助手调用 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L147 "支持按应用和绑定版本隔离会话、核对可见性并调用 AssistantRuntime.turn。")

<a id="responsibilities"></a>
## 搜索负责找候选，回答负责完成问题

搜索层的统一结果叫 `RetrievalHit`：它可以代表原件、知识、记忆或事项，并保留标题、正文摘录、结构路径、固定目标和原件 references。代码调用位置只标为候选，不等同于已经解析出的完整调用图。参考 [统一检索结果合同 ↗](../../../apps/server/src/retrieval/port.ts#L45 "支持 RetrievalHit 的类型、结构上下文、固定目标、原件引用和候选调用位置字段。")

三个入口共用这份底层合同，但参数和消费方式不同：

| 入口 | 召回方式 | 后续行为 |
| --- | --- | --- |
| 顶部搜索 | `/api/search` 使用统一检索，接收用途、代码意图、材料角色和有效时间，默认最多 30 条 | 直接把实际命中交给读者比较 |
| 知识搜索 | 同一检索，但只取 `knowledge`，默认偏概念，并可限定主题路径 | 每篇文章只保留最相关章节一次 |
| 助手 | 同一检索，默认取 16 个候选并先按会话可见性过滤 | 原件变成可引用证据；知识、记忆和事项作为回答背景，随后继续调查 |

参考 [顶部搜索入口 ↗](../../../apps/server/src/app.ts#L312 "支持顶部搜索向统一检索传递用途、代码意图、材料角色和有效时间，并设置结果上限。") [知识搜索入口 ↗](../../../apps/server/src/knowledge/api.ts#L118 "支持知识搜索限定 knowledge、topicPath 和 concept 默认用途，并按文章去重。") [助手召回消费方式 ↗](../../../apps/server/src/assistant/runtime.ts#L918 "支持助手统一召回、会话可见性过滤，以及将原件转为证据、其他类型作为背景。")

这里的 **RAG（检索增强生成）**，就是先用检索召回带固定出处的原件与整理背景，再由 Agent 围绕问题补读材料并组织答案。搜索解决“哪些候选可能有用”，生成回答解决“这些材料是否真的回答了问题、还缺哪些条件”；两层协作，但不能互相替代。参考 [助手召回消费方式 ↗](../../../apps/server/src/assistant/runtime.ts#L918 "支持助手统一召回、会话可见性过滤，以及将原件转为证据、其他类型作为背景。") [ACP 调查环境 ↗](../../../apps/server/src/assistant/acp-model.ts#L191 "支持 ACP 把问题、历史、事项、初始原件和讲解接入可补读调查环境，并明确初始命中只是线索。")

所以“助手答对了”不必然说明首轮排序理想：助手可能靠后续补查救回答案；反过来，命中正确片段也不保证最终回答保留了关键条件。

<a id="signals"></a>
## 全文、中文短词、符号、向量、记忆与知识各做什么

这些不是互斥的搜索模式，而是共同产生候选的线索：

- **全文（BM25）**适合正文、标题和代码中已经出现的词。检索单位的标题、结构上下文和正文写入 FTS；查询词以 OR 方式召回，再参与融合。参考 [全文召回实现 ↗](../../../apps/server/src/retrieval/unified.ts#L414 "支持 FTS/BM25 使用查询词 OR 召回并结合正文、标题和概念上下文筛选。")
- **中文短词**先用中文分词并去掉常见虚词；对 2–8 个汉字的纯短查询还保留完整字面量，避免“重试”之类词被拆散后消失。它改善可找性，不保证语义唯一。参考 [中文短词处理 ↗](../../../apps/server/src/retrieval/relevance.ts#L1 "支持中文分词、停用词过滤以及保留 2 到 8 汉字纯短查询的行为。")
- **符号**识别显式方法名、驼峰、下划线、限定名或引号中的名字，走 AST 定义候选；明确查询调用方时返回最小包含调用位置的代码单位。调用仍是按名称得到的候选，别名、接收者类型和动态调用可能缺失。参考 [符号与调用候选 ↗](../../../apps/server/src/retrieval/unified.ts#L303 "支持显式代码名识别、AST 定义候选和按名称生成调用候选及其限制。")
- **向量**用自然语言与正文的语义相似度补候选。当前查询与已索引窗口做归一化点积，再用动态门槛过滤并与全文、符号融合；模型缺失或出错时退回词法/符号结果。参考 [向量召回与回退 ↗](../../../apps/server/src/retrieval/unified.ts#L476 "支持语义向量打分、动态阈值、与词法及符号融合，以及异常时退回词法结果。")
- **知识**适合先理解整体：文章按章节参与搜索，并递归保留其原件 references；**记忆**只投影当前 active head，也保留原始证据。两者是整理后的背景，不是脱离原件的新事实。参考 [知识章节与原件引用 ↗](../../../apps/server/src/retrieval/units.ts#L589 "支持已接受知识按章节投影、保留固定文章版本并递归解析原件 references。") [当前记忆投影 ↗](../../../apps/server/src/retrieval/units.ts#L804 "支持仅检索 active memory 当前 head，并保留其原始证据定位。")

`purpose` 只是排序偏好：概念偏知识、实现偏代码、背景偏知识/记忆、跟进偏事项/记忆/会话，其他类型通常仍可出现。参考 [按用途调整偏好 ↗](../../../apps/server/src/retrieval/unified.ts#L606 "支持 concept、implementation、background 和 follow-up 对不同材料类型的排序偏好。")

<a id="context"></a>
## 命中片段后：补成可读上下文并固定出处

保存单位、检索单位和讲解单位刻意分开。Markdown 按标题路径下的段落、列表或表格形成检索块；代码通过 AST 保留完整函数或方法，局部变量不会把控制流切碎，import 与模块初始化也可单独搜索。参考 [Markdown 检索块 ↗](../../../apps/server/src/retrieval/units.ts#L32 "支持按标题路径组织 Markdown 块并合并引导句与紧随列表、表格或代码块。") [完整代码操作切分 ↗](../../../apps/server/src/retrieval/units.ts#L90 "支持以 AST 形成完整函数或方法范围、保留控制流，并让模块初始化可搜索。")

聊天检索单位会把会话、发言人、事件时间加入上下文；若命中 part 带 `replyTo` 或 `quoted` provenance，还会加入回复消息和“含引用内容”的提示，使读者能沿对话关系补读。参考 [聊天检索上下文 ↗](../../../apps/server/src/retrieval/units.ts#L286 "支持检索投影从材料和 part provenance 中组装会话、发言人、事件时间、回复消息与引用内容提示。")

因此命中 `processMessage` 中的一行后，不必从文件开头硬读，也不能只看那一行。`read_section(atLine)` 会找到包含命中行的最内层完整章节或代码符号；需要跨文件入口时再用代码导航补定义、import 和候选调用方。参考 [按命中行读取完整结构 ↗](../../../apps/server/src/knowledge/agent-research.ts#L444 "支持 read_section.atLine 打开最内层完整章节或代码符号。")

固定引用由材料 key、revision、digest、精确起止行和覆盖的 fragment 组成。助手提交时还会检查引用是否属于本次授权材料、历史版本是否来自同一 source、范围是否可见，以及正文标签是否能映射回该范围。这样讲解可以更新，读者仍能回到回答当时使用的原文。参考 [固定来源锚点 ↗](../../../apps/server/src/retrieval/units.ts#L244 "支持固定引用记录材料 key、revision、digest、行范围和覆盖片段。") [答案引用校验 ↗](../../../apps/server/src/assistant/research.ts#L102 "支持校验授权范围、同源历史版本、可见性、精确范围和正文引用映射。")

<a id="assistant"></a>
## 助手怎样补查关键条件并复核答案

助手 turn 会先持久化，再按会话串行执行；同一会话的新消息会中断旧 turn。真正回答前，它读取同会话历史、当前事项和统一检索的初始线索，再把问题、原件证据与派生讲解交给 ACP 调查环境。参考 [助手 turn 生命周期 ↗](../../../apps/server/src/assistant/runtime.ts#L302 "支持 turn 先持久化、同会话串行以及新消息中断旧 turn。") [回答前的上下文装配 ↗](../../../apps/server/src/assistant/runtime.ts#L560 "支持读取同会话历史、统一召回、旧工作上下文、事项与当前时钟。")

这里的 **ACP** 是承载 Agent 工具循环的运行与连接层：它把当前问题、会话背景、初始命中和讲解交给 Agent，并接入当前固定快照中的只读搜索、章节读取、知识、记忆、历史、图片与代码导航工具。它不是另一套检索器，也不是把首轮命中直接总结成答案。参考 [ACP 调查环境 ↗](../../../apps/server/src/assistant/acp-model.ts#L191 "支持 ACP 把问题、历史、事项、初始原件和讲解接入可补读调查环境，并明确初始命中只是线索。") [按缺口补查与独立复核 ↗](../../../docs/reader-first/answer-investigation.md#L13 "支持 Agent 通过工具循环围绕缺口补查，并让复杂问题在同一固定快照中独立复核。")

初始命中只是线索。Agent 应围绕会改变结论的缺口继续补读。例如判断群消息是否自动交给助手，必须同时核对发送者身份、群聊 mention 条件和采集分支，而不能因为看见 `AssistantRuntime.turn` 就宣称所有消息都会触发。参考 [ACP 调查环境 ↗](../../../apps/server/src/assistant/acp-model.ts#L191 "支持 ACP 把问题、历史、事项、初始原件和讲解接入可补读调查环境，并明确初始命中只是线索。") [按缺口补查与独立复核 ↗](../../../docs/reader-first/answer-investigation.md#L13 "支持 Agent 通过工具循环围绕缺口补查，并让复杂问题在同一固定快照中独立复核。")

复杂机制、冲突或当前行为的重要前提可以启动独立答案复核。复核者拿原问题、候选答案和同一固定快照自行搜索，不接收作者笔记；一旦请求复核，宿主会阻止未取回结果或带重要问题的原样草稿提交。短小、直接的查询不强制额外模型调用。参考 [按缺口补查与独立复核 ↗](../../../docs/reader-first/answer-investigation.md#L13 "支持 Agent 通过工具循环围绕缺口补查，并让复杂问题在同一固定快照中独立复核。") [复核提交门槛 ↗](../../../apps/server/src/assistant/answer-review.ts#L107 "支持复核任务复用、结果取回以及阻止未完成或未修订草稿提交。")

<a id="limits"></a>
## 当前模型与时间能力的边界

当前仓库配置启用 `memory-zh`，即锁定版本的 `Xenova/bge-small-zh-v1.5`：本地 q8/CPU 运行，禁止运行时远程下载；query 添加中文检索指令，passage 保持原文，并统一做 CLS pooling 与归一化。默认配置没有启用 reranker。参考 [默认检索模型配置 ↗](../../../config/retrieval.json#L1 "支持当前默认仅启用 memory-zh embedding，未配置 reranker。") [中文嵌入模型加载 ↗](../../../apps/server/src/retrieval/embedding.ts#L14 "支持锁定 BGE-small-zh-v1.5、本地 q8 CPU、禁止远程模型及查询与正文的不同预处理。")

代码中已有 BGE cross-encoder 重排适配，可把 query-passage 对截断到 512 token 后评分；长单位最多选择两个约 800 字符的局部窗口参与重排，完整固定单位仍可继续阅读。它是可选排序信号，不是“答案正确概率”。参考 [中文重排适配 ↗](../../../apps/server/src/retrieval/reranker.ts#L31 "支持可选 BGE reranker 的锁定模型、512 token 截断和串行 CPU 评分。") [长单位重排窗口 ↗](../../../apps/server/src/retrieval/rerank-passages.ts#L3 "支持长单位最多选择两个局部窗口评分，同时保留完整固定单位供阅读。")

时间也要分开：`timeRange` 过滤捕获 revision 的时间，不是事件时间或历史 as-of；`effectiveAt` 只使用材料说明里明确的有效期；跟进用途才会对事项、记忆和会话给轻微近期偏好。当前不能据此重建任意时点“系统当时相信什么”的完整状态。参考 [时间查询合同 ↗](../../../apps/server/src/retrieval/port.ts#L96 "支持 timeRange 明确表示捕获 revision 时间，而非事件时间或历史 as-of。") [有效期与近期偏好 ↗](../../../apps/server/src/retrieval/unified.ts#L225 "支持 effectiveAt 按明确有效期过滤，以及 follow-up 对带 eventAt 的内容施加轻微近期偏好。")

<a id="diagnosis"></a>
## 从现象定位问题与修改入口

遇到“搜不到或答不好”，按内容流向排查：

1. 正确原件或讲解没进候选池：检查切分、中文词、符号/向量、可见性、材料角色和有效时间。
2. 候选存在但被噪声压后：检查融合、用途偏好、材料状态与去重；“提到了问题”不等于“能回答问题”。
3. 命中正确但漏掉方法尾部、父章节或下游条件：用完整章节和代码导航补读。
4. 完整材料已读，答案仍漏条件、偏题或把计划当现状：这是回答组织问题；复杂题再看复核是否触发并吸收。
5. 助手补查后答对而首轮命中仍差：同时记录回答成功与召回缺陷，不能相互替代。参考 [召回与回答诊断 ↗](../../../docs/reader-first/answer-investigation.md#L5 "支持按没找到、没补读和最终遗漏区分问题，并强调命中分数不等于可回答。")

修改入口也按这条链分工：消息是否直达助手看 `integrations/lark/realtime.ts`，会话隔离看 `integrations/lark/runtime.ts`；切分与上下文看 `retrieval/units.ts`，候选融合和排序看 `retrieval/unified.ts`，查询合同看 `retrieval/port.ts`；助手初始召回看 `assistant/runtime.ts`，调查与固定引用看 `assistant/acp-model.ts`、`assistant/research.ts`，答案复核看 `assistant/answer-review.ts`。当前仍存在主题相关但不可回答的材料靠前、跨文件业务链不完整、章节级混合用途和完整时态推理缺失等限制。参考 [当前检索与阅读缺口 ↗](../../../docs/reader-first/progress.md#L63 "支持当前关于噪声排序、跨文件业务链、章节用途、时态推理和复核边界的说明。")
