# 一次提问如何找到答案：搜索、上下文与 RAG

用“活动要准备多少钱、到哪里集合”的教学示例，解释 omem 如何把整句问题变成全文、向量与符号候选，材料用途、状态、有效时间与概念别称怎样影响候选，命中后如何在固定版本中补回章节与父级条件，以及怎样按未解项处理另一章、旧记录和对象歧义。最后给出从召回、原文、补读、调查到回答与复核的故障定位入口。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="what-counts-as-an-answer"></a>
## 先定义“答全”：结果、条件与对象都要有依据

假设已经保存了几份活动材料。当前活动说明的一章写“参加预算八十元”，同章或上级简介还写着“仅限已报名者”“不含交通费”“周三 18 点前确认”；另一章写“在图书馆集合”。库里另有一份旧活动记录，也提到八十元。用户问：

> 这次活动要准备多少钱、到哪里集合？

这是贯穿本文的**教学示例**，不代表一次真实检索的固定排名。对这个问题，“答全”至少包含三件事：

1. 分别回答金额和集合点，并让每项都能回到固定原文；
2. 把会改变行动的资格、费用范围、截止时间放在对应结论附近；
3. 确认“这次”指的是哪场活动、哪个版本。

因此，“活动很适合周末参加”即使语义相关，也没有回答金额或地点；旧记录里的“八十元”即使字面完全命中，也不能证明适用于这次。关键前提可能在召回、补读或最终表达时丢失，而引用格式正确本身发现不了这些语义缺口。参考 [可用答案与关键前提 ↗](../../../docs/reader-first/answer-investigation.md#L5 "说明关键前提可能在召回、补读或表达阶段丢失，引用正确不等于语义完整。")

<a id="retrieve-candidates"></a>
## 整句问题先产生候选，而不是直接产生答案

普通助手先把用户整句问题交给检索，取得最多 48 个候选，再装配回答上下文；这一步不会判断“金额、地点和条件是否已经找齐”。它关闭浏览用途的多样化去重，避免同一原件的第三个必要事实只因展示限制而被提前丢掉。参考 [普通助手的首轮候选 ↗](../../../apps/server/src/assistant/runtime.ts#L974 "说明整句问题的候选规模、关闭浏览去重、传入字段及回答上下文装配入口。") [候选不等于覆盖 ↗](../../../docs/reader-first/retrieval-redesign.md#L19 "说明候选有限、按子问题搜索也不判断答案要点是否已经覆盖。")

这里有一个会改变起点的前提：个人会话若已经保存了讨论项目，首轮检索会在排序和截断前只保留该项目来源中的可见材料；没有已确认项目时，仍从整个可见库开始。这个范围也作用于上轮引用。它只是阅读起点，不扩大或缩小权限，后续原生调查仍可查看其他已授权材料。参考 [会话项目限定首轮阅读 ↗](../../../apps/server/src/assistant/runtime.ts#L1061 "说明已保存个人会话项目按来源成员过滤首轮候选，而原生调查仍可跨到其他授权范围。")

Markdown 原件不是整份文件作为一个单元排序。系统按结构 token 生成带真实行号和标题路径的检索段；一段话若以冒号引出表格、列表或代码块，引导语会与紧随的块合在一个检索段中，避免只返回无法独立理解的半句话。参考 [Markdown 检索段 ↗](../../../apps/server/src/retrieval/units.ts#L33 "说明结构化段落、标题路径及引导语与列表、表格、代码块的合并规则。")

候选主要从三条路线汇合：

- **全文路线**用 FTS/BM25 找字面匹配，擅长“八十元”“图书馆”和精确名称；
- **向量路线**在 embedding 可用时找语义相近的窗口，例如问题写“要带多少活动费”，原文写“参加预算”；
- **符号路线**为代码名称与导航补充入口。

这些路线的分值尺度不同，系统按各路线中的名次做 RRF 融合。没有向量模型、查询是精确标识符，或向量执行失败时，仍会退回全文与符号路线。参考 [全文检索与 RRF ↗](../../../apps/server/src/retrieval/unified.ts#L408 "说明 BM25 全文候选及不同路线按名次融合。") [向量路线与降级 ↗](../../../apps/server/src/retrieval/unified.ts#L480 "说明语义向量的使用、融合，以及向量不可用或失败时退回全文与符号路线。")

材料说明会在这个阶段提供三种导航信号，但**不是另一份事实来源**：

1. 概念及别称只加入与其原文行范围相交的检索单位，因此“活动费”可以帮助写着“参加预算”的那一段进入全文和向量候选；不会把整篇摘要复制到每一段，返回正文仍是原文。参考 [材料说明怎样影响搜索 ↗](../../../docs/reader-first/material-understanding.md#L17 "解释用途与状态的排序先验、显式角色和有效时间过滤、按行概念别称及其非事实裁决边界。") [概念别称的行范围投影 ↗](../../../apps/server/src/retrieval/units.ts#L368 "说明概念及别称只进入与其原文范围相交的检索单位。")
2. 已分类材料的用途与状态会形成默认排序先验：计划、调研、示例、拟议、历史或被替代内容可能后排，但仍可被找到；未分类材料也不会因此从默认搜索消失。显式选择材料角色时才按角色过滤。参考 [角色、状态与有效时间 ↗](../../../apps/server/src/retrieval/unified.ts#L231 "说明显式角色和有效时间何时过滤，以及默认用途和状态只形成适用性排序先验。")
3. 只有调用方显式传入 `effectiveAt`，才按材料明确记录的有效起止时间过滤；捕获时间不会代替有效时间。普通助手首轮只传整句文本、用途、可见范围与候选设置，并不自动把提问时间作为 `effectiveAt`。参考 [普通助手的首轮候选 ↗](../../../apps/server/src/assistant/runtime.ts#L974 "说明整句问题的候选规模、关闭浏览去重、传入字段及回答上下文装配入口。") [浏览去重与显式筛选 ↗](../../../apps/server/src/retrieval/port.ts#L109 "说明 diversify=false 只关闭浏览去重，排序、范围、可见性、角色和有效时间仍是独立约束。") [角色、状态与有效时间 ↗](../../../apps/server/src/retrieval/unified.ts#L231 "说明显式角色和有效时间何时过滤，以及默认用途和状态只形成适用性排序先验。")

所以旧活动记录即使被标成历史而后排，也不能据此直接判定“不适用”；相反，一条排名靠前的当前说明也不保证已经覆盖地点。**相关候选只是阅读入口，不是答案覆盖证明。** 当前候选数有限，没有一个确定性选择器等待所有答案槽位都填满才停止。参考 [候选不等于覆盖 ↗](../../../docs/reader-first/retrieval-redesign.md#L19 "说明候选有限、按子问题搜索也不判断答案要点是否已经覆盖。")

这也解释了为什么网页搜索列表与助手读到的内容不一定一一对应。浏览列表默认会限制同一来源或章节的重复展示；助手和调查工具使用不做这种浏览去重的候选池。两者仍受排序、显式范围与可见性过滤约束，不能只按显示条数比较。参考 [浏览去重与显式筛选 ↗](../../../apps/server/src/retrieval/port.ts#L109 "说明 diversify=false 只关闭浏览去重，排序、范围、可见性、角色和有效时间仍是独立约束。")

<a id="restore-context"></a>
## 细段用于排序，固定完整章节用于理解

候选排序用细段，但回答不能只读命中的一句。原件候选被选中后，系统会在**同一个不可变版本**内，把命中扩为包含它的最小完整 Markdown 章节或代码结构；没有可靠结构时保留原命中，不把整份文件附上。扩展范围还必须全部通过可见性检查。参考 [最小完整章节 ↗](../../../apps/server/src/retrieval/context.ts#L13 "说明命中在同一固定版本内扩展到最小结构上下文、H1 特例及可见性回退。")

Markdown 层级决定扩展边界。普通章节包含自己的子章节，所以费用章里的“八十元”命中后，可以一起读到该章下的报销或费用条件。文档唯一的 H1 则被视为标题：命中开篇导言时只恢复到第一个子章节之前，不会因一个简介命中展开整篇。参考 [最小完整章节 ↗](../../../apps/server/src/retrieval/context.ts#L13 "说明命中在同一固定版本内扩展到最小结构上下文、H1 特例及可见性回退。")

系统还会沿父链补入各级章节在第一个子节之前的引言，并把它们保留成独立固定引用。因此，上级写的“仅限已报名者”可以随费用命中进入语境；但兄弟章节不会自动附加，另一章的“图书馆集合”需要自己的候选或后续补查。参考 [父级引言与兄弟边界 ↗](../../../apps/server/src/retrieval/context.ts#L64 "说明父级开头作为独立固定引用加入，而兄弟章节不会自动附加。")

回答上下文限制的是不同阅读上下文的数量。一个上下文选入后，其必要固定引用一起保留；同一版本中被更大范围完整包含的小范围会去重，不同版本不会合并，也不会拼成原文不存在的新范围。参考 [回答上下文装配 ↗](../../../apps/server/src/assistant/context.ts#L74 "说明不同阅读上下文的数量限制、固定引用恢复、包含范围去重与版本隔离。") 多版本测试验证了旧版“八十元”和新版“一百二十元”可以同时存在，旧背景仍指向旧版，而且费用命中不会自动带入兄弟章的集合点。参考 [多版本上下文测试 ↗](../../../apps/server/tests/retrieval-hierarchy.test.ts#L149 "验证旧版和新版事实可并存、旧背景保持旧版且兄弟地点不被自动带入。")

可以把这一层记成一句话：**细段用于排序，固定完整章节用于理解。** 它能补回结构上明确相邻的条件，却不能保证兄弟章、其他文件或原文没有明确写出的替代关系自动出现。

<a id="investigate-gaps"></a>
## 只补未解项，并先确认“这次”指哪个对象

第一次阅读后，可以把教学问题拆成三个待答槽位：

- 金额及会改变金额含义的费用条件；
- 集合点；
- “这次活动”对应的对象和版本。

如果费用章已经给出八十元、报名资格和交通费条件，就不必换几个近义词反复搜索金额；应把调查资源用于仍为空的集合点或对象身份。多部分问题可以通过 `search_contexts` 分别检索：每个问题保留自己的候选排名和完整上下文，跨问题共享的固定上下文只返回一次。调查者还可以为具体缺口显式指定材料角色或有效时间。工具不会宣布某个问题已经覆盖；空结果也只是搜索缺口，不是事实不存在的证明。参考 [按子问题保留完整上下文 ↗](../../../apps/server/src/knowledge/agent-research.ts#L685 "说明 search_contexts 的独立候选池、显式角色和时间筛选、共享去重及空结果边界。")

如果已经发现多个可能对象，而本轮和会话都没有选定其中一个，应先做最小澄清，例如“你指春游活动，还是同名的读书会？”只有用户明确要求比较时，才并列调查。参考 [对象澄清与只补未解项 ↗](../../../packages/agent-runtime/roles/daily-assistant/1/skills/omem-assistant-research/SKILL.md#L14 "说明多个对象未选定时先最小澄清，并围绕具体缺口继续调查。")

项目或主题归属可以缩小查找范围，但不裁决事实。调查者可用项目成员找到正文没有重复项目名的后续记录；多个项目范围取并集，与明确材料键同时使用时取交集。已确认的个人会话项目会成为后续首轮阅读起点，换对象时应改选，无关问题、跨项目比较或歧义未解时应清空。无论哪种情况，归属只说明“去哪里找”，哪条记录替代旧约定仍要读正文判断。参考 [项目范围与会话阅读起点 ↗](../../../docs/reader-first/project-contexts.md#L23 "说明项目范围运算、会话项目、首轮过滤及项目身份不裁决事实。")

回到旧活动记录：应核对原文中的活动名称或适用对象、日期，以及是否明确写了变更或替代关系。材料角色、状态、默认排名、捕获先后和同属一个项目都只是导航信号，不能替用户决定“这次”。若证据仍不足，可以先问一句对象澄清，也可以按对象给出条件分支——“若指春游说明，则……；若指旧活动记录，则……”——并明确尚未确认的部分。原件没有说明交通费或替代关系时，应保留未知，不能用 RAG 补造。

<a id="write-the-answer"></a>
## 把结论、条件与未知组织成可行动的答案

材料足够时，答案应先按用户的两个问题逐项写结论，再把条件贴近对应结论。例如：

> 这次活动按每人八十元准备，在图书馆集合。八十元仅适用于已报名者，不含交通费；请在周三 18 点前确认。［分别附金额/条件与集合点的原文引用］

这仍是格式教学，只有固定原文确实支持每一句时才成立。若“这次”尚未消歧，就先问对象，或把结论写成清楚的条件分支；若材料没有说明某项条件，则明确未知。

提交阶段会校验项目选择与引用：非空项目必须是当前可用的正式个人项目；引用必须来自本次授权材料，历史版本须与当前材料同源，范围须可见，正文使用的引用编号也必须有原文定位。这些门禁保证选择与来源链接合法，却不会验证金额、地点和条件是否都答到了。参考 [项目选择与答案引用校验 ↗](../../../apps/server/src/assistant/research.ts#L82 "说明提交阶段对项目 ID、授权材料、同源历史版本、可见性及正文引用定位的校验。")

复杂机制、冲突或关键推断还可以交给独立读者复核。一旦请求复核，复核运行中、未完成、反馈未读取，或报告有实质问题但草稿仍原样未改时，都不能提交。参考 [复核提交门禁 ↗](../../../apps/server/src/assistant/answer-review.ts#L204 "说明复核运行、完成、反馈读取和含实质问题的原样草稿会阻止提交。") 独立读者能补查同一固定快照并指出会改变结论或行动的遗漏，但是否启动复核以及能否发现问题仍依赖模型判断；它是门禁和第二双眼睛，不是完整性证明。参考 [复核的能力边界 ↗](../../../docs/reader-first/answer-investigation.md#L21 "说明独立复核可补查重要遗漏，但是否启动和能否发现问题仍依赖模型判断。")

<a id="locate-failures"></a>
## 答案仍不完整时，按信息丢失的位置定位

不要先用“搜索不好”概括所有遗漏。沿问题到答案倒查，通常能落到下面一层：

| 现象 | 问题所在层 | 优先查看的实现入口 |
| --- | --- | --- |
| 金额或地点从未进入候选，概念别称没有帮助对应段，或取消项目范围后才出现 | 召回范围：passage 切分、概念行范围、全文/向量/符号路线、融合、材料用途与状态先验、显式角色或 `effectiveAt`、可见性和 `readingScope` | `retrieval/units.ts`、`retrieval/unified.ts`、`retrieval/port.ts`、`assistant/runtime.ts` |
| 候选或人工指定的原文本身没写必要条件 | 原文或选材 | 原材料正文、材料历史、选材入口 |
| 原文有条件，但同章、父级引言或固定引用没有交给助手 | 补读装配 | `retrieval/context.ts`、`assistant/context.ts` |
| 费用已读到，但兄弟章地点、对象切换或歧义仍未补查 | 调查策略与项目选择 | `knowledge/agent-research.ts`、`omem-assistant-research/SKILL.md`、`assistant/acp-model.ts` |
| 本轮已确认新项目，后续轮次仍沿旧范围 | 项目选择的应用与持久化 | `assistant/runtime.ts`、`conversation/router.ts` |
| 金额、地点和条件都已读到，最终答案仍漏写或混用版本 | 回答与复核 | `assistant/research.ts`、`assistant/answer-review.ts` |

判定时要同时看初始命中、后续读取、草稿、复核与最终答案：工具日志只能证明发起过读取，不能证明内容已经被理解；人工指定原文也可能选得不全。“有引用”“给过材料”或“复核完成”都不能单独证明语义完整。参考 [分层验收方法 ↗](../../../docs/reader-first/answer-investigation.md#L47 "说明需结合命中、读取、草稿、复核与答案定位遗漏，读取发生和人工选材不等于理解或完备。")

这张表的用途是把修复放回正确层：候选根本不到就检查检索投影、范围和排序；命中了却缺结构语境就改补读装配；跨章或对象身份没继续查就改调查策略；项目已切换但后续没生效就查保存链路；证据已齐却没写进结论，才主要处理回答与复核。
