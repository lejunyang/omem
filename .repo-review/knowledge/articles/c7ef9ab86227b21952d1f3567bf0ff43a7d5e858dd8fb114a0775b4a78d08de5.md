# 一次中文提问如何找到答案：召回、上下文与 RAG

以“飞书 消息 后台”为贯穿示例，解释顶部搜索、知识搜索和助手如何共享原始证据召回，词法、符号、记忆、知识与中文向量如何互补，命中后怎样补齐章节上下文，以及如何区分召回失败、可见性限制、上下文不足和模型回答失败。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="scenario"></a>
## 从一个记不清文件名的问题开始

假设用户只记得“飞书消息要经过后台处理”，于是输入 **“飞书 消息 后台”**，看到若干原始材料片段后，再追问“具体经过哪些步骤？”。系统不会直接把搜索摘要当答案，而是找回仍属当前版本的原始片段，再把可见证据交给助手；候选保留原始 fragment 标识，方便回到不可变材料核对。参考 [统一检索证据合同 ↗](../../../apps/server/src/retrieval/port.ts#L1 "说明检索结果保留不可变原始片段标识，支持从候选回到原文核对。")

```mermaid
flowchart LR
  Q[中文问题] --> R[词法与语义召回]
  R --> F[融合、排序与去重]
  F --> C[补同节标题和相邻片段]
  C --> M[模型组织回答]
  M --> X[必要时追加一轮查询]
  X --> V[校验引用并保存结果]
```

运行时先召回和补充证据，再调用模型；模型可以请求至多一轮扩展检索。回答完成后，服务器校验引用是否属于实际提供的证据，最后保存答案及有效引用。参考 [助手处理主流程 ↗](../../../apps/server/src/assistant/runtime.ts#L481 "支持初次召回、模型调用和至多一轮扩展检索的整体流程。") [回答引用白名单 ↗](../../../apps/server/src/assistant/runtime.ts#L604 "支持服务器过滤未提供给模型的引用，并只保存校验后的 selected evidence。")

<a id="entry-points"></a>
## 三个入口共享底座，但返回的不是同一种东西

生产应用创建一套检索服务，并把同一个实例交给知识路由和助手；顶部搜索也直接使用该实例。因此，三个入口共享候选来源和底层排序能力，但对结果的组织方式不同。参考 [共享检索实例 ↗](../../../apps/server/src/app.ts#L80 "证明知识路由与助手注入同一个检索实例，顶部搜索也使用该实例。")

| 入口 | 返回内容 | 适合判断 |
| --- | --- | --- |
| 顶部搜索 | 原始片段摘要、标题、分数、路线和章节 | 材料是否进入工作区级召回 |
| 知识搜索 | 当前知识文章中相关的章节 | 已整理知识是否覆盖问题 |
| 助手 | 基于当前会话可见证据生成的回答 | 上下文是否充分、模型是否理解 |

顶部接口直接返回原始命中及其 `routes`；知识搜索则先召回原始片段，再把排名投影到引用这些材料的文章章节，并叠加标题和正文的词面匹配。参考 [顶部原始片段搜索 ↗](../../../apps/server/src/app.ts#L273 "说明顶部搜索只传文本和数量上限，并返回原始命中、路线与章节；它没有传时间范围或会话可见性。") [知识章节搜索 ↗](../../../apps/server/src/knowledge/api.ts#L86 "说明知识搜索如何调用检索端口，再把原始证据排名投影到当前文章章节并融合词面匹配。")

所以，顶部搜索有结果而知识搜索没有文章，不一定是召回失败，也可能只是尚无当前文章引用该材料，或文章文字没有匹配查询。

<a id="lexical-recall"></a>
## 词面召回如何处理中文短词、路径和代码符号

查询先按空白和标点切分。ASCII 单词会被保留；中文连续文本既保留完整词，也产生相邻二元组，同时跳过过于常见的二字组合。示例中的“飞书”“消息”“后台”因此都能成为检索词。参考 [中文查询分词 ↗](../../../apps/server/src/retrieval/keyword.ts#L210 "支持中文完整词、相邻二元组和停用二元组的分词行为。")

长度至少三个字符的词走 trigram 全文索引，适合较长中文词、代码路径和子串；二字中文改走正文或标题包含查询，因区分度较低，可能产生更多泛化候选。若查询包含 `AssistantRuntime` 一类标识符，系统还会精确匹配当前代码快照中的符号名或限定名，但结果仍指向统一的原始片段。参考 [长词与短词检索 ↗](../../../apps/server/src/retrieval/keyword.ts#L53 "说明长词使用 trigram 全文索引、二字词使用正文或标题包含匹配。") [精确代码符号召回 ↗](../../../apps/server/src/retrieval/keyword.ts#L123 "支持从当前代码快照精确匹配符号，并仍返回统一的原始 fragment。")

全文、短词、代码符号、记忆和知识路线通过倒数排名融合，避免直接比较不同体系的原始分数；之后再用相关性和重复度调整顺序，代码符号命中获得额外权重。参考 [多路线排名融合 ↗](../../../apps/server/src/retrieval/keyword.ts#L97 "说明全文、短词、符号、记忆和知识路线使用倒数排名融合。") [相关性与去重排序 ↗](../../../apps/server/src/retrieval/ranking.ts#L3 "支持符号权重、MMR 式相关性排序和冗余控制的说明。")

<a id="semantic-recall"></a>
## 记忆、知识与中文向量各自补什么

**记忆和知识提供新的找法，不充当新的独立事实。** 命中已应用记忆后，检索沿证据集合回到仍为当前版本的原始片段；知识正文命中后也会检查固定依赖和引用范围，再返回引用覆盖的原文。无效知识投影不会阻断其他召回路线。参考 [记忆回到原始证据 ↗](../../../apps/server/src/retrieval/keyword.ts#L81 "说明记忆命中沿证据集合返回原始片段，不把记忆正文当作独立来源。") [知识导航到原文 ↗](../../../apps/server/src/knowledge/retrieval.ts#L34 "说明派生知识用于定位固定引用覆盖的原始片段，无效投影不会中断检索。")

语义路线负责弥补“意思接近、用词不同”。当前配置启用 `memory-zh`，加载锁定版本的 `bge-small-zh-v1.5`；应用校验本地权重并以 CPU 量化方式运行，不会自行联网下载。参考 [中文检索配置 ↗](../../../config/retrieval.json#L1 "证明当前语义检索配置启用了 memory-zh。") [本地中文向量模型 ↗](../../../apps/server/src/retrieval/embedding.ts#L14 "支持锁定 BGE 模型版本、校验权重和离线 CPU 量化加载的说明。")

长片段按 **400 字窗口、320 字步长**生成重叠向量，以免尾部内容被忽略。查询时，每个片段保留最相近的窗口，词法与向量候选再经倒数排名融合。参考 [长片段向量窗口 ↗](../../../apps/server/src/retrieval/semantic.ts#L125 "支持长片段使用 400 字窗口和 320 字步长建立重叠向量的精确参数。") [语义索引与降级 ↗](../../../apps/server/src/retrieval/semantic.ts#L21 "说明后台索引、词法与向量融合，以及异常时退回词法检索。")

索引在后台追赶新材料，不阻塞查询；模型尚未加载或推理出错时仍返回词法结果，并在健康状态中显示 indexing 或 degraded。因此，没有 `semantic` 路线不等于没有材料，应结合其他 `routes` 和检索健康状态判断。

<a id="context"></a>
## 命中一个片段后，怎样补齐可读上下文

单个命中可能只说明“后台处理存在”，却不足以解释前后步骤。助手会定位其所属章节，尝试补入章节标题、前一个片段和后一个片段；补充内容不能跨越章节边界，而且要再次通过可见性检查。参考 [章节邻居补充 ↗](../../../apps/server/src/retrieval/context.ts#L5 "说明命中后只补同一章节的标题和相邻片段，并继续执行可见性过滤。")

例如命中某节的“失败后重试”时，可以补到同节标题和前面的“发送待处理消息”，但不会混入下一节的“永久删除”；若可见性策略全部拒绝，就不补任何内容。参考 [邻居边界示例 ↗](../../../apps/server/tests/reading-context.test.ts#L48 "用测试场景证明邻居补充不会跨到下一章节，可见性拒绝时结果为空。")

运行时先保留已排序命中，再用剩余预算补邻居，总证据量最多 28 条。语义命中会把窗口摘要作为定位信息传给证据展开。参考 [助手召回与证据预算 ↗](../../../apps/server/src/assistant/runtime.ts#L665 "支持助手显式传入会话可见性、保留排序命中、补充章节邻居和 28 条预算。")

若原始片段超过 2000 字，助手会确认该窗口确实存在于当前原文，再围绕命中位置截取最多 2000 字；定位摘要本身不会成为独立证据。这样可避免向量找到了长片段尾部，模型却只读到开头。参考 [语义命中原文截取 ↗](../../../apps/server/src/assistant/runtime.ts#L786 "支持验证语义焦点仍存在于当前原文，并围绕命中位置截取最多 2000 字。")

<a id="assistant-rag"></a>
## 助手如何追问、扩展检索并约束引用

助手处理追问时，会读取当前会话最近的已完成历史，并合并上一轮实际选中的证据，因此“按这个继续说”可以沿用刚才找到的材料。首轮模型输入包括用户问题、对话历史、证据和运行时上下文；模型提出的额外搜索词只用于检索，不能当作事实。参考 [会话历史与工作上下文 ↗](../../../apps/server/src/assistant/runtime.ts#L465 "说明助手合并当前会话历史及上一轮工作证据来理解追问。")

额外查询会去重，最多 3 个、每个最多 160 字；并行召回后与原证据按 fragment 去重，最多保留 24 条，再调用模型一次。这适合从“飞书消息进入后台”继续寻找具体处理阶段，但不是无限搜索循环。参考 [一轮扩展检索 ↗](../../../apps/server/src/assistant/runtime.ts#L514 "支持额外查询的数量、长度、并行召回、去重截断和第二次模型调用限制。")

模型提交的 fragment id 必须存在于本轮实际 evidence 中，否则会被过滤；保存的 selected evidence 也只包含校验后的引用。参考 [回答引用白名单 ↗](../../../apps/server/src/assistant/runtime.ts#L604 "支持服务器过滤未提供给模型的引用，并只保存校验后的 selected evidence。")

模型未配置或真实传输不可用时，轮次保持待重试；其他模型异常会生成明确的降级回复且不附引用。参考 [模型不可用与降级 ↗](../../../apps/server/src/assistant/runtime.ts#L524 "说明模型不可用时保持待重试，以及其他异常生成无引用降级回复。")

<a id="diagnosis"></a>
## 如何区分“找不到”与“找到却答不好”

可以沿同一个问题逐层定位：

1. **顶部搜索没有正确原始片段**：问题发生在回答之前。顶部 `/api/search` 当前只传查询文本和数量上限，不传时间范围或会话可见性，因此先检查分词是否过泛、材料是否仍为当前原始版本，以及语义索引是否正在建立或已经降级。查看 `routes` 可以判断命中来自全文、短词、符号、记忆、知识还是语义路线。参考 [顶部原始片段搜索 ↗](../../../apps/server/src/app.ts#L273 "说明顶部搜索只传文本和数量上限，并返回原始命中、路线与章节；它没有传时间范围或会话可见性。")
2. **顶部搜索有结果，助手却看不到同一片段**：再检查助手的会话可见性。助手调用检索时会显式传入可见性函数；飞书宿主还要求材料所属 conversationId 与当前 chatId 一致。参考 [助手召回与证据预算 ↗](../../../apps/server/src/assistant/runtime.ts#L665 "支持助手显式传入会话可见性、保留排序命中、补充章节邻居和 28 条预算。") [飞书群聊证据可见性 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L93 "支持飞书助手宿主按当前 chatId 限制可交给模型的材料。")
3. **顶部搜索有片段，知识搜索没有文章**：底层召回可能正常，只是当前文章尚未引用该材料，或查询没有匹配相应章节。参考 [知识章节搜索 ↗](../../../apps/server/src/knowledge/api.ts#L86 "说明知识搜索如何调用检索端口，再把原始证据排名投影到当前文章章节并融合词面匹配。")
4. **助手有命中，却缺少流程前后文**：检查章节与 fragment 边界、可见性以及 28 条上下文预算。参考 [章节邻居补充 ↗](../../../apps/server/src/retrieval/context.ts#L5 "说明命中后只补同一章节的标题和相邻片段，并继续执行可见性过滤。") [助手召回与证据预算 ↗](../../../apps/server/src/assistant/runtime.ts#L665 "支持助手显式传入会话可见性、保留排序命中、补充章节邻居和 28 条预算。")
5. **首轮和扩展检索都提供了正确证据，回答仍遗漏或误解**：这是“找到却答不好”。应查看第二轮实际输入、24 条合并截断及最终有效引用，而不是继续调整第一阶段分词。参考 [一轮扩展检索 ↗](../../../apps/server/src/assistant/runtime.ts#L514 "支持额外查询的数量、长度、并行召回、去重截断和第二次模型调用限制。") [回答引用白名单 ↗](../../../apps/server/src/assistant/runtime.ts#L604 "支持服务器过滤未提供给模型的引用，并只保存校验后的 selected evidence。")
6. **轮次处于 pending 或 degraded**：优先处理模型可用性；它与搜索能否找到材料是两个独立故障面。参考 [模型不可用与降级 ↗](../../../apps/server/src/assistant/runtime.ts#L524 "说明模型不可用时保持待重试，以及其他异常生成无引用降级回复。")

当前排序由路线融合、来源或符号权重及 MMR 式去重组成，现有实现没有展示独立的学习型重排阶段；中文向量又依赖本地锁定权重，权重不可用时只剩词法路线。参考 [相关性与去重排序 ↗](../../../apps/server/src/retrieval/ranking.ts#L3 "支持符号权重、MMR 式相关性排序和冗余控制的说明。") [本地中文向量模型 ↗](../../../apps/server/src/retrieval/embedding.ts#L14 "支持锁定 BGE 模型版本、校验权重和离线 CPU 量化加载的说明。")

检索合同允许调用方显式提供时间范围，但过滤依据是材料 revision 的捕获时间，而不是飞书消息实际发生时间，也不是历史时点查询。当前顶部搜索和助手调用都没有传入这一条件；只有未来某个调用方实际提供 `timeRange` 时，才应把捕获时间过滤纳入该入口的排查。参考 [可选时间过滤合同 ↗](../../../apps/server/src/retrieval/port.ts#L25 "证明时间范围是调用方可选条件，且针对 revision 捕获时间，而不是事件时间或历史时点。")

<a id="limits"></a>
## 理解当前边界，避免修错层次

“搜不到”并不总是排名问题。顶部搜索是工作区级原始材料检索，而助手还受宿主可见性约束；如果两者结果不一致，应先确认访问范围，而不是放宽相关性阈值。飞书群聊只把当前 chatId 对应的材料交给助手，这是证据隔离边界。参考 [飞书群聊证据可见性 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L93 "支持飞书助手宿主按当前 chatId 限制可交给模型的材料。")

语义检索使用本地小型中文模型和精确余弦计算，索引按批次追赶；RRF 负责融合不同路线，MMR 负责降低重复，但不能替代模型对候选进行细粒度交叉理解。参考 [语义索引与降级 ↗](../../../apps/server/src/retrieval/semantic.ts#L21 "说明后台索引、词法与向量融合，以及异常时退回词法检索。") [相关性与去重排序 ↗](../../../apps/server/src/retrieval/ranking.ts#L3 "支持符号权重、MMR 式相关性排序和冗余控制的说明。")

上下文也有明确预算：单个长片段最多围绕命中位置取 2000 字，初始证据与章节邻居最多 28 条，扩展检索合并后最多 24 条。跨越多个远距离章节的完整流程仍可能被截断，因此确认“材料已命中”之后，还要检查模型实际收到的证据范围。参考 [助手召回与证据预算 ↗](../../../apps/server/src/assistant/runtime.ts#L665 "支持助手显式传入会话可见性、保留排序命中、补充章节邻居和 28 条预算。") [一轮扩展检索 ↗](../../../apps/server/src/assistant/runtime.ts#L514 "支持额外查询的数量、长度、并行召回、去重截断和第二次模型调用限制。") [语义命中原文截取 ↗](../../../apps/server/src/assistant/runtime.ts#L786 "支持验证语义焦点仍存在于当前原文，并围绕命中位置截取最多 2000 字。")
