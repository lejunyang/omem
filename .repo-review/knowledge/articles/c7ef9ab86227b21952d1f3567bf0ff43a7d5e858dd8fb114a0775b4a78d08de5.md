# 一次提问如何找到答案：搜索、上下文与 RAG

沿“这次活动要准备多少钱、到哪里集合？”这一教学问题，解释整句提问怎样先形成全文与向量候选，候选怎样在固定版本中补回完整章节和上级条件，以及 Agent 怎样只针对未解的金额、地点或活动身份分别检索完整语境。最后用召回、补读、调查和回答四层定位遗漏。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="example"></a>
## 先明确什么才算回答了问题

一次可用回答不是“找到一段相关文字”，而是依次完成四件事：**召回可能有用的候选，补回会改变结论的完整语境，围绕仍未解决的部分继续调查，最后逐项写进答案**。任一步都可能遗漏。

下面是全文共用的**教学示例**，只用于解释机制，不代表一次真实运行或固定排名：

| 已保存的材料 | 内容 |
| --- | --- |
| 当前活动说明的“费用”章 | 参加预算八十元；仅限已报名者；不含交通费；周三 18 点前确认 |
| 同一说明的“集合”章 | 在图书馆集合 |
| 旧活动记录 | 也出现“八十元” |
| 主题介绍 | 讨论活动内容，但没有金额、集合点或适用条件 |

用户问：“这次活动要准备多少钱、到哪里集合？”

可用答案至少要覆盖**金额**与**集合点**，并保留会改变行动或适用范围的条件。例如：

> 若这份当前活动说明确实对应你说的这次活动，并且你已经报名，预算为八十元，不含交通费，需在周三 18 点前确认；集合点是图书馆。

这里的金额、报名资格、费用范围、截止时间和集合点应分别贴近对应原件引用。如果材料不能把“这次”唯一绑定到某个活动或版本，就应把活动身份或日期标为未知，而不是按相似度、上传时间或“看起来更新”替用户决定。设计说明把语义遗漏概括为：必要条件没有找到、命中后没有读上下文、读到后没有写进结论；引用合法本身发现不了这些问题。参考 [语义遗漏与可用答案 ↗](../../../docs/reader-first/answer-investigation.md#L5 "说明必要条件可能在召回、补读或写入答案时遗漏，并要求保留改变结果的对象、时间与例外。")

因此，坏答案可以先分成四层：

1. 金额或地点没有进入候选：**召回遗漏**。
2. 命中“八十元”，但同章的报名、交通费或截止条件没有进入阅读材料：**补读遗漏**。
3. 地点在另一章，首轮没命中，Agent 也没有围绕这个未解子问题继续找：**调查遗漏**。
4. 金额、地点和条件都已读到，最终仍漏写或把旧记录当成当前安排：**回答遗漏**。

## 整句问题怎样变成候选

材料保存后不总是以整文件参加排序。Markdown 会按块形成检索段并保留章节路径；表格、列表和代码块如果由上一段引出，会尽量和引导句保持在一起。这样，“参加预算八十元”和“图书馆集合”可以分别成为可排序的线索，又不会丢失所在章节。参考 [Markdown 检索段保留结构 ↗](../../../apps/server/src/retrieval/units.ts#L33 "支持按块形成检索段、保留章节路径，并让表格列表代码与引导句保持完整。")

**全文路线**先把查询拆成词，再用 FTS5/BM25 找原文中直接出现的内容。中文查询使用 `Intl.Segmenter`，过滤常见停用词，并为 2～8 个汉字的短查询保留完整词形；案例里的“八十元”“图书馆”“集合”等字面信息适合走这条路线。参考 [中文查询分词与短词保留 ↗](../../../apps/server/src/retrieval/relevance.ts#L1 "支持中文分词、停用词过滤和 2 至 8 个汉字完整短词。") [BM25 全文候选 ↗](../../../apps/server/src/retrieval/unified.ts#L427 "支持用查询词构造 FTS5 查询并按 BM25 形成候选。")

**向量路线**在 embedding 可用时比较问题与检索段的语义接近程度，所以“准备多少钱”也可能找到写着“参加预算”的段落。向量不可用或执行失败时，搜索仍可依靠全文和符号候选。参考 [向量召回与失败回退 ↗](../../../apps/server/src/retrieval/unified.ts#L480 "支持向量候选，以及 embedding 不可用或执行失败时退回全文与符号候选。") 各路线原始分数尺度不同，当前实现用 RRF 按各自名次融合；融合后还会在最终排序中叠加查询用途、材料适用性等优先级。参考 [RRF 名次融合 ↗](../../../apps/server/src/retrieval/unified.ts#L408 "支持全文、向量和符号路线忽略不可比的原始分数尺度，按各路线名次计算标准 RRF。") [用途与材料适用性优先级 ↗](../../../apps/server/src/retrieval/unified.ts#L606 "支持融合后按查询用途、代码定义、文章复核状态和材料适用性等因素调整最终优先级。")

这些结果仍只是“值得读的线索”。主题介绍可能因词面或语义接近而进入清单，但没有金额或地点，不能支持答案。共享检索接口让阅读器、助手和 Agent 工具使用同一类固定目标，不过不同入口可以用不同的展示与上下文策略。参考 [共享检索合同 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持阅读器、助手和 Agent 工具共享检索，并让结果保留固定目标与原件引用。")

普通助手首轮把**整句**用户问题交给共享搜索，取一批候选并关闭浏览用的来源/章节去重，然后按原排名装配不同的完整阅读上下文。它此时没有先把问题自动拆成“金额”和“集合点”。界面搜索仍可以为浏览体验去重，所以页面只展示同一来源的少数段落，不代表助手只能读这些段落。参考 [助手首轮整句召回 ↗](../../../apps/server/src/assistant/runtime.ts#L940 "支持普通助手将整句 userText 交给搜索、取 48 条且关闭展示去重，再装配回答上下文。") [候选、上下文与分组调查的边界 ↗](../../../docs/reader-first/retrieval-redesign.md#L19 "说明浏览列表、助手首轮和按子问题调查的差异，并明确不存在答案要点覆盖保证。")

当前候选数和阅读入口数都有上限，也没有“金额和地点都出现才算召回完成”的确定性覆盖算法。相关性分数提高找到材料的机会，却不等于材料已经回答问题。

<a id="context"></a>
## 命中预算后怎样补回条件

假设全文或向量先命中“参加预算八十元”。回答阶段不会只把这一小段交给模型。

对原件命中，当前实现只在**同一固定 revision** 内恢复包住命中的最小完整 Markdown 章节或代码操作。没有可靠结构时保留原命中，不默认附上整份文件；扩展范围中的片段必须全部通过可见性检查。参考 [原件命中恢复同版完整上下文 ↗](../../../apps/server/src/retrieval/context.ts#L13 "支持命中只在同一固定版本中扩为最小完整章节或操作，并检查扩展范围可见性。")

系统还会沿结构向上读取父章节在第一个子节之前的真实引言，并作为独立固定范围加入。例如，“仅限已报名者”若写在费用子节的上级引言中，可以随费用章进入阅读材料。这个规则不会自动拼接兄弟章节，所以另一章的“图书馆集合”仍需要自己的候选，或在后续调查中单独补查。参考 [父章节引言独立补入 ↗](../../../apps/server/src/retrieval/context.ts#L43 "支持补入父章节首个子节前的真实说明，同时不自动拼接兄弟章节。")

回答上下文装配以恢复后的 revision 和行范围去重，并限制不同阅读上下文的数量，而不是把已经选中的完整章再次截成零散片段。知识文章命中也只恢复同一固定文章版本的相关完整章节，并合并该节实际使用的原件引用。换句话说，**细段用于排序，固定完整章节用于理解**。参考 [完整回答上下文装配 ↗](../../../apps/server/src/assistant/context.ts#L74 "支持知识整节恢复、原件完整范围去重、不同阅读上下文限制及引用合并。")

结构展开能补回同章相邻内容和父级明确写出的适用条件，但不能发现任意兄弟章、其他文件或模型没有识别出的前提。它也可能带来与问题无关的文字。因此，“读了完整章”仍不是找全答案的证明。

<a id="investigation"></a>
## 按未解子问题继续查，并辨认旧记录

首轮整句召回之后，Agent 才可以主动把复合问题拆成具体的调查部分。当前助手技能规定：用户同时问多个结果、比较多种情况，或者缺少会改变结论的前提时，可以使用 `search_contexts`；简单查值不强拆，同义关键词也不能冒充多个子问题。参考 [何时按子问题调查 ↗](../../../packages/agent-runtime/roles/daily-assistant/1/skills/omem-assistant-research/SKILL.md#L8 "说明多结果、比较或关键前提缺失时按具体问题检索，简单查询不强拆且同义改写不算多个问题。")

在教学案例中，一个合适的**建议性调查策略**是维护三个槽位：

1. **金额与费用条件**：预算、报名资格、是否含交通、确认截止时间。
2. **集合点**：地点以及它对应哪个活动。
3. **“这次”的身份**：活动名称、日期或版本关系。

这是 Agent 使用现有工具的策略，不是检索器内置的自动规划。若费用槽位已经有完整语境、集合点仍为空，就只围绕材料中出现的真实术语补搜“集合、地点、图书馆”等，不必反复搜索费用。

`search_contexts` 接收 Agent 自己提出的具体问题和查询。实现会为每个问题分别调用检索，关闭浏览去重，使金额与集合点不必竞争同一份全局 top-k；原件命中立即恢复同版焦点章节和父级引言，知识命中返回固定文章版本的完整节。相同固定上下文在全局 `contexts` 中只返回一次；每个问题各自保留 `matches` 映射，可以用同一个共享 `contextId` 指向该正文，并记录它在该问题检索池中的 `rank`。当前测试也明确验证：两个费用问题命中同一费用章时，二者映射中的 `contextId` 相等。结果只是阅读线索，不是已验证答案或覆盖分数；某一组为空表示搜索缺口，不证明事实不存在。参考 [按问题检索与共享上下文映射 ↗](../../../apps/server/src/knowledge/agent-research.ts#L612 "支持每题独立检索、固定上下文全局去重，并由各题 matches 通过共享 contextId 和题内 rank 建立映射。") [共享 contextId 的回归测试 ↗](../../../apps/server/tests/agent-research.test.ts#L30 "验证两个费用问题命中同一费用章时共享相同 contextId，同时保留各自 matches。")

初始命中也以 leads 的身份写入助手上下文，并携带材料用途、状态等阅读辅助。它们不构成强制阅读顺序或完整答案。参考 [初始命中只是阅读线索 ↗](../../../apps/server/src/assistant/acp-model.ts#L245 "支持助手上下文携带初始命中及材料说明，并明确它们不是完整答案或强制阅读顺序。") 先读阶段会检查对象、时间、关键前提和用户所需结果；若需要跨文件追踪、解决冲突或补关键前提，应交接已经确认的事实和具体缺口，而不是提交半份答案。条件仍未知时可以给简短的条件式答案。参考 [按关键前提决定回答或交接 ↗](../../../apps/server/src/assistant/reading-stage.ts#L59 "支持直接回答、条件式回答，以及围绕跨文件、冲突或缺失前提交接具体缺口。")

旧活动记录也出现“八十元”时，应依次核对：

- 原件正文中的活动名称、日期、版本与适用对象；
- 版本绑定的材料说明中的 role、status、scope、validFrom/validUntil；这些是阅读和排序辅助，不是真伪裁决；
- 同一来源的历史版本关系。指定旧 revision 时，历史工具返回那一版自己的正文和行数，旧事实必须保持自己的版本身份。

检索只有在查询显式提供 `effectiveAt` 时才按 validFrom/validUntil 过滤；默认的 plan、research、example、historical 或 superseded 标注只是导航先验，不能替用户判断哪条记录代表“这次”。参考 [有效期过滤与材料排序先验 ↗](../../../apps/server/src/retrieval/unified.ts#L231 "支持 effectiveAt 仅在显式提供时过滤，并说明材料用途和状态是导航偏好而非真伪裁决。") [历史版本保持独立身份 ↗](../../../apps/server/src/knowledge/agent-research.ts#L950 "支持按同一来源列出版本，并在指定 revision 时读取对应旧正文和行数。")

若名称、时间和版本关系仍无法消歧，当前**未知项**就是活动身份或日期。此时应并列说明候选差异，询问一个最小澄清问题，或写成“若你指的是 X 当前说明，则……”；不能凭排名、捕获先后或历史标签断言旧记录错误。

<a id="diagnosis"></a>
## 组织答案，并按遗漏所在层修改

最后一步是把已确认的金额、报名资格、费用范围、截止时间和集合点逐项写入答案，并让引用贴近所支持的句子。提交时，宿主会校验引用是否来自本次授权材料或其同源历史版本、固定范围是否可见，以及正文引用标记是否有原文定位。这个门禁保证“引用来自哪里”，不保证问题已经答全。参考 [提交时校验固定原件引用 ↗](../../../apps/server/src/assistant/research.ts#L105 "支持校验授权材料、同源历史版本、可见性和行范围，并要求正文引用有原文定位。")

跨来源机制、冲突或会改变结论的重要推断可以交给独立答案复核；简单的原文直接查值不必为形式再启动复核。复核使用同一固定材料快照。参考 [独立复核适用范围 ↗](../../../apps/server/src/assistant/answer-review.ts#L107 "说明独立复核用于复杂解释或重要前提，简单直接查值不必触发。") 一旦启动复核，运行时会阻止在复核仍进行、意见未读取，或发现实质问题却原样提交时结束。这个门禁仍不是正确性证明。参考 [复核后的提交门禁 ↗](../../../apps/server/src/assistant/answer-review.ts#L204 "支持复核运行中、意见未读取或有实质问题但答案未修改时阻止提交。")

发现坏答案时，保留同一次问题的**首轮候选、按子问题得到的候选组、展开后的完整上下文和最终答案**，再定位修改入口：

| 观察 | 所在层 | 首要实现入口 |
| --- | --- | --- |
| 金额或地点没进任何候选 | 召回 | `retrieval/units.ts`（检索段）、`retrieval/relevance.ts`（查询词）、`retrieval/unified.ts`（全文、向量与融合） |
| 命中费用，但报名、交通或截止条件没进入阅读材料 | 补读 | `retrieval/context.ts`（焦点完整章、父引言、可见性）、`assistant/context.ts`（上下文选择与去重） |
| 地点在兄弟章，首轮没中，Agent 又没有按未解子问题继续搜 | 调查 | daily-assistant 调查技能、`assistant/reading-stage.ts`、`assistant/acp-model.ts`、`knowledge/agent-research.ts` 的 `search_contexts` |
| 金额、地点和条件都已进入模型材料，答案仍漏项或误用旧记录 | 回答与复核 | `assistant/research.ts`（提交引用）、`assistant/answer-review.ts`（独立复核） |

工具调用只证明某次读取发生过，不能证明模型理解并采用了条件。修改后仍应回到同一个真实问题，逐层确认：必要材料是否进入候选、完整上下文是否保留改变结论的条件、未解子问题是否得到补查、最终答案是否逐项回应用户。参考 [按阅读链路验收回答 ↗](../../../docs/reader-first/answer-investigation.md#L41 "支持结合候选、读取记录和最终答案定位遗漏，并说明工具记录不能证明模型已经理解。")
