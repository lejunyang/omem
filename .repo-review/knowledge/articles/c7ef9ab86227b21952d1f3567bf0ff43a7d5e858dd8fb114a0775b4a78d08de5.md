# 一次提问如何找到答案：搜索、上下文与 RAG

用一条群消息贯穿 omem 的搜索与回答链路：共享召回怎样组合全文、中文语义、符号、知识和记忆，命中后怎样补齐结构上下文，助手怎样继续调查并把结论固定到原文；最后给出区分召回、上下文调查和回答组织问题的方法与修改入口。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="scenario"></a>
## 先看一条群消息怎样变成答案

以下是**教学示意**，不承诺某个搜索词一定排第一：同事在已监控群里发“报名截止改到周五，入口在表单页”。这条普通群消息会以聊天原件捕获，保留事件时间、发言人和回复关系；owner 随后在同群 @机器人问“报名现在到哪天，入口在哪？”，才进入实时助手分支。换句话说，并非所有群消息都触发回答，触发助手的提问也不等同于前一条被捕获的普通消息。参考 [群聊助手触发条件 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L530 "支持教学场景中只有绑定 owner 的私聊或群内 @机器人消息进入实时助手分支。") [普通群消息捕获 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L602 "支持未进入助手分支的受监控群消息按 chat 原件保存，并记录事件与来源信息。")

群助手为这个群打开独立会话并调用助手运行时；检索可见性只允许同一 chatId 已采集的证据，owner 的私聊或私人导入不会混进来。这是群会话的服务端范围控制，不应外推成团队级隔离能力。参考 [群会话证据范围 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L90 "支持群助手只读取同一 chatId 已采集证据的可见性约束。") [飞书会话进入助手 ↗](../../../apps/server/src/integrations/lark/runtime.ts#L147 "支持为飞书群打开独立会话并调用 AssistantRuntime.turn 的流程。")

用户可观察到的结果是：助手给出截止时间和入口，并能回到当时那条群消息的固定原文；开发者若要追问“为什么能进入回答”，则从概念搜索转向实现定位。

<a id="division"></a>
## 搜索找候选，回答完成判断

**搜索**解决“哪些材料可能有用且能定位”，**回答**解决“这些材料是否真的回答当前问题、还缺什么上下文、结论怎样表达”。共享合同把原件、派生讲解和已应用状态保留为不同结果，同时让固定来源仍可阅读。参考 [共享检索合同 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持读者、助手和 Agent 共用检索，同时区分原件、讲解与已应用状态。")

| 入口 | 共用什么 | 主要差异 |
| --- | --- | --- |
| 顶部搜索 | 统一检索 | 默认综合查找，可显式给用途、代码意图、材料角色和有效时间。参考 [顶部搜索入口 ↗](../../../apps/server/src/app.ts#L312 "支持顶部搜索调用统一检索并暴露用途、代码意图、角色与有效时间筛选。") |
| 知识搜索 | 同一统一检索 | 只取 knowledge，并受分类路径限制。参考 [知识搜索范围 ↗](../../../apps/server/src/knowledge/api.ts#L118 "支持知识搜索限定 knowledge 类型与分类路径，说明它与顶部搜索结果不同。") |
| 助手 | 同一统一检索 | 用用户原话和用途取候选，再叠加当前会话的可见性；原件进入证据，知识、记忆、事项等进入背景，其原始 references 仍会还原为证据。参考 [助手首轮上下文 ↗](../../../apps/server/src/assistant/runtime.ts#L918 "支持助手使用统一检索、会话可见性，并把原件 references 还原为证据、其他类型作为背景。") |

所以三个入口共用召回基础，却不会显示同一结果集。kind、topicPath、purpose、会话范围和 limit 都会改变候选。相关性分数只说明“值得读”，不等于“已经能回答”。

<a id="routes"></a>
## 五类线索各自补什么

统一检索先让不同路线独立找候选，再融合和按用途排序：

- **全文与中文短词**：标题、上下文和正文进入 FTS/BM25；ICU 分词之外，2–8 字纯中文查询会保留整体词，适合正文确实出现的“报名截止”、路径或标识符。明确标识符要求真实字面命中，不让向量猜一个相似名字。参考 [中文短词与精确查询 ↗](../../../apps/server/src/retrieval/relevance.ts#L9 "支持 ICU 分词、短中文整体词和精确标识符判断的解释。") [全文候选生成 ↗](../../../apps/server/src/retrieval/unified.ts#L414 "支持 FTS/BM25 从检索单位的正文与上下文生成词法候选。")
- **中文向量**：补足“说法不同、意思相近”的候选；向量失败会退回词法路线。当前配置启用本地 memory-zh，实际锁定 BGE-small-zh-v1.5 的版本与校验和，使用 CPU q8；它只提供召回线索。参考 [混合召回与可选重排 ↗](../../../apps/server/src/retrieval/unified.ts#L476 "支持词法、向量、符号融合、向量失败回退，以及重排候选范围的当前实现。") [当前检索配置 ↗](../../../config/retrieval.json#L1 "支持当前仅启用 memory-zh、没有配置 reranker 的事实。") [中文向量模型加载 ↗](../../../apps/server/src/retrieval/embedding.ts#L14 "支持 BGE-small-zh-v1.5 固定版本、校验、本地 CPU q8 运行的说明。")
- **符号**：显式方法名、限定名或 codeIntent 可走 AST 定义/调用方导航，适合从讲解落到修改入口。调用方按名称产生候选，不做完整接收者类型和跨文件调用图，仍要读 import 与完整方法。参考 [符号与调用方导航 ↗](../../../docs/reader-first/code-navigation-and-passages.md#L7 "支持 AST 定义/调用候选的用途，以及名称级导航、类型和跨文件解析限制。")
- **知识**：已整理的文章按章节进入检索，携带文章版本、章节和递归原件 references；它适合先理解整体，但仍是派生背景。参考 [知识章节检索单位 ↗](../../../apps/server/src/retrieval/units.ts#L692 "支持文章按受支持章节投影，携带固定文章定位和原件 references。")
- **记忆与事项**：只投影当前 active memory 或事项版本，并保留能回到原件的 references；它们帮助回答当前个人状态和跟进，不是第二份原文。参考 [当前记忆检索单位 ↗](../../../apps/server/src/retrieval/units.ts#L827 "支持只投影 active memory 当前 head，并保留原始证据 references。")

purpose 只调节组合偏好：概念偏知识、实现偏代码、背景偏知识/记忆、跟进偏事项和近期会话，不是真伪判断。

<a id="context"></a>
## 命中片段后怎样恢复上下文

保存单位、检索单位和阅读单位彼此分开。Markdown 按标题路径组织段落，并把引导句与紧随的列表、表格或代码块保持在一起；TS/JS/Vue 按完整函数或方法组织，局部变量不会把外层控制流切碎，import 和顶层配置也可搜索。参考 [Markdown 结构切分 ↗](../../../apps/server/src/retrieval/units.ts#L31 "支持标题路径、段落与列表表格代码块保持连贯的检索单位设计。") [代码结构切分 ↗](../../../apps/server/src/retrieval/units.ts#L90 "支持按完整函数方法与顶层配置建立代码检索单位，而不让局部声明破坏控制流。")

聊天单位额外携带会话、发言人、事件时间和 replyTo。统一结果返回 headingPath/context；短知识段可直接展示完整文字，长原件展示最相关摘录，但 target 仍指向完整单位。旧的原件兼容路径还会在同一章节内补标题、前后相邻片段，并逐一检查可见性。参考 [聊天结构上下文 ↗](../../../apps/server/src/retrieval/units.ts#L286 "支持聊天检索单位携带发言人、事件时间、会话和回复关系。") [章节邻接补读 ↗](../../../apps/server/src/retrieval/context.ts#L5 "支持原件命中后补充同章节标题、前后片段并检查可见性。")

因此命中“周五”后，助手还应核对它属于哪段对话、谁说的、发生时间以及是否回复了另一条消息；理解代码时则应打开所在完整方法、调用条件和下游操作，而不是只解释命中的几百字。

<a id="investigation"></a>
## 助手怎样继续查并固定引用

当前主路径会进入原生 Agent 调查，而不是把首批片段直接塞给一次性回答器。工作区获得当前问题、用途、初始原件线索、知识背景、会话历史、事项和时钟；初始命中只是 reading leads，Agent 可继续搜索材料与知识、打开完整章节、查历史、记忆、图片和代码导航。参考 [原生调查准备 ↗](../../../apps/server/src/assistant/acp-model.ts#L163 "支持当前 ACP 主路径建立调查工作区、复核工具和可补读材料环境。") [调查线索与工具循环 ↗](../../../apps/server/src/assistant/acp-model.ts#L228 "支持初始命中只是线索，Agent 可自主选择工具且当前会话不设宿主工具次数上限。")

```mermaid
flowchart LR
  Q[用户问题] --> R[统一检索候选]
  R --> C[补读章节与方法]
  C --> J[判断事实、背景与缺口]
  J --> A[形成答案]
  A --> F[固定原文行范围]
```

最终引用不是“现在最相似的文本”。提交时，宿主检查材料是否在本次授权范围、历史版本是否属于同一来源、所有 fragment 是否可见、行号是否合法，再把它还原成固定 revision 与范围。参考 [固定引用校验 ↗](../../../apps/server/src/assistant/research.ts#L102 "支持提交引用时检查授权材料、历史版本、可见性与真实行范围。")

复杂的跨来源机制、冲突或当前行为关键前提可请求独立答案复核；简单原文查询不强制增加一次模型调用。复核者读取相同冻结材料和候选答案，不读取作者笔记；作者必须取回意见并修订有实质问题的原样草稿。但是否触发复核、复核者是否漏判，仍不能由宿主完全证明。参考 [调查与独立复核边界 ↗](../../../docs/reader-first/answer-investigation.md#L13 "支持复杂问题按需独立复核、短查询不强制复核，以及当前 Sol 与复核漏判限制。")

<a id="limits"></a>
## 当前模型、重排和时间边界

当前仓库只在检索配置中启用 memory-zh，没有配置 reranker，因此 cross-encoder 重排默认关闭；可选重排最多处理前 40 个融合候选，长单位只抽取有限窗口，不能替代完整阅读。默认回答 profile 当前使用 Sol，而召回 embedding 与回答模型职责不同。参考 [混合召回与可选重排 ↗](../../../apps/server/src/retrieval/unified.ts#L476 "支持词法、向量、符号融合、向量失败回退，以及重排候选范围的当前实现。") [调查与独立复核边界 ↗](../../../docs/reader-first/answer-investigation.md#L13 "支持复杂问题按需独立复核、短查询不强制复核，以及当前 Sol 与复核漏判限制。")

时间也有两个容易混淆的维度：timeRange 过滤的是**捕获 revision 时间**，不是事件发生时间或历史 as-of；effectiveAt 只有调用方明确提供、且材料有正式有效期时才参与过滤。聊天 eventAt、记忆 valid_from 和事项修订时间可帮助跟进排序，但系统尚无完整时态推理。参考 [检索时间字段 ↗](../../../apps/server/src/retrieval/port.ts#L96 "支持 timeRange 是捕获时间、effectiveAt 是显式有效时间查询的区别。")

实际限制不是“没有测试就不知道机制”，而是初始排序仍可能把题目、计划或宽泛说明放在真正答案前；Agent 补查成功与独立复核通过，都不能反推首屏召回已经改善。参考 [失败分层与验收方法 ↗](../../../docs/reader-first/answer-investigation.md#L29 "支持把问题区分为没找到、没补读和最后遗漏，并说明复核或工具记录不能替代真实效果。")

<a id="diagnosis"></a>
## 从结果反推问题和修改入口

排查时依次看三个检查点：

1. **正确原件或知识章节有没有进入初始候选或补查结果？** 没有，优先查索引、检索单位、分类、范围和融合排序。
2. **命中后有没有打开完整章节、方法、调用条件、来源和时间？** 没有，这是上下文调查问题。
3. **材料已经齐全，答案仍漏条件、混淆当前与历史，或不给下一步？** 这是回答组织与推理问题。参考 [失败分层与验收方法 ↗](../../../docs/reader-first/answer-investigation.md#L29 "支持把问题区分为没找到、没补读和最后遗漏，并说明复核或工具记录不能替代真实效果。")

对应修改入口也按这三层分开：改召回路线、融合、用途偏好和去重看 `retrieval/unified.ts`；改文档、代码、聊天、知识、记忆怎样成为检索单位看 `retrieval/units.ts`，改共享字段看 `retrieval/port.ts`；改顶部/知识入口范围看 `app.ts` 与 `knowledge/api.ts`；改助手首轮上下文和固定引用看 `assistant/runtime.ts`、`assistant/research.ts`，改原生调查与独立核对看 `assistant/acp-model.ts`、`assistant/answer-review.ts`。共享接口明确把用途、代码意图、类型、分类、时间与可见性作为调用方可控字段，而不是从目录猜测。参考 [统一查询可控字段 ↗](../../../apps/server/src/retrieval/port.ts#L96 "支持修改入口说明中用途、代码意图、类型、分类、时间和可见性均是正式查询字段。")
