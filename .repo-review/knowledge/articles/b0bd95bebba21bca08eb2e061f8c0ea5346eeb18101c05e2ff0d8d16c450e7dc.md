# 检索查询的词面解释与局部相关性

这一组共享函数把中英文自然语言问题整理成检索词和代码符号候选，并提供正文覆盖度评分、精确查找判断、调用者意图捷径与局部摘要选择。它连接统一检索、关键词检索和代码导航，但自身不是完整的搜索或意图理解系统。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 把自然问题变成可检索信号

`relevance.ts` 是检索链路的轻量共享层：它不访问数据库，而是把用户问题转换成稳定的词面信号。`queryTerms` 保留 ASCII 标识符式片段，用中文 ICU 分词拆分其余文本，再做小写化、停用词过滤与去重；对 2–8 个纯汉字的短查询还保留完整字面量，避免“重试”之类领域词被拆散。参考 [查询词生成 ↗](../../../apps/server/src/retrieval/relevance.ts#L3 "支持中英文分词、短汉字复合词保留、小写化、停用词过滤与去重的说明。")

代码导航另走更保守的识别：`exactLookup` 判断单个标识符或路径式查询，`querySymbols` 只接受独立查找、引号包裹或带驼峰、下划线、点号等代码形态的名称。因此普通英文句子里的 `apply` 不会自动成为符号，而 `` `apply` `` 可以；这些名称只是导航候选，不代表已经回答问题。参考 [代码符号识别 ↗](../../../apps/server/src/retrieval/relevance.ts#L29 "支持精确查找规则、显式代码形态筛选，以及符号仅为导航候选的边界。")

<a id="representative-flow"></a>
## 代表性调用：寻找某个函数的调用方

以“哪些地方调用 `reserveParcel`？要找调用方，而不是定义”为例：符号提取先得到 `reserveparcel`，调用者短语检测命中后，统一检索把未显式指定意图的请求改写为 `codeIntent: callers`。参考 [调用者意图改写 ↗](../../../apps/server/src/retrieval/unified.ts#L339 "证明统一检索在存在符号且命中调用者问法时，将请求改写为 callers 意图。")

```mermaid
flowchart LR
  Q[自然语言问题] --> S[提取代码符号]
  S --> I[识别调用者意图]
  I --> C[调用候选导航]
  C --> O[候选调用位置与局部代码]
```

随后调用分支在代码检索单元中定位名称，交给导航器核对匹配行，并以 `code-call-candidate` 返回最小包围操作及附近代码；这里明确是候选关系，不应解读成类型解析完备的调用图。参考 [调用候选输出 ↗](../../../apps/server/src/retrieval/unified.ts#L346 "支持调用分支筛选代码单元、核对匹配行并输出候选位置和局部代码的流程。") 测试场景也验证了自然语言意图与显式 `codeIntent: callers` 得到相同结果，并将命中标为候选。参考 [调用导航行为 ↗](../../../apps/server/tests/retrieval-unified.test.ts#L675 "验证自然语言调用者请求与显式 callers 意图的一致性，以及结果的候选状态。")

<a id="scoring-boundaries"></a>
## 正文门槛、摘要窗口与边界

普通词面检索中，`relevance` 先要求正文命中足够多的查询词：一两个词至少命中一个，更多词至少命中三分之一、上限三个。通过门槛后才计算加权覆盖率平方，并叠加最多 `0.15` 的标题奖励；所以仅标题相符不能让所有片段入选。参考 [覆盖度评分 ↗](../../../apps/server/src/retrieval/relevance.ts#L74 "支持正文命中门槛、可选词权重、覆盖率平方和标题加分的计算方式。")

`bestSnippet` 对每个词最多检查 30 个出现位置，从命中前 60 个字符开始比较固定长度窗口，选择包含不同查询词最多的片段；非开头窗口加前导省略号。它按子串和字符窗口工作，可能切在句子中间，也不负责最终排序。参考 [最佳摘要窗口 ↗](../../../apps/server/src/retrieval/relevance.ts#L88 "支持候选偏移枚举、每词出现次数上限、窗口评分与省略号输出规则。")

修改入口因此很集中：分词与停用词在文件前段，精确查找、调用者短语和符号形态在中段，覆盖门槛与标题权重在评分函数，窗口大小和偏移在摘要函数。`asksForCallers` 只是中英文正则捷径；未覆盖的表达应由调用方显式传入 `codeIntent`，而不是把它当作通用意图模型。参考 [调用者识别边界 ↗](../../../apps/server/src/retrieval/relevance.ts#L32 "源码注释明确该判断只是导航捷径，并允许调用方为其他表达直接提供 codeIntent。")
