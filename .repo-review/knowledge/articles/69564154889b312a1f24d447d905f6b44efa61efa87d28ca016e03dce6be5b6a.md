# 代码生成预算与模型上下文窗口测试

该测试验证两层预算保护：估算多字节文本的 token 成本并校验宿主输入上限，再依据 ACP 选项中发现到的当前模型窗口检查输入、输出与预留之和。现有材料覆盖主要成功和失败路径，但未展示核心实现及其启动调用点。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 预算测试的作用

生成任务需要估算中文等多字节文本的输入成本，并约束宿主传入的预算参数。第一组测试以“中文abc”为样本，断言字符数为 5、UTF-8 字节数为 9、估算 token 为 3、计入余量后为 4；它还确认合法的宿主输入上限会被采用，而负数上限会触发错误。[UTF-8 估算与宿主上限断言 ↗](../../../apps/server/tests/code-budget.test.ts#L5 "支持多字节文本估算、合法宿主输入上限被采用以及负数上限被拒绝的论断。") 此结论替代此前“覆盖默认输入上限”的说法，因为材料没有给出默认值或预算实现。预算函数由服务器代码入口转发自共享的 agent-runtime，表明这里验证的不是 code 模块内的独立算法。[共享预算能力导出 ↗](../../../apps/server/src/code/budget.ts#L1 "说明服务器 code 入口从通用 agent-runtime 转发预算函数与类型。")

<a id="flow"></a>
## 发现窗口的校验流程

第二组测试构造 ACP 模型选择项：当前值为 `small` 时，元数据给出的发现窗口是 32000；输入 40000、输出 8000、预留 16000 合计 64000，因此校验应抛出包含需求量和窗口值的错误。切换到 `large` 后返回 272000；完全没有选项时返回 `null`。[当前模型发现窗口检查 ↗](../../../apps/server/tests/code-budget.test.ts#L11 "支持按当前选项的发现窗口检查预算总量、切换模型和无选项返回空值的流程。") 这里应称为“发现到的当前模型上下文窗口”，替代此前“实际模型窗口”的过强表述，因为测试只使用会话选项元数据。`AcpOptions` 将三项预算作为可选 `contextBudget` 暴露给代理运行接口，但所给范围未显示校验函数的定义或调用时机。[代理运行接口的上下文预算 ↗](../../../apps/server/src/agents.ts#L24 "证明代理运行选项接收估算输入、最大输出与上下文预留三项预算。")

<a id="boundaries"></a>
## 覆盖范围与限制

现有两个用例覆盖多字节估算、合法与非法宿主上限、发现窗口超限、切换模型成功及缺少选项五类路径。[预算测试现有覆盖 ↗](../../../apps/server/tests/code-budget.test.ts#L5 "用于归纳当前两个测试实际覆盖的行为，并界定尚未验证的边界。") 尚未固定需求恰好等于窗口时的行为，也未覆盖缺失或畸形 `contextWindow`、当前模型无法匹配、零值或非有限预算，以及更复杂 Unicode 输入。测试仅证明函数在构造数据上的返回值和错误文本，不能据此确认真实 ACP CLI 一定准确报告窗口，也不能确认生成任务必然在启动前执行校验。
