# 代码生成上下文预算测试

该测试验证 UTF-8 输入的保守 token 估算、宿主预算覆盖校验，以及所选模型的已发现上下文窗口能否容纳输入、输出和预留空间。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="estimation"></a>
## 字符、字节与预算余量

测试用“中文abc”同时约束字符数、UTF-8 字节数、估算 token 与计费 token，表明预算不是简单按 JavaScript 字符长度计算，并会额外计入余量。宿主传入的合法最大输入值可覆盖默认配置，负数则必须抛出 `Invalid`，避免无效配置绕过限制。[UTF-8 估算与宿主覆盖断言 ↗](../../../apps/server/tests/code-budget.test.ts#L5 "支持字节计数、预算余量及非法最大输入配置被拒绝的说明。")

材料只给出了单个中英混合样例，因此无法从测试本身确定完整估算公式在 emoji、组合字符、超长文本或零长度输入上的表现。

<a id="model-window"></a>
## 按已选择模型校验上下文窗口

`assertContextBudget` 使用模型选项中当前选择项的 `contextWindow` 元数据，将估算输入、最大输出和上下文预留相加。总需求 64000 超过 small 模型的 32000 时抛错；切到 272000 的 large 模型后返回该窗口。若没有发现任何模型选项，则返回空值而不是伪造容量。[模型窗口容量断言 ↗](../../../apps/server/tests/code-budget.test.ts#L11 "支持上下文需求由输入、输出、预留共同组成，并按当前模型窗口校验的说明。")

测试未覆盖当前值不存在、元数据畸形、多个模型选项组或恰好等于窗口上限等边界，也不证明外部 Agent CLI 一定能报告该元数据。
