# 可追溯的代码知识图谱与理解流程

代码模块把 Capture 链中的固定仓库修订投影为可按版本阅读的文件、符号、关系和模块说明，并以合同与引用校验连接原文、派生理解和界面。当前支持离线 TypeScript/Vue 解析、历史快照、人工种子、显式模型生成及成果恢复；跨文件关系、选择性同步、团队隔离和恢复成果的独立语义复核仍有限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 为什么需要代码知识层

普通代码搜索主要反映当前工作树，难以回答某项结论基于哪个版本。本模块把 Capture→Source/Revision/Fragment 中的固定内容投影为文件、符号、关系和理解记录；同步器不重新捕获正文，代码表也不改写原始来源、修订或片段。参考 [代码同步证据边界 ↗](../../../apps/server/src/code/sync.ts#L1 "支持代码知识由已捕获片段投影、同步不重新捕获正文及快照幂等性的说明。") [代码图派生存储边界 ↗](../../../apps/server/src/code/store.ts#L1 "支持代码图是同一评审数据库中的附加派生视图，不改写原始捕获相关表。")

历史文本只从无损固定修订读取，缺失时不会回读当前磁盘来重建证据。参考 [固定修订文本读取 ↗](../../../apps/server/src/source-text.ts#L3 "支持历史证据仅来自无损固定修订，且不会用当前工作树重建。") 因此读者既能阅读 Wiki，也能回到对应版本的原文。延伸阅读：[代码知识同步说明 ↗](77a2bfa010fcb7c75cfc06e221def951343d041b819f5adf30ede8d0dcd8a178.md#purpose "作为子知识延伸阅读，进一步解释同步服务的职责、输入筛选和证据边界。")。底层目前仍是单用户 SQLite，尚不能提供真实的团队租户隔离。参考 [单用户存储边界 ↗](../../../apps/server/src/store.ts#L4 "支持当前 SQLite 是单用户基础，团队级约束仍属于后续迁移。")

<a id="workflow"></a>
## 从固定源码到可阅读知识

```mermaid
flowchart LR
  A[固定 Capture 修订] --> B[离线结构解析]
  B --> C[版本化代码快照]
  C --> D[符号与关系投影]
  D --> E[人工种子或显式模型理解]
  E --> F[人读 DTO]
```
解析器使用单文件 TypeScript AST、Vue SFC 拆块和保守正则，产出带源码坐标的符号、导入、候选调用、路由与测试。参考 [离线代码解析范围 ↗](../../../apps/server/src/code/parse.ts#L1 "说明单文件 TypeScript AST、Vue SFC、正则提取和名称级候选调用的能力边界。") 同步器据此建立稳定符号身份：定义边可确认，相对导入只在捕获集合内解析，调用则仅按同文件名称匹配并保持候选状态。参考 [符号与关系投影 ↗](../../../apps/server/src/code/sync.ts#L250 "支持稳定符号身份、确认定义边、相对导入解析和同文件候选调用边的流程。")

模型理解先限定目标文件和可引用节点，组装完整固定证据并检查输入预算。参考 [模型输入与预算门禁 ↗](../../../apps/server/src/code/understanding-store.ts#L741 "支持目标范围限定、固定证据组装、可引用节点限制和模型调用前预算检查。") 输出还要核对角色、提示词、输入摘要、引用对象和行号范围，未知或越界引用不会成为当前成果。参考 [理解输出引用校验 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L521 "支持角色与摘要封存、引用存在性、选择器范围和种子诚实性的确定性验证。") 延伸阅读：[模型理解生成流程 ↗](b3371593c4922018b730c855f682b8fe880f0633812ad1d353f218a718c4abc2.md#model-flow "作为子知识延伸阅读，串联模型预算、取消、来源封存、验证和持久化过程。")。最后，DTO 保留导航所需内部键，同时增加人读标题、路径、引用标签和不可操作原因，避免把内部标识直接展示给用户。参考 [用户可见 DTO 原则 ↗](../../../apps/server/src/code/dto.ts#L1 "支持保留内部操作键、增加人读字段且不把内部标识渲染为可见标签。")

<a id="versioning"></a>
## 版本、可信度与成果恢复

符号和关系以“稳定身份＋快照”为复合键保存，使代码经历 A→B→A 时各版本仍可并存。参考 [快照历史复合键 ↗](../../../apps/server/src/code/store.ts#L125 "解释符号和关系按快照保存，以及避免 A→B→A 覆盖历史记录的实现。") 当前版本由显式头指针决定，因为复用旧快照时不能按捕获时间推断当前状态。参考 [显式当前快照指针 ↗](../../../apps/server/src/code/store.ts#L273 "支持复用旧快照时不能按捕获时间推断当前版本，必须显式维护头指针。")

模型成果可携带依赖摘要和符号定位器导出。恢复时会比较固定来源摘要、按路径与限定名重定位符号，并重新执行输出合同校验；来源变化记为过期，定位或合同失败记为拒绝。参考 [恢复前依赖与定位校验 ↗](../../../apps/server/src/code/artifacts.ts#L63 "支持恢复时比较依赖摘要、重定位符号并重新执行统一理解合同校验。")

恢复成功的成果会以 `generated`、未过期、模型生成来源写入数据层，同时注明尚未进行独立语义复核。参考 [恢复成果写入状态 ↗](../../../apps/server/src/code/artifacts.ts#L97 "证明恢复结果以 generated、未过期的模型成果写入，并明确记录尚未进行独立语义复核。") 默认理解列表会读取未过期的模型 `generated` 记录，因此这类恢复成果在复核前已经进入当前读取面。参考 [默认当前理解读取条件 ↗](../../../apps/server/src/code/understanding-store.ts#L521 "证明默认读取面包含未过期、来源为模型生成且状态为 generated 的记录。") 合同中只有独立核验代理实际复查后，才允许设置验证标记和 `verified` 状态；结构、来源及引用校验通过并不等于语义已复核。参考 [独立复核状态合同 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L228 "支持 generated 与 verified 的区别，以及只有独立代理复查后才能设置验证标记。")

<a id="progress_limits"></a>
## 当前进展与适用边界

当前流程已覆盖固定修订读取、离线结构解析、幂等快照、历史代码图、人工种子、受预算约束的模型生成、人读 DTO 及模型成果恢复，适合追踪“某版本包含什么”“说明引用了哪里”和“知识为何过期”。

精度上，解析器不建立跨文件 TypeScript Program；调用只形成单文件名称级候选，Vue 组件使用也没有解析到实际目标，因此候选边不能作为真实调用证明。参考 [离线代码解析范围 ↗](../../../apps/server/src/code/parse.ts#L1 "说明单文件 TypeScript AST、Vue SFC、正则提取和名称级候选调用的能力边界。") [符号与关系投影 ↗](../../../apps/server/src/code/sync.ts#L250 "支持稳定符号身份、确认定义边、相对导入解析和同文件候选调用边的流程。") 服务入口虽然接收 `only`，当前仍执行全量同步，不能据此估计增量同步成本或失效范围。参考 [同步选择器现状 ↗](../../../apps/server/src/code/sync.ts#L147 "证明公开同步入口接收 only 参数，但当前仍直接执行全量同步。")

恢复成果会在独立语义复核前进入默认读取面，消费端应区分“可重放且合同有效”与“已独立复核”。参考 [恢复成果写入状态 ↗](../../../apps/server/src/code/artifacts.ts#L97 "证明恢复结果以 generated、未过期的模型成果写入，并明确记录尚未进行独立语义复核。") [默认当前理解读取条件 ↗](../../../apps/server/src/code/understanding-store.ts#L521 "证明默认读取面包含未过期、来源为模型生成且状态为 generated 的记录。") 共享部署同样受单用户存储边界约束，在团队授权模型落地前不应承诺租户隔离。参考 [单用户存储边界 ↗](../../../apps/server/src/store.ts#L4 "支持当前 SQLite 是单用户基础，团队级约束仍属于后续迁移。")
