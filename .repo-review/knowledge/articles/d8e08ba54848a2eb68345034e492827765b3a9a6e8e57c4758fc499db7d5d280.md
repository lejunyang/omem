# code · 模块理解

code 模块把 Capture 链中的固定仓库修订离线投影为可追溯的代码快照、符号与关系图，并在其上承载人工 seed 和可选模型生成的模块理解。源码已串联快照历史、人读 DTO、严格引用校验及版本化产物恢复，但跨文件语义、独立复核、选择性同步和部分事务一致性仍待完善。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_model"></a>
## 统一证据链上的代码派生视图

该模块服务于 Code Wiki 的代码定位、关系浏览与可追溯解释，但不把代码另建为事实权威。分析只读取 Capture 中固定且无损的修订正文；旧式有损捕获视为缺失，不会用当前工作树补造历史证据。[固定 Capture 修订正文读取 ↗](../../../apps/server/src/source-text.ts#L3 "支持代码分析只接受无损固定修订，并拒绝从当前工作树重建历史证据。") 代码侧表位于同一评审 SQLite，文件、符号、边和快照采用确定性身份，是既有 Fragment 上的可重建投影。[统一 SQLite 与确定性代码身份 ↗](../../../apps/server/src/code/store.ts#L1 "支持代码侧表属于统一存储上的派生视图，以及文件、符号、边和快照的稳定身份规则。")

“派生视图完全不支持快照文本副本”的旧结论已被替代：表结构和读取路径允许保存逐快照 `content_text`，并在固定修订不可读时回退到该副本。[快照文本副本的存储与回退能力 ↗](../../../apps/server/src/code/store.ts#L446 "支持表结构允许保存逐快照文本副本，并在固定修订正文不可读时使用该字段回退。") 但当前同步调用明确传入 `contentText: null`，所以这只是存储与兼容读取能力，不能理解为当前同步已经填充了不可变文本副本；当前主要依赖固定 Capture 修订。[同步输入、快照协调与文件绑定 ↗](../../../apps/server/src/code/sync.ts#L170 "支持固定捕获输入、快照身份、新旧快照协调，并直接证明当前同步为快照文件绑定传入空文本副本。") 面向前端的 DTO 保留路由所需内部键，同时增加人读标题、路径、引用标签、可操作状态和原因，避免把内部 ID 当作可见文本。[用户可见 DTO 投影边界 ↗](../../../apps/server/src/code/dto.ts#L1 "支持保留内部操作键、增加人读字段并避免将内部 ID 渲染为标签。")

<a id="sync_graph"></a>
## 从固定修订到快照关系图

同步从已捕获 Source 读取固定 head revision，筛选受支持路径和格式后离线解析；快照身份还会纳入查询所得全部捕获行的内容摘要。新快照和复用快照都会重新协调来源、文件及图数据，不因身份复用而跳过处理。[同步输入、快照协调与文件绑定 ↗](../../../apps/server/src/code/sync.ts#L170 "支持固定捕获输入、快照身份、新旧快照协调，并直接证明当前同步为快照文件绑定传入空文本副本。") 解析器使用单文件 TypeScript AST、Vue SFC 与保守正则提取符号、导入、名称级调用、路由、测试和模板组件；它不做跨文件类型解析，因此调用只能作为候选。[离线 TypeScript 与 Vue 解析边界 ↗](../../../apps/server/src/code/parse.ts#L1 "支持单文件 AST、Vue SFC、保守正则、名称级候选调用及位置合同，并解释跨文件语义限制。")

关系状态需区分来源：声明形成 `defines` confirmed；只有解析到捕获文件集合中目标的相对导入才形成 confirmed，无法解析的相对导入以及所有非相对导入仍会写入 `imports` 边，但状态为 missing。同文件名称匹配的调用和未解析目标的 Vue 组件使用保持 candidate。[符号与关系图状态投影 ↗](../../../apps/server/src/code/sync.ts#L250 "支持声明为 confirmed、导入按解析结果区分 confirmed 与 missing，以及调用和组件使用保持 candidate。") 收尾阶段标记 removed 文件、更新当前快照内的陈旧边、切换显式 head、失效旧模型理解，再投影人工 seed 并恢复版本化成果。[同步收尾与理解失效顺序 ↗](../../../apps/server/src/code/sync.ts#L435 "支持 removed 文件处理、边失效、当前快照切换、旧模型理解失效、seed 投影和产物恢复的串联顺序。") 未在本轮重现或接触 removed 文件的边只在指定快照内变为 stale，其他历史快照不受影响。[快照限定的陈旧边更新 ↗](../../../apps/server/src/code/store.ts#L863 "支持只更新指定快照内未重现或接触 removed 文件的边，其他快照保持不变。")

<a id="understanding_flow"></a>
## 人工 seed、模型生成与版本化恢复

人工 seed 通过“路径、限定名、类型”定位器重解析到固定快照；节点或证据无法解析时保存 rejected，不能静默丢弃引用或冒充模型结果。校验通过的 seed 与引用镜像被持久化，默认读取面可以同时包含当前 seed 和已接受的模型结果。[人工 seed 定位、校验与持久化 ↗](../../../apps/server/src/code/understanding-store.ts#L281 "支持定位或证据失败保存 rejected、成功 seed 与引用写入，以及历史结果保留语义。")

当前适配器支持 ACP、CLI 和显式 HTTP 端点，未配置时默认不构造模型端口。[当前模型适配器的默认与范围 ↗](../../../apps/server/src/code/understanding-model.ts#L1 "支持评审模式默认不硬接模型，以及当前适配器面向 ACP、CLI 和显式 HTTP 端点。") 生成函数本身接收结构化 port；未注入 port 时直接返回 unavailable，没有快照时直接返回 failed，这两种前置失败均不分配有效理解记录。[模型端口或快照缺失时的生成行为 ↗](../../../apps/server/src/code/understanding-store.ts#L674 "支持未注入端口或没有当前快照时直接返回，且 understandingId 为空、不会进入失败记录持久化流程。") 只有进入已建立结果标识的生成流程后，预取消、未知目标、预算超限、传输异常、合同或引用范围失败等才会持久化为 failed/rejected；这些记录不会进入默认当前读取面。流程还执行输入输出预算、取消超时、JSON 合同、引用范围及 head 移动栅栏检查。[模型生成的预算、验证与提交栅栏 ↗](../../../apps/server/src/code/understanding-store.ts#L709 "支持已进入生成流程后的失败留痕、目标范围、预算、取消超时、合同校验、引用范围及 head 移动检查。")

严格合同区分 raw fact 与 interpretation，并以独立 verifier 标志决定能否称为 verified；结构和交叉引用校验不等于语义复核。[严格理解状态与独立复核合同 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L216 "支持 raw fact 与 interpretation 的区分，以及 generated、verified 和独立 verifier 标志的语义。") 当前成功、非 seed、未过期且属于当前快照的模型结果可导出为版本化 JSON，包含依赖摘要和稳定符号定位器。[当前模型理解的版本化导出 ↗](../../../apps/server/src/code/artifacts.ts#L38 "支持导出门槛、依赖清单、稳定节点定位器和 JSON 文件写出。") 恢复时比较依赖摘要、重绑定当前符号并重新验证；来源变化记 stale，定位或合同失败记 rejected，恢复记录仍明确标注未经独立语义复核。[生成理解产物的可信恢复 ↗](../../../apps/server/src/code/artifacts.ts#L63 "支持依赖摘要比较、定位器重绑定、严格验证、事务写入以及未经独立语义复核的声明。")

<a id="progress_limits"></a>
## 已串联环节、限制与被替代结论

固定材料能够证明源码已串联固定文本读取、确定性解析、逐快照历史、状态化关系、人读 DTO、seed 投影、可选模型生成及产物恢复，但不能替代真实退出码、行为测试或浏览器验收。解析仍缺少跨文件类型语义，调用者上下文对类方法、箭头函数和嵌套结构也不完整。[离线 TypeScript 与 Vue 解析边界 ↗](../../../apps/server/src/code/parse.ts#L1 "支持单文件 AST、Vue SFC、保守正则、名称级候选调用及位置合同，并解释跨文件语义限制。")

符号表以符号 ID 与快照 ID 为联合身份，但 `symbolById` 只按符号 ID 查询；同一稳定符号跨快照存在时，返回的范围、签名和 Fragment 未被明确限定。[未限定快照的符号查询 ↗](../../../apps/server/src/code/store.ts#L559 "支持符号可按快照列举，但 symbolById 仅按符号 ID 查询的边界。") `sync({ only })` 当前忽略参数并执行全量同步，不能当作已实现的选择性刷新。[当前同步入口忽略 only ↗](../../../apps/server/src/code/sync.ts#L147 "支持公开同步入口虽接受 only 参数，实际仍直接执行全量同步。")

一致性风险需限定在新生成模型结果：主记录及旧模型失效在事务内完成，规范化引用镜像随后在事务外写入，中断可能留下可见主记录但引用侧表不完整。[新生成结果与引用镜像的事务边界 ↗](../../../apps/server/src/code/understanding-store.ts#L894 "支持新模型主记录在事务内提交，而规范化引用镜像随后在事务外写入。") 恢复路径则在一个事务中写入主记录和引用，不能与该风险混为一谈。[生成理解产物的可信恢复 ↗](../../../apps/server/src/code/artifacts.ts#L63 "支持依赖摘要比较、定位器重绑定、严格验证、事务写入以及未经独立语义复核的声明。") 本次修订由此替代了“同步已保存文本副本”“所有导入均可确认”和“所有生成失败都会形成记录”等范围过宽的结论；统一证据链、逐快照历史、候选关系及派生知识不等于原始证据等认识继续保留。[统一 SQLite 与确定性代码身份 ↗](../../../apps/server/src/code/store.ts#L1 "支持代码侧表属于统一存储上的派生视图，以及文件、符号、边和快照的稳定身份规则。")[人工 seed 定位、校验与持久化 ↗](../../../apps/server/src/code/understanding-store.ts#L281 "支持定位或证据失败保存 rejected、成功 seed 与引用写入，以及历史结果保留语义。")
