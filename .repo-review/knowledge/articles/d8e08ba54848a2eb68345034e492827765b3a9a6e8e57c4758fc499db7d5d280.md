# code · 模块理解

code 模块把 Capture 中的固定源码修订转换为可重建、可追溯的代码快照与结构图，并在其上投影人工或模型生成的模块理解；其核心约束是保留历史、区分确定事实与候选关系、让派生知识始终回指原始材料。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责与设计背景

该模块不是另一套事实库，而是 Capture→Source/Revision/Fragment 权威链上的代码视图：同步从固定 head 修订读取源码，生成文件、符号、关系和快照，再供 DTO、理解结果与知识产物使用。[代码同步流程 ↗](77a2bfa010fcb7c75cfc06e221def951343d041b819f5adf30ede8d0dcd8a178.md#input_snapshot "支持 code 模块从 Capture 固定修订读取源码并形成代码知识快照的总体职责。")[固定 Capture 修订输入 ↗](../../../apps/server/src/code/sync.ts#L152 "直接证明同步读取 sources.head 指向的修订正文，并限定纳入分析的文件范围。") 文件、符号、边和快照采用确定性身份；符号范围归属于具体快照，复合主键与显式 head 使旧状态可读，也避免工作树回到旧内容时误把捕获时间当作当前状态。[代码知识存储模型 ↗](6d7798d48631440ff518a72a9b36c01b933e3d320d2f8aedc0497fe75c3f37a9.md#model "解释确定性身份、快照历史、显式 head 与图读取之间的关系。")[显式当前快照指针 ↗](../../../apps/server/src/code/store.ts#L273 "支持不能按 captured_at 推断当前状态，以及同步必须显式切换 head 的论断。")

<a id="pipeline"></a>
## 从源码到可浏览代码图

解析层以 TypeScript AST 提取声明、导入和名称级调用，并专门处理 Vue SFC；路由与测试只由保守正则识别。[离线结构解析器 ↗](c33bf6dd869d6d14492edb191c8bcd75164a8c834233aaa62a01843588388516.md#pipeline "概括 TypeScript AST、Vue SFC 和保守正则各自承担的解析职责与边界。") 同步层把解析结果绑定到固定修订和声明 fragment：导入仅在捕获文件集合内解析，未解析目标记为 missing；调用只做同文件名称匹配且标为 candidate，不能视作跨文件调用证明。[关系投影规则 ↗](../../../apps/server/src/code/sync.ts#L291 "直接支持导入、同文件候选调用、路由、测试和 Vue 组件关系的状态判定。")[名称级调用收集 ↗](../../../apps/server/src/code/parse.ts#L167 "说明调用仅保留简单被调用名称和有限调用者上下文，不能证明跨文件真实调用。") 面向界面时，DTO 保留路由所需内部键，但增加人类标题、路径、引用标签及不可操作原因，避免直接展示内部标识。[人类可读 DTO 投影 ↗](e58e44f85e38e3c9472965c7bc3f115d20bfc2e5a405e76a24b08f76ed0be160.md#projection "支持保留内部动作键、增加展示字段，并为 missing 或 stale 对象提供不可操作原因。")

<a id="understanding"></a>
## 派生理解、校验与恢复

代码理解层把当前图、固定源码证据和人工 seed 投影为严格合同；locator、证据文件或引用提示无法解析时会保存 rejected 结果，而不是静默丢失引用或覆盖已有好结果。[理解结果投影与校验 ↗](b3371593c4922018b730c855f682b8fe880f0633812ad1d353f218a718c4abc2.md#projection "解释人工 seed、固定证据、严格合同以及派生结果不改写原始代码图的边界。")[定位失败的拒绝持久化 ↗](../../../apps/server/src/code/understanding-store.ts#L304 "直接支持 locator、证据或提示解析失败会形成 rejected 记录而非静默丢弃。") 可选模型生成会先限定目标范围并检查输入、输出、超时和取消预算；服务端封装 provenance，校验引用确实曾展示给模型，并在提交前确认 head 未移动。[可选模型生成防线 ↗](b3371593c4922018b730c855f682b8fe880f0633812ad1d353f218a718c4abc2.md#generation "支持目标裁剪、预算、中止、引用范围校验与 head 移动防线的完整生成流程。") 成功模型结果还可导出为带依赖哈希和稳定 locator 的版本化产物；恢复时依赖变化标 stale，定位或合同失败标 rejected，且派生产物不会被重新当作独立原始证据。[代码理解产物恢复 ↗](6cec8ff9441999507ac0cd70efdd0459bb4722ffa6ca135373be067b0e44501e.md#restore "解释生成结果如何通过依赖摘要、稳定 locator 和严格合同在新快照中恢复。")[产物重绑定与事务恢复 ↗](../../../apps/server/src/code/artifacts.ts#L87 "直接支持仅重绑定已校验引用、保留原生成信息并写入规范化引用表的论断。")

<a id="progress_limits"></a>
## 当前进展与限制

现有实现已覆盖固定修订同步、历史快照、结构图、人类可读 DTO、人工 seed、显式模型生成及产物恢复；失败或过期结果均不会晋升为当前理解。主要边界仍是单仓 PoC，仓库标识固定为 `omem`；理解快照也诚实地使用空调用边集，因为当前调用信息不足以形成已确认的符号关系。[固定单仓标识 ↗](../../../apps/server/src/code/store.ts#L40 "直接证明当前仓库标识固定为 omem，属于单仓 PoC 边界。")[空调用边的明确依据 ↗](../../../apps/server/src/code/understanding-store.ts#L262 "直接说明当前名称级调用不足以形成确认的符号间关系，因此理解快照使用空边集。") 此外，模型端口虽默认关闭并要求宿主显式选择 transport，但缺少真实模型名时会回退为 `acp`、`cli` 或 `http`，与文件头所声明的模型身份 provenance 规则存在冲突。[显式配置的模型端口 ↗](b0bb42649ce074381a811835d4b466488349bd7140ccf93724cea568f78d76bf.md#http_boundary "解释模型默认关闭、由宿主选择 transport，以及当前模型身份回退存在的 provenance 缺陷。")[模型身份声明 ↗](../../../apps/server/src/code/understanding-model.ts#L11 "直接给出模型 ID 应来自 transport 响应或显式配置的声明，用于对照当前 transport 标签回退行为。")
