# code · 模块理解

代码知识模块把 Capture 中的固定源码修订投影为按解析器版本区分、可追溯的快照化代码图，并在图上管理人工或模型生成的理解；当前仍受全量同步、单文件名称级解析、查询语义和模型传输预算差异限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 职责与数据边界

该模块不建立第二套源码事实库，而把 Capture→Source/Revision/Fragment 投影为文件、符号、关系和快照侧表；稳定标识便于跨解析定位，符号与关系则按快照保存。[代码图投影与稳定身份 ↗](../../../apps/server/src/code/store.ts#L1 "支持代码侧表依附 Capture 链、稳定标识及按快照保存结构记录的架构说明。") 此处替代此前“新解析未重现的历史关系都会变为 stale”的宽泛结论：stale 对账只修改本轮目标快照内未重现或触及已删除文件的关系，其他快照的关系保持原状态。[本轮快照内的关系失效 ↗](../../../apps/server/src/code/store.ts#L863 "支持 stale 对账仅修改指定快照、其他历史快照关系保持不变的修正结论。")

DTO 保留内部动作键用于路由，同时补充人类可读标题、路径、引用标签和深链。不可操作状态目前只明确覆盖 removed 文件及 missing/stale 关系；符号 DTO 始终可操作，因此不能再泛称所有 missing/stale 对象都已统一处理。[文件、符号与关系展示状态 ↗](../../../apps/server/src/code/dto.ts#L35 "支持 removed 文件和 missing/stale 关系不可操作，同时符号始终可操作的精确 DTO 边界。")

<a id="sync-flow"></a>
## 从固定修订到代码快照

同步从 Capture 当前 head revision 读取固定文本，Git 只补充提交、分支、远端和 dirty 元数据。快照身份实际由解析器版本、仓库、提交、dirty 状态及排序后的捕获内容哈希共同决定；解析器版本变化也会产生不同快照，这补全了此前遗漏版本因素的枚举。[包含解析器版本的快照身份 ↗](../../../apps/server/src/code/store.ts#L34 "支持解析器版本、仓库、提交、dirty 状态及内容哈希共同进入快照标识。") 相同身份可复用旧快照，但仍重新执行当前文件、关系和理解状态的对账；公开 `sync` 虽接受 `only`，当前实现没有消费它，实际仍是全量同步。[同步入口与快照复用 ↗](../../../apps/server/src/code/sync.ts#L147 "支持 only 参数当前未使用、同步读取固定 Capture head，并在复用快照后继续对账。")

解析使用 TypeScript 单文件 AST、Vue SFC 编译器和保守正则，不建立跨文件类型程序。[离线解析精度边界 ↗](../../../apps/server/src/code/parse.ts#L1 "支持单文件 TypeScript AST、Vue SFC、保守正则及名称级候选调用的限制。") 投影会固定文件 revision、写入符号，并生成 confirmed 的定义边、可解析或 missing 的导入边以及同文件名称匹配的 candidate 调用边。[文件、符号与基础关系投影 ↗](../../../apps/server/src/code/sync.ts#L220 "支持固定 revision、符号写入以及定义、导入和同文件调用关系的生成状态。") 路由、测试和 Vue 组件线索写入后，流程标记删除文件，在本轮目标快照内对账 stale 关系，切换显式 head，再投影人工 seed 并恢复可校验产物。[特殊结构与同步收尾 ↗](../../../apps/server/src/code/sync.ts#L332 "支持路由、测试、Vue 组件线索以及删除、stale 对账、head 切换和理解恢复流程。")

<a id="understanding"></a>
## 人工与模型理解的可信流程

人工 seed 的证据必须来自固定快照正文；节点定位器、证据文件或证据别名无法解析时会保存 rejected 记录，而不是静默删引。通过合同的 seed 明确为低置信度、无模型且未独立验证，先前有效结果保留为历史并标记 stale。[人工 seed 定位与持久化 ↗](../../../apps/server/src/code/understanding-store.ts#L213 "支持固定证据解析、定位失败拒绝、低置信度 seed 属性及旧结果转为历史。")

模型默认关闭，只有宿主显式配置 ACP、CLI 或 HTTP 才建立端口，适配器本身不读取凭据或主动推理。[模型端口默认关闭 ↗](../../../apps/server/src/code/understanding-model.ts#L1 "支持模型仅由宿主显式启用，且适配器不读取秘密或自行发起推理。") 生成时按目标路径限制文件与可见符号，检查输入和最终输出预算，处理取消、超时、引用范围及运行期间 head 移动。[生成范围、预算与提交栅栏 ↗](../../../apps/server/src/code/understanding-store.ts#L741 "支持目标范围、预算检查、取消超时、引用可见性及 head 移动防护。") 当前成功结果可导出为带依赖摘要和稳定定位器的 JSON；恢复会重新核对依赖、范围、定位器和合同，但明确不等于重新生成或独立语义复核。[生成理解的导出与恢复 ↗](../../../apps/server/src/code/artifacts.ts#L38 "支持当前结果的导出条件、依赖摘要、精确定位器恢复及未独立语义复核的限制。")

<a id="status-limits"></a>
## 当前能力与未收敛限制

当前或指定历史快照可分别查询符号、关系和整图；历史视图保留当时文件，当前视图隐藏 removed 文件，并默认过滤 stale 关系。[当前与历史快照查询 ↗](../../../apps/server/src/code/store.ts#L541 "支持按当前或指定快照查询符号和图、历史文件展示及 stale 关系过滤。") 但 `symbolById` 只按稳定符号标识查询，没有限定或排序快照，多版本并存时返回语义尚不确定。

名称级调用不能证明跨文件或动态分派目标，测试边目前指回测试文件，Vue 组件使用边也没有解析目标。[离线解析精度边界 ↗](../../../apps/server/src/code/parse.ts#L1 "支持单文件 TypeScript AST、Vue SFC、保守正则及名称级候选调用的限制。")[特殊结构与同步收尾 ↗](../../../apps/server/src/code/sync.ts#L332 "支持路由、测试、Vue 组件线索以及删除、stale 对账、head 切换和理解恢复流程。") 模型传输能力同样不完全一致：ACP 会消费并下传请求预算，而 CLI 与 HTTP 分支未接收该预算。[各模型传输的预算差异 ↗](../../../apps/server/src/code/understanding-model.ts#L80 "支持 ACP 消费请求预算，而 CLI 与 HTTP 运行分支未接收该预算的能力差异。") 因而“已入库”只表示结构或派生结果完成持久化，不能视为候选关系已经语义确认，也不能宣称各传输具有等价预算保证。
