# 代码评审模型配置

该文件声明代码评审生成任务通过 ACP 启动 traex 服务，选用 gpt-5.6-sol 与 medium 推理强度，并设置超时、输入输出令牌及上下文预留预算。它描述的是期望运行配置，本身不能证明命令已成功启动、模型能力已被运行时接受或评审流程已经执行。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="transport_model"></a>
## 传输方式与模型选择

配置采用 `acp` 传输，由 `traex -c sandbox_mode="read-only" acp serve` 启动服务，并把评审模型指定为 `gpt-5.6-sol`。只读沙箱体现了生成过程不应直接改写工作区的运行边界；但该文件只是静态声明，无法单独证明本机存在对应命令、ACP 握手成功，或服务端确实支持所选模型。[ACP 传输与评审模型配置 ↗](../../../config/review-code-model.json#L2 "支持附近关于 traex 启动参数、只读沙箱、ACP 传输方式及 gpt-5.6-sol 模型选择的说明。")

<a id="runtime_budget"></a>
## 运行预算与上下文边界

单次调用超时设置为 480000 毫秒，最大输入为 192000 tokens，最大输出为 24000 tokens，并额外预留 16000 tokens 上下文空间；推理强度配置为 `medium`。这些数值共同约束长代码材料的装载、生成篇幅和调用时长，但材料没有说明超限时的截断策略、重试机制，也没有提供真实运行 trace，因此不能据此认定配置已通过能力校验或在生产流程中生效。[推理强度与调用预算 ↗](../../../config/review-code-model.json#L11 "支持附近关于 medium 推理强度、超时、输入输出令牌上限和上下文预留值的说明。")
