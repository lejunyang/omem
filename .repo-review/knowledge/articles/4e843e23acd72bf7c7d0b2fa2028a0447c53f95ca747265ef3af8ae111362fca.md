# 仓库知识模型实际配置

当前实际配置以只读 TraeX ACP 运行 gpt-5.6-sol/medium，并设置较大的输入预算和独立输出、预留额度；状态文档确认生成与 review 服务默认读取此文件。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="active-runtime"></a>
## 当前运行合同

实际配置指定 ACP 传输及 `traex` 命令，并用只读沙箱参数启动服务；选定模型为 `gpt-5.6-sol`、effort 为 `medium`。[实际 ACP 模型选择 ↗](../../../config/review-code-model.json#L1 "支持当前实际文件采用只读 TraeX ACP、gpt-5.6-sol 和 medium effort。") 与示例文件内容一致并不意味着两者地位相同：状态文档明确说生成及 review 服务默认读取本文件，只有环境变量可覆盖，因此它才是仓库评审流程的默认模型入口。[默认模型配置来源 ↗](../../../docs/implementation/status.md#L11 "确认生成和 review 服务默认读取实际配置文件，而非示例或个人 Agent profile。")

<a id="capacity-and-evidence"></a>
## 容量设置与验证口径

配置将超时设为 480000 毫秒，输入上限 192000、输出上限 24000，并保留 16000 tokens 的上下文空间。[实际模型预算 ↗](../../../config/review-code-model.json#L12 "支持超时、输入输出上限和上下文预留的具体数值。") 这些预算支持较长材料分析，但仍应在运行 trace 中记录实际模型、快照、范围和失败结果。状态记录表明真实 gpt-5.6-sol 已用于来源更新闭环验证；这证明特定流程在当次环境中跑通，不应外推为所有知识、助手或外部集成都已验收。[来源更新真实模型验证 ↗](../../../docs/implementation/status.md#L3 "说明真实模型验证覆盖的具体闭环，并帮助限制结论外推范围。")
