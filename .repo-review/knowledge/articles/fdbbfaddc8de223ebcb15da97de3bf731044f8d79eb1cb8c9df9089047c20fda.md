# 问题背景、研究取舍与历史演进

omem 从可核对的不可变证据出发，坚持本地优先与可替换检索，并在早期采用 Agent CLI/ACP 作为模型接入方向；产品由离线原型、Batch 2 工程底座演进到主助手与渐进记忆。研究建议、历史方案和演示均不等同于当前实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="why"></a>
## 为何以证据与本地边界为起点

omem 要让结论在材料更新后仍可回到当时原文，因此材料按不可变 revision 切片，引用固定 fragment；目前跨 revision 身份续接尚未实现，会留下历史断点。[不可变引用与本地优先约束 ↗](../../../docs/research/code-wiki-landscape.md#L5 "支持固定 revision、固定 fragment、跨版本身份续接缺口、关键词检索现状及本地模型边界。") 未来续接的验收原则是误接率低于门槛，匹配失败时宁可保留为历史版本，也不错误连接证据。[跨版本续接的保守验收原则 ↗](../../../docs/research/code-wiki-landscape.md#L285 "直接支持跨 revision 匹配失败时保留历史版本、宁可断开不可错接的治理选择。") 渐进记忆把 Evidence、派生索引、工作上下文和正式知识视为并存层次，中间摘要始终是 derived，不成为新的独立证据。[主助手与渐进记忆的信息分层 ↗](80a42c56937c7b3ed2983bb792ce92442174d94a7f50e7d2a1d00916bce7b17b.md#flow "链接相关子知识，解释原件、派生索引、工作上下文与正式知识为何并存。")

本地优先服务于隐私和可运维性，不要求 SaaS，模型端点可以在本机。早期材料明确选择个人助理、服务器或本地运行、Vue 与 CLI/ACP 优先；这是一项接入方向，而不是外部模型已经验证可用的证明。[CLI/ACP 优先的阶段性选择 ↗](../../../docs/research.md#L3 "直接支持个人助理、服务器或本地运行、Vue 与 CLI/ACP 优先是已确认的早期方向。") 工程上模型只产生结构化建议，权限、并发、证据版本和事实提交仍由领域服务掌握，fixture 与真实 CLI/ACP 验证必须分级记录。[Batch 2 的模型与交付边界 ↗](../../../docs/implementation/batch2/README.md#L40 "支持模型只产结构化建议、领域服务负责治理，以及 fixture 与真实 CLI/ACP 验证分级。")

<a id="retrieval"></a>
## 为何检索能力必须可替换

早期研究提出“统一证据与记忆内核 + 可替换检索/学习引擎”：核心数据模型和阅读界面不随 WeKnora、Hindsight 或其他后端更换，系统自持版本引用、变更语义、自治风险与结果验证。[自治记忆与检索组件复用研究 ↗](ee168961c9fafa031cdaba5bdb9a55d445a3b911c4384ac4c4f152f254bb86ac.md#core-strategy "链接早期研究子知识，解释统一证据内核与可替换检索、学习引擎的总体取舍。") 后续薄适配器方案把权威原件留在 omem，sidecar 仅保存可重建投影；搜索返回候选后再回查固定原件、有效性和范围，移除后端时仍可降级到关键词检索。[检索 sidecar 的薄适配器方案 ↗](../../../docs/research/mempalace/README.md#L77 "支持权威原件留在 omem、候选回查、关键词降级和索引 generation 回退。")

完整平台常重复数据库、UI 与模型编排，生成的 Wiki 散文若没有 fragment 回链也可能被误当证据。因此研究倾向复用 SCIP、Tree-sitter、repo-map 等协议或算法，而非整体引入平台。[代码知识组件复用决策 ↗](../../../docs/research/code-wiki-landscape.md#L13 "支持复用协议与算法而不整体引入完整平台，并说明缺少固定证据回链的风险。") 早期 WeKnora、Hindsight 首选只是待 PoC 验证的历史建议，不能表述为已完成生产选型。[早期研究与 CLI/ACP 方向的事实边界 ↗](../../../docs/research.md#L3 "支持 CLI/ACP 优先的阶段性方向，并证明研究未部署候选引擎或复现性能基准。")

<a id="evolution"></a>
## 从离线原型到渐进记忆

第一阶段主要是研究与离线交互验证：固定提交下核验资料、许可证和部分源码，但没有部署候选引擎或复现性能基准。[早期研究与 CLI/ACP 方向的事实边界 ↗](../../../docs/research.md#L3 "支持 CLI/ACP 优先的阶段性方向，并证明研究未部署候选引擎或复现性能基准。") 单文件原型演示递归引用、版本比较、局部追问和异常来源，却未连接真实模型、数据库、数据源或后台任务。[离线原型的非生产限制 ↗](../../../docs/prototype/README.md#L18 "支持原型未连接真实模型、数据源、数据库、记忆引擎或后台任务。") 相关子知识可用于下钻证据阅读流程，但只能作为交互思想和历史验证记录。[可追溯知识交互的离线原型 ↗](9c86be659ffe238413d8fab296ee85a9d95072d8f2723190c4396d5ca80d66aa.md#workflow "链接原型子知识，供读者下钻其递归证据阅读、问答和历史演示流程。")

Batch 2 随后形成合同、持久任务、角色运行时、飞书与 Vue 等工程底座；专项审查认为其仍不能作为个人超级助理验收，且“尽早提炼 claim、遇到不确定就询问”的路径造成过度打扰。[Batch 2 审查结论 ↗](../../../docs/reviews/2026-09-27-batch2/README.md#L1 "支持工程底座已有实现但尚不能作为个人超级助理验收，以及旧提炼确认策略需要调整。") 这一旧结论已被 v3 路线替代：保留数据、事务、任务、ACP、飞书和 UI 基础设施，改由主助手先理解目的，以使用、任务或变化触发整理，只在真实选择或高影响动作上询问。[Batch 2 历史状态与目标更替 ↗](b66e4cfbeb480806a83508dcf928e7cdcc6d94a899fc99732a0f929923c7dbbd.md#status "链接实施历史子知识，说明旧逐句确认路径已被 v3 替换，历史完成度不能替代当前代码证据。")[入口与策略层的调整方向 ↗](../../../docs/reviews/2026-09-27-batch2/README.md#L109 "支持保留基础设施、重做主助手入口与整理触发策略，并只就真实选择询问用户。")

<a id="progress-limits"></a>
## 当前进展与解释边界

当前状态记录了主助手路由、持久 turn、关键词检索、治理门控、输入保真与本地测试，ACP 适配器也已连接实际传输；但语义检索、跨版本 fragment 续接和 MemPalace sidecar仍未完成，真实 ACP 主助手及真实飞书 WebSocket 端到端也尚未 live 验证。[当前能力与剩余缺口 ↗](../../../docs/implementation/status.md#L45 "支持当前主助手、关键词检索和治理进展，同时限定语义检索、跨版本身份、sidecar及真实外部端到端验证尚未完成。")

因此，研究材料回答“为何这样设计”，原型展示“希望怎样交互”，Batch 2 与 v3说明“策略怎样演变”；只有状态页及相应验证工件能说明当前能力。检索路线还必须在冻结的脱敏中文语料上同口径比较，并通过候选回查、更新过滤、断网运行和索引可重建等硬门，才能从研究优先级转为采用决定。[本地检索 PoC 的明确决策门 ↗](../../../docs/research/mempalace/README.md#L92 "支持冻结中文语料的同口径比较，以及证据映射、更新过滤、离线、可控性和可重建运维等硬门。")
