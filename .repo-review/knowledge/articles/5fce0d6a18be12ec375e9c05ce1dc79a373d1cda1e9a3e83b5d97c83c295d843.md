# 生成预算估算与校验

为角色运行提供可解释但非模型精确的 token 估算，并合并输入、输出与上下文预留限制；网关和 ACP 在不同阶段执行这些限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 估算方法与适用边界

该模块不调用模型专属 tokenizer，而按 UTF-8 字节数除以 3 估算 token，再增加 25% 余量。结果保留字符数、字节数、原始估算和计费估算，便于追踪超限原因；它适合代码与中日韩混合文本的保守预算，但不能替代模型的精确分词结果。[启发式 token 估算 ↗](../../../apps/server/src/agent-runtime/budget.ts#L1 "支持 UTF-8 字节估算公式、25% 余量和返回的诊断字段。")

<a id="configuration"></a>
## 预算合并与参数校验

`generationBudget` 优先采用调用方覆盖值，否则读取角色清单中的上下文和输出上限；上下文预留默认是 16000。三个值都必须是 1 至 1,000,000 的安全整数，非法配置会在进入模型调用前失败。[生成预算配置 ↗](../../../apps/server/src/agent-runtime/budget.ts#L9 "支持覆盖优先级、默认上下文预留及整数范围校验。")

<a id="enforcement"></a>
## 运行时执行位置

网关对每次初始或修复提示重新估算文本输入，超出 `maxInputTokens` 时拒绝运行，并在收到完整输出后检查 `maxOutputTokens`。[网关输入与输出预算检查 ↗](../../../apps/server/src/agent-runtime/gateway.ts#L302 "支持网关在每次提示渲染后检查输入估算，并在模型返回后检查输出估算。") ACP 路径还会把估算输入、最大输出及预留量相加；仅当模型配置暴露有效的上下文窗口元数据时，才据此执行总窗口校验，缺少元数据时不会作该项判断。[ACP 模型上下文窗口校验 ↗](../../../apps/server/src/agents.ts#L74 "支持仅在发现有效模型上下文窗口时，将输入、输出和预留之和与其比较。")
