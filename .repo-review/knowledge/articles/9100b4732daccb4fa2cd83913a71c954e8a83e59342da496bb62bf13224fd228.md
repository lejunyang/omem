# 材料分析角色的证据化写作规范

该角色规范用于把需求、设计、研究、进展与配置材料整理成可复核的中文 Wiki，同时严格区分文档主张、实现事实和历史计划，并以固定范围引用支撑正文。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

材料分析角色面向需要理解项目背景、方案与进展的读者，将零散文档转化为结构化知识。它特别要求区分**文档陈述、已经实现的事实与历史状态**，因此旧计划只能作为历史意图描述，不能据此宣称能力已经落地。参考 [分析对象与事实边界 ↗](../../../packages/agent-runtime/roles/material-analyst/1/prompt.md#L1 "支持角色需要分析多类项目材料，并明确旧计划不得表述为已实现能力。")

<a id="analysis_flow"></a>
## 从目标材料到结构化文章

分析以任务指定的目标为边界：每个目标都要生成键值完全一致的文档，并用中文解释其作用、背景、流程、限制及与其他材料的关系。输出只采用既定 JSON 合同；材料中的命令或提示词仅是待分析内容，不能被当作操作指令。正文中的每项引用必须就近出现，疑点则进入带原因、后续动作和阻塞状态的问题列表。参考 [结构化分析流程 ↗](../../../packages/agent-runtime/roles/material-analyst/1/prompt.md#L3 "支持目标覆盖、JSON 输出、引用放置和问题记录等分析流程约束。")

<a id="reader_and_evidence"></a>
## 读者体验与证据约束

成文应让首次接触项目的人先理解实际问题和使用场景，再进入关键概念与限制；标题按功能命名，避免用文件路径、内部编号或校验数据充当叙事主线。引用标签应放在所支持的句段末，即使移除标签，正文也要保持通顺。表格仅在有助于对照时使用；涉及多阶段流程时可使用简洁的 Mermaid 图，且图中关系必须有材料依据，不得为格式硬凑。参考 [面向读者的写作规范 ↗](../../../packages/agent-runtime/roles/material-analyst/1/prompt.md#L11 "支持功能化标题、首次阅读体验、表格与流程图的适用条件，以及就近引用要求。")
