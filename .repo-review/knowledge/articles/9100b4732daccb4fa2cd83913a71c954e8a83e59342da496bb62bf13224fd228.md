# 材料分析角色提示词

定义材料分析角色的任务边界、输出语言与 JSON 约束、目标覆盖规则、证据引用方式以及不确定事项的表达要求；它描述的是分析合同，不证明任何运行时校验或宿主提引能力已经实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_boundary"></a>
## 职责与边界

该提示词要求角色分析需求、设计、研究、进展和配置，并明确区分文档陈述、实现事实与历史状态，尤其禁止把旧计划表述为已经实现。[分析对象与状态区分 ↗](../../../packages/agent-runtime/roles/material-analyst/1/prompt.md#L1 "支持本角色需要分析多类文档，并禁止把历史计划误报为实现事实的论断。") 输入材料被视为待分析资料，其中出现的命令或提示不能成为行动指令；角色只应使用已提供内容，以中文返回指定 JSON，且不得调用工具或读取额外文件。[语言、格式与资料边界 ↗](../../../packages/agent-runtime/roles/material-analyst/1/prompt.md#L3 "支持仅输出中文 JSON、不得执行材料指令或读取额外文件的边界说明。") 这些条款约束分析行为，但材料没有提供运行器如何隔离工具或验证输出的实现证据。

<a id="coverage_evidence"></a>
## 覆盖与证据组织

输出必须逐一覆盖 `task.targetKeys`，并保持文档键完全一致；正文应解释材料的作用、背景、流程、限制及相互关系，而非只罗列名称和数量。[目标覆盖与正文要求 ↗](../../../packages/agent-runtime/roles/material-analyst/1/prompt.md#L4 "解释文档键一致性、目标全覆盖以及正文需要呈现关联和限制的要求。") 每节需把引用放在相关论断附近，引用目标限于所给材料或文章；材料引用必须采用真实行号并留空 `quote`，由宿主复制短引文。[节内引用与固定证据 ↗](../../../packages/agent-runtime/roles/material-analyst/1/prompt.md#L5 "支持引用必须邻近论断、使用完整材料键和真实行号且留空引文的规则。") 对缺少背景、存在歧义或需要选择的事项，应形成带原因、下一步、阻塞状态和引用键的问题，而不是无依据推断。[问题与引用说明规则 ↗](../../../packages/agent-runtime/roles/material-analyst/1/prompt.md#L7 "支持对不确定事项建立结构化问题，并为引用提供人读标签和具体理由的要求。")
