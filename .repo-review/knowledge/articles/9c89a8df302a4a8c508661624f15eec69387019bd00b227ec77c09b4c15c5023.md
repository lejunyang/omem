# Lark 决策卡回调核验与异步执行

把 Lark 卡片点击转换为带租约的决策命令，在入队时绑定应用、操作者、会话、消息、nonce、摘要与版本，执行后更新原卡片并按错误性质重试或停用连接。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="validation_and_enqueue"></a>
## 回调真实性与一次性消费

服务先把卡片事件写入统一收件箱，再解析严格的决议回调结构。事务中联查动作、决策、绑定和连接，核对应用、操作者、聊天、消息、提案摘要、有效期、nonce 摘要及预期版本摘要，并要求动作和决策仍待处理。验证成功后以条件更新消费动作并创建 queued 命令，重复或失效点击不会再次入队。[卡片动作联合校验与消费 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L119 "支持事件去重、上下文与摘要联合核验、条件消费及命令入队。")

<a id="lease_and_business_flow"></a>
## 租约领取与业务执行

工作器可领取 queued、到期 retry_wait 或租约过期的 processing 命令；领取时生成随机租约令牌、递增尝试次数并设置到期时间，完成写回必须匹配当前令牌，从而阻止旧工作器覆盖新结果。重试采用有上限的指数退避。[命令租约与完成保护 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L240 "支持可领取状态、租约令牌、尝试次数、指数退避和旧租约拒绝。") 执行阶段调用记忆决策服务，以稳定请求号关联卡片命令，再读取并核对应用密钥，通过消息适配器更新原卡片。[决策执行与卡片更新 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L355 "支持调用记忆决策服务、核对密钥所属应用并更新原卡片。")

<a id="failure_boundaries"></a>
## 失败分类与安全边界

陈旧、已解决、摘要不符或操作者不符属于终止性业务错误，服务会尽力把实际决策状态更新到卡片。普通失败最多尝试五次；投递错误中仅限流和结果不确定可重试，认证错误会禁用目标并把连接置为失败。错误信息会脱敏、移除换行并截断；业务决策成功而卡片更新失败时，两侧状态仍分别保存。[终止错误、重试与认证失效 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L388 "支持终止性业务错误处理、五次尝试上限、可重试错误分类及认证失败后的停用。")
