# 飞书决策卡片动作的校验、排队与执行

该模块把飞书/Lark 卡片回调转换为一次性、可租约重试的决策命令：入口校验回调和数据库快照，后台调用记忆决策并更新原卡片，同时防护重复消费、过期请求、陈旧租约、凭据失效及敏感错误泄漏。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-and-ingress"></a>
## 入口协议与一次性消费

卡片按钮不是可直接信任的业务命令。回调值必须符合固定协议，携带动作、卡片动作标识、nonce、提案摘要、过期时间和预期版本摘要，并拒绝未知字段。[卡片回调值协议 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L13 "支持回调动作、nonce、摘要、期限和预期版本摘要必须通过严格结构校验的论断。") 卡片动作属于统一的 Lark 入站事件，事件合同同时提供应用、操作者、会话和消息上下文。[Lark 入站事件合同 ↗](../../../apps/server/src/integrations/lark/realtime.ts#L15 "说明卡片动作属于统一入站事件，并携带应用、操作者、会话和消息上下文。")

入队时，服务先持久化事件并识别重复投递，再在事务内联结动作、决策、绑定和连接，核对应用与连接状态、操作者、消息位置、摘要、期限、nonce、预期版本及决策状态。校验成功后，以条件更新将动作从 pending 改为 consumed，创建 queued 命令并完成 inbox，限制重复点击和并发消费。[动作校验与事务入队 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L119 "支持数据库快照校验、一次性消费、命令创建及 inbox 完成的事务流程。") 其中摘要采用键排序、忽略 undefined 的规范化 JSON 后计算 SHA-256，避免对象键顺序造成差异。[稳定摘要算法 ↗](../../../apps/server/src/storage/digest.ts#L3 "解释预期版本和 nonce 校验依赖的规范化 JSON 与 SHA-256 摘要。")

<a id="worker-flow"></a>
## 租约执行与外部协作

后台 worker 从 queued、到期的 retry_wait 或租约过期的 processing 命令中领取任务，递增尝试次数并写入 lease token；完成时必须仍持有该 token，否则拒绝陈旧 worker 写回。[命令租约与写回保护 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L240 "支持任务领取、租约过期重领、尝试计数及 lease token 防止陈旧写回的论断。")

取得租约后，服务以命令标识构造稳定 requestId，调用 `MemoryService.decide`，随后读取加密凭据、核对 appId，并更新原消息卡片。[决策执行与结果卡更新 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L355 "支持调用记忆决策、读取凭据、核对应用并更新原消息卡片的执行顺序。") 凭据库要求 32 字节主密钥，缺少环境配置会失败，目录权限限制为仅所有者访问。[加密凭据库初始化约束 ↗](../../../apps/server/src/integrations/lark/secret-store.ts#L24 "说明 Lark 凭据依赖 32 字节主密钥、环境配置和受限目录权限。") 但当前提供的 `MemoryService` 范围只有类型与辅助代码，未展示 `decide` 实现，因此不能据此确认跨进程重试的持久化幂等保证。

<a id="failure-boundaries"></a>
## 失败语义、重试与限制

错误信息会替换本次使用的密钥及常见令牌形态，并移除换行、限制长度。stale、已解决、摘要不匹配和 actor 不匹配属于终局业务错误；服务会尝试把数据库中的当前决策状态回写卡片。[终局业务错误回写 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L383 "支持敏感错误脱敏、终局业务错误识别及当前决策状态回写卡片的流程。")

旧结论“只有限流或结果不明确才重试，其他错误直接失败”已被替代。实际规则是：尝试次数少于五次时，`rate_limit`、`ambiguous` 以及所有非 `LarkDeliveryError` 普通异常都会进入指数退避重试；其他种类的确定性 `LarkDeliveryError` 或第五次失败直接终止。`auth` 错误还会禁用该连接的捕获目标并把连接标为 failed。[投递重试与认证失效 ↗](../../../apps/server/src/integrations/lark/card-actions.ts#L416 "纠正旧结论并支持普通异常同样重试、确定性投递错误不重试、五次上限及认证失败禁用连接的真实语义。") 业务决策与远端卡片更新并非原子操作，材料也未提供相应测试，故幂等与边界覆盖仍需另行核验。
