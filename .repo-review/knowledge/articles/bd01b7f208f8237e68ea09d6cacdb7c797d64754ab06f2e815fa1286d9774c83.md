# 系统概览与能力边界

omem 是以不可变原始证据为基础的个人助手：多类材料进入统一证据链；一般知识经材料分析、独立复核与不可变发布形成派生正文，明确任务和记忆则分别经过服务器意图复核、MemoryService 与 Attention Gate 治理。个人工作区与仓库 Wiki 共用固定引用和递归阅读机制。当前已有可运行闭环，但仍限于单用户 SQLite，语义检索、全面自动重核验、跨修订身份续接及真实外部端到端验收尚未完成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-context"></a>
## 要解决的问题与判断框架

omem 要解决的不是“再生成一份摘要”，而是让助手理解材料、支持行动，同时让结论始终能回到当时原文。系统以固定 Revision 和 Fragment 为证据锚点，坚持本地优先；当前检索仍是关键词基线，跨 Revision 身份续接与语义检索尚未实现。[Code Wiki 研究中的现行约束 ↗](../../../docs/research/code-wiki-landscape.md#L5 "支持固定修订与片段、关键词检索基线、本地优先，以及跨修订身份和语义检索尚未完成的概览判断。") 背景章节进一步解释本地与证据边界、可替换检索的取舍，以及产品从离线原型向渐进记忆演进的过程。[本地优先与证据边界 ↗](fdbbfaddc8de223ebcb15da97de3bf731044f8d79eb1cb8c9df9089047c20fda.md#why "解释固定证据、本地优先及模型接入的背景边界。")[可替换检索的研究取舍 ↗](fdbbfaddc8de223ebcb15da97de3bf731044f8d79eb1cb8c9df9089047c20fda.md#retrieval "解释权威原件留在 omem、检索后端保持可替换及不整体引入完整平台的原因。")[从离线原型到渐进记忆 ↗](fdbbfaddc8de223ebcb15da97de3bf731044f8d79eb1cb8c9df9089047c20fda.md#evolution "支持产品由离线交互原型、Batch 2 工程底座向主助手与渐进记忆路线演进的概括。")

阅读仓库时应区分三类信息：状态与验证记录说明现行能力，需求和设计描述目标约束，历史 Batch、原型及研究建议只供追溯。当前产品个人优先，采集材料不是工具指令，单用户实现也不能冒充租户隔离。[个人优先与统一输入边界 ↗](020535cac6a20a32782f6edf53b2b45bd07679546b8c9d6f6325ef8f9347b17b.md#product-boundary "支持个人优先、单用户限制、材料非工具指令及统一输入等现行产品边界。") 普通、高置信且小范围的变化可以自治处理并通知用户；含糊、缺少背景、范围过大或危险的操作仍需用户决策。[自治变更与外部授权 ↗](020535cac6a20a32782f6edf53b2b45bd07679546b8c9d6f6325ef8f9347b17b.md#autonomy-integrations "支持高置信小范围变化可自治并通知，以及含糊、危险或范围过大事项需要决策。")

## 统一证据链与受治理结果

手工、文件、Git、聊天、Hook、Lark 和屏幕事件先进入统一 Capture，再归并为 Source，并追加不可变 Revision 与固定 Fragment。[从采集到固定证据 ↗](4bc8adb6a65e6b818c804d2af88381e390be0fa9ab0ce0f2bd6c8c8e95b35155.md#evidence-chain "支持统一 Capture、Source 归并、不可变 Revision 与固定 Fragment 构成证据主链。") 捕获后的持久作业负责去重、租约和重试；一般知识按“分析原始材料—独立复核—组织上层正文”推进，来源变化会使依赖失效。记忆与待办则作为版本化的受治理结果写入，并非都经过同一独立 verifier。[持久作业、知识与受治理结果 ↗](4bc8adb6a65e6b818c804d2af88381e390be0fa9ab0ce0f2bd6c8c8e95b35155.md#processing-flow "支持持久作业和知识独立复核流程，并说明记忆与待办属于版本化治理结果，不能将独立 verifier 扩大为所有写入的共同门禁。") 检索候选回连固定证据，主助手和个人阅读界面围绕同一主链工作；代码结构只是附加投影。[检索、对话与阅读投影 ↗](4bc8adb6a65e6b818c804d2af88381e390be0fa9ab0ce0f2bd6c8c8e95b35155.md#retrieval-assistant-ui "支持检索候选回连固定证据，以及助手、阅读界面和代码附加投影围绕同一主链工作。")

知识正文是解释与导航层，不是新的事实权威；发布前会核验依赖并保存不可变修订。[知识复核与不可变发布 ↗](6b734c7cdc9d476ff9167d11ed7df68b14c2a2d9bcd5bbb8e5e559398a790494.md#generation_lifecycle "支持发布前依赖核验、不可变知识修订和 current 指针切换。") 用户回答先保存为新的手工原始 Revision，再作为固定输入进入后续分析和复核。[用户回答与后续复核 ↗](6b734c7cdc9d476ff9167d11ed7df68b14c2a2d9bcd5bbb8e5e559398a790494.md#questions_and_retrieval "支持用户回答先保存为手工原始 Revision，再作为固定材料进入后续分析、复核与证据召回。") Agent 运行时以版本化角色包及可信、非可信上下文分区约束模型，提示词本身不授予权限。[Agent 宿主治理与信任边界 ↗](427d80e2761bec7fb9333352245e6998b17a2c8f7c22a187904fd37369078271.md#governance_foundation "支持版本化角色资产及可信上下文与不可信材料的分区治理。") 两条写入路径须明确区分：用户明确交办的任务由服务器复核意图后直接交给 MemoryService，不经过学习管线的独立 verifier；一般知识候选才依次经过 extractor、独立 verifier 与 Attention Gate。[任务写入与知识学习治理 ↗](e707b04e3e968a054cd6ab20d7f82cc2dac61d74243de62b9bdd86142c620562.md#governed_memory "支持明确任务由服务器意图复核后直接交给 MemoryService且不经过学习 verifier，并区分一般知识的 extractor、独立 verifier 与 Attention Gate 路径。") 外部输入虽复用统一合同，但真实 Lark 授权、群聊采集同意、媒体下载和异常对账仍是独立集成边界。[Lark 接入与现有限制 ↗](4cd44e7a1651788a5722bb27cbe318c7f8092c4ee060e8d3811806c3065085c6.md#lark-integration "支持外部输入复用统一合同，同时限定真实授权、群聊采集、媒体下载和异常对账边界。")

## Code Wiki 不是第二套事实库

repo-review 只是仓库输入适配器和隔离运行配置：文件先进入通用 Capture，代码快照、符号及结构边是按快照保存的附加投影，显式 head 决定当前图。[仓库证据与代码投影 ↗](533fd1a4bb3a2c159680bc25bb26fd6d4a7762c632096aa74613a68381131d35.md#capture_projection "支持 repo-review 以通用 Capture 为输入，并用不可变快照和显式 head 构建附加代码投影。") 代码与需求、决策、研究或测试之间的确认关系只能来自人工维护的 association；词面或语义相似不能自动升级为 confirmed。[确定性结构与人工关系 ↗](533fd1a4bb3a2c159680bc25bb26fd6d4a7762c632096aa74613a68381131d35.md#structure_relations "支持确认关系只来自人工 association，语义相似不得自动形成 confirmed 关系。")

模块理解不改写原始代码事实。人工 seed 必须定位当前快照中的符号并绑定固定代码或文档证据，无法解析的 locator、证据或引用提示会保存为 rejected。[人工理解与证据阅读 ↗](533fd1a4bb3a2c159680bc25bb26fd6d4a7762c632096aa74613a68381131d35.md#understanding_reading "支持人工 seed 的当前快照定位、固定证据绑定、解析失败保留 rejected，以及共享 Evidence Trail。") 模型说明也受到生成范围、预算、引用可见性和 head 新鲜度约束；失败或过期结果不得晋升为当前结论。[模型生成防线与代码 Wiki 限制 ↗](533fd1a4bb3a2c159680bc25bb26fd6d4a7762c632096aa74613a68381131d35.md#progress_limits "支持模型生成的范围、预算、引用及 head 防线，并说明代码投影与深链仍有限制。") Code Wiki 与个人知识入口共用 Evidence Trail，可从正文逐层进入模块、文件、符号和原始 Fragment。[人工理解与证据阅读 ↗](533fd1a4bb3a2c159680bc25bb26fd6d4a7762c632096aa74613a68381131d35.md#understanding_reading "支持人工 seed 的当前快照定位、固定证据绑定、解析失败保留 rejected，以及共享 Evidence Trail。") 因此代码图和 Wiki 文章只能帮助导航，不能取代原始证据。

## 当前闭环、验证强度与未交付能力

当前基线已覆盖共用正文与固定引用、持久分析及独立复核、个人知识入口、多层证据阅读、主助手 ACP 装配、关键词召回、任务治理，以及可恢复的 Code Wiki 知识投影；失败、过期或未生成结果不计完成。[已验证的现行闭环 ↗](f146bcb111d5896d7a8ad00482ccd15d8cb67f066a67b3906a0102a36f8b575c.md#verified-slices "支持当前知识、助手和 Code Wiki 已交付切片，并限定失败、过期或未生成结果不算完成。") 全量类型检查和测试，以及真实 Fastify／SQLite／Chromium 配合确定性 ACP fixture 的浏览器流程，只证明对应代码基线和受控纵向行为。[代码基线与浏览器验证 ↗](c49ee764f7d9b87114cb9f53b1e33849d54b174cff3dc14809b8f77368460c79.md#evidence-layers "解释全量代码检查和使用确定性 ACP fixture 的真实服务、数据库与浏览器流程能够证明的范围。") 窄范围真实 ACP 冒烟也只能证明实际调用与有限内容断言。[真实 ACP 检查的证据边界 ↗](c49ee764f7d9b87114cb9f53b1e33849d54b174cff3dc14809b8f77368460c79.md#live-evidence "支持窄范围 ACP 冒烟只能证明实际调用和有限内容断言，不能外推为完整会话或外部链路验收。") 质量评测流程可用于验证人工确认、数据集冻结、隔离预测和确定性评分，但现有材料不能证明整条路径已完整执行。[人工质量数据集流程 ↗](c49ee764f7d9b87114cb9f53b1e33849d54b174cff3dc14809b8f77368460c79.md#quality-loop "说明人工确认、冻结数据集、隔离预测和确定性评分的设计职责，并限定现有材料尚未证明整条路径完整执行。") 当前进展记录还明确指出，40 条 dev 草稿尚未全部人工确认，live 标注已停止，因而尚无冻结数据集。[局部支持与能力缺口 ↗](f146bcb111d5896d7a8ad00482ccd15d8cb67f066a67b3906a0102a36f8b575c.md#evidence-levels "支持尚无冻结质量数据集的当前状态，以及语义检索、自动重核验、跨文件解析和跨修订续接尚未完成。")

仍未交付的重点包括 embedding 语义检索、覆盖所有来源的自动重核验、跨文件精确调用与类型解析，以及跨 Revision 的符号和 Fragment 身份续接。[局部支持与能力缺口 ↗](f146bcb111d5896d7a8ad00482ccd15d8cb67f066a67b3906a0102a36f8b575c.md#evidence-levels "支持尚无冻结质量数据集的当前状态，以及语义检索、自动重核验、跨文件解析和跨修订续接尚未完成。") 当前关键词检索还缺少可靠的 workspace 过滤，并存在排序和记忆证据回溯限制；这些问题应在引入语义后端前纳入统一检索合同。[关键词检索的隔离与可靠性限制 ↗](e707b04e3e968a054cd6ab20d7f82cc2dac61d74243de62b9bdd86142c620562.md#feedback_limits "支持当前关键词检索缺少 workspace 强制过滤，并存在候选排序和记忆原文回溯方面的限制。") 真实 ACP 主助手、飞书图片与引用回复、断网恢复和限流窗口仍需独立现场验收；部署继续受个人单用户 SQLite 与 shared token 边界约束，不具备多租户 ACL。[真实限制与下一步 ↗](f146bcb111d5896d7a8ad00482ccd15d8cb67f066a67b3906a0102a36f8b575c.md#remaining-work "支持真实外部链路尚待验收、单用户 SQLite 与 shared token 边界及多租户能力缺失。") Batch 2 清单及旧环境结论已被现行状态替代，只能用于追溯，不能充当当前能力证明。[已被替代的历史结论 ↗](f146bcb111d5896d7a8ad00482ccd15d8cb67f066a67b3906a0102a36f8b575c.md#superseded-history "支持旧 Batch 2 清单、旧环境记录和历史原型只能用于追溯，不能证明当前能力。")
