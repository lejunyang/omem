# omem：从原始证据到可行动的个人记忆

omem 把多来源材料、可追溯知识、对话检索、事项跟进和代码理解组织在同一证据体系中。当前已形成个人单用户的可运行切片，但完整主动助理、团队隔离、正式质量门和若干一致性边界仍待完成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 解决什么问题

omem 面向个人长期积累文档、聊天、代码和任务经历，目标不是保存更多摘要，而是让回答、知识和行动都能回到当时的原始依据。飞书主助手与 Web 管理入口属于同一记忆体系；代码虽然需要 AST 特化，也不另建独立知识库。参考 [个人助理与统一证据目标 ↗](020535cac6a20a32782f6edf53b2b45bd07679546b8c9d6f6325ef8f9347b17b.md#product-purpose "说明个人优先、飞书与 Web 入口分工，以及代码知识仍属于统一记忆体系。")

系统以 Capture、Source、不可变 Revision 和固定 Fragment 构成证据主链，当前服务在单用户 SQLite 上连接检索、知识整理、助手和持久任务。参考 [证据主链与服务形态 ↗](4bc8adb6a65e6b818c804d2af88381e390be0fa9ab0ce0f2bd6c8c8e95b35155.md#purpose-and-shape "支持不可变证据基础、当前服务组合和单用户 SQLite 边界。") 知识文章是便于理解与导航的派生视图，事实依据仍来自固定原始修订与片段。参考 [原始证据基础 ↗](6b734c7cdc9d476ff9167d11ed7df68b14c2a2d9bcd5bbb8e5e559398a790494.md#evidence-foundation "解释知识正文是带引用的派生视图，事实依据仍来自原始修订与片段。")

<a id="knowledge-flow"></a>
## 材料如何成为可复核知识

```mermaid
flowchart LR
  A[文本、图片、链接与代码] --> B[统一捕获]
  B --> C[不可变修订与固定片段]
  C --> D[角色分析与章节写作]
  D --> E[独立语义复核]
  E -->|通过| F[发布可追溯知识]
  F --> G[阅读、检索与助手召回]
  C -->|来源更新| H[失效与重新核验]
```
手工输入、文件、Git、Hook、聊天、屏幕和飞书材料使用共同的多模态合同；需要上下文的事件可以先聚合，离线 Hook 则可经本地队列补传。参考 [多来源统一捕获 ↗](4cd44e7a1651788a5722bb27cbe318c7f8092c4ee060e8d3811806c3065085c6.md#unified_capture "支持不同来源共享文本、图片、链接和逐片来源合同。") 捕获更新会追加修订、固定片段并触发受影响知识或记忆的重新核验，入列本身不等于修复成功。参考 [修订与来源更新 ↗](4bc8adb6a65e6b818c804d2af88381e390be0fa9ab0ce0f2bd6c8c8e95b35155.md#capture-and-refresh "说明捕获追加修订、固定片段、失效记录和重新核验的关系。")

运行时把角色说明和可信配置与不可信材料分开，材料正文不能取得指令权限；模型还受能力检查、预算、结构化输出和运行追踪约束。参考 [可信配置与材料分层 ↗](427d80e2761bec7fb9333352245e6998b17a2c8f7c22a187904fd37369078271.md#purpose "支持角色配置与材料正文的信任分层，以及材料不能取得指令权限。") 知识草稿经过独立复核后才发布；依赖变化会向上层传播失效，历史版本仍可回读。参考 [知识复核与发布 ↗](6b734c7cdc9d476ff9167d11ed7df68b14c2a2d9bcd5bbb8e5e559398a790494.md#review-publish "支持独立复核、有限修订、事务发布和依赖失效传播。")

<a id="assistant-and-integrations"></a>
## 助手如何回答并执行低风险操作

统一助手运行时设计为服务 Web 与飞书入口；配置有效 ACP Profile 时由适配器调用 ACP 模型。模型只能引用宿主提供的证据并请求受管工具，权限、可见性和最终写入仍由服务端控制。参考 [统一助手信任边界 ↗](e707b04e3e968a054cd6ab20d7f82cc2dac61d74243de62b9bdd86142c620562.md#assistant_boundary "说明统一运行时的入口定位、ACP 配置边界，以及模型只能使用宿主证据和受管工具。") 检索融合全文、短关键词、代码符号、记忆和知识导航，并可叠加固定中文向量模型；无论从记忆还是知识命中，最终依据仍回到原始 Fragment。参考 [会话与原始证据检索 ↗](e707b04e3e968a054cd6ab20d7f82cc2dac61d74243de62b9bdd86142c620562.md#conversation_retrieval "支持混合检索、语义降级以及记忆和知识命中回查原始片段。")

事项创建要求明确交办意图，长期记忆还需经过提取、独立复核、固定证据校验和策略评估；来源更新后会重新提取并按真实应用结果对账。参考 [事项与记忆治理 ↗](e707b04e3e968a054cd6ab20d7f82cc2dac61d74243de62b9bdd86142c620562.md#governed_memory "支持明确事项意图、提取复核、策略评估和来源刷新对账。") 飞书接入已覆盖所有者绑定、持久化收件箱、私聊与群聊路由及统一消息捕获。参考 [飞书绑定与实时捕获 ↗](4cd44e7a1651788a5722bb27cbe318c7f8092c4ee060e8d3811806c3065085c6.md#lark_ingress "支持所有者绑定、事件收件箱、助手路由、群消息分流和统一捕获。") 助手回复、决策卡片和通知投递另有 outbox、租约与重试状态机，但群采集授权、真实多 worker 竞争及部分外部联调仍需补证。参考 [飞书可靠投递 ↗](4cd44e7a1651788a5722bb27cbe318c7f8092c4ee060e8d3811806c3065085c6.md#reliable_delivery "说明助手回复、决策卡片、通知租约和重试状态机及其验证边界。")

<a id="code-progress-limits"></a>
## 代码知识、当前进展与限制

Code Wiki 把仓库文件先纳入统一证据链，再投影为代码快照、符号和人工关系；解析器当前以单文件结构为主，名称级调用保持候选，人工关系无法定位时保留缺失状态。参考 [仓库知识生成流程 ↗](533fd1a4bb3a2c159680bc25bb26fd6d4a7762c632096aa74613a68381131d35.md#pipeline "支持仓库捕获、固定快照、单文件解析和人工关系构建的范围。") 阅读界面将知识、模块、文件、符号和固定源码放入同一证据轨迹，支持逐层返回，不会以当前工作树补造历史内容。参考 [代码知识阅读路径 ↗](533fd1a4bb3a2c159680bc25bb26fd6d4a7762c632096aa74613a68381131d35.md#reading "支持知识、模块、文件、符号和固定源码共用证据轨迹。")

当前个人应用已经提供持久会话、等待与事项操作、站内提醒、可追溯知识阅读和来源更新闭环。参考 [当前个人助理体验 ↗](f146bcb111d5896d7a8ad00482ccd15d8cb67f066a67b3906a0102a36f8b575c.md#current-experience "支持统一应用、持久会话、等待跟进、事项操作和站内提醒的当前进展。") 中文混合检索及固定向量模型已经接入，但小样本命中不能代表整体质量。参考 [知识检索与更新闭环 ↗](f146bcb111d5896d7a8ad00482ccd15d8cb67f066a67b3906a0102a36f8b575c.md#knowledge-loop "支持混合检索、中文向量召回、原片段回查和来源更新复核。") 系统仍是单用户实现，缺少完整主动监听、重复提醒、团队 ACL、跨文件精确调用、周期巡检和正式冻结质量集。参考 [交付边界与未完成项 ↗](f146bcb111d5896d7a8ad00482ccd15d8cb67f066a67b3906a0102a36f8b575c.md#limits-and-status "支持单用户限制、主动助理缺口、代码解析边界和正式质量门状态。")

完成度需要分层判断：自动化检查、浏览器验收、真实模型或外部集成冒烟、冻结人工数据集分别验证不同风险，不能彼此替代。参考 [分层验证体系 ↗](c49ee764f7d9b87114cb9f53b1e33849d54b174cff3dc14809b8f77368460c79.md#validation_layers "说明自动化、浏览器、实机冒烟与冻结数据集分别承担不同验收职责。") 当前实机快照、复杂中文评测、并发一致性和飞书投递回填仍需更强证据。参考 [验证证据的现有限制 ↗](c49ee764f7d9b87114cb9f53b1e33849d54b174cff3dc14809b8f77368460c79.md#progress_and_limits "支持实机记录、中文质量、并发一致性和飞书回填仍需补强的判断。")
