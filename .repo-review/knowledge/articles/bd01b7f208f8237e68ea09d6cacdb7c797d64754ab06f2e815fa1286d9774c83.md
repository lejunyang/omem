# 系统概览与能力边界

omem 是以个人助手为起点、以不可变原始材料为事实基础的渐进记忆系统。它已形成统一采集、固定引用、知识复核、主助手治理和仓库 Wiki 阅读等闭环，但当前仍是单用户 SQLite 实现；语义检索、跨修订身份续接、全面自动重核验及真实外部端到端验收尚未交付。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose"></a>
## 要解决的问题与判断框架

omem 要解决的不是“生成更多摘要”，而是让个人助手持续吸收材料、辅助行动，同时让结论仍可回到当时原文。基础约束包括固定 Revision 与 Fragment、可替换检索和本地隐私优先；语义检索与跨 Revision Fragment 身份续接尚未实现。[代码知识研究中的现行约束 ↗](../../../docs/research/code-wiki-landscape.md#L5 "支持固定修订与片段、关键词检索现状、本地隐私原则，以及语义检索和跨修订身份续接尚未实现。") 产品原则进一步限定个人优先、统一多模态输入、材料不是指令，以及普通高置信变更可自治而高风险事项须由用户决定。[现行产品原则与工程约束 ↗](020535cac6a20a32782f6edf53b2b45bd07679546b8c9d6f6325ef8f9347b17b.md#product-boundary "提供个人优先、统一输入、材料非指令、模型接入和自治分级边界。")

阅读仓库时必须区分现行能力、目标设计和历史原型：背景章节说明离线原型、Batch 2 与渐进记忆路线的演变，[问题背景与历史演进 ↗](fdbbfaddc8de223ebcb15da97de3bf731044f8d79eb1cb8c9df9089047c20fda.md#evolution "解释离线原型、Batch 2 工程底座与渐进记忆路线之间的演变。")当前进展则以状态及行为验证为准，失败、过期或未生成结果不能计作完成。[已验证的当前功能切片 ↗](f146bcb111d5896d7a8ad00482ccd15d8cb67f066a67b3906a0102a36f8b575c.md#verified-slices "支持现行知识、主助手和阅读闭环的交付范围，并强调状态与行为验证才是能力依据。")

<a id="shared-chain"></a>
## 个人工作区与仓库 Wiki 的共同证据链

多类输入经统一 Capture 归并为 Source，并以追加 Revision 和固定 Fragment 保存历史证据。[统一采集与固定证据主链 ↗](4bc8adb6a65e6b818c804d2af88381e390be0fa9ab0ce0f2bd6c8c8e95b35155.md#evidence-chain "支持 Capture、Source、追加 Revision 和固定 Fragment 构成共同证据基础。") 持久作业在其上执行知识处理，记忆与待办采用受治理的版本化写入；它们不取代原始 Fragment。[持久作业与受治理结果 ↗](4bc8adb6a65e6b818c804d2af88381e390be0fa9ab0ce0f2bd6c8c8e95b35155.md#processing-flow "支持任务处理、知识流程以及记忆和待办的版本化治理，并说明派生结果不替代原始证据。") 知识正文经历分析、独立复核、不可变发布和依赖失效，只承担解释与导航作用。[知识生成、复核与失效 ↗](6b734c7cdc9d476ff9167d11ed7df68b14c2a2d9bcd5bbb8e5e559398a790494.md#generation_lifecycle "支持角色化分析、独立复核、不可变发布和依赖变化后的失效传播。") Agent 运行时通过可信上下文分区、能力协商、结构化合同、预算和追踪约束模型，但这些机制不等于自由文本天然正确。[Agent 输出治理与限制 ↗](427d80e2761bec7fb9333352245e6998b17a2c8f7c22a187904fd37369078271.md#outputs_progress_limits "解释结构化合同、预算、追踪和后验校验边界，并说明这些机制不能自动证明语义正确。")

Code Wiki 同样从已捕获修订建立代码快照和附加投影，个人知识与仓库知识沿共享 Evidence Trail 回到固定材料；它不是第二套 Capture 或事实权威。[代码知识投影与共享阅读 ↗](533fd1a4bb3a2c159680bc25bb26fd6d4a7762c632096aa74613a68381131d35.md#reading_generation_limits "支持 Code Wiki 从通用 Capture 建立附加投影，并说明共享 Trail、显式生成和程序分析限制。")

<a id="working-loops"></a>
## 已经形成的主要闭环

主助手已具备会话持久化、证据召回、ACP 调用和受治理任务写入；一般知识学习还经过 extractor、独立 verifier 与 Attention Gate。[主助手与受治理记忆 ↗](e707b04e3e968a054cd6ab20d7f82cc2dac61d74243de62b9bdd86142c620562.md#governed_memory "解释会话检索、ACP、任务意图门控、一般知识学习和 Attention Gate 构成的闭环。") 手工、文件、Git、Lark、Hook、聊天和屏幕事件使用统一输入形状，[统一输入合同 ↗](4cd44e7a1651788a5722bb27cbe318c7f8092c4ee060e8d3811806c3065085c6.md#unified-capture "支持手工、文件、Git、Lark、Hook、聊天和屏幕事件共享统一输入形状。")其中 Hook 可暂存重放，连续聊天与屏幕事件可聚合成批次，但多消费者和跨事务补偿仍有限制。[暂存、聚合与提交边界 ↗](4cd44e7a1651788a5722bb27cbe318c7f8092c4ee060e8d3811806c3065085c6.md#reliability-flow "支持 Hook 暂存、聊天与屏幕聚合，并说明多消费者协调和跨事务补偿仍有限制。") Lark 侧另有幂等收件、事务性发件及决策卡状态机，真实授权和平台验收仍需单独完成。[Lark 接入与交互闭环 ↗](4cd44e7a1651788a5722bb27cbe318c7f8092c4ee060e8d3811806c3065085c6.md#lark-integration "支持幂等收件、事务性发件、决策卡状态机及真实平台授权和验收边界。")

验证已覆盖代码基线和真实服务下的浏览器 fixture，但这只能证明对应装配与断言范围。[代码与浏览器验证证据 ↗](c49ee764f7d9b87114cb9f53b1e33849d54b174cff3dc14809b8f77368460c79.md#evidence-layers "支持区分代码基线、真实服务浏览器 fixture 及其有限外推范围。") 隔离质量流程另包含冻结数据集、逐样本运行、确定性评分和退出门禁；运行错误与业务性背景不足目前仍可能混入同一预测分布。[隔离质量评测流程 ↗](c49ee764f7d9b87114cb9f53b1e33849d54b174cff3dc14809b8f77368460c79.md#quality-loop "支持冻结数据集、逐样本隔离运行、确定性评分与退出门禁，并指出错误分类的现有限制。")

<a id="limits"></a>
## 当前边界与下一步阅读

当前部署是个人单用户 SQLite／shared-token 边界，不具备多租户 ACL。尚未完成 embedding 语义检索、跨文件精确调用与类型解析、跨 Revision 身份续接，以及覆盖所有来源的自动重核验。[尚未交付的核心能力 ↗](f146bcb111d5896d7a8ad00482ccd15d8cb67f066a67b3906a0102a36f8b575c.md#remaining-work "支持单用户部署边界、自动重核验、语义检索、跨文件分析、跨修订身份和真实外部验收等剩余工作。") 真实 ACP 主助手和飞书消息、图片、回复引用、断网恢复及限流窗口也需按授权范围独立验收。质量侧已有开发草稿，但尚未全部人工确认，也没有冻结数据集。[质量草稿与证据等级 ↗](f146bcb111d5896d7a8ad00482ccd15d8cb67f066a67b3906a0102a36f8b575c.md#evidence-levels "支持质量侧已有开发草稿但尚未全部人工确认、未冻结数据集的当前状态。")
