# osdk 命令工作流参考

该参考按工具生命周期、项目复现、任务、依赖、安全、模型、技能、容器和诊断等领域组织命令，并记录部分退出码；内容标注对应 osdk 0.0.3，实际使用仍应核对当前帮助。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="authority"></a>
## 覆盖范围与版本边界

材料自述覆盖全部一级命令，并按功能分组，所依据的是 `osdk 0.0.3` 的命令面。它用于解释命令意图和易错点，而非取代 `osdk <command> --help`；若当前安装版本不同，选项、默认值和可用子命令都需要重新确认。[命令参考的范围和版本 ↗](../../../.claude/skills/osdk-guide/reference/commands.md#L1 "支持该参考覆盖一级命令、对应实测版本 0.0.3，并明确当前帮助才是权威来源。")

<a id="repro-flow"></a>
## 复现、任务与应用依赖

项目工具链的复现流程包括把精确版本写入锁文件、按解析后的配置安装，以及检查过期或升级锁定结果。[项目工具链复现命令 ↗](../../../.claude/skills/osdk-guide/reference/commands.md#L71 "支持锁定、按配置安装、过期检查和升级共同构成项目工具链复现及维护流程。") 项目任务通过 `run` 执行，还可查询任务清单、解析后的定义和执行顺序；材料明确不存在裸 `osdk <name>` 的任务入口。[项目任务命令入口 ↗](../../../.claude/skills/osdk-guide/reference/commands.md#L88 "支持任务通过 run 执行，并可查询清单、解析定义和依赖执行顺序。") 应用依赖由 `deps` 从项目清单兑现，其中 `--frozen` 要求原生锁文件存在且不被修改，`--verify` 则依据包管理器收据深入核验已安装环境，二者分别约束声明稳定性与落地完整性。[应用依赖命令参数 ↗](../../../.claude/skills/osdk-guide/reference/commands.md#L109 "支持 `deps` 的用途，以及冻结安装和环境验证两类约束的区别。")

<a id="state-and-results"></a>
## 持久声明与结果判断

文档把命令视为一次性动作或即时查询，把配置视为持久声明，并给出一般成功为 0、失败非零、参数错误为 2 的约定。部分命令另有专门语义，例如计划检测到改动时返回 2；自动化流程应按具体命令解释退出码，不能将所有非零值视为同一种失败。[退出码与配置对应关系 ↗](../../../.claude/skills/osdk-guide/reference/commands.md#L327 "支持自动化应按命令解释退出码，以及命令动作与持久配置之间的关系。")
