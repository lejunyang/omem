# docs-implementation · 模块理解 · 专题 2

批次二把固定材料转化为可追溯、可复核、可治理的记忆与事项：持久任务驱动角色化提炼和独立验证，再按风险自动应用或请求决策，并通过飞书完成绑定、通知和反馈。核心链路已有实现与小范围真实验证，但质量集、通知聚合、部分飞书事件和若干运行边界仍未完成。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose_flow"></a>
## 职责与端到端流程

本模块把文本、图片、链接和会话事件保存为固定修订，再由持久 worker 聚合上下文、调用角色化 CLI/ACP 提炼，并经合同、引文、版本与语义复核分流为自动应用、补证决策或终结记录；应用产生通知，用户纠正则作为有来源的新输入回流。[批次二端到端数据流 ↗](../../../docs/implementation/batch2/plan.md#L11 "支持从固定材料、持久提炼和多层验证到策略分流、通知及反馈回流的整体流程。") 任务通过短事务取得租约，模型和网络调用不长期占锁；迟到结果必须重新核验租约、任务代次、取消状态及输入修订，防止旧 worker 覆盖新状态。[任务租约与迟到提交保护 ↗](../../../docs/implementation/batch2/plan.md#L50 "支持短事务认领、外部调用不持锁以及结果提交重新核验租约和输入版本。")

<a id="contracts_roles"></a>
## 合同、角色与证据治理

Proposal 顶层统一要求种类、操作、作用域、正文、证据、不确定性、理由、预期版本和派生来源，并支持 task、claim、episode、procedure 四类候选。[Proposal 顶层字段、种类与作用域 ↗](../../../docs/implementation/batch2/examples/proposal.schema.json#L1 "支持公共必填字段、四种候选类型、三种操作及作用域结构。") 文本证据绑定固定 fragment/source revision、逐字引文和 Unicode 选择器，图片证据则绑定资源哈希、区域与观察描述。[文本与图片证据结构 ↗](../../../docs/implementation/batch2/examples/proposal.schema.json#L73 "支持固定修订文本证据、Unicode 选择器以及图片哈希、区域和观察描述。") 不确定性、来源和预期版本分别保留；更新或替代还必须指定目标并携带至少一个预期版本，各类正文另有独立字段约束。[不确定性、版本与派生来源 ↗](../../../docs/implementation/batch2/examples/proposal.schema.json#L196 "支持不确定性、预期版本、派生来源和目标标识等公共字段。")[分类正文与更新前置条件 ↗](../../../docs/implementation/batch2/examples/proposal.schema.json#L240 "支持四类正文各自的字段约束，并证明更新或替代必须指定目标和非空预期版本。")

Extractor 只生成可独立核对的候选，负责人或日期无法唯一确认时须留空并补证；Verifier 在新上下文中给出 supported、contradicted、insufficient 或 needs_scope，确定性引文失败时不得判支持，也无权批准应用。[Extractor 候选与不确定性规则 ↗](../../../docs/implementation/batch2/prompts/extractor.md#L3 "支持候选原子化、负责人和时间解析、固定证据以及信息不足时显式补证。")[Verifier 独立复核边界 ↗](../../../docs/implementation/batch2/prompts/verifier.md#L3 "支持四类语义判定、独立上下文复核、引文失败不得判支持及角色无权批准应用。") 角色清单隔离工具、用户扩展和历史会话并限制预算，但 skill 摘要仍是构建占位符，不能据示例断言运行产物已完成不可变校验。[提炼角色隔离、预算与摘要占位符 ↗](../../../docs/implementation/batch2/examples/role-manifest.json#L10 "支持无工具、会话不复用、禁继承用户扩展、预算限制，并显示产物摘要尚为构建占位值。")

<a id="lark_relation"></a>
## 飞书接入与跨模块关系

飞书是治理链路的外部交互层，而非事实权威。独立企业自建应用扫码取得凭据后，后端加密保存并回读能力，再以同一应用内的一次性配对码和 Web 确认绑定 owner 与通知目标。[飞书扫码创建与安全配对 ↗](../../../docs/implementation/batch2/lark.md#L30 "支持凭据保存、能力核验、WebSocket 建连、一次性配对和最终绑定分阶段完成。") 投递重试保持同一 provider UUID，无法对账时保留 unknown。卡片回调须先完成最低限度的身份与 nonce 校验并持久写入事件收件箱或决策命令，再快速 ACK；消息归属、digest、expiry、expected_versions 等其余耗时核验及 CAS 业务应用异步完成，不能先宣告批准成功再尝试落库。[飞书投递与卡片决策机制 ↗](../../../docs/implementation/batch2/lark.md#L100 "支持同 UUID 重试与 unknown 状态，并明确回调须先做最低限度的身份、nonce 检查和持久化，再快速确认，其他核验及 CAS 异步完成。") 注册档案虽预留消息、文档、日历、任务和会议能力，但申请 scope 不等于实际授权或功能可用，用户身份操作仍依赖 OAuth、目标授权和业务确认。[平台权限与实际授权边界 ↗](../../../docs/implementation/batch2/lark.md#L86 "支持预留权限不等于功能可用，用户身份调用仍依赖 OAuth、目标授权、平台策略和业务确认。")

<a id="progress_limits"></a>
## 进展、质量门与现阶段限制

计划材料记录 B2-01～B2-07 已实现，B2-08 的受控学习 worker 主链、生产飞书 host 和通知路径已接入，并完成部分真实 ACP 与飞书验收。[批次二总体进展摘要 ↗](../../../docs/implementation/batch2/plan.md#L3 "支持 B2-01～B2-07、B2-08 主链、生产飞书 host、通知路径及小范围验收的状态表述。") 飞书专项材料进一步限定：现有 live 验证覆盖权限回读、WebSocket、私聊配对、主动通知、卡片回调和入群消息，但文档、日历、会议事件尚未逐项触发，若干故障仍只做确定性注入。[飞书核心实现与真实验证范围 ↗](../../../docs/implementation/batch2/lark.md#L118 "限定已完成的 API、确定性验收和 live 验证项目，并列出尚未真实覆盖的事件与故障。") 因此，此前可能把“通知聚合已接入”理解为完整聚合能力的结论已被替代；A-N04 当前仅完成逐条即时投递，短窗合并与定时摘要仍待实现。[通知聚合实际完成度 ↗](../../../docs/implementation/batch2/lark.md#L124 "明确 A-N04 目前只完成逐条即时投递，短窗合并和定时外发摘要仍待实现，替代过宽的完成度解释。")

质量方面，40 条 dev 内容仍是未确认草稿，live 标注已停止且没有冻结数据集；单一来源也不能拆分冒充独立 holdout。[开发集当前状态与 holdout 限制 ↗](../../../docs/implementation/batch2/quality-evaluation.md#L33 "支持 40 条内容仍为草稿、标注会话已停止、尚无冻结数据集以及单一来源不能充当独立 holdout。") 正式评测要求先冻结数据集，并达到自动应用与证据支持 precision 至少 95%、明确样本 coverage 至少 80%、特定负责人误判为零。[正式质量评测门槛 ↗](../../../docs/implementation/batch2/quality-evaluation.md#L65 "支持冻结数据集前置条件、precision、coverage、误判指标以及不得提前声称通过 holdout。") 当前仍只有一个已认证 owner，workspace 字段仅为未来团队迁移预留，不能宣称已有逐人 ACL。[单一认证用户限制 ↗](../../../docs/implementation/batch2/plan.md#L48 "支持 workspace 字段仅为未来迁移预留，当前实现仍只有一个已认证 owner 且没有逐人访问控制。")
