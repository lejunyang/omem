# 关联知识更新角色的界面与默认提示配置

该配置为“更新关联知识”角色声明面向用户的名称、简短说明和默认提示词，表达了基于固定证据构建关联知识的预期用途；它属于角色入口元数据，不能单独证明知识更新流程已经实现或能够成功运行。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="role-purpose"></a>
## 角色解决什么问题

该角色面向需要从既有、固定证据中整理关联知识的场景。界面名称采用“更新关联知识”，让用户能从角色列表或操作入口理解其用途；英文短说明进一步限定目标是依据固定证据构建相互关联的知识，而不是脱离来源自由生成内容。参考 [角色名称与用途 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/skills/omem-knowledge-refresher/agents/openai.yaml#L1 "支持附近关于角色展示名称以及“基于固定证据构建关联知识”这一预期职责的说明。")

这里记录的是角色的**展示语义与预期职责**。仅凭这份配置，无法确认材料解析、引用固定、独立复核或结果保存等实际处理能力是否已经接通。

<a id="invocation"></a>
## 默认调用方式与边界

默认提示词要求使用指定的知识更新技能处理已提供的固定材料，说明该角色被设计为把具体工作委托给技能合同，并以调用时供应的材料作为输入。参考 [默认技能调用提示 ↗](../../../packages/agent-runtime/roles/knowledge-refresher/1/skills/omem-knowledge-refresher/agents/openai.yaml#L4 "支持附近关于默认提示词会调用知识更新技能并处理所供应固定材料的说明。")

因此，这个 YAML 更像 Agent 入口配置：它统一展示名称、用途摘要和默认请求，却没有描述技能内部流程、支持的材料类型、失败处理或输出如何落库。判断功能是否可用，仍需结合技能定义、运行时装配及真实执行结果，不能把默认提示词视为已实现能力。
