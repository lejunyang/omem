# 主助手、会话、检索与受治理记忆

Web 与 Lark 共用助手运行时：会话隔离历史，回合先持久化再执行，原始证据经服务器可见性过滤后交给 ACP。助手任务由服务器确认明确意图并提交 MemoryService，不经过学习管线 verifier；学习材料产生的提案才走 extractor、独立 verifier 与整批策略评估。外部事件标识提供去重和有限副作用恢复，但来源更新后的自动重核验仍未实现。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="conversation_flow"></a>
## 会话身份与回合生命期

Web 与 Lark 明确共用同一个主助手运行时，由它统一负责上下文、只读检索、受治理工具、回合持久化与降级。[统一主助手运行时 ↗](../../../apps/server/src/assistant/runtime.ts#L160 "直接支持 Web 与 Lark 进入同一个 AssistantRuntime，以及该运行时承担的统一职责。") 会话则按 workspace、主体、渠道、聊天和线程共同定位，不能从聊天标识推断项目；详细边界可下钻到《conversation · 模块理解》。[会话模块：身份与边界 ↗](81d4d6a6944ddd94da96faa5cd664f461b3056f4e36190947d017aac68862156.md#identity "提供相邻子知识入口，解释组合会话键、private/group 状态及持久化职责。") 每轮输入在模型调用前先持久化，携带传输事件标识时可复用既有轮次；同一会话的新消息会取消在途回合并串行执行。[轮次入队与事件去重 ↗](../../../apps/server/src/conversation/router.ts#L146 "支持模型调用前持久化 pending 轮次，以及按传输事件标识复用既有记录。")[会话内抢占与串行执行 ↗](../../../apps/server/src/assistant/runtime.ts#L198 "支持新消息取消在途回合并沿会话执行链串行运行。")

外部取消、会话控制器与回合定时器会合并成中止信号，工具调用及最终落库前另设取消栅栏，防止迟到结果产生副作用。[合并取消信号与定时器 ↗](../../../apps/server/src/assistant/runtime.ts#L393 "直接支持外部信号、会话控制器和回合定时器如何共同形成中止信号。")[工具调用与落库取消栅栏 ↗](../../../apps/server/src/assistant/runtime.ts#L494 "支持任务意图检查、MemoryService 治理、引用白名单及副作用前后的取消检查。") receipt 恢复只对带传输事件标识的回合有效：此前“所有未完成回合都能识别已提交副作用”的结论已被替代，无该标识的 Web 回合不具备同等保证。[取消与有限 receipt 恢复 ↗](../../../apps/server/src/assistant/runtime.ts#L261 "支持取消、重试和重启恢复，并证明 receipt 匹配依赖传输事件标识。")

<a id="retrieval_model"></a>
## 原始证据检索与模型上下文

执行阶段只回放当前会话近期已完成历史，并合并本轮检索、上一轮选中证据和会话范围内的确认纠正。检索优先走 `RetrievalPort`，旧测试才回退到 Store；两类证据都重新经过服务器可见性过滤。未注入策略时 private 可读、group 默认拒绝，但这并不证明生产宿主已经装配完整的主体与来源隔离策略。[检索与服务器可见性过滤 ↗](../../../apps/server/src/assistant/runtime.ts#L604 "支持统一检索端口优先、Store 回退、上一轮证据复用及群聊默认拒绝规则。") 固定 Fragment 回读、中文二元组和 active memory 搜索可继续下钻到《retrieval · 模块理解》。[检索模块：流程与回读 ↗](08f25ff6e25e1918acb0892c2a3a12abd21c662ab179814edc853f516920ebfb.md#retrieval-flow "提供相邻子知识入口，解释固定证据回读、关键词分词与 active memory 搜索。")

生产适配器只接受 ACP profile，限制历史和证据长度，声明材料不是指令，并要求模型返回回答、引用及可选任务请求的 JSON。[ACP 上下文与输出合同 ↗](../../../apps/server/src/assistant/acp-model.ts#L42 "支持 ACP profile 限制、上下文预算、证据非指令约束、JSON 输出协议和传输失败处理。") 确定性模型仅供测试；生产缺少真实模型时必须如实报告不可用。[确定性模型的测试限定 ↗](../../../apps/server/src/assistant/default-model.ts#L7 "证明确定性模型只供测试，生产缺少真实模型时必须如实降级。")

<a id="governed_memory"></a>
## 助手任务与学习提案的不同治理路径

模型只能提出结构化任务请求；服务器先核对明确交办、过滤引用白名单，再提交 `MemoryService`。直接 owner 交办可捕获本轮原话作为证据，并由运行时构造 `assistant-intent-v1` assessment。因此，此前“助手任务也经过独立 verifier”的结论已被替代：该路径直接依赖意图检查和 MemoryService 治理。[工具调用与落库取消栅栏 ↗](../../../apps/server/src/assistant/runtime.ts#L494 "支持任务意图检查、MemoryService 治理、引用白名单及副作用前后的取消检查。")[助手任务的直接治理评估 ↗](../../../apps/server/src/assistant/runtime.ts#L701 "证明助手运行时直接构造意图 assessment 并调用 MemoryService，而非经过学习管线 verifier。")

MemoryService 会精确校验 Fragment 所属 revision、Unicode 引文区间或图片资产，再由 Attention Gate 在自动应用、请求决定、延后、保留来源、忽略噪声和拒绝之间裁决；详细匹配策略可下钻到《memory · 模块理解》。[精确引文与图片资产校验 ↗](../../../apps/server/src/memory/service.ts#L201 "直接支持文本 selector、精确引文、来源 revision 以及图片资产的一致性校验。")[Attention Gate 策略分支 ↗](../../../apps/server/src/memory/service.ts#L704 "支持证据错误、冲突、软不确定性、来源保留和自动应用等治理结果。")[记忆模块：匹配与策略 ↗](1ac17957490c0bb09fc31aaa4495f7676845abf9e570143a0e9f9d8760292b06.md#matching-and-policy "提供相邻子知识入口，供读者下钻同域知识匹配和 Attention Gate 的整体边界。") 提案还保存来源 revision 与有效性纪元快照，应用或人工决定前重新比较当前 head 与 epoch，变化即按陈旧处理。[提案来源读取快照 ↗](../../../apps/server/src/memory/service.ts#L135 "支持提案持久化时保存证据来源 revision 与有效性纪元。")[当前来源新鲜度比较 ↗](../../../apps/server/src/memory/service.ts#L255 "支持应用或决定前比较当前 source head、epoch 与提案读取快照。")

学习材料走另一条链路：extractor 产生提案，独立 verifier 完整覆盖候选并核对摘要，随后整个 ChangeSet 一次性交给批量策略评估；详细流程见《learning · 模块理解》。[学习模块：提取与独立复核 ↗](10d08569c7ebcd6fe394a2f2453ddcb298d886363c472add78e054af606bf143.md#purpose-and-flow "提供相邻子知识入口，说明 extractor、verifier 与整批策略评估的关系。")[独立复核与整批评估 ↗](../../../apps/server/src/learning/pipeline.ts#L443 "支持 assessment 完整覆盖、摘要一致性检查及整个 ChangeSet 的批量治理。")

<a id="progress_limits"></a>
## 当前进展、替代结论与限制

现有链路已覆盖会话持久化、事件去重、会话内抢占、关键词召回、ACP 调用、引用白名单、受治理任务创建及有限恢复。关键词来源检索按词面累计分数，但每个 term 最多读取 200 行且截断前没有稳定 SQL 排序；`MemoryCandidate` 也没有原始 Revision 与 Fragment 定位。[关键词来源评分与截断 ↗](../../../apps/server/src/retrieval/keyword.ts#L52 "支持词面累计评分、每词最多读取 200 行及截断前缺少 SQL 排序的限制。")[来源与记忆候选合同 ↗](../../../apps/server/src/retrieval/port.ts#L45 "展示来源候选包含 Revision 与 Fragment 定位，而记忆候选没有对应字段。")

批量超预算时会把原本可自动应用的提案停放，并建立包含全部摘要的汇总 Attention Case；但决定行锚定代表提案摘要，公开 `decide` 又只按该摘要重建并应用一个提案。[汇总批量决定的锚定方式 ↗](../../../apps/server/src/memory/service.ts#L1491 "证明批量 Attention Case 保存全部提案摘要，但决定行以代表提案摘要作为锚点。")[公开决定的单提案应用流程 ↗](../../../apps/server/src/memory/service.ts#L1660 "证明 decide 按决定绑定的摘要重建一个提案，并在批准时调用单提案 apply。") 因而“批准即可整体应用全部停放提案”尚不能成立。

来源更新后，刷新函数只记录 `needs_review` 或 `no_effect`，处理器随后以未实现错误结束。此前“刷新已完成失效记忆重核验”的结论已被替代：当前尚无自动 extractor/verifier 重核验闭环。[来源刷新记录状态 ↗](../../../apps/server/src/learning/refresh.ts#L25 "支持刷新只记录影响范围、区分 needs_review 与 no_effect，并返回 blocked/not_implemented。")[刷新作业尚未重核验 ↗](../../../apps/server/src/learning/pipeline.ts#L126 "证明刷新处理器记录范围后抛出未实现错误，不能报告重新复核成功。")
