# 主助手、会话、检索与受治理记忆

系统以统一运行时连接会话账本、原始证据检索、ACP 模型、事项操作和长期记忆治理。模型只提出回答、引用与工具候选；可见性、固定证据、写入许可、复核及成功回执由服务端控制。源码已覆盖主要流程，但生产入口装配、事项更新的崩溃恢复、批量批准语义和真实行为验证仍待补证。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="assistant_boundary"></a>
## 统一入口与信任边界

主助手运行时面向 Web、Lark 等入口，集中承担上下文组装、只读检索、模型端口调用、事项治理、轮次持久化和降级；模型实现通过端口注入。[统一助理运行时职责 ↗](../../../apps/server/src/assistant/runtime.ts#L192 "支持多入口共用运行时，以及上下文、检索、事项治理、轮次持久化和降级等职责。") 确定性模型明确只用于测试，因此“生产入口已实际装配 ACP”仍不能仅凭此设计约束确认。[测试模型的装配边界 ↗](../../../apps/server/src/assistant/default-model.ts#L7 "支持确定性模型仅用于测试，并说明生产应注入真实 ACP 模型；不把设计要求误写成入口装配事实。")

模型只能引用宿主传入的证据并请求受管工具；证据可见性由服务端依据规范主体和来源范围判断，未注入策略时群聊默认拒绝证据。[模型端口与可见性合同 ↗](../../../apps/server/src/assistant/runtime.ts#L86 "支持模型只能使用宿主证据和受管工具，并由服务端控制证据可见性。") 生产适配器要求 ACP Profile，缺少 Profile 或使用非 ACP transport 时明确报告不可用，不以测试替身伪造回答。[ACP 模型适配边界 ↗](../../../apps/server/src/assistant/acp-model.ts#L12 "支持缺少 Profile 或使用非 ACP transport 时明确报告模型不可用。") ACP 层还会拒绝自动权限与补充输入请求，并限制输出量；模型和推理强度必须属于会话实际声明的可选值。[ACP 权限与输出限制 ↗](../../../apps/server/src/agents.ts#L180 "支持后台 ACP 不自动批准权限或补充输入，并对文本输出设置上限。")[模型能力选项校验 ↗](../../../apps/server/src/agents.ts#L301 "支持依据 ACP 会话实际配置选项校验模型与推理强度，不支持的值直接拒绝。")

## 会话、检索与可追溯回答

轮次在模型调用前持久化；有外部事件号时可返回既有轮次，同一会话串行执行，新消息中止旧轮次，预取消请求不会启动模型。[轮次入列与会话串行 ↗](../../../apps/server/src/assistant/runtime.ts#L231 "支持模型调用前持久化、重复投递识别、新消息取消旧轮次和预取消栅栏。") 会话路由的未完成恢复依赖 JSON 文本匹配，并直接解析多个 JSON 字段，因此并发约束、格式变化和损坏数据恢复仍需迁移与测试补证。[未完成轮次恢复与反序列化 ↗](../../../apps/server/src/conversation/router.ts#L286 "支持恢复查询依赖 JSON 文本匹配，并揭示多个 JSON 字段直接解析的健壮性边界。")

检索端口要求所有候选回到不可变 fragment。[统一检索与固定证据锚点 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持检索后端可替换，且所有结果必须指回不可变 fragment。") 关键词实现融合代码符号、全文、短关键词、记忆和知识五路候选。[关键词五路召回与融合 ↗](../../../apps/server/src/retrieval/keyword.ts#L97 "支持代码符号、全文、短关键词、记忆和知识五路候选及倒数排名融合。") 其中记忆命中从 evidence set 回查当前 head 上的原始片段，[记忆命中回查原始片段 ↗](../../../apps/server/src/retrieval/keyword.ts#L81 "支持记忆正文通过 evidence set 回查当前 head 上的非派生原始 fragment。") 知识正文则先校验依赖和内联引用，再递归映射到覆盖引用范围的原始 fragment；两者均不把派生正文当作独立证据。[知识引用回溯原始证据 ↗](../../../apps/server/src/knowledge/retrieval.ts#L33 "支持知识依赖校验、文章引用递归和材料引用向原始 fragment 的范围映射。")

可选语义层只为当前查询条件选出的、尚未以当前模型身份完成索引的片段分窗写入向量。[当前片段的语义分窗索引 ↗](../../../apps/server/src/retrieval/semantic.ts#L51 "支持按当前查询条件选择未完成索引的片段，并以当前模型身份分窗、嵌入和事务写入。") 中文模型由 osdk 提供固定快照，校验仓库、revision 和文件哈希，并禁止远程加载。[离线锁定的中文向量模型 ↗](../../../apps/server/src/retrieval/embedding.ts#L14 "支持固定 BGE 中文模型 revision、文件哈希校验和禁止远程模型加载。") 查询先取词法候选，再融合当前模型向量；模型未就绪或语义处理异常时保留词法结果，最终排序只改变次序，不改变证据身份。[语义融合与异常回退 ↗](../../../apps/server/src/retrieval/semantic.ts#L81 "支持词法预取、当前模型向量融合，以及模型未就绪或异常时保留词法候选。")

<a id="governed_memory"></a>
## 事项操作与记忆治理闭环

事项创建必须先匹配所有者明确交办意图，咨询式问题即使模型请求创建也会被拒绝。[明确事项意图检测 ↗](../../../apps/server/src/assistant/runtime.ts#L130 "支持创建事项不能只信任模型请求，咨询式或不明确的输入不得自动创建。") 更新还需核对动作措辞、事项可见性和版本；等待对象与时间表达必须来自当前指令，随后捕获原始变更指令并通过任务服务执行。[事项更新治理流程 ↗](../../../apps/server/src/assistant/runtime.ts#L695 "支持动作表达、可见性、版本、时间来源校验、指令捕获及以 turnId 调用任务命令。")

长期记忆由持久化学习流水线处理：worker 只领取提取、独立复核和来源刷新三类作业。[学习作业范围与路由 ↗](../../../apps/server/src/learning/pipeline.ts#L65 "支持学习流水线只处理提取、复核和来源刷新三类持久化作业。") 每次角色运行前核对 revision 仍是来源当前 head，且 sourceId 与 validity epoch 未变化。[学习输入时效校验 ↗](../../../apps/server/src/learning/pipeline.ts#L180 "支持角色运行前核对来源当前 head、sourceId 和 validity epoch。") extractor 产生非空提案后才派生 verifier 作业；复核会验证父子关系和已存输出，再调用独立角色。[提取与独立复核编排 ↗](../../../apps/server/src/learning/pipeline.ts#L421 "支持 extractor 产生提案后派生 verifier 作业，以及复核父子关系和已存输出。") verifier 必须覆盖全部提案且逐项摘要一致，之后才把整批 ChangeSet 交给记忆服务评估。[全覆盖复核与整批评估 ↗](../../../apps/server/src/learning/pipeline.ts#L505 "支持 verifier 覆盖全部提案、逐项核对摘要，并调用 evaluateBatch 处理整批 ChangeSet。")

记忆服务对每项提案保存来源读取，校验固定引文，匹配重复、独立来源等价与冲突，再按影响和不确定性决定自动应用、延后、保留来源、拒绝或请求决定。[记忆评估核心 ↗](../../../apps/server/src/memory/service.ts#L1282 "支持提案持久化、固定证据校验、知识匹配、策略分流和批量停放等记忆治理步骤。") 来源更新先冻结首次发现的失效记忆集合，避免重复投递缩小影响范围；若新 revision 仍是 head，则复用 extractor 身份重新入列。[冻结来源刷新影响集合 ↗](../../../apps/server/src/learning/refresh.ts#L6 "支持首次刷新时冻结受影响的失效记忆集合，重复投递复用同一记录。")[来源刷新重新提取 ↗](../../../apps/server/src/learning/pipeline.ts#L126 "支持确认新 revision 仍为当前 head 后复用 extractor 身份重新入列。") 最终刷新状态依据当前依赖和真实应用结果对账，不能把“已入列”视为“已修复”。[刷新结果实际对账 ↗](../../../apps/server/src/learning/refresh.ts#L27 "支持刷新状态依据当前 head、依赖和真实应用结果判定，而非依据入列成功。")

## 当前进展、替代结论与限制

源码已连通轮次入列、补充检索、引用白名单、明确事项意图、固定证据评估、独立复核和来源刷新；补检最多进行一轮，最终引用只保留运行时实际提供的 fragment。[补充检索与第二轮生成 ↗](../../../apps/server/src/assistant/runtime.ts#L494 "支持补充检索词去重、截断、限量，证据合并后最多再生成一次。")[最终引用白名单 ↗](../../../apps/server/src/assistant/runtime.ts#L602 "支持最终只保留运行时实际提供给模型的 fragment 引用。")[全覆盖复核与整批评估 ↗](../../../apps/server/src/learning/pipeline.ts#L505 "支持 verifier 覆盖全部提案、逐项核对摘要，并调用 evaluateBatch 处理整批 ChangeSet。") 这替代了此前用单一“所有者消息捕获”引用概括整条链路的结论。

创建事项会尝试捕获当前所有者原话，但捕获失败不会中止评估，proposal 的 evidence 可能为空；因此“创建必然携带成功捕获的原始证据”已被替代。[所有者消息捕获与空证据边界 ↗](../../../apps/server/src/assistant/runtime.ts#L832 "支持创建时尝试捕获所有者原话、捕获异常非致命，并可能以空 evidence 继续评估。") 重启恢复目前只按外部事件号查询创建事项 proposal 前缀，而更新事项以 turnId 作为请求身份调用任务服务，尚不能证明更新提交后崩溃不会重复执行。[创建回执恢复机制 ↗](../../../apps/server/src/assistant/runtime.ts#L308 "支持恢复查询依赖外部事件号和创建事项 proposal 前缀，不能外推到所有更新操作。")[事项更新治理流程 ↗](../../../apps/server/src/assistant/runtime.ts#L695 "支持动作表达、可见性、版本、时间来源校验、指令捕获及以 turnId 调用任务命令。")

批量超预算时，系统会生成一个确认事项并保存全部停放提案的摘要标识、聚合证据与代表提案锚点。[批量确认事项与摘要标识 ↗](../../../apps/server/src/memory/service.ts#L1522 "支持单个批量确认事项保存全部停放提案摘要标识、聚合证据及代表提案锚点。") 但通用批准入口只按决定行的单个 proposal digest 重建并应用代表提案，没有展示遍历整批摘要的路径。[通用批准的单提案路径 ↗](../../../apps/server/src/memory/service.ts#L1697 "支持通用决定入口仅按决定行锚定的 proposal digest 重建并应用一个提案。") 因而“批量批准会整体应用全部提案”的旧结论已被替代。材料也未提供测试文件、退出码或真实 ACP 运行记录，不能据源码分支宣称并发竞争、索引生命周期、批量失败恢复和外部传输已通过端到端验证。
