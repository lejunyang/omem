# 主助手、会话、检索与受治理记忆

主助手以持久会话为入口，经受范围和可见性约束的检索取得固定原始证据，再由 ACP 模型生成回答；记忆提案、助手事项、来源刷新和轮次恢复分别经过服务器治理、收据与新鲜度检查。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="runtime-boundary"></a>
## 统一入口、会话与模型边界

主助手是 Web 与飞书共用的执行面，集中完成上下文组装、只读检索、轮次持久化和受治理写入，模型不能自行扩大权限。[主助手统一执行面 ↗](../../../apps/server/src/assistant/runtime.ts#L185 "支持 Web 与飞书共享运行时，以及上下文、检索、治理、持久化和降级由宿主集中负责。") 会话由 workspace、主体、渠道、聊天和线程共同定位，默认工作区为 `personal`，项目身份不从聊天 ID 推断。[会话复合身份 ↗](../../../apps/server/src/conversation/router.ts#L67 "支持会话定位字段、personal 默认工作区及不从聊天标识推断项目身份。") 轮次在模型调用前写为 pending；外部事件标识生成确定性轮次 ID，用于重复投递去重和同会话串行执行。[轮次持久化与串行执行 ↗](../../../apps/server/src/assistant/runtime.ts#L224 "支持模型调用前入队、外部事件去重、新消息取消旧轮次和同会话串行执行。")

生产模型只接受已配置的 ACP profile，缺少配置或使用不支持的 CLI transport 时明确报告不可用。[ACP 生产模型限制 ↗](../../../apps/server/src/assistant/acp-model.ts#L10 "支持生产适配器只接受 ACP profile，并在配置缺失或 transport 不支持时明确失败。") 当前应用围绕同一 Store 装配助手、检索、记忆、反馈和学习服务，健康接口将运行模式标为 SQLite、personal，因此不能据此声称已有团队租户隔离。[共享服务与个人运行模式 ↗](../../../apps/server/src/app.ts#L53 "支持各服务共享 Store，并证明健康接口将当前存储和模式报告为 SQLite、personal。")

<a id="conversation-retrieval"></a>
## 从会话问题到固定原始证据

检索合同要求只有已确认的项目关联才能收窄范围；项目未知时保持工作区召回，并在最终排序和截断前应用可见性过滤。[检索范围与可信项目规则 ↗](../../../apps/server/src/retrieval/port.ts#L17 "支持项目关联不得从会话载体推断、未知项目保持工作区召回及可见性过滤时机。") 关键词基线融合全文、短词、活跃记忆回溯和知识路线：前三路明确回到当前 head 的非派生片段，知识路线则由外部函数提供，当前材料未证明其自身具有同等保证。[四路关键词融合 ↗](../../../apps/server/src/retrieval/keyword.ts#L52 "支持全文、短词和记忆路线的当前原始证据约束，并显示知识路线由外部函数直接提供。")

可选语义分支加载由 osdk 管理的固定 BGE 中文模型快照，校验仓库、revision 和文件摘要，并禁止远程模型及运行时隐式下载。[锁定的本地中文向量模型 ↗](../../../apps/server/src/retrieval/embedding.ts#L14 "支持固定 BGE 仓库与 revision、文件摘要校验、禁止远程模型和仅本地 CPU 加载。") 模型尚未加载或语义查询异常时仍返回词法结果。[语义融合与词法降级 ↗](../../../apps/server/src/retrieval/semantic.ts#L80 "支持模型未加载时直接返回词法结果，以及语义计算异常时记录错误并降级。") 每轮只读取当前会话已完成历史，最多补充一轮检索；最终引用标识还会与宿主实际提供的 fragment 集合求交集，但这不等于回答正文的每项陈述都已完成语义核验。[历史上下文与补充检索 ↗](../../../apps/server/src/assistant/runtime.ts#L447 "支持只读取当前会话已完成历史、合并上一轮工作证据并限制补充检索轮数。")[引用标识过滤 ↗](../../../apps/server/src/assistant/runtime.ts#L581 "证明最终引用只保留运行时实际提供过的 fragment 标识，同时限定该机制只过滤引用集合。")

<a id="governed-memory"></a>
## 记忆提案与助手事项的不同治理路径

学习作业在构造模型上下文时先确认输入 revision 仍是 source head，并核对 sourceId 与 validity epoch；这是进入 extractor/verifier 前的修订新鲜度检查。[模型上下文前的新鲜度检查 ↗](../../../apps/server/src/learning/pipeline.ts#L180 "支持在角色运行前校验 revision head、sourceId 和 validity epoch，并保留逐片段来源信息。") verifier 随后核验父输出、摘要和逐提案覆盖，完成独立复核后才把完整 ChangeSet 交给 `evaluateBatch`。[独立复核后进入批量评估 ↗](../../../apps/server/src/learning/pipeline.ts#L457 "支持 verifier 先核验父输出及逐提案覆盖，随后才调用 MemoryService.evaluateBatch。") 治理层在批量评估内部持久化提案并确定性校验文本 selector、来源修订或图片资产，再执行知识匹配、AttentionGate 和应用；这替代了“先确定性校验证据内容、再运行 verifier”的旧结论。[治理层的确定性证据校验 ↗](../../../apps/server/src/memory/service.ts#L1271 "支持 evaluateBatch 调用的治理流程在 verifier 之后持久化提案、校验证据并执行政策和应用。")

助手事项不经过这条学习流水线。创建事项需先识别明确记录意图、尝试捕获所有者原话，并且只有治理返回持久化收据才能声称成功。[受治理的事项创建 ↗](../../../apps/server/src/assistant/runtime.ts#L784 "支持助手先确认明确意图、捕获所有者原话并仅以应用收据确认创建成功。") 完成、重开和改期则校验明确指令、可见事项及期望版本，再由 `commandTask` 使用所有者原始证据和统一应用接口写入；只有改期额外要求原文时间表达和带时区时间。[助手事项更新校验 ↗](../../../apps/server/src/assistant/runtime.ts#L697 "支持事项变更校验用户动作、可见版本，以及仅改期需要验证时间表达。")[所有者事项命令写入 ↗](../../../apps/server/src/memory/service.ts#L84 "支持 commandTask 校验所有者原始证据、任务归属和版本，并通过统一应用接口生成收据。")

<a id="refresh-progress-limits"></a>
## 来源重核验、启动恢复与现有限制

来源更新会按来源和新修订生成稳定记录，并冻结首次发现的受影响记忆集合。[冻结来源刷新影响集合 ↗](../../../apps/server/src/learning/refresh.ts#L6 "支持刷新记录冻结首次发现的受影响记忆，并以工作区、来源和新修订形成稳定身份。") 当前修订仍有效时复用 extractor 身份重新入列，来源继续前进时则记为 superseded；入列不等于应用成功，只有记忆恢复 active、依赖指向新修订且 source head 一致时才成为 applied。[来源刷新重新入列 ↗](../../../apps/server/src/learning/pipeline.ts#L126 "支持当前修订有效时复用 extractor 身份重新入列，来源前进时核对为 superseded。")[刷新结果依据实际状态核对 ↗](../../../apps/server/src/learning/refresh.ts#L27 "支持队列成功不等于应用，并以记忆状态、依赖和来源 head 决定 applied、needs_review 或 superseded。")

应用启动阶段会实际调用未完成轮次恢复，而不只是提供恢复方法。[应用启动时恢复轮次 ↗](../../../apps/server/src/app.ts#L598 "直接证明服务器构建完成前实际调用未完成轮次恢复方法。") 恢复会扫描 pending/running 轮次，并查询真实 application receipt，避免已提交的创建事项再次执行。[未完成轮次与收据恢复 ↗](../../../apps/server/src/assistant/runtime.ts#L301 "支持 pending/running 轮次恢复和真实 application receipt 防重，并显示其依赖外部事件标识及创建事项前缀。") 但现有 receipt 匹配依赖外部事件标识及创建事项提案前缀，不能推广为所有写操作均具备同等崩溃防重能力。被替代的另一宽泛结论是“所有召回路线和渠道都已端到端验证”：当前只能确认群聊未注入策略时缺省拒绝证据，知识路线自身的当前性与原始性仍待核验。[群聊证据缺省拒绝 ↗](../../../apps/server/src/assistant/runtime.ts#L115 "支持证据可见性由服务器策略决定，且未注入策略时群聊不暴露证据。")[四路关键词融合 ↗](../../../apps/server/src/retrieval/keyword.ts#L52 "支持全文、短词和记忆路线的当前原始证据约束，并显示知识路线由外部函数直接提供。")
