# 主助手、会话、检索与受治理记忆

Web 与 Lark 共用会话及助手运行时：回合先持久化，再检索证据并调用 ACP；任务写入须经过服务器意图复核和 MemoryService，一般知识还经过 extractor、独立 verifier 与 Attention Gate。当前关键词检索未强制 workspace 隔离，此外仍受群聊策略、无事件标识恢复、证据回溯和来源更新重核验未闭环等限制。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="conversation_runtime"></a>
## 会话身份、持久化与恢复

Web 与 Lark 会话由 workspace、主体、渠道、聊天和线程共同定位，聊天标识不能推导项目；线程隔离及持久化职责可继续下钻到会话子知识。[会话身份与线程隔离 ↗](81d4d6a6944ddd94da96faa5cd664f461b3056f4e36190947d017aac68862156.md#identity "提供会话组合键、线程隔离和持久化边界的子知识入口。")[会话组合键与创建流程 ↗](../../../apps/server/src/conversation/router.ts#L67 "支持会话由 workspace、主体、渠道、聊天和线程共同确定，且聊天标识不代表项目。") 每轮在模型调用前以 pending 状态落库；外部事件标识用于稳定去重，同一会话的新消息会取消旧回合并沿队列串行接续。[回合入队、去重与会话抢占 ↗](../../../apps/server/src/assistant/runtime.ts#L198 "支持模型调用前持久化、外部事件幂等去重和同一会话中新消息取消旧回合。")

取消信号合并外部中止、会话抢占与回合定时器，模型等待还通过独立竞速超时避免因模型忽略 abort 而永久挂起。[合并取消信号与独立超时 ↗](../../../apps/server/src/assistant/runtime.ts#L393 "支持外部信号、会话控制器、回合定时器及独立模型等待超时的组合行为。") 重试和崩溃恢复会查询真实 application receipt，但匹配依赖 transportEventId；带事件标识且已有 receipt 的回合只补齐完成状态，其他未完成回合重新执行。因此，无事件标识的 Web 回合不具备同等级的副作用恢复幂等保证。[Receipt 恢复的事件标识限制 ↗](../../../apps/server/src/assistant/runtime.ts#L275 "证明 receipt 查询依赖 transportEventId，并支持据此补齐完成或重新执行的恢复边界。")

<a id="retrieval_model"></a>
## 证据检索、隔离与模型调用

助手只回放当前会话近期已完成轮次，并合并本轮召回与上一轮选中证据；两类证据都会再次经过可见性过滤。未注入宿主策略时，private 会话可读而 group 默认拒绝全部证据；上下文和模型失败语义可下钻到助手子知识。[助手上下文与模型失败处理 ↗](4419e180caae25b020ef79e7512459de0e315a056057ef5d1e5ddb969b796cd7.md#context_and_model "提供当前会话历史、上一轮证据、纠正上下文和模型失败语义的子知识入口。")[检索与可见性过滤 ↗](../../../apps/server/src/assistant/runtime.ts#L604 "支持 RetrievalPort 优先、上一轮证据复用，以及群聊未注入策略时默认拒绝。") 检索端口要求结果最终指向固定 Fragment，摘要只是定位线索，不能成为新的独立事实依据。[检索端口的证据与范围合同 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持固定 Fragment 证据目标及未确认项目时应退化为 workspace 范围的设计要求，同时显示查询合同没有 workspace 标识。")

当前 SQLite 关键词实现按中文完整串、二元组和 ASCII 词累计命中分数，但来源 SQL 与记忆 SQL 均未带 workspace 条件；`SearchQuery` 本身也没有 workspace 标识。来源搜索会跨所有当前 source head 查找，记忆搜索会读取全部 active memory 后至多按可信项目过滤。[关键词检索缺少 workspace 过滤 ↗](../../../apps/server/src/retrieval/keyword.ts#L102 "直接支持来源 SQL 和 active memory SQL 均没有 workspace 条件，证明当前实现无法强制 workspace 隔离。") 因而此前“项目未确认时检索保持 workspace 范围”的结论已被替代：端口只表达了应退化为 workspace-wide recall 的设计要求，现有实现却不能证明或强制 workspace 边界，存在跨 workspace 召回风险。[检索端口的证据与范围合同 ↗](../../../apps/server/src/retrieval/port.ts#L1 "支持固定 Fragment 证据目标及未确认项目时应退化为 workspace 范围的设计要求，同时显示查询合同没有 workspace 标识。")[关键词检索缺少 workspace 过滤 ↗](../../../apps/server/src/retrieval/keyword.ts#L102 "直接支持来源 SQL 和 active memory SQL 均没有 workspace 条件，证明当前实现无法强制 workspace 隔离。")

ACP 适配器限制历史、证据与输出长度，声明材料中的内容不是指令，并要求模型返回回答、引用和可选任务请求组成的 JSON；未配置 ACP、使用不支持的 CLI transport 或传输失败时会如实报告模型不可用。[ACP 上下文与输出协议 ↗](../../../apps/server/src/assistant/acp-model.ts#L42 "支持 ACP transport 限制、上下文预算、材料非指令约束、JSON 输出合同及传输失败处理。")

<a id="governed_memory"></a>
## 任务写入与知识学习的两条治理路径

助手任务路径不信任模型自行授权：服务器先用确定性规则复核用户是否明确交办，只允许引用实际暴露的片段，并在工具执行和最终持久化前设置取消栅栏。明确 owner 交办可捕获本轮原话作为证据，再将任务提案交给 MemoryService；只有返回任务 receipt 才代表真正创建。[任务意图、引用与治理写入 ↗](../../../apps/server/src/assistant/runtime.ts#L494 "支持明确任务意图复核、直接消息捕获、引用解析、MemoryService 评估和 receipt 成功条件。") 该直接路径使用 `assistant-intent-v1` 评估，不经过学习管线的独立 verifier。

一般捕获知识则由 extractor 产生 proposal，再创建 verifier 作业；verifier 必须完整覆盖候选、核对提案摘要，并将整个 ChangeSet 一次性交给批量策略评估，避免拆分绕过影响预算。流程背景可继续下钻到学习子知识。[学习管线流程 ↗](10d08569c7ebcd6fe394a2f2453ddcb298d886363c472add78e054af606bf143.md#purpose-and-flow "提供 extractor、独立 verifier 与整批策略评估的子知识入口。")[独立复核与整批评估 ↗](../../../apps/server/src/learning/pipeline.ts#L443 "支持 verifier 完整覆盖候选、核对摘要并把整个 ChangeSet 送入批量治理。") MemoryService 按稳定摘要幂等保存提案，校验精确文本或图片证据，并记录来源 head 与 validity epoch 快照；应用前重新检查新鲜度。[提案证据与来源新鲜度 ↗](../../../apps/server/src/memory/service.ts#L135 "支持提案摘要幂等、精确证据校验以及来源 head 和 validity epoch 快照检查。") Attention Gate 根据证据、语义结论、来源冲突、任务关联及影响范围，在拒绝、忽略、保留来源、延后、请求用户决定和自动应用之间选择，模型不能绕过这些分支。[Attention Gate 策略分支 ↗](../../../apps/server/src/memory/service.ts#L704 "支持拒绝、忽略、保留、延后、请求决定和自动应用等治理结果及升级条件。")

<a id="feedback_limits"></a>
## 反馈约束与未完成闭环

反馈按身份验证、原始生产者、证据完整性和是否涉及受保护策略分为 confirmed、weak 或 shadow。confirmed 约束目前只在显式调用时改写任务负责人；助手另会读取会话范围内的纠正作为模型上下文，但这不能表述为反馈已经全面接入所有提案治理。[反馈可信度与有限改写 ↗](../../../apps/server/src/memory/service.ts#L1869 "支持反馈幂等、强度分级，以及 confirmed 约束目前仅改写任务负责人的能力边界。")

当前限制不止于缺少语义检索：关键词来源查询每词最多读取 200 行且无 SQL 排序，记忆候选也缺少直接回到 Revision、Fragment 的定位字段；更关键的是，现有来源与记忆检索没有 workspace 过滤，尚不能承担 workspace 或租户隔离。[关键词检索缺少 workspace 过滤 ↗](../../../apps/server/src/retrieval/keyword.ts#L102 "直接支持来源 SQL 和 active memory SQL 均没有 workspace 条件，证明当前实现无法强制 workspace 隔离。")[检索实现限制 ↗](08f25ff6e25e1918acb0892c2a3a12abd21c662ab179814edc853f516920ebfb.md#trust-progress-limits "提供无序候选截断、项目范围和记忆候选原文回溯缺口的子知识入口。") 群聊的主体、来源和范围授权仍依赖宿主注入完整策略。[检索与可见性过滤 ↗](../../../apps/server/src/assistant/runtime.ts#L604 "支持 RetrievalPort 优先、上一轮证据复用，以及群聊未注入策略时默认拒绝。")

来源更新会确定性地使旧依赖失效，并记录受影响记忆范围，但刷新作业随后以未实现错误结束，尚未重新运行 verifier；这一边界可下钻到学习刷新子知识。[来源刷新限制 ↗](10d08569c7ebcd6fe394a2f2453ddcb298d886363c472add78e054af606bf143.md#runtime-progress-limits "提供来源更新只记录影响范围、尚未完成自动重核验的子知识入口。")[重新复核尚未实现 ↗](../../../apps/server/src/learning/pipeline.ts#L126 "证明刷新作业记录影响范围后仍抛出未实现错误，不能报告为已经完成 verifier 重核验。") 因此，重新取证、独立重核验、部分失败重试和只允许新 head 结果提交仍未形成闭环。
