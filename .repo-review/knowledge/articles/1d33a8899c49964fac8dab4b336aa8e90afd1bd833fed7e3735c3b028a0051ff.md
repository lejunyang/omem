# 代码理解结果的确定性边界与校验流程

该模块定义固定代码快照、版本化理解输出、角色资产加载和确定性交叉引用校验，并在模型不可用时生成仅含机械事实的低置信度 seed。校验器约束结构、来源封印、引用与字段一致性，使调用方可以拒绝无效结果；它不证明独立复核实际发生，也不核验自由文本论断的语义真伪或负责结果持久化。

来源：gpt-5.6-sol 分析，gpt-5.6-sol 独立复核；模型解释仍可被原始证据纠正。

<a id="purpose-contract"></a>
## 固定材料边界与数据合同

该模块把一次代码理解运行限制在预先固定的文件、符号、关系边和证据集合中。材料正文作为不可信数据，不会被当作给模型或校验器的指令执行；这替代了“材料不能影响模型或校验器行为”的过强结论，因为材料内容仍可影响模型产出，文件文本行数也参与选择器范围判断。[固定快照与不可信材料边界 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L1 "支持固定输入范围，并准确限定材料正文不会被当作模型或校验器指令执行。") 快照 schema 限制集合规模，检查各类 ID 唯一性及符号到文件、边到符号的引用完整性，形成封闭的可引用范围。[快照结构与引用完整性检查 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L114 "支持输入集合规模、ID 唯一性以及符号和关系边引用完整性的说明。")

`CodeUnderstanding.v1` 描述职责、边界、流程、入口出口、风险、声明和未知项；声明区分机械事实与解释，并显式携带节点、边和证据引用。[版本化理解输出合同 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L216 "支持输出字段、机械事实与解释分类以及显式快照引用的说明。") 来源字段只提供内部一致性约束：seed 不能命名模型或声称经过 agent 复核，`status=verified` 必须配合验证标记和验证者身份。它并不能证明非 seed 结果确实经过独立复核，而且 `status=generated` 仍可与 `verified_by_agent=true` 同时出现；这替代了“schema 可避免未经复核结果被标为已验证”的旧结论。[来源字段内部一致性约束 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L266 "支持 seed、模型、验证标记、验证者和 verified 状态之间的约束，并显示这些规则未禁止 generated 状态携带验证标记。")

<a id="asset-validation-flow"></a>
## 角色资产加载与确定性校验

角色注册表仅接受四种代码理解角色。加载过程校验角色版本、目录边界、manifest 身份、输出 schema、技能唯一性和摘要；越界路径及符号链接会被拒绝，提示词、schema 与技能摘要共同形成可复现的 bundle 封印。[安全的角色资产加载 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L314 "支持角色白名单、路径及符号链接防护、资产摘要校验和 bundle 封印流程。")

校验器先严格解析输出，解析失败返回 `failed`；成功后核对角色、提示词摘要、schema 摘要、快照摘要，以及模型可用性与 seed 声明。[结构解析与运行封印核对 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L502 "支持 schema 解析失败状态及角色、资产摘要、输入摘要和模型可用性核对。") 随后检查顶层引用和 claim 内嵌引用是否存在，并按快照中文件文本的实际行数验证证据选择器。节点预算只统计顶层 `referenced_node_ids`；claim 的 `node_ids` 仅检查存在性，无须同步出现在顶层数组中。上述封印、引用或诚信错误返回 `rejected`。[引用、选择器与顶层节点预算验证 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L544 "支持未知引用、按文件文本行数进行的选择器检查，以及仅计算顶层节点引用的预算限制。")

<a id="fallback-boundaries"></a>
## 无模型降级与能力边界

模型不可用时，`buildSeedOutput` 从快照选取受顶层节点预算限制的符号，只生成 `raw_fact`；模块职责、边界、流程和入口出口留空，置信度为零，并记录无法形成模块叙事的未知项。[无模型 seed 构建 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L620 "支持 seed 仅生成受限机械事实、留空模块叙事并记录未知项的说明。") 校验器同时禁止 seed 携带解释性声明或超过 0.1 的置信度，因此该产物只是结构骨架。[seed 解释与置信度限制 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L605 "支持 seed 不得携带解释性声明且置信度不得超过阈值。")

本模块只判断输出是否满足 schema、封印、引用和有限的字段诚信约束，不核验自由文本解释是否符合事实。它返回可区分的失败或拒绝结果，供调用方决定是否记录、持久化或提升；注释表达了避免虚构 ID 进入知识图谱的设计意图，但本材料没有证明调用方已正确接线。[校验结果与调用方职责边界 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L489 "支持校验器返回失败或拒绝状态，并表明避免无效引用被提升需要调用方正确处理结果。") 模块直接依赖 Node 的摘要、文件系统和路径能力以及 Zod，并以内置稳定摘要实现保持与记忆或存储层解耦。[自包含摘要实现及依赖 ↗](../../../packages/agent-runtime/src/code-understanding.ts#L12 "支持模块依赖 Node 摘要、文件系统、路径和 Zod，并刻意避免耦合存储层。")
