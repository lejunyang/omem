# 检索与解释背景：当前结果

2026-10-04。检索实现 `43a0f7f`，局部生成范围修正 `7aae95d`，对照 `b9eb2fd`。这是当前报告，旧轮完整记录从 Git 回看，不再叠加另一套时间戳文件。[精简逐题结果](unified-retrieval.json)保留前后各五项实际文字和固定定位。

## 为什么这次先改内容的可用范围

此前一篇文章只要有一个引用原件变化，就整篇退出检索。即使另一个章节的引用版本完全没变，模型也拿不到已经整理过的解释。结果容易只剩关键词相近的测试、旧计划或界面说明。单纯调整排序权重无法恢复已经被排除的内容。

现在按完整章节判断支持范围：本节引用仍指向同一原件版本时可作为“待复核背景”；本节任一引用变化则整节退出。对指定子文章章节的引用递归检查该固定章节，未指定章节则仍检查整篇。原件可见性、用户更正和固定引用历史沿用原合同，文章不会因此被重新标记为当前。

搜索结果按文章修订和章节去重，同一节选分数最高的段落，其他章节继续竞争。没有将段落拼成一段新的无来源文字。章节之间未显式表达的前提仍可能变化，因此派生解释只是调查背景，不能据此自动应用事实。

没有把十题压成一个“通过率”：能开始回答、仅有相关背景和直接偏题是不同情况。旧六道路径回归只看原件，不能用新增知识背景的收益替代它的失败。

## 真实问答、模型文章与检查

冻结依赖、403 项测试、类型和构建已通过。使用同库隔离副本启动生产 HTTP 服务，语义索引就绪后检查三个中文问题，均返回 200；换版问题的首项改善，审核失败和固定历史引用的问题仍有偏题。测试副本已释放。这与直接检索对照分开记录，不冒称浏览器验收。

真实 Traex ACP / GPT-5.6-sol（medium）回答“换了一份规则文档，之前保存的结论还会被继续拿来回答吗？”，约 **330 秒**完成，无降级、未创建事项。作者自主补读，独立复核又核对换版与事实应用：同源新版本会停用旧记忆，抽取、核验和应用成功后才替换结论；排入后台不代表一定更新成功。如果以另一来源标识另建材料，旧来源不会自动失效。

人工阅读仍发现两点不足：答案把“更新/换版”写成已有操作入口，而实际输入页面是填写“来源标识（相同标识产生新版本）”；同时内部状态术语较多，耗时仍长。因此这题说明材料调查改善了机制解释，**不能判为完整可操作的好答案**。最终文字及复核要点留在 JSON，问答验收数据库已自动释放。

五篇实现说明与一篇检索读者指南已由真实 Sol 写作并独立复核后发布。指南沿群内报名时间变更讲解搜索、补读和回答，加入入口对照表、流程图与排查路径；仍夹杂 owner、kind、purpose 等工程字段，不等于已经达到面向普通读者的最终表达。本轮完整验证已结束：冻结依赖、403 项测试、类型与构建、真实中文检索运行检查、134 篇当前文章的 774 处引用以及语义索引均通过；原件搜索六题只有 **3/6** 进入前五，完整验证因此退出 **1**，未判为全部通过。

## 局部更新与资料保留

发现旧生成脚本会把两个指定文件自动扩成历史批次中的十三个材料。已改为默认只处理明确指定目标，只有显式 `--modules` 才扩展关联模块，并优先处理用户指定文件。初次扩展运行已停止，停止前成功复核发布的三篇保留；取消或未完成的工作不计为成功。随后按两个明确目标重新运行真实模型，再更新检索读者指南。

本报告覆盖现行文件，旧对照从 Git 查阅；完整自动检查沿用“最近两次成功、两次失败”的保留策略。正式原件和固定引用所需文章历史不作日志清理。

## 仍应继续做什么

已经找回解释后，需要让排序区分“说了同一主题”和“回答了当前条件或处理流程”。本轮没有解决这项判断，也没有加入按本仓库目录或题目定制的优先级。下一步应针对仍失败的问法检查候选池、阅读窗口与最终答案，保留无收益和退步；不要继续只比较几个融合权重。

具体先分两种失败：问“为什么保留旧引用”，首项却讲防止旧请求覆盖新请求，这是候选对用户问题的区分不足；已经查清来源换版机制，却建议不存在的界面入口，这是作者与复核者没有核对最终行动。前者应先确认正确解释是否进入候选、完整上下文是否送到相关性判断，再比较成熟重排方法的真实收益；后者应把最终给出的操作回读到实际界面或 API，而不是再增加一套“已找到引用”的形式检查。两项都用陌生问法检查，不能按这两个样例硬编码。
