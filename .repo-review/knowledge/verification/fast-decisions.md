更新：2026-10-05，Apple M2 Pro / 32GB。此文件与[结构化结果](fast-decisions.json)覆盖更新；历史可查 Git，不逐轮添加整份日志。代码、配置与真实消费者见[快速决策方案](../../../docs/reader-first/fast-decisions.md)。

## StartLux 0.8B / 2B / 4B 的同输入对照

官方 `MLXDecision`，原始 BF16 权重，上游源码固定 `0e7a2e81b9c92756e26d8edd843a44d50e362669`。固定八条中文合成材料和六条 dev HTTP 命中，每段同时问相关性、回答覆盖、内容支持、前提矛盾、指令注入、父章节需求。输入在 `scripts/startlux/cases.json`；预期不交给模型。每种模型顺序加载释放，没有同时驻留。

| 大小 | 暖机单段中位数 | 暖机范围 | 六条 HTTP 合计 | 初始化 | MLX 峰值分配 | 进程 RSS 峰值 |
| --- | --- | --- | --- | --- | --- | --- |
| 0.8B | 253 ms | 249–315 ms | 1.72 s | 38.9 s | 2.19 GiB | 1.45 GiB |
| 2B | 576 ms | 567–727 ms | 3.96 s | 40.8 s | 4.04 GiB | 1.75 GiB |
| 4B | 1469 ms | 1445–1843 ms | 10.15 s | 50.7 s | 8.39 GiB | 2.25 GiB |

MLX 与 RSS 是不同统计口径，不相加，也不将 RSS 当总内存。设备其他程序负载未受控，这是一轮小样本对照，不是稳定吞吐、可靠速度倍数或泛化准确率。

**看到了局部收益，也保留明确失败：**

- 0.8B 将不同活动的规则判成前提冲突，把教程引用的攻击示例误报为实际注入，漏掉真实 HTTP 中的选材步骤。
- 2B 改善攻击示例的判断；不同活动冲突转为未知，但仍漏判选材步骤。
- 4B 找回选材步骤，对缺条件的规则更倾向 conditional；仍把宽泛目的说明当 answer/sufficient，其他材料也存在覆盖过高判断。

完整原生概率和模型 revision 在 JSON 的 `latestStartluxComparison`。概率未校准，分布集中不等于判断可靠；没有根据这十四个例子反向选阈值。

## 已接入的真实路径

共用 DecisionService 已连接助手初始召回与原文页用途建议。每段六维；安排、学习、代码、业务是四个可重叠的用途。负载策略选择一份常驻 2B/4B，内存不足时不用小模型，空闲三分钟释放。一般搜索列表没有改排序，Agent 自主检索仍可找回初始未选内容，事实和事项仍经 MemoryService。

实际 HTTP 曾评估十二条召回，按当时负载选到 2B，三十条候选均保留，没有材料达到保守联合省略门槛。说明真实调用通了，**不说明已改善噪声或问答质量**。冷请求验收 0.37 秒返回三十条原候选并后台预热，没有等待四十秒模型初始化；模型切换或暖机评估也设置八秒等待范围。

注入标记目前只做诊断，父章节需求用于保留材料，尚未驱动自动补读；目录分类、记忆更新候选和通用请求路由没有接入。不能把六个字段的输出算成六种完整能力。

## 此前对照保留哪些结论

| 实验 | 结果及取舍 |
| --- | --- |
| 38 个中文短场景、每题交换选项 | GLiClass 26/76、Qwen4B Q4 55/76、Plumb4B Q8 62/76、Q4 52/76；包含操作/询问混淆、对象与更新混淆，不用总分接管记忆 |
| 五问各六条实际 HTTP 材料 | Plumb Q8 找出更多直接支持，也有七次误判；Qwen 与 GLiClass 漏掉多条材料。原生 GLiClass query-as-label 三题退步、一题不变 |
| Sol medium 调查与 Sol low 先读 | 首轮仓库三题一题明显更快、两题遗漏条件或对象混淆；修正材料后的回放纠错，但频繁复核没有普遍速度收益 |
| 同库合成生活四题 | 先读 29–53 秒、常规 41–58 秒，保留了候补、退款条件与同名对象；小规模短材料收益，不默认接管复杂问答 |
| 简短问题先搜再判断 | “导入文档是否自动整理用途”补材料后选项更稳定，却仍未辨认材料中的否定答案；稳定不等于正确 |

这些输入、版本、逐题结果和真实 ACP trace 摘要仍在同份 JSON，不与 StartLux 十四段的成绩混算。9B+ 本机排除；English-only 模型低优先级；不再继续 Luna 对照。
