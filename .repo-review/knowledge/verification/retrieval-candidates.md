记录：2026-10-09，北京时间。实现 `cdb3bb1`、诊断修正 `9fddf5a`；两份模型说明分别提交为 `bf57479`、`022a593`。逐题数据见 [JSON](retrieval-candidates.json)，当前完整验收见 [verification.json](../verification.json)。

本轮修好评分链路并补齐阶段诊断。真实 BGE 对部分题目有排序收益，但长代码处理和记忆重核验两题的核心实现依据没有进入融合候选池，重排器无法评分。当前仍保留独立重排器默认关闭；没有证据支持全局启用或宣称中文检索已达标。

## 实现与诊断

- 显式配置的 cross-encoder 可以重排词面候选，向量未启用、未就绪或失败时也能运行。此前这些分支提前返回，实际跳过了重排器。
- 重排器加载失败后释放失败的加载记录，资源恢复时可再次尝试。评分异常、缺项或非有限分数沿用原候选。
- 检索观察接口记录实际词面、符号与向量候选，随后记录融合、重排输入、评分、宿主选择、Decision 和最终结果。观察者拿到副本，不改变过滤或排序。
- 返回的 `reranking` 单独保存模型身份、相关分和重排前检索分；`assessment` 仍表示原生 Decision 的判断。相关分经过现有温度变换，未经概率校准。
- 精确符号与显式 AST 导航绕过评分模型。现有 top-40、局部窗口、分数混合及用途偏好保持一致，没有针对题目改权重。

`osdk run retrieval:compare` 对已索引库开启只读事务，四组顺序使用同一批 18,303 单元、当前原件和中文 embedding。查询采用原件检索、limit 40、`diversify:false`，用于 Agent 选材诊断；完整报告另测实际 HTTP 阅读入口，其投影和去重约定不同，名次不能直接互换。运行不下载、不复制数据库。人工核心依据标注只用于验收，不传给检索或模型。

长代码题的重叠分窗与逐窗索引，以及记忆重核验题的过期登记和应用依赖协调，均未进入融合候选池。BGE base 把记忆题的原路径指标提高到通过，实际命中的是 README 中“来源更新后已有记忆重核验”的宽泛能力说明，缺少解释机制的实现依据。因此原路径指标 4/6 高估了这道题的改善。

不隐式下载题在原检索中已有可回答陈述，核心依据排名第三；BGE base 提到第一。历史原型确已召回，两种 BGE 都将目标从第九提到第一，这属于实际排序收益。阶段记录也显示宿主偏好可以改动模型顺序：不下载题在 v2 的纯模型顺序中核心依据排第二，最终排第三。

词面前排还会出现包含同一测试问题的验收说明。它们能匹配问题，却不提供实现。后续应通过正式材料用途及概念说明区分这些内容，并调查缺失依据；不能用目录名单或特定路径加权替代。
