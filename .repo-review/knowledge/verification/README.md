# 验证记录怎么用

当前入口是上一级的 `verification.json`。它由 `osdk run review:verify` 自动生成，记录当前源码指纹、题集指纹、实际执行结果、知识覆盖和检索结果。

- `osdk run review:verify`：同步仓库材料和 AST，验证当前知识引用/依赖，补齐已配置的向量索引，通过真实本地 HTTP 跑仓库回归问题。
- `osdk run review:verify --full`：额外执行冻结依赖、完整 typecheck/test/build 和真实中文向量模型小样本验证。单项失败也写入报告，并以非零状态退出。
- 未执行的检查标为 `skipped`，不继承旧报告的通过结果。当前引用检查通过不表示未复核材料已经完成；报告分别列出覆盖与缺口。
- `queries.json` 是可维护的公开回归题集，指定可接受的原始文件；整个 `.repo-review` 都不作为知识输入，防止问题和答案路径污染召回。它不代替真实用户数据评测。
- `history/` 中的自动报告仅保留最近两次成功、两次失败；当前文档直接引用的报告额外保留。早期 seed 核对及固定引用历史不按自动报告清理。更旧记录查 Git，不无限累加。

运行日志保存在忽略提交的 `.repo-review/runtime/verification/<运行时间>/`，只保留最近三次已结束运行；报告保存其路径与 SHA-256，旧日志可能已清理。`review:verify` 完成后自动清理，亦可用 `osdk run review:prune` 预览、加 `--apply` 执行。源码或题集在运行中变化会令本次验证失败。历史记录不参与自动判定当前通过率，也不会让知识文章自动通过语义复核。

正式读者页由 `review:guides` 或网页“整理文章”调查、写作和独立复核，产物保存在 `articles/*.json`；`review:generate` 只处理明确选择的内部分析笔记。本验证入口不会偷偷调用生成式模型，也不自动 push。

专项记录保留当前简报、必要排名和模型输入；重复原文和 HTML 展示副本已经清理。被压缩的 JSON 在 `retention` 字段记录范围和原报告摘要，旧全量响应可以从 Git 历史读取。压缩日期不代表新的实验日期或通过结果。
