# 材料说明对搜索的实际作用

更新：2026-10-05。**补齐换版说明改善了部分前排结果，但仍不能把“谈到同一主题”变成“回答了问题”。** 当前流程和实现位置见[材料用途与概念入口](../../../docs/reader-first/material-understanding.md)。本简报与 [material-search.json](material-search.json)覆盖更新；10 月 3 日的旧实验可查 Git，不追加整库副本或另一份历史正文。

## 这次比较了什么

在实现 `5e084c0` 上复制隔离仓库库，用真实开发适配器导入工作区一次后冻结。657 份有效材料中，81 份当前版本有说明；另有 19 份只有旧版有说明。只对后者调用真实 Traex ACP / `gpt-5.6-sol`，按三批完成，约 214/140/65 秒。模型自主读取原件和必要背景，没有得到问题、预期路径或答案。说明按新原文重新判断用途并定位概念，不复制旧版状态或行号。

前后调用同一生产 `/api/search`，使用同一原件与文章 head、ICU/FTS5/BM25、BGE 中文模型、标准 RRF；没有改排序、权重、问题或重排配置。两侧均为 `structure-icu-v6`，12,998 单元全部就绪、无待建向量，cross-encoder 未启用。原件与文章摘要相同。输入包含八个自然语言诊断问题和六个已有路径回归；新措辞的主题已在库中，不称为独立盲测，也不把路径命中当答案正确率。

## 问题落在哪一层

1. **换版断档确实存在。** 说明补齐后，文章页面计划再次被识别为计划，直接行为解释前移。显式开启后的持久维护已接通，未开启的来源和以前的缺口不会自动全部解决。
2. **旧分类也可能错，而不只是缺。** `fast-assistant.md` 的旧说明把解释/评测文档标成了 implementation，它的正文没换版，不在这 19 份目标中。这轮重新明确用途定义后，需要按实际内容补查旧说明；不能通过按路径降权掩盖分类问题。
3. **整体用途太粗。** 一份 reference 文档可以同时含使用步骤和实验表。给整份文档同一个用途偏好，无法区分其中哪个段落真能回答。这次有概念覆盖多种内容的宽范围，也有词法直接答案未进入向量前列而在融合后靠后的情况。
4. **源文本自己也有过时现状。** 文档入口仍声称发布与维护没有重构；已在 `992dffa` 修正三份入口说明。该修订发生在冻结之后，不计入这次同库收益。

下一步应先保住候选中的直接答案，再比较完整段落的回答相关性和上下文；复杂问题由同一 Agent 按缺口补读。章节用途、中文重排或询问目的解析都需要与简单基线比较，不根据这八题继续调权重。只有文章和原文确有清楚解释，排序才有东西可以返回。

## 数据与边界

真实模型说明按固定材料 digest 发布，旧说明保留历史；分类是导航信息，不是独立事实。分类任务未执行独立知识写作复核，不能套用文章 verifier 的通过结论。此次没有生成最终问答，因此没有答案正确率或端到端提速结论。

专项 JSON 只保留前十项、必要摘录、固定定位和此次条件；完整模型说明各自发布，不再复制进报告。原始前后响应暂存于 gitignored `runtime/description-retrieval-comparison/latest.json`，运行结束释放该实验的数据库，保留有界报告。个人库和正式仓库运行库不受清理影响。
