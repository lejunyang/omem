# 按问题调查与独立补查：本轮实际结果

2026-10-03。使用真实 Traex ACP / GPT-5.6-sol，未调用 Luna。实现为 `ae44b5b`、`2e2cb20`，指南计划为 `4b336cd`，符号兼容修正为 `9e7b1ea`。本轮新增的是调查和答前检查能力；尚未解决普通搜索相关性、复杂答案篇幅与等待时间。

## 实际改了什么

助手可在临时工作区保存围绕问题的事实笔记：要回答什么、材料已经说明什么、还缺哪项条件。复杂问题可提交候选答案给另一个 Sol 会话；复核者拿原问题与同一封存材料，自主搜索和补读，不看作者笔记。作者再读反馈指出的原件，决定如何修订。简单查询不用额外复核。

代码导航增加导入别名、接收者、构造调用、外围条件和完整方法定位。它帮助找到该读哪里，不推断完整跨文件调用图。符号保存名称和检索预处理保持原有规则；对验收库全部 TS/JS/Vue 原件与本轮前解析器比较，符号输出差异为 0。为排除开发中间状态，仅清空隔离验证库的派生投影缓存并重新建立，没有删除原件、历史或个人库。

材料用途曾试验只在明确寻找实现时降低计划等内容的排序偏好，最后因同库退步撤回（`da3cf42`）。默认排序恢复本轮前的用途策略，明确用途与背景查询仍可使用。没有增加目录或题目特判，也没有修改融合权重。

## 四个真实回答

下表是逐题阅读检查，不是通用准确率。仓库两题使用一份冻结语料，普通约定两题使用另一份人工构造的独立语料。题目文件未导入知识库；第一题属于已公开的回归场景，不能当作盲测。原文、草稿、反馈、最终答案和耗时见[结构化记录](answer-investigation.json)。

| 问题 | 实际效果 | 仍存在的问题 | 耗时 |
| --- | --- | --- | --- |
| 原始资料修改后，已保存的记忆会自动更新吗？ | 作者已找出同一来源产生新版本、学习启用、Agent 可用及后台运行的前提；复核补出了“重新核验不保证替换成功”、部分完成和待判断操作入口 | 答案偏长，结尾夹有内部状态名 | 290 秒 |
| 六篇入门指南的选题在哪里维护，如何新增？ | 找到 `config/wiki-pages.json` 和实际生成入口；复核发现字段清单遗漏必填 `title`，最终补齐 | 缺少可复制的完整最小配置例子 | 220 秒 |
| 我和朋友填过问卷但没各自收到确认，周六能直接参加吗？ | 分清问卷只是意向、每人需确认、提案尚未生效和本周/下周条件；没有把例外当通用规则 | 复核者曾把开始时间已过写成活动已结束，作者补读后拒绝了这个推断。最终仍偏长、略有重复 | 169 秒 |
| 共读会几点开始？ | 简短回答每周六 14:00，附原文引用，没有调用独立复核 | 46 秒仍不够快 | 46 秒 |

第三题说明复核意见本身也要核查。材料只给开始时间，没有结束时间；最终答案明确“开始时间已过，不能确认是否仍在进行”。不能把多一个模型等同于事实更可靠。本轮同步加强了作者和复核者对建议、事实和推断的区分。

这四次调用均未降级，调查记录没有失败的 MCP 调用。它只说明这些实际流程完成，不说明模型已读懂全部材料。仓库两题准备材料各约 11 秒，原生 Agent 阶段约 277/208 秒；普通资料准备约 0.1 秒，Agent 阶段约 168/46 秒。主要等待在 Agent 调查与复核，不能只优化 SQLite 或换快模型来宣称体验已解决。

不同问题跨越了角色提示的小幅修正，角色包和 trace 各自保留；并行负载未控制，耗时不能用于严格模型比较。宿主仅阻止缺少已要求复核、复核仍运行和有问题却原样提交的草稿，不会把字符串变化视为语义修订充分。

### 最终实现复查：未交付答案

撤回排序实验后，在同一冻结仓库语料上再次询问第一题，实际 Sol/medium 在 480 秒触发既有整轮超时，命令退出 1，**没有成功交付最终答案**。不能拿前面四次成功覆盖这次失败。

这次独立复核确实找出了重要问题：作者将 schema 中 `learning` 缺失时的 false，说成实际启动默认关闭；但仓库没有个人配置时会读取启用了 learning 的示例配置。它还指出“循环正在运行”不代表没有后台错误。作者拿到反馈后没有在时限内修订完成。草稿和反馈随结构化报告保留，不当作已发布回答。

日志还保留了长复核期间的交互问题：作者再次请求复核，被“已有复核运行中”拒绝；又在复核完成前提交答案，被宿主拒绝。独立复核后来成功返回，但最终整轮仍超时。前四次没有 MCP 错误，不代表长耗时复核已经稳定。当前复核工具仍等待整次模型运行后才返回，尚无可重复读取的运行状态接口；这是下一切片应优先处理的具体问题，而非把它全部归为模型慢。

没有通过加大超时、删掉失败题或降低复核要求把它改成通过。最终实现的调查与复核能力已接通，但复杂回答耗时与稳定性尚未解决；多模型调用能发现遗漏，并不自动形成可用体验。

## 下一步应解决什么

先补齐长复核的状态读取与重复请求处理，让作者知道复核是否完成、完成后取得哪一份意见；同时缩短“给足材料后仍啰嗦”的回答。用户首先应看到明确结论、必要条件和下一步，补充解释按需阅读。独立复核只指出会改变判断的遗漏，不把答案扩成边界审计。

本轮刷新还暴露了维护成本：依赖收集包括作者和复核者读过的材料，进度文档或局部实现变化也可能令整页过期，再跑完整研究、写作和复核。后续应区分调查访问记录与正文结论的依赖，判断哪些章节实际受影响；这需要真实内容验证，不能简单删掉依赖以换取 current 状态。当前并未实现这种更新粒度。

初始搜索另做一个完整切片：区别命中问题文本与包含答案的段落，检查现有可读讲解为何没进前排，再决定候选组织和排序的改造。用同一冻结语料记录候选、模型实际阅读与最后回答；不继续只调几个融合权重，不把本轮四个例子当作题目模板。普通文档、跨文件机制、无答案问题都应保留，失败也一起报告。
